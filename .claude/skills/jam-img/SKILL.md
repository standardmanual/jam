# /jam-img — 배지 이미지 제작 파이프라인

**핵심 원칙: 각 단계 사이의 "결과 확인" 지점은 오케스트레이터가 임의로 건너뛰지 않는다.**
자동화 가능한 단계라도 사용자가 눈으로 보고 다음으로 넘어가라고 말할 때까지 대기한다.
(2026-08-21 티켓: Recraft 최초 배치에서 사용자 확인 없이 로고 합성·DB 반영까지 한 번에
진행했다가 배경 투명화가 빠진 채로 등록된 사고 이후 이 스킬로 절차를 못박음)

```
① 이미지 생성 ──Recraft(API)──▶ ② 결과 확인 ──사용자──▶
③ 로고 합성 ──Claude Code──▶ ④ 결과 확인 ──사용자──▶
⑤ 배경 제거 ──사용자(직접 작업, 파일 제공)──▶ ⑥ 결과 확인 ──사용자──▶
⑦ DB 반영 ──Claude Code──▶ 완료
```

## 0. 시작 전 확인 (매번 다름 — 절대 이전 실행값을 재사용하지 않는다)

이 파이프라인의 프롬프트·스타일·레퍼런스는 세계관·컬렉션마다 다르다. 진행 전 아래를 확인:

1. **대상 세계관/컬렉션** — `Service Plan/Specs/Content/IMAGE_PRODUCTION/02_스타일그룹/{NN 세계관명}/`
   폴더와 그 안의 `컨텐츠_브리프/{컬렉션명}/` (또는 이미 평탄화된 `컨텐츠_브리프/{컬렉션명}.md`)를 확인해
   대상 아이템 목록과 각 아이템의 컨셉을 파악한다.
2. **스타일 등록 여부** — 세계관 폴더에 `recraft_style.json`이 있는지 확인.
   - 없으면 먼저 `register-style.js`로 스타일을 등록해야 한다 (세계관당 1회).
     레퍼런스 이미지는 `{세계관 폴더}/레퍼런스_이미지/`에 최대 5장, 스타일그룹_정의서.md의
     "레퍼런스 적용 기준"(그림체·선스타일·표현기법·컬러톤·조형적 밸런스만 참고)을 반드시 따른다.
   - 있으면 재사용 — 스타일은 세계관 전체에서 동일해야 하므로 컬렉션마다 새로 만들지 않는다.
3. **배치 설정(`recraft_batch_config.json`) 작성** — 컬렉션 폴더에 아이템별 프롬프트를 준비한다.
   프롬프트는 컨텐츠_브리프 문서의 아이템 설명에서 "가장 상징적인 한 장면·상태"를 뽑아 작성하고,
   스타일그룹_정의서.md의 절대 금지 요소·텍스트 규칙·캐릭터화 규칙을 프롬프트에도 반영한다.
   **이 파일 내용은 실제 API 호출(크레딧 소모) 전에 사용자에게 보여주고 승인받는다.**
4. **로고 파일 경로 확인** — `compose-logo.js`에 넘길 브랜드 로고 이미지 경로.
   보통 프로젝트 공식 로고 폴더에 고정 파일로 있음 — 없으면 사용자에게 위치를 물어본다.

## ① 이미지 생성 — Recraft

```bash
node jam-web/scripts/recraft/generate-batch.js "<컬렉션 폴더 절대경로>"
```

- `recraft_batch_config.json`의 각 아이템을 순회하며 `POST /v1/images/generations` 호출,
  결과를 컬렉션 폴더에 `{filename}`으로 저장한다.
- **주의**: Recraft의 생성 API는 배경을 투명하게 만들어주지 않는다 — 항상 불투명(RGB) 이미지가
  나온다. 이 단계에서 나오는 파일은 아직 배경이 있는 원본이다 (정상).
- 크레딧을 소모하는 실제 API 호출이므로, 0단계 승인 없이 먼저 실행하지 않는다.
- 실행 후 사용 크레딧 합계를 사용자에게 보고한다.

## ② 결과 확인 — 사용자

생성된 원본 이미지를 사용자에게 보여주고(SendUserFile 등으로 첨부) 승인을 받는다.
컨셉이 어긋나면 프롬프트를 수정해 ①을 다시 돈다. **승인 전에는 ③으로 넘어가지 않는다.**

## ③ 로고 합성 — Claude Code

```bash
node jam-web/scripts/recraft/compose-logo.js "<원본 이미지>" "<로고 경로>" "<출력 경로>" [로고폭비율] [하단여백비율]
```

- 아이템마다 반복 실행 (배치 래퍼 스크립트는 아직 없음 — 셸 for문으로 순회).
- 로고폭비율/하단여백비율 기본값(0.224 / 0.05)은 01-01 1차 검증 배치 기준. 세계관마다 배지
  전체 구도가 다르면 육안 확인 후 조정할 수 있다.
- 출력 파일명 규칙: 컬렉션 폴더에 `{원본파일명 stem}_logo.png` 또는 팀이 합의한 접미사로 저장.

## ④ 결과 확인 — 사용자

로고 위치·크기가 브랜드 세이프존 규칙(정의서의 "브랜드 로고 세이프존" 항목)에 맞는지 확인받는다.

## ⑤ 배경 제거 — 사용자 작업

**이 단계는 Claude Code가 자동화하지 않는다.** Recraft에 별도 배경 제거 기능이 있는지 확인되지
않았고(2026-08-21 기준 조사 결과 생성 API에는 없음, 별도 엔드포인트 존재 여부·크레딧 비용 미검증),
사용자가 직접 배경을 투명하게 처리해 최종 파일(`_final.png` 등)을 제공한다.

- 오케스트레이터는 사용자가 파일 경로를 알려주면, 파일마다 **알파 채널 존재 여부와 코너/중앙
  픽셀의 투명도를 실제로 검증**한다 (`PIL`로 `im.mode`, corner alpha, center alpha 확인 —
  "배경 흰색으로 보임" 사고가 이미지 자체 문제인지 이후 캐시 문제인지 구분하기 위해 필수):

```bash
python3 -c "
from PIL import Image
im = Image.open('<파일경로>')
print(im.mode, im.size)
im2 = im.convert('RGBA')
print('corner', im2.getpixel((0,0)))
print('center', im2.getpixel((im2.width//2, im2.height//2)))
"
```

- corner alpha가 0이 아니거나 mode에 알파가 없으면 배경 제거가 안 된 것 — 진행하지 말고 사용자에게
  알린다.

## ⑥ 결과 확인 — 사용자

투명 처리된 최종본을 실제로 렌더링해 보여주거나(Artifact/SendUserFile) 육안 확인을 요청한다.

## ⑦ DB 반영 — Claude Code

```bash
node jam-web/scripts/recraft/register-badge-images.js "<컬렉션 폴더 절대경로>"
```

- `recraft_badge_mapping.json`(아이템별 파일명 → badge id 목록)을 읽어 Storage 업로드 +
  `badges.image_url` UPDATE. **재업로드 시에도 이 스크립트가 자동으로 `?v=<timestamp>` 캐시버스팅
  쿼리스트링을 붙인다** (2026-08-21 흰 배경 캐시 사고 이후 수정됨 — 같은 Storage 경로를 재사용해도
  Vercel Image Optimization 엣지 캐시가 예전 이미지를 서빙하는 문제 방지).
- 실행한 UPDATE문은 스크립트가 컬렉션 폴더에 `seed_{collection_id}_badge_images.sql`로 자동 저장—
  이 파일과 이미지 파일들을 staging에 커밋+push한다 (레포 관례).
- 컬렉션 대표 이미지(`item_books.image_url`)를 함께 갱신해야 하면(보통 등록이 끝난 컬렉션은
  첫 번째 아이템 이미지를 대표 이미지로도 반영하는 것이 기본 규칙) 별도 UPDATE 후 SQL로 기록한다.
