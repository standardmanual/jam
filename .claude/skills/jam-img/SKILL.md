# /jam-img — 배지 이미지 제작 파이프라인

**핵심 원칙: 각 단계 사이의 "결과 확인" 지점은 오케스트레이터가 임의로 건너뛰지 않는다.**
자동화 가능한 단계라도 사용자가 눈으로 보고 다음으로 넘어가라고 말할 때까지 대기한다.

```
① 스타일그룹 정의서 생성 ──Claude(대화)──▶ ② 결과 확인 ──사용자──▶
③ 컨텐츠 브리프 프롬프트 생성 ──Claude──▶ ④ 결과 확인 ──사용자──▶
⑤ 이미지 생성 + 배경 투명화 ──사용자(Gemini에 직접 입력 + 직접 후처리)──▶
⑥ 결과 확인 ──사용자──▶
⑦ DB 반영 ──Claude Code──▶ 완료
```

> 2026-08-22 기준: Recraft API 자동 생성·로고 합성 단계는 폐지했다. 이미지 생성은 사용자가
> Gemini에 직접 프롬프트를 입력해 진행하고, 배경 투명화까지 포함한 최종 파일을 사용자가
> 준비해서 가져온다. 오케스트레이터는 그 파일을 검증하지 않고 그대로 DB에 반영한다 — 이 부분은
> 사용자가 명시적으로 선택한 절차이며, 알파 채널 검증 같은 자동 확인 장치는 두지 않는다.

## 0. 시작 전 확인

1. **대상 세계관/컬렉션** — `Service Plan/Specs/Content/IMAGE_PRODUCTION/02_스타일그룹/{NN 세계관명}/`
   폴더와 그 안의 `컨텐츠_브리프/{컬렉션ID} {컬렉션이름}.md`를 확인해 대상 아이템 목록과
   각 아이템의 "생성해야 하는 표현"을 파악한다.
2. **스타일그룹 정의서 완결 여부** — 세계관 폴더의 `스타일그룹_정의서.md`가 팔레트·렌더링
   규칙·절대 금지 요소·텍스트 사용 여부·캐릭터화 규칙·톤까지 채워져 있는지 확인한다.
   - 비어 있거나 없으면 ①단계부터 시작한다.
   - 채워져 있으면(다른 컬렉션 작업 시 재사용) 바로 ③단계로 넘어간다 — 스타일은 세계관
     전체에서 동일해야 하므로 컬렉션마다 새로 만들지 않는다.

## ① 스타일그룹 정의서 생성 — Claude

`01_템플릿/정의서_작성_요청_프롬프트.md`의 재사용 템플릿을 사용자가 채워서 요청하면(또는
레퍼런스 이미지 + 요구사항만 주면 이 템플릿 형식에 맞춰), 세계관 폴더의 `스타일그룹_정의서.md`를
`01_템플릿/스타일그룹_정의서_양식.md` 양식에 맞춰 작성한다.

- 레퍼런스 이미지는 그림체·선 스타일·표현 기법·컬러톤·조형적 밸런스만 참고 대상이며, 이미지
  속 구체적인 사물·캐릭터·문구는 참고하지 않는다.
- 사용자가 준 요구사항이 레퍼런스 이미지 내용과 상충하면 요구사항을 우선한다.
- 정의서 파일만 만든다 — 다른 파일을 함께 만들지 않는다.
- 이 세계관의 전체 아이템 수를 전제하는 표현을 쓰지 않는다 (컬렉션 1개만 대상으로 작업할 수도
  있으므로).
- 로고 합성 단계가 없으므로, 정의서에 "로고_URL" 같은 로고 배치·세이프존 관련 필드를 새로
  넣지 않는다 (기존 세계관 정의서에 이미 있는 로고 관련 서술은 남겨두되, 새 워크플로우에서는
  참조하지 않는다).

## ② 결과 확인 — 사용자

작성된 정의서를 사용자가 검토한다. 팔레트·규칙이 의도와 다르면 요구사항을 조정해 ①을 다시
돈다. **승인 전에는 ③으로 넘어가지 않는다.**

## ③ 컨텐츠 브리프 프롬프트 생성 — Claude

세계관의 `스타일그룹_정의서.md`와 대상 컬렉션의 `컨텐츠_브리프/{컬렉션ID} {컬렉션이름}.md`를
합쳐서, `01_템플릿/컨텐츠_브리프_프롬프트_양식.md` 구조에 맞춰 Gemini에 그대로 입력할 수 있는
`{컬렉션ID} {컬렉션이름}_프롬프트.md`를 같은 `컨텐츠_브리프/` 폴더에 작성한다.

- **아이템별로 섹션을 나눈다** (컨텐츠_브리프 표의 각 행 = 섹션 하나).
- 각 섹션에는 두 항목을 반드시 포함한다:
  - **negative prompt**: 정의서의 "절대 금지 요소" 전체 + (텍스트_사용여부가 no면 텍스트·레터링
    관련 금지도 포함)
  - **생성 prompt**: 정의서의 팔레트·렌더링 규칙·캐릭터화 규칙·톤/다이나믹함을 문장으로 녹이고,
    그 아이템의 "생성해야 하는 표현"(컨텐츠_브리프 표)을 핵심 장면으로 반영한다. 정의서의
    "톤/다이나믹함"에 정해둔 문법(예: 중앙 오브젝트 + 상태 과장 묘사)이 있으면 모든 아이템
    섹션에 동일하게 적용한다.
- 정의서의 "생성해야 하는 표현"을 스타일 규칙을 이유로 생략·변형하지 않는다 (정의서 대원칙).
- 이 문서는 컬렉션마다 새로 만드는 완성된 산출물이다 — 재사용 템플릿이 아니다.

## ④ 결과 확인 — 사용자

아이템별 negative/생성 prompt가 정의서·브리프 내용을 정확히 반영했는지 확인받는다.
**승인 전에는 사용자에게 Gemini 입력을 권하지 않는다** — 프롬프트 자체가 최종 산출물이므로
여기서 틀리면 이미지 생성을 반복해야 한다.

## ⑤ 이미지 생성 + 배경 투명화 — 사용자 작업

**이 단계는 Claude Code가 관여하지 않는다.** 사용자가 ③에서 만든 프롬프트를 아이템별로
Gemini에 직접 입력해 이미지를 생성하고, 배경 투명화까지 포함한 최종 파일을 준비한다.

## ⑥ 결과 확인 — 사용자

사용자가 준비한 최종 파일을 오케스트레이터에게 전달하면, 실제로 렌더링해 보여주거나
(Artifact/SendUserFile) 육안 확인을 요청한다.

## ⑦ DB 반영 — Claude Code

```bash
node jam-web/scripts/recraft/register-badge-images.js "<컬렉션 폴더 절대경로>"
```

- `recraft_badge_mapping.json`(아이템별 파일명 → badge id 목록)을 읽어 Storage 업로드 +
  `badges.image_url` UPDATE. 스크립트/매핑 파일명에는 `recraft_`가 남아 있지만 Recraft API를
  호출하지 않는 순수 업로드·DB반영 로직이므로 그대로 재사용한다.
- 재업로드 시에도 이 스크립트가 자동으로 `?v=<timestamp>` 캐시버스팅 쿼리스트링을 붙인다
  (Vercel Image Optimization 엣지 캐시가 예전 이미지를 서빙하는 문제 방지).
- 실행한 UPDATE문은 스크립트가 컬렉션 폴더에 `seed_{collection_id}_badge_images.sql`로 자동
  저장 — 이 파일과 이미지 파일들을 staging에 커밋+push한다 (레포 관례).
- 컬렉션 대표 이미지(`item_books.image_url`)를 함께 갱신해야 하면(보통 등록이 끝난 컬렉션은
  첫 번째 아이템 이미지를 대표 이미지로도 반영하는 것이 기본 규칙) 별도 UPDATE 후 SQL로 기록한다.

## 완료 후

- staging에 커밋+push는 CLAUDE.md 절대 규칙 3에 따라 항상 수행.
- main 배포는 사용자의 명시적 요청이 있을 때만 `/jam-ship`으로 처리한다.
