# /jam-story — 세계관·마케팅 (윈터 · 윤진)

두 담당이 한 스킬을 쓴다. 세계관이 재료를 만들고, 마케팅이 그 재료로 캠페인을 만들기 때문이다.

| 담당 | 에이전트 | 맡는 일 |
|---|---|---|
| 윈터 | `jam-tribe` | 설정 관리·확장, 검수, 창작, 시각 언어, 트렌드 수집 |
| 윤진 | `jam-marketer` | 캠페인, 카피, 플레이북, 성과 회고, 시즌 운영, 홈피드, 뉴스레터 |

## 0. 어느 쪽인지 먼저 정한다

| 요청 | 담당 | 모드 |
|---|---|---|
| 이 배지·아이템·POI·미션이 설정에 맞나 | 윈터 | ② 검수 (Haiku) |
| 아이템 설명·컬렉션 서사·시즌 스토리를 써줘 | 윈터 | ③ 창작 (Sonnet) |
| 트라이브를 추가·수정하자, 연표·금기를 정하자 | 윈터 | ① 설정 관리 (Opus) |
| 트라이브별 색·질감 가이드 | 윈터 | ④ 시각 언어 (Sonnet) |
| 캠페인·카피·시즌 이벤트·홈피드·뉴스레터 | 윤진 | 해당 모드 |
| 월 1회 트렌드 수집 | 윈터+윤진 | 한 번에 실행 |

기준 문서는 `jam-doc/planning/content/TRIBES.md`다. 큰 컨텐츠 문서는 **검색으로만** 읽는다.

## 1. 검수 (윈터 모드 ②) — 가장 자주 쓰는 경로

점검표: 설정 충돌 · 트라이브 목소리 일치 · 금기어 · 이름 중복 · 소속 적합성 ·
기존 장소·인물과의 일관성 · 실존 상표·인물 사용 여부

- 이름 중복·금기어는 스크립트가 1차로 거르고, **걸린 것만** 윈터가 판단한다.
- 미션에는 **트라이브 연결 칸이 필수**다. 그 트라이브의 목소리로 쓴다.
  운영성 미션은 `공통`으로 표시한다.

## 2. 설정 변경 (윈터 모드 ①) — 승인 필수

**인접 그래프는 드랍 확률에 쓰인다. 설정 변경이 곧 게임 로직 변경이다.**

1. 변경안을 받는다 (윈터는 문서를 직접 고치지 않는다)
2. 인접 관계를 건드렸으면 **시뮬레이터 검증 결과를 함께 올린다**
3. 고립되는 트라이브가 생기는지 확인한다 — 인접 관계는 "유저가 처음 고른 트라이브에 갇히지
   않게" 하는 장치다
4. 사용자 승인 → 오케스트레이터가 `TRIBES.md`에 반영 (덮어쓰기. 버전 사본을 만들지 않는다)

확률·가중치 수치는 윈터가 정하지 않는다 — 엔진 작업(`engine` 유형 `/jam-work`)이다.

## 3. 창작 (윈터 모드 ③)

아이템 설명은 **10~20개 배치**로 만들어 스크립트로 한 번에 반영한다. 낱개로 돌리지 않는다.
새 아이템·시즌 소재는 **컨텐츠 반응 기록**(픽업률·컬렉션 완성률)을 먼저 본다.

## 4. 시즌 운영·홈피드 (윤진)

| 업무 | 승인 | 반영 |
|---|---|---|
| 미션 제안 (조건·보상·기간, 트라이브 연결 필수) | 필요 | 어드민 등록 |
| 액티비티배지 제안 (활동 조건·기준값) | 필요 | 윈터 검수 → 이미지(`/jam-img`) → 티켓 |
| 체크인배지 제안 (POI·조건) | 필요 | 윈터 검수 → 이미지(`/jam-img`) → 티켓 |
| 아이템배지 제안 | 필요 | 윈터 검수 → 이미지(`/jam-img`) → 티켓 |
| 앰비언트 드랍 일정 | 필요 | 승인 후 실행 |
| 홈피드 '오늘 카드' | **주 1회 7건 묶음** | 어드민 등록, 발행은 카즈하 |
| 시즌 캘린더 | — | 월 1회 갱신 |

- 경제 수치는 기존 허용 범위 안에서만 제안한다. 벗어나면 `/jam-plan`(혜린)의 리스크 점검으로
  넘긴다.
- 시즌 제안에는 **트라이브 분포**를 표시해 쏠림을 드러낸다.
- 제안 전에 **지난 결과 기록**을 먼저 읽는다. 끝난 항목의 결과 한 줄은 카즈하가 남긴다.
- 배지·미션 제안 전에 **최근 리포트의 지표**(`jam-doc/operations/reports/` 주간 4주·월간 3개월)와
  월간 리포트의 "배지·미션 제안 재료" 절을 읽는다.
- 미션은 트렌드와 지표를 반영해 조건을 다양하게 만들어 재미를 준다(거리·장소·시간대·날씨·연속·
  함께하기·수집). 트라이브 연결 필수는 그대로다.
- 제안은 세션에서만 만든다. 월간 예약 작업은 재료만 모은다(`scheduled-jobs.md`).

## 5. 트렌드 수집 (월 1회, 윈터+윤진 한 번에)

- **축 A (윈터)**: 액티비티 씬 유행·밈, 계절 소재, 수집·게임화 사례, 말투·신조어·낡은 표현
- **축 B (윤진)**: 브랜드 프로모션·팝업·콜라보 사례를 **작동 원리** 기준으로 JAM 기능에 대입.
  탐색은 윤진 정의의 "Trend sources" 7곳부터 시작한다(`scheduled-jobs.md` 월간 작업에도 같은 목록)

규칙: 트렌드가 설정을 바꾸지 않는다 · 유행어를 영구 컨텐츠에 넣지 않는다 · 6개월 미채택은
폐기 · 같은 관찰이 3회 이상이면 정체성 보강 후보(승인 필요)

## 금지

- 외부 게시·발송 (전부 승인 후, 실행은 카즈하)
- 문서·코드 직접 수정 (둘 다 안만 낸다)
- 실존 브랜드명·인물 사용
- 기존 기능 밖의 개발이 필요한 제안 → `/jam-plan`으로 넘긴다
