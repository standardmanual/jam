# 팀 공통 규칙

> 설계 원본(아이클라우드 `JAM-WORK/01_공통규칙.md`)을 프로젝트 안으로 이관·정리했다
> (티켓 20260918_0423). 전원이 지키는 규칙이며, 코드 규칙(lint·테스트 등)은 프로젝트
> `CLAUDE.md`에 별도로 있다.

| # | 규칙 |
| --- | --- |
| 1 | 에이전트 정의는 **영어**로 작성한다. 출력은 한국어다 |
| 2 | 카리나가 **티켓 핵심 요약**(요구사항·구현 계획·관련 파일)만 전달한다. 전체 티켓은 필요할 때만 읽는다 |
| 3 | `CLAUDE.md`는 모두에게 필요한 규칙만 남긴다. 카리나 전용 내용은 참고 문서로 옮긴다 |
| 4 | 에이전트 정의에 매번 바뀌는 값을 넣지 않는다. 자주 수정하지 않는다 |
| 5 | 큰 파일은 검색으로 위치를 찾은 뒤 그 부분만 읽는다 |
| 6 | 이상 신호는 **참고 / 주의 / 중단**, 확신도는 **높음 / 보통 / 낮음** |
| 7 | 하니 말투(사용자에게 보이는 글의 말투)는 전체 설정이 끝난 뒤 정한다 |
| 8 | 한국어 문장 지침(`docs/specs/UX_WRITING_GUIDELINE.md`)을 사용자에게 보이는 모든 글에 적용한다 |
| 9 | **슬롭 제거** — 글·시각·설계 세 종류를 각 담당이 관리한다 (아래 표) |
| 10 | 평소 개발 흐름에는 4명만 관여한다 (카리나·아현·민지·채원) |
| 11 | **묶음 승인** — 문서 갱신은 머지 승인과 함께, 홈피드는 주 1회 7건, 티켓 우선순위는 주간 브리핑에서 |
| 12 | 예약 작업은 2개로 묶는다. 주간(브리핑+피드 초안), 월간(트렌드+문서 점검+시즌 제안) — 스펙은 `scheduled-jobs.md` |
| 13 | 스크립트는 1차 7개(`verify`·diff 정리·현황판·승인 후 처리·어드민 API 읽기·작업 공간 준비·push hook), 나머지는 2차. 목록은 `automation-list.md` |
| 14 | 리스크는 시점으로 나눈다. 만들기 전 혜린 / 코드 단계 민지 / 운영 중 카즈하 |
| 15 | 문서는 시점으로 나눈다. 신규 기능 정의 혜린 / 구현 결과 반영 아현 / 누락 점검 민지 / 체계·템플릿·정기 점검 하니 |
| 16 | 데이터 쓰기·읽기는 DB 직접이 아니라 **어드민 API**를 통한다. 권한 검사와 검증 로직을 그대로 탄다 |
| 17 | 모델은 에이전트 정의의 `model` 키로 고정한다. 메인 세션은 `settings.json`의 `model`로 고정한다 |
| 18 | 서브에이전트는 호출마다 `CLAUDE.md`를 읽는다. **아현·민지만 코드 규칙이 필요하지만, 이를 선택적으로 뺄 수 있는 공식 기능이 Claude Code에 없어(티켓 20260918_0422 확인) 실제로는 8개 전부가 받는다** |
| 19 | `settings.json` 거부 목록에 `Bash(git commit --no-verify)`·`Bash(git push --no-verify)`를 넣어 검사 우회를 막는다 |
| 20 | 요약본·지도·패턴 카드를 만들지 않는다. 원본을 검색해서 필요한 부분만 읽는다 (사본이 낡는 위험을 없앤다) |
| 21 | 개선 리뷰 단계는 두지 않는다. 위험을 줄이는 개선점은 민지의 범위 밖 발견물로 처리한다 |
| 22 | 티켓에 **완료 조건**(무엇을 어떻게 확인하면 끝인지)을 반드시 적는다 — 템플릿 참조 |
| 23 | 사용자가 제안을 거절하면 **이유를 결정 기록에 남긴다** — `forms/decision-record-format.md` |
| 24 | 미션·홈피드·드랍·캠페인이 끝나면 **결과 한 줄**을 남긴다. 다음 제안은 그 기록을 먼저 본다 — `forms/outcome-record-format.md` |
| 25 | 여러 에이전트가 얽힌 작업은 **상위 티켓 1개 + 하위 티켓** 구조로 묶는다 |
| 26 | 처리 규칙표는 **공용**이다. 에이전트별 섹션을 두고 각자 자기 섹션만 읽는다 — `handling-rules.md` |
| 27 | 문서는 **한 저장소**의 두 폴더에 있다. 코드와 같은 커밋에서 바뀌는 문서는 `docs/`, 기획·마케팅·운영 자료는 `jam-doc/`. 경로는 작업 폴더 기준으로 적고, 격리 워크트리에도 `jam-doc/`이 함께 들어 있어 직접 읽고 고친다 (2026-09-20 재통합, 티켓 20260920_1412) |

## 슬롭 제거 기준

| 종류 | 걷어낼 것 | 담당 |
| --- | --- | --- |
| 글 슬롭 | 상투구("~을 통해", "혁신적인", "여정"), 번역투, 과장, 의미 없는 수식, 반복, 이모지 남발, 내용 없는 서론·맺음말 | 글 쓰는 전원 + 게이트 리뷰(민지, 체크리스트 12번) |
| 시각 슬롭 | 의미 없는 그라디언트·유리질 효과, 뜻 없는 아이콘, 습관적 가운데 정렬, 재고 이미지 느낌 | 채원 (배지 이미지는 윈터와 함께) |
| 설계 슬롭 | 의미 없는 기능·배지 남발, 근거 없는 효과 주장, 채우기용 화면, 가짜 긴급감 | 혜린·민지·카즈하 |

**작동 방식:** JAM 문장 사전(`docs/specs/SLOP_DICTIONARY.md`, 금칙 표현 + 대체 표현)
→ `scripts/check-slop.mjs`가 패턴 매칭 가능한 부분을 `verify` 단계에서 기계적으로 거름 →
문맥 판단이 필요한 나머지(사전 §4)는 게이트 리뷰(민지)가 직접 판정 → 사용자가 거슬린 표현을
사전에 추가. 초기 목록은 AI 씬의 보편 기준으로 시작한다(2026-09-18부터 별도 `humanize-korean`
플러그인 호출을 없애고 이 경로로 통합, 티켓 20260918_1033).
