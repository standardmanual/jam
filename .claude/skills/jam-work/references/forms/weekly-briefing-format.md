수집 실패: 출처 (사유) → 비어 있는 항목      ← 실패가 있을 때만, 맨 위에

## 계획 대비 실행
## 지표
## 위험

## 멈춘 티켓 (2주 이상)
## 다음 주 일정

## 선별 동의율            체크된 줄 / 전체 줄 (카즈하 모드 ③ 선별 리포트 기준)

## 비용                  이번 실행의 토큰 사용량 (임시 상한 15만, 4회 실측 후 재설정)

VOC 절은 VOC 경로를 구축하기 전까지 두지 않는다(카즈하 모드 ②가 꺼져 있음).

## 지표 출처

| 출처 | 지표 |
| --- | --- |
| GA4 Data API (`scripts/ga4-weekly-metrics.mjs`) | 활성 유저 · 가입 완료 · 온보딩 완료 · 드랍 · 픽업 · 믹스 성공 · 미션 참가 |
| 어드민 집계 API (`/api/admin/kpi/weekly`) | 미션 달성자 수 · 배지 발급량 · Strava 동기화 실패 |

> **현재 상태(2026-09-18):** 어드민 집계 API는 미션 달성자 수·배지 발급량·Strava 동기화 실패를 숫자로 반환한다. Strava 동기화 실패는 티켓 20260918_1307에서 만든 `strava_sync_failures` 테이블(마이그레이션 176, 2026-09-18 실행)을 센다. 기록은 해당 코드가 배포된 환경에서만 쌓이므로, 프로덕션 반영(`/jam-ship`) 전 기간의 0건은 "실패 없음"이 아니라 "기록 전"으로 적는다. 배지 중복 발급(DB 제약상 불가)과 앰비언트 드랍 만료(설계상 만료 없음)는 **지표에서 제외**한다(사용자 결정).

- "0건이면 고장" 판정은 어드민 집계 API 값으로만 한다. GA4는 광고 차단기 유저를 놓치고 일부
  이벤트가 특정 경로에서만 계측된다.
- **집계 수치만 쓴다.** 닉네임·이메일·유저 ID는 쓰지 않는다. 개별 사례는 "의심 계정 N건, 어드민
  화면에서 확인 필요"로만 적는다.
- 경제 지표의 정상 범위가 정해지기 전까지는 "이상" 판정 대신 수치만 보고한다.

## 워크플로 수치 계산 (티켓 20260921_2308)

`node scripts/ticket-metrics.mjs --since YYYY-MM-DD`(지난 리포트 이후 날짜)를 실행해 나온
마크다운 표를 리포트의 「워크플로 수치」 절에 그대로 붙인다. 이 스크립트는 CLOSED 티켓
완료 기록의 「실행 지표」 고정 표(`docs/tickets/_TEMPLATE.md` 참고, 20260921_0841 표준)만
읽는다 — 표가 없는 옛 티켓은 문장을 긁지 않고 "미기록"으로만 센다. 루프 장부(머지·반려 수)는
2단계(20260921_2234 §5) 도입 전까지 0으로 나온다.

## 선별 동의율 계산 (티켓 20260921_2306)

지난 1주간 쌓인 `jam-doc/operations/reports/triage/YYYY-MM-DD.md` 파일들에서
**체크된 줄 수 / 전체 줄 수**로 계산한다. 선별 루틴이 아직 등록 전이거나 대상 티켓이 없어
쌓인 파일이 없는 주는 이 칸을 비워 둔다("대상 없음").

## 실행 점검 대조 목록 (①)

홈피드(예약 글이 떴나) · 미션(기간·달성자 0명이면 조건 오류 의심) · 배지 발급(급증·급감) ·
앰비언트 드랍(예정대로·픽업률) · Strava 동기화 실패율 · 배포 상태 · 승인했는데 미반영된 티켓
**+ 배포 후 핵심 플로우 점검:** 로그인 → 동기화 → 배지 획득 → 지도 픽업

뉴스레터는 기능이 없어 대조 목록에서 뺐다.
