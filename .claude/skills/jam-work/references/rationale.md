# 규칙의 근거와 이력

> 규칙 문서에서 규칙만 남기고 옮겨 온 경위·실측·티켓 번호다. 범위는 `/jam-work` 절차(`SKILL.md`·`references/`)와
> jam-work 밖 규칙 문서(`CLAUDE.md`, 에이전트 정의, 다른 스킬, 문서 체계, 라이팅 규칙, `docs/agents/` 운영 문서)다.
> 판단 근거가 되는 실측과 사고만 옮기고, 단순 이력은 git 이력에 맡긴다. 규칙을 풀거나 바꿀 때만 읽는다 — 절차를
> 실행할 때는 각 규칙 문서만으로 충분하다. 팀 전체의 사고 원장(사고 → 지금의 장치)은 `docs/agents/team-operations.md`
> §8이다. 앞쪽 절 번호는 `SKILL.md`와 같고, 그 밖의 문서는 「jam-work references」와 「jam-work 밖 규칙 문서」 아래에 둔다.

## 4.1 staging push

커밋 단위로 push하던 관행이 20일간 staging 커밋 1,212개 = 배포 1,212개를 만들어 Build CPU만
$66.15가 나왔다(2026-09-06 실측). `vercel-ignore.sh`의 판정 기준이 "직전 커밋"이 아니라 "직전에
실제로 빌드한 커밋"인 이유는 한 push에 코드·문서 커밋이 섞여도 코드 변경을 놓치지 않기 위해서다.
push마다 도는 jam-stage 빌드가 Vercel 비용의 대부분이라, 2026-11-10 사용자 지시로 push는 사용자가 요청할 때만
하고 staging 빌드는 `[배포]` 표식 커밋에서만 돌린다(티켓 20261110_0907, 규칙 ③). 리뷰 브랜치 push는 규칙 ①로
빌드가 돌지 않아 비용 근거가 없으므로 요청 전 push 금지의 대상에서 뺐다(2026-11-26 사용자 결정, 상위 티켓
20261125_1923 10회차).
