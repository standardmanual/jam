## 공통 원칙

### 무엇을 예약 실행하나 (안건 2·4-8)

- 예약 실행 대상은 **점검형(카즈하·하니)** 과 **형식이 고정된 반복 초안**(윤진의 홈피드 7일치 등)뿐이다.
- 되묻기가 핵심인 일(혜린·윈터·윤진의 기획·창작·시즌 제안)은 워크플로로 만들지 않고 세션에서
  `/jam-plan`·`/jam-story`로 대화하며 진행한다. 백그라운드 실행은 중간에 사용자에게 물을 수 없기
  때문이다.
- 단서(4-8): 형식이 고정되어 방향이 틀릴 여지가 적고, 승인이 어차피 사후에 이뤄지는 반복 초안은
  예약 실행해도 된다.

### 실행 환경 (4-1)

- **클라우드 예약 작업**(claude.ai/code/routines)에서 실행한다. PC·외장 드라이브 상태와 무관하게 돈다.
- 이 PC에만 있는 비밀 값은 쓸 수 없다. 필요한 값은 클라우드 환경에 따로 등록한다:
  `ADMIN_API_READ_TOKEN`(어드민 읽기 토큰, 티켓 1149), `GA4_PROPERTY_ID`·`GA4_SERVICE_ACCOUNT_KEY`
  (GA4 읽기, 티켓 1151).

GA4는 광고 차단기 유저를 놓치고 일부 이벤트가 특정 경로에서만 계측되므로, "0건이면 고장" 판정은
어드민 집계 API 값으로만 한다.

### 개인정보 (4-6)

리포트와 Slack 글에는 **집계 수치만** 남긴다. 닉네임·이메일·유저 ID 등 개인 식별 정보는 쓰지
않는다. 개별 사례는 "의심 계정 N건, 어드민 화면에서 확인 필요"처럼만 적는다.

### 저장 위치와 읽기 상한 (3-1·3-2)

- 주간: `Service Plan/Reports/주간/YYYY-Www.md` · 월간: `Service Plan/Reports/월간/YYYY-MM.md`
- 쌓기만 하고 덮어쓰지 않는다(`Reports/README.md`).
- 에이전트는 **주간 최근 4주·월간 최근 3개월**만 읽는다. 오래된 기록은 필요할 때 찾아 읽는다.

### 실패 처리 (4-10)

- 수집 출처(GA4·집계 API·Vercel 등)가 실패하면 **그 출처만 1회 재시도**한다.
- 그래도 실패하면 나머지로 리포트를 완성하고, 맨 위에 `수집 실패: 출처 (사유) → 비어 있는 항목`을 적는다.
- 리포트 파일 자체를 만들지 못하면(전체 실패) `#jam-alert`에 알린다. 세션 시작 hook도 예정 시각이
  지났는데 리포트가 없으면 감지한다(티켓 20260918_1153).

### 모델과 비용 상한 (4-11)

- 예약 작업의 에이전트는 **모두 Sonnet**으로 실행한다.
- 임시 상한: **주간 15만 · 월간 30만 토큰**(월간은 웹 검색 때문에 두 배).
- 매 실행의 실제 사용량을 리포트 "비용" 절에 기록한다. **4회 실행 뒤** 실측값으로 상한을 다시 정한다.
- 도구가 토큰 상한을 강제로 끊지 못하면, "상한에 가까우면 수집을 멈추고 있는 자료로 마무리"하라는
  지시와 사후 기록으로 운영한다(확인은 티켓 1156).
