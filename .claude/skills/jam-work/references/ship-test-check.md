## 점검 범위 — 다섯 시나리오

커밋 범위(`baseSha..headSha`)의 diff에서 로직이 바뀐 부분마다 아래 다섯 시나리오 중 테스트로
덮이지 않은 것을 공백으로 보고한다.

| 시나리오 | 예시 |
|---|---|
| 해피 패스 | 정상 입력이 기대한 출력을 내는가 |
| 빈 입력 | 빈 문자열·빈 배열·null·undefined |
| 경계값 | 최소·최대·0·음수 |
| 오류 경로 | 잘못된 입력·네트워크 실패·타임아웃 |
| 동시성 | 빠른 반복 호출·순서가 뒤바뀐 응답 |

## 안티패턴 — 발견하면 주의로 보고

| 안티패턴 | 문제 |
|---|---|
| 구현 세부사항을 테스트함 | 리팩터링만으로 깨진다 |
| 스냅샷 남용 | 아무도 diff를 검토하지 않는다 |
| 테스트 간 공유 가변 상태 | 테스트끼리 서로 오염시킨다 |
| 서드파티 코드를 테스트함 | 우리 버그가 아닌데 시간을 쓴다 |
| CI 통과를 위한 skip | 실제 버그를 숨긴다 |
| 지나치게 느슨한 assertion | 회귀를 못 잡는다 |
| async 오류를 처리하지 않음 | 오류가 삼켜져 거짓 통과가 난다 |
