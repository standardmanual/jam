# JAM! Phase 14 PRD — 드랍 메뉴 개선 (POI 상태 기반 단일 플로우)

> 작성일: 2026-07-25
> 로직 원천: `jam-web/src/app/(main)/drops/DropsClient.tsx`, `jam-web/src/components/map/MapView.tsx`, `jam-web/src/app/api/drops/`
> 데이터 원천: `poi`, `poi_drops`, `inventory`, `inventory_items`, `badges`(`src/types/database.ts`)

---

## 1. 배경 및 목표

### 현행 분석 (2026-07-25 코드 확인)

**이미 있는 것:**
- `/drops` 화면 — 헤더에 "드랍 · 픽업" 타이틀, 상단 **드랍 모드 / 픽업 모드 탭**, 지도는 카드형(풀스크린 아님)으로 하단에 배치.
- 지도 마커 색상: 드랍 있음(초록 `#22c55e`) / 범위 내 드랍 없음(회색) / 범위 밖(어두운 회색+반투명). 배지 종류·개수는 마커에 표시 안 됨.
- POI 클릭 시 지도 아래 바텀시트 — **현재 선택된 모드에 따라** 드랍 가능한 내 인벤토리 목록 또는 픽업 가능한 드랍 목록을 세로 리스트로 보여줌.
- 드랍: `POST /api/drops` — 50m 반경 검증(`isUserNearPoi`) 후 `poi_drops` INSERT, 해당 인벤토리 아이템은 `dropped_at`/`drop_id` 기록으로 논리 삭제.
- 픽업: `POST /api/drops/[dropId]/pickup` — 50m 반경 검증 + GPS 조작 탐지(`src/lib/abusing/`) 후 `pickup_drop()` RPC(원자 트랜잭션)로 소유권 이전.
- 앰비언트(시스템 자동) 드랍: 활동 완료 시 `src/lib/drop-engine/`가 별도로 `poi_drops`에 `source='system'`으로 INSERT(유저가 직접 드랍한 것과 같은 테이블, `source` 컬럼으로만 구분).
- 인벤토리 화면(`/inventory`)의 3열 그리드 카드 UI — 현재 `page.tsx`에 인라인으로 작성되어 있고 별도 재사용 컴포넌트로 분리되어 있지 않음.
- 배지 상세 화면(`/badges/[id]`) — 이미지·이름·희귀도·설명·획득조건·획득정보·연결 POI 버튼 등 완성된 UI 존재.

**이번 Phase에서 바뀌는 것:**
- 드랍/픽업 **모드 탭 개념을 완전히 제거**. 유저는 모드를 고르지 않고 곧바로 POI를 누르며, 그 POI가 "배지를 갖고 있는지"에 따라 시스템이 자동으로 드랍 화면 또는 픽업 화면을 보여준다.
- 화면 타이틀 제거, 지도를 페이지 전체 풀스크린으로 사용.
- 인벤토리 그리드 카드 UI를 공용 컴포넌트로 추출해 `/inventory`와 드랍 바텀시트 양쪽에서 재사용.

### Phase 14 목표

1. **모드 없는 단일 플로우** — POI 클릭 → 그 POI의 현재 배지 보유 상태로 화면 분기(드랍 UI vs 픽업 UI). 유저가 미리 "드랍할지 픽업할지" 선택할 필요 없음.
2. **몰입감 있는 풀스크린 지도** — 헤더 타이틀 제거, 지도가 화면 전체를 차지.
3. **POI에 아이템배지가 여러 개 동시에 존재 가능** — 한 곳에 여러 유저(또는 시스템)가 드랍한 배지가 쌓일 수 있고, 지도에서는 여전히 "배지 있음=초록"으로 단순 표시.
4. **기존 인벤토리 그리드 UI를 드랍 화면에서도 동일하게 사용** — 사용자가 이미 익숙한 카드 UI를 그대로 재사용해 학습 비용을 줄인다.
5. **배지 상세화면 UI를 픽업 플로우에서도 재사용** — 새 UI를 만들지 않고 기존 `/badges/[id]` 스타일을 픽업 확인 화면에 적용.

## 2. 확정된 결정사항 (인터뷰 결과)

| 항목 | 결정 |
|------|------|
| 드랍/픽업 모드 탭 | **완전 제거.** POI 상태(배지 있음/없음)로 화면이 자동 분기된다. |
| 한 POI당 동시 드랍 가능 개수 | **제한 없음(여러 개 가능).** 기존 `poi_drops` 스키마가 이미 POI당 여러 행을 허용하므로 스키마 변경 불필요. |
| 인벤토리 그리드 UI 재사용 방식 | **공용 컴포넌트로 추출**(`src/components/inventory/InventoryGrid.tsx` 신규) 후 `/inventory` 페이지와 드랍 바텀시트 양쪽에서 import. |
| 앰비언트(시스템) 드랍 표시 | **유저 드랍과 동일하게 초록 마커로 표시.** 지도 상에서 드랍 주체(유저/시스템)를 구분하지 않는다. |
| 근접 제한(50m) 유지 여부 | **유지.** 어뷰징 방지 인프라(`src/lib/abusing/`, `isUserNearPoi`)는 이번 범위와 무관하게 그대로 작동 — 지도 마커의 "범위 밖 흐림" 표시도 유지하되, 배지 유무(초록) 표시가 우선 노출된다. |

## 3. 사용자 여정

### 3-1. 화면 진입

```
1. 유저가 /drops 진입
2. 헤더 타이틀 없이 지도가 화면 전체를 채움
3. 주변 POI가 마커로 표시됨 — 배지 있는 POI는 초록, 없는 POI는 회색, 반경 밖은 흐리게
```

### 3-2. 배지 없는 POI를 눌렀을 때 (드랍)

```
1. POI 마커 클릭 → 바텀시트 등장 (POI 이름 + "아직 아이템이 없어요" 안내 + [드랍] 버튼)
2. [드랍] 버튼 클릭 → 인벤토리 그리드 UI(공용 컴포넌트) 표시 — 보유한 아이템배지 카드 목록
3. 배지 카드 하나 선택 → "드랍하시겠습니까?" 확인/취소 다이얼로그
4. [확인] → POST /api/drops 호출 → 성공 시 바텀시트가 "드랍 완료" 상태로 전환, 방금 드랍한 배지가 POI 바텀시트에 표시됨
```

### 3-3. 배지 있는 POI를 눌렀을 때 (픽업)

```
1. POI 마커 클릭 → 바텀시트 등장 (POI 이름 + 그 POI에 있는 아이템배지 목록, 여러 개면 전부 나열)
2. 배지 하나 선택 → 배지 상세화면 UI(기존 /badges/[id] 스타일 재사용) 오버레이로 표시
3. 하단에 [픽업]/[취소] 버튼
4. [픽업] → POST /api/drops/[dropId]/pickup 호출 → 성공 시 상세화면 닫힘 → POI 바텀시트로 복귀(픽업한 배지는 목록에서 사라짐, 남은 배지 있으면 계속 표시)
```

## 4. 기능 요구사항

### 4-1. 화면 레이아웃

| 항목 | 내용 |
|------|------|
| 헤더 타이틀 | 제거 (필요 시 뒤로가기 버튼만 최소한으로 유지) |
| 지도 영역 | `100dvh` 풀스크린. 기존 카드형 래퍼(둥근 모서리·테두리·그림자) 제거 |
| 모드 탭 | 완전 제거 |

### 4-2. 지도 마커

| 상태 | 표시 |
|------|------|
| POI에 픽업 가능한 배지가 1개 이상(`available_drops_count > 0`, source 무관) | 초록 |
| POI에 배지 없음, 반경 내 | 기존 회색 유지 |
| 반경 밖 | 기존 흐림 처리 유지 |
| 선택된 POI | 기존처럼 마커 확대 |

- 배지 개수/종류에 따른 색상 세분화는 이번 범위 아님(초록 단색 유지).

### 4-3. POI 바텀시트 — 상태 분기

```
GET /api/drops/poi/[poiId] (기존 API 재사용/확장 — 해당 POI의 현재 available 배지 목록 반환)

배지 목록이 비어있음 → "드랍" 상태 UI (4-4)
배지 목록이 1개 이상 → "픽업" 상태 UI (4-5)
```

### 4-4. 드랍 플로우

1. [드랍] 버튼 → 공용 인벤토리 그리드 컴포넌트 오픈 (보유 아이템배지, 이미 드랍된/장착된 아이템 제외 — 기존 `/inventory` 목록 필터 로직 재사용)
2. 카드 선택 → 확인 다이얼로그("'{배지명}'을 여기에 드랍하시겠습니까?" / 확인·취소)
3. 확인 → 기존 `POST /api/drops` 호출 (변경 없음, 50m 검증 등 기존 로직 그대로)
4. 성공 → 바텀시트에 방금 드랍한 배지 카드 표시 + 완료 안내

### 4-5. 픽업 플로우

1. POI가 보유한 배지 목록(여러 개 가능) → 각 항목 클릭 가능한 카드/리스트로 표시
2. 항목 클릭 → 배지 상세화면 UI(기존 `/badges/[id]` 컴포넌트 스타일 재사용, 이 배지가 "이 POI에 드랍되어 있음" 컨텍스트로 표시) + 하단 [픽업]/[취소] 버튼
3. [픽업] → 기존 `POST /api/drops/[dropId]/pickup` 호출 (변경 없음, 50m·어뷰징 검증 그대로)
4. 성공 → 상세화면 닫고 POI 바텀시트로 복귀, 목록에서 픽업한 항목 제거(남은 배지 있으면 계속 노출, 없으면 드랍 상태로 전환)

### 4-6. 인벤토리 그리드 공용 컴포넌트화

- `src/app/(main)/inventory/page.tsx`에 인라인으로 있던 3열 그리드 카드 UI(희귀도별 배경색, 만료 임박 표시, 빈 슬롯 placeholder)를 `src/components/inventory/InventoryGrid.tsx`로 추출.
- `/inventory` 페이지는 이 컴포넌트를 그대로 사용(동작 변경 없음).
- 드랍 바텀시트는 이 컴포넌트를 "선택 모드"(클릭 시 페이지 이동 대신 `onSelect(item)` 콜백)로 사용.
