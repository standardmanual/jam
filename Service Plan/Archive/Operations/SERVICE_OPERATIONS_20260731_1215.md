## [근본 원인 수정] 드랍/픽업 지도에서 POI 누락 — max-rows 제한 (동일 원인 재발)

**배경**: Phase 17(JAM 지도 개편) 배포 직후 유저가 실서비스에서 "산/지하철 POI 배지는 나오는데 기존 드랍/픽업 가능한 POI들이 표시되지 않는다"고 리포트. Phase 17 코드(`/api/poi-badges`, `MapView.tsx`, `DropsClient.tsx`)를 전부 재검토했으나 드랍/픽업 관련 로직은 이번 커밋에서 변경된 바 없음을 diff로 확인.

**진짜 원인**: `SERVICE_OPERATIONS_20260731_1130.md`에서 `matcher.ts`(활동-POI 매칭)에 대해 이미 진단·수정했던 것과 **완전히 동일한 원인**이 `/api/drops/route.ts`에도 남아있었음. 이 라우트는 `service.from('poi').select('*')`로 POI 테이블을 **3곳에서 전체 조회**하고 있었는데, `poi` 테이블이 현재 2,105행(직접 조회로 확인)으로 Supabase/PostgREST 기본 max-rows 제한(1,000행)을 넘어서면서, 응답이 앞쪽 1,000행으로 잘린 상태였음. 유저가 보고한 하남 스타필드 지역의 경우 DB에는 편의점·음식점 등 드랍 가능 POI가 다수 존재함을 직접 쿼리로 확인했으나(잘린 1,000행 밖에 위치해) API 응답에 전혀 포함되지 못하고 있었음.

**수정**: `matcher.ts`와 동일한 패턴으로, 세 곳의 `.select('*')`를 요청 좌표 기준 bbox 쿼리(`.gte/.lte('latitude'/'longitude', lat/lng ± 0.01°)`, 약 1.1km 반경 — 실제 사용 반경 500m보다 여유 있게)로 교체. 결과 행 수가 크게 줄어(하남 예시: bbox 적용 시 19행) max-rows 제한에 걸릴 일이 없어짐.

**검증**: 수정 후 동일 bbox 조건으로 직접 DB 조회해 19건이 정상 반환됨을 확인. `npx tsc --noEmit`/`npx eslint` — 이번 수정 관련 신규 에러 없음(기존 `any` 관련 lint 경고 3건은 수정 전부터 동일하게 존재, git stash로 대조 확인).

**관련 파일**: `jam-web/src/app/api/drops/route.ts`. `matcher.ts`와 마찬가지로 `poi` 테이블을 전체 조회하는 다른 코드가 더 있는지는 이번엔 점검하지 않음 — 향후 유사 증상 재발 시 우선 의심할 것.

**남은 영향 범위**: 이 버그는 Phase 17과 무관하게 `poi` 테이블이 1,000행을 넘어선 시점부터 존재했을 것으로 추정되며, 지역에 따라 드랍/픽업 POI가 임의로 누락되는 문제가 이전부터 있었을 수 있음(이번에 처음 신고됨). 소급 영향 분석은 진행하지 않음.
