# [Infra] POI 드랍 테이블 및 RLS 마이그레이션

## 배경 / 문제 정의
Phase 7에서 유저 드랍/픽업 시스템 도입. 드랍 기록을 추적하고 RLS(Row Level Security)로 권한 관리해야 함.

## 상세 요구사항

### 테이블 스키마
**poi_drops**
- `id` (uuid, PK)
- `poi_id` (uuid, FK → poi.id)
- `dropper_user_id` (uuid, FK → users.id, NOT NULL)
- `dropped_at` (timestamp, NOT NULL, DEFAULT now())
- `expires_at` (timestamp, NOT NULL, DEFAULT now() + INTERVAL '30 days')
- `is_available` (boolean, DEFAULT true) — 픽업 완료/만료 시 false
- `created_at` (timestamp, DEFAULT now())
- `updated_at` (timestamp, DEFAULT now())

**인덱스**
- (poi_id, is_available, dropped_at DESC) — 특정 POI의 활성 드랍 조회
- (dropper_user_id, dropped_at DESC) — 유저의 드랍 이력

### RLS 정책
1. **SELECT**: 인증된 모든 유저가 조회 가능 (is_available=true인 것만)
2. **INSERT**: 인증된 유저만 자신이 드랍 생성 가능 (dropper_user_id = auth.uid())
3. **UPDATE**: dropper_user_id가 자신이거나, 타 유저의 픽업에 의한 is_available 업데이트만 가능
4. **DELETE**: 어드민만 가능 (또는 30일 만료 자동 소각)

## 구현 계획
1. `supabase/migrations/004_poi_drops.sql` 생성
2. 마이그레이션 스크립트에 테이블 + 인덱스 + RLS 정책 포함
3. `src/types/supabase.ts`에 `Database['public']['Tables']['poi_drops']['Row']` 타입 추가
4. Supabase JS 라이브러리 버전 확인 (^2.x)
