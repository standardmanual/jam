# [Infra] Google 로그인 화면 supabase.co 도메인 노출 검토

## 배경 / 문제 정의
Google 로그인 팝업에 "계정을 선택하세요. `ceehnkzdbecxwzxrhhns.supabase.co`(으)로 이동"이라는 문구가 표시됨. Supabase OAuth 플로우 구조상 Google의 redirect_uri가 Supabase 도메인으로 설정되어 있어 발생하는 현상. 서비스 도메인(`j-a-m.app`)으로 표시되도록 변경 검토.

## 상세 요구사항

### 서비스/코드베이스 관점
- Google 로그인 화면에 표시되는 도메인을 `j-a-m.app`으로 변경
- 현재 구조: 사용자 → Google → `supabase.co/auth/v1/callback` → `j-a-m.app/auth/callback`
- 목표 구조: 사용자 → Google → `j-a-m.app/...` (직접 처리)

## 구현 계획

### 검토한 방법들

**방법 A: Supabase Custom Domain**
- Supabase의 Auth 엔드포인트를 커스텀 도메인으로 프록시
- Pro 플랜 이상 필요 (유료)
- Google redirect_uri가 커스텀 도메인으로 변경됨

**방법 B: Next.js에서 Google OAuth 직접 처리 (무료)**
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`을 서버에서만 사용
- `/api/auth/google/start` → Google OAuth URL 생성 후 리디렉트
- `/api/auth/google/callback` → code 교환 → `supabase.auth.signInWithIdToken()` 호출
- Google 로그인 화면에 `j-a-m.app` 노출됨
- 클라이언트에 어떤 키도 노출되지 않음

**방법 C: Google Cloud Console에서 redirect_uri 직접 추가**
- 승인된 리디렉션 URI에 `https://j-a-m.app` 추가만으로는 해결 안 됨
- Supabase SDK가 내부적으로 `supabase.co/auth/v1/callback`을 redirect_uri로 사용하기 때문
