# [Service] 피드 이벤트 날짜 — 실제 활동 날짜로 기록 (백필 시 오늘 날짜 버그 수정)

## 배경 / 문제 정의

`sihyunrr@gmail.com` 계정의 `last_synced_at`을 null로 리셋한 후 동기화하자,
2026-03-18 ~ 2026-07-23 기간의 과거 활동 150여 건이 일괄 처리됐다.
이 과정에서 발급된 배지·드랍 피드 이벤트가 모두 처리 시각(2026-08-10 13:04)으로
`event_at`이 기록되어, 피드에 오늘 날짜로 표시됐다.

## 원인

`recordFeedEvent()`가 `event_at`을 별도 파라미터로 받지 않고 항상 DB 기본값
(INSERT 시점의 NOW())을 사용했기 때문. 과거 활동을 처리할 때도 피드 삽입은
현재 시점에 이뤄지므로, 트리거 활동 날짜가 아닌 처리 시각이 기록됐다.

## 수정 내용

**`recordFeedEvent` 시그니처 변경:**
```ts
// before
recordFeedEvent(userId, eventType, metadata)
// after
recordFeedEvent(userId, eventType, metadata, eventAt?: string)
```
- `eventAt` 미지정 시 DB 기본값(NOW()) 사용 — 기존 동작 보존

**각 호출부에 활동 날짜 전달:**
- `badge-engine/index.ts`: `triggerActivity?.startDate` 전달
- `drop-engine/index.ts`: `insertDrop()` → `activityStartDate` 파라미터 추가 후 전달
- `sync.ts`: POI 배지 `recordFeedEvent` 호출 시 `rawActivity.start_date` 전달

## 데이터 복구 (수동 SQL)

이미 잘못 기록된 이벤트를 실제 활동 날짜로 직접 UPDATE:

| 이벤트 유형 | 대상 이벤트 수 | 적용 날짜 기준 |
|---|---|---|
| `badge_earned` (액티비티 배지) | 8건 | `user_activity_badges.triggered_by_activity_date` JOIN |
| `badge_earned` (POI 배지) | 1건 | `user_poi_badge_earns.triggered_by_activity_date` |
| `item_dropped` | 4건 | `user_drop_state.last_activity_at` (2026-07-22) |

### 주요 의사결정
- `eventAt` 미지정 시 NOW() 폴백 유지 — 실시간 활동(정상 동기화)은 처리 시점 ≈ 활동 시점이라 영향 없음
- 드랍 엔진의 `insertDrop()` 내부까지 전달 방식 선택 (드랍 엔진이 recordFeedEvent를 직접 호출하는 구조라 파라미터 체인이 필요했음)

- `mission_completed` 피드 이벤트는 이번 수정 범위 외 (`checkMissions`도 동일하게 eventAt 미전달이나, 미션은 기간 단위 달성이라 "트리거 활동 날짜" 개념이 불명확해 보류)
