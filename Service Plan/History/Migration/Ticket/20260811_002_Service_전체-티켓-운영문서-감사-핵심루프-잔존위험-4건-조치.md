## 배경 / 문제 정의
20260811_001(인벤토리 미생성 인시던트) 이후, 같은 유형("코드/DB 변경 중 관련된 걸 놓쳐서 조용히 보상 미발급")의 문제가 더 있는지 점검해 달라는 요청을 받음. 티켓 146개(이 중 68개는 실제 내용 없이 옛 `SERVICE_OPERATIONS_*.md`를 가리키는 placeholder) + 운영 이력 문서 66개 전체를 5개 에이전트로 나눠 조사하고, 상위 위험 항목은 실제 운영 DB·현재 코드와 대조 검증했다.

## 조사 결과 요약

**이미 해결된 것으로 확인**: 커서 롤백 버그(전수 재확인, 추가 피해자 없음), UTC/KST 시간대 문제(현재 `startDateLocal` 기준으로 정상 반영), 대용량 테이블 1000행 조회 절단(POI 매칭·드랍 지도 API 모두 bbox로 구조적 해결됨), 공유 RPC 함수 드리프트(`handle_new_user` 외 전수 대조 결과 없음), 산 배지 반경(50m→150m로 완화됨, 단 재실측 검증은 안 됨).

**지금도 살아있는 것으로 확인되어 이번에 조치**: 아래 "구현 내용" 참고.

## 구현 내용 요약

1. **포인트 지급 실패 로깅을 `awardPoints()` 내부로 중앙화** — 기존엔 6개 호출부(배지/드랍/미션×2/조합/어드민) 중 드랍·배지 2곳만 각자 `logEngineDecision`으로 감쌌고 나머지 4곳(미션 2곳, 조합, 어드민 지급)은 실패해도 `console.error`만 남기고 아무 데도 기록되지 않았음. `awardPoints()` 함수 자체가 실패 시 `engine_decision_log`에 `points/point_award_failed`로 기록하도록 옮겨 6곳 전체를 한 번에 커버. 기존에 이미 감싸고 있던 드랍·배지 쪽 중복 래핑은 제거(이중 기록 방지).
2. **드랍엔진 "인벤토리 없음"/"드랍 구조 없음" 조기 종료 경로에 로깅 추가** — 이번 인시던트의 원인은 고쳤지만 증상(실패해도 아무 기록도 안 남는 사각지대)은 그대로였음. `tryItemDrop()`의 두 조기 return 지점에 `logEngineDecision('drop', 'drop_attempt', ..., { outcome: 'no_inventory' | 'no_drop_structure' })` 추가 — 같은 클래스의 문제가 다른 원인으로 재발해도 이제 DB에서 바로 감지 가능.
3. **마이그레이션 번호 045 중복 정리** — `045_point_system.sql`(22:20 커밋)이 `045_poi_search_cache_empty_ttl.sql`(22:09 커밋, 11분 먼저)과 번호가 중복돼 있던 것을 발견. 이미 운영 DB엔 오래전 적용된 상태라 내용은 그대로 두고 파일만 `080_point_system_renumbered_from_045_duplicate.sql`로 재배치(신규 환경 셋업 시 혼동 방지).
4. **드랍엔진 아이템배지 후보 조회를 페이지네이션으로 전환** — 활성 아이템북 기준 아이템배지가 현재 900개로 PostgREST 기본 max-rows(1,000) 제한에 근접해 있었음(전체 아이템배지는 3,600개). 컨텐츠가 조금만 늘어도 과거 POI/산 배지 인시던트와 똑같이 조용히 잘려나갈 수 있는 임박한 위험이라, `fetchAllRows()` 헬퍼로 `.range()` 기반 전체 순회 조회로 구조적으로 전환.
5. **부수 발견 — 회귀 테스트 3건이 08-10 타임존 수정 이후로 깨져 있던 것을 발견·수정**: `badge-engine/__tests__/new-conditions.test.ts`의 주말/계절/월별 조건 테스트가 `startDate`만 오버라이드하고 `startDateLocal`은 기본값(2026-07-20, 월요일)에 그대로 남겨둔 채였음. 프로덕션 코드가 `startDateLocal` 우선으로 바뀐 뒤(08-10) 이 테스트들의 의도(토요일/일요일/특정 월 활동 시뮬레이션)가 깨져 3개가 실패 상태였음 — CI 게이트가 없어 아무도 모르고 있었음. 테스트 픽스처에 `startDateLocal`을 함께 오버라이드하도록 수정.

### 주요 의사결정 / 핵심 메모
- **로깅 중앙화 위치**: 각 호출부에서 개별적으로 실패를 감지·기록하게 하지 않고 `awardPoints()` 함수 자체에 넣기로 결정 — "호출부마다 챙겨야 하는 체크리스트"를 없애고 "함수 하나만 고치면 전부 커버"되는 구조로 바꾼 것이 이번 감사에서 반복 확인된 프로세스 실패 패턴(사람이 기억해서 각자 챙겨야 하는 구조)에 대한 직접적 대응.
- **max-rows 위험의 근본 해결 범위**: `badges` 테이블 전체를 페이지네이션하는 대신, 실제로 위험한 지점(드랍엔진의 활성 아이템북 조회)만 우선 전환. 어드민 전용 조회(`/admin/badges` 등)는 이미 `.limit(5000)`으로 명시 상한이 있어 낮은 우선순위로 판단, 이번 범위에서 제외.
- **44개 지하철 POI 오탐, UTC 이전 데이터 소급보정**: 코드 수정이 아니라 데이터 조사·재검증이 선행돼야 해서 이번 티켓에서 분리. 별도 확인 후 필요 시 후속 티켓.
