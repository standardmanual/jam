# [UI] 뒤로가기 네비게이션 UX 정책 수립 및 적용

## 배경 / 문제 정의

TopNav 컴포넌트의 `title` prop이 두 가지 역할로 혼용되고 있다:
- **현재 화면명** (search: "검색", points: "포인트", profile/edit: "프로필 편집")
- **뒤로가기 레이블** (missions: "미션", inventory: "인벤")

TopNav의 실제 렌더 구조는 `[← title ──────] [rightSlot]` 으로, title은 항상
"← 아이콘 옆 텍스트 = 뒤로가기 레이블"로 작동한다. 즉 title을 현재 화면명으로
쓰는 것은 구조적 오용이며 iOS HIG Back Button 패턴과도 어긋난다.

## 상세 요구사항

### 서비스/코드베이스 관점

**UX 정책 기준 (확정):**

| 조건 | title | backHref |
|---|---|---|
| 목록→상세, 진입 경로 고정 | 목록 화면명 ("미션", "인벤") | 있음 |
| 프로필→하위 화면 | 유저명 (username) | 있음 |
| 다양한 경로로 진입 가능 | `d.common.back` ("뒤로") | 없음 (router.back) |
| 탭바 루트 화면 | 없음 | showBack=false |

**수정 대상 5곳:**
1. `search/page.tsx` — title="검색" → title={d.common.back}
2. `profile/edit/page.tsx` — title="프로필 편집" → title="프로필"
3. `points/page.tsx` — title="포인트" → title={d.common.back}
4. `[username]/following/page.tsx` — title="N명 팔로잉" → title={username}
5. `[username]/followers/page.tsx` — title="N명 팔로워" → title={username}

### UI/UX 관점

- title은 "어디로 돌아가는가"를 뜻한다. 현재 화면명이 아니다.
- UX_WRITING_GUIDELINE.md에 뒤로가기 네비게이션 정책 섹션 신설
- 디자인시스템 `jam-web/design-system/components/navigation/TopNav.prompt.md`에
  back-label 결정 정책 추가

### 주요 의사결정 / 핵심 메모

- profile/edit은 d.profile.title("프로필") 재사용 — 별도 i18n key 추가 불필요
- following/followers의 미사용 t import 제거 (코드 품질 개선, 스펙 범위 내)
