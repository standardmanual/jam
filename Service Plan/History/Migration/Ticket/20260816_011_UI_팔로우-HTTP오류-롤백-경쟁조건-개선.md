# [UI] 팔로우 HTTP 오류 롤백 완성 및 경쟁 조건 해소

## 배경 / 문제 정의
티켓 010 개선 리뷰에서 두 가지 미비점 제기:
1. fetch()는 네트워크 단절만 reject — 4xx/5xx는 정상 resolve이므로 현재 try/catch로는 서버 오류 시 롤백 불가
2. handleFollow/handleListFollow 실행 중 연속 클릭 시 낙관적 업데이트와 롤백이 뒤섞이는 경쟁 조건

## 상세 요구사항

### 서비스/코드베이스 관점 (`ProfileClient.tsx`)
1. **HTTP 오류 롤백**: 각 fetch() 후 `if (!res.ok) throw new Error(res.statusText)` 추가
   - handleFollow의 DELETE/POST fetch 두 곳
   - handleListFollow의 DELETE/POST fetch 두 곳
2. **경쟁 조건 방지**: followLoading 상태(boolean) 추가
   - handleFollow 진입 시 true, 완료 시 finally에서 false
   - 헤더 팔로우 버튼에 disabled={followLoading} 적용
   - handleListFollow는 targetId별로 독립 동작하므로 listFollowStates 구조 활용 가능 —
     별도 loading 맵 또는 간단히 낙관적 업데이트 직후 중복 클릭을 막는 방식 적용
