# [UI] 카드/버튼 보더라인 제거 + 신규 배경톤 도입 + 모듈러 동기화

## 배경 / 문제 정의
현재 서비스 전반의 카드·버튼 컴포넌트에 1px 보더라인(실제 구현은 `shadow-[inset_0_0_0_1px_var(--token)]`
방식)이 적용되어 있고, 일부 화면(예: 미션 상황보기 리스트)에는 `<hr>` 대신 1px 높이 div로 구현한
구분선이 하드코딩 색상으로 박혀 있다. 사용자는 이 얇은 보더라인과 구분선을 전부 제거하고, 보더가
없어져도 카드 영역 구분이 가능하도록 블랙(#000000)보다 살짝 밝고 `#222222`보다는 어두운 신규 배경색
토큰을 카드·버튼 배경으로 쓰길 원한다.

**사전 조사에서 발견한 중요 사실**: `jam-web/design-system/`(모듈러 카탈로그)는 Storybook 전용이며
실제 Next.js 앱 빌드에 포함되지 않는다. 프로덕션 카드·버튼의 실제 구현은 `jam-web/src/components/ui/`와
`jam-web/src/app/(main)/**`에 있고, 토큰 값은 두 곳에 **수동으로 동기화**되어 있다(자동 import 아님).
또한 `design-system/readme.md`에는 "보더는 명시적 요구가 있는 경우를 제외하고 절대 사용하지 않음"이라고
이미 문서화되어 있는데, 실제 프로덕션 코드는 정반대로 거의 모든 카드에 보더를 쓰고 있어 문서-코드 불일치가
있었다. 이번 작업으로 프로덕션 코드가 오히려 모듈러의 기존 원칙에 맞춰지는 방향이 된다.

## 상세 요구사항

### 서비스/코드베이스 관점 — 1차 작업 (프로덕션 코드)

**신규 토큰 추가** (`src/app/globals.css`)
- 현재 다크 계열: `--color-bg` #000000 < `--color-surface` #1a1a1a < `--color-bg-tint` #222222
- "블랙보다 살짝 밝고 #222222보다 어두운" 신규 레벨 토큰을 추가한다 (예: `--color-surface-elevated`
  또는 `--color-card-bg`, 제안값 `#121212` — Material Dark 컨벤션과 유사한 미세 엘리베이션 레벨).
  기존 `--color-surface`(#1a1a1a)를 재정의하지 말 것 — 이미 여러 곳에서 다른 의미로 쓰이고 있어
  값 변경 시 회귀 범위가 커진다. **신규 토큰**을 별도로 추가해 보더 제거로 구분이 사라지는 카드·버튼에만
  적용한다.
- 라이트 테마 오버라이드 블록(`@media prefers-color-scheme: light`, `:root[data-theme="light"]`)에도
  대응 값을 추가한다 (다크 대비 관계를 라이트에서도 유지 — 예: `--color-surface`보다 살짝 진한 톤).

**보더 제거 대상 (조사 완료 목록, 파일:라인)**
- `src/components/ui/Card.tsx:25` — `shadow-[inset_0_0_0_1px_var(--color-border-inverse)]` 제거.
  단 이 카드는 inverse(흰 배경) 카드이므로 보더 제거 후 구분이 필요하면 흰 카드에는 신규 다크 토큰이
  적용되지 않는다 — 라이트 계열에서 구분 방법(그림자 없이, 여백/톤 차이 등)을 개발자가 판단해 처리.
- `src/components/ui/ListRowCard.tsx:20` — `--color-border` 보더 제거, 신규 배경톤 적용.
- `src/components/ui/BadgeGridCard.tsx:49` — selected 상태 2px 보더(`--color-text`) 제거 여부 검토
  (selected 상태 표시는 기능적 의미가 있으므로 보더 대체 수단 — 배경톤 또는 다른 표시 방식 — 확인).
- `src/components/ui/Button.tsx:59,64` — outline variant의 인셋 보더(`--color-border-light`,
  `--color-border-inverse`) 제거. outline 버튼은 보더가 정체성이므로 제거 시 신규 배경톤으로 채워진
  필형 버튼으로 전환하거나, 대체 시각 표현을 결정해 문서(README 주석)에도 남긴다.
- `src/components/ui/BottomSheet.tsx:139,172`, `TabBar.tsx:145`, `Toast.tsx:45`,
  `SlidingTabs.tsx:56,65` — 각 보더 제거, 필요한 곳은 신규 배경톤으로 구분.
- `src/app/(main)/**` 내 인라인 보더 27개 파일 (admin 제외) — 대표: `FeedSection.tsx`,
  `TodayCardStack.tsx`, `CombineClient.tsx`, `MissionDetailClient.tsx`, `MissionStatusClient.tsx`,
  `MissionsListClient.tsx`, `badges/[id]/page.tsx`, `DropsClient.tsx`, `onboarding/page.tsx`,
  `profile/edit/page.tsx` 등. 카드/버튼 형태로 쓰인 보더만 제거 대상 — 단순 입력창 포커스 링 등
  기능적 보더는 유지.
- **하드코딩 색상 → 토큰 치환** (이번 작업 대상 라인에 한함, 전체 리팹토링 아님):
  `MissionStatusClient.tsx:270-271,312,345,573`(`#2A2A2A`,`#3A5A3A`,`#1E1E1E`,`#2E7D52`),
  `MissionsListClient.tsx:30,111` — 보더/구분선 제거 작업과 겹치는 라인은 토큰 참조로 바꾼다.

**`<hr>` 및 구분선 제거**
- 실제 `<hr>` 태그는 0건(이미 없음). 대신 `<hr>`과 동일한 역할을 하는 div 기반 구분선을 제거한다.
  - `MissionStatusClient.tsx:326` — `행 구분선: 1px solid #1E1E1E` div. 제거하고 신규 배경톤으로
    행 사이 구분(예: 짝수/홀수 행 배경 교차, 또는 행 자체를 카드화)하는 방식으로 대체.
  - `MissionStatusClient.tsx:573` 동일 패턴.
  - 한쪽 방향 inset-shadow로 구현된 구분선(`FeedSection.tsx:156`, `CombineClient.tsx:234`,
    `today/[cardId]/page.tsx:30`, `DropsClient.tsx:408`, `InventoryItemHistorySheet.tsx:71`,
    `BottomSheet.tsx:172`)도 리스트 행 구분 목적이면 동일하게 제거·대체 대상으로 검토.

**어드민 제외**: `src/app/admin/`, `src/components/admin/`는 이번 작업 대상이 아니다 (정책 예외).

### UI/UX 관점
- 보더 제거 후에도 카드/버튼 경계가 시각적으로 인지되어야 한다 — 신규 배경톤이 실제로 페이지 배경
  (`--color-bg` #000000)과 구분되는지 반드시 화면에서 눈으로 확인한다.
- outline 버튼처럼 보더가 곧 컴포넌트 정체성인 경우는 기계적 삭제가 아니라 대체 표현(배경 채움 등)을
  설계한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. **신규 토큰**: `--color-surface-elevated`(#1f1f1f, 다크) 추가. `src/app/globals.css` `@theme` 블록에
   추가해 `bg-surface-elevated` Tailwind 유틸리티로 사용 가능. (main) 페이지 대부분이 `bg-surface`를
   페이지 캔버스로 쓰고 있어(실측 확인) `--color-bg`(#000)가 아니라 `--color-surface`(#1a1a1a)보다
   밝게 잡아야 카드가 실제로 "떠 보인다" — 그 결과값이 #1f1f1f.
2. **컴포넌트 8종 보더 제거** (Card, ListRowCard, BadgeGridCard, Button, BottomSheet, TabBar, Toast,
   SlidingTabs):
   - 흰(inverse) 카드/토스트/탭바처럼 다크 페이지 위에서 색 대비만으로 이미 구분되는 요소는 보더만
     삭제(대체 불필요) — Card(inverse), TabBar, Toast, UserSearchBar 등.
   - `bg-surface`를 배경으로 쓰던 다크 카드(페이지 캔버스와 같은 색이라 보더 없이는 구분 불가)는
     `bg-surface-elevated`로 교체 — ListRowCard, badges/[id] 정보 카드들, MissionDetailClient의
     InfoCard, PoiMapButton/실물패치 버튼 등.
   - Button outline variant: main surface는 `bg-surface-elevated` 채움, sub surface는 4% 블랙 틴트
     채움으로 전환(보더 대신 필형 버튼).
   - BadgeGridCard selected 2px 보더 → `bg-[var(--color-primary)]/15` 배경 채움(기능적 의미 유지).
   - BottomSheet 드래그 핸들: 속 빈 보더 원 → 실제 채워진 바(`bg-white/20`/`bg-black/20`)로 교체.
   - SlidingTabs `outlined` 변형: `--tabs-bar-border` 제거, `.jam-tabs-outlined`를
     `background: var(--color-surface-elevated)`로 전환(실제 서비스 4개 호출부 모두 `outlined={false}`
     라 현재 화면 영향 없음, API만 정리).

   다크 컨테이너 위는 `bg-surface-elevated` 또는 기존 `bg-border`(진행바 트랙 등 이미 필 방식으로 쓰이던
   토큰) 재사용으로 대체. 이미지가 콘텐츠를 완전히 채우는 경우(배지 이미지, 커버 이미지 등)는 대체 없이

### 주요 의사결정 / 핵심 메모
- **`--color-surface-elevated` 값 산정 근거**: 티켓 제안값(#121212 부근)은 "블랙 캔버스" 전제였으나,
  실측 결과 (main) 페이지 래퍼 대부분이 `--color-bg`(#000)가 아니라 `bg-surface`(#1a1a1a=26)를 페이지
  배경으로 쓰고 있었다. 카드가 그 위에서 밝아 보이려면 26보다 커야 하므로 26~34(`--color-bg-tint`) 구간
  안에서 `#1f1f1f`(31)로 정했다. 티켓 예시값보다 밝은 쪽으로 조정한 것으로, 실제 화면 확인 시 밝기
  조정이 필요하면 이 토큰 한 곳만 바꾸면 된다.
- **프로덕션 라이트 테마 오버라이드는 추가하지 않음**: 티켓 1차 섹션은 `src/app/globals.css`에 라이트
  오버라이드 블록이 있다고 전제했으나, 조사 결과 프로덕션에는 그런 메커니즘이 전혀 없다(`html { color-scheme:
  dark }`만 있고 `@media (prefers-color-scheme: light)`/`data-theme` 분기는 존재하지 않음 — 다크 전용).
  신규 토큰 하나에만 라이트 값을 추가하면 다른 토큰은 그대로 다크값이라 OS 라이트 모드 사용자에게 부분적으로
  깨진 화면을 보여줄 위험이 있어, 프로덕션 쪽 라이트 오버라이드는 만들지 않았다. design-system에는 기존에
  DS-019 라이트 오버라이드 메커니즘이 이미 있어 그쪽에는 라이트 값을 정상 추가했다.
- **`--radius-card`(모듈러) vs `--radius-cards`(프로덕션)**: 이번 조사에서 재확인된 기존 간극. 이번
  보더/배경 변경과 직접 관련이 없어 이번 티켓에서는 손대지 않음 — 별도 티켓 대상.
- **design-system `Accordion.jsx`/`ModalToast.jsx`의 보더**: 둘 다 프로덕션에 대응 사용처가 없음
  (`src/components/ui/accordion.tsx`는 어떤 화면에서도 import되지 않는 미사용 컴포넌트). 이번 변경과
  "직접 관련된 것만 반영" 범위를 지키기 위해 손대지 않음.
- **`_ds_manifest.json`**: 자동 생성 추정 파일로 이미 다른 값들(radius-card 10px 등)이 실제 소스와
  어긋나 있어 이번 신규 토큰도 반영하지 않았다 — 수동 편집 시 포맷 손상 위험이 있고, 이번 변경 범위 밖의
  기존 불일치라 판단.
- **Button.jsx(모듈러)의 `border: '2px solid transparent'`**: 이미 투명이라 화면에 보이지 않는 보더라
  "제거 대상 보더"가 아니라고 판단해 손대지 않음(레이아웃 시프트 위험 대비 여지로 보임).

### 잔여 이슈
- 신규 톤(`#1f1f1f`) 및 각 대체 배경(`bg-black/[0.04~0.08]`, 4% 블랙 틴트 등)이 실제 기기/브라우저에서
  카드·버튼 경계로 충분히 인지되는지 시각 확인 필요 (이번 세션은 브라우저 렌더링 도구 없이 코드 레벨로만
  진행).
- MissionDetailClient.tsx 확인 취소 버튼(`variant="outline"`)이 부모 InfoCard와 같은
  `--color-surface-elevated`를 쓰게 되는 충돌을 발견해 해당 인스턴스만 `rgba(255,255,255,0.08)`로
  인라인 오버라이드했다 — 임시 처치이며, Button 컴포넌트가 "카드 안에 놓인 outline 버튼"을 인식하는
  근본적인 elevation 체계는 없다. 유사 중첩이 추후 다른 화면에서 또 나올 수 있음.
- design-system `Accordion`/`ModalToast`의 보더, `--radius-card`/`--radius-cards` 네이밍 통일,
  두 컴포넌트 트리(프로덕션 vs design-system) 전체 통합은 별도 티켓 대상으로 남김.
