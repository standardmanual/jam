# [UI] 세계관·컬렉션 배경테마 일괄 적용 + 배경 레이어 폭 보정

## 배경 / 문제 정의
두 가지를 함께 처리한다.

1. **[20260818_001]** 원 요청의 2번 항목("어드민의 세계관 또는 컬렉션 PRD에서 이 기능을 하위
   컨텐츠에 일괄 적용할 수 있도록 선택값을 노출") — Phase 2로 미뤄뒀던 부분을 이번에 개발한다.
2. **버그**: [20260818_003]에서 만든 배지 상세 고정 배경 레이어(`position: fixed; inset: 0`)가
   브라우저 전체 폭을 덮는다. 앱은 `(main)/layout.tsx`에서 `max-w-[430px] mx-auto`로 폭이
   제한되는데, 데스크톱처럼 뷰포트가 430px보다 넓은 환경에서는 배경색이 앱 컬럼 바깥
   (원래 검은색이어야 하는 여백)까지 덮어버린다. **배경색은 TopNav와 같은 폭(앱 서비스 폭,
   최대 430px)에만 적용하고, 그 바깥의 기존 검은 배경은 그대로 유지해야 한다.**

## 확정된 결정 사항
- 세계관(factions)·컬렉션(item_books) 어드민에도 배지와 동일한 배경색(피커+hex+자동추출 없음,
  수동 입력만)·쉐이더(임시 placeholder) 필드를 추가
- 하위 배지 반영 방식은 **일괄 적용 버튼(1회성 복사)** — 자동 fallback 아님. 버튼을 누르는
  순간 값을 하위 배지들의 `background_color`/`background_shader_id`에 실제로 복사해 넣는다.
  이후 개별 배지에서 자유롭게 수정 가능하지만, 세계관/컬렉션 값을 나중에 바꿔도 자동 반영은
  안 됨(다시 눌러야 함) — 명확히 안내 문구로 고지
- 배경 레이어는 **TopNav와 같은 폭(앱 컬럼, 최대 430px, 중앙 정렬)**으로 제한. 그 바깥 여백은
  기존 검은 배경 유지

## 상세 요구사항

### 서비스/코드베이스 관점

1. **배경 레이어 폭 보정** (버그 수정)
   - 대상: `jam-web/src/app/(main)/badges/[id]/page.tsx`의 `badgeBackgroundLayer`
   - 현재: `style={{ position: 'fixed', inset: 0, zIndex: 0, pointerEvents: 'none', ... }}`
   - 변경: `inset: 0` 대신 `top: 0, bottom: 0, left: '50%', transform: 'translateX(-50%)',
     width: '100%', maxWidth: '430px'`로 — `(main)/layout.tsx`의 앱 컬럼(`max-w-[430px]
     mx-auto`)과 동일한 폭·중앙정렬을 유지하면서 fixed 특성(스크롤에 안 끌려감)은 유지
   - 검증: 뷰포트를 430px보다 넓게(예: 1280px 데스크톱) 리사이즈했을 때 배경색이 앱 컬럼
     밖으로 새어나가지 않는지 Playwright로 확인

2. **DB 스키마**
   - `factions` 테이블에 `background_color` (text, nullable), `background_shader_id`
     (text, nullable) 컬럼 추가
   - `item_books` 테이블에 동일하게 `background_color`, `background_shader_id` 컬럼 추가
   - 마이그레이션 파일 작성: `jam-web/supabase/migrations/087_add_faction_itembook_background_columns.sql`
   - **SQL 파일 작성까지만 — 실행은 오케스트레이터가 사용자 승인 후 별도 처리**

3. **어드민 세계관 폼** (`jam-web/src/app/admin/factions/FactionForm.tsx`)
   - 배경색 필드 추가: 색상 피커 + hex 입력 + 스와치 + 지우기 (자동 평균컬러 추출 없음 —
     세계관은 특정 이미지 1장에 종속되지 않으므로 수동 입력만)
   - 쉐이더 임시 드롭다운 추가: [20260818_003]의 `BADGE_BACKGROUND_SHADER_OPTIONS`를 그대로 재사용
   - **"하위 배지에 일괄 적용" 버튼** 추가 (세계관 수정 화면, 신규 등록 시에는 비활성 —
     저장된 세계관에만 하위 배지가 존재)
     - 클릭 시 확인 다이얼로그: "이 세계관에 속한 배지 N개의 배경색이 지금 이 값으로 즉시
       덮어써집니다. 개별 배지에서 따로 지정한 색상도 모두 이 값으로 바뀝니다. 계속할까요?"
       (N은 사전 조회한 실제 하위 배지 수)
     - 확인 시 `badges.faction_id = 이 세계관 id`인 모든 배지의 `background_color`/
       `background_shader_id`를 세계관 폼의 현재 값으로 UPDATE
     - 완료 후 "N개 배지에 적용했어요" 토스트/안내 표시
     - 안내 문구: "이후 세계관 색상을 바꿔도 이미 적용된 배지에는 자동 반영되지 않아요.
       다시 이 버튼을 눌러야 해요."

4. **어드민 컬렉션(아이템북) 폼** (`jam-web/src/app/admin/itembooks/ItemBookForm.tsx`)
   - 세계관 폼과 동일한 배경색/쉐이더 필드 + "하위 배지에 일괄 적용" 버튼
   - 하위 배지 기준: `badges.item_book_id = 이 아이템북 id`

5. **API**
   - `POST /api/admin/factions/[id]/apply-background` — body 불필요(폼이 이미 저장된 상태의
     현재 값을 사용하거나, 저장 직후 값을 함께 전달), 응답에 적용된 배지 수 포함
   - `POST /api/admin/itembooks/[id]/apply-background` — 동일 패턴
   - 두 라우트 모두 적용 전 최신 폼 값이 먼저 저장돼 있어야 함 (저장 안 된 상태에서 일괄
     적용 시도 시 막거나, 저장까지 함께 처리 — 구현 시 UX 흐름 판단은 jam-developer에게 위임)

6. **재사용**
   - 배경색 피커+hex+스와치+지우기 UI가 이제 3곳(BadgeForm, FactionForm, ItemBookForm)에
     반복되므로, 공통 컴포넌트로 추출 권장 (예: `src/components/admin/BackgroundColorField.tsx`)
     — 어드민 전용이라 MODULAR 대상 아님, 서비스(어드민) 내부 재사용 컴포넌트로 추출

### UI/UX 관점
- 일괄 적용은 **파괴적 작업**(기존 개별 배지 커스터마이징을 덮어씀)이므로 확인 다이얼로그 필수,
  실행 취소 기능은 없음(개별 배지에서 다시 수정 가능하다는 점만 안내)
- 신규 노출 텍스트(확인 다이얼로그, 완료 토스트, 안내 문구)는 UX Writing 가이드 준수
  (해요체, [현상]→[원인]→[해결책] 불필요한 경우 생략 가능하나 파괴적 작업이므로 결과 명확히 고지)

### DS 재사용 판정 (오케스트레이터, 1.5단계)
- 전부 admin 정책상 MODULAR 탐색 대상 아님
- 배경색 필드 공통 컴포넌트 추출은 서비스(어드민) 내부 재사용이지 MODULAR 승격 대상 아님

## 구현 계획
1. 배지 상세 고정 배경 레이어 폭 보정 (버그 수정, 최우선)
2. `087_add_faction_itembook_background_columns.sql` 마이그레이션 작성
3. 배경색 피커 공통 컴포넌트 추출 (`BackgroundColorField.tsx`)
4. FactionForm·ItemBookForm에 배경색/쉐이더 필드 + 일괄 적용 버튼 추가
5. `/api/admin/factions/[id]/apply-background`, `/api/admin/itembooks/[id]/apply-background` 구현
6. Playwright로 (a) 배경 레이어 폭 보정 확인 (b) 일괄 적용 동작 및 확인 다이얼로그 (c) 기존
   배지 개별 편집 회귀 없는지 검증
