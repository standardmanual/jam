# [Admin] 배경테마 제너레이터 스파이크 (프로토타입)

## 배경 / 문제 정의
배지 상세화면(`/badges/[id]`) 배경테마 기능을 쉐이더+패턴+애니메이션으로 확장하는 방향을
티켓 [20260818_001](20260818_001_Feature_배지상세-배경테마-등급태그-커스터마이징-기획검토.md)에서
"쉐이더 기술 스택(CSS vs WebGL) 결정 보류"로 남겼고, 이후 별도 대화(2026-08-18~19)에서 다음과 같이
설계를 확정했다:

- 어드민에서만 저작(Paper Shaders 단독, Three.js 제외), 유저단은 static 이미지/반복 영상만 렌더링
- 패턴 모드(그리드/오프셋/대칭반복/크기/Gap/stagger/회전) 또는 애니메이션 모드(collidingScopes 기반
  Canvas2D 스크립트, 리퀴드 왜곡류) 중 배타적 선택
- 그 결과 위에 전역 Paper 필터 1종 선택 적용: fluted glass / image dithering / halftone dots /
  halftone cmyk / lens distortion (`@paper-design/shaders-react`)

실제 구현 착수 전에, 이 설계가 기술적으로 실현 가능한지 스파이크로 검증하고 최종 옵션 세트를
확정해야 한다. 이번 티켓은 **정식 기능이 아니라 검증용 프로토타입** 개발 범위다.

## 상세 요구사항

  **독립 라우트**로 개발한다. DB 변경 없음.
- 신규 의존성: `@paper-design/shaders-react` 추가. Three.js 등 다른 WebGL 라이브러리는 추가하지 않는다.

  라이브러리가 아니라 데모 사이트 소스코드 묶음이므로, 리퀴드 왜곡류 애니메이션에 필요한 로직만
  조사해서 발췌/포팅한다. MIT 라이선스 확인됨.
- **로그인 없이 접근 가능한 단독 URL**로 제공한다. 기존 인증 미들�어(어드민 인증)를 이 라우트에는
  적용하지 않도록 예외 처리한다. 예: `/spike/background-generator`
- **스테이징에만 존재한다.** main으로 머지하지 않는다 — 이 스파이크의 목적은 검증이며, 최종 기능
  스펙이 확정되면 이 프로토타입 코드는 폐기하거나 재작업하는 것을 전제로 한다.

- **패턴 모드(7종)**: XY 그리드/오프셋/대칭반복/이미지 크기/Gap/Row·Column stagger/회전. "오프셋"만
  순수 CSS `background-position`으로 라이브 적용하고, 나머지(대칭반복·Gap·stagger·회전·크기)는 반복

- **애니메이션 모드**: collidingScopes/liquify(MIT)의 핵심 로직만 발췌해 TypeScript 클래스로 이식
  (`liquify/perlin.ts`, `liquify/engine.ts`). Perlin 노이즈로 브러시 중심을 자동으로 소용돌이
  이동시키며 픽셀을 스미어(smear)하는 제너레이티브 애니메이션이 그대로 재현된다.

  halftone-dots/halftone-cmyk/lens-distortion 각각 검증.
- **GIF 프레임 테스트**: 업로드 파일이 GIF일 때만 노출되는 비교 패널 — "정지 프레임"(image prop에
  GIF URL을 그대로 전달)과 "실시간 갱신"(살아있는 `<img>`의 현재 프레임을 250ms마다 캔버스로
  캡처해 새 data URL로 재주입) 두 결과를 나란히 비교할 수 있다.

### 주요 의사결정 / 핵심 메모

**1) GIF를 Paper 필터에 넣으면 프레임 단위로 처리되는가 → 아니오, 정적 텍스처로 고정된다.**
`@paper-design/shaders-react`의 `shader-mount.js`를 코드 레벨로 확인한 결과:
- `image` prop에 문자열(URL)을 넘기면 내부에서 `new Image()`로 **한 번만** 디코드해 `processedUniforms`에
  넣는다(`shader-mount.js` `processUniforms()`, img.onload 시점 1회).
- 텍스처 업로드(`setTextureUniform` → `gl.texImage2D`)는 uniform 값이 바뀔 때만 실행되고, 캐시 키는
  `HTMLImageElement`의 경우 `src 문자열 + naturalWidth/Height`다(`areUniformValuesEqual`/`uniformCache`).
  즉 **같은 GIF URL을 계속 넘겨도 최초 디코드 시점의 프레임에서 영원히 고정**되며, GIF 자체의
  프레임 애니메이션은 셰이더 쪽에서 전혀 반영되지 않는다.
- **대안(스파이크에서 실제 구현·검증함)**: 브라우저에 실제로 애니메이션 재생 중인 `<img>` 엘리먼트의
  "현재 프레임"을 캔버스에 `drawImage()`로 캡처한 뒤 `canvas.toDataURL()`로 매번 새로운 문자열을
  만들어 `image` prop에 다시 주입하면, 문자열이 바뀔 때마다 캐시가 무효화되어 텍스처가 재업로드된다
  → 프레임 단위(스로틀링된) 애니메이션 재현 가능. 다만 매 프레임(60fps) 캡처+인코딩+재업로드는
  비용이 크므로, 스파이크에서는 250~400ms 간격으로 스로틀링했다. 정식 기능에서 이 방식을 쓰려면
  스로틀 간격/성능 예산을 별도로 정해야 한다. (구현: `GifFrameTest.tsx`, `AnimationPanel.tsx`의
  `onSnapshotChange` 인터벌)
- 프로덕션 방향(메모리 `project_background_theme_shader_stack_decision`)이 "유저단은 static
  이미지/영상으로 굽는다"이므로, 실제로는 어드민 저작 단계에서 최종 결과를 정지 이미지 또는 짧은
  반복 영상으로 한 번 구워서 저장하면 되고, 이 GIF-텍스처 캐싱 이슈는 **어드민 라이브 편집 화면**에서만
  신경 쓰면 된다는 점도 함께 확인했다.

**2) collidingScopes 포팅 — 정확히 무엇을 가져왔는가.**
`https://github.com/collidingScopes/collidingScopes.github.io`는 안내 조사 결과 리퀴드 왜곡류
애니메이션이 아니라 만화경(kaleidoscope) 데모였다. 같은 조직(collidingScopes) 소유 리포 중
"리퀴드 왜곡류 + Canvas 2D 기반"이라는 티켓 조건에 정확히 부합하는 리포는
`https://github.com/collidingScopes/liquify`(MIT, Alan Ang)였다 — Canvas2D `getImageData`/
`putImageData`로 이미지를 스미어(smear)하는 "liquify" 이펙트, 브러시가 Perlin 노이즈를 따라
자동으로 소용돌이 이동하는 제너레이티브 애니메이션 모드가 이미 내장돼 있어 "리퀴드 왜곡류"라는
요구와 가장 근접했다. (`liquid-shape-distortions`라는 유사 이름의 리포도 있었으나 WebGL 셰이더
기반이라 "Canvas 2D 기반" 조건과 맞지 않아 제외했다.)
- 가져온 것: `perlin.js`(Perlin 노이즈 생성기, 그대로) / `liquify()` 함수(마우스·브러시 속도 기반
  픽셀 스미어 핵심 알고리즘, 그대로) / `startGenerativeDraw()`의 `loop()`(Perlin 노이즈로 브러시
  중심을 자동 이동시키는 제너레이티브 애니메이션, 그대로) / `generatePerlinData()`(방향 그리드 사전
  계산, 그대로).
- 가져오지 않은 것: dat.gui 컨트롤 패널, mp4-muxer 기반 비디오 녹화, 몬드리안/그라디언트 배경
  생성기, 마우스 드래그 수동 스미어의 DOM 이벤트 배선(이 스파이크는 자동 재생 애니메이션만 다룸).
- 포팅 난이도: 낮음. 전역 변수를 클래스 필드로, DOM 이벤트 콜백을 `requestAnimationFrame` 루프
  하나로 정리하는 정도였고 핵심 수식은 손대지 않았다. 라이선스 표기는 이식한 두 파일 상단 주석에
  출처·MIT 라이선스·가져온/가져오지 않은 범위를 명시했다.

**3) Paper Shaders 5종 — 실제 prop명과 애니메이션(시간 기반) 지원 여부.**
5종 모두 `image?: HTMLImageElement | string` prop으로 이미지를 받고, 모두 `ShaderMotionParams`
(`speed?`, `frame?`)를 타입 레벨로 상속한다. 그러나 컴파일된 프래그먼트 셰이더 소스를 직접 grep한
결과, **`u_time`을 실제로 사용하는 것은 halftone-dots 하나뿐**이었다(fluted-glass/image-dithering/
halftone-cmyk/lens-distortion은 `speed`/`frame` prop이 타입에는 존재하지만 셰이더 내부에서 시간을
전혀 참조하지 않아 사실상 no-op). 즉 "이 5종을 애니메이션 배경에 쓸 수 있는가"라는 질문에는
"기본적으로는 정적 필터이고, halftone-dots만 자체적으로 애니메이션된다"가 정답이다. 필터별로
스파이크에서 노출한 실제 prop(라벨 그대로 코드에 사용): fluted-glass(`size`/`distortion`/`blur`/
`angle`/`shape`/`distortionShape`), image-dithering(`size`/`colorSteps`/`type`/`originalColors`),
halftone-dots(`size`/`radius`/`grid`/`type`/`contrast`/`speed`), halftone-cmyk(`size`/`contrast`/
`softness`/`type`), lens-distortion(`spread`/`dispersion`/`lensBulge`/`swirl`/`count`). `type`/
`shape`/`grid` 등 열거형 prop은 숫자가 아니라 **문자열 리터럴 키**(`'random'`, `'lines'` 등)를
받는다 — 패키지가 별도로 export하는 `*Types`/`*Shapes` 런타임 상수 객체는 필터별로 일관되게
공개되지 않아(예: image-dithering은 export 안 됨) UI에서는 문자열 배열을 직접 하드코딩했다.

**4) 패턴 모드 CSS 구현 관련 판단.**
티켓은 "전부 CSS(background-repeat/transform) 레벨로 구현"을 요구했다. "그리드 수"와 "오프셋"은
말 그대로 CSS `background-size`/`background-position`만으로 라이브 처리했다. 그러나 "Row/Column
stagger(벽돌쌓기)"는 **단일 배경 레이어의 `background-size`/`background-position`만으로는 구현이
불가능**하다는 것을 확인했다 — 하나의 레이어는 반복 주기가 균일해서 "짝수 행은 그대로, 홀수 행만
가로로 절반 밀기" 같은 행별 분기를 표현할 방법이 없다(레이어를 두 장 겹치는 방식도 시도했으나 각
레이어가 이미 평면 전체를 100% 덮어버려 "짝수 행만 보이게" 마스킹할 수 없었다). 그래서 대칭반복
(mirror)·Gap·회전·크기와 마찬가지로 stagger도 "반복 가능한 최소 단위(1~2칸)를 캔버스에 구운 뒤
`background-repeat: repeat`로 반복시키는" 방식으로 통일했다. 결과적으로 CSS는 "타일을 반복시키는
역할"만 맡고, 타일 내용 합성(mirror/gap/rotation/stagger)은 캔버스가 담당한다 — 순수 CSS만으로는
7종 옵션을 전부 만족시킬 수 없다는 것이 이번 스파이크의 결론이다. 정식 기능 스펙에서는 이 트레이드
오프를 감안해 "CSS 레벨"을 "타일 반복은 background-repeat, 타일 합성은 1회성 캔버스 굽기"로
구체화하는 것을 제안한다.
Paper 필터에는 CSS 미리보기와 동일한 결과(같은 타일을 미리보기 박스 크기만큼 한 번 더 평면화한
이미지)를 흘려보내 WYSIWYG를 맞췄다(`patternTile.ts`의 `flattenPattern`).

**5) 선택하지 않은 대안.**
- 패턴 전체를 매 프레임 하나의 큰 캔버스로 그리는 방식(순수 JS 렌더링)은 배제했다 — 티켓이 명시한
  "CSS 레벨" 방향에 더 가깝게, 반복 자체는 `background-repeat`가 담당하도록 최소 단위만 굽는 절충안을
  택했다.
- Three.js 등 다른 WebGL 라이브러리는 추가하지 않았다(티켓 명시 제약).
- Paper Shaders의 `paper texture`, `liquid metal`은 import하지 않았다(티켓 명시 제외).
