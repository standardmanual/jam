# [Admin] 배경 제너레이터 스파이크 — 오프셋 행/열 독립 조정 버그 수정

## 배경 / 문제 정의
티켓 [20260819_003](20260819_003_Admin_배경제너레이터-스파이크-패턴오프셋-간격으로-재정의.md)에서
패턴 모드의 "오프셋"을 행 간격/열 간격 두 개의 독립 슬라이더로 재정의했다. 그러나 staging 배포 후
실제로 확인해보니 **두 슬라이더가 서로 독립적으로 동작하지 않고, 둘 다 행과 열에 동시에 영향을
준다**는 버그가 있다. 하나는 행 간격만, 다른 하나는 열 간격만 조정해야 하는데 실제로는 그렇게
동작하지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `PatternPanel.tsx`의 "행 사이 간격" 슬라이더는 오직 `rowGap`(행 사이 세로 여백)만 바꿔야 하고,
  "열 사이 간격" 슬라이더는 오직 `colGap`(열 사이 가로 여백)만 바꿔야 한다. 서로의 값에 영향을
  주면 안 된다.
- `patternTile.ts`의 `buildTileCanvas`(또는 관련 타일 굽기 로직)에서 `rowGap`이 실제로 **세로
  방향(행 사이)** 간격에만, `colGap`이 **가로 방향(열 사이)** 간격에만 반영되는지 코드 레벨로
  직접 확인한다. 티켓 003 완료 기록에 "`tilePitchY - rowGap`, `tilePitchX - colGap`"으로
  구현했다고 돼 있는데, 실제 코드에서 이 축 대응이 뒤바뀌었거나(rowGap이 가로에, colGap이 세로에
  반영) 두 값이 같은 변수에 합산되는 등의 버그가 있을 가능성이 높다 — 직접 코드를 읽고 근본 원인을
  찾아 수정할 것.
- 수정 후 두 슬라이더를 서로 다른 값으로 각각 설정했을 때 타일 결과물이 **가로/세로 비대칭 여백**을
  갖는지 반드시 시각적으로(스크린샷 등) 확인해서 완료 기록에 남긴다 — 이전 두 티켓(002, 003)에서
  브라우저 육안 확인이 누락돼 실제로는 스펙과 다르게 동작하는 버그가 배포까지 흘러갔으므로, 이번엔
  같은 실수를 반복하지 않는다.
- 그 외 제약(스테이징 전용, 로그인 없이 접근, main 머지 금지, 금지 의존성 미추가)은 이전 티켓과 동일.

### UI/UX 관점 (해당 시)
- 두 슬라이더 라벨이 "행 사이 간격"/"열 사이 간격"으로 명확히 구분돼 있는지도 같이 확인한다.

### 컨텐츠 관점 (해당 시)
- 해당 없음

## 구현 계획
1. `patternTile.ts`의 타일 굽기 로직에서 rowGap/colGap이 각각 어느 축에 반영되는지 추적
2. 축 대응이 뒤바뀌었거나 두 값이 잘못 합산/공유되는 지점을 찾아 수정
3. `PatternPanel.tsx`에서 두 슬라이더의 상태 업데이트 핸들러가 서로 다른 필드(`rowGap`/`colGap`)를
   정확히 타겟하는지 확인
4. 수정 후 **반드시 시각적으로 확인**(스크린샷 또는 Playwright)해서 행 간격만 바꿨을 때 세로 여백만,
   열 간격만 바꿨을 때 가로 여백만 변하는지 검증하고 완료 기록에 근거를 남긴다

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- **근본 원인**: `patternTile.ts`의 `buildTileCanvas`에서 `rowGap`/`colGap`은 셀 크기(`cellW`/`cellH`)까지는
  각 축에 맞게 정확히 반영되고 있었다(축이 뒤바뀌거나 합산되는 버그는 아니었음). 문제는 그 다음
  단계 — 이미지를 셀 안에 그릴 때 `image.naturalWidth/naturalHeight` 종횡비를 유지한 채
  "letterbox fit"(더 좁은 쪽 축에 맞춰 다른 축도 비율대로 줄이는 방식)으로 그렸다는 점이다. 그
  결과 `rowGap`을 늘려 `cellH`가 좁아지면, 세로가 fit을 제한하는 축이 되면서 종횡비를 지키기 위해
  `drawW`(가로로 그려지는 실제 크기)까지 함께 줄어들었다 — 이게 "행 간격을 조정했는데 열 방향
  여백도 같이 변한다"는 버그의 정체다. `colGap` 조정 시에도 대칭적으로 동일한 현상이 발생했다.
- **수정**: `drawW = cellW * imageScale`, `drawH = cellH * imageScale`로 변경해 종횡비 보존
  letterbox fit을 제거하고, 가로는 `cellW`(→ `colGap`)에서만, 세로는 `cellH`(→ `rowGap`)에서만
  파생되도록 완전히 분리했다. 이미지가 셀 종횡비와 다를 경우 비균등 스케일(가로/세로 다르게
  늘어나는 왜곡)이 발생할 수 있으나, 이는 "두 슬라이더의 완전한 축 독립성"이라는 티켓 요구사항을
  만족시키기 위한 의도된 트레이드오프다(패턴 스파이크 프로토타입이며 실제 배지 이미지를 정밀
  렌더링하는 화면이 아님).
- `PatternPanel.tsx`의 슬라이더 상태 업데이트 핸들러(`update({ rowGap: ... })` /
  `update({ colGap: ... })`)는 원래부터 서로 다른 필드를 정확히 타겟하고 있어 버그 원인이 아니었다.
  다만 UI/UX 요구사항에 따라 두 슬라이더를 한 줄에 묶어 라벨이 모호했던 것을 "오프셋 — 행 사이
  간격" / "오프셋 — 열 사이 간격" 두 줄로 분리해 각 슬라이더가 어떤 축을 조정하는지 명확히 했다.

  4. 행 간격 40 / 열 간격 10 → 세로 여백이 가로 여백보다 뚜렷하게 넓은 비대칭 결과 확인.
  - 케이스 2·3에서 "한쪽 축만 여백이 생기고 다른 축은 완전히 0"이라는 점이 수정 전 버그(두 축이
    항상 함께 변함)와 대비되는 핵심 증거다. 수정 전 코드로는 케이스 2에서 세로 여백뿐 아니라
    가로 여백도 함께 발생해 타일 사이에 십자형 간격이 생겼을 것(letterbox fit이 두 축을 함께
    제한하므로).

### 주요 의사결정 / 핵심 메모
- 종횡비 보존(letterbox fit)을 포기하고 셀 크기에 그대로 맞추는(non-uniform scale) 방식을
  택했다 — "두 슬라이더 완전 독립"이라는 명시적 요구사항이 "이미지 왜곡 없음"보다 우선한다고
  판단했다. 정식 기능화 시에는 이 트레이드오프를 재검토해야 한다(예: 이미지 자체를 정사각형으로
  전제하거나, 왜곡을 허용할지 여부를 별도 옵션으로 노출하는 등).
- `PatternPanel.tsx`의 슬라이더 라벨을 "오프셋 (행 간격 / 열 간격)" 한 줄에서 "오프셋 — 행 사이
  간격" / "오프셋 — 열 사이 간격" 두 줄로 분리했다. 기능 버그와는 무관하지만 티켓의 UI/UX 확인
  항목("두 슬라이더 라벨이 명확히 구분돼 있는지")에 따른 개선이다.
