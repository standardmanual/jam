# [Admin] 배경 제너레이터 스파이크 — 패턴 모드 그리드 수 제거·실제 서비스 폭 기준 재구성

## 배경 / 문제 정의
현재(티켓 005까지) 패턴 모드는 "그리드 수"와 "이미지 크기 조절" 두 슬라이더가 동시에 최종 이미지
크기(`drawW = baseCellW(그리드수 파생) × imageScale`)를 결정하고 있어, 두 손잡이가 같은 결과값을
두고 충돌한다. 또한 미리보기가 스파이크 자체의 프리뷰 박스 크기 기준으로 렌더링되고 있어, 실제
배지 상세화면(`/badges/[id]`, 앱 컬럼 `max-w-[430px]`)에서 보일 실제 크기와 다르다.

사용자 결정(대화로 확정):
- **그리드 수를 설정 옵션에서 완전히 제거**한다. "넘쳐도 되기 때문에" 그리드 수는 이미지 크기
  설정으로 대체 가능 — 이미지 크기가 유일한 크기 결정 요소가 된다.
- 미리보기는 스파이크의 임의 프리뷰 박스가 아니라 **실제 서비스 가로폭(430px, 배지 상세 앱 컬럼
  폭)을 기준**으로 렌더링한다.
- 이미지 크기 기본값은 **"가로로 5개가 들어가는 크기"** = `430px ÷ 5 = 86px`로 계산해서 표시한다.
  (업로드한 원본 이미지 파일을 강제로 축소 저장하는 게 아니라, 렌더링 시 그 크기로 그리는 것.)
- 오프셋(행 간격/열 간격) 기본값은 0.
- 오프셋을 조정해 이미지+간격의 합이 실제 서비스 폭을 넘어가면, **이미지가 캔버스/미리보기 영역
  밖으로 넘쳐도 된다** — 넘치지 않게 강제로 줄이거나 클리핑하지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `types.ts`의 `PatternParams`에서 `gridX`/`gridY`(또는 그리드 수 관련 필드)를 제거한다.
- 이미지 크기 조절 파라미터를 **실제 서비스 폭(430px) 기준 절대 px 값**으로 재정의한다. 상대
  배율(`imageScale` 곱셈)이 아니라 "이 이미지가 실제 화면에서 몇 px로 보일지"를 직접 의미하는
  값이어야 한다.
- 기본값 계산: `defaultImageSize = 430 / 5 = 86`(px). 이 값을 `DEFAULT_PATTERN_PARAMS`에 반영한다.
- `patternTile.ts`의 `buildTileCanvas`(또는 관련 함수)를 재작성:
  - 미리보기/캔버스 렌더링 기준 폭을 430px(실제 서비스 앱 컬럼 폭)로 고정한다. 스파이크 UI상
    프리뷰 박스의 CSS 표시 크기는 반응형으로 줄어들 수 있어도, **내부 렌더링 좌표계는 항상 430px
    기준**이어야 한다(배지 상세화면에 실제로 적용됐을 때와 동일한 결과가 나오도록).
  - 이미지는 항상 설정된 절대 px 크기로 그려진다. 그리드 수 개념이 없으므로, 반복 개수는
    `(430 + colGap) / (imageWidth + colGap)`처럼 자연스럽게 파생되는 값일 뿐 별도 상태로 관리하지
    않는다.
  - 티켓 005에서 확정한 원칙("간격은 이미지 크기에 영향을 주지 않는다", `pitchX = drawW + colGap`,
    `pitchY = drawH + rowGap`)은 그대로 유지한다.
  - 이미지+간격의 합이 430px보다 커서 반복 개수가 1개 미만이 되거나 경계에서 이미지가 잘리는 것은
    정상 동작이다 — 강제로 맞추거나 clamp하지 않는다.
- `PatternPanel.tsx`에서 그리드 수 슬라이더 UI를 제거하고, 이미지 크기 슬라이더를 px 단위(또는
  실제 폭 대비 %) 절대값으로 노출한다. "약 N개 표시됨" 같은 읽기 전용 파생 정보를 보여주는 건
  선택 사항(있으면 좋지만 필수 아님).
- 그 외 제약(스테이징 전용, 로그인 없이 접근, main 머지 금지, 금지 의존성 미추가)은 이전 티켓과 동일.

### UI/UX 관점 (해당 시)
- 미리보기 영역이 실제 배지 상세 화면과 동일한 비례로 보이는지 확인 (예: 미리보기 박스 자체를
  430px 폭 또는 그 비율로 맞추거나, 최소한 내부 렌더링 좌표계가 430px 기준임을 명시)

### 컨텐츠 관점 (해당 시)
- 해당 없음

## 구현 계획
1. `types.ts`: `PatternParams`에서 그리드 관련 필드 제거, 이미지 크기 필드를 절대 px로 재정의,
   기본값 86px(=430/5) 반영
2. `patternTile.ts`: 렌더링 기준 폭을 430px로 고정, 그리드수 파생 로직 제거, 이미지 크기는 직접
   지정된 px 값 그대로 사용, 넘침 허용(clamp 없음)
3. `PatternPanel.tsx`: 그리드 수 UI 제거, 이미지 크기 슬라이더를 절대값 기준으로 교체
4. Playwright 등으로 시각 검증: 이미지 크기를 86px로 뒀을 때 실제로 430px 폭에 대략 5개가 반복
   되는지, 오프셋을 크게 줘서 이미지+간격 합이 430px를 넘길 때 정상적으로 넘치는지(잘리거나
   강제 축소되지 않는지) 확인하고 완료 기록에 근거를 남길 것

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `types.ts`: `PatternParams`에서 `gridX`/`gridY`/`imageScale`을 제거하고, 실제 서비스 폭 기준
  절대 px 값인 `imageSize`(기본값 86 = `SERVICE_WIDTH(430) / 5`)로 대체. `SERVICE_WIDTH = 430`
  상수를 신설해 배지 상세화면 앱 컬럼 폭(`max-w-[430px]`)과 값을 일치시킴.
- `patternTile.ts`: `buildTileCanvas`가 더 이상 `baseCellW`/`baseCellH` 인자를 받지 않고
  `params.imageSize`를 그대로 `drawW`/`drawH`로 사용. 그리드 수 파생 로직 완전 삭제. 티켓
  005에서 확정한 "간격은 이미지 크기에 영향 없음"(`pitchX = drawW + colGap`,
  `pitchY = drawH + rowGap`) 원칙은 그대로 유지. 값 clamp를 추가하지 않아 이미지+간격 합이
  430px를 넘으면 캔버스/미리보기 경계에서 자연스럽게 잘리도록 방치.
- `PatternPanel.tsx`: 그리드 수 슬라이더 2종 제거, 이미지 크기 슬라이더를 px 절대값(10~430,
  기본 86)으로 교체. 미리보기 박스의 CSS 표시 크기 자체를 `SERVICE_WIDTH`(430×430)로 고정해
  프리뷰 박스 크기가 임의 값(기존 360)에 좌우되지 않게 함. "430px 폭에 약 N개 표시됨" 읽기
  전용 파생 정보를 추가(그리드 수와 달리 상태로 관리하지 않음). `flattenPattern` 호출도
  `previewSize` 대신 `SERVICE_WIDTH`로 구워 Paper 필터 입력이 실제 서비스 스케일과 일치하도록
  수정.
- `page.tsx`: `PatternPanel`이 더 이상 `previewSize` prop을 받지 않으므로 호출부에서 해당 prop
  제거(애니메이션/필터 프리뷰는 기존 `PREVIEW_SIZE=360` 그대로 유지, 패턴 모드만 영향).

### 주요 의사결정 / 핵심 메모
- 이미지 크기(`imageSize`)는 가로/세로 동일한 정사각 값으로 단순화(원본 코드도 그리드가
  정사각일 때는 사실상 정사각 셀에 이미지를 그리는 구조였고, 티켓 문구도 "이미지 크기 조절
  파라미터"를 단수로 지칭해 폭/높이를 분리하지 않음).
- "미리보기 박스 자체를 430px 폭으로 맞추거나, 최소한 내부 렌더링 좌표계가 430px 기준임을
  명시" 중 전자(박스 자체를 430×430으로 고정)를 택함 — 검증이 더 명확하고 실제 배지 상세화면과
  1:1 대응되기 때문.
- `flattenPattern`의 출력 크기도 기존 `previewSize`(360) 대신 `SERVICE_WIDTH`(430)로 변경 —
  Paper 필터 입력(필터 적용 결과 미리보기)도 실제 서비스 스케일과 일치해야 하므로 함께 수정.
  이 부분은 티켓에 명시된 필수 항목은 아니었으나, 그리드 수 제거로 발생한 정합성 문제라
  범위 내로 판단해 함께 처리함.
