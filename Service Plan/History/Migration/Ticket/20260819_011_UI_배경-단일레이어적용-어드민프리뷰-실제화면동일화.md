# [UI] 배경 단일 레이어 적용 + 어드민 프리뷰를 실제 화면과 동일하게

## 배경 / 문제 정의
티켓 20260819_008로 배경 제너레이터 저장이 프로덕션에 반영된 뒤, 실제 사용에서 두 가지 문제가
확인됐다(사용자 스크린샷 첨부 확인 — 어드민 미리보기 + 모바일 실서비스 화면).

### 문제 1 — 배경이 3중으로 적용됨
`getBadgeBackgroundStyle(badgeRow)`가 **세 지점에 각각 독립적으로** 적용되고 있다
(`jam-web/src/app/(main)/badges/[id]/page.tsx`):

1. `badgeBackgroundLayer` — `position:fixed`, `maxWidth:430px` 앱 컬럼 폭 고정 레이어 (line 245~)
2. `topNavStyle` — TopNav `headerStyle`로 주입 (line 233)
3. `BadgeHeroSection` — Hero 카드 자체(`w-full aspect-square ... bg-surface-elevated`)에
   `style={backgroundStyle}` (BadgeHeroSection.tsx line 20, 28)

`background_color`(단색)일 때는 세 곳이 같은 색이라 문제가 드러나지 않았지만,
`background_image_url`(제너레이터 이미지)은 각 지점의 박스 크기·비율이 달라 `cover`가 **서로 다른
배율·위치로 3번 잘라 그리면서** 패턴이 어긋나 이음매가 눈에 띈다.

**요구사항**: 배경은 **서비스 가로폭(430px 앱 컬럼) 기준 레이어에 단 한 번만** 적용한다.
PC에서 페이지 전체 배경으로 퍼지면 안 되고, TopNav·Hero 카드에 중복 적용해서도 안 된다.

### 문제 2 — 어드민 프리뷰가 실제 화면과 다름
어드민 미리보기에서는 Hero 카드 배경이 검정(`bg-surface-elevated`)으로 보이는데, 실제 서비스에서는
그 자리에 배경이 비쳐 보인다. 프리뷰가 실제와 다르면 저작 도구로서 신뢰할 수 없다.

**요구사항**: 어드민 프리뷰는 **TopNav부터 Footer까지 실제 서비스 화면 그대로** 보여준다.
레이아웃도 함께 변경:
- **PC**: 프리뷰를 **우측**, 설정/정보를 **좌측**에 배치
- **모바일**: 프리뷰를 **위**, 설정/정보를 **아래**에 배치

## 상세 요구사항

### 서비스/코드베이스 관점 (문제 1 — 단일 레이어)
- 배경은 `badgeBackgroundLayer`(430px 앱 컬럼 폭 고정 레이어) **한 곳에만** 적용한다.
- `topNavStyle`에서 `getBadgeBackgroundStyle` 주입을 제거하고, TopNav가 고정 배경 레이어를
  가리지 않도록 **투명 처리**한다(현재 `background: 'var(--color-surface)'` 불투명이라 그냥
  제거만 하면 배경이 안 비침 — TopNav 배경을 `transparent`로 두어 아래 레이어가 보이게 할 것).
  단, 배경이 없는 배지(기존 동작)에서는 TopNav가 지금과 동일하게 `--color-surface`로 보여야 하므로
  **배경 값이 있을 때만 투명 처리**한다.
- `BadgeHeroSection`도 마찬가지로 `getBadgeBackgroundStyle` 적용을 제거하고, 배경 값이 있을 때
  카드가 고정 레이어를 가리지 않도록 처리한다. 배경이 없을 때는 기존 `bg-surface-elevated`
  그대로 유지해 회귀가 없어야 한다.
- z-index 관계(고정 레이어 z-0, 본문 `relative z-10`, TopNav sticky z-30)를 유지하면서 배경이
  정상적으로 비쳐 보이는지 확인한다. 클릭 차단 회귀(`pointerEvents:none`)도 유지할 것.
- `getBadgeBackgroundStyle` 자체는 그대로 두되, `backgroundSize: 'cover'`가 단일 레이어 기준으로
  적절한지 재검토한다(430px 폭에 맞춰 구운 이미지이므로 `cover`보다 `100% 100%`나
  `contain`+repeat이 더 정확할 수 있음 — 실제 렌더링 결과를 보고 판단).

### UI/UX 관점 (문제 2 — 프리뷰 동일화)
- `BackgroundGeneratorPreview`의 미리보기가 실제 배지 상세화면과 동일한 구조(TopNav → Hero →
  본문 → Footer)를 렌더링하도록 확장한다. 실제 컴포넌트(`TopNav`, `BadgeHeroSection`, `Footer`)를
  최대한 그대로 재사용할 것 — 프리뷰 전용으로 비슷하게 흉내 낸 마크업을 새로 만들지 말 것
  (그렇게 하면 또 실제와 어긋난다).
- 레이아웃: PC(넓은 화면)는 좌측 설정 / 우측 프리뷰 2단, 모바일(좁은 화면)은 위 프리뷰 / 아래 설정.
  Tailwind 반응형 유틸리티로 처리.
- 프리뷰는 실제 앱 컬럼 폭(430px, `SERVICE_WIDTH`) 기준을 유지한다.

### DB 스키마 관점
- 변경 없음.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
**문제 1 — 배경 단일 레이어화**
- 배경을 그리는 지점을 `badgeBackgroundLayer`(430px 앱 컬럼 폭 고정 레이어) **한 곳으로 통일**했다.
- `topNavStyle`에서 `getBadgeBackgroundStyle` 주입 제거 → 배경이 있으면 `transparent`, 없으면
  기존과 동일하게 `var(--color-surface)`.
- `BadgeHeroSection`에서도 배경 주입 제거 → 배경이 있으면 카드가 `bg-transparent`, 없으면 기존
  `bg-surface-elevated` 유지.
- 판정은 `hasBadgeBackgroundTheme()`(신규)로 한 곳에서 계산하고, 배경 위 텍스트 그림자도
  `getBadgeThemedTextStyle()`로 공통화해 상세화면·어드민 미리보기가 같은 값을 쓰게 했다.
- z-index 관계(레이어 z-0 / 본문 `relative z-10` / TopNav sticky z-30)와 `pointerEvents:'none'`은
  그대로 유지.

**backgroundSize 재검토 결과 — `cover` → `100% auto` + `repeat`**
- 저장 이미지는 430×430 정사각인데 적용 레이어는 430×뷰포트높이(2배 이상 세로로 김)라 실제
  3안을 렌더링해 비교했다: `cover`(2.17배 확대 + 좌우 잘림) / `100% 100%`(세로 2배 늘어나 원이
  타원이 됨) / `100% auto`+repeat(저작한 크기·비율 그대로 유지). 마지막 안 채택.

**문제 2 — 어드민 프리뷰 실제화면 동일화**
- `BadgeDetailPreviewFrame`(신규, admin 전용)이 실제 상세화면과 **같은 컴포넌트**(TopNav /
  BadgeHeroSection / BadgeConditionCard / Footer)로 TopNav→Hero→본문→Footer를 렌더링한다.
  흉내 낸 전용 마크업은 만들지 않았다. 본문 "획득 조건" 카드는 실제 페이지에 인라인으로 중복돼
  있던 마크업을 `BadgeConditionCard`로 순수 추출해 양쪽이 같은 컴포넌트를 쓴다.
- 프레임은 430×932(기준 단말 뷰포트)로 고정하고, 배경 레이어를 본문 스크롤 컨테이너 바깥 형제로
  두어 실제의 `position:fixed` 레이어 동작(스크롤에 안 끌려감)을 재현했다.
- 제너레이터 라이브 노드(430×430 DOM 노드)는 CSS repeat이 불가능하므로 정사각 슬롯을 세로로
  3개 쌓아 실제의 `100% auto`+repeat와 동일하게 보이도록 했다.
- 레이아웃: xl(1280px↑) 좌측 설정 / 우측 프리뷰 2단, 그 미만은 위 프리뷰 / 아래 설정.
  2단에서 설정 영역이 눌리지 않도록 이 섹션만 폼 기본 폭(max-w-2xl)을 넘어 넓어진다.

### 주요 의사결정 / 핵심 메모
- `backgroundSize`는 실제 렌더링 3안 비교 후 `100% auto` + `backgroundRepeat: repeat`로 확정.
  제너레이터 자체가 타일 반복 패턴을 굽는 도구라 반복이 본래 의도와도 맞는다.
- 어드민 프리뷰는 실제 컴포넌트 재사용이 원칙이라, 본문 조건 카드를 `BadgeConditionCard`로
  추출했다(순수 추출, 실제 화면 렌더링 결과 동일).
- 프리뷰 TopNav는 클릭만 차단(`pointer-events-none`)해 작성 중 폼을 벗어나지 않게 했다.
  스크롤은 그대로 가능하다.

### 잔여 이슈
- 저장 이미지 높이가 430px 고정이라, 타일 피치가 430을 정수로 나누지 못하는 설정(이미지 크기·
  간격 조합)에서는 세로 반복 경계(y=430 배수)에 미세한 어긋남이 생길 수 있다. 어드민 프리뷰가
  실제와 같은 규칙으로 보여주므로 저작 단계에서 확인·회피 가능하다.
- 어드민 프리뷰의 본문은 "획득 조건" 카드 1개만 예시로 보여준다(실제 조건·포인트 보상·획득 정보
  카드까지 재현하지는 않음). 배경 확인 목적에는 충분하다고 판단했다.
