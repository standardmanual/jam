# [UI] 컬렉션·세계관 배경 일괄 적용 — 스키마 신설 + 공용 저작 UI 리팩터링

## 배경 / 문제 정의

티켓 007~012에서 배지 상세화면(`/badges/[id]`)에 배경 제너레이터(패턴/애니메이션 + Paper 필터 →
정적 이미지 또는 MP4로 굽기) 기능을 완성해 프로덕션에 배포했다. 이제 이 기능을 상위 관리 단위인
**컬렉션(item_book)**과 **세계관(faction)**의 어드민 상세 화면에도 추가해, 소속 배지 전체에
일괄 적용할 수 있어야 한다.

현재 `item_books`/`factions` 테이블에는 `background_color`/`background_shader_id`(미사용 placeholder)만
있고, `/api/admin/itembooks/[id]/apply-background`·`/api/admin/factions/[id]/apply-background`는
이 두 필드만 하위 배지에 복사하는 구버전 로직이다. 배경 이미지/영상은 전혀 다루지 않는다.

또한 저작 UI(패턴/애니메이션 옵션, Paper 필터, 미리보기, 굽기)는 현재 `BadgeForm.tsx`에만 있고
`BackgroundGeneratorPreview.tsx`로 분리돼 있긴 하지만 배지 저장 흐름에 강하게 결합돼 있다. 이를
그대로 복사해 컬렉션/세계관 폼에도 붙이면 3중 유지보수 부담이 생긴다.

이 티켓은 **선행 작업(기반 다지기)**만 다룬다. 실제 컬렉션/세계관 어드민 화면 UI 연결과
캐스케이드 로직 확장은 후속 티켓(014, 015)에서 진행한다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **DB 마이그레이션**: `item_books`, `factions` 테이블에 `background_image_url text`,
   `background_video_url text` 컬럼 추가 (badges 테이블과 동일 스키마 패턴).
   - `background_shader_id`는 이미 미사용 placeholder이므로 이번 작업 범위에서 다루지 않음(제거도 안 함).
   - SQL 파일만 작성한다 (`jam-web/supabase/migrations/0XX_...sql`). **실행하지 않는다** —
     오케스트레이터가 사용자 승인 후 직접 실행한다.

2. **저작 UI 공용화**: `BackgroundGeneratorPreview.tsx`(및 `bakePreviewToBlob.ts`,
   `bakeBackgroundVideo.ts`)를 badges 전용 결합에서 분리해, "무엇을 편집 중인가"에 무관하게
   재사용 가능한 형태로 리팩터링한다.
   - 현재 이 컴포넌트가 badge row(`background_color`/`image_url`/`video_url`, 이미지 소스로
     "배지 자신의 이미지 재사용" 옵션 등)에 얼마나 의존하는지 먼저 조사할 것.
   - "이 배지의 기존 이미지 재사용" 같은 badge 전용 옵션은 상위 단위(컬렉션/세계관)에는
     해당 개념이 없으므로(대표 이미지가 없음), **옵션을 prop으로 켜고 끌 수 있게** 하거나
     컬렉션/세계관에서는 "새 이미지 업로드"만 노출하도록 한다.
   - 결과물(색상 / 정적 이미지 URL / 영상 URL, 3자 배타)을 상위 컴포넌트에 콜백으로 전달하는
     형태로 인터페이스를 정리한다. 저장 시점(API 호출)은 각 폼(BadgeForm/ItemBookForm/FactionForm)이
     계속 담당한다 — 공용 컴포넌트가 저장까지 책임지지 않는다.
   - 리팩터링 후 `BadgeForm.tsx`의 기존 동작(배지 상세 배경 제너레이터)이 **회귀 없이** 그대로
     동작해야 한다 — 이 티켓의 가장 중요한 통과 기준.

3. **타입 갱신**: `ItemBookRow`, `FactionRow` 타입(`jam-web/src/types/database.ts`)에
   `background_image_url`, `background_video_url` 필드 추가.

### UI/UX 관점

- 이번 티켓은 실제 컬렉션/세계관 어드민 화면에 UI를 노출하지 않는다 (후속 티켓에서 진행).
  공용 컴포넌트 자체의 화면 동작(배지 폼에서 보이는 모습)은 변화가 없어야 한다.

## 구현 계획

1. `item_books`/`factions`에 컬럼 추가하는 마이그레이션 SQL 작성
2. `database.ts` 타입 갱신
3. `BackgroundGeneratorPreview.tsx` 내부에서 badge 전용 가정(이미지 소스로 "배지 이미지 재사용" 등)을
   찾아 prop 기반으로 일반화
4. `BadgeForm.tsx`가 새 인터페이스로 공용 컴포넌트를 호출하도록 조정 (기존 동작 유지)
5. 배지 상세화면 수동 확인: 단색/패턴/애니메이션 각 모드로 저장 시 기존과 동일하게 동작하는지 확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. `item_books`/`factions`에 `background_image_url`/`background_video_url` 컬럼을 추가하는
   마이그레이션 SQL만 작성(미실행). `badges` 테이블 20260819_008/012와 동일 패턴.
2. `database.ts`의 `ItemBookRow`/`FactionRow`에 두 필드 타입 추가.
3. `BackgroundGeneratorPreview.tsx`를 badge 전용 결합에서 분리:
   - `name`/`description`/`rarity`/`imageUrl` prop 제거 — "배지 상세화면 프리뷰를 어떻게
     그릴지"는 더 이상 이 컴포넌트가 모른다.
   - "등록된 이미지 재사용" 라디오 옵션을 `existingImageOption?: { label, imageUrl }` prop으로
     뺐다. 생략하면(컬렉션/세계관 케이스) 라디오 없이 "새 이미지 업로드"만 노출된다.
   - 라이브 미리보기 프레임 렌더링을 `renderPreview({ themed, backgroundLayerStyle,
     backgroundLayerRef, liveNode }) => ReactNode` 렌더 함수로 호출부에 위임 — 실제 화면과
     동일한 구조로 그리는 책임은 호출부(BadgeForm 등)가 진다. `bakePreviewToBlob.ts`,
     `bakeBackgroundVideo.ts`는 원래도 DOM 컨테이너만 다뤄 badge 결합이 없어 수정하지 않았다.
4. `BadgeForm.tsx`가 새 인터페이스로 호출하도록 조정: `BadgeDetailPreviewFrame` 렌더링과
   "실제 배지 상세화면과 같은 구조로 보여줘요…" 안내 문구를 `renderPreview` 클로저 안으로
   그대로 옮겼다(문구·구조 변경 없음). `existingImageOption={{ label: '등록된 배지 이미지
   사용', imageUrl }}`로 기존 동작(비어 있으면 비활성 라디오)을 그대로 재현.

### 주요 의사결정 / 핵심 메모
- BadgeDetailPreviewFrame(TopNav/Hero/Footer로 실제 배지 상세화면을 그대로 재현)은 애초에
  `BadgeHeroSection`에 강하게 결합돼 있어 배지 전용이다. 컬렉션/세계관은 대표 이미지·조건
  카드 같은 개념이 없어 동일한 프레임을 그대로 재사용할 수 없으므로, 프레임 자체를 일반화하는
  대신 "무엇을 미리보여줄지"를 호출부 렌더 함수로 위임하는 방식을 택했다. 실제 컬렉션/세계관
  미리보기 프레임 설계는 후속 티켓(014, 015) 몫.
- `existingImageOption`을 생략하면 라디오 자체가 렌더링되지 않게 해, 컬렉션/세계관 폼이
  "새 이미지 업로드"만 쓰도록 강제한다(요구사항 그대로).

### 잔여 이슈
- 실제 컬렉션/세계관 어드민 화면에 이 공용 컴포넌트를 붙이는 작업, `apply-background` API의
  이미지/영상 URL 처리 확장은 후속 티켓(014, 015) 범위.
