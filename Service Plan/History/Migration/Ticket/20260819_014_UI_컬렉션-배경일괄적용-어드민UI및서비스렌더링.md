# [UI] 컬렉션 배경 일괄 적용 — 어드민 저작 UI + 서비스 페이지 렌더링 + 캐스케이드

## 배경 / 문제 정의

티켓 013에서 `item_books`/`factions`에 `background_image_url`/`background_video_url` 컬럼을
추가하고, 배경 저작 UI(`BackgroundGeneratorPreview.tsx`)를 badge 전용 결합에서 분리해 재사용
가능하게 만들었다. 이 티켓은 그 기반 위에서 **컬렉션(item_book)** 단위 실제 기능을 완성한다.

현재 상태:
- `/itembooks/[id]` 서비스 페이지(`jam-web/src/app/(main)/itembooks/[id]/page.tsx`)는
  배경을 전혀 렌더링하지 않는다 (`PAGE_BG = 'var(--color-surface)'` 고정).
- `/admin/itembooks/ItemBookForm.tsx`에는 `background_color`/`background_shader_id`만
  다루는 구버전 필드가 있고, 이미지/영상 제너레이터 UI는 없다.
- `/api/admin/itembooks/route.ts`·`[id]/route.ts`(저장)와
  `/api/admin/itembooks/[id]/apply-background/route.ts`(하위 배지 일괄 적용)는 모두
  `background_color`/`background_shader_id` 두 필드만 다룬다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **배경 테마 계산 공용화**: `jam-web/src/lib/badgeBackgroundTheme.ts`의
   `getBadgeBackgroundStyle`/`hasBadgeBackgroundTheme`/`getBadgeBackgroundVideoUrl`이 받는
   타입(`BadgeBackgroundThemeSource`)은 현재 `BadgeRow`에서 `Pick`한 구조 타입이라 실질적으로는
   이미 필드 이름만 맞으면 어떤 row든 재사용 가능하다. `item_books`(그리고 향후 `factions`)에도
   그대로 쓸 수 있도록 타입을 일반화한다 (badge 전용이 아닌 구조적 타입으로 정리 — 기존 badge
   호출부는 변경 없이 그대로 동작해야 함).

2. **컬렉션 서비스 페이지 배경 렌더링**: `/itembooks/[id]/page.tsx`에 배경 레이어를 추가한다.
   배지 상세화면(티켓 011)에서 확정한 "단일 레이어, 여러 곳에 중복 적용하지 않음" 원칙을 그대로
   따른다 — `position:fixed`, 앱 폭(430px) 기준, `TopNav`·본문 카드는 배경이 있을 때만 투명
   처리(없으면 기존 그대로, 회귀 없음). `background_image_url` 우선, 없으면 `background_color`.
   `background_video_url`이 있으면 배지 상세와 동일하게 `<video autoPlay muted loop playsInline
   poster={image_url}>` 렌더링 + `prefers-reduced-motion` CSS 대응(티켓 012에서 발견한 인라인
   style 버그를 반복하지 말 것 — `display`는 클래스로).

3. **어드민 저작 UI**: `ItemBookForm.tsx`에 `BadgeForm.tsx`와 동일한 패턴(단색/제너레이터
   배타적 라디오)으로 배경 설정 UI를 추가한다. 티켓 013에서 일반화한
   `BackgroundGeneratorPreview`를 사용하되, `existingImageOption`은 전달하지 않는다 — 컬렉션은
   "이 컬렉션 자신의 이미지"라는 개념이 없으므로 이미지 소스는 항상 "새 이미지 업로드"만
   노출한다. 미리보기는 실제 `/itembooks/[id]` 서비스 페이지 구조를 재사용하는 프리뷰 프레임을
   새로 만든다 (티켓 011의 `BadgeDetailPreviewFrame` 패턴과 동일 — 어드민 프리뷰가 실제 화면과
   달라지는 사고를 반복하지 않기 위함).
   - 이 배경 설정은 **컬렉션 자신의 저장값**이다 — 일반 폼 저장(`저장` 버튼)으로
     `background_color`/`background_image_url`/`background_video_url`이 저장된다 (3자 배타,
     반대쪽은 null로 정리).
   - **일괄 적용** 버튼은 별도 동작이다 — 지금 저장된(방금 폼에서 저장한, 또는 이전에 저장된)
     컬렉션 자신의 값을 하위 배지 전체에 복사한다. 클릭 시점의 스냅샷을 1회성으로 복사하는
     기존 동작(20260818_004)을 유지한다 — 실시간 fallback 구조 아님.
   - 화면에 적용 범위를 명시한다: "이 설정은 이 컬렉션 상세화면과 소속된 모든 아이템배지 상세
     화면에 일괄 적용됩니다." 같은 안내 문구 (UX Writing 가이드라인 준수 — 해요체, 간결하게).

4. **저장 API 확장**: `/api/admin/itembooks/route.ts`(POST)·`[id]/route.ts`(PUT)가
   `background_image_url`/`background_video_url`도 body에서 받아 저장하도록 확장한다
   (기존 `background_color`/`background_shader_id` 처리와 동일한 패턴).

5. **일괄 적용 API 확장**: `/api/admin/itembooks/[id]/apply-background/route.ts`가
   `background_color`/`background_image_url`/`background_video_url` 3필드 모두를 하위 배지에
   복사하도록 확장한다 (`background_shader_id`는 기존 동작 유지 — 이번 범위에서 굳이 배제할
   필요는 없음, 어차피 렌더링에 미사용). 대상은 기존과 동일하게
   `item_book_id = X AND deleted_at IS NULL`, 항상 덮어쓰기(사용자 확정 방침).

### UI/UX 관점

- 어드민 화면(`src/app/admin/`)은 MODULAR 적용 대상 아님 — 탐색·재사용 판정 절차 생략.
- 서비스 페이지(`/itembooks/[id]`)에 신규 노출되는 안내 문구가 있다면 UX Writing 가이드라인
  검증 필수.

### 구현 내용 요약
- `badgeBackgroundTheme.ts`의 `BadgeBackgroundThemeSource`를 badge 전용 `Pick<BadgeRow, ...>`에서
  구조적 인터페이스 `BackgroundThemeSource`로 일반화했다. 기존 이름은 `@deprecated` 별칭으로 남겨
  기존 badge 호출부(배지 상세화면·어드민 미리보기·테스트)는 변경 없이 그대로 동작한다.
- `/itembooks/[id]/page.tsx`에 배지 상세화면(20260819_011/012)과 동일한 원칙의 단일 고정 배경
  레이어를 추가했다 — `background_image_url` 우선, 없으면 `background_color`, 영상은
  `<video autoPlay muted loop playsInline poster>` + `.badge-background-video` 클래스로
  `prefers-reduced-motion` 대응(인라인 `display` 버그 반복 안 함). 배경이 있을 때만 TopNav·본문을
  투명 처리하고, 없으면 기존 `PAGE_BG` 그대로라 회귀 없음.
- 대표 이미지·이름/설명·진행도 바 블록을 `ItemBookHeroSection.tsx`로 분리해 실제 서비스 페이지와
  어드민 미리보기가 완전히 같은 컴포넌트를 쓰도록 했다(배지 상세의 `BadgeHeroSection` 패턴과 동일
  이유 — 티켓 011).
- 어드민 컬렉션용 미리보기 프레임 `ItemBookDetailPreviewFrame.tsx`를 신규 작성했다
  (`BadgeDetailPreviewFrame` 패턴 그대로 — 실제 `TopNav` + `ItemBookHeroSection`을 재사용, 진행도는
  0/0 고정값).
- `ItemBookForm.tsx`에 `BackgroundGeneratorPreview`(티켓 013에서 공용화)를 연결했다.
  `existingImageOption`은 전달하지 않아 항상 "새 이미지 업로드"만 노출된다. "이 설정은 이 컬렉션
  상세화면과 소속된 모든 아이템배지 상세화면에 일괄 적용됩니다" 안내 문구를 추가했다(해요체,
  UX Writing 가이드 준수).
- `BackgroundGeneratorPreview.tsx`에 선택적 `onThemedChange` 콜백을 추가했다 — 저장 전에도
  "지금 배경값이 있는가"(단색/제너레이터 이미지 스테이징 포함)를 부모가 정확히 알아야 "하위 배지에
  일괄 적용" 버튼의 활성화 조건(20260818_004 개선 리뷰에서 확정한 "배경값 없으면 비활성화")을
  이미지 모드에서도 정확히 지킬 수 있어서다. `onThemedChange`를 넘기지 않는 기존 `BadgeForm`은
  영향 없음.
- `/api/admin/itembooks/route.ts`(POST)·`[id]/route.ts`(PUT)가
  `background_image_url`/`background_video_url`도 저장하도록 확장했다.
- `/api/admin/itembooks/[id]/apply-background/route.ts`가 `background_color`/
  `background_image_url`/`background_video_url` 3필드(+ 기존 `background_shader_id`)를 모두
  하위 배지에 복사하도록 확장했다. 대상·항상 덮어쓰기 방침은 기존과 동일.

### 주요 의사결정 / 핵심 메모
- `BadgeBackgroundThemeSource` → `BackgroundThemeSource` 이름 변경은 기존 이름을 `@deprecated`
  별칭으로 유지하는 방식을 택했다(완전 삭제 대신) — 호출부가 늘어날수록 이름 이관 비용이 커지므로
  다음에 실제로 badge 쪽 코드를 만질 때 자연스럽게 정리해도 무방.
- 컬렉션 상세화면에는 "본문 카드"라는 별도 wrapper가 원래 없어(배지 상세의 Hero 카드와 달리 루트
  div 자체가 `PAGE_BG`를 직접 들고 있음), "본문 투명 처리"는 루트 컨테이너의 배경을 투명화하는
  것으로 해석했다. POI 카드·완성 배너 등 개별 카드(`CARD_BG` 고정 검정)는 배지 상세의 다른 카드들과
  마찬가지로 그대로 불투명 유지 — 배경 레이어는 티켓 011 원칙대로 한 곳(고정 레이어)에서만 그린다.
- "하위 배지에 일괄 적용" 버튼 활성화 조건을 색상 전용 로직에서 이미지/영상까지 포함한 `themed`
  기반으로 바꾸면서, 기존 20260818_004 개선 리뷰에서 반영했던 "쉐이더만 선택해도 활성화" 동작은
  `themed || backgroundShaderId !== ''`로 그대로 보존했다.
