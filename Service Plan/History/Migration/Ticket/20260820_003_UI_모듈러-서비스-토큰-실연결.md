# [UI] 모듈러-서비스 토큰 실연결 (1단계: 토큰)

## 배경 / 문제 정의

모듈러(`jam-web/design-system/tokens/*.css`)와 서비스(`jam-web/src/app/globals.css`)는 지금까지
`@import` 없이 각자 독립적으로 같은 이름의 토큰 값을 수동으로 맞춰온 상태였다(전수조사 완료,
68개 이름 일치 확인). 이 티켓은 실제 코드 레벨 연결(`@import`)의 **1단계 — 토큰**을 다룬다.
컴포넌트 연결(RarityBadge 등을 서비스가 실제 import)은 후속 티켓 범위.

## 사용자 확정 사항 (착수 전 확인 완료)

1. **`--font-family-base` 충돌**: 서비스 값(Pretendard Variable)을 정본으로 — **모듈러 쪽
   `typography.css`의 `--font-family-base`를 Pretendard로 갱신**한다(서비스 값이 바뀌는 게
   아니라 모듈러가 서비스 결정을 따라간다).
2. **라이트 테마**: 서비스는 다크 전용 고정(`color-scheme: dark`)이라 **라이트 테마 오버라이드
   블록(`@media (prefers-color-scheme: light)`, `:root[data-theme="light"]`)은 연결 대상에서
   제외**한다. 서비스에 라이트 모드를 추가하는 것이 아님 — 스토리북 자체의 라이트/다크 토글
   기능에는 영향 주지 않아야 한다(스토리북은 계속 원본 `colors.css` 전체를 쓸 수 있어야 함).
3. **누락 토큰 이식**: `--text-micro` / `--leading-micro` / `--color-text-on-primary`는 모듈러에는
   있지만 서비스에 이식된 적이 없어 `SlotGrid.tsx`(`--text-micro`/`--leading-micro`),
   `SlidingTabs.tsx`(`--color-text-on-primary`)에서 미정의 상태로 참조되고 있다 — **모듈러 값
   그대로 서비스에 이식**한다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **`design-system/tokens/typography.css` 수정**: `--font-family-base` 값을 서비스와 동일하게
   `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, Roboto,
   sans-serif`로 갱신. 이 변경으로 스토리북에 렌더링되는 텍스트의 실제 폰트가 바뀔 수 있음 —
   의도된 변경.

2. **`design-system/tokens/colors.css` 구조 분리**: 다크(기본) 값과 라이트 오버라이드를
   분리해, 서비스가 **라이트 블록을 제외하고 다크 값만** import할 수 있게 한다. 접근 예시(구현
   편한 쪽으로 판단):
   - `colors.css`(다크·기본 `:root`만) + `colors.light.css`(라이트 오버라이드 분리)로 파일 분할,
     스토리북 엔트리는 두 파일을 계속 함께 로드하도록 조정
   - 또는 라이트 오버라이드 블록에 최상위에서 무력화 가능한 감싸는 조건을 추가
   - 스토리북 자체의 라이트/다크 미리보기 기능이 이번 변경으로 깨지지 않는지 반드시 확인
     (`npm run storybook` 또는 `build-storybook`으로 검증)

3. **`globals.css` 실연결**: 하드코딩된 중복 `:root`/`@theme` 블록(색상·모션 일부·반경·스페이싱·
   타이포 중 모듈러와 이름이 겹치는 항목)을 걷어내고, `design-system/tokens/*.css`를
   `@import`하도록 바꾼다(라이트 블록 제외 파일만 import — 2번 항목).
   - 값이 완전히 일치했던 68개 토큰(색상·모션 duration/ease 5종·반경 전체·스페이싱/레이아웃
     전체·타이포 일부)은 교체해도 시각적 차이가 없어야 한다 — 이게 이번 작업의 핵심 회귀
     기준이다.
   - 모듈러에만 있던 55개 토큰(base palette, `--color-tag-*`, `--color-text-on-primary`,
     확장 타이포 스케일 h1~h4/weight/tracking, `--radius-subtle`/`--radius-input`,
     `--scale-press`/`--scale-modal`)은 import로 자연스럽게 서비스에서도 쓸 수 있게 된다 —
     추가 조치 불필요(순수 추가, 충돌 없음).
   - 서비스에만 있던 227개 토큰(레거시 브랜드 `--color-jam-*`, `--color-main`/`--color-sub`,
     transitions.dev 모션 토큰 ~190개, `--spacing-40`/`--spacing-96`, `--shadow-subtle*` 등)은
     **이번 티켓 범위에서 모듈러로 역이식하지 않는다** — 서비스 전용 확장으로 유지. 필요시
     후속 티켓에서 판단.
   - `--text-micro`/`--leading-micro`/`--color-text-on-primary`는 import로 자동 해결된다
     (55개 그룹에 포함) — 별도 조치 불필요, 다만 `SlotGrid.tsx`/`SlidingTabs.tsx`가 실제로
     의도한 대로 보이는지 시각 확인.

4. **회귀 검증**: `@import` 전환 전후로 실제 렌더링 값이 달라지는 요소가 없는지 확인.
   - 일치했던 68개 토큰 값이 정말 그대로인지(계산된 스타일 비교)
   - 라이트 테마 블록이 정말 서비스에 영향 주지 않는지(OS 라이트 모드 시뮬레이션해서 확인 —
     `prefers-color-scheme` 강제 전환 가능한 개발자 도구 활용)
   - 스토리북 빌드·기존 컴포넌트 Story들이 정상 동작하는지(`npm run build-storybook`)

### UI/UX 관점

### 구현 내용 요약
1. `typography.css`의 `--font-family-base`를 Noto Sans KR → Pretendard Variable로 갱신(서비스 값 정본화).
2. `colors.css`를 다크(기본)만 남기고, 라이트 오버라이드(`@media (prefers-color-scheme: light)`,
   `:root[data-theme="light"]`)를 신규 `colors.light.css`로 분리. `design-system/styles.css`(스토리북
   진입점)는 두 파일을 함께 import해 라이트/다크 토글 기능 유지.
3. `globals.css`에 `design-system/tokens/{colors,typography,spacing,radius,motion}.css`를 `@import`
   (라이트 오버라이드 파일은 제외). 이름이 일치하는 68개 토큰의 하드코딩 값을 globals.css에서
   제거하고 import로 대체. 서비스 전용 227개 토큰(레거시 브랜드 `--color-jam-*`, `--color-main`/
   `--color-sub`, transitions.dev 모션 ~190개, `--spacing-40`/`-96`, `--shadow-subtle*` 등)은
   그대로 유지.
4. Tailwind `@theme` 블록 안에서 유틸리티 클래스(`bg-surface`, `rounded-card` 등) 생성에 쓰이던
   색상 8종·반경 10종은 하드코딩 값 대신 `@theme inline`으로 옮기고 같은 이름의 `var(--…)`로
   모듈러 import 값을 참조하도록 변경. 컴파일된 CSS를 직접 확인해 Tailwind가 `@theme` 내용을
   `@layer theme`로 감싸고, import한 모듈러 `:root` 선언은 레이어 밖(unlayered)에 위치함을
   확인 — CSS 스펙상 unlayered 선언이 항상 우선하므로 `@theme inline`의 자기참조(`var(--color-surface)`
   등)는 사용되지 않고 항상 모듈러 값이 실제로 적용됨(빌드 CSS로 검증, 우연이 아닌 표준 동작).

### 주요 의사결정 / 핵심 메모
- Tailwind v4 `@theme`는 컴파일 시 항상 `@layer theme`로 감싸져 출력되고, `@import`로 가져온
  일반 `:root` 선언(모듈러 토큰)은 레이어 밖에 위치한다. CSS 카스케이드 레이어 규칙상 unlayered
  선언이 layered 선언보다 항상 우선하므로, `@theme inline { --color-surface: var(--color-surface); }`
  같은 동일 이름 자기참조가 안전하게 동작한다(자기참조 선언은 항상 지고, 모듈러 값이 항상 이김).
  빌드 순서에 의존하는 우연한 동작이 아니라 표준 명세에 근거한 동작임을 직접 컴파일된 CSS로 검증했다.
