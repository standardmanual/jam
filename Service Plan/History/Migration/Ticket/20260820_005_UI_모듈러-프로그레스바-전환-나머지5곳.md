# [UI] 모듈러 ProgressBar 전환 — 나머지 5개 호출처

## 배경 / 문제 정의

티켓 20260820_004에서 `MissionDetailClient.tsx`를 `@ds/components/feedback/ProgressBar`로
전환하는 파일럿을 완료하고, "서비스가 `@ds/*` 컴포넌트를 import하는 올바른 방법"을 문서화했다
(확장자 생략 import, `.jsx`+`.d.ts` 페어가 별도 설정 없이 동작 확인됨). 이 티켓은 티켓
20260820_001에서 전수조사됐던 나머지 5개 실사용처를 같은 패턴으로 전환한다.

## 대상 (각각 현재 상태 — 티켓 001 조사 결과)

1. `jam-web/src/app/(main)/itembooks/[id]/ItemBookHeroSection.tsx` — 트랙 `#FFFFFF` 하드코딩,
   필 `#E8461F` 하드코딩, height 8px, n/n 라벨
2. `jam-web/src/components/ui/CollectionGridCard.tsx` — 트랙 `bg-white/20`, 필
   `bg-[#E8461F]` 하드코딩, height 6px(h-1.5), n/n 라벨
3. `jam-web/src/app/(main)/[username]/itembooks/page.tsx` — 트랙 `bg-black/[0.08]`, 필
   `bg-text-inverse`, height 6px, n/n 라벨
4. `jam-web/src/app/(main)/inventory/page.tsx` — 트랙 `bg-border`(토큰), 필 `bg-text`,
   height 6px, 라벨은 바 아래 별도 문장(바 옆이 아님)
5. `jam-web/src/app/(main)/missions/[id]/status/MissionStatusClient.tsx` — 트랙
   `var(--color-surface-elevated)`, 필은 **순위별 그라데이션**(고정 색상 아님),
   `transform: scaleX()` 방식(다른 4곳과 구현 방식이 다름), radius 3px(토큰 아닌 임의값),
   라벨 없음

## 상세 요구사항

### 서비스/코드베이스 관점

각 호출처를 `import { ProgressBar } from '@ds/components/feedback/ProgressBar'`로 전환한다.
티켓 004의 "올바른 import 방법" 섹션을 그대로 따른다(확장자 생략, 별도 설정 불필요).

1~3번(`ItemBookHeroSection`, `CollectionGridCard`, `[username]/itembooks`): 트랙/필 색상이
지금 캐노니컬 스펙(`var(--color-border)`/`var(--color-primary)`)과 다르게 하드코딩돼 있다.
**이건 단순 리팩터링이 아니라 시각적 정규화(디자인 통일)를 겸한다** — 색상이 캐노니컬 스펙으로
바뀌면서 실제로 보이는 색이 달라질 수 있다(예: `ItemBookHeroSection`은 흰 트랙+레드 필 → 어두운
트랙+레드 필로 바뀜). 이건 티켓 001에서 이미 "파편화를 통일한다"는 목표로 의도된 것이지만,
**교체 후 실제로 색이 바뀌는 지점은 완료 기록에 스크린샷 없이도 명확히 텍스트로 나열**해서
사용자가 리뷰 시 놓치지 않게 할 것.

4번(`inventory/page.tsx`): 트랙은 이미 토큰이라 시각 차이 없음. 필(`bg-text`)은 캐노니컬
`var(--color-primary)`와 다른 색(중립색 vs 강조색)이므로 이것도 색이 바뀐다 — 위와 동일하게
명시할 것. 라벨이 바 옆이 아니라 바 아래 문장이라 `ProgressBar`의 라벨 prop은 쓰지 않고
`labelType="none"`으로 바만 교체(기존 문장은 그대로 유지).

5번(`MissionStatusClient.tsx`): **예외 처리 대상일 가능성이 높다.** 순위별 그라데이션은
`ProgressBar`의 `color` prop이 단색만 받는지 CSS 문자열(그라데이션 포함)도 받는지 먼저
`ProgressBar.d.ts`로 확인. 받는다면 `getRankGradient(entry.rank)` 결과를 `color` prop으로
그대로 전달해 전환. 못 받는다면(구조상 안 되면) **이 하나는 전환하지 않고 그대로 남겨두는 것도
정답이다** — 무리하게 컴포넌트 확장까지 하지 말고, 안 되는 이유를 완료 기록에 남기고 다음
컴포넌트 확장 티켓(범위 밖)으로 넘길 것. radius 3px(임의값)도 `ProgressBar`의 `radius` prop
오버라이드로 유지 가능한지 확인.

### UI/UX 관점

- 1~4번은 트랙/필 색상이 실제로 바뀌는 시각적 변경을 포함한다(디자인 통일이 목적) — 새 문구는
  없지만 순수 무변화 리팩터링은 아니라는 점을 완료 기록에 분명히 할 것.
- 5번은 예외 처리 여부에 따라 무변화이거나 아예 손대지 않음.

## 구현 계획

1. `ProgressBar.d.ts` 확인 — `color`/`trackColor`/`radius`/`height` prop이 어디까지 오버라이드
   가능한지 파악
2. 1~4번 순서대로 전환, 각각 색상 변경 여부와 실제 변경 내용을 완료 기록에 기록
3. 5번 그라데이션 호환 여부 판단 후 전환 또는 명시적 보류
4. staging에서 dev-login으로 5개 화면 전부 실제 확인 (컬렉션 상세, 컬렉션 그리드가 보이는
   화면, 프로필 아이템북 목록, 인벤토리, 미션 랭킹)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

티켓 004에서 확립한 `import { ProgressBar } from '@ds/components/feedback/ProgressBar'`(확장자 생략,
별도 설정 불필요) 방식으로 4개 호출처를 전환했다. 라벨은 티켓 004 파일럿과 동일하게 기존 커스텀
스팬/문장을 그대로 두고, 바(트랙+필) 마크업만 `<ProgressBar />`로 교체하는 패턴을 유지했다
(ProgressBar 자체 라벨 기능은 4곳 모두 미사용, `labelType` 기본값 `'none'`).

**1. `ItemBookHeroSection.tsx`**
- `<div>` 트랙(`background: '#FFFFFF'`, height 8px)+필(`background: '#E8461F'`)을
  `<ProgressBar percent={pct} />`로 교체. height는 기본값 8px로 기존과 동일해 변경 없음.
- **트랙 색이 바뀐다**: `#FFFFFF`(흰색) → `var(--color-border)`(#2a2a2a, 어두운 회색).
- **필 색은 시각적으로 무변화**: 기존 하드코딩 `#E8461F`와 캐노니컬 `var(--color-primary)`
  (`var(--color-base-red)` = `#e8461f`)가 같은 값이라 실제로는 색이 바뀌지 않는다.
- 미사용이 된 `PROGRESS_FILL` 상수 제거.

**2. `CollectionGridCard.tsx`**
- 트랙(`bg-white/20`, height 6px/h-1.5)+필(`bg-[#E8461F]`)을
  `<ProgressBar percent={pct} height={6} />`로 교체(height 6px는 `height` prop으로 지정해 유지).
- **트랙 색이 바뀐다**: `bg-white/20`(반투명 흰색 오버레이) → `var(--color-border)`(#2a2a2a 불투명
  진회색). 컴포넌트 배경(썸네일 아래 카드 영역, 다크 톤)에서 반투명 흰 선이 진회색 실선으로
  바뀌어 보인다.
- 필 색은 1번과 동일하게 값이 같아(`#E8461F` = `var(--color-primary)`) 시각적 무변화.

**3. `[username]/itembooks/page.tsx`**
- 트랙(`bg-black/[0.08]`, height 6px/h-1.5)+필(`bg-text-inverse`)을
  `<ProgressBar percent={pct} height={6} />`로 교체.
- **트랙 색이 바뀐다**: `bg-black/[0.08]`(연한 검정 반투명, 밝은 카드 배경 위 옅은 회색) →
  `var(--color-border)`(#2a2a2a 불투명 진회색). 이 화면은 밝은 톤 카드(`bg-black/[0.04]` 썸네일
  배경 등)를 쓰고 있어, 진회색 트랙이 이전보다 눈에 띄게 진해진다.
- **필 색이 바뀐다**: `bg-text-inverse`(이 라이트 카드 맥락에서는 어두운/검정 계열) →
  `var(--color-primary)`(레드 `#e8461f`). 진행 바 색상이 무채색에서 레드로 바뀐다.

**4. `inventory/page.tsx`**
- 트랙(`bg-border`, height 6px/h-1.5)+필(`bg-text`)을
  `<ProgressBar percent={...} height={6} labelType="none" />`로 교체. 라벨은 바 옆이 아니라 바
  아래 별도 문장(`{used}/{max}슬롯 사용 중` 등)이라 `labelType="none"`으로 바만 교체, 기존
  문장은 그대로 유지.
- **트랙 색은 무변화**: `bg-border`가 이미 `var(--color-border)` 토큰이라 색상 차이 없음.
- **필 색이 바뀐다**: `bg-text`(중립색, 흰색 계열) → `var(--color-primary)`(레드 `#e8461f`).
  인벤토리 슬롯 사용량 바가 흰색에서 레드로 바뀐다.

**5. `MissionStatusClient.tsx` — 전환하지 않고 보류(의도된 결정)**
- `ProgressBar.d.ts`/`.jsx` 확인 결과, `color` prop은 그라데이션 문자열을 그대로 받을 수 있어
  `getRankGradient(entry.rank)` 자체는 문제없이 전달 가능했다.
- 그러나 `ProgressBar.jsx`가 필/트랙 모두 `borderRadius: 'var(--radius-pill)'`(9999px, 완전
  캡슐형)을 **하드코딩**하고 있고, `radius`를 오버라이드할 수 있는 prop이 애초에 존재하지 않는다
  (`ProgressBarProps`에 `radius` 없음). `MissionStatusClient`의 순위 행 바는 `borderRadius: 3`
  (미묘하게 둥근 사각형)이 스펙이라 전환 시 캡슐형으로 강제 변경되며 이는 시각적 회귀다.
  또한 구현 방식도 `transform: scaleX()`(다른 4곳의 `width: %` 방식과 다름)라 애니메이션 특성이
  달라질 수 있다.
- 티켓 지시대로 "무리한 컴포넌트 확장 금지" 원칙에 따라 전환하지 않고 그대로 유지했다.
  `radius` prop을 `ProgressBar`에 추가하는 것은 이 티켓 범위 밖(다음 컴포넌트 확장 티켓 대상)이다.
