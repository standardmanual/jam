# [UI] 프로필 본인 화면 TopNav 제거

## 배경 / 문제 정의

배지 목록(`badges/page.tsx`)·인벤토리(`inventory/page.tsx`)처럼 하단 탭 최상위(뒤로가기가
필요 없는) 화면은 `TopNav`를 쓰지 않고 자체 `<h1>` 헤더만 둔다. 반면 프로필 페이지
(`ProfileClient.tsx:429`)는 본인 프로필(하단 탭 진입, 뒤로가기 불필요)에서도
`<TopNav title="" showBack={!isOwnProfile} />`가 항상 렌더링돼 빈 sticky 헤더 바가 공간을
차지한다. 다른 유저 프로필(검색·팔로우 목록 등에서 진입, 뒤로가기 필요)은 현재처럼
TopNav(뒤로가기 버튼)를 유지해야 한다 — 사용자 확인 완료.

## 상세 요구사항

### 서비스/코드베이스 관점
- `isOwnProfile === true`일 때 `TopNav` 자체를 렌더링하지 않는다 (조건부 렌더링, prop으로
  숨기는 방식이 아니라 컴포넌트를 아예 그리지 않음).
- `isOwnProfile === false`일 때는 기존과 동일하게 `<TopNav title="" showBack />`를 유지한다.
- TopNav의 sticky header가 제공하던 `paddingTop: env(safe-area-inset-top)`이 본인 프로필에서
  사라지므로, 컨텐츠 wrapper(`ProfileClient.tsx:429` 다음 div, 현재
  `pt-[var(--spacing-24)]`)에 노치 기기 대응을 위해 `pt-[calc(env(safe-area-inset-top)+var(--spacing-24))]`
  형태로 safe-area 보정을 추가한다 (inventory/page.tsx가 쓰는 동일 패턴 참고).
- 타인 프로필(TopNav 유지 경로)의 컨텐츠 패딩은 기존 그대로 둔다 — 조건부로 패딩값을 분기.

### UI/UX 관점
- 본인 프로필: 상단에 빈 바 없이 프로필 헤더 카드가 화면 최상단(safe-area 아래)에 바로
  나타나야 한다.
- 타인 프로필: 기존과 동일하게 TopNav 뒤로가기 바가 유지돼야 한다 — 회귀 없음.

## 구현 계획
1. `ProfileClient.tsx`의 `<TopNav title="" showBack={!isOwnProfile} />`를
   `{!isOwnProfile && <TopNav title="" showBack />}`로 변경
2. 컨텐츠 wrapper의 `pt-[var(--spacing-24)]`을 `isOwnProfile` 여부에 따라
   `pt-[calc(env(safe-area-inset-top)+var(--spacing-24))]`(본인) /
   `pt-[var(--spacing-24)]`(타인, 기존 유지)로 분기
3. staging에서 dev-login 후 본인 프로필(상단 여백 없이 시작하는지, 노치 기기 시뮬레이션 시
   safe-area 침범 없는지)과 타인 프로필(뒤로가기 버튼 정상 동작) 양쪽 확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`ProfileClient.tsx`의 `TopNav`를 `isOwnProfile`일 때 아예 렌더링하지 않도록 조건부 렌더링으로
변경(`{!isOwnProfile && <TopNav title="" showBack />}`). 컨텐츠 wrapper의 상단 패딩도 본인
프로필(`pt-[calc(env(safe-area-inset-top)+var(--spacing-24))]`)과 타인 프로필
(`pt-[var(--spacing-24)]`, 기존 유지)로 분기해 TopNav가 사라지며 없어진 safe-area 보정을
컨텐츠 wrapper에서 대신 처리하도록 함.
