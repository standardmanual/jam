# [UI] 드랍(지도) POI 모달 캐러셀 개편

## 배경 / 문제 정의
현재 `/drops` 화면에서 POI 마커를 클릭하면 [DropsClient.tsx](../../../../jam-web/src/components/DropsClient.tsx)의
커스텀 바텀시트가 열리고, 반경 내 다른 POI를 보려면 모달을 닫고 다시 다른 마커를 클릭해야 한다.
반경 내 여러 POI를 연속으로 탐색하는 흐름이 끊긴다. 이를 개선해 선택된 POI를 중앙 모달로,
반경 내 나머지 POI들을 옆으로 스와이프해 넘길 수 있는 캐러셀 구조로 바꾼다.

## 상세 요구사항

### 서비스/코드베이스 관점
- POI 마커 클릭 → 캐러셀 모달 오픈. **캐러셀 아이템 자체가 모달 카드** (모달과 캐러셀이 분리된 두 개의
  컴포넌트가 아니라 하나의 통합 캐러셀이며, 중앙에 오는 카드가 "선택된 POI").
- 캐러셀 스와이프(플리킹)로 카드가 전환되면, 지도([MapView.tsx](../../../../jam-web/src/components/map/MapView.tsx))도
  동시에 해당 POI 좌표로 포커싱 이동. 기존 `handleLocateClick`/클러스터 클릭에서 쓰는 `map.morph()` 패턴을 재사용.
- 데이터 로딩: `/api/drops` (반경 내 POI 목록, `in_drop_range` 포함)를 최초 1회 조회하고,
  **클라이언트 사이드에서 3개 단위로 윈도잉**하여 캐러셀에 순차 노출한다 (서버 페이지네이션 아님).
- 정렬: 거리순(가까운 순). `lib/poi/proximity.ts`의 거리 계산 로직 재사용.
- 순환: 마지막 카드 다음에 처음 카드가 다시 이어지는 **무한 루프** (리셋 아님, `modulo` 인덱싱).
- 카드 레이아웃: POI 내 드랍된 아이템배지가 많으면 카드 세로 높이를 늘려 전부 노출, **하단 정렬**.
  배지 UI는 기존 `RarityBadge`/썸네일 패턴 재사용.
- 현재 위치 버튼(`handleLocateClick`, [MapView.tsx:432](../../../../jam-web/src/components/map/MapView.tsx))은
  이미 구현되어 있음 — 로직 재구현 불필요. 캐러셀 모달 오버레이와의 z-index/레이아웃 충돌만 확인.
- 단일 POI 상세 조회 API(`/api/drops/poi/[poiId]/route.ts`)는 각 캐러셀 카드가 열릴 때(또는 최초 3개 시점)
  호출해 해당 POI의 드랍 아이템 목록을 채운다.

### UI/UX 관점
- 기존 바텀시트(화면 하단 고정) → **화면 중앙 모달**로 레이아웃 변경. `ModulerTicket`
  `20260820_012` (바텀시트 다크표면전환)과의 관계 확인 — 바텀시트 자체를 대체하는 것이지 그 개선을
  무효화하는 것은 아님.
- 모션은 MODULAR 모션 토큰(`--duration-medium`, `--ease-smooth-out` 등) 사용, 신규 커스텀 easing 금지.

## UI 탐색·재사용 판정 *(오케스트레이터, 1.5단계)*

`jam-web/design-system/_ds_manifest.json` 확인 결과 캐러셀/슬라이더 계열 컴포넌트 **없음**
(Button, Card, RarityBadge, BottomSheet, SlidingTabs, TabBar, BadgeGridCard, ListRowCard,
CollectionGridCard 등 23종 중 해당 없음). `ModulerTicket/` 디렉토리에도 캐러셀 관련 티켓 없음.

**판정: MODULAR 확장 (신규 컴포넌트 `Carousel` 추가)**
- 근거: 카드 캐러셀은 POI 모달 외에도 향후 컬렉션·인벤토리 등에서 재사용 가능성이 높은 범용 패턴이며,
  기존 모션/spacing 토큰만으로 구현 가능해 MODULAR 원칙(§2 토큰 재사용, 드롭섀도 금지, 배경톤 elevation)에
  맞출 수 있음.
- 구성 요소:
  - `jam-web/design-system/components/navigation/Carousel.jsx` (신규, 무한 루프·센터포커스 카드 캐러셀 프리미티브)
  - 서비스 측 `PoiCarouselModal` (`jam-web/src/components/` 신규 또는 `DropsClient.tsx` 리팩터): `Carousel` +
    기존 `RarityBadge`/`Card`/썸네일을 조합한 서비스 전용 합성 컴포넌트
- 기존 `BottomSheet` 컴포넌트는 레이아웃(하단 고정)이 요구사항(중앙 모달)과 맞지 않아 재사용 대상 아님.

## 구현 계획
1. MODULAR에 `Carousel.jsx` 프리미티브 추가 (센터 포커스, 좌우 스와이프, 무한 루프 인덱싱, 접근성 고려)
   + Story 파일 동반
2. `jam-web/src/components/` 아래 `PoiCarouselModal` 신설 — `Carousel` 위에 POI 카드(썸네일 + 배지 목록 +
   기본 정보) 합성, 카드 높이 가변 + 하단 정렬
3. `DropsClient.tsx`의 `handlePoiSelect` 로직을 반경 내 POI 목록(거리순 정렬 + 3개 윈도잉)을 계산해
   `PoiCarouselModal`에 전달하도록 수정
4. `PoiCarouselModal`의 index 변경 이벤트를 `MapView.tsx`의 포커스 이동 함수(`map.morph()` 경유)에 연결
5. 각 카드가 뷰포트에 들어올 때 `/api/drops/poi/[poiId]` 호출해 해당 POI의 드랍 아이템배지 목록 채움
   (이미 열람한 POI는 캐싱해 재호출 방지)
6. 소스코드 → 스테이징까지 반영 (스토리북 포함, staging push 시 자동 재빌드)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- MODULAR에 `Carousel` 프리미티브 신규 추가 — CSS scroll-snap 기반 네이티브 스와이프 + 클론 슬라이드
  ([마지막, ...items, 첫]) 트릭으로 무한 루프 구현. 클론 슬라이드에 안착하면 애니메이션 없이 실제
  위치로 순간 이동시켜 리셋 없이 이어지는 것처럼 보이게 한다.
- 서비스 측 `PoiCarouselModal`을 신설해 `DropsClient.tsx`의 기존 POI 바텀시트(하단 고정)를
  대체 — 화면 중앙 모달 + 캐러셀 아이템 자체가 모달 카드(모달·캐러셀 통합, 중앙 카드 = 선택된 POI).
  드랍/픽업/인벤토리 플로우 상태는 전부 이 컴포넌트로 이관해 `DropsClient.tsx`를 단순화했다.
- POI 정렬: 거리순(`distance_meters` 오름차순) 후 클릭한 POI가 캐러셀 index 0(중앙)에 오도록
  순환 회전.
- 3개 단위 윈도잉: 캐러셀은 최초 3개만 공개(`visibleCount`)하고, 활성 카드가 공개된 윈도우 끝에
  가까워지면 3개씩 확장(최대 전체 개수까지). 전체가 공개된 뒤에는 Carousel 자체의 모듈로
  인덱싱으로 전체 목록을 무한 순환한다.
- 카드별 드랍 아이템 목록(`/api/drops/poi/[poiId]`)은 공개된 카드마다 지연 로드하고 POI id로
  캐싱해 재열람 시 재호출하지 않는다(네이버 fallback POI인 `poi_tier===2`는 DB 미저장이라 스킵).
- 카드 세로 높이: 최대 높이/스크롤 제약 없이 자연 높이로 렌더 — 캐러셀 컨테이너를
  `alignItems:'flex-end'`로 하단 고정해 배지가 많을수록 카드가 위로만 길어지도록 했다
  (2026-08-20 사용자 피드백 반영 — 최초 구현의 `flex-start`/상단 고정 해석을 정정).
- 지도 포커싱: `MapView`에 `onMapReady` 콜백을 추가해 `focusPoi(lat,lng)` 명령형 핸들을 전달받고,
  캐러셀 활성 카드가 바뀔 때(스와이프 포함)마다 기존 `map.morph()` 패턴으로 포커싱한다.
  (`next/dynamic`으로 지연 로드되는 `MapView`는 `ref`를 forwardRef 없이 그대로 전달받지 못해
  ref 대신 콜백 방식을 택함 — 아래 "주요 의사결정" 참고)
- 현재 위치 버튼(`handleLocateClick`)은 기존 구현 그대로 유지, 신규 구현 없음. 레이아웃 충돌은
  기존과 동일(모달 오픈 중에는 모달이 위에 덮는 것이 기존 바텀시트와 같은 동작이라 회귀 아님).

### 2026-08-20 사용자 피드백 반영 수정
게이트 리뷰는 WARN(FAIL 아님)이었으나, 사용자가 아래 3건을 명시적으로 지적해 반영했다.

1. **범위 축소(원복)**: 이 캐러셀은 "드랍/픽업 가능한 POI 지점"에만 적용되고, POI 배지
   (`user_poi_badge_earns`, 반복 획득형 배지) 기능과는 무관하다는 것이 재확인됐다("반경 밖의
   POI는 존재하지 않음"). 최초 구현이 `in_drop_range===false`인 POI(반경 밖/네이버 fallback)를
   클릭했을 때도 캐러셀을 열고 안내 카드를 보여주도록 확장한 것은 스펙에 없던 임의 확장이었다 —
   `DropsClient.tsx`의 `handlePoiSelect`에 `in_drop_range` 체크를 복원해, 반경 밖 마커 클릭 시
   캐러셀을 열지 않고 기존처럼 토스트(`d.drops.outOfRange`)만 표시하도록 되돌렸다. 더불어
   `PoiCarouselModal`의 `orderedPois` 계산 자체를 `in_drop_range===true`인 POI만 대상으로
   필터링해, 캐러셀로 스와이프해 도달하는 다른 카드도 반경 밖 POI가 섞여 들어오지 않게 했다
   (마커 클릭 시점 가드만으로는 반경 내 다른 마커로 목록이 갱신될 때 반경 밖 POI가 끼어들
   여지가 남아 있었음).
2. **정렬 기준점 정정**: 캐러셀 좌우 스와이프 구조는 유지, 정렬 기준만 수정. `Carousel.jsx`
   컨테이너를 `alignItems:'flex-start'`(상단 고정)에서 `alignItems:'flex-end'`(하단 고정)로
   변경 — 모든 카드의 하단이 같은 기준선에서 시작하고, 드랍된 아이템배지가 많은 카드는 위쪽으로만
   늘어난다.
3. **카피/UI 제거**: 1번 수정으로 더 이상 이 모달에서 쓰이지 않게 된 "반경 밖" 안내 카드 UI를
   `PoiCarouselModal`의 `PoiCard`에서 제거했다. `d.drops.outOfRange` i18n 키는 grep 확인 결과
   `DropsClient.tsx`의 복원된 토스트에서 계속 쓰이므로 키 자체는 유지, 캐러셀 모달 쪽 사용처만
   제거했다.

### 주요 의사결정 / 핵심 메모

- POI 정렬은 거리순 확정 (지도 좌표순 대안 기각)
- `MapView`에 `ref`를 직접 전달하는 대신 `onMapReady` 콜백으로 명령형 핸들을 넘기는 방식을
  택함 — `next/dynamic`이 반환하는 `LoadableComponent`는 `forwardRef`로 감싸져 있지 않아
  `<DynamicMapView ref={...}>`로는 ref가 실제로 전달되지 않는다(React가 경고를 내며 무시).
  콜백 방식은 이 제약과 무관하게 동작한다.
- 캐러셀 무한 루프는 커스텀 포인터 드래그 물리 코드 대신 CSS `scroll-snap` + 클론 슬라이드
  트릭을 택함 — 터치/트랙패드/마우스 드래그를 브라우저가 그대로 처리해 제스처 코드가 필요 없고,
  더 적은 코드로 더 안정적으로 동작할 것으로 판단(대안: 직접 pointer 이벤트로 드래그·관성·스냅을
  구현하는 방식은 코드량과 버그 표면적이 커 기각).

### 잔여 이슈
- 실기기 스와이프 체감(관성, 클론 슬라이드 점프 시 미세한 끊김 여부)은 브라우저 환경에서
  실측하지 못했다 — staging 병합 후 확인 필요.
- 반경 내 POI가 많고(예: 15개 이상) 카드마다 드랍된 배지 수가 들쭉날쭉한 경우, `visibleCount`가
  커질수록 캐러셀 컨테이너 높이가 그 시점까지 공개된 카드 중 가장 높은 카드에 맞춰 커질 수
  있다(스크롤 컨테이너 특성상 화면 밖 카드도 높이 계산에 포함됨). 실사용 데이터로 체감 확인 필요.
