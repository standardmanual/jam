# [UI] 프로필 상단 영역 개편

## 배경 / 문제 정의
프로필 화면 상단 헤더(아바타·아이디·이메일·포인트·편집/팔로우 버튼)가 Card 박스 안에
빽빽하게 배치돼 있고, 이메일이 불필요하게 노출되고 있다. Figma 시안(컨텐츠 배치만 참고,
디자인 토큰은 무시)을 바탕으로 레이아웃을 재구성한다.

### 재시도 (게이트 리뷰 FAIL 대응, 2026-08-20)
- 게이트 리뷰 지적: 아이디 `<p>` 태그에 `truncate`는 있으나, 이를 감싸는 요소(당시 구조상 `<p>`
  자신이 flex 아이템)에 `min-w-0`가 없고 별도 `<div className="flex-1" />` 스페이서로 여백을
  분리해 두고 있어, Flexbox 기본값(`min-width:auto`)에서 truncate가 실제로 걸리지 않을 수 있다는
  지적.
- 수정: 아이디 `<p>`를 `<div className="flex-1 min-w-0">`로 감싸고, 별도 스페이서
  `<div className="flex-1" />`는 제거(래핑 div가 스페이서 역할도 겸함). 코드베이스 기존 컨벤션
  (`ListRowCard.tsx:46`)과 동일한 패턴.
- 검증: Playwright 헤드리스 Chromium으로 최대 허용 길이(30자) 아이디를 넣은 재현 페이지를
  렌더링해 (1) 수정 전 구조, (2) 수정 후 구조 각각의 실제 truncate 동작을 측정·스크린샷으로
  확인함. 두 구조 모두 시각적으로는 말줄임표가 표시되고 우측 요소가 밀려나지 않았는데, 이는
  `truncate`에 포함된 `overflow:hidden`이 CSS Flexbox 스펙상 해당 flex 아이템을 "스크롤
  컨테이너"로 만들어 자동 최소 너비를 0으로 만드는 별도 규칙 때문일 가능성이 있음(즉 수정 전
  구조도 `<p>`가 flex 아이템 자신일 때는 이 특정 케이스에서 이미 truncate가 걸렸을 수 있음).
  다만 이는 overflow:hidden이 flex 아이템 자신에 직접 걸려 있을 때만 성립하는 스펙상의
  엣지케이스이고, 아바타·우측 버튼 폭 변화나 향후 구조 변경에도 안정적으로 truncate를
  보장하는 방법은 명시적 `min-w-0`뿐이며 게이트 리뷰가 요구한 코드베이스 컨벤션이기도 하므로
  그대로 적용함.
- 작업 중 이 저장소 작업 디렉터리를 다른 세션(티켓 018)이 동시에 사용하고 있어 `git checkout`이
  서로 되돌아가는 레이스 상황이 발생했다. 이후로는 작업 디렉터리 체크아웃을 건드리지 않고
  `git commit-tree`/`update-ref` plumbing 명령으로 019 브랜치에 직접 커밋을 쌓는 방식으로
  우회해 018 세션의 미커밋 작업을 건드리지 않고 안전하게 반영·push함
  (코드 수정 커밋 `cd9970c`, 이 문서 갱신 커밋은 그 다음 커밋).
