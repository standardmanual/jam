# [bug] POI 캐러셀 3건 — 로딩 지연 / 옆카드 잘림 / 패널 위치 정정

## 배경 / 문제 정의
프로덕션 사용자 리포트 3건. 티켓 20260820_018/020으로 배포된 POI 캐러셀 모달 관련.

1. 캐러셀 카드를 열면 드랍 데이터 로딩이 매우 오래 걸려 스핀휠만 계속 돈다. 지도를 이리저리
   옮기다 보면 그제서야 한두 개가 보인다.
2. 캐러셀의 이전/다음(peek) 카드가 화면 끝에서 잘려서 보인다 — 마진 여백 없이 페이지(화면) 끝에
   딱 맞춰 배치돼야 한다.
3. "카드를 하단에 맞춰 정렬"이라는 요구사항은 카드 내부 정렬이 아니라, **캐러셀 패널 전체가
   TabBar 바로 위에 고정**되고(이 기능 개발 전 바텀시트 위치와 동일), 컨텐츠가 길어지면 패널이
   **위쪽으로만** 늘어나야 한다는 뜻이었다. 현재 구현(화면 중앙 모달, 카드 컨테이너만
   `alignItems:'flex-end'`)은 이 의도와 다르다 — 정정 필요.

## 원인 조사 결과 (오케스트레이터, 이미 확인 완료)

### 1. 로딩 지연 — 근본 원인은 `PoiCarouselModal`이 아니라 상위 `/api/drops` GET
`jam-web/src/app/api/drops/route.ts`가 매 요청마다 동기적으로 외부 API를 호출한다:
- L112: `reverseGeocodeToRegionName` — 네이버 역지오코딩(타임아웃 5s, 캐시 없음, 매 요청마다 호출)
- L118-138: 카테고리 검색 캐시 미스 시 `fetchNearbyNaverPoisForCategories`가 카테고리×키워드
  조합만큼 네이버 지역검색 API를 병렬 호출(개별 타임아웃 8s). 레벨1 결과가
  `LEVEL_2_FALLBACK_THRESHOLD` 미만이면 레벨2까지 한 번 더 호출 — 최악의 경우 13초+ 소요 가능.
- L99-105, L124-130, L143-149: 동일 bbox로 `poi` 테이블을 **3번** 재조회(불필요한 라운드트립).
- `DropsClient.tsx`가 이 응답을 기다리는 동안 `pois`가 비어 있어 캐러셀이 열려도
  `visiblePois`가 비고, `PoiCarouselModal`의 `fetchPoiDrops`/캐시 로직(L110-141) 자체는 정상이며
  원인이 아니다. "지도를 옮기면 보인다"는 현상은 지도 조작이 트리거가 아니라, 느린 요청이
  백그라운드에서 진행되다가 우연히 그 사이에 완료되는 코인시던스로 판단됨.

### 2. 옆카드 잘림
`PoiCarouselModal.tsx`의 센터 정렬 레이어(`px-[var(--spacing-16)]`)와 `Carousel.jsx`의
`scroll-padding`(10%) 조합이 뷰포트를 좁혀, peek 카드가 화면 끝에서 잘려 보인다.

### 3. 패널 위치
`PoiCarouselModal.tsx`의 최상위 레이어가 `flex flex-col items-center justify-center`로
화면 세로 중앙에 패널을 배치한다 — TabBar 위 고정 위치가 아니다.

## 상세 요구사항

### 서비스/코드베이스 관점 (성능)
- `jam-web/src/app/api/drops/route.ts`의 동일 bbox `poi` 테이블 3회 재조회를 1회로 통합한다.
- 역지오코딩(`reverseGeocodeToRegionName`) 결과에 캐시를 추가한다(예: 좌표를 적당히 반올림한
  키로 짧은 TTL 캐시) — 매 요청마다 네이버 API를 부르지 않도록.
- 네이버 지역검색(T2 카테고리 검색)이 응답을 블로킹하는 시간을 줄인다. 방법은 조사 후 결정하되,
  우선순위: (a) 캐시에 이미 있는 결과(T1 + 캐시된 T2)는 즉시 응답하고, 캐시 미스분만 백그라운드로
  채워 다음 요청부터 반영되게 하는 방식을 우선 검토. 리스크가 크면 최소한 전체 응답에 합리적인
  타임아웃 상한(예: 3~4초)을 걸어 최악의 경우에도 빠르게 응답하도록 한다.
- 백엔드 로직 변경이므로 회귀 위험(POI 목록 정확성, T1/T2 병합 로직)에 특히 주의하고, 변경 전후
  응답 구조/필드가 동일함을 확인한다.

### UI/UX 관점
- `PoiCarouselModal.tsx`의 센터 정렬 레이어에서 좌우 padding(`px-[var(--spacing-16)]`)을 제거해
  캐러셀이 화면 폭 전체를 쓰도록 한다. `Carousel.jsx`의 peek 폭/scroll-padding 값도 이에 맞춰
  재조정해 옆 카드가 잘리지 않고 온전히 보이도록 한다.
- `PoiCarouselModal.tsx`의 패널 컨테이너를 화면 세로 중앙 배치(`justify-center`)에서
  **TabBar 바로 위 고정**(이 기능 개발 이전 바텀시트와 동일한 하단 위치, safe-area 및 TabBar
  높이 고려)으로 변경한다. 컨텐츠(드랍된 배지 수)가 많아지면 패널이 위쪽으로만 늘어나야 한다
  (`Carousel.jsx`의 카드 컨테이너 `alignItems:'flex-end'`는 그대로 유지 — 이건 카드 내부 정렬로는
  맞는 방향이었음).
- TabBar 컴포넌트의 높이/safe-area 처리 방식을 확인해 동일한 기준으로 맞춘다.

## 구현 계획

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. `/api/drops` GET — 응답 경로에서 역지오코딩·네이버 지역검색을 완전히 제거하고 Next.js
   `after()`로 응답 전송 후 백그라운드에서 수행하도록 변경. 이번 요청은 DB에 이미 있는 T1/T2
   POI만 즉시 응답하고, 캐시 미스분(신규/만료 카테고리)은 백그라운드에서 검색·저장되어 다음
   요청부터 반영된다(티켓 "우선순위 (a)" 방식). 동일 bbox `poi` 재조회도 3회→1회로 통합
   (백그라운드 함수 내부에서 레벨2 판정을 위해 1회 재조회하지만 응답 경로와 무관).
2. `reverseGeocodeToRegionName`에 좌표를 ~100m 격자로 반올림한 키 기반 인메모리 캐시 추가
   (성공 24시간 TTL, 실패 60초 TTL). 이제 백그라운드 작업 안에서만 호출된다.
3. `PoiCarouselModal.tsx` — 센터 정렬 레이어의 좌우 padding(`px-[var(--spacing-16)]`) 제거,
   `justify-center`(화면 세로 중앙) → `justify-end` + TabBar 높이만큼 paddingBottom(TabBar와
   동일한 `safe-area+16px+64px` 관례에 12px 여유를 더함)으로 변경해 패널을 TabBar 바로 위에
   고정하고 컨텐츠가 늘어나면 위로만 자라도록 함. 닫기 버튼에는 별도로 `px-16`을 남겨 화면
   가장자리에 붙지 않게 함.
4. `Carousel.jsx` — `SLIDE_WIDTH_PERCENT` 80%→72%로 축소. 부모 padding 제거 후에도 80%는
   실측 peek이 ~20px 남짓(카드 내부 콘텐츠가 거의 안 보임)이라 72%로 좁혀 실측 peek을
   35~44px(390~430px 폭 기준)로 넓힘 — Storybook `CenterFocusInfiniteLoop` 스토리를 Playwright로
   390px/430px 뷰포트에서 스크린샷·DOM 실측해 확인.
5. Carousel 카드 내부 `alignItems:'flex-end'`(하단 정렬)는 변경하지 않음 — 요구사항대로 유지.
