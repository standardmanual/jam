# [bug] POI 캐러셀 — tier2 POI 무한 로딩 스피너 / 닫기 버튼 위치

## 배경 / 문제 정의
프로덕션 사용자 리포트 2건.

1. 특정 POI 카드를 열면 1분 넘게 로딩 스피너가 멈추지 않음.
2. 닫기(X) 버튼이 카드 바깥(캐러셀 위 별도 행)에 떠 있어 위치가 어색함 — 카드 안쪽 우측
   상단으로 옮겨달라는 요청.

## 원인

### 1. tier2 POI 무한 스피너
[PoiCarouselModal.tsx](../../../../jam-web/src/components/PoiCarouselModal.tsx)의 드랍 목록
지연 로드 useEffect가 `poi.poi_tier === 2`(네이버 자동수집 POI, DB에 `poi_drops`가 연결될 수
없음)인 경우 `continue`로 API 호출 자체를 건너뛰었다. 문제는 이 분기가 `dropsCache[poi.id]`를
채우지 않은 채 그냥 넘어가, `dropsCache[poi.id]`가 영원히 `undefined`로 남는다는 것이다.
`PoiCard`의 렌더 조건은 `loading || drops === undefined ? <스피너> : ...`이므로, tier2 POI
카드는 절대 스피너를 벗어나지 못했다(사용자 스크린샷의 "성은약국", 이전 리포트의
"코코온누리약국" 모두 이 케이스로 추정).

### 2. 닫기 버튼 위치
캐러셀 패널 상단에 별도 행으로 `IconButton`이 있어 카드 바깥에 떠 보이는 레이아웃이었다.

## 상세 요구사항
1. tier2 POI는 API를 호출하지 않고 `dropsCache[poi.id]`를 빈 배열로 즉시 채운다 —
   "드랍된 배지 없음" 빈 상태(EmptyState)로 정상 렌더되도록.
2. 닫기 버튼을 캐러셀 위 별도 행에서 제거하고, 각 `PoiCard`의 헤더(제목·거리 텍스트) 우측에
   같은 행으로 배치한다. 모든 카드가 동일한 `onClose`를 받아 어느 카드에서 눌러도 전체
   캐러셀 모달이 닫힌다.

## 구현 계획
1. `PoiCarouselModal.tsx`의 드랍 지연 로드 useEffect에서 tier2 분기를 `continue`가 아니라
   `dropsCache`를 빈 배열로 채우는 것으로 변경(react-hooks/set-state-in-effect 규칙 때문에
   마이크로태스크로 지연)
2. 캐러셀 위 닫기 버튼 행 제거, `PoiCard`에 `onClose` prop 추가해 헤더 우측에 `IconButton` 배치
3. tsc/eslint/build 검증 후 소스코드 → 스테이징 → 프로덕션까지 반영

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `PoiCarouselModal.tsx`의 드랍 지연 로드 useEffect: tier2 POI는 `continue`로 스킵하는 대신
  `dropsCache[poi.id]`를 빈 배열로 즉시 채우도록 수정 — 무한 스피너 해소.
  `react-hooks/set-state-in-effect` 규칙 때문에 이 setState와 기존 `fetchPoiDrops(poi.id)`
  호출(내부에서 첫 await 전에 `setLoadingIds`를 동기 호출) 모두 `Promise.resolve().then()`으로
  마이크로태스크 지연 처리(같은 틱 내, 페인트 이전 실행이라 체감 타이밍 차이 없음).
- 캐러셀 패널 상단의 독립 닫기 버튼 행 제거. `PoiCard`에 `onClose: () => void` prop을 추가하고,
  헤더(제목+거리 텍스트) 오른쪽에 `IconButton`을 같은 행으로 배치(`flex items-start
  justify-between`) — 카드 안쪽 우측 상단에 위치.

  요청을 만들지 않음).
