# [UI] 배지 공유 — 실제 이미지 생성 + 스트라바 연동 + OS 공유시트

## 배경 / 문제 정의

티켓 `20260821_003`에서 UI 셸(공유 아이콘 버튼 + 전체화면 바텀시트 + 더미 미리보기)까지
구현했다. 이번 티켓은 그 안을 실제 기능으로 채운다: 피그마 템플릿대로 투명 PNG를 실제 생성하고,
스트라바 데이터(페이스·시간)를 연동하고, OS 공유시트(또는 다운로드)로 내보낸다.

PRD: `Service Plan/Specs/PRD/BadgeShare/PRD.md` 참조 — 이번 티켓의 상세 스펙(템플릿 좌표,
데이터 소스, 예외 처리)은 전부 이 PRD를 단일 진실 원천으로 따른다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **이미지 생성**: `BadgeShareButton.tsx`(티켓 003에서 신설)의 더미 미리보기를 실제 생성
   파이프라인으로 교체.
   - DOM에 PRD 6장의 템플릿 레이아웃(1080×1920, 배지 483×483 contain, 텍스트 3세트 또는
     로고만)을 오프스크린(화면 밖, `position: absolute; left: -9999px` 등)으로 렌더링한 뒤
     `jam-web/src/app/admin/badges/bakePreviewToBlob.ts` 패턴을 확장해 `canvas.toBlob()`으로
     PNG Blob 생성.
   - 폰트: `Inter Bold`, 폴백 `Arial Bold`. 웹폰트 로딩 타이밍 이슈(canvas 렌더링 시 폰트 미로드로
     기본 폰트가 찍히는 문제)에 주의 — `document.fonts.ready` 대기 등 필요.
2. **스트라바 데이터 연동**:
   - 액티비티/POI 배지: `triggered_by_strava_id`로 스트라바 액티비티를 재조회해 페이스·시간을
     계산. 클라이언트가 스트라바 access token을 직접 다루지 않으므로 신규 API 라우트
     (`jam-web/src/app/api/badges/[id]/share-data` 등, 라우트명은 구현 시 기존 API 네이밍
     관례에 맞춰 결정)에서 `lib/strava/api.ts`의 `getActivityById`를 호출해 필요한 값만
     클라이언트로 반환한다.
   - `triggered_by_distance_km`는 이미 DB에 있으므로 재조회 불필요, 그대로 사용.
   - **신규 API 라우트가 추가되므로 PRD 갱신 트리거에 해당** — 이미 위 PRD 문서에 반영해뒀으니
     구현 중 API 계약(요청/응답 스키마)이 PRD와 달라지면 PRD도 함께 갱신할 것.
3. **아이템 배지**: 스트라바 조회 없이 배지 이미지 + 로고만으로 즉시 생성 가능.
4. **예외 처리**:
   - 스트라바 토큰 만료/연동 해제 상태의 유저가 액티비티/POI 배지 공유 시도 시: 공유 버튼
     비활성화 + 안내 문구 (UX Writing 가이드의 에러 3단계 구조 참고, 다만 이건 에러라기보다
     "지금은 못 함" 안내이므로 톤 조정)
   - 스트라바 API 조회 실패(레이트리밋·5xx 등)도 유사하게 처리.
5. **공유/다운로드**:
   - `navigator.share` 지원 시 생성된 PNG Blob을 `navigator.canShare`로 확인 후 공유시트 호출.
   - 미지원(주로 데스크톱) 시 PNG 다운로드 링크(`<a download>` 또는 `URL.createObjectURL` +
     프로그래매틱 클릭)로 대체.

- `buildBadgeShareBlob.ts` 신규: 피그마 템플릿(1080×1920, 배지 이미지 483×483 contain, activity/poi는
  DISTANCE·PACE·TIME 텍스트 3세트 + 로고, item은 이미지+로고만)을 오프스크린 `<canvas>`에 Canvas 2D

  재사용. `document.fonts.ready` 대기로 웹폰트 미로드 이슈 방지.
- `BadgeShareButton.tsx` 전면 교체: 시트를 열면 (미획득 시 API 호출 없이 미획득 안내) → (획득 시

### 주요 의사결정 / 핵심 메모
- **DOM 캡처 대신 Canvas 2D 직접 합성**: 티켓은 "오프스크린 DOM 렌더링 후 `canvas.toBlob()`"을
  지시했지만, 이 프로젝트엔 DOM 래스터라이즈 라이브러리(html2canvas 등)가 없고 `bakePreviewToBlob.ts`의
  기존 구현은 "이미 렌더링된 단일 `<canvas>`/`<img>` 노드를 그대로 캡처"하는 방식이라 배지 이미지 +
  텍스트 3세트 + 로고의 합성에는 맞지 않는다. 대신 `<canvas>` 하나에 `drawImage`/`fillText`로 직접
  그리는 방식을 택하고, 마지막 PNG 변환 단계(`canvasToBlob`)만 기존 유틸을 그대로 재사용해 "패턴 확장"
  취지를 지켰다.
- **PACE는 `moving_time`, TIME은 `elapsed_time` 기준**: PRD가 "moving_time/elapsed_time에서 페이스·
  시간 계산"이라고만 명시하고 어느 필드를 어디에 쓸지 명시하지 않아, 페이스는 정지 시간을 뺀
  `moving_time` 기준(표준적인 러닝 페이스 계산 방식)으로, TIME은 정지 시간을 포함한 `elapsed_time`
  기준(활동 시작~종료까지 전체 소요 시간)으로 계산하도록 결정했다.
- **미획득 배지는 API 호출 없이 바로 미획득 안내**: 티켓의 예외 처리 목록엔 스트라바 토큰
  만료/연동 해제만 명시돼 있었지만, 활동/POI 배지는 획득 전에는 거리·페이스·시간 데이터 자체가
  없어 공유 이미지를 만들 수 없다. `hasEarned=false`면 API를 아예 호출하지 않고 기존 페이지의
  "아직 획득하지 못한 배지예요" 문구를 그대로 재사용해 안내한다(신규 문구 추가 없이 일관성 유지).
- **템플릿 좌표는 재설계**: 피그마 노드(`1:55`/`1:60`)의 정확한 좌표를 조회할 수단이 없어(이 서브
  에이전트에는 Figma MCP가 연결돼 있지 않음), PRD가 명시한 캔버스 크기(1080×1920)·배지 영역
  (483×483 contain)·로고 크기(174×72)·라벨/값 폰트 크기(~20px/~51px)는 그대로 따르되 상하 여백은
  균형 잡힌 값으로 새로 설계했다. 실제 피그마 시안과 픽셀 단위로 다를 수 있어 시각 QA가 필요하다.
- **Web Share 지원 여부 판정 기준**: `navigator.canShare({ files: [file] })`는 실제 파일이 있어야
  정확히 판정되므로, 액션 버튼 라벨(공유하기/저장하기)은 시트가 열린 시점에 `navigator.share`/
  `navigator.canShare` 함수 존재 여부만으로 미리 결정하고, 실제 공유 가능 여부(`canShare(files)`)는
  버튼 클릭 시점에 다시 확인한다.

### 잔여 이슈
- 템플릿 상하 여백·폰트 크기가 피그마 시안과 픽셀 단위로 정확히 일치하는지 실제 Figma 파일과
  대조하는 시각 QA가 필요하다(위 "주요 의사결정" 참고).
- `no_strava_trigger`(획득했으나 트리거 활동 스냅샷이 없는 레거시/어드민 발급 케이스)는 실제
  운영 데이터에 이런 배지가 얼마나 있는지 확인되지 않았다 — 사용자가 이 안내를 실제로 보게 될
  빈도는 미검증.
