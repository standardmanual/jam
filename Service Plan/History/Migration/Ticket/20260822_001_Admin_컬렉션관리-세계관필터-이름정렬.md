# [Admin] 컬렉션 관리 목록 — 세계관별 필터 + 이름 오름차순/내림차순 정렬 추가

## 배경 / 문제 정의
어드민 `/admin/itembooks`(사이드바 라벨: "컬렉션") 목록은 현재 `created_at` 내림차순 고정
정렬만 지원하고, 별도 필터가 없다. 컬렉션 수가 늘면서 특정 세계관(faction)에 속한 컬렉션만
보거나 이름순으로 훑어볼 방법이 없어 운영 효율이 떨어진다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 대상 화면: [jam-web/src/app/admin/itembooks/page.tsx](jam-web/src/app/admin/itembooks/page.tsx)
  → [ItemBookList.tsx](jam-web/src/components/admin/itembooks/ItemBookList.tsx)
  (모바일 카드: [ItemBookCard.tsx](jam-web/src/components/admin/itembooks/ItemBookCard.tsx),
  데스크톱 테이블: [ItemBookTable.tsx](jam-web/src/components/admin/itembooks/ItemBookTable.tsx))
- 목록 상단에 필터 바 신설:
  1. **세계관 필터**: `factionMap`(이미 `page.tsx`에서 `factions` 테이블 조회 후 전달 중)을 기반으로
     드롭다운/셀렉트 구성. "전체" 옵션 포함. `item_books.faction_id`로 매칭.
  2. **이름 정렬 토글**: 오름차순/내림차순 전환 (기본값은 기존과 동일하게 등록일 최신순 유지,
     사용자가 이름 정렬을 선택했을 때만 `name` 기준 asc/desc 적용)
- 필터링·정렬은 클라이언트 사이드 처리 권장 (이미 전체 목록을 `page.tsx`에서 한 번에 불러와
  `ItemBookList`에 내려주는 구조이므로 서버 재조회 불필요). 유사 패턴 참고:
  [jam-web/src/app/admin/poi/PoiFilters.tsx](jam-web/src/app/admin/poi/PoiFilters.tsx)
- 모바일 카드 뷰·데스크톱 테이블 뷰 양쪽 모두에 필터 결과가 반영되어야 함
  (`ItemBookList`가 두 뷰의 공통 상위이므로 여기서 필터링된 배열을 각각에 전달)

## 구현 계획
1. `ItemBookList`(또는 신설 `ItemBookFilterBar` 컴포넌트)에 로컬 상태(`selectedFactionId`,
   `sortOrder: 'default' | 'name-asc' | 'name-desc'`) 추가
2. `itemBooks` 배열을 상태 기준으로 필터링(`faction_id` 일치) → 정렬(이름 선택 시 `localeCompare`)
   한 파생 배열을 만들어 `ItemBookCard`/`ItemBookTable`에 전달
3. 빈 결과 시 기존 "등록된 컬렉션이 없습니다" 문구를 필터 상황에 맞게 조정 검토
   (예: "조건에 맞는 컬렉션이 없습니다")

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`ItemBookList`에 로컬 상태(`selectedFactionId`, `sortOrder`)를 추가하고, 헤더와 목록 사이에
필터 바(세계관 셀렉트 + 정렬 셀렉트)를 신설했다. `factionMap`(전체 factions) 기준으로 세계관
드롭다운을 구성하고, `item_books.faction_id` 일치 여부로 필터링한다. 정렬은 기본값(`default`,
등록일 최신순 — 서버에서 이미 `created_at desc`로 조회)을 유지하다가 사용자가 "이름 ↑/↓"를
선택하면 `localeCompare('ko')` 기준으로 정렬한다. 필터·정렬된 파생 배열(`filteredItemBooks`)을
모바일 카드(`ItemBookCard`)와 데스크톱 테이블(`ItemBookTable`) 양쪽에 동일하게 전달한다.
빈 결과 문구는 필터가 적용된 상태인지 여부에 따라 "조건에 맞는 컬렉션이 없습니다." /
"등록된 컬렉션이 없습니다."로 분기했다. 서버 재조회 없이 클라이언트 사이드에서 처리한다.

### 주요 의사결정 / 핵심 메모
- 세계관 필터 옵션은 티켓 지시대로 `page.tsx`에서 이미 전달받는 `factionMap`(전체 `factions`
  테이블) 기준으로 구성했다. 즉 어떤 컬렉션에도 사용되지 않은 세계관도 드롭다운에 노출될 수
  있으나, 티켓에 "factionMap 기반으로 드롭다운 구성"이라고 명시돼 있어 별도 필터링(사용 중인
  세계관만 노출) 로직은 추가하지 않았다.
- 필터 바 위치·구조는 `jam-web/src/app/admin/poi/PoiFilters.tsx`(URL 쿼리 파라미터 + 서버
  재조회 방식)를 참고했으나, 티켓이 클라이언트 사이드 처리를 권장해 URL 상태 동기화 없이
  컴포넌트 로컬 상태로만 구현했다 (새로고침 시 필터가 초기화되는 트레이드오프 있음).
