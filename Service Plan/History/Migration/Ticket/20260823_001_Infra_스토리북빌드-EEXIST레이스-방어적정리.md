# [Infra] 스토리북 빌드 EEXIST 레이스 — 빌드 스크립트에 방어적 정리 추가

## 배경 / 문제 정의
2026-08-22 어드민 컬렉션 필터 배포(`main` push) 직후, `jam-stage` Vercel 프로젝트에서
부수적으로 트리거된 Preview 빌드가 스토리북 빌드 단계에서 실패했다:

```
Error: EEXIST: file already exists, mkdir './storybook-static/badges/poi/mountain'
  at async mkdir (node:internal/fs/promises:916:10)
  at async mkDirAndCopy (node:internal/fs/cp/cp:318:3)
```

`storybook build`가 outputDir(`storybook-static`) 정리 로그를 찍은 직후 발생한 것으로 보아,
정리(clean)가 완전히 끝나기 전에 `staticDirs`(`.storybook/main.ts`의 `../public`) 복사가
시작됐거나, 이전(취소된) 빌드의 잔여물이 남은 상태에서 복사가 시작된 것으로 추정된다.
Vercel 빌드 머신 내부 동작이라 정확한 레이스 메커니즘을 100% 특정하기는 어렵다.

이번 실패는 `jam-stage` 프로젝트의 버려지는 Preview 빌드에서만 발생했고 실제 서비스
(`j-a-m.app`, `jam-stage.vercel.app`)에는 영향이 없었다. 그러나 같은 빌드 스크립트가
프로덕션/스테이징 정식 빌드에도 쓰이므로 재발 시 실제 배포에도 영향을 줄 수 있는 잠재 리스크다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 대상 파일: [jam-web/package.json](jam-web/package.json) `build` 스크립트
- `storybook build` 실행 전에 `storybook-static`·`public/storybook`을 명시적으로 삭제해,
  잔여물 유무와 무관하게 항상 클린 상태에서 빌드를 시작하도록 방어적 정리 단계 추가
- 근본 레이스 메커니즘을 완전히 규명하진 못했지만, 이 방어적 정리로 증상 자체를 무력화한다
- (사용자 결정: 이번엔 `vercel.json`의 `ignoreCommand` 강화— jam-stage가 staging 외 브랜치
  push에 반응하지 않도록 하는 조치 — 는 적용하지 않음. 빌드 스크립트 방어적 정리만 적용)

## 구현 계획
`package.json`의 `build` 스크립트를:
```
storybook build && cp -r storybook-static public/storybook && next build
```
에서
```
rm -rf storybook-static public/storybook && storybook build && cp -r storybook-static public/storybook && next build
```
로 변경.
