# [UI] 플루이드 인터랙션 3건 수정 (Apple Fluid Interfaces 감사 후속)

## 배경 / 문제 정의
`/apple-design` 스킬로 프로덕션 서비스 전체를 감사한 결과, 모션 관련 이슈 중 사용자 체감이
가장 큰 3건을 우선 수정한다. 나머지 항목(재질/backdrop-filter, reduced-transparency·
reduced-contrast 대응, dialog/sheet 모션 통일 등)은 이번 범위에서 제외하고 완료 후 별도
안내한다.

프로젝트는 framer-motion 등 스프링 라이브러리 없이 순수 CSS transition/keyframe 기반
"transitions.dev 스니펫" 체계(`src/components/transitions.css`)를 쓴다. 각 블록은
참고 문서에서 원문 그대로 복사한 것이며 **원본 스니펫(셀렉터·keyframe)을 직접 고치지
말라는 파일 상단 주석 규칙이 있다** — 필요한 변경은 파일 맨 아래 "프로젝트 확장" 섹션에
덧붙이거나, 컴포넌트 자체 로직(JS)에서 흡수한다.

## 상세 요구사항

### 1. BottomSheet 드래그 닫기 — 릴리즈 속도 무시 (`src/components/ui/BottomSheet.tsx`)
- 현재 `handlePointerUp()`(122행)이 `dragY > DRAG_CLOSE_THRESHOLD(120)`만으로 닫힘을
  판정한다. 빠르게 짧게 내려도 안 닫히고, 느리게 121px 끌면 닫힌다.
- **요구사항**: `handlePointerMove`에서 최근 몇 개 포인트의 timestamp+위치를 기록해
  릴리즈 시 속도(px/ms)를 계산하고, "충분히 빠른 하향 플릭이면 거리와 무관하게 닫기"
  판정을 추가한다 (예: 속도 임계값 OR 거리 임계값, 둘 중 하나 충족 시 닫힘).
- 닫기 취소 시 원위치 트랜지션(`transition: transform 200ms ease-out`, 162행)이 고정
  duration이라 재드래그 시 매끄럽게 이어지지 않는다. 드래그 중 재시작(재클릭) 시
  현재 transform 값에서 자연스럽게 이어지는지 확인하고, 문제가 있으면 duration을
  줄이거나 현재 위치 기준으로 보정한다. 스프링 라이브러리 도입은 이번 범위 밖 —
  CSS transition 튜닝으로 해결한다.
- 기존 포인터 캡처·1:1 추적 로직은 그대로 유지한다 (양호하다고 감사에서 확인됨).

### 2. shadcn dialog/sheet가 JAM 모션 시스템 밖에서 논다 (`src/components/ui/dialog.tsx`, `sheet.tsx`)
- 현재 Radix + tailwindcss-animate 기본 keyframe(`zoom-in-95`, `slide-in-from-*`)을
  그대로 쓴다. keyframe이라 애니메이션 도중 상태가 뒤집히면(열림 중 닫힘 등) 현재
  값이 아닌 정의된 시작점에서 재생돼 점프가 생긴다.
- **요구사항**: `t-panel-slide`/`t-panel-backdrop`(BottomSheet가 쓰는 것과 동일 패턴,
  `transitions.css` 19~44행·378~391행)을 재사용해 `sheet.tsx`를 통일한다.
  `dialog.tsx`(중앙 모달)는 슬라이드 방향이 다르므로 무리하게 같은 클래스를 억지로
  끼워 맞추지 말고, 필요하면 `transitions.css` 맨 아래 "프로젝트 확장" 섹션에
  `t-panel-slide`를 응용한 중앙 모달용 변형(예: `data-open` 기반 scale+opacity
  transition)을 추가한다. `dialog.tsx`는 이번 범위에서 **트리거 요소 기준
  transform-origin까지는 요구하지 않음** — keyframe→transition 전환만 한다
  (인터럽트 가능성 확보가 목적, 공간적 앵커링은 별도 범위).
- Radix의 `data-[state=open|closed]` 속성을 `data-open` boolean으로 그대로 매핑할 수
  없다면, BottomSheet가 쓰는 `shown`/`lingering` 2단계 마운트 패턴 대신 Radix가 이미
  제공하는 마운트/언마운트 콜백(`onOpenAutoFocus` 등)이나 `forceMount`+수동 상태로
  대체 가능한지 판단해 구현한다.

### 3. keyframe 강제 재시작 — TabBar 활성탭 점 · PopInNumber
- `src/components/ui/TabBar.tsx`가 쓰는 `.t-badge`(`transitions.css` 73~120행,
  `@keyframes t-badge-slide-in`)와 `src/components/ui/PopInNumber.tsx`가 쓰는
  `.t-digit-group`(`transitions.css` 235~272행, `@keyframes t-digit-pop-in`) 둘 다
  `classList.remove → reflow → add`로 keyframe을 강제 재생하는 방식이다. 탭 연타나
  포인트 급증처럼 상태가 짧은 간격으로 연속 갱신되면 매번 시작점으로 스냅 후
  재생돼 이전 진행이 끊긴다.
- **요구사항**: 두 곳 모두 원본 keyframe 블록(`t-badge-slide-in`, `t-digit-pop-in`)은
  건드리지 않는다. 대신 컴포넌트 JS 레벨에서 "이미 애니메이션 진행 중이면 재시작을
  스킵"하거나 "마지막 값만 반영하도록 짧게 debounce"하는 가드를 추가해 재시작 빈도
  자체를 줄인다 (CSS를 keyframe→transition으로 완전히 바꾸는 것은 원본 스니펫 규칙과
  충돌하므로 이번 범위에서는 하지 않는다).

### UI/UX 관점
- 세 항목 모두 시각적으로 눈에 띄는 디자인 변경이 아니라 "느낌"의 개선이므로 별도
  UX 라이팅 검증 대상 텍스트는 없다.

## 구현 계획
- 파일 3~5개 내외 수정 (BottomSheet.tsx, dialog.tsx, sheet.tsx, TabBar.tsx,
  PopInNumber.tsx, 필요 시 transitions.css 맨 아래 확장 섹션에 추가).
- 신규 라이브러리 설치 없음 (framer-motion 등 도입하지 않음 — 순수 CSS/JS로 해결).
- 회귀 위험: BottomSheet는 이미 프로덕션에서 여러 화면(배지 공유 미리보기 등)에 쓰이므로
  드래그 판정 로직 변경 후 기존 동작(느린 드래그로도 닫히는지)이 깨지지 않는지 반드시
  확인한다. dialog/sheet 변경은 사용처(Confirm 다이얼로그 등) 전수 확인.
