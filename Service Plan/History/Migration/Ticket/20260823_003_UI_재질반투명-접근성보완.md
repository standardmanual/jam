# [UI] 재질(반투명 크롬) 도입 + reduced-transparency·contrast 접근성 보완

## 배경 / 문제 정의
`/apple-design` 감사 후속 티켓(3건 중 나머지 2건). 프로젝트 전체에서 `backdrop-filter`는
`NavigationLoader.tsx` 한 곳뿐이고, "떠 있는 크롬" 역할인 TabBar·TopNav·BottomSheet
백드롭은 모두 불투명/저정보 반투명이라 Apple HIG의 재질(materials) 원칙 — 반투명+blur로
계층(depth)을 표현 — 이 적용되어 있지 않다. 또한 `prefers-reduced-transparency`,
`prefers-contrast` 두 접근성 설정에 대한 대응이 프로젝트 전체에 전혀 없다
(`prefers-reduced-motion`은 이미 전역에 잘 되어 있음 — 참고 패턴으로 그대로 따른다).

> 참고: [20260823_002](./20260823_002_UI_플루이드인터랙션-3건수정.md)에서 다뤘던
> 4번 항목(TopNav `titleTracking="normal"`)은 재검토 결과 실제 버그가 아님이 확인됨
> (body 16px 타이틀엔 애초에 트래킹 토큰이 정의돼 있지 않아 `normal`이 올바른 값) —
> 이번 티켓 범위에서 제외한다.

## MODULAR 탐색 결과 (1.5단계)
`design-system/tokens/`에 재질(material/blur/translucency) 관련 토큰이 전혀 없음
(`_ds_manifest.json`·`readme.md`에 grep 결과 0건). 신규 토큰 카테고리 도입 필요 —
**MODULAR 확장**으로 판정 (서비스 전용으로 만들면 TopNav처럼 이미 연결된 컴포넌트와
값이 어긋날 위험이 있고, 향후 다른 화면에도 재사용될 성격의 값이므로).

- `design-system/components/navigation/TopNav.jsx` — 서비스 `TopNav.tsx`가 `@ds/*`로
  **실제로 import**하고 있음(20260820_009 연결 완료). 여기 수정하면 서비스에 자동 반영.
- `design-system/components/navigation/TabBar.jsx` — 캐노니컬 스펙은 있으나 서비스
  `src/components/ui/TabBar.tsx`는 **별도 Tailwind 구현이라 연결되어 있지 않음**
  (2026-08-20 기준 CLAUDE.md 연결 상태 노트와 일치, 여전히 미연결). 두 파일을 각각
  수정해야 하며 값이 어긋나지 않게 동일한 토큰을 참조하게 한다.
- `BottomSheet.tsx`(서비스 전용, MODULAR 대상 아님)의 백드롭은 서비스에서 직접 수정.

## 상세 요구사항

### 1. 재질(반투명 크롬) 도입
- **신규 토큰**: `design-system/tokens/colors.css`(또는 신규 `materials.css`)에
  `--blur-chrome`(예: 20px), `--color-chrome-bg`(반투명 배경, TabBar/TopNav 공용) 추가.
  다크/라이트 모드 값은 `colors.css`/`colors.light.css` 패턴을 그대로 따른다.
- **TopNav** (`design-system/components/navigation/TopNav.jsx`): `background: var(--color-bg)`
  → 반투명+`backdrop-filter: blur(var(--blur-chrome)) saturate(180%)`로 교체. 콘텐츠가
  아래로 스크롤되어 지나가는 상단 크롬이라 재질 적용 효과가 가장 큼.
- **TabBar** (`design-system/components/navigation/TabBar.jsx` + `src/components/ui/TabBar.tsx`
  둘 다): `--color-bg-inverse`/`bg-surface-inverse` 완전 불투명 → 반투명+blur로 교체.
  두 파일 모두 같은 토큰(`--blur-chrome`, `--color-chrome-bg`)을 참조하게 해서 값이
  갈리지 않게 한다.
- **BottomSheet 백드롭** (`src/components/ui/BottomSheet.tsx`, `bg-surface/60`): blur 추가.
  시트 본체(`bg-[var(--color-surface)]`)는 불투명 유지 — 백드롭(스크림)만 재질화한다.
- Apple 원칙 §12 "재질 무게로 계층 표현" — TopNav/TabBar는 구조적 크롬이라 상대적으로
  무거운(진한) blur, BottomSheet 백드롭은 스크림 역할이라 대비만 있으면 되므로 과도한
  blur를 넣지 않는다 (톤 조정은 구현 중 시각적으로 판단).

### 2. `prefers-reduced-transparency` / `prefers-contrast` 대응
- 1번에서 새로 추가하는 모든 반투명+blur 표면에 `@media (prefers-reduced-transparency: reduce)`
  가드를 짝지어 추가한다 — `backdrop-filter: none`, 배경을 solid(불투명) 값으로 승격.
  `prefers-reduced-motion` 가드가 이미 `src/app/globals.css`·`transitions.css`·
  `design-system/styles.css`에 있는 패턴(선언 바로 옆에 미디어 쿼리)을 그대로 따른다.
- `@media (prefers-contrast: more)` 가드를 다음 두 곳에 추가한다:
  - TabBar 비활성 아이콘 `--color-icon-inactive` — 활성/비활성 대비를 높인 값으로 승격.
  - 반투명 크롬 위에 얹히는 텍스트/아이콘(재질 위 비메탈릭 텍스트) — Apple 원칙 §12
    "vibrancy"에 따라 flat gray 대신 고대비 색+약간 굵은 weight로 대체.
- 새 토큰은 `design-system/tokens/`에 두어 서비스 쪽(BottomSheet, TabBar) CSS에서도
  `var(--...)`로 그대로 재사용한다 (중복 값 하드코딩 금지).

### UI/UX 관점
- 시각적으로 눈에 띄는 변화(반투명 크롬)가 있으므로 구현 후 라이트/다크 모드 스크린샷으로
  실제 대비가 무너지지 않는지 확인 필수 (특히 TabBar 활성/비활성 아이콘 구분).
- 사용자 노출 텍스트 변경 없음 — UX Writing 검증 대상 아님.

## 구현 계획
- `design-system/tokens/`에 재질 토큰 추가 (신규 파일 또는 `colors.css` 확장 — 판단은
  jam-developer가 기존 파일 분리 관례를 보고 결정).
- `design-system/components/navigation/TopNav.jsx`, `TabBar.jsx` 수정 + **Story 갱신**
  (반투명 배경이 Storybook 프리뷰에서도 보이도록 배경 콘텐츠가 있는 스토리 확인/추가).
- 서비스 쪽 `src/components/ui/TabBar.tsx`, `src/components/ui/BottomSheet.tsx` 수정.
- 신규 라이브러리 설치 없음.
- 회귀 위험: `backdrop-filter`는 구형 브라우저/저사양 기기에서 성능 비용이 있다 —
  TabBar는 스크롤 중 상시 노출되는 요소이므로 과도한 blur radius로 인한 프레임 드랍이
  없는지 실기기 확인 권장(이번 세션에서 어려우면 잔여 이슈로 남긴다).
- **완료 기록에 1.6단계 요구사항대로 명시할 것**: 이번 변경이 (a) TopNav처럼 스토리북+
  서비스에 동시 반영되는지, (b) TabBar처럼 스토리북에만 반영되고 서비스는 별도 수정이
  필요했는지 구분해서 기록.

## 구현 기록 (2026-08-23)

### 신규 토큰
`design-system/tokens/materials.css`(신규, 다크/기본) + `materials.light.css`(신규, 라이트
오버라이드) — `--blur-chrome`(20px, TopNav/TabBar 공용 구조적 크롬), `--blur-scrim`(8px,
BottomSheet 등 모달 백드롭 전용, 가벼운 값), `--color-chrome-bg`(TopNav/TabBar 공용 반투명
배경 — 다크 `rgba(0,0,0,0.72)` / 라이트 `rgba(255,255,255,0.72)`). `colors.css`/
`colors.light.css` 분리 패턴을 그대로 따름. 서비스(`src/app/globals.css`)는 `materials.css`만
import(다크 전용 고정), 스토리북(`design-system/styles.css`)은 두 파일 모두 import.

### (a) 스토리북+서비스 동시 반영 — TopNav
`design-system/components/navigation/TopNav.jsx`만 수정하면 서비스 `src/components/ui/TopNav.tsx`가
`@ds/components/navigation/TopNav`를 실제로 import하므로 자동 반영(20260820_009 연결).
`background: var(--color-bg)` → `.ds-topnav-chrome` 클래스(`background: var(--color-chrome-bg)`
+ `backdrop-filter: blur(var(--blur-chrome)) saturate(180%)`)로 교체. WanderingEyesLoader와
동일한 패턴(모듈 스코프 `STATIC_CSS` + 인라인 `<style>` 주입)을 사용 — 인라인 style에 배경을
두면 헤더 배경 오버라이드용 `style`/`headerStyle` prop이 항상 이겨 media query가 먹지 않기
때문(`badge-background-video` 케이스와 동일 이유로 클래스 분리).

### (b) 스토리북만 반영, 서비스는 별도 수정 필요 — TabBar
`design-system/components/navigation/TabBar.jsx`(캐노니컬)는 서비스와 미연결이라 별도로
`src/components/ui/TabBar.tsx`도 수정. 두 파일 모두 같은 토큰(`--blur-chrome`,
`--color-chrome-bg`)을 참조하되, 캐노니컬은 컴포넌트 내부 인라인 `<style>` 주입
(`.ds-tabbar-chrome`), 서비스는 Tailwind 클래스 기반이라 `src/components/transitions.css`
"프로젝트 확장" 섹션에 `.jam-tabbar-chrome`을 신설해 참조하는 방식으로 값만 맞췄다(이전
`bg-surface-inverse`/`--color-bg-inverse` 불투명 흰 필 → 반투명 크롬으로 교체).

**주의(설계 판단, alerts 참고)**: 기존 TabBar는 불투명 흰 필(`--color-bg-inverse`)이었으나
티켓이 "TopNav/TabBar 공용" 토큰을 명시해 TabBar도 TopNav와 동일한 톤(캔버스 기반 반투명
크롬)으로 전환했다. 이는 다크모드에서 흰 필 대신 어두운 프로스티드 크롬이 되는 시각적
변화이며, 기존 `--color-icon-inactive`(#2a2a2a, grey-700 — 흰 배경 전제)가 새 배경에서
거의 안 보이게 되어 `grey-500`(#b2b2b2)으로 재보정했다(라이트 테마는 grey-700 유지 —
라이트 크롬은 여전히 밝은 톤).

### `prefers-reduced-transparency` / `prefers-contrast` 대응
- TopNav(`.ds-topnav-chrome`), TabBar 캐노니컬(`.ds-tabbar-chrome`), TabBar 서비스
  (`.jam-tabbar-chrome`) 3곳 모두 `@media (prefers-reduced-transparency: reduce)` 가드로
  `backdrop-filter: none` + `background: var(--color-bg)`(solid) 승격.
- BottomSheet 백드롭은 `src/components/transitions.css`의 `.t-panel-backdrop`(공유 클래스,
  FeedSection·PoiCarouselModal과 공용)에 `backdrop-filter: blur(var(--blur-scrim))` 추가 +
  reduced-transparency 가드로 `background-color: var(--color-surface)`(solid) 승격.
- `--color-icon-inactive`에 `@media (prefers-contrast: more)` 가드 추가(`colors.css`
  다크/`colors.light.css` 라이트 양쪽) — `var(--color-text)`(테마별 최대 대비)로 승격.
  TopNav 타이틀/뒤로가기 아이콘은 이미 `--color-text`(최대 대비)라 별도 조치 불필요.
