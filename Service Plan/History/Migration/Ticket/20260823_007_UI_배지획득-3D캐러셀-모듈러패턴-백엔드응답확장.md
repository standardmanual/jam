# [UI] 배지 획득 3D 캐러셀 — MODULAR 패턴 등록 + 백엔드 응답 확장 + 스파이크 검증 페이지

> **이 티켓은 서비스 화면에 연결하지 않는다.** 실제 동기화 버튼 연결은 후속 티켓
> 20260823_008에서 사용자 승인 후 진행한다. 이 티켓의 산출물은 ① 백엔드 응답 확장
> ② MODULAR 신규 패턴 ③ 스파이크 검증 페이지 3종이며, `SyncButton.tsx`는 **손대지 않는다**.

## 배경 / 문제 정의

현재 스트라바 동기화가 끝나면 하단 탭바 위에 `"배지 3개 획득"` 토스트만 3초간 뜬다.
무엇을 얻었는지 보이지 않아 획득의 체감이 없다.

획득한 배지를 3D 코버플로우 캐러셀 카드로 한 장씩 보여주는 연출을 도입한다.
사용자가 제공한 Originkit/Framer 산출물(`Smooth3DSlideshow`)을 기반으로 하되, MODULAR
컨벤션에 맞게 전면 재작성한다.

### 현재 구조의 제약 (구현 전 반드시 인지할 것)

1. **`/api/strava/sync` 응답이 개수만 반환한다.**
   `{ synced, badges, itemBooksCompleted, missionsCompleted }` — 배지 이미지·이름·설명이 없다.
2. **엔진 4경로 중 어디도 `description`을 조회하지 않는다.**
   `badges.description`은 DB에 `TEXT NOT NULL`로 존재하고 운영 데이터 5,585행 전부 채워져
   있으나, 드랍/배지 엔진의 SELECT 목록에 없다.
3. **`tryItemDrop()`은 `Promise<void>`다.** 무엇이 드랍됐는지 호출자가 알 방법이 없다.
4. **제공된 소스코드는 Framer 산출물이다.** `.tsx` + default export + 외부 CDN 이미지 +
   `useIsStaticRenderer` 스텁 + `__originkitPresetProps` 등 MODULAR 컨벤션과 전면 충돌한다.

## 상세 요구사항

### A. 백엔드 — 획득 배지 상세를 응답에 실어보내기

`/api/strava/sync` 응답에 필드를 **추가**한다(기존 필드는 유지 — 소비처가 있으므로 제거 금지).

```ts
// 추가 필드
earnedBadges: Array<{
  id: string
  name: string
  description: string
  imageUrl: string      // badges.image_url ?? '' — null 방어
  rarity: 'common' | 'rare' | 'legend' | 'mythic'
  type: 'activity' | 'item' | 'poi'
}>
```

**수집 방식 — 엔진 4곳을 각각 개조하지 말고, `badge_id`만 수집해 마지막에 1회 조회한다.**
(엔진 내부 로직 변경을 최소화해 회귀 위험을 줄이기 위함)

| 경로 | 현재 | 변경 |
|---|---|---|
| 액티비티배지 | `evaluateBadges()`가 `earned.length`만 반환 | 발급된 `badge_id[]`도 함께 반환 (`evaluateBadgesDetailed`의 `earned`에 이미 `id`가 있음) |
| 아이템배지 | `tryItemDrop()`이 `Promise<void>` | 드랍된 `badge_id[]`를 반환하도록 시그니처 변경 |
| POI 배지 | `sync.ts`에서 카운터만 | 발급된 `badge_id[]` 수집 |
| 컬렉션·미션 보상배지 | 카운터만 | 발급된 `badge_id[]` 수집 |

`syncStravaActivities()` 종료 직전에 수집된 id 배열로 `badges` 테이블을 **1회** 조회한다:
`select('id, name, description, image_url, rarity, type')`

**필수 규칙**
- **획득한 순서를 보존한다.** 조회 결과를 id 수집 순서대로 다시 정렬할 것 (PostgREST는 순서를
  보장하지 않는다).
- `deleted_at IS NOT NULL`인 배지는 제외한다.
- `image_url`이 `null`이면 빈 문자열 `''`로 내려보낸다 (기존 페이로드 관례와 동일).
- 배지가 0개면 `earnedBadges: []`를 내려보낸다 (필드 자체를 생략하지 말 것 — 계약 검증용).
- **`tryItemDrop` 호출 순서 불변식을 깨지 말 것.** `sync.ts`에서 오래된→최신 순으로
  `.reverse()` 후 순차 호출하는 구조는 `user_drop_state`를 읽고 쓰기 때문이며, 반환값 추가를
  이유로 `Promise.all` 병렬화하면 안 된다.

### B. MODULAR — `patterns/BadgeRevealCarousel`

파일 3종 필수: `BadgeRevealCarousel.jsx` / `.d.ts` / `.stories.tsx`

**컨벤션 (기존 patterns 컴포넌트와 동일하게)**
- `.jsx` 구현 + 별도 `.d.ts` 타입. `.tsx` 금지
- **named export만.** `export default` 금지
- **`'use client'` 금지** (design-system 트리에 0건 — 서비스 래퍼가 담당)
- 스타일은 **인라인 style 객체 + CSS 변수**. Tailwind·CSS Module 금지
- 색상 하드코딩 금지 — `var(--color-*)` 토큰만
- 키프레임이 필요하면 컴포넌트 내부에 `<style>{`@keyframes ...`}</style>` 인라인 (BottomSheet·Carousel 선례)
- 파일 상단 JSDoc으로 역할·슬롯·상태·인터랙션 모드를 한국어 서술
- Story title: `MODULAR/Patterns/BadgeRevealCarousel`, import는 `@storybook/nextjs-vite`

**제공 소스에서 반드시 제거할 것**
`useIsStaticRenderer` 스텁 / `COMPONENT_DEFAULTS` / `__originkitPresetProps` /
`DEFAULT_SLIDES`(외부 CDN URL) / `@framerIntrinsic*`·`@framerSupported*` JSDoc /
`slides`·`showTitle`·`titleFont`·`titleColor`·`titlePosition` prop 5종 /
`cssTransition()`의 Framer Transition 파싱 / 이미지 위 그라디언트 오버레이

**Props (제안 — 구현 중 조정 가능하나 동작은 아래 스펙을 만족할 것)**
```ts
interface BadgeRevealCarouselProps {
  open: boolean
  /** 'spinning' = 빈 카드 회전 / 'revealed' = 실제 배지 노출 */
  phase: 'spinning' | 'revealed'
  items: Array<{
    id: string
    name: string
    description: string
    imageUrl?: string | null
    rarity?: 'common' | 'rare' | 'legend' | 'mythic'
  }>
  /** 11번째 "전체 보기" 카드에 표시할 잔여 개수. 0이면 카드 미표시 */
  moreCount?: number
  onMoreClick?: () => void
  onClose: () => void
  cardWidth?: number   // 기본 344
  cardHeight?: number
  className?: string
  style?: CSSProperties
}
```

**동작 스펙**

1. **스핀 단계 (`phase='spinning'`)**
   - **빈 카드 5장**을 고속 회전시킨다 (배지 개수·2개 규칙 등 다른 규칙은 이 단계에서 전부 무시)
   - 빈 카드는 배지 자리를 암시하는 플레이스홀더(스켈레톤/실루엣). 이미지·텍스트 없음
   - 카드 클릭·스와이프·키보드 입력 전부 비활성
   - ⚠️ **원본 소스의 락 로직으로는 고속 회전이 불가능하다.** `autoplay` 간격은 최소 300ms인데
     입력 락(`lockRef`)이 `duration × 1000`(기본 600ms)이라, 간격이 락보다 짧으면 `step()`이
     막혀 씹힌다. 스핀 경로는 **락을 우회**하고, 스핀 전용 duration(예: 0.18s)을 쓸 것

2. **전환 (`spinning` → `revealed`)**
   - 빈 카드 5장 → 실제 N장으로 바뀔 때 **중앙 카드 자리를 고정**한 채 내용만 교체하고,
     이웃 카드는 개수에 맞춰 정리한다. 전체를 크로스페이드시켜 화면이 통째로 깜빡이게 하지 말 것

3. **노출 단계 (`phase='revealed'`)**
   - 카드 내용 세로 배치: **배지 이미지 → 등급 pill(`RarityBadge`) → 이름 → 설명**
   - 설명은 **3줄 클램프** 후 말줄임 (POI 배지는 한 줄, 아이템배지는 두세 줄로 편차가 큼)
   - `imageUrl`이 `''` 또는 `null`이면 폴백 아이콘 (`BadgeGridCard.jsx`의 SVG 폴백 참조)
   - 카드 배경 **`var(--color-surface-elevated)`** (#1f1f1f — 페이지 실질 배경 `--color-surface`보다 밝음)
   - 좌우 무한 순환

4. **배지 개수별 규칙**

   | 개수 | 동작 |
   |---|---|
   | 1개 | 카드 1장. **이웃 카드 없음, 플리킹 비활성** |
   | 2개 | **왼쪽 없음 — 오른쪽에만 1장.** ⚠️ 원본 `rel` 로직은 `active=1`일 때 나머지 카드가 왼쪽(`rel=-1`)에 붙는다. `rel`을 항상 양수로 정규화할 것 |
   | 3개 이상 | 좌우 1장씩 peek (원본 동작) |

5. **인터랙션**
   - **좌우 스와이프(플리킹) 직접 구현.** 원본은 클릭·키보드만 지원한다. 제스처 라이브러리를
     추가하지 말고 `src/components/ui/BottomSheet.tsx:135-175`의 포인터 드래그 로직
     (거리 임계 120px / 속도 임계 0.5px·ms, `setPointerCapture`)을 **수평 버전으로 이식**할 것
   - **중앙 카드 탭으로 다음 카드로 넘기는 원본 동작은 제거한다** (닫기 버튼 오조작 방지)
   - 키보드 ArrowLeft/Right 유지

6. **닫기 버튼**
   - `IconButton icon="close"`, **중앙 카드 우측 상단에 겹쳐 보이도록** 배치
   - ⚠️ **카드 DOM 안에 넣지 말 것.** 카드는 `preserve-3d` 안에서 `rotateY`/`rotateZ`/`scale`
     변환을 받으므로 버튼도 같이 기울고 축소되며 터치 타겟이 뒤틀린다.
     **스테이지 기준 절대 위치**로 두어 3D 변환의 영향을 받지 않게 한다

7. **11번째 "전체 보기" 카드**
   - `moreCount > 0`일 때 마지막 카드로 추가. 넘기면 첫 카드로 순환
   - 시각 구성은 `ModalToast`를 **참조만** (중앙 정렬 / 원형 아이콘 / 메시지 / pill CTA).
     `ModalToast` 컴포넌트 자체는 import 금지 (티켓 20260820_010 "도입 보류")
   - 클릭 시 `onMoreClick()` 호출 (이동 경로는 호출부 책임)

8. **접근성**
   - `prefers-reduced-motion` 시 **3D 틸트·고속 스핀을 제거**하고 단순 페이드로 대체.
     `src/lib/motion.ts`의 `prefersReducedMotion()` 참조 (design-system은 서비스 코드를
     import할 수 없으므로 동일 로직을 컴포넌트 내부에 구현)
   - `role="dialog"`, `aria-modal="true"`, Escape 닫기, 포커스 트랩
     (`BottomSheet.jsx`·`ModalToast.jsx` 구현 참조)

9. **스토리**
   - 개수별: 0·1·2·3·5·20(전체보기 카드 포함)
   - 상태별: 스핀 중 / 노출 / 스핀→노출 전환
   - 엣지: 이미지 없음 / 설명 아주 김 / 이름 아주 김 / mythic만

### C. 스파이크 검증 페이지 — `/spike/badge-reveal`

사용자가 실제 스트라바 없이 캐러셀 동작을 직접 확인하기 위한 페이지. **상시 유지한다**
(기존 `/spike/background-generator`와 동일하게 가드 없이 둔다 — 링크를 걸지 않아 노출만 안 됨).

**버튼 구성**

| 그룹 | 버튼 |
|---|---|
| 개수 | 0개 / 1개 / 2개 / 3개 / 20개 |
| **응답 지연** | 0.5초 / 3초 / 8초 |
| 엣지 | 이미지 없음 / 설명 아주 김 / 이름 아주 김 / mythic만 |

**응답 지연 버튼이 이 페이지의 핵심이다.** `max(2초, API 응답)` 로직은 실제 Strava로는
응답 시간을 통제할 수 없어 여기서만 제대로 검증된다:
- 0.5초 → 응답이 먼저 와도 **2초는 채우고** 멈추는지
- 3초·8초 → 2초가 지나도 **계속 돌다가** 응답 도착 즉시 멈추는지

**🔴 절대 규칙 — 배지를 발급하지 말 것**

스테이징(`jam-stage.vercel.app`)은 **프로덕션과 동일한 Supabase(`jam-prod`)를 쓴다.**
활성 Supabase 프로젝트가 하나뿐이라 스테이징 전용 DB가 없다.

- 이 페이지는 `badges` 테이블을 **읽기만** 한다. 드랍 엔진·배지 엔진을 호출하지 않는다
- `user_activity_badges`·`inventory_items`·`user_activity_feed`에 **쓰기 금지**
- 이유: `user_activity_badges`에 `UNIQUE(user_id, badge_id)` 제약이 있어 한 번 발급하면
  같은 계정으로 재테스트가 불가능해진다. 또 `tryItemDrop`은 인벤토리 슬롯을 소모하고
  시리얼 번호를 순차 발급해 되돌리기 어렵다
- 조회 전용 API 라우트를 새로 만들거나 서버 컴포넌트에서 직접 조회할 것

**A. 백엔드 — `earnedBadges[]` 응답 확장**

| 경로 | 변경 |
|---|---|
| 액티비티배지 | `evaluateBadges()` `Promise<number>` → `Promise<string[]>` (발급 id 목록) |
| 아이템배지 | `tryItemDrop()` `Promise<void>` → `Promise<string[]>` (드랍 id 목록) |
| POI 배지 | `sync.ts`에서 발급 시점마다 id 수집 (poi 타입·레거시 activity 타입 모두) |

| 미션 보상 | `MissionCheckResult.awardedBadgeIds` 추가 |

수집 순서 = 획득 순서(POI → 아이템 드랍 → 액티비티 → 컬렉션 보상 → 미션 보상). PostgREST가
`.in()` 결과 순서를 보장하지 않으므로 조회 후 **id 수집 순서로 재정렬**한다. `deleted_at IS NOT NULL`
제외, `image_url` null → `''`, 0개면 `earnedBadges: []`(필드 생략 없음). `tryItemDrop` 순차 호출
불변식은 그대로 유지(반환값이 생겼다고 병렬화하지 말라는 주석을 코드에 남김).

### 주요 의사결정 / 핵심 메모

1. **`evaluateBadges` 반환 타입을 number → string[]로 바꿨다.** 호출부가 `sync.ts` 한 곳뿐이라
   개수 필드를 따로 유지할 이유가 없었다. 개수는 `.length`로 얻는다.
2. **순환 시 rel 정규화는 "n/2 초과일 때만" 음수로 접는다.** 이 "초과(>)" 비교가 2장일 때 나머지
   한 장을 왼쪽이 아니라 오른쪽에 세우는 근거다.
3. **카드가 3~4장일 때는 순환하는 한 장이 중앙 카드 뒤를 가로지른다.** 5장 이상이면 `|rel| >= 2`가
   숨김 링(opacity 0)이 되어 건너뜀이 보이지 않지만, 3~4장은 숨김 링 자체가 없다. 렌더 중 직전
   rel을 참조하면(ref 읽기) 없앨 수 있으나 React 규칙 위반이라 그대로 뒀다 — 뒤쪽(zIndex 낮음·
   축소·반투명)으로 지나가 시각 부담이 크지 않다.
4. **활성 카드 위치는 이펙트로 리셋하지 않는다.** `phase:count` 토큰과 함께 들고 다니며 구성이
   바뀌면 0으로 파생시킨다 (`react-hooks/set-state-in-effect` 회피 + 렌더 연쇄 제거).
5. **스파이크 페이지는 service_role을 쓰지 않는다.** `/spike`는 프록시 공개 경로라 미인증
   접근이 가능해, service_role로 읽으면 로그인 없이 배지 데이터가 노출된다. 세션 클라이언트로만
   조회하고 세션이 없으면 화면에서 예시 데이터로 대체한다.

#### 개선 리뷰 반영 2건 (오케스트레이터, 머지 전)

6. **화살표 키를 스테이지가 아니라 document 리스너로 옮겼다.** 오버레이가 열릴 때 초기 포커스가
   닫기 버튼으로 가는데 `onKeyDown`이 스테이지에 걸려 있어, Tab으로 포커스를 옮기기 전까지
   좌우 키 전환이 동작하지 않았다. Escape와 같은 document 리스너에서 처리하고 **스테이지
   핸들러는 제거**했다 — 양쪽에 걸어두면 버블링으로 `step`이 두 번 호출된다.
   핸들러는 ref로 최신 상태를 유지하되, `no-use-before-declare`를 피하려 ref 갱신 이펙트를
   `handleKeyDown` 선언 뒤(단, early return 앞)에 배치했다.
7. **"전체 보기" 카드 문구를 `moreMessage` prop으로 분리했다.** `closeLabel`·`moreLabel`·
   `ariaLabel`은 전부 prop인데 본문 문구만 하드코딩돼 있어 서비스가 i18n 사전(`d`)에서 주입할 수
   없었다. 문자열과 `(count) => string` 양쪽을 받고, 타입 정의와 전용 스토리
   (`CustomMoreMessage`)를 함께 추가했다.

#### 후속 티켓(20260823_008)에서 먼저 정할 것

8. **`badges` 카운터와 `earnedBadges.length`는 서로 다른 집합을 센다.** 게이트·개선 리뷰가
   동시에 지적한 사항이다. 기존 카운터에는 아이템 드랍 배지와 미션 보상 배지가 빠져 있고,
   반대로 `earnedBadges`는 중복 제거·소프트삭제 제외로 더 짧아질 수도 있다. 이번 티켓은
   소비처가 없어 사용자 영향이 0이지만, 008에서 토스트 "배지 N개 획득"과 캐러셀 카드 수가
   달라 보일 수 있으므로 **어느 값을 기준으로 삼을지 연결 전에 확정**해야 한다.
   (배지엔진 문서 §3.7.1에도 같은 경고를 남겼다.)
