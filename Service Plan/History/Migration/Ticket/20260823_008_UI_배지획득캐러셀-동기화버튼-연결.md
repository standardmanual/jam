# [UI] 배지 획득 캐러셀 — 실제 동기화 버튼에 연결

> 선행 티켓 **20260823_007**(백엔드 응답 확장 + MODULAR 패턴 + 스파이크 페이지) 완료 후속.
> **사용자가 `jam-stage.vercel.app/spike/badge-reveal`에서 캐러셀 동작을 확인하고 승인한 뒤에
> 착수한다.** 승인 전에는 시작하지 않는다.

## 배경 / 문제 정의

티켓 007에서 `patterns/BadgeRevealCarousel`과 `/api/strava/sync`의 `earnedBadges[]`가
준비됐지만, 서비스 화면 어디에도 연결되지 않았다. 현재 동기화 후 사용자에게 보이는 것은
여전히 탭바 위 `"배지 N개 획득"` 토스트뿐이다.

이 티켓에서 실제 동기화 버튼에 캐러셀을 연결한다.

## 착수 전 확정해야 할 사항

### 🔴 `badges` 카운터와 `earnedBadges.length`가 어긋난다 (게이트·개선 리뷰 공통 지적)

`src/lib/strava/sync.ts`의 `badges: badgesEarned + poiBadgesEarned + rewardBadgesIssued`에는
**아이템 드랍 배지와 미션 보상 배지가 포함되지 않는다.** 반면 `earnedBadges`에는 들어간다.
반대로 중복 id 제거(`Array.from(new Set())`)와 소프트삭제 제외로 `earnedBadges`가 더
짧아질 수도 있다.

→ 토스트 문구와 캐러셀 카드 수가 달라 보일 수 있다. **어느 값을 기준으로 삼을지 먼저 정한다.**
(배지엔진 문서 §3.7.1에 같은 경고 기재)

## 상세 요구사항

### 서비스/코드베이스 관점

1. **`SyncButton.tsx` — 성공 토스트 제거**
   - `toast(...)` 성공 분기 4줄 제거 (컬렉션 완성 / 미션 달성 / 배지 획득 / 그냥 완료)
   - **실패 토스트(`syncFailed`)와 네트워크 에러 토스트는 유지한다**
   - 미사용이 된 i18n 키 정리: `syncBadgeDone`·`syncMissionDone`·`syncItembookDone`
     (`syncButton`·`syncFailed`는 유지)
   - ⚠️ **배지 0개일 때는 기존 "동기화 완료" 토스트를 유지한다** — 캐러셀이 뜨지 않으므로
     이것까지 지우면 무반응으로 보인다 (사용자 확정 사항)

2. **캐러셀 오버레이 마운트**
   - `phase`는 `max(2초, API 응답)` 규칙으로 전환. 응답이 2초보다 빨라도 2초는 채우고,
     2초가 지나도 응답 전이면 계속 스핀
   - `z-50` 이상 + **`pushTabBarHidden()` 병행** (`src/lib/uiOverlay.ts`) — z-index로만 덮으면
     iOS Safari 동적 툴바 상태에 따라 탭바가 비쳐 보인 이력이 있다
   - 배경 스크롤 락은 `document.querySelector('main').style.overflow` 방식
     (`BottomSheet.tsx:121-131` 선례 — `document.body` 아님)
   - 오버레이 폭은 `maxWidth: 430, margin: '0 auto'` (서비스 컬럼 관례)

3. **10장 상한 + "전체 보기" 카드**
   - 앞에서부터 10장, 나머지는 `moreCount`로 전달
   - `moreMessage`는 i18n 사전(`d`)에서 주입 (컴포넌트에 하드코딩하지 않는다 — 007에서 prop 분리 완료)
   - ⚠️ `MAX_CARDS = 10` 상수가 스파이크 클라이언트에만 있다. 서비스와 값이 갈라지지 않도록
     공용 위치로 옮길지 검토

4. **"전체 보기" 이동 경로**
   - **탭바 프로필 링크와 동일한 값**: `username ? \`/${username}\` : '/profile'`
     (`src/components/ui/TabBar.tsx`의 `profileHref`와 같은 식). **해시는 붙이지 않는다**
   - `username`은 `(main)/layout.tsx`가 이미 TabBar에 넘기고 있으므로 같은 값을 전달
   - 참고: 이 경로로 가면 배지 갤러리가 아니라 프로필 기본 화면(Strava 상태 + 피드)이 열린다
     (`ProfileClient`의 `isTabView` 판정). 사용자가 이를 알고 확정한 사항이다

5. **`router.refresh()` 시점 이동**
   - 현재 동기화 직후 호출된다. **캐러셀을 닫을 때**로 미룬다 — 오버레이가 떠 있는 동안
     뒤 페이지가 리렌더되지 않도록

6. **최초 Strava 연동 경로 포함**
   - `api/strava/callback/route.ts:91`이 sync를 돌린 뒤 곧바로 리다이렉트해 응답 본문에
     배지를 실을 수 없다
   - 리다이렉트 목적지에 플래그(예: `?reveal=1`)를 붙이고, 도착 페이지에서
     **최근 획득 배지 조회 API**로 되읽는 방식
   - 조회 로직은 `user_activity_feed`를 `event_at` 내림차순으로 읽어 `badge_id` 수집 후
     `badges` 조인. `src/lib/activity-feed/hydrate.ts`가 이미 같은 패턴이다

### UI/UX 관점

- 접근성 보완(007 개선 리뷰 4번, 이번 티켓에서 함께 처리):
  스핀 → 노출 전환이 스크린리더에 알려지지 않는다. 중앙 카드 텍스트 영역에
  `aria-live="polite"`를 얹거나, `phase`가 `revealed`로 바뀔 때 중앙 카드로 포커스를 옮긴다

- UX Writing: "전체 보기" CTA는 가이드 5-1 기준으로 목적지가 드러나지 않는다.
  **`배지 전부 보기` / `배지함에서 보기`** 같은 대안을 함께 검토한다
  (007 티켓이 "전체 보기"를 명시했으므로 준수 자체는 문제없음)

## 구현 계획

1. `badges` 카운터 vs `earnedBadges.length` 기준 확정 (착수 전)
2. `SyncButton.tsx` 토스트 제거 + 캐러셀 오버레이 마운트 + `max(2초, 응답)` 로직
3. `router.refresh()` 시점 이동
4. 최초 연동 콜백 경로 + 최근 획득 조회 API
5. `aria-live` 보완, CTA 문구 확정
6. `tsc` / `eslint` / `build` 검증 후 staging 확인 → 사용자 승인 → `/jam-ship`
