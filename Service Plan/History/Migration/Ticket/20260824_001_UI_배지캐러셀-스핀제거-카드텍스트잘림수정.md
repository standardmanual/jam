# [UI] 배지 획득 캐러셀 — 응답대기 스핀 제거 + 카드 텍스트 잘림 수정

> 선행 티켓 **20260823_007** 후속. staging(`jam-stage.vercel.app/spike/badge-reveal`) 확인 중
> 발견된 2건을 처리한다. 이 티켓도 **서비스 화면에는 연결하지 않는다** —
> `SyncButton.tsx`·`api/strava/callback/route.ts` 수정 금지(연결은 티켓 20260823_008).

## 배경 / 문제 정의

### 1. 응답대기 스핀 화면 제거 (사용자 결정)

007에서는 동기화 버튼을 누르면 **빈 카드 5장이 도는 전체화면 캐러셀**을 먼저 띄우고,
`max(2초, API 응답)` 시점에 실제 배지로 전환하는 설계였다. 이를 폐기한다.

**새 동작:** 배지 드랍 엔진의 최종 결과가 나온 **뒤에만** 캐러셀을 띄운다.
동기화·엔진 판정이 오래 걸리면 **버튼의 스피너가 도는 상태를 유지**한다
(`Button` 컴포넌트의 기존 `loading` prop).

폐기 근거:
- 빈 카드가 도는 화면은 정보량이 0인데 화면 전체를 점유하는 가짜 로딩이다
- `max(2초, 응답)` 타이밍·autoplay 락 우회·스핀 5장 → 실제 N장 전환 처리가 전부
  이 기능만을 위해 존재했고, 007 게이트 리뷰에서 검증이 가장 까다로웠던 부분이다
- 응답이 10초 걸릴 때 전체화면을 점유하는 것보다 버튼 스피너가 사용자를 가두지 않는다

> 등장 애니메이션 강화는 **하지 않는다**(사용자 결정). 기존
> `ds-badge-reveal-in 220ms`를 그대로 둔다.

### 2. 카드 텍스트 2행째 잘림 (오케스트레이터 선처리 완료)

배지 이름이 2행, 설명이 3행이 되면 마지막 행이 잘렸다.

**원인은 이미지 크기가 아니었다.** 등급 pill·이름·설명이 flex 자식인데 `flex-shrink`
기본값이 `1`이라, `flex: 1 1 auto`인 이미지에 밀려 **높이가 깎였고**, `-webkit-box`의
`overflow: hidden`이 그 깎인 만큼 잘라냈다.

## 상세 요구사항

### A. 스핀 제거 (이 티켓의 구현 범위)

**MODULAR `patterns/BadgeRevealCarousel`에서 스핀 기능을 완전히 제거한다.**
서비스가 쓰지 않는 기능을 남겨두면 죽은 코드가 된다(티켓 20260820_010에서 미사용 DS
컴포넌트 8종을 "보류" 처리한 이력 참고).

제거 대상:
- `phase` prop (`'spinning' | 'revealed'`) 및 `spinning` 분기 전부
- 빈 카드 플레이스홀더 컴포넌트(`PlaceholderCard`)와 관련 스타일·키프레임
- 스핀 전용 autoplay·락 우회 로직, 스핀 duration 상수
- 스핀 관련 스토리 3종(`Spinning`, `SpinToReveal`, 그 외 스핀 상태 스토리)
- `.d.ts`의 `phase` 타입 정의 및 관련 주석

유지 대상:
- `open` prop으로만 노출 제어 (열리면 곧바로 실제 배지 카드)
- 기존 `ds-badge-reveal-in 220ms` 등장 애니메이션
- 나머지 동작(개수별 규칙·스와이프·닫기·전체보기 카드·reduced-motion) 전부 그대로

**스파이크 페이지(`/spike/badge-reveal`) 갱신:**
- 응답 지연 버튼(0.5초/3초/8초)은 **유지하되 의미가 바뀐다** —
  이제 "지연 동안 트리거 버튼 스피너가 돌고, 결과가 오면 캐러셀이 뜬다"를 검증한다
- 지연 중에는 트리거 버튼을 `loading` 상태로 두어 실제 `SyncButton` 동작을 모사한다
- `MIN_SPIN_MS` 등 최소 대기 상수 제거

### B. 카드 텍스트 잘림 (이미 반영됨 — 회귀만 확인)

오케스트레이터가 경미 수정으로 선반영했다. 이 티켓에서는 **회귀가 없는지만 확인**한다.

- 등급 pill·이름·설명에 `flexShrink: 0` — 텍스트는 눌리지 않고 이미지가 먼저 양보
- 이미지 영역 `maxHeight: '46%'` — 이미지를 줄여 텍스트 공간 확보
- 카드 컨테이너 `justifyContent: 'center'` — 이미지가 상한에 걸려 슬랙이 남을 때
  위로 쏠리지 않도록

### C. 하지 않을 것

- `SyncButton.tsx` 수정 금지 (티켓 20260823_008)
- `api/strava/callback/route.ts` 수정 금지 (티켓 20260823_008)
- 서비스 화면에 캐러셀 마운트 금지 (스파이크 페이지 제외)
- 백엔드(`earnedBadges[]`) 변경 금지 — 007에서 완료됐고 이번 범위 아님
- 등장 애니메이션 강화 금지 (사용자가 명시적으로 "안 함" 결정)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**A. 스핀 제거 (`patterns/BadgeRevealCarousel`)**
- `phase` prop과 `spinning` 분기를 전부 삭제. 이제 `open`만으로 노출을 제어하고,
  열리면 곧바로 실제 배지 카드가 나온다.
- `PlaceholderCard` 컴포넌트 삭제 + 전용 키프레임 `ds-badge-reveal-pulse` 삭제.
- 스핀 전용 상수 3종(`SPIN_CARD_COUNT` / `SPIN_STEP_MS` / `SPIN_MOVE_MS`)과
  `setInterval` 기반 스핀 autoplay 이펙트 삭제. 이동 시간은 `STEP_MOVE_MS` 하나로 단일화.
- `navToken`을 `` `${phase}:${count}` `` → `count`로 축소(카드 수가 바뀌면 중앙 카드 리셋).
- `canFlick = !spinning && count > 1` → `count > 1`.
- 스토리 `Spinning` / `SpinToReveal` 및 `SpinToRevealDemo` 헬퍼 삭제,
  `argTypes.phase` 컨트롤과 각 스토리의 `phase: 'revealed'` 인자 제거.
  더 이상 필요 없어진 `React` / `useState` / `useEffect` import도 함께 제거.
- `.d.ts`에서 `BadgeRevealPhase` 타입과 `phase` prop 삭제, `open` 주석에 새 규칙 명시.

**B. 스파이크 페이지(`/spike/badge-reveal`) 갱신**
- `MIN_SPIN_MS` 상수 제거. `simulateSyncWait()`은 최소 대기 없이 응답 소요 시간만 돌려준다.
- `phase` state 대신 `pendingCount` state 도입 — 눌린 트리거 버튼에 `loading`(스피너),
  나머지 트리거 버튼에 `disabled`를 걸어 실제 `SyncButton` 대기 동작을 모사한다.
- 캐러셀은 결과 도착 시점(`setOpen(true)`)에만 열린다. 0개면 열지 않는다.
- 응답 지연 안내 문구를 새 의미로 교체:
  "지연 동안 아래 버튼의 스피너가 돌아요. 결과가 도착하는 그 시점에 캐러셀이 열려요."

**C. 카드 텍스트 잘림 — 회귀 확인 전용**
- 오케스트레이터 선반영분(`flexShrink: 0` / 이미지 `maxHeight: '46%'` /
  `justifyContent: 'center'`)은 그대로 두고, 최악 조합을 실측하는 스토리
  `LongNameAndDescription`(이름 2행 + 설명 3행)만 추가했다.

### 주요 의사결정 / 핵심 메모

- **`navToken`을 없애지 않고 `count`로 축소했다.** `phase`가 사라져도 카드 수가 바뀔 때
  중앙 카드를 0번으로 되돌리는 역할은 그대로 필요하다(20개 → 닫기 → 1개 재실행 시
  active 인덱스가 범위를 벗어나는 것을 막는다). 이펙트 없이 렌더 중 파생시키는 기존 구조 유지.
- **스파이크 트리거 버튼은 `loading`(누른 버튼) + `disabled`(나머지)로 나눴다.**
  실제 `SyncButton`은 버튼이 하나뿐이라 `loading` 하나로 충분하지만, 하네스는 트리거가
  5개라 대기 중 다른 개수를 눌러 실행이 겹치는 것을 막아야 한다(`runIdRef` 가드의 시각적 짝).
- **`ds-badge-reveal-in 220ms`는 손대지 않았다.** 사용자가 등장 애니메이션 강화를
  명시적으로 "안 함"으로 결정했다.
