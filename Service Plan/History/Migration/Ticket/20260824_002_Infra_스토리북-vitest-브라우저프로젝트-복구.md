# [Infra] Storybook vitest 브라우저 프로젝트 복구 — play 회귀 테스트가 전부 실행 불가

## 배경 / 문제 정의

`npx vitest run --project=storybook`이 **저장소 전역에서 깨져 있다.** 스토리 파일 32개가
전부 동일한 오류로 실패한다:

```
Failed to import node_modules/@storybook/addon-vitest/dist/vitest-plugin/setup-file-with-project-annotations.js
SyntaxError: '@testing-library/dom/node_modules/aria-query/lib/index.js'
             does not provide an export named 'elementRoles'
```

`@testing-library/dom`이 물고 있는 중첩 `aria-query@5.3.0`의 CJS/ESM interop 문제다.
**스토리 소스를 평가하기 전 setup 단계에서 실패**하므로 특정 컴포넌트와 무관하며,
`Button.stories.tsx` 같은 단순 스토리로도 동일하게 재현된다.

### 왜 지금 고쳐야 하나

티켓 20260824_001에서 **실제 회귀가 발생했고**, 그 회귀를 잡는 `play` 테스트
(`BadgeRevealCarousel.stories.tsx`의 `ReopenResetRegression`)를 추가했다. 검출력도 검증했다 —
컴포넌트를 수정 전 커밋으로 되돌리면 `expected '한강 러너 2' to be '한강 러너 1'`로 실패한다.

**그런데 이 테스트가 CI에서도 로컬에서도 자동 실행되지 않는다.** 현재 회귀 방어망은
사람이 매번 Storybook을 직접 열어보는 것뿐이다.

20260824_001의 회귀는 "스핀이 우연히 겸하던 리셋 역할이 스핀 제거와 함께 사라진" 유형이었다.
이런 **암묵적 의존이 끊기는 회귀는 코드 리뷰로 잡기 어렵고, 자동 테스트가 유일한 방어선**이다.
같은 유형의 사고가 반복될 가능성이 높다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. `npx vitest run --project=storybook`이 정상 실행되게 복구한다
2. 복구 후 `BadgeRevealCarousel.stories.tsx`의 `ReopenResetRegression`이 **실제로 통과**하는지,
   그리고 **컴포넌트를 되돌리면 실패하는지**(검출력) 양방향으로 확인한다
3. 나머지 31개 스토리 파일도 실행되는지 확인하고, 이 과정에서 드러나는 기존 스토리 실패는
   별도 목록으로 정리한다 (이번 티켓에서 전부 고칠 필요는 없다 — 현황 파악이 목적)

### 조사 방향 (참고용, 이대로일 필요 없음)

- `@testing-library/dom`이 중첩 설치한 `aria-query` 버전을 상위로 끌어올리는 방법
  (`overrides` / `resolutions`)
- `@storybook/addon-vitest` 및 `@testing-library/*` 버전 조합 확인
- `vitest.config.ts`의 `deps.optimizer` / `server.deps.inline` 설정으로 interop 우회

### 함께 확인할 것

`npx tsc --noEmit`가 `jam-web/src/lib/**/__tests__/*.test.ts`에서 `describe`/`it`/`expect`
미정의 오류(TS2582/TS2304)를 다수 낸다. vitest globals 타입 설정 누락으로 보이며,
**타입체크를 상시 적색으로 만들어 진짜 오류를 묻어버린다.** 같은 테스트 환경 문제이므로
이번 티켓에서 함께 처리할지 판단한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**원인.** `@testing-library/dom@10.4.1`이 `aria-query`를 **정확 버전 `5.3.0`으로 핀**하고 있어
`node_modules/@testing-library/dom/node_modules/aria-query`에 중첩 설치됐다. 5.3.0의
`lib/index.js`는 CJS 네임드 익스포트를 `exports.aria = aria;`처럼 **선언과 분리된 별도 대입문**으로
내보내는데, Vite가 이 파일을 사전번들 없이(= `server.deps.inline: ['@storybook/addon-vitest']`로
addon이 인라인 처리되면서) 브라우저에 그대로 내려보내면서 네임드 익스포트 탐지에 실패했다.
5.3.2는 같은 코드를 `var aria = exports.aria = _ariaPropsMap.default;` 형태로 바꿔 탐지가 된다.
setup 파일 단계에서 터지므로 32개 스토리 파일이 스토리 소스 평가 전에 전부 죽었다.

```
5.3.0  var aria = _ariaPropsMap.default;  exports.aria = aria;
5.3.2  var aria = exports.aria = _ariaPropsMap.default;
```

**조치 1 — aria-query 5.3.2로 통일.** `jam-web/package.json`에 `overrides: { "aria-query": "5.3.2" }`.

- **왜 5.3.2인가**: 이 저장소에는 이미 `eslint-plugin-jsx-a11y@6.10.2`(`^5.3.2`)와
  `@testing-library/jest-dom@6.9.1`(`^5.0.0`)이 루트에 5.3.2를 설치해 두고 있었다.
  중첩된 5.3.0 하나만 5.3.2로 올리면 **트리 전체가 단일 5.3.2로 dedupe**된다(신규 버전 도입 아님).
- **왜 안전한가**: 5.3.1/5.3.2는 5.3.0의 빌드 산출물 정리 릴리스로 공개 API
  (`aria`/`dom`/`roles`/`elementRoles`/`roleElements`)가 동일하다. 부수 효과로 `dequal` 의존이
  사라져 lock에서 2개 패키지가 제거된다.
- `@testing-library/dom`의 `5.3.0` 핀은 **범위가 아니라 정확 버전**이라 overrides 없이는
  절대 dedupe되지 않는다. `vitest.config.ts`의 `optimizeDeps`/`server.deps.inline` 우회도
  후보였지만, 근본 원인(깨진 버전이 트리에 남는 것)을 그대로 두는 방식이라 채택하지 않았다.

**조치 2 — vitest globals 타입 (`함께 확인할 것` 항목, 이번 티켓에서 함께 처리).**
`jam-web/vitest.shims.d.ts`에 `/// <reference types="vitest/globals" />` 추가.
`tsconfig.json`의 `compilerOptions.types`를 지정하는 방식은 **`@types/*` 자동 포함이 끊겨**
`node`/`react` 타입까지 직접 나열해야 하므로 채택하지 않았고, 이미 존재하던 shims 파일에
참조만 더했다(테스트 전용 tsconfig 분리도 파일 하나로 끝나는 이 방법보다 비용이 커 제외).
`tsc --noEmit` 오류 **400건 → 0건**.

### 변경된 파일
```
jam-web/package.json          overrides.aria-query = 5.3.2 추가
jam-web/package-lock.json     중첩 aria-query@5.3.0 + dequal@2.0.3 제거 (dedupe)
jam-web/vitest.shims.d.ts     vitest/globals 타입 참조 추가
```
서비스 코드(`jam-web/src/**`, `jam-web/design-system/**`)는 **한 줄도 바꾸지 않았다.**

### 주요 의사결정 / 핵심 메모

- **overrides vs vitest 설정 우회**: `optimizeDeps.include: ['aria-query']`로도 증상은 가릴 수 있으나,
  깨진 5.3.0이 트리에 남아 다른 도구(스토리북 dev 서버, 향후 addon 업데이트)에서 재발할 수 있다.
  버전 통일이 근본 해결이라 판단했다.
- **`npm install` 부수 효과 확인**: lock에서 제거된 것은 중첩 `aria-query@5.3.0`과 그 전용 의존
  `dequal@2.0.3` 둘뿐이다(총 2 패키지 제거, 추가 0). 빌드·타입체크·전체 테스트로 회귀 없음을 확인했다.
- **CI 연결은 범위 밖**: 저장소에 `.github/workflows`가 없어 이번 복구만으로 자동 실행되는 CI는 없다.
  `npm test`(= `vitest run`)가 두 프로젝트를 모두 돌리므로 CI를 붙일 때 별도 설정은 필요 없다.

### 잔여 이슈
- 위 표의 스토리 콘솔 경고 2건 (ListRowCard 버튼 중첩 / Textarea read-only) — 별도 티켓 대상

  (`.mts` 확장자 또는 `"type": "module"` 필요) — 동작에는 영향 없어 이번 범위에서 제외
- 저장소에 CI 워크플로우가 없어 `play` 테스트는 여전히 사람이 `npm test`를 돌려야 실행된다
