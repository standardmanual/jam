# [Infra] Storybook vitest 브라우저 프로젝트 복구 — play 회귀 테스트가 전부 실행 불가

## 배경 / 문제 정의

`npx vitest run --project=storybook`이 **저장소 전역에서 깨져 있다.** 스토리 파일 32개가
전부 동일한 오류로 실패한다:

```
Failed to import node_modules/@storybook/addon-vitest/dist/vitest-plugin/setup-file-with-project-annotations.js
SyntaxError: '@testing-library/dom/node_modules/aria-query/lib/index.js'
             does not provide an export named 'elementRoles'
```

`@testing-library/dom`이 물고 있는 중첩 `aria-query@5.3.0`의 CJS/ESM interop 문제다.
**스토리 소스를 평가하기 전 setup 단계에서 실패**하므로 특정 컴포넌트와 무관하며,
`Button.stories.tsx` 같은 단순 스토리로도 동일하게 재현된다.

### 왜 지금 고쳐야 하나

티켓 20260824_001에서 **실제 회귀가 발생했고**, 그 회귀를 잡는 `play` 테스트
(`BadgeRevealCarousel.stories.tsx`의 `ReopenResetRegression`)를 추가했다. 검출력도 검증했다 —
컴포넌트를 수정 전 커밋으로 되돌리면 `expected '한강 러너 2' to be '한강 러너 1'`로 실패한다.

**그런데 이 테스트가 CI에서도 로컬에서도 자동 실행되지 않는다.** 현재 회귀 방어망은
사람이 매번 Storybook을 직접 열어보는 것뿐이다.

20260824_001의 회귀는 "스핀이 우연히 겸하던 리셋 역할이 스핀 제거와 함께 사라진" 유형이었다.
이런 **암묵적 의존이 끊기는 회귀는 코드 리뷰로 잡기 어렵고, 자동 테스트가 유일한 방어선**이다.
같은 유형의 사고가 반복될 가능성이 높다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. `npx vitest run --project=storybook`이 정상 실행되게 복구한다
2. 복구 후 `BadgeRevealCarousel.stories.tsx`의 `ReopenResetRegression`이 **실제로 통과**하는지,
   그리고 **컴포넌트를 되돌리면 실패하는지**(검출력) 양방향으로 확인한다
3. 나머지 31개 스토리 파일도 실행되는지 확인하고, 이 과정에서 드러나는 기존 스토리 실패는
   별도 목록으로 정리한다 (이번 티켓에서 전부 고칠 필요는 없다 — 현황 파악이 목적)

### 조사 방향 (참고용, 이대로일 필요 없음)

- `@testing-library/dom`이 중첩 설치한 `aria-query` 버전을 상위로 끌어올리는 방법
  (`overrides` / `resolutions`)
- `@storybook/addon-vitest` 및 `@testing-library/*` 버전 조합 확인
- `vitest.config.ts`의 `deps.optimizer` / `server.deps.inline` 설정으로 interop 우회

### 함께 확인할 것

`npx tsc --noEmit`가 `jam-web/src/lib/**/__tests__/*.test.ts`에서 `describe`/`it`/`expect`
미정의 오류(TS2582/TS2304)를 다수 낸다. vitest globals 타입 설정 누락으로 보이며,
**타입체크를 상시 적색으로 만들어 진짜 오류를 묻어버린다.** 같은 테스트 환경 문제이므로
이번 티켓에서 함께 처리할지 판단한다.

## 구현 계획

1. 의존성 트리 확인 (`npm ls aria-query`)으로 중첩 설치 경로 특정
2. overrides 또는 vitest 설정으로 해결책 적용
3. `npx vitest run --project=storybook` 전체 실행 → 통과/실패 현황 정리
4. `ReopenResetRegression` 검출력 A/B 확인
5. `tsc` globals 타입 문제 처리 여부 판단 후 반영
