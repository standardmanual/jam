# [bug] 홈 화면이 투데이 카드의 외부 이미지 호스트 때문에 통째로 렌더 실패

> 티켓 20260823_008 게이트 리뷰 중 발견. **이번 작업과 무관한 선행 버그**이며,
> 해당 투데이 카드에 매칭되는 사용자는 **홈 화면 전체가 에러 화면으로 떨어진다.**

## 배경 / 문제 정의

`src/app/(main)/TodayCardStack.tsx`의 `<Image src={cover}>`가 `next.config.ts`의
`images.remotePatterns`에 등록되지 않은 외부 호스트를 받는다.

`next/image`는 미허용 호스트를 만나면 **렌더 시점에 throw** 하므로, 카드 하나가 아니라
**홈 화면 전체가 에러 바운더리로 떨어진다.** dev·prod 모두 동일하다.

### 재현

로컬 `next dev` + dev-login 계정으로 `/` 진입 시:

```
Invalid src prop (https://storage.heypop.kr/...) on `next/image`,
hostname "storage.heypop.kr" is not configured under images in your `next.config.ts`
```

### 확인된 미등록 호스트

- `storage.heypop.kr`
- `cdn.news.bbsi.co.kr`

투데이 카드 콘텐츠는 외부 기사·콘텐츠를 참조하므로 **호스트가 계속 늘어날 수 있다.**

## 상세 요구사항

### 서비스/코드베이스 관점

- 근본 대응이 필요하다. 호스트를 하나씩 `remotePatterns`에 추가하는 방식은 새 콘텐츠가
  등록될 때마다 같은 사고가 반복된다. 아래 중 선택:
  1. **외부 이미지에는 `next/image` 대신 `<img>`를 쓴다** — 최적화를 포기하는 대신
     호스트 제약이 사라진다
  2. **`unoptimized` 처리** — `next/image`를 쓰되 외부 URL은 최적화를 건너뛴다
  3. **이미지 프록시 라우트** — 외부 이미지를 자체 도메인 경유로 서빙
  4. **어드민 등록 시 이미지를 Supabase Storage로 복사** — 근본적이지만 작업량이 크다
- 어떤 방식이든 **이미지 로드 실패가 화면 전체를 죽이지 않도록** 폴백을 둔다
- DB에 실제로 어떤 호스트들이 들어와 있는지 먼저 전수 조사한다

## 구현 계획

1. 투데이 카드 테이블에서 `cover` 호스트 전수 조사
2. 위 4개 방식 중 선택 (조사 결과에 따라 판단)
3. 이미지 로드 실패 폴백 추가
4. 재현 계정으로 홈 화면 정상 렌더 확인
