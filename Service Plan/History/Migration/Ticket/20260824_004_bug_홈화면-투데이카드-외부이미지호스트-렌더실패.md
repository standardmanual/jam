# [bug] 홈 화면이 투데이 카드의 외부 이미지 호스트 때문에 통째로 렌더 실패

> 티켓 20260823_008 게이트 리뷰 중 발견. **이번 작업과 무관한 선행 버그**이며,
> 해당 투데이 카드에 매칭되는 사용자는 **홈 화면 전체가 에러 화면으로 떨어진다.**

## 배경 / 문제 정의

`src/app/(main)/TodayCardStack.tsx`의 `<Image src={cover}>`가 `next.config.ts`의
`images.remotePatterns`에 등록되지 않은 외부 호스트를 받는다.

`next/image`는 미허용 호스트를 만나면 **렌더 시점에 throw** 하므로, 카드 하나가 아니라
**홈 화면 전체가 에러 바운더리로 떨어진다.** dev·prod 모두 동일하다.

### 재현

로컬 `next dev` + dev-login 계정으로 `/` 진입 시:

```
Invalid src prop (https://storage.heypop.kr/...) on `next/image`,
hostname "storage.heypop.kr" is not configured under images in your `next.config.ts`
```

### 프로덕션 실데이터 전수 조사 (2026-08-24, 오케스트레이터 조회)

`today_cards` 활성 카드 **40건** 기준:

| 구분 | 건수 | 상태 |
|---|---|---|
| `storage.heypop.kr` | **10** | 🔴 미등록 호스트 → 렌더 시 throw |
| `cdn.news.bbsi.co.kr` | **1** | 🔴 미등록 호스트 → 렌더 시 throw |
| `cover_image_url` 없음 | 27 | 정상 (배지 이미지로 폴백 — Supabase Storage 또는 `/badges/...`) |
| 로컬 경로(`/badges/sample/*.png`) | 2 | 정상 |

→ **활성 카드 40건 중 11건(27.5%)이 홈 화면을 통째로 죽인다.**

### 왜 계속 재발하는가

`cover_image_url`은 어드민(`src/app/admin/today/TodayCardList.tsx:276`)의
**자유 입력 텍스트 필드**다. 운영자가 어떤 외부 URL이든 붙여넣을 수 있다.

호스트를 하나씩 `remotePatterns`에 추가하는 방식은 **새 콘텐츠를 등록할 때마다
같은 사고가 반복된다.** 게다가 등록 시점에는 아무 경고도 없고, 배포 후 해당 카드가
노출되는 사용자만 홈 화면이 깨진다.

## 상세 요구사항

### 서비스/코드베이스 관점

**두 가지를 모두 해결해야 한다. 하나만으로는 재발한다.**

#### (1) 임의 외부 URL이 `next/image`를 거치지 않게 한다

`cover_image_url`은 어드민 자유 입력값이라 **호스트를 사전에 알 수 없다.**
호스트 화이트리스트를 전제하는 `next/image`는 이 값에 맞지 않는 도구다.

권장: `cover_image_url`이 **외부 절대 URL이면 일반 `<img>`로 렌더**한다.
(프로젝트는 이미 `BadgeGridCard.jsx`·`BadgeRevealCarousel.jsx`에서 `<img>`를 쓰고 있고
`@next/next/no-img-element` 경고는 수용된 상태다.)

`resolved_badges[0].image_url` 폴백 경로는 Supabase Storage 또는 `/badges/...` 로컬이라
**`next/image`를 그대로 유지해도 된다** — 두 경로를 구분해서 처리할 것.

대안으로 `unoptimized` 속성이나 이미지 프록시 라우트도 가능하나, 최적화 이득이 크지 않은
커버 이미지에 복잡도를 더할 이유는 없다.

#### (2) 이미지 하나가 화면 전체를 죽이지 않게 한다

지금은 이미지 한 장이 throw하면 **홈 화면 전체가 에러 바운더리로 떨어진다.**
`onError` 폴백을 둬서 **이미지만 빠지고 카드·화면은 정상 렌더**되게 한다.

#### (3) 어드민에서 사전 경고 (선택 — 범위 판단)

`TodayCardList.tsx`의 URL 입력 시점에 로드 검증을 하거나, 저장 후 미리보기를 보여주면
운영자가 등록 단계에서 알아챌 수 있다. 이번 범위에 넣을지는 구현자가 판단한다.

### 게이트 리뷰 WARN 대응 (오케스트레이터 직접 수정, 머지 전)

게이트가 **WARN**을 냈다(버그는 고쳐졌으나 우려 2건). 사용자 승인 후 직접 처리했다.

**우려 1 — 판별 함수가 호스트만 검사** → `next.config.ts`와 **단일 소스로 통합**했다.
`imageSrc.ts`가 `IMAGE_REMOTE_PATTERNS`를 export하고 `next.config.ts`가 그걸 import한다.
호스트만 보던 판정을 `protocol` + `hostname` + `pathname`(`/**` 접두 일치) 전부 검사로 바꿨다.
next 내부 매처보다 **의도적으로 보수적**이다 — false negative는 `<img>` 렌더라는 무해한
열화지만 false positive는 화면 전체가 죽는 500이기 때문이다.

`next start` 런타임 실측으로 판별 함수와 `next/image` 실제 판정이 일치함을 확인:

| src | `isOptimizableImageSrc` | `next/image` 응답 |
|---|---|---|
| Supabase `/object/public/...` | `true` | `"url" parameter is valid` (패턴 통과) |
| 내부 경로 `/badges/...` | `true` | 200 |
| `storage.heypop.kr` | `false` | `"url" parameter is not allowed` |
| Supabase **서명 URL**(`/object/sign/`) | `false` | `"url" parameter is not allowed` |
| Supabase **http** 스킴 | `false` | `"url" parameter is not allowed` |

테스트도 4케이스 보강(서명 URL / http / 경계 유사 경로 `publicX` / 쿼리스트링) — 총 9개 통과.

**우려 2 — 배너형 로드 실패 시 대비 저하** → `SafeImage`의 `fallback`에 어두운 플레이트
(`absolute inset-0 bg-black`)를 넘겨 스크림 전제를 유지했다. 이 컴포넌트는 서버 컴포넌트라
"로드 실패"를 서버에서 알 수 없어 `OtherCard` 대체를 쓸 수 없다(커버가 *없는* 경우와 다름).
주석에 이 제약을 명시했다.

### 주요 의사결정 / 핵심 메모

- **호스트 화이트리스트를 늘리지 않았다.** `remotePatterns`에 `storage.heypop.kr`를 추가하면
  이번 11건은 살지만 다음 콘텐츠 등록에서 같은 사고가 반복된다. 판별 기준을 코드로 옮겼다.
- **`unoptimized`/이미지 프록시 대신 `<img>`를 골랐다.** 티켓 권장안이자,
  프로젝트에 이미 `<img>` 선례(BadgeGridCard·BadgeRevealCarousel)가 있다.
- **판정은 "출처 필드"가 아니라 "URL 모양"으로 한다.** `cover_image_url`이라도 로컬 경로면
  최적화를 유지하고, 배지 이미지라도 미등록 호스트면 `<img>`로 내린다. 같은 규칙 하나로
  두 경로를 모두 안전하게 덮는다.
- **MODULAR 신규 컴포넌트로 만들지 않았다.** `_ds_manifest.json`을 확인했으나 이미지 프리미티브가
  없고, `SafeImage`는 시각 디자인이 아니라 src 안전성 처리 인프라라 `src/components/`에 뒀다.
- 티켓이 지정한 두 지점(`TodayCardStack:58`, `:144`) 외에 **배지목록형 썸네일과 아티클 상세**도
  같이 고쳤다. 같은 필드·같은 크래시 경로이고, 아티클 상세는 홈 카드를 눌러 진입하는 화면이라
  홈만 고치면 한 클릭 뒤에서 동일한 500이 난다.

### 잔여 이슈
- `src/lib/imageSrc.ts`의 `OPTIMIZABLE_HOSTS`는 `next.config.ts`의 `images.remotePatterns`와
  **수동 동기화**다. 호스트를 추가·삭제할 때 두 곳을 같이 고쳐야 한다(양쪽에 주석으로 명시).
  어긋나도 크래시가 아니라 "최적화를 안 하고 `<img>`로 렌더"로만 degrade된다.
- 다른 화면(배지·컬렉션·프로필 등)은 여전히 DB의 `image_url`을 `next/image`에 직접 넘긴다.
  현재는 전부 업로드 경로라 안전하지만, 향후 자유 입력 URL 필드가 생기면 `SafeImage`를 쓴다.
