# [bug] 어드민 자유 입력 이미지 URL — 미션·컬렉션·세계관에 남은 동일 크래시 경로

> 티켓 **20260824_004**(홈 화면 렌더 실패) 개선 리뷰에서 발견. 004는 투데이 카드만
> 고쳤고, **같은 구조의 크래시가 세 곳에 더 남아 있다.**

## 배경 / 문제 정의

004에서 "`cover_image_url`이 어드민 전체에서 유일한 자유 입력 이미지 URL 필드"라고
판단했으나 **사실이 아니었다.**

`src/components/admin/ImageUploadField.tsx`의 **`allowManualUrl` 기본값이 `true`**이고,
`allowManualUrl={false}`로 막은 곳은 배지 폼(`admin/badges/BadgeForm.tsx`) **한 군데뿐**이다
(20260818_002에서 배지만 업로드 전용으로 전환하면서 기본값을 뒤집지 않았다).

### 남아 있는 크래시 경로

| 필드 | 어드민 입력 | 서비스 렌더 (`next/image` 직행) |
|---|---|---|
| 미션 썸네일 | `admin/missions/MissionList.tsx` | `(main)/missions/[id]/MissionDetailClient.tsx` |
| 컬렉션 이미지 | `admin/itembooks/ItemBookForm.tsx` | `ui/CollectionGridCard.tsx`, `[username]/collections/page.tsx` |
| 세계관 이미지 | `admin/factions/FactionForm.tsx` — **업로드 없는 순수 자유 입력** | (렌더 지점 확인 필요) |

운영자가 이 필드에 미등록 호스트 URL을 넣는 순간, 004와 **똑같이 해당 화면 전체가 500**이
된다. 지금 깨지지 않는 건 우연히 그런 값이 안 들어갔기 때문이다.

### 부가 리스크 — Google 아바타 호스트 가정

`next.config.ts`는 구글 아바타 호스트를 `lh3.googleusercontent.com`으로 고정 가정하는데,
`src/app/auth/callback/route.ts`는 `includes('googleusercontent')`로 **느슨하게** 검사한다.
`lh4`/`lh5`가 오면 프로필·검색·팔로워 화면이 같은 방식으로 죽는다.

## 상세 요구사항

### A. 실태 조사 (선행)

`missions.image_url` / `item_books.image_url` / `factions.image_url`에 **미등록 호스트가
실제로 들어와 있는지** 프로덕션 DB를 조회해 확인한다. (조회만 — 쓰기 금지)

### B. 렌더 지점을 `SafeImage`로 전환

004에서 만든 `src/components/SafeImage.tsx`를 그대로 쓴다. 미등록 호스트는 일반 `<img>`로
렌더되고, 로드 실패는 폴백으로 흡수된다.

> `SafeImage`가 세 번째 사용처를 넘기므로 **MODULAR 승격 여부를 재검토**한다.
> 004 개선 리뷰 판단: 재사용성·범용성·토큰 준수는 충족하나 `next/image`와 `next.config.ts`에
> 강결합돼 있어 `design-system/`에 넣으면 Storybook이 Next 런타임에 묶인다. 시각 컴포넌트가
> 아니라 "src 안전성 인프라"라는 성격 판단도 함께 고려할 것.

### C. `allowManualUrl` 기본값을 `false`로 뒤집는다

지금은 **위험한 기본값(fail-open)** 이다. 기본을 업로드 전용으로 바꾸고, 자유 입력이
꼭 필요한 곳만 `allowManualUrl={true}`를 명시하게 한다.

세계관 폼은 업로드 경로가 아예 없으므로 업로드를 붙일지, 자유 입력을 유지하되 `SafeImage`로
방어할지 판단한다.

### D. Google 아바타 호스트 범위 확대

`next.config.ts`의 hostname을 `*.googleusercontent.com`으로 넓힌다 (한 줄, 저비용 방어).
패턴은 `src/lib/imageSrc.ts`의 `IMAGE_REMOTE_PATTERNS`가 단일 소스다 — 거기만 고치면 된다.

### E. 관측성 (선택 — 범위 판단)

미등록 호스트가 들어와도 조용히 `<img>`로 내려가 운영자가 영원히 모른다.
카드/미션/컬렉션 로드 시점에 `isOptimizableImageSrc(src) === false`면 id와 함께
`console.warn` 한 줄만 남겨도 Vercel 로그로 수집된다.

더 나은 쪽은 어드민 입력란 옆 미리보기 — `admin/ImageUploadField.tsx`에 이미 `onError`로
숨기는 미리보기 패턴이 있어 그대로 옮길 수 있다.

## 구현 계획

1. 세 테이블의 `image_url` 호스트 전수 조사 (조회 전용)
2. 렌더 지점을 `SafeImage`로 전환 + 각 화면에 맞는 폴백 지정
3. `allowManualUrl` 기본값 `false`로 전환, 필요한 곳만 명시적 `true`
4. `IMAGE_REMOTE_PATTERNS`에 `*.googleusercontent.com` 반영
5. `SafeImage` MODULAR 승격 여부 재검토 후 결론 기록
6. 실제로 깨지는 URL을 넣어 A/B 확인 (DB 쓰기 없이 로컬에서 목 데이터로 렌더 검증)
7. `tsc` / `eslint` / `build` 검증

#### C. `allowManualUrl` 기본값을 `false`로 뒤집음

- `components/admin/ImageUploadField.tsx` — 기본값 `true` → **`false`**(업로드 전용).
- 결과적으로 **자유 입력을 명시적으로 켠 화면은 한 곳도 없다.** 미션 썸네일(45건 전부 Storage)·
  컬렉션 이미지(전부 Storage 또는 내부 경로) 모두 이미 업로드 경로만 쓰고 있어 운영 손실이 없다.
- 배지 폼(`admin/badges/BadgeForm.tsx`)의 `allowManualUrl={false}`는 **그대로 뒀다.**
  기본값이 다시 뒤집혀도 "배지 이미지는 Storage만"(20260818_002)이라는 보장이 유지된다.
- **세계관 폼**은 업로드 경로가 아예 없는 순수 자유 입력이었다 → `ImageUploadField`(업로드 전용,
  `folder="factions"`)로 교체했다. `factions.image_url`은 프로덕션에 값이 **0건**이라 기존 값이
  막히는 부작용이 없고, 세계관 폼은 이미 배경 이미지를 같은 업로드 API로 올리고 있어
  경로가 새로 필요하지도 않다.

#### D. 구글 아바타 호스트 범위 확대

`IMAGE_REMOTE_PATTERNS`(단일 소스)의 `lh3.googleusercontent.com` → **`*.googleusercontent.com`**.
`isOptimizableImageSrc`에 `matchesHostname()`을 추가해 `*.` 접두를 **서브도메인 한 단계만**
매칭한다(`matchesPathname`과 같은 보수적 방향).

`auth/callback/route.ts`가 `includes('googleusercontent')`로 느슨하게 판정해 저장하므로
`lh4`/`lh5`가 들어오면 프로필·검색·팔로워가 죽는 경로였다. 코드는 그대로 두고 패턴만 넓혔다.

#### E. `SafeImage` MODULAR 승격 재검토 — **승격하지 않는다 (결론 유지)**

사용처가 4→8곳(004의 4곳 + 이번 4곳)으로 늘었지만 `design-system/`으로 옮기지 않는다.

- `design-system/`은 Next 런타임에 의존하지 않는 순수 컴포넌트 모음이다(`.jsx` + Storybook).
  `SafeImage`는 `next/image`와 `next.config.ts`의 `remotePatterns`에 **본질적으로** 강결합돼
  있어(존재 이유 자체가 그 결합의 방어다) 옮기면 Storybook이 Next 런타임에 묶인다.
- 시각 컴포넌트가 아니라 **"src 안전성 인프라"** 다. 토큰·레이아웃·상태를 정의하지 않고
  디자인 산출물이 없어 Storybook에 실을 스토리가 사실상 없다. 실제 디자인 결정은
  `SafeImage`를 쓰는 쪽(카드·히어로·그리드)이 갖는다.
- 디자인시스템에는 이미 같은 이름값의 시각 패턴(`BadgeGridCard`·`CollectionGridCard`)이 있고,
  그 DS 버전들은 Next 밖에서 순수 `<img>`로 렌더된다. `SafeImage`는 **앱 쪽에서만** 필요하다.

→ `src/components/SafeImage.tsx` 유지. 004 판단을 사용처 8곳 기준으로 재확인한 것이다.

### 주요 의사결정 / 핵심 메모

- **데이터를 고치지 않았다.** 조회만 했고, 실제로 고칠 값도 없었다(미등록 호스트 0건).
  `next.config.ts`에 호스트를 추가하는 우회도 하지 않았다(004가 명시적으로 배제한 방식).
- **`allowManualUrl`을 "필요한 곳만 true"로 뒤집었더니 true를 줄 곳이 없었다.** 자유 입력이
  실제로 필요한 화면은 투데이 카드 커버(`TodayCardList`의 별도 `<input>`)뿐이고, 그 렌더 경로는
  004에서 이미 `SafeImage`로 막혀 있다.
- **세계관은 업로드를 붙이는 쪽을 택했다.** 자유 입력 유지 + `SafeImage` 방어도 가능했지만,
  `factions.image_url`은 서비스 화면에서 렌더되는 지점이 아직 없어(어드민 미리보기만 `<img>`로
  사용) 방어할 렌더 지점 자체가 없다. 값이 0건이라 업로드 전용 전환의 비용도 0이다.
- **판별 함수는 `next/image`보다 좁게 유지한다.** 실측 결과 next는 `*.googleusercontent.com`에
  `a.b.googleusercontent.com`(2단계)도 통과시켰지만, 이 함수는 한 단계만 인정한다.
  덜 매칭되면 `<img>`로 내려가 최적화만 놓치고(무해), 더 매칭되면 화면이 죽는다.
- **관측성(요구사항 E의 선택 항목)은 넣지 않았다.** 미등록 호스트가 `console.warn`을 남기게 하려면
  서버·클라이언트 양쪽 렌더 경로에 부수효과를 넣어야 하는데, 이번 전환으로 자유 입력 자체가
  어드민에서 사라져 "모르는 사이 미등록 URL이 들어오는" 경로가 닫혔다. 남은 자유 입력(투데이 카드)에
  대한 어드민 사전 경고는 별도 판단 사안이다.

### 잔여 이슈
- **어드민 화면은 로컬/스테이징에서 검증할 수 없다.** dev-login 계정에 관리자 권한이 없어
  `/admin/*`이 `forbidden`으로 떨어진다. 세계관 폼의 업로드 전환·미션/컬렉션 폼의 URL 입력란
  제거는 `tsc`/`eslint`/`build`로만 확인했고, **프로덕션 배포 후 실제 확인이 필요하다.**
- `(main)/missions/MissionsListClient.tsx`와 `(main)/collections/[id]/ItemBookHeroSection.tsx`는
  이미 일반 `<img>`라 **화면이 죽지는 않지만** 로드 실패 폴백이 없다(깨진 이미지 아이콘 노출).
  크래시 경로가 아니라 이번 범위에서 제외했다.
- 미션 상세의 보상 배지 썸네일(`MissionDetailClient`)과 배지 그리드 등은 여전히
  `badges.image_url`을 `next/image`에 직접 넘긴다. 배지 폼이 업로드 전용이고 5,585건 전수 조사에서
  미등록 호스트가 0건이라 이번 범위에서 제외했다.
- `auth/callback/route.ts`의 `includes('googleusercontent')` 판정은 그대로 뒀다.
  `evil-googleusercontent.com` 같은 문자열도 통과하는 느슨한 검사지만, 이 값은 구글 OAuth가 준
  `user_metadata.avatar_url`과 비교하는 용도라 외부 입력 경로가 아니다. 렌더 쪽은
  `matchesHostname`이 정확히 판정하므로 화면이 죽는 경로는 닫혔다.
