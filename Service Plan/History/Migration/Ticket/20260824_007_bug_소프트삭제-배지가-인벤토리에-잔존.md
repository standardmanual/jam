# [bug] 소프트 삭제된 배지가 인벤토리에 그대로 남아 화면 간 불일치가 난다

> 티켓 20260824_003 게이트 리뷰에서 발견. **규모가 예상보다 크다.**

## 배경 / 문제 정의

`badges.deleted_at`이 설정된 배지는 서비스 화면에서 숨긴다(의도된 동작). 그런데
**사용자가 이미 보유한 `inventory_items`는 그대로 남는다.**

결과적으로 같은 아이템이 화면마다 다르게 보인다:
- 인벤토리 — 보인다
- 배지 획득 연출·피드·컬렉션 — 안 보인다

### 프로덕션 실측 (2026-08-24, 조회 전용)

| 항목 | 값 |
|---|---|
| 전체 `inventory_items` | 200건 |
| **소프트 삭제된 배지를 가리키는 항목** | **109건 (54.5%)** |
| 영향받는 사용자 | **9명** |

**보유 아이템의 절반 이상이 삭제된 배지를 가리킨다.** 2026-08-23 orphan 아이템배지
1,245건 소프트 삭제(커밋 `1e77419`)의 여파로 보인다.

추가로 최근 피드 50건의 `badge_id` 중 15건(30%)이 삭제 대상이라 획득 연출에서 제외된다.

### 왜 문제인가

- 사용자가 **인벤토리에서는 보이는 아이템**을 컬렉션·피드에서 못 찾는다
- 배지를 받았는데 획득 연출에 카드가 0장이면 **아무 일도 안 일어난 것처럼 보인다**
- 아이템배지는 **시리얼 번호**가 있어 사용자가 소유물로 인식한다. 조용히 사라지면
  "내 아이템이 없어졌다"로 받아들여진다

## 상세 요구사항

### A. 정책 결정 (선행 — 이 티켓의 핵심)

**소프트 삭제된 배지를 이미 보유한 사용자에게 어떻게 할 것인가?**

1. **인벤토리에서도 숨긴다** — 화면 간 일관성은 맞지만, 사용자 입장에서는 보유물이
   말없이 사라진다. 시리얼 번호가 있는 아이템이라 체감이 크다
2. **인벤토리에 남기고 다른 화면에도 노출한다** — 삭제는 "신규 발급 중단"만 의미하게
   된다. 기존 보유자의 소유권을 존중하는 방향
3. **인벤토리 항목도 함께 정리한다** — 회수. 되돌리기 어려우므로 신중해야 한다
4. **"단종" 상태로 구분 표시** — 보유는 유지하되 화면에 표시를 다르게 한다

> 소프트 삭제의 **원래 의도가 무엇이었는지** 먼저 확인할 것.
> 티켓 `20260823_004`(컬렉션 비활성화 배지 연쇄 회수)·`20260823_005`·`20260823_006`이
> 관련 결정을 담고 있을 가능성이 있다.

### B. 결정에 따른 구현

- 1·3안 → 인벤토리 조회에 `deleted_at` 필터 추가 또는 데이터 정리 SQL
- 2안 → 다른 화면의 `deleted_at` 필터를 완화 (보유분에 한해)
- 4안 → 상태 표시 UI 신규

### C. 1,245건 소프트 삭제의 적정성 재확인

`seed_deactivate_orphan_item_badge_rarity_variants_20260823.sql`이 지운 1,245건이
**실제로 보유자가 없는 orphan이었는지** 확인한다. 위 실측(보유분 109건이 삭제 배지를
가리킴)은 그 전제와 어긋날 수 있다.

## 구현 계획

1. 소프트 삭제의 원래 의도 확인 (관련 티켓 검토)
2. A의 4개 안 중 결정 (사용자 판단 필요)
3. 1,245건 삭제분 중 실제 보유자가 있는 건이 얼마나 되는지 조사
4. 결정에 따른 구현 + 실데이터 검증
