# [bug] 소프트 삭제된 배지가 인벤토리에 그대로 남아 화면 간 불일치가 난다

> 티켓 20260824_003 게이트 리뷰에서 발견. **규모가 예상보다 크다.**


> # ✅ 결정 완료 (2026-08-24) — 정책이 아니라 일관성 버그였다
>
> 사용자 확인: **소프트 삭제로 배지를 화면에서 숨기는 것 자체가 의도된 동작이다.**
> 즉 "숨길지 말지"는 이미 결정돼 있었고, 실제 문제는 **어디는 숨기고 어디는 새는
> 일관성 결함**이었다.
>
> 재조사 결과 원래 제목의 "인벤토리에 잔존"이라는 진단도 부정확했다 — **인벤토리
> 목록(`inventory/page.tsx`) 자체는 이미 정확히 필터링되고 있다.** 진짜 구멍은
> `badges/[id]/page.tsx`(배지 상세)에 `deleted_at` 필터가 아예 없다는 것이고, 이 한
> 곳이 필터 없이 뚫려 있어서 아래 4개의 **정상적인 앱 내 클릭 경로**로 삭제된 배지가
> 노출된다:
>
> | 경로 | 재현 조건 |
> |---|---|
> | **포인트 내역** (`/api/points`) | 없음 — 배지로 포인트를 받은 적 있으면 항상 재현 |
> | 미션 상세 보상 카드 | 삭제된 배지가 미션 보상으로 지정된 경우 |
> | 컬렉션(아이템북) 상세 슬롯 | 보유/슬롯 중이던 배지가 삭제된 경우 |
> | 홈 "최근 획득 배지" | 최근 4개 안에 삭제된 배지가 포함된 경우 |
>
> → 아래 A절(정책 결정)은 **더 이상 유효하지 않다.** B절(구현)을 아래처럼 대체한다.

## 배경 / 문제 정의

`badges.deleted_at`이 설정된 배지는 서비스 화면에서 숨긴다(의도된 동작). 그런데
**사용자가 이미 보유한 `inventory_items`는 그대로 남는다.**

결과적으로 같은 아이템이 화면마다 다르게 보인다:
- 인벤토리 — 보인다
- 배지 획득 연출·피드·컬렉션 — 안 보인다

### 프로덕션 실측 (2026-08-24, 조회 전용)

| 항목 | 값 |
|---|---|
| 전체 `inventory_items` | 200건 |
| **소프트 삭제된 배지를 가리키는 항목** | **109건 (54.5%)** |
| 영향받는 사용자 | **9명** |

**보유 아이템의 절반 이상이 삭제된 배지를 가리킨다.** 2026-08-23 orphan 아이템배지
1,245건 소프트 삭제(커밋 `1e77419`)의 여파로 보인다.

추가로 최근 피드 50건의 `badge_id` 중 15건(30%)이 삭제 대상이라 획득 연출에서 제외된다.

### 왜 문제인가

- 사용자가 **인벤토리에서는 보이는 아이템**을 컬렉션·피드에서 못 찾는다
- 배지를 받았는데 획득 연출에 카드가 0장이면 **아무 일도 안 일어난 것처럼 보인다**
- 아이템배지는 **시리얼 번호**가 있어 사용자가 소유물로 인식한다. 조용히 사라지면
  "내 아이템이 없어졌다"로 받아들여진다

## 상세 요구사항

### 수정 대상 — `deleted_at` 필터 누락 지점 전수

| 파일 | 조회 | 조치 |
|---|---|---|
| `src/app/(main)/badges/[id]/page.tsx` | `badges.select('*').eq('id', id)` | `deleted_at IS NULL` 확인 후 없으면 `notFound()` — **핵심 지점** |
| 같은 파일 내 `item_books` 조회(소속 컬렉션) | 필터 없음 | 조인에 `deleted_at IS NULL` 추가 |
| 같은 파일 내 `prereqBadges`(선행 배지) | 필터 없음 | 동일 |
| 같은 파일 내 POI 미획득 배지 역조회 | 필터 없음 | 동일 |
| `src/app/(main)/collections/[id]/page.tsx` | `badges.select('*').eq('item_book_id', id)` | `deleted_at IS NULL` 추가. `SlotGrid.tsx`가 이 결과로 링크를 만들므로 조회 단계에서 막아야 한다 |
| `src/app/(main)/missions/[id]/page.tsx` | 보상 배지 `select('id, name, image_url, rarity')` | `deleted_at IS NULL` 추가 |
| `src/app/(main)/page.tsx` (홈) | `user_activity_badges` 조인 "최근 획득 배지" | `badge.deleted_at`으로 사후 필터 (다른 화면 관례와 동일) |
| `src/app/api/points/route.ts` | 포인트 내역의 배지명 조회 | `deleted_at IS NULL` 추가. **북마크 없이 항상 재현되는 가장 확실한 경로라 우선순위 최상** |
| `src/app/api/badges/[id]/share-data/route.ts` | 공유 데이터 API | `deleted_at IS NULL` 확인 후 없으면 오류 응답 |
| `src/app/(main)/inventory/[itemId]/page.tsx` | 조회 안 함, 무조건 `/badges/{id}`로 리다이렉트 | **수정 불필요** — `badges/[id]/page.tsx`만 고치면 이 경로도 함께 막힌다 |

**참고 — 이미 올바르게 필터링된 화면** (변경 불필요, 관례 확인용):
`inventory/page.tsx`, `badges/page.tsx`, `[username]/page.tsx`, `activity-feed/hydrate.ts`

**어드민 화면은 의도적 예외** — 소프트 삭제 상태를 관리 목적으로 노출하는 게 맞다.
`admin/badges/page.tsx`의 활성/비활성 탭, `BadgeActiveToggleButton` 등은 그대로 둔다.

### 표시 정책

배지가 삭제됐을 때 링크·이름·이미지를 어떻게 처리할지는 화면마다 기존 "미획득"·"빈 상태"
관례를 따른다:
- 배지 상세 직접 접근 → `notFound()` (다른 존재하지 않는 배지와 동일하게 처리)
- 컬렉션·미션·홈처럼 목록 안의 항목 하나가 삭제된 경우 → **항목만 빠지고 나머지는 유지**
  (전체 화면을 막지 않는다 — 20260824_004의 교훈과 동일)

## 구현 계획

1. `src/app/(main)/badges/[id]/page.tsx`에 `deleted_at IS NULL` 필터 추가 (배지 본체 +
   소속 컬렉션 + 선행 배지 + POI 역조회 4곳)
2. `collections/[id]/page.tsx`, `missions/[id]/page.tsx`, `page.tsx`(홈),
   `api/points/route.ts`, `api/badges/[id]/share-data/route.ts`에 동일 필터 추가
3. 목록형 화면(컬렉션·미션·홈)은 항목만 빠지고 나머지는 유지되는지 확인
4. 실측 검증 — 삭제된 배지로 각 경로 재현 (수정 전 실제로 노출되는지 A/B 확인 후 수정)
5. 필요 시 1,245건 소프트 삭제의 적정성 재확인 (C절)
