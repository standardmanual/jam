## 배경 / 문제 정의

`badges.deleted_at`이 설정된 배지는 서비스 화면에서 숨긴다(의도된 동작). 그런데
**사용자가 이미 보유한 `inventory_items`는 그대로 남는다.**

결과적으로 같은 아이템이 화면마다 다르게 보인다:
- 인벤토리 — 보인다
- 배지 획득 연출·피드·컬렉션 — 안 보인다

### 왜 문제인가

- 사용자가 **인벤토리에서는 보이는 아이템**을 컬렉션·피드에서 못 찾는다
- 배지를 받았는데 획득 연출에 카드가 0장이면 **아무 일도 안 일어난 것처럼 보인다**
- 아이템배지는 **시리얼 번호**가 있어 사용자가 소유물로 인식한다. 조용히 사라지면
  "내 아이템이 없어졌다"로 받아들여진다

### 표시 정책

배지가 삭제됐을 때 링크·이름·이미지를 어떻게 처리할지는 화면마다 기존 "미획득"·"빈 상태"
관례를 따른다:
- 배지 상세 직접 접근 → `notFound()` (다른 존재하지 않는 배지와 동일하게 처리)
- 컬렉션·미션·홈처럼 목록 안의 항목 하나가 삭제된 경우 → **항목만 빠지고 나머지는 유지**
  (전체 화면을 막지 않는다 — 20260824_004의 교훈과 동일)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`badges.deleted_at IS NULL` 필터가 누락돼 있던 6개 지점에 필터를 추가했다. 표시 정책은
두 갈래로 나눴다 — (1) 배지 상세를 직접 여는 경우는 존재하지 않는 배지와 동일하게
`notFound()` 처리, (2) 컬렉션·미션·홈처럼 목록 안에 배지가 여러 개 섞여 있는 화면은
삭제된 항목만 조용히 빠지고 나머지 항목·집계(완성도 등)는 그대로 유지.

- `badges/[id]/page.tsx`: 배지 본체 조회에 필터 추가(없으면 `notFound()`). 이 시점 이후의
  소속 컬렉션(`item_books`)·POI 역조회(`poi.linked_badge_id`) 조회는 `notFound()`보다 뒤에
  있는 코드라 별도 필터 없이도 함께 막힌다. 선행 배지 조회에도 필터를 추가했고, 필터로
  제외된 선행 배지는 빈 값(`id: ''`)으로 렌더링되던 기존 버그도 함께 고쳐 목록에서
  완전히 빠지도록 정리했다(제거하지 않으면 깨진 링크·중복 React key가 남는 문제였음).
- `collections/[id]/page.tsx`: 컬렉션 소속 배지 조회에 필터 추가. 삭제된 배지는 슬롯
  자체가 안 보이고, 완성도 분모(`totalBadgeCount`)에서도 자동으로 제외된다(다른 화면과
  동일한 관례).
- `missions/[id]/page.tsx`: 보상 배지 조회에 필터 추가. 삭제된 보상 배지 카드만 빠지고
  포인트 보상·다른 배지 보상은 그대로 보인다.
- `page.tsx`(홈): "최근 획득 배지" 조인 결과를 `!badge.deleted_at`으로 사후 필터
  (`lib/activity-feed/hydrate.ts`, `badges/page.tsx`와 동일한 관례). 쿼리 자체는
  `limit(4)`를 유지하므로, 최근 4건 중 삭제된 배지가 섞여 있으면 화면에는 4건보다
  적게 보일 수 있다 — 다른 화면들의 기존 관례를 그대로 따른 것이라 이번 티켓에서
  새로 만든 특성은 아니다.
- `api/points/route.ts`: 포인트 내역의 배지명 조회에 필터 추가. 삭제된 배지를 가리키는
  거래는 실제 배지명 대신 `REASON_KIND`의 일반 사유 라벨("배지 보상")로 표시된다
  (기존 폴백 로직 그대로 재사용, 별도 신규 문구 없음).
- `api/badges/[id]/share-data/route.ts`: 배지 조회에 필터 추가. 없으면 기존과 동일하게
  `404 badge_not_found` 응답.
- `inventory/[itemId]/page.tsx`는 수정 불필요 확인 — `badges` 테이블을 조회하지 않고
  무조건 `/badges/{id}`로 리다이렉트하므로, 위 배지 상세 수정만으로 이 경로도 함께 막힘.
