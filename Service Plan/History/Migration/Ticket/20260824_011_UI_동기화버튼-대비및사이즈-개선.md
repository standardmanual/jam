# [UI] Topnavi 동기화 버튼 대비·사이즈 개선 + DS Button 컴팩트 사이즈 신설

## 배경 / 문제 정의

티켓 20260824_010(Topnavi 3분할 개편) 게이트 리뷰에서 WARN으로 남겨뒀던 잔여 이슈가
staging 배포 후 실제로 확인됐다. `Button(variant="outline" surface="sub")`는 라이트
배경 전제 색 조합(검정 텍스트 + 4% 블랙 틴트 배경)인데, 다크 캔버스(홈 화면 등,
`--color-bg` 검정) 위에서 그대로 쓰여 "동기화" 버튼이 거의 안 보였다(사용자 스크린샷
확인). 이어서 버튼이 44px 높이로 너무 크다는 피드백, 높이를 줄이되 모듈러(DS)에
해당 사이즈가 없으면 새로 만들라는 지시, 마지막으로 "70% 정도로 줄이고 싶다 — 모듈러에
토큰이 없으면 추가해서 적용하라"는 지시가 이어졌다.

## 상세 요구사항

### 색상 (대비 문제)
- 미연동 유저용 버튼(`src/components/ui/TopNav.tsx`)과 연동 유저용 `SyncButton.tsx` 모두
  `style={{ backgroundColor: 'var(--color-secondary)', color: 'var(--color-base-white)' }}`로
  배경을 서브 강조 컬러(브라운, `--color-secondary` = `--color-base-brown` = `#8a5a2e`)로
  오버라이드해 다크 배경에서도 항상 보이도록 함.

### 사이즈 (컴팩트 버튼 신설)
- DS `design-system/components/buttons/Button.jsx`에 `size` prop 신설: `'md'`(기본,
  44px) | `'sm'`(신규 — 내비게이션 바 등 조밀한 컨텍스트 전용, 44px 터치 타겟 규칙의
  명시적 예외).
- `'sm'`의 치수는 매직 넘버가 아니라 신규 토큰 `--scale-compact: 0.7`
  (`design-system/tokens/motion.css`)로 `md` 치수에서 유도: `minHeight: calc(44px *
  var(--scale-compact))`(≈31px), `padding: calc(12px * var(--scale-compact)) calc(24px *
  var(--scale-compact))`. 폰트는 스케일 곱셈 대신 기존 `--text-caption`(12px) 토큰을
  그대로 사용(임의 폰트 크기 신설 방지).
- `--scale-compact`는 기존 `--scale-press`/`--scale-modal`(press 시 transform: scale()
  피드백용)과 성격이 다름을 주석으로 명시 — 이건 절대 치수(minHeight/padding) 계산용.
- 서비스 `src/components/ui/Button.tsx`에 동일 스펙의 `'xs'` 사이즈 추가(서비스 자체
  사이즈 체계가 `sm`/`md`/`lg`로 이미 다른 의미를 갖고 있어 `sm`을 재정의하지 않고
  새 값 `xs`로 추가 — 기존 `size="sm"` 호출처 8곳에 영향 없음, grep으로 확인).
  DS `sm`과 동일하게 `--scale-compact` 기반 `calc()`로 치수 도출.
- `Button.tsx`가 호출부에서 넘긴 `style` prop을 컴포넌트 내부 계산 스타일과 병합하도록
  변경(기존엔 `{...props}` 스프레드가 내부 style을 완전히 덮어썼음) — TopNav/SyncButton이
  배경색만 오버라이드하면서 `xs` 사이즈 치수도 함께 적용받을 수 있어야 하기 때문.
- Storybook `Button.stories.tsx`에 `Small` 스토리 추가.
- `Button.prompt.md`에 `size="sm"` 사용법 및 `--scale-compact` 토큰 참조 추가.

## 구현 계획
1. `design-system/tokens/motion.css`에 `--scale-compact: 0.7` 토큰 추가
2. DS `Button.jsx`에 `size` prop + `'sm'` 사이즈(토큰 기반 calc) 추가, `.d.ts`/
   `.stories.tsx`/`.prompt.md` 동반 갱신
3. 서비스 `Button.tsx`에 `'xs'` 사이즈 추가(동일 스펙), `style` prop 병합 로직으로 변경
4. `TopNav.tsx`/`SyncButton.tsx`에서 `size="xs"` + 브라운 배경색 오버라이드 적용
5. 로컬 dev 서버(`npm run dev`)로 홈/배지 목록/배지 상세에서 대비·크기 육안 확인

### 주요 의사결정 / 핵심 메모
- `size="sm"`을 서비스 `Button.tsx`에서 재정의하지 않고 `xs`로 신설한 이유: 서비스는
  이미 `sm`/`md`/`lg`를 "패딩만 미세 조정, 높이는 항상 44px 고정"이라는 의미로 8곳에서
  쓰고 있어(`UserSearchBar`, `FollowButton`, 어드민 테이블 등) `sm`의 의미를 바꾸면
  기존 호출처가 깨진다.
- `--scale-compact`를 `--scale-press`/`--scale-modal`과 같은 motion.css에 뒀지만 용도가
  다름을 주석으로 분명히 함(transform 배율이 아니라 절대 치수 계산용) — 이름 충돌로
  인한 오용을 막기 위한 의도적 문서화.
- 폰트 크기는 `--scale-compact`로 곱하지 않고 기존 `--text-caption` 토큰을 그대로 사용
  — 44px 기준 16px×0.7=11.2px는 기존 타입 스케일에 없는 임의 크기라 채택하지 않음.
