# [Feature] 아이템배지 미슬롯 컬렉션, 타인에게 노출 차단

## 배경 / 문제 정의

kangwonc 프로필의 컬렉션 상세(`/collections/f3e7e637-1f47-569a-014a-4cca4c0fe691?u=kangwonc`)에서
프로그레스바는 `0/9`인데 그리드에는 배지가 채워진 것처럼 보이는 현상을 사용자가 발견해 조사를
요청함.

조사 결과 원인은 확인했으나(아이템배지를 인벤토리에 보유만 하고 `user_item_book_slots`에는 넣지
않은 상태 — `SlotGrid.tsx`에서 "보유·미슬롯" 배지가 `opacity-70`만 적용된 채 컬러로 그대로
렌더링되고, 타인 열람 시 `readOnly=true`라 "슬롯 장착" 버튼도 숨겨져 슬롯 완료 배지와 구분이 거의
안 됨), 이번 티켓은 **그 표시 버그를 고치는 대신 정책 자체를 바꾼다**: 아이템배지를 한 개도
슬롯에 넣지 않은 컬렉션은 타인(팔로워 등)에게 아예 노출하지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **노출 조건**: `user_item_book_slots`에서 해당 유저 + 해당 `item_book_id` 조합의 행 개수(아이템배지
  슬롯 개수)가 1개 이상이어야 타인에게 노출. 0개면 숨김.
- **POI 배지 무관**: POI 배지만 획득하고 아이템배지 슬롯이 0개인 경우도 여전히 숨김 (아이템배지
  슬롯 개수만 기준).
- **본인 열람은 예외**: 본인이 자신의 컬렉션을 볼 때는 기존과 동일하게 항상 노출 (슬롯 0개여도
  보임). 이 정책은 "타인이 보는 내 컬렉션"에만 적용.
- **적용 범위 — 타인이 내 컬렉션을 볼 수 있는 모든 지점**:
  1. 컬렉션 목록: `src/app/(main)/[username]/collections/page.tsx`,
     `src/app/(main)/profile/ProfileClient.tsx` 등 프로필에서 컬렉션 카드를 나열하는 곳 — 슬롯
     0개인 컬렉션 카드는 목록에서 제외.
  2. 컬렉션 상세 페이지: `src/app/(main)/collections/[id]/page.tsx` — `?u=username`으로 타인 기준
     조회 시 슬롯이 0개면 상세 페이지 접근 자체를 막는다 (404 등). 직접 URL 진입도 차단.

### UI/UX 관점

- 목록에서 카드가 사라지는 것 외에 별도 안내 문구는 불필요 (사용자 확정: 그냥 안 보이면 됨).
- 컬렉션 상세 직접 URL 접근 시 404/찾을 수 없음 처리 시 기존 `notFound()` 패턴을 따른다
  (배지가 없는 아이템북 등 기존 처리와 동일한 UX).

## 구현 계획

1. `[username]/collections/page.tsx`에서 대상 유저 기준 아이템북 목록 조회 시, 조회 대상이 본인이
   아니면 슬롯 개수 0인 아이템북을 결과에서 필터링.
2. `ProfileClient.tsx` 등 다른 목록 노출 지점이 있다면 동일 조건 적용 (탐색 후 확정).
3. `collections/[id]/page.tsx`에서 `subjectId !== user.id`(타인 조회)이고 `slots.length === 0`이면
   `notFound()` 처리. 단 이 검사는 아이템배지가 애초에 없는 컬렉션(`badges.length === 0`)과는 별개
   조건이므로 혼동 없이 분리해서 구현.
4. dev 서버에서 슬롯 0개/1개 이상 케이스를 각각 만들어 목록·상세 양쪽에서 노출 여부 확인.

## 추가 요구사항 (2026-08-24, 1차 구현 게이트 PASS 후 사용자 확정 — 같은 티켓으로 병합)

1차 구현으로 "슬롯 0개 컬렉션은 타인에게 아예 안 보임" 정책은 반영됐지만, **본인이 자기 컬렉션을
볼 때는 여전히 "보유·미슬롯" 배지가 "슬롯 완료" 배지와 시각적으로 거의 구분되지 않는 원인 버그가
남아있음** ([`SlotGrid.tsx`](../../../../jam-web/src/app/(main)/collections/[id]/SlotGrid.tsx) —
`isSlottable`일 때 컨테이너에 `opacity-70`만 적용되고 `BadgeGridCard`에는 `earned`/`undiscovered`를
안 넘겨 기본값(`earned=true`)으로 컬러 썸네일이 그대로 렌더링됨). 이번엔 이 근본 원인을 고친다.

- **대상**: 본인 열람 화면(`isOwnBook=true`)의 `SlotGrid` — 타인 열람은 이미 슬롯 0개면 페이지
  자체가 안 보이므로 이 버그의 영향권 밖.
- **요구 동작**: "슬롯 완료"(컬러, 정상 표시) / "보유·미슬롯"(구분 가능한 흐림 처리, 이름·희귀도는
  유지 — 아직 뭔지 모르는 `undiscovered`(`???`, 이름 숨김)와는 달라야 함) / "미보유"(`undiscovered`,
  기존 그대로) 세 상태가 한눈에 구분되도록 한다.
- **구현 방향(참고, 강제 아님)**: `BadgeGridCard`는 이미 `earned` prop으로 "썸네일 흑백+반투명"
  처리를 지원한다(`earned=false` → `grayscale opacity-40`, 이름/희귀도는 유지 — `undiscovered`와
  달리 이름을 `???`로 바꾸지 않음). `SlotGrid.tsx`에서 `isSlottable` 배지에 `earned={false}`
  (또는 동등한 `earned={isSlotted}`)를 넘기는 정도로 기존 컴포넌트 재사용만으로 해결 가능해 보임 —
  신규 컴포넌트·신규 prop 추가는 불필요할 것으로 판단됨. 다만 최종 판단은 구현자가 코드를 보고 결정.
- **범위 밖**: 프로필 상단 통계 `itemBookCount`(인벤토리 보유 기준) 불일치는 별도 사안, 이번 범위 아님.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`user_item_book_slots`의 유저+아이템북 조합 행 개수(슬롯 개수)가 0이면 타인에게 해당
컬렉션을 노출하지 않도록 세 지점 모두에 필터/차단을 추가했다. 본인 열람 시에는 조건 없이
항상 노출되도록 `isOwnList`/`isOwnBook` 분기로 예외 처리했다.

1. `[username]/collections/page.tsx` — 대상 유저가 로그인 유저 본인이 아니면
   `slottedCount === 0`인 카드를 목록에서 제외.
2. `api/users/[username]/itembooks/route.ts` — ProfileClient의 컬렉션 탭이 호출하는 API.
   요청자(`createClient().auth.getUser()`)와 대상 유저 id를 비교해 본인이 아니면 동일하게
   `slottedCount === 0`인 항목을 필터링. (이 API는 세션 쿠키만으로 호출되고 원래
   요청자 신원을 전혀 확인하지 않았음 — 이번에 처음 추가함.)
3. `collections/[id]/page.tsx` — `isOwnBook`이 false이고 `slots.length === 0`이면
   `notFound()`. 배지가 아예 없는 컬렉션(`badges.length === 0`) 처리와는 분리된 별도 조건으로
   구현(기존 EmptyState 분기는 그대로 유지).

POI 배지 획득 여부는 조건에 포함하지 않음(슬롯 개수만 기준, 스펙대로).

## 추가 요구사항 구현 기록 *(2026-08-24, 1차 구현 게이트 PASS 후)*

`SlotGrid.tsx`에서 `BadgeGridCard`에 `earned` prop을 넘기지 않아 "보유·미슬롯"(`isSlottable`)
배지가 기본값(`earned=true`)으로 컬러 썸네일 그대로 렌더링되던 원인 버그를 고쳤다.

- `earned={isSlotted}`를 `BadgeGridCard`에 전달 — 슬롯 완료(`isSlotted=true`)만 컬러 정상 표시,
  보유·미슬롯(`isSlotted=false`, `isUndiscovered=false`)은 `BadgeGridCard` 내부 로직(`thumbDimmed`)에
  의해 썸네일 흑백(`grayscale`)+반투명(`opacity-40`) 처리되고 이름·희귀도는 그대로 유지됨.
  `undiscovered=true`(미보유)는 기존과 동일하게 이름 `???` 처리 + 썸네일 흑백.
- 컨테이너 레벨 `className`에서 `isSlottable`일 때 걸려있던 `opacity-70`(카드 전체 반투명 —
  이름·희귀도까지 흐리게 만들어 "보유·미슬롯"과 "미보유"의 구분을 오히려 흐리게 하던 원인)을
  제거. `isUndiscovered`의 `opacity-30`은 그대로 유지.
- 신규 컴포넌트·신규 prop 추가 없이 기존 `earned` prop 재사용만으로 해결 (티켓의 구현 방향 예상과 일치).
- `readOnly`(타인 열람) 분기와 무관하게 `earned={isSlotted}`를 항상 전달함 — 슬롯 개수가
  1개 이상이라 페이지 접근이 허용된 타인 열람 시에도, 보유·미슬롯 배지가 섞여 있다면 동일하게
  구분 표시되는 것이 정책 취지(원 버그를 근본에서 고침)에 부합한다고 판단.
