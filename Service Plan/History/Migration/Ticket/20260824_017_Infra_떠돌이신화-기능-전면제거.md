# [Infra] 떠돌이 신화(wandering mythic) 기능 전면 제거

## 배경 / 문제 정의

알림(소식) 기능을 설계하는 과정에서 "떠돌이 신화 아이템이 72시간 뒤 인벤토리에서 소각되는데
사전 고지가 없다"는 문제를 발견했다. 소각 예고 알림을 추가할지 검토하다가, 이 기능 자체가
**한 번도 실사용되지 않은 미완성 기능**임이 확인되어 사용자 결정으로 기능을 제거한다.

### 실사용 0건 확인 (프로덕션 DB, service_role 조회, 2026-08-24)

| 조회 | 결과 |
|---|---|
| `badges WHERE is_wandering AND deleted_at IS NULL` | 0건 |
| `wandering_mythic_state` | 0건 |
| `user_activity_badges JOIN badges WHERE is_wandering` | 0건 |
| `inventory_items JOIN badges WHERE is_wandering` | 0건 |

→ 데이터 마이그레이션 이슈 없음, 유저 영향 없음. 스키마와 Cron만 만들어두고 컨텐츠를
한 번도 붙이지 않은 상태다.

### 잔여 이슈

- **🚨 DDL 실행 순서 제약 (최우선)**: `095_remove_wandering_mythic.sql`은 **프로덕션(main)에
  코드가 배포 완료된 뒤에만** 실행한다.
  - **위반 시 무증상 장애**: 옛 코드가 도는 상태에서 `badges.is_wandering`이 사라지면
    PostgREST가 `42703`으로 HTTP 400을 반환하고 supabase-js는 `data: null`을 준다.
    `badges/page.tsx`의 `allActivityBadges ?? []`가 이를 삼키므로 **에러 하나 없이
    액티비티 배지 175건이 통째로 빈 목록**이 된다. 게이트 리뷰에서 실제 요청으로 재현 확인.
  - 올바른 순서: `staging 머지 → staging 검증 → /jam-ship으로 main 승격 →
    프로덕션 배포 완료 → 095 실행 → npm run db:types 재생성 대조(git diff 0)`
  - 이 순서 제약은 SQL 파일 상단 주석에도 동일하게 기재해 두었다.
- **DDL 미실행**: 위 순서에 따라 프로덕션 배포 전까지 실행하지 않는다. 되돌릴 수 없는 DDL이므로
  실행 직전 실사용 0건을 재확인한다(SQL 파일 상단 주석에 조회문 기재).
  → **이 항목이 남아 있어 티켓은 `IN_PROGRESS`다. DDL 실행 + 타입 재생성 대조까지 마친 뒤 CLOSED로 전환한다.**
