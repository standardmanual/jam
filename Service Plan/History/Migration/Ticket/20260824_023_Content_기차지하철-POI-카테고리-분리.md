# [Content] 기차/지하철 POI 카테고리 분리 + 산 카테고리 정합성 정리

## 배경 / 문제 정의
[[20260824_020]]에서 지하철·기차역 배지 929개에 JAM METRO 디자인을 적용했는데, 이들이 속한
`transit`(대중교통) 카테고리에는 버스정류장·출구·자전거대여소가 함께 섞여 있었다. 배지 디자인이
갈라진 만큼 카테고리도 분리한다.

또한 사용자 요구: **"산 카테고리의 POI들에는 동일한 이름의 POI 배지가 연결되어 있어야 한다."**
확인해 보니 `mountain` 853개 중 6개가 배지 미연결이었고, 그 6개는 전부 산이 아니었다
(네이버 검색이 '산' 키워드로 잘못 수집한 학원·빌라·마켓·학교·와인샵).

> **용어 정리**: POI 배지에는 자체 카테고리 컬럼이 없다. 배지의 카테고리는 연결된 POI의
> `poi.category`를 경유해 결정되는 **파생값**이다(사용자 화면 `(main)/badges/page.tsx`,
> 어드민 배지 필터 모두 동일). 따라서 "POI 배지 카테고리"를 나누는 일 = `poi_categories`를
> 나누는 일이다.

## 상세 요구사항
- `poi_categories`에 기차/지하철 카테고리 신설 + 역 929개 이동
- 자동수집 파이프라인이 앞으로 역을 새 카테고리로 넣도록 키워드 이관
- 산 카테고리를 POI = 배지 1:1로 정리
- 어드민에서 카테고리별 배지 조회가 실제로 동작할 것

## 구현 계획
1. 영향 범위 조사 (파이프라인·드랍엔진·화면·어드민·DB 제약)
2. 코드 선행 배포 (반경 정책 + 어드민 버그)
3. DB 변경 (카테고리 생성 → POI 이동 → 키워드 이관 → 산 정리)
4. 문서 갱신

## 완료 기록

### 구현 내용 요약
1. **산 카테고리 정리** — 배지 미연결 6건(전부 산이 아닌 오수집 tier 2)을 `other`로 이동.
   → `mountain`은 POI 847개 = 배지 847개로 1:1 완전 일치
2. **`train_subway`(기차/지하철) 카테고리 신설** — `pipeline_linked=true, tier=1,
   keywords=['지하철역']`. slug는 API 검증 규칙(`^[a-z][a-z0-9_]*$`)상 한글 불가,
   label은 기존 컨벤션("편의점/마트")에 맞춰 슬래시 표기
3. **역 929개 이동** — `transit AND name LIKE '%역'`. tier 1 = 역 929개 / tier 2 = 그 외 69개로
   경계가 정확히 일치함을 사전 확인
4. **키워드 이관** — `'지하철역'`은 새 카테고리로, `transit`에는 `'버스정류장'`만 남김.
   이렇게 해야 앞으로 자동 수집되는 역이 다시 대중교통으로 섞이지 않는다
5. **반경 정책 등록** — `radius-policy.ts`에 `train_subway: 50` 추가 (아래 의사결정 참고)
6. **어드민 버그 2건 수정** (아래)

### 주요 의사결정 / 핵심 메모
- **코드를 먼저 배포하고 DB를 나중에 바꿨다**: `radius-policy.ts`에 `train_subway: 50`이
  배포되기 전에 POI를 옮기면, 어드민에서 그 POI를 수정하거나 배지를 재연결하는 순간 반경이
  기본값 500m로 풀려 [[20260811_006]] 오탐 인시던트가 재발한다. Supabase는 staging·프로덕션
  공용 단일 DB라 DB 변경이 즉시 프로덕션에 반영되는 반면 코드는 배포가 필요하다 — 이 시차를
  어느 방향으로 감수할지가 작업마다 다르다([[20260824_020]]은 반대 방향으로 실패한 사례).
- **산 6건은 배지를 만들지 않고 카테고리에서 제외**: 요구사항("산 POI에는 동명 배지가 연결")을
  문자 그대로 실행하면 "산김영준국어논술전문학원 반포 직영학원" 배지가 MOUNTAIN 디자인으로
  생성된다. 사용자에게 확인 후 `other`로 이동하는 쪽을 택했다.
- **`transit` 잔여 47개는 배지를 만들지 않았다**: "강남역 신분당선"(노선별 중복),
  "길음역10번출구"(출구), "종로2가버스정류장…자전거대여소" 등이라 역 배지와 중복되거나
  배지화할 대상이 아니다.
- **키워드는 `'지하철역'`만 이관, `'기차역'`은 추가하지 않았다**: 카테고리 이름은 기차를
  포함하지만(이미 서울역·천안역 등이 '지하철역' 검색으로 수집돼 있다), `'기차역'` 키워드를
  새로 넣으면 지금까지 수집되지 않던 POI가 늘어나는 **수집 범위 확대**라 별도 판단 사항으로 남긴다.
- **어드민 필터를 조인으로 바꿨다**: 기존 방식(POI에서 배지 id를 모아 `.in()`)은 카테고리가
  900개를 넘으면 URL이 수십 KB가 된다. FK를 통한 inner join으로 DB에서 직접 필터한다.

### 잔여 이슈
- `poi_search_cache`에 남은 `category='transit'` 캐시 150행은 고아가 된다(FK 없음, 무해).
  새 카테고리는 캐시가 비어 있어 최초 조회 시 네이버 재검색이 한 차례 발생한다.
- `'기차역'` 키워드 추가 여부는 미결(위 참고).
