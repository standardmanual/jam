# [UI] 알림 종 서클 형태 통일 + 알림함 자신에도 노출

## 배경 / 문제 정의

[20260824_021](20260824_021_UI_알림함-화면-TopNav-진입점.md)로 알림함을 배포한 뒤
staging에서 확인하며 나온 UI 피드백 2건이다.

1. **종 아이콘이 우측 프로필 아이콘과 형태가 다르다.** 아바타는 36px 서클 안에 담겨 있는데
   종은 서클 없이 24px 아이콘만 떠 있어 우측 슬롯의 시각적 리듬이 깨진다.
2. **알림함(`/notifications`) 자신에는 종이 없다.** 021이 세운 "back chevron이 없는 루트
   화면에만" 규칙 때문인데, 화면마다 우측 아이콘 구성이 달라지는 게 어색하다.

## 상세 요구사항

### 1. 종을 프로필 아바타와 같은 형태로

아바타(`TopNav.tsx`의 `avatarSlot`)가 이미 쓰는 패턴을 그대로 따른다.

| 층 | 크기 |
|---|---|
| 터치영역 (`<Link>`) | 44×44 (`w-11 h-11`) |
| 서클 | 36×36 (`w-9 h-9`), `--radius-pill`, `bg-surface-elevated` |
| 아이콘 | 16×16 (`w-4 h-4`) |

### 2. 버블 앵커 재조정

`.t-badge`의 기준 박스가 24px 아이콘 → 36px 서클로 바뀐다. 원형이라 바운딩 박스의 우상단
모서리는 이미 원 바깥이므로 `-6/-8` 같은 큰 오프셋이 불필요하다. `-2/-2`로 당겨 아바타 배지처럼
테두리에 걸치게 한다. 서클에 배경색이 있어 종 글리프와 겹칠 일도 없다.

**`transitions.css`의 원본 스니펫 영역은 건드리지 않는다** — 확장 섹션의 `.jam-bell-dot`만 수정.

### 3. 노출 규칙 확장

```
기존: 루트 화면(logo || !showBack)에만
변경: 루트 화면 + 알림함(/notifications)
```

알림함에서는 링크가 제자리를 가리키지만, 우측 아이콘 구성이 화면마다 달라지지 않는 편이
낫다는 판단이다. 타인 프로필·상세 화면은 그대로 제외된다.

## 구현 계획

경미 수정(3파일·로직 무변경)이라 파이프라인 없이 직접 처리한다.

### 주요 의사결정 / 핵심 메모

- **021의 "루트 화면에만" 규칙을 깬 것이 아니라 확장했다.** 알림함은 back 모드지만 예외로
  포함한다. 규칙을 화면 목록 하드코딩으로 되돌리지 않고 `isRootScreen || isNotificationsScreen`
  두 조건의 OR로 유지해, 루트 화면이 늘어나면 여전히 자동으로 따라온다.
- **서클 배경이 부수적 이득을 준다.** 021에서 점이 종 글리프와 겹치는 문제(C-3)를 좌표 계산으로
  피했는데, 서클에 배경색이 생기면서 겹침 자체가 구조적으로 불가능해졌다.

### 3. 우측 슬롯 간격 균일화 (2026-08-25 추가)

staging 확인 결과 종 좌우 간격이 어긋나 보였다. DS TopNav 구조를 실측하니 원인이 명확했다.

```
헤더 바깥      : gap 8   ([좌측][centerSlot][우측영역])
우측 영역 안쪽 : gap 8   ([rightSlot][avatarSlot])
44px 터치박스 안의 36px 서클 → 양옆 4px 여백
```

| 구간 | 계산 | 실측 |
|---|---|---|
| 동기화 → 종 | 8(바깥 gap) + 4(종 좌 여백) | **12px** |
| 종 → 프로필 | 4(종 우 여백) + 8(안쪽 gap) + 4(아바타 좌 여백) | **16px** |

종에 `-mr-1`(-4px)을 주어 안쪽 gap을 상쇄, 양쪽 모두 12px로 맞췄다.
**DS를 고치지 않았다** — `gap: 8`은 배지 상세의 공유 버튼 등 다른 호출부에도 적용되므로
서비스 쪽에서 해결하는 편이 영향 범위가 작다.
