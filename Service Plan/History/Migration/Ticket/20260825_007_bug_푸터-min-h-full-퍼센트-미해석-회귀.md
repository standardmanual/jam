# [UI] 티켓 20260825_006 회귀 — `min-h-full`(퍼센트) 방식이 실제로는 동작하지 않음

## 배경 / 문제 정의
[20260825_006](./20260825_006_UI_푸터-화면-바깥쪽-고정-배치.md)에서 `min-h-full`(부모의 100%) 트릭으로
컨텐츠가 짧을 때 Footer를 화면 바깥으로 밀어내도록 수정해 프로덕션에 배포했으나, 실제 사용자가
프로덕션(인벤토리 빈 상태 화면)에서 확인한 결과 Footer가 여전히 탭바 바로 위(화면 안쪽)에 그대로
보였다.

### 원인 분석
`jam-web/src/app/(main)/layout.tsx`의 `main`은 `flex:1 1 0%`(Tailwind `flex-1`)로 크기가 정해지는
flex 아이템이다. flex 알고리즘이 계산한 **used height**는 뷰포트 전체(~100dvh)로 정확했지만
(`getBoundingClientRect().height`로 확인), `height` **computed value 자체는 `auto`로 남는다** —
`flex-basis: 0%`를 통해 크기가 결정되기 때문. 브라우저는 자식의 `min-height: 100%` 퍼센트를
해석할 때 부모의 "computed height property가 auto가 아닌지"를 기준으로 판단하는데, 이 케이스에서는
그 조건을 만족하지 못해 퍼센트가 해석되지 않고 `auto`로 폴백됐다(로컬 재현 스크립트로 실측 확인 —
`min-height:50%`, `100%` 모두 자식 실제 높이 51px로 변화 없음, `min-height:300px`처럼 절대값은
정상 적용됨).

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/app/(main)/layout.tsx`의 `<div className="min-h-full">{children}</div>`를
  `<div className="min-h-dvh">{children}</div>`로 교체 — 퍼센트 대신 뷰포트 절대 단위(`dvh`)를 써서
  flex-item computed-height-auto 문제 자체를 우회한다
- 로컬 재현 스크립트로 `min-height: 100dvh` 적용 시 실제 뷰포트 높이(예: innerHeight 2123 → 2122)에
  맞게 정상 확보되는 것을 실측 확인함

## 구현 계획
이미 오케스트레이터가 직접 원인 분석·재현·수정·로컬 검증까지 완료함(경미 수정 — 1파일, 클래스 하나

### 주요 의사결정 / 핵심 메모
- 20260825_006에서 채택한 `min-h-full`(부모 100%) 방식은 이론상 표준 sticky-footer 트릭이지만,
  이 프로젝트의 실제 DOM 구조(`overflow-y-auto` + `flex:1 1 0%`인 flex 아이템)에서는 브라우저가
  퍼센트를 해석하지 않는 것으로 실측 확인됐다. 앞으로 같은 구조에서 퍼센트 기반 높이 트릭을 쓸 때는
  반드시 실제 브라우저에서 `getBoundingClientRect()`로 실측 검증할 것 — 타입체크·정적 분석만으로는
  잡히지 않는 레이아웃 버그였다.
