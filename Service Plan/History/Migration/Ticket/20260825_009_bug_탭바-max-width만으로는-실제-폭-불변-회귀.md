# [UI] 티켓 20260825_008 회귀 — `max-width`만 줄여선 실제 폰에서 폭이 안 변함

## 배경 / 문제 정의
[20260825_008](./20260825_008_UI_탭바-가로폭-10px-축소.md)에서 탭바 `max-width`를 398→388px로
줄여 프로덕션에 배포했으나, 사용자가 실제 아이폰(393pt 폭 기기)에서 확인한 결과 탭바 크기가
전혀 줄지 않았다.

### 원인 분석
탭바 실제 폭은 `width: calc(100% - 32px)`와 `max-width` 중 **더 작은 값**으로 결정된다.
일반 아이폰 화면 폭(약 375~428pt)에서는 `calc(100% - 32px)` 쪽이 이미 `max-width`보다 작다
(예: 393pt 기기 → 393-32=361px, max-width 398/388px보다 항상 작음). 즉 `max-width`는 앱 컬럼
폭이 420px를 넘는 매우 넓은 화면에서만 실제로 작동하는 상한값이었고, 대다수 실기기에서는
`calc()`쪽 값이 항상 이겨서 `max-width`를 아무리 줄여도 시각적으로 아무 효과가 없었다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/components/ui/TabBar.tsx`의 `w-[calc(100%-32px)]` → `w-[calc(100%-42px)]`
  (좌우 여백을 10px 늘려 실제 폭을 10px 줄임 — `left-1/2 -translate-x-1/2`로 중앙 정렬되므로
  좌우 대칭 유지)
- `jam-web/design-system/components/navigation/TabBar.jsx`의 `width: 'calc(100% - 32px)'` →
  `'calc(100% - 42px)'`도 동일하게 수정 (병존 구현)
- `max-width` 388px는 그대로 유지 (더 넓은 화면에서의 상한 캡)

## 구현 계획
Storybook iframe을 실제 아이폰 폭(393px)으로 강제 리사이즈해 `getBoundingClientRect()`로
수정 전/후 폭을 실측 비교(361px → 351px, 정확히 -10px) 확인 후 배포.

원인(calc formula)을 고쳤다.
