# [UI] 미션 진행 상황(랭킹) 화면 디자인 리뉴얼 — 다른 화면과 통일

## 배경 / 문제 정의
미션 진행 상황(`/missions/[id]/status`, 랭킹형) 화면이 2026-08-15 Figma 리뉴얼(20260815_021/022/024) 때
그린 계열 hex(#56C985 등)와 임의 px 폰트·spacing을 그대로 이식해, 앱의 다른 화면(인벤토리·배지·미션 상세
등)이 쓰는 레드(`--color-primary`) 단일 강조색·모듈러 토큰 체계와 시각적으로 크게 어긋나 있었다.

## 상세 요구사항

### 디자인 방향 (Claude Design 캔버스로 먼저 정렬)
`/design`으로 Before/After/참고화면 3안을 캔버스로 만들어 사용자와 함께 조정했다:
1. 강조색: 그린 → 앱 전체 유일한 강조색인 `--color-primary`(레드) 하나로 통일 (1위만 강조, 2·3위는 중립톤)
2. 산출물 형태: 정적 목업으로 진행
3. 사용자가 캔버스 에디터에서 직접 레이아웃을 수정 — 포디엄 상단의 별도 순위/진행값 라벨 제거하고
   포디엄 바 안에 순위·진행값을 함께 배치, 상단 헤더 정보 바("랭킹 · 참가자 N명" / "미션: 목표") 제거,
   "전체 순위" 섹션 라벨 옆에 참가자 수 병기, 하단 "나의 순위 카드" 전체 삭제(목록 내 강조 행으로 대체)
4. 사용자가 임의로 지정한 색상값·폰트 크기를 모듈러 토큰 기준으로 정합화 요청 → 색상은
   `--color-primary`(#e8461f) 파생 rgba 틴트로, 폰트는 타이포 토큰 스케일(`--text-h3`:28,
   `--text-h4`:24, `--text-caption`:12, `--text-micro`:11, `--text-small`:14)에 맞춰 구현

### 기능 회귀 검토 — "나의 순위 카드" 삭제
`visible_rank_count`(상위 N명만 공개, 마이그레이션 046 주석: "본인은 항상 별도 표시") 설정 때문에
카드를 완전히 삭제하면 순위가 공개 목록 밖인 유저는 자기 진행상황을 볼 방법이 없어지는 회귀가
발생함을 확인 — 사용자에게 확인 후 **목록 밖일 때만 예외적으로 표시**하는 조건부 렌더링으로 절충.

### 서비스/코드베이스 관점
- `jam-web/src/app/(main)/missions/[id]/status/MissionStatusClient.tsx`
  - `PODIUM_CONFIG`: 그린 hex 전부 제거, 레드 그라디언트(`rgba(232,70,31,…)`)+토큰 폰트 크기로 교체
  - `PodiumColumn`: 아바타 위/아래 별도 순위·진행값 라벨 제거, 바 하단에 순위+진행값 함께 배치
  - `RankingListRow`: `getRankGradient()`(그린 그라디언트 함수) 제거, 진행바를 `var(--color-primary)`
    단색으로 통일, 내 순위 행만 `var(--text-h4)`(24px)로 확대
  - `MyRankCard`: 그린 하드코딩 → 레드 틴트(`rgba(232,70,31,0.12)`, `MissionDetailClient`의
    "참가중" 칩과 동일 어휘)로 교체, 목록 밖(`meOutsideList`)일 때만 렌더링
  - 랭킹 타입 렌더 블록: 상단 헤더 정보 바 삭제, 포디엄·전체 순위 목록을 `bg-surface-elevated
    rounded-[var(--radius-cards)] p-6`(다른 화면의 InfoCard와 동일 클래스)로 카드화, "전체 순위"
    라벨 옆에 참가자 수 병기
  - `goalLabel` prop 및 관련 i18n 키(`statusRankingLabel`, `statusMissionGoal`) 제거 — 상단 헤더
    바와 함께 쓰임이 사라져 미사용 코드가 됨
- `jam-web/src/app/(main)/missions/[id]/status/page.tsx`: `extractGoalLabel` 함수·`mission_type`/
  `condition_json` 조회·`goalLabel` prop 전달 제거

## 구현 계획
1. `/design` 캔버스로 방향 합의 (완료)
2. 사용자가 캔버스에서 직접 레이아웃 수정 → 그 결과를 스펙으로 삼아 실제 코드 반영
3. 색상·폰트를 모듈러 토큰 기준으로 정합화하며 구현
4. `visible_rank_count` 회귀 여부 확인 → 조건부 렌더링으로 절충 (사용자 승인)
5. 로컬 dev 서버 + `dev-login`으로 실제 DB 데이터(참가자 3명/6명 미션) 브라우저 검증

### 주요 의사결정 / 핵심 메모
- Claude Design 캔버스(`/design`)로 Before/After/참고화면을 나란히 만들어 방향을 먼저 합의한 뒤
  구현했다 — 사용자가 캔버스에서 직접 레이아웃을 수정한 결과를 최종 스펙으로 삼았다.
- 캔버스 목업의 임의 색상·폰트 값은 전부 모듈러 토큰(색상: `--color-primary` 파생 rgba, 폰트:
  타이포 스케일)으로 정합화해서 구현했다 — 목업 그대로의 하드코딩 값을 복사하지 않았다.
- "나의 순위 카드" 완전 삭제는 `visible_rank_count`("본인은 항상 별도 표시") 스펙과 충돌해
  기능 회귀가 될 뻔했다 — 목록 밖일 때만 표시하는 절충안으로 사용자 승인 후 결정.
- 1파일 경미 수정 기준을 넘는 실질적 UI 변경이지만, 이미 사용자와 매 결정을 직접 조율하며 진행했고
  실 데이터 브라우저 검증까지 마쳐 별도 게이트 리뷰 파이프라인 없이 오케스트레이터가 직접 구현했다.

### 잔여 이슈
- `visible_rank_count` 밖 유저의 카드 노출 케이스, 프로덕션 실데이터로 재확인 권장
