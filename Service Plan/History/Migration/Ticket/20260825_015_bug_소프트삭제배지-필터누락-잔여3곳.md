# [bug] 소프트 삭제 배지 필터 누락 — 잔여 3개 지점 (오늘 카드 추천/노출, 프로필 통계)

> 티켓 20260824_009 완료 기록 "잔여 이슈"에서 후속 작업으로 분리된 3곳 중 표시(노출) 문제
> 3곳. 004→005, 007→009로 이어진 "이게 전부다"가 매번 틀렸던 동일 패턴.
> (정책 판단이 필요한 `lib/missions/rewards.ts:42`는 이 티켓 범위 밖 — 별도 판단 필요)

## 배경 / 문제 정의

`badges` 테이블 조회 시 `deleted_at IS NULL` 필터가 누락되면 소프트 삭제된 배지가
계속 화면/로직에 노출되거나 카운트에 포함된다. 007이 6곳, 009가 7곳을 고쳤지만
전수 grep 결과 아래 3곳이 여전히 남아 있음이 확인됐다.

## 상세 요구사항

### 서비스/코드베이스 관점

| # | 지점 | 문제 | 조치 |
|---|---|---|---|
| 1 | `jam-web/src/lib/today/exposure.ts:121-125` | "오늘" 카드 추천 로직에서 아이템북 미완성 여부를 판정할 때, 북의 "전체 아이템 배지 수"(분모)를 세는 `badges` 쿼리에 필터 없음 → 삭제된 배지가 분모에 남아 이미 완성한 북을 "미완성"으로 오판, 불필요한 추천 카드 노출 가능 | `.is('deleted_at', null)` 추가 |
| 2 | `jam-web/src/lib/today/cards.ts:115-118` (`fetchBadgesById`) | "오늘" 피드 카드에 표시되는 배지 이름/이미지/희귀도를 조회하는 쿼리에 필터 없음 → 삭제된 배지가 이름·이미지·희귀도 그대로 사용자 화면에 노출 (체감도 가장 높은 지점) | `.is('deleted_at', null)` 추가 |
| 3 | `jam-web/src/app/(main)/[username]/page.tsx:99-104` (`booksForCount`) | 프로필 통계 "발견한 아이템북 수"를 게이팅하는 쿼리(보유 배지 → 아이템북 id 매핑)에 필터 없음 → 삭제된 배지도 아이템북 발견으로 카운트되어 실제보다 과대 표시 가능 | `.is('deleted_at', null)` 추가 |

이번 수정으로 다시 일치시켜야 한다 (안 그러면 009 이전처럼 숫자·목록 불일치 재발).
