# [Admin] 어드민 배지 조회 쿼리 소프트 삭제 필터 일괄 점검

## 배경 / 문제 정의
> 티켓 20260825_016(미션 보상 지급 시 소프트 삭제 배지 스킵) 게이트 리뷰에서 발견된 범위 밖
> 이슈. 20260825_019에서 `admin/missions/page.tsx`는 이미 수정 완료했으나, 같은 게이트
> 리뷰어가 동일 패턴이 남아있는 다른 어드민 화면들을 지목했다 (19번 티켓 "잔여 이슈" 참고).
> 지급 시점 로직은 이미 `deleted_at IS NULL`로 걸러지므로 실제 오지급은 없지만, 어드민이
> 배지 선택/후보 목록에서 이미 삭제된 배지를 계속 보게 되면 "선택했는데 반영이 안 된다"는
> 혼란을 겪을 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
아래 5개 파일의 `badges` 테이블 조회 쿼리를 점검하고, "선택 목록/후보 노출용" 조회에
`.is('deleted_at', null)` 필터를 추가한다.

- `jam-web/src/app/admin/today/page.tsx`
- `jam-web/src/app/admin/poi/page.tsx`
- `jam-web/src/app/admin/poi/[id]/page.tsx`
- `jam-web/src/app/admin/factions/page.tsx`
- `jam-web/src/app/admin/badges/[id]/edit/page.tsx`

**주의**: `admin/badges/[id]/edit/page.tsx`처럼 "이미 삭제된 배지 자체를 편집/조회"하는
용도의 쿼리(상세 조회)는 필터를 걸면 안 된다 — 삭제된 배지를 어드민이 열람/복구하는 흐름을
막게 되므로 문맥을 구분해서 판단한다.

## 구현 계획
1. 5개 파일 각각에서 `badges` 조회 쿼리의 용도(선택 목록용 vs 단건 상세 조회용)를 확인
2. 선택 목록/후보 노출용 쿼리에만 `.is('deleted_at', null)` 추가 (19번 티켓과 동일 패턴)
3. 타입체크로 회귀 여부 확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
5개 대상 파일의 `badges` 조회 쿼리를 점검해 "선택 목록/집계용" 조회 2건에만
`.is('deleted_at', null)`을 추가했다. 나머지 3건은 이미 확정된 단건(연결된 배지 이름 표시,
편집 대상 상세 조회)을 조회하는 용도라 필터를 걸면 안 되는 케이스로 판단해 그대로 두었다.

- `admin/today/page.tsx`: 투데이 카드 CMS에서 노출/보상 배지를 고르는 선택 목록 → 필터 추가
- `admin/factions/page.tsx`: 세계관별 "배지 수" 집계(카운트) → 필터 추가 (삭제된 배지가
  카운트에 섞이면 실제보다 부풀려진 수치를 어드민이 보게 됨)
- `admin/poi/page.tsx`: POI 목록에서 이미 연결된 `linked_badge_id`의 이름을 표시하는 용도
  (선택 목록 아님, 이미 확정된 연결의 라벨 조회) → 필터 미적용
- `admin/poi/[id]/page.tsx`: 동일하게 해당 POI에 이미 연결된 배지 1건의 이름을 표시하는
  단건 조회 → 필터 미적용 (필터를 걸면 이미 연결된 배지가 삭제됐을 때 이름이 사라져 오히려
  혼란 가중)
- `admin/badges/[id]/edit/page.tsx`: 편집 대상 배지 자체의 단건 조회(`.eq('id', id).single()`)
  → 필터 미적용 (티켓에 명시된 예외 케이스, 삭제된 배지도 열람/복구할 수 있어야 함)

참고: 실제 배지 선택 콤보박스(POI/미션 폼 등)는 `/api/admin/badges/search` API를 통해
동적으로 검색하는 구조(`BadgeSearchSelect` 컴포넌트)라 이번 5개 파일에서 직접 select
드롭다운으로 전체 배지를 나열하는 케이스는 없었다.
