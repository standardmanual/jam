# [BadgeEngine] 아이템북 완성 판정 분모에 삭제 배지도 계속 포함 (완성 기준 고정)

> 20260825_022(research) 조사 결과 후속. 사용자 승인(2026-08-25) — 방향 (a) 채택:
> "분모 유지: 완성 기준 불변, 단 미보유 유저는 영구 완성 불가"를 감수한다.

## 배경 / 문제 정의

022 조사에서 확인된 두 가지 문제:

1. **정책 문제**: `checker.ts`·`completable.ts`가 북 소속 배지 수(분모)를
   `.is('deleted_at', null)`로 필터링해 계산한다. 북 소속 배지가 나중에
   소프트 삭제되면 분모가 줄어들어 "완성 기준선"이 관리자의 삭제 행위에
   따라 흔들린다.
2. **버그**: `checker.ts`는 분모(`badgeCountByBook`, 삭제 필터 적용)와 분자
   (`slotCountByBook`, `user_item_book_slots` raw row count, 삭제 여부 무관)를
   서로 다른 배지 집합 기준으로 계산한다. 북 소속 배지 중 유저가 이미
   보유한 배지가 삭제되면, 분모만 줄고 분자는 그대로라 **미완성 상태인데
   완성으로 오판정 + 보상 배지 오지급**이 발생할 수 있다.

**결정된 방향 (a)**: 분모는 삭제 여부와 무관하게 북에 소속된 배지 전체를
그대로 카운트한다. 완성 기준선은 관리자의 배지 삭제와 무관하게 불변으로
유지되며, 그 결과 삭제된 배지를 아직 갖지 못한 유저는 해당 북을 완성할
방법이 없어진다(신규 발급이 막힌 배지이므로) — 이는 이번 결정으로 감수하는
트레이드오프다. 이 방향을 택하면 분자·분모가 같은 "북 소속 배지 전체"
집합을 기준으로 하게 되어 위 버그도 함께 해소된다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `jam-web/src/lib/itembook/checker.ts` (52~59행): 북별 전체 소속 배지 수
  (`badgeCountByBook`) 조회에서 `.is('deleted_at', null)` 필터를 제거한다.
  `type IN ('item','poi')` 필터는 유지.
- `jam-web/src/lib/itembook/completable.ts` (45~56행): 동일하게
  `badgeIdsByBook`(및 `poiBadgeIds`) 조회에서 `.is('deleted_at', null)`
  필터를 제거한다.
- **회귀 확인**: 삭제 이력이 없는 일반적인 북(대다수)은 필터를 제거해도
  결과가 기존과 100% 동일해야 한다 — 차이는 오직 "소속 배지가 삭제된 북"
  케이스뿐.
- **분자·분모 일관성 재확인**: 필터 제거 후에도 `slotCountByBook`(분자)이
  여전히 `badgeCountByBook`(분모)과 같은 배지 집합(북 소속 배지 전체, 삭제
  포함)을 기준으로 하는지 코드 리뷰로 확인한다. (raw row count 방식은
  그대로 두되, 두 집합이 이제 일치하므로 022에서 지적한 왜곡 시나리오가
  재현되지 않는지 시나리오로 검증)
- 삭제된 배지가 북에 남아있는 상태에서 그 배지를 **아무도 갖지 못한 북은
  완성 불가 상태로 영구 고정**된다 — 의도된 동작이므로 별도 처리(경고 로그
  등) 없이 그대로 둔다. 필요 시 어드민에서 "이 북은 삭제된 배지 때문에
  완성 불가 상태" 같은 안내가 있으면 좋지만, 이번 티켓 범위 밖(운영 편의는
  후속 과제로 남김).

### 문서 관점

- `Service Plan/Specs/BadgeEngine/BADGE_ENGINE_UNIFIED.md`에 이 정책을
  명문화한다: "아이템북 완성 판정의 분모(북 소속 배지 수)는 배지의 소프트
  삭제 여부와 무관하게 고정된다 — 완성 기준선은 불변이며, 삭제된 배지를
  갖지 못한 유저는 해당 북을 완성할 수 없다." (020/021의 "이력 유지" 원칙과
  구분되는 별도 정책임을 명시 — 020/021은 유저 개별 이력 보존, 이번 건은
  완성 기준선 고정)

## 구현 계획

1. `checker.ts` 52~59행에서 `.is('deleted_at', null)` 제거
2. `completable.ts` 45~56행에서 `.is('deleted_at', null)` 제거
3. 022에서 제시한 왜곡 시나리오(북 소속 배지 A~J 중 유저가 A~I 보유, A가
   나중에 삭제)를 코드 추적으로 재검증 — 이제 분모=10(고정) 유지, 분자=9
   유지로 `9 < 10` 미완성 유지되는지 확인
4. `BADGE_ENGINE_UNIFIED.md`에 정책 명문화
5. 회귀 확인: 삭제 이력 없는 북 다수 케이스에서 기존과 동일 결과인지 확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`checker.ts`(`badgeCountByBook`)와 `completable.ts`(`badgeIdsByBook`/`poiBadgeIds`)의 북 소속 배지
조회에서 `.is('deleted_at', null)` 필터를 제거했다. 이제 두 파일 모두 `item_book_id` in +
`type in ('item','poi')`만으로 북 소속 배지 전체를 집계하며, 삭제 여부와 무관하게 완성 기준선(분모)이
고정된다. `checker.ts`의 분자(`slotCountByBook`, raw row count)는 원래 삭제 여부를 보지 않았으므로,
이번 변경으로 분자·분모가 "북 소속 배지 전체(삭제 포함)"라는 동일 집합을 기준으로 계산되게 되어
022에서 지적된 왜곡 시나리오(북 소속 배지 A~J 중 유저 A~I 보유, A 삭제 → 분모=9로 축소되며 완성 오판정)도
함께 해소됐다. 필터 제거 후에도 분모=10(고정), 분자=9(A~I) 유지로 `9 < 10` 미완성이 정상 유지됨을
코드 추적으로 확인. 삭제 이력이 없는 일반 북(대다수)은 필터 유무와 무관하게 결과가 기존과 동일하다
(필터가 걸러내던 대상 자체가 없었으므로). `BADGE_ENGINE_UNIFIED.md`에 §3.16으로 정책을 명문화하고,
20260823_004(유저 이력 유지) 원칙과 이번 건(완성 기준선 고정)이 서로 다른 정책임을 명시했다.
