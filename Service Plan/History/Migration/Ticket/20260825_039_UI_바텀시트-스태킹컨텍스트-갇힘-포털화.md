# [UI] 바텀시트가 `relative z-10` 스태킹 컨텍스트에 갇혀 탭바·페이지 콘텐츠에 가려지는 문제

## 배경 / 문제 정의

POI 배지 상세 화면에서 과거 획득 이력(2번째 이후 항목)을 눌러 바텀시트를 열면 아래 4가지가
동시에 발생한다 (사용자 제보 영상·스크린샷 기준).

1. 바텀시트 위로 **플로팅 탭바가 그려져** 시트 내용을 가린다
2. 시트가 **투명해 보이고** 뒤 페이지 텍스트(배지 설명·Footer 문구)가 겹쳐 보인다
3. 백드롭 블러가 **화면 일부에만** 적용되어, 배경 스크롤에 따라 블러/비블러 영역이 갈려 보인다

### 근본 원인 (단일)

세 증상은 서로 다른 버그가 아니라 **하나의 원인**에서 파생된다.

`BottomSheet`의 루트는 `fixed inset-0 z-50`이지만, 호출부인 `PoiEarnHistory`가
`badges/[id]/page.tsx`의 `<div className="relative z-10 …">`(info-section) 안에 있다.
`position: relative` + `z-index: 10`은 **스태킹 컨텍스트를 만든다.**

- 그 안의 `z-50`은 컨텍스트 **내부** 순서일 뿐이고, 컨텍스트 전체는 루트에서 `z-index: 10`으로 취급된다
- 플로팅 탭바(`TabBar.tsx`, `z-40`)는 스태킹 컨텍스트를 만들지 않는 `relative` 조상 아래라
  **루트 컨텍스트에서 z-40**으로 참여한다 → `10 < 40`이므로 **탭바가 시트 위에 그려진다** (증상 1)
- 같은 이유로 시트보다 **DOM 뒤에 오는 `relative z-10` 섹션**(action-section, 배지 설명, Footer)이
  시트 위에 페인트된다 → 시트가 투명해 보이는 착시 (증상 2)
- 백드롭의 `backdrop-filter: blur()`는 **자기보다 뒤에 페인트된 것만** 블러 처리한다. 위에 얹히는
  섹션들은 블러 대상이 아니므로 화면이 블러/비블러로 갈린다 (증상 3)

> 참고: `position: fixed` 자체는 `relative` 조상에 포획되지 않으므로 시트의 **위치**는 정상이다.
> 깨지는 것은 **페인트 순서(z-order)** 뿐이다.

### 영향 범위

`BottomSheet`를 쓰는 모든 호출부가 잠재적으로 같은 문제를 갖는다. `badges/[id]/page.tsx`는
변형 3종 모두 `relative z-10` 섹션을 쓰므로 `PoiEarnHistory`·`ItemEarnHistory` 둘 다 해당된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `src/components/ui/BottomSheet.tsx`가 **`createPortal`로 `document.body`에 렌더**되도록 수정한다.
  포털은 조상 스태킹 컨텍스트를 벗어나므로 `z-50`이 루트 기준으로 평가되어 탭바(z-40) 위에 온다.
- SSR 안전성: `document`는 클라이언트에서만 존재하므로 마운트 이후에만 포털을 생성한다.
- 기존 동작 회귀 금지 — 드래그-투-클로즈, `detent`/`topGapPx`/`footer`/`footerBottomInset`,
  `contentScrollable`, panel reveal 트랜지션, 배경(`main`) 스크롤 잠금이 그대로 동작해야 한다.
- 시트 루트의 `maxWidth: 430, margin: '0 auto'`(앱 셸 폭)는 포털 이후에도 유지한다.

### UI/UX 관점
- 통상적인 모달 UX 기준: 시트가 열려 있는 동안 **탭바는 시트에 가려지거나 숨겨져야 하며**,
  뒤 페이지 콘텐츠가 시트 위로 새어 나오면 안 된다.
- 백드롭 블러는 시트 뒤 영역 **전체**에 균일하게 적용되어야 한다.

## 구현 계획

1. `BottomSheet.tsx`에 mounted 게이트(`useEffect`로 `setMounted(true)`)를 추가
2. 기존 반환 JSX를 그대로 두고 `createPortal(<루트 …>, document.body)`로 감싼다
3. 배지 상세 화면(POI·아이템·일반) 3종에서 시트 열기/닫기·드래그·스크롤 회귀 확인
4. 다른 호출부(`drops/BadgeDetailSheet`, `inventory/[itemId]/InventoryItemHistorySheet`,
   `badges/[id]/BadgeShareButton`, `PoiCarouselModal`) 회귀 확인

### 검토했으나 택하지 않은 대안
- **호출부의 `relative z-10` 제거**: 그 z-10은 배지 배경 레이어보다 섹션을 앞세우려는 의도적
  장치라(page.tsx:303 주석) 제거하면 배경 레이어 회귀가 난다. 또 호출부마다 반복될 문제라
  근본 해결이 아니다.
- **탭바 z-index 낮추기**: 시트 외 다른 오버레이와의 관계가 깨지고, 같은 문제가 다른
  스태킹 컨텍스트에서 재발한다.
- **`pushTabBarHidden`으로 탭바 숨기기**: 증상 1만 없애고 증상 2·3(페이지 콘텐츠가 시트 위로
  올라오는 문제)은 그대로 남는다. 근본 원인을 덮는 대증요법.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`src/components/ui/BottomSheet.tsx`의 반환 JSX를 `createPortal(…, document.body)`로 감쌌다.
포털된 노드는 조상 스태킹 컨텍스트(`relative z-10` info-section)를 벗어나므로 루트의 `z-50`이
루트 스태킹 컨텍스트 기준으로 평가되고, 탭바(z-40)와 뒤 페이지 섹션들(z-10) 위에 페인트된다.
세 증상(탭바가 시트를 가림 / 시트가 투명해 보임 / 블러가 화면 일부에만 적용)이 한 번에 해소된다.

SSR 안전성은 `useSyncExternalStore(subscribeNoop, () => true, () => false)` 마운트 게이트로 처리했다.
서버 렌더·하이드레이션 렌더에서는 `false`를 돌려줘 아무것도 렌더하지 않고, 하이드레이션 이후에만
포털을 만든다. 계획서에는 `useEffect`+`setMounted(true)`로 적혀 있었으나, 이 저장소의 eslint
설정(`react-hooks/set-state-in-effect`)이 effect 안의 동기 setState를 error로 잡아 새 린트 오류가
생겼다. 동작이 동일하고 저장소에 이미 같은 관용구가 있는(`src/lib/uiOverlay.ts`)
`useSyncExternalStore`로 대체했다.

그 외 로직(드래그-투-클로즈, detent/topGapPx/footer/footerBottomInset/contentScrollable,
panel reveal 트랜지션, `main` 스크롤 잠금, `maxWidth: 430 + margin: 0 auto`)은 손대지 않았다.

### 주요 의사결정 / 핵심 메모
- 포털 이후에도 루트는 `fixed inset-0` + `maxWidth: 430` + `margin: 0 auto`라 앱 셸(430px 중앙 정렬)과
  동일한 폭·위치를 유지한다. body는 `min-h-full flex flex-col`이지만 포털 루트가 `position: fixed`라
  플로우에서 빠져 flex 레이아웃에 영향을 주지 않는다.
- 디자인 토큰(`--color-surface` 등)은 모두 `:root`에 선언되어 있어 body 직속으로 옮겨도 스타일이
  그대로 상속된다.
- React 포털은 DOM 위치만 바뀌고 React 트리상의 이벤트 버블링은 유지되므로, 호출부의 이벤트
  핸들러 동작은 변하지 않는다.
