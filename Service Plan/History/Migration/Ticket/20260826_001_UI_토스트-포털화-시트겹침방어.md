# [UI] 토스트 컨테이너 포털화 + footer 시트와의 겹침 방어

## 배경 / 문제 정의

티켓 20260825_039에서 `BottomSheet`를 `createPortal`로 `document.body`에 렌더하도록 바꾸고,
그 부작용으로 토스트가 시트 뒤에 숨는 회귀가 생겨 토스트 컨테이너를 `z-50` → `z-[60]`으로 올렸다.
인터랙션 리뷰에서 후속 과제 2건이 확인됐다.

### 과제 1 — `z-[60]`이 주석에만 존재하는 불변식에 의존한다

현재 토스트의 `z-[60]` 정합성은 **"앱 셸 `div`가 `z-index: auto`라 스태킹 컨텍스트를 만들지
않는다"**는 불변식에 기대고 있고, 그 불변식은 `Toast.tsx`의 주석에만 있다.
`src/app/(main)/layout.tsx:47`의 셸에 누구든 `transform`·`filter`·`isolation`·`z-*`를 하나
붙이면 **20260825_039와 완전히 같은 종류의 버그가 조용히 재발한다.**

### 과제 2 — footer 있는 시트와 토스트가 기하학적으로 겹친다 (잠복)

`Toast.tsx:46`의 `ToastRow`에는 `pointer-events-auto`와 `onClick={onDismiss}`가 있다.
컨테이너만 `pointer-events-none`이고 **토스트 사각형 자체는 포인터를 먹는다** — 그 영역을 탭하면
토스트만 닫히고 아래 버튼은 눌리지 않는다.

`footerBottomInset='tabbar'`(기본값) 기준 실측:

| | 화면 하단 기준 위치 |
|---|---|
| 토스트 (`bottom` + `py-3` + body-sm ≈ 44px) | `safe + 88px` ~ `safe + 132px` |
| 시트 footer 버튼 (safe + 16 + 64 + 12) | `safe + 92px` ~ `safe + 140px` |

거의 완전히 포개진다.

> ~~단, 2026-08-26 기준 실제로 터지지는 않는다. `footer`를 쓰는 유일한 호출부인
> `badges/[id]/BadgeShareButton.tsx`가 `footerBottomInset="safe-area"`를 쓰고 토스트를
> 사용하지 않으므로 잠복 위험이다.~~
>
> **⚠️ 정정 (2026-08-26, 1차 구현 중 발견) — 잠복이 아니라 이미 발생 중이던 버그였다.**
> 위 판단은 `footer` **prop 사용처만** 조사해서 나온 오판이다.
> `src/app/(main)/drops/BadgeDetailSheet.tsx:47`은 `footer` prop을 쓰지 않고 스크롤 영역에 직접
> `paddingBottom: calc(env(safe-area-inset-bottom) + 16px + 64px + 12px)`를 줘서
> 픽업/취소 버튼을 **`footerBottomInset='tabbar'`와 완전히 동일한 위치(`safe+92~140px`)**에 놓는다.
> 픽업 실패 토스트(`safe+88~132px`)와 거의 완전히 포개져, 토스트가 떠 있는 3초 동안
> 그 영역 탭이 버튼 대신 **토스트 디스미스로 먹히고 있었다.**
>
> 교훈: 겹침 조사는 `footer` prop이 아니라 **화면 하단을 실제로 점유하는 좌표** 기준으로 해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `src/components/ui/Toast.tsx`의 토스트 컨테이너를 `createPortal(document.body)`로 렌더한다.
  `BottomSheet.tsx`에 이미 도입한 `useSyncExternalStore` 마운트 게이트 패턴을 그대로 쓴다
  (이 저장소 eslint의 `react-hooks/set-state-in-effect`가 effect 내 동기 setState를 error로 잡으므로
  `useEffect`+`setMounted` 방식은 쓰지 말 것).
- 포털은 `document.body` **맨 뒤**에 붙는다 — `BottomSheet`도 같은 곳에 포털되므로
  **두 포털의 DOM 순서에 의존하지 말고 z 값으로 서열이 확실히 정해지는지** 검증한다.
- `ToastProvider`의 컨텍스트 제공(`{children}`)은 그대로 두고 **컨테이너만** 포털한다.

### UI/UX 관점 — 겹침 방어 (2차 재작업으로 방향 확정)

**채택: 하단 앵커를 유지하고, 시트가 자기 하단 점유 높이를 신고해 토스트를 그만큼 올린다.**

```ts
// uiOverlay.ts — 오버레이가 자기 값을 신고
export function pushBottomOverlay(reservedBottomPx: number): () => void
// Toast.tsx — 매직 넘버 없이 신고값만 사용
bottom: `calc(env(safe-area-inset-bottom) + ${Math.max(88, reserved + 8)}px)`
```

의존 방향이 **시트 → 토스트**라 `Toast.tsx`에 footer 높이 매직 넘버가 생기지 않는다.
`BadgeDetailSheet`는 이미 같은 값을 자기 파일에서 계산 중이므로 그대로 넘기면 되고,
진실의 원천이 한 곳에 남는다.

#### 🔒 원칙 — 점유 높이는 "추정"하지 말고 "실측"한다

이 티켓에서 기하값을 **코드에서 추정했다가 틀린 사고가 세 번** 났다:

| # | 추정 | 실제 | 결과 |
|---|---|---|---|
| 1 | "`footer` prop 사용처가 없으니 잠복 위험" | `BadgeDetailSheet`가 prop 없이 같은 좌표 점유 | 이미 발생 중인 버그를 잠복으로 오판 |
| 2 | 상단 앵커 `56px` = "TopNav 아래" | `/drops`에는 TopNav 자체가 없음 | 근거 없는 값 + 로딩 필과 중복 |
| 3 | 버튼 높이 = `min-h-11`(44px) | `py-[14px]`×2 + `16px`×`1.5` = **52px** | 신고값 8px 부족, 간격 0px로 소진 |

반면 `BottomSheet`가 footer에 쓴 **실측(`offsetHeight`)** 방식은 리뷰를 문제없이 통과했다.

**따라서 하단 점유 높이는 상수를 곱하거나 `min-h-*`로 추정하지 말고, 실제 DOM 박스를 실측해
신고한다.** `BadgeDetailSheet`의 버튼 행도 예외가 아니다 — 라벨이 길어져 두 줄이 되거나
`Button`의 패딩·타이포 토큰이 바뀌어도 자동으로 따라가야 한다.

> 진입/퇴장 트랜지션 중에는 토스트가 최종 위치보다 `--toast-distance`(16px)만큼 아래에 그려진다.
> 간격(`+8px`)이 그보다 작으면 애니메이션 250~300ms 동안 버튼 상단을 덮으므로,
> **간격은 `--toast-distance` 이상**으로 잡는다.

#### ❌ 상단 앵커 전환 방식은 배제한다 (1차 구현에서 시도했다가 반려)

1차에서 "오버레이가 뜨면 토스트를 TopNav 아래 상단 앵커로 옮기는" 방식을 구현했으나
게이트 WARN + 인터랙션 리뷰에서 아래가 확인돼 폐기한다:

- **버그가 화면 반대편으로 이사할 뿐이다.** `full` 디텐트 시트(`BadgeDetailSheet`)의 자체
  뒤로가기 버튼(`min-h-11`)을 상단 토스트가 부분적으로 덮고, `pointer-events-auto`라
  그 띠를 누르면 뒤로가기 대신 토스트가 닫힌다.
- **`56px`(= "TopNav 아래")의 근거가 그 화면에 없다.** 상단 앵커가 쓰이는 유일한 경로인
  `/drops`는 **TopNav를 렌더하지 않는다**(grep 0건).
- **같은 모양이 두 개 쌓인다.** 그 자리엔 `DropsClient.tsx:245`의 탐색 중 로딩 필이 있는데
  `bg-surface-inverse` + 라운드 + 중앙정렬로 토스트와 외형이 사실상 동일하다.
- **같은 사건이 화면 양 끝에서 보고된다.** 동일한 픽업 실패가 시트에서는 상단, 캐러셀
  카드에서는 하단에 뜬다 — 같은 문구·같은 원인인데 위치가 달라진다.
- 상·하단 동시 존재라는 **새 상태**가 생기고, "토스트 먼저 → 시트 열림" 역방향 케이스도
  방어되지 않는다.

#### 함께 해결되는 것
위 방식을 쓰면 앵커 분기·이중 컨테이너·모션 방향 반전·상단 오프셋 근거 문제·시트 경계
걸침·역방향 케이스가 **한꺼번에** 사라지고, 토스트는 계속 "행동이 일어난 곳 근처에서
위로 올라온다"는 의미를 유지한다.

#### 부수 검토 (보류 가능)
토스트 위치의 `88px`은 **플로팅 탭바 높이에 맞춘 값**이라 `pushTabBarHidden`으로 탭바를
숨기는 화면에서는 근거 없는 여백이 된다. 다만 현재 `pushTabBarHidden` 사용처
(`BadgeShareButton`, `BadgeRevealOverlay`) 중 토스트를 쓰는 곳이 없어 실효가 0이므로
이번 범위에서는 보류해도 된다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**과제 1 — 포털화**
`ToastProvider`의 토스트 컨테이너를 `createPortal(document.body)`로 렌더한다. 마운트 게이트는
`BottomSheet.tsx`가 쓰는 `useSyncExternalStore(subscribeNoop, () => true, () => false)` 패턴을
그대로 재사용했다(`useEffect`+`setMounted`는 `react-hooks/set-state-in-effect`에 걸림).
`ToastContext.Provider`와 `{children}`은 그대로 두고 컨테이너만 포털한다.

이제 토스트와 `BottomSheet`가 **둘 다 `document.body` 직속 = 같은 루트 스태킹 컨텍스트**에 있으므로
DOM 순서와 무관하게 z 값만으로 서열이 확정된다(토스트 60 > 시트 50). `NavigationLoader`도
`src/app/layout.tsx:48`에서 `<body>` 직속으로 렌더되므로 `z-[9999]`가 그대로 최상위를 유지한다.
"앱 셸 `div`가 `z-index: auto`"라는 주석-only 불변식 의존이 제거됐다.

**과제 2 — 겹침 방어: 하단 앵커 유지 + 오버레이가 자기 점유 높이를 신고(2차 재작업)**

의존 방향을 **오버레이 → 토스트**로 두어, 토스트 쪽에는 footer 높이 매직 넘버가 생기지 않게 했다.

- `src/lib/uiOverlay.ts`에 하단 점유 높이 스토어를 둔다.
  - `pushBottomOverlay(reservedBottomPx)` — `env(safe-area-inset-bottom)` **위로** 점유하는
    높이(px)를 신고하고, 반환된 해제 함수로 등록을 해제한다.
  - 여러 오버레이가 겹칠 수 있으므로 카운터가 아니라 **항목 목록**으로 관리하고 그 중 **최대값**을
    노출한다. 음수·NaN은 0으로 클램프하고, 해제 함수는 id 기준이라 여러 번 호출해도 멱등하다.
  - `useBottomOverlayReserved()`(구독) / `getBottomOverlayReserved()`(테스트·비훅용 getter).
  - 개발 모드 한정으로 등록 항목이 8건을 넘으면 `console.warn` — 해제 누수 시 "모든 토스트가
    영구히 밀려 올라간" 상태로 조용히 망가지기 때문.
- `Toast.tsx`는 컨테이너 하나(하단 앵커)만 남기고 위치를
  `calc(env(safe-area-inset-bottom) + max(88, reserved + --toast-distance)px)`로 계산한다.
  간격을 별도 상수(8px)로 두지 않고 `--toast-distance`(globals.css, 16px)를 읽어 쓴다(3차) —
  진입/퇴장 트랜지션 동안 `.t-toast`는 최종 위치보다 그만큼 **아래**에 그려지므로, 간격이 그보다
  작으면 애니메이션 250~350ms 동안 아래 버튼을 덮고 그 사각형이 `pointer-events-auto`라
  탭이 가로채진다. 값 읽기는 `cssDurationMs`와 같은 자리(`lib/motion.ts`)에 `cssLengthPx`로 뒀다.
- `BottomSheet.tsx`는 `footer`가 있을 때 footer 박스의 **실측 높이**(`offsetHeight`에서 resolve된
  `padding-bottom`의 safe-area 몫을 뺀 값)를 신고한다. footer는 임의의 `ReactNode`라 컨텐츠 높이를
  코드에서 알 수 없어 계산이 아니라 실측을 쓴다. `open`이 아니라 `lingering` 기준이라 닫힘
  트랜지션 350ms 동안에도 유지된다. footer가 없는 시트는 하단에 눌러야 할 것이 없어 신고하지 않는다.
- `drops/BadgeDetailSheet.tsx`는 `footer` prop을 쓰지 않고 스크롤 영역 맨 아래에 직접 픽업/취소
  버튼을 놓으므로 **자기 값**을 직접 신고한다. 3차에서 이 값을 상수 계산(`16+64+12` + 버튼 높이
  `min-h-11`=44 → 136px, 실제보다 8px 부족)에서 **실측**으로 바꿨다:
  - `(a) content.offsetHeight − 버튼 행 offsetTop`(= 아래 여백 + 버튼 행 실제 높이)
    `+ (b) sheet.offsetHeight − scroller.offsetTop − scroller.offsetHeight`
    (= BottomSheet가 footer 없는 시트의 스크롤 영역 아래에 두는 `env(safe-area-inset-bottom,1rem)` 여백)
    에서 safe-area 몫을 뺀 값을 신고한다.
  - `getBoundingClientRect`가 아니라 `offsetTop/offsetHeight`만 쓴다 — rect는 시트 열림
    트랜지션의 `translateY`와 스크롤 위치에 함께 흔들리지만 offset 계열은 레이아웃 값이라
    둘 다에 영향받지 않는다. 화면이 작아 콘텐츠가 넘칠 때도 "스크롤을 끝까지 내렸을 때"
    (= 버튼을 눌러야 하는 상태)의 기하를 그대로 돌려준다.
  - 실측 대상 DOM은 ref가 아니라 **콜백 ref + state**로 받는다. `BottomSheet`는 마운트 게이트
    때문에 첫 렌더에서 `null`을 반환하므로, ref였다면 이 컴포넌트의 첫 effect 시점에 시트 내부
    DOM이 없어 측정이 영영 건너뛰어진다(3차 구현 중 Playwright 실측으로 확인한 실제 증상 —
    `reserved`가 0으로 남았다).
  - `ResizeObserver`로 버튼 행·콘텐츠 크기 변화(웹폰트 로드·라벨 줄바꿈·`loading` 상태·dvh 변동)를
    구독해 재신고한다. 콜백이 레이아웃 확정 후에 불리므로 "트랜지션 중 측정" 문제도 함께 해소된다.

### 주요 의사결정 / 핵심 메모

**1차에서 상단 앵커를 시도했다가 폐기한 경위**
1차 구현(커밋 `d5b36efd`)은 "하단 오버레이가 떠 있으면 토스트를 TopNav 아래 상단 앵커로 옮기는"
방식이었다. 당시 2안(오프셋 밀어올리기)을 배제한 근거는 **"footer 높이 매직 넘버가 `Toast.tsx`에
이중화된다"**였다. 그러나 게이트 WARN + 인터랙션 리뷰에서 아래가 확인돼 반려됐다:

- **버그가 화면 반대편으로 이사할 뿐이다.** `full` 디텐트 시트(`BadgeDetailSheet`)의 자체 뒤로가기
  버튼(`min-h-11`)을 상단 토스트가 부분적으로 덮고, `pointer-events-auto`라 그 띠를 누르면
  뒤로가기 대신 토스트가 닫힌다 — 고치려던 것과 같은 종류의 탭 가로채기다.
- **`56px`(= "TopNav 아래")의 근거가 그 화면에 없다.** 상단 앵커가 쓰이는 유일한 경로인 `/drops`는
  TopNav를 렌더하지 않는다(grep 0건).
- **같은 모양이 두 개 쌓인다.** 그 자리엔 `DropsClient.tsx:245`의 탐색 중 로딩 필이 있는데
  `bg-surface-inverse` + 라운드 + 중앙정렬로 토스트와 외형이 사실상 동일하다.
- **같은 사건이 화면 양 끝에서 보고된다.** 동일한 픽업 실패가 시트에서는 상단, 캐러셀 카드에서는
  하단에 뜬다.
- 상·하단 동시 존재라는 **새 상태**가 생기고, "토스트 먼저 → 시트 열림" 역방향 케이스가 방어되지 않는다.

**왜 2차 방식(오프셋 밀어올리기)에서는 매직 넘버 문제가 사라지는가**
**의존 방향을 뒤집었기 때문이다.** `Toast.tsx`가 footer 높이를 계산하는 게 아니라, 하단을 점유하는
쪽이 자기 높이를 신고한다. `Toast.tsx`에 남는 숫자는 자기 기본 여백(88)과 최소 간격(8)뿐이다.
`BottomSheet`는 자기 footer를 실측하고, `BadgeDetailSheet`는 `paddingBottom` 계산에 이미 쓰던 상수를
그대로 신고한다 — 각 값의 진실의 원천이 그 값을 실제로 쓰는 파일 한 곳에 남는다.

**왜 스냅샷이 아니라 구독인가 (1차와 반대 결론)**
1차에서 "뜨는 순간 스냅샷"을 쓴 이유는 상단↔하단 **앵커 순간이동** 방지였다. 앵커 분기가 사라진
2차에서는 그 이유도 사라진다. 오히려 오프셋 방식에서는 이미 떠 있는 토스트(3초)가 살아 있는 동안
시트가 열리는 **역방향 케이스**를 스냅샷으로는 막을 수 없다 — 그 토스트가 시트 액션 버튼 위에
그대로 남는다. 그래서 `useSyncExternalStore`로 구독한다. 하단 앵커는 유지된 채 위치만 위아래로
옮겨가는 것이라 순간이동처럼 보이지 않는다.

**`open`이 아니라 `lingering` 기준으로 등록하는 이유**
시트 닫힘 트랜지션 350ms 동안에도 시트는 여전히 화면 하단을 덮고 있다.

**3안(`pointer-events-auto` 제거)은 1·2차 모두 배제**
탭-투-디스미스는 이 티켓의 회귀 금지 목록에 명시돼 있다.

**누수 방어를 개발 모드 `console.warn`으로 둔 이유**
해제 함수를 호출하지 않은 곳이 있으면 `reserved`가 영원히 남아 **모든 토스트가 영구히 밀려 올라간**
상태가 되는데, 화면이 죽지 않아 조용히 지나간다. 프로덕션 동작을 바꾸지 않으면서 개발 중에만
드러나게 했다(임계 8건).

**부수 검토(`88px` 여백 → 탭바 숨김 시 `safe+16px`)는 이번 범위에서 보류**
현재 `pushTabBarHidden`을 쓰는 두 화면(`BadgeShareButton`, `BadgeRevealOverlay`) 중
토스트를 띄우는 곳이 하나도 없어 실제 효과가 0이다. 또한 `BadgeShareButton`은 탭바를 숨기면서
동시에 `BottomSheet`를 열기 때문에, 그 안에서 토스트가 생기더라도 위 1안에 의해 이미 상단 앵커로
간다. 반대로 탭바 가시성을 구독해 하단 offset을 실시간으로 바꾸면 위와 같은 순간이동 문제가
재발한다. 실사용처가 생기는 시점에 "뜨는 순간 스냅샷" 방식으로 함께 처리하는 편이 안전하다.

### 잔여 이슈
- **`BadgeDetailSheet`의 겹침은 잠복이 아니라 실제 발생 중이었다.** 티켓 본문은 `footer` prop
  사용처만 조사해 "실제로 터지지는 않는다"로 판단했으나, `drops/BadgeDetailSheet.tsx:47`은
  `footer` prop을 쓰지 않고 스크롤 영역 자체에
  `paddingBottom: calc(env(safe-area-inset-bottom) + 16px + 64px + 12px)`를 줘서 픽업/취소 버튼을
  **`footerBottomInset='tabbar'`와 완전히 동일한 위치(safe+92~140px)**에 놓는다. 픽업 실패 토스트
  (safe+88~132px)와 거의 완전히 포개져, 토스트가 떠 있는 3초 동안 그 영역 탭이 버튼 대신 토스트
  디스미스로 먹혔다. 이번 변경으로 해소된다.
- **위치 변화에 모션이 없다(즉시 이동).** 시트가 열리고 닫힐 때 살아 있는 토스트의 `bottom`이 즉시
  바뀐다. `transition: bottom`을 주려면 `prefers-reduced-motion` 가드까지 함께 둬야 해서
  `src/components/transitions.css`(이번 재사용 판정의 수정 허용 파일 밖)를 건드려야 한다.
  실제로는 시트 열림·닫힘과 동시에 일어나는 56px 이동이라 눈에 거슬리는지 육안 확인 후 판단한다.
- `PoiCarouselModal`(`z-30`) 자체는 이 스토어에 등록하지 않았다 — 티켓 범위 밖.
  캐러셀 패널 하단도 `safe+92px`라 캐러셀만 열린 상태(예: `loadDropsFailed`)에서 뜨는 토스트는
  여전히 카드 하단과 겹친다. 필요하면 `pushBottomOverlay(점유높이)`를 `PoiCarouselModal`에도
  한 줄 등록하면 된다.
- **콘텐츠가 넘치는 작은 화면에서 스크롤을 안 내린 상태면 토스트가 필요보다 위에 뜬다(과잉 확보).**
  신고값은 "스크롤을 끝까지 내렸을 때"의 기하(144px)라, 스크롤 상단에서는 버튼이 화면 아래쪽
  (예: 375×667에서 하단 56px 지점)에 있어 토스트가 그보다 ~100px 위에 뜬다. 겹침은 없고 방향이
  안전한 쪽이라 그대로 뒀다 — 스크롤 위치까지 반영하려면 스크롤 구독이 필요한데, 토스트가 떠 있는
  3초 동안 스크롤이 바뀌는 케이스까지 감안하면 얻는 것보다 복잡도가 크다.
- `BottomSheet`의 footer 실측은 **열리는 시점 1회**다. footer 컨텐츠 높이가 열린 뒤에 바뀌면
  (현재 그런 호출부는 없다) 신고값이 낡는다. 필요해지면 `ResizeObserver`로 재신고하면 된다.
- `design-system/components/navigation/BottomSheet.jsx:57~59`는 여전히 포털 없는 `zIndex: 50`
  병존 구현이다. 이번 티켓에서는 DS를 건드리지 않았다(별도 티켓 20260826_003의 z-index 레이어
  체계 문서화와 함께 처리하는 편이 자연스럽다).
