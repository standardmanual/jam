# [UI] 알림 클릭 이동 시 배지 하이라이트(빨간 보더) 기능 제거

## 배경 / 문제 정의

알림을 클릭해 배지 목록/인벤토리로 이동할 때, 방금 획득한 항목들이 빨간색(`--color-primary`)
2px 보더로 하이라이트되는 기능이 있다. 이 기능을 제거한다(사용자 결정, 별도 배경 설명 없음 —
UX 단순화 목적으로 추정).

오케스트레이터가 전수 조사한 결과, `highlight` 쿼리 파라미터를 실제로 생성·소비하는 지점은
정확히 아래로 닫혀 있다 — 다른 기능과 얽혀 있지 않다.

## 상세 요구사항

### 서비스/코드베이스 관점

**1. URL 생성 — `jam-web/src/lib/notifications/href.ts`**
- `highlightQuery()` 헬퍼 함수(30~32행) 및 이를 호출하는 3개 지점 제거:
  - `badge_earned`(활동 배지 묶음, 44~46행) → `/badges?tab=activity&highlight=...`
  - `item_badge_earned`(아이템 배지 묶음, 54~56행) → `/inventory?highlight=...`
  - `poi_badge_earned`(POI 배지 묶음, 58~62행) → `/badges?tab=poi&highlight=...`
- 위 3개 알림 타입은 highlight 쿼리 없이 순수 목록 이동(`/badges?tab=activity`,
  `/inventory`, `/badges?tab=poi`)만 하도록 남긴다 — **탭 이동 자체는 유지**, 하이라이트만 제거.

**2. 쿼리 파싱 제거**
- `jam-web/src/app/(main)/badges/page.tsx`(15~22행) — `highlight` 쿼리 파싱 및
  `highlightIds`를 `BadgesClient`로 전달하는 부분 제거
- `jam-web/src/app/(main)/inventory/page.tsx`(20~27행) — 동일하게 `highlightItemIds` 전달 제거

**3. 소비 측 컴포넌트에서 하이라이트 로직 제거**
- `jam-web/src/app/(main)/badges/BadgesClient.tsx`(56, 88, 233, 281행 근처) —
  `highlightIds`/`highlightSet` 관련 prop·로직 제거 (활동 탭·POI 탭 둘 다)
- `jam-web/src/app/(main)/inventory/InventoryGrid.tsx`(53, 55, 74행 근처) —
  `highlightItemIds`/`highlightSet` 관련 prop·로직 제거

**4. 렌더링(시각 강조) 제거**
- `jam-web/src/components/ui/BadgeGridCard.tsx`(28, 58행 근처) — `highlighted` prop과
  그에 연결된 `shadow-[inset_0_0_0_2px_var(--color-primary)]` CSS 클래스 제거
  - ⚠️ **주의**: 같은 컴포넌트의 `selected` prop(컬렉션 슬롯 선택 모드용 배경 채움,
    `SlotGrid.tsx`에서 사용)은 하이라이트와 무관한 별도 기능이므로 **건드리지 않는다**.

### UI/UX 관점

- 하이라이트가 사라진 뒤에도 알림 클릭 시 올바른 탭/화면으로 이동하는 것은 그대로 유지돼야 한다
  (URL의 `tab=activity`/`tab=poi` 등 이동 자체는 남기고, `highlight` 파라미터만 제거)
- 사용자 노출 문구 변경 없음 — 순수 시각 효과 제거

## 구현 계획

1. `href.ts`의 `highlightQuery()` 및 3개 호출부에서 `highlight` 쿼리만 제거(이동 경로는 유지)
2. `badges/page.tsx`, `inventory/page.tsx`의 쿼리 파싱·prop 전달 제거
3. `BadgesClient.tsx`, `InventoryGrid.tsx`의 `highlightIds`/`highlightSet` 로직 제거
4. `BadgeGridCard.tsx`의 `highlighted` prop·CSS 제거 (`selected` prop은 유지)
5. 타입(`NotificationPayloadMap` 등)에 `highlight` 전용 필드가 있다면 함께 정리
6. 관련 테스트가 있다면(예: `message-href.test.ts`의 highlight 관련 케이스) 함께 제거·정리

## 검증
- 3개 알림 타입(활동/아이템/POI 배지 묶음 획득) 클릭 시 각각 올바른 탭으로 이동하되
  하이라이트(빨간 보더)가 더 이상 나타나지 않는지 확인
- 컬렉션 슬롯 선택 모드의 `selected`(배경 채움) 표시는 회귀 없이 그대로 동작하는지 확인
- 타입체크·기존 테스트 통과

이 경위를 보고한 결과 다음 3가지를 확인받았다:

   이번 범위에서 넘어감

### 주요 의사결정 / 핵심 메모
- **`BadgeGridCard.tsx`의 `highlighted` prop·CSS는 삭제하지 않고 유지했다.** 티켓
  요구사항 4번은 이 prop을 완전히 제거하라고 명시했지만, 실제 코드에는 오케스트레이터의
  "전수조사"가 잡아내지 못한 4번째 소비처가 있었다 —
  `src/app/(main)/collections/[id]/SlotGrid.tsx:157`가 컬렉션 슬롯 장착 모드
  (`/collections/[id]?slot=1`, `collection_completable` 소식 #11의 착지점)에서
  "지금 넣을 수 있는 칸"을 짚어주는 데 같은 `highlighted` prop·같은 CSS
  (`shadow-[inset_0_0_0_2px_var(--color-primary)]`)를 사용 중이다. 이 소식 타입은
  `highlight` 쿼리 파라미터를 전혀 쓰지 않고(`slot=1` 불리언 + `isSlottable` 내부
  계산) 사용자 요청("알림 클릭 시 배지 목록/인벤토리로 이동할 때 방금 획득한 항목
  하이라이트")과 목적지·의미가 다르다(배지 목록/인벤토리가 아니라 컬렉션 상세, "방금
  획득"이 아니라 "지금 슬롯에 넣을 수 있음"). prop을 통째로 제거하면 이 무관한 기존
  기능이 컴파일 에러와 함께 깨지므로, `highlight` 쿼리 기반 3개 소비처(BadgesClient
  활동/POI 탭, InventoryGrid navigate 모드)에서 `highlighted={...}` 호출만 제거하고
  prop 정의 자체는 남겼다. prop 설명 주석은 SlotGrid 용도로 갱신했다.
- 탭 이동(`?tab=activity`, `?tab=poi`) 자체는 요구사항대로 유지했다.
- `selected` prop(컬렉션 슬롯 선택 모드 배경 채움)은 전혀 건드리지 않았다.
