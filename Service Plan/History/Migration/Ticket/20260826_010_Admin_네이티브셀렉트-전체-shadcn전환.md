# [Admin] 어드민 화면 전체 네이티브 select → shadcn Select 전환

## 배경 / 문제 정의
티켓 [20260822_002](20260822_002_Admin_컬렉션필터-네이티브셀렉트-다크팝업버그수정.md)에서
"어드민 화면은 shadcn/ui 표준 컴포넌트를 쓴다"는 규칙이 확정됐다. 계기는 네이티브 `<select>`
팝업이 OS 다크모드 설정을 그대로 따라가 라이트 테마 어드민 화면과 색상이 어긋나는 실제
프로덕션 버그였다.

당시 [ItemBookList.tsx](jam-web/src/components/admin/itembooks/ItemBookList.tsx) 1개 파일만
전환됐고 규칙만 남았다. 이번에 `grep -rl "<select" jam-web/src/app/admin/` 로 재조사한 결과,
같은 버그를 재현할 수 있는 네이티브 `<select>`가 **12개 파일에 총 31개** 남아있는 것을 확인했다
(사전 메모리에 있던 "5개 파일" 추정은 부정확했음 — [BadgesFilterBar.tsx](jam-web/src/app/admin/badges/BadgesFilterBar.tsx)는
상태 필터 1개만 shadcn으로 전환되고 나머지 7개는 네이티브로 남은 **혼재 상태**였고,
"AmbientDropForm.tsx"는 현재 저장소에 존재하지 않는 파일명이었다).

## 상세 요구사항

### 서비스/코드베이스 관점
아래 12개 파일의 네이티브 `<select>`를 전부 `@/components/ui/select`
(`Select`/`SelectTrigger`/`SelectValue`/`SelectContent`/`SelectItem`)로 교체한다.

- 각 select의 기존 상태 바인딩(`value`)·변경 핸들러(`onChange` → `onValueChange`)·옵션 목록·
  `disabled` 조건·조건부 렌더링은 값 그대로 유지한다. 이번 작업은 마크업 레이어 교체이며
  폼 로직·검증·제출 동작을 바꾸지 않는다.
- 참고 패턴: [ItemBookList.tsx](jam-web/src/components/admin/itembooks/ItemBookList.tsx) (완전
  전환된 예시), [BadgesFilterBar.tsx](jam-web/src/app/admin/badges/BadgesFilterBar.tsx)의 상태
  필터 부분(혼재 중 이미 전환된 부분).
- `BadgesFilterBar.tsx`의 `SELECT_CLASS` 상수(네이티브 select 전용 커스텀 스타일)는 전환 후
  더 이상 참조되지 않으면 제거한다.

### UI/UX 관점 (해당 시)
- 모든 드롭다운 팝업이 시스템 다크모드 설정과 무관하게 라이트 테마로 렌더링되어야 한다.

## 구현 계획
`@/components/ui/select`는 이미 세팅돼 있으므로 신규 컴포넌트 제작 없이 그대로 가져다 쓴다.
파일마다 `<select>` → `<Select>` 교체 후 `npx tsc --noEmit`, `npx eslint`로 회귀 여부를 확인한다.
어드민은 구글 로그인이 필요해 자동화 브라우저 육안 확인이 불가하므로(과거 티켓과 동일 제약),
코드 리뷰와 타입/린트 검증으로 대체하고 실제 화면 확인은 배포 후 사용자가 진행한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`grep -rl "<select" jam-web/src/app/admin/`로 재확인된 12개 파일의 네이티브 `<select>` 31개를
전부 `@/components/ui/select`(`Select`/`SelectTrigger`/`SelectValue`/`SelectContent`/`SelectItem`)로
교체했다. `value`/`onChange→onValueChange` 바인딩, 옵션 목록, `disabled`·조건부 렌더링은 모두
그대로 유지했고 폼 로직·검증·제출 동작은 건드리지 않았다(마크업 레이어 교체만).

- **빈 문자열 값 처리**: Radix `SelectItem`은 `value=""`를 허용하지 않는다(런타임 경고/오동작).
  "— 없음 —"/"— 전체 —"류 옵션이 있던 8개 select(TodayCardList 2개, ItemBookForm 1개,
  FactionForm 1개, BadgeForm 4개)에는 파일별 로컬 상수 `NONE_VALUE = '__none__'`을 도입해
  `value={state || NONE_VALUE}` / `onValueChange={(v) => setState(v === NONE_VALUE ? '' : v)}`
  패턴으로 매핑했다. 내부 상태(`factionId`, `mission_id` 등)는 여전히 빈 문자열을 저장하므로
  저장 payload(`xxx_id: xxx || null`)는 변경 없음.
- **숫자 값 select**: `CategoryManager.tsx`의 티어(1|2)는 Radix Select의 `value`가 항상
  string이라 `value={String(tier)}` / `onValueChange={(v) => setTier(Number(v) as 1|2)}`로
  변환했다. 내부 state 타입(`1 | 2`)은 유지.
- **`BadgesFilterBar.tsx`**: 이미 shadcn으로 전환돼 있던 상태 필터 1개(상태값 참고 패턴)를
  제외한 나머지 6개(타입/액티비티/POI카테고리/세계관/컬렉션/등급/정렬 — 실제로는 7개
  select 슬롯이나 그중 하나(상태)만 기존 전환분)를 shadcn Select로 전환했다. 네이티브
  select 전용 스타일이던 `SELECT_CLASS` 상수는 더 이상 참조되지 않아 제거했다.
- `PoiForm.tsx`의 카테고리 select는 원래 `required` 속성이 있었으나 Radix Select는 네이티브
  `required`를 지원하지 않는다 — 다만 이 필드는 `categories[0]?.slug ?? 'other'`로 항상
  기본값이 채워지는 구조라 실질적 검증 동작 변화는 없다(로직 변경 아님, 마크업 특성 차이).

### 주요 의사결정 / 핵심 메모
- 빈 문자열 sentinel(`NONE_VALUE = '__none__'`)은 공유 유틸로 뽑지 않고 필요한 파일마다
  로컬 상수로 각자 선언했다 — 티켓 범위가 "마크업 교체"이고 새 공유 추상화 도입은 요청받지
  않았으므로, 기존 코드베이스가 폼마다 자기 완결적으로 두는 관례(`uploadBackgroundFile` 등)를
  그대로 따랐다.
- `BADGE_BACKGROUND_SHADER_OPTIONS`(공유 옵션 배열, `value: ''`인 "없음" 항목 포함)는 3개 파일
  (ItemBookForm/FactionForm/BadgeForm)에서 재사용되는데, 배열 자체는 그대로 두고 `SelectItem`
  렌더링 시점에만 `opt.value || NONE_VALUE`로 변환해 원본 데이터 모델을 건드리지 않았다.
- **티켓 ID 재부여**: 최초 생성 시(`20260826_009`) origin/staging에는 해당 번호가 비어있었으나,
  구현이 진행되는 동안 `20260826_009_BadgeEngine_앰비언트-POI-드랍-재도입.md`가 별도로 staging에
  먼저 병합돼 번호가 겹쳤다(게이트 리뷰에서 발견). 병합 전 `20260826_010`으로 재부여했다.
  review 브랜치명(`claude/jamwork-20260826_009-admin-shadcn-select`)과 이미 push된 커밋 메시지는
  구 번호(`009`)를 참조하고 있으나, 이미 원격에 push된 히스토리라 재작성하지 않고 이 메모로
  대응 관계를 남긴다.
