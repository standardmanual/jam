# [Admin] 어드민 UI 성능 개선 및 UX 라이팅 정합성

## 배경 / 문제 정의

`/impeccable optimize` → `shape` → `clarify` 세 단계로 어드민 화면(`src/app/admin/`,
`src/components/admin/`) 전체를 점검했다. 코드 감사와 로컬 dev 서버 실측(네트워크·DOM·타이밍)을
병행해 확인한 성능 이슈 8건과, `UX_WRITING_GUIDELINE.md` 고정 용어 대조로 확인한 카피 위반을
하나의 리뉴얼 작업으로 묶는다.

**실측 근거**: `/admin/badges`(50건/페이지)에서 `<img>` 100개(카드+테이블 이중 마운트 확인),
TTFB 1.6s(dev). `/admin/itembooks/[id]` 편집 화면은 배지 피커(무제한 프리로드) 마운트 후 입력
반응이 지연됐다.

### ⚠️ 이 티켓은 `20260826_010`(같은 제목)의 재번호 재시도다

최초 시도(`20260826_010`)에서 jam-developer가 **로컬 저장소가 `origin/staging`보다 3커밋
뒤처진 상태**로 구현을 진행했다. 그 사이 다른 세션이 **같은 번호 `20260826_010`으로 "어드민
네이티브 select 31개 전체를 shadcn Select로 전환"** 작업을 이미 완료해 병합해둔 상태였고,
jam-developer는 이를 모른 채 native `<select>`가 남은 버전으로 여러 파일을 재작성해
**게이트 리뷰에서 FAIL**(shadcn 전환 회귀 위험, grep으로 재현 확인)을 받았다. 커밋·푸시는
전혀 없었고, 오케스트레이터가 변경사항을 stash로 보존한 뒤 `origin/staging`(`728e70dd`)까지
pull해 로컬을 최신화하고 이 티켓을 `011`로 재배정했다.

**⚠️ 이번 구현은 반드시 최신 `origin/staging` 기준(현재 로컬 HEAD)에서 시작할 것.** 아래
"절대 건드리면 안 되는 것"에 **shadcn select 전환 결과물 유지**를 추가했다 — 이번 작업으로
새 native `<select>`를 만들거나 기존 shadcn `<Select>`를 되돌리지 말 것.

### ⚠️ 선행 티켓과의 경계 — 반드시 읽고 시작할 것

- **`20260825_037`**(`bug`, CLOSED)이 `admin/missions/page.tsx`·`admin/today/page.tsx`의
  배지 `range()`-루프 전량 조회를 **PostgREST 1000행 응답 상한으로 인한 배지 절단 버그의
  방어책으로 명시적으로 도입했다** (2172건 중 이름 정렬 뒤쪽 배지가 통째로 안 잡히던 버그).
  이번 티켓의 항목 A2는 이 range-loop를 "줄이거나 제거"하는 게 아니라 **프리로드+클라이언트
  필터 UX 자체를 서버검색 피커로 교체**하는 것이다 — 아래 상세 요구사항 참조. 단순 `limit()`
  축소나 range-loop 제거는 037의 버그를 재현하므로 **절대 금지**.
- **`20260826_004`**(`Service`, CLOSED)가 "POI" 표기를 서비스 전역에서 정리하면서
  어드민의 경계를 이미 확정했다: **"배지 도메인(배지 타입 enum)만 `checkin`으로 바꾸고,
  지점 관리 화면(`admin/poi/*`, 사이드바 'POI 관리', `POI 블록`, `POI 매칭` 등)은 운영자용
  기술 식별자로 그대로 유지한다."** 이번 티켓은 그 결정을 재론하지 않는다 — 아래
  "절대 건드리면 안 되는 것" 섹션 참조. 이번 티켓이 손대는 POI→지점 표기는 `BadgeForm.tsx`의
  체크인 배지-지점 연결 섹션 **한 곳뿐**이며, 그마저도 20260826_004가 이미 절반(주석·본문
  일부)을 "지점"으로 바꿔놓고 헤딩·placeholder·에러 메시지를 놓친 것을 마저 완결하는 것이다.
- **`20260826_010`**(`Admin`, CLOSED, 네이티브 select 전체 shadcn 전환) — 위 참고. 이번
  티켓이 새로 만드는 UI(신규 배지 다중선택 컴포넌트 등)도 native `<select>`가 아니라
  이 티켓이 확립한 shadcn `<Select>` 패턴을 따를 것.

## 상세 요구사항

### A. 성능/아키텍처 (서비스/코드베이스 관점)

**A1. 배지 다중선택 검색 컴포넌트 신설 — 아래 세 호출부를 교체한다 (최우선, 나머지 항목의 기반)**

현재 세 화면이 각자 "배지 전체를 프리로드한 뒤 클라이언트에서 `.filter(name.includes())`"
방식을 독립 구현하고 있다. 이걸 디바운스 서버검색 방식(이미 `BadgeSearchSelect.tsx` +
`/api/admin/badges/search`가 검증해둔 패턴, 참고: `MAX_RESULTS=20`)의 **다중선택 버전**으로
통일한다. 새 컴포넌트 하나를 만들어 세 곳에서 재사용할 것 (이름은 재량, 예:
`BadgeMultiSearchSelect`) — 클릭해도 닫히지 않고 계속 검색·추가할 수 있는 멀티애드 UX,
선택된 배지는 칩/리스트로 표시하고 개별 제거 가능. **입력 필드·드롭다운 등은 native
엘리먼트가 아니라 `20260826_010`이 도입한 shadcn 컴포넌트 패턴을 따를 것.**

- `ItemBookForm.tsx`(656-695번째 줄 부근) "배지 선택 모달" — 현재 `[id]/page.tsx`의
  `.is('item_book_id', null).eq('type','item').limit(10000)`로 미배정 아이템 배지 전량을
  props로 받아 로컬 필터링. → 신규 컴포넌트로 교체, `type=item`+미배정 필터로 검색.
  (파일이 `20260826_010`에서 이미 수정됐으니 정확한 현재 줄 번호는 구현 시 다시 확인할 것)
- `MissionList.tsx`의 `reward_badge_ids`(다중, `selectedBadges`/`badgeQuery` 필터 로직) →
  신규 컴포넌트로 교체. `gated_badge_id`(단일선택, `gatedBadge`/`gatedBadgeQuery`)는
  다중선택이 아니므로 **기존 `BadgeSearchSelect.tsx`를 그대로 재사용**(신규 컴포넌트 불필요).
  MissionList가 보상 배지의 "포인트 포함 여부" 경고에 `point_reward`를 쓰므로, 검색 결과에
  이 필드가 필요.
- `TodayCardList.tsx`의 `badge_ids`(다중, `selectedBadges`/`badgeQuery` 필터 로직) →
  신규 컴포넌트로 교체.

**`/api/admin/badges/search/route.ts` 확장 필요:**
1. `unassigned=true` 쿼리 파라미터 추가 — `item_book_id is null` 필터 (ItemBookForm 전용).
   기존 `type` 파라미터와 조합 가능해야 하고, 다른 호출부(레시피 등)는 파라미터 미지정 시
   기존 동작 그대로 유지할 것(하위호환).
2. `select()`에 `point_reward` 추가 (MissionList 보상 배지 경고 로직에 필요, 나머지
   호출부는 무시하면 그만이라 부작용 없음).

**A2. `admin/missions/page.tsx`, `admin/today/page.tsx` — range-loop 프리로드 제거**

A1의 컴포넌트로 UI를 교체한 뒤에는, 페이지 진입 시 배지 2172건 전량을 서버에서 끌어올 필요가
없어진다(검색 API가 그때그때 20건만 반환). `fetchAllBadgeOptions`/`BADGE_PAGE_SIZE` 루프와
그 결과를 프롭으로 넘기는 부분을 제거하고, `MissionList`/`TodayCardList`가 필요 시 A1
컴포넌트를 통해 직접 검색하도록 리팩터한다. **037의 range-loop 코드/주석을 그대로 남겨둔 채
단순히 limit만 줄이는 식의 수정은 하지 말 것** — UI 자체를 A1 컴포넌트로 바꾸는 것이 목적이다.

**A3. God 컴포넌트 분리 — UI 변화 없음, 순수 리팩터**

`TodayCardList.tsx` · `MissionList.tsx` · `RecipeList.tsx` — 저작 폼(텍스트 입력 등)과 하단
테이블/카드 렌더링이 한 컴포넌트에 결합돼 있어 폼에 한 글자 입력할 때마다 리스트 전체가
리렌더된다. 리스트 렌더링 부분을 `React.memo`로 감싼 별도 자식 컴포넌트로 분리할 것.

**A4. 모바일/데스크톱 이중 마운트 제거 — UI 변화 없음**

`components/admin/badges/BadgeList.tsx`, `components/admin/poi/PoiList.tsx` 등이
`md:hidden`/`hidden md:block`으로 카드 그리드와 테이블을 **둘 다 마운트**한다(실측: `/admin/badges`
50건 페이지에서 `<img>` 100개 = 2배). 뷰포트 조건부로 한쪽만 마운트하도록 전환.
**PoiList.tsx의 텍스트 내용("등록된 POI가 없습니다." 등)은 건드리지 않는다** — 렌더링 구조만 수정.

**A5. WebGL 셰이더·비디오 인코더 지연 로드**

`BadgeForm.tsx`가 정적 import하는 `BackgroundGeneratorPreview`(→ `@paper-design/shaders-react`
셰이더 5종 + `mp4-muxer`)를 지연 로드로 전환. "제너레이터" 탭을 열 때만 청크 로드.

**주의(최초 시도에서 발견한 함정)**: `next/dynamic`으로 감싸면 `next/dynamic`의 loadable
래퍼(`node_modules/next/dist/shared/lib/loadable.shared-runtime.js`)가 `ref`를 가로채
`{ retry }`로 덮어써 실제 컴포넌트로 전달하지 않는다 — `BackgroundGeneratorPreview`가
`ref.bake()`로 배경을 저장하는 기능이 **조용히 깨진다**. Next.js 공식 문서가 인정하는 대안인
**`React.lazy` + `Suspense`**로 구현할 것 (`next/dynamic` 아님). 로딩 폴백은 기존
`MapPreview.tsx`(`components/admin/poi/PoiDetail.tsx`) 컨벤션과 동일하게
`<div className="h-64 bg-muted animate-pulse rounded" />` 재사용. `ItemBookForm.tsx`,
`FactionForm.tsx`도 같은 컴포넌트를 쓰므로 함께 적용.

**A6. itembooks 목록 서버 페이지네이션 전환**

`itembooks/page.tsx`가 전체 로드 후 `ItemBookList.tsx`가 클라이언트에서 세계관 필터·정렬을
처리 중(서버 페이지네이션 없음, POI·배지 목록과 다름). `admin/poi/page.tsx` + `Pagination.tsx`와
동일한 구조로 전환: `searchParams`로 `page`/`faction`/`sort` 받아 `select('*',{count:'exact'})`
+ `.range()` 서버 필터링. `ItemBookList`의 세계관 필터·정렬 `Select`(이미 shadcn)는 로컬
state 대신 URL 파라미터로 구동(참고: `admin/poi/PoiFilters.tsx`). `Pagination.tsx`를
`basePath="/admin/itembooks"`로 재사용, 페이지 크기 30(POI와 동일).

**A7. `users/page.tsx` 쿼리 병렬화**

배지 수 집계 → 인벤토리 조회 → 아이템 수 집계가 순차 `await`. 독립적인 쿼리는
`Promise.all`로 병렬화(인벤토리→인벤토리 아이템처럼 의존 관계가 있는 것은 유지). UI 변화 없음.

**A8. 넓은 `select('*')` 정리**

`admin/poi/page.tsx`, `admin/badges/page.tsx`의 `select('*', {count:'exact'})`를
목록에 실제로 쓰는 컬럼만 명시하도록 축소. UI 변화 없음.

### 주요 의사결정 / 핵심 메모

- **애초 `20260826_010`으로 시도했다가 재번호(`011`)로 재시도했다.** 로컬 저장소가
  `origin/staging`보다 3커밋 뒤처진 상태로 첫 시도를 진행해, 같은 번호로 동시에 병합된
  "어드민 네이티브 select 31개 전체 shadcn 전환" 작업(커밋 `8d4eef92`)을 모르고 여러 파일에
  native `<select>`를 재도입했다. 커밋·푸시 전에 게이트 리뷰가 grep으로 회귀를 재현 확인해
  FAIL 처리했고, 오케스트레이터가 미커밋 변경사항을 `git stash`로 보존한 뒤(`stash@{0}`, 현재도
  보존 중 — 재작업본과 무관해 폐기 대상) `origin/staging`까지 pull, 티켓을 `011`로
  재배정해 재시도했다. 재시도는 시작 전 `git log -1` 확인을 티켓에 명시해 같은 사고를
  막았고, 실제로 stale 베이스 재현 없이 단일 커밋으로 완료됐다.
- **A2(배지 range-loop 프리로드 제거)는 037의 range-loop 자체를 축소하지 않았다.** 037이
  PostgREST 1000행 절단 버그 방어책으로 도입한 range-loop 패턴은 그대로 두고(다른 파일에
  존속), `missions/today`의 배지 "전량 프리로드 후 클라이언트 검색" UX를 서버검색 피커로
  바꿔 애초에 전량 조회가 필요 없게 만드는 방식으로 우회했다 — "쿼리 축소"가 아니라

- **A5는 티켓이 지시한 `next/dynamic` 대신 `React.lazy`+`Suspense`로 구현했다.**

  그대로 반영했다. 게이트 리뷰가 fallback 컨벤션 일치·ref 안전성을 재확인했다.
