## 상세 요구사항

### 교체 대상

- `src/components/admin/AdminSidebar.tsx` — 데스크탑 좌측 사이드바(접기/펼치기 가능)
- `src/components/admin/AdminNav.tsx` — 모바일 헤더+드로어 네비게이션
- `src/components/admin/AdminHeader.tsx` — 헤더
- `src/components/admin/AdminMain.tsx` — 사이드바 접힘 상태에 맞춘 메인 콘텐츠 여백 조정
- `src/components/admin/AdminSidebarContext.tsx` — 접기/펼치기 상태 관리

이 5개 파일이 담당하는 기능(아래)을 shadcn 공식 `Sidebar` 컴포넌트로 재구현한다. **먼저
`npx shadcn@latest docs sidebar`로 공식 API·예제 URL을 가져와 확인할 것 — 임의 커스텀
마크업 금지.**

### 유지해야 하는 기능

1. **데스크탑 접기/펼치기**: 지금 `AdminSidebarContext`가 담당. shadcn `Sidebar`는
   `SidebarProvider`/`useSidebar`가 이 상태를 기본 제공하므로 그대로 대체 가능 — 커스텀
   context를 유지할 필요 없으면 제거.
2. **모바일 드로어**: 지금 `AdminNav`가 헤더 햄버거 + 드로어를 담당. shadcn `Sidebar`는
   `collapsible="offcanvas"` 등 반응형 모드를 공식 지원 — 이 패턴을 따를 것.
3. **인증 상태 표시**: `admin/layout.tsx`가 `userEmail`을 `AdminNav`/`AdminSidebar`에
   props로 전달해 로그인 이메일을 표시 중. 새 구현에서도 유지.
4. **네비게이션 항목**: `src/components/admin/adminNavItems.ts`의 메뉴 구조(라벨·href·
   아이콘·그룹핑)는 그대로 유지 — 렌더링 방식만 shadcn `Sidebar`로 교체, 항목 자체는
   손대지 않는다.

### CSS 스코프 주의 (1단계에서 발견한 함정)

shadcn 테마 실값은 전역 `:root`가 아니라 `[data-admin-theme]` 스코프 셀렉터 안에만
존재한다(`admin/layout.tsx`의 최상위 wrapper div에 이미 이 속성이 부여돼 있음). 새
`Sidebar` 컴포넌트가 `admin/layout.tsx`의 그 wrapper **안에서** 렌더링되는 한 문제없다 —
`SidebarProvider`를 wrapper 밖에 두거나 별도 포털로 렌더링하면 스타일이 깨지니 주의.

## 완료 기록

### 구현 내용 요약

`npx shadcn@latest docs sidebar`로 공식 API를 확인한 뒤, 공식 Sidebar 레지스트리 아이템
(`sidebar`)이 요구하는 신규 파일 5개(`separator.tsx`, `tooltip.tsx`, `skeleton.tsx`,
`sidebar.tsx`, `use-mobile.tsx`)를 `--view`로 원본 그대로 확보해 수동 배치했다 —
`npx shadcn add sidebar`를 그대로 실행하면 이미 tabler로 마이그레이션된
`button.tsx`/`sheet.tsx`/`input.tsx`를 lucide 기반 원본으로 **덮어써** 1단계(20260826_012)
완료 기준("lucide-react 어드민 내 잔존 0건")을 되돌릴 뻔했다 — `--dry-run`/`--diff`로 먼저
확인해 그 3개 파일은 덮어쓰지 않고, 신규 파일만 추가했다. `sidebar.tsx`의 유일한 lucide
참조(`PanelLeft`)는 tabler `IconLayoutSidebar`로 교체.

기존 5개 파일(`AdminSidebar`/`AdminNav`/`AdminHeader`/`AdminMain`/`AdminSidebarContext`)을
`AdminSidebar.tsx`(shadcn `Sidebar collapsible="icon"` + `adminNavItems.ts` 그룹 매핑)와
`AdminHeader.tsx`(`SidebarInset` 상단 고정 헤더 — `SidebarTrigger` 하나로 데스크탑 접기/
펼치기·모바일 드로어를 모두 처리)로 재구성했다. `AdminNav`/`AdminMain`/`AdminSidebarContext`는
삭제 — 각각 shadcn의 내장 반응형 전환(`useIsMobile`), `SidebarInset`, `SidebarProvider`/
`useSidebar`가 대체한다. 접기/펼치기 상태는 기존 localStorage 대신 shadcn 공식 쿠키
(`sidebar_state`)로 전환하고, `admin/layout.tsx`(서버 컴포넌트)가 요청 시점에 쿠키를 읽어
`SidebarProvider defaultOpen`에 넘겨 새로고침 시 깜빡임 없이 이전 상태를 복원한다.

그룹 아코디언(구현 전 검토했던 `Collapsible` + `SidebarGroupLabel asChild` 공식 패턴)은
최종적으로 **채택하지 않았다** — Radix `Collapsible.Content`가 닫힘 상태에서 DOM에서
완전히 제거되는데, 데스크탑 `collapsible="icon"` 모드에서 그룹이 닫혀 있으면 아이콘조차
전혀 렌더링되지 않는 조합 버그를 발견했기 때문(재현: 그룹이 닫힌 채 사이드바를 아이콘으로
접으면 그 그룹은 완전히 사라짐). 대신 그룹을 항상 펼친 상태로 렌더링하는 기본 패턴을
썼다 — `SidebarGroupLabel`이 아이콘 모드에서 자동으로 사라지는 내장 동작만으로 기존
"접힘 상태에서는 라벨 생략, 아이콘만 나열" 요구사항이 그대로 충족된다.

모바일 드로어(Sidebar 내부 `Sheet`)가 `bg-sidebar`/`text-sidebar-foreground` 등 시맨틱
토큰을 쓰는데, shadcn 어드민 테마 실값은 `[data-admin-theme]` 스코프 안에만 존재하고
Radix `Sheet`의 Portal은 기본적으로 `document.body`(스코프 밖)에 렌더링된다 — 이 조합이면
모바일 드로어 배경이 깨진다(티켓의 "CSS 스코프 주의" 항목이 예견한 위험군과 동일 카테고리,
PHASES.md Phase 4가 "그 시점에 처리"라고 미뤄둔 것과 같은 문제가 이번 티켓에서 먼저
발생함). `sheet.tsx`의 `SheetContent`에 선택적 `container` prop을 추가해 Radix Portal에
그대로 전달하고, `sidebar.tsx`의 모바일 분기에서 `document.querySelector('[data-admin-theme]')`
로 실제 admin 스코프 노드를 찾아 넘기도록 수정했다(공식 Radix Portal API 사용, 커스텀
마크업 아님).

### 주요 의사결정 / 핵심 메모

- **접기/펼치기 상태 저장소를 localStorage → shadcn 공식 쿠키로 전환**했다. 요구사항인
  "상태 기억"은 유지하면서, 서버 컴포넌트가 쿠키를 미리 읽어 `defaultOpen`을 정해줄 수
  있어 localStorage 방식보다 새로고침 시 깜빡임이 없다(개선이지 기능 변경 아님).
- **그룹 아코디언(개별 접기/펼치기) 기능은 유지하지 않았다.** 티켓은 "adminNavItems.ts의
  그룹핑을 그대로 유지"만 요구했고 "그룹별 접고 펼치는 상호작용 자체"는 렌더링 방식(옛
  Accordion 컴포넌트)의 구현 디테일이었다 — 위에서 설명한 아이콘 모드 조합 버그 때문에
  공식 컴포넌트만으로 안전하게 재현할 수 없어 제외했다. 그룹 라벨은 4개 모두 상시 노출되고
  스크롤로 전체 열람 가능(기존과 동일하게 스크롤 가능한 `SidebarContent`).
  **재도입이 필요하면 별도 티켓으로 검토 권장**(제어형 `Collapsible`을 사이드바 아이콘 모드와
  동기화하는 별도 로직이 필요).
- **헤더 정보(현재 페이지 제목·로그인 이메일) 노출 범위가 모바일 전용 → 전 화면대로
  확장됐다.** 기존엔 데스크탑에 헤더 자체가 없었으나, shadcn 공식 패턴은 `SidebarInset`
  상단에 `SidebarTrigger`를 두는 단일 헤더 구조를 쓴다(임의 커스텀 마크업 금지 원칙에 따라
  데스크탑 전용 커스텀 토글을 별도로 만들지 않음) — 정보 손실은 없고 데스크탑에 새 얇은
  헤더 바(h-14)가 추가되는 시각적 차이만 있다.
