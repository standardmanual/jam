전체 배경·원칙은 `Service Plan/Specs/PRD/AdminUI/REDESIGN.md`(3절 "레이아웃 셸") 참조 —
시작 전 반드시 먼저 읽을 것. 실행 순서·완료 기준은
`Service Plan/Specs/PRD/AdminUI/PHASES.md`의 "Phase 2 — 레이아웃 셸" 절과 동일하다.

프리셋 `b5Jgcv00m` 테마(`[data-admin-theme]` 스코프) + Pretendard + tabler 아이콘까지
완료됐다. 2단계는 그 기반 위에서, 지금 손수 구현된 어드민 레이아웃 셸을 shadcn 공식
`Sidebar` 컴포넌트/블록으로 교체한다.

## 상세 요구사항

### 교체 대상

- `src/components/admin/AdminSidebar.tsx` — 데스크탑 좌측 사이드바(접기/펼치기 가능)
- `src/components/admin/AdminNav.tsx` — 모바일 헤더+드로어 네비게이션
- `src/components/admin/AdminHeader.tsx` — 헤더
- `src/components/admin/AdminMain.tsx` — 사이드바 접힘 상태에 맞춘 메인 콘텐츠 여백 조정
- `src/components/admin/AdminSidebarContext.tsx` — 접기/펼치기 상태 관리

이 5개 파일이 담당하는 기능(아래)을 shadcn 공식 `Sidebar` 컴포넌트로 재구현한다. **먼저
`npx shadcn@latest docs sidebar`로 공식 API·예제 URL을 가져와 확인할 것 — 임의 커스텀
마크업 금지.**

### 유지해야 하는 기능

1. **데스크탑 접기/펼치기**: 지금 `AdminSidebarContext`가 담당. shadcn `Sidebar`는
   `SidebarProvider`/`useSidebar`가 이 상태를 기본 제공하므로 그대로 대체 가능 — 커스텀
   context를 유지할 필요 없으면 제거.
2. **모바일 드로어**: 지금 `AdminNav`가 헤더 햄버거 + 드로어를 담당. shadcn `Sidebar`는
   `collapsible="offcanvas"` 등 반응형 모드를 공식 지원 — 이 패턴을 따를 것.
3. **인증 상태 표시**: `admin/layout.tsx`가 `userEmail`을 `AdminNav`/`AdminSidebar`에
   props로 전달해 로그인 이메일을 표시 중. 새 구현에서도 유지.
4. **네비게이션 항목**: `src/components/admin/adminNavItems.ts`의 메뉴 구조(라벨·href·
   아이콘·그룹핑)는 그대로 유지 — 렌더링 방식만 shadcn `Sidebar`로 교체, 항목 자체는
   손대지 않는다.

### CSS 스코프 주의 (1단계에서 발견한 함정)

shadcn 테마 실값은 전역 `:root`가 아니라 `[data-admin-theme]` 스코프 셀렉터 안에만
존재한다(`admin/layout.tsx`의 최상위 wrapper div에 이미 이 속성이 부여돼 있음). 새
`Sidebar` 컴포넌트가 `admin/layout.tsx`의 그 wrapper **안에서** 렌더링되는 한 문제없다 —
`SidebarProvider`를 wrapper 밖에 두거나 별도 포털로 렌더링하면 스타일이 깨지니 주의.

## 절대 건드리면 안 되는 것

- 서비스 본체(비-admin) 레이아웃 — 이번 티켓과 무관
- `src/components/admin/adminNavItems.ts`의 메뉴 항목 구조(라벨·경로) — 렌더링 방식만 교체
- `admin/layout.tsx`의 인증 로직(`ADMIN_EMAILS` 화이트리스트 체크) — 그대로 유지
- 어드민 기능 로직(각 화면의 CRUD·시뮬레이터 등) — 이 티켓은 순수 레이아웃 셸 교체
