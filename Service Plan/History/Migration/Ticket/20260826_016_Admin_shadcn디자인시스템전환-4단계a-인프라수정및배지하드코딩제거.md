# [Admin] shadcn 디자인시스템 전환 — 4단계a: 인프라 수정 + 배지 도메인 하드코딩 제거

## 배경 / 문제 정의

전체 배경은 `Service Plan/Specs/PRD/AdminUI/REDESIGN.md`(1절 "완전 분리" 원칙) 참조.
실행 순서·화면별 분배·완료 기준은 `Service Plan/Specs/PRD/AdminUI/PHASES.md`의
"Phase 4 — 하드코딩 제거" 절 참조 — **시작 전 반드시 먼저 읽을 것.**

1~3단계(폴더 분리·테마·Sidebar·Data Table)로 shadcn 프레임워크 자체는 다 갖춰졌지만,
기존 폼·모달 코드는 여전히 `text-[#111111]`/`border-[#e5e7eb]`/`bg-[#f8f9fa]` 같은
하드코딩 hex 클래스를 쓴다(전체 39개 파일 824건 실측). 이 티켓(4단계a)은 그중 가장 큰
덩어리인 배지 도메인 + 이후 모든 하위 티켓의 전제조건인 인프라 버그 2건을 처리한다.

## 상세 요구사항

### 1. 선행 인프라 수정 (이후 4b/4c/4d의 전제조건, 먼저 처리할 것)

**1-1. `--color-border` 스코프 누락**

`jam-web/src/app/globals.css`의 `@theme` 블록에 있는 `--color-border: var(--color-border)`는
DS v2(서비스 본체)가 `design-system/tokens/colors.css`의 `:root` 선언을 `border-border`
Tailwind 유틸리티로 노출하는 기존(20260820_003) 매핑이다. 1단계가 `[data-admin-theme]`
스코프 안에 shadcn 프리셋 원시 변수(`--border` 등)는 넣었지만, 이 **유틸리티 매핑 이름**
(`--color-border`)을 스코프 안에서 재정의하지 않아서, 어드민 스코프 안에서
`border-border` 클래스를 써도 여전히 서비스 다크 테두리 색으로 풀린다.

`[data-admin-theme]` 블록 안에 `--color-border: var(--border)`를 추가로 오버라이드할 것.
같은 이름 충돌 패턴이 다른 시맨틱 클래스(`--color-background`, `--color-foreground`,
`--color-primary` 등)에도 있는지 `grep -n "color-background\|color-foreground\|color-primary\|
color-secondary\|color-muted\|color-accent" src/app/globals.css`로 함께 점검하고, 있으면
같이 고칠 것. 수정 후 브라우저에서 `border-border`/`bg-background` 등 클래스가 실제
stone 테마 색으로 렌더링되는지 반드시 확인(1단계가 `--background`/`--foreground`에 썼던
`getComputedStyle` 검증 방식과 동일하게).

**1-2. Radix Portal 스코프 (dialog/alert-dialog/select)**

`sheet.tsx`(2단계, `src/components/admin/ui/sheet.tsx`)가 이미 가진 패턴 —
`container?: React.ComponentProps<typeof SheetPortal>["container"]`을 prop으로 받아
Radix Portal에 전달 — 을 `src/components/admin/ui/dialog.tsx`,
`src/components/admin/ui/alert-dialog.tsx`, `src/components/admin/ui/select.tsx`
세 파일에도 동일하게 추가한다. 이 prop 자체는 이번 티켓에서 당장 쓰이지 않아도 된다
(인터페이스만 갖춰두면 4b/4c/4d에서 이 컴포넌트들을 시맨틱 클래스로 바꿀 때 바로 쓸 수
있음) — 단, 이 컴포넌트들을 호출하는 곳(주로 `[data-admin-theme]` 하위)에서 실제로
`container={document.querySelector('[data-admin-theme]')}` 같은 형태로 넘겨야 스코프
안에서 렌더링되니, 최소 1곳(배지 관련 다이얼로그/셀렉트 중 하나)에서 실제로 연결해
동작을 확인할 것.

### 2. 배지 도메인 하드코딩 제거

대상 파일(실측 occurrence 수):
- `src/app/admin/badges/BadgeForm.tsx` (160건 — 가장 큼)
- `src/app/admin/badges/BackgroundGeneratorPreview.tsx` (28건)
- `src/components/admin/BadgeMultiSearchSelect.tsx` (13건)
- `src/components/admin/BadgeSearchSelect.tsx` (9건)

`text-[#111111]` → `text-foreground`, `border-[#e5e7eb]` → `border-border`,
`bg-[#f8f9fa]` → `bg-muted` 식으로 shadcn 시맨틱 토큰에 매핑한다. 정확한 매핑은 색상값을
보고 가장 가까운 시맨틱 의미로 판단할 것(예: 어두운 텍스트는 `text-foreground`, 옅은
회색 텍스트는 `text-muted-foreground`, 테두리는 `border-border`, 옅은 배경은 `bg-muted`
또는 `bg-accent`). 애매하면 `npx shadcn@latest docs` 관련 컴포넌트 문서나 이미 3단계에서
변환된 Data Table 컴포넌트들의 클래스 사용례를 참고할 것.

**주의**: `BackgroundGeneratorPreview.tsx`는 배지 배경 테마(WebGL 셰이더 미리보기)를
다루는데, 이 컴포넌트가 렌더링하는 **미리보기 결과물 자체**(배지 카드처럼 보이는 부분)는
유저가 실제로 보게 될 서비스 화면을 시뮬레이션하는 거라 MODULAR 색상을 쓰는 게 맞을
수 있다 — 이 컴포넌트를 열어보고 "어드민 편집 UI 껍데기"와 "미리보기 결과물" 부분을
구분해서, 껍데기만 shadcn으로 바꾸고 미리보기 결과물 부분은 그대로 둘 것(애매하면 현재
상태를 유지하고 완료 기록에 판단 근거를 남길 것).

  Data Table 공용 컴포넌트) — 재사용만 하고 재설계하지 않는다
