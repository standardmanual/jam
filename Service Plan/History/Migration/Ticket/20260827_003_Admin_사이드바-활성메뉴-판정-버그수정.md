# [Admin] 사이드바 활성 메뉴 판정 버그 수정 (`/admin/points` → "POI 관리" 오표시)

## 배경 / 문제 정의
`src/components/admin/adminNavItems.ts`의 `isNavItemActive` 함수가 `exact`가 아닌 항목에 대해
`pathname.startsWith(item.href)`만 사용한다. `/admin/poi`가 `/admin/points`의 문자열 접두어이기
때문에(`'/admin/points'.startsWith('/admin/poi')` === `true`), `/admin/points`에 접속하면
"POI 관리" 메뉴 항목이 사이드바에서 잘못 활성(하이라이트)된다.

`AdminHeader.tsx`도 동일한 `isNavItemActive`로 페이지 타이틀을 뽑기 때문에, 상단 헤더 타이틀도
"포인트 관리" 대신 "POI 관리"로 잘못 표시된다. 페이지 본문 헤딩 자체는 정상("포인트 관리")이라
증상이 사이드바·헤더에만 국한된다.

2단계 shadcn Sidebar 전환(티켓 20260826_013) 산출물에서 비롯된 버그이며, 3단계b(티켓 20260826_015)
게이트 리뷰 중 발견됐다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `isNavItemActive`(`src/components/admin/adminNavItems.ts:48-51`)를 단순 `startsWith`가 아니라
  정확히 일치하거나 그 다음 문자가 `/`인 경우만 매칭하도록 수정한다.
  (예: `pathname === item.href || pathname.startsWith(item.href + '/')`)
- 아래처럼 하위 경로 매칭이 계속 필요한 항목들이 깨지지 않는지 확인한다:
  - `/admin/badges/new`, `/admin/badges/[id]` → `/admin/badges` 활성 유지
  - `/admin/poi/new`, `/admin/poi/[id]`, `/admin/poi/categories` → `/admin/poi` 활성 유지
  - `/admin/itembooks/new`, `/admin/itembooks/[id]` → `/admin/itembooks` 활성 유지
  - `/admin/factions/new`, `/admin/factions/[id]` → `/admin/factions` 활성 유지
  - `/admin/users/[id]` → `/admin/users` 활성 유지
- 반대로 `/admin/points`는 `/admin/poi`와 더 이상 매칭되지 않아야 한다(이번 버그의 핵심 케이스).
- `activeNavGroupId`도 같은 함수를 재사용하므로 함께 검증한다(사이드바 그룹 펼침 상태 영향).

### UI/UX 관점 (해당 시)
- 사이드바 메뉴 하이라이트, 상단 헤더 타이틀 둘 다 실제 페이지와 일치해야 한다.

## 구현 계획
`isNavItemActive`의 `exact`가 아닌 분기만 수정하는 최소 변경. 로컬 재현은
`ADMIN_EMAILS`를 `dev-tester@jam.local`로 오버라이드 → `/api/dev-login` 로그인 →
`/admin/points`, `/admin/poi`, `/admin/badges/new` 등 하위 경로를 순회하며 사이드바·헤더 확인.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`isNavItemActive`의 `exact`가 아닌 분기를 `pathname.startsWith(item.href)` 단일 조건에서
`pathname === item.href || pathname.startsWith(item.href + '/')`로 수정했다. 이 함수는
`AdminSidebar.tsx`(메뉴 하이라이트, `activeNavGroupId`를 통한 그룹 펼침 상태)와
`AdminHeader.tsx`(페이지 타이틀)에서 공용으로 사용하므로 한 곳 수정으로 양쪽 증상이 모두 해결된다.
