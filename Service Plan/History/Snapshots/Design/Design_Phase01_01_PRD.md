## 1. 제품 개요

### 한 줄 요약
JAM!의 기존 네오브루탈리즘 UI(두꺼운 테두리 + 오프셋 섀도우 + 다색 팔레트 + 이모지 아이콘)를 SuperHi Plus 디자인 스펙(코발트/아이스화이트 바이너리 컬러, Pretendard 400 단일 웨이트, 1px inset border, 이모지 금지) 기반으로 전면 리뉴얼하되, iOS Human Interface Guideline의 UX 패턴(터치 영역, 바텀 탭바, 바텀시트, 세이프 에어리어 등)은 그대로 유지·강화한다.

### 해결하는 문제
- 현재 UI는 톤이 확실하지만(게임형 네오브루탈리즘), 핀테크/에디토리얼급 절제된 룩앤필로 브랜드를 갱신하고 싶다.
- 30여 개 파일에 네오브루탈 카드 스타일이 복사-붙여넣기되어 있어 유지보수 비용이 크다 — 공통 컴포넌트 부재.
- 다국어 확장을 위해 하드코딩된 한글 문자열을 구조적으로 분리해야 한다.
- 향후 어드민이 브랜드 컬러를 직접 바꿀 수 있는 유연성이 필요하다(화이트라벨/시즌 이벤트 대응).

### 핵심 가치
- **UX 뼈대는 그대로, 표면만 재도색**: 정보구조·네비게이션·인터랙션 흐름은 HIG 기준으로 유지/보강하고, 시각적 스타일만 SuperHi Plus 토큰으로 교체한다. 리스크를 낮추고 회귀 버그를 최소화한다.
- **공통 컴포넌트화**: 반복되던 카드/버튼/네비 패턴을 이번 기회에 재사용 컴포넌트로 승격시켜, 이후 디자인 변경이 훨씬 쉬워진다.
- **어드민 테마 가변성**: 하드코딩된 2색을 CSS 변수 + DB 설정으로 분리해, 코드 배포 없이 브랜드 컬러를 바꿀 수 있게 한다.

## 2. 사용자

### 주요 사용자
- **일반 유저**: JAM! 앱을 모바일 웹으로 사용하는 러너/워커 — 투데이 피드, 배지 수집, 미션 참여, 프로필 확인이 핵심 동선.
- **어드민(운영자)**: 배지/미션/포인트 정책을 관리하며, 이번 리뉴얼로 브랜드 메인/서브 컬러와 상태 팔레트(희귀도/카테고리 색)를 실시간으로 조정하게 된다.

### 사용자 시나리오
1. 유저가 마이페이지에 진입하면 코발트/아이스 바이너리 톤의 프로필 헤더, 통계바, 배지 그리드를 보게 되고
2. 기존과 동일한 탭 전환·팔로우·로그아웃 동작을 그대로 수행하면서
3. 더 절제되고 일관된 시각 경험을 얻는다.
4. 어드민은 테마 설정 화면에서 메인/서브 컬러를 컬러피커로 바꾸고 실시간 미리보기로 확인한 뒤 저장하면, 전체 서비스에 즉시 반영된다.

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름 (리뉴얼 작업 관점)
```
공통 컴포넌트 설계 -> 토큰/변수 시스템 구축 -> 프로필 화면 적용 -> 투데이 -> 배지(+상태 팔레트) -> 인벤토리/드랍/미션 -> BottomSheet 통합 -> 어드민 테마 UI
```

### 상세 흐름
1. **토큰 시스템 구축**: `globals.css`에 SuperHi Plus 토큰(코발트/아이스/미스트/피치)을 CSS 변수로 정의하고, 기존 `jam-*` 팔레트는 상태 팔레트 예외분(희귀도/카테고리)만 남기고 제거한다.
2. **공통 컴포넌트 작성**: `src/components/ui/`에 `TopNav`, `TabBar`(기존 TabBar.tsx 리팩터링), `Card`, `Button`을 만들고 1px inset border + 무섀도우 규칙을 강제한다.
3. **화면별 적용**: 결정된 순서(프로필 → 투데이 → 배지 → 인벤토리/드랍/미션)대로 화면을 하나씩 새 컴포넌트로 교체하고, 매 화면마다 실제 브라우저에서 회귀 테스트한다.
4. **상태 팔레트 어드민 기능**: 희귀도(common/rare/legendary/mythic) 4색 + 카테고리 색상을 어드민이 관리하는 팔레트 테이블로 이관한다.
5. **어드민 테마 UI**: 메인/서브 컬러 컬러피커 + 실시간 미리보기 화면을 어드민에 추가한다.

## 5. 성공 기준

- [ ] 리뉴얼된 모든 화면에서 터치 가능 요소가 44×44pt 이상을 만족한다.
- [ ] 드롭섀도/오프셋섀도가 완전히 제거되고 1px inset border로 대체된다 (상태 팔레트 예외 색상 제외, 제3의 컬러 사용 없음).
- [ ] 사용자 화면에서 등록된 배지/아이템북 이미지를 제외한 모든 이모지가 SVG 아이콘으로 교체된다.
- [ ] TopNav/TabBar/Card/Button 4개 공통 컴포넌트가 만들어지고, 최소 5개 이상의 화면에서 재사용된다.
- [ ] 어드민에서 메인/서브 컬러를 바꾸면 실시간 미리보기와 실제 서비스 화면에 CSS 변수로 반영된다.
- [ ] 하드코딩된 UI 문구가 최소 1개 화면(마이페이지)에서 i18n 딕셔너리 키 참조 방식으로 전환된다.
- [ ] 바텀시트가 필요한 화면에서 드래그 핸들 + 스와이프다운 닫기가 동작한다.

## 6. 안 만드는 것 (Out of Scope)

> 이 목록은 이번 리뉴얼(Phase 1~2)에서 만들지 않습니다.

- 영어 등 실제 번역 파일 작성 — 이유: 이번 범위는 "구조 준비"까지로 합의됨. 번역은 별도 작업.
- DB에 저장된 배지명/미션명/아이템북명의 다국어 컬럼 추가 — 이유: UI 문구 i18n과 작업 성격이 달라 범위 초과.
- 어드민 화면(admin/*) 내부의 이모지 아이콘 교체 — 이유: 내부 관리자 전용 화면이라 우선순위 낮음(Phase 3 후보).
- 컬러 프리셋 방식이 아닌 완전 자유 커스텀 브랜드 테마(폰트 교체, 레이아웃 변경 등) — 이유: 스펙은 컬러 2종 + 상태 팔레트까지만 가변으로 정의.
- 기존 BottomSheet 3종(BadgeDetailSheet, InventoryItemHistorySheet, ShareCardModal)을 공통 컴포넌트로 완전히 마이그레이션하는 것 — 이유: Phase 2로 분리, Phase 1은 4대 공통 컴포넌트(TopNav/TabBar/Card/Button)까지만.

## 7. [NEEDS CLARIFICATION]

- [ ] `state_color_palette`의 `scope` 종류를 배지 희귀도/카테고리 외에 어디까지 미리 정의해둘지 (팩션, POI 카테고리 등) — Phase 2 착수 시점에 재검토.

### 확정된 결정 (변경 불가 기준)

- 상태 팔레트(희귀도/카테고리) 색상값은 기존 `jam-lime/teal/purple/yellow`를 **그대로 재사용**한다 (재조정 없음).
- 브랜드 컬러는 싱글턴이 아닌 **`theme_presets` 다중 프리셋 구조**로 저장하고, 그중 1개만 활성화(`is_active`)하는 방식으로 시즌 이벤트 컬러 전환을 지원한다. 전환은 **즉시 적용만** 지원(예약 발행 없음).
- Pretendard 웹폰트는 **CDN import** 방식(`pretendard@v1.3.9`)을 사용한다 (self-host 전환 없음).
- 상태 팔레트 어드민 UI는 희귀도 4개(`common`/`rare`/`legendary`/`mythic`) **고정 슬롯**이며 색상만 수정 가능 — 슬롯 자유 추가/삭제 불가.
- 화면은 **다크 테마 고정 유지**(현재와 동일). 단, 향후 라이트 테마 확장 가능성을 열어두기 위해 색상 토큰은 시맨틱 이름(`--color-surface`, `--color-text` 등)으로 설계하고 dark 값을 하드코딩하지 않는다 — 실제 라이트 테마 구현은 이번 범위 밖.
- 신규 테이블(`theme_presets`, `state_color_palette`)의 RLS는 전체 유저 SELECT 허용 + admin 역할만 쓰기 가능.
