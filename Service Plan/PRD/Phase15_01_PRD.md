# JAM! Phase 15 PRD — 홈 → '투데이' 개편

> 작성일: 2026-07-26
> 참고자료: 유저 첨부 "애플 앱스토어 투데이 메뉴 분석" 문서
> 로직 원천: `jam-web/src/app/(main)/page.tsx`(현재 홈), `jam-web/src/app/(main)/TabBar.tsx`

---

## 1. 배경 및 목표

### 현행 분석 (2026-07-26 코드 확인)

**이미 있는 것:**
- 홈(`/`)은 이미 인사말 + Strava 연동 카드 + 유저검색 + "최근 배지" 4개 + 바로가기(미션/인벤토리/드랍/조합) + 통합 피드(`HomeFeedSection`, 배지·아이템·미션 이벤트 최대 200개) 구조. 즉 "내가 한 일" 중심의 개인 피드는 이미 있음.
- 콘텐츠 재료가 될 실제 데이터: 배지(`badges`, rarity/type/조건), 아이템북 완성 이벤트(`user_item_book_completions`), 미션(`missions`, Phase13에서 상태표시타입·복수보상 지원), 드랍(`poi_drops`, Phase14에서 UI 개편).
- 어드민 CRUD 패턴: `missions`/`itembooks`/`poi`처럼 "목록 페이지 + 리스트 컴포넌트(인라인 생성폼)" 구조가 표준.

**이번 Phase에서 없는 것(신규로 만들어야 함):**
- "오늘의 추천/소개" 개념의 콘텐츠 자체가 없음 — 지금 홈은 전부 "내가 한 일"만 보여주고, "내가 안 해본 것/시도해볼 만한 것"을 큐레이션해서 보여주는 기능이 없음.
- 어드민에 콘텐츠(카드) CMS가 없음.
- 아티클(기사) 형태 콘텐츠를 서빙할 라우트가 없음.
- 유저의 활동 기록을 장기간 조회 가능한 원본 테이블이 없음(Strava 동기화 시점에만 일시적으로 사용되고, 결과인 `user_activity_badges` 등만 영구 저장됨) — "러닝 많이 하는 유저" 같은 자동 세그먼트 판정은 이번 Phase 범위에서 구현 불가(§5 비범위 참고).

### Phase 15 목표

1. **하단 탭 "홈" → "투데이"로 개명** — 컨셉을 "내 활동 로그"에서 "오늘 소개할 콘텐츠"로 확장.
2. **콘텐츠 카드 스택 신설** — 배지·아이템북·미션·드랍을 다양한 포맷(소개/진행알림/트렌드/기사)으로 소개해 참여·관심을 유도.
3. **어드민 콘텐츠 CMS 신설** — 카드 타입 선택 → 타입별 입력 템플릿 → 시작/종료 일시 지정(예약 발행) → 노출 조건(태그) 설정.
4. **수동 태그 기반 조건부 노출** — 완전 자동 추천은 다음 Phase, 이번엔 어드민이 카드 제작 시 "노출 조건 태그"를 직접 골라 붙이고, 서버는 그 태그와 유저의 (계산 가능한) 현재 상태를 매칭해서 보여줄지 결정.
5. **아티클형 콘텐츠 지원** — "○○의 도전일기" 같은 기사형 콘텐츠는 실제 웹페이지로 렌더링, 카드에서 링크.
6. **샘플 콘텐츠 30개 시뮬레이션 생성 + 실제 서비스 반영** — 실제 배지/미션/아이템북 데이터를 활용해 30개 카드 제작(아티클형은 가상 기사 본문 포함), 운영 중인 느낌을 살림.

## 2. 확정된 결정사항 (인터뷰 결과)

| 항목 | 결정 |
|------|------|
| 콘텐츠 노출 범위 | **카드마다 개별 시작/종료 일시**(`starts_at`/`ends_at`) 지정. "오늘"은 고정된 하루 단위가 아니라, 현재 시각이 그 구간에 포함되는 카드들의 스택. 미션(`starts_at`/`ends_at`) 패턴과 동일해서 기존 컨벤션과 일관됨. |
| Phase 15 개인화 범위 | **수동 태그 조건부 노출.** 어드민이 카드 제작 시 노출 조건 태그를 선택(예: 시간대, 참여중 미션 존재 여부). 유저별 진짜 추천 알고리즘은 Phase 2. |
| 예약 발행 | **지원.** 어드민이 미래 날짜의 카드를 미리 만들어두면 `starts_at` 도달 시 자동 노출, `ends_at` 지나면 자동 숨김. |

## 3. 콘텐츠 템플릿 taxonomy (유저 제시 10개 예시 → 7개 타입으로 정리)

| # | 템플릿 | 유저 예시 | 핵심 데이터 |
|---|--------|-----------|--------------|
| 1 | `badge_spotlight` (배지 소개) | "이런 배지 어때요?", "핫한 성수동에서 발견된 레전드 배지 5" | `badges`(복수 선택 가능) |
| 2 | `progress_nudge` (진행 알림) | "곧 받게 될 배지 TOP5", "참가중인 미션 남은 달성조건" | `badges`/`missions` 참조 — **Phase 15는 실제 진행률 자동계산 없이 어드민이 정적 카피로 작성**(§5 참고), 노출 조건 태그로 대상만 좁힘 |
| 3 | `mission_spotlight` (미션 소개) | "곧 종료되는 미션 참여해보세요" | `missions` |
| 4 | `itembook_milestone` (아이템북 소식) | "극악의 아이템북을 처음 완성한 유저 소개" | `item_books`, 완성자 닉네임(수동 입력 또는 실데이터 조회) |
| 5 | `location_trend` (지역 트렌드) | "핫한 성수동에서 발견된 레전드 배지 5" | `badges` + 지역명 텍스트(자유 입력) |
| 6 | `drop_alert` (드랍 유도) | "지금 주변에 드랍된 아이템배지를 확인해보세요" | 고정 CTA, `target_href=/drops` |
| 7 | `editorial_article` (에디토리얼 기사) | "슈처 루키의 도전일기" | 자체 본문(마크다운) + 표지 이미지, 전용 상세 페이지로 링크 |

- "새벽 접속 시 침대 박차고 일어나면 받을 배지" 같은 **상황 맞춤형 카피**는 별도 템플릿이 아니라 **템플릿 1(badge_spotlight) + 노출조건 태그(`time_dawn`)**의 조합으로 구현.
- 템플릿별 상세 필드는 Phase15_02_DATA_MODEL.md §2 참고.

## 4. 노출 조건 태그 (Phase 15 구현 가능 범위)

실제로 DB에서 조회 가능한 값만 태그로 채택 — "러닝 많이 하는 유저"처럼 원본 활동 로그가 필요한 조건은 이번 범위 제외(§5).

| 태그 | 판정 방법 | 자동/수동 |
|------|-----------|-----------|
| `all` | 항상 매칭(기본값) | 고정 |
| `time_dawn`(00~06시) / `time_morning`(06~11) / `time_afternoon`(11~17) / `time_evening`(17~21) / `time_night`(21~24) | 요청 시점 서버 시각(KST) | 자동 계산 |
| `has_participating_mission` | `user_mission_participations`에 진행 중 미션 존재 | 자동 계산 |
| `has_ending_soon_mission` | 참가 중이고 `ends_at`이 3일 이내인 미션 존재 | 자동 계산 |
| `has_incomplete_itembook` | 슬롯 일부만 채운 미완성 아이템북 보유 | 자동 계산 |
| `new_user`(가입 7일 이내) | `users.created_at` | 자동 계산 |

- 카드는 노출조건 태그를 **복수 선택** 가능(OR 매칭 — 유저가 그중 하나라도 해당하면 노출).
- `all`이 포함돼 있으면 다른 태그와 무관하게 항상 노출.

## 5. 사용자 여정

### 5-1. 투데이 탭 진입 (유저)

```
1. 하단 탭 "투데이" 클릭 (기존 "홈" 자리, 아이콘/경로는 "/" 그대로)
2. 상단에 투데이 카드 스택 노출 — starts_at<=now<=ends_at 이고
   내 현재 태그와 매칭되는 카드들을 sort_order 순으로 세로 스택
3. 카드 클릭:
   - editorial_article → 전용 기사 페이지(/today/[cardId])로 이동
   - 그 외 → target_href(배지/미션/아이템북 상세, 또는 /drops)로 이동
4. 카드 스택 아래는 기존 홈 구성(최근 배지/바로가기/피드) 그대로 유지 — 회귀 없음
```

### 5-2. 어드민 카드 제작

```
1. /admin/today 진입 — 날짜순으로 쌓인 카드 목록(카드형 UI)
2. [+ 콘텐츠 추가] 클릭 → 템플릿 타입 선택(7종 중 택1)
3. 타입별 입력 폼 노출(§3 표의 "핵심 데이터" 필드들 + 공통 필드: 제목/부제/커버이미지/시작일시/종료일시/노출조건 태그/정렬순서)
4. 저장 → starts_at 도달 시 자동 노출, ends_at 지나면 자동 숨김(별도 배치 불필요, 조회 시점에 필터링)
```

## 6. 기능 요구사항

### 6-1. 하단 탭 개명

- `TabBar.tsx`의 `label: '홈'` → `label: '투데이'`. href/아이콘/active 판정 로직은 변경 없음.

### 6-2. 투데이 카드 스택 (홈 화면 상단)

- 신규 섹션, 기존 홈 콘텐츠(최근 배지/바로가기/피드) 위에 삽입.
- 카드 없음(조건 매칭 카드가 하나도 없음)이면 섹션 자체를 숨김 — 빈 상태 UI 불필요.

### 6-3. 어드민 CMS

- 목록: 날짜(starts_at) 내림차순, 카드형 UI로 스택.
- 생성: 템플릿 선택 → 동적 폼 → 저장.
- 수정/비활성화(`is_active`) 가능.

### 6-4. 아티클 페이지

- `/today/[cardId]` — `editorial_article` 타입 카드 전용. 커버 이미지 + 제목 + 마크다운 본문 렌더링. 로그인 여부 무관하게 접근 가능(공유 링크 용도 고려, 단 이번 Phase는 내부 링크만 지원 — SNS 공유 최적화는 비범위).

### 6-5. 노출조건 매칭

- 서버 컴포넌트에서 위 §4 태그를 계산 → `today_cards` 조회 시 `exposure_tags && ARRAY[...유저태그, 'all']` 배열 겹침 연산으로 필터.

## 7. 비범위 (Out of Scope — Phase 2 후보)

- **활동 데이터 기반 자동 세그먼트**("러닝 많이 하는 유저", "곧 배지 받을 유저 TOP5"의 실제 자동 계산) — 원본 활동 로그 테이블 신설 + 배지 조건 근접도 계산 로직 필요, 별도 Phase.
- 완전 자동 추천 알고리즘(유저별 다른 카드 순서/선택).
- 아티클 SNS 공유 최적화(OG 태그 커스터마이징, 카카오톡 공유 등).
- 카드 성과 지표(클릭률 등) 대시보드.
- 알림/푸시 연동(신규 카드 등록 시 알림 발송).

## 8. 완료 기준

- [ ] 하단 탭이 "투데이"로 표시됨
- [ ] 투데이 카드 스택이 홈 상단에 노출되고, 시작/종료 일시·노출조건 태그가 정확히 적용됨
- [ ] 어드민에서 7종 템플릿 중 하나를 선택해 카드를 만들 수 있고, 타입별 입력 필드가 다르게 노출됨
- [ ] `editorial_article` 카드 클릭 시 전용 기사 페이지로 이동, 본문이 정상 렌더링됨
- [ ] 그 외 템플릿 카드 클릭 시 연결된 배지/미션/아이템북/드랍 화면으로 정상 이동
- [ ] 노출조건 태그가 매칭되지 않는 유저에게는 해당 카드가 보이지 않음(자동 계산 태그 기준)
- [ ] 예약 발행: 미래 `starts_at`인 카드는 그 시각 전까지 노출 안 됨, `ends_at` 지나면 자동 숨김
- [ ] 샘플 카드 30개가 실제 서비스 DB에 등록되어 투데이 탭에서 확인 가능
- [ ] 기존 홈 콘텐츠(최근 배지/바로가기/피드) 회귀 없음
- [ ] `npx tsc --noEmit` 0 에러
