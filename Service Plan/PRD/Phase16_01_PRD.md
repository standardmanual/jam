# JAM! Phase 16 PRD — POI 배지 타입 추가

> 작성일: 2026-07-27
> 로직 원천: `jam-web/src/lib/badge-engine/index.ts`, `jam-web/src/lib/strava/sync.ts`, `jam-web/src/lib/poi/matcher.ts`, `jam-web/src/lib/itembook/checker.ts`, `jam-web/src/app/admin/badges/BadgeForm.tsx`

---

## 1. 배경 및 목표

### 현행 분석 (2026-07-27 코드 확인)

**이미 있는 것 (놀랍게도 절반은 이미 동작 중):**
- `poi.linked_badge_id` — POI 하나가 배지 하나를 가리키는 FK가 이미 스키마에 있음(Phase 1부터).
- `matchPoisForActivity()`(`src/lib/poi/matcher.ts`) — 유저의 Strava 활동 GPS 경로(Streams API)가 POI 반경(`poi.radius_meters`, 기본값 **50m**) 안을 지나가는지 Haversine으로 판정하는 로직이 이미 있음.
- `syncStravaActivities()`(`src/lib/strava/sync.ts`)가 동기화할 때마다 이 매칭을 실행해서, 반경 안을 지나간 POI에 `linked_badge_id`가 있으면 `user_activity_badges`에 배지를 발급 — **즉 "액티비티가 POI를 포함하면 발급"은 이미 동작한다.**
- `user_activity_badges.triggered_by_poi_id` 컬럼도 이미 있고, 배지 상세 페이지(`badges/[id]/page.tsx`)는 이미 `poi:triggered_by_poi_id(...)` 조인까지 걸어둔 상태.
- 배지 조건 빌더(`BadgeForm.tsx`)에 `condPoiId`라는 죽은 필드가 있음 — `condition_json.poi_id`는 배지 엔진에서 **항상 false**로 막혀 있고(주석: "POI 배지는 GPS 경로 매칭으로만 발급됨"), 실제로는 위 `linked_badge_id` 경로로만 발급됨. 미완성 상태로 방치된 코드.
- 아이템북은 Phase 8에서 "인벤토리 아이템 보유" 모델로 재설계됨 — `badges.item_book_id`(배지가 북에 소속)로 멤버십을 정하고, `user_item_book_slots`(유저가 그 인벤토리 아이템을 북에 꽂음) 개수가 북 소속 배지 총 개수에 도달하면 완성(`checkItemBookCompletion`). `required_activity_badge_id`는 Phase 8에서 이미 nullable로 풀려 있음.

**이번 Phase에서 없는 것(신규로 만들어야 함):**
- `badge_type` ENUM에 `'poi'`가 없음(`'activity' | 'item'`만 존재) — 어드민에서 "POI 타입"으로 명시적으로 만들 수 없고, 지금은 그냥 `activity` 타입 배지를 만들어 POI 어드민 폼에서 몰래 연결하는 우회 방법만 있음.
- **반복 획득이 안 됨** — `user_activity_badges`에 `UNIQUE(user_id, badge_id)` 제약이 있어서, `sync.ts`도 발급 전에 "이미 보유했는지" 확인 후 있으면 건너뜀. 즉 지금 구조로는 같은 POI를 몇 번을 지나가도 딱 1번만 발급됨.
- 어드민에서 "POI 검색해서 배지에 연결" UI가 없음 — 지금은 반대 방향(POI 등록 화면에서 배지 1개를 고르는)만 있고, 배지 등록 화면에서 POI를 검색해 붙이는 방향은 없음. 또한 배지 1개에 POI 여러 개를 연결하는 UI도 없음(스키마는 이미 가능 — 여러 POI 행이 같은 `linked_badge_id`를 가리키면 됨).
- 배지 상세 화면의 "획득 이력" 리스트(최신순, 복수 건) — 지금은 `earned_at` 1건만 조회하는 구조.
- 아이템북 완성 로직이 `type='item'` 배지만 카운트함 — `poi` 타입 배지를 북에 넣었을 때 완성 조건에 포함되지 않음.
- 어드민 배지 목록에 페이지네이션이 없음(전체 목록을 한 번에 렌더링).

### Phase 16 목표

1. **배지 타입에 `poi` 추가** — 어드민에서 활동/아이템과 동급으로 "POI" 타입을 선택해 만들 수 있게 함.
2. **배지 ⇄ POI 다중 연결 UI** — 배지 등록/수정 화면에서 등록된 POI를 검색해 여러 개 연결(추가/삭제) 가능.
3. **반복 획득 지원** — 같은 배지를 여러 번(같은 POI든 다른 POI든, 방문할 때마다) 발급받을 수 있도록 새 발급 경로 신설. 기존 활동/아이템 배지의 "1인 1회" 규칙은 그대로 유지(건드리지 않음).
4. **배지 상세 화면에 획득 이력(최신순) 표시** — `poi` 타입 배지에 한해 목록형으로 표시.
5. **아이템북 구성에 `poi` 배지 포함/단독 구성 허용** — 완성 판정 로직 확장.
6. **어드민 배지 목록 페이지네이션** — 1,2,3... 숫자 네비게이션(Phase 15에서 POI 관리 화면에 이미 만든 `Pagination.tsx` 패턴 재사용).

## 3. 기능 요구사항

### 3-1. 어드민 — 배지 타입 `poi` 추가

- `badge_type` ENUM에 `poi` 추가.
- `/admin/badges` 등록/수정 폼(`BadgeForm.tsx`): 타입 선택에 "POI" 추가. `poi` 선택 시:
  - 기존 활동 조건 빌더(거리/횟수/고도/속도/연속일수/계절/기온/시간대 등) **숨김** — POI 배지는 조건이 아니라 "어느 POI를 지나갔는가"로만 판정됨.
  - 대신 **"연결된 POI" 섹션** 노출: 이름으로 POI를 검색해 추가/삭제할 수 있는 다중 선택 UI(기존 `PoiForm.tsx`의 네이버 검색 UI가 아니라, 이미 DB에 등록된 `poi` 테이블을 이름으로 검색 — 신규 API 필요).
  - 각 연결된 POI 옆에 반경(`radius_meters`) 표시 + 인라인 수정 가능(기본 50m).
- `condition_json.poi_id` 관련 죽은 필드(폼 state `condPoiId`, 엔진의 `evaluateConditionDetailed` 내 poi_id 분기) 제거.

### 3-2. 어드민 — 배지 목록 페이지네이션

- `/admin/badges` 목록 하단에 숫자 페이지네이션(1,2,3,4...) 추가. `jam-web/src/app/admin/poi/Pagination.tsx` 컴포넌트를 그대로 재사용(범용화해서 옮기거나 복제 — Step 단계에서 결정).
- 페이지 크기: POI 관리와 동일하게 30개.

### 3-3. 서비스 — 반복 획득 가능한 POI 배지

- Strava 동기화(`syncStravaActivities`) 중 GPS 경로가 POI 반경을 통과하면:
  - 연결된 배지가 `type='poi'`이면 → **매번** `user_poi_badge_earns`에 새 행 추가(중복 방지 없음, 단 같은 Strava 활동 재처리로 인한 완전 동일 중복만 방지 — §Phase16_02 참고).
  - 연결된 배지가 `type='activity'`(레거시 호환)이면 → 기존 로직 그대로(`user_activity_badges`, 1회만).

### 3-4. 서비스 — 배지 상세 화면 획득 이력

- `badges/[id]/page.tsx`: `badge.type === 'poi'`이면 단건 `earned_at` 대신 **획득 이력 리스트(최신순)** 렌더링. 각 항목에 POI 이름 + 발생 시각 + (있으면) 트리거 Strava 활동명 표시.
- 활동/아이템 타입은 기존 UI 그대로(회귀 없음).

### 3-5. 서비스 — 아이템북 POI 배지 지원

- 아이템북 완성 판정(`checkItemBookCompletion`): 북 소속 배지 카운트를 `type IN ('item','poi')`로 확장. `item`은 기존처럼 `user_item_book_slots` 카운트, `poi`는 `user_poi_badge_earns`에서 **해당 배지를 1회 이상 획득한 적 있는지**(distinct badge_id 존재 여부)로 판정. 두 카운트를 합산해 "총 소속 배지 수"와 비교.
- 아이템북 상세 화면(유저용)에서 `poi` 타입 소속 배지는 "슬롯에 꽂기" 액션이 없고, 획득 여부만 뱃지로 표시(자동 반영 — 유저가 아무 조작 안 해도 Strava 싱크 시점에 자동으로 채워짐).

## 4. 사용자 여정

### 4-1. 어드민 — POI 배지 만들기

```
1. /admin/badges → [+ 배지 등록]
2. 타입에서 "POI" 선택 → 활동 조건 폼 사라지고 "연결된 POI" 섹션 노출
3. POI 이름 검색(예: "성수 대림창고") → 검색 결과에서 선택 → 리스트에 추가
   (필요하면 여러 개 더 검색해서 추가 — "전국 OO편의점 배지"처럼)
4. 각 POI의 발급 반경(기본 50m) 확인/수정
5. 이름/설명/이미지/희귀도/포인트 리워드 등 공통 필드 입력 후 저장
```

### 4-2. 유저 — POI 배지 반복 획득

```
1. 유저가 Strava로 러닝/라이딩 완료 → JAM! 앱이 동기화
2. 활동 GPS 경로가 POI 반경(예: 50m) 안을 지나감
3. 그 POI에 연결된 poi 타입 배지가 자동 발급 (몇 번째 방문이든 매번)
4. 배지 상세 화면 진입 → "획득 이력" 리스트에 이번 방문 건이 최상단에 추가되어 있음
```

### 4-3. 유저 — 아이템북에 POI 배지 포함

```
1. 어드민이 아이템북을 만들면서 POI 타입 배지 1개 이상을 소속시킴(아이템 배지와 섞어도 되고, POI 배지만으로도 됨)
2. 유저가 해당 POI를 한 번이라도 방문(=배지 획득)하면 그 즉시 "보유"로 카운트됨(슬롯팅 불필요)
3. 북 소속 배지를 전부 채우면(아이템은 슬롯팅 완료 + POI는 1회 이상 획득) 자동 완성 처리, reward_badge 있으면 지급
```

## 5. 비범위 (Out of Scope — Phase 2 후보)

- 배지 관리 메뉴를 POI 전용 메뉴로 완전히 분리(현재는 기존 배지 목록에 통합, "추후 분리 예정"으로만 명시)
- `poi_drops`(드랍/픽업) 시스템과의 연동 — POI 배지는 드랍/픽업과 완전히 무관하게 동작(GPS 경로 매칭으로만 발급)
- POI 배지 발급 알림/공유 카드
- 같은 활동에서 여러 POI를 동시에 지나갔을 때의 발급 순서/우선순위 최적화(현재도 순차 처리 — 성능 이슈 생기면 후속 Phase)
- 어드민 배지 목록의 검색/필터(이번엔 페이지네이션만)
