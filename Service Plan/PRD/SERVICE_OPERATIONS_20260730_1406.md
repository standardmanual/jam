## [정책 확정] 아이템북 슬롯 ↔ 인벤토리 용량 연동

**배경**: 인벤토리 진행률(`used_slots/max_slots`)이 실제와 안 맞는다는 문의(sihyunrr@gmail.com, 15/50 표시)를 조사하며 정책 자체가 미확정 상태였음을 확인. 확정된 정책:

- 발급받은 아이템배지는 인벤토리에 위치(최대 50, 추후 구매로 확장 가능).
- 아이템배지를 1개라도 보유하면 그 배지가 속한 아이템북이 노출됨 (`GET /api/itembooks` — 기존에 이미 구현돼 있었음, 변경 없음).
- 아이템북 상세화면은 인벤토리의 미슬롯 아이템 중 해당 북에 맞는 걸 슬롯에 "임시 배치"해 보여주고 '추가' 버튼 노출 (기존 `SlotGrid.tsx` 구현 그대로, 변경 없음).
- **'추가'** → 아이템이 아이템북에 편입되고 **인벤토리에서 빠짐(`used_slots -1`)**. 슬롯 활성화, 버튼이 '해제'로 전환.
- **'해제'** → 슬롯이 다시 '추가' 가능 상태가 되고, 아이템이 인벤토리로 복귀(`used_slots +1`). **인벤토리가 이미 꽉 찼으면(50/50) 해제 자체를 차단**하고 `"인벤토리가 꽉 차 해제할 수 없어요. 인벤토리를 늘려보세요."` 오류 반환.
- **아이템북 완성 기록**(`user_item_book_completions`)은 이후 조각을 해제해도 그대로 유지 — 완성은 한 번 달성한 업적으로 보존하고, 물리적 슬롯 상태(어떤 조각이 지금 꽂혀 있는지)만 별도로 변한다.

**관련 파일:** `src/app/api/itembooks/[id]/slot/route.ts`, `src/app/api/itembooks/[id]/route.ts`, `src/app/api/drops/route.ts`, `src/lib/combine/index.ts`, `supabase/migrations/068_used_slots_slot_policy_fix.sql`

### 코드 변경

1. **`POST /api/itembooks/[id]/slot`(추가)**: 슬롯 성공 시 `inventory.used_slots -= 1`. 이미 드랍(다른 유저에게 넘김)된 아이템은 슬롯 불가 가드 추가(`dropped_at` 체크 — 아래 버그 수정과 짝).
2. **`DELETE /api/itembooks/[id]/slot`(해제)**: 처리 전 `used_slots >= max_slots`면 409로 차단. 성공 시 `used_slots += 1`. 완성 기록 테이블은 원래도 안 건드리던 로직이라 추가 변경 없음.
3. **`GET /api/itembooks/[id]`**: 슬롯 후보 조회 쿼리에 `dropped_at IS NULL` 필터 추가 — 기존엔 이 필터가 없어 이미 드랍된 아이템도 "슬롯 가능"으로 잘못 표시됐음(아래 버그의 근본 원인).
4. **`POST /api/drops`(POI에 드랍)**: `slotted_in`이 있는(아이템북에 장착된) 아이템은 드랍 불가 가드 추가. 드랍 성공 시 `used_slots -= 1`(기존엔 드랍해도 칸이 안 줄던 별도 버그였음 — 같이 수정).
5. **`src/lib/combine/index.ts`(조합 재료 선택)**: 재료 소유권 확인 쿼리에 `slotted_in IS NULL AND dropped_at IS NULL` 필터 추가 — 기존엔 슬롯된 아이템도 조합 재료로 선택해 그대로 소각될 수 있었음.

### 발견한 버그 — 이번에 같이 수정

아이템북 상세화면(3번)이 "슬롯 가능한 아이템"을 찾을 때 `dropped_at`을 확인하지 않아, 이미 드랍한 아이템도 여전히 슬롯 가능으로 표시되고 실제로 슬롯까지 됐음. 그 결과 `slotted_in`과 `dropped_at`이 동시에 찍힌 모순 데이터가 발생 — sihyunrr 계정에서도 2건 확인됨. 마이그레이션 068에서 이런 행은 슬롯 해제(완성 기록은 유지)로 정리.

### 데이터 정합화 (마이그레이션 068)

- 모순 데이터(슬롯+드랍 동시) 정리: 슬롯만 해제, 완성 기록은 유지.
- 전체 유저 `inventory.used_slots`를 `COUNT(dropped_at IS NULL AND slotted_in IS NULL)`로 재계산 — 드랍/슬롯 시 칸 계산이 누락됐던 과거 이력을 일괄 정정.
- **참고**: sihyunrr@gmail.com 계정은 재계산 후 **0/50**이 됨 — 현재 보유 중인 9개 전부가 이미 아이템북에 슬롯돼 있어 인벤토리 자체는 비어있는 게 정책상 맞는 상태.

### ⚠️ 배포 후 수동 작업 필요

이번 세션엔 DB 실행 권한이 없어 마이그레이션 068을 직접 적용하지 못함. Supabase 대시보드 SQL 에디터에서 `supabase/migrations/068_used_slots_slot_policy_fix.sql` 내용을 그대로 실행해야 실제 데이터가 정정됨(코드 배포만으로는 기존 유저 데이터가 자동으로 안 고쳐짐).

### 범위 밖으로 남겨둔 것 — 확인 필요

**조합(`combine`) 결과 아이템 지급도 `used_slots`를 안 건드림** — 재료 N개 소각 후 결과 1개(또는 세계관 다양성 경로에선 여러 개) 지급 시 인벤토리 칸 계산이 이번 수정 범위 밖에서 여전히 어긋나 있음(오래된 별개 버그, 이번 이슈와 무관하게 존재). 별도로 다룰지 확인 필요.
