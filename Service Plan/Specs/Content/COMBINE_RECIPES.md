# 아이템 조합(믹스) 시스템 — 정책

> 관련 코드: `jam-web/src/lib/combine/index.ts`, `jam-web/src/lib/combine/policy.ts`
> 관련 어드민: `/admin/recipes` (레시피 CRUD), `/admin/combine-policy` (실패 보상 포인트)
> 관련 마이그레이션: `jam-web/supabase/migrations/153_combine_v3.sql`

## 1. 믹스 결과 두 갈래

| 경로 | 조건 | 결과 |
|---|---|---|
| **매칭** | `combination_recipes`의 재료가 정확히 일치(순서 무관)하고 보유 조건 배지를 전부 보유 | 레시피가 지정한 보상(`reward_points` + `reward_badge_ids` 전부)을 **확정 지급**. 확률 개념 없음 |
| **미매칭** | 위 조건을 만족하는 레시피 없음 | 배지를 전혀 지급하지 않고 `combine_policy.fail_reward_points`(고정 포인트)만 지급 |

**배지 지급은 어드민이 등록한 레시피를 통해서만 일어난다.** 재료로 투입한 아이템 개체는
성공/실패 무관하게 항상 소각된다(`Consume` 이벤트 + `destroyed_at` 소프트 삭제).

## 2. 레시피 구성

재료 슬롯에서 아이템·액티비티·체크인 배지를 타입 구분 없이 고르고, **저장 시점에 서버가
배지 타입으로 자동 분류한다**.

| 컬럼 | 담기는 배지 | 믹스 시 처리 |
|---|---|---|
| `ingredient_badge_ids` | 아이템 배지 (2~10개 필수) | 소각된다 |
| `required_badge_ids` | 액티비티·체크인 배지 (0개 이상) | 보유 여부만 검증, 소각되지 않음 |
| `reward_points` | — | 매칭 시 확정 지급 (0이면 미지급) |
| `reward_badge_ids` | 지급할 배지 | 무작위 추첨 없이 **전부** 지급 |

```
매칭 성립 = (유저가 투입한 아이템 배지 집합 == ingredient_badge_ids, 순서 무관 완전 일치)
          AND (required_badge_ids의 모든 배지를 유저가 보유)
```

보유 검증은 액티비티 배지가 `user_activity_badges`, 체크인 배지가 `user_checkin_badge_earns`를
조회한다. 보상은 포인트와 배지를 함께 지정할 수 있고, 둘 중 최소 하나는 있어야 저장된다.

어드민의 보상 배지 선택 UI에는 트라이브·컬렉션·등급 필터가 있다. **이 세 필터는 원하는
배지를 찾기 위한 검색 도구일 뿐 무작위 추첨 풀이 아니다.**

## 3. 실패 처리

- 미매칭 실패는 `combine_policy.fail_reward_points`(싱글톤 id=1, `/admin/combine-policy`에서
  조정) 고정 포인트만 지급한다. 포인트 사유 코드는 `combine_pity_reward`(표시 라벨 「믹스 실패
  보상」), 매칭 성공 보상 포인트는 `combine_recipe_reward`(「믹스 보상」)로 원장에 남는다.
- 모든 실패 시도는 `user_combine_fail_logs`에 1건씩 쌓인다(시도 일시 · 투입 재료 ·
  실패 사유 · 지급 포인트). 어드민 유저 상세에서만 조회하며 유저 화면에는 노출하지 않는다.
- **폐기(2026-09-10, 티켓 20260910_1408)**: 트라이브 다양성 티어 확률 경로(경로 B),
  피티 확률 보정·계단식 포인트, `success_rate`, `user_combine_state` 테이블. 경로 B는 아이템
  배지 보유 트라이브가 2종뿐인 실제 카탈로그에서 "소재 트라이브 제외" 후보가 0종이 되는
  인센티브 역전을 일으켰고, 티어2·3의 다양성 임계값(3종·5종)은 도달 자체가 불가능했다.

## 4. 레시피 카탈로그 현황 (2026-09-10 실측)

**등록된 레시피 0건이다.**

이전에 이 문서가 담고 있던 "정석 레시피 33선" 기획안은 **2026-09-10 폐기했다.** 폐기 사유는
아래와 같다.

- `057_seed_combine_recipes.sql`이 33선을 이름 키워드 매칭으로 자동 시딩하도록 작성되었으나,
  매칭 실패 시 조용히 스킵하는 설계였고 결과적으로 **한 건도 삽입되지 않았다**
  (프로덕션 `combination_recipes` 0건).
- 33선의 재료로 표기된 액티비티 배지(R5/H5/C2 등)는 실제 시딩된 배지 이름이 아니라 기획
  단계의 예시 라벨이었다.
- 33선이 전제한 "트라이브 10종에 각각 고유한 소재 아이템 배지가 존재"하는 카탈로그가
  구축되지 않았다. 실제 아이템 배지 108종은 트라이브 2종(낭만 미식가 90개, 아스팔트 레인저
  18개)에만 분포하며 전부 common 등급이다.
- 결과 배지로 쓰기로 했던 055 마이그레이션의 세력별 epic/mystic 배지는 33선이 부여한 고유
  서사 이름과 다른 템플릿 이름을 갖는다. 서사와 실제 지급물이 어긋난 상태였다.

레시피는 `/admin/recipes`에서 개별 등록한다. 스키마는 위 2절(티켓 `20260910_1408` 재설계)을
따른다.

## 6. 알려진 카탈로그 공백

아이템 배지가 트라이브 2종에만 존재하고 전부 common 등급이다. 8개 트라이브의 소재 아이템
배지와 epic·mystic 등급 배지 확보는 별도 컨텐츠 작업이며, 이 공백이 메워지기 전까지는 레시피
설계의 폭이 두 트라이브로 제한된다.
