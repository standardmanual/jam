## 1. 개요

### 한 줄 정의

**메뉴 이름은 "알림"이지만 실체는 최신순으로 쌓이는 소식 히스토리다.**

### 푸시 알림이 아니다

스마트폰 푸시 노티가 아니라 **앱 내 알림 메뉴에 리스팅하는 방식**이다.
Web Push 인프라(PWA manifest / Service Worker)는 여전히 미구현이며 이 기능의 전제가 아니다.

이 정체성이 설계 전반을 결정한다.

- **실시간성 요구가 사실상 0** — 유저가 앱을 여는 시점에 준비돼 있기만 하면 된다
- **읽음 상태를 개별 관리할 필요가 없다** — 히스토리는 사라지지 않으므로 "어디까지 봤나" 한 점만 알면 된다
- **지나간 일만 담는다** — 조치가 필요한 상태(state)가 아니라 발생한 사건(event)의 기록

### 왜 지금 필요한가

| 문제 | 현재 |
|---|---|
| Strava 동기화가 끊겨도 유저가 모른다 | 배지 발급이 완전히 멈추는데 아무 신호가 없다 |
| 내 드랍 아이템 배지를 누가 픽업해도 모른다 | `pickup_drop()`이 `dropper_user_id`를 기록하지만 통보 경로가 없다 |
| 참가한 미션이 마감돼도 모른다 | 직접 `/missions`에 들어가 확인해야 한다 |
| 비동기 발급 배지를 놓친다 | 동기화 오버레이 상한(10건) 초과분은 다시 볼 창구가 없다 |

[01_PRD.md](../01_PRD.md) §6에 "거래 알림은 앱 내 알림으로만"이 이미 명시돼 있다.
신규 발상이 아니라 인지된 갭을 채우는 작업이다.

## 2. 설계 원칙

### 2-1. 인스타그램 정책의 JAM! 번역

레퍼런스로 삼은 인스타그램의 알림 정책은 원칙 하나로 요약된다.

> **약한 신호(좋아요류)는 적극적으로 압축, 강한 신호(멘션·DM·보안)는 압축 금지**

JAM!에 대응시키면 이렇게 된다.

| 인스타 | JAM! |
|---|---|
| 게시물 좋아요 32개 → 1건으로 묶음 | 동기화 1회로 발급된 배지 3개 → 1건으로 묶음 |
| 멘션·팔로우요청수락은 개별 유지 | 미션 완료·컬렉션 완성·계정 이상은 개별 유지 |
| "게시물 A"가 묶음 단위 | "동기화 1회"가 묶음 단위 |
| 새 좋아요가 붙으면 카운트만 갱신 | 새 픽업이 붙으면 카운트·타임스탬프만 갱신 |

### 2-2. JAM! 고유 원칙 — 자기 행동의 메아리를 넣지 않는다

**앱 안에서 이미 결과를 본 행동은 소식으로 만들지 않는다.**

Strava 동기화는 webhook이 없어 100% 수동이다. `SyncButton`이 `/api/strava/sync`를 호출하고
그 응답 시점에 `BadgeRevealOverlay`가 바로 열린다. 즉 ①(보상 획득)은 유저가 방금 버튼을 눌러
화면으로 확인한 것의 재방송이다.

그래서 ①은 **리스트에는 남기되 dot을 켜지 않는다**(`bumps_badge=false`).
히스토리로서의 가치("그때 뭐 받았더라")는 살리고, dot은 "내가 모르는 사이에 일어난 일"에만 켠다.

### 2-3. 상태(state)가 아니라 사건(event)만 담는다

알림함 진입은 곧 "확인했다"는 신호다. 그런데 조치가 필요한 상태는 확인만으로 해결되지 않는다.

이 문제를 **경고 스타일의 동적 재평가**로 푼다. 경고 여부를 저장하지 않고 렌더 시점에 현재
상태를 조회해 결정한다 — 자세한 내용은 §6-2.

### 2-4. 게이미피케이션 윤리

| 원칙 | 적용 |
|---|---|
| 숫자 배지 대신 dot | 강박적 확인(compulsive checking) 유도 회피 |
| 완성 임박은 평생 1회 | 반복 발송은 즉시 다크패턴이 된다 |
| 순위 하락 소식 없음 | 상승만 알림. 리더보드는 하위 30%를 이탈시킨다 |
| 팔로잉 활동 하루 상한 2건 | 남의 소식이 내 보상 소식을 묻지 않게 |
| FOMO 톤 금지 | "지금 안 하면 놓쳐요" 류 문구 사용 안 함 |

| # | 종류 | 예시 문구 | 트리거 | 묶음 | 착지점 |

> #3은 배지 도감(`/badges/[id]`)이 아니라 **인벤토리 인스턴스**로 보낸다. 유저가 확인하고 싶은 건
> "내가 받은 그 개체(시리얼)"이지 도감이 아니다.
>
> **#5의 트리거를 좁힌 이유** — `grantMissionRewards()`가 미션 보상 배지의 포인트도 같은
> `badge_point_reward` reason으로 지급한다. reason만으로 판정하면 하나의 미션 완료가
> #5와 #22 두 줄로 보인다. #22가 이미 "배지 **1개**와 **500 JAM 포인트**를 획득했어요"로 보상을 다 말하므로
> 미션 경유분은 #5에서 제외한다.

## 5. 문구 강조 규칙

> **`payload`로 채워지는 변수 슬롯은 자동 볼드, 고정 텍스트는 일반. 컬러 강조는 쓰지 않는다.**

| 소식 | 템플릿 | 슬롯 = 볼드 |
|---|---|---|
| 1 | `오늘 활동으로 {badgeCount}를 획득했어요` | 배지 3개 |
| 4 | `{poiName}에서 체크인 배지를 획득했어요` | 북한산 |
| 10 | `'{bookName}', 한 칸만 남았어요` | 잃어버린 시간 |
| 41 | `{days}째 활동을 못 불러오고 있어요` | 3일째 |
| 42 | `인벤토리가 꽉 찼어요...` (슬롯 없음) | 없음 |

#10의 "한 칸"이 볼드가 아닌 것도 이 규칙과 일치한다 — 잔여 1칸일 때만 발송하므로 변수가
아니라 고정값이다.

**소식 종류마다 강조 지점을 따로 정의할 필요가 없다.** 렌더러가 슬롯을 볼드로 감싸면 28종이
자동으로 일관되고, 나중에 소식을 추가할 때도 문구만 쓰면 강조가 따라온다.

사람 이름(actor)도 다른 슬롯과 동일하게 볼드만 적용한다. 같은 요소가 화면 안에서 어떤 줄은
컬러이고 어떤 줄은 아니면 유저가 규칙을 읽지 못한다.

### 5-1. 호칭 — 닉네임 직접 호출

[UX_WRITING_GUIDELINE.md](../../UX_WRITING_GUIDELINE.md)가 `고객님`·`유저님` 류 호칭을 지양하고
`OO님`(닉네임)을 쓰도록 규정한다. **"회원님"을 쓰지 않는다.**

본인도 닉네임으로 호출하며, 본인 닉네임 역시 `payload` 슬롯이므로 볼드가 적용된다.

## 6. 화면

### 6-1. 알림함 `/notifications`

- **전체 페이지**, 최신순 단일 리스트
- 시간 구간 헤더 — **오늘 / 이번 주 / 이번 달 / 이전**
- 커서 페이지네이션 (`user_activity_feed`와 동일 패턴)
- 보관 기간 제한 없음 — 히스토리가 정체성이므로 만료시킬 이유가 없다

**진입 시 전체 읽음 처리.** 다만 진입 직전의 `seen_at` 값을 스냅샷해 **그 페이지에서만
"새 소식" 구분선**을 그린다. 안 그리면 유저가 뭐가 새 거였는지 알 수 없다.

```
─────────── 새 소식 3 ───────────
  예린님이 시현님을 팔로우해요
  '한강 100km'가 이틀 뒤 끝나요
  시현님 활동 지역에 아이템 배지 5개가 새로 떨어졌어요
─────────────────────────────
  오늘 활동으로 배지 3개를 획득했어요
  ...
```

읽음 처리는 이미 끝났으므로 새로고침하면 구분선이 사라진다.

**착지점은 저장하지 않고 런타임 계산한다.** `target_href`를 컬럼으로 저장하면 라우트를 바꿀 때
과거 소식이 전부 깨진다. `type` + `payload` → href 매핑 함수 하나로 렌더 시점에 계산하며,
§3의 28종 표가 그 함수의 명세다.

### 6-2. ⑧ 경고 스타일 — 동적 재평가

40·41·42·44는 경고 아이콘 + 컬러 차별화로 표시한다. 단 **경고 여부를 저장하지 않고 렌더 시점에
현재 상태를 조회해 결정한다.**

| 소식 | 경고 스타일 유지 조건 | 해소되면 |
|---|---|---|
| 40 Strava 끊김 | `strava_connections` 토큰이 여전히 무효 | 일반 텍스트로 강등 |
| 41 동기화 지연 | 마지막 sync가 여전히 3일+ 경과 | 일반 텍스트로 강등 |
| 42 인벤토리 포화 | 현재 잔여 슬롯이 여전히 부족 | 일반 텍스트로 강등 |
| 44 포인트 **차감** | 항상 유지 (되돌릴 수 없는 사건) | — |

이러면 "인벤토리 비웠는데 아직도 경고가 떠 있는" 상황이 사라지고, 히스토리로서의 기록은 남는다.
이 4종은 `bumps_badge=true`를 유지해 dot을 켠다.

### 6-3. 진입점 — TopNav

DS의 `TopNav`는 이미 4분할이다.

```
[logoSlot │ back+title] ─── [centerSlot: 동기화] ─── [rightSlot] [avatarSlot: 프로필]
                                                        ↑ 알림 종
```

`rightSlot`은 `avatarSlot` 바로 앞에 붙도록 설계돼 있어 **디자인 시스템 변경 없이** 원하는
위치(동기화 버튼 ↔ 프로필 이미지 사이)가 나온다.

**`rightSlot` 충돌 처리** — 배지 상세 화면의 공유 버튼이 이미 `rightSlot`을 쓴다. 서비스 래퍼
(`src/components/ui/TopNav.tsx`)가 `centerSlot`·`avatarSlot`을 자동 주입하듯 합성한다.

```
rightSlot = <>{호출부가 넘긴 값}{알림 종}</>
```

알림 종을 **뒤에** 붙여야 아바타 바로 왼쪽에 온다. 결과: `[공유버튼][알림종][아바타]`.

### 6-4. 노출 범위

> **back chevron이 없는 루트 화면에만 알림 종을 주입한다** (`logo` 또는 `showBack={false}`)

| 화면 | 현재 TopNav | 알림 종 |
|---|---|---|
| 홈 `/` | `logo` | ✅ |
| 배지 `/badges` | `logo` | ✅ |
| 미션 `/missions` | `logo` | ✅ |
| 인벤토리 `/inventory` | `logo` | ✅ |
| **본인** 프로필 `/[me]` | **없음 → 신규 추가** (`logo`) | ✅ |
| 타인 프로필 `/[username]` | back + 닉네임 타이틀 | ❌ |
| 드랍 `/drops` | 없음 (지도 전체화면) | ❌ 자동 제외 |
| 상세 화면 전반 | back + title | ❌ |

화면 목록을 하드코딩하지 않고 이 규칙으로 판정하면 호출부는 손댈 게 없고, 나중에 루트 화면이
늘어나도 알아서 따라온다.

### 6-5. 아이콘과 배지

- **아이콘**: `BellIcon` 신규. Material Symbols `notifications`(FILL 0 / wght 400 / opsz 24)의
  형태를 따르되, **기존 세트 규칙(stroke 1.5px, 24 viewBox, `currentColor`)으로 구현**한다.
  - 폰트를 로드하지 않는다 — 아이콘 하나 때문에 수백 KB를 받을 이유가 없다 (Apache 2.0이라
    SVG path 추출은 자유)
  - Material Symbols Outlined는 겉보기와 달리 **fill 기반 path**라 그대로 넣으면 stroke 세트와
    선 굵기·질감이 어긋난다
- **배지**: 우측 상단 **빨간 버블, 숫자 없음**. `bumps_badge=true`인 안 읽은 소식이 하나라도
  있으면 노출
  - 숫자 배지는 강박적 확인을 유도한다
  - 아이콘 세트의 "제3의 컬러 도입 금지" 규칙과 충돌하므로 **버블은 아이콘 바깥의 별도
    엘리먼트**로 둔다

### 6-6. 필요한 신규 라우트 파라미터

| 파라미터 | 쓰이는 소식 |
|---|---|
| `?highlight=<ids>` — 배지·인벤토리 목록 하이라이트 | 1, 3, 4 |
| `/collections/[id]` 장착 모드 진입 | 11 |
| `/drops?poi=<id>` — 지도 카메라 이동 | 18, 32 |

### 6-7. 필요한 신규 컬러 토큰

`globals.css`에 정의된 건 브랜드 팔레트(`--color-jam-*`)뿐이라 "빨강"에 해당하는 시맨틱 토큰이 없다.

| 용도 | 제안 토큰 |
|---|---|
| 안 읽은 소식 있음 | `--color-notification-dot` |
| 경고 상태 | `--color-warning` |

같은 빨강 계열이어도 **의미가 달라 토큰은 분리**한다("소식 있음" vs "문제 있음"). 나중에 한쪽만
색을 바꿀 때 갈라칠 수 있다.
