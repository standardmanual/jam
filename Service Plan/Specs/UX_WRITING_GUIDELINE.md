# JAM! UX 라이팅 가이드라인

> 생성일: 2026-07-31
> 최종 수정: 2026-08-26
> 적용 범위: 화면 텍스트, 알림, 에러 메시지, 버튼 문구, 커밋 메시지 외 사용자 노출 문구 전체

---

## 핵심 철학: "운동 마치고 돌아온 사람이, 앱을 켜자마자 바로 이해할 수 있는가?"

JAM!은 **트래커가 아니라 보상 수확 경험**이다. 사용자는 이미 Strava에서 운동을 기록했고,
JAM!에서는 "오늘 뭘 획득했는지" 확인하러 온다. 은행/시스템의 사무적 언어가 아니라,
**함께 운동하는 친구가 오늘의 성과를 축하해주는 어조**를 기본값으로 삼는다.

또한 JAM!은 배지·아이템·드랍·믹스라는 **수집·게임 메커니즘**을 가진 서비스다.
**신남/설렘의 톤**을 허용하되, 사기·거래·소각처럼
되돌릴 수 없는 행동 앞에서는 토스와 동일하게 냉정하고 명확해야 한다.

## 1. 용어 및 시점 원칙

### 1) 공급자 언어를 JAM! 사용자 언어로 번역

시스템/운영 관점 용어를 사용자가 실제로 겪는 행동으로 바꾼다.

| 공급자 언어 (지양)    | JAM! 사용자 언어 (지향) |
| -------------- | ---------------- |
| 배지 발급 완료       | 배지 획득!            |
| 조건 충족 확인       | 조건을 다 채웠어요       |
| Strava 동기화 실행  | 오늘 활동 불러오는 중     |
| 아이템 드랍 이벤트 생성됨 | 근처에 아이템이 떨어졌어요   |
| POI 반경 매칭 성공   | 여기 체크인됐어요        |
| 컬렉션 레시피 충족      | 컬렉션을 다 모았어요       |
| 인벤토리 슬롯 초과    | 인벤토리가 꽉 찼어요       |
| 아이템 만료 처리      | 아이템이 포인트로 바뀌었어요  |
| 거래 체결 완료       | 교환을 완료했어요        |

### 2) 사용자 중심의 호칭과 주어 설정

- '당사', '고객님', '유저님' 지양 → **'JAM!'**, **'OO님'** (닉네임/이름) 사용
  - 당사가 제공하는 배지입니다 ➔ JAM!이 준비한 배지예요
  - 고객님이 획득한 아이템 ➔ 시현님이 획득한 아이템
- '시스템' 시점 지양 → **'사용자' 시점** 적용
  - 배지 발급 처리가 완료되었습니다 ➔ 배지를 획득했어요
  - POI 방문 인증이 확인되었습니다 ➔ 체크인됐어요
- **드랍/아이템 계열은 '세계관 속 사건'처럼 서술**한다 (JAM!만의 톤)
  - 드랍 아이템이 생성되었습니다 ➔ 근처에 아이템이 떨어졌어요
  - 신화 아이템이 이동했습니다 ➔ 신화 아이템이 다른 곳으로 떠났어요

### 3) 용어 일관성 (Consistency)

동일 개념을 화면마다 다른 단어로 섞어 쓰지 않는다. JAM!의 고정 용어는 다음과 같다.

| 개념 | 고정 용어 | 사용 기준 |
|---|---|---|
| 배지나 아이템을 얻는 행위 | **획득 (GET)** | 배지·아이템을 획득하는 모든 맥락에 적용. X: 겟, 수령, 발급받음, 취득, 언락 |
| 아이템을 조합해 새로운 결과물을 얻는 행위 | **믹스 (MIX)** | 여러 아이템을 소모하여 확률에 따라 새로운 결과물을 얻는 고유 기능. X: 조합, 합성, 믹스 |
| 아이템을 특정 위치에 두는 것 | **드랍 (DROP)** | 유저가 아이템을 특정 위치에 두는 행위. X: 배치, 생성, 놓기 |
| 아이템을 특정 위치에서 가져오는 것 | **픽업 (PICKUP)** | 유저가 특정 위치의 아이템을 가져오는 행위. X: 수집, 채집, 회수 |
| 드랍·픽업·체크인이 일어나는 실제 위치 | **지점 (SPOT)** | 어드민이 등록한 좌표와 반경을 가진 실제 위치. 화면에 내부 약어 POI를 노출하지 않는다. X: POI, 장소, 스팟, 위치, 거점<br>**예외** — 개수를 세는 일상 문장에서는 「곳」을 쓴다(「드랍한 3지점에」가 어색하다). 라벨·제목·명사구는 「지점」 고정. 티켓 20260827_014 |
| 지점에 실제로 다녀간 것이 기록되는 것 | **체크인 (CHECK-IN)** | 활동의 GPS 경로가 지점 반경을 지나면 성립한다. X: 방문, 체크, 인증, 매칭, 확인 |
| 체크인으로 획득하는 배지 | **체크인 배지 (CHECK-IN BADGE)** | 지점에 체크인하면 획득되는 배지. 배지도감 탭명·컬렉션 섹션명·알림 문구에 모두 이 표기를 쓴다. X: 장소 배지, POI 배지, 장소, 방문 배지 |
| 같은 체크인 배지를 두 번째 이상 반복 획득한 것을 알리는 것 | **N번째 체크인 했어요** | 체크인 배지 재획득 시 피드·알림에 쓰는 고정 패턴. 첫 획득은 '체크인 했어요', 두 번째부터 이 패턴을 쓴다. X: N번째 방문했어요, 재획득, 재체크인, 반복 획득 |
| 유저가 보유한 아이템 보관 공간 | **인벤토리 (INVENTORY)** | 유저가 보유한 아이템을 확인하고 관리하는 공간. X: 인벤, 보관함, 창고 |
| 특정 배지·아이템 세트를 모으는 목표 및 진행 상태 | **컬렉션 (COLLECTION)** | 세계관별 아이템배지 세트 단위의 수집 목표와 진행 상태를 지칭. X: 아이템북, 컬렉션북, 도감 |
| 서비스 내 보유 화폐 | **포인트 (POINT)** | 배지·아이템 획득 등에 사용되는 서비스 내 화폐 단위. **유저 노출 문구에 「JAM」을 붙이지 않는다**(「JAM 포인트 시스템」은 내부 도메인명으로만 유지). X: 잼포인트, JAM 포인트, 캐시, P |
| Strava 계정과 서비스를 연결하는 것 | **Strava 동기화 (Strava Sync)** | Strava 계정을 서비스와 연결하는 기능. X: Strava 연동, 스트라바 계정 연결, 트래커 연동, 트래커 연결 |
| 배지와 연계된 실물 자수 제품 | **패치 (PATCH)** | 배지 달성 시 구매 가능한 실물 자수 제품. X: 굿즈, 상품 |
| 배지 희귀도 등급명 | **Common / Rare / Legend / Mythic** | 배지의 4단계 희귀도 등급. 영문 표기 고정. X: Legendary, 레전더리, 레전드 등 비표준 표기 |
| 미션에 참여하는 행위 | **참가 (Join)** | 미션에 참여 신청하는 행위. X: 신청, 등록, 참여 |
| 어드민이 유저 포인트를 추가하는 것 | **지급** | 어드민 전용 포인트 추가 행위. 유저 노출 화면에는 사용 금지. X: 추가, 충전 |
| 어드민이 유저 포인트를 차감하는 것 | **회수** | 어드민 전용 포인트 차감 행위. 유저 노출 화면에는 사용 금지. X: 차감, 환수 |
| 선행 조건을 채우지 못해 참가·진입이 막힌 상태 | **잠김 (LOCKED)** | 상태 라벨은 '잠김', 해제 안내는 '열려요'로 고정 (예: "첫 숨결 Rare 배지를 획득하면 열려요"). X: 잠금, 미해금, 비활성, 언락, 해금 |

이 표에 없는 새 용어가 필요해지면, 이 문서의 표를 갱신한 뒤 사용한다 (자체 판단으로 임의 표기 확산 금지).

## 2. 문장 구조 및 톤앤매너

### 1) 대화하듯 자연스러운 '해요체'

- Good: 배지를 획득했어요.
- Bad: 배지가 발급되었습니다.

### 2) 간결함과 명확성

- Good: 지금 드랍할까요?
- Bad: 아이템을 드랍하려면 아래 버튼을 눌러 진행해 주시기 바랍니다.
- 원칙: 한 문장에는 하나의 의미와 행동만 담는다.

### 3) 상황별 톤앤매너 완급 조절

JAM!은 게임적 재미(드랍·픽업·믹스)와 실물 자산(패치 구매 자격·JAM 포인트·거래)이
공존하는 서비스이므로, 상황에 따라 톤을 명확히 구분한다.

| 상황 | 톤 | 예시 |
|---|---|---|
| 배지/아이템 획득, 컬렉션 완성   | **신남 · 축하 (Warm & Cheerful)** | 배지 획득! 오늘도 한 걸음 더 갔어요 🎉 |
| 동기화·로딩 등 일반 진행 | **담담 · 안내 (Conversational)** | 오늘 활동을 불러오는 중이에요. 잠시만요. |
| 체크인·드랍·픽업·신화 아이템 이벤트 | **설렘 · 세계관 (Playful & Immersive)** | 근처에 신화 아이템이 나타났어요! |
| 아이템 만료, 인벤토리 초과, 소각 확정 | **단호 · 명확 (Professional & Direct)** | 이 아이템은 30일 후 사라져요. 포인트로 미리 바꿔둘까요? |
| 거래(P2P)·환전·되돌릴 수 없는 확정 | **단호 · 명확 (Professional & Direct)** | 교환은 취소할 수 없어요. 이대로 진행할까요? |
| 계정·Strava 동기화 오류, 부정 어뷰징 감지 | **전문 · 직접 (Professional & Direct)** | Strava 동기화가 끊겼어요. 다시 동기화해야 배지를 획득할 수 있어요. |

**원칙**: 되돌릴 수 없는 행동(소각·거래 확정·환전·동기화 해제)일수록 신남 톤을 배제하고
현상 → 결과 → 확인 순서로 단호하게 전달한다. 게임적 재미와 되돌릴 수 없는 결정을 같은 톤으로 섞지 않는다.

## 4. 에러 대응 가이드라인

시스템 관점 오류 통보를 피하고 **[현상 → 원인 → 해결책]** 3단계 구조를 지킨다.
JAM! 특화 시나리오 예시:

| 구형 방식 (Bad) | JAM! 3단계 적용 (Good) |
|---|---|
| Strava 동기화 실패 (Error 401) | Strava 동기화가 끊겼어요. (현상) 비밀번호를 바꾸셨거나 동기화 권한이 해제됐을 수 있어요. (원인) [Strava 다시 동기화하기] (해결책/CTA) |
| 체크인 실패 | 여기 체크인이 안 됐어요. (현상) GPS 신호가 약했거나 반경 50m 밖이었을 수 있어요. (원인) [활동 다시 확인하기] (해결책/CTA) |
| 인벤토리 용량 초과로 드랍 불가 | 인벤토리가 꽉 찼어요. (현상) 50개까지만 보관할 수 있어요. (원인) [정리하러 가기] (해결책/CTA) |
| 아이템 만료 처리됨 (단순 통보) | 아이템이 사라졌어요. (현상) 30일이 지나 자동으로 300 포인트로 바뀌었어요. (원인) [내 포인트 보기] (해결책/CTA) |
| 어뷰징 감지 (차단 사유 비공개) | 이 활동은 배지로 인정하지 않았어요. (현상) 이동 속도가 너무 빨라 운동으로 보기 어려웠어요. (원인) [기준 자세히 보기] (해결책/CTA) |

## 5. 행동 유도 버튼 규칙 (CTA)

### 1) 예측 가능한 행동 동사 사용

버튼을 눌렀을 때 일어날 결과가 명확히 드러나는 동사를 쓴다.

- Good: 배지 획득하러 가기, 포인트로 바꾸기, Strava 다시 동기화하기
- Bad: 확인, 다음, 실행, 완료
- **예외** — 드랍·픽업처럼 §1.2에서 이미 고정 용어로 정의됐고 화면에서 반복 노출되는 액션은
  버튼 레이블을 명사형(드랍, 픽업)으로 축약한다. 확인 다이얼로그 본문 등 문장 안에서는
  계속 동사형(드랍할까요?, 픽업할 수 있어요)을 쓴다 — 축약은 버튼 레이블에만 적용. (티켓 20260830_2015)

### 2) 1화면 1주요 버튼 원칙

한 화면에서 가장 중요한 행동 버튼은 1개만 강조 배치한다.
드랍/픽업처럼 되돌릴 수 없는 행동은 보조 버튼("취소", "나중에")을
반드시 동일한 시각적 무게로 함께 노출해, 실수로 확정 버튼만 누르지 않게 한다.

## 6. 네비게이션 — TopNav 뒤로가기 레이블 정책

### TopNav title의 역할

TopNav 렌더 구조는 `[← title ──────] [rightSlot]` 이다.
`title`은 항상 **"어디로 돌아가는가"를 뜻하는 back-label**이다.
현재 화면명이 아니다. (iOS HIG Back Button 패턴과 동일)

### 화면 유형별 결정 기준

| 조건 | title | backHref |
|---|---|---|
| 목록 → 상세, 진입 경로 고정 | 목록 화면명 ("미션", "인벤토리") | 있음 (목록 URL) |
| 프로필 → 하위 화면 | 유저명 (username) | 있음 (`/{username}`) |
| 다양한 경로로 진입 가능 | `d.common.back` ("뒤로") | 없음 (router.back) |
| 탭바 루트 화면 | 없음 | showBack=false |

### 적용 예시

| 화면 | title | 근거 |
|---|---|---|
| `/missions/{id}` | "미션" | 미션 목록에서만 진입 |
| `/inventory/{id}` | "인벤토리" | 인벤토리 목록에서만 진입 |
| `/{username}/following` | username | 프로필 화면으로 돌아감 |
| `/{username}/followers` | username | 프로필 화면으로 돌아감 |
| `/profile/edit` | "프로필" | 프로필 화면으로 돌아감 |
| `/search` | "뒤로" | 여러 경로(투데이, 내비 등)에서 진입 |
| `/points` | "뒤로" | 여러 경로(프로필, 투데이 등)에서 진입 |

### 레이블 텍스트 규칙

- "뒤로" 고정 문구는 `d.common.back` 키를 사용한다. 화면마다 다른 표현("돌아가기", "이전" 등)을 쓰지 않는다.
- 유저명(username)을 그대로 쓴다. "OO님의 프로필"처럼 부연하지 않는다.
- 목록 화면명은 탭바 라벨(`d.nav.*`)과 일치시킨다.
- 마침표 없음, 해요체 불필요 (레이블이므로).

## 7. 적용 방법

- 신규 기능 개발, 기존 화면 문구 수정, 알림/에러 메시지 작성 시 **이 문서를 항상 우선 참조**한다.
- 새로운 용어가 필요하면 1절 3항 "용어 일관성" 표를 갱신한 뒤 사용한다. 표에 없는 용어를 임의로 만들어 쓰지 않는다.
- 이 가이드라인 자체가 변경되면(용어 추가, 톤 기준 조정 등) 기존 파일을 직접 수정하지 않고
  `UX_WRITING_GUIDELINE.md`를 갱신 이력과 함께 직접 수정한다 (SERVICE_OPERATIONS류 스냅샷 문서와 달리
  이 문서는 살아있는 단일 기준 문서로 유지한다).
