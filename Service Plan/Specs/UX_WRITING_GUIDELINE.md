# JAM! UX 라이팅 가이드라인

> 생성일: 2026-07-31
> 기반: 토스(Toss) UX Writing 가이드라인을 JAM! 서비스 맥락에 맞게 재구성
> 적용 범위: 화면 텍스트, 알림, 에러 메시지, 버튼 문구, 커밋 메시지 외 사용자 노출 문구 전체

---

## 핵심 철학: "운동 마치고 돌아온 사람이, 앱을 켜자마자 바로 이해할 수 있는가?"

JAM!은 **트래커가 아니라 보상 수확 경험**이다. 사용자는 이미 Strava에서 운동을 기록했고,
JAM!에서는 "오늘 뭘 얻었는지" 확인하러 온다. 은행/시스템의 사무적 언어가 아니라,
**함께 운동하는 친구가 오늘의 성과를 축하해주는 어조**를 기본값으로 삼는다.

또한 JAM!은 배지·아이템·드랍·조합이라는 **수집·게임 메커니즘**을 가진 서비스다.
그래서 토스보다 한 걸음 더 **신남/설렘의 톤**을 허용하되, 사기·거래·소각처럼
되돌릴 수 없는 행동 앞에서는 토스와 동일하게 냉정하고 명확해야 한다.

---

## 1. 용어 및 시점 원칙

### 1) 공급자 언어를 JAM! 사용자 언어로 번역

시스템/운영 관점 용어를 사용자가 실제로 겪는 행동으로 바꾼다.

| 공급자 언어 (지양) | JAM! 사용자 언어 (지향) |
|---|---|
| 배지 발급 완료 | 배지를 받았어요 |
| 조건 충족 확인 | 조건을 다 채웠어요 |
| Strava 동기화 실행 | 오늘 활동 불러오는 중 |
| 아이템 드랍 이벤트 생성됨 | 근처에 아이템이 떨어졌어요 |
| POI 반경 매칭 성공 | 여기 다녀오신 거 확인했어요 |
| 아이템북 레시피 충족 | 아이템북을 다 모았어요 |
| 인벤토리 슬롯 초과 | 인벤토리가 꽉 찼어요 |
| 아이템 만료 처리 | 아이템이 JAM 포인트로 바뀌었어요 |
| 거래 체결 완료 | 교환을 완료했어요 |

### 2) 사용자 중심의 호칭과 주어 설정

- '당사', '고객님', '유저님' 지양 → **'JAM!'**, **'OO님'** (닉네임/이름) 사용
  - 당사가 제공하는 배지입니다 ➔ JAM!이 준비한 배지예요
  - 고객님이 획득한 아이템 ➔ 시현님이 모은 아이템
- '시스템' 시점 지양 → **'사용자' 시점** 적용
  - 배지 발급 처리가 완료되었습니다 ➔ 배지를 받았어요
  - POI 방문 인증이 확인되었습니다 ➔ 다녀오신 곳, 확인했어요
- **드랍/아이템 계열은 '세계관 속 사건'처럼 서술**한다 (JAM!만의 톤)
  - 드랍 아이템이 생성되었습니다 ➔ 근처에 아이템이 떨어졌어요
  - 신화 아이템이 이동했습니다 ➔ 신화 아이템이 다른 곳으로 떠났어요

### 3) 용어 일관성 (Consistency)

동일 개념을 화면마다 다른 단어로 섞어 쓰지 않는다. JAM!의 고정 용어는 다음과 같다.

| 개념 | 고정 용어 (다른 표현 금지) |
|---|---|
| 배지를 얻는 행위 | **획득** (X: 수령, 발급받음, 취득) |
| 아이템을 두고 오는 행위 | **드랍** (X: 배치, 생성, 놓기) |
| 아이템을 가져오는 행위 | **픽업** (X: 수집, 채집, 회수) |
| 특정 장소를 다녀온 것 | **방문 인증** (X: 체크인, 매칭, 확인) |
| 배지/아이템의 화폐 단위 | **JAM 포인트** (X: 잼포인트, 포인트, 캐시) |
| 아이템 보관함 | **인벤토리** (X: 보관함, 창고) |
| 세트 수집 목표 | **아이템북** (X: 컬렉션북, 도감) |
| Strava 연동 | **Strava 연동** (X: 스트라바 계정 연결, 트래커 연동) |
| 실물 자수 패치 | **실물 패치** (X: 굿즈, 상품) |
| 배지 희귀도 등급명 | **Common / Rare / Legend / Mythic** (X: Legendary, 레전더리, 레전드 등 비표준 표기 금지) |

이 표에 없는 새 용어가 필요해지면, 이 문서의 표를 갱신한 뒤 사용한다 (자체 판단으로 임의 표기 확산 금지).

## 2. 문장 구조 및 톤앤매너

### 1) 대화하듯 자연스러운 '해요체'

- Good: 배지를 받았어요.
- Bad: 배지가 발급되었습니다.

### 2) 간결함과 명확성

- Good: 지금 드랍할까요?
- Bad: 아이템을 드랍하려면 아래 버튼을 눌러 진행해 주시기 바랍니다.
- 원칙: 한 문장에는 하나의 의미와 행동만 담는다.

### 3) 상황별 톤앤매너 완급 조절

JAM!은 게임적 재미(수집·드랍·조합)와 실물 자산(패치 구매 자격·JAM 포인트·거래)이
공존하는 서비스이므로, 상황에 따라 톤을 명확히 구분한다.

| 상황 | 톤 | 예시 |
|---|---|---|
| 배지/아이템 획득, 아이템북 완성 | **신남 · 축하 (Warm & Cheerful)** | 배지 획득! 오늘도 한 걸음 더 갔어요 🎉 |
| 동기화·로딩 등 일반 진행 | **담담 · 안내 (Conversational)** | 오늘 활동을 불러오는 중이에요. 잠시만요. |
| 드랍/픽업/신화 아이템 이벤트 | **설렘 · 세계관 (Playful & Immersive)** | 근처에 신화 아이템이 나타났어요! |
| 아이템 만료, 인벤토리 초과, 소각 확정 | **단호 · 명확 (Professional & Direct)** | 이 아이템은 30일 후 사라져요. JAM 포인트로 미리 바꿔둘까요? |
| 거래(P2P)·환전·되돌릴 수 없는 확정 | **단호 · 명확 (Professional & Direct)** | 교환은 취소할 수 없어요. 이대로 진행할까요? |
| 계정·Strava 연동 오류, 부정 어뷰징 감지 | **전문 · 직접 (Professional & Direct)** | Strava 연동이 끊겼어요. 다시 연결해야 배지를 받을 수 있어요. |

**원칙**: 되돌릴 수 없는 행동(소각·거래 확정·환전·연동 해제)일수록 신남 톤을 배제하고
현상 → 결과 → 확인 순서로 단호하게 전달한다. 게임적 재미와 되돌릴 수 없는 결정을 같은 톤으로 섞지 않는다.

## 3. 문장 부호 및 표기 규칙

| 구분 | 규칙 | 적용 예시 (Good) | 미적용 예시 (Bad) |
|---|---|---|---|
| 제목 / 버튼 | 끝에 마침표를 찍지 않음 | 배지를 받았어요 / 드랍하기 | 배지를 받았어요. / 드랍하기. |
| 본문 / 안내문 | 두 줄 이상 문장에는 정확히 마침표 사용 | 근처에 떨어진 아이템이에요. 지금 픽업할 수 있어요. | 근처에 떨어진 아이템이에요 지금 픽업할 수 있어요 |
| 날짜 / 시간 | 직관적인 한국어 형태로 표기 | 7월 31일 금요일 오후 3시 30분 | 2026.07.31(Fri) 15:30 |
| 만료/남은 기간 | 사용자가 바로 체감하는 단위로 표기 | 3일 뒤 사라져요 / 오늘 자정까지 | 만료까지 D-3 / TTL 259200s |
| JAM 포인트 / 금액 | 읽기 쉬운 단위와 '포인트'·'원' 사용 | 1,200 JAM 포인트 / 1만 원 | 1200P / ₩10,000 |
| 거리/기록 (Strava 연동값) | 사용자 일상어 단위 유지 | 5.2km 라이딩 | 5200m 이동 |

## 4. 에러 대응 가이드라인

시스템 관점 오류 통보를 피하고 **[현상 → 원인 → 해결책]** 3단계 구조를 지킨다.
JAM! 특화 시나리오 예시:

| 구형 방식 (Bad) | JAM! 3단계 적용 (Good) |
|---|---|
| Strava 동기화 실패 (Error 401) | Strava 연동이 끊겼어요. (현상) 비밀번호를 바꾸셨거나 연동 권한이 해제됐을 수 있어요. (원인) [Strava 다시 연결하기] (해결책/CTA) |
| POI 반경 매칭 실패 | 다녀오신 곳을 확인하지 못했어요. (현상) GPS 신호가 약했거나 반경 50m 밖이었을 수 있어요. (원인) [활동 다시 확인하기] (해결책/CTA) |
| 인벤토리 초과로 드랍 불가 | 인벤토리가 꽉 찼어요. (현상) 50개까지만 보관할 수 있어요. (원인) [정리하러 가기] (해결책/CTA) |
| 아이템 만료 처리됨 (단순 통보) | 아이템이 사라졌어요. (현상) 30일이 지나 자동으로 300 JAM 포인트로 바뀌었어요. (원인) [내 포인트 보기] (해결책/CTA) |
| 어뷰징 감지 (차단 사유 비공개) | 이 활동은 배지로 인정하지 않았어요. (현상) 이동 속도가 너무 빨라 운동으로 보기 어려웠어요. (원인) [기준 자세히 보기] (해결책/CTA) |

## 5. 행동 유도 버튼 규칙 (CTA)

### 1) 예측 가능한 행동 동사 사용

버튼을 눌렀을 때 일어날 결과가 명확히 드러나는 동사를 쓴다.

- Good: 배지 획득하러 가기, 지금 드랍하기, 픽업할래요, JAM 포인트로 바꾸기, Strava 다시 연결하기
- Bad: 확인, 다음, 실행, 완료

### 2) 1화면 1주요 버튼 원칙

한 화면에서 가장 중요한 행동 버튼은 1개만 강조 배치한다.
드랍/픽업처럼 되돌릴 수 없는 행동은 보조 버튼("취소", "나중에")을
반드시 동일한 시각적 무게로 함께 노출해, 실수로 확정 버튼만 누르지 않게 한다.

## 6. 적용 방법

- 신규 기능 개발, 기존 화면 문구 수정, 알림/에러 메시지 작성 시 **이 문서를 항상 우선 참조**한다.
- 새로운 용어가 필요하면 2절 "용어 일관성" 표를 갱신한 뒤 사용한다. 표에 없는 용어를 임의로 만들어 쓰지 않는다.
- 이 가이드라인 자체가 변경되면(용어 추가, 톤 기준 조정 등) 기존 파일을 직접 수정하지 않고
  `UX_WRITING_GUIDELINE.md`를 갱신 이력과 함께 직접 수정한다 (SERVICE_OPERATIONS류 스냅샷 문서와 달리
  이 문서는 살아있는 단일 기준 문서로 유지한다).
