# [Service] 배지·드랍 판정 기준 — UTC → 활동 현지 시각(start_date_local)

## 배경 / 문제 정의

배지 발급·드랍 판정이 UTC 기준으로 동작해 시간대 차이가 있는 국가 유저에게
요일·월·시즌 조건이 틀리게 적용됐다.

예:
- 한국(UTC+9) 유저가 **일요일 밤 11시** 운동 → UTC는 월요일 → 주말 파이터 배지 누락
- **12월 31일 밤 11시** 운동 → UTC 1월 1일 → 이달의 주자왕 월 버킷 오류
- 드랍 일일 카운터가 UTC 자정(= KST 09:00)에 리셋 → 오전 9시까지 드랍 제한

서비스를 글로벌로 확장할 계획임을 고려해 유저별 시간대를 별도로 저장하지 않고도
모든 국가에서 올바르게 동작하는 구조로 근원 수정.

## 해결 방식

**Strava `start_date_local` 활용.**
Strava는 활동 GPS 위치를 기반으로 해당 지점의 시간대를 계산해 현지 시각을
`start_date_local`로 제공한다. 별도 시간대 DB나 역지오코딩 없이 활동이 발생한
국가 기준 날짜/시각을 바로 얻을 수 있다.

- GPS 없는 실내 활동은 Strava 계정 시간대로 자동 폴백
- `startDateLocal ?? startDate` 폴백으로 null 안전성 유지

### 주요 의사결정
- **유저별 시간대 저장 불채택**: Strava `start_date_local`이 GPS 기반으로 이미 현지 시각을 제공하므로 별도 저장 불필요. 해외 여행 중 운동도 올바르게 처리됨.
- **UTC 폴백 유지**: `startDateLocal ?? startDate` 패턴 — GPS 없는 실내 활동이나 레거시 데이터에서 `startDateLocal`이 null인 경우 대비.
- **`start_date`(UTC) 는 정렬·커서·멱등 처리에 계속 사용**: 조회 범위(`after` 파라미터)·`last_synced_at` 커서 등은 UTC 절대 시각이 필요한 구간이므로 변경 안 함.

### 잔여 이슈
- 기존에 UTC 기준으로 잘못 저장된 `triggered_by_activity_date` 데이터는 이번 수정으로 재처리(재동기화) 시 새 값으로 덮어써짐. 이전 데이터 일괄 마이그레이션은 별도 판단 필요.
