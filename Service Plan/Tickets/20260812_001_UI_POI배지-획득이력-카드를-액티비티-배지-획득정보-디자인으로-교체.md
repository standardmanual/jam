# [UI] POI 배지 획득 이력을 액티비티 배지 "획득 정보" 카드 디자인으로 교체

## 배경 / 문제 정의

[티켓 010](./20260811_010_UI_POI배지-상세화면-스트라바-액티비티-링크-노출.md)에서 POI 배지 상세화면(`/badges/[id]`)의
"획득 이력" 리스트 각 항목(`<li>`) 안에 `StravaLink` 버튼을 끼워 넣었는데, 사용자가 스크린샷으로
액티비티 배지의 "획득 정보" 카드 디자인(흰색 카드 하나 안에 획득 일시·트리거 활동·활동 거리·활동
일자·Strava 버튼이 나란히, 인셋 보더의 작은 리스트 아이템이 아니라 카드 자체가 바로 흰 박스)을
제시하며 정정을 요청함.

**요청 원문**: "액티비티 배지와 같이 흰색 가장 바깥 박스 안에 위치해. 지금의 방문이력 박스 바깥으로
빼내는거야."

## 현재 구조 (레인저 사전 확인)

`jam-web/src/app/(main)/badges/[id]/page.tsx`:
- **액티비티 배지** "획득 정보" 카드(611~654행): `<Card>` 하나 = 흰 박스 하나. 그 안에 획득
  일시/트리거 활동/활동 거리/활동 일자 각 행 + 마지막에 `StravaLink` 버튼.
- **POI 배지** "획득 이력" 카드(584~610행): `<Card>` 하나 = 흰 박스 하나인데, 그 **안에 `<ul>`이
  있고 각 방문이 `<li>`(인셋 보더의 작은 하위 박스)로 들어감**. 지금은 그 `<li>` 안에 장소명·
  날짜·활동명·`StravaLink` 버튼이 전부 들어있어 박스 안에 박스가 중첩된 모양 — 사용자가 지적한
  문제 지점.
- `UserPoiBadgeEarnRow`에는 활동 배지와 동일한 필드(`triggered_by_activity_name`,
  `triggered_by_distance_km`, `triggered_by_activity_date`, `triggered_by_strava_id`)가 이미 있음
  (마이그레이션 `053_user_poi_badge_earns.sql`).

## 상세 요구사항

### 서비스/코드베이스 관점
- POI 배지는 반복 획득이라 방문 건수만큼 카드가 여러 개 나올 수 있음(1건이면 카드 1개). **방문
  1건 = 액티비티 배지 "획득 정보"와 동일한 디자인의 독립된 `<Card>` 1개**로 교체한다. 지금처럼
  하나의 "획득 이력" Card 안에 `<ul>`/`<li>`로 중첩하지 않는다.
- 각 카드에 표시할 필드는 액티비티 배지 "획득 정보"와 동일하게: 획득 일시(`earned_at`), 트리거
  활동(`triggered_by_activity_name`), 활동 거리(`triggered_by_distance_km`), 활동 일자
  (`triggered_by_activity_date`), Strava 버튼(`triggered_by_strava_id`) — 각각 있을 때만 표시하는
  기존 조건부 렌더링 패턴 유지.
- POI는 장소가 여러 곳일 수 있어 액티비티 배지에는 없는 "장소명"(`e.poi?.name`) 표시가 필요함 —
  카드 상단(제목 자리)에 장소명을 추가로 노출한다. 방문 건수 카운트 표시(`earnHistoryCount`)는
  전체 섹션 헤더로 유지할지, 각 카드가 독립되면서 자연히 사라질지는 구현 시 판단.
- 액티비티 배지 쪽 "획득 정보" 카드(611~654행)는 이번 요청 대상이 아니므로 그대로 둔다 — 로직/
  스타일 변경 없음.
- 스카우트가 티켓 010에서 제안했던 "StravaLink 공용화"는 이미 적용돼 있으니 그대로 재사용한다.
  이번 카드 구조 자체(필드 행 5개 + 버튼)를 또 다른 공용 컴포넌트로 뽑을지는 판단에 맡기되,
  뽑는다면 액티비티 배지 카드도 그 컴포넌트를 쓰도록 같이 정리 — 뽑지 않고 각자 유지해도 무방
  (스펙 범위 밖 리팩터링을 강제하지 않음).

### UI/UX 관점
- 최종 결과가 첨부 스크린샷(액티비티 배지 "획득 정보" 카드)과 동일한 디자인 톤으로 보여야 함:
  흰 카드 하나 = 하나의 방문/획득 단위.
- 신규 문구 추가 없음(기존 라벨·버튼 문구 재사용) — UX 라이팅 가이드 신규 검증 불필요.

## 완료 기록

### 구현 내용 요약
`jam-web/src/app/(main)/badges/[id]/page.tsx`의 POI "획득 이력" 렌더링 블록(구 584~612행)을
교체. 기존에는 `<Card>` 하나 안에 `<ul>`/`<li>`로 방문 건수를 중첩 리스트로 표시했는데, 이를
방문 1건당 독립된 `<Card>`로 분리했다. 각 카드는 액티비티 배지 "획득 정보" 카드와 동일한
필드 행 구조(획득 일시·트리거 활동·활동 거리·활동 일자·Strava 버튼, 값 있을 때만 조건부
렌더링)를 사용하며, 카드 상단에는 POI 배지 전용으로 장소명(`e.poi?.name`, 없으면
`earnHistoryUnknownPlace`)을 제목으로 노출한다. 방문 건수 카운트(`earnHistoryCount`)는
전체 섹션 헤더로 유지하되 흰 카드 밖의 얇은 타이틀 행(`px-1`)으로 옮겨, 카드 자체는
액티비티 배지 카드와 완전히 동일한 톤을 갖도록 했다. StravaLink 공용 컴포넌트는 그대로
재사용. 필드 행 구조를 별도 공용 컴포넌트로 추출하지는 않음(스펙에서 강제하지 않은
선택적 리팩터링이라 범위 밖으로 판단).
