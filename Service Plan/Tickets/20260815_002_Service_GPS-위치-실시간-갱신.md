# [Service] 드랍 화면 GPS 위치 — 마운트 1회 → 실시간 갱신

## 배경 / 문제 정의

현재 `/drops` 페이지(`DropsClient.tsx`)는 컴포넌트 마운트 시 `navigator.geolocation.getCurrentPosition()`을 1회만 호출한다. 사용자가 이동하더라도 위치가 갱신되지 않아, 드랍 가능 배지 판정이 마운트 시점의 좌표를 기준으로 고정된다.

**발견 경위:** 2026-08-15 Figma vs 스테이징 분석 중 Casey 항목으로 식별.

## 상세 요구사항

### 서비스/코드베이스 관점
- `navigator.geolocation.watchPosition()` 으로 전환하여 이동 중 위치 갱신
- 컴포넌트 언마운트 시 `clearWatch()` 호출로 리소스 정리 필수
- 갱신 주기·오차 허용 범위(accuracy threshold)는 배터리·UX 트레이드오프 검토 필요
- 과도한 갱신으로 드랍 API가 반복 호출되지 않도록 debounce 또는 위치 변화 임계값(예: 20m) 적용

### UI/UX 관점
- 위치 갱신 중 상태 표시 여부 결정 필요 (현재는 "위치 파악 중" 초기 상태만 존재)
- 위치 갱신 실패(accuracy 불량, 타임아웃) 시 기존 좌표 유지 or 재시도 정책 결정

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`DropsClient.tsx`의 GPS 위치 획득 방식을 `getCurrentPosition`(1회) → `watchPosition`(실시간)으로 전환했다.
위치 변화 임계값 20m를 Haversine 공식으로 검사해, 이 이하로 이동하면 `setUserLat`/`setUserLng` 갱신을 스킵하여 API 과다 호출을 방지한다.
컴포넌트 언마운트 시 `clearWatch(watchId)` cleanup을 반환해 배터리·리소스를 정리한다.

### 주요 의사결정 / 핵심 메모
- 배터리 소모 vs 위치 정확도 트레이드오프 → 임계값 20m로 확정. debounce 대신 거리 기반 필터링 선택 (GPS 흔들림에 더 견고)
- 이전 좌표를 `useRef` 대신 클로저 지역 변수(`prevLat`, `prevLng`)로 관리. watch 콜백 내부에서만 필요하므로 React 상태 불필요
- `enableHighAccuracy` 미사용 유지 (기존 주석 사유 그대로 — 실내 오탐 방지)
- 임계값 상수 `DROP_RELOAD_THRESHOLD_METERS = 20`으로 별도 선언해 추후 조정 편의 확보

### 잔여 이슈
- 위치 갱신 실패(accuracy 불량, 타임아웃) 시 재시도 정책 미구현 (티켓 원본 미결 사항)
- `GeolocationPositionError.code` 1/2/3 미분류 — 현재 모든 GPS 오류가 "권한 거부" 메시지로 표시됨
- `pos.coords.accuracy` 미검증 — 불량 좌표가 그대로 반영될 수 있음
- `watchPosition` `timeout`/`maximumAge` 옵션 미지정
