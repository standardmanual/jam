# [UI] 인벤토리 아이템배지 상세 → 배지 상세로 redirect 통일

## 배경 / 문제 정의

아이템배지 상세 화면은 어디서 접근하든 획득/미획득 여부만 다를 뿐 내용이 동일하다.
- 배지 메뉴(컬렉션 포함) 진입 시 → `/badges/[id]` (1:1 카드 레이아웃, 티켓 006 적용)
- 인벤토리 진입 시 → `/inventory/[itemId]` (별도 UI — 동일 배지를 다르게 표시)

단일 소스를 유지하는 가장 단순한 해법: `/inventory/[itemId]`에서 `/badges/[badge_id]`로 redirect.
이렇게 하면 향후 어느 쪽을 수정해도 분기가 생기지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `/inventory/[itemId]/page.tsx`를 다음 로직으로 교체:
  1. 인증 확인 (`user` 없으면 `/login` redirect)
  2. `inventory_items`에서 `badge_id`, `inventory_id` 조회 → 없으면 `notFound()`
  3. `inventory` 테이블에서 소유 확인 (다른 유저 아이템 접근 방지) → 없으면 `notFound()`
  4. `redirect('/badges/${badge_id}')`

### 히스토리 / 뒤로가기 관점
- Next.js `redirect()`는 302 응답 → 브라우저가 `/inventory/[itemId]`를 히스토리에 남기지 않고
  `/badges/[badge_id]`로 교체한다.
- 결과: 뒤로 가기 시 `/inventory/[itemId]` 이전 화면(인벤토리 목록 등)으로 자연스럽게 돌아간다.
- `/badges/[id]`의 TopNav는 `backHref={undefined}` → 브라우저 native back 사용 → 진입 경로가
  어디든(인벤토리 목록, 배지 탭, 컬렉션 등) 올바른 이전 화면으로 돌아간다.

### UI/UX 관점
- `/badges/[id]` item 변형에 ItemEarnHistory(획득 이력 배열, 시리얼·만료일 포함)가 이미 있으므로
  인벤토리 특화 정보(단일 아이템 획득일·만료일) 손실 없음.
- 미획득 배지를 인벤토리에서 접근하는 경우는 없으므로 `hasEarned` 판정은 배지 페이지에서 그대로 처리됨.

## 구현 계획

`/inventory/[itemId]/page.tsx` 전체 교체:

```ts
import { createClient } from '@/lib/supabase/server'
import { redirect, notFound } from 'next/navigation'

export default async function InventoryItemPage({ params }: { params: Promise<{ itemId: string }> }) {
  const { itemId } = await params
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!user) redirect('/login')

  const { data: itemData } = await supabase
    .from('inventory_items')
    .select('badge_id, inventory_id')
    .eq('id', itemId)
    .single()
  if (!itemData) notFound()

  const { data: inventoryCheck } = await supabase
    .from('inventory')
    .select('id')
    .eq('id', itemData.inventory_id)
    .eq('user_id', user.id)
    .single()
  if (!inventoryCheck) notFound()

  redirect(`/badges/${itemData.badge_id}`)
}
```
