# [UI] 배지 상세화면 배경테마 기반 구조 개편 (1차 — 시각 결과 무변경)

## 배경 / 문제 정의
[20260818_001](20260818_001_Feature_배지상세-배경테마-등급태그-커스터마이징-기획검토.md)에서 배지별
배경색·쉐이더 적용 방향을 검토하고 사용자와 범위를 확정했다. 쉐이더 기술 스택(CSS vs WebGL)은
아직 미정이라, 먼저 **코드 구조를 개편**해 추후 배경테마 기능을 얹기 쉽게 만드는 선행 작업을
진행한다. **이번 티켓은 시각적 결과물을 바꾸지 않는다** — 순수 구조 개편 + DB 컬럼 추가 +
어드민 이미지 업로드 방식 전환까지가 범위.

## 확정된 결정 사항 (20260818_001에서 이관)
- 등급 태그(RarityBadge) 쉐입 커스터마이징: **폐기**
- Footer도 배경 적용 대상에 포함 — 단, 전역 레이아웃을 조건부로 바꾸지 않고 배지 상세 페이지에서
  로컬 오버라이드하는 방식으로 구현
- 쉐이더 기술 스택: **보류** (다음 티켓에서 결정)
- 배지 이미지 Supabase Storage 이전: **이번 티켓에 포함**

## 스코프 수정 (2026-08-18, PASS 이후 사용자 피드백 반영)

개선 리뷰에서 `GlobalFooterSlot`의 경로 하드코딩 방식이 지적됨. 사용자 피드백: "TopNav·Footer가
자기 배경색을 스스로 칠하지 않으면(=투명하면), 페이지가 뷰포트 전체를 덮는 배경 레이어 하나만
깔아도 헤더든 본문이든 푸터든 자동으로 같은 색이 비쳐 보인다 — 페이지별 예외 코드가 필요 없다."

**Footer는 배경 테마 대상에서 제외하지 않는다** (이전 수정안 철회). 대신 구현 방식을 바꾼다:

- `Footer`는 이미 `bg-transparent` — 손댈 필요 없음
- `TopNav`는 기본이 불투명 `bg-[var(--color-bg)]`이고, "헤더·본문 배경톤 차이로 구분"하는 전역
  규칙([20260816_012])이 걸려 있어 전역 기본값은 유지. 배지 페이지에서만 기존 `headerStyle` prop으로
  덮어씀 (신규 매커니즘 불필요, 이미 있는 확장 지점 사용)
- Footer가 있는 지점까지 배경이 안 닿는 문제(Footer는 `(main)/layout.tsx`의 `main`
  안에서 렌더되고 `main` 자체가 불투명 `bg-surface`를 깖) → **배지 페이지가
  `position: fixed; inset: 0` 배경 레이어를 1개 렌더**해서 뷰포트 전체(헤더 밑~본문~푸터 밑)를
  깔고, `main`의 `bg-surface`보다 위 z-index로 배치. TopNav만 투명 처리하면 나머지는 자동으로
  비쳐 보임

**변경 지시**: `GlobalFooterSlot` 컴포넌트, `(main)/layout.tsx`의 Footer 교체, 배지 상세
페이지의 자체 Footer 렌더링(전역 Footer를 페이지가 대신 렌더하는 방식)을 모두 되돌리고
**Footer는 기존처럼 전역 레이아웃이 그대로 렌더링**하도록 원복. 대신 배지 페이지에 고정
배경 레이어 1개를 추가하고, `getBadgeBackgroundStyle`이 이 레이어와 TopNav `headerStyle`
양쪽에 동일한 값을 공급하도록 배선. 지금은 여전히 no-op(빈 값)이라 시각적 변화 없음.

## 게이트 리뷰 수정 (2026-08-18, Playwright 실증에서 발견된 클릭 차단 회귀)

### 원인
바로 위 "스코프 수정 반영 결과"에서 도입한 `position: fixed; inset: 0; zIndex: 0` 고정 배경
