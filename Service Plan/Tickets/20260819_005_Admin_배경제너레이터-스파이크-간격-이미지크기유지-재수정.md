# [Admin] 배경 제너레이터 스파이크 — 간격 조정 시 이미지 크기 유지하도록 재수정

## 배경 / 문제 정의
티켓 [20260819_004](20260819_004_Admin_배경제너레이터-스파이크-오프셋-행열-독립조정-버그수정.md)에서
"행 간격/열 간격이 서로 다른 축에만 영향을 주도록" 고쳤는데, 그 구현 방식(`buildTileCanvas`에서
`cellW`/`cellH`를 줄이고 `drawW = cellW * imageScale`, `drawH = cellH * imageScale`로 이미지를
셀 크기에 맞춰 다시 스케일)이 **근본적으로 잘못된 접근**이었다.

사용자 정정: **간격(행 간격/열 간격)을 조정해도 이미지 자체의 크기는 절대 바뀌면 안 된다.**
간격은 "이미지와 이미지 사이에 여백을 추가/제거하는 것"이지 "셀을 줄여서 그 안에 이미지를 다시
맞춰 넣는 것"이 아니다. 이미지 크기는 오직 별도 옵션인 "이미지 크기 조절"로만 바뀌어야 한다.
간격과 이미지 크기는 완전히 독립적인 두 옵션이다.

## 상세 요구사항

### 서비스/코드베이스 관점
- **핵심 원칙**: `patternTile.ts`에서 이미지를 그리는 크기(`drawW`/`drawH`)는 오직 "이미지 크기
  조절" 파라미터에서만 파생돼야 한다. `rowGap`/`colGap`은 이 크기 계산에 절대 관여하면 안 된다.
- 대신 간격은 **반복 주기(타일 피치)를 늘리는 방식**으로 구현한다:
  - 열 방향 타일 피치 = 이미지 가로 크기 + `colGap`
  - 행 방향 타일 피치 = 이미지 세로 크기 + `rowGap`
  - 이미지는 이 피치 박스 안에서 고정된 크기 그대로 그려지고, 나머지 공간(간격만큼)은 투명하게
    비워둔다. 간격을 늘리면 이미지 사이 여백만 넓어지고, 이미지 자체 크기는 그대로 유지된다.
- 티켓 004의 `cellW = tilePitchX - colGap`, `cellH = tilePitchY - rowGap` 방식(간격을 늘리면 셀이
  작아지고 이미지가 그 셀에 맞춰 축소되는 방식)은 **완전히 폐기**한다. 방향을 반대로 바꿔야 한다:
  타일 피치가 이미지 크기 + 간격으로 **늘어나는** 방식이어야 한다.
- 대칭반복(mirror)·stagger·회전 등 다른 패턴 옵션과 조합될 때도 이 원칙(간격≠이미지 크기 변화)이
  깨지지 않는지 함께 확인한다.
- **반드시 시각적으로 검증**(Playwright 스크린샷 등)해서: 간격을 0에서 크게 늘렸을 때 이미지
  자체의 픽셀 크기(가로/세로)가 동일하게 유지되고, 이미지 사이 여백만 넓어지는지 확인한다.
  예: 간격 0일 때 이미지 크기를 측정하고, 간격을 크게 늘린 뒤 이미지 크기를 다시 측정해서 두
  값이 같은지 스크린샷 비교나 픽셀 측정으로 확인하고 완료 기록에 근거를 남길 것.
- 그 외 제약(스테이징 전용, 로그인 없이 접근, main 머지 금지, 금지 의존성 미추가)은 이전 티켓과 동일.

## 구현 계획
1. `patternTile.ts`의 `buildTileCanvas`(또는 관련 함수)에서 이미지 그리기 크기 계산과 타일 피치
   계산을 분리 — 이미지 크기는 "이미지 크기 조절" 파라미터에서만, 타일 피치는 "이미지 크기 + 간격"

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`patternTile.ts`의 `buildTileCanvas`를 티켓 004의 "셀을 줄여서 이미지를 다시 스케일"하는
방식에서 "이미지 크기는 고정, 반복 주기(피치)만 늘리는" 방식으로 재작성했다.

- `drawW`/`drawH`(이미지가 실제로 그려지는 크기)는 이제 `baseCellW * imageScale` /
  `baseCellH * imageScale`로만 계산한다. `baseCellW`/`baseCellH`는 "XY 그리드 수"가 정하는
  기준 셀 크기(`previewSize / gridX`)이며, `rowGap`/`colGap`은 이 계산에 전혀 관여하지 않는다.
- 간격은 반복 주기(타일 피치)를 늘리는 방식으로 구현했다: `pitchX = drawW + colGap`,
  `pitchY = drawH + rowGap`. `ctx.drawImage`에는 항상 고정된 `drawW`/`drawH`를 전달하고,
  캔버스 크기·셀 중심 좌표·stagger 이동량 모두 `tilePitchX`/`tilePitchY` 대신 이 `pitchX`/`pitchY`
  기준으로 다시 계산했다.
- `PatternPanel.tsx`에서 `buildTileCanvas`에 넘기는 인자명을 `tilePitchX/Y` → `baseCellW/H`로
  바꾸고, 이 값이 더 이상 "타일 피치"가 아니라 "이미지 크기의 기준값"이라는 점을 주석으로 명시했다
  (동작은 그대로, 명명만 정정 — 실제 값 계산식 `previewSize / gridX`는 변경 없음).
- mirror(대칭반복)·stagger·rotation은 `drawW`/`drawH`를 그대로 사용하고 `pitchX`/`pitchY`
  단위로 반복 개수·이동량만 계산하므로, 이 옵션들과 조합해도 간격이 이미지 크기에 영향을
  주지 않는다.

### 주요 의사결정 / 핵심 메모
- 티켓 004의 근본 원인은 "간격만큼 셀을 줄이고 그 줄어든 셀에 이미지를 다시 맞춰 그리는" 접근
  자체였다. 셀이 작아지면 그 안에 그려지는 이미지도 작아질 수밖에 없어, "간격≠이미지 크기 변화"
  원칙과 구조적으로 충돌했다. 이번 수정은 방향을 반대로 바꿔 "이미지 크기는 고정 상수, 간격은
  반복 주기에 더해지는 여백"으로 재정의해 이 충돌을 근본적으로 제거했다.
- 함수 파라미터명을 `tilePitchX/Y`에서 `baseCellW/H`로 바꾼 것은 리팩터링이 아니라 버그의 원인이
  된 잘못된 명명(실제로는 "타일 피치"가 아니라 "이미지 크기의 기준값"이었음)을 바로잡은 것이다.
