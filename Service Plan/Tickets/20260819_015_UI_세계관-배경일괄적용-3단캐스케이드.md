# [UI] 세계관 배경 일괄 적용 — 어드민 저작 UI + 3단 캐스케이드

## 배경 / 문제 정의

티켓 013(스키마+공용 UI)·014(컬렉션)에 이어 마지막 단계로, **세계관(faction)** 단위 배경
일괄 적용 기능을 완성한다.

현재 상태 확인 결과:
- `/api/admin/factions/[id]/apply-background/route.ts`는 이미 존재하지만 `background_color`/
  `background_shader_id` **2필드만**, 그리고 **세계관 직속 배지(`faction_id` 일치)에만** 1회성
  복사한다. 소속 컬렉션(`item_books`)이나 그 컬렉션의 아이템배지에는 전혀 적용되지 않는다.
- `/api/admin/factions/route.ts`(POST)·`[id]/route.ts`(PUT)도 `background_color`/
  `background_shader_id` 2필드만 저장한다.
- `FactionForm.tsx`에는 색상 필드만 있고 이미지/영상 제너레이터 UI가 없다.
- 세계관은 서비스에 공개 상세 페이지가 없다 (`/admin/factions/[id]`만 존재) — 세계관 자신의
  배경값은 화면에 직접 렌더링되지 않고, 오직 하위로 캐스케이드하기 위한 마스터 값이다.

**사용자 확정 사항**(이번 작업 착수 전 확인 완료):
- 캐스케이드 범위는 **3단 전부**: (a) 세계관에 직속된 배지(`badges.faction_id` 일치),
  (b) 그 세계관 소속 모든 컬렉션(`item_books.faction_id` 일치), (c) 그 컬렉션들에 속한 모든
  아이템배지(`badges.item_book_id` in 소속 컬렉션 id 목록).
- 덮어쓰기 동작은 **항상 덮어씀** — 개별 배지/컬렉션이 자기 값으로 커스터마이징했어도 상위에서
  일괄 적용을 누르면 그 값으로 교체된다 (기존 20260818_004의 1회성 스냅샷 복사 방식 그대로,
  실시간 fallback 구조 아님).

## 상세 요구사항

### 서비스/코드베이스 관점

1. **어드민 저작 UI**: `FactionForm.tsx`에 `ItemBookForm.tsx`(티켓 014)와 동일한 패턴으로
   배경 설정 UI를 추가한다. `BackgroundGeneratorPreview`를 `existingImageOption` 없이 사용
   (새 이미지 업로드만). 세계관은 실제 렌더링되는 서비스 화면이 없으므로, 미리보기는 "이 배경이
   실제로 어떻게 보일지"를 보여주는 대표 프레임을 쓴다 — 컬렉션용
   `ItemBookDetailPreviewFrame`을 재사용하거나(세계관 배경 = 소속 컬렉션에 그대로 복사되는
   값이므로 컬렉션 프레임으로 미리 보여주는 것이 실제 결과와 가장 가깝다), 여의치 않으면 배지
   프레임을 재사용한다 — 실제 구현 시 더 적절한 쪽으로 판단.
   - 저장(`저장` 버튼): `background_color`/`background_image_url`/`background_video_url`을
     세계관 자신의 행에 저장 (3자 배타).
   - **일괄 적용** 버튼: 저장된 세계관 자신의 값을 3단 전체로 복사 — 아래 2번 항목.
   - 화면에 적용 범위를 명시: "이 설정은 이 세계관에 속한 배지, 소속 컬렉션, 그 컬렉션의
     아이템배지 전체에 일괄 적용됩니다." 같은 안내 문구 (해요체, 간결하게).

2. **일괄 적용 API 3단 캐스케이드 확장**: `/api/admin/factions/[id]/apply-background/route.ts`를
   다음과 같이 확장한다:
   - 세계관 자신의 `background_color`/`background_shader_id`/`background_image_url`/
     `background_video_url` 4필드를 조회한다.
   - (a) `badges` 중 `faction_id = X AND deleted_at IS NULL`에 4필드 복사.
   - (b) `item_books` 중 `faction_id = X`에 4필드 복사.
   - (c) (b)에서 찾은 `item_books.id` 목록을 `IN`으로 사용해 `badges` 중
     `item_book_id IN (...) AND deleted_at IS NULL`에 4필드 복사.
   - 항상 덮어쓰기(사용자 확정). 응답에 각 단계별 적용 건수를 포함해 어드민 화면에서 확인
     가능하게 한다 (예: `{ directBadges: n, itemBooks: n, itemBookBadges: n }`).
   - 티켓 014 개선 리뷰에서 badges/item_books/factions 3개 apply-background 라우트의 로직
     패턴이 유사하다는 지적이 있었다 — 억지로 공용 유틸로 뽑을 필요는 없지만, 컬렉션 라우트
     (014에서 이미 4필드로 확장됨)를 참고해 일관된 방식으로 작성할 것.

3. **저장 API 확장**: `/api/admin/factions/route.ts`(POST)·`[id]/route.ts`(PUT)가
   `background_image_url`/`background_video_url`도 받아 저장하도록 확장.

### UI/UX 관점

- 어드민 화면은 MODULAR 적용 대상 아님 — 탐색·재사용 판정 절차 생략.
- 세계관 자신은 공개 서비스 페이지가 없으므로, 이 티켓에서 신규 서비스 페이지를 만들 필요는
  없다 (범위 아님). 오직 캐스케이드 대상인 컬렉션 상세화면(이미 티켓 014에서 렌더링 구현됨)과
  배지 상세화면(기존)에서 결과가 보인다.

## 구현 계획

1. `FactionForm.tsx`에 배경 저작 UI 연결 + 적용 범위 안내 문구
2. `/api/admin/factions/route.ts`·`[id]/route.ts` 저장 필드 확장
3. `/api/admin/factions/[id]/apply-background/route.ts` 3단 캐스케이드로 재작성
4. 기존 세계관 목록/폼 다른 필드 동작에 회귀 없는지 확인
5. 컬렉션 배경 렌더링(티켓 014)·배지 배경 렌더링(티켓 007~012)과 실제로 맞물려 동작하는지
   전체 흐름 점검 (세계관 배경 설정 → 일괄 적용 → 컬렉션 상세/배지 상세에 반영)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `/api/admin/factions/[id]/apply-background/route.ts`를 3단 캐스케이드로 재작성:
  (a) 세계관 직속 배지(`faction_id` 일치) → (b) 소속 컬렉션(`item_books.faction_id` 일치) →
  (c) 그 컬렉션들의 아이템배지(`badges.item_book_id IN (...)`). 4필드(color/shader_id/
  image_url/video_url) 모두 복사, 항상 덮어쓰기. 응답에 `directBadges`/`itemBooks`/
  `itemBookBadges`/`appliedCount` 포함.
- `/api/admin/factions/route.ts`(POST)·`[id]/route.ts`(PUT)가 `background_image_url`/
  `background_video_url`도 받아 저장하도록 확장(DB 컬럼은 티켓 013에서 이미 존재).
- `FactionForm.tsx`에 `ItemBookForm.tsx`(티켓 014)와 동일한 패턴으로 `BackgroundGeneratorPreview`
  연결(`existingImageOption` 없이 새 이미지 업로드만). 미리보기는 `ItemBookDetailPreviewFrame`을
  재사용 — 세계관 배경이 소속 컬렉션에 그대로 복사되는 값이라 컬렉션 프레임이 실제 결과와 가장
  가깝다고 판단(티켓 지시 그대로).
- 적용 범위 안내 문구, "일괄 적용" 확인 다이얼로그·결과 배너를 3단 건수(직속 배지/소속 컬렉션/
  컬렉션 아이템배지)로 노출하도록 변경.
- 일괄 적용 버튼 클릭 시 클라이언트에서 `/api/admin/badges`·`/api/admin/itembooks`를 함께 조회해
  3단 각각의 예상 건수를 미리 계산 후 확인 다이얼로그에 표시(실제 적용은 서버 API가 재계산해 처리).

### 주요 의사결정 / 핵심 메모
- 미리보기 프레임은 배지 프레임 대신 `ItemBookDetailPreviewFrame`을 재사용 — 세계관 배경값이
  최종적으로 렌더링되는 화면은 항상 "컬렉션 상세"이므로(직속 배지는 배지 프레임에서, 컬렉션은
  컬렉션 프레임에서 이미 동일 값을 보게 됨) 컬렉션 프레임이 세계관 저작자에게 가장 대표성 있는
  미리보기라고 판단했다.
- 일괄 적용 확인 다이얼로그의 건수는 클라이언트에서 전체 배지/컬렉션 목록을 받아 필터링해 계산한
  추정치다. 실제 적용은 서버(`apply-background` API)가 같은 조건으로 다시 조회해 처리하므로
  결과 배너의 건수(서버 응답)가 최종 진실값이다.
