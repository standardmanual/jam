# [bug] POI 캐러셀 — tier2 POI에 드랍된 아이템이 안 보이는 회귀 (티켓 023 원인)

## 배경 / 문제 정의
사용자가 `sihyunrr@gmail.com` 계정으로 "시오의원"(tier2, 네이버 자동수집 POI)에 아이템배지를
드랍했는데, 캐러셀 카드에는 "아직 아이템이 없어요"(빈 상태)만 표시됨.

## 원인 (DB로 직접 확인)
`poi` 테이블 확인 결과 "시오의원"은 `poi_tier=2`이며 실제 UUID(`b522607b-...`)로 정식 저장돼
있고, `poi_drops` 테이블에도 이 `poi_id`를 참조하는 드랍이 정상적으로 존재함
(`source=user`, `is_available=true`, `dropper_user_id`가 해당 계정과 일치, 미만료).

티켓 20260820_023에서 "tier2 POI는 DB에 저장 안 돼서 poi_drops와 연결될 수 없다"는 **잘못된
전제**로 [PoiCarouselModal.tsx](../../../../jam-web/src/components/PoiCarouselModal.tsx)의 드랍
지연 로드 useEffect를 수정해, tier2 POI는 `/api/drops/poi/[poiId]` API를 아예 호출하지 않고
`dropsCache`를 무조건 빈 배열로 채우도록 만들었다. 하지만 실제로는 tier2 POI도 백그라운드에서
`poi` 테이블에 정식 저장되고 나면(티켓 20260820_022에서 이미 "poi_tier=2 고정 저장" 확인된 사실)
진짜 UUID를 가지므로 `poi_drops`가 정상적으로 연결될 수 있다 — 이번 사례가 그 증거.

## 상세 요구사항
- tier1/tier2 구분 없이 모든 POI에 대해 항상 `/api/drops/poi/[poiId]`를 호출해 드랍 목록을 채운다.
- (원래 티켓 023이 고치려던) tier2 POI 무한 스피너 문제는 tier 분기 자체가 아니라 "API 호출을
  건너뛰면 캐시가 영원히 undefined로 남는다"는 구조적 문제였으므로, tier 분기를 제거하고 모든
  POI가 API를 호출하도록 하면 스피너 문제도 함께 해소된다(API가 정상적으로 빈 배열이든 실제
  드랍이든 응답하므로).

## 구현 계획
1. `PoiCarouselModal.tsx`의 드랍 지연 로드 useEffect에서 `poi.poi_tier === 2` 분기를 제거하고
   모든 POI가 `fetchPoiDrops`를 호출하도록 복원
2. tsc/eslint/build 검증
3. 소스코드 → 스테이징 → 프로덕션까지 반영, 실제 DB 데이터(시오의원 드랍)로 재확인
