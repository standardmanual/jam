# [Admin] 배지 비활성(회수) 상태 — 상세 화면 표시 + 목록 필터

## 배경 / 문제 정의
[20260823_004](./20260823_004_Admin_컬렉션비활성화-배지연쇄회수.md)(컬렉션 비활성화 →
소속 배지 연쇄 회수)를 프로덕션 배포 후 사용자가 실제로 컬렉션을 비활성화하고 소속 배지
상세 화면에서 확인했으나, **회수(소프트 삭제)됐다는 상태값을 어디서도 확인할 수 없었다.**
조사 결과 두 가지 갭이 원인:

1. **`src/components/admin/badges/BadgeDetail.tsx`가 `deleted_at`을 전혀 렌더링하지 않는다**
   — 배지가 활성인지 회수됐는지 상세 화면 어디에도 표시가 없다.
2. **`src/app/admin/badges/page.tsx`(45행)가 `.is('deleted_at', null)`로 목록 자체에서
   회수된 배지를 숨긴다** — 검색·필터로는 아예 찾을 수 없고, 컬렉션 수정 화면의 "소속 배지"
   목록(`item_books/[id]/page.tsx`, 이쪽은 `deleted_at` 필터가 없어 그대로 보임)을 거쳐
   링크를 타고 들어가야만 상세 화면에 도달 가능했다.

## 상세 요구사항

### 1. 배지 상세 화면 — 활성/비활성 상태 표시
- 대상: `src/components/admin/badges/BadgeDetail.tsx`
- `badge.deleted_at`이 `null`이면 "활성" 표시(또는 아무 표시 없이 기본 상태로 두어도 무방 —
  기존 화면에 상태 배지가 전혀 없었으므로 판단은 구현자 재량), `deleted_at`이 있으면 눈에
  띄는 상태 배지로 **"비활성화됨 · YYYY.MM.DD 회수"** 형태로 표시한다 (날짜 포맷은
  `Service Plan/Specs/UX_WRITING_GUIDELINE.md`의 날짜 표기 규칙 참고, 위치는 배지 이름/타입
  근처 헤더 영역 권장).
- 색상/톤은 기존 어드민 화면의 위험·경고 표현(예: 삭제 확인 모달의 빨간 계열)과 일관되게.

### 2. 배지 목록 — 상태 필터 추가 (기본 동작은 유지)
- 대상: `src/app/admin/badges/page.tsx`, `BadgesFilterBar.tsx`, `BadgeList.tsx`/`BadgeCard.tsx`
- `page.tsx`의 `.is('deleted_at', null)` 무조건 필터를 제거하고, **상태 필터 파라미터**
  (`status` — 값: `active`(기본값) / `inactive` / `all`)로 대체한다.
  - `status` 쿼리 파라미터가 없거나 `active`면 기존과 동일하게 `deleted_at IS NULL`만 조회
    (기본 목록 화면이 갑자기 회수 배지로 뒤덮이지 않게 — 기존 동작 보존이 최우선).
  - `inactive`면 `deleted_at IS NOT NULL`, `all`이면 필터 없음.
- `BadgesFilterBar.tsx`에 상태 필터 셀렉트를 추가한다. **주의**: 이 파일의 기존 필터들은
  네이티브 `<select>`로 되어 있지만(레거시), 신규 추가하는 이 필터는 프로젝트 규칙(어드민 UI는
  shadcn 표준 — 네이티브 select 금지)에 따라 **`components/ui/select.tsx`(shadcn, 이미 존재)**
  로 구현한다. 기존 필터들을 함께 shadcn으로 교체할 필요는 없음(이번 티켓 범위 밖).
- `all`/`inactive`로 조회했을 때 목록에 표시되는 각 배지 카드/행에도 1번과 동일한 방식의
  상태 배지를 작게 표시한다(`BadgeCard.tsx`, 데스크톱 테이블이 있다면 해당 컴포넌트도).

### UI/UX 관점
- 어드민 화면은 MODULAR 적용 대상 아님(정책) — service-specific으로 구현.
- 상태 필터 기본값은 반드시 `active`(기존과 동일한 목록)로 — 회수 배지가 기본 노출되어
  운영 화면이 지저분해지는 걸 방지.
- "비활성화됨" 표시는 명확하고 눈에 띄어야 한다(운영자가 실수로 활성 배지처럼 다루지 않도록).

## 범위 밖 (참고만, 이번 티켓에서 다루지 않음)
- `item_books`(컬렉션) 목록/상세 화면도 `is_active` 상태를 시각적으로 표시하지 않는 동일한
  종류의 갭이 있다(컬렉션 목록은 `is_active` 필터링 자체는 안 하지만, 활성/비활성 상태 배지가
  없음). 이번 티켓은 사용자가 명시적으로 지적한 "배지 상세 화면" 범위로 한정한다 — 컬렉션
  쪽은 필요시 별도 티켓으로.
- `BadgeForm.tsx`(수정 화면)에도 상태 표시를 추가할지는 이번 범위 밖 — 상세(읽기전용)
  화면에만 추가한다.
- `BadgeDetail.tsx`의 "삭제" 버튼(239~246행)은 `// 삭제 로직은 추후 구현` 상태로 실제 동작이
  없는 미완성 코드다 — 이번 티켓과 무관하니 손대지 않는다(발견 사실만 기록).

## 구현 계획
- DB 마이그레이션 없음 (기존 `badges.deleted_at` 컬럼만 사용).
- 수정: `src/app/admin/badges/page.tsx`, `BadgesFilterBar.tsx`,
  `src/components/admin/badges/BadgeDetail.tsx`, `BadgeCard.tsx`(및 데스크톱 테이블 컴포넌트가
  있다면 함께).
- 회귀 위험: 목록 쿼리 필터 로직을 바꾸는 것이므로, `status` 파라미터 미지정 시 기존
  `.is('deleted_at', null)`과 정확히 동일한 결과가 나오는지 확인 필수.
