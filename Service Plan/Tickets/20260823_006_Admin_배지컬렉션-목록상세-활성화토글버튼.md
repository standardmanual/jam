# [Admin] 배지/컬렉션 목록·상세 화면에 활성/비활성 토글 버튼 추가

## 배경 / 문제 정의
[20260823_004](./20260823_004_Admin_컬렉션비활성화-배지연쇄회수.md)·
[20260823_005](./20260823_005_Admin_배지비활성상태-노출및필터.md)로 컬렉션 비활성화 연쇄
회수와 배지 상태 표시는 구현됐지만, 상태를 바꾸려면 여전히 각 화면(컬렉션 수정 폼, 배지
수정 폼)까지 들어가야 한다. 목록·상세 화면에서 바로 토글할 수 있는 버튼이 필요하다.

## 기존 자산 (재사용 대상)
- `badges.deleted_at` 소프트 삭제, `item_books.is_active` — 이미 존재.
- `PUT /api/admin/itembooks/[id]`: `is_active` true→false 저장 시 소속 배지 연쇄 소프트
  삭제하는 로직이 이미 있음(20260823_004). 이번 신규 엔드포인트도 **같은 캐스케이드 로직을
  중복 구현하지 말고 함수로 추출해 공유**한다.
- `GET /api/admin/itembooks/[id]/deactivation-impact`: 영향 범위(배지 수·보유 유저 수) 조회 —
  이미 있음, 재사용.
- `ItemBookForm.tsx`의 기존 활성화 Switch+AlertDialog 흐름(폼 "저장" 시점까지 실제 반영을
  미루는 방식)은 **이번 티켓에서 건드리지 않는다** — 새로 만드는 목록용 토글은 그와 별개로
  **즉시 반영**(별도 저장 버튼 없이 클릭 즉시 API 호출) 방식이어야 한다.

## 상세 요구사항

### 1. 신규 API — 즉시 토글용 (폼의 전체 저장 PUT과 별개)
- `PATCH /api/admin/itembooks/[id]/route.ts` 신규 핸들러: body `{ is_active: boolean }`.
  `is_active` 컬럼만 갱신. `true→false`(비활성화)면 기존 PUT이 이미 수행하는 배지 연쇄
  소프트 삭제(`badges.item_book_id = id AND deleted_at IS NULL` → `deleted_at = now()`)를
  동일하게 수행 — 이 로직을 공용 함수로 추출해 PUT과 PATCH 둘 다에서 호출한다.
  `false→true`(재활성화)는 `is_active`만 갱신, 배지는 건드리지 않는다(기존 설계 결정 유지).
- `PATCH /api/admin/badges/[id]/route.ts` 신규 핸들러: body `{ active: boolean }`.
  `active: false` → `deleted_at = now()`(기존 DELETE 핸들러와 동일 동작, DELETE는 그대로 두고
  건드리지 않음 — `BadgeForm.tsx`의 기존 삭제 흐름이 DELETE를 쓰고 있음). `active: true` →
  `deleted_at = null`(신규 — 지금까지 배지를 되살리는 API가 없었음).

### 2. 배지 상세 화면 (`src/components/admin/badges/BadgeDetail.tsx`)
- 기존 "액션 버튼" 영역(수정/삭제 버튼이 있는 곳)에 **활성화/비활성화 토글 버튼**을 추가한다.
  `deleted_at` 없으면 "비활성화" 버튼(누르면 끔), 있으면 "활성화" 버튼(누르면 켬).
- 비활성화(끄기) 시에는 shadcn `AlertDialog`로 간단히 확인("이 배지를 비활성화하면 이미
  획득한 유저에게 더 이상 보이지 않습니다. 계속하시겠습니까?" 정도, 영향 범위 숫자 조회는
  불필요 — 배지 단건이라 컬렉션 캐스케이드만큼 큰 영향이 아님). 활성화(켜기)는 확인 없이 즉시.
- 기존 "삭제" 버튼(현재 `// 삭제 로직은 추후 구현` 상태, 미완성)은 이번 티켓과 무관 —
  손대지 않는다.

### 3. 배지 목록 화면 (`BadgesTable.tsx`, `BadgeCard.tsx`)
- `BadgesTable.tsx`: "액션" 열(현재 "상세보기" 버튼만 있음) 안에서 **"상세보기" 버튼의 왼쪽에**
  토글 버튼을 추가한다(새 열을 만드는 게 아니라 같은 액션 열 안에 나란히 배치).
- `BadgeCard.tsx`: 하단 액션 영역의 "상세보기" 버튼 옆(왼쪽)에 동일한 토글 버튼을 추가한다
  (모바일 카드 뷰도 목록 화면의 일부이므로 함께 처리 — 필수).
- 두 곳 모두 2번과 동일한 확인 방식(끄기만 확인, 켜기는 즉시). 토글 후 목록에 반영된 상태
  (상태 배지·필터 결과)가 갱신되어야 한다(예: `router.refresh()` 또는 로컬 상태 갱신).

### 4. 컬렉션 목록 화면 (`ItemBookTable.tsx`, 데스크톱 우선)
- **가장 우측에 새 열**을 추가해 활성/비활성 토글 버튼을 배치한다(헤더 "상태" 또는 "관리").
- 비활성화(끄기) 시 `GET /deactivation-impact`로 영향 범위(소속 활성 배지 수·보유 유저 수)를
  조회해 shadcn `AlertDialog`로 표시 후 확인 — `ItemBookForm.tsx`가 이미 하는 것과 동일한
  안전장치이나, **코드는 새로 작성**(폼의 기존 로직은 건드리지 않는다는 제약 때문). 중복이
  걱정되면 "확인 모달 표시" 부분만 작은 공용 컴포넌트/훅으로 뽑아 폼과 목록 둘 다에서 쓰는
  것은 허용(단, 폼의 기존 저장 흐름 자체는 변경 금지).
- `ItemBookCard.tsx`(모바일)에도 동일 토글을 추가하는 것을 권장하나 필수는 아니다(사용자가
  "열"이라는 표현을 써서 테이블 기준으로 요청했음 — 모바일 카드는 구현자 재량).

### UI/UX 관점
- 어드민 화면은 MODULAR 적용 대상 아님 — service-specific 구현.
- 토글 버튼 라벨은 상태에 따라 명확히 바뀌어야 한다("활성화" ↔ "비활성화") — 아이콘만으로
  표현하지 말 것(오조작 방지).
- 목록에서 토글 직후 해당 행/카드의 상태 배지(20260823_005에서 추가된 것)도 즉시 갱신되어야
  한다.

## 구현 계획
- DB 마이그레이션 없음.
- 신규: `PATCH /api/admin/itembooks/[id]/route.ts`, `PATCH /api/admin/badges/[id]/route.ts`.
- 수정: `ItemBookTable.tsx`(신규 열), `BadgesTable.tsx`/`BadgeCard.tsx`(액션 열 내 버튼 추가),
  `BadgeDetail.tsx`(액션 버튼 추가).
- 회귀 위험: 기존 `PUT /api/admin/itembooks/[id]`의 캐스케이드 로직을 함수로 추출할 때 동작이
  바뀌지 않는지 확인(리팩터링이지 로직 변경이 아니어야 함). 기존 `ItemBookForm.tsx`·
  `BadgeForm.tsx`의 저장/삭제 흐름은 이번 티켓으로 변경되지 않아야 한다.
