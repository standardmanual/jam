# [UI] 최초 Strava 연동 직후 배지 획득 연출 — 피드 기록 시각 스키마 보완 포함

> 티켓 **20260823_008**에서 분리됐다. 게이트 리뷰가 프로덕션 실데이터로 **동작 불가**를
> 확인했고, 근본 원인이 스키마 문제라 우회하지 않고 제대로 푼다.

## 배경 / 문제 정의

수동 동기화 경로(`SyncButton`)는 20260823_008에서 연결됐다. 그런데 **최초 Strava 연동**은
OAuth 콜백이 백필 싱크를 돌린 뒤 곧바로 리다이렉트해서, 응답 본문에 배지를 실을 수 없다.
도착 페이지에서 "방금 획득한 배지"를 되읽어야 한다.

### 🔴 왜 008에서 실패했나 — `event_at`은 기록 시각이 아니다

008 구현은 `user_activity_feed.event_at`으로 "최근 10분 획득"을 판정했다. 그런데 이 컬럼에는
**Strava 활동 시작 시각**이 들어간다. `recordFeedEvent()`의 4번째 인자로 활동 시작 시각을
그대로 넘기기 때문이다:

- `src/lib/badge-engine/index.ts` — `triggerActivity?.startDateLocal ?? triggerActivity?.startDate`
- `src/lib/drop-engine/index.ts` — `activityStartDate`
- `src/lib/strava/sync.ts` — `rawActivity.start_date`

**프로덕션 실측 대조** (`item_dropped` 피드 14건의 `event_at` vs `inventory_items.obtained_at`):

| 항목 | 결과 |
|---|---|
| 10분 이내 | **0 / 14건** |
| 편차 | **-470분 ~ +1813분** |
| 예시 | 피드 `2026-08-22T07:17:10Z` vs 삽입 `2026-08-22T11:24:18Z` (247분) |

백필은 사용자의 *과거* 활동을 처리하므로, 그 활동 시작 시각이 10분 이내일 확률은 사실상 0이다.

### 🔴 두 번째 문제 — 로컬 벽시계가 UTC로 오해석된다

`startDateLocal`은 Strava가 **로컬 벽시계에 `Z` 접미를 붙여** 주는 값이다. 이걸 `timestamptz`에
넣으면 KST 사용자는 `event_at`이 실제보다 **최대 +9시간 미래**로 찍힌다.

그러면 "몇 시간 전에 이미 본 배지"가 10분 창에 걸려 **오검출**된다. 즉 미노출과 오검출이
양방향으로 발생한다. 이 문제는 최초 연동 연출뿐 아니라 **피드 정렬과 "획득 시각" 표시 전반**에
영향을 준다.

### 🔴 세 번째 문제 — 삽입 시각 컬럼이 아예 없다

`user_activity_feed`의 컬럼은 `id / user_id / event_type / event_at / metadata` 5개뿐이다.
**"언제 기록됐는지"를 사후에 알 방법이 없다.**

## 상세 요구사항

### A. 스키마 보완 (선행)

`user_activity_feed`에 **기록 시각 컬럼을 추가**한다 (`created_at timestamptz NOT NULL DEFAULT now()` 등).

- 마이그레이션 파일을 `jam-web/supabase/migrations/0XX_*.sql`로 남긴다
- 기존 행 백필 전략을 정한다 (예: `event_at`으로 채우거나 NULL 허용 후 점진 적용)
- **실행은 사용자 승인 후 오케스트레이터가 한다** — jam-developer는 SQL 파일 작성까지만

### B. 최초 연동 연출 연결

- 콜백 리다이렉트에 플래그를 붙이고, 도착 페이지에서 최근 획득 배지를 되읽는다
  (`/profile`은 `/{username}` 경유지이므로 플래그를 목적지까지 전달해야 한다)
- 판정 기준은 **A에서 추가한 기록 시각 컬럼**을 쓴다
- 대기 표현은 **`WanderingEyesLoader`** (2026-08-24 사용자 확정)
- 오버레이는 `src/components/BadgeRevealOverlay.tsx` 재사용.
  ⚠️ 008에서 이 경로가 빠지면서 **`loading` prop과 대기 화면 분기를 제거**했으므로 되살려야 한다
  (죽은 코드를 남기지 않으려는 의도적 제거였다)
- i18n `badgeReveal.loading` 키도 함께 제거됐으므로 되살린다

### C. 검증 — 목 데이터로 끝내지 말 것

008이 이 경로만 Playwright route 가로채기(목 데이터)로 검증했고, 실제 호출에서 빈 배열을 받고
"최근 획득 없음"으로 오해석해 FAIL을 놓쳤다.

**실제 DB 데이터로 판정 로직이 동작함을 반드시 실측한다.** 프로덕션 Supabase는 조회만 하고,
쓰기가 필요한 검증은 사용자 승인 후 진행한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**1. 스키마 보완 — `user_activity_feed.created_at` (마이그레이션 093, 미실행)**

`jam-web/supabase/migrations/093_user_activity_feed_created_at.sql`을 **작성만** 했다.
실행은 사용자 승인 후 오케스트레이터가 한다.

실행 순서를 세 단계로 나눈 것이 핵심이다. `ADD COLUMN created_at TIMESTAMPTZ NOT NULL
DEFAULT NOW()`를 한 줄로 쓰면 PostgreSQL 11+ 는 기존 행 전체에 **ALTER 시점의 NOW() 하나**를
채운다 — 기존 388행이 전부 "방금 기록됨"이 되어 마이그레이션 직후 10분 동안 연출이 과거
배지를 통째로 띄우는 오검출이 난다. 그래서 (1) NULL 컬럼 추가 → (2) 백필 → (3) DEFAULT·NOT NULL
순으로 나누고, 세 단계를 한 트랜잭션(ACCESS EXCLUSIVE 락)으로 묶었다.

백필 값은 `LEAST(event_at, NOW() - INTERVAL '1 hour')`다. 기존 행의 기록 시각은 사후에 알 수
없어 `event_at`으로 근사하되, `event_at`이 "지금에 가깝거나 미래"인 행(로컬 벽시계 오해석)은
판정 창(10분) 밖으로 밀어낸다 — **오검출보다 미노출이 안전한 방향**이기 때문이다.
실측 시점 기준 `event_at`이 현재 이후인 행은 0건이라 이 상한은 사실상 no-op이며 백필 결과는
`event_at`과 동일하다. 조회 조건(user_id + event_type + created_at)에 맞춘 인덱스
`idx_user_activity_feed_user_created`도 함께 만든다.

`recordFeedEvent()`는 `created_at`을 넘기지 않으므로 이후 INSERT는 항상 DB 시계로 채워진다.

**2. 판정 기준을 `created_at`으로 바꾼 최근 획득 조회 API**

`src/app/api/badges/recent-earned/route.ts`(신규)는 `user_activity_feed`를 **`created_at`**
내림차순으로 읽어(최근 10분, `badge_earned`·`item_dropped`) `badge_id`를 모으고, 획득
순서(오래된→최신)로 뒤집어 `buildEarnedBadgePayload()`에 넘긴다. 상한·잔여 개수 계약이
`/api/strava/sync`와 완전히 동일하다.

조회 오류 시에는 연출만 생략하고 빈 결과를 준다(화면은 정상 동작). 단 **오류 코드까지 로그에
남긴다** — 008이 빈 배열을 "최근 획득 없음"으로 오독해 FAIL을 놓쳤기 때문에, "컬럼 없음(42703)"과
"진짜 없음"이 로그에서 구분되게 했다.

**3. 최초 연동 연출 연결 (008에서 제거됐던 경로 복원 + 판정 기준 교체)**

- `api/strava/callback/route.ts`: 리다이렉트 목적지에 `&reveal=1`을 붙인다.
- `profile/page.tsx`: `/profile`은 `/{username}`으로 넘기는 경유지라 쿼리가 사라진다 →
  `reveal=1`을 목적지 URL에 다시 실어준다.
- `src/components/StravaConnectReveal.tsx`(신규)를 `(main)/layout.tsx`에 마운트했다.
  도착 지점이 한 번 더 옮겨가므로 특정 페이지가 아니라 레이아웃에 둔다. `?reveal=1`을 보면
  URL에서 플래그를 지우고(`router.replace`) `/api/badges/recent-earned`를 호출한다.
  재요청 방지는 `startedRef`, 언마운트 후 setState 방지는 `mountedRef`로 나눠 처리했다.
- `BadgeRevealOverlay.tsx`: `loading` prop과 `WanderingEyesLoader` 대기 화면 분기를 되살렸다
  (008에서 죽은 코드를 남기지 않으려고 의도적으로 제거했던 부분). `revealing = open && !loading`.
- i18n `badgeReveal.loading`(`방금 획득한 배지를 확인하고 있어요`) 키를 되살렸다.

신규 MODULAR 컴포넌트는 만들지 않았다. `patterns/BadgeRevealCarousel`·
`feedback/WanderingEyesLoader`·`BadgeRevealOverlay` 전부 기존 자산 그대로다.

**4. 타입**

`ActivityFeedRow`에 `created_at: string`을 추가하고 `event_at`이 **활동 시작 시각**이라는 주석을
달았다(피드 조회는 `select('*')`라 정합성 유지). Insert 타입에서는 선택 필드로 뺐다.
`[username]/page.tsx`의 레거시 합성 행(`makeFeedItem`)은 `created_at`을 `event_at`으로 채운다 —
실기록이 없는 화면용 행이고 이 값을 읽는 화면은 없다.

### 게이트 WARN 2 대응 (오케스트레이터, 머지 전)

**대기 오버레이에 탈출 수단이 없던 문제**를 고쳤다. `loading` 구간은 `pushTabBarHidden()`으로
탭바가 DOM에서 제거되고 `main.overflow='hidden'`으로 스크롤이 잠긴 상태라, 요청이 매달리면
사용자가 전체화면에 갇힌다.

- `fetch`에 `AbortSignal.timeout(8000)` — 상한을 보장한다. 넘기면 연출을 포기하고
  원래 화면으로 돌아간다(갇히지 않는 것이 우선)
- 대기 중 **Escape 탈출** — 8초를 기다리는 대신 즉시 빠져나올 수단도 둔다
- `phaseRef`로 "지금도 대기 중인가"를 확인 — Escape로 빠져나온 뒤 뒤늦게 응답이 와도
  화면이 다시 열리지 않는다 (state를 클로저로 읽으면 요청 시작 시점 값이 굳는다)

### 주요 의사결정 / 핵심 메모

- **`event_at`에 로컬 벽시계가 저장되는 문제는 이 티켓에서 고치지 않았다.** 티켓이 범위 판단을
  맡긴 항목이다. `badge-engine`의 `startDateLocal ?? startDate`를 뒤집는 것 자체는 한 줄이지만,
  `event_at`은 홈·프로필 피드의 **정렬 키이자 "획득 시각" 표시값**이라 회귀 범위가 UI 전반이다.
  이번 연출의 판정은 `created_at`으로 분리했으므로 **이 티켓의 목적에는 영향이 없다.**
  별도 티켓으로 남긴다 (실측: `badge_earned` 편차 최대 +159분, `item_dropped` 최대 +470분 —
  로컬 벽시계 오해석과 일치하는 방향).
- **`?strava=connected`를 읽는 화면이 없는 문제도 이번 범위에서 제외했다.** 연동 성공 자체는
  프로필 화면의 Strava 연동 상태 UI에 이미 반영되고, 배지를 받은 경우엔 이번 연출이 피드백을
  대신한다. "배지 0개 + 연동 성공" 케이스에 토스트를 새로 붙이는 것은 스펙에 없는 신규 노출
  문구가 필요해 별도 티켓으로 남긴다.
- **마이그레이션 SQL은 실행하지 않았다.** 프로덕션과 같은 Supabase(jam-prod)라 스키마 변경이
  즉시 프로덕션 영향이다. 실데이터 접근은 **GET 조회만** 했고 배지 발급·드랍 엔진 호출은 0건이다.
- **`SyncButton.tsx`는 건드리지 않았다** (008에서 완료돼 프로덕션에 나가 있는 경로).

### 잔여 이슈
- **마이그레이션 093 적용 전에는 이 기능이 동작하지 않는다.** 병합 순서: SQL 승인·실행 → 배포.
  적용 후 확인 쿼리는 SQL 파일 하단 주석 참조(`null_cnt = 0`, `recent_cnt = 0`).
- **최근 획득 배지 상당수가 소프트 삭제 상태다.** 실측에서 2026-08-20 이후 획득 이벤트 2건의
  배지가 둘 다 `deleted_at` 있음(2026-08-23 orphan 아이템배지 1,245건 소프트 삭제 여파).
  넓은 창에서도 50건 중 15건이 제외됐다. 배지를 받았는데 카드가 0장이면 연출이 뜨지 않는다 —
  의도된 동작이지만(삭제된 컨텐츠 미노출), 인벤토리에는 해당 아이템이 남아 있어 사용자 입장에서
  불일치로 보일 수 있다.
- `event_at` 로컬 벽시계 문제 / `?strava=connected` 미소비 — 위 의사결정 참조.
