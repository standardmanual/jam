# [Service] "POI" 표기 전수 제거 → "체크인" 통일 (DB enum 포함) + 체크인 피드 신규 구현

## 배경 / 문제 정의

**이 티켓은 2026-08-14에 예고됐으나 끝내 생성되지 않은 후속 전파 티켓이다.**

커밋 `2d01df14` "[UXWriting] 고정 용어 체계 전면 개정"에서 **"체크인(CHECK-IN)"이 공식 고정
용어로 확정**됐다 (`Specs/UX_WRITING_GUIDELINE.md:61`, 금칙어: 방문·체크·인증·매칭·확인).
그 커밋 메시지 마지막 줄에 "소스코드·기타 문서는 미적용 (별도 티켓 예정)"이라 명시돼 있고,
같은 개정의 다른 항목들은 후속 티켓으로 전파됐다:

- `20260816_001` 겟 → 획득 (CLOSED)
- `20260816_002` 인벤 → 인벤토리 (CLOSED)
- **체크인 → 티켓 없음** ← 이번 티켓이 그 누락분

### 현재 상태 — 같은 개념을 7가지로 부르고 있다

`Specs/UX_WRITING_GUIDELINE.md:51`의 "동일 개념을 화면마다 다른 단어로 섞어 쓰지 않는다"를
명백히 위반 중이다:

| 표기 | 노출 위치 |
|---|---|
| `장소` | 배지도감 탭 / 피드 상세 행 라벨 |
| `장소 배지` | 배지 탭 빈 상태 / 컬렉션 상세 섹션 제목 |
| `POI 배지` | 컬렉션 상세 섹션 힌트 |
| `POI 픽업`·`POI 드랍`·`POI 로드 실패` | 인벤토리 이력 / 지도 토스트 |
| `POI 체크인` | 미션 상세 달성 조건 |
| `장소 체크인` | 미션 유형 (dead key) |
| `체크인 배지` | 알림함 소식 #4 ← 유일하게 목표 상태 |

`ko.ts:576`은 **한 문장 안에 두 표기가 동시 노출**된다:
`'POI 배지는 해당 장소를 지나가면 자동으로 채워져요'`

### 획득 조건 설명도 6가지 버전이 돌아다닌다

같은 GPS 판정 로직을 "지나는" / "지나가는" / "경유하는" / "스쳐 지나가기만 해도" 등으로
제각각 설명한다. (ko.ts 217·233·268·576, `badges/[id]/page.tsx:547`)

### 절차상 선행 조건

가이드라인은 **행위(체크인)**만 규정하고 **사물(체크인 배지·탭명)**에 대한 고정 용어가 없다.
현재 `ko.ts:651`의 "체크인 배지"는 알림 PRD 작성 중 자연 발생한 **비공식 용어**다.
가이드 L73·L195가 "표에 없는 용어를 임의로 만들어 쓰지 않는다"를 명시하므로
**용어표 신규 행 추가가 코드 변경보다 먼저 이뤄져야 한다.**

### DB 관점 — 사전 검증 완료 (안전)

**의존 객체 조사 결과 — 변경을 막는 요소 없음:**
- 두 enum을 참조하는 뷰·함수·머티리얼라이즈드뷰·인덱스: **0건**
- enum 사용 컬럼: `badges.type`, `notifications.type` **뿐**. default expression 없음
- enum 값 `'poi'`를 참조하는 CHECK 제약: 없음 (`missions_mission_type_check`만 `'poi_visit'` 문자열 보유)

**실데이터 규모:**

| 대상 | 건수 | 처리 |
|---|---|---|
| `badges` type=poi | 1,800 | `ALTER TYPE ... RENAME VALUE` → **UPDATE 불필요** |

| `poi` 지점 테이블 | 2,374 | **변경 없음 (유지)** |

**SQL 파일은 작성만 하고 실행하지 않는다.** (`db` 유형 규칙 — 실행은 오케스트레이터가 승인 후)
`jam-web/supabase/migrations/0XX_*.sql`로 남길 것.

**✅ 표현 구조 — 체크인만 문장형으로 확정 (2026-08-26 사용자 결정)**

피드는 현재 6개 이벤트 타입 전부 **완성 문장이 아니라 짧은 라벨만 표시**하는 구조다
(`'배지 획득'`, `'아이템 획득'`, `'아이템 드랍'`, `'아이템 픽업'`, `'미션 참가/완료/취소'`).

이번에는 **체크인 항목만 문장형으로 표시**한다:
- 첫 체크인 → `'체크인 했어요'`
- 반복 체크인 → `'{n}번째 체크인 했어요'`

기존 5개 타입의 라벨은 **건드리지 않는다.** 한 피드 안에서 체크인만 문장이고 나머지는 라벨이라
모양이 섞이는 점은 사용자가 인지하고 선택한 결과다.

### 주요 의사결정

- **`feed_event_type` enum을 확장하지 않았다.** 이 티켓 초안은 "체크인은 피드에 기록되지 않는다"를
  전제로 enum 확장을 계획했으나, 티켓 작성 직후 머지된 **20260826_001(커밋 `943653b7`)이
  체크인 피드 기록을 `badge_earned` + metadata(`poi_name`·`visit_count`)로 이미 구현**했다.
  별도 enum 값을 새로 만들면 (a) 기존 피드 행을 재분류하는 데이터 마이그레이션이 필요하고
  (b) `FeedSection`의 필터 탭(전체/배지/아이템/미션) 어디에도 속하지 않는 이벤트가 생겨 피드에서
  사라진다. 사용자가 확정한 것은 **표시 문구**(체크인만 문장형)이므로 그 델타만 구현했다.
  회차 계산도 20260826_001이 `sync.ts`에서 이미 하고 있어 회차 컬럼을 추가하지 않았다.
- **어드민의 'POI' 표기는 배지 도메인만 바꾸고 지점 관리 화면은 유지했다.**
  경계 규칙 2(드랍/픽업 지점 정보는 `poi` 유지)에 따라 `POI 관리` 메뉴·`admin/poi/*`·`POI 블록`·
  `POI 카테고리`·시뮬레이터의 `POI 매칭`은 운영자용 지점 식별자로 그대로 뒀다.
  `PoiForm.tsx:118 '네이버 장소 검색으로 채우기'`도 네이버 지도의 고유 기능명이라 유지.
- **어드민 배지 타입 라벨을 `'활동'` → `'액티비티'`로 통일했다.** 라벨 맵 3곳은 `'활동'`,
  필터바는 `'액티비티'`로 갈라져 있었고 공용 상수로 합치려면 하나를 골라야 했다.
  유저 화면(`ko.ts badges.tabActivity`)이 쓰는 `'액티비티'`를 정본으로 삼았다.
- **피드 문장에서 지점명을 뺐다.** 확정 문구가 `'체크인 했어요'`/`'{n}번째 체크인 했어요'`라
  20260826_001의 `'{poiName}을(를) N번째 방문했어요'`에서 지점명이 빠진다. 카드 제목이 이미
  배지명(=지점명)이고, 상세 시트에 `체크인 지점` 행을 새로 넣어 보완했다.
- **`notifications.group_key`의 `'poi_badge_earned:<id>'` 문자열은 치환하지 않았다.**
  묶음 병합 키일 뿐 렌더에 쓰이지 않고, 과거 소식을 다시 병합할 일이 없다. 건드리면 UNIQUE 충돌
  위험만 커진다(마이그레이션 SQL 주석에 명시).

사용자 결정(2026-08-26): **SQL 실행 → 즉시 main 승격**. 프로덕션 장애를 Vercel 빌드 시간
(실측 1분)으로 제한하고, 검증은 배포 완료 후 프로덕션에서 수행했다.

실제 순서: staging push(c5d27a90) → 103 SQL 실행 → seed SQL 실행 → DB 검증 →

### ⚠️ 배포 순서 (반드시 지킬 것)

**DB DDL과 코드 배포는 원자적이어야 한다. DDL 먼저 → 곧바로 코드 배포.**
- DDL만 적용하고 구 코드가 살아 있으면: `'poi'`/`'poi_badge_earned'`/`'poi_visit'` 리터럴이
  전부 무효값이 되어 22P02, `user_poi_badge_earns` 접근은 42P01 → HTTP 404.
- 코드만 배포하고 DDL이 없으면: 같은 오류가 방향만 반대로 발생.
- 실행 순서: ① `103_rename_poi_badge_to_checkin.sql` → ② `seed_checkin_copy_20260826.sql`
  → ③ 코드 배포 승격 → ④ `npm run db:types`로 `src/types/database.generated.ts` 재생성.

   (전체/배지/아이템/미션) 어디에도 안 걸려 피드에서 사라진다. 사용자가 확정한 것은 **표시
   문구**이므로 그 델타만 구현한 것이 맞다. → **티켓 본문의 enum 확장 지시는 무효 처리한다.**
