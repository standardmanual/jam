## 상세 요구사항

### 1. shadcn 전용 폴더 분리

`src/components/ui/`는 지금 MODULAR 래퍼(`Button.tsx`, `TopNav.tsx`, `Footer.tsx`,
`TabBar.tsx`, `Toast.tsx`, `SlidingTabs.tsx`, `BadgeGridCard.tsx`, `CollectionGridCard.tsx`,
`ListRowCard.tsx`, `LoadingSpinner.tsx`, `NotificationBell.tsx`, `PopInNumber.tsx`,
`SwapText.tsx`, `icons.tsx`, `dotm-hex-8.tsx`, `dotm-square-3.tsx`, `wandering-eyes.css`)와
shadcn 프리미티브(`accordion.tsx`, `alert-dialog.tsx`, `alert.tsx`, `checkbox.tsx`,
`dialog.tsx`, `input.tsx`, `select.tsx`, `sheet.tsx`, `switch.tsx`, `table.tsx`, `tabs.tsx`,
`textarea.tsx`, `shadcn-badge.tsx`, `shadcn-button.tsx`, `shadcn-card.tsx`)가 한 폴더에
섞여 있다. `shadcn-*` 접두어는 이름 충돌(진짜 `Button.tsx`/`Card.tsx`가 MODULAR 걸로 이미
있어서) 회피 흔적이다.

- shadcn 프리미티브 전용 폴더 신설(예: `src/components/admin/ui/` — 정확한 경로는 재량,
  MODULAR와 절대 겹치지 않는 이름으로).
- `components.json`의 `aliases.ui`를 새 경로로 변경.
- 기존 shadcn 프리미티브 12개 파일 이전 + 어드민 전역 import 경로 갱신.
- `shadcn-button.tsx`/`shadcn-badge.tsx`/`shadcn-card.tsx`는 새 폴더로 옮기며 접두어 없는
  정식 이름(`button.tsx`/`badge.tsx`/`card.tsx`)으로 복원 가능(새 폴더에선 충돌 없음).
- MODULAR 래퍼 파일들은 `src/components/ui/`에 그대로 둔다 — 이번 티켓 대상 아님.

### 2. 프리셋 테마 적용 (공식 shadcn CLI 사용, 하드코딩 절대 금지)

```bash
npx shadcn@latest apply b5Jgcv00m --only theme,font
```

- 프리셋: `style: maia`, `baseColor: stone`, `theme: stone`, `chartColor: sky`,
  `radius: medium` (`npx shadcn@latest preset decode b5Jgcv00m`로 재확인 가능)
- 위 1번에서 `tailwind.css` 경로를 이전했다면, CLI가 그 새 경로에 쓰도록
  `components.json` 갱신이 먼저 돼 있어야 한다.
- **실측 확인(2026-08-26)**: `globals.css`에 shadcn 표준 변수가 지금 전혀 없어서, 서비스
  본체(MODULAR, 완전히 다른 변수 이름 체계)와 충돌 위험이 없다. 별도 CSS 파일 분리는
  불필요 — 단일 `tailwindCssFile`에 직접 적용하는 공식 방식을 따른다.
- 적용 후 어드민 화면에서 `bg-primary`/`text-foreground` 등 시맨틱 클래스가 실제로
  이 프리셋 색상으로 렌더링되는지 반드시 눈으로 확인할 것(2026-08-05 실패의 재발 방지 —
  "설정은 됐지만 실제로 안 먹힘" 상태를 남기지 않는다).

### 3. 폰트 — Pretendard로 교체

- `src/app/admin/layout.tsx`가 지금 `next/font/google`로 Inter를 로드 중
  (`--font-admin-inter` 변수, 주석: "Cal Sans는 공개 웹폰트가 아니라...Inter 600 대체").
  이 로드를 제거한다.
- Pretendard는 `globals.css` 최상단에 이미 CDN import(`@import url('https://cdn.jsdelivr.net/
  gh/orioncactus/pretendard@v1.3.9/dist/web/static/pretendard.css')`)로 전역 로드돼 있다
  (서비스 본체·어드민 공용). 추가 설치 없이 `font-family: 'Pretendard', ...` 참조만 어드민
  레이아웃에 반영하면 된다.
- shadcn `apply --only font`가 프리셋 기본값(`inter`)을 CSS 변수로 써넣을 수 있는데, 그
  변수 값을 Pretendard로 덮어쓸 것(프리셋 폰트 값보다 이 요구사항이 우선).

### 4. 아이콘 — lucide → tabler

## 게이트 리뷰 WARN 후속 (2026-08-26, 사용자 승인 — 같은 브랜치에서 이어서 수정)

1차 구현(`claude/jamwork-20260826_012-admin-shadcn-foundation`, 커밋 `d2b594a1`)의
게이트 리뷰가 **WARN**을 받았다. `npx shadcn@latest apply b5Jgcv00m --only theme`가
기존 `:root { --background: var(--color-bg); --foreground: var(--color-text); }`
오버라이드 블록(서비스 DS v2가 `--background`/`--foreground`를 자기 토큰에 매핑하던 것)을
**삭제**하고, 그 자리를 shadcn 프리셋의 `--background: oklch(1 0 0)`(흰색) 등으로 전역
`:root`에서 대체했다. 지금은 서비스 코드가 `bg-background`/`text-foreground` 클래스를
전혀 안 써서(전부 `bg-surface`/`text-text` 등 DS v2 전용 클래스 사용) 시각적 회귀가 없지만,
**변수 이름 자체는 실재로 충돌**한다 — 향후 서비스 코드가 이 흔한 shadcn 관용구를 실수로
쓰면 조용히 흰 배경으로 샌다. `@custom-variant dark (&:is(.dark *))` 전역 재정의도 같은
CLI가 심었는데, 이건 서비스 코드가 `dark:` variant를 전혀 안 써서(실측 확인) 현재 위험 없음
— 이번 후속 수정 대상 아님.

**요구사항**: shadcn 테마 변수 블록(`@theme inline`의 `--background`부터 `--sidebar-ring`까지
전체 + `.dark` 블록)을 전역 `:root`/`.dark`가 아니라 **어드민 루트에만 걸리는 스코프 셀렉터**
(예: `[data-admin-theme]`, `admin/layout.tsx`의 최상위 wrapper div에 부여)로 감싼다.
`AdminBodyThemeFix.tsx`가 이미 admin 전용으로 html/body 배경을 인라인 오버라이드하는
선례가 있으니 같은 격리 패턴을 참고할 것. 스코프 후에도 어드민 화면의 `bg-primary` 등
shadcn 시맨틱 클래스가 정확히 같은 색상으로 렌더링되는지(1차 구현 때 확인한 색상값과 동일)
재검증할 것 — Tailwind v4 `@theme inline`이 스코프 셀렉터 안에서도 유틸리티 클래스를
정상 생성하는지가 핵심 리스크이므로, 먼저 작은 컴포넌트 하나로 검증 후 전체 반영 권장.

**주의**: 새 브랜치를 만들지 말고 기존 `claude/jamwork-20260826_012-admin-shadcn-foundation`

### 주요 의사결정 / 핵심 메모

- **`--background`/`--foreground` 이름 충돌을 스코프 셀렉터로 해결**했다 — 별도 CSS 파일
  분리(초기에 검토했다가 기각)가 아니라, 같은 `globals.css` 안에서 `[data-admin-theme]`
  셀렉터로 값 선언만 스코프하는 방식. `@theme inline`의 유틸리티 매핑(`--color-primary:
  var(--primary)` 등, Tailwind가 `bg-primary` 클래스를 생성하는 데 필요)은 전역에 유지하되,
  **실값**만 스코프했다 — 매핑 자체는 참조라 누출 위험이 없기 때문.
- **DS v2의 옛 `--background: var(--color-bg)` 매핑은 복원하지 않았다.** 코드베이스 전체에서
  이 bare 변수를 참조하는 곳이 0건이라 현재는 무해(스코프 밖에서 실수로 `bg-background`를
  쓰면 흰 배경 대신 투명/상속색으로 떨어지는 무해한 실패 모드). 필요해지면 별도 티켓.
- **`npx shadcn apply --only theme,font` 조합이 공식 레지스트리 404로 실패**하는 현상을
  발견(`font-inter.json` 리소스 부재, 프로젝트 설정 문제 아님). `--only theme`만 분리
  실행하고 폰트는 티켓 지시대로 수동으로 Pretendard 반영 — 결과는 티켓 의도와 동일.
- **아이콘 교체 범위가 티켓 명시(3개 파일)보다 넓었다.** 이전된 shadcn 프리미티브 5개
  (`accordion`/`checkbox`/`dialog`/`select`/`sheet`)도 내부적으로 lucide 아이콘을 썼음을
  발견해 함께 교체(순수 심볼 교체, 로직 변경 없음) — PHASES.md의 "lucide-react 잔존 0건"
  완료 기준을 문자 그대로 충족시키기 위함.
