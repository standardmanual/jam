# [bug] 아이템북(컬렉션) 비활성화 시 소속 배지의 미픽업 드랍이 즉시 무효화되지 않음

## 배경 / 문제 정의

티켓 [20260826_016](20260826_016_Service_소프트삭제배지-드랍-잔존-알림404.md)에서 "배지를
소프트 삭제해도 그 배지를 가리키는 미픽업 `poi_drops`가 무효화되지 않는" 버그를 고쳤다.
수정 지점은 [api/admin/badges/[id]/route.ts](../../../../jam-web/src/app/api/admin/badges/[id]/route.ts)의
`DELETE`·`PATCH(active:false)` 핸들러 — `badges.deleted_at`을 세팅한 직후
`invalidateUnclaimedDrops()` 헬퍼로 해당 `badge_id`의 미픽업(`picked_up_at IS NULL`)
`poi_drops`를 `is_available=false`로 즉시 무효화한다.

같은 티켓의 개선 리뷰(progressive-reviewer)가 동일한 버그 패턴이 남아있는 지점을 하나 더
발견해 20260826_016의 "잔여 이슈"로 범위 밖 분리했다(이 티켓이 그 후속):

[lib/admin/itembook-deactivation.ts](../../../../jam-web/src/lib/admin/itembook-deactivation.ts)의
`cascadeDeactivateItemBookBadges()`는 컬렉션(item_book) 비활성화 시 소속 배지 전체를
`item_book_id` 기준 bulk `UPDATE`로 `badges.deleted_at`을 일괄 소프트 삭제하는데, 이 함수는
`invalidateUnclaimedDrops()`를 호출하지 않는다. 이 함수는
[api/admin/itembooks/[id]/route.ts](../../../../jam-web/src/app/api/admin/itembooks/[id]/route.ts)의
`PUT`/`PATCH`에서 호출된다.

item-type 배지도 `poi_drops`에 올라갈 수 있음이
[api/drops/route.ts](../../../../jam-web/src/app/api/drops/route.ts)의 `POST` 핸들러로
확인됐다 — 즉 컬렉션을 비활성화하면 그 소속 배지들을 가리키는 미픽업 드랍이 즉시
무효화되지 않고, 20260826_016에서 추가한 크론 안전망
([api/cron/poi-cleanup/route.ts](../../../../jam-web/src/app/api/cron/poi-cleanup/route.ts),
매일 00:00 UTC 실행)에만 의존하게 된다. 최종적으로는 정리되지만 최대 24시간의 지연 창이
생기고, 그 사이 픽업되면 20260826_016과 동일한 증상(드랍한 사람에게는 클릭 불가 알림,
주운 사람의 인벤토리 상세는 404)이 재현된다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **`invalidateUnclaimedDrops`를 배열 입력으로 확장하고 공유 위치로 이동**
   현재 `invalidateUnclaimedDrops(supabase, badgeId, caller)`는
   `api/admin/badges/[id]/route.ts` 안의 로컬 함수라 다른 라우트에서 import할 수 없다.
   `badge_id` 단일 값이 아니라 배열(`badgeIds: string[]`)을 받도록 시그니처를 확장하고
   (`.eq('badge_id', ...)` → `.in('badge_id', badgeIds)`), `badgeIds`가 빈 배열이면
   쿼리를 실행하지 않고 조기 리턴한다. import 가능한 공유 위치(예:
   `jam-web/src/lib/admin/poi-drops.ts` 신설, 또는 기존
   `lib/admin/itembook-deactivation.ts`처럼 `lib/admin/` 하위)로 옮기고,
   `api/admin/badges/[id]/route.ts`는 이 공유 함수를 `[badgeId]` 형태로 호출하도록 수정한다.

2. **`cascadeDeactivateItemBookBadges`에서 무효화된 badge_id 목록을 확보**
   현재 bulk `UPDATE`는 영향받은 행의 `id`를 반환하지 않는다(`.select()` 없음). `.select('id')`
   등으로 이번 호출에서 실제로 `deleted_at`이 새로 세팅된 배지 ID 목록을 받아온다(이미
   `deleted_at IS NOT NULL`이던 배지는 `.is('deleted_at', null)` 조건에 걸려 대상에서
   빠지므로 멱등성은 그대로 유지된다).

3. **위 목록으로 공유된 무효화 함수를 호출**
   `cascadeDeactivateItemBookBadges`가 배지 소프트 삭제에 성공한 직후, 확보한 badge_id
   목록으로 1번에서 만든 공유 함수를 호출해 해당 배지들을 가리키는 미픽업(`picked_up_at
   IS NULL`) `poi_drops`를 `is_available=false`로 무효화한다. 무효화 실패는 20260826_016과
   동일하게 요청 자체를 실패시키지 않고 로그만 남긴다(크론 안전망이 다음 주기에 정리).

4. **회귀 방지**
   - `api/admin/badges/[id]/route.ts`의 기존 `DELETE`/`PATCH` 동작(단일 배지 무효화)이
     시그니처 변경 후에도 동일하게 동작해야 한다.
   - 이미 픽업된 드랍(`picked_up_at IS NOT NULL`)은 여전히 건드리지 않는다.
   - 컬렉션 비활성화 대상 배지가 0건이면(빈 컬렉션이거나 이미 전부 삭제된 상태) 드랍 무효화
     쿼리 자체를 스킵한다(빈 배열로 `.in()` 호출 시 전체 매치되는 사고 방지).
   - `PUT`/`PATCH` 양쪽 호출부 모두에서 동일하게 반영되는지 확인한다(20260823_006에서
     `cascadeDeactivateItemBookBadges`를 두 핸들러가 공유하도록 만든 이력 참고).

### UI/UX 관점

### 구현 내용 요약
1. **`invalidateUnclaimedDrops`를 배열 입력으로 확장 + 공유 위치로 이동** —
   `jam-web/src/lib/admin/poi-drops.ts`를 신설하고, 기존
   `api/admin/badges/[id]/route.ts`의 로컬 함수를 이곳으로 옮기면서 시그니처를
   `(supabase, badgeId: string, caller)` → `(supabase, badgeIds: string[], caller)`로
   확장했다(`.eq('badge_id', ...)` → `.in('badge_id', badgeIds)`). `badgeIds.length === 0`이면
   쿼리를 실행하지 않고 즉시 리턴한다. `api/admin/badges/[id]/route.ts`의 `DELETE`/`PATCH`는
   이 공유 함수를 `[id]` 단일 원소 배열로 호출하도록 수정 — 기존 단일 배지 무효화 동작은
   동일하게 유지된다.
2. **`cascadeDeactivateItemBookBadges`에서 무효화된 badge_id 목록 확보** —
   `jam-web/src/lib/admin/itembook-deactivation.ts`의 bulk `UPDATE`에 `.select('id')`를
   추가해, 이번 호출에서 `item_book_id` + `deleted_at IS NULL` 조건을 통과해 실제로
   새로 소프트 삭제된 배지 ID만 받아온다(이미 삭제돼 있던 배지는 `.is('deleted_at', null)`
   조건에서 걸러지므로 재확인 대상에서 자연히 빠짐 — 함수의 멱등성 그대로 유지).
3. **확보한 목록으로 공유 무효화 함수 호출** — 배지 소프트 삭제(bulk UPDATE)가 성공한
   직후, 확보한 badge_id 배열로 `invalidateUnclaimedDrops`를 호출해 해당 배지들을
   가리키는 미픽업(`picked_up_at IS NULL`) `poi_drops`를 `is_available=false`로 즉시
   무효화한다. 무효화 자체가 실패해도 컬렉션 비활성화 요청은 실패시키지 않고
   `console.error`로 로그만 남긴다(20260826_016과 동일 원칙 — 크론 안전망이 다음
   주기에 정리).
4. **회귀 방지** — `api/admin/itembooks/[id]/route.ts`의 `PUT`/`PATCH` 두 핸들러 모두
   여전히 `cascadeDeactivateItemBookBadges` 하나만 호출하므로(20260823_006부터의 공유
   구조 유지) 별도 수정 없이 양쪽에 동일하게 반영된다. 빈 컬렉션이거나 소속 배지가 이미
   전부 삭제된 상태면 `.select('id')` 결과가 빈 배열이 되어 `invalidateUnclaimedDrops`가
   조기 리턴 — `.in()`에 빈 배열을 넘겨 전체 매치되는 사고를 방지한다.

### 주요 의사결정 / 핵심 메모
- `invalidateUnclaimedDrops`의 이동처는 티켓이 제시한 두 옵션(`lib/admin/poi-drops.ts` 신설
  vs 기존 `lib/admin/itembook-deactivation.ts`에 추가) 중 전자를 택했다 — 이 함수는 배지
  단건 삭제 경로와 컬렉션 연쇄 삭제 경로 양쪽이 대칭적으로 참조하는 유틸이라, 후자에
  두면 이름과 달리 "아이템북 비활성화" 전용 파일이 드랍 무효화라는 더 넓은 책임까지
  떠안게 되는 어색함이 있었다.
- `cascadeDeactivateItemBookBadges`가 무효화 실패를 삼키는 방식은 기존 배지 단건 삭제
  경로와 동일하게 맞췄다(요청 자체는 성공, 로그만 남김) — 컬렉션 비활성화는 이미 배지
  소프트 삭제가 끝난 뒤의 부수 효과이므로, 여기서 실패해도 이미 반환한 500(배지 회수
  실패) 처리 흐름과 별개로 두는 게 기존 설계와 일관적이라 판단.

    있음, `api/cron/poi-cleanup`의 성공 로그 스타일과 대칭 맞추면 운영 진단에 도움)

  - 실제 DB 접속 테스트는 이 워크트리 환경 제약으로 미수행 — staging 배포 후 컬렉션
