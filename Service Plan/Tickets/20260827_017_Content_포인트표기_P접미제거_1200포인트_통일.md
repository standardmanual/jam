# [Content] 유저 노출 포인트 표기 「1200P」 잔여 전수 정리 → 「1,200 포인트」 통일

## 배경 / 문제 정의

티켓 20260827_014(알림 소식 전면 개편)에서 UX 라이팅 가이드 §1-3 화폐 용어를
**「포인트」로 고정**하고, 유저 노출 문구에 「JAM」을 붙이지 않도록 확정했다.
§3 표기 규칙도 함께 갱신됐다:

```
| 포인트 / 금액 | 읽기 쉬운 단위와 '포인트'·'원' 사용
| Good: 1,200 포인트 / 1만 원
| Bad:  1200P / 1,200 JAM 포인트 / ₩10,000
```

014는 **알림(소식) 계열 문구만** 정리했다. 알림 밖의 유저 노출 화면에는
「{n}P」 표기와 천단위 구분 누락이 그대로 남아 있다. 이번 티켓은 그 잔여분을
`copy` 유형 전수 점검으로 마무리한다.

**「JAM 포인트 시스템」은 내부 도메인명이므로 PRD·데이터모델·서버 코드 주석에서는 유지한다.**
이번 작업은 **유저 노출 문구에 한정**한다.

#### C. 하드코딩 「P」 — 포인트 화면 `jam-web/src/app/(main)/points/page.tsx`

i18n 규칙(모든 UI 텍스트는 딕셔너리 키로 참조) 위반이기도 하다. **키를 새로 추가해 처리한다.**

`ko.ts`의 `points` 네임스페이스에 추가:
```ts
/** 잔액 카드의 단위 — 숫자 팝인 애니메이션 대상에서 분리해 정적으로 렌더한다 */
unitSuffix: '포인트',
/** 잔액 카드 스크린리더 문구 */
balanceAria: '{amount} 포인트',
/** 내역 행 금액. amount는 부호(+/−)와 천단위 구분을 포함한 문자열 */
amountValue: '{amount} 포인트',
```

1. **22행 `formatAmount`** — `` `${sign}${Math.abs(n).toLocaleString('ko-KR')}P` `` →
   `t(d.points.amountValue, { amount: `${sign}${Math.abs(n).toLocaleString('ko-KR')}` })`
   (부호 `−`(U+2212)는 현행 유지)

2. **34행 `balanceText` / 84~91행 잔액 카드 — ⚠️ 애니메이션 회귀 주의**

   `balanceText`는 `useDigitPopIn`(`src/components/transitions-pages.ts:83`)에 그대로 들어간다.
   이 훅은 **문자열을 한 글자씩 쪼개 `t-digit` span을 만들고, 마지막 두 글자에
   `data-stagger="1"/"2"`를 붙여 늦게 등장시킨다.** 여기에 `' 포인트'`를 붙이면
   스태거가 마지막 자릿수가 아니라 「인」「트」에 걸리고, 한글까지 자릿수 팝인이 재생된다.

   **따라서 애니메이션 대상 문자열에는 단위를 넣지 않는다.** 처리 방식:
   - `useDigitPopIn`에 넘기는 값은 **숫자 부분만** 유지
     (`balance.toLocaleString('ko-KR')`)
   - 단위는 `t-digit-group` span **바깥에 정적 형제 span**으로 렌더한다
     (`aria-hidden="true"`, 숫자와 같은 글꼴 크기·굵기·색을 따르되 `t-digit` 클래스는 붙이지 않는다)
   - `<p>`의 `aria-label`은 `t(d.points.balanceAria, { amount: ... })`로 **전체 문구**를 읽어준다
   - `balance === null`일 때는 기존처럼 `—`만 나오고 단위 span은 렌더하지 않는다

   → 참고 구현: `ProfileClient.tsx:490~496`이 이미 "숫자 span + 단위 span" 구조다.

#### D. 천단위 구분 누락 — 가이드 §3 「1,200 포인트」 형식 위반 4건

문구는 「N 포인트」로 고쳤어도 호출부가 `toLocaleString` 없이 원시 숫자를 넘기면
「1200 포인트」가 되어 여전히 Good 예시에 못 미친다.

| 파일:줄 | 현재 | 변경 |
|---|---|---|
| `src/app/(main)/missions/[id]/MissionDetailClient.tsx:344` | `{ points: mission.reward_points }` | `{ points: mission.reward_points.toLocaleString('ko-KR') }` |
| `src/app/(main)/missions/MissionsListClient.tsx:75` | `{ points: m.reward_points }` | `{ points: m.reward_points.toLocaleString('ko-KR') }` |
| `src/app/(main)/FeedSection.tsx:250` | `{ points: String(meta.reward_points) }` | `{ points: Number(meta.reward_points).toLocaleString('ko-KR') }` |
| `src/app/(main)/FeedSection.tsx:291` | `{ points: String(meta.reward_points) }` | `{ points: Number(meta.reward_points).toLocaleString('ko-KR') }` |

- `FeedSection.tsx:253`(`pointsGained`)과 `badges/[id]/page.tsx:642~643`은 **이미 `toLocaleString` 처리돼 있다 — 건드리지 않는다.**
- `meta.reward_points`는 느슨한 타입이므로 `Number(...)`로 감싸 `toLocaleString`을 안전하게 부른다.
  (`meta.reward_points`가 truthy일 때만 진입하는 분기이므로 NaN 경로는 없다)
