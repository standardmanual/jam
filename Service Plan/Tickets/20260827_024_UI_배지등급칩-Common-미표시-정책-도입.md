# [UI] 배지 등급칩 — Common 미표시 정책 도입 및 MODULAR 전역 적용

## 배경 / 문제 정의
스토리북 MODULAR/Patterns/BadgeGridCard의 "그리드 레이아웃 (4×2)" 패턴을 다듬는 과정에서, common 등급
배지에 "COMMON" 칩을 표시하는 게 불필요하다는 판단이 나왔다(common은 "특별할 것 없는 기본 등급"이라
라벨링할 가치가 없음). 이어서 칩 크기가 전반적으로 커 보인다는 피드백으로 축소 작업이 붙었고, 실제
서비스에 이미 같은 시각 언어를 자체 복제해 구현해둔 곳들이 있어 정책이 부분 적용되는 문제가 확인됐다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `RarityBadge`(`@ds/components/cards/RarityBadge`, MODULAR 단일 진실 원천)가 `rarity==='common'`이면
  칩을 렌더링하지 않도록 변경
- 칩 크기를 기존 대비 70% 이하로 축소
- 위 두 가지를 실제 서비스 전역에 반영 — RarityBadge를 직접 import하는 화면은 자동 반영되지만,
  등급 pill을 자체 복제 구현해둔 곳은 별도로 찾아 공용 컴포넌트로 교체해야 함

### UI/UX 관점 (해당 시)
- 칩이 사라져도 그리드/리스트에서 형제 요소와 세로 정렬이 깨지지 않아야 함
- "완성" 태그처럼 등급 칩과 나란히 붙는 다른 칩은 같은 크기로 맞춤

### 컨텐츠 관점 (해당 시)
- 해당 없음

## 구현 계획
1. `RarityBadge.jsx`에 `rarity==='common'` 얼리 리턴 추가, 칩 크기를 패딩 6px/14px→4px/9px,
   폰트 12px→8px로 축소 (더 작은 타입스케일 토큰이 없어 칩 전용 리터럴 값 사용)
2. 실 서비스 전수 검사(`grep`)로 등급 pill을 자체 복제한 곳을 모두 찾아 `RarityBadge` import로 교체
3. 디자인 정책 문서(DESIGN_RENEWAL_SPEC.md)에 위 정책을 명문화해 향후 화면이 같은 실수를
   반복하지 않도록 함

## 완료 기록

### 구현 내용 요약
- **RarityBadge** (`jam-web/design-system/components/cards/RarityBadge.jsx`): `rarity==='common'`이면
  `null` 반환. 칩 크기 축소(패딩 4px/9px, 폰트 8px, letterSpacing 0.3px) — 원본 대비 약 65%
- **BadgeGridCard** (`jam-web/design-system/components/patterns/BadgeGridCard.jsx`, MODULAR
  카탈로그본): 등급 pill을 자체 복제(`RARITY_CONFIG`)해두고 있어 RarityBadge 수정이 반영되지
  않던 문제 발견 → 공용 RarityBadge import로 교체
- **CollectionGridCard** (`jam-web/design-system/components/patterns/CollectionGridCard.jsx`): 동일한
  이유로 공용 RarityBadge import로 교체. 옆에 붙는 "완성" 태그도 같은 크기 스케일로 맞춤
- **BadgeGridCard 스토리북**: 샘플 이미지를 jam_logo 플레이스홀더에서 실제 DB 배지 이미지
  (등급별, `public/badges/sample/`)로 교체
- **FeedSection** (`jam-web/src/app/(main)/FeedSection.tsx`, 알림 피드 상세시트·리스트행): 등급 pill을
  Tailwind 클래스로 직접 구현(`RARITY_COLOR`/`RARITY_LABEL`)해뒀던 두 곳을 공용 RarityBadge로 교체.
  common일 때는 wrapper까지 렌더링하지 않도록 해 상세시트의 불필요한 여백도 제거
- **정책 문서화**: `DESIGN_RENEWAL_SPEC.md`의 "Chip / Badge" 절에 COMMON 미표시 정책과 축소된
  치수를 명문화 — 새 화면은 반드시 RarityBadge를 재사용하고 직접 구현하지 말 것을 명시
- **정리**: `src/lib/rarity.ts`의 미사용 `RARITY_COLOR`, `src/lib/utils.ts`의 미사용
  `BADGE_RARITY_LABELS`/`BADGE_RARITY_COLORS`(전수 검사로 발견한 죽은 중복 코드) 삭제

### 주요 의사결정 / 핵심 메모
- **RarityBadge를 유일한 등급 칩 구현으로 강제**: BadgeGridCard(카탈로그본)·CollectionGridCard·
  FeedSection이 각자 등급 pill을 복제 구현해뒀던 게 이번 문제의 근본 원인. 세 곳 모두 공용
  컴포넌트 import로 교체해 앞으로의 정책 변경이 한 곳만 고치면 전역에 반영되도록 함
- **ShapeTag는 축소 대상에서 제외**: 배지 썸네일/틀 프레임용으로 `minHeight: 44px`(터치 타겟
  규칙)를 의도적으로 쓰고 있어, RarityBadge와 같이 축소하면 접근성 규칙을 깬다. 사용자 확인 후
  제외 결정
- **어드민 화면은 정책 대상 제외**: `BadgesTable.tsx` 등 어드민의 등급 표시는 데이터 그리드/필터
  옵션이라 기능적으로 "Common" 텍스트가 필요하고, CLAUDE.md상 어드민은 애초에 MODULAR 적용
  대상이 아님
- **칩 크기 축소값**: 사용자가 지정한 "70% 이하" 기준으로 패딩 6px/14px→4px/9px, 폰트
  12px→8px 적용 (원본 대비 약 65%). 더 작은 타입스케일 토큰이 없어 `--text-caption` 대신
  칩 전용 리터럴 px 값 사용
