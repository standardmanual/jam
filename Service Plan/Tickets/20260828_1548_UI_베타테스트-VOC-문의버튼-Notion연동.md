# [UI] 베타테스트 VOC 문의 버튼 + Notion 임베드 페이지

## 배경 / 문제 정의

서비스 베타테스트 기간 동안 유저 피드백(VOC)을 받을 임시 채널이 필요하다. 별도 백엔드 없이
기존 Notion 공유 페이지를 창구로 쓰고, TopNav에서 바로 접근할 수 있게 한다. **임시(베타테스트
전용) 기능** — 정식 VOC 시스템이 생기면 제거될 수 있음을 전제로 최소 구현한다.

## 확정 스펙 (사용자 확인 완료)

- TopNav 로고 이미지 **바로 옆(오른쪽)**에 작은 '문의' 버튼을 추가한다. 로고가 노출되는
  화면(탭 최상위: 홈/배지/미션/인벤토리, `logo` prop 사용처)에만 자연히 노출된다 —
  로고가 없는 서브페이지(뒤로가기 화면)는 대상 아님.
- 버튼 클릭 시 내부 라우트 `/voc`로 이동한다.
- `/voc` 페이지는 TopNav(뒤로가기, title="문의")를 유지한 채 하단 전체 영역에 Notion 페이지를
  **iframe으로 임베드**한다.
- iframe src는 Notion 공식 임베드 전용 경로를 쓴다:
  `https://sordid-dragonfly-b31.notion.site/ebd//3caaf2fe364580afb650e2529c39a2ae`
  (일반 공유 링크 `https://sordid-dragonfly-b31.notion.site/3caaf2fe...?source=copy_link`는
  `X-Frame-Options: SAMEORIGIN` + `frame-ancestors 'self' app.notion.com ...`로 임베드가
  차단된다 — 오케스트레이터가 `curl -I`로 직접 확인함. `/ebd/` 경로는
  `frame-ancestors https: http:`로 모든 오리진의 임베드를 허용하므로 이것만 동작한다.
  다른 경로로 대체하지 말 것.)
- 이 구조 덕분에 "다른 도메인의 페이지로 이동해도 TopNav가 고정" 요구사항이 자동 충족된다 —
  iframe 내부에서 어떤 페이지 전환이 일어나도 부모 문서(JAM! 앱)의 TopNav는 영향받지 않는다.

## UI 탐색·재사용 판정 *(1.5단계, 오케스트레이터 판정)*

- **문의 버튼**: `_ds_manifest.json` 기준 DS `Button`(`design-system/components/buttons/
  Button.jsx`) 재사용. "작게"라는 요구사항에 맞춰 `size="xs"`(기존 `SyncButton`/미연동
  동기화 버튼과 동일 톤) 또는 `variant="ghost"` 조합 중 시각적으로 로고와 어울리는 쪽 선택.
  신규 컴포넌트 불필요.
- **아이콘**: `src/components/ui/icons.tsx`에 말풍선/문의류 아이콘 없음(확인 완료 — 26종
  중 근접한 건 `InfoIcon`뿐). 신규 아이콘을 추가할 정도로 무게 있는 기능이 아니므로
  **텍스트 라벨 "문의"만 쓰는 텍스트 버튼**으로 최소 구현(아이콘 신규 제작 불필요).
- **레이아웃 확장 불필요**: DS `TopNav.jsx`의 `logoSlot`은 이미 임의 ReactNode를 받는
  자유 슬롯이고 내부가 `gap:4`의 flex 컨테이너다. 서비스 `TopNav.tsx`(`logoSlot`
  생성부, `logo=true`일 때)에서 로고 `<Image>`와 문의 버튼을 Fragment로 함께 반환하면
  "로고 뒤에 작게" 배치가 그대로 된다 — DS prop 신규 추가 불필요.
- **iframe**: DS/서비스 어디에도 대응 컴포넌트 없음(당연히 신규 UI 요소 아님) — `/voc`
  페이지에 순수 `<iframe>` 엘리먼트로 최소 구현.

  `(main)` 레이아웃 그룹 안에 둬 기존 TopNavDataProvider·인증 컨텍스트를 그대로 상속.
- 별도 API 라우트·DB 변경 없음.

### UI/UX 관점
- 문의 버튼 터치 영역이 로고 옆에서 과하게 커지지 않도록 주의(로고 높이 26px 기준 시각
  균형) — 다만 클릭 가능 영역 자체는 접근성 기준(가능하면 최소 32px 높이) 확보.
- iframe 로딩 중 빈 화면 방지를 위한 최소한의 로딩 처리(스피너 등)는 선택 사항 — 과도한
  구현 지양, 필요 시 최소한으로만.
- `/voc` 페이지는 임시 기능이므로 TabBar 등 다른 진입점에 별도로 노출하지 않는다
  (TopNav 문의 버튼이 유일한 진입점).

### 후속 수정 *(경미, 2026-08-28)*
인터랙션 리뷰가 지적한 "다크 앱 크롬 → 밝은 Notion 페이지 명도 급변"을 사용자가 직접
확인 후 요청.

1차 시도: `voc/page.tsx`의 최상위 wrapper(TopNav 포함)에서 `--color-bg`/`--color-surface`/
`--color-text` 등 CSS 변수를 라이트 값으로 재정의 — TopNav까지 흰 배경/검정 텍스트로
바뀜. 사용자가 "TopNav·TabBar는 그대로 두고 페이지(콘텐츠 영역)만"이라고 정정해
되돌렸다.

2차(확정): CSS 변수 재정의는 제거하고 `<iframe>` 엘리먼트 자체에만
`style={{ background: '#ffffff' }}`를 지정. TopNav는 기존 `bg-surface text-text`
그대로 유지(변경 없음). 로컬 dev 서버에서 `/voc` 재확인 — TopNav 다크 유지, iframe
로드 전/여백은 흰색으로 표시됨을 확인.

**한계(사용자에게 보고 완료)**: iframe 안 Notion 페이지 콘텐츠 자체는 다른 도메인
(notion.site)이라 브라우저의 cross-origin 정책상 우리 CSS가 그 안에 침투할 수 없다.
브라우저 `prefers-color-scheme: light`로 강제해도 Notion 콘텐츠는 여전히 다크로
렌더링됨을 실측 확인 — 이는 우리 앱의 다크모드를 따라간 게 아니라 **Notion 페이지
자체가 다크 테마로 명시적으로 고정 설정**돼 있기 때문. 콘텐츠 내부를 흰색으로 보이게
하려면 Notion 페이지 소유자가 Notion 쪽에서 페이지 테마를 Light로 바꿔야 한다(코드로
해결 불가, 범위 밖).
