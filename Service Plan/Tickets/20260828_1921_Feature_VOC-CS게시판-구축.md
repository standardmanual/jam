# [Feature] VOC CS 게시판 구축 (Google Sheets 기반, Notion 임베드 대체)

## 배경 / 문제 정의

티켓 20260828_1548에서 베타테스트 임시 채널로 `/voc`를 Notion iframe 임베드로 만들었다
("정식 VOC 시스템이 생기면 제거 검토 대상"이라고 명시). 이제 정식 버전을 만든다: Tally →
Google Sheets 연동을 데이터 소스로 삼아 문의/답변이 피드처럼 쌓이는 CS 게시판으로
`/voc` 페이지를 전면 재작성한다.

**Supabase는 사용하지 않는다** — 이 기능만 Google Sheets를 데이터 소스로 쓰고, 나머지
서비스는 기존처럼 Supabase를 그대로 쓴다. 두 데이터소스가 공존하는 구조다.

## UI 탐색·재사용 판정 *(1.5단계, 오케스트레이터 판정)*

- **문의 버튼(TopNav)**: 티켓 20260828_1548에서 이미 구현됨 — TopNav 로고 옆 DS `Button`
  재사용, `/voc`로 라우팅. **그대로 유지, 변경 불필요.**
- **페이지 상단 "문의하기" CTA(신규)**: `/voc` 페이지 콘텐츠 최상단에 별도로 필요
  (TopNav 버튼과는 별개). 서비스 `Button`(`src/components/ui/Button.tsx`) 재사용,
  외부 링크(`https://tally.so/r/BzWqY7`)로 이동 — **새 탭이 아니라 같은 탭에서 이동**
  (`<a href>` 또는 `window.location.href`로 구현, `target="_blank"` 금지).
- **TabBar**: `src/components/ui/TabBar.tsx` 재사용. 이전 티켓(20260828_1548)에서는
  "/voc는 임시 기능이라 TabBar 노출 안 함"으로 의도적으로 뺐는데, 이번엔 정식 페이지가
  되므로 **다른 (main) 페이지와 동일하게 TabBar를 노출**한다.
- **피드 카드**: `src/components/ui/ListRowCard.tsx` 재사용.
  `jam-web/src/app/(main)/FeedSection.tsx`의 `FeedCard`가 정확히 같은 패턴(아이콘+trailing+
  children 슬롯으로 카드 구성)이니 그 구조를 참고할 것. 신규 카드 컴포넌트를 만들지 말고
  `ListRowCard`의 children 영역에 상태/날짜/카테고리/내용/답변을 레이아웃.
- **정렬 토글("최신글 순" / "최신 답변 순")**: `src/components/ui/SlidingTabs.tsx` 재사용.
  `FeedSection.tsx`의 필터 탭(`FILTER_TABS`)과 동일한 패턴 — 신규 탭 컴포넌트 불필요.
- **상태/카테고리 칩**: DS `ShapeTag`는 "미도입 8종"(서비스에 대응 개념 없음, 티켓
  20260820_010에서 유지/보류 확정)이므로 신규 도입 대신, `FeedSection.tsx`의 `lastPiece`
  배지에 이미 쓰인 인라인 span 패턴(`inline-flex items-center gap-1 text-[length:var(--text-caption)]
  px-2 py-1 rounded-[var(--radius-tags)] bg-surface text-text`)을 그대로 따라 칩을 구성한다.
- **페이지네이션(신규)**: 서비스 레이어에 기존 번호형 페이지네이션 컴포넌트 없음
  (`FeedSection.tsx`는 "더보기" 버튼 방식이라 이번 요구사항인 페이지 번호 네비게이션과
  다름 — 어드민 `src/app/admin/poi/Pagination.tsx`는 어드민 전용이라 MODULAR 대상이 아니고
  서비스에서 재사용하지 않음). **서비스 전용 신규 컴포넌트로 최소 구현**
  (`src/app/(main)/voc/` 아래 또는 `src/components/ui/`) — MODULAR 승격은 다른 화면에서도
  필요해질 때 별도 판단.
- **JAM 로고 배지(답변자 표시)**: 기존 로고 에셋(TopNav에서 쓰는 것과 동일) 재사용, 신규
  아이콘/이미지 제작 불필요.

### 글(카드) 구성

레이아웃: **상태값, 날짜, 카테고리** (줄바꿈) → **상세 내용** (줄바꿈 두 번) → **답변**(있을 때만)

- **번호**: 자동 넘버링. 제출 순서 오름차순(가장 오래된 글=1번, 최신 글=가장 큰 번호) —
  Submission ID 순서 또는 Submitted at 오름차순으로 서버에서 계산해 부여. 피드 자체는
  최신순 정렬이라 화면 맨 위에 가장 큰 번호가 온다.
- **상태값**: 시트 J열 값 그대로 노출(문의중/확인중/답변완료). UX Writing 가이드 톤 확인.
- **카테고리(E열)**: 다중값, 칩으로 표시.
- **심각도(G열, 0~5)**: 노출함. 표현 형식(숫자 배지 등)은 구현 재량.
- **답변**: **상태 = 답변완료일 때만** 답변 칩 노출. 답변자 실명 표시 안 함 — 고정된
  "JAM" 로고/배지로만 답변자를 표시.
- **작성자(질문자)**: 완전 익명, 이름/닉네임 어떤 형태로도 노출 안 함.

### 정렬 (토글로 전환)
