# [UI] 모듈러 승격 — Icon Catalog·MissionCard 신규 편입, error.tsx EmptyState 전환

## 배경 / 문제 정의

`jam-web/docs/storybook/08-component-candidates.md`(2026-08-16 작성)에서 서비스 전용 UI 중
MODULAR 편입 가치가 있다고 분류(C: 신규 컴포넌트 후보)해두고 "구현은 별도 티켓으로 진행한다"고
미뤄둔 항목들 중 3건을 이번 티켓에서 실제로 편입한다. 사용자가 5개 후보 중 리스크가 낮은 3건만
선택했다(UserSearchBar의 Input `surface` prop 확장, PopInNumber/SwapText의 transitions.css 이관은
기존 MODULAR API 변경·다른 스토리 회귀 위험이 있어 이번 범위에서 제외).

### 사전 재검증 결과 (오케스트레이터, 1.5단계)

- `icons.tsx`(`src/components/ui/icons.tsx`, 299줄) — 여전히 서비스 전역에서 쓰이는 라인 아이콘
  세트. `currentColor` 고정, 토큰 준수. 재검증 결과 문서 판정(C) 그대로 유효.
- 미션 카드(`src/app/(main)/missions/MissionsListClient.tsx` 인라인) — 여전히 컴포넌트화 미완료,
  하드코딩 색상 존재. 문서 판정(C) 그대로 유효.
- Error/Forbidden 화면 — **문서 작성 이후 진행된 티켓 20260820_011(EmptyState 전면 전환,
  CLOSED)이 서비스 14개 파일 22곳을 이미 전환 완료했으나, `src/app/error.tsx`·
  `src/app/forbidden/page.tsx`는 그 목록에 없어 미전환 상태로 남아있었다.**
  단, `forbidden/page.tsx`는 함수명이 `AdminForbiddenPage`이고 실제로는 어드민 접근거부
  전용 화면이다 — 경로가 `/admin/` 하위가 아니어도 프로젝트 규칙("어드민은 MODULAR 적용 대상
  아님")에 따라 **이 티켓 범위에서 제외**한다. `src/app/error.tsx`(루트 에러 바운더리, 전체
  서비스 공통)만 전환 대상.
- 08-16 문서 작성 이후 신설된 `VocPagination.tsx`·`NotificationBell.tsx`는 재확인 결과 각각
  단일 화면에서만 쓰이고(재사용성 기준 미충족), 코드 주석에도 "재사용 필요해지면 그때 MODULAR
  승격 판단"이라고 명시돼 있어 이번 편입 대상에서 제외한다.

### 1.6 모듈러-서비스 연결 범위

- **Icon Catalog(신규)**: 이번 티켓에서 `design-system/components/icons/`에 신규 편입하는
  Storybook 전용 카탈로그다. 서비스 `src/components/ui/icons.tsx`를 대체하거나 서비스가
  이 경로를 import하도록 바꾸지 않는다 — 서비스는 계속 기존 `src/components/ui/icons.tsx`를
  쓴다(단일 소스 유지, 리스크 최소화). MODULAR 쪽은 문서화·카탈로그 목적의 사본이다.
- **MissionCard(신규)**: MODULAR 신규 컴포넌트로 추가만 하고, 이번 티켓에서 서비스
  `MissionsListClient.tsx`의 인라인 마크업을 이 컴포넌트로 교체하는 연결 작업까지는 포함하지
  않는다(서비스 쪽 교체는 하드코딩 색상 7개 제거·데이터 매핑 등 추가 검증이 필요해 별도 판단
  필요 — 컴포넌트 신설까지가 이번 범위).
- **EmptyState 전환**: 이미 "연결된 컴포넌트 9종"에 속해 서비스에 즉시 반영된다.
  `src/app/error.tsx` 1개 파일만 변경.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **Icon Catalog** — `design-system/components/icons/` 디렉토리 신설.
   `src/components/ui/icons.tsx`의 아이콘 세트를 MODULAR 컴포넌트 관례(`.jsx`)에 맞게 이식하고
   `IconCatalog.stories.tsx`로 전체 아이콘 그리드 카탈로그 Story 작성. `.d.ts` 동반.
2. **MissionCard** — `design-system/components/cards/MissionCard.jsx` 신설.
   `MissionsListClient.tsx` 인라인 마크업을 참고해 `Card` + `RarityBadge` + `Button` 조합으로
   구성하고, 인라인 하드코딩 색상 7개를 `tokens/`로 교체. `.d.ts`·`.stories.tsx` 동반.
3. **error.tsx EmptyState 전환** — `src/app/error.tsx`의 하드코딩 마크업(`bg-[#0A0A0A]`,
   `#e8461f` 등)을 `design-system/components/feedback/EmptyState.jsx`로 교체.
   `isEnvError` 분기(환경변수 안내 블록)는 EmptyState의 `description` 영역에 맞게 문구를
   재구성하거나, EmptyState 구조를 벗어나는 커스텀 블록이 꼭 필요하면 EmptyState 아래에
   보조 요소로 유지 — 임의로 정보 손실시키지 말 것. 재시도 버튼은 `action` prop으로 연결.

### UI/UX 관점

- 신규 문구는 `Specs/UX_WRITING_GUIDELINE.md` 기준(해요체·간결함) 준수.
- `error.tsx` 기존 문구("페이지 로드 오류" 등)는 최대한 재사용하되 EmptyState title/description
  2단 구조에 맞게 다듬는다.

### 주요 의사결정 / 핵심 메모

- Icon Catalog는 개별 아이콘 파일 26개로 쪼개지 않고 `IconCatalog.jsx` 한 파일에 전체 세트 +
  카탈로그 그리드 컴포넌트를 함께 담았다. 서비스 `icons.tsx`도 단일 파일 구조이고, `_ds_manifest.json`의
  컴포넌트 단위는 개별 아이콘이 아니라 "세트"이므로 `IconButton`의 `ICON_PATHS` 딕셔너리 패턴과
  일관된 선택이다.
- MissionCard는 `MissionsListClient.tsx`의 `NewBadge`/`JoinedBadge`(강조 칩) 같은 세부 변형을
  그대로 복제하지 않고 `statusLabel`(범용 문자열 prop)로 단순화했다 — 티켓이 "참고해 구성"이라고
  명시했고 "컴포넌트 신설까지"가 범위라 원본과의 1:1 마크업 동일성보다 Card/RarityBadge/Button
  조합 패턴 자체를 우선했다. 서비스 연결 시점에 필요하면 세부 변형(NewBadge 등)을 별도 prop으로
  추가하는 판단이 필요할 수 있다.
- error.tsx의 `isEnvError` 안내 블록(Vercel 환경변수 체크리스트)은 EmptyState 구조 밖에 그대로
  두었다 — 목록형 정보를 description 한 줄로 욱여넣으면 정보 손실이 생기기 때문(티켓 명시 지침).
