# [Admin] 아이템배지 발급 현황·이력 조회 화면

## 배경 / 문제 정의

[20260829_2101](20260829_2101_BadgeEngine_아이템배지-개체정체성-드랍픽업-일련번호유지.md)에서
아이템배지 개체(`InventoryItem`) 정체성 모델을 바로잡으면서, 어드민이 "서비스 전체에
발급된 아이템배지가 지금 어디에·누구에게 있는지, 최초 발급부터 어떻게 흘러왔는지"를
조회할 필요가 확인됐다. 잡스토리는 `admin/users` 조회 화면과 같은 성격의 **조회/상세
확인 + 전체 현황 감사·투명성 확보** — 어뷰징 이상거래 감지용 모니터링 대시보드는
스코프가 아님(2026-08-29 확인).

이 티켓은 그 조회 화면의 인터랙션 플로우를 다룬다. **개념 모델(`CustodyEvent` 이력
로그, `destroyed_at` 소프트 삭제, "재발급된 일련번호" 정의)은 20260829_2101에 이미
확정돼 있고, 이 화면은 그 위에서만 동작한다** — 해당 티켓의 스키마 작업이 선행돼야
한다.

### 기존 어드민 패턴 확인 (구현 전 재사용 판단)

- `admin/users`(목록) → `admin/users/[id]`(상세) : 목록에서 행 클릭으로 상세 이동,
  공용 `DataTable` 컴포넌트(정렬·컬럼 표시 토글, 읽기 전용) 사용
- `admin/users/[id]`에 이미 "배지 획득 히스토리"(`BadgeHistoryTable.tsx`)가 있으나 이건
  `user_activity_badges`(활동배지, 일련번호 없음) 대상이다 — 이번 화면(`inventory_items`,
  일련번호 있는 아이템배지)과는 **다른 테이블·다른 잡스토리**이므로 별개 화면으로 간다
- `admin/badges/[id]`(배지 도안 상세), `admin/poi/[id]`(POI 상세)가 이미 존재 — 교차
  링크 시 새로 만들지 않고 재사용

## 인터랙션 플로우 브레드보드

**잡스토리**: 관리자가 서비스 전체에 발급된 아이템배지의 현재 상태를 조회하거나,
특정 배지 하나를 골라 최초 발급부터 지금까지의 흐름을 확인한다.

```
아이템배지 발급 현황 (배지 검색)
- [키워드 검색: 배지 이름] → 같은 화면, 검색된 배지(도안) 목록
- 배지 목록에서 배지 클릭 → 배지별 발급 일련번호 목록 (해당 Badge)
- (검색 결과 없음) [ 조건에 맞는 배지 없음 안내 ]
[ 검색창, 검색된 배지 목록(이미지·이름·등급·총 발급 수량) ]

배지별 발급 일련번호 목록
- [뒤로] → 아이템배지 발급 현황(배지 검색)으로 복귀
- [필터: 현재 상태(Held/Dropped/AtPoi/Slotted/Consumed/Orphaned/Destroyed)]
  → 같은 화면, 필터링된 목록
- [필터: 재발급된 일련번호만 보기] → 같은 화면, 필터링된 목록
  (정상 재발급 / 동시존재 이상 두 경우를 뱃지로 구분 표시)
- [페이지네이션] → 같은 화면, 다음/이전 페이지
- 행(일련번호) 클릭 → 아이템배지 이력 상세 (해당 InventoryItem)
- (이 배지로 발급된 개체가 아직 없음) [ 빈 상태 안내 ]
- (필터 결과 없음) [ 조건에 맞는 결과 없음 안내 ]
[ 선택한 배지 이름·이미지(헤더), 일련번호·현재 상태·현재 위치/소유자·발급일시 테이블 ]

아이템배지 이력 상세
- [뒤로] → 배지별 발급 일련번호 목록으로 복귀
- 현재 소유자 이름 클릭 → 어드민 유저 상세 (/admin/users/[id], 기존 화면 재사용)
  ※ 현재 상태가 Orphaned면 소유자 없음 — 링크 대신 "고아(어드민 보관 중)" 표시,
    관리 기능은 별도 티켓([20260829_2150]) 참고
- 현재 위치 POI 이름 클릭 → 어드민 POI 상세 (/admin/poi/[id], 기존 화면 재사용)
- 배지(도안) 이름 클릭 → 어드민 배지 상세 (/admin/badges/[id], 기존 화면 재사용)
- (같은 번호를 가진 다른 개체 존재 = 재발급된 번호)
  - 이전 개체가 파괴된 상태 → [ 배너: 재발급된 번호, 이전 개체 상세로 이동 링크 ]
  - 이전 개체도 파괴 안 된 상태(둘 다 생존) → [ 경고 배너: 동일 번호 동시 존재 이상 ]
- (현재 상태가 Destroyed) [ 파괴 사유(만료/조합소모)·파괴 시각 표시 ]
[ 배지 이미지·이름·등급, 일련번호, 현재 상태, 현재 위치/소유자,
  이력 타임라인(CustodyEvent를 발급부터 현재까지 시간순 나열 —
  각 항목: 이벤트 종류·시각·관련 유저/POI. 유저 식별자는 스냅샷값이라 탈퇴한
  유저도 그대로 표시되며 익명화하지 않는다. 유저·POI 이름은 각각 상세로
  이동 가능) ]
```

### 엣지 케이스 / 실패 경로

- 목록·상세 조회 실패(서버 오류) → 기존 어드민 화면 관례 재사용(신규 문구 최소화)
- 이력이 `Minted` 하나뿐(발급 이후 아무 일도 없음) → 타임라인에 한 줄만 표시, 빈
  상태로 취급하지 않음
- 상세는 현재 상태가 `Destroyed`여도 조회 가능해야 함(소프트 삭제 결정 활용 — 이력이
  끊기지 않는다는 20260829_2101의 전제를 그대로 검증하는 화면)

### 열린 결정

1. ~~탈퇴/삭제된 유저·POI 참조 표시~~ — **확정(2026-08-29): 익명화하지 않는다.**
   `poi_drops`의 드랍한 사람 익명화 관례를 여기엔 적용하지 않음 — 탈퇴한 유저의
   식별자도 이력에 그대로 표시한다. 이건 `CustodyEvent`가 유저 식별자를 스냅샷
   값으로 저장하기 때문에 가능하다(20260829_2101의 "스냅샷 불변식" 참고) — 살아있는
   `users` row 조인에 의존했다면 탈퇴 후 빈 값이 됐을 것이다.
   > 이 결정을 확인하는 과정에서 **`inventory_items`가 계정 탈퇴 시 CASCADE로 하드
   > 삭제되는 문제**를 추가로 발견했다 — 상세는 20260829_2101 참고. 소유자만 비우고
   > 개체는 고아(`Orphaned`)로 보존하는 방향으로 확정했고, 그 후속 관리 기능은
   > [20260829_2150](20260829_2150_Admin_고아-아이템배지-관리-기능.md)으로 분리했다.
2. ~~목록 규모 대응~~ — **확정(2026-08-29): 배지 검색 우선 UX.** 전체를 한 목록으로
   훑지 않고, 먼저 배지(도안)를 키워드로 검색해 고른 뒤 그 배지로 발급된 일련번호만
   페이지네이션 목록으로 본다. 위 브레드보드에 반영함. 목록 컴포넌트는 다른 어드민
   화면과 동일하게 `admin/data-table`(shadcn 기반 공용 `DataTable`) 구조를 재사용한다
   — `BadgeHistoryTable.tsx`와 같은 패턴.
3. ~~라우트 위치~~ — **확정(2026-08-29): 별도 최상위 메뉴로 신설.** 기존
   `/admin/badges`(도안 관리) 하위 탭이 아니라 독립된 메뉴(`/admin/item-badges` 가칭)로
   만든다. `Badge`(도안)와 `InventoryItem`(개체)은 서로 다른 객체라는 개념모델 결정과
   일치한다.
