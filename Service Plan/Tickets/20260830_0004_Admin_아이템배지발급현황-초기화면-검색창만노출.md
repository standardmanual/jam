# [Admin] 아이템배지 발급 현황 — 첫 화면은 검색창만 노출 (미리 조회하지 않음)

## 배경 / 문제 정의

`/admin/item-badges`([page.tsx](../../jam-web/src/app/admin/item-badges/page.tsx))가 검색어
없이 처음 열려도 `badges` 테이블을 `type='item'` 조건으로 최대 100건 미리 조회해 목록을
바로 렌더링한다. 요청 사항: 첫 화면은 검색창만 보이고, 검색어를 입력하기 전에는 조회
자체가 일어나지 않아야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `q`가 비어있으면 `badges`/`inventory_items` 쿼리를 아예 실행하지 않는다.
- `q`가 비어있을 때 화면에는 검색창만 노출하고, 목록·"N종" 카운트 문구·빈 상태 안내는
  숨긴다.
- `q`가 있을 때의 기존 동작(검색 결과 목록, 빈 결과 안내)은 그대로 유지한다.

## 구현 계획
`ItemBadgesSearchPage`에서 쿼리 실행부와 하단 목록 렌더링을 `if (q)` 분기로 감싼다.
`ItemBadgeSearchBar.tsx`는 검색창 자체이므로 변경 불필요.

## 구현 기록 (2026-08-30)

- **변경 내용**: `page.tsx`의 `badges`/`inventory_items` 쿼리 실행부를 `if (q) { ... }` 블록으로
  감쌌다. `q`가 비어 있으면 `badges`/`totalCountByBadge`가 빈 상태로 유지돼 조회 자체가
  실행되지 않는다. 하단의 "N종" 카운트 문구·배지 목록·빈 상태 안내(`조건에 맞는 배지가
  없습니다`)도 `{q && (...)}`로 감싸 `q`가 없을 때는 검색창만 렌더링되도록 했다.
  `q`가 있을 때의 기존 UI·동작은 그대로 유지했다.
- **변경 파일**: `jam-web/src/app/admin/item-badges/page.tsx`
- **로컬 검증**: `cd jam-web && npm run lint` 전체 실행 — 에러 0건, 경고 26건(모두 이번 변경과
  무관한 기존 파일의 사전 존재 경고). 게이트 리뷰에서 별도 worktree로 `tsc --noEmit`·
  `npm run build`(프로덕션 빌드, `/admin/item-badges` 라우트 포함)도 통과 확인. 실제 화면
  육안 확인은 QA 테스트 계정에 어드민 권한이 없어 하지 못함(잔여 이슈 참고) — 정적 코드
  검토·타입체크·빌드로 PASS 판정.
- **DB 변경**: 없음.

`{q && (...)}`)라 정적 검토로 충분하다고 판단했다는 점을 그대로 남긴다.

### 잔여 이슈
- QA용 테스트 계정(`00000000-0000-0000-0000-000000000001`)이 `is_admin=false`라 어드민
  화면을 로컬/스테이징에서 dev-login으로 즉시 육안 확인할 수 없다. 반복되는 문제라 별도
  테스트 계정에 어드민 권한을 부여하는 방안을 고려할 만하다(이번 티켓 스코프 밖).
