# [Admin] "소유자 없음" 아이템배지 전체 목록 화면 + 라벨 변경

## 배경 / 문제 정의

[20260829_2150](20260829_2150_Admin_고아-아이템배지-관리-기능.md)에서 계정 탈퇴로 소유자를
잃은 아이템배지 개체(`Orphaned`)를 어드민이 영구 폐기·재배정할 수 있는 액션을 구현했다.
다만 그 액션에 접근하려면 지금은 **먼저 특정 배지(도안)를 검색·선택해야만** 해당 배지의
개체 목록(`SerialListTable`)에서 `Orphaned` 행을 찾을 수 있다 — 어떤 배지가 얼마나 소유자를
잃은 채 쌓여있는지 전체를 한눈에 보려면 배지 종류 수만큼 반복해서 들어가봐야 한다.

**요청**: 배지를 먼저 선택하지 않고도, 전체 배지에 걸쳐 소유자 없는 개체만 모아 바로 볼 수
있는 별도 목록 화면이 필요하다.

**추가 요청**: 사용자 노출 라벨 `고아`는 사람을 지칭하는 은유라 어드민 화면에 부적절하다 —
`소유자 없음`으로 전면 교체한다.

## 확정된 결정 (2026-08-30, 사용자 확인)

- **새 라벨**: `고아` → **`소유자 없음`**. 상태 코드명(`Orphaned`, DB/타입/RPC/CustodyEvent
  이벤트 타입 등 내부 식별자)은 선행 티켓에서 확정된 개념 모델 용어이므로 **그대로 유지**한다
  — 바꾸는 건 사용자 노출 문구뿐이다.
- **화면 위치**: 기존 `/admin/item-badges` 페이지에 탭을 추가하는 게 아니라 **별도 페이지로
  분리**한다 (`/admin/item-badges/orphaned` 등, 정확한 경로는 구현 시 기존 라우팅 관례에 맞춰
  결정). 사이드바(`src/components/admin/adminNavItems.ts`)의 "콘텐츠 관리" 그룹, 기존
  "아이템배지 발급 현황" 항목 바로 아래에 별도 메뉴 항목으로 노출한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **전체 조회 API 신규 필요**: 현재 `SerialListTable`이 쓰는 목록 조회는 특정 `badge_id`로
  스코프돼 있다(`/admin/item-badges/[badgeId]/page.tsx`). 배지 무관 전체 조회를 위한 신규
  API(또는 기존 API의 badge_id 옵셔널화)가 필요하다. "소유자 없음" 판정 조건은
  `admin_destroy_orphaned_item()`/`admin_reassign_orphaned_item()` RPC
  ([110_admin_orphaned_item_actions.sql](../../jam-web/supabase/migrations/110_admin_orphaned_item_actions.sql))가
  이미 쓰고 있는 것과 동일해야 한다: `inventory_id IS NULL` AND `destroyed_at IS NULL` AND
  해당 개체를 참조하는 활성(`is_available = TRUE`) `poi_drops`가 없음. `deriveItemBadgeStatus()`
  ([item-badge-status.ts](../../jam-web/src/lib/admin/item-badge-status.ts))의 애플리케이션
  레벨 판정 로직과 반드시 동일한 결과를 내야 한다 — 로직을 별도로 다시 구현하지 말고 재사용
  가능한 형태로 공유할 것.
- **대용량 대비**: 소유자 없는 개체가 배지 종류를 가리지 않고 누적될 수 있으므로, 전체 조회는
  페이지네이션(또는 `.range()` 순회)을 갖춰야 한다 — PostgREST 기본 1,000행 절단 위험
  ([DEV_PROCESS_GUARDRAILS.md](../Specs/DEV_PROCESS_GUARDRAILS.md) 패턴 3 참고).
- **목록에 배지 정보 포함**: 배지 무관 목록이므로 각 행에 어떤 배지(이름·이미지·등급)의
  개체인지 함께 표시해야 한다(기존 `SerialListTable`은 이미 특정 배지 안이라 이 정보가
  없었음).
- **관리 액션 재사용**: 영구 폐기(`DestroyOrphanedAction`)·재배정(`ReassignOrphanedAction`)
  컴포넌트는 이미 `items: {id, serialLabel}[]` 형태로 범용 설계돼 있으므로 그대로 재사용한다
  — 새 화면에서도 동일한 일괄 선택 + 액션 바 패턴을 적용한다(기존
  [SerialListTable.tsx](../../jam-web/src/app/admin/item-badges/[badgeId]/SerialListTable.tsx)의
  `enableRowSelection`/일괄 액션 바 구현 참고).

  라벨로 구성(예: "소유자 없음 배지 관리" 등, 정확한 문구는 UX Writing 가이드
