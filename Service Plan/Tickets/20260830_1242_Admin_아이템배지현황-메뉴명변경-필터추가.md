# [Admin] 아이템배지 현황 메뉴명 변경 및 검색 필터 추가

## 배경 / 문제 정의
1. `adminNavItems.ts`의 메뉴명이 실제 화면 성격을 정확히 드러내지 못한다.
   - "아이템배지 발급 현황" → 화면은 발급 이력뿐 아니라 배지별 현황 조회 전반을 다룬다.
     "아이템배지 현황"으로 축약해 명확히 한다.
   - "소유자 없음 아이템 배지" → 실제 화면 제목·URL 세그먼트(`orphaned`)와 맞춰
     "미소유 아이템배지 현황"으로 통일한다.
2. `/admin/item-badges`(아이템배지 현황) 페이지는 현재 배지 이름 검색만 지원한다
   (`ItemBadgeSearchBar.tsx`, 티켓 20260829_2139 "검색 우선 UX"). 배지 수가 많아지면
   세계관·컬렉션·등급으로 좁혀 찾을 수 있어야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/components/admin/adminNavItems.ts`
  - `/admin/item-badges` label: `'아이템배지 발급 현황'` → `'아이템배지 현황'`
  - `/admin/item-badges/orphaned` label: `'소유자 없음 아이템배지'` → `'미소유 아이템배지 현황'`
- `jam-web/src/app/admin/item-badges/page.tsx`
  - 페이지 제목(`<h1>`)도 메뉴명과 일치시킨다 (`아이템배지 발급 현황` → `아이템배지 현황`).
  - `searchParams`에서 `faction_id` · `item_book_id` · `rarity`를 읽어 배지 검색 쿼리에
    `.eq()` 조건으로 추가한다 (검색어 `q`와 AND 결합).
  - 세계관·컬렉션·등급 옵션 조회를 위해 `factions`(id, name)·`item_books`(id, name,
    faction_id) 목록을 서버에서 함께 조회해 필터 바에 내려준다
    (`admin/badges/page.tsx`의 기존 조회 패턴 참고).
- `jam-web/src/app/admin/item-badges/ItemBadgeSearchBar.tsx`
  - **재사용 판정(admin 유형이라 MODULAR 탐색 대상 아님, 서비스 전용 패턴 재사용)**:
    `admin/badges/BadgesFilterBar.tsx`가 이미 `DataTableFacetedFilter` +
    세계관/컬렉션/등급 필터를 구현해뒀다 — 동일 컴포넌트(`@/components/admin/data-table/
    data-table-faceted-filter`)와 URL 동기화 패턴을 그대로 재사용한다. 신규 필터 컴포넌트를
    새로 만들지 않는다.
  - 검색창(Input) **하단**에 세계관 · 컬렉션 · 등급 3개 `DataTableFacetedFilter`를 배치한다
    (`BadgesFilterBar.tsx`처럼 같은 줄이 아니라, 이 화면은 검색창 아래 별도 줄에 배치 —
    요청 원문 "검색창 하단에" 반영).
  - 세계관 선택 시 컬렉션 옵션을 해당 세계관 소속으로 좁힌다 (`BadgesFilterBar.tsx`의
    `filteredItemBooks` 로직과 동일).
  - 세계관 변경 시 이미 선택된 컬렉션이 새 세계관 소속이 아니면 초기화한다.
  - 필터 변경 시 `page` 파라미터가 있다면 제거한다(현재 이 화면엔 페이지네이션 없음 — 확인 후
    없으면 생략).
  - 필터가 하나라도 걸려 있으면 "필터 초기화" 버튼 노출.

### UI/UX 관점
- 등급 옵션은 `admin/badges/BadgesFilterBar.tsx`의 `RARITY_OPTIONS`
  (common/rare/legend/mythic) 그대로 사용한다 — 이 화면도 `badges.rarity`가 동일 enum이다.
- 필터를 아무것도 선택하지 않은 초기 상태는 기존과 동일하게 "검색어 없으면 결과 미노출"
  (티켓 20260830_0004 "초기화면 검색창만 노출" 정책 유지) — 필터만 걸고 검색어가 없는
  경우의 동작은 구현 시 정하되, 검색어 없이 필터만으로도 조회되게 하는 편이 필터 추가
  취지에 맞는다 (검색창 텍스트가 비어 있어도 `q`가 없을 뿐 필터 조건은 있을 수 있음 — 이
  경우 결과를 보여준다).

## 구현 계획
1. `adminNavItems.ts` 라벨 2건 변경 + 관련 스냅샷/테스트(`adminNavItems.test.ts`) 확인.
2. `page.tsx`에서 factions/item_books 조회 추가, 쿼리에 필터 조건 반영, `<h1>` 텍스트 변경.
3. `ItemBadgeSearchBar.tsx`에 3개 필터 UI 추가 (props로 factions/itemBooks 목록 전달받음 —
   또는 서버 컴포넌트에서 클라이언트 컴포넌트로 props 전달).
4. 로컬에서 `/admin/item-badges` 진입 → 필터 조합별 결과 확인.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. `adminNavItems.ts`의 메뉴명 2건 변경: `/admin/item-badges` → "아이템배지 현황",
   `/admin/item-badges/orphaned` → "미소유 아이템배지 현황".
2. `/admin/item-badges/page.tsx`
   - `<h1>`을 "아이템배지 현황"으로 일치.
   - `factions`(id,name)·`item_books`(id,name,faction_id) 목록을 서버에서 조회해
     `ItemBadgeSearchBar`에 props로 전달.
   - `searchParams`의 `faction_id`/`item_book_id`/`rarity`를 `badges` 쿼리에 `.eq()`로
     반영(검색어 `q`와 AND 결합).
   - "검색어 없으면 결과 미노출" 정책을 "검색어 또는 필터 중 하나라도 있으면 조회"로 확장
     (`hasFilter` 변수 도입). 필터만 걸렸을 때는 결과 카운트 문구를 `"쿼리" 검색 결과 N종`
     대신 `필터 결과 N종`으로 분기.
3. `ItemBadgeSearchBar.tsx`에 `admin/badges/BadgesFilterBar.tsx`와 동일한
   `DataTableFacetedFilter` 패턴으로 세계관·컬렉션·등급 필터 3개를 검색창 **아래 별도 줄**에
   추가. 세계관 선택 시 컬렉션 옵션을 해당 세계관 소속으로 좁히고, 세계관 변경 시 선택된
   컬렉션이 새 세계관 소속이 아니면 초기화. 필터가 하나라도 걸리면 "필터 초기화" 버튼 노출.
   페이지네이션이 없는 화면이라 `page` 파라미터 제거 로직은 불필요(확인 후 생략).
4. 부수 변경(범위 확장, 동일 리네임 취지): `[badgeId]/page.tsx`의 뒤로가기 링크 텍스트
   "← 아이템배지 발급 현황" → "← 아이템배지 현황"으로 동기화(같은 화면을 가리키는 라벨이라
   불일치 방지).

5. 게이트 리뷰 WARN 지적(orphaned 화면 `<h1>` 불일치) 확인 후 사용자 승인 하에
   `orphaned/page.tsx`의 `<h1>`도 "소유자 없음 아이템배지" → "미소유 아이템배지 현황"으로
   변경해 nav 라벨과 완전히 일치시켰다.
