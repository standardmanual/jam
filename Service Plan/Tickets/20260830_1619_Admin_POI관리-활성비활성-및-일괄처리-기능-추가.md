# [Admin] POI 관리 화면에 활성/비활성 상태 + 일괄 처리 기능 추가

## 배경 / 문제 정의
`/admin/poi`에는 POI를 등록·수정·삭제하는 기능만 있고, 임시로 노출을 끄는 "비활성화"
개념이 없다 — 지점을 없애려면 하드 삭제(`DELETE /api/admin/poi/[id]`)뿐이다. 다른 컨텐츠
엔티티(`item_books.is_active`)는 이미 활성/비활성 토글을 지원하므로 동일한 패턴을 POI에도
적용한다. 또한 POI 목록에는 다중 선택 UI(`PoiTable.tsx`)와 일괄 삭제(`DataTableBulkActionBar`)가
이미 있으나 일괄 활성화/비활성화 액션은 없다.

**범위 결정(오케스트레이터·사용자 확인, 2026-08-30)**: 이번 티켓은 **어드민 화면 전용**이다.
`is_active=false`인 POI라도 드랍·체크인·매칭 로직(`lib/poi/matcher.ts`, `api/drops`,
`api/checkin-badges`, `lib/ambient-drop/`, `lib/notifications/batch/dropSpot.ts`)은 **이번
티켓에서 건드리지 않는다** — 서비스 로직 연동은 후속 티켓
`20260830_1620_BadgeEngine_비활성POI-드랍체크인로직-제외.md`로 분리했다.

### 코드 조사 메모 (오케스트레이터 사전 조사, 구현자가 재확인할 것)
- **DB**: `poi` 테이블에 `is_active` 컬럼이 없다(`jam-web/src/types/database.ts` 301~311행
  `PoiRow`). `item_books.is_active boolean`과 동일한 패턴으로 마이그레이션을 추가한다.
  최신 마이그레이션은 `jam-web/supabase/migrations/113_badges_category.sql` — 다음 번호는
  `114_poi_is_active.sql`. 기존 ~1,800건은 전부 활성 취급해야 하므로
  `DEFAULT true NOT NULL`로 추가한다.
- **참고 패턴 — 단건 토글 버튼**: `jam-web/src/components/admin/itembooks/ItemBookActiveToggleButton.tsx`.
  단, 이 컴포넌트는 컬렉션 비활성화가 하위 아이템배지를 연쇄 비활성화하기 때문에
  "영향 범위 조회 → AlertDialog 확인" 단계가 있다. **POI는 연쇄 영향이 없으므로(이번 티켓
  범위에서 드랍/체크인 로직 미연동) 확인 다이얼로그 없이 클릭 즉시 PATCH하는 단순 버전으로
  만든다** — `deactivation-impact` API도 필요 없다.
- **참고 패턴 — PATCH API**: `jam-web/src/app/api/admin/itembooks/[id]/route.ts`의 PATCH
  핸들러. `jam-web/src/app/api/admin/poi/[id]/route.ts`에는 현재 PUT/DELETE만 있다 — PATCH를
  추가해 `{ is_active: boolean }`만 받아 갱신한다(전체 필드 PUT과 별개 경로).
- **참고 패턴 — 폼 Switch**: `jam-web/src/app/admin/itembooks/ItemBookForm.tsx` 439~440행
  `<Switch checked={isActive} onCheckedChange={...} />`. POI 폼(`PoiForm.tsx`)에는 이런
  cascade 확인이 필요 없으므로 `handleActiveToggle`의 확인 다이얼로그 분기 없이 단순
  `useState` + 제출 시 `body.is_active` 포함으로 충분하다. 신규 등록 시 기본값은 `true`.
- **참고 패턴 — 일괄 처리**: `jam-web/src/components/admin/poi/PoiTable.tsx`에 이미
  `rowSelection`·`DataTableBulkActionBar`·일괄 삭제(`handleBulkDelete`, 기존 단건 DELETE
  API를 선택 행 전체에 순차 호출)가 구현돼 있다. 동일한 구조로 `handleBulkActivate`/
  `handleBulkDeactivate`를 추가해 선택된 행 전체에 PATCH를 순차 호출한다
  (`jam-web/src/components/admin/itembooks/ItemBookTable.tsx`의 `handleBulkDeactivate`가
  가장 가까운 참고 패턴 — 단, 그쪽은 cascade 확인 다이얼로그가 있고 POI는 필요 없다).
  활성화/비활성화 모두 비파괴적·가역적 동작이라 **확인 다이얼로그 없이 즉시 실행**한다
  (기존 "선택 항목 삭제"만 파괴적 동작이라 확인 다이얼로그 유지).
- **목록 표시**: `page.tsx`의 `POI_LIST_COLUMNS`(19행)와 `PoiList.tsx`의 `PoiListRow`
  Pick 타입(10~13행)에 `is_active`를 추가해야 목록/테이블에서 값을 받을 수 있다.
- **상세 표시**: `PoiDetail.tsx`에는 상태를 보여줄 배지가 없다 — `linkedBadgeDeletedAt`
  표시에 쓰인 `Badge`/빨간 pill 패턴(46~53행, 74~79행)을 참고해 "활성"/"비활성" 상태
  배지를 카드 상단에 추가한다.
- **모바일 카드**: `PoiCard.tsx`에도 카테고리 옆에 상태 배지를 추가한다(데스크톱 테이블과
  동등한 정보 제공).
- 필터 화면(`PoiFilters.tsx`)에 "활성만 보기" 같은 상태 필터는 **이번 요구사항에 없으므로
  추가하지 않는다** — 목록은 활성/비활성 관계없이 전체를 계속 보여준다(어드민은 관리 목적상
  비활성 항목도 봐야 한다).

## 상세 요구사항

### 서비스/코드베이스 관점
- `poi` 테이블에 `is_active boolean NOT NULL DEFAULT true` 컬럼 추가 (마이그레이션 파일
  `114_poi_is_active.sql` 작성, **실행은 오케스트레이터가 사용자 승인 하에 처리**).
- `PoiRow` 타입에 `is_active: boolean` 추가.
- `PoiForm.tsx`: 등록/수정 폼에 활성 상태 Switch 추가, 제출 body에 `is_active` 포함.
- `PoiDetail.tsx`, `PoiCard.tsx`: 활성/비활성 상태를 배지로 표시.
- `PoiTable.tsx`: 상태 컬럼(배지 표시) + 행별 토글 버튼(확인 없이 즉시 PATCH) 추가.
- `PoiTable.tsx`의 `DataTableBulkActionBar`에 "선택 항목 활성화"/"선택 항목 비활성화" 버튼
  추가 — 기존 단건 PATCH API를 선택 행에 순차 호출(확인 다이얼로그 불필요, 기존 "선택 항목
  삭제" 확인 다이얼로그는 유지).
- `app/api/admin/poi/[id]/route.ts`에 PATCH 핸들러 추가 (`{ is_active }` 갱신 전용, 관리자
  인증은 기존 PUT/DELETE와 동일하게 `getAdminUser()` 사용).
- `page.tsx`/`PoiList.tsx`의 목록 조회 select 컬럼·타입에 `is_active` 반영.

### UI/UX 관점
- 상태 배지 라벨: "활성"/"비활성" (POI 상세·목록 전반에서 일관 사용,
  `UX_WRITING_GUIDELINE.md`의 고정 용어 원칙에 따름 — 이미 컬렉션·배지 화면에서 쓰는 표현
  그대로 재사용).
- 비활성 배지 스타일은 `PoiDetail.tsx`의 기존 빨간 pill(`bg-red-50 border-red-200
  text-red-600`) 톤을 따르거나, `Badge` 컴포넌트의 `variant="destructive"`/`outline`으로
  일관되게 구현(구현자 판단, 다른 화면과 톤 일치 우선).
- 일괄 처리 버튼 라벨: "선택 항목 활성화" / "선택 항목 비활성화" (기존 "선택 항목 삭제"와
  동일 톤).

## 구현 계획
1. 마이그레이션 `114_poi_is_active.sql` 작성 (`ALTER TABLE poi ADD COLUMN is_active boolean
   NOT NULL DEFAULT true`) — 파일만 작성, 실행하지 않음.
2. `types/database.ts` `PoiRow`에 `is_active: boolean` 추가.
3. `app/api/admin/poi/[id]/route.ts`에 PATCH 핸들러 추가.
4. `page.tsx`(select 컬럼) + `PoiList.tsx`(`PoiListRow` Pick 타입)에 `is_active` 반영.

6. `PoiCard.tsx`, `PoiDetail.tsx`에 상태 배지 표시 추가.
7. `PoiForm.tsx`에 활성 상태 Switch 추가, 생성/수정 body에 반영.
8. `npx tsc --noEmit -p .`, `npm run lint` 확인.
9. 회귀 확인: 카테고리 필터·검색·정렬·페이지네이션과 신규 컬럼이 함께 정상 동작하는지,

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
계획대로 8단계를 구현했다. `poi` 테이블에 `is_active boolean NOT NULL DEFAULT true` 컬럼을
추가하는 마이그레이션(`114_poi_is_active.sql`)을 작성했고(실행은 오케스트레이터 처리 대기),
`PoiRow` 타입·목록 select 컬럼·`PoiListRow` Pick 타입에 `is_active`를 반영했다.
`app/api/admin/poi/[id]/route.ts`에 `item_books` PATCH와 동일한 패턴으로 PATCH 핸들러를
추가했고(확인 없이 즉시 반영, cascade 없음), 기존 PUT/POST에도 `is_active` 필드를 포함시켰다.
목록 화면(`PoiTable.tsx`)에는 상태 배지 컬럼 + 행별 토글 버튼(`PoiActiveToggleButton.tsx`,
확인 다이얼로그 없는 단순 버전)을 추가했고, `DataTableBulkActionBar`에 "선택 항목 활성화"/
"선택 항목 비활성화" 버튼을 추가해 기존 단건 PATCH를 선택 행 전체에 순차 호출한다(기존
"선택 항목 삭제" 확인 다이얼로그는 그대로 유지). 모바일 카드(`PoiCard.tsx`)·상세
화면(`PoiDetail.tsx`)에도 동일한 "활성"/"비활성" 상태 배지를 추가했다. 등록/수정
폼(`PoiForm.tsx`)에는 `item_books` 폼과 달리 cascade 확인이 필요 없어 단순
`useState` + `Switch`로 활성 상태를 노출하고, 신규 등록 시 기본값은 `true`다.
