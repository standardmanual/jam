# [UI] 투데이 홈 상단 재구성 — "오늘의 현황" 스트립 도입

## 배경 / 문제 정의

투데이 홈(`jam-web/src/app/(main)/page.tsx`)은 유저가 가장 먼저 접속하는 화면이다.
Layers of Product Design 프레임워크로 상단 구성을 진단한 결과:

- 유저 니즈 분석(job story 기반) 결과 두 니즈가 상단에서 서빙되지 않고 있었다:
  - **니즈①(오늘의 성취 확인)**: 카드 스택·최근 배지 그리드가 담당하지만 인사말·Strava
    배너·검색바 뒤에 위치해 항상 늦게 등장한다.
  - **니즈③(격차 인식을 통한 재수집 동기)**: 소셜 비교(친구 대비 내 위치)와 개인 진행도
    (컬렉션·미션 격차) 통합 니즈. 서비스 특성(수집형 게이미피케이션 — 세계관/미션/드랍이
    전부 "완성해야 할 것" 축)상 핵심 리텐션 메커니즘인데 현재 전혀 서빙되지 않는다.
  - 니즈②(활동 반영 확신)는 TopNav 중앙 동기화 슬롯이 이미 잘 서빙하고 있어 손대지 않는다.
- 인터랙션 구조 분석 결과 기존 상단에서 규율 위반 2건 발견:
  - Strava 미연동 안내 카드: 탭해도 아무 데도 안 가는 "목적지 없는 콘텐츠". TopNav 중앙
    동기화 버튼과 기능 중복.
  - 상시 노출 전체 폭 검색바: "능동 검색"만 서빙, 니즈③(수동적 격차 인지)은 못 채움.
    소셜 탐색은 4개 페르소나 중 1개(러닝 크루)에만 해당하는 좁은 니즈라 상단 전체 폭을
    차지할 근거가 약함.
- 승인된 프로토타입(Claude Design 캔버스, MODULAR 토큰 기준 제작):
  https://claude.ai/code/artifact/5d8211c7-6f74-4bb4-88b9-62a36d831ff4

**중요 — 어드민 CMS 중복 방지**: `today_cards` CMS(투데이 카드 스택)는 그대로 유지된다.
조사 결과 `jam-web/src/lib/today/exposure.ts`가 이미 `new_user`·`has_participating_mission`·
`has_incomplete_itembook` 태그를 계산해 today_cards의 `exposure_tags` 매칭에 쓰고 있고,
어드민이 `mission_spotlight`/`itembook_milestone` 템플릿 + `new_user` 태그로 "신규 유저 추천"
카드를 이미 발행할 수 있는 구조다. 따라서 이번에 새로 만드는 "오늘의 현황" 스트립은
**큐레이션(콘텐츠 선택)을 하지 않는다** — today_cards CMS와 기능이 겹치면 같은 화면에
같은 성격의 추천이 중복 노출된다. 신규 어드민 UI도 필요 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

`jam-web/src/app/(main)/page.tsx` 상단 영역(TopNav 아래 ~ 투데이 카드 스택 위)을 재구성한다.
**투데이 카드 스택·최근 획득 배지 그리드·바로가기 그리드는 콘텐츠·형태 변경 없음** (위치만
상향 조정).

**1. 인사말 압축 + 검색 아이콘화**
- 기존 `<h1>{displayName}</h1>` 큰 인사말 블록 + 상시 노출 `UserSearchBar`(전체 폭 폼) 제거
- 한 줄로 대체: "{이름}님, 오늘도 좋은 하루예요" (좌) + 검색 아이콘 버튼(우, 36×36px 원형,
  `bg-surface-elevated`) → 탭 시 `/search`로 이동
- `UserSearchBar`의 폼 제출 로직(`/search?q=` 이동)은 기존 `/search` 페이지 자체 검색 UI로
  이전하거나, 아이콘 탭 시 인라인 확장되는 형태로 재사용 — 구현 시 판단

**2. "오늘의 현황" 스트립 (신규)** — 2열 그리드, 각 셀은 `Card`(`tone="inverse"`) 재사용

좌: **내 진행도**
- Strava 미연동: "Strava 연동하면 시작해요" → 탭 시 `/api/strava/auth` (기존 미연동 배너의
  기능을 흡수 — 어포던스 없던 기존 배너를 대체)
- 연동 + 진행 중인 컬렉션/미션 있음: "{세계관/컬렉션명} {진행}/{전체}" + `ProgressBar`(DS
  컴포넌트, 기본 트랙/필 색상 그대로) → 탭 시 해당 컬렉션 상세(`/collections/{id}`) 또는
  미션 목록(`/missions`)
  - **판정 로직 재사용**: `jam-web/src/lib/today/exposure.ts`의 `hasParticipatingMission`,
    `hasIncompleteItemBook` 헬퍼와 동일한 조회 패턴을 재사용해 "진행 중인지" 판정. 실제
    진행률(n/total)을 보여줘야 하므로 구체 데이터 조회는 별도 함수로 작성하되, 판정 조건은
    맞춘다.
  - 유저가 진행 중인 항목이 여러 개면 **하나만 선택해서 보여준다** (완성도가 가장 높은
    항목 우선 — 동률이면 최근 활동순). 여러 개를 동시에 나열하지 않는다.
- 연동 + 진행 이력 없음(신규 유저 또는 `isNewUser` 판정과 무관하게 순수 "진행 이력 없음"
  상태): **큐레이션이 아닌 정적 안내** — 아래 두 후보 중 **랜덤으로 1개만** 노출
  1. "드랍 아이템 찾아보기" → `/drops`
  2. "미션 참가해보기" → `/missions`
  - 후보 풀은 코드에 정적으로 정의(i18n 딕셔너리에 문구 추가). 어드민 편집 대상 아님.
  - 프로토타입에는 데모용 "다른 추천 보기" 리롤 버�른이 있으나, 실제 서비스에서는 페이지
    로드 시 1회 랜덤 선택이면 충분하다(리롤 UI는 넣지 않아도 됨 — 필요 판단은 구현 시).

우: **친구 활동** (상태당 메시지 1개만 — 여러 항목 나열 금지)
- 팔로잉 있음 + 최근 활동 있음: 아바타 스택(최대 3개) + "친구 N명이 오늘 배지를 받았어요"
  → 탭 시 팔로잉 유저들의 통합 활동 피드로 이동
  - **신규 쿼리 필요**: 기존 `FeedSection`(`jam-web/src/app/(main)/FeedSection.tsx`)은 단일
    유저 전용이다. "내가 팔로우하는 모든 유저의 최근 활동"을 보여주는 목적지가 필요한데,
    `activity_feed` 개념 자체는 이미 있으므로 **팔로잉 필터를 추가한 쿼리 확장**으로 해결할
    것 (신규 화면을 통째로 만들지 말 것 — 재사용 우선 원칙).
- 팔로잉 없음: "아직 팔로우한 친구가 없어요" → 탭 시 `/search`
- 팔로잉 있음 + 최근 활동 없음: **슬롯 자체를 렌더링하지 않는다** (빈 콘텐츠로 자리를
  차지하지 않음 — 이 경우 그리드가 1열로 좁아지거나 좌측 카드만 표시)

### UI/UX 관점

**MODULAR 재사용 판정(오케스트레이터 결정, 이대로 따를 것)** — 신규 UI는 기존 컴포넌트로
전부 커버되며, 신규 MODULAR 컴포넌트나 서비스 전용 신규 컴포넌트가 필요하지 않다:
- `Card`(`tone="inverse"`) — 스트립 좌/우 셀 컨테이너 (연결된 컴포넌트, 즉시 반영)
- `ProgressBar` — 진행중 상태의 진행도 바 (연결된 컴포넌트, 즉시 반영, 기본 트랙/필 색상
  그대로 사용 — inverse 카드 위에서도 기존 컴포넌트가 이미 다른 화면에서 쓰이는 방식 그대로)
- 기존 `icons.tsx`의 `PackageIcon`(드랍) · `TargetIcon`(미션) · `SearchIcon` · `UserIcon` ·
  `UsersIcon`(팔로잉 없음 빈 상태 — `EmptyState` 아이콘 관례와 동일하게 opacity 0.5 톤) 재사용
- `EmptyState`는 컴포넌트 자체를 스트립 셀에 넣지 않는다(카드 여백·타이포 규격이 안 맞음) —
  대신 그 시각적 관례(아이콘 opacity 0.5 + `text-secondary` 톤)만 인라인으로 차용
- `design-system/`을 건드리지 않으므로 `ds` 유형이 아니라 `ui` 유형이다 (1.6절 미해당)

**UX Writing 가이드 적용** — 신규 노출 문구는 전부 `d.today` i18n 딕셔너리에 새 키로 추가
(예: `todayStatus.stravaCta`, `todayStatus.suggestionDrops`, `todayStatus.suggestionMissions`,
`todayStatus.friendActivity`, `todayStatus.noFollowing` 등), 해요체·간결한 문장 유지, 기존
고정 용어(획득·드랍·픽업·체크인) 그대로 사용.

### 컨텐츠 관점

해당 없음 — 새 어드민 콘텐츠·CMS 없음 (배경 절 참조).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 인사말을 압축 한 줄("{이름}님, 오늘도 좋은 하루예요")로 바꾸고, 상시 노출 전체 폭
  `UserSearchBar`를 36×36px 원형 검색 아이콘 버튼(`/search` 이동)으로 대체했다.
  `UserSearchBar` 자체는 삭제하지 않고 `/search` 페이지에서 그대로 유지된다.
- "오늘의 현황" 2열 스트립(`TodayStatusStrip.tsx`, 신규)을 추가했다. 좌 슬롯(내 진행도)은
  Strava 미동기화/진행 중 컬렉션·미션 1건(완성도 최고 우선, 동률 시 최근 활동순)/신규
  유저 정적 안내(코드 고정 후보 풀에서 매 요청 랜덤 1개) 3가지 상태로 분기하고, 우 슬롯
  (친구 활동)은 팔로잉 없음/팔로잉 있음+오늘 활동 없음(슬롯 미노출, 그리드 1열로 축소)/
  팔로잉 있음+오늘 배지 획득 있음(아바타 스택 최대 3 + "친구 N명이 오늘 배지를
  획득했어요") 3가지로 분기한다. Strava 미연동 안내 카드(기존, 목적지 없던 배너)는
  좌 슬롯이 흡수해 제거했다.
- 데이터 조회는 신규 `src/lib/today/status.ts`에 작성했다. 좌 슬롯의 "진행 중" 판정은
  `lib/today/exposure.ts`의 `hasParticipatingMission`/`hasIncompleteItemBook`과 동일한
  조회 패턴(참가/슬롯 → 완료 테이블 제외)을 재사용했고, 우 슬롯은 `user_follows` +
  `user_activity_feed`(event_type='badge_earned', KST 오늘 00:00 이후)를 조회한다.
  두 함수 모두 `page.tsx`의 기존 병렬 `Promise.all`에 합류시켰다(순차 대기 추가 없음).
- 우 슬롯의 목적지로 팔로잉 통합 활동 피드(`/feed`, 신규 라우트)를 최소 구현했다.
  신규 화면을 통째로 만들지 않고 기존 `FeedSection`(단일 유저 전용 컴포넌트) 렌더링은
  그대로 두고, **쿼리만** `user_activity_feed.user_id IN (팔로잉 목록)`으로 확장해
  재사용했다(Strava 활동 id는 전역 유일값이라 여러 유저 활동이 섞여도 활동 단위 묶음
  로직이 깨지지 않는다).
- i18n: `today.greeting`/`stravaLabel`/`stravaNotConnectedTitle`/`stravaNotConnectedBody`/
  `stravaConnectButton`(다른 곳에서 더 이상 참조되지 않아 삭제) → 신규 `todayStatus.*`
  네임스페이스로 대체, `feed.friendFeedTitle`/`friendFeedEmptyTitle`/`friendFeedEmptyBody`
  추가.
- UI 재사용: 신규 MODULAR 컴포넌트 없음. `Card(tone="inverse")`·`ProgressBar`(기본
  트랙/필 색상)·`PackageIcon`·`TargetIcon`·`SearchIcon`·`UserIcon`·`UsersIcon`만
  재사용했고, `EmptyState`는 컴포넌트 자체 대신 시각 관례(아이콘 opacity 0.5 톤)만
  인라인 차용했다. `design-system/`은 건드리지 않았다.

### 잔여 이슈
- `/feed`(팔로잉 통합 활동 피드)는 `FeedSection`을 쿼리만 확장해 재사용한 최소 구현이라,
  각 활동 카드에 "누구의" 활동인지(아바타·이름)가 표시되지 않는다. 단일 유저 전용으로
  설계된 컴포넌트라 항목별 주체 표시 기능 자체가 없다 — 여러 친구 활동이 한 목록에
  이름 없이 섞여 보인다. 이번 티켓 범위(신규 화면을 통째로 만들지 말 것 + 최소 구현)
  안에서는 의도된 트레이드오프이지만, 실사용성 관점에서 후속 개선 여지가 있다.
- (범위 밖, 별도 작업으로 분리) `getTodayLeftStatus(userId, true)`가 Strava 미연동
  유저에게도 매번 컬렉션/미션 DB 조회를 실행하는 성능 이슈 — 정합성 문제는 없으나
  최적화 후보. 게이트 리뷰 sideFindings에서 발견, 별도 작업 칩으로 분리함.
- 인사말 truncate가 이름이 아니라 문장 전체 단위로 잘리는 문제(인터랙션 리뷰 제안) —
  이름이 긴 유저는 "오늘도 좋은 하루예요" 문구 자체가 사라질 수 있음. 후속 개선 후보로
  남겨둠(이번 티켓 범위 밖).
