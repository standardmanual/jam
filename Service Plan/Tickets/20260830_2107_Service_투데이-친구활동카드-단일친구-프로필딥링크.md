# [Service] 투데이 "친구 활동" 카드 — 친구 1명일 때 해당 친구 프로필로 딥링크

## 배경 / 문제 정의

티켓 20260830_2030(투데이 홈 상단 재구성)에서 만든 "오늘의 현황" 우 슬롯(친구 활동) 카드가
방금 프로덕션에 배포됐다. 사용자가 실사용 중 발견: 친구 1명이 오늘 배지를 획득한 경우에도
카드를 탭하면 항상 `/feed`(팔로잉 통합 활동 피드)로 이동한다. 정확히 1명일 때는 "그 친구가
누구인지"가 이미 명확하므로, 여러 명이 섞인 통합 피드로 보내지 말고 **그 친구의 프로필
페이지로 바로 이동**해야 한다.

`jam-web/src/lib/today/status.ts`의 `getTodayRightStatus` 확인 결과: `friend_activity`
상태의 `href`가 인원수와 무관하게 항상 `'/feed'`로 하드코딩돼 있다(코드 262번째 줄). 또한
아바타 조회 시 `users` 테이블에서 `id, avatar_url`만 가져오고 `username`은 조회하지 않아,
프로필 경로(`/{username}`)를 만들 재료 자체가 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `getTodayRightStatus`(`jam-web/src/lib/today/status.ts`)에서 오늘 배지를 획득한 팔로잉이
  **정확히 1명**이면: 그 유저의 `username`을 조회해 `href`를 `/${username}`으로 설정한다.
  (2명 이상이면 기존대로 `href: '/feed'` 유지)
- `users` 테이블 조회에 `username` 컬럼을 추가로 select한다.
- username이 없는 예외 상황(탈퇴 등 edge case)이 있다면 안전하게 `/feed`로 폴백한다.
- `TodayStatusStrip.tsx`(`RightCell`)는 `status.href`를 그대로 쓰고 있으므로 마크업 변경은
  불필요 — `status.ts`의 href 계산 로직만 고치면 된다.

### UI/UX 관점

- 카드 문구("친구 N명이 오늘 배지를 획득했어요")는 변경 없음 — 목적지만 바뀐다.

## 구현 계획

1. `getTodayRightStatus`에서 `orderedUserIds.length === 1`일 때 해당 유저의 `username`을
   조회하고 `href`를 `/${username}`으로 설정
2. 기존 회귀 테스트(있다면) 확인, 없으면 순수 로직 유닛테스트 추가 고려
   (`count===1` → 프로필 href / `count>=2` → `/feed` href)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`getTodayRightStatus`(`jam-web/src/lib/today/status.ts`)의 `users` 조회에 `username`을 추가
select하고, 목적지 계산을 순수 함수 `resolveFriendActivityHref(count, singleUsername)`로 분리했다.
- 오늘 배지를 획득한 팔로잉이 **정확히 1명**이고 그 유저의 `username`을 정상 조회했으면
  `href`를 `/${username}`으로 설정
- 2명 이상이면 기존대로 `/feed` 유지
- 1명이지만 `username`이 없는 예외(탈퇴 등)에는 `/feed`로 폴백
`TodayStatusStrip.tsx`(`RightCell`)는 이미 `status.href`를 그대로 쓰고 있어 마크업 변경 없음.
