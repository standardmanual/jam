# [UI] 타인(친구) 프로필 기본뷰에 "최근 활동" 노출

## 배경 / 문제 정의

티켓 20260830_2107(투데이 홈 친구활동 카드 — 단일 친구 프로필 딥링크) 작업 중 사용자가
직접 지적: 친구 1명일 때 카드가 이동하는 "친구활동" 화면(`/feed`)이 내 프로필의 "최근 활동"
구성과 겹쳐 보인다는 피드백에서 출발해, 실제로는 **타인 프로필(`/{username}`)에 "최근 활동"
섹션 자체가 없다**는 더 근본적인 문제를 확인했다.

`jam-web/src/app/(main)/[username]/page.tsx`와 `jam-web/src/app/(main)/profile/ProfileClient.tsx`
조사 결과: 본인/타인 프로필은 **완전히 같은 컴포넌트**(`ProfileClient`)를 쓰고, 데이터도 이미
방문 대상 유저(`target`/`subjectId`) 기준으로 조회해 전달하고 있다. 유일한 차이는
`isOwnProfile` 플래그이며, 그 결과:

- `isTabView = !isOwnProfile || VALID_TABS.has(hashFragment)` — 타인 프로필은 **항상**
  탭뷰(기본 '배지' 탭)로 고정된다.
- Strava 카드·`FeedSection`(최근 활동)은 `isOwnProfile && !isTabView`일 때만 렌더링 —
  즉 **본인 전용**이라 타인 프로필에는 "최근 활동"이 아예 존재하지 않는다.

**백엔드/쿼리 변경은 불필요** — `[username]/page.tsx`가 이미 대상 유저의 `feedItems`를
조회해 `ProfileClient`에 넘기고 있다. `ProfileClient.tsx`의 조건부 렌더링만 고치면 된다.

## 상세 요구사항 (사용자 확인 완료)

### 서비스/코드베이스 관점

`jam-web/src/app/(main)/profile/ProfileClient.tsx` 수정:

1. **`isTabView` 계산을 전역으로 통일**: `!isOwnProfile || VALID_TABS.has(hashFragment)` →
   `VALID_TABS.has(hashFragment)`로 변경. 본인/타인 구분 없이 해시가 없으면 기본뷰,
   유효한 해시가 있으면 탭뷰.
   - **범위는 전역이다** — 투데이 "친구 활동" 카드에서 들어갈 때만이 아니라, 검색·팔로워/
     팔로잉 목록 등 **어떤 경로로 타인 프로필에 들어가도** 항상 이 기본뷰가 적용된다
     (같은 컴포넌트를 공유하는 구조라 진입 경로별 분기는 하지 않기로 확정함).
2. **`FeedSection`(최근 활동) 노출 조건**: `isOwnProfile && !isTabView` → `!isTabView`로
   변경. 본인/타인 관계없이 기본뷰일 때 노출되고, 데이터는 이미 대상 유저 기준이라
   자동으로 "그 유저의 최근 활동"이 된다. `badgeLinkQuery`(`?u=${username}`)는 이미 두
   케이스 모두 정확히 대상 유저 기준으로 설정돼 있어 손댈 필요 없음.
3. **Strava 상태 카드는 타인 프로필에 노출하지 않는다** — 조건은 **변경하지 않고 그대로
   `isOwnProfile && !isTabView` 유지**. 연동 여부와 무관하게 카드 자체를 숨긴다(사용자
   확정: "친구 프로필에 방문했을 때는 스트라바 상태 카드는 필요없어" — 미연동 시
   "지금 동기화하기" 버튼이 "내 계정 연동" 액션이라 타인 프로필에서 의미가 없기도 함).
4. **다음은 그대로 본인 전용 유지** (사용자 확인 완료 — 변경하지 않음):
   - 아바타 편집 버튼 (`isOwnProfile &&`)
   - 포인트 잔액 표시 (`isOwnProfile && pointBalance !== null` — 애초에 서버에서
     `isOwnProfile`일 때만 조회함, 이메일급 비공개 정보)
   - 로그아웃 버튼 (`isOwnProfile &&`)

### UI/UX 관점

- MODULAR 재사용 판정: 신규 컴포넌트 없음. 기존 `ProfileClient.tsx`의 조건문만 수정,
  `FeedSection`은 이미 존재하는 재사용 컴포넌트를 조건만 바꿔 더 넓게 쓰는 것.
- `design-system/`은 건드리지 않음 (`ui` 유형, `ds` 아님).
- UX 라이팅: 신규 노출 문구 없음 (기존 `FeedSection`/`d.feed.*` 문구 그대로 재사용).

## 구현 계획

1. `ProfileClient.tsx`의 `isTabView` 계산식에서 `!isOwnProfile ||` 제거
2. `FeedSection` 렌더 조건에서 `isOwnProfile &&` 제거 (Strava 카드 조건은 그대로 둠)
3. 타인 프로필 기본뷰에서 Strava 카드가 안 뜨는지, 탭(#배지/#컬렉션/#팔로워/#팔로잉)
   해시 이동은 여전히 정상 동작하는지, 본인 프로필 동작에 회귀가 없는지 확인
4. 티켓 20260830_2107(친구활동카드 href 수정)과의 관계 확인 — 그 티켓이 친구 1명일 때
   `/{username}`으로 보내도록 고치면, 이 티켓 덕분에 그 페이지가 이제 "최근 활동"을
   기본으로 보여주게 되어 두 티켓이 합쳐져 완성된다. 순서 무관하게 독립적으로 머지 가능
   (서로 다른 파일: `status.ts` vs `ProfileClient.tsx`).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`ProfileClient.tsx`에서 (1) `isTabView` 계산식을 `!isOwnProfile || VALID_TABS.has(hashFragment)`
→ `VALID_TABS.has(hashFragment)`로 단순화해 본인/타인 구분 없이 해시 유무로만 기본뷰/탭뷰를
가르도록 전역 통일했고, (2) `FeedSection`(최근 활동) 렌더 조건을 `isOwnProfile && !isTabView`
→ `!isTabView`로 완화해 기본뷰에서는 본인/타인 관계없이 노출되도록 했다. Strava 카드 조건
(`isOwnProfile && !isTabView`)과 아바타 편집·포인트 잔액·로그아웃 버튼(모두 `isOwnProfile &&`)은
지시대로 변경하지 않았다. `[username]/page.tsx`의 `feedItems`는 이미 `subjectId`(대상 유저)
기준으로 조회돼 전달되고 있음을 코드로 재확인했고(변경 불필요), `badgeLinkQuery`(`?u=${username}`)도
기존 그대로 대상 유저 기준이라 손대지 않았다.
