# [UI] 투데이 "오늘의 현황" 스트립 카드 타이틀 레이블 추가

## 배경 / 문제 정의
티켓 [20260830_2030](./20260830_2030_UI_투데이홈-상단-재구성-오늘의현황-스트립.md)에서 도입한
"오늘의 현황" 좌우 슬롯 카드(`TodayStatusStrip.tsx`)는 카드 내용만 보여줄 뿐, 각 카드가
무엇에 대한 정보인지(좌: 내 진행도 / 우: 친구 활동) 알려주는 타이틀 레이블이 없다.
사용자 요청: 좌우 슬롯 카드 각각의 왼쪽 상단에 해당 컨텐츠의 타이틀 레이블을 추가한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/app/(main)/TodayStatusStrip.tsx`의 `LeftCell`·`RightCell` 각 카드 좌측
  상단에 타이틀 레이블(칩)을 추가한다.
- **MODULAR 재사용 판정(오케스트레이터 결정)**: 신규 컴포넌트를 만들지 않는다.
  `jam-web/src/app/(main)/TodayCardStack.tsx`의 `TemplateChip` 패턴(캡션 크기·bold·
  `bg-surface text-text` 칩, `tone="inverse"` 카드 위에서 대비 확보)을 그대로 차용해
  인라인으로 구현한다. 이 스트립은 티켓 20260830_2030에서 이미 "신규 컴포넌트 없이 기존
  Card·ProgressBar·icons만 사용" 원칙을 세웠으므로 이번에도 동일 원칙을 따른다.
- 레이블 텍스트: 좌 "내 진행도", 우 "친구 활동" (코드 주석에 이미 쓰인 명칭과 동일,
  `todayCard.badgeSpotlight` 등 기존 칩 레이블처럼 명사형·해요체 아님).
  `d.todayStatus`에 `myProgressLabel`·`friendActivityLabel` 등으로 신규 추가.
- 좌 카드의 3분기(미연동/진행중/신규유저 안내) 모두 동일하게 "내 진행도" 레이블을 노출한다
  (분기별로 다른 레이블을 쓰지 않는다 — 카드가 속한 슬롯 자체를 설명하는 레이블이므로).
- 우 카드는 `friend_activity`·`no_following` 두 분기 모두 "친구 활동" 레이블을 노출한다
  (`none` 분기는 카드 자체가 렌더링되지 않으므로 해당 없음).

### UI/UX 관점
- 레이블은 카드 본문(진행바·문구 등)보다 시각적으로 낮은 위계여야 한다 — `TemplateChip`과
  동일하게 캡션 크기 유지.
- 카드 클릭 영역(`Link`)에 레이블도 포함되어도 무방 (레이블 자체가 별도 인터랙션을 갖지 않음).

### 컨텐츠 관점
- 해당 없음 (UX Writing 가이드의 고정 용어 범위 밖 — 순수 카테고리 레이블)

## 구현 계획
1. `d.todayStatus`에 레이블 텍스트 2종 추가.
2. `TodayStatusStrip.tsx`의 `LeftCell`·`RightCell` 각 `Card` 상단에 칩 요소 추가
   (`TemplateChip`과 동일한 스타일 클래스, 컴포넌트 재사용은 아니고 스타일 관례만 차용 —
   `TemplateChip`은 `TodayCardTemplateType`에 의존적이라 그대로 import해 재사용하기 어려움).
3. 3개 좌 분기·2개 우 분기 모두에서 레이블이 정상 노출되는지 확인, 레이아웃 회귀(카드 높이·
   정렬) 없는지 확인.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `d.todayStatus`에 `myProgressLabel`('내 진행도')·`friendActivityLabel`('친구 활동') 2종 추가.
- `TodayStatusStrip.tsx`에 `CellLabel` 헬퍼(파일 내부 전용, MODULAR 신규 컴포넌트 아님)를
  추가해 `TemplateChip`(TodayCardStack.tsx)과 동일한 시각 클래스(캡션 크기·bold·uppercase·
  `bg-surface text-text` 칩)를 인라인으로 차용했다.
- `LeftCell`의 3분기(`strava_disconnected`/`progress`/`suggestion`) 전부에 `myProgressLabel`을,
  `RightCell`의 2분기(`no_following`/`friend_activity`) 전부에 `friendActivityLabel`을 적용.
- 레이아웃 회귀 방지: 기존 `CELL_CLASS`(`flex-col justify-center`)에 레이블을 그냥 끼워넣으면
  레이블이 본문과 함께 카드 중앙에 묶여버려 "좌측 상단 고정" 요구를 만족 못한다. 이를 위해
  `CELL_CLASS`에서 `justify-center`를 제거해 레이블이 항상 카드 최상단에 오도록 하고, 기존
  본문 요소들은 `CELL_BODY_CLASS`(`flex-1 flex flex-col justify-center gap-8`)로 감싸
  레이블 아래 남은 공간에서 세로 중앙 정렬되도록 재구성했다. 레이블 span에는 `self-start`를
  추가해 `flex-col` 부모의 기본 `align-items: stretch`로 인해 칩이 카드 전체 너비로 늘어나는
  것을 방지했다.

### 주요 의사결정 / 핵심 메모
- `TemplateChip`을 그대로 import하지 않고 클래스만 차용하는 오케스트레이터 판정을 그대로
  따랐다 — `TemplateChip`은 `TodayCardWithHref`/`TodayCardTemplateType`에 의존적이라 시그니처가
  안 맞는다.
- 레이블을 절대 위치(absolute positioning)로 카드 좌상단에 고정하는 방식도 검토했으나,
  `Card` 컴포넌트가 `padding` 값을 인라인 스타일로만 지정하고(`var(--layout-card-padding)`)
  `position: relative`를 갖지 않아 absolute 자식이 padding box 기준으로 배치되면서
  기존 본문의 padding-respect 정렬과 어긋날 위험이 있었다. 대신 flex 정상 흐름(레이블을
  최상단 flex 아이템으로, 본문을 `flex-1 justify-center`로 감싸는 방식)으로 구현해 이 문제를
  피했다.
