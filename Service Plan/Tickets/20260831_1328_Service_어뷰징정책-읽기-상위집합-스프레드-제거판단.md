# [Service] getAbusingPolicy의 상위집합 스프레드 — 제거 판단

## 배경 / 문제 정의

`jam-web/src/lib/abusing/policy.ts`의 `getAbusingPolicy()`가 `{ ...row, ...normalized }`로
**원본 행의 상위집합**을 돌려준다. 티켓 20260831_1149가 넣은 장치인데, **정당화하던 근거가
두 단계에 걸쳐 사라졌다.**

원래 근거는 이랬다 — 마이그레이션 115(등급명 legend·mythic → epic·mystic) 미실행 구간에는
DB에 구 컬럼명이 남아 있고, `shadow-ban.ts`가 런타임 `rarity` 값으로
`${banLevel}_${rarity}_rate` 키를 **문자열 조합**하므로, `DEFAULT_POLICY` 키만 추려 새 객체를
만들면 구 키가 탈락해 작동 중이던 차단이 꺼진다.

1. **2026-08-31 마이그레이션 115가 적용됐다.** DB 컬럼과 앱 키가 일치한다
   (1149의 잔여 이슈: "제거 조건이 이미 충족됐다", 롤백 안전성 때문에 유지).
2. **티켓 20260831_1259가 문자열 조합을 타입 맵으로 바꿨다.** 이제 `shadow-ban.ts`는
   `Record<BadgeRarity, keyof AbusingPolicy>`로 키를 찾으므로 **구 키를 보존해도 그 키를
   조회하지 않는다.** 상위집합이 shadow-ban을 돕던 경로 자체가 없어졌다.

즉 지금 이 스프레드는 **`AbusingPolicy` 타입에 없는 키를 런타임 객체에 실어 나르기만 한다**
(`as unknown as AbusingPolicy` 이중 캐스팅으로 타입 검사를 두 번 우회하면서). 남겨둘 이유가
있는지, 있다면 무엇인지를 확정해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **먼저 판단한다: 이 스프레드에 남은 소비자가 정말 없는가.** `getAbusingPolicy()`의 반환을
  받는 지점을 전수 확인한다 — 현재 확인된 곳은 `api/drops/[dropId]/pickup/route.ts:68`,
  `lib/drop-engine/index.ts:427`, `app/admin/abusing/page.tsx:16`,
  `api/admin/abusing/policy/route.ts`. `DEFAULT_POLICY`에 없는 키를 읽는 곳이 하나라도 있으면
  제거하면 안 된다.
- 소비자가 없다면 `return normalized as AbusingPolicy`로 좁히고 `as unknown as` 이중 캐스팅을
  없앤다. 근거를 설명하던 주석 블록(`policy.ts` 105~109행 부근)과
  `__tests__/policy-save.test.ts` 헤더 주석도 함께 정리한다.
- **테스트를 어떻게 바꿀지 명시적으로 판단한다.** `policy-save.test.ts`의
  "마이그레이션 115 미실행 구간에서도 구 컬럼 키를 보존한다" 케이스는 스프레드를 지우면
  성립하지 않는다. 그 케이스를 지울지, "구 등급은 fail-closed로 막힌다"로 의미를 바꿀지
  결정하고 이유를 남긴다.
- 남기기로 한다면 **남기는 이유를 코드 주석에 현재형으로 다시 쓴다.** 지금 주석은
  "근거가 사라졌지만 별건으로 남겨둔다"고만 적혀 있어 다음 사람이 판단할 근거가 없다.

### 범위 밖

- 마이그레이션 115의 롤백 SQL 자체는 건드리지 않는다.
- `DEFAULT_POLICY` 값 변경·DB 쓰기는 이 티켓과 무관하다.

## 구현 계획

1. `getAbusingPolicy()` 반환 소비 지점 전수 확인 (`DEFAULT_POLICY` 밖 키를 읽는 곳이 있는지)
2. 제거 / 유지 결정 + 근거 기록
3. 결정에 맞춰 코드·주석·테스트 정리
4. `npx tsc --noEmit` / `npm run lint` / `npx vitest run src/lib/abusing` / `npm run build`
