# [Admin] 어뷰징 정책을 어드민에서 바꾸면 DEFAULT_POLICY 미러가 조용히 깨진다

## 배경 / 문제 정의

티켓 20260831_1259가 `jam-web/src/lib/abusing/policy.ts`의 `DEFAULT_POLICY`를
**`abusing_policy` id=1 행의 미러**로 정의했다. 폴백이 정책을 바꾸지 않게 하려는 불변식이다.
불변식을 지키는 장치로 코드 주석과 `SERVICE_OPERATIONS.md` §12-5에
**"DB 배율을 바꾸면 같은 티켓에서 `policy.ts`도 함께 바꾼다"** 를 명시했다.

문제는 **이 규칙이 "티켓" 경로만 가정한다**는 점이다. 배율을 바꾸는 가장 흔한 경로는 티켓이
아니라 **어드민 화면**이다 — 운영자가 `/admin/abusing`에서 슬라이더를 움직이고
`PUT /api/admin/abusing/policy`로 저장하면 DB만 바뀌고 `policy.ts`는 그대로 남는다.
문서에 적힌 규칙은 그 경로를 덮지 못한다.

불일치가 생기면 **정상 경로와 폴백 경로의 판정이 갈리고, 그 차이는 무음이다.** 이번 사고의
본질이 정확히 "규율이 문서에만 있고 코드에 붙어 있지 않았다"였다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **저장 시점에 불일치를 감지해 신호를 남긴다.** `updateAbusingPolicy()` 성공 직후
  배율 8종(`RATE_KEYS`)을 `DEFAULT_POLICY`와 비교해 다르면 `console.warn` 1회.
  드랍마다가 아니라 **저장 시 1회**라 로그 노이즈가 없다.
  문구에 "어느 키가 얼마에서 얼마로 갈렸는지"와 "`policy.ts`를 같이 갱신해야 한다"를 담는다.
- **어드민 화면에 불일치 배너를 띄울지 함께 판단한다.** 로그는 보는 사람이 있어야 신호가 되고,
  이 규칙을 지켜야 하는 사람은 운영자다. 배너를 넣는다면:
  - 위치는 `/admin/abusing` 정책 섹션 상단
  - **어드민 UI는 shadcn/ui 표준을 따른다** (`components/ui`의 기존 컴포넌트 사용)
  - 문구는 `Specs/UX_WRITING_GUIDELINE.md`의 [현상] → [원인] → [해결책] 3단계
  - 운영자가 코드를 고칠 수는 없으므로 **"개발자에게 알려달라"는 행동 지시**가 맞다
- 배너를 넣지 않기로 하면 그 이유를 티켓에 남긴다 (로그만으로 충분하다고 볼 근거가 있는지).

### 범위 밖

- **DB 배율 값 자체를 바꾸지 않는다.** Epic 차단을 켤지는 여전히 별도 판단이다
  (마이그레이션 115 §5). Supabase는 staging·프로덕션 공용 단일 DB다.
- `DEFAULT_POLICY` 값 변경도 하지 않는다.

## 구현 계획

1. `updateAbusingPolicy()` 성공 경로에 배율 8종 대조 + `console.warn` 추가
2. 어드민 배너 도입 여부 판단, 도입 시 shadcn 컴포넌트로 구현 + UX 라이팅 검증
3. 단위 테스트 — 불일치 시 경고가 나가고, 일치 시 나가지 않는다
4. `npx tsc --noEmit` / `npm run lint` / `npx vitest run src/lib/abusing` / `npm run build`
5. **어드민은 staging 검증 대상이 아니다** — 실화면 확인은 프로덕션 배포 후
