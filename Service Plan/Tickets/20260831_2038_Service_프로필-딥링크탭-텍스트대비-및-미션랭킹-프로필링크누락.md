# [Service] 프로필 딥링크 탭 텍스트 대비 문제 + 미션 랭킹/달성 현황 프로필 링크 누락

## 배경 / 문제 정의

사용자가 아이폰 사파리에서 알림함 → 다른 유저 프로필로 이동했을 때(특정 통계탭이 URL
파라미터로 미리 선택된 상태로 랜딩) 상단 통계탭("배지/컬렉션/팔로워/팔로잉")의 활성 탭
텍스트가 잘 안 보이는 문제와, 다른 유저의 아이디/프로필을 눌러도 그 사람 프로필로 이동하지
않는 문제 두 가지를 함께 신고했다.

**원인 조사 결과 (조사 완료, 코드 수정 없음)**:

### 1. 딥링크 탭 텍스트 대비 문제
- `#followers`로 직결되는 알림 경로는 실제로 코드에 없다(`src/lib/notifications/href.ts`
  `followed` 케이스는 팔로워 1명이면 그 사람 프로필로, 2명 이상이면 `/{me}/followers`라는
  `SlidingTabs`가 아예 없는 별도 페이지로 감). 유일하게 재현 가능한 딥링크는
  `following_rare_badge` 알림 → `/{username}#badge`(배지 탭 초기 선택)이다. 사용자가 "팔로워"로
  기억한 건 실제로는 "배지" 탭이었을 가능성이 높다.
- 하지만 **탭 이름과 무관하게 실재하는 구조적 결함**을 찾았다:
  `src/components/ui/SlidingTabs.tsx`가 딥링크로 초기 activeIndex가 0이 아닌 값으로 처음
  포지셔닝될 때, pill 배경 위치는 무애니메이션 트릭(`transition:none` → 강제 reflow →
  transition 복원)으로 즉시 자리를 잡지만, 이 트릭은 pill 자신에만 적용되고
  `src/components/transitions.css:137-155`의 `.t-tab[aria-selected="true"] { color:
  var(--tabs-text-active); transition: color var(--tabs-dur) ... }`(300ms)는 건드리지 않는다.
  결과적으로 **pill 배경은 이미 목표 탭에 있는데, 그 위 텍스트 색은 muted→active로 300ms에
  걸쳐 서서히 페이드**되는 프레임이 생겨, 그 사이 대비가 낮은 중간색으로 잠깐 읽기 어려워진다.
  `prefers-reduced-motion` 환경에서는 이 문제가 없다(transition이 전부 꺼짐) — OS 설정에
  따라 재현 여부가 갈리는 구조.
- (참고, 범위 밖) `ProfileClient.tsx`가 URL 해시를 `useEffect`(비-Layout)로 늦게 동기화해
  첫 프레임이 항상 기본뷰로 그려졌다가 탭뷰로 전환되는 플래시도 있으나, 이건 전 브라우저
  공통이고 이번 신고 증상(텍스트 대비)과 직접적 인과가 약해 이번 티켓 범위에서 제외한다.

### 2. 친구 프로필 이동 안 되는 문제
- 대부분 위치(팔로워/팔로잉 목록, 검색, 알림함, 프로필 내 팔로워/팔로잉 탭)는 이미
  `/${username}`으로 정상 연결돼 있음을 확인했다.
- **미션 랭킹/달성 현황 화면**(`src/app/(main)/missions/[id]/status/MissionStatusClient.tsx`)만
  누락: 랭킹형 미션의 4위 이하 순위 리스트(`RankingListRow`, 215행)와 달성형 미션의 참가자
  리스트(`AchievementRow`, 376행) 둘 다 `ListRowCard`를 쓰면서 `href`를 전달하지 않는다.
  `RankingEntry.username`/`AchievementEntry.username`이 이미 데이터에 있어 배선만 하면 된다.
  (1~3위 포디엄과 "나의 순위" 카드는 `ListRowCard`가 아닌 별도 마크업이라 이번 범위에서 제외 —
  포디엄은 시각적 강조가 목적이라 링크 추가 시 레이아웃 영향 검토가 별도로 필요하고, "나의
  순위"는 본인이라 링크 필요성이 낮음. 필요 시 별도 판단.)
- (범위 밖, 별도 판단 필요) 인벤토리 아이템 히스토리(`InventoryItemHistorySheet.tsx`)와 드랍
  상세(`BadgeDetailSheet.tsx`)의 유저 언급도 링크가 없지만, 이쪽은 API가 라우팅 가능한
  `username` 슬러그를 아예 안 내려주고 표시용 이름만 내려주는 구조라 API 확장이 필요한 더 큰
  작업이다 — 사용자 확인 결과 이번 티켓에서는 제외.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. `SlidingTabs.tsx`의 `moveTo(key, animate)` 중 무애니메이션(`animate=false`) 분기에서
   pill뿐 아니라 현재 마운트된 모든 `.t-tab` 버튼의 인라인 `transition`도 `'none'`으로
   임시 설정 → `pill.offsetWidth` 강제 리플로우 → 원래 transition 값으로 복원하는 방식으로
   확장했다. `animate=true`(사용자가 직접 탭을 클릭해 전환하는 경우) 분기는 그대로 두어
   기존 300ms 페이드가 유지된다.
   - 실제 버그 경로 확인: `ProfileClient.tsx`는 첫 렌더에 `activeTab` 기본값 `'badge'`이지만
     `isTabView`가 아직 `false`라 `SlidingTabs`에 `value=''`(매칭 탭 없음)를 넘긴다 → 첫
     `moveTo('', false)`는 매칭 탭이 없어 `hasPositionedRef`가 `false`로 남는다. 이후
     `useEffect`(비-Layout)가 URL 해시를 읽어 `activeTab`을 실제 딥링크 탭으로 갱신하면,
     `SlidingTabs`의 `useLayoutEffect`가 `moveTo(target, false)`(여전히 `hasPositionedRef`가
     `false`)를 호출한다 — 이 시점에 대상 탭의 `aria-selected`가 `false→true`로 실제로
     플립되므로 CSS `.t-tab` transition이 진짜로 발화해 텍스트가 300ms에 걸쳐 페이드된다.
     이번 수정으로 이 프레임에서 pill과 텍스트 색이 동시에 즉시 적용된다.
2. `MissionStatusClient.tsx`의 `RankingListRow`(215행 부근)에 `href={`/${entry.username}`}`,
   `AchievementRow`(376행 부근)에 `href={`/${e.username}`}`를 추가했다. `ListRowCard`는
   `href`가 있으면 `<Link>`로 렌더되고 `active:scale-[0.98]`·`cursor-pointer` 등 interactive
   스타일을 자동으로 적용하므로(`ListRowCard.tsx` 80행) 별도 스타일 작업 없이 배선만으로
   충분했다. 두 필드 모두 타입상 `username: string`(non-nullable)이라 안전하다.

#### 게이트 리뷰 FAIL 후속 수정 (2번 항목)
위 2번 구현이 게이트 리뷰에서 FAIL 판정을 받았다: `RankingEntry.username`/`AchievementEntry.username`은
`src/app/api/missions/[id]/status/route.ts`의 `nameOf()`(= `getDisplayName` = `display_name?.trim()
|| username`) 결과였다 — 즉 필드명이 `username`이어도 실제 값은 표시용 이름(닉네임 우선)이라
라우팅용 `users.username` 컬럼과 다를 수 있었다. 닉네임을 아이디와 다르게 설정한 참가자는
프로필 라우트(`/[username]/page.tsx`, `.eq('username', ...)` 정확 매칭)와 어긋나 404가 나거나,
드물게 그 표시 이름이 우연히 다른 유저의 username과 일치하면 엉뚱한 사람 프로필로 연결될 위험이
있었다. `followers/following` 페이지는 이미 원본 `u.username`을 그대로 쓰는 정상 패턴이라 이와
어긋났다. 부가로, `userMap`에 유저 레코드가 없는 경우(탈퇴 계정 등)도 `nameOf()`가 `'익명'`을
반환해 존재하지 않는 라우트로 연결될 위험이 있었다.

수정 내용:
- `route.ts`의 `RankingEntry`/`AchievementEntry`를 `displayName`(표시용, 기존 `nameOf()` 결과)과
  `username`(라우팅용, `users.username` 원본 컬럼값, 유저 레코드가 없으면 `null`)으로 분리했다.
  새 `usernameOf(userId)` 헬퍼로 원본 컬럼값만 뽑아 `username` 필드에 담고, 화면 표시 문구는
  전부 `displayName`으로 옮겼다.
- `MissionStatusClient.tsx`의 두 인터페이스도 동일하게 `displayName`/`username: string | null`로
  맞추고, 포디엄(`PodiumColumn`)·`RankingListRow`·`MyRankCard`·`AchievementRow`의 노출 텍스트를
  전부 `displayName`으로 교체했다. `href`는 `entry.username ? `/${entry.username}` : undefined`
  형태로 조건부 배선해, 원본 username이 없는 경우(탈퇴 계정 등) `ListRowCard`가 `href` 없이
  비인터랙티브 카드로 렌더되도록 방어했다.
