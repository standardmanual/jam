# [UI] 배지 트리 — 획득 표시·정렬·잠금칩 문구 개선

## 배경 / 문제 정의

`/badges/tree`(티켓 20260831_2208, 2026-08-31 프로덕션 배포 완료)의 게이트 리뷰·개선 리뷰에서
나온 발견사항 중 사용자가 반영을 승인한 3건을 처리한다.

1. **미획득 배지 시각적 구분이 없다.** 이 화면은 `badges`·`missions`만 조회하고 유저의 실제
   획득 여부(`user_activity_badges`)를 전혀 조회하지 않아, 모든 배지 카드가 항상 컬러로
   렌더링된다. `/badges`·`/badges/[id]`는 이미 이 조회를 하고 `BadgeGridCard`에 `earned` prop을
   넘겨 미획득 배지를 흑백·반투명 처리한다 — 스킬트리도 "내가 어디까지 왔는지"를 보여주는 게
   본질이므로 동일하게 맞춘다.
2. **D01~D11·트로피 매트릭스(걷기 전용 32종, "선행 조건 없이 얻는 배지" 섹션) 정렬이 가나다순이라
   성장 서사가 깨진다.** `src/lib/badgeTree.ts`의 `independentFamilies.sort((a, b) =>
   a.name.localeCompare(b.name, 'ko'))`가 원인. 이름 자체가 "첫 발자국→일주일의 증인→…→
   천일의 방랑자"라는 누적일수 순서를 담고 있는데(`Service Plan/Specs/Content/
   ACTIVITY_BADGES.md` D01~D11·트로피 매트릭스 표) 가나다순으로 섞인다.
3. **잠금칩 문구 조사 누락.** `d.badges.treeLockBadgeHint`("{name} 획득하면 열려요")가 목적격
   조사(을/를) 없이 배지 이름 뒤에 바로 동사가 붙어 부자연스럽다("동네 산책러 획득하면
   열려요"). 기존 `missions.lockedHint`는 고정 명사 "배지를"을 붙여 어떤 이름이 와도 조사
   문제가 안 생기게 했다 — 동일 패턴으로 맞춘다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `jam-web/src/app/(main)/badges/tree/page.tsx`: `badges/page.tsx`(27~38행)와 동일하게
  `user_activity_badges`를 `user_id`로 조회해 획득한 `badge_id` 집합을 만들고, 클라이언트
  컴포넌트에 내려준다. 삭제된 배지(`badges.deleted_at`) 제외 로직도 동일하게 맞춘다.
- `jam-web/src/components/badges/BadgeTreeFamily.tsx`: 등급 카드마다 자신의 `badges.id`가
  획득 집합에 있는지로 `BadgeGridCard`의 `earned` prop을 계산해 넘긴다
  (`earned={earnedBadgeIds.has(variant.id)}`, 지금은 prop 자체를 안 넘겨 기본값 `true`로
  항상 컬러 렌더링됨).
- `jam-web/src/lib/badgeTree.ts`: `independentFamilies` 정렬을
  `Specs/Content/ACTIVITY_BADGES.md`의 실제 서술 순서(D01→D11, 그다음 트로피 매트릭스
  T01·T02·T03…T18·T20·T22·T23 — T19·T21은 결번)로 고정한 순서 배열
  (`INDEPENDENT_BADGE_ORDER: string[]`, 배지 이름 기준) 기준 정렬로 교체.
  이름이 배열에 없는 경우(향후 신규 독립 배지 추가 시)를 대비해 배열에 없는 항목은 뒤로 보내는
  fallback을 둔다(에러로 죽지 않게).
- `jam-web/src/lib/i18n/ko.ts`: `treeLockBadgeHint`를 `'{name} 배지를 획득하면 열려요'`로 수정
  (`missions.lockedHint`와 동일한 "배지를" 고정 명사 패턴).

### UI/UX 관점

- 미획득 배지 카드의 시각 처리는 `BadgeGridCard`가 이미 갖고 있는 흑백·반투명 로직을 그대로
  쓴다(신규 스타일 추가 없음).
- 잠금칩(🔒)과 흑백 처리가 동시에 나타나는 카드가 생길 수 있는데, 이는 의도된 상태다 —
  "아직 조건도 못 채웠고 선행조건도 안 열림"이라는 두 가지 서로 다른 정보(진행도 vs 해금
  경로)를 동시에 보여주는 것이므로 하나로 합치지 않는다.
- 이번 변경은 신규 컴포넌트가 없다 — 기존 재사용 판정(BadgeGridCard/SlidingTabs/RarityBadge)을
  그대로 유지한다.
- UX Writing: 잠금칩 문구만 변경, `Service Plan/Specs/UX_WRITING_GUIDELINE.md`의 고정 패턴
  준수 여부를 완료 기록에 다시 체크한다.

## 구현 계획

1. `page.tsx`에 `user_activity_badges` 조회 추가 → `earnedBadgeIds: Set<string>` 계산 →
   `BadgeTreeClient`·`BadgeTreeFamily`로 전달.
2. `BadgeTreeFamily.tsx`에서 `BadgeGridCard`에 `earned` prop 배선.
3. `badgeTree.ts`에 `INDEPENDENT_BADGE_ORDER` 배열 추가, `independentFamilies` 정렬 로직 교체.
4. `ko.ts`의 `treeLockBadgeHint` 텍스트 수정.
5. 로그인 상태로 로컬에서 일부 배지를 획득/미획득 섞인 계정으로 실제 흑백 처리가 되는지
   스크린샷 확인. `type='activity'` 조회 결과가 많아(160개) 획득/미획득이 섞인 실제 유저를
   Supabase에서 찾거나, 테스트 계정에 임시로 몇 개 지급해 확인(원복 필요 없으면 read-only
   확인만으로 충분 — 기존 획득 이력이 있는 계정으로 충분히 확인 가능한지 먼저 확인).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. `page.tsx`에서 `user_activity_badges`를 `user_id`로 조회(`badges/page.tsx`와 동일 패턴,
   `badge:badges(deleted_at)` 조인으로 소프트 삭제 배지 제외)해 `earnedBadgeIds: string[]`을
   계산, `BadgeTreeClient`에 prop으로 내려줌. 서버→클라이언트 컴포넌트 경계는 배열로 넘기고,
   `BadgeTreeClient` 내부에서 `useMemo`로 `Set`을 만들어 `BadgeTreeFamily`(클라이언트 간 전달이라
   `Set` 그대로 넘겨도 안전)에 전달.
2. `BadgeTreeFamily.tsx`가 `earnedBadgeIds: Set<string>` prop을 받아 각 등급 카드마다
   `earned={earnedBadgeIds.has(variant.id)}`로 `BadgeGridCard`에 배선. 신규 스타일 없이 기존
   흑백/반투명 로직 그대로 활용.
3. `badgeTree.ts`에 `INDEPENDENT_BADGE_ORDER`(D01~D11 + 트로피 매트릭스 T01~T18·T20·T22·T23,
   `Specs/Content/ACTIVITY_BADGES.md` 서술 순서 그대로) 추가, `independentFamilies` 정렬을
   가나다순에서 이 배열 인덱스 기준으로 교체. 배열에 없는 이름(향후 신규 독립 배지)은
   `indexOf === -1` → 배열 길이값으로 취급해 맨 뒤로 보내는 fallback 적용(에러 없이 동작).
4. `ko.ts`의 `treeLockBadgeHint`를 `'{name} 배지를 획득하면 열려요'`로 수정
   (`missions.lockedHint`의 "배지를" 고정 명사 패턴과 통일).

### 주요 의사결정 / 핵심 메모
- `earnedBadgeIds`를 서버→클라이언트 경계에서 `Set`이 아닌 `string[]`로 넘긴 이유: 이
  코드베이스에서 서버 컴포넌트가 클라이언트 컴포넌트에 `Set` 인스턴스를 직접 prop으로
  넘기는 선례가 없어(전부 배열/plain object로 변환 후 전달), 안전하게 배열로 넘기고
  `BadgeTreeClient`(클라이언트 컴포넌트) 내부에서 `useMemo`로 `Set`을 구성해 그 아래
  클라이언트 컴포넌트 간에만 `Set`을 전달하도록 함.
- 소프트 삭제 배지 필터(`badge:badges(deleted_at)` 조인)는 `badges` 트리 자체가 이미
  삭제된 배지를 제외하고 빌드되므로 실질적으로는 결과에 영향이 없지만, 티켓 요구사항
  ("삭제된 배지 제외 로직도 동일하게 맞춘다")과 `badges/page.tsx`와의 패턴 일관성을 위해
  그대로 포함함.
