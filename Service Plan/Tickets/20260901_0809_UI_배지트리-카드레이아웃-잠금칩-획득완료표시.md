# [UI] 배지 트리 카드 레이아웃·잠금칩 획득완료 표시

## 배경 / 문제 정의

사용자가 `/badges/tree`(티켓 20260831_2208·2250) 실화면을 보고 스크린샷과 함께 3가지 UI 수정을
직접 요청했다. 경미 수정(2~3파일, 로직 소폭 추가, 오타 수준 아님)이라 `/jam-work` 풀 파이프라인
없이 오케스트레이터가 직접 처리한다.

## 상세 요구사항

1. **배지 이름·등급 표시를 설명 위로 이동**: 첨부 스크린샷처럼 카드 안에서 "등급 pill →
   배지 이름(볼드) → 설명" 순으로 보이게 한다. 기존에는 `BadgeGridCard`를 그대로 써서
   썸네일 아래(왼쪽 컬럼)에 이름·pill이 있고, 설명은 오른쪽 컬럼에 별도로 있었다.
2. **선행 배지를 이미 획득한 경우 "OOO 배지 획득 완료"로 표기**: 지금까지는 선행조건 충족
   여부와 무관하게 항상 "OOO 배지를 획득하면 열려요"만 보였다. (미션 게이팅은 이번 범위 아님 —
   "선행 배지"라고 명시했으므로 배지-대-배지 OR 게이팅만 대상.)
3. **선행 배지명 볼드 처리**: 잠금칩 문구 안의 배지/미션 이름을 볼드로 강조.

## 구현 계획

- `jam-web/src/components/badges/BadgeTreeFamily.tsx`: `BadgeGridCard` 사용을 중단하고
  썸네일(Link+Image, 기존과 동일한 흑백/반투명·터치타겟)만 직접 구성. 텍스트 컬럼 최상단에
  `RarityBadge` → 볼드 이름(Link) → 설명 → 잠금칩 순으로 배치.
- `jam-web/src/lib/badgeTree.ts`: `BadgeTreeLock`을 `{label, href}`에서
  `{kind: 'badge'|'mission', name, href, fulfilled}`로 확장. `buildBadgeActivityTrees`에
  `earnedBadgeIds: Set<string>` 3번째 인자 추가 — 배지-게이팅 잠금(`kind:'badge'`)마다 선행
  배지 family의 어느 등급이든(OR 규칙, 엔진과 동일) `earnedBadgeIds`에 있으면 `fulfilled: true`.
  미션 게이팅(`kind:'mission'`)은 `fulfilled: false` 고정(이번 범위 아님).
- `jam-web/src/components/badges/BadgeTreeLockChip.tsx`: `label` 문자열 대신 구조화된
  `{kind, name, href, fulfilled}`를 받아 이름을 `<strong>`으로 볼드 처리. `kind==='badge' &&
  fulfilled`면 `treeLockBadgeFulfilled`("{name} 배지 획득 완료") 템플릿 + 체크 아이콘,
  아니면 기존 잠금 아이콘 + 기존/미션 템플릿.
- `jam-web/src/lib/i18n/ko.ts`: `treeLockBadgeFulfilled` 신규 키 추가. `treeLockMissionHint`의
  플레이스홀더를 `{title}`→`{name}`으로 통일(노출 문구 자체는 불변, 코드 일관성 목적).
- `jam-web/src/app/(main)/badges/tree/page.tsx`: 기존에 계산하던 `earnedBadgeIdSet`을
  `buildBadgeActivityTrees` 호출에 그대로 전달(신규 조회 없음).

### 구현 내용 요약
계획대로 구현. `npx tsc --noEmit` 에러 0건, `eslint`(수정 파일 전체) 경고·에러 0건. 로컬
`next dev`에 `/api/dev-login`(dev-tester)로 로그인 후 `/badges/tree` 걷기 탭에서 실제 확인:

  레이아웃과 일치).
- "산책의 명상가"·"루틴의 수호자"의 배지-게이팅 잠금칩이 이 계정이 이미 보유한 "동네
  산책러"·"밤의 보행자"·"산책의 명상가"에 대해 체크 아이콘 + "OOO 배지 획득 완료"(볼드 이름)로
  정확히 바뀜을 확인.
- 종목 대표배지(미션 게이팅) 잠금칩은 기존과 동일하게 자물쇠 아이콘 + "'OOO 레벨업' 미션을
  완료하면 열려요"(볼드 이름)로 문구 불변 확인 — 미션 게이팅은 이번 범위가 아니므로 항상
  미충족으로 유지됨을 코드로 확인(`fulfilled: false` 고정).

### 주요 의사결정 / 핵심 메모
- 선행조건 OR 충족 판정은 "선행 배지 family의 어느 등급이든 보유"를 기준으로 했다 — 배지
  엔진의 크로스게이트 규칙(`Specs/BadgeEngine/BADGE_ENGINE_UNIFIED.md`: "이름 기반: 해당
  배지의 어느 등급이든 소유 시 통과")과 동일하게 맞춘 것으로, 임의 판단이 아니다.
- 미션 게이팅 잠금칩은 "선행 배지"라는 사용자 표현 범위 밖으로 보고 그대로 두었다. 필요하면
  후속 요청으로 별도 처리.
- `BadgeGridCard`(서비스 공용 컴포넌트)는 건드리지 않았다 — 그리드 레이아웃이 필요한 다른
  화면(`/badges`, `/badges/[id]` 선행배지 그리드)에 영향 없음.
