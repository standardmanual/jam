# [UI] 투데이 "친구 활동" 카드 — 레이블·단수 문구·레이아웃 수정

## 배경 / 문제 정의
사용자가 투데이 홈 상단 "오늘의 현황" 스트립 우측 카드("친구 활동")에 3가지 수정을 요청했다.

레이블을 "팔로워"로 바꿔달라는 최초 요청이 있었으나, 이 카드는 실제로 **내가 팔로우하는
사람(팔로잉)** 의 오늘 배지 획득 활동만 집계한다 — "팔로워"(나를 팔로우하는 사람)로 바꾸면
용어와 실제 동작이 어긋난다. 사용자에게 확인한 결과 **"팔로잉 소식"** 으로 확정했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 카드 레이블(`d.todayStatus.friendActivityLabel`) `'친구 활동'` → `'팔로잉 소식'`
- 오늘 배지를 획득한 팔로잉이 **정확히 1명**일 때 표시 문구를 `'{name}님이 오늘 배지를
  획득했어요!'`로 변경 (`name`은 `getDisplayName()` 규칙과 동일하게 `display_name` 우선,
  없으면 `username`). 2명 이상일 때 기존 `'친구 {count}명이 오늘 배지를 획득했어요'` 문구는
  유지.
- `getTodayRightStatus()`(`src/lib/today/status.ts`)가 1명 케이스의 표시 이름을 계산해
  `TodayRightStatus`의 `friend_activity` variant에 실어 보낸다 — `users` 조회 select에
  `display_name` 추가.

### UI/UX 관점
- 아바타(친구 프로필 이미지) 스택을 텍스트 위(세로 배치)가 아니라 **텍스트 왼쪽 열**에 배치
  (가로 배치: 아바타 — 텍스트).
- `no_following`(팔로잉 없음) 상태의 아이콘+텍스트 세로 배치는 이번 범위에 포함하지 않음
  (사용자 요청 대상은 아바타 노출 케이스만).

## 구현 계획
1. `src/lib/i18n/ko.ts` — `friendActivityLabel` 텍스트 교체, `friendActivitySingle` 키 추가.
2. `src/lib/today/status.ts` — `users` select에 `display_name` 추가, `friend_activity`
   variant에 `singleFriendName: string | null` 필드 추가(count===1일 때만 값, 그 외 null).
3. `src/app/(main)/TodayStatusStrip.tsx`의 `RightCell` — `count === 1 && singleFriendName`이면
   `friendActivitySingle` 문구 사용, 아바타+텍스트를 `flex-row items-center`로 재배치.
4. 로컬에서 팔로잉 0명/1명/2명 이상 각 상태를 스크린샷으로 확인.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
계획대로 구현. `getTodayRightStatus()`가 `users` 조회에 `display_name`을 추가로 select해
`friend_activity` variant에 `singleFriendName`(`getDisplayName()` 규칙: display_name 우선,
없으면 username)을 함께 실어 보내도록 했다. `RightCell`은 `count === 1 && singleFriendName`일
때만 `friendActivitySingle` 문구를 쓰고, 그 외(2명 이상 또는 이름 조회 실패)에는 기존
`friendActivity` 문구를 그대로 쓴다. 아바타 스택+텍스트는 기존 `flex-col`(세로 배치)에서
한 단계 감싸는 `flex items-center` 행으로 바꿔 아바타가 텍스트 왼쪽에 오도록 재배치했다.

### 주요 의사결정 / 핵심 메모
- 최초 요청은 레이블을 "팔로워"로 변경하는 것이었으나, 이 카드가 팔로잉(내가 팔로우하는
  사람) 기준으로 동작한다는 점을 사용자에게 AskUserQuestion으로 확인시켜 "팔로잉 소식"으로
  조정했다 — 용어와 기능 불일치 방지.
- 표시 이름은 화면 전반의 표준 유틸 `getDisplayName()`(display_name 우선, 없으면 username)을
  그대로 재사용했다 — 이 카드만의 별도 규칙을 만들지 않음.

### 잔여 이슈
- `friend_activity` 분기(팔로잉 1명/2명 이상)의 실제 화면 시각 확인은 staging 배포 후
  실사용자 데이터로 확인 권장(위 테스트 결과 참고).

### 추가 수정 (2026-09-01, 같은 날 후속 요청)
사용자가 "텍스트 말줄임을 하면 안된다"고 지적했다. `RightCell`의 팔로잉 소식 문구
(`{name}님이 오늘 배지를 획득했어요!` 등)에 걸어뒀던 `truncate`(말줄임표) 클래스를
제거했다 — 이제 문구가 길면 줄바꿈되며, 카드는 `min-h-[92px]`라 내용이 늘어나면 자연히
높이도 늘어난다. `min-w-0 flex-1`은 유지(아바타 옆 flex 행에서 텍스트가 정상적으로
줄바꿈되도록 하는 데 필요). `LeftCell`의 기존 `truncate`(내 진행도 카드)는 이번 요청
범위가 아니라 건드리지 않았다.
