# [UI] 하단 탭바 — 활성탭 점 제거, 슬라이딩 모션 추가

## 배경 / 문제 정의
사용자가 하단 탭바(`TabBar`)에 두 가지 수정을 요청했다.
1. 활성 탭 아이콘 아래의 점(`TabActiveDot`)을 제거한다.
2. 활성 탭 배경 필(티켓 20260901_1030에서 추가된 64×48 캡슐)에 미션 페이지
   진행중/참가중/종료 탭(`SlidingTabs`)과 같은 슬라이딩 모션을 추가한다.

현재 활성 배경 필은 각 탭(`Link`)마다 `active && <span>...</span>`로 조건부 렌더링되는
방식이라 탭 전환 시 즉시 스냅(인스턴트 전환)한다 — 이전 탭에서 사라지고 다음 탭에서
나타날 뿐, 둘 사이를 미끄러지는 모션이 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

**1) 점 제거**
- `src/components/ui/TabBar.tsx`: `TabActiveDot` 컴포넌트, `useDebouncedBadgeOpen` 훅,
  `<TabActiveDot active={active} />` 사용부를 전부 삭제한다.
- `design-system/components/navigation/TabBar.jsx`: 활성 점 `<span>`(하단 4×4 원,
  opacity 토글) 삭제.
- `src/components/transitions.css`: `.t-badge.jam-tabbar-dot` 스코프 규칙만 삭제한다.
  **`.t-badge`/`.t-badge-dot`/`@keyframes t-badge-slide-in`은 삭제하지 않는다** —
  `.jam-bell-dot`(알림 벨 점)이 같은 공용 클래스를 쓰고 있어 공유 자산이다.

**2) 슬라이딩 모션**
- `TabBar`는 `(main)/layout.tsx`에 마운트되어 5개 탭 간 라우트 전환 중에도
  **언마운트되지 않는 persistent layout**이다 — 이는 `SlidingTabs.tsx`가 컴포넌트
  내부 `value` prop 변화에 반응하는 것과 동일한 조건을 만족시킨다(`usePathname()`이
  바뀔 때 = `value`가 바뀔 때). `SlidingTabs.tsx`의 `moveTo()` 패턴을 그대로 차용해
  TabBar 내부에 이식한다:
  - 탭마다 개별 배경 `<span>`을 조건부 렌더링하는 현재 방식을 버리고, `nav` 안에
    **단일 공유 pill** `<span ref={pillRef}>`을 두고 활성 탭의 `offsetLeft`/폭 중앙에
    맞춰 `translateX(...)`로 이동시킨다(크기는 고정 64×48이므로 각 탭 슬롯 중앙에
    오도록 `tab.offsetLeft + (tab.offsetWidth - 64) / 2` 계산).
  - 최초 마운트 시(`hasPositionedRef.current === false`)에는 `transition: none`으로
    스냅시키고, 이후 활성 탭이 바뀔 때만(라우트 전환) CSS 트랜지션으로 슬라이드한다
    — `SlidingTabs.moveTo(key, animate)`와 동일한 분기.
  - 활성 탭이 없는 페이지(프로필/검색/알림함 등, `isActive()`가 모든 탭에 대해
    false)에서는 필을 숨긴다(현재 동작과 동일하게 유지) — opacity 0 또는 미배치로
    처리.
  - `ResizeObserver`(뷰포트 폭 변화)·웹폰트 로드 후 재배치도 `SlidingTabs.tsx`와
    동일하게 무애니메이션으로 처리해, 탭 폭이 바뀌어도 필이 어긋나지 않게 한다.
  - `prefers-reduced-motion: reduce`를 존중해 트랜지션을 끈다(순간이동).
  - 시각(크기·모양·색)은 기존 그대로 유지: `w-16 h-12 rounded-full`,
    `background: rgba(0,0,0,0.08)`.
- 서비스(`src/components/ui/TabBar.tsx`)·MODULAR(`design-system/.../TabBar.jsx`)
  병존 구현 양쪽 모두 동일하게 구현한다.

## 구현 계획

### 1.5 UI 탐색·재사용 판정 (오케스트레이터 결정)
- `SlidingTabs` **컴포넌트 자체는 재사용하지 않는다** — `value`/`onChange` 기반
  단일 페이지 탭 전환 모델이라 `Link` 기반 라우트 탐색(TabBar)과 프로퍼티 모델이
  맞지 않는다(TabBar는 페이지 이동이지 상태 전환이 아님).
- `SlidingTabs.tsx`의 **JS 포지셔닝 패턴만 차용**한다(단일 pill + offsetLeft/offsetWidth
  측정 + CSS transform 트랜지션 + 첫 배치 무애니메이션 + ResizeObserver 재배치).
  TabBar 자체가 이미 "병존 구현"으로 분류돼 있으므로 새 MODULAR 컴포넌트를 만들지
  않고 TabBar 내부에 서비스 전용으로 구현한다.

### 구현 단계
1. `src/components/ui/TabBar.tsx`: `TabActiveDot`/`useDebouncedBadgeOpen` 삭제.
2. `src/components/ui/TabBar.tsx`: 단일 pill 방식으로 활성 배경 리팩터
   (`SlidingTabs.tsx`의 `moveTo`/`useLayoutEffect`/`ResizeObserver` 패턴 차용).
3. `design-system/components/navigation/TabBar.jsx`: 점 삭제 + 동일한 pill 로직
   포팅(React state/ref 기반, DS 컴포넌트도 클라이언트 컴포넌트이므로 가능).
4. `src/components/transitions.css`: `.t-badge.jam-tabbar-dot` 스코프만 삭제.
5. 로컬에서 투데이→배지→드랍→미션→인벤토리 순서로 탭을 눌러 필이 미끄러지듯
   이동하는지, 점이 완전히 사라졌는지, 활성 탭이 없는 페이지(예: 프로필)에서
   필이 숨는지 스크린샷/화면 녹화로 확인.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. 점 제거: `TabBar.tsx`의 `TabActiveDot`/`useDebouncedBadgeOpen`, `TabBar.jsx`의 하단 4×4
   점 `<span>`을 삭제. `cssDurationMs` import(점 전용)도 함께 제거.
2. 슬라이딩 모션: 탭마다 조건부 렌더링하던 배경 필을 `nav` 안 단일 공유 `<span ref={pillRef}>`로
   교체. `SlidingTabs.tsx`의 `moveTo(key, animate)` 패턴(첫 배치 무애니메이션 스냅 →
   `pill.offsetWidth` 강제 reflow → transition 복원, 이후 트랜지션으로 트윈)을 그대로 이식.
   - `TabBar.tsx`: `activeHref = tabs.find(isActive)?.href ?? null`을 SlidingTabs의 `value`에
     대응시켜 사용(Link 기반이라 `onChange` 없이 `usePathname()` 변화가 트리거).
   - `TabBar.jsx`: 이미 `active`/`onChange` controlled prop 모델이라 SlidingTabs 패턴을 그대로
     적용(코드 구조가 서비스판보다 SlidingTabs.tsx에 더 가까움).
   - 활성 탭 없음(href/tab 못 찾음) → `pill.style.opacity = '0'`으로 숨김.
   - `ResizeObserver`(nav 관찰) + `window resize` + `document.fonts.ready`로 무애니메이션
     재배치. `activeHref`를 ref로 미러링해 리사이즈 이펙트 deps에서 제외(SlidingTabs.tsx와
     동일 이유 — observe() 최초 발화가 방금 트리거된 트윈을 캔슬하는 것 방지).
   - CSS: 신규 `.jam-tabbar-pill` 클래스(`transform`/`opacity`에 `--tabs-dur`/`--tabs-ease`
     트랜지션, `prefers-reduced-motion: reduce`에서 `transition: none !important`).
     DS는 동일 값을 `--ease-smooth-out`(=cubic-bezier(0.22,1,0.36,1), `--tabs-ease`와 동일 값)로
     맞춘 `.ds-tabbar-pill`을 `STATIC_CSS`에 추가.
3. `.t-badge.jam-tabbar-dot` 스코프 규칙만 삭제. `.t-badge`/`.t-badge-dot`/
   `@keyframes t-badge-slide-in`/`.jam-bell-dot`(알림 벨, 공유 자산)은 그대로 유지.

### 주요 의사결정 / 핵심 메모
- `TabBar.tsx`는 Link 기반 라우트 탐색이라 SlidingTabs처럼 명시적 `onChange`가 없다 —
  대신 `usePathname()`/`useSearchParams()`로 계산한 `activeHref`를 `value`로 취급해
  `useLayoutEffect` deps로 사용. `isActive()` 로직(다른 유저 프로필 맥락, 배지발
  파생 페이지 등)은 그대로 유지, pill 포지셔닝만 새로 얹었다.
- pill 크기(64×48)는 Tailwind 클래스(`w-16 h-12`)와 JS 상수(`PILL_WIDTH = 64`)로 이중
  선언된다 — 하나만 바꾸면 중앙 정렬이 어긋나므로 두 값을 함께 수정해야 한다는 점을
  주석으로 남겼다(DS 쪽도 동일).
