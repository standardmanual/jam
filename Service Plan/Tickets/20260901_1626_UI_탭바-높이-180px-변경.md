# [UI] 하단 탭바 높이 180px 변경

## 배경 / 문제 정의
사용자가 하단 탭바(`TabBar`)의 높이값을 180px로 변경해달라고 요청했다. 활성 배경 필
(64×48 캡슐)의 높이는 그대로 유지해야 한다는 조건이 명시됐다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `src/components/ui/TabBar.tsx`: `nav`의 `h-16`(64px) → `h-[180px]`.
- `design-system/components/navigation/TabBar.jsx`: `nav` 인라인 스타일의 `height: 64` →
  `height: 180`.
- 활성 배경 필(`PILL_WIDTH`/`h-12`·`height: 48`)은 변경하지 않는다 — 필은 `top-1/2` +
  `translateY(-50%)`로 nav 높이와 무관하게 항상 수직 중앙에 위치하므로, nav 높이만 바꿔도
  필 크기·중앙 정렬 로직에는 영향이 없다.

## 구현 계획
1. `TabBar.tsx`·`TabBar.jsx`의 nav 높이 값만 교체(병존 구현 양쪽 동기화).
2. 로컬에서 스크린샷으로 확인.

### 주요 의사결정 / 핵심 메모

### 잔여 이슈
-

### 추가 수정 (2026-09-01, 같은 날 후속 요청)
사용자가 180px가 과하다고 판단했는지 곧바로 59px 요청 후 취소하고 최종 49px로 정정
요청했다. nav 높이를 180px → 49px로 재조정(`h-[49px]` / `height: 49`). 활성 배경 필
(48px)보다 1px 큰 값이라 필이 여전히 컨테이너 안에 들어가며, 필 크기·중앙정렬 로직은
이번에도 무변경. 로컬 스크린샷으로 원래(64px)와 비슷한 컴팩트한 높이로 복귀했음을 확인.

### 추가 수정 2 (2026-09-01, 같은 날 재차 요청)
사용자가 스크린샷과 함께 "활성배경 필의 좌우 라운드 모양과 탭바의 좌우 라운드가 균일한
반원이 되도록 해달라 — 값이 달라서 형태가 찌그러져 있다"고 지적했다.

**원인**: nav(탭바 전체)와 필(활성 배경)이 둘 다 `rounded-full`/`var(--radius-pill)`
(9999px)로 "완전히 둥근 캡슐"을 의도했지만, 이 값은 각 요소 **자기 자신의 높이** 기준으로
auto-clamp된다. 필은 고정 48px 높이라 항상 반경 24px로 클램프되는 반면, nav는 높이가
바뀔 때마다(64→180→49→52px 등) 반경도 함께 바뀌어(각각 32/90/24.5/26px) 필의 24px와
어긋났다 — "값이 달라서" 곡률이 다르게 보인 정확한 원인.

**해결**: nav의 `border-radius`를 auto-clamp 토큰이 아니라 필과 동일한 고정값
(`PILL_RADIUS = PILL_HEIGHT / 2 = 24`)으로 직접 지정했다. 요청받은 높이 52px 자체는
유지하되(52/2=26 ≠ 24이므로 nav 자체만 놓고 보면 엄밀한 최대-라운드는 아니지만 2px
차이는 시각적으로 감지되지 않는 수준), 필과 정확히 같은 24px 반경을 공유하게 해 두 캡슐의
곡률이 실측으로 일치하도록 했다(`getComputedStyle`로 nav `border-radius: 24px` 확인,
필은 여전히 9999px 지정값이 자기 48px 높이에서 24px로 렌더 클램프되어 동일).

- 변경 파일: `jam-web/src/components/ui/TabBar.tsx`(`PILL_HEIGHT`/`PILL_RADIUS` 상수 추가,
  nav `borderRadius: PILL_RADIUS`로 교체), `jam-web/design-system/components/navigation/TabBar.jsx`(동일)
- `npx tsc --noEmit -p .` 에러 0건, `npm run lint` 0 errors(기존과 동일)
- 로컬 스크린샷 + `getComputedStyle` 실측으로 nav `border-radius: 24px` 확인(콘솔 에러 없음)
