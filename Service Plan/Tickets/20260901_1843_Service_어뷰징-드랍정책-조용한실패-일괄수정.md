# [Service] 어뷰징·드랍 정책 영역 조용한 실패(에러 삼킴) 일괄 수정

## 배경 / 문제 정의
티켓 [20260831_1118](20260831_1118_Service_어드민-드랍정책-저장-조용한실패-upsert에러삼킴.md)에서
어드민 드랍정책 저장 무음 실패를 고치는 과정에 같은 "조용한 실패" 패턴이 5곳 더 있음을
발견해 "범위 밖 발견물"로 기록했다(후속 티켓으로 미분리 상태). 또한 티켓
[20260831_1149](20260831_1149_Service_어드민-어뷰징정책-저장-조용한실패-upsert에러삼킴.md)/
[20260831_1259](20260831_1259_Service_어뷰징정책-폴백이-섀도우밴-판정을-뒤집음.md)의
"미분리(기록만)" 항목 중 `shadow-ban.ts`의 밴 부여·해제 무음 실패와
`getUserBanLevel()`의 무검증 캐스팅도 같은 파일군(`abusing/`, `drop-engine/`)에 속하는
동일 계열 결함이라 한 티켓으로 묶어 처리한다.

패턴: Supabase 쿼리의 `error`를 확인하지 않고 버리거나, 응답을 무조건 `{ ok: true }`로
반환해 저장·조회 실패가 "성공" 또는 "빈 값"으로 위장되는 문제. 어뷰징 판정처럼 실패가
정책 오적용으로 이어지는 영역에서 특히 위험하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `combine/policy.ts:50` — 에러 삼킴 확인 후 적절히 노출/처리
- `drop-engine/index.ts:422` — 동일
- `poi/search-cache.ts:47` — 동일
- `abusing/poi-block.ts:39·45` — 동일
- `abusing/shadow-ban.ts:70·78` — 동일
- `abusing/shadow-ban.ts`의 `applyBan`·`removeBan`·`logAbusingEvent` — `error`를 버리는
  지점 확인, `AbusingClient`에 else 분기(실패 시 사용자/운영자에게 알림) 추가
- `getUserBanLevel()` — DB `ban_level`을 검증 없이 `as BanLevel`로 캐스팅하는 부분에
  방어 코드 추가 (현재는 마이그레이션 010의 CHECK 제약이 막고 있어 실현 불가하나, 제약이
  완화될 경우 `BAN_RATE_KEY[banLevel]`가 undefined가 되어 `shouldAllowDrop`에서
  TypeError가 드랍 경로로 전파되는 것을 방지)
- 읽기 로더의 "키 누락 무음 폴백" 패턴도 함께 점검

## 구현 계획
- 각 지점의 실제 실패 시나리오를 먼저 확인(어떤 값으로 폴백되는지, 그게 안전한
  기본값인지)한 뒤, 안전하지 않은 지점은 에러를 로깅하고 명시적으로 실패를 알리도록 수정
- `shouldAllowDrop`/`getUserBanLevel` 등 드랍 판정 경로에 있는 지점은 fail-open/fail-closed
  방향을 신중히 결정(어뷰징 판정은 fail-closed가 기본, 20260831_1259의 §5 결정 참고)
- 티켓 20260831_1118·1149·1259의 "완료 기록"에 남은 배경 설명을 우선 참고
