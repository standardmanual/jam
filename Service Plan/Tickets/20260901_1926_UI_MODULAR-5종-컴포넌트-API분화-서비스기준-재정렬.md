# [UI] MODULAR 5종 컴포넌트 API 분화 — 서비스 기준으로 재정렬

## 배경 / 문제 정의

`/jam-ds` 첫 정리(티켓 20260901_1854)에서 `ds:check` 의 `PROPS_DRIFT` 로 드러났다.
서비스 UI 가 계속 발전하는 동안 MODULAR 쪽 구현이 따라오지 못해, 같은 이름의 컴포넌트가
**서로 다른 API** 를 갖게 됐다.

| 컴포넌트 | 서비스에만 있는 props | MODULAR 타입에만 |
|---|---|---|
| BottomSheet | `onClose` `detent` `footer` `topGapPx` `footerBottomInset` `contentScrollable` | `onDismiss` |
| SlidingTabs | `items` `variant` `size` `shape` `block` `outlined` `tabClassName` | `tabs` `active` |
| TopNav | `backHref` `headerStyle` `logo` | `logoSlot` `centerSlot` `avatarSlot` `titleSize` `titleWeight` `titleLineHeight` `titleTracking` |
| TabBar | `username` | `active` |
| BadgeGridCard | `highlighted` | — |

특히 `BottomSheet` 는 콜백 이름부터 다르고(`onClose` ↔ `onDismiss`), `SlidingTabs` 는
데이터 prop 이름과 변형 체계가 통째로 다르다. **Storybook 카탈로그를 보고 재사용을 판단하면
실제 서비스 컴포넌트와 맞지 않는 API 를 기대하게 된다** — `/jam-design` 의 "탐색 → 재사용"
선순환이 깨지는 지점이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **기준은 서비스 UI** (`src/components/ui/*.tsx`). MODULAR 을 여기 맞춘다
  (기준값 방향은 `/jam-ds` 스킬 0절 참조)
- `.d.ts` 만 고치면 타입과 구현이 어긋나 더 나빠진다. **`.jsx` 구현까지 함께** 바꾼다
- 컴포넌트를 바꾸면 대응 `*.stories.tsx` 도 새 API 로 갱신한다

### 검증

- `cd jam-web && npm run ds:check` 의 `PROPS_DRIFT` 가 해당 컴포넌트에서 사라질 것
- Storybook(`npm run storybook`, :6006)에서 각 Story 가 실제로 렌더될 것
  — 20260901_1854 에서는 `node_modules` 가 없어 이 검증을 못 했다

## 구현 계획

컴포넌트당 독립적이므로 **하나씩 끊어서** 처리한다. 한 번에 5개를 바꾸면 회귀 범위가 커진다.
분화 폭이 큰 순서로:

1. `SlidingTabs` — 데이터 prop·변형 체계 전면 재정렬
2. `TopNav` — 슬롯 방식(`*Slot`) ↔ 서비스 방식(`logo`/`backHref`) 중 서비스 기준 채택
3. `BottomSheet` — `onDismiss` → `onClose`, detent·footer 관련 props 추가
4. `TabBar` — `username` 추가, `active` 는 서비스가 pathname 으로 판단하는지 확인
5. `BadgeGridCard` — `highlighted` 추가

각 단계마다 Story 갱신 + `ds:check` 재실행.

## 완료 기록 *(작업 완료 후 작성)*

컴포넌트당 독립적으로 처리(SlidingTabs → TopNav → BottomSheet → TabBar → BadgeGridCard),
각 단계마다 `ds:check` 재실행으로 확인했다.

### 구현 내용

- **SlidingTabs** (병존 구현): `tabs`/`active` → `items`/`value`로 이름 변경, `variant`
  (`onSurface`/`onCard`)·`size`(`md`/`lg`/`xl`)·`shape`(`pill`/`card`)·`block`·`outlined`·
  `tabClassName` 추가. 서비스의 CSS 트랜지션 기반 슬라이딩 pill 애니메이션은 이식하지
  않고(범위 밖), 활성 탭을 채운 pill로 표시하는 기존 MODULAR 방식은 유지.
- **TopNav** (연결된 컴포넌트 — `src/components/ui/TopNav.tsx`가 `@ds/components/navigation/TopNav`를
  직접 렌더링): `logoSlot`→`logo`, `style`→`headerStyle`로 이름 정렬. `avatarSlot`은
  제거하고 `rightSlot` 컨테이너 안에서 바로 뒤에 이어붙이는 것으로 통합(같은 flex 컨테이너
  안 인접 위치라 시각적 변화 없음). `titleSize`/`titleWeight`/`titleLineHeight`/`titleTracking`
  4개 오버라이드 prop은 제거하고 서비스가 항상 넘기던 고정값(body 16px)을 DS 기본값으로
  흡수(모든 실사용처가 예외 없이 이 값을 오버라이드하고 있었음을 확인). `backHref` 추가
  (제공 시 `<a href>`로 렌더링 — 프레임워크 비종속 대안 경로. 실제 서비스 래퍼는 여전히
  서버 컴포넌트 호출처 제약 때문에 `onBack`(router.push 기반)을 사용). 실연결 컴포넌트라
  `src/components/ui/TopNav.tsx` 래퍼도 새 API에 맞춰 함께 수정(prop 이름 변경만, 동작 변경 없음).
  `centerSlot`(스트라바 동기화 버튼)은 도메인 결합 콘텐츠라 서비스 `TopNavProps`에 노출하지
  않고 DS 전용 slot으로 의도적으로 남김 — `ds:check`에 1건 남는 문서화된 예외.
- **BottomSheet** (병존 구현): `onDismiss`→`onClose`, `detent`(`compact`/`full`)·`footer`·
  `topGapPx`·`footerBottomInset`(`tabbar`/`safe-area`)·`contentScrollable` 추가. 서비스의
  드래그투클로즈 제스처는 "단순 스왑 금지" 원칙에 따라 이식하지 않음(기존 미구현 상태 유지,
  주석으로 명시).
- **TabBar** (병존 구현): `username` 추가 — DS는 Next.js 라우터가 없어 서비스처럼 pathname
  기반 활성 탭 판정을 재현할 수 없으므로 `data-username` 속성으로만 값을 반영. `active`는
  서비스가 외부 prop이 아니라 pathname으로 직접 판단함을 확인했고(요구사항의 "확인" 지시
  이행), MODULAR은 독립 카탈로그 컴포넌트라 controlled prop으로 계속 필요해 유지 — `ds:check`에
  1건 남는 문서화된 예외.
- **BadgeGridCard** (병존 구현): `highlighted`(inset 강조 링) 추가. 티켓 작성 이후
  서비스에 `onNavigate`(20260902_0923)가 추가돼 있어 현재 드리프트 기준으로 이것도 함께
  반영(href 모드 전용 클릭 핸들러).
