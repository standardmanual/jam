# [Admin] 컬렉션 상세·아이템배지상세 배경 편집 — 패턴/쉐이더 기능 제거, 배경색만 유지

## 배경 / 문제 정의

`/admin/badges`(아이템배지 도안), `/admin/itembooks`(컬렉션), `/admin/factions`(세계관) 세 화면은
공용 컴포넌트 `BackgroundGeneratorPreview.tsx`(`jam-web/src/app/admin/badges/BackgroundGeneratorPreview.tsx`)로
배경 편집 UI를 제공한다. 현재 배경 편집 방식은 두 가지다.

1. **단색** — `background_color` hex 값 하나만 저장. 대표 이미지를 업로드하면
   서버(`computeAverageColorHex`, `jam-web/src/lib/imageAverageColor.ts`)가 계산한 평균 색상이
   자동으로 채워진다 (`ImageUploadField`의 `onAverageColor` 콜백).
2. **제너레이터(패턴/쉐이더)** — 이미지를 올려 패턴/애니메이션 합성 + Paper 필터를 적용하고,
   그 결과를 PNG/영상으로 구워(`bake()`) `background_image_url`/`background_video_url`에 저장.
   추가로 각 폼에는 실제 렌더링에 연결되지 않은 **"배경 쉐이더 (임시)" 드롭다운**
   (`background_shader_id`, `BADGE_BACKGROUND_SHADER_OPTIONS`)이 별도로 존재한다 — 값만 저장되고
   상세화면에는 반영되지 않는 죽은 필드다.

이번 작업은 2번(제너레이터 패턴/애니메이션/필터 + 쉐이더 드롭다운)을 완전히 제거하고, 1번(단색 +
이미지 평균색 자동 지정)과 "하위 배지 일괄 적용" 캐스케이드 기능만 남긴다.

**범위 판단**: 사용자는 "컬렉션 상세, 아이템배지상세" 두 화면을 지목했지만, 두 화면이 쓰는
`BackgroundGeneratorPreview.tsx`는 `/admin/factions`(세계관)에서도 동일하게 재사용되는 완전
공용 컴포넌트다. 컴포넌트 자체에서 패턴/쉐이더를 제거하면서 특정 호출부만 골라 남기는 것은
불필요한 분기를 만드는 일이라, **세계관(`FactionForm.tsx`)도 동일하게 적용 대상에 포함한다.**
(오케스트레이터 판단 — 필요시 사용자에게 세계관 제외를 요청받으면 되돌린다.)

## 상세 요구사항

### 서비스/코드베이스 관점

**제거 대상**
1. `BackgroundGeneratorPreview.tsx`에서 "제너레이터" 모드 전체 제거:
   - 단색/제너레이터 배타 라디오 선택 UI
   - 제너레이터의 자체 이미지 업로드(`ImageUploader`)·"기존 이미지 재사용" 라디오
     (`existingImageOption` prop 포함)
   - 패턴 모드(`PatternPanel`)/애니메이션 모드(`AnimationPanel`) 전환 UI
   - Paper 필터 선택 UI(`FilterPreview`)
   - `bake()`의 영상/이미지 굽기 분기(정적 패턴 PNG, 애니메이션 MP4) 및 관련 진행 상태
     (`baking`/`bakeStatus`) — 컴포넌트는 이제 "제너레이터로 새로 구울 것"이 없으므로
     `bake()` 자체가 필요 없어질 수 있다. 호출부의 저장 로직과 함께 정리할 것.
   - **주의**: `bakePreviewToBlob.ts`/`bakeBackgroundVideo.ts`(`jam-web/src/app/admin/badges/`)와
     `/app/spike/background-generator/` 하위 모듈(`ImageUploader`/`PatternPanel`/`AnimationPanel`/
     `FilterPreview`/`loadImage`/`patternTile`/`kaleidoscope` 등)은 **삭제하지 말 것** —
     `bakePreviewToBlob`/`bakeBackgroundVideo`는 서비스 배지 공유 기능
     (`jam-web/src/app/(main)/badges/[id]/buildBadgeShareBlob.ts`, `BadgeShareButton.tsx`)에서도
     쓰고, spike 하위 모듈도 그 경유로 참조된다. `BackgroundGeneratorPreview.tsx`의 import만
     제거하고 원본 모듈은 그대로 둔다(다른 기능이 계속 쓰므로 삭제 시 빌드 깨짐).
   - 남는 것: `backgroundColor`/`onBackgroundColorChange` 기반의 `BackgroundColorField` UI +
     `themed`(= `Boolean(backgroundColor)`) 계산 + `renderPreview` 델리게이션. 컴포넌트를
     통째로 없애고 각 폼에 인라인해도 되고, 얇은 래퍼로 남겨도 된다 — 3개 호출부가 동일한
     프리뷰 프레임 위임 패턴(`renderPreview`)을 쓰므로 중복을 늘리지 않는 쪽으로 판단할 것.

2. 아래 3개 폼에서 "배경 쉐이더 (임시)" 드롭다운 UI + `backgroundShaderId` 상태 제거:
   - `jam-web/src/app/admin/badges/BadgeForm.tsx`
   - `jam-web/src/app/admin/itembooks/ItemBookForm.tsx`
   - `jam-web/src/app/admin/factions/FactionForm.tsx`
   - 저장 payload에서 `background_shader_id` 필드를 아예 보내지 않는다(기존 문서화된 null
     덮어쓰기 버그 수정 — 티켓 20260827_005/009/011 — 덕분에 필드를 아예 생략하면 API가 기존
     DB 값을 건드리지 않는다. 저장 라우트가 실제로 "누락 필드는 무시" 동작인지 반드시 코드로
     확인하고 진행할 것).
   - `background_image_url`/`background_video_url`도 마찬가지로 저장 payload에서 생략해
     기존 DB 값을 그대로 보존한다(제너레이터가 사라졌으니 이 필드를 새로 만들 방법이 없다 —
     과거에 생성된 값이 있다면 손대지 않고 그대로 둔다. 상세화면 렌더링 로직
     `getBadgeBackgroundStyle`은 이번 티켓에서 변경하지 않으므로 기존 이미지/영상 배경은
     계속 정상 렌더링된다).

3. 3개 폼의 "하위(에) 일괄 적용" 버튼 활성화 조건을 단순화:
   현재 `hasBackgroundValue = themed || backgroundShaderId !== ''` 형태 → 쉐이더가 사라지므로
   `Boolean(backgroundColor.trim())` 하나로 단순화.

4. 일괄 적용 API 3곳에서 `background_shader_id`/`background_image_url`/`background_video_url`
   복사를 제거하고 `background_color`만 복사하도록 축소:
   - `jam-web/src/app/api/admin/itembooks/[id]/apply-background/route.ts`
   - `jam-web/src/app/api/admin/factions/[id]/apply-background/route.ts` (3단 캐스케이드 —
     직속 배지 + 소속 컬렉션 + 그 컬렉션의 아이템배지 전부 동일하게 축소)
   - (배지 자신에게는 일괄 적용 API가 없음 — 배지가 캐스케이드의 최종 대상이므로 해당 없음)

5. 각 폼의 저장(submit) 핸들러에서 `backgroundMode`/`bake()` 관련 분기 제거하고
   `background_color`만 다루도록 단순화. 컬렉션/세계관의 "일괄 적용 버튼 비활성화 안내 문구"
   ("배경색 또는 배경 이미지를 먼저 지정해야…")도 "배경색을 먼저 지정해야…"로 표현을 맞춘다
   (UX Writing 가이드 — 해요체, 간결).

**유지 대상 (건드리지 않음)**
- `ImageUploadField.tsx`의 `onAverageColor` 콜백과 `/api/admin/upload-image/route.ts`의
  `computeAverageColorHex` 호출 — 대표 이미지 업로드 시 평균색 자동 지정 기능. 그대로 유지.
- `getBadgeBackgroundStyle`/`hasBadgeBackgroundTheme`/`getBadgeBackgroundVideoUrl`
  (`jam-web/src/lib/badgeBackgroundTheme.ts`) — 상세화면 렌더링 로직. 변경 없음.
- 각 상세화면(`/badges/[id]`, `/itembooks/[id]`, 세계관 상세)의 배경 렌더링 자체. 변경 없음.
- 일괄 적용 API의 "배경색만" 복사 동작(대상 범위·항상 덮어쓰기 방침)은 그대로.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `BackgroundGeneratorPreview.tsx`를 패턴/애니메이션/Paper 필터 저작 UI 전체(`ImageUploader`/
  `PatternPanel`/`AnimationPanel`/`FilterPreview`/`bake()`/`baking`/`bakeStatus`/단색-제너레이터
  배타 라디오)를 제거하고 `backgroundColor`/`onBackgroundColorChange` + `renderPreview` 델리게이션만
  남긴 얇은 컴포넌트로 축소했다. `forwardRef`/`useImperativeHandle`도 제거(더 이상 굽기 대상이
  없음). `spike/background-generator/**`, `bakePreviewToBlob.ts`, `bakeBackgroundVideo.ts` 원본
  모듈은 서비스 배지 공유 기능(`buildBadgeShareBlob.ts`)이 계속 쓰므로 삭제하지 않고 import만 뺐다.
- `BadgeForm.tsx`/`ItemBookForm.tsx`/`FactionForm.tsx` 3개 폼에서 "배경 쉐이더 (임시)" 드롭다운
  UI·`backgroundShaderId`/`backgroundMode`/`themed`(콜백 기반) state·`backgroundGeneratorRef`를
  모두 제거했다. `BackgroundGeneratorPreview`가 더 이상 무거운 라이브러리(@paper-design/shaders-react,
  mp4-muxer)를 정적 import하지 않으므로 `React.lazy`+`Suspense` 지연 로딩도 함께 제거하고 정적
  import로 되돌렸다(그 근거였던 청크 분리 이유 자체가 사라짐).
- 저장 payload는 `background_color`만 보내도록 단순화했다. `background_shader_id`/
  `background_image_url`/`background_video_url`은 아예 payload에서 생략 — 저장 API 3곳(`badges`/
  `item_books`/`factions` PUT)이 이미 "undefined 필드는 기존 DB 값 유지" 패턴(티켓
  20260827_005/007/011)이라, 생략만으로 기존 값이 보존되는지 코드로 확인 후 그대로 재사용했다
  (별도 API 코드 변경 없음).
- "하위(에) 일괄 적용" 버튼 활성화 조건을 `themed || backgroundShaderId !== ''` →
  `Boolean(backgroundColor.trim())`으로 단순화(ItemBookForm/FactionForm).
- 일괄 적용 API 2곳 축소:
  - `itembooks/[id]/apply-background/route.ts`: 조회·update 대상을 `background_color` 한
    컬럼으로 축소.
  - `factions/[id]/apply-background/route.ts`: 실제 복사 로직이 Postgres 함수
    `apply_faction_background_cascade`(마이그레이션 092)에 있어, 라우트 코드는 그대로 두고
    마이그레이션 121에서 `CREATE OR REPLACE FUNCTION`으로 3단 캐스케이드가 `background_color`만
    복사하도록 축소했다. 같은 시그니처라 마이그레이션 109의 REVOKE/GRANT(PUBLIC 회수,
    service_role만 허용)는 그대로 유지된다. 건수 미리보기(`count_faction_background_cascade`)는
    COUNT만 계산해 필드와 무관하므로 변경하지 않았다.
- 비활성화 안내 문구 "배경색 또는 배경 이미지를 먼저 지정해야…" → "배경색을 먼저 지정해야…"로
  통일(ItemBookForm/FactionForm).
- `getBadgeBackgroundStyle`/`hasBadgeBackgroundTheme`/`getBadgeBackgroundVideoUrl`
  (`badgeBackgroundTheme.ts`), 상세화면 렌더링 로직, `ImageUploadField`의 `onAverageColor` 평균색
  자동 지정 콜백, `computeAverageColorHex`는 티켓 범위 밖이라 변경하지 않았다.
