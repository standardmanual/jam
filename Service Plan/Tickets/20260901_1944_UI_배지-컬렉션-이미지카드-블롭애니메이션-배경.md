# [UI] 배지·컬렉션 이미지 카드 배경 — 블롭 애니메이션 옵션 추가

## 배경 / 문제 정의

현재 배지(활동/아이템/체크인)·컬렉션의 배경 저작은 **단색(`background_color`) 하나뿐**이다.
과거에 있던 패턴/쉐이더/Paper 필터 제너레이터는 티켓 `20260901_1929`에서 제거 중이고(선행 작업),
그 결과 저작 UI에는 배경색 필드만 남는다.

여기에 **블롭(blob) 애니메이션 배경**을 두 번째 선택지로 추가한다. 사용자가 제시한 참조 스크립트
(Canvas 2D 기반 — 유기적 블롭 6개가 blur 합성되며 부유하는 애니메이션)를 서비스 렌더링 엔진으로
삼는다.

### 기존 배경 시스템과의 차이 (중요)

현재 `background_color`/`background_image_url`/`background_video_url`은 **상세화면 전체를 덮는
고정 배경 레이어**에 적용되고, 이미지 Hero 카드는 `bg-transparent`가 되어 그 배경이 비쳐 보인다
(`BadgeHeroSection.tsx:37`, 티켓 20260819_011에서 "단일 레이어" 원칙 확정).

**이번 애니메이션은 전체 배경이 아니라 이미지가 놓인 정사각형 Hero 카드 "안"에만 그린다**
(사용자 결정). 즉 기존 전체배경 레이어와는 별개의 새 렌더링 지점이다. 둘의 관계 정의가
이 티켓의 핵심 설계 포인트다.

### 과거 애니메이션 배경과의 차이 (중요)

티켓 `20260819_012`의 애니메이션 배경은 **어드민에서 MP4로 굽고 서비스는 `<video>`로 재생**하는
방식이었고, "유저단(모바일 웹)에는 무거운 렌더링을 올리지 않는다"가 명시 원칙이었다. 그 원칙은
**WebGL/Three.js 기준**이었고, 이번 블롭 애니메이션은 Canvas 2D + `ctx.filter` blur만 쓴다.

이번에는 **파라미터를 저장하고 서비스에서 라이브 실행**한다(사용자 결정). 근거:
- 저장 후 재편집이 가능하다 (기존 제너레이터는 완성 이미지만 저장해 재편집 불가였다 — 실사용
  불편의 주원인)
- 영상 파일 다운로드가 없어 네트워크 페이로드가 오히려 작다 (파라미터 JSON 수백 바이트)
- 렌더링 대상이 상세화면 Hero 카드 **1개**로 한정돼 동시 렌더 수가 통제된다

단, blur 필터는 모바일에서 비용이 있으므로 **성능 가드는 필수 요구사항**이다(아래 참조).

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 데이터 모델 — 신규 컬럼

`badges` / `item_books` / `factions` 세 테이블에 애니메이션 파라미터 컬럼을 추가한다.
(세계관까지 포함하는 이유: 기존 배경 4컬럼이 세 테이블 모두에 있고, 세계관 → 컬렉션 → 배지
3단 캐스케이드 일괄 적용이 이미 동작 중이라 한 테이블만 빠지면 캐스케이드가 깨진다.)

- 컬럼명 제안: `background_animation` (`jsonb`, nullable)
- **`background_shader_id`를 재사용하지 않는다** — 그 컬럼은 죽은 레거시(값만 저장, 렌더링
  미연결)이고 선행 티켓 `20260901_1929`에서 저작 UI가 제거된다. 의미가 다른 값을 얹으면
  혼란만 커진다. 신규 컬럼으로 깨끗하게 분리한다.
- 저장 형태(제안 — 구현자가 최종 확정):
  ```json
  {
    "type": "blob",
    "colors": ["#ff6d30", "#a8aded", "#ffe5d1", "#ff4c00"],
    "bgColor": "#ffffff",
    "speed": 1,
    "seed": 21,
    "blur": 0.54,
    "scale": 0.66
  }
  ```
  `type`을 두는 이유: 향후 다른 애니메이션을 추가할 때 컬럼을 또 늘리지 않기 위함.
- 마이그레이션 파일을 작성한다. **번호는 push 직전에 원격 staging 기준으로 재확인할 것** —
  현재 최신은 120이나 병렬 세션이 선점할 수 있고, 실제로 094번 중복 사고 이력이 있다.
- 마이그레이션 추가 후 **`npm run db:types`로 `database.generated.ts`를 재생성해 같은 커밋에
  포함**한다. 생성 타입이 낡으면 올바른 코드가 잘못된 컴파일 오류를 낸다(실제 사고 이력 있음).
- **DB 실행은 하지 않는다** — SQL 파일 작성까지만. 실행은 오케스트레이터가 사용자 승인 후 수행.

#### 2. 배경색 ↔ 애니메이션 배타 선택

저작 UI에서 두 모드는 **배타**다(사용자 요구: "배경색 / 애니메이션 선택 두개의 옵션").
- 애니메이션을 선택해 저장하면 `background_animation`에 값이 들어간다
- 배경색을 선택하면 `background_animation`은 `null`이 된다
- 기존 `background_color`/`background_image_url` 우선순위 규칙과의 관계를 명시적으로 정해
  `badgeBackgroundTheme.ts`에 한 곳으로 모은다. 제안 우선순위:
  `background_animation` > `background_image_url` > `background_color`
- **주의**: 선행 티켓 `20260901_1929`가 저장 payload에서 `background_image_url`/
  `background_video_url`을 **생략**해 기존 DB 값을 보존하도록 바꾼다. 애니메이션을 켤 때
  과거에 구워둔 이미지 배경이 남아 있으면 우선순위 충돌이 난다 — 애니메이션 저장 시
  이 두 필드를 명시적으로 `null`로 덮을지 여부를 구현자가 판단하고 근거를 완료 기록에 남길 것.

#### 3. 서비스 렌더링 — 이미지 카드 안

- 신규 컴포넌트(예: `BlobAnimationBackground.tsx`)를 만들어 **정사각형 Hero 카드 내부**에
  절대배치 캔버스 레이어로 깐다. 이미지는 그 위(z-index 상위)에 그대로 둔다.
- 적용 지점:
  - 배지 상세: `jam-web/src/app/(main)/badges/[id]/BadgeHeroSection.tsx` (`:37` 카드 div)
  - 컬렉션 상세: `jam-web/src/app/(main)/collections/[id]/ItemBookHeroSection.tsx` (`:34`)
  - 두 Hero 컴포넌트는 어드민 프리뷰 프레임에서도 **그대로 재사용**되므로(티켓 20260819_011/014
    확립 패턴), 여기에만 넣으면 어드민 미리보기는 자동으로 따라온다 → **미리보기용 별도 구현
    금지**
- 카드가 `overflow-hidden` + `rounded-[var(--radius-cards)]`로 애니메이션을 라운드 안에 가둘 것
  (`ItemBookHeroSection`은 이미 `overflow-hidden`, `BadgeHeroSection`은 확인 필요)
- 배경 애니메이션이 있을 때 카드의 `bg-surface-elevated`/`bg-transparent` 분기를 어떻게 둘지
  정한다 — 애니메이션 자체가 카드 배경이므로 별도 배경색은 불필요할 가능성이 높다.
- **전체 배경 레이어(기존 시스템)는 이번 티켓에서 변경하지 않는다.** 애니메이션이 카드 안에만
  있고 전체배경은 기존 규칙대로 동작한다. 둘이 동시에 켜진 경우의 시각적 결과를 확인하고
  어색하면 완료 기록에 남길 것.

#### 4. 성능 가드 (필수)

블롭 애니메이션은 `ctx.filter = blur()`를 매 프레임 6회 호출한다 — 모바일에서 비용이 크다.
아래를 **모두** 구현한다:
- `prefers-reduced-motion: reduce`이면 애니메이션을 돌리지 않고 **정지 1프레임만 렌더**한다.
  기존 관행은 `globals.css:538`의 `.badge-background-video` 패턴(미디어쿼리로 `display:none`)이나,
  이 경우는 배경이 통째로 사라지면 카드가 비어 보이므로 **정지 프레임 유지**가 맞다.
- 카드가 뷰포트 밖이거나 탭이 백그라운드면 `requestAnimationFrame` 루프를 **정지**한다
  (`IntersectionObserver` + `document.visibilitychange`).
- 캔버스 백킹 스토어 해상도에 상한을 둔다(DPR 캡). 참조 스크립트도 모바일에서 DPR을 1.5로
  캡하고 프레임을 32ms로 제한하는 가드를 갖고 있다 — 동일 수준으로 적용한다.
- 언마운트 시 rAF·옵저버를 반드시 해제한다(누수 방지).

#### 5. 어드민 저작 UI

- 선행 티켓 `20260901_1929`가 `BackgroundGeneratorPreview.tsx`를 배경색 전용으로 축소한다.
  그 위에 **배경색 / 애니메이션 배타 선택 UI**를 얹는다. 1929가 지운 패턴/쉐이더/Paper 필터를
  되살리는 것이 아니다 — 새 단일 애니메이션 타입 하나만 추가한다.
- 애니메이션 선택 시 파라미터 컨트롤을 노출: 색상 4개 + 배경색 + 속도 + 시드 + blur + 크기
  (+ 시드 랜덤화 버튼). 참조 스크립트의 Aperture Size/Edge Softness는 원형 마스크 전용이라
  **채택하지 않는다**(카드 안 렌더링에는 불필요).
- 세 폼 모두에 적용: `BadgeForm.tsx`(배지 3종 공통 — 타입별 화면이 나뉘지 않음),
  `ItemBookForm.tsx`(컬렉션), `FactionForm.tsx`(세계관)
- 저작 중 미리보기는 실시간 반영(파라미터 조절 → 즉시 캔버스 갱신)

#### 6. 일괄 적용 캐스케이드 확장

`background_animation`을 기존 배경 필드와 함께 하위로 복사하도록 확장:
- `jam-web/src/app/api/admin/itembooks/[id]/apply-background/route.ts`
- `jam-web/src/app/api/admin/factions/[id]/apply-background/route.ts` (3단 캐스케이드)
- `092_faction_background_cascade_rpc.sql`에 RPC가 있다면 함께 갱신 필요 — 확인할 것
- 일괄 적용 버튼 활성화 조건(선행 티켓이 `Boolean(backgroundColor.trim())`으로 단순화)에
  애니메이션 값도 포함되도록 확장

#### 7. 저장 API

- `POST /api/admin/badges`, `PUT /api/admin/badges/[id]`
- `POST /api/admin/itembooks`, `PUT /api/admin/itembooks/[id]`
- 세계관 대응 라우트
- PUT은 `body.x !== undefined ? body.x : existing.x` 병합 패턴이므로, 애니메이션을 **끄는**
  경우(`null` 저장)가 이 패턴에서 정상 동작하는지 반드시 확인할 것 — `undefined`와 `null`
  구분이 깨지면 "애니메이션 해제"가 저장되지 않는다.

### UI/UX 관점

- **DS 재사용 판정(오케스트레이터 1.5단계 수행 결과)**: `design-system/components/`의
  buttons·cards·feedback·forms·icons·navigation·patterns 전 범주를 확인했고 캔버스/배경/
  애니메이션 계열 컴포넌트는 **존재하지 않는다**. 따라서 **서비스 전용 신규 구현**으로 진행한다.
  MODULAR 승격 여부는 개선 리뷰에서 판단한다(현재는 배경 데이터 모델에 강하게 결합돼 있어
  범용 컴포넌트로 올리기에 이르다).
- 어드민 화면 부분은 MODULAR 적용 대상이 아니다.
- 사용자 노출 문구(모드 선택 라벨, 안내 문구)는 UX Writing 가이드라인 준수 — 해요체, 간결.

## 구현 계획

1. 마이그레이션 작성(`background_animation` jsonb × 3 테이블) + `npm run db:types` 재생성
2. `badgeBackgroundTheme.ts`에 애니메이션 판정/우선순위 로직 추가 (렌더링 결정을 한 곳에 모음)
3. `BlobAnimationBackground.tsx` 신규 작성 — 참조 스크립트의 블롭 드로잉 로직 이식 +
   성능 가드(reduced-motion·IntersectionObserver·visibilitychange·DPR 캡·정리) 구현
4. `BadgeHeroSection.tsx` / `ItemBookHeroSection.tsx`에 카드 내부 배경 레이어로 연결
   (→ 어드민 프리뷰는 재사용으로 자동 반영)
5. 어드민 저작 UI: 배경색/애니메이션 배타 선택 + 파라미터 컨트롤 (3개 폼)
6. 저장 API 4~6곳에 `background_animation` 반영 (null 저장 경로 포함)
7. 일괄 적용 캐스케이드 2~3곳 확장 (+ RPC 확인)
8. 테스트 갱신, `npm run lint` / `npx tsc --noEmit` / `npm run build` 통과 확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`badges`/`item_books`/`factions`에 `background_animation`(jsonb) 컬럼을 추가하고, 배지·컬렉션
상세화면의 **정사각형 Hero 카드 안**에서 Canvas 2D로 블롭 애니메이션을 라이브 실행한다.
어드민 저작 UI는 배경색 / 애니메이션 배타 선택으로 바뀌었다.

1. **데이터 모델** — 마이그레이션 124. 세 테이블에 `background_animation JSONB` 추가 +
   `apply_faction_background_cascade` RPC가 `background_color`와 함께 복사하도록 확장.
   `background_shader_id`는 재사용하지 않았다(티켓 방침).
2. **렌더링 판단 일원화** — `badgeBackgroundTheme.ts`에 우선순위
   `background_animation` > `background_video_url` > `background_image_url` > `background_color`를
   구현. 애니메이션이 켜져 있으면 `getBadgeBackgroundStyle`은 빈 스타일을,
   `getBadgeBackgroundVideoUrl`은 null을, `hasBadgeBackgroundTheme`은 false를 돌려준다
   (전체 배경 레이어를 CSS·영상 모두 통째로 비운다).
3. **렌더러** — `lib/blobAnimation.ts`(React·DOM 비의존 순수 모듈: 파라미터 정의·정규화·
   `drawBlobFrame`) + `components/BlobAnimationBackground.tsx`(클라이언트 컴포넌트, 성능 가드).
4. **적용 지점** — `BadgeHeroSection` / `ItemBookHeroSection` 두 Hero 컴포넌트에만 연결했고,
   어드민 미리보기는 같은 컴포넌트를 재사용하므로 자동으로 따라온다(미리보기 전용 구현 없음).
5. **어드민 저작 UI** — `BackgroundGeneratorPreview`에 모드 라디오(배경색/애니메이션)를 얹고,

### 주요 의사결정 / 핵심 메모

1. **애니메이션을 켤 때 `background_image_url`/`background_video_url`을 null로 덮지 않는다.**
   (티켓 상세요구 #2가 구현자 판단으로 남긴 항목)
   근거: 선행 티켓 20260901_1929가 저장 payload에서 이 두 필드를 의도적으로 생략해 기존 DB 값을
   보존하도록 바꿨다 — 제너레이터가 사라져 **다시 만들 수 없는 값**이기 때문이다. 여기서 파괴적
   null 덮어쓰기를 되살리면 그 결정을 뒤집는다. 대신 우선순위 충돌은 **렌더링 단계**에서 해결했다:
   `getBadgeBackgroundStyle`이 애니메이션이 있으면 빈 스타일을 돌려주므로, 과거 이미지 배경이
   DB에 남아 있어도 화면에는 절대 나타나지 않는다. 데이터는 보존하고 "무엇을 그릴지"만 한 곳
   (`badgeBackgroundTheme.ts`)에서 결정한다. `background_color`도 같은 이유로 남겨둔다 —
   모드를 배경색으로 되돌리면 이전 색이 그대로 살아나 저작 편의가 오히려 좋아진다.

2. **`hasBadgeBackgroundTheme`은 애니메이션 모드에서 false다.** 이 판정의 의미는 "고정 배경
   레이어에 무언가 그려지는가"이고, 애니메이션은 그 레이어가 아니라 카드 안에 그려진다. 따라서
   TopNav·본문은 배경 없는 화면과 동일하게(`--color-surface` / `PAGE_BG`) 유지된다.

   **[1차 게이트 리뷰 FAIL → 수정]** 1차 구현에서 이 분기를 `getBadgeBackgroundStyle`·
   `hasBadgeBackgroundTheme` 두 함수에만 넣고 `getBadgeBackgroundVideoUrl`을 빠뜨렸다. 그 결과
   "전체 배경 레이어와 카드 애니메이션이 동시에 켜지는 경우는 발생하지 않는다"고 적었던 기록은
   **사실과 달랐다** — CSS 배경만 비고 반복 MP4는 계속 재생돼, 화면 전체를 덮는 영상과 카드 안
   블롭이 동시에 돌았다. 프로덕션 DB에 `background_video_url`이 채워진 행이 badges 351건 /
   item_books 10건 / factions 1건으로 사실상 대부분이라 엣지 케이스도 아니었다.
   `getBadgeBackgroundVideoUrl`에도 동일한 `parseBlobAnimation` 분기를 넣어 **세 함수가 모두**
   "애니메이션이 있으면 전체 배경 레이어 없음"으로 답하도록 고쳤고, 회귀 방지 테스트
   (애니메이션 + 영상 동시 보유 / 캐스케이드 직후 상태 / 해제 시 영상 복귀)를 추가했다.
   수정 후 위 문장이 실제로 성립한다.

3. **성능 가드**(티켓 필수) 전부 구현: `prefers-reduced-motion: reduce` → 루프 없이 정지 1프레임
   유지(배경이 통째로 사라지면 카드가 비어 보이므로 display:none 방식은 쓰지 않았다),
   `IntersectionObserver`로 뷰포트 밖 정지, `visibilitychange`로 백그라운드 탭 정지,
   DPR 캡(모바일 1.5 / 그 외 2) + 모바일 프레임 간격 32ms, 언마운트 시 rAF·옵저버·리스너 전량 해제.

4. **`npm run db:types`를 실행하지 않았다.** 이 명령은 원격 Supabase의 **현재** 스키마를 읽는데,
   마이그레이션 124가 아직 적용 전이라 실행하면 새 컬럼이 빠진 파일이 생성돼 오히려 회귀한다.
   `database.generated.ts`의 badges/item_books/factions Row·Insert·Update 9곳에
   `background_animation: Json | null`을 수기로 추가했다(생성기가 쓰는 알파벳 순서·optional 규칙을
   그대로 따랐다). **마이그레이션 적용 후 `npm run db:types`를 한 번 돌려 수기 편집과 일치하는지
   확인할 것.**

5. **파라미터 정규화(`parseBlobAnimation`)를 관용적으로 설계했다.** jsonb는 스키마 검증이 없어
   깨진 값이 들어올 수 있는데, 배경은 장식이라 데이터 하나로 상세화면이 죽으면 안 된다. 타입이
   틀리면 `null`(애니메이션 없음), 개별 필드만 틀리면 기본값, 범위를 벗어난 숫자는 클램프한다.
   테스트 작성 중 `Number(null) === 0` 때문에 `blur: null`이 기본값이 아니라 최솟값으로 눌리는
   버그를 발견해 강제 변환을 제거했다.

6. **참조 스크립트의 aperture_size / edge_softness는 채택하지 않았다** — 원형 마스크 전용
   파라미터이고, 사용자가 "카드 전체 영역에 보이도록" 요청해 마스크 자체를 제거했다. 라운드
   클리핑은 카드의 `overflow-hidden`이 담당한다.

7. **마이그레이션 번호를 122 → 124로 재번호했다.** 1차 구현 이후 원격 staging에
   `123_backfill_feed_event_at_approx.sql`이 들어와, 122로 두면 이미 적용된 123보다 뒤에
   실행되는 순서 역전이 생긴다. 원격 staging 기준 최신은 123이므로 124를 쓴다(122는 빈 번호로
   남는다 — 되메우지 않는다). `database.generated.ts`는 컬럼 정의만 담아 번호와 무관하다.

8. **일괄 적용 캐스케이드에서도 `background_video_url`/`background_image_url`을 복사하거나
   지우지 않는다.** (1차 게이트 리뷰가 "부수 결함"으로 지적한 항목)
   근거는 의사결정 1과 같다 — 제너레이터가 사라져 다시 만들 수 없는 값이라 파괴적으로 덮지
   않는다. 대신 렌더링 우선순위가 충돌을 막는다: 캐스케이드 직후 하위 배지가 갖게 되는
   "부모의 애니메이션 + 자기 예전 영상" 상태에서 세 함수가 모두 "전체 배경 레이어 없음"으로
   답하는 것을 테스트로 고정했다. 라우트 2곳과 RPC 주석에도 이 관계를 명시했다.
