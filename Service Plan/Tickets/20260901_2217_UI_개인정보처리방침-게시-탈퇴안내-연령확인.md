# [UI] 개인정보처리방침 게시 + 탈퇴 신청 안내 + 14세 미만 가입 제한

## 배경 / 문제 정의

`Service Plan/Specs/PRIVACY_POLICY.md`에 개인정보처리방침 초안을 작성했다(PIPC 작성지침
2025.4. 및 실제 코드 조사 기반). 이 문서를 실제 서비스에 반영하려면 아래 3가지가 필요하다.

1. 방침 본문을 실제 페이지로 공개하고 Footer에서 접근 가능하게 한다.
2. 방침 9항("14세 미만 아동의 회원가입을 허용하지 않는다")을 실제로 집행할 최소 장치가 없다
   — 현재 코드에 연령 확인 로직이 전혀 없다.
3. 방침 9항의 회원 탈퇴 절차("이메일로 요청")에 대응하는 진입점이 서비스 UI에 없다
   — 현재 자기 탈퇴 API/UI가 없다(전수 검색 결과 미발견).

## 상세 요구사항

### UI/UX 관점

**A. 개인정보처리방침 페이지 신설**

- 경로: `jam-web/src/app/(main)/privacy/page.tsx`
- `(main)/philosophy/page.tsx`(티켓 20260901_2125)의 레이아웃·타이포·여백 패턴을 그대로 따른다:
  `TopNav` + 단일 컬럼 본문, `--text-body` + `--leading-reading`, 문단 간격
  `--spacing-32`, 상단 여백 `--spacing-64`, 커버 이미지·태그 없음. 서버 컴포넌트로 둔다
  (DB/API 의존 없음).
- 본문 내용은 `Service Plan/Specs/PRIVACY_POLICY.md`의 "1. 개인정보의 처리 목적" ~
  "12. 개인정보 처리방침의 변경" 섹션만 옮긴다. **"게시 전 확인 필요 사항"(내부 메모)
  섹션은 페이지에 포함하지 않는다.**
- 표(마크다운 테이블)가 여러 개 있다 — 앱 컬럼 폭이 398px로 좁으므로 표를 그대로 HTML
  `<table>`로 넣지 말고, 각 행을 세로로 쌓는 정의목록(dt/dd) 또는 카드형 레이아웃으로
  변환할 것. 가로 스크롤이 필요한 표는 만들지 않는다.
- `[◯◯◯]`, `[YYYY. M. D.]` 같은 미확정 플레이스홀더는 페이지 게시 시점 기준으로 확정된 값
  (또는 최소한 "추후 공지" 같은 자연스러운 한국어 문구)으로 교체한다 — 대괄호를 그대로
  사용자에게 노출하지 않는다. 사업자 등록 정보(대표자·사업자등록번호 등)는 사용자가
  "비움"으로 확정했으므로 해당 항목 자체를 섹션에서 생략한다(빈 대괄호로 남기지 않는다).
  개인정보 보호책임자 연락처는 `sihyunrr@gmail.com`으로 확정해 채운다.
  시행일은 이 티켓의 배포일(완료 기록에 실제 배포일 적을 때 함께 확정)로 채운다.

**B. Footer 링크 추가**

- `jam-web/src/components/ui/Footer.tsx`의 "Philosophy" 링크(`d.common.footerPhilosophy`)
  **우측에** "개인정보처리방침" 링크를 추가한다. 두 링크를 가로로 나란히 배치
  (기존 `flex flex-col` 3단 구조에서 Philosophy 줄만 `flex-row`로 바꾸고 구분점 또는 gap으로
  분리).
- 기존 Philosophy 링크와 동일한 스타일(`text-caption`, `underline`, `min-h-11` 터치영역,
  `active:opacity-60`)을 그대로 따른다. `/privacy` 경로로 라우팅.
- `FOOTER_EXCLUDED_PATHS`에 `/privacy`도 추가해 방침 페이지 자신에서는 Footer가 순환 노출되지
  않게 한다(Philosophy와 동일한 이유, 20260901_2125 선례).
- `d.ts`(i18n) 라벨: `d.common.footerPrivacy` 같은 키를 새로 추가한다(`footerPhilosophy`
  패턴을 따름).

**C. 회원 탈퇴 신청 안내 (프로필 편집 화면)**

- `jam-web/src/app/(main)/profile/edit/page.tsx`의 저장/취소 버튼 아래에 "탈퇴 신청" 텍스트
  링크를 추가한다. 기존 `cancelButton`(text-text/60, text-body-sm, 링크형 버튼)과 동일한
  스타일을 재사용하되 시각적으로 구분되도록 별도 줄에 배치한다.
- 클릭 시 `mailto:sihyunrr@gmail.com?subject=...` 링크로 이메일 클라이언트를 연다(제목에
  "JAM! 탈퇴 신청"류 문구 프리필). 실제 계정 삭제 로직은 구현하지 않는다 — 안내 UI만.
- UX 라이팅: 클릭 전 사용자가 "탈퇴 = 되돌릴 수 없음"을 인지하도록 링크 라벨 또는 근접
  캡션에 간단히 명시한다(예: "탈퇴 신청" 아래 캡션 "이메일로 요청하면 계정과 활동 기록이
  삭제돼요"). `Service Plan/Specs/UX_WRITING_GUIDELINE.md`의 해요체·간결함 규칙을 따른다.

**D. 14세 미만 가입 제한 (온보딩 자기확인)**

- `jam-web/src/app/(main)/onboarding/page.tsx`에 "만 14세 이상입니다" 자기 확인 체크박스를
  추가한다. 실제 생년월일 검증이 아니라 self-declaration이다(Google OAuth로 생년월일을
  받아오지 않음 — 방침 문서에도 이렇게 명시돼 있다).
- 위치: 유저네임 입력 영역과 "생성하기" 버튼 사이.
- **체크하지 않으면 "생성하기" 버튼이 비활성화**되도록 기존 `canSave`/`disabled` 패턴처럼
  게이트 조건에 추가한다 (`status === 'available'` 조건에 `ageConfirmed` 추가).
- 서비스에 Checkbox 개념이 없다(MODULAR `Checkbox`는 "미도입 8종" — 티켓 20260820_010에서
  유지/보류 확정, 임의 도입 금지). **네이티브 `<input type="checkbox">`를 서비스 전용으로
  최소 스타일링**해서 쓴다. 온보딩 페이지가 이미 쓰는 바이너리-컬러 원칙(색상 대신 보더
  두께/굵기로 상태 구분)을 유지 — 체크 여부는 색이 아니라 체크 아이콘/보더로 표현한다.
  MODULAR 승격은 이번 범위 밖.
- 라벨 문구는 링크가 아닌 평문("만 14세 이상이에요" 류, 해요체)로 하되, 체크박스 자체가
  법적 의미를 갖는 동의이므로 문구가 모호하지 않아야 한다.
