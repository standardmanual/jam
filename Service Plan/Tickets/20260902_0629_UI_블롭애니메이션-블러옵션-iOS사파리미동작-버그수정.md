# [UI] 블롭 애니메이션 배경 — 블러 옵션이 iOS Safari에서 아예 동작하지 않는 버그 수정

## 배경 / 문제 정의

티켓 `20260901_1944`(배지·컬렉션 이미지 카드 블롭 애니메이션 배경)가 프로덕션에 배포된 직후,
사용자가 어드민 저작 화면의 미리보기(iPhone Safari)에서 **블러 슬라이더를 움직여도 미리보기
캔버스가 전혀 변하지 않는다**고 보고했다.

### 원인 (오케스트레이터가 코드·격리 테스트로 확인함)

`jam-web/src/lib/blobAnimation.ts`의 `paintBlobs()`가 블러를 `ctx.filter = 'blur(Npx)'`
(Canvas 2D 컨텍스트의 `filter` 프로퍼티)로 적용한다. 이 API는 **iOS Safari 17.4 이전에는
지원되지 않는다** — 지원하지 않는 브라우저에서 `ctx.filter`에 값을 대입해도 조용히 무시되고
`filter`는 `'none'`으로 남아, 블러 없이 선명한 윤곽으로만 그려진다. 이 한계는 코드 주석에도
이미 명시돼 있었다(`blobAnimation.ts` `paintBlobs` 함수 주석: "ctx.filter를 지원하지 않는
구형 브라우저에서는 대입이 무시돼 경계가 선명한 블롭이 그려진다").

**검증**: 실제 프로덕션 렌더링 로직(`drawSmoothBlob`/`paintBlobs`/`drawBlobFrame`)을 그대로
이식한 격리 HTML 테스트를 Chrome(ctx.filter 지원)에서 실행한 결과, blur 0.01~0.8 전 구간에서
시각적 차이가 뚜렷했다 — **렌더링 수식 자체는 정상**이다. 문제는 순수히 `ctx.filter`의 브라우저
지원 범위다.

**다른 파라미터는 영향 없음**: 색상 4개·카드 배경색·속도·시드·크기는 모두 `fillStyle`/
`translate`/`rotate`/`scale`/`quadraticCurveTo` 등 오래전부터 보편 지원되는 API만 사용해
이 문제와 무관하다(사용자 요청 "모든 옵션을 점검해" 대응 — 블러 외에는 호환성 리스크가 없음을
확인했다).

**영향 범위**: 이 시점 기준 프로덕션 DB에 `background_animation`이 설정된 행은 0건이라(배지
0/2194, 컬렉션 0/100, 세계관 0/10) 실사용 배지에는 아직 영향이 없다. 사용자가 배포 직후
어드민 미리보기에서 테스트하다 발견한 것이다.

## 상세 요구사항

### 서비스/코드베이스 관점

**핵심 수정 — 블러를 Canvas 2D `ctx.filter` 대신 DOM 엘리먼트 CSS `filter`로 전환한다.**

CSS `filter: blur()`를 캔버스 **엘리먼트 자체**에 거는 방식(`canvas.style.filter = 'blur(Npx)'`)은
iOS Safari 9부터 지원되는 훨씬 오래되고 안전한 API다(Canvas 2D 컨텍스트의 `filter` 프로퍼티와는
별개의 기능 — CSS Filter Effects Module). 시각적 결과는 동일하다.

1. `jam-web/src/lib/blobAnimation.ts`:
   - `paintBlobs()`에서 `ctx.filter = blur(...)` 대입을 제거한다. 블롭은 선명하게(필터 없이) 그린다.
   - **오프스크린 축소 렌더링(scratch canvas) 관련 코드를 전량 제거한다** —
     `BLOB_SCRATCH_SCALE` / `BLOB_SCRATCH_MIN_BLUR_PX` / `prepareScratch()` / `useScratch` 분기 /
     `drawBlobFrame`의 `scratch` 옵션. CSS `filter`는 GPU 합성이라 도형 개수·복잡도에 비용이
     비례하지 않으므로(구 `ctx.filter`는 도형마다 소프트웨어 래스터화 비용이 들어 축소 렌더링이
     필요했다), 이 최적화 자체가 더 이상 필요 없다. 코드가 상당히 단순해진다.
   - `blobBlurRadiusPx(blur, minDim, opaque)` 함수는 그대로 유지 — 반경 계산 자체는 유효하다.
     이제 이 값을 호출부(`BlobAnimationBackground`)가 `canvas.style.filter`에 쓴다.
   - `drawBlobFrame`의 시그니처·옵션에서 `scratch` 제거. `flatten`/`opaque` 옵션은 유지.
2. `jam-web/src/components/BlobAnimationBackground.tsx`:
   - `scratch` 오프스크린 캔버스 생성·전달 코드를 제거한다.
   - `canvas.style.filter`를 blur 반경으로 설정한다. **매 프레임 쓰지 않는다** — blur는 `t`(위상)에
     의존하지 않으므로, `render()` 안에서 이전에 쓴 값과 비교해 **달라졌을 때만** DOM에 쓴다
     (직전 개선 라운드에서 opacity를 매 프레임 쓰다가 강제 리플로우가 걸렸던 것과 같은 함정을
     반복하지 않는다 — `filter`는 `opacity`처럼 compositor 전용 속성이 아니라 리플로우를 유발할
     수 있으므로 더욱 주의).
   - `opaque`(`prefers-reduced-transparency`) 시 반경을 절반으로 줄이는 기존 로직은 유지 —
     `blobBlurRadiusPx`가 이미 처리하므로 그대로 가져다 쓴다.
3. **캔버스 배경색이 함께 블러되는 것에 대한 확인**: CSS 엘리먼트 필터는 캔버스 전체(블롭 +
   배경색 채움)를 함께 블러한다(기존에는 배경색만 `ctx.filter='none'`으로 선명하게 유지했다).
   배경색은 단색 fillRect라 블러해도 내부는 동일한 색으로 보이고, 카드 가장자리는 부모의
   `overflow-hidden` + 라운드 클리핑이 잘라내며, 그 바깥은 `BadgeHeroSection`의 인라인
   `backgroundColor`(같은 `bgColor`)가 이미 깔려 있어 시각적 이음매가 없어야 한다 — **구현 후
   스크린샷으로 카드 모서리를 확인하고 완료 기록에 남길 것.**
4. 테스트(`jam-web/src/lib/__tests__/blobAnimation.test.ts`)에서 `scratch` 옵션·축소 경로를
   검증하던 테스트는 제거하거나 CSS filter 방식에 맞게 갱신한다. `blobBlurRadiusPx`의 수치
   계산 테스트는 그대로 유효하다.
5. **브라우저 호환성 검증**: iOS Simulator(가능한 iOS 버전 중 가장 낮은 것 포함)에서 블러
   슬라이더를 최소~최대로 움직여 실제로 시각적 변화가 나는지 확인한다. 데스크톱 Chrome/Safari
   에서도 회귀가 없는지 스크린샷으로 확인한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
요구사항대로 블러를 Canvas 2D `ctx.filter`에서 캔버스 엘리먼트의 CSS `filter: blur()`
(`canvas.style.filter`)로 전환했다.

- `blobAnimation.ts`의 `paintBlobs()`에서 `ctx.filter` 대입을 제거하고 블롭을 항상 선명하게
  그리도록 바꿨다. `drawBlobFrame`도 더 이상 `ctx.filter`를 쓰지 않는다.
- 오프스크린 축소 렌더링(scratch canvas) 경로를 전량 제거했다 — `BLOB_SCRATCH_SCALE`,
  `BLOB_SCRATCH_MIN_BLUR_PX`, `prepareScratch()`, `BlobFrameOptions.scratch`, `drawBlobFrame`의
  `useScratch` 분기. CSS filter는 GPU 합성이라 이 최적화가 필요 없어졌다.
- `blobBlurRadiusPx()`를 export해 `BlobAnimationBackground`가 직접 쓸 수 있게 했다. 계산식
  자체(`blur * minDim * 0.15 * (opaque ? 0.5 : 1)`)는 그대로 유지했다.
- `BlobAnimationBackground.tsx`: scratch 캔버스 생성 코드를 제거하고, `render()` 안에서
  `canvas.style.filter`를 blur 반경으로 설정하되 **직전에 쓴 문자열과 다를 때만** DOM에 쓴다
  (매 프레임 쓰기로 인한 강제 리플로우 방지 — opacity에서 이미 겪은 함정 재발 방지).
  - **CSS 픽셀 vs 백킹 스토어 픽셀 보정**: 예전 `ctx.filter`는 캔버스 백킹 스토어(device pixel)
    좌표계에서 블러를 적용한 뒤 CSS 크기로 축소 표시돼, 실질 시각 블러가 `반경/dpr`이었다.
    CSS `filter: blur(Npx)`의 `N`은 이미 CSS 픽셀 단위라 dpr로 나눌 필요가 없다. 이 차이를
    반영하지 않으면 dpr(모바일 1.5, 데스크톱 2)만큼 블러가 진해진다 — `blobBlurRadiusPx`의
    `minDim` 인자를 캔버스 백킹 크기가 아니라 **CSS 크기(`cssWidth`/`cssHeight`)**로 넘겨
    시각적 반경이 예전과 동일하도록 맞췄다. (스펙 문서에는 이 보정이 명시돼 있지 않아 직접
    도출했다 — 근거는 "주요 의사결정" 절 참조.)
- 테스트: 기존 파일에 scratch 관련 테스트는 원래 없었다(파악 결과, `drawBlobFrame`을 직접
  테스트하는 코드가 없었음). `blobBlurRadiusPx`를 export한 김에 수치 계산 회귀 테스트 3개를
  새로 추가했다(선형 비례, opaque 절반, blur=0 → 반경 0).

### 주요 의사결정 / 핵심 메모
- **CSS 픽셀 보정을 직접 도출한 근거**: 티켓 본문은 "시각적 결과는 동일해야 한다"고만 규정하고
  dpr 보정을 명시하지 않았다. 그러나 예전 `ctx.filter` blur는 캔버스 백킹 스토어(device pixel)
  좌표계에서 적용된 뒤 CSS 크기로 다운스케일 표시되므로, 대입값 R(backing px)이 화면에는
  R/dpr(CSS px 단위 시각 반경)로 보인다. `blobBlurRadiusPx(blur, minDim, opaque)`가 `minDim`에
  비례하므로, `minDim`을 backing 크기 대신 CSS 크기로 넣으면
  `blobBlurRadiusPx(blur, cssMinDim) = blobBlurRadiusPx(blur, backingMinDim) / dpr`이 대수적으로
  성립해(∵ `backingMinDim = cssMinDim * dpr`) 정확히 예전과 같은 시각적 반경이 나온다. dpr을
  그대로 두고 backing 크기를 CSS filter에 넘겼다면 dpr 배(모바일 1.5배, 데스크톱 최대 2배)만큼
  더 흐려 보이는 회귀가 났을 것이다.
- **DB 영향 없음 확인**: 티켓 명시대로 `background_animation`이 저장된 행이 0건이라(배지
  0/2194, 컬렉션 0/100, 세계관 0/10) 백필·마이그레이션이 필요 없다. 확인만 하고 실행하지
  않았다(변경 자체가 없었으므로).
- **iOS Simulator 미검증**: 이 환경(샌드박스 bash)에 Xcode/`simctl`이 없어 실제 iOS Simulator
  구동이 불가능했다. 대신 Playwright의 WebKit 엔진(Safari와 동일 렌더링 계열)으로 CSS
  `filter: blur()`가 정상 동작함을 확인했다. 다만 Playwright WebKit은 최신 빌드(26.5)라
  iOS Safari 17.4 미만의 실제 재현은 아니다 — 이번 수정의 핵심 근거는 "CSS `filter`가
  iOS Safari **9**부터 지원된다"는 사양 자체(ctx.filter의 17.4 하한보다 훨씬 이전)이지 실기기
  재현이 아니므로, 사양 근거와 최신 WebKit 렌더링 확인을 결합해 confidence를 medium으로
  잡았다(low가 아닌 이유: 계산식·렌더링 경로 자체는 실제로 동작을 확인했다).
- **admin 화면 자체는 미검증**: dev-login 테스트 계정(`dev-tester@jam.local`)이 admin 권한이
  없어(ADMIN_EMAILS 미설정, `is_admin` 컬럼) `/admin/badges/new`의 실제 블러 슬라이더 UI는
  이번 세션에서 열지 못했다. DB에 `is_admin`을 세팅해 우회할 수도 있었지만, 진단 목적의 DB 쓰기라도
  직접 실행하지 않는다는 절대 규칙(SQL 마이그레이션 작성까지만, 실행은 오케스트레이터)을 지켜
  대신 `BlobAnimationBackground`를 실제 프로덕션 코드 그대로 별도 공개 라우트(스파이크,
  커밋 전 삭제)에 마운트해 렌더링 로직 자체를 검증했다. 어드민 폼의 슬라이더 UI 자체(값 바인딩
