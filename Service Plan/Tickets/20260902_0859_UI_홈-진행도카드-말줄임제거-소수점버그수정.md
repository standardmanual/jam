# [UI] 홈 진행도 카드 말줄임 제거 및 소수점 버그 수정

## 배경 / 문제 정의
홈 페이지 상단 "내 진행도" 카드(`TodayStatusStrip`)에서 두 가지 문제가 발견됨.

1. 진행도 텍스트(예: "전체 활동 누적 300km 245.99999999999997/300")에 Tailwind `truncate`
   클래스가 적용되어 있어 텍스트가 말줄임(ellipsis) 처리된다. 사용자는 이 말줄임을 원하지 않음.
2. `current` 값이 `245.99999999999997`처럼 소수점이 비정상적으로 길게 표시된다.
   개별 활동의 `distanceKm`은 `metersToKm()`에서 이미 소수 2자리로 반올림되어 있지만,
   `calculateProgress()`(distance·elevation_gain_m 케이스)가 이를 `reduce`로 합산한 뒤
   반올림 없이 그대로 반환해 IEEE-754 부동소수점 오차가 그대로 노출됨.

## 상세 요구사항

### 서비스/코드베이스 관점
- `src/lib/missions/checker.ts`의 `calculateProgress()` — `distance`(약 456번 줄)와
  `elevation_gain_m`(약 481번 줄) 케이스의 `reduce` 합산 결과를 반올림 처리
  (예: 소수 2자리로 `Math.round(sum * 100) / 100`)
- 기존에 이미 `progress_value`로 저장된 오염 데이터(부동소수점 잔여값)가 있다면 재계산 시
  자연히 정정됨 — 별도 백필 불필요 (트리거 시점에 재계산되는 구조인지 확인)

### UI/UX 관점 (해당 시)
- `src/app/(main)/TodayStatusStrip.tsx`의 진행도 텍스트 `<p>` 태그에서 `truncate` 클래스 제거
  (또는 정당한 사유가 있다면 유지하되 근거를 완료 기록에 남길 것)

## 구현 계획
1. `TodayStatusStrip.tsx`에서 `truncate` 클래스 제거 (레이아웃 깨짐 없는지 확인)
2. `checker.ts`의 `calculateProgress()` distance·elevation_gain_m 케이스에 반올림 로직 추가
3. 관련 테스트(`missions/checker` 테스트 존재 시) 실행 및 필요 시 업데이트

## 구현 기록 (2026-09-02)
- `TodayStatusStrip.tsx` 진행도 텍스트 `<p>`에서 `truncate` 클래스 제거.

  구조를 확인함 — 별도 백필 불필요.
