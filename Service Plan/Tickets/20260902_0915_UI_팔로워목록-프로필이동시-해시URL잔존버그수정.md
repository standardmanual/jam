# [UI] 팔로워 목록에서 프로필 이동 시 해시 URL 잔존 버그 수정

## 배경 / 문제 정의
`/profile` 화면(`src/app/(main)/profile/ProfileClient.tsx`)은 팔로워/팔로잉 탭 상태를
URL 해시로 관리한다(`window.location.hash = tab`, 약 215행). 이 탭이 열린 상태(예:
`/profile#followers`)에서 팔로워 프로필이미지 또는 아이디/이름(`ListRowCard`, `Link
href={`/${u.username}`}`)을 클릭하면, Next.js 클라이언트 라우팅이 pathname만 교체하고
기존 `location.hash`를 지우지 않아 최종 URL이 `/{username}#followers` 형태로 남는다.

기대 동작: 팔로워 프로필이미지/아이디·이름을 클릭하면 해시 없이
`https://j-a-m.app/[아이디]` 형태의 클린 URL로 이동해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `src/app/(main)/profile/ProfileClient.tsx`의 팔로워/팔로잉 리스트 아이템(`ListRowCard`)
  클릭 시, 이동 직전에 잔존 `location.hash`를 제거한다.
- `/[username]/followers/page.tsx`, `/[username]/following/page.tsx`는 이미 해시를 쓰지
  않는 정상 패턴이므로 변경 불필요 — 회귀 없는지만 확인.
- `ListRowCard`(`src/components/ui/ListRowCard.tsx`)가 `href`와 별도로 `onClick`을
  받아 `Link`에 전달하는지 확인하고, 없다면 이동 전 hash 제거 로직을 넣을 수 있는
  지점을 찾는다 (예: `Link`의 `onClick` prop 활용, 또는 `history.replaceState`로
  네비게이션 직전 정리).

## 구현 계획
- `ListRowCard` 또는 호출부에서 클릭 시 `history.replaceState(null, '', 경로만)`으로
  해시를 먼저 제거한 뒤 Next 라우터의 기본 네비게이션이 이어지도록 처리.
- 다른 해시 의존 로직(탭 상태 복원 등)에 회귀가 없는지 확인.

---
## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`ListRowCard`(`src/components/ui/ListRowCard.tsx`)에 `href`와 함께 쓰는 `onNavigate?: () => void`
prop을 추가해 `Link`의 `onClick`으로 전달하도록 했다. `/profile` 화면(`ProfileClient.tsx`)의
팔로워/팔로잉 리스트 아이템에서 이 `onNavigate`로 `window.location.hash`가 남아 있을 때만
`history.replaceState(null, '', pathname + search)`를 호출해 해시를 제거한 뒤 Next의 기본
Link 네비게이션이 이어지도록 했다. `history.replaceState`는 `hashchange` 이벤트를 발생시키지
않으므로 기존 탭 상태 복원 로직(`hashchange` 리스너, 약 199~211행)에는 영향이 없다.
`/[username]/followers`, `/[username]/following` 페이지는 애초에 해시를 쓰지 않아 새 prop을
전달하지 않고 기존 동작 그대로 유지된다.
