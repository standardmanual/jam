# [UI] 배지 목록에서 상세 이동 시 해시 URL 잔존 버그 수정

## 배경 / 문제 정의
티켓 `20260902_0915`(팔로워 목록 해시 URL 잔존 버그 수정)의 개선 리뷰에서, 동일한 구조가
`/badges` 화면(`src/app/(main)/badges/BadgesClient.tsx`)에도 있다는 범위 밖 이슈가
발견됐다(`task_d7269786`).

`BadgesClient`는 활동/체크인/컬렉션 탭 상태를 URL 해시로 관리한다
(`window.history.replaceState(null, '', '#' + key)`, 약 107행). 이 상태에서
(예: `/badges#checkin`) 배지 그리드 카드(`BadgeGridCard`, `href={/badges/${badge.id}}`,
228행·276행)를 클릭해 상세 페이지로 이동하면, Next.js 클라이언트 라우팅이 pathname만
교체하고 기존 `location.hash`를 지우지 않아 최종 URL이 `/badges/{id}#checkin` 형태로
남는다. `ListRowCard`/`ProfileClient`와 동일한 버그 패턴이다.

기대 동작: 배지 카드를 클릭하면 해시 없이 `https://j-a-m.app/badges/{id}` 형태의 클린
URL로 이동해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `BadgeGridCard`(`src/components/ui/BadgeGridCard.tsx`)에 `ListRowCard`와 동일한 패턴으로
  `onNavigate?: () => void` prop을 추가하고, `href` 모드의 `Link`에 `onClick={onNavigate}`로
  전달한다.
- `BadgesClient.tsx`의 활동 탭(228행 부근)·체크인 탭(276행 부근) `BadgeGridCard` 호출부에서
  이동 직전 `window.location.hash`가 남아있으면 `history.replaceState`로 제거하는
  `onNavigate` 콜백을 전달한다.
- 컬렉션 탭의 `CollectionGridCard`는 별도 컴포넌트이므로 이번 티켓 범위에서는 재현 여부만
  확인하고, 필요하면 별도로 기록한다(컬렉션 탭도 동일한 해시 관리 구조를 공유하므로 잠재적
  동일 버그 대상).
- `history.replaceState`는 `hashchange` 이벤트를 발생시키지 않으므로 기존 탭 상태 popstate
  복원 로직(96~102행)에는 영향이 없는지 확인.

## 구현 계획
- `ListRowCard`/`ProfileClient` 수정과 동일한 접근: 컴포넌트에 `onNavigate` prop 추가 →
  호출부에서 해시 제거 콜백 전달.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`BadgeGridCard`(`src/components/ui/BadgeGridCard.tsx`)에 `ListRowCard`와 동일한 패턴으로
`href`와 함께 쓰는 `onNavigate?: () => void` prop을 추가해 `Link`의 `onClick`으로 전달하도록
했다. `/badges` 화면(`BadgesClient.tsx`)에 `clearHashOnNavigate` 콜백을 정의해, 활동 탭·
체크인 탭의 `BadgeGridCard` 호출부에서 이 콜백을 `onNavigate`로 전달했다. `window.location.hash`가
남아 있을 때만 `history.replaceState(null, '', pathname + search)`를 호출해 해시를 제거한 뒤
Next의 기본 Link 네비게이션이 이어지도록 했다. `history.replaceState`는 `hashchange`/`popstate`
이벤트를 발생시키지 않으므로 기존 탭 상태 popstate 복원 리스너(96~102행)에는 영향이 없다.
Next `Link`는 전달받은 `onClick`을 라우팅 시작 전에 동기 실행하므로(실측 확인) 타이밍 문제도 없다.
컬렉션 탭(`CollectionGridCard`)은 이번 범위에서 제외했다.
