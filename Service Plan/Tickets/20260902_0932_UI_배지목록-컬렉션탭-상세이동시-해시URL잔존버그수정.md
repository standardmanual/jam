# [UI] 배지목록 컬렉션 탭에서 상세 이동 시 해시 URL 잔존 버그 수정

## 배경 / 문제 정의
티켓 20260902_0923에서 `/badges` 화면의 활동/체크인 탭에 있던 해시 URL 잔존 버그를
`BadgeGridCard`에 `onNavigate` prop을 추가해 수정했다. 그러나 같은 화면의 **컬렉션 탭**은
아이템북 카드를 `CollectionGridCard`로 렌더하는데, 이 컴포넌트는 `href`만 받는 `Link` 래퍼라
`onNavigate`/`onClick` 훅이 없다. `BadgesClient.tsx`의 컬렉션 탭 호출부(약 299~309행)도
`clearHashOnNavigate`(0923에서 추가된 헬퍼)를 전달하지 않는다.

즉 `/badges#collection` 상태에서 컬렉션 카드를 클릭하면 `/collections/{id}?from=badges`로
이동해도 기존 `#collection` 해시가 지워지지 않고 `/collections/{id}?from=badges#collection`
형태로 남을 것으로 예상된다 — 코드 확인 결과 재현 조건이 그대로 성립한다(직접 브라우저 재현은
생략하고 코드 경로로 확정. 활동/체크인 탭과 100% 동일한 구조이며 0923에서 이미 검증된 패턴).

## 상세 요구사항

### 서비스/코드베이스 관점
- `CollectionGridCard`(`src/components/ui/CollectionGridCard.tsx`)에 `onNavigate?: () => void`
  prop을 추가하고 `href` 모드의 `Link`에 `onClick={onNavigate}`로 전달한다
  (`BadgeGridCard`·`ListRowCard`와 동일한 패턴).
- `BadgesClient.tsx`의 컬렉션 탭 `CollectionGridCard` 호출부에 이미 존재하는
  `clearHashOnNavigate` 헬퍼를 `onNavigate` prop으로 전달한다.
- `/collections/[id]` 화면 자체나 다른 `CollectionGridCard` 호출부(있다면)에 회귀가 없는지 확인.

## 구현 계획
- `CollectionGridCard`는 `href` 모드에서만 해시 제거가 의미 있다 (`onClick` 모드는 이동이
  아니므로 대상 아님) — `BadgeGridCard`와 동일하게 `Link`에만 `onClick` 연결.
- 다른 `CollectionGridCard` 사용처가 있는지 `grep`으로 확인 후 필요한 곳에만 prop 전달.

### 구현 내용 요약
`CollectionGridCard`에 `onNavigate?: () => void` prop을 추가하고 `href` 모드의 `Link`에
`onClick={onNavigate}`로 연결했다 (`BadgeGridCard`와 동일한 패턴). `BadgesClient.tsx`의
컬렉션 탭 `CollectionGridCard` 호출부에 기존 `clearHashOnNavigate` 헬퍼를 `onNavigate`로
전달했다. `CollectionGridCard`의 다른 호출부인 `ProfileClient.tsx`(`/profile` 화면)는 탭 상태를
해시로 관리하지 않으므로 대상이 아니라 건드리지 않았다.
