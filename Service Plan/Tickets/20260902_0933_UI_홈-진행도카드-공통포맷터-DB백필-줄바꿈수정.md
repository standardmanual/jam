# [UI] 홈 진행도 카드 공통 포맷터 도입 + DB 백필 + 줄바꿈 수정

## 배경 / 문제 정의
티켓 20260902_0859(홈 진행도카드 말줄임 제거·소수점 버그 수정)를 프로덕션 배포했으나,
사용자가 실기기에서 여전히 "245.99999999999997/300" 노출과 텍스트 카드 밖 넘침(overflow)을
확인함. 재조사 결과 근본 원인 2가지가 추가로 확인됨.

1. **DB 백필 누락**: `progress_value`는 `checkMissions()`(`src/lib/missions/checker.ts`)가
   Strava 활동 동기화 시점(`src/lib/strava/sync.ts:584`)에만 재계산해 저장한다. 코드에
   반올림 로직을 추가해도 **이미 저장된 기존 로우는 다음 동기화 전까지 옛날 오염값 그대로
   남는다.** 이게 프로덕션에서 버그가 재현되는 직접 원인.
2. **공통 포맷터 부재 + 정책 불일치**: 서비스 전체에 거리·진행도 표시용 공통 포맷터가 없다.
   - `MissionDetailClient.tsx:295`: `progressValue.toFixed(1)` (거리), `Math.floor()` (그 외)
   - `MissionStatusClient.tsx:103-104`: 로컬 `formatProgress()` — 위와 다른 조건부 로직
   - `TodayStatusStrip.tsx`(`ko.ts:219`의 `progressLabel` 템플릿): **포맷팅 전무**, DB 원시값
     그대로 문자열 보간
   각 화면이 제각각의 자릿수 규칙을 써서 같은 미션의 진행도가 화면마다 다르게 보일 수 있음.
3. **줄바꿈 없음**: `TodayStatusStrip.tsx`의 진행도 텍스트 `<p>`에 `break-words`나
   `overflow-wrap` 없이 공백 없는 긴 숫자 토큰을 담아 카드 폭을 넘으면 그대로 넘친다.

## 상세 요구사항

### 서비스/코드베이스 관점
1. **공통 포맷터 신설**: 거리(km)·기타 수치(고도 m 등)를 일관되게 표시하는 공통 함수를 만들어
   `TodayStatusStrip.tsx`(`progressLabel` 렌더 지점), `MissionDetailClient.tsx:295`,
   `MissionStatusClient.tsx`의 `formatProgress()`가 모두 이 함수를 쓰도록 통일.
   - 정책: 거리(distance) 소수 1자리(`toFixed(1)`), 그 외(count·checkin 등 정수형) `Math.floor`
     또는 정수 표시 — 기존 `MissionDetailClient.tsx:295`의 관례를 기준으로 통일
     (`UX_WRITING_GUIDELINE.md` "거리/기록은 사용자 일상어 단위 유지" 원칙에 부합)
   - 위치 제안: `src/lib/missions/` 또는 `src/lib/format/` 하위에 신규 유틸 파일
2. **DB 백필**: 기존 `user_mission_participations.progress_value`의 부동소수점 오염값을
   `calculateProgress()` 로직(반올림 포함)으로 재계산해 일괄 UPDATE하는 SQL 또는 스크립트 작성.
   실행은 사용자 승인 후 오케스트레이터가 직접 진행(project CLAUDE.md 5번 규칙).
3. **줄바꿈 수정**: `TodayStatusStrip.tsx`의 진행도 텍스트 `<p>`에 `break-words`(또는
   `whitespace-normal` + `overflow-wrap: anywhere`) 추가해 카드 밖으로 넘치지 않게.

### UI/UX 관점
- 카드 폭을 넘지 않게 자연스럽게 줄바꿈되는지 실제 브라우저에서 확인
- 포맷 통일 후 미션 상세·미션 현황·홈 진행도 카드 세 화면에서 같은 미션의 진행도가 일관되게
  보이는지 확인

## 구현 계획
1. 공통 포맷터 유틸 작성 및 3개 호출부(TodayStatusStrip, MissionDetailClient,
   MissionStatusClient) 교체
2. `TodayStatusStrip.tsx` 텍스트 줄바꿈 CSS 수정
3. DB 백필 SQL/스크립트 작성 (jam-developer는 파일 작성까지만, 실행은 오케스트레이터)
4. 브라우저에서 실제 오버플로우·포맷 통일 여부 확인

## 구현 기록 (2026-09-02)

### 공통 포맷터
- `src/lib/missions/format.ts` 신규 작성: `formatMissionProgress(value, missionType)`.
  `missionType === 'distance'`면 `toFixed(1)`, 그 외는 `Math.floor` 후 정수 문자열.

### 호출부 교체
- `MissionDetailClient.tsx:295` — 기존 `progressValue.toFixed(1)`/`Math.floor()` 3항 분기를
  `formatMissionProgress(progressValue, mission.mission_type)`로 교체.
- `MissionStatusClient.tsx` — 로컬 `formatProgress()`(소수 유무로만 판단, mission_type 무관)를
  제거하고 `formatMissionProgress()`로 통일. 이 컴포넌트는 원래 `mission_type`을 받지 않아
  포디엄(`PodiumColumn`)·순위 목록(`RankingListRow`)·내 순위 카드(`MyRankCard`)·개인형 진행도
  표시 4곳 모두 mission_type을 몰랐다 — `page.tsx`에서 `missions` 조회에 `mission_type`
  컬럼을 추가하고 `MissionStatusClient`에 `missionType` prop으로 내려 하위 3개 컴포넌트에
  모두 threading했다. 개인형(`data.type === 'individual'`) 브랜치에 있던 별도의 인라인
  중복 포맷 로직(`progressValue.toFixed(progressValue % 1 === 0 ? 0 : 1)`, 소수점 오염값에
  같은 취약점을 가지고 있었음)도 함께 `formatMissionProgress()`로 교체.
- `TodayStatusStrip.tsx` — `progressLabel` 렌더 지점에 포맷 없이 DB 원시값을 그대로 보간하던
  것을 `formatMissionProgress()`로 교체. 이 컴포넌트는 미션 진행도뿐 아니라 아이템북 진행도도
  같은 슬롯에서 표시하므로(둘 다 `current`/`total`), `src/lib/today/status.ts`의
  `ProgressCandidate`/`TodayLeftStatus`에 `missionType: MissionType | null` 필드를 추가해
  아이템북 경로는 `null`(항상 정수 취급), 미션 경로는 실제 `mission.mission_type`을 흘려보내게
  했다.

### 줄바꿈 수정
- `TodayStatusStrip.tsx`의 `progressLabel` `<p>`에 `break-words [overflow-wrap:anywhere]` 추가.

### DB 백필
- `supabase/migrations/125_backfill_mission_progress_value_precision.sql` 작성(실행 안 함).
  `calculateProgress()`가 반올림(`Math.round(sum*100)/100`)을 적용하는 두 타입
  (`distance`, `elevation_gain_m`)만 대상으로 `ROUND(progress_value::numeric, 2)`로 정규화.
  `duration_minutes`는 원래도 반올림 로직이 없는 원본값(코드 의도)이라 대상에서 제외 —
  SQL 파일 상단에 근거 명시. STEP 1(진단 SELECT) → 사용자 승인 → STEP 2(UPDATE) 순서.

  숫자-슬래시 조합(`24.5/10` / `0.0`)까지 임의 위치에서 끊길 수 있다는 지적을 반영.
