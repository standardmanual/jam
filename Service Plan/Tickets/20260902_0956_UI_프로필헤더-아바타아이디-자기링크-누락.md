# [UI] 프로필 헤더의 아바타·아이디에 프로필 링크 누락

## 배경 / 문제 정의
`ProfileClient.tsx`(`src/app/(main)/profile/ProfileClient.tsx`, 약 465~517행)는 `/profile`
(본인)과 `/[username]`(타인) 양쪽에서 공용으로 쓰이는 프로필 상단 헤더를 렌더링한다. 이
헤더의 아바타 이미지(466~479행)와 아이디/이름 텍스트(494~498행)는 현재 어떤 링크나 클릭
핸들러도 없는 순수 정적 마크업이다.

티켓 20260902_0915에서 팔로워/팔로잉 목록 항목(`ListRowCard`)을 클릭하면 해시 없는
`/${username}` 클린 URL로 정상 이동하도록 고쳤는데, 그 결과 도착하는 프로필 상세 페이지
(예: `https://j-a-m.app/9irrun`) 자체의 상단 아바타·아이디에는 애초에 링크가 없다는 점이
이번에 확인됐다. 예: `https://j-a-m.app/9irrun` 페이지에 들어갔을 때 상단에 보이는 9irrun의
프로필이미지·아이디를 눌러도 아무 반응이 없다(자기 자신의 프로필 URL로도 연결되지 않음).

## 상세 요구사항

### 서비스/코드베이스 관점
- `ProfileClient.tsx`의 프로필 헤더에서 아바타 이미지와 아이디/이름 텍스트를 클릭하면
  현재 보고 있는 프로필의 URL(`/${profile.username}`)로 이동(또는 self-link)하도록 만든다.
- 본인 프로필(`isOwnProfile`)에서 아바타 옆의 편집 버튼(483~491행)·포인트 버튼
  (502~516행)의 기존 클릭 영역과 겹치지 않게 처리한다.
- 타인 프로필에서는 우측 팔로우 버튼(519~530행)의 클릭 영역과 겹치지 않게 처리한다.

## 구현 계획
- 아바타 이미지와 아이디 텍스트를 `next/link`의 `Link href={`/${profile.username}`}`로
  감싸거나, `ListRowCard`에 이미 추가된 `onNavigate` 패턴처럼 해시 정리가 필요하면 함께
  적용한다. 버튼(편집·포인트·팔로우)은 별도 상호작용 요소이므로 링크 영역에서 제외되도록
  DOM 구조를 주의해서 설계한다 (예: `<a>` 안에 `<button>` 중첩 금지 — 편집 버튼은 형제
  요소로 분리하거나 `stopPropagation` 처리).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`ProfileClient.tsx` 프로필 헤더의 아바타 이미지와 아이디 텍스트를 `next/link`의 `Link
href={`/${username}`}`로 감쌌다. 이 페이지는 `/profile`이 항상 `/{username}`으로 리다이렉트된
뒤 렌더되므로(본인·타인 공용 경로), 본인 프로필에서도 자기 자신의 프로필 URL로 연결되는
self-link가 자연스럽게 성립한다.

- 아바타: 기존 `relative` 컨테이너 내부에서 `<Image>`(또는 빈 아바타 placeholder)만 `<Link>`로
  감싸고, 편집 버튼(`<button>`)은 형제 요소로 그대로 둬 `<a>` 안에 `<button>`이 중첩되지
  않도록 했다. 편집 버튼의 절대 위치(`absolute -top-2 -right-2`)는 그대로 컨테이너 기준으로
  유지된다.
- 아이디: 기존 `<p>` 텍스트를 `<Link>`로 교체하고 동일한 타이포 클래스를 유지했다. 포인트
  버튼(`<button>`)은 여전히 형제 요소.
- 팔로우 버튼(타인 프로필)은 애초에 아바타·아이디 블록과 별도 flex 자식이라 겹치지 않는다.
- `ListRowCard`의 `onNavigate` 해시 정리 패턴(20260902_0915)과 동일하게, 두 `Link` 모두
  `onClick={clearProfileHash}`를 붙여 `#followers` 등 해시가 열린 상태에서 같은 페이지로
  self-link할 때 pathname이 같아 해시가 지워지지 않고 남는 문제를 방지했다.
