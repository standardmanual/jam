# [Admin] 투데이컨텐츠 어드민 화면을 날짜별 캘린더뷰로 전환

## 배경 / 문제 정의
현재 `/admin/today`는 `today_cards`(starts_at~ends_at 구간 기반 노출, exposure_tags OR매칭) 전체를
필터 없이 리스트로만 보여준다. 운영자가 "오늘/특정일에 무엇이 노출되는지"를 한눈에 파악하기 어렵고,
어드민에 실시간 미리보기 기능이 전혀 없어 저장 후 실제 홈 화면에서 재확인해야 한다.

기대 상태: 캘린더 일정 목록과 같은 개념으로, 날짜를 선택하면 해당일 노출 카드 목록만 보여주고
좌우로 날짜를 이동할 수 있는 화면.

## 상세 요구사항

### 서비스/코드베이스 관점
- `/admin/today` 화면을 아래 레이아웃으로 개편:
  ```
  < 현재 날짜 >   [미리보기]
  ------------------------
  선택 날짜의 카드 목록
  [+ 컨텐츠 추가]
  ```
- 상단: 좌우 화살표로 이전/다음 날짜 이동. 과거 날짜로 이동해도 해당일 조회 가능 (과거는 조회 목적,
  수정 가능 여부는 기존 화면과 동일하게 유지 — 별도 제한 없음)
- 목록: 선택된 날짜 기준 `starts_at <= 선택일 <= ends_at`인 카드를 나열한다. 여러 날짜에 걸쳐
  노출되는 카드는 그 구간에 포함되는 모든 날짜의 목록에 각각 나타난다 (구간 카드 = 매일 반복 노출로
  간주, 카드 자체를 날짜별로 복제하지 않음 — 기존 `today_cards` 스키마 변경 없음)
- 정렬 기준은 기존과 동일하게 `sort_order`(또는 기존 `TodayCardTable` 정렬 로직)를 따른다
- [컨텐츠 추가] 버튼: 클릭 시 기존 카드 생성 폼(현재 `TodayCardList.tsx`의 생성 동선)으로 이동.
  선택된 날짜를 생성 폼의 초기값(starts_at)으로 프리필하는 건 선택 사항 — 구현 편의에 따라 판단

### UI/UX 관점 (해당 시)
- [미리보기] 버튼: 선택한 날짜를 기준으로 그 날짜에 실제 유저가 봤을/볼 화면을 **시뮬레이션**한다.
  실제 라이브 페이지를 그대로 띄우는 게 아니라, 선택 날짜 기준 노출조건(`getTodayCards` 로직 재사용
  또는 해당 날짜를 인자로 넘긴 등가 쿼리)으로 카드 목록을 재현해 보여준다.
  - 유저向 노출조건 중 `exposure_tags`는 시간대/참여미션/신규유저 등 **유저 개인화 조건**을 포함한다
    (`src/lib/today/exposure.ts`). 어드민 미리보기는 특정 유저 컨텍스트가 없으므로, `is_active` +
    날짜 구간만으로 필터링하고 개인화 태그 조건은 무시(또는 'all' 기준)하는 것으로 단순화한다.
    구현 중 더 나은 접근이 있다면 결정 사항으로 티켓에 남길 것.
- MODULAR 디자인 시스템 적용 대상 아님 (admin 유형 — 탐색 생략). 기존 어드민 shadcn/ui 컴포넌트
  스타일을 따른다.

### 컨텐츠 관점 (해당 시)
- 해당 없음 (화면 로직 변경, 데이터 스키마 변경 없음)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`/admin/today`를 `?date=YYYY-MM-DD`(KST 달력 기준) 쿼리로 페이지 자체를 서버에서 다시
조회하는 날짜별 캘린더뷰로 전환했다.

- `page.tsx`가 `searchParams.date`를 읽어 선택 날짜를 정하고, `today_cards` 조회에
  `starts_at <= 그날 23:59:59.999 AND ends_at >= 그날 00:00:00`(KST) 조건을 추가했다 —
  구간에 걸친 카드는 그 구간에 포함되는 모든 날짜의 조회 결과에 각각 나타난다(복제 없음,
  단순 필터 조건이므로 자연히 만족).
- 상단에 `TodayDateNav`(좌우 화살표로 `router.push('?date=...')`, 가운데 날짜 라벨,
  [미리보기] 버튼)를 추가했다. 과거 날짜도 동일 경로로 조회 가능(별도 제한 없음).
- `TodayCardList`의 레이아웃을 요구된 순서(목록 → `+ 컨텐츠 추가` → 폼)로 재배치했다.
  `+ 컨텐츠 추가` 클릭 시 선택 날짜를 시작 일시 초기값(`{selectedDate}T00:00`)으로
  프리필한다(선택 사항으로 명시된 편의 기능, 구현함).
- [미리보기]는 `TodayPreviewModal`(shadcn Dialog) → `/api/admin/today/preview?date=...` →
  `getAdminTodayPreviewCards()`(`is_active=true` + 날짜 구간만 필터, `exposure_tags`
  개인화·미션 노출 필터는 스킵) → 유저向 실제 홈 화면과 **같은 컴포넌트**(`TodayCardStack`,
  `src/app/(main)/TodayCardStack.tsx`)를 그대로 재사용해 렌더링한다. 해당 컴포넌트와
  `getTodayCards()`는 이 티켓에서 수정하지 않았다(읽기 전용 재사용, 타입·순수 함수만 import).
  admin은 MODULAR 신규 UI 판정 대상이 아니지만, 미리보기의 목적 자체가 "실제 화면 재현"이라
  실제 유저向 컴포넌트를 그대로 쓰는 편이 더 정확하다고 판단했다.

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- 구간형 카드는 포함되는 모든 날짜의 목록에 각각 나타나는 것으로 확정 (매일 반복 노출 개념,
  카드 복제 없음) — 사용자 확인 완료 (2026-09-02)
- 미리보기는 라이브 페이지 임베드가 아닌 선택 날짜 기준 시뮬레이션으로 확정 — 사용자 확인 완료
  (2026-09-02)
- 날짜 경계는 KST(Asia/Seoul, UTC+9 고정) 달력 기준으로 확정 — `lib/notifications/kst.ts`의
  `KST_OFFSET_MS`와 동일 근거(서비스 전역이 이미 이 기준을 채택 중, 티켓에 명시적 지정은
  없었으나 일관성을 위해 이 기준을 택함).
- 미리보기 조회는 `getTodayCards()`를 직접 확장하지 않고 별도 함수(`getAdminTodayPreviewCards`)로
  분리했다 — 티켓이 유저向 로직(`getTodayCards`, `TodayCardStack.tsx`)을 "읽기 전용 참조만"
  하도록 명시했기 때문. 대신 화면 렌더링은 `TodayCardStack`을 그대로 재사용해 시각적 정확도를
  유지했다(위 "구현 내용 요약" 참고).
- 목록(전체 카드, 활성/비활성 무관)과 미리보기(활성 카드만)는 서로 다른 필터라 별도 쿼리로
  분리했다 — 목록은 운영 관리 목적(비활성 카드도 봐야 편집 가능), 미리보기는 유저 체감
  시뮬레이션 목적으로 역할이 다르다.
