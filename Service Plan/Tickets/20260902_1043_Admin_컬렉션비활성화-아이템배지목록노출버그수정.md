# [Admin] 컬렉션 비활성화 시 어드민 "배지 슬롯 관리" 목록이 사라지는 버그 수정

## 배경 / 문제 정의
어드민 컬렉션 관리(`/admin/itembooks/[id]`)에서 컬렉션을 비활성화하면 컬렉션에 배정된
("컬렉션에 포함되도록 설정된") 아이템 배지 목록이 어드민 화면에서도 통째로 사라진다.
사용자 보고: "컬렉션을 비활성화 하면 컬렉션에 포함되도록 설정된 아이템 배지 목록이 사라짐.
사라지면 안됨."

### 원인
[20260823_004](./20260823_004_Admin_컬렉션비활성화-배지연쇄회수.md)에서 "컬렉션 비활성화 →
소속 아이템배지를 유저에게서 회수" 기능이 의도적으로 도입됐다. `item_books.is_active`를
끄면 `badges.item_book_id = 해당 컬렉션 AND deleted_at IS NULL`인 배지 전체에
`deleted_at = now()`가 세팅된다 (`src/lib/admin/itembook-deactivation.ts`). **이 설계 결정
자체는 유지한다** — 유저 노출 회수는 의도된 동작이다.

문제는 어드민 자신의 배지 배정 목록도 같은 `deleted_at IS NULL` 필터를 그대로 재사용하는
것이다:
- `src/app/admin/itembooks/[id]/page.tsx:20` — 컬렉션 수정 화면에 넘길 `slottedBadges`를
  `.is('deleted_at', null)`로 조회 → 컬렉션이 비활성화되면 빈 배열이 되어
  `ItemBookForm.tsx`의 "배지 슬롯 관리" 섹션이 "등록된 배지가 없습니다"로 표시된다.
- 하지만 `badges.item_book_id`(배정 관계) 자체는 그대로 남아있다 — 배지는 여전히 이
  컬렉션 소속이지만 어드민이 그 사실을 확인·관리(개별 재활성화, 배정 해제 등)할 방법이
  없어진다.

### 확인된 실제 영향 (2026-09-02)
DB 조회 결과, 오늘 09:05~09:07(KST)에 컬렉션 18개가 일괄 비활성화되며 소속 아이템 배지
162개(컬렉션당 9개씩)가 이 캐스케이드로 `deleted_at`이 세팅됐다. 해당 18개 컬렉션은 현재도
`is_active=false` 상태다. 사용자 확인 결과, **유저 노출 회수는 의도된 동작이므로 그대로
유지**하고(`deleted_at`을 되돌리지 않음), **어드민 화면에서만 이 162개를 포함한 전체
배정 목록이 다시 보이도록** 이번 버그를 수정하는 것으로 복원을 대신한다 — 즉 별도 DB 복원
작업 없이, 아래 코드 수정만으로 이 18개 컬렉션의 배지 목록도 자동으로 다시 보이게 된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `src/app/admin/itembooks/[id]/page.tsx`: `slottedBadges` 조회에서 `.is('deleted_at', null)`
  필터를 제거하고, `deleted_at` 컬럼을 select에 추가한다. `item_book_id = id AND type = 'item'`
  조건은 유지(= 이 컬렉션에 배정된 전체 배지, 활성/비활성 무관).
- `src/app/admin/itembooks/ItemBookForm.tsx`:
  - `slottedBadges` prop 타입에 `deleted_at` 추가.
  - "배지 슬롯 관리" 목록에서 `deleted_at`이 있는(비활성) 배지는 시각적으로 구분 표시
    (예: 흐리게 처리 + "비활성" 상태 텍스트/배지). 목록 자체에서 제외하지 않는다.
  - 비활성 배지를 개별적으로 다시 활성화할 수 있는 수단 제공 — 이미 있는
    `BadgeActiveToggleButton`(`src/components/admin/badges/BadgeActiveToggleButton.tsx`,
    `PATCH /api/admin/badges/[id]` `{active: boolean}` 재사용, 20260823_006에서 구현됨)을
    각 배지 행에 붙인다. 새 API를 만들지 않는다.
  - 상단 "N개 배지 등록됨" 카운트는 배정된 전체 개수(활성+비활성)로 표시할지, 활성 개수만
    표시할지 구현 시 판단 — 목록 자체가 전체를 보여주므로 전체 개수로 표시하는 쪽을 권장
    (목록 항목 수와 카운트가 일치해야 혼란이 없다).
  - `ItemBookDetail`에 넘기는 `itemBadgeCount`(상세 정보 "소속 아이템배지" 표시)는 기존처럼
    활성 배지 수만 의미해도 무방(리스트 페이지의 "아이템 배지 수" 컬럼과 같은 의미로 유지) —
    이 값은 이번 버그(목록이 통째로 사라지는 문제)와 무관하므로 그대로 두거나, 위 카운트
    선택과 일관되게만 맞추면 된다. 무엇을 선택했는지 완료 기록에 남길 것.
