# [Admin] 투데이컨텐츠 캘린더뷰 `date` 쿼리 파라미터 달력 유효성 미검증

## 배경 / 문제 정의
티켓 20260902_1028(투데이컨텐츠 캘린더뷰 전환, staging 커밋 `f434ef85`)에서 발견된 사이드
이슈. `jam-web/src/lib/admin/today-calendar.ts`의 `normalizeDateParam`이
`/admin/today?date=YYYY-MM-DD` 쿼리 파라미터를 정규식(`/^\d{4}-\d{2}-\d{2}$/`)으로 형식만
검증하고, `new Date(...)` 파싱 결과가 `NaN`인지만 확인한다. 자바스크립트 `Date`는 달력상
존재하지 않는 날짜(예: `2026-02-30`)를 오버플로우 보정해 조용히 다음 달(`2026-03-02`)로
넘겨버리므로 `Number.isNaN` 체크를 통과한다 — 즉 형식만 맞으면 실제로는 존재하지 않는
날짜도 "유효한 값"으로 그대로 통과된다.

정상 UI 네비게이션(`TodayDateNav`의 좌우 화살표, `shiftDateStr` 사용)은 항상 달력상 유효한
날짜만 생성하므로 실사용 경로에는 영향이 없다. URL을 수동으로 조작했을 때만 발생하는 낮은
우선순위 엣지케이스다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `normalizeDateParam`이 형식뿐 아니라 실제 달력 유효성까지 검증하도록 수정
  (오버플로우 보정 여부를 잡아내는 방법이면 방식은 자유 — 예: 파싱한 년/월/일로 UTC
  타임스탬프를 만든 뒤 `getUTCFullYear/Month/Date`로 되읽어 원래 값과 일치하는지 비교)
- 유효하지 않은 날짜가 들어오면 기존 폴백 관례(형식 오류·값 없음과 동일하게 오늘 날짜로
  대체)를 그대로 따른다 — 별도 400 응답 등 새로운 동작을 도입하지 않는다
- `today-calendar.test.ts`에 `2026-02-30` 등 달력상 존재하지 않는 날짜 케이스 유닛테스트 추가

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`normalizeDateParam`이 형식 검증(정규식)과 `NaN` 체크만 하던 것을, 파싱한 년/월/일로
`Date.UTC`를 만든 뒤 `getUTCFullYear/Month/Date`로 되읽어 원래 값과 일치하는지 대조하는
`isValidCalendarDateStr` 헬퍼를 추가해 실제 달력 유효성까지 검증하도록 수정했다.
`2026-02-30`처럼 오버플로우 보정되는 값은 되읽었을 때 3월로 어긋나므로 걸러지고, 기존
관례대로 오늘 날짜로 대체된다. 새로운 400 응답 등은 도입하지 않았다. `page.tsx`·
`api/admin/today/preview/route.ts`는 `normalizeDateParam`의 반환값만 소비하므로 호출부
변경 없이 그대로 동작을 확인했다.
