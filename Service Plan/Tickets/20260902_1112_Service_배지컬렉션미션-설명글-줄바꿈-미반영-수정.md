# [Service] 배지·컬렉션·미션 설명글 줄바꿈 미반영 수정

## 배경 / 문제 정의
어드민에서 배지·컬렉션·미션의 설명(description)을 여러 줄로 입력해도, 서비스 화면에서는
줄바꿈이 사라지고 한 줄로 붙어서 표시된다. HTML은 기본적으로 텍스트 노드의 `\n`을 렌더링에
반영하지 않으므로(공백으로 합쳐짐), 해당 텍스트를 렌더링하는 요소에 `whitespace-pre-line`
(또는 동등한 `white-space: pre-line`)이 없으면 어드민에서 입력한 줄바꿈이 그대로 무시된다.

사전 조사 결과 원인이 두 갈래로 나뉜다:
1. **배지·컬렉션**: 어드민 폼은 `<textarea>`라 줄바꿈 입력 자체는 가능하고 저장 로직에도
   trim/replace가 없어 DB에는 `\n`이 그대로 저장된다. 문제는 순수하게 **서비스 렌더링 지점에
   `white-space: pre-line`이 없는 것.**
2. **미션**: 렌더링 지점도 동일하게 `white-space: pre-line`이 없을 뿐 아니라, 어드민 폼
   (`MissionList.tsx:186-188`)의 설명 필드가 `<textarea>`가 아니라 **`<input type="text">`다.**
   단일행 input은 Enter로 줄바꿈을 입력할 수 없고 붙여넣기 시에도 대부분 브라우저가 개행을
   제거/공백 치환하므로, **폼 필드 타입부터 고치지 않으면 미션은 애초에 줄바꿈을 입력할 방법이
   없다.**

### 서비스/코드베이스 관점

**A. 렌더링 지점에 `white-space: pre-line` 추가 (본문 전체 노출 3곳 — 확정 적용)**
1. 배지 상세 — `src/app/(main)/badges/[id]/BadgeHeroSection.tsx:106-111`
   (`<p>` className에 `whitespace-pre-line` 추가)
2. 컬렉션 상세 — `src/app/(main)/collections/[id]/ItemBookHeroSection.tsx:78-81`
   (inline `style` 객체이므로 `whiteSpace: 'pre-line'` 추가)
3. 미션 상세 — `src/app/(main)/missions/[id]/MissionDetailClient.tsx:196-198`
   (`<p>` className에 `whitespace-pre-line` 추가)

**B. 요약/카드형 노출 지점 — 적용하되 line-clamp와의 상호작용을 실제 화면에서 확인**
   (line-clamp는 시각적 줄 수를 세므로, 명시적 `\n`이 있으면 줄 소진이 빨라져 요약이 더 짧게
   잘릴 수 있다. 깨지거나 레이아웃이 무너지는 게 아니라 "예상보다 일찍 …로 잘림" 정도의 UX
   영향이므로, 적용 자체는 진행하되 브라우저에서 실제 배지/미션 데이터로 눈으로 확인할 것)
4. 배지 트리 카드 — `src/components/badges/BadgeTreeCard.tsx:49-52`
5. 배지 획득 연출 캐러셀 — `design-system/components/patterns/BadgeRevealCarousel.jsx:525-542`
   (`-webkit-line-clamp: 3`과 함께 `whiteSpace: 'pre-line'` 추가)
6. 미션 리스트 카드 — `src/app/(main)/missions/MissionsListClient.tsx:411-426`
   (`-webkit-line-clamp: 2`와 함께 `whiteSpace: 'pre-line'` 추가)

**C. 미션 어드민 폼 필드 타입 수정 (선행 필요 — 이게 없으면 미션은 줄바꿈을 입력할 수조차 없음)**
7. `src/app/admin/missions/MissionList.tsx:186-188`의 설명 입력을 `<input type="text">`에서
   `<textarea rows={3}>`로 변경 (배지 `BadgeForm.tsx:413-420`, 컬렉션 `ItemBookForm.tsx:325-332`와
   동일한 패턴을 따를 것). `onChange` 핸들러의 이벤트 타입(`ChangeEvent<HTMLInputElement>` →
   `ChangeEvent<HTMLTextAreaElement>`)도 함께 수정.

### UI/UX 관점
- 배지 상세·컬렉션 상세·미션 상세 화면에서 여러 줄 설명이 실제로 줄바꿈되어 보이는지 확인
- 카드형 요약 3곳(B)에서 line-clamp가 여전히 정상 동작하는지(카드 밖으로 안 넘치는지),
  줄바꿈 추가로 요약이 지나치게 일찍 잘리지는 않는지 육안 확인
- 어드민에서 미션 설명 textarea에 Enter로 줄바꿈을 입력하고 저장 → 서비스 화면 반영까지
  end-to-end 확인
