# [Content] 철학 페이지 원고 교체 + 섹션 제목 구조 추가

## 배경 / 문제 정의
`/philosophy` 페이지(티켓 20260901_2125에서 신규 도입)의 확정 원고를 사용자가 제공한 최신
Google Docs 원고("260902_JAM! Philosophy")로 전량 교체 요청. 문서 소스:
`https://docs.google.com/document/d/1ayE3NUw0A8937IThS_loX0KllRYEqszhEqTmxQQEKv8`

기존 원고는 10개 문단이 제목 구분 없이 flat하게 나열된 구조였으나, 신규 원고는 문서
아웃라인상 3개의 소제목("두 가지 약속", "의심스러운 계정을 바로 막지 않는 이유",
"땀 흘린 끝에 '빈손'은 없습니다")으로 섹션이 나뉘어 있어, 컴포넌트에 섹션 제목 렌더링
구조를 추가해야 원고 구조를 그대로 반영할 수 있음.

## 상세 요구사항

### 컨텐츠 관점
- `src/app/(main)/philosophy/page.tsx`의 `PARAGRAPHS` 상수를 신규 원고 전문으로 교체
- 원고는 Google Docs 내보내기(`export?format=txt`)로 받은 원문 그대로 사용 — 임의 윤문 금지
  (기존 페이지 코드 주석의 "확정 원고. 임의 수정·윤문 금지" 원칙 승계)

### 서비스/코드베이스 관점
- `PARAGRAPHS: string[]` 플랫 배열 → `SECTIONS: { heading?: string; paragraphs: string[] }[]`
  구조로 변경해 소제목 3곳을 `<h2>`로 렌더링
- 소제목 타이포는 기존 DS 토큰(`--text-h4`/`--leading-h4`/`--weight-h4`/`--tracking-h4`) 사용,
  신규 토큰 추가 없음
- 여백 서열: 섹션 간 `--spacing-64`(가장 큼) > 제목-본문 간 `--spacing-16` > 문단 간
  `--spacing-32` — 기존 페이지의 "위→아래로 좁아지는 서열" 원칙 유지, 제목은 자기 본문과
  붙고 다음 섹션과는 크게 떨어지도록

## 구현 계획
1. `SECTIONS` 데이터 구조로 교체, 원문 4개 섹션(인트로 무제목 1 + 소제목 3) 반영
2. 렌더링을 섹션 단위로 변경 (`<h2>` + 문단 그룹)
3. 파일 상단 주석에 원고 교체 이력·구조 변경 근거 追記
4. `tsc --noEmit`/`lint`로 회귀 없는지 확인, 브라우저에서 육안 확인

## 구현 기록 (2026-09-02)
- 원문 확보: Google Docs 공유 링크가 로그인 필요 상태라 처음엔 401. 사용자가 "링크가 있는
  모든 사용자"로 공유 설정을 바꾼 뒤 `curl -sL ".../export?format=txt"`로 원문을 있는 그대로
  받아옴 (WebFetch는 내부적으로 소형 모델이 프롬프트를 거쳐 요약해버려 "원문 그대로"가
  보장되지 않아 폐기 — curl 직접 다운로드로 전환).
- `src/app/(main)/philosophy/page.tsx`의 `PARAGRAPHS: string[]` → `SECTIONS: { heading?,
  paragraphs }[]`로 구조 변경. 원문 아웃라인의 소제목 3곳("두 가지 약속", "의심스러운 계정을
  바로 막지 않는 이유", "땀 흘린 끝에 '빈손'은 없습니다")을 `<h2>`로 렌더링, 기존 h4 토큰
  재사용(신규 토큰 추가 없음). 여백 서열: 섹션 간 `--spacing-64` > 소제목-본문 `--spacing-16`
  > 문단 간 `--spacing-32`.
- 원문은 curl로 받은 텍스트를 그대로 배열에 옮겨 담아 임의 윤문 없음.
- 검증: `npx tsc --noEmit -p .` 통과, `npx eslint` 대상 파일 통과. `npm run dev` 미리보기에서
  `get_page_text`/`read_page`로 전체 본문과 소제목 3곳이 원문과 정확히 일치함을 확인. 상단
  섹션의 스크린샷으로 제목-본문 간격이 의도한 서열대로 보이는 것도 확인(하단 두 섹션은
  브라우저 패널이 백그라운드로 전환되며 스크린샷이 검게 나와 육안 스크린샷은 생략, 대신
  `read_page`로 heading 역할 렌더링 확인).
- 이번 변경은 단일 파일(정적 원고+렌더링 구조)이라 별도 리뷰 파이프라인 없이 직접 처리
  (jam-work 스킬의 "경미 수정" 예외).
