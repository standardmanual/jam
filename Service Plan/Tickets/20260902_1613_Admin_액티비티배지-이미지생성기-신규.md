# [Admin] 운영 도구 — 액티비티 배지 이미지 생성기 신규

## 배경 / 문제 정의

액티비티 배지 **207개가 전부 `/badges/sample/sNNN.png` 플레이스홀더 이미지**를 쓰고 있다
(2026-09-02 프로덕션 DB 확인: `type='activity'` 207건, `image_url` 207건 전부 sample 경로).
체크인 배지(1,789건)는 `/admin/badge-image`로 실제 이미지를 굽고 있으나, 액티비티 배지에는
대응하는 저작 도구가 없다.

등급 칩 · 배지 이름 · 설명 텍스트 · 블롭 배경을 한 장의 정사각 이미지로 합성하는 어드민
도구를 만든다.

**디자인 최종 확정본** (사용자 확인, 2026-09-02):
https://www.figma.com/design/1mSlxABxlyPQDBAdGNil8l/?node-id=8-33
(fileKey `1mSlxABxlyPQDBAdGNil8l`, node `8:33`). 다른 피그마 파일·노드를 근거로 삼지 않는다.

### 이 티켓이 확정한 방향 (사용자 결정, 2026-09-02)

| 항목 | 결정 |
|---|---|
| 이미지 용도 | `badges.image_url`을 교체한다 |
| 등급 칩 | 등급 드롭다운 선택 → 해당 칩 디자인을 캔버스에 **합성** |
| 배지 이름 · 설명 | **수동 입력** (자동 생성 안 함) |
| 배경 애니메이션 | 서비스 라이브 실행 **안 함**. 합성 단계에서 **정지 프레임으로 구워 배경에 합성** |
| 배경 정지 방식 | 미리보기는 재생. **일시정지 버튼으로 멈춘 그 프레임**을 합성한다 |
| `common` 등급 | 칩을 **표시하지 않는다** |
| 텍스트 넘침 | 자동 축소하지 않는다. **운영자가 수동으로 조절** |
| 생성 단위 | **1개씩** (일괄 생성 없음) |
| 서비스 화면 변경 | **없음.** 이 티켓은 어드민 저작 도구만 만든다 (아래 "범위 밖" 참조) |

### 범위 밖 — 추후 의사결정 예정

배지 상세 Hero 카드의 **등급 칩 · 배지 이름 `<h1>` · 카드 패딩을 제거하지 않는다.**
따라서 서비스 코드는 이 티켓에서 변경하지 않고, 구운 이미지는 기존 Hero 카드 안에
`image_url`로 그대로 들어간다(카드 안 200×200 영역).

Hero 카드를 이미지 전면(full-bleed)으로 전환할지, 그때 카드 안 등급·이름을 숨길지는
**별도 티켓에서 결정한다.** 그 전까지는 상세 화면에서 등급·이름이 이미지 안과 카드 양쪽에
보이는 상태가 되는데, 이는 사용자가 인지하고 유예한 사항이다.

## 상세 요구사항

### 피그마 디자인 스펙 (node 8:33, 540×540)

`get_design_context`로 뽑은 실측값이다 (2026-09-02 기준). **모든 수치는 540×540 캔버스 기준**이며,
출력 해상도를 올릴 때는 같은 배율로 환산한다.

| 노드 | 스펙 |

| `glass` (1:7) | 500×500, bg 기준 **상하좌우 20px 인셋**(중앙 정렬). 라운드 사각형 − 좌우 원 2개 = 가로 티켓 노치 |
| 콘텐츠 프레임 (8:4) | 500×500, **패딩 58px**, 세로 flex, 위(등급칩+이름) / 아래(설명) **양끝 정렬** |
| `RarityBadge` (8:29) | 패딩 `6.5px 14.625px`, 라운드 999, 라벨 **13px Bold**, uppercase, 자간 `0.3px`, 배경 `--color-rarity-mystic` / 글자 `--color-rarity-mystic-text` |

| `condition` (8:2) | **Pretendard Bold 20px**, 흰색, 자간 **-0.8px**, `line-height: 30px`, 폭 = 콘텐츠 프레임 전체 |

#### 라운드 변경 반영 (2026-09-02)

`bg`의 라운드가 **60px로 변경**됐다(540 기준 = 11.1%). 파생 결정 두 가지:

- **출력 해상도에 비례 환산한다.** 1080×1080으로 구우면 라운드도 **120px**이다. 고정 px을
  그대로 쓰면 해상도를 바꿀 때 모양이 달라진다 — 비율(0.111 × 변)로 계산한다.
- **모서리 바깥 픽셀 처리를 정해야 한다.** 라운드 밖은 캔버스에 아무것도 그리지 않으므로
  PNG에서 투명이 된다. 그대로 두면 서비스 Hero 카드 배경(`--radius-cards` = 16px 라운드)이
  모서리로 비쳐 **라운드가 이중으로 보인다**. 아래 중 하나를 고르고 근거를 완료 기록에 남긴다:
  1. 모서리를 투명하게 두고 카드 배경이 비치게 한다 (권장 — 배경색과 자연스럽게 섞인다)
  2. 라운드를 무시하고 540 정사각형 전체를 배경색으로 채운다 (이미지 자체는 사각형)
- 참고: 이미지는 Hero 카드 안 **200×200**에 들어가므로 60px 라운드는 화면에서 약 22px로 보인다.

#### 디자인 시스템과의 차이 (의도된 것으로 보되 확인 필요)

- **등급칩 치수가 MODULAR과 다르다.** `RarityBadge.jsx`는 라벨 8px / 패딩 `4px 9px`인데
  피그마는 13px / `6.5px 14.625px`이다. 540 캔버스가 서비스 카드보다 크기 때문으로 보인다 —
  **색상 토큰만 MODULAR과 공유하고 치수는 피그마 값을 쓴다.**
- **피그마 등급칩 라벨 폰트가 Inter**로 잡혀 있다. 서비스는 `--font-family-base`(Pretendard)다.
  구현 시 Pretendard로 통일할지 확인한다.
- 피그마 컴포넌트 설명에 "rarity=common은 칩을 렌더링하지 않음 / 색상은 `--color-rarity-*`
  토큰 고정 매핑, 절대 재매핑 금지"가 명시돼 있다 — 아래 3절 규칙과 일치한다.

### 서비스/코드베이스 관점

#### 1. 렌더링 파이프라인 — 클라이언트 캔버스 굽기

**기존 체크인 이미지 엔진(`scripts/badge-image-gen/`)을 재사용하지 않는다.** 근거:

- 그 엔진은 **정적 SVG 배경 1장 + 텍스트 1블록**이 전부다(`configs/*.config.js`).
  다중 텍스트 블록도, 컬러 필 칩도, 동적 배경도 표현할 수 없다.
- `next/og`(satori)는 **Canvas 2D를 실행할 수 없고 `backdrop-filter`도 지원하지 않는다.**
  블롭 배경과 글래스 판 둘 다 서버에서 그릴 수 없다.
- 서버 렌더로 가려면 `@napi-rs/canvas` 같은 네이티브 의존성을 추가해야 하고, 서버리스
  번들 크기와 배포 트레이싱 리스크(20260830_1438에서 이미 겪은 문제 계열)가 따라온다.

대신 **이미 두 번 검증된 클라이언트 캔버스 합성 패턴**을 따른다:
- `src/app/admin/badges/bakePreviewToBlob.ts` — 미리보기를 PNG Blob으로 (20260819_008)
- `src/app/(main)/badges/[id]/buildBadgeShareBlob.ts` — 오프스크린 캔버스 직접 합성 (20260821_004)

#### 2. 배경 — 블롭 정지 프레임 합성

`src/lib/blobAnimation.ts`를 **그대로 재사용**한다. 새 블롭 구현을 만들지 않는다.

**정지 방식 — 일시정지 버튼 (사용자 결정)**

미리보기는 서비스와 동일하게 애니메이션을 **재생**하고, 슬라이더 옆 **일시정지 버튼**으로
멈춘다. 합성은 그 정지 상태의 프레임을 쓴다.

- `drawBlobFrame(ctx, w, h, params, t)`의 `t`는 경과 시간이 아니라 **위상(rad)** 이다
  (20260902_0629 주석 참조 — 속도를 바꿔도 이미 지나온 위상이 재스케일되지 않도록 누적을
  호출부가 맡는다). 일시정지 시점의 누적 위상을 그대로 합성에 넘긴다.
- **정지 위상 `t`를 `image_gen_params`에 저장해야 한다.** 저장하지 않으면 재편집으로 다시
  열었을 때 다른 프레임이 나와 "같은 이미지를 다시 굽는" 것이 불가능해진다. 재편집 시에는
  저장된 `t`에서 정지 상태로 복원한다.
- `BLOB_STILL_T`(`prefers-reduced-motion` 대응 고정 위상)는 **초기값으로만** 쓴다. 운영자가
  재생·일시정지하기 전의 첫 화면이 접근성 모드 서비스 화면과 같은 그림이 되도록 하는 용도다.
- 재생/일시정지 토글은 rAF 루프 시작·정지로 구현하고, **언마운트 시 rAF를 반드시 해제한다.**
- **블러 적용 방식에 주의한다.** `drawBlobFrame`은 블러를 걸지 않는다 — 서비스는 캔버스
  **엘리먼트**의 CSS `filter: blur()`로 건다(20260902_0629에서 `ctx.filter`가 iOS Safari
  17.4 미만에서 무시되는 버그 때문에 옮겼다). 굽기 경로에서는 CSS filter를 쓸 수 없으므로:
  1. 오프스크린 캔버스에 `drawBlobFrame`으로 블롭 + 배경색을 그린다
  2. 출력 캔버스에 먼저 `params.bgColor`를 채운다 (블러 가장자리가 투명으로 빠지는 것을 메움 —
     서비스에서 Hero 카드 인라인 `backgroundColor`가 하던 역할)
  3. `ctx.filter = blur(${blobBlurRadiusPx(params.blur, minDim, false)}px)`를 걸고 오프스크린
     캔버스를 `drawImage`
  - `blobBlurRadiusPx`는 **CSS 픽셀 기준 minDim**을 받는다(백킹 스토어 크기가 아니다).
    출력 해상도를 2배로 잡으면 블러 반경도 함께 2배로 환산해야 서비스와 같은 비율이 된다.
- 파라미터 저작 UI는 `src/app/admin/badges/BlobAnimationFields.tsx`를 재사용한다
  (색상 4 + 속도/시드/블러/크기 슬라이더, 라벨은 UX 라이팅 용어표 등재값).
  - `속도` 슬라이더는 **그대로 노출한다.** 미리보기를 재생해 원하는 모양이 나올 때 멈추는
    방식이므로 속도가 실제 의미를 갖는다. 슬라이더 **옆에 일시정지/재생 버튼**을 둔다.

#### 3. 등급 칩 합성

- 등급은 드롭다운 선택(`common | rare | epic | mystic`). 선택값에 따라 칩을 캔버스에 그린다.
- 색은 MODULAR 토큰을 **단일 출처로** 쓴다: `--color-rarity-{등급}` (배경) /
  `--color-rarity-{등급}-text` (글자). 캔버스에는 CSS 변수를 직접 넣을 수 없으므로
  `getComputedStyle`로 해석하거나 토큰값을 한 곳에 상수로 두고 쓴다 — **어느 쪽이든
  `design-system/tokens/colors.css`가 바뀌면 같이 바뀌는 구조**여야 한다.
  하드코딩 hex를 두 번째 출처로 만들지 않는다.
- **`common`을 선택하면 칩을 그리지 않는다** (사용자 결정). 서비스 `RarityBadge.jsx`가
  `common`에서 `null`을 반환하는 것, 피그마 컴포넌트 설명의 "common은 칩을 렌더링하지 않음"과
  모두 일치한다. **"칩 표시" 토글은 만들지 않는다.**
- 칩이 빠지면 배지 이름이 위로 올라붙는지, 칩 자리를 비워 두는지 정한다. 콘텐츠 프레임이
  세로 양끝 정렬(`justify-between`)이므로 **칩 없이 이름부터 시작**하는 쪽이 자연스럽다.
- 기본값은 대상 배지의 DB `rarity`로 채우고, 어드민이 바꿀 수 있게 둔다.

#### 4. 글래스 노치 판

- 좌우 노치 형태는 **MODULAR에 이미 있다** — `design-system/components/cards/BadgeFrame.jsx`의
  `ticket-h` 셰이프(7종 clip shape 중 하나). `makePath('ticket-h', w, h)`가 만드는 path를
  재사용하고 노치 path를 새로 그리지 않는다.
- 캔버스에서는 `Path2D`로 그 path를 만들어 `clip()` 후 반투명 fill(또는 blur된 배경 복사본)을
  올린다. 피그마의 글래스가 backdrop-blur라면 캔버스에서는
  `ctx.filter = blur()` + `clip()`으로 배경을 다시 그려 표현한다.

#### 5. 텍스트 — 이름 · 설명 수동 입력

- **배지 이름**: 여러 줄 입력(줄바꿈 반영). 기본값은 대상 배지의 DB `name`으로 채운다.
- **설명(피그마의 `condition`)**: 여러 줄 입력. 기본값은 대상 배지의 DB `description`으로 채운다.
- 두 필드 모두 자동 생성하지 않는다. `formatConditionText()`(`badges/[id]/page.tsx:86`)를
  끌어다 쓰지 않는다 — 사용자 결정.
- 폰트는 `--font-family-base`(Pretendard Variable)를 쓴다. `buildBadgeShareBlob.ts`의
  `waitForFonts()`와 동일하게 **`document.fonts.load` 완료를 기다린 뒤** 그린다. 기다리지
  않으면 폴백 폰트로 구워진다.
- **텍스트가 영역을 넘쳐도 자동 축소하지 않는다** (사용자 결정). 운영자가 미리보기를 보고
  줄바꿈·문구를 **수동으로 조절**한다. 자동 축소(`autoShrink`)·말줄임을 넣지 않는다.
- 따라서 **미리보기에서 넘침이 그대로 보여야 한다** — 넘친 텍스트를 잘라내거나 숨기면 운영자가
  판단할 근거를 잃는다. 콘텐츠 프레임의 `overflow-clip`을 미리보기에 그대로 적용할지는
  구현자가 판단하되, 넘쳤다는 사실 자체는 화면에서 알 수 있어야 한다.

#### 6. 데이터 모델 — 신규 컬럼 `image_gen_params`

`badges`에 `image_gen_params jsonb` (nullable)을 추가한다.

- **주 용도 — 재편집.** 저장된 파라미터를 다시 불러와 수정·재생성한다. 과거 배경 제너레이터가
  "완성 이미지만 저장해 재편집 불가"였던 것이 실사용 불편의 주원인이었다(20260901_1944 명시).
- **부수 효과 — 포맷 식별.** `NOT NULL`이면 "이 도구로 구운 이미지"라는 뜻이 된다. 나중에
  Hero 전면 전환을 결정할 때 구/신 포맷을 가르는 근거가 되지만, **이 티켓에서는 그 분기를
  구현하지 않는다.**

- **`background_animation`을 재사용하지 않는다.** 그 컬럼에 값이 들어가면 서비스가 Hero 카드에
  라이브 블롭을 **또** 그려서 배경이 이중이 된다(구운 이미지 배경 + 라이브 배경).
  액티비티 배지는 라이브 애니메이션을 쓰지 않는다 — 이 티켓에서 `background_animation`은
  건드리지 않는다.
- 저장 형태(제안 — 구현자가 최종 확정):
  ```json
  {
    "version": 1,
    "rarity": "mystic",
    "name": "동네 산책러\n레벨업\nUltra",
    "condition": "누적 30000회",
    "background": {
      "type": "blob",
      "colors": ["#…"], "bgColor": "#…",
      "speed": 1, "seed": 21, "blur": 0.54, "scale": 0.66,
      "phase": 12.34
    }
  }
  ```
  - `phase`가 **일시정지 시점의 위상(rad)** 이다. 이 값이 없으면 재편집으로 열었을 때 같은
    프레임을 복원할 수 없다 — 필수 저장 항목이다.
  - `rarity`/`name`을 함께 저장하는 이유: 나중에 DB의 `name`·`rarity`가 바뀌면 구운 이미지가
    낡는데, 그때 **불일치를 감지할 근거**가 된다(감지 UI 자체는 이 티켓 범위 밖).
- 마이그레이션 파일을 작성한다. **번호는 push 직전에 원격 staging 기준으로 재확인할 것** —
  로컬 최신은 125이나 병렬 세션이 선점할 수 있고 실제 중복 사고 이력이 있다.
- 마이그레이션 추가 후 **`npm run db:types`로 `database.generated.ts`를 재생성해 같은 커밋에
  포함**한다.
- **DB 실행은 하지 않는다** — SQL 파일 작성까지. 실행은 사용자 승인 후 오케스트레이터가 처리한다.

#### 7. 저장 · 배포 — 전용 API 라우트

`POST /api/admin/activity-badge-image/generate` (경로명은 구현자 재량).

- 요청: `badgeId` + 구운 PNG(멀티파트 또는 base64) + `image_gen_params` JSON
- 서버가 하는 일:
  1. `getAdminUser()` 권한 확인
  2. `badgeId`가 `type='activity'`이고 `deleted_at IS NULL`인지 **DB로 검증**
     (이 값이 파일 경로에 그대로 들어가므로 필수)
  3. Storage `images` 버킷 `badges/activity/{badgeId}.png`에 **`upsert: true`**로 업로드
  4. `image_url = publicUrl + '?v=' + Date.now()`, `image_gen_params` 를 함께 UPDATE
- 이 구조는 `/api/admin/badge-image/generate`가 이미 쓰는 패턴 그대로다. 고정 경로 upsert라
  Storage에 고아 파일이 쌓이지 않고, Storage는 배포와 무관하게 즉시 서빙되므로
  "DB부터 갱신해 이미지가 깨지는" 순서 문제(20260824_020)가 발생하지 않는다.
- **`/api/admin/upload-image`를 쓰지 않는다** — 랜덤 파일명(`{Date.now()}_{random}.{ext}`)이라
  재생성할 때마다 고아 파일이 쌓인다.
- 출력 해상도를 정한다. 피그마 원본이 540이고 Hero 카드가 화면폭 기준 ~360 CSS px이므로
  **2배인 1080×1080 PNG**를 제안한다. 이 경우 **모든 치수를 2배로 환산한다** — 라운드 120px,
  패딩 116px, 이름 128px, 설명 40px, 블러 반경도 2배. 업로드 상한 5MB를 넘지 않는지 실제
  파일로 확인하고, 넘거나 근접하면 크기·포맷을 조정한다.

#### 8. 서비스 화면 — 변경하지 않는다

`src/app/(main)/badges/[id]/BadgeHeroSection.tsx`를 비롯한 서비스 컴포넌트는 **이 티켓에서
건드리지 않는다.** 구운 이미지는 기존 Hero 카드 안 200×200 영역에 그대로 들어간다.

즉 상세 화면에서는 **카드 배경(기존 규칙) + 이미지(구운 배경·등급·이름·설명 포함) + 카드의
등급 칩 · 이름**이 함께 보인다. 등급·이름이 두 번 나오는 상태이며, Hero 전면 전환 여부는
별도 티켓에서 결정한다(위 "범위 밖" 참조).

**게이트 리뷰는 이 중복을 결함으로 판정하지 않는다** — 사용자가 인지하고 유예한 상태다.
반대로 서비스 코드에 손을 대는 변경이 들어오면 범위 밖으로 판정한다.

### UI/UX 관점

#### 어드민 화면 (`/admin/activity-badge-image`)

- 신규 라우트. **기존 `/admin/badge-image`를 확장하지 않는다** — 체크인은 서버 satori,
  이쪽은 클라이언트 캔버스로 파이프라인이 완전히 다르다.
- 네비게이션: `src/components/admin/adminNavItems.ts`의 `ops`(운영 도구) 그룹에
  "체크인 배지 이미지 생성" 아래 **"액티비티 배지 이미지 생성"** 추가.
- 어드민 UI는 **shadcn/ui**(`src/components/admin/ui/`)를 쓴다. 네이티브 select 금지.
- 화면 구성:
  1. **배지 검색** — 이름 키워드 + 등급 필터 + 활동유형 필터, `type='activity'` 한정.
     결과 표에 **등급·활동유형 컬럼을 반드시 노출한다** — 액티비티 배지는 이름이 중복된다
     (예: 「이달의 산책왕」이 common과 epic으로 2건 존재). 이름만으로는 구분할 수 없다.
     기존 체크인 검색의 POI 이름/카테고리 컬럼은 액티비티에 해당 없음.
  2. **설정** — 등급 드롭다운 / 배지 이름(여러 줄) / 설명(여러 줄) / 블롭 배경 파라미터
     - 배지를 선택하면 DB의 `rarity`·`name`·`description`으로 초기값을 채운다
     - `image_gen_params`가 이미 있으면 그 값으로 복원한다(재편집)
  3. **미리보기** — **실제로 굽는 그 캔버스를 그대로 화면에 표시한다.** 별도 미리보기 구현을
     만들지 않는다(WYSIWYG가 구조적으로 보장돼야 한다 — 20260819_011/014에서 확립한 원칙).
  4. **적용** — 생성 → 업로드 → `image_url`·`image_gen_params` UPDATE까지 한 번에.
     완료 후 결과 이미지와 반영된 URL을 표시한다.
- 생성 단위는 **1건**이다. 일괄 생성은 만들지 않는다(사용자 결정 — 이름·설명이 수동 입력이라
  일괄 처리의 이점이 없다).

## 구현 계획

1. 마이그레이션 `1XX_badge_image_gen_params.sql` 작성 (실행 안 함) + `npm run db:types`
2. 캔버스 합성 모듈 (`src/lib/admin/composeActivityBadgeImage.ts` 등)
   — 블롭 정지 프레임 → 글래스 노치 → 등급 칩 → 이름 → 설명 순서로 그리고 `canvasToBlob()`
3. 어드민 페이지 + 검색 API + 생성 API
4. 네비게이션 항목 추가
5. 프로덕션 배포 후 **배지 1건으로 먼저 검증**하고 나머지로 확장

서비스 컴포넌트는 손대지 않는다 — 4번에 `BadgeHeroSection` 변경이 들어가면 범위 밖이다.

### 검증 시 주의

- **어드민은 staging에서 검증할 수 없다** — 배포 후 프로덕션에서 확인한다.
- **Supabase는 staging·프로덕션 공용 단일 DB**다. `image_url` UPDATE는 즉시 프로덕션에
  반영되므로, 한 건으로 상세 화면·목록 화면을 눈으로 확인한 뒤 다음 배지로 넘어간다.

## 유예된 판단 (이 티켓에서 확인하지 않음)

아래는 검토 단계에서 제기했으나 **사용자가 "무시"로 정리한 항목**이다. 게이트/개선 리뷰에서
결함으로 올리지 않는다. 나중에 Hero 전면 전환을 논의할 때 함께 다시 꺼낸다.

1. **목록 썸네일 가독성** — 배지 목록 썸네일은 90×90이라(`BadgeGridCard.tsx:73`) 이미지 안
   설명 텍스트가 읽히지 않는다. 이름·등급은 썸네일 아래 별도 표시되므로 기능 결손은 없다.
2. **설명 중복** — 이미지 안 설명과 카드 밖 `description`이 상세 화면에 함께 보일 수 있다.
3. **이름 불일치** — 이미지 안 이름은 수동 입력이라 DB `name`과 달라질 수 있고, 목록·피드·
   알림에는 DB `name`이 나온다.
4. **낡은 이미지** — 이름·등급이 나중에 DB에서 바뀌어도 구운 이미지는 생성 시점 값을 유지한다.
   `image_gen_params`에 생성 당시 값을 남겨 감지 근거만 확보하고, 감지·경고 UI는 만들지 않는다.
