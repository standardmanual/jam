# [Admin] 액티비티 배지 이미지 생성기 — 블롭 색상 프리셋 추가

## 배경 / 문제 정의

`/admin/activity-badge-image`(20260902_1613)에서 배경 블롭 4색은 `<input type="color">` 4개를
운영자가 매번 직접 골라야 한다. 사전 대화에서 액티비티 5종(걷기/러닝/사이클링/등산/트레일러닝)
× 배지 등급 4단계(common/rare/epic/mystic) 조합별로 어울리는 4색 팔레트 20세트를 디자인해
확정했다 — 아티팩트: https://claude.ai/code/artifact/6aab0d6a-c4c4-4452-ae1d-0c0ca405cd9b

이 20세트를 코드 상수로 저장하고, 저작 화면에서 활동 종목·등급을 고르면 즉시 색상 입력값에
채워지도록 한다. 신규 배지를 고를 때는 자동으로도 적용되게 한다.

**사용자 지시 원문**: "생성된 값을 어드민 > 액티비티 배지 이미지 생성 메뉴에서 볼륨 색상의
프리셋으로 추가해줘. [액티비티 ▼] [등급 ▼] 선택시 제공해준 컬러셋이 값에 입력되도록해. 검색한
배지 목록에서 배지를 선택하면 프리셋이 바로 선택되면 돼. 현재의 커스텀 값 입력 기능도 그대로
유지해야해."

## 상세 요구사항

### 서비스/코드베이스 관점

1. **프리셋 상수 테이블** — `src/lib/badgeBlobPresets.ts` 신규.
   `Record<ActivityType, Record<BadgeRarity, [string, string, string, string]>>` 형태로 20세트
   (5×4) hex 값을 담는다. `ActivityType`은 `database.ts`의
   `'cycling' | 'running' | 'trail_running' | 'hiking' | 'walking'` 그대로, `BadgeRarity`도
   기존 타입 그대로 써서 키 오타가 컴파일 타임에 잡히게 한다. 값 순서는
   `BlobAnimationFields.tsx`의 색상 슬롯 1~4(베이스·포인트·라이트·딥)와 동일하게 맞춘다.

2. **프리셋 선택 UI** — `page.tsx`(`ActivityBadgeImagePage`)의 "설정" 카드, `BlobAnimationFields`
   바로 위(또는 그 안 상단)에 활동 종목 Select + 등급 Select 2개를 추가한다.
   - `BlobAnimationFields.tsx`는 건드리지 않는다 — 이 컴포넌트는
     `BackgroundGeneratorPreview.tsx`에서도 재사용되는 범용 블롭 파라미터 컨트롤이라, 액티비티
     배지 전용 프리셋 로직을 넣으면 그쪽 호출부와 무관한 책임이 섞인다. 프리셋 UI는 이 페이지
     (`page.tsx`)에만 둔다.
   - 두 Select 값이 모두 정해지면 `setDraft`로 `draft.background.colors`만 프리셋 4색으로
     덮어쓴다. `bgColor`·`speed`·`seed`·`blur`·`scale`·`phase`는 그대로 둔다(사용자가 이미
     조정했을 수 있는 값을 프리셋이 건드리지 않는다).
   - 활동 종목 Select의 초기값은 선택된 배지의 `activityTypes[0]`(있으면), 등급 Select의
     초기값은 `draft.rarity`로 잡아 두면 대부분 바로 맞는 조합이 뜬다. 배지에 활동 종목이
     여러 개 지정된 경우 첫 번째 값만 기본값으로 쓰고, 나머지는 운영자가 드롭다운으로 바꾸면
     된다(활동 종목별로 배지를 따로 만드는 게 일반적이라 드묾).

3. **배지 선택 시 자동 적용** — `selectBadge()`의 "저장된 `imageGenParams`가 없는" 분기에서
   기존 `DEFAULT_ACTIVITY_BADGE_BACKGROUND`를 펼친 뒤, `badge.activityTypes[0]`과 `badge.rarity`
   조합에 대응하는 프리셋이 있으면 `colors`만 그 값으로 교체한다. 매칭되는 프리셋이 없으면
   (활동 종목 미지정 등) 기존 기본값(`DEFAULT_BLOB_ANIMATION.colors`)을 그대로 쓴다.
   - **저장된 `imageGenParams`가 있는 배지는 절대 건드리지 않는다** — 그 분기(`if
     (badge.imageGenParams)`)는 지금 그대로 둔다. 이미 구운 배지를 다시 열었는데 색이 프리셋으로
     바뀌어 있으면 안 된다.

4. **커스텀 입력 유지** — `BlobAnimationFields`의 `<input type="color">` 4개는 그대로 남는다.
   프리셋은 초기값을 채워주는 역할일 뿐이고, 프리셋 적용 후에도 그 입력으로 자유롭게 개별 색을
   수정할 수 있어야 한다(드롭다운이 입력을 막거나 비활성화하지 않는다).

## 구현 계획

- `src/lib/badgeBlobPresets.ts`: 프리셋 상수 + 조회 헬퍼(`getBadgeBlobPreset(activityType,
  rarity)`) export.
- `src/app/admin/activity-badge-image/page.tsx`:
  - 프리셋 Select 2개 상태(`presetActivity`, `presetRarity`) 추가.
  - `selectBadge()`에서 신규 배지 분기에 프리셋 조회·적용 로직 삽입, Select 초기값도 함께 세팅.
  - 프리셋 Select `onChange`에서 `getBadgeBlobPreset` 조회 → `draft.background.colors` 교체.
- `BlobAnimationFields.tsx`·`composeActivityBadgeImage.ts`·`activityBadgeImage.ts`(저장 포맷)는
  변경하지 않는다 — 순수 프런트엔드 초기값 채움 기능이라 저장 스키마에 영향이 없다.
- 어드민 화면이라 MODULAR 탐색 대상 아님(기존 정책). Select는 `@/components/admin/ui/select`
  기존 것을 그대로 사용한다(이미 이 파일에서 등급·활동 종목 필터 Select로 쓰고 있음).
