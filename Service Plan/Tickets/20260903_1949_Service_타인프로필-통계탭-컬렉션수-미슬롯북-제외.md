# [Service] 타인 프로필 통계탭 컬렉션 수, 미슬롯 아이템북 제외

## 배경 / 문제 정의

티켓 20260824_016에서 **"아이템배지를 한 개도 슬롯에 넣지 않은 컬렉션은 타인에게 노출하지
않는다"** 는 정책을 확정하고, 컬렉션 **목록**(`/api/users/[username]/itembooks`,
`[username]/collections/page.tsx`)과 **상세**(`collections/[id]/page.tsx`)에는 반영했다.

그런데 프로필 화면 **통계탭의 "컬렉션" 숫자**에는 이 필터가 적용되지 않았다.
`src/app/(main)/[username]/page.tsx`의 `itemBookCount`는 "인벤토리에 보유 중인(dropped_at IS NULL)
아이템배지가 속한 활성 아이템북 수"만 세기 때문에, 친구가 아이템배지를 인벤토리에 **소유만 하고
컬렉션 슬롯(`user_item_book_slots`)에는 하나도 넣지 않은** 아이템북까지 합산된다.

결과적으로 팔로잉 중인 친구 프로필에서 **통계탭 숫자 > 실제 컬렉션 탭 목록 개수**가 되어
숫자와 목록이 어긋난다. 해당 코드에는 이미
`// (/api/users/[username]/itembooks의 목록 필터와 반드시 일치시켜야 함 — 안 그러면 숫자와 목록이 어긋남)`
주석이 달려 있으나, 20260824_016의 슬롯 필터가 추가될 때 이 카운트 쪽이 함께 갱신되지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **타인 프로필 열람 시**(`isOwnProfile === false`): 통계탭 컬렉션 숫자는
  `user_item_book_slots`에 해당 유저 + 해당 `item_book_id` 행이 **1개 이상**인 아이템북만 센다.
  슬롯 0개 아이템북은 인벤토리에 배지를 보유하고 있어도 합산하지 않는다.
- **본인 프로필 열람 시**(`isOwnProfile === true`): 기존 동작 유지 — 슬롯 0개여도 합산한다.
  (20260824_016에서 "본인 열람은 예외 없이 항상 노출"로 확정했고, 목록 API의
  `.filter(book => isOwnList || book.slottedCount > 0)`와 축을 맞춘다.)
- **최종 정합 기준**: 통계탭 숫자는 `/api/users/[username]/itembooks`가 돌려주는 `books.length`와
  항상 같아야 한다. 즉 기존 필터 조건(보유 중 아이템배지 · `badges.type='item'` ·
  `item_book_id IS NOT NULL` · `badges.deleted_at IS NULL` · `item_books.is_active = true`)에
  **타인일 때만 슬롯 1개 이상** 조건이 추가된 형태다.
- **POI 배지 무관**: 슬롯 개수는 아이템배지 슬롯 기준이며, POI 배지 보유 여부는 판정에 영향을 주지
  않는다 (20260824_016 정책 그대로).
- 아이템배지를 드랍한 경우(`dropped_at IS NOT NULL`)는 기존과 동일하게 제외한다.

### UI/UX 관점

- 화면 문구·레이아웃 변경 없음. 숫자 값만 정확해진다.
- 팔로잉 중인 친구가 슬롯을 하나도 넣지 않았다면 컬렉션 숫자가 `0`으로 표시될 수 있으며,
  이는 컬렉션 탭의 빈 상태와 일치하므로 의도된 결과다.

## 구현 계획

1. `src/app/(main)/[username]/page.tsx`의 `itemBookCount` 산출 블록(현재 약 102~131행)에서,
   `item_books` 카운트 쿼리로 넘기기 전에 `isOwnProfile === false`인 경우
   `user_item_book_slots`를 `user_id = subjectId` · `item_book_id IN (bookIdsForCount)`로 조회해
   슬롯이 존재하는 `item_book_id` 집합으로 교집합을 취한다.
2. 교집합 결과가 비면 `itemBookCount = 0`으로 두고 불필요한 `item_books` 카운트 쿼리를 생략한다.
3. `isOwnProfile` 값이 해당 블록보다 앞에서 확정되어 있는지 확인하고, 아니라면 순서를 조정한다.
4. 기존 주석("목록 필터와 반드시 일치시켜야 함")에 이번 슬롯 조건을 명시해 다음 변경에서 다시
   어긋나지 않게 한다.
5. 조회 실패 시 기존 패턴대로 `console.error`로 로그를 남긴다(에러를 삼켜 0으로 위장하지 않도록
   로그 메시지에 컨텍스트를 포함).

### 검증 시나리오

- 슬롯 0개 + 인벤토리 보유 아이템북만 있는 유저를 **타인**으로 조회 → 통계탭 컬렉션 = 0,
  컬렉션 탭 목록도 비어 있음 (일치).
- 슬롯 1개 이상 아이템북 N개 + 슬롯 0개 아이템북 M개를 가진 유저를 **타인**으로 조회 →
  통계탭 = N, 목록 카드 수 = N (일치).
- **본인** 프로필 조회 → 기존과 동일하게 N+M (목록도 N+M 노출).

### 범위 밖 (이번 티켓에서 건드리지 않음)

- `src/app/api/users/[username]/stats/route.ts`에도 동일한 `itemBookCount` 계산이 중복 존재하나,
  코드베이스 내 호출부가 확인되지 않는 고아 API로 보인다. 실제 화면에 영향이 없으므로 이번
  티켓에서는 수정하지 않고 별도 정리 대상으로 남긴다.
  (참고: 이 API의 계산은 `dropped_at` 필터조차 없어 더 부정확하다.)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`src/app/(main)/[username]/page.tsx`의 `itemBookCount` 산출 블록에서, 보유 아이템배지로 뽑아낸
`bookIdsForCount`를 `item_books` 카운트 쿼리에 넘기기 전에 **타인 열람(`!isOwnProfile`)일 때만**
`user_item_book_slots`(`user_id = subjectId`, `item_book_id IN bookIdsForCount`)를 조회해
슬롯이 1개 이상인 아이템북만 남기도록 교집합을 취했다.

- 교집합이 비면 기존 `if (bookIdsForCount.length > 0)` 가드에 그대로 걸려 `item_books` 카운트
  쿼리를 생략하고 `itemBookCount = 0`이 된다 (별도 분기 추가 없이 기존 가드 재사용).
- 본인 열람은 슬롯 조회 자체를 하지 않아 기존 동작(슬롯 0개도 합산) 유지.
- `isOwnProfile`은 해당 블록보다 위(대상 유저 조회 직후)에서 이미 확정돼 있어 순서 조정 불필요.
- 슬롯 조회 실패 시 `console.error`로 컨텍스트("슬롯 미확인분은 카운트에서 제외됨") 포함 로그를
  남긴다. 기존 블록의 다른 쿼리들과 동일한 실패 처리 패턴.
- 블록 상단 주석에 목록 API의 실제 필터식(`isOwnList || book.slottedCount > 0`)과 티켓 번호를
  명시해 다음 변경에서 다시 어긋나지 않도록 했다.

### 범위 밖 발견물 (사용자 승인 하에 별도 작업으로 분리)

1. **`src/app/api/users/[username]/stats/route.ts`는 3중으로 어긋난 고아 API.**
   `src` 전체 grep에서 호출부가 없고, `dropped_at` 미필터 + 이번 슬롯 필터 미적용 +

   정합화보다 **삭제**를 권고 — 남겨두면 다음 사람이 "여기가 통계 로직"이라 착각한다.
2. **목록 쪽 `badges.deleted_at IS NULL` 필터 누락.**
   `api/users/[username]/itembooks/route.ts`·`[username]/collections/page.tsx`의
   `discoveredByBook` 구성에는 이 필터가 없는데 통계 카운트에는 있다. 소프트 삭제된 아이템배지를
   `dropped_at IS NULL`로 보유 중인 `inventory_items`가 실DB에 293건 있어, 그 배지의 아이템북이
   활성이고 슬롯 1개 이상이면 "목록에는 뜨는데 통계에는 안 잡히는" 비대칭이 성립한다.
   현재는 해당 북 대부분이 비활성이라 전수 대조 불일치 0건이지만 구조적 축 어긋남은 남아 있다.
   이번 변경이 만든 것이 아니라 20260824_016 이전부터의 상태다.
3. **프로필 빈 상태 문구의 본인/타인 미구분.**
   `lib/i18n/ko.ts`의 `emptyItembooks`·`emptyBadges`·`emptyFollowers`·`emptyFollowing`이 전부
   본인 시점 2인칭 행동 유도 문구인데 타인 프로필에서도 그대로 노출된다. 이번 수정으로
   "타인 프로필 컬렉션 = 0" 화면이 의도된 정상 결과가 되면서 표면화됐다.

- **정책 중복이 4곳으로 늘었다.** `isOwnList || slottedCount > 0` 판정이
  `api/users/[username]/itembooks/route.ts` · `[username]/collections/page.tsx` ·
  `collections/[id]/page.tsx` · `[username]/page.tsx`에 흩어져 있다. 이번 버그가 정확히

  있다. `ProfileClient`에서 목록 응답 수신 후 숫자를 동기화하는 방안은 숫자 깜빡임과의
  트레이드오프가 있어 채택하지 않았다.
- `[username]/page.tsx`의 `console.error` 로그에 `username`/`subjectId`가 없어 사후 추적이
  어렵다(이 파일 전체 공통).
