# [Infra] 고아 API `stats/route.ts` 삭제 검토

## 배경 / 문제 정의

티켓 20260903_1949(타인 프로필 통계탭 컬렉션 수에서 미슬롯 아이템북 제외) 작업 중,
게이트 리뷰(conservative-reviewer)가 범위 밖 발견물로 보고한 항목.

`jam-web/src/app/api/users/[username]/stats/route.ts`는 프로필 통계 바(팔로워/팔로잉/배지/아이템북
수 + isFollowing)를 돌려주는 API인데, **`jam-web/src/` 전체 grep에서 호출부가 하나도 발견되지
않는 고아 API**다. 실제 프로필 통계 숫자는 서버 컴포넌트인
`jam-web/src/app/(main)/[username]/page.tsx`가 직접 계산해 `ProfileClient`에 prop으로 넘긴다.

게다가 이 고아 API의 계산은 현재 화면 로직과 **3중으로 어긋나** 있다:

1. **`dropped_at` 미필터** (76~86행 부근) — 드랍해서 이미 보유하지 않는 아이템배지까지 아이템북
   카운트에 합산한다. `page.tsx`는 `.is('dropped_at', null)`로 거른다.
2. **슬롯 필터 미적용** — 티켓 20260824_016에서 확정하고 20260903_1949에서 통계 카운트에도
   반영한 "타인 열람 시 아이템배지 슬롯이 0개인 컬렉션은 제외" 정책이 여기엔 없다.
3. **배지 카운트의 `badges.deleted_at` 미제외** (56~59행 부근) — `page.tsx`(67~71행 부근)와
   값이 달라진다.

남겨두면 다음 사람이 "여기가 통계 로직"이라 착각할 위험이 있다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 먼저 **호출부가 정말 없는지 재확인**한다. `jam-web/src/` 전체는 물론, 외부에서 직접 호출할
  가능성(어드민 도구, 외부 스크립트, 문서에 기재된 엔드포인트 등)도 확인한다. `Service Plan/`
  문서에서 이 엔드포인트를 참조하는 곳이 있는지도 grep으로 본다.
- 호출부가 없다는 게 확인되면 **파일을 삭제**한다. 정합화(세 가지 필터를 맞추는 것)보다 삭제를
  권고받은 이유는, 남겨두면 다음 사람이 "여기가 통계 로직"이라고 착각할 위험이 실제로 커졌기
  때문이다.
- 만약 호출부가 발견되면 삭제하지 말고, 발견 내용을 보고한 뒤 위 3가지 불일치를 `page.tsx` 기준으로
  정합화하는 방향으로 전환한다.

## 구현 계획

1. `grep -rn "users/.*\\/stats\\|itembooks/route\\|api/users" jam-web/src Service\\ Plan` 등으로
   호출부·문서 참조 여부를 전수 확인.
2. 호출부 없음이 확정되면 `git rm jam-web/src/app/api/users/[username]/stats/route.ts`.
3. 호출부가 있다면 3가지 필터(`dropped_at`, 슬롯, `badges.deleted_at`)를 `page.tsx` 기준으로
   정합화하고, 이후 검증 시나리오를 티켓 20260903_1949와 동일한 방식(service_role 전수 대조)으로
   수행.
