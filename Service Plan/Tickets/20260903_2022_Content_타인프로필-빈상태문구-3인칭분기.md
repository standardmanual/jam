# [Content] 타인 프로필 빈 상태 문구 3인칭 분기

## 배경 / 문제 정의

티켓 20260903_1949(타인 프로필 통계탭 컬렉션 수에서 미슬롯 아이템북 제외) 작업 중, 개선
리뷰(progressive-reviewer)가 UX Writing 가이드 점검에서 지적한 항목이다.

프로필 화면의 빈 상태(empty state) 문구가 **본인 시점 2인칭 행동 유도**로만 작성돼 있는데,
**타인 프로필에서도 그대로 재사용**된다. 남의 프로필을 보면서 "모아 발견해보세요"라는 말을
듣는 셈이라 어색하다.

`jam-web/src/lib/i18n/ko.ts`의 해당 문구들 (약 64~70행):
- `emptyItembooks`: '아직 발견한 컬렉션이 없어요'
- `emptyItembooksBody`: '아이템 배지를 모아 컬렉션을 발견해보세요'
- `emptyBadges` / `emptyFollowers` / `emptyFollowing` 계열도 동일한 문제

### 왜 지금인가

티켓 20260903_1949로 **"타인 프로필 컬렉션 = 0"이 의도된 정상 결과가 되면서** 이 화면이
처음으로 제대로 표면화됐다. 그 전에는 인벤토리에 배지만 있어도 숫자가 잡혀 빈 상태를 볼 일이
적었지만, 이제 슬롯을 하나도 안 넣은 친구의 프로필에서는 컬렉션 탭이 정상적으로 비어 보인다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `jam-web/src/app/(main)/profile/ProfileClient.tsx`에 **`isOwnProfile` prop이 이미 존재**하므로
  분기 비용은 낮다. 이를 이용해 본인/타인 문구를 나눈다.
- **컬렉션 탭만이 아니라 프로필 화면 4개 탭 전체**(배지·컬렉션·팔로워·팔로잉)의 빈 상태 문구를
  함께 점검한다. progressive-reviewer가 "컬렉션만의 문제가 아니다"라고 지적했다.
- 표시 이름 처리 주의: 프로필 표시 이름 도입 티켓
  (`20260830_0113_Feature_유저프로필-표시이름-도입.md`)이 있으므로, 3인칭 문구에 쓸 이름을
  `username`으로 할지 표시 이름으로 할지 그 티켓의 규칙을 먼저 확인할 것.

### UI/UX 관점

- 문구는 `Service Plan/Specs/UX_WRITING_GUIDELINE.md`의 **"1-2) 사용자 중심의 호칭과 주어 설정"**
  원칙(`OO님` 표기)을 따른다. 3인칭 예시: `{닉네임}님이 공개한 컬렉션이 아직 없어요` — 설명문
  (body)은 타인 시점에서 행동 유도가 성립하지 않으므로 생략하거나 중립 서술로 바꾸는 것을
  검토한다.

## 구현 계획

1. `20260830_0113` 티켓에서 확정한 이름 표기 규칙(username vs 표시 이름) 확인.
2. `ko.ts`의 4개 탭 빈 상태 문구를 본인/타인 버전으로 분리(또는 함수형으로 이름을 받도록 변경).
3. `ProfileClient.tsx`에서 `isOwnProfile`에 따라 분기 렌더.
4. UX Writing 검증 체크리스트(용어 일관성·톤앤매너·문장 규칙·표기 규칙)를 완료 기록에 채운다 —
   사용자 노출 텍스트를 바꾸는 작업이라 필수 항목이다.
