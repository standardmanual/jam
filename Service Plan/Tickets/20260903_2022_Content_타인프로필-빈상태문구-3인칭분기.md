# [Content] 타인 프로필 빈 상태 문구 3인칭 분기

## 배경 / 문제 정의

티켓 20260903_1949(타인 프로필 통계탭 컬렉션 수에서 미슬롯 아이템북 제외) 작업 중, 개선
리뷰(progressive-reviewer)가 UX Writing 가이드 점검에서 지적한 항목이다.

프로필 화면의 빈 상태(empty state) 문구가 **본인 시점 2인칭 행동 유도**로만 작성돼 있는데,
**타인 프로필에서도 그대로 재사용**된다. 남의 프로필을 보면서 "모아 발견해보세요"라는 말을
듣는 셈이라 어색하다.

`jam-web/src/lib/i18n/ko.ts`의 해당 문구들 (약 64~70행):
- `emptyItembooks`: '아직 발견한 컬렉션이 없어요'
- `emptyItembooksBody`: '아이템 배지를 모아 컬렉션을 발견해보세요'
- `emptyBadges` / `emptyFollowers` / `emptyFollowing` 계열도 동일한 문제

### 왜 지금인가

티켓 20260903_1949로 **"타인 프로필 컬렉션 = 0"이 의도된 정상 결과가 되면서** 이 화면이
처음으로 제대로 표면화됐다. 그 전에는 인벤토리에 배지만 있어도 숫자가 잡혀 빈 상태를 볼 일이
적었지만, 이제 슬롯을 하나도 안 넣은 친구의 프로필에서는 컬렉션 탭이 정상적으로 비어 보인다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `jam-web/src/app/(main)/profile/ProfileClient.tsx`에 **`isOwnProfile` prop이 이미 존재**하므로
  분기 비용은 낮다. 이를 이용해 본인/타인 문구를 나눈다.
- **컬렉션 탭만이 아니라 프로필 화면 4개 탭 전체**(배지·컬렉션·팔로워·팔로잉)의 빈 상태 문구를
  함께 점검한다. progressive-reviewer가 "컬렉션만의 문제가 아니다"라고 지적했다.
- 표시 이름 처리 주의: 프로필 표시 이름 도입 티켓
  (`20260830_0113_Feature_유저프로필-표시이름-도입.md`)이 있으므로, 3인칭 문구에 쓸 이름을
  `username`으로 할지 표시 이름으로 할지 그 티켓의 규칙을 먼저 확인할 것.

### UI/UX 관점

- 문구는 `Service Plan/Specs/UX_WRITING_GUIDELINE.md`의 **"1-2) 사용자 중심의 호칭과 주어 설정"**
  원칙(`OO님` 표기)을 따른다. 3인칭 예시: `{닉네임}님이 공개한 컬렉션이 아직 없어요` — 설명문
  (body)은 타인 시점에서 행동 유도가 성립하지 않으므로 생략하거나 중립 서술로 바꾸는 것을
  검토한다.

## 구현 계획

1. `20260830_0113` 티켓에서 확정한 이름 표기 규칙(username vs 표시 이름) 확인.
2. `ko.ts`의 4개 탭 빈 상태 문구를 본인/타인 버전으로 분리(또는 함수형으로 이름을 받도록 변경).
3. `ProfileClient.tsx`에서 `isOwnProfile`에 따라 분기 렌더.
4. UX Writing 검증 체크리스트(용어 일관성·톤앤매너·문장 규칙·표기 규칙)를 완료 기록에 채운다 —
   사용자 노출 텍스트를 바꾸는 작업이라 필수 항목이다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
프로필 화면 4개 탭(배지·컬렉션·팔로워·팔로잉)의 빈 상태 문구를 `isOwnProfile` 기준으로
본인(2인칭)/타인(3인칭) 두 버전으로 분리했다.

- `ko.ts`의 기존 4쌍(`emptyBadges`/`emptyItembooks`/`emptyFollowers`/`emptyFollowing` +
  각 `*Body`)은 본인 시점 그대로 유지하고, `{name}` 보간 플레이스홀더를 쓰는 타인 시점
  전용 키 4개(`emptyBadgesOther`/`emptyItembooksOther`/`emptyFollowersOther`/
  `emptyFollowingOther`)를 신규 추가했다. 기존 `t()` 헬퍼(`src/lib/i18n/index.ts`)의
  `{변수}` 보간 패턴을 그대로 재사용해 신규 인프라 없이 처리했다.
- 타인 시점 문구는 UX_WRITING_GUIDELINE "OO님" 규칙을 따라 `{name}님이 아직 ~없어요` 형태로
  통일했다(팔로워만 "님에게"가 자연스러워 예외).
- 타인 시점 body(description)는 티켓 지시대로 "행동 유도가 성립하지 않으므로 생략"을
  택했다 — `EmptyState`의 `description` prop이 옵셔널이라 `undefined`를 넘기면 title만
  렌더된다(design-system 컴포넌트 수정 없이 처리 가능함을 코드로 확인).
- 이름 표기는 20260830_0113 티켓에서 도입한 `getDisplayName()` 폴백 헬퍼를 그대로 재사용
  (이름 있으면 이름, 없으면 username, 프로필 자체가 없으면 `anonymous`) — 프로필 헤더
  (516행)와 동일한 폴백 규칙을 `subjectName` 변수로 한 번만 계산해 4곳에서 공유한다.
- `ProfileClient.tsx`의 `renderTabContent()` 4개 분기(배지/컬렉션/팔로워/팔로잉) 모두
  `isOwnProfile ? 본인문구 : t(타인문구, { name: subjectName })` 형태로 분기했다.

### 주요 의사결정 / 핵심 메모
- **`d.social.*`(별도 라우트 `/{username}/followers`·`/{username}/following` 전체 페이지)는
  이번 범위에서 건드리지 않았다.** 티켓 상세 요구사항이 명시적으로 "`ProfileClient.tsx`에
  `isOwnProfile` prop이 이미 존재하므로 이를 이용"이라고 지시했고, 20260903_1949의
  "범위 밖 발견물" 3번도 `lib/i18n/ko.ts`의 `emptyItembooks`·`emptyBadges`·`emptyFollowers`·
  `emptyFollowing`(=`d.profile.*` 네임스페이스)만 지목했다. `d.social.*`를 쓰는 두 라우트는
  `isOwnProfile` 개념 자체가 코드에 없어(대상 유저 vs 로그인 유저 비교 로직 부재) 이번
  범위를 넘어서는 별도 작업이 필요 — alerts에 남긴다.
- 타인 시점 body를 "생략"(undefined) vs "중립 서술" 중 생략을 택했다. 중립 서술("활동하면
  이곳에 쌓여요" 류)은 사실상 본인 문구를 약하게 재탕하는 것이라 정보값이 낮고, 티켓이
  두 옵션을 모두 허용했으므로 더 단순하고 안전한 쪽을 선택했다.
- 팔로워 문구만 "{name}님에게 아직 팔로워가 없어요"로 조사를 다르게 썼다(다른 3개는
  "님이"). "{name}님이 아직 팔로워가 없어요"도 문법적으로는 성립하나 "OO님에게 팔로워가
  없다"가 더 자연스러운 한국어 소유 표현이라 판단.

   ProfileClient보다 구현 비용이 크다(비교 로직 신규 추가 필요). 이번 티켓 범위 밖으로
   판단해 손대지 않았다.
