# [BadgeEngine] 액티비티 배지 v5 전면 재설계 — 마스터

## 배경 / 문제 정의

현행 액티비티 배지 체계(v4, 207종)는 네 가지 구조적 문제를 안고 있다.

1. **대부분이 1회성이다.** 엔진이 모든 조건을 «전체 이력 소급 + 역대 최고값»으로 평가하므로
   (`BADGE_ENGINE_UNIFIED.md` §2.3), 한 번 넘으면 영구 달성이고 되돌아오지 않는다.
   반복성이 있어야 할 `weekly_count`조차 «역대 가장 잘한 주»로 판정한다.
2. **소진 후 컨텐츠가 없다.** 실측(2026-09-04) — 실유저 5명 중 5명이 러닝 Mystic을 전부 획득했다.
3. **배지 홍수.** 첫 싱크가 수년치 이력을 한꺼번에 소급 평가한다. 실측 최대 **1분에 16개** 발급.
4. **신규 배지를 만들 수 없다.** 획득률이 오르면 조건값을 올려야 하는데, 인간이 달성 불가능한
   수준이 되어 무의미해진다.

v5는 이 넷을 구조로 해결한다. 핵심은 **«달성(achievement)»에서 «기록(record)»으로의 이동**이다.

## 확정된 설계 (전체)

### 평가 기준
- **가입 시점부터 카운트** — 과거 이력 배제. 첫 싱크는 마지막 활동 1건만 정산
- 기존 배지 207종 폐기, 획득 이력 전체 초기화

### 배지 구조
- **무한레벨형** — 등급 없이 Lv.1~∞, 수열 고정(중간 삽입 포기, 뒤로만 연장)
- **등급형** — Common/Rare/Epic/Mystic 4단, **레일 4눈금 코드 강제**
- **반복 획득** — 같은 배지를 여러 번. 평면 반복은 횟수에 등급, 자동 상승 반복은 숫자만
- 원칙: **난이도가 스스로 오르면 숫자만, 난이도가 고정이면 등급을 붙인다**

### 게이트 (2단)
| 관문 | 조건 | 강도 가산 |
|---|---|---|
| Rare → Epic | 축 내 교차(같은 축 다른 계열 Common 이상) 또는 축 간 교차 | +2 |
| Epic → Mystic | 축 간 교차(보완 축 Rare 이상) **+ 미션 보상 배지** | +6 |

- 축 내 교차는 **9개 축 중 4개에서만 성립**한다(나머지는 계열이 포함관계 → 자동 통과).
  성립하지 않는 축은 Epic도 축 간 교차로 대신하며 보완 축을 2개 지정한다.
- **축은 같은 종목 안에서만 공유한다** — 교차도 미션도 종목 경계를 넘지 않는다

### 강도 채점 (등급 산정)
4축 각 1~5점. **「행동 변경」은 첫 1회의 장벽, 나머지 3축은 반복의 장벽**이므로
첫 회 등급은 4축 총점, 횟수 사다리는 3축만으로 정한다.

| 강도 | 사다리 |
|---|---|
| 낮음 4~7 | 1 / 5 / 20 / 50회 |
| 중간 8~11 | 1 / 3 / 10회 |
| 높음 12~15 | 1 / 2회 |
| 매우 높음 16+ | 단일 |

### 카탈로그 규모
5종목 **164계열 / 약 550종** + 미션 보상 배지 40종(종목당 8).

| 종목 | 기준선 | 계열 |
|---|---|---|
| 걷기 | 주 3회 × 60분 (주 12km) | 44 |
| 러닝 | 주 4회 × 12.5km · 5:30/km (주 50km) | 34 |
| 자전거 | 주 3회 × 67km · 25km/h (주 200km) | 32 |
| 등산 | 월 4회 × 고도 750m (월 3,000m) | 26 |
| 트레일 | 주 3회 × 16.7km · 고도 333m (주 50km/1,000m) | 28 |

### 포인트
**지급 전면 없음.** 운동은 이미 내재 동기가 있는 행동이라 거리→포인트 환산은
과잉정당화와 게이밍을 유발한다. 어드민 배지 폼의 포인트 설정 필드만 존치(값 0).

### 라이팅
- 배지 이름·설명은 세계관 문어체, **획득 조건은 명사구 사실 표기**
- 요소 순서 고정: **①기간 ②맥락 ③지표 / ④달성 횟수**
- 「이상·이하」만 쓰고 「초과·미만」은 쓰지 않는다
- 「주」가 들어가면 예외 없이 `(월~일)` 표기
- 지표 이름은 `badge_metric_labels` 단일 출처. 신규 12개 추가·2개 수정 필요

### Strava 필드
스포츠 일반 단위만 쓴다(거리·시간·고도·속도·페이스·심박·파워·케이던스).
**Strava 독자 지표는 쓰지 않는다** — `suffer_score`, 세그먼트, 응원 수.
`pr_count`도 제외한다: **Strava 계정 전체 이력 기준**이라 «가입 시점 카운트»와 충돌한다.
기록 갱신은 가입 이후 활동만으로 직접 계산한다.

## 주요 의사결정 / 미채택 대안

| 결정 | 미채택 대안과 이유 |
|---|---|
| 가입 시점 카운트 | «계산에 포함하되 발급만 차단» — 조건은 채웠는데 배지가 안 나오는 최악의 경험 |
| 수열 고정, 중간 삽입 포기 | «정수 레벨 축 도입» — 구현 부담이 크고, 수열을 촘촘히 깔면 중간 삽입 필요가 줄어든다 |
| 포인트 지급 없음 | «운동량 → 포인트 환산» — 과잉정당화로 내재 동기를 밀어낸다 |
| 조건 전면 공개 | «비공개 발견형» — 아이템 배지 드랍이 이미 우연·발견을 담당해 중복 |
| 조건값에 편차(±) 미적용 | 검토 후 철회 — 조건 유형별 3중 규칙·진행률 분모 분리 등 복잡성이 이득보다 크다 |
| 기온 조건 → 달력 조건 | 실측상 걷기·자전거·등산의 기온 데이터가 **100% 비어 있다** |
| `best_efforts` 미사용 | 상위 거리를 빠르게 뛰면 하위 기록도 따라오는 **비대칭 겹침**이라 게이트가 성립하지 않는다 |
| 기록 갱신 축을 정체기 유저용으로 보완하지 않음 | 스포츠에서 기록 갱신은 본래 드물고, 나머지 8개 축에서 얼마든지 받을 수 있다 |
| 활동당 최대 5개 허용 | 드물게 일어나고 오히려 특별한 날로 읽힌다 |

## 잔여 이슈

- **자전거 기준선만 실측 근거가 없다.** 프로덕션 표본 13건이 전부 생활 이동(중앙값 4.8km·21분)이라
  아마추어 로드 통념으로 잡았다. 로드 유저가 들어오는 즉시 재조정이 필요하다.
- **기준선이 현재 유저 실측보다 크게 높다.** 러닝 주 50km는 실측 중앙값의 2.6배 — 의도된 선택이나
  초반 밀도가 충분한지는 실사용 데이터로만 확인할 수 있다.
- **「간격」 축이 「연속」만큼의 동기를 만드는지 미검증.**
