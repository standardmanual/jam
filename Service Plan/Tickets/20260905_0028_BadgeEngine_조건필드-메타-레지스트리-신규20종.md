# [BadgeEngine] 조건 필드 메타 레지스트리 + 신규 20종

> 마스터: `20260905_0026`. 선행: `20260905_0027`(스키마).

## 배경 / 문제 정의

**① DB CHECK 제약이 550종 시딩을 첫 행에서 막는다.**
`badges_condition_json_known_keys`가 허용 키 **25개를 하드코딩**하고 있어
(`migrations/117_condition_json_same_activity_flag.sql`), v5 신규 필드가 하나라도 들어간
INSERT/UPDATE는 Postgres 레벨에서 거부된다.

**② 같은 키 목록이 6곳에 복제돼 있다.**

| # | 위치 | 누락 시 |
|---|---|---|
| 1 | DB CHECK 제약 | INSERT 거부 |
| 2 | `condition-schema.ts:28-71` `MEASURABLE` / `FILTER_ONLY` | 「평가 가능한 조건 없음」으로 항상 fail |
| 3 | `types/database.ts:717-786` `BadgeCondition` | 컴파일 에러(Assert가 강제) |
| 4 | `migrations/128`의 `check_family_condition_consistency()` **두 번째 복사본** | 트리거 오판정 |
| 5 | `badge_metric_labels` 시드 | 화면에 **영문 원문 노출** |
| 6 | `admin/badges/conditionFormFields.ts:51-71` `FORM_COVERED_CONDITION_KEYS` | 어드민에 입력 UI 없음 |

**조건 필드 1개 추가에 6곳을 손대야 하고 그중 4곳은 누락돼도 조용히 통과한다.**
가장 위험한 것은 `index.ts:117-138` `matchesPerActivityCondition()` — 여기 빠지면
**조건이 무조건 통과된다**. v5는 이걸 20번 반복한다.

**③ 휴식 조건을 담을 필드가 없다.**
`BadgeCondition` 25개 필드가 전부 «활동이 존재한다»를 전제한 양의 임계값이고,
`computeUserPeriodMetrics`도 전부 활동 배열 집계라 «활동이 없는 기간»을 표현할 수단이 없다.

## 상세 요구사항

### 신규 조건 필드 (20종)

**활동 1건의 스칼라 값** — `PER_ACTIVITY_KEYS` 경로
`max_elevation_m`(최고 도달 고도) · `max_speed_kmh` · `single_distance_km` ·
`single_elevation_m` · `avg_heartrate_bpm` · `avg_watts` · `avg_cadence`

**이력 패턴** — 신규 독립 블록 필요
`rest_after_streak`(연속 후 휴식) · `rest_after_long`(장거리 후 휴식) ·
`return_gap_days`(복귀 전 휴식일) · `interval_days`(활동 간격) ·
`daily_once_count`(하루 1회 활동일) · `negative_split`(후반 구간 페이스) ·
`weekly_streak`(주 연속) · `distinct_time_bands`(서로 다른 시간대) ·
`day_of_month`(매달 N일) · `activities_within_hours`(N시간 안에 M회) ·
`personal_record_break`(개인 기록 갱신) · `month_over_month_ratio`(전월 대비) ·
`vs_personal_average`(평소 평균 대비)

> `negative_split`은 `splits_metric`이 필요하고 Strava **Summary** 응답에는 없다 — `20260905_0029` 참조.
> `personal_record_break`은 Strava `pr_count`를 쓰지 않고 **가입 이후 활동만으로 직접 계산**한다.

### 지표 라벨 (`badge_metric_labels`)
**추가 12종** — 위 필드에 대응하는 한국어 라벨·단위
**수정 2종** — `duration_minutes` 「이동시간」 → **「한 번의 이동시간」**(누적/단일 구분 불명),
`weekend_duration_hours` 「주말활동시간」 → **「주말 활동시간」**(띄어쓰기 누락)

> 어드민 지표 라벨 화면은 키 화이트리스트 대조가 없어(`api/admin/badge-metric-labels/route.ts:7`)
> **코드 배포 없이 즉시 추가 가능**하다.

### 메타 레지스트리 (신규)
필드 1개 추가 비용을 6곳 → 1곳으로 줄인다.

- `src/lib/badge-engine/conditionRegistry.ts` 신설
- 필드별 메타: 키 · 라벨 · 단위 · 입력 타입 · min/max/step · 짝 필드 · 방향성(higher/lower-is-better)
- **이 선언에서 파생시킨다**: `ALL_CONDITION_KEYS` · 어드민 입력 UI · `buildConditionJsonFromFields` ·
  `BadgeDetail.formatCondition` · `BadgesTable.conditionSummary`
- DB CHECK 배열도 이 선언에서 생성하는 마이그레이션 스크립트
