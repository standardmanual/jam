# [BadgeEngine] 발급 엔진 v5 전면 개편

> 마스터: `20260905_0026`. 선행: `20260905_0027`(스키마) · `20260905_0028`(조건 필드).

## 배경 / 문제 정의

`evaluateBadgesDetailed`의 후보 선정·게이트 판정이 «등급 4단 + 1회 보유»를 전제로 짜여 있어
v5의 네 구조를 하나도 수용하지 못한다.

| 지점 | 코드 | v5 충돌 |
|---|---|---|
| 성장 티어 | `index.ts:656-675` · `:700` | 이름당 최상위 1개만 보유 — 무한레벨·반복 불가 |
| 선행 배지 게이트 | `index.ts:703-709` | `prerequisite_badge_names` **OR 하나뿐** — 2단 게이트 표현 불가 |
| 진행 트랙 병합 | `index.ts:732-747` · `getProgressionKey():903-933` | 같은 트랙 최고값 1개만 남긴다 |
| 첫 싱크 게이트 | `index.ts:756-770` | `rarity !== 'common'` 탈락 — 등급 없는 배지에 무의미 |
| 가입 시점 | `index.ts:604` | `getActivityHistory(supabase, userId)` — **3번째 인자 `sinceDate`를 안 쓴다** |

## 상세 요구사항

### 1. 무한레벨 발급
- 후보 선정 루프(`index.ts:694-730`)를 `level` 기반 분기로 재작성
- 같은 `family_key`에서 **현재 보유 레벨 + 1**만 후보. 여러 레벨을 한 번에 넘겨도 순차 발급 또는 최상위 1개
- `RARITY_TIER` 비교를 레벨형에는 적용하지 않는다

### 2. 반복 획득
- **「발급」과 「카운터 증가」를 분리한다** — 매 회차는 `earn_count` 증가(피드 이벤트 없음),
  등급 임계값(1·5·20·50)에서만 실제 배지 발급 + 피드 기록
- 이 분리가 홍수 방지의 핵심이다. 카운터는 홍수 집계에 잡히지 않는다
- ⚠️ `23505`(중복키)를 동시 싱크 방어에 쓰는 4곳(`index.ts:825`, `sync.ts:649`,
  `itembook/checker.ts:209`, `missions/rewards.ts:115`)의 멱등 보장을 대체할 수단 필요

### 3. 2단 교차 게이트
- `condition_json`에 신규 필드 — 예: `cross_in_axis` · `cross_between_axis` · `gate_mission_badge`
- Rare→Epic은 축 내 교차(성립하는 4개 축) 또는 축 간 교차, Epic→Mystic은 축 간 교차 **AND** 미션 보상 배지
- **AND 관계를 표현할 수 있어야 한다** — 현재는 OR 배열 하나뿐
- 교차 대상은 **조건이 겹치지 않는 계열**이어야 한다. 겹치면 같은 활동으로 동시 달성돼 게이트가 자동 통과된다
  (걷기 검사 결과: 9축 중 4축만 축 내 교차 성립)

### 4. 휴식 조건
- 활동이 없는 기간을 판정하는 신규 블록. `activityFilters.ts`에 순수 헬퍼로 작성해
  **`index.ts`와 `badgeProgress.ts`가 같은 함수를 공유**하게 한다(진행률과 발급 판정이 어긋나는 사고 방지)
- **발급 시점**: 휴식은 싱크 트리거가 없으므로 **다음 활동 시 소급 판정**한다
- 역인센티브 차단: 활동이 선행되어야 성립하는 조건으로 설계(6일 연속 후 휴식 / 장거리 다음날 휴식).
  순수 공백 기반(「겨울잠」)만 쿨다운 90일

### 5. 가입 시점 앵커
- `getActivityHistory(supabase, userId, sinceDate)`의 **미사용 3번째 인자를 활성화**한다
  (`activity-history.ts:13, 20-22` — 이미 구현돼 있고 호출처 4곳이 전부 생략 중)
- 앵커: `strava_connections.created_at` 또는 `users.created_at`
- 호출처 4곳 전부 적용 — `index.ts:604` · `missions/checker.ts:119` · `sync.ts:397` · `badges/tree/page.tsx:184`
- **현재는 «그 테이블에 그것만 들어있다»는 암묵적 불변식**이라, 어드민 재동기화나 시뮬레이터가
  과거 활동을 주입하면 즉시 깨진다

### 6. 첫 싱크 게이트 재정의
- 등급 없는 배지에 `rarity !== 'common'` 판정은 무의미. 레벨형은 Lv.1만 허용하는 식으로 재정의

## 구현 계획
순서대로 하되 각 단계마다 회귀 테스트를 돌린다. 기존 테스트 6개 파일 1,887줄이 안전망이다.

1. 가입 앵커(가장 독립적, 위험 낮음) → 2. 무한레벨 → 3. 반복 카운터 → 4. 2단 게이트 → 5. 휴식
