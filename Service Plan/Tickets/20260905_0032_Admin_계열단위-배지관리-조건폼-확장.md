# [Admin] 계열 단위 배지 관리 · 조건 폼 확장

> 마스터: `20260905_0026`. 선행: `20260905_0027`(스키마) · `20260905_0028`(조건 필드).

## 배경 / 문제 정의

**어드민에 「계열」 개념이 아예 없다.**
서비스는 `badges.name`으로 계열을 묶지만(`src/lib/badgeTree.ts:180-183`), 어드민에는
계열 단위 조회·생성·정렬 수단이 없다. 현재 액티비티 배지 207종 = **87개 계열**인데,
**배지 1개당 폼 1개를 열어 등록**해야 한다.

v5는 164계열 550종이다. **이 방식으로는 카탈로그 시딩 자체가 불가능하다.**

**조건 폼이 신규 20종을 담지 못한다.**
`BadgeForm.tsx`는 조건 state 18개를 `useState`로 개별 선언하고(`:98-125`),
입력 UI를 `grid grid-cols-2` 2블록에 하드코딩한다(`:686-892`).

**희귀도 Select가 필수 + 4개 고정**이라(`:452-464`) 무한레벨을 입력할 수단이 없다.

**목록은 550종을 감당하지만 실무적으로 못 쓴다.**
페이징은 서버사이드 `PAGE_SIZE=50`이라 부하는 없으나(이미 2,032건 처리 중),
정렬이 최신순·이름순 4종뿐이고 **계열·레벨 축이 없다**.

## 상세 요구사항

### 계열 관리 화면 (신규) — `/admin/badge-families`
- **계열 목록**: 종목 · 현재 최고 레벨 · 레벨 수 · 사용 조건 지표 · 이미지 커버리지
- **계열 상세**: Lv.1~N을 한 화면 테이블에서 **인라인 편집**
- **레벨 추가**: 조건 축·이미지·설명 템플릿을 상속해 다음 레벨 1클릭 생성.
  증가 규칙(등차·등비·수동) 지정
- **일괄 재계산**: 임계값 공식을 바꾸면 계열 전체 재생성 — **변경 전후 diff 확인 후 커밋**
- **CSV/JSON 임포트**: 550종을 폼으로 등록하는 건 비현실적

## 선행 티켓이 확정한 전제 (20260905_0028, 2026-09-05 완료)

- **새 입력 UI는 레지스트리에 `form` 파서를 추가하는 것만으로 커버 목록에 자동 반영된다.**
  `FORM_COVERED_CONDITION_KEYS`·`buildConditionJsonFromFields`·어드민 표시 문구가 전부
  `conditionRegistry.ts` 선언에서 파생된다. 단 **`ConditionFormFields`에 state 키를 함께
  추가**해야 한다 — `form.read`가 받는 값은 `Record<string, string | boolean>`이라
  키 오타를 컴파일이 잡지 못하고 그 필드가 조용히 유실된다.
- **어드민 생성 API가 레벨형 배지를 만들 수 없다** — `api/admin/badges/route.ts:46`의
  `if (!name || !description || !type || !rarity || !image_url)`가 400을 낸다.
  이 티켓에서 열면서, `badges_rarity_level_exclusive` 위반 시 Postgres 원문
  (`new row for relation "badges" violates check constraint …`)이 그대로 노출되지 않도록
  3단계 에러 메시지로 감싸라.
- **`family_key`가 이름 파생이라 rename에 동기화되지 않는다.** 마이그레이션 130이
  `activity_types[1] || ':' || name`으로 구웠지만 이후 이름을 고쳐도 키는 옛 이름을 유지한다.
  ① 이름과 무관한 안정 슬러그 발급 ② 계열 정합성 트리거의 그룹핑 키를
  `(activity_types, name)` → `family_key`로 이관 — 둘을 **한 번에** 결정하라.
- **`sort_order = 0`은 맨 뒤다.** 저장소의 다른 `sort_order`(`today_cards`·`factions`·
  `item_books`)는 0이 앞이라는 반대 관습이므로, 습관대로 `.order('sort_order')`를 쓰면
  배지 트리와 순서가 갈린다.
- 어드민에 **「평가 대기」 표시**를 넣는 것을 검토하라 — 0035 시딩이 0030보다 먼저 들어오면
  어드민은 배지가 왜 발급되지 않는지 화면에서 알 수 없다(엔진 로그·시뮬레이터를 열어야 한다).

## 티켓 0030이 넘긴 것 (2026-09-05 완료)

**「저장은 되는데 영원히 안 나오는 배지」 경로가 3가지**다. 셋 다 이미 순수 함수로 존재하므로
**어드민 저장 API가 호출만 하면 된다** — 발급 시점이 아니라 저장 시점에 막는 것이 이 티켓의 몫이다.

| 경로 | 이미 있는 함수 |
|---|---|
| 짝 필드 없음(`rest_after_streak`↔`streak_days` 등) | `findBlockingConditionKeys().unpaired` |
| `repeat_count`와 휴식 조건 조합 | `restConditionKeysIn` |
| 교차 게이트 형태 오류(`family_keys` 누락·오타) | `crossGate.ts`의 정규화 |

그 밖에:
- **어드민 생성 API가 레벨형 배지를 만들 수 없다** — `api/admin/badges/route.ts`의 `!rarity` 필수 검사

- **조건 빌더 입력 UI 목록은 `conditionRegistry`의 `form` 선언에서 파생된다.** 새 필드를 넣을 때

  `Record<string, string | boolean>`이라 키 오타를 컴파일이 잡지 못하고 그 필드가 조용히 유실된다
- 교차 게이트 **값 스키마 검증**이 DB CHECK(키 이름만 검사)에도 `badge-validation.ts`에도 없다

## 판단 (2026-09-05 확정)

### ① 550종 시딩은 **시드 스크립트**로 한다 (사용자 확정) — 임포터는 이 티켓에서 뺀다

카탈로그를 코드로 정의하고 스크립트로 넣는다. **소유는 티켓 `0035`**다.

- 어드민 CSV/JSON 임포터는 **만들지 않는다** — 검증 로직을 화면에 다시 지어야 하고 비용이 크다

→ 이 티켓의 「CSV/JSON 임포트」 항목은 **범위에서 제외**한다.

### ② 계열 관리 화면은 «조회 + 편집 + 레벨 생성·일괄 재계산»까지 (사용자 확정)

티켓 원문 그대로다(임포터만 제외). 164계열을 폼 하나씩 열어 관리하는 건 불가능하다.

### ③ `family_key`는 **생성 시 발급하고 이후 불변**이다

티켓이 「①안정 슬러그 ②트리거 그룹핑 키 이관 — 둘을 한 번에 결정하라」고 남긴 지점.

**근거**: 2단 교차 게이트(`cross_in_axis` 등)가 대상 계열을 **`family_key`로 지정**한다
(티켓 `0030` B2). 이름 파생 키를 유지한 채 어드민이 배지 이름을 고치면 **교차 게이트 참조가
조용히 끊긴다** — 게이트가 영원히 안 열리거나(대상 소멸) 엉뚱한 계열을 가리킨다.

**결정**
- **어드민 폼에서 `family_key`를 편집할 수 없다.** 읽기 전용으로 보여주기만 한다
- **이름을 바꿔도 `family_key`는 그대로다.** 계열 정체성은 키가 갖고 이름은 표시일 뿐이다
- **슬러그 형식은 `0035` 시드 스크립트가 정한다.** 어드민이 교차 게이트에 손으로 적어야 하므로
  **읽을 수 있는 형태**여야 한다(예: `walking:night-walker`)
- 비어 있을 때의 폴백(`familyKeyOf()`의 `#name:` 접두)은 그대로 둔다 — 레거시 안전망

### ④ 계열 정합성 트리거의 그룹핑 키를 `family_key`로 이관한다

`(activity_types, name)` → `family_key`. **마이그레이션 134**(133까지 사용, 2026-09-05 실측).

- 마이그레이션 128의 알려진 한계(「이름 오타로 계열이 쪼개지면 검사가 스킵된다」)가 해소된다
- **기존 207종은 동작이 바뀌지 않는다** — 130이 `family_key = "{activity_type}:{name}"`로 구웠으므로
  그들에게는 두 그룹핑이 **같은 집합**이다
- ⚠️ 130·131·132·133의 변경분(레벨형 스킵 두 줄 · `repeat_count` · 교차 3종 제외 · 트리거
  `UPDATE OF` 5컬럼)을 되돌리면 회귀다. 앞선 마이그레이션들이 서로를 보존한 방식을 그대로 따를 것

## A묶음 구현 기록 (2026-09-05) — status는 그대로 둔다(B·C 남음)

### A-1. 저장 시점 검증 3종
판정 함수를 새로 짜지 않고 **어드민 저장 API가 부르게** 했다. 순수 판정은
`src/lib/admin/badge-condition-guards.ts`에 모았다 — `badge-validation.ts`는
`drop-engine`(→ `next/headers`)을 물어 **서버 전용**이라 조건 폼(클라이언트 컴포넌트)이
같은 문자열을 쓸 수 없었다. 이제 폼과 API가 같은 함수·같은 문구를 쓴다.

| 경로 | 부르는 함수 |
|---|---|
| 짝 필드 없음 | `findBlockingConditionKeys().unpaired` |
| `repeat_count` + 휴식 | `restConditionKeysIn` |
| 교차 게이트 형태 오류 | `crossGate.ts`의 `normalizeRequirement` (신규 `findCrossGateShapeError`) |

`pending`(평가 구현 대기)은 **막지 않는다** — 시딩(0035)이 평가 구현(0030)보다 먼저
들어오는 것이 전제다. 대신 화면에 「평가 대기」로 표시한다.

### A-2. 조건 폼 레지스트리 기반 전환
- `conditionRegistry.ts`의 `form`에 `write`(역방향)·`controls`(입력 UI)·`section`을 더했다.
  BadgeForm은 이 선언을 순회해 입력을 **생성**한다 — 필드마다 JSX가 없다.
- 폼 state 20개 `useState` → `ConditionFormFields` 객체 1개.
  「모든 `form.fields`가 `emptyConditionFormFields()`의 키에 존재한다」를 테스트로 고정했다.
- 폼 커버리지: 19종 → **46종**. 남은 3종은 `day_of_week`(요일 다중 선택 전용 UI 필요) ·
  `route`(엔진 평가 없음) · `poi_id`(지점 연결 UI로 관리).
- `month`가 배열([6,7])이면 예전에는 폼이 첫 달로 접었다 — 쉼표 목록으로 왕복하게 고쳤다.
- `findUnrepresentableConditionKeys`: 폼 지원 필드인데도 `write→read` 왕복이 깨지는 값
  (쉼표가 든 배지 이름, 형태가 깨진 게이트)을 화면 경고로 드러낸다.

### A-3. 레벨형 배지 생성
- `POST /api/admin/badges`의 `!rarity` 필수 검사 해제 · `level` 저장 · `PUT`도 `level` 병합.
- `findRarityLevelError`가 CHECK(`badges_rarity_level_exclusive`) 위반을 **Postgres 원문 대신**
  한국어 문구로 막는다.
- 폼에 「배지 종류」 Select(등급형/레벨형) 추가 — 판정은 `badgeKind.ts`의 `isLeveledBadge`.
  레벨형은 **활동 배지 전용**으로 뒀다(아이템은 등급으로 드랍 풀을, 체크인은 표시를 가른다).

### A-4. 2단 게이트 입력 UI
`family_keys` + `min_rarity` + `min_count`를 게이트 3종 각각에 입력한다. 결합 관계를
화면에 드러냈다 — 교차 둘은 「다음 중 하나만 충족해도 통과해요 (OR)」 상자에, 미션 게이트는
「그리고 (AND)」 아래 별도 상자에 둔다.

### family_key
`PUT`은 `family_key`를 **병합하지 않는다**(판단 ③). 폼은 편집 모드에서 읽기 전용으로만 보여준다.

화면과 발급이 어긋난다).

| 화면 | 내용 |
|---|---|
| 목록 | 종목 · 계열(이름 + 키) · 종류 · 최고 자리 · 자리 수 · 사용 조건 지표 · 이미지 커버리지 |
| 상세 | Lv.1~N(또는 Common~Mystic) 인라인 편집(이름·설명·이미지·축 값) → 고친 행만 저장 |
| 자리 추가 | 최고 자리의 조건 축·필터·이미지·설명·계열 키·`sort_order`를 상속. 등차·등비·수동 |
| 일괄 재계산 | 축 하나의 공식을 바꿔 계열 전체 재계산 |

- **일괄 재계산은 확인 없이 쓰지 않는다.** 서버가 강제한다 — `confirm_token`이 없으면
  계획만 돌려주고 아무것도 쓰지 않으며, 토큰은 계획 내용(대상·현재값·새 값)에서 나오므로
  diff를 본 뒤 계열이 바뀌면 커밋이 409로 거부된다.
- **축이 없는 배지는 건너뛴다** — 없는 축을 새로 넣으면 계열 안 측정 필드 조합이 달라져
  정합성 트리거가 EXCEPTION을 낸다.
- 저장은 전부 기존 배지 API(`POST`/`PUT /api/admin/badges`)를 탄다 — A묶음의 저장 시점 검증
  3종을 이 화면만 우회하는 경로를 만들지 않기 위해서다.
- `sort_order`: 「0은 맨 뒤」 규칙을 다시 선언하지 않고 `badgeTree.ts`의 `sortRank`를 export해
  공유했다. 자리 추가는 계열의 값을 물려준다(안 물려주면 그 배지만 트리 맨 뒤로 떨어진다).
- **PostgREST 1000행 상한**: 경고에 그치지 않고 `range`로 끝까지 넘겨 전량을 가져온다

### A묶음 — 「저장은 되는데 영원히 안 나오는 배지」를 저장 시점에 막는다

경로 3가지가 이제 **DB 쓰기 전 400**으로 거부된다(리뷰어가 라우트 핸들러를 직접 호출해 확인).
판정은 새로 짜지 않고 기존 순수 함수를 그대로 부른다 —
`findBlockingConditionKeys().unpaired` · `restConditionKeysIn` · `crossGate.normalizeRequirement`.

**레벨형 배지를 만들 수 있게 됐다** — 생성 API의 `!rarity` 검사와 폼의 `?? 'common'` 접기가
둘 다 막고 있었다. CHECK 위반은 Postgres 원문 대신 한국어로 나간다.
`month` 배열이 첫 달로 접히던 유실도 함께 고쳤다.

**게이트 FAIL** — 새로 넣은 「재현 불가」 경고가 `JSON.stringify` 비교라 **키 순서에 민감**했다.
Postgres jsonb가 `time_range`를 `{end, start}`로 주는데 레지스트리는 `{start, end}`로 만들어,
**207종 중 19종**이 수정 화면을 열기만 해도 거짓 경고를 띄웠다(실제 왕복 손실 0건).
`deepEqualIgnoringKeyOrder`로 교체했고 **배열은 순서가 의미를 가지므로 정렬하지 않는다**.
화면에 `**함께**` 마크다운이 문자 그대로 보이던 것도 함께 고쳤다.

### B묶음 — 계열 관리 화면 · 트리거 그룹핑 이관

**일괄 재계산의 확인 강제를 서버가 한다.** `confirm_token`이 계획 내용(대상·현재값·새 값)에서

**`family_key`는 「비어 있으면 발급」만** 허용한다 — 같은 값이어도 재발급을 거부해
발급과 변경을 한 경로에 두지 않았다.

**마이그레이션 134** — 사전 확인으로 **두 그룹핑이 72계열로 같은 집합**임을 확인한 뒤 실행했다.

마이그레이션 128이 명시한 「이름 오타로 계열이 쪼개지면 검사가 스킵된다」 **구멍이 닫혔다.**
130의 레벨형 스킵 · 132의 `repeat_count` · 133의 교차 게이트 제외가 전부 생존한다.
트리거 `UPDATE OF`에 `family_key`가 추가돼 키 발급 UPDATE도 정합성 검사를 탄다.

**게이트 WARN** — 「자리 추가」의 증가 방향이 뒤집혔다. `source`는 **가장 높은 자리**에서
상속하는데 제안은 **가장 낮은 빈 자리**여서, Mystic 하나뿐인 계열에 **Mystic보다 임계값이 큰

「계열을 위로 잇는다」이므로 가장 높은 자리의 바로 위를 제안하도록 맞췄다.
중간이 빈 계열의 구멍 메우기는 상속 없이 임의 등급을 만드는 일이라 기존 배지 폼의 몫이다.

로그가 그때만 없었다). C가 staging의 선형 후손이라 ff 머지로 **B → C 순서가 그대로** 지켜졌다.
