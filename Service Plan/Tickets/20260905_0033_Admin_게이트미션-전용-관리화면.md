# [Admin] 게이트 미션 전용 관리 화면

> 마스터: `20260905_0026`. 선행: `20260905_0030`(발급 엔진 — 게이트 판정).

## 배경 / 문제 정의

v5는 **종목당 8개 × 5종목 = 미션 40개**가 Mystic·Lv.8+를 여는 열쇠가 된다.
기간형 이벤트 미션과 데이터 모델·운영 리듬이 완전히 달라 같은 화면에서 관리하면 실수가 난다.

**현재 미션 관리 화면의 한계**
- 폼이 인라인 접이식이고 별도 페이지가 없다(`MissionList.tsx:175-315`)
- `condition_json`을 **생짜 JSON 텍스트에어리어**로 입력하고 `JSON.parse` 성공 여부만 검증(`:124-129`)
- API가 `body`를 **검증 없이 그대로 insert**(`api/admin/missions/route.ts:19-34`)
- 목록 컬럼이 4개(제목/타입/완료수/상태)뿐 — **게이트 배지 컬럼·필터·검색이 전부 없다**
- 게이트 배지 연결이 `gated_badge_id` 단일 선택(`:261-276`)

**스키마에 축 개념이 없다.** `missions` 테이블(`database.generated.ts:932-985`)에
「어느 축을 여는지」를 저장할 컬럼이 없다.

**노출 규칙이 코드에 하드코딩돼 있다.**
`visibility.ts:85-114`가 `gated_badge_id` → 그 배지의 rarity tier → 유저의 **같은 이름** 배지
최고 tier를 ±1로 비교한다. v5의 «해당 축 Epic 보유 AND Mystic 미보유»는 이 규칙으로 표현할 수 없다.

⚠️ **`visibility.ts:92`의 `RARITY_TIER[rarity] ?? 0`은 등급 없는 배지를 게이트로 걸면
`0 <= 1`이 되어 `OPEN`을 반환한다 — 에러도 로그도 없이 게이팅이 꺼진다.**

## 상세 요구사항

### 스키마
- `missions.gate_axis` — 여는 축
- `missions.gate_stage` — 단계(Rare→Epic / Epic→Mystic)
- `missions.visibility_rule_json` — 노출 조건
- 또는 별도 `gate_missions` 테이블. 기간형 미션과 컬럼이 거의 겹치지 않으므로 분리도 합리적

### 화면 `/admin/gate-missions` (신규)
- **매트릭스 목록** — 축 × 단계 격자. 축별로 두 단계가 다 채워졌는지 **커버리지가 한눈에**
- **구조화 입력** — 여는 축 / 게이트 단계 / 보상 배지 / 노출 조건을 자유 JSON이 아니라 선택 UI로
- **노출 미리보기** — 유저 id를 넣으면 그 유저에게 `open`/`locked`/`hidden` 중 무엇으로 보이는지 판정.
  **현재 `visibility` 로직을 어드민에서 확인할 방법이 전혀 없다**
- **정합성 검사** — 축은 있는데 미션이 없는 구멍 / 같은 축·단계에 미션 2개 이상 /
  보상 배지가 비활성·삭제됨

### 노출 판정 재작성
- `visibility.ts:85-114`를 축·단계 기반으로 교체
- `visibility-server.ts:106-117`의 「최대 5트리×4등급=20개, 유저당 175행」 전제가 550종에서 붕괴 —
  이 두 파일은 **미션 목록·상세·참가 API 가드·오늘 카드 4개 진입점의 공유 규칙**이다
