# [Admin] 배지 카탈로그 일괄 작업 도구

> 마스터: `20260905_0026`. 후속: `20260905_0039`(리셋 실행)가 이 도구를 쓴다.

## 배경 / 문제 정의

기존 배지 207종 폐기와 참조 정리를 안전하게 수행할 도구가 없다.

**현재 존재하는 유일한 일괄 수단**은 «현재 페이지 선택 행 비활성화»뿐이고
(`BadgesTable.tsx:359-420`), 전용 API 없이 단건 `PATCH`를 순차 호출한다(`:361-370`).
범위도 현재 페이지 50건이다.

**유저 초기화 API는 유저 1명 단위**라(`api/admin/users/[id]/reset/route.ts`) 배지 계열 단위로 못 쓴다.
게다가 이 API는 `user_checkin_badge_earns` · `user_family_progress` · `notifications` · 포인트를
건드리지 않고, `strava_activities`를 남긴 채 `last_synced_at=NULL`로 만들어
**재싱크가 0건 처리되는 상태**를 만든다(멱등 필터가 전부 걸러냄).

**단건 삭제의 참조 가드가 불완전하다.**
`api/admin/badges/[id]/route.ts:128-135`가 검사하는 6개 테이블에
`point_transactions.source_badge_id`(NO ACTION FK) · `missions.reward_badge_ids` ·
`missions.gated_badge_id` · `combination_recipes.ingredient_badge_ids`가 빠져 있다.
`point_transactions` 참조가 생기면 사전 체크를 통과한 뒤 FK 위반 →
**raw Postgres 에러 문자열이 500으로 그대로 노출**된다.

## 상세 요구사항

### 영향 분석 (dry-run)
대상 배지를 지정하면 실행 전에 보여준다.
- 획득 이력 건수
- 참조하는 투데이 카드 / 미션 / 컬렉션 건수
- 기존 단건 참조 카운트 로직(`api/admin/badges/[id]/route.ts:128-161`)을 **일괄로 확장**하고
  누락된 4개 참조를 추가

### 일괄 작업
- **필터 기준 전체 선택** — 페이지 경계 무관 (예: `type=activity` 전체)
- **일괄 비활성화 / 일괄 하드삭제**
- **획득 이력 선택 삭제** — 유저 단위가 아니라 **배지 id 집합 기준**
- **참조 정리** — 폐기 대상을 가리키는 `today_cards.badge_ids`(라이브 16장) ·
  `missions.reward_badge_ids`(15건) · `gated_badge_id`(15건)를 목록으로 뽑아 개별 해제

### 안전장치
- **2단계 확인** — 대상 건수 + 영향 건수를 타이핑 확인. service_role 전권이라 필수
- 실행 로그 — 무엇을 몇 건 처리했는지 기록

### 임포트
CSV/JSON으로 계열·레벨·조건을 일괄 등록·갱신. `20260905_0032`의 계열 관리와 함께 설계한다.

## 구현 계획
1. 참조 카운트 로직 확장 (누락 4개 추가) — 단건 삭제 가드도 함께 고쳐진다
2. dry-run API
3. 일괄 실행 API + 2단계 확인 UI
4. 임포터

## 잔여 이슈
- 하드삭제 vs 소프트삭제 선택. 새 카탈로그를 완전히 새 UUID로 시작하면 하드삭제가 합리적이나,
  소프트가 가역적이라 안전하다
