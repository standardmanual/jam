# [Admin] 배지 카탈로그 일괄 작업 도구

> 마스터: `20260905_0026`. 후속: `20260905_0039`(리셋 실행)가 이 도구를 쓴다.

## 배경 / 문제 정의

기존 배지 207종 폐기와 참조 정리를 안전하게 수행할 도구가 없다.

**현재 존재하는 유일한 일괄 수단**은 «현재 페이지 선택 행 비활성화»뿐이고
(`BadgesTable.tsx:359-420`), 전용 API 없이 단건 `PATCH`를 순차 호출한다(`:361-370`).
범위도 현재 페이지 50건이다.

**유저 초기화 API는 유저 1명 단위**라(`api/admin/users/[id]/reset/route.ts`) 배지 계열 단위로 못 쓴다.
게다가 이 API는 `user_checkin_badge_earns` · `user_family_progress` · `notifications` · 포인트를
건드리지 않고, `strava_activities`를 남긴 채 `last_synced_at=NULL`로 만들어
**재싱크가 0건 처리되는 상태**를 만든다(멱등 필터가 전부 걸러냄).

**단건 삭제의 참조 가드가 불완전하다.**
`api/admin/badges/[id]/route.ts:128-135`가 검사하는 6개 테이블에
`point_transactions.source_badge_id`(NO ACTION FK) · `missions.reward_badge_ids` ·
`missions.gated_badge_id` · `combination_recipes.ingredient_badge_ids`가 빠져 있다.
`point_transactions` 참조가 생기면 사전 체크를 통과한 뒤 FK 위반 →
**raw Postgres 에러 문자열이 500으로 그대로 노출**된다.

## 상세 요구사항

### 영향 분석 (dry-run)
대상 배지를 지정하면 실행 전에 보여준다.
- 획득 이력 건수
- 참조하는 투데이 카드 / 미션 / 컬렉션 건수
- 기존 단건 참조 카운트 로직(`api/admin/badges/[id]/route.ts:128-161`)을 **일괄로 확장**하고
  누락된 4개 참조를 추가

### 일괄 작업
- **필터 기준 전체 선택** — 페이지 경계 무관 (예: `type=activity` 전체)
- **일괄 비활성화 / 일괄 하드삭제**
- **획득 이력 선택 삭제** — 유저 단위가 아니라 **배지 id 집합 기준**
- **참조 정리** — 폐기 대상을 가리키는 `today_cards.badge_ids`(라이브 16장) ·
  `missions.reward_badge_ids`(15건) · `gated_badge_id`(15건)를 목록으로 뽑아 개별 해제

### 안전장치
- **2단계 확인** — 대상 건수 + 영향 건수를 타이핑 확인. service_role 전권이라 필수
- 실행 로그 — 무엇을 몇 건 처리했는지 기록

### 임포트
CSV/JSON으로 계열·레벨·조건을 일괄 등록·갱신. `20260905_0032`의 계열 관리와 함께 설계한다.

## 구현 계획
1. 참조 카운트 로직 확장 (누락 4개 추가) — 단건 삭제 가드도 함께 고쳐진다
2. dry-run API
3. 일괄 실행 API + 2단계 확인 UI
4. 임포터

## 판단 확정 (2026-09-05 사용자 결정)

### ① 폐기 방식 = **소프트삭제**
가역성을 택했다. 하드삭제는 되돌리려면 `backup_badges_activity`에서 복원해야 한다.

**소프트삭제의 정본 수단은 `deleted_at`이다 — `is_active` 컬럼은 존재하지 않는다.** (실측)
- `information_schema.columns`로 확인: `badges`에 `is_active` 없음. 어드민 UI가 말하는
  「비활성화」는 `deleted_at = now()`의 표시 이름일 뿐이다
  (`api/admin/badges/[id]/route.ts:213` — `active: false → deleted_at = now()`, `true → null`).
- **엔진이 이미 이 필터를 쓴다**: `badge-engine/index.ts:754`의 `.is('deleted_at', null)`.
  따라서 소프트삭제만으로 발급 후보에서 즉시 빠진다 — 엔진 쪽 추가 작업이 없다.

**소프트삭제를 택한 데 따르는 파급 — 구현이 반드시 감당해야 하는 것:**
- 207종이 DB에 계속 남는다. 0035가 550종을 넣으면 **액티비티 배지만 757행**이 된다.
  어드민 목록·정합성 검사·계열 그룹핑·`nextFamilySlot` 같은 계열 계산은 **폐기분을 세면
  안 된다** — 「자리 추가」가 죽은 계열의 레벨을 보고 엉뚱한 슬롯을 제안하게 된다.
- **PostgREST 1000행 페이지 상한**(0035 선행 조건 b)이 이 티켓에서 먼저 문제가 된다.
  757행은 상한 아래지만, 필터 없이 `badges` 전체를 읽는 경로는 이미 상한을 넘는다
  (체크인 1,789 + 아이템 1,825). 일괄 도구의 「필터 기준 전체 선택」은 **처음부터
  페이지 끝까지 순회**하도록 만든다 — 나중에 고치는 것이 아니라 지금 그렇게 만든다.
- 폐기분을 되살리는 경로(`deleted_at = null`)도 일괄로 제공한다. 가역성을 이유로 고른
  방식이므로 되돌리는 수단이 단건뿐이면 그 이유가 성립하지 않는다.

### ② CSV/JSON 임포터 = **이번 범위에서 제외**
임포터를 만들 유일한 용례였던 「550종 시딩」이 티켓 `20260905_0035`에서 **시드 스크립트**로
확정돼 사라졌다. 시딩 이후의 카탈로그 수정 수요가 실제로 생기면 그때 별도 티켓으로 뺀다.
이번 티켓은 **폐기·참조 정리·dry-run·안전장치**에 집중한다.

## 구현 기록 (2026-09-05, 리뷰 대기)

### 만든 것
- `lib/admin/badge-references.ts` — **참조 카운트 단일 출처.** 배지를 가리키는 15개 자리를
  FK 규칙(NO ACTION / CASCADE / 없음)과 함께 선언하고 한 번에 센다. 큰 테이블은 `count`,
  작은 테이블(투데이 카드·미션·레시피·컬렉션)은 행을 통째로 읽어 «어느 행이 가리키는지»까지
  뽑는다. id는 80개씩 쪼개 넘긴다(URL 길이 상한).
- `lib/admin/badge-bulk.ts` — 계획·확인 토큰·확인 문구(순수 함수, 화면과 API가 공유).
- `lib/admin/badge-bulk-query.ts` — 대상 조회(**`range` 페이지 끝까지 순회**) + 실행 로그.
- `api/admin/badges/bulk` — ① 토큰 없으면 dry-run만, ② 토큰+확인 문구가 맞을 때만 실행.
- `api/admin/badges/bulk/detach` — 투데이 카드·미션 보상·미션 게이트 개별 해제.
- `/admin/badges/bulk` 화면 — 필터 → 작업 → 영향 분석 → 참조 정리 → 2단계 확인 → 실행 로그.
- 마이그레이션 `136_admin_badge_bulk_runs.sql` (**작성만 함, 미실행**).

### 고친 것 (티켓 배경의 기존 결함)
단건 하드 삭제 가드(`api/admin/badges/[id]/route.ts`)가 직접 세던 6곳을 위 공용 함수로 교체했다.
누락됐던 `point_transactions.source_badge_id`(NO ACTION FK — raw 500 노출 경로) ·
`missions.reward_badge_ids` · `missions.gated_badge_id` · `combination_recipes.ingredient_badge_ids`가
함께 세어진다. 추가로 `combination_recipes.required_activity_badge_id`(NO ACTION, 같은 500 경로) ·
`today_cards.badge_ids` · 컬렉션 2자리도 포함했다.

### 확정 전제를 지킨 자리
- 폐기 = 소프트삭제(`deleted_at`)만. **하드삭제 경로는 이 도구에 없다.** 되살리기도 일괄로 제공.
- 「필터 기준 전체 선택」은 처음부터 `range` 페이지 순회다(1000행 상한을 나중에 고치지 않았다).
- CSV/JSON 임포터는 만들지 않았다.
- 계열 계산(`nextFamilySlot` 등)에 폐기분이 섞이는 자리를 점검했다 — `fetchActivityFamilyBadges`가
  이미 `deleted_at IS NULL`을 걸고 계열 화면·계열 상세·일괄 재계산·게이트 정합성 검사가 전부 그
  함수를 쓴다. 폐기분을 **일부러** 함께 보는 두 자리(계열 키 중복 검사·게이트 미션이 참조하는
  배지 표시)는 근거가 주석에 있어 그대로 뒀다.
