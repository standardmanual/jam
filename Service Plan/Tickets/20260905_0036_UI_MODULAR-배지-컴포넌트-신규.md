# [UI] MODULAR 배지 컴포넌트 신규·개편

> 마스터: `20260905_0026`. 후속: `20260905_0037`(배지 트리)이 이 컴포넌트를 쓴다.

## 배경 / 문제 정의

배지 트리 리뉴얼에 필요한 DS 컴포넌트를 먼저 만든다.
프로토타입에서 구조·색·그리드가 확정됐다(마스터 산출물 링크).

**등급 의존도 실측**

| 컴포넌트 | 의존 | 판정 |
|---|---|---|
| `RarityBadge` | `:14-19` config 4키, `:33` **미지 값을 조용히 Common으로 폴백** | 개편 + 레벨 칩 신규 |
| `BadgeStageRail` | `:220-332` 등급 서열이 곧 레일 구조, `overflow`·`flexWrap` **둘 다 없음** | 개편 |
| `BadgeTreeSummaryHeader` | `:47` `repeat(4, 1fr)` — 요약이 «등급 4칸» 그 자체 | 개편 |
| `UnlockConditionSheetContent` | `:115-119` «또는»만, `:135` 「배지 · 어느 등급이든 1개」 하드코딩 | 개편 |
| `DualAxisGauge` | `:126` RarityBadge 한 줄. `AxisRow`(`:45-73`)는 등급 무관 | 수정 |
| `RecentSyncBanner` | 등급 참조 0건 | **그대로 사용** |

⚠️ **토큰 함정** — 등급 색이 등급 밖으로 새어 있다.
`--color-tag-3/4/5`가 `--color-rarity-epic/rare/mystic`을 참조하고,
**폼 입력 에러 색이 `--color-rarity-mystic`**이다(`forms/{Input,Checkbox,Select,Textarea}.jsx` 4개 파일).
등급 토큰을 지우면 **폼 에러 표시가 함께 깨진다.**

## 상세 요구사항

### 신규

**`BadgeLevelGauge`** — 무한레벨형
- props: `name · level · current · next · left · fraction · silhouette`
- **`condition`·`metric`을 받지 않는다** — 배지 이름이 지표를 말하고, 값 행이 조건을 말한다
- 레벨 수와 무관하게 **높이 고정**. 550종의 핵심 해법
- 레벨 칩 = `--color-secondary` 채움 + 흰 텍스트 (**5.86:1**, AA 통과)

**`BadgeStampRow`** — 반복형
- 누적 횟수는 **×N 칩 하나로만**. 점 그리드를 쓰지 않는다
  (47회를 점 47개로 그리면 100회를 넘는 순간 의미를 잃고, 축약하면 임의 기준이 화면에 드러난다)

**`BadgeStatusSection`** — 상태 섹션
- 「다음 목표」와 「받은 배지」 **둘뿐**. 설계 분류(누적·주기)를 노출하지 않는다
- 접힘 상태에서도 개수를 노출해 숨은 콘텐츠에 힌트
- 펼친 섹션만 진행 계산을 요청 — 서버 계산량 절감

**`BadgeSilhouette`** — 미획득 외형
- **원본 이미지를 로드하지 않는다.** 현행 `grayscale(1)`은 원본 URL이 네트워크에 나가
  «외형 비공개»가 성립하지 않는다 (5곳에서 사용 중)
- 공통 SVG를 `opacity .22`로. 조건 텍스트는 그대로 노출

### 개편

**`BadgeStageRail` v2**
- `earnCount` prop → **×N 칩**을 행 오른쪽 끝에
- 눈금마다 `rarity`를 받아 **아이콘 아래 3px 등급색 바** — 44px 폭에 「Mystic」 칩은 안 들어간다.
  등급명은 눈금의 `aria-label`이 읽는다
- `gates: [{kind:'cross'|'mission'}]` 배열 — 게이트 자리 폭 36px → **44px**(자물쇠 2개 수용)
- **4눈금 상한을 코드로 강제** — `stops.length > 4`면 개발 빌드에서 에러

**`RarityBadge`**
- 미지 값을 Common으로 폴백하지 않고 명시적으로 처리
- **등급 색은 `--color-rarity-*` 기존 값 유지** — 변경하지 않는다

**`RARITY_LABEL` 통합** — 5곳에 중복 재선언된 것을 하나로.
`rarity.ts:1-7` 주석이 같은 유형의 누락 사고(티켓 20260813_003)를 기록하고 있다

### 공통 레이아웃 규칙 (프로토타입 확정)
- 계열 카드는 **2열 그리드** `[썸네일 44px][내용 1fr]`, 썸네일이 `grid-row: 1 / -1`로
  **정렬 엣지를 하나만** 만든다
- 1행 그리드 `[52px 칩][1fr 이름][auto 카운터]` — 칩 폭 고정이라 이름 시작 x가 모든 계열에서 같다
- 값 행 그리드 `[5ch][auto][1fr][auto]` — 현재값 **5ch 우측 정렬**로 **`/` 구분자가 세로 정렬**
- 진행 바는 **트랙 기준 그라데이션** — `--status-short-solid` → `--status-done-solid`,
  `clip-path: inset(0 calc(100% - var(--fill)) 0 0)`. fill 안에서 그라데이션을 주면
  진행률과 무관하게 늘 같은 그림이 압축돼 보인다
- 미획득은 이름·칩·바에서 **색을 전부 거둔다**

## 색 (측정 완료, 카드 `#1a1a1a` 위)
| 역할 | 토큰 | 대비 |
|---|---|---|
| 현재값 · 채우는 중 | `--status-short-solid` | 11.04:1 |
| 현재값 · 다 채움 | `--status-done-solid` | 13.81:1 |
| 지표·목표 | `--color-text-secondary` | 8.21:1 |
| 레벨 칩(흰 텍스트) | `--color-secondary` | 5.86:1 |
| 미션 게이트 자물쇠 | `--color-primary` | **4.18:1** ⚠️ |

미션 자물쇠만 텍스트 기준 미달이나 아이콘이라 비텍스트 기준(3:1)은 통과.
교차 자물쇠와 구분하는 유일한 색이라 유지하고, **형태로도 갈라 두었다**(자물쇠 vs 별).

**이번 리뉴얼에서 새로 만든 색은 없다.**

## 탐색·재사용 판정 (2026-09-06, 오케스트레이터 직접 — `/jam-work` 1.5단계)

DS 34개 컴포넌트와 서비스 연결 현황을 실측한 결과다. **이대로 따를 것.**

### 서비스 ↔ MODULAR 연결 실측

서비스가 `@ds/*`를 **65건** import한다. 배지 관련 실사용:
`RarityBadge` 9 · `ProgressBar` 8 · `Card` 9 · `BadgeRevealCarousel` 2 ·
`UnlockConditionSheetContent`·`RecentSyncBanner`·`DualAxisGauge`·`BadgeTreeSummaryHeader`·
`BadgeStageRail` 각 1.

→ **`RarityBadge`(9곳)와 `ProgressBar`(8곳)는 파괴적으로 바꾸면 안 된다.** 기존 호출부가
그대로 동작해야 한다.

### ① `ProgressBar` — **확장한다** (재사용 불가, 신규 작성도 아님)

**티켓이 요구하는 「트랙 기준 그라데이션」을 현재 `ProgressBar`로는 만들 수 없다.**
구현이 `width: N%` + `background: color`이라(`ProgressBar.jsx:79-82`),
`color`에 그라데이션 문자열을 넣으면 **그라데이션이 fill 안에서 압축된다** —
티켓이 「진행률과 무관하게 늘 같은 그림이 압축돼 보인다」며 금지한 바로 그 결과다.

**판정: `ProgressBar`에 트랙 기준 그라데이션 모드를 추가한다.**
- 자체 바를 새로 그리면 `ProgressBar`와 두 벌이 되고, 서비스 8곳·`DualAxisGauge`가
  쓰는 컴포넌트와 표현이 갈린다
- **기본 동작을 바꾸지 마라.** 새 prop(예: `fillMode="track-gradient"`)으로만 켠다 —
  8곳이 즉시 영향받는다
- `clip-path: inset(0 calc(100% - var(--fill)) 0 0)` 방식은 티켓에 적힌 그대로

### ② `BadgeStatusSection` — **신규** (`Accordion` 재사용 안 함)

`Accordion`은 「미도입 8종」이고(서비스에 대응 개념 없음, 티켓 20260820_010에서 유지/보류
확정) API가 **「한 번에 하나만 열림」**(`Accordion.d.ts`)이다. 티켓은 「다음 목표」·「받은
배지」가 **각각 독립으로 접히고, 펼친 섹션만 진행 계산을 요청**하는 것이 핵심이라 맞지 않는다.
→ 신규로 만들되 `Accordion`을 서비스에 끌어다 쓰지 마라.

### ③ `BadgeLevelGauge`의 값 행 — `DualAxisGauge.AxisRow`를 **참고만**

`AxisRow`(`DualAxisGauge.jsx:45-73`)는 등급 무관하고 `[label][bar][value]` 3열이다.
티켓이 요구하는 값 행은 `[5ch][auto][1fr][auto]` **4열**이고 「현재값 5ch 우측 정렬로
`/` 구분자가 세로 정렬」이 요점이라 구조가 다르다. → 신규. 다만 색 규칙
(`--status-short-solid` / `--status-done-solid`)은 `AxisRow`와 **같은 값을 쓴다**.

### ④ `RarityBadge` — 재사용 + 비파괴 개편

9곳이 쓴다. 미지 값 폴백 제거는 **호출부가 유효한 등급만 넘기고 있는지 먼저 확인**한 뒤에
한다. 레벨 칩은 `RarityBadge`에 분기를 넣지 말고 **별도 컴포넌트로** 빼라 —
`RarityBadge`는 «등급»을 그리는 컴포넌트이고 레벨형은 `rarity`가 NULL이다(v5).

### ⑤ 신규 3종은 그대로 신규

`BadgeLevelGauge` · `BadgeStampRow` · `BadgeSilhouette` — DS에 대응 개념이 없다.

## 티켓 전제 정정 — `RARITY_LABEL`은 이미 통합돼 있다

티켓 구현 계획 1번이 「`RARITY_LABEL` 통합 (5곳 중복)」인데, **서비스 코드는 이미
통합됐다.** `src/lib/rarity.ts`가 유일한 정의이고, 티켓 `20260905_0027`이
`badgeProgressText.ts`·`BadgeFamilyRailItem.tsx`의 중복을 흡수했다(그 파일 주석에 근거 있음).

**실측 결과 남은 재선언은 7곳이고 전부 어드민이다:**

| 파일 | 성격 |
|---|---|
| `app/admin/itembooks/ItemBookForm.tsx:39` | 재선언 |
| `app/admin/simulator/page.tsx:165` | 재선언 |
| `app/admin/users/[id]/BadgeHistoryTable.tsx:29` | 재선언 |
| `components/admin/badges/BadgesTable.tsx:43` | 재선언 |
| `components/admin/badges/BadgeDetail.tsx:23` | 재선언 |

`lib/admin/composeActivityBadgeImage.ts:126`의 `RARITY_LABELS`는 **다른 것**이다
(영문 대문자, 이미지에 굽는 용도) — 통합 대상이 아니다.

→ **이번 티켓은 DS 작업이고 어드민은 MODULAR 적용 제외 대상이다.**
어드민 7곳 통합은 이 티켓에서 하지 말고 별도로 다룬다. 구현 계획 1번은 **불필요**하다.
