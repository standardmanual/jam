# [UI] 배지 트리 전면 리뉴얼

> 마스터: `20260905_0026`. 선행: `20260905_0031`(진행 계산) · `20260905_0036`(MODULAR 컴포넌트).

## 배경 / 문제 정의

현행 트리는 «등급 4단 = 가로 레일»을 **데이터 모델·정렬·레이아웃·집계 네 층에서 각각 독립적으로**
전제한다. 한 층만 고쳐도 나머지가 막는다 — **전면 리뉴얼이다.**

| 층 | 지점 | 무슨 일이 일어나는가 |
|---|---|---|
| 데이터 모델 | `badgeTree.ts:294-299` | 계열 눈금이 **`RARITY_ORDER` 4회 루프로만** 생성 — 등급 없는 배지는 stages에 못 들어가고 **화면에서 사라진다** |
| 집계 | `BadgeTreeClient.tsx:104-118` | `byRarity[stage.rarity].total += 1` — 키가 없으면 **런타임 TypeError로 페이지 크래시** |
| 레이아웃 | `BadgeStageRail.jsx:220-332` | 눈금을 flex 가로 배치, **overflow·flexWrap 둘 다 없음**. 8눈금 482px는 카드를 뚫는다 |
| 요약 | `BadgeTreeSummaryHeader.jsx:47` | `repeat(4, 1fr)` — 요약이 «등급 4칸» 그 자체 |
| 정렬 | `badgeTree.ts:34-80` | **배지 이름 72개 하드코딩**. 없는 이름은 `indexOf`가 `-1` → **그리드 맨 앞으로 튀어나온다** |
| 게이트 | `badgeTree.ts:252-253` | 선행 배지 링크가 그 계열의 **Common을 찾는다**. 무한레벨형(Common 없음)을 지목하면 **락이 조용히 사라진다** |
| 게이트 | `badgeTree.ts:240-247` | 미션 락이 있으면 그것만 반환 — «미션 AND 선행배지» 표현 불가 |
| 상태 | `badgeTreeConditionStatus.ts:14` | 4종뿐 — «1단 통과, 2단 대기»를 나타낼 값이 없다 |

**가장 결정적인 것은 계열(레일)의 정의 자체가 «같은 `name`을 4등급 순서로 늘어놓은 것»이라는 점이다.**
등급 축을 빼면 레일을 만들 방법이 없다. 레일은 세로 목록의 가로 압축이 아니라 **등급 서열의 시각화**다.

## 상세 요구사항

### 구조 (프로토타입 확정)
```
[종목 탭]  ← 가로 스크롤, 레이아웃 마진 밖으로 bleed
[요약: 38 / 114 · 다음 목표 4개]

다음 목표                                    ⌄
  [Lv.3] 자기 초월
  ▬▬▬▬▬▬▬▬░░
   9.8 / 12.4km                    2.6km 남음
  ...
받은 배지  38개                              ›
```

- **설계 분류를 노출하지 않는다** — 「누적·주기·최고 기록」은 유저 언어가 아니고
  배지 이름과 뜻이 겹친다. 배지 이름이 곧 구분자다
- 구분은 **「다음 목표 / 받은 배지」 상태 둘뿐**
- 목록은 **다음 목표가 가까운 순** — 이 화면의 질문이 «다음에 뭘 하면 되나»이므로
- 값 행에 **「N 남음」** — 이전에는 `178 / 210km`를 보고 32를 암산해야 했다
