# [UI] 피드·프로필·획득 연출 v5 대응

> 마스터: `20260905_0026`. 선행: `20260905_0036`(MODULAR). `20260905_0037`(트리)과 **병렬 가능**.

## 배경 / 문제 정의

배지 트리 외에도 반복 획득·무한레벨을 수용하지 못하는 화면이 여럿이다.
가장 심한 셋은 각각 다른 이유로 깨진다.

**① 피드 — 같은 배지 15회가 픽셀 단위로 동일한 카드 15장**
`FeedSection.tsx:363-390`의 그룹화 축이 `strava_activity_id` 하나뿐이다.
`:107-114` `checkinInfo()`가 `poi_name` 유무로 ×N 표시를 가르는데 **액티비티 배지는 무조건 null**이다.
`:406-422` 헤드라인도 이벤트 수를 「배지 N개」로 표기한다.

**② 프로필 — ×N을 정책으로 막고 있다**
`ProfileClient.tsx:144-155`가 `badge_id` 기준 중복 제거를 **「갤러리는 항상 고유 배지만」으로 주석에 명시**한다.
타인 프로필(`[username]/page.tsx:303-324`)도 배지별 최초 1건만 남기고 횟수를 폐기한다.

**③ 획득 연출 — Lv·×N을 넣을 여백이 없다**
`BadgeRevealCarousel.jsx:505`의 카드 슬롯이 「이미지 → 등급 pill → 이름 → 설명」 고정이고
이미지가 `maxHeight: 46%`다. `:360` 스크린리더가 등급을 반드시 낭독한다.
`:154-158`에 반복 획득을 접는 로직이 없다.

## 상세 요구사항

### 피드
- 그룹화 축에 **배지 id 추가** — 같은 배지 반복 획득은 한 카드에 `×N`
- 액티비티 배지도 `earnCount`를 받아 `CheckinCountBadge`와 같은 패턴으로 표시
  (체크인 배지는 이미 `×N` 필이 있다 — `FeedSection.tsx:79-88`)
- 헤드라인 문구 재작성

**⚠️ 휴식 배지의 소급 발급**이 피드 정렬에 영향을 준다.
`feed/page.tsx:58`이 `created_at desc`로 정렬하므로 **소급분이 「방금 획득」으로 최상단에 뜬다**.
발급 시점(`created_at`)과 성립 시점을 구분할지 판단 필요.

### 프로필
- 갤러리 중복 제거 정책 재검토 — `×N` 표시로 전환
- 통계 탭이 4개 고정(`:425-458`) — 무한레벨 지표 추가 여부
- 가상화 없는 3열 그리드(`:322-335`) — 550종에서 재검토

### 획득 연출
- 카드 슬롯에 **레벨 칩 / ×N 자리** 확보
- 반복 획득을 한 장으로 접기 — 같은 배지 3회 획득이 카드 3장이 되면 안 된다
- 스크린리더 문구 — 등급 없는 배지 대응

### 배지 상세 (`/badges/[id]`)
- 조건 문구가 `if` 66줄 나열(`page.tsx:87-183`)이라 **신규 조건은 전부
  「관리자가 직접 발급하는 배지예요」로 오표시**된다(`:165-167`)
- `20260905_0028`의 메타 레지스트리 기반으로 교체
- `.maybeSingle()`(`:229-234`)이라 반복 획득 표현 불가
- 진행률 표시 자체가 없다

### 그 외 수정 필요
- `lib/activity-feed/hydrate.ts:34` — `rarity`만 리프레시. 레벨·횟수 미지원.
  `:44-51`이 **소프트삭제 배지의 과거 피드를 화면에서 제거**한다
- 홈 `(main)/page.tsx:134` — RarityBadge 무조건 렌더
- 오늘 카드 `TodayCardStack.tsx:98-117` — **보유 여부 판정 없이** 아트를 나열하고
  `:49,151` 미획득 배지 이미지를 커버로 승격
- 알림 `notifications/message.ts:240-242` — `asRarity()`가 미지 값을 **조용히 common으로 강등**,
  `batch/following.ts:255`에 `.in('rarity',['epic','mystic'])` DB 필터
- 공유 카드 `buildBadgeShareBlob.ts:135-139` — 3행 하드코딩, Lv·×N 슬롯 없음

### 🔴 실측으로 규모가 드러난 것 — 배지 상세 오표시

`badges/[id]/page.tsx`의 조건 문구는 `if (condition.X)` **18개**만 다루고,
하나도 안 걸리면 **「관리자가 직접 발급하는 배지예요」**로 떨어진다(`:165-167`).

다루는 키 20종: `active_days_count` · `day_of_week` · `distance_km` · `duration_minutes` ·
`elevation_gain_m` · `max_pace_sec_per_km` · `min_speed_kmh` · `month` · `monthly_km` ·
`season` · `season_count` · `season_count_all` · `streak_days` · `temperature_max_c` ·
`temperature_min_c` · `time_range` · `total_count` · `weekend_duration_hours` · `weekly_count`

**프로덕션 실측: 비미션 590종 중 209종 46계열(35%)이 오표시된다.**

v5가 도입한 `single_distance_km` · `single_elevation_m` · `max_elevation_m` ·
`personal_record_break` · `interval_days` · `return_gap_days` · `rest_after_streak` ·
`rest_after_long` · `avg_heartrate_bpm` · `avg_watts` · `avg_cadence` ·
`month_over_month_ratio` · `vs_personal_average` · `max_speed_kmh` ·
`activities_within_hours` · `distinct_time_bands` · `weekly_streak` · `day_of_month` 등이
전부 `if` 목록에 없다.

→ **구현 계획 1번이 맞다.** 그리고 `20260905_0028`이 만든 `conditionRegistry.ts`가
이미 49종의 라벨·설명을 갖고 있으므로 **거기서 문구를 만들어야 한다.**
`if`를 늘리는 방식으로 고치면 다음 카탈로그 변경에서 같은 일이 반복된다.

### 🔴 알림 — 레벨형 193종은 팔로잉 알림이 아예 안 간다

`notifications/batch/following.ts:255`가 `.in('rarity', ['epic','mystic'])`로 **DB에서**
거른다. **v5 레벨형은 `rarity`가 NULL이라 이 필터에 절대 걸리지 않는다** —
193종 26계열의 획득이 팔로워에게 한 건도 알려지지 않는다.

같은 파일 `:289` 주석이 「위 필터 때문에 실제로는 null이 올 수 없다」고 적어 두었는데,
그 전제가 v5에서 깨졌다. **주석이 가리키는 가정 자체를 다시 봐야 한다.**

`message.ts:248-251`의 `asRarity()`는 빈 문자열이면 `null`을 돌려주므로 레벨형에
「Common」을 붙이지는 않는다. 다만 **미지 값(빈 문자열이 아닌)은 여전히 `'common'`으로
강등**한다 — 0036이 `RarityBadge`에서 없앤 것과 같은 유형의 조용한 폴백이다.

### 재사용 판정

- **`BadgeLevelChip`(0036)을 쓴다** — 레벨 칩을 새로 만들지 마라. 0037이 이미
  `BadgeTrophyGridCard`에서 `rarity: null` + `level` 폴백으로 연결했다. 같은 패턴을 따르라.
- **체크인 배지의 `×N` 필이 이미 있다**(`FeedSection.tsx:79-88` `CheckinCountBadge`).
  액티비티 배지 `×N`은 **그 컴포넌트를 재사용**하거나 같은 시각 문법을 쓴다 — 새로 만들지 마라.
- **`RarityBadge`는 미지 값을 그리지 않는다**(0036). 레벨형에 이걸 넘기면 칩이 사라진다.
  `rarity == null`이면 `BadgeLevelChip`으로 갈라라.
- 조건 문구는 **`conditionRegistry.ts` 단일 출처**에서 만든다. `badgeProgressText.ts`가
  이미 레지스트리 라벨을 폴백으로 쓰는 선례가 있다(0031).

### 티켓 전제 정정 — 실루엣은 폐기됐다

관련 판단 시 **2026-09-06 확정 규칙**을 따르라:
**미획득 배지는 원본 이미지를 `grayscale(1)`로 표시한다.** 실루엣을 만들지 마라.
