# [UI] 피드·프로필·획득 연출 v5 대응

> 마스터: `20260905_0026`. 선행: `20260905_0036`(MODULAR). `20260905_0037`(트리)과 **병렬 가능**.

## 배경 / 문제 정의

배지 트리 외에도 반복 획득·무한레벨을 수용하지 못하는 화면이 여럿이다.
가장 심한 셋은 각각 다른 이유로 깨진다.

**① 피드 — 같은 배지 15회가 픽셀 단위로 동일한 카드 15장**
`FeedSection.tsx:363-390`의 그룹화 축이 `strava_activity_id` 하나뿐이다.
`:107-114` `checkinInfo()`가 `poi_name` 유무로 ×N 표시를 가르는데 **액티비티 배지는 무조건 null**이다.
`:406-422` 헤드라인도 이벤트 수를 「배지 N개」로 표기한다.

**② 프로필 — ×N을 정책으로 막고 있다**
`ProfileClient.tsx:144-155`가 `badge_id` 기준 중복 제거를 **「갤러리는 항상 고유 배지만」으로 주석에 명시**한다.
타인 프로필(`[username]/page.tsx:303-324`)도 배지별 최초 1건만 남기고 횟수를 폐기한다.

**③ 획득 연출 — Lv·×N을 넣을 여백이 없다**
`BadgeRevealCarousel.jsx:505`의 카드 슬롯이 「이미지 → 등급 pill → 이름 → 설명」 고정이고
이미지가 `maxHeight: 46%`다. `:360` 스크린리더가 등급을 반드시 낭독한다.
`:154-158`에 반복 획득을 접는 로직이 없다.

## 상세 요구사항

### 피드
- 그룹화 축에 **배지 id 추가** — 같은 배지 반복 획득은 한 카드에 `×N`
- 액티비티 배지도 `earnCount`를 받아 `CheckinCountBadge`와 같은 패턴으로 표시
  (체크인 배지는 이미 `×N` 필이 있다 — `FeedSection.tsx:79-88`)
- 헤드라인 문구 재작성

**⚠️ 휴식 배지의 소급 발급**이 피드 정렬에 영향을 준다.
`feed/page.tsx:58`이 `created_at desc`로 정렬하므로 **소급분이 「방금 획득」으로 최상단에 뜬다**.
발급 시점(`created_at`)과 성립 시점을 구분할지 판단 필요.

### 프로필
- 갤러리 중복 제거 정책 재검토 — `×N` 표시로 전환
- 통계 탭이 4개 고정(`:425-458`) — 무한레벨 지표 추가 여부
- 가상화 없는 3열 그리드(`:322-335`) — 550종에서 재검토

### 획득 연출
- 카드 슬롯에 **레벨 칩 / ×N 자리** 확보
- 반복 획득을 한 장으로 접기 — 같은 배지 3회 획득이 카드 3장이 되면 안 된다
- 스크린리더 문구 — 등급 없는 배지 대응

### 배지 상세 (`/badges/[id]`)
- 조건 문구가 `if` 66줄 나열(`page.tsx:87-183`)이라 **신규 조건은 전부
  「관리자가 직접 발급하는 배지예요」로 오표시**된다(`:165-167`)
- `20260905_0028`의 메타 레지스트리 기반으로 교체
- `.maybeSingle()`(`:229-234`)이라 반복 획득 표현 불가
- 진행률 표시 자체가 없다

### 그 외 수정 필요
- `lib/activity-feed/hydrate.ts:34` — `rarity`만 리프레시. 레벨·횟수 미지원.
  `:44-51`이 **소프트삭제 배지의 과거 피드를 화면에서 제거**한다
- 홈 `(main)/page.tsx:134` — RarityBadge 무조건 렌더
- 오늘 카드 `TodayCardStack.tsx:98-117` — **보유 여부 판정 없이** 아트를 나열하고
  `:49,151` 미획득 배지 이미지를 커버로 승격
- 알림 `notifications/message.ts:240-242` — `asRarity()`가 미지 값을 **조용히 common으로 강등**,

- 공유 카드 `buildBadgeShareBlob.ts:135-139` — 3행 하드코딩, Lv·×N 슬롯 없음
