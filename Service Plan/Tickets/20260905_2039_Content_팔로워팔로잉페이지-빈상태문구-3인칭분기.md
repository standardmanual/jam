# [Content] 팔로워/팔로잉 전체 페이지 빈 상태 문구 3인칭 분기

## 배경 / 문제 정의

티켓 `20260903_2022`(프로필 화면 4개 탭의 빈 상태 문구 3인칭 분기)에서 범위 밖으로 남긴
후속 이슈다. 프로필 화면(`ProfileClient.tsx`)의 팔로워/팔로잉 **탭**은 이미 `isOwnProfile`
기준으로 3인칭 분기가 적용됐지만, 팔로워/팔로잉 **전체 페이지** 라우트
(`/{username}/followers`, `/{username}/following`)는 같은 문제를 그대로 갖고 있다 —
빈 상태 문구가 본인 시점 2인칭 행동 유도로만 작성돼 있는데 타인이 봐도 그대로 노출된다.

`jam-web/src/lib/i18n/ko.ts`의 `social` 네임스페이스:
- `emptyFollowers`: '팔로워가 없어요' / `emptyFollowersBody`: '누군가 팔로우하면 여기에 표시돼요'
- `emptyFollowing`: '아직 팔로우한 사람이 없어요' / `emptyFollowingBody`: '유저가 팔로우를 시작하면 여기에 표시돼요'

`emptyFollowersBody`·`emptyFollowingBody`는 본인 시점에서도 행동 유도라기보다 상태 설명에
가까워 원래 2인칭성이 약하지만, 타인 프로필에서 그대로 쓰이면 "당신이 팔로우하면" 같은
독자 지칭 뉘앙스가 남아 여전히 어색하다.

### 왜 지금 처리하지 않았나 (선행 조건)

이 두 라우트는 서버 컴포넌트(`page.tsx`)라서 `ProfileClient.tsx`처럼 이미 존재하는
`isOwnProfile` prop이 없다. "대상 유저(`target`) vs 로그인 유저(`user`)가 같은지" 비교하는
판정 로직 자체가 아직 없는 상태다 — 이번 티켓에서 함께 추가한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `jam-web/src/app/(main)/[username]/followers/page.tsx`,
  `jam-web/src/app/(main)/[username]/following/page.tsx` 각각에서
  `const isOwnProfile = target.id === user.id`를 계산해 `EmptyState`에 분기 적용.
  (두 파일 모두 이미 `target`과 `user`를 조회해두므로 추가 쿼리 불필요.)
- `20260903_2022`가 적용한 패턴을 그대로 따른다:
  - `t()` 헬퍼로 `{name}` 보간 (`jam-web/src/lib/i18n/index.ts`)
  - 이름 폴백: `getDisplayName(target) || d.profile.anonymous`
    (`ProfileClient.tsx`의 `subjectName` 계산과 동일 규칙)
  - 타인 시점에서는 description(body)을 생략 — 행동 유도가 성립하지 않음

### UI/UX 관점

- `Service Plan/Specs/UX_WRITING_GUIDELINE.md` "2) 사용자 중심의 호칭과 주어 설정" 원칙
  (`OO님` 표기)을 따른다.
- `ko.ts`의 `profile.emptyFollowersOther`/`emptyFollowingOther`와 문구가 겹치지 않도록
  `social` 네임스페이스에 별도 키로 추가한다 (이 페이지는 `d.social.*`를 쓰고 있어 네임스페이스가
  다름 — 혼용하지 말 것).
  - 예시: `emptyFollowersOther: '{name}님에게 아직 팔로워가 없어요'`,
    `emptyFollowingOther: '{name}님이 아직 아무도 팔로우하지 않았어요'`
    (`20260903_2022`에서 확정한 동일 문구를 재사용해 용어 일관성을 유지한다)

## 구현 계획

1. `ko.ts`의 `social` 네임스페이스에 `emptyFollowersOther`/`emptyFollowingOther` 키 추가
   (기존 `emptyFollowers`/`emptyFollowersBody`/`emptyFollowing`/`emptyFollowingBody`는 유지 —
   본인 시점 문구로 계속 사용).
2. `followers/page.tsx`·`following/page.tsx`에 `isOwnProfile` 계산 추가.
3. `EmptyState`의 `title`/`description`을 `isOwnProfile` 기준으로 분기.
4. UX Writing 검증 체크리스트를 완료 기록에 채운다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`followers/page.tsx`·`following/page.tsx`(서버 컴포넌트)에 `isOwnProfile = target.id === user.id`와
`subjectName = getDisplayName(target) || d.profile.anonymous`를 계산해 추가하고, `EmptyState`의
`title`/`description`을 `isOwnProfile` 기준으로 분기했다. 본인 시점은 기존 2인칭 문구(title+description)를
그대로 쓰고, 타인 시점은 `social.emptyFollowersOther`/`emptyFollowingOther`(`{name}님...` 3인칭)를
`t()`로 보간해 title만 노출하고 description은 생략했다. `20260903_2022`가 `ProfileClient.tsx`에서
확립한 패턴(계산식·이름 폴백·body 생략 규칙)을 그대로 따랐다. `ko.ts`의 `social` 네임스페이스에
`emptyFollowersOther`/`emptyFollowingOther` 키를 신규 추가했고(기존 `profile.emptyFollowersOther` 등과는
네임스페이스가 달라 재사용하지 않음), 기존 본인 시점 키(`emptyFollowers`/`emptyFollowersBody`/
`emptyFollowing`/`emptyFollowingBody`)는 그대로 유지했다.
