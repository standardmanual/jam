# [UI] 배지 트리가 `?activity=` 쿼리로 종목을 열도록

## 배경 / 문제 정의

`/badges/tree?activity=running`으로 들어가도 항상 첫 트리(걷기)가 열린다. 탭 클릭은 정상
동작하므로 특정 종목을 가리키는 URL을 만들 수 없다 — 딥링크·공유가 불가능하다.

티켓 `20260906_0940`(v5 전반 QA) ④번 항목이고, 코드 확인 결과 **결함이 아니라 미구현**이다.
읽는 코드가 아예 없다.

```ts
// src/app/(main)/badges/tree/page.tsx
export default async function BadgeTreePage() {   // ← searchParams 인자 자체가 없다
```

```tsx
// src/app/(main)/badges/tree/BadgeTreeClient.tsx:73
const [activeActivity, setActiveActivity] = useState<ActivityType>(
  trees[0]?.activityType ?? 'walking'          // ← 항상 첫 트리
)
```

### 왜 지금 하는가 — 트리만 관례에서 이탈해 있다

`(main)` 그룹에서 `searchParams`를 읽는 화면은 8개다(`badges`·`badges/[id]`·
`collections/[id]`·`drops`·`onboarding`·`profile`·`search`). **트리만 빠져 있다.**

특히 바로 옆 `/badges`는 `?tab=`을 이미 읽는다. 즉 「명세에 없던 신기능」이 아니라
**이 저장소의 기존 패턴을 트리에 마저 적용하는 일**이다.

### 선례 확인 — 쿼리 기반 이동은 승인된 패턴이다

티켓 `20260826_006`은 `highlight` 쿼리 파라미터를 제거했지만 **`?tab=activity` 이동 자체는
명시적으로 유지**했다("탭 이동 자체는 유지, 하이라이트만 제거"). 제거 대상은 시각 강조였지
쿼리 기반 이동이 아니다. 이번 작업은 그 유지된 쪽과 같은 부류다.

`20260905_0037`(트리 전면 리뉴얼)에는 딥링크·쿼리에 대한 논의나 미채택 기록이 없다.
의도적으로 배제된 게 아니라 다뤄지지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점

**형제 화면 `/badges`의 패턴을 그대로 따른다.** 새 패턴을 만들지 않는다.

1. **`src/app/(main)/badges/tree/page.tsx`**
   - `searchParams: Promise<{ activity?: string }>`를 받아 `await`한다
   - 값을 `BadgeTreeClient`에 `initialActivity` prop으로 넘긴다
   - 서버에서 조회 범위를 바꾸지 않는다 — 트리는 전 종목을 이미 다 만든다.
     쿼리는 **어느 탭을 열지만** 정한다

2. **`src/app/(main)/badges/tree/BadgeTreeClient.tsx`**
   - `initialActivity?: string` prop 추가
   - `activeActivity` 초기값을 지연 초기화(`useState(() => ...)`)로 바꿔
     정규화 결과 → 기존 폴백(`trees[0]?.activityType ?? 'walking'`) 순으로 결정
   - **정규화 함수는 두 가지를 모두 통과해야 유효로 친다**:
     ① `ActivityType` 5종(`cycling`·`running`·`trail_running`·`hiking`·`walking`) 중 하나인가
     ② **그 종목의 트리가 실제로 `trees`에 있는가**
     — ②를 빠뜨리면 `?activity=hiking`인데 등산 트리가 없을 때 탭이 하나도 선택되지 않아
     화면이 비어 보인다. 유효하지 않으면 `null`을 돌려주고 기존 폴백으로 떨어진다
     (`/badges`의 `normalizeTab`이 미지 값에 `null`을 주는 것과 같은 처리)

3. **탭 클릭 시 URL은 갱신하지 않는다.** `/badges`도 하지 않는다(`BadgesClient`에
   `router.replace`가 없다). 읽기만 추가하고 쓰기는 범위 밖이다 — 히스토리 정책은
   별도 판단 사항이다

### UI/UX 관점

- 유효한 종목이면 그 탭이 선택된 상태로 화면이 열린다. 그 외 동작은 변화 없다
- 잘못된 값·없는 종목이면 **오류를 보이지 않고** 기존 기본 탭으로 연다
  (URL은 사용자가 손으로 고칠 수 있는 입력이므로 조용히 폴백하는 편이 맞다)
- 사용자 노출 문구 추가·변경 없음

### 컨텐츠 관점

해당 없음.

## 구현 계획

1. `page.tsx`에 `searchParams` 수신 → `initialActivity` 전달
2. `BadgeTreeClient.tsx`에 prop 추가 + 지연 초기화 + 정규화(유효값 ∧ 트리 존재)
3. 회귀 확인: 쿼리 없이 들어갔을 때 기존과 동일하게 첫 트리가 열리는지

### 1.5 UI 탐색·재사용 판정 (오케스트레이터 결정 — 이대로 따를 것)

**판정: 재사용. 신규 컴포넌트를 만들지 않는다. MODULAR(`design-system/`)를 건드리지 않는다.**

근거:
- 이번 변경은 **초기 상태값의 출처만 바꾸는 데이터 흐름 작업**이다. 새로 그리는 UI가 없다
- 탭 UI는 이미 `SlidingTabs`가 담당하고 `activeKey`를 받는 제어형이다.
  선택된 탭을 바꾸는 것은 기존 prop으로 끝난다
- 따라서 1.6(모듈러-서비스 연결 범위)도 해당 없음 — `design-system/` 변경이 없다

**하지 말 것**: 종목 선택용 새 컴포넌트·새 훅·URL 동기화 유틸을 만들지 않는다.
`/badges`의 `normalizeTab` 패턴을 트리에 맞게 옮기는 선에서 끝낸다.

### 범위 밖 (이번 티켓에서 하지 않음)

- 탭 클릭 시 URL 갱신(`router.replace`) — 히스토리 정책 판단이 필요하다
- `?activity=`를 만들어내는 내부 링크 추가 — 현재 트리로 오는 내부 링크는
  `BadgesClient.tsx:185` 하나뿐이고 파라미터가 없다. 이 티켓은 **읽기만** 연다
- 트리 안 특정 눈금·계열로 바로 여는 딥링크

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`/badges/tree`가 `?activity=`를 읽어 해당 종목 탭을 연 상태로 열리게 했다. `/badges`의
`?tab=` 패턴(page.tsx가 `searchParams`를 await → 클라이언트가 지연 초기화)을 그대로 옮겼다.

- `page.tsx`: `searchParams: Promise<{ activity?: string }>` 수신 → `initialActivity` prop 전달.
  서버 조회 범위는 그대로 둔다(트리는 어차피 전 종목을 만든다)
- `BadgeTreeClient.tsx`: `initialActivity` prop + `normalizeActivity()` 추가.
  ① `ActivityType` 5종인가 ② 그 종목 트리가 `trees`에 실재하는가 — 둘 다 통과해야 유효,
  아니면 `null`을 돌려 기존 폴백(`trees[0]?.activityType ?? 'walking'`)으로 떨어진다
- 탭 클릭 시 URL 갱신은 하지 않는다(범위 밖, `/badges`와 동일)
