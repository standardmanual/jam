# [Infra] `vitest run` 전체가 항상 레드로 끝나 회귀 감시에 못 쓴다

## 배경 / 문제 정의

`npx vitest run`을 전체로 돌리면 **항상 실패로 끝난다.** 실테스트 1,041건은 전부 통과하는데,
storybook 프로젝트의 **스토리 파일 44개가 「No test suite found」로 실패**한다.

티켓 `20260906_1312`(중복 쿼리 파라미터) 게이트 리뷰가 범위 밖 발견물로 보고했다.

### 왜 문제인가 — 초록/빨강 신호가 죽었다

**「테스트가 통과하는가」를 명령 하나로 물을 수 없다.** 지금은 매번 출력을 읽고 «실패 44건은
원래 그런 것»이라고 사람이 걸러내야 한다. 그래서:

- **회귀가 이 노이즈에 묻힌다.** 실테스트 하나가 새로 깨져도 이미 빨간 화면에서는 눈에 안 띈다
- CI·pre-push 같은 자동 게이트가 이 명령을 쓸 수 없다
- 서브에이전트가 매번 «전체는 레드지만 실테스트는 통과»를 다시 확인하고 보고해야 한다
  (실제로 여러 티켓에서 반복됐다)

## 상세 요구사항

### 서비스/코드베이스 관점

**① 먼저 원인을 확정한다 — 고치는 방법이 여기서 갈린다**

「No test suite found」는 vitest가 그 파일을 **테스트 파일로 수집했는데 그 안에 `test`/`it`이
하나도 없을 때** 나온다. 즉 스토리 파일이 테스트 대상으로 잡히고 있다는 뜻이다. 확인할 것:

- `vitest.config.*`(또는 `vitest.workspace.*`)의 storybook 프로젝트 정의와 `include` 패턴
- `@storybook/experimental-addon-test`(또는 `storybook/test` 계열) 애드온이 설치·설정돼 있는가
  — 스토리를 테스트로 돌리려면 이 애드온이 스토리를 테스트로 **변환**해야 하는데,
  설정만 있고 변환기가 빠졌으면 정확히 이 증상이 난다

**② 두 방향 중 하나를 고른다 — 어느 쪽인지 티켓에 근거와 함께 남길 것**

| 방향 | 언제 맞나 |
|---|---|
| **스토리를 테스트에서 제외** | 스토리를 테스트로 돌릴 계획이 없다. `include`에서 빼거나 storybook 프로젝트 자체를 뺀다. **비용이 가장 작다** |
| **스토리 테스트를 제대로 켠다** | 스토리로 렌더 스모크를 얻고 싶다. 애드온·브라우저 러너 설정이 필요해 비용이 크다 |

**임의로 고르지 말 것.** 스토리북을 Vercel 배포에서 뺀 결정(티켓 `20260906_1142`)과 함께
보면 스토리에 테스트 인프라를 더 태울 이유가 약하지만, 그건 스펙 소유자 판단이다.
**두 안의 비용과 얻는 것을 정리해 사용자에게 묻는다.**

**③ 판정 기준**

`npx vitest run`이 **exit 0으로 끝나야 한다.** 실테스트 1,041건이 그대로 통과하는 것을
전후로 대조한다(숫자가 줄면 무언가를 잘못 뺀 것이다).

## 구현 계획

1. `vitest.config.*` / `vitest.workspace.*` / `package.json` 스크립트 실측
2. 44개 파일이 어떤 패턴에 걸려 수집되는지 특정
3. 두 방향의 비용·이득 정리 → 사용자 확인
4. 적용 후 `npx vitest run` exit 0 + 실테스트 1,041건 유지 확인

- CI 파이프라인 신설
