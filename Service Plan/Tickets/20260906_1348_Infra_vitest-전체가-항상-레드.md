# [Infra] `vitest run` 전체가 항상 레드로 끝나 회귀 감시에 못 쓴다

## 배경 / 문제 정의

`npx vitest run`을 전체로 돌리면 **항상 실패로 끝난다.** 실테스트 1,041건은 전부 통과하는데,
storybook 프로젝트의 **스토리 파일 44개가 「No test suite found」로 실패**한다.

티켓 `20260906_1312`(중복 쿼리 파라미터) 게이트 리뷰가 범위 밖 발견물로 보고했다.

### 왜 문제인가 — 초록/빨강 신호가 죽었다

**「테스트가 통과하는가」를 명령 하나로 물을 수 없다.** 지금은 매번 출력을 읽고 «실패 44건은
원래 그런 것»이라고 사람이 걸러내야 한다. 그래서:

- **회귀가 이 노이즈에 묻힌다.** 실테스트 하나가 새로 깨져도 이미 빨간 화면에서는 눈에 안 띈다
- CI·pre-push 같은 자동 게이트가 이 명령을 쓸 수 없다
- 서브에이전트가 매번 «전체는 레드지만 실테스트는 통과»를 다시 확인하고 보고해야 한다
  (실제로 여러 티켓에서 반복됐다)

## 상세 요구사항

### 서비스/코드베이스 관점

**① 먼저 원인을 확정한다 — 고치는 방법이 여기서 갈린다**

「No test suite found」는 vitest가 그 파일을 **테스트 파일로 수집했는데 그 안에 `test`/`it`이
하나도 없을 때** 나온다. 즉 스토리 파일이 테스트 대상으로 잡히고 있다는 뜻이다. 확인할 것:

- `vitest.config.*`(또는 `vitest.workspace.*`)의 storybook 프로젝트 정의와 `include` 패턴
- `@storybook/experimental-addon-test`(또는 `storybook/test` 계열) 애드온이 설치·설정돼 있는가
  — 스토리를 테스트로 돌리려면 이 애드온이 스토리를 테스트로 **변환**해야 하는데,
  설정만 있고 변환기가 빠졌으면 정확히 이 증상이 난다

**② 두 방향 중 하나를 고른다 — 어느 쪽인지 티켓에 근거와 함께 남길 것**

| 방향 | 언제 맞나 |
|---|---|
| **스토리를 테스트에서 제외** | 스토리를 테스트로 돌릴 계획이 없다. `include`에서 빼거나 storybook 프로젝트 자체를 뺀다. **비용이 가장 작다** |
| **스토리 테스트를 제대로 켠다** | 스토리로 렌더 스모크를 얻고 싶다. 애드온·브라우저 러너 설정이 필요해 비용이 크다 |

**임의로 고르지 말 것.** 스토리북을 Vercel 배포에서 뺀 결정(티켓 `20260906_1142`)과 함께
보면 스토리에 테스트 인프라를 더 태울 이유가 약하지만, 그건 스펙 소유자 판단이다.
**두 안의 비용과 얻는 것을 정리해 사용자에게 묻는다.**

**③ 판정 기준**

`npx vitest run`이 **exit 0으로 끝나야 한다.** 실테스트 1,041건이 그대로 통과하는 것을
전후로 대조한다(숫자가 줄면 무언가를 잘못 뺀 것이다).

### UI/UX 관점

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**① 원인 확정** — `vitest.config.*`의 `include`/`exclude`나 애드온 미설치 문제가 아니었다.
`@storybook/addon-vitest`(변환 애드온)와 `@vitest/browser-playwright`는 이미 설치·설정돼 있었고,
`storybookTest()` 플러그인의 `transform()` 훅도 스토리 파일마다 정상적으로 호출되고 있었다.

실제 원인은 **`@storybook/addon-vitest`의 업스트림 버그**다. 이 애드온은 스토리를 테스트로
변환할 때 각 `test()` 호출을 `if (isRunningFromThisFile) { ... }` 가드로 감싸는데, 이 가드는
`convertToFilePath(import.meta.url)`(브라우저 쪽 URL)과 `globalThis.__vitest_worker__.filepath`
(OS 파일 경로)를 비교해서 "지금 이 스토리 파일 안에서 실행 중인가"를 판정한다.
그런데 `convertToFilePath`
(`node_modules/@storybook/addon-vitest/dist/vitest-plugin/test-utils.js`)는
`url.replace(/^file:\/\//, '').replace(/^\/+([a-zA-Z]:)/, '$1').replace(/%20/g, ' ')` —
**공백(`%20`)만 디코딩하고 나머지는 `decodeURIComponent`를 쓰지 않는다.**

이 저장소의 절대경로(`/Volumes/뚝섬하드/시현/JAM!/...`)에 한글이 포함돼 있어서, 브라우저가
넘기는 `import.meta.url`은 한글이 퍼센트 인코딩된 문자열인데 `convertToFilePath`는 이를
디코딩하지 않고 그대로 실제(디코딩된) 파일 경로와 `.includes()` 비교를 한다 — 영원히
불일치하고, 가드가 항상 `false`가 되어 `test()`가 단 한 번도 호출되지 않는다. 결과적으로
44개 스토리 파일 전부가 예외 없이 "테스트를 하나도 등록하지 못한 파일"이 되어
「No test suite found」가 난다.

**직접 재현·검증**: `node_modules/@storybook/addon-vitest/dist/vitest-plugin/test-utils.js`의
`convertToFilePath`에 `decodeURIComponent`를 임시로 추가하고 vite/storybook 캐시
(`node_modules/.cache/storybook`, `node_modules/.vite`)를 지운 뒤 재실행하니 스토리가 정상적으로
테스트로 등록되어 통과했다(패치 후 원상 복구함, node_modules는 git 추적 대상이 아님).

**② 방향 선택 — "스토리를 테스트에서 제외"를 골랐다.**
저장소 경로에 한글을 쓰는 것은 프로젝트 운영 규칙(`CLAUDE.md`)이 못 박은 것이라 우리 쪽에서
바꿀 수 없다. `addon-vitest`의 업스트림 버그를 고치려면 `patch-package`로 의존성 코드를
패치해야 하는데, 스토리 렌더 스모크 테스트 하나(그것도 지금까지 단 한 번도 통과한 적이
없어 실질적으로 아무 가치도 제공하지 못했던 기능)를 위해 들이기엔 비용·유지보수 부담이
크다. 스토리북은 이미 Vercel 배포에서도 제외됐다(티켓 `20260906_1142`) — 스토리에 테스트
인프라를 더 태울 이유가 약하다는 그 결정과도 일치한다. `npm run storybook`(로컬 :6006,
눈으로 컴포넌트를 보는 용도)은 이 변경과 무관하게 그대로 동작한다.

**구현**: `vitest.config.ts`에서 `test.projects`의 2번째 항목("storybook" 프로젝트,
`storybookTest` 플러그인 + `@vitest/browser-playwright` 브라우저 설정)을 통째로 제거했다.
프로젝트가 하나만 남아 `projects` 래퍼 자체도 걷어내고 `test` 필드를 평평하게 만들었다.
사용하지 않게 된 `storybookTest`/`playwright`/`fileURLToPath` import도 함께 정리했다.
재발 방지로 `test.exclude`에 `**/*.stories.@(js|jsx|mjs|ts|tsx)`를 명시적으로 추가했다
(기본 include 패턴에는 원래도 안 걸리지만, 문서화 목적).

### 주요 의사결정 / 핵심 메모
- 원인은 티켓이 예상한 "설정 누락"이 아니라 `@storybook/addon-vitest`의 업스트림 버그
  (파일 경로 URL 디코딩 미흡)였다. 이 프로젝트의 작업 폴더가 한글 경로를 쓰는 한(운영 규칙상
  고정) 이 애드온으로 스토리 렌더 테스트를 돌리는 것은 patch-package 없이는 원천적으로 불가능하다.
- "스토리 테스트를 제대로 켠다" 방향은 patch-package + 의존성 업그레이드마다 재패치라는
  유지보수 비용이 드는 반면, 지금까지 이 기능이 단 한 번도 정상 동작한 적이 없어 잃는 가치가
  없다고 판단해 "제외" 방향으로 확정했다. 사용자가 스토리 렌더 스모크 커버리지를 원한다면
  이 판단을 뒤집고 후속 티켓으로 patch-package 도입을 진행할 수 있다(아래 alerts 참고).

### 잔여 이슈
- 스토리 렌더 스모크 테스트 자체를 되살리고 싶다면 `patch-package`로
  `@storybook/addon-vitest`의 `convertToFilePath`를 `decodeURIComponent` 적용 버전으로 패치하는
  후속 티켓이 필요하다 (범위 밖으로 남겨둠).
