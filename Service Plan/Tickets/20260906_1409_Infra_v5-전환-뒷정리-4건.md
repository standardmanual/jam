# [Infra] v5 전환 뒷정리 4건 — 고아 아이템 · 백업 테이블 · 진단 라우트 · Storage

> 마스터: `20260905_0026`. 선행: `20260905_0039`(유저 초기화, CLOSED) · `20260906_1241`(리전, CLOSED)

## 배경 / 문제 정의

2026-09-06 v5 프로덕션 배포와 유저 서비스 데이터 초기화가 끝났다. 그 과정에서
**의도적으로 남겨둔 잔여물 4건**이 있다. 각각은 작지만 방치하면 다음 사람이
「이게 왜 여기 있지」를 매번 다시 조사하게 된다.

**공통 전제 — 프로덕션이 안정화된 뒤에 한다.** 특히 ②는 되돌릴 마지막 수단을 없애는 일이다.

## 상세 요구사항

### ① 고아 아이템 429개 폐기 — **사용자 작업 (어드민 UI)**

유저 초기화(`0039` 결정 ②-A)에서 `inventory`만 지워 아이템 429개를 **Orphaned로
전이**시켰다. `inventory_items`를 직접 지우면 `custody_events` 257건이 CASCADE로 함께
사라지기 때문이다(보관 이력은 append-only로 보존해야 한다).

- 화면: `/admin/item-badges/orphaned`
- 기능은 이미 있다 — `DestroyOrphanedAction`(**일괄 폐기**) ·
  `ReassignOrphanedAction`(일괄 재배정), 다중 선택 액션 바
- **페이지당 50개**(`PAGE_SIZE = 50`)라 429개면 **9쪽**이다. 쪽마다 전체 선택 → 일괄 폐기
- 폐기와 재배정 중 무엇을 할지는 판단 사항이다. 전원이 「최초 가입자」로 다시 시작하는
  것이 초기화의 취지이므로 **폐기가 기본**이지만, 특정 아이템을 살리고 싶으면 재배정한다

**이건 오케스트레이터가 대신 할 수 없다** — 어드민 화면은 구글 로그인이 필요하다.

### ② 백업 테이블 25개 삭제 — **DB 작업**

초기화 직전에 만든 `bak20260906_*` 25개. 되돌릴 유일한 수단이므로 **프로덕션이
충분히 안정화됐다고 판단될 때까지 지우지 않는다.**

**지우기 전에 확인할 것**: 초기화가 되돌릴 필요 없이 잘 굴러갔는가 —
유저가 실제로 동기화해서 v5 배지를 정상 획득하는 것을 최소 한 명 이상 확인한 뒤가 안전하다.

`DROP TABLE IF EXISTS ... CASCADE;` 25줄. SQL 파일로 남긴다.

### ③ 진단 라우트 `/api/diag-perf` 제거 — ✅ **완료 (2026-09-06)**

TTFB 원인 규명(`20260906_1241`)을 위해 만든 임시 계측기다. **목적을 달성했고
프로덕션에도 나가 있다.**

- 파일: `jam-web/src/app/api/diag-perf/route.ts`
- 로그인 게이트만 있고 노출되는 것은 시각 수치뿐이라 위험은 낮지만, **진단이 끝났으면
  남길 이유가 없다**
- 지우기 전에 **프로덕션의 「이전」 리전을 확정**하는 편이 좋다 —
  Vercel 대시보드 `jam` → Settings → Functions → Function Region이 `iad1`이면
  실사용자가 이번에 3~6배 개선을 얻은 것이고, `icn1`이면 staging만 느렸던 것이다.
  이 값은 티켓 `1241`의 잔여 이슈로 남아 있다
- ✅ **교훈 이관 완료** — `Specs/DEV_PROCESS_GUARDRAILS.md` **패턴 12**로 옮겼다.
  「`_` 접두사 폴더가 라우팅에서 조용히 제외되고, 404가 아니라 앱 HTML이 돌아와 배포
  문제로 오진하게 된다」와 재발 시 확인 순서를 적었다. 브라우저가 307을 캐시하는 함정도
  참고로 함께 남겼다
- ✅ **라우트 삭제 완료** — `jam-web/src/app/api/diag-perf/route.ts`. `tsc --noEmit` 0건

> ⚠️ **프로덕션의 「이전」 리전은 끝내 확정하지 못했다.** 확인 전에 계측 작업을 종료했다.
> 배포 후 `icn1`인 것은 `vercel.json`에 의해 확정적이지만, **고치기 전에 `iad1`이었는지는
> 모른다** — 즉 실사용자가 이번에 3~6배 개선을 얻었는지 단정할 수 없다.
> 확인하려면 Vercel `jam` → Settings → Functions → **Function Region**을 보면 된다.
> 계측 라우트를 지웠으므로 이제 그 값이 유일한 단서다.

### ④ Storage `images/badges/activity/` 175MB 정리 — **판단 먼저**

v4 액티비티 배지 207종의 이미지다. 정의는 소프트삭제됐지만(`20260905_0034`)
**이미지 파일은 그대로 남아 있다.**

⚠️ **소프트삭제라 되살릴 여지가 남아 있다는 점을 먼저 확인할 것.** 정의가 `deleted_at`으로만
지워졌으므로 복구 가능성이 있고, 이미지를 지우면 그 복구가 반쪽이 된다.
「v4를 되살릴 일이 없다」가 확정된 뒤에 지운다.

- 현재 남은 v5 이미지와 경로가 겹치지 않는지 확인 (같은 폴더면 선별 삭제가 필요하다)
- 175MB는 Vercel/Supabase 과금에서 큰 비중이 아니다 — **급하지 않다**
