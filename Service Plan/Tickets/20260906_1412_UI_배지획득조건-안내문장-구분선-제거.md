# [UI] 배지 획득 조건에서 안내 문장과 구분선을 뺀다 — 조건 표기만 남긴다

> 선행: `20260906_1305`(조건 표기 줄 신설). 그 티켓의 「티켓으로 만들지 않은 제안 1건」이
> 사용자 지시로 되살아났다 (2026-09-06)

## 배경 / 문제 정의

`20260906_1305`에서 획득 조건 카드를 두 줄로 나눴다. 그때는 **기존 안내 문장을 그대로 두라**는
사용자 결정에 따라 문장을 유지하고 아래에 표기 줄을 덧붙였는데, 실제 화면에서
**같은 조건이 두 번 나온다**는 것이 확인됐다.

```
획득 조건
매주 일요일에 활동 · 총 10회 이상 조건을 채우면 획득할 수 있어요.   ← 조건이 이미 여기 다 있다
─────────────────────────────────────────────
매주 일요일에 활동 · 총 10회 이상                                  ← 같은 말
```

개선 리뷰도 같은 지점을 지적했다 — 표기 줄이 사실을 다 담게 된 이상 문장 쪽의 조건 나열은
잉여이고, 「…총 10회 이상 **조건을** 채우면」처럼 「조건」이 연달아 나오는 어색함도 남는다.

**사용자 지시(2026-09-06): 조건 표기만 남기고 설명문과 가로줄을 제거한다.**

## 상세 요구사항

### UI/UX 관점

- `BadgeConditionCard`는 **조건 표기(`spec`)가 있으면 그것만** 그린다.
  안내 문장(`text`)도 구분선(`border-t`)도 그리지 않는다
- **`spec`이 없으면 지금처럼 `text` 한 줄을 그린다.** 표기할 조건이 없는 경우가 실제로 있다:
  | 호출부 | `spec` | 그리는 것 |
  |---|---|---|
  | 액티비티 배지 (`page.tsx:525`) | 있음 | 조건 표기만 |
  | 액티비티 배지 — 미션 보상·수동 발급·미지원 키 | `null` | 문장 (「'X' 미션을 완료하면…」 등) |
  | 체크인 배지 (`page.tsx:454`) | 안 넘김 | 문장 (`conditionCheckinBody`) |
  | 어드민 미리보기 (`BadgeDetailPreviewFrame`) | 안 넘김 | 문장 |
- 표기 줄만 남으면 **카드 안에 문장이 없으므로 굵기를 낮춘다.** 지금은 문장과 구분하려고
  볼드를 줬는데, 대비 대상이 사라지면 볼드가 근거를 잃는다. 본문 색 + 일반 굵기 +
  `tabular-nums`로 간다
- 말줄임(truncate) 금지는 그대로 — 조건이 잘리면 안 된다

### 서비스/코드베이스 관점

- `formatBadgeConditionText()`·`formatBadgeConditionSpec()`은 **건드리지 않는다.**
  둘 다 여전히 쓰인다(문장은 폴백 경로에서). 로직 변경 없이 카드의 렌더 분기만 바꾼다
- 어드민 미리보기가 `text`만 넘기는 현행 호출을 깨지 않는다

## 구현 계획

1. `BadgeConditionCard.tsx` — `spec ? <조건 표기> : <문장>` 분기로 바꾸고 구분선 제거
2. `npx tsc --noEmit` · `npx vitest run src/lib/__tests__/badgeConditionText.test.ts`
3. staging 배포 후 실화면 확인 — 액티비티 배지(표기만) / 미션 보상 배지(문장 폴백) 둘 다

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`BadgeConditionCard`의 렌더를 «두 줄 병기»에서 **`spec ? 표기 : 문장` 분기**로 바꿨다.
표기가 있으면 조건 표기 한 줄만 그리고, 안내 문장도 구분선(`border-t`)도 그리지 않는다.

- **볼드를 뺐다.** `20260906_1305`에서 준 `font-bold`는 «문장과 구분하기 위한» 것이었는데,
  대비할 문장이 사라졌으므로 근거를 잃는다. 본문 색 + 일반 굵기 + `tabular-nums`로 간다
- `formatBadgeConditionText()`·`formatBadgeConditionSpec()`은 **한 글자도 고치지 않았다.**
  문장은 폴백 경로에서 여전히 쓰인다 — 로직이 아니라 카드의 렌더 분기만 바뀌었다
- 폴백이 실제로 도는 경로 4가지를 주석에 명시했다: 미션 보상 · 어드민 수동 발급 ·
  레지스트리가 모르는 키 · 체크인 배지(`conditionCheckinBody`) · 어드민 미리보기

  때문이다. 「문장을 없앤다」가 「문장 생성기를 없앤다」가 아니다.
