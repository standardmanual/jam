# [UI] 미션 목록 — 같은 보상 배지를 여는 게이트 미션 중복 표시 제거

## 배경 / 문제 정의

`20260906_2231`이 시딩한 게이트 미션 53건(축 기준) 중 다수는 **같은 보상 배지를 서로
다른 두 개 이상의 축에서 열 수 있게** 설계됐다 — 예: `주말의 증명`(자전거 `cycling:Q5`
배지)은 `cycling:요일` 축과 `cycling:주기` 축 어느 쪽에서 Epic을 채워도 열리도록 두 개의
`missions` 행(같은 `reward_badge_ids`, 다른 `gate_axis`/`visibility_rule_json`)으로
시딩됐다. 사용자 실측(스크린샷, 2026-09-07):

> "동일한 게이트 미션이 여러 개 있어" — `주말의 증명`·`이어진 바퀴의 증명`이 목록에
> 각각 두 번씩 나타난다.

또한 "참가할 수 없는 모든 게이트 미션이 다 표시돼서 혼란스럽다"는 지적도 있었으나,
**종목 필터가 이미 있어 종목별로 여러 게이트 미션이 남는 것 자체는 유지한다**
(2026-09-07 사용자 확정 — "한 종목만 쓰는 경향이 있어 종목별로 존재해야 함"). **이번
티켓의 범위는 "같은 보상 배지 중복 행을 1개로 합치는 것"만이다.**

## 상세 요구사항

### 서비스/코드베이스 관점

- `jam-web/src/app/(main)/missions/page.tsx`의 `visibleOngoing` 계산(`:67-70`) 이후,
  **`toItem()` 적용 전에** 중복 제거 단계를 추가한다.
- 그룹핑 키: `reward_badge_ids[0]` — **`reward_badge_ids.length === 1`인 미션에만
  적용한다**(다중 보상 미션까지 잘못 묶이지 않도록 안전장치).
- 그룹 안에서 대표 행 선택 우선순위(위에서부터):
  1. **참가중**(`participationSet.has(m.id)`)인 행 — 유저가 이미 특정 축으로 참가했다면
     그 행이 사라지면 안 된다("참가했는데 안 보임" 회귀 방지)
  2. **열림**(visibility `open`)인 행 — 유저가 참가 가능한 상태를 우선 노출
  3. 그 외(전부 `locked`)면 **결정적으로 하나만** 선택 — 매 새로고침마다 다른 축이
     뽑히면 안 되므로 `gate_axis` 알파벳 순 등 고정 기준으로 정렬 후 첫 번째를 쓴다
  4. 위 우선순위가 동률이면(예: 열린 행이 2개) 마찬가지로 `gate_axis` 알파벳 순으로
     타이브레이크
- 같은 보상을 두 축에서 동시에 만족하는 극단적 케이스(유저가 두 축 모두 Epic 보유)는
  둘 다 `open`일 수 있다 — 이 경우도 위 규칙(3번 기준 타이브레이크)으로 하나만 보여준다.
  실제로 참가·완료하면 어느 쪽 행이든 같은 물리적 보상 배지가 지급되므로 기능적으로
  문제 없다.
- `requiredBadge`(잠금 힌트, `MissionListItem.requiredBadge`)는 **선택된 대표 행의 값을
  그대로 쓴다** — "두 축 중 하나"라는 안내 문구를 새로 만들지 않는다(범위 밖, 아래 참고).
- **'완료/지난' 탭(`ended`)은 이번 범위가 아니다** — 이미 종료·완료된 이력은 중복이어도
  기록으로서 의미가 있으므로 건드리지 않는다.

### 하지 않는 것
- 종목별로 여러 개(축마다 하나씩) 남는 게이트 미션을 더 줄이는 것 — 사용자가 이미
  "종목별로 존재해야 한다"고 확정함
- 잠금 힌트 문구를 "두 축 중 하나"처럼 재작성하는 것 — 대표 행의 기존 문구를 그대로 씀
- `ended` 탭의 중복 제거
- 미션 상세 페이지(`/missions/[id]`) — 목록 화면만
