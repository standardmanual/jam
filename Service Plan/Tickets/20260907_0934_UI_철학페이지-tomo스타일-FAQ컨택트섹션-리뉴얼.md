# [UI] 철학 페이지 — tomo.ai/about 스타일 Philosophy/FAQ/Contact 3섹션 리뉴얼

## 배경 / 문제 정의

`/philosophy`는 현재 Footer의 'Philosophy' 링크로만 진입하는 단일 에세이 페이지다
(`jam-web/src/app/(main)/philosophy/page.tsx`, 티켓 20260901_2125·20260902_1347).
사용자가 참고 사이트로 제시한 https://www.tomo.ai/about 는 About(소개) → FAQ(아코디언
Q&A) → Contact(문의) 3섹션 구성이다. 이 구성을 차용해 `/philosophy`를 확장한다.

`/layers-orient` 세션에서 다음을 확인·결정했다:
- FAQ 후보 주제(배지 획득·운영정책·어뷰징)를 실제 VOC 문의 로그와 대조하지 않고
  직관적 판단으로 진행하기로 사용자가 확정
- FAQ 개수는 tomo(10개)에 맞추지 않아도 됨
- UI는 tomo 사이트 구성을 따르되, MODULAR 컴포넌트를 사용
- 아코디언의 토글 버튼은 tomo의 디자인(원형 회전 버튼)을 참고해 MODULAR에 반영
- About 섹션의 제목은 "About"이 아니라 "Philosophy"로 유지하고, 기존 철학 페이지
  원고(임의 수정·윤문 금지 확정 원고, 티켓 20260902_1347)를 그대로 삽입

## 상세 요구사항

- `jam-web/src/app/(main)/philosophy/page.tsx`를 3섹션(Philosophy/FAQ/Contact) 구조로 확장

  개인정보 보호책임자 연락처와 동일 주소)

### UI/UX 관점

**1.5 탐색·재사용 판정 (오케스트레이터 확정)**
- `_ds_manifest.json` 탐색 결과 `Accordion`(DS-021, `components/navigation/Accordion.jsx`)이
  이미 MODULAR에 존재 — 신규 컴포넌트를 만들지 않고 **재사용**한다.
- 단, 현재 구현은 평문 셰브런 토글이며 tomo.ai 실측 결과 토글이 **원형 배지 버튼**(배경색
  pill, 안에 아이콘, `isOpen` 시 180도 회전 트랜지션) 패턴이다. 이 버튼 디자인을 JAM 토큰
  (`--color-primary` 등, `--duration-fast`/`--ease-smooth-out` 모션 토큰 그대로 재사용)으로
  옮겨 **Accordion 컴포넌트 자체를 업데이트**한다 — 서비스 페이지 전용 커스텀 래퍼로
  우회하지 않는다.
- tomo의 아이콘(도트 패턴 화살표, 브랜드 고유 마스코트 성격)은 그대로 복제하지 않는다.
  "원형 배경 + 회전 아이콘"이라는 인터랙션 패턴만 차용하고, 아이콘 자체는 JAM 아이콘
  세트에서 가져온 단순 셰브런/플러스 형태로 재해석한다.
- 컴포넌트를 변경하므로 `Accordion.stories.tsx`도 함께 갱신한다 (`jam-web/CLAUDE.md` 규칙).

**1.6 모듈러-서비스 연결 범위 표기**
- `Accordion`은 현재 "미도입 8종"(스토리북 전용, 서비스 대응 개념 없음, 티켓
  20260820_010에서 유지/보류로 확정)에 속한다. 이번 티켓이 **Accordion을 서비스에
  처음 도입하는 시점**이다 — `/philosophy` FAQ 섹션이 유일한 호출부가 된다.
- 이번 변경은 "미도입 → 신규 도입" 케이스이며, 병존 구현(서비스에 동명 구현이 따로 있는
  경우)에 해당하지 않으므로 이중 반영 이슈는 없다.
- 완료 기록에 위 분류(신규 도입)와 호출부(philosophy 페이지 1곳)를 명시할 것.

**FAQ 콘텐츠 — 발굴한 후보** (원고 확정은 UX_WRITING_GUIDELINE.md 톤 준수, 배지 관련은
Philosophy 원고와 톤 일치시키는 방향으로 검토)

출처: `Service Plan/Specs/SERVICE_OPERATIONS.md` §3(Strava)·§4(뱃지 발급)·§5(드랍)·
§6(POI)·§12(어뷰징), `Service Plan/Specs/PRIVACY_POLICY.md`(탈퇴 관련은 중복 대신 링크 고려)

배지 획득:
- 배지는 어떻게 얻나요? (기록형/레벨형/반복형 차이)
- 운동을 마쳤는데 왜 배지가 바로 안 나오나요? (동기화 텀)
- 직접 기록을 입력해도 인정되나요? (워치·앱 자동 측정만 인정)
- 배지 등급(Common/Rare/Epic/Mystic)은 어떻게 다른가요?
- 이미 얻은 배지를 또 얻을 수 있나요? (반복 획득형)
- 아이템은 어떻게 드랍되나요?
- 장소(POI)에서 배지를 얻으려면 어떻게 하나요?

운영정책:
- 계정을 탈퇴하면 데이터는 어떻게 되나요? (개인정보처리방침 링크 고려)
- 스트라바 연동을 해제하면 어떻게 되나요?
- 자동차·오토바이로 이동해도 기록되나요? (차량 속도 필터 — 원칙만 서술)

어뷰징:
- GPS 조작이나 부정 기록을 하면 어떻게 되나요?
- 갑자기 배지·아이템을 못 받는 것 같은데 왜 그런가요? (섀도우밴을 직접 명명하지 않고
  Philosophy 원고 톤 유지 — "의심스러우면 조용히 보상만 비워둔다")
- 오해로 제한된 것 같으면 어떻게 하나요? (Contact로 연결)

⚠️ **필수 가드레일**: 답변 원고에 `vehicle_speed_filter_kmh`(60km/h)·
`gps_max_speed_kmh`(300km/h)·`gps_daily_distance_cap_km`(3000km/일)·`poi_block_hours`
(72시간) 등 **구체적 임계값 수치를 노출하지 않는다.** 수치 공개는 어뷰저에게 우회
가이드를 주는 것과 같다. Philosophy 원고처럼 원칙만 서술한다.

  기존 "미도입 8종"(티켓 20260820_010 유지/보류)에서 벗어난 최초 사례.

- `Accordion` 인터랙티브 특성(useState)과 `page.tsx`의 서버 컴포넌트 설계를 함께 지키기
  위해 얇은 클라이언트 경계 `FaqAccordion.tsx` 신설.
- **게이트 리뷰 PASS 후 인터랙션 리뷰 제안 2건을 추가 반영**: Accordion의 트랜지션을
  인라인 style → CSS 클래스(`STATIC_CSS` + `<style>` 주입, `BadgeFamilyCardHeader.jsx`와
  동일 패턴)로 이동해 `prefers-reduced-motion` 킬스위치를 추가했고, 헤더 버튼에
  `:active{opacity:.7}`를 더해 탭 다운 즉시 피드백이 오도록 했다.

### 주요 의사결정 / 핵심 메모
- `/layers-orient` 세션에서 VOC 로그 대조를 생략하고 직관적 판단으로 FAQ 주제를 확정하기로
  결정(사용자 확인). FAQ 개수는 tomo(10개)에 맞추지 않고 12개로 구성.
- Accordion 토글 아이콘은 tomo의 실제 아이콘(도트 패턴 화살표, 브랜드 자산)을 복제하지
  않고 "원형 배경 + 회전"이라는 인터랙션 패턴만 차용하기로 결정 — 저작권/브랜드 혼동 방지.
- 어뷰징 FAQ 답변에서 구체적 임계값 수치(60km/h·300km/h·3000km/일·72시간)를 의도적으로
  배제 — 수치 공개가 어뷰저에게 우회 가이드가 될 위험 때문. Philosophy 원고와 같은
  원칙 서술 톤을 유지.
- 게이트 리뷰 PASS 후 인터랙션 리뷰(제안형)에서 reduced-motion 미대응·active 피드백 부재를
  지적받아 사용자 승인 하에 추가 반영. 인라인 style이 스타일시트를 항상 이겨
  `prefers-reduced-motion`이 먹지 않는다는 점은 `globals.css` 기존 실측 기록과 동일한
  함정이었다 — 향후 새 MODULAR 컴포넌트 작성 시 처음부터 `STATIC_CSS` + `<style>` 패턴을
  기본으로 채택할 것을 권장.
- MODULAR 승격 후보 없음(Contact 카드는 호출부 1곳뿐이라 현재는 페이지 전용 구현 유지).
