# [Infra] POI 카테고리 체계 재정리 + 기존 POI 재분류

## 배경 / 문제 정의
현재 `poi_categories`는 14개 카테고리로 구성되고 키워드는 `text[]`로, 카테고리 하나에 지역
범위(구+동 고정)가 일괄 적용된다. 이 구조로는 다음이 표현되지 않는다:

- **키워드마다 필요한 지역 단위가 다름** — 관공서 카테고리의 주민센터는 동 단위, 구청은 구
  단위, 시청은 시/도 단위로 검색해야 결과가 나오는데 지금은 전부 "구+동"으로 고정
- **"자동수집은 하되 지도에는 안 보이게"가 불가능** — `poi_categories`에 그런 플래그가 없고,
  수집 INSERT 로직([drops/route.ts:66-74](../../jam-web/src/lib/poi/naver.ts))에도 반영할 지점이 없음

실측(2026-09-07)으로 확인된 사실:
- 산(mountain) 자동수집은 32그리드 검색해 **0건** — 현재 산 847건은 전부 수동 등록(T1)이었고
  자동수집 파이프라인은 애초에 산출물이 없었다
- 기차/지하철(train_subway) 967건 중 자동수집 산출은 40건뿐 — 927건은 수동 등록
- 대중교통(transit, 버스정류장)은 그리드당 수확 0.09로 낮고, 지도 비노출 결정과 겹쳐 자동수집
  중단 + 기존 16건 삭제로 확정
- 관광명소(tourist_attraction) 기존 97건 중 새 키워드(박물관/미술관/전망대) 기준에 맞는 건 3건뿐,
  35건은 공원류, 59건은 판정 불가 — 카테고리 전환 시 재분류 필요성의 근거

이 논의의 전체 맥락(카테고리별 실측 수확률, 최종 확정 표 도출 과정)은 이 티켓을 만든 대화
세션에 있다 — 아래 "확정 카테고리 표"가 그 결론이다.

## 상세 요구사항

### 서비스/코드베이스 관점

**스키마 변경**
- `poi_categories.keywords`를 `text[]` → `jsonb`로 전환. 각 원소는
  `{"keyword": string, "scope": "dong" | "gu" | "sido"}` 형태
- `poi_categories.display_on_map`(boolean, default true) 컬럼 추가 — false면 자동수집은 계속하되
  지도에는 노출하지 않음
- `jam-web/src/lib/poi/reverse-geocode.ts`가 현재 `area2+area3`(구+동)만 합쳐 문자열 하나로
  반환([reverse-geocode.ts:86-88](../../jam-web/src/lib/poi/reverse-geocode.ts)) — `area1`(시/도)까지
  포함해 `{ sido, gu, dong }` 형태로 분리 반환하도록 변경. 호출부(`naver.ts`,
  `fetchNearbyNaverPoisForCategories`)가 키워드별 `scope`에 맞는 지역 단위를 조합하도록 수정
- `jam-web/src/lib/poi/categories.ts`의 `loadPipelineCategories` — jsonb 키워드 구조에 맞게
  파싱 로직 수정. **tier 컬럼은 스키마에서 제거하지 않고, 전체 `pipeline_linked=true` 카테고리를
  `tier=1`로 통일**해 티어 분기를 무력화한다(코드 로직은 `tier=1|2` 필터를 그대로 두되 데이터로만
  해소 — 42~50행이 `tier===1||tier===2` 필터라 이 변경으로 충분함)
- `jam-web/src/app/api/drops/route.ts`의 POI INSERT 페이로드([66-74행](../../jam-web/src/app/api/drops/route.ts))에
  `is_active: category.display_on_map` 반영 — 지금은 이 필드가 아예 없어 전부 활성으로 들어감
- `jam-web/src/lib/poi/radius-policy.ts` — stadium·school·park 반경 정책 등록 검토(현재 미등록
  카테고리는 기본 500m 적용, 배지 연동 전이면 당장 무해하나 향후 배지 연동 시 재검토 필요)

**카테고리 구조 변경**
- 신규: `stadium`(경기장), `school`(학교), `unassigned`(미정)
- 삭제: `transit`(대중교통/버스정류장) — 카테고리 자체와 기존 POI 16건 전부 삭제
- 삭제: `other`(기타) — 기존 3건은 `unassigned`로 이관 후 카테고리 삭제
- 통합: `bike_route`·`trail` → `route`(자전거길/트레일)로 통합 (기존 POI 0건이라 무손실)
- `mountain`·`train_subway`: `pipeline_linked=false`로 전환(자동수집 중단). 기존 POI는 활성
  유지, **재분류 대상에서 제외**(아래 재분류 작업은 이 두 카테고리를 건드리지 않음)

**확정 카테고리 표**

> 관공서는 "구청/군청/시청 3개를 매 그리드마다 다 검색하면 2개는 항상 헛돈다"는 문제가 있음 —
> 역지오코딩 `area2` 접미사로 분기(`~구`→구청만, `~군`→군청만, `~시`→시청만) 시 그리드당 2콜
> 절약 가능. 구현 여유가 되면 함께 처리, 아니면 후속 최적화로 미룸

**재분류 대상 (599건)**
- 산·기차/지하철 제외한 기존 자동수집 POI 전체 (2026-09-07 기준 599건)
- 원본 검색 키워드가 DB에 저장돼 있지 않아 이름만으로는 판정 불가 — 이름+좌표로 네이버
  지역검색 API에 재조회해 원본 분류 문자열을 받아 새 카테고리 표에 매핑
  ([20260907_1242 티켓](20260907_1242_Infra_POI-네이버원본분류검증게이트및-어드민검토큐.md)의
  `naver_category` 저장 기능을 전제로 함 — 그 티켓을 먼저 완료)
- 애매한 것은 전부 `unassigned`로 배정
- 599콜은 네이버 일일 한도(25,000) 대비 여유 있음

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- park을 비노출로 결정 — 사용자가 명시적으로 선택. 기존 관광명소 소속 공원류 35건이 함께
  비노출 전환되므로 도심 노출 POI가 크게 줄어드는 점은 인지된 트레이드오프
- 관광명소 키워드를 "관광명소"(포괄어)에서 "박물관/미술관/전망대"(구체 유형)로 좁힌 것도
  사용자 확정 — 기존 97건 중 3건만 부합하는 실측 결과를 알린 뒤에도 유지 결정
- nature·stadium·school 자동수집 지속 여부 — 이 시설들이 도심 500m 반경 안에 있을 가능성이
  낮아 자동수집 구조상 한계가 있다는 의견을 제시했으나, 사용자가 자동수집 유지로 확정.
  대신 오염 방지를 위해 [20260907_1242 티켓](20260907_1242_Infra_POI-네이버원본분류검증게이트및-어드민검토큐.md)의
  검증 게이트 도입이 세트로 결정됨
- tier 컬럼 자체를 스키마에서 제거하는 대신 전체 tier=1 통일로 처리 — 코드 변경 없이 티어
  분기를 무력화할 수 있어 채택. 컬럼 완전 제거는 후속 정리로 미룸
