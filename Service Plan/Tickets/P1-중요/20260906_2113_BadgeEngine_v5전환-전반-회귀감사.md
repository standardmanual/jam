# [BadgeEngine] v5 전환 전반 회귀 감사

> 계기: 사용자가 "체크인 배지가 액티비티 배지에 리스팅된다"고 보고 → 조사 결과 v5와
> 무관한 기존(v4) 결함으로 확인됨(`20260906_2023`). 다만 이를 계기로 "v5 이전에 문제가
> 없던 것들에 v5가 회귀를 만들지 않았는지" 전반 점검을 요청받았다.

## 배경 / 문제 정의

v5 전환(2026-09-05~06)은 다음을 포함하는 큰 변경이었다:
- 카탈로그 재시딩 (630→현재 837종, 티켓 `20260905_0035`)
- 유저 서비스 데이터 전체 초기화 (티켓 `20260905_0039`)
- 조건 레지스트리·엔진 확장 (티켓 `20260905_0028`~`0033`, `20260906_0110`)
- 배지 트리 리뉴얼 (티켓 `20260905_0037`)
- 리전 이전 등 인프라 변경 (티켓 `20260906_1241`)

이 정도 규모의 변경 이후 "v5 이전엔 멀쩡했던 기능"에 회귀가 없는지 코드 조사·테스트
스위트·DB 실측으로 점검한다. **코드 변경 없음 — 조사·기록 전용(research 유형).**

## 조사 범위
- 미션 보상 지급(`missions/rewards.ts`)이 활동/아이템 이분법만 가정 — v5 카탈로그의
  체크인·컬렉션 보상 배지가 미션 보상으로 잘못 설정된 경우 있는지
- 아이템북 완성 보상(`itembook/checker.ts`)이 보상 배지를 항상 activity로 가정
- 합성(`combine/index.ts`) 출력이 타입 무관 가정하는지
- 활동 피드/알림 배치(`activity-feed/hydrate.ts`, `notifications/batch/*`)가 v5 신규
  조건 필드·회차 계산과 정합하는지
- 포인트·팩션·랭킹 등 배지 개수/희귀도 분포에 의존하는 로직이 630→837종 변화로 깨지는지
- 전체 테스트 스위트 실행 결과
- 기존 티켓들의 "잔여 이슈" 절에 이미 기록된 v5발 회귀 후보 취합

## 완료 기록 *(작업 완료 후 작성)*

### 조사 결과 요약

**결론: v5가 새로 만든 활성 회귀는 발견되지 않았다.** (계기가 된 체크인 배지 건도
`20260906_2023`로 별도 확인했듯 v4 시절 결함이었다.) 전체 vitest 스위트(61 files/1103
tests) 전부 통과. 조사 항목별 결론:

1. **미션 보상 지급**(`missions/rewards.ts`) — `activity`/`item` 이분법 하드코딩. DB 실측
   `reward_badge_ids`가 가리키는 배지 중 그 외 타입 **0건**이라 지금은 안전하지만, 콘텐츠
   담당이 checkin 배지를 미션 보상으로 잘못 설정하면 재현되는 **구조적 결함**이 남아 있다.
2. **아이템북 완성 보상**(`itembook/checker.ts`) — `item_books.reward_badge_id` 설정 **0건**
   이라 현재 무해. 같은 유형의 구조적 결함(무조건 `user_activity_badges`에 씀) 잠재.
3. **합성(combine)** — `combination_recipes` 테이블 자체가 **0행**이라 검증 데이터 없음.
   레시피가 생기면 결과 배지 타입을 확인해야 함.
4. **`user_activity_badges` "통합 소유권 테이블" 주석**(`strava/sync.ts:177-180`) — 같은
   파일 160행 서술과 모순되는 **낡은 주석**. 실제 코드는 checkin을 별도 테이블로 정확히
   분리해서 쓰고 있어 기능적 오염은 없음. 주석만 정정 필요.
5. **하드코딩된 개수 상수**(207/630/837 등) — 전부 주석용, 로직 분기에 쓰인 곳 없음. 이상 없음.
6. **`familyKeyOf` 계열 그룹핑** — 전 호출부가 `badgeKind.ts`의 단일 함수를 통해 그룹핑.
   구식 우회 구현 없음. 이상 없음.
7. **기존 티켓 잔여 이슈 취합** — 대부분 이미 별도 티켓으로 분리 완료. 유일하게 미분리:
   `20260905_0039`의 "유저 초기화로 `users.created_at`이 전원 동일 시각이 돼 어드민
   유저 목록 가입순 정렬이 무의미해짐" — 서비스 화면(팔로우·컬렉션)은 영향 없고
   `admin/users/page.tsx` 정렬 1곳만 경미하게 영향받음.
