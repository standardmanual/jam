# [Admin] 유저 관리 강제 완전 삭제 기능

## 배경 / 문제 정의
지금까지 특정 유저를 완전히 삭제해야 할 때(예: `jadeny23.jy@gmail.com` 삭제 사례) 오케스트레이터가
Supabase MCP로 SQL을 직접 실행했다. 반복적으로 필요한 작업인데 어드민 화면에 기능이 없어 매번
수동 SQL 조회·삭제를 거쳐야 한다.

기존 `/admin/users` 화면에는 [UsersTable.tsx](../../../jam-web/src/app/admin/users/UsersTable.tsx)의
`ResetUserButton`(유저 콘텐츠만 초기화, 계정은 유지)이 있지만, **계정 자체를 완전히 삭제**하는
기능은 없다. `UsersTable.tsx` 주석의 "일괄 삭제/정지는 정책상 민감해 범위 밖"이라는 언급은
DataTable 전환 티켓(20260826_015)의 스코프 언급일 뿐, 개별 유저 완전 삭제 자체를 금지한 결정은
아니다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `/admin/users` 목록의 액션 컬럼에 "완전 삭제" 버튼 추가 (기존 `ResetUserButton`과 나란히,
  시각적으로 명확히 구분되는 더 강한 위험 표시 — 예: 더 진한 빨강·아이콘)
- 신규 API 라우트 `DELETE /api/admin/users/[id]` (또는 `POST /api/admin/users/[id]/delete`,
  `getAdminUser()` 가드는 기존 라우트들과 동일 패턴 사용)
  - `public.users` 삭제 → FK `ON DELETE CASCADE`로 관련 데이터(strava_connections,
    user_activity_badges, inventory, inventory_items, trades 등) 자동 정리
  - **`auth.users`도 함께 삭제** (Supabase Admin API `supabase.auth.admin.deleteUser(userId)`
    사용 — `execute_sql`로 직접 `DELETE FROM auth.users`한 것과 동일 효과를 서비스 코드 안에서
    안전하게 재현. `createServiceClient()`가 service_role 키를 쓰므로 Admin API 호출 가능한지
    확인할 것)
  - 삭제 대상 유저가 없으면 404, 성공 시 삭제된 이메일/주요 카운트를 응답에 포함(로그용)
  - `console.info`로 관리자 이메일과 대상 유저 정보 감사 로그 남기기 (기존 reset 라우트 패턴과 동일)
- 어드민 본인 계정 삭제 방지 로직은 불필요(유저 삭제는 항상 "다른 유저" 대상 — 필요 시
  `getAdminUser()`로 조회한 admin.id와 대상 id가 같으면 400으로 막는 방어 코드 정도는 추가해도 됨)

### UI/UX 관점 (필수)
- 삭제 버튼 클릭 시 확인 다이얼로그(기존 `ResetUserButton`의 모달 패턴 재사용) 표시
- 다이얼로그 문구는 "초기화"보다 훨씬 강하게: 이 작업이 계정 자체와 모든 데이터를
  **영구적으로, 되돌릴 수 없이** 삭제한다는 점을 명시
- **"삭제합니다"라는 텍스트를 정확히 입력해야만 삭제 버튼이 활성화**되는 텍스트 확인 입력란 추가
  - 입력값이 정확히 "삭제합니다"와 일치하지 않으면 삭제 버튼은 disabled 상태 유지
  - 입력란 위/아래에 "삭제하려면 아래에 '삭제합니다'를 입력하세요"라는 안내 문구를 명확히 표시
  - 대상 유저를 식별할 수 있도록 이름/이메일을 다이얼로그 본문에 노출
- 삭제 완료 후에는 결과 메시지를 보여주고 목록에서 사라지도록 `router.refresh()` 호출
  (기존 `ResetUserButton` 패턴 참고)

## 구현 계획
- `jam-web/src/app/admin/users/DeleteUserButton.tsx` 신규 생성 (ResetUserButton.tsx 구조 참고,
  텍스트 확인 입력 로직 추가)
- `jam-web/src/app/api/admin/users/[id]/route.ts`에 `DELETE` 핸들러 추가 (기존 파일에 이미
  `GET`/다른 메서드가 있는지 확인 후 병합 또는 신규 라우트 분리 — jam-developer가 기존
  `route.ts` 구조를 먼저 확인하고 판단)
- `UsersTable.tsx`의 액션 컬럼에 `DeleteUserButton` 추가
- Supabase Admin API(`auth.admin.deleteUser`)가 `createServiceClient()`로 정상 동작하는지
  로컬에서 실측 확인 (DEV_PROCESS_GUARDRAILS.md 패턴 13 — `ADMIN_EMAILS` 로컬 환경변수로 검증)
