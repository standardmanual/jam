# [UI] 배지 공유 캐러셀 미리보기 확대 비율 버그 (프로덕션 핫픽스)

## 배경 / 문제 정의
티켓 `20260911_1102`(배지 공유 시트 이미지 선택 캐러셀 추가)가 프로덕션에 배포된 직후,
사용자가 실기기에서 확인한 결과 두 캐러셀 항목의 미리보기가 모두 잘려 보이는 문제를
발견했다.

`BadgeShareButton.tsx`의 캐러셀 `renderItem`이 두 항목(카드 1080×1920, 배지 이미지
300×300 정사각형) 모두에 동일하게 `transform: scale(1.3)`을 적용하고 있었다. 이 130%
확대는 원래 **카드**(위아래 여백이 넓은 세로 스토리 템플릿)만을 위한 것이었는데
(2026-08-21 결정), 이번 캐러셀 추가 작업에서 배지 이미지 항목에도 그대로 재사용됐다.

- 카드: 130% 확대로 인해 배지 이미지·통계(거리/페이스/시간)·로고까지 프레임 밖으로
  밀려나 거의 안 보이는 상태였다.
- 배지 이미지(300px, 여백 없이 꽉 찬 정사각형): 130% 확대가 그대로 잘려 보였다.

## 상세 요구사항
### 서비스/코드베이스 관점
- 캐러셀 `renderItem`의 확대 배율을 항목별로 분리한다.
  - 카드(`kind === 'card'`): 기존 130%(`scale(1.3)`) 유지.
  - 배지 이미지(`kind === 'badge'`): 축소해서 잘리지 않게 한다(`scale(0.5)`).

## 구현 계획
1. `BadgeShareButton.tsx`의 `renderItem` 내 `<img>` style을 `kind`에 따라 분기.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `BadgeShareButton.tsx`의 캐러셀 `renderItem`에서 미리보기 `<img>`의 `transform`을
  `kind === 'card' ? 'scale(1.3)' : 'scale(0.5)'`로 분기했다. 실제 저장/공유되는 파일은
  두 항목 모두 원본 그대로이며, 이 스케일은 미리보기 화면에만 영향을 준다.

### 주요 의사결정 / 핵심 메모
- **원인**: 카드(여백 많은 세로 이미지)에만 필요했던 130% 확대가, 이번 캐러셀 추가로
  배지 이미지 항목에도 동일하게 재사용되면서 발생한 회귀. 두 항목의 이미지 종횡비·여백이
  근본적으로 다르므로 앞으로 캐러셀에 세 번째 항목이 추가되면 그 항목의 여백 특성에 맞는
  배율을 별도로 정해야 한다.
- 카드가 "안 보인다"고 보고된 첫 스크린샷은 실제로는 확대 문제가 아니라
  `strava_fetch_failed`(스트라바 API 조회 실패, 502) 에러 상태였다 — 이는 코드 버그가
  아니라 외부 API/데이터 문제로 별도 조사가 필요하다(이 티켓 범위 밖).

### 잔여 이슈
- 카드 생성 시 `strava_fetch_failed` 에러가 발생하는 근본 원인(스트라바 API 응답 실패)은
  이 티켓에서 다루지 않았다. 재현되면 별도 티켓으로 조사 필요.
