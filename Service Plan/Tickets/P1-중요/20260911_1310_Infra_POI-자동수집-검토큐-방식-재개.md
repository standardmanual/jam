# [Infra] POI 자동수집을 검토 큐 방식으로 재개

## 배경 / 문제 정의
2026-09-07 하루 안에 POI 자동수집 정책이 두 번 바뀌었다.

- **오전** (`20260907_1242`): 네이버 원본 분류 검증 게이트 + 어드민 검토 큐 신설. 자동수집은
  계속하되, 결과를 곧바로 노출(`is_active=true`)하지 않고 `pending_review`로 쌓아 관리자가
  검토·승인한 뒤 노출하는 구조로 구현됐다 (`jam-web/src/app/api/drops/route.ts`의
  `searchAndPersistCategories`, 119~140행).
- **저녁** (`20260907_1811`, CLOSED 2026-09-08): 네이버 지역검색 API의 구조적 한계(좌표/반경
  검색 미지원, 매치율 0~15%, 포괄 키워드로 인한 명칭 오염)를 이유로 자동수집 자체를 전면
  중단하기로 결정. `poi_categories.pipeline_linked`를 연동된 전체 카테고리(15개)에서
  `false`로 전환해 프로덕션에 반영했다. 이 플래그는 `jam-web/src/lib/poi/categories.ts`의
  `loadPipelineCategories`가 카테고리 로딩 단계에서 참조하므로, `false`가 되면 오전에 만든
  검증 게이트/검토 큐 로직(119~140행)까지 도달하지도 못하고 자동수집 자체가 실행되지 않는다.

오늘(2026-09-11) 사용자가 "새 POI가 검토 큐에 쌓이지 않는다"고 문제를 제기했다. 조사 결과
버그가 아니라 저녁 티켓의 정책 전환이 원인이었다(Supabase 실측: `poi_categories` 15개 전부
`pipeline_linked=false`, `poi` 테이블에 `pending_review=true AND is_active=false`인 행 0건,
`created_at` 최댓값이 2026-09-08 이후로 갱신되지 않음).

사용자는 오전 정책(자동수집 지속 + 검토 큐 대기)으로 되돌리기를 원한다. 저녁 티켓이 지적한
네이버 API의 반경검색 미지원·키워드 오염 문제는 이번 범위에서 해결하지 않으며, 같은 품질
이슈가 재발할 수 있음을 인지한 상태로 정책만 복귀한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `poi_categories.pipeline_linked`를 2026-09-08 이전 값(연동 대상 카테고리 전체)으로 복원한다.
  `jam-web/supabase/seed_20260907_poi_pipeline_linked_off.sql`을 참고해 어떤 카테고리가
  `true`였는지 확인하고, 복원용 SQL 파일(`jam-web/supabase/seed_YYYYMMDD_poi_pipeline_linked_on.sql`
  또는 `migrations/0XX_...sql`)을 신규 작성한다 — 기존 파일을 덮어쓰지 않는다.
- `jam-web/src/app/api/drops/route.ts`의 `searchAndPersistCategories`(119~140행)와
  `jam-web/src/lib/poi/categories.ts`의 `loadPipelineCategories`는 삭제되지 않고 그대로
  남아 있음이 조사로 확인됐다. **코드 변경은 원칙적으로 불필요**하지만, 구현 담당자는 실제로
  플래그를 켰을 때 이 경로가 의도대로(검증 게이트 통과 → `pending_review=true`,
  `is_active=false`로 저장) 동작하는지 코드를 다시 읽고 확인한다. 09-07 오전 이후 관련 코드가
  손대진 것이 없는지 `git log`로 재확인할 것.
- `/admin/poi/new` 수동등록 경로(항상 `is_active=false, pending_review=true`로 저장)는
  이번 변경과 무관하게 그대로 유지한다 — 자동수집과 수동등록 두 경로가 공존해도 되는지 확인.

### 컨텐츠 관점
- `Service Plan/Specs/Content/POI.md`의 "신규 등록 정책" 절이 현재 "자동수집 전면 중단,
  수동등록만" 기준으로 작성돼 있다. 이번 정책 복귀에 맞춰 "자동수집 재개 + 검토 큐 대기"로
  갱신한다.

## 구현 계획
1. `jam-web/supabase/seed_20260907_poi_pipeline_linked_off.sql`을 읽고 09-07 저녁 이전에
   `pipeline_linked=true`였던 카테고리 목록을 정확히 복원한다 (전체를 무조건 true로 켜지
   않는다 — 애초에 연동 대상이 아니었던 카테고리가 있을 수 있음).
2. 복원 SQL 파일을 `jam-web/supabase/` 아래 신규 파일로 작성한다 (실행은 사용자 승인 후
   오케스트레이터가 5단계에서 처리).
3. `route.ts`/`categories.ts`의 검증 게이트·검토 큐 로직을 재확인하고, 플래그 복원만으로
   의도한 동작(자동수집 재개 + `pending_review` 큐잉)이 재현되는지 판단한다. 코드 수정이
   필요 없다면 "코드 변경 없음, DB 플래그 복원만으로 충분함"을 완료 기록에 명시한다.
4. `Specs/Content/POI.md` 갱신.
