# [Admin] 쉐이더 텍스트 생성기 — 거리장 링 텍스처를 디졸브 에코에 결합

## 배경 / 문제 정의

`20260912_1532`(쉐이더 텍스트 생성기 신규)·`20260912_1729`(그라디언트맵 버그 수정) 이후에도,
사용자가 참고 삼았던 Brik "LOVE" 레퍼런스 이미지와 우리 도구 결과를 나란히 비교한 결과
**스타일 자체가 다르다**는 피드백을 받았다.

- 레퍼런스: 획 가장자리에서부터 안쪽으로 **여러 겹의 동심원/등고선 무늬**가 보이고,
  전체적으로 흑백 톤 + 강한 그레인
- 우리 도구(디졸브 에코): 글자를 통째로 여러 번 복제해 겹치고 2단 블러로 후광만 얹는
  방식이라, 획 내부가 매끈한 단색 면이 되고 등고선 무늬가 나오지 않는다 — **구조적으로
  다른 기법**이기 때문

이번 대화 초반에 별도로 만들었다가 범위에서 뺐던 **"리퀴드 메탈" 프로토타입**(거리장
기반 동심원 링 — 획 중심에서 테두리로 갈수록 링이 맺히고 바깥으로 갈수록 부드럽게
사라지는 효과, `https://claude.ai/code/artifact/af9669ea-af29-4f95-a830-f2448b91607b`)의
핵심 기법이 이 레퍼런스와 훨씬 가깝다는 게 확인됐다. 사용자가 두 기법을 결합하기로
결정했다.

### 프로토타입 검증 완료 (2026-09-12, 스크래치 사본)

Brik 소스는 이번에도 가져오지 않았다 — 우리가 이미 만들어 둔 "리퀴드 메탈" 거리장
로직을 "디졸브 에코"의 에코 합성 실루엣에 적용하는 실험을 스크래치 사본에서 진행해
esbuild+Playwright 헤드리스로 실제 렌더링까지 확인했다. 결과가 레퍼런스에 크게
가까워짐을 육안으로 확인했다(사용자에게 전달한 이미지 참고).

**핵심 아이디어**: `buildEchoLayers()`가 만든 `full`(에코 합성 실루엣)을 알파 기반
그라디언트맵으로 바로 색칠하는 대신, 그 실루엣의 **경계선까지의 거리**(2-패스 챔퍼
거리 변환)를 계산해서 그 거리를 기준으로 밝고 어두운 링이 반복되도록 그린다.

### 프로토타입 코드 (참고용 — 그대로 옮기지 말고 이해한 뒤 어드민 코드 스타일로 재작성)

```ts
// 2-패스 챔퍼 거리 변환: mask[i]===0 인 픽셀까지의 거리를 반환한다.
function chamferDistance(mask: Uint8Array, w: number, h: number): Float32Array {
  const INF = 1e6
  const dist = new Float32Array(w * h)
  for (let i = 0; i < w * h; i++) dist[i] = mask[i] === 0 ? 0 : INF
  const D1 = 1, D2 = Math.SQRT2
  for (let y = 0; y < h; y++) {
    const row = y * w
    for (let x = 0; x < w; x++) {
      const idx = row + x
      let d = dist[idx]
      if (x > 0) d = Math.min(d, dist[idx - 1] + D1)
      if (y > 0) d = Math.min(d, dist[idx - w] + D1)
      if (x > 0 && y > 0) d = Math.min(d, dist[idx - w - 1] + D2)
      if (x < w - 1 && y > 0) d = Math.min(d, dist[idx - w + 1] + D2)
      dist[idx] = d
    }
  }
  for (let y = h - 1; y >= 0; y--) {
    const row = y * w
    for (let x = w - 1; x >= 0; x--) {
      const idx = row + x
      let d = dist[idx]
      if (x < w - 1) d = Math.min(d, dist[idx + 1] + D1)
      if (y < h - 1) d = Math.min(d, dist[idx + w] + D1)
      if (x < w - 1 && y < h - 1) d = Math.min(d, dist[idx + w + 1] + D2)
      if (x > 0 && y < h - 1) d = Math.min(d, dist[idx + w - 1] + D2)
      dist[idx] = d
    }
  }
  return dist
}

// full(에코 실루엣)을 축소 해상도로 내려 거리장을 계산하고, 링 텍스처를 만들어 원해상도로 확대한다.
function buildRingLayer(source: HTMLCanvasElement, opt: {
  insideRange: number; outsideRange: number; density: number; sharpness: number; decay: number; res: number
}): HTMLCanvasElement {
  const RES = opt.res
  const bake = document.createElement('canvas')
  bake.width = RES; bake.height = RES
  const bctx = bake.getContext('2d')!
  bctx.drawImage(source, 0, 0, source.width, source.height, 0, 0, RES, RES)
  const img = bctx.getImageData(0, 0, RES, RES)
  const n = RES * RES
  const mask = new Uint8Array(n)
  const inv = new Uint8Array(n)
  for (let i = 0; i < n; i++) {
    const on = img.data[i * 4 + 3] > 32 ? 1 : 0
    mask[i] = on; inv[i] = on ? 0 : 1
  }
  const insideDist = chamferDistance(mask, RES, RES)
  const outsideDist = chamferDistance(inv, RES, RES)

  const out = bctx.createImageData(RES, RES)
  for (let i = 0; i < n; i++) {
    let field: number
    if (mask[i]) field = 0.5 + 0.5 * Math.min(1, insideDist[i] / opt.insideRange)
    else field = 0.5 - 0.5 * Math.min(1, outsideDist[i] / opt.outsideRange)
    const d = Math.abs(field - 0.5) * 2                      // 0=경계, 1=포화(안/밖)
    const envelope = Math.pow(Math.max(0, 1 - d), opt.decay) // 경계 근처에서만 링이 살아있음
    const phase = d * opt.density
    const frac = phase - Math.floor(phase)
    const ridgeRaw = Math.pow(Math.max(0, 1 - Math.abs(frac - 0.5) * 2), opt.sharpness)
    const flat = mask[i] ? 232 : 0        // 포화 영역의 평평한 값(안쪽=밝게, 바깥=검정)
    const ripple = 6 + (255 - 6) * ridgeRaw
    const v = flat * (1 - envelope) + ripple * envelope
    const alpha = mask[i] ? 255 : Math.round(255 * Math.max(0, 1 - outsideDist[i] / opt.outsideRange))
    const p = i * 4
    out.data[p] = v; out.data[p + 1] = v; out.data[p + 2] = v; out.data[p + 3] = alpha
  }
  bctx.putImageData(out, 0, 0)

  const result = document.createElement('canvas')
  result.width = source.width; result.height = source.height
  const rctx = result.getContext('2d')!
  rctx.drawImage(bake, 0, 0, RES, RES, 0, 0, result.width, result.height)
  return result
}
```

프로토타입에서 검증한 파라미터(1280 캔버스 기준, "LOVE" 텍스트): `insideRange: size*0.028`,
`outsideRange: size*0.02`, `density: 11`, `sharpness: 2.4`, `decay: 1.6`, `res: 480`.

## 상세 요구사항

### 1. 렌더링 파이프라인 변경

`composeShaderTextDissolve.ts`의 `drawShaderTextDissolve()`에서:

- `buildEchoLayers()`로 만든 `full`을 `buildRingLayer()`에 넣어 링 텍스처를 만든다.
- 기존에는 `glow + full`을 `lighter`로 합친 뒤 **알파 기반** `applyGradientMap()`을
  씌웠는데, **링 레이어는 이미 스스로 명암(그레이스케일)을 인코딩**하므로 그 위에
  알파 기반 LUT를 그대로 다시 씌우면 안 된다(명암이 뭉개짐 — 프로토타입에서 실제로
  겪은 문제).
- **색상 처리를 다시 설계해야 한다.** 사용자가 그라디언트맵 4색(그림자·헤일로·코어·
  이너코어)으로 색을 넣고 싶어할 수 있으므로, `applyGradientMap()`을 **알파가 아니라
  링 레이어의 밝기(그레이스케일 값)를 키로 쓰는 LUT**로 바꾼다. 즉 `data[p]`(R채널,
  이미 그레이스케일이므로 R=G=B) 값을 LUT 인덱스로 쓰도록 수정.
- `20260912_1729`에서 고친 그라디언트맵 최소 구간 폭 안전장치(`GRADIENT_STOP_MIN_GAP`)는
  이 변경 후에도 그대로 유지한다.

### 2. 새 컨트롤 노출

프로토타입에 하드코딩한 5개 값을 컨트롤 패널에 슬라이더로 추가한다 (그룹명·배치는
구현자 재량, 예: "링 텍스처"라는 새 그룹):

| 파라미터 | 의미 | 프로토타입 값 | 제안 범위 |
|---|---|---|---|
| `ringDensity` | 링 밀도(경계 근처에 몇 겹이 맺히는가) | 11 | 3~24 |
| `ringSharpness` | 링 선명도(경계가 뚜렷한 정도) | 2.4 | 1~6 |
| `ringDecay` | 링이 경계에서 멀어질수록 잦아드는 속도 | 1.6 | 0.5~4 |
| `ringInsideRange` | 안쪽으로 얼마나 깊이 포화(평평)되는가 | size×0.028 | size×0.01~0.08 |
| `ringOutsideRange` | 바깥으로 얼마나 멀리 글로우가 번지는가 | size×0.02 | size×0.005~0.06 |

`badges.image_gen_params`(`generator: "shader-text-dissolve"`)와 신규 `shader_text_presets`
테이블에 이 5개 필드를 추가로 저장해야 한다 — **마이그레이션은 필요 없다**(둘 다 jsonb라
스키마 변경 없이 필드만 늘면 된다). `parseShaderTextParams()`/`SHADER_TEXT_RANGES`에
정의만 추가하면 된다.

### 3. 성능

프로토타입은 480×480로 축소해 거리 변환(챔퍼 2-패스, O(n))을 계산한 뒤 1280으로 다시
확대하는 방식이라 가벼워야 하지만, **실제 어드민 화면에서 애니메이션 재생 중 매 프레임
다시 계산하면 안 된다** — `20260912_1532`가 그레인 타일에 이미 적용한 캐시 패턴
(설정이 안 바뀌면 재계산하지 않음)을 여기도 적용한다. 텍스트·폰트·에코 설정이 바뀔
때만 링 레이어를 다시 굽고, 애니메이션(웨이브·플로트)만 도는 프레임에서는 캐시된
링 레이어를 재사용한다(에코 오프셋이 애니메이션에 따라 프레임마다 바뀌면 `full` 자체가
바뀌므로 이 경우는 재계산이 불가피할 수 있다 — 구현자가 실측해서 판단).

### 4. 기존 항목과의 관계

- **에코(Text Echo) 그룹은 그대로 유지한다** — 링 레이어의 소스가 `full`(에코 합성
  실루엣)이므로, 에코 카피 수·오프셋을 조정하면 링이 맺히는 실루엣 자체가 달라져
  두 효과가 함께 작동한다. 별도 토글(에코 on/off, 링 on/off)을 만들지는 이 티켓
  범위에서 정하지 않는다 — 필요하면 후속 논의.
- **헤일로(Halo & Glow) 그룹도 유지한다** — 프로토타입은 `glow`(기존 2단 블러 후광)를
  링 레이어와 `lighter`로 합쳤다. 이 관계를 그대로 가져간다.
- **가장자리 부드럽기(edgeBlur)**는 최종 합성 단계에서 그대로 적용된다.

4. `ShaderTextControls.tsx`에 "링 텍스처" 컨트롤 그룹 추가
5. 링 레이어 캐싱 적용(3절)
6. esbuild+Playwright 헤드리스로 실제 shipped 코드를 렌더링해 프로토타입 결과와
   동등한 수준인지 육안 확인 (이번 대화에서 쓴 방식 그대로)
7. 컬러 그라디언트맵(밝기 기반)도 최소 1개 조합으로 실제 색이 들어가는지 확인

## 유예된 판단 (이 티켓에서 다루지 않음)

- 에코/링 두 효과의 온오프를 독립적으로 켜고 끄는 토글은 만들지 않는다 — 항상 함께

  같은 파라미터가 잘 맞는지는 구현 후 실사용 피드백으로 조정한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `chamferDistance`/`buildRingLayer`를 티켓 원문 프로토타입 그대로(알고리즘 동일) 어드민
  코드 스타일로 옮겨 `shaderTextRingField.ts`에 신설.
- `drawShaderTextDissolve()` 파이프라인에서 `full`(에코 합성 실루엣)을 `buildRingLayer()`에
  넣어 링 레이어를 만들고, 기존에 `full`을 그대로 합성하던 자리에 이 링 레이어를 대신
  합성하도록 교체(`glow + ringLayer`를 `lighter`로 합성).
- `applyGradientMap()`을 알파 기반에서 **밝기 기반**(R채널, 그레이스케일이라 R=G=B)으로
  변경 — 링 레이어가 스스로 인코딩한 명암을 LUT 키로 쓴다.
- `ring: { density, sharpness, decay, insideRange, outsideRange }` 5개 필드를
  `ShaderTextParams`에 추가(타입·범위·기본값·`parseShaderTextParams`·
  `extractShaderTextStyle` 모두 반영). `insideRange`/`outsideRange`는 캔버스 크기 대비
  비율로 저장한다(절대 px 아님 — 다른 캔버스 크기에서도 프리셋 재사용 가능하도록).
- `ShaderTextControls.tsx`에 "Ring Field — 링 텍스처" 아코디언 그룹 신설(슬라이더 5종,
  기존 `SliderField` 패턴 재사용).
- 링 레이어 캐싱: `full`에 영향을 주는 값(문구·폰트·에코·소스·링 파라미터·실루엣
  이미지)이 바뀔 때만 재계산. 메인 웨이브·에코 플로트 애니메이션이 켜져 있으면
  `bakedPhase`가 매 프레임 `full`을 바꾸므로 그 경우엔 캐시 키에 위상을 포함해 매 프레임
  재계산이 불가피하다(티켓 3절에서 명시한 대로 구현자 재량으로 판단).
- `badges.image_gen_params`/`shader_text_presets`는 jsonb라 스키마 변경 없이 필드가
  늘어난 대로 저장된다 — 마이그레이션 없음(티켓 명시대로).
