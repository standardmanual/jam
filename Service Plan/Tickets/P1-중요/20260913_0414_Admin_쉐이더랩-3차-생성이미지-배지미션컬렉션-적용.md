# [Admin] 쉐이더 랩 3차 — 생성 이미지를 배지·미션·컬렉션 대표이미지로 적용

## 배경 / 문제 정의

1차 티켓([20260912_1951](20260912_1951_Admin_쉐이더랩-신규-1차-에디터골격및핵심이펙트.md))과
2차 티켓([20260912_2157](20260912_2157_Admin_쉐이더랩-2차-나머지레이어-텍스트우선-재생루프버그.md))
모두 "사용처: 이미지 업로드 → 레이어 합성 → 배지/컬렉션(아이템북)/미션 이미지로 컨텐츠 검색
후 자동 등록"을 전체 로드맵으로 명시하면서 "3차(배지·컬렉션·미션 자동 등록)는 범위 밖,
재검토 시 별도 요청 필요"라고 유예해뒀다. 이번이 그 별도 요청이다.

현재 `/admin/shader-lab`(29종 레이어 지원, staging 배포 완료)은 캔버스에서 합성한 이미지를
**로컬 PNG 다운로드**만 지원한다(`ShaderLabExportPanel.tsx` 파일 헤더 주석에 "1차는 로컬
PNG 다운로드만 지원한다(배지/컬렉션/미션 자동 등록은 3차 범위)"라고 명시돼 있다). 서버
업로드·특정 콘텐츠 레코드 반영 로직이 전혀 없다.

## 사용자 확정 요구사항

내보내기 패널에 아래 흐름을 추가한다.

1. **탭으로 대상 콘텐츠 타입 3종을 나열**: 배지 이미지 / 미션 대표이미지 / 컬렉션 대표이미지.
2. 탭을 선택하면 **텍스트로 이미 등록된 대상을 검색**한다(배지명/미션명/컬렉션명).
3. 검색 결과에서 하나를 선택하면 **적용 전 미리보기**를 보여준다(현재 생성된 이미지가 그
   레코드에 반영됐을 때 어떤 모습이 될지).
4. **적용하기** 버튼을 누르면 실제로 서버에 업로드하고 해당 레코드의 이미지 컬럼을 갱신한다.

## 사전 조사 결과 (착수 전 세션에서 확인, 재검토 없이 그대로 신뢰 가능)

### 배지 — 사실상 동일한 기능이 이미 있다

`/admin/shader-text`의 `ShaderTextBadgeApply.tsx`가 정확히 이 흐름(검색 → 선택 → 미리보기
→ 적용)을 이미 구현하고 있다. 이 컴포넌트와 아래 API를 참고해 shader-lab에 맞게 재사용/
일반화한다.

- 검색: `POST /api/admin/shader-text/search`(`src/lib/admin/shaderTextBadgeSearch.ts`,
  shader-text 전용) 또는 범용 `GET /api/admin/badges/search`(`src/app/api/admin/badges/
  search/route.ts`) — 둘 중 범용 쪽을 재사용하는 게 shader-lab에 더 적합할 가능성이 높다.
  실제 응답 스키마를 비교해 선택할 것.
- 적용: `POST /api/admin/shader-text/generate`(`src/app/api/admin/shader-text/generate/
  route.ts`)가 참고 구현이다. canvas PNG를 FormData로 받아 Storage 버킷 `images`의
  `badges/shader-text/{badgeId}.png` 경로에 `upsert: true`로 올리고, `getPublicUrl()` +
  캐시 무효화 쿼리(`?v=Date.now()`)를 붙여 `badges.image_url`(text)과
  `badges.image_gen_params`(jsonb, 생성 파라미터 재편집용 — shader-lab 레이어 구성을 여기에
  넣을지는 구현 시 판단)를 갱신한다. shader-lab용으로는 `badges/shader-lab/{badgeId}.png`
  경로를 쓸 것(도구별 경로 분리 관례를 따름, 다른 도구의 파일을 덮어쓰지 않기 위함).

### 미션 — 업로드 UI는 있으나 검색 API가 없다

실제 테이블명은 `missions`(UI 라벨만 "게이트 미션"). 대표 이미지 컬럼은
`missions.image_url`(text). 업로드 UI는 `GateMissionForm.tsx`(696~703줄)가
`ImageUploadField`를 `folder="mission-images"`로 이미 쓰고 있다. **이름으로 검색하는 서버
API가 없다** — 기존 어드민 화면(`GateMissionManager.tsx`/`formData.ts`)은 `missions` 테이블을
통째로 클라이언트에 로드해 필터링한다. 이 티켓에서 `GET /api/admin/missions/search`(또는
기존 `/api/admin/missions` route에 `?q=` 쿼리 파라미터 추가) 신규 구현이 필요하다.

### 컬렉션(아이템북) — 마찬가지로 검색 API가 없다

테이블 `item_books`, 대표 이미지 컬럼 `image_url`(별도로 배경용 `background_image_url`도
있음 — 헷갈리지 않도록 반드시 `image_url` 쪽에 반영). 업로드 UI는
`ItemBookForm.tsx`(321~325줄)가 `ImageUploadField`를 `folder="itembooks"`로 쓰고 있다.
`GET /api/admin/itembooks/route.ts`는 전체 목록만 반환하고 이름 검색 파라미터가 없다 —
이 티켓에서 검색 파라미터(`?q=`) 추가 또는 신규 검색 엔드포인트가 필요하다.

### 공통 패턴

- Storage 버킷은 항상 `'images'`(공개 버킷), `getPublicUrl()` + `?v=Date.now()` 캐시
  무효화 쿼리 관례를 따른다.
- 재사용 가능한 공용 유틸: `ImageUploadField`(`src/components/admin/ImageUploadField.tsx`),
  `canvasToBlob`(`src/app/admin/badges/bakePreviewToBlob.ts`, 이미 shader-lab이 로컬
  다운로드에 쓰고 있음 — 서버 업로드에도 동일하게 재사용).
- **"생성된 캔버스를 서버에 업로드해 특정 레코드의 이미지 컬럼을 갱신"하는 서버 로직 자체는
  공용 유틸로 추출돼 있지 않고 도구마다(`activity-badge-image`·`badge-image`·`shader-text`)
  중복 구현돼 있다.** 이번에 배지·미션·컬렉션 3종을 동시에 다루므로, 이 기회에
  `{bucket, path, table, idColumn, imageColumn}` 형태로 매개변수화한 공용 함수(예:
  `src/lib/admin/applyGeneratedImage.ts`)를 만들어 3개 라우트가 공유하는 편이 좋다 — 다만
  기존 3개 도구(activity-badge-image 등)까지 리팩터링해 이 공용 함수를 쓰게 바꾸는 것은
  이 티켓 범위 밖이다(회귀 위험 대비 이득이 낮음, 신규 3개 라우트만 공용 함수를 쓰게 한다).

## 상세 요구사항

### 서비스/코드베이스 관점

1. 신규 서버 라우트 3종(또는 `type` 파라미터로 분기하는 1~2개 라우트):
   - 검색: 배지는 기존 API 재사용 검토, 미션·컬렉션은 신규(`?q=` 텍스트 검색, 최소 id/이름/
     현재 이미지 URL 반환).
   - 적용: 배지·미션·컬렉션 공통으로 `applyGeneratedImage` 공용 함수를 통해 PNG 업로드 +
     대상 레코드 이미지 컬럼 갱신.
2. `ShaderLabExportPanel.tsx`(또는 그 옆에 신규 컴포넌트)에 탭 UI(shadcn `Tabs`, 프로젝트
   컨벤션대로 어드민은 shadcn/ui 기반) 3개(배지/미션/컬렉션) 추가.
3. 각 탭: 텍스트 검색 인풋 → 검색 결과 목록(현재 이미지 썸네일 포함 권장) → 항목 선택 시
   "적용 전 미리보기"(현재 생성된 캔버스 이미지를 대상 이름과 함께 보여주는 정도로 충분,
   레이아웃 합성까지는 불필요) → "적용하기" 버튼.
4. 적용 성공/실패 토스트 안내(UX Writing 가이드 준수, [현상]→[원인]→[해결책] 구조).
5. 캔버스 소스는 기존 `ShaderLabViewport.tsx`가 소유한 1280×1280 WebGPU 백킹 canvas를
   그대로 재사용(`canvasToBlob()`으로 PNG Blob화, 로컬 다운로드와 동일한 방식).

### UI/UX 관점

- 신규 UI이지만 `/admin/` 화면이므로 MODULAR 탐색 절차는 생략한다(기존 정책).
- shadcn/ui 기존 컴포넌트(`Tabs`, `Input`, `Command`/`Combobox` 계열 검색 UI 등) 재사용,
  `ShaderTextBadgeApply.tsx`의 기존 UI 패턴을 최대한 그대로 따른다(사용자에게 이미 익숙한
  패턴).

### 컨텐츠 관점

- 해당 없음(콘텐츠 데이터 자체를 새로 만들지 않음, 기존 레코드의 이미지 컬럼만 갱신).

## 구현 계획

1. 배지 탭: `ShaderTextBadgeApply.tsx` + 관련 API를 shader-lab 캔버스 소스에 맞게
   재사용/일반화. 범용 `/api/admin/badges/search` 재사용 가능 여부 확인.
2. `src/lib/admin/applyGeneratedImage.ts`(가칭) 공용 함수 신설 — bucket/path/table/
   idColumn/imageColumn을 매개변수로 받아 PNG 업로드 + DB 갱신을 수행.
3. 미션 검색 API 신규(`GET /api/admin/missions/search?q=`) + 적용 API(공용 함수 사용).
4. 컬렉션 검색 API 신규(`GET /api/admin/itembooks/search?q=` 또는 기존 route에 `?q=` 추가) +
   적용 API(공용 함수 사용).
5. `ShaderLabExportPanel.tsx`에 탭 UI + 검색 + 미리보기 + 적용 버튼 통합.
6. 로컬 `ADMIN_EMAILS` 실렌더 확인(3개 탭 각각 검색→선택→미리보기→적용까지, 워크트리
   제약으로 esbuild+playwright 병행 검증).
7. DB는 스키마 변경이 없다(기존 image_url 컬럼 갱신만) — 마이그레이션 불필요.

## 유예된 판단

1. 기존 3개 도구(activity-badge-image·badge-image·shader-text)를 공용 함수로 리팩터링하는
   것은 범위 밖(위 "공통 패턴" 절 참고).
2. 배지의 `image_gen_params`처럼 "생성 파라미터를 저장해 나중에 재편집" 기능을 미션·컬렉션에도
   만들지는 이번에 결정하지 않는다 — 사용자가 요구하지 않았고, 대상 테이블에 그런 컬럼도 없다.
   구현 중 필요성이 보이면 별도 티켓으로 판단.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 공용 함수 applyGeneratedImage(bucket=images 고정, table/id/path/png)를 신설해 Storage 업로드
  + getPublicUrl() + 캐시 무효화 쿼리 + 대상 레코드 image_url 갱신을 한 곳에 모았다. idColumn/
  imageColumn은 세 테이블(badges/missions/item_books) 모두 id/image_url로 동일해 매개변수화
  하지 않고 table만 받는다(사전 조사 결과의 판단 위임 사항, 주요 의사결정 참고).
- 미션/컬렉션 검색 API를 신규 작성했다: GET /api/admin/missions/search?q=(테이블 missions,
  이름 컬럼은 name이 아니라 title이었다 - 사전 조사에 없던 사실이라 여기 기록), GET
  /api/admin/itembooks/search?q=(테이블 item_books, 기존 GET 라우트는 건드리지 않고 별도
  서브라우트로 분리).
- 배지 검색은 사전 조사 지시대로 범용 GET /api/admin/badges/search(query= 파라미터)를 그대로
  재사용했다 - shader-text 전용 POST 검색(페이지네이션·image_gen_params 포함)보다 단순해
  shader-lab의 검색/선택/미리보기/적용만 필요한 흐름에 더 맞았다.
- 적용 API는 POST /api/admin/shader-lab/apply 하나로 통합하고 FormData의 target(badge/
  mission/collection)으로 분기했다(티켓이 허용한 1~2개 라우트 방식). Storage 경로는 도구별
  분리 관례를 따라 badges/shader-lab/{id}.png, missions/shader-lab/{id}.png,
  itembooks/shader-lab/{id}.png로 고정했다.
- ShaderLabApplyTab.tsx를 신설해 ShaderTextBadgeApply.tsx와 동일한 흐름(검색 -> 선택 ->
  미리보기 스냅샷 -> 적용, 재생 중 적용 비활성화)을 target별로 재사용 가능하게 일반화했다.
  ShaderLabExportPanel.tsx에 shadcn Tabs 3개(배지 이미지/미션 대표이미지/컬렉션 대표이미지)로
  통합했고, 기존 로컬 PNG 다운로드 버튼은 그대로 유지했다.
