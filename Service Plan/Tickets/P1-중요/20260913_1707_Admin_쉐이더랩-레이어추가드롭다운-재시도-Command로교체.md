# [Admin] 쉐이더 랩 — 레이어 추가 드롭다운 재시도(Command로 교체) + 헤더 문구 삭제

## 배경 / 문제 정의

직전 티켓([20260913_1613](../P2-일반/20260913_1613_Admin_쉐이더랩-레이어사이드바-저장패널-UI개선.md),
CLOSED, staging 배포 완료)에서 "레이어 추가 드롭다운이 잘려서 선택 불가"를 HIGH로
판정하고 `select.tsx`의 popper 뷰포트 높이 고정 제거로 고쳤다고 보고했으나, **실제
배포 환경에서 재현한 결과 여전히 잘리고 스크롤도 되지 않는다**는 사용자 재현 보고를
받았다. 이전 수정(esbuild+playwright 검증)은 격리된 하네스에서는 개선을 확인했지만,
실제 Next.js 페이지 컨텍스트(레이아웃 CSS·다른 요소와의 상호작용)에서는 Radix
Select의 popper 충돌 인식 로직이 여전히 신뢰할 수 없게 동작하는 것으로 보인다.

사용자가 명시적으로 "다른 유형의 컴포넌트를 사용해보라"고 요청했다 — 이번엔 Select를
패치하는 대신 완전히 다른 컴포넌트로 교체한다.

추가로 사용자가 지적한 2가지:
1. "쉐이더 랩" 타이틀 아래 부제 문구("레이어를 쌓아 이미지 위에 이펙트를 합성해요...")를
   삭제해달라 — 직전 티켓에서 카드 3곳의 `CardDescription`은 지웠지만 이 최상단 부제는
   범위에 없어 남아 있었다.
2. 저장/불러오기 폼이 "쉐이더 랩" 타이틀의 우측 페이지 끝에 오지 않는다 — 위 부제 문구가
   길어서 헤더 flex 행이 좁은 화면에서 줄바꿈됐을 가능성이 높다(1번과 연관).

## 결정된 방향

1. **레이어 추가 컨트롤을 `Select`에서 `Popover`+`Command`로 완전히 교체** (둘 다
   `jam-web/src/components/admin/ui/`에 이미 있는 컴포넌트, 신규 의존성 없음).
   `command.tsx`의 `CommandList`는 `max-h-[300px] overflow-y-auto`인 평범한 CSS 스크롤
   컨테이너라 Radix Select 특유의 "충돌 인식 가용 높이" 계산에 기대지 않는다 — 뷰포트
   크기나 레이아웃 컨텍스트와 무관하게 항상 스크롤 가능하다. 부가 이득으로 검색(타이핑
   필터링)도 얻는다(직전 티켓의 "유예된 판단" 1번이 이번에 해소됨).
2. `page.tsx`의 "쉐이더 랩" 타이틀 아래 부제 `<p>` 삭제.
3. 헤더 행을 `flex-nowrap`으로 바꿔(부제 삭제로 내용이 짧아져 실질적으로 줄바꿈 여지가
   거의 없어지지만, 명시적으로 보장) 저장 폼이 항상 타이틀 우측 끝에 위치하게 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. `jam-web/src/app/admin/shader-lab/ShaderLabLayerSidebar.tsx`의 레이어 추가
   `Select`/`SelectContent`/`SelectGroup`/`SelectLabel`/`SelectItem`/`SelectTrigger`/
   `SelectValue` 사용을 전부 제거하고, `Popover`(트리거: "+ 레이어 추가" 버튼)
   +`Command`(`CommandInput` 검색창 + `CommandList` + `CommandGroup`
   "소스"/"이펙트" + `CommandItem`)로 교체한다. 항목 선택 시 `onAdd(type)` 호출 후
   팝오버를 닫는다. `PopoverContent`는 다른 포털 컴포넌트와 동일하게
   `[data-admin-theme]` 스코프 `container`를 전달한다(직전 티켓에서 확립한 패턴).
2. `page.tsx`의 부제 `<p className="mt-1 text-sm text-muted-foreground">...</p>` 삭제.
3. `page.tsx`의 헤더 `<div className="flex flex-wrap items-start justify-between gap-4">`를
   `flex-nowrap items-center`로 변경(부제 삭제로 `<div>` 래퍼도 불필요해져 `h1`을 직접
   자식으로 둘 수 있다).

### UI/UX 관점

- 어드민 화면이므로 MODULAR 탐색 절차는 생략한다(기존 정책).
- 검색 placeholder는 "레이어 검색…" 등 UX Writing 가이드(해요체 불필요, 입력 필드
  placeholder는 예시/안내 텍스트) 톤에 맞게 작성.

## 구현 계획
