# [Admin] 쉐이더 랩 — 배경 투명 설정이 PNG export에 반영되지 않음

## 배경 / 문제 정의

사용자가 쉐이더 랩에서 레이어의 배경색 알파(투명도)를 0(완전 투명)으로 설정했는데, PNG를
저장(export)하면 투명하게 저장되지 않고 불투명하게 나온다고 보고했다. 컴포지션 전체 배경색을
따로 설정하는 UI는 없으므로, 사용자가 말한 "배경색"은 텍스트 레이어 `textColor` 또는 리퀴드
메탈 `colorBack`의 알파 슬라이더(둘 다 티켓
[20260913_2110](../P2-일반/20260913_2110_Admin_쉐이더랩-리퀴드메탈이미지마스크-색상투명도지원.md)에서
`alpha: true`로 추가됨)를 가리키는 것으로 판단된다.

## 사전 조사 결과 (오케스트레이터, Explore 에이전트 위임)

### 원인

`ShaderLabExportPanel.tsx`의 `canvasToBlob()`, `bakePreviewToBlob.ts`의 `canvas.toBlob(...,
'image/png')` 자체에는 배경을 강제로 채우는 로직이 없다 — 문제는 export 이전에 렌더링되는
캔버스 자체가 처음부터 알파를 가질 수 없는 상태로 만들어진다는 데 있다. 원인은 JAM! 코드가
아니라 `@basementstudio/shader-lab` 패키지(node_modules, `patches/@basementstudio+shader-lab
+3.0.2.patch`가 건드리지 않는 파일들)의 렌더러 설계에 있다:

1. **`create-webgpu-renderer.js:6-11`**: `new THREE.WebGPURenderer({ alpha: false, ... })`로
   WebGPU 컨텍스트 자체가 opaque로 생성된다.
2. **같은 파일 `:25`**: `renderer.setClearColor("#0a0d10", 1)` — 매 프레임 alpha=1(완전
   불투명)로 클리어한다.
3. **`pipeline-manager.js:130-136, 204-205`**: `PipelineManager` 생성자가
   `MeshBasicMaterial({ color: "#080808" })`의 풀스크린 쿼드(`baseMesh`)를 만들어, 모든 레이어
   패스가 돌기 **전에** 프레임 전체를 opaque `#080808`로 먼저 채운다. 레이어가 하나도
   없거나(`activePasses.length === 0`) 전부 alpha=0이어도 이 base scene만 그려진 채 끝난다.

레이어 자신의 텍스처(Canvas 2D `fillStyle` / `getShaderColorFromString`) 안에서는 알파가
정확히 계산된다 — 티켓 20260913_2110의 QA는 "**아래 레이어가** 비쳐 보이는지"(레이어 간 합성)
만 검증했고, 최상단 캔버스가 opaque로 시작한다는 사실은 그때 발견되지 않았다. 즉 레이어 내부
알파 계산과 export UI(패널·훅) 코드는 정상이며, 파이프라인 최상단(WebGPU 컨텍스트·클리어
컬러·베이스 메시)이 문제다.

### 게이트 리뷰 sideFinding(티켓 20260914_1025)과의 관계 — 별개 문제

티켓 [20260914_1025](../P3-낮음/20260914_1025_Admin_쉐이더랩PNG-export-헤드리스환경alpha0-잠재이슈.md)
(P3, OPEN)는 **헤드리스(WebGPU 미지원) 환경에서 PNG export가 완전 투명(alpha=0)하게 나온다**는
내용으로, 실제 GPU 환경(macOS Chrome)에서는 문제없다고 보고됐었다. 이번 사용자 보고는 그
반대다 — **실제 지원 브라우저에서, 알파를 0으로 설정해도 export가 항상 완전 불투명하게
나온다.** 한쪽은 "항상 불투명"(이 티켓), 다른 한쪽은 "항상 투명"(20260914_1025)이라 증상이
반대이고 코드 경로도 다르다(하나는 정상 렌더링 파이프라인 내부의 opaque 하드코딩, 다른 하나는
렌더링 자체가 실패/유실되는 특수 테스트 환경 현상). **두 티켓을 하나로 묶어 고치려 하면 안
된다** — 20260914_1025는 그대로 별도 유지한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 레이어 알파가 0에 가까울수록 최종 export PNG의 해당 영역도 그에 비례해 투명해지도록
  렌더링 파이프라인을 수정한다.
- 수정은 `patches/@basementstudio+shader-lab+3.0.2.patch`에 `create-webgpu-renderer.js`·
  `pipeline-manager.js` 패치를 추가하는 방식이 될 가능성이 높다(`WebGPURenderer({ alpha: true
  })`, `setClearColor`의 alpha 인자를 0으로, `baseMesh`를 조건부 처리 또는 알파 인식하도록
  변경 등) — 착수 시 실측으로 최소 변경 지점을 확정한다.
- **사이드 이펙트 위험**: `baseMesh`(#080808 배경판)를 단순 제거하거나 투명화하면, 레이어가
  없는/약한 상태에서 배경이 무엇으로 보여야 하는지(현재는 짙은 회색으로 안정적으로 보임)가
  바뀐다 — 다른 모든 레이어 타입(그라디언트·하프톤·ASCII·디더링 등 29종)의 기존 시각적
  결과물에 회귀가 없는지 반드시 확인한다. 특히 alpha 블렌딩이 기본으로 꺼져 있던 레이어들이
  이번 변경으로 의도치 않게 반투명해지지 않는지 주의한다.
- `ShaderLabViewport`(미리보기)·`ShaderLabExportPanel`(PNG export)·`ShaderLabApplyTab`(배지/
  미션/컬렉션 적용)이 모두 같은 캔버스/텍스처를 공유하므로, 수정 하나로 세 화면 모두 일관되게
  반영되는지 확인한다.

## 구현 계획

1. 로컬 실렌더(`DEV_PROCESS_GUARDRAILS.md` 패턴 13)로 현재 버그를 재현한다 — 텍스트 레이어
   `textColor` 알파 0, 리퀴드 메탈 `colorBack` 알파 0 각각의 export PNG를 픽셀 단위(alpha
   채널)로 확인해 항상 255로 고정되는지 재확인한다.
2. `create-webgpu-renderer.js`(`alpha` 옵션, `setClearColor`)와 `pipeline-manager.js`
   (`baseMesh`)를 최소 범위로 patch해 알파가 최종 캔버스까지 전파되도록 수정한다.
3. 수정 후 같은 조건으로 재측정해 alpha 채널이 레이어 알파값에 비례하는지 확인한다.
4. **회귀 확인**: 알파를 지원하지 않는 나머지 레이어 타입들(그라디언트·플루이드·픽셀 트레일
   등 대표 몇 종)의 기존 export 결과가 이번 변경으로 달라지지 않는지 픽셀 비교로 확인한다.
5. `ShaderLabApplyTab.tsx` 적용 결과물도 함께 확인한다.
6. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` 재확인, patch-package 재적용성
   (postinstall) 확인.
