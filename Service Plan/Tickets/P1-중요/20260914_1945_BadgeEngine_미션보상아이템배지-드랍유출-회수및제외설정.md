# [BadgeEngine] 미션 보상 전용 아이템배지 드랍 유출 — 회수 및 재발 방지

## 배경 / 문제 정의

사용자가 본인 계정(sihyunrr@gmail.com)에 동기화 직후 "5일 연속 습관 런" 아이템배지가 발급된
경위를 문의했다. 조사 결과 이 배지는 `type='item'`으로, `condition_json`이 비어 있어 실제로는
어떤 조건도 검사하지 않는 **드랍엔진(확률 뽑기) 소관**이었다. 동일 이름의 미션
(`missions.id: fcf11064-...`)이 이 배지를 보상으로 명시하고 있어, 사용자가 이 배지를 "미션
완료 시에만 받아야 하는 보상"으로 설계했음을 확인했다.

전수 조사 결과 **미션 보상으로 지정된 아이템배지 18종 전부**가 `badges.drop_excluded=false`
상태였다 — 드랍 제외 기능(`drop_excluded` 컬럼 + `/admin/drop-policy/exclusions` 화면 + 드랍엔진
`src/lib/drop-engine/index.ts:190,257`의 이중 체크)은 이미 존재했지만, 미션 보상용 배지를 만들
때 이 설정을 켜는 절차가 없어 18종 전부가 빠져 있었다. 그 결과 실제로 **6개 개체가 미션 완료
없이 드랍으로 유출**됐다 — 실유저 3명(kangwonc·cheerslovelymate·jae_everydae) + 테스트 계정
1명(god).

## 상세 요구사항

### 서비스/코드베이스 관점
- **재발 방지**: 미션 보상 아이템배지 18종 전부 `drop_excluded=true`로 전환.
- **회수**: 유출된 6개체를 사용자 승인(유저별 영향 범위 확인 후 "수거 후 아예 폐기해") 하에
  전량 폐기. 유저 알림은 만들지 않는다(사용자 명시 지시 — "알리지마").
  - 슬롯된 2건(jae_everydae·god)은 기존 `unslot_item_from_book()` RPC로 먼저 해제.
  - 6건 전부 `destroyed_at` 처리, 인벤토리 `used_slots` 유저별 정확히 반환, `custody_events`에
    `AdminDestroy` 이벤트(기존 8종 이벤트 중 이 용도로 이미 정의돼 있던 것 재사용) 기록.
- 코드 변경 없음 — 전부 데이터 정정.

### UI/UX 관점 (해당 시)
- jae_everydae·god 두 유저는 아이템북 슬롯 화면에서 장착돼 있던 칸이 빈 칸으로 바뀐 걸 보게
  된다. 별도 안내는 만들지 않기로 사용자가 결정했다.

### 컨텐츠 관점 (해당 시)
- 해당 없음.

## 구현 계획
1. `missions.reward_badge_ids`와 `badges.type='item'`을 조인해 미션 보상 아이템배지 전수 확인

   custody_events 기록, 트랜잭션으로 묶음
4. Supabase MCP `execute_sql`로 프로덕션 DB에 직접 실행, 실행 후 재조회로 6건 전부 폐기·

## 완료 기록

### 구현 내용 요약
`supabase/seed_reclaim_leaked_mission_reward_badges_20260914.sql`을 작성해 프로덕션 DB에
트랜잭션으로 직접 실행했다.

- 미션 보상으로 지정된 아이템배지 18종 전부 `drop_excluded=true`로 전환 — 이후 드랍엔진
  후보 조회(`getDropStructure`)와 최종 필터(`isDroppableForActivity`) 양쪽에서 제외되어
  더 이상 확률 드랍으로 나오지 않는다.
- 유출된 6개체(kangwonc 3·cheerslovelymate 1·jae_everydae 1·god 1) 전량 폐기:
  - jae_everydae·god의 슬롯된 2건은 `unslot_item_from_book()` RPC로 먼저 해제(인벤토리 칸을
    일시적으로 다시 소비) — 두 유저 모두 인벤토리에 여유가 있어 정상 처리됨(`inventory_full`
    사유로 막힐 위험 사전 확인 완료).
  - 6건 전부 `destroyed_at` 처리, 유저별 정확한 개수만큼 `used_slots` 반환(슬롯 해제로
    다시 소비된 분 + 원래 Held였던 분 합산 — 슬롯된 2건은 해제(+1)와 폐기(-1)가 상쇄돼
    최종적으로 원래 인벤토리 사용량에 변화 없음, "슬롯된 아이템은 인벤토리 칸을 차지하지
    않는다"는 기존 정책과 일치하는 결과).
  - `custody_events`에 6건 전부 `AdminDestroy` 이벤트 기록(기존 8종 이벤트 enum에 이미
    정의돼 있던 값 — `admin_destroy_orphaned_item()` RPC가 Orphaned 상태 전용으로 쓰던 것과
    같은 이벤트 타입을 Held/Slotted 유출분 회수에도 재사용).

### 주요 의사결정 / 핵심 메모
- **유저 알림을 만들지 않는다**(사용자 명시 지시 "알리지마", "저동화는 하지 않아"[자동화는
  하지 않아]) — 회수 사실을 알리는 별도 알림 문구·기능은 이번 범위에서 의도적으로 제외했다.
  필요해지면 별도 티켓.
- 미션 보상 아이템배지 18종을 "전부" 제외 전환한 근거: 사용자가 문의한 배지 1건만이 아니라
  전수 조사에서 18종 모두 동일한 결함(설정 누락)을 가지고 있음을 확인했고, 사용자가 "5일
  연속 습관런" 확인 대화에서 이어서 "기존 유저에게 드랍된 배지를 모두 수거 폐기해"라고 지시한
  것으로 보아 개별이 아닌 전체 범위로 판단했다.
- **재발 방지 구조 개선(자동화)은 이번 티켓 범위에서 다루지 않았다** — "미션 보상으로 지정되는
  순간 자동으로 드랍 제외되게 하자"는 방향을 사용자에게 제안했으나, 이번 대화에서는 회수까지만
  지시받았다. 별도 후속 티켓 대상.

### 잔여 이슈
- **재발 방지 자동화 미착수**: 지금은 미션 보상용 배지를 새로 만들 때 `drop_excluded`를
  사람이 직접 켜야 하는 구조 그대로다. 같은 클래스의 누락이 다시 발생할 수 있다 — 미션 저장
  시점에 `reward_badge_ids`에 포함된 아이템배지를 자동으로 `drop_excluded=true`로 맞추는
  로직(또는 저장 시점 가드)을 후속 티켓으로 검토할 것.
