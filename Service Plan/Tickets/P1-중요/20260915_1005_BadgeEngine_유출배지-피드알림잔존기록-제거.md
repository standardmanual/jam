# [BadgeEngine] 유출 배지의 피드·알림함 잔존 기록 제거

## 배경 / 문제 정의

티켓 [20260914_1945](../P1-중요/20260914_1945_BadgeEngine_미션보상아이템배지-드랍유출-회수및제외설정.md)·
[20260915_0912](../P1-중요/20260915_0912_BadgeEngine_아이템배지폐기-inventory_id미해제-정정.md)에서
유출된 6개체(kangwonc 3·cheerslovelymate 1·jae_everydae 1·god 1)의 인벤토리 소유 상태는
정리했으나, 사용자가 확인 요청 — 드랍 당시 함께 기록된 **피드(`user_activity_feed`)**와
**알림함 결산(`notifications` type=`activity_recap`)**에는 여전히 이 배지 획득 기록이 남아
있었다.

`notifications.payload.item_badges`는 유저·일자 단위로 그날의 모든 아이템 드랍을 배열 하나에
묶어 담는 구조라(`recordActivityRecap`), 4명 각각의 결산 1건 안에 이번에 지울 배지와 **그날의
다른 정상 드랍이 함께 들어있었다**(예: kangwonc 결산 1건에 이번 대상 3건 + 무관한 정상 드랍
"검은 비닐봉지" 1건). 행 전체를 지우면 무관한 정상 기록까지 함께 사라지므로, 배열 안에서
대상 항목만 골라 제거해야 했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `user_activity_feed`에서 대상 6개체의 `item_dropped` 이벤트 6건 삭제(이 6건은 각 개체
  전용 단일 행이라 행 자체를 삭제해도 무관한 데이터 손실 없음).
- `notifications`(type=`activity_recap`) 4건(유저별 1건)의 `payload.item_badges` 배열에서
  대상 6개체만 제거, **같은 배열 안의 다른 정상 드랍 4건(검은 비닐봉지·동면 동굴의 흙·양갱
  포장지·낡은 시장 바구니 조각)은 그대로 유지**.
- 코드 변경 없음 — 전부 데이터 정정.

### UI/UX 관점 (해당 시)
- 4명의 알림함 결산·피드 화면에서 이번 배지 관련 항목만 사라지고, 같은 날의 다른 항목은
  그대로 보인다.

## 구현 계획
1. `metadata->>'inventory_item_id'`로 `user_activity_feed`에서 대상 6건 확인 후 삭제
2. `payload->'item_badges'`에 대상 `inventory_item_id`가 포함된 `notifications` 행 확인(4건,
   유저별 1건) — 각 행에 무관한 다른 드랍이 섞여 있음을 먼저 확인
3. `jsonb_agg` + `jsonb_array_elements`로 배열에서 대상만 제외한 새 배열을 `jsonb_set`으로
   반영, `RETURNING`으로 각 행에 무관한 드랍만 남았는지 확인

  경로임을 확인했다 — 향후 유사 조사 시 참고.
