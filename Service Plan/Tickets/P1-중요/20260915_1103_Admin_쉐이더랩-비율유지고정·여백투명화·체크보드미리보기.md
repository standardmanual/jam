# [Admin] 쉐이더 랩 — 이미지 레이어 채우기 항상 비율 유지로 고정, 여백 투명화, 미리보기 체크보드

## 배경 / 문제 정의

티켓 [20260915_1042](20260915_1042_Admin_쉐이더랩-PNG투명도-three.js알파강제클로버링수정.md)로
알파 강제 클로버링 버그를 고친 뒤 스테이징에서 재확인한 결과, 알파 자체는 정상화됐지만 이미지
레이어 관련 별개 버그 3건이 추가로 드러났다.

1. "캔버스 채우기"(cover) 모드로 이미지를 올리면 원본이 캔버스보다 크게(잘려서) 보인다 —
   확인 결과 CSS `object-fit: cover`와 동일한 의도된 크롭 동작이었으나, 배지처럼 원본 형태를
   그대로 보존해야 하는 용도에는 맞지 않는다는 사용자 판단에 따라 **"채우기" 옵션 자체를
   없애고 항상 "비율 유지"(contain)로 고정**하기로 결정했다.
2. "비율 유지"로 축소(확대/축소 < 1)하면, 원본 이미지 바깥 영역(letterbox 여백)이 투명이
   아니라 **불투명 검정**으로 채워진다.
3. 이 검정이 PNG 다운로드에도 그대로 저장된다(2번과 동일 원인).
4. 스테이지(미리보기 캔버스)는 항상 투명 배경이어야 하는데, 지금은 단색 배경이라 어디가
   실제로 투명한 영역인지 눈으로 구분할 수 없다 — 체크보드 패턴으로 표시해야 한다.

## 사전 조사 결과

### 원인 1·2·3 — `media-pass.js`의 fitMode 분기와 letterbox 폴백색

`@basementstudio/shader-lab`의 `media-pass.js` `buildEffectNode()`:

```js
const contained = select(inBounds, this.mediaTextureNode, vec4(0, 0, 0, 1));
return mix(this.mediaTextureNode, contained, useContain);
```

- `useContain`이 UI의 "채우기" select(`params.fitMode`)로 0/1 전환되는데, 이걸 없애고
  1(비율 유지)로 고정하면 1번이 해결된다.
- letterbox 영역(`inBounds`가 false인 곳)의 폴백 색이 `vec4(0, 0, 0, 1)` — RGB는 검정이라도
  **알파가 1(불투명)**이라 2·3번 증상이 나타난다. `vec4(0, 0, 0, 0)`으로 바꾸면 해결된다.

### 원인 4 — 미리보기 컨테이너가 단색 배경

`ShaderLabViewport.tsx`의 캔버스 부모 요소가 `bg-[#0a0d10]`(단색)이라, 캔버스가 알파 0을
정확히 그려도 뒤에 있는 배경이 단색이라 "투명하게 보였다"는 사실을 시각적으로 구분할 방법이
없었다. 체크보드 패턴으로 바꾸면 실제 투명 영역이 무엇인지 즉시 눈에 보인다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `effectRegistry.ts`의 `imageFields`에서 `fitMode` select 필드를 제거한다(UI에서 선택지
  자체를 없앤다).
- `media-pass.js`(patch)에서 `fitModeUniform`을 UI 값과 무관하게 항상 1(비율 유지)로
  고정한다 — 기존 저장된 컴포지션에 `params.fitMode: 'cover'`가 남아있어도 무시하도록.
- `media-pass.js`(patch)의 letterbox 폴백 색을 `vec4(0, 0, 0, 0)`(완전 투명)으로 바꾼다.
- `ShaderLabViewport.tsx`의 캔버스 배경을 체크보드 패턴으로 바꾼다.

## 구현 계획

1. `media-pass.js` 생성자의 `this.fitModeUniform = uniform(0)` → `uniform(1)`.
2. `media-pass.js`의 `updateParams()`에서 `this.fitModeUniform.value = params.fitMode ===
   "contain" ? 1 : 0` → 조건 없이 `1`로 고정.
3. `media-pass.js`의 `vec4(0, 0, 0, 1)` → `vec4(0, 0, 0, 0)`.
4. `effectRegistry.ts`의 `imageFields`에서 `fitMode` 필드 정의 제거.
5. `ShaderLabViewport.tsx`의 캔버스 컨테이너 배경을 체크보드 CSS로 교체.
6. `npx patch-package @basementstudio/shader-lab`로 patch 재생성, `npm install`로 재적용성
   확인.
7. 로컬 esbuild+실제 WebGPU 브라우저 실렌더로 letterbox 영역이 `[0,0,0,0]`으로 나오는지,
   `fitMode:'cover'`를 넘겨도 강제로 contain 처리되는지 재확인.
8. `npx tsc --noEmit`, `npm run lint`.

## 완료 기록

### 구현 내용 요약

구현 계획 1~8 그대로 진행했다. `media-pass.js`는 `fitModeUniform` 기본값과
`updateParams()`의 조건부 대입 모두 `1` 고정으로 바꿔, UI 필드를 없앤 뒤에도(그리고 이미
저장된 컴포지션의 과거 `cover` 값이 남아있어도) 항상 비율 유지로 렌더링되도록 이중으로
막았다. letterbox 폴백은 알파만 0으로 바꾸고 RGB(0,0,0)는 그대로 뒀다 — 알파가 0이면 RGB
값은 어차피 화면에 드러나지 않는다.

`effectRegistry.ts`에서 `fitMode` 필드를 제거해 UI에서 선택지가 사라졌고,
`ShaderLabViewport.tsx`는 캔버스 부모 컨테이너 배경을 `bg-[#0a0d10]` 단색에서
`repeating`형 다중 `linear-gradient` 체크보드(16px 타일, `#3a3a3a`/`#4d4d4d`)로 바꿨다.

### 주요 의사결정 / 핵심 메모

- **UI 필드 제거 + 렌더링 강제를 이중으로 처리한 이유**: `effectRegistry.ts`에서 필드를
  없애도, 이미 저장된 컴포지션 JSON에 과거 `params.fitMode: 'cover'`가 남아있으면 그 값이
  그대로 읽힌다. `media-pass.js` 쪽에서 UI 값과 무관하게 항상 1로 고정해 과거 데이터에도
  안전하게 적용되도록 했다.
- **letterbox 폴백에서 RGB는 그대로 두고 알파만 바꾼 이유**: 알파가 0이면 어차피 화면에
  드러나지 않으므로 RGB 값 자체를 바꿀 필요가 없다 — 최소 변경 원칙.
