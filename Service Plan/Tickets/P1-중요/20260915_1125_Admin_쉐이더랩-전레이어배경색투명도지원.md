# [Admin] 쉐이더 랩 — 리퀴드 메탈 외 배경색 필드 전체 알파 지원 추가

## 배경 / 문제 정의

리퀴드 메탈 레이어에서 이미지를 마스크로 올렸을 때 도형 바깥 영역이 흰색으로 나온다는 사용자
보고를 확인한 결과, 원인은 버그가 아니라 `colorBack`(배경 색상) 필드의 기본값이 불투명
(`#AAAAACFF`)이었기 때문이었다 — 알파 자체는 이미 지원되고 있었다(티켓 20260913_2110). 기본값을
`#AAAAAC00`(완전 투명)으로 바꾸는 것으로 이 건은 해결했다.

사용자가 "다른 레이어 프로퍼티에도 동일한 이슈를 확인해서 수정해달라"고 요청해, `effectRegistry.ts`
전체의 배경/채우기류 색상 필드를 전수 점검했다.

## 사전 조사 결과 (Explore 에이전트 위임 + 오케스트레이터 직접 검증)

`type: 'color'`이고 "그 레이어 전체 프레임을 채우는 베이스 색상"으로 쓰이는 필드(스트로크·잉크·
포인트 등 "그려지는 내용 자체의 색"은 제외) 6곳을 찾아 대응 렌더러 코드를 대조했다.

| 레이어 | 필드 | 기존 상태 | 결과 |
|---|---|---|---|
| `text` | `backgroundColor`+`backgroundAlpha`(별도 숫자 필드) | 알파 이미 반영됨(`text-pass.js`가 `globalAlpha`로 적용) | 정상, 범위 밖 |
| `ink` | `backgroundColor` | `alpha:true` 없음, 셰이더가 `float(1)` 하드코딩 | **버그, 수정** |
| `pattern`(custom) | `customBgColor` | 〃 | **버그, 수정** |
| `particle-grid` | `backgroundColor` | 〃(클리어 알파도 `1` 고정) | **버그, 수정** |
| `plotter` | `paperColor` | 〃 | **버그, 수정** |
| `edge-detect`(mono) | `bgColor` | 〃 | **버그, 수정** |

패턴이 그려지지 않는 "빈(gap) 영역"이 있는 5개 레이어 모두, 배경색의 알파를 조절할 UI 자체가
없었고(컬러 피커에 알파 슬라이더 없음), 설령 있었더라도 셰이더 최종 출력이 알파를
`float(1)`로 고정 반환해 무시했을 것이다.

### 추가로 실렌더 중 발견한 숨은 버그 — `ink-pass.js`의 별도 내부 머티리얼

`ink-pass.js`를 고친 뒤 로컬 실렌더로 검증했더니 알파가 여전히 255(불투명)로 나왔다. 원인은
`InkPass`가 `PassNode` 기본 생성자의 `this.material`(20260915_1042에서 이미
`alphaToCoverage=true` patch됨) 외에 **자체적으로 3개의 별도 `MeshBasicNodeMaterial`
(`blurMaterial`·`copyMaterial`·`compositeMaterial`)을 만들어 쓴다**는 데 있었다 — 이 셋은
그 patch 대상이 아니라서 three.js의 알파 강제 클로버링(`NodeMaterial.js:938`,
`isOpaque()`)을 그대로 맞는다. 최종 알파를 계산하는 `compositeMaterial`에도
`alphaToCoverage=true`를 추가해 해결했다(`blurMaterial`·`copyMaterial`은 그 알파가
다운스트림에서 읽히지 않아 그대로 둬도 무방).

이 패턴(전용 머티리얼을 추가로 만드는 레이어)이 다른 곳에도 있는지 `grep`으로 전수 확인했다
(`blob-tracking-pass.js`·`crt-pass.js`·`grid-render-pass.js`·`pixel-sorting-pass.js`·
`dual-filter-bloom.js`) — 이 티켓이 배경 알파를 추가하는 5개 레이어 중에는 `ink`만 해당했고,
나머지 레이어(그 목록에 없는 것들)는 이번 범위 밖(배경색 필드 자체가 없음)이라 손대지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 5개 pass 파일에서 배경/채우기 색상 저장소를 RGB(Vector3/개별 uniform 3개)에서 RGBA로
  확장하고, 파라미터 파싱이 8자리 hex(`#RRGGBBAA`)의 알파도 추출하도록 한다.
- 각 셰이더의 최종 `vec4` 반환에서, 패턴/라인/파티클이 "없는" 영역은 배경색 자신의 알파를,
  "있는" 영역은 항상 완전 불투명(1)을 쓰도록 마스크 기반으로 보간한다(기존 RGB `mix` 로직과
  동일한 마스크를 재사용).
- `effectRegistry.ts`의 대응 필드에 `alpha: true`를 추가하고 기본값을 완전 투명으로 바꾼다.
- **알려진 한계**: 블룸(bloom) 활성화 시 공용 `BloomCompositor`(`dual-filter-bloom.js`)가
  알파를 항상 1로 반환한다 — `ink`·`pattern`·`particle-grid` 모두 블룸 옵션이 있는데, 블룸을
  켜면 이번 수정이 적용되지 않는다. 이 티켓 범위 밖으로 남겨둔다(공용 컴포지터라 손대면 다른
  레이어 다수에 영향).

## 구현 계획

1. `ink-pass.js`: `backgroundColorUniform`을 Vector3→Vector4, 알파 파싱 헬퍼 추가,
   `buildCompositeNode()` 최종 알파를 마스크 보간으로, `buildEffectNode()` 비-블룸 분기가
   `finalInputNode.a`를 읽도록, `compositeMaterial`에 `alphaToCoverage=true` 추가.
2. `pattern-pass.js`: `customBgColorUniform`을 Vector3→Vector4, `customBgAlpha`를
   `patternMask`로 보간(원본/단색 배경은 범위 밖, 항상 불투명 유지).
3. `particle-grid-pass.js`: `bgAlpha` 필드 추가, `setClearColor`의 알파 인자에 사용,
   `buildEffectNode()`가 `blitInputNode.a`를 읽도록.
4. `plotter-pass.js`: `paperAlphaUniform` 추가, `combinedHatch`로 알파 보간.
5. `edge-detect-pass.js`: `bgAlphaUniform` 추가(mono 모드만), `finalEdge`로 알파 보간.
6. `effectRegistry.ts` 5곳에 `alpha: true` + 완전 투명 기본값.
7. `npx patch-package @basementstudio/shader-lab`, `npm install` 재적용성 확인.
8. 로컬 esbuild+실제 WebGPU 브라우저 실렌더로 5개 레이어 각각 배경 알파가 0일 때 빈 영역이
   투명하게 나오는지 확인.
9. `npx tsc --noEmit`, `npm run lint`.

### 주요 의사결정 / 핵심 메모

- **모든 레이어에 알파를 추가하지 않고 "배경/채우기" 성격의 필드만 골랐다**: 스트로크·잉크
  색상·포인트 색상처럼 "그려지는 내용 자체의 색"에 알파를 붙이면 그 레이어의 시각적 정체성이
  자체적으로 반투명해지는 것이라 의미가 다르다. 이번 원칙("스테이지는 항상 투명이어야 함")은
  "패턴/도형이 없는 빈 영역"에 한정된다.
- **블룸 활성화 시 알파가 반영되지 않는 한계를 의도적으로 남겼다**: `BloomCompositor`는
  `ink`·`pattern`·`particle-grid` 등 여러 레이어가 공유하는 컴포지터라, 여기서 알파를
  스레딩하려면 공용 코드를 건드려야 하고 회귀 범위가 커진다. 블룸을 끈 상태(기본값)에서는
  정상 동작하므로, 블룸+투명 배경을 동시에 쓰는 조합만 후속 과제로 남긴다.
- **`ink-pass.js`의 숨은 버그(전용 머티리얼)를 실렌더로만 발견했다**: 정적 코드 분석(Explore
  에이전트 조사)으로는 `compositeMaterial`이 `PassNode.material`과 다른 별도 인스턴스라는
  사실 자체는 확인됐지만, three.js의 `isOpaque()` 클로버링이 "해당 pass 전용 머티리얼
  각각"에 개별적으로 적용된다는 걸 실제 픽셀값을 찍어보기 전까지는 확신할 수 없었다. 20260915_1042
  때의 교훈(정적 분석만으로는 놓치는 지점이 있다)이 이번에도 똑같이 재현됐다.
