   축약), 빈 상태(empty state, §4.3, 에러와 구분해 원인·해결책을 붙이지 않음), 처리 중 상태의

   (20260915_2237) 도메인의 실제 대상 파일을 확인해 반영했다.
3. **톤 경계가 흐려지기 쉬운 지점 (§2.4 신설)**: 로딩→실패 전환, 빈 상태 vs 에러, 소셜 액션
   vs 되돌릴 수 없는 확정, VOC 안내 vs 확정 경고 4가지 혼동 지점을 명시적으로 구분했다.
   톤 매트릭스에 "빈 상태"·"VOC 접수·처리 안내" 2행을 추가했다(신규 톤 라벨 없이 기존

4. **Anti-slop 판단 기준 (§7 신설, 구 §7 적용 방법은 §8로 이동)**: `/im-not-ai` 전수검사가

   일반 한국어 유창성 규칙(`.claude/output-styles/fluent-korean.md`)과의 관계(이 절은 그 위에
   JAM! 특화분만 추가)를 명시했다.
5. 기존 §7(현 §8) 적용 방법의 자기모순 문장("기존 파일을 직접 수정하지 않고 ...를 직접
   수정한다")을 발견해 "버전 사본을 만들지 않고 이 파일을 직접 덮어써 갱신한다"로 정정했다.

### 주요 의사결정 / 핵심 메모
- **용어표·등급명 표는 그대로 유지**: 이미 예시·금지어·이력이 충분히 구체적이라 판단했다.
  재검토 결과 새 용어를 추가할 필요는 발견하지 못했다(하위 도메인 티켓이 작업 중 필요한
  용어를 §1.3 절차대로 직접 추가하게 될 것).
- **새 톤 라벨 신설을 최소화**: "빈 상태"는 새 톤이 아니라 기존 "담담·안내"의 적용 사례로
  분류했다("없어요"라는 담담한 사실 전달이라는 점에서 로딩 안내와 결이 같음). "VOC"만
  "차분·공감"이라는 새 라벨을 신설했다 — 기존 5개 톤 어디에도 "사용자가 이미 불편을 겪은
  상태에 공감하며 응대"하는 성격이 없었기 때문.
- **섹션 번호 재배치**: 기존 §7 "적용 방법"을 §8로 밀고 그 자리에 §7 "Anti-slop 판단 기준"을
  넣었다. §4는 하위 번호를 0)부터 시작(0=ADR 참조 원칙, 1=기존 3단계 구조, 2·3=신설)해 기존
  §4.1 표 내용을 그대로 보존하면서 원칙 절을 앞에 추가했다.
- **`/im-not-ai` 전수검사는 이 티켓에서 실행하지 않음**: 상위 스펙(20260915_2227)의 실행
  순서가 "①가이드 확정(선행) → ②전수검사·딕셔너리 편입 병행"이라 이 티켓은 ①에 해당한다.
  가이드 자체에 대한 전수검사는 CONTEXT.md 결정사항에 "`UX_WRITING_GUIDELINE.md` 문서 자체"도
  검사 대상이라 명시돼 있으나, 이는 가이드 확정 후 별도 단계로 보고 이 티켓에서 직접
  실행하지 않았다(가이드가 아직 하위 티켓들에 의해 계속 참조·보완될 살아있는 문서이기
  때문). 리뷰어가 이 판단에 동의하지 않으면 이 티켓 범위에 전수검사를 추가할 것을 제안한다.
