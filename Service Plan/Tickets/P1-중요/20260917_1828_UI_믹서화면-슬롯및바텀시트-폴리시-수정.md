# [UI] 믹서 화면 슬롯·바텀시트 폴리시 수정

## 배경 / 문제 정의

티켓 `20260917_1655`(믹스하기 화면 리뉴얼)로 staging에 반영된 화면을 실제 데이터로
확인한 뒤, 사용자가 세부 UI/상호작용 수정 12건을 요청했다. 큰 흐름(레시피 탐색 →
믹서 → 가방 시트 → 결과)은 그대로 두고, 슬롯 표현·상단 요약 영역·바텀시트 세부를
다듬는다.

## 상세 요구사항

### 레시피 탐색 목록 (믹스하기 진입 화면)

13. 지금 각 행에 있는 왼쪽 **배지 이미지 아이콘 스택을 제거**한다. 행에는 **레시피명과
    슬롯 개수만** 남긴다(`슬롯 N개` 형태 유지).
14. 지금 행 오른쪽에 있는 "+N P" 포인트 표시를 없애고, 그 자리에 **믹서 화면 요약 영역과
    동일한 조건별 보상 블록**(위 7번 항목과 같은 컴포넌트)을 노출한다:
    - 배지 + 포인트 둘 다 있으면: 배지 이미지 + 등급 칩 + 배지명 / (아이콘 없이)
      "xxx,xxx,xxx Point"
    - 배지만 있으면: 배지 이미지 + 등급 칩 + 배지명만
    - 포인트만 있으면: (아이콘 없이) "xxx,xxx,xxx Point"만
    - 이 보상 블록은 7번 항목(믹서 요약 영역)과 **같은 하위 컴포넌트를 공유**해서 두 곳에
      각각 다시 구현하지 않는다.

### 슬롯(`MixerSlot`, MODULAR 컴포넌트)

1. 빈 슬롯 중앙에는 **'+' 아이콘만** 표시한다. 지금 있는 타입 아이콘(🎒/⚡/📍류)과 후보
   배지 이름 텍스트는 제거한다.
2. 지금 채울 수 있는(후보 중 하나 이상 보유한) 슬롯은 **테두리를 컬러로** 표현해 잠긴
   슬롯과 구분한다. 색상은 기존 토큰 중 적절한 것을 쓴다(신규 색상 추가 지양).
3. 잠긴 슬롯의 배경에 있는 사선(빗금) 패턴을 제거한다. 잠김 표현은 불투명도만으로 충분하다.
11. 슬롯에 배지를 채웠을 때 우상단에 뜨는 'X' 제거 버튼의 **크기를 줄이고, 배경색을
    어두운 네거티브(다크)로** 바꾼다(지금은 밝은 배경).

### 상단 요약 영역 (믹서 화면)

5. "슬롯 N개" 텍스트 대신 **레시피 이름**을 노출한다(레시피에 표시용 이름 컬럼이 없다는
   이전 제약은 검색 매칭에만 해당 — 화면 표시용 이름을 어떻게 확보할지는 구현 단계에서
   정한다. 안 되면 이번 기회에 `combination_recipes.name` 컬럼 추가를 검토한다).
6. "다른 레시피" 링크를 제거한다. 레시피 전환은 **상단 `TopNav`의 뒤로가기 버튼**이
   담당한다 — 지금은 뒤로가기가 `/combine` 라우트를 벗어나는데, 믹서 화면에서는 먼저
   레시피 탐색(목록) 화면으로 돌아오고, 탐색 화면에서 다시 누르면 그때 라우트를 벗어난다.
7. "다른 레시피" 링크가 있던 자리에 **보상 정보**를 조건별로 다르게 노출한다:
   - 배지 + 포인트 둘 다 있으면: 배지 이미지 + 등급 칩(`RarityBadge`, MODULAR
     `components/cards/RarityBadge.jsx` 재사용) + 배지명, 그 옆에 (포인트 아이콘 없이)
     "xxx,xxx,xxx Point"
   - 배지만 있으면: 배지 이미지 + 등급 칩 + 배지명만
   - 포인트만 있으면: (아이콘 없이) "xxx,xxx,xxx Point"만
   - 보상 배지가 여러 개면 표시 방식은 구현 단계에서 정한다(예: 첫 번째만 대표로 노출 +
     "+N" 표기, 또는 가로 스크롤).
   - 이 보상 블록은 **레시피 탐색 목록의 각 행(아래 13·14번 항목)과 같은 컴포넌트를
     공유**한다. 둘 다 조건별 배지/포인트 표시가 필요해서다.
8. "믹스하기" CTA 버튼의 가로 폭을 줄인다 — 지금처럼 화면 전체 폭을 채우지 않는다.

### 가방 → "내 배지" 바텀시트

4. 슬롯을 탭하면 열리는 바텀시트를 수정한다:
   - 타이틀을 "가방"에서 **"내 배지"**로 바꾼다.
   - 시트의 상하좌우 여백을 **다른 바텀시트(레시피 관련이 아닌, 앱 내 기존 `BottomSheet`
     사용처)와 동일하게** 맞춘다 — 지금은 이 시트만 다른 패딩을 쓰고 있다.
9. 미보유 후보 배지의 이미지를 **그레이스케일**로 표시한다(미획득 배지를 다른 화면에서
   표시하는 기존 방식과 동일하게 — 예: 인벤토리/컬렉션 화면의 미획득 처리 참고).
10. 미보유 후보 배지 아래에 있는 **"필요" 텍스트를 제거**한다(그레이스케일 처리만으로
    미보유임을 표현).

### 레시피 전환 바텀시트 제거

12. "다른 레시피" 링크(및 그 링크가 열던 레시피 검색 바텀시트)를 제거하므로, **그
    바텀시트 자체(레시피 목록 + 검색 입력을 다시 보여주던 `switchSheetOpen` 관련 코드)를
    통째로 삭제**한다. 최초 진입 화면(탐색, 검색 입력 + 세로 목록)은 그대로 유지 — 이건
    레시피를 처음 고를 때 쓰는 화면이지 이번에 제거 대상인 "전환용 시트"가 아니다.

### 수용 기준

1. 빈 슬롯에 '+' 아이콘만 보이고, 채울 수 있는 슬롯은 테두리 색으로 구분된다.
2. 잠긴 슬롯에 사선 패턴이 없다.
3. 슬롯 탭 시 열리는 시트 제목이 "내 배지"이고, 여백이 앱 내 다른 시트와 일치한다.
4. 상단 요약 영역에 "슬롯 N개" 대신 레시피 이름이 보이고, 그 옆에 조건별 보상 정보가
   보인다(배지+포인트/배지만/포인트만 3가지 케이스 확인).
5. "다른 레시피" 링크와 그 전환 시트가 화면에서 사라졌고, 뒤로가기를 누르면 믹서 →
   레시피 탐색 → (그다음 뒤로가기에서) 라우트 이탈 순서로 동작한다.
6. "믹스하기" 버튼이 전체 폭을 채우지 않는다.
7. 시트의 미보유 배지가 그레이스케일로 보이고 "필요" 텍스트가 없다.
8. 채운 슬롯의 제거 버튼이 더 작고 어두운 배경으로 보인다.
9. 레시피 탐색 목록의 각 행에 배지 아이콘 스택이 없고, 레시피명·슬롯 개수만 보인다.
10. 레시피 탐색 목록 각 행에 조건별 보상 블록이 보이고, 믹서 요약 영역의 보상 블록과
    같은 컴포넌트를 재사용한다(둘 다 같은 코드 수정으로 함께 바뀌는지 확인).

### 롤백 계획
클라이언트 화면·MixerSlot 컴포넌트 변경 위주. `combination_recipes.name` 컬럼을 추가하게
되면 별도 마이그레이션 롤백 계획을 그때 세운다(현재 레시피 10건은 테스트 데이터라 영향
적음).

### 주요 의사결정 / 핵심 메모
- `combination_recipes.name`은 NOT NULL로 강제하지 않고 nullable로 추가했다 — 기존
  10건(테스트 데이터)에 이름이 없어 백필이 필요한데, 이번 티켓 범위가 아니라고 판단.
  어드민 폼은 클라이언트 검증으로 신규/수정 시 이름을 필수로 요구한다.
- 보상 배지가 여러 개일 때는 대표(첫 번째) 배지 + "+N" 표기로 정했다(티켓이 "구현
  단계에서 정한다"고 위임한 부분) — 현재 실데이터(레시피 10건)는 보상 배지가 최대
  1개라 이 분기는 시각적으로 검증되지 않았다.
- 레시피 전환(TopNav 뒤로가기가 믹서→탐색→라우트 이탈 순으로 동작하는 것)은 선행
  티켓 20260917_1655에서 이미 구현돼 있어 이번 티켓에서 추가 변경이 필요 없었다 —
  "다른 레시피" 링크·전환 시트만 제거하면 요구사항 6·5가 그대로 충족됨을 확인.

### 잔여 이슈
- `combination_recipes.name`이 NULL인 기존 레시피 10건은 화면에 "이름 없는 레시피"로
  노출된다 — 어드민에서 실제 이름으로 채워 넣는 작업은 이 티켓 범위 밖.
