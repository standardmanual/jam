## 상세 요구사항

### ① 실패 테스트 13건 정리
`src/lib/__tests__/badgeProgressText.test.ts`에서 13건이 실패한다(2026-09-18 실측, 전체 1,509건 중).
원인은 기능 오류가 아니라 **화면 문구를 바꾸면서 테스트 기대값을 갱신하지 않은 것**이다.

| 테스트 기대값 | 실제 문구 |
|---|---|
| 진행 표시 준비 중 | 진행률을 표시할 수 없어요 |
| 직전 동기화보다 누적 거리 1.3km 가까워졌어요 | 지난번보다 누적 거리 기록이 1.3km 가까워졌어요 |
| …채워도 돼요. (마침표) | …채워도 돼요 |

- 현재 문구가 UX 라이팅 가이드 기준으로 맞는지 먼저 확인한다
- 맞으면 테스트 기대값을 현재 문구로 갱신한다
- 틀리면 문구를 고치고 테스트는 그대로 둔다
- 판단이 갈리는 문구는 사용자에게 확인한다

### ② 오래된 작업 공간 정리
`.claude/worktrees/`에 워크트리가 다수 남아 있고, 각각 `jam-web/node_modules`를 따로 갖고 있다.

- 미커밋 변경이 없는 워크트리만 제거한다 (`git status --short` 확인 후 `git worktree remove`)
- 미커밋 변경이 있으면 손대지 말고 보고한다
- 제거 전후 디스크 사용량을 기록한다

### ③ 기준선 기록
도입 전후를 비교할 수 있도록 최근 티켓 2~3건의 소요 시간과 사용량을 완료 기록에 남긴다.
(측정이 어려우면 티켓별 커밋 시각 간격·에이전트 호출 수 등 가능한 지표로 대체)

`badgeProgressText.test.ts`의 13건 실패를 전부 대조했다. 13건 모두 **테스트가 낡은 것**으로

기준으로 이미 검토·확정한 값이었고(마침표 규칙 §3, 공급자 언어 §1.1), 그 티켓이 `ko.ts`의

(HALT 없음).

세부 대조:
- `dualAxisRuleSame`/`Different`/`dualAxisBottleneckNote`(3건): 한 문장 본문 → §3 "본문(한 문장)은
  마침표 없음" 규칙에 따라 마침표 없는 현재 문구가 맞다. 테스트가 마침표를 기대하고 있었다 →
  테스트 기대값에서 마침표 제거.
- `regretLinePace`/`regretLineGeneral`(2건): 티켓 20260916_0734가 "명사로 끊긴 문장"을
  "...였어요. ...모자랐어요."의 완성 두 문장으로 교정한 것 — §3 "본문(두 줄 이상)은 정확히
  마침표 사용"에 부합. 테스트가 교정 전 옛 표현을 기대하고 있었다 → 테스트 기대값을 현재
  완성 문장으로 갱신.
- `progressUnsupported`(3건: `formatFrontierProgressText` 2곳, `formatStampCaption` 1곳): "진행
  표시 준비 중"(내부 용어 "진행 표시" 노출) → "진행률을 표시할 수 없어요"(사용자 시점)로
  교체된 것이 §1.1 공급자 언어 원칙에 부합. 테스트가 옛 문구를 기대하고 있었다 → 테스트
  기대값 갱신(설명 텍스트도 함께 갱신).
- `syncComparisonPace`/`syncComparisonGeneral`(5건): "직전 동기화보다"(시스템 이벤트 시점) →
  "지난번보다"(사용자 시점, §1.2)로, 목적어 누락을 "기록이"로 보완한 것이 가이드에 부합.
  테스트가 옛 시스템 시점 문구를 기대하고 있었다 → 테스트 기대값 갱신.
