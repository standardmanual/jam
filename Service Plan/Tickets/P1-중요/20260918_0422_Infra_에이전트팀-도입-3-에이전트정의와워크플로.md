### ② `progressive-reviewer` 삭제
개선 리뷰 단계는 두지 않는다. 위험을 줄이는 개선점은 민지의 범위 밖 발견물로 처리한다.

### ③ `jam-work.js` 수정
```
전: 구현 → 게이트 → [개선 · 인터페이스 · 한국어]
후: 채원① 사전 판정 → 구현 → 게이트 → [채원② 사후 리뷰 · 한국어]
```
- 개선 리뷰 단계와 "15줄 미만 개선 리뷰 생략" 조건 제거
- 인터페이스 리뷰(general-purpose + 외부 스킬 5종) → 채원② 로 교체
- 아현의 새 반환 상태 `plan_only`·`needs_design`을 받아 멈추도록 처리
- 채원② 의 중대 문제 판정을 재작업으로 연결

### ④ 스킬 문서 수정
- `/jam-work`: 1.5·1.6단계(재사용 판정·연결 범위)를 채원으로 이관, 개선 리뷰 관련 내용 삭제
- `/jam-design`: "개선 리뷰가 승격 후보 제안" → "채원② 가 제안"
- `jam-web/CLAUDE.md`: "UI를 만들기 전에 직접 탐색한다" → "채원의 판정을 따른다"
- 루트 `CLAUDE.md`: 카리나 전용 내용(PC 경로·동기화·DB 권한)을 참고 문서로 이동

### ⑤ 스킬·커맨드 정리
- 디자인 커맨드 4개(`ui-audit`·`design-system-review`·`accessibility-check`·`refactor-ui`) 삭제 → 채원 모드로 흡수
- 외부 스킬 5종 심볼릭 링크(`better-*`·`interface-review`, 총 60KB) 제거 → 채원용 JAM 전용 점검표 1~2쪽 작성
- 신규 스킬 `/jam-plan`(혜린), `/jam-story`(윈터·윤진 협업) 작성

## 진행 기록

### CLAUDE.md 제외 요구사항 — 포기 (2026-09-18, 사용자 결정)
①번 요구사항 중 6개 에이전트의 "CLAUDE.md 제외"는 **기술적으로 불가능함을 확인해 포기했다.**

- 조사 결과: `.claude/agents/*.md`의 공식 frontmatter 키는 `name`·`description`·`tools`·
  `disallowedTools`·`model`·`permissionMode`·`skills`·`memory`·`maxTurns`·`isolation` 뿐이며,
  프로젝트 CLAUDE.md 자동 주입을 제어하는 키는 존재하지 않는다(Claude Code 공식 문서 확인).
- jam-developer가 처음 구현에서 남긴 `# CLAUDE.md: excluded` YAML 주석은 실제로는 아무 기능이
  없는 장식이었다 — 오케스트레이터가 review 브랜치에서 6개 파일(`jam-designer`·`jam-pm`·
  `jam-tribe`·`jam-marketer`·`jam-ops`·`jam-guide`)의 해당 주석을 제거했다.
- 루트 `CLAUDE.md`의 "CLAUDE.md는 아현·민지에게만 들어간다"는 문구도 사실과 달라 정정했다 —
  실제로는 8개 에이전트 전부가 CLAUDE.md를 받는다.
- 대체 방법(Read 도구 제한으로 간접 차단, `.claude/agents/` 대신 인라인 호출 전환)은 이번
  범위에서는 적용하지 않는다 — 전자는 효과가 불확실하고 후자는 서브에이전트 구조 자체를 바꾸는
  더 큰 변경이라 별도 검토가 필요하다.
- 토큰 절감(호출당 약 8.4KB) 목표는 이번 시리즈에서는 달성하지 못한다.
