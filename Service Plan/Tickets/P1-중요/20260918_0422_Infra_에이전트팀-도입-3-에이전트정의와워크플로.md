# [Infra] 에이전트 팀 도입 ③: 에이전트 정의와 워크플로

## 배경 / 문제 정의
도입의 핵심이다. 에이전트 정의 문장 하나가 이후 모든 작업의 품질을 좌우한다.
**이 티켓만 Opus로 진행하길 권한다.**

설계 원본: `~/Library/Mobile Documents/com~apple~CloudDocs/파일/Work/StandardManual/JAM-WORK/agents/`
(한국어 R&R 9개 문서. 이 티켓에서 **영어 정의로 옮겨 쓴다**)

## 상세 요구사항

### ① 에이전트 정의 8개 작성 (영어, `.claude/agents/`)
| 이름 | 파일명 | 모델 | CLAUDE.md |
|---|---|---|---|
| 아현 (개발) | `jam-developer` (기존 수정) | sonnet | 포함 |
| 민지 (판정 리뷰) | `conservative-reviewer` (기존 수정) | sonnet | 포함 |
| 채원 (디자인) | `jam-designer` | 모드별 (sonnet/haiku) | 제외 |
| 혜린 (PM) | `jam-pm` | sonnet | 제외 |
| 윈터 (세계관) | `jam-tribe` | 모드별 (opus/sonnet/haiku) | 제외 |
| 윤진 (마케팅) | `jam-marketer` | sonnet | 제외 |
| 카즈하 (운영·리스크) | `jam-ops` | haiku/sonnet | 제외 |
| 하니 (문서 체계) | `jam-guide` | haiku | 제외 |

- 정의는 **영어**, 출력은 한국어 (프로젝트 절대 규칙 1번 유지)
- 각 정의에 `model` 고정, CLAUDE.md 제외 설정
- 이상 신호는 **참고 / 주의 / 중단**, 확신도는 **높음 / 보통 / 낮음** (한국어 유지)
- 긴 절차 설명은 참고 문서로 빼고 정의에는 원칙·금지·형식만 남긴다

### ② `progressive-reviewer` 삭제
개선 리뷰 단계는 두지 않는다. 위험을 줄이는 개선점은 민지의 범위 밖 발견물로 처리한다.

### ③ `jam-work.js` 수정
```
전: 구현 → 게이트 → [개선 · 인터페이스 · 한국어]
후: 채원① 사전 판정 → 구현 → 게이트 → [채원② 사후 리뷰 · 한국어]
```
- 개선 리뷰 단계와 "15줄 미만 개선 리뷰 생략" 조건 제거
- 인터페이스 리뷰(general-purpose + 외부 스킬 5종) → 채원② 로 교체
- 아현의 새 반환 상태 `plan_only`·`needs_design`을 받아 멈추도록 처리
- 채원② 의 중대 문제 판정을 재작업으로 연결

### ④ 스킬 문서 수정
- `/jam-work`: 1.5·1.6단계(재사용 판정·연결 범위)를 채원으로 이관, 개선 리뷰 관련 내용 삭제
- `/jam-design`: "개선 리뷰가 승격 후보 제안" → "채원② 가 제안"
- `jam-web/CLAUDE.md`: "UI를 만들기 전에 직접 탐색한다" → "채원의 판정을 따른다"
- 루트 `CLAUDE.md`: 카리나 전용 내용(PC 경로·동기화·DB 권한)을 참고 문서로 이동

### ⑤ 스킬·커맨드 정리
- 디자인 커맨드 4개(`ui-audit`·`design-system-review`·`accessibility-check`·`refactor-ui`) 삭제 → 채원 모드로 흡수
- 외부 스킬 5종 심볼릭 링크(`better-*`·`interface-review`, 총 60KB) 제거 → 채원용 JAM 전용 점검표 1~2쪽 작성
- 신규 스킬 `/jam-plan`(혜린), `/jam-story`(윈터·윤진 협업) 작성

## 구현 계획
1. JAM-WORK의 한국어 R&R 9개를 읽고 영어 정의로 옮긴다
2. 기존 2개 수정 → 신규 6개 작성 → `progressive-reviewer` 삭제
3. `jam-work.js` 파이프라인 수정
4. 스킬 문서 수정 → 커맨드·링크 정리 → 신규 스킬 2개
5. 간단한 티켓 하나로 파이프라인이 끝까지 도는지 확인

## 완료 조건
- 에이전트 8개가 각각 지정한 모델로 실제 호출된다
- `ui` 유형 티켓 하나가 채원① → 아현 → 민지 → 채원② 순서로 끝까지 돈다
- 삭제한 커맨드·스킬을 참조하는 곳이 남아 있지 않다
- 외부 폴더(`~/.agents/skills`)에 의존하는 경로가 없다
