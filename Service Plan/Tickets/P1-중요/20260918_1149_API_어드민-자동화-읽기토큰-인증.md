# [API] 어드민 자동화 전용 읽기 토큰 인증

## 핵심 요약
- 요구사항: 클라우드 예약 작업이 어드민 API를 읽을 수 있도록 GET만 허용하는 자동화 토큰 인증 경로를 추가한다.
- 구현 계획: `auth.ts`에 토큰 검사 경로를 추가하고 `admin-api-read.mjs`가 토큰으로 호출하게 한다.
- 관련 파일: `jam-web/src/lib/admin/auth.ts`, `scripts/admin-api-read.mjs`
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 없음
- 경로: ③ 표준 (api 유형이라 채원 없이 아현→민지)

## 배경 / 문제 정의
지금 어드민 API 인증은 브라우저에서 복사한 로그인 쿠키뿐이다. `getAdminUser()`는 관리자 세션이면 쓰기까지 모두 허용하므로 클라우드에 맡길 수 없고, 쿠키가 만료되면 조용히 실패한다(상위 티켓 4-5).

## 상세 요구사항

### 서비스/코드베이스 관점
- 환경변수의 토큰과 요청 헤더의 토큰이 일치하면 **GET 요청만** 통과시킨다. POST·PUT·PATCH·DELETE는 토큰으로 통과하지 못한다
- 토큰은 만료가 없고, 환경변수 값을 바꾸면 즉시 이전 토큰이 차단된다
- 토큰 비교는 타이밍 공격에 안전한 방식으로 한다
- 어드민 API 경유 원칙(권한 검사)을 유지한다. DB 직접 접근 경로는 만들지 않는다
- `admin-api-read.mjs`는 토큰 환경변수가 있으면 토큰으로, 없으면 기존 쿠키 방식으로 호출한다

## 구현 계획
토큰 경로는 기존 관리자 세션 검사와 분리된 함수로 두고, 읽기 라우트에서만 쓰도록 한다.

## 완료 기록 *(2026-09-18)*

### 구현 내용 요약
- `auth.ts`에 상수시간 비교(순수 JS — `proxy.ts`가 Edge 런타임이라 `node:crypto` 사용 불가), `isValidAdminReadToken`,
  `requireAdminRead(req)`를 추가했다. `requireAdmin()` 본체는 수정하지 않았다
- `requireAdminRead`는 GET + 유효한 `x-admin-read-token` 헤더일 때만 통과시키고, 그 외에는 `requireAdmin()`으로 폴백한다
- `proxy.ts`는 `GET /api/admin/*` + 유효 토큰이면 로그인 리다이렉트를 건너뛴다. 최종 인증은 라우트가 다시 검사한다
- 읽기 라우트 5곳(missions·badges·users·drop-policy·badge-metric-labels)의 GET 핸들러만 교체했다
- `admin-api-read.mjs`는 `ADMIN_API_READ_TOKEN`이 있으면 토큰 헤더, 없으면 기존 `ADMIN_API_COOKIE` 방식으로 호출한다
