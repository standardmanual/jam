# [Infra] 기획·운영 문서를 jam-doc 저장소로 분리하고 폴더명을 영문 소문자로 정리

## 핵심 요약

- 요구사항: Vercel로 배포되는 코드와 그 코드가 따라야 할 스펙·작업 이력은 `standardmanual/jam`에,
  기획·마케팅·운영 자료와 제작 자산은 새 저장소 `standardmanual/jam-doc`에 둔다. 두 저장소의
  폴더명은 영문 소문자로 바꾼다.
- 구현 계획: `git filter-repo`로 옮길 경로를 이력째 추출해 `jam-doc`에 푸시하고, `jam`에서는 추적을
  해제한 뒤 `Service Plan/` → `docs/`로 이름을 바꾼다. 경로 참조와 자동화(훅·스크립트·스킬·예약
  작업·CLAUDE.md)를 새 경로로 갱신한다.
- 관련 파일: `.githooks/pre-commit`, `scripts/check-slop.mjs`, `scripts/ticket-dashboard.mjs`,
  `scripts/verify.sh`, `.claude/settings.json`(세션 시작 훅), `.claude/skills/jam-docs/SKILL.md`,
  `.claude/skills/jam-sync/SKILL.md`, `.claude/skills/jam-work/references/scheduled-jobs.md`,
  `.claude/workflows/jam-work.js`, `CLAUDE.md`, `.gitignore`

## 배경 / 문제 정의

- 출시 후 운영 자료(CS·장애 기록·캠페인·지표 리포트)가 가장 빠르게 늘어날 텐데, 지금은 모든 문서가
  코드 저장소 안 `Service Plan/`에 섞여 있다.
- 최근 staging 커밋 50개 중 45개가 `jam-web`을 건드리지 않았다. 코드 저장소 이력의 90%가 문서 커밋이다.
- git 추적 용량의 80%가 `Service Plan/Assets`(504MB, 배지 이미지 제작물)이고, Vercel은 빌드마다 이
  용량을 함께 받아 간다(`jam-web`은 116MB).

## 상세 요구사항

### 경계 판단 기준

"Vercel에 배포되는 코드와 같은 커밋 안에서 함께 바뀌어야 하는가." 그렇다면 `jam`, 아니면 `jam-doc`.

## 구현 계획

0. 준비: 복구 지점 태그 `pre-docs-split-20260918` 생성
