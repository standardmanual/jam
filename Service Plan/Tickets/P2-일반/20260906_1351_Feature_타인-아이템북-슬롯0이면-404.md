# [Feature] 타인의 아이템북을 열 때 그 사람 슬롯이 0이면 아이템북 자체가 404가 된다

## 배경 / 문제 정의

`jam-web/src/app/(main)/collections/[id]/page.tsx:169`

```ts
if (!isOwnBook && slots.length === 0) notFound()
```

**다른 유저 기준(`?u={username}`)으로 아이템북을 열었을 때 그 유저가 채운 슬롯이 하나도 없으면
아이템북 페이지 자체가 404가 된다.** 실측으로 확인됐다 — 슬롯 없는 북을 `?u=jamfather`로
열면 404다.

티켓 `20260906_1312` 게이트 리뷰가 범위 밖 발견물로 보고했다. **기존 동작이고 그 티켓의
변경과는 무관하다.**

### 왜 문제로 보는가

**프로필에서 넘어온 링크가 404로 보일 수 있다.** 사용자 입장에서는 "존재하는 아이템북"인데
"없는 페이지"라는 답을 받는다. 아이템북 자체는 실재하고, 없는 것은 **그 사람의 수집 기록**뿐이다.

「아직 아무것도 모으지 않았어요」에 해당하는 상태를 **404로 표현한 것**이라, 빈 상태(empty state)로
바꾸는 편이 사용자에게 정확하다.

## 상세 요구사항

### 판단이 먼저 필요하다 — 의도된 동작일 수 있다

**이 줄이 왜 들어갔는지부터 확인할 것.** 프라이버시 의도였을 가능성이 있다:

> "남이 안 모은 아이템북을 들여다보게 하지 않는다"

만약 그렇다면 **404가 의도된 설계**이고 이 티켓은 「기존 유지」로 닫아야 한다.
`git log -S "isOwnBook && slots.length === 0"`와 관련 티켓을 먼저 뒤질 것.

**의도가 확인되지 않으면 사용자에게 묻는다.** 임의로 바꾸지 말 것 —
타인 프로필 노출 범위는 정책 사안이다.

### 서비스/코드베이스 관점 (바꾸기로 결정된 경우)

- `notFound()` 대신 **빈 상태**를 렌더한다
- 문구는 `Specs/UX_WRITING_GUIDELINE.md`를 따른다. 「아직 ~하지 않았어요」 계열이 기존
  빈 상태와 일관된다 — **새 톤을 만들지 말 것**
- 자기 북(`isOwnBook`)의 빈 상태가 이미 있다면 **그것을 재사용**하고, 주어만 바꾼다
- `readOnly` 모드에서 수집 유도 CTA가 뜨면 안 된다 — 남의 북이다

### UI/UX 관점

- 빈 상태에서도 **아이템북 이름·세계관 등 북 자체의 정보는 보여야 한다**.
  그게 404와 빈 상태를 가르는 지점이다
- 프로필로 돌아가는 경로가 막히지 않아야 한다

### 컨텐츠 관점

빈 상태 문구가 새로 필요하다면 UX Writing 검증 대상이다.

## 구현 계획

1. **`git log -S`로 이 줄의 도입 경위와 관련 티켓 확인** → 의도된 것인지 판정
2. 의도된 것이면 「기존 유지」로 티켓을 닫고 **근거를 코드 주석에 남긴다**
   (다음 사람이 또 결함으로 착각하지 않도록)
3. 아니면 빈 상태로 전환 + 기존 빈 상태 재사용

### 범위 밖

- 타인 프로필의 다른 노출 범위 정책
- 아이템북 목록 화면

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
**판정: 의도된 동작 확인 — 코드 변경 없음(주석 보강만), 「기존 유지」.**

`git log -S "slots.length === 0" -- jam-web/src/app/(main)/collections/[id]/page.tsx`로
도입 경위를 추적한 결과, 이 줄은 우발적 부작용이 아니라 티켓 `20260824_016`(CLOSED)에서
사용자가 명시적으로 확정한 정책이다.

- 원래 문제: 아이템배지를 인벤토리에 보유만 하고 슬롯에는 넣지 않은 경우("보유·미슬롯"),
  타인 `readOnly` 열람 화면에서 "슬롯 완료" 배지와 시각적으로 거의 구분되지 않는 표시 버그가
  있었다(`SlotGrid.tsx`가 `opacity-70`만 적용하고 `BadgeGridCard`에 `earned`를 넘기지 않아
  기본값으로 컬러 렌더링됨).
- 해결 방향: 그 표시 버그를 직접 고치는 대신, "아이템배지 슬롯이 0개인 컬렉션은 타인에게
  아예 노출하지 않는다"는 정책으로 우회 해결하기로 **사용자가 명시적으로 확정**했다
  (목록·상세 페이지 양쪽 동일 적용, "그냥 안 보이면 됨" — 별도 안내 문구 불필요라고 확정,
  상세 직접 URL 접근 시 기존 `notFound()` 패턴을 그대로 쓰기로 확정).
- 본인 열람(`isOwnBook`)은 이 정책과 무관하게 항상 노출되며, 본인 화면의 "보유·미슬롯"
  구분 표시는 같은 티켓 2차 작업(`SlotGrid.tsx`의 `earned={isSlotted}` 전달)으로 근본
  수정됐다.

따라서 이번 티켓이 지적한 "슬롯 0개면 아이템북 상세가 404가 된다"는 현상은 **버그가 아니라
설계된 접근 제어**이며, 프로필에서 넘어온 링크가 404로 보이는 것도 이 정책의 의도된 결과다
(그 사람이 공개할 만한 수집 기록이 없는 컬렉션은 상세 자체를 감춤). 티켓 요구사항에 따라
코드를 변경하지 않고, 다음 사람이 다시 결함으로 오인하지 않도록 `page.tsx:169` 위에
근거·출처(20260824_016)를 명시한 주석을 보강했다.
