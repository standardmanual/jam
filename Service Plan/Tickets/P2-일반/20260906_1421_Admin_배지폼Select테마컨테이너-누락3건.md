# [Admin] 배지 폼 Select 3종(희귀도·트라이브·컬렉션)에 테마 포털 컨테이너 누락

> 어드민 배지 생성/수정/상세 화면 구성 점검(2026-09-06) 중 발견. 관련: `20260906_1420`·`20260906_1422`·`20260906_1423`·`20260906_1424`

## 배경 / 문제 정의

`jam-web/src/components/admin/ui/select.tsx` 73-78행 주석에 따르면, `SelectContent`의
`container` prop은 Radix Portal이 `[data-admin-theme]` 스코프 밖(기본값 `document.body`)에
렌더링되는 문제를 막기 위한 것이다. 지금은 `SelectContent`가 시맨틱 토큰이 아니라
`bg-white`·`text-neutral-900` 같은 하드코딩된 색을 쓰고 있어 **당장은 시각적으로 티가 나지
않지만**, 이 prop을 지정해두는 것은 "select.tsx가 향후 시맨틱 토큰으로 전환될 때"를 대비한
선제 조치라고 명시돼 있다(`BadgeForm.tsx` 102-108행 주석 — "4b~4d에서 select.tsx가
시맨틱 토큰으로 전환될 때 테마 색이 정상 적용된다").

`jam-web/src/app/admin/badges/BadgeForm.tsx` 안에서 실제로 이 관례가 지켜지는지 확인한
결과, 같은 파일 안에서도 지켜진 곳과 빠진 곳이 갈렸다:

| Select | container prop | 위치 |
|---|---|---|
| 타입 | ✅ 있음 | 595-604행 |
| 배지 종류(등급형/레벨형) | ✅ 있음 | 612-624행 |
| **희귀도** | ❌ 없음 | **646-656행** |
| **소속 트라이브** | ❌ 없음 | **684-698행** |
| **소속 컬렉션** | ❌ 없음 | **701-717행** |
| 지점 카테고리 | ✅ 있음 | 727-740행 |

희귀도·트라이브·컬렉션 Select만 빠져 있다. 새 Select를 추가하면서 기존 관례를 놓친 것으로
보인다 — 지금 당장 눈에 보이는 결함은 아니지만, select.tsx가 시맨틱 토큰으로 전환되는
순간 이 3개만 조용히 테마가 깨진다(다른 어드민 Select는 이미 전환에 대비돼 있는데
이 3개만 그렇지 않아서).

## 상세 요구사항

### 서비스/코드베이스 관점
- `BadgeForm.tsx`의 희귀도(646-656행)·소속 트라이브(684-698행)·소속 컬렉션(701-717행)
  `SelectContent`에 `container={themeContainer ?? undefined}`를 추가해 파일 내 다른
  Select들과 동일한 패턴으로 맞춘다
- **같은 문제가 다른 어드민 폼에도 있는지 함께 확인할 것** — `FactionForm.tsx`·
  `ItemBookForm.tsx` 등 같은 `themeContainer` 패턴(`sidebar.tsx` 최초 도입, `20260826_016`)을
  쓰는 다른 폼에서도 `grep -n "SelectContent" <파일>`로 `container` prop 누락 여부를 전수
  확인 — 이번 점검은 `BadgeForm.tsx`만 봤다

### UI/UX 관점 (해당 시)
- 지금은 시각적 차이가 없어야 정상이다(`select.tsx`가 아직 하드코딩 색을 쓰므로) — 수정
  후에도 화면이 달라 보이지 않는 것을 확인하는 것 자체가 회귀 테스트다

### 컨텐츠 관점 (해당 시)

## 구현 계획

1. `BadgeForm.tsx` 3곳에 `container` prop 추가
2. `grep -n "SelectContent" jam-web/src/app/admin/**/*.tsx`로 다른 폼의 누락 여부 전수 확인,
   있으면 같은 티켓에서 함께 고친다
3. 어드민 로그인 후 배지 등록/수정 화면에서 희귀도·트라이브·컬렉션 드롭다운을 열어 이전과
   동일하게 보이는지 육안 확인(회귀 없음 확인)

  정리일 뿐, 전환은 다루지 않는다
