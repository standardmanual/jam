# [Admin] 패치 가격(patch_price_krw)에 음수 방지 가드 누락

> 어드민 배지 생성/수정/상세 화면 구성 점검(2026-09-06) 중 발견. 관련: `20260906_1420`·`20260906_1421`·`20260906_1422`·`20260906_1423`

## 배경 / 문제 정의

`jam-web/src/app/admin/badges/BadgeForm.tsx`에서 포인트 보상(`point_reward`)과 패치 가격
(`patch_price_krw`)은 성격이 비슷한 "원화/포인트 숫자 입력" 필드인데 검증 수준이 다르다.

**포인트 보상**은 클라이언트(352행 `Math.max(0, parseInt(pointReward, 10) || 0)`)와 서버
양쪽에서 음수를 막는다 —
`jam-web/src/app/api/admin/badges/route.ts` 112행(POST),
`jam-web/src/app/api/admin/badges/[id]/route.ts` 83-86행(PUT) 모두
`Math.max(0, Math.trunc(Number(...) || 0))`.

**패치 가격**은 입력 UI(876-882행)에 `min` 속성도 없고, 클라이언트(340-341행:
`patchAvailable && patchPriceKrw ? parseInt(patchPriceKrw, 10) : null`)도 서버도 음수를
막지 않는다 —
`route.ts` 100행(POST): `patch_price_krw: patch_price_krw ?? null`,
`[id]/route.ts` 71행(PUT): `patch_price_krw: body.patch_price_krw !== undefined ? body.patch_price_krw : existing.patch_price_krw`.

지금 상태로는 어드민이 실수로 음수를 입력하면(또는 API를 직접 호출하면) 음수 패치 가격이
그대로 저장된다. 서비스 화면에서 이 값을 어떻게 렌더링하는지는 이번 점검 범위 밖이지만,
저장 단계에서부터 막아두는 게 다른 숫자 필드들과 일관된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `BadgeForm.tsx` 입력 UI에 `min="0"` 추가(포인트 보상 입력과 동일하게)
- `BadgeForm.tsx` 저장 로직에서 `patch_price_krw` 계산 시 `point_reward`와 동일한 패턴으로
  `Math.max(0, ...)` 적용
- `api/admin/badges/route.ts`(POST)·`api/admin/badges/[id]/route.ts`(PUT) 양쪽에서
  `patch_price_krw`를 `point_reward`와 동일하게 `Math.max(0, Math.trunc(Number(...) || 0))`로
  정규화 — 단, `patch_price_krw`는 `patch_available=false`일 때 `null`이 허용되는 필드이므로
  `point_reward`(항상 0 이상 정수)와 달리 **null 허용은 유지**한 채 값이 있을 때만 음수 방지
  적용할 것 (값이 없으면(`null`/`undefined`) 그대로 null 유지)

### UI/UX 관점 (해당 시)
- 에러 메시지를 새로 추가할지, 조용히 0으로 클램프할지는 `point_reward`가 택한 방식(조용히
  클램프)과 통일 — 별도 판단 불필요, 기존 패턴을 그대로 따른다

### 컨텐츠 관점 (해당 시)
해당 없음.

## 구현 계획

1. `BadgeForm.tsx` 입력 UI + 저장 로직 수정
2. POST/PUT 라우트 양쪽에 `Math.max(0, ...)` 정규화 추가 (null 허용 유지)
3. 회귀 확인: 음수 입력 시 0(또는 클램프된 양수)으로 저장되는지, `patch_available=false`일
   때 여전히 `null`로 저장되는지 두 케이스 확인

### 범위 밖
- 서비스(비-어드민) 화면에서 `patch_price_krw` 렌더링 방식 — 이번 점검 범위가 아님

### 구현 내용 요약
`patch_price_krw`에 `point_reward`와 동일한 음수 방지 패턴을 클라이언트·서버 양쪽에 적용했다.
- `BadgeForm.tsx` 입력 UI에 `min="0"` 추가, 저장 로직에서
  `Math.max(0, parseInt(patchPriceKrw, 10) || 0)`로 클램프 (값이 있을 때만 적용, 없으면 여전히 `null`)

  값이 있으면 `Math.max(0, Math.trunc(Number(...) || 0))`로 정규화
