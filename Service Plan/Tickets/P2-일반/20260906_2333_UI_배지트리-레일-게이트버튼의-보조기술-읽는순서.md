# [UI] 배지 트리 레일 게이트 버튼이 눈금보다 먼저 읽힌다

## 배경 / 문제 정의

티켓 20260906_2140이 레일을 「눈금 그리드 + 연결선 절대배치 레이어」로 재구성하면서,
게이트 자물쇠 버튼이 **DOM에서 눈금 그리드보다 앞선 레이어 안**에 들어갔다.
그래서 보조기술이 **눈금 4개보다 먼저** 자물쇠를 읽는다 — 시각 순서(눈금1 → 자물쇠 → 눈금2)와
어긋난다.

**이전보다는 나아진 상태다.** 예전 구조는 연결선 span에 `aria-hidden="true"`가 걸려 있어
**그 안의 자물쇠 버튼이 통째로 보조기술에서 가려져 있었다.** 노출 자체는 개선이고,
같은 동작(받는 방법 시트)이 해당 눈금 버튼에도 있어 **정보 손실은 없다.**

읽는 순서를 눈금 사이로 되돌리려면 절대배치 레이어를 셀 안으로 쪼개야 하는데, 그러면
20260906_2140이 확보한 「고정 기하 — 글자가 기하를 못 움직인다」가 다시 깨진다.
그래서 그 티켓에서 잔여 이슈로 남겼다.

## 상세 요구사항

### UI/UX 관점
- 기하 불변식(`THUMB_SIZE=52`·`LINK_WIDTH=16`·`PITCH=68`, 연결선 폭이 눈금 수·글자 수와
  무관하게 하나)을 **깨지 않으면서** 읽는 순서를 시각 순서에 맞춘다. 후보:
  - 자물쇠 버튼만 눈금 셀 안으로 옮기고 위치는 `position: absolute`로 연결선 자리에 얹기
  - `aria-owns`로 읽기 순서를 재지정 (지원 범위 확인 필요)
  - 눈금 버튼의 `aria-label`에 「앞에 잠금이 있다」를 포함시키고 자물쇠는 `aria-hidden`으로
    되돌리기 (동작이 눈금에도 있으므로 정보 손실 없음)
- 어느 쪽이든 **375px·320px에서 연결선 폭이 하나로 유지되는지 실측**으로 확인할 것

## 구현 계획

세 후보 중 세 번째가 가장 저렴하다 — 자물쇠는 시각 표식으로만 두고 동작은 눈금이 담당한다.
다만 「자물쇠를 직접 누르고 싶다」는 사용자 기대가 있으면 첫 번째가 맞다. 착수 시 판단할 것.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

> ⚠️ **2차 방향 전환으로 아래 1차 구현은 최종 상태가 아니다.** 1차 구현(게이트 버튼을
> 눈금 셀 안으로 이동)은 게이트 리뷰 PASS까지 받았고 오케스트레이터가 로컬 재검증까지
> 마쳤으나, 그 직후 사용자가 로컬 Storybook 화면을 직접 보고 **게이트 버튼(자물쇠) 자체를
> 완전히 제거하고, 게이트 존재는 기존 눈금 이미지의 마커(잠김 자물쇠)만으로 표시하기로
> 확정**했다(2026-09-08). 최종 구현 내용은 이 절 하단 "2차 — 최종 반영"을 참조. 1차
> 기록은 "왜 이 방향이 아닌지"와 "필요하면 어떻게 되돌리는지"를 위해 그대로 남긴다.

**1차 — 게이트 버튼 위치만 이동 (게이트 리뷰 PASS, 이후 폐기)**

오케스트레이터가 사전 검토·기각한 대안(자물쇠 `aria-hidden` 되돌리기, `aria-owns`)을 배제하고,
채택안(게이트 버튼을 그 앞 눈금 그리드 셀 안으로 이동)대로 구현했다.

- `BadgeStageRail.jsx`의 연결선 절대배치 레이어(378행대)에 있던 `<button className="ds-rail-lock-btn">`을
  분리해 `GateButton` 컴포넌트로 추출했다. 연결선 레이어에는 트랙(점선 배경)만 남기고, 버튼(인터랙티브
  요소)은 눈금 그리드의 셀 안으로 옮겼다.
- `connectors` 계산 결과에서 `isGateBefore`인 항목만 추려 `gateByBeforeStopIndex`(Map, key = i-1)를
  만들고, 눈금 그리드 `visibleStops.map((stop, i) => ...)` 루프에서 `gateByBeforeStopIndex.get(i)`로
  "이 눈금 바로 다음에 게이트가 있는가"를 조회한다.
- 있으면 셀 div(`position: relative` 추가)에 `StopHitArea`의 다음 형제로 게이트 버튼을
  `position: absolute; left: THUMB_SIZE; top: THUMB_SIZE/2 - 10; width: LINK_WIDTH`로 절대배치했다.
  이 좌표는 부모가 "그 눈금 셀 자신"이라 `(i-1)*PITCH`를 빼지 않아도 되는 단순한 형태다(지침 그대로).
- `THUMB_SIZE`(52)·`LINK_WIDTH`(16)·`PITCH`(68) 상수는 건드리지 않았다.

**2차 — 게이트 버튼 완전 제거 (사용자 확정, 최종 반영)**

사용자가 로컬 Storybook에서 1차 구현 결과(눈금 사이에 얹힌 작은 자물쇠 버튼)를 직접
보고, 그 버튼 자체를 없애고 게이트 유무 표시를 눈금 이미지 자체의 마커로 일원화하기로
확정했다. 실제로 각 눈금(`ds-rail-stop`)은 이미 `status`가 `ready`/`locked`일 때
버튼이고 `onLockClick`으로 같은 받는 방법 시트를 열므로, 게이트 버튼을 없애도 **동작
손실은 없다** — 다만 게이트별 세부 정보(미션/교차 종류, 통과·대기 상태)는 화면에서
사라진다(사용자가 감수하기로 확정한 트레이드오프).

- `GateButton` 함수 컴포넌트, 그 사용부(눈금 셀 안 절대배치 wrapper), `gateByBeforeStopIndex`
  Map, `connectors` 계산의 `gates`·`gateAriaLabel` 필드, `GATE_KIND_LABEL` 상수를 전부
  제거했다. 미사용이 된 `StarGlyph` import도 정리했다.
- 연결선 트랙(점선 스타일, `.ds-rail-gate-link`)은 그대로 남겼다 — "여기 막는 문이
  있다"는 최소한의 시각 신호로 유지, 다만 클릭 가능한 요소는 없다.
- 이 변경으로 1차 구현이 고치려던 "보조기술 읽기 순서" 문제 자체가 원천적으로
  해소된다 — 자물쇠 버튼이 아예 없어졌으므로 DOM 순서 문제도 함께 사라진다.
- 1차 커밋(`645c8b9c`)은 그대로 두고 2차를 별도 커밋(`60917197`)으로 쌓았다 —
  필요하면 2차 커밋만 `git revert`해 1차 상태(버튼 위치 이동 방식)로 되돌릴 수 있다.

  안에 인라인으로 버튼을 그렸는데, 이제 두 자리(연결선 레이어의 옛 위치는 제거, 그리드 셀의 새
  위치)에서 같은 렌더 로직이 필요해 중복을 피하려 함수로 뽑았다. 시각적 출력(스타일 값)은 기존과
  동일하게 유지했다.
