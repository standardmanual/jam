# [Infra] ds-sync-check가 `<style>` 문자열 안의 지역 CSS 변수를 못 읽어 오탐한다

## 배경 / 문제 정의

`jam-web/scripts/ds-sync-check.mjs:607`의 지역 CSS 변수 인식이 **JS 객체 키
`'--x': value` 패턴만** 잡는다. 컴포넌트가 `<style>{STATIC_CSS}</style>` 문자열로 주입하는
선언은 보지 못한다.

티켓 20260906_2140의 1차 구현이 그 첫 오탐 사례였다 — `BadgeStageRail`이 `--ds-rail-thumb`·
`--ds-rail-gap`을 `STATIC_CSS` 안에 선언했는데 스크립트가 **미정의 토큰**으로 잡아
`ds:check`가 레드가 됐다. 값 자체는 정상이었고 렌더도 안 깨졌다.

그 티켓은 **컨테이너 쿼리와 해당 변수를 제거하는 방식**으로 우회했다(고정값이 320px에서도
맞아 축소가 불필요해졌다). 스크립트는 손대지 않았다 — 느슨하게 만들면 진짜 누락까지
놓치기 때문이다. 그래서 **원인은 그대로 남아 있고**, 다음에 누가 `<style>` 문자열로 지역
변수를 선언하면 같은 오탐이 재발한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `<style>` 템플릿 리터럴 안의 `--x: value` 선언을 인식하도록 파싱을 **정확히** 넓힌다
- **느슨하게 만들지 않는다** — "어딘가에 `--x`라는 문자열이 있으면 정의된 것으로 친다"
  식으로 바꾸면 진짜 미정의 토큰을 놓친다. 선언(`--x:`)과 참조(`var(--x)`)를 구분할 것
- 회귀 방지: 일부러 미정의 토큰을 쓰는 픽스처를 만들어 스크립트가 여전히 잡는지 확인

## 구현 계획

`ds-sync-check.mjs`의 지역 변수 수집 단계에 템플릿 리터럴 스캔을 추가한다.
`STATIC_CSS` 같은 상수를 정규식으로 훑어 `--이름:` 형태의 선언만 수집한다.

---
## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`checkUndefinedTokens()`의 지역 변수 수집 정규식을 `['"](--[\w-]+)['"]\s*:`(JS 객체 키만)에서
`['"]?(--[\w-]+)['"]?\s*:`(따옴표 유무 무관, `:` 로 끝나는 선언 전부)로 넓혔다. `var(--x)` 참조는
이름 뒤에 `,` 또는 `)` 가 오지 `:` 가 오지 않으므로 이 패턴에 자연히 걸리지 않는다 — 별도 lookahead
없이도 선언과 참조가 구분된다. 이로써 `<style>{STATIC_CSS}</style>` 문자열 리터럴 안에 있는
`--x: value` CSS 선언도 JS 객체 키와 동일하게 지역 변수로 인식된다.

### 주요 의사결정 / 핵심 메모
