# [UI] 미션 목록 — 보상 배지 노출 시 배지명 앞에 등급칩 표시

## 배경 / 문제 정의

미션 목록(`/missions`)의 보상 표시가 배지 이름을 순수 텍스트로만 보여준다
(`MissionsListClient.tsx:68-77` `rewardSummary()` → `"${name} 배지"` 문자열 조합,
`:429-432`에서 색 있는 `<span>` 한 줄로 렌더). 등급(Rare/Epic/Mystic)이나 레벨(Lv.N) 정보가
전혀 드러나지 않아, 유저가 보상이 얼마나 특별한지 목록에서 가늠할 수 없다.

## 상세 요구사항

### UI/UX 관점

- 보상 배지 이름 앞에 등급칩을 붙인다.
- 배지는 **등급형**(`rarity`)과 **무한레벨형**(`level`)이 상호배타적으로 존재한다
  (`badges` 테이블 CHECK: `(rarity IS NULL) = (level IS NOT NULL)`, 마이그레이션 130).
  보상 배지의 실제 값에 따라 분기해서 칩을 고른다.
- `rarity === 'common'` 또는 `rarity == null`이고 `level == null`인 경우(칩이 없는 배지)는
  지금처럼 칩 없이 이름만 표시한다 — `RarityBadge`가 이미 이 규칙을 내장하고 있다
  (v4/v5 정책, 티켓 20260905_0036).

### 서비스/코드베이스 관점

- `jam-web/src/app/(main)/missions/page.tsx:76-79`의 보상 배지 조회
  (`service.from('badges').select('id, name')`)에 `rarity, level`을 추가한다.
- `rewardBadgeNames`(`page.tsx:75`, `MissionsListClient.tsx:31`, 현재
  `Record<string, string>`)를 `Record<string, {name: string; rarity: BadgeRarity | null;
  level: number | null}>` 형태로 확장한다.
- `rewardSummary()`(`MissionsListClient.tsx:68-77`)가 문자열만 리턴하는 구조라, 칩을 JSX로
  끼워 넣으려면 이 함수의 리턴 형태(또는 호출부 `:429-432`의 렌더링 방식)를 바꿔야 한다 —
  포인트 보상("+100P") 등 텍스트 전용 부분과 배지 보상(칩+이름)을 분리해서 조립하는 형태로
  정리한다.
- `requiredBadge`(잠금 해제 조건 배지, `:23`·`:179-192`)는 이 티켓의 대상이 **아니다** —
  다른 UI(`lockedHintText`)로 이미 별도 처리되고 있다. 보상 배지 표시만 바꾼다.

### UI 재사용 판정 (오케스트레이터 결정 — 이대로 따를 것)

**신규 컴포넌트 없음.** 기존 MODULAR 컴포넌트 2종을 배지의 `rarity`/`level` 값에 따라
분기 사용한다:
- `RarityBadge`(`design-system/components/cards/RarityBadge.jsx`) — 등급형(`rarity` 있음)
- `BadgeLevelChip`(`design-system/components/cards/BadgeLevelChip.jsx`) — 레벨형(`level` 있음)

두 컴포넌트 다 각각 값이 `null`/`common`이면 스스로 아무것도 렌더하지 않으므로, 호출부에서
`rarity`/`level` 존재 여부로 분기만 하면 된다(추가 조건 분기 로직 최소화).

## 하지 않는 것
- `requiredBadge`(잠금 해제 조건) 표시 방식 변경
- 신규 MODULAR 컴포넌트 제작
- 미션 상세 페이지(`/missions/[id]`)의 보상 표시 — 이 티켓은 목록 화면(`/missions`)만
  (상세 페이지도 같은 문제가 있다면 범위 확인 후 별도 판단)

## 구현 계획
1. `page.tsx`의 보상 배지 select에 `rarity, level` 추가, `rewardBadgeNames` 타입 확장
2. `MissionsListClient.tsx`의 보상 렌더링을 "칩 + 이름"(배지) / "텍스트"(포인트) 조합으로 재구성
3. 검증: `npx tsc --noEmit` · `npm run lint` · `npx vitest run` · `npm run ds:check`
4. staging 실화면 확인 — 등급형·레벨형·칩 없는 보상(공용) 각각 섞인 미션에서 정상 렌더되는지

## 2026-09-07 게이트 리뷰 WARN → 실화면 확인 완료

정적 검증(tsc·lint·vitest 1137건·ds:check)은 전부 통과했으나, 게이트 리뷰 워크트리의
