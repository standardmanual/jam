# [UI] 드랍 시트는 같은 배지를 여러 개 보유해도 어느 개체를 내놓는지 알 수 없다

## 배경 / 문제 정의

티켓 [20260907_2221](20260907_2221_UI_장착개체-선택시트-ListRowCard-재구성.md) 개선 리뷰에서
발견된 범위 밖 항목이다.

[20260907_2059](../P1-중요/20260907_2059_UI_아이템배지-개체별-상세라우팅-및-장착개체-선택.md)가
**컬렉션 장착** 쪽에서 푼 문제가, **드랍** 쪽에는 그대로 남아 있다.

`src/components/PoiCarouselModal.tsx:481`의 드랍 시트는 `InventoryGrid mode="select"`를 쓰는데
일련번호도 만료일도 싣지 않는다. 같은 배지를 3개 보유하면 **구분할 수 없는 카드 3장**이 뜨고,
어느 개체가 드랍될지 사용자가 알 수 없다.

> ⚠️ **접수 시점 판단 정정 (2026-09-08)**: 아래 "형태는 장착 시트와 다를 수 있다" 절은
> "드랍 그리드가 이미 배지 종류별로 묶여 있다"고 전제했으나, 코드를 확인한 결과 **그렇지
> 않다.** `dropGridItems`(`PoiCarouselModal.tsx:296`)는 `inventoryItems`를 **개체 1:1로**
> 매핑한다 — 배지 종류가 아니라 보유 개체 하나하나가 이미 카드 한 장이다. 같은 배지가
> 3개면 지금도 카드 3장이 뜬다("배지 간 선택"이 아니라 이미 "개체 간 선택"인데, 구분 수단만
> 없는 상태). 아래 결정은 이 정정을 반영한 최종본이다.

두 가지가 걸린다.

1. **개체 정체성** — 일련번호는 이 서비스에서 소유를 증명하는 값이다. 아끼는 번호를 모르고
   내놓을 수 있다. 드랍은 소유권 이전이므로 되돌리기 어렵다.
2. **만료 임박 개체** — 20260907_2059가 장착 시트에 "곧 만료" 칩을 넣은 이유가 그대로 적용된다.
   오히려 드랍에서는 만료 임박한 것을 **골라서** 내놓고 싶을 수 있어 더 유용하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `PoiCarouselModal`의 드랍 후보에 일련번호와 만료일을 싣는다
- 어느 개체를 드랍하는지 사용자가 고를 수 있게 한다

### UI/UX 관점 — 형태는 장착 시트와 다를 수 있다

**두 시트를 무조건 같은 형태로 통일하려 들지 말 것.** 선택 축이 다르다.

| 시트 | 고르는 대상 | 맞는 형태 |
|---|---|---|
| 드랍 (`PoiCarouselModal`) | **서로 다른 배지들** 중 하나 | 이미지 그리드 |
| 장착 (`SlotGrid`) | **같은 배지의 개체들** 중 하나 | 문자(일련번호) 리스트 |

드랍 시트는 "어느 배지를 내놓을까"가 1차 선택이므로 그리드가 맞다. 문제는 그 다음 단계
"같은 배지가 여러 개일 때 어느 개체인가"가 없다는 것이다. **2단계로 나누는 안**(배지 선택 →
개체 선택)이 자연스러울 수 있으나 단계가 늘어나는 비용이 있으므로 함께 판단한다.

> 이 축 구분(**그리드 = 배지 간 선택 / 리스트 = 개체 간 선택**)을 이 티켓에서 명문화해두면,
> 다음 작업자가 "두 시트가 다르니 통일하자"며 되돌리는 사고를 막을 수 있다.

### 결정 (2026-09-08, 사용자 — 위 정정 반영 최종본)

**그리드를 배지 종류별로 묶는다.** 지금처럼 개체마다 카드를 따로 그리지 않고, **같은
`badge_id`끼리 카드 1장으로 합친다.** 보유 개수는 신규 UI 없이 표시한다 —
`BadgeGridCard`에 **이미 `count?: number | null` prop이 있고**, "2 이상일 때만 모서리에
«×N»을 그린다"는 관례가 정확히 이 상황을 위한 것이다(`src/components/ui/BadgeGridCard.tsx:31`,
피드 카드 카운터 필과 같은 시각 문법). 다만 `InventoryGrid`는 현재 이 prop을 쓰지 않으므로
전달 경로를 새로 잇는다.

탭했을 때:
- **묶음이 1개** → 지금처럼 그 개체로 즉시 드랍 확인 단계(`confirmDrop`)로 진행. **변경 없음.**
- **묶음이 2개 이상** → 20260907_2221에서 만든 개체 선택 시트(등급칩+일련번호 `ListRowCard`
  목록)를 여기서도 연다. 고른 개체가 그대로 기존 `confirmDrop` 확인 단계로 이어진다 —
  **드랍 확인 자체를 없애지 않는다**(소유권 이전은 되돌리기 어려우므로 이중 확인을 유지한다).
  장착 시트가 쓰는 "후보 1개는 즉시, 2개 이상은 시트" 규칙과 그대로 같다.

## 구현 계획

**신규 컴포넌트를 만들지 않는다.** `SlotGrid.tsx`가 20260907_2221에서 만든 개체 행(등급칩 위·
일련번호 아래, `ListRowCard` 기반)을 **공용 컴포넌트로 추출**해 `PoiCarouselModal`과 함께 쓴다.
이 티켓이 그 컴포넌트의 두 번째 사용처이므로 추출할 시점이 맞다(오케스트레이터 판정).

1. `SlotGrid.tsx`의 개체 행 JSX(`RarityBadge` + `ItemSerialCode` 세로 스택 + 선택 톤 +
   만료 임박 칩, `SlotGrid.tsx:363-409`)를 `src/components/inventory/ItemCandidateRow.tsx`
   (가칭)로 뽑아낸다. `formatSerial`·`isExpiringSoon`도 함께 옮긴다(`InventoryGrid.tsx`에
   같은 이름의 `isExpiringSoon`이 이미 있으므로 이름 충돌에 주의 — 병합하거나 import 경로로
   구분한다). `SlotGrid`가 이 컴포넌트를 쓰도록 바꾼다 — **동작·시각 변화가 없어야 한다**
   (순수 리팩터, 20260907_2221의 게이트 통과 상태를 깨지 않는다).
2. `PoiCarouselModal`: `dropGridItems` 계산을 개체 1:1 매핑에서 **`badge_id`별 그룹화**로
   바꾼다. 각 그룹 카드에 `count`(그룹 내 개체 수)를 `BadgeGridCard`까지 전달한다. 그룹 내
   **어느 개체가 만료 임박이면** 그리드 카드에도 기존 "곧 만료" 칩을 보여준다(가장 이른
   `expires_at` 기준) — 지금은 `dropGridItems`가 `expiresAt` 필드를 아예 안 보내고 있어
   이 칩 자체가 드랍 그리드에 없다(3번에서 API 확장과 함께 해결).
3. 그룹을 탭하면: 1개면 그 개체로 `setPendingDropItem` 즉시 호출(현재 동작 그대로). 2개
   이상이면 `BottomSheet` + `ItemCandidateRow` 목록을 열어 고르게 하고, 선택 결과를
   `setPendingDropItem`으로 넘겨 **기존 `confirmDrop` 단계와 그대로 합류시킨다**(새 확인
   단계를 만들지 않는다). 시트 상단은 배지 이름만(20260907_2221과 동일 규칙).
4. **API 확장 필요** — 확인 결과 `GET /api/inventory/items`(`src/app/api/inventory/items/route.ts`)가
   현재 `id, badge_id, badge_name, badge_rarity, badge_image_url`만 반환하고
   `serial_prefix`·`serial_number`·`expires_at`을 **아예 select하지 않는다.** 이 세 컬럼을
   select와 응답 매핑에 추가한다(DB 마이그레이션 불필요 — 기존 컬럼을 조회에 더하는 것뿐).
5. 선택된 개체 id로 기존 드랍 생성 요청을 호출한다. **API·RPC 변경 불필요** — 확인 결과
   `POST /api/drops`(`src/app/api/drops/route.ts:293`)가 이미 body로 `inventory_item_id`를
   받아 `create_user_drop()` RPC에 `p_inventory_item_id`로 그대로 넘긴다. `pendingDropItem.id`가
   이미 개체 id이므로(`PoiCarouselModal.tsx:194`) 이 경로는 그대로 쓴다.

### 문구

새 문구가 필요하다 — 20260907_2221의 안내문("장착할 수 있는 배지가 {count}개예요…")은
"장착" 맥락이라 드랍에 그대로 못 쓴다. `UX_WRITING_GUIDELINE.md` 기준으로 드랍 맥락에 맞는
안내문을 새로 짓는다("드랍·내놓다" 등 이미 정의된 용어 우선 사용).

`BadgeGridCard`의 «×N» 접근성 문구 `d.badges.earnCountAria`("{count}번 획득했어요")를 그대로
재사용할지도 확인한다 — 드랍 그리드의 «보유 개수»는 "몇 번 획득했는가"와 의미가 겹치긴 하지만
맥락이 다르므로(장착·트로피 화면은 "획득 이력", 드랍은 "지금 갖고 있는 것 중 고르기") 그대로
써도 되는지 판단이 필요하다.

### 회귀 확인 포인트
- 보유 개체가 1개뿐인 배지는 그리드·확인 단계 모두 지금과 동일하게 동작하는가(카드 1장,
  ×N 칩 없음, 탭하면 바로 확인 단계)
- `ItemCandidateRow` 추출이 `SlotGrid`의 기존 동작(선택 톤·중복 탭 가드·만료 칩·닫힘
  트랜지션 중 유지·열림 중 최신 목록 반영·요청 중 닫기 무시)을 바꾸지 않는가 — 리팩터
  전후로 20260907_2221의 실렌더 검증을 다시 해야 한다
- `isExpiringSoon` 중복 정의를 병합하면서 다른 사용처(인벤토리 목록)의 만료 판정 기준이
  바뀌지 않는가
- 드랍 대상 개체가 파괴·만료·타인 소유로 바뀐 사이 시트가 열려 있었을 때 실패가 사용자에게
  보이는가 (장착 시트의 실패 노출 규칙과 동일하게)
- 아이템배지가 전부 `common`이라 등급칩은 여기서도 보이지 않는다 — 20260907_2221과 같은
  전제이며, 이 티켓에서 되돌리지 않는다 (별도 티켓 [20260908_0010](20260908_0010_UI_아이템배지-등급표시-전제불일치.md)에서 다룬다)
- 드랍 확인 단계(`confirmDrop`)가 그룹 선택 경로에서도 정확히 그 개체를 보여주는가(그룹
  대표 이미지가 아니라 실제 선택된 개체 기준 — 이미지/이름은 배지 단위라 동일하지만 id가
  맞아야 한다)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `SlotGrid.tsx`의 개체 행(등급칩+일련번호+만료칩)을 `src/components/inventory/ItemCandidateRow.tsx`로
  추출했다. `formatSerial`·`isExpiringSoon`·`SELECT_SERIAL_HEIGHT_PX`도 함께 옮겼다. `SlotGrid`는
  이 컴포넌트를 쓰도록 바꿨고 JSX·클래스·문구는 그대로다(순수 리팩터).
- `PoiCarouselModal`의 드랍 그리드를 개체 1:1 매핑에서 `badge_id`별 그룹화로 바꿨다. 그룹 카드에는
  `count`(그룹 내 개체 수)와 `countAriaText`를 `InventoryGrid` → `BadgeGridCard`까지 전달한다.
  그룹 내 가장 이른 `expires_at`을 그리드 카드의 "곧 만료" 칩 기준으로 쓴다.
- 그룹 탭 시 개체가 1개면 기존과 동일하게 즉시 `pendingDropItem`으로 진행하고, 2개 이상이면
  `ItemCandidateRow` 목록을 담은 `BottomSheet`(제목=배지 이름)를 열어 고르게 한 뒤, 선택 결과를
  그대로 기존 `confirmDrop` 확인 단계로 합류시켰다(새 확인 단계 없음).
- `GET /api/inventory/items`가 `serial_prefix`·`serial_number`·`expires_at`을 select·응답에
  추가하도록 확장했다(DB 마이그레이션 없음, 기존 컬럼 조회 추가뿐).
- `BadgeGridCard`에 `countAriaText?: string` prop을 추가해 ×N 접근성 문구를 화면별로 교체할 수
  있게 했다. `InventoryGrid.tsx`는 `InventoryGridItem.count`·`countAriaText`를 그대로
  `BadgeGridCard`에 전달하기만 한다(자체적으로 i18n 그룹을 알지 않는다 — 두 화면이 공유하는
  정규화 컴포넌트라는 기존 설계를 유지).
- 신규 문구: `d.drops.selectDropItemBody`(드랍 개체 선택 시트 안내문), `d.drops.dropOwnedCountAria`
  (드랍 그리드 ×N 접근성 문구 — 기본 `d.badges.earnCountAria`"N번 획득했어요"는 "획득 이력" 맥락이라
  "지금 보유한 것 중 고르기" 맥락인 드랍에는 맞지 않아 새로 지었다).

  발생하지 않는다 — 병합은 한쪽을 고칠 때 다른 쪽에 회귀를 만들 위험만 추가한다고 판단했다.
- `count`/`countAriaText`를 `InventoryGrid`가 직접 `d.drops.*`를 참조해 만들지 않고, 호출부
  (`PoiCarouselModal`)가 완성된 문자열을 넘기도록 했다 — `InventoryGridItem`이 이미 "인벤토리
  목록"과 "드랍 시트" 두 화면이 공유하는 정규화 타입이라는 파일 상단 주석의 설계 원칙을 그대로
  따른 것이다.

### 잔여 이슈
- **실화면 확인 필요.** staging은 데이터 없는 테스트 계정으로 자동 로그인되어 이 티켓이 다루는
  "동일 배지 다수 보유" 상황을 재현한 화면은 실제 계정으로 직접 확인해야 한다 — 그룹 카드 ×N
  표시, 개체 선택 시트 열림/닫힘, 선택 후 드랍 확인 단계로의 전환.
- 인터랙션 리뷰의 제안 3건(전부 선택 사항, 미결정): ①그룹 카드의 "곧 만료" 칩이 그룹 전체를
  대표해 일부만 만료 임박이어도 뜬다 ②×N 카드가 "누르면 고르는 목록이 뜬다"를 암시하는 시각
  신호가 없다 ③드랍 쪽은 API 호출이 없어 행 탭 즉시 시트가 닫혀 장착 쪽과 손맛이 다르다.
