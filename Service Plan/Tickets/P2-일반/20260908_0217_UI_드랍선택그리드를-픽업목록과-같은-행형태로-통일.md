# [UI] 드랍 선택 UI를 픽업 목록과 같은 행(row) 형태로 통일

## 배경 / 문제 정의

같은 `PoiCarouselModal` 안에서 두 목록이 서로 다른 시각 문법을 쓰고 있다.

- **픽업 목록**(이 POI에 드랍된 배지들, `PoiCarouselModal.tsx:609-637`) — 아이콘(44px) + 이름 +
  등급칩 + 화살표로 된 **행(row)**. `bg-white/[0.04]` 배경의 개별 `<button>`.
- **드랍 선택**(내 인벤토리에서 여기 내놓을 배지 고르기, 티켓 20260908_0040) —
  `InventoryGrid` + `BadgeGridCard`로 된 **그리드 카드**.

사용자가 같은 화면 안에서 두 형태를 오가며 보게 되는데, 스크린샷으로 지적된 대로 드랍 선택도
픽업 목록과 같은 행 형태를 써야 자연스럽다.

## 상세 요구사항

### UI/UX 관점

1. **드랍 선택 목록을 픽업 목록과 같은 행 형태로 바꾼다** — 아이콘(44px) + 이름 + 등급칩 +
   화살표. 그리드(`InventoryGrid`+`BadgeGridCard`)는 이 화면에서 걷어낸다.
2. **동일한 이름의 아이템배지는 하나의 행으로 묶는다**(이미 그렇게 그룹화돼 있다 —
   `dropGridItems`가 `badge_id`별로 묶은 배열이다. 변경 없음).
3. **개수 표시는 아이콘 모서리에 원형 서클로** — `BadgeGridCard`의 «×N» 필(피처 텍스트, 썸네일
   하단 우측)과는 다르게, **아이콘 우측 상단에 숫자만 든 원형 배지**를 얹는다(2026-09-08
   사용자 결정). 그리드 카드용 «×N» 시각 문법을 그대로 가져오지 않는다.
4. **행을 누르면 지금과 동일하게 동작한다** — 개체 1개면 즉시 확인 단계, 2개 이상이면
   20260908_0040에서 만든 개체 선택 시트(`ItemCandidateRow` 목록)가 열린다. **이 로직은
   전혀 바뀌지 않는다** — 데이터(`dropGridItems`, `handleSelectDropGridItem`,
   `handleSelectDropGroup`)가 이미 준비돼 있고 렌더링만 바뀐다.
5. **만료 임박 정보를 잃지 않는다** — 그리드 카드는 그룹 내 가장 이른 만료일로 "곧 만료" 칩을
   보여줬다(20260908_0040 인터랙션 리뷰 지적 반영분). 행 형태에서도 동등한 정보를 유지한다
   (정확한 배치는 구현 판단 — 다만 픽업 행의 기본 모습(이름+등급칩 한 줄)과 시각적으로 크게
   갈리지 않게 한다. 만료 임박이 아닌 경우엔 지금 픽업 행과 완전히 같은 모습이어야 한다).

### 서비스/코드베이스 관점

**재사용 판정 (오케스트레이터 결정 — 이대로 따를 것)**

**신규 MODULAR 컴포넌트를 만들지 않는다.** 픽업 행의 마크업(`PoiCarouselModal.tsx:616-635`)을
`PoiCarouselModal.tsx` 안에 **로컬 프레젠테이션 컴포넌트로 추출**해 픽업 목록·드랍 선택 목록
양쪽이 함께 쓴다. 이 파일 안에서 같은 모양이 두 번째로 필요해진 시점이라 추출이 맞다.

- **`src/components/ui/ListRowCard`를 쓰지 않는다** — 겉보기엔 비슷하지만 배경 토큰
  (`bg-white/[0.04]` vs `ListRowCard`의 `bg-surface-elevated`)과 패딩(`px-16 py-8` vs 균일
  `p-16`)이 실제로 다르다. "픽업 목록과 같은 UI"라는 요구를 정확히 지키려면 픽업 행 자체의
  마크업을 그대로 재사용해야 한다 — 겉모습이 비슷한 다른 컴포넌트로 바꿔 타면 미묘하게
  달라진다.
- 개수 서클은 새로 만든다(위 3번). `BadgeGridCard`의 «×N» 배지(`bg-surface-elevated` +
  `border` + `radius-pill`)와 같은 색상 토큰을 쓰되, **모양은 완전한 원**(`rounded-full`)이고
  **위치는 아이콘 우측 상단**(`-top-1 -right-1`, 기존 «×N»은 하단 우측이었다)이다.

### 회귀 확인 포인트
- 픽업 목록(이 POI에 드랍된 배지들) 쪽 모습·동작이 이번 추출로 조금도 바뀌지 않는가
  (순수 리팩터여야 한다)
- 보유 개체가 1개뿐인 배지는 서클 없이, 지금과 동일하게 즉시 확인 단계로 가는가
- 2개 이상인 배지를 눌렀을 때 개체 선택 시트가 지금과 완전히 동일하게 열리는가
  (20260908_0040의 동작·문구·시트 구현은 전혀 건드리지 않는다)
- 만료 임박이 아닌 행은 픽업 행과 시각적으로 동일한가
- 아이템배지가 전부 `common`이라 등급칩은 여기서도 안 보인다 — 그대로 둔다(되돌리지 않는다,
  픽업 행도 이미 같은 상태다)
- `InventoryGrid`·`BadgeGridCard`의 다른 사용처(`/inventory` 목록 등)가 무영향인가

## 구현 계획

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
픽업 행(`PoiCarouselModal.tsx:616-635` 부근, `<button>`+44px 아이콘+이름+`RarityBadge`+
`ChevronRightIcon`)의 마크업을 파일 내부 로컬 컴포넌트 `ItemRow`로 추출해 픽업 목록·드랍 선택
목록 양쪽이 함께 쓰도록 했다. 드랍 선택 쪽의 `InventoryGrid`+`BadgeGridCard` 그리드 렌더링을
`ItemRow` 목록으로 교체했다. `dropGridItems` 계산·`handleSelectDropGridItem`·
`handleSelectDropGroup`·개체 선택 시트(`ItemCandidateRow` 기반)는 전혀 건드리지 않았다.

개수 서클(`count>1`일 때만)은 `BadgeGridCard`의 ×N과 같은 색 토큰
(`bg-surface-elevated`+`border-[color:var(--color-border)]`+`font-bold`)이되
모양은 `rounded-full`, 위치는 아이콘 우측 상단(`-top-1 -right-1`), 내용은 숫자만(접두어 없음)
으로 새로 만들었다.

**보완(같은 날, 게이트 PASS 후 인터랙션 리뷰 지적 반영)** — 1차 구현의 서클이
`min-w-[18px] h-[18px] px-1`이라 **두 자리 수(10~50, 최대 보유 슬롯 50개라 실제로 나옴)에서
폭만 늘어나 알약 모양**이 됐다. `w-5 h-5` 고정 크기로 바꿔 해결했다 — Chromium 실렌더로
`getBoundingClientRect()` 측정 결과 1자리(2·9)·2자리(12·50) 전부 22×22(테두리 포함)로
정확한 정원임을 확인했다. 접근성도 `aria-label`로 버튼 전체를 덮던 방식(등급·만료 정보가
스크린리더에서 사라지는 회귀)을 `BadgeGridCard`와 같은 `sr-only` **추가** 방식으로 바꿔,
`count>1`이어도 이름·등급·만료 정보가 그대로 읽히도록 정정했다.

만료 임박(그룹 내 가장 이른 `expires_at`, 7일 이내)일 때만 `RarityBadge` 옆에 만료 칩을
추가로 그리고, 그렇지 않으면(대부분의 경우, 그리고 픽업 행은 항상) 기존 픽업 행과 완전히
동일한 마크업(`RarityBadge`만, `mt-1`)을 그대로 렌더한다 — 분기 자체를 두 갈래로 나눠 평소
모습을 건드리지 않았다.
