# [UI] POI 픽업 목록도 동일 이름 배지를 그룹핑 + 개체 선택 시트 적용

## 배경 / 문제 정의

**선행 티켓**: [20260908_0217](20260908_0217_UI_드랍선택그리드를-픽업목록과-같은-행형태로-통일.md)
(드랍 선택 목록을 픽업 목록과 같은 행 형태로 통일). **이 티켓은 그 결과물(추출된 공용 행
컴포넌트)을 전제로 한다 — 0217이 staging에 병합된 뒤 시작한다.**

지금까지 "같은 이름 배지가 여러 개일 때 행 하나로 묶고, 서클에 개수를 표시하고, 누르면
일련번호로 개체를 고르는 바텀시트가 열린다"는 패턴이 두 곳에 이미 있다.

1. **컬렉션 장착** — [20260907_2221](20260907_2221_UI_장착개체-선택시트-ListRowCard-재구성.md)
2. **POI 드랍**(인벤토리에서 골라 내놓기) — [20260908_0040](20260908_0040_UI_드랍시트-개체식별수단-부재.md) +
   0217(행 형태 통일)

**세 번째로, POI 픽업 목록**(이 POI에 이미 드랍돼 있어 주워갈 수 있는 아이템들, 스크린샷의
"성수1가2동 주민센터" 목록)에도 같은 패턴을 적용한다. 지금은 같은 이름의 배지가 여러 명의
드랍자로부터 동시에 드랍돼 있어도 **구분할 수 없는 행이 여러 개** 뜬다(장착·드랍에서 이미
고쳤던 것과 같은 문제).

### 데이터 확인 결과

`GET /api/drops/poi/[poiId]`(`src/app/api/drops/poi/[poiId]/route.ts`)는 이미
`inventory_items(serial_prefix, serial_number)`를 조인해 **포맷된 일련번호 문자열**
(`serial: "ZPRS545679"` 형태)을 내려주고 있다(픽업 개체는 이미 발급된 개체를 가리키므로
픽업 전에도 일련번호가 확정돼 있다 — 20260829_2101). 다만:
- **원본 `serial_prefix`/`serial_number`는 안 내려준다** — `ItemCandidateRow`가 요구하는
  `ItemCandidate` 셰이프(`id`, `serial_number`, `serial_prefix`, `expires_at`)와 다르다
- **`expires_at`은 아예 select하지 않는다** — 만료 임박 칩을 못 그린다

## 상세 요구사항

### UI/UX 관점

1. **픽업 목록도 `badge_id`별로 그룹핑한다** — 지금은 `drops`가 개체 1:1 flat 배열이다
   (`PoiCarouselModal.tsx` `drops.map(...)`, 611행 부근). 20260908_0040의 `dropGroups`
   그룹핑과 같은 방식으로 묶는다.
2. **행 형태·개수 서클은 0217에서 만든 공용 행 컴포넌트를 그대로 재사용한다** — 신규 UI를
   만들지 않는다. 그룹 내 개체가 2개 이상일 때만 아이콘 우측 상단에 원형 서클로 개수를
   표시한다.
3. **그룹을 눌렀을 때**:
   - 개체 1개 → **지금과 완전히 동일하게** `onSelectDrop(drop)`을 바로 호출해 픽업 상세
     바텀시트(`BadgeDetailSheet`)를 연다. 변경 없음.
   - 개체 2개 이상 → `ItemCandidateRow` 목록의 개체 선택 시트를 연다(20260907_2221/
     20260908_0040과 같은 컴포넌트, 새로 만들지 않는다). 시트 상단은 배지 이름만. 후보를
     골라 선택하면 그 개체로 `onSelectDrop(drop)`을 호출해 **기존 `BadgeDetailSheet`로 그대로
     이어진다**(새 확인 단계를 만들지 않는다 — 20260908_0040에서 확인이 `confirmDrop`으로
     합류했던 것과 같은 원칙).
4. **만료 임박 정보를 유지한다** — 그룹 내 가장 이른 `expires_at`을 그룹 행에도 반영한다
   (0217에서 드랍 선택 쪽에 이미 적용한 것과 동일 기준).

### 서비스/코드베이스 관점

**API 확장 필요** — `GET /api/drops/poi/[poiId]`가 `inventory_items`에서
`expires_at`을 추가로 select하고, 응답에 **원본** `serial_prefix`·`serial_number`도 함께
내려준다(기존 포맷된 `serial` 필드는 **그대로 유지** — `BadgeDetailSheet.tsx:172`가
`drop.serial`을 계속 쓰므로 하위 호환이 깨지면 안 된다). DB 마이그레이션 불필요(기존 컬럼
조회 추가뿐).

`ItemCandidateRow`(`src/components/inventory/ItemCandidateRow.tsx`)는 그대로 재사용한다 —
`{id, serial_number, serial_prefix, expires_at}` 셰이프로 각 드랍을 매핑하기만 하면 된다.

### 회귀 확인 포인트
- 픽업 상세 바텀시트(`BadgeDetailSheet`)의 동작·표시(`drop.serial` 포함)가 API 확장 이후에도
  그대로인가(포맷된 `serial` 필드를 건드리지 않았는가)
- 개체 1개인 그룹은 서클 없이, 지금과 동일하게 즉시 `BadgeDetailSheet`로 가는가
- 2개 이상인 그룹을 눌렀을 때 개체 선택 시트가 열리고, 고른 개체가 정확히 그 개체로
  `BadgeDetailSheet`에 전달되는가(그룹 대표가 아니라 실제 선택된 개체)
- 등급칩이 `common`이라 안 보이는 건 그대로 둔다(다른 두 곳과 같은 전제)
- 픽업 성공·실패 흐름(픽업 API 호출, 토스트) 자체는 전혀 바뀌지 않는가

### 문구

새 문구가 필요할 수 있다 — 시트 안내문은 "장착"·"드랍" 맥락과 달리 "픽업" 맥락이다.
`UX_WRITING_GUIDELINE.md` 기준으로 기존 고정 용어("픽업")를 써서 짓는다. 시트 제목(배지 이름)은
기존 패턴 그대로 문구 없이 재사용된다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `GET /api/drops/poi/[poiId]`가 `inventory_items`에서 `expires_at`을 추가 select하고,
  응답에 원본 `serial_prefix`·`serial_number`·`expires_at`을 함께 내려주도록 확장했다.
  기존 포맷된 `serial` 필드는 그대로 유지했다.
- 픽업 목록(`drops`)을 `badge_id`별로 그룹핑하는 `groupPickupDrops()`를 추가하고(0040의
  `dropGroups` 빌드 루프와 같은 패턴), 0217에서 만든 공용 `ItemRow`로 그룹 행을 렌더링했다
  (개체 2개 이상일 때만 개수 서클 표시, 그룹 내 가장 이른 `expires_at`을 "곧 만료" 칩에 반영).
- 그룹 클릭 시 개체가 1개면 지금까지처럼 즉시 `BadgeDetailSheet`를 열고, 2개 이상이면
  `ItemCandidateRow` 목록의 개체 선택 시트(`pickupCandidateGroup`)를 열도록 했다. 시트에서
  고른 개체는 기존 `selectedDrop` 경로로 합류해 `BadgeDetailSheet`로 이어진다 — 새 확인
  단계를 만들지 않았다.
- `earliestExpiry()`의 파라미터 타입을 `InventoryItem[]`에서 `{ expires_at: string | null }[]`로
  넓혀 드랍 선택 그룹·픽업 그룹 양쪽에서 재사용했다.
- 픽업 맥락 문구 2건을 신규 추가했다: `selectPickupItemBody`(시트 안내문), `pickupAvailableCountAria`
  (개수 서클 sr-only 보조문).
