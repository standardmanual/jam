# [UI] 개체 선택 시트 헤더 시각 조정 + ItemCandidateSheet 공용 컴포넌트 추출

## 배경 / 문제 정의

동일 배지 다수 보유 시 일련번호로 개체를 고르는 시트(컬렉션 장착·POI 드랍·POI 픽업 3곳)의
헤더(배지 이름)와 본문(안내문) 사이 시각 균형이 어긋나 있었다. 사용자가 스크린샷과 함께
4가지를 지적했고, 이어서 "이전에 정의한 대로 이 바텀시트가 노출되는 모든 케이스에 동일하게
수정 적용해, 같은 케이스라면 공통 컴포넌트로 개발해야해"라고 명시했다 — 세 시트가 실제로
거의 동일한 마크업이었으므로(20260908_0223 개선 리뷰도 이미 같은 지적을 했다) 공용 컴포넌트
추출로 처리한다.

## 상세 요구사항

### UI/UX 관점 (스크린샷 기반 4가지 지적, 실측으로 확인)

1. **배지 이름(제목) 크기를 키운다** — 기존 `--text-body`(16px) → `--text-h4`(24px, weight 500).
   `privacy`·`philosophy` 페이지의 소제목이 이미 같은 토큰을 쓴다(선례).
2. **제목 윗부분(핸들과 제목 사이) 간격을 확보한다** — 헤더 래퍼에 `pt-[var(--spacing-8)]` 추가
   (기존엔 top padding이 아예 없었다).
3. **제목과 설명문 사이 간격을 줄인다** — 헤더 래퍼 하단 패딩을 `pb-16` → `pb-8`로 좁힌다.
4. **설명문 시작 위치를 배지 이름과 맞춘다** — 본문 컨테이너 좌우 패딩을 `px-16` → `px-24`로
   맞춘다(헤더의 `px-24`와 동일). 기존엔 8px 어긋나 있었다(헤더 24 vs 본문 16).

### 서비스/코드베이스 관점 — 공용 컴포넌트로 추출 (사용자 지시)

**신규 컴포넌트**: `src/components/inventory/ItemCandidateSheet.tsx`. `BottomSheet` + 안내문
+ `ItemCandidateRow` 목록을 묶어, 컬렉션 장착(`SlotGrid.tsx`)·POI 드랍·POI 픽업
(`PoiCarouselModal.tsx` 2곳) 4개 호출부가 전부 이 컴포넌트로 교체됐다.

**`BottomSheet`에 선택적 prop 2개 추가**(기존 13개 사용처 무영향 — 지정 안 하면 기존 기본값
그대로):
- `headerClassName?: string` — 헤더 래퍼 클래스 **전체 교체**(병합 아님, 패딩 유틸리티 충돌
  방지)
- `titleClassName?: string` — 제목(`<h2>`) 클래스 **전체 교체**

**장착 시트만의 요청 진행 중 상태(20260907_2221)는 선택적 prop으로 보존**:
- `error?: ReactNode` — API 실패 배너(장착만 사용)
- `busy?: boolean` — 후보 목록 `aria-busy`(장착만 사용)
- `isSelected?/isMuted?/renderTrailing?: (candidate) => ...` — 행별 선택 표시·비활성화·진행
  표시(장착만 사용). 드랍·픽업은 API를 호출하지 않으므로 이 값들을 넘기지 않는다(기본 동작
  유지).

### 주요 의사결정 / 핵심 메모

**`headerClassName`/`titleClassName`을 "병합"이 아니라 "전체 교체"로 설계한 이유** — 패딩·폰트
크기 유틸리티는 같은 CSS 속성을 두고 여러 클래스가 동시에 걸리면 결과가 Tailwind 생성 순서(JSX
작성 순서가 아니다)에 좌우돼 예측 불가능해진다. 지정 시 기본값을 완전히 대체하게 해 이 문제를
원천 차단했다.

**장착 시트의 진행 중 상태를 콜백 prop(`isSelected`/`isMuted`/`renderTrailing`)으로 뺀 이유** —
드랍·픽업 시트는 이 상태 자체가 없다(API를 호출하지 않으므로). 공용 컴포넌트에 이 상태를
내장하면 드랍·픽업 쪽에 불필요한 개념이 강제된다. 콜백을 옵셔널로 두어 필요한 화면만 채워
넣게 했다 — 세 화면의 "같은 부분"(레이아웃)과 "다른 부분"(상호작용 상태)을 정확히 그 경계에서
나눴다.

**드랍·픽업 시트의 `onSelect`가 `candidate.id`로 원본 배열을 다시 찾는 이유** — `candidates` prop
타입이 `ItemCandidate[]`(일련번호 표시에 필요한 최소 필드)라, `onSelect` 콜백이 받는 값도 그
좁은 타입이다. 그런데 `handleSelectDropCandidate`/`handleSelectPickupCandidate`는 더 많은
필드(예: `badge_id`)가 있는 원본 타입을 요구한다 — 좁혀진 타입을 그대로 넘기면 타입 오류가
난다. `id`로 원본 배열에서 다시 찾는 방식으로 타입을 안전하게 좁혔다(런타임 비용은 배열이
작아 무시할 만하다).
