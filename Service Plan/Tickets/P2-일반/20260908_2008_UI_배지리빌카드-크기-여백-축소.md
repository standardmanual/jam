# [UI] 배지 리빌 카드 크기·내부 여백을 줄인다

## 배경 / 문제 정의

동기화 후 배지 획득 시 뜨는 `BadgeRevealCarousel`(`design-system/components/patterns/
BadgeRevealCarousel.jsx`) 카드가 사용자 육안 확인(스크린샷, "서초역" POI형 배지) 기준으로
너무 크다는 피드백. 현재 수치:

- 카드 폭 `344px`(서비스 컬럼 430px의 80%), 높이 = 폭×1.34 ≈ `461px`
- 내부 패딩 `24px`, 세로 요소 간 gap `12px`
- 이미지 영역 상한 `maxHeight: 46%`

오케스트레이터 사전 분석(코드 근거):
- 344px는 "이름 2줄+설명 3줄"이 꽉 차는 케이스를 기준으로 잡은 크기라, 이름·설명이 짧은
  카드(서초역처럼)에서는 그 여유가 그대로 빈 공간으로 남는다.
- "여백이 많다"는 인상의 실질 원인은 패딩(24px, 카드 높이의 약 10%)보다 **이미지 영역
  46% cap**일 가능성이 크다 — 정사각형에 가까운 이미지가 46%를 거의 채우고, 짧은 텍스트
  아래로 큰 빈 공간이 남는다.

## 상세 요구사항

### UI/UX 관점
- 카드 폭을 사용자 요청 70%가 아니라 **85% 선(`344px → 약 292px`)에서 시작**한다 —
  70%(≈241px)는 텍스트가 긴 케이스(이름 2줄+설명 3줄)에서 답답해질 위험이 있다고
  오케스트레이터가 판단했고, 사용자가 이 판단에 동의해 진행을 승인함.
- `NEIGHBOR_OFFSET_RATIO`·`NEIGHBOR_DEPTH_PX`·`NEIGHBOR_ROTATE_DEG` 등은 `cardWidth`에
  비례하는 상수라 폭 하나만 바꾸면 캐러셀 전체가 따라온다 — 별도 조정 불필요(코드 구조
  확인 완료).
- 내부 여백은 패딩(24px)·gap(12px) 자체보다 **이미지 영역 상한(46%)을 낮추는 쪽**을
  우선 시도한다 — 긴 설명 케이스는 그대로 두고 짧은 케이스만 조밀해지는 효과를 노린다.
  실측 후 패딩·gap 자체도 줄일 필요가 있으면 함께 조정.
- 렌더 결과를 로컬 Storybook(`npm run storybook`, :6006)에서 **극단 케이스까지** 확인한다:
  - 이름 1줄+설명 1줄(서초역 케이스, 여백 문제의 근원)
  - 이름 2줄+설명 3줄(텍스트가 가장 긴 케이스 — 축소가 답답해지지 않는지)
  - 등급 칩·Lv.N 칩·×N 반복 획득 칩 각각
  - 이미지 없음(FALLBACK_ICON) 케이스
  - 이웃 카드(peek) 3장+ 순환에서 시각적으로 어색하지 않은지

### 서비스/코드베이스 관점
- `BadgeRevealCarousel.jsx`의 `cardWidth` 기본값·`BadgeCard` 함수의 패딩·gap·이미지
  `maxHeight` 값을 조정한다.
- 이 컴포넌트는 서비스가 실제로 쓰는 **연결된 컴포넌트**다(`BadgeRevealOverlay.tsx`가
  `@ds/components/patterns/BadgeRevealCarousel`을 직접 import). `.claude/skills/
  jam-work/SKILL.md` 1.6절 "연결된 컴포넌트 9종" 목록에는 빠져 있다 — 이미 티켓
  `20260908_0920`(P3, 문서 정리)이 이 낡은 목록 갱신을 다루고 있으므로 이번 티켓에서
  중복 처리하지 않는다. 완료 기록에는 "연결된 컴포넌트"로 명시한다.

## 구현 계획
1. `cardWidth` 기본값 344 → 292(85%) 조정
2. `BadgeCard`의 이미지 영역 `maxHeight: '46%'`를 낮춰(1차 시도 값은 개발자 판단, 예 38~40%)
   짧은 텍스트 케이스의 빈 공간을 줄인다
3. 로컬 Storybook으로 위 극단 케이스 전수 실측
4. 필요하면 패딩(24px)·gap(12px)도 미세 조정

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `cardWidth` 기본값을 344px(컬럼 430px의 80%) → 292px(약 85%)로 축소. `NEIGHBOR_*` 상수는
  모두 `cardWidth`에 비례하는 구조라 별도 조정 없이 캐러셀 전체가 따라왔다.
- `BadgeCard` 이미지 영역 상한을 `maxHeight: 46%` → `38%`로 낮췄다. 짧은 텍스트(이름 1줄+
  설명 1줄, "서초역" 케이스)에서 이미지 아래 남던 빈 공간을 줄이는 것이 목적이며, 긴 텍스트
  케이스(이름 2줄+설명 3줄)는 이미지가 먼저 양보하는 flex 구조(`flex: 1 1 auto`, 텍스트는
  `flexShrink: 0`)가 그대로라 텍스트 잘림 회귀는 없다.
- 패딩(24px)·gap(12px)은 이번 조정으로 별도 변경하지 않았다 — 이미지 cap 축소만으로 짧은
  텍스트 케이스의 여백 문제가 실질적으로 해소된다고 판단(코드 구조상 이미지가 46%를 거의
  채우던 것이 38%로 낮아지면 카드 높이(폭×1.34) 대비 약 62px 줄어드는 효과).
- Storybook 스토리에 짧은 텍스트 극단 케이스(`ShortText`, "서초역" 케이스)를 신규 추가해
  회귀 방지 커버리지를 넓혔다. 기존 `LongNameAndDescription`(이름 2행+설명 3행) 스토리가
  긴 텍스트 케이스를 이미 커버한다.
- `BadgeRevealCarousel.jsx`는 `BadgeRevealOverlay.tsx`가 직접 import하는 **연결된 컴포넌트**다.

### 주요 의사결정 / 핵심 메모
- 패딩·gap은 이번 1차 조정에서 건드리지 않았다. 이미지 cap만으로 여백 문제의 실질 원인을
  해소한다는 티켓의 가설을 그대로 따랐고, 리뷰 단계 실측에서 부족하면 후속으로 조정.
- cardWidth 축소값은 티켓이 지정한 292px(85%)를 그대로 사용, 별도 판단 없음.
- 이미지 maxHeight 축소값은 티켓이 "38~40%선에서 시작"이라 지정한 범위의 하단인 38%로
  잡았다 — 여백 축소 효과를 더 크게 보기 위함. 리뷰에서 과하다는 피드백이 있으면 40%로
  올리는 것도 고려 가능.
