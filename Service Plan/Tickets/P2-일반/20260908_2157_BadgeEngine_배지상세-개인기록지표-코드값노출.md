# [BadgeEngine] 배지 상세 획득조건에 personal_record_break_metric 코드값 노출

## 배경 / 문제 정의
액티비티배지 '발끝의 한계' 상세페이지(`/badges/[id]`)의 「획득 조건」 문구에
"개인 기록 갱신 1회 이상 · 개인 기록 지표 single_distance_km"처럼 `personal_record_break_metric`
필드의 값이 코드값(`single_distance_km` 등)으로 그대로 노출된다. 사용자에게 보이면 안 되는
내부 값이다.

원인: `jam-web/src/lib/badgeConditionText.ts`는 `USER_PHRASE`에 override가 없는 필드를
`phraseOf()`의 일반 조립 규칙(`${meta.label} ${value}${unit}`)으로 처리한다.
`personal_record_break_metric`은 이 override가 없어서 코드값이 그대로 붙는다.

반면 `conditionRegistry.ts`의 `detail`(어드민 상세용)은 이미
`PERSONAL_RECORD_METRIC_FORM_OPTIONS.find(...)?.label`로 사람이 읽는 라벨을 찾는 로직이
있지만, `PERSONAL_RECORD_METRIC_FORM_OPTIONS`가 export되지 않아 `badgeConditionText.ts`에서
재사용할 수 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/lib/badge-engine/conditionRegistry.ts`의 `PERSONAL_RECORD_METRIC_FORM_OPTIONS`를
  export한다.
- `jam-web/src/lib/badgeConditionText.ts`의 `USER_PHRASE`에 `personal_record_break_metric`
  override를 추가해, 코드값이 아니라 `PERSONAL_RECORD_METRIC_FORM_OPTIONS`의 `label`로
  문구를 조립한다 (예: "개인 기록 지표: 한 번의 거리").
- `formatBadgeConditionText`·`formatBadgeConditionSpec` 양쪽 모두 이 override를 공유하므로
  자동으로 함께 고쳐진다.
- 같은 문제 유형(레지스트리에 select 라벨이 있는데 `badgeConditionText.ts`에서 값만 노출되는
  다른 필드)이 있는지 함께 점검한다.

## 구현 계획
1. `conditionRegistry.ts`에서 `PERSONAL_RECORD_METRIC_FORM_OPTIONS`에 `export` 추가
2. `badgeConditionText.ts`에서 이를 import해 `USER_PHRASE.personal_record_break_metric`에
   라벨 조회 override 작성 (레지스트리 `detail` 로직과 동일한 폴백 패턴: 못 찾으면 원래 값)
3. 기존 테스트(`badgeConditionText.test.ts`)에 이 필드가 포함된 케이스가 있는지 확인하고,
   없으면 회귀 테스트 추가
4. 배지 상세 페이지 실렌더로 '발끝의 한계' 등 해당 조건을 쓰는 배지에서 라벨이 정상 표시되는지
   확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `conditionRegistry.ts`의 `PERSONAL_RECORD_METRIC_FORM_OPTIONS`(코드값→한국어 라벨 매핑)를
  export했다.
- `badgeConditionText.ts`의 `USER_PHRASE`에 `personal_record_break_metric` override를 추가해,
  레지스트리 `detail`과 같은 폴백 패턴(`find(...)?.label ?? 원래 값`)으로 라벨을 조립하도록
  고쳤다. `formatBadgeConditionText`·`formatBadgeConditionSpec` 양쪽 모두 이 맵을 공유하므로
  자동으로 함께 고쳐졌다.
- 같은 유형(레지스트리에 select 라벨이 있는데 `badgeConditionText.ts`가 값만 노출)의 다른 필드가
  있는지 점검 — `season`은 이미 `SEASON_RANGE` override가 있고, `activity_type`은 표기 규칙상
  침묵(`() => null`) 처리라 문제없음. 추가 override가 필요한 필드는 없었다.
