# [UI] 컬렉션 슬롯에 장착된 아이템배지, 동일 배지 미장착 개체가 있으면 "교체" 버튼 노출

## 배경 / 문제 정의
컬렉션 상세(`/collections/[id]`) 슬롯 그리드에서, 이미 장착된 칸은 "해제" 버튼만 보여준다.
그런데 사용자가 같은 배지(badge_id)를 여러 개 보유하고 있고 그중 일부가 인벤토리에
미장착 상태로 남아 있는 경우, 지금 장착된 개체를 다른 개체로 바꿔 끼우고 싶을 수 있다.
현재는 이 경로가 없다 — 일단 해제한 뒤 다시 장착 버튼을 눌러 후보를 골라야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점 — 이미 확인된 사실
- `src/app/(main)/collections/[id]/page.tsx:193-224`에서 `badgeSlots[].candidates`는
  이미 "이 배지의 미장착 개체 후보 전체"로 구성돼 있다(`item.slotted_in`이 없는 것만 담음,
  197행). **슬롯이 이미 채워진 상태에서도 candidates 배열은 비어있지 않을 수 있다** — 즉
  서버 쪽 데이터는 이미 이 기능에 필요한 걸 다 주고 있고, 프론트가 안 쓰고 있을 뿐이다.
- `src/app/(main)/collections/[id]/SlotGrid.tsx`의 `isSlotted && !readOnly` 분기(272-282행)는
  지금 무조건 "해제" 버튼만 그린다. `badgeSlot.candidates.length > 0`일 때는 이 자리를
  "교체" 버튼으로 바꿔야 한다(해제 버튼 자체를 없애는 게 아니라, 같은 자리를 대체 — 교체
  흐름 안에 "그냥 해제"도 포함되지 않으므로, 교체 시트에 "해제하기" 옵션을 별도로 둘지는
  구현 단계에서 판단할 것. 최소 요구사항은 "교체 버튼 노출 + 선택 시트"이다)
- 이미 있는 `ItemCandidateSheet`(`src/components/inventory/ItemCandidateSheet.tsx`)와
  `SlotGrid.tsx`의 다중 후보 선택 흐름(`handleSlotButton`→`selectingBadgeId`→
  `handleSelectCandidate`, 187-236행)이 정확히 같은 UI 패턴(배지 이름 + 후보 리스트에서
  하나 선택)이다. **신규 컴포넌트를 만들지 말고 이 흐름을 재사용/확장할 것.**
- ⚠️ **백엔드 원자성 문제 — 반드시 확인·해결할 것**: `POST /api/itembooks/[id]/slot`이
  호출하는 `slot_item_into_book()` RPC(마이그레이션 111)는 `user_item_book_slots`에
  INSERT하는데, 같은 배지가 이미 슬롯에 있는 상태에서 다시 호출하면 (badge_id에 유니크
  제약이 있다면) INSERT가 실패해 의미 없는 `slot_insert_failed`(500) 에러가 난다.
  프론트에서 "해제 API 호출 → 성공하면 장착 API 호출"처럼 순차 호출로 흉내내면, 두 번째
  호출이 실패했을 때 슬롯이 빈 채로 남는 정합성 문제가 생긴다. 이 프로젝트는 108/109/111
  마이그레이션에서 "원자적 소유권 이전"을 반복 원칙으로 삼아왔다(SELECT ... FOR UPDATE
  기반 단일 RPC) — 같은 원칙을 따라 **새 원자적 RPC(예: `swap_item_in_book`)를 만들어
  기존 슬롯 해제 + 새 개체 장착을 한 트랜잭션으로 처리할 것**을 강력히 권장한다. 순차 호출로
  갈 경우 실패 시 사용자에게 정확한 상태(교체 실패, 기존 개체 유지/해제됨)를 알려야 한다 —
  판단 근거를 완료 기록에 남길 것.
- **DB 마이그레이션이 필요하면 SQL 파일만 작성하고 절대 직접 실행하지 말 것.** 실행은
  사용자 승인을 받은 뒤 오케스트레이터가 처리한다(프로젝트 절대 규칙 5번).

### UI/UX 관점
- "교체" 버튼 문구는 `d.itembooks`에 새 키(예: `swapButton: '교체'`)로 추가.
  `UX_WRITING_GUIDELINE.md` 대조해 톤 확인할 것
- "교체" 버튼을 누르면 기존 `ItemCandidateSheet`가 열리고, 후보 중 하나를 고르면 즉시
  교체 요청이 나가야 한다(기존 `handleSelectCandidate`와 같은 패턴 — 탭 즉시 선택 톤,
  성공 시에만 시트 닫힘, 실패는 시트 안에서 표시)
- 시트의 안내 문구(`bodyText`, 현재 `selectItemBody`)가 "장착할 개체를 골라주세요" 류라면
  교체 맥락에서는 어색할 수 있다 — 장착/교체 공용으로 자연스러운 문구인지, 아니면 별도
  문구가 필요한지 검토할 것
- 버튼 색상: 이번 티켓 직전에 "해제" 버튼을 그레이(`--color-base-grey-600`)로 바꿨다
  (20260910_0025). "교체"는 장착(원래 색)과 해제(그레이) 사이의 성격이라 어느 톤을 쓸지
  판단해 근거를 남길 것 — 기본값은 장착과 같은 `--color-primary`를 권장(양성 액션에 가까움)

## 구현 계획
1. `page.tsx`에서 이미 내려주는 `candidates`(미장착 후보)를 슬롯이 찬 상태에서도 그대로

   확인해야 하므로, 기존 "후보 1개면 즉시 장착" 자동 처리와는 다르게 갈 가능성이 높다.
   판단 근거를 완료 기록에 남길 것)
3. 백엔드: 원자적 교체 RPC 신설(권장) 또는 순차 호출 방식 채택 — 판단 근거 명시
4. 새 API 라우트 또는 기존 `/api/itembooks/[id]/slot`에 교체 전용 메서드 추가 검토
5. 로컬 실렌더로 "같은 배지 2개 보유 → 1개 장착 → 교체 버튼 → 시트에서 다른 개체 선택 →

### 주요 의사결정 / 핵심 메모
1. **순차 호출 대신 원자적 RPC를 신설했다.** `user_item_book_slots`는
   `UNIQUE(user_id, item_book_id, badge_id)` 제약을 갖고 있어(`017_item_book_slots.sql`),
   "해제 → 장착" 두 번의 REST 호출로 흉내내면 두 번째 호출(재INSERT)이 이 제약을
   그대로 어겨 `slot_insert_failed`가 날 리스크가 있었다. `swap_item_in_book()`
   (마이그레이션 151)은 슬롯 row를 삭제·재삽입하지 않고 `inventory_item_id` 컬럼만
   갈아 끼우므로 이 제약을 아예 건드리지 않는다. 락 순서는 111의 선례(락 표면 최소화,
   `inventory` 테이블은 건드리지 않음 — 교체는 순인벤토리 칸 변화가 0이므로 잠글 이유가
   없다)를 따랐다.
2. **후보가 1개뿐이어도 항상 시트를 연다(자동 즉시 교체 없음).** 장착 버튼의 "후보 1개면
   즉시 장착" 지름길과 다르게 갔다 — 교체는 이미 뭔가 장착된 상태에서 그것을 다른 것으로
   "바꾸는" 행동이라, 사용자가 무엇으로 바뀌는지 보지 못한 채 실행되면 당혹스러울 수
   있다. 장착은 빈 칸을 채우는 최초 액션이라 자동화의 부담이 적지만, 교체는 이미 있는
   것을 대체하는 액션이라 확인 지점을 하나 더 두는 편이 안전하다고 판단했다.
3. **버튼 색상은 `--color-primary`(장착과 동일)를 채택했다.** 티켓의 기본 권장을 그대로
   따랐다 — 교체는 "없앤다"가 아니라 "다른 걸로 채운다"는 점에서 장착에 더 가까운
   양성 액션이다. 단, 이 판단 시점에 `SlotGrid.tsx`의 "해제" 버튼은 아직 그레이로
   바뀌어 있지 않았다(아래 alerts 참고) — 색상 대비를 실제로 확인하려면 20260910_0025가
   먼저 머지돼야 한다.
4. **(수정됨) 시트 안에 "해제하기" 옵션을 추가했다.** 인터페이스 리뷰가 이 구현을
   레이아웃 회귀(better-layout — Regression)로 지적했다: "교체"가 "해제" 버튼 자리를
   완전히 대체하면서, 후보가 있는 상태에서 그냥 해제만 하고 싶은 사용자의 경로가 아예
   사라졌었다. `ItemCandidateSheet`에 선택적 `secondaryAction` prop(라벨·클릭·비활성
   여부)을 추가해 교체 시트에서만 하단에 "해제하기" 보조 버튼을 노출한다(장착·드랍·픽업
   시트는 이 prop을 넘기지 않아 영향 없음). 클릭하면 시트를 연 대상(`sheetView`)을 그대로
   써서 기존 DELETE 호출을 실행하고, 실패는 그리드 배너가 아니라 시트 안(`sheetError`)에
   표시한다 — 교체 실패와 동일한 원칙(20260907_2059, 장착 모드에서는 그리드가 화면 밖일
   수 있다). 그리드의 «해제» 버튼과 로직을 공유하도록 `handleUnslot`을
   `requestUnslot`(공통, 실패 사유를 문자열로 반환)과 `handleUnslot`(그리드 배너용)으로
   나누고, `handleSheetUnslot`(시트 배너용)을 추가했다.
