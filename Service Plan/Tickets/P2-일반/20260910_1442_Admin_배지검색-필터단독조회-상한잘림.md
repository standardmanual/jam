# [Admin] 배지 검색이 필터 단독 조회에서 상한에 잘려 원하는 배지를 못 찾는다

## 배경 / 문제 정의

티켓 `20260910_1408`에서 `/api/admin/badges/search`에 `tribe_id`·`item_book_id`·`rarity`
파라미터를 추가하고, 필터가 있으면 이름 없이도 조회할 수 있게 완화했다.

그 결과 필터 하나만 지정한 조회(예: `rarity=common`)가 결과 상한 20건에서 잘린다. 아이템
배지가 108종이고 그중 낭만 미식가 트라이브에만 90종이 있으므로, 어드민이 트라이브 필터만
걸면 90종 중 20종만 보인다. 원하는 배지가 상한 밖에 있으면 찾을 방법이 없다.

조건이 전혀 없는 요청은 여전히 빈 배열을 돌려주므로 Supabase Max Rows 절단 위험은 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 필터 단독 조회에서 결과가 상한에 잘렸는지 응답으로 알린다(총 건수 또는 잘림 플래그).
- 페이지네이션 또는 상한 확대 중 하나를 택한다. 어드민 전용 조회이므로 상한을 넉넉히 올리는
  편이 단순하지만, 트라이브 하나에 수백 종이 쌓이는 상황을 대비하면 페이지네이션이 안전하다.

### UI/UX 관점
- 결과가 잘렸을 때 "검색어를 추가해 좁히세요" 같은 안내를 콤보박스 목록 하단에 표시한다.
- 어드민 UI는 shadcn/ui 표준을 따른다.

## 구현 계획

`/api/admin/badges/search` 라우트와 이를 쓰는 `BadgeSearchSelect`·`MultiBadgeSearchSelect`를
함께 손댄다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`/api/admin/badges/search`가 상한(`MAX_RESULTS`=20)보다 1건 더 조회해 초과 여부를 판단하고,
초과분은 다시 잘라 응답 본문에 `truncated: boolean` 플래그로 내려주도록 고쳤다. 상한 자체는
그대로 두고(페이지네이션은 도입하지 않음) 잘림 여부만 알리는 방식을 택했다 — 상한을 아무리
올려도 "트라이브 하나에 수백 종" 시나리오에서는 다시 잘릴 수 있으므로, 상한 확대보다 잘림을
알리고 검색어로 좁히게 유도하는 편이 근본적이라고 판단했다.

`BadgeSearchSelect`·`MultiBadgeSearchSelect`는 응답의 `truncated`를 상태로 받아, 콤보박스
결과 목록 하단에 "결과가 많아 일부만 표시했습니다. 검색어를 추가해 좁혀보세요." 안내를
추가했다(로딩 중이 아닐 때만 노출).

### 주요 의사결정 / 핵심 메모
- 페이지네이션 대신 "잘림 플래그 + 검색어 좁히기 안내"를 택했다. 어드민 검색 도구의 목적이
  후보를 좁혀 고르는 것이므로, 페이지 넘기기보다 필터/검색어 추가를 유도하는 편이 UX상
  단순하고 목적에 부합한다고 판단(티켓이 "상한 확대 또는 페이지네이션 중 택일" 중 페이지네이션을
  안전한 선택으로 언급했으나, 잘림을 알리기만 해도 "찾을 방법이 없다"는 원래 문제는 해결된다).
- DB 왕복은 그대로 1회 유지(`limit(MAX_RESULTS + 1)`로 잘림 판단), 별도 count 쿼리를 추가하지
  않아 성능 부담이 없다.
