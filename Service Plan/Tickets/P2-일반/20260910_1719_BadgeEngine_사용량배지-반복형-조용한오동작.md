# [BadgeEngine] 사용량 배지(팔로워·팔로잉·일일동기화)에 반복형을 만들면 조용히 등급형처럼 오동작한다

## 배경 / 문제 정의

티켓 [20260910_1557](../P1-중요/20260910_1557_BadgeEngine_JAM카테고리-서비스사용량-배지엔진-신설.md)
(`/jam-work` engine 파이프라인)의 게이트 리뷰·개선 리뷰 양쪽에서 독립적으로 발견한 범위 밖 이슈.

신설된 `usageBadges.ts`는 등급형(rarity 있음)·레벨형(level 있음, family_key로 묶임) 두 종류만
지원한다 — 티켓 20260910_1557의 Acceptance Criteria 11이 이 둘만 명시했기 때문에 범위 판단
자체는 합리적이다. 문제는 **어드민 폼(`conditionFormFields.ts`)에 이 제약에 대한 안내가 전혀
없다**는 점이다.

어드민이 `follower_count`/`following_count`/`daily_sync_count` 조건에 `repeat_count`(반복
획득)까지 같이 넣어 반복형 배지를 만들면, 에러 없이 저장은 되지만 `isLeveledBadge()`가
`rarity == null` 여부로만 이진 판정하기 때문에 실제로는 등급형 경로(`gradedByName`)로 흘러가
"이름 그룹 내 최상위 tier 1개만 발급, `repeat_count` 조건은 무시, 재발급 없음"으로 조용히
오처리된다. 저장 시점 에러도, 발급 시점 로그도 없어 어드민이 원인을 알기 어렵다.

## 상세 요구사항

### 서비스/코드베이스 관점

두 가지 방향 중 하나(또는 둘 다)로 처리한다.

1. **저장 시점 가드**: 어드민 폼에서 `follower_count`/`following_count`/`daily_sync_count` 중
   하나와 `repeat_count`를 함께 저장하려 하면 명시적으로 막고, "이 지표는 등급형·레벨형만
   지원합니다"라는 안내를 보여준다 (`findBadgeConditionSaveError`,
   `src/lib/admin/badge-validation.ts` 확장 후보).
2. **문서·도움말**: 어드민 폼(`conditionFormFields.ts` 또는 `BadgeForm.tsx`)의 해당 조건 입력
   근처에 "반복형 미지원" 안내 문구를 추가한다.

우선순위는 1이 근본적이지만(조용한 오동작 자체를 막음), 비용이 크면 2만으로도 최소한 "왜
안 되는지"는 어드민이 알 수 있게 된다.

## 구현 계획
> 지금은 발견 기록 단계 — 실제 구현 착수 시 위 두 방향 중 범위를 확정한다.

1. `findBadgeConditionSaveError`에 "measurable/meta 사용량 키 + `repeat_count` 동시 존재
   금지" 가드 추가 검토
2. 어드민 폼 도움말 문구 추가
3. 회귀 테스트: 기존 `repeat_count`를 쓰는 다른 배지(활동 기반)에는 영향 없는지 확인
