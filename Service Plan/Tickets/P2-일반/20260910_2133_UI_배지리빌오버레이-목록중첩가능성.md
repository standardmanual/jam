# [UI] 배지 리빌 오버레이 — 목록 페이지에서 여러 인스턴스 동시 노출 가능성

## 배경 / 문제 정의

티켓 [20260910_2056](20260910_2056_BadgeEngine_JAM카테고리-팔로우리빌애니메이션연동.md)
인터페이스 리뷰(MEDIUM)에서 발견된 범위 밖 이슈.

팔로워/팔로잉 목록 페이지(`[username]/followers`·`following`)는 행마다 독립된
`FollowButton` 인스턴스를 렌더하고, 각 인스턴스가 로컬 `revealOpen` state로
`BadgeRevealOverlay`를 직접 연다 — N행이면 이론상 N개의 오버레이가 동시에 존재할 수 있다.

`BadgeRevealCarousel`은 `document.body` 포털이 아니라 제자리에서
`position:fixed; zIndex:60`으로 그려진다(`design-system/components/patterns/
BadgeRevealCarousel.jsx:373-375`, `createPortal` 미사용). 프로젝트 z-index 문서
(`Service Plan/Specs/PRD/2026-08-15 DESIGN_RENEWAL_SPEC.md:325-328,385-387`)의
"동일 z에서는 DOM 순서가 승자를 정한다" 규칙에 따라, 목록에서 두 사람을 연달아 팔로우해
각각 배지를 얻으면 두 오버레이가 동시에 열릴 수 있고 위로 뜨는 쪽은 클릭 순서가 아니라
목록 배열 순서로 정해진다. **가려진 쪽은 화면에 안 보이는 채로 `aria-live` 공지와 배경
스크롤락만 남는다** — 사용자가 오버레이를 닫을 길이 없는 상태에 빠질 수 있다.

`SyncButton`(TopNav의 단일 전역 인스턴스)은 이 문제가 없었는데, 이번 티켓으로 처음으로
"여러 인스턴스가 동시에 뜰 수 있는" 위치에 `BadgeRevealOverlay`가 놓였다.

## 상세 요구사항

### 서비스/코드베이스 관점

**제안 변경**

리빌 상태를 개별 `FollowButton` 인스턴스가 아니라 목록 페이지 레벨로 끌어올린다 —
`SyncButton`이 `TopNav`에 단일 인스턴스로 두는 것과 같은 패턴. `FollowButton`은 획득
배지를 콜백(`onEarnBadges` 등)으로 상위(목록 페이지)에 전달하고, 오버레이는 페이지에
하나만 둔다.

### 구현 계획

1. `[username]/followers/page.tsx`·`following/page.tsx`(또는 공용 목록 컴포넌트)에
   `revealOpen`/`earnedBadges` state와 `BadgeRevealOverlay`를 페이지 레벨로 이동
2. `FollowButton`에 콜백 prop 추가, 내부 오버레이 렌더 제거
3. 연달아 팔로우해 여러 배지를 얻는 경우의 큐잉/병합 정책 결정(구현 단계 판단 — 순차 표시
   vs 합쳐서 한 번에 표시)

### Acceptance Criteria

1. 목록에서 두 사람을 연달아 팔로우해 각각 배지를 얻어도 오버레이가 한 번에 하나만 뜬다.
2. 오버레이를 닫으면 다음 대기 중인 배지(있다면)가 정상적으로 이어서 뜨거나, 합쳐서 한 화면에 표시된다(정책은 구현 단계에서 확정).
3. 기존 단일 팔로우 → 단일 리빌 흐름에는 회귀가 없다.
