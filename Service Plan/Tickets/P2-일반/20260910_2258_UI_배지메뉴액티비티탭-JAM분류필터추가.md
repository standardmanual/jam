# [UI] 배지 메뉴 액티비티 탭 — JAM! 분류 필터 추가

## 배경 / 문제 정의

`badges.admin_category='jam'`인 JAM! 배지 3종(팔로워 수·팔로잉 수·일일 동기화 횟수 기반
서비스 사용량 배지)은 `type='activity'`이지만 `activity_types=[]`라 실제 종목이 없다.
일반 유저가 보는 "배지 메뉴 > 액티비티 탭"(`/badges`, `BadgesClient.tsx`)의 분류 필터가
`ACTIVITY_TYPE_ORDER`(35행 — 달리기/자전거/트레일러닝/등산/걷기 5개 고정)로 하드코딩돼
있어, JAM! 배지는 특정 종목을 선택하면 사라지고 "전체" 필터에서만 보인다.

**"배지 트리"(`/badges/tree`, `BadgeTreeClient.tsx`)와는 다른 화면이다** — 배지 트리는
미획득 배지를 포함한 전체 종목별 계열 트리·진행률 시각화를 전담하며, JAM! 배지는 그쪽에
당분간 노출하지 않는다는 원칙을 그대로 유지한다. 이번 티켓은 "이미 획득한 배지만 보여주는"
`/badges` 화면의 필터 옵션에만 해당한다.

### UI 탐색·재사용 판정 (1.5단계, 오케스트레이터 직접 수행)

해당 필터(`BadgesClient.tsx:210-219`)는 MODULAR 컴포넌트가 아니라 네이티브 `<select>` +
유틸리티 클래스로 짜인 **서비스 전용 구현**이다. MODULAR에 `Select`(`components/forms/
Select.jsx`)가 이미 존재하지만, 이번 작업은 신규 UI 도입이 아니라 기존 select에 옵션 값
하나를 추가하는 확장이므로 MODULAR 컴포넌트로 교체할 범위가 아니다(컴포넌트 마이그레이션은
이번 티켓 목적과 무관 — 필요하면 별도 `ds` 유형 티켓으로 검토). **판정: 기존 서비스 전용
구현을 그대로 확장한다.**

## 상세 요구사항

### 서비스/코드베이스 관점

1. `BadgesClient.tsx:35` `ACTIVITY_TYPE_ORDER`에 JAM!에 대응하는 여섯 번째 식별자를
   추가한다. `ActivityType`(`@/types/database`)이 DB `activity_types` 컬럼 값과 결합된
   타입이라, JAM!을 이 유니온에 직접 추가할지 별도 sentinel 값(예: `'jam'`)으로 필터 상태
   타입만 넓힐지는 구현 단계에서 타입 영향 범위를 확인하고 판단한다.
2. `BadgesClient.tsx:170-174` 필터링 로직(`badge.activity_types.includes(activityFilter)`)에
   JAM! 선택 시 분기를 추가한다 — `activity_types`가 아니라 배지의 `admin_category==='jam'`
   여부로 판정해야 한다(현재 `BadgesClientProps`에 이 필드가 클라이언트로 전달되는지 먼저
   확인 — 안 되어 있으면 서버 컴포넌트 조회 쿼리·prop 전달 경로도 함께 넓힌다).
3. `jam-web/src/lib/utils.ts:33-40` `ACTIVITY_TYPE_LABELS`에 "JAM!" 라벨을 추가한다.
4. 분류 필터 select(210-219행)의 옵션 목록(216-218행 map)이 새 식별자를 자동으로
   순회하도록 되어 있으므로 `ACTIVITY_TYPE_ORDER`·`ACTIVITY_TYPE_LABELS`만 갱신하면
   select 자체는 추가 수정이 필요 없을 가능성이 높다 — 실제 렌더로 확인한다.

### UI/UX 관점

- JAM! 필터 선택 시 배지 카드 그리드(`BadgeGridCard`)가 다른 종목과 동일한 렌더 경로를
  타는지 확인한다(별도 처리 없이 기존 그리드 로직을 그대로 재사용해야 한다).
- 배지 상세(`/badges/[id]`)·프로필 배지 탭(`ProfileClient.tsx`)·배지 트리(`/badges/tree`)는
  이번 범위와 무관하다 — 손대지 않는다.

## 구현 계획

`ACTIVITY_TYPE_ORDER`·`ACTIVITY_TYPE_LABELS`·필터링 로직 세 지점을 함께 고쳐야 필터가
정상 동작한다(하나만 고치면 옵션은 뜨지만 결과가 비거나, 옵션 자체가 안 뜬다). `admin_category`
필드가 클라이언트 props까지 전달되는 경로 존재 여부를 가장 먼저 확인한다.

## Out of Scope

- 배지 트리(`/badges/tree`) 노출 — 원칙대로 유지, 변경 금지
- MODULAR `Select` 컴포넌트로의 교체
- `activity_types` DB 컬럼 자체에 `'jam'` 값을 채우는 것 — JAM! 배지는 계속 `[]`로 둔다
