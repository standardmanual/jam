# [Feature] 홈 피드 랭킹보드 노출

> `to-prd` 스킬(탐색 → 테스트 경계 스케치 → PRD 작성) 프로세스로 작성했다. 원본 스킬은
> 완성된 PRD를 이슈 트래커에 발행하도록 되어 있으나, JAM!은 이슈 트래커 대신 이 티켓
> 체계를 쓰므로 그 부분만 `jam-docs` 규칙으로 바꿔 적용했다. 원본 스킬 지침에 따라
> **파일 경로·코드 스니펫은 의도적으로 넣지 않았다** — 빨리 낡기 때문에, 실제 구현
> 시점에 코드를 보고 정한다.

## 배경 / 문제 정의

지금은 미션의 순위 경쟁 현황을 미션 상세 화면(`/missions/[id]/status`)에 들어가야만 볼 수
있다. 앱의 첫 화면인 홈 피드(투데이 컨텐츠)에는 노출되지 않아, 경쟁 요소가 있다는 사실
자체를 미션 상세를 열어보기 전까지는 알기 어렵다. 운영자 입장에서도 "지금 이 미션 경쟁이
불붙었다"는 걸 홈 화면에서 큐레이션해 보여줄 방법이 없다.

목표는 운영자가 어드민에서 특정 조건의 랭킹을 만들어두면, 투데이 컨텐츠 카드 하나로
홈 피드에 노출할 수 있게 하는 것이다. 다만 이번 요청에는 지금 바로 만들 수 있는 범위와,
아직 뒷받침하는 기능이 없어 별도 설계가 필요한 범위가 섞여 있다 — 이 둘을 가르는 것이
이 PRD의 핵심 목적이다.

## 상세 요구사항

### User Stories

**운영자(어드민)**
1. As an 운영자, I want 특정 미션을 골라 랭킹모드를 생성, so that 그 미션의 순위를 홈
   피드에도 노출할 수 있다.
2. As an 운영자, I want 랭킹모드의 미션 선택 목록에 랭킹형이 아닌 미션(성취형·개인형)이
   아예 안 뜨길, so that 순위 개념이 없는 미션을 실수로 랭킹으로 노출하지 않는다.
3. As an 운영자, I want 랭킹 집계 시작·종료 일시를 지정, so that 원하는 기간의 데이터만
   반영된 순위를 보여줄 수 있다.
4. As an 운영자, I want 투데이 컨텐츠 카드를 만들 때 카드 타입 중 하나로 "랭킹보드"를
   고르고 만들어둔 랭킹모드를 연결, so that 원하는 발행 일정에 맞춰 노출할 수 있다.
5. As an 운영자, I want 랭킹보드 카드에 제목·설명을 직접 입력, so that 어떤 경쟁인지
   맥락을 유저에게 전달할 수 있다.
6. As an 운영자, I want 발행 전에 랭킹보드가 실제로 어떻게 보일지 미리보기로 확인,
   so that 데이터가 비정상인 채로 유저에게 노출되는 걸 막을 수 있다.
7. As an 운영자, I want 랭킹모드 하나를 여러 투데이카드에서 재사용, so that 같은 경쟁을
   다른 시점에 다시 노출할 때 매번 새로 설정하지 않아도 된다.
8. As an 운영자, I want 랭킹모드에 연결된 미션이 삭제되거나 랭킹형이 아니게 바뀌면
   경고를 받길, so that 깨진 랭킹보드가 그대로 노출되는 사고를 막을 수 있다.

**앱 유저**
9. As an 앱 유저, I want 홈 피드에서 랭킹보드 카드를 보면, so that 미션 상세로 들어가지
   않아도 지금 순위 경쟁이 어떻게 돌아가는지 바로 알 수 있다.
10. As an 앱 유저, I want 랭킹보드 카드를 탭하면 해당 미션의 랭킹 화면으로 이동,
    so that 더 자세한 순위와 내 진행 내역을 볼 수 있다.
11. As an 앱 유저, I want 랭킹 리스트에서 내 순위가 눈에 띄게 표시되길, so that 내
    위치를 빠르게 파악할 수 있다(기존 미션 상세 랭킹 화면과 동일한 동작).
12. As an 앱 유저, I want 랭킹보드가 1·2·3위 강조 그래프 없이 리스트 형태로만 보이길,
    so that 홈 피드의 간결한 카드 레이아웃과 어울린다.
13. As an 앱 유저, I want 집계 기간이 끝난 뒤에도 랭킹보드가 최종 결과를 그대로
    유지해서 보여주길, so that 경쟁이 끝난 뒤에도 결과를 확인할 수 있다.

**(참고용 — Out of Scope로 분리한 story)**
14. As an 운영자, I want 여러 유저를 직접 지정하고 그들의 통계값(또는 조합)으로 랭킹을
    매기길, so that 미션에 매이지 않는 임의의 경쟁·큐레이션을 만들 수 있다.
15. As an 운영자, I want 배지(액티비티/아이템/체크인)를 고르고 조건값을 설정해 랭킹을
    매기길, so that 배지 수집 경쟁 같은 걸 홈 피드에 노출할 수 있다.

### 서비스/코드베이스 관점

- 지금 랭킹은 항상 특정 미션에 종속된 속성(랭킹형/성취형/개인형을 가르는 표시 방식
  설정)으로만 존재하고, 랭킹 자체가 독립된 개념으로 존재하지 않는다. 이번 작업의
  핵심은 "랭킹모드"라는 새 독립 엔티티를 만들어, 랭킹이 미션에 종속되지 않고도 존재할
  수 있게 하는 것이다 — 지금은 미션 하나만 감싸는 형태로 쓰지만, 그 구조 자체는
  이후 다른 종류의 랭킹도 얹을 수 있게 열어둔다.
- 랭킹모드는 소스 종류(미션 기반 / 유저 지정 기반 / 배지 기반)를 구분해서 갖되, 이번
  범위에서 실제로 계산 로직을 구현하는 건 미션 기반 하나뿐이다. 나머지 두 종류는
  선택지 자체는 존재해도 되지만, 계산 로직이 없으므로 실제로 동작하는 랭킹은 만들 수
  없다(또는 아예 이번 범위에서는 선택지에 노출하지 않는다 — 뒤 Implementation
  Decisions 참고).
- 미션 기반 랭킹모드의 순위 계산은 지금 미션 상세 화면이 쓰는 비교 규칙(완료 여부 →
  완료 시각 → 진행도)을 그대로 따른다. 새로 발명하지 않는다.
- 투데이 컨텐츠는 이미 "카드 종류에 따라 필요한 참조 데이터가 다른" 구조로 여러
  종류의 카드를 다루고 있다. 랭킹보드도 그 카드 종류 중 하나로 자연스럽게 추가한다.

### UI/UX 관점

- 랭킹 리스트 UI 자체(순위·이름·진행값·본인 강조)는 지금 미션 상세 화면의 것을
  최대한 그대로 따르되, 1·2·3위를 그래프로 강조하는 부분만 뺀 형태로 홈 피드 카드에
  얹는다. "그대로 재사용"이라기보다는 "리스트 부분만 뽑아서 두 화면에서 같이 쓰는"
  형태에 가깝다 — 지금 그 UI는 미션 상세 화면 전용으로 짜여 있어 데이터를 그 화면이
  직접 가져오는 구조라서, 홈 피드에서도 쓰려면 데이터를 바깥에서 넣어주는 방식으로
  바꾸는 작업이 먼저 필요하다(뒤 Implementation Decisions 참고).
- 어드민에서 "배지 선택 + 조건값"·"유저 선택 + 상태값 조합" 같은 조건 입력 UI를 새로
  만들 때 참고할 수 있는 기존 조건 입력 화면 패턴(필드를 목록으로 선언하면 폼이
  자동으로 그려지는 방식)이 이미 배지 조건 설정 화면에 있다 — 이번 범위(미션 선택)에는
  해당하지 않지만, Out of Scope 항목을 나중에 구현할 때 이 패턴을 그대로 본뜰 수 있다.

## 구현 계획

**모듈 구성**
- 랭킹 계산을 담당하는 새 도메인 모듈을 하나 둔다. 이 모듈은 "랭킹모드 정의 + 참가자
  데이터"를 받아 "순위가 매겨진 목록"을 돌려주는 순수 계산 계층으로, 소스 종류별로
  계산기를 나눈다. 이번 범위에서는 미션 계산기만 구현하고, 이 계산기는 지금 있는 순위
  비교 규칙을 그대로 감싸 재사용한다.
- 투데이 컨텐츠 쪽 모듈에 랭킹보드용 카드 종류를 하나 추가한다. 기존 카드 종류들과
  동일하게 "카드 종류 → 필요한 참조 필드 → 노출 방식"을 매핑하는 방식을 그대로 따른다.
- 어드민에 "랭킹모드 관리" 화면을 신설한다 — 생성·조회·수정, 소스 선택(이번 범위는
  미션만 실제로 선택 가능), 대상 미션 선택(랭킹형 미션만 노출), 집계 시작·종료 일시
  입력.
- 어드민 투데이 컨텐츠 생성 화면에 카드 종류 선택지로 "랭킹보드"를 추가하고, 선택 시
  기존에 만든 랭킹모드 중 하나를 고르는 입력을 추가한다.
- 랭킹 리스트를 보여주는 화면 조각을 미션 상세 전용 구현에서 분리해, 데이터(순위가
  매겨진 목록)를 바깥에서 주입받는 형태로 만든다. 상단 강조 그래프 노출 여부는
  옵션으로 분리해서, 랭킹보드 카드에서는 리스트만 쓴다. 이 분리·리팩토링이 미션 상세
  화면 자체의 기존 동작을 바꾸면 안 된다.

**인터페이스 결정**
- 랭킹모드: 제목, 소스 종류(미션/유저/배지 — 이번 범위는 미션만 계산 가능), 소스
  설정(미션 하나 참조), 집계 시작·종료 일시, 공개할 순위 인원 제한(선택, 미션 상세
  화면에 이미 있는 개념을 그대로 가져옴), 생성자, 생성일.
- 소스 설정은 소스 종류에 따라 담는 내용이 달라지는 유연한 구조로 둬서, 이후 유저
  지정·배지 지정을 추가할 때 랭킹모드 테이블 자체는 바꾸지 않고 계산기와 소스 설정
  내용만 추가하면 되게 한다.
- 투데이카드 – 랭킹모드는 카드 여러 개가 같은 랭킹모드 하나를 참조할 수 있는 단순한
  참조 관계로 둔다(카드 하나가 랭킹모드 여러 개를 갖지는 않는다).

**기술적 명확화**
- 어드민의 미션 선택 목록은 표시 방식이 랭킹형으로 설정된 미션만 노출한다.
- 랭킹모드 생성 화면에서 유저 지정·배지 지정 소스 종류를 선택지로 보여줄지, 아니면
  이번 범위에서는 아예 미션 하나만 선택 가능하게 하고 선택지 자체를 숨길지는 구현
  시점에 정한다 — 뼈대(스키마 구조)는 확장 가능하게 두되, 어드민 화면에 동작하지
  않는 선택지를 보여주는 건 혼란을 줄 수 있어 지양하는 쪽을 권장한다.

## 테스트 결정

- 좋은 테스트의 기준: 랭킹모드 정의와 참가자 데이터가 주어졌을 때 계산된 순위 목록만
  검증한다. 계산기 내부에서 데이터를 어떻게 가져오는지, 화면이 어떻게 그려지는지 같은
  구현 세부사항은 테스트하지 않는다.
- 테스트 대상: 새로 만드는 랭킹 계산기(순수 함수 — 참가자·진행값 목록을 넣으면 순위가
  매겨진 목록이 나오는 형태), 투데이 카드 종류 판별 로직에 랭킹보드 케이스가 추가된
  부분.
- 이 프로젝트의 선례: 조합(믹스) 판정과 드랍 판정처럼 복잡한 로직을 도메인 모듈의
  순수 함수로 분리하고 별도 테스트 폴더에서 단위테스트하는 관례가 이미 있다 — 새
  랭킹 계산기도 같은 결로 만든다. 투데이 카드 로직은 이미 자체 테스트가 있으니 그
  파일에 케이스를 추가하는 형태가 자연스럽다. API 라우트 자체는 이 프로젝트에서 보통
  도메인 모듈을 그대로 호출하는 얇은 통로로만 두고 별도 테스트를 두지 않는 관례이므로
  이번에도 그 관례를 따른다.
- 참고로 지금 쓰이는 미션 순위 비교 규칙에는 테스트가 없었다 — 이번에 계산기를
  분리하면서 이 로직도 함께 테스트 대상에 넣는 게 자연스럽다.

## Out of Scope

- **유저를 직접 지정하고 통계값(또는 그 조합)으로 순위를 매기는 랭킹모드.** 유저
  단위로 재사용 가능한 통계 집계와, 여러 지표를 하나의 점수로 합성하는 로직이 지금
  프로젝트에 없다. 랭킹모드의 소스 구조 자체는 이번에 확장 가능하게 만들어 두지만,
  계산 로직 구현과 "어떤 통계를 어떻게 조합할지"의 구체적인 스펙은 별도로 정한 뒤
  후속 작업으로 진행한다.
- **배지를 선택하고 조건값을 설정해 순위를 매기는 랭킹모드.** "조건값"이 보유 개수
  기준인지 획득 속도 기준인지 등 아직 정해지지 않았다. 시나리오가 한두 개 구체화된
  뒤 별도로 진행한다.
- 랭킹 결과에 대한 알림·시상 자동화(집계 종료 시 상위권 유저에게 알림을 보내는 등).
- 랭킹모드 하나를 투데이카드 이외의 다른 위치(예: 미션 상세 화면 자체의 구조 변경)에
  노출하는 것 — 이번 범위는 투데이카드의 랭킹보드 카드 종류 하나로 한정한다.

## Further Notes

- 미션 상세 화면의 지금 랭킹 UI는 그 화면 전용 API에서 데이터를 직접 가져오는
  구조라, "재사용"이 컴포넌트를 그대로 가져다 쓰는 수준이 아니라 데이터를 바깥에서
  주입하는 방식으로 바꾸는 리팩토링을 동반한다. 이 리팩토링 자체가 미션 상세 화면의
  기존 동작에 회귀를 만들지 않는 게 조건이다.
- 조사 중에 발견한 사소한 별건: PRD 문서의 배지 종류 설명에 지금은 쓰지 않는 옛
  명칭이 하나 남아 있었다(체크인 배지로 이름이 바뀐 지 오래됐는데 문서만 안 바뀜).
  이번 작업과는 무관하지만, 다음에 그 문서를 만질 일이 있으면 같이 정정하면 좋겠다.
