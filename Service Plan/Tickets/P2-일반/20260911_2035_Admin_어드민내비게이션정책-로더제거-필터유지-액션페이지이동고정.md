# [Admin] 어드민 내비게이션 정책 수정 — 로더 제거·필터 상태 유지·목록 액션 페이지 이동 고정

## 배경 / 문제 정의
> 왜 이 작업이 필요한가. 현재 상태와 기대 상태의 차이.

사용자 요청. 어드민 목록 화면의 내비게이션 동작이 불편하다는 세 가지 지적을 조사 후 정리했다.

### 1. 링크 클릭 시 로더가 매번 뜸

원인은 어드민 전용 코드가 아니라 루트 레이아웃(`jam-web/src/app/layout.tsx:49-51`)에 전역
렌더링되는 `NavigationLoader`(`jam-web/src/components/NavigationLoader.tsx`)다. 문서 전체의
`a[href]` 클릭을 감지해, 클릭 후 라우트 전환(pathname/searchParams 변경)이 1초
(`SHOW_DELAY_MS`)를 넘기면 전체 화면 오버레이(`WanderingEyesLoader`, `fixed inset-0
z-[9999]`)를 띄우는 구조다. 서비스 전체(일반 사용자 화면 + 어드민) 공용 컴포넌트이며, 어드민
목록 화면은 DB 조회가 있는 서버 컴포넌트라 1초를 넘기기 쉬워 유독 자주 노출된다.

**결정(2026-09-11, 사용자): 어드민 경로(`/admin/*`)에서만 배제한다.** 일반 사용자 화면(배지·
피드 등)의 로딩 UX는 그대로 유지한다. `NavigationLoader` 자체를 삭제하지 않고, 현재 경로가
`/admin`으로 시작하면 로더를 표시하지 않도록 조건을 추가한다.

> ⚠️ 관련 과거 이력: `NavigationLoader`는 과거 "8초 고착"·"과다 노출" 버그가 있었다
> (`Tickets/P1-중요/20260908_0536_...`, `20260908_0544_...`, `20260908_0557_...`,
> `Tickets/P2-일반/20260908_0529_...`, `Tickets/P3-낮음/20260908_0556_...`). 이번 수정은 그
> 수정 사항들을 되돌리지 않고, admin 경로만 배제하는 조건 분기를 추가하는 것이어야 한다.

### 2. 목록 필터값이 페이지 이동 후 히스토리 back 시 리셋됨 (⚠️ 2026-09-11 구현 후 철회)

> **철회(2026-09-11, 사용자)**: 아래 조사에서 지목한 6개 화면을 구현 단계에서 원본 코드로
> 재검증한 결과, 6곳 모두 목록 레벨 검색·필터 UI 자체가 존재하지 않았다(미션·레시피·포인트는
> 전량 조회, 트라이브·유저조회는 정렬 전용 표시 테이블, 게이트미션의 `query` 상태는 목록
> 필터가 아니라 폼 내부 "보상 배지 계열 검색" 위젯). 티켓 작성 시점의 조사가 부정확했다.
> 없는 필터를 "유지"할 수 없고, 신규 필터 기능을 새로 만드는 것은 이번 요청의 취지를 벗어나
> 사용자가 이번 요청을 철회했다. 아래 원 조사 내용은 기록으로만 남긴다.

조사 결과 화면별로 상태 관리 방식이 다르다.

- **URL 쿼리 동기화가 이미 있는 화면** (`useSearchParams` + `router.push`로 필터를 URL에
  반영): `badges/BadgesFilterBar.tsx`, `badge-families/BadgeFamiliesFilterBar.tsx`,
  `item-badges/ItemBadgeSearchBar.tsx`, `item-badges/[badgeId]/SerialListFilterBar.tsx`,
  `itembooks/ItemBookFilters.tsx`, `poi/PoiFilters.tsx`, `poi/review/PoiReviewFilters.tsx`.
  검색어 input은 `useState(searchParams.get('q'))`로 초기화 후 URL에 반영하는 구조라 back 시
  URL 자체는 복원되지만, 로컬 input state와의 동기화 타이밍에 따라 깜빡임이 있을 수 있다 —
  이 화면들은 **회귀 확인만** 한다(정상 동작이면 수정 불필요).
- **URL 동기화가 전혀 없어 실제로 리셋되는 화면** (로컬 `useState`만 사용, 페이지 이탈 후
  back 시 컴포넌트 리마운트로 상태 완전 초기화): `missions/MissionList.tsx`,
  `recipes/RecipeList.tsx`, `gate-missions/GateMissionManager.tsx`(`query` 상태),
  `tribes/TribesTable.tsx`, `users/UsersTable.tsx`, `points/RankingTable.tsx`. **이 화면들에
  URL 쿼리 동기화를 새로 도입한다.**

### 3. 목록에서 상세/수정 액션이 "인스턴트"(같은 페이지 내 폼 토글)로 열림 — 항상 페이지 이동으로 고정

조사 결과 대부분의 도메인(9개: badge-families, badges, item-badges, itembooks, poi,
ranking-modes, today, tribes, users)은 이미 `[id]` 라우트로 페이지 이동하는 방식이라 해당
없음. 다음 **3곳만** 같은 페이지 내 `showForm`/`editingId` 상태로 폼을 토글하는 "인스턴트"
방식이라 전환이 필요하다:

- `missions/MissionList.tsx` — 미션 상세·수정
- `recipes/RecipeList.tsx` — 레시피 상세·수정
- `gate-missions/GateMissionManager.tsx` — 게이트 미션 상세·수정

> `today/TodayPreviewModal.tsx`의 Dialog(미리보기), `poi/review/PoiReviewTable.tsx`의
> Dialog(카테고리 일괄수정), 각 폼의 `AlertDialog`(삭제 확인)는 "상세조회/수정 액션"이 아니라
> 미리보기·일괄유틸리티·확인용이므로 이번 범위에서 제외한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `NavigationLoader.tsx`(또는 이를 렌더링하는 `layout.tsx`)에 `usePathname()` 기반으로
  `/admin`으로 시작하는 경로에서는 클릭 감지·오버레이 표시를 하지 않는 조건을 추가한다.
  일반 사용자 경로의 기존 동작(딜레이·최소 노출 시간 등)은 변경하지 않는다.
- 필터 URL 동기화가 없는 6개 화면(위 목록)에 `useSearchParams`/`router.push` 기반 동기화를
  추가한다. 기존에 URL 동기화가 있는 7개 화면의 패턴(예: `badges/BadgesFilterBar.tsx`)을
  참고해 일관된 방식으로 구현한다.
- `missions`·`recipes`·`gate-missions` 3곳의 인라인 폼 토글을 `[id]` 하위 라우트(신규 상세/
  수정 페이지) 이동 방식으로 전환한다. 목록 컴포넌트에서 폼을 렌더링하던 부분을 제거하고,
  라우트 이동(`router.push` 또는 `<Link>`)으로 교체한다. 기존 폼 컴포넌트 자체(입력 필드·
  검증 로직)는 재사용하되 페이지로 옮긴다.

### UI/UX 관점 (해당 시)
- 어드민 목록 화면에서 링크 클릭 시 전체 화면 로더가 더 이상 뜨지 않아야 한다(일반 사용자
  화면은 기존과 동일하게 유지).
- 필터를 설정한 상태로 상세 페이지에 진입했다가 브라우저 뒤로가기로 돌아오면, 검색어·필터
  선택값이 그대로 남아 있어야 한다.
- 미션·레시피·게이트미션 목록에서 항목을 클릭하면 같은 화면에서 폼이 펼쳐지는 대신 별도
  페이지로 이동해야 한다.

## 구현 계획
> 어떻게 구현할지. 접근 방법, 영향 범위, 주요 변경 포인트.

1. `NavigationLoader.tsx`에 admin 경로 배제 조건 추가 (또는 `layout.tsx`에서 pathname 분기로
   컴포넌트 자체를 admin에서 마운트하지 않는 방식도 검토 — 서버/클라이언트 경계 고려해 더
   단순한 쪽으로 구현).
2. 필터 URL 동기화 없는 6개 화면에 동기화 로직 추가.
3. `missions`·`recipes`·`gate-missions` 3곳을 페이지 이동 방식으로 전환 (신규 `[id]` 라우트

4. 회귀 확인: 일반 사용자 화면(배지 상세 등)에서 기존 로더 동작이 그대로인지, admin에서는
   로더가 안 뜨는지, 필터 유지가 6개 화면에서 실제로 동작하는지, 3곳의 페이지 이동이 정상
   동작하는지 로컬 실렌더로 확인.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

1. **로더 어드민 배제**: `NavigationLoader.tsx`의 클릭 핸들러 최상단에
   `pathname.startsWith('/admin')`이면 즉시 반환하는 조건을 추가. 일반 사용자 화면의 딜레이·
   최소 노출 시간 등 기존 로직은 변경 없음.
2. **필터 상태 유지**: 철회(위 2번 절 참조). 지목한 6개 화면에 목록 레벨 필터 UI 자체가
   없어 구현하지 않음.
3. **목록 액션 페이지 이동 고정**: `missions`·`recipes`·`gate-missions` 3곳의 인라인 폼
   (`showForm`/`editingId`)을 제거하고, 폼 컴포넌트를 `MissionForm.tsx`/`RecipeForm.tsx`/
   `GateMissionForm.tsx`로 분리해 `/new`·`/[id]` 라우트에서 렌더링하도록 전환. 목록
   컴포넌트는 표와 "생성" 링크·삭제 액션만 남기고 "수정"은 해당 id 페이지로 이동.
   게이트미션은 폼이 필요로 하던 서버 조회(계열·보상 배지 라벨·기존 축 목록)를
   `formData.ts`로 분리해 목록/신규/수정 페이지가 공유.
