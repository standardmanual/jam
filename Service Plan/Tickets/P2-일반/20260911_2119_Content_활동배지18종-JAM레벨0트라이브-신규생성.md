# [Content] 걷기·러닝·라이딩 활동배지 18종 신규 생성

## 배경 / 문제 정의
사용자가 걷기·러닝·라이딩 세 활동별로 각 6종(COMMON 2 · RARE 2 · EPIC 1 · MYSTIC 1)씩
총 18종의 아이템배지 생성을 요청했다. 이 배지들은 특정 기존 트라이브에 속하지 않는
독립 배지 묶음으로, 사용자가 지정한 신규 트라이브 "JAM! 레벨 0"에 등록한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `public.tribes`에 신규 트라이브 1건 추가: `name = 'JAM! 레벨 0'`
  (필수 필드: `id`, `name`, `sort_order`, `drop_weight`, `is_active` — `019_seed_worldview.sql:10-21`
  패턴 참고. `tagline`/`description`/`image_url`은 시드 시점엔 비움)
- `public.item_books`(컬렉션)에 신규 컬렉션 1건 추가: `name = 'JAM! 레벨 0'`
  - `tribe_id` = 위에서 생성한 "JAM! 레벨 0" 트라이브 id
  - `is_active = true` — 드랍엔진(`jam-web/src/lib/drop-engine/index.ts:172-179`)이
    `is_active=true`인 컬렉션만 드랍 후보 풀에 포함시키므로 필수
  - `description`은 NOT NULL이므로 짧은 플레이버 텍스트로 채움
  - `required_activity_badge_id`는 nullable(`018_schema_relax.sql`)이므로 비움
  - `reward_points`는 기본값 0 사용 (컬렉션 완성 보상은 이번 범위 밖)
- `public.badges`에 아이템배지(`type='item'`) 18건 추가
  - `tribe_id` = "JAM! 레벨 0" 트라이브 id, `item_book_id` = "JAM! 레벨 0" 컬렉션 id
    (2026-09-11 방향 전환 — 최초엔 컬렉션 미소속으로 등록하려 했으나, 드랍엔진이
    `item_book_id`가 활성 컬렉션에 속한 배지만 후보로 삼아 미소속 배지는 영구 드랍
    불가라는 것이 확인돼 신규 컬렉션 신설로 정정함. 과거 동일 안티패턴 배지 100개가
    이 이유로 전량 삭제된 이력도 있음 — `027_remove_legacy_item_badges.sql`)
  - `rarity`는 표 그대로 소문자 enum(`common/rare/epic/mystic`)으로 매핑, `level`은 NULL
  - `image_url`은 **NULL로 둔다** — 이 코드베이스의 관례(`019_seed_worldview.sql:133`
    주석: "image_url은 어드민에서 추후 설정")를 따름. 실제 이미지는 이번 티켓 범위 밖,
    `/jam-img` 파이프라인으로 후속 진행 (사용자 확정)
  - `condition_json`은 **비운다(NULL) — 조건 없는 랜덤 드랍.** 표의 "설명" 컬럼은 발급
    조건이 아니라 배지에 표시되는 `description`(플레이버 텍스트)으로만 사용한다.
    (사용자 확정 — 최초 설계는 `condition_json`에 거리/연속일 조건을 구조화하려 했으나,
    `type='item'` 배지는 조건부 드랍을 지원하지 않는 구조임을 확인하고 방향 전환함.
    상세 경위는 "주요 의사결정" 참고)
- SQL은 `jam-web/supabase/migrations/0XX_활동배지18종-jam레벨0트라이브.sql`로 저장

### 주요 의사결정 / 핵심 메모
- "JAM!" 트라이브 및 "레벨 0" 개념은 실제 DB·문서 어디에도 존재하지 않았음. 사용자 확인 결과
  트라이브명을 리터럴 "JAM! 레벨 0"으로 등록하는 것으로 확정.
- `image_url`은 플레이스홀더 문자열이 아니라 **NULL**로 등록 — 이 코드베이스의 실제 관례
  (`019_seed_worldview.sql:133`)를 확인 후 반영. 실제 이미지는 `/jam-img`로 별도 진행.
- 컬렉션(구 아이템북) 소속은 **최초엔 등록하지 않기로 했으나(1차 결정) 2차 HALT로 뒤집힘** —
  드랍엔진이 활성 컬렉션 소속 배지만 후보로 삼아 미소속 배지는 영구 미발급이 되는 것을 확인,
  최종적으로 "JAM! 레벨 0"이라는 이름의 신규 컬렉션을 만들어 소속시킴.
- **최초 시도 HALT (1차)**: `type='item'` + 표의 "설명"을 거리/연속일 조건으로 구조화한 `condition_json`
  조합으로 구현을 시도했으나, jam-developer가 코드 근거 3곳
  (`jam-web/src/lib/drop-engine/index.ts:78` `isDroppableForActivity()`,
  `jam-web/src/lib/drop-engine/cumulativeConditionFields.ts`,
  `jam-web/src/lib/badge-engine/index.ts:1011` `.eq('type','activity')`)을 들어 "조건이 있는
  `type='item'` 배지는 드랍엔진·배지엔진 양쪽에서 영구히 발급 불가능한 죽은 콘텐츠가 된다"고
  HALT함. 사용자에게 재확인한 결과 **"설명"은 조건이 아니라 배지에 표시되는 플레이버 텍스트로
  넣으라는 것**으로 확정 — `condition_json`은 NULL(랜덤 드랍), 설명 텍스트는 `description`
  컬럼에 그대로 저장하는 방향으로 티켓을 수정함.
- **두 번째 HALT (2차)**: `condition_json`은 고쳤으나 `item_book_id = NULL`(컬렉션 미소속)
  지시가 여전히 남아있어, 드랍엔진(`jam-web/src/lib/drop-engine/index.ts:172-201`)이
  `item_book_id`가 활성 컬렉션에 속한 배지만 후보로 조회한다는 점에서 재차 HALT함. 과거
  동일 패턴(`type='item' AND item_book_id IS NULL`) 배지 100개가 같은 이유로 전량 삭제된
  이력(`027_remove_legacy_item_badges.sql`)도 확인됨. 사용자 재확인 결과 **"JAM! 레벨 0"이라는
  이름의 신규 컬렉션(item_book)을 만들어 18종을 그 컬렉션에 소속시키는 것**으로 최종 확정.

### 잔여 이슈
- `/jam-img`로 18종 배지 이미지 제작 필요
- **DB 실행 이상 발견 및 조치**: SQL 실행 전 사용자 승인을 기다리는 동안, `sort_order=0`
  (기본값)에 badges·item_books 연결이 전혀 없는 "JAM! 레벨 0" 트라이브 orphan 1건이
  이미 DB에 존재하는 것을 실행 직후 검증 쿼리로 발견했다. 이 티켓의 파이프라인
  (jam-developer·conservative-reviewer)은 SQL을 작성만 하고 실행하지 않았다고 보고했고
  실제로 두 에이전트 모두 격리 워크트리에서만 작업해 프로덕션 DB에 직접 접속할 수단이
  없었으므로, 이 orphan 행이 이번 파이프라인에서 생성됐다고 보기는 어렵다(원인 미상).
  배지·컬렉션 연결이 전혀 없는 완전한 고아 행이라 서비스에 영향이 없음을 확인하고 즉시
  삭제했다 — 최종 확인 시 tribe_count=1이 되어 이번 등록분과 완전히 분리됨을 검증함.
  **원인은 밝히지 못했으므로, 유사 orphan 행이 다른 트라이브/컬렉션에도 있는지 점검하는
  별도 조사 티켓을 고려할 것.**
