# [API] 미션 노출 옵션 — 숨김 / 시작일 노출 / 노출일 지정

## 배경 / 문제 정의
어드민 미션 관리에는 미션 노출을 수동으로 제어하는 옵션이 없다. `missions` 테이블은
`starts_at`(NOT NULL)·`ends_at`(nullable, null=상시미션)만 가지고 있고, 서비스 목록 쿼리
(`src/app/(main)/missions/page.tsx`)는 `ends_at.is.null,ends_at.gte.${now}`만 필터링해서
**아직 시작하지 않은 미션도 목록에 그대로 노출되는 상태**다(`starts_at <= now` 조건이 아예 없음).

게이트 미션(축/단계 기반) 노출 판정(`src/lib/missions/visibility.ts`)은 게이트 없는 일반
미션을 기간(starts_at/ends_at) 기준으로 무조건 `open`으로 본다 — 이번에 추가하는 "관리자
수동 노출 제어"는 이 게이트 판정과 완전히 별개 레이어로 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `missions` 테이블에 노출 모드 컬럼 신설:
  - `exposure_mode text not null default 'start_date'` (CHECK: `hidden`/`start_date`/`scheduled`)
  - `exposure_at timestamptz null` (`scheduled`일 때만 사용)
  - `hidden`: 목록·오늘 피드 카드·참가 API·미션 상세 직접 접근 등 모든 노출 지점에서 무조건 제외
  - `start_date`: 미션에 설정된 `starts_at` 시각에 노출 (= 지금 빠진 `starts_at <= now` 필터를
    보강하는 것과 동일 효과). 기존 미션 전체 기본값도 `start_date`
  - `scheduled`: 관리자가 지정한 `exposure_at` 시각에 노출. `starts_at`과 무관하게 노출 시점만
    별도로 조정 가능
- 노출 필터 공용 헬퍼 하나로 통일해 목록·오늘 카드·참가 API·상세 직접 접근에 동일 적용
- 게이트 미션 노출 판정(`visibility.ts`)보다 먼저 적용되는 별도 레이어 — 기존 게이트 로직은
  건드리지 않는다

### UI/UX 관점
- `src/app/admin/missions/MissionForm.tsx`에 '미션 노출' 3택 옵션 추가 (숨김/시작일 노출/노출일 지정)
  - 기본값 '시작일 노출'
  - '노출일 지정' 선택 시에만 datetime-local 입력폼 노출
- 어드민 화면 — MODULAR 탐색 제외 대상, service-specific 구현

## 구현 계획

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`missions`에 `exposure_mode text not null default 'start_date'`(CHECK: hidden/start_date/
scheduled)·`exposure_at timestamptz null` 컬럼을 추가하고, 판정 함수 `isMissionExposed()`를
`src/lib/missions/visibility.ts`에 순수 함수로 신설했다. 게이트 미션 노출 판정
(`resolveMissionVisibility`)보다 먼저 적용되는 별도 레이어로 두어, 게이트 로직 자체는
변경하지 않았다. 이 함수를 목록(`/missions`)·미션 상세 직접 접근·오늘 피드 미션 소개
카드(`filterMissionSpotlightCards`)·참가 API(`/api/missions/[id]/join`) 4개 지점에 동일하게
적용했다. 목록 쿼리가 기존에 빠뜨리고 있던 `starts_at <= now` 필터 갭도 `start_date` 모드의
기본 동작으로 함께 메웠다. 어드민 `MissionForm.tsx`에 '미션 노출' 3택(숨김/시작일 노출/노출일
지정) 세그먼트를 추가했고, '노출일 지정' 선택 시에만 datetime-local 입력폼이 나타나며 값이
비어 있으면 저장 전에 막는다(비워두면 fail-closed로 영구 숨김되는 사고를 방지).

### 주요 의사결정 / 핵심 메모
- 노출 필터 지점은 티켓이 명시한 4곳(목록·오늘 카드·참가 API·상세 직접 접근)에만 적용했다.
  `today/status.ts`·`today/exposure.ts`·알림 배치(`notifications/batch/missions.ts`,
  `following.ts`)·포인트 요약(`points/summary.ts`)의 `missions` 조회는 전부 **이미 참가한
  유저**를 대상으로 한 이력 조회라 "발견 경로"가 아니라고 판단해 대상에서 제외했다 — 판단에
  개입이 있어 confidence를 medium으로 둔다.
- `missions/[id]/status/page.tsx`(참가자 전용 미션 상황 화면)도 같은 이유로 노출 필터를
  적용하지 않았다. 참가 후 숨김 처리된 미션이라도 이미 참가자는 진행 상황을 계속 볼 수 있다.
- '숨김'은 **참가 이력 유무와 무관하게 상세 페이지·참가 API를 무조건 막는다** — "서비스에서
  무조건 숨김"이라는 티켓 문구를 문자 그대로 해석했다. 이미 참가한 유저가 숨김 처리 이후
  상세 페이지에 재진입하면 404가 된다(참가 자체는 유지, `user_mission_participations` 삭제
  없음). 이 동작이 의도와 다르면 별도 조정이 필요하다.
