# [Admin] 체크인 배지 생성/조회/수정 + 지도 마커 표시 활성/비활성 옵션

## 배경 / 문제 정의
어드민 배지 관리(`jam-web/src/app/admin/badges/BadgeForm.tsx`)는 이미 `type='checkin'` 배지의
생성·조회·수정을 지원한다 (POI 1:1 연결, `badge-poi-category` 선택 등 §3.14 로직 반영).
다만 체크인 배지가 지도 드롭메뉴 마커로 노출될지 여부를 관리자가 제어할 방법이 없다.
`/api/checkin-badges/route.ts`는 현재 `poi.is_active`와 `badges.deleted_at`만 필터링하며,
"마커 표시" 자체를 껐다 켰다 하는 옵션 컬럼이 존재하지 않는다.

이번 작업은 (1) 체크인 배지 생성/조회/수정 화면이 기존 요구사항을 온전히 충족하는지 확인하고,
(2) 신규로 "지도 드롭메뉴에 마커로 표시" 활성/비활성 토글을 추가하는 것이다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `badges` 테이블에 마커 노출 제어 컬럼 신설:
  - `show_on_map boolean not null default true`
  - `type='checkin'` 배지에만 의미가 있는 옵션이나, 다른 타입에 대해서도 컬럼 자체는
    영향이 없도록 기본값 `true`로 둔다 (기존 `admin_category` 신설 선례와 동일 패턴,
    티켓 `20260910_2055` 참고)
- `/api/checkin-badges/route.ts`의 마커 조회 쿼리에 `show_on_map=true` 필터 추가
  (`poi.is_active` 필터와 동일한 위치에 병렬로 적용)
- `src/types/database.generated.ts`·`database.ts` 타입 갱신

### UI/UX 관점
- `BadgeForm.tsx`의 체크인 전용 섹션(줄 888~987 부근, `badge-poi-category` 인근)에
  "지도에 마커로 표시" `Switch` 토글 추가 (`@/components/admin/ui/switch`,
  `PoiForm.tsx`의 `is_active` 토글 패턴과 동일하게 구현)
  - 기본값 ON (활성)
  - `type !== 'checkin'`일 때는 이 옵션 자체를 숨긴다 (다른 타입에는 무의미한 옵션)
- 어드민 화면 — MODULAR 탐색 제외 대상, service-specific 구현

## 구현 계획
1. 마이그레이션 SQL 작성 (`badges.show_on_map`, 실행은 오케스트레이터가 처리)
2. `/api/admin/badges` 생성·수정 라우트에 `show_on_map` 필드 read/write 반영
3. `/api/checkin-badges/route.ts` 마커 조회 쿼리에 필터 추가
4. `BadgeForm.tsx`에 토글 UI 추가 (checkin 타입 조건부 노출)
5. 타입 재생성·로컬 실렌더(`ADMIN_EMAILS` 셸 환경변수)로 생성/조회/수정 + 토글 on/off 동작 확인

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
체크인 배지 생성/조회/수정은 이미 `BadgeForm.tsx`가 지원하고 있어 기능 자체는 손대지 않았다.
이번 작업은 신규 요구사항인 "지도 드롭메뉴 마커 표시 활성/비활성" 옵션만 추가했다.

- `badges.show_on_map BOOLEAN NOT NULL DEFAULT true` 컬럼 신설(마이그레이션 SQL만 작성,
  미실행 — 실행은 사용자 승인 후 오케스트레이터가 처리)
- 어드민 배지 생성(POST)·수정(PUT) API에 `show_on_map` 필드 read/write 반영. `admin_category`와
  동일하게 `type`과 무관하게 그대로 저장/병합한다(강제 null 가드 없음)
- `/api/checkin-badges/route.ts`의 마커 조회 쿼리에 `.eq('show_on_map', true)` 필터를
  `type='checkin'`·`deleted_at IS NULL`과 같은 위치에 병렬로 추가 — false인 배지는 지도에서
  숨겨지지만 이미 획득한 유저의 이력(마이페이지)에는 영향 없음
- `BadgeForm.tsx`의 체크인 전용 섹션에 "지도에 마커로 표시" `Switch` 토글 추가(`PoiForm.tsx`의
  `is_active` 토글과 동일한 패턴). 기본값 ON, `type === 'checkin'` 조건부 블록 안에 있어
  다른 타입에는 자동으로 숨겨짐
- `src/types/database.ts`·`database.generated.ts`에 `show_on_map: boolean` 필드 추가

### 주요 의사결정 / 핵심 메모
- 컬럼명은 티켓 원안 그대로 `show_on_map`을 썼다 — `admin_category`(마이그레이션 156) 때와
  달리 기존 컬럼명과 충돌하는 지점이 없어 별도 조사·개명이 필요 없었다.
- 저장 API 가드는 `admin_category`와 동일한 패턴(type과 무관하게 항상 그대로 저장/병합)을
  따랐다 — `category`(지점 카테고리)처럼 `type==='checkin'`일 때만 강제하는 방식은 쓰지
  않았다. 티켓이 "type='checkin' 배지에만 의미 있는 옵션이나 다른 타입에도 컬럼 자체는
  영향 없도록"이라고 명시했고, 컬럼 기본값이 true라 다른 타입에서 값이 있어도 아무 동작에도
  관여하지 않기 때문이다(마커 조회는 `type='checkin'` 필터와 함께 걸리므로).
- UI 토글은 `type === 'checkin'` 조건부 블록 안에 배치해 별도의 "다른 타입일 때 숨김" 로직을
  추가로 작성하지 않았다 — 기존 블록 구조가 이미 그 조건을 충족한다.
