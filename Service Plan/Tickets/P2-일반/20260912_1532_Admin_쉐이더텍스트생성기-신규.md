# [Admin] 운영 도구 — 쉐이더 텍스트 생성기 신규 (디졸브 에코)

## 배경 / 문제 정의

사용자가 Suno 마케팅 영상에서 본 "리퀴드 메탈" 텍스트 이펙트를 계기로, 텍스트에 실시간
그래픽 이펙트를 입혀 배지 이미지 등에 쓸 수 있는 어드민 도구를 요청했다. 대화 중 두 방향을
Claude 아티팩트로 프로토타입 검증했다.

- 리퀴드 메탈(WebGL, 거리장 기반 링·글로우): https://claude.ai/code/artifact/af9669ea-af29-4f95-a830-f2448b91607b
- 디졸브 에코(Canvas2D, 에코 복제+헤일로+노이즈+그레인+그라디언트맵): https://claude.ai/code/artifact/442ae704-27cf-429a-b435-b10a16d33886

참고로 살펴본 외부 사이트(Brik "Dissolve" 툴, `brik.space/toolviewer?slug=dissolve-mou5yxqt`)는
**스크립트를 가져오지 않았다** — Wix 산하 상업 서비스의 타 창작자 콘텐츠라 소스 재사용은
저작권·이용약관 문제가 있어 배제했고, 컨트롤 패널의 **파라미터 구성만** 참고해서 디졸브 에코
프로토타입을 처음부터 새로 짰다.

사용자가 최종적으로 **디졸브 에코만** 정식 개발하기로 확정했다. 리퀴드 메탈은 이 티켓 범위 밖.

### 사전 조사로 확인한 사실 (구현 전 필독)

1. **거의 동일한 선례가 있다** — 티켓 `20260902_1613`(액티비티 배지 이미지 생성기)이 "캔버스
   합성 → 기존 배지 `image_url` 반영 → `image_gen_params`로 재편집 가능"이라는 구조를
   이미 확립해 뒀다. 이 티켓은 그 패턴을 그대로 따른다 — 전용 API 라우트, 고정 경로
   Storage upsert, WYSIWYG(미리보기 캔버스가 곧 굽는 캔버스) 원칙 포함.
2. **경고성 선례** — 이전 "배경 패턴 쉐이더 제너레이터"는 결과 이미지가 재편집 불가능해서
   티켓 `20260901_1929`로 **완전히 폐기**됐다. 이 티켓은 처음부터 `image_gen_params`에
   전체 설정값을 저장해 재편집을 구조적으로 보장한다.
3. **Pretendard는 원래 가변 폰트가 아니었다 (2026-09-12 게이트 재시도 시 결정 변경됨)** —
   `jam-web/src/app/globals.css` 1행은 CDN **static** 배포판
   (`.../pretendard@v1.3.9/dist/web/static/pretendard.css`)을 `@import`하고, 사이트 전역은
   이 static 로드를 그대로 유지한다(건드리지 않는다). 최초 결정은 이 정적 배포판이 제공하는
   9단계 고정 굵기 드롭다운이었으나, **사용자가 게이트 FAIL 재시도 승인과 함께 진짜 가변 축으로
   변경을 지시**했다. 아래 "폰트 굵기 결정 변경" 절 참고.

   #### 폰트 굵기 결정 변경 (2026-09-12)

   - **이 어드민 라우트(`/admin/shader-text`)에 한해서만** Pretendard **Variable** 웹폰트를
     별도로 로드한다. `globals.css`나 다른 어드민 화면의 static 로드는 건드리지 않는다 —
     사이트 전역 타이포그래피 회귀 위험을 이 화면 하나로 격리한다.
   - 참고 저장소: https://github.com/orioncactus/pretendard/tree/main/packages/pretendard/dist/web/variable
   - 로드 URL은 기존 static import와 **같은 버전 태그(`v1.3.9`)로 고정**한다(사용자가 검증한
     시점의 static 배포판과 동일 릴리스를 쓰기 위함, `@main`처럼 최신 추적 태그 금지):
     `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable.css`
     (또는 서브셋 최적화가 필요하면 `pretendardvariable-dynamic-subset.css` — 구현자가 실제
     파일 존재 여부·용량을 확인하고 선택한다).
   - **`wght` 축의 실제 최소/최대값은 코드에 추측해서 넣지 말고, 위 CSS 파일을 직접 받아
     `@font-face`의 `font-weight: <min> <max>;` 선언값을 그대로 읽어 슬라이더 range로 쓴다.**
     (일반적으로 Pretendard Variable은 45~920 범위로 알려져 있으나, 이 티켓 작성 시점에
     실제 CDN 파일로 재확인하지 않았으므로 구현 시 반드시 실측한다.)
   - 캔버스에 그릴 때는 `ctx.font = "<weight> <size>px 'Pretendard Variable'"` 형태로 임의
     정수 굵기를 그대로 넣는다. `document.fonts.load()`로 해당 굵기 문자열의 로드 완료를
     기다린 뒤 그린다(기존 `composeActivityBadgeImage.ts`의 `waitForFonts()` 패턴 참고 —
     다만 그쪽은 static 폰트 이름 로드이므로 그대로 재사용은 못 하고, 가변 축에 맞게 조정한다).
   - UI는 9단계 드롭다운 대신 **연속 슬라이더**(위에서 실측한 min~max 범위, 기본값 700 근처)로
     교체한다. `image_gen_params.font.weight`는 그 정수값을 그대로 저장한다(구조 변경 없음 —
     기존에도 숫자 타입이었다).
   - 이 변경은 이 어드민 라우트 전용이며, 사이트 전역 Pretendard 로딩 전략(다른 static 로드
     지점)에는 영향을 주지 않는다. **`globals.css`를 수정하지 않는다.**
4. **신규 npm 의존성 추가 금지** — 과거 티켓(`20260819_007`)에서 셰이더 라이브러리는
   `@paper-design/shaders-react`만 허용하기로 못박았다. 디졸브 에코는 Canvas2D API만으로
   구현되므로 이 제약과 무관하다 — **신규 의존성을 추가하지 않는다.**
5. **배지 이름 검색은 이미 존재하지만, 이 티켓 전용 검색을 별도로 만든다** — `/admin/badges`의
   `BadgesFilterBar.tsx`는 배지 관리 목록용이다. `20260902_1613`이 그랬듯, 이 도구도
   `POST /api/admin/shader-text/search` 같은 전용 검색 API를 새로 만든다(대상 배지 타입 제한이
   없는 범용 검색이라 결과 컬럼 구성이 다르다).

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 렌더링 파이프라인 — 클라이언트 Canvas 2D

프로토타입(`dissolve-echo-preview.html`, 이 세션 스크래치패드에 있던 파일 — 코드를 그대로
옮기지 말고 어드민 코드 스타일·구조에 맞게 재작성)의 파이프라인을 기반으로 확장한다.

그리는 순서: 텍스트 마스크(여러 줄) → 에코 N회 합성(오프셋·스케일·회전·페이드·스캐터) →
이중 블러 헤일로(바깥/안쪽) → 그라디언트맵 색상 매핑(4색) → 노이즈 오버레이 → 필름 그레인
오버레이 → (배경 있음이면) 배경색 합성.

- **1280×1280 고정.** 프리뷰 화면에서는 CSS로 축소 표시해도 되지만, 백킹 스토어(`canvas.width/height`)는
  항상 1280이어야 한다 (WYSIWYG — `20260902_1613`과 동일 원칙).
- **여러 줄 텍스트**: textarea 입력을 줄바꿈 기준으로 분리해 각 줄을 별도로 그린다. 줄 간격
  옵션(라인 하이트 배수 또는 px) 추가.
- **배경 처리**:
  - 단색 배경: 지정한 색으로 `fillRect` 후 그 위에 이펙트를 합성.
  - 투명 배경: 배경을 채우지 않고 캔버스 알파를 유지한 채 PNG로 인코딩(`toBlob('image/png')`는
    기본적으로 알파를 보존하므로 별도 처리 불필요 — 다만 그라디언트맵 픽셀 연산 단계에서
    알파 채널을 건드리지 않도록 주의. 현재 프로토타입은 알파를 255 고정으로 쓰고 있어
    수정이 필요하다).
- **에코 패턴 프리셋** (Brik의 "Echo Path"/"Freehand Brush" — 실제 드로잉 UI는 없으므로 설정값
  프리셋으로 대체): 최소 "직선"(기존 프로토타입 방식) · "지그재그" · "원형 배치" 3종을
  드롭다운으로 제공. 각 프리셋은 에코 인덱스 `i`에 따른 오프셋 계산식만 다르다.

#### 3. 데이터 모델

**A. `badges.image_gen_params` 재사용 — 신규 마이그레이션 불필요**

이미 `20260902_1613`(마이그레이션 126)에서 추가된 컬럼을 그대로 쓴다. 저장 형태 제안

  "halo": { "outerSpread": 14, "outerIntensity": 35, "innerSpread": 6, "innerIntensity": 55, "offsetX": 0, "offsetY": 0, "contrast": 0, "preserveSharpCore": false },
  "noise": { "enabled": true, "type": "perlin", "scale": 4, "intensity": 18, "blendMode": "overlay" },
  "grain": { "size": 2, "amount": 20 },
  "gradientMap": { "shadow": "#05040a", "halo": "#1c3a8f", "core": "#ff6a2c", "innerCore": "#fff2b0", "haloPosition": 0.33, "corePosition": 0.66 },
  "edgeBlur": 2,

**B. 신규 테이블 — 스타일 프리셋**

마이그레이션 파일 `167_shader_text_presets.sql` (가안 — **번호는 push 직전에 원격 staging
기준으로 재확인**, 병렬 세션 선점 이력 다수).

```sql
create table if not exists shader_text_presets (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  params jsonb not null,
  created_at timestamptz not null default now(),
  created_by text
);
alter table shader_text_presets enable row level security;
comment on table shader_text_presets is '쉐이더 텍스트 생성기(디졸브 에코) 스타일 프리셋. 티켓 20260912_1532';
```

**RLS 필수 (2026-09-12 게이트 FAIL로 확인됨)** — `ENABLE ROW LEVEL SECURITY`를 빠뜨리면
정책이 없어도 PostgREST가 anon 키로 전체 조회·수정을 허용한다. 이 저장소는 이 유형 사고를
두 차례 겪었다(마이그레이션 074, 147). 정책(POLICY)은 추가하지 않아도 된다 — RLS만 켜면
`service_role` 키를 쓰는 서버 라우트만 접근 가능해지고, 그게 이 테이블의 유일한 접근 경로다.

- `params`는 위 A절 JSON에서 `text`(문구)와 `canvasSize`를 뺀 스타일 값만 저장할지, 전체를
  저장할지는 구현자 재량 — 문구까지 프리셋에 포함되면 매번 문구를 지워야 하는 불편이 있으므로
  **스타일 값만 저장하고 문구는 제외하는 쪽을 권장**하되 최종 판단은 구현 시 확정한다.
- 소프트 삭제(`deleted_at`) 여부는 구현자 재량 — 프리셋은 운영 편의용 데이터라 하드 삭제도 무방.
- **DB 실행은 하지 않는다** — SQL 파일 작성까지. 실행은 사용자 승인 후 오케스트레이터가 처리한다.
- 마이그레이션 추가 후 **`npm run db:types`가 이 환경에서 실행 불가**(supabase CLI 없음,
  `20260902_1613` 완료 기록 참고) — Supabase MCP `generate_typescript_types` 출력과 대조해
  `database.generated.ts`를 수기 반영한다.

#### 4. 저장·배포 — 전용 API 라우트 (경로명은 구현자 재량, 예시)

- `POST /api/admin/shader-text/search` — 배지 이름 검색. **대상 배지 타입 제한 없음**
  (activity/item/checkin 전체). 결과에 `type`·`rarity`·`image_url`(현재 썸네일) 컬럼을
  노출해 어떤 배지인지 식별 가능하게 한다.
- `POST /api/admin/shader-text/generate` — 요청: `badgeId` + 구운 PNG + `image_gen_params` JSON.
  1. `getAdminUser()` 권한 확인
  2. `badgeId`가 `deleted_at IS NULL`인지 DB로 검증 (파일 경로에 그대로 들어가므로 필수)
  3. Storage `images` 버킷 `badges/shader-text/{badgeId}.png`에 **`upsert: true`**로 업로드
     (`/api/admin/upload-image`는 랜덤 파일명이라 쓰지 않는다 — `20260902_1613`과 동일 결정)
  4. `image_url = publicUrl + '?v=' + Date.now()`, `image_gen_params` UPDATE
- `POST /api/admin/shader-text/presets` (목록/저장), `DELETE /api/admin/shader-text/presets/{id}`
  (삭제) — B절 테이블 CRUD. 최소 기능(생성·조회·삭제)만 구현, 수정(rename)은 있으면 좋으나
  필수 아님.
- **투명 배경 PNG는 `image_url`로 배지에 적용했을 때 서비스 카드 배경이 그대로 비친다** —
  의도된 동작이다(별도 이슈 아님).

#### 5. 내보내기

- **PNG**: 위 4절 API 흐름과 별개로, "배지에 적용하지 않고 그냥 다운로드"하는 경로도 필요하다
  (마케팅 소재용 — 애초 요청 취지). `canvas.toBlob()` → 브라우저 다운로드.
- **WebM 동영상**: `canvas.captureStream()` + `MediaRecorder`. 애니메이션이 켜져 있을 때만
  의미가 있다 — 애니메이션 꺼짐 상태에서 WebM 버튼은 비활성화하거나 안내 문구를 띄운다.
  녹화 길이(예: 3~5초 루프) 옵션 UI가 필요한지는 구현자 판단.
- **MP4는 이번 범위에서 제외** (브라우저 인코딩 지원이 갈려 별도 검토 필요).

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- **서브셋 CSS(`pretendardvariable-dynamic-subset.css`) 대신 전체 파일 선택** — 서브셋은
  입력 문구의 실제 문자에 맞춰 `document.fonts.load(font, text)`처럼 텍스트 인자를 넘겨야
  필요한 조각만 받는데, 이 도구는 문구를 자주 바꾸는 저작 도구라 매번 다른 서브셋 로딩을
  기다리는 편이 오히려 사용성이 나쁘다고 판단했다. 전체 파일(2MB)은 최초 1회만 받고 이후
  브라우저 캐시로 재사용된다.
- **RLS 정책(POLICY)은 추가하지 않음** — 티켓이 명시한 대로 `service_role` 서버 라우트만
  접근하면 되므로 RLS ON만으로 충분하고, 별도 정책을 만들지 않았다.
- **`ShaderTextFontWeight` 타입을 리터럴 유니언에서 `number`로 완화** — 가변 축은 특정
  정수 집합이 아니라 연속 범위이므로, 유니언 타입으로는 표현할 수 없다. 정규화(clamp)는
  다른 숫자 필드(`size`, `tracking` 등)와 동일한 `num()` 헬퍼로 통일했다.

### 잔여 이슈
- `/admin/shader-text` 화면의 실제 렌더링·CDN 폰트 로드·슬라이더 동작은 staging 병합 후
  육안 확인이 필요하다(위 테스트 결과 항목 참고).
- Echo Path 프리셋 3종의 시각적 정확도, WebM 녹화 길이 옵션 등은 티켓의 "유예된 판단"
  절에 따라 이번 범위에서 검증하지 않았다(변경 없음, 1차 구현 그대로).
