# [UI] 인벤토리 포화 안내 + 드랍 화면 진입 CTA

## 배경 / 문제 정의
> 왜 이 작업이 필요한가. 현재 상태와 기대 상태의 차이.

인벤토리 슬롯(`inventory.used_slots` / `max_slots`)이 가득 차면 액티비티 동기화로 아이템배지
드랍이 판정 단계(`drop-engine`)에서 조용히 스킵된다(`outcome: 'slot_full'`, 로그만 남고 유저
알림 없음). 알림함 #42(인벤토리 포화)가 하루 1회 배치로 인지시키긴 하지만, 유저가 실제로 슬롯을
채운 순간(인벤토리 화면 진입)에 그 자리에서 원인과 해결책을 즉시 보여주는 상시 안내는 없다.

PRD: [Service Plan/Specs/PRD/Inventory/PRD.md](../../Specs/PRD/Inventory/PRD.md)

이 PRD를 구현한다. 사용자 추가 지시사항 2건:
1. 안내 메시지가 화면 가로 전체에 꽉 차지 않도록 한다 (edge-to-edge 금지, 카드형 인셋).
2. 안내 메시지에 아이콘·이모지를 쓰지 않는다 (텍스트 + 버튼만).

**2026-09-12 방향 수정**: 최초 구현 착수 중 `/api/drops`가 poi_id + 500m 반경(`isUserNearPoi`)
검증을 강제한다는 사실이 확인되어(위치·POI 컨텍스트가 없는 인벤토리 화면에서는 드랍 시트를
독립적으로 열어도 API 단계에서 거부됨) HALT됐다. 사용자 확인 후 CTA를 "드랍하기 → `/drops`
이동"으로 단순화했다 — 실제 드랍은 종전과 동일하게 체크인 지점에서만 이뤄진다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `app/(main)/inventory/page.tsx`의 `ProgressBar` 바로 아래(`d.inventory.slotsDetail` 텍스트와
  같은 블록)에 `remainingSlots === 0`일 때만 렌더되는 조건부 안내 블록 추가.
- CTA "드랍하기" 버튼은 `Link href="/drops"`로 드랍 지도 화면으로 이동하는 순수 네비게이션이다.
  드랍 시트(`PoiCarouselModal`)나 `/api/drops`·`/api/inventory/items`의 계약은 건드리지 않는다.
- 드랍 완료 후 인벤토리 화면으로 재진입하면 `used_slots`가 갱신된 값으로 다시 조회되어 안내가
  자동으로 사라져야 한다(서버 컴포넌트 재조회이므로 별도 캐시 무효화 불필요).
- 배지엔진(`drop-engine`)의 슬롯 초과 스킵 로직, 알림 #42의 배치 생성·문구는 변경하지 않는다.
- `/api/drops`의 위치 반경 검증, 드랍 시트를 POI 컨텍스트에서 분리하는 작업은 이번 티켓 범위에
  포함하지 않는다.

### UI/UX 관점 (해당 시)
- 안내 블록은 화면 좌우 여백을 유지하는 카드형(rounded, 인셋 패딩)으로, 화면 폭 전체를 꽉 채우는
  edge-to-edge 배너로 만들지 않는다.
- 아이콘·이모지·장식용 도트 등 그래픽 요소를 넣지 않는다 — 텍스트(현상→원인→해결책 3단계)와
  드랍 CTA 버튼만으로 구성한다.
- 문구는 `Service Plan/Specs/UX_WRITING_GUIDELINE.md`의 [현상 → 원인 → 해결책] 3단계 구조와
  알림함 #42의 톤·고정 용어(드랍·픽업)를 따른다.

### 컨텐츠 관점 (해당 시)
- 해당 없음.

## 구현 계획
> 어떻게 구현할지. 접근 방법, 영향 범위, 주요 변경 포인트.

- **1.5 탐색 결과**: MODULAR에 유사 인라인 배너 패턴으로 `RecentSyncBanner`
  (`jam-web/design-system/components/patterns/RecentSyncBanner.jsx`)가 있다 — 카드형 인셋
  컨테이너(둥근 모서리·패딩·surface-elevated 배경)로 "가로 꽉 참 금지" 요구와 시각 언어가
  일치한다. 다만 이 컴포넌트는 단일 텍스트 줄 + 장식용 컬러 도트 전용이라 CTA 버튼 슬롯이 없고,
  이번 요구사항은 도트류 그래픽 요소 자체를 배제해야 한다(아이콘·이모지 금지 지시). **그대로
  재사용하지 않고**, `RecentSyncBanner`의 컨테이너 스타일(패딩·radius·배경, 도트 제외)만 시각적
  참고로 삼아 서비스 전용 블록으로 구현한다 — MODULAR 승격 대상 아님(재사용 범용성이 낮음).
- `app/(main)/inventory/page.tsx`에 조건부 블록 + `/drops`로 이동하는 "드랍하기" CTA 버튼 추가.
- 드랍 시트·`/api/drops` 쪽은 손대지 않는다.
- 문구 최종 카피는 구현 단계에서 UX 라이팅 가이드를 따라 작성하고, 한국어 리뷰 단계에서 검수한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`app/(main)/inventory/page.tsx`의 슬롯 프로그레스바·상세 텍스트 블록 바로 아래에
`remainingSlots === 0`일 때만 렌더되는 카드형 안내 블록을 추가했다. 컨테이너는 `RecentSyncBanner`의
패딩·radius·배경(도트 제외)만 시각적으로 참고해 신규로 구현했고, 좌우 여백을 유지하는 인셋
카드(edge-to-edge 금지)로 구성했다. 아이콘·이모지 없이 [현상→원인→해결책] 3단계 문구 한 문장과
"드랍하기" CTA 버튼(`Link href="/drops"`)만 배치했다. 드랍 시트·`/api/drops`·`/api/inventory/items`
계약, 배지엔진 슬롯 스킵 로직, 알림 #42 문구는 손대지 않았다. 문구는
`jam-web/src/lib/i18n/ko.ts`의 `inventory.fullNoticeBody`/`fullNoticeCta`에 신규 추가했다.
