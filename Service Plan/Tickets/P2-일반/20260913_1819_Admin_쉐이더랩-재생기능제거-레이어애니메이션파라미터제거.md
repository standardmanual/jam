# [Admin] 쉐이더 랩 — 재생/정지 기능 제거 + 레이어별 자동 애니메이션 파라미터 제거

## 배경 / 문제 정의

쉐이더 랩의 최종 산출물은 1:1 정적 PNG(배지·미션·컬렉션 대표이미지) 한 장이다. 그런데
일부 레이어(디더링·메시 그라디언트·서킷 벤트·잉크·파티클 그리드·슬라이스)는 시간이
지나면 파라미터에 따라 스스로 움직이는("애니메이션") 기능을 갖고 있고, 이를 미리보기에서
확인하려는 목적으로 전역 "재생/정지" 버튼이 있었다. 사용자가 이 도구의 실제 용도(정적
이미지 생성)에는 이 개념이 불필요하다고 판단해 완전히 제거를 요청했다.

단, 플루이드·픽셀 트레일·매그니파이 렌즈는 "애니메이션"이 아니라 마우스 좌표에
실시간으로 반응하는 것이라 성격이 다르다 — 사용자가 명시적으로 유지를 요청했다.

## 원본 저장소 조사 결과 (근거)

`node_modules/@basementstudio/shader-lab`(설치된 실제 런타임)의 각 렌더 패스가 공식으로
제공하는 `needsContinuousRender()` 메서드를 전수 확인해, "시간에 따라 스스로 계속
다시 그려져야 하는지"를 레이어별로 정확히 판별했다.

**시간 기반 자동 애니메이션(제거 대상, 6종)**:
| 레이어 | 파일 | 판정 조건 | 제거할 필드 | 언더파인드(undefined) 시 런타임 기본값 |
|---|---|---|---|---|
| 디더링 | dithering-pass.js | `this.isAnimated`(`animateDither===true`) | `animateDither`, `animateSpeed` | `false`(꺼짐) — 필드 삭제만으로 충분 |
| 메시 그라디언트 | gradient-pass.js | `this.isAnimated`(`animate!==false`) | `animate`, `motionAmount`, `motionSpeed` | **`true`(켜짐, 위험)** — 명시적 `animate:false` 필요 |
| 서킷 벤트 | circuit-bent-pass.js | `scrollSpeedValue>0.0001` | `scrollSpeed` | **`4`(최대 속도, 위험)** — 명시적 `scrollSpeed:0` 필요 |
| 잉크 | ink-pass.js | `this.isAnimated`(smokeSpeed>0) | `smokeSpeed` | **`0.2`(켜짐, 위험)** — 명시적 `smokeSpeed:0` 필요 |
| 파티클 그리드 | particle-grid-pass.js | `this.isAnimated` | `noiseSpeed` | **`0.5`(켜짐, 위험)** — 명시적 `noiseSpeed:0` 필요 |
| 슬라이스 | slice-pass.js | `speedValue>0.0001` | `speed` | **`0.2`(켜짐, 위험)** — 명시적 `speed:0` 필요 |

**마우스/포인터 반응형(유지, 그대로 둠)**:
- 플루이드(fluid-pass.js): `needsContinuousRender()`가 `runtime.isRunning && !paused`(포인터 스플랫 물리 시뮬레이션). `render()`가 `this.runtime.step(delta)`를 호출해 델타 타임으로 감쇠·이류를 진행시킨다 — **delta가 0으로 고정되면 스플랫이 감쇠하지 않거나 아예 안 그려진다.** 그래서 전역 delta 자체는 계속 실제로 흘러야 한다(재생/정지 스위치만 없앤다).
- 픽셀 트레일·매그니파이 렌즈: `needsContinuousRender()`가 항상 `true`(포인터 위치 기반, 시간과 무관).

**건드리지 않음**: CRT의 "글리치 속도"는 "글리치 강도"가 0이면 자동으로 `needsContinuousRender`가 꺼지는 일반 강도 파라미터(전용 애니메이션 온오프 스위치가 따로 없음)라 제거 대상에서 제외했다 — 사용자가 강도를 직접 조절해 끌 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. `jam-web/src/app/admin/shader-lab/ShaderLabViewport.tsx`: 재생/정지 `<Button>`과 안내
   캡션("1280×1280 · 애니메이션 파라미터가 있는 레이어만...") 삭제. `playing`/
   `onTogglePlaying` prop 삭제.
2. `jam-web/src/lib/admin/shaderLab/useShaderLabPlayback.ts`: `playing` 매개변수 삭제.
   시간(`timeRef`)은 **항상 실제 경과 시간만큼 누적**(정지 개념 자체를 없앰) — 플루이드의
   델타 기반 물리가 항상 정상 동작하도록.
3. `jam-web/src/app/admin/shader-lab/page.tsx`: `playing` state 삭제, `ShaderLabViewport`
   호출부에서 `playing`/`onTogglePlaying` 제거.
4. `jam-web/src/app/admin/shader-lab/ShaderLabExportPanel.tsx`,
   `jam-web/src/app/admin/shader-lab/ShaderLabApplyTab.tsx`: `applyDisabled` prop과
   "재생 중에는 적용할 수 없어요" 안내 문구 삭제(재생 개념이 없어지므로 이 안전장치도
   불필요).
5. `jam-web/src/lib/admin/shaderLab/effectRegistry.ts`: 위 표의 6개 레이어에서 해당 필드
   삭제. `getDefaultParamsForType()`에 레이어 타입별 강제 정적값(위 표의 "명시적으로
   필요" 값들, 디더링도 안전을 위해 명시)을 병합하는 로직 추가.

### UI/UX 관점

- 재생/정지 버튼 제거로 미리보기 캔버스 하단 컨트롤 영역이 단순해진다 — 레이아웃 확인
  필요(빈 공간이 어색하지 않게).

## 구현 계획

1. `effectRegistry.ts` 필드 삭제 + `getDefaultParamsForType` 강제값 병합 로직 추가.
2. `useShaderLabPlayback.ts` 단순화(재생/정지 개념 제거, delta 상시 흐름).
3. `ShaderLabViewport.tsx`/`page.tsx`/`ShaderLabExportPanel.tsx`/`ShaderLabApplyTab.tsx`에서
   재생 관련 UI·prop 제거.
4. esbuild+playwright로 실측: (a) 디더링/그라디언트/서킷벤트/잉크/파티클그리드/슬라이스
   레이어를 새로 추가했을 때 `getDefaultParamsForType`가 반환하는 params에 강제값이
   정확히 들어있는지, (b) 플루이드 레이어에 포인터 이벤트를 시뮬레이션했을 때 스플랫이
   정상적으로 나타나고 감쇠하는지(delta가 살아있음을 실증).
5. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` 재확인.

## 유예된 판단

- 이미 저장된 컴포지션(`shader_lab_compositions`)을 불러올 때 옛 데이터에 `animate:true`
  등이 남아있으면 그 값 그대로 복원된다 — 로드 시 강제 재정규화는 이번 범위 밖(실사용
  데이터가 아직 없어 영향 낮음 판단).
