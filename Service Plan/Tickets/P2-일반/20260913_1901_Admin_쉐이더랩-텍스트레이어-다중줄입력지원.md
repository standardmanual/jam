# [Admin] 쉐이더 랩 — 텍스트 레이어 다중 줄(줄바꿈) 입력 지원

## 배경 / 문제 정의

텍스트 레이어의 "텍스트" 입력값이 줄바꿈을 포함한 여러 줄을 지원하지 않는다. 사용자가
줄바꿈 포함 다중 줄 입력을 요청했다.

## 원본 저장소 조사 결과

- **UI**: `node_modules/@basementstudio/shader-lab/dist/src/renderer/text-pass.js`
  (설치된 실제 런타임)의 `rebuildTextTexture()`는 `text` 파라미터 문자열 전체를
  `[...text]`로 문자 단위 분해해 **한 줄로만** 배치한다 — `\n` 문자가 섞여 들어와도
  줄바꿈으로 처리하지 않고 그냥 폭 0(또는 이상값)짜리 글리프로 취급해 한 줄에
  이어 그려진다(실측: 개행 문자를 포함해 렌더링하면 한 줄에 뭉쳐 보임).
- **원본 저장소 자체도 다중 줄 미지원**: GitHub `basementstudio/shader-lab`의
  `src/lib/editor/config/layer-registry.ts`(`textParams`)를 조회해보니 `text` 필드가
  `maxLength: 32`인 단순 `type: "text"`(단일 줄) 그대로이고 `lineHeight` 등 다중 줄
  관련 파라미터 자체가 없다 — JAM!이 원본에 없는 기능을 추가하는 순수 확장이다.
- **적용 방식**: 사용자 확정 — `patch-package`로 설치된 패키지의 `text-pass.js`를
  직접 고친다(fork 유지·전체 재구현 등 다른 대안 대신 이 방식으로 결정).

## 상세 요구사항

### 서비스/코드베이스 관점

1. `patch-package` 개발 의존성 설치 + `package.json`에 `postinstall: "patch-package"`
   스크립트 추가 — CI·다른 PC에서 `npm install` 시 패치가 자동 재적용되도록.
2. `node_modules/@basementstudio/shader-lab/dist/src/renderer/text-pass.js`의
   `rebuildTextTexture()`를 다중 줄 레이아웃으로 교체한다.
   - `text.split('\n')`으로 줄 단위 분리
   - 줄마다 기존과 동일한 글리프 레이아웃(`visualLeft`/`visualRight`/글자별 x좌표)을
     독립 계산 — 가로 정렬(`anchor`의 horizontal: left/center/right)은 줄마다
     자기 폭 기준으로 적용(일반적인 워드프로세서 정렬과 동일)
   - 줄 간격은 `fontSize`의 고정 배율(1.2, 통상적인 본문 줄간격 기본값)로 계산 —
     별도 파라미터로 노출하지 않는다(사용자 요청 범위 밖, 필요 시 후속 확장)
   - 세로 정렬(`anchor`의 vertical: top/center/bottom)은 전체 텍스트 블록(줄 수 ×
     줄간격 + 첫 줄 ascent/마지막 줄 descent) 기준으로 계산 — 단일 줄일 때는 원본과
     100% 동일한 좌표가 나오도록 만든다(회귀 방지)
3. `npx patch-package @basementstudio/shader-lab`로 패치 파일 생성
   (`patches/@basementstudio+shader-lab+3.0.2.patch`) — 커밋 대상.
4. `jam-web/THIRD_PARTY_NOTICES.md`에 이번 패치 사실(대상 파일·변경 요지·이유) 고지
   추가.
5. `jam-web/src/lib/admin/shaderLab/paramFields.ts`의 `TextFieldDefinition`에
   `multiline?: boolean` 옵션 추가.
6. `jam-web/src/lib/admin/shaderLab/effectRegistry.ts`의 `text` 필드(468행 부근)에
   `multiline: true` 지정, `maxLength`를 다중 줄에 맞게 상향 조정(현재 32는 한 줄
   기준값이라 여러 줄엔 너무 작음 — 착수 시 적정값 판단해 근거를 완료 기록에 남길 것).
7. `jam-web/src/app/admin/shader-lab/ShaderLabParamField.tsx`의 `type === 'text'`
   분기에서 `field.multiline`이 true면 `Textarea`(shadcn, 이미 프로젝트에 있음)를,
   아니면 기존 `Input`을 렌더링하도록 분기 — ASCII 레이어의 `customChars` 등 다른
   `text` 타입 필드는 영향받지 않아야 한다(회귀 방지).

## 구현 계획

1. `patch-package` 설치 + `postinstall` 스크립트 추가.
2. `text-pass.js`의 `rebuildTextTexture()`를 다중 줄 알고리즘으로 교체 후
   `npx patch-package @basementstudio/shader-lab`로 패치 파일 생성.
3. `paramFields.ts`/`effectRegistry.ts`/`ShaderLabParamField.tsx` 수정.
4. `THIRD_PARTY_NOTICES.md` 갱신.
5. esbuild+playwright 실측: (a) 단일 줄 입력 시 패치 전/후 렌더링 결과가 픽셀
   동일한지(회귀 없음 증명), (b) 여러 줄 입력이 실제로 줄바꿈되어 렌더링되는지,
   (c) anchor 9종 조합 중 대표값(top-left/center/bottom-right)에서 다중 줄 정렬이
   올바른지.
6. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` 재확인.

## 유예된 판단

- 줄 간격(line-height) 커스터마이징 UI는 이번 범위 밖(고정 배율 1.2 사용).
- 자동 줄바꿈(word-wrap, 폭을 넘으면 자동 개행)은 이번 범위 밖 — 사용자가 명시적으로
  입력한 `\n`만 줄바꿈으로 처리한다.
