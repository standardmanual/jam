# [Admin] 쉐이더 랩 — 리퀴드 메탈 레이어 추가

## 배경 / 문제 정의

사용자가 `https://shaders.paper.design/liquid-metal`(Paper Shaders의 "Liquid Metal" 데모)을
참고해 쉐이더 랩에 리퀴드 메탈 레이어 추가를 요청했다. 프로젝트에는 이미
`@paper-design/shaders-react@0.0.80`이 설치돼 있다(과거 티켓 20260819_007/20260912_1532에서
"유일하게 허용되던 셰이더 라이브러리"로 확립됐으나, 실제 코드에서 사용된 적은 없음 — 이번이
첫 실사용).

## 기술적 난제와 통합 방식 결정

`@basementstudio/shader-lab`(WebGPU + Three.js + TSL)과 `@paper-design/shaders`(순수 WebGL2
GLSL 프래그먼트 셰이더)는 렌더링 파이프라인이 완전히 다르다. 검토한 대안:

1. **GLSL을 TSL로 재작성**: `liquid-metal.js`(630줄, 포아송 디스크 샘플링·이미지 전처리 등
   복잡한 로직)를 통째로 재작성 — 리스크가 크고 원본과의 시각적 차이가 생길 위험이 높아
   기각.
2. **`custom-shader-pass.js`(원본의 커스텀 셰이더 확장 지점) 재활용**: 소스 코드를 실행 시점에
   컴파일하는 방식이라 매력적이었으나, 이 레이어는 순수 TSL 함수만 반환할 수 있고
   `sourceCode`/`entryExport` 외에 임의 UI 파라미터(색상·반복 등)를 노출할 방법이 없다 —
   원본 앱도 이 레이어를 일반 사용자 UI에 노출하지 않고 내부용으로만 쓴다. 기각.
3. **오프스크린 WebGL 브릿지(채택)**: `@paper-design/shaders`의 `ShaderMount`(순수 JS 클래스,
   React 의존성 없음)로 숨겨진 `<div>`에 GLSL 셰이더를 직접 마운트하고, 그 안에서 자체
   생성되는 `<canvas>`(별도 WebGL2 컨텍스트)를 `THREE.CanvasTexture`로 감싸 shader-lab의
   TSL `texture()` 노드에 공급한다. `text-pass.js`가 Canvas 2D 결과를 `CanvasTexture`로
   공급하는 것과 원리가 동일 — WebGPU와 WebGL은 서로 다른 canvas를 쓰는 한 한 페이지 안에
   공존 가능하다.

**패치 방식**: 새 pass 클래스(`liquid-metal-pass.js`)를 `patch-package`로 패키지에 신규
파일로 추가하고, `pipeline-manager.js`의 `createPass()`에 새 case(`layer.type ===
"liquid-metal"`)를 추가한다.

## 범위 결정 — 이미지 업로드는 제외

원본 `LiquidMetal`은 로고 이미지를 업로드해 그 위에 리퀴드 메탈 질감을 입히는 것이 핵심
용도이지만, 이미지를 마스크로 변환하는 `toProcessedLiquidMetal()`이 비동기 canvas 전처리
(edge gradient + opacity 추출)를 수행하는 무거운 로직이라 이번 범위에서 제외한다. 대신
셰이더가 기본 제공하는 `shape`(도형 프리셋: 없음/원/데이지/다이아몬드/메타볼) 기반으로만
동작하는 "소스" 레이어로 구현한다 — `fullScreenPreset`("Backdrop", `shape: "none"`)이 이미
이미지 없이 전체 화면을 채우는 표준 사용법으로 라이브러리에 내장돼 있어 이 범위로도
정상적인 시각 효과를 낼 수 있음을 확인했다. 이미지 업로드 지원은 후속 확장으로 유예한다.

## 상세 요구사항

### 패치 (`patches/`)

1. **신규 파일 `liquid-metal-pass.js`** (`PassNode` 확장, `text-pass.js` 패턴 참고):
   - 생성자: 뷰포트 좌상단에 겹치되 `opacity: 0; pointer-events: none; position: fixed`로
     시각적으로 숨긴 `<div>`를 만들어 `document.body`에 붙인다. `display: none`이나 화면 밖
     좌표(`left: -9999px`)는 쓰지 않는다 — `ShaderMount`의 `IntersectionObserver`가
     "화면 밖"으로 판정해 렌더링을 자동 정지시키기 때문(실측 확인 필요).
   - `updateParams(params)`: 최초 호출 시 `new ShaderMount(container,
     liquidMetalFragmentShader, uniforms, ...)`으로 마운트, 이후에는 `shaderMount.
     setUniforms(...)`만 호출. `u_image`는 항상 1x1 투명 픽셀(data URL 상수), `u_isImage:
     false` 고정(이미지 미지원 범위).
   - `render(...)`: `shaderMount.canvasElement`를 최초 1회 `THREE.CanvasTexture`로 감싸고
     매 프레임 `needsUpdate = true`(ShaderMount 자체 RAF가 그 canvas를 계속 갱신하므로).
   - `resize(width, height)`: container div의 CSS 크기를 갱신(ShaderMount의
     `ResizeObserver`가 자동으로 canvas 해상도를 맞춤).
   - `needsContinuousRender()`: `true`(줄무늬가 항상 흐르는 것이 이 레이어의 정체성 — 이전
     티켓 20260913_1819에서 제거한 "정적 이미지에 불필요한 자동 애니메이션"과는 성격이
     다르다. 플루이드·픽셀 트레일과 같은 카테고리).
   - `dispose()`: `shaderMount.dispose()` + container 엘리먼트 제거.
2. **`pipeline-manager.js` patch**: import 추가 + `layer.kind === "source" && layer.type ===
   "liquid-metal"` 케이스에서 `new LiquidMetalPass(layer.id)` 반환.
3. `npx patch-package @basementstudio/shader-lab`로 패치 파일 갱신.

### 의존성

4. `@paper-design/shaders`(코어, react 아님)를 `package.json` dependencies에 명시적으로
   추가 — 지금은 `@paper-design/shaders-react`의 전이 의존성으로만 node_modules에 존재해
   직접 import가 버전 관리 밖에 있다.

### UI/서비스 코드 (`jam-web/src/lib/admin/shaderLab/`, `jam-web/src/app/admin/shader-lab/`)

5. `effectRegistry.ts`: `SHADER_LAB_LAYER_TYPES`에 `'liquid-metal'` 추가(kind: 'source').
   파라미터 필드(원본 `LiquidMetalParams` 대조, 한국어 라벨):
   - `colorBack`(배경색, color), `colorTint`(틴트색, color)
   - `shape`(모양, select: 없음/원/데이지/다이아몬드/메타볼)
   - `repetition`(줄무늬 밀도, number 1~10), `softness`(경계 부드러움, number 0~1)
   - `shiftRed`/`shiftBlue`(색수차, number -1~1), `distortion`(왜곡, number 0~1)
   - `contour`(윤곽 강도, number 0~1), `angle`(방향, number 0~360)
   - sizing 관련(`fit`/`scale`/`rotation`/`offset*`/`origin*`/`worldWidth`/`worldHeight`)은
     `fullScreenPreset` 고정값을 그대로 써서 UI에는 노출하지 않는다(범위 최소화).
6. `layerFactory.ts`/`composition.ts`/`ShaderLabLayerSidebar.tsx`는 제너릭 코드라 별도 수정
   불필요할 가능성이 높음(착수 시 재확인).
7. `THIRD_PARTY_NOTICES.md`: (a) `@basementstudio/shader-lab` 패치 고지에 신규 파일 추가
   내용 보강, (b) `@paper-design/shaders`의 Apache License 2.0 NOTICE("Powered by Paper
   Shaders: https://shaders.paper.design") 신규 고지 추가.

## 구현 계획

1. `liquid-metal-pass.js` 작성 → `pipeline-manager.js` patch → `patch-package`로 패치 파일
   생성.
2. `package.json`에 `@paper-design/shaders` 의존성 추가.
3. `effectRegistry.ts`에 레이어 타입·필드 추가.
4. `THIRD_PARTY_NOTICES.md` 갱신.
5. esbuild+playwright 실측: (a) 레이어가 실제로 렌더링되는지(빈 화면이 아님을 확인),
   (b) 시간이 지나면 프레임이 계속 바뀌는지(애니메이션 확인 — 두 시점의 canvas 픽셀이
   달라야 함), (c) `shape` 값을 바꾸면 렌더링 결과가 달라지는지, (d) 레이어를 제거
   (`dispose()`)했을 때 숨겨진 DOM 엘리먼트가 실제로 정리되는지(DOM 누수 확인).
6. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` 재확인.

## 유예된 판단

- 이미지 업로드(로고를 리퀴드 메탈 질감으로 감싸는 원본 핵심 기능)는 이번 범위 밖.
- `speed`(애니메이션 속도) 파라미터는 고정값(1)으로 두고 UI에 노출하지 않는다 — 필요하면
  후속 확장.
