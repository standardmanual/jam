# [Admin] 쉐이더 랩 — 리퀴드 메탈 레이어 미리보기·스테이지 크기 불일치

## 배경 / 문제 정의

사용자가 어드민 쉐이더 랩에서 리퀴드 메탈 레이어를 선택했을 때, 미리보기(`ShaderLabViewport`)에
표시되는 결과물의 크기와 실제로 렌더링되어야 할 스테이지 크기가 서로 맞지 않는다는 것을
스크린샷과 함께 보고했다. 스크린샷만으로는 정확한 배율을 확정할 수 없지만, 사용자 체감상 실제
리퀴드 메탈 크기가 미리보기에 보이는 것보다 최소 3배 이상 커 보인다.

리퀴드 메탈 레이어는 티켓 [20260913_1948](20260913_1948_Admin_쉐이더랩-리퀴드메탈레이어추가.md)에서
"오프스크린 WebGL→WebGPU 브릿지" 방식으로 처음 추가됐고, 티켓
[20260913_2110](20260913_2110_Admin_쉐이더랩-리퀴드메탈이미지마스크-색상투명도지원.md)에서
이미지 마스크·색상 투명도가 추가됐다. 다른 28종 레이어와 달리 리퀴드 메탈만 실제 DOM에 붙는
숨겨진 `<div>`(`liquid-metal-pass.js`의 `this.container`)를 렌더링 스테이지로 쓴다는 구조적
차이가 있다 — 이 구조 자체가 이번 크기 불일치의 원인일 가능성이 높다.

## 사전 조사 결과 (오케스트레이터, Explore 에이전트 위임)

### 1. 미리보기와 실제 컴포지션 크기 체인

- 컴포지션(=출력) 크기는 `src/lib/admin/shaderLab/composition.ts:8`의
  `SHADER_LAB_OUTPUT_SIZE = 1280` 상수에서 시작해 모든 레이어 파이프라인에 그대로
  전달된다(`useShaderLabPlayback.ts` → `shader-lab-canvas-source.js` → `create-webgpu-renderer.js`
  → `pipeline-manager.js`). admin 코드는 `resize()`/`pixelRatio` 옵션을 전혀 넘기지 않는다.
- 화면에 보이는 미리보기 캔버스(`ShaderLabViewport.tsx:41,48`)는 실제 픽셀 버퍼(canvas
  width/height)가 1280×1280이지만, CSS 표시 크기는 `aspect-square w-full max-w-[560px]`로
  최대 560px까지만 축소돼 보인다(`ShaderLabExportPanel.tsx:5-6` 주석에도 "1:1 1280×1280
  고정 — 캔버스 백킹 스토어 자체가 이미 그 크기"라고 명시돼 있다). 이 축소 자체는 일반적인
  캔버스-CSS 관계라 다른 레이어에는 왜곡을 일으키지 않는다.

### 2. 리퀴드 메탈만의 별도 "진짜 스테이지"

- `liquid-metal-pass.js`의 `this.container`는 `document.body`에 직접 붙는 `position: fixed`
  `<div>`다(`opacity: 0; pointer-events: none`로 시각적으로만 숨김 — `display: none`/화면 밖
  좌표를 쓰지 않은 이유는 `ShaderMount`의 `IntersectionObserver`가 렌더링을 멈추기 때문이라고
  티켓 20260913_1948에 명시돼 있다).
- `resize(width, height)`가 이 `<div>`의 `style.width/height`를 컴포지션 크기 그대로
  `"1280px"`로 설정한다 — 이건 **미리보기 캔버스처럼 CSS로 축소 표시되는 값이 아니라, 실제
  문서 레이아웃상 1280×1280 CSS px 크기로 존재하는 진짜 DOM 박스**다. `ShaderMount`의
  `ResizeObserver`가 이 컨테이너 크기 변화를 감지해 내부 WebGL 캔버스 해상도를 맞춘다.
- 이 WebGL 캔버스 내용은 매 프레임 2D 캔버스로 미러링된 뒤 `THREE.CanvasTexture`로 감싸져
  최종 WebGPU 컴포지션에 텍스처로 공급된다.
- 다른 레이어 타입은 이런 구조를 쓰지 않는다: 텍스트 레이어(`text-pass.js`)도 캔버스를
  만들지만 `document.body`에 붙이거나 스타일을 지정하지 않는 순수 오프스크린 캔버스이고,
  나머지 레이어들은 WebGPU/TSL 노드로 직접 렌더링되어 별도 DOM 박스가 없다.

### 3. 사용자 확인 사항 — export 결과물도 미리보기와 동일하게 어긋난다

사용자가 "실제로 이미지를 생성(export)하면 미리보기에서 보여지는 대로 저장된다"고 확인했다.
즉 **미리보기 표시와 최종 export 파일이 서로 일치**한다 — export 파이프라인 자체에 미리보기와
별도의 버그가 있는 게 아니라, 리퀴드 메탈이 실제로 계산되는 "스테이지"(셰이더가 그려지는
좌표계·해상도) 단계에서 이미 어긋난 결과가 만들어지고, 그 결과가 미리보기·export 양쪽에
동일하게 전파되고 있다는 뜻이다. 첨부 스크린샷에서 패턴이 정사각형 프레임의 우하단 구석에
확대되어 잘린 형태로 보이는 것도 이 해석과 일치한다 — "훨씬 큰 캔버스에 그려진 패턴 중
한쪽 귀퉁이만 1280×1280 프레임 안에 들어온" 모습처럼 보인다.

→ 이 확인 사항 덕분에 원인 조사 범위가 좁혀진다: 컴포지션 텍스처 합성이나
`ShaderLabViewport`/`ShaderLabExportPanel`의 표시 로직 자체는 의심하지 않아도 되고,
`liquid-metal-pass.js`가 셰이더를 실제로 그리는 지점(`this.container`의 실제 CSS 크기 ↔
`ShaderMount` 내부 WebGL canvas의 실제 픽셀 버퍼 크기 ↔ 셰이더 좌표계 uniform)에 집중해서
파야 한다.

### 4. 원인 가설 (미확정 — 로컬 실측으로 검증 필요)

Explore 조사만으로는 "실제로 화면에 합성되는 리퀴드 메탈 패턴 자체의 스케일"이 잘못되는
정확한 지점까지는 특정하지 못했다. 다음 두 가설이 유력하며, 구현 착수 시 실측으로 좁혀야 한다.

1. **셰이더 좌표계 스케일 오류**: 티켓 20260913_2110의 완료 기록에 리퀴드 메탈 셰이더 소스가
   `pixel_thickness = min(250/캔버스크기, 0.5)`처럼 **절대 픽셀 값**을 캔버스 크기와 섞어
   계산하는 로직을 쓴다는 언급이 있다. `worldWidth`/`worldHeight`(셰이더의 "월드 좌표계"
   크기를 지정하는 파라미터, 20260913_1948에서 "UI에 노출하지 않고 `fullScreenPreset` 고정값
   그대로 사용"하기로 결정됨)가 실제 컨테이너 픽셀 크기(1280)와 어긋나 있다면, 줄무늬
   `repetition` 등 크기 의존적 파라미터가 의도한 것보다 훨씬 크게(또는 작게) 그려질 수 있다.
2. **ResizeObserver 타이밍/단위 문제**: `resize()`가 CSS px 문자열로 컨테이너 크기를 설정하는
   시점과 `ShaderMount`가 실제 WebGL canvas의 `width`/`height`(디바이스 픽셀) 속성을 갱신하는
   시점 사이에 `devicePixelRatio`가 이중으로 반영되거나, 초기 마운트 시 컨테이너가 아직
   레이아웃되지 않은 상태(`0px` 또는 브라우저 기본값)로 `ShaderMount`가 먼저 초기화돼버려
   이후 실제 리사이즈가 셰이더 좌표 계산에는 반영되지 않는 시나리오도 배제할 수 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 리퀴드 메탈 레이어를 선택했을 때 미리보기에 보이는 패턴의 스케일이 컴포지션(1280×1280)
  기준으로 다른 레이어(텍스트·이미지 등)와 시각적으로 일관된 비율을 갖도록 수정한다.
- 수정 대상은 `patches/@basementstudio+shader-lab+3.0.2.patch`(`liquid-metal-pass.js`) 쪽일
  가능성이 높지만, 위 가설 검증 결과에 따라 admin 쪽 코드(`useShaderLabPlayback.ts` 등)의
  `resize` 호출 누락일 수도 있다 — 착수 시 먼저 실측으로 원인을 확정한 뒤 계획을 구체화한다.
- 사이드 이펙트 점검: 이번 수정이 티켓 20260913_2110에서 확립한 "코너 픽셀은 테두리 감쇠
  마스크 영향권, 중앙 픽셀이 애니메이션 판정 기준" 같은 기존 실측 전제를 깨뜨리지 않는지
  확인한다(캔버스 크기 계산을 바꾸면 테두리 감쇠 범위도 함께 바뀔 수 있음).

### UI/UX 관점

- 리퀴드 메탈 레이어의 미리보기가 실제 배지/미션/컬렉션에 적용됐을 때의 최종 결과물과
  동일한 비율로 보여야 한다 — `ShaderLabApplyTab.tsx`의 160×160 적용 미리보기와
  `ShaderLabExportPanel.tsx`의 최종 PNG 내보내기 결과물도 함께 확인 대상에 포함한다.

## 구현 계획

1. 로컬 실렌더(`DEV_PROCESS_GUARDRAILS.md` 패턴 13, `ADMIN_EMAILS` 셸 환경변수 방식)로
   현재 버그를 먼저 재현한다. 사용자 확인대로 export=미리보기가 일치하므로, 원인 조사는
   `liquid-metal-pass.js`의 `this.container` 실제 CSS 크기, `ShaderMount` 내부 WebGL
   canvas의 실제 픽셀 버퍼 크기(`canvas.width`/`canvas.height`), 셰이더에 전달되는
   해상도·좌표계 uniform(`u_resolution`, `worldWidth`/`worldHeight` 등) 세 값을 직접
   로그·`readPixels`로 찍어 비교하는 데 집중한다 — 위 가설 1·2 중 실제 원인을 확정한다.
2. 확정된 원인에 맞춰 `liquid-metal-pass.js`(패치) 또는 admin 호출부를 수정한다.
3. 수정 후 리퀴드 메탈 미리보기 스케일이 컴포지션 크기와 일치하는지, `repetition`·`softness`
   등 크기 의존 파라미터가 조정 시 기대한 시각적 결과를 내는지 재확인한다.
4. `ShaderLabApplyTab.tsx`·`ShaderLabExportPanel.tsx` 양쪽에서도 동일하게 정상 비율로
   보이는지 확인한다.
5. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` 재확인.
