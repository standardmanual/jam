# [Admin] 쉐이더 랩 — PNG 다운로드 해상도를 1920으로 상향

## 배경 / 문제 정의

사용자가 쉐이더 랩 PNG 다운로드 전반의 해상도가 너무 낮다며, 1920 해상도로 높여달라고
요청했다. 현재 컴포지션(=출력) 해상도는 `SHADER_LAB_OUTPUT_SIZE = 1280`으로 고정돼 있다.
UI·코드 어디에도 종횡비를 고르는 옵션이 없고 항상 정사각형(1:1)으로 고정돼 있으므로,
1280×1280 → 1920×1920으로 폭·높이를 동일하게 올리는 것이 유일하게 자연스러운 해석이다.

## 사전 조사 결과 (오케스트레이터, Explore 에이전트 위임)

### 상수 전파 경로

`SHADER_LAB_OUTPUT_SIZE`(`jam-web/src/lib/admin/shaderLab/composition.ts:8`)를 참조하는
곳은 같은 파일의 `createEmptyComposition()`/`buildComposition()` 두 곳뿐이다. 그 외
`ShaderLabViewport`·`ShaderLabExportPanel`·`ShaderLabApplyTab` 등은 이 상수를 직접 참조하지
않고, `config.composition.width/height`를 거쳐 간접적으로 물려받는다 — 즉 상수 값을 바꾸면
미리보기 캔버스의 실제 렌더 해상도(WebGPU backing store), export PNG 해상도, 개별 pass의
`resize()` 인자(예: 리퀴드 메탈)까지 자동으로 전파된다. `ShaderLabApplyTab`의 160×160은
미리보기 `<img>`를 담는 CSS 박스 크기일 뿐 실제 캡처(`canvas.toDataURL`/`canvasToBlob`)는
원본 해상도 그대로 이뤄진 뒤 축소 표시되므로 무관하다.

### 상수 외에 함께 고쳐야 할 곳

`ShaderLabViewport.tsx:61`에 `"1280×1280"`이 텍스트로 하드코딩돼 있다 — 상수만 바꾸면 실제
출력은 1920×1920인데 화면에는 계속 "1280×1280"이라고 표시된다. 이 표시 문구도 상수 참조로
바꾸거나 함께 갱신해야 한다. 그 외 코드 안의 `1280` 리터럴은 `composition.ts:4`·
`ShaderLabExportPanel.tsx:5`의 주석뿐이라 로직에는 영향 없지만, 설명이 실제와 달라지지 않도록
같이 갱신한다.

### 성능·용량 영향 — 실측 필요

1. **리퀴드 메탈 레이어의 매 프레임 복사 비용 증가**: `liquid-metal-pass.js`의 `render()`가
   `needsContinuousRender()=true`이므로 레이어가 있는 한 매 프레임 오프스크린 WebGL 캔버스를
   2D 캔버스로 `drawImage` 복사한다. 1280×1280 → 1920×1920은 픽셀 수 기준 약 2.25배 증가라
   이 복사 비용도 그만큼 커진다. 바로 이 경로가 티켓
   [20260914_0953](20260914_0953_Admin_쉐이더랩-리퀴드메탈-미리보기스테이지크기불일치.md)에서
   수정한 지점과 같다 — 그 수정("mirrorCanvas 크기가 소스와 달라질 때마다 텍스처 재생성")은
   크기 값 자체와 무관하게 안전하게 동작하므로 새 버그가 생기진 않지만, 실제 애니메이션이
   1920 해상도에서도 매끄럽게 흐르는지는 실측으로 확인해야 한다.
2. **`ShaderLabApplyTab`의 5MB 업로드 캡과 충돌 가능성**: `applyGeneratedImageConstants.ts`의
   `MAX_APPLY_IMAGE_BYTES = 5 * 1024 * 1024`를 `runApply()`가 강제한다(순수 PNG 다운로드
   버튼에는 이 제한이 없음). 픽셀 수가 2.25배 늘어나므로, 노이즈·그레인이 많은 레이어(잉크·
   CRT·디더링 등) 조합에서는 PNG 파일 크기가 이 캡에 더 쉽게 걸릴 수 있다 — 실측으로 확인이
   필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `SHADER_LAB_OUTPUT_SIZE`를 1280 → 1920으로 변경한다.
- `ShaderLabViewport.tsx:61`의 하드코딩된 "1280×1280" 표시 문구를 실제 값과 일치하도록
  수정한다(상수 참조 또는 리터럴 갱신).
- `composition.ts:4`·`ShaderLabExportPanel.tsx:5`의 주석도 실제 값에 맞게 갱신한다.
- 리퀴드 메탈 레이어의 애니메이션이 1920 해상도에서도 매끄럽게 동작하는지, 눈에 띄는 프레임
  드랍이 없는지 확인한다.
- 노이즈성 레이어(잉크·CRT·디더링 등 파일 크기가 크게 나올 만한 조합) 몇 종을 1920 해상도로
  export해 5MB 캡에 걸리는 사례가 있는지 확인한다 — 걸리는 경우가 실제로 있다면 캡 상향
  여부를 사용자에게 보고하고 판단을 구한다(이 티켓 범위를 벗어나는 결정일 수 있음).

## 구현 계획

1. `SHADER_LAB_OUTPUT_SIZE` 상수 변경 + `ShaderLabViewport.tsx` 표시 문구 수정 + 관련 주석
   갱신.
2. 로컬 실렌더(`DEV_PROCESS_GUARDRAILS.md` 패턴 13)로 미리보기·export PNG가 실제 1920×1920
   해상도로 나오는지 확인한다.
3. 리퀴드 메탈 레이어를 추가한 상태에서 애니메이션이 매끄럽게 흐르는지, 눈에 띄는 성능 저하가
   없는지 확인한다.
4. 노이즈성 레이어 조합으로 export한 PNG 파일 크기를 몇 가지 측정해 5MB 캡 근처인지 확인한다.
5. `ShaderLabApplyTab.tsx` 적용 결과물도 1920 해상도 기준으로 정상 동작하는지 확인한다.
6. `npx tsc --noEmit`, `npm run lint`, `npx vitest run` 재확인.
