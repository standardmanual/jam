# [Admin] 쉐이더 랩 — PC 화면에서 스크롤 시 미리보기 영역 고정

## 배경 / 문제 정의

쉐이더 랩은 레이어·미리보기·속성 3단 그리드로 구성돼 있다. 레이어가 많거나 선택한 레이어의
속성 필드가 많으면 페이지 전체가 길어지는데, 이때 페이지를 스크롤하면 미리보기도 함께
화면 밖으로 밀려나 작업하면서 결과를 계속 눈으로 확인하기 어렵다는 문제가 있었다. PC(넓은
화면) 기준으로, 스크롤 중에도 미리보기는 화면에 고정하고 레이어·속성 영역만 스크롤되도록
요청받았다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `page.tsx`의 미리보기 `<Card>`에 PC 화면(`lg` 브레이크포인트 이상)에서 `position: sticky`를
  적용한다.
- 어드민 공통 헤더(`AdminHeader`, `sticky top-0 h-14`)와 겹치지 않도록, 기존
  `AdminEditorLayout.tsx`가 이미 쓰고 있는 관례값(`top-[4.5rem]`, 헤더 높이 + 여백)을 그대로
  재사용한다.
- 3단 그리드가 `align-items: stretch`(그리드 기본값)라 미리보기 카드가 가장 긴 컬럼 높이만큼
  늘어나면 sticky가 의도대로 동작하지 않으므로, `self-start`로 카드 자신의 콘텐츠 높이만
  차지하도록 한다.

## 구현 계획

1. `ShaderLabPage`(`page.tsx`)의 미리보기 `<Card>`에
   `lg:sticky lg:top-[4.5rem] lg:self-start` 클래스를 추가한다.
2. 로컬 실렌더(`DEV_PROCESS_GUARDRAILS.md` 패턴 13)로 레이어를 여러 개 추가해 목록을 화면
   높이보다 길게 만든 뒤, 실제 스크롤 시 미리보기 카드가 헤더 아래 정확한 위치에 고정되는지
   확인한다.
3. `npx eslint`(변경 파일)로 최소 검증한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`page.tsx`의 미리보기 `<Card>`에 `lg:sticky lg:top-[4.5rem] lg:self-start`를 추가했다.
`top-[4.5rem]`(72px)은 `AdminEditorLayout.tsx`가 이미 쓰고 있는 관례값을 그대로 재사용해
어드민 공통 헤더(`sticky top-0 h-14`, 56px) 바로 아래 적절한 여백을 두고 고정되도록 했다.
`self-start`는 그리드 기본 `align-items: stretch` 때문에 미리보기 카드가 가장 긴 컬럼(레이어
또는 속성 패널) 높이까지 늘어나 sticky가 무력화되는 것을 막기 위해 필요했다.

      디스플레이스먼트맵 등 6개 레이어를 추가해 목록을 화면 높이(뷰포트 500px)보다 길게
      만든 뒤, JS로 `getBoundingClientRect()`를 스크롤 위치별로 직접 측정해 확인했다:
      - `position: sticky`, `top: 72px`가 실제 computed style에 정확히 적용됨
      - 스크롤 100~350px 구간 전체에서 미리보기 카드의 뷰포트상 top이 정확히 72px로
        고정 유지됨
      - 400px(부모 grid row 바닥 도달 지점 이후)로 더 스크롤하면 카드가 그 시점부터는
        문서 흐름을 따라 같이 위로 밀려남 — 이는 표준 sticky 동작(부모 컨테이너를
        벗어나면 고정이 풀림)이라 의도한 그대로다.
