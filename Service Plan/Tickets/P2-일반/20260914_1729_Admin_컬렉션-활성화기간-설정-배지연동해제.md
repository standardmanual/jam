# [Admin] 컬렉션 활성화 기간(시작-종료) 설정 및 배지 연동 해제

## 배경 / 문제 정의
현재 `item_books`(컬렉션) 테이블은 `is_active` boolean만 갖고 있고, 어드민 화면
(`ItemBookTable.tsx`의 `ItemBookActiveToggleButton`)에서도 단순 on/off 토글만 지원한다.
컬렉션을 비활성화하면 `jam-web/src/lib/admin/itembook-deactivation.ts`의
`cascadeDeactivateItemBookBadges`가 소속 배지 전체를 연쇄 비활성화(`deleted_at` 세팅 +
`deactivated_by_item_book_id` 기록)하고, 재활성화 시 `cascadeActivateItemBookBadges`가
그 배지들만 되살린다.

사용자 요청은 다음 두 가지다.
1. 컬렉션에 시작-종료 기간을 지정해 예약 노출(및 자동 만료)이 가능하게 한다. 배지 상세화면에
   이미 있는 기간 설정 UI/로직을 참고한다.
2. 컬렉션의 활성 상태와 소속 배지의 활성 상태를 더 이상 연동하지 않는다. 컬렉션이 비활성(또는
   기간 밖)이어도 소속 배지의 `item_book_id` 지정 목록은 그대로 유지하고, 배지 자체의 활성
   여부는 컬렉션과 무관하게 독립적으로 관리된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `item_books` 테이블에 활성화 시작/종료 시각 컬럼을 추가한다(마이그레이션 파일 작성, 배지
  상세화면의 기존 기간 컬럼·판정 로직을 참고해 동일한 패턴으로 맞춘다).
- 컬렉션의 "활성 상태" 판정은 기간(시작 ≤ 현재 < 종료, 종료 미설정 시 시작 이후 계속 활성 등
  배지 쪽 기존 규칙과 동일하게) 기준으로 계산한다.
- `cascadeDeactivateItemBookBadges` / `cascadeActivateItemBookBadges` 및 이를 호출하는
  지점을 제거한다. 컬렉션 활성화/비활성화(또는 기간 설정) 작업이 배지의 `deleted_at`,
  `deactivated_by_item_book_id`를 더 이상 건드리지 않게 한다.
- 배지 노출 판정 로직(서비스 측 컬렉션/배지 조회 API·쿼리)에서: 배지가 소속된 컬렉션이 비활성
  (기간 밖 포함)이면 **컬렉션**은 노출하지 않는다. 배지 자체는 컬렉션 상태와 무관하게 자신의
  활성 여부로만 노출 판단한다. 즉 컬렉션 비활성 시에도 배지-컬렉션 연결(`item_book_id`)은
  삭제·해제하지 않고 유지한다.
- `deactivated_by_item_book_id` 컬럼(마이그레이션 146)이 이번 변경으로 더 이상 쓰이지 않게
  되면 사용처 전체를 확인하고 정리 방향을 구현 단계에서 판단한다(즉시 컬럼 삭제까지는 이번
  티켓 범위인지 여부를 구현 시 재검토 — 최소 범위로는 코드 참조 제거만 하고 컬럼 자체는
  후속 티켓으로 미뤄도 됨).

### UI/UX 관점 (해당 시)
- 컬렉션 상세화면(어드민)에 시작일시-종료일시 입력 UI를 추가한다. 배지 상세화면의 동일 UI
  컴포넌트/패턴을 그대로 재사용한다(신규 컴포넌트 제작 금지, 기존 것을 확인하고 재사용).
- 기존 `ItemBookActiveToggleButton`(단순 on/off)은 기간 기반 설정과의 관계를 정리한다
  (완전 대체할지, 병기할지는 배지 상세화면의 기존 패턴을 그대로 따른다).

### 컨텐츠 관점 (해당 시)
- 해당 없음.

### 구현 내용 요약
- `item_books`에 `valid_from`/`valid_until`(마이그레이션 171) 추가 — `badges.valid_from/
  valid_until`(마이그레이션 025)과 동일한 패턴. 컬렉션 상세 폼(`ItemBookForm.tsx`)에
  `BadgeForm.tsx`의 "유효기간" 섹션과 동일한 UI(날짜 두 칸 + `~` + 초기화 버튼)를 추가했다.
- `cascadeDeactivateItemBookBadges`/`cascadeActivateItemBookBadges`(및 파일
  `lib/admin/itembook-deactivation.ts`)를 완전히 삭제. `PUT`/`PATCH /api/admin/itembooks/[id]`
  호출부에서 캐스케이드 호출을 제거하고, 관련 영향 범위 조회 라우트
  (`/api/admin/itembooks/[id]/deactivation-impact`)도 함께 삭제했다 — 캐스케이드가 없어지면서
  "소속 배지 N개가 함께 비활성화됩니다"라는 조회·경고 자체가 더 이상 사실이 아니게 되기
  때문. 확인 모달 문구는 `BadgeActiveToggleButton`과 동일하게 정적 문구("유저에게 더 이상
  노출되지 않습니다. 소속 아이템배지에는 영향을 주지 않습니다.")로 단순화했다
  (`ItemBookForm.tsx`, `ItemBookActiveToggleButton.tsx`, `ItemBookTable.tsx` 일괄 비활성화
  확인 모달 포함).
- 노출 판정 = `is_active && (valid_from is null or <= now) && (valid_until is null or >= now)`.
  기존에 `item_books.is_active`만 필터하던 8개 서비스 쿼리 지점에 기간 조건을
  `.or(...)` 두 번으로 추가했다(배지 쪽 `badge-engine/index.ts`와 동일한 필터 문법):
  `api/users/[username]/itembooks/route.ts`, `(main)/[username]/collections/page.tsx`,
  `(main)/[username]/page.tsx`(컬렉션 카운트), `lib/itembook/completable.ts`,
  `lib/itembook/checker.ts`, `lib/notifications/batch/collections.ts`,
  `lib/drop-engine/index.ts`(아이템 배지 드랍 후보 컬렉션 필터), `lib/today/status.ts`.
  이 필터는 컬렉션 자체의 노출/드랍 후보 여부만 결정하며, 소속 배지의 `item_book_id` 연결과
  배지 자체 활성 여부(`badges.deleted_at`)는 전혀 건드리지 않는다.
- `deactivated_by_item_book_id`(마이그레이션 146) 컬럼: 이 티켓으로 캐스케이드가 폐지되면서
  이 컬럼을 채우는 코드가 더 이상 존재하지 않는다. `api/admin/badges/[id]/route.ts`의 PATCH가
  개별 토글 시마다 이 컬럼을 NULL로 리셋하던 로직도 이제 의미가 없어 제거했다. **컬럼 자체는
  삭제하지 않았다** — 과거 데이터 보존 및 범위 재검토를 위해 후속 티켓으로 미룸(아래
  "잔여 이슈" 참조).
- 컬렉션 상세 읽기 전용 요약(`ItemBookDetail.tsx`)에 `BadgeDetail.tsx`의 "유효기간" 표시와
  동일한 "노출 기간" 항목을 추가했다.
- `POST /api/admin/itembooks`(신규 등록)도 `valid_from`/`valid_until`을 받아 저장하도록
  확장했다 — `ItemBookForm.tsx`가 신규/수정 양쪽에 동일한 body를 보내기 때문에 필요했다.

### 주요 의사결정 / 핵심 메모
- **UI 재사용**: 오케스트레이터 지시대로 `BadgeForm.tsx`의 "유효기간" 섹션(날짜 두 칸 + `~` +
  초기화 버튼, `FieldLabel`/`FieldMessage` 조합)을 그대로 복제했다. 신규 컴포넌트로
  추상화하지 않고 배지 쪽과 동일한 인라인 패턴을 답습했다 — 두 폼의 스타일이 이미 조금씩
  다르고(BadgeForm은 그리드 레이아웃 헬퍼를 쓰는 반면 ItemBookForm은 단순 flex 컬럼), 공통
  컴포넌트로 뽑으면 오히려 두 폼의 기존 스타일 차이를 강제로 맞춰야 해 범위가 커진다.
- **"병기" vs "완전 대체" 판단**: 배지는 활성/비활성(소프트 삭제, `BadgeActiveToggleButton`)과
  유효기간(`valid_from/until`)이 완전히 독립된 별개 개념으로 병존한다(배지 폼 안에는 활성
  토글이 없고, 유효기간만 있다 — 활성/비활성은 목록·상세의 별도 버튼으로만 관리). 컬렉션도
  동일하게 "활성화 Switch(is_active)"와 "노출 기간(valid_from/until)"을 **병기**하는 쪽으로
  구현했다 — 노출 여부는 `is_active AND 기간` 둘 다를 만족해야 한다.
- **영향 범위 조회 라우트 삭제**: 캐스케이드가 없어지면서 `/deactivation-impact`가 보여주던
  "소속 배지 N개·보유 유저 M명에게 영향"이라는 경고 자체가 거짓 정보가 된다. 이 라우트를
  살려두고 문구만 지우는 대신, 배지 쪽(`BadgeActiveToggleButton`)이 원래 쓰던 "정적 확인
  문구" 패턴으로 통일해 라우트를 완전히 제거했다 — 사용하지 않는 API가 남는 것도, 잘못된
  정보를 보여주는 확인 모달도 둘 다 피하는 선택.
- **`deactivated_by_item_book_id` 컬럼 삭제는 이번 범위 밖으로 재확인**: 티켓 본문의 지시대로
  "구현 시 재검토"했고, 과거 캐스케이드로 이미 세팅된 프로덕션 데이터가 있을 수 있어(이력
  성격) 컬럼 자체를 지우는 마이그레이션은 만들지 않았다. 이 컬럼을 채우던 유일한 코드
  경로(캐스케이드)가 사라졌으므로 앞으로는 항상 NULL로 유지된다.

### 잔여 이슈
- `deactivated_by_item_book_id` 컬럼(마이그레이션 146)이 이제 어떤 코드에서도 채워지지
  않는다. 과거 캐스케이드로 세팅된 값이 남아있을 수 있는데, 이 값을 참고하는 코드가 없으니
  현재는 완전히 죽은 데이터다. 컬럼 제거(마이그레이션) 또는 데이터 정리는 후속 티켓에서
  판단할 것.
- 컬렉션 목록 테이블(`ItemBookTable.tsx`)에는 노출 기간 컬럼을 추가하지 않았다 — 배지 목록
  테이블(`BadgeList.tsx`)도 유효기간을 목록에 노출하지 않고 상세화면에만 표시하는 기존
  패턴과 동일하게 맞춘 것으로, 이번 범위에서 의도한 선택이다.
