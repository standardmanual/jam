# [Admin] 쉐이더 랩 — 배지/미션/컬렉션 대표이미지 적용 시 PNG 자동 용량 축소

## 배경 / 문제 정의

셰이더 랩에서 배지·미션 대표이미지·컬렉션 대표이미지로 "적용"할 때, 결과 PNG가
`MAX_APPLY_IMAGE_BYTES`(5MB)를 넘으면 지금까지는 에러만 띄우고 적용을 막았다
(`ShaderLabApplyTab.tsx`의 `runApply()`, 서버 쪽 `apply/route.ts`도 동일 상한으로 이중
검증). 사용자가 직접 캔버스 파라미터(해상도·이펙트 복잡도 등)를 조절해 용량을 줄여야 했다.

목표: 적용 시 자동으로 허용 용량의 70% 정도로 줄여서 등록되게 한다. **일반 PNG
다운로드**(`ShaderLabExportPanel`의 `downloadPng`)는 사용자가 직접 받는 원본 파일이므로
용량을 줄이지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 적용(`runApply()`) 직전에 캔버스를 PNG로 인코딩한 결과가 목표 용량(허용치의 70%)을
  넘으면 자동으로 줄여서 적용한다.
- PNG는 무손실 포맷이라 JPEG처럼 "화질"을 낮춰 용량을 줄일 수 없다 — 해상도를 줄이는
  방식으로 접근한다.
- 목표 용량에 도달하지 못해도(예: 이미 매우 작은 해상도인데 압축이 거의 안 되는 노이즈성
  이미지) 무한정 반복하지 않고, 기존 5MB 상한 체크(클라이언트·서버 양쪽)가 최종 안전망
  역할을 그대로 유지한다.
- 일반 PNG 다운로드 경로는 건드리지 않는다.

## 구현 계획

1. `applyGeneratedImageConstants.ts`에 `TARGET_APPLY_IMAGE_BYTES = MAX_APPLY_IMAGE_BYTES *
   0.7` 상수 추가.
2. `ShaderLabApplyTab.tsx`에 `compressCanvasPngToTarget(canvas, targetBytes)` 헬퍼 추가 —
   먼저 원본 그대로 인코딩해 이미 목표 이하면 그대로 반환하고, 아니면 매번 90%씩 축소한
   임시 캔버스에 `drawImage`로 다시 그려 재인코딩하는 걸 목표 용량 이하가 되거나 최대
   시도 횟수(20회)·최소 해상도(32px)에 도달할 때까지 반복.
3. `runApply()`가 `canvasToBlob(canvas)` 대신 `compressCanvasPngToTarget(canvas,
   TARGET_APPLY_IMAGE_BYTES)`를 쓰도록 교체. 기존 `MAX_APPLY_IMAGE_BYTES` 초과 시 에러
   처리는 최종 안전망으로 그대로 둔다.
4. `ShaderLabExportPanel.tsx`(일반 다운로드)는 변경하지 않는다.
5. 로컬 브라우저 실렌더로 검증 — 압축이 거의 안 되는 최악 조건(1920×1920 완전 랜덤
   노이즈 PNG)에서도 목표 용량 이하로 수렴하는지 확인.
6. `npx tsc --noEmit`, 변경 파일 `eslint`.

## 완료 기록

### 구현 내용 요약

구현 계획 1~6 그대로 진행했다. `compressCanvasPngToTarget()`는 원본이 이미 목표 이하면
재인코딩 없이 그대로 반환해(가장 흔한 경우 — 실제 배지 이미지는 단색·그라디언트 위주라
PNG 압축이 잘 먹는다) 불필요한 화질 손실이 없다. 목표를 넘을 때만 해상도를 단계적으로
줄인다.

### 변경된 파일
```
jam-web/src/lib/admin/applyGeneratedImageConstants.ts
  (TARGET_APPLY_IMAGE_BYTES 상수 추가)
jam-web/src/app/admin/shader-lab/ShaderLabApplyTab.tsx
  (compressCanvasPngToTarget 헬퍼 추가, runApply()가 이를 사용하도록 교체)
```

### 주요 의사결정 / 핵심 메모

- **PNG는 해상도 축소로만 용량을 줄였다**: JPEG 변환 등 손실 압축으로 바꾸는 방안도 있었지만,
  요구사항이 "PNG로 등록"이고 배지·대표이미지는 투명 배경을 쓰는 경우가 많아(최근
  20260915_1042~1156 티켓들) JPEG는 알파 채널 자체를 지원하지 않아 채택하지 않았다.
- **원본이 이미 목표 이하면 재인코딩을 아예 건너뛴다**: 대부분의 실제 사용 사례(단색·그라디언트
  위주 배지 이미지)에서 불필요한 화질 손실을 피하기 위함이다.
