# [UI] 컬렉션 상세화면 대표 이미지+이름 영역을 배지 상세화면 구조와 통일

## 배경 / 문제 정의
컬렉션 상세화면(`/collections/[id]`)의 대표 이미지~설명 영역이 배지 상세화면
(`/badges/[id]`)의 동일 영역과 마크업 구조가 달랐다. 배지 상세는 이미지+이름이
`bg-surface-elevated` 카드 하나에 속하고 설명은 카드 밖에 분리돼 있는 반면, 컬렉션 상세는
대표 이미지가 카드 전체를 꽉 채우고 이름·설명이 별도 블록으로 나뉘어 있어 두 상세화면의
시각 구조가 어긋나 있었다.

## 상세 요구사항

### UI/UX 관점
- 수정 대상: 컬렉션 상세화면의 대표 이미지 ~ 설명 영역 (`ItemBookHeroSection.tsx`)
- 수정 방향: 배지 상세화면(`BadgeHeroSection.tsx`)의 동일 영역 구조에 맞춰 변경
  - 이미지 + 이름을 하나의 카드(`bg-surface-elevated`, `rounded-[var(--radius-cards)]`, `p-6`)로 묶음
  - 설명은 카드 밖(`mt-6`)으로 분리
- 추가사항: 배지 이미지 크기(200×200px 고정)에 맞춰 컬렉션 대표 이미지도 동일 크기로 수정

### UI 재사용 판정 (오케스트레이터 결정)
서비스 전용 구현 유지 — MODULAR `_ds_manifest.json`에 히어로 카드 패턴 없음,
`BadgeHeroSection.tsx` 주석에도 'MODULAR 신규 컴포넌트 아님' 명시. `ItemBookHeroSection.tsx`를
`BadgeHeroSection.tsx` 패턴에 맞춰 개별 수정한다.

## 구현 계획
`ItemBookHeroSection.tsx`의 마크업을 `BadgeHeroSection.tsx`와 동일한 구조로 재작성한다.
진행도 바(`ProgressBar`)는 이번 티켓 범위 밖이라 기존 위치·마크업을 유지한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `ItemBookHeroSection.tsx`의 대표 이미지 카드를 배지 상세와 동일한 구조로 재작성:
  - 이미지+이름을 `bg-surface-elevated`(애니메이션 배경 시 `bg-transparent`) +
    `rounded-[var(--radius-cards)]` + `aspect-square` + `p-6` 카드 하나로 묶음
  - 대표 이미지를 200×200px 고정 컨테이너로 축소(기존에는 카드 전체를 꽉 채우는 크기)
  - 이름(`h1`)을 카드 안으로 이동, 설명(`p`)은 카드 밖 `mt-6`으로 분리
  - 진행도 바는 기존 위치·마크업 그대로 유지(부모 컨테이너의 `gap-3`에 의존)
- 어드민 배경 제너레이터 미리보기(`ItemBookDetailPreviewFrame.tsx`)는 동일 컴포넌트를
  그대로 재사용하므로 별도 수정 없이 함께 반영됨

### 재작업 (게이트 리뷰 FAIL 대응, 2차 시도)
- **간격 이중 계산 수정**: 카드 div + 설명 p를 Fragment로 나란히 최상위 반환하던 구조를,
  카드+설명을 하나의 outer `<div>`로 감싸는 구조로 변경. 이 컴포넌트는 부모
  (`collections/[id]/page.tsx`, `ItemBookDetailPreviewFrame.tsx` 모두 `flex flex-col gap-3`)의
  직속 자식으로 렌더링되므로, 카드/설명이 각각 최상위 자식이면 부모 gap-3(12px)가 둘 사이에도
  적용돼 설명 자체의 mt-6(24px)과 합산된 36px로 벌어졌다(배지 상세는 mt-6 단독 24px).
  outer wrapper로 감싸 부모 gap이 wrapper 앞뒤에만 적용되게 하고, wrapper 내부 카드~설명
  간격은 mt-6만으로 결정되도록 수정. 진행도 바는 wrapper 밖에 남겨 기존 gap-3 리듬 유지.
- **이름 타이포 통일 판단**: 컬렉션 이름(`h1`)의 하드코딩 `fontSize: 24px, lineHeight: 1.2`를
  배지 상세와 동일한 `var(--text-heading-sm)`(28px)/`var(--leading-heading-sm)` 토큰으로
  통일. 근거 — 이번 티켓의 목적이 두 상세화면의 대표 이미지~설명 영역 "구조 통일"이고, 카드
  크기·이미지 크기(200×200px)까지 동일하게 맞춘 상황에서 이름 폰트 크기만 다른 값으로
  하드코딩해 둘 이유가 없다고 판단(디자인 토큰 사용은 회귀 리스크도 낮음). 단, 글자 색상
  (`#FFFFFF` 고정)은 그대로 유지 — 배지 상세는 배경 테마 유무에 따라 흰/기본색을 조건부로
  쓰지만, 컬렉션 상세는 항상 테마 배경 위에 렌더링돼 전제 조건이 달라 이번 티켓 범위(구조
  통일) 밖으로 판단해 손대지 않았다.

### 재작업 (게이트 리뷰 FAIL 대응, 3차 시도 — 카드 경계 시각 보정)
- **원인**: 2차 시도 PASS 판정 후 오케스트레이터가 로컬 실렌더로 확인한 결과, 카드 배경
  `bg-surface-elevated`(#1f1f1f)와 페이지 배경 `--color-surface`(#1a1a1a)의 명도 차이가
  5/255뿐이라 카드 경계가 육안으로 거의 인지되지 않았다. 배지 상세(`BadgeHeroSection`)는
  배지 이미지 자체가 카드 전체를 채우는 정사각형 아트워크라 이미지로 경계가 자연히
  드러나지만, 컬렉션 대표 이미지는 200×200px 컨테이너 안의 작은 원형 아이콘이라 카드의
  빈 배경 여백이 그대로 노출돼 카드 존재감이 약했다.
- **수정**: 새 임의 색상값을 하드코딩하지 않고 기존 디자인 토큰
  `--color-border`(`design-system/tokens/colors.css`, `#2a2a2a` = `--color-base-grey-700`)를
  그대로 사용해 카드에 `border border-[var(--color-border)]`(1px)를 추가했다. 이 토큰은
  `ModalToast.jsx`·`RarityBadge.stories.tsx`·어드민 `dashboard.html` 등에서 이미 카드
  테두리 용도로 쓰던 값이라 신규 값이 아니다.
- **애니메이션 모드는 제외**: `backgroundAnimation`이 있을 때는 카드 전체가 애니메이션
  고유 배경색(`backgroundAnimation.bgColor`)으로 채워져 페이지 배경과 이미 시각적으로
  구분되므로(테두리가 없어도 경계가 보임) 테두리를 추가하지 않았다. `bg-surface-elevated`
  분기(기본 카드)에만 조건부로 적용.
- 배지 상세(`BadgeHeroSection.tsx`)는 이번 재작업에서도 손대지 않음 — 배지 이미지 자체로
  이미 경계가 드러나 같은 문제가 없고, 티켓 범위는 컬렉션 상세 쪽 시각 보정으로 한정.
