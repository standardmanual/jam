## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
ADR 0001(서버-클라이언트 단일 진실 소스)에 맞춰 drops 도메인 API가 `d.drops.*`로 완성한
사용자 문구를 직접 반환하도록 바꾸고, 클라이언트는 그 문구를 그대로 신뢰해 노출하도록
정비했다. `DropsClient.tsx`·`BadgeDetailSheet.tsx`·`drops/page.tsx`는 조사 결과 이미
딕셔너리 키만 참조하고 있어(하드코딩 한글 리터럴 없음) 추가 편입이 필요 없었다. 대신 실제
"서버 메시지를 무시하고 코드→문구 매핑을 자체적으로 갖는" 패턴은 `PoiCarouselModal.tsx`
(드랍/픽업/POI별 드랍목록 API의 실제 소비 컴포넌트)에 있었다 — 티켓의 화면 목록에는 없었지만
API 계약을 바꾸는 이번 작업을 완결하려면 반드시 함께 고쳐야 해서 포함했다(아래 alerts 참고).

- `api/drops/route.ts`(GET/POST), `api/drops/[dropId]/pickup/route.ts`, `api/drops/poi/[poiId]/route.ts`,
  `api/drops/[dropId]/route.ts`: `error` 필드를 snake_case 코드 대신 `d.drops.*`로 완성한
  실제 문구로 변경. 반경 안내(`dropOutOfRange`/`pickupOutOfRange`)는 `t()`로 `DROP_RADIUS_METERS`를
  서버에서 직접 주입.
- `PoiCarouselModal.tsx`: `executeDrop`/`executePickup`/`fetchPoiDrops`의 코드→문구 매핑 객체를
  전부 제거하고 `err.error ?? d.drops.xxxFailed`로 서버 문구를 그대로 신뢰하도록 변경. 더 이상
  쓰지 않는 `DROP_RADIUS_METERS` import 제거.
- `DropsClient.tsx`의 `loadNearbyPois`: `res.ok` 확인 없이 `json.pois ?? []`만 세팅하던
  버그를 함께 고쳤다 — 서버 오류(세션 만료 등)가 "주변에 지점 없음"으로 조용히 위장되고
  있었다(아래 alerts 참고).
- `drops/[dropId]/route.ts`(GET 단건 조회)의 하드코딩 한글('인증 필요'·'드랍 없음'·'익명')을
  `d.drops.*`로 교체. 조사 결과 이 라우트를 호출하는 클라이언트 코드가 없다(`api/drops/poi/[poiId]`가
  대체) — 재사용 시를 대비해 정비만 하고 삭제하지 않았다.
- `drops/debug/route.ts`: 어드민 전용 진단 엔드포인트(`requireAdmin()`)로 확인돼 범위에서 제외.
- `cron/ambient-drop/route.ts`: Vercel Cron 전용(Bearer 시크릿 인증), 사람이 보는 화면이 아니라
  UX 가이드 적용 대상이 아님 — 변경 없음.

### 주요 의사결정 / 핵심 메모
- 티켓의 대상 화면 목록(`DropsClient.tsx`·`BadgeDetailSheet.tsx`·`drops/page.tsx`)에는
  하드코딩 한글 리터럴이 없었다 — 세 파일 모두 이미 딕셔너리 키만 참조한다. 실제
  "서버 메시지 무시, 클라이언트 자체 문구" 패턴은 이 세 파일이 아니라 `PoiCarouselModal.tsx`
  (드랍/픽업 실행, POI별 드랍 목록 조회를 실제로 수행하는 컴포넌트)에 있었다. 티켓이 요구한
  ADR 0001 적용을 완결하려면 API 응답 계약을 바꾸는 이 작업의 유일한 소비자인
  `PoiCarouselModal.tsx`를 함께 고치지 않으면 클라이언트가 여전히 서버의 완성 문구를 무시하고
  자체 코드 매핑을 쓰게 되므로, 범위를 이 파일까지 넓혔다.
- 서버가 반환하는 문구 값은 전부 **기존에 이미 `ko.ts`에 있던 `d.drops.*` 상수를 그대로 재사용**했다
  — 새 문구를 짓지 않고, "코드→문구 매핑 위치"만 클라이언트에서 서버로 옮겼다. 화면에 보이는
  최종 텍스트는 변경 전과 동일하다.
- `unauthorized`(401) 응답은 도메인 전체에서 `d.drops.sessionExpired`(로그인이 풀렸어요 —
  다시 로그인하고 시도해 주세요)로 통일했다. `d.common.authRequired`(다른 도메인이 먼저
  참조한 범용 "인증이 필요해요")도 검토했으나, drops 화면은 페이지 진입 시 이미
  로그인을 강제하므로(`drops/page.tsx`가 미로그인 시 `/login`으로 리다이렉트) 진행 중 401은
  "애초에 로그인 안 함"이 아니라 "세션이 끊김"이 맞는 해석이라 기존에 이미 쓰이던
  `sessionExpired`를 그대로 확장했다(20260826_002 이후 관례).

### 잔여 이슈
- `api/drops/[dropId]/route.ts`(GET 단건 조회)는 실제 호출하는 클라이언트 코드가 없는
  것으로 확인됐다(조사: `rg "api/drops/\\$\\{"` 전체 검색). 죽은 코드일 가능성이 있으나 이번
  티켓 범위(텍스트 정비)를 벗어나 삭제 여부는 판단하지 않았다.
