## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- **ADR 0001 위반 수정**: `api/missions/[id]/join`, `api/missions/[id]/status` 두 라우트의
  하드코딩 에러 문구('인증이 필요합니다.', '미션을 찾을 수 없어요.', '이미 종료된 미션이에요.',
  '이미 참가 중인 미션이에요.', '참가 처리 중 오류가 발생했어요.', '참가한 유저만 미션 상황을
  볼 수 있어요.', 랭킹 표시 이름 폴백 '익명')를 `d.common.authRequired`(재사용) +
  `d.profile.anonymous`(재사용) + 신설 `d.missions.missionNotFound/alreadyEndedError/
  alreadyJoinedError/joinProcessError/statusForbidden`로 교체.
  `MissionDetailClient.tsx`는 `data.error ?? d.missions.joinError`로 이미 서버 문구를
  올바르게 신뢰하고 있었다 — 문제는 서버가 반환하던 원문 자체가 가이드를 거치지 않은
  하드코딩이었다는 점이었으므로, 클라이언트 로직은 그대로 두고 서버 쪽만 고쳤다(ADR 0001
  본문의 "MissionDetailClient.tsx 사례"가 가리키는 지점).
- **화면 감사 결과 추가로 발견된 하드코딩 텍스트**를 `d.missions` 네임스페이스로 편입:
  - `MissionDetailClient.tsx`: 이미지 자리표시 문구("이미지 영역"→`imagePlaceholder`),
    썸네일 alt("{title} 썸네일"→`thumbnailAlt`), 활동 종류 라인("활동 종류: …"→
    `conditionActivityType`), 자동완료 안내("미션 참가 후 언제든지 조건을 충족하면 자동
    완료"→ §1.3 "충족" 금지어를 피해 `conditionAutoCompleteHint`="미션 참가 후 조건을
    채우면 자동으로 완료돼요"로 재작성), 보상 배지 캡션("미션 완료 시 획득"→
    `rewardBadgeCaption`), 보상 포인트 캡션("미션 완료 즉시 지급"→ §1.3 "지급"은 어드민
    전용 용어라 유저 화면 금지이므로 `rewardPointsCaption`="미션 완료 즉시 받아요"로 교체),
    완료 CTA("종료"→`ctaEnded`), 참가 CTA("참가하기"→`joinButton`).
  - `MissionsListClient.tsx`: 보상 배지 표기(`${info.name} 배지`→`rewardBadgeName` 템플릿).
  - `MissionStatusClient.tsx`: 감사 결과 이미 딕셔너리 완전 편입 확인, 코드 변경 없음.
- **lib 감사**: `src/lib/ranking/format.ts`는 `t(template, vars)` 딕셔너리 체계 대상이 아닌
  숫자·단위 포맷터(예: "12.3km", "128명")로, 배지 조건 레지스트리(`conditionRegistry.ts`)와
  동일한 관례를 따르고 있어 하드코딩 조각으로 볼 근거가 없었다 — 코드 변경 없음.
- 시간 표기("N일 N시간 남음")·달성 조건 불릿의 "달성"/"일 중" 등 단위 접미사는 앱 전역에서
  이미 통용되는 house pattern(다른 도메인 감사에서도 손대지 않은 범위)이라 이번 티켓
  스코프에서 제외했다 — 필요하면 전역 단위 표기 정비로 별도 티켓화.

### 주요 의사결정 / 핵심 메모
- 서버 에러 문구의 3단계([현상→원인→해결책]) 구조·번역투·정형구 등 깊은 톤 재작성은
  이 티켓 스코프에 넣지 않았다 — 선행 사례(티켓 20260915_2241 드롭 도메인)가 구조 이관은
  그대로 병합하고, 한국어 리뷰(`/im-not-ai`)에서 나온 세부 문구 교정은 후속 티켓으로 분리한
  선례를 따랐다. 이번 티켓도 게이트 리뷰에서 유사한 지적이 나오면 같은 방식으로 후속
  티켓으로 분리할 것을 제안한다.
- `d.profile.anonymous`를 재사용해 `d.missions` 안에 별도 익명 키를 새로 만들지 않았다 —
  이미 `d.drops.anonymous`도 같은 값으로 존재해 두 번째 중복 키를 늘리지 않기 위함.
