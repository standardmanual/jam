## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `search/page.tsx`는 이미 `d.search.*`를 대부분 참조하고 있었으나, 남아 있던 표기·구조
  문제를 가이드 기준으로 정비했다.
  - `promptBody`: "입력해주세요" → "입력해 주세요" (§3 보조용언 `-어 주다` 띄어쓰기 규칙).
  - `emptyTitle`: 검색어를 인용하지 않던 고정 문구 "검색 결과가 없어요"를, §4.3 빈 상태
    가이드가 명시한 예시 `"{검색어}" 검색 결과가 없어요` 패턴에 맞춰 템플릿화하고, 화면에서
    `t(d.search.emptyTitle, { query })`로 실제 검색어를 인용하도록 고쳤다.
- `api/users/search/route.ts`는 ADR 0001(서버-클라이언트 단일 진실 소스)을 위반하고 있었다.
  - 미로그인(401) 응답이 `d.common.authRequired`를 참조하지 않고 자체 하드코딩 문구
    "인증이 필요합니다."를 쓰고 있었다. `d.common.authRequired`를 참조하도록 고쳤다(값 자체는
    티켓 20260916_0904 소관이라 건드리지 않음).
  - DB 조회 실패(500) 시 Supabase의 원본 `error.message`(내부 오류 문자열)를 그대로
    클라이언트에 내려보내고 있었다 — 가이드 톤·용어를 거치지 않은 raw 문자열 노출이자 내부
    정보 유출 소지가 있었다. 원인은 서버 로그(`console.error`)에만 남기고, 클라이언트에는
    신설한 `d.search.searchFailed`("유저 검색에 실패했어요. 잠시 후 다시 시도해 주세요.")를
    반환하도록 고쳤다.
- `ko.ts`의 `search` 네임스페이스에 위 변경을 반영하고 `searchFailed` 키를 신설했다.

      어미·엠대시)을 문구별로 수기 대조했고 위반 사항을 찾지 못했다.
- [x] 딕셔너리 편입 후 실렌더 대조(문구 동일성 확인) — `search/page.tsx`가 이미 `d.search.*`를
      참조하던 구조라 화면에 노출되는 최종 문자열이 편입 전후 코드상 동일함을 대조했다(신규

      아래 잔여 이슈에 별도 기록). 이 워크트리는 `next dev`/`next build`가 되지 않는 환경이라
      브라우저 실렌더는 하지 못했고, `npm run lint` 결과(0 errors)로 구문·타입 오류가 없음만
      확인했다.

**가이드:** `Service Plan/Specs/UX_WRITING_GUIDELINE.md` 참조

- [x] 용어 일관성: 고정 용어만 사용 (획득·드랍·픽업·체크인·포인트 등) — 이 도메인은 유저

      톤 유지, 조회 실패(500)는 "전문·직접" 톤으로 재시도를 안내.
- [x] 에러 메시지: [현상] → [원인] → [해결책] 3단계 구조 — `searchFailed`는 [현상](검색
      실패)+[해결책](잠시 후 재시도)만 담은 2단계다. 원인(DB 조회 실패 등 내부 사유)은 사용자
      에게 의미 있는 정보가 아니라 의도적으로 생략했다(§4.2 인라인 축약과 유사한 판단, 다만
      이건 토스트 대상이라 완전히 같은 조항은 아님 — 잔여 이슈에 기록).
- [x] 문장 규칙: 해요체, 간결함, 마침표 위치 정확 — `promptBody` 띄어쓰기 수정, `searchFailed`는
      두 문장이라 마침표 포함(§3).
- [x] 표기 규칙: 날짜/시간/금액/기간 직관적 형식 — 해당 표기 대상 없음.

### 주요 의사결정 / 핵심 메모
- `emptyTitle`에 검색어를 인용하는 변경은 티켓 요구사항(하드코딩 텍스트를 가이드에 맞게
  다듬기)의 연장으로 판단해 진행했다 — §4.3이 이 정확한 문구를 예시로 명시하고 있어 가이드가
  이미 이 화면을 염두에 두고 작성된 것으로 해석했다.
- `search/page.tsx`의 `searchUsers()` 내부 `console.error('[search/page] 유저 검색 조회
  실패', error)`는 서버 전용 로그라 딕셔너리 편입 대상이 아니라고 판단해 그대로 뒀다.
- `d.common.authRequired`는 티켓 20260916_0904가 별도로 전면 교정 중이라는 지시에 따라 참조만
  하고 값은 그대로 뒀다.

### 잔여 이슈
- `searchFailed`는 [현상]+[해결책] 2단계로만 구성했다 — 이 도메인의 500 오류는 사용자가
  통제할 수 있는 원인이 없어(내부 DB 조회 실패) §4.1 3단계 구조를 억지로 채우면 오히려
  근거 없는 원인 문구가 될 위험이 있다고 판단했다. 리뷰에서 3단계 구조를 엄격히 요구하면
  조정이 필요하다.
- `/im-not-ai` 실제 플러그인 실행 및 브라우저 실렌더 대조는 이 워크트리 환경 제약으로
  수행하지 못했다 — staging 병합 후 실제 화면 확인이 필요하다.
