# [Content] 컬렉션/아이템북 에러 문구 톤 및 용어 정비

> 상위 스펙: [`20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md`](../P1-중요/20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md)
> 출처: 티켓 20260915_2239(컬렉션/아이템북 도메인 텍스트 정비) 한국어 리뷰에서 나온 제안 — 게이트는 PASS했으나 병합 전 반영하지 않고 이 후속 티켓으로 분리하기로 사용자가 결정함(2026-09-16)

## 배경 / 문제 정의

티켓 20260915_2239에서 `src/app/api/itembooks/[id]/slot/route.ts`의 하드코딩 에러 메시지를
`d.itembooks.*` 딕셔너리로 이관하는 작업(구조) 자체는 게이트 PASS했지만, 한국어 리뷰가
이관된 문구 표현·가이드 준수 여부에서 다수 문제를 지적했다 — "not found" 직역 반복,
내부어("개체"·"정보") 노출, 에러 3단계 구조 미충족, 서로 다른 에러가 같은 문구로 뭉개짐 등.

## 상세 요구사항 — `jam-web/src/lib/i18n/ko.ts`의 `d.itembooks`/`d.common` 값만 수정

### (a) "찾을 수 없어요" 직역 반복 4종 — 원인별로 구체화
- `inventory_not_found` → "인벤토리를 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요"
- `item_not_found` → "인벤토리에 없는 아이템이에요. 목록을 새로고침해 주세요"
- `badge_not_found` → "배지 정보를 불러오지 못했어요. 잠시 뒤 다시 시도해 주세요"
- `slot_not_found`(해제 대상) → "이미 해제된 자리예요. 컬렉션을 새로고침해 주세요"

### (b) 내부어 노출 — §1.3 위반
- "개체"는 §1.3에 없는 내부어다(§1.3은 개체 구분을 **일련번호**로 부르기로 이미 정함).
  `same_item`("이미 장착된 개체예요") → "이미 이 자리에 장착한 아이템이에요. 다른
  일련번호를 골라 주세요"
- "장착 정보"/"아이템 정보"도 시스템 관점의 "정보" 객체를 노출한다. 파라미터 누락 3종을
  아래 (c)로 통합하면서 함께 해소

### (c) 파라미터 누락 3종 — 원인 없이 "다시 시도해 주세요"만 반복, 서버 내부 분기 노출
현재 `slotMissingInventoryItemId`/`unslotMissingSlotId`/`swapMissingParams`가 재시도해도
결과가 같은 400 오류에 "다시 시도해 주세요"를 걸고 있다. 하나로 통합:
→ "요청이 제대로 전달되지 않았어요. 화면을 새로고침한 뒤 다시 골라 주세요"

### (d) 의미가 뭉개진 에러 쌍 — `already_slotted` vs `same_item`
"다른 자리에 이미 장착"과 "바로 이 자리에 이미 장착"이 똑같이 "이미 장착된 아이템/개체예요"로
나와 사용자가 구분 못 한다.
- `already_slotted` → "이미 다른 자리에 장착한 아이템이에요. 그 자리를 해제한 뒤 다시
  장착해 주세요"
- `same_item` → (b) 참고

### (e) 그 외
- `not_owner`("본인이 보유한 아이템만") → "내 아이템만 장착할 수 있어요" (§1.2 사용자 시점,
  '본인'·'보유' 한자어 제거)
- `wrong_item_book`("이 배지는 해당 컬렉션에 속하지 않아요") → "이 컬렉션에 들어가는 배지가
  아니에요" ('해당' 공문서투 제거)
- `already_dropped`(피동+역순) → "장착할 수 없어요. 지점에 드랍해 둔 아이템이라, 픽업한
  뒤에 장착할 수 있어요"
- `wrong_badge` → "같은 배지끼리만 교체할 수 있어요. 일련번호가 다른 같은 배지를 골라 주세요"
- `inventory_full`(unslot 실패) → "인벤토리가 꽉 차서 해제할 수 없어요. 50개까지만 보관할
  수 있어요" + [정리하러 가기] CTA (§4.1 3단계 구조 적용, 티켓 20260915_2239에서 이미
  "정리하고 다시 시도"로 1차 교정한 것을 3단계로 보완)
- `d.common.authRequired`("인증이 필요해요") → 티켓 20260916_0734(배지 도메인 후속)에서도
  동일 지적이 나왔다 — 두 티켓이 같은 키를 공유하므로 **한쪽에서만 수정**한다. 먼저 처리되는
  티켓에서 "로그인해야 볼 수 있어요"(또는 확정된 대안)로 바꾸고, 이 티켓에서는 중복 수정하지
  않는다.

### (f) 마침표 규칙(§3)
단문(현상만 있는 문구)은 마침표 없음, 두 문장 이상은 마침표 사용 — 위 (a)~(e) 교정 문구
작성 시 이 규칙을 함께 지킨다.

## 구현 계획
- `ko.ts`의 해당 키 값만 수정한다(구조 변경 없음, 순수 문구 교체).
- `authRequired` 중복 수정을 피하기 위해 티켓 20260916_0734와 작업 순서를 조율한다.
- 완료 후 `/im-not-ai`로 교체된 문구를 재검사한다.
