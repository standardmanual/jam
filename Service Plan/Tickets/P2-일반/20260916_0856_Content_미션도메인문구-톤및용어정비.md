## 배경 / 문제 정의

티켓 20260915_2244의 딕셔너리 이관·ADR 0001 적용 구조는 게이트 PASS했지만, 한국어 리뷰가
신규 문구의 표현·가이드 준수 여부에서 다수 문제를 지적했다 — 에러 4종 모두 3단계 구조
미충족, 미등록 용어("미션 상황"), 호칭 문제("유저"), CTA 규칙 위반 등.

## 상세 요구사항 — `jam-web/src/lib/i18n/ko.ts`의 `d.missions` 값 수정

### (a) 에러 3단계 구조(§4.1) 미충족 — 4건 전부
- `missionNotFound` → "이 미션은 사라졌어요. 삭제됐거나 링크가 잘못됐을 수 있어요."
  + CTA `[미션 목록 보기]`
- `alreadyEndedError` → "이미 끝난 미션이에요. 지금 참가할 수 있는 미션을 볼까요?"
  + CTA `[미션 목록 보기]`
- `joinProcessError` → "미션에 참가하지 못했어요. 잠시 뒤 다시 참가해 주세요." (§1.1 공급자
  언어 "처리" 제거)
- `statusForbidden` → "미션에 참가하면 상황을 볼 수 있어요." + CTA `[참가하기]` (§1.2 위반인
  "유저" 삭제, 1인칭 시점으로 재작성)

### (b) 미등록 용어 — §1.3 표 갱신 선행
- **미션 상태명**: `alreadyEndedError`("종료된")와 `ctaEnded`("종료")가 같은 상태를 다르게
  부른다. §1.3에 미션 상태(모집/진행 중/종료) 행이 없으니 먼저 고정 표현을 정하고 두 문구를
  맞춘다.
- **"미션 상황"**: §1.3에 없는 신규 표현. §1.3의 "랭킹(RANKING)" 정의("미션 상세 순위
  리스트")와 겹칠 여지가 있어 어느 개념인지 확정한 뒤 표에 등재한다.

### (c) CTA 규칙(§5.1/§5.3)
- `ctaEnded: "종료"`는 §5.1이 Bad로 지목한 단독 명사(확인/완료류)와 같은 문제 → "끝난 미션"
  또는 "참가 마감"
- `joinButton`("참가하기")에 대응하는 처리 중 라벨이 없다 → §5.3 기본형에 따라
  `joinButtonPending: "참가하는 중"` 신설

### (d) 용어 일관성(§1.3) — 같은 화면에서 형태가 갈림
`rewardBadgeCaption`("완료 시 획득")과 `rewardPointsCaption`("완료 즉시 받아요")이 문형이
다르다 → 형태를 맞춘다: "완료하면 획득해요" / "완료하면 바로 받아요"

### (e) 그 외 어색한 표현
- `conditionAutoCompleteHint`("참가 후 조건을 채우면 자동으로 완료돼요"): 수동태·문어체
  → "참가한 뒤 조건을 다 채우면 미션이 자동으로 끝나요"
- `conditionActivityType`("활동 종류: {type}"): 라벨-값 콜론 표기가 개발 문자열 관습 →
  "{type} 활동" 또는 라벨/값 시각적 분리로 UI 검토
- `thumbnailAlt`/`imagePlaceholder`("썸네일"/"이미지 영역"): 개발 용어 노출 →
  "{title} 대표 이미지" / "이미지 준비 중"(장식용이면 텍스트 대신 `aria-hidden` 검토)

### 주요 의사결정 / 핵심 메모
- **CTA 라벨 미부착 3건** — `missionNotFound`·`alreadyEndedError`("미션 목록 보기"),
  `statusForbidden`("참가하기"): 코드 확인 결과 앞의 두 개는 `useToast`(액션 버튼 미지원
  토스트), 뒤의 하나는 `/missions/[id]/status` 페이지의 평범한 텍스트 문단으로 렌더되며 둘 다
  버튼을 붙일 자리가 없다. 티켓 지시대로 문구만 완성하고 CTA는 붙이지 않았다 — 아래 잔여
  이슈에 기록.
- **"미션 상태명" 등재 범위** — 티켓이 예시로 든 "모집/진행 중/종료"를 그대로 §1.3 상태명
  행에 등재했다. 다만 코드의 실제 라벨(`tagUpcoming: '시작전'`)은 "모집"이 아니라 "시작전"을
  쓰고 있어 즉시 어긋난다. 이번 티켓 범위는 alreadyEndedError/ctaEnded 두 문구의 "종료" 계열
  표현 통일이므로 `tagUpcoming` 값 자체는 건드리지 않았다 — §1.3 상태명 표와 `tagUpcoming`
  실제 값의 불일치는 별도 확인이 필요해 잔여 이슈로 남긴다.
- **joinButtonPending 연결 지점** — 티켓 문구상 "joinButton에 대응하는 처리 중 라벨"이지만
  `joinButton`(초기 "참가하기") 클릭은 동기적으로 확인 패널만 열 뿐 비동기 요청이 없다. 실제
  비동기 요청(`handleJoin`)은 확인 패널의 `joinConfirmButton`("참가 확정") 클릭에서
  발생하므로, 신규 라벨은 그 버튼의 `loading` 상태에 연결했다.

### 잔여 이슈
- `/im-not-ai` 전수검사는 오케스트레이터/리뷰어가 별도 수행 필요(이 티켓의 정책상 1회
  리뷰만 반영하고 마무리하되, 검사 자체는 아직 실행되지 않았다).
- `missionNotFound`·`alreadyEndedError`·`statusForbidden`의 CTA(`[미션 목록 보기]`/
  `[참가하기]`)는 현재 렌더 경로(액션 버튼 미지원 토스트, 버튼 없는 텍스트 문단)에 붙일 자리가
  없어 문구만 완성했다. CTA를 실제로 넣으려면 토스트에 액션 버튼 지원을 추가하거나
  `statusForbidden` 노출부에 버튼을 추가하는 별도 UI 작업이 필요하다.
- §1.3 "모집/진행 중/종료" 상태명과 `d.missions.tagUpcoming`("시작전")의 실제 표기가 어긋난다
  — 이번 범위(종료 상태 표현 통일) 밖이라 손대지 않았다.
