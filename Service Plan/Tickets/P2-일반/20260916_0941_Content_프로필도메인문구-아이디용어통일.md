# [Content] 프로필 도메인 문구 톤 정비 및 "아이디" 용어 통일

> 상위 스펙: [`20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md`](../P1-중요/20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md)
> 출처: 티켓 20260915_2248(프로필 도메인 텍스트 정비) 한국어 리뷰에서 나온 제안 — 게이트는 PASS했으나 병합 전 반영하지 않고 이 후속 티켓으로 분리(사용자 결정, 2026-09-16)

## 배경 / 문제 정의

티켓 20260915_2248의 딕셔너리 이관·ADR 0001 적용 구조는 게이트 PASS했지만, 한국어 리뷰가
**"아이디"라는 개념이 §1.3 용어표에 아예 등재돼 있지 않아, 코드 안에서 "ID"·"아이디"·
"닉네임"·"유저명" 4가지로 갈라져 있다는 구조적 결함**을 발견했다. 이번 티켓의 문구 개선은
용어표 등재가 선행돼야 의미가 있다.

## 상세 요구사항

### (A) `UX_WRITING_GUIDELINE.md` §1.3 용어표 신설 — 선행 작업
"유저를 가리키는 고유 식별자"를 **"아이디(ID)"**로 고정 등재한다.
(X: ID, 닉네임, 유저명, 사용자명, 계정명 — 단, 이미 §4.2 Good 예시와
`jam-web/src/app/(main)/privacy/page.tsx`(142·170·428행)가 "닉네임"을 쓰고 있으므로, 이
문서 예시와 코드도 함께 "아이디"로 맞춰야 한다 — 그러지 않으면 등재 자체가 새로운 불일치를
만든다.)

### (B) `jam-web/src/lib/i18n/ko.ts` 값 수정 (A 확정 후 진행)
- `onboarding.usernamePlaceholder`("ID를 입력해 주세요") → 지시문 대신 예시값(`jam_runner`)으로
  전환 — `profileEdit.usernameLabel`("아이디")과 `errorEmpty`("아이디를 입력해 주세요")가
  이미 같은 말을 하고 있어 placeholder의 지시문은 중복
- `onboarding.errorTooLong`("30자 이하로 입력해 주세요") → 주어 없음, §3 물결표 규칙 미적용
  → "아이디는 2~30자까지 쓸 수 있어요"
- `onboarding.errorFormat`("영문, 숫자, ., _ 만 사용할 수 있어요") → 쉼표·마침표 나열로
  가독성 저하, 조사 붙여쓰기 오류 → "영문·숫자와 점(.), 밑줄(_)만 쓸 수 있어요"
- `onboarding.errorDot`류 → 금지형을 긍정형으로 전환: "점(.)은 아이디 가운데에만 쓸 수
  있어요" / "점(.)은 연달아 쓸 수 없어요"
- `onboarding.available`("사용 가능한 아이디예요") → "쓸 수 있는 아이디예요"
- `onboarding.taken`("이미 사용 중인 아이디예요") → §4.2 이미 벌어진 충돌 유형, [현상+해결책]
  → "이미 다른 사람이 쓰고 있어요. 다른 아이디를 지어볼까요?"
- `profileEdit.fileTypeError`/`fileSizeError` → "JPEG·PNG·WebP 사진만 올릴 수 있어요" /
  "5MB 이하 사진만 올릴 수 있어요"
- `profileEdit.uploadError`/`saveError` → §4.1 3단계 중 원인이 빠짐 →
  "사진을 올리지 못했어요. 연결이 불안정했을 수 있어요." (+ CTA `[다시 시도]`) /
  "프로필을 저장하지 못했어요. 연결이 불안정했을 수 있어요." (+ CTA `[다시 시도]`)
- `d.common.authRequired`("인증이 필요해요")는 **티켓 20260916_0904로 이미 통합됨** — 이
  티켓에서는 중복 수정하지 않는다.

## 구현 계획
1. (A) 용어표 등재 + §4.2 예시·`privacy/page.tsx` 정합화를 먼저 처리한다.
2. (B) `ko.ts` 값을 확정된 용어에 맞춰 교정한다.
3. 완료 후 `/im-not-ai`로 재검사한다.
