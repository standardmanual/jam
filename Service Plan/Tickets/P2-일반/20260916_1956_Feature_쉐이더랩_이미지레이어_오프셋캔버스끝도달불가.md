# [Feature] 쉐이더 랩 이미지 레이어 위치 오프셋이 캔버스 끝까지 도달하지 못하는 문제 수정

## 배경 / 문제 정의
쉐이더 랩(어드민 배경 제너레이터)에서 이미지 레이어를 불러온 뒤 위치 오프셋(X/Y) 슬라이더를
최대·최소로 조절해도 이미지가 캔버스 양 끝까지 이동하지 못한다. (사용자 실사용 피드백)

**원인 (조사 완료)**: 오프셋 슬라이더 범위가 `effectRegistry.ts`에 정적 상수
`min: -1, max: 1`로 고정되어 있다(이미지 레이어: L149, 텍스트 레이어: L506 — 텍스트는
이번 범위 밖). 실제 렌더링 좌표 변환(`node_modules/@basementstudio/shader-lab/dist/src/
renderer/media-pass.js`의 `buildEffectNode`/`updateParams`)은 다음 식을 쓴다:

```
scaleUniform = 1 / max(scale, 0.01)
centeredUv = (uv - 0.5) * scaleUniform
scaleX = clamp(aspectRatio, 0, 1)   // aspectRatio = 이미지/캔버스 종횡비
sampledUv.x = centeredUv.x / scaleX - offsetXUniform + 0.5
```

캔버스 우측 끝(`uv.x=1`)에서 텍스처 우측 끝(`sampledUv.x=1`)까지 이동하는 데 필요한
오프셋은 `0.5 / (scale × scaleX) − 0.5`다. `scale=1`이고 종횡비가 캔버스와 정확히
일치(`scaleX=1`)할 때만 필요 오프셋이 정확히 `±1`이 되어 슬라이더 끝과 맞아떨어진다.
이미지를 축소(`scale<1`, 최소 0.25까지 허용)하거나 종횡비가 달라 레터박스가 생기면
(`scaleX<1`) 필요 오프셋이 1을 초과해버려 슬라이더 범위(-1~1)로는 절대 캔버스 끝에
닿지 못한다. Y축도 대칭 구조라 동일한 문제가 있을 것으로 추정된다(구현 시 확인 필요).

## 상세 요구사항

### 서비스/코드베이스 관점
- 이미지 레이어의 위치 오프셋(X, Y)을 슬라이더 끝(현재 -1~1)까지 조절하면, 현재 `scale`과
  이미지/캔버스 종횡비가 무엇이든 **항상** 이미지 가장자리가 캔버스 가장자리에 닿아야 한다
  ("상대값 매칭" — 사용자 요청)
- 즉 UI 슬라이더의 절대 범위(-1~1)는 그대로 두되, 그 값이 실제 이동 거리로 변환될 때
  현재 `scale`·종횡비에 따라 동적으로 스케일링되어야 한다
- X, Y 양쪽 모두 대상

## 구현 계획
- `media-pass.js`(패치 파일 `patches/@basementstudio+shader-lab+3.0.2.patch`)의 오프셋
  적용 로직에서, 사용자 입력 오프셋(-1~1)에 동적 계수(`maxOffset = 0.5/(scale×scaleX) − 0.5`,
  Y축은 대응 `scaleY` 사용)를 곱해 실제 uv 이동량으로 변환
- **patch-package 재생성 절차 준수**: `node_modules/@basementstudio/shader-lab`을 직접
  수정한 뒤 `npx patch-package @basementstudio/shader-lab`으로 패치 파일을 재생성해
  같은 커밋에 포함할 것. Vercel 빌드캐시 충돌(과거 티켓 20260913_2207)은 `installCommand`
  방식으로 이미 근본 해결되어 있으니 재발 우려는 낮으나, 패치 재생성 자체는 반드시 수행
- `effectRegistry.ts`의 min/max(-1~1)는 변경하지 않는다 — UI 슬라이더 단순성 유지,
  변환식만 수정
- 텍스트 레이어(`effectRegistry.ts:506`)의 동일 패턴은 이번 티켓 범위 밖(발견되면 별도 티켓)

### UI 재사용 판정
해당 없음 — 기존 쉐이더 랩 렌더링 로직 수정, 신규 UI 없음.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`media-pass.js`의 `buildEffectNode()`에서 `sampledUv` 계산 직전에 동적 계수
`maxOffsetX = 0.5 × scaleUniform / scaleX − 0.5`(Y축은 `scaleY` 사용)를 도입하고,
사용자 입력 오프셋(-1~1)에 이 계수를 곱한 `effectiveOffsetX/Y`를 실제 uv 이동에
사용하도록 변경했다. `scaleUniform`(= `1/scale`)과 `scaleX/scaleY`(contain 모드
레터박스 비율)는 이미 셰이더 그래프의 TSL 노드이므로, 계수 계산도 JS 스칼라가 아니라
같은 그래프 안에서 노드 연산으로 처리해 매 프레임 실제 scale·종횡비 값을 반영한다.
수치 시뮬레이션(scale 0.5~4, aspect 일치/불일치 조합)으로 offset=+1일 때 항상
`sampledUv=1`(우측/하단 끝), offset=-1일 때 항상 `sampledUv=0`(좌측/상단 끝)에
정확히 도달함을 확인했다. `effectRegistry.ts`의 슬라이더 범위(-1~1)는 그대로 뒀다.

      - `scale=2`(줌인, 게이트 리뷰가 다루지 않은 추가 케이스 — X축이 `scale=1`일 때 이미

        텍스처 중앙 50%가 캔버스 전체를 채우고(빨강/파랑 경계가 캔버스 정중앙에 위치),

        오른쪽 끝에 정확히 닿고, offset=−1에서는 대칭적으로 왼쪽 절반(빨강)과 왼쪽 끝
        테두리가 닿음을 확인 — 부호 반전이나 투명 영역 노출(오버슈트) 없음.
      - **게이트 리뷰가 보고한 회귀("scale=0.5에서 X 오프셋이 전혀 반응하지 않음")는
        이번 재현 시도에서 재현되지 않았다.** 코드(`buildEffectNode`)와 커밋된 패치
        파일은 정확히 일치함을 `npx patch-package` 재생성 후 `diff`로 재확인했다
        (바이트 단위 동일). 게이트 리뷰 당시 관찰은 재시작 전 dev 서버·빌드 캐시가 패치
