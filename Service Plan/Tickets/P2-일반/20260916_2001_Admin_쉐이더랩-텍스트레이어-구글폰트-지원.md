# [Admin] 쉐이더 랩 텍스트 레이어에 구글 폰트 검색·자유 선택 지원

## 배경 / 문제 정의
쉐이더 랩(`/admin/shader-lab`)의 텍스트 레이어는 현재 Pretendard Variable 단일 폰트만
지원한다(`jam-web/src/lib/admin/shaderLab/textFontOptions.ts`). 사용자가 텍스트 레이어에서
**구글 폰트 전체를 검색해 자유롭게 선택**할 수 있도록 기능을 확장해달라고 요청했다.

(1차 조사에서 미사용 슬롯 하나에 Noto Sans KR 1종을 고정으로 얹는 좁은 범위로 구현을
시도했으나, 사용자가 "구글 폰트 전체 검색·자유 선택"을 원한다고 확인해 범위를 이 문서로
재정의한다. 좁은 범위 구현은 로컬에서 되돌렸고 커밋되지 않았다.)

`@basementstudio/shader-lab` 패키지의 텍스트 렌더링 패스는 임의의 `font-family` 문자열을
받지 않고, 패키지 내부에 고정된 슬롯 이름(`sans`/`mono`/`bsmnt-grotesque`/`caniche`/
`blob`/`bunker`/`carpenter`/`curia`/`ffflauta`/`numero`/`xer0`/`trovador`/`b-mecha`/
`impact`/`display-serif`) 중 하나여야만 실제로 폰트가 반영된다. 그중 `cssVariable`이
지정된 슬롯만 `getComputedStyle(document.documentElement)`로 CSS 커스텀 프로퍼티 값을
읽어 실제 웹폰트를 적용한다 — 즉 **슬롯의 CSS 변수를 런타임에 원하는 폰트로 덮어쓰면
렌더링 자체는 임의 웹폰트를 받아들인다는 사실을 1차 조사에서 실측 확인**했다
(`jam-web/src/lib/admin/shaderLab/layout.tsx`의 정적 오버라이드 방식으로 Noto Sans KR
로드·렌더링까지 성공).

제약:
- 연속 굵기(range)를 지원하는 슬롯은 `sans`(`--geist-sans`)·`mono`(`--geist-mono`)·
  `bsmnt-grotesque`(`--bsmnt-grotesque`) 3개뿐이며, 이미 ASCII 레이어(고딕/고정폭)와
  기존 텍스트 레이어(Pretendard)가 점유하고 있다.
- 나머지 미사용 슬롯(`caniche`/`blob`/`bunker`/`carpenter`/`curia`/`ffflauta`/`numero`/
  `xer0`/`trovador`/`b-mecha`/`impact`, 총 11개)은 고정 굵기 1개만 지원한다.
- 슬롯 하나 = 한 시점에 CSS 변수 하나 = 폰트 하나이므로, **한 컴포지션 안에서 동시에
  서로 다른 구글 폰트를 쓸 수 있는 한도는 미사용 슬롯 개수(11개)로 제한**된다.
- 구글 폰트 전체(수천 종) 카탈로그 자체를 검색할 수 있게 하려면, `layout.tsx`처럼 라우트
  진입 시 정적으로 한 번 덮어쓰는 방식이 아니라, **레이어별로 사용자가 고른 폰트를 런타임에
  동적으로 미사용 슬롯 하나에 주입**하는 방식으로 바꿔야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 구글 폰트 검색 UI를 텍스트 레이어 속성 패널의 "폰트" 필드에 추가한다(자동완성/드롭다운
  검색, 구글 폰트 API 또는 정적 폰트 목록 데이터 활용).
- 사용자가 폰트를 선택하면:
  1. 해당 폰트의 구글 폰트 CSS(`fonts.googleapis.com/css2?family=...`)를 동적으로
     `<link>` 삽입하거나 `document.fonts`로 로드한다.
  2. 미사용 슬롯 11개 중 이 레이어(또는 이 폰트)에 배정된 슬롯 하나를 찾아, 그 슬롯의
     `cssVariable` 값을 선택한 폰트 이름으로 런타임에 덮어쓴다(`document.documentElement
     .style.setProperty`).
  3. 레이어의 `fontFamily` 파라미터 값을 그 슬롯 식별자로 설정한다.
- **슬롯 배정 로직**: 한 컴포지션에서 서로 다른 폰트를 쓰는 텍스트 레이어가 11개를
  초과하면 어떻게 할지 결정한다(예: 초과 시 안내 메시지 + 기존 슬롯 재사용 유도, 또는
  폰트별 슬롯 캐싱·재사용). 같은 폰트를 여러 레이어가 쓸 때는 슬롯을 공유해야 한다.
- **굵기 처리**: 모든 미사용 슬롯이 고정 굵기 1개뿐이므로, 구글 폰트를 로드할 때 어떤
  굵기(400/700 등)로 고정할지 정책을 정한다. 사용자가 굵기까지 고를 수 있게 하려면 폰트
  하나당 슬롯을 굵기별로 나눠 써야 해서 동시 사용 가능 폰트 수가 더 줄어드는 트레이드오프가
  있다 — 1차로는 고정 굵기 1개(예: 400 또는 700) 단일 지원으로 시작하는 방안을 검토한다.
- 기존 Pretendard Variable 옵션(`bsmnt-grotesque` 슬롯)은 그대로 유지하고 회귀시키지 않는다.
- 구글 폰트 CSS 로드는 `/admin/shader-lab` 라우트 한정으로 유지하고, 전역 타이포그래피에
  영향을 주지 않는다.
- 폰트 검색 데이터 소스(구글 폰트 API 키 필요 여부, 또는 정적 폰트 목록 번들)를 조사하고
  택한다 — API 키가 필요하면 별도 환경변수·비용 검토가 필요할 수 있다.

### UI/UX 관점 (해당 시)
- 폰트 검색 필드는 기존 속성 패널의 다른 드롭다운(예: 블렌드 모드)과 시각적으로 일관돼야
  한다.
- 슬롯 초과·동일 폰트 재사용 등 예외 상황을 사용자에게 명확히 안내한다(에러 메시지
  [현상]→[원인]→[해결책] 3단계 구조, UX Writing 가이드 준수).
- 굵기 조절이 불가능한 경우, 기존 Pretendard 옵션의 "이 폰트는 굵기가 고정이에요" 같은
  안내 패턴을 재사용한다.

### 컨텐츠 관점 (해당 시)
- 해당 없음.

## 구현 계획
1. 구글 폰트 카탈로그 데이터 소스를 결정한다(정적 JSON 번들 vs 런타임 API 호출, 비용·
   유지보수 관점에서 비교).
2. 슬롯 배정·재사용·초과 처리 로직을 설계한다(레이어 ID ↔ 슬롯 ↔ 폰트 이름 매핑 상태 관리).
3. `textFontOptions.ts`의 정적 배열 구조를 동적 폰트 선택을 지원하도록 확장하거나 별도
   모듈로 분리한다.
4. 텍스트 레이어 속성 패널에 폰트 검색 UI를 추가한다.
5. 런타임 CSS 변수 주입·구글 폰트 `<link>` 동적 로드 로직을 구현한다.
6. 로컬 `npm run dev`로 `/admin/shader-lab`에서 여러 폰트를 검색·선택해 동시에 여러
   텍스트 레이어에 각기 다른 폰트가 반영되는지, 슬롯 초과 시나리오가 안내대로 동작하는지
   확인한다(로컬 `ADMIN_EMAILS` 셸 환경변수로 인증).
7. 굵기 정책을 문서화하고 완료 기록에 남긴다.
