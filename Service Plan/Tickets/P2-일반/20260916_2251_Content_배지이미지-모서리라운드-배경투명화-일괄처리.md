# [Content] 배지 이미지 일괄 후처리 — 모서리 라운드(radius 12px) + 배경 투명화

## 배경 / 문제 정의
사용자가 특정 배지 이미지들의 모서리가 직각(정사각형)이라 지적하고, radius 12px로 둥글게
처리하고 배경을 투명하게 만들어달라고 요청했다.

오케스트레이터가 대상 이미지 샘플 2장을 직접 다운로드해 확인한 결과, 요청의 의미는
"인물/오브젝트만 오려내는 전체 배경 제거"가 아니라 **이미지 전체에 라운드 사각형(radius
12px) 알파 마스크를 씌워, 네 모서리의 잘려나가는 삼각형 영역만 투명하게 만드는 것**이다
(이미지 내부 콘텐츠·배경색은 그대로 유지, 모서리 바깥만 투명).

## 상세 요구사항

### 대상 범위 (DB 직접 조회로 확정, 오케스트레이터가 이미 조회 완료)
1. **컬렉션 "JAM! 레벨 0" 전체** — 19개 배지, 전부 `badges/shader-lab/{badge_id}.png`
   경로 (쉐이더 랩으로 생성된 이미지, 그라디언트 배경 완전 불투명 정사각형)
2. **트라이브 "아스팔트 레인저" 전체** — 10개 컬렉션(02-01~02-10), 90개 배지, 전부
   `badges/factions/{collectionSlug}/item-{collectionSlug}-{n}.png` 경로 (검정 배경
   완전 불투명 정사각형)
- 총 109개 배지. 정확한 목록(badge id·image_url)은 완료 기록에 SQL로 남긴다.

### 서비스/코드베이스 관점
- `jam-web/scripts/recraft/` 폴더 관례를 따라 신규 스크립트를 작성한다(예:
  `round-corners.js`). 기존 `remove-background-local.py`(PIL 기반 배경 제거)와는 목적이
  다르므로 그대로 재사용하지 말고, `sharp`(이미 `jam-web/package.json`에 설치돼 있음)로
  구현한다.
- 처리 로직: 각 이미지를 실제 크기(w×h)로 로드 → radius 12px의 라운드 사각형 SVG 마스크를
  같은 크기로 생성 → `composite`로 `dest-in` 블렌드 적용(마스크 바깥은 투명, 안쪽은 원본
  유지) → PNG(알파 채널 포함)로 저장.
- **이미 라운드+투명 처리된 이미지가 섞여 있을 가능성**을 배제하지 않는다 — 스크립트 실행
  전 각 이미지의 네 모서리 픽셀이 이미 투명(alpha=0)인지 검사해, 이미 처리된 이미지는
  건너뛰고 처리 대상만 추려서 로그로 남긴다(멱등성 확보, 중복 처리로 이미 둥근 모서리를
  또 깎아 화질 손상되는 것 방지).
- 업로드는 기존 `register-badge-images.js`와 같은 방식(Storage 버킷 `images`, 같은 경로에
  upsert, `?v={timestamp}` 캐시버스팅 쿼리스트링 추가)을 재사용하거나 그 로직을 참고해
  새 스크립트에 포함한다.
- `badges.image_url`을 새 캐시버스팅 URL로 UPDATE한다.
- 실행한 UPDATE문은 기존 레포 관례대로 `seed_배지이미지라운드처리_20260916.sql` 형태로
  저장해 커밋한다.

### UI/UX 관점 (해당 시)
- 해당 없음(이미지 에셋 자체 수정).

### 컨텐츠 관점 (해당 시)
- `item_books`(컬렉션)·`tribes`의 대표 이미지(`image_url`)는 이번 요청 범위에 포함되지
  않는다 — 사용자가 명시한 "배지 이미지"만 처리한다. 대표 이미지도 같은 처리가 필요하면
  별도 요청으로 진행한다.

## 구현 계획
1. 신규 스크립트(`round-corners.js`) 작성 — radius 12px 고정 상수, 대상 목록은 DB
   쿼리(위 대상 범위)로 직접 가져오거나, 이 티켓에 첨부된 목록을 JSON으로 하드코딩해 받는다.
2. 처리 전 각 이미지의 모서리 alpha 값을 검사해 "이미 처리됨" 여부를 판별하고 로그 출력.
3. 처리 대상만 라운드 마스크 적용 → Storage 재업로드(upsert) → `badges.image_url` UPDATE.
4. 처리 전/후 샘플 이미지(각 그룹에서 1장씩, 총 2장)를 사용자에게 보여주고 확인받는다 —
   전량 처리 전에 반드시 승인 게이트를 거친다(이미지 파이프라인 관례).
5. 승인 후 나머지 전량 처리.
6. SQL 로그 파일 커밋.
