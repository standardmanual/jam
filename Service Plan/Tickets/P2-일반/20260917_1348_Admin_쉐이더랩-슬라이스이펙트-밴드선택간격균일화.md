# [Admin] 쉐이더랩 슬라이스 이펙트 — 밴드 선택 간격 균일화

## 배경 / 문제 정의
직전 두 티켓([20260917_1256](./20260917_1256_Admin_쉐이더랩-슬라이스이펙트-균일패턴-교차라인-회전각도추가.md),
[20260917_1324](./20260917_1324_Admin_쉐이더랩-슬라이스이펙트-교차선제거-이동량균일화.md))에서
"선택된" 밴드가 프레임 간 고정되도록 하고 이동 강도를 균일화했지만, **어느 밴드를 선택할지
자체**는 여전히 `bandNoise`(밴드 인덱스별 해시값) 임계값 통과 여부로 결정되는 확률적 방식이다.
사용자가 실렌더 스크린샷을 첨부해 "슬라이스 간격이 균일하지 않다"고 재차 지적했다 — 밀리는
밴드들이 화면 위쪽에 몰려있고 그 사이 간격이 불규칙하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 대상 파일: `jam-web/patches/@basementstudio+shader-lab+3.0.2.patch` 안의 `slice-pass.js`
  (`buildEffectNode`의 `gate` 계산부)
- 현재: `const gate = step(float(1).sub(this.densityUniform), bandNoise)` — `bandNoise`가
  밴드 인덱스마다 임의의 값이라 `density`로 정한 비율만큼 밴드가 선택되긴 하지만, 선택된
  밴드 사이 간격이 무작위로 흩어진다(클러스터링·큰 공백이 불규칙하게 발생).
- 목표: `density`가 "몇 밴드마다 한 번씩 규칙적으로 선택할지"를 결정하는 **일정 간격** 패턴으로
  바꾼다. 예: 선택 주기 `period = round(1 / max(density, 0.001))`(또는 유사 공식)를 구해
  `mod(sliceIndex, period)`가 0(또는 특정 나머지 범위)일 때만 `gate = 1`이 되도록 한다.
  - `density = 1`이면 모든 밴드가 선택(현재와 동일한 결과 유지)
  - `density`가 낮을수록 선택 주기가 길어져 밴드 사이 간격이 넓어지되, **그 간격 자체가
    일정해야** 한다(현재처럼 무작위 클러스터링 없이).
  - 공식·경계값(density=0 처리 등)은 구현 시 판단하고 근거를 완료 기록에 남긴다.
- `bandNoise`는 다른 곳(있다면)에서 여전히 필요한지 확인하고, 더 이상 쓰이지 않으면 정리한다.

### UI/UX 관점 (해당 시)
- `density` 필드 라벨·설명은 그대로 두되, 동작이 "확률적 밀도"에서 "규칙적 선택 주기"로
  바뀌므로 필드 라벨을 "밀도"에서 "선택 주기" 등으로 바꿀지 여부는 구현 시 판단한다(사용자가
  기존 라벨에 특별히 이견을 내지 않았으므로, 라벨 변경이 필요치 않다고 판단되면 유지).

### 컨텐츠 관점 (해당 시)
- 해당 없음.

## 구현 계획
1. `slice-pass.js`의 `gate` 계산 로직을 확률 기반에서 규칙적 주기 기반으로 재작성.
2. patch 파일 재생성(`patch-package`).
3. 로컬 실렌더로 `density`를 여러 값(0.2, 0.58, 1.0)으로 바꿔가며 밴드 간격이 실제로 일정한지
   확인 후 스크린샷 보고.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `gate` 계산을 확률 기반(`step(1-density, bandNoise)`)에서 규칙적 주기 기반
  (`mod(sliceIndex, period) == 0`)으로 재작성했다. `period`는 JS(`updateParams`)에서
  `Math.round(1/density)`로 미리 계산해 정수 유니폼(`periodUniform`)으로 넘긴다(three/tsl에
  정수 round 노드가 마땅치 않고, density는 프레임마다가 아니라 파라미터 갱신 시에만
  바뀌므로 JS 계산이 더 간단하고 정확하다).
  - `density = 1` → `period = 1` → 모든 밴드 선택(기존 "density=1이면 전체 선택" 동작 유지).
  - `density <= 0` → `densityEnabledUniform`을 0으로 꺼서 gate를 항상 0으로 만든다(간격이
    무한대가 되는 특수 케이스라 period 값 자체는 의미가 없음).
  - `mod()`는 음수 `sliceIndex`(회전각에 따라 발생)에도 항상 `[0, period)` 범위를 반환하므로
    회전 상태에서도 동일하게 규칙적이다.
- `bandNoise`와 이를 계산하던 `hash2` 함수는 gate 재작성 이후 어디에서도 쓰이지 않아 함께
  제거했다(직전 시도에서 죽은 코드로 남겼던 것을 이번에 정리). `hash2`가 쓰던 `dot`·`fract`
  import도 함께 제거, `mod` import를 추가했다.
- UI 라벨("밀도")은 변경하지 않았다 — 사용자가 기존 라벨에 이견을 내지 않았고, "몇 밴드마다
  한 번씩 선택할지"를 0~1 슬라이더로 표현하는 UX는 유지해도 무리가 없다고 판단.

### 주요 의사결정 / 핵심 메모
- period 계산을 셰이더(TSL) 안이 아니라 JS `updateParams`에서 수행 — three/tsl에 정수 반올림
  노드가 마땅치 않고, 매 프레임이 아니라 파라미터 변경 시에만 필요한 계산이라 GPU보다 CPU에서
  계산하는 편이 더 명확하고 저렴하다.
- `density<=0`을 "period 무한대"로 취급하지 않고 별도 `densityEnabledUniform` 스위치로 분리 —
  `period`를 무한대에 준하는 큰 정수로 넘기는 방식보다 명시적이고, `mod` 연산에서 극단적으로
  큰 값을 다룰 때 생길 수 있는 부동소수점 오차 우려를 피했다.
