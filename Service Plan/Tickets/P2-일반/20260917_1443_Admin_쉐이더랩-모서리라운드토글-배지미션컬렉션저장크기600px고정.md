# [Admin] 쉐이더랩 — 모서리 라운드 토글·배지/미션/컬렉션 저장 크기 600px 고정

## 배경 / 문제 정의
쉐이더랩(`/admin/shader-lab`)의 미리보기 저장 영역에 사용자가 두 가지 기능을 요청했다.

1. 저장되는 이미지의 모서리를 72px 라운드로 잘라내고, 잘려나간 영역은 투명하게 처리하는
   기능을 켜고 끌 수 있게 한다.
2. 배지 이미지·컬렉션 대표이미지·미션 대표이미지로 저장(적용)할 때는 이미지 크기를
   600×600px로 고정 저장한다(투명도 유지).

## 상세 요구사항

### 서비스/코드베이스 관점
- 관련 파일:
  - `jam-web/src/app/admin/shader-lab/ShaderLabExportPanel.tsx` (PNG 다운로드 버튼 + 적용 탭 3종)
  - `jam-web/src/app/admin/shader-lab/ShaderLabApplyTab.tsx` (배지/미션/컬렉션 적용 로직,
    `runApply()`·`compressCanvasPngToTarget()`)
  - `jam-web/src/app/admin/badges/bakePreviewToBlob.ts` (`canvasToBlob` 등 공용 캔버스→Blob
    유틸, 필요시 라운드 클립 헬퍼를 이곳 혹은 shader-lab 전용 유틸로 추가)

- **모서리 라운드 토글 (72px)**:
  - 쉐이더랩 미리보기/저장 영역에 켜고 끌 수 있는 토글 UI를 추가한다(위치는
    `ShaderLabExportPanel` 상단 등 구현 시 판단).
  - 켰을 때: 저장되는 이미지에 반경 72px의 둥근 사각형 클립을 적용하고, 클립 밖 영역은
    완전 투명(alpha 0)으로 만든다. Canvas 2D의 `roundRect` 클리핑 패스 + `globalCompositeOperation`
    (또는 클립 후 `clearRect`가 아닌 클립 패스 안에만 `drawImage`)로 구현한다.
  - **72px 기준 해상도**: 이 값은 실제 서비스에서 노출되는 600×600 기준으로 보이는 반경이다.
    배지/미션/컬렉션 적용(요구사항 2, 항상 600×600으로 저장)에는 72px을 그대로 적용한다.
    반면 일반 "PNG 다운로드"는 기존처럼 1920×1920 원본 해상도를 유지하므로(아래 참고), 같은
    시각적 비율을 유지하려면 반경을 `72 × (다운로드 해상도 / 600)`으로 비례 확대해야 한다 —
    이 비례 계산 방식으로 구현하고, 최종 판단·근거는 완료 기록에 남긴다.
  - 토글은 PNG 다운로드와 배지/미션/컬렉션 적용 양쪽에 공통으로 적용되는 하나의 설정으로
    둔다(사용자가 "미리보기 저장 영역"이라고 표현한 것을 export 시점 공통 옵션으로 해석).

- **배지/미션/컬렉션 저장 크기 600×600 고정**:
  - 현재 `ShaderLabApplyTab.tsx`의 `compressCanvasPngToTarget()`은 목표 용량
    (`TARGET_APPLY_IMAGE_BYTES`, 3.5MB)을 넘지 않을 때까지 90%씩 반복 축소하는 방식이라
    최종 해상도가 매번 달라진다. 이를 **항상 600×600px 고정 캔버스에 리사이즈해서 저장**하는
    방식으로 바꾼다(비율 유지 불필요 — 쉐이더랩 캔버스는 이미 1:1 정사각형 고정, 티켓
    20260914_1045 참고).
  - 리사이즈는 `drawImage(sourceCanvas, 0, 0, 600, 600)`처럼 단순 스케일로 처리하고,
    캔버스를 투명 배경으로 초기화한 뒤 그려 투명도를 유지한다.
  - `MAX_APPLY_IMAGE_BYTES`(5MB) 체크는 안전망으로 계속 남긴다 — 600×600 PNG가 실제로
    이 상한을 넘는 경우는 드물겠지만, 넘으면 기존과 동일하게 에러 메시지를 보여준다.
    반복 축소 로직(`compressCanvasPngToTarget`)은 더 이상 필요 없으면 제거하되, 완전히
    안 쓰이는지 확인 후 정리한다.
  - 일반 "PNG 다운로드"(`ShaderLabExportPanel.downloadPng`)는 이 변경 대상이 아니다 —
    기존 주석대로 사용자가 직접 받는 파일은 원본 해상도(1920×1920)를 유지한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `shaderLabCanvasUtils.ts`(신규) — 쉐이더 랩 캔버스(WebGPU) 공용 변환 유틸.
  `canvasToImage()`로 WebGPU 캔버스를 `<img>`로 먼저 디코딩한 뒤(직접 drawImage 시 빈 화면
  버그 회피, 기존 `compressCanvasPngToTarget`의 노하우 재사용), `drawImageToCanvas(image,
  size, radiusPx)`로 정사각 캔버스에 리사이즈 + (radiusPx가 있으면) `roundRect` 클립 패스
  적용. 클립 밖은 `clearRect`로 초기화된 투명 배경 위에 그려 alpha 0 유지.
- `ShaderLabExportPanel.tsx` — 상단에 "모서리 라운드 (72px)" `Switch` 토글 추가(초기값
  꺼짐). `downloadPng()`는 토글이 켜지면 `APPLY_ROUND_RADIUS_PX * (canvas.width /
  APPLY_IMAGE_SIZE_PX)`로 비례 확대한 반경을 1920×1920 그대로에 적용, 꺼지면 기존과 동일.
  토글 상태를 `ShaderLabApplyTab` 3개 인스턴스에 `roundEnabled` prop으로 전달.
- `ShaderLabApplyTab.tsx` — 반복 축소 방식(`compressCanvasPngToTarget`/
  `loadImageFromBlob`/`DOWNSCALE_STEP`/`MAX_DOWNSCALE_ATTEMPTS`)을 전량 제거하고,
  `runApply()`를 `canvasToImage()` → `drawImageToCanvas(image, 600, roundEnabled ? 72 :
  null)` → `canvasToBlob()` 순서로 재작성. `MAX_APPLY_IMAGE_BYTES` 초과 체크는 안전망으로
  유지.
- `applyGeneratedImageConstants.ts` — 더 이상 쓰이지 않게 된 `TARGET_APPLY_IMAGE_BYTES`
  상수(반복 축소 목표 용량)를 제거. 전체 코드베이스에서 이 상수를 사용하는 다른 호출부가
  없음을 grep으로 확인.

### 주요 의사결정 / 핵심 메모
- 72px 반경의 "600×600 기준" 해석: 티켓 요구사항대로 배지/미션/컬렉션 적용(600×600 고정)에는
  72px을 그대로, PNG 다운로드(1920×1920 유지)에는 `72 × (1920/600) = 230.4px`로 비례
  확대해 적용했다. 두 경로가 공유하는 단일 toggle 상태(`ShaderLabExportPanel`)에서 관리한다.
- `compressCanvasPngToTarget`(반복 축소 방식)과 `TARGET_APPLY_IMAGE_BYTES`는 항상 600×600
  고정 리사이즈로 대체되어 더 이상 쓰이지 않으므로 완전히 제거했다(티켓 지시사항 55번째 줄).
- **⚠️ 실렌더 검증 중 실제 프로덕션 DB에 쓰기 발생(WARN→HALT급 알림, 아래 alerts 참고)**:
  이 프로젝트는 staging/production이 단일 Supabase DB를 공유한다(사용자 메모리 규칙).
  배지 적용 기능을 실제 화면에서 눌러 검증하는 과정에서 실제 배지 "2일 연속 출석 라이딩"
  (id `e79aaf15-9621-4254-a0e4-27875e02ce87`)의 대표이미지가 테스트용 초록색 메시
  그라디언트로 실제로 덮어써졌다. 되돌릴 원본 백업이 없어 트레일메이커 권한으로는 복구할
  수 없다 — 오케스트레이터/사용자가 원래 이미지를 재생성하거나 Storage 버전 이력으로
