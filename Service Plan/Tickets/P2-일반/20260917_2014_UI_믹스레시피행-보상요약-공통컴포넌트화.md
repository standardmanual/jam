# [UI] 믹스 레시피 행·믹서 요약바 보상 표시 공통 컴포넌트화

## 배경 / 문제 정의

티켓 `20260917_1828`에서 만든 서비스 전용 `RecipeRewardBlock`을 대체한다. 사용자가 제시한
목업(배지+포인트 / 배지만 / 포인트만 3케이스)에 맞춰, **레시피 탐색 목록의 각 행**과
**믹서 화면 상단 요약바**를 완전히 같은 컴포넌트로 통일한다. 두 위치 모두 "이 레시피를
완료하면 무엇을 받는지"를 보여주는 행이므로 같은 컴포넌트여야 한다는 게 이번 결정이다.

**0.5단계 탐색 결과**: 딱 맞는 기존 컴포넌트가 이미 있다 — `ListRowCard`가
`icon`(40×40)/`title`/`subtitle`/`trailing` 슬롯 구조라 목업 레이아웃과 정확히 일치한다.
신규 레이아웃 컴포넌트를 만들 필요 없이, 이 컴포넌트를 감싸서 레시피 데이터를 슬롯에
매핑하는 얇은 어댑터만 만든다.

**⚠️ 병존 구현 주의**: `ListRowCard`는 `.claude/skills/jam-work/references/
ds-connection-scope.md`의 "병존 구현 8종"에 속한다 — `design-system/components/
patterns/ListRowCard.jsx`(MODULAR)와 `src/components/ui/ListRowCard.tsx`(서비스)가
따로 존재하고 값만 수동으로 맞춰둔 상태다. **실제 화면(`MissionDetailClient.tsx` 등)은
`@/components/ui/ListRowCard`를 쓴다** — MODULAR 쪽만 고치면 서비스에는 반영되지 않는다.
새 어댑터는 **`@/components/ui/ListRowCard`(서비스 구현)를 감싸서** 만들고, 어댑터 자체를
MODULAR로 신규 등록할지는 이 구조를 감안해 구현 단계에서 판단한다.

## 상세 요구사항

### 표시 규칙 (목업 3케이스, 위→아래 순서)

레시피 행 하나는 `ListRowCard`로 구성한다:
- **icon**: 보상 배지 이미지(있으면) — 없으면(포인트만 보상인 레시피) "POINT" 아이콘
  자리로 대체(문구는 한국어 UX 라이팅 규칙에 맞춰 "포인트"로 표기하거나, 순수 아이콘
  글리프로 처리 — 구현 단계에서 정한다).
- **title**: 레시피 이름(`combination_recipes.name`, 마이그레이션 175로 이미 존재).
- **subtitle**: 획득 배지가 있으면 `RarityBadge`(MODULAR, 등급 칩) + 배지 이름. 배지가
  여러 개면 이름을 이어붙이거나 대표 1개 + "+N" 표기(구현 단계에서 정함). 포인트만 있는
  레시피는 subtitle을 비운다.
- **trailing**: 포인트가 있으면 포인트 값(아이콘 없이 숫자만, 천 단위 콤마). 포인트가
  0이면 표시하지 않는다.

3가지 케이스:
1. 배지 + 포인트: icon=배지 이미지, subtitle=등급칩+배지명, trailing=포인트값
2. 배지만: icon=배지 이미지, subtitle=등급칩+배지명, trailing 없음
3. 포인트만: icon=포인트 아이콘, subtitle 없음, trailing=포인트값

### 적용 범위

- `jam-web/src/app/(main)/combine/CombineClient.tsx`의 **레시피 탐색 목록 각 행**과
  **믹서 화면 상단 요약바**, 이 두 곳만 교체한다. 믹서 요약바는 클릭 동작(레시피 전환 등)이
  없으므로 `ListRowCard`의 `href`/`onClick`은 쓰지 않고 표시 전용으로 렌더한다.
- 미션 화면 등 다른 화면은 이번 범위에 포함하지 않는다(사용자 확인 — 목업의 "미션 이름"
  placeholder는 일반 예시 텍스트였을 뿐, 실제로는 믹스 레시피 이름 자리다).
- 기존 `jam-web/src/app/(main)/combine/RecipeRewardBlock.tsx`는 이 작업으로 대체되므로
  삭제한다.

### 컴포넌트 전략

`ListRowCard`가 병존 구현이라 MODULAR 쪽만 감싸면 실제 화면에 반영되지 않는다 — 새
어댑터는 **서비스 구현(`@/components/ui/ListRowCard`)을 감싸는 서비스 전용 컴포넌트**로
만든다(믹스 화면(`src/app/(main)/combine/`) 안에 둔다). MODULAR 승격은 이번 범위가
아니다 — 다른 화면(미션 등)에서 같은 조합이 필요해지면 그때 병존 구현 문제까지 포함해
별도 판단한다.

## 구현 계획

### 파일별 변경 (예상)

| 파일 | 변경 |
|---|---|
| 신규 어댑터(경로·MODULAR 등록 여부는 구현 단계에서 결정 — 병존 구현 문제 때문에 서비스
  전용 `src/app/(main)/combine/` 아래에 둘 수도 있음) | `@/components/ui/ListRowCard`
  (서비스)+`RarityBadge` 조합, 레시피 데이터 → 슬롯 매핑 |
| `jam-web/src/app/(main)/combine/CombineClient.tsx` | 레시피 행·믹서 요약바를 신규 컴포넌트로 교체 |
| `jam-web/src/app/(main)/combine/RecipeRewardBlock.tsx` | 삭제 |

### 수용 기준

1. 레시피 탐색 목록의 각 행이 `ListRowCard` 기반 레이아웃(아이콘+타이틀+서브타이틀+
   우측값)으로 보인다.
2. 믹서 화면 상단 요약바가 레시피 행과 동일한 컴포넌트로 렌더된다(같은 코드 경로임을
   코드로 확인 가능해야 함).
3. 배지+포인트/배지만/포인트만 3케이스가 목업대로 각각 다르게 렌더된다.
4. `RecipeRewardBlock.tsx`가 삭제되고 참조가 남아있지 않다.
5. 신규 어댑터가 `@/components/ui/ListRowCard`(서비스 구현)를 재사용하고, MODULAR
   `ListRowCard`를 직접 import하지 않는다.

### 롤백 계획
클라이언트 화면 변경 위주. 문제가 생기면 이전 `RecipeRewardBlock` 기반 구현으로 되돌린다.
