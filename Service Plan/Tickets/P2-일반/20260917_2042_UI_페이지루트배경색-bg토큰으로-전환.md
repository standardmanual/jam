# [UI] 페이지 루트 배경색을 `--color-bg`(#000)로 전환

## 배경 / 문제 정의

바텀시트 배경(`--color-surface-elevated: #1f1f1f`)과 페이지 배경(`--color-surface:
--color-base-grey-800` = `#1a1a1a`)이 5 단위 차이라 실제 화면에서 거의 구분되지 않는다.
바텀시트가 페이지 위에 떠 있다는 느낌이 나지 않는 문제.

`jam-web/design-system/tokens/colors.css`에 이미 순수 검정 토큰
`--color-bg: var(--color-base-black)`(`#000000`)이 정의돼 있는데, 주석(46행 근처)에
"프로덕션(main) 페이지 캔버스 대부분이 `--color-bg`가 아니라 `--color-surface`를 그대로
깔고 있다"고 명시돼 있다 — 즉 원래 의도한 아키텍처는 **페이지=`--color-bg`(순정 검정),
카드/바텀시트=`--color-surface`(밝은 회색)로 대비**를 주는 것인데, 실제 페이지들이
`--color-surface`를 페이지 배경으로 잘못 쓰고 있어 이 의도가 깨진 상태다.

**`--color-surface` 토큰 자체를 `#000`으로 바꾸지 않는다** — 이 토큰은 카드·바텀시트 등
"떠 있어야 하는" 요소들이 공유해서 쓰고 있어, 토큰 값을 바꾸면 그 요소들의 대비가 오히려
사라진다. 대신 **페이지 루트 컨테이너의 클래스를 `bg-surface` → `bg-bg`로 교체**한다.

## 상세 요구사항

### 서비스/코드베이스 관점

아래 29개 위치(어드민 제외, `src/app/(main)/**`의 페이지 루트 `<div>`)에서 **루트
컨테이너에만** `bg-surface`를 `bg-bg`로 바꾼다. 같은 파일 안에 있는 다른 `bg-surface`
사용(카드·아이템 등)은 건드리지 않는다 — grep으로 찾은 아래 줄만 정확히 대상이다.

방향이 더 안전하면 그 방향으로 구현해도 된다(같은 결과라면 구현 단계 판단에 맡김).

### UI/UX 관점
- 바텀시트를 열었을 때 시트 배경(`#1f1f1f`)과 그 뒤로 보이는 페이지 배경(`#000`)이
  명확히 구분돼야 한다.
- 어드민(`src/app/admin/**`)은 이번 범위가 아니다 — 별도 디자인 정책(MODULAR 미적용)이라
  건드리지 않는다.

## 구현 계획

### 수용 기준

1. 위 29개 위치의 페이지 루트 배경이 `#000`(순정 검정)으로 렌더된다.
2. 같은 파일 안의 카드·바텀시트 등 다른 요소의 배경(`--color-surface`,
   `--color-surface-elevated`)은 값이 바뀌지 않는다.
3. 바텀시트를 열었을 때 시트와 뒤 배경이 시각적으로 구분된다(실렌더 확인).
4. 어드민 화면은 배경색이 바뀌지 않는다.
5. 전체 페이지를 스크린샷 또는 인터페이스 리뷰로 훑어 텍스트 대비·이미지 경계 등이
   깨진 곳이 없는지 확인한다(페이지 배경이 밝은 회색→순정 검정으로 바뀌면서 반투명
   오버레이·그림자 등 배경색을 전제한 스타일이 깨질 수 있음).

### 롤백 계획
클래스명 교체 위주(토큰 값 변경 없음)라 위험이 낮다. 문제가 생기면 해당 줄만 되돌리면 된다.
