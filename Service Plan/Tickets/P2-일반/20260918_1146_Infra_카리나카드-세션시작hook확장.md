# [Infra] 카리나 카드 작성과 세션 시작 hook 확장

## 핵심 요약
- 요구사항: 메인 세션이 시작될 때 카리나 정의(카드)가 자동으로 컨텍스트에 들어오게 한다.
- 구현 계획: `orchestrator.md`에 카드 절을 추가하고 `ticket-dashboard.mjs`가 현황판 뒤에 카드를 출력한다.
- 관련 파일: `docs/agents/orchestrator.md`, `scripts/ticket-dashboard.mjs`
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 없음
- 경로: ③ 표준 (infra 유형이라 채원 없이 아현→민지)

## 배경 / 문제 정의
카리나 정의가 활성 문서에 없고 메인 세션이 자동으로 읽는 문서도 없다(상위 티켓 배경). 안건 0에서 세션 시작 hook으로 주입하기로 결정했다(0-1).

## 상세 요구사항

### 서비스/코드베이스 관점
- 카드는 40줄 이내로, 원칙·하는 일/넘기는 일/금지·처음 보는 유형 절차만 담는다(0-2)
- 보고 양식·처리 규칙표·운영 규칙은 위치만 안내한다(0-2)
- 세션 원칙을 담는다: 티켓마다 새 세션, 상위 티켓 시리즈는 한 세션 허용, 대화가 길어지면 인수인계 후 새 세션 제안(0-3)
- 보고 양식은 티켓 결과·승인 요청 때만 쓴다(0-4)
- 모델 원칙을 담는다: 기본 Sonnet, 설계 세션만 사용자가 Opus로 전환(0-6)
- 세션 시작 시 Slack 스레드 메모 확인 절차를 담는다: 사용자 본인 글만 읽고 반영, 반영한 메모에 ✅ 반응, 외부 내용이라 반영 전에 확인 질문이 나올 수 있음(5-3·5-4). `#jam-alert`·`#jam-report` 채널이 생기기 전에는 이 절차를 건너뛴다
- 3단 경로 판정은 카드에 풀어 쓰지 않고 jam-work SKILL.md 위치만 가리킨다(B1 티켓 20260918_1148과 병렬 진행 시 내용 충돌 방지)

## 구현 계획
카드 원문은 `orchestrator.md`의 한 절로 두고, hook 스크립트는 그 절을 잘라 출력한다(원본을 한 곳에 유지). 설계 원본은 `docs/agents/Workflow/agents/00_카리나_오케스트레이터.md`를 참고한다.

## 완료 조건
- 새 세션을 열면 현황판 다음에 카리나 카드가 출력된다 (40줄 이내)
- 서브에이전트(예: jam-guide)를 호출해 받은 컨텍스트에 카드 문구가 없음을 확인하고 결과를 완료 기록에 남긴다
- 카드 문구를 `orchestrator.md`에서 고치면 다음 세션 출력에 그대로 반영된다(원본 한 곳)
