# [Infra] jam-work 파이프라인 정비

## 핵심 요약
- 요구사항: `needs_approval` 발생 시 멈춤, 3단 경로 분기, 뒤처진 워크트리 결함 수정, 요청문 축소를 구현한다.
- 구현 계획: `jam-work.js`와 jam-work SKILL.md를 고친다. 머지 후 다음 실제 UI 티켓으로 토큰을 실측해 닫는다.
- 관련 파일: `.claude/workflows/jam-work.js`, `.claude/skills/jam-work/SKILL.md`
- 후속 티켓: 20260918_1158 (인수인계·병렬화 개선)
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 없음 (권장: 다른 ③ 티켓보다 먼저. 워크트리 결함이 남아 있으면 민지가 잘못된 `[주의]`로 검사를 다시 돌린다)
- 경로: ③ 표준 (infra 유형이라 채원 없이 아현→민지)

## 배경 / 문제 정의
34줄 여백 수정 티켓(20260915_2016)이 22만 8천 토큰·16분을 썼다. 채원①의 `needs_approval`이 있어도 구현이 진행되고, 워크트리가 최신 `origin/staging`보다 뒤처져 배정된다(상위 티켓 안건 1).

## 상세 요구사항

### 서비스/코드베이스 관점
- 채원①이 `needs_approval`을 내면 파이프라인을 멈추고 카리나가 사용자에게 묻는다. 승인되면 채원① 판정을 `reuseDecision`으로 넘겨 아현부터 다시 돌린다(1-1)
- 경로 3단 분기(1-2): ① 경미(파일 1~2개·10줄 이내) = 카리나 직접 / ② 가벼운 UI(로직 변경 없는 스타일·문구이고 고칠 내용이 티켓에 확정) = 아현→민지 / ③ 표준 = 채원①→아현→민지→채원②. 카리나가 유형 판정 때 경로를 정해 사용자에게 먼저 알린다
- 워크트리가 최신 `origin/staging`에서 시작하도록 결함을 고친다
- 파이프라인이 끝날 때 에이전트별 토큰 사용량과 소요 시간을 결과에 담고, 카리나가 티켓 완료 기록에 남긴다 (성공 기준 1-3을 측정하기 위해 필요, 2026-09-18 워크플로 검토에서 추가). 워크플로 도구가 사용량을 돌려주지 않으면 대안(세션 사용량 조회 등)을 조사해 적는다
- 카리나 요청문은 티켓 경로와 한 줄 지시로 줄이고, 에이전트는 티켓의 `핵심 요약` 절을 읽는다(공통규칙 2번)

## 구현 계획
워크트리 결함의 원인(배정 시점의 기준 커밋)을 먼저 확인한 뒤 수정한다. 경로 값은 워크플로 인자로 받아 채원 호출 여부를 가른다.

## 완료 조건
- `needs_approval`이 있는 판정이 나오면 워크플로가 아현을 호출하지 않고 멈춘 결과를 반환한다
- 경로 ②로 호출하면 채원①·②가 호출되지 않는다
- 워크트리의 HEAD가 호출 시점의 `origin/staging` 최신 커밋을 포함한다
- 파이프라인 결과에 에이전트별 토큰 사용량이 담겨 나온다 (또는 수집 불가 사유와 대안이 완료 기록에 있다)
- 성공 기준(1-3): 머지 후 다음 실제 UI 티켓(비슷한 규모)의 총 토큰이 약 11만 이하다. 머지 후 이 티켓은 `WAITING`으로 두고, 측정 결과를 완료 기록에 남기고 닫는다 (테스트용 호출은 하지 않는다, 안건 2-3)
