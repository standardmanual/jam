# [Infra] Slack 채널 생성과 클라우드 연결 확인

## 핵심 요약
- 요구사항: `#jam-alert`·`#jam-report` 채널을 만들고, 클라우드 예약 작업에서 Slack에 글을 올릴 수 있는지 먼저 확인한다.
- 구현 계획: 사용자 승인 후 카리나가 Slack 도구로 채널을 만든다. 클라우드 연결은 시범 호출 1회로 확인한다.
- 관련 파일: Slack 워크스페이스, `automation-list.md`(채널 정보 기록)
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 없음
- 경로: ① 카리나 직접

## 배경 / 문제 정의
안건 5에서 용도별 Slack 채널 2개로 알림을 도입하기로 했다. 클라우드에서 Slack을 쓸 수 없으면 안건 5의 설계를 바꿔야 하므로, 이 확인을 예약 등록보다 앞에 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `#jam-alert`: 즉시 알림급 위험(장애·비용 급증·개인정보·경제 붕괴)과 예약 작업 전체 실패. 휴대폰 푸시 켬(5-2)
- `#jam-report`: 주간·월간 리포트 요약. 푸시 끔(5-2)
- 클라우드 예약 작업 환경에서 Slack 커넥터로 테스트 글 1건을 올릴 수 있는지 확인한다
- 올릴 수 없으면 대안(예: Webhook)을 조사해 상위 티켓 안건 5에 결정 요청으로 올린다

## 구현 계획
채널 생성은 외부에 보이는 작업이라 사용자 승인을 받은 뒤 실행한다.

## 사용자 작업
> Claude가 대신할 수 없는 일이다. 완료되면 이 절에 체크한다.

- [ ] 채널 생성을 승인한다
- [ ] 휴대폰 Slack 앱에서 `#jam-alert` 푸시를 켜고 `#jam-report` 푸시를 끈다

## 완료 조건
- 두 채널이 존재하고 채널 ID가 `automation-list.md`에 기록되어 있다
- 클라우드 환경에서 올린 테스트 글이 채널에 보인다 (또는 불가 사유와 대안이 기록되어 있다)
