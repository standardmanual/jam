# [Infra] 클라우드 예약 작업 등록

## 핵심 요약
- 요구사항: 주간·월간 예약 작업을 1회 수동 실행으로 확인한 뒤 클라우드에 꺼진 상태로 등록한다.
- 구현 계획: 수동 실행 → 결과 확인 → 꺼진 상태로 등록 → Slack 연결 → 사용자가 켜는 시점 결정.
- 관련 파일: `scheduled-jobs.md`, 클라우드 예약 작업 설정
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 20260918_1149·1150·1151·1152·1154·1155 (모두 필요)
- 경로: ① 카리나 직접 (예약 등록은 메인 세션만)

## 배경 / 문제 정의
안건 2-3에서 카즈하·하니는 무인 실행이라 등록 전에 반드시 1회 수동 실행하기로 했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 주간 작업을 1회 수동 실행해 `Reports/주간/`에 리포트가 저장되고 `#jam-report`에 요약이 올라가는지 확인한다
- 월간 작업도 같은 방식으로 1회 수동 실행한다
- 수동 실행의 실제 토큰 사용량을 리포트 "비용" 절에 기록한다
- 예약 도구가 토큰 상한을 강제로 끊을 수 있는지 확인한다. 불가능하면 "상한에 가까우면 수집을 멈추고 있는 자료로 마무리" 지시와 사후 기록으로 운영한다(4-11)
- 등록은 꺼진 상태로 한다. 켜는 시점은 사용자가 정한다

## 구현 계획
수동 실행 결과를 사용자에게 보여 준 뒤 등록한다.

## 선행 확인 (2026-09-18, 4차 실행 시점)
- 아직 진행 불가: `#jam-report`에 시범 글 없음(1154), GA4 키(1151) 미확인, 클라우드 환경 등록 미완
- 해소됨(2026-09-18): 1149·1150 프로덕션 배포, 읽기 토큰 Vercel 등록·프로덕션 200 확인
- **1153 메모:** 세션 시작 hook이 `scheduled-jobs.md`의 표 제목(`## 주간 — 월요일 09:00 KST`·`## 월간 — 매월 1일 09:00 KST`)과
  "상태" 행을 정규식으로 읽는다. 등록 시 시각·요일·표 구조를 바꾸면 `scripts/ticket-dashboard.mjs` 파서도 함께 고치고
  `node scripts/ticket-dashboard.test.mjs`를 다시 돌린다. 켤 때는 "상태" 값을 정확히 `켜짐`으로 바꾼다
