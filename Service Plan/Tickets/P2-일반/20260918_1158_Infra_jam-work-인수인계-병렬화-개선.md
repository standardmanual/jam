# [Infra] jam-work 인수인계·병렬화 개선

## 핵심 요약
- 요구사항: 에이전트 간 인수인계를 구조화하고, 민지 점검을 유형별로 줄이고, 민지와 채원②를 동시에 돌리고, 재작업이 이전 브랜치에서 이어지게 한다.
- 구현 계획: `jam-work.js`와 아현·민지 정의를 고친다. 1148(파이프라인 정비)이 머지된 뒤 진행한다.
- 관련 파일: `.claude/workflows/jam-work.js`, `.claude/agents/jam-developer.md`, `.claude/agents/conservative-reviewer.md`, `.claude/agents/jam-designer.md`, `.claude/skills/jam-work/SKILL.md`
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 20260918_1148 (같은 파일, 토큰 측정 기능이 있어야 개선 효과를 잴 수 있음)
- 경로: ③ 표준 (infra 유형이라 채원 없이 아현→민지)

## 배경 / 문제 정의
1차 티켓 실행 전에 에이전트 역할과 워크플로를 토큰·시간·업무 효율·연계 효율 관점으로 검토했다(2026-09-18, 상위 티켓 세션). 1148이 다루지 않는 빈틈 4가지가 확인됐다.

## 상세 요구사항

### 서비스/코드베이스 관점
- **구조화 인수인계:** 아현의 결과를 자유 문장 대신 정해진 칸(schema)으로 받는다. 지금은 워크플로가 문장에서 `status:`를 글자 검색으로 찾아 형식이 조금만 달라져도 인식에 실패한다
- **채원① 판정도 구조화:** 채원①의 `needs_approval`을 schema 필드로 받는다. 지금(1148)은 글자 검색(정규식)으로 찾아 형식이 달라지면 놓칠 수 있다 (1148 민지 발견물 ①). 관련 파일에 `.claude/agents/jam-designer.md` 추가
- **커밋 전달:** 아현이 브랜치 이름과 함께 push한 커밋 SHA와 기준 커밋(origin/staging SHA)을 넘기고, 민지·채원②는 그 두 커밋 사이의 diff만 본다. 낡은 코드를 보는 문제를 막는다. 1148의 워크트리 수정은 에이전트가 fetch 지시를 따르는지에 의존하므로, 이 SHA 대조로 구조적으로 보완한다 (1148 민지 발견물 ②)
- **민지 점검 항목 유형별 축소:** 12개 항목 중 작업 유형에 해당하는 항목만 판정하고, 나머지는 '해당 없음' 한 줄로 끝낸다 (예: 문구만 바뀐 티켓은 DB·보안 항목 생략). 유형별 항목표를 민지 정의에 둔다
- **민지·채원② 동시 실행:** 두 에이전트 모두 아현의 결과만 필요하므로 병렬로 호출한다. 민지가 FAIL이면 채원② 결과는 참고로만 쓴다
- **재작업 이어받기:** 재시도 시 아현이 새로 시작하지 않고 기존 review 브랜치를 체크아웃해 이어서 작업한다 (지금은 `retryReason`에 사람이 브랜치를 적어야 이어받는다)

## 구현 계획
1148이 추가한 토큰 측정값으로 개선 전후를 비교한다. 병렬 실행은 워크플로의 `parallel()`을 쓴다.

## 완료 조건
- 채원①의 `needs_approval`이 schema 필드로 반환되고 워크플로가 글자 검색 없이 정지 여부를 판단한다
- 아현의 결과가 schema 필드(status·branch·commitSha·baseSha 등)로 반환되고, 워크플로가 글자 검색 없이 상태를 판단한다
- 민지의 판정문에 검토한 커밋 범위(baseSha..commitSha)가 적혀 있다
- `copy` 유형 티켓에서 민지가 DB·보안 항목을 '해당 없음'으로 처리한다
- `ui` 유형 티켓에서 민지와 채원②가 동시에 시작된다 (워크플로 진행 화면에서 확인)
- 재시도 호출 시 아현이 기존 review 브랜치에 커밋을 이어서 쌓는다
- 개선 후 첫 실제 UI 티켓의 토큰·시간을 1148의 측정값과 비교해 완료 기록에 남긴다 (테스트용 호출은 하지 않는다)
