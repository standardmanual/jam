# [Infra] 서브에이전트가 작업 중 쌓는 토큰 줄이기 (작업 폴더 연결·부분 읽기·티켓 지도)

## 핵심 요약
- 요구사항: 아현이 ① 격리 작업 폴더에서 `npm install` 없이 시작하고 ② 큰 파일을 통째로 읽지 않으며 ③ 티켓의 "지도"(함수 이름·줄 위치)를 보고 바로 해당 구간으로 가게 한다.
- 구현 계획:
  1. `.claude/workflows/jam-work.js` 약 202행 — 아현 프롬프트의 "첫 명령"에 `scripts/workspace-setup.sh link "$(pwd)"`를 이어 붙인다 (스크립트는 티켓 0421에서 이미 만들었으나 어디에서도 호출하지 않는다)
  2. `.claude/agents/jam-developer.md` 130행 `## Token discipline` — 구체 규칙 추가: 300줄 넘는 파일은 `grep -n`으로 위치를 찾은 뒤 `Read`의 offset/limit로 필요한 구간만 읽는다. 생성 파일(`database.generated.ts` 등)은 통째로 읽지 않는다. 같은 구간을 두 번 읽지 않는다. 티켓에 지도가 있으면 탐색(`find`) 전에 그 위치부터 연다
  3. `Service Plan/Tickets/_TEMPLATE.md` 21행 `- 관련 파일:` — "파일 경로 + 고칠 함수 이름·대략 줄 위치(지도)"를 적도록 안내 문구 추가
  4. `.claude/skills/jam-work/references/handling-rules.md` 카리나 섹션 — 두 줄 추가: (a) 티켓 생성 전 같은 주제의 열린 티켓·최근 해결 커밋을 교차 확인한다(근거: 2016 중복) (b) 티켓의 관련 파일에 지도를 채운다
- 관련 파일: 위 4개 (각 줄 위치 표기)
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)

## 배경 / 문제 정의
1307 기록 분석(2026-09-18): 에이전트 기본 비용은 민지 기준 13,305토큰으로 작다. 총 162,733토큰 중 아현이 약 118,000이며
대부분 작업 중 쌓인 컨텍스트다 — 1,295줄 `sync.ts` 통독 후 같은 파일 재독, 초반 10여 회 `find`·`grep` 탐색, 워크트리에
`node_modules`가 없어 `npm install` 실행. 컨텍스트는 행동마다 다시 읽히므로 실제 비용은 "쌓인 양 × 행동 횟수"로 커진다.
민지는 커밋 범위 고정(1158) 덕분에 44,000으로 효율적이었다.
