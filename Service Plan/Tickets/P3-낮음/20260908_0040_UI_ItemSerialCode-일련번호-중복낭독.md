# [UI] ItemSerialCode의 일련번호가 보조기술에 두 번 읽힐 소지가 있다

## 배경 / 문제 정의

티켓 [20260907_2221](20260907_2221_UI_장착개체-선택시트-ListRowCard-재구성.md) 게이트
리뷰가 실렌더 중 발견한 범위 밖 항목이다.

`design-system/components/patterns/ItemSerialCode.jsx`를 브라우저에서 렌더하면 요소의
`textContent`가 `AAAA000001000001`처럼 **숫자 부분을 두 번 담는다.** SVG 내부에 같은 숫자가
중복 렌더되는 구조로 보인다.

시각적으로는 문제가 없지만, 스크린리더가 일련번호를 두 번 읽을 소지가 있다.

**이번 변경으로 생긴 문제가 아니다.** 드랍 시트·배지 상세 히어로 등 기존 사용처에서도 동일하다.
다만 20260907_2221에서 **행의 접근 가능한 이름이 사실상 일련번호뿐**이 되면서 영향이 커졌다 —
등급칩이 `common`이라 렌더되지 않고 배지 이름도 행에서 빠졌기 때문에, 보조기술 사용자에게는
일련번호가 그 행을 식별하는 유일한 단서다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 실제로 두 번 낭독되는지 스크린리더(VoiceOver 등)로 확인한다 — `textContent` 중복이 곧 중복
  낭독을 뜻하지는 않으므로 **먼저 재현부터 한다**
- 중복이 사실이면 시각 표현용 노드에 `aria-hidden="true"`를 주고 낭독용 텍스트를 하나만 남긴다
  (컴포넌트에 이미 `sr-only` 처리가 일부 있으므로 그 구조와 맞출 것)
- MODULAR 컴포넌트이므로 Story도 함께 확인한다

### 함께 볼 것
- 20260907_2221 인터랙션 리뷰가 지적한 「행의 접근 가능한 이름」 문제와 같은 뿌리다.
  행에 `aria-label`로 "일련번호 ZPRS545679" 같은 이름을 주는 편이 나은지도 함께 판단한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
재현부터 확인한 결과, **코드 변경이 필요 없다는 결론**에 도달했다. 코드 변경 없이 조사
결과만 기록한다.

- `ItemSerialCode.jsx`의 `DigitTile`은 이미 `<span className="sr-only">{digits}</span>`(낭독용,
  숫자 1벌)과 `<div className="t-reel" aria-hidden="true">`(시각용 릴, 0-9 셀 전체)로 분리돼
  있다. 이 구조는 티켓 20260908_0040보다 앞선 티켓 20260903_1611(a011fa2e 커밋)에서
  "릴 애니메이션 접근성 회귀 해결"로 이미 반영됐다.
- 이 티켓이 지적한 `textContent`가 `AAAA000001000001`처럼 두 번 담기는 현상은 사실이다
  (`element.textContent`는 DOM 트리를 그대로 순회하므로 `aria-hidden` 여부와 무관하게
  모든 텍스트 노드를 이어붙인다). **그러나 `textContent` 중복은 곧 중복 낭독을 의미하지
  않는다** — WAI-ARIA 스펙상 `aria-hidden="true"`는 해당 요소와 자손 전체를 접근성 트리에서
  제외하며, 이는 (1) 접근 가능한 이름(accessible name) 계산과 (2) 스크린리더의 읽기 커서
  탐색(브라우즈 모드 순회) 양쪽 모두에 적용된다. 즉 `t-reel` 내부의 0-9 셀들은 스크린리더가
  아예 지나치지 않고, `sr-only` 텍스트만 한 번 읽힌다.
- 이 worktree에는 `node_modules`가 설치돼 있지 않아(격리 워크트리 특성상 `npm install` 없이
  시작) Playwright/VoiceOver로 실제 렌더 확인은 이번 세션에서 하지 못했다. 다만 위 결론은
  구현 코드 구조 자체(`aria-hidden` + `sr-only` 분리)와 ARIA 스펙 동작으로 확정적으로
  판단 가능한 범위다. **최종 확신을 위해서는 리뷰어가 staging 배포본에서 VoiceOver로 한 번
  실제 청취 확인을 권장**(아래 alerts 참고).
- 「함께 볼 것」의 행 `aria-label` 논의(20260907_2221 연장선)는 이번 조사로 범위를 좁혔다:
  일련번호 자체가 이미 스크린리더에 한 번만 정확히 읽히는 유효한 식별자이므로, 이 티켓의
  "중복 낭독" 문제는 해소된 상태로 본다. 행 전체의 접근 가능한 이름을 더 친절하게
  ("일련번호 ZPRS545679" 형태)만들지는 UX 판단의 영역이라 이 티켓 범위를 벗어난다고 보고
  손대지 않았다 — 필요하면 별도 티켓으로 분리 제안.

### 주요 의사결정 / 핵심 메모
- `textContent` 중복 ≠ 중복 낭독. `aria-hidden`은 접근성 트리 전체(이름 계산 + 순회)에서
  요소를 제외하므로, 이미 적용된 구조로 문제가 해소돼 있다고 판단.
- 행 아이덴티티(aria-label) 개선은 이 티켓 범위 밖으로 보고 보류.
