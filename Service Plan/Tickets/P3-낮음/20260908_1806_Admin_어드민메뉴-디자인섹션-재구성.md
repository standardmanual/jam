# [Admin] 어드민 메뉴 재구성 — 배지 이미지 생성 2종을 디자인 섹션으로 이동, 테마 컬러 기능 제거

## 배경 / 문제 정의
> 왜 이 작업이 필요한가. 현재 상태와 기대 상태의 차이.

사용자 요청. 어드민 사이드바 메뉴 구조를 정리한다.

메뉴 정의는 `jam-web/src/components/admin/adminNavItems.ts`의 `NAV_GROUPS`(4개 그룹: 콘텐츠
관리·정책 및 밸런스·운영 도구·디자인), 렌더링은 `AdminSidebar.tsx`가 그대로 매핑한다.

현재 상태(조사 완료):
- "체크인 배지 이미지 생성"(`/admin/badge-image`)·"액티비티 배지 이미지 생성"
  (`/admin/activity-badge-image`)은 **운영 도구(ops)** 그룹에 있다.
- **디자인(design)** 그룹에는 "테마 컬러"(`/admin/theme`) 1개 항목만 있다.

## 상세 요구사항

### 1. 배지 이미지 생성 2종을 디자인 섹션으로 이동
- `adminNavItems.ts`에서 두 항목("체크인 배지 이미지 생성"·"액티비티 배지 이미지 생성")을
  `ops` 그룹에서 `design` 그룹으로 옮긴다. 라우트(`/admin/badge-image`,
  `/admin/activity-badge-image`)·아이콘·라벨은 그대로 유지한다(메뉴 위치만 이동).

### 2. 디자인 섹션의 테마 컬러 기능 제거
> ⚠️ **조사 결과 확인 필요**: "테마 컬러"(`/admin/theme`, `ThemeManager.tsx`)는 죽은 화면이
> 아니라 실제로 서비스에 적용되는 기능이다. `theme_presets` 테이블의 활성 프리셋을
> `getActiveThemeColors()`(`jam-web/src/lib/theme/get-active-preset.ts`)가 읽어 루트 레이아웃
> (`jam-web/src/app/layout.tsx:37`)에서 서비스 전체 메인/서브 컬러에 반영한다. **제거하면
> 서비스 색상을 관리자가 바꿀 수단이 사라지고, 현재 활성 프리셋 색상으로 고정되거나(코드에서
> 기본값을 하드코딩) 별도 대체 수단이 필요해진다.** 구현 전 아래 중 어느 방향인지 확인받는다.
>
> 1. **메뉴만 숨기고 기능은 남긴다** — `/admin/theme` 라우트·API·DB는 그대로 두고 사이드바
>    메뉴 항목만 제거한다. URL을 직접 알면 여전히 접근 가능.
> 2. **완전히 제거한다** — 메뉴·페이지(`app/admin/theme/`)·API(`api/admin/theme-presets/`)를
>    전부 삭제하고, `getActiveThemeColors()`/`layout.tsx`는 현재 활성 프리셋의 색상값을
>    하드코딩된 기본값으로 대체한다. `theme_presets` 테이블은 삭제하지 않고 남겨둔다(데이터
>    손실 방지, 필요시 향후 복원 가능).
>
> **결정(2026-09-08, 사용자): 2안 채택 — 완전히 제거한다.** 메뉴·페이지(`app/admin/theme/`)·
> API(`api/admin/theme-presets/`)를 전부 삭제하고, `getActiveThemeColors()`/`layout.tsx`는
> 제거 시점의 활성 프리셋 색상값을 하드코딩된 기본값으로 대체한다. `theme_presets` 테이블은
> 삭제하지 않고 남겨둔다.

## 구현 계획
> 어떻게 구현할지. 접근 방법, 영향 범위, 주요 변경 포인트.

1. 사용자에게 "테마 컬러" 제거 방식(위 1안/2안)을 확인받는다.
2. `adminNavItems.ts`에서 배지 이미지 생성 2종을 `design` 그룹으로 이동.
3. 확인받은 방식대로 테마 컬러 메뉴·기능을 처리한다.
4. 1안을 택했다면 라우트가 그대로 살아있으므로 회귀 확인 불필요. 2안을 택했다면
   `layout.tsx`에 반영되는 기본 색상값이 제거 시점의 활성 프리셋과 동일한지 확인하고,
   `/admin/theme`·`/api/admin/theme-presets/*` 접근 시 404가 정상적으로 뜨는지 확인한다.

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- 테마 컬러 제거는 본 티켓에 이미 기록된 2안(완전 제거) 결정을 그대로 따랐다.
- `theme_presets` 테이블·관련 타입(`ThemePresetRow`, `activate_theme_preset`)은 데이터 손실
  방지를 위해 보존만 하고 코드에서 참조를 끊었다(지시사항 그대로).
- 4개 그룹 전체의 항목 순서·레이블을 재배열하는 작업은 이 티켓 문서 어디에도 명시되어 있지
  않아(상세요구사항 1·2번 항목만 존재, "목표 구조" 절 없음) 수행하지 않았다 — alerts 참조.
