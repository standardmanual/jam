# [Service] trail_running 활동은 교통수단 구간 감지 대상에서 빠져 있음

## 배경 / 문제 정의
> 왜 이 작업이 필요한가. 현재 상태와 기대 상태의 차이.

티켓 [20260909_1012](../P1-중요/20260909_1012_Service_교통수단구간감지-거리시간재산정.md)
게이트 리뷰에서 범위 밖으로 지적된 사항이다.

`jamActivityType`이 `running`인 활동은 이번 티켓으로 교통수단 구간 감지 대상이 됐지만,
`trail_running`은 `THRESHOLD_FIELD_BY_ACTIVITY_TYPE`(`jam-web/src/lib/strava/transitSegment.ts`)에
등록되지 않아 대상에서 빠져 있다. 티켓 20260909_1012의 요구사항 문구가 "러닝"으로만 명시돼
있어 범위 밖 해석이 합리적이었지만, trail_running 중에도 대중교통 혼입이 발생할 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `trail_running`에 어떤 임계값을 적용할지 판단한다. 일반 러닝(27km/h)과 같은 값을 쓸지,
  트레일 특성(내리막 구간에서 순간 속도가 더 튈 수 있음)을 감안해 별도 값을 둘지 결정한다.
- `THRESHOLD_FIELD_BY_ACTIVITY_TYPE`에 `trail_running` 항목을 추가한다.

### UI/UX 관점 (해당 시)
- 별도 임계값을 둔다면 `abusing_policy` 어드민 화면에 필드를 추가한다. 러닝과 같은 값을
  재사용한다면 UI 변경은 불필요하다.

### 컨텐츠 관점 (해당 시)
- 해당 없음.

## 구현 계획
> 어떻게 구현할지. 접근 방법, 영향 범위, 주요 변경 포인트.

1. trail_running의 실제 최고속도 분포를 실측하거나(가능하면) 일반 러닝과 같은 임계값을
   우선 적용한 뒤 필요시 조정한다.
2. `transitSegment.ts`의 `THRESHOLD_FIELD_BY_ACTIVITY_TYPE`에 항목을 추가한다.
3. 회귀 테스트를 `transitSegment.test.ts`에 추가한다.
