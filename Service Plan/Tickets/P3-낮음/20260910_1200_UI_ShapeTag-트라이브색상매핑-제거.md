# [UI] ShapeTag의 트라이브 색상 매핑 제거

> **착수 시 방향 전환** — 처음에는 "TRIBE_COLORS를 실제 트라이브 10개로 재매핑"으로 열었으나,
> 조사 결과 재매핑이 아니라 **기능 제거**가 맞다고 판단해 사용자 승인을 받고 방향을 바꿨다.
> 판단 근거는 아래 「재매핑 대신 제거를 택한 이유」에 있다.

## 배경 / 문제 정의

`jam-web/design-system/components/cards/ShapeTag.jsx`의 `TRIBE_COLORS` 매핑 테이블이
아직 stub 상태다. 키가 `fire`·`water`·`nature`·`shadow`·`light`·`storm`·`earth`·`void`
8개 가상 이름으로 되어 있는데, 실제 트라이브는 `Specs/Content/TRIBES.md`에 정의된
한글 이름 10개(아날로그 수집가·미스터리 헌터 등)다. 키가 하나도 겹치지 않아 지금은
어떤 트라이브 이름을 넘겨도 전부 `colorIndex=0` 폴백으로 떨어진다.

원래 DS-018(`Tickets/Moduler/018_P2_IMPROVE_shapetag-faction-mapping.md`)의 잔여
이슈로 "FACTIONS.md 확정 후 재매핑 필요"라고 기록돼 있었으나, 그 티켓은 CLOSED이고
가리키던 `FACTIONS.md`·`FACTION_COLORS`는 티켓 20260910_1129의 용어 변경으로
`TRIBES.md`·`TRIBE_COLORS`가 되었다. 지금은 존재하지 않는 이름을 가리키는 상태라
후속으로 집는 사람이 찾지 못한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `TRIBES.md`에 확정된 트라이브 10개의 정식 이름을 키로 `TRIBE_COLORS`를 다시 채운다.
- 토큰은 `--color-tag-1` ~ `--color-tag-N` 범위에서 고른다. 트라이브가 10개인데
  기존 태그 토큰이 몇 개인지 먼저 확인해야 한다 — 부족하면 토큰 확장 여부부터 판단한다.
- 알 수 없는 이름이 들어오면 `colorIndex=0`으로 폴백하는 기존 동작은 유지한다.
- `ShapeTag.stories.tsx`의 예시 목록도 실제 트라이브 이름으로 맞춘다.

### 영향 범위

`ShapeTag`는 `ds-connection-scope.md` 기준 **미도입 8종**이다. `grep -rn "ShapeTag"
jam-web/src` 결과가 0건으로 서비스 화면에서 쓰이지 않으므로, **이 작업은 서비스에
영향을 주지 않고 Storybook 표시만 정확해진다.** 우선순위를 P3으로 둔 이유다.

## 구현 계획

1. `Specs/Content/TRIBES.md`에서 트라이브 10개 정식 이름을 확인한다
2. `design-system/tokens/colors.*.css`에서 사용 가능한 `--color-tag-*` 개수를 센다
3. 토큰이 10개에 미달하면 확장할지, 색을 재사용할지 판단해 티켓에 기록한다
4. `TRIBE_COLORS`·`ShapeTag.stories.tsx`를 갱신하고 로컬 Storybook(`npm run storybook`)에서 확인한다

## 완료 기록

### 재매핑 대신 제거를 택한 이유

착수 후 조사에서 재매핑을 막는 사실 세 가지가 나왔다.

1. **토큰이 모자란다.** `--color-tag-*`는 8개인데 트라이브는 10개다. 재매핑하려면 토큰을
   2개 늘리거나 색을 2쌍 중복시켜야 하는데, 중복시키면 태그 색으로 트라이브를 구분한다는
   목적 자체가 깨진다.
2. **남은 토큰 중 3개가 등급 색이다.** `tag-3`=Epic, `tag-4`=Rare, `tag-5`=Mystic으로
   희귀도 토큰을 그대로 참조한다. 트라이브 태그에 이 색을 쓰면 유저가 등급으로 오인한다.
   실질적으로 쓸 수 있는 중립 색은 5개뿐이다.
3. **`ShapeTag`는 서비스에서 쓰이지 않는다.** `ds-connection-scope.md`의 **미도입 8종**이고
   `grep -rn "ShapeTag" jam-web/src`가 0건이다. 도입 시점도 정해지지 않았다.

즉 지금 색을 확정하려면 토큰 확장이라는 디자인 결정을 해야 하는데, 정작 그 결과를 쓸
화면이 없다. 실제 도입 시점에 화면 맥락을 보고 정하는 편이 나은 판단이라고 보아
사용자 승인을 받아 매핑 기능 자체를 걷어냈다. 색이 필요해지면 그때 `colorIndex`나
`color` prop으로 넘기면 되고, 매핑 테이블이 다시 필요하면 그 시점에 다시 만든다.

원래 이 매핑은 DS-018(`Tickets/Moduler/018_P2_IMPROVE_shapetag-faction-mapping.md`)이
stub으로 넣어두고 "FACTIONS.md 확정 후 재매핑"을 잔여 이슈로 남긴 것이었다. 그 잔여
이슈는 이 티켓으로 종결된다.

### 구현 내용 요약

`ShapeTag`에서 트라이브 → 색상 매핑을 제거하고 `colorIndex` / `color` 방식만 남겼다.

1. `ShapeTag.jsx` — `TRIBE_COLORS` 상수와 `tribe` prop을 삭제하고, 배경색 결정을
   `color ?? TAG_COLORS[colorIndex % TAG_COLORS.length]` 한 줄로 단순화했다.
2. `ShapeTag.d.ts` — `tribe?: string` 및 stub 매핑을 설명하던 JSDoc을 삭제했다.
3. `ShapeTag.stories.tsx` — `Tribes` 스토리와, 그 스토리에서만 쓰이던 `TRIBES` 상수
   (`fire`·`water` 등 실재하지 않는 8개 이름)를 삭제했다.

### 주요 의사결정 / 핵심 메모

- **토큰을 늘리지 않았다.** 토큰은 `ds-connection-scope.md` 기준 "서비스에 즉시 반영"
  부류라, 쓰지도 않는 컴포넌트를 위해 서비스 전역에 영향을 주는 변경을 하는 것은

  이번 제거로 깨지는 호출부가 없다.
