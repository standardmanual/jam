# [API] INVALID_FACTION 에러 코드를 트라이브 용어로 정리

## 배경 / 문제 정의

티켓 20260910_1129에서 서비스 용어를 트라이브로 통일했으나, 온보딩 API의 에러 코드
문자열 `INVALID_FACTION` 2건만 옛 용어로 남았다.

- 서버: `jam-web/src/app/api/onboarding/complete/route.ts`
- 클라이언트: `jam-web/src/app/(main)/onboarding/page.tsx`

**의도적으로 남긴 것이다.** 이 코드 문자열은 서버가 내려주고 클라이언트가 비교하는
계약이라, 한쪽만 배포되는 순간 온보딩에서 트라이브 검증 에러가 잡히지 않는다. 배포
시차 동안 유저가 실제로 겪을 수 있는 문제라 용어 통일보다 안전을 택했다.

다만 지금 상태로 두면 나중에 "왜 이것만 안 바뀌었지"라는 의문이 반복되고, 정리할 수
있는 시점을 놓치기 쉽다.

## 상세 요구사항

- 서버와 클라이언트를 **같은 배포에 함께** 올릴 수 있는 시점에 `INVALID_FACTION` →
  `INVALID_TRIBE`로 바꾼다. 두 파일을 한 커밋·한 배포로 처리하는 것이 조건이다.
- 이 에러 코드는 유저에게 그대로 노출되지 않는다. 화면 문구는 이미 "이 트라이브는
  지금 선택할 수 없어요"로 트라이브 용어를 쓰고 있으므로 UX 영향은 없다.
- 함께 확인할 것: 같은 파일의 `ALREADY_SET` 등 다른 에러 코드에는 faction 어휘가
  없는지 점검한다.

## 구현 계획

1. `grep -rn "INVALID_FACTION" jam-web/src`로 잔여 지점을 전수 확인한다
2. 서버·클라이언트를 한 커밋으로 함께 수정한다
3. 온보딩에서 비활성 트라이브를 제출하는 경로를 재현해 400 응답과 화면 문구를 확인한다
