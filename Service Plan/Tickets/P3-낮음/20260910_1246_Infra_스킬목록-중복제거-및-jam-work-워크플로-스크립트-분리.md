# [Infra] CLAUDE.md 스킬 목록 중복 제거 및 jam-work 워크플로 스크립트 분리

## 배경 / 문제 정의

세션마다 컨텍스트에 실리는 스킬 관련 텍스트에 중복과 불필요한 분량이 누적되어 있다.
2026-09-10에 321개 세션 로그를 집계해 실사용 현황과 컨텍스트 비용을 실측했다.

**측정 1 — 스킬 실사용 빈도 (321세션 누적 `Skill` 도구 호출)**

| 스킬 | 호출 횟수 |
|---|---|
| `jam-work` | 162 |
| `jam-ship` | 75 |
| `jam-docs` | 16 |
| `jam-img` / `jam-design` / `jam-sync` / `jam-ds` | 8 / 3 / 2 / 1 |
| gstack 73종 전체 | **`browse` 1회, 나머지 72종은 0회** |

**측정 2 — 컨텐츠 중복**

gstack 스킬 이름 42종을 나열한 목록이 세 곳에 중복 존재한다.

- 전역 `~/.claude/CLAUDE.md` 1회 (파일 전체 1,163바이트 중 상당 부분)
- 프로젝트 `CLAUDE.md` 2회 (상단 "gstack" 절, 하단 "gstack" 절)

스킬 시스템이 사용 가능한 스킬 목록과 각 description을 시스템 프롬프트에 이미 주입하므로,
이 세 목록은 같은 정보를 네 번째로 반복하는 순수한 낭비다. 게다가 gstack 스킬을 추가·제거할
때 세 파일을 모두 손봐야 해서 실제로 낡은 상태로 방치되기 쉽다.

**측정 3 — jam-work SKILL.md 분량**

`.claude/skills/jam-work/SKILL.md`는 20,564바이트(292줄)이며, 이 중 2단계 "Workflow 호출"의
자바스크립트 스크립트가 약 7KB를 차지한다. 이 파일은 `jam-work` 호출 때마다(누적 162회)
전체가 컨텍스트에 로드되지만, 스크립트 본문은 오케스트레이터가 읽어서 이해해야 할 내용이
아니라 Workflow 도구에 그대로 넘길 코드다. `scriptPath`로 분리하면 호출당 약 2,000토큰이
줄고, 스크립트를 파일로 편집한 뒤 `resumeFromRunId`와 함께 재실행하기도 쉬워진다.

## 상세 요구사항

### 서비스/코드베이스 관점

**① CLAUDE.md 스킬 목록 중복 제거**

- 프로젝트 `CLAUDE.md`의 gstack 스킬 이름 나열 2곳을 제거한다. "웹 브라우징은 항상 gstack의
  `/browse` 스킬을 사용한다. `mcp__claude-in-chrome__*` 도구는 절대 사용하지 않는다"라는
  **동작 규칙은 반드시 남긴다** — 이것은 목록이 아니라 정책이며 시스템 프롬프트가 대체해
  주지 않는다.
- 프로젝트 `CLAUDE.md`에 gstack 절이 상단·하단 두 번 나오는데, 내용이 거의 같으므로 하나로
  합친다. "gstack 산출물은 jam-docs 규칙으로 저장" 절의 내용은 정책이므로 전량 보존한다.
- 전역 `~/.claude/CLAUDE.md`의 gstack 스킬 이름 나열도 같은 기준으로 제거한다. 단
  **전역 파일은 이 저장소 밖이므로 git 이력에 남지 않는다** — 변경 전 원본을 티켓 완료
  기록에 인용해 두고, 변경 사실을 사용자에게 명시적으로 보고한다.
- 목록을 지우는 대신 "사용 가능한 gstack 스킬은 세션 시작 시 스킬 목록으로 주입된다"는
  한 줄 안내로 대체해, 목록이 사라진 이유를 다음 세션이 알 수 있게 한다.

**② jam-work 워크플로 스크립트 분리**

- `.claude/workflows/jam-work.js`를 새로 만들고, `SKILL.md` 2단계의 자바스크립트 블록
  전체(`export const meta`부터 `return { ... }`까지)를 **한 글자도 바꾸지 않고** 옮긴다.
  주석도 전부 보존한다 — 각 주석은 실제 사고 이력(티켓 20260906_0110의 워크트리 격리 사유,
  Vercel 빌드 비용, `diffLineCount` 임계값 도입 경위)을 담고 있어 이 티켓의 범위 밖이다.
- `SKILL.md` 2단계는 스크립트 본문 대신 아래 내용만 남긴다.
  - 호출 방법: `Workflow` 도구를 `scriptPath: '.claude/workflows/jam-work.js'`로 호출
  - 주입할 변수: `ticketPath`·`userRequest`·`workType`·`reuseDecision`·`retryReason`
  - `docs`·`research` 유형은 이 단계를 건너뛴다는 기존 규칙
- **호출 방식은 구현자가 실측으로 확정한다.** `Workflow` 도구는 `scriptPath`(디스크상 경로)와
  `name`(`.claude/workflows/`에 있는 사전 정의 워크플로) 두 경로를 모두 문서화하고 있으나,
  프로젝트 상대 경로가 실제로 해석되는지, `args`로 변수를 주입하는 형태가 맞는지는 확인이
  필요하다. `.claude/skills/workflow-authoring`(또는 `workflow-authoring` 스킬)을 읽고
  확정한 뒤, 확정한 근거를 완료 기록에 남긴다.
- 변수 주입 방식이 바뀌면(예: 스크립트 상단에서 `args`를 구조 분해) 그 변경은 허용한다.
  단 **파이프라인 동작(phase 구성·분기 조건·에이전트 타입·프롬프트 문구)은 일절 바꾸지
  않는다** — 이 티켓은 순수한 구조 분리이지 파이프라인 개선이 아니다.

## 구현 계획

1. `.claude/workflows/` 디렉터리를 만든다 (현재 없음).
2. `workflow-authoring` 스킬을 읽어 `scriptPath`/`name` 호출 규약과 `args` 주입 방식을 확인한다.
3. `jam-work.js`에 스크립트를 그대로 옮기고, 확인한 규약에 맞게 변수 수신부만 조정한다.
4. `SKILL.md` 2단계를 호출 안내로 축약한다. 나머지 절(0·1·1.5·1.6·3·4·참고)은 손대지 않는다.
5. 프로젝트 `CLAUDE.md`의 gstack 절 2개를 하나로 합치고 스킬 이름 나열을 제거한다.
6. 전역 `~/.claude/CLAUDE.md`도 같은 기준으로 정리하되, 원본을 완료 기록에 남긴다.
7. 축약 후 `SKILL.md` 바이트 수와 `CLAUDE.md` 바이트 수를 재서 감소량을 완료 기록에 적는다.

**영향 범위**: `.claude/` 아래 설정·스킬 파일과 저장소 밖 전역 `CLAUDE.md`. `jam-web/` 무변경이므로
Vercel 빌드는 발생하지 않는다.

**리스크**: `scriptPath` 호출이 기대대로 동작하지 않으면 `jam-work` 파이프라인 전체가 멈춘다.
이 경우 스크립트를 `SKILL.md`로 되돌리고(①만 적용) 사유를 보고한다 — 억지로 우회하지 않는다.

**검증 방법**: 구조 분리이므로 실제 파이프라인을 한 번 돌려 보는 것이 유일한 확증이다. 다만
검증용으로 파이프라인을 도는 것 자체가 서브에이전트 다섯 개를 소모하므로, 게이트 리뷰
단계에서 **정적 검증**(스크립트 내용이 원본과 동일한지 diff, 호출 규약이 문서와 맞는지)까지만
하고 실동작 확인은 다음 `jam-work` 호출에 맡긴다.

### 호출 규약 확정 근거

`workflow-authoring` 스킬은 이 환경(`~/.claude/skills/`, 프로젝트 `.claude/skills/`)에 존재하지
않았다. 대신 설치된 Claude Code 패키지의 공식 타입 선언
`/opt/homebrew/lib/node_modules/@anthropic-ai/claude-code/sdk-tools.d.ts`의 `WorkflowInput`
정의를 근거로 확정했다.

- `name`: "Name of a predefined workflow (built-in or from `.claude/workflows/`)" —
  `.claude/workflows/`에 둔 스크립트를 가리키는 **명시적으로 문서화된 경로**다.
- `scriptPath`: "Path to a workflow script file on disk. … Takes precedence over `script` and
  `name`." — 동작하지만 문서상 용도는 세션 디렉터리에 영속화된 스크립트를 재실행하는 것이고,
  프로젝트 상대 경로 해석 여부는 명시돼 있지 않다.
- `args`: "Optional input value exposed to the script as the global `args`, verbatim." —
  스크립트에서 전역 `args`로 받는다. 배열·객체는 문자열화하지 말고 JSON 값으로 넘길 것.

따라서 `SKILL.md`에는 **`name: 'jam-work'` + `args`** 를 1순위 호출로 적고, 티켓이 전제한
`scriptPath: '.claude/workflows/jam-work.js'`는 동등한 대안으로 병기했다(우선순위 관계 포함).
이 세션에서는 `Workflow` 도구를 직접 호출할 수 없어 실행 확증은 하지 못했다 — 티켓의
검증 방침(정적 검증까지만, 실동작은 다음 `jam-work` 호출에서 확인)과 일치한다.
