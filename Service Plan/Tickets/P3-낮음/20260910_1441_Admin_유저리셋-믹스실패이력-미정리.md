# [Admin] 유저 리셋이 믹스 실패 이력을 정리하지 않는다

## 배경 / 문제 정의

`POST /api/admin/users/[id]/reset`이 `user_combine_fail_logs`를 삭제하지 않는다. 리셋 후에도
어드민 유저 상세 화면에 이전 믹스 실패 이력이 그대로 남아 "초기 상태로 되돌린다"는 리셋의
의미와 어긋난다.

기존에도 `user_combine_state`를 지우지 않았으므로 새로 생긴 문제는 아니지만, 실패 이력이
시도 일시·투입 재료 단위로 남게 되면서 잔존 데이터가 눈에 보이게 되었다.

티켓 `20260910_1408`(믹스 v3 재설계) 게이트 리뷰에서 범위 밖 발견물로 확인되었다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `POST /api/admin/users/[id]/reset`이 `user_combine_fail_logs`의 해당 유저 행을 삭제하도록
  한다.
- 의도적으로 보존하는 편이 맞다고 판단되면, 그 근거를 코드 주석과 이 티켓에 남기고 CLOSED
  처리한다. 어느 쪽이든 판단을 문서로 남기는 것이 목적이다.

## 구현 계획

리셋 라우트가 이미 지우는 테이블 목록을 확인하고 같은 방식으로 한 건 추가한다. 유저 강제
완전 삭제는 FK `ON DELETE CASCADE`로 이미 정리되므로 손댈 필요가 없다.
