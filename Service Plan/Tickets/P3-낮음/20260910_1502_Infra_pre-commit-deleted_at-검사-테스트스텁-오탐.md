# [Infra] pre-commit의 deleted_at 필터 검사가 테스트 스텁을 오탐한다

## 배경 / 문제 정의

`.githooks/pre-commit`은 `.from('badges')` 조회에 `deleted_at` 필터가 빠졌는지 검사한다.
이 검사가 테스트 파일의 Supabase 클라이언트 스텁까지 훑어 경고를 낸다. 스텁은 실제 조회가
아니므로 필터가 있을 수 없다.

티켓 `20260910_1408` 구현 중 신규 테스트 파일에서 실제로 오탐이 발생했다. 이번 건은
무해했지만, 같은 경고가 반복되면 개발자가 경고를 습관적으로 넘기게 되어 진짜 필터 누락을
흘려보낼 위험이 생긴다. 훅의 가치는 경고가 드물 때만 유지된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `.githooks/pre-commit`의 `deleted_at` 검사에서 `__tests__/` 경로와 `*.test.ts`·`*.test.tsx`
  파일을 제외한다.
- 제외 규칙을 넣은 뒤 기존 커밋 이력에서 이 검사가 잡아냈어야 할 진짜 누락이 새 규칙에
  걸러지지 않는지 확인한다.

## 구현 계획

훅 스크립트의 대상 파일 목록 산출 부분에 경로 필터를 추가한다.
