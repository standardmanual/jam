# [Admin] 배지 폼의 네이티브 버튼·입력을 shadcn 컴포넌트로 바꿀지 검토

## 배경 / 문제 정의

티켓 [20260911_0901](../P2-일반/20260911_0901_Admin_배지생성조회수정-아티팩트기준리뉴얼.md) 게이트
리뷰에서 발견된 범위 밖 이슈.

어드민 UI는 shadcn 컴포넌트(`components/admin/ui/*`)를 표준으로 쓰는 것이 방침이다. 그런데
리뉴얼로 배지 폼에 네이티브 요소가 늘었다.

- 네이티브 `<button>`: 분류 태그, 세그먼트 컨트롤(배지 타입·발급 방식)
- 네이티브 `<input>`: 필드 찾기, 계열 키 읽기 전용 칸

드롭다운 다크모드 문제를 일으켰던 `<select>`는 없다. 네이티브 입력 일부는 `cn`이 className을
병합하지 못해서(티켓 20260911_1019 P2) shadcn `Input`의 여백을 덮을 수 없기 때문에 직접 칠한
것이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 세그먼트 컨트롤은 `components/admin/ui/tabs.tsx`나 토글 그룹 패턴으로 바꿀 수 있는지 검토한다.
  배경 방식 선택(`BackgroundGeneratorPreview`)이 이미 `Tabs`를 쓰고 있다.
- 필드 찾기·계열 키 입력은 `cn` 문제(20260911_1019 P2)가 해결되면 shadcn `Input`으로 되돌린다.
- 분류 태그(`aria-pressed` 토글 버튼)는 shadcn에 대응 컴포넌트가 없으면 현재 구현을 유지하고
  근거를 남긴다.

## 구현 계획

`cn` 티켓(20260911_1019 P2)을 먼저 처리한 뒤 진행한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
세 항목을 검토하고 코드에 근거를 남겼다. 코드 변경은 주석 추가뿐이고, 렌더 결과는 바뀌지 않는다.

1. **세그먼트 컨트롤(배지 타입·발급 방식) → Tabs 전환**: 유지로 결론.
   `BackgroundGeneratorPreview`의 Tabs는 선택값이 그 자리 패널 하나를 통째로 바꾸는 구조라
   tab/tabpanel 의미가 맞았다. 반면 `BadgeForm`의 배지 타입(`type`)은 이 섹션 뒤로도 폼 전체에
   흩어진 조건부 렌더링(여러 곳의 `type === 'activity' | 'item' | 'checkin'` 분기)을 좌우해서
   값 하나가 여러 TabsContent에 걸치는 모양이 되어 tab/tabpanel로 표현할 수 없다. 전체를 하나의
   Tabs 트리로 감싸려면 폼 구조 자체를 새로 짜야 해 이 티켓 범위를 넘어선다.
   `BadgeConditionSection`의 발급 방식(자동/미션)도 아래 조건 그룹을 다른 패널로 바꾸지 않고
   경고 배너 + 흐림 처리(`opacity-50`)만 하므로 같은 이유로 Tabs가 맞지 않는다.
   두 곳 모두 현재 구현(버튼 + `role="radiogroup"`)을 유지하고, 근거를 인라인 주석으로 남겼다.
2. **필드 찾기·계열 키 입력 → shadcn `Input` 복귀**: 보류. 선행 조건인 `cn` 티켓
   (20260911_1019 P2, `cn`이 `tailwind-merge`를 쓰지 않아 className 덮어쓰기가 불안정한 문제)이
   아직 `OPEN`이라 되돌릴 수 없다. `cn` 티켓 해결 후 재작업이 필요하다.
3. **분류 태그(`aria-pressed` 토글 버튼)**: 유지. `components/admin/ui/`에 toggle-group·
   radio-group에 대응하는 컴포넌트가 없음을 확인했다(`ls` 결과: accordion, alert(-dialog),
   badge, button, card, checkbox, command, dialog, dropdown-menu, input, popover, select,
   separator, sheet, sidebar, skeleton, switch, table, tabs, textarea, tooltip — 없음).
   현재 구현을 유지한다.
