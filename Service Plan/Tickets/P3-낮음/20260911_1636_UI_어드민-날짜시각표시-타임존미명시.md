# [UI] 어드민 투데이·배지 화면의 날짜·시각 표시가 타임존을 명시하지 않음

## 배경 / 문제 정의

티켓 [20260911_1454](../P2-일반/20260911_1454_Admin_투데이컨텐츠-화면리뉴얼.md) 게이트
리뷰 중 발견됨(범위 밖). `TodayCardDetail.tsx`의 날짜·시각 포맷 함수, `TodayCardForm.tsx`의
`toLocalInputValue`(예전 `TodayCardList.tsx`에서 그대로 옮겨온 로직), `TodayCardTable.tsx`의
`toLocaleDateString('ko-KR')` 호출이 모두 `timeZone`을 명시하지 않고 실행 환경의 로컬
타임존에 의존한다.

이 프로젝트는 이미 `LocalDate.tsx`·`today-calendar.ts` 등에서 `timeZone: 'Asia/Seoul'`을
명시하는 패턴을 쓰고 있는데, 어드민 투데이·배지 쪽 화면은 이 티켓 이전부터 그 패턴을
따르지 않고 있었다 — 이번 리뉴얼이 새로 만든 문제가 아니라 기존 코드를 그대로 옮기거나
동일한 관례를 반복한 것이다.

이 컴포넌트들은 모두 `'use client'`라, 서버(보통 UTC로 도는 Vercel 서버리스)에서 먼저
렌더된 값과 브라우저(KST 로컬)에서 hydration될 때의 값이 달라질 수 있다 — 시각이 9시간
어긋나 보이거나, React hydration 경고가 날 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 어드민 투데이·배지 화면에서 날짜·시각을 표시하는 지점을 모두 찾아, `Intl.DateTimeFormat`
  또는 기존 유틸에 `timeZone: 'Asia/Seoul'`을 명시하도록 통일한다.
- 이미 있는 `LocalDate.tsx`·`today-calendar.ts`의 타임존 처리 패턴을 그대로 따를지, 아니면
  어드민 전용 공통 포맷 유틸을 새로 만들지는 구현 시점에 판단한다.

## 구현 계획
`TodayCardDetail.tsx`·`TodayCardForm.tsx`의 날짜 조립 로직, `TodayCardTable.tsx`의
`toLocaleDateString('ko-KR')` 호출에 `timeZone: 'Asia/Seoul'`을 명시한다. 같은 게터 조립
패턴이 배지 화면(`BadgeDetail.tsx`·`BadgeCard.tsx`·`BadgesTable.tsx`)에도 있어 함께 고친다
(티켓 제목이 "투데이·배지 화면"을 명시).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `src/lib/admin/kst-format.ts` 신규 — `LocalDate.tsx`·`today-calendar.ts`와 동일하게
  `KST_OFFSET_MS`를 더한 뒤 UTC 필드를 읽는 방식으로 `formatKstYmdHm`·`toKstLocalInputValue`·
  `formatKstYmd` 세 함수를 제공한다. `toLocaleString`의 `timeZone` 옵션은 완성된 문자열에만
  적용되고 `getFullYear()` 같은 개별 게터는 대체하지 못해, 기존 게터 조립 패턴을 그대로 두고
  값만 KST 오프셋 보정된 `Date`에서 읽도록 바꿨다.
- `TodayCardDetail.tsx`의 `formatYmdHm` → `formatKstYmdHm`로 교체.
- `TodayCardForm.tsx`의 `toLocalInputValue` → `toKstLocalInputValue`로 교체(시작·종료 일시
  `datetime-local` 값의 초기 표시만 대상 — 저장 시 `new Date(startsAt).toISOString()`으로
  되돌리는 부분은 브라우저 로컬 타임존을 KST로 가정하는 기존 로직 그대로 뒀다. 이 티켓은
  표시 포맷 통일이 범위이고, 이 왕복 변환 자체를 바꾸는 건 범위 밖이라 alerts로 남긴다).
- `TodayCardTable.tsx`의 `toLocaleDateString('ko-KR')` 두 곳에 `timeZone: 'Asia/Seoul'` 추가.
- `BadgeDetail.tsx`·`BadgeCard.tsx`·`BadgesTable.tsx`의 동일한 `formatYmd` 로컬 함수를 모두
  제거하고 `formatKstYmd`로 교체.
- `VirtualActivityForm.tsx`·`PoiDetail.tsx`·`BulkToolManager.tsx`에도 유사한 미지정 타임존
  포맷이 있으나 티켓 제목이 "투데이·배지 화면"으로 한정하고 있어 범위 밖으로 남겼다(alerts 참고).

### 주요 의사결정 / 핵심 메모
- `toLocaleString(..., { timeZone })` 옵션 방식 대신 `KST_OFFSET_MS` 오프셋 보정 방식을
  택했다 — 기존 코드가 `getFullYear()`·`getMonth()` 등 개별 게터로 문자열을 조립하고 있어,
  `toLocaleString` 옵션 방식으로 바꾸려면 조립 로직 전체를 다시 써야 한다. 오프셋 보정은
  기존 조립 로직을 그대로 두고 입력 `Date`만 보정해 변경 범위를 최소화한다(이미
  `today-calendar.ts`가 쓰는 검증된 패턴).
- 배지 화면 3개 파일을 티켓 범위에 포함했다 — 티켓 제목이 "어드민 투데이·배지 화면"을
  명시하고, 상세 요구사항도 "어드민 투데이·배지 화면에서 날짜·시각을 표시하는 지점을 모두
  찾아"라고 돼 있어 배지 화면도 명시적 범위로 판단했다.

### 잔여 이슈
- `TodayCardForm.tsx`의 저장 시 `new Date(startsAt).toISOString()` 왕복 변환은 여전히
  브라우저의 시스템 타임존이 KST라고 가정한다(이번 티켓 범위 밖, alerts 참고).
- `VirtualActivityForm.tsx`·`PoiDetail.tsx`·`BulkToolManager.tsx`에도 동일한 미지정 타임존
  포맷 패턴이 남아 있다(alerts 참고, 필요시 별도 티켓).
