# [Admin] 드랍 제외 관리 화면 — 초과 page 파라미터 접근 시 count null로 "총 0개" 오표시

## 배경 / 문제 정의

티켓 [20260911_2235](../P2-일반/20260911_2235_Admin_드랍제외화면-전체보기500건누락.md)의
게이트 리뷰(WARN)에서 발견된 엣지 케이스.

`/admin/drop-policy/exclusions`에 페이지네이션(`.range()` + `count: 'exact'`)을 도입한
뒤, 실제 총 건수(예: 288건)보다 큰 `page` 쿼리 파라미터(예: `?page=2`, 1페이지가 500건
단위라 총 건수가 500 이하면 사실상 존재할 수 없는 페이지)로 직접 접근하면 Supabase/
PostgREST가 `.range()`의 offset이 실제 행 수를 초과했다며 416(`PGRST103`,
`Requested range not satisfiable`)을 반환하고 `count`가 `null`로 돌아온다. 코드가
`count ?? 0`으로 처리하기 때문에 실제로는 288건이 있는데도 화면에는 "총 0개"로 잘못
표시된다(배지 목록도 비어 보임).

정상 클릭 내비게이션에서는 `Pagination` 컴포넌트가 `totalPages<=1`일 때 다음 페이지
링크를 숨기므로 이 경로는 트리거되지 않는다. 북마크된 URL·공유된 링크·데이터가 줄어든
뒤(배지 소프트삭제 등) 재방문하는 경우 등 `page` 쿼리 파라미터를 직접 조작하면 재현된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `page.tsx`에서 `.range()` 조회 결과 `count`가 `null`이고 요청한 페이지가 1보다 크면,
  실제 총 건수를 다시 조회하거나(count 전용 쿼리) 1페이지로 리다이렉트하는 방식으로
  "총 0개" 오표시를 막는다.
- 이 티켓이 원래 해결하려던 문제("안내 없이 조용히 데이터가 빠지는 것")와 같은 계열의
  실패 양상이 새 코드 경로에 남아 있다는 점에 유의한다.
