# MODULAR → Storybook 구축 워크플로우

> JAM! 프로젝트 전용. ChatGPT 설계 대화를 기반으로 작성하고, 실제 프로젝트 구조에 맞게 경로·주의사항·문서 체계를 수정한 버전.

---

## 핵심 역할 정의

| 시스템 | 역할 |
|---|---|
| **MODULAR** (`jam-web/design-system/`) | 디자인 시스템 원본. Token·Component·API의 Source of Truth |
| **UX Writing Guide** (`Service Plan/Specs/UX_WRITING_GUIDELINE.md`) | 사용자 노출 언어의 Source of Truth |
| **Storybook** (`jam-web/` 내 설치) | 실제 컴포넌트의 문서·Preview·상태·탐색 환경 (UI Catalog) |
| **실제 서비스** (`jam-web/src/`) | 위 시스템이 실제로 적용되는 제품 |

```
MODULAR         → 어떻게 만들고 동작하는가
UX Writing      → 무엇이라고 표현하는가
Storybook       → 어떻게 존재하고 재사용되는가
Service         → 실제 사용처
```

---

## 5가지 절대 원칙

```
1. MODULAR이 원본이다.
2. Storybook은 MODULAR의 복제본이 아니다.
3. Storybook은 실제 컴포넌트를 직접 import해서 보여준다.
4. UX Writing Guide는 모든 사용자 노출 문구의 원본이다.
5. Storybook 구축과 디자인 시스템 개선은 분리한다.
```

## 주의사항 (시작 전 반드시 확인)

### ⚠️ iCloud 중복 파일
`jam-web/design-system/`에 iCloud 동기화 충돌로 인해 숫자가 붙은 중복 파일이 존재한다:
```
SKILL 2.md, SKILL 3.md
_ds_bundle 2.js, _ds_bundle 3.js
dashboard 2.html, dashboard 3.html
...
```
**분석·프롬프트 실행 시 "숫자가 붙은 파일은 제외하고 원본만 대상으로 한다"를 명시할 것.**

### ⚠️ Storybook 설치 위치
Storybook은 반드시 `jam-web/` 내부에 설치한다.
- 설정 파일: `jam-web/.storybook/main.ts`, `jam-web/.storybook/preview.ts`
- 실행: `jam-web/` 디렉토리에서 `npm run storybook`
- 포트: `http://localhost:6006`

### ⚠️ 파일 경로
모든 경로는 프로젝트 루트 기준이 아닌 `jam-web/` 기준:
- 디자인 시스템: `jam-web/design-system/`
- 서비스 코드: `jam-web/src/`
- Storybook 설정: `jam-web/.storybook/`

### ⚠️ 산출물 문서 위치
분석 산출물은 `jam-web/docs/storybook/`에 저장한다 (개발 참고용).

## STEP 2. MODULAR ↔ 실제 서비스 Gap 분석

> **Skill: `design-system-review`**
> **코드 수정 없음.**
> **산출물: `jam-web/docs/storybook/02-modular-gap.md`**

```
방금 생성한 01-modular-audit.md를 기반으로
MODULAR과 실제 서비스(jam-web/src/) 사이의 디자인 시스템 Gap을 분석해줘.

이번 단계에서는 코드 수정 금지.

목표는 Storybook 구축 범위를 결정하는 것이다.

다음 항목을 조사한다:

1. MODULAR에 존재하고 서비스에서 사용되는 컴포넌트
2. MODULAR에 존재하지만 서비스에서 사용되지 않는 컴포넌트
3. 서비스에 존재하지만 MODULAR에 없는 공통 UI
4. MODULAR 컴포넌트와 비슷하지만 별도로 구현된 UI
5. 동일 목적의 컴포넌트가 여러 개 존재하는 경우
6. 동일 컴포넌트의 서비스별 변형
7. Token을 사용하지 않는 UI (하드코딩된 값)
8. 기존 MODULAR과 다른 스타일을 사용하는 UI
9. 실제 서비스에 필요한데 MODULAR에서 부족한 상태/variant
10. Storybook에서 반드시 표현해야 하는 edge case

각 항목을 다음 중 하나로 분류한다:

KEEP
REUSE
EXTEND
NEW CANDIDATE
SERVICE-SPECIFIC
DUPLICATE
DEPRECATED
DECISION REQUIRED

중요:

- NEW CANDIDATE라고 해서 MODULAR에 바로 추가하지 않는다.
- 현재 구현을 먼저 Storybook으로 표현할 수 있는지 판단한다.
- 디자인 개선 제안은 별도 섹션으로 분리한다.
- 이번 작업의 목적은 Storybook 구축이지 디자인 시스템 리디자인이 아니다.

다음 문서를 생성해줘:

jam-web/docs/storybook/02-modular-gap.md

구조:

# MODULAR ↔ Service Gap

## 1. Reusable Components
## 2. Components Requiring Extension
## 3. New Component Candidates
## 4. Service-specific UI
## 5. Duplicate Implementations
## 6. Token Inconsistencies
## 7. Variant / State Gaps
## 8. Deprecated / Unused
## 9. Decision Required
## 10. Storybook Scope Recommendation
```
