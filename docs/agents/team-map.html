4. 워크트리 · 브랜치 — 누가 어디서 도는가

격리 대상은 jam-work.js의 isolation: 'worktree', 차단 장치는 .githooks/에서 읽었다.

메인 작업 폴더 JAM!/ — staging 체크아웃
카리나(메인 세션) · 읽기만 하는 에이전트: 민지·채원·혜린·윈터·윤진·카즈하·하니
jam-web/node_modules 실체 · 시크릿 파일(.env.local 등)
세션 시작 훅:
  • scripts/ticket-dashboard.mjs
  • scripts/check-routine-reports.mjs
  • scripts/workspace-setup.sh
  • scripts/ensure-hooks-path.sh
격리 워크트리 .claude/worktrees/wf_* — 아현 전용
첫 명령: git fetch origin staging → git checkout --detach origin/staging → workspace-setup.sh link
브랜치 claude/jamwork-{ticket}-{slug}에 커밋 → 리뷰 브랜치로만 push
jam-web/node_modules → 메인 폴더로 향하는 심볼릭 링크 · 시크릿 없음 · jam-doc/는 실제 폴더로 따라옴
GitHub · Vercel
claude/jamwork-* push → CI verify가 커밋 상태(도장)를 남김 → 민지가 도장을 읽음
staging ← 카리나가 사용자 승인 후 머지·push (CI 없음)
main ← /jam-ship(JAM_SHIP=1)만 → Vercel 프로덕션

훅이 실제로 막는 것

어디서무엇을어떻게
pre-pushmain 직접 push 차단JAM_SHIP=1(/jam-ship)만 통과
pre-push에이전트 워크트리(wf_*)에서 staging push 차단우회 변수 없음
pre-push리뷰 브랜치(claude/jamwork-*)에서 staging push 차단우회 변수 없음
pre-push리뷰 브랜치 push 시 verify 게이트메인 트리·wf_ 아닌 워크트리에서 실행, wf_*는 CI에 맡김
pre-commit리뷰 브랜치에서 티켓 CLOSED 커밋 차단아현은 티켓을 닫지 못한다
pre-commit이 지도(team-map.html)가 낡으면 커밋 차단node scripts/gen-team-map.mjs

머지와 배포의 경계

대상누가막는 장치
review 브랜치 (claude/jamwork-*)아현이 pushpre-push가 기준 방어는 항상 실행하고, verify.sh는 메인 트리·wf_가 아닌 워크트리에서만 실행한다(wf_* 링크드 워크트리는 CI에 맡긴다, 티켓 20260922_1755). CI(GitHub Actions verify)가 같은 검사를 돌려 결과를 커밋 상태로 남긴다
staging카리나가 사용자 승인 후 머지·pushpre-push가 jam-web lint와 기준 방어 실행. 에이전트 작업 공간(wf_*)과 리뷰 브랜치(claude/jamwork-*)에서 오는 push는 차단. CI는 돌지 않는다
main (프로덕션)카리나가 /jam-ship으로만pre-push가 직접 push를 차단, JAM_SHIP=1이 유일한 통로
DB카리나만 실행아현에게 DB 도구를 주지 않음

5. 스킬 콜사인 /jam-*

카리나(메인 세션)가 부른다. 「부르는 에이전트」는 각 SKILL.md가 이름으로 언급하는 서브에이전트다.

콜사인부르는 에이전트용도
/jam-design채원 jam-designerJAM! 디자인 시스템 MODULAR과 Storybook 카탈로그를 탐색해 기존 컴포넌트 재사용 여부를 판단하고, 신규 UI가 필요할 때 MODULAR 확장 vs 서비스 전용 구현을 결정한다. UI·화면·컴포넌트를 새로 만들거나 고칠 때, "이런 컴포넌트 있어?", "디자인 시스템에 추가할까?", "Storybook 확인해줘" 같은 요청에 사용.
/jam-docs카리나 직접JAM! 프로젝트의 문서 체계(① PRD ② 티켓 ③ 컨텐츠 ④ 배지엔진 ⑤ 서비스플랜) 작성·갱신 절차. 티켓 생성/CLOSED 처리, PRD 갱신, 컨텐츠 문서 수정, 배지엔진 문서 수정, 서비스플랜 버전 갱신이 필요할 때 사용한다. "티켓 만들어줘", "문서 갱신해줘", "PRD 업데이트", "티켓 닫아줘" 같은 요청에 사용.
/jam-ds카리나 직접서비스 UI ↔ MODULAR 디자인시스템 ↔ Storybook ↔ claude.ai/design 네 층의 정합성을 진단하고 어긋난 곳을 맞춘다. UI 작업을 끝낸 뒤, "디자인시스템 동기화", "스토리북이랑 맞춰줘", "MODULAR 최신화", "업로드본 갱신" 같은 요청에 사용. /jam-work의 UI 작업 마무리 단계에서도 호출한다.
/jam-img카리나 직접JAM! 배지 이미지 제작 파이프라인. Recraft 생성 → 로고 합성 → 배경 제거 → DB 반영까지 단계별로 사용자 확인을 받으며 처리한다. "배지 이미지 만들어줘", "이 배지 그림 생성해줘", "/jam-img" 같은 요청에 사용.
