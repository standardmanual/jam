# 도입 체크리스트

실제 적용은 사용자 승인 후 JAM!의 `/jam-work`(`infra`·`docs` 유형) 티켓으로 진행한다.

## 0. 사전 준비
- [ ] 브랜드 보이스 가이드 초안 (마케팅·스토리 문체 기준)
- [ ] 승인 지점 목록 확정 (세계관 설정 변경, 외부 게시, 비용 지출, 프로덕션 배포, DB 대량 변경, 홈피드 발행, 유저 제재)
- [ ] 외부 게시 금지 원칙 확정 (에이전트는 초안까지만)

## 1. 비용 정비
- [ ] 기존 에이전트 3개에 모델 고정 (jam-developer·conservative-reviewer → Sonnet)
- [ ] 메인 세션은 Sonnet으로 운영하는 원칙 정리
- [ ] 티켓 하나가 끝나면 새 세션으로 시작하는 습관

## 2. 이슈 트래커 + 주간 브리핑
- [ ] 에이전트 정의 초안
- [ ] 주 1회 예약 작업 (요일·시간 결정 필요)
- [ ] 브리핑 형식: 바뀐 것 / 결정 필요 / 위험 / 비용

## 3. 디자인 에이전트
- [ ] 에이전트 정의 초안
- [ ] jam-work 1.5·1.6단계 이관 설계
- [ ] 디자인 리뷰를 판정형으로 할지 제안형으로 할지 결정

## 4. 세계관 바이블 + 세계관 에이전트
- [ ] TRIBES.md를 기준 문서로 지정
- [ ] 비어 있는 것 보강 계획: 인물, 장소(무명·블랙 트랙·그루터기 살롱 등), 사건 연표, 스토리 아크
- [ ] 인접 그래프 변경 시 드랍엔진 영향 확인 절차

## 5. 마케팅 에이전트 + /jam-story
- [ ] 에이전트 정의 초안
- [ ] 마케팅 ↔ 세계관 협업 흐름 (브리프 → 설정 검수 → 카피 → 승인)
- [ ] 첫 캠페인 주제·채널 결정

## 6. 기록관 + Learn 폴더
- [ ] 해설 문서 형식 확정 (한 줄 요약 / 왜 / 어떻게 / 다른 선택지 / 더 알아보기)
- [ ] 해설 대상 범위 확정 (P0·P1 + 직접 요청 티켓)
- [ ] 용어집·서비스 지도 첫 버전

## 7. 월간 점검
- [ ] 반복 FAIL·비용·에이전트 정의 점검 항목

## 8. 서비스 운영 에이전트
- [ ] 1차: 읽기 전용 (지표·VOC·운영 리포트)
- [ ] 읽기 전용 DB 경로(집계 뷰 등) 설계 — service_role 키는 주지 않음
- [ ] 홈피드 발행 스펙이 PRD에 있는지 확인
- [ ] VOC 수집 위치를 한 곳으로 모으기
- [ ] 2차: 홈피드 초안 → 승인 → 발행
