# 기존 대비 비효율과 대응

도입하면 기존보다 나빠지는 지점과, 각각을 어떻게 막는지 정리한다. 대응이 없는 항목은 남기지 않는다.

| # | 비효율 | 대응 | 확인 시점 |
| --- | --- | --- | --- |
| 1 | **티켓당 호출이 1회 늘어남** (채원① 사전 판정) | 15줄 미만이거나 처리 규칙표에 같은 판정이 있으면 생략. 경미 수정은 카리나가 직접 | 검증 티켓 3건 |
| 2 | **스크립트 유지보수 부담** | 1차는 6개까지만(`verify`·diff 정리·현황판·승인 후 처리·어드민 API 읽기·작업 공간 준비). 2차는 "없어서 불편할 때" 추가. 스크립트가 깨지면 그 단계는 건너뛰고 사람이 판단 | 월간 회고 |
| 3 | ~~요약본이 낡을 위험~~ | **요약본·지도·패턴 카드를 만들지 않기로 해 사라짐** (공통 20번) | — |
| 4 | **정의가 영어라 바로 못 읽음** | 필요할 때 번역 요청. JAM-WORK 폴더의 한국어 R&R 문서가 원본 역할을 한다 | 상시 |
| 5 | **승인 항목 증가** | 묶음 승인(공통 11번): 문서 갱신은 머지 승인과 함께, 홈피드는 주 1회 7건, 티켓 우선순위는 주간 브리핑에서 | 월간 회고 |
| 6 | **초기 구축 비용** (파일 30개 이상 한 번에) | 작업 브랜치에서 전부 만들고 검증 티켓 3건 통과 후 머지. 도입 커밋에 태그를 달아 되돌릴 수 있게 함 | 도입 당일 |
| 7 | **채원 병목** | 생략 조건 + 이전 판정 재사용. 4주 뒤에도 병목이면 사전 판정을 `ds` 유형에만 적용 | 도입 4주 뒤 |
| 8 | **문서 담당이 4주체** | 공통 15번에 시점으로 명시 (정의 혜린 / 반영 아현 / 누락 민지 / 체계 하니) | 상시 |
| 9 | **에이전트 8명 관리 부담** | 평소 개발 흐름은 4명만 관여(공통 10번). 나머지는 상황이 있을 때만 | 상시 |
| 10 | **예약 작업이 조용히 실패** | 카즈하가 예약 작업의 성공 여부를 점검 항목에 포함 | 주간 브리핑 |
| 11 | **자동 등록·실행이 잘못 나감** | 승인된 항목만 실행. 스크립트가 새 항목을 만들지 않음. 자동 발행은 꺼진 상태로 시작 | 도입 1~2주 |
| 12 | **규칙이 여러 문서에 흩어져 어긋남** | 상태값·카테고리·파일명 규칙은 한 곳에 적고 나머지는 참조. 양식을 바꾸면 검사 규칙도 같이 바꾼다(하니) | 월간 점검 |

## 되돌리는 기준
- 검증 티켓 3건이 통과하지 못하면 도입 커밋으로 되돌린다.
- 도입 4주 뒤 회고에서 **티켓당 소요 시간이 기존보다 늘었다면** 채원①과 큰 작업 계획 단계를 먼저 걷어낸다.
- 3개월 뒤에도 쓰지 않는 스크립트·문서는 없앤다.
