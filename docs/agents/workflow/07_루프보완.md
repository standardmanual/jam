# 루프 보완 (에이전트 협업 관점)

실행 → 검증 → 이벤트 → 개선 네 단계 중 끊긴 곳을 잇는다.

## 즉시 반영 (문서·양식만 고치면 됨)

| # | 보완 | 내용 | 적용 대상 |
| --- | --- | --- | --- |
| 1 | **티켓 '완료 조건' 칸** | 무엇을 어떻게 확인하면 끝인지 한두 줄. 검증 가능한 문장으로 | 티켓 템플릿 · 카리나 · 민지 · 혜린 |
| 2 | **거절 이유 기록** | 사용자가 제안을 거절하면 이유를 결정 기록에 남긴다. 규칙표가 자랄 연료 | 카리나 |
| 3 | **결과 한 줄 기록** | 미션·홈피드·드랍·캠페인이 끝나면 결과를 한 줄 남긴다 (달성자 수·반응·픽업률) | 카즈하 기록 → 윤진·윈터 참조 |
| 4 | **세계관 변경 시 시뮬레이터 검증 의무** | 인접 그래프·트라이브 설정 변경은 드랍 확률에 영향을 준다. 승인 전에 시뮬레이션 결과를 함께 올린다 | 윈터 · 민지 |
| 5 | **상위 티켓 구조** | 여러 에이전트가 얽힌 작업(시즌 이벤트 등)은 상위 티켓 1개에 하위 티켓을 연결한다. 현황판에 상위 티켓 단위로 표시 | 카리나 · 혜린 |
| 6 | **공용 규칙표** | 처리 규칙표를 카리나 전용이 아닌 공용으로 두고 에이전트별 섹션을 만든다. 각 에이전트는 자기 섹션만 읽는다 | 전원 |

## 도입 후 과제

| # | 보완 | 내용 | 담당 |
| --- | --- | --- | --- |
| 7 | **경제 지표 정상 범위** | 배지 발급량·포인트 발행량·드랍 확률의 정상 범위를 정한다. 이게 있어야 카즈하의 "이상" 판단이 성립한다 | 혜린 (첫 기획 과제에 포함) |
| 8 | **컨텐츠 반응 루프** | 드랍·픽업·컬렉션 완성률을 월간 요약으로 윈터·윤진에게 전달 | 카즈하 → 윈터·윤진 |
| 9 | **공개 준비 점검표** | 약관·개인정보·성능·스토어 노출·장애 대응 등 런칭 전 점검 목록 | 혜린 작성 · 카즈하 점검 |

## 결과 기록 형식 (3번)
```
대상   : 미션 「첫눈의 증인」 / 홈피드 12월 2주 / 드랍 12/10 성수
기간   :
결과   : 달성자 n명 · 조회 n · 픽업률 n%
판단   : 좋음 / 보통 / 나쁨 + 한 줄 이유
다음에 : 반영할 것 한 줄
```

## 완료 조건 예시 (1번)
- 나쁨: "배지 중복 문제를 해결한다"
- 좋음: "같은 활동을 두 번 동기화해도 배지가 1개만 발급된다. 재현 경로: 어드민 시뮬레이터에서 같은 배치 2회 실행"
