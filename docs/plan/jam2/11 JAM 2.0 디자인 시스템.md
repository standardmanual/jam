# JAM 2.0 디자인 시스템

> **JAM 2.0 기획 문서다.** 디자인 단계의 산출물이고, 사용자가 2026-10-15에 토큰 정리 5건과 적용 결정 4건을 정했다. 서비스 적용은 상위 티켓 20261015_2130에서 진행한다. 1~4단계(토큰 교체 20261015_2131, 서체 교체 20261015_2132, 공통 컴포넌트 정비 20261015_2133, 직접 적은 색 정리 20261015_2134)는 2026-10-16 staging에 반영했고 5단계(스토리북·DESIGN.md 동기화, 20261015_2135)도 같은 날 반영했다. claude.ai/design 업로드본 갱신만 디자인 시스템 인증을 기다리며 티켓 20261016_2220에 남아 있다.
> 값의 원천은 `jam-web/design-system/tokens/`의 토큰 파일이다. 1~4절은 결정 이력과 대응표라 현재 서비스 사실의 근거로 쓰지 않고, 5절(화면 규칙)은 지금 서비스에 적용하는 기준이다. 지금 서비스의 디자인 시스템 지도는 [`jam-web/DESIGN.md`](../../../jam-web/DESIGN.md)이고 이 문서 5절과 토큰 파일을 가리킨다.

## 0. 이 문서에 대해

- 서비스 적용 티켓(상위 `20261015_2130`, 하위 5개)이 이 문서를 기준으로 쓴다. 코드에 옮긴 뒤에는 코드의 토큰 파일이 값의 원천이 된다.
- 서비스 적용은 staging에 바로 쌓고, 토큰 이름은 새 시스템 이름으로 일괄 교체한다. 새 시스템에 없는 값도 새 시스템의 이름 규칙을 따른다(2026-10-15 사용자 결정, 상위 티켓 결정 1·2).
- 1절의 피그마 파일 외에 이전 피그마 파일(서비스 화면 파일, 리뉴얼 파일)은 참고하지 않는다(2026-10-15 사용자 결정).
- 토큰 값의 원천은 1절의 피그마 파일이다. 이 문서는 피그마 값을 모두 옮겨 적지 않고, 사용자 결정으로 바뀐 값과 지금 서비스와의 대응만 적는다.
- `jam-web/DESIGN.md`는 2026-10-16에 이 문서의 결과로 덮어썼다(티켓 20261015_2135 1회). 서비스를 staging에 바로 적용하기로 해서 JAM 2.0 배포 때가 아니라 앞당겼다. DESIGN.md는 값을 옮겨 적지 않고 토큰 파일과 이 문서 5절을 가리킨다.
- 2026-10-19 사용자 결정(티켓 20261019_1120): 기본 배경 `background/background`를 #fafaf0에서 #f1f0eb로, 새 바탕과 거의 같아지는 회색 면 `background-secondary`·`default`·`default-soft`를 #f2f2f2에서 #e9e7e0로 바꿨다. 이 문서의 3절 새 값 열과 5·6절의 크림 바탕 대비 숫자는 새 값 기준이다. 1~2절의 2026-10-15 결정 표는 이력이라 그대로 두고, 2.1절 3번의 투명 기준색만 새 바탕에 맞췄다.

### 0.1 그대로 두는 것 (2026-10-15 사용자 결정)

- 해상도 기준. 유저 화면은 모바일 컨테이너 최대 폭 430px(`jam-web/src/app/(main)/layout.tsx`)이다. 새 시스템의 `dimensions/screens/*`(640px부터)는 유저 화면 분기에 쓰지 않는다.
- UX 라이팅 가이드라인([`UX_WRITING_GUIDELINE.md`](../../service/writing/UX_WRITING_GUIDELINE.md), JAM 2.0 재정비안은 [UX 라이팅 재정비](<service-redesign/UX 라이팅 재정비.md>)).
- UI 기능과 정책. 바뀌는 것은 토큰과 시각 표현이다.
- 단위 화면은 사용자가 피그마에서 고칠 수 있다.
- 어드민(운영툴 포함)은 범위 밖이다(진행 노트 2절 진행 규칙 16).

## 5. 화면 규칙

### 5.1 카드와 표면

- 페이지 바탕은 `background/background`, 카드는 `surface/surface` + 1px `border`이고 그림자를 쓰지 않는다(2.2절 7번).
  흰 카드와 크림 바탕의 대비가 1.14:1이라 테두리가 없으면 카드가 보이지 않는다.
- 카드 안의 구획(카드 안 행 `ListRowCard tone="tint"`, 썸네일 칸, 라벨 칩)은 `background/background-secondary` #e9e7e0이고 테두리가 없다. 크림 바탕과의 대비가 1.08:1이라 크림 바탕 위 단독 카드로는 쓰지 않는다.
- 카드 톤 `inverse`(어두운 반전 면 `background-inverse` + 글자 `snow`)는 선택 신호처럼 면이 어두워야 하는 곳에만 남는다(1회 시점에는 온보딩 트라이브 선택 카드 한 곳, JAM 2.0 개발 때 바꾼다).
  그 밖의 카드 위 글자는 제목·필수 정보 `foreground`, 설명·보조 `foreground/muted`, 강조 숫자 `foreground/link`다. 불투명도로 글자색을 만들지 않는다.
- 탭(`SlidingTabs`) 기본 팔레트는 트랙 `default/default`, 비활성 라벨 `foreground/muted`, hover `foreground`, 활성 필 `background-inverse` + 글자 `snow`다. 흰 카드 위 팔레트(`onCard`)는 비활성 라벨이 같은 `foreground/muted`다.
- 새 시스템에는 TopNav와 카드류 컴포넌트가 없다. 지금 서비스의 TopNav, ListRowCard, Card, BottomSheet, BadgeGridCard, CollectionGridCard는 새 토큰과 새 기본 부품으로 다시 조립한 서비스 패턴 컴포넌트로 둔다.

### 5.2 진행 상태 색 (2.2절 8번)

| 상태 | 가는 선·점·링 | 면 채우기 |
|---|---|---|
| 모자람(채우는 중) | `warning/warning` #f5a300 | `accent-content/accent-yellow` + `foreground/foreground` 글자 |
| 다 채움·획득 | `success/success` #17c964 | `accent-content/accent-green` + `foreground/foreground` 글자 |
| 방금 들어옴 | `accent-content/accent-blue`(6절 열린 항목) | `accent-content/accent-lightblue` + `foreground/foreground` 글자 |
| 손대지 않음(트랙) | `default/default` #e9e7e0 | |

`accent-content`의 초록·노랑·하늘색은 크림 바탕 대비가 1.04~1.17:1이라 선과 점으로 쓰지 않는다.

진행 상태 색은 글자로 쓰지 않는다. 다 채움 글자 `link`, 거의 다·진행 중 `foreground`, 0·계산 불가 `muted`다(흰 면 위 5.44 / 17.93 / 5.74:1). 단일 원천은 MODULAR `BadgeFamilyCardHeader`의 `progressRampColor`이고, `warning`·`success`·`progress-*`는 선·링·점·막대 면에만 남는다. 그 색은 흰 면 위 2.07~2.19:1이라 글자에 쓰면 4.5:1에 못 미치고, 선·링·점·막대로는 사용자 결정에 따라 유지한다(6절 열린 항목 「진행 트랙 대비」).

### 5.3 강조색

- `accent/accent` #19b551은 크림 바탕 위 글자 대비가 2.37:1이다. 버튼 같은 채우기에만 쓰고, 강조 글자는 `foreground/link` #0e7a38(4.77:1)을 쓴다.
- 초록 위 글자는 `accent/accent-foreground`(#171717, 6.63:1)다. 흰 글자는 2.7:1이라 쓰지 않는다.
- 안 읽은 소식 점은 `danger/danger`다. 지금은 주 강조색과 같은 빨강이었지만 주 강조색이 초록이 되므로 위험 계열로 옮긴다.

### 5.4 버튼 (2.2절 2번, 티켓 20261015_2133 2회)

서비스 `Button.tsx`와 MODULAR `Button.jsx`는 같은 변형 표를 쓴다. 모든 변형에 1px 테두리가 있어(외곽선 외에는 투명) 변형을 바꿔도 높이가 같다(md 52px).

| 변형 | 면 | 글자 | 테두리 |
|---|---|---|---|
| `primary` | `accent/accent` | `accent/accent-foreground` (6.63:1) | 투명 |
| `secondary` | `default/default` | `foreground/foreground` (14.49:1) | 투명 |
| `danger` | `danger/danger` | `foreground/foreground` (5.02:1) | 투명 |
| `outline` | 투명 | `foreground/foreground` | 1px `field/border` |
| `ghost` | 없음 | `foreground/link` (크림 4.77:1) | 투명 |

- 한 영역에 `primary`는 하나이고 나머지는 `secondary`다. 다만 크림 바탕 위에서는 `secondary` 면(#e9e7e0)이 1.08:1이라 윤곽이 안 보이므로 보조 버튼을 `outline`으로 둔다(TopNav 문의, 프로필 편집·로그아웃, 위치 권한 재시도, 피드 더보기 5곳, 2026-10-16 사용자 승인, 티켓 20261016_2231). 흰 카드 안과 `--warning` 면 위는 `secondary`를 유지하고, 크림 시트 패널 안 보조 버튼 4곳은 사용자 판단 대기다. `danger`의 글자는 흰색이 아니다(흰 글자는 3.5:1이라 4.5:1에 못 미친다).
- `secondary`(#e9e7e0)는 `background-secondary`(#e9e7e0)와 같은 값이라 카드 안 구획(`tone="tint"`) 위에 놓지 않는다.
- 서비스 `surface="main"` primary(11곳)는 사용자 결정(2026-10-16)으로 검정(`background-inverse` + `snow`, 17.47:1)을 유지한다. 그래서 같은 크림 바탕에서 서비스 main primary(검정)와 `surface="sub"`·MODULAR light primary(`accent`)의 색이 갈라진 채 남는다(6절 열린 항목).
- MODULAR `surface="dark"`(반전 면 위, 스토리 전용): primary는 `snow` 채움 + `foreground` 글자, secondary는 투명 + 1px `snow` 테두리 + `snow` 글자다.

### 5.5 입력창 (2.2절 3번)

- `Input`·`Select`는 면 `surface/surface` + 1px `field/border` + 캡슐(`field/radius` 100), `Textarea`는 같은 면과 테두리에 반경만 `--radius-2xl`(16)이다. 서비스에서 같은 모양인 `UserSearchBar`와 레시피가 같다. 글자 `foreground`, placeholder `foreground/muted`(흰 면 위 5.74:1)다.
- 오류는 `danger/danger`, 성공은 `success/success` 테두리다. border를 1px로 두고 같은 색 inset 링 1px를 더해 시각 2px로 만든다(두께가 바뀌면 글자가 1px 움직인다). 오류·성공 문구는 컴포넌트가 그리지 않으므로 호출부가 `foreground` 글자로 쓴다(`danger` 글자는 흰 면 위 3.57:1이다).
- `field/border`(#cfc9b4)는 값을 바꾸지 않았다. 흰 면 위 1.66:1, 크림 위 1.45:1, `background-secondary` 위 1.34:1로 UI 경계 3:1에 못 미친다(6절 열린 항목).

### 5.6 TopNav와 BottomSheet (2.2절 4번, 티켓 20261015_2133 2회)

- TopNav 면은 불투명 `background/background`이고 구분선·그림자가 없다. 크림 바탕 페이지와 같은 면이다. 로고는 흰색 PNG의 알파만 마스크로 쓰고 `foreground`로 칠한다(크림 위 15.71:1, 흰 로고는 1.14:1). 사진이 없는 아바타 폴백은 카드 면 레시피(`surface` + 1px `border`)다.
- BottomSheet 스크림은 `--backdrop`(검정 50%), 핸들은 `border`다. 시트 패널은 크림 `background`, 푸터는 흰 `surface`이며 서비스와 MODULAR가 같다(사용자 결정 2026-10-16). 투명도 줄이기 설정의 대체 스크림은 불투명 `background-inverse`다(크림이면 패널과 같은 색이 된다). 시트와 스크림 경계는 3.94:1이다.

### 5.7 상태 칩 색과 배경 위 글자 (티켓 20261015_2134 1회, 2026-10-16 사용자 승인)

- 상태 칩 색 매핑(미션·VOC·컬렉션·알림): 중립(시작 전·기간·완료) → `background-secondary` 면 + `muted` 글자(4.64:1), 잠김·미달성 → `border` 면 + `foreground`(10.81:1), NEW·참가중 → `accent` 면 + `accent-foreground`(6.63:1), 달성·획득·답변완료 → `accent-content-green` 면 + `foreground`(13.44:1), 문의중 → `danger` 면 + `foreground`(5.02:1), 확인중 → `accent-content-blue` 면 + `foreground`(6.82:1), 알림 경고 칸 → `warning` 면 + `foreground` 아이콘(8.64:1). `muted`는 `border` 면 위 3.46:1이라 쓰지 않는다. NEW와 참가중이 둘 다 `accent`라 같은 줄에 놓이면 위계가 흐리다(알려진 임시 결함).
- 이미지·영상·블롭·어두운 막 위 글자만 `snow`를 유지한다(기본 블롭 `#555555` 위 7.27:1). 그 밖의 글자는 모두 `foreground`·`muted`·`link`다. 불투명도로 글자색을 만들지 않는다(`/80`·`/90`은 `foreground`, `/30`~`/70`은 `muted`). 이미지·블롭 위 글자의 `textShadow`(`getBadgeThemedTextStyle`)는 대비 보정이라 유지한다.
- 그림자는 입력창(`field/shadow`)만 남기고 지운다. `box-shadow: inset 0 0 0 1px …` 형태의 테두리·선택 링은 그림자가 아니다. blur는 탭바(`tabbar/blur`)만 남기고 두 가지만 예외로 둔다(티켓 20261015_2134 2회, 사용자 승인 2026-10-16). 하나는 화면 전환 모션의 `filter` blur(`transitions.css`·`transitions-pages.css`)로 전환 중에만 있다가 0으로 돌아온다. 다른 하나는 블롭 배경 캔버스의 blur(`BlobAnimationBackground.tsx`)로 어드민이 저장한 콘텐츠 데이터라 지우면 블롭 아트가 달라진다. 장식용 `backdrop-blur`는 쓰지 않는다.
- 이미지·지도 위 막은 새 토큰을 만들지 않는다(사용자 결정). 포스터 카드 막과 지도 라벨 막은 `--base-black`을 60~65% 섞어 직접 가지고, 그 위 글자는 `snow`(5.60:1 이상)다. 배지 획득 오버레이는 `--backdrop` 위에 글자를 두며 크림 바탕 합성 시 4.14:1이다(허용 명시).
- Strava 주황 버튼은 면 `#FC4C02`를 브랜드 색으로 유지하고 글자만 `foreground`(5.27:1)로 둔다. 흰 글자는 3.40:1이다.
- 지도 드랍 마커의 글리프는 `accent` 면 위 `accent-foreground`(6.63:1), `muted` 면 위 `snow`(5.60:1)다. 현재 위치 버튼은 그림자 대신 `surface` 면 + 1px `border`로 지도와 갈라진다.
