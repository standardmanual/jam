# JAM 2.0 오픈 전후 적용 순서

> **초안이다(2026-10-25).** 티켓 7-9(`20261022_1140`)의 목록이며 7-4 2회, 7-5, 7-7b 4회가 끝나기 전이라 확정본이 아니다. 아직 파일로 없는 SQL은 「미작성」으로 적었다. `/jam-ship`의 오픈 직전 점검과 「출시 뒤 실행 대기 목록」이 이 표를 참조한다.

## 1. 원칙

- Supabase는 staging과 프로덕션이 한 DB를 쓴다. 실행하는 순간 옛 프로덕션 코드에도 바로 반영된다. 그래서 **오픈 직전 SQL은 main 승격 직전에, `post_release` SQL은 승격 뒤에** 실행한다.
- 모든 SQL은 파일마다 채팅에서 사용자 승인을 받고 카리나가 실행한다. 실행 전에 파일 이름, 영향 범위, 되돌림 SQL의 위치를 먼저 말한다.
- 아래 표의 「롤백 실측」 칸은 티켓에 적힌 사실만 옮겼다. 적히지 않은 것은 「기록 없음」이다.
- 마이그레이션 기록표(`schema_migrations`)는 SQL을 직접 실행한 건(281, 287 등)이 빠져 있어 적용 여부의 근거로 쓰지 않는다. 실제 객체를 읽어 확인한다.

## 5. 출시 (main 승격)

- `/jam-ship`으로 진행하고 사용자의 명시적 승인이 있을 때만 한다. 2026-10-25 기준 staging이 main보다 1,074커밋 앞서 있고 main에만 있는 커밋은 없다.
- 승격과 함께 `docs/service/SERVICE_OPERATIONS.md`를 10번 문서(JAM 2.0 서비스 운영 로직)로 덮어쓴다(진행 노트 2절 규칙 5, 사용자 결정 2026-10-10).
- 승격 전에 사용자가 정할 법무 항목: 약관·방침 시행일, 서비스 이용약관 초안의 확정 여부, 위치기반서비스 이용약관(`20260929_1303`, 대기).
