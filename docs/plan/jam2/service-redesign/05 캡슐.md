# 캡슐 (폐지)

> **이 주제는 2026-11-27에 폐지했다.** 사용자 결정이고 근거와 작업은 티켓 20261127_1720에 있다.
> 폐지 전의 정책 본문은 이 문서를 고치기 전 커밋(`git log --follow`)에서 볼 수 있다. 에이전트는 이 문서를 현재 서비스 사실의 근거로 쓰지 않는다.
> 확인 상태는 [서비스 재설계 정책](README.md) 2절에 있다.

## 1. 결정

- 잼을 채워 열면 아이템 배지가 나오던 기능을 없앤다. 유저 화면에서는 이 말을 기능 이름으로 쓰지 않고, 문서에서는 폐지 기록으로만 쓴다([공통 용어](<01 공통 용어.md>) 3.1절).
- 잼은 챕터를 올리는 경험치로 쓴다. 포인트는 별도 재화로 그대로 둔다(잼과 포인트를 합치는 안은 사용자가 철회했다).
- 캡슐이 주던 아이템 배지는 챕터가 오를 때 받는다. 개수와 확률은 시뮬레이션 뒤 정한다(티켓 20261127_1723).

## 2. 옮겨 간 곳

| 캡슐에 있던 것 | 지금 있는 곳 |
|---|---|
| 잼을 쓰는 곳, 채워야 하는 양 | 챕터마다 필요한 잼([챕터](<17 챕터.md>) 3절). 챕터 1~9는 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이다 |
| 채운 양을 게이지로 보이는 화면 | 홈과 내 프로필의 챕터 게이지 카드. 이번 챕터에서 모은 잼과 필요량을 숫자로도 보인다([챕터](<17 챕터.md>) 6절) |
| 열기와 보상(소속·비소속 아이템 배지) | 챕터 오름 보상([챕터](<17 챕터.md>) 4절). 소속·비소속 구성과 확률은 시뮬레이션 뒤 정한다 |
| 인벤토리 빈칸이 모자라면 열 수 없고 채운 잼을 남기는 규칙 | 챕터 오름 보상 때의 빈칸 부족 처리로 다시 정한다(열린 질문, 티켓 20261127_1720의 Q-c) |
| 이용 정지 중에는 채우거나 열 수 없다 | 이용 정지 중에는 잼이 챕터 진행에 쌓이지 않는다([어뷰징과 밴](<20 어뷰징과 밴.md>) 3절, [챕터](<17 챕터.md>) 3절) |
| 캡슐을 연 횟수를 조건으로 하는 액티비티 배지와 미션 | 조건 키를 어드민에서 비활성화한다. 이미 받은 배지는 유지한다(티켓 20261127_1743, 1744) |
| 캡슐의 수치를 어드민 설정으로 두는 원칙(2026-10-10) | 챕터별 필요 잼과 챕터 오름 보상을 어드민 설정으로 둔다([챕터](<17 챕터.md>) 8절) |
| 트라이브가 바뀌면 채우다 만 잼을 새 트라이브로 옮기는 규칙(13-5) | 이번 챕터에 모은 잼은 트라이브가 바뀌어도 그대로 이어진다([트라이브, 출신, 레벨](<04 트라이브, 출신, 레벨.md>) 4절) |

## 3. 기존 유저

- 챕터는 내려가지 않는다. 이번 챕터 진행값은 현재 챕터에 오른 뒤 캡슐에 채운 잼의 합계와 지갑 잔액으로 계산해 옮긴다. 기존 대기 보상과 이미 받은 아이템 배지는 그대로 둔다.
- 캡슐을 연 기록(열린 시각, 챕터, 채운 양, 나온 아이템 배지)과 보지 않은 결과, 대기 보상 기록은 지우지 않고 보존한다.
- 이관 규칙의 세부는 티켓 20261127_1728에서 정한다.
