# 홈 화면과 오늘의 카드, 운영 자동화와 운영툴, 크론, 안전과 약관

조사일 2026-10-09(KST). DB 값은 `execute_sql` SELECT로 확인했다.

## 홈 화면 (홈)
- **유저 화면**: `/`. 위에서부터 상단 바(로고, 온보딩 퀘스트 sync 차례면 가운데가 연출 동기화 버튼), 인사말과 검색 아이콘(→ `/search`), 온보딩 퀘스트 카드(대상 유저만), 오늘의 현황 줄(2칸), 오늘의 카드 묶음(제목 「투데이」). 로그인하지 않으면 `/login`으로 보낸다. 하단에 푸터가 나온다.
- **어드민**: 상태 줄과 인사말은 없음. 오늘의 카드는 아래 절.
- **규칙과 값**: 상태 줄 왼쪽(내 진행도)은 Strava 미연동이면 연동 유도(`/api/strava/auth`), 진행 중 컬렉션·미션이 있으면 완성도가 가장 높은 1건(동률은 최근 활동순), 없으면 코드에 고정된 안내 2개(드랍·미션) 중 요청마다 무작위 1개다. 오른쪽(친구 활동)은 팔로잉이 없으면 검색 유도, 오늘(KST 0시 이후) `badge_earned`를 받은 팔로잉이 없으면 칸을 그리지 않고, 있으면 인원 수(1명이면 그 프로필, 그 외 `/feed`)다. 피드 조회 상한 200행(코드).
- **데이터**: `strava_connections`, `user_item_book_slots`, `user_mission_participations`, `user_follows`, `user_activity_feed`.
- **코드**: `jam-web/src/app/(main)/page.tsx`, `lib/today/status.ts`, `app/(main)/TodayStatusStrip.tsx`.
- **알려진 문제**: 날씨는 홈 화면에 표시되지 않는다. 날씨는 오늘의 카드 노출 태그로만 쓴다(아래). 「홈 피드」는 코드에서 오늘의 카드를 가리키는 이름이다(`/feed`의 `FeedSection.tsx`는 활동 피드로 별개 화면이다).

## 오늘의 카드 (투데이 카드, 홈피드 카드)
- **유저 화면**: 홈의 카드 묶음. 기사형(`editorial_article`)은 `/today/[cardId]` 상세로 연다. 노출 카드가 0장이면 영역 자체를 그리지 않는다.
- **어드민**: `/admin/today`(날짜 이동, 검색·템플릿·이미지 출처 필터, 일괄 활성화·비활성화·기간 종료·삭제(삭제는 확인 문구), CSV 내보내기, 날짜별 미리보기), `/admin/today/new`·`[id]/edit`. 폼에서 바꿀 수 있는 것: 템플릿 9종, 레이아웃 6종, 컨텐츠 유형 T01~T17, 제목·부제·설명, 커버 이미지 주소, 배지 목록, 미션, 컬렉션, 지역 이름, 본문(기사), 랭킹모드, 레시피, 이동 주소, 노출 태그(복수, OR), 시작·종료 시각, 정렬 순서, 활성. 폼에 없는 칸: `shape`(카드 모양), `title_in_image`, `pattern_no`. 이 셋은 운영툴 실행 경로(`lib/admin/opsInbox/registerInput.ts`)만 채운다.
- **규칙과 값**: 조회 조건은 `is_active` 이고 `starts_at ≤ 지금 ≤ ends_at` 이고 `exposure_tags`가 유저 태그와 하나라도 겹치는 카드, 정렬은 `sort_order` 오름차순 뒤 `starts_at` 내림차순이다. 노출 장수 상한은 없다. 미션 소개 카드는 미션이 그 유저에게 `open`일 때만 남긴다. 카드 모양은 5종(hero·poster·square·brief·list), 제목 상한은 모양별 18~28자(코드)다. `shape`가 비면 템플릿·레이아웃으로 모양을 정한다(`LEGACY_SHAPE_CUTOVER = true`).
- **DB 값**: 카드 71장(badge_spotlight 8, drop_alert 12, editorial_article 9, itembook_milestone 9, location_trend 8, mission_spotlight 10, progress_nudge 15). `ranking_board`·`recipe_reveal` 카드는 0장이다. 지금 노출 중인 카드는 1장(drop_alert)이다. 71장 모두 `shape`와 `pattern_no`가 비어 있다.
- **데이터**: `today_cards`(id, template_type, title, subtitle, description, cover_image_url, badge_ids, mission_id, item_book_id, region_label, body_markdown, target_href, exposure_tags, starts_at, ends_at, sort_order, is_active, layout_type, ranking_mode_id, content_type_id, image_source, shape, title_in_image, pattern_no, recipe_id).
- **코드**: `lib/today/cards.ts`, `lib/today/shape.ts`, `lib/today/cardView.ts`, `app/admin/today/TodayCardForm.tsx`, `lib/admin/today-sections.ts`.

## 오늘의 카드 노출 태그와 날씨·특일
- **유저 화면**: 없음(태그는 카드 선택에만 쓴다).
- **어드민**: 카드 폼의 노출 태그 선택(20개). 태그 판정 기준값과 특일 이름 목록은 바꿀 수 없음(코드 상수).
- **규칙과 값**: 항상 `all`과 시간대 태그 1개(KST 05~08 dawn, 08~11 morning, 11~17 afternoon, 17~22 evening, 22~05 night). 조건 태그: 참가 중 미완료 미션, 종료 3일 이내 참가 미션, 미완성 컬렉션, 컬렉션 잔여 3개 이하, Strava 마지막 동기화 14일 이상, 가입 7일 이내, 날씨 4종(clear·mild·rain·extreme), 공휴일·절기(11개 이름)·기념일(10개 이름). 날씨는 서울 격자(nx 60, ny 127) 하나의 예보로 전 유저에게 같은 값이다. 강수가 있으면 rain, 최고 33도 이상 또는 최저 -12도 이하면 extreme, 하늘 맑음이면 clear, 그 외 mild다. 카드 조회는 외부 API를 부르지 않고 크론이 저장한 값만 읽는다.
- **DB 값**: `external_input_daily` weather 14일치·special_days 15일치(2026-09-25~10-09).
- **코드**: `lib/today/exposure.ts`, `lib/inputs/weather.ts`, `lib/inputs/special-days-config.ts`, `app/api/cron/external-inputs/route.ts`.

## 크론 작업
- **유저 화면**: 없음.
- **어드민**: 크론 일정은 바꿀 수 없음(`vercel.json`). 앰비언트 드랍의 켜기·실행 시각은 `/admin/ambient-drop`에서 바꾼다(다른 영역). 운영툴 신호 기준값은 운영 설정에서 바꾼다.
- **규칙과 값**(시각은 KST, 모두 `Authorization: Bearer CRON_SECRET` 확인):

| 경로 | 일정(UTC 원문) | 하는 일 |
|---|---|---|
| `/api/cron/poi-cleanup` | 매일 09:00 (`0 0 * * *`) | `expire_stale_poi_drops` RPC(`expires_at` 지난 드랍과 삭제된 배지의 미픽업 드랍 소각, `custody_events`에 Expire 기록), 3개월 지난 `abusing_logs` 삭제 |
| `/api/cron/notifications` | 매일 18:00 (`0 9 * * *`) | 소식 배치 7단계(collections, drop-spot, missions, mission-rank, following, sync-stalled, inventory-full) |
| `/api/cron/ambient-drop` | 매시 정각 | 도래한 날짜 예약 배포를 먼저 처리하고, `auto_enabled`이고 `schedule_hour_kst` 시각이며 그날 처음이면 매일 배포 실행 |
| `/api/cron/external-inputs` | 매일 06:00 (`0 21 * * *`) | 기상청 단기예보와 특일 정보를 받아 `external_input_daily`에 저장 |
| `/api/cron/ops-reconcile` | 10분마다 | 운영툴 항목 상태를 실제 자원에 맞춤(게재중·종료·취소·실패, 밖에서 바뀐 것은 결정 기록만), 슬랙 알림 |
| `/api/cron/ops-stop-signals` | 매시 5분 | 상태 맞추기 1회 뒤 중단 신호(예약 누락·루틴 실패)를 계산해 `#jam-alert`에 알림 |

- **DB 값**: `ambient_drop_config.auto_enabled = false`, `schedule_hour_kst = 3`, 마지막 자동 실행 2026-10-01. 따라서 매일 배포는 지금 건너뛰고, 날짜 예약(`ambient_drop_schedules` 2행)만 처리된다. 운영툴 신호 기준값은 DB에 바꾼 값이 없어 코드 기본값을 쓴다. `routineCheckStartsAt` 기본값이 null이라 「루틴 실패」 신호는 확인하지 않는다.
- **코드**: `jam-web/vercel.json`, `app/api/cron/*/route.ts`, `lib/notifications/batch/index.ts`.

## 받은 기획함 (운영툴 S2, ops-inbox)
- **유저 화면**: 없음.
- **어드민**: `/admin/ops-inbox`(상태 탭 4개, 목록), `/admin/ops-inbox/[bundleId]`(묶음 상세, 밸런스 경고, 결정 기록). 운영자가 할 수 있는 것: 항목별 승인·반려(사유 500자)·직접 수정(문안 `copy.*`, 색 `colors.*`, 공개·종료 시각, 대상 문자열, 「유저가 겪는 것」만, 새 키 추가 불가)·되돌리기·색 채우기, 승인된 항목 예약 등록(실행), 공개 전 취소, 게재중 항목 지금 종료, 이미지 저장, 시험 묶음 삭제. 에이전트는 토큰으로 `POST /api/admin/ops-inbox`에 묶음을 제출한다(본문 1MB, 항목 60개, 시간당 20회).
- **규칙과 값**: 항목 종류 7개(home_feed_card, mission, drop_schedule, recipe, jam_badge, collection_launch, pattern_proposal). 상태 10개(arrived, reviewing, approved, preparing, scheduled, live, ended, rejected, cancelled, failed). 연결 항목(카드와 그 카드가 여는 미션 등)은 함께 공개·되돌림한다. 같은 묶음 재실행은 거부한다.

- **데이터**: `ops_bundles`, `ops_bundle_items`(original, edited, created_resource, status, pattern_no), `ops_decisions`.
- **코드**: `app/admin/ops-inbox/`, `lib/admin/opsInbox/decide.ts`·`edit.ts`·`constants.ts`·`execute/`, `lib/admin/opsInbox/slack.ts`.
