# 옛 아이템 배지 행과 새 아이템의 짝짓기 표 (7-6)

> 티켓 `20261022_1137`(JAM 2.0 묶음 7, 7-6)의 시작 전 자료다. 사용자는 이어받는 컬렉션 44개의 옛 아이템 배지 행 396개를 **모두 덮어쓰기로** 정했다(2026-10-22). 이 표는 컬렉션마다 옛 배지 행 9개와 새 아이템 9개를 어떻게 1:1로 짝지을지 정했다. 사용자가 2026-10-22에 이 표를 확인했고, DB 적용 SQL이 이 표를 쓴다. SQL은 배지 id를 적지 않고 «컬렉션의 옛 이름과 옛 배지 이름»으로 옛 행을 찾는다. `jam-web/scripts/jam2-content/pairing.json`이 이 표와 같은 내용이며, 시험(`__tests__/pairing.test.mjs`)이 둘을 비교한다.
> 옛 배지 이름, 보유 수, 장착 수는 공용 DB를 읽은 값이다(2026-10-22). 새 아이템 이름과 처리는 원고(`docs/plan/jam2/tribe-rethink/manuscript/`)의 6절 표다.
> 옛 컬렉션 이름도 공용 DB의 이름이다. 원고에는 «무명(無名)을 쫓는 야식가들»로 적혀 있지만 DB에는 괄호 없는 «무명無名을 쫓는 야식가들»이라 DB 쪽을 적었다.

## 1. 짝짓기 규칙

컬렉션마다 아래 순서로 짝지었다.

1. **이름 일치**: 원고의 «옛 이름과 처리» 열의 옛 이름(끝의 «자리»는 뺐다)이 공용 DB 옛 배지 이름과 띄어쓰기·따옴표를 무시하고 같다.
2. **이름 유사**: 1에서 남은 것 가운데 이름 유사도가 0.5 이상인 것을 높은 순서로 짝지었다(표기 차이로 보이는 것이 대부분이다).
3. **순서 짝**: 그래도 남은 옛 행과 새 아이템을 옛 행은 공용 DB의 생성 순서, 새 아이템은 원고 번호 순서로 짝지었다. 내용이 서로 관련이 없는 짝이므로 **사용자가 확인할 대상**이다.
