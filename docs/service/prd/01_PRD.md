# JAM! 유저 모바일 웹 — PRD (Product Requirements Document)

> 최초 생성일: 2026-07-09 / 생성 도구: Show Me The PRD
> **2026-08-06 갱신**: `jam-web/src/app` 전체 라우트 대조로 현재 상태 기준 재작성.

---

## 1. 제품 개요

### 한 줄 요약
운동 후 Strava 동기화 한 번으로 디지털 배지를 수확하고, 지도에서 아이템을 드랍·픽업하며 트라이브 컬렉션을 완성하고, 믹스·미션·포인트로 게임 경제를 순환시키는 피지털 게이미피케이션 모바일 웹 앱.

### 해결하는 문제
운동 기록 앱(Strava, Garmin)은 이미 충분하지만, **운동에 대한 의미 있는 보상**이 없다. JAM!은 기존 트래킹 습관을 바꾸지 않고 저녁에 앱을 열면 배지와 아이템이 쌓이는 "보상 수확" 경험을 제공한다.

### 핵심 가치
- **Tracker-less**: 자체 GPS 트래킹 없음. 기존 Strava 데이터 그대로 활용
- **10초 첫 보상**: 가입 → Strava 동기화 → 첫 배지 획득까지 마찰 제로
- **탐험형 컬렉션**: 지도에서 아이템을 드랍/픽업하고, 10개 트라이브 서사에 따라 컬렉션을 완성해가는 수집 루프
- **피지털 커머스**: 배지 달성 시에만 구매 가능한 실물 자수 패치 (돈이 있어도 아무나 살 수 없음) — *현재 D2C 연동 미구현, 배지 조건만 존재*

## 2. 사용자

### 주요 사용자
- **누구**: Strava를 사용하는 자전거/달리기/등산/걷기 활동자
- **상황**: 운동 후 귀가해서 저녁에 스마트폰으로 앱 확인, 또는 야외 활동 중 지도에서 주변 드랍 아이템 확인
- **목표**: 오늘 운동으로 어떤 배지가 생겼는지 확인, 아이템 드랍/픽업, 트라이브별 컬렉션 진행, 미션 참가, 포인트 적립

### 페르소나
1. **자전거 자출족 (2030)**: 출퇴근 라이딩. 누적 거리 배지 + 주변 드랍 아이템 픽업.
2. **등산 인증샷러 (3040)**: 주말 산행. 봉우리 POI 인증 배지(반복 획득) + 가방 꾸미기 아이템 패치.
3. **러닝 크루 (2030)**: 소셜 중심. 팔로우·유저 검색·프로필 공개, 미션 참가로 그룹 동기부여.
4. **일상 걷기러 (4050)**: 최대 DAU 기반. 일별/주별 걸음 달성 배지 + 홈 "투데이" 카드로 재방문 유도.

### 핵심 사용자 시나리오

**시나리오 1 — 첫 방문 (10초 보상 플로우)**
1. 링크로 JAM! 접속 → 구글 로그인
2. 온보딩(2단계): 1단계 아이디·이름 설정(아이디는 실시간 중복확인), 2단계 트라이브 선택 +
   프로필이미지 변경(선택)
3. Strava 동기화 버튼 탭 → OAuth 연결 완료
4. 이후 Strava 활동이 동기화될 때마다 조건 달성 시 배지 자동 발급
5. 첫 동기화 후 "배지 획득!" 알림 → 배지 컬렉션 화면으로 이동

> **온보딩 퀘스트 (티켓 [20260927_2123](../../tickets/p2-normal/20260927_2123_Feature_온보딩-퀘스트-도입.md)):**
> 2단계 뒤 신규 가입자의 홈 상단에 «JAM! 시작하기» 카드가 뜬다(유저 화면에는 「퀘스트」라는 말을 쓰지 않는다, 2026-10-21 티켓 20261021_1248 2회). 카드의 [다음 단계]로 실제 화면(홈 동기화 버튼·인벤토리·드랍 가상 지도·믹서·미션)에
> 들어가 연출용 데이터로 7단계(동기화 → 가방 → 픽업 → 레시피 확인 → 믹스 성공 → 드랍 → 둘러보기, 구역 라벨 «미리 해보기»)를 해 본다. 같은 카드 아래에는 «내 활동으로 3단계» 체크 목록이 붙고,
> 연출을 끝냈거나 건너뛰면 이 실제 구역이 카드 위로 올라와 지금 할 차례 한 가지에 버튼 하나를 둔다(카드 모양은 `docs/service/prd/home-feed/PRD.md` 2절). 1~7단계는 실제 배지·아이템·포인트를 만들지 않고 `user_onboarding_quests.step_progress`에
> 진행만 기록한다. 이와 별개로 유저가 자기 활동으로 하는 **실제 3단계**(① 걸러지지 않은 활동이 처리된 첫 동기화 ② 캡슐 열기 ③ 잠긴 아이템 배지 열기, 순서 무관)가 있고,
> 실제 3단계를 마친 순간 챕터 1을 받는다(연출 7단계와 무관, 건너뛴 유저도 같다). 완료는 «연출 7단계를 마쳤거나 건너뜀»과 «실제 3단계 완료»가 둘 다 된 뒤 기록하고,
> 그때 건너뛰지 않은 유저만 완료 배지 「JAM!」(처음 이름은 「퀘스트 클리어」, 마이그레이션 256으로 바꾼다)와 100P를 한 번 받는다(티켓 20261021_1248).
> 카드 아래 「미리 해보기 건너뛰기」로 연출만 언제든 넘길 수 있고, 건너뛰면 완료 배지와 포인트는 영구히 받을 수 없다(챕터 1은 받는다). 기능 스위치는
> `jam-web/src/lib/onboarding-quest/config.ts`의 `ONBOARDING_QUEST_ENABLED`, 관리자 미리보기는 `docs/service/SERVICE_OPERATIONS.md` §2-4.
> 2단계(인벤토리) 연출 배지 칸에는 「지금 눌러야 할 곳」 공용 펄스 강조를 준다(`.jam-quest-pulse`, 티켓 20260928_1753).
> `pickup`(3단계)·`drop`(6단계)에서는 가상 지도 마커 → 모달 내부 대상(픽업 그룹 행 / 「여기에
> 드랍」 버튼 / 드랍 아이템 칸 / 확인 버튼) 순으로 지금 눌러야 할 요소 하나에만 같은
> 「지금 눌러야 할 곳」 펄스(`.jam-quest-pulse`)가 옮겨 간다(티켓 20260928_1754, 상위 20260927_2123 Q3).
> `mix_fail`(4단계)·`mix_success`(5단계)의 `/combine`에서는 레시피 미선택 시 레시피 행 →
> 선택 후 첫 빈 슬롯(`mix_fail`) / 가방 시트 열림 시 활성 후보 행 → 시트 닫힘+빈 슬롯 시
> 다음 빈 슬롯 → 전체 충족 시 「조합하기」 버튼(`mix_success`) 순으로 같은 펄스가 옮겨
> 간다(티켓 20260928_1755, 상위 20260927_2123 Q4).

**시나리오 2 — 일상 사용 (매일 저녁)**
1. 앱 열기 → 홈("투데이") 화면에서 오늘의 현황과 투데이 카드 확인
2. 나의 배지 탭 → 새 배지 상세 보기 (선행배지, POI 위치, 조건 텍스트)
3. 인벤토리에서 아이템 확인 → 컬렉션 슬롯에 장착하거나 믹스 재료로 사용

**시나리오 3 — 야외 탐험 (드랍/픽업)**
1. `/drops` 화면에서 네이버 지도로 주변 POI·드랍된 아이템 확인
2. 이동 중 POI 반경 내에서 아이템 픽업 또는 직접 드랍
3. 드랍된 아이템은 다른 유저가 픽업할 때까지 그 자리에 남음(만료 없음), 시스템도 상시 자동 배치(앰비언트 드랍)

**시나리오 4 — 컬렉션 완성 (믹스/미션)**
1. 컬렉션에서 트라이브별 슬롯 진행도 확인
2. `/combine`에서 레시피를 검색해 고르고 믹서 화면에서 슬롯(2~10개)을 탭 → 가방 바텀시트로 보유 배지를 채워 믹스 → 전체 슬롯이 충족되면 지정 보상(포인트·배지) 확정 획득
3. `/missions`에서 진행중 미션 참가 → 완료 시 배지+포인트 보상

**시나리오 5 — 실물 패치 구매 (미구현)**
- 배지 상세 화면에 "실물 패치 구매 가능" 조건은 존재(`patch_available`)하나, 실제 D2C 스토어 연결 플로우는 아직 구현되지 않음

## 3. 핵심 기능 (2026-08-06 기준 실제 구현 상태)

| 기능 | 설명 | 상태 |
|------|------|------|
| 구글 소셜 로그인 | Supabase Auth + Google OAuth | ✅ |
| 온보딩 | 2단계 카드형. 1단계 아이디(중복확인)·이름, 2단계 트라이브(`tribes.is_active=true`만 노출) 선택 + 프로필이미지(선택). 트라이브는 온보딩에서 1회 설정하며 유저는 직접 바꿀 수 없다(바꾸는 길은 어드민 변경뿐이고, 로그인한 유저가 브라우저에서 본인 `tribe_id`를 직접 쓰면 DB 트리거가 거절한다 — 마이그레이션 260, 티켓 20261021_1247). 온보딩 2단계 저장도 트라이브가 비어 있을 때만 반영한다. 지역·운동종목 선택은 20260909 폐지 | ✅ |
| 트라이브 게이트 | 트라이브를 고르기 전에는 앱의 어느 화면도 쓸 수 없다. 판정 기준은 `users.tribe_id` 하나다(`onboarding_completed_at`이 아니다). 로그인 직후만이 아니라 앱에 들어오는 모든 경로가 지나는 `(main)` 레이아웃이 트라이브가 없으면 `/onboarding`으로 보낸다. 고르기 화면은 `(main)` 밖의 `(onboarding)` 라우트 그룹에 있어 이 판정을 지나지 않는다(되돌림 반복 없음, 하단 탭 없음). 로그인 콜백·`/profile`·고르기 화면의 «이미 끝난 유저는 홈으로» 조건도 같은 기준이다. Strava 연결 시작(`/api/strava/auth`)과 동기화(`/api/strava/sync`)는 403 `tribe_required`로 거절하고, 연결 콜백은 연결을 저장하지 않고 `/onboarding`으로 보낸다. 트라이브를 읽지 못하면 API는 «있음»으로 보지 않고 거절하며, 화면 게이트는 막지 않고 로그만 남긴다. 고르기 화면은 트라이브 카드를 세로 1열로 보이고, 카드를 눌러도 확정되지 않으며 «이 트라이브로 시작하기»를 눌러야 확정된다. 트라이브가 없는 유저는 프로필 화면에 닿지 못하므로, 온보딩의 두 단계(아이디·이름, 트라이브 고르기) 맨 아래에 프로필과 같은 문구의 «로그아웃»을 둔다. 로그아웃에 실패하면 «네트워크 오류가 발생했어요.»를 보이고 다시 누를 수 있다. 제목 아래에 «한 번 고르면 바꿀 수 없어요»와 «동기화로 받는 아이템 배지는 고른 트라이브의 것이에요»를 보인다. 티켓 20261021_1247(어드민의 트라이브 변경은 아래 «어드민 트라이브 변경» 행) | ✅ |
| 어드민 트라이브 변경 | 어드민이 트라이브를 고른 유저의 트라이브를 바꾼다(운영 로직 2.4절). 사유는 고정 목록(유저가 잘못 골랐어요·유저가 옮기길 원해요·운영 정정·기타)에서 고르고 «기타»는 메모가 필수다. 변경 한 번은 DB 함수 `admin_change_user_tribe`가 한 트랜잭션으로 처리한다: 트라이브 갱신 → 새 트라이브가 대상이 아닌 트라이브 제한 미션의 참가 취소(`mission_cancel_for_tribe_change`, 이미 받은 보상·완료 기록은 그대로) → 변경 기록(`user_tribe_changes`: 누가·언제·어디서 어디로·왜·취소된 미션 수). 트라이브가 없는 유저·비활성 트라이브·같은 트라이브는 거절한다. 성공하면 유저에게 «트라이브가 바뀌었어요» 소식(`tribe_changed`, 사유 없음)이 한 건 가고, 취소된 미션이 있으면 참가 취소 소식이 한 건 더 간다. 이미 가진 배지·잼·챕터는 그대로다. API는 `POST·GET /api/admin/users/[id]/tribe`. 티켓 20261021_1247 | ✅ (마이그레이션 258~261 공용 DB 적용 완료, 어드민 유저 상세의 트라이브 구역 구현 완료) |

## 6. 안 만드는 것 (Out of Scope — 영구)

- **자체 GPS 트래킹 UI** — 이유: JAM! 핵심 철학 "Tracker-less". Strava/Garmin이 이미 잘 함 (드랍/픽업 지도는 위치 조회용이지 트래킹이 아님)
- **과거 데이터 소급 분석** — 이유: 연동 시점 이후 활동만 인정. `reconcile` Cron은 누락 보정 목적으로 별개
- **Garmin 연동** — 미착수. Strava 단일 소스 유지 중
- **Apple Health 연동** — 이유: 웹 앱에서 직접 접근 불가. 별도 네이티브 앱 필요
- **D2C 실물 패치 외부 URL 연결** — 이유: D2C 쇼핑몰은 앱 내 구현 예정으로 결정됨 (2026-08-07 확정). 현재 배지 조건 필드(`patch_available`)만 존재, 구매 플로우 미구현
- **P2P 실시간 채팅** — 이유: 거래 알림은 앱 내 알림으로만 (거래 자체도 아직 미구현)
- **앰비언트 채널 자동 밸런싱** — 유저별 컬렉션 보유 현황·발행 현황 등을 근거로 앰비언트 드랍과
  액티비티 드랍엔진 채널의 희귀도 분포를 교차 자동 조정하는 시스템. 이유: 현재는 어드민이 수동
  설정한 3축 값을 그대로 실행할 뿐(§3.12 참고), 자동 조정 로직은 향후 계획(티켓
  [20260826_009](../../tickets/p1-high/20260826_009_BadgeEngine_앰비언트-POI-드랍-재도입.md) §6).
