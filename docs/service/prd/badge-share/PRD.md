# 배지 공유 기능 — PRD

> 생성일: 2026-08-21
> 관련 티켓: `20260821_003`(UI 셸, CLOSED), `20260821_004`(이미지 생성·스트라바 연동·OS 공유시트, CLOSED),
> `20260903_1047`(공유/저장 2버튼 분리, CLOSED), `20260903_1122`(저장 버튼 iOS 미저장 버그 수정, CLOSED),
> `20260911_1102`(이미지 선택 캐러셀 추가, 이후 폐지), `20261115_1249`(체크무늬 카드 한 장과 복사·저장·더보기, Strava 기록 카드 폐지. 상위 티켓 `20261115_1247`)

## 1. 배경

과거 드랍 공유 카드 기능(`ShareCardModal`, `/api/drops/{id}/share`)은 2026-08-17 메뉴 개편으로
삭제됐다(티켓 `20260731_004`). 이는 이후 제대로 재개발하기 위한 임시 삭제였고, 이 PRD는 그
정식 재구현 스펙을 정의한다.

## 2. 한 줄 요약

획득한 액티비티/POI/아이템 배지 상세 페이지에서 배지 이미지 한 장(투명 PNG)을 클립보드에 복사하거나,
기기에 저장하거나, OS 공유시트로 내보낼 수 있게 한다.

## 3. 대상 화면

`jam-web/src/app/(main)/badges/[id]/page.tsx` — activity/POI/item 3개 배지 타입이 공통으로
쓰는 단일 라우트. 콘텐츠 맨 끝에 전체 폭 «공유하기» 버튼을 두고(2026-11-10 사용자 지시, 이전에는 TopNav 우측 공유 아이콘) 3타입 공통으로 동작한다.

## 4. 핵심 플로우

1. 유저가 배지 상세 페이지 맨 끝의 «공유하기» 버튼을 누른다.
2. 바텀시트(`detent="compact"`, 제목 없음)가 열리고, 좌우 24px 여백의 **정사각 투명 체크무늬 카드 한 장**
   안에 배지 이미지를 가운데에 카드 폭의 약 70% 크기로 보여준다(카드 최대 폭 360px). 이미지가 준비되기 전에는
   같은 카드 안에 로더가, 만들지 못했으면 같은 카드 안에 실패 문구가 보이고 이때는 버튼 줄이 없다.
3. 이미지가 준비되면 바텀시트 하단에 높이 56px 버튼이 아이콘(위)과 이름표(아래)로 나란히 보인다. 앞에서부터 순서는 다음과 같다.
   - **복사하기**(`CopyIcon`, primary): 이미지를 `image/png`로 클립보드에 쓴다. 성공하면 «이미지를 복사했어요» 토스트.
     브라우저가 이미지 복사를 지원하지 않거나 쓰기가 거절되면 «저장하기»를 안내하는 실패 토스트(현상 → 원인 → 해결).
     Safari는 사용자 동작 안에서만 클립보드 쓰기를 허용하므로 클릭 핸들러에서 곧바로 시작하며, 끝날 때까지 중복 탭은 무시한다.
   - **저장하기**(`DownloadIcon`, secondary): 플랫폼별로 동작이 다르다(§8 «저장하기의 플랫폼 제약»).
     - iOS: `navigator.share({ files })`로 OS 공유시트를 연다(`20260903_1122`). 시트가 뜨기 직전 «곧 열리는 공유 시트에서 '저장'을 눌러주세요» 안내 토스트를 띄운다.
     - Android: `<a download>`로 저장 → MediaStore가 스캔해 갤러리/사진 앱에 자동 노출. 저장 뒤 성공 토스트.
     - 데스크톱(PC): `<a download>`로 브라우저가 지정한 폴더에 내려받는다. 저장 뒤 성공 토스트.
   - **더보기**(`MoreIcon`, secondary): `navigator.share({ files })`로 OS 공유시트를 연다. 취소(`AbortError`)는 조용히 넘긴다.
     이미지가 준비된 시점에 `navigator.canShare({ files })`가 참일 때만 그린다. 거짓이면(주로 PC) **버튼 자체를 그리지 않고**
     복사하기·저장하기 두 개가 반반 폭을 차지한다(비활성으로 남기지 않는다).
4. 파일은 `{배지이름}-badge.png`다.

## 5. 이미지 생성 방식

- **클라이언트 Canvas API**로 생성한다. 어드민의 `bakePreviewToBlob.ts`(`jam-web/src/app/admin/badges/`)의
  `canvasToBlob`을 재사용해 `canvas.toBlob()`으로 PNG를 뽑는다. 별도 서버사이드 렌더링 파이프라인은 두지 않는다.
- 배지 원본 이미지를 **300×300 정사각형 투명 PNG**에 `contain`으로 맞춰 그린다(`buildBadgeImageBlob`).
  통계·로고 없이 배지 이미지만 담는다. 미리보기는 이 PNG를 키우거나 줄이는 transform 없이 카드 폭의 약 70%로 보여준다(300px 원본을 늘리면 흐려진다).
- 시트를 열 때마다 그때그때 새로 생성한다. DB에 캐싱하지 않는다 — `user_activity_badges.share_card_url`
  (과거 공유 카드 기능이 남긴 죽은 필드)은 재사용하지 않는다.

## 6. 폐지한 Strava 기록 카드 (`20261115_1249`)

시트에 두 번째 항목으로 있던 **Strava 기록 카드**(1080×1920, 거리·페이스·시간 + 로고 합성, 활동·체크인 배지는 `share-data`
API로 페이스·시간을 재조회)는 폐지했다(사용자 결정 2026-11-15, 상위 티켓 `20261115_1247`). 이유는 사용자가 요청한 공유가
«배지 이미지만 투명 배경으로»이기 때문이다. 함께 지운 것은 다음과 같다.

- `buildBadgeShareBlob`의 카드 합성(남긴 `buildBadgeImageBlob`·`drawContain`은 `buildBadgeImageBlob.ts`로 옮겼다)
- `GET /api/badges/{id}/share-data` API와 그 시험, `d.badges`의 Strava 오류 문구(`shareErrorStrava*` 등)와 캐러셀 문구
- `page.tsx`의 공유 전용 `strava_connections` 조회와 `BadgeShareButton`의 `stravaConnected`·`subjectUsername`·`level`·`earnCount` 속성

이에 따라 배지 공유는 Strava 연동 상태와 무관하다(연동이 끊겨 있어도 배지 이미지 공유는 동일하게 동작한다).

## 7. 데이터 소스

- 배지 이미지: 기존 배지 레코드의 `image_url`. 그 밖의 데이터는 쓰지 않는다.

## 8. 예외 처리

- **공유는 본인 배지에서만 가능하다**: 타인의 배지 상세(`isOwnBadge=false`)에서는 공유 버튼 자체를 노출하지 않는다(비활성화가 아니라 미노출).
- **미획득 배지는 버튼을 그리지 않는다**(2026-11-10 사용자 지시, 이전에는 비활성 표시): 버튼은
  본인이 획득한 배지(`isOwnBadge && hasEarned`)에서만 보인다. 미획득 배지와 타인의 배지에는 두지 않는다.
- **이미지 변환 실패·이미지 URL 없음**: 시트를 연 뒤 카드 안에 «이미지를 만들지 못했어요 / 잠시 후 다시 시도해 주세요»를 보이고 버튼 줄은 그리지 않는다. 스크린 리더에는 같은 문구를 `aria-live`로 한 번만 알린다.
- **Web Share API 미지원**(`canShare({ files })`가 거짓): «더보기» 버튼을 그리지 않는다(§4).
- **«저장하기»의 플랫폼 제약(`20260903_1047`, `20260903_1122`)**: 웹 표준상 사용자 승인 없이
  iOS Photos 라이브러리에 직접 쓰는 API가 없다 — `<a download>`는 Files 앱에만 저장되고 사진
  앱에는 들어가지 않는다. 시스템 공유시트를 띄우지 않고 곧장 저장하는 API도 없다("시트 없이
  1탭 저장"은 불가능). 이 제약 때문에 iOS "저장"은 `navigator.share`로 여는 공유시트 경로만
  실제로 Photos에 저장되는 것으로 확인됐고(§4), 저장 완료 여부를 코드로 확인할 수 없어
  "저장했어요"로 단정하지 않고 시트 진입 전 안내 토스트만 띄운다. iOS에서는 «저장하기»와 «더보기»가 같은 시트를 띄운다.
- **버튼 폭**: 폭 320~360px에서 버튼 한 칸이 88~99px라 «아이콘 24px + 간격 8px + 4글자»를 한 줄에 둘 수 없어, 버튼 안을 아이콘 위·이름표 아래 세로 배치로 한다(글자를 줄이거나 말줄임하지 않는다). 터치 영역은 56px 높이 × 최소 88px 폭이다.
- **미해결 후속**: 흰색 위주 배지는 연한 체크무늬(`--foreground` 8%) 위에서 대비가 약할 수 있다. 사용자가 투명 체크무늬를 확정했으므로 그대로 두고, 실기기에서 흰 배지가 안 보이면 후속 티켓으로 올린다.
