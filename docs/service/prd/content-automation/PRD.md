# 홈피드·배지·미션·드랍 운영 자동화 파이프라인 — PRD (JAM 2.0)

## 1. 한 줄 정의

트렌드·시즌·세그먼트·컨텐츠 코퍼스를 입력받아 홈피드 주간 편성안·미션 초안·드랍 일정을 주간 운영 묶음 JSON으로 만들고, 어드민 운영툴에서 사람이 승인하면 자동 예약 공개하며, 반응 계측과 패턴 사전으로 다음 기획에 되먹이는 운영 자동화 체계다.

---

## 2. 원칙

1. **완전 자동 게시는 없다.** 외부로 노출되는 모든 컨텐츠(홈피드 카드, 미션, 시스템 드랍 등)는 사람이 운영툴에서 승인해야 예약 공개된다.
2. **개인화는 세그먼트 단위다.** 유저 1인 단위 추천 엔진은 만들지 않는다. 노출 태그(§5) 조합으로 편성한다.
3. **경제 수치와 안전 규칙은 자동화가 바꾸지 않는다.** 배지 드랍 확률, 잼 산식, 캡슐 충전 비용 같은 밸런스 수치는 기획 대상이 아니다. 날씨는 야외 활동을 강요하는 조건으로 쓰지 않고, 밤 조건과 캡슐 개봉 횟수는 순위형 미션의 기준으로 쓰지 않는다(§7).
4. **정치·재난·사건사고·혐오 소재는 자동 제외한다(§10).** 통과한 소재만 윈터가 세계관 톤을 검수한다.
5. **운영툴(`/admin/ops-inbox`)이 단일 승인·예약 관문이다.** 에이전트는 운영 묶음을 `POST /api/admin/ops-inbox`로 제출하고(구현됨), 승인된 항목은 예약 대상별 핸들러가 서비스 자원으로 만든다(구현됨, §3).
6. **세계관 원문을 왜곡하거나 임의로 창작하지 않는다.** 트라이브 정본 서사(`docs/plan/jam2/tribe-rethink/`)의 원문이나 승인된 발췌만 인용한다.
7. **묶음이 도착하면 슬랙으로 알린다(구현됨).** 제출 API가 `#jam-report`에 도착 알림과 운영툴 링크를 보내고 결과를 결정 기록(`ops_decisions.slack_result`)에 남긴다.
8. **모든 기획은 이유를 단다(필드 검증은 구현됨, 루틴이 채우는 일은 예정).** 묶음에는 기획 제목을, 항목에는 기획 이유(트렌드·시즌·날씨·신호·패턴)를 붙인다. 운영자가 "왜 이 기획인지"를 칩 하나로 알 수 있어야 한다. 필드 형식은 [`admin-boards/PRD.md`](../admin-boards/PRD.md) §5다.

## 4. 컨텐츠 코퍼스와 활성 규칙

생성 층이 참조하는 코퍼스는 트라이브 서사, 컬렉션 서사, 아이템 배지 설명이다. 활성 판정은 구현돼 있다(`lib/content-corpus/active.ts`).

| 코퍼스 | 출처 | 활성 판정 |
|---|---|---|
| **트라이브** | `tribes.description`·`tribes.tagline` (정본 서사: `docs/plan/jam2/tribe-rethink/`) | `tribes.is_active` |
| **컬렉션 서사** | `item_books.story_text` | `item_books.is_active`이고 소속 트라이브도 활성 |
| **아이템 배지** | `badges.description` | `deleted_at IS NULL`이고 소속 컬렉션·트라이브가 모두 활성 |

**지금 DB의 활성 상태는 출시 전 과도기다.** 새 트라이브 5개(한입만 연구회·찰칵단·비사이드 레코즈·소나무 잡화점·혼자들)와 옛 트라이브 3개가 함께 켜져 있고, 옛 방식 컬렉션을 끄는 정리 SQL은 오픈 직전에 적용한다. 적용 순서와 현재 수치의 정본은 [`12 JAM 2.0 오픈 전후 적용 순서`](<../../../plan/jam2/12 JAM 2.0 오픈 전후 적용 순서.md>)다. 이 문서에는 수치를 적지 않는다.

### 생성 규칙
1. **비활성 컨텐츠는 추천하지 않는다.** 카드의 목적지, 미션 보상, 드랍 대상은 활성 컨텐츠에서만 고른다.
2. **세계관 배경 인용은 따로 본다.** 비활성 트라이브·컬렉션의 글은 에디토리얼 본문의 배경으로 인용할 수 있지만, 획득·방문을 유도하는 대상으로 지정하지 않는다.
3. **자동 선택(구현됨).** `/api/admin/content-corpus`를 후보 ID 없이 부르면 KST ISO 주차 순환으로 활성 후보만 골고루 고른다(`lib/content-corpus/select.ts`).

## 5. 세그먼트 태그

노출 태그의 판정과 목록은 [`home-feed/PRD.md`](../home-feed/PRD.md) §4가 정본이다(코드에서 생성되는 표). 이 문서에 태그 표를 다시 적지 않는다.

- **지금 있는 태그(구현됨):** 항상 붙는 `all`과 시간대 5개, 미션 참여 2개, 컬렉션 2개, `strava_stale_14d`, `new_user`, 날씨 4개, 특일 3개다.
- **JAM 2.0 태그(구현됨, 티켓 20261026_2030 1·2회차):** 챕터 구간 4개·캡슐 2개·잼 2개·인벤토리 2개, 그리고 소속 트라이브 태그 `tribe_<트라이브 ID>`(구현됨, 2회차)이다. 태그 이름과 판정은 [`home-feed/PRD.md`](../home-feed/PRD.md) §4가 정본이다. 트라이브 태그 값은 트라이브 ID(UUID)라 읽기 어렵고, 운영 화면(카드 폼·표·상세)이 트라이브 이름으로 보인다. 에이전트가 묶음에 쓸 때는 트라이브 ID를 `tribe_` 뒤에 소문자로 붙인다.

## 6. 컨텐츠 유형 카탈로그 (17종 유지)

사용자 결정(2026-10-26)에 따라 유형 카탈로그 전면 개편은 보류하고 17종(T01~T17)을 유지한다. 화자와 대상은 새 트라이브 5개의 정본 서사에서 고른다. JAM 2.0에 없는 조건에 걸리는 유형은 「미편성」으로 둔다.

**새 체계 주간 기획(운영 묶음)은 기사를 만들지 않는다(사용자 결정 2026-10-31, 티켓 20261031_2049).** 아래 T01(에디토리얼 기사)과 기사형 연재는 에이전트가 제안하지 않고, 운영자가 직접 쓸 때만 쓴다. 에이전트가 읽는 패턴 사전의 «쓰는 카드 모양»에서 기사(`hero`)를 뺐고 돔·티켓을 배정했다([home-feed/PRD.md](../home-feed/PRD.md) §6).

| **T16** | 여행·지역 이동 감지 | 평소 밖 지역 활동 | 최근 활동 위치 | 담백, 좌표·경로 언급 금지 / 공통 | 지도 |
| **T17** | 계절 전환 예고 | 시즌 전환 임박 | 시즌 캘린더 | 세계관 목소리 / 다음 시즌 트라이브 | 미션 목록 |

T05·T13이 체크인 지점을 홈피드 컨텐츠로 내보이는 유형이다. 트렌드에서 **아직 없는 지점**을 새로 만들어 소개하는 일은 지금 예약 대상에 없다(§3 ⑤의 6종). 지점 만들기를 예약 대상에 더할지는 티켓 20261026_2029에서 정한다.

### 편성 규칙
카드 모양은 `shape` 7종(`hero`·`poster`·`square`·`brief`·`list`·`dome`·`ticket`)이다(정본: [`home-feed/PRD.md`](../home-feed/PRD.md) §6). 옛 `layout_type`(`large_thumbnail` 등)은 쓰지 않는다.

1. **요일마다 모든 유저가 보는(`all`) 카드가 1장 이상 있다.** 그중 대표 카드는 이미지가 있는 모양 중 하나로 한다.
2. **같은 모양을 연달아 두지 않는다.** 모양은 컨텐츠 특성으로 고른다.
3. **트라이브 제한 카드는 그 트라이브 유저에게만 보인다.** 다른 트라이브 유저의 피드가 비지 않도록 `all` 카드가 받친다.
4. **미션 소개 카드는 미션 대표 이미지를 그대로 쓴다.**

글자수 가이드는 새 비율(16:9·4:5)의 실측값으로 바꾸는 일이 티켓 20260930_1504에 남아 있다.

## 7. 미션 기획 (`kind: "mission"`)

에이전트는 주간 묶음에 트라이브 미션과 공통 미션을 함께 기획한다. 트렌드에서 출발한 미션은 기획 이유에 트렌드를 단다(원칙 8).

### 7.1 미션 구분
- **트라이브 미션(주 1~2건):** 특정 트라이브만 참여한다. 참여 트라이브는 `mission_allowed_tribes`로 지정한다(구현됨, 마이그레이션 249).
- **공통 미션(주 1건 또는 상시):** 트라이브 제한이 없다.

### 7.2 미션 조건 가드레일 (구현됨)
1. **밤 조건은 순위형으로 쓰지 않는다.** 달성형·개인형만 허용하고 안전 안내 「어두울 때는 무리하지 마세요」를 붙인다.
2. **캡슐 개봉 횟수는 순위형 조건으로 쓰지 않는다.**
3. **모은 잼(`jam_period_earned`) 미션은 홈 랭킹 보드에 연결하지 않는다.** 진행값은 미션 상세에서만 보인다(`lib/admin/ranking-mode-mission-guard.ts`).
4. **날씨·기온은 미션 조건으로 쓰지 않는다.**

## 8. 시스템 드랍 기획 (`kind: "drop_schedule"`)

시즌 행사, 주말 게릴라, 미개척 지점 활성화를 위해 에이전트가 드랍 일정을 기획한다. 저장 위치는 `ambient_drop_schedules`다(구현됨, 마이그레이션 209).

1. **지점:** 지점 카테고리 기반 분배 또는 지점 목록 직접 지정.
2. **아이템:** 아이템 배지 목록 또는 컬렉션 지정.
3. **수량 상한:** 예약 1건의 드랍 합계는 100개 이하다(구현됨, `AMBIENT_SCHEDULE_MAX_TOTAL`).
4. **종료 시각 없음:** 드랍은 유저가 주울 때까지 남으므로 놓은 직후 운영 항목을 「종료」로 닫는다.

## 9. JAM 2.0 특화 패턴 5개 (사용자 확정)

1. **피드 + 지점 + 드랍 + 미션 게릴라 묶음.** 축제나 트렌드 장소를 찾으면 홈피드 카드·드랍·연계 미션을 서로 연결(`links`)해 한 묶음으로 제안한다.
2. **컬렉션 마지막 한 칸 추적.** 9칸 중 7~8칸을 채운 유저층에 빠진 배지가 나오는 지점으로 드랍을 모으고 대상 카드를 낸다.
3. **잠긴 배지 구출과 인벤토리 정체 해소.** 잠긴 배지가 쌓이고 잼이 부족한 신호가 보이면 `jam_period_earned` 미션과 해금 안내 카드를 묶는다.
4. **다른 트라이브 원정 미션.** 소속 밖 컬렉션이 많이 비면 트라이브 미션으로 다른 트라이브 지점 방문을 유도하고 그 트라이브 배지를 보상으로 준다.
5. **잊힌 지점 보물찾기.** 최근 30일 체크인·픽업이 0건인 지점에 Rare·Epic 드랍을 1~2개 두고 탐험 카드를 낸다.

## 10. 소재 입력과 자동 제외

### 10.1 소재 출처
- **자동 수집:** 기상청 단기예보와 공공 특일정보(구현됨), TourAPI 지역 행사(수집 스크립트 `scripts/tour-festivals.mjs`만 있고 루틴 연결은 1504).
- **사용자가 등록한 트렌드 출처(읽기 API는 구현됨, 루틴이 읽는 일은 예정):** 해시태그·채널·검색어 추이처럼 운영자가 어드민에 등록한 출처와, 직접 올린 자료(`docs/operations/inbox/trends/`)다. 등록된 출처 목록은 `GET /api/admin/ops-trend-sources`(읽기 토큰, 켜진 출처만)로 읽는다(티켓 20261026_2033). 에이전트는 등록된 출처만 읽고, 읽은 트렌드와 처리 결과(반영·보류·제외)를 묶음에 함께 제출한다. 등록 화면과 필드는 [`admin-boards/PRD.md`](../admin-boards/PRD.md) §6.4다.

### 10.2 자동 제외 범주
| 범주 | 기록 사유 | 예외 |
|---|---|---|
| **정치** | 정치적 논쟁 소재 | 없음 |
| **재난·사고** | 재난·사고 소재 | 순수 기상특보 안전 안내만 허용 |
| **범죄·사건** | 범죄·사건 소재 | 없음 |
| **혐오·비하** | 혐오·비하 표현 | 없음 |
| **실존 인물** | 실존 인물 언급 | 없음 |
| **저작권** | 저작권 직접 인용 | 작동 원리 차용만 허용 |
| **비교·순위형 밈, 의료 조언** | 세계관 미배정 소재 | 없음 |

자동 제외한 트렌드도 「제외」 결과와 범주를 남겨 운영자가 걸러진 것을 볼 수 있게 한다.

## 11. 주간 주기

화요일 기획 → 수요일 결정 → 목요일 공개 순서를 유지한다.

```
[화 09:00] 주간 루틴 시작 (시작 기록 1회: 기록 API는 구현됨, 루틴이 부르는 일은 예정)
   ↓  윤진 기획 → 윈터 세계관 검수 → 혜린 밸런스 점검
[제출] POST /api/admin/ops-inbox (단계 기록·기획 이유·트렌드 포함)
   ↓  슬랙 #jam-report 도착 알림 (구현됨)
[화~수] 운영자가 운영 상황판에서 검토·수정·홈피드 미리보기
   ↓
[수 18:00까지] 「승인하고 예약」 한 번 (승인과 예약 등록을 합친다, 구현됨 · 티켓 20261026_2022)
   ↓  핸들러가 다음 주 월~일 자원을 공개 전 상태로 만든다
[공개 시각] 10분마다 도는 상태 맞추기가 예약됨 → 게재중 → 종료로 바꾼다 (구현됨)
```

승인과 예약 등록은 한 요청에서 끝난다(`POST /api/admin/ops-inbox/[bundleId]/execute`의 `approve`). 실패하면 연결된 항목을 함께 되돌리는 동작은 그대로다.
