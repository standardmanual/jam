# 슬롭 사전

> 신설 문서 (티켓 20260918_0423, 팀 공통 규칙 9번). "슬롭 제거" 중 **글 슬롭**의 금칙 표현과
> 대체 표현을 모은다. 초기 목록은 AI 씬(생성형 AI로 작성된 글에서 자주 보이는 상투구)의
> 보편 기준으로 시작하고, **사용자가 거슬린 표현을 발견하면 이 문서에 직접 추가**하는 구조다.
>
> 이 문서는 `docs/specs/UX_WRITING_GUIDELINE.md`(제품 UI 문구의 용어·톤·구조 규칙)와 역할이
> 다르다 — 그쪽은 "무엇을 어떻게 쓸지", 이 문서는 "무엇을 쓰지 말지"다. 둘 다 참조한다.

## 담당

글 쓰는 전원(카리나·아현·혜린·윈터·윤진·하니) + 게이트 리뷰(민지). 1·2절(패턴 매칭 가능한
단어·문장)은 `scripts/check-slop.mjs`(자동화 A1)가 diff의 추가 라인에서 기계적으로 먼저
거른다. 문맥 판단이 필요한 항목(4절)은 기계 검사 대상이 아니라 민지가 게이트 리뷰에서 직접
판정한다(티켓 20260918_1033 — 별도 `humanize-korean` 플러그인 호출을 없애고 민지의
체크리스트로 흡수).

## 1. 금칙 단어·표현

### 관습적 비유
| 금칙 | 왜 슬롭인가 | 대체 |
| --- | --- | --- |
| "태피스트리"(tapestry), "축소판" | 근거 없이 분위기만 만드는 관습적 비유 | 실제로 무엇의 조합·요약인지 직접 서술 |
| "여정"(journey) | 번역투 상투구 | "과정", "동안" 또는 생략 |
| "나침반" | 근거 없이 방향성만 암시하는 관습적 비유 | 실제 기준·지표를 직접 서술 |

### 과장된 수식어
| 금칙 | 왜 슬롭인가 | 대체 |
| --- | --- | --- |
| "혁신적인", "획기적인", "게임체인저" | 근거 없는 과장 | 구체적 효과를 직접 서술 |
| "무한한", "궁극의", "완벽한" | 근거 없는 과장 | 구체적 조건·수치로 대체 |
| "다채로운", "역동적인" | 뻔한 형용사, 검증 불가능 | 실제 구성 요소·수치로 대체 |
| "압도적", "파격적", "폭발적", "전례 없는" | 근거 없는 과장(hype 어휘) | 구체 수치·사실로 환원 |
| "시사하는 바가 크다", "주목할 만하다", "매우 중요하다" | 의의를 과장만 하고 근거가 없음 | 삭제하거나 구체적 결론으로 |

### 번역투 표현
| 금칙 | 왜 슬롭인가 | 대체 |
| --- | --- | --- |
| "~을 통해" | 번역투, 없어도 뜻이 통함 | 문장을 능동형으로 재구성 |
| "~되어진다", "~지게 된다"(이중 피동) | 문법적으로 항상 어색한 이중 피동 | 능동 또는 단일 피동("판단되어진다" → "판단된다") |
| "업계 지형"(landscape 직역) | 원어 관용구를 그대로 옮긴 번역투(단, "지형" 단독은 트라이브·POI 세계관 텍스트에서 정상적으로 쓰이므로 금칙에서 제외) | "현황", "구도" 또는 구체적 서술 |
| "깊이 파고들어"(delve into) | 번역투 상투구 | "자세히 살펴보면", "따져보면" |
| "숨가쁘게 돌아가는"(fast-paced) | 번역투 상투구 | 실제 속도·주기를 수치로 서술 |

### 의미 없는 수식·반복
| 금칙 | 왜 슬롭인가 | 대체 |
| --- | --- | --- |
| "다양한", "여러 가지" | 의미 없는 수식, 개수·종류를 감춤 | 실제 개수·목록으로 대체 |
| 반복 강조("정말", "진짜", "너무너무") | 의미 없는 강도어 반복 | 필요하면 구체적 근거로 대체, 없으면 삭제 |
| 이모지 남발 | 내용을 대체하지 못하는 장식 | 필요한 곳 1개 이내, 없어도 무방하면 삭제 |
| "만나보세요", "확인해보세요"(남발) | 마케팅 상투구 | 구체적 행동·혜택으로 대체 |

## 2. 금지 문장

글의 시작과 끝에서 공간만 차지하고 정보를 전달하지 않는 "메타 문장"이다. 단어 하나가
아니라 문장 전체 패턴을 금지 대상으로 본다.

| 유형 | 예시 | 대체 |
| --- | --- | --- |
| 무의미한 서론 | "오늘날 빠르게 변화하는 현대 사회에서~", "디지털 시대가 도래함에 따라~", "이 글에서는 ~에 대해 자세히 알아보겠습니다.", "오늘은 ~에 대해 알아보겠습니다", "크게 세 가지로 나눌 수 있다" | 배경 설명 없이 바로 본론(핵심 정보·결론)부터 시작 |
| 불필요한 범용성 강조 | "초보자부터 전문가까지 모두에게~", "규모에 상관없이 모든 비즈니스에서~" | 실제 대상 독자·조건을 구체적으로 명시하거나 생략 |
| 기계적인 주의 환기 | "~라는 점을 유의하는 것이 중요합니다.", "여기서 한 가지 명심해야 할 사실은~" | 정말 중요하면 그 내용 자체를 본문에 바로 서술 |
| 뻔한 요약·마무리 | "결론적으로 말하자면~", "요약하자면~", "이상으로 마치겠습니다", "이 정보가 여러분의 선택에 도움이 되셨기를 바랍니다.", "~할 때입니다", "~시점입니다", "~할 순간입니다" | 다음 행동(CTA)이 있으면 그것만 남기고, 없으면 구체적 동사로 직접 단언 |

## 3. 안티 슬롭 구조 원칙

단어·문장 필터링을 넘어, 글 전체의 정보 밀도를 높이기 위한 작성 지침이다. `verify`
스크립트가 기계적으로 검사하기 어려운 영역이라 글 쓰는 사람이 직접 점검한다.

- **서론 없는 본론 진입**: 배경 설명·인사말·예열 문장을 삭제하고 첫 문장부터 핵심 정보나
  결론을 배치한다.
- **묘사 대신 구체적 팩트**: "매우 빠르고 효율적인 시스템"처럼 뻔한 형용사 대신 "처리
  속도를 3배 높인 시스템"처럼 사실과 수치로 증명한다.
- **행동 중계 금지**: "다음은 세 가지 장점입니다"처럼 무엇을 쓸지 예고하지 말고, 곧바로
  목록·내용을 제시한다.

## 4. 문맥 판단이 필요한 항목 (민지가 게이트 리뷰에서 직접 판정)

단어·문구 하나로는 매칭되지 않고 문장 앞뒤를 봐야 슬롭인지 아닌지 판단되는 항목이다.
`check-slop.mjs`의 대상이 아니며, `copy`·`ui`·`content` 유형에서 민지(jam-reviewer)가
게이트 리뷰 체크리스트 12번으로 직접 본다(티켓 20260918_1033 — 이전에는 별도
`humanize-korean` 플러그인을 호출했으나, 판정에 영향을 주지 않는 제안형 단계라 실효성이
낮고 파이프라인만 복잡하게 만들어 민지의 판정 항목으로 흡수했다).

- **대명사 지시 모호성**: "그", "이것", "이는" 등이 가리키는 대상이 직전 문장에 명확히
  없는데도 쓰였는가
- **종결어미·리듬의 기계적 균일성**: 같은 종결어미가 4문장 이상 연속되거나, 문장 길이가
  부자연스럽게 고르게 반복되는가
- **완곡 표현 중첩**: "~할 가능성이 있을 수 있다"처럼 추측·유보 표현을 이중삼중으로 쌓았는가
- **격식/구어체 혼재(register 붕괴)**: 한 문서 안에서 존댓말 격식 단계(해요체/합쇼체 등)가
  근거 없이 오락가락하는가
- **형식명사·당위 구조의 어색함**: "필요한 것은 ~이다", "문제는 ~라는 점이다"처럼 주어-서술을
  에둘러 가는 구조를 반복하는가
- **의인화 추상 주어**: "기술이 묻는다", "시대가 부른다"처럼 사물·개념을 주어로 세워
  의인화하는가
- **결산 lexicon 밀집**: "결론적으로/따라서/그러므로/요약하면/정리하자면"이 한 문서에서
  3회를 넘게 반복되는가(단독 1~2회 사용은 정상적인 한국어이므로 슬롭이 아니다 — 이 이유로
  단어 자체를 1·2절 기계 검사에 넣지 않는다)
- **접속사 밀집**: "또한/나아가/아울러/게다가/더욱이/즉"이 한 문단에서 3회 이상 몰려 있는가
  (마찬가지로 단독 사용은 정상)
- **번역투 조사구 밀집**: "~에 대해(서)", "~에 기반하여/바탕으로", "가지고 있다"가 한 문단에
  반복돼 리듬을 지배하는가(단독 사용은 자연스러운 한국어와 구분되지 않는다)

판단 기준은 `docs/specs/UX_WRITING_GUIDELINE.md`의 톤앤매너 요구사항과 함께
본다. 심각하면(격식 붕괴, 지시 대상 혼동으로 의미가 불분명해짐) FAIL 사유가 되고, 경미하면
WARN으로 남긴다 — 다른 체크리스트 항목과 동일하게 판정에 실질적으로 반영된다.

## 확장 방식

1. 사용자가 거슬린 표현을 발견 → 이 표에 행 추가 (금칙·이유·대체)
2. `verify`의 금칙어 검사 목록에도 반영 (자동화 A1, 스크립트 쪽은 티켓 20260918_0421 담당)
3. 같은 표현이 검사에서 3회 이상 걸리면 대체 표현을 더 구체화

## 예외

트라이브별 목소리(세계관 캐릭터의 말투)는 윈터 검수를 거쳐 이 사전보다 우선한다 — 목소리
설정 자체가 금칙 표현을 의도적으로 쓰는 경우(패러디·풍자 톤)는 윈터가 판단한다.
