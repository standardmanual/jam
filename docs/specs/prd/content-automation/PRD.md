# 홈피드·배지·미션 운영 자동화 파이프라인 — PRD

> 직후 작성한 계획 문서다. 하위 티켓이 닫힐 때마다 해당 절을 현재 상태로 고치고, 1단계가 끝나면 `active`로 바꾼다.
> `draft`인 동안 에이전트는 이 문서를 현재 사실의 근거로 쓰지 않는다(`docs/specs/DOCUMENT_SCHEMA.md` §4.3).
> 기획 경위·결정 기록·리스크는 상위 티켓에, 이 문서는 **동작 정의와 규칙**만 담는다.

## 1. 한 줄 정의

트렌드·시즌·세그먼트·컨텐츠 코퍼스를 입력받아 홈피드 주간 편성 후보안·미션 초안·배지 추천을 자동 생성하고, 사람 승인을 거쳐 반영하며, 컨텐츠 유형별 반응을 기록해 전략 변경안과 유형 카탈로그 재평가를 주기적으로 사람에게 올리는 운영 자동화 체계.

## 2. 원칙

1. **완전 자동 게시는 없다.** 외부로 나가는 것은 전부 사람이 승인한다. 전략 변경도 시스템이 안을 올리고 사람이 승인해야 반영된다.
2. **개인화는 유저군 세그먼트 단위다.** 유저 1인 단위 추천 엔진은 만들지 않는다.
3. **경제 수치는 건드리지 않는다.** 배지 드랍 확률·포인트 보상은 자동화 대상이 아니다.
4. **정치·재난·사건사고·혐오 소재는 항상 자동 제외**하고, 나머지 소재는 톤만 조정한다(§7).
5. **제안 결과물은 리포트 문서에서 시작**하고, 리포트 방식이 4주 이상 안정 운영된 뒤 어드민 화면으로 이관을 검토한다.
6. 세계관 텍스트 원문은 요약·재작성하지 않는다. 원문 그대로 또는 윈터가 승인한 발췌만 쓴다.

## 3. 6층 구조

| 층 | 입력 | 출력 | 승인 | 저장 위치 |
|---|---|---|---|---|
| ① 입력 | 기존: 트라이브·컬렉션 진행률·유저 최근 위치·시간대·Strava 원본·**컨텐츠 코퍼스**(§4). 신규: 기상청 단기예보·특일정보·지역 축제(TourAPI)·이슈 소재(윤진, §7) | 정규화된 신호값 | 없음 | 호출 시점 계산. 외부 원자료를 상시 저장하지 않는다 |
| ② 세그먼트 | ①의 신호 | `exposure_tags` 값(§5) | 태그 정의 변경은 세션 승인 | `jam-web/src/lib/today/exposure.ts`, 정의는 이 문서 |

## 4. 컨텐츠 코퍼스와 활성·비활성 규칙

생성 층이 참조하는 코퍼스는 트라이브 10종의 세계관 설정, 컬렉션(아이템북) 100종의 서사, 아이템배지 900종의 설명 **전부**다.

| 코퍼스 | 출처 | 활성 판정 |
|---|---|---|
| 트라이브 세계관 | `tribes.description`·`tribes.tagline`(정본 서사는 `jam-doc/planning/content/TRIBES.md`) | `tribes.is_active` |
| 컬렉션 서사 | `item_books.story_text` | `item_books.is_active` |
| 배지 설명 | `badges.description` | `deleted_at IS NULL` 이고 `valid_from`·`valid_until` 기간 안. 배지 엔진의 발급 후보 필터(`jam-web/src/lib/badge-engine/index.ts`)와 같은 규칙이다 |

생성 규칙:

1. **비활성 컨텐츠는 추천·소개 카드의 대상으로 선택하지 않는다.** 대상 선택은 활성 목록에서만 한다.
2. **비활성 컨텐츠의 글(설명·서사)과 트라이브 세계관 설정은 카드 본문에 배경으로 인용할 수 있다.** 획득·방문 대상 안내로는 쓰지 않는다.
3. 대상 선택과 본문 인용은 같은 생성 호출 안에서 **분리 판정**한다.
4. 코퍼스를 통째로 프롬프트에 넣지 않는다. 유형별로 필요한 발췌만(관련 배지·컬렉션·트라이브 각 1~3건) 넘긴다.
5. 승인 전 **기계 검사**: 후보안의 대상 ID를 재조회해 활성 판정에 어긋나면 자동 반려하고 사유를 남긴다.

| 구분 | 유형 |
|---|---|
| 추천·소개형(대상은 활성 필수) | ② ⑤ ⑥ ⑦ ⑩ ⑬ ⑯ |
| 글·세계관 노출형(본문 인용만, 비활성도 가능) | ① ④ ⑨ ⑪ ⑰의 서사 부분 |

## 5. 세그먼트 태그

현재 값(2026-09-23 확인): `all`, 시간대 5종(`time_dawn`·`time_morning`·`time_afternoon`·`time_evening`·`time_night`), `has_participating_mission`, `has_ending_soon_mission`, `has_incomplete_itembook`, `new_user`.

1단계에서 추가할 값(이름은 구현 티켓에서 확정):

| 후보 태그 | 조건 | 근거 데이터 |
|---|---|---|
| 컬렉션 잔여 N개 이하 | 미완성 컬렉션의 남은 슬롯 수가 임계값 이하 | `user_item_book_slots`, `computeBookCompletion` |
| 동기화 경과 N일 이상 | 마지막 동기화 후 경과일이 임계값 이상 | `strava_connections.last_synced_at` |
| POI 근접 | 유저 최근 위치 기준 반경 안에 미픽업 POI 존재 | `users.last_location_*`, POI 위경도 |
| 날씨·기념일 | 오늘 날씨 구분(맑음·비·극한)과 기념일 여부 | 기상청·특일정보 API(티켓 2) |

임계값은 시범 운영 데이터로 조정한다. 위치 태그는 카드에 좌표를 노출하지 않고, 매칭 외 목적으로 좌표를 보관하지 않는다.

등급 판단 기준은 유저 규모가 아니라 세계관·창의성·리스크다. 세계관 창작이 핵심이면 사람, 정형 데이터의 사실 서술이면 자동, 데이터 해석이나 리스크 판단이 섞이면 초안이다. 사람 등급과 초안 등급은 완전 자동으로 승격하지 않는다.

**미스터리 헌터 노출 상한**: 미스터리 헌터는 "전역 스파이스, epic·mystic 한정 저확률" 정체성이므로 일상 화자로 쓰지 않는다. 일간 편성에서 노출 빈도 상한을 둔다(컨텐츠 노출 빈도 조정이며 드랍 확률과 무관하다).

## 7. 이슈 소재 입력과 자동 제외 필터

### 7.1 소재 소스

지정 출처 7곳(윤진 정의의 Trend sources)은 유지한다. 그 밖의 소스는 2026-09-23 조사 기준으로 다음과 같이 나눈다.

| 구분 | 소스 | 얻는 것 | 자동 수집 |
|---|---|---|---|
| 자동화 1순위 | 기상청 API 허브 | 단기예보 | 가능(인증키) |
| 자동화 1순위 | 특일정보 API(공공데이터포털) | 공휴일·기념일·24절기 | 가능(인증키) |

### 7.2 소재 카드 입력 형식

윤진이 넣는 소재 카드는 다음 칸을 갖는다: 제목 · 범주(계절·날씨·기념일·지역 축제·공공 캠페인·활동 씬 유행·수집 문화·밈) · 출처 · 관찰일 · 유효 기간 · 지역(있으면) · 트라이브 후보 · 필터 판정(통과·제외) · 제외 사유. 형식의 정본은 구현 티켓에서 확정한다.

### 7.3 자동 제외 범주

| 범주 | 기록에 남길 사유 문구 | 예외 |
|---|---|---|
| 정치(선거·정당·정책 논쟁) | 정치적 논쟁 소재로 자동 제외 | 없음 |
| 재난·사고(자연재해·화재·사고·사망) | 재난·사고 소재로 자동 제외 | 재난을 소재로 쓰지 않는 순수 안전 안내(기상특보 기반 활동 주의)만 예외. 윈터 검수 필수 |
| 범죄·사건 | 범죄·사건 소재로 자동 제외 | 없음 |
| 혐오·비하(집단·성별·지역·세대) | 혐오·비하 표현 소재로 자동 제외 | 없음 |
| 실존 인물 | 실존 인물 언급으로 자동 제외 | 없음 |
| 저작권 소재(음원·캐릭터·문구) | 저작권 소재 직접 인용으로 자동 제외 | 작동 원리만 차용하면 허용(마케팅 플레이북 원칙) |
| 논쟁 중인 사회 갈등 | 사회 갈등 논쟁 소재로 자동 제외 | 없음 |
| 순위·비교형 밈, 다이어트·체중·시술 등 의료성 조언, 종교 의례, 실존 대회명 | 세계관 미배정 소재로 제외(윈터) | 없음 |

뉴스 소스는 카테고리 메타데이터로 기계가 1차 제외하고 통과분만 사람이 본다. 밈 소스는 메타데이터가 없으므로 전량 사람이 본다(윤진 1차 스크리닝 → 윈터 최종 검수). 걸러진 항목은 사유와 함께 리포트에 남긴다. 유행어는 영구 컨텐츠에 넣지 않고, 6개월 미채택 소재는 폐기한다.

## 8. 주간 편성표 형식 (주간 리포트 「홈피드 초안」 절)

```
## 홈피드 초안 (YYYY-MM-DD ~ YYYY-MM-DD)

### 요일별 후보
| 요일 | 주제 | 후보 A | 후보 B | 후보 C | 윤진 1픽 | 최종 선택 | 승인 |
|---|---|---|---|---|---|---|---|
| 월 | ... | 세그먼트 · 유형ID · 트라이브 · 문안 방향 [등급] | ... | ... | A | (비움) | [ ] |

### 트라이브·유형 분포
- 트라이브: 0회·2회 이상인 트라이브 표시
- 유형: 요일별 대표 유형 ID
```

- 요일마다 주제가 다르고, 후보는 2~3개다. 같은 주에 같은 유형이 두 번 이상 대표가 되지 않게 섞는다.
- 트라이브 이야기 계열은 주 2회를 넘기지 않고 연속 배치하지 않는다. 트라이브 분포는 매주 순환한다.
- 사람이 「최종 선택」에 A/B/C를 적고 「승인」에 체크하면 카즈하가 `/admin/today`에 등록한다.
- 발행 뒤 실측은 결과 기록(`.claude/skills/jam-work/references/forms/outcome-record-format.md`)에 카드 단위로 남긴다.

## 9. 계측

- 카드에는 유형 ID(§6)가 붙는다.
- 기록하는 이벤트: 노출, 열람(클릭), 후속 행동(§6의 성공 행동), 후보 채택 여부(제안 대비 사람이 고른 비율).
- 이벤트는 **집계 목적으로만** 저장한다. 개인 식별자는 저장하지 않는다(결정 4-6).
- 저장 구조와 API는 구현 티켓에서 확정한다.

## 10. 전략 변경안 양식 (주간 리포트 「전략 변경안」 절)

```
바꾸자는 것 : [유형 비중 / 요일 배치 / 톤 / 세그먼트 대상] 중 무엇을, 어떻게
근거 신호   : [노출·열람·미션 참가·배지 획득·복귀] 중 무엇이 몇 주 연속 어떤 패턴인지
기대하는 변화:
되돌리는 조건: 변경 후 N주 연속 반대 신호가 나오면 원복 (N은 최소 3주)
과장 검사   : 이 변경이 카피를 더 자극적이거나 긴급하게 만드는 방향인가? [예/아니오]
              예이면 반려하고 브랜드 보이스 가이드를 다시 확인한 뒤 재제출
승인        : [ ] 승인 [ ] 반려 [ ] 보류. 사유:
```

- 최소 3주 연속 신호가 없으면 변경안을 만들지 않고 관찰만 한다. 오픈 초기의 표본 미달 기간에는 학습 기반이 아니라 규칙 기반(트렌드+세그먼트 매칭)으로만 제안한다.
- 전략 변경안 승인은 주간 편성 승인과 별개 절차다.

## 11. 유형 카탈로그 성과 리뷰

- **주기**: 자동 등급 유형(T02·T03·T07·T08·T10·T14)은 **2주**. 주간 리포트 루틴 안에서 격주 조건으로 「유형 리뷰」 절을 만든다(새 루틴을 만들지 않는다). 초안·사람 등급 유형(나머지 11종)은 **1개월**. 월간 리포트에 「유형 카탈로그 리뷰」 절을 만든다.
- **양식**(유형당 1행): `유형 ID | 지표 요약(노출·열람·성공 행동·채택률) | 판정(유지·수정·보완·제거) | 근거 | 다음 리뷰까지 관찰 조건 | 승인`
- **반응 없음 기준**: 연속 N회 리뷰에서 채택률·열람이 카탈로그 안에서 하위권인 유형을 "관찰 대상"으로 올리고, 다음 회차도 하위면 판정 후보로 올린다. N과 하위권 기준선은 오픈 후 실측으로 정한다.
- **역할 분리**: 유형 리뷰는 카탈로그 구성을 바꾸고, 전략 변경안(§10)은 있는 유형의 편성 비중·요일·톤·세그먼트 대상을 바꾼다. 유형 리뷰 결과는 다음 전략 변경안의 재료가 된다.
- **부활 조건**: 제거된 유형은 자동으로 되돌아오지 않는다. 트리거 데이터·세그먼트 조건이 새로 생기거나 사람이 다시 제안해 승인받을 때만 돌아온다.

## 12. 시즌·소재 × 트라이브 매핑

정본은 윈터 모드 ①로 `jam-doc/planning/content/TRIBES.md`(또는 컨텐츠 문서)에 등재한 표다. 등재 전까지 T04·T17은 이 표를 즉석에서 만들지 않는다. 2026-09-23 윈터 검수의 초안은 상위 티켓에 있다. 어떤 트라이브에도 붙이지 않는 소재는 §7.3 마지막 행과 같다.

생성 전 프롬프트에 반드시 넣는 것: 해당 트라이브의 캐치프레이즈와 핵심 장소·오브젝트 원문, T13·T16의 "지역 트라이브" 표현 금지, T04·T17은 등재된 매핑표만 참조, T06은 실존 레시피만, 미스터리 헌터 노출 상한. 생성 후 검수: 주간 승인 배치 통독은 매주, 월 1회 지난 4주분 표본 점검(목소리 이탈·원문 훼손·미스터리 헌터 빈도), 분기 1회 매핑표와 프롬프트 대조.
