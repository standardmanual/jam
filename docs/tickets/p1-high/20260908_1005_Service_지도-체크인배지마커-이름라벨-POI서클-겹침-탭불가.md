# [bug] 지도에서 체크인 배지 마커의 이름 라벨이 POI 서클을 덮어 탭이 안 된다

## 배경 / 문제 정의

지도 화면에서 같은 좌표에 POI(드랍/픽업 지점)와 체크인 배지가 함께 있으면(예: 뚝섬역처럼
`linked_badge_id`가 있는 역), 두 마커가 겹쳐 **어느 쪽도 탭해서 선택할 수 없는** 상태가 됐다.
사용자가 스크린샷으로 신고했고, "이 상황이 되면 문제를 해결하는 정책으로 적용해"라고 명시했다
— 특정 POI 하나가 아니라 **겹치는 모든 지점에 공통 적용되는 수정**이 필요하다는 뜻이다.

### 원인 (실제 데이터·함수로 재현해 확정)

`MapView.tsx`는 체크인 배지 마커를 POI 서클과 같은 좌표에 그리면서 서클을 가리지 않도록
`anchor.y`를 위로 띄우는 로직(`BADGE_MARKER_LIFT`)을 이미 갖고 있었다(2026-08-01, 커밋
`65d832f8`). 그런데 이 오프셋은 **배지 이미지 절반 높이만** 계산에 넣었고, 이미지 아래에
붙는 **이름 라벨**(`badgeMarkerIconHtml`의 `label` div — 줌 배율과 무관하게 고정 24px)의
높이는 빠져 있었다. 그 결과 불투명 배경(`rgba(0,0,0,0.65)`)의 라벨이 서클 중앙에 그대로
얹혀 서클을 완전히 가리고, 클릭 이벤트도 라벨 쪽(배지 마커)이 가져가 POI 서클은 사실상
탭할 수 없었다.

실제 `dropMarkerIconHtml`·`badgeMarkerIconHtml`을 그대로 복사해 뚝섬역의 실제 배지 이미지·
좌표·줌(17) 값으로 정적 재현했더니 사용자 스크린샷과 픽셀 단위로 일치했고, 수정 후 같은
재현에서 라벨과 서클이 분리됨을 확인했다.

## 상세 요구사항

### 서비스/코드베이스 관점 — 특정 POI가 아니라 공통 오프셋 공식을 고친다

`MapView.tsx`의 배지 마커 `anchor.y` 계산에 라벨 높이를 새 상수로 더한다. 이 계산은
`badgeMarkers.forEach(...)` 루프 안에 있어 **지도에 그려지는 모든 체크인 배지 마커에
동일하게 적용된다** — 뚝섬역만이 아니라 POI와 체크인 배지가 겹치는 모든 지점(현재·향후
데이터 포함)에 공통으로 작동한다.

### 회귀 확인 포인트
- 배지 마커가 없는 일반 POI(체크인 배지가 연결 안 된 지점)는 영향받지 않는가
- 배지 클러스터(줌 13 이하)는 이 계산과 무관하므로 영향받지 않는가
- 이름이 짧아 라벨이 작은 경우·긴 경우 모두 서클이 가려지지 않는가
- 줌 레벨별(13 초과 각 구간)로 `zoomScale`이 달라져도 라벨이 서클을 가리지 않는가

포함한 콘텐츠 전체가 서클 위로 뜨게 되어, 라벨이 서클을 덮지 않는다.

### 주요 의사결정 / 핵심 메모

**특정 POI(뚝섬역) 조건문이 아니라 공용 상수·공식을 고친 이유** — 사용자가 명시적으로
"이 상황이 되면 문제를 해결하는 정책으로 적용해"라고 요청했다. 다행히 원인 자체가 이미
공용 함수(`badgeMarkers.forEach`) 안의 오프셋 공식이었으므로, 특정 POI를 분기하는 코드를
추가할 필요 없이 그 공식 자체를 고치는 것만으로 목표를 만족한다 — 뚝섬역은 이 버그가
드러난 사례일 뿐, 코드에 "뚝섬역"이라는 문자열이나 조건은 전혀 등장하지 않는다.

**실제 화면 대신 정적 재현으로 검증한 이유** — 지도는 브라우저의 실제 GPS 위치를 지도
중심으로 쓰고(`DropsClient.tsx`), URL로 특정 좌표에 진입하는 기능이 없어 자동화 브라우저로
정확히 뚝섬역 위치까지 이동시키기 어려웠다. 대신 실제 코드의 두 아이콘 생성 함수를 그대로
복사하고, DB에서 조회한 실제 배지 이미지·좌표·줌 값으로 재현해 사용자 스크린샷과 대조하는
방식으로 원인을 확정하고 수정을 검증했다.

### 잔여 이슈
- 실제 지도에서 줌을 바꿔가며(13/16/19 경계 등) 라벨-서클 간격이 항상 적절한지, 그리고
  선택된 POI(서클이 더 커지는 상태)에서도 겹침이 없는지는 로그인 후 사용자가 직접 확인한다.
