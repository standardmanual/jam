# [Admin] 운영 도구 — 쉐이더 랩 신규 (1차: 에디터 골격 + 핵심 이펙트 + 1:1 내보내기)

## 배경 / 문제 정의

사용자가 [basementstudio/shader-lab](https://github.com/basementstudio/shader-lab)
(데모: https://eng.basement.studio/tools/shader-lab )을 보고, 동일한 수준의 범용 레이어형
셰이더 합성 편집기를 JAM! 어드민에 이식해달라고 요청했다. 검토 결과와 사용자 확정 사항은
다음과 같다.

### 원본 저장소 조사 결과

- **라이선스**: Apache License 2.0. 상업적 사용·수정·재배포 허용, 조건은 원본 저작권 고지·
  라이선스 사본 첨부·변경 사항 명시(§4).
- **구조**: Bun 워크스페이스 모노레포.
  - `packages/shader-lab-react` — **실제 npm에 `@basementstudio/shader-lab`로 배포되는
    렌더링 런타임**. WebGPU(`WebGPURenderer`) + Three.js + TSL 기반이며, 디스플레이스먼트맵·
    블룸(듀얼필터)·ASCII·블롭 트래킹·CRT·디더링·하프톤·크로마틱 애버레이션·픽셀레이션·
    포스터라이즈·핀치/렌즈·플루이드·플루티드 글래스·잉크·엣지 디텍트·픽셀 소팅·픽셀 트레일·
    커스텀 셰이더 등 **25종 이상의 이펙트 패스**를 이미 구현해 포함하고 있다. 이 부분은 코드를
    옮길 필요 없이 **npm 의존성으로 설치하면 그대로 쓸 수 있다.**
  - `src/components/editor/*`, `src/components/pages/shader-lab-page.tsx`,
    `src/components/ui/*` — **에디터 애플리케이션 UI**(레이어 사이드바·속성 패널·타임라인·
    캔버스 뷰포트·커브 에디터·컬러 피커·그라디언트 램프 등). 이건 npm 패키지로 배포되지
    않고 모노레포 앱 소스로만 존재하므로, **직접 파일을 이식하고 JAM! 코드 스타일에 맞게
    적응시켜야 한다.**
  - `src/components/community/*`, `src/app/api/community/*`, Neon 기반 자체 인증, 씬 공유·
    좋아요·리믹스·신고 기능, `packages/shader-lab-mcp`(AI 에이전트 제어용 MCP 서버) — **JAM!에
    불필요. 이식 대상에서 완전히 제외한다.**
- **스택 호환성**: 원본은 React 19 / Next ^16.2.3 / Three ^0.183.2. JAM!(`jam-web`)은 현재
  React 19.2.4 / Next 16.2.10으로 **거의 동일** — 호환성 리스크가 낮다. `three`는 JAM!에
  아직 의존성으로 없으므로 신규 추가한다.

### 기존 프로젝트 방침과의 충돌 및 사용자 승인

과거 티켓 `20260819_007`, `20260912_1532`에서 "신규 셰이더 라이브러리 추가 금지
(`@paper-design/shaders-react`만 허용, Three.js 등 금지)"를 명시적으로 못박은 바 있다.
이번 요청은 그 방침을 깨고 `three` + `@basementstudio/shader-lab`을 신규 의존성으로
추가한다 — **사용자가 명시적으로 승인함(2026-09-12)**. 사유: 독자 재구현보다 원본 오픈소스
런타임(Apache 2.0, 실사용 검증된 25종 이상의 GPU 이펙트)을 그대로 쓰는 쪽이 품질이 높다고
판단.

기존 `/admin/shader-text`(디졸브 에코 텍스트 전용, Canvas 2D, 티켓 `20260912_1532` 등)는
**이 티켓과 무관하게 그대로 유지한다.** 이번 신규 기능은 별도 도구다.

### 라이선스 준수 의무 (Apache 2.0 §4)

- 이식하는 파일 상단에 출처 주석(원본 저장소 URL, 라이선스, 이식 시점 커밋/버전, 변경 사항
  요약)을 남긴다.
- `jam-web/` 루트 또는 이식 디렉터리 하위에 `THIRD_PARTY_NOTICES.md`(또는 동등한 파일)를
  추가해 Apache 2.0 라이선스 전문과 원본 저작권 고지를 포함한다.
- 소스를 그대로 복붙하지 않는다 — JAM! 코드 스타일(TypeScript strict, 기존 어드민 컴포넌트
  패턴)에 맞게 옮기면서 불필요한 기능(커뮤니티·인증·MCP)을 제거한 결과물이어야 한다.

### 사용자 확정 요구사항 (전체 로드맵, 이 티켓은 1차만 다룸)

| 항목 | 결정 |
|---|---|
| 목표 | shader-lab과 동일한 수준의 범용 레이어 편집기 |
| 사용처 | 이미지 업로드 → 레이어 합성 → 배지/컬렉션(아이템북)/미션 이미지로 컨텐츠 검색 후 자동 등록 |
| 출력 규격 | **1:1 비율 고정** (정확한 픽셀 크기는 구현 시 기존 도구 관례상 1280×1280 준용, 다른 값이 필요하면 구현자가 판단) |
| 진행 방식 | **단계별** (사용자 승인) — 1차: 에디터 골격+핵심 이펙트+1:1 PNG 내보내기 / 2차: 나머지 이펙트+타임라인+오디오 연동 / 3차: 배지·컬렉션·미션 3종 자동 등록 |

**이 티켓은 1차만 다룬다.** 2차·3차는 1차 완료·게이트 통과 후 별도 티켓으로 진행한다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 의존성 추가

- `@basementstudio/shader-lab`(npm, 원본이 배포하는 최신 안정 버전), `three`(peer dep,
  원본과 동일 계열 `^0.183.x`)를 `jam-web`에 추가한다.
- 설치 후 **에디터 UI가 이 패키지의 공개 API(`packages/shader-lab-react/src/index.ts`가
  export하는 것)만으로 필요한 기능을 구성할 수 있는지 먼저 확인한다.** 원본 에디터 소스가
  공개 API 대신 `packages/shader-lab-react/src/renderer/*` 내부 모듈을 직접 import하는
  경우, 그 내부 모듈도 함께 이식 대상에 포함시킨다(패키지가 export하지 않는 부분이므로).
  이 확인 결과와 근거를 완료 기록에 남긴다.
- WebGPU 미지원 브라우저(구형 Safari 등) 대응: `navigator.gpu` 존재 여부를 초기 진입 시
  확인해, 없으면 크래시 대신 "Chrome/Edge 최신 버전에서 이용해주세요" 안내 화면을 보여준다
  (이 도구는 어드민 전용이므로 폴백 렌더러 구현은 범위 밖).

#### 2. 에디터 UI 이식 — 축소 범위

원본 `src/components/editor/*` + `src/components/pages/shader-lab-page.tsx` +
필요한 `src/components/ui/*` 프리미티브(슬라이더·컬러 피커·그라디언트 램프·넘버 인풋·
셀렉트·토글·글래스 패널 등)를 참고해 `jam-web/src/app/admin/shader-lab/`에 이식한다.
**코드를 그대로 복붙하지 말고** JAM! 어드민 컴포넌트 스타일(shadcn/ui 기반, 기존
`/admin/shader-text` 패턴 참고)로 재작성하되, 레이아웃·상호작용 구조는 원본을 최대한
따른다.

포함 범위:
- 레이어 사이드바(추가·삭제·순서 변경·표시/숨김 토글)
- 속성 패널(선택된 레이어의 파라미터 조정 — 슬라이더/컬러/셀렉트 등 원본 UI 위젯 그대로)
- 캔버스 뷰포트(실시간 프리뷰, WYSIWYG)
- 이미지 업로드(미디어 레이어 소스로 사용)
- 재생/정지 컨트롤만 있는 최소 타임라인 (키프레임·오디오 연동은 2차 범위)

제외 범위 (이 티켓에서 손대지 않음):
- 커뮤니티(씬 공유·좋아요·리믹스·신고), 자체 인증, MCP 에이전트 브릿지 — 파일 자체를
  가져오지 않는다.
- 오디오 연동(`audio-link-button`·`audio-spectrum-display` 등), 커브 에디터 기반 키프레임
  타임라인 — 2차 범위.
- 커스텀 셰이더 작성 모드(TSL 코드 직접 편집) — 필요성이 확인되지 않았으므로 이 로드맵
  전체에서 범위 외. 유예된 판단 절 참고.

#### 3. 이펙트 레이어 종류 — 1차는 대표 세트만

패키지가 25종 이상의 패스를 모두 제공하지만, 1차에서는 **레이어 종류당 속성 패널 UI를
새로 이식해야 하는 작업량**을 고려해 대표 세트만 노출한다. 최소 다음 6종을 포함한다
(구현자가 이식 난이도를 보고 조정 가능, 완료 기록에 최종 목록과 사유를 남길 것):
미디어(이미지), 디스플레이스먼트맵, 블룸, 디더링, ASCII, 하프톤.

나머지 패스는 2차에서 순차 노출한다 — **런타임 자체는 이미 전체 패스를 지원하므로, 2차는
"이미 되는 기능의 UI 노출"이지 새 렌더링 로직 구현이 아니다.**

#### 4. 데이터 모델 — 1차는 최소 지속성만

3차(컨텐츠 자동 등록)에서 정식 저장 스키마를 확정하므로, 1차는 작업 유실 방지 수준의
최소 지속성만 갖춘다. 신규 테이블 `shader_lab_compositions`(가안, `shader_text_presets`
패턴 참고 — `id`/`name`/`scene_json`/`created_at`/`created_by`, **RLS 필수 활성화**)에
현재 편집 상태(레이어 스택 + 각 레이어 파라미터)를 저장/불러오기하는 정도로 충분하다.
마이그레이션 번호는 push 직전 원격 staging 기준으로 재확인한다. **DB 실행은 하지 않는다
— SQL 파일 작성까지, 실행은 사용자 승인 후 오케스트레이터가 처리한다.**

#### 5. 내보내기

- PNG, 1:1 비율 고정 크기(기존 관례상 1280×1280 준용). `canvas.toBlob()` 또는 WebGPU
  렌더 타깃에서 픽셀을 읽어 인코딩 — 원본 구현 방식을 그대로 따른다.
- 배지/컬렉션/미션에 적용하는 흐름은 3차 범위이므로 1차는 로컬 다운로드만 지원한다.

### UI/UX 관점

- 신규 라우트 `/admin/shader-lab`. `src/components/admin/adminNavItems.ts`의 `design`
  (디자인) 그룹에 "쉐이더 랩" 항목 추가.
- 어드민 화면이므로 MODULAR 디자인 시스템 적용 대상이 아니다(기존 정책, 탐색 절차 생략).
- 원본 에디터의 레이아웃 기조(좌: 레이어 목록, 중앙: 캔버스, 우: 속성 패널)를 따르되, 세부
  스타일은 JAM! 어드민 톤에 맞춘다.

### 컨텐츠 관점

- 해당 없음 (3차에서 다룸)

## 구현 계획

1. `@basementstudio/shader-lab` 최신 버전 확인 후 `three`와 함께 설치, 공개 API로 최소
   샘플(이미지 레이어 1개 + 이펙트 1개)이 화면에 렌더링되는지 스파이크 검증
2. 에디터 UI가 패키지 공개 API만 쓰는지, 내부 모듈 직접 참조가 있는지 원본 소스 확인 →
   필요 시 내부 모듈 이식 목록 확정
3. 마이그레이션 파일 작성(`shader_lab_compositions`, RLS 포함, 실행 안 함)
4. 어드민 페이지 골격 + 레이어 사이드바 + 속성 패널 + 캔버스 뷰포트 이식·재작성
5. 대표 이펙트 6종 속성 패널 연결
6. 이미지 업로드(미디어 레이어) + PNG 1:1 내보내기
7. 저장/불러오기(4절 테이블) 연결
8. 네비게이션 항목 추가
9. `THIRD_PARTY_NOTICES.md` 작성 + 이식 파일 상단 출처 주석
10. WebGPU 미지원 브라우저 안내 화면
11. 로컬 `ADMIN_EMAILS` 환경변수로 실렌더 확인 (`DEV_PROCESS_GUARDRAILS.md` 패턴 13)

## 유예된 판단 (이 티켓에서 확인하지 않음)

1. **커스텀 셰이더(TSL 코드 직접 편집) 지원 여부** — 사용자 요청에 명시되지 않았다. 필요성이
   생기면 별도 티켓으로 판단한다.
2. **2차(나머지 이펙트+타임라인 키프레임+오디오 연동), 3차(배지·컬렉션·미션 자동 등록)의
   상세 스펙은 이 티켓에서 확정하지 않는다** — 1차 완료 후 실제 이식 난이도를 보고 후속
   티켓에서 구체화한다.
3. **`shader_lab_compositions` 저장 스키마가 3차에서 확장될 가능성이 높다** — 1차 스키마는
   잠정적이며, 3차에서 필요하면 마이그레이션으로 컬럼을 추가한다(재설계는 아님).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`@basementstudio/shader-lab@3.0.2` + `three@0.183.2`를 신규 의존성으로 설치하고,
`/admin/shader-lab`에 레이어형 셰이더 합성 편집기 1차 골격을 신규 구현했다.

- **런타임 사용 방식**: 원본 저장소를 클론해 실제 소스를 확인한 결과, 에디터 UI에 필요한
  기능은 패키지가 **공개 export하는 API만으로 전부 구성 가능함을 확인했다** —
  `packages/shader-lab-react/src/renderer/*` 내부 모듈 이식은 필요 없었다(구현 계획 2단계
  완료). 구체적으로:
  - 레이어 스키마(`ShaderLabConfig`/`ShaderLabLayerConfig`/`ShaderLabParameterValue` 등)는
    `index.d.ts`가 공개 export.
  - 캔버스 렌더링은 최상위 `ShaderLabComposition` 컴포넌트 대신 "Advanced API"인
    `useShaderLabCanvasSource`(공개 export)를 직접 썼다 — `ShaderLabComposition`은 내부
    RAF 루프가 항상 wall-clock 시간으로만 그리고 `config` 참조가 바뀔 때마다 렌더러를
    통째로 재생성해(원본 소스 확인, `shader-lab-composition.js`) 슬라이더 드래그 시 매
    프레임 렌더러가 재생성되는 문제가 있었다. `useShaderLabCanvasSource`는 `config`가

### 게이트 리뷰 재시도 기록 (2026-09-12, 이 절이 이번 재시도의 핵심)

**게이트 FAIL 사유 요약**: 리뷰어는 `page.tsx`의 `handleAdd`가 새 레이어를 배열 맨 앞
(`[layer, ...prev]`)에 추가하는데, `pipeline-manager.js`의 `syncLayers`/`render`가 배열을
인덱스 0부터 순서대로(아래→위) 합성하므로 "이미지 추가 → 효과 추가" 시 배열이
`[effect, image]`가 되어 효과가 먼저 빈 배경에 그려지고 뒤의 불투명 이미지가 100% 덮어써
효과가 전혀 보이지 않는다고 진단했다. 제안된 수정 방향은 `handleAdd`가 배열 끝에 추가하도록
반전하는 것이었다.

**재시도 조사 결과 — 이 진단은 틀렸다.** `pipeline-manager.js`의 `syncLayers`/`render`만
보면 리뷰어의 추론이 논리적으로는 맞아 보이지만, **실제 그 함수를 호출하는 지점**
(`node_modules/@basementstudio/shader-lab/dist/src/renderer/create-webgpu-renderer.js` L38)은
다음과 같다:

```js
pipeline.syncLayers([...frame.layers].reverse());
```

즉 `config.layers` 배열은 **호출 직전에 뒤집힌 뒤** `pipeline-manager`에 전달된다. 이
reverse()는 `create-headless-renderer.js`에도 동일하게 있어(패키지 전역의 일관된 설계),
공개 API(`ShaderLabCanvasSource`/`useShaderLabCanvasSource`/`ShaderLabComposition` 전부 이
경로를 거친다) 어디로 들어가도 항상 적용된다. 결과적으로:

- **배열 인덱스 0(목록 맨 위)이 실제로는 합성 순서상 가장 나중에(맨 위에) 그려진다.**
- 원본(미수정) `handleAdd`의 `[layer, ...prev]`(새 레이어를 배열 맨 앞에 추가)는 **이미
  정확했다** — "이미지 추가 → 효과 추가" 시 배열이 `[effect, image]`가 되고, 이 배열은
  reverse 후 `[image, effect]`로 합성돼 효과가 이미지 위에 정상적으로 나타난다.
- 사이드바 주석·`CardDescription`의 기존 문구("목록 위쪽일수록 나중에(위에) 그려져요")도
  이미 정확한 문구였다.

**실측 검증 방법**: 워크트리에서 `next dev`가 불가하므로, `layerFactory.ts`/`composition.ts`
(앱이 실제로 쓰는 코드)와 실제 설치된 `@basementstudio/shader-lab@3.0.2` 런타임을 esbuild로
그대로 번들해(Next.js를 거치지 않음), 시스템 Chrome 152(WebGPU 지원)에서 playwright로 로드해
`ShaderLabCanvasSource`(앱이 쓰는 것과 동일한 클래스)로 실제 GPU 렌더링을 90프레임 구동한 뒤
캔버스를 PNG로 저장해 육안 확인했다. 테스트 대상은 미수정 `handleAdd` 순서(이미지 추가 →
효과 추가 시 실제로 만들어지는 배열, `[effect, image]`)를 이미지(그라디언트) + 디더링,
이미지 + 하프톤 두 조합으로 구성했다. 결과:
- 이미지만: 매끈한 그라디언트.
- `[디더링, 이미지]`(원본 순서): 그라디언트 위에 디더링 패턴이 뚜렷하게 나타남(효과가
  이미지 위에 보임 — 원본이 이미 정상 동작).
- `[하프톤, 이미지]`(원본 순서): 그라디언트 위에 하프톤 도트 패턴이 뚜렷하게 나타남(동일).
- (조사 과정에서 리뷰어 지시대로 `[...prev, layer]`로 반전해서도 같은 방식으로 테스트했더니
  이번엔 반대로 효과가 전혀 보이지 않는 것도 확인했다 — 즉 리뷰어의 제안대로 "고치면"
  실제로는 없던 버그가 새로 생긴다.)

**조치**: 기능 코드는 원본(3d8f7066)과 동일하게 유지했다(`git diff`로 로직 무변경 확인).
`page.tsx`의 `handleAdd`와 `ShaderLabLayerSidebar.tsx` 상단 주석에 이 reverse() 호출 근거를
파일:라인과 함께 명시해, 이후 리뷰어가 `pipeline-manager.js`만 보고 같은 오진단을 반복하지
않도록 했다. 검증에 쓴 esbuild 번들·playwright 스크립트·PNG는 커밋하지 않았다(스크래치 산출물).
