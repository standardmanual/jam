# [Admin] 쉐이더 랩 — 리퀴드 메탈 미러 캔버스 잔상으로 이미지 마스크·배경 알파가 안 먹힘

## 배경 / 문제 정의

리퀴드 메탈 레이어에 이미지를 올려 마스크를 씌워도, 레이어 추가 시 기본으로 나오는 "캔버스
전체를 채우는" 효과가 사라지지 않는다는 보고. 다른 설정을 만졌다가 돌아오면 사라지는 것으로
보아 캐시성 문제로 추정된다는 설명이 있었다. 같은 세션에서 "배경 색상 옆 알파 슬라이더가
동작하지 않는다"는 두 번째 보고도 함께 들어왔다.

## 사전 조사 결과

리퀴드 메탈은 순수 WebGL2 GLSL 셰이더(`@paper-design/shaders`)를 화면 밖에 숨긴
`<canvas>`(`ShaderMount`)에서 그린 뒤, 그 결과를 **매 프레임 2D 캔버스로 미러링**해서
WebGPU 파이프라인의 텍스처 소스로 쓰는 브릿지 구조다(`liquid-metal-pass.js`, 티켓
20260913_1948 도입).

GLSL 셰이더 자체(`@paper-design/shaders`의 `liquid-metal.js`)는 알파를 정확히 계산해
반환한다 — 확인 결과 마지막 줄이 `fragColor = vec4(color, opacity)`이고, `opacity`는
`u_colorBack.a`를 정확히 반영하도록 짜여 있었다(`opacity = opacity + u_colorBack.a * (1. -
opacity)`). 즉 **셰이더 코드에는 문제가 없었다.**

문제는 `render()`에서 매 프레임 미러링하는 부분이었다.

```js
this.mirrorContext.drawImage(sourceCanvas, 0, 0);
```

`clearRect` 없이 매 프레임 `drawImage`만 호출하고 있었다. 2D 캔버스의 기본 합성 방식
(`globalCompositeOperation = "source-over"`)에서는, 새로 그리는 프레임의 알파가 낮은
픽셀이 있어도 **그 아래 이전 프레임에서 그려진 내용을 지우지 못하고 그대로 남는다.** 즉
이전 프레임이 계속 "밑에 깔린 채" 누적된다.

- **이미지 추가 후에도 기본 채우기 효과가 안 사라지는 것**: 이미지를 올리기 전(배경 전체
  채우기 모드)에 그려진 불투명한 프레임들이 미러 캔버스에 누적돼 있다가, 이미지를 올려 셰이더
  결과가 (형태 바깥은 투명한) 새 프레임으로 바뀌어도, 새 프레임의 투명한 영역으로는 예전
  누적분이 그대로 비쳐 보인다.
- **배경 알파 슬라이더가 안 먹히는 것**: 같은 이유로, 슬라이더를 낮춰도 새로 그려지는(더
  투명한) 프레임이 이전의 더 불투명했던 누적분을 지우지 못한다.
- **다른 설정을 바꾸다 오면 사라지는 것처럼 보이는 이유**: `render()`의 `sizeChanged` 분기
  (캔버스 리사이즈 감지 시 `mirrorCanvas`를 통째로 새로 만드는 기존 로직, 티켓 20260914_0953)가
  우연히 걸리면 미러 캔버스 자체가 새로 생성돼 누적된 잔상이 함께 사라진다 — 사용자에게는
  "다른 설정을 바꾸면 고쳐진다"는 우연한 인상을 준 것이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `render()`에서 `drawImage()` 호출 직전에 `mirrorContext.clearRect(0, 0, width, height)`를
  추가해, 매 프레임 이전 내용을 지우고 새로 그리도록 한다.

## 구현 계획

1. `liquid-metal-pass.js`의 `render()`에 `clearRect` 추가.
2. `npx patch-package @basementstudio/shader-lab`로 patch 반영, `npm install` 재적용성 확인.
3. 로컬 esbuild+실제 WebGL2/WebGPU 지원 브라우저 실렌더로: 배경 알파 100%(불투명)로 여러
   프레임 렌더한 뒤, 알파를 0(완전 투명)으로 바꿔 다시 여러 프레임 렌더하고, 이전 불투명
   프레임의 잔상 없이 실제로 투명해지는지 확인.
4. `npx tsc --noEmit`, `npm run lint`.

## 완료 기록

### 구현 내용 요약

구현 계획 그대로 진행했다. `mirrorContext.drawImage(sourceCanvas, 0, 0)` 직전에
`mirrorContext.clearRect(0, 0, this.mirrorCanvas.width, this.mirrorCanvas.height)`를
추가하는 한 줄짜리 수정이었다 — GLSL 셰이더 자체는 이미 알파를 정확히 계산하고 있었으므로,
그 값이 최종 캔버스까지 온전히 전달되도록 미러링 단계의 합성 방식만 고치면 됐다.

### 주요 의사결정 / 핵심 메모

- **GLSL 셰이더 코드는 건드리지 않았다**: `@paper-design/shaders`(별도 npm 패키지, 이
  프로젝트가 patch하지 않는 의존성)의 `liquid-metal.js`를 열어 최종 `fragColor` 계산까지
  직접 확인한 결과 이미 정확했다 — 문제를 셰이더 탓으로 오판해 거기부터 손대지 않고, 실제
  브라우저 렌더로 "어느 단계에서 알파가 사라지는지"를 좁혀간 게 정확한 원인 지점(2D 캔버스
  합성)을 찾은 결정적 과정이었다.
- **"다른 설정을 바꾸면 고쳐진다"는 사용자 관찰이 결정적 단서였다**: 이 진술이 "리사이즈
  시 캔버스가 통째로 재생성된다"는 기존 코드(티켓 20260914_0953)의 존재를 떠올리게 했고,
  거기서 "그럼 재생성되지 않는 일반 프레임은 뭔가 누적되고 있겠구나"로 역추적할 수 있었다.
