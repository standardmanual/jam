# [Infra] 어드민 실렌더 검증 가이드라인 — 더미 타깃 필수화 (DEV_PROCESS_GUARDRAILS 패턴 13 보완)

## 배경 / 문제 정의
티켓 [20260917_1443](../P2-일반/20260917_1443_Admin_쉐이더랩-모서리라운드토글-배지미션컬렉션저장크기600px고정.md)
구현 검증 과정에서 실제 사고가 발생했다. jam-developer가 쉐이더랩의 "배지 이미지로 적용" 기능을
로컬 실렌더로 검증하면서, 더미 데이터가 아니라 **검색으로 찾은 실제 프로덕션 배지 "2일 연속
출석 라이딩"(id `e79aaf15-9621-4254-a0e4-27875e02ce87`)을 선택해 실제로 "적용" 버튼을
눌렀고**, 그 결과 실제 배지의 대표이미지가 테스트용 이미지로 덮어써졌다.

JAM! 프로젝트는 staging/production이 단일 Supabase DB를 공유한다(`project_supabase_shared_staging_prod`
메모리 규칙). `DEV_PROCESS_GUARDRAILS.md` 패턴 13은 "로컬 `next dev` + `ADMIN_EMAILS` 셸
환경변수로 어드민 화면을 실렌더 검증할 수 있다"는 절차는 정리해뒀지만, **쓰기 동작(적용·저장·
삭제 등)을 실제로 실행하는 검증에서 실제 컨텐츠가 아닌 더미/테스트 전용 대상을 써야 한다**는
규칙은 명문화돼 있지 않았다. 이번 사고로 그 공백이 실제 데이터 손상으로 이어졌다.

되돌릴 수단이 없어(Storage 오브젝트 버전 이력 없음, `badges.image_gen_params` null) 해당
배지 이미지는 복구되지 않은 상태다(사용자 확인 후 처리 보류 중).

## 상세 요구사항

### 서비스/코드베이스 관점
- `docs/specs/DEV_PROCESS_GUARDRAILS.md` 패턴 13에 아래 내용을 보강한다:
  - 로컬 실렌더 검증이라도 **쓰기 동작을 실제로 트리거하는 단계**(적용·저장·삭제·수정·발송 등)는
    검색·선택 시 실제 컨텐츠(실제 배지·미션·컬렉션·유저 등)를 대상으로 하지 않는다.
  - 대안: (a) 검색 결과 화면까지만 확인하고 실제 "적용"·"저장" 클릭은 생략하거나,
    (b) 사전에 합의된 테스트 전용 더미 레코드(예: 이름에 `[TEST]` 접두사가 붙은 전용 배지/
    미션/컬렉션)를 만들어 그 대상으로만 쓰기 동작을 검증하거나,
    (c) API 라우트 자체를 직접 호출해 응답 형식·상태 코드만 확인하고 실제 DB반영은
    스테이징 전용 격리 프로젝트가 생기기 전까지 보류한다.
  - 어느 방식을 표준으로 삼을지는 구현 시 판단하되, **적어도 (a)를 최소 기준으로 문서에 못
    박는다** — jam-developer가 매번 판단하게 두지 않는다.
- 이번 사고의 구체적 경위(위 배경 참고)를 사례로 문서에 남겨 재발 방지 근거로 삼는다.
