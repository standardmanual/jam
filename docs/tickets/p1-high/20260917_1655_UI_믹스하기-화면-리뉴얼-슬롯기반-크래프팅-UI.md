# [UI] 믹스하기 화면 리뉴얼 — 슬롯 기반 크래프팅 UI

## 배경 / 문제 정의

티켓 `20260917_1427`에서 믹스 레시피가 "슬롯 OR 매칭" 구조로 바뀌면서, 레시피를 어떤 것으로
시도할지 자체가 유저의 판단이 됐다. 같은 티켓의 1차 구현은 레시피 선택 → 슬롯 채우기 2단계
화면 전환으로 이를 처리했지만, 최소한의 기능 동작만 확인한 상태라 실제 유저 경험(정보 밀도·
탐색성)을 고려한 설계는 아니었다.

이번 티켓은 그 화면을 유저 조사·프로토타입 검증을 거쳐 확정한 "가방(내 배지) → 믹서(슬롯)"
크래프팅형 UI로 전면 리뉴얼한다. 참고한 게임 UI 패턴은 아이템 강화 시 자신의 가방에서 재료를
강화 슬롯에 넣는 방식이다.

**검증 과정**: `/mattpocock-skills:grilling`으로 설계를 확정하고, 독립 프로토타입
(https://claude.ai/artifact/Q9vt6rs2aitafA8iJxS8Ys, 이 세션 한정 비공개 링크 — 참고용,
실제 코드베이스에 반영된 파일이 원본이다)으로 흐름을 검증했다. 1차 프로토타입 확인 중
"레시피가 많아지면 가로 칩 스트립으로는 탐색이 어렵다", "슬롯이 8개까지 늘어나면 가방을
같은 화면에 상시 노출하는 건 비좁다"는 두 가지 문제가 나와 아래 최종 설계에 반영했다.

## 상세 요구사항

### 화면 구조 (화면 이동 없이 한 라우트 안에서 전환)

1. **레시피 탐색 (초기 상태)**: 검색 입력 + 세로 스크롤 레시피 목록. 각 행에 보상 미리보기
   (획득 배지 아이콘 + 포인트)와 슬롯 개수를 표시한다. 레시피가 많아질 걸 전제로 한 구조이므로
   가로 칩 스트립은 쓰지 않는다.
2. **믹서 (레시피 선택 후)**: 상단에 선택한 레시피 요약 바(보상 미리보기 + "다른 레시피"
   버튼)를 두고, 그 버튼을 탭하면 레시피 목록이 **`BottomSheet`(MODULAR, 이미 등록됨,
   `design-system/components/navigation/BottomSheet.jsx`)** 로 다시 열려 화면 이동 없이
   즉시 다른 레시피로 바꿀 수 있다. 그 아래 믹서 슬롯 그리드, 맨 아래 CTA 버튼("믹스하기")을
   배치한다.
3. **슬롯**: 아이템·액티비티·체크인 타입 구분 없이 시각적으로 동일하게 표시한다. 빈 슬롯은
   점선 테두리 + 타입 아이콘 + 필요 배지 이름, 채운 슬롯은 배지 아이콘·이름 카드 + 우상단
   제거 버튼(X 서클)으로 표시한다. 후보 배지를 유저가 하나도 보유하지 못한 슬롯은 "잠김"
   상태(사선 패턴)로 구분한다. 완료 여부는 슬롯의 시각 상태만으로 표현하고 별도 진행률
   텍스트는 두지 않는다.
4. **가방(내 배지) — 슬롯을 탭하면 `BottomSheet`로 열림** (2026-09-17 수정 — 최초 구현에서
   드러난 문제 반영): 빈 슬롯뿐 아니라 **잠긴 슬롯(후보를 하나도 보유하지 못한 슬롯)을 탭해도
   같은 시트가 열린다.** 시트 내용은 유저가 보유한 배지를 타입 탭으로 훑는 방식이 아니라,
   **그 슬롯의 후보 전체 목록(`slot.candidates`)을 그대로 보여준다** — 슬롯 하나의 후보는
   애초에 전부 같은 타입이라 탭 구분 자체가 무의미하므로, 이전 설계에 있던 전체/액티비티/
   체크인/아이템 탭은 제거한다.
   - 후보 중 유저가 보유한 것은 활성(탭 가능), 다른 슬롯에 이미 쓰였으면 "사용 중" 표시,
     **아예 보유하지 않은 후보는 흐리게 비활성 + "필요" 같은 표시로 구분**한다. 이렇게 해야
     유저가 "이 슬롯을 채우려면 뭘 구해야 하는지"를 항상 확인할 수 있다(잠긴 슬롯을 탭했을 때
     아무 정보도 없이 빈 화면만 뜨는 문제를 해결하기 위한 변경).
   - 활성 배지를 탭하면 그 슬롯에만 채워지고 시트가 자동으로 닫힌다.
5. **TopNav**: `points` 화면과 동일한 뒤로가기형(`<TopNav title={...} />`)으로 바꾼다 —
   `/combine`은 인벤토리에서 진입하는 하위 화면이라 로고형이 아니다.
6. **결과 피드백**: 기존 MODULAR `BadgeRevealCarousel`(패턴 카테고리, 이미 등록됨)과 서비스단
   진입점 `BadgeRevealOverlay.tsx`를 재사용한다. 성공 시 획득 배지를 캐러셀로 보여주고, 실패
   시 같은 오버레이 셸에 "미안, 이번엔 아무것도 없어요" 류의 메시지를 노출한다(이 컴포넌트엔
   빈 상태가 내장돼 있지 않으므로 호출부에서 처리 — 실패 시 `items`를 비우고 메시지 슬롯을
   커스텀 렌더). 오버레이를 닫으면 같은 레시피 화면에 슬롯만 비운 채로 남는다(레시피 목록으로
   강제 복귀하지 않음). 슬롯에 채웠던 아이템 배지는 소각 처리(인벤토리에서 제거), 액티비티·
   체크인 배지는 다시 사용 가능한 상태로 남는다.

### 컴포넌트 전략

- **신규 MODULAR 등록**: "믹서 슬롯"(빈/잠김/채움 3상태를 갖는 슬롯 UI)을 `design-system/
  components/`에 정식 컴포넌트로 추가하고 Storybook Story를 함께 작성한다. 배지 드랍·픽업
  화면에서도 재사용할 여지가 있다고 판단해 서비스 전용으로 두지 않기로 했다(사용자 결정).
  `/jam-design` 절차대로 배치할 카테고리(패턴/카드 등)를 정하고 `_ds_manifest.json`에
  등록한다.
- **기존 컴포넌트 재사용**: `BottomSheet`(가방 시트, 레시피 전환 시트), `BadgeRevealCarousel`
  / `BadgeRevealOverlay`(결과 피드백), `Card`·`BadgeGridCard` 등 기존 서비스 컴포넌트.
  신규로 만들 필요가 없는 것들은 그대로 쓴다.
- **레시피 목록 행**: 이번에 처음 나오는 형태(아이콘 스택 + 이름 + 슬롯 개수 + 포인트가 있는
  가로 리스트 행)라 MODULAR 승격 여부는 `/jam-design` 판정에 맡긴다 — 재사용 근거가
  뚜렷해지면 승격, 아니면 서비스 전용으로 둔다.

### 수용 기준

1. 레시피가 여러 개(테스트 데이터 기준 5개 이상) 있어도 검색으로 원하는 레시피를 바로 찾을
   수 있다.
2. 슬롯이 8개인 레시피를 선택해도 가방이 화면을 잠식하지 않고, 빈 슬롯을 탭했을 때만 가방
   바텀시트가 열린다.
3. 가방 바텀시트를 열면 탭한 슬롯의 타입 탭이 기본 선택돼 있다.
4. 가방에서 배지를 탭하면 해당 슬롯에만 채워지고 시트가 자동으로 닫힌다.
5. 후보 배지를 하나도 보유하지 못한 슬롯은 잠김 상태로 표시되고, 탭해도 채울 배지가 없다는
   것을 알 수 있다.
6. `/combine` 화면 상단이 `points` 화면과 동일한 뒤로가기형 TopNav로 표시된다.
7. 믹스 성공 시 `BadgeRevealCarousel` 기반 오버레이로 보상이 표시되고, 실패 시 같은 오버레이
   셸에 실패 메시지가 표시된다.
8. 결과 오버레이를 닫으면 같은 레시피 화면에 슬롯이 전부 비워진 채로 남는다.
9. 믹서 슬롯이 MODULAR 컴포넌트로 등록되고 Storybook Story가 존재한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

`/combine`을 레시피 탐색(검색 가능한 세로 목록) → 믹서(슬롯 그리드) 2단계 화면으로 전면
재작성했다.

- **레시피 탐색**: 검색 입력 + 세로 스크롤 목록. 각 행에 보상 배지 아이콘 스택 + 슬롯 개수 +
  포인트를 보여준다. 레시피에 표시용 이름 컬럼이 없어(마이그레이션 174) 검색은 슬롯 후보·
  보상 배지 이름을 합쳐 매칭한다.
- **믹서**: 상단 요약 바("다른 레시피" 버튼 → `BottomSheet`로 레시피 목록 재오픈, 화면 이동
  없음) + 슬롯 그리드(신규 MODULAR `MixerSlot`, 타입 구분 없이 동일 시각, 빈/잠김/채움 3상태) +
  CTA. 빈 슬롯뿐 아니라 **잠긴 슬롯(후보 미보유)을 탭해도** 그 슬롯 전용 가방 `BottomSheet`가
  열린다.
- **가방** (2026-09-17 2차 수정 — 사용자 지적으로 설계 변경): 최초 구현은 유저가 "보유한"
  배지만 타입 탭으로 걸러 보여줬는데, 이러면 잠긴 슬롯을 탭했을 때 빈 목록만 뜨고 무엇이
  필요한지 알 수 없는 문제가 있었다. **탭한 슬롯의 후보(`slot.candidates`) 전체를 그대로
  보여주는 방식으로 교체**했다 — 슬롯 하나의 후보는 항상 같은 타입이라 타입 탭(전체/액티비티/
  체크인/아이템) 자체를 제거했다. 후보마다 상태 3가지: 보유 중이면 활성(탭해서 채움), 다른
  슬롯에 이미 쓰였으면 "사용 중"(비활성), 아예 보유하지 않았으면 흐리게 비활성 + "필요"
  표시. 이제 어떤 슬롯을 탭하든 그 슬롯을 채우려면 무슨 배지가 필요한지 항상 확인할 수
  있다. 활성 배지를 탭하면 그 슬롯에만 채워지고 시트가 자동으로 닫힌다.
- **TopNav**: `points`와 동일한 뒤로가기형(`<TopNav title={d.combine.title} onBack={...} />`)
  으로 교체. 믹서 화면에서는 뒤로가기가 라우트를 벗어나지 않고 먼저 레시피 탐색으로 돌아온다.
- **결과 피드백**: `BadgeRevealOverlay`에 `emptyMessage` prop을 추가해(기존 5개 호출처는
  영향 없음, 옵셔널) 배지가 0장인 성공(포인트만)·실패를 같은 오버레이 셸에서 메시지로
  보여준다. 오버레이를 닫으면 같은 레시피 화면에 슬롯만 비운 채로 유지된다(레시피 목록으로
  강제 복귀하지 않음).
- **신규 MODULAR**: `MixerSlot`(`design-system/components/patterns/`) — 빈/잠김/채움 3상태
  슬롯 카드. Storybook Story 4종(Empty/Locked/Filled/FilledNoImage) 포함, `_ds_manifest.json`·
  `readme.md`에 등록.
- 서버(매칭·소각·보상 지급)는 티켓 20260917_1427에서 이미 구현된 것을 그대로 사용 — API 계약
  변경 없음.
