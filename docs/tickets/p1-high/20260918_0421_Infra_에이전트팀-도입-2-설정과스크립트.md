# [Infra] 에이전트 팀 도입 ②: 설정과 스크립트

## 배경 / 문제 정의
비용 절감 효과가 가장 확실한 항목들이다. 모델 고정과 컨텍스트 축소는 모든 에이전트 호출에 누적된다.
근거: `JAM-WORK/05_자동화목록.md`, `01_공통규칙.md`(17~19번)

## 상세 요구사항

### ① 설정
- `.claude/settings.json`에 메인 세션 기본 모델 `"model": "sonnet"` 추가
- `permissions.deny`에 `Bash(git commit --no-verify)`·`Bash(git push --no-verify)` 추가
  (검사 우회 차단 — `verify`를 강제하기 위함)

### ② 스크립트 6개 (`jam-web/scripts/` 또는 저장소 루트 `scripts/`)
| 이름 | 내용 |
|---|---|
| `verify` | lint 전체 + typecheck + test 전체 + `ds:check` + 슬롭/금칙어 검사. **출력은 통과/실패와 실패 항목만** |
| diff 정리 | 잠금·자동 생성·대용량 데이터 파일을 뺀 diff와 변경 요약 출력 |
| 현황판 생성 | 티켓 frontmatter에서 OPEN·IN_PROGRESS·WAITING 목록 생성 |
| 승인 후 처리 | 오염 검사(`git merge-base --is-ancestor`) → staging 머지 → 티켓 CLOSED → push 1회 → Vercel 배포 확인 |
| 어드민 API 읽기 | 지표·미션·드랍·배지·유저 현황 조회 (service_role 키 사용하지 않음) |
| 작업 공간 준비 | 워크트리 생성 시 기존 `node_modules` 연결, 오래된 워크트리 정리 |

### ③ hook
- `.githooks/pre-push`에 리뷰 브랜치(`claude/jamwork-*`) push 시 `verify` 실행 추가
  (전체 테스트 3.1초 실측 — 부담 없음)
- 세션 시작 시 현황판을 읽어 들이는 hook (`.claude/settings.json`의 hooks)

## 구현 계획
1. 설정 파일 수정 → 모델 고정이 실제로 적용되는지 확인
2. `verify`부터 만들고 실제로 돌려 출력 형식 확인
3. 나머지 스크립트 순서대로
4. hook 연결 후 리뷰 브랜치에 시험 push

## 완료 조건
- `verify` 한 번으로 lint·타입·테스트·ds·슬롭 검사가 모두 실행되고, 출력이 20줄 이내다
- 리뷰 브랜치에 검사를 통과하지 못한 코드를 push하면 막힌다
- 현황판 스크립트가 OPEN 티켓 목록을 정확히 만든다
- 어드민 API 읽기 스크립트가 service_role 키 없이 동작한다
- 새 세션을 시작하면 현황판이 자동으로 읽힌다

## 진행 기록

### 구현 완료 (2026-09-18)
- `.claude/settings.json`: `"model": "sonnet"` 추가, `permissions.deny`에
  `Bash(git commit --no-verify)`·`Bash(git push --no-verify)` 추가, `hooks.SessionStart`에
  `node "$CLAUDE_PROJECT_DIR/scripts/ticket-dashboard.mjs"` 추가.
- `scripts/verify.sh`: lint:ci·typecheck·test·ds:check·슬롭(플레이스홀더) 5단계를 순차 실행,
  실패 항목과 로그 경로만 출력(2줄, 20줄 제한 안). 실측: node_modules 연결 후 약 35초.
  실행 중 `src/lib/__tests__/badgeProgressText.test.ts` 13건 실패를 실제로 잡아냈다 — 이는
  티켓 20260918_0420(선행 정리)에서 다루는 기존 문제이며 이 워크트리가 origin/staging 기준으로
  분기되어 0420의 수정이 아직 반영되지 않았기 때문이다. 0421이 만든 회귀는 아니다.
- `scripts/diff-summary.sh`: 잠금·자동생성·이미지 확장자 제외 diff, 500라인 이상 변경 파일은
  본문 생략하고 요약만 표시.
- `scripts/ticket-dashboard.mjs`: `docs/tickets/`(Archive 제외) frontmatter를 훑어
  OPEN·IN_PROGRESS·WAITING 목록 생성. 실행 결과 현재 15건 확인.
- `scripts/post-approval.sh`: 오염 검사(`git merge-base --is-ancestor origin/staging <branch>`)
  → staging 머지 → 티켓 CLOSED sed 치환 → push 1회 → `vercel ls jam-stage` 확인. 오케스트레이터가
  사용자 승인 후 수동 실행하는 보조 스크립트이며 자동 실행되지 않는다.
- `scripts/admin-api-read.mjs`: `ADMIN_API_COOKIE` 환경변수(어드민 화이트리스트 계정의 세션
  쿠키, 사람이 브라우저에서 한 번 발급)로 `/api/admin/{missions,badges,users,drop-policy,
  badge-metric-labels}` GET을 호출해 건수/값을 요약 출력. service_role 키를 쓰지 않는다.
  어드민 API에 "지표"(서비스 KPI) 전용 엔드포인트가 없어 badge-metric-labels로 대체했다
  (alerts 참고).
- `scripts/workspace-setup.sh`: `link <경로>`는 기존 워크트리의 `jam-web/node_modules`를
  심볼릭 링크로 연결(재설치 방지, 실측: 즉시 완료), `cleanup`은 미커밋 변경이 없고
  `origin/staging`에 이미 병합된 워크트리만 `git worktree remove`로 제거.
- `.githooks/pre-push`: `claude/jamwork-*` 브랜치 push 시 `scripts/verify.sh` 실행 블록 추가
  (기존 main·staging 게이트 로직은 그대로 유지). `JAM_SKIP_VERIFY=1`로 긴급 우회 가능 —
  기존 `JAM_SKIP_LINT` 패턴과 동일한 설계.

### 검증 방법
- `bash scripts/verify.sh` 직접 실행 → 실패 시 2줄 출력(실패 단계 + 로그 경로) 확인
