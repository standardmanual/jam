# [Infra] 한국어 리뷰 단계를 민지(게이트)로 흡수, 슬롭 사전 확장

## 배경 / 문제 정의
새 5단계 파이프라인(채원①·아현·민지·채원②·한국어)을 실제 티켓(20260915_2016)으로 시험한 뒤,
사용자가 "한국어 리뷰가 워크플로우에 별도로 있을 필요 없이 에이전트가 담당하면 되지 않나"라는
의문을 제기했다. 조사 결과:

- 한국어 리뷰는 `humanize-korean:humanize-monolith`라는 외부 플러그인을 매 `copy`·`ui`·`content`
  티켓마다 자동 호출하는 5번째 파이프라인 단계였다. 결과는 제안형(판정에 영향 없음)이라
  실효성이 낮았고, 파이프라인만 복잡하게 만들었다.
- 그 플러그인(`~/.claude/plugins/marketplaces/im-not-ai/`)의 taxonomy(931줄)를 확인한 결과,
  절반은 "패턴 매칭 가능"(hype 어휘, 이중 피동 등)하고 절반은 "문맥 판단 필요"(대명사 지시,
  리듬 균일성, register 혼재 등)였다. 전자만 기존 `scripts/check-slop.mjs`(diff 기반 grep
  검사)에 발췌해 넣을 수 있었다.
- `docs/service/writing/UX_WRITING_GUIDELINE.md` §7(Anti-slop 판단 기준, 2026-09-15 신설)이
  이미 이 플러그인을 참조하는 JAM 특화 기준을 담고 있었다 — 완전히 없애지 않고 두 용도(자동
  게이트 판정 / 대규모 전수검사)를 모두 인정하는 방향으로 갱신했다.

## 상세 요구사항
사용자 결정: 문맥 판단이 필요한 항목은 **민지(게이트 리뷰)**의 체크리스트로 흡수한다(채원②가
아니라 — 판정에 실질적 강제력이 생기도록).

- `docs/service/writing/SLOP_DICTIONARY.md`: taxonomy에서 패턴 매칭 가능한 항목(hype 어휘,
  이중 피동 등)을 발췌해 1·2절에 추가. 빈도·문맥 의존 항목("즉", "또한" 등 반복 시에만
  문제되는 것)은 존재-검사 방식과 안 맞아 오탐 위험이 커서 1·2절에서 제외하고 신설 4절
  "문맥 판단이 필요한 항목"으로 옮겼다
- `.claude/agents/conservative-reviewer.md`: 체크리스트 12번 "Korean naturalness" 신설.
  `SLOP_DICTIONARY.md` §4와 `UX_WRITING_GUIDELINE.md` §7을 함께 참조해 판정하고, 심각하면
  FAIL, 경미하면 WARN
- `.claude/workflows/jam-work.js`: `humanize-korean` 호출·`koreanReview`·`runKoreanReview`
  관련 로직 전부 제거. 5단계 → 4단계(채원①·아현·민지·채원②)로 단순화
- `.claude/skills/jam-work/SKILL.md`, `references/team-composition.md`,
  `references/common-rules.md`, `.claude/skills/jam-design/references/ui-review-checklist.md`,
  `docs/agents/issue-tracker.md`, `docs/service/writing/UX_WRITING_GUIDELINE.md` §7: 한국어
  리뷰 관련 서술을 민지 흡수 방식으로 갱신

### 주요 의사결정 / 핵심 메모
- taxonomy 전체 이식은 하지 않았다 — 대상(긴 글)이 JAM 실사용(짧은 UI 카피)과 안 맞고,
  원본이 계속 개선 중(v2.4~v2.7)이라 통째로 복사하면 유지보수가 단절된다
- "즉", "또한", "가지고 있다", "~에 대해(서)" 등은 원래 taxonomy에서 "한 문단 3회+ 반복 시"
  조건부였는데, grep 존재-검사로 옮기면 의미가 바뀌어(단독 사용도 위반 처리) 대량 오탐을
  일으킨다 — 이런 항목은 전부 4절(민지 담당)로 재배치했다
- "지형" 단독은 트라이브·POI 세계관 텍스트에 정상적으로 쓰일 수 있어 "업계 지형"이라는
  구체 구절만 남기고 단독 패턴에서 제외했다
