# [Infra] 이식 ② 기준 방어 훅과 CI 검증 도장 — 검사 결과를 기계가 남기고, 기준을 낮추는 변경을 막는다

## 핵심 요약

- 요구사항: (a) GitHub Actions로 `scripts/verify.sh`를 커밋마다 실행해 결과를 커밋 상태로 남긴다(검증 도장). 민지의 점검표 1번과 카리나의 머지 전 확인은 이 상태를 읽는다. (b) `constraint-driven-development`의 「기준 방어(guard the bar)」를 pre-push에 이식한다: 새 `eslint-disable`·`@ts-ignore`·`.skip`·`.only`, `--max-warnings` 상향, 테스트 파일 삭제를 차단한다. (c) 링크드 워크트리에서의 `staging` push를 pre-push가 차단한다(20260921_2207 #4). (d) 기준 수치는 `docs/agents/contract.json`에 선언한다.
- 구현 계획: `.github/workflows/verify.yml` 신설(트리거: `claude/**`·`staging` push, 단계: checkout → node 설치 → `npm ci` → `scripts/verify.sh`), `.githooks/pre-push`에 기준 방어·워크트리 차단 절 추가, `contract.json`에 `quality_bar` 절 신설, `jam-reviewer.md` 점검표 1번 문구 갱신, `/jam-work` SKILL.md 4단계 머지 전 확인에 상태 확인 추가.
- 관련 파일: `.githooks/pre-push`, `.github/workflows/`(신규), `docs/agents/contract.json`, `scripts/check-contract.mjs`(선언 검사 확장 시), `.claude/agents/jam-reviewer.md`(Checklist 1·「Re-running checks yourself」), `.claude/skills/jam-work/SKILL.md`(4단계), `jam-web/package.json`(`lint:ci --max-warnings 26`). 원본 스킬: `~/.claude/plugins/cache/addy-agent-skills/agent-skills/0.6.10/skills/constraint-driven-development/SKILL.md`(§Step 6 Guard the bar·§Floor), `~/.claude/plugins/cache/addy-agent-skills/agent-skills/0.6.10/skills/ci-cd-and-automation/SKILL.md`
- 상위 티켓: 20260921_2219. 포함하는 개선점: 20260921_2207 #1(검증 도장)·#4(staging push 차단). 경로: ③ 표준(infra)

## 배경 / 문제 정의

운영 점검(20260921_2207)에서 최근 CLOSED 59건 중 22건(37%)에서 민지가 `verify.sh`·테스트를 다시 돌렸고, 9건(15%)에서 `JAM_SKIP_*` 우회가 쓰였다. 원인은 "통과했다"는 사실을 기계가 어디에도 남기지 않아 확인 방법이 재실행뿐이라는 점이다. JAM에는 CI가 없고 훅만 있다(`.github/workflows` 부재). 또 아현의 `staging` push 금지는 프롬프트 규칙뿐이고(pre-push는 main만 차단), 검사 기준을 낮추는 변경(eslint-disable 추가·테스트 skip)을 막는 장치가 없다. 사고 이력의 결론("프롬프트로 막은 것은 예외 없이 뚫렸다")을 이 세 곳에 적용한다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **CI 검증 도장**: Actions 워크플로가 `claude/**`·`staging` push에서 `npm ci` 후 `scripts/verify.sh`를 훅 없이 직접 실행한다(`JAM_SKIP_*` 환경변수는 CI에서 무시된다). 결과는 커밋 상태(check)로 남는다. 카리나가 상태를 읽는 명령(`gh run list --commit <sha>` 또는 `gh api`)을 `/jam-work` 4단계 오염 검사 옆에 적는다. 민지 점검표 1번은 "push 시점 verify 통과"에서 "CI 상태 성공"으로 바꾸고, 재실행 조건에서 "[주의] 알림"을 뺀다(재실행은 상태가 없거나 실패했을 때만).
2. **기준 방어(pre-push)**: 이번 push 범위의 diff에서 다음을 차단한다 — `eslint-disable`(파일·줄 단위 모두)·`@ts-ignore`·`@ts-expect-error` 신규 추가, `it.skip`·`describe.skip`·`.only` 신규 추가, `*.test.*` 파일 삭제, `package.json`의 `--max-warnings` 값 상향. 정당한 예외는 우회 변수 대신 **diff 안의 사유 주석**(예: `// eslint-disable-next-line ... -- 사유`)이 있을 때만 통과시킨다.
3. **워크트리 차단**: `git rev-parse --git-common-dir`이 `.git`이 아닌 곳(링크드 워크트리)에서 `staging`으로 push하면 차단한다. 우회 변수는 두지 않는다. 카리나는 메인 트리에서만 push한다.
4. **선언**: `contract.json`에 `quality_bar` 절(`lint_max_warnings: 26`, 차단 패턴 목록)을 두고, `package.json` 값과 훅의 패턴이 선언과 일치하는지 `check-contract.mjs`가 대조한다.
5. **비용 기록**: Actions 실행 1회의 소요 시간과 분당 과금(비공개 저장소)을 완료 기록에 남긴다. 리뷰 브랜치 push는 Vercel 빌드를 만들지 않으므로 CI만 는다.

## 구현 계획

1. 임시 저장소에 훅을 복사해 기준 방어 4종과 워크트리 차단을 테스트한다(`scripts/*.test.mjs` 형식, `GIT_*` 제거 규칙 준수 — 가드레일 패턴 15).
2. 워크플로 파일을 작성하고 리뷰 브랜치 push로 1회 실측한다.
3. 정의·스킬·contract 문서를 갱신하고 `gen-team-doc` 생성 구간이 걸리면 생성기를 돌린다.

## 완료 조건

- 리뷰 브랜치 push 뒤 GitHub에 커밋 상태(verify)가 남고, `gh`로 조회한 결과가 완료 기록에 있다(실측 1회).
- 임시 저장소에서 기준 낮춤 변경 4종(eslint-disable 추가·@ts-ignore 추가·.skip 추가·테스트 파일 삭제)의 push가 각각 다른 문구로 막히고, 사유 주석이 있는 eslint-disable은 통과한다.
- 링크드 워크트리에서 `git push origin staging`이 막히고, 메인 트리에서는 통과한다(임시 저장소 테스트).
- `jam-reviewer.md` 점검표 1번과 재실행 조건이 갱신되어 있고, `/jam-work` SKILL.md 4단계에 상태 확인 명령이 있다.
- `contract.json`에 `quality_bar` 선언이 있고 `check-contract.mjs`가 대조한다. `scripts/verify.sh` 통과.
