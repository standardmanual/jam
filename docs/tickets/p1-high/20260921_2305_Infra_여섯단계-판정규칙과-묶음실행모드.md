# [Infra] 카리나의 여섯 단계 판정 규칙(진입 조건·정지 조건 단일 원천)과 묶음 실행 모드

## 핵심 요약

- 요구사항: 사용자 결정(2026-09-21)대로 워크플로 뿌리를 「카리나 주도 여섯 단계(Define→Plan→Build→Verify→Review→Ship)」로 확정한다. `/jam-work` SKILL.md의 유형 판정 앞에 **단계 판정**(각 단계의 진입 조건·실행 주체·사용자 승인 지점)을 두고, **정지 조건 목록**을 한 곳에만 정의해 묶음 실행·야간 루프·재작업이 모두 참조하게 한다. 묶음 실행 모드는 상위 티켓 단위로만 켠다.
- 구현 계획: SKILL.md 0절 앞에 「0.0 단계 판정」 표를 추가하고, `references/handling-rules.md`(또는 새 `references/stop-conditions.md`)에 정지 조건을 단일 원천으로 둔다. `jam-work.js`에 `batch` 인자(상위 티켓 ID)를 추가해 하위 티켓을 순서대로 실행하고, 티켓마다 게이트를 돌리며, 정지 조건에서 반환한다. 카리나 카드에 "단계 판정 → 유형 판정" 순서와 「가정 목록 공개」 규칙을 넣는다.
- 관련 파일: `.claude/skills/jam-work/SKILL.md`(0절·3.1절), `.claude/skills/jam-work/references/handling-rules.md`, `.claude/workflows/jam-work.js`(인자 파싱·실행 루프), `docs/agents/orchestrator.md`(카리나 카드), `docs/agents/team-operations.md` §3. 원본 스킬: `~/.claude/plugins/cache/addy-agent-skills/agent-skills/0.6.10/skills/using-agent-skills/SKILL.md`(수명주기·핵심 동작 6개), `~/.claude/plugins/cache/addy-agent-skills/agent-skills/0.6.10/skills/spec-driven-development/SKILL.md`(§Phase 1 가정 목록), `~/.claude/plugins/cache/addy-agent-skills/agent-skills/0.6.10/skills/incremental-implementation/SKILL.md`, agent-skills `commands/build.toml`(`auto` 모드의 단일 승인·정지 조건 원문)
- 상위 티켓: 20260921_2219 §6. 경로: ③ 표준(infra)

## 배경 / 문제 정의

이식 분석(20260921_2219 §6.1)에서 여섯 단계를 카리나의 판정 순서로 삼기로 했다. 지금 `/jam-work`는 유형 판정(0.2)만 있고 "이 요청이 어느 단계에 있는가"와 "다음 단계로 넘어갈 조건"이 문서에 없다. 정지 조건(게이트 FAIL·[중단]·`db`/`engine` 진입·되돌릴 수 없는 작업·채원 `needs_approval`)도 SKILL.md 3절, 루프 제안(20260921_2234), 아현 정의에 흩어져 있어 갈라질 위험이 있다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **단계 판정 표**(2219 §6.1 표를 옮긴다): DEFINE·PLAN·BUILD·VERIFY·REVIEW·SHIP마다 진입 조건 / 실행 주체 / 사용자 승인. 기계가 확인할 수 있는 조건(예: 완료 조건 절이 비어 있지 않다, `ui`·`ds`면 채원 판정이 있다)은 `check-contract`나 `ticket-dashboard`가 검사하도록 후속 항목으로 적는다.
2. **가정 목록**: 요청이 모호하면 BUILD로 보내기 전에 "이런 가정으로 진행한다" 목록을 사용자에게 보여 주고 확인받는다(`spec-driven-development` §Phase 1). 카리나 카드에 한 줄, SKILL.md 0절에 양식.
3. **정지 조건 단일 원천**: 목록을 한 파일에 두고 SKILL.md 3절·아현 정의·`jam-work.js` 주석·루프 문서는 그 파일을 가리킨다. 항목: 게이트 FAIL · `[중단]` 알림 · `db`/`engine` 유형 진입 · 되돌릴 수 없는 작업(DB 변경·외부 발행·프로덕션 배포) · 채원 `needsApproval` · 아현 `plan_only`/`needs_design`/`halted` · 같은 티켓 2회 연속 FAIL.
4. **묶음 실행(`batch`)**: `Workflow(name: 'jam-work', args: { batch: '<상위 티켓 ID>' })`로 호출하면 상위 티켓의 「하위 티켓」 표(또는 `parent` 필드)에서 OPEN 티켓을 순서대로 실행한다. 티켓마다 지금과 같은 파이프라인(채원①→아현→민지∥채원②)이 돌고, 정지 조건에 걸리면 그 티켓에서 멈춰 결과를 반환한다. 머지는 카리나가 순차로 한다(각 브랜치는 `origin/staging`에서 분기하므로 앞 티켓 머지 뒤 뒤 티켓은 오염 검사에 걸릴 수 있다 → 재분기 절차를 SKILL.md 4단계에 적는다). 기본은 끔. 사용자가 상위 티켓 분해안을 승인할 때 "묶음 실행"을 명시했을 때만 쓴다.
5. **토큰 기록**: batch 실행은 티켓별 `tokenUsage`를 티켓 ID로 나눠 반환한다.

## 구현 계획

1. 정지 조건 파일을 먼저 만들고 기존 문서 세 곳의 서술을 참조로 바꾼다.
2. SKILL.md 0.0절·가정 목록 양식·4단계 재분기 절차를 쓴다. 카리나 카드는 40줄 이내를 지킨다.
3. `jam-work.js`에 `batch` 분기를 추가한다(하위 티켓 조회는 `docs/tickets/`에서 `parent:` 필드로).
4. 작은 OPEN 티켓 2건(예: 20260921_1411·1412)을 상위 티켓 없이 임시 목록으로 묶어 드라이런하거나, 실제 상위 티켓이 있으면 실측한다. 실측 결과(토큰·소요)를 완료 기록에 남긴다.

## 완료 조건

- SKILL.md에 단계 판정 표와 가정 목록 양식이 있고, 카리나 카드에 "단계 판정 → 유형 판정" 순서가 한 줄로 있다(카드 40줄 이내 유지, `node scripts/ticket-dashboard.mjs` 출력 확인).
- 정지 조건이 한 파일에만 정의되어 있고, SKILL.md·아현 정의·`jam-work.js`·루프 검토 티켓의 후속 문서가 그 파일을 참조한다(`git grep`으로 중복 정의 0건).
- `batch` 호출로 하위 티켓 2건이 순서대로 실행되고 티켓별 결과·토큰이 나뉘어 반환된다(실측 1회 또는 드라이런 기록).
- 기본 동작(`batch` 없이 호출)은 기존과 동일하다(기존 티켓 1건 실측으로 회귀 확인).
