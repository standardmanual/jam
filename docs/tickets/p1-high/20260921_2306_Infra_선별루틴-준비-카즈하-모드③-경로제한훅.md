# [Infra] 선별 루틴 준비 — 카즈하 모드 ③(무인 적격 판정), 리포트 규격, 무인 커밋 경로 제한 훅, 루틴 스펙

## 핵심 요약

- 요구사항: 루프 1단계 「선별 루틴」(사용자 결정 2026-09-21: 등록, 읽기 전용 2주 관찰)을 등록할 수 있게 준비한다. 카즈하(`jam-ops`)에 모드 ③ 선별을 추가하고, 리포트·상태 파일 규격을 정하고, 무인 커밋이 리포트 폴더 밖을 못 건드리게 pre-commit으로 막고, `scheduled-jobs.md`에 루틴 스펙(시각·환경·프롬프트·상한)을 적는다. **루틴 등록 자체는 카리나가 수동 1회 실행으로 확인한 뒤 사용자 승인을 받아 한다.** 코드 수정은 하지 않는 루틴이라 무인 권한표(§4-3) 안에 있다.
- 구현 계획: `jam-ops.md`에 모드표(① 주간 브리핑 ② 월간 문서 점검 ③ 선별)와 선별 절차, `scheduled-jobs.md`에 「선별 — 매일 06:00 KST」 절, `.githooks/pre-commit`에 무인 작성자 경로 제한, 주간 브리핑 양식에 「선별 동의율」 칸.
- 관련 파일: `.claude/agents/jam-ops.md`, `.claude/skills/jam-work/references/scheduled-jobs.md`, `.claude/skills/jam-work/references/forms/weekly-briefing-format.md`, `.githooks/pre-commit`, `docs/agents/team-operations.md` §6, `docs/agents/contract.json`(hooks·경로 선언), `jam-doc/operations/reports/README.md`

## 배경 / 문제 정의

루프 검토(20260921_2234)의 결론: 큐는 있는데 소비 주체가 사람이다. 첫 단계는 티켓을 고치는 것이 아니라 **어느 티켓이 무인 처리에 적격인지만 판정**하는 읽기 전용 루틴이고, 사용자가 2주 동안 판정에 동의하는 비율이 다음 단계(야간 소화)의 근거가 된다. 선별 판정을 티켓 파일에 쓰면 무인 커밋이 `docs/tickets/`를 건드리게 되므로, 판정은 리포트 폴더 안의 상태 파일에만 기록한다(스키마 필드 등록이 필요 없어진다).

## 상세 요구사항

### 서비스/코드베이스 관점

1. **판정 기준** (모두 만족해야 적격): ① 범위가 닫혀 있다 — 관련 파일 지도가 티켓에 있고 파일 5개·100줄 이내로 예상된다(아현 `plan_only` 임계와 동일) ② 검증이 기계적이다 — `verify.sh` 통과가 완료 증명이 된다(화면 육안 확인 불필요) ③ 되물을 일이 없다 — 구현 계획이 적혀 있고 선택지가 남아 있지 않다 ④ 되돌릴 수 있다 — DB 변경·외부 발행·프로덕션 배포가 없다 ⑤ 제외 영역 — 훅·워크트리·git 설정·`CLAUDE.md`·에이전트 정의·워크플로 스크립트를 건드리지 않고, 유형이 `infra`·`db`·`engine`이 아니다. 판정 불가는 전부 「사람 필요」.
2. **증분 실행**: 전날 실행 이후 생성·수정된 OPEN 티켓만 읽는다(기준: `git log --since` 또는 상태 파일의 마지막 실행 시각). 상태 파일 `jam-doc/operations/reports/triage/state.json`에 티켓별 판정·이유·판정 시각을 캐시한다. 조용한 날은 리포트를 만들지 않는다(또는 "변경 없음" 한 줄).
3. **리포트** `jam-doc/operations/reports/triage/YYYY-MM-DD.md`: 티켓당 한 줄 — `- [ ] {티켓 ID} · {적격|사람 필요} · {이유 한 줄}`. 사용자는 동의하면 체크한다. Slack `#jam-report`에 건수와 적격 목록만 요약.
4. **동의율**: 주간 브리핑 양식에 「선별 동의율」 칸(체크된 줄 / 전체 줄)을 두고 카즈하가 계산한다. 2주 뒤 이 값이 야간 소화 도입 재질문의 입력이다.
5. **경로 제한 훅**: 루틴 커밋 작성자(현재 예약 작업 커밋의 작성자 이름 `Claude`, 정확한 이메일은 `git log --format=%ae --grep="예약 작업"`으로 확인해 적는다)의 커밋이 `jam-doc/operations/reports/` 밖 파일을 바꾸면 pre-commit이 차단한다. 우회 변수는 두지 않는다.
6. **루틴 스펙**: 매일 06:00 KST, 환경 `jam-ops`, 모델 Haiku(동의율이 80% 미만이면 Sonnet으로 2주 재측정 후 기준 수정 순으로 대응), 도구 호출 30회·토큰 상한 명시, 실패 시 `#jam-alert`. 프롬프트 초안은 지시를 받지 않는 원칙(§6)대로 고정 문장으로 쓴다.
7. **문서**: `team-operations.md` §6 예약 목록에 선별 루틴 추가(생성 구간이면 생성기), `contract.json`에 리포트 경로·훅 선언.

## 구현 계획

1. `jam-ops.md` 모드 ③ 절과 `scheduled-jobs.md` 루틴 절을 쓴다.
2. pre-commit 경로 제한을 임시 저장소에서 테스트한다(작성자 위장 커밋 4종: 리포트 폴더 안 통과 / 밖 차단 / 혼합 차단 / 일반 작성자 무관).
3. 카리나가 세션에서 카즈하 모드 ③을 1회 수동 실행해 리포트·상태 파일이 만들어지고 `docs/tickets/`가 바뀌지 않는 것을 확인한다.
4. 루틴 등록은 이 티켓 밖(사용자 승인 후 카리나).

## 완료 조건

- 카즈하 모드 ③ 수동 실행 1회에서 `triage/YYYY-MM-DD.md`와 `state.json`이 만들어지고 티켓당 한 줄 형식을 지키며, `git status`에 `docs/tickets/` 변경이 없다.
- 두 번째 실행에서 변경된 티켓이 없으면 새 판정을 만들지 않는다(증분 확인).
- 임시 저장소에서 루틴 작성자의 리포트 폴더 밖 커밋이 pre-commit에 막히고, 폴더 안 커밋은 통과한다.
- 주간 브리핑 양식에 「선별 동의율」 칸이 있고 계산식이 적혀 있다.
- `scheduled-jobs.md`에 선별 루틴 절(시각·환경·모델·상한·프롬프트·실패 처리)이 있고 등록 절차가 "수동 1회 → 사용자 승인 → 등록"으로 적혀 있다.
