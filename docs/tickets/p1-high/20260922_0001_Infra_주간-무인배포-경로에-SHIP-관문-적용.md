# [Infra] 주간 무인 배포 경로에 `/jam-ship`의 새 관문을 어디까지 적용할지 정하고 루틴 프롬프트를 고친다

## 핵심 요약

- 요구사항: 티켓 20260921_2303이 `/jam-ship`에 신설한 「배포 전 점검표」「롤백 계획」「완료 기준」「배포 후 검증」은 사람이 세션에서 배포할 때만 적용된다. 목요일 23:59 KST 무인 배포(실행 루틴 `trig_01JRRY1cXt6uWGin8xbtS1Sk`)는 fetch → ff 머지 → push → `curl`만 수행한다. 무인 경로에 적용할 범위를 정하고, 루틴 프롬프트와 `scheduled-jobs.md`를 함께 고친다.
- 구현 계획: ① 클라우드 환경(`jam-ops`)에서 실행할 수 있는 점검을 가려낸다 ② 낮 확인 글에 마이그레이션 포함 여부와 롤백 계획 요약을 넣어, 사용자의 "승인" 답장이 그 계획까지 승인하도록 만든다 ③ 실행 루틴의 배포 확인을 "새 배포가 실제로 공개됐는가"까지 넓힌다 ④ 루틴 프롬프트를 교체한다.
- 관련 파일: `.claude/skills/jam-work/references/scheduled-jobs.md` 「주간 배포 승인」, `.claude/skills/jam-ship/SKILL.md`, 저장소 밖에 있는 루틴 프롬프트(claude.ai/code/routines)
- 상위 티켓: 20260921_2303. 출처: 민지 게이트 리뷰의 WARN 사유(회귀 위험). 경로: ③ 표준(infra). 무인 프로덕션 배포의 동작이 바뀌므로 적용 범위는 사용자 승인을 받아서 정한다.

## 배경 / 문제 정의

확인된 사실(2026-09-22):

- 실행 루틴의 절차는 `scheduled-jobs.md` 「배포 실행」 절에 있는 bash 블록과 같다. 점검표·롤백 계획·완료 기준·배포 후 검증 단계가 없다.
- 주간 배포 루틴의 프롬프트는 "문서와 충돌하면 이 지시가 우선한다"고 명시한다(티켓 20260920_1933 완료 기록). 따라서 `scheduled-jobs.md`만 고쳐서는 무인 실행의 동작이 바뀌지 않는다.
- Vercel은 롤백을 실행한 뒤에 프로덕션 도메인 자동 할당을 끈다. 그 상태에서 main에 push하면 새 배포가 만들어져도 공개되지 않는다. 그런데 옛 배포가 계속 200으로 응답하므로, 실행 루틴의 `curl` 확인은 그대로 통과한다(Vercel 문서 「Performing an Instant Rollback」의 「Undo a rollback」 절).
- 첫 무인 실행 예정일은 2026-09-24(목)이다.

판단: 새 안전장치가 사람이 있는 경로에만 적용되어 있고, 사람이 없는 경로에는 적용되어 있지 않다. 다만 무인 경로의 동작 자체는 2303 이전과 같으므로, 기존보다 위험해진 것은 아니다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. 무인 경로에서 실행할 수 있는 점검을 가려낸다. 비밀값 `grep`, 승격 범위 안의 신규 마이그레이션 파일 유무, 되돌림 SQL 동반 여부는 git만으로 확인된다. `scripts/verify.sh`·`npm audit`·`vercel env ls`·Supabase 적용 여부 대조는 클라우드 환경의 의존성 설치·인증·네트워크 허용 목록에 달려 있으므로, 실제로 실행되는지부터 확인한다.
2. 낮 확인 글(루틴 ①)에 "신규 마이그레이션 N건(되돌림 SQL 있음/없음)"과 롤백 계획 요약(되돌릴 직전 배포, 롤백은 사용자 승인 후 세션에서 실행)을 넣는다. 되돌림 SQL이 없는 마이그레이션이 포함된 주에는 무인 배포를 건너뛴다.
3. 실행 루틴의 배포 확인을 `curl` 200 확인에서 "프로덕션이 방금 push한 커밋의 배포를 가리키는가"로 강화한다. 클라우드에서 Vercel CLI 인증을 쓸 수 없으면 대안(빌드 커밋 SHA를 노출하는 응답 헤더나 엔드포인트)을 검토한다.
4. 무인 롤백은 계속 하지 않는다(기존 안전장치 유지). 이상이 감지되면 `#jam-alert`에 올리고 사용자 결정을 기다린다.
5. 루틴 프롬프트를 교체하고, 고친 부분의 before/after를 이 티켓에 남긴다. `scheduled-jobs.md` 「배포 실행」 절과 `/jam-ship` SKILL.md의 무인 경로 안내 문구를 같은 작업에서 맞춘다.

## 구현 계획

1. 카리나가 적용 범위 안을 만들어 사용자에게 승인받는다(무인 권한표가 바뀌므로 필수).
2. 아현이 `scheduled-jobs.md`와 필요한 스크립트를 고치고, 민지가 게이트 리뷰를 한다.
3. 카리나가 루틴 프롬프트를 교체하고, 다음 목요일 실행 결과(배포 리포트)로 동작을 확인한다.

## 완료 조건

- 무인 경로에 적용하는 점검과 적용하지 않는 점검이 `scheduled-jobs.md`에 사유와 함께 적혀 있다.
- 낮 확인 글 형식에 마이그레이션 포함 여부와 롤백 계획 요약이 있다.
- 실행 루틴이 "새 배포가 공개됐는가"를 확인하고, 공개되지 않았으면 `#jam-alert`에 올린다.
- 루틴 프롬프트의 before/after가 이 티켓에 남아 있고, 교체 후 첫 실행 결과가 기록돼 있다.
