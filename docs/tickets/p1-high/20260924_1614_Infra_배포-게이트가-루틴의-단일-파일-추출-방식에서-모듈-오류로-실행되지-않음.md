# [Infra] 티켓 1555로 게이트가 옆 파일을 불러오게 되어, 루틴의 단일 파일 추출 방식에서 `ERR_MODULE_NOT_FOUND`로 죽는다

## 핵심 요약

- 요구사항: `scripts/deploy-gate.mjs`를 **다시 단일 파일**로 만든다. 티켓 20260924_1555(머지 `c6954775`)가 판정 함수를 `scripts/deploy-gate-wrapper.mjs`로 분리하고 `deploy-gate.mjs`가 `import ... from './deploy-gate-wrapper.mjs'`(35줄)로 불러오게 했는데, 루틴은 이 파일 **하나만** `/tmp`로 꺼내 실행해서 모듈을 찾지 못한다.
- 긴급도: 이 결함 때문에 2026-09-24 23:59 KST 주간 배포는 여전히 막힌다(게이트 실행 오류는 차단으로 처리된다). 오늘 밤 전에 staging에 반영돼야 한다.
- 구현 계획: 아래 「구현 계획」 1~6을 따른다.
- 관련 파일:
  - `scripts/deploy-gate.mjs` (35줄 import, 파일 맨 아래 `main(...)` 호출, 머리말의 "성격: 의존성 없음")
  - `scripts/deploy-gate-wrapper.mjs` (150줄, 순수 함수 `stripSource`·`moduleSpecifierFor`·`checkWrapperSource`·`routeUsesWrapper`·`WRAPPER_AUTH_CALLS`)
  - `scripts/check-contract.mjs` (22줄 import, 427줄 부근 auth_wrappers 대조)
  - `scripts/deploy-gate.test.mjs`
  - `docs/agents/contract.json` (`paths_exist`의 `scripts/deploy-gate-wrapper.mjs`, `deploy_gate._why`)
  - `.claude/skills/jam-work/references/scheduled-jobs.md` (202~213줄, 루틴이 게이트 스크립트를 꺼내는 절차)

## 배경 / 문제 정의

루틴 문서(`scheduled-jobs.md` 202~213줄)는 게이트를 이렇게 꺼내 실행한다고 정해 두었다.

```bash
git show origin/staging:scripts/deploy-gate.mjs > /tmp/deploy-gate.mjs && test -s /tmp/deploy-gate.mjs
node /tmp/deploy-gate.mjs check
```

2026-09-24 16:13 KST 카리나가 이 방식 그대로 재현했다(최신 staging).

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/private/tmp/deploy-gate-wrapper.mjs' imported from /private/tmp/deploy-gate.mjs
종료코드=1
```

티켓 1555를 검증할 때 카리나가 `/tmp`에 **두 파일을 함께** 복사해서 이 문제를 가렸다. 아현·민지의 검증도 저장소 안에서 실행해서 잡지 못했다. `deploy-gate.mjs` 머리말에는 이미 "성격: 의존성 없음(Node 내장 모듈과 전역 fetch만 쓴다 — 클라우드 세션에서 npm install 없이 돈다)"이라고 적혀 있었다. 같은 규칙(래퍼 판정)을 두 파일에 적지 않으려고 분리한 것이 이 전제와 충돌했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- **단일 파일 원칙을 계약 검사로 강제한다.** `deploy-gate.mjs`에 다른 스크립트 파일을 가리키는 상대 경로 import(`from './...'`, `from '../...'`)가 생기면 `check-contract.mjs`가 위반으로 잡는다.
- 판정 동작은 티켓 1555와 **완전히 같아야 한다**(기존 테스트 전부 통과, 새 로직 없음). 이 티켓은 코드를 옮기고 가드를 붙이는 일이다.
- 판정 규칙을 두 파일에 복제하지 않는다. 판정 함수는 `deploy-gate.mjs`에만 두고 `check-contract.mjs`는 그곳에서 가져다 쓴다.
- **`deploy-gate.mjs`는 직접 실행하면 항상 `main`을 실행해야 한다**(fail-closed). 라이브러리로 불러올 때만 명시적으로 끈다: `globalThis.__JAM_DEPLOY_GATE_AS_LIBRARY__ === true`일 때만 건너뛴다. 실행 경로를 비교해서 판정하는 방식(`import.meta.url`과 `process.argv[1]`)은 쓰지 않는다. 심볼릭 링크(`/tmp` → `/private/tmp`) 때문에 비교가 어긋나면 게이트가 아무것도 검사하지 않고 종료 코드 0으로 끝나는 위험이 있기 때문이다.
- 저장소·DB·Vercel에 쓰지 않는다는 성격과 "의존성 없음(Node 내장 모듈만)"을 유지한다.
- 이 티켓은 `jam-web/` 파일을 고치지 않는다.

## 구현 계획

1. `scripts/deploy-gate-wrapper.mjs`의 순수 함수(주석 포함)를 `scripts/deploy-gate.mjs`로 옮기고 `export`를 유지한다. `import ... from './deploy-gate-wrapper.mjs'`(35줄)를 지우고 `scripts/deploy-gate-wrapper.mjs`를 삭제한다.
2. `deploy-gate.mjs` 맨 아래의 `main(...)` 호출 전체를 `if (globalThis.__JAM_DEPLOY_GATE_AS_LIBRARY__ !== true) { ... }`로 감싼다. 머리말에 "단일 파일이어야 하는 이유(루틴이 이 파일 하나만 꺼내 실행한다)"와 위 플래그의 용도를 적는다.
3. `scripts/check-contract.mjs`: 22줄의 정적 import를 지우고, 파일 안에서 `globalThis.__JAM_DEPLOY_GATE_AS_LIBRARY__ = true`를 먼저 설정한 뒤 `await import('./deploy-gate.mjs')`로 `checkWrapperSource`·`moduleSpecifierFor`·`WRAPPER_AUTH_CALLS`를 가져온다. 그리고 **`deploy-gate.mjs` 본문에 상대 경로 import가 없는지** 검사하는 계약 항목을 추가한다(위반 메시지에 "루틴이 이 파일 하나만 /tmp로 꺼내 실행한다"는 이유를 적는다).
4. `scripts/deploy-gate.test.mjs`: 옮긴 함수를 가져오던 테스트의 경로를 고친다. **회귀 테스트를 추가한다**: (a) 임시 디렉터리에 `deploy-gate.mjs` **한 파일만** 복사하고, 테스트 픽스처 저장소를 대상으로 그 복사본을 실행해서 종료 코드가 0 또는 1이며 출력에 `ERR_MODULE_NOT_FOUND`가 없어야 한다(루틴 방식 재현). (b) `__JAM_DEPLOY_GATE_AS_LIBRARY__`를 켜고 불러오면 `main`이 실행되지 않고 함수만 쓸 수 있다. (c) 플래그 없이 직접 실행하면 항상 `main`이 실행된다(인자 없이 실행하면 사용법과 종료 코드 64).
5. `docs/agents/contract.json`: `paths_exist`에서 `scripts/deploy-gate-wrapper.mjs`를 빼고, `paths_absent`에 등록해 다시 분리되는 것을 막는다(이유: 루틴이 단일 파일만 꺼낸다). `deploy_gate._why`에서 "판정은 deploy-gate-wrapper.mjs"라는 서술을 `deploy-gate.mjs`로 바로잡는다.
6. `.claude/skills/jam-work/references/scheduled-jobs.md`의 게이트 스크립트를 꺼내는 절차(206줄 부근)에 한 줄을 더한다: "이 스크립트는 단일 파일이어야 하며(다른 스크립트를 불러오지 않는다) `check-contract.mjs`가 그것을 확인한다." 규칙의 원천은 `contract.json`이므로 문서에는 이 참조만 둔다.

## 완료 조건

- (카리나, 머지 뒤) **루틴과 똑같이** 최신 staging에서 파일 하나만 꺼내 실행한 결과가 종료 코드 0이다.
  ```bash
  git show origin/staging:scripts/deploy-gate.mjs > /tmp/deploy-gate.mjs && test -s /tmp/deploy-gate.mjs && node /tmp/deploy-gate.mjs check
  ```
  출력에 `API 라우트: 통과 — 새 라우트 6건(인증 확인 6건, 이 중 인증 래퍼 경유 2건...)`과 `인증 래퍼: 통과`가 나온다.
- 티켓 1555의 테스트(래퍼에서 인증 호출 제거·가져오기만 하고 미호출·주석 위장·지역 함수 사칭 차단)를 포함한 기존 `deploy-gate.test.mjs`가 모두 통과하고 판정 결과가 바뀌지 않는다.
- 위 4번 회귀 테스트 (a)~(c)가 있고 통과한다. (a)는 `deploy-gate-wrapper.mjs`를 다시 불러오게 만들면 실패한다.
- 계약 검사가 `deploy-gate.mjs`의 상대 경로 import를 위반으로 잡는다(단위 테스트 또는 임시 수정으로 확인).
- `scripts/deploy-gate-wrapper.mjs`가 없고 `jam-web/` 파일이 바뀌지 않았다.
