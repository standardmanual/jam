# [BadgeEngine] JAM! 카테고리 행동 지표 추가 (O5)

> 상위: 20260930_1450 · 순서 2 병행 · 07 인벤토리 G(O5)

## 핵심 요약

- 요구사항: 액티비티 배지 JAM! 카테고리에 행동 지표를 더한다. 드랍, 픽업, 남의 드랍 픽업, 주워짐, 믹스 시도·성공·실패, 레시피 최초 성공,
  미션 완료, 컬렉션 완성, 가입 경과일, 주간 활동일, 같은 지점 방문일(06 6.2 O5, 07 5.2).
- 구현 계획: 부풀릴 수 없게 센다. 같은 아이템을 다시 주운 것은 한 번만, 상대가 있는 지표는 서로 다른 유저 수로, 주간 활동일은 동기화나
  체크인을 한 날만 센다(06 6.2 「O5 계산 방식」). 자원 연결(1500)에서 JAM! 배지를 쓰려면 먼저 필요하다.
- 관련 파일: `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md`, `jam-web/src/lib/badge-engine/`, 드랍·픽업 API `jam-web/src/app/api/drops/`,
  06 플랜 6.1(지금 지표 6종).

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

**사용자 결정 (2026-10-01).**

- Q1 소급: **기록이 있는 만큼 센다.** 미션·컬렉션은 전체 기록, 드랍·픽업은 2026-08-29 이후, 믹스는 기록을 시작한 날부터. 새 배지를 열기 전에 받을 유저 수와 포인트 합계를 먼저 본다(하위 ④).
- Q2 활동일: **실제로 활동한 날(활동 기록의 날짜)과 체크인한 날로 센다.** 앱을 열기만 한 날과 동기화만 한 날은 세지 않는다. 06 플랜 74행·O5 계산 방식과 OPS_PATTERNS를 고쳤다.
- Q3 자기 드랍: **줍기는 지금처럼 허용하고 배지 숫자에서만 뺀다.**
- 분할: **하위 티켓 4개로 나눠 ①부터 진행한다.** 마이그레이션은 하위 티켓마다 사용자 승인을 받는다.

**가정 (사용자가 수정 없이 받아들임, 2026-10-01).** 혜린 검토의 A1~A20이다. 요지만 적는다.

- 모든 수는 서로 다른 아이템 개체·유저·날짜로 센다(A14). 드랍·픽업은 개체 수, 남의 드랍 픽업·주워짐은 서로 다른 상대 유저 수이고 자기와 시스템 드랍, 탈퇴 유저는 뺀다(A1~A4, A15).
- 믹스 시도는 재료가 소각된 믹스(성공+실패), 빈손 성공도 성공, 실패는 `no_recipe_match`만(A5~A7). 레시피 최초 성공은 전체 유저 중 처음 1명, DB가 동시 성공을 하나로 선점하고,
  이 기능 배포 뒤 만든 레시피에만 붙이는 것을 운영 규칙으로 한다(A8).
- 미션 완료는 서로 다른 미션 수, 컬렉션 완성은 장착·동기화 두 경로 모두에서 판정, 가입 경과일은 KST 날짜 차, 주간 활동일은 역대 최고 주(월~일 KST)의 활동일 수로 1회 발급,
  같은 지점 방문일은 지점별 서로 다른 방문일의 최댓값(A9~A13).
- 행동 직후 판정하고 판정 실패가 본 동작 응답을 깨지 않는다. 주워짐은 놓은 사람에게 발급한다. 획득 알림은 알림함과 피드만(A16). 단계형은 레벨형(A17). JAM! 공통 제약 유지(A18).
  2026-08-29 이전 드랍·픽업 행은 세지 않는다(A19).

**포인트 추천 (미검증, 1459 밸런스 규칙의 초기값 제안으로 넘긴다).** 배지는 모두 100 이하. 첫 경험(첫 드랍·첫 믹스) 10 · 횟수·인원 누적(줍기·함께 줍기·나눔가·믹스 성공·
방문일·활동일) 단계별 5/10/20 · 믹스 실패 0(실패 보상 10이 이미 있다) · 가입 경과일 10/20 · 미션 완료·컬렉션 완성 30/60/100 · 레시피 최초 성공 50.

**주의할 점 (혜린).** 공용 단일 DB의 CHECK 재정의(키만 넓히는 추가형, 롤백 전 사용 행 조회) · 소급 지급 크기는 유저 8명이라 작지만 미측정 · 포인트 시뮬레이터가 없다 ·
