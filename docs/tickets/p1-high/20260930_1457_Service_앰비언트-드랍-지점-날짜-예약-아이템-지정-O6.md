# [Service] 앰비언트 드랍의 지점·날짜 예약·아이템 지정 (O6)

> 상위: 20260930_1450 · 순서 2 병행 · 07 인벤토리 G(O6)
> 선행: 20260930_1516(컬렉션 노출 판정 통일)을 먼저 끝낸다. 이 티켓이 그 판정에 기대기 때문이다(티켓 20260930_1451 결정).

## 핵심 요약

- 요구사항: 앰비언트 즉시 배포에 대상 지점, 날짜 예약, 아이템 단위 지정을 더한다(06 6.2 O6). 운영툴 일정표에 드랍을 올리고 예약 공개하려면
  먼저 필요하다(07 5.1).
- 구현 계획: 혜린 검토에서 확정한다. 알려진 제약은 정기 배포와 즉시 배포가 설정 하나를 공유해, 즉시 배포 때 바꾼 설정이 다음 정기 배포에
  남는다는 점이다(티켓 20260929_2226 드랍 제약).
- 관련 파일: `jam-web/src/lib/ambient-drop/`(`index.ts`, `config.ts`), `jam-web/src/app/api/admin/ambient-drop/`, `jam-web/src/app/admin/ambient-drop/`,
  `docs/service/badge-engine/BADGE_ENGINE_UNIFIED.md` §3.12.

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

### 주요 의사결정 / 핵심 메모
> 시작할 때 혜린 검토에서 사용자가 답한 내용을 먼저 적는다(상위 티켓 20260930_1450 진행 규칙 3).

- (시작 검토 입력, 2026-10-01 티켓 20260930_1459에서) 밸런스 규칙 R8(경제 수치 불변)은 항목의 `resource`·`knobs`에 `drop_policy`·`combine_policy`의
  값 컬럼 이름 23개(`ops_rules`의 `economy_keys`)가 들어 있으면 주의를 띄운다. `drop_schedule` 필드를 정할 때 이 이름과 겹치지 않게 하거나(예: 등급
  비율을 `rarity_*` 이름으로 두면 R8에 걸린다), 겹쳐야 하면 R8 키 목록을 함께 고친다(운영툴 PRD §5.2 「R8의 키 목록은 1457이 확정」).
- (같은 출처) 운영툴 PRD §5.2 「규칙이 읽는 자리」에는 `drop_schedule` 행이 없고 R8만 적용된다. 드랍 일정에 밸런스 규칙이 더 필요하면(예: 1459에서
  근거가 없어 보류한 「드랍 대상 컬렉션 수」) 시작 검토에서 정한다. R1(동시 개방 수)은 1516의 노출 판정을 쓰므로, 드랍 대상 컬렉션도 같은 판정을
  따르는지 함께 본다.

- (혜린 시작 검토, 2026-10-01) 첫 판단은 「만들자」. 드랍 확률·등급 비율·보상 수치는 바꾸지 않는다. 공급량이 늘 수 있다는 영향은 미검증이다(시뮬레이터는
  영향 티켓 20261001_1219로 고치는 중, DB 직접 조회 없음). 규모는 파일 약 30개·3,000줄로 추정해 하위 조각 3개로 나눈다(아래 「하위 티켓」).
- 사용자 결정(2026-10-01, 다섯 질문 모두 추천안):
  - Q1 놓을 지점: 예약마다 「지점 직접 선택(몇 곳이든)」과 「지점 종류+개수(시스템이 흩어 놓음, 매일 배포와 같은 방식)」 중 하나를 고른다. 한 예약 안에서
    섞지 않는다.
  - Q2 놓을 것: 예약마다 「아이템 직접 선택」과 「컬렉션 선택(그 안의 노출 중 아이템에서 시스템이 고름)」 중 하나를 고른다.
  - Q3 겹침: 직접 고른 지점에 이미 드랍이 있어도 겹쳐서 놓는다. 등록 화면에서 「이미 드랍이 있는 지점 N곳」을 미리 알린다. 종류+개수 예약은 매일
    배포와 같은 한도(`max_active_per_poi`)로 흩어 놓는다.
  - Q4 지금 배포: 새 예약 폼에서 시각 대신 「지금」을 고를 수 있게 한다. 지정한 1회 배포이고 매일 배포 설정에는 저장하지 않으며 이력에 남는다. 기존
    「지금 배포」 버튼(저장된 설정, 본문 없는 POST)은 그대로 둔다.
  - Q5 놓은 뒤: 내리지 않는다. 예약은 「완료」로 끝나고 안 주워진 드랍은 매일 배포처럼 남는다. 회수 기능은 필요해지면 후속 티켓으로 한다. 07 4.4·4.9에
    「드랍 일정은 놓은 뒤 내리지 않는다」 한 줄을 먼저 더한다(진행 규칙 5, 이 답으로 승인).
- 가정(혜린 초안, 카리나 확정): A1 예약은 새 테이블 `ambient_drop_schedules`에 두고 싱글톤 `ambient_drop_config`를 쓰지 않는다(완료 조건 2는 구조로
  보장하고 실행 전후 config 행 비교 테스트). A2 매일 배포는 그대로 돌고 예약은 그 위에 더해지며 예약에는 상호 배제 창을 적용하지 않는다. A3 시각은 KST
  정시만 받고 과거 시각은 거절한다. A4 실행 주체는 기존 매시 cron(`api/cron/ambient-drop`)이다. 도래한 예약을 먼저 처리하고, 예약 실패는 격리해 매일 배포를
  막지 않으며 `auto_enabled`와 무관하게 돈다. `vercel.json`은 바꾸지 않고 라우트에 `maxDuration = 60`을 둔다. A5 한 번만 실행한다(`scheduled → running`
  조건부 UPDATE 선점). 3시간(임시값)을 넘겨 놓치면 `missed`로 두고 놓지 않는다. A6 대상은 1516 노출 판정을 따른다. 실행 때 `isItemBookDroppable(book,
  ranAt)`·아이템 `deleted_at`·`valid_from/until`·지점 `is_active`로 다시 보고 걸린 것은 건너뛰며 사유를 남긴다(fail-closed). 등록 때는 같은 판정을
  「예정 시각」 기준으로 미리 돌린다. A7 지정할 수 있는 아이템은 컬렉션 소속 아이템 배지뿐이다. A8 예약에는 등급 비율을 두지 않는다. 필드 이름은
  `poi_ids`·`poi_category`·`badge_ids`·`collection_ids`·`per_poi_count`·`total_count`로 R8 키 23개와 겹치지 않는다. R8 목록은 23개로 확정하고 겹침
  방지 테스트를 둔다. A9 새 밸런스 규칙은 만들지 않고 예약 1건당 총 100개 상한(임시값, 위반 400)을 둔다. A10 서버 함수 5동작(만들기·공개 전 취소·공개
  전 시각 수정·상태 읽기·실행 후 취소 409)을 1458과 같은 모양으로 둔다. 내용 수정은 취소 후 새 등록이다. A11 `drop_schedule` 항목의 `ends_at`은
  형식 오류다. A12 화면은 `/admin/ambient-drop`에 구역을 더하고 `PoiSearchSelect`·`MultiBadgeSearchSelect`·`ItemBookSearchSelect`를 재사용한다.
  A13 실행 이력은 `ambient_batch_result`에 `trigger: 'scheduled'`로 남긴다. A14 슬랙 알림과 「예약 누락」 신호는 1500·1502-④ 몫이다. A15 유저 화면은
  변하지 않는다. A16 DB는 새 테이블 추가(확장 단계)뿐이다.
- 1500에 넘길 메모: 서버 함수 5개를 부른다(HTTP 아님), `created_resource`에는 예약 id, 같은 묶음이면 컬렉션 생성이 드랍 예약보다 먼저(등록 판정이 예정
  시각 기준), 되돌림은 공개 전 취소까지. 1500의 선행 조건은 「1457 하위 ① 종료」로 줄일 수 있다(혜린 제안).
