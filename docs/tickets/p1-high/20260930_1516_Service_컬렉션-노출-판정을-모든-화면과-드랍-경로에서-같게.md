# [Service] 컬렉션 노출 판정을 모든 화면·드랍 경로에서 같게 한다

> 상위: 20260930_1450 · 진행 규칙 4로 생성(티켓 20260930_1451 결정)

## 핵심 요약

- 요구사항: 아직 공개하지 않은 컬렉션(`item_books.is_active=false`이거나 `valid_from`·`valid_until` 기간 밖)은 어떤 화면·API·드랍 경로에서도
  보이거나 드랍되지 않는다. 지금은 주소를 직접 열면 보일 수 있다.
- 구현 계획: 컬렉션 노출 판정(`is_active` + 노출 기간, 마이그레이션 171)을 한 곳에 모으고, 필터가 빠진 세 경로(`/api/itembooks`,
  `/collections/[id]`, 앰비언트 드랍)에 적용한다. 착수 전에 20260924_0938(트라이브 비활성화의 드랍 반영)을 합칠지 판단한다.
- 관련 파일:
  - `jam-web/src/app/api/itembooks/route.ts` 62줄 부근: `item_books`를 `.in('id', bookIds)`로만 읽고 활성·기간 조건이 없다
  - `jam-web/src/app/(main)/collections/[id]/page.tsx` 86~93줄 부근: `.eq('id', id).single()`로만 읽고 활성·기간 조건이 없다
  - `jam-web/src/lib/ambient-drop/index.ts` 89~106줄 「축 3: 대상 컬렉션」: random 모드는 `is_active`만 보고 기간을 보지 않는다.
    explicit 모드는 `config.collection_ids`를 그대로 써서 활성 여부도 보지 않는다
  - 이미 판정을 쓰는 곳(맞출 기준): `jam-web/src/lib/itembook/checker.ts` 37~44줄, `jam-web/src/lib/itembook/completable.ts` 33~40줄,
    `jam-web/src/lib/admin/itembook-list-query.ts` 82~106줄(「노출 중」 정의)
  - 스펙: `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md` §3.12(앰비언트 대상 컬렉션), `docs/specs/prd/02_DATA_MODEL.md` item_books 절

## 배경 / 문제 정의

- 티켓 20260929_2226 「사실 확인 결과」(233~237줄, 2026-09-29 코드 조회): 컬렉션 노출 판정은 `is_active` + `valid_from/valid_until`이다.
  프로필 컬렉션·드랍엔진·완성 판정은 이 조건을 쓰지만, `/collections/[id]` 직접 접근과 `/api/itembooks`는 필터가 없다. 앰비언트 드랍은
  random 모드가 기간을 보지 않고, explicit 모드는 활성 여부도 보지 않는다.
- `/api/itembooks`에 활성·기간 조건이 없는 것은 2026-09-30 검토자가 직접 확인했다. 같은 날 세 경로의 코드를 다시 열어 위 관련 파일의
  줄 위치를 확인했다.
- 07 블루프린트 5.1은 컬렉션 예약 공개를 「된다(기간)」로 적었다. 새 운영 체계는 공개 전 컬렉션을 미리 만들어 두고 공개 시각에 여는
  방식이라, 공개 전 컬렉션이 주소나 설정 실수로 드러나면 런칭이 새어 나간다.
- 순서: 20260930_1457(앰비언트 드랍의 지점·날짜 예약·아이템 지정)과 20260930_1500(자원 연결·예약 공개)이 이 판정에 기댄다. 두 티켓보다
  먼저 끝낸다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 기존 코드가 쓰는 노출 판정은 `is_active = true` 그리고 (`valid_from`이 비었거나 지금 이전) 그리고 (`valid_until`이 비었거나 지금 이후)다
  (`checker.ts`·`completable.ts`). 이 조건을 공용 함수(또는 쿼리 헬퍼) 하나로 모으고, 필터가 빠진 경로가 그것을 쓴다.
- **반드시 막을 것: 공개 전 컬렉션**(비활성이거나 `valid_from` 이전). `/api/itembooks` 목록에서 빠지고, `/collections/[id]`는 없는 컬렉션과
  같이 404(`notFound()`)가 되고, 앰비언트 드랍 대상에서 빠진다.
- 앰비언트 드랍: random 모드에 기간 조건을 더한다. explicit 모드는 설정된 컬렉션 가운데 판정을 통과한 것만 쓰고, 하나도 남지 않으면
  드랍하지 않고 사유를 로그와 실행 결과에 남긴다(카리나 초안, 착수 때 확인).

### 착수 때 정할 것 (카리나 초안에는 추천을 붙였다)
- **기간이 끝난 컬렉션(`valid_until` 이후)을 이미 보유한 유저에게 계속 보여 줄지.** 06 플랜(62줄)은 「일반적인 루틴으로 만든 것은 생성 뒤
  사라지지 않는다」고 적었고, 20260930_1503은 「기간 한정 운영이 끝나 얻을 길이 없는 아이템」을 보여 주는 기능이다. 추천: 드랍 대상에서는
  빼고, 보유자의 화면(`/collections/[id]`)에서는 계속 보이게 한다. 이 경우 화면용 판정과 드랍용 판정이 둘로 나뉘므로 헬퍼도 둘로 둔다.
- **`/api/itembooks` 목록 라우트를 쓰는 화면이 있는지.** 2026-09-30 `jam-web/src`에서 `api/itembooks` 문자열을 찾았을 때 목록 라우트의 호출부는
  나오지 않았다(`/slot` 하위 라우트만 나왔다). 쓰는 곳이 없으면 필터를 더하는 대신 라우트를 지우는 것도 선택지다.
- **어드민 미리보기 예외.** 어드민이 공개 전 컬렉션을 `/collections/[id]`로 확인하는 흐름이 있으면 어드민에게만 보이는 예외를 둘지 정한다.
- **20260924_0938(트라이브 비활성화가 드랍에 반영되지 않음)을 합칠지.** 같은 「노출 판정」 계열이다. 합치면 드랍엔진의 트라이브 조회에
  활성 조건을 더하는 일까지 이 티켓에서 한다.

## 구현 계획

「착수 때 정할 것」 네 가지는 2026-10-01 사용자가 정했다(「주요 의사결정」 E1~E4). 아래는 그 결정을 반영한 파일 단위 계획이다.

**판정 두 가지.** 결정 E1에 따라 판정을 둘로 나눈다. 시각 비교는 기존 코드처럼 ISO 문자열의 대소 비교다.

| 판정 | 조건 | 쓰는 곳 |
|---|---|---|
| 공개됨(화면용) | `is_active` 그리고 (`valid_from`이 비었거나 지금 이전) | `/api/itembooks`, `/collections/[id]`, 장착 `/api/itembooks/[id]/slot` |
| 노출 중(드랍·완성용) | 공개됨 그리고 (`valid_until`이 비었거나 지금 이후) | 앰비언트 드랍, 완성 판정(`checker.ts`), 완성 가능 소식(`completable.ts`) |

1. **신규 `jam-web/src/lib/itembook/visibility.ts`** — 순수 판정 2개(`isItemBookLaunched(book, nowIso)`, `isItemBookDroppable(book, nowIso)`. 인자는
   `is_active`·`valid_from`·`valid_until`만 가진 객체)와 쿼리 헬퍼 2개(`applyLaunchedItemBookFilter(query, nowIso)`, `applyDroppableItemBookFilter(query, nowIso)`.
   지금 `checker.ts` 41~44행에 있는 `.eq('is_active', true).or(...)` 체인을 그대로 옮긴다). 머리 주석에 위 표와 결정 E1을 적는다.
2. **`jam-web/src/app/api/itembooks/route.ts`** 62행 `item_books` 조회에 `applyLaunchedItemBookFilter`를 건다(결정 E2: 라우트를 지우지 않고 필터를 더한다).
   공개 전 컬렉션은 응답에서 빠지고, 기간이 끝난 컬렉션은 그대로 나온다(E1). 뒤의 배지·슬롯·완성 조회는 걸러진 컬렉션 id로만 한다.
3. **`jam-web/src/app/(main)/collections/[id]/page.tsx`** 86~93행 — 조회 뒤 `isItemBookLaunched`가 거짓이면 `notFound()`. 어드민 예외는 두지 않는다(E3).
   기간이 끝난 컬렉션은 그대로 보인다(E1).
4. **`jam-web/src/app/api/itembooks/[id]/slot/route.ts`**(카리나가 더한 범위, 아래 발견 2) — 장착 RPC를 부르기 전에 컬렉션을 읽어 공개되지 않았으면 404로 막는다.
   오류 표(19~30행)에 컬렉션 없음 항목을 더한다. 새 문구가 필요하면 `jam-web/src/lib/i18n/ko.ts` `itembooks`(1087행 부근)에 기존 404 문구와 같은 형식
   ([현상]. [해결책])으로 더한다. 기간이 끝난 컬렉션의 장착은 막지 않는다(E1: 보유자는 계속 쓸 수 있다).
5. **신규 `jam-web/src/lib/ambient-drop/collectionTarget.ts`** — 순수 함수 `resolveAmbientTargetCollections({ useRandom, configIds, droppableIds, pick })`.
   돌려주는 값은 `{ effectiveCollectionIds, restrictToCollectionIds, excludedCollectionIds, reason? }`이다.
   - random: `droppableIds`에서 하나를 고른다. 비었으면 `reason: 'no_eligible_collection'`.
   - explicit, `configIds`가 있음: `droppableIds`와 겹치는 것만 남기고 빠진 것은 `excludedCollectionIds`에 담는다. 하나도 안 남으면 `reason: 'no_eligible_collection'`.
   - explicit, `configIds`가 빈 배열(「전체」): `effectiveCollectionIds`는 `[]` 그대로 두되 `restrictToCollectionIds = droppableIds`로 후보 배지를 노출 중 컬렉션으로 좁힌다
     (아래 발견 1). `droppableIds`가 비었으면 `reason: 'no_eligible_collection'`.
6. **`jam-web/src/lib/ambient-drop/index.ts`** 89~106행 「축 3」 — 노출 중 컬렉션 id를 `applyDroppableItemBookFilter`로 한 번 읽고 5번 함수로 대상을 정한다.

## 완료 조건

- 「착수 때 정할 것」 네 가지의 사용자 결정이 이 티켓 「주요 의사결정」에 적혀 있다.
- 공개 전 컬렉션(비활성, `valid_from` 이전)이 `/api/itembooks` 응답에 없다(라우트 테스트). 라우트를 지우기로 했으면 라우트와 테스트가 없다.

- 앰비언트 드랍 random 모드가 기간 밖 컬렉션을 고르지 않고, explicit 모드가 비활성·기간 밖 컬렉션에 드랍하지 않는다(단위 테스트).

- 공개 전 컬렉션에 장착하는 요청은 404이고 장착 RPC를 부르지 않는다(라우트 테스트).
- 필터가 빠졌던 경로가 공용 판정 헬퍼를 쓴다는 것을 코드로 확인할 수 있다.
- `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md` §3.12와 관련 스펙이 바뀐 동작과 맞고, `scripts/verify.sh`가 통과한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- 판정을 «공개됨»(화면용: 활성 + 공개 시각 지남)과 «노출 중»(드랍·완성용: 공개됨 + 기간 안)으로 나눠 `jam-web/src/lib/itembook/visibility.ts`에 모았다. 시각 비교는 표기 차이를 피하려고 epoch ms로 했다(아현 가정 1).
- 목록 API(`/api/itembooks`)는 공개된 컬렉션만 읽고 배지·슬롯·완성 조회도 걸러진 id로만 한다. 상세(`/collections/[id]`)는 공개되지 않으면 `notFound()`다.
  장착 `POST /slot`은 RPC 전에 컬렉션을 읽어 없거나 공개 전이면 404(`item_book_not_found`, 신규 문구 `itemBookNotFound`)다. DELETE·PATCH는 칸 수를 늘리지 않아 두었다(가정 2).
- 앰비언트 드랍은 노출 중 컬렉션만 읽어 `resolveAmbientTargetCollections`(`collectionTarget.ts`)로 대상을 정한다. 「전체」는 후보 배지를 노출 중 컬렉션으로 좁히고,
  대상이 없으면 POI 조회 전에 `no_eligible_collection`으로 건너뛴다(빈 배열이 「전체」로 넓어지던 발견 1을 막음). 조회 실패도 건너뛴다(fail-closed, 가정 3).
- `checker.ts`·`completable.ts`는 같은 헬퍼로 바꿨고 동작은 그대로다. 기간이 끝난 컬렉션은 보유자에게 계속 보이고 장착도 막지 않는다(E1).
