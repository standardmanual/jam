## 상세 요구사항

### 서비스/코드베이스 관점
- 주간 루틴은 이미지를 만들지 않는다. 채원·윈터의 이미지용 호출과 루틴 본체의 `npm ci`도 하지 않는다. 이미지가 필요한 후보는 리포트 표에
  「이미지: 승인 뒤 세션에서 만든다」로 적는다(지금의 「이미지 준비 대기(사유)」 표기와 구분한다).
- 미션 대표 이미지(`missions.image_url`)를 재사용하는 카드 규칙은 그대로 둔다(새로 만드는 이미지가 아니다).
- 슬랙 편성 안내 글의 「이미지 N장 포함」 줄은 「이미지는 승인 뒤 세션에서 만든다」로 바꾼다. PRD §8-1 표도 같이 고친다.
- 리포트 「비용」 절의 비교 기준 문장(이미지 단계 포함 실행값 371,460)은 이미지 단계가 빠진다는 사실을 함께 적도록 고친다.
- 루틴이 커밋하는 경로(`jam-doc/operations/reports/weekly/` 리포트와 `YYYY-Www-images/`)는 바꾸지 않아도 된다. 이미지 폴더가 더는 생기지 않을 뿐이다.
- 승인 뒤 세션의 이미지 제작은 지금 문서의 세션 경로(윤진 ⑧의 세션 실행, 등록은 메인 세션)를 그대로 쓴다. 새 절차를 만들지 않는다.

   (`job_config.ccr`를 통째로 바꾸므로 프롬프트와 차단 도구를 함께 보낸다, `scheduled-jobs.md` 32줄 부근 주의).
