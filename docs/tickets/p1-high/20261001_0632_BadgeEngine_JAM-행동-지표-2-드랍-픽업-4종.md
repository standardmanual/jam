- 구현 계획: 아래 「구현 계획」(파일 단위, 혜린 초안·카리나 확정 2026-10-01)을 따른다. 0712 머지 뒤 착수한다.
- 관련 파일: `jam-web/src/app/api/drops/route.ts:353`(드랍 등록 뒤), `jam-web/src/app/api/drops/[dropId]/pickup/route.ts:129`(픽업 뒤), ①의 지표 계산 파일, `poi_drops`(`jam-web/supabase/migrations/004_phase7_user_drops.sql:15`, `108_item_identity_custody_model.sql:49`)

### 키 이름과 정의 (②)

| 키 | 값 | 세는 것 | 가정 |
|---|---|---|---|
| `drop_item_count` | 정수 ≥1 | 내가 놓은 서로 다른 아이템 개체 수(같은 개체를 몇 번 놓아도 1) | A1 |
| `pickup_item_count` | 정수 ≥1 | 내가 주운 서로 다른 아이템 개체 수. 자기 드랍은 뺀다. 시스템 드랍·놓은 사람이 탈퇴한 드랍은 포함한다 | A2, Q3 |
| `pickup_from_user_count` | 정수 ≥1 | 내가 주운 드랍을 놓은 서로 다른 유저 수. 자기·시스템·탈퇴 유저는 뺀다(함께 줍기) | A3, A15 |
| `picked_up_by_user_count` | 정수 ≥1 | 내가 놓은 드랍을 주운 서로 다른 유저 수. 자기·탈퇴 유저는 뺀다(나눔가) | A4, A15 |

- 모든 지표는 `inventory_item_id`가 있는 행만 센다(A19, 2026-08-29 이전 행이 자동으로 빠진다). 원시 행 수를 세는 지표는 없다(A14).

- 라이브 인덱스 확인(카리나, 2026-10-01): `poi_drops`의 인덱스는 `idx_poi_drops_available`·`idx_poi_drops_inventory_item`·`idx_poi_drops_system_available`·`poi_drops_pkey` 4개로 저장소와 같고, 놓은 사람·주운 사람 조회 인덱스는 없다.

   ```
   SELECT u.id,

     (SELECT count(DISTINCT inventory_item_id) FROM poi_drops WHERE picked_up_by=u.id AND inventory_item_id IS NOT NULL AND dropper_user_id IS DISTINCT FROM u.id) AS pickup_item_count,
   ```

### 구현 범위 (게이트 판정 대상)
- 마이그레이션 2개에 각각 `-- 되돌림 SQL` 블록이 있다(`deploy-gate check` 통과). 201은 CHECK를 66키로 넓히고 기존 행을 바꾸지 않는다. 202는 `poi_drops`에 부분 인덱스 2개를 더한다.

- 자기 드랍을 자기가 주운 것은 픽업·함께 픽업·주워짐에 세지 않고 드랍 수에는 센다(테스트). 줍는 동작 자체는 바뀌지 않는다.
- 시스템 드랍과 놓은 사람이 탈퇴한 드랍은 픽업에 세고 함께 픽업에는 세지 않는다. 줍는 사람이 탈퇴한 행은 주워짐에 세지 않는다(테스트).
- `inventory_item_id`가 없는 행은 어떤 지표에도 세지 않는다(테스트). 서로 다른 유저 수는 서로 다른 유저만 센다(테스트).
- 행이 1,000개를 넘어도 끝까지 읽고 30페이지를 넘으면 그 지표만 건너뛴다(fail-closed, 테스트).
- 4개 지표 각각을 조건으로 한 배지가 조건을 채우면 발급된다(테스트).
- 드랍·픽업 성공 뒤 `after()`로 판정한다(드랍 → 놓은 사람 `drop_item_count`, 다른 유저 드랍 픽업 → 줍는 사람 2키와 놓은 사람 `picked_up_by_user_count`, 시스템 드랍 → 줍는 사람 `pickup_item_count`만,
  자기 드랍 → 판정 없음). 실패 분기에서는 예약하지 않는다(테스트).
- 판정·알림이 실패해도 두 라우트의 응답 본문·상태 코드·에러 문구와 소식 #13은 변경 전과 같다(테스트).
- 레지스트리가 66키를 선언하고 최신 CHECK 마이그레이션의 키 집합과 같다(자동 탐지 테스트). 새 4키는 단독 저장되고 `repeat_count`와 함께면 거부된다. 어드민 폼 왕복(테스트).
- 유저 조건 문구는 고정 용어 「드랍」·「픽업」을 쓴다(UX Writing 검증 기록).
- 기존 JAM! 지표·믹스 지표 경로와 `badge-condition-guards.ts`는 바뀌지 않고 기존 테스트가 전부 통과한다.
