# [Infra] 세션 시작 훅의 워크트리 정리가 사용 중인 앱 세션 워크트리까지 지운다

## 핵심 요약
- 요구사항: 세션 시작 훅이 실행하는 `scripts/workspace-setup.sh cleanup`이 앱이 만든 세션 워크트리(병렬 카리나 세션의 작업 폴더)를 지우지 않게 한다. 무엇을 지웠는지 나중에 확인할 수 있게 기록을 남긴다.
- 구현 계획: `cleanup_worktrees`의 제거 대상을 파이프라인이 만드는 `.claude/worktrees/wf_*` 경로로 한정하고(가정 1), 제거·보존 판정을 git 공용 디렉터리의 로그 파일에 시각과 함께 남긴다(가정 2). 테스트 사례를 추가하고 `docs/agents/team-operations.md` 「워크트리 수명」 3번을 고친다.
- 관련 파일: `scripts/workspace-setup.sh` `cleanup_worktrees()` L106-144(제거 조건 L110-139), `remove_worktree()` L91-104 / `scripts/workspace-setup.test.mjs`(cleanup 사례 L29-96) / `.claude/settings.json` L80-84(SessionStart 세 번째 훅) / `docs/agents/team-operations.md` L155-167 「워크트리 수명」

## 배경 / 문제 정의

### 확인한 사실 (2026-10-01 11:40경 KST, 명령으로 확인)
- 티켓 20260930_1502를 맡은 세션이 열리자마자 작업 폴더 `.claude/worktrees/amazing-dhawan-bfd6a9`가 디스크에 없었다. `.git/worktrees/`의 등록 정보도 없었다. 브랜치 `claude/amazing-dhawan-bfd6a9`는 남아 있고, 가리키는 커밋은 `efd7be8d4`(= `origin/main`, `origin/staging`의 조상)다.
- `.claude/settings.json` SessionStart 훅이 모든 세션 시작 때 `scripts/workspace-setup.sh cleanup`을 `async`로 실행하고 출력을 `/dev/null`로 버린다.
- `cleanup_worktrees`는 메인 체크아웃을 뺀 모든 워크트리 가운데 `git status --short`가 비어 있고 HEAD가 `origin/staging`의 조상인 것을 `git worktree remove`(강제 옵션 없음)로 지운다. 경로·브랜치 이름은 보지 않는다.
- 같은 시점에 남아 있던 워크트리 9개의 상태:

- 저장소 안에서 `git worktree remove`를 실행하는 곳은 `scripts/workspace-setup.sh`와 `scripts/cleanup-stale-worktree.sh` 둘이다. 후자는 인자로 받은 브랜치를 점유한 워크트리 하나만 다룬다.
- `.claude/worktrees/karina-merge` 폴더는 디스크에 있지만 `git worktree list`에 없다. 폴더의 `.git` 파일이 가리키는 `.git/worktrees/karina-merge`가 존재하지 않는다(폴더 수정일 2026-09-26).

### 판단
- `amazing-dhawan-bfd6a9`는 다른 세션이 시작될 때 돈 `cleanup`이 지웠다고 본다(확신도 높음). 아무것도 고치지 않은 새 워크트리라서 제거 조건 두 개를 모두 만족했고, 남은 9개도 "잠겨서 제거가 거부됨" 또는 "미커밋 변경·미병합이라 보존됨"으로 모두 같은 규칙에 맞는다. 정확한 시각과 실행한 세션은 출력을 버리기 때문에 특정하지 못했다(티켓 20260928_2339에서 출력을 버리도록 바뀌었다).
- 이 정리 기능의 원래 대상은 Workflow가 `.claude/worktrees/wf_*`에 만드는 격리 워크트리다(`docs/agents/team-operations.md` 「워크트리 수명」 1번). 앱 세션 워크트리는 설계 당시 고려 대상이 아니었던 것으로 보인다.
- 같은 일은 계속 일어난다. 데이터는 잃지 않지만(미커밋 변경이나 미푸시 커밋이 있으면 보존된다) 세션이 작업 폴더를 잃고 멈춘다. 위험한 순간은 두 가지다.
  1. 세션을 막 열어 아직 아무것도 고치지 않았을 때(이번 사례)
  2. 워크트리 세션이 커밋을 staging에 push해서 HEAD가 staging에 포함되고 변경이 없어졌을 때
- 1458·1459 세션은 워크트리를 직접 잠가서 이 위험을 피하고 있다. 이 방법은 규칙표나 문서에 없다.

### 재발 기록
- 2026-10-08 13:40경 KST: 티켓 20261008_1349 세션이 열린 직후 첫 명령에서 작업 폴더 `.claude/worktrees/priceless-goldwasser-8b738a`가 이미 없었다(셸이 "Working directory ... was deleted"로 응답). `git worktree list`에도 없었고, 브랜치 `claude/priceless-goldwasser-8b738a`(HEAD `836983f78`, `origin/staging`의 조상)는 남아 있었다. 위험한 순간 1번(아무것도 고치지 않은 새 세션)과 같다. 같은 경로에 워크트리를 다시 만들고 `git worktree lock`으로 잠근 뒤 작업을 이어 갔다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `cleanup`이 앱 세션 워크트리를 잠금 여부와 상관없이 지우지 않는다.
- 기존 대상(staging에 병합되고 변경이 없는 `wf_*` 워크트리)은 지금처럼 지운다.
- 브랜치 정리(`cleanup_local_branches`)와 `cleanup --remote`의 동작은 바꾸지 않는다.
- 제거·보존 판정이 시각과 함께 기록되어, 훅 출력을 버려도 나중에 확인할 수 있다.

## 구현 계획

착수 전에 아래 가정을 사용자에게 확인받는다.

1. **(가정 1, 추천) 제거 대상을 경로로 한정한다.** `cleanup_worktrees`가 `$REPO_ROOT/.claude/worktrees/wf_*` 경로의 워크트리만 제거 후보로 본다. 나머지는 "보존(정리 대상 경로 아님)"으로 출력한다. 파이프라인이 만드는 폴더만 건드리는 허용 목록 방식이라, 앞으로 새 종류의 워크트리가 생겨도 기본값이 "지우지 않음"이 된다.
   - 대안: 브랜치 이름이 `claude/<폴더명>`인 워크트리(앱 세션 이름 규칙)만 건너뛰는 제외 목록 방식. 세션이 `git checkout --detach`로 브랜치를 떼면 구분하지 못하므로 추천하지 않는다.
   - 확인할 점: `.claude/worktrees/` 아래 `wf_*`가 아닌 이름 가운데 파이프라인이 만드는 것이 있는지(`elated-bohr-e3d2a1`·`modest-blackburn-deb10c` 같은 detached HEAD 워크트리의 출처). 있으면 그 이름 규칙도 허용 목록에 넣는다.
2. **(가정 2) 판정 기록을 남긴다.** `cleanup` 실행마다 시각·워크트리 경로·판정(제거/보존/실패와 사유)을 `$(git rev-parse --git-common-dir)/workspace-cleanup.log`에 덧붙인다. git 내부 디렉터리라 `git status`에 잡히지 않고 `.gitignore`를 고칠 필요가 없다. 파일이 커지지 않게 최근 500줄만 유지한다.
3. `scripts/workspace-setup.test.mjs`에 앱 세션 워크트리 보존 사례를 추가한다.
4. `docs/agents/team-operations.md` 「워크트리 수명」 3번의 정리 대상 문장을 고치고, 판정 기록 위치를 한 줄 덧붙인다.

수정 전까지 쓸 회피책: 워크트리에서 여는 카리나 세션은 첫 작업으로 아래 명령을 실행해 워크트리를 잠근다(1458·1459 세션이 쓰는 방식).
`git worktree lock --reason "티켓 <번호> 카리나 세션 사용 중" "$(git rev-parse --show-toplevel)"`

- `node scripts/workspace-setup.test.mjs`가 통과하고, 새 사례가 다음을 확인한다: 임시 저장소에 변경이 없고 staging에 병합된 워크트리 두 개(`.claude/worktrees/wf_test`, 브랜치 `claude/app-test`인 `.claude/worktrees/app-test`)를 만들고 `cleanup`을 실행하면 `wf_test`는 제거되고 `app-test`는 남는다.
- 기존 사례(로컬 브랜치 정리, `cleanup --remote` 목록/삭제 분리, `link-secrets`)가 그대로 통과한다.

- `docs/agents/team-operations.md` 「워크트리 수명」 3번이 바뀐 정리 대상을 설명한다.

### 후속 범위 (담당: 카리나, 시점: staging 머지 뒤)
