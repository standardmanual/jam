# [Service] 배지 화면 2곳의 컬렉션 조회에도 공개 판정을 적용한다

> 민지 게이트 리뷰 WARN 사유 2와 범위 밖 발견물 [주의] 2건(티켓 20260930_1516, 2026-10-01)이다. 사용자가 1516 머지 직후 바로 실행하기로 했다(2026-10-01).

## 핵심 요약

- 요구사항: 1516은 목록 API·컬렉션 상세·장착·앰비언트 드랍에 「공개됨」 판정을 걸었지만, `/badges` 컬렉션 탭과 배지 상세의 컬렉션 카드는 아직 공개 여부를 보지 않고
  `item_books`를 읽는다. 그래서 공개 전 컬렉션(라이브 100개 중 비활성 70개, 2026-10-01 조회)의 진행도·카드·이름·이미지가 보이고, 카드 링크는 1516 이후 404가 된
  `/collections/[id]`로 이어지는 막다른 링크가 된다. 두 화면도 같은 판정을 쓰게 한다.
- 구현 계획: 두 조회에 화면용 판정 `applyLaunchedItemBookFilter`(`jam-web/src/lib/itembook/visibility.ts:50`)를 건다. 판정 정의는 `docs/specs/prd/02_DATA_MODEL.md` «컬렉션 노출 판정»이 단일 원천이다.
  - 컬렉션 탭: 걸러진 컬렉션 id로만 소속 배지·슬롯·완성 조회를 한다(1516의 `jam-web/src/app/api/itembooks/route.ts`와 같은 방식).
  - 배지 상세: 소속 컬렉션이 공개 전이면 컬렉션 카드를 그리지 않는다. 배지 자체의 상세 내용은 그대로 둔다.
  - 기간이 끝난 컬렉션은 계속 보인다(1516 결정 E1). 서버 컴포넌트라 테스트가 어려우면 판정 부분을 순수 함수로 빼서 테스트한다.
- 관련 파일: `jam-web/src/app/(main)/badges/page.tsx:120-132`(컬렉션 탭의 `item_books`·소속 배지·슬롯·완성 병렬 조회), `jam-web/src/app/(main)/badges/[id]/page.tsx:228-238`(`badgeRow.item_book_id`로 `item_books` 단건 조회),
  `jam-web/src/lib/itembook/visibility.ts`(공용 판정), `docs/specs/prd/02_DATA_MODEL.md` «컬렉션 노출 판정»

## 완료 조건

- 공개 전 컬렉션은 `/badges` 컬렉션 탭과 배지 상세 컬렉션 카드에 나오지 않는다. 공개된 컬렉션과 기간이 끝난 컬렉션은 그대로 나온다(테스트).
- 두 화면에서 `/collections/[id]`로 가는 링크는 공개된 컬렉션에만 생긴다.
- 머지 뒤 카리나가 로컬에서 비활성 컬렉션 소속 배지를 가진 화면을 읽기만 해서 확인하고 방법을 완료 기록에 적는다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- `/badges` 컬렉션 탭: `item_books` 조회에 `applyLaunchedItemBookFilter`를 걸고, 소속 배지·슬롯·완성 조회는 걸러진 컬렉션 id로만 한다(`/api/itembooks`와 같은 방식, 왕복 1회 증가).
  탭 개수와 `/collections/[id]` 링크는 걸러진 목록에서 나오므로 공개된 컬렉션에만 생긴다.
- 배지 상세: 단건 조회 결과를 새 순수 함수 `pickLaunchedItemBook`(`visibility.ts`, `isItemBookLaunched` 래핑)에 통과시켜 공개 전이면 컬렉션 카드를 그리지 않는다. 배지 상세 내용은 그대로다.
  기간이 끝난 컬렉션은 계속 보인다(E1).
- `02_DATA_MODEL.md` «컬렉션 노출 판정» 표와 `visibility.ts` 머리 주석의 「쓰는 곳」에 두 화면을 더했다.
- 게이트: 민지 1차 PASS(CI 36809575918). 머지 `a821a582`(리뷰 브랜치 `claude/jamwork-20261001_1205-badges-collection-visibility`, 범위 `bd9ebf79..26296ae2`).
  오염 검사는 staging만 앞서 가서 실패했다. 브랜치는 이 티켓 커밋 하나뿐이고, 겹친 파일 `02_DATA_MODEL.md`는 서로 다른 절(254행 대 457~605행)이라 시험 머지에서 충돌이 없어 진행했다.
