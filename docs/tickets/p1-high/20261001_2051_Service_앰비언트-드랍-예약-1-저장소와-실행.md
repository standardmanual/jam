# [Service] 앰비언트 드랍 예약 ① 저장소와 실행(서버)

> 상위: 20260930_1457 · 하위 순서 ① · 선행 없음 · 유형 `db`(마이그레이션 209)

## 핵심 요약

- 요구사항: 날짜(KST 정시)·지점·아이템을 정한 예약을 저장하고, 매시 cron이 도래한 예약을 한 번만 실행한다. 예약 경로는 `ambient_drop_config`에 쓰지 않는다.
  화면 없이 서버 함수 5동작과 cron 처리까지 만든다. 이 조각이 끝나면 1500(자원 연결)이 시작할 수 있다(1500은 HTTP가 아니라 서버 함수를 부른다).
- 구현 계획: 아래 「구현 계획」(파일 단위, 혜린 초안·카리나 확정)을 따른다.
- 관련 파일: 「구현 계획」에 파일·함수·줄 위치가 있다.

## 시작 절차

상위 티켓 20260930_1457의 「주요 의사결정」(사용자 결정 Q1~Q5, 가정 A1~A16)이 이 티켓의 전제다. 혜린 검토는 1457에서 끝났으므로 다시 하지 않는다.
다르게 가야 하면 멈추고 사용자에게 확인한다.
마이그레이션은 작성까지만 하고, 실행은 머지 뒤 사용자 승인을 받아 메인 세션(카리나)이 한다.

**1. 마이그레이션 209** `jam-web/supabase/migrations/209_ambient_drop_schedules.sql`(새 파일).
- `.claude/skills/jam-work/references/db-migration-rules.md`를 먼저 읽는다. 확장 단계 하나(새 테이블 추가뿐, 기존 테이블·RPC·`poi_drops`·`engine_decision_log`는 건드리지
  않는다). 백필 없음.
- 칸: `id uuid` PK 기본 `gen_random_uuid()` · `title text` null(100자 이하) · `scheduled_at timestamptz` NOT NULL, KST 정시 CHECK(`date_trunc('hour',
  scheduled_at AT TIME ZONE 'Asia/Seoul') = scheduled_at AT TIME ZONE 'Asia/Seoul'`) · `status text` NOT NULL 기본 `'scheduled'`, CHECK(`scheduled`·`running`·
  `done`·`skipped`·`failed`·`missed`·`canceled`) · `poi_mode text` NOT NULL CHECK(`list`·`category`) · `poi_ids uuid[]` NOT NULL 기본 `'{}'` · `poi_category text`
  null, FK 없음 · `item_mode text` NOT NULL CHECK(`items`·`collections`) · `badge_ids`·`collection_ids uuid[]` NOT NULL 기본 `'{}'` · `per_poi_count`·`total_count
  integer` null, 1 이상 · `created_by text` null(관리자 이메일) · `created_at`·`updated_at timestamptz` NOT NULL 기본 `now()` · `claimed_at`·`finished_at`·
  `canceled_at timestamptz` null · `result jsonb` null(실행 결과 요약).
- 모드별 CHECK: `list`는 `cardinality(poi_ids) >= 1`, `per_poi_count` 있음, `total_count` 없음, `cardinality(poi_ids) * per_poi_count <= 100`. `category`는
  `poi_ids` 비어 있음, `total_count` 1~100, `per_poi_count` 없음(`poi_category` null은 「전체 종류」). `items`는 `badge_ids` 1개 이상·`collection_ids` 비어 있음,
  `collections`는 반대.
- `poi_category`에 FK를 걸지 않는 이유: `ON DELETE SET NULL`이면 종류가 지워질 때 예약이 「전체」로 넓어진다. 앱이 등록 때 존재를 검증하고, 실행 때 종류가
  없으면 대상 없음으로 건너뛴다.
- 부분 인덱스 `idx_ambient_drop_schedules_due ON (scheduled_at) WHERE status = 'scheduled'`. `ENABLE ROW LEVEL SECURITY`(정책 없음 = service_role만, 207과
  같은 방식). `COMMENT ON TABLE/COLUMN`(티켓 번호, `result` 모양, 칸 이름이 R8 키와 겹치지 않아야 한다는 주의).
- 정시 CHECK는 승인 뒤 실행 전에 DO 블록 + `RAISE EXCEPTION` 롤백으로 스모크한다(카리나).
- 파일 끝 `-- 되돌림 SQL` 블록: 사전 확인 `SELECT count(*) FROM public.ambient_drop_schedules WHERE status IN ('scheduled', 'running');`이 0이 아니면 그 예약을
  먼저 취소한다(테이블을 지우면 놓일 드랍이 놓이지 않는다). 이미 놓인 `poi_drops`는 이 테이블을 가리키지 않아 영향이 없고 실행 이력은 `engine_decision_log`에
  남는다. 코드(cron의 예약 처리)를 먼저 되돌린 뒤 `DROP TABLE IF EXISTS public.ambient_drop_schedules;`.
- **번호는 착수 때 원격 staging 기준으로 다시 확인한다**(2026-10-01 20:49 KST 원격 최신 208, 1503이 210부터 쓴다). 밀리면 파일 이름만 바꾼다.
