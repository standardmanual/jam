# [Admin] 앰비언트 드랍 예약 ② 어드민 예약 관리

> 상위: 20260930_1457 · 하위 순서 ② · 선행: ① 20261001_2051 머지 + 마이그레이션 209 라이브 적용 + 생성 타입 대조 · 유형 `admin`

## 핵심 요약

- 요구사항: `/admin/ambient-drop`에 「날짜 예약」 구역을 더한다. 운영자가 두 지점 모드 × 두 아이템 모드로 예약을 등록하고, 목록에서 상태·결과를 보고, 공개 전에
  취소·시각 수정을 한다. 지점 직접 모드는 등록 전에 「이미 드랍이 있는 지점 N곳(겹쳐서 놓여요)」을 미리 알린다(1457 Q3).
- 구현 계획: 착수할 때 파일 단위로 다시 쓴다. 혜린 초안의 범위: 어드민 API `api/admin/ambient-drop/schedules/`(`route.ts` GET·POST, `[id]/route.ts`
  PATCH·DELETE, `preview/route.ts` POST 미리 알림, 모두 ①의 서버 함수를 부르고 `getAdminUser()` 403), `lib/ambient-drop/schedulePreview.ts`(①의
  `loadScheduleTargets(…, 예정 시각)` 재사용), 화면 `ScheduleSection.tsx`·`ScheduleForm.tsx`(③이 「지금」을 더할 자리를 비워 둔다)·
  `components/admin/PoiMultiSearchSelect.tsx`(지점 다중 선택 칩, `PoiSearchSelect`는 단일 선택이라 새로 만든다)·`lib/ambient-drop/scheduleView.ts`(상태 라벨·
  사유 문장·KST 표기), `page.tsx`·`AmbientDropForm.tsx`(최근 이력 라벨에 「예약」, 안내 문구 162~163행 정정). 아이템은 `MultiBadgeSearchSelect`(`badgeType='item'`),
  컬렉션은 체크박스 목록(공개 전 컬렉션도 「공개 전」 표시로 보이게).
- 관련 파일: 위 경로, 문서 `jam-doc/planning/business-plan/06 JAM! 라이브 운영 플랜.md` §6.1(240행)·439행, BADGE_ENGINE §3.12 어드민 화면 문단.

## 시작 절차

상위 티켓 20260930_1457의 「주요 의사결정」(사용자 결정 Q1~Q5, 가정 A1~A16)이 이 티켓의 전제다. 혜린 검토는 1457에서 끝났으므로 다시 하지 않는다.
다르게 가야 하면 멈추고 사용자에게 확인한다.
어드민 화면이라 채원 판정·MODULAR 적용은 제외다(shadcn 표준). 크기 추정은 약 15개 파일·1,200~1,600줄이라 착수할 때 파일 단위 계획을 적고 면제한다.

## 완료 조건

- 운영자가 어드민에서 두 지점 모드 × 두 아이템 모드로 예약을 등록하고, 목록에서 상태와 결과(놓은 수·건너뜀 사유)를 보고, 공개 전에 취소와 시각 수정을 할 수
  있다(API 테스트 + 로컬 실렌더).
- 지점 직접 모드에서 등록 전에 「이미 드랍이 있는 지점 N곳」이 보이고, 예정 시각에 노출되지 않는 대상은 등록 전에 경고가 보인다(테스트).
- 실행 뒤·실행 중 예약은 취소·시각 수정 버튼이 막히고, 서버도 409로 거절한다(테스트).
- 실행 이력의 「예약」 표시, 한도·비활성 지점 같은 오류 문구가 [현상]→[원인]→[해결책] 해요체다.
- 실렌더는 카리나가 머지 뒤 push 전에 로컬(`ADMIN_EMAILS`)로 한다. 공용 DB라 시험 예약은 **먼 미래 시각으로 등록해 목록 확인 후 바로 취소**하고 실제 드랍 0건을
  확인한다.
- 06 §6.1·439행과 BADGE_ENGINE §3.12가 갱신됐다.
