# [Admin] 앰비언트 드랍 예약 ③ 지금 배포에 지점·아이템 지정

> 상위: 20260930_1457 · 하위 순서 ③ · 선행: ② 20261001_2052 머지(폼이 있어야 한다) · 유형 `admin`

## 핵심 요약

- 요구사항: 1457 Q4대로 새 예약 폼에서 시각 대신 「지금」을 고르면 지정한 지점·아이템으로 1회 배포한다. 매일 배포 설정에는 저장하지 않는다. 기존 「지금 배포」
  버튼(저장된 설정, 본문 없는 POST)은 그대로 둔다.
- 구현 계획: 아래 「구현 계획 (파일 단위)」 표(2026-10-02 착수 때 2052·2154 머지 코드를 읽고 다시 썼다).
- 관련 파일: 위 경로, BADGE_ENGINE §3.12 즉시 배포 문단(1849~1850행)에 「지정 배포」 갈래.

## 시작 절차

상위 티켓 20260930_1457의 「주요 의사결정」(사용자 결정 Q1~Q5, 가정 A1~A16)이 이 티켓의 전제다. 혜린 검토는 1457에서 끝났으므로 다시 하지 않는다.
다르게 가야 하면 멈추고 사용자에게 확인한다.
어드민 화면이라 채원 판정은 제외다. 크기 추정은 5~6개 파일·250~350줄이다.

## 착수 전 확인한 사실 (2026-10-02 계획 탐색)

- 1457 Q4 전제는 그대로다. 파서 `parseAmbientDropScheduleInput`의 `allowNow`(`scheduleSpec.ts` 154~192행)와 `runAmbientDropSpec`(`scheduleRun.ts` 102행, `trigger: 'manual'`, 설정은 읽기만)가 이미 있다.
- `deploy/route.ts`는 본문 없는 POST만 받고 `getAmbientDropConfig`로 상호 배제 창(409)을 검사한 뒤 `runAmbientDropBatch('manual')`을 부른다. 이 라우트 테스트는 아직 없다.
- 미리 확인 `previewAmbientDropSchedule`(`schedulePreview.ts` 61행)은 `allowNow` 없이 파싱해 시각이 없으면 400이다. 「지금」에서도 겹침 안내가 필요하므로 **본문에 `scheduled_at: 'now'`가 명시된 경우에만** 미리 확인이 「지금」을 받는다(시각이 빠진 요청이 조용히 「지금」이 되지 않게). 등록 라우트(`schedules/route.ts`)는 지금처럼 「지금」을 거부한다.
- `ScheduleForm.tsx`는 `when: { kind: 'at', ymd, hour }`만 쓰고, `scheduleView.ts` 211행 주석이 `{ kind: 'now' }` 추가 자리를 예고한다. `handleRegister`(153행)·`canPreview`(130행)가 `ymd`를 요구한다.
- `AmbientDropForm.tsx` 즉시 배포 구역은 371~395행이고 결과는 `formatAmbientBatchSummary`로 보인다. 지정 배포도 `runAmbientDropSpec`이 `logAmbientBatchResult(trigger: 'manual')`를 남기므로 이력에는 `[수동]`으로 뜬다.

## 완료 조건

- 폼에서 「지금」으로 지정한 지점·아이템이 즉시 놓이고 `ambient_drop_config`는 바뀌지 않는다(테스트).
- 본문 없는 기존 POST는 예전과 똑같이 동작하고 상호 배제 창 409도 그대로다(회귀 테스트). 본문이 있는 요청은 창의 영향을 받지 않는다(테스트).
- 입력 검증 실패는 400 해요체 문장이고, 비관리자는 403이며, 예기치 못한 오류는 고정 문장 500이다(테스트).
- 확인 대화상자 없이는 지정 배포가 실행되지 않는다. 실렌더는 즉시 실행이라 되돌릴 수 없으므로 **실렌더 전에 사용자에게 알리고, 지점 1곳·아이템 1개로 시험한 뒤
  놓인 드랍을 기록해 둔다**.
- BADGE_ENGINE §3.12가 갱신됐다.
