# [Admin] 앰비언트 드랍 예약 ②-B 어드민 예약 관리 화면

> 상위: 20260930_1457 · 하위 순서 ②의 조각 B · 선행: 조각 A 20261001_2052(서버·API) 머지 · 유형 `admin`
> 2026-10-01 2052를 둘로 나눴다(2052 「주요 의사결정」). 이 티켓은 화면·문서만 한다. API·순수 함수(`scheduleView.ts`의 라벨·버튼 규칙·결과 문장)는 2052가 만든다.

## 핵심 요약

- 요구사항: `/admin/ambient-drop`에 「날짜 예약」 구역을 더한다. 운영자가 두 지점 모드 × 두 아이템 모드로 예약을 등록하고, 목록에서 상태·결과를 보고, 공개 전에
  취소·시각 수정을 한다. 지점 직접 모드는 등록 전에 「이미 드랍이 있는 지점 N곳(겹쳐서 놓여요)」을 미리 알린다(1457 Q3). 놓침 예약은 시각 수정 버튼이 막힌다(2132).
- 구현 계획: 아래 「구현 계획」 표(파일 단위). 2052의 API와 `scheduleView.ts`를 쓴다. 어드민 shadcn(`W/components/admin/ui/`)만 쓰고 네이티브 select는 쓰지 않는다.
- 관련 파일: 아래 표. 문서 `jam-doc/planning/business-plan/06 JAM! 라이브 운영 플랜.md` 240행·439행, `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md` §3.12 1919~1921행.

## 착수 전 확인한 사실 (2026-10-01 계획 탐색)

- 어드민 shadcn은 `W/components/admin/ui/`(button·input·select·checkbox·tabs·table·badge·dialog·alert-dialog·sonner)다. 라디오가 없어서 모드 전환은 `Tabs`로 한다.
- Select·Dialog·AlertDialog의 Content에는 `container={themeContainer}`가 필요하다(`AmbientDropForm.tsx` 81~83행 패턴).
- 지금 화면은 매일 자동 배포를 「예약 배포」라고 부른다(`AmbientDropForm.tsx` 156·160·168·182·194·211·392행). 이력 라벨 「예약」(`trigger: 'scheduled'`), 새 구역 「날짜 예약」과 겹친다.
- `/api/admin/poi/search`(24행 select)가 `is_active`를 돌려주지 않는다.
- `MultiBadgeSearchSelect`는 `tribes`·`itemBooks` props가 필요하다.
- 클라이언트 컴포넌트는 `scheduleView.ts`·`scheduleSpec.ts`·`kst-format.ts`만 값으로 가져온다(서버 모듈을 값으로 가져오면 next/headers가 클라이언트 번들에 들어가 빌드가 깨진다).
  클라이언트 렌더 안에서 `new Date()`를 부르지 않고 서버가 `nowIso`를 props로 넘긴다(하이드레이션). 표기는 `formatKstYmdHm`(`toLocaleString` 금지).

### 화면 구성

- 구역 순서(AmbientDropForm 안): 배포 트리거 → 메타 → 축 1~3 → 배치 규모 → 저장 → 즉시 배포 → **날짜 예약(slot)** → 최근 실행 이력.
- 배포 트리거 안내(159~164행 대체): 「배포는 세 갈래예요. **예약 배포**는 아래에서 정한 시각에 매일 저절로 배포하고, **즉시 배포**는 「지금 배포」를 누른 그 자리에서
  1회 배포해요. 두 갈래는 저장된 같은 설정값을 써요. **날짜 예약**은 아래 「날짜 예약」에서 날짜·지점·아이템을 정해 한 번만 드랍하고, 이 설정을 바꾸지 않아요.」
- 날짜 예약 구역 안내: 「날짜(한국 시각 정시)·지점·아이템을 정해 두면 그 시각에 한 번 드랍해요. 예약 배포 설정은 쓰지도 바꾸지도 않아요. 드랍한 뒤에는 내리지 않아요.
  실행 전에는 취소하거나 시각을 바꿀 수 있고, 내용을 바꾸려면 취소하고 새로 등록해요.」

**폼(ScheduleForm)**

| 칸 | 컴포넌트 | 규칙 |
|---|---|---|
| 이름(선택) | `Input` maxLength 100 | 비우면 보내지 않는다 |
| 드랍 시각 | `ScheduleWhenField`: `Input type="date"`(min `kstYmd(nowIso)`) + `Select` 0~23시(「09시」) | `{ kind: 'at' }`만. 2053이 「지금」을 더한다 |
| 지점 방식 | `Tabs`: 「지점 직접 선택」 = `PoiMultiSearchSelect` + 지점당 개수(기본 1) / 「지점 종류+개수」 = `Select`(「전체 종류」 + categories) + 총 개수(기본 10) | 고르지 않은 탭의 값은 본문에 넣지 않는다 |
| 놓을 것 | `Tabs`: 「아이템 직접 선택」 = `MultiBadgeSearchSelect badgeType='item'` / 「컬렉션 선택」 = `Checkbox` 목록 | 공개 전이면 Badge 「공개 전 · M/D 공개」, 기간 끝나면 「기간 끝남」 + 누를 수 없음 |
| 합계 줄 | 텍스트 | 「총 N개 · 한 예약 최대 100개」, 넘으면 빨간 글씨 |
| 미리 확인 결과 | `SchedulePreviewNotice` | 직접 선택 + 겹침: 「이미 드랍이 있는 지점 N곳(겹쳐서 놓여요)」 / 종류 모드: 「운영 중인 지점 N곳에 흩어 드랍해요. 한도를 넘는 지점은 건너뛰고, 자리가 모자라면 있는 만큼만 드랍해요.」 / `problem`이면 빨간 경고 / 입력이 바뀌면 흐리게 + 「입력이 바뀌었어요. 다시 확인해 주세요.」 |

| 버튼 | 활성 조건 |
|---|---|
| 확인하기(preview) | 날짜 있음 + (직접: 지점 1곳 이상·지점당 1 이상 / 종류: 총 1 이상) + 아이템이나 컬렉션 1개 이상 + N ≤ 100 + 요청 중 아님 |
| 예약 등록(POST) | 위 조건 + **지금 입력과 같은 본문으로 받은 미리 확인이 있음**(`JSON.stringify(body)` 비교) + `problem` 없음 + 요청 중 아님. 성공하면 toast 「예약을 등록했어요. {시각}에 드랍해요.」, 폼 비우고 목록 재조회 |

- 목록 열: 드랍 시각(KST) · 이름 · 지점(이름 2개 + 「외 N곳」 또는 종류 라벨 × 총 개수) · 놓을 것(이름 2개 + 「외 N개」) · 상태 Badge · 결과 · 동작(시각 수정 / 취소).
- 네트워크 오류: 「네트워크 오류로 {등록·취소·시각 수정}하지 못했어요. 연결을 확인하고 다시 시도해 주세요.」(`RecipeForm` 선례).
- 용어: UX 가이드 §1.3에 따라 새 화면 문구는 「드랍」을 쓴다(「놓기」 금지). ① 서버 문장과 1457 Q3 원문 「겹쳐서 놓여요」는 그대로 둔다.

## 완료 조건

- [ ] 운영자가 어드민에서 두 지점 모드 × 두 아이템 모드로 예약을 등록하고, 목록에서 상태와 결과(드랍 수·건너뜀 사유)를 보고, 공개 전에 취소와 시각 수정을 할 수 있다(렌더 테스트 + 로컬 실렌더).
- [ ] 지점 직접 모드에서 등록 전에 「이미 드랍이 있는 지점 N곳」이 보이고, 예정 시각에 노출되지 않는 대상은 등록 전에 경고가 보인다(테스트).
