# [Infra] Next.js를 16.3.8 이상으로 올려 새로 공개된 high 보안 권고를 해소한다

## 핵심 요약
- 요구사항: `jam-web`의 `next`를 16.3.8 이상으로 올려 `npm audit --omit=dev`의 high 1건을 0건으로 만든다. `/jam-ship` 점검표의 "critical·high 0건" 기준을 다시 충족시킨다.
- 구현 계획: (미정 — 착수 시 작성) `next`와 짝을 맞춰야 하는 패키지(`eslint-config-next` 등, P3 20260923_0101 참고)를 함께 확인하고, `verify.sh`·staging 실렌더로 회귀를 본다.
- 관련 파일: `jam-web/package.json`, `jam-web/package-lock.json` / 참고 티켓: P1 20260922_2321(이전 Next.js 취약점 상향), P3 20260923_0101(`eslint-config-next` 고정)

## 배경 / 문제 정의

### 확인한 사실 (2026-10-08 15:00경 KST, `/jam-ship` 3단계 점검 중)
- `npm audit --omit=dev` 결과 high 1건, 패키지 `next`(현재 16.3.6), 수정 가능 버전 있음(`fixAvailable: true`). 권고 6건이 모두 `<16.3.8` 범위다: `use cache` 채움 중 Draft Mode 내용 유출, 자체 호스팅 SSG·ISR 캐시 오염 2건, 개발 서버 MCP 엔드포인트 정보 노출, App Router 메타데이터 이미지 라우트의 `dynamicParams` 우회, 이미지 최적화 SSRF.
- 2026-10-07 배포 기록(티켓 20260930_1450)에는 `npm audit --omit=dev` 0건이었다. 이번 배포 범위(`origin/main..d7a6fcdfb`)에서 `package.json`·`package-lock.json`은 바뀌지 않았다. 그래서 그 사이에 새로 공개된 권고이고, 지금 프로덕션에도 같은 버전이 올라가 있다.
- `jam-web/src`에서 `use cache`·`draftMode`를 쓰는 파일은 없다.

### 판단
- JAM은 Vercel에서 돌아가므로 자체 호스팅 캐시 오염 2건과 개발 서버 항목은 해당하지 않는다고 본다. 이미지 최적화 SSRF와 메타데이터 이미지 라우트 항목은 해당 여부를 확인하지 않았다. **위험도: 주의, 확신도 보통.**
- 2026-10-08 배포(P0 20261008_1349·1354 포함)는 이 권고 때문에 막지 않았다. 버전이 바뀌지 않아 배포가 위험을 늘리지 않고, P0 수정을 늦추는 쪽이 더 위험하다고 판단해 사용자에게 알리고 진행했다.

## 완료 조건
- (착수 시 구체화) `npm audit --omit=dev` critical·high 0건, `scripts/verify.sh` 통과, staging에서 핵심 화면 정상.
