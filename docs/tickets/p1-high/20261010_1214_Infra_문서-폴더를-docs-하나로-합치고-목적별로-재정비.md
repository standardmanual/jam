# [Infra] 문서 폴더를 docs 하나로 합치고 목적별로 재정비한다

## 핵심 요약

- 요구사항: `docs/`와 `jam-doc/` 두 루트를 `docs/` 하나로 합치고, 첫 단계를 목적별 폴더(service, plan, marketing, operations, tickets, agents, assets, archive)로
  다시 나눈다. 문서의 태그로 주제 지도를 자동 생성해, 어떤 주제든 한 페이지에서 현재·JAM 2.0·보관 문서를 찾게 한다. 티켓의 우선순위 폴더는 그대로 둔다.
- 구현 계획: 이동표대로 `git mv`하는 일회용 이전 스크립트를 쓰고, 그 스크립트로 저장소 전체의 경로 참조(마크다운 상대 링크, 작업 폴더 기준 경로, frontmatter)를
  새 경로로 고친다. 그다음 경로를 하드코딩한 훅·검사 설정·생성 스크립트·스킬·에이전트 정의·CLAUDE.md를 손으로 고치고, 색인 생성기에 주제 지도를 더한다.
- 관련 파일: 아래 「구현 계획」의 파일 단위 목록
- 경로: ③ 표준 (`infra` 유형)
- 사용자 결정(2026-10-10): 루트를 `docs` 하나로 합친다. 첫 단계는 목적별 폴더와 자동 생성 주제 지도다. 티켓은 우선순위 폴더를 최상위로 유지하고,
  필요하면 그 아래를 연도별로 묶는다(지금은 모두 2026년이라 만들지 않는다).

## 배경 / 문제 정의

- 루트가 둘이다. `docs/`(specs 39, tickets 1,745, agents 24)는 코드와 함께 바뀌는 문서, `jam-doc/`(planning 64, marketing 4, operations 20, inbox 1, archive 89, assets)은
  기획·운영 문서라는 기준으로 나뉘어 있다(`jam-doc/README.md`). 이 기준은 문서를 찾는 사람에게 드러나지 않는다.
- 분류 기준이 섞여 있다. 루트 구분, 수명주기(현재 상태·이력·보관), 카테고리 번호(①~⑤), 버전(`jam2-redesign`, `archive/business-plan/v1~v4`, `tribes-history`)이
  동시에 쓰여, 한 주제의 문서가 여러 곳에 흩어진다. 예: 트라이브 문서는 `jam-doc/planning/content/TRIBES.md`, `jam-doc/planning/business-plan/04 JAM! 트라이브.md`,
  `jam-doc/planning/jam2-redesign/tribe-rethink/`, `jam-doc/archive/`에 있다.
- 지금 색인(`docs/specs/INDEX.md`)은 폴더별 목록이라 주제로 찾을 수 없다.

**경로 참조 고치기 범위**

- 고친다: `docs/` 아래 모든 문서(티켓 포함), `CLAUDE.md`, `.claude/agents/`, `.claude/skills/`, `.claude/workflows/`, `.claude/output-styles/`, `.claude/settings*.json`,
  `scripts/`, `.githooks/`, `.github/`, `jam-web/`의 주석과 스크립트.
- 고치지 않는다: `docs/archive/`와 `docs/agents/workflow/`의 본문(읽기 전용·동결 문서), `.claude/worktrees/`, `node_modules/`, `.git/`.
- 마크다운 상대 링크는 문자열 치환이 아니라, 옛 위치에서 링크 대상을 풀어 새 대상으로 바꾼 뒤 새 위치 기준 상대 경로로 다시 계산한다. 원본 파일과 대상 파일이 함께
  움직이는 경우가 많기 때문이다.
- 작업 폴더 기준 경로(백틱 경로, frontmatter `basis`·`related`·`code`·`specs`, 스크립트 문자열)는 이동표의 긴 접두어부터 치환한다.
- 문장 속의 폴더 이름(예: "`docs/specs`는 현재 서비스만 담는다", "jam-doc/ 폴더")도 새 이름으로 고치되, 뜻이 바뀌는 문장은 손으로 다시 쓴다.

**새 입구와 주제 지도**

- `docs/README.md`(손으로 쓰는 문서): 폴더 지도(폴더마다 담는 것과 쓰기 방식), 버전 규칙, `jam-doc/README.md`에 있던 쓰기 규칙과 경로 표기 규칙을 합친다.
  JAM 2.0을 배포할 때 `plan/jam2/`의 결과를 `service/`에 반영하고 밀려난 문서를 `archive/`의 버전 폴더로 옮긴다는 규칙을 적는다.
- `docs/INDEX.md`(`scripts/gen-doc-index.mjs`가 생성): 지금의 폴더별 목록에 더해, 맨 위에 **주제 지도**를 둔다. 주제는 `DOCUMENT_SCHEMA.md` §6.2의 태그 어휘이고,
  주제마다 문서를 `service`(현재), `plan/jam2`(JAM 2.0), `plan/vision`, `marketing`, `operations`, `agents`, `archive`(보관) 묶음으로 나눠 보여 준다. 티켓은 넣지 않는다.
  태그가 없는 문서는 「주제 없음」 묶음에 모은다.

**쓰기 규칙의 대응**

## 구현 계획

1. **이전 스크립트** `scripts/migrate-doc-tree.mjs`(새 파일, 일회용. 이전 뒤에도 기록으로 남긴다)
   - 이동표를 상수로 두고 `git mv`로 옮긴다. 드라이런 모드(`--dry-run`)는 옮길 목록과 고칠 파일 수만 출력한다.
   - 위 「경로 참조 고치기 범위」대로 상대 링크를 다시 계산하고, 작업 폴더 기준 경로를 치환한다. 고친 파일 수와 남은 옛 경로 수를 출력한다.
   - 테스트 `scripts/migrate-doc-tree.test.mjs`: 상대 링크 재계산(원본만 이동, 대상만 이동, 둘 다 이동), 접두어 치환의 긴 것 우선, 제외 경로를 확인한다.
2. **훅** `.githooks/pre-commit`
   - 133~220행 근처의 경로 규칙 ①~⑥: `jam-doc/archive/` → `docs/archive/`, `jam-doc/planning/business-plan/` → `docs/plan/vision/`,
     `jam-doc/planning/content/TRIBES`·`tribes-history/` → `docs/service/content/...`, `jam-doc/inbox/trends/` → `docs/operations/inbox/trends/`,
     옛 경로(`Service Plan/`·`Asset/`)가 다시 생기는 것을 막는 규칙에 `jam-doc/`과 `docs/specs/`를 더한다.
   - 35~42행의 루틴 허용 접두어 `ROUTINE_ALLOWED_PREFIX`: `docs/operations/reports/`.
   - 267행 근처 INDEX 안내 문구의 경로.
3. **검사 설정** `scripts/doc-check.config.json`: `scope.include`·`exclude`, `codeSpanRoots`, `codeSpanIgnore`의 경로를 새 폴더로 바꾼다.
4. **생성 스크립트**
   - `scripts/gen-doc-index.mjs`(+ `gen-doc-index.test.mjs`): 대상 폴더와 출력 경로(`docs/INDEX.md`)를 바꾸고, 주제 지도를 더한다.
   - `scripts/gen-team-doc.mjs`, `scripts/gen-team-map.mjs`(+ 테스트), `scripts/gen-home-feed-doc.mjs`(+ 테스트), `scripts/ticket-dashboard.mjs`, `scripts/verify.sh`,
     `scripts/workspace-setup.sh`, `scripts/ops-patterns-seed.mjs`, `scripts/public-mission-check.mjs`, `scripts/issue-filter-check.mjs`(+ 테스트),
     `scripts/pre-commit-routine-author.test.mjs`: 하드코딩된 경로를 바꾼다. 이 목록은 2026-10-10에 `grep -rlE 'jam-doc/|docs/(specs|tickets|agents)' scripts .githooks`로 뽑았다.
5. **계약 검사** `docs/agents/contract.json`: 경로 주장을 새 경로로 바꾸고, `docs/specs/`와 `jam-doc/`이 없다는 검사 줄을 더한다(CLAUDE.md 절대 규칙 5).
6. **에이전트와 스킬**: `.claude/agents/*.md`(7개), `.claude/skills/**`(20개), `.claude/workflows/jam-work.js` 등. 1번 스크립트가 경로를 치환하고, 폴더 체계를 설명하는
   문장(예: `/jam-docs` 스킬의 카테고리 표, `jam-work` 0.2절 `research` 행)은 손으로 다시 쓴다.
7. **규칙 문서**: `CLAUDE.md`의 「문서 체계 개요」(카테고리 표의 위치, 「폴더 = 수명주기」 표), `docs/DOCUMENT_SCHEMA.md`의 적용 범위와 경로, `docs/README.md` 새로 쓰기,
   `docs/agents/orchestrator.md`·`team-operations.md`의 경로(자동 생성 구간은 생성기로).
8. **생성물 다시 만들기**: `node scripts/gen-doc-index.mjs`, `node scripts/gen-team-doc.mjs`, `node scripts/gen-team-map.mjs`, `node scripts/gen-home-feed-doc.mjs`.
9. **검증**: `node scripts/doc-check.mjs`를 전체 범위로 돌려 새로 깨진 링크가 0인지 확인한다(이전 전부터 깨져 있던 링크 수는 이전 전에 재서 비교한다).
   `scripts/verify.sh`, 위 스크립트들의 테스트, `node scripts/check-contract.mjs`를 통과시킨다. `rg -n 'jam-doc/|docs/specs' --glob '!docs/archive/**' --glob '!docs/agents/workflow/**' --glob '!.claude/worktrees/**'`가
   기록성 문장(이 티켓, 옛 티켓의 이력 서술 등) 말고는 0건인지 확인한다.

- 커밋은 둘로 나눈다. (가) 이전 스크립트와 그 테스트, (나) 이전 실행 결과와 손으로 고친 파일. (나)는 이동이 많아 `JAM_SKIP_DOCLINT=1`이 필요할 수 있다. 쓰면 사유를
  커밋 메시지에 남긴다(선례: 티켓 20260920_1412).
- 규모가 `plan_only` 임계값을 크게 넘지만, 대부분이 스크립트의 기계적 이동·치환이고 파일 단위 계획이 위에 있어 면제한다.
