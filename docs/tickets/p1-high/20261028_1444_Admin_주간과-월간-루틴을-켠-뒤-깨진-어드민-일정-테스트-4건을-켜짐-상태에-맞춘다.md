# [Admin] 주간과 월간 루틴을 켠 뒤 깨진 어드민 일정 테스트 4건을 켜짐 상태에 맞춘다

> 경미 수정(파일 2개, 줄 수 적음, 원인·수정이 1:1로 명확)이라 카리나가 직접 처리했다. 원인은 카리나의 변경(티켓 20260930_1504 7-A3)이다.

## 핵심 요약

- 요구사항: 주간·월간 루틴을 켜면서 바뀐 생성 파일 때문에 실패하는 어드민 테스트 4건을 현재 상태(주간·월간 켜짐, 나머지 꺼짐)에 맞춘다.
- 구현 계획: 테스트의 기대값만 고친다. 코드(`scheduledJobs.generated.ts`, `agentRows.ts`)는 바꾸지 않는다.
- 관련 파일: `jam-web/src/lib/admin/__tests__/scheduled-routines.test.ts`(약 110~152행의 「실제 생성 파일 기준」 묶음), `jam-web/src/app/admin/__tests__/home-sections.test.tsx`(약 292~306행 `BoardSection` 테스트의 「예약 꺼짐」 단언), 원인 파일 `jam-web/src/lib/admin/scheduledJobs.generated.ts`(22·24행의 `enabled: true`), `jam-web/src/lib/admin/opsBoard/agentRows.ts`(`nextRoutineRunLabel`, 46행~).

## 배경 / 문제 정의

- 2026-10-28 14:00 KST에 주간·월간 새 체계 루틴을 켜면서(티켓 20260930_1504 7-A3) 생성기를 다시 돌려 `scheduledJobs.generated.ts`의 주간·월간 `enabled`를 `true`로 바꿨다(커밋 `b294d5f88`).
- 그 변경을 push하기 전에 `jam-web` 테스트를 돌리지 않았다. pre-push 훅은 `jam-web`이 바뀌면 lint만 돌린다. staging의 CI(`verify`, 05:03 UTC)가 test 단계에서 실패했고, 그 뒤 push들은 문서만 바뀌어 test 단계가 건너뛰어져 성공으로 보였다.
- 2026-10-28 마이그레이션 298 파이프라인(티켓 20261028_1425)의 민지 게이트가 CI 실패를 근거로 FAIL을 냈고, 실패 원인이 이 4건임을 확인했다.
- 실패한 테스트: `scheduled-routines.test.ts` 3건(주간이 꺼짐으로 나오기를 기대, 월간 10월 1일이 꺼짐으로 나오기를 기대, 켜진 루틴이 없기를 기대), `home-sections.test.tsx` 1건(주간 루틴이 꺼져 「예약 꺼짐」이 나오기를 기대).

## 상세 요구사항

### 서비스/코드베이스 관점

- `scheduled-routines.test.ts`: 주간은 `enabled: true`, 월간 10월 1일은 `enabled: true`, 켜진 루틴은 `['주간', '월간']`으로 기대한다. 선별·주간 배포 승인·데일리 미팅은 꺼짐 그대로다. 테스트 이름과 맥락 주석도 현재 상태에 맞춘다.
- `home-sections.test.tsx`: 기준 시각 `THURSDAY`(2026-10-01 목) 다음의 주간 루틴은 화요일 09:00이므로 「화 09:00」이 보이는지 확인한다.

## 구현 계획

위 두 파일의 기대값 4곳과 맥락 주석 1곳을 고친다(약 12줄).
