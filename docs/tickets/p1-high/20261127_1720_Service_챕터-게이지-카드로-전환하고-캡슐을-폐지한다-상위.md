# [Service] 챕터 게이지 카드로 전환하고 캡슐을 폐지한다 (상위)

## 핵심 요약

- 요구사항: 홈과 내 프로필의 캡슐 게이지를 «챕터 게이지 카드»로 바꾸고, 챕터를 «이번 챕터에서 모은 잼 / 이번 챕터 필요 잼»으로 올린다. 캡슐 개념을 코드·화면·문서·어드민에서 제거한다. 잼은 챕터를 올리는 경험치이고, 포인트는 별도 재화로 둔다.
- 구현 계획: 준비(A), DB 확장(B), 전환(C)을 오픈 전에 하고, 제거(D)는 안정화 기간 뒤에 별도 배포로 한다. 하위 티켓은 아래 표의 「선행」 열 순서로 `/jam-work`에 태운다.
- 관련 파일: 하위 티켓 각자의 「관련 파일」. 확정 시안은 Claude 디자인 캔버스 https://claude.ai/artifact/2UzUpS1Na3QnbBkifPzEhp 이다.
- 기획 경위: 혜린(`jam-pm`) 1단계 문답(2026-11-27, 질문 5건)과 2단계 기획서를 사용자가 승인했다. 경제 수치는 시뮬레이션 전이라 «미검증»이다.

## 배경 / 문제 정의

챕터가 «잼 → 캡슐 채움 → 캡슐이 가득 찬 횟수 → 챕터»의 간접 구조로 오른다. 화면의 게이지는 캡슐 모양에 묶여 있고, 홈에는 챕터가 보이지 않는다. 유저는 잼과 챕터의 관계를 화면에서 읽을 수 없다.

확인한 사실(출처)
- 챕터는 지금 `capsule_chapter_costs.advance_count`(챕터 1~9에서 6, 7, 7, 8, 9, 9, 10, 11, 12회)와 `user_chapters.capsule_full_count`로 오른다. 점수 함수 `chapter_add_score`와 점수 표는 마이그레이션 305에서 삭제했다(마이그레이션 300, 301, 305, 운영 로직 12.2절).
- 가입 즉시 챕터 1을 받는다. 온보딩 퀘스트는 2026-11-15에 없앴다(운영 로직 2.2절).
- 서비스 활동 잼은 종류별 값과 하루 40, 한 주 100 상한이 있고, 받는 즉시 캡슐을 채운다(운영 로직 4.2·4.4절).
- `jam_wallets.total_earned`는 활동 정산만 센다(`220_jam_ledger.sql` 10행). 서비스 활동 잼은 별도라서 «이번 챕터에서 모은 잼»은 새로 적립해야 한다.
- 현재 위젯은 이미 «채운 양» 숫자를 게이지에 보인다(`home-feed/PRD.md` 63행). 운영 로직 5.3절은 «진행 숫자가 없다»고 적어 문서끼리 어긋나 있다.
- 오늘 큐레이션 노출 태그 4개(`capsule_full`, `capsule_nearly_full`, `jam_plenty`, `jam_low`)가 캡슐 필요량과 지갑 잔액에 묶여 있다(`lib/today/exposure.ts`).
- 시뮬레이터 `scripts/balance-sim/chapter-capsule-sim.mjs`와 `collection-sim.mjs`가 모두 캡슐을 모델에 넣고 있다.
- 오픈 전 공용 DB의 유저는 8명이었다(2026-10-25 읽기, `12 JAM 2.0 오픈 전후 적용 순서.md` 2절). 현재 수는 미확인이다(카즈하).

## 가정

확인됨
- 챕터는 `capsule_full_count`와 `advance_count`로 오른다. 점수 함수·표는 삭제됐다(마이그레이션 300, 301, 305).
- 알림 enum 값은 지우지 않기로 한 상태다(`policiesData.ts` `ch5-capsule-alerts`).
- 필요량 표는 `fill_amount_v2 × advance_count`의 산술이다.

미확인
- 현재 프로덕션의 유저 수, 챕터별 진행 분포, 대기 보상 보유자 수(카즈하)
- 프로덕션(main) 코드가 새 열·함수와 호환되는지
- 챕터 보상 값과 아이템 유입 영향(시뮬레이션 전). 설계값으로 계산한 캡슐 비중(아이템 배지의 약 40%, Epic의 약 60%, Mystic의 약 70%)은 산술이며 실측이 아니다
- 약관이 게시 중인지 초안인지(`TERMS_OF_SERVICE.md` 284·297행에 미정 항목)
- `capsule_open_count` 조건 미션·J8-1 배지 보유자 수, 오늘 큐레이션 카드 행이 4개 태그를 쓰는지
- 확률 공시 의무의 적용 범위(법무)

## 검토한 대안

- 누적 게이지(B안): 챕터 후반에 늘 거의 찬 상태라 모션이 의미를 잃어 기각했다.
- 점수 체계 복원: 이미 폐지됐고 확정 결정과 충돌해 기각했다.
- 전환과 제거를 한 번에: 기록·원장 때문에 되돌리기 어려워 기각했다(Q5).
- 캡슐 UI만 교체하고 로직 유지: 사용자가 캡슐 제거를 확정해 기각했다.
- 잼포인트로 잼과 포인트를 합치는 안: 사용자가 철회했다(2026-11-27).
