# [Service] A1 약관 개정안과 공지 일정을 확정한다

## 핵심 요약

- 요구사항: 캡슐 폐지와 챕터 게이지 전환에 맞춰 약관 개정 조항안을 쓰고, 공지 일정(적용일, 7일 또는 30일 전)을 사용자와 확정한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `docs/service/legal/TERMS_OF_SERVICE.md`(정의·확률·이용 정지·탈퇴 조항)
- 선행 티켓: 없음
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 A(결정과 준비)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `docs/service/legal/TERMS_OF_SERVICE.md`의 8곳을 읽어 개정안을 쓴다: 정의 제1조 ③·⑤(잼은 «캡슐을 채우는 데 쓰는 수치»), 아이템 배지 획득 경로, 99·109행 확률 조항, 176·179행 이용 정지, 199행 탈퇴.
2. 공지 기간 판단에 필요한 사실을 정리한다: 약관이 게시 중인지 초안인지(284·297행에 미정 항목), 이 변경이 회원에게 불리한지, 54행의 공지 규정(적용일 7일 전, 불리하면 30일 전).
3. 법무 확인 항목 목록을 만든다: 확률 공시 의무의 적용 범위, 공지 기간.
4. 공지 일정을 사용자에게 보고하고 확정받는다(질문 Q-g).

## 완료 조건

- 약관 개정 조항안이 문서에 반영돼 있고, 각 조항이 어떤 변경에서 나왔는지 적혀 있다.
- 공지 일정(적용일, 공지 게시일, 7일 또는 30일)을 사용자가 확정했고 티켓에 기록돼 있다.
- 법무 확인이 필요한 항목이 목록으로 남아 있다.

## 규모와 체크포인트

- 규모: 파일 1~2개, 약 60줄(추정, 미검증)
- 체크포인트: 공지 게시는 외부 발행에 해당하므로 게시 전에 사용자 승인을 받는다. 이 티켓은 일정 확정까지만 한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 경로: `/jam-work` docs 유형(서브에이전트 없이 카리나 직접). 면제 대상이 아니다(파일 1개, 약 30줄 변경).
- 공지 일정 판단(2026-11-27): 이용약관은 게시 전 초안이고 시행일이 비어 있어 이번 수정은 «개정 공지(7일, 불리하면 30일 전)» 대상이 아니다. 이 기간은 약관을 게시한 뒤 고칠 때부터 적용된다.
  사용자에게 «약관 확정은 전환과 분리 / 전환 배포일에 맞춰 게시 / 30일 전 공지 전제» 중 하나를 물었고, 사용자는 선택지 대신 «바로 고쳐»라고 답했다. 이를 «초안 개정을 지금 반영하고 공지 일정은 약관 게시 때 따로 정한다(권장안, 분리)»로 해석했다. 해석이 다르면 사용자가 알려 준다.
- 이미 게시한 «확률 안내» 화면의 변경은 약관과 별개다. 제7조 ③(바뀐 날짜와 내용을 적는다)과 운영 로직 18.3(바꾸기 전에 공지한다)은 C8(20261127_1738)에서 다룬다.
- 약관 게시 시점·시행일·법무 확인은 이 티켓이 아니라 약관 확정 때 사용자가 정한다(TERMS 내부 메모 A-1, A-10).
