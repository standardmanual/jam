# [Service] A2 정책 정본을 개정한다: 용어와 챕터

## 핵심 요약

- 요구사항: 정책 정본 문서에서 캡슐 정의를 걷고, 챕터가 필요 잼 도달로 오른다는 규칙과 숫자 노출 결정을 기록한다. 대체되는 기존 결정은 상위 티켓의 표대로 남긴다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(6단계).
- 관련 파일: `docs/plan/jam2/service-redesign/01 공통 용어.md`(34·35·51~65·81행) / `docs/plan/jam2/service-redesign/05 캡슐.md`(전체) / `docs/plan/jam2/service-redesign/17 챕터.md`(3·4·6절) / `docs/plan/jam2/service-redesign/04 트라이브, 출신, 레벨.md`(3·4절), `README.md`
- 선행 티켓: 20261127_1721(A1)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 A(결정과 준비)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `docs/plan/jam2/service-redesign/01 공통 용어.md`: 34·35행(캡슐·채우다 정의), 51~65행(동사 규칙), 81행(잼 이름의 근거)을 개정한다. 잼은 챕터를 올리는 경험치로 다시 정의한다.
2. `05 캡슐.md`: 폐지 문서로 바꾸고 «대체됨» 표시와 연결 문서를 남긴다(파일은 삭제하지 않는다).
3. `17 챕터.md` 3·4·6절: 챕터가 필요 잼 도달로 오른다, 챕터별 필요 잼 표, 홈과 프로필의 카드, 숫자 노출을 기록한다.
4. `04 트라이브, 출신, 레벨.md` 3·4절과 `README.md`를 맞춘다.
5. 상위 티켓의 «대체되는 기존 결정» 표를 문서에 반영한다(결정 날짜 2026-11-27 명시).
6. 윈터 검수를 받는다: «캡슐» 용어 제거, 잼의 새 정의, 챕터의 서사 의미.

## 완료 조건

- 공통 용어 문서에서 캡슐이 기능 용어로 남아 있지 않고, 잼의 정의가 «챕터를 올리는 경험치»다.
- 챕터 문서에 챕터별 필요 잼 표(870~3,960)와 카드 노출 규칙이 있고, 대체된 기존 결정이 날짜와 함께 기록돼 있다.
- 윈터 검수 결과(통과 또는 수정 사항)가 티켓에 남아 있다.
- 문서 검사(`scripts/doc-check.mjs`)와 `scripts/check-contract.mjs`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 5개, 약 250줄(추정, 미검증)
- 체크포인트: 윈터 검수가 정지 조건이다. 검수 결과를 사용자에게 보고한 뒤 이후 티켓으로 넘어간다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
