# [Infra] B1 DB 확장: 챕터별 필요 잼과 이번 챕터 진행값 열을 더한다

## 핵심 요약

- 요구사항: `chapter_definitions`에 필요 잼 열(챕터 10은 NULL)과 시드 값을, `user_chapters`에 이번 챕터 진행값 열을 더한다. 옛 열은 그대로 두어 지금 모양이 계속 동작한다(확장→전환→축소 중 확장).
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/supabase/migrations/36x_chapter_jam_expand.sql`(+ `_down.sql`) / `jam-web/src/types/database.generated.ts`
- 선행 티켓: 20261127_1722(A2)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 B(DB 확장, 비가시)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 새 마이그레이션 `jam-web/supabase/migrations/36x_chapter_jam_expand.sql`과 `_down.sql`: 열 추가와 시드(870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960, 챕터 10 NULL).
2. 되돌림 SQL: 추가한 열을 DROP한다. 데이터를 바꾸지 않는다.
3. `jam-web/src/types/database.generated.ts`: Supabase MCP `generate_typescript_types`로 재생성해 같은 커밋에 넣는다.
4. 실행 전 점검: 되돌림 SQL 확인, 드라이런, 프로덕션(main) 코드와의 호환 확인(카즈하). 실행은 메인 세션(카리나)만 한다.

## 완료 조건

- 새 열이 추가돼 있고 챕터 1~9의 필요 잼이 상위 티켓 표와 같으며, 챕터 10은 NULL이다.
- 옛 열과 함수가 바뀌지 않았고, 기존 시험이 모두 통과한다.
- 되돌림 SQL을 실측으로 확인했고 생성 타입이 새 열을 포함한다.

## 규모와 체크포인트

- 규모: 파일 3개, 약 110줄(추정, 미검증)
- 체크포인트: db 유형은 SQL 파일 작성까지만 서브에이전트가 한다. 실행은 카리나가 드라이런·되돌림 확인 뒤 한다.
