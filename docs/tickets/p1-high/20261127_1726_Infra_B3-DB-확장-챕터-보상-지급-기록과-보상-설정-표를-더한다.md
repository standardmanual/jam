# [Infra] B3 DB 확장: 챕터 보상 지급 기록과 보상 설정 표를 더한다

## 핵심 요약

- 요구사항: (유저, 챕터)마다 1회 지급을 기록하는 표와, 어드민에서 개수·확률을 바꿀 수 있는 보상 설정 표를 만든다. 값은 A3 결과로 확정된 Q-b와 Q-c를 따른다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/supabase/migrations/36x_chapter_reward.sql`(+ `_down.sql`) / `jam-web/src/types/database.generated.ts`
- 선행 티켓: 20261127_1723(A3), 20261127_1724(B1)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 B(DB 확장, 비가시)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 새 마이그레이션 `36x_chapter_reward.sql`과 `_down.sql`: 지급 기록 표(유저·챕터 고유), 보상 설정 표, 대기 보상 처리는 Q-c 결정대로.
2. `jam-web/src/types/database.generated.ts` 재생성.
3. 되돌림 SQL: 표 DROP(운영 데이터가 생긴 뒤에는 백업 후).

## 완료 조건

- 지급 기록 표가 (유저, 챕터) 고유 제약을 갖고, 같은 키로 두 번 넣으면 한 번만 기록된다.
- 보상 설정 표에 A3 확정 값이 시드로 들어 있다.
- 되돌림 SQL을 확인했고 생성 타입이 새 표를 포함한다.

## 규모와 체크포인트

- 규모: 파일 3개, 약 150줄(추정, 미검증)
- 체크포인트: A3와 사용자의 Q-b, Q-c 확정이 선행이다. db 유형 단독 호출, 실행은 카리나.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
