# [BadgeEngine] B4 진행값 적립 호출을 이중 쓰기로 붙인다

## 핵심 요약

- 요구사항: 활동 정산과 서비스 활동 잼 지급 때 새 함수로도 진행값을 쌓는다(승급은 아직 옛 방식). 같은 일은 한 번만 쌓이고, 두 값이 어긋나면 로그에 남긴다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(5단계).
- 관련 파일: `jam-web/src/lib/chapter/applyJam.ts`(신규)와 시험 / `jam-web/src/lib/jam/settlement.ts`, `jam-web/src/lib/jam/serviceActivity.ts`(145~146행 근처)와 시험
- 선행 티켓: 20261127_1725(B2)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 B(DB 확장, 비가시)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 새 `jam-web/src/lib/chapter/applyJam.ts`: B2 함수를 호출하는 얇은 래퍼와 시험.
2. `jam-web/src/lib/jam/settlement.ts`: 활동 정산 뒤 `applyJam` 호출을 더한다.
3. `jam-web/src/lib/jam/serviceActivity.ts`(145~146행 근처): 서비스 활동 잼 지급 뒤 호출을 더한다.
4. 옛 진행(캡슐 채움)과 새 진행값이 어긋나면 `engine_decision_log`에 남긴다.
5. 시험: 두 호출부의 멱등, 하루 40·한 주 100 상한 경계, 실패 시 옛 흐름이 막히지 않음.

## 완료 조건

- 활동 정산과 서비스 활동 잼 지급 뒤 새 진행값이 쌓이고, 같은 일을 다시 처리해도 한 번만 쌓인다.
- 옛 캡슐 진행과 새 진행값이 어긋나면 `engine_decision_log`에 남는다.
- 새 호출이 실패해도 옛 흐름(캡슐 채움)이 그대로 동작한다. `scripts/verify.sh`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 6개, 약 220줄(추정, 미검증)
- 체크포인트: engine 유형 단독 호출. 공용 DB라서 프로덕션(main) 코드가 새 함수 없이도 동작하는지 확인한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
