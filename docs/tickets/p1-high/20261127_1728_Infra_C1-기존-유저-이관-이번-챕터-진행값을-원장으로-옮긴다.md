# [Infra] C1 기존 유저 이관: 이번 챕터 진행값을 원장으로 옮긴다

## 핵심 요약

- 요구사항: 유저별 이번 챕터 진행값을 (현재 챕터 도달 이후 `capsule_fill` 합계 + 지갑 잔액)으로 채운다. 챕터는 내려가지 않고, 대기 보상·아이템·기록 표는 그대로다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/supabase/seed_2026xxxx_chapter_jam_backfill.sql`(+ 되돌림, 백업 표)
- 선행 티켓: 20261127_1724(B1), 20261127_1725(B2), 20261127_1726(B3), 20261127_1727(B4)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 새 `jam-web/supabase/seed_2026xxxx_chapter_jam_backfill.sql`과 되돌림 SQL, 백업 표.
2. 청크로 나눠 실행한다(`db-migration-rules.md` 2절). 진행값이 필요량을 넘는 유저의 승급 규칙은 Q-h 결정대로(보상은 단계마다 (유저, 챕터)당 1회).
3. 실행 전 점검: 백업 표, 드라이런, 롤백 실측, 이전·이후 유저별 대조표. 카즈하가 현재 유저 수와 분포를 확인한다.

## 완료 조건

- 이관 전후 유저별 대조표에서 챕터 하향 0명, 이번 챕터 진행값 일치율 100%다.
- `capsule_opens`, `capsule_unseen_results`, `capsule_pending_rewards` 행 수 변화가 0이고 대기 보상·받은 아이템이 그대로다.
- 되돌림 SQL을 실측으로 확인했고 사용자에게 보고했다.

## 규모와 체크포인트

- 규모: 파일 2~3개, 약 150줄(추정, 미검증)
- 체크포인트: 데이터를 바꾸므로 카즈하의 현재 유저 수와 대조표를 사용자에게 보고한 뒤, main 승격 직전에 실행한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
