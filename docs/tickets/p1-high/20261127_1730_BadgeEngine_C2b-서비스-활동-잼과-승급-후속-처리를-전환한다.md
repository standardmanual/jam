# [BadgeEngine] C2b 서비스 활동 잼과 승급 후속 처리를 전환한다

## 핵심 요약

- 요구사항: 서비스 활동 잼의 즉시 채움을 새 진행값 적립으로 바꾸고, 승급 후속 처리(소식, 챕터 배지 판정)를 이어서 부른다. 챕터 오름 소식은 유지한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/src/lib/jam/serviceActivity.ts` / `jam-web/src/lib/chapter/rise.ts`, `jam-web/src/lib/chapter/badgeReceive.ts`와 시험
- 선행 티켓: 20261127_1729(C2a)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/lib/jam/serviceActivity.ts`: 즉시 채움 호출을 새 적립·승급으로 바꾼다.
2. `jam-web/src/lib/chapter/rise.ts`의 `processChapterRise`와 `lib/chapter/badgeReceive.ts`를 새 승급 결과에 맞게 이어 부른다.
3. 시험을 새 흐름에 맞게 고친다.

## 완료 조건

- 서비스 활동 잼이 새 진행값에 쌓이고, 승급하면 챕터 오름 소식과 챕터 배지 판정이 한 번만 실행된다.
- 이용 정지 중에는 진행값이 쌓이지 않는다.
- `scripts/verify.sh`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 5개, 약 180줄(추정, 미검증)
- 체크포인트: engine 유형 단독 호출.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
