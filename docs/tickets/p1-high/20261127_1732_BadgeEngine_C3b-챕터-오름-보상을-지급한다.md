# [BadgeEngine] C3b 챕터 오름 보상을 지급한다

## 핵심 요약

- 요구사항: 챕터가 오른 직후 (유저, 챕터)당 1회 보상을 지급한다. 활동 피드에서는 제외하고, 인벤토리 빈칸이 모자라면 Q-c 결정대로 처리하며, 이용 정지 중에는 막는다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/src/lib/chapter/reward/*`, `jam-web/src/lib/chapter/rise.ts` / `jam-web/src/lib/capsule/settle-pending.ts`와 시험 2~3개
- 선행 티켓: 20261127_1731(C3a)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/lib/chapter/reward/*`: 지급 함수와 지급 기록(B3 표) 기록.
2. `jam-web/src/lib/chapter/rise.ts`: 승급 직후 지급을 호출한다.
3. `jam-web/src/lib/capsule/settle-pending.ts`: 옛 대기 보상 지급은 유지한다(비워질 때까지).
4. 챕터 배지와 챕터 오름 아이템 배지의 이름 겹침은 윈터 검수 결과(Q-d)대로 문구를 고른다.

## 완료 조건

- 승급하면 (유저, 챕터)당 1회만 지급되고, 같은 승급을 다시 처리해도 중복 지급이 없다.
- 인벤토리 빈칸이 모자랄 때 Q-c 결정대로 동작하고, 이용 정지 중에는 지급되지 않는다.
- 지급된 아이템 배지가 활동 피드에 올라가지 않는다. `scripts/verify.sh` 통과.

## 규모와 체크포인트

- 규모: 파일 5개, 약 250줄(추정, 미검증)
- 체크포인트: engine 유형 단독 호출. 윈터 검수(Q-d) 결과를 받은 뒤 문구를 쓴다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
