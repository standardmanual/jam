# [API] C5a 챕터 게이지 읽기 모델을 새 진행값으로 바꾼다

## 핵심 요약

- 요구사항: `getMyChapter`가 챕터 번호, 이번 챕터 모은 잼, 필요 잼, 트라이브 이름, 마지막 챕터 여부를 돌려준다. 타인용 읽기에는 진행값이 없다는 시험이 유지된다. 점수(`total_score`)는 더 읽지 않는다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/src/lib/chapter/read.ts`(`getMyChapter`, `getMyTribeName`) / `jam-web/src/lib/chapter/progress.ts`와 시험
- 선행 티켓: 20261127_1728(C1)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/lib/chapter/read.ts`: `getMyChapter`, `getMyTribeName`을 새 열 기준으로 바꾼다. 점수로 비율을 계산하던 부분을 걷는다.
2. `jam-web/src/lib/chapter/progress.ts`: 구간 진행(모은 잼, 필요 잼, 마지막 챕터)을 계산한다.
3. 시험: 응답 키 목록 고정, 타인용 응답에 진행값이 없음.

## 완료 조건

- `getMyChapter`가 챕터 번호, 모은 잼, 필요 잼, 트라이브 이름, 마지막 챕터 여부를 돌려주고, 점수 열을 읽지 않는다.
- `getPublicChapter`의 응답에 진행값이 없다는 시험이 통과한다.
- 챕터 10(마지막)에서 필요 잼이 없을 때의 값이 Q-e 결정대로 돌아온다.

## 규모와 체크포인트

- 규모: 파일 4개, 약 150줄(추정, 미검증)
- 체크포인트: api 유형. Q-e(챕터 10 표시)를 채원 판정에서 받은 뒤 마지막 챕터 값을 확정한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
