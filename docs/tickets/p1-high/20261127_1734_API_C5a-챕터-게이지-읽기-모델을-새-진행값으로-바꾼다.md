# [API] C5a 챕터 게이지 읽기 모델을 새 진행값으로 바꾼다

## 핵심 요약

- 요구사항: `getMyChapter`가 챕터 번호, 이번 챕터 모은 잼, 필요 잼, 트라이브 이름, 마지막 챕터 여부를 돌려준다. 타인용 읽기에는 진행값이 없다는 시험이 유지된다. 점수(`total_score`)는 더 읽지 않는다.
- 구현 계획: `getMyChapter`가 `user_chapters.chapter_jam`과 `chapter_definitions.required_jam`으로 진행을 계산하고(점수 열은 더 읽지 않는다) `chapterJam`·`requiredJam`·`isLastChapter`·`tribeName`을 더해 돌려준다. 기존 키(`chapterNo`, `nextChapterNo`, `progress`)는 유지해 프로필 화면이 그대로 동작하게 한다. 타인용 `getPublicChapter`는 바꾸지 않고 시험으로 고정한다. DB 변경은 없다.
- 관련 파일: `jam-web/src/lib/chapter/read.ts`(`getMyChapter` 약 144~165행, `readUserChapter` 약 92~110행, `readDefinitions` 약 113~128행, `MyChapterResult` 약 43~56행, `getMyTribeName`, `getPublicChapter`), `jam-web/src/lib/chapter/progress.ts`(`computeChapterProgress`, `ChapterDefinitionRow`) / 호출처 `jam-web/src/app/(main)/[username]/page.tsx`(약 81~120행, 응답의 `chapterNo`만 쓴다) / 시험 `jam-web/src/lib/chapter/__tests__/read.test.ts`, `progress.test.ts`, `jam-web/src/app/(main)/[username]/__tests__/page.test.tsx`(`MY_CHAPTER` 고정값 약 230행과 `getMyChapterMock` 약 553·579·588행)
- 선행 티켓: 20261127_1728(C1)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

### 설계 결정 (카리나, 2026-11-27)

- **새 응답 계약(내 챕터)**: `MyChapterResult`의 성공 응답은 `{ ok: true, chapterNo, chapterJam, requiredJam, nextChapterNo, isLastChapter, progress, tribeName }`이다. 챕터가 없는 유저(행 없음·`chapter_no` NULL, 퀘스트 전)는 `chapterNo`·`chapterJam`·`requiredJam`·`nextChapterNo`·`progress`·`tribeName`이 모두 `null`이고 `isLastChapter`는 `false`다. 읽지 못하면 지금처럼 던지지 않고 `{ ok: false }`다.
- **필드 뜻**: `chapterJam`은 이번 챕터에서 모은 잼(`user_chapters.chapter_jam`, 0 이상의 정수). `requiredJam`은 지금 챕터를 마치는 데 필요한 잼(`chapter_definitions.required_jam`)이고 마지막 챕터(`required_jam`이 NULL)면 `null`이다. `isLastChapter`는 더 오를 수 없는 챕터다: 지금 챕터보다 큰 챕터가 없거나 `required_jam`이 NULL이면 `true`(승급 함수 `chapter_jam_apply`가 같은 조건으로 승급하지 않는다). `nextChapterNo`는 지금보다 큰 정의 가운데 가장 작은 번호이고 `isLastChapter`면 `null`이다. `progress`는 `chapterJam / requiredJam`을 0 이상 1 이하로 자르고 소수 둘째 자리까지 **내린** 값이다(0.9992는 0.99, 다 찼다고 보이면 안 된다). 마지막 챕터면 `null`이다. 필요량이 0 이하인 비정상 정의는 게이지가 찬 것(1)으로 본다(0으로 나누지 않는다). `tribeName`은 지금 소속 트라이브 이름이고 소속이 없거나 읽지 못하면 `null`이다(트라이브를 못 읽어도 챕터 응답은 `ok: true`로 만든다, 읽기 실패는 `console.error`로 남긴다).
- **마지막 챕터의 표시**(Q-e)는 이 티켓이 정하지 않는다. 사실값(`requiredJam: null`, `isLastChapter: true`, `progress: null`, `chapterJam`은 쌓인 값)만 돌려주고 화면 표현(«마지막», «MAX» 금지 등)은 C5b에서 채원 판정으로 정한다.
- **점수 열을 더 읽지 않는다**: `getMyChapter`는 `total_score`와 `chapter_definitions.required_score`를 읽지 않는다. `user_chapters`에서 `chapter_no, chapter_jam`, `chapter_definitions`에서 `chapter_no, required_jam`, 트라이브는 기존 `readTribe`를 쓴다. 세 조회는 독립이라 `Promise.all`로 읽고(챕터 번호가 NULL이면 정의는 버린다) 하나라도 실패하면(트라이브 제외) 전체를 읽지 못함으로 돌려준다.
- **타인용(`getPublicChapter`)은 바꾸지 않는다**: `{ ok, tribe, chapterNo }`만 돌려주고 `chapter_jam`·`required_jam`·`total_score`를 읽지도 않는다. 시험으로 고정한다(조회 인자에 이 열 이름이 없음, 응답 키 목록).
- **호환**: `getMyTribeName`(프로필 화면이 쓴다)은 그대로 둔다(C6에서 카드로 바꿀 때 걷는다). 프로필 서버 화면은 `chapterNo`만 쓰므로 바꾸지 않는다. 기존 키 `chapterNo`·`nextChapterNo`·`progress`의 이름과 뜻을 유지한다.
- 점수 열 자체와 `required_score`는 DB에 남는다(제거는 D단계).

### 파일별

1. `jam-web/src/lib/chapter/progress.ts`: `ChapterDefinitionRow`를 `{ chapterNo: number; requiredJam: number | null }`로 바꾸고 `computeChapterProgress(chapterJam, chapterNo, definitions)`가 `{ nextChapterNo, requiredJam, progress, isLastChapter }`를 돌려주게 한다. 정의에 지금 챕터가 없으면 `null`(호출부는 읽지 못함으로 다룬다). 순수 함수를 유지한다. 머리 설명을 «필요 잼과 이번 챕터 진행값 기준»으로 다시 쓴다.
2. `jam-web/src/lib/chapter/read.ts`: `readUserChapter`는 `chapter_no, chapter_jam`만 읽는다(`includeScore` 인자 제거, 타인용은 `chapter_no`만). `chapter_jam`은 0 이상의 안전한 정수가 아니면 읽지 못함이다. `readDefinitions`는 `chapter_no, required_jam`을 읽고 `required_jam`이 NULL 또는 1 이상의 정수가 아니면 읽지 못함으로 한다. `getMyChapter`가 위 계약으로 `Promise.all` 읽기와 계산을 한다. 머리 설명(응답 키 목록, 점수 비노출)을 새 계약으로 고친다.
3. 호출처: `jam-web/src/app/(main)/[username]/page.tsx`는 변경 없음(타입이 맞으면). 컴파일에 영향이 있으면 최소로 고친다.

### 시험
- `progress.test.ts`: 새 입력(`requiredJam`)으로 다시 쓴다. 비율 0·0.5·0.99(다 찬 것으로 보이지 않음)·1, 소수 오차(0.29가 0.28로 내려가지 않음), 마지막 챕터(다음 정의 없음, `required_jam` NULL)에서 `requiredJam: null`·`isLastChapter: true`·`progress: null`, 필요량 0 이하 비정상 정의는 1, 정의에 지금 챕터가 없으면 `null`, 챕터 번호가 연속이 아니어도 «다음»이 맞음.
- `read.test.ts`: `getMyChapter`가 새 키 목록 `['chapterJam','chapterNo','isLastChapter','nextChapterNo','ok','progress','requiredJam','tribeName']`만 돌려줌, 챕터 없는 유저의 값, 챕터 10(마지막), `chapter_jam`·`required_jam` 이상값은 읽지 못함, 트라이브 읽기 실패는 `tribeName: null`로 `ok: true`, 조회 오류·예외는 `{ ok: false }`, **조회가 `total_score`·`required_score`를 요구하지 않음**(조회 인자 검사). `getPublicChapter`는 응답 키 `['chapterNo','ok','tribe']`와 `chapter_jam`·`required_jam`·`total_score`를 읽지 않음(조회 인자에 열 이름이 없음).
- `page.test.tsx`: `MY_CHAPTER`와 `getMyChapterMock` 고정값을 새 계약 모양으로 고치고, 다른 유저 프로필의 비밀값 검사(`progress`, `nextChapterNo`, `score`, `total_score`)에 `chapterJam`, `requiredJam`, `isLastChapter`를 더한다.
- `scripts/verify.sh`가 통과해야 한다.

## 완료 조건

- `getMyChapter`가 `{ ok, chapterNo, chapterJam, requiredJam, nextChapterNo, isLastChapter, progress, tribeName }`를 돌려주고, `user_chapters.chapter_jam`과 `chapter_definitions.required_jam`으로 계산하며 `total_score`·`required_score`를 읽지 않는다. 응답 키 목록을 시험이 고정한다.
