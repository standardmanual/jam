# [BadgeEngine] C8 확률 안내 페이지를 챕터 보상 기준으로 바꾼다

## 핵심 요약

- 요구사항: 확률 안내 페이지에서 «캡슐» 구역을 걷고, 챕터 보상에 확률이 있으면 그 표를 보인다. 변경 이력에 바뀐 날짜를 남긴다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/src/app/(legal)/probability/page.tsx`, `jam-web/src/lib/probability/disclosure.ts`, `changeLog.ts` / 시험 3개, `docs/service/prd/probability/PRD.md`
- 선행 티켓: 20261127_1731(C3a)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/app/(legal)/probability/page.tsx`와 `jam-web/src/lib/probability/disclosure.ts`: 캡슐 구역을 챕터 보상 구역으로 바꾼다(확률이 있을 때).
2. `jam-web/src/lib/probability/changeLog.ts`: 바뀐 날짜를 기록한다. 사전 공지 모달 규칙(`ch18-probability-pre-notice`)을 확인한다.
3. 시험 3개(`page.test.tsx`, `page.tierUp.test.tsx`, `disclosure.test.ts`)와 `docs/service/prd/probability/PRD.md`.

## 완료 조건

- 확률 안내 페이지에 «캡슐» 구역이 없고, 챕터 보상 확률이 A3 확정 값과 같게 보인다.
- 변경 이력에 바뀐 날짜가 남아 있고 관련 시험이 통과한다.
- 확률 공시 범위(법무)와 사전 공지 규칙을 확인해 티켓에 적었다.

## 규모와 체크포인트

- 규모: 파일 7개, 약 250줄(추정, 미검증)
- 체크포인트: 확률 변경이므로 법무 확인(A1)과 사전 공지 규칙을 확인한 뒤 배포한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
- 결정 반영(2026-11-27, A3 20261127_1723): 확률 안내에 보일 챕터 오름 보상 확률은 후보 E의 등급 확률(Common 30, Rare 40, Epic 22, Mystic 8)과 개수(마친 챕터 1~3은 3개, 4~6은 4개, 7~9는 5개)다. 보정 장치는 캡슐 값 그대로다.
