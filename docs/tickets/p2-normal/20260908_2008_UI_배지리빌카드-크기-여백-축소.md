# [UI] 배지 리빌 카드 크기·내부 여백을 줄인다

## 배경 / 문제 정의

동기화 후 배지 획득 시 뜨는 `BadgeRevealCarousel`(`design-system/components/patterns/
BadgeRevealCarousel.jsx`) 카드가 사용자 육안 확인(스크린샷, "서초역" POI형 배지) 기준으로
너무 크다는 피드백. 현재 수치:

- 카드 폭 `344px`(서비스 컬럼 430px의 80%), 높이 = 폭×1.34 ≈ `461px`
- 내부 패딩 `24px`, 세로 요소 간 gap `12px`
- 이미지 영역 상한 `maxHeight: 46%`

오케스트레이터 사전 분석(코드 근거):
- 344px는 "이름 2줄+설명 3줄"이 꽉 차는 케이스를 기준으로 잡은 크기라, 이름·설명이 짧은
  카드(서초역처럼)에서는 그 여유가 그대로 빈 공간으로 남는다.
- "여백이 많다"는 인상의 실질 원인은 패딩(24px, 카드 높이의 약 10%)보다 **이미지 영역
  46% cap**일 가능성이 크다 — 정사각형에 가까운 이미지가 46%를 거의 채우고, 짧은 텍스트
  아래로 큰 빈 공간이 남는다.

## 상세 요구사항

### UI/UX 관점
- 카드 폭을 사용자 요청 70%가 아니라 **85% 선(`344px → 약 292px`)에서 시작**한다 —
  70%(≈241px)는 텍스트가 긴 케이스(이름 2줄+설명 3줄)에서 답답해질 위험이 있다고
  오케스트레이터가 판단했고, 사용자가 이 판단에 동의해 진행을 승인함.
- `NEIGHBOR_OFFSET_RATIO`·`NEIGHBOR_DEPTH_PX`·`NEIGHBOR_ROTATE_DEG` 등은 `cardWidth`에
  비례하는 상수라 폭 하나만 바꾸면 캐러셀 전체가 따라온다 — 별도 조정 불필요(코드 구조
  확인 완료).
- 내부 여백은 패딩(24px)·gap(12px) 자체보다 **이미지 영역 상한(46%)을 낮추는 쪽**을
  우선 시도한다 — 긴 설명 케이스는 그대로 두고 짧은 케이스만 조밀해지는 효과를 노린다.
  실측 후 패딩·gap 자체도 줄일 필요가 있으면 함께 조정.
- 렌더 결과를 로컬 Storybook(`npm run storybook`, :6006)에서 **극단 케이스까지** 확인한다:
  - 이름 1줄+설명 1줄(서초역 케이스, 여백 문제의 근원)
  - 이름 2줄+설명 3줄(텍스트가 가장 긴 케이스 — 축소가 답답해지지 않는지)
  - 등급 칩·Lv.N 칩·×N 반복 획득 칩 각각
  - 이미지 없음(FALLBACK_ICON) 케이스
  - 이웃 카드(peek) 3장+ 순환에서 시각적으로 어색하지 않은지

### 서비스/코드베이스 관점
- `BadgeRevealCarousel.jsx`의 `cardWidth` 기본값·`BadgeCard` 함수의 패딩·gap·이미지
  `maxHeight` 값을 조정한다.
- 이 컴포넌트는 서비스가 실제로 쓰는 **연결된 컴포넌트**다(`BadgeRevealOverlay.tsx`가
  `@ds/components/patterns/BadgeRevealCarousel`을 직접 import). `.claude/skills/
  jam-work/SKILL.md` 1.6절 "연결된 컴포넌트 9종" 목록에는 빠져 있다 — 이미 티켓
  `20260908_0920`(P3, 문서 정리)이 이 낡은 목록 갱신을 다루고 있으므로 이번 티켓에서
  중복 처리하지 않는다. 완료 기록에는 "연결된 컴포넌트"로 명시한다.

## 구현 계획
1. `cardWidth` 기본값 344 → 292(85%) 조정
2. `BadgeCard`의 이미지 영역 `maxHeight: '46%'`를 낮춰(1차 시도 값은 개발자 판단, 예 38~40%)
   짧은 텍스트 케이스의 빈 공간을 줄인다
3. 로컬 Storybook으로 위 극단 케이스 전수 실측
4. 필요하면 패딩(24px)·gap(12px)도 미세 조정

## 1차 시도 FAIL — 2차 방향

### 게이트 리뷰 FAIL 사유
1. 티켓의 핵심 목표(짧은 텍스트 카드에서 이미지 아래로 남는 빈 공간 해소)가 실제로는
   해결되지 않았다. 리뷰어가 Storybook을 직접 빌드해 `ShortText` 스토리("서초역" 케이스)를
   이전 값(`cardWidth` 344px, `maxHeight` 46%)과 1차 시도 값(292px, 38%)으로 각각
   렌더링해 카드 높이로 정규화 비교한 결과, 텍스트 아래 여백 비율이 19.1%(이전) →
   21.0%(1차 시도)로 오히려 소폭 증가했다.
2. 원인: `BadgeCard`의 flex 컨테이너가 `justifyContent:'center'`로 고정 높이(`cardWidth
   ×1.34`)를 채우는 구조에서, 이미지 wrapper가 `flex:'1 1 auto'`(growable)인 채로
   `maxHeight` 상한만 낮추면 wrapper가 여전히 남는 공간을 흡수하려 하고, 그 여유가 카드
   상하로 재분배될 뿐 사라지지 않는다. "이미지 cap 축소만으로 여백 문제가 해소된다"는
   1차 가정이 실측으로 반증됐다.
3. 티켓이 "로컬 Storybook에서 극단 케이스까지 확인 필수"라고 명시했음에도 1차 개발자는
   브라우저 렌더 확인 없이 코드 리뷰만으로 완료 보고했다(WARN alert로 스스로 인정) — 바로
   그 생략된 단계에서 결함이 발견됐어야 한다.
4. 부수적 사실 오류: 주석에 "292px는 서비스 컬럼 430px의 85%"라고 적었으나 292/430≈68%다
   (85%는 292/344 기준) — 정정 필요.
5. 카드 폭 축소(344→292px) 자체와 텍스트 잘림 회귀 없음, `lint`(0 errors)·storybook build는
   1차에서 이미 정상 — 유지.

### 사용자가 지시한 2차 방향
"컴포넌트가 스크립트되었던 원래 구조에 최적화된 방법으로 진행" — 3D 코버플로우 캐러셀은
모든 카드가 동일한 고정 크기 사각 박스(`cardBaseStyle`의 width/height 상수, `marginTop`/
`marginLeft` 음수 오프셋)라는 것이 원 설계다. 카드마다 높이가 달라지는 가변 높이 재설계는
이 전제를 깨므로 채택하지 않는다. 대신:
- 고정 카드 박스는 그대로 두고, **이미지 wrapper 자체를 growable(`flex:'1 1 auto'`)에서
  고정 크기(`flex:'0 0 auto'` + 카드 폭 기준 고정 비율)로 바꾼다.**
- `justifyContent:'center'`는 유지 — 콘텐츠 블록(이미지+칩+이름+설명)을 카드 중앙에 배치하는
  것이 원래 설계 의도. 텍스트가 짧으면 블록 전체가 작아지고 카드 상하로 여백이 고르게
  분산되는 것이 목표.
- 정사각형 62% 선에서 시작해 실측 조정.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약 (2차)
- `cardWidth` 기본값은 1차와 동일하게 344px(컬럼 430px의 68%, 344px 대비 85%) → 292px로
  유지. 이 값 자체는 FAIL 사유에 없었다.
- `BadgeCard` 이미지 wrapper를 growable(`flex:'1 1 auto'` + `maxHeight:'46%'`)에서
  **고정 크기**(`flex:'0 0 auto'`, `width`/`height` = `cardWidth × IMAGE_SIZE_RATIO(0.58)`
  정사각형)로 바꿨다. `justifyContent:'center'`는 그대로 둬 콘텐츠 블록 전체를 카드
  중앙에 배치한다 — 텍스트가 짧으면 블록 전체 높이가 줄어 카드 상하 여백이 **고르게**
  분산되고, 텍스트가 길면 블록이 커져 여백이 줄어드는 구조로 바뀌었다(1차의 "남는 공간을
  이미지가 흡수" 구조를 제거).
- 이미지 비율 62%(티켓 예시 시작값)로 시작했으나, 이름 2행+설명 3행 최악 케이스에서
  카드 높이(391px) 대비 콘텐츠 총합이 근소하게 넘칠 여지가 있어(추정) 58%로 낮춰 실측—
  아래 "실측 결과" 참조.
- 코드 주석의 "292px = 컬럼 430px의 85%" 오류를 "292/430≈68%(344px 대비 85%)"로 정정.
