# [UI] 팔로우 배지 리빌 애니메이션 — 프로필 화면 팔로우 버튼 2곳 미연동

## 배경 / 문제 정의

티켓 [20260910_2056](20260910_2056_BadgeEngine_JAM카테고리-팔로우리빌애니메이션연동.md) 구현·
게이트 리뷰 중 발견된 범위 밖 이슈. `POST /api/follows`를 호출하는 프론트 코드는 총 3곳인데,
리빌 애니메이션은 그중 1곳에만 연동됐다.

| # | 호출부 | 파일 | 리빌 연동 |
|---|---|---|---|
| ① | 팔로워/팔로잉 전용 목록 페이지 | `[username]/FollowButton.tsx` | ✅ (20260910_2056에서 연동) |
| ② | 타인 프로필 헤더의 팔로우 버튼 | `profile/ProfileClient.tsx` `handleFollow`(276~310행) | ❌ |
| ③ | 본인 프로필의 팔로워/팔로잉 탭 내부 리스트 | `profile/ProfileClient.tsx` `handleListFollow`(251~273행) | ❌ |

②·③ 모두 같은 `POST /api/follows` 엔드포인트를 호출하지만 응답을 `.json()`으로 파싱하지
않아, 이 두 화면에서 팔로우해 JAM! 사용량 배지(`following_count` 등)를 획득해도 리빌
연출이 뜨지 않는다. 특히 ③(탭 내부 리스트)은 여러 명을 연달아 팔로우하기 가장 쉬운
동선이라 `following_count` 조건 배지가 실제로 걸리기 쉬운 상황인데도 아무 연출이 없다.

티켓 [20260817_002](20260817_002_UI_팔로우버튼-그레이톤-대비-수정.md)에서 이미 이 3곳
중복 구현이 스타일 버그의 원인이 된 전례가 있다 — 같은 구조적 원인(팔로우 토글 로직이
한 곳이 아니라 3곳에 각각 구현됨)이 이번엔 기능 격차로 재발했다.

## 상세 요구사항

### 서비스/코드베이스 관점

**제안 변경**

1. `ProfileClient.tsx`의 `handleFollow`·`handleListFollow` 둘 다 `POST /api/follows` 응답을
   `.json()`으로 파싱하고, `earnedBadges.length > 0`이면 `BadgeRevealOverlay`를 연다 —
   `FollowButton.tsx`(20260910_2056)가 이미 이식해둔 패턴을 그대로 재사용.
2. 세 호출부(`FollowButton.tsx`, `handleFollow`, `handleListFollow`)의 팔로우 토글 로직이
   구조적으로 반복되는 문제 자체는, 이번 티켓에서 셋을 공용 훅(`useFollowToggle` 등)으로
   합칠지 각자 리빌만 추가할지 구현 단계에서 판단한다 — `/jam-design` 판정 참고.

### 구현 계획

`FollowButton.tsx`(2056)의 리빌 연동 패턴을 `ProfileClient.tsx`의 두 핸들러에 이식한다.
신규 컴포넌트 불필요, `BadgeRevealOverlay` 재사용.

### Acceptance Criteria

1. 타인 프로필 헤더에서 팔로우해 배지를 획득하면 리빌 오버레이가 뜬다.
2. 본인 프로필의 팔로워/팔로잉 탭 리스트에서 팔로우해 배지를 획득하면 리빌 오버레이가 뜬다.
3. 배지를 획득하지 않은 일반 팔로우는 기존과 동일하게 동작한다(회귀 없음).
4. 언팔로우 동작에는 영향이 없다.

## 완료 기록

### 구현 내용 요약
`FollowButton.tsx`(티켓 20260910_2056)가 이미 이식해둔 패턴(`FollowResponse` 타입,
`earnedBadges.length > 0` 판정, `BadgeRevealOverlay` 오픈)을 `ProfileClient.tsx`의
`handleFollow`·`handleListFollow` 두 핸들러에 그대로 이식했다. 오버레이 상태
(`revealOpen`/`earnedBadges`/`earnedBadgesMore`)는 두 호출부가 공유하도록 컴포넌트
최상단에 한 벌만 두고, `<BadgeRevealOverlay>` 렌더도 최하단에 하나만 추가했다.
`handleListFollow`는 언팔로우 분기(`current === true`)에는 배지 지급이 없으므로 신규
팔로우(`!current`)일 때만 응답을 파싱한다.
