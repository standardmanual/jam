# [Admin] JAM! 카테고리 — 어드민 배지 분류 표시 통합

## 배경 / 문제 정의

티켓 [20260910_2055](../P1-중요/20260910_2055_BadgeEngine_JAM카테고리-어드민전반영-admin_category컬럼신설.md)로
`badges.admin_category` 컬럼을 신설하고 어드민 6개 화면에 반영했다. 판정 로직(컬럼 자체,
`usageBadges.ts`의 실시간 평가 경로)은 이미 걷기/러닝/자전거/등산/트레일러닝 5종목 체계와
완전히 분리돼 있어 그대로 유지한다 — 이번 티켓은 **오직 어드민 화면의 표시 방식**만 다룬다.

사용자와 협의한 결과, 어드민에서 JAM!을 "카테고리"라는 별도 개념으로 취급하지 않고 기존
5종목과 나란히 "분류의 한 항목"(여섯 번째 종목)처럼 자연스럽게 노출하기로 했다. 조사 결과
화면마다 반영 상태가 갈린다:

- **계열관리**(`badge-families/page.tsx:131-134`)·**게이트미션**(`GateMissionManager.tsx:249-257`,
  `gate-missions/page.tsx:78`)은 이미 종목 칸/드롭다운에 자연스럽게 섞여 표시된다 — 수정 불필요.
- **배지 목록 필터**(`BadgesFilterBar.tsx`)는 "액티비티"(44-50행, 5개 하드코딩)와
  "카테고리"(209-214행, JAM! 하나뿐) 드롭다운이 완전히 분리돼 있어, 어드민이 종목을 고르려고
  액티비티 드롭다운을 열어도 JAM!이 안 보이고 별도의 "카테고리"를 따로 찾아야 한다.
- **아이템북 검색**(`BadgeSearchSelect.tsx:88,141-145`)은 `[JAM!]` 인디고색 전용 칩이 다른
  배지 표기 옆에서 시각적으로 튄다.
- **배지 생성·수정 폼**(`BadgeForm.tsx:755-778`)은 "어드민 카테고리" 드롭다운이 "활동
  종류" 체크박스 그룹(876-892행)과 100줄 넘게 떨어진 별개 섹션·별개 UI 패턴(Select vs
  체크박스)으로 존재해 가장 튄다.
- 시뮬레이터·활동배지이미지·배지진단·배지지표관리는 이미 의도대로 제외돼 있어 수정 불필요.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **`BadgesFilterBar.tsx`** — `ACTIVITY_TYPE_OPTIONS`(44-50행)에 `{value:'jam', label:'JAM!'}`을
   여섯 번째로 추가한다. 선택 시 내부적으로 `admin_category=jam` 쿼리 파라미터로 매핑해
   서버 필터링은 지금과 동일하게 동작시킨다. 별도로 떠 있는 "카테고리" `DataTableFacetedFilter`
   컨트롤(200-214행)은 제거해 하나의 드롭다운으로 통합한다. 서버 측 쿼리 분기
   (`badge-list-view.ts`)는 파라미터 이름이 바뀌지 않는 한 그대로 둔다.
2. **`BadgeSearchSelect.tsx`** — 88행 선택 라벨의 `[JAM!]` 접미와 141-145행 드롭다운의
   인디고색 전용 칩을 제거하고, 다른 배지의 `[type/rarity]` 표기와 같은 무채색 보조텍스트
   형태로 흡수한다.
3. **`BadgeForm.tsx`** — "어드민 카테고리" 드롭다운(755-778행)을 "활동 종류" 체크박스
   그룹(876-892행) 안 또는 바로 옆으로 재배치하고, 같은 컨트롤 형태(체크박스에 "JAM!" 옵션
   추가, 선택 시 활동 종류 값을 비우는 상호배타 처리)로 통일한다. 저장 API 계약
   (`admin_category` 필드, `type==='checkin'` 가드와 무관하게 항상 저장)은 그대로 유지한다.
4. **손대지 않는 화면**: 계열관리, 게이트미션, 시뮬레이터, 활동배지이미지, 배지진단,
   배지지표관리 — 조사로 이미 정상 또는 의도된 제외 상태임을 확인했다.

## 구현 계획

세 파일(`BadgesFilterBar.tsx`, `BadgeSearchSelect.tsx`, `BadgeForm.tsx`) 각각 독립적인 UI
정리 작업이라 순서 의존성은 없다. `admin_category` 컬럼·API 저장 로직·시뮬레이터 제외 로직 등
판정 계층은 전혀 건드리지 않는다 — 순수 표시 레이어 정리다.

## Out of Scope

- `admin_category` 컬럼·CHECK 제약·판정 로직 변경 — 이번 티켓은 표시만 다룬다
- 배지 트리 탭 노출, 진행률 UI — 여전히 범위 밖
- MODULAR 컴포넌트로의 마이그레이션 — 어드민 화면은 MODULAR 적용 대상이 아니다(정책 결정)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

세 파일 모두 요구사항대로 반영했다. `BadgesFilterBar.tsx`는 "액티비티"·"카테고리" 두
`DataTableFacetedFilter`를 하나로 통합했다 — `ACTIVITY_TYPE_OPTIONS`에 `{value:'jam',
label:'JAM!'}`을 여섯 번째로 추가하고, 선택 시 `admin_category=jam` 쿼리로 매핑하는
`handleActivityTypeChange` 핸들러를 신설해 상호배타로 동작시켰다. 별도 "카테고리" 필터
블록은 제거했다. `BadgeSearchSelect.tsx`는 `[JAM!]` 인디고 전용 칩을 없애고
`[type/rarity, JAM!]` 형태의 무채색 보조텍스트로 흡수했다. `BadgeForm.tsx`는 "어드민
카테고리" `Select`를 제거하고 "활동 종류" 체크박스 그룹에 JAM! 옵션을 추가했다 —
`toggleActivityType`이 종목 선택 시 `adminCategory`를 비우고, 신설한
`toggleAdminCategoryJam`이 JAM! 선택 시 `activityTypes`를 비우는 양방향 상호배타
처리다. 저장 페이로드(`admin_category: adminCategory || null`, `type` 무관 항상 저장)는
손대지 않았다.
