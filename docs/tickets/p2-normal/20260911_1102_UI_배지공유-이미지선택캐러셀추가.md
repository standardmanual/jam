# [UI] 배지 공유 시트에 이미지 선택 캐러셀 추가

## 배경 / 문제 정의
현재 배지 상세페이지의 공유 시트(`BadgeShareButton.tsx`)는 `buildBadgeShareBlob`이 합성한
1080×1920 "공유 카드"(배지 이미지 + 거리/페이스/시간 텍스트 + 로고) 한 장만 미리보고,
공유하거나 저장할 수 있다. 배지 원본 이미지(`badgeRow.image_url`)는 카드 합성 재료로만
쓰이고, 배지 이미지 단독으로 공유·저장하는 경로가 없다.

사용자는 상황에 따라 통계가 포함된 완성 카드보다 배지 이미지 자체만 가볍게 공유하고
싶을 수 있다. 이번 작업은 시트 안에 "기존 이미지(공유 카드)"와 "배지 이미지" 두 항목을
캐러셀로 보여주고, 사용자가 선택한 항목을 저장·공유하도록 기능을 확장한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `BadgeShareButton.tsx`의 미리보기 영역을 단일 이미지에서 **캐러셀 2항목**으로 바꾼다.
  - 항목 1(기존): `buildBadgeShareBlob`이 만드는 현재의 공유 카드(1080×1920).
  - 항목 2(신규): 배지 원본 이미지(`imageUrl`)를 **300px 정사각형**으로 변환한 이미지.
- 사용자가 캐러셀에서 항목을 바꾸면, 그 시점에 선택된 항목의 blob이 "공유"·"저장" 버튼
  (`handleAction`/`handleSave`)의 대상이 된다.
- 300px 변환은 서버 사이드(sharp)가 아니라 기존 `buildBadgeShareBlob.ts`의 `drawContain`
  캔버스 합성 패턴을 재사용해 클라이언트에서 처리한다(조사 결과, 이 프로젝트의 정착된 패턴).
- 두 blob 모두 시트가 열릴 때 함께 생성해두고(또는 캐러셀 진입 시 지연 생성), 로딩 상태는
  항목별로 독립적으로 표시한다.

### UI/UX 관점
- 캐러셀 컴포넌트는 신규 제작하지 않고 MODULAR `Carousel`
  (`jam-web/design-system/components/navigation/Carousel.jsx`)을 재사용한다 — 조사 결과
  이미 `items`/`activeIndex`/`onActiveIndexChange`/`renderItem` 컨트롤드 API를 제공하며
  이번 2항목 선택 UI에 그대로 맞는다.
- 기존 체크보드 미리보기 프레임(투명 PNG 시각화)과 130% 확대 스타일은 캐러셀 안의 각
  `renderItem`에도 유지한다.
- "공유"·"저장" 버튼 라벨과 시트 레이아웃(푸터 2버튼)은 기존 구조를 유지한다.

## 구현 계획
1. `buildBadgeShareBlob.ts`(또는 신규 파일)에 배지 이미지를 300×300으로 `drawContain`하는
   `buildBadgeImageBlob(imageUrl: string): Promise<Blob>` 함수를 추가한다.
2. `BadgeShareButton.tsx`의 `ShareState`를 확장해 두 항목(카드/배지 이미지)의 준비 상태를
   각각 담을 수 있게 한다(예: `{ kind: 'ready'; items: [{blobUrl, blob}, {blobUrl, blob}] }`
   또는 항목별 상태 배열).
3. 미리보기 영역을 `Carousel`로 교체하고 `activeIndex` state로 선택된 항목을 추적한다.
4. `handleAction`/`handleSave` 호출 시 `activeIndex`에 해당하는 blob을 넘기도록 수정한다.
   파일명(`${badgeName}-jam.png`)도 항목에 따라 구분할지 검토한다(예: 배지 이미지는
   `${badgeName}-badge.png`).
5. `Service Plan/Specs/PRD/BadgeShare/PRD.md`의 "핵심 플로우"·"이미지 생성 방식" 절에
   캐러셀 선택 흐름과 300px 배지 이미지 변환 규격을 반영한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `buildBadgeShareBlob.ts`에 `buildBadgeImageBlob(imageUrl): Promise<Blob>`을 추가했다.
  기존 `drawContain` 캔버스 합성 패턴을 재사용해 배지 원본 이미지를 300×300 정사각형
  투명 PNG로 변환한다(통계 텍스트·로고 없음).
- `BadgeShareButton.tsx`의 `ShareState`를 단일 상태에서 `{ card, badge }` 2항목 구조로
  확장하고, 각 항목을 독립된 `useEffect`(각자 objectURL ref)로 생성한다 — 카드는 기존처럼
  스트라바 통계 API 조회 후 생성, 배지 이미지는 API 의존 없이 바로 생성돼 더 빨리
  준비될 수 있다. 로딩 상태도 항목별로 `useDebouncedLoading`을 따로 적용했다.
- 미리보기 영역을 MODULAR `Carousel`(`design-system/components/navigation/Carousel.jsx`)로
  교체했다. `items`에 `['card','badge']`를 넣고 `activeIndex`/`onActiveIndexChange`로 선택을
  추적하며, `renderItem`이 기존 체크보드 프레임 + 130% 확대 스타일을 각 슬라이드 안에
  그대로 유지한다.
- "공유"·"저장" 버튼(`handleAction`/`handleSave`)은 이제 `activeIndex`에 해당하는 항목의
  blob과 파일명 접미사(`jam`/`badge`)를 받는다. 파일명은 `{배지이름}-jam.png`(카드) /
  `{배지이름}-badge.png`(배지 이미지)로 구분된다.
- 시트를 여는 시점(`handleButtonClick`)에 두 항목 모두 loading으로 되돌리고
  `activeIndex`를 0(카드)으로 초기화한다.
- `Service Plan/Specs/PRD/BadgeShare/PRD.md`의 "핵심 플로우"·"이미지 생성 방식" 절에
  캐러셀 2항목 흐름과 300px 배지 이미지 변환 규격을 반영했다.
- **(머지 후 보완)** 인터페이스 리뷰(better-accessibility) 제안을 반영해 접근성을
  보완했다: 에러 상태·로딩 상태 안내에 `role="status" aria-live="polite"`를 추가하고,
  캐러셀 각 슬라이드(`renderItem`)에 `role="group" aria-label`로 "통계 포함 공유
  카드"/"배지 이미지 단독" 구분을 붙였다. 로딩 안내 문구는 `d.badges.shareImageLoading`
  ("공유 이미지를 준비하고 있어요")을 새 i18n 키로 추가해 `sr-only`로 노출한다
  (`BadgeRevealOverlay.tsx`의 기존 sr-only 패턴과 동일 형태).

### 주요 의사결정 / 핵심 메모
- **파일명 접미사**: 티켓 구현 계획 4단계 제안대로 카드는 `-jam`(기존 유지, 하위 호환),
  배지 이미지는 `-badge`로 구분했다.
- **캐러셀 페이지네이션 표시(dots) 미추가**: 스펙에 없는 범위 확장이라 배제했다. 이 앱의
  기존 Carousel 사용처(`PoiCarouselModal`)도 별도 dots 없이 peek 레이아웃(옆 카드가 부분적으로
  보임)만으로 스와이프 가능함을 암시하는 패턴이라 일관성 있게 따랐다.
- **로딩 디바운스를 항목별로 분리**: 티켓이 "로딩 상태는 항목별로 독립적으로 표시"를
  명시해, 기존 단일 `showShareLoader`를 `showCardLoader`/`showBadgeLoader`로 나눴다.

### 잔여 이슈
- 로컬/staging 테스트 계정에 획득한 배지가 없어(activity·item 모두 0건) 실제 시트를 열어
  캐러셀 스와이프·버튼 동작을 눈으로 확인하지 못했다. staging 배포 후 배지를 보유한 계정으로
  확인이 필요하다(HALT는 아님 — 코드 경로는 기존 검증된 패턴을 그대로 확장한 것이라
  타입체크·린트로 정적 검증은 마쳤다). 이 제약은 범위 밖 발견물로 별도 티켓
  `20260911_1116`(스테이징 테스트 계정 배지 시드 데이터 없음)에 남겼다.
- 인터페이스 리뷰(better-accessibility)가 제안한 aria-live·aria-label 보완은 머지 시점에
  함께 반영 완료. 레이아웃 리뷰가 지적한 "peek 레이아웃으로 미리보기가 이전보다 살짝
  좁아 보이는 점"은 MODULAR Carousel 재사용에 따른 의도된 트레이드오프로 보고 이번에는
  손대지 않았다.
