## 상세 요구사항

### 서비스/코드베이스 관점
- `src/components/ui/` 하위 공용 컴포넌트: Button, BottomSheet, Footer, TabBar, Toast, TopNav, LoadingSpinner, SwapText, ListRowCard, BadgeGridCard, CollectionGridCard, PopInNumber, SlidingTabs, icons 등
- `src/components/` 기타 공용 컴포넌트: SafeImage, SyncButton, LocalDate, NavigationLoader, BlobAnimationBackground, BadgeBackgroundVideoTiles, BadgeRevealOverlay, PoiCarouselModal, map/MapView, ranking/RankingListRow
- `src/app/layout.tsx`의 SEO 메타데이터(title/description 등) 하드코딩 텍스트

## 구현 계획
- 각 파일의 하드코딩 한글 텍스트를 `/im-not-ai`로 검사한 뒤 문제를 고치면서 `d.common.*` 등 적절한 딕셔너리 네임스페이스로 편입한다.
- 여러 도메인이 공유하는 컴포넌트이므로, 03~16 도메인 티켓 작업자가 이 컴포넌트를 수정하지 않도록 이 티켓을 먼저 마친다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
대상 파일 전체를 전수 스캔한 결과, 대부분의 공용 컴포넌트(Button, BottomSheet, Footer, TabBar,
Toast, TopNav, SwapText, ListRowCard, BadgeGridCard, PopInNumber, SlidingTabs, icons, SafeImage,
SyncButton, LocalDate, NavigationLoader, BlobAnimationBackground, BadgeBackgroundVideoTiles,
BadgeRevealOverlay, ranking/RankingListRow)는 이미 `d.*` 딕셔너리를 참조하거나 props로 텍스트를
전달받는 구조였고, 남아 있는 한글은 전부 코드 주석이었다(사용자 노출 아님, 작업 범위 밖).

실제로 컴포넌트 내부에 고정 리터럴로 박혀 있던 항목만 골라 딕셔너리 키로 옮겼다:
- `LoadingSpinner`의 `aria-label="로딩 중"` → `d.common.loading`(신설)
- `CollectionGridCard`의 완성 뱃지 텍스트 `"완성"` → 기존 `d.itembooks.completed` 재사용(신규
  용어 아님 — 가이드 §1.3 "컬렉션" 항목의 "완성" 고정 용어와 동일 개념이라 새 키를 만들지 않음)
- `PoiCarouselModal`의 캐러셀 `ariaLabel="주변 지점 목록"` → `d.drops.poiCarouselListAriaLabel`(신설,
  기존 `poiCarouselAriaLabel`은 다이얼로그 라벨이라 별개)
- `map/MapView`의 내 위치 마커 `title="현재 위치"`, 버튼 `aria-label="현재 위치로 이동"` →
  `d.map.myLocationMarkerLabel`·`d.map.myLocationButtonAriaLabel`(신설 `map` 네임스페이스 —
  `/drops`·`/missions` 양쪽이 이 컴포넌트를 공유해 특정 도메인 네임스페이스에 넣지 않음)
- `app/layout.tsx`의 SEO `title`/`description` → `d.common.seoTitle`·`d.common.seoDescription`(신설)

`/im-not-ai` anti-slop 기준(가이드 §7)으로 각 문구를 재검토했으나 표현 자체를 바꿀 필요는
없었다 — "로딩 중"·"완성"·"주변 지점 목록"·"현재 위치"는 모두 짧은 상태 라벨/aria-label로
번역투·클리셰·수동태 패턴이 끼어들 여지가 없었다. SEO description "피지털 게이미피케이션
플랫폼"은 §2.5 예외(명사형 종결 허용)에 해당하고, `Service Plan/Business/서비스플랜/`에서
이미 확립된 브랜드 고정 용어(피지털·게이미피케이션)라 표현을 바꾸지 않고 그대로 딕셔너리로만
옮겼다.

`map/MapView.tsx`의 `script.onerror = () => reject(new Error('네이버 지도 로드 실패'))`는
`console.error`로만 소비되는 내부 디버그 로그이고 화면에 노출되지 않아 작업 범위(사용자 노출
텍스트) 밖으로 판단해 건드리지 않았다.

**한국어 리뷰(`humanize-korean`) 결과 — 후속 티켓으로 분리**: 게이트는 PASS했지만, 한국어
리뷰에서 옮겨진 문구 표현 자체(딕셔너리 이관 구조가 아니라 문구 톤)에 대한 지적이 나왔다.
가장 심각한 항목은 SEO description "피지털 게이미피케이션 플랫폼"이 가이드 §1.1 공급자
언어 금지·핵심 철학을 위반한다는 것. 그 외 "로딩 중"(§5.3 명시적 금지어), "현재 위치"류
(§1.2 사용자 시점), "주변 지점 목록"(어휘 톤) 지적도 있었다. 구조(딕셔너리 편입) 자체는
문제없다고 판단해 이 티켓은 그대로 병합하고, 문구 표현 개선은 후속 티켓
[`20260915_2315_Content_SEO문구및공용컴포넌트라벨-톤정비.md`](../P2-일반/20260915_2315_Content_SEO문구및공용컴포넌트라벨-톤정비.md)로
분리했다(사용자 결정, 2026-09-15).

### 주요 의사결정 / 핵심 메모
- `map/MapView.tsx`는 `/drops`·`/missions` 두 화면이 공유하는 컴포넌트라 두 도메인 중
  하나의 네임스페이스에 종속시키지 않고 새 `d.map` 네임스페이스를 신설했다.
- `CollectionGridCard`의 "완성"은 새 키를 만들지 않고 기존 `d.itembooks.completed`를 재사용했다
  — 같은 개념(컬렉션 완성)에 두 번째 문자열을 만들면 가이드 §1.3 "용어 일관성" 원칙과
  어긋난다.
- `src/app/api/**` 서버 에러 메시지는 이 티켓의 대상 목록(공용 UI 컴포넌트 + SEO 메타데이터)에
  없어 ADR 0001의 적용 대상 파일을 이 작업에서 건드리지 않았다.
