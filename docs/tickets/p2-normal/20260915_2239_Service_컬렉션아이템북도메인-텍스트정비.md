## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
대상 화면 3개(`collections/[id]/page.tsx`, `SlotGrid.tsx`, `ItemBookHeroSection.tsx`)는
조사 결과 이미 `d.itembooks.*`를 전부 사용 중이라 하드코딩이 없었다(diff 0줄). 실제 위반은
API 라우트 2개에 있었다 — `-습니다`체 하드코딩 한글 메시지를 응답 바디에 직접 담고,
클라이언트가 가공 없이 그대로 노출하는 구조라 ADR 0001 적용 대상이었다.

- `d.itembooks`에 API 에러 메시지 키 20여 개 신설. §1.3 고정 용어에 따라 데이터 모델 내부
  명칭 "슬롯"을 사용자 노출 문구에서 전부 "장착"/"장착 정보"로 교정, `-습니다`체를 해요체로
  통일
- `api/itembooks/[id]/slot/route.ts`(POST/DELETE/PATCH)·`api/itembooks/route.ts`(GET)의
  `Unauthorized` 하드코딩을 `d.common.authRequired`로 통일(badges/checkin-badges 도메인과
  동일 패턴)
- unslot 실패 코드 `inventory_full`의 기존 메시지("인벤토리를 늘려보세요")가 실제로 존재하지
  않는 사용자 행동(인벤토리 최대치는 어드민이 전역 정책으로 설정, 개인이 늘릴 방법 없음)을
  해결책으로 제시하던 버그성 문구임을 발견해 "정리하고 다시 시도해 주세요"로 정정
