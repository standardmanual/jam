## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `d.combine.*` 딕셔너리를 UX 가이드 §1.3(용어)·§3(표기)·§4.0(서버-클라이언트 단일 진실
  소스)·§4.2(인라인 축약)·§5.3(처리 중 라벨)·§7(anti-slop) 기준에 맞게 재작성했다.
  - `selectRangeError`: "아이템 2~10개를 선택해주세요." → "아이템은 2개에서 10개까지 선택할
    수 있어요" (§4.2 닉네임 예시와 같은 [현상+해결책] 축약 패턴, 마침표 제거).
  - `itemsNotFound`: "아이템을 찾을 수 없어요." → "선택한 아이템을 찾을 수 없어요. 인벤토리를
    새로고침하고 다시 선택해 주세요" (드랍 도메인 `dropItemNotFound`와 동일한 [현상+해결책]
    구조로 통일).
  - `recipeFail`: "믹스에 실패했어요. 아이템이 소각됐어요." → "재료가 뒤섞이더니 흔적도 없이
    사라졌어요" — UX 가이드 §1.2가 이 정확한 시나리오("조합에 실패하였습니다")의 예시로 이미
    제시한 문구를 그대로 채택했다.
  - `genericError`(네트워크 예외 전용): "오류가 발생했어요." → "지금은 믹스할 수 없어요. 잠시
    후 다시 시도해 주세요" (드랍/픽업 `dropFailed`/`pickupFailed`와 동일한 톤으로 통일).
  - `genericFail`(서버 reason 미매칭 방어적 폴백): "믹스 실패" → "오류가 발생했어요".
  - `consolationPoints`에 누락됐던 "포인트" 단위를 붙였다(" (실패 보상 +{points})" →
    " (실패 보상 +{points} 포인트)").
  - `emptyInventory`의 불필요한 마침표 제거(§3 "본문 한 문장·빈 상태는 마침표 없음").
  - `combineButtonLoading`("믹스하는 중") 신설 — §5.3에 따라 처리 중 버튼 라벨이 유휴 상태와
    같은 "믹스하기"로 고정돼 있던 것을 진행형으로 분리했다(믹스 버튼은 드랍/픽업처럼 반복
    노출되는 목록형 액션이 아니라 화면당 1개인 주요 CTA라 §5.1 명사 축약 예외 대상이
    아니라고 판단, 기본형인 동사형을 유지).
- ADR 0001(서버-클라이언트 단일 진실 소스)에 따라 `api/combine/route.ts`가 실패
  사유(`invalid_count`/`items_not_found`/`no_recipe_match`)와 "레시피는 매칭됐지만 보상이
  전부 비어 실패에 가까운" 엣지 케이스(20260910_1515)를 서버에서 판정해 완성된 `message`를
  응답에 실어 보내도록 바꿨다. `CombineClient.tsx`는 더 이상 `reason` 코드를 자체 딕셔너리로
  재매핑하지 않고 `data.message`를 그대로 신뢰해 노출한다(과거에는 서버 메시지를 무시하고
  자체 `msgs` 맵으로 재조립하던 것이 ADR이 지적한 anti-pattern 사례였다).
  - 401 인증 필요 응답의 하드코딩 문구("인증이 필요합니다.")도 이미 다른 라우트가 쓰는
    `d.common.authRequired`로 통일했다.
  - 400(2~10개 범위 위반) 응답도 `CombineResult` 형태(`{ success: false, reason:
    'invalid_count', message, pointsAwarded: 0 }`)로 맞춰 클라이언트가 단일 경로(`data.message`)
    로만 처리하게 했다.
- `src/lib/combine/policy.ts`는 사용자 노출 문자열이 없어(로그만 존재) 변경 대상이 아니었다.
- `src/lib/combine/recipe-payload.ts`의 하드코딩 에러 문구는 `lib/admin/recipe-write.ts`
  (어드민 레시피 저작 API)에서만 쓰인다 — UX 가이드 §1.3·§4.0의 어드민 예외
  (`src/app/api/admin/**`, 저작 도구 용어) 대상이라 이관하지 않고 그대로 두었다.

### 주요 의사결정 / 핵심 메모
- **레시피 성공-빈손 엣지 케이스(20260910_1515)의 판정 위치를 서버로 이전**했다. 기존에는
  `CombineClient.tsx`가 `resultBadges.length === 0 && pointsAwarded === 0`을 직접 재판정해
  `d.combine.recipeFail`을 표시했는데, 이는 ADR 0001이 금지하는 "서버 상태를 클라이언트가
  재현" 패턴이라 `api/combine/route.ts`로 옮겼다. `CombineResult` 타입(`success: true`)은
  건드리지 않고 응답에 `message` 필드만 추가하는 방식을 택해 DB 스키마·타입 변경 없이
  해결했다.
- **`combineButton` 유휴 라벨은 "믹스하기"(동사형)를 유지**했다. 드랍/픽업 버튼은 목록에서
  반복 노출되는 액션이라 §5.1 예외로 명사 축약("드랍"/"픽업")을 쓰지만, 믹스 버튼은 화면당
  1개뿐인 주요 CTA라 §5.1 본문 규칙(예측 가능한 동사형 사용)을 그대로 적용하는 것이
  일관적이라고 판단했다. 처리 중 라벨만 §5.3 기본형(동사형 "믹스하는 중")으로 신설했다.
- **`src/lib/combine/recipe-payload.ts`는 이관 대상에서 제외**했다 — 호출부를 추적한 결과
  `lib/admin/recipe-write.ts`(어드민 전용)에서만 쓰여 UX 가이드의 어드민 예외 조항에
  해당한다. 무리하게 딕셔너리로 옮기면 어드민 전용 문구까지 사용자 노출 규칙 대상으로
  잘못 편입하는 것이라 판단해 감사만 하고 그대로 두었다.
- **hint_text가 없을 때의 대체 표시 `'???'`는 변경하지 않았다.** 자연어 문장이 아니라
  의도된 미공개 힌트 placeholder라 UX 가이드의 문장·톤 규칙 적용 대상이 아니라고 봤다.
