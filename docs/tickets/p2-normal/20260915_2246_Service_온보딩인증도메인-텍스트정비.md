### 주요 의사결정 / 핵심 메모
- **`StravaConnectReveal.tsx`의 기존 `d.profile.stravaConnect*` 키는 이관하지 않았다.** 티켓
  지침은 "d.onboarding/d.auth 네임스페이스로 편입"이지만, 이 키들은 이미 하드코딩 없이
  딕셔너리를 완전히 경유하고 있었다 — 단순 네임스페이스 재배치는 하드코딩 제거라는 티켓
  목적과 무관한 리팩터링이라 판단해 손대지 않았다(범위 외 작업 금지 원칙, 알림 도메인 티켓
  20260915_2245의 동일 판단과 일관).
- **`d.common.authRequired` 재사용 시 문구가 '인증이 필요합니다.' → '인증이 필요해요'로
  바뀐다.** 티켓 지침대로 이 키의 *값 자체*는 고치지 않고 그대로 참조만 했다 — 값 교정은
  티켓 20260916_0904가 별도로 담당한다. 두 API route(`strava/auth`, `strava/sync`)는 모두
  JSON 에러 바디이며 현재 클라이언트가 이 필드를 화면에 그대로 노출하지 않는다(SyncButton은
  자체 `d.today.syncFailed` 고정 토스트를 쓰고, StravaStatusCard는 애초에 미사용) — 사용자에게
  실제로 보이는 문구가 달라지는 지점은 없다.
- **`SyncButton.tsx`(서버 메시지 미신뢰)는 이번 티켓 범위 밖으로 판단**: ADR 0001은 "서버가
  완성 문구를 만들고 클라이언트가 그대로 신뢰해 노출"하라는 규칙이나, 이 컴포넌트는 "피드/오늘"
  도메인 티켓(20260915_2242)의 소유 파일이라 이 티켓에서는 API route(`strava/sync`)만
  ADR 0001에 맞춰 정비하고 클라이언트는 건드리지 않았다.
- **`StravaStatusCard.tsx`는 현재 어떤 화면에서도 import되지 않는 고아(orphan) 컴포넌트다**
  (git log 확인 결과 최근 정비 이력과도 무관 — 2026-08 이전부터 미사용 추정). 그래도 티켓이
  명시적으로 대상 파일로 지정했으므로 하드코딩 제거는 수행했다.

### 잔여 이슈
- `StravaStatusCard.tsx`가 실제로 어디에도 쓰이지 않는 고아 컴포넌트인지, 삭제 대상인지는
  이 티켓 범위 밖의 판단이 필요하다(정리 여부는 별도 논의 필요).

  ADR 0001 미준수는 "피드/오늘" 도메인 티켓(20260915_2242)에서 확인이 필요하다.
