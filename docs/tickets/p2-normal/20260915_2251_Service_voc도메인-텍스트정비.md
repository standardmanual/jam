## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `d.voc` 네임스페이스는 이미 존재해(20260828_1921) 신규 키 대부분은 만들 필요가 없었다.
  기존 값 중 가이드 위반 2건만 고쳤다: ①`loadError`→`loadFailed`로 개명하며 ADR 0001에 맞게
  서버가 완성해 보내는 문구로 성격을 바꿨다(§4.0), ②`emptyBody`의 "남겨보세요"를 보조용언
  띄어쓰기 규칙(§3)에 맞춰 "남겨 보세요"로 고쳤다.
- API route(`api/voc/route.ts`): ADR 0001에 따라 `Unauthorized`/`fetch_failed` 하드코딩
  문자열을 각각 `d.common.authRequired`(값 자체는 티켓 20260916_0904 소관이라 참조만 함)와
  `d.voc.loadFailed`로 교체. Google Sheets 조회 실패 시 원인은 `console.error`로만 남기고
  클라이언트에는 딕셔너리 완성 문구만 내려준다.
- 화면(`voc/page.tsx`): 클라이언트가 서버 에러 메시지를 그대로 신뢰해 노출하도록
  `error` state를 `boolean`→`string | null`로 바꿨다. 실패 응답의 `json.error`를 우선
  사용하고, 응답 자체를 못 받은 경우(JSON 파싱 실패·네트워크 단절)에만 `d.voc.loadFailed`로
  폴백한다. `VocPagination.tsx`는 검사 결과 가이드 위반 없어 변경 없음.

### 주요 의사결정 / 핵심 메모
- `d.voc.pageTitle`("문의")이 §6 TopNav 뒤로가기 레이블 정책(다양한 경로로 진입 가능한
  화면은 `d.common.back`을 써야 함)과 어긋나 보였지만, 이 티켓 범위(§7 anti-slop·§1.3
  용어·§2.3 톤·ADR 0001)에 명시되지 않은 네비게이션 구조 변경이라 임의로 고치지 않고
  alerts로만 보고한다.
- `loadError`→`loadFailed`로 개명한 이유: ADR 0001 적용 후 이 값은 더 이상 "클라이언트가
  로컬로 들고 있는 에러 문구"가 아니라 "서버가 응답 바디에 담아 보내는 완성 문구"로 성격이
  바뀌었다. 티켓 20260915_2250의 `d.drops.loadPoiFailed`/`d.search.searchFailed` 네이밍
  관행(`loadXFailed`)을 따라 통일했다.
- VOC 카드의 상태 칩 매핑 키(`문의중`/`확인중`/`답변완료`)는 Google Sheets가 실제로 내려주는
  데이터 값과 1:1 매칭하는 상수라 딕셔너리로 옮기지 않았다 — 개발자가 작성한 UI 카피가
  아니라 외부 데이터 소스의 어휘를 그대로 매칭하는 코드이므로 이 티켓의 "하드코딩된 텍스트"
  범위 밖으로 판단.

### 잔여 이슈
- `d.voc.pageTitle`의 TopNav 레이블 정책 위반(§6)은 별도 티켓으로 분리 검토 필요(위 alerts 참고).
