# [Content] 조합(combine) 도메인 문구 톤 및 표기 정비

> 상위 스펙: [`20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md`](../p1-high/20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md)
> 출처: 티켓 20260915_2240(조합 도메인 텍스트 정비) 한국어 리뷰에서 나온 제안 — 게이트는 PASS했으나 병합 전 반영하지 않고 이 후속 티켓으로 분리(사용자 결정, 2026-09-16)

## 배경 / 문제 정의

티켓 20260915_2240의 딕셔너리 이관·ADR 0001 적용 구조는 게이트 PASS했지만, 한국어 리뷰가
`d.combine.*` 문구 표현과 표기 규칙에서 문제를 지적했다. 그중 **포인트 표기(§3, 천 단위
콤마 누락)는 단순 톤 문제가 아니라 가이드 위반이 코드로 그대로 노출되는 결함**이라 우선순위가
높다.

## 상세 요구사항 — `jam-web/src/lib/i18n/ko.ts`의 `d.combine`/`d.common` 값·포맷팅 수정

### (a) 포인트 표기(§3) — 우선 처리
`consolationPoints`가 `+{points} 포인트`를 raw 숫자로 그대로 보간한다. §3은 "1,200 포인트"
(천 단위 콤마)를 요구한다. 값을 채우는 호출부에서 `points.toLocaleString()` 등으로 콤마
포맷을 적용한 뒤 템플릿에 넘기도록 고친다. 문구도 "실패 보상"이라는 공급자 언어를
정리: **"그래도 {points} 포인트가 남았어요"**

### (b) 에러 3단계 구조(§4.1) 미충족
- `itemsNotFound`: 원인이 빠져 있다 → "선택한 아이템이 인벤토리에 없어요. 믹스하는 사이에
  다른 곳에서 쓰였을 수 있어요. 목록을 다시 불러온 뒤 골라 주세요."
- `genericError`/`genericFail`: 둘 다 현상뿐이고 역할이 겹친다. 하나로 통합하거나
  `genericFail` 쪽은 서버 `message`를 그대로 쓰는 경로로 정리한다 →
  "지금은 믹스할 수 없어요. 조금 뒤에 다시 해주세요."

### (c) 마침표 규칙(§3)
`itemsNotFound`, `genericError`는 두 문장인데 마침표가 없다 — (b) 교정과 함께 마침표를 채운다.

### (d) 용어 일관성(§1.3)
- `authRequired`의 "인증" 문제는 **티켓 20260916_0904(`d.common.authRequired` 공용 문구
  전면 교정)로 이관됨** — 이 티켓에서는 중복 수정하지 않는다.
- "재료"(`recipeFail`)는 §1.2 예시문에 이미 있으므로 §1.3 용어표에 정식 등재
- "보상"(`consolationPoints`)은 용어표 미등재 — (a) 교정으로 문구 자체에서 제거되므로
  별도 등재 불필요

### (e) 그 외 어색한 표현
- `genericFail`("오류가 발생했어요"): 시스템 시점 → "믹스가 안 됐어요. 다시 한 번 눌러
  주세요." (단, (b)에서 genericError와 통합 검토)
- `emptyInventory`: "인벤토리가 비어 있어요" → "아직 가진 아이템이 없어요" (경미, §4.3
  빈 상태 톤과 더 잘 맞음)

## 구현 계획
- `ko.ts`의 해당 키 값만 수정하고, (a)는 값을 채우는 호출부(`CombineClient.tsx` 또는
  `api/combine/route.ts`)의 포맷팅 로직도 함께 고친다.
- `authRequired` 중복 수정 방지를 위해 20260916_0734·0750과 처리 순서를 조율한다.
- 완료 후 `/im-not-ai`로 교체된 문구를 재검사한다.

- (a) `consolationPoints`를 "그래도 {points} 포인트가 남았어요."로 교정하고, `api/combine/route.ts`에서
  `result.pointsAwarded.toLocaleString()`으로 천 단위 콤마를 적용한 뒤 템플릿에 넘기도록 수정.
  또한 앞 문장(재료 소각/아이템 없음 등)과 이어붙일 때 마침표가 중복되거나 누락되지 않도록
  `message.replace(/[.]+$/, '')`로 기존 끝 마침표를 정리한 뒤 `'. '`로 이어붙이는 로직을 추가.
  (기존에는 `+{points} 포인트` raw 숫자를 괄호로 덧붙이는 "실패 보상" 공급자 언어였음)

  다시 불러온 뒤 골라 주세요." `genericError`(클라이언트 fetch 예외 전용)와 `genericFail`

  나중에 재시도), genericFail="믹스가 안 됐어요. 다시 한 번 눌러 주세요."(서버는 응답했으니

### 주요 의사결정 / 핵심 메모
- consolationPoints 문구 자체에는 마침표를 미리 넣지 않고(단독으로는 안 쓰이므로), route.ts가
  선행 문장과 결합할 때 동적으로 마침표를 채우는 방식을 택함 — recipeFail(단일 문장, 마침표
  없음)과 itemsNotFound(다문장, 마침표 있음) 두 경로 모두에서 결합 후 정확히 두 문장·마침표
  구조가 되도록 하기 위함. ko.ts에 고정 텍스트로 마침표를 박아두면 recipeFail처럼 단독으로
  쓰일 때 §3 "단일 문장은 마침표 없음" 규칙과 충돌하는 문제가 있어 이 방식을 선택.
- genericError/genericFail은 "하나로 통합" 대신 "명확히 구분"을 선택 — 실제로 트리거 조건이
  다르므로(네트워크 미도달 vs 서버 응답했으나 사유 미매핑) 통합 시 재시도 안내 타이밍이
  달라져야 하는데 한 문구로는 표현 불가.

### 잔여 이슈
- 브라우저 실렌더 확인은 staging 병합 후 필요 (로컬 워크트리 `next dev`/`build` 제약).
- 한국어 리뷰 지적(정책상 미반영, 기록만): `consolationPoints`가 한 문장인데 마침표가
  남아 있음(§3 위반), `genericError`/`genericFail`의 원인 누락, "믹스하는 사이에 ~쓰였을
  수 있어요"의 피동 표현, `emptyInventory`의 §1.3 "획득" 고정 용어 재검토 등. 필요시
  별도 검토.
