# [Content] 인벤토리 도메인 문구 톤 및 용어 정비

> 상위 스펙: [`20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md`](../P1-중요/20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md)
> 출처: 티켓 20260915_2243(인벤토리 도메인 텍스트 정비) 한국어 리뷰에서 나온 제안 — 게이트는 PASS했으나 병합 전 반영하지 않고 이 후속 티켓으로 분리(사용자 결정, 2026-09-16)

## 배경 / 문제 정의

티켓 20260915_2243의 딕셔너리 이관 구조는 게이트 PASS했지만, 한국어 리뷰가 신규 작성된
`d.inventory.*` 문구에서 고정 용어 위반(§1.3 "꽉 찼어요" 대신 "가득 찼어요" 사용, 드랍의
이중 의미 충돌), 에러 3단계 구조 미충족, 표기 규칙 위반을 지적했다.

## 상세 요구사항 — `jam-web/src/lib/i18n/ko.ts`의 `d.inventory` 값 수정

### (a) 고정 용어 위반(§1.3) — 최우선
- `fullNoticeBody`의 "가득 찼어요"는 §1.3·§4.1이 이미 고정한 "꽉 찼어요"와 다른 표현이다 →
  "꽉 찼어요"로 통일
- 같은 문구 안에서 "드랍"이 두 뜻(시스템이 아이템을 떨어뜨림 vs 유저가 아이템을 드랍하는
  행위)으로 섞여 §1.3 드랍 정의와 충돌한다 → "새 아이템 배지가 드랍되지 않아요"를
  "새 아이템 배지를 받을 수 없어요"로 교체해 시스템 동작에는 "드랍"을 쓰지 않는다

### (b) 에러 3단계 구조(§4.1) 미충족
- `fullNoticeBody`: 원인 자리에 [결과]가 들어가 있다 — 구체 수치(보관 한도)로 교체:
  "인벤토리가 꽉 찼어요. {max}개까지만 보관할 수 있어서, 지금 활동을 동기화해도 새 아이템
  배지를 받을 수 없어요. 아이템을 드랍해 자리를 비워 주세요." (단, `{max}`가 이 문구에서
  실제로 참조 가능한지 먼저 확인 — 불가하면 "인벤토리에 자리가 없어서"로 대체)
- `fetchFailed`/`historyItemNotFound`/`historyForbidden`: 원인이 빠져 있다 →
  - `fetchFailed`: "인벤토리를 불러오지 못했어요. 연결이 잠깐 끊겼을 수 있어요." + CTA
    `[다시 불러오기]`
  - `historyItemNotFound`: "이 아이템을 더 이상 볼 수 없어요. 만료됐거나 다른 유저에게
    갔을 수 있어요." + CTA `[인벤토리로 가기]`
  - `historyForbidden`: "이 아이템의 기록은 주인만 볼 수 있어요"

### (c) 용어 일관성 — "기록"/"이력" 혼용
`historyEmptyBody`는 "기록", `historyForbidden`은 "이력"을 쓴다 — §1.3에 없는 개념이면
먼저 등재하고 하나로 고정한다("기록" 권장, 다른 문구들과의 일관성).

### (d) 표기 규칙(§3)
- `fetchFailed`: 두 문장인데 끝 마침표 없음 → 마침표 추가(위 (b) 교정과 함께 처리)
- `fullNoticeBody`: "비워보세요" → "비워 주세요"(보조용언 띄어쓰기)
- `slotsDetail`의 `{used} / {max}`: 슬래시 앞뒤 공백 제거(가이드 표기 예시 "휴식 2/5일"·
  "Lv.3"과 통일) → `{used}/{max}개 사용 중 · {remaining}개 남음` (또는 중복 정보 제거해
  `{used}/{max}개 사용 중`만 남기는 것도 검토)

### (e) 그 외 어색한 표현
- `historyItemNotFound`("이 아이템을 찾을 수 없어요")는 위 (b)에서 교정
- "잠시 후 다시 시도해 주세요" 등 정형구는 다른 도메인 후속 티켓과 동일하게, 원인을 아는
  경우 구체화하고 정말 모르는 경우에만 남긴다

## 구현 계획
- `ko.ts`의 해당 키 값만 수정한다.
- `fullNoticeBody`가 실제로 어떤 버튼(드랍/드랍하기)과 짝을 이루는지, `{max}` 변수를 이
  문구에서 참조할 수 있는지 코드에서 먼저 확인한다.
- 완료 후 `/im-not-ai`로 재검사한다.

### 구현 내용 요약
- `jam-web/src/lib/i18n/ko.ts`의 `d.inventory` 6개 키를 (a)~(d) 지시대로 교정했다.
- `fullNoticeBody`에 `{max}` 변수를 추가했다 — 호출부(`inventory/page.tsx`)에서 이미
  `maxSlots`가 스코프에 있는 것을 확인하고, 기존 `{d.inventory.fullNoticeBody}` 직접 렌더를
  `t(d.inventory.fullNoticeBody, { max: maxSlots })`로 바꿔 실제로 참조 가능하게 했다.
  (b)의 "불가하면 대체 문구" 분기는 발동하지 않았다.
- `fetchFailed`/`historyItemNotFound`의 CTA(`[다시 불러오기]`/`[인벤토리로 가기]`)는 추가하지
  않았다 — 실제 소비처(`InventoryItemHistorySheet.tsx`)가 에러를 `<p>` 텍스트로만 렌더하고
  버튼을 지원하지 않아, 지시대로 "문구만 완성"했다.
- `historyForbidden`을 "기록"으로 통일했고, `historyEmptyBody`/`historyEmpty`(제목, 티켓
  범위 밖) 등 다른 "이력" 표기는 (c)가 명시적으로 지목한 두 키만 대상으로 삼아 건드리지 않았다.

### 주요 의사결정 / 핵심 메모
- `{max}` 참조 가능 여부는 (b)가 조건부로 명시했으므로 우회 문구를 미리 준비하지 않고
  코드부터 확인했다 — `maxSlots`가 이미 같은 컴포넌트 스코프에 있어 대체 문구
  ("인벤토리에 자리가 없어서")는 사용하지 않았다.
- CTA 라벨 2건은 실제 렌더 경로에 버튼이 없어 추가하지 않았다. 추후 히스토리 시트에
  재시도/이동 버튼을 붙일 계획이 생기면 이 라벨을 그대로 쓸 수 있다.
- `historyEmpty`("이력이 없어요")는 (c)가 지목한 두 키(`historyEmptyBody`/`historyForbidden`)
  범위 밖이라 이번 티켓에서는 건드리지 않았다 — 아래 alerts 참조.

### 잔여 이슈
- `d.inventory.fetchFailed`가 실제로 노출되는 경로가 없어(PoiCarouselModal.tsx가 서버
  error를 무시) 별도 태스크로 분리해 확인 중(칩으로 표시됨).
- `historyEmpty`("이력이 없어요")와 `historyEmptyBody`("기록이 없어요")의 용어 혼용은
  이번 범위 밖으로 남김.
- 한국어 리뷰 지적(정책상 미반영, 기록만): "받을 수 없어요"를 §1.3 "획득"으로,
  "유저"를 "다른 사람"으로, "만료"를 사용자 언어로, "주인"을 용어표 미등재 상태로 지적.
  필요시 별도 검토.
