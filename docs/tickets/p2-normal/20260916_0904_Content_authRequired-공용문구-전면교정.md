## 배경 / 문제 정의

`d.common.authRequired`("인증이 필요해요")가 여러 도메인 티켓의 API route에서 공용으로
재사용되면서, 한국어 리뷰가 각 티켓마다 독립적으로 같은 문제를 지적했다 — "인증"이 §1.3
체크인 행의 금지어 목록과 겹치고, "~이 필요해요"는 상태만 통보할 뿐 사용자가 할 행동을
말하지 않는다. 개별 도메인 티켓에서 각자 고치면 값이 갈라질 위험이 있어, 이 키 하나를
전면적으로 한 번에 교정하는 것으로 합친다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/lib/i18n/ko.ts`의 `d.common.authRequired` 값을 교정한다.
  - 대안: **"로그인이 필요해요. 다시 로그인해 주세요"**
  - 세션 만료와 최초 미로그인을 구분할 수 있는 지점이면 "로그인이 풀렸어요. 다시 로그인해
    주세요"(세션 만료)와 구분 검토 — 단, 지금처럼 여러 도메인이 401을 뭉뚱그려 반환하는
    구조라면 무리하지 말고 공용 문구 하나로 유지
- 이 키를 참조하는 모든 API route(현재 배지·아이템북·조합·알림 도메인 + 인벤토리 등)에
  영향을 주므로, 값 교정 후 각 도메인 화면에서 401 응답이 실제로 이 문구를 그대로
  노출하는지(ADR 0001) 최소 1곳 이상 실렌더로 확인한다.

### UX Writing 검증
- §1.3 금지어("인증") 제거 확인
- §1.2 사용자 시점(로그인은 사용자가 하는 행동) 확인

## 구현 계획
- `ko.ts`의 값 하나만 수정하면 모든 참조처에 일괄 반영된다(단일 진실 소스의 장점).
- 완료 후 아래 티켓들의 "authRequired 중복 수정 방지" 메모를 정리(이 티켓으로 이관됨을 표시).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`d.common.authRequired` 값을 `'인증이 필요해요'`에서 `'로그인이 필요해요. 다시 로그인해
주세요'`로 교정했다(제안 3안 채택). 단일 진실 소스라 값 하나만 고쳐 배지·컬렉션/아이템북·
조합·알림·인벤토리·미션·포인트·프로필·검색·VOC 등 이 키를 참조하는 모든 API route(총 20곳,
`route.ts` 기준)에 일괄 반영됐다.

검증은 `collections/[id]/SlotGrid.tsx`(아이템북 슬롯 장착/교체/해제) 경로로 코드 대조했다.
`requestSlot`/`requestSwap`/`requestUnslot`이 `/api/itembooks/[id]/slot`을 호출하고, 응답이
`!res.ok`이면 `data.error ?? d.itembooks.slotFailed`로 화면에 표시한다 — 서버가 401과 함께
`{ error: d.common.authRequired }`를 내려주면(`route.ts` 55·60·100·104·141·145행) `data.error`가
그 문자열 그대로 참이 되어 폴백 없이 화면에 노출된다. ADR 0001("서버가 완성한 문구를
그대로 신뢰해 노출")대로 클라이언트가 별도 가공 없이 서버 문구를 표시하는 것을 코드로
확인했다. 참고로 `notifications` 도메인은 서버 에러 문구를 직접 노출하지 않고 고정
`errorTitle`/`errorBody`를 쓰는 별개 패턴이라 이번 검증 대상에서 제외했다.

`ko.ts`의 주석도 이 값이 여러 도메인 공용 단일 진실 소스임을 명시하도록 보강했다.
