# [Content] 소셜 도메인 문구 톤 정비 및 SEO 타이틀 구분자 통일

> 상위 스펙: [`20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md`](../P1-중요/20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md)
> 출처: 티켓 20260915_2249(소셜/팔로우 도메인 텍스트 정비) 한국어 리뷰에서 나온 제안 — 게이트는 재작업 후 PASS했으나 병합 전 반영하지 않고 이 후속 티켓으로 분리(사용자 결정, 2026-09-16)

## 배경 / 문제 정의

티켓 20260915_2249은 게이트 1차 FAIL(SEO 타이틀 엠대시 §7.3 위반 오판 + 완료 기록 자기모순)
후 엠대시를 파이프(`|`)로 교체해 재시도, 2차 PASS했다. 하지만 재검토 결과 §7.3의 엠대시
금지는 **"유저가 읽는 화면 문구"**에만 적용되고 SEO 메타데이터(§2.5)는 대상이 아니다 —
`notifications/page.tsx`가 이미 같은 자리에 엠대시를 쓰고 있어, 이번에 소셜 도메인만
파이프로 바꾸면 오히려 서비스 안에서 구분자가 갈리는 새 불일치가 생긴다. 그 외에도 한국어
리뷰가 "언팔로우"가 §1.3 용어표에 없는 임의 용어라는 점, 에러 문구의 번역투를 지적했다.

## 상세 요구사항

### (a) SEO 타이틀 구분자 통일 — 최우선
`d.social.profileTitle`(`{username} | JAM!`)을 다른 화면과 통일한다. 두 가지 선택지 중
하나로 결정하고 전체를 맞춘다:
1. **엠대시로 통일**(기존 `notifications/page.tsx` 관례를 따름) — `{username} — JAM!`,
   `notifications/page.tsx`는 그대로 둠
2. **파이프로 통일**(이번 티켓에서 새로 정한 형태를 표준으로 승격) — `notifications/page.tsx`도
   함께 `{title} | JAM!`로 변경

어느 쪽이든 `app/layout.tsx`(공용 SEO 컴포넌트 기본 골거리 경로 20260915_2237에서 편입)와도
일관되는지 확인한다.

### (b) "언팔로우" 미등재 용어(§1.3) — 선행 필요
현재 화면 어디에도 "언팔로우"라는 말이 노출되지 않는다(버튼은 `팔로잉`↔`팔로우` 토글). 새
에러 문구에서 이 개념을 가리킬 고정 표현을 `UX_WRITING_GUIDELINE.md` §1.3에 등재한 뒤 값을
교정한다: 후보 "팔로우 해제"(X: 언팔로우, 언팔, 팔로우 끊기).
- `unfollowError` → "팔로우 해제가 안 됐어요. 잠시 뒤에 다시 눌러 주세요."

### (c) 번역투·정형구 교정
- `selfFollowError`("자기 자신은 팔로우할 수 없어요") → "나를 팔로우할 수는 없어요"
- `followError`("지금은 팔로우할 수 없어요. 잠시 후 다시 시도해 주세요.") → "팔로우가 안
  됐어요. 잠시 뒤에 다시 눌러 주세요." (팔로우/해제 두 문구의 뒷부분을 동일하게 맞춰 한쪽만
  고쳐지는 갈라짐 방지)
- `userNotFound`("이 유저를 찾을 수 없어요") → "찾는 프로필이 없어요" (지시관형사 "이" 제거,
  "유저"를 화면 언어 "프로필"로 교체)

## 구현 계획
1. (a) 구분자 방향을 먼저 결정(엠대시 유지 권장 — 변경 파일이 이번 티켓 것 하나뿐이라 되돌리는
   비용이 가장 낮음)한다.
2. (b) 용어표 등재 후 (c)까지 `ko.ts` 값을 함께 교정한다.
3. 완료 후 `/im-not-ai`로 재검사한다.

### 구현 내용 요약
- (a) `d.social.profileTitle`을 엠대시로 통일(`{username} — JAM!`), 티켓 권고안대로
  `notifications/page.tsx`는 그대로 두고 이번 티켓 파일 하나만 되돌린다. `app/layout.tsx`는
  구분자 없는 단독 타이틀(`JAM!`)이라 비교 대상 자체가 없음을 확인.
- (b) `UX_WRITING_GUIDELINE.md` §1.3에 "팔로우 해제" 용어 신규 등재(X: 언팔로우, 언팔,
  팔로우 끊기) 후 `unfollowError` 값을 티켓 지정 문구로 교정.
- (c) `selfFollowError`·`followError`·`userNotFound` 3개 값을 티켓 지정 문구로 교정.
  `followError`/`unfollowError`는 뒷부분("잠시 뒤에 다시 눌러 주세요.")을 동일하게 맞춤.

### 주요 의사결정 / 핵심 메모
- (a) 엠대시 vs 파이프 중 **엠대시로 통일**을 선택했다 — 이번 티켓에서 변경하는 파일이
  `ko.ts` 한 곳뿐이라 되돌리는 비용이 가장 낮고, `notifications/page.tsx`가 이미 이 관례를
  쓰고 있어 기존 코드를 건드리지 않고 일관성을 회복할 수 있다. `app/layout.tsx`는 구분자
  없는 단독 타이틀이라 이번 결정과 직접 비교되지 않음을 확인했다.
- §7.3의 엠대시 금지는 "유저가 읽는 화면 문구" 대상이고 SEO 메타데이터는 §2.5로 별도
  예외라는 점을 §7.3·§7.4 원문으로 재확인했다 — 티켓 20260915_2249 1차 게이트가 이 부분을
  오판했던 것이 이번 후속 티켓의 발단이다.

**한국어 리뷰 반영 — 병합 전 추가 커밋**: 한국어 리뷰가 "팔로우 해제"가 §1.3 「해제
(UNEQUIP)」(장착의 반대 행위, 티켓 20260916_0825에서 이미 전 도메인 고정 용어로 등재됨)와
충돌한다고 지적했다 — 스타일이 아니라 실제 용어 중복이라 즉시 반영. 대안으로 "팔로우
취소"를 제안했으나 사용자가 "언팔로우"로 확정해 그대로 적용했다. 그 외 지적(에러 3단계
구조 원인 보강, "다시 눌러 주세요"→"다시 시도해 주세요" 등)은 정책상 기록만 남긴다.
