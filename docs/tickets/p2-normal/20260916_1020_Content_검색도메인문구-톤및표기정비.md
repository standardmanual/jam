# [Content] 검색 도메인 문구 톤 및 표기 정비

## 배경 / 문제 정의

티켓 20260915_2250의 딕셔너리 이관 구조는 게이트 PASS했지만, 한국어 리뷰가 신설 문구
`searchFailed`의 시스템 시점·정형구, `emptyTitle`의 자리표시자 표기(`{query}` vs 가이드
규정 `{검색어}`), `promptBody`의 수치 표기 불일치를 지적했다.

## 상세 요구사항 — `jam-web/src/lib/i18n/ko.ts`의 `d.search` 값 수정

### (a) `searchFailed` — 최우선
"유저 검색에 실패했어요. 잠시 후 다시 시도해 주세요."는 시스템 시점("~에 실패했어요")과
정형구("잠시 후 다시 시도해 주세요")가 겹치고, §4.1 3단계 중 [원인]이 빠졌다.
→ "검색이 안 됐어요. 네트워크 연결이 불안정할 수 있어요." (인라인 재시도 버튼이 있으면
CTA `[다시 검색하기]` 추가)

### (b) `emptyTitle` 자리표시자 표기 — §4.3 규정과 실제 코드의 불일치
가이드 §1.2·§4.3은 사용자 입력값 자리표시자를 **`{검색어}`(한글)**로 명시 고정했는데, 실제
`ko.ts`의 보간 키는 `query`(영문)다. 문서와 코드 중 하나를 정합시켜야 한다 — 다음 중 택1:
1. 딕셔너리 문구 원문을 `"{검색어}" 검색 결과가 없어요`로 표기하되 런타임 키는 그대로
   `query`로 유지(문서 표기와 코드 키 이름이 다를 수 있음을 명확히 함)
2. `UX_WRITING_GUIDELINE.md` §4.3에 "코드 보간 키는 예외로 영문을 쓸 수 있다"는 단서를
   한 줄 추가해 현재 상태를 정당화

### (c) `promptBody` 수치 표기 불일치
"두 글자 이상 입력해 주세요"의 "두 글자"(한글 수사)가 다른 곳의 아라비아 숫자 표기(§3, §4.2
"2자에서 12자까지")와 갈린다 → "2자 이상 입력해 주세요"

## 구현 계획
- `ko.ts`의 해당 키 값만 수정한다.
- (b)는 가이드 문서 수정 또는 딕셔너리 표기 변경 중 하나를 택해 반영한다.
- 완료 후 `/im-not-ai`로 재검사한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- (a) `searchFailed`: '유저 검색에 실패했어요. 잠시 후 다시 시도해 주세요.' →
  '검색이 안 됐어요. 네트워크 연결이 불안정할 수 있어요.' 이 문구를 소비하는 곳은
  `api/users/search/route.ts`의 500 에러 응답뿐이며, 이를 렌더링하는 클라이언트 쪽에
  인라인 재시도 버튼이 없어(검색 페이지는 서버 컴포넌트로, 이 에러 응답 자체를 아직
  화면에 연결해 쓰지 않는 상태) CTA `[다시 검색하기]`는 추가하지 않았다.
- (b) `emptyTitle`: 실제 코드 표기(`"{query}" 검색 결과가 없어요`)는 §4.3 가이드가 규정한
  최종 문구 형태와 이미 일치한다(따옴표로 감싼 검색어 인용). 문제는 보간 키 이름 자체가
  `query`(영문)인 점 — 코드를 확인해보니 `t()` 함수(`lib/i18n/index.ts`)가
  `/\{(\w+)\}/g` 정규식으로 치환 대상을 찾는데, JS의 `\w`는 ASCII 단어문자만 매칭하고
  한글은 매칭하지 않는다. 따라서 템플릿과 보간 객체 키를 `{검색어}`/`검색어: q`로 바꾸면
  치환 자체가 깨진다(리터럴 `{검색어}`가 화면에 그대로 노출됨). 이 정규식을 유니코드
  대응으로 고치는 것은 `ko.ts` 범위를 벗어나는 코드 변경이라 이번 티켓에서는 택하지
  않았다 — 대신 **문서 쪽(옵션 2)**을 택해 `UX_WRITING_GUIDELINE.md` §4.3에 "문서 표기는
  사용자에게 보이는 최종 문구 형태를 설명하는 것이고, 코드 보간 키 이름까지 한글로 맞출
  필요는 없다"는 단서를 추가했다. `ko.ts`의 `emptyTitle` 값 자체는 변경하지 않고, 표기
  근거를 설명하는 주석만 보강했다.
- (c) `promptBody`: '두 글자 이상 입력해 주세요' → '2자 이상 입력해 주세요' (아라비아 숫자
  통일, §3·§4.2와 정합).
- 코드베이스 내 유사 확립 표현 확인: "네트워크 연결이 불안정" 문구는 기존에 쓰인 적 없어
  신규 도입. "두 글자 이상"/"유저 검색에 실패" 문자열은 다른 곳에서 재사용되지 않아
  누락 없이 교체됐다(grep 확인 완료).

### 주요 의사결정 / 핵심 메모
- (b) 옵션 1(런타임 보간 키를 한글 `검색어`로 변경)은 `t()`의 `\w` 정규식이 한글을
  매칭하지 않아 채택 시 화면에 `{검색어}` 리터럴이 그대로 노출되는 회귀를 유발한다.
  정규식을 유니코드 대응으로 바꾸는 건 `ko.ts` 범위를 넘는 코드 변경이자 `t()`를 쓰는
  모든 호출부에 영향을 주는 더 큰 변경이라, 이번 티켓 범위에서는 옵션 2(문서에 단서 추가)를
  택했다. 필요하다면 `t()` 정규식의 유니코드 지원은 별도 티켓으로 분리할 만하다.
- `searchFailed`에 CTA를 추가하지 않은 이유: 이 문구를 실제로 렌더링하는 인라인 재시도
  버튼이 현재 UI에 없다(검색 페이지는 서버 컴포넌트로 직접 이 API를 fetch하지 않음).
  향후 클라이언트 검색 UI가 이 에러를 표시하게 되면 그때 CTA 추가를 검토한다.

### 잔여 이슈
- `t()` 함수의 보간 정규식이 ASCII 단어문자만 지원해 한글 보간 키를 쓸 수 없다는 구조적
  제약은 별도 태스크로 분리해 확인 중이다(칩으로 표시됨).

**한국어 리뷰 반영 — 병합 전 추가 커밋**: 한국어 리뷰가 `searchFailed`의 새 원인 문구
("네트워크 연결이 불안정할 수 있어요")가 사실과 다르다고 지적했다 — 500 응답이 오는
시점엔 이미 네트워크가 연결돼 있으므로 실제 원인은 서버 쪽 조회 실패이며, 기존 코드
주석이 이미 "구체적 원인은 로그에만 남긴다"고 결정해둔 것과도 어긋났다. 스타일이 아니라
잘못된 정보 전달이라 판단해 원래 정형구로 되돌리되 "실패했어요"만 "안 됐어요"로 다듬었다.
`promptBody`의 아라비아 숫자 표기 지적은 정책상 기록만 남긴다.
