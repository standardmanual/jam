# [Content] VOC 도메인 문구 톤 정비

> 상위 스펙: [`20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md`](../P1-중요/20260915_2227_Service_사용자노출텍스트-톤앤매너통합정비-스펙.md)
> 출처: 티켓 20260915_2251(VOC 도메인 텍스트 정비) 한국어 리뷰에서 나온 제안 — 게이트는 PASS했으나 병합 전 반영하지 않고 이 후속 티켓으로 분리(사용자 결정, 2026-09-16)
> 참고: `d.common.authRequired` 자체 값 교정은 티켓 20260916_0904로 통합됐다 — 이 티켓 범위에서 제외. TopNav title(§6 정책) 사항은 별도 태스크로 분리됨.

## 배경 / 문제 정의

티켓 20260915_2251의 딕셔너리 이관 구조는 게이트 PASS했지만, 한국어 리뷰가 `loadError`
(구 `loadFailed`)의 §4.1 3단계 미충족·정형구, `emptyBody`의 UI 조작 지시형 문장, 기존
`emptyTitle`의 수동태를 지적했다.

## 상세 요구사항 — `jam-web/src/lib/i18n/ko.ts`의 `d.voc` 값 수정

### (a) `loadError` — §4.1 3단계 구조 미충족 (최우선)
현재("문의 내역을 불러오지 못했어요. 잠시 후 다시 시도해 주세요.")는 현상만 있고 원인이
없으며, 해결책도 CTA가 아니라 서술문이다.
→ "문의 내역을 불러오지 못했어요. 네트워크 연결이 불안정할 수 있어요." + 가능하면 CTA
버튼 `[다시 불러오기]`로 해결책 분리(§5.1 동사형)

### (b) `emptyBody` — UI 조작 지시형 문장
"문의하기 버튼을 눌러 첫 문의를 남겨 보세요"는 화면에 이미 보이는 버튼을 문장으로 다시
지시하는 매뉴얼식 표현이다(§2.2 Bad 예시와 동일 구조).
→ "궁금한 점이 생기면 언제든 문의해 주세요" (버튼 조작 지시 제거, 첫 문의임을 살리고
싶다면 "첫 문의를 남겨 보세요"로 조작 절차만 뗀 형태도 검토)

### (c) `emptyTitle` — 수동태(시스템 시점), 이번 티켓 대상 아니었으나 (b)와 세트로 처리 권장
"아직 등록된 문의가 없어요"의 "등록된"은 시스템이 처리하는 관점이다.
→ "아직 남긴 문의가 없어요" (사용자 시점 능동)

## 구현 계획
- `ko.ts`의 해당 키 값만 수정한다.
- (a)의 CTA 버튼 추가가 필요하면 `voc/page.tsx`의 에러 뷰 구조도 함께 확인한다.
- 완료 후 `/im-not-ai`로 재검사한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- **(a) `loadFailed`(구 `loadError`) — 원인 문구는 추가하지 않았다.** 이 티켓의 요청 문서(§(a))는
  "네트워크 연결이 불안정할 수 있어요"를 제안했지만, 구현 전 실제 코드
  (`jam-web/src/app/api/voc/route.ts`)를 확인한 결과 이 메시지가 발생하는 유일한 경로는
  서버가 Google Sheets API(`fetchSheetValues`)를 호출하다 실패해 502를 반환하는 경우뿐이다.
  클라이언트 네트워크 문제가 아니라 서버 쪽 문제이므로 "네트워크 연결이 불안정할 수 있어요"는
  잘못된 원인 안내가 된다 — 검색 도메인 후속 티켓(20260916_1020)에서 동일한 실수(`searchFailed`에
  근거 없는 원인 문구를 붙였다가 한국어 리뷰가 발견해 되돌린 사례, 커밋 `5c86cbd8`)가 있어
  반복하지 않았다. `loadFailed` 문자열 자체는 이미 다른 병렬 티켓(ADR 0001, 20260915_2251)이
  원인 미표기 정형구로 정리해 둔 상태였고 그대로 유지했다.
- **(a) CTA 버튼**: `voc/page.tsx`의 에러 분기는 MODULAR `EmptyState`
  (`design-system/components/feedback/EmptyState.jsx`)를 쓰고, 이 컴포넌트는 이미
  `action: { label, onClick }` prop을 지원한다(`src/app/error.tsx`,
  `NotificationsClient.tsx`와 동일 패턴). 신규 컴포넌트 없이 `action`을 추가해 "다시 불러오기"
  버튼을 붙였다. 클릭 시 `error`/`data`를 초기화하고 `retryKey`를 증가시켜 조회 이펙트를
  재실행한다. 라벨은 최초 구현 시 이 티켓이 명시한 "다시 불러오기"(`d.voc.reload`)로
  채택했으나, 한국어 리뷰가 `UX_WRITING_GUIDELINE.md` §1.3 「새로고침」 항목의 X리스트
  (금지어: 리프레시, 갱신, 재조회, **다시 불러오기**)에 정확히 걸린다고 지적해 병합 전
  `d.voc.retry`(값 "다시 시도")로 고쳤다. 같은 절이 "새로고침(화면 데이터 재조회) vs
  다시 시도(방금 실패한 액션 재실행)"를 구분하는데, 이 버튼은 방금 실패한 조회 자체를
  재실행하는 동작이라 후자가 맞고, 코드베이스 기존 관용구(`points.retry`,
  `notifications.retry`)와도 일치한다.
- **(b) `emptyBody`**: `'문의하기 버튼을 눌러 첫 문의를 남겨 보세요'` →
  `'궁금한 점이 생기면 언제든 문의해 주세요'` (버튼 조작 지시 제거)
- **(c) `emptyTitle`**: `'아직 등록된 문의가 없어요'` → `'아직 남긴 문의가 없어요'`
  (사용자 시점 능동)

### 주요 의사결정 / 핵심 메모
- **원인 문구를 추가하지 않기로 한 결정**: `api/voc/route.ts`의 에러 경로는 서버가 Google
  Sheets API를 호출하는 과정의 실패뿐이며 사용자 기기의 네트워크 문제가 아니다. 이 티켓
  문서(§(a))가 제안한 "네트워크 연결이 불안정할 수 있어요"는 실제 원인과 다르므로 채택하지
  않았고, [현상]→[해결책] 2단계 구조로 마무리했다. §4.1의 3단계 구조를 기계적으로 채우는 것보다
  정확한 정보 전달을 우선했다.
- **병렬 세션 충돌 처리**: 이 워크트리는 origin/staging에 이미 존재하던 본 티켓 파일보다
  오래된 커밋에서 분기되어, 구현 착수 시점에 로컬에 이 티켓 파일이 없어 별도로 새로 작성했다.
  `git fetch` 후 origin/staging의 실제 최신 상태(ADR 0001 적용, `loadError`→`loadFailed`
  키 변경, `error` state가 서버 완성 문구를 그대로 담는 구조로 전환됨— 티켓 20260915_2251,
  20260915_2252, 20260916_0904)를 확인하고 그 위에 맞춰 재작업했다. 최초 커밋(로컬 임시)은
  버리고 origin/staging 기준으로 다시 구현했다.

**한국어 리뷰 반영 — 병합 전 추가 커밋**: 한국어 리뷰가 `reload: '다시 불러오기'`가
§1.3 「새로고침」 항목의 금지어를 직접 위반한다고 지적했다 — 스타일이 아니라 용어표와의
실제 충돌이라 즉시 반영, `d.voc.retry`(값 "다시 시도")로 교정했다(`voc/page.tsx` 호출부도
함께 수정). 그 외 지적("궁금한 점이 생기면 언제든" 상투구, "남긴 문의"의 어휘 미스매치,
§1.3 표에 '문의' 용어 미등재)은 정책상(1회만 반영 정책) 이 기록에만 남기고 추가 수정은
하지 않는다.

### 잔여 이슈
- §1.3 용어표에 '문의(VOC)' 행이 아직 없다는 한국어 리뷰 지적은 반영하지 않았다. 필요하면
  별도 문서 정비 작업에서 다룬다.
