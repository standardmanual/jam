# [Content] 배지 이미지 픽셀 크기 일률성 전수 조사

## 배경 / 문제 정의
> 왜 이 작업이 필요한가. 현재 상태와 기대 상태의 차이.

사용자가 "배지 이미지들의 크기가 일률적인지 확인해달라"고 요청. 코드 변경 없는 조사
(`research` 유형)로 진행. `badges` 테이블 전체(3,386건)의 `image_url`을 출처별로 나눠
실제 픽셀 크기를 확인했다.

## 상세 요구사항

### 컨텐츠 관점
- 로컬 정적 파일(`jam-web/public/badges/`)과 Supabase Storage 원격 업로드 파일을 모두
  포함해 픽셀 크기 분포를 확인한다.

## 구현 계획
> 어떻게 구현할지. 접근 방법, 영향 범위, 주요 변경 포인트.

Supabase MCP로 `image_url` 출처별 건수를 집계 → 로컬 파일은 PNG 헤더를 직접 파싱해 전수
검사 → 원격 파일은 대표 샘플을 다운로드해 검사. 코드 변경 없음.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**결론: 일률적이지 않다.** 출처별로 상황이 크게 다르다.

| 출처 | 파일 수 | 크기 | 비고 |
|---|---|---|---|
| `public/badges/poi/{mountain,metro,michelin,transit}` | 2,793개 | **256×256 균일** | 예외 1개(156×156) |
| `public/badges/activity` | 147개 | **400×400 균일** | 예외 1개(600×600) |
| `public/badges/sample` (common 등급 배지 다수가 참조) | 372개 | **완전 불균일** — 102~1047px, 341개(92%)가 정사각형도 아님 | DB에서 495건이 이 폴더를 참조 |
| Supabase Storage 원격 업로드(`factions/item`, `activity`, `shader-lab`, 어드민 직접 업로드) | 427건(DB 기준) | **파일마다 제각각** — 샘플 18개 확인 결과 913~1555px 사이 6가지 크기, 그중 2개는 정사각형도 아님(1075×1080) | 배지 이미지 제작 파이프라인(Recraft 생성 원본)이 리사이즈 없이 그대로 저장된 것으로 보임 |
| `public/badges/` 최상위 100개(`002.png` 등) | 100개 | 512×512 균일 | **현재 어떤 배지 레코드에서도 참조되지 않는 죽은 자산** — DB 조회 결과 0건 매칭 |

가장 큰 비중(poi 2,793개 + activity 147개 = 2,940개, 전체의 87%)은 각 카테고리 안에서
크기가 통일돼 있다. 문제는 두 곳:

1. **`sample` 폴더(372개 파일, DB 495건 참조)** — 사실상 크기 규칙이 없다. 가로 102~843px,
   세로 102~1047px 범위에 341개(92%)가 정사각형도 아니다. 화면에서는 `object-contain` 등으로
   비율을 맞춰 표시되겠지만, 원본 해상도·비율이 제각각이라 화질·여백이 배지마다 다르게 보일
   가능성이 크다.
2. **Supabase Storage 원격 업로드분(427건)** — 배지 이미지 제작 파이프라인(`/jam-img` 스킬:
   Recraft 생성 → 로고합성 → 배경제거 → DB반영)의 산출물로 추정되며, 최종 리사이즈 단계 없이
   원본 해상도 그대로 저장돼 있다. 913~1555px 사이에서 파일마다 다르다.
