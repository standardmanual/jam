# [Admin] 쉐이더 랩 레이어 소스 3종(플루이드·픽셀 트레일·매그니파이 렌즈) 삭제

## 배경 / 문제 정의
사용자가 쉐이더 랩(`/admin/shader-lab`)의 레이어 소스 중 "플루이드"(`fluid`)·"픽셀
트레일"(`pixel-trail`)·"매그니파이 렌즈"(`magnify-lens`) 3종을 삭제해달라고 요청했다.
이 3종은 티켓 20260912_2157에서 도입됐다.

오케스트레이터의 사전 조사(Explore 에이전트) 결과, 핵심 수정 지점은
`jam-web/src/lib/admin/shaderLab/effectRegistry.ts` 한 파일에 집중돼 있다 — 레이어
추가 드롭다운(`ShaderLabLayerSidebar.tsx`)·속성 패널(`ShaderLabPropertiesPanel.tsx`)·
레이어 생성(`layerFactory.ts`)은 모두 이 registry를 제네릭하게 읽어 렌더링하므로 별도
하드코딩 수정이 필요 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
`jam-web/src/lib/admin/shaderLab/effectRegistry.ts`에서:
- `SHADER_LAB_LAYER_TYPES` 배열에서 `'fluid'`·`'pixel-trail'`·`'magnify-lens'` 3개
  항목 제거 (파일 상단 "소스 4종(신규)" 안내 주석도 그라디언트만 남도록 정리)
- `fluidFields`·`pixelTrailFields`·`magnifyLensFields` 필드 정의 상수 3개 전체 삭제
- `SHADER_LAB_LAYER_REGISTRY` 안의 `fluid`·`'pixel-trail'`·`'magnify-lens'` 엔트리
  3개 삭제
- 파일 상단 헤더 주석(L5-6, L11 부근)의 "소스 4종" 관련 문구를 실제 남은 소스 종수에
  맞게 정정
- `fluidNoise`(잉크 이펙트 파라미터, 이름만 유사할 뿐 무관)는 **삭제 대상 아님** — 건드리지
  않는다
- `SupportedShaderLabLayerType`은 `SHADER_LAB_LAYER_TYPES`에서 자동 파생되므로 별도
  수정 불필요
- `src/lib/admin/shaderLab/useShaderLabPlayback.ts` L18-25의 주석은 "플루이드·픽셀
  트레일·매그니파이 렌즈가 포인터 위치 기반이라 delta를 실제 시간으로 유지해야 한다"는
  근거를 담고 있다. 이 3종이 사라지면 그 근거가 무효화되므로:
  1. delta를 실제 경과 시간으로 유지하는 정책 자체를 그대로 둘지(다른 레이어에 영향 없는지
     확인 후 유지) 재검토한다.
  2. 정책을 유지하기로 하면 주석만 최신 상태로 고친다(더는 존재하지 않는 3종을 근거로
     들지 않도록).
  3. 정책을 바꿀 근거가 없다면(다른 레이어도 delta 흐름이 필요할 수 있음) 함부로 delta=0
     고정으로 바꾸지 않는다 — 회귀 위험이 있으므로 신중히 판단하고 근거를 완료 기록에 남긴다.
- 패키지(`@basementstudio/shader-lab`) 자체의 `fluid-pass.js`/`pixel-trail-pass.js`/
  `magnify-lens-pass.js`는 건드리지 않는다(제3자 패키지, JAM! 쪽에서 사용을 끊는 것만이
  목표).

### UI/UX 관점 (해당 시)
- "레이어 추가" 드롭다운에서 이 3종이 더 이상 나타나지 않아야 한다(registry 수정만으로
  자동 반영됨 — 별도 UI 코드 수정 불필요, 실렌더로 확인).

### 컨텐츠 관점 (해당 시)
- 해당 없음.

### 기존 저장된 컴포지션 호환성
- 기존에 저장된 쉐이더 랩 컴포지션(`scene_json`)에 이 3종 레이어가 포함돼 있을 가능성이
  있다. 그런 컴포지션을 불러왔을 때 어떻게 동작하는지 확인한다(registry에서 정의가 사라진
  레이어 타입을 만났을 때 에러 없이 무시/건너뛰는지, 아니면 크래시하는지) — 기존 코드의
  방어 로직을 그대로 신뢰하되, 명백히 깨지는 경우에만 최소한의 방어 코드를 추가한다
  (범위를 벗어나는 과잉 대응은 하지 않는다).

## 구현 계획
1. `effectRegistry.ts`에서 위 3개 항목(배열·필드 상수·registry 엔트리·헤더 주석) 삭제.
2. `useShaderLabPlayback.ts`의 delta 정책 관련 주석을 재검토하고 정리.
3. 로컬 `npm run dev`(`ADMIN_EMAILS` 셸 환경변수)로 `/admin/shader-lab`에서 레이어 추가
   드롭다운에 3종이 더 이상 보이지 않는지, 남은 소스·이펙트가 정상 동작하는지 확인.
4. 기존 저장 컴포지션에 이 3종이 포함된 경우의 동작을 확인(가능하면).

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- delta=0 고정으로 바꾸지 않고 실제 경과 시간 유지 정책을 그대로 둔 이유: 남은 레이어
  중에도 포인터/시간 기반 동작을 쓰는 것이 있을 수 있어, 근거가 사라진 주석만 정리하고
  정책 자체는 건드리지 않는 쪽이 회귀 위험이 낮다고 판단.
- 기존 저장 컴포지션에 삭제된 3종이 남아있을 가능성은 DB 조회로 확인하지 못했다 —
  `isSupportedLayerType` 가드가 있어 크래시는 없을 것으로 판단되나(코드 방어 로직 확인),
  실제 그런 컴포지션을 열었을 때 "알 수 없는 레이어 타입"으로 보일 수 있다는 점은 잔여
  이슈로 남긴다.

### 잔여 이슈
- 기존 저장 컴포지션에 플루이드·픽셀 트레일·매그니파이 렌즈 레이어가 포함된 경우가
  실제로 있는지 DB 조회로 확인되지 않았다. 사용자가 그런 컴포지션을 열었을 때 이상이
  보이면 별도 티켓으로 보고.
