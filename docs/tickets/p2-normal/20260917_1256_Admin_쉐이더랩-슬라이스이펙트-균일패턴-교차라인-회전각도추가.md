# [Admin] 쉐이더랩 슬라이스 이펙트 — 균일 패턴·교차 라인·회전각도 추가

## 배경 / 문제 정의
쉐이더랩(`/admin/shader-lab`)의 슬라이스(slice) 이펙트는 사용자가 첨부한 참고 이미지(세로
줄무늬가 중앙에서 바깥으로 대칭적으로 번지는 균일한 스트라이프 패턴)와 달리, 현재는 밴드마다
매 프레임 랜덤으로 흔들리는 방식이라 결과물이 불규칙하게 보인다. 사용자가 다음 6가지를
요청했다.

1. 화면을 균일한 간격으로 슬라이스
2. 슬라이스 라인의 기준 간격 조절 가능
3. 슬라이스로 틀어지는 양 조절 가능
4. 슬라이스 라인 사이를 가로지르는 짧은 교차 슬라이스 추가
5. 4번 교차 라인의 간격 조절 가능
6. 슬라이스 방향을 360도 회전값(슬라이더)으로 지정 가능

## 상세 요구사항

### 서비스/코드베이스 관점
- 대상 파일:
  - `jam-web/patches/@basementstudio+shader-lab+3.0.2.patch` 안의
    `node_modules/@basementstudio/shader-lab/dist/src/renderer/slice-pass.js` (벤더 패치 셰이더,
    TSL 기반)
  - `jam-web/src/lib/admin/shaderLab/effectRegistry.ts`의 `sliceFields` 정의 (필드 UI)
- **목표 1 (균일 패턴)**: 현재 `sliceHeight`로 그리드 간격 자체는 고정이지만,
  `bandNoise`·`gate`(density 기반)·`randomDirection`이 매 프레임 랜덤으로 밴드를 골라 흔드는
  구조라 화면이 불규칙하게 보인다. 노이즈 게이팅 의존도를 줄이거나 시드를 고정해, 패턴이
  프레임 간 안정적으로 유지되도록 로직을 수정한다. 참고 이미지처럼 중앙에서 바깥으로 대칭
  번짐이 필요하다면 밴드 인덱스 기반 결정적 함수(거리 기반 그라디언트 등)로 대체하는 방안도
  검토한다.
- **목표 2·3 (간격·이동량 조절)**: 기존 `sliceHeight`·`amount` 필드가 이미 이 역할을 하므로
  신규 필드는 불필요하다. 다만 목표 1 수정 후 두 필드가 참고 이미지 수준의 결과를 내는지
  재확인한다.
- **목표 4·5 (교차 라인)**: 현재 `blockWidth`는 수직축 인덱스(`blockIndex`) 계산에만 쓰이고
  화면에 실제 선으로 렌더링되지 않는다. 슬라이스 축과 수직인 방향으로 얇은 분할선을 시각적으로
  그리는 로직을 신규 추가한다. 간격 조절용 필드는 `blockWidth`를 재사용할지 별도 필드로 분리할지
  구현 시 판단해 근거를 완료 기록에 남긴다.
- **목표 6 (360도 회전)**: 현재 `direction`은 `right`/`left`/`both`/`down`/`up` 5개 옵션의
  select다. `pixelCoord`를 회전 행렬로 회전시킨 뒤 슬라이스 축(`sliceIndex`/`blockIndex`)을
  계산하는 방식으로 축 계산 로직을 재작성하고, `effectRegistry.ts`에 0~360도 슬라이더 필드를
  추가한다. 기존 5개 프리셋 방향과의 호환(기존 저장된 레이어 값 마이그레이션 여부)을 함께
  검토한다.

### UI/UX 관점 (해당 시)
- 어드민 전용 도구이므로 MODULAR 디자인 시스템 탐색 대상 제외.
- 필드 슬라이더·라벨은 기존 `sliceFields` 패턴(한글 라벨, unit 표기)을 따른다.

### 컨텐츠 관점 (해당 시)

## 구현 계획
1. `slice-pass.js` 패치 파일을 수정해 노이즈 게이팅 로직을 결정적 패턴으로 전환하고, 교차 라인
   렌더링과 회전각 축 계산을 추가한다. 수정 후 `patch-package`로 patch 파일을 재생성한다.
2. `effectRegistry.ts`의 `sliceFields`에 교차 라인 간격 필드와 회전각(0~360, 슬라이더) 필드를
   추가한다.
3. 기존 slice 이펙트를 쓰는 다른 화면·프리셋(배경 제너레이터 등)에 회귀가 없는지 확인한다.
4. 어드민 화면이라 staging 시각 검증이 불가능하므로, `DEV_PROCESS_GUARDRAILS.md` 패턴 13
   (로컬 `ADMIN_EMAILS` 셸 환경변수)으로 로컬 실렌더 검증 후 스크린샷을 첨부해 보고한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 밴드 게이팅 결정 함수에서 매 프레임 바뀌던 `timeBucket` 의존을 제거해, 같은 밴드가 프레임
  간 고정된 위치에 유지되도록 수정 (목표 1). 애니메이션은 위상 고정 `sin` 파형으로만 부드럽게
  유지하며 `speed=0`이면 완전히 정적이다.
- `sliceHeight`(간격)·`amount`(이동량) 필드는 그대로 유지 — 신규 필드 불필요 확인 (목표 2·3).
- 회전된 로컬 x축 기준으로 `crossLineSpacing`(신규 필드, px) 간격마다 얇은 교차선을 렌더링하는
  로직 추가 (목표 4·5). `blockWidth`(밴드 내 랜덤 오프셋 결정에 계속 사용)와는 분리했다 —
  교차선은 시각적 그리드고 `blockWidth`는 노이즈 계산용 인덱스라 역할이 달라 병합하지 않았다.
- `direction`(오른쪽/왼쪽/양쪽/위/아래 select) 필드를 폐지하고 `rotation`(0~360도 슬라이더)으로
  대체. 픽셀 좌표를 화면 중심 기준으로 회전시켜 밴드 축과 미는 방향을 함께 결정한다.
  0도가 기존 "오른쪽"과 동일 (목표 6).

### 주요 의사결정 / 핵심 메모
- 게이팅을 "완전 결정적"이 아니라 "위상 고정 + 부드러운 sin 애니메이션"으로 구현했다 —
  완전 정적이면 이펙트로서의 생동감이 사라진다고 판단했기 때문. 참고 이미지와의 완전 일치
  여부는 사용자 육안 확인이 필요하다 (게이트 리뷰 confidence: medium).
- **WARN**: 기존에 저장된 slice 컴포지션이 `direction: 'left'/'both'/'down'/'up'` 값을 갖고
  있었다면, 새 셰이더는 이 값을 더 이상 읽지 않고 `rotation` 기본값(0도, 기존 "오른쪽"과 동일)
  으로 조용히 폴백된다. 마이그레이션 스크립트는 작성하지 않았다 — 어드민 프리뷰 전용 도구라
  영향이 제한적이라는 판단이었으나, 실제 저장된 컴포지션 존재 여부는 확인되지 않아 리스크로
  남는다.

### 잔여 이슈
- 저장된 슬라이스 컴포지션 중 `direction` 값이 `left`/`both`/`down`/`up`인 것이 있는지 확인
  필요 (있다면 회전값으로 수동 재설정하거나 마이그레이션 스크립트 작성)
