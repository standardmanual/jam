# [Admin] 쉐이더랩 슬라이스 이펙트 — 밀도 제거·전체 균일 슬라이스

## 배경 / 문제 정의
직전 티켓([20260917_1348](./20260917_1348_Admin_쉐이더랩-슬라이스이펙트-밴드선택간격균일화.md))에서
`density`가 결정하는 밴드 선택을 확률적 방식에서 규칙적 주기(`mod` 패턴) 방식으로 바꿨지만,
사용자가 실렌더 스크린샷을 다시 확인한 결과 여전히 간격이 균일하지 않다고 판단했다. 사용자
요청은 더 단순하다 — **밀도(density) 기능 자체를 없애고, 슬라이스 밴드 전부가 동일한 간격으로
동작하게 한다.** 즉 "어느 밴드를 선택할지" 게이팅 개념 자체를 제거하고, `sliceHeight`로 나뉜
모든 밴드가 예외 없이 같은 강도로 밀리도록 한다.

이 결정에 따라 직전 티켓(20260917_1348)의 주기 기반 구현은 staging에 병합하지 않고 폐기했다
(완료 기록 참고). 이번 티켓은 `origin/staging`(20260917_1348 변경이 반영되지 않은 상태) 기준으로
새로 작업한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 대상 파일:
  - `jam-web/patches/@basementstudio+shader-lab+3.0.2.patch` 안의 `slice-pass.js`
  - `jam-web/src/lib/admin/shaderLab/effectRegistry.ts`의 `sliceFields`
- **밀도 필드·로직 완전 제거**: `effectRegistry.ts`에서 `density` 필드를 삭제한다.
  `slice-pass.js`에서 `densityUniform`과 `gate` 계산(및 그 계산에만 쓰이는 `bandNoise`/
  `hash2`)을 제거하고, 게이트 없이 **모든 밴드가 항상 선택된 것**으로 취급한다
  (`sliceStrength = amount * breathe`, 밴드별 on/off 분기 없음).
- **전체 균일 슬라이스**: `sliceHeight`로 나뉜 모든 밴드가 동일한 `amount` 강도로, 동일한
  애니메이션 위상으로 밀린다. 밴드 간 시각적 차이(어떤 밴드는 밀리고 어떤 밴드는 안 밀리는
  상태)가 전혀 없어야 한다 — 화면 전체가 균일한 가로/세로 줄무늬 패턴으로만 보여야 한다.
- `smearMix`(트레일 블렌드 강도)도 `gate`를 곱하던 부분을 제거하고 고정값만 남긴다(이미
  `gate * 0.39`였던 걸 `0.39`로 단순화하거나, 트레일 자체를 계속 쓸지 재검토 — 구현 시 판단).
- `updateParams()`·`.d.ts`에서 `density` 관련 파라미터 매핑을 함께 제거한다.

### UI/UX 관점 (해당 시)
- 어드민 속성 패널에서 `밀도` 슬라이더가 사라진다.

### 컨텐츠 관점 (해당 시)
- 해당 없음.

## 구현 계획
1. `origin/staging` 최신 기준(20260917_1348 변경 미포함)에서 새로 브랜치를 딴다.
2. `effectRegistry.ts`의 `sliceFields`에서 `density` 필드 제거.
3. `slice-pass.js`에서 `densityUniform`·`gate`·`bandNoise`·`hash2`(다른 용도로 안 쓰이면)를
   제거하고 모든 밴드가 항상 같은 강도로 밀리도록 단순화.
4. patch 파일 재생성(`patch-package`).
5. **반드시** 로컬 `next dev`(ADMIN_EMAILS 셸 환경변수) + 브라우저 실렌더로 확인한다.
   headless Chromium은 WebGPU "Device Lost"로 실패하므로 headed 모드로 전환해야 한다
   (직전 티켓 완료 기록 참고). 이동량을 여러 값으로 바꿔가며 전체 밴드가 정말 균일하게
   슬라이스되는지 스크린샷으로 직접 확인하고, 그 스크린샷을 근거로 보고한다. 수식 검증만으로는
   게이트를 통과할 수 없다(직전 티켓의 1차 시도 FAIL 사유).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
1. `effectRegistry.ts`의 `sliceFields`에서 `density`(밀도) 필드 정의를 삭제했다.
2. `slice-pass.js`(패치 대상 파일)에서 `densityUniform`·`params.density` 매핑을 제거하고,
   `gate`(밴드 선택 게이트) 계산과 그 계산에만 쓰이던 `bandNoise`/`hash2` 함수를 완전히
   삭제했다. `sliceIndex`도 게이트 계산 외 다른 용도가 없어 함께 제거했다(회전된 좌표계
   `centered`/`rotated`/`center` 산출도 sliceIndex 계산에만 쓰였으므로 같이 정리).
3. `sliceStrength = amount * gate * breathe` → `sliceStrength = amount * breathe`로
   단순화했다 — 티켓이 명시한 그대로, 게이트 없이 모든 밴드가 항상 선택된 것으로 취급한다.
4. `smearMix`(트레일 블렌드 강도)도 `gate * 0.39` → 고정값 `0.39`로 단순화했다(게이팅
   개념이 없어졌으므로 곱할 대상이 없다).
5. `.d.ts` 타입 선언에서 `densityUniform` 필드를 삭제했다.
6. `patch-package @basementstudio/shader-lab` 재실행으로 패치 파일 재생성.
7. `sliceHeight`(조각 높이) 필드는 티켓 지시대로 그대로 남겨뒀다 — 다만 게이팅이 사라지면서
   셰이더 출력에는 더 이상 영향을 주지 않는다(밴드 폭과 무관하게 화면 전체가 균일하게 밀림).
   실렌더로 조각 높이를 20px/150px로 바꿔가며 비교해 출력이 동일함을 확인했다(주요
   의사결정 참고).

### 주요 의사결정 / 핵심 메모
- 게이팅(`gate`)을 없애면 `sliceIndex`(밴드 인덱스)가 셰이더 어디에서도 쓰이지 않게 된다.
  이를 계산하기 위한 회전 중심 좌표 변환(`center`/`centered`/`rotated`)도 sliceIndex
  계산에만 쓰였던 죽은 코드가 되므로 함께 제거했다. `cosA`/`sinA`(밀리는 방향 계산)는
  `pushPixel` 산출에 계속 쓰이므로 남겨뒀다.
- `sliceHeight`(조각 높이) 필드는 삭제 대상이 아니었으므로(티켓 범위 밖) UI에 유지했다.
  다만 게이팅 제거로 셰이더 출력에 영향을 주지 않게 된 점은 사용자가 인지해야 할 부작용이라
  `alerts`에 WARN으로 남긴다.
- `smearMix` 고정값은 직전 티켓(20260917_1324)에서 이미 `gate * 0.39`로 정했던 값의
  게이팅만 제거한 `0.39` 그대로 사용했다 — 트레일 세기 자체의 크기는 이번 티켓 범위가
  아니므로 임의로 바꾸지 않았다.
