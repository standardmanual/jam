## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/lib/admin/shaderLab/effectRegistry.ts`에서 `slice` 관련 항목 전부 제거:
  - `SHADER_LAB_LAYER_TYPES` 배열의 `'slice'` 항목
  - `SHADER_LAB_BLOB_INNER_EFFECT_OPTIONS`의 `{ label: '슬라이스', value: 'slice' }` 옵션
  - `sliceFields` 필드 정의 전체
  - `SHADER_LAB_LAYER_REGISTRY`의 `slice: {...}` 엔트리
  - `SHADER_LAB_FORCED_STATIC_PARAMS`의 `slice: { speed: 0 }` 엔트리
  - 파일 상단 개요 주석의 이펙트 목록·종수 카운트 갱신(26종 → 25종, Distort 9종 → 8종)
- 벤더 패치(`jam-web/patches/@basementstudio+shader-lab+3.0.2.patch`)의 `slice-pass.js` 관련
  diff는 그대로 둔다 — UI에서 선택 불가능해지면 완전히 죽은 코드가 되어 실질적 영향이
  없고, 패치 파일에서 해당 부분만 도려내는 작업은 이번 범위 밖의 위험 대비 이득이 낮다고
  판단했다(패치 재생성 과정에서 다른 패스에 영향을 줄 가능성을 배제하기 위함).

### UI/UX 관점 (해당 시)
- 어드민 쉐이더랩 레이어 추가 드롭다운·블롭 트래킹의 내부 이펙트 선택지에서 "슬라이스"가
  사라진다.

### 컨텐츠 관점 (해당 시)
- 해당 없음. 기존에 슬라이스 레이어를 쓰던 저장된 컴포지션이 있다면 해당 레이어가 더 이상
  렌더링되지 않을 수 있으나, 이전 티켓들에서 이미 같은 성격의 리스크(direction 필드 폐지 등)를
  "어드민 프리뷰 전용 도구라 영향 제한적"으로 판단해온 것과 동일한 근거로 마이그레이션은
  진행하지 않는다.

## 구현 계획
1. `effectRegistry.ts`에서 위 5곳을 모두 제거.
2. `npx eslint`(변경 파일 한정)·`npm run typecheck`로 검증.
3. 코드베이스 전체에서 `'slice'` 문자열 리터럴 참조가 남지 않았는지 grep으로 확인.

  제거하면 완전히 죽은 코드가 되어 실질적 위험이 없는데, 패치 파일 재생성 과정에서 실수로
