# [API] 주간 집계 API /api/admin/kpi/weekly

## 핵심 요약
- 요구사항: GA4가 볼 수 없는 운영 이상 4개를 DB 기준으로 집계해 숫자만 반환하는 어드민 API를 만든다.
- 구현 계획: 읽기 토큰(20260918_1149)으로 호출하는 GET 라우트를 추가한다.
- 관련 파일: `jam-web/src/app/api/admin/kpi/weekly/`
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../p1-high/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 20260918_1149 (읽기 토큰)
- 경로: ③ 표준 (api 유형이라 채원 없이 아현→민지)

## 배경 / 문제 정의
GA4는 광고 차단기 유저를 놓치고 일부 이벤트는 특정 경로에서만 계측돼, "0건이면 고장" 판정에 쓸 수 없다(상위 티켓 4-7, `GA4_EVENTS.md` 알려진 계측 공백).

## 상세 요구사항

### 서비스/코드베이스 관점
- 지표 4개: 미션 달성자 수, 배지 발급량과 중복 발급 건수, Strava 동기화 실패 건수, 앰비언트 드랍 만료 건수
- 기간은 지난 7일(KST)이며 쿼리 파라미터로 바꿀 수 있다
- 응답에는 집계 숫자만 담는다. 닉네임·이메일·유저 ID 등 개인 식별 정보는 넣지 않는다(4-6)
- 뉴스레터는 기능이 없어 넣지 않는다

## 구현 계획
각 지표의 정의(어느 테이블·어느 조건)를 먼저 티켓에 적고 구현한다. 공용 프로덕션 DB라 읽기 쿼리만 쓴다.

## 완료 기록 *(2026-09-18)*

### 구현 내용 요약
`GET /api/admin/kpi/weekly?days=N` (기본 7일 KST, 1~90 범위 밖은 기본값). 인증은 `requireAdminRead(req)`(GET만 export). 읽기 쿼리만 쓴다.

지표 정의:
| 지표 | 정의 | 반환 |
|---|---|---|
| 미션 달성자 수 | `user_mission_completions.completed_at`이 기간 안인 행의 `user_id` 고유 개수 | 숫자 |
| 배지 발급량 | `user_activity_badges.earned_at`이 기간 안인 행 개수 (반복 획득은 `earn_count`만 올려 발급으로 세지 않음) | 숫자 |
| 배지 중복 발급 | `UNIQUE(user_id, badge_id)`로 구조상 발생 불가 | `null` + 사유 |
| Strava 동기화 실패 | 실패가 DB에 기록되지 않음(`console.error`만) | `null` + 사유 |
| 앰비언트 드랍 만료 | `source='system'` 드랍은 `expires_at`이 항상 NULL | `null` + 사유 |
