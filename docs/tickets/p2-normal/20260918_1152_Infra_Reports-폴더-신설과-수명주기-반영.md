# [Infra] docs/operations/reports/ 신설과 수명주기 반영

## 핵심 요약
- 요구사항: 주간·월간 리포트를 저장할 `docs/operations/reports/`를 만들고 "시점별 기록" 수명주기를 규칙에 반영한다.
- 구현 계획: 폴더와 README를 만들고 CLAUDE.md 폴더표·`pre-commit`·`dashboard-format.md`를 고친다.
- 관련 파일: `docs/operations/reports/`, `CLAUDE.md`, `.githooks/pre-commit`, `.claude/skills/jam-work/references/dashboard-format.md`
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../p1-high/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 없음
- 경로: ③ 표준 (`pre-commit` 코드 수정이 있어 아현→민지)

## 배경 / 문제 정의
주간 브리핑 양식은 있으나 저장 위치가 없어 보고가 대화와 함께 사라진다(상위 티켓 안건 3).

## 상세 요구사항

### 서비스/코드베이스 관점
- `Reports/주간/YYYY-Www.md`, `Reports/월간/YYYY-MM.md` 구조를 만들고 README에 규칙을 적는다(3-1)
- CLAUDE.md 폴더표에 `Reports/` 행을 추가한다: 시점별 기록, 쌓기만 하고 덮어쓰지 않음
- `pre-commit`이 `Reports/`의 날짜 파일명을 버전 사본으로 막지 않게 예외를 둔다
- 읽기 상한을 README에 적는다: 에이전트는 주간 최근 4주·월간 최근 3개월만 읽는다(3-2)
- `dashboard-format.md`의 `DASHBOARD.md` 저장 계약을 폐기하고, 현황판은 hook이 즉석 생성한다고 고친다(3-3)

## 구현 계획
`pre-commit`의 기존 버전 사본 검사 로직을 확인하고 `Reports/` 경로만 예외로 둔다.

## 완료 조건
- `Reports/주간/2026-W38.md` 같은 파일을 커밋하면 `pre-commit`을 통과한다
- 다른 폴더의 버전 사본(예: `_20260918`)은 여전히 막힌다
- CLAUDE.md 폴더표와 README에 수명주기·읽기 상한이 적혀 있다
- `dashboard-format.md`에 `DASHBOARD.md` 저장 계약이 남아 있지 않다
