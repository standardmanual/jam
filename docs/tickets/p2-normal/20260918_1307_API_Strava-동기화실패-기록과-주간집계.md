# [API] Strava 동기화 실패 기록과 주간 집계 반영

## 핵심 요약
- 요구사항: Strava 동기화 실패를 DB에 기록하고, `/api/admin/kpi/weekly`가 지난 기간의 실패 건수를 숫자로 반환하게 한다.
- 구현 계획: 실패 기록 방식(테이블 신설 등)을 정한 뒤 동기화 경로에 기록을 추가하고 집계 API에 반영한다.
- 관련 파일: `jam-web/src/app/api/strava/sync/`, `jam-web/src/lib/admin/kpiWeekly.ts`, `jam-web/supabase/migrations/`
- 상위 티켓: [20260918_1101 에이전트 팀 운영 정비](../P1-중요/20260918_1101_Infra_에이전트팀-운영정비-상위.md)
- 선행 티켓: 20260918_1150 (주간 집계 API)
- 출처: 1150 게이트 리뷰(민지) 범위 밖 발견물, 사용자 결정(2026-09-18: 미확보 지표 3개 중 이것만 티켓화)

## 배경 / 문제 정의
`/api/strava/sync`는 실패를 `console.error`로만 남기고 DB에 기록하지 않는다. 그래서 1150의 주간 집계 API가 동기화 실패
건수를 `null`로 반환하고, 주간 브리핑이 Strava 장애를 잡지 못한다(상위 티켓 4-7: GA4로는 볼 수 없는 운영 이상).

## 상세 요구사항

### 서비스/코드베이스 관점
- 동기화가 실패하면 실패 시각·실패 유형(토큰 만료·Strava API 오류·레이트리밋 등)을 DB에 남긴다. 유저 식별값은 집계 응답에 넣지 않는다(4-6)
- 동기화 성공 흐름과 응답은 바뀌지 않는다. 기록 실패가 동기화 자체를 실패시키지 않는다
- 집계 API의 `stravaSyncFailures`가 기간 안 실패 건수를 숫자로 반환한다(유형별 건수는 선택)
- DB 스키마 변경은 SQL 파일 작성까지만 하고, 실행은 사용자 승인 후 메인 세션이 한다

## 완료 조건
- 동기화 실패 시 기록이 남는다 (단위 테스트)
- 읽기 토큰으로 집계 API를 호출하면 `stravaSyncFailures`가 숫자로 반환된다
- `scheduled-jobs.md`·`weekly-briefing-format.md`의 "현재 상태" 안내가 갱신되어 있다
