# [Infra] 콜사인을 이름과 통일하고 카즈하에게 Workflow 개선점 발견 역할을 추가

> 상위 티켓: `20260918_1101_Infra_에이전트팀-운영정비-상위.md`

## 핵심 요약
- 요구사항: ① 에이전트 콜사인을 전부 본인 이름과 동일하게 통일한다(기존 트레일메이커·체크포인트 등
  닉네임 폐기). ② 카즈하(jam-ops)에게 jam-work 파이프라인 실행을 모니터링해 개선점을 찾는 역할을
  추가한다. ③ `/jam-work`은 카리나(오케스트레이터) 담당임을 팀 구성 문서에 명시한다.
- 구현 계획: `.claude/agents/*.md` 9개 파일의 `Call sign:` 줄을 이름으로 교체, `jam-work/SKILL.md`
  헤더·섹션 제목의 콜사인 표기 정리, `jam-ops.md`에 Workflow 개선점 발견 모드 추가,
  `team-composition.md`·루트 `CLAUDE.md`의 카즈하 역할 설명과 `/jam-work` 담당 표기 갱신.
- 관련 파일:
  - `.claude/agents/jam-developer.md:9`, `conservative-reviewer.md:9`, `jam-designer.md:9`,
    `jam-marketer.md:9`, `jam-ops.md:10`, `jam-pm.md:8`, `jam-tribe.md:9`, `jam-guide.md:9`
  - `.claude/skills/jam-work/SKILL.md:8-9`, `:216`
  - `.claude/skills/jam-work/references/team-composition.md`
  - `CLAUDE.md` (팀 구성 표), `.claude/global-CLAUDE.md` (사본 동기화 대상 아님 — 전역 규칙 아님)

## 배경 / 문제 정의
2026-09-18에 8인 에이전트 팀을 영어 정의로 도입하면서(티켓 20260918_0422) 각 에이전트에
산행·캠프 테마 콜사인(트레일메이커·체크포인트·팔레트·워치타워 등)을 붙였다. 사용자가 팀 지도
아티팩트를 검토하며 "콜사인은 이름과 동일하게 함"으로 방향을 바꿨다 — 별도 닉네임 없이 이름
자체가 콜사인이다.

동시에, jam-work 파이프라인 실행이 쌓일수록(토큰 사용량·소요 시간·재작업 횟수 등) 개선 포인트를
찾아 반영하는 일을 지금은 카리나가 티켓 단위로 직접 해 왔다. 사용자가 이 역할을 전담 에이전트에게
맡기고 싶다고 요청했고, 카즈하(운영·리스크, 읽기 전용, 이미 주간 브리핑에 "워크플로 수치" 항목을
갖고 있음)가 가장 근접한 역할이라 판단해 카즈하에게 배정한다. `/jam-work`의 호출 주체는 원래부터
카리나였고 이번에 바뀐 것은 없다 — 팀 구성 문서에 명시만 추가한다.

## 상세 요구사항

### 콜사인 통일
- `.claude/agents/` 9개 파일의 `**Call sign: <닉네임> (<English>)**` 줄을 `**Call sign: <이름>**`으로 교체.
  모토(따옴표 문장)는 그대로 유지 — 페르소나 원칙 자체는 바뀐 게 없다.
- `jam-work/SKILL.md` 8~9행의 "카리나(오케스트레이터=나, 콜사인 베이스캠프) · 채원(`jam-designer`, 팔레트) ·
  아현(`jam-developer`, 트레일메이커) · 민지(`conservative-reviewer`, 체크포인트)"에서 괄호 안 콜사인
  표기를 제거(이름과 중복이므로).
- 같은 파일 216행 "## 4. 승인 후 처리 — 베이스캠프 모자를 쓴다" 같은 절차 제목의 콜사인 잔재도
  정리(대체할 마땅한 표현이 없으면 "카리나가 직접 처리" 등 기능 설명으로 대체).

### 카즈하 — Workflow 개선점 발견
- `jam-ops.md`에 새 모드로 추가: jam-work 파이프라인 실행 지표(완료 기록에 남는 `tokenUsage`·
  `duration_ms`·`agent_count`·재작업 횟수·재작업 사유)의 반복 패턴을 관찰해 개선 후보를 찾는다.
- 기존 "문제를 발견했을 때" 3단계 표(즉시 알림급 / 명확한 문제 → 티켓 초안 / 애매한 신호 → 브리핑
  관찰, 3회 반복 시 초안)를 그대로 따른다 — 새 판정 기준을 만들지 않는다.
- **쓰기 권한은 주지 않는다.** 카즈하는 발견물만 올리고, `handling-rules.md`·`jam-work.js` 반영은
  기존과 동일하게 카리나가 승인 후 처리한다(Forbidden 목록에 이미 있는 "editing code"에 파이프라인
  스크립트도 포함됨을 재확인).

### `/jam-work` 담당 명시
- `team-composition.md`의 스킬 목록 표에서 `/jam-work`에 `(카리나)`를 붙여, `/jam-plan(혜린)` ·
  `/jam-story(윈터·윤진 협업)`와 같은 표기 방식으로 통일한다.
