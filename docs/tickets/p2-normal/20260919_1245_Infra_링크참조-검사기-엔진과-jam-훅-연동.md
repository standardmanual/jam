# [Infra] 링크·참조 검사기 엔진과 jam 훅 연동

> 상위 티켓: 20260919_1223(문서 체계 정비). 스키마: `docs/specs/DOCUMENT_SCHEMA.md`. 하위 T1.

## 핵심 요약

- 요구사항: 문서의 내부 링크와 작업 폴더 기준 코드 스팬 경로를 검사하는 설정 기반 엔진을 만들고 `jam`의 `pre-commit`에 연결한다. 새로 깨지는 링크는 차단하고, 기존에 깨진 링크는 건드리지 않는다.
- 구현 계획: `scripts/`에 의존성 없는 node 스크립트(엔진)와 묶음 설정 파일, 단위 테스트를 만들고 `.githooks/pre-commit`에 연결한다. 검사 방식은 "추가된 줄 검사 + 파일 이동·삭제 시 인바운드 전수 검사"다.
- 관련 파일: `.githooks/pre-commit`(기존 문서 검사 절과 같은 구조로 추가), `scripts/`(신규 엔진과 테스트), `docs/specs/DOCUMENT_SCHEMA.md` §5·§7(검사 범위와 확장 규칙)

## 배경 / 문제 정의

내부 링크 697개 중 약 411개가 깨져 있다(임시 측정이며 코드 블록 예시가 섞였을 수 있다). 혜린 검토가 확인한 바로는 `docs/tickets`에서 옛 폴더명(`../P1-중요/`, `../Specs`) 링크만 110개 파일 172곳이다. 폴더 재편 때 **바뀌지 않은 파일의 링크**가 끊어져서 생긴 손상이라, 새로 만드는 링크만 검사해서는 재발을 막지 못한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **엔진에 JAM 고유 문자열을 넣지 않는다.** 필수 필드, 열거값(status·period), 태그 어휘, 링크 강제 여부, 제외 폴더는 모두 묶음 설정 파일에서 읽는다. 개인 지식 묶음으로 복사할 수 있게 하기 위해서다.
- **외부 npm 의존 없이 `node`만으로 실행한다.** `jam-doc`에는 `node_modules`가 없다.
- **검사 대상**: 마크다운 링크(파일 단위 검증, 앵커·외부 URL·코드 블록은 제외)와 백틱으로 적은 작업 폴더 기준 경로. 백틱 경로는 `UX_WRITING_GUIDELINE.md:317`처럼 실제로 자주 쓰이지만 예시 경로 오탐이 있을 수 있어 경고 등급으로 시작한다.
- **검사 방식(사용자 결정, 2026-09-19)**: 기준선 목록을 쓰지 않는다. 커밋에서 추가된 줄만 검사하고, 파일이 삭제·이동되면 그 경로를 가리키는 모든 문서를 전수 검사한다. 기존 훅에 있는 "추가된 줄만 검사" 선례를 따른다.
- **차단 정책**: 위반은 차단한다. 엔진 자체의 실패(설정 파싱 오류 등)는 경고를 내고 커밋을 통과시킨다. 기존 `JAM_SKIP_DOCLINT=1` 우회는 유지한다.
- **경로 해석**: `jam-doc/`로 시작하는 경로는 작업 폴더에 해당 폴더가 없으면 해석 불가로 보고 경고로 처리한다. 격리 워크트리에서는 `jam-doc`이 메인 폴더를 가리키는 심볼릭 링크임에 유의한다.
- **`jam` 설정**: 활성 type은 문서가 있는 13개다(`insight`와 `campaign`은 문서가 처음 생길 때 활성화, 사용자 결정). `type`·`description`·태그 어휘 검사는 이 티켓에서 구현하되 **경고 등급**으로 둔다(오류 전환은 하위 T4).

## 구현 계획

1. 설정 스키마와 엔진 뼈대를 만든다(설정 로드, 대상 파일 선정, 등급별 보고).
2. 링크·코드 스팬 경로 검사와 추가된 줄 판별, 이동·삭제 시 인바운드 전수 검사를 구현한다.
3. 필드·태그 검사를 경고 등급으로 구현한다.
4. `.githooks/pre-commit`에 연결하고 우회·실패 정책을 확인한다.
5. 단위 테스트를 작성하고 전체 문서에 돌려 깨진 링크를 실측한다.

## 완료 조건

- 단위 테스트가 통과한다. 케이스는 코드 블록 제외, 앵커 무시, 상대 링크, 백틱 경로, 이동·삭제 시 인바운드 전수 검사다.
- 없는 경로로 링크를 추가한 md를 커밋하면 차단되고, 기존에 깨진 링크만 있는 md의 다른 줄을 고쳐 커밋하면 통과한다.
- 다른 문서가 링크하는 파일을 `git mv`하는 커밋은 차단된다(참조하는 문서를 같은 커밋에서 고치면 통과한다).
- 엔진 자체 실패(설정 파싱 오류를 일부러 만든 경우)는 경고만 내고 커밋이 통과하며, `JAM_SKIP_DOCLINT=1` 우회가 동작한다.
- 엔진과 테스트 코드에서 JAM 고유 문자열(트라이브, 배지 등)이 grep으로 0건이다.
- 외부 npm 의존 없이 `node`만으로 실행된다.
- `jam` 설정의 활성 type이 13개이고 `insight`·`campaign`은 비활성이다.
- 완료 기록에 깨진 링크 실측(전체, 티켓, 비티켓, 코드 블록 제외)을 남긴다.
