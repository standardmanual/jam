# [Infra] jam-doc 훅 복사본과 설정

> 상위 티켓: 20260919_1223(문서 체계 정비). 하위 T2. **선행: 20260919_1245(T1) 완료, 티켓 20260918_2105 확인(월요일 2026-09-21 09:00 KST 주간 루틴 첫 실행) 후 착수.**

## 핵심 요약

- 요구사항: T1의 검사 엔진 복사본을 `jam-doc`에 두고 `jam-doc/.githooks/pre-commit`에 연결한다. `jam-doc` 전용 설정 파일을 만든다.
- 구현 계획: 엔진 복사 → `jam-doc` 설정 작성 → 기존 검사(archive 신규 파일 차단, 서비스 플랜·세계관 버전 사본 차단) 유지한 채 연동 → 두 엔진 복사본의 해시 일치를 검증하는 단계 추가.
- 관련 파일: `jam-doc/.githooks/pre-commit`, `jam-doc/README.md`(규칙 절), `jam-doc` 안의 신규 엔진 복사본과 설정, `verify.sh`(혜린 검토가 지목한 검증 스크립트, 위치는 착수 시 확인)

## 배경 / 문제 정의

`jam`의 `pre-commit`은 `jam-doc`이 없는 환경에서도 돌아야 하므로 엔진 원본은 `jam`에 둔다. 그러면 `jam-doc` 단독 복제(클라우드 루틴 등)에서는 `jam`의 엔진을 쓸 수 없어 복사본이 필요하다. 티켓 20260918_2105가 월요일 주간 루틴 첫 실행을 확인하기 전에 `jam-doc` 훅을 바꾸면 실패 원인을 가르기 어렵다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 복사본과 원본은 바이트가 같아야 한다. 어긋나면 검증 단계가 실패해야 한다.
- 기존 `jam-doc` 검사(archive 신규 파일 차단, 서비스 플랜·세계관 문서 버전 사본 차단)와 `JAM_SKIP_DOCLINT=1` 우회는 그대로 유지한다.
- `jam` 폴더 없이 `jam-doc`만 복제한 상태에서도 훅이 오류 없이 돈다. 작업 폴더 기준 경로 중 해석할 수 없는 것은 경고로 처리한다.
- **편집 방식**: 격리 워크트리가 아니라 메인 폴더에서 `git fetch` 후 rebase하고, 커밋 파일을 명시적으로 나열한다(워크트리 안의 `jam-doc`은 메인 폴더를 가리키는 심볼릭 링크다). `jam-doc`에서 커밋·푸시하고 커밋 메시지에 이 티켓 번호를 적는다.
- `jam-doc` 설정에서 `report`의 필드 검사는 경고 전용이다(무인 예약 루틴이 커밋하므로).
