# [Infra] jam-doc 훅 복사본과 설정

> 상위 티켓: 20260919_1223(문서 체계 정비). 하위 T2. **선행: 20260919_1245(T1) 완료, 티켓 20260918_2105 확인(월요일 2026-09-21 09:00 KST 주간 루틴 첫 실행) 후 착수.**

## 핵심 요약

- 요구사항: T1의 검사 엔진 복사본을 `jam-doc`에 두고 `jam-doc/.githooks/pre-commit`에 연결한다. `jam-doc` 전용 설정 파일을 만든다.
- 구현 계획: 엔진 복사 → `jam-doc` 설정 작성 → 기존 검사(archive 신규 파일 차단, 서비스 플랜·세계관 버전 사본 차단) 유지한 채 연동 → 두 엔진 복사본의 해시 일치를 검증하는 단계 추가.
- 관련 파일: `jam-doc/.githooks/pre-commit`, `docs/README.md`(규칙 절), `jam-doc` 안의 신규 엔진 복사본과 설정, `verify.sh`(혜린 검토가 지목한 검증 스크립트, 위치는 착수 시 확인)

## 배경 / 문제 정의

`jam`의 `pre-commit`은 `jam-doc`이 없는 환경에서도 돌아야 하므로 엔진 원본은 `jam`에 둔다. 그러면 `jam-doc` 단독 복제(클라우드 루틴 등)에서는 `jam`의 엔진을 쓸 수 없어 복사본이 필요하다. 티켓 20260918_2105가 월요일 주간 루틴 첫 실행을 확인하기 전에 `jam-doc` 훅을 바꾸면 실패 원인을 가르기 어렵다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 복사본과 원본은 바이트가 같아야 한다. 어긋나면 검증 단계가 실패해야 한다.
- 기존 `jam-doc` 검사(archive 신규 파일 차단, 서비스 플랜·세계관 문서 버전 사본 차단)와 `JAM_SKIP_DOCLINT=1` 우회는 그대로 유지한다.
- `jam` 폴더 없이 `jam-doc`만 복제한 상태에서도 훅이 오류 없이 돈다. 작업 폴더 기준 경로 중 해석할 수 없는 것은 경고로 처리한다.
- **편집 방식**: 격리 워크트리가 아니라 메인 폴더에서 `git fetch` 후 rebase하고, 커밋 파일을 명시적으로 나열한다(워크트리 안의 `jam-doc`은 메인 폴더를 가리키는 심볼릭 링크다). `jam-doc`에서 커밋·푸시하고 커밋 메시지에 이 티켓 번호를 적는다.
- `jam-doc` 설정에서 `report`의 필드 검사는 경고 전용이다(무인 예약 루틴이 커밋하므로).
- 완료되면 `docs/DOCUMENT_SCHEMA.md` §10과 `.claude/skills/jam-docs/SKILL.md`의 "`jam-doc` 문서는 아직 커밋 검사가 없다" 문구를 고친다(T6에서 넣은 임시 문구).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

T1(`scripts/doc-check.mjs`)의 검사 엔진을 `jam-doc`에 바이트 동일 복사본으로 두고
`jam-doc/.githooks/pre-commit`에 연동했다. `jam-doc` 전용 설정(`scripts/doc-check.config.json`)은
경로를 `jam-doc` 저장소 루트 기준으로 재작성하고, `jam-doc/`·`docs/`·`jam-web/`·`.claude/`를
externalPrefixes로 지정해 `jam` 없이 단독 복제된 환경에서 다른 저장소를 가리키는 경로를
"해석 불가(경고)"로 처리했다. 기존 검사(archive 신규 파일 차단·서비스플랜/TRIBES 버전 사본
차단)는 그대로 유지된다. `jam` 쪽 `scripts/verify.sh`에 두 엔진 복사본의 해시(cmp) 일치를
확인하는 단계를 추가했다.

**1차 시도는 착수 전 중단됐다.** 아현이 참조한 `origin/staging`에 티켓 20260918_2105의
CLOSED 전환이 아직 반영되지 않은 상태였다(PR merge 전이었음) — 선행조건 미충족을 정확히
판단해 구현하지 않고 멈췄다. PR merge 후 재실행.

**2차 시도(첫 실구현)는 게이트 리뷰 FAIL.** report 문서의 필드 검사를 경고 전용으로 두라는
요구사항을 `severity.field`를 `jam-doc` 전역(모든 문서 타입)으로 낮춰 구현해, report 외
`guideline`·`catalog`·`service-plan` 등도 frontmatter 누락이 차단되지 않는 스펙 불일치가
있었다. 민지가 재현 테스트로 확인했고, 실제 리포트 파일은 `operations/reports/`가 이미
`scope.exclude`에 있어 이 완화 자체가 애초에 불필요했다는 사실도 함께 밝혔다.

**3차 시도(재작업)로 PASS.** `severity.field`를 `jam`과 동일한 `error`로 되돌렸다(report 보호는
`scope.exclude`만으로 충분). 관련 테스트를 report 경로 기준으로 교체하고 `scope.exclude`
검증 테스트를 추가했으며, `docs/README.md` 서술을 정정했다. `jam-doc` 3개 파일은 아현이
격리 워크트리 권한 밖이라 내용만 수정해 넘겼고, 오케스트레이터가 확인 후 직접 커밋·푸시했다.
