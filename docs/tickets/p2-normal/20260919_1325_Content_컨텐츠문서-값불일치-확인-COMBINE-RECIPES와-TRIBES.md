# [Content] 컨텐츠 문서 값 불일치 확인: COMBINE_RECIPES와 TRIBES의 컬렉션 이름·수량, TRIBES DB 대조

> 발견 경위: 티켓 20260919_1248(T4) 하니 초안 작성 중 발견(하니 보고, 아직 직접 검증하지 않음). 상위 티켓 20260919_1223과 직접 관련은 없다.

## 핵심 요약

- 요구사항: `COMBINE_RECIPES.md`와 `TRIBES.md`가 같은 사실을 다르게 적은 곳이 있다. DB를 읽기 전용으로 조회해 어느 쪽이 낡았는지 확인하고 문서를 고친다.
- 구현 계획: DB 조회(SELECT만) → 두 문서와 대조표 작성 → 낡은 쪽 문서 갱신 → `TRIBES.md`의 `source_of_truth`(현재 `doc`)를 재판정한다.
- 관련 파일: `docs/service/content/COMBINE_RECIPES.md`(§4, §5), `docs/service/content/TRIBES.md`(서두 원천 소스, '채워야 할 내용'), `docs/service/content/ITEMBOOKS.xlsx`

## 배경 / 문제 정의

하니 보고(미검증)의 불일치는 세 가지다.

- `COMBINE_RECIPES.md` §5의 컬렉션 이름이 `TRIBES.md`와 트라이브 10개 중 7개에서 다르다(예: 숲속의 갱단은 '그루터기 살롱의 VIP'와 '그루터기 살롱의 장물들', 셔터 마피아는 '매직 아워 25시'와 '노을 헌터의 기록').
- `COMBINE_RECIPES.md` §4의 "아이템 배지 108종, 트라이브 2종에만 분포"와 `TRIBES.md`의 "아이템배지 900종, 트라이브당 90개"가 다르다.
- `TRIBES.md`의 '채워야 할 내용'에 "실제 DB(`tribes` 테이블)와 100% 일치하는지 검증"이 미완으로 남아 있고, 어드민 화면(`admin/tribes`)이 있어 DB가 문서와 어긋날 수 있다.

공용 단일 DB 구조라서 문서가 낡았는지 DB가 낡았는지는 조회해야 안다.

> **부분 확인(2026-09-26, DB 읽기 전용 조회)**: 첫 번째 불일치 중 숲속의 갱단은 이름 차이가 아니라 **서로 다른 컬렉션 2개**였다(「그루터기 살롱의 장물들」 `68a6ef7d-8ef3-117b-b25c-1418e1c5d416`, 「그루터기 살롱의 VIP」 `3a7f3fa1-08de-ad46-8c03-ac0ada645054`, 둘 다 활성, 트라이브당 컬렉션 10개). `COMBINE_RECIPES.md` §5에 이 구분을 적었다. 나머지 6개 트라이브도 같은 원인인지는 아직 조회하지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB 조회는 읽기 전용(SELECT)이며 메인 세션(카리나)만 실행한다. 쓰기가 필요하면 별도 승인을 받는다.
- 대조 결과는 표로 남긴다(항목, 문서 값, DB 값, 낡은 쪽).

### UI/UX 관점 (해당 시)
- 해당 없음.

### 컨텐츠 관점 (해당 시)

- 컬렉션 이름은 세계관 정설과 관련되므로 수정 전에 윈터가 검수한다.
- 갱신은 `TRIBES.md` 변경 전 스냅샷 규칙(`tribes-history/`)을 따른다.
- **윈터 권고(2026-09-19, T4 검토)**: ① 서사와 캐치프레이즈의 원문은 04 문서, 트라이브 구조(수량·컬렉션·인접 그래프)의 기준은 `TRIBES.md`라는 구분을 `TRIBES.md` 서두 문구('원천 소스')에 명시한다. ② 어드민(`admin/tribes`)에서 인접 그래프나 트라이브 설정을 고칠 때는 문서를 먼저 갱신하는 절차를 본문에 적는다. ③ 인접 그래프가 `ITEMBOOKS.xlsx`의 '트라이브 인접' 시트에도 있어 원천이 셋으로 갈리므로 어느 쪽이 기준인지 정한다.

## 구현 계획

1. DB의 트라이브·컬렉션·아이템배지 수를 조회한다.
2. 두 문서와 대조표를 만든다.
3. 낡은 문서를 갱신한다(`jam-doc` 저장소에서 커밋).
4. `TRIBES.md`의 `source_of_truth`를 재판정하고 필요하면 바꾼다.

## 완료 조건

- 대조표가 완료 기록에 있고, 두 문서의 컬렉션 이름과 아이템배지 수가 조회한 DB 값과 일치한다.
- `TRIBES.md`의 '실제 DB와 100% 일치하는지 검증' 항목이 완료로 표시된다.
- `TRIBES.md`의 `source_of_truth` 재판정 결과와 근거가 완료 기록에 있다.
- `TRIBES.md` 서두에 서사 원문과 구조 기준의 구분, 어드민 수정 시 문서 선갱신 절차, 인접 그래프의 기준 원천이 명시돼 있다.
