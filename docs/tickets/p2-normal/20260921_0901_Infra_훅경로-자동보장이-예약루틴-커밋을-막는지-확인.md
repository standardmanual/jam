# [Infra] 훅 경로 자동 보장이 예약 루틴(클라우드 세션)의 커밋을 처음으로 막는지 확인한다

## 핵심 요약

- 요구사항: 티켓 20260921_0841이 세션 시작 때 `core.hooksPath`를 자동으로 맞추게 하면, 새 클론에서 도는 예약 루틴의 커밋과 push에도 `pre-commit` 문서 검사·계약 검사와 `pre-push` 게이트가 처음으로 걸릴 수 있다. 루틴 환경에서 실제로 훅이 켜지는지, 켜진다면 루틴이 쓰는 리포트가 검사를 통과하는지 확인한다.
- 관련 파일: `.claude/skills/jam-work/references/scheduled-jobs.md`(루틴 프롬프트), `scripts/ensure-hooks-path.sh`(20260921_0841에서 신설), `.githooks/pre-commit`, `.githooks/pre-push`
- 선행 티켓: 20260921_0841(부모)

## 배경 / 문제 정의

티켓 20260921_0841의 게이트 리뷰(민지)가 남긴 범위 밖 발견물이다. 예약 루틴은 저장소를 새로 받아 도는 클라우드 세션이라 `core.hooksPath`가 비어 있었을 가능성이 높고, 그러면 지금까지 루틴의 커밋은 어떤 훅 검사도 받지 않았다. 세션 시작 스크립트가 값을 채우면 같은 커밋이 문서 규칙(frontmatter·링크·백틱 경로)과 계약 검사를 처음으로 통과해야 한다. 루틴 환경에서 SessionStart 훅이 실제로 실행되는지는 확인하지 못했다. 이 항목은 확인되지 않은 위험이다.

티켓 20260921_0841 재작업으로 값 판정이 바뀌었다. 이 저장소의 `.githooks`를 가리키는 절대경로도 정상으로 본다(상대경로 `.githooks`와 같다). 이 티켓은 착수할 때 그 새 기준으로 확인한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 루틴 세션에서 프로젝트의 `SessionStart` 훅이 실행되는지 확인한다. 실행되지 않으면 이 위험은 없는 것이므로 그 사실만 기록하고 닫는다.
- 실행된다면 루틴별로 커밋이 만드는 파일(리포트 등)이 `pre-commit` 검사를 통과하는지 확인한다. 통과하지 못하는 규칙이 있으면 루틴 프롬프트를 고칠지, 루틴 경로에 한해 예외를 둘지 정한다.
- **`pre-push`도 함께 확인한다 (2026-09-22 티켓 20260921_2304 머지로 추가됨).** 그 티켓이 `pre-push`에 기준 방어(경고를 끄는 주석·테스트 건너뛰기·테스트 파일 삭제·`--max-warnings` 상향 차단)와 staging 직접 push 차단(`wf_*` 워크트리, `claude/jamwork-*` 로컬 브랜치)을 넣었다. 분석상 루틴의 리포트 push는 걸리지 않아야 한다: 기준 방어는 `jam-web` 코드 파일만 보고, 목요일 무인 배포의 main push는 기준 방어 앞에서 빠져나간다. 다만 **클라우드 세션의 로컬 브랜치 이름이 `claude/jamwork-*`이면 staging push가 막힌다.** 실제 이름은 확인하지 못했다. 루틴이 `git push origin staging`을 실행할 때 훅이 통과하는지 함께 기록한다. 첫 확인 기회는 2026-09-28(월) 09:00 KST 주간 리포트다.

## 완료 조건

- 루틴 환경의 훅 실행 여부가 확인되어 완료 기록에 남아 있다(SessionStart 출력이나 커밋 시 훅 동작 로그 같은 근거와 함께).
- 훅이 실행되는 환경이면, 루틴 한 건 이상의 실제 산출물에 대해 `pre-commit` 통과 여부가 기록되어 있다.
- 같은 실행의 `pre-push` 통과 여부와 그 세션의 로컬 브랜치 이름이 기록되어 있다.
