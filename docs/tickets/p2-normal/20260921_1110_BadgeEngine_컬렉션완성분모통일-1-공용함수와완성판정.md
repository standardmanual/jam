# [BadgeEngine] 컬렉션 완성 분모 통일 ① 공용 함수와 완성 판정(checker·completable)

## 핵심 요약

- 요구사항: 공용 함수 `computeBookCompletion`을 만들고, 완성 판정·보상 발급을 하는 `checker.ts`와 `completable.ts`가 이를 쓰게 한다.
- 관련 파일: `jam-web/src/lib/itembook/completion-basis.ts`(신규), `lib/itembook/checker.ts`, `lib/itembook/completable.ts`, `lib/drop-engine/index.ts`(`buildBadgeIdsOfBook` 재사용), 신규 테스트
- 상위 티켓: 20260914_1130 (사용자 결정 2026-09-21: 「완성 판정과 보상까지 포함해 드랍 제외 배지를 분모에서 뺀다」)

## 배경 / 문제 정의

개별 배지 `badges.drop_excluded = true`는 컬렉션 완성 분모에서 제외한다는 정책(티켓 20260911_2236 확정)을 지금은 드랍엔진(`lib/drop-engine/index.ts`의 `buildBadgeIdsOfBook`)만 따른다. 완성 판정·보상 발급·화면 표시는 배지 전체를 센다. 사용자 결정으로 이 정책을 전 구간에 통일한다. 설계안의 공통 원칙은 아래와 같다.

- **분모**: 컬렉션 소속 배지에서 `drop_excluded = true`를 뺀 id 집합.
- **분자**: 사용자가 장착(`user_item_book_slots.badge_id`)했거나 획득한 배지 id 집합과 분모의 **교집합 크기**. 슬롯 개수(count)를 그대로 쓰지 않는다. 제외 배지를 이미 장착한 사용자가 조기 완성되거나 「9/8」이 되는 것을 막는다.
- **공용 함수**: `jam-web/src/lib/itembook/completion-basis.ts`의 순수 함수 `computeBookCompletion`. 입력은 `{id, item_book_id, type, drop_excluded}` 배지 목록과 채운 배지 id 집합, 옵션 `types`(예: item, item+checkin)다. 출력은 북별 `{denomIds, filledIds, total, filled, complete}`다. 분모는 `buildBadgeIdsOfBook`을 재사용한다(이 함수는 type을 보지 않으므로 호출 전에 types로 거른다).
- **사용자 결정으로 확정한 범위 밖 항목**: (1) 소프트 삭제 배지 처리가 위치마다 다른 문제(checker·completable은 삭제 배지를 분모에 포함, RPC·화면은 제외)는 이번에 통일하지 않는다. 별도 티켓 20260921_1114에서 다룬다. (2) checker의 catch-up 경로가 포인트를 지급하지 않는 현행 동작은 그대로 둔다. (3) 이미 완성 기록이 있는 사용자의 기록·보상은 건드리지 않는다.
- **의도된 동작**: 제외 배지를 보유하지 않은 채 나머지를 모두 장착한 사용자는 재계산으로 즉시 완성 처리된다(티켓 20260911_2236 확정).

## 상세 요구사항

### 서비스/코드베이스 관점
- `completion-basis.ts`에 공용 순수 함수를 만든다. 분자·분모 규칙은 위 원칙을 따른다.
- `checker.ts`: 배지 조회 select에 `drop_excluded`를 **컬럼으로만 추가**한다(서버 필터 `.eq('drop_excluded', ...)`는 넣지 않는다 — 제외 배지가 결과에서 빠져 분자 교집합 계산이 어긋난다). 기존 `range` 페이지네이션과 `.order('id')`는 유지한다. `badgeCountByBook`과 `slotCountByBook`의 개수 비교를 공용 함수로 교체한다. 슬롯은 `badge_id` 집합으로 만든다. 기존 완성 기록(`alreadyCompletedSet`)이 있는 사용자는 지금처럼 건너뛴다. 보상 배지 중복 방지(`user_activity_badges` 선조회와 `23505` 무시)는 그대로 둔다.
- `checker.ts`의 「분모는 소프트 삭제 여부와 무관하게 고정」 정책 주석(20260825_025)은 유지한다. 삭제 배지 처리는 이번 범위가 아니다.
- `completable.ts`: 이미 집합 기반이므로 분모를 공용 함수의 `denomIds`로 바꾼다.
- 슬롯 장착 RPC(`slot_item_into_book`)는 이 티켓에서 다루지 않는다(별도 티켓).

### 테스트
- `lib/itembook/completion-basis`의 단위 테스트를 신규로 만든다(checker·completable 전용 테스트는 지금 없다). 핵심 케이스: (a) 8개 중 제외 1개를 장착한 사용자는 분모 7 기준으로 계산되고 분자에 제외 배지가 들어가지 않는다, (b) 제외 배지를 미보유한 채 나머지를 모두 장착한 사용자는 완성이다, (c) 제외 배지가 없는 컬렉션은 기존과 결과가 같다, (d) 배지가 0개인 컬렉션은 완성이 아니다, (e) type 필터(item만 / item+checkin)가 분모에 반영된다.
- 기존 `lib/drop-engine/__tests__/badge-ids-of-book.test.ts`는 계속 통과해야 한다.

### 문서
- `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md`의 컬렉션 완성 규칙(§3.16, §3.1 완성 페이싱)에 「완성 분모는 드랍 제외 배지를 뺀다」를 현재 사실로 덮어쓴다. 이력을 본문에 쌓지 않는다.
- `docs/specs/prd/01_PRD.md`의 컬렉션 완성 서술(87행 부근)을 같은 기준으로 맞춘다.

### 구현 내용 요약
컬렉션 완성 분모·분자를 계산하는 공용 순수 함수 `computeBookCompletion`을 만들고, 완성 판정·보상 발급을 하는 `checker.ts`와 `completable.ts`가 이를 쓰게 했다. 분모는 `buildBadgeIdsOfBook`을 재사용해 드랍 제외 배지를 뺀 id 집합이고, 분자는 장착·획득한 배지 id와 분모의 교집합 크기다. `checker.ts`는 배지 select에 `drop_excluded`를 컬럼으로만 추가했고(서버 필터 없음) `range` 페이지네이션과 `order('id')`를 유지했다. 기존 완성 기록 건너뛰기, 보상 배지 중복 방지(`23505` 무시), 삭제 배지 정책 주석(20260825_025)은 그대로다.
