# [BadgeEngine] 컬렉션 완성 분모 보정: 등록된 배지가 전부 드랍 제외이면 등록 배지 전체를 분모로 쓴다

## 핵심 요약

- 결정(사용자, 2026-09-21): 컬렉션 완성 분모는 컬렉션 설정에 등록된 배지의 수를 기본으로 하되, 기존 정책(드랍 제외 배지를 뺀다)은 유지한다. **등록된 배지가 전부 드랍 제외라서 뺀 분모가 0이 되는 컬렉션만 예외로, 등록 배지 전체(소프트 삭제 제외)를 분모로 센다.**
- 배경: 슬롯 SQL 178을 jam-prod에 적용한 뒤 확인 쿼리에서, 드랍 제외 배지가 있는 컬렉션 「JAM! 레벨 0」이 18개 전부 제외라 분모가 0이 된다는 사실이 드러났다. 분모가 0이면 완성되지 않으므로 이 컬렉션은 완성 보상(`reward_points` 20)을 받을 수 없다. 지금은 장착한 사용자와 완성 기록이 0건이라 영향받는 사용자는 없다.
- 관련 파일: `jam-web/src/lib/itembook/completion-basis.ts`, `jam-web/src/lib/itembook/__tests__/completion-basis.test.ts`, 신규 마이그레이션 `179_*.sql`(슬롯 함수 `slot_item_into_book` 재정의), `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md`, `docs/specs/prd/01_PRD.md`
- 상위 티켓: 20260914_1130, 직전 작업 20260921_1110(공용 함수), 20260921_1111(슬롯 SQL 178)

## 상세 요구사항

### 서비스/코드베이스 관점
- **공용 함수 `computeBookCompletion`**: 북별로 `types` 필터를 건 뒤 배지 집합에서 드랍 제외를 뺀 분모가 **비어 있고** 그 북에 (types 필터 후) 등록 배지가 1개 이상이면, 분모를 「제외를 무시한 등록 배지 전체」로 바꾼다. 분자는 새 분모와 채운 배지 집합의 교집합이다. 분모가 비지 않으면 기존 동작 그대로다. 등록 배지가 0개인 컬렉션은 여전히 완성이 아니다.
- **슬롯 SQL 179**: 178의 `slot_item_into_book` 함수 본문에서 완성 체크 두 쿼리만 바꾼다. 소프트 삭제되지 않은 배지 중 제외가 아닌 배지 수가 0이면, 분모를 「제외 여부와 무관한 소프트 삭제되지 않은 배지 수」로, 분자를 같은 조건의 슬롯 배지 수로 센다. 함수 시그니처·`ON CONFLICT`·`ROW_COUNT` 중복 방지·포인트 지급·`REVOKE`/`GRANT`는 178과 동일하다(파라미터를 바꾸면 오버로드가 생긴다, `DEV_PROCESS_GUARDRAILS.md` 패턴 14). **SQL 파일 작성까지만 한다. 적용은 카리나가 한다.**
- **드랍엔진**(`lib/drop-engine/index.ts`의 `buildBadgeIdsOfBook`)은 바꾸지 않는다. 드랍 후보는 제외 배지를 빼는 것이 맞고, 이번 예외는 완성 판정·표시에만 해당한다.
- 소프트 삭제 배지 처리(`deleted_at`)는 이 티켓 범위가 아니다(20260921_1114).

### 테스트
- `completion-basis.test.ts`에 케이스를 추가한다: (f) 등록 배지가 전부 드랍 제외인 컬렉션은 등록 배지 전체가 분모이고, 전부 장착하면 완성이다, (g) 일부만 제외된 컬렉션은 기존과 같이 제외를 뺀다, (h) 전부 제외이지만 `types` 필터로 걸러 남은 배지가 없으면 완성이 아니다, (i) 등록 배지가 0개면 완성이 아니다.
- 기존 케이스(a~e)와 `badge-ids-of-book.test.ts`는 계속 통과해야 한다.

### 문서
- `BADGE_ENGINE_UNIFIED.md`의 컬렉션 완성 분모 서술(§3.3, §3.16)과 `01_PRD.md` 컬렉션 행에 「등록된 배지가 전부 드랍 제외이면 등록 배지 전체를 분모로 센다」를 현재 사실로 덮어쓴다. 이력을 본문에 쌓지 않는다.
