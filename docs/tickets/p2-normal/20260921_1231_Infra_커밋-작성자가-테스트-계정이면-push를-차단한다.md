# [Infra] 끝 커밋 작성자가 테스트 계정(@example.com)이면 push를 차단한다

## 핵심 요약

- 요구사항: push할 끝 커밋의 작성자·커미터 이메일이 `@example.com`이면 `.githooks/pre-push`가 push를 막는다. 대상은 staging과 main 모두다.
- 구현 계획: `pre-push`의 브랜치 루프 안에서 `local_sha` 커밋의 `%ae`·`%ce`를 검사한다. 차단 메시지에 원인과 해결 방법(전역 git 설정 확인, 커밋 재작성 여부)을 안내한다. `/jam-ship` 문서에 같은 검사가 있다고 한 줄로 참조만 남긴다.
- 관련 파일: `.githooks/pre-push`(브랜치 루프, 14행 이후), `.claude/skills/jam-ship/SKILL.md`(3절 main 승격), `scripts/verify.sh` 계약 검사 또는 훅 테스트(`scripts/*hook*.test.mjs`)

## 배경 / 문제 정의

- 확인한 사실: Vercel이 "t@example.com attempted to deploy a commit to Standard Manual ... not a member of the team" 오류를 냈다. 저장소 이력에 작성자·커미터가 `tester <t@example.com>`인 커밋이 여러 건 있다(예: `79997a5a`, `1df741d1`, `77138774`, `3d6180b1`).
- 확인한 사실: 원인은 테스트가 훅 환경의 `GIT_DIR`을 물려받아 실제 저장소 설정을 오염시킨 것이고, 커밋 `62eff343`(티켓 20260921_1116)에서 격리 검사와 함께 수정되었다. 수정 이후 커밋 4건은 `sihyunrr@gmail.com`으로 정상 기록되었다.
- 남은 위험: 다른 PC나 옛 상태의 클론에서 같은 오염이 재발하면, 오류가 Vercel에서 뒤늦게 나타난다. 승격 커밋의 끝이 `tester`로 찍히면 프로덕션 배포가 막힌다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 검사 대상은 push하는 ref의 끝 커밋 하나다. 과거 이력의 `tester` 커밋은 이미 원격에 있으므로 검사하지 않는다(이력을 다시 쓰지 않는다).
- 판정 규칙은 거부 목록 방식(`@example.com` 도메인)으로 한다. 허용 이메일 목록으로 바꾸면 작성자 정책이 바뀔 때마다 훅을 고쳐야 하므로 채택하지 않는다.
- 브랜치 삭제 push(`local_sha`가 전부 0)는 검사에서 제외한다.
- 우회 수단은 `JAM_SKIP_AUTHOR_CHECK=1`로 두되, 사유를 커밋 메시지에 남기게 안내한다.
- 새 환경 주장을 문서에 적으면 `docs/agents/contract.json`에 검사 줄을 함께 추가한다(CLAUDE.md 규칙 5).

### 작성자 이메일 통일안 (철회됨)

- 검토 중 사용자가 커밋 작성자를 `admin@j-a-m.app`으로 통일하는 안을 제안했으나, 같은 날 사용자가 철회했다. 작성자 이메일은 현재 값(`sihyunrr@gmail.com`)을 그대로 쓴다. 이 티켓의 범위는 차단 검사까지다.

## 구현 계획

1. `pre-push` 루프에서 삭제 push를 제외하고 `git log -1 --format='%ae %ce' "$local_sha"`를 읽는다.
2. 두 이메일 중 하나라도 `@example.com`으로 끝나면 원인과 해결 방법을 안내하고 종료 코드 1로 막는다.
3. 훅 테스트에 정상 작성자는 통과하고 `@example.com` 작성자는 차단되는 경우를 추가한다. 테스트는 `62eff343`의 환경 격리 방식을 따른다(실제 저장소 설정을 건드리지 않는다).
4. `/jam-ship` 3절에 "끝 커밋 작성자 검사는 pre-push가 수행한다"는 한 줄을 추가한다.

## 완료 조건

- 임시 저장소에서 작성자가 `t@example.com`인 커밋을 staging과 main으로 push하면 훅이 차단하고 안내 메시지를 출력한다.
- 작성자가 `sihyunrr@gmail.com`인 커밋은 기존과 같이 통과한다. 재현 경로: 훅 테스트의 두 경우.
- `JAM_SKIP_AUTHOR_CHECK=1`이면 검사를 건너뛰고 건너뛴다는 사실을 출력한다.
- `scripts/verify.sh`가 통과하고, 실제 저장소의 `git config`와 `core.bare`가 테스트 전후로 변하지 않는다.
