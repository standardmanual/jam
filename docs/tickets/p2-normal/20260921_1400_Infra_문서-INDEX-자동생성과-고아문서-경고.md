# [Infra] 문서 INDEX 자동 생성 · 새 고아 문서 경고 · 조사 결과 환류 규칙

## 핵심 요약

- 요구사항: karpathy의 LLM wiki 패턴을 검토한 결과, 요약 사본을 두는 별도 wiki는 만들지 않고(CLAUDE.md 규칙 5, 중복은 드리프트의 필요조건) 빠져 있던 세 가지만 보강한다
  1. frontmatter `description`을 모아 자동 생성하는 `docs/specs/INDEX.md`
  2. 새로 추가된 문서가 어디서도 링크되지 않으면 pre-commit이 경고 (기존 `--orphans` 조회를 재사용)
  3. 조사 결과 중 재사용할 결론은 티켓에만 두지 않고 specs·planning 문서로 환류하는 규칙 한 줄
- 구현 계획:
  - (1) `scripts/gen-doc-index.mjs` 신설. `scripts/gen-team-doc.mjs`의 생성 구간·`--check` 방식을 따른다. 생성물에 시각·난수를 넣지 않는다(재실행해도 같은 결과여야 `--check`가 성립한다). pre-commit에서 `--check`를 돌리고, 테스트 `scripts/gen-doc-index.test.mjs`를 함께 둔다(`verify.sh`가 `scripts/*.test.mjs`를 자동 실행한다)
  - (2) `scripts/doc-check.mjs`의 `findOrphans`를 `--staged` 검사에 연결한다. 이번 커밋에서 **새로 추가(A)된 문서**만 대상으로 하고 등급은 경고다. 기존 고아 11개는 건드리지 않는다(기준선 목록을 두지 않는 이 엔진의 원칙). **INDEX.md는 링크 출처에서 제외한다** — 제외하지 않으면 INDEX가 모든 문서를 링크해 고아 판정이 무의미해진다. 제외 목록은 설정(`scripts/doc-check.config.json`의 `orphans`)에서 읽고 엔진에 경로를 박지 않는다
  - (3) `.claude/skills/jam-work/SKILL.md` 분기표의 `research` 행 절차에 한 문장 추가, `references/handling-rules.md` 카리나 표에 한 행 추가
- 관련 파일:
  - `scripts/gen-team-doc.mjs` (생성 구간·`--check` 참고 구현)
  - `scripts/doc-check.mjs` (`collectDocGraph`·`findOrphans` 약 623~690줄, `--staged` 진입점)
  - `scripts/doc-check.config.json` (`scope`, `orphans`, `severity`)
  - `.githooks/pre-commit` (⑧ 블록, 약 175~192줄: `gen-team-doc.mjs --check` 옆에 추가)
  - `docs/agents/contract.json` (새 스크립트·문서 존재 주장은 검사 줄과 함께 추가, 규칙 5)
  - `docs/specs/DOCUMENT_SCHEMA.md` (INDEX.md의 `type`·frontmatter 규칙 확인)
  - `CLAUDE.md`는 수정하지 않는다(사용자 소유 지침). INDEX 링크 연결이 필요하면 완료 보고에 제안만 남긴다

## 배경 / 문제 정의

- 새 세션의 읽기 순서를 CLAUDE.md가 손으로 나열한다. 문서가 2,000여 개라 낡기 쉽고, 어떤 문서가 있는지 한눈에 보는 목록이 없다
- 고아 문서 조회(`--orphans`)는 있으나 어떤 검사에도 연결돼 있지 않아, 링크 없이 추가된 문서를 아무도 알아채지 못한다
- 세션에서 조사한 결론이 대화와 티켓에만 남아 다음 세션이 다시 조사한다

**조사로 확인한 사실**: 끊긴 링크는 pre-commit(`doc-check.mjs`)이 이미 오류로 차단한다. 따라서 "끊긴 링크 검사 추가"는 이 티켓의 범위가 아니다. 현재 고아 문서는 `node scripts/doc-check.mjs --orphans` 실측 11개다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 서비스 코드(`jam-web/`)는 건드리지 않는다
- INDEX 대상은 `docs/specs/`·`jam-doc/planning/`·`jam-doc/marketing/`의 문서다. 티켓·`jam-doc/archive/`·`jam-doc/assets/`·`jam-doc/operations/reports/`는 제외한다(폴더 수명주기 규칙)
- INDEX 각 항목은 경로 링크 + `description` 한 줄이다. 폴더별로 묶고 정렬 순서를 고정한다
- INDEX.md 자체도 frontmatter(`type`, `description`)를 갖추고, 사람이 손으로 고치지 않는 자동 생성 파일임을 본문에 밝힌다
- (2)의 경고 문구는 어떤 파일이 어디서도 링크되지 않았는지 알려 주고, 어디에 링크를 걸면 되는지 한 줄로 안내한다
- 모든 새 사실 주장은 `docs/agents/contract.json`에 검사 줄을 함께 추가한다

### 완료 조건

- `node scripts/gen-doc-index.mjs`를 두 번 실행해도 결과가 같고, `--check`가 최신 여부를 판정한다
- INDEX가 오래됐으면 pre-commit이 차단한다
- 링크 없는 새 문서를 추가하면 경고가 나오고 커밋은 통과한다. 기존 11개 고아 문서로는 경고가 나오지 않는다
- INDEX.md가 링크 출처로 세어지지 않는다(INDEX만 링크한 문서는 여전히 고아로 판정)
- `scripts/verify.sh` 통과
