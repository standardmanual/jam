# [Infra] CLAUDE.md 축소 — 이력 서사와 중복 표를 빼고 규칙만 남긴다

## 핵심 요약

- 요구사항: 프로젝트 `CLAUDE.md`는 13,209바이트이고 서브에이전트 8명 전원이 호출마다 받는다(2207 §2.5). 분리·재통합 경위 같은 이력 서사와 다른 문서에 있는 표의 중복을 `team-operations.md`·티켓으로 옮기고, 규칙·문서 체계·읽기 순서만 남긴다. 문서 속 크기 수치("호출당 약 8.4KB")는 없애고 `contract.json`의 낡은 문구 검사에 등록한다. 목표 크기는 사용자 결정(제안: 8,000바이트 이하). 유형은 `docs`이지만 규칙 문서라 티켓으로 처리한다.
- 구현 계획: 절별로 「유지 / 이동(어디로) / 삭제」 표를 먼저 만들어 사용자 확인 → 이동 → 크기 측정 → `stale_phrases`에 "약 8.4KB" 등록 → `SKILL.md`·`05_자동화목록.md`(동결 전이면)·`08_인수인계.md`의 수치 정정.
- 관련 파일: `CLAUDE.md`, `docs/agents/team-operations.md`, `docs/agents/contract.json`(`stale_phrases`), `.claude/skills/jam-work/SKILL.md`(참고 절 267행 부근), `docs/agents/orchestrator.md`(카리나 전용 내용의 이동 대상). 참고 스킬: agent-skills `context-engineering`(무엇이 규칙 파일에 속하는가)
- 상위 티켓: 20260921_2207(#6). 경로: 카리나 직접(docs) 또는 ③ 표준. 절 이동은 판단이 많아 카리나가 표를 만들고 사용자 확인 후 진행한다.

## 배경 / 문제 정의

서브에이전트에 `CLAUDE.md`를 선택적으로 빼는 기능이 없어(team-operations §9 ⑤) 파일 크기가 곧 모든 호출의 고정 비용이다. 사용자 결정(2026-09-21)으로 각 스킬의 상세 내용을 에이전트 정의에 최대한 이식할 예정이라 정의 파일은 커진다. 그만큼 공통 파일에서 이력 서사를 덜어내야 호출당 비용이 유지된다. 이력은 git과 티켓이 보관한다(CLAUDE.md 「폴더 = 수명주기」 원칙과 같다).

## 상세 요구사항

### 서비스/코드베이스 관점

- 유지: 절대 규칙 6개(본문은 짧게, 근거 사례는 티켓 참조로), 팀 구성 표, 작업 진행 방식 표, 문서 체계 표와 폴더 수명주기 표, 읽기 순서.
- 이동 후보: 규칙 5의 "이 규칙이 생긴 이유" 인용 블록(→ team-operations §8 사고 이력), 문서 체계 개요의 분리·재통합 서사 두 문단(→ 티켓 20260920_1412 이미 기록), Agent skills 절의 설명문(→ team-operations 참조 한 줄), CLAUDE.md 자동 포함 설명(→ team-operations §9 ⑤).
- 검사: `doc-check`·`check-contract`·`gen-team-doc --check` 통과. 서브에이전트가 반드시 알아야 할 규칙이 빠지지 않았는지 아현·민지 정의가 참조하는 항목 목록과 대조한다.
- 수치: 변경 전후 바이트 수를 완료 기록에 남긴다. 문서 어디에도 크기 수치를 적지 않는다.

## 완료 조건

- `CLAUDE.md`가 목표 크기 이하이고(사용자가 정한 값, 기본 제안 8,000바이트), 유지 항목이 모두 남아 있다.
- 이동한 내용이 대상 문서에 있고 원문 링크가 남아 있다(`doc-check` 통과).
- `contract.json` `stale_phrases`에 "약 8.4KB"가 등록되어 있고 저장소에서 그 문구가 사라졌다(`check-contract` 통과).
- 아현·민지 정의가 참조하는 규칙 항목이 CLAUDE.md 또는 그 정의 파일 안에 남아 있다(대조표를 완료 기록에).
