## 2. 최적화 안 — 효과 순

### A. `plan_only` 왕복 제거 (효과 최대, 코드 변경 없음)

**문제**: 임계값(파일 5개 초과 또는 100줄 이상)이 낮아 4건 중 1건이 걸린다. 걸리면 아현이 탐색만 하고 돌아오고, 면제 후 2차 호출에서 같은 탐색을 다시 한다. 최근 3건(1521·1522·1523)은 카리나가 만든 이식 티켓이라 처음부터 클 것이 예측 가능했다.

**안**: `SKILL.md` 1단계(사전 준비)에 **카리나의 규모 사전 판정**을 넣는다.
- 티켓을 만들 때 「관련 파일」을 세고, 5개를 넘길 것 같으면 (a) 티켓을 쪼개거나 (b) 「구현 계획」을 파일 단위로 적고 **첫 호출부터 `planOnlyWaiver`를 넘긴다**(stop-conditions.md 면제 조건 (a)(b)를 그대로 충족).
- 아현의 `plan_only`는 안전망으로 남긴다 — 카리나 판정이 틀렸을 때만 발동한다.
- 2차 호출 프롬프트에 1차의 계획을 그대로 넣는 규칙은 이미 있다(3.0절). 여기에 "1차에서 읽은 파일 목록"도 함께 넘겨 재탐색을 줄인다.

**기대**: 해당 티켓에 한해 8~11만 토큰·4~5분 절감. 전체 평균으로 약 2만 토큰/티켓.

### B. `verify.sh` 3중 실행 → 로컬 1회 + CI, 아현의 CI 대기 이관 (속도 효과 최대)

**문제**: 같은 검사를 아현 로컬·pre-push·CI에서 세 번 돌리고, 아현은 CI가 끝날 때까지 약 3분을 기다린다.

**안**:
1. `.githooks/pre-push` — `wf_*` 워크트리에서 `claude/jamwork-*`로 push할 때는 전체 `verify.sh`를 건너뛰고 **규칙 검사만** 남긴다(`eslint-disable` 사유·`it.skip`·`--max-warnings`·테스트 삭제 사유·staging 차단). CI가 도장을 찍으므로 결과가 빠지지 않는다. 카리나가 메인 트리에서 staging으로 push할 때는 지금처럼 전체를 돌린다(staging push에는 CI가 없다 — team-operations §9-⑦).
2. `jam-developer.md` — CI를 기다리지 않는다. push 후 run URL만 `검증 결과`에 적고 바로 반환한다.
3. `jam-reviewer.md` 점검표 1번 — CI가 아직 도는 중이면 티켓·diff 판독을 먼저 하고 **마지막에** 상태를 확인한다(최대 5분 대기). 실패면 CI 로그를 근거로 FAIL.

**위험**: 로컬 `verify.sh`가 통과했는데 CI만 실패하는 경우 재작업이 한 번 생긴다. 같은 스크립트·같은 커밋이라 드물고, 그때는 `gateOnly` 경로로 카리나가 패치한다.

**기대**: pre-push 1~2분 + 아현 대기 3분 ≈ **티켓당 3~4분 단축**(표준 티켓 15~20분의 20~25%). 민지·채원②가 CI와 병렬로 읽기 시작하므로 전체 임계 경로가 짧아진다.

### C. 고정 로딩 슬림화 — 이력 서사를 원장으로 옮긴다

**원칙**: 정의·CLAUDE.md·SKILL.md에는 **규칙만** 남기고, "왜 이렇게 됐나"(티켓 번호·날짜·사고 경위)는 이미 사고 원장 역할을 하는 `team-operations.md` §8로 옮긴다. `check-contract.mjs`가 있어 서술이 낡는 위험은 기계가 잡는다.

### D. 아현 요약 길이를 스키마로 강제 (티켓 20260922_0620 실행)

`DEV_RESULT.summary`에 `maxLength`를 걸어 diff 원문이 들어올 수 없게 한다. 프롬프트 규칙(30줄)은 세 번 연속 뚫렸다(§8 패턴: 프롬프트로 막은 건 뚫리고 훅·스키마로 막은 건 안 뚫린다). 이 요약은 카리나 컨텍스트·민지 프롬프트·채원② 프롬프트 세 곳에 그대로 들어가므로 한 번 새면 세 배로 든다.

### E. 하지 않기로 한 것

- **워크트리 이중 체크아웃 제거**: 하네스가 `main` 기준으로 만드는 것은 바꿀 수 없고, 재체크아웃 비용은 수 초라 손대지 않는다.
- **민지·채원② 통합**: 이미 병렬이라 시간 이득이 없고, 독립 컨텍스트에서 판정하는 이점을 잃는다.
- **게이트 모델 하향**: 판정 품질 위험이 절감액보다 크다.
- **에이전트 수 축소**: 부르지 않으면 비용이 없다.
