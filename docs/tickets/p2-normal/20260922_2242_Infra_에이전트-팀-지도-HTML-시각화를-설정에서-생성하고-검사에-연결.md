# [Infra] 에이전트 팀 지도 HTML 시각화 — 정의·워크플로·훅에서 생성하고 낡으면 커밋을 막는다

## 핵심 요약

- 요구사항: 새로 구축한 워크트리 구조, 에이전트 9인의 역할, 에이전트 간 연결(누가 누구를 부르는가), 호출 콜사인(`jam-*` 에이전트 이름과 `/jam-*` 스킬)을 한 화면에서 상시 확인할 수 있는 HTML을 `docs/agents/team-operations.md` 옆에 두고, 변경이 있으면 항상 갱신되게 한다. `docs` 유형, 카리나 직접.
- 구현 계획: 손으로 그린 HTML은 정의가 바뀌는 순간 낡으므로 `gen-team-doc.mjs`와 같은 원칙으로 **생성**한다. ① `scripts/gen-team-map.mjs` — `.claude/agents/*.md` frontmatter·`contract.json` `agents`·`.claude/workflows/jam-work.js`(`meta.phases`, `agent()` 호출, `isolation`, 병렬)·`.claude/skills/jam-*/SKILL.md`·`.claude/settings.json` 훅·`.githooks/`의 차단 장치·`team-operations.md`의 §3·§5·§6 표에서 `docs/agents/team-map.html`을 만든다. `--check`는 최신이 아니면 종료 코드 1 ② pre-commit ⑧·`verify.sh`·CI 가벼운 경로에 `--check` 연결 ③ `contract.json` `paths_exist` 등록 ④ `team-operations.md` 갱신 규칙 상자와 §10에 안내 ⑤ 테스트 `scripts/gen-team-map.test.mjs`
- 관련 파일: `scripts/gen-team-map.mjs`(신규, `collect()`·`renderHtml()`), `scripts/gen-team-map.test.mjs`(신규), `docs/agents/team-map.html`(생성물), `.githooks/pre-commit`(⑧ 검사 블록), `scripts/verify.sh`(team-doc 단계 뒤), `.github/workflows/verify.yml`(가벼운 검증 단계), `docs/agents/contract.json`(`paths_exist`), `docs/agents/team-operations.md`(갱신 규칙 상자·§10 표)

## 배경 / 문제 정의

티켓 20260922_1749·1754·1800으로 에이전트 R&R과 워크트리 격리 구조가 정리됐지만, 그 결과를 보려면 `team-operations.md` 400줄·정의 파일 8개·`jam-work.js`·훅을 나눠 읽어야 한다. 사용자(디자이너)가 "누가 어떤 콜사인이고 누구를 부르며 어디서 도는가"를 한 장으로 보는 화면이 없었다. 손으로 그린 그림을 두면 규칙 5(확인한 결과만 적는다)와 "중복은 드리프트의 필요조건" 원칙에 정면으로 어긋나므로, 그림 자체를 근거에서 생성하고 낡으면 기계가 막게 해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **생성기**: 시각·난수를 넣지 않아 같은 저장소 상태에서 항상 같은 HTML이 나온다(`--check` 성립 조건). 외부 스크립트·폰트·CSS 없이 단일 파일로, `file://`로 열려야 한다. 라이트·다크 모두 지원.
2. **화면 구성**: ① 팀 카드 9장(이름·콜사인·역할·모델·도구·쓰기 권한·평소 관여·격리 여부·부르는 스킬) ② 카리나 중심 호출 관계도 SVG(서브에이전트끼리의 간선은 없다 — 서로를 부를 도구가 없다는 사실을 그대로 보인다. 예약 루틴의 "A → B" 담당만 점선) ③ 표준 파이프라인(`meta.phases` 순서, 칸 안의 `agent()` 호출, 격리·병렬·모델 덮어쓰기 표시) + 경로 3단 표 ④ 워크트리·브랜치 구조(메인 폴더 / `wf_*` 격리 워크트리 / GitHub·Vercel 세 레인) + 훅이 실제로 막는 것 + 머지·배포 경계 표 ⑤ 스킬 콜사인 표(`SKILL.md`가 이름으로 언급하는 서브에이전트; `jam-developer.md`처럼 정의 파일을 가리키는 언급은 세지 않는다) ⑥ 접근 범위 표 ⑦ 예약 루틴 표.
3. **검사 연결**: 낡은 HTML은 pre-commit·`verify.sh`·CI 가벼운 경로 세 곳에서 모두 잡힌다. `team-operations.md`의 표 제목(`## 3.`·`### 머지와 배포의 경계`·`## 5.`·`## 6.`)이 사라지면 생성기가 종료 코드 2로 알린다.

### 주요 의사결정 / 핵심 메모
- **손으로 그리지 않고 생성한다.** 요청은 "항상 변경 사항이 있으면 업데이트"였다. 사람이 기억해 갱신하는 방식은 규칙 5와 §9 빈틈 ①의 재발이므로, 생성기 + `--check` 3중 연결로 "갱신을 잊으면 커밋이 막히는" 구조로 만들었다.
- **현재 워크트리 목록은 싣지 않는다.** `git worktree list`는 세션마다 바뀌는 실행 상태라 넣으면 `--check`가 항상 실패한다. 지도는 워크트리 *구조*(메인 폴더·`wf_*` 격리·리뷰 브랜치·차단 장치)를 보이고, 순간의 목록은 `git worktree list`로 본다.
- **사람이 관리하는 표(§3·§5·§6)는 `team-operations.md`에서 그대로 옮긴다.** 접근 범위·예약 루틴은 설정 파일에 기계로 읽을 근거가 없어 문서 표가 단일 원천이다. HTML은 그 표의 사본이지만 생성물이므로 드리프트가 생기지 않는다.
- 세션 훅 설명문(`gen-team-doc.mjs`의 `explain` 표)은 옮겨 적지 않고 스크립트 이름만 싣는다 — 같은 문장을 두 생성기에 두면 중복이다.

### 잔여 이슈
- `--open`은 macOS `open`에 의존한다. 다른 OS에서는 파일을 직접 연다.
- 호출 관계도는 8인 고정 배치가 아니라 인원수로 원을 나누므로 에이전트가 늘어도 그려지지만, 12인을 넘으면 노드가 겹친다. 그때 반지름·크기를 조정한다.
