# [Infra] 워크트리 `node_modules` 심볼릭 링크가 `npm install`류 작업에 부적합 — 메인 체크아웃 일시 손상 사례

## 핵심 요약

- 요구사항: `scripts/workspace-setup.sh link`가 워크트리에 만드는 `node_modules` 심볼릭 링크는 메인 체크아웃과 물리적으로 같은 디렉터리를 가리킨다. 이 링크를 유지한 채 워크트리에서 `npm install`/`npm audit fix`처럼 `node_modules`를 변형(mutate)하는 명령을 실행하면 메인 체크아웃의 `node_modules`가 함께 깨진다. `db`처럼 `infra`도 실행 전 전용 처리가 필요한 유형으로 다뤄야 한다.
- 구현 계획: (착수 전 검토 필요 — 아래 참고)
- 관련 파일: `scripts/workspace-setup.sh`(`link_node_modules` 함수), `.claude/agents/jam-developer.md`(첫 명령 지시), `.claude/skills/jam-work/SKILL.md`(1단계 규모 사전 판정과 함께 검토)

## 배경 / 문제 정의

티켓 20260922_2321(Next.js 등 npm audit 상향) 구현 중 아현이 `npm audit fix --force`를 실행하자, 하네스가 연결한 심볼릭 링크(메인 체크아웃 `jam-web/node_modules`와 공유)를 통해 메인 체크아웃의 물리 `node_modules`가 함께 변형됐다 — `next`·`sharp` 폴더가 유실되고 `esbuild` 바이너리 검증이 실패했다. 아현이 `node_modules/esbuild`만 지우고 `npm install`로 메인 체크아웃을 원상 복구했으며, 카리나가 2026-09-23 직접 확인해 `next@16.2.10`·`sharp@0.35.3`·정상 `npm ls` 결과를 확인했다 — 사용자 개발 환경 영향 없음.

`git` 추적 파일(`package.json`·`package-lock.json`)은 워크트리 안에서만 바뀌므로 손상되지 않았지만, `node_modules`는 파일시스템 링크로 직접 공유돼 원인 파일과 무관하게 영향을 받는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `npm install`/`npm ci`/`npm audit fix`처럼 `node_modules`를 변형하는 명령이 필요한 `infra` 티켓은 심볼릭 링크를 쓰지 않고 워크트리 안에서 독립적으로 `npm install`하도록 아현 정의 또는 `workspace-setup.sh`의 안내를 바꾼다.
- 판단 지점: 링크를 계속 쓸지(변형 명령 금지 안내만 추가) 아니면 `infra` 유형은 기본적으로 독립 설치로 전환할지 — 아현의 alerts 제안(「다음에 유사 티켓을 배정할 때는 link 대신 독립 설치를 기본으로 하거나, 하네스 지시를 이 경우엔 건너뛰도록 조정」)을 출발점으로 검토한다.

## 완료 조건
- `npm install`류 명령을 쓰는 `infra` 티켓에서 메인 체크아웃 `node_modules`가 영향받지 않는 절차(링크 대신 독립 설치, 또는 명시적 경고+수동 확인)가 정의돼 있다.
- 재현 확인: 유사 티켓을 하나 만들어 절차대로 처리했을 때 메인 체크아웃 `node_modules`가 그대로임을 확인한다(또는 다음 `db`/`infra`류 npm 변경 티켓에서 자연히 확인).
