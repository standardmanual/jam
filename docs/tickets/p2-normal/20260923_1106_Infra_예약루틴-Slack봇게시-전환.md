## 배경 / 문제 정의
20260918_1154에서 클라우드 예약 루틴이 claude.ai에 연결된 **사용자 계정용 Slack 커넥터**
(`connector_uuid 1d4ae418-...`)로 글을 올리는 구조를 만들었는데, 이 방식은 게시자가 항상
사용자 본인 계정으로 표시된다("Claude를 사용하여 보냄" 표시만 붙음). 사용자가 이를 원치 않아
별도 Slack 앱("JAM 봇")을 만들어 전용 Bot Token을 발급받았다. 이제 예약 루틴이 이 봇 토큰으로
직접 API를 호출해 봇 계정 이름으로 게시하도록 저장소 쪽 스크립트와 문서를 바꾼다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `scripts/slack-post.mjs`는 CLI 인자 또는 환경변수로 채널 ID와 메시지 텍스트를 받아
  `https://slack.com/api/chat.postMessage`를 `Authorization: Bearer $SLACK_BOT_TOKEN`으로
  호출한다.
- 채널 ID는 `#jam-alert` (`C0C2S11PPRQ`), `#jam-report` (`C0C2U1T186M`) 두 곳만 쓴다
  (`automation-list.md` "Slack 채널" 절이 이미 단일 원천이므로 스크립트에 하드코딩하지 않고
  호출부에서 인자로 넘긴다).
- API 응답의 `ok` 필드가 `false`면 `error` 값을 그대로 노출하고 비정상 종료한다(예:
  `not_in_channel`이면 봇이 채널에 없다는 뜻이므로 원인을 바로 알 수 있어야 한다).
- 토큰 값 자체는 로그에 찍지 않는다(`deploy-gate.mjs:55`와 같은 원칙 — 출력에는 값이 아니라
  종류만 적는다).

## 구현 계획
> 1차 시도(아현)가 시험 구현·검증까지 마친 뒤 `plan_only`로 반환한 계획을 그대로 옮긴다.
> 계획 반환 면제 사유는 「주요 의사결정」 참고.

1. `scripts/slack-post.mjs` (신규, 약 85줄) — `scripts/admin-api-read.mjs` 스타일(상단 사용법
   주석, `process.env`로 인증값 읽기). `--channel`·`--text` 인자를 파싱해 `SLACK_BOT_TOKEN`으로
   `https://slack.com/api/chat.postMessage`를 `Authorization: Bearer` 헤더로 호출한다.
   테스트에서 재사용할 수 있도록 `postToSlack({channel, text, token, fetchImpl})`을 export하고,
   실행 가드는 `scripts/ga4-weekly-metrics.mjs` 191-195행과 같은 `fileURLToPath` 비교 방식을
   쓴다. 토큰 미제공 / 채널·텍스트 누락 / 응답 `ok:false`는 각각 한 줄 안내 후 종료 코드
   1(`fail()` 헬퍼). 토큰 값 자체는 로그에 찍지 않는다(`deploy-gate.mjs:55` 원칙).
2. `scripts/slack-post.test.mjs` (신규, 약 65줄) — `scripts/ga4-weekly-metrics.test.mjs` 패턴을
   따른다. (a) 모의 `fetchImpl`로 `chat.postMessage` 호출 인자(Authorization 헤더·channel·text)와
   정상 응답 처리를 검증. (b) `spawnSync`로 `SLACK_BOT_TOKEN` 없이 `--channel`·`--text`만 넘겨
   실행했을 때 종료 코드 1·stderr 1줄·`SLACK_BOT_TOKEN` 문구 포함을 검증.
3. `scheduled-jobs.md` 4개 지점 교체(총 +9/-7줄 예상):
   - 14행: "커넥터는 Slack만 붙인다" → 환경변수 목록에 `SLACK_BOT_TOKEN` 추가
   - 35-37행: 클라우드 환경 등록 비밀 값 목록에 `SLACK_BOT_TOKEN` 추가
   - 113-116행: `connector_uuid` 서술 → `scripts/slack-post.mjs` 사용법. "사용자 계정 이름으로
     게시" → "게시자는 JAM 봇 계정"(카리나가 5-4에서 표시 대신 작성자가 봇 계정인지로 구분)
   - 320행 부근: "커넥터 Slack만 붙임" → `SLACK_BOT_TOKEN` 등록
   새 문구는 "루틴은 `scripts/slack-post.mjs`로 `SLACK_BOT_TOKEN`을 써서 직접 게시한다"는
   사실과 "게시자는 JAM 봇 계정이다"는 사실을 분리해서 적는다(CLAUDE.md 사실/판단 분리 원칙).
4. 완료 조건 재확인(1차 시도에서 시험 구현으로 이미 통과 확인):
   `node scripts/slack-post.mjs --channel C0C2S11PPRQ --text 테스트`를 `SLACK_BOT_TOKEN` 없이
   실행 → 안내 1줄 + 종료 코드 1. `grep -n "connector_uuid\|사용자 계정 이름으로 게시\|커넥터는
   Slack만\|커넥터 Slack만" scheduled-jobs.md` → 결과 없음. `scripts/verify.sh` 전체 통과.
5. 실제 테스트 게시(클라우드 루틴 환경변수 등록·클라우드에서 1회 시범 호출)는 외부 발행이라
