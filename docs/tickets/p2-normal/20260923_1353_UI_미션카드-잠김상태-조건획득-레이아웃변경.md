# [UI] 미션 카드 — 잠김/상시 상태 + 조건/획득 행 레이아웃 변경

## 배경 / 문제 정의
현재 미션 카드는 "미션명 → (잠김 시) 안내 문장 한 줄 → 등급 텍스트/등급칩 → 보상 배지명" 순으로
표시된다. 참가 조건이 되는 선행 배지 정보(등급 포함)는 이미 서버에서 계산돼 내려오지만 카드에
문장 형태("앞 단계 배지를 먼저 획득하면 참가할 수 있어요")로만 노출되고, 정작 조건 배지의
이름·등급은 카드에 보이지 않는다. 사용자는 미션의 잠김 여부, 조건 배지, 보상 배지를 한눈에 비교할
수 있는 구조를 원한다.

## 상세 요구사항

### UI/UX 관점
- 카드 상단: 현재 여러 칩(잠김·NEW·참가완료·상시/종료 태그)이 섞여 있는 meta-row를 정리해,
  최소한 "잠김" 또는 "상시" 상태를 하나의 라벨로 보여준다. `NEW`/`참가완료` 등 기존에 이미
  의미가 확정된 다른 상태 라벨과의 우선순위·동시 노출 여부는 채원① 판정 시 확정한다.
- 미션명(`<h3>`)은 그대로 두 번째 줄에 유지한다.
- "조건" 행: 라벨 "조건" + 등급칩(`RarityBadge`/`BadgeLevelChip`) + 선행 배지명
  (`requiredBadge.name`/`rarity`). 선행 배지가 없는(잠김 조건이 없는) 미션에서는 이 행을
  생략한다.
- "획득" 행: 라벨 "획득" + 등급칩 + 보상 배지명. 기존 `rewardBadgeNode()` 로직을 그대로 재사용해
  라벨만 "획득"으로 붙인다.
- 잠김 안내 문장(`lockedHintText()`)은 "조건" 행이 그 역할을 대신하므로 카드에서 제거한다.
- 정확한 여백·타이포·아이콘 등 시각 디테일은 채원①(디자이너)이 MODULAR 기존 패턴과의 정합성을
  보고 판정한다 — 이 티켓은 정보 구조(상태/미션명/조건/획득 4단)만 확정한다.

## 완료 조건
- 참가 조건이 있는(잠김) 미션 카드에서 "조건" 행에 선행 배지의 등급칩과 이름이 정확히
  표시된다. 재현 경로: `/missions`에서 아직 조건을 채우지 못한 잠김 미션 카드 확인.
- 참가 조건이 없는 미션 카드에서는 "조건" 행이 아예 렌더링되지 않는다.
- 모든 미션 카드에서 "획득" 행에 보상 배지의 등급칩과 이름이 기존과 동일하게(정보 손실 없이)
  표시된다.
- 카드 상단에 잠김/상시 상태가 하나의 라벨로 보이며, 기존 "앞 단계 배지를 먼저 획득하면
  참가할 수 있어요" 같은 잠김 안내 문장은 더 이상 카드에 남지 않는다.
- `npm run typecheck`, `npm run lint`(jam-web) 통과.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
미션 카드 meta-row를 잠김/상시/참가중/완료/시작전을 각각 별도 칩으로 보여주던 방식에서
`topStatusLabel()`(신규, 기존 `statusLabel()`/`periodText()`/`StatusBadge`/`JoinedBadge` 재사용해
우선순위대로 하나만 병합) 단일 라벨로 교체했다. 그 아래 미션명·설명문(기존 위치·노출 그대로
유지, 사용자 승인)에 이어 "조건" 행(신규 로컬 헬퍼 `conditionBadgeNode()` + `RarityBadge` 재사용,
중립색)과 "획득" 행(기존 `rewardNodes()` 그대로, 강조색)을 4~5단으로 배치했다. `requiredBadge`가
없는 잠김 미션(v5 게이트 미션 등)은 조건 행 자리에 칩 없이 기존 `lockedHintText()`의 범용 안내
문구를 그대로 남기도록 해 정보 손실을 막았다. `RarityBadge`·`BadgeLevelChip`·`StatusBadge`·
`JoinedBadge` 등 기존 컴포넌트만 재사용했고 MODULAR 신규/확장은 없었다.

### 주요 의사결정 / 핵심 메모
- 채원① 사전 판정이 "설명문(m.description)을 카드 목록에서 완전히 제거"를 제안했으나, 티켓
  완료 조건에 없던 범위 확대이고 비잠김 카드의 기존 노출 정보까지 줄이는 변경이라 사용자에게
  별도 확인했고, 사용자는 반려(설명문 유지)했다. 상태 라벨 우선순위 병합과 조건/획득 행 색상
  분리(오렌지=보상 신호와 혼동 방지)는 채원 제안대로 승인했다.
- 1차 구현에서 `requiredBadge`가 없는 잠김 미션(v5 게이트 미션, `gate_axis`/`visibility_rule_json`
  기반)은 항상 `requiredBadge: null`이라는 사실을 채원① 사전 판정과 아현 구현 양쪽 모두
  놓쳤다 — 기존 `lockedHintText()`(범용 잠김 안내 문구)를 통째로 삭제해 이 케이스의 잠김 사유
  안내가 카드에서 사라지는 회귀가 발생, 게이트 FAIL로 잡혔다. 2차 시도에서 `requiredBadge` 유무로
  분기해 없으면 칩 없이 범용 문구를 남기는 방식으로 해결했다.
- 2차 시도는 게이트 WARN(완료 조건 전부 충족하나 이번에 실제로 회귀가 났던 분기에 회귀
  테스트가 없음 — 저장소 전체에 컴포넌트 렌더 테스트 관례 자체가 없어 진행은 막지 않음)과
  채원② 사후 리뷰의 디자인 토큰 미준수 2건(fontSize/lineHeight/marginRight 하드코딩)을
  받았다. 토큰 위반은 파일 1개·8줄 이내 기계적 치환이라 아현을 다시 부르지 않고 카리나가
  직접 패치한 뒤 "게이트만 재실행"(`gateOnly`)으로 민지·채원②만 다시 불러 PASS를 받았다.

### 잔여 이슈
- 이번 회귀가 발생했던 지점(`requiredBadge` 유무에 따른 조건 행 분기)에 자동화된 회귀
  테스트가 없다(게이트 WARN 사유). 저장소 전체에 React 컴포넌트 렌더 테스트 인프라
  (`@testing-library/react`, jsdom 등)가 없어 이 티켓 범위에서는 추가하지 않았다 — 필요하면
  테스트 인프라 도입을 별도 티켓으로 검토한다.
