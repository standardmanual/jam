# [API] 외부 입력 연동 — 기상청 단기예보·특일정보 API

## 핵심 요약

- 요구사항: 오늘 날씨 구분(맑음·비·극한)과 공휴일·기념일을 서버에서 받아 세그먼트 태그(날씨·기념일)로 쓸 수 있게
  한다. API 실패 시 태그가 빠질 뿐 오류가 나지 않아야 한다. PRD §5·§7.1.
- 구현 계획: `jam-web/src/lib/inputs/`에 날씨·특일 모듈을 두고 하루 단위 캐시로 호출 수를 제한한다. 결과를
  `computeUserExposureTags`의 입력으로 연결한다.
- 관련 파일: `jam-web/src/lib/inputs/`(신규), `jam-web/src/lib/today/exposure.ts`, 환경변수 문서
  `docs/specs/prd/04_PROJECT_SPEC.md`. 스펙: `docs/specs/prd/content-automation/PRD.md` §5·§7.1.

## 배경 / 문제 정의

유형 T01(날씨·시간·장소 조합 컬렉션 소개)·T04(시즌×트라이브)·T08(날씨 기반 즉시 추천)은 날씨와 기념일 입력이 없으면
만들 수 없다. 2026-09-23 조사에서 기상청 API 허브와 특일정보 API(공공데이터포털)는 인증키로 자동 수집이 가능한
것으로 확인했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 기상청 API 허브 단기예보에서 서울 기준(1단계) 오늘 날씨 구분을 받는다. 지역 확장은 후속.
- 특일정보 API에서 오늘의 공휴일·기념일·24절기를 받는다.
- 하루 1회 캐시. 실패 시 이전 값이나 "없음"으로 처리하고 카드 생성은 계속된다(graceful degradation).
- 인증키는 환경변수로 관리하고, 키 이름과 발급 절차를 `04_PROJECT_SPEC.md`에 적는다.

## 구현 계획

1. 두 API 스펙 확인 → 응답을 내부 형식(날씨 구분 enum, 특일 목록)으로 정규화
2. 캐시(메모리 또는 Supabase 테이블 없이 API 라우트 revalidate) 적용
3. 세그먼트 태그(`weather_*`, 기념일 여부) 연결
4. 키 없는 환경에서 오류 없이 동작하는지 확인

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 인증키가 있을 때 오늘 날씨 구분과 특일 목록이 정규화 형식으로 반환되고, 세그먼트 태그에 반영된다.
- 인증키가 없거나 API가 실패할 때 오류 없이 태그만 빠지는 것을 테스트로 확인한다.
- 호출은 하루 단위로 캐시되어 카드 조회마다 외부 호출이 발생하지 않는다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 신규 환경변수를 Vercel에 등록한다(등록 전 사용자 승인. 체크포인트).

크기 상한: 5파일/100줄.
