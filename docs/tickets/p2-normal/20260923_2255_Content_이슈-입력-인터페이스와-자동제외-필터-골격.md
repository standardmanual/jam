# [Content] 이슈 소재 입력 인터페이스와 자동 제외 필터 골격

## 핵심 요약

- 요구사항: 윤진이 트렌드·사회 이슈 소재를 표준 형식으로 넣으면, 정치·재난·사건사고·혐오 등 PRD §7.3 범주는
  기계가 자동 제외하고 "왜 걸렀는지"가 리포트에 남는다. 통과한 소재만 생성 층이 쓴다.
- 구현 계획: 소재 카드 형식(§7.2)을 정하고, 범주 필터를 검사 스크립트로 만들며, 월간 리포트에 「제외된 소재」 절을
  둔다. 뉴스 소스(빅카인즈)는 카테고리로 1차 기계 제외, 밈 소스는 전량 사람 스크리닝.
- 관련 파일: `jam-doc/marketing/트렌드_노트.md`(소재 카드 형식), `scripts/`(검사 스크립트 신규),
  `.claude/agents/jam-marketer.md`·`jam-tribe.md`(스크리닝 절차), `.claude/skills/jam-work/references/scheduled-jobs.md`
  (월간 작업 절). 스펙: PRD §7.

## 배경 / 문제 정의

사용자는 한국 사회 이슈·밈까지 소재로 받되 정치·재난·사건사고·혐오는 항상 자동 제외하기로 결정했다. 지금은 월간
트렌드 수집이 소재를 자유 서술로 모아 필터가 사람 판단에만 기대고 있고, 걸러진 이유가 남지 않는다.

## 상세 요구사항

### 컨텐츠 관점
- 소재 카드 필수 칸: 제목 · 범주 · 출처 · 관찰일 · 유효 기간 · 지역 · 트라이브 후보 · 필터 판정 · 제외 사유.
- 자동 제외 범주와 사유 문구는 PRD §7.3을 정본으로 한다. 윈터가 추가한 미배정 소재(순위·비교형 밈, 의료성 조언,
  종교 의례, 실존 대회명)도 포함한다.
- 뉴스 소스는 카테고리 필드로 기계 제외, 밈 소스는 윤진 1차 → 윈터 최종.
- 월간 「제외된 소재」 절이 생성되면 `#jam-report`에 제외 건수와 범주별 건수를 안내한다(승인 불필요, PRD §8-1).

### 서비스/코드베이스 관점
- 검사 스크립트는 소재 카드 파일(마크다운 표 또는 JSON)을 읽어 범주·금지어 기준으로 판정을 채운다. 외부 API 호출은
  하지 않는다(수집은 별도).

## 구현 계획 (파일 단위, 계획 반환 면제 근거)

| 파일 | 할 일 |
|---|---|
| `jam-doc/marketing/트렌드_노트.md` | 「소재 카드」 표(22행 근방)를 PRD §7.2 칸으로 확장: 제목(관찰) · 범주 · 출처 · 관찰일 · 유효 기간 · 지역 · 트라이브 후보 · 활용 경로 · 필터 판정(통과/제외) · 제외 사유 · 상태 · 수명. 범주 어휘와 필터 범주 목록은 PRD §7.2·§7.3을 참조만 한다(옮겨 적지 않음) |
| `scripts/issue-filter-check.mjs` (신규) | 소재 카드 파일(마크다운 표 또는 JSON 배열)을 읽어 범주·금지어 기준으로 「필터 판정」·「제외 사유」를 채운다. 자동 제외 범주 8종(정치 · 재난·사고 · 범죄·사건 · 혐오·비하 · 실존 인물 · 저작권 소재 · 논쟁 중인 사회 갈등 · 세계관 미배정 소재)과 사유 문구는 PRD §7.3 표와 글자 단위로 같게 상수로 둔다. 뉴스 소스(빅카인즈 카테고리 필드)는 기계 제외, 밈 소스는 `사람 스크리닝 필요`로 표시. 외부 API 호출 없음. `--dry` 옵션으로 결과만 출력 |
| 스크립트 테스트 (기존 `scripts/verify.sh`의 scripts-test 단계가 도는 위치·관례를 따라 신규) | 시험 소재 12건(범주별 1건 이상 + 통과 3건)에 대해 판정·사유가 기대와 일치하는지 확인 |
| `.claude/agents/jam-marketer.md` | 「⑤ 시즌 운영」 또는 트렌드 절에 스크리닝 순서 한 단락: 소재 카드 표준 형식으로 기록 → 뉴스 소스는 스크립트 기계 제외 → 밈 소스는 윤진 1차 스크리닝 → 윈터 최종 검수. 제외된 소재는 사유와 함께 리포트에 남긴다 |
| `.claude/agents/jam-tribe.md` | 「⑤ 트렌드 수집」 절에 최종 검수 역할 한 줄(밈 소스 통과분과 재난 예외 안전 안내) |
| `.claude/skills/jam-work/references/scheduled-jobs.md` | 「월간」 표의 절차 ①에 "소재 카드를 표준 형식으로 적고 `node scripts/issue-filter-check.mjs`로 판정 → 「제외된 소재」 절(건수·범주별 건수·사유)" 추가. ④ 요약 게시에 제외 건수·범주별 건수 포함(PRD §8-1) |
| `jam-doc/operations/reports/README.md` | 월간 리포트 구조에 「제외된 소재」 절 추가 |

예상 규모: 파일 7개, 약 180줄. 임계값을 넘기므로 첫 호출부터 `planOnlyWaiver`를 넘긴다(사전 확인: 2026-09-23 카리나가 월간 작업 절차·소재 카드 표·
verify.sh의 scripts-test 단계를 대조함). 시험 실행은 세션에서 2026-09 월간 리포트의 소재(축 A·B 카드)를 표준 형식으로 옮긴 파일로 1회 한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 소재 카드 형식이 문서에 정의되어 있고, 시험 소재 10건 이상을 넣은 파일에 대해 검사 스크립트가 PRD §7.3 범주를
  자동 제외하며 사유 문구를 채운다.
- 제외된 소재가 리포트의 「제외된 소재」 절에 사유와 함께 남는 것을 시험 실행 결과로 확인한다.
- 뉴스 소스와 밈 소스의 처리 차이가 에이전트 정의에 적혀 있다.
- 시험 실행에서 「제외된 소재」 요약이 `#jam-report`에 게시되는 절차가 월간 작업 지시문에 있다(실제 게시는 첫 월간 실행 때 확인).

크기 상한: 5파일/100줄(스크립트 포함).
