# [Content] 시즌·소재·POI 유형 × 트라이브 매핑표 정식 등재 (윈터 모드 ①)

## 핵심 요약

- 요구사항: 자동 생성이 시즌·날씨·기념일·지역 행사·POI 유형 소재를 트라이브에 연결할 때 쓸 매핑표를 세계관 정본에
  정식 등재한다. 등재 전까지 T04·T17은 즉석 배정을 하지 않고, T17은 사람 전용이다. PRD §12.
- 구현 계획: 윈터 모드 ①(설정 관리, Opus)이 2026-09-23 검수 초안을 정식 표로 확장해 제안 → 사용자 승인 → 카리나가
  `TRIBES.md`(또는 컨텐츠 문서)에 반영. 인접 그래프는 건드리지 않는다.
- 관련 파일: `jam-doc/planning/content/TRIBES.md`, `jam-doc/planning/content/POI.md`(POI 유형 목록), 상위 티켓
  20260923_2252 「윈터 검수 요지와 매핑 규칙 초안」. 스펙: PRD §12.

## 배경 / 문제 정의

윈터 검수에서 "지역 트라이브" 개념이 설정에 없고, 시즌·소재를 트라이브에 연결하는 표가 없어 자동화가 즉석 배정을
하면 임의 배정이 된다고 지적했다(주의·보통). 미스터리 헌터를 일상 화자로 쓰는 것은 정체성과 충돌한다(주의·높음).

## 상세 요구사항

### 컨텐츠 관점
- 표 1: 소재 범주(계절·날씨 구분·전통 기념일·지역 축제·공공 캠페인·활동 씬 유행·수집 문화 등) → 어울리는 트라이브
  1~3개 → 안 어울리는 트라이브 → 이유.
- 표 2: POI 유형(`naver_category` 대분류) → 어울리는 트라이브.
- 어떤 트라이브에도 붙이지 않는 소재 목록(PRD §7.3 마지막 행)과 미스터리 헌터 노출 상한 원칙을 함께 적는다.
- 시즌 캘린더(연간 시즌 구분과 전환 시점)의 초안도 같은 절에 둔다. DB 저장은 후속 판단.
- 인접 그래프·드랍 확률은 변경하지 않는다. 변경이 필요해 보이면 별도 엔진 티켓으로 넘긴다.

## 구현 계획

1. 윈터 모드 ① 호출: 초안 확장 + 근거(각 트라이브 정의 원문 인용)
2. 사용자 승인
3. `TRIBES.md`에 반영(큰 설정 변경이면 `tribes-history/`에 변경 전 스냅샷)
4. PRD §12의 "등재 전" 문구를 "등재됨"으로 고치고 T17 등급을 초안으로 상향

## 완료 조건

- 매핑표 두 개와 미배정 소재 목록, 시즌 캘린더 초안이 세계관 정본 문서에 있고 사용자 승인 기록이 이 티켓에 있다.
- 인접 그래프에 변경이 없음을 diff로 확인한다.
- PRD §6의 T17 등급과 §12 문구가 등재 상태에 맞게 갱신된다(카리나, 반영 직후).

체크포인트: 표 반영 전 사용자 승인(설정 변경). 크기 상한: 문서 3파일.
