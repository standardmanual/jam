# [Infra] 유형 ID·노출·열람 계측 도입 ① DB 확장 (유형 ID 컬럼·이벤트 테이블·어드민 폼 필드)

## 핵심 요약

- 요구사항: 투데이 카드에 유형 ID(T01~T17)를 붙일 수 있게 하고, 노출·열람·후속 행동 이벤트를 집계 목적으로만 담는 테이블을 만든다(개인
  식별자 없음, 결정 4-6). **이 티켓은 확장 단계(DB 스키마 + 어드민 폼 필드)까지다.** 이벤트 기록 API·클라이언트 트래커·집계 조회는 후속
  티켓 20260924_0004(전환 단계, 선행 = 이 티켓의 SQL 실행 완료). PRD §9.
- 구현 계획: 아래 파일 단위 표. **SQL은 마이그레이션 파일 작성까지, 실행은 사용자 승인 후 메인 세션.** 되돌림 SQL 포함.
- 관련 파일: `jam-web/supabase/migrations/`(신규, 번호는 원격 staging 기준 다음 번호. 규칙표 카리나 항목), `jam-web/src/lib/admin/today-sections.ts`
  (카드 폼 필드·검증 `TodayFormValues`·`exposure_tags` 31~52행 근방), `jam-web/src/app/admin/today/TodayCardForm.tsx`, `jam-web/src/types/database.generated.ts`
  (수동 추가), `docs/specs/prd/02_DATA_MODEL.md`(SQL 실행 뒤 카리나). 규칙: `.claude/skills/jam-work/references/db-migration-rules.md`.

## 배경 / 문제 정의

카드 단위 반응 기록이 없으면 전략 변경안(⑤)과 유형 리뷰(⑥)가 설 수 없다. 카즈하 확인(2026-09-23): GA4는 켜져 있으나 카드 단위 이벤트
전송은 코드에서 확인되지 않았다. 확장→전환→축소 규칙에 따라 스키마 확장을 먼저 분리한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `today_cards.content_type_id text NULL` + CHECK(T01~T17). 기존 카드는 NULL.
- `today_card_events`: `id bigserial`, `card_id uuid`(→ today_cards, on delete set null 또는 cascade 중 되돌림이 쉬운 쪽), `content_type_id text`,
  `event text` CHECK(`impression`·`click`·`followup`), `followup_action text NULL`, `occurred_at timestamptz default now()`. **유저 식별자 컬럼 없음.**
  인덱스 `(content_type_id, occurred_at)`. RLS 활성화, 쓰기는 서비스 롤만(클라이언트 직접 insert 금지).
- 어드민 카드 폼에 유형 ID 선택(T01~T17, 라벨은 PRD §6 유형명, 비움 허용). 저장·상세 표시.
- 되돌림 SQL 블록(컬럼 drop, 테이블 drop).

## 구현 계획 (파일 단위, 계획 반환 면제 근거)

| 파일 | 할 일 |
|---|---|
| `jam-web/supabase/migrations/<다음번호>_today_card_type_and_events.sql` (신규) | 위 확장 SQL + 파일 끝 `-- 되돌림 SQL` 블록 |
| `jam-web/src/types/database.generated.ts` | `today_cards.content_type_id`, `today_card_events` Row/Insert/Update 타입을 SQL과 일치하게 수동 추가(자동 생성 금지. 카리나가 SQL 실행 뒤 MCP 출력과 대조) |
| `jam-web/src/lib/admin/today-sections.ts` | 폼 값·검증에 `contentTypeId` 추가, 유형 ID 선택지 상수(T01~T17 + 유형명) |
| `jam-web/src/app/admin/today/TodayCardForm.tsx` | 유형 ID 선택 필드(shadcn Select, 비움 허용) |
| `jam-web/src/components/admin/today/TodayCardDetail.tsx` | 상세에 유형 ID 표시 |
| 기존 어드민 today 테스트(`jam-web/src/lib/admin/__tests__/today-sections.test.ts`) | 검증 규칙 테스트 추가 |

예상 규모: 파일 6개, 약 150줄(SQL 제외). 임계값을 넘기므로 첫 호출부터 `planOnlyWaiver`를 넘긴다(사전 확인: 2026-09-24 카리나가 폼 구조·규칙 문서 대조).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 마이그레이션 SQL과 되돌림 SQL이 규칙 문서 형식으로 있고, 유저 식별자 컬럼이 없다.
- 어드민 카드 폼에서 유형 ID를 고르거나 비워 저장할 수 있고 상세에 표시된다(수동 타입 추가로 typecheck 통과).
- `scripts/verify.sh` 통과.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)
- SQL 실행(공용 단일 DB, 즉시 프로덕션 반영). 실행 전 사용자 승인. 체크포인트.
- MCP `generate_typescript_types` 출력과 수동 타입 대조, `02_DATA_MODEL.md` 반영.

> 상태 WAITING인 이유(2026-09-24): 구현 범위는 게이트 PASS·staging 로컬 병합(278454d8)까지 끝났다. 후속 범위의 마이그레이션 183 실행이
> 사용자 승인은 받았으나 세션의 자동 모드 분류기가 Supabase 쓰기 동작을 차단해 실행하지 못했다. 사용자가 SQL을 직접 실행하거나 권한을
> 허용하면 타입 대조·`02_DATA_MODEL.md` 반영 후 CLOSED로 바꾼다. 코드 push는 컬럼이 생긴 뒤에 한다(어드민 저장 실패 방지).
