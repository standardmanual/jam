# [Infra] 유형 ID·노출·열람 계측 도입 ① DB 확장 (유형 ID 컬럼·이벤트 테이블·어드민 폼 필드)

## 핵심 요약

- 요구사항: 투데이 카드에 유형 ID(T01~T17)를 붙일 수 있게 하고, 노출·열람·후속 행동 이벤트를 집계 목적으로만 담는 테이블을 만든다(개인
  식별자 없음, 결정 4-6). **이 티켓은 확장 단계(DB 스키마 + 어드민 폼 필드)까지다.** 이벤트 기록 API·클라이언트 트래커·집계 조회는 후속
  티켓 20260924_0004(전환 단계, 선행 = 이 티켓의 SQL 실행 완료). PRD §9.
- 구현 계획: 아래 파일 단위 표. **SQL은 마이그레이션 파일 작성까지, 실행은 사용자 승인 후 메인 세션.** 되돌림 SQL 포함.
- 관련 파일: `jam-web/supabase/migrations/`(신규, 번호는 원격 staging 기준 다음 번호. 규칙표 카리나 항목), `jam-web/src/lib/admin/today-sections.ts`
  (카드 폼 필드·검증 `TodayFormValues`·`exposure_tags` 31~52행 근방), `jam-web/src/app/admin/today/TodayCardForm.tsx`, `jam-web/src/types/database.generated.ts`
  (수동 추가), `docs/service/prd/02_DATA_MODEL.md`(SQL 실행 뒤 카리나). 규칙: `.claude/skills/jam-work/references/db-migration-rules.md`.

## 배경 / 문제 정의

카드 단위 반응 기록이 없으면 전략 변경안(⑤)과 유형 리뷰(⑥)가 설 수 없다. 카즈하 확인(2026-09-23): GA4는 켜져 있으나 카드 단위 이벤트
전송은 코드에서 확인되지 않았다. 확장→전환→축소 규칙에 따라 스키마 확장을 먼저 분리한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `today_cards.content_type_id text NULL` + CHECK(T01~T17). 기존 카드는 NULL.
- `today_card_events`: `id bigserial`, `card_id uuid`(→ today_cards, on delete set null 또는 cascade 중 되돌림이 쉬운 쪽), `content_type_id text`,
  `event text` CHECK(`impression`·`click`·`followup`), `followup_action text NULL`, `occurred_at timestamptz default now()`. **유저 식별자 컬럼 없음.**
  인덱스 `(content_type_id, occurred_at)`. RLS 활성화, 쓰기는 서비스 롤만(클라이언트 직접 insert 금지).
- 어드민 카드 폼에 유형 ID 선택(T01~T17, 라벨은 PRD §6 유형명, 비움 허용). 저장·상세 표시.
- 되돌림 SQL 블록(컬럼 drop, 테이블 drop).
