# [API] 외부 입력(날씨·특일) 호출을 카드 조회 경로 밖으로 분리하고 특일 캐시 테스트를 보강한다

> 티켓 20260923_2254 게이트 WARN 사유 1·3의 후속. 타임아웃 단축(20260923_2332)은 임시 상한이고, 이 티켓이 근본 해결이다.

## 핵심 요약

- 요구사항: `computeUserExposureTags`가 외부 API를 직접 기다리지 않게 한다. 날씨·특일 값은 요청 경로 밖에서 미리 갱신해 두고(예: 하루 1회 cron 또는 첫 요청 후 백그라운드 갱신), 카드 조회는 저장된 값만 읽는다. 값이 없으면 지금처럼 태그만 빠진다. 특일 모듈의 캐시 히트(재호출 없음) 테스트를 추가한다.
- 구현 계획: 착수 시 카리나가 파일 단위로 채운다. 후보 경로는 Vercel cron 라우트(`04_PROJECT_SPEC.md` Cron 절 참고)로 하루 1회 갱신해 Supabase 소형 테이블 또는 KV에 저장하는 방식이다. DB 테이블을 쓰면 `db` 유형으로 분리한다.
- 관련 파일: `jam-web/src/lib/inputs/weather.ts`(`getTodayWeather`, 캐시), `jam-web/src/lib/inputs/holidays.ts`(`getTodaySpecialDays`), `jam-web/src/lib/today/exposure.ts`(`computeUserExposureTags` 151행 근방), `jam-web/src/lib/inputs/__tests__/inputs.test.ts`, `jam-web/src/lib/today/cards.ts`(70행 호출 지점).

## 배경 / 문제 정의

민지 게이트(2254): 오늘 카드 조회는 모든 유저가 매번 거치는 공유 경로인데 그 안에 외부 호출 2건이 들어가, 서버리스 인스턴스별 캐시가 비어 있을 때마다 타임아웃까지 지연될 수 있다. 특일 모듈은 캐시 히트 테스트가 없다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 카드 조회 경로(`getTodayCards` → `computeUserExposureTags`)에서 외부 네트워크 호출이 발생하지 않는다(테스트로 fetch 미호출 확인).
- 사전 갱신 경로가 하루 1회 값을 갱신하고, 값이 없을 때 태그만 빠지는 폴백이 유지된다.
- 특일 모듈 캐시 히트 테스트가 추가된다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- cron 등록이 필요하면 Vercel 설정 반영(사용자 승인).

크기 상한: 5파일/100줄. DB 테이블이 필요하면 `db` 유형으로 티켓을 나눈다.
