# [API] 외부 입력(날씨·특일) 호출을 카드 조회 경로 밖으로 분리하고 특일 캐시 테스트를 보강한다

> 티켓 20260923_2254 게이트 WARN 사유 1·3의 후속. 타임아웃 단축(20260923_2332)은 임시 상한이고, 이 티켓이 근본 해결이다.

## 핵심 요약

- 요구사항: `computeUserExposureTags`가 외부 API를 직접 기다리지 않게 한다. 날씨·특일 값은 요청 경로 밖에서 미리 갱신해 두고(예: 하루 1회 cron 또는 첫 요청 후 백그라운드 갱신), 카드 조회는 저장된 값만 읽는다. 값이 없으면 지금처럼 태그만 빠진다. 특일 모듈의 캐시 히트(재호출 없음) 테스트를 추가한다.
- 구현 계획: **선행 20260924_0602(테이블 `external_input_daily`, 마이그레이션 184) 실행 뒤 착수한다.**
  ① 새 모듈 `jam-web/src/lib/inputs/daily-store.ts`: `readDailyInput(kind, dateKst)`(서비스 클라이언트로 읽기, 오류·없음이면 null,
  요청 경로용)와 `writeDailyInput(kind, dateKst, value)`(upsert, cron 전용). ② `weather.ts`·`holidays.ts`: 외부 호출 본체를
  `refreshTodayWeather()`·`refreshTodaySpecialDays()`로 분리해 export하고, `getTodayWeather()`·`getTodaySpecialDays()`는 저장값만 읽는다
  (모듈 하루 캐시는 저장 조회 결과에만 유지, 값이 없으면 지금처럼 null·빈 배열). ③ 새 라우트 `jam-web/src/app/api/cron/external-inputs/route.ts`:
  `CRON_SECRET` 검증 후 두 갱신 함수를 호출해 저장(패턴은 `poi-cleanup/route.ts`). ④ `jam-web/vercel.json` crons에 `"0 21 * * *"`(06:00 KST) 추가.
  ⑤ 테스트: `getToday*`가 fetch를 부르지 않음, 특일 캐시 히트(두 번째 호출이 fetch 재호출 없음), refresh 함수 동작.
- 관련 파일: `jam-web/src/lib/inputs/weather.ts`(`getTodayWeather`, 캐시), `jam-web/src/lib/inputs/holidays.ts`(`getTodaySpecialDays`), `jam-web/src/lib/today/exposure.ts`(`computeUserExposureTags` 151행 근방), `jam-web/src/lib/inputs/__tests__/inputs.test.ts`, `jam-web/src/lib/today/cards.ts`(70행 호출 지점), `jam-web/src/app/api/cron/poi-cleanup/route.ts`(cron 라우트 패턴),
  `jam-web/vercel.json`, `docs/specs/prd/04_PROJECT_SPEC.md`(Cron 절, 97행 근방 갱신).

## 배경 / 문제 정의

민지 게이트(2254): 오늘 카드 조회는 모든 유저가 매번 거치는 공유 경로인데 그 안에 외부 호출 2건이 들어가, 서버리스 인스턴스별 캐시가 비어 있을 때마다 타임아웃까지 지연될 수 있다. 특일 모듈은 캐시 히트 테스트가 없다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 카드 조회 경로(`getTodayCards` → `computeUserExposureTags`)에서 외부 네트워크 호출이 발생하지 않는다(테스트로 fetch 미호출 확인).
- 사전 갱신 경로가 하루 1회 값을 갱신하고, 값이 없을 때 태그만 빠지는 폴백이 유지된다.
- 특일 모듈 캐시 히트 테스트가 추가된다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- cron 등록이 필요하면 Vercel 설정 반영(사용자 승인).

크기 상한: 5파일/100줄(위 계획은 신규 3·수정 4+테스트라 초과한다 — 티켓 분할 대신 `planOnlyWaiver`로 진행). 테이블은 20260924_0602로 분리했다.
