# [API] 유형 ID·노출·열람 계측 도입 ② 전환 (이벤트 기록 API·클라이언트 트래커·유형별 집계 조회)

> 티켓 20260923_2259(DB 확장)의 후속. 선행: 2259의 SQL이 실행되어 `today_cards.content_type_id`와 `today_card_events`가 DB에 있어야 한다.

## 핵심 요약

- 요구사항: 홈 투데이 카드의 노출·열람·후속 행동을 유형 ID와 함께 `today_card_events`에 기록하고, 어드민 자동화 읽기 토큰으로 유형 ID별
  누적(노출·열람·후속 행동)을 조회한다. 개인 식별자는 저장하지 않는다. PRD §9.
- 구현 계획: 아래 「구현 계획 (파일 단위)」 표.
- 관련 파일: 위 후보 + `jam-web/src/lib/analytics/gtag.ts`(`trackEvent`, GA4 병행 여부 판단).

## 구현 계획 (파일 단위, 계획 반환 면제 근거)

선행 확인(2026-09-24): 마이그레이션 183 실행 완료(`today_cards.content_type_id`, `today_card_events` 존재, 타입 반영됨). `TodayCardStack.tsx`는
서버 컴포넌트이며 카드마다 `<Link>`(249행 미션 헤더, 306행 일반 카드)로 감싸고 `ranking_list`는 행별 자체 링크를 가진다. 투데이 피드는
로그인 유저에게만 노출된다(`getTodayCards(userId)`).

| 파일 | 할 일 |
|---|---|
| `jam-web/src/lib/today/events.ts` (신규) | 이벤트 상수(`impression`·`click`·`followup`), 입력 검증(`cardId` UUID, `event`, `followupAction` ≤ 80자), `recordTodayCardEvent(input)`: 서비스 클라이언트로 카드의 `content_type_id`를 조회해 함께 insert(유저 식별자 저장 안 함), `aggregateTodayCardEvents(from, to)`: 유형 ID×이벤트별 건수 집계 |
| `jam-web/src/app/api/today/events/route.ts` (신규) | `POST`. 로그인 세션이 있어야 받되 유저 ID는 저장·로그하지 않는다. 검증 실패 400, 성공 204. 본문 크기 제한 |
| `jam-web/src/app/(main)/TodayCardTracker.tsx` (신규, `'use client'`) | 카드 하나를 감싸는 클라이언트 래퍼. IntersectionObserver로 노출 1회 전송(세션당 카드당 1회, `sessionStorage`), 클릭 시 `click` 전송(`navigator.sendBeacon` 우선, 폴백 `fetch keepalive`). 자식으로 기존 `<Link>`를 그대로 렌더 |
| `jam-web/src/app/(main)/TodayCardStack.tsx` | 249행·306행 `<Link>`를 `TodayCardTracker`로 감싼다. `ranking_list` 카드는 노출만 추적(클릭은 행별 링크라 제외) |
| `jam-web/src/app/api/admin/today/metrics/route.ts` (신규) | `GET ?from=&to=`. `requireAdminRead(req)`(kpi/weekly와 동일). 유형 ID×이벤트 건수와 유형별 열람률(열람/노출) 반환 |
| `jam-web/src/lib/today/__tests__/events.test.ts` (신규, vitest) | 검증 규칙, insert 시 유저 식별자 미포함, 집계 형태 |
| `docs/specs/prd/content-automation/PRD.md` | §9에 저장 구조·API 경로·노출 억제 규칙을 현재 상태로 기재 |

예상 규모: 파일 7개, 약 220줄. 임계값을 넘기므로 첫 호출부터 `planOnlyWaiver`를 넘긴다(사전 확인: 2026-09-24 카리나가 카드 스택 구조·
`requireAdminRead`·서비스 클라이언트 위치를 대조함). 후속 행동(`followup`)은 1단계에서 클라이언트가 열람 뒤 같은 세션에서 발생한 행동을
카드 ID와 함께 보고하는 최소 형태로 두고, 서버 조인은 후속으로 남긴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 테스트 환경에서 카드 노출·클릭 시 유형 ID가 포함된 이벤트가 기록되고, 유저 식별자가 저장되지 않는다.
- 어드민 집계 조회로 유형 ID별 누적 수치가 나오며 자동화 읽기 토큰으로만 접근된다.
- 노출 이벤트는 세션당 카드당 1회로 억제된다.

크기 상한: 5파일/100줄. 넘기면 착수 시 쪼갠다.
