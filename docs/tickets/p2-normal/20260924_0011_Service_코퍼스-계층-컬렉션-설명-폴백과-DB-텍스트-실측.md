# [Service] 코퍼스 계층 컬렉션 설명 폴백 + DB 컨텐츠 텍스트 실측 (트라이브 원문은 문서에만 있음)

> 경로 ① 경미 수정(카리나 직접). 티켓 20260923_2258 수동 실행 준비 중 발견.

## 핵심 요약

- 요구사항: `selectCorpusForType`의 컬렉션 인용이 `item_books.story_text`만 읽어 빈 결과를 내므로 `description`으로 폴백한다.
- 관련 파일: `jam-web/src/lib/content-corpus/select.ts` `fetchItemBooksRaw`·서사형 분기, 테스트 모킹.

## 실측 (2026-09-24, 서비스 롤로 건수만 조회)

| 코퍼스 | 결과 |
|---|---|
| 트라이브 | 총 10, 활성 3(낭만 미식가·아스팔트 레인저·숲속의 갱단), `description`·`tagline` 있는 행 **0** |
| 컬렉션(item_books) | 총 100, 활성 30, `story_text` 있음 **0**, `description` 있음 96 |
| 아이템배지(삭제 제외) | 270, `description` 있음 270 |

해석: 트라이브 세계관 원문은 DB가 아니라 `docs/service/content/TRIBES.md`(source_of_truth: doc)에만 있다. 컬렉션 서사 필드는 비어 있고 설명 필드가
사실상의 원문이다. 900 아이템배지 중 현재 DB에는 270건이 있다(나머지는 미생산).

## 완료 조건

- 컬렉션 인용이 `story_text`가 비면 `description`을 쓴다. 테스트에 설명만 있는 컬렉션 케이스 추가, typecheck·테스트 통과.
