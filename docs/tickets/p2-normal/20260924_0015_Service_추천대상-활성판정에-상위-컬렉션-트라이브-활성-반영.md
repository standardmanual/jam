# [Service] 추천 대상 활성 판정에 상위 컬렉션·트라이브의 활성 여부를 반영한다

> 사용자 결정(2026-09-24): "포함". 활성 트라이브가 3종뿐인 상태에서 비활성 트라이브·컬렉션에 속한 배지가 추천 대상에 오르는 것을 막는다.

## 핵심 요약

- 요구사항: 코퍼스 계층의 추천·소개형(`role: 'recommend'`) 대상 선택과 `verifyActiveTargets` 기계 검사에서, 배지의 활성 판정을
  "삭제 안 됨 + 유효기간 안" 에 더해 **소속 컬렉션(`badges.item_book_id` → `item_books.is_active`)과 소속 트라이브(`badges.tribe_id` →
  `tribes.is_active`)가 활성일 때만** 활성으로 본다(소속이 없으면 그 조건은 통과). 컬렉션 대상도 소속 트라이브 활성을 요구한다.
  글·세계관 인용(`narrative`)에는 적용하지 않는다(비활성도 인용 가능, PRD §4 규칙 2).
- 구현 계획: 아래 파일 단위 표.
- 관련 파일: `jam-web/src/lib/content-corpus/active.ts`(활성 판정 3종), `jam-web/src/lib/content-corpus/select.ts`(recommend 분기 54~64행),
  `jam-web/src/lib/content-corpus/verify.ts`, `jam-web/src/lib/content-corpus/__tests__/content-corpus.test.ts`, PRD §4 표.

## 구현 계획 (파일 단위, 계획 반환 면제 근거)

| 파일 | 할 일 |
|---|---|
| `jam-web/src/lib/content-corpus/active.ts` | 배지 활성 조회가 `item_book_id`·`tribe_id`도 읽고, 참조된 컬렉션·트라이브의 `is_active`를 한 번씩 조회해 비활성 소속 배지를 제외한다(쿼리는 유형당 상수 회수). 컬렉션 활성 조회도 `tribe_id`로 트라이브 활성을 확인한다 |
| `jam-web/src/lib/content-corpus/select.ts` | recommend 분기가 새 판정 함수를 쓰도록만 바꾼다(구조 변경 없음) |
| `jam-web/src/lib/content-corpus/verify.ts` | 재조회 판정도 같은 함수를 쓴다. 반려 사유에 "소속 트라이브 비활성"·"소속 컬렉션 비활성"을 구분해 적는다 |
| `jam-web/src/lib/content-corpus/__tests__/content-corpus.test.ts` | 케이스 추가: 배지 자체는 활성이지만 소속 컬렉션 비활성 / 소속 트라이브 비활성 → 추천 대상 제외·반려. 서사형 인용에는 영향 없음 |
| `docs/specs/prd/content-automation/PRD.md` | §4 표의 배지·컬렉션 활성 판정 행에 소속 조건 추가 |

예상 규모: 파일 5개, 약 90줄. 100줄 미만이지만 경계에 가까워 첫 호출부터 `planOnlyWaiver`를 넘긴다(사전 확인: 2026-09-24 카리나가 배지의 `item_book_id`·`tribe_id` 컬럼과 현재 판정 함수 구조를 대조함).

## 완료 조건

- 소속 컬렉션 또는 트라이브가 비활성인 배지는 추천 대상·인용 대상(recommend 분기)에서 빠지고, `verifyActiveTargets`가 사유와 함께 반려한다.
- 소속이 없는 배지(`item_book_id`·`tribe_id` NULL)는 기존 판정과 같다. 서사형 인용은 영향이 없다(테스트로 확인).
- PRD §4 표가 갱신되고 `scripts/verify.sh`가 통과한다.

크기 상한: 5파일/100줄.

## 완료 기록 (2026-09-24)

### 구현 내용 요약
`fetchActiveBadges`·`fetchActiveItemBooks`가 소속 컬렉션(`item_book_id`)·소속 트라이브(`tribe_id`)의 `is_active`를 확인해 비활성 소속이면 추천 대상에서
제외한다(소속 없음은 통과, 유형당 상수 회수). `verifyActiveTargets`는 배지 반려 사유를 자체 비활성/소속 컬렉션 비활성/소속 트라이브 비활성으로
구분한다(`fetchBadgeParentStatus`). 서사형 인용 경로는 손대지 않았다. PRD §4 표·생성 규칙 1 갱신.
