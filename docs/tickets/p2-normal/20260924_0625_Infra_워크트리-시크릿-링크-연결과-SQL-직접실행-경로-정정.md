# [Infra] 워크트리 세션에서 Supabase MCP가 안 뜨는 문제 해결과 SQL 직접 실행 경로 문서 정정

## 핵심 요약

- 요구사항: 카리나가 SQL을 전부 직접 실행할 수 있게 한다. 워크트리 세션에서 실행 수단이 빠지지 않게 하고, 실제 관행(Supabase MCP)과 다른 문서를 바로잡는다.
- 구현 계획: `scripts/workspace-setup.sh`에 `link-secrets` 명령을 추가하고, `orchestrator.md` 4절과 규칙표를 MCP 우선 절차로 고친다.
- 관련 파일: `scripts/workspace-setup.sh`(`link_secrets`), `scripts/workspace-setup.test.mjs`, `docs/agents/orchestrator.md` 2·4절, `.claude/skills/jam-work/references/handling-rules.md`(카리나 섹션).

## 배경 / 문제 정의

새 워크트리에서 연 세션은 SQL을 직접 실행하지 못했다. 원인은 정책이 아니라 파일이다.

- Supabase MCP 서버는 저장소 루트의 `.mcp.json`에 정의돼 있고, 이 파일은 아이클라우드 `JAM-secrets`로 이어지는 심볼릭 링크다. `.vercel`, `jam-web/.env.local`도 같다. 세 파일 모두 gitignore 대상이라 워크트리로 따라오지 않는다.
- `mcp__supabase__execute_sql` 자동 허용은 `.claude/settings.local.json`에 있고, 이 파일도 전역 gitignore 대상이라 워크트리에 없다.
- 문서(`orchestrator.md` 4절)는 service_role 키 스크립트만 적었지만, 실제 이력은 Supabase MCP다(티켓 20260914_1813의 `apply_migration` 실행, 타입 재생성 `generate_typescript_types`).
- 티켓 20260924_0602에서는 이 상태 때문에 MCP를 시도하지 않고 사용자가 SQL 편집기에서 직접 실행했다.

서브에이전트에게는 처음부터 SQL 실행 권한이 없다(아현의 `tools`에 MCP가 없고 정의에서 금지). 이 티켓은 그 경계를 바꾸지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `link-secrets <경로>`는 메인 체크아웃의 `.mcp.json`·`.vercel`·`jam-web/.env.local`을 워크트리에 심볼릭 링크로 연결한다. 원본이 없으면 건너뛰고, 이미 있으면 덮어쓰지 않는다.
- 기존 `link`(node_modules)에는 합치지 않는다. `link`는 아현의 격리 워크트리에서 불리는데(`jam-work.js`), 시크릿을 섞으면 DB 실행 권한이 없는 아현이 service_role 키를 읽을 수 있다.
- `.claude/settings.json`의 권한 목록은 바꾸지 않는다. 프로덕션 DB 쓰기의 자동 허용은 이 티켓이 정하지 않으며, 승인 확인이 남는 쪽을 유지한다.

## 구현 계획

1. `link_secrets` 함수와 `link-secrets` 분기 추가.
2. 테스트 추가: 연결·원본 없음 건너뜀·재실행 안전·메인 체크아웃 무시, `link`가 시크릿을 연결하지 않음, `jam-work.js`가 `link-secrets`를 부르지 않음.
3. `orchestrator.md` 4절을 MCP 우선·키 스크립트 대체로 고치고, 워크트리 절차를 추가. 2절에 4절 참조 한 줄.
4. 규칙표 카리나 섹션에 "DB 쓰기 SQL 실행" 행 추가.

## 완료 조건

- `node scripts/workspace-setup.test.mjs`가 통과한다(위 테스트 항목 포함).
- 워크트리에서 `link-secrets`를 실행한 뒤 그 워크트리에서 새로 연 세션에 `supabase` MCP 서버가 로드된다.
- `orchestrator.md`와 규칙표가 MCP 우선 절차를 서술한다.

### 주요 의사결정 / 핵심 메모
- `link`에 합치지 않고 명령을 나눴다. 이유는 아현 경로에 시크릿이 들어가지 않게 하려는 것이다.
- 자동 허용(`settings.json`) 추가는 하지 않았다. 프로덕션 공용 DB에 쓰는 도구라 사용자가 정할 일이다.
- 세션 시작 훅으로 자동 연결하는 안은 MCP가 세션 시작 때 읽히는 순서를 확인하지 못해 보류했다.
- 184는 사용자가 직접 실행했고, 이 티켓에서 다시 실행하지 않았다.

### 잔여 이슈
- 워크트리 세션에서 MCP가 실제로 뜨는지는 다음 세션에서 확인해야 한다.
