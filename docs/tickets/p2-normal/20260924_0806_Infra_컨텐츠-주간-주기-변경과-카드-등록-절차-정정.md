# [Infra] 컨텐츠 주간 주기(화 기획안·수 확정·목 배포)를 도입하고 카드 등록 절차를 실제에 맞춘다

> 사용자 요청(2026-09-24)과 혜린 점검 발견 5·6을 반영한 티켓이다. 문서 정정은 1단계에서 끝냈고 루틴 교체는 사용자 확인을 기다린다.

## 핵심 요약

- 요구사항: (1) 주기를 **화요일 컨텐츠 기획안 제공 → 수요일 중 최종 컨텐츠 확정 → 목요일 정기 배포에 포함해 함께 배포**로 바꾼다(2026-09-24 사용자 결정). (2) 문서는 "카즈하가 어드민에 등록"이라고 하지만 카즈하는 읽기 전용이고 어드민 쓰기는 로그인 세션이 필요해, 실제로는 메인 세션이 DB에 직접 넣었다. 등록 주체와 방식을 문서에 맞춘다.
- 구현 계획: 등록은 **수요일 확정 뒤 카리나(메인 세션)가 카드 등록용 시드 SQL(`jam-web/supabase/migrations/seed_today_cards_<연도주차>.sql`)을 작성·커밋하고, 목요일 정기 배포 승인 때 사용자 승인 아래 메인 세션이 실행**한다(Supabase MCP 우선, 차단되면 SQL 편집기). 시드 파일 끝에 삭제로 되돌리는 SQL을 싣는다. 문서(PRD §8-2, `scheduled-jobs.md`)는 이 티켓의 1단계에서 정정했다. 클라우드 주간 루틴의 실행 시각 변경(월 09:00 → 화)은 **사용자 확인 뒤 `RemoteTrigger`로 교체**한다.
- 관련 파일: `docs/specs/prd/content-automation/PRD.md` §8·§8-2, `.claude/skills/jam-work/references/scheduled-jobs.md` 주간 절(123~140행)·주간 배포 승인 절(160행~), `.claude/agents/jam-marketer.md`, `.claude/agents/jam-ops.md`, 클라우드 루틴 저장 프롬프트(저장소 밖)

## 배경 / 문제 정의

현재 흐름은 월요일 09:00 주간 리포트에서 다음 주 후보안이 오고, 사용자 선택 뒤 카즈하가 등록하는 것으로 문서에 적혀 있었다. 혜린 점검(발견 5)이 이 등록 절차가 문서와 실제가 다르다고 지적했다. 새 주기를 쓰면 확정(수)과 배포(목)가 이어져, 카드 데이터도 배포 승인 흐름에 실을 수 있다.

- 배포: `git log origin/main --since='7 days ago' --oneline`

- `/api/admin/users` 등 개인 정보를 담은 엔드포인트는 직접 호출하지 않는다. 리포트와 Slack에는 집계 수치만 쓴다(닉네임·이메일·유저 ID 금지).

## 2. 홈피드 편성 후보안 (윤진)
브리핑을 쓴 뒤 Task 도구로 `jam-marketer`(윤진)를 model sonnet으로 불러 같은 파일의 '홈피드 초안' 절에 **다음 주(월~일) 편성 후보안**을 PRD §8 형식으로 쓰게 한다. 규칙은 scheduled-jobs.md 주간 절의 윤진 지시문과 PRD §8·§8-2를 따른다. 특히:
- 요일마다 후보 A·B(·C), 윤진 1픽, 「전원 카드」 칸을 쓴다. **요일마다 전원(`all`) 카드가 1장 이상** 있어야 한다.
- 후보마다 등록에 필요한 내용을 모두 쓴다(제목·부제·템플릿·레이아웃·노출 태그·노출일·목적지). 에디토리얼 기사 후보는 본문 전문과 CTA 목적지를 「후보 본문」 절에 쓴다. 커버 이미지가 없는 기사는 레이아웃을 `other`로 한다.
- 코퍼스는 `curl -s -H "x-admin-read-token: $ADMIN_API_READ_TOKEN" "https://j-a-m.app/api/admin/content-corpus?type=<유형 ID>&limit=3"`로만 받는다.
초안일 뿐 발행하지 않는다. 사람이 수요일 안에 고르면 목요일 정기 배포 때 세션에서 등록한다.

## 3. 전략 변경안·유형 리뷰 (윤진, 모드 ④)
- `curl -s -H "x-admin-read-token: $ADMIN_API_READ_TOKEN" "https://j-a-m.app/api/admin/today/metrics?from=YYYY-MM-DD&to=YYYY-MM-DD"`로 최근 3주를 주 단위로 나눠 조회하고, 유형 ID별 노출·열람으로 「전략 변경안」 절을 쓴다(PRD §10 양식). 3주 연속 신호가 없으면 "관찰 중" 한 줄만 쓴다.
- ISO 주차가 짝수인 주에는 「유형 리뷰 (격주)」 절도 쓴다(PRD §11 양식, 자동 등급 T02·T03·T07·T08·T10·T14). 리뷰 기간에 편성 이력이 없는 유형은 "미편성"으로 적고 판정 대상에서 뺀다. 판정 확정은 세션에서 한다.

## 4. 티켓 초안
명확한 문제는 티켓 파일을 만들지 말고 리포트 '결정 필요' 절에 `[분류 대기 초안]`으로 적는다(우선순위 비움, 기존 티켓과 중복 확인).

## 5. 비용
임시 상한은 15만 토큰이다. 강제로 끊을 수 없으므로, 상한에 가까우면 수집을 멈추고 있는 자료로 마무리한다. '비용' 절에 서브에이전트 결과에 표시된 토큰 사용량을 적고, 알 수 없는 값은 '측정 불가'로 적는다.

### 구현 범위 (게이트 판정 대상)
- PRD §8-2에 주 단위 주기(화·수·목)와 등록 절차가 적혀 있고, 「카즈하가 등록」 서술이 없다.

- 루틴 저장 프롬프트가 새 주기·형식(본문 전문 포함)으로 교체된다(사용자 확인 뒤).

### 진행 (2026-09-24)
- 주간 루틴 실행 시각을 화요일 09:00 KST로 변경했다(cron `0 0 * * 2`, 첫 실행 2026-09-29). 저장 프롬프트는 `scheduled-jobs.md` 규칙을 따르도록 되어 있어 교체하지 않았다.

- 에이전트 정의를 맞췄다(2026-09-24): `jam-ops.md` 주간 브리핑 요일을 화요일로, `jam-marketer.md`의 "카즈하가 등록" 서술을 카리나(PRD §8-2)로 고치고 본문 전문·전원 카드 규칙을 넣었다.
- 주간 루틴 저장 프롬프트를 교체했다(사용자 승인 2026-09-24 "전부 추천대로", `RemoteTrigger update`, 응답의 `updated_at` 2026-09-24T01:02:03Z). 교체 뒤 응답에서 저장 본문이 교체안과 같고, 활성·cron `0 0 * * 2`·다음 실행 2026-09-29 09:01 KST·환경·Slack 연결이 그대로임을 확인했다. 교체 전과 다른 점: ① 실행 요일 명시(화요일) ② 규칙 원본에 PRD(§5·§6·§8·§8-1·§8-2·§10·§11) 추가 ③ 편성 후보안에 전원 카드·후보 본문·이미지 없는 기사 `other` 규칙 ④ 전략 변경안·격주 유형 리뷰 단계(3절) 신설, 미편성 유형 제외 ⑤ Slack 편성 안내 글을 브리핑 요약과 분리, 변경안·유형 리뷰 안내 글 분리 ⑥ 개인정보 검사가 유저 ID만 지우고 컬렉션·미션·카드 ID는 남기도록 조정 ⑦ Strava 해석을 `scheduled-jobs.md` 「데이터 출처」 절에 맡김.
