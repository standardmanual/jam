# [Infra] 컨텐츠 주간 주기(화 기획안·수 확정·목 배포)를 도입하고 카드 등록 절차를 실제에 맞춘다

> 사용자 요청(2026-09-24)과 혜린 점검 발견 5·6을 반영한 티켓이다. 문서 정정은 1단계에서 끝냈고 루틴 교체는 사용자 확인을 기다린다.

## 핵심 요약

- 요구사항: (1) 주기를 **화요일 컨텐츠 기획안 제공 → 수요일 중 최종 컨텐츠 확정 → 목요일 정기 배포에 포함해 함께 배포**로 바꾼다(2026-09-24 사용자 결정). (2) 문서는 "카즈하가 어드민에 등록"이라고 하지만 카즈하는 읽기 전용이고 어드민 쓰기는 로그인 세션이 필요해, 실제로는 메인 세션이 DB에 직접 넣었다. 등록 주체와 방식을 문서에 맞춘다.
- 구현 계획: 등록은 **수요일 확정 뒤 카리나(메인 세션)가 카드 등록용 시드 SQL(`jam-web/supabase/migrations/seed_today_cards_<연도주차>.sql`)을 작성·커밋하고, 목요일 정기 배포 승인 때 사용자 승인 아래 메인 세션이 실행**한다(Supabase MCP 우선, 차단되면 SQL 편집기). 시드 파일 끝에 삭제로 되돌리는 SQL을 싣는다. 문서(PRD §8-2, `scheduled-jobs.md`)는 이 티켓의 1단계에서 정정했다. 클라우드 주간 루틴의 실행 시각 변경(월 09:00 → 화)은 **사용자 확인 뒤 `RemoteTrigger`로 교체**한다.
- 관련 파일: `docs/specs/prd/content-automation/PRD.md` §8·§8-2, `.claude/skills/jam-work/references/scheduled-jobs.md` 주간 절(123~140행)·주간 배포 승인 절(160행~), `.claude/agents/jam-marketer.md`, `.claude/agents/jam-ops.md`, 클라우드 루틴 저장 프롬프트(저장소 밖)

## 배경 / 문제 정의

현재 흐름은 월요일 09:00 주간 리포트에서 다음 주 후보안이 오고, 사용자 선택 뒤 카즈하가 등록하는 것으로 문서에 적혀 있었다. 혜린 점검(발견 5)이 이 등록 절차가 문서와 실제가 다르다고 지적했다. 새 주기를 쓰면 확정(수)과 배포(목)가 이어져, 카드 데이터도 배포 승인 흐름에 실을 수 있다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- PRD §8-2에 주 단위 주기(화·수·목)와 등록 절차가 적혀 있고, 「카즈하가 등록」 서술이 없다.
- `scheduled-jobs.md`의 주간 절이 새 주기를 따르는지, 주간 루틴 실행 시각 변경 계획이 명시된다.
- 루틴 저장 프롬프트가 새 주기·형식(본문 전문 포함)으로 교체된다(사용자 확인 뒤).

### 후속 범위 (담당: 카리나, 시점: 사용자 확인 뒤)
- 클라우드 주간 루틴 실행 시각과 저장 프롬프트 교체.
- 첫 시드 SQL 방식 시행(다음 주 편성분).

크기 상한: 3파일 문서 위주.
