# [Admin] scheduled-jobs.md에서 생성한 파일로 Claude 예약 루틴의 상태와 다음 실행을 캘린더에 표시한다

## 핵심 요약

- 요구사항: Claude 예약 루틴(주간, 선별, 배포 승인 등)의 켜짐 상태와 실행 시각을 캘린더에 표시한다.
- 구현 계획: `scripts/gen-scheduled-jobs.mjs`를 신설해 `scheduled-jobs.md`의 루틴 절(제목의 요일·시각, `상태` 행)을 파싱하고 `jam-web/src/lib/admin/scheduledJobs.generated.ts`를 만든다. 생성 파일이 md와 어긋나면 커밋 검사가 실패하도록 `docs/agents/contract.json`에 검사 줄을 추가한다. 캘린더(0904)에 루틴 항목을 크론과 구분되는 표식으로 넣는다.
- 관련 파일:
  - `.claude/skills/jam-work/references/scheduled-jobs.md` (원천, 읽기만)
  - 신규: `scripts/gen-scheduled-jobs.mjs`, `jam-web/src/lib/admin/scheduledJobs.generated.ts`
  - `scripts/check-contract.mjs`, `docs/agents/contract.json` (검사 줄 추가)
  - `jam-web/src/app/admin/WeeklyCalendar.tsx` (0904에서 생성)
  - 참고 패턴: `scripts/gen-team-doc.mjs`

## 배경 / 문제 정의

Vercel에 배포된 어드민은 저장소의 `.claude/` 문서를 런타임에 읽을 수 있다는 보장이 없다. 그래서 원천은 md에 두고 생성 파일을 커밋하는 방식(기획 대안 B)으로 정했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 최신 리포트 날짜(`jam-doc/operations/reports/`)는 1차 범위에서 제외한다.
- 꺼진 루틴은 흐리게 표시하고 다음 실행 시각을 표시하지 않는다.
- 어드민 유형이므로 MODULAR를 적용하지 않는다. 조회만 하며 DB 변경은 없다.
- 표시하는 시각은 모두 KST다. 데이터 하나를 불러오지 못해도 해당 영역만 오류 문구를 보이고 페이지 전체는 렌더된다(기존 `serviceError` 패턴).
- 실렌더 검증은 `docs/specs/DEV_PROCESS_GUARDRAILS.md` 패턴 13(로컬 `ADMIN_EMAILS` 셸 환경변수)으로 한다.

## 구현 계획

`scripts/gen-scheduled-jobs.mjs`를 신설해 `scheduled-jobs.md`의 루틴 절(제목의 요일·시각, `상태` 행)을 파싱하고 `jam-web/src/lib/admin/scheduledJobs.generated.ts`를 만든다. 생성 파일이 md와 어긋나면 커밋 검사가 실패하도록 `docs/agents/contract.json`에 검사 줄을 추가한다. 캘린더(0904)에 루틴 항목을 크론과 구분되는 표식으로 넣는다.

## 완료 조건

- `node scripts/gen-scheduled-jobs.mjs`를 실행하면 생성 파일이 만들어지고, md를 바꾸지 않고 다시 실행하면 diff가 없다.
- md의 루틴 시각을 바꾸고 생성기를 돌리지 않은 채 커밋하면 계약 검사가 실패한다.
- 캘린더에 주간 루틴(화요일 09:00)과 선별 루틴(매일 06:00)이 켜짐 상태로 표시된다.
- 생성기 파싱에 단위 테스트가 있다.
