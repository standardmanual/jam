## 배경 / 문제 정의

Vercel에 배포된 어드민은 저장소의 `.claude/` 문서를 런타임에 읽을 수 있다는 보장이 없다. 그래서 원천은 md에 두고 생성 파일을 커밋하는 방식(기획 대안 B, 2026-09-24 사용자 승인)으로 정했다.

루틴 절 제목의 일정 표기는 4가지다(2026-09-24 확인).
- `## 주간 — 화요일 09:00 KST`
- `## 선별 — 매일 06:00 KST`
- `## 주간 배포 승인 — 매주 목요일, 확인(15:00) → 실행(23:59) KST` (하루에 실행 2회)
- `## 월간 — 매월 1일 09:00 KST`

`| 상태 |` 칸은 `켜짐`으로 시작하고 뒤에 괄호 설명이 붙기도 한다. `## 공통 원칙` 절은 `| 상태 |` 행이 없고 루틴이 아니다.

주간 배포 승인 루틴은 같은 날짜에 항목이 2개 생기므로, 현재 항목 id(`${path}-${date}`) 방식이면 티켓 0930의 id 중복이 실제로 발생한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 최신 리포트 날짜(`docs/operations/reports/`)는 이번 범위에서 제외한다.
- 꺼진 루틴은 흐리게 표시하고, 크론 항목과 구분되는 표식을 붙인다.
- 어드민 유형이므로 MODULAR를 적용하지 않는다. 조회만 하며 DB 변경은 없다.
- 표시하는 시각은 모두 KST다. 생성 파일에 들어가지 않은 값을 화면에 따로 적지 않는다.
- 실렌더는 격리 워크트리에서 시도하지 않는다(티켓 20260924_1016). 머지 뒤 카리나가 메인 폴더에서 확인한다.

## 구현 계획

1. `scripts/gen-scheduled-jobs.mjs` (신규): scheduled-jobs.md의 `## ` 절 중 `| 상태 |` 행이 있는 절만 루틴으로 읽는다. 제목의 일정 표기 4종(매일 / `<요일>요일` / `매주 <요일>요일, <라벨>(HH:MM) → <라벨>(HH:MM)` / `매월 N일`)을 파싱하고, 상태는 `| 상태 |` 칸의 첫 단어(켜짐·꺼짐)로 정한다. 루틴 절인데 파싱할 수 없으면 종료 코드 1로 실패한다(표기가 바뀌면 검사가 잡도록). 출력은 `jam-web/src/lib/admin/scheduledJobs.generated.ts`이며 맨 위에 자동 생성 파일이라는 주석을 둔다. `--check`는 기존 생성기처럼 "최신인지만 판정하고 다르면 종료 코드 1"이다.
2. `scripts/gen-scheduled-jobs.test.mjs` (신규): 제목 4종 파싱, 상태 첫 단어 판정, 파싱 실패 시 오류를 검사한다(verify.sh의 scripts-test가 실행).
3. `scripts/verify.sh`와 `.githooks/pre-commit`: 기존 `gen-team-doc.mjs --check` 호출 옆에 `gen-scheduled-jobs.mjs --check`를 추가한다.
4. `jam-web/src/lib/admin/scheduledJobs.generated.ts` (생성물, 커밋한다).
5. 루틴 정의를 "그 주의 발생 목록(날짜·시각·라벨·켜짐 여부)"으로 바꾸는 순수 함수와 단위 테스트(`jam-web/src/lib/admin/` 안). 매월 N일 루틴은 그날이 그 주에 들어 있을 때만 발생한다.
6. `jam-web/src/app/admin/page.tsx`: 캘린더 항목에 루틴을 추가한다. **항목 id에 실행 시각을 포함해 같은 날짜의 항목끼리 겹치지 않게 한다(티켓 0930).**
7. `jam-web/src/app/admin/WeeklyCalendar.tsx`: 항목 종류 표식과 흐림 표시를 지원한다(항목 데이터에 선택 필드 추가).
8. `docs/service/prd/admin-ui/ADMIN_PRD.md` §5-7: 「현재 동작」에 루틴 표시를 추가하고 「예정」에서 뺀다.

크기: 바뀌는 파일 약 10개로 `plan_only` 임계값을 넘는다. 사용자가 분해안과 방식(생성 스크립트)을 승인했으므로 카리나가 첫 호출부터 계획 반환 면제를 넘긴다.

## 완료 조건

- `node scripts/gen-scheduled-jobs.mjs`를 실행하면 생성 파일이 만들어지고, md를 바꾸지 않고 다시 실행하면 diff가 없다. `--check`는 최신이면 종료 코드 0이다.
- md의 루틴 시각을 바꾸고 생성기를 돌리지 않은 채 커밋하면 pre-commit이 실패하고, `scripts/verify.sh`도 실패한다.
- 캘린더에 주간 루틴(화요일 09:00)과 선별 루틴(매일 06:00)이 켜짐 상태로 표시되고, 목요일 칸에 주간 배포 승인 항목 2개(15:00 확인, 23:59 실행)가 서로 다른 id로 표시된다.
- 월간 루틴은 매월 1일이 들어 있는 주에만 표시된다(예: 2026-09-28 주의 10월 1일 목요일 09:00).
- 생성기 파싱과 주간 발생 변환에 단위 테스트가 있다.
- (티켓 0930) `0 6,18 * * *`처럼 시 필드가 여러 값인 cron 식이 같은 날짜에 서로 다른 id의 항목 2개를 만든다는 단위 테스트가 있고, 기존 크론 4개의 표시 결과(시각·라벨·순서)는 바뀌지 않는다.
