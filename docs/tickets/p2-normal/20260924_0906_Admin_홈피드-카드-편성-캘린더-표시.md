# [Admin] 주간 캘린더의 요일 칸에 홈피드 카드 편성을 표시한다

## 핵심 요약

- 요구사항: 어드민 메인 주간 캘린더의 각 요일 칸에 그날 노출되는 홈피드 카드를 표시한다. **기간이 7일 이하인 카드(단기 카드)는 한 장씩 유형 ID·제목으로 보이고, 기간이 7일을 넘는 카드(장기 카드)는 "장기 카드 N장" 한 줄로 묶는다. 활성 단기 카드가 없는 날은 "미편성"으로 표시한다**(2026-09-24 사용자 결정).
- 구현 계획: 아래 「구현 계획」 1~5를 따른다.
- 관련 파일:
  - `jam-web/src/app/admin/today/page.tsx` 32~37줄 (하루에 걸치는 카드 조회 조건: `.lte('starts_at', endIso).gte('ends_at', startIso)`, 정렬 `sort_order` → `starts_at` 내림차순)
  - `jam-web/src/lib/admin/today-calendar.ts` `kstDayBoundsIso` (45줄, KST 하루의 시작~끝 ISO, 끝은 다음 날 00:00 직전), `shiftDateStr` (53줄)
  - `jam-web/src/app/admin/today/TodayCardTable.tsx` (카드 행이 이동하는 경로, 유형 ID 표시 형식 참고)
  - `jam-web/src/app/admin/page.tsx` `AdminDashboardPage`의 `columns` 생성 (41~68줄)
  - `jam-web/src/app/admin/WeeklyCalendar.tsx` `CalendarCellItem` (9~18줄), 항목 렌더 (86~94줄)
  - `docs/specs/prd/admin-ui/ADMIN_PRD.md` §5-7
  - 스펙: 홈피드 편성 절차 `docs/specs/prd/content-automation/PRD.md` §8

## 배경 / 문제 정의

주간 편성 승인 뒤 카드가 요일마다 등록됐는지 확인하려면 지금은 `/admin/today`에서 날짜를 하나씩 넘겨야 한다.

2026-09-24 읽기 전용 조회로 확인한 데이터(판단의 근거):
- 9/21~9/27의 날마다 활성 카드 40장이 겹친다. 40장 모두 기간이 32일 이상(7/26 시작, 9/27 종료)이고 `content_type_id`가 없다.
- 9/28~10/4의 카드는 모두 기간 1일이며 날마다 1~3장이다. 한 장(9/29 drop_alert)을 빼면 모두 `content_type_id`가 있다. 비활성 카드도 섞여 있다(9/29·10/2).

그래서 "그날 카드 전부"를 칸에 넣으면 9/21 주는 칸마다 40줄이 된다. 유형 ID 유무로 편성 카드를 가르면 유형 ID를 빠뜨린 편성 카드가 숨는다. 사용자는 기간 기준을 택했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 하루에 걸치는 카드의 판정은 `/admin/today` 목록과 같아야 한다: `kstDayBoundsIso(날짜)`의 `startIso`·`endIso`로 `starts_at <= endIso` 그리고 `ends_at >= startIso`. 같은 날짜의 `/admin/today?date=` 목록과 캘린더 칸(단기 카드 + 장기 카드 수)의 합이 같아야 한다.
- 단기·장기 경계는 `ends_at - starts_at`이 7일 이하인지로 가른다. 경계값은 상수 하나로 둔다.
- 비활성(`is_active = false`) 단기 카드는 흐리게(`dim`) 표시하고, "미편성" 판정에는 넣지 않는다. 장기 카드 수는 활성 카드만 센다.
- 조회는 필요한 컬럼만 가져온다(id·title·content_type_id·template_type·starts_at·ends_at·is_active·sort_order). 한 주 범위로 한 번만 조회하고 요일 배분은 순수 함수에서 한다.
- 카드 조회가 실패해도 크론·루틴 항목과 다른 영역은 그대로 표시한다(이 페이지의 출처별 격리 원칙).
- 어드민 유형이므로 MODULAR를 적용하지 않는다. 조회만 하며 DB 변경은 없다.
- 실렌더는 격리 워크트리에서 시도하지 않는다(티켓 20260924_1016). 머지 뒤 카리나가 메인 폴더에서 확인한다.

## 구현 계획

1. 순수 함수 신설(`jam-web/src/lib/admin/` 안, 예: `weeklyCards.ts`): 카드 목록과 주의 월요일을 받아 요일별로 `{ shortCards, longActiveCount, unprogrammed }`를 만든다. 날짜 겹침은 `kstDayBoundsIso`를 쓴다. 단기 카드 정렬은 `/admin/today`와 같게(`sort_order` 오름차순 → `starts_at` 내림차순). 단기 경계 상수(7일)를 이 파일에 둔다.
2. 1번의 단위 테스트: 단기·장기 분류(정확히 7일 포함), KST 날짜 경계(끝이 다음 날 00:00 직전), 여러 날에 걸친 단기 카드가 해당 날짜마다 나타나는지, 비활성 흐림과 미편성 판정.
3. `WeeklyCalendar.tsx`: 항목에 선택 필드 `href`(있으면 링크)와 카드 종류 표식(예: `kind: 'card'`)을 추가한다. 칸 단위 선택 필드로 "장기 카드 N장" 줄(그 날짜의 `/admin/today?date=YYYY-MM-DD` 링크)과 "미편성" 표시를 지원한다. 기존 크론·루틴 표시는 바뀌지 않아야 한다.
4. `page.tsx`: 보고 있는 주 범위로 카드를 한 번 조회해(출처별 try/catch) 1번 함수로 요일에 배분한다. 카드 항목은 칸 안에서 자동화 항목(크론·루틴)보다 위에 둔다. 카드 항목의 시각 자리에는 유형 ID(없으면 "유형 없음")를, 라벨에는 제목을 넣고, 누르면 `TodayCardTable.tsx`가 카드 행에서 이동하는 경로와 같은 곳으로 간다. 항목 id는 카드 id와 날짜를 함께 써서 칸 안에서 겹치지 않게 한다.
5. `ADMIN_PRD.md` §5-7: 「현재 동작」에 카드 표시 규칙(단기·장기 경계, 미편성 기준, 링크)을 추가하고 「예정」에서 뺀다.

## 완료 조건

- 1번 함수에 단위 테스트가 있다: 7일 경계, KST 날짜 경계, 여러 날 단기 카드, 비활성 흐림, 미편성 판정.
- 캘린더 칸의 "단기 카드 + 장기 카드 수"가 같은 날짜의 `/admin/today?date=` 목록 개수와 같다(카리나가 머지 뒤 실렌더로 한 날짜 이상 대조한다).
- 9/21 주는 날마다 "장기 카드 N장" 한 줄과 "미편성"이 표시된다. 9/28 주는 요일마다 단기 카드가 유형 ID·제목으로 표시되고, 비활성 카드는 흐리게 표시된다.
- 카드 항목을 누르면 카드 화면으로, "장기 카드 N장" 줄을 누르면 그 날짜의 `/admin/today?date=`로 이동한다.
- 카드 조회가 실패해도 크론·루틴 항목과 나머지 영역은 표시된다.
- 기존 크론·루틴 항목의 표시(시각·라벨·순서·루틴 표식)는 바뀌지 않는다.

### 구현 내용 요약
- 어드민 메인 주간 캘린더의 요일 칸에 홈피드 카드를 표시한다. 기간 7일 이하 카드(단기)는 "유형 ID(없으면 '유형 없음') + 제목"으로 한 장씩, 비활성은 흐리게 표시한다. 7일을 넘는 카드(장기)는 "장기 카드 N장" 한 줄(활성만, `/admin/today?date=` 링크)로 묶는다. 활성 단기 카드가 없는 날은 "미편성"을 표시한다.
- `weeklyCards.ts`(신규)의 `weeklyCards()`가 한 주 카드를 요일별 `{ date, shortCards, longActiveCount, unprogrammed }`로 배분한다. 하루 겹침은 `kstDayBoundsIso`로 `/admin/today`와 같게 판정하고, 정렬도 같다(`sort_order` 오름차순 → `starts_at` 내림차순). 경계 상수는 `SHORT_CARD_MAX_DAYS = 7`.
- `page.tsx`는 보고 있는 주 범위로 `today_cards`를 필요한 컬럼만 한 번 조회한다. 실패하면 카드 표시만 비우고 "미편성"으로 단정하지 않는다. 카드 항목은 칸 안에서 크론·루틴보다 위에 두고, 누르면 `/admin/today/[id]?date=`(목록의 [상세보기]와 같은 경로)로 이동한다.
