# [Admin] 캘린더의 홈피드 카드 옆에 노출·열람·후속 행동 수를 표시한다

## 핵심 요약

- 요구사항: 0906에서 표시한 카드마다 노출, 열람, 후속 행동 수를 함께 표시한다. 지난 날짜의 카드만 대상이다.
- 구현 계획: `/api/admin/today/metrics`의 집계 로직을 서버 컴포넌트에서 재사용해 카드 ID별 수치를 붙인다. 표본이 적은 카드는 수치 옆에 '표본 적음'을 표시한다(PRD §10 표본 기준을 따른다).
- 관련 파일:
  - `jam-web/src/app/api/admin/today/metrics/route.ts` (집계 로직)
  - `jam-web/src/app/admin/WeeklyCalendar.tsx`
  - 스펙: PRD §10

## 배경 / 문제 정의

주간 브리핑에서 윤진이 읽는 카드 반응 수치를 운영자도 캘린더에서 바로 확인하기 위함이다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 개인 식별 정보 없이 집계 수치만 표시한다.
- 어드민 유형이므로 MODULAR를 적용하지 않는다. 조회만 하며 DB 변경은 없다.
- 표시하는 시각은 모두 KST다. 데이터 하나를 불러오지 못해도 해당 영역만 오류 문구를 보이고 페이지 전체는 렌더된다(기존 `serviceError` 패턴).
- 실렌더 검증은 `docs/specs/DEV_PROCESS_GUARDRAILS.md` 패턴 13(로컬 `ADMIN_EMAILS` 셸 환경변수)으로 한다.

## 구현 계획

`/api/admin/today/metrics`의 집계 로직을 서버 컴포넌트에서 재사용해 카드 ID별 수치를 붙인다. 표본이 적은 카드는 수치 옆에 '표본 적음'을 표시한다(PRD §10 표본 기준을 따른다).

## 완료 조건

- 지난 날짜 카드 옆에 노출·열람·후속 행동 수가 표시되고, 오늘 이후 카드에는 표시되지 않는다.
- 수치가 `/api/admin/today/metrics`의 응답과 일치한다.
- 지표 조회가 실패해도 카드 편성 표시는 유지된다.
