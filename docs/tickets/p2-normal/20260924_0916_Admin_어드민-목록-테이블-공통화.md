# [Admin] 어드민 목록 테이블 공통화 (상위 티켓)

## 핵심 요약

- 요구사항: 어드민의 모든 목록 화면이 같은 틀을 쓰게 한다. 전체 선택, 메뉴별 필터(연쇄 필터 포함),
  번호 페이지 이동, 상세는 항상 새 페이지, 상세로 넘어갈 때 로더 없음, 정렬, 이름 검색, 그리고
  **메뉴별 대표 기능(표에서 바로 고치는 기능과 일괄 처리 버튼)** 을 갖춘다. 사용자는 대표 기능(아래
  §4)을 가장 중요한 항목으로 지정했다.
- 구현 계획: 공통 부품을 먼저 만들고 체크인 관리(POI)에 시범 적용한 뒤, 나머지 메뉴를 묶음 단위로
  옮긴다(§7 분해안, 하위 티켓 11개).
- 관련 파일: `jam-web/src/components/admin/data-table/*`(공통 부품),
  `jam-web/src/app/admin/poi/Pagination.tsx`(번호 페이지 이동, 공용 폴더로 옮길 대상),
  `jam-web/src/components/NavigationLoader.tsx:55-58`(어드민 로더 제외 지점),
  `docs/specs/prd/admin-ui/REDESIGN.md` §4(목록 표준을 적을 곳)

## 상세 요구사항

### 1. 목록 표준 (공통 부품이 보장할 것)

| # | 요구 | 표준 |
|---|---|---|
| 1 | 전체 선택 | 머리 체크박스는 현재 페이지를 선택한다. 선택하면 표 위에 "이 조건의 N건 모두 선택" 안내가 나타나고, 누르면 필터 결과 전체가 선택된다. 페이지를 넘겨도 선택이 유지된다 |
| 2 | 필터 | 메뉴의 상태 값(활성·노출·유형·분류)을 필터로 둔다. 앞 필터에 따라 선택지가 바뀌는 연쇄 필터를 부품이 지원한다(예: 배지 유형 → 종목/카테고리/트라이브, 트라이브 → 컬렉션). 필터를 바꾸면 1쪽으로 돌아가고 선택이 풀린다 |
| 3 | 페이지 이동 | 번호형(처음·끝, 현재 ±2, 이전·다음). 한 쪽 크기는 50건으로 통일한다. 1쪽뿐이면 숨긴다 |
| 4 | 상세 이동 | 같은 탭에서 상세 페이지로 이동한다. 모달·서랍으로 상세를 열지 않는다. 행 아무 곳이나 눌러도 이동하고, 이름은 링크로 남겨 Cmd+클릭으로 새 탭을 열 수 있게 한다. 체크박스·스위치·버튼을 누를 때는 이동하지 않는다 |
| 5 | 로더 | 목록에서 상세로 이동할 때 전체 화면 로더·스피너를 띄우지 않는다(현재 동작을 표준으로 고정). 멈춘 것처럼 보이는 시간은 링크 미리 불러오기로 줄인다 |
| 6 | 정렬 | 정렬 선택(최신순·오래된순·이름순 등 메뉴별 목록)과 머리 칸 정렬을 URL 하나로 묶는다. 페이지가 나뉜 목록은 서버에서 정렬한다 |
| 7 | 대표 기능 | §4 메뉴별 표를 따른다. 공통 틀: (a) 표 안의 대표 기능은 메뉴당 1개, 누르면 바로 반영되고 실패하면 원래 값으로 돌아가며 이유를 안내한다. 단, 끄는 쪽이 등급 2인 메뉴(배지·트라이브·미션 숨김·POI·제재 등급)는 1건짜리 확인창을 거친다 (b) 일괄 처리 바에는 대표 버튼 1~2개를 드러내고 나머지는 "더보기"에 넣는다 (c) 확인 방식은 §3 위험 등급을 따른다 (d) 결과는 "N건 처리, M건 건너뜀(사유)"로 안내한다 |
| 8 | 이름 검색 | 이름(메뉴에 따라 제목·이메일 포함)으로 검색한다. 입력을 멈추고 0.4초 뒤 반영하고, URL에 남는다 |

### 2. 서버 일괄 처리

- 일괄 기능은 메뉴마다 **요청 한 번**으로 처리한다(`POST /api/admin/<메뉴>/bulk`, 본문에 ID 목록 또는
  필터 조건, 동작 이름, 값).
- 상태 변경(활성화·노출·분류 지정)은 모두 반영되거나 모두 취소된다. 200건 이하는 한 문장으로 처리한다. 200건을 넘으면
  (`.in()` 목록이 URL 16KB 상한에 걸림) 바꾸기 전 값을 저장하고 200건씩 반영하며, 실패하면 저장한 값으로 되돌린다. DB 함수(RPC)는
  만들지 않는다. 200건을 넘을 수 있는 메뉴는 POI와 배지뿐이다.
- 삭제처럼 참조 보호가 걸린 동작은 막힌 항목만 건너뛰고, 건너뛴 항목과 사유를 돌려준다.
- 유저 단위 작업(포인트 지급·초기화·삭제, 아이템 재배정)은 원자적으로 묶을 수 없으므로 유저별 결과를 돌려준다.
- 한 번에 처리하는 상한은 1,000건이다. 필터 결과가 상한을 넘으면 실행하기 전에 알린다. 무거운 동작은 동작별 상한을 더 낮게 둔다
  (배지 삭제 100, POI 삭제 200, 아이템 재배정 200, 유저 초기화·삭제 50).
- 등급 2·3의 영향 수치는 같은 API의 미리보기(`dry_run`)가 계산한다. 등급 3의 확인 문구도 서버가 정하고 실행 때 다시 대조한다.

### 3. 위험 등급별 확인 방식

| 등급 | 해당 동작 | 확인 방식 |
|---|---|---|
| 1 되돌릴 수 있음 | 활성화, 노출 켜기, 분류 지정, 컬렉션·투데이 카드 비활성화 | 표 안의 대표 기능은 확인 없이 바로 반영. 일괄 처리는 "N건을 ○○할까요?" 확인창 |
| 2 되돌릴 수 있으나 유저에게 보임 | 배지 비활성화(아직 줍지 않은 월드 드랍 무효화), POI 비활성화(지도·체크인·드랍에서 빠짐), 트라이브 비활성화(온보딩 선택지·추천 후보에서 빠짐), 미션 숨김·기간 종료, 제재 등급 변경·해제·연장, 아이템 재배정 | 확인창에 영향 건수를 함께 표시(예: 참여 중인 유저 N명, 무효화될 드랍 N건) |
| 3 되돌릴 수 없음 | 삭제, 아이템 폐기, 획득 이력 삭제, 유저 초기화, 포인트 지급·회수 | 확인 문구 입력(배지 일괄 변경 도구의 방식을 공용으로 승격) |

내보내기(CSV)는 데이터를 바꾸지 않으므로 확인창 없이 바로 내려받는다.

기호: **기존** = 이미 있음, **신규** = 새로 만듦, **교체** = 단건 반복을 서버 일괄 처리로 바꿈.

### 4.5 같은 값을 두 메뉴에서 바꾸지 않는다

드랍 제외 여부는 **드랍 제외 관리 한 곳**에서만 바꾼다. 배지·컬렉션 목록에는 드랍 제외 스위치나
일괄 버튼을 넣지 않는다. 같은 값을 두 화면에서 바꾸면 어느 화면이 기준인지 흐려진다.

## 6. 결정 사항 (2026-09-24 사용자 확정)

1. 전체 선택 범위: **현재 페이지 + "필터 결과 전체" 확장.** 선택은 ID 집합으로 유지하고, 일괄 API는 ID
   목록만 받는다. "필터 결과 전체"는 서버가 같은 필터로 ID를 모아(상한 1,000건) 돌려준다.
2. 예외: **배지 지표 라벨·POI 카테고리·게이트 미션은 표준에서 뺀다.** 현재 방식을 유지한다.
3. 위험한 일괄 기능: **확인 문구를 입력하면 허용한다.** 유저 일괄 삭제·초기화, 포인트 일괄 지급·회수를
   유저 조회 목록의 일괄 처리에 넣는다(§4.4). 안전장치: 어드민 계정과 본인 계정은 대상에서 자동 제외,
   포인트는 단건 지급 API와 같은 검증(금액 범위·사유 필수)을 유저마다 적용하고 유저별 결과를 돌려준다.
4. 진행 방식: **묶음 실행.** 단, 묶음 실행은 하위 티켓마다 `origin/staging`에서 새로 분기하므로
   (`.claude/workflows/jam-work.js:383-386`) 앞 티켓의 미머지 결과를 이어받지 못한다. 그래서 공통 부품에
   의존하는 순서만 지킨다: ① 단독 실행 → staging 머지 → ② 단독 실행 → staging 머지 → ③~⑥ 묶음 실행.
