# [Admin] 어드민 목록 테이블 공통화 (상위 티켓)

## 핵심 요약

- 요구사항: 어드민의 모든 목록 화면이 같은 틀을 쓰게 한다. 전체 선택, 메뉴별 필터(연쇄 필터 포함),
  번호 페이지 이동, 상세는 항상 새 페이지, 상세로 넘어갈 때 로더 없음, 정렬, 이름 검색, 그리고
  **메뉴별 대표 기능(표에서 바로 고치는 기능과 일괄 처리 버튼)** 을 갖춘다. 사용자는 대표 기능(아래
  §4)을 가장 중요한 항목으로 지정했다.
- 구현 계획: 공통 부품을 먼저 만들고 체크인 관리(POI)에 시범 적용한 뒤, 나머지 메뉴를 묶음 단위로
  옮긴다(§7 분해안). 하위 티켓은 분해안이 승인되면 만든다.
- 관련 파일: `jam-web/src/components/admin/data-table/*`(공통 부품),
  `jam-web/src/app/admin/poi/Pagination.tsx`(번호 페이지 이동, 공용 폴더로 옮길 대상),
  `jam-web/src/components/NavigationLoader.tsx:55-58`(어드민 로더 제외 지점),
  `docs/specs/prd/admin-ui/REDESIGN.md` §4(목록 표준을 적을 곳)

## 상세 요구사항

### 1. 목록 표준 (공통 부품이 보장할 것)

| # | 요구 | 표준 |
|---|---|---|
| 1 | 전체 선택 | 머리 체크박스는 현재 페이지를 선택한다. 선택하면 표 위에 "이 조건의 N건 모두 선택" 안내가 나타나고, 누르면 필터 결과 전체가 선택된다. 페이지를 넘겨도 선택이 유지된다 |
| 2 | 필터 | 메뉴의 상태 값(활성·노출·유형·분류)을 필터로 둔다. 앞 필터에 따라 선택지가 바뀌는 연쇄 필터를 부품이 지원한다(예: 배지 유형 → 종목/카테고리/트라이브, 트라이브 → 컬렉션). 필터를 바꾸면 1쪽으로 돌아가고 선택이 풀린다 |
| 3 | 페이지 이동 | 번호형(처음·끝, 현재 ±2, 이전·다음). 한 쪽 크기는 50건으로 통일한다. 1쪽뿐이면 숨긴다 |
| 4 | 상세 이동 | 같은 탭에서 상세 페이지로 이동한다. 모달·서랍으로 상세를 열지 않는다. 행 아무 곳이나 눌러도 이동하고, 이름은 링크로 남겨 Cmd+클릭으로 새 탭을 열 수 있게 한다. 체크박스·스위치·버튼을 누를 때는 이동하지 않는다 |
| 5 | 로더 | 목록에서 상세로 이동할 때 전체 화면 로더·스피너를 띄우지 않는다(현재 동작을 표준으로 고정). 멈춘 것처럼 보이는 시간은 링크 미리 불러오기로 줄인다 |
| 6 | 정렬 | 정렬 선택(최신순·오래된순·이름순 등 메뉴별 목록)과 머리 칸 정렬을 URL 하나로 묶는다. 페이지가 나뉜 목록은 서버에서 정렬한다 |
| 7 | 대표 기능 | §4 메뉴별 표를 따른다. 공통 틀: (a) 표 안의 대표 기능은 메뉴당 1개, 누르면 바로 반영되고 실패하면 원래 값으로 돌아가며 이유를 안내한다 (b) 일괄 처리 바에는 대표 버튼 1~2개를 드러내고 나머지는 "더보기"에 넣는다 (c) 확인 방식은 §3 위험 등급을 따른다 (d) 결과는 "N건 처리, M건 건너뜀(사유)"로 안내한다 |
| 8 | 이름 검색 | 이름(메뉴에 따라 제목·이메일 포함)으로 검색한다. 입력을 멈추고 0.4초 뒤 반영하고, URL에 남는다 |

### 2. 서버 일괄 처리

- 일괄 기능은 메뉴마다 **요청 한 번**으로 처리한다(`POST /api/admin/<메뉴>/bulk`, 본문에 ID 목록 또는
  필터 조건, 동작 이름, 값).
- 상태 변경(활성화·노출·분류 지정)은 모두 반영되거나 모두 취소된다.
- 삭제처럼 참조 보호가 걸린 동작은 막힌 항목만 건너뛰고, 건너뛴 항목과 사유를 돌려준다.
- 한 번에 처리하는 상한은 1,000건이다. 필터 결과가 상한을 넘으면 실행하기 전에 알린다.

### 3. 위험 등급별 확인 방식

| 등급 | 해당 동작 | 확인 방식 |
|---|---|---|
| 1 되돌릴 수 있음 | 활성화·비활성화, 노출 전환, 분류 지정, 내보내기 | 표 안의 대표 기능은 확인 없이 바로 반영. 일괄 처리는 "N건을 ○○할까요?" 확인창 |
| 2 되돌릴 수 있으나 유저에게 보임 | 배지 비활성화(아직 줍지 않은 월드 드랍 무효화), 미션 기간 종료, 제재 등급 변경 | 확인창에 영향 건수를 함께 표시(예: 참여 중인 유저 N명, 무효화될 드랍 N건) |
| 3 되돌릴 수 없음 | 삭제, 아이템 폐기, 획득 이력 삭제 | 확인 문구 입력(배지 일괄 변경 도구의 방식을 공용으로 승격) |

## 4. 메뉴별 대표 기능 (7번 분석 결과)

기호: **기존** = 이미 있음, **신규** = 새로 만듦, **교체** = 단건 반복을 서버 일괄 처리로 바꿈.

### 4.1 발행형 컨텐츠: 대표 상태는 "노출"

| 메뉴 (규모) | 표 안 대표 기능 | 일괄 처리 | 필터·검색·정렬 보강 | 주의 |
|---|---|---|---|---|
| 배지 관리 (4,091) | 활성 스위치 **기존** | 활성화·비활성화 **교체**, 삭제 **기존**, 트라이브·컬렉션 지정 **신규**, 내보내기 **신규** | 연쇄 필터는 이미 있음. 필터 결과 전체 선택이 가장 필요한 화면 | 비활성화는 등급 2(무효화될 월드 드랍 건수 표시). 트라이브·컬렉션을 바꾸면 컬렉션 완성 판정이 달라지므로 등급 2 |
| 컬렉션 (100) | 활성 스위치 **기존** | 활성화·비활성화 **교체**, 삭제 **기존** | 이름 검색·상태 필터 **신규** | 노출 기간이 컬렉션 노출에 바로 반영됨 |
| 트라이브 (10) | 활성 스위치 **신규** | 활성화 **신규**(지금은 비활성화만 있음), 비활성화 **교체** | 없음(10건) | 활성 여부가 드랍 엔진에 바로 반영되므로 등급 2. 삭제는 드랍 기록 참조 때문에 사실상 항상 막힌다 → 삭제 버튼 대신 막힌 이유를 표시 |
| 투데이 콘텐츠 (51) | 활성 스위치 **기존**(실패 안내 없음 → 보강) | 활성화 **신규**, 비활성화 **교체**, 기간 종료 **신규**, 삭제 **기존** | 템플릿 유형 필터·제목 검색 **신규**, 날짜 이동은 유지 | 날짜를 바꿔도 선택이 풀리지 않는 문제 수정 |
| 미션 (53) | 노출 선택(숨김 ↔ 노출) **신규** | 숨김·노출 전환 **신규**, 기간 종료 **신규**, 삭제 **기존** | 연쇄 필터 **신규**: 일반/게이트 → 미션 유형 → 보상 유형. 상태 필터(예정·진행·종료). 제목 검색, 번호 페이지 이동 | 기간 종료·숨김은 참여 중인 유저 수를 보여 주는 등급 2 |
| 체크인 관리·POI (2,451) | 활성 스위치 **기존** | 활성화·비활성화·카테고리 변경 **교체**, 삭제 **기존**, 내보내기 **신규** | 상태·등급·연결 배지 유무 필터 **신규** | 지역 → 구 연쇄 필터는 POI에 지역 칸이 없어 불가(위도·경도만 있음). 이번 범위에서 뺀다 |
| 믹스 레시피 (0) | 없음(활성 여부 칸이 없음) | 삭제 **교체** | 이름 검색 | 삭제가 막혀도 안내하지 않는 문제 수정(`RecipeList.tsx:29`). 활성 여부 칸 추가는 믹스 로직에도 영향을 주므로 별도 기획으로 분리 |
| 랭킹 규칙 (소수) | 없음 | 없음 | 표준 표로 교체 | 삭제하면 이 규칙을 쓰는 투데이 카드가 끊긴 채 남는다 → 삭제 전 참조 보호 추가 |

### 4.2 검토 큐형: 대표 기능은 "승인·거부"

| 메뉴 | 표 안 대표 기능 | 일괄 처리 | 보강 |
|---|---|---|---|
| POI 검토 큐 | 승인·카테고리 지정 후 승인·거부 **기존** | 일괄 승인·거부 **기존**(이미 서버 일괄) | 이름 검색·네이버 원본 분류 필터 **신규** |

### 4.3 감사·기록형: 바꾸는 기능 없이 "내보내기"

| 메뉴 | 표 안 대표 기능 | 일괄 처리 | 보강 |
|---|---|---|---|
| 아이템배지 발급현황 | 없음 | 내보내기 **신규** | 필터를 걸지 않으면 목록이 안 나오고 100건까지만 보여 준다 → 번호 페이지 이동으로 교체. 발급 수 집계가 1,000행 상한에 걸릴 수 있음(`item-badges/page.tsx:66`) |
| 미소유 아이템배지 (1,268) | 없음 | 폐기(등급 3)·재배정 **기존**, 내보내기 **신규** | 발급일시 정렬이 현재 페이지 안에서만 됨 → 서버 정렬 |

| 배지 계열 | 없음 | 선택한 계열 재계산 **신규**(기존 재계산 API 재사용) | 행 선택과 번호 페이지 이동 도입 |

### 4.4 사람·제재형

| 메뉴 | 표 안 대표 기능 | 일괄 처리 | 보강 |
|---|---|---|---|
| 유저 조회 | 없음(제재 상태·어드민 여부를 표시만 함) | 내보내기 **신규** | 이름·이메일 검색, 서버 페이지 이동, 트라이브·온보딩·제재 상태 필터 **신규**. 일괄 삭제·초기화는 넣지 않는다(되돌릴 수 없음) |
| 유저 상세의 하위 표 | 없음 | 없음 | 배지 이력에 개수 제한이 없음 → 번호 페이지 이동 |
| 어뷰징 (제재·POI 차단) | 제재 등급 전환(soft ↔ hard) **신규** | 해제 **교체**, 만료 연장 **신규** | 활성/만료 필터 **신규**(만료된 제재가 계속 목록에 남는 문제). 해제가 행 삭제라 기록이 남지 않는 문제는 범위 밖 발견물로 분리 |
| 드랍 제외 관리 | 제외 스위치(컬렉션 **기존**, 아이템배지 **신규**) | 제외·해제 **교체** | 이름 검색·정렬 **신규**. 컬렉션 구역도 표준 표로 교체 |

### 4.5 같은 값을 두 메뉴에서 바꾸지 않는다

드랍 제외 여부는 **드랍 제외 관리 한 곳**에서만 바꾼다. 배지·컬렉션 목록에는 드랍 제외 스위치나
일괄 버튼을 넣지 않는다. 같은 값을 두 화면에서 바꾸면 어느 화면이 기준인지 흐려진다.

- **예외 후보(결정 대기)**: 배지 지표 라벨·POI 카테고리(사전형 설정표로, 줄 안에서 바로 편집함),

- **대상 아님(설정·도구 화면 10개)**: 드랍 정책, 앰비언트 드랍, 믹스 정책, 인벤토리 최대치, 배지 일괄

## 6. 결정 대기

1. 전체 선택 범위: 현재 페이지 + "필터 결과 전체" 확장(추천) / 현재 페이지만
2. 예외 후보 3개 화면을 예외로 둘지
3. 위험한 일괄 기능(유저 일괄 삭제·초기화, 포인트 일괄 지급·회수)을 제외할지(추천: 제외)
4. 진행 방식: 공통 부품 + POI 시범 적용 후 확인하고 나머지를 진행(추천) / 전체 묶음 실행

## 7. 분해안 (승인 후 하위 티켓 생성)

아현의 계획 반환 기준(파일 5개 초과 또는 100줄 이상)을 모든 하위 티켓이 넘으므로, 하위 티켓마다
파일 단위 구현 계획을 적고 첫 호출부터 계획 반환 면제를 넘긴다.

| 순서 | 하위 티켓 | 범위 |
|---|---|---|
| ① | 공통 부품 | URL 상태 훅, 검색 입력, 정렬 선택, 번호 페이지 이동(공용 폴더로 이동), 필터 결과 전체 선택 안내, 일괄 처리 바(대표 버튼 + 더보기), 위험 등급별 확인창, 표 안 스위치 셀, 행 클릭 이동, 내보내기. REDESIGN.md §4에 목록 표준 명문화 |
| ② | 서버 일괄 처리 틀 + 체크인 관리 시범 적용 | 공용 서버 헬퍼, POI 일괄 API, POI 화면 전환(①의 부품 검증) |
| ③ | 배지 관리·컬렉션·트라이브 | §4.1 해당 행 |
| ④ | 미션·투데이·랭킹 규칙 | §4.1 해당 행 |
| ⑤ | POI 검토 큐·드랍 제외 관리·믹스 레시피·배지 계열 | §4.2·§4.3·§4.4 해당 행 |
| ⑥ | 아이템배지 발급현황·미소유 아이템배지·유저 조회·어뷰징·포인트 | §4.3·§4.4 해당 행 |

- 대표 기능을 메뉴 성격 네 가지(발행형·검토 큐형·감사 기록형·사람 제재형)로 나눠 정했다. 발행형은
