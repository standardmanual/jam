## 배경 / 문제 정의

상위 티켓 §배경 참고. 요약: 공용 `DataTable`은 헤더·본문·빈 상태만 그리고, 검색(400ms 지연)·정렬·URL 갱신 코드가 11곳에
복사돼 있으며, 번호 페이지 이동 부품은 `poi` 폴더 안에 있다. 선택은 현재 페이지에서만 되고, 확인 방식에 위험 등급이 없다.

설계 조사에서 확인한 사실(2026-09-24):
- Next 16은 쿼리만 바뀐 이동에서 클라이언트 상태를 유지한다. TanStack v9의 `toggleAllPageRowsSelected`는 다른 페이지의 선택
  키를 보존한다. 그래서 페이지를 넘는 선택은 표의 `rowSelection` 상태로 유지할 수 있다. 단, `getSelectedRowModel`은 현재 페이지
  행만 돌려주므로 선택 ID는 `rowSelection`의 키에서 읽는다.
- vitest가 `environment: 'node'`라서 테스트는 순수 함수와 소스 스캔 계약 테스트로 한다.
- 전역 로더는 어드민을 일부러 제외한다(`jam-web/src/components/NavigationLoader.tsx:55-58`). 이 동작을 표준으로 유지한다.

### UI/UX 관점
- 행 클릭(`DataTable`의 `getRowHref`):
  - 같은 탭에서 `router.push`. Cmd·Ctrl 클릭이면 `window.open`으로 새 탭.
  - 무시: `defaultPrevented`, 주 버튼이 아닌 클릭, `a·button·input·label·[role=switch]·[role=checkbox]` 안의 클릭, 텍스트 선택 중,
    행 DOM 밖에서 온 이벤트(포털 대화상자의 클릭이 React 트리를 타고 올라오는 경우).
  - 마우스를 올리면 `router.prefetch(href)`, 행에 `cursor-pointer`. 로더·스피너는 띄우지 않는다. 어드민에 `loading.tsx`를 만들지 않는다.
  - 개발 모드에서 `getRowId`가 없으면 경고한다(없으면 쪽이 달라도 같은 행 번호끼리 선택이 섞인다).
- 일괄 처리 바: 앞의 `primaryCount`개는 버튼, 나머지는 "더보기". 선택 수 문구는 "N건 선택됨"(기존 "개"를 "건"으로).
- 확인창 등급:
  - 1: "N건을 ○○할까요?"
  - 2: 1 + `impact` 영역(불러오는 중에는 확인 버튼 비활성)
  - 3: 2 + 확인 문구 입력. 일치할 때만 확인 버튼 활성(`isPhraseMatch`, 앞뒤 공백 무시)
- 내보내기는 데이터를 바꾸지 않으므로 확인창 없이 바로 내려받는다.
- 사용자 노출 문구는 `.claude/output-styles/fluent-korean.md`와 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

### 주요 의사결정 / 핵심 메모
- 아현의 가정(민지 PASS로 수용):
  - `formatBulkResult`는 "N건 처리"를 동사 치환(`${count}건 ${verb}`)으로 구현
  - `useListParams`의 `filters`는 page·sort·q를 뺀 필터만, `filterQuery`는 필터 + q(서버 조회·CSV용)
  - `selectAllBannerState`의 네 상태는 hidden / prompt / all-selected / capped(상한 초과)
  - `confirmPhraseFor(action, count)`는 동작과 건수만 쓴다. 영향 수치는 `BulkConfirmDialog`의 별도 영역이 맡는다
  - 7개 화면 교체 때 `<Suspense>`를 더하지 않았다(이미 searchParams prop으로 동적 렌더링됨)
- 머지 전 오염 검사가 실패했다. ①이 도는 동안 병렬 세션이 staging에 커밋 18개를 올렸기 때문이다. `origin/staging..브랜치`는 ①의 커밋
  하나뿐이었고 변경 파일도 겹치지 않았다. 처리 규칙표(들어온 내용을 먼저 읽고 `git rebase origin/staging`)대로 격리 워크트리에서
  리베이스했다. 기존 review 브랜치의 강제 push는 권한 설정에 막혀, 리베이스한 커밋을 새 브랜치
  `claude/jamwork-20260924_0940-admin-list-common-parts-rebased`로 올려 CI를 다시 돌린 뒤 그 커밋을 머지했다.
