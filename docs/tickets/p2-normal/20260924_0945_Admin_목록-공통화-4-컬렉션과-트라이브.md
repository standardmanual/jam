# [Admin] 목록 공통화 ④ 컬렉션·트라이브 목록 전환과 트라이브 삭제 보호 누락 수정

## 핵심 요약

- 요구사항: 컬렉션(100건)과 트라이브(10건) 목록을 상위 티켓 20260924_0916 §1 표준과 §4.1 해당 행대로 바꾼다.
  - 컬렉션: 표 안 활성 스위치(등급 1), 일괄 활성화·비활성화(등급 1)·삭제(등급 3)·내보내기, 이름 검색·상태 필터 추가.
  - 트라이브: 표 안 활성 스위치(끄기는 등급 2), 일괄 활성화(신규)·비활성화(등급 2)·삭제(등급 3), 삭제 불가 사유 표시.
  - 유저가 고른 트라이브의 삭제 보호 누락(현재 500 오류)을 고친다.
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀과 `countRowsByKey`·`sanitizeSearchTerm`을 쓴다.
- 관련 파일: `jam-web/src/app/admin/itembooks/page.tsx`, `jam-web/src/app/admin/itembooks/ItemBookFilters.tsx`,
  `jam-web/src/components/admin/itembooks/ItemBookTable.tsx`, `jam-web/src/app/admin/tribes/page.tsx`,
  `jam-web/src/app/admin/tribes/TribesTable.tsx`, `jam-web/src/lib/admin/reference-guards.ts:269-294`

## 배경 / 문제 정의

- 컬렉션·트라이브 모두 일괄 처리가 단건 요청을 반복한다(`ItemBookTable.tsx:207-253`, `TribesTable.tsx:177-200`).
- 두 화면 모두 연결된 배지 수를 행째로 받아 세므로 1,000행 상한에 걸릴 수 있다(`itembooks/page.tsx:70-72`, `tribes/page.tsx:10-11`).
- `users_tribe_id_fkey`는 삭제를 막는 FK(NO ACTION)인데 `reference-guards.ts`의 트라이브 보호 목록에 없다(운영 DB에서 확인,
  2026-09-24). 그래서 유저가 고른 트라이브를 지우면 보호 검사를 통과한 뒤 DB에서 막혀 500이 난다.
- 드랍 엔진은 트라이브의 활성 여부를 읽지 않는다(`jam-web/src/lib/drop-engine/index.ts:185-201`). 트라이브 비활성화의 실제 영향은
  온보딩 선택지(`jam-web/src/app/(main)/onboarding/page.tsx:72-74`)와 추천 후보(`jam-web/src/lib/content-corpus/active.ts`)에서
  빠지는 것이다. 확인창 문구는 이 사실대로 쓴다(의미 확장은 티켓 20260924_0938).

쓴다. 파일 단위 계획은 위 표와 같다.
