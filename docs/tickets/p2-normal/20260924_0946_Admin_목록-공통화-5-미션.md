# [Admin] 목록 공통화 ⑤ 미션 목록 전환 — 연쇄 필터·노출 스위치·숨김/기간 종료 일괄 처리

## 핵심 요약

- 요구사항: 미션(53건) 목록을 상위 티켓 20260924_0916 §1 표준과 §4.1 미션 행대로 바꾼다.
  - 표 안 대표 기능: 노출 스위치(숨김 ↔ 노출). 숨김은 등급 2.
  - 일괄: [숨김] (등급 2) [노출] (등급 1), 더보기 [기간 종료] (등급 2) [내보내기] [삭제] (등급 3).
  - 연쇄 필터: 구분(일반/게이트) → 미션 유형 → 보상 유형. 상태(예정·진행·종료), 제목 검색, 정렬, 번호 페이지 이동.
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀과 `countRowsByKey`·`sanitizeSearchTerm`을 쓴다.
- 관련 파일: `jam-web/src/app/admin/missions/page.tsx:8-27`, `jam-web/src/app/admin/missions/MissionTable.tsx:87-100,202-324`,
  `jam-web/src/app/admin/missions/MissionList.tsx:22-40`, `jam-web/src/app/api/admin/missions/[id]/route.ts:13-93`,
  `jam-web/src/lib/missions/checker.ts:55-60,80-85`, `jam-web/src/lib/admin/badge-labels.ts:39`

## 배경 / 문제 정의

- 목록이 필터·페이지 이동 없이 전체를 불러오고, 게이트 미션까지 섞여 보인다(`missions/page.tsx:8-11`).
- 완료 수를 행째로 받아 세므로 1,000행 상한에 걸릴 수 있다(`missions/page.tsx:17-27`).
- 단건 삭제가 브라우저 기본 `confirm()`을 쓴다(`MissionList.tsx:22-40`). 제목은 링크가 아니고 "수정" 버튼으로만 이동한다.
- 상태(예정·진행·종료)는 저장된 값이 아니라 날짜에서 계산한다(`MissionTable.tsx:87-100`).
- 진행 판정(`checker.ts:80-85`)은 노출 모드를 보지 않는다. 그래서 숨겨도 참여 중인 유저는 계속 진행·완료·보상을 받는다.

연쇄 필터:
- 구분: 일반 = `gate_axis`와 `gated_badge_id`가 모두 null / 게이트 = 그 밖.
- 미션 유형: `MISSION_TYPE_LABEL`(`badge-labels.ts:39`). 앞 구분에 존재하는 유형만 선택지로 보인다.
- 보상: 배지 = `reward_badge_ids`가 비어 있지 않음 / 포인트 = `reward_points > 0` / 없음.

상태 필터(기준 시각은 서버에서 한 번 정하고 계산한 상태를 행에 실어 보낸다):
- 진행: `starts_at <= now` 그리고 (`ends_at` null 또는 `>= now`) — `activeMissionsQueryFilter`(`checker.ts:55-60`) 재사용.
- 예정: `starts_at > now`. 종료: `ends_at < now`.

노출 스위치:
- 숨김: `exposure_mode = 'hidden'`. `beforeChange`로 1건 미리보기 → 등급 2 확인창.
- 노출: `exposure_at`이 있으면 `'scheduled'`, 없으면 `'start_date'`로 되돌린다. 기존 `PATCH /api/admin/missions/[id]`(13-93)로 충분하다.

`bulk` 동작:
- `hide`(등급 2)·`show`(등급 1): `show`는 행마다 되돌릴 모드가 달라 두 문장이 된다. 뒤 문장이 실패하면 앞 문장을 되돌린다.
- `end_period`(등급 2): `ends_at = now`. 시작 전·이미 종료된 미션은 사유와 함께 건너뛴다.
- `delete`(등급 3): 기존 참조 보호(`jam-web/src/lib/admin/reference-guards.ts:103-120`)로 막힌 항목은 건너뛴다.
- 미리보기 `impact.inProgressUsers` = 미션별 `user_mission_participations` 건수 − `user_mission_completions` 건수의 합(두 표 모두
  유저·미션당 한 행이고 완료는 참여가 전제다, `checker.ts:136-138`).
- 숨김 확인창에 "숨겨도 이미 참여 중인 유저는 계속 진행하고 보상을 받아요"를 적는다.
