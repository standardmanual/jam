# [Admin] 목록 공통화 ⑥ 투데이 콘텐츠·랭킹 규칙 목록 전환과 랭킹 규칙 삭제 보호

## 핵심 요약

- 요구사항: 투데이 콘텐츠(51건)와 랭킹 규칙 목록을 상위 티켓 20260924_0916 §1 표준과 §4.1 해당 행대로 바꾼다.
  - 투데이: 표 안 활성 스위치(실패 시 복원·안내), 일괄 [활성화] (신규) [비활성화] 더보기 [기간 종료] (신규) [내보내기] [삭제] (등급 3).
    템플릿 필터·제목 검색·정렬 추가, 날짜 이동 유지.
  - 랭킹 규칙: 표준 표로 교체(행 클릭 이동, 제목 검색, 정렬, 연결된 카드 수 칸). 일괄 처리 없음. 삭제 전 참조 보호 추가.
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀·공용 도구를 쓴다. 참조 보호는 `reference-guards.ts`가 아닌 새 파일에
  둔다(④가 `reference-guards.ts`를 고치므로 묶음 실행의 병합 충돌을 피한다).
- 관련 파일: `jam-web/src/app/admin/today/page.tsx:31-37`, `jam-web/src/app/admin/today/TodayCardTable.tsx:66-82,208-229`,
  `jam-web/src/app/admin/today/TodayCardList.tsx:24-37`, `jam-web/src/app/admin/today/TodayDateNav.tsx:23`,
  `jam-web/src/app/admin/ranking-modes/page.tsx:57-104`, `jam-web/src/app/api/admin/ranking-modes/[id]/route.ts:33-44`

## 배경 / 문제 정의

- 투데이 활성 토글이 응답 성공 여부를 보지 않고, 삭제도 오류를 무시한다(`TodayCardList.tsx:24-37`).
- 날짜를 바꿔도 선택이 풀리지 않는다(`TodayCardTable.tsx:66-82`에 목록 변경 시 선택 초기화가 없음).
- 일괄 비활성화가 단건 PATCH를 반복한다(`TodayCardTable.tsx:208-229`).
- 날짜 이동이 다른 쿼리 파라미터를 버린다(`TodayDateNav.tsx:23`).
- 랭킹 규칙 삭제는 바로 지운다(`ranking-modes/[id]/route.ts:33-44`). 카드의 규칙 참조는 삭제 시 비워지도록 되어 있어
  (`jam-web/supabase/migrations/158_ranking_modes.sql:76`) 랭킹보드 카드가 빈 채로 남는다.

## 완료 조건

- `TodayCardList.tsx`와 `today/bulk-delete` 라우트가 없고, 투데이 화면에 단건 요청 반복이 없다.
- 단위 테스트: `today-list-query`(날짜·템플릿·검색어 조건), 랭킹 규칙 참조 집계(활성·미종료 카드만 셈).
- 랭킹 규칙을 쓰는 활성 카드가 있으면 `DELETE /api/admin/ranking-modes/[id]`가 409를 돌려준다(로컬에서 존재하지 않는 규칙 ID로
  호출해 404/409 분기를 확인하고, 실제 삭제는 하지 않는다).
- `scripts/verify.sh` 통과.
- 로컬 실렌더(패턴 13, **저장하지 않고 읽기만**): 날짜를 바꾸면 선택이 풀린다. 템플릿 필터를 건 채 날짜를 넘겨도 필터가 유지된다.
  스위치 실패 시 원래 값으로 돌아간다(개발자 도구로 요청 차단). 랭킹 규칙 표에 연결된 카드 수가 보인다.
