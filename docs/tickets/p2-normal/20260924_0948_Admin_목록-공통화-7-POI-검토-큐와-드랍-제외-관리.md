# [Admin] 목록 공통화 ⑦ POI 검토 큐·드랍 제외 관리 목록 전환과 검토 처리 조건 누락 수정

## 핵심 요약

- 요구사항: POI 검토 큐와 드랍 제외 관리 목록을 상위 티켓 20260924_0916 §1 표준, §4.2, §4.4 드랍 제외 행대로 바꾼다.
  - POI 검토 큐: 행 안 버튼 3개(승인·카테고리 지정 후 승인·거부)는 유지. 일괄 [일괄 활성화] 더보기 [카테고리 지정 후 활성화] [거부].
    이름 검색·네이버 원본 분류 필터·정렬 추가. 검토 처리에 `pending_review` 조건을 더한다.
  - 드랍 제외 관리: 탭(아이템배지/컬렉션)마다 표준 표 하나. 표 안 제외 스위치, 일괄 [제외] [해제] (등급 1). 트라이브 → 컬렉션 연쇄
    필터, 이름 검색, 상태(제외됨/드랍 대상), 정렬.
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀·공용 도구를 쓴다.
- 관련 파일: `jam-web/src/app/admin/poi/review/page.tsx:11,39-50`, `jam-web/src/app/admin/poi/review/PoiReviewTable.tsx:78-97,400-431`,
  `jam-web/src/app/api/admin/poi/review/bulk/route.ts:15-42`, `jam-web/src/lib/admin/poi-review.ts:90-132`,
  `jam-web/src/app/admin/drop-policy/exclusions/page.tsx:19,41-94`,

## 배경 / 문제 정의

- 검토 처리 update에 `pending_review = true` 조건이 없다(`poi-review.ts:90-92, 109-112, 132`). "필터 결과 전체 선택" 사이에 다른
  어드민이 이미 승인한 POI를 거부하면, 그 POI가 미분류로 옮겨지고 지도에서 숨겨진다.
- 검토 큐 일괄 라우트는 자체 파싱과 `{ updated }` 응답을 쓴다(`review/bulk/route.ts:15-27, 42`).
- 드랍 제외 아이템배지 표는 단건 PATCH를 반복하고 확인창이 없다(`DropExclusionBadgesTable.tsx:166-186`). 한 쪽 크기가 500이다.
- 드랍 제외 컬렉션 구역은 선택·페이지 이동이 없는 카드 목록이다(`DropExclusionCollectionsTable.tsx:45-73`).

## 완료 조건

- `poi-review.ts`의 승인·거부 update 세 곳에 `pending_review = true` 조건이 있다. 단위 테스트(기록형 스텁)가 이를 고정한다.
- 드랍 제외 두 표에 단건 요청 반복이 없다.
- 단위 테스트: `poi-review-list`·`drop-exclusion-list`의 필터 조건.
- `scripts/verify.sh` 통과.
- 로컬 실렌더(패턴 13, **저장하지 않고 읽기만**): 검토 큐에서 필터 결과 전체 선택 → 일괄 활성화 확인창까지 연다(실행하지 않음).
  드랍 제외 탭을 바꾸면 선택과 쪽 번호가 탭별로 유지된다. 트라이브를 고르면 컬렉션 선택지가 좁혀진다.
