# [Admin] 목록 공통화 ⑧ 믹스 레시피·배지 계열 목록 전환과 레시피 삭제 실패 무안내 수정

## 핵심 요약

- 요구사항: 믹스 레시피와 배지 계열 목록을 상위 티켓 20260924_0916 §1 표준, §4.1 레시피 행, §4.3 배지 계열 행대로 바꾼다.
  - 믹스 레시피: 행 클릭 이동, 이름 검색·정렬·번호 페이지 이동. 삭제는 선택 후 일괄 삭제(등급 3) 한 경로로 합친다. 삭제가 막혀도
    안내하지 않는 문제와 브라우저 기본 `confirm()`을 없앤다.
  - 배지 계열: 일반 HTML 표를 표준 표로 바꾸고 행 선택·번호 페이지 이동·내보내기를 넣는다. 일괄 재계산은 넣지 않는다(상위 티켓 결정).
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀·공용 도구를 쓴다. 배지 계열의 행 ID는 UUID가 아닌 계열 키이므로
  `idFormat: 'string'`을 쓴다.
- 관련 파일: `jam-web/src/app/admin/recipes/RecipeList.tsx:22-29`, `jam-web/src/app/admin/recipes/RecipeTable.tsx:159-212`,
  `jam-web/src/lib/admin/recipe-references.ts:55`, `jam-web/src/app/admin/badge-families/page.tsx:109-182`,
  `jam-web/src/lib/admin/badge-families-query.ts:36`

## 배경 / 문제 정의

- 레시피 단건 삭제가 응답 성공 여부를 보지 않는다(`RecipeList.tsx:29`). 참조로 409가 나도 아무 안내 없이 새로고침된다.
  확인창도 브라우저 기본 `confirm()`이다(`RecipeList.tsx:28`).
- 레시피 일괄 삭제가 단건 DELETE를 반복한다(`RecipeTable.tsx:192-212`).
- 배지 계열 목록은 선택·페이지 이동이 없는 일반 표다(`badge-families/page.tsx:109-182`).
- 레시피에는 활성 여부 칸이 없다(`is_public`은 마이그레이션 174에서 삭제). 그래서 표 안 대표 기능은 두지 않는다.
