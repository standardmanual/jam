# [Admin] 목록 공통화 ⑨ 아이템배지 발급현황·미소유 아이템배지·포인트 고액 원장 목록 전환

## 핵심 요약

- 요구사항: 감사·기록형 목록 세 화면을 상위 티켓 20260924_0916 §1 표준과 §4.3 해당 행대로 바꾼다.
  - 아이템배지 발급현황: "필터가 없으면 목록이 안 나옴"과 100건 제한을 없애고 번호 페이지 이동으로 바꾼다. 발급 수를 정확히 센다.
    일괄 처리는 내보내기뿐이다.
  - 미소유 아이템배지(1,268건): 정렬을 서버로 옮긴다. 일괄 [폐기] (등급 3) [재배정] (등급 2, 상한 200) [내보내기].
  - 포인트 고액 원장: 고정 20건을 필터·페이지 이동이 있는 목록으로 바꾸고 내보내기를 넣는다.
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀과 `countRowsByKey`·`sanitizeSearchTerm`을 쓴다.
- 관련 파일: `jam-web/src/app/admin/item-badges/page.tsx:38-86`, `jam-web/src/app/admin/item-badges/ItemBadgeSearchBar.tsx:38-50`,
  `jam-web/src/app/admin/item-badges/orphaned/page.tsx:75-187`, `jam-web/src/app/admin/item-badges/orphaned/OrphanedItemsTable.tsx`,
  `jam-web/src/app/admin/item-badges/_orphaned-actions/`, `jam-web/src/lib/points/summary.ts:90-92`,
  `jam-web/src/app/admin/points/HighValueTable.tsx`

## 배경 / 문제 정의

- 발급현황은 필터를 걸지 않으면 목록이 안 나오고(`item-badges/page.tsx:38, 52, 86`), 100건까지만 보여 준다(`:61`). 발급 수는 행을
  전부 받아 세므로 1,000행에서 잘려 적게 나온다(`:64-70`). 필터를 바꿔도 쪽 번호가 남는다(`ItemBadgeSearchBar.tsx:38-45`).
- 미소유 목록은 전체를 불러온 뒤 발급일 역순으로 고정 정렬하고(`orphaned/page.tsx:75-170`), 머리 칸 정렬은 현재 페이지 안에서만
  된다(`OrphanedItemsTable.tsx:48, 122, 139-140`). 폐기 확인은 단순 확인창이다.
- 포인트 고액 원장은 20건 고정이다(`summary.ts:90-92`).

## 완료 조건

- 발급현황이 필터 없이도 목록을 보여 주고, 발급 수가 `countRowsByKey`로 계산된다(단위 테스트: 1,000행을 넘는 스텁).
- 미소유 목록의 정렬이 쪽을 넘어 일관된다(단위 테스트: `sortOrphanedRows`).
- 옛 `orphaned/destroy`·`orphaned/reassign` 라우트가 없고 `rg "orphaned/(destroy|reassign)" jam-web/src` 결과가 0건이다.
- `scripts/verify.sh` 통과.
- 로컬 실렌더(패턴 13, **저장하지 않고 읽기만**): 세 화면의 번호 페이지 이동·필터·정렬이 동작한다. 폐기 확인창에 확인 문구 입력이
  나타난다(실행하지 않음). 내보낸 CSV를 엑셀에서 열면 한글이 정상이다.
