# [Admin] 목록 공통화 ⑪ 어뷰징(제재·POI 차단) 목록 전환 — 활성/만료 필터, 등급 전환, 해제 기록 남기기

## 핵심 요약

- 요구사항: 어뷰징 화면의 제재·POI 차단 목록을 상위 티켓 20260924_0916 §1 표준과 §4.4 어뷰징 행대로 바꾼다.
  - URL 기반 탭(`?tab=bans|poi-blocks`)과 서버 페이지 이동. 상태 필터(활성/만료/전체), 검색.
  - 표 안 대표 기능: 제재 등급 전환(soft ↔ hard, 등급 2 확인창).
  - 일괄: [해제] (등급 2) [만료 연장] (등급 2). 해제할 때 지운 행을 `abusing_logs`에 남긴다(스키마 변경 없음).
- 구현 계획: ①(20260924_0940) 부품, ②(20260924_0941) 서버 틀·공용 도구를 쓴다.
- 관련 파일: `jam-web/src/app/admin/abusing/page.tsx:18-22`, `jam-web/src/app/admin/abusing/AbusingClient.tsx:55,116-132,174-204`,
  `jam-web/src/app/admin/abusing/BanTable.tsx`, `jam-web/src/app/admin/abusing/PoiBlockTable.tsx`,
  `jam-web/src/lib/abusing/shadow-ban.ts:139-146`, `jam-web/src/lib/abusing/poi-block.ts`,
  `jam-web/src/app/api/admin/abusing/bans/route.ts:31`

## 배경 / 문제 정의

- 제재 목록이 만료된 제재까지 200건을 보여 준다(`abusing/page.tsx:18-22`에 만료 조건 없음).
- 탭이 클라이언트 상태라 URL에 남지 않고(`AbusingClient.tsx:55`), 확인이 브라우저 기본 `confirm()`이며(`:116-132`), 일괄 해제가 단건
  DELETE를 반복한다(`:174-204`, 두 곳).
- 해제가 행 삭제라 누가 언제 해제했는지 기록이 남지 않는다(`shadow-ban.ts:139-146`).
- 기존 제재 적용(`POST .../bans`, `applyBan`)은 upsert라 `expires_at`을 null로 덮는다(`bans/route.ts:31`). 등급 전환에 재사용하면
  임시 제재가 영구 제재로 바뀐다.

미리보기 `impact`:
- 해제: 활성 hard 수, 활성 soft 수, 이미 만료된 수.
- 연장: 다시 적용될 만료 제재 수, 건너뛸 영구 제재 수.
- 등급 전환: 정책(`jam-web/src/lib/abusing/policy.ts`)상 드랍 배율이 어떻게 바뀌는지 문장으로.
