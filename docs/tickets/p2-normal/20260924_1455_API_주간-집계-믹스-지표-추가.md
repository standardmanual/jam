# [API] 주간 집계 API에 믹스 지표(실패 포인트 합계·결과물 배지 유효 여부)를 추가한다

> 티켓 20260924_1207에서 데이터 출처가 없어 분리한 항목이다.

## 핵심 요약

- 요구사항: 믹스 레시피를 등록하면 재료 1개만 넣어도 미매칭으로 소각되고 실패 포인트가 지급되는 파밍 통로가 열린다(`SERVICE_OPERATIONS.md` §8-1). 카즈하 주간 점검이 그 규모를 보려면 어드민 읽기 토큰으로 읽을 수 있는 지표가 필요하다. `GET /api/admin/kpi/weekly`에 다음을 추가한다: (1) 기간 내 `combine_fail_reward` 지급 건수와 합계, `combine_recipe_reward` 지급 건수와 합계, (2) 등록 레시피별 결과물 배지가 삭제되지 않았는지(`deleted_at`) 여부. 개인 식별 정보(닉네임·이메일·유저 ID)는 넣지 않는다.
- 구현 계획: `lib/admin/kpiWeekly.ts`의 `computeKpiWeeklyMetrics`에 포인트 원장 집계와 레시피 결과물 배지 유효 검사를 추가하고, 응답 형식을 문서(`scheduled-jobs.md` 데이터 출처 표, `weekly-briefing-format.md` 지표 출처)에 맞춘다. 단위 테스트를 추가한다. 카즈하 지시문 반영은 데이터가 생긴 뒤 별도로 한다.
- 관련 파일: `jam-web/src/app/api/admin/kpi/weekly/route.ts`, `jam-web/src/lib/admin/kpiWeekly.ts`, `jam-web/src/lib/points/index.ts`(`combine_fail_reward` 사유), `.claude/skills/jam-work/references/scheduled-jobs.md`

## 완료 조건

- 주간 집계 응답에 믹스 지표 두 가지가 들어가고 개인 식별 정보가 없다.
- 테스트가 원장 집계와 삭제된 결과물 배지 판정을 고정한다.

크기 상한: 3~4파일/100줄 미만(착수 시 파일 단위 계획을 먼저 적는다).
