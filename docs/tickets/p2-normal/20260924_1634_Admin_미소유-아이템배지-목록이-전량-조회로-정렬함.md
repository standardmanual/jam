### 구현 내용 요약
- **결정: 고치지 않는다(2026-09-26, 카리나).** 완료 조건 (b)(고치지 않기로 한 사유를 기록)에 해당한다.

### 사유
- 티켓의 문제는 미소유 목록·`orphaned/ids`·`orphaned/export`가 `loadOrphanedRows`로 전량(티켓 작성 시점 약 1,268건)을 읽고 요청당 DB 왕복이 수십 회라, 규모가 **수천 건 이상**이 되면 느려진다는 성능 잠재 위험이다. 현재는 그 규모에 미치지 못하고 화면이 동작 중이다. 정합성 오류(틀린 결과)가 아니라 속도 문제이며, 어드민 전용 화면이다.
- 서버 정렬을 DB 정렬·페이지 단위 조회로 바꾸는 것은 목록·ids·내보내기 세 경로의 조회 구조를 함께 바꾸는 작업이라 규모가 크다. 지금 규모에서 얻는 이득이 작고, 구조를 바꾸다 결과가 달라질 위험이 더 크다고 판단했다.
- 응답 시간은 이번에 측정하지 않았다(측정 없이 판단한 점을 밝힌다).

### 재검토 트리거
- 미소유 아이템배지가 **3,000건을 넘거나** 목록 응답이 눈에 띄게 느려지면(운영자 보고) 이 티켓 내용으로 새 티켓을 만들어 DB 정렬·페이지 단위 조회로 전환한다. 같은 성격의 티켓 20260926_1307(주간 집계 `.in()` 조회)·20260924_1636(제재 필터)과 조회 관례를 함께 정한다.
