# [Admin] 에셋 제너레이터 이미지 레이어 추가

## 핵심 요약

- 요구사항: 리본 레이어 위(또는 아래)에 업로드한 PNG/SVG를 고정 레이어로 얹는 이미지 레이어를 추가한다. 위치·크기는 스테이지
  비율(%)로, 회전·불투명도·순서를 조절한다. PRD §4.2.
- 구현 계획: 2155의 레이어 합성 훅에 이미지 레이어 렌더러를 구현하고, 2156 화면에 레이어 목록(추가·순서·삭제)과 이미지 레이어
  속성 패널을 붙인다. `shader-lab`의 이미지 레이어 사용감(업로드·위치·크기)을 참고하되 코드는 수정하지 않는다.
- 관련 파일: `jam-web/src/lib/asset-generator/render.ts`(레이어 합성 훅), `types.ts`(이미지 레이어 타입), `jam-web/src/app/admin/asset-generator/`
  (레이어 사이드바·속성 패널 신규 컴포넌트), 참고 `jam-web/src/app/admin/shader-lab/ShaderLabLayerSidebar.tsx`·`ShaderLabPropertiesPanel.tsx`

## 배경 / 문제 정의

배지 대표 이미지는 리본 그래픽 위에 아이콘(`/jam-img` 산출물 등)을 얹어 완성한다. 프리셋의 "아이콘 이미지 자리"가 이 레이어다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 레이어 목록: 리본 레이어(고정 1개, 삭제 불가) + 이미지 레이어 0~N. 위/아래 순서 변경.
- 이미지 레이어 속성: 원본(업로드, 화면에서는 메모리 보관 — 저장소 업로드는 2159), 위치 x·y(%), 크기(짧은 변 대비 %), 회전(°),
  불투명도(%), 순서.
- 렌더링은 리본 장면 위에 합성한다. 재생 중에도 고정 위치에 그대로 있다(곡선을 따라 움직이지 않는다).
- PNG·영상 저장 결과에 이미지 레이어가 포함된다.

### UI/UX 관점
- 레이어 사이드바와 속성 패널은 기존 설정 패널의 섹션 규칙(접기·펼치기, 한 줄 행)을 따른다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 이미지 레이어를 추가해 PNG/SVG를 올리면 리본 위에 고정으로 표시되고, 위치·크기·회전·불투명도·순서 변경이 즉시 반영된다.
- 스테이지 비율을 바꿔도 이미지의 상대 위치·크기가 유지된다.
- PNG 저장 결과에 이미지 레이어가 포함된다(저장 파일 픽셀 확인). **카리나 실렌더, 머지 뒤**(격리 워크트리에서는 확인 불가).
- `shader-lab` 파일 변경 없음. `npm run lint`·`npm test` 통과.

### 주요 의사결정 / 핵심 메모
- 유형 `admin`, 경로 ③ 표준, 채원① 없음(2156과 같은 근거). 규모 사전 판정: 티켓 표는 파일 4개였으나 2156 화면 파일과 번들 재생성까지 8~9개가 바뀔 것을 확인하고 카리나가 첫 호출부터 `planOnlyWaiver`를 부여했다(재시도에도 다시 부여).
- **1차 게이트 FAIL**(2026-09-25). 사유 ① 레이어를 배열 인덱스로 식별해, 선택한 레이어 옆 레이어를 이동하면 선택 인덱스에 다른 레이어가 들어가 속성 패널·슬라이더가 엉뚱한 레이어를 수정함(아현 가정 "id 없이 인덱스 식별"이 원인, 참고 대상 shader-lab은 id 추적). 이동·선택 테스트 없음. ② 이미지 로드 완료 전 저장하면 레이어가 조용히 빠지는 경합. 사용자가 재작업 방향 A(아현 재작업)를 승인해 `retryReason`·`retryBranch`로 같은 브랜치에서 이어 갔다. 민지의 범위 밖 발견물 2건(죽은 `order` 필드, 캐시 누수)은 같은 코드 구간이라 별도 티켓 없이 재작업에 포함했다.
- 재작업 결과 게이트 WARN. 사유 ① 픽셀 확인은 실렌더로만 가능(→ 위 실렌더로 통과, 완료 조건에 "카리나 실렌더, 머지 뒤" 표기 추가). ② 로드 경합 방지 로직(`pendingImageLoadCountRef`·`waitForImageAssets`·캐시 정리 이펙트)에 자동 테스트가 없다 — 민지가 코드 추적으로 문제는 못 찾았으나 회귀 방지 테스트가 없다는 점을 남겼다(잔여 이슈).
- 아현 가정(재작업): 선택 레이어 삭제 시 "선택 해제"를 택함. 로딩 안내 toast 문구는 기존 사례 톤을 차용. `[참고]` 캡처 전 대기 요구를 타이밍 의존 없이 만족시키기 위해 `imageAssets`를 React state에서 ref로 옮겼고, LayerSidebar 리스트 `key`도 `layer.id`로 바꿨다.
- 아현 가정(1차, 유지): `widthPct`·`heightPct`는 각각 짧은 변 대비 %로 독립 조절. 합성 순서는 fillBackground → drawRibbonLayer → 이미지 레이어 고정이라 이미지 레이어는 항상 리본 위에만 그려지고 "위/아래 이동"은 이미지 레이어끼리의 순서만 바꾼다(리본을 넘어가지 않음). 새 레이어 기본값 중앙(50,50)·짧은 변 30%·회전 0·불투명도 100. LayerSidebar는 shader-lab의 사용감만 참고해 아이콘 버튼으로 단순화.

### 잔여 이슈
- 로드 경합 방지 로직(뷰포트 `waitForImageAssets`·카운터·캐시 정리)에 자동 테스트가 없다(게이트 WARN 사유). 추가 조치를 원하면 P3 티켓으로 분리한다.
- 리본 레이어를 이미지 레이어 위로 올리는 순서 변경은 지원하지 않는다(합성 순서 고정). PRD §4.2 "위(또는 아래)" 표현과 어긋나면 프리셋(2159) 전에 정리한다.
