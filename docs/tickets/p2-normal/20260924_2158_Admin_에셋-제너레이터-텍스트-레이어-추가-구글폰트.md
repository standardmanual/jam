# [Admin] 에셋 제너레이터 텍스트 레이어 추가 (구글 폰트 선택 포함)

## 핵심 요약

- 요구사항: 글자를 리본 그래픽 위에 얹는 텍스트 레이어를 추가한다. 구글 폰트 선택은 `shader-lab`과 같은 방식. 글자 내용은 프리셋에
  저장하지 않고 화면 입력(수동) 또는 컨텐츠(자동)에서 채운다. PRD §4.3.
- 구현 계획: 2155 합성 훅에 텍스트 렌더러를 구현하고 2156 화면에 텍스트 레이어 속성 패널을 붙인다. 구글 폰트 목록·로드는
  `jam-web/src/lib/admin/shaderLab/googleFonts.ts`를 **읽어서 재사용**한다(수정 금지). 공용으로 옮길 필요가 있으면 새 파일로 복사하지
  말고 그대로 import 한다.
- 관련 파일: `jam-web/src/lib/asset-generator/render.ts`·`types.ts`, `jam-web/src/app/admin/asset-generator/TextLayerFields.tsx`(신규),
  참고 `jam-web/src/app/admin/shader-lab/ShaderLabTextFontField.tsx`·`useGoogleFontSlots.ts`, `jam-web/src/lib/admin/shaderLab/googleFonts.ts`

## 배경 / 문제 정의

배지 대표 이미지에 배지 이름을 얹어야 한다(사용자 결정 8·10). 텍스트 스타일은 프리셋에 담고 글자 내용만 매번 바뀌므로, 내용과
스타일을 분리한 레이어가 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 텍스트 레이어 속성: 글자 내용(프리셋 미저장), 글꼴(구글 폰트 + 시스템 기본), 크기(짧은 변 대비 %), 굵기, 자간, 행간, 정렬, 색,
  위치 x·y(%), 회전(°), 불투명도(%), 순서. 여러 줄 입력 허용.
- 서버(CLI) 렌더링에서도 같은 글꼴로 그려야 하므로, 글꼴 로드 방식은 브라우저(폰트 CSS)와 서버(폰트 파일 등록) 양쪽을 고려해
  인터페이스를 나눈다. 서버 쪽 실제 구현은 2201에서 하되, 이 티켓에서 글꼴 식별자(패밀리·굵기)를 프리셋 값으로 확정한다.
- PNG·영상 저장 결과에 텍스트가 포함된다. 글꼴 로드가 끝나기 전에는 저장을 막거나 기다린다.

### UI/UX 관점
- 글꼴 선택은 `shader-lab`과 같은 사용감(검색·최근 사용). 사용자 노출 문구는 UX 가이드라인 준수.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 텍스트 레이어를 추가해 글자를 입력하면 리본 위에 표시되고, 구글 폰트를 고르면 미리보기·저장 결과에 그 글꼴이 적용된다. **글꼴 실제 적용은 카리나 실렌더, 머지 뒤.**
- 스타일 속성 전부가 즉시 반영되고, 비율을 바꿔도 상대 위치·크기가 유지된다.
- 글꼴 로드 전 저장 시 깨진 글꼴로 저장되지 않는다. **카리나 실렌더, 머지 뒤.**
- `shader-lab` 파일과 `googleFonts.ts` 변경 없음. `npm run lint`·`npm test` 통과.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 텍스트 레이어(구글 폰트 포함)를 추가했다. 구현 커밋 e04c214f(아현) + fb9b9def(카리나 패치), staging 병합 159bec10.
  - 레이어 목록을 이미지·텍스트가 섞인 하나의 순서 있는 오버레이 목록(`overlayLayers`)으로 확장했다(리본은 목록 하단 고정). 프리셋(2159)의 `layers` 배열 구조와 맞췄고, 이동·삭제 헬퍼는 id 기반 제네릭으로 일반화했다.
  - 공용 모듈: `render.ts`에 `drawTextLayer`(위치·크기·회전·불투명도는 이미지 레이어와 같은 패턴, 자간은 `measureText` 기반 글자 단위 배치, 행간 배수, 정렬 3종, 여러 줄), `Canvas2DContextLike`에 font·fillText·measureText·textAlign·textBaseline 추가, `FontLoader` 인터페이스. `types.ts`의 `TextLayerConfig` 확정(`font: { family, weight }`, `content`는 프리셋 직렬화 제외 주석). 프로토타입 번들 재생성.
  - 어드민 화면: `TextLayerFields.tsx`(글자 내용·글꼴 검색·굵기·크기·자간·행간·정렬·색·위치·회전·불투명도), 사이드바에 텍스트 추가 버튼과 혼합 목록. 글꼴 검색·로드는 `googleFonts.ts`의 `searchGoogleFonts`·`ensureGoogleFontLoaded`·`waitForGoogleFontLoaded`를 수정 없이 재사용. 시스템 기본 글꼴 항목 포함.
  - 뷰포트가 `areFontsReady`·`waitForFonts`·`getMissingFontCount`를 노출하고, PNG·영상 다운로드는 폰트 로드를 기다린 뒤 캡처하며 실패 레이어는 toast로 안내한다.
  - **카리나 패치(fb9b9def)**: `loadFontInBrowser`가 `ensureGoogleFontLoaded`가 삽입한 `<link>`의 스타일시트 파싱(`sheet` 존재 또는 `load`/`error` 이벤트, 10초 안전 타임아웃)을 기다린 뒤 `fonts.load`·`check`를 실행하도록 `waitForGoogleFontStylesheet`를 추가했다. 오류 이벤트면 실패로 처리한다.
  - PRD §4.3 필드 표 확정, §15 갱신.

### 주요 의사결정 / 핵심 메모
- 유형 `admin`, 경로 ③ 표준, 채원① 없음. 규모 사전 판정: 티켓 표는 3개 파일이나 2157 결과와 번들 재생성까지 10개 안팎이 바뀔 것을 확인하고 첫 호출부터 `planOnlyWaiver`를 부여했다.
- 카리나 지시로 레이어 목록을 이미지·텍스트 통합 목록으로 확장했다(프리셋 2159가 `layers` 배열 하나를 저장하기 때문). 글꼴 식별자는 `{ family, weight }`로 확정해 서버 렌더링(2201)이 같은 식별자로 폰트 파일을 등록한다.
- 실렌더에서 발견한 결함은 원인이 로더 한 함수라 3.1절 "게이트만 재실행" 경로로 카리나가 임시 워크트리에서 14줄을 패치해 review 브랜치에 올리고(`tmp/…` 브랜치·워크트리는 제거) 민지에게 패치 범위만 재판정받았다. 머지는 `--no-ff`로 다시 했고 결함 재현·패치 후 확인을 실렌더 1·2차로 나눠 기록했다.
- 아현 가정: 자간·행간은 글자 크기 대비 배수, 텍스트 블록 위치는 블록 중심 기준, "최근 사용" 글꼴 기능은 참고 대상 shader-lab에도 없어 검색만 구현, 폰트 실패 감지는 `document.fonts.check` 기반.
- `[참고]`(아현·민지): 재사용한 `ensureGoogleFontLoaded`가 굵기 400 스타일시트만 요청해 굵기 700은 브라우저 합성 볼드로 그려진다 → 티켓 20260925_0148(P2).
- 실렌더 절차 메모: 가속 캔버스는 `getImageData` 직접 호출이 0을 돌려줄 수 있어 `createImageBitmap` 복사 뒤 `willReadFrequently` 컨텍스트에서 읽는다. `document.fonts.check`는 글자를 지정하지 않으면 미사용 서브셋 때문에 false가 나올 수 있으니 `fonts.load` 뒤에 판정한다.
