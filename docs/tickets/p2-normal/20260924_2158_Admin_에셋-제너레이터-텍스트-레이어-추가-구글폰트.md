# [Admin] 에셋 제너레이터 텍스트 레이어 추가 (구글 폰트 선택 포함)

## 핵심 요약

- 요구사항: 글자를 리본 그래픽 위에 얹는 텍스트 레이어를 추가한다. 구글 폰트 선택은 `shader-lab`과 같은 방식. 글자 내용은 프리셋에
  저장하지 않고 화면 입력(수동) 또는 컨텐츠(자동)에서 채운다. PRD §4.3.
- 구현 계획: 2155 합성 훅에 텍스트 렌더러를 구현하고 2156 화면에 텍스트 레이어 속성 패널을 붙인다. 구글 폰트 목록·로드는
  `jam-web/src/lib/admin/shaderLab/googleFonts.ts`를 **읽어서 재사용**한다(수정 금지). 공용으로 옮길 필요가 있으면 새 파일로 복사하지
  말고 그대로 import 한다.
- 관련 파일: `jam-web/src/lib/asset-generator/render.ts`·`types.ts`, `jam-web/src/app/admin/asset-generator/TextLayerFields.tsx`(신규),
  참고 `jam-web/src/app/admin/shader-lab/ShaderLabTextFontField.tsx`·`useGoogleFontSlots.ts`, `jam-web/src/lib/admin/shaderLab/googleFonts.ts`

## 배경 / 문제 정의

배지 대표 이미지에 배지 이름을 얹어야 한다(사용자 결정 8·10). 텍스트 스타일은 프리셋에 담고 글자 내용만 매번 바뀌므로, 내용과
스타일을 분리한 레이어가 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 텍스트 레이어 속성: 글자 내용(프리셋 미저장), 글꼴(구글 폰트 + 시스템 기본), 크기(짧은 변 대비 %), 굵기, 자간, 행간, 정렬, 색,
  위치 x·y(%), 회전(°), 불투명도(%), 순서. 여러 줄 입력 허용.
- 서버(CLI) 렌더링에서도 같은 글꼴로 그려야 하므로, 글꼴 로드 방식은 브라우저(폰트 CSS)와 서버(폰트 파일 등록) 양쪽을 고려해
  인터페이스를 나눈다. 서버 쪽 실제 구현은 2201에서 하되, 이 티켓에서 글꼴 식별자(패밀리·굵기)를 프리셋 값으로 확정한다.
- PNG·영상 저장 결과에 텍스트가 포함된다. 글꼴 로드가 끝나기 전에는 저장을 막거나 기다린다.

### UI/UX 관점
- 글꼴 선택은 `shader-lab`과 같은 사용감(검색·최근 사용). 사용자 노출 문구는 UX 가이드라인 준수.

## 구현 계획 (파일 단위)

| 파일 | 할 일 |
|---|---|
| `jam-web/src/lib/asset-generator/types.ts` | `TextLayer` 타입 확정(내용은 별도 필드로 분리) |
| `jam-web/src/lib/asset-generator/render.ts` | 텍스트 합성(글꼴·크기·자간·행간·정렬·색·위치·회전·불투명도) |
| `jam-web/src/app/admin/asset-generator/TextLayerFields.tsx` (신규) | 텍스트 레이어 속성·구글 폰트 선택(기존 모듈 재사용) |

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 텍스트 레이어를 추가해 글자를 입력하면 리본 위에 표시되고, 구글 폰트를 고르면 미리보기·저장 결과에 그 글꼴이 적용된다.
- 스타일 속성 전부가 즉시 반영되고, 비율을 바꿔도 상대 위치·크기가 유지된다.
- 글꼴 로드 전 저장 시 깨진 글꼴로 저장되지 않는다.
- `shader-lab` 파일과 `googleFonts.ts` 변경 없음. `npm run lint`·`npm test` 통과.
