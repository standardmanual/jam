# [Admin] 에셋 제너레이터 프리셋 저장·불러오기 (이미지 원본 저장소 업로드 포함)

## 핵심 요약

- 요구사항: 현재 레이어 구성(스테이지 비율, 이미지 레이어 목록, 텍스트 레이어 스타일, 순서)을 이름 붙여 프리셋으로 저장·불러오기·
  삭제한다. 이미지 원본은 저장소에 함께 올리고 프리셋이 경로를 가리킨다. 글자 내용·색·리본 랜덤값·시드는 저장하지 않는다. PRD §5·§12.
- 구현 계획: 프리셋 테이블 마이그레이션 **파일 작성**(실행은 승인 후 메인 세션), 어드민 API(목록·저장·삭제), 화면의 프리셋 패널.
  저장 구조는 `shader-lab`의 compositions API(`/api/admin/shader-lab/compositions`) 관례를 참고하되 별도 테이블·별도 라우트로 둔다.
- 관련 파일: `jam-web/supabase/migrations/<다음번호>_asset_presets.sql`(신규, 되돌림 SQL 포함), `jam-web/src/app/api/admin/asset-generator/presets/`
  (신규 route), `jam-web/src/app/admin/asset-generator/PresetPanel.tsx`(신규), `jam-web/src/types/database.generated.ts`(수동 추가),
  규칙 `.claude/skills/jam-work/references/db-migration-rules.md`

## 배경 / 문제 정의

자동 경로(윤진)는 어드민 화면 없이 프리셋만으로 렌더링해야 한다. 그러려면 프리셋이 이미지 원본까지 포함해 서버에서 읽을 수 있는
형태로 저장되어야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 테이블 `asset_presets`: `id uuid`, `name text`, `target_type text CHECK ('badge')`(후속 차수에서 값 추가), `stage_ratio text`,
  `layers jsonb`(이미지·텍스트 레이어와 순서. 이미지는 저장소 경로), `created_by uuid`, `created_at`, `updated_at`. RLS 활성화, 어드민만.
- 저장소 경로: `asset-generator/presets/{presetId}/{layerId}.{png|svg}`. 프리셋 삭제 시 파일도 정리한다.
- API: 목록·상세·저장(신규/덮어쓰기)·삭제. 어드민 권한 검사는 기존 어드민 API와 같은 방식(`getAdminUser`).
- 화면: 프리셋 패널(목록·이름 입력·저장·불러오기·삭제). 불러오면 레이어 구성이 복원되고 텍스트 글자 내용은 비어 있다.
- 되돌림 SQL 블록(테이블 drop)을 파일 끝에 둔다.

### UI/UX 관점
- 덮어쓰기·삭제는 확인 단계를 둔다. 문구는 UX 가이드라인 준수.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 프리셋 저장·불러오기·삭제(이미지 원본 저장소 업로드 포함)를 구현했다. 구현 커밋 067b9d75, staging 병합 391f5481.
  - `jam-web/supabase/migrations/185_asset_presets.sql`: `asset_presets` 테이블(id·name·target_type CHECK badge·stage_ratio CHECK 3값·layers jsonb·created_by uuid·created_at·updated_at), RLS 켜고 정책 없음(서비스 롤 전용), 재실행 가능, 파일 끝 되돌림 SQL. **2026-09-25 카리나가 Supabase MCP `apply_migration`으로 jam-prod에 적용**(이름 `185_asset_presets`). 검증: 제약 3개(pkey·target_type·stage_ratio), RLS true, 정책 0행, 컬럼 8개 확인.
  - API `/api/admin/asset-generator/presets`(GET 목록·POST 저장)와 `/[id]`(GET 상세·DELETE). 전부 `getAdminUser` 인증 뒤 `createServiceClient`. 저장은 멀티파트(`layers` JSON + 레이어별 `image_{id}` 파일, 파일당 5MB 상한은 기존 `MAX_APPLY_IMAGE_BYTES` 재사용)로 blob 이미지만 `images` 버킷 `asset-generator/presets/{presetId}/{layerId}.{png|svg}`에 올리고 공개 URL을 `assetUrl`에 넣는다. http(s) 이미지는 재업로드하지 않는다. id 있으면 update(덮어쓰기). 삭제는 저장소 list→remove 뒤 행 delete.
  - `presetSerialize.ts`(`serializePresetLayers`·`deserializePresetLayers` 순수 함수): 텍스트 `content` 비움, 이미지 `assetUrl` 저장소 경로 치환, 순서 유지. `AssetPreset.layers` 타입을 `OverlayLayerConfig[]`로 좁힘(리본은 프리셋에 없음).
  - 화면 `PresetPanel.tsx`: 이름·저장(신규 즉시, 덮어쓰기는 AlertDialog 확인)·목록·불러오기·삭제(AlertDialog 확인). 설정 패널 Accordion 최상단 "프리셋" 섹션. 불러오면 비율·오버레이 레이어를 통째로 교체하고 blob URL을 정리한다.
  - `database.generated.ts`에 `asset_presets` 타입 수동 추가. PRD §5(비저장 대상을 리본 레이어 전체로 명확화)·§12(확정 스키마)·§15 갱신. `docs/service/prd/02_DATA_MODEL.md` §12 표에 테이블 추가(카리나, 후속 범위).
