# [Infra] 배지 등록 묶음 포맷과 등록 스크립트 (컨펌 뒤 메인 세션이 실행)

## 핵심 요약

- 요구사항: 윤진이 준비하는 **등록 묶음** 파일 형식(배지 이름·설명·획득 조건 + 이미지 파일 경로 + 생성 시드 + 컬러·프리셋 정보)을
  정하고, 그 파일을 읽어 배지 데이터와 이미지를 함께 등록하는 스크립트를 만든다. 스크립트는 **작성만** 하고 이 티켓에서 실행하지 않는다.
  실행은 사용자 컨펌 뒤 메인 세션. PRD §8·§2-2.
- 구현 계획: 등록 시 이미지는 2200의 적용 경로와 같은 규칙(원본 PNG 보관 + WebP 축소본, `image_source = 'agent-generator'`)으로
  올린다. 등록 기록과 되돌림 SQL은 홈피드 카드 등록 선례(20260923_2252)의 형식을 따른다. 배지 데이터 컬럼은 어드민 배지 생성 폼
  (`jam-web/src/lib/admin/badge-sections.ts`)의 필드와 맞춘다.
- 관련 파일: 신규 `jam-web/scripts/asset-generator/register-badge.mjs`, 신규 `docs/specs/prd/asset-generator/REGISTRATION_BUNDLE.md`
  (묶음 형식 정본, type `prd`), 참고 `jam-web/scripts/recraft/register-badge-images.js`(Storage 업로드·`image_url` 갱신 관례),
  `jam-web/src/lib/admin/badge-sections.ts`(배지 필드), 2252 상위 티켓의 등록 기록 형식

## 배경 / 문제 정의

사용자 결정 3·6: 윤진의 기획안과 이미지를 함께 컨펌하면 배지 데이터와 이미지가 같이 등록되어야 하고, DB에 실제로 쓰는 주체는
메인 세션이어야 한다. 그러려면 "컨펌 대상 = 등록 입력"이 되는 묶음 형식과, 그 묶음을 그대로 등록하는 스크립트가 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 등록 묶음(JSON 또는 frontmatter 붙은 Markdown 한 벌 — 아현이 정하되 사람이 읽고 컨펌할 수 있어야 한다): 배지 필드(이름·설명·획득
  조건·계열·등급 등 배지 생성에 필요한 최소 항목), 이미지 파일 경로(2201 출력), 시드, 프리셋 ID, 배경색·끝색, 컬러 선택 근거(기획 문서
  링크), 작성자(윤진)·작성 시각.
- 스크립트: 묶음을 검증(필수 항목·이미지 존재·색 형식) → 배지 행 생성(또는 기존 배지 갱신은 1차 범위 밖) → 이미지 업로드(원본+WebP)
  → `image_url`·`image_source='agent-generator'` 갱신 → 등록 기록 파일과 되돌림 SQL 출력. `--dry-run`으로 검증만 할 수 있다.
- 실행 권한: 스크립트는 메인 세션이 실행한다는 전제로 서비스 키를 쓴다. 이 티켓의 게이트 판정은 `--dry-run`까지만 본다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 등록 묶음 형식 문서가 있고, 예시 묶음이 첨부되어 있다.
- 예시 묶음으로 `--dry-run`을 실행하면 검증 결과(통과/실패 사유)와 등록 예정 내용, 되돌림 SQL 미리보기가 출력되고 DB·저장소에는
  아무것도 쓰지 않는다.

  - **`register-badge.mjs`**(`npx tsx`, cwd는 `jam-web`): `--bundle [--dry-run] [--record-dir]`와 `--undo [--dry-run]`. 검증 → DB 읽기 검사(이름 중복·트라이브·컬렉션 존재, 키가 있을 때만) → WebP 변환 → 원본 PNG·WebP 업로드 → 배지 insert → 등록 기록. insert나 WebP 업로드가 실패하면 올라간 파일을 지운다. 같은 이름의 삭제되지 않은 배지는 중복으로 거절. `--undo`는 `user_activity_badges`·`inventory_items`·`poi_drops` 참조가 있거나 읽지 못하면 중단하고, 없을 때만 배지 행을 먼저 지운 뒤 파일 2개를 지운다.
  - 어드민 배지 생성 API의 검증 함수(`findRarityLevelError`·`isValidFamilyKey`·`findBadgeConditionSaveError`)를 재사용한다. 저장소 루트에서 실행하면 `@/` 별칭을 못 찾아 안내 문구를 내고, `cd jam-web`에서 실행하면 된다.
  - 등록 기록 `registration-record.json`(배지 id·저장소 경로·시드·프리셋·색·작성자·등록 시각 KST)과 `registration.sql`(등록과 동등한 INSERT + 파일 끝 `-- 되돌림 SQL`). 메인 세션이 SQL 기록을 `jam-web/supabase/migrations/seed_agent_badge_<슬러그>.sql`로 옮겨 커밋한다.
  - PRD §8·§14·§15, `docs/specs/INDEX.md` 갱신. 카리나가 머지 뒤 형식 정본에 새 거절 규칙과 실제 실행 확인을 반영했다.

### 주요 의사결정 / 핵심 메모
- 유형 `infra`(라이트 파이프라인), 경로 ③. 스키마 변경이 없고 스크립트 작성이 범위라 `db` 유형이 아니라 `infra`로 돌렸다(정지 조건 3번의 취지는 사용자가 실제 등록·되돌림 실렌더를 채팅에서 명시 승인해 충족). 규모 사전 판정: 티켓 표는 2개이나 10개 안팎 → 첫 호출부터 `planOnlyWaiver`.
- 묶음 형식은 JSON으로 정했다. 저장소에 YAML·frontmatter 파서 의존성이 없고 새 의존성을 넣지 않기 위해서다. 컨펌용 사람이 읽는 자료는 `--dry-run` 출력이 맡는다.
- **보안 결함 처리(사용자 선택 A, 머지 전 직접 패치)**: 게이트가 낸 SQL 주석 개행 주입을 카리나가 재현해 사실로 확인하고, 사용자에게 직접 패치(A)와 그대로 머지(B)를 물어 A로 답을 받아 처리했다. 등록 기록 SQL은 마이그레이션 폴더에 커밋되어 다시 실행될 수 있고 윤진은 웹 검색 도구를 쓰므로 외부 글이 이름에 섞일 여지가 있다는 점이 근거였다. 패치는 임시 워크트리(브랜치명 `claude/jamwork-*` 회피)에서 만들고 `gateOnly`로 민지가 패치 범위만 재판정했다.
