# [Infra] 채원(jam-designer)·윈터(jam-tribe) 에이전트 정의 갱신 — 컨텐츠 단위 컬러 방향 제시·검수 역할

## 핵심 요약

- 요구사항: 채원 정의에 "컨텐츠 단위로 배경색·그라데이션 끝색을 브랜드 일관성·대비(가독성) 기준으로 제시하거나 검수한다"를, 윈터
  정의의 기존 "트라이브별 소재·색·질감 가이드" 모드에 "배지·컨텐츠 컬러의 세계관 적합성 검수"를 추가한다. 컬러는 UI 디자인 토큰과
  별개이고, 결과는 윤진의 컨텐츠 기획 문서에 기록된다. PRD §6.
- 구현 계획: 두 정의 파일의 Modes 표에 항목 추가. 채원의 "읽고 판단만, 파일 수정 없음" 원칙과 윈터의 "제안만, 정본 직접 수정 없음"
  원칙은 그대로 둔다.
- 관련 파일: `.claude/agents/jam-designer.md`, `.claude/agents/jam-tribe.md`, `docs/agents/team-operations.md`(생성 구간이면 스크립트로)

## 배경 / 문제 정의

사용자 결정 5·9: 컬러는 별도 표가 아니라 컨텐츠마다 채원·윈터가 방향을 주고 윤진이 기획 문서에 기록한다. 두 에이전트 정의에 그
역할이 없으면 윤진이 물어볼 상대가 없다. 에이전트 정의 변경은 사용자 명시 승인 사항이다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 채원: 입력(컨텐츠 내용·성격·무드·이슈·트라이브) → 출력(배경색·끝색 후보 1~3쌍, 대비 확인 결과, 근거 한 줄). 브랜드 색 기준은 기획
  문서에 근거 링크로 남긴다.
- 윈터: 입력(같음) → 출력(트라이브·세계관 관점의 적합 여부와 이상 신호 — 참고/주의/중단, 확신도 높음/보통/낮음).
- 두 출력 모두 윤진이 기획 문서의 컬러 열에 그대로 옮긴다.

### 주요 의사결정 / 핵심 메모
- 컬러는 UI 디자인 토큰과 별개라고 채원 정의에 명시했다(토큰 표·새 토큰 제안 규칙 적용 없음). 브랜드 색 기준은 `jam-web/design-system/` 토큰에서 찾고 근거는 파일 경로로 남긴다. 기준이 없으면 추측하지 않는다.
- 채원은 브랜드 일관성·대비, 윈터는 트라이브·세계관 색의 의미로 판단을 나눴고 서로의 몫은 넘기도록 적었다.
- 두 에이전트의 도구(채원 Bash 있음, 윈터 없음)는 그대로라 `contract.json`은 바뀌지 않았다.
