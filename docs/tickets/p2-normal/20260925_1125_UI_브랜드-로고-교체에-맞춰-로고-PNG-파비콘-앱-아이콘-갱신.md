# [UI] 브랜드 로고 교체에 맞춰 적용 이미지(로고 PNG)와 파비콘·앱 아이콘을 새 로고로 바꾼다

## 핵심 요약

- 요구사항: 사용자가 2026-09-24 20:13에 `jam-doc/assets/brand/jam_logo.svg`를 새 글자 형태로 다시 그렸다(커밋 `7961a099`, 578×205,
  글자별 `j.svg`·`a.svg`·`m.svg` 추가, `logo_square.png` 갱신). 이 원본에서 만들어 앱에 적용한 이미지 4개와 디자인시스템 사본 3개는 아직
  옛 디자인이다. 전부 새 로고로 바꾼다. **파비콘(`favicon.ico`)과 앱 아이콘(`icon.png`·`apple-icon.png`)을 포함한다**(사용자 요청, 2026-09-25).
- 구현 계획: SVG에서 PNG·ICO를 다시 만드는 스크립트를 두고 아래 표의 7개 파일을 교체한다. 규격 검사 테스트를 추가한다. 고칠 내용이 확정돼
  있어 `/jam-work` 경로 ②(가벼운 UI)로 처리할 수 있다. 다만 아이콘 안 J의 크기는 눈으로 확인해야 한다(아래 「시안」).
- 관련 파일:
  - 원본: `jam-doc/assets/brand/jam_logo.svg`, `jam-doc/assets/brand/j.svg`
  - 앱 적용본: `jam-web/public/jam-logo-white.png`, `jam-web/src/app/icon.png`, `jam-web/src/app/apple-icon.png`, `jam-web/src/app/favicon.ico`
  - 디자인시스템 사본: `jam-web/design-system/assets/logo/jam-logo-white.png`, `jam-web/design-system/assets/logo/jam-logo-black.png`,
    `jam-web/design-system/uploads/jam_logo.png`
  - 로고 PNG 사용처: `jam-web/src/components/ui/TopNav.tsx:124`, `jam-web/src/app/(auth)/login/page.tsx:26`, `jam-web/src/app/(main)/voc/page.tsx:93`,
    `jam-web/src/app/(main)/badges/[id]/buildBadgeShareBlob.ts:153`

- 새 로고의 J는 굵고 왼쪽 위에 홈이 있는 형태다. 앱 아이콘 3개의 J는 이와 다른 옛 글자다. 이번에 `j.svg`(136×205, 흰색)가 추가됐다.
- 새 로고 비율은 578:205 = 2.82:1이다. 옛 SVG(3818×1353, 2.822:1)와 거의 같아서 `jam-logo-white.png`의 2610×925 규격은 유지된다.
  디자인시스템의 검정 로고와 업로드 사본만 옛 비율(2238×925)로 남아 있다.
- `login/page.tsx:26`과 `voc/page.tsx:93`은 이미지 크기를 `width={2238}`로 적고 있다(옛 비율 값). CSS는 `w-auto`라 화면에는 영향이 없다.
  같은 파일을 쓰는 화면이라 이번에 `2610`으로 함께 맞춘다(2줄).
- `buildBadgeShareBlob.ts:153`은 로고를 캔버스에 그려 배지 공유 이미지에 합성한다. 파일 규격이 그대로면 코드는 바꿀 것이 없다.
- 저장소에 웹 앱 매니페스트와 링크 미리보기(OG) 이미지 파일은 없다. 레이아웃은 `themeColor: "#000000"`만 갖고 있다.

### 시안 (임시 폴더에서만 만들었고 저장소 파일은 바꾸지 않았다)

- SVG → PNG는 `sharp`(0.35.4)가 렌더한다. `fill="black"`을 `fill="white"`로 바꿔 흰색 로고를 만든다. 2609×925가 나와 2610×925 캔버스에 가운데 맞춘다.
- ICO는 `sharp`가 만들 수 없다. Pillow로 16·32·48 내장 ICO를 만드는 것까지 확인했다.
- 옛 아이콘의 J는 캔버스 높이의 68.5%를 차지하고 정중앙(x·y 모두 50%)에 있다(512px 아이콘 실측). 새 J를 같은 높이 비율로 넣으면 폭이
  캔버스의 약 45%가 되고 원 안에서 모서리 여백이 약 9%다. 16px에서도 글자 형태가 읽힌다. 비교 이미지는 이 티켓을 만든 대화에서 사용자에게 전달했다.
- **J 크기(68.5%)는 시작값이다.** 새 J가 옛 J보다 훨씬 굵어 답답해 보이면 구현 뒤 눈으로 보고 줄인다.

### 서비스/코드베이스 관점

| 2 | `jam-web/src/app/icon.png` | 512×512 RGBA. 검정 원(지름 = 캔버스 폭, 모서리 투명) + 흰 J. J 높이 68.5%, 정중앙 |

- J는 새 `j.svg` 모양이다. 옛 J를 옮겨 그리지 않는다.
- 색은 원본 SVG 값을 그대로 쓴다(검정 `black`, J는 흰색). 임의로 회색 등을 섞지 않는다.
- 출력 크기는 기존 규격을 유지해 `TopNav.tsx`의 `width={2610} height={925}`가 그대로 유효하다.

재생성 스크립트:

- `jam-web/scripts/gen-brand-assets.mjs`를 만든다. `jam-doc/assets/brand/jam_logo.svg`와 `j.svg`에서 위 7개 파일을 생성한다.
- `--check` 옵션은 파일을 쓰지 않고 저장소 파일이 SVG와 맞는지(치수, 알파 마스크)만 검사한다. 다음에 로고가 바뀌면 이 스크립트를
  다시 돌리면 된다. 이번처럼 사람이 파일마다 손으로 만들지 않는다.
- ICO는 의존성을 추가하지 않는 방식으로 만든다(PNG 내장 ICO를 직접 조립하거나 기존에 있는 도구를 쓴다). 새 패키지를 넣기 전에 사용자 확인을 받는다.

코드 수정(2줄): `login/page.tsx:26`, `voc/page.tsx:93`의 `width={2238}`을 `width={2610}`으로.

### UI/UX 관점

- 브라우저 탭 아이콘(파비콘), iOS 홈 화면 아이콘(`apple-icon.png`), 상단 바·로그인·VOC 화면의 로고가 새 로고로 보인다.
- 배지 공유 이미지(`buildBadgeShareBlob.ts`)에 합성되는 로고가 새 로고다.
- 파비콘 캐시: 브라우저와 `_next/image`가 옛 이미지를 잡고 있을 수 있다. 배포 뒤 강력 새로고침으로 확인하고, 그래도 옛 것이 남으면 파일명에
  버전을 붙이는 방안을 그때 정한다.

### 범위 밖 (같이 처리하지 않는다)

- **이미 만든 배지 이미지에 합성된 옛 로고**: `jam-web/scripts/recraft/compose-logo.js`·`compose-logo-edge.py`가 배지 이미지 아래에 로고를 합성해
  저장한다. 이미 게시된 배지 이미지에는 옛 로고가 박혀 있다. 다시 합성할지는 규모(Supabase Storage 교체)가 커서 별도 결정이 필요하다.
  이 스크립트들은 로고 경로를 인자로 받고 기본 경로가 없어서, 앞으로 만드는 이미지에는 새 `jam-logo-white.png`를 넘기면 된다.
- 링크 미리보기(OG) 이미지·웹 앱 매니페스트 신설: 지금 없다. 필요하면 별도 티켓.
- claude.ai/design에 올린 디자인시스템 업로드본 갱신은 머지 뒤 `/jam-ds`로 한다(후속 범위).
- `jam-doc/assets/brand/logo_square.png`는 이미 새 로고다(커밋 `7961a099`에서 갱신됨).

## 구현 계획

1. `gen-brand-assets.mjs` 작성: `sharp`로 SVG를 렌더(로고는 높이 925 기준, 2610×925 캔버스 가운데 맞춤, J는 캔버스 높이의 68.5%),
   ICO 조립, `--check` 모드.
2. 스크립트로 1~7번 파일을 교체하고, 5·7번은 1·6번을 복사해 바이트가 같게 한다.
3. `login/page.tsx`, `voc/page.tsx`의 이미지 `width` 정정.
4. 규격 검사 테스트(vitest, `sharp`로 읽는다): 치수, 알파(2·4번의 원 모서리는 투명, 3번의 모서리는 불투명), ICO 내장 크기,
   1=5 · 6=7 바이트 동일.
5. `npm run ds:check`를 돌려 디자인시스템 검사가 통과하는지 본다(매니페스트에는 `guidelines/logo.html`만 등록돼 있어 PNG 교체는 영향이 없을 것으로 보지만
   실제로 확인한다).
6. 로컬 실렌더(패턴 13)로 상단 바·로그인·VOC 로고, 탭 아이콘, 배지 공유 이미지를 눈으로 확인한다.

그래서 티켓을 쪼개지 않고 아래 계획을 적은 채 `planOnlyWaiver`로 첫 호출부터 면제한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 위 표 1~7번 파일이 규격과 맞는다. 확인: 규격 검사 테스트 통과.
- 1번이 새 `jam_logo.svg`를 같은 크기로 렌더한 결과와 알파 마스크가 거의 같다(다른 픽셀이 전체의 1% 미만). 6번도 같은 기준이다.
- 2·3·4번의 J가 새 `j.svg` 모양이다. 확인: 같은 크기로 렌더한 새 J의 마스크와 비교해 다른 픽셀이 1% 미만이고, 옛 J 마스크와는 다르다.

- `login/page.tsx`, `voc/page.tsx`의 이미지 `width`가 2610이다.
- `node jam-web/scripts/gen-brand-assets.mjs --check`가 통과한다.
- `scripts/verify.sh`가 통과한다(`ds:check` 포함).

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 로컬 실렌더(패턴 13, 읽기 전용)로 로고가 보이는 화면과 탭 아이콘을 눈으로 확인하고, 아이콘 안 J 크기가 답답하면 조정한다.
