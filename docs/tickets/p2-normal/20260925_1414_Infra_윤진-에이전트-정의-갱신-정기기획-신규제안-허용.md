## 핵심 요약

- 요구사항: `.claude/agents/jam-marketer.md`의 "제안은 세션(`/jam-story`)에서만, 예약 실행에서는
  절대 하지 않는다"는 원칙(결정 4-9)에, 정기 산출물(주간 홈피드/월간 배지·미션)에서 신규 콘텐츠
  기획+이미지 준비는 예외로 허용하는 조건을 추가한다. 등록 실행 권한은 여전히 없다(Forbidden 유지).
  담당은 카리나·하니(에이전트 정의·문서체계), 사용자 명시 승인은 이 기획 승인 대화에서 이미
  받았다.
- 구현 계획: 정의 파일에 새 절(또는 기존 ⑧ 절 확장)을 추가해 — 정기 산출물에서 신규 배지·미션·
  홈피드 기획안(이름+설명+이미지+시드, 트렌드·지표 근거)을 준비하고 등록 묶음 파일로 저장할 수
  있음, 세계관과 닿는 기획안은 윈터 검수를 거치며 그 여부·사유를 등록 묶음에 남김, 등록 실행은
  절대 하지 않고 항상 메인 세션이 사용자 컨펌 후 처리함(변경 없음)을 명시한다.
- 관련 파일: `.claude/agents/jam-marketer.md`

## 배경 / 문제 정의

상위 티켓 결정 8: 사용자가 이 정의 변경을 명시 승인했다 — "윤진이 신규배지 제안, 신규 미션 제안,
주간 홈피드 컨텐츠 기획안을 트렌드와 지표를 반영해서 주간·월간으로 나에게 제시하고, 승인하면
어드민에 등록해서 유저에게 노출한다."

## 제안안 (카리나, 2026-09-25 — 사용자 승인 대기)

에이전트 정의 변경이라 실제 수정 전에 아래 안을 사용자에게 보이고 승인을 받는다. **승인 전에는 정의 파일을
고치지 않는다.**

### 확인한 사실 (2026-09-25 코드·문서를 읽고 확인한 결과)

- 현재 `jam-marketer.md`의 ⑧ 「배지 이미지·등록 묶음」은 「⑤의 배지 제안이 **승인된 뒤에만** 시작」하고 「세션에서만
  실행하고 예약 실행에서는 하지 않는다(결정 4-9와 같은 이유)」고 적혀 있다. 이 티켓이 바꾸려는 것이 바로 이 두 문장이다.
  상위 티켓 결정 6은 「정기 산출물에서 제안 → 컨펌 → 등록」에 이미지 준비까지 넣는다(이미지가 승인 **전에** 준비됨).
- **예약(클라우드) 실행에서는 이미지를 만들 수 없다.** `render.mjs`는 프리셋을 읽으려고 `SUPABASE_SERVICE_ROLE_KEY`를
  요구하고(`render.mjs` 21~22·90~98행), `fonts.mjs`는 실행 중에 구글 폰트를 내려받는다. 예약 환경에 등록된 비밀 값은
  `ADMIN_API_READ_TOKEN`·GA4·`SLACK_BOT_TOKEN`뿐이고(`scheduled-jobs.md` 4-1), 서비스 롤 키는 RLS를 우회하는 전체 DB 권한이라
  무인 실행에 두지 않는다(CLAUDE.md 규칙 6, 4-3의 무인 권한 표). 구글 폰트 접근과 `node_modules` 준비가 예약 환경에서
  되는지는 확인하지 않았다(월간 1회차에 `EGRESS_BLOCKED` 사례가 있다).
- 「예약 실행 금지」는 `jam-marketer.md`뿐 아니라 정본 `scheduled-jobs.md`에도 있다: 공통 원칙(29~33행, 「윤진의 기획·창작·시즌
  제안은 세션에서」와 단서 4-8), 무인 권한 금지 표(52행), 월간 목적(338행 「시즌 제안은 하지 않는다」). 정의만 고치면
  두 문서가 어긋난다.
- 에이전트 계약 검사(`contract.json`)와 자동 생성 문서(`gen-team-doc.mjs`)는 에이전트의 도구·모델만 보므로 문구 변경은
  검사에 걸리지 않는다. 도구 목록(`Read, Grep, Glob, WebSearch, WebFetch, Bash`)은 바꾸지 않는다.

### 결정이 필요한 것

1. **예약 실행에서의 범위**: 위 사실 때문에 「정기 산출물에서 기획+이미지 준비」를 예약 실행에 그대로 열 수 없다.
   - **A (카리나 추천)**: 정의는 결정 8대로 「정기 산출물에서 신규 배지·미션·홈피드 기획안을 낼 수 있다」로 갱신하되,
     **이미지·묶음·`--dry-run`은 서비스 키와 네트워크가 있는 세션 실행에서만** 한다. 예약 실행은 기획안까지 쓰고
     「이미지 준비 대기」를 표시한 뒤 멈춘다. 지금 되는 것만 사실대로 적는 안이다.
   - B: 예약 환경에서도 이미지가 만들어지게 먼저 환경을 고친다(`render.mjs`가 프리셋을 어드민 읽기 API로 받게 하고
     폰트 접근을 확인). 그 뒤에 정의를 갱신한다. 규모가 큰 별도 작업이다.
   - C: 서비스 롤 키를 예약 환경에 등록한다. **비추천**(전체 DB 권한을 무인 실행에 주게 된다).
2. **승인 전 이미지 준비**: 세션에서 사용자가 후보를 이미지로 비교하고 싶다고 **요청할 때만** 기획안 승인 전에 이미지를
   미리 만들 수 있게 한다(결정 6). 기본은 기존처럼 승인 뒤다. 카리나 추천: 허용.
3. **문서 범위**: 이번에는 `jam-marketer.md`와 `scheduled-jobs.md`(원칙·금지 표·월간 목적 문구)까지 고치고, **실제 클라우드
   루틴 프롬프트 교체는 이번 범위 밖**(외부 설정 변경이라 별도 승인·별도 티켓)으로 둔다. 카리나 추천.

### 주요 의사결정 / 핵심 메모
- 승인 전에 정의 파일을 고치지 않고 제안안을 먼저 티켓에 남겼다. 제안안을 만들면서 **예약(클라우드) 실행에서는 이미지를 만들
  수 없다**는 사실을 확인했다: `render.mjs`가 프리셋을 읽으려고 `SUPABASE_SERVICE_ROLE_KEY`를 요구하고(21~22·90~98행) 폰트를
  네트워크에서 받는데, 예약 환경의 비밀 값은 어드민 읽기 토큰·GA4·슬랙뿐이다(`scheduled-jobs.md` 4-1). 그래서 티켓 문구
  그대로(정기 산출물에서 기획+이미지 준비)가 아니라 A안으로 좁혔다. 서비스 롤 키를 예약 환경에 주는 안(C)은 전체 DB 권한을
  무인 실행에 주게 돼 채택하지 않았다.
- 예약 환경에서 이미지를 만들게 하는 안(B: 프리셋을 어드민 읽기 API로 받게 하고 폰트 접근 확인)은 별도 대규모 작업이라 이번에
  하지 않았다. 구글 폰트 접근과 `node_modules` 준비가 예약 환경에서 되는지는 확인하지 않았다(월간 1회차 `EGRESS_BLOCKED` 사례).

### 잔여 이슈
- [주의] **실제 클라우드 루틴 프롬프트는 아직 바뀌지 않았다.** 정의와 문서(4-12)는 기획안을 허용하지만 주간·월간 루틴이 그 기획안을
  쓰게 하려면 루틴 프롬프트를 교체해야 한다(외부 설정 변경이라 별도 승인·별도 티켓). 루틴 프롬프트를 다루는 기존 티켓
  `20260920_1933`·`20260922_0001`과 함께 정리하는 것을 제안한다.
- [참고] 예약 환경에서 이미지 준비를 가능하게 하는 B안은 필요해질 때 별도 티켓으로 다룬다.
