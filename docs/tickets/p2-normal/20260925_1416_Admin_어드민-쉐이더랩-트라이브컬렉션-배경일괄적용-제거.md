  제거한다. 함께 트라이브·컬렉션의 "배경 하위 일괄 적용" 기능(`apply_faction_background_cascade`·

## 배경 / 문제 정의

에셋 제너레이터를 점진적으로 발전시킬 예정이라, 배지·미션·컬렉션 대표 이미지에 쓰이던 별도
어드민 도구(쉐이더 랩)를 지금 정리한다. 트라이브·컬렉션 배경 일괄 적용 기능도 같은 정리 범위에
포함하기로 사용자가 확정했다.

### 규모 사전 판정과 실행 범위 (2026-09-26, 카리나)

- 변경 파일이 삭제를 포함해 수십 개(삭제 위주)이고 신규 마이그레이션 2개·`package.json`·문서 2개가 있어 100줄 기준을 넘긴다. 위 「구현 계획」의 여섯 단계가 이미 파일·디렉터리 단위로 적혀 있으므로 티켓을 쪼개지 않고 `planOnlyWaiver`로 첫 호출부터 면제한다.
- **DB는 SQL 파일 작성까지만 한다.** `apply_faction_background_cascade`·`count_faction_background_cascade` DROP과 `shader_lab_compositions` DROP은 마이그레이션 파일(되돌림 SQL 포함)을 `jam-web/supabase/migrations/`에 남기기만 하고 **실행하지 않는다**. Supabase는 staging·프로덕션 공용 단일 DB라 실행은 사용자 승인 뒤 카리나가 한다. 코드에서 이 함수·테이블을 부르는 곳이 모두 사라졌는지 마이그레이션 헤더 주석에 적는다.
- **패키지 제거는 링크를 걷은 뒤 한다.** 아현 첫 명령이 `node_modules`를 메인 폴더에 링크하므로(티켓 20260923_0100), `npm uninstall`을 실행하기 전에 `rm jam-web/node_modules && (cd jam-web && npm ci)`로 독립 설치한다(`jam-developer.md` 안내).
- `background_*`·`image_url` 데이터와 렌더링 경로(`badgeBackgroundTheme.ts`)는 건드리지 않는다. 실렌더 회귀 확인은 하지 않고(격리 워크트리에서 어드민 실렌더 불가) 단위 테스트·`npm run build`·CI로 검증하며, 실렌더는 카리나가 머지 뒤 가능한 범위에서 한다.
- 문서 정정(하위 6번)은 `docs/specs/prd/asset-generator/PRD.md` §2·§13과 `jam-doc/planning/business-plan/02 JAM! 서비스 플랜.md` §4.1.4①을 대상으로 한다.

### 주요 의사결정 / 핵심 메모
- **티켓의 DB 함수 이름이 틀렸다.** 티켓은 `apply_faction_background_cascade`·`count_faction_background_cascade`로 적었지만 마이그레이션 152가 옛 이름을 지우고 `apply_tribe_background_cascade(uuid)`·`count_tribe_background_cascade(uuid)`로 다시 만들었다. 191은 실제 이름 기준이고 되돌림 SQL에 152 본문과 109·182 권한 이력을 넣었다. 2026-09-26 읽기 전용 조회로 `tribe` 이름 함수 2개가 있고 `faction` 이름은 없음을 확인했다.
- **`textFontOptions.ts`는 이동하지 않고 삭제했다.** 티켓은 이동 대상으로 적었지만 사용처가 쉐이더 랩뿐이었다(`git grep`으로 삭제 뒤 참조 0건 확인). 에셋 제너레이터에는 영향이 없다.
- **재작업은 `gateOnly`가 아니라 아현 재호출로 했다.** 패치 파일 삭제는 단순하지만 `THIRD_PARTY_NOTICES.md`는 라이선스 고지라서 각 절의 코드가 남아 있는지 판단이 필요했다(파일 2개·10줄 이내 조건에 맞지 않음).
- **1차에서 아현이 "verify.sh 전 항목 통과"라고 보고했으나 실제 CI는 실패했다.** 아현의 워크트리는 기존 `node_modules`를 유지한 채 확인해 새 설치 경로를 검증하지 못한 것이 원인이다. `npm uninstall`이 있는 티켓은 완료 전에 `node_modules`를 지우고 `npm ci`를 다시 실행하도록 재작업 지시에 넣었고, 같은 유형이 반복되면 `jam-developer.md`에 규칙으로 올린다.
- **범위 밖 발견물(민지 [주의]·[구조]·[참고])** → P3 티켓 생성: 남은 죽은 의존성 `@paper-design/shaders`와 고지 절 정리, 삭제된 쉐이더 랩을 가리키는 낡은 주석·속성명 정리, 트라이브 폼의 배경 값이 어디에도 쓰이지 않게 된 문제와 서비스 플랜 문장 정정.

### 잔여 이슈
- **DB 삭제는 실행을 마쳤다(2026-09-26, 사용자 승인).** 다만 승인 시점에 프로덕션에는 옛 코드가 돌고 있었다(마이그레이션 머리말이 정한 순서는 "코드 배포 → DB 적용"이었다). 사용자가 이 순서 제약을 안내받은 뒤 승인했고, 영향은 어드민 전용이다: 프로덕션 `/admin/shader-lab`(저장·불러오기)과 트라이브 폼의 "일괄 적용" 버튼이 프로덕션 배포 전까지 오류를 낸다. 일반 사용자 화면에는 영향이 없다.
- **삭제 전 백업**: `192`가 지운 2행(개발 테스트 계정이 2026-09-17에 만든 "뉴클베-러닝"·"뉴클베-자전거")을 JSON으로 보관했다. 이미지 레이어는 브라우저 임시 주소(`blob:`)라 어차피 복원할 수 없는 상태였다. 보관 위치는 카리나 세션의 임시 폴더라 세션 종료 뒤에는 사라질 수 있다. 필요하면 요청해 저장소 밖으로 옮긴다.
- 기존 `background_*` 렌더링 전후 동일 실렌더 확인.
