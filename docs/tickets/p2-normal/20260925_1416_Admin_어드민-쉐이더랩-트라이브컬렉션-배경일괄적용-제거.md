## 핵심 요약

- 요구사항: 어드민 "쉐이더 랩"(`/admin/shader-lab`, `@basementstudio/shader-lab`)을 완전히
  제거한다. 함께 트라이브·컬렉션의 "배경 하위 일괄 적용" 기능(`apply_faction_background_cascade`·
  `count_faction_background_cascade` DB 함수, `TribeForm.tsx`/`ItemBookForm.tsx`의 "하위에 일괄
  적용" 버튼)도 제거한다. 죽은 패키지 `@paper-design/shaders-react`(src 임포트 0건)도 같이 정리한다.
  **에셋 제너레이터의 기능을 점진적으로 발전시킬 예정이라 이번엔 제거만 하고, 배경 저작 기능
  흡수는 후속 차수에서 다룬다(이번 범위 아님).**
- **사실 정정(중요)**: `/admin/shader-lab`은 배경(`background_*`)이 아니라 **배지·미션·컬렉션
  대표 이미지(`image_url`)에 정지 PNG를 적용하는 도구**다(`app/api/admin/shader-lab/apply/route.ts`
  확인, `image_url`만 갱신). 패턴/애니메이션/Paper 필터/PNG·MP4 굽기로 `background_*`를 채우던
  진짜 "배경 제너레이터"는 **별개 시스템**이었고 **2026-09-01 티켓 20260901_1929에서 이미
  제거됐다** — 서비스 플랜 §4.1.4①이 이 옛 상태를 아직 "🟢 프로덕션 배포 완료"로 서술하고 있어
  정정이 필요하다(하위 5번). **결론: shader-lab을 지워도 기존 `background_*` 데이터·렌더링에는
  아무 영향이 없다**(굽는 주체가 다른 시스템이었고 그 시스템은 이미 죽어 있었다).
- **트라이브·컬렉션 배경 일괄 적용도 shader-lab과 무관한 별개 컴포넌트**다
  (`BackgroundGeneratorPreview`, 배경색+블롭 애니메이션 전용). 사용자가 이 기능도 함께 제거하기로
  확정했다 — 단 `BackgroundGeneratorPreview` 자체(배경색·애니메이션 개별 저작)는 그대로 두고,
  "하위 일괄 적용"(캐스케이드 버튼+확인모달+DB 함수)만 좁게 도려낸다.
- 구현 계획: 하위 순서대로 진행 — ① 공용 구글폰트 코드 대피(에셋 제너레이터가 같은 경로를 써서
  먼저 옮겨야 함) → ② `/admin/shader-lab` 화면·API·나브 메뉴 삭제 → ③ 배경 일괄 적용 기능 삭제
  (버튼·확인모달·API 라우트, `BackgroundGeneratorPreview`는 유지) → ④ DB 정리(캐스케이드 DB 함수
  2개 + `shader_lab_compositions` 테이블 DROP, 되돌림 SQL 포함, 실행은 승인 후 메인 세션) →
  ⑤ 죽은 패키지 2종 제거 → ⑥ PRD·서비스 플랜 문서 정정.

## 배경 / 문제 정의

에셋 제너레이터를 점진적으로 발전시킬 예정이라, 배지·미션·컬렉션 대표 이미지에 쓰이던 별도
어드민 도구(쉐이더 랩)를 지금 정리한다. 트라이브·컬렉션 배경 일괄 적용 기능도 같은 정리 범위에
포함하기로 사용자가 확정했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `lib/admin/shaderLab/googleFonts.ts`·`textFontOptions.ts`·`googleFontsCatalog.json`을
  `shaderLab/` 밖(`lib/admin/googleFonts.ts` 등)으로 이동 — 에셋 제너레이터의
  `TextLayerFields.tsx`·`assetGeneratorHelpers.ts`·`render.ts`가 이 경로를 참조하므로 shader-lab
  삭제 전에 먼저 처리해야 에셋 제너레이터 텍스트 레이어가 깨지지 않는다.
- `app/admin/shader-lab/**` 전체, `lib/admin/shaderLab/` 잔여 파일(`composition.ts`·
  `effectRegistry.ts`·`layerFactory.ts`·`paramFields.ts`·`useShaderLabPlayback.ts`·`webgpu.ts`),
  `app/api/admin/shader-lab/**`(`apply`·`compositions`·`compositions/[id]`) 삭제.
  `adminNavItems.ts`의 "쉐이더 랩" 항목 제거 + `adminNavItems.test.ts` 갱신.
- `TribeForm.tsx`·`ItemBookForm.tsx`에서 `bulkApplyLoading`·`bulkApplyCount`·
  `showBulkApplyConfirm`·`bulkApplyResult`·`hasBackgroundValue` 상태, `handleBulkApplyClick`·
  `handleBulkApplyConfirm` 핸들러, "일괄 적용" 버튼·확인모달·결과배너 UI를 삭제. "배경 테마" 섹션
  안내 문구가 캐스케이드를 더 이상 언급하지 않도록 정정(UX Writing 가이드 준수).
- `app/api/admin/tribes/[id]/apply-background/route.ts`,
  `app/api/admin/itembooks/[id]/apply-background/route.ts` 삭제.
- DROP FUNCTION 마이그레이션(`apply_faction_background_cascade`·`count_faction_background_cascade`,
  되돌림 SQL에 권한 설정 이력 포함)과 `shader_lab_compositions` 테이블 DROP 마이그레이션을 별도
  파일로 작성(서로 무관한 변경이라 되돌림 단위 분리). 파일 작성까지, 실행은 승인 후 메인 세션.
- `package.json`에서 `@basementstudio/shader-lab`·`@paper-design/shaders-react` 제거.

### UI/UX 관점
- 어드민 나브 메뉴에서 "쉐이더 랩" 항목이 사라진다.
- 트라이브·컬렉션 폼에서 "하위에 일괄 적용" 버튼이 사라지지만, 배경색·블롭 애니메이션 개별 저작
  (`BackgroundGeneratorPreview`)은 그대로 동작한다.

### 컨텐츠 관점
- 해당 없음(유저 노출 화면 변화 없음).

## 구현 계획

위 「핵심 요약」·「상세 요구사항」의 순서(공용 코드 대피 → 화면·API 삭제 → 배경 일괄 적용 삭제 →
DB 정리 → 패키지 정리 → 문서 정정)를 그대로 따른다. `today_cards`·배지·트라이브 등 기존
`background_*`·`image_url` 데이터는 전혀 건드리지 않는다(렌더링 경로 `badgeBackgroundTheme.ts`
무변경).

## 완료 조건
- `/admin/shader-lab` 경로가 404를 반환하고 나브 메뉴에서 사라진다.
- 트라이브·컬렉션 폼에 "일괄 적용" 버튼이 없고, `BackgroundGeneratorPreview`(배경색·애니메이션
  개별 저작)는 그대로 동작한다.
- `apply_faction_background_cascade`·`count_faction_background_cascade`·
  `shader_lab_compositions`이 DB에서 제거된다(승인 후 메인 세션 실행, 되돌림 SQL로 재현 가능함을
  확인).
- `@basementstudio/shader-lab`·`@paper-design/shaders-react`가 `package.json`에서 사라지고
  `npm run build`가 통과한다.
- 기존 배지·트라이브·컬렉션의 `background_*` 값과 화면 렌더링이 이 작업 전후로 동일하다(회귀
  없음, 실렌더로 확인).
- 에셋 제너레이터의 텍스트 레이어(구글 폰트 검색)가 이 작업 뒤에도 정상 동작한다(공용 코드 대피
  회귀 없음).
- PRD `docs/specs/prd/asset-generator/PRD.md` §2·§13, 서비스 플랜 §4.1.4①이 실제 상태(배경
  제너레이터는 2026-09-01에 이미 제거, `/admin/shader-lab`은 무관한 별개 도구였으며 이번에 제거,
  트라이브·컬렉션 배경 캐스케이드도 제거)로 정정된다.
- `scripts/verify.sh` 통과.
