# [Infra] jam-work 규모 사전 판정이 plan_only 임계값을 과소 추정하는 사례 재발

## 핵심 요약

- 요구사항: 티켓 20260925_1405 처리 중 민지(게이트)가 [주의]로 지적한 사항 — 계획 반환 면제
  (`planOnlyWaiver`)가 없는 상태로 아현을 호출했는데, 실제 diff가 7개 파일·230줄로 `stop-conditions.md`의
  `plan_only` 임계값(파일 5개 초과 또는 100줄 이상)을 넘겼다. 실제 변경 내용은 티켓 관련 파일
  목록·테스트 보강 범위 안이라 스코프 크립은 아니었고 결과적으로 PASS했지만, 1단계 규모 사전
  판정이 이 티켓의 실제 규모를 과소 추정했다는 뜻이다.
- 요구사항: `/jam-work` SKILL.md 1단계 3번(규모 사전 판정) 절차나, 이런 유형(마이그레이션+타입+
  API+UI+테스트가 한 묶음으로 따라오는 "확장" 성격 티켓)의 파일 수 추정 방식을 점검해 재발을
  줄일지 검토한다.
- 관련 파일: `.claude/skills/jam-work/SKILL.md` 1단계 3번, `.claude/skills/jam-work/references/stop-conditions.md`,
  참고 사례: `docs/tickets/p2-normal/20260925_1405_Admin_에셋제너레이터-프리셋-대상유형-확장-target-type.md`

## 배경 / 문제 정의

카리나가 티켓 1405를 규모 사전 판정 없이(면제 부여 없이) Workflow에 넘겼는데, 실제로는 임계값을
넘는 규모였다. 이번엔 아현이 스코프 안에서 처리해 게이트가 PASS했지만, 임계값을 넘긴 상태에서
`plan_only`로 멈추지 않고 그대로 구현까지 진행된 것은 절차상 안전망을 우회한 결과다. 유사한
"확장" 성격 하위 티켓(20260925_1406~1416)이 이어지므로, 이 패턴이 반복되는지 관찰하고 필요하면
규모 사전 판정 기준을 조정한다.

## 완료 조건
- 유사 사례(에셋 제너레이터 2차 하위 티켓들)를 2~3건 더 관찰한 뒤, 규모 사전 판정 기준을 조정할
  필요가 있는지 판단해 기록한다.
- 조정이 필요하면 `SKILL.md` 1단계 3번 또는 `stop-conditions.md`에 반영한다.
- 조정이 불필요하면(우연한 1회성 과소 추정으로 판단되면) 그 판단 근거를 이 티켓에 남기고 닫는다.
