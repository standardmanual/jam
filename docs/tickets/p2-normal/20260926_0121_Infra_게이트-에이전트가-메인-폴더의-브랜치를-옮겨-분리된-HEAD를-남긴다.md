# [Infra] 게이트 에이전트가 메인 폴더에서 브랜치를 옮겨 분리된 HEAD를 남긴다

> 2026-09-26 묶음 D 진행 중 발견했다. 카리나가 메인 폴더에서 커밋하려다 `git status -sb`가 `HEAD (no branch)`인 것을 보고 알았다.

## 핵심 요약

- 요구사항: 게이트(민지) 실행이 메인 작업 폴더의 브랜치를 옮기지 못하게 한다. 기준 SHA를 재현해야 할 때는 별도 워크트리를 쓰게 한다.
- 구현 계획: 원인 확인(어느 에이전트·어느 명령) → 민지 정의(`.claude/agents/jam-reviewer.md`)와 `jam-work.js`의 게이트 프롬프트에 「메인 폴더에서 `git checkout`·`git switch` 금지, 재현은 `git worktree add`」를 명시 → 가능하면 훅으로 기계 방어.
- 관련 파일: `.claude/agents/jam-reviewer.md`, `.claude/workflows/jam-work.js`(게이트 프롬프트), `.githooks/`(기계 방어 후보), `docs/agents/team-operations.md`.

## 배경 / 문제 정의

### 사실 (2026-09-26 `git reflog`로 확인한 결과)

- 메인 폴더 reflog에 카리나 커밋(`a023a714`) 뒤로 다음 이동이 남아 있다: `checkout: moving from staging to 4c7a8750`, 이어서 `moving from 4c7a8750 to a023a714`. `4c7a8750`은 묶음 D 리뷰 브랜치의 커밋이고 `a023a714`는 그 브랜치의 기준 커밋(`staging`)이다. 게이트가 D의 CI 실패 원인을 베이스에서 재현하려고 한 것으로 보이며(민지 보고: 「베이스 a023a714에서 `--check`를 직접 돌렸다」), **어느 명령을 누가 실행했는지는 확인하지 못했다**.
- 그 결과 메인 폴더가 `staging`이 아닌 분리된 HEAD(`a023a714`)에 남았다. 카리나는 이를 모르고 그 위에 커밋(`95f8708c`)했고 `git push origin staging`은 「Everything up-to-date」로 아무것도 올리지 않았다. 부모가 같아 `git checkout staging && git merge --ff-only 95f8708c`로 복구했다(잃은 커밋 없음).
- 카리나 운영 규칙에는 이미 「메인 트리에서 브랜치를 전환하지 않는다(병렬 세션 공유)」가 있다(`SKILL.md` 3.1절). 이 규칙은 카리나 절차에 적혀 있고 서브에이전트 정의에 같은 금지가 있는지는 확인하지 않았다.

### 왜 문제인가 (판단)

메인 폴더는 카리나와 병렬 세션이 공유한다. 분리된 HEAD에서 커밋하면 브랜치에 남지 않아 유실되거나 push가 조용히 no-op이 된다. 이번에는 부모가 같아 복구됐지만 그렇지 않은 경우 커밋을 잃을 수 있다.

## 결정 필요

- **A. 문서·프롬프트에 금지를 명시한다**(민지 정의와 게이트 프롬프트). 비용이 작다. 카리나 추천의 첫 단계다(판단).
- **B. 훅으로 기계 방어한다**(예: 메인 폴더에서 분리된 HEAD 상태를 pre-commit·pre-push가 감지해 차단). 에이전트 지시에 의존하지 않는다. A와 함께 하는 것을 추천한다.

## 완료 조건

- 게이트 프롬프트와 민지 정의에 메인 폴더 브랜치 전환 금지와 대안(`git worktree add`)이 적혀 있다.
- (B를 정하면) 메인 폴더가 분리된 HEAD일 때 커밋 또는 push가 막히고 복구 안내가 나온다(로컬 재현으로 확인).
- 실제로 어느 에이전트가 이동시켰는지 원인이 확인되어 기록되어 있다(다음 게이트 실행 기록 확인 등).
- `scripts/verify.sh` 통과.
