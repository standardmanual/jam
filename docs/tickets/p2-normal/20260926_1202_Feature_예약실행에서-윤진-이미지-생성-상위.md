# [Feature] 예약(클라우드) 실행에서 윤진이 홈피드 후보 이미지를 만든다 (상위)

> 하위 티켓: 20260926_1203(API) · 1204(render 프리셋 조회) · 1205(예약 환경 준비) · 1206(저장·노출·게시) · 1207(정의·문서·루틴 프롬프트) · 1208(텍스트 레이어 2개 채우기) · 1209(list-presets 스크립트·PRD 실행환경, 1204에서 분리)
> 선행: 티켓 20260925_1404(에셋 제너레이터 2차, 윤진 신규 기획), 20260925_1414(정의 갱신, A안). 이 티켓은 1414의 A안(예약 실행은 이미지를 만들지 않고 「이미지 준비 대기」만 표시)을 B안으로 바꾼다.

## 핵심 요약

- 요구사항: 주간 예약 실행이 홈피드 후보 중 **이미지가 필요한 신규 카드**의 이미지를 에셋 제너레이터(`render.mjs`)로 만들어 리포트에 함께 싣고, 사용자가 리포트에서 이미지를 보고 컨펌한다. 서비스 롤 키는 예약 환경에 두지 않는다.
- 구현 계획: 프리셋 조회를 서비스 롤 키 직접 조회에서 어드민 읽기 API(`x-admin-read-token`)로 바꾸고(1203·1204), 홈피드 프리셋의 텍스트 레이어 2개에 제목·요약을 각각 채우게 하고(1208), 예약 환경에서 글꼴·모듈이 동작하게 준비하고(1205), 이미지를 저장소에 커밋해 리포트에 인라인으로 표시하고(1206), 정의·문서·루틴 프롬프트를 갱신한다(1207).
- 관련 파일: `jam-web/scripts/asset-generator/render.mjs`(프리셋 조회 74~98행, 텍스트 채우기 99~102행), `jam-web/src/app/api/admin/asset-generator/presets/route.ts`(GET 41행)·`presets/[id]/route.ts`(GET 9행), `.claude/agents/jam-marketer.md`(⑧), `.claude/skills/jam-work/references/scheduled-jobs.md`(4-1·4-12·주간 절)

## 배경 / 문제 정의

2026-09-26 주간 리포트 테스트(W39)에 홈피드 이미지·컨펌 요청이 없었다. 원인은 둘이다.

1. 클라우드 루틴의 저장 프롬프트가 1414 이전 그대로라 「이미지 준비 대기」 표시조차 쓰지 않았다(1414가 프롬프트 교체를 범위 밖으로 남겼다).
2. 예약 환경에서는 이미지를 만들 수 없다. `render.mjs`가 프리셋을 읽으려고 `SUPABASE_SERVICE_ROLE_KEY`를 요구하는데(RLS를 우회하는 전체 DB 권한이라 무인 실행에 두지 않는다, `scheduled-jobs.md` 4-1), 글꼴은 실행 중 구글에서 내려받으며(`fonts.mjs`), 예약 환경 네트워크는 허용 목록 방식이다.

사용자 결정(2026-09-26): A안(세션에서만 이미지)이 아니라 **B안(예약 환경에서도 이미지 생성)** 을 택했다.

## 결정 사항 (2026-09-26, 사용자)

- 이미지 범위: **이미지가 필요한 신규 카드만**. 전원용 바로가기 카드처럼 이미지가 없는 카드는 제외한다.
- 컬러 방향(배경색·끝색): **루틴 본체가 채원(색 후보·대비)과 윈터(세계관 적합)를 호출**하고, 그 결과로 윤진이 렌더한다. 윤진은 색을 정하지 않는다(`jam-marketer.md` ⑧ 1단계 원칙 유지).
- 프리셋: 에셋 제너레이터의 **`홈피드` 프리셋**(id `51aa4673-f723-4929-ac20-a302202b7aa7`, target_type `home_feed`, 비율 1:1, 2026-09-26 DB 조회로 확인)을 쓴다. 텍스트 레이어는 2개다: **`피드 제목`** 레이어(큰 글씨, 세로 31%, 크기 10%)에 카드 제목을, **`간단한 설명`** 레이어(작은 글씨, 세로 41%, 크기 5%)에 짧은 요약을 넣는다. 프리셋 JSON에는 레이어 이름 필드가 없으므로 배열 순서(첫 번째 = 제목, 두 번째 = 설명)로 구분한다(하위 티켓 1208).
- 프리셋 조회: 이미 예약 환경에 있는 `ADMIN_API_READ_TOKEN`을 재사용한다. **새 비밀 값과 서비스 롤 키는 등록하지 않는다.**

## 상세 요구사항

### 서비스/코드베이스 관점
- 프리셋 목록·단건 GET만 읽기 토큰을 허용한다(POST·DELETE는 세션 인증 그대로, `requireAdminRead`는 GET 전용).
- `render.mjs`는 예약 환경에서 `process.env`(`ADMIN_API_BASE_URL`·`ADMIN_API_READ_TOKEN`)로 동작한다. 지금의 `loadEnv()`는 `.env.local`만 읽으므로 `process.env`도 읽어야 한다.
- 예약 실행에서 하지 않는 일은 그대로다: 등록(`register-*.mjs`를 `--dry-run` 없이 실행, `--undo`), DB·스토리지 쓰기, 프리셋 생성·수정.

### 컨텐츠 관점
- 세계관과 닿는 카드는 윈터 검수를 거친다(1414의 `world_review` 규칙 유지).
- 이미지를 만들 수 없으면(글꼴·네트워크 실패 등) 임의 색이나 자리표시 이미지로 채우지 않고 「이미지 준비 대기(사유)」로 표시한다.

## 완료 조건

- 예약(클라우드) 환경에서 수동 실행한 주간 루틴이 이미지가 필요한 신규 카드마다 PNG를 만들고, 리포트 「홈피드 초안」 절에서 그 이미지가 보인다(상대 경로 인라인). 이미지에는 카드 제목(`피드 제목` 레이어)과 짧은 요약(`간단한 설명` 레이어)이 각각 들어 있다.

- 예약 실행이 등록·DB 쓰기를 하지 않는다(리포트와 이미지 묶음 커밋 외의 변경 없음).
- 하위 티켓 1203~1209가 모두 CLOSED다.
