# [API] 에셋 제너레이터 프리셋 조회 GET 두 개에 어드민 읽기 토큰을 허용한다

> 상위 티켓 [20260926_1202](20260926_1202_Feature_예약실행에서-윤진-이미지-생성-상위.md)

## 핵심 요약

- 요구사항: 예약 환경(서비스 롤 키 없음)이 프리셋을 읽을 수 있게, 프리셋 목록·단건 조회 GET을 `x-admin-read-token` 헤더로도 호출할 수 있게 한다.
- 구현 계획: 두 라우트의 GET에서 `getAdminUser()` 직접 검사를 `requireAdminRead(req)`로 바꾼다. POST·DELETE는 그대로 세션 인증만 받는다.
- 관련 파일: `jam-web/src/app/api/admin/asset-generator/presets/route.ts`(GET 41행, `getAdminUser` import), `jam-web/src/app/api/admin/asset-generator/presets/[id]/route.ts`(GET 9행), `jam-web/src/lib/admin/auth.ts`(`requireAdminRead` 96행 참고), 테스트 `presets/__tests__/route.test.ts`·`presets/[id]/__tests__/route.test.ts`, 전례 `jam-web/src/app/api/admin/content-corpus/route.ts`

## 배경 / 문제 정의

두 GET이 `getAdminUser()`만 써서 세션 쿠키가 없는 예약 실행은 403을 받는다. 같은 데이터를 읽는 다른 어드민 GET(`content-corpus`, `today/metrics`)은 이미 `requireAdminRead`를 쓴다. 단건 응답에는 `layers`(이미지 레이어의 스토리지 주소 포함)가 들어가지만 어드민 화면과 같은 공개 스토리지 주소이며 개인정보는 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 목록 GET(`?targetType=` 필터 포함)과 단건 GET만 `requireAdminRead(req)`로 바꾼다. 응답 본문은 바꾸지 않는다.
- 단건 GET 시그니처가 `_req`를 무시하고 있으므로 `req`를 사용하도록 이름을 바꾼다.
- 목록의 `targetType` 검증(400)은 그대로 유지한다.
- PRD(`docs/specs/prd/asset-generator/PRD.md`)에 「읽기 토큰으로 조회 가능한 API」 사실을 한 줄 추가한다.

## 구현 계획

1. 두 라우트 GET 수정.
2. 테스트: (a) 유효한 읽기 토큰 + GET → 200, (b) 잘못된 토큰·토큰 없음·세션 없음 → 기존과 같은 거절, (c) 토큰이 있어도 POST·DELETE는 통과하지 못한다(회귀), (d) 목록 `targetType=home_feed` 필터가 토큰 경로에서도 동작한다. 테스트 파일에 `admin-read-token.test.ts`·`content-corpus/__tests__/route.test.ts`의 인증 목킹 방식을 따른다.

## 완료 조건

- 유효한 `x-admin-read-token`으로 `GET /api/admin/asset-generator/presets?targetType=home_feed`가 200과 `{ presets }`를 돌려주고, `GET /api/admin/asset-generator/presets/<id>`가 200과 `{ preset }`을 돌려준다(자동 테스트).
- 토큰·세션이 없거나 틀리면 거절된다. POST·DELETE는 토큰만으로 통과하지 못한다(자동 테스트).
- `scripts/verify.sh`가 통과한다.

### 구현 내용 요약
- 프리셋 목록 GET(`presets/route.ts`)과 단건 GET(`presets/[id]/route.ts`)의 `getAdminUser()` 직접 검사를 `requireAdminRead(req)`로 교체했다. 단건 GET의 `_req`는 `req`로 바꿨다. POST·DELETE는 세션 인증 그대로다. 목록의 `targetType` 400 검증과 응답 본문은 그대로다.
