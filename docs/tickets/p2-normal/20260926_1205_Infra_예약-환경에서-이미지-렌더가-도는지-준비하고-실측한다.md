# [Infra] 예약(클라우드) 환경에서 이미지 렌더가 도는지 준비하고 실측한다

> 상위 티켓 [20260926_1202](20260926_1202_Feature_예약실행에서-윤진-이미지-생성-상위.md). 선행: 1203·1204·1208이 staging에 반영된 뒤 시험 실행한다. 환경 설정은 사용자 조치가 필요하다.

## 핵심 요약

- 요구사항: 클라우드 환경 `jam-ops`(`env_01MKAxUHmjTbwAKrrUEb2zMe`)에서 `npm ci`(jam-web) → `render.mjs` 실행이 성공하는지 확인하고, 막히는 곳(네트워크 허용 목록·설치 시간)을 찾아 해소한다.
- 구현 계획: (사용자) 허용 목록·환경변수 추가 → (카리나) 최소 프롬프트로 루틴을 수동 1회 실행해 PNG 생성 여부·소요 시간 실측 → 결과를 이 티켓과 `scheduled-jobs.md` 4-1에 기록. 코드 변경은 없다(막히는 곳이 코드 문제면 별도 티켓).
- 관련 파일: `.claude/skills/jam-work/references/scheduled-jobs.md`(환경 설명 5~20행, 4-1), `jam-web/scripts/asset-generator/fonts.mjs`(`fonts.googleapis.com`·`fonts.gstatic.com`), `jam-web/scripts/asset-generator/serverCanvas.ts`(이미지 레이어 URL 로드), `docs/agents/contract.json`(환경 주장 검사 줄)

## 배경 / 문제 정의

예약 환경 네트워크는 허용 목록 방식이다(현재 `j-a-m.app`·`stage.j-a-m.app`·트렌드 수집 사이트·`slack.com` + 기본 목록). 이미지 렌더가 부르는 외부 주소는 다음이고, 허용 여부는 아직 확인하지 않았다.

| 호출 | 주소 | 필요한 경우 |
|---|---|---|
| 구글 폰트 CSS·TTF | `fonts.googleapis.com`·`fonts.gstatic.com` | 텍스트 레이어가 구글 폰트(홈피드 프리셋은 Noto Sans KR 600)를 쓸 때 항상 |
| 이미지 레이어 원본 | `ceehnkzdbecxwzxrhhns.supabase.co`(스토리지 공개 주소) | 프리셋에 이미지 레이어가 있을 때만(홈피드 프리셋은 텍스트 2개뿐이라 해당 없음, 다른 프리셋 확인 필요) |
| 프리셋 조회 | `stage.j-a-m.app`(프로덕션 반영 뒤 `j-a-m.app`) | 항상(이미 허용됨) |
| 패키지 설치 | npm 레지스트리 | `npm ci`가 `@napi-rs/canvas` 등 네이티브 바이너리를 받을 때 |

월간 트렌드 수집 1회차에 `EGRESS_BLOCKED`가 난 전례가 있어 허용 여부를 시험 실행으로 확인한다.

## 상세 요구사항

### 사용자 조치 (claude.ai 루틴 환경 설정, 카리나는 대신 못 함)
- 허용 목록에 `fonts.googleapis.com`·`fonts.gstatic.com` 추가.
- 환경변수 `ADMIN_API_BASE_URL`(`https://stage.j-a-m.app`) 추가. `ADMIN_API_READ_TOKEN`은 이미 있다. **`SUPABASE_SERVICE_ROLE_KEY`는 추가하지 않는다.**
- (필요 시) 시험 실행에서 npm 레지스트리가 막히면 그 주소도 추가.

### 시험 실행 (카리나)
- 시험 전용 루틴 또는 기존 주간 루틴의 수동 실행에 아래만 시키는 최소 프롬프트를 쓴다: `cd jam-web && npm ci` → `npx tsx scripts/asset-generator/list-presets.mjs --target-type home_feed` → `render.mjs`로 `홈피드` 프리셋 렌더(제목·설명 예시 문구, 색 임의, 결과는 커밋하지 않고 파일 크기·소요 시간만 보고).
- 기록할 것: `npm ci` 소요 시간, `render.mjs` 소요 시간, 실패한 단계와 원인(허용 목록·설치·글꼴 등), PNG 파일 크기, 서비스 롤 키 없이 성공했는지.
- 기존 주간 루틴 자체의 시간·토큰 상한(15만 토큰)에 이미지 단계가 얹히면 초과할 수 있으므로 소요 시간을 상한 재산정 근거로 남긴다.

## 구현 계획

1. 사용자가 위 조치를 한 뒤 알려 준다(티켓 상태 WAITING).
2. 시험 실행 → 결과 기록.
3. 막힌 곳이 있으면 원인별로 처리: 허용 목록 → 사용자 조치 추가, 설치 시간 과다 → 필요한 패키지만 설치하는 방법 검토(별도 티켓), 글꼴 다운로드 불안정 → 글꼴 파일 사전 캐시 방안 검토(별도 티켓).
4. `scheduled-jobs.md` 4-1에 이미지 렌더 준비 사실(허용 목록 추가분·환경변수·실측 시간)을 적고, 새 환경 사실은 `docs/agents/contract.json`에 검사 줄을 추가한다(CLAUDE.md 규칙 5).

## 완료 조건

- 예약 환경에서 서비스 롤 키 없이 `홈피드` 프리셋 렌더가 성공하고 PNG가 만들어진다(시험 실행 기록에 성공 출력과 소요 시간).
- 막힌 단계가 있었다면 원인과 해소 방법이 완료 기록에 있다.
- `scheduled-jobs.md` 4-1이 허용 목록·환경변수의 실제 상태와 일치하고 `scripts/check-contract.mjs`가 통과한다.
