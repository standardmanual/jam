# [Infra] 예약 실행이 만든 이미지를 저장소에 커밋하고 리포트에 인라인으로 보여 준다

> 상위 티켓 [20260926_1202](20260926_1202_Feature_예약실행에서-윤진-이미지-생성-상위.md). 선행: 20260926_1205(시험 실행에서 PNG 크기를 실측한 뒤 상한을 정한다).

## 핵심 요약

- 요구사항: 사용자가 「홈피드 초안」 절에서 후보 이미지를 눈으로 보고 컨펌할 수 있어야 한다. 이미지는 저장소에 커밋되고, 리포트 표에 상대 경로 인라인 이미지로 표시된다.
- 구현 계획: 묶음 폴더 `jam-doc/assets/home-feed-bundles/<묶음 ID>/`에 `image.png`와 `bundle.json`(`--dry-run` 검증을 통과한 것)을 커밋하고, 리포트 표의 해당 후보 칸에 `![](../../../assets/home-feed-bundles/<묶음 ID>/image.png)`와 컬러(배경·끝색·근거)를 함께 적는다. 슬랙 안내 글에 「이미지 N장 포함」과 리포트 링크를 넣는다.
- 관련 파일: `.claude/agents/jam-marketer.md`(⑧ 4단계 묶음 폴더 표), `.claude/skills/jam-work/references/scheduled-jobs.md`(주간 절 절차 ④·⑤), `docs/specs/prd/content-automation/PRD.md`(§8 편성표·§8-1 슬랙 안내 형식), `.githooks/pre-commit`(자산·문서 검사: `jam-doc/assets/`는 문서 검색 대상이 아님), `scripts/slack-post.mjs`

## 배경 / 문제 정의

예약 실행은 리포트만 커밋한다. 이미지를 사용자가 확인할 저장 위치와 표시 방식이 없다. 리포트는 저장소 마크다운이라(옵시디언 볼트가 저장소 루트, GitHub에서도 열림) 상대 경로 이미지가 어느 쪽에서든 보인다. 다만 리포트 위치(`jam-doc/operations/reports/weekly/`)에서 자산 폴더까지의 상대 경로는 `../../../assets/...`이다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 이미지 파일은 묶음 폴더 안에 두고, 리포트에는 파일을 복사하지 않고 경로만 참조한다(같은 이미지를 두 곳에 두지 않는다).
- 용량: PNG 한 장 크기를 1205 시험 실행에서 실측한다. 주 7장 수준이면 연 수백 MB가 쌓일 수 있으므로, 상한(예: 장당 몇 MB)과 초과 시 처리(리포트용 축소 미리보기 WebP를 따로 커밋하고 원본은 묶음에만 두는 방식 등)를 실측 뒤 정한다. `.gitignore`에는 새 항목을 추가하지 않는다(CLAUDE.md 규칙 4).
- 리포트 표에는 후보마다 이미지 유무를 명시한다: 이미지가 필요 없는 카드는 「이미지 없음(사유)」, 만들 수 없었던 카드는 「이미지 준비 대기(사유)」.
- 「최종 선택」·「승인」 칸을 채우는 방식은 그대로다(사람이 이미지를 보고 후보를 고른다). 승인된 카드의 묶음 폴더는 그대로 등록 절차(메인 세션, `register-home-feed-card.mjs`)의 입력이 된다.
- 슬랙 안내 글(PRD §8-1)에 「이미지 N장 포함」 한 줄을 추가한다. 슬랙에 이미지 파일을 올리는 일은 이번 범위 밖(리포트 링크로 확인).

## 구현 계획

1. 1205 시험 결과로 이미지 용량 상한 결정.
2. `jam-marketer.md` ⑧·`scheduled-jobs.md` 주간 절·`content-automation/PRD.md` §8·§8-1에 저장 위치·표시 형식·슬랙 문구 반영(정의·문서 갱신은 1207과 한 번에 진행해도 된다).
3. 가짜 리포트 한 편(테스트 카드 1장, 커밋하지 않은 임시 파일)으로 옵시디언·GitHub 미리보기에서 이미지가 보이는지 확인.
