# [Infra] 윤진 정의·예약 실행 문서를 이미지 생성 흐름으로 갱신하고 루틴 저장 프롬프트를 교체한다

> 상위 티켓 [20260926_1202](20260926_1202_Feature_예약실행에서-윤진-이미지-생성-상위.md). 선행: 1204·1208(render 동작)·1205(예약 환경 실측 성공)·1206(저장·노출 형식). 루틴 프롬프트 교체는 **외부 설정 변경이라 교체 직전에 사용자 승인**을 받는다.

## 핵심 요약

- 요구사항: 1414의 「예약 실행은 이미지를 만들지 않는다(A안)」 규정을 「예약 실행에서도 조건을 갖춰 이미지를 만든다(B안)」로 바꾸고, 클라우드 루틴 저장 프롬프트를 새 흐름으로 교체한다.
- 구현 계획: `jam-marketer.md` ⑧·Forbidden, `scheduled-jobs.md` 단서 4-12·4-1·주간 절, asset-generator PRD를 고친 뒤(아현·민지 게이트), 사용자 승인 후 카리나가 루틴 프롬프트를 교체하고 수동 1회 실행으로 검증한다.
- 관련 파일: `.claude/agents/jam-marketer.md`(Modes 표 ⑧ 행, ⑧ 절 「실행 환경」·1~4단계·Forbidden), `.claude/skills/jam-work/references/scheduled-jobs.md`(단서 4-12 33~41행, 4-1, 주간 절의 「절차」·「프롬프트 초안 (윤진)」), `docs/specs/prd/asset-generator/PRD.md`(§8), `docs/agents/contract.json`·`docs/agents/team-operations.md`(자동 생성 구간은 손으로 고치지 않고 `node scripts/gen-team-doc.mjs`)

## 배경 / 문제 정의

1414가 정의와 문서만 A안으로 고치고 루틴 프롬프트 교체를 범위 밖에 두었기 때문에, 실제 주간 루틴은 이미지 관련 지시를 전혀 받지 않았다(W39 테스트에서 확인). 이번 티켓이 정의·문서와 루틴 프롬프트를 함께 맞춘다.

## 상세 요구사항

### 구현 범위 (게이트 판정 대상)

`jam-marketer.md`:
- ⑧ 「실행 환경」: 예약 실행에서도 이미지·묶음(`--dry-run` 검증까지)을 만들 수 있다. 단, 조건: 읽기 API 경로 환경변수(`ADMIN_API_BASE_URL`·`ADMIN_API_READ_TOKEN`)가 있고 `render.mjs`가 성공할 때만. 실패하면 「이미지 준비 대기(사유)」로 표시하고 임의 색·자리표시 이미지를 쓰지 않는다(기존 원칙).
- 대상 범위: **이미지가 필요한 신규 카드만**(전원용 바로가기처럼 이미지가 없는 카드는 「이미지 없음」).
- 컬러 방향: 루틴 본체(호출 세션)가 채원·윈터를 호출해 받은 결과를 쓴다. 결과가 없으면 색을 정하지 않고 멈춘다(기존 원칙 유지, 예약 실행에서는 루틴 본체가 그 호출을 맡는다).
- 프리셋: 홈피드 카드는 `list-presets.mjs --target-type home_feed`로 찾은 **`홈피드` 프리셋**(id `51aa4673-f723-4929-ac20-a302202b7aa7`)을 쓴다. 제목은 `--text`(레이어 `피드 제목`), 짧은 요약은 `--subtext`(레이어 `간단한 설명`)에 넣는다. 글자 수 가이드는 1208 결과를 따른다.
- Forbidden 문구: 「예약 실행에서 이미지·묶음 생성 금지」를 지우고, 예약 실행에서도 **등록 실행(`--dry-run` 없이 `register-*.mjs`, `--undo`), 프리셋 생성·수정, DB·스토리지 쓰기는 금지**임을 명시한다. Bash 허용 범위에 읽기 API 경로의 `render.mjs`·`list-presets.mjs`를 추가한다.

`scheduled-jobs.md`:
- 단서 4-12를 개정한다(이미지·묶음·`--dry-run`은 예약 실행 가능, 서비스 롤 키는 여전히 예약 환경에 두지 않음, 프리셋은 읽기 토큰 API로 조회, 등록은 컨펌 뒤 메인 세션).
- 4-1(환경): 허용 목록 추가분·`ADMIN_API_BASE_URL`(1205 실측 결과 반영).
- 주간 절: 절차에 「윤진 후보안 → 루틴 본체가 채원·윈터 호출 → 윤진 이미지·묶음 → 커밋 → 슬랙」 순서와 「프롬프트 초안 (윤진)」 갱신, 비용 절(이미지 단계·채원·윈터 호출 토큰, 임시 상한 15만의 재산정 필요 표시).

`asset-generator/PRD.md`: §8 예약 실행 서술 갱신(서비스 롤 키 → 읽기 API 경로).
`content-automation/PRD.md`: §8·§8-1(1206과 겹치는 부분은 한 번만 고친다).
자동 생성 구간이 바뀌면 `node scripts/gen-team-doc.mjs`, 환경 사실은 `contract.json` 검사 줄 추가·`scripts/check-contract.mjs` 통과.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤, 사용자 승인 필요)

- 클라우드 루틴(주간 `trig_01DrqvaJccpp17ZBKyTgQgeX`)의 저장 프롬프트를 새 지시문으로 교체한다. **교체 직전에 교체본 전문을 사용자에게 보이고 승인을 받는다**(외부 설정 변경). 교체본 전문은 이 티켓 완료 기록에 남긴다(0806 전례).
- 교체 뒤 수동 1회 실행으로 검증한다: 리포트에 이미지가 인라인으로 보이고, 이미지가 필요한 카드만 만들어졌고, 등록·DB 변경이 없다.

## 구현 계획

1. 정의·문서 갱신(아현) → 민지 게이트.
2. 머지 뒤 카리나가 교체본 초안을 만들어 사용자 승인.
3. 승인 후 루틴 교체 → 수동 실행 → 결과 확인 → 상위 티켓 완료 판단.

## 완료 조건

### 구현 범위
- `jam-marketer.md`가 예약 실행의 이미지 생성 조건·범위·프리셋·색 방향 처리·`--subtext` 규칙을 담고 있고, 등록 실행 금지가 그대로 명시돼 있다.
- `scheduled-jobs.md` 단서 4-12·4-1·주간 절이 새 흐름과 일치하고 두 문서 사이에 「예약에서는 이미지를 만들지 않는다」는 옛 문장이 남아 있지 않다(전체 검색으로 확인).
- `scripts/check-contract.mjs`·`gen-team-doc.mjs --check`가 통과한다.

### 후속 범위
- 사용자 승인 뒤 루틴 프롬프트가 교체됐고, 수동 실행 결과 리포트에서 이미지가 보인다.
