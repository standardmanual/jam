# [Infra] CI 검증 보강 묶음: 액션 버전 상향(1818)과 클라이언트→서버 전용 모듈 도달 검사(1639)

> 하위 티켓 두 건을 한 번의 구현·게이트·머지로 처리하기 위한 묶음 티켓이다(사용자 지시, 2026-09-26). 끝나면 하위 티켓 두 건도 함께 닫는다.

## 핵심 요약

- 요구사항: (1) `verify` 워크플로의 `actions/checkout`·`actions/setup-node`를 Node 24 기반 최신 메이저로 올려 Node 20 사용 중단 경고를 없앤다(20260922_1818). (2) `'use client'` 파일이 값 import를 따라가다 서버 전용 모듈에 닿으면 `scripts/verify.sh`가 실패하게 한다(20260924_1639).
- 구현 계획: 아래 「파일 단위 계획」.
- 관련 파일: `.github/workflows/verify.yml`, `scripts/verify.sh`, `scripts/check-client-server-imports.mjs`(신규), 같은 이름 `.test.mjs`(신규).
- 하위 티켓 본문: `docs/tickets/p2-normal/20260922_1818_*`, `docs/tickets/p2-normal/20260924_1639_*`. **세부 요구사항과 배경은 하위 티켓을 읽는다.**

## 배경 / 문제 정의

하위 티켓 두 건을 참고한다. (1)은 GitHub 측 Node 20 강제 전환 경고, (2)는 통합 실측에서 CI·게이트가 못 잡고 실렌더에서만 드러난 빌드 오류(`UsersFilterBar → user-list → auth`)의 재발 방지다.

## 상세 요구사항

### 서비스/코드베이스 관점

- (1) `verify.yml`의 두 액션을 Node 24 기본 메이저(v5 이상, 릴리스 노트로 확인)로 올린다. `node-version: "24"`는 그대로 둔다.
- (2) 클라이언트 파일(`'use client'`)에서 시작해 `import type`·`{ type X }`만 가져오는 import는 빼고 값 import만 따라가, 서버 전용 모듈에 도달하면 도달 경로(파일 → … → 서버 전용 모듈)를 출력하며 실패한다. 서버 전용 모듈은 `next/headers` 또는 `server-only`를 import하는 파일과, 목록 상수(한 곳)에 적은 파일(`lib/supabase/server.ts`, `lib/admin/auth.ts` 등)이다.

| 2 | `scripts/check-client-server-imports.mjs` (신규) | `jam-web/src` 하위 `'use client'` 파일 수집 → import 문 파싱(`import type`·`{ type X }`만 있는 것 제외, `@/` 별칭·상대경로 해석) → 값 import를 따라 도달 검사 → `SERVER_ONLY_MODULES` 상수(파일 위쪽, 한 곳)와 `next/headers`·`server-only` import 파일에 닿으면 경로 출력 후 종료 코드 1. 순수 함수(`findViolations(files)`)와 실행부 분리 | 약 120 |

- 예상 합계 200줄 안팎, 변경 파일 4개. `planOnlyWaiver`로 첫 호출부터 면제한다. 사전 확인: DB 변경 없음, 서비스 코드 변경 없음.
- 검사가 현재 저장소에서 실패하면 위반 지점이 실제 결함이다. 그 경우 고치지 말고 `alerts`에 `[주의]`로 보고한다(범위 밖).

## 완료 조건

- `verify.yml`의 두 액션이 Node 24 기반 메이저로 올라가 있고, 리뷰 브랜치 push의 `verify` 체크런 annotations에 Node 20 사용 중단 경고가 없다.
- 서버 전용 모듈에 닿는 클라이언트 파일이 있으면 검사가 실패하고 도달 경로를 출력한다. `import type`만 가져오면 통과한다. 이번 사례를 재현하는 픽스처가 실패로 판정된다(단위 테스트).
- `scripts/verify.sh`가 이 검사를 포함하고 현재 저장소에서 통과한다.
