# [Infra] 워크트리 정리 스크립트 안전장치 묶음: `worktree-wf_*` 강제 삭제 가드(1432)와 `set -e` 누락(1214)

> 하위 티켓 두 건을 한 번의 구현·게이트·머지로 처리하기 위한 묶음 티켓이다(사용자 지시, 2026-09-26). 끝나면 하위 티켓 두 건도 함께 닫는다.

## 핵심 요약

- 요구사항: (1) `cleanup_local_branches`가 연결 워크트리 없는 `worktree-wf_*`를 `-D`로 지우기 전에 실제 작업 커밋이 있는지 확인해 유실을 막는다(20260922_1432). (2) `cleanup-stale-worktree.sh`의 중간 명령 실패가 조용히 다음 분기로 흐르지 않게 한다(20260922_1214).
- 구현 계획: 아래 「파일 단위 계획」.
- 관련 파일: `scripts/workspace-setup.sh`(`cleanup_local_branches`), `scripts/workspace-setup.test.mjs`, `scripts/cleanup-stale-worktree.sh`, `scripts/cleanup-stale-worktree.test.mjs`.
- 하위 티켓 본문: `docs/tickets/p2-normal/20260922_1432_*`, `docs/tickets/p3-low/20260922_1214_*`. **세부 요구사항·제약(재작성된 이력 때문에 `merge-base --is-ancestor`를 쓸 수 없다는 점 등)은 하위 티켓을 읽는다.**

## 배경 / 문제 정의

하위 티켓 두 건을 참고한다. 둘 다 정리 스크립트가 조용히 잘못 지우거나 잘못 판정하는 fail-open 성격이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- (1) 가드 조건은 아현이 하위 티켓의 제약 안에서 정하고 「주요 의사결정」에 근거를 남긴다. 작업 커밋이 있는 `worktree-wf_*`는 보존하고 이유를 출력하며, 빈 브랜치는 종전대로 삭제한다.
- (2) `set -uo pipefail`을 `set -euo pipefail`로 바꾸고 의도적 실패 지점을 가드한다. 기존 테스트 4종은 그대로 통과해야 한다.

## 구현 계획

### 파일 단위 계획 (규모 사전 판정, 2026-09-26)

| # | 파일 | 하는 일 | 예상 줄 수 |
|---|---|---|---|
| 1 | `scripts/workspace-setup.sh` (`cleanup_local_branches`) | `worktree-wf_*` 삭제 직전에 작업 커밋 유무 검사 추가, 있으면 보존·이유 출력 | 약 25 |
| 2 | `scripts/workspace-setup.test.mjs` | 임시 저장소에서 `worktree-wf_*` 위에 커밋 1개 → 워크트리 제거 → `cleanup` → 보존과 출력 확인 / 빈 브랜치는 삭제되는 기존 동작 확인 | 약 40 |
| 3 | `scripts/cleanup-stale-worktree.sh` | `set -euo pipefail`로 전환, 의도적 실패 지점 가드 | 약 15 |
| 4 | `scripts/cleanup-stale-worktree.test.mjs` | 기존 4종 유지 + git 명령이 실패하는 상황(저장소 밖 실행) 1건 추가 | 약 25 |

- 예상 합계 약 105줄. `planOnlyWaiver`로 첫 호출부터 면제한다. 사전 확인: DB 변경 없음, 로컬 스크립트만이다.
- 이 스크립트들은 로컬 브랜치를 지우므로 **테스트는 반드시 임시 저장소에서만** 돌린다. 메인 저장소의 브랜치·워크트리를 지우거나 옮기는 명령을 실행하지 않는다.

## 완료 조건

- 임시 저장소에서 `worktree-wf_*` 위에 커밋 1개를 쌓고 워크트리를 지운 뒤 `cleanup`을 돌리면 그 브랜치가 보존되고 이유가 출력된다. 빈 `worktree-wf_*`는 기존처럼 삭제된다.
- `cleanup-stale-worktree.sh`가 `set -euo pipefail`이고 기존 테스트 4종과 명령 실패 1종이 통과한다.
- `scripts/verify.sh` 통과.
