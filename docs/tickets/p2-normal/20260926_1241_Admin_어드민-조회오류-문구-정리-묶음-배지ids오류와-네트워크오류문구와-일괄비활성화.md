# [Admin] 어드민 조회·오류 문구 정리 묶음: 배지 ids 오류(1405), 네트워크 오류 문구(1152), 일괄 비활성화 시각(1404)

> 하위 티켓 세 건을 한 번의 구현·게이트·머지로 처리하기 위한 묶음 티켓이다(사용자 지시, 2026-09-26). 끝나면 하위 티켓 세 건도 함께 닫는다.

## 핵심 요약

- 요구사항: (1) `fetchBadgeListIds`가 DB 오류를 빈 결과가 아니라 오류로 돌려주고 `ids`·`export` 라우트가 500과 한국어 안내를 응답한다(20260924_1405). (2) 서버 응답을 받지 못한 네트워크 오류일 때 표 안 스위치·일괄 처리 토스트가 고정된 한국어 문장을 보여 준다(20260924_1152). (3) 이미 비활성인 배지를 다시 비활성화해도 원래 `deleted_at`이 바뀌지 않는다(20260924_1404).
- 구현 계획: 아래 「파일 단위 계획」.
- 하위 티켓 본문: `docs/tickets/p3-low/20260924_1405_*`, `20260924_1152_*`, `20260924_1404_*`. **세부 요구사항은 하위 티켓을 읽는다.** 세 건은 서로 독립이며 파일이 겹치지 않는다.

## 배경 / 문제 정의

어드민 목록 공통화(20260924_0916)의 하위 티켓 게이트가 남긴 범위 밖 발견물이다. 정합성(조용히 틀리는 결과)과 오류 문구 세 가지다.

## 상세 요구사항

### 서비스/코드베이스 관점

- (2)의 문장은 `docs/specs/UX_WRITING_GUIDELINE.md`의 "[현상] → [원인] → [해결책]" 구조를 따른다. 서버가 돌려준 오류 메시지는 지금처럼 그대로 쓴다.
- (1)의 `AssignTribeDialog` 미리보기 effect 의존성(`ids` 배열 참조) 점검은 코드로 고치고, 실렌더 확인은 카리나가 머지 뒤 가능한 범위에서 한다.

## 완료 조건

- DB 오류 스텁에서 `ids`·`export`가 500과 한국어 안내를 응답한다(단위 테스트).
- `fetch`가 reject될 때 `requestJson`·`runBulk`가 고정 한국어 문장으로 throw하고, 서버가 준 오류 메시지는 그대로 쓴다(단위 테스트).

- `scripts/verify.sh` 통과.
