Task 도구로 `jam-marketer`(윤진)를 model sonnet으로 불러 「유형 카탈로그 리뷰」 절과 「매핑표 갱신 후보」 항목을 쓰게 한다. 초안·사람 등급 유형 11종이 대상이다(PRD `"## 11."` 절 양식: 유형당 1행). 입력은 지난달 유형 ID별 집계 `curl -s -H "x-admin-read-token: $ADMIN_API_READ_TOKEN" "https://j-a-m.app/api/admin/today/metrics?from=YYYY-MM-DD&to=YYYY-MM-DD"`다. 편성 이력이 없는 유형은 "미편성"으로 적고 판정 대상에서 뺀다. 판정은 "유지"·"관찰"만 내고 확정은 세션에서 한다. 「매핑표 갱신 후보」는 `jam-doc/planning/content/TRIBES.md`의 `"### 매핑표 갱신 규칙"` 절 규칙에 따라 후보만 쓴다. 문서는 `node scripts/doc-section.mjs docs/specs/prd/content-automation/PRD.md "## 11."`처럼 필요한 절만 읽는다.

하니(`jam-guide`)는 Bash 도구가 없다. **먼저 네가** `node scripts/doc-check.mjs --all --summary`와 `node scripts/doc-check.mjs --orphans`를 실행하고, `git log --since='1 month ago' --name-only --format= -- jam-doc | sort | uniq -c | sort -rn | head -30`도 실행해 세 출력을 받는다. 그다음 Task 도구로 `jam-guide`(하니)를 model sonnet으로 불러 **그 출력에 근거해** 문서 체계 월간 점검(누락·중복·고아·깨진 링크·수명주기 위반·색인 불일치)의 판단과 수정안만 '문서 점검' 절에 쓰게 하고, `jam-doc/`에 실제로 어떤 종류의 문서가 바뀌고 있는지도 위 git 출력으로 관찰만 적게 한다. 세 출력 전문을 호출 프롬프트에 붙여 넘긴다. 하니는 문서를 통째로 열어 읽지 않고 도구 호출은 15회 이내로 한다. 「낡음」(6개월 미갱신+관련 코드 변경)은 저장소 이력이 2026-06-18에 시작해 2026-12-18 전에는 해당 문서가 없으므로 「해당 없음」으로 적는다. 명확한 문제는 티켓 파일을 만들지 말고 같은 절에 `[분류 대기 초안]`으로 적는다.
