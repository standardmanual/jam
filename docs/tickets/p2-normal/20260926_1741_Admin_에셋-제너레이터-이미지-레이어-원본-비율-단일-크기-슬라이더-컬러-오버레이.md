# [Admin] 에셋 제너레이터 이미지 레이어: 원본 비율로 표시, 크기 슬라이더 단일화, 컬러 오버레이 추가

## 핵심 요약

- 요구사항: (1) 이미지 레이어로 불러온 이미지가 원본과 다른 크기·비율로 보이는 문제를 고친다. (2) 가로 크기·세로 크기 슬라이더를 크기 슬라이더 하나로 합친다(원본 비율 유지). (3) 이미지 레이어에 컬러 오버레이 설정을 추가한다. 토글을 켜면 컬러 셀렉터가 나타나고, 고른 색이 이미지의 불투명한 부분에 입혀진다.
- 구현 계획: 아래 「구현 계획」 참고. 크기는 `widthPct`(스테이지 짧은 변 대비 가로 크기) 하나만 저장하고 세로는 그릴 때 원본 비율로 계산한다. 색 입히기는 `drawImageLayer`가 임시 캔버스에서 `source-in`으로 처리해 브라우저·서버 렌더가 같은 결과를 낸다.
- 관련 파일: 「구현 계획」 파일 목록 참고. 영향받는 스펙은 `docs/service/prd/asset-generator/PRD.md` §4.2.

## 배경 / 문제 정의

- 현재 `createImageLayer`(`assetGeneratorHelpers.ts` 약 148줄)가 `widthPct: 30`, `heightPct: 30`으로 정사각형 크기를 넣고, `drawImageLayer`(`render.ts` 약 233줄)는 `dw`·`dh`를 각각 계산해 그대로 늘려 그린다. 가로세로 비율이 다른 이미지는 항상 찌그러져 보인다.
- `loadImageLayerAsset`(`AssetGeneratorViewport.tsx` 약 255줄)이 쓰는 `loadImageFromBlob`은 긴 변을 512px로 줄이고 SVG는 512px로 래스터화한다. 원본보다 크게 그리면 흐려진다. 리본 스탬프용 로더를 그대로 공유해서 생긴 제약이다.
- 프리셋(`asset_presets.layers` JSON)에는 `widthPct`·`heightPct`가 이미 저장돼 있다. 새 형태로 바뀌어도 기존 프리셋이 읽혀야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `ImageLayerConfig`에서 `heightPct`를 없애고 `widthPct`만 남긴다. 세로 크기는 `image.height / image.width` 비율로 `drawImageLayer`가 계산한다. 기존 프리셋 JSON에 남은 `heightPct`는 읽을 때 무시한다(마이그레이션 없음).
- `ImageLayerConfig`에 `overlayEnabled?: boolean`, `overlayColor?: string`을 추가한다. 두 필드가 없는 기존 프리셋은 오버레이 꺼짐으로 읽는다. 색 입히기는 이미지의 알파 모양은 유지하고 색만 바꾼다(`source-in`). 불투명도는 그 결과에 이어서 적용한다.
- 서버 렌더(`jam-web/scripts/asset-generator/renderCard.mjs`)가 같은 `drawImageLayer`를 쓰므로 새 필드를 그대로 넘긴다. 서버에서 임시 캔버스를 만들 수 있게 `drawImageLayer`가 캔버스 생성 함수를 선택 인자로 받는다.
- 브라우저의 이미지 레이어 원본 로더는 리본용과 분리해 원본 해상도를 유지한다(PNG는 원본 그대로, SVG는 원본 크기 속성 또는 긴 변 2048px).

### UI/UX 관점

- 이미지 레이어 설정 패널: 가로 크기·세로 크기 두 슬라이더를 `크기` 슬라이더 하나로 바꾼다.
- 새 이미지를 추가하면 원본 픽셀 크기 그대로 보이게 시작한다: 원본 가로 px를 현재 스테이지 짧은 변 px로 나눠 %로 바꾸고 슬라이더 범위(`IMAGE_SIZE_RANGE`, 1~200)로 제한한다.
- 「컬러 오버레이」 스위치(`@/components/admin/ui/switch`)를 추가한다. 켜면 컬러 셀렉터(`TextLayerFields.tsx`의 `색` 행과 같은 `type="color"` 입력)가 나타나고 미리보기에 바로 반영된다. 처음 켤 때 기본 색은 `#ffffff`다.

### 컨텐츠 관점 (해당 시)

- 해당 없음

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 가로세로 비율이 1:1이 아닌 PNG를 이미지 레이어로 추가하면 원본 비율 그대로 보이고 찌그러지지 않는다. 처음 표시 크기는 원본 픽셀 크기와 같다(스테이지 짧은 변 대비 %로 환산, 1~200% 범위로 제한).
- 이미지 레이어 설정 패널에는 크기 슬라이더가 하나뿐이고(가로 크기·세로 크기 슬라이더 없음), 움직이면 비율이 유지된 채 커지고 작아진다.
- 「컬러 오버레이」를 켜면 컬러 셀렉터가 나타나고, 고른 색이 이미지의 불투명한 영역에 입혀지며 투명한 영역은 그대로 투명하다. 끄면 원래 색으로 돌아온다. 미리보기·PNG 저장·영상 저장이 같은 결과를 낸다.
- `heightPct`가 들어 있는 기존 프리셋을 불러와도 오류 없이 열리고 오버레이는 꺼져 있다. 프리셋 저장 뒤 다시 불러오면 오버레이 설정이 유지된다.
- 서버 렌더(`renderCard.mjs`)가 오버레이 색을 브라우저와 같게 처리한다(`scripts/verify.sh`의 관련 테스트 통과).
- `scripts/verify.sh` 통과(lint·typecheck·test).

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- `DEV_PROCESS_GUARDRAILS.md` 패턴 13에 따라 로컬에서 실제 화면으로 (1) 세로로 긴 PNG와 SVG를 올려 비율·선명도 (2) 오버레이 켜기·끄기·색 변경 (3) 프리셋 저장 후 불러오기를 확인한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- 이미지 레이어의 세로 크기를 원본 비율로 계산한다(`heightPct` 삭제, `dh = dw * image.height / image.width`). 처음 추가할 때는 원본 가로 px를 스테이지 짧은 변 px로 나눠 %로 잡는다(1~200% 제한, 원본을 못 읽으면 30%).
- 크기 슬라이더를 「크기」 하나로 합쳤다.
- 「컬러 오버레이」 스위치와 색 입력을 추가했다(기본 `#ffffff`). `drawImageLayer`가 임시 캔버스에서 `source-in`으로 색을 입혀 브라우저·서버 렌더가 같은 결과를 낸다.
- 이미지 레이어 전용 로더를 분리해 원본 해상도를 유지한다(PNG 원본, SVG는 크기 속성 또는 긴 변 2048px).
- 기존 프리셋은 `heightPct`를 버리고 오버레이 꺼짐으로 읽는다.
- 원본 다시 올리기도 새 파일의 원본 크기로 크기를 다시 맞춘다(계획 해석, 사용자에게 보고함).

### 주요 의사결정 / 핵심 메모

- 크기 필드는 `sizePct`로 이름을 바꾸지 않고 `widthPct`를 유지한다. 저장된 프리셋 JSON을 마이그레이션하지 않기 위해서다.
- 문제(1)의 원인은 두 가지다: 정사각형 기본값(비율 왜곡)과 512px 축소 로더(선명도).
- 사용자가 채팅에서 계획을 승인했다(2026-09-26). 5개 초과 파일 계획 반환 면제의 근거다. 3건을 한 티켓으로 묶어 진행했다.
- 머지 전 오염 검사가 실패로 나왔으나(브랜치가 최신 staging를 조상으로 물지 않음) 원인은 카리나의 티켓 문서 커밋(015ef7a8) 하나뿐이었고 브랜치에는 승인된 커밋 2건만 있어 그대로 머지했다.
- 계획 밖 파일 2개(`presetSource.test.ts` 픽스처, 프로토타입 번들 재생성)는 타당하다고 게이트가 판정했다.
