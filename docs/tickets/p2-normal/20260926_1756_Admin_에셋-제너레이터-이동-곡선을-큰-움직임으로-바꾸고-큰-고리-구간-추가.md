# [Admin] 에셋 제너레이터 이동 곡선: 큰 움직임으로 바꾸고 가끔 큰 고리 구간 추가

## 핵심 요약

- 요구사항: 스테이지에 그려지는 이동 곡선이 조밀해 보이므로 (A) 잔굴곡을 줄이고 (B) 스테이지 밖으로 나가는 비율을 15%에서 30%로 늘려 움직임을 크게 만든다. 또한 시드에 따라 가끔 곡선이 아주 큰 고리(한 바퀴 원)를 한 번 그리는 구간을 넣는다.
- 구현 계획: `curve.ts`의 상수 조정 + 후보에 `loop` 구간 추가 + 후보 선택에서 시드마다 고리 포함 여부를 먼저 정함. 시제품으로 시드 16개를 그려 확인했다(고리 포함 약 50%, 고리 지름이 스테이지 짧은 변의 약 1/3).
- 관련 파일: `jam-web/src/lib/asset-generator/curve.ts`, `jam-web/src/lib/asset-generator/__tests__/curve.test.ts`, `docs/specs/prd/asset-generator/PRD.md`(§4.1, 약 66줄).

## 배경 / 문제 정의

- 현재 곡선은 진행 방향을 흔드는 파형 6개(`CANDIDATE_HARMONIC_BASE`, 약 62줄)를 겹쳐 만들어 3~6번째 파형이 잔굴곡을 만들고, 화면 밖 비율(`OUT_FRACTION`, 약 46줄)은 0.15다. 사용자가 "조밀하다, 더 큰 움직임을 원한다"고 요청했다.
- 후보 선택(`pickCandidate`, 약 233줄)은 자기 겹침 점수가 가장 낮은 후보를 고르므로, 고리가 있는 후보는 그냥 두면 거의 뽑히지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 상수: `CANDIDATE_HARMONIC_BASE`를 `[0, 1.1, 1.3, 0.6, 0.35, 0.2, 0.1]`, `OUT_FRACTION`을 `0.3`, `RADIUS_MIN`을 `0.15`로 바꾼다.
- `CurveCandidate`에 `loop: { u0: number; width: number; sign: number } | null`을 추가한다. `unitCurve`의 진행 방향 θ(u)에 고리 항을 더한다: `d = (u - u0)`을 0~1로 감은 값이 `width`보다 작으면 `sign * 2π * smoothstep(d / width)`, 그 이후는 `sign * 2π`를 더한다(방향 함수가 계속 매끄럽고 한 바퀴 곡선의 이음매가 유지된다).
- `makeCandidate(rnd, withLoop)`: `withLoop`이면 `u0 = rnd()`, `width = LOOP_WIDTH_MIN + (LOOP_WIDTH_MAX - LOOP_WIDTH_MIN) * rnd()`, `sign = rnd() < 0.5 ? -1 : 1`. 고리가 있으면 `turns`는 항상 1이다(고리 + 두 바퀴 감기가 겹치지 않게).
- 상수 `LOOP_CHANCE = 0.5`, `LOOP_WIDTH_MIN = 0.32`, `LOOP_WIDTH_MAX = 0.45`를 export한다.
- `pickCandidate`: 후보를 뽑기 전에 `wantLoop = rnd() < LOOP_CHANCE`를 시드마다 한 번 정하고 모든 후보를 그 값으로 만든다(겹침 점수가 고리 후보를 밀어내지 않게). 고리 후보의 최소 회전 반경 기준은 `RADIUS_MIN * 0.5`로 낮춘다.
- 같은 시드·같은 입력이면 같은 좌표를 내는 성질(PRD §11)은 유지한다. 시드가 같아도 예전 결과와는 달라진다(프리셋에는 시드를 저장하지 않으므로 저장된 프리셋에는 영향이 없다).
- 서버 렌더(`renderCard.mjs`)와 브라우저가 같은 `buildPath`를 쓰므로 그 밖의 코드 변경은 없다.

### UI/UX 관점 (해당 시)

- 화면 변경 없음. 불규칙성 슬라이더의 동작 범위(`IRR_LO`·`IRR_HI`)는 그대로다.

### 컨텐츠 관점 (해당 시)

- 해당 없음

## 구현 계획

1. `jam-web/src/lib/asset-generator/curve.ts`: 위 상수·`CurveCandidate`·`makeCandidate`·`unitCurve`(약 100~130줄, θ 계산 루프)·`pickCandidate` 수정. 파일 머리 주석에 고리 구간 설명 한 줄.
2. `jam-web/src/lib/asset-generator/__tests__/curve.test.ts`: 화면 밖 비율 기대값을 `0.29~0.31`로, 첫 줄 주석의 15%도 30%로 고친다. 최소 회전 반경 테스트(`>= 0.05`)는 그대로 통과해야 한다. 추가: 시드 0~49에 대해 `pickCandidate`(export 확인 필요)로 고른 후보 중 `loop`가 있는 비율이 0.3~0.7이고, 고리 후보의 완성 경로도 회전 반경 0.05 이상·중앙 통과 10% 이상을 만족한다.
3. `docs/specs/prd/asset-generator/PRD.md` §4.1(약 66줄): "화면 밖으로 조금 나갔다 들어오며(길이의 15%)"를 "화면 밖으로 크게 나갔다 들어오며(길이의 30%), 시드에 따라 큰 고리(한 바퀴 원)를 한 번 그린다"로 덮어쓴다(덮어쓰기 규칙).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 완성 경로에서 화면 밖 길이 비율이 30%±1%p다(불규칙성 0%·100% 모두, 시드 42).
- 시드 0~49 중 30~70%에서 곡선에 큰 고리가 있고, 고리 유무와 무관하게 모든 시드에서 최소 회전 반경이 짧은 변의 5% 이상, 화면 중앙 통과 비율이 10% 이상이다.
- 같은 시드·같은 입력이면 좌표가 같고, 시드가 다르면 좌표가 다르다(기존 결정성 테스트 통과).
- `scripts/verify.sh` 통과.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 로컬 화면에서 "무작위" 버튼을 여러 번 눌러 고리 곡선·일반 곡선이 모두 나오고, 리본이 고리에서 끊기거나 튀지 않는지 확인한다.

### 구현 내용 요약

- 잔굴곡을 줄이고(`CANDIDATE_HARMONIC_BASE` 3~6번째 파형 약화) 화면 밖 비율을 30%(`OUT_FRACTION`)로 늘렸다. `RADIUS_MIN`은 0.15다.
- 시드마다 큰 고리 포함 여부를 먼저 정하고(`LOOP_CHANCE` 0.5) 고리 구간(`LOOP_WIDTH` 0.32~0.45)을 진행 방향에 더한다. 시드 0~49에서 고리 비율은 21/50(42%)다.
- 티켓에 없던 보정 3가지를 `pickCandidate`에 넣었다: 중앙 판정 여유(`CENTER_MARGIN` 1.3), 반경 기준을 절반으로 낮춘 2순위, fallback 점수 기준. 티켓 상수만으로는 전 시드의 중앙 통과 10% 조건이 맞지 않았기 때문이다(민지가 범위 이탈이 아니라고 판정).
- PRD §4.1을 덮어썼다.

### 주요 의사결정 / 핵심 메모

- 사용자가 A(잔굴곡 줄이기)+B(화면 밖 30%)를 골랐고, 고리는 "작은 고리가 아니라 아주 큰 고리"로 정정했다(작은 고리 시제품: 폭 0.10~0.16 → 큰 고리: 0.32~0.45).
- 고리를 후보 선택의 겹침 점수에 맡기지 않고 시드마다 포함 여부를 먼저 정한 이유: 겹침이 적은 후보를 고르는 기존 방식에서는 고리 후보가 거의 선택되지 않는다.
- 티켓 1741(이미지 레이어)을 먼저 머지했고, 이 브랜치는 충돌 없이 이어 머지됐다(번들·PRD 자동 병합 후 재생성 대조).
