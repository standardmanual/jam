# [Admin] 브라우저 이미지 레이어 로더와 이미지 추가·원본 교체의 비동기 흐름을 로직 단위로 분리해 테스트한다

> **연결 메모 (2026-09-30 티켓 20260930_1451 사용자 결정):** 20260930_1501(운영툴 미리보기·이미지) 착수 때 함께 판단한다. 07 블루프린트 4.5가 승인 때 에셋 제너레이터의
> 서버 렌더를 재사용하므로 에셋 제너레이터의 역할이 커진다.

## 핵심 요약

- 요구사항: 브라우저 이미지 레이어 로더와 이미지 추가·원본 교체의 비동기 흐름을 로직 단위로 분리해 테스트한다
- 구현 계획: 미정(착수 전 실측부터)
- 관련 파일: `jam-web/src/app/admin/asset-generator/AssetGeneratorViewport.tsx`(`loadImageLayerFromBlob`·`normalizeSvgMarkup`), `assetGeneratorHelpers.ts`(`readImageNaturalWidth`), `page.tsx`(`handleAddImageLayer` 약 118줄, `handleReplaceImageLayerAsset` 약 184줄)

## 배경 / 문제 정의

프로덕션 배포 전 점검(민지 모드 ②·③, 티켓 1741·1756 배포)의 범위 밖 발견물이다. 이 로직에 테스트가 없다: SVG 크기 속성이 없을 때 긴 변 2048px로 맞추는 분기, 원본 읽기 실패 시 null, 빠르게 두 파일을 연속 추가할 때 순서, 교체 중 레이어를 삭제하는 경우, 원본을 못 읽으면 `widthPct`를 그대로 두는지.

## 완료 조건

- 위 분기·경계를 로직 단위 테스트가 확인한다(화면 확인은 카리나 몫이라 제외).
