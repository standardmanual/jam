# [Admin] 에셋 제너레이터 텍스트 정렬이 화면에 반영되지 않는 문제

## 핵심 요약

- 요구사항: 텍스트 레이어의 정렬(왼쪽/가운데/오른쪽)을 바꾸면 화면에서 실제로 위치가 달라진다. 지금은 한 줄 텍스트를 어떤 정렬로 바꿔도 항상 가운데로 보인다.
- 구현 계획: `drawTextLayer`가 정렬을 앵커 기준으로 적용하게 바꾼다. 왼쪽이면 (xPct)가 텍스트 왼쪽 끝, 가운데면 가운데, 오른쪽이면 오른쪽 끝이다. 세로 위치는 지금처럼 블록 중심이다. 여러 줄일 때 줄끼리의 정렬은 같은 앵커를 기준으로 그대로 유지된다.
- 관련 파일:
  - `jam-web/src/lib/asset-generator/render.ts` `drawTextLayer`(303~350줄 부근): `startX` 계산 분기(343~345줄)와 `TextLayerRenderInput` 위치 주석(283줄)·함수 주석(296줄)
  - `jam-web/src/lib/asset-generator/types.ts`(128·130줄 주석): "텍스트 블록 중심" 표현
  - `jam-web/src/lib/asset-generator/__tests__/render.test.ts`(395~416줄 부근): 정렬별 `fillText` x 좌표 기대값
  - `jam-doc/assets/prototypes/20260924_jam-asset-generator.core.js`: `node jam-web/scripts/asset-generator/build-prototype.mjs`로 재생성(손으로 고치지 않는다)
  - `docs/specs/prd/asset-generator/PRD.md` §4.3(88·89줄): 정렬·위치 행 갱신
  - 호출부(수정 불필요, 확인만): `jam-web/src/app/admin/asset-generator/AssetGeneratorViewport.tsx:321`, `jam-web/scripts/asset-generator/renderCard.mjs:140`

## 배경 / 문제 정의

어드민 에셋 제너레이터의 텍스트 레이어 옵션 중 정렬(왼쪽/가운데/오른쪽)이 동작하지 않고 항상 가운데 정렬로 보인다는 제보가 있었다.

조사 결과 UI 배선(`TextLayerFields.tsx` → `AssetGeneratorViewport.tsx` → `drawTextLayer`)은 정상이고, 렌더 방식에 원인이 있다. `drawTextLayer`는 정렬을 여러 줄 블록 안에서 줄끼리의 상대 위치로만 적용하고, 블록 전체는 항상 (xPct, yPct)에 가운데로 놓는다. 그래서 한 줄이거나 줄 길이가 같으면 정렬을 바꿔도 결과가 똑같다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 한 줄 텍스트에서 정렬을 바꾸면 위치가 달라진다: 왼쪽이면 텍스트 왼쪽 끝이 가로 위치(x)에 닿고, 오른쪽이면 오른쪽 끝이 x에 닿고, 가운데면 텍스트 가운데가 x에 온다.
- 세로 위치(y)는 지금처럼 전체 블록 중심 기준이다.
- 여러 줄이면 각 줄이 같은 앵커(x)에 왼쪽·가운데·오른쪽으로 맞춰진다.
- 회전은 앵커(x, y) 기준으로 지금처럼 적용된다.
- 브라우저(어드민 미리보기·PNG/영상 저장)와 서버(CLI `renderCard.mjs`)가 같은 함수를 쓰므로 결과가 같다.
- 가운데 정렬은 기존과 픽셀 단위로 같은 결과여야 한다(기본값이 가운데라 기존 프리셋 대부분은 위치가 바뀌지 않는다).
- 왼쪽·오른쪽으로 저장된 기존 프리셋은 위치가 이동하지만, 이는 이번 수정이 의도한 동작이다.

## 구현 계획

`render.ts`의 `startX` 분기를 다음처럼 바꾼다(앵커 기준, 회전 좌표계 원점이 앵커).

- `left`: `startX = 0`
- `center`: `startX = -lineWidth / 2`
- `right`: `startX = -lineWidth`

`maxLineWidth`가 더 쓰이지 않으면 제거한다. 주석(`render.ts`·`types.ts`)과 PRD §4.3의 "블록 중심" 서술을 "가로는 정렬 앵커, 세로는 블록 중심"으로 고친다. `render.test.ts`의 정렬 테스트를 새 기대값으로 바꾸고 한 줄 텍스트 케이스를 추가한다. `.core.js`를 재생성한다.

## 완료 조건

- `render.test.ts`: 한 줄 텍스트에서 `left`·`center`·`right`의 첫 글자 x 좌표가 서로 다르다(왼쪽=0, 가운데=-폭/2, 오른쪽=-폭). 여러 줄에서 줄별 정렬도 같은 앵커 기준으로 맞다. `center` 결과는 수정 전과 같다.
- `node jam-web/scripts/asset-generator/build-prototype.mjs --check`가 통과한다(`.core.js`가 원본과 일치).
- `scripts/verify.sh`의 lint·typecheck·test가 통과한다.
- PRD §4.3의 정렬·위치 행이 새 동작과 일치하고, 소스 주석에 "블록 중심" 표현이 남지 않는다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`drawTextLayer`의 `startX`를 앵커 기준으로 바꿨다(왼쪽 0, 가운데 -줄폭/2, 오른쪽 -줄폭). 안 쓰게 된 `maxLineWidth`는 제거했다. 세로 위치와 회전은 그대로다. 소스 주석과 PRD §4.3의 "블록 중심" 서술을 "가로는 정렬 앵커, 세로는 전체 줄 높이 중심"으로 고쳤고 `.core.js`를 재생성했다.

### 주요 의사결정 / 핵심 메모
- 대안으로 "블록 중심은 유지하고 줄끼리만 정렬"(현재 동작)을 그대로 두는 안은 한 줄 텍스트에서 정렬이 무의미해 제보된 문제를 해결하지 못해 채택하지 않았다.

- 왼쪽·오른쪽으로 저장된 기존 프리셋은 텍스트 위치가 이동한다(의도한 동작). 가운데가 기본값이라 대부분의 프리셋은 그대로다.

### 잔여 이슈
- 어드민 화면에서의 실렌더 확인은 로그인 제약으로 하지 못했다. 다음에 어드민에서 텍스트 레이어를 열 때 정렬 3종이 기대대로 보이는지 확인하면 된다.
