# [Admin] 에셋 제너레이터 프리셋에 텍스트 글자 내용도 저장

## 핵심 요약

- 요구사항: 프리셋을 저장할 때 텍스트 레이어에 입력한 글자 내용(`content`)도 함께 저장하고, 불러오면 그 값이 그대로 복원된다.
- 구현 계획: 직렬화(저장)와 역직렬화(불러오기) 두 곳에서 텍스트 레이어 `content`를 빈 문자열로 비우던 처리를 없앤다. 옛 프리셋(빈 문자열로 저장됨)은 그대로 동작한다. CLI 자동 경로(`fillTextLayers`)는 지금처럼 저장된 값을 항상 덮어쓴다.
- 관련 파일:
  - `jam-web/src/lib/asset-generator/presetSerialize.ts` `serializePresetLayers`(86줄 `content: ''`), `deserializePresetLayers`(100줄 `content: ''`)와 두 함수 주석(74·94줄)
  - `jam-web/src/lib/asset-generator/__tests__/presetSerialize.test.ts`(48~52줄 "content를 빈 문자열로 비운다" 테스트 등)
  - `jam-web/scripts/asset-generator/__tests__/presetSource.test.ts`(39·117~125줄: "DB 행은 역직렬화를 거친다(텍스트 content가 비워진다)"). 100~115줄 "DB 행 경로와 API 응답 경로가 같은 형태" 테스트도 `apiPreset` 텍스트 레이어 content를 `dbRow`와 맞춰야 한다
  - `jam-web/scripts/asset-generator/__tests__/fillTextLayers.test.ts`: 저장된 content가 있어도 덮어쓰는 케이스 추가
  - `jam-web/src/app/api/admin/asset-generator/presets/__tests__/route.test.ts`(256·284·367줄 `toMatchObject({ type: 'text', content: '' })`와 4줄 헤더 주석): 입력 content 유지로 변경
  - `docs/service/prd/asset-generator/PRD.md`: §4.3 84줄(글자 내용 행), §5 96~101줄(저장하는 것·저장하지 않는 것), §5 DB 컬럼 설명 317줄(`layers` jsonb), §8 CLI 절 170~177줄(저장된 값을 덮어쓴다는 서술)
  - 확인만(수정 불필요): `jam-web/src/app/api/admin/asset-generator/presets/route.ts:174`(저장 경로), `jam-web/src/app/admin/asset-generator/PresetPanel.tsx:186`(불러오기), `jam-web/scripts/asset-generator/fillTextLayers.mjs`, `jam-web/scripts/asset-generator/presetSource.mjs:28`

## 배경 / 문제 정의

지금은 프리셋에 텍스트 레이어의 글자 내용을 일부러 저장하지 않는다(PRD §4.3·§5). 프리셋을 저장할 때 `serializePresetLayers`가, 불러올 때 `deserializePresetLayers`가 `content`를 빈 문자열로 만든다. 그래서 프리셋을 불러올 때마다 글자를 다시 입력해야 한다. 어드민에서 반복해 쓰는 고정 문구(예: 시리즈 이름)를 프리셋과 함께 보관하려는 요구가 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 프리셋 저장 시 텍스트 레이어의 `content`가 그대로 `layers` jsonb에 저장된다.
- 프리셋 불러오기 시 저장된 `content`가 텍스트 레이어에 복원된다. 저장된 값이 없으면(옛 프리셋) 빈 문자열로 채운다.
- CLI 자동 경로(`render.mjs`·`make-home-feed-card.mjs`)는 저장된 `content`가 있어도 `--text`·`--subtext`로 항상 덮어쓴다. 동작이 바뀌지 않아야 한다.
- DB 스키마 변경은 없다(`layers`는 jsonb).
- 역직렬화의 이미지 레이어 처리(`heightPct` 제거, `overlayEnabled` 기본값)는 그대로 둔다.

## 구현 계획

1. `presetSerialize.ts`: 저장 시에는 텍스트 레이어를 그대로 통과시키고(`content` 유지), 불러오기 시에는 `content`가 문자열이 아니면 `''`로 채운다. 주석을 새 동작에 맞게 고친다.
2. 테스트: `presetSerialize.test.ts`와 `presetSource.test.ts`의 "비운다" 기대값을 "유지한다"로 바꾸고, 옛 프리셋(`content` 없음)이 빈 문자열이 되는 경우를 추가한다.
3. `fillTextLayers.test.ts`는 저장된 값이 있어도 덮어쓰는 케이스가 이미 있는지 확인하고, 없으면 추가한다.
4. PRD §4.3·§5·DB 컬럼 설명·§8을 새 동작("글자 내용도 저장, 자동 경로는 CLI 입력이 덮어쓴다")으로 고친다.

## 완료 조건

- `presetSerialize.test.ts`: 저장 시 텍스트 레이어 `content`가 유지되고, 불러올 때 복원된다. `content`가 없는 옛 레이어는 `''`로 채워진다.
- `presetSource.test.ts`: DB 행을 역직렬화해도 `content`가 유지된다.
- `fillTextLayers.test.ts`: 프리셋 텍스트 레이어에 `content`가 저장돼 있어도 `text`·`subtext`로 덮어쓰는 것이 테스트로 확인된다.
- PRD에 "글자 내용은 저장하지 않는다"는 서술이 남아 있지 않고 새 동작과 일치한다.
- `scripts/verify.sh`의 lint·typecheck·test가 통과한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
프리셋 저장(`serializePresetLayers`)이 텍스트 레이어를 그대로 통과시켜 글자 내용(`content`)도 저장하고, 불러오기(`deserializePresetLayers`)는 저장된 `content`를 복원한다(값이 문자열이 아닌 옛 프리셋은 빈 문자열). CLI 자동 경로(`fillTextLayers`)는 코드 변경 없이 저장된 값을 `--text`·`--subtext`로 항상 덮어쓴다. DB 스키마 변경은 없다(`layers` jsonb). PRD·데이터 모델 문서와 소스 주석의 "글자 내용은 저장하지 않는다" 서술을 새 동작으로 고쳤다.

### 주요 의사결정 / 핵심 메모
- 저장된 글자 내용은 어드민 수동 편집의 기본값이다. CLI 자동 경로는 배지 이름 등을 채워야 하므로 저장된 값을 계속 덮어쓴다.

- 1차 실행에서 아현이 `plan_only`로 멈췄다. 티켓 「관련 파일」에 `route.test.ts`가 빠져 있어 파일이 6개(임계값 5개 초과)가 됐다. 규모 사전 판정에서 저장 API 테스트를 확인하지 않은 것이 원인이다. 변경은 약 57줄로 작아 쪼개지 않고, 사용자 승인(2026-09-26)으로 `planOnlyWaiver`를 부여해 재실행했다.

- 재작업 사유(게이트 FAIL): 티켓 「관련 파일」이 `02_DATA_MODEL.md`와 `types.ts` 주석 2곳을 빠뜨렸다. 두 번의 지연(`plan_only`, 게이트 FAIL)이 모두 티켓을 만들 때 낡은 서술을 전수 확인하지 않은 데서 나왔다. 처리 규칙표(카리나)에 "「~하지 않는다」로 적힌 동작을 뒤집는 티켓은 티켓을 만들기 전에 `git grep`으로 문서·주석·테스트를 전수 확인한다"는 한 줄을 추가했다.

### 잔여 이슈
- 어드민 화면에서 프리셋을 저장한 뒤 불러와 텍스트 값이 복원되는지 실제 화면 확인은 하지 못했다.
