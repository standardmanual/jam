# [Admin] 에셋 제너레이터 적용 이미지가 뭉개지는 문제: WebP 규격을 1280px로 통일

## 핵심 요약

- 요구사항: 에셋 제너레이터로 만든 이미지를 미션·홈피드 등에 적용했을 때 화면에서 뭉개지지 않게, 서비스에 반영하는 WebP의 긴 변을 유형 구분 없이 **1280px**로 통일한다(원본이 더 작으면 확대하지 않는다).
- 구현 계획: `badgeImageWebp.ts`의 상수 `BADGE_IMAGE_WEBP_MAX_LONG_SIDE_PX`를 400에서 1280으로 바꾼다. 적용 API와 CLI 등록 흐름 4곳이 같은 변환기를 쓰므로 함께 바뀐다. 코드·테스트·문서에 적힌 "400px" 서술은 아래 목록대로 전수 고친다.

## 배경 / 문제 정의

에셋 제너레이터 적용 탭으로 미션(`5fc147fd-307e-4dc0-a7dd-a736ceee906f`)에 이미지를 적용했더니 미션 상세 화면에서 이미지가 뭉개져 보인다는 제보가 있었다.

저장소를 확인한 결과 원본 PNG(721,504바이트)는 보관돼 있지만 `image_url`이 가리키는 WebP는 9,134바이트, 긴 변 400px이다. 400px 규격은 배지가 그려지는 최대 크기(200px)의 2배로 정한 값이고, 미션·컬렉션·홈피드는 실측 없이 같은 값을 임시로 썼다(PRD §9, `03_PHASES.md`). 미션 상세는 이미지를 가로 전체 정사각형(최대 640px, 고해상도에서는 1280px)으로 그려서 400px 이미지가 확대돼 뭉개진다. 홈피드 카드(4:5)와 홈피드 상세도 같은 문제가 예상된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 적용 API(`convertBadgeImageToWebp`)와 CLI 등록 흐름(배지·미션·홈피드)이 만드는 WebP의 긴 변 상한이 1280px이다. 유형별 분기는 두지 않는다.
- 원본이 1280px보다 작으면 확대하지 않는다(`withoutEnlargement` 유지). 비율은 `fit: 'inside'`로 유지한다.
- 함수·상수 이름(`convertBadgeImageToWebp`, `BADGE_IMAGE_WEBP_MAX_LONG_SIDE_PX`)은 바꾸지 않는다. 이름을 바꾸면 스크립트 12곳 이상이 함께 바뀌어 범위가 커진다(잔여 이슈로 남긴다).
- 이미 400px로 적용된 이미지는 자동으로 바뀌지 않는다. 배포 뒤 어드민에서 다시 적용하면 저장소의 원본 PNG로 1280px WebP가 만들어진다(후속 범위).

### 문서 관점
- "400px WebP", "표시 규격의 2배 200px", "미션·컬렉션·홈피드는 임시 400px" 서술이 현재 규격(1280px 통일, 근거: 미션 상세 가로 전체 정사각형 최대 640px의 2배)으로 바뀐다.

## 구현 계획

1. `badgeImageWebp.ts` 상수를 1280으로 바꾸고 주석의 근거를 새 규격으로 다시 쓴다.
2. 위 코드 주석·문구·테스트 이름과 기대값을 새 값으로 맞춘다.
3. 문서 목록을 새 규격으로 고친다. PRD §9의 표와 산출 근거는 "긴 변 1280px, 표시 크기 최대 640px×2 기준, 작은 칸은 Next 이미지 최적화가 줄여 내려준다"는 취지로 다시 쓴다.
4. 변경 후 `git grep -nE "400 ?px|긴 변 400"`으로 asset-generator 범위에 낡은 서술이 없는지 확인한다.

### 주요 의사결정 / 핵심 메모
- 처음에는 미션·홈피드만 1280px로 올리는 유형별 분기안을 제안했으나, 사용자가 전체 통일을 제안했다. 분기가 없어 코드·문서가 단순하고, 저장량 증가도 작다고 판단해 통일안을 채택했다(2026-09-26). 저장 측면: 원본 PNG가 장당 약 880KB로 이미 함께 저장되고 있어 WebP가 수십~100KB로 커져도 장당 약 10% 증가다. 화면 측면: 배지 그리드 등 `SafeImage`를 쓰는 곳은 Next 이미지 최적화가 화면 크기에 맞게 줄여 내려준다.
- 미채택 대안: 유형별 크기 분기(배지·컬렉션 400px, 미션·홈피드 1280px). 분기 코드와 유형별 문서 서술이 늘어난다.
- 티켓 규모 판정: 파일 약 17개, 변경 약 60~100줄(대부분 한두 줄 문구). 티켓에 파일 단위 계획을 적어 `planOnlyWaiver`로 넘긴다.
