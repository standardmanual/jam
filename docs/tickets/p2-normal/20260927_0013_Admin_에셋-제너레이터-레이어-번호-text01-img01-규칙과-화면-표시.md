- 구현 계획: 번호 규칙을 순수 함수 하나(`layerKeys.ts`)로 만들어 화면과 CLI가 함께 쓴다. 번호는 목록 순서(위에서 아래)로 종류별 01부터 자동으로 매긴다(저장 필드 없음, DB 변경 없음). 레이어 목록 항목과 선택한 레이어 설정 패널에 번호를 표시한다.

## 배경 / 문제 정의

프리셋을 많이 쓰게 되면서 레이어 정의가 불분명해 활용이 어렵다는 요청이 있었다. 지금 사이드바는 이미지를 「이미지 레이어 N」으로 표시하지만 텍스트는 입력한 글자의 첫 줄만 보여 번호가 보이지 않는다. CLI는 텍스트만 배열 순서(1번째=`--text`, 2번째=`--subtext`)로 채우고 이미지는 값을 지정할 수 없다. 사용자가 프리셋의 번호마다 어떤 값을 넣을지 배치 요청으로 지정하려면 화면과 CLI가 같은 번호 규칙을 써야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- **번호 규칙(단일 원천 `layerKeys.ts`)**: 오버레이 레이어 배열(인덱스 0이 목록 맨 위, 화면 표시 순서와 같다)을 앞에서부터 훑으며 종류별로 01부터 번호를 매긴다. 텍스트는 `text01`, `text02`, …, 이미지는 `img01`, `img02`, …이다. 번호는 저장하지 않고 항상 배열 순서로 계산한다(레이어를 추가·삭제하거나 순서를 바꾸면 번호가 다시 매겨진다).
- 예: 「미션」 프리셋(이미지 1개, 텍스트 3개)은 `img01`(로고), `text01`(조건 문구), `text02`(미션 이름), `text03`(MISSION)이다.
- 리본 레이어는 번호 대상이 아니다(고정 1개).
- `parseLayerKey`는 대소문자를 구분하고 `text`·`img` 뒤에 숫자 두 자리 이상(`01`, `12`)만 받는다. `text1`·`Text01`·`img00`은 null이다(0번은 없다).

### UI/UX 관점
- 레이어 목록의 각 항목 왼쪽에 번호 칩이 보인다. 텍스트 레이어는 번호 칩 뒤에 입력한 첫 줄 미리보기를 붙이고(내용이 비어 있으면 미리보기 없음), 이미지 레이어는 번호 칩만 보인다. 기존 위·아래 이동·삭제 버튼과 선택 강조는 그대로다.
- 레이어를 추가하면 새 항목이 번호 칩과 함께 목록에 나타난다(추가 시점에 별도 안내는 두지 않는다).
- 레이어를 선택하면 그 설정 패널 위에 「선택한 레이어: text01」처럼 제목이 보인다.
- 사용자 노출 한국어 문구는 새로 만들지 않는다(번호는 코드 이름이고, 제목 「선택한 레이어」 하나만 추가).

### 문서 관점
- PRD에 번호 규칙(종류별·목록 순서·저장하지 않음)과 예시를 적는다. CLI 인자 서술(§8)은 다음 티켓에서 고친다.

## 구현 계획

1. `layerKeys.ts`를 순수 함수로 작성한다(React·DOM 의존 없음, CLI가 그대로 가져다 쓴다).

3. `AssetGeneratorPanel.tsx` 선택 레이어 영역에 제목을 추가한다.

### 주요 의사결정 / 핵심 메모
- 번호 부여는 「목록 순서 자동」으로 정했다(사용자 선택, 2026-09-27). 저장 필드가 없어 DB·프리셋 형식이 바뀌지 않고 기존 프리셋(미션·홈피드)도 다시 저장하지 않고 바로 번호가 붙는다. 대신 레이어 순서를 바꾸거나 지우면 번호가 바뀌므로, 배치 값을 지정할 때는 그 시점의 프리셋 화면 번호를 기준으로 한다.
- 미채택 대안: 레이어 생성 시 번호를 고정 저장(순서를 바꿔도 번호 유지). 프리셋 형식에 필드가 추가되고 삭제 후 빈 번호 처리 규칙이 필요해 채택하지 않았다.
- 상위 요청은 3가지(번호 표시·CLI 번호 매칭·배치 값 지정)라 티켓을 나눴다. 이 티켓이 번호 규칙과 표시, 다음 티켓 20260927_0015가 CLI와 배치 계획 파일, 예약 루틴 프롬프트 교체는 배포 시점에 카리나가 직접 한다.
- 티켓 규모 판정: 파일 6~7개, 변경 약 120줄. 티켓에 파일 단위 계획을 적어 `planOnlyWaiver`로 넘긴다.

- 실렌더 중 이전 작업(티켓 20260926_2229, 프리셋에 글자 내용 저장)의 누락을 발견해 고쳤다. 텍스트 레이어 「글자 내용」 입력칸 아래 안내가 「이 값은 프리셋에 저장되지 않아요. 적용할 때마다 다시 입력해요.」로 남아 있었다(`TextLayerFields.tsx:70`). 당시 전수 검색이 「저장하지 않」·「직렬화 제외」 계열 표현 위주라 「저장되지 않아요」 어미를 놓쳤다. 「프리셋에 함께 저장돼요. 프리셋을 불러오면 그대로 채워져요.」로 고쳤다(파일 1개·1줄, 카리나 직접). 게이트 리뷰를 거치지 않은 사용자 노출 문구이므로 이 기록으로 남긴다.
- 머지 전 점검에서 review 브랜치가 최신 `origin/staging` 위에 있지 않다고 나왔다. 원인은 병렬 세션이 staging에 티켓 문서 커밋 3개(티켓 0025~0027)를 추가한 것이었고, 브랜치에만 있는 커밋은 이 티켓 자신의 2개뿐이라 다른 작업의 미승인 커밋 유입은 아니었다. 확인한 뒤 머지했다.
