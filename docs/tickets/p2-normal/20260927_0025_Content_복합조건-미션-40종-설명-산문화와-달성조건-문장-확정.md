# [Content] 복합 조건 미션 40종의 설명을 산문으로 고치고 달성 조건 문장을 확정한다

## 핵심 요약

- 요구사항: 게이트 미션 40종(운영 DB 53행)의 `description`이 조건 문장("4주 안에 한 번에 10km 이상, 5:30/km보다 빠르게 / 3회")으로 채워져 있다. 설명은 조건의 뉘앙스를 담은 산문으로 다시 쓰고, 조건 문장은 달성 조건 카드에 표시할 별도 문안으로 분리해 확정한다.
- 구현 계획: 이 티켓은 문안 확정까지만 한다. 표(아래 「컨텐츠 관점」)를 사용자가 승인하면 후속 티켓 `20260927_0026`이 구현과 반영을 맡는다.
- 관련 파일: `jam-doc/planning/content/v5_mission_seed_build.py` 80~200줄 `CONDITION_BY_CODE`(40개 항목이 원본), 운영 DB `missions` 테이블 `mission_type = 'engine_condition'` 53행. 영향받는 문서 `jam-doc/planning/content/ACTIVITY_BADGES.md` 722줄 부근(미션 문장 인용).

## 배경 / 문제 정의

미션 상세 화면의 달성 조건 카드는 복합 조건(`engine_condition`) 미션에서 "미션 완료 1 달성"이라는 고정 문구만 출력한다(`MissionDetailClient.tsx` `missionGoalText`). 조건 내용을 보여줄 수 없어서, 문안을 만들 때 실제 조건을 설명 칸에 적어 넣었다. 결과는 세 가지 문제다.

1. 설명에 달성 조건이 서술되어 있고, 달성 조건 카드에는 조건이 없다.
2. 설명이 조건의 뉘앙스를 산문으로 전하지 못한다.
3. 달성 조건 카드의 "미션 완료 1 달성"은 당연한 말이라 정보가 없다.

원인은 사용자 입력 실수가 아니라 저희가 시드 스크립트에서 설명 칸을 조건 문장으로 채운 것이다.

## 상세 요구사항

### 컨텐츠 관점

- 설명: 조건의 뉘앙스를 담은 한 문장 산문. 조건의 수치(거리·횟수·기간)를 되풀이하지 않는다. 다른 미션과 겹치지 않는다.
- 조건 문장: `condition_json`에 **실제로 집행되는 조건만** 서술한다. 새 문장은 옛 설명이 아니라 조건 데이터에서 다시 도출한다. 해요체 안내 문구는 화면 쪽 회색 보조 문구가 맡으므로 이 문장에는 넣지 않는다.
- 활동 종류는 카드의 둘째 줄(예: "달리기 활동")이 이미 표시하므로 조건 문장에서 종류를 중복해 강조하지 않는다. 다만 동사(달리기·타기·걷기·산행하기)는 문장 완결에 필요해 남긴다.
- 시간대는 괄호로 시각을 밝힌다. 새벽은 05~08시, 낮은 08~22시(걷기), 밤은 20~05시(달리기)·22~05시(걷기)로 `condition_json`의 값 그대로다.

**⚠ 표시 항목(2건: 쉼표의 증명·회복의 증명)**: 옛 설명이 "매주 2일 이상 휴식"·"매주 하루 이상 쉬면서"라고 적었지만 `condition_json`에는 이를 검사하는 키가 없다(발견물 티켓 `20260927_0027`). 조건 문장은 집행되는 부분만 적었고, 설명 산문에도 휴식 약속을 넣지 않았다.

## 구현 계획

1. 카리나가 표를 작성하고 사용자에게 승인받는다(이 티켓의 산출물).
2. 윈터가 세계관 톤(설명 40건)을 검수하고, 가이드 위반과 트라이브 설정 불일치를 지적한다.
3. 승인된 표를 티켓 `20260927_0026`의 입력으로 넘긴다. 그 티켓이 시드 스크립트·DB·화면·문서에 반영한다.

## 완료 조건

- 40종 모두 새 설명과 새 조건 문장이 있고, 조건 문장은 `condition_json`에 집행되는 조건만 서술한다(⚠ 2건은 발견물 티켓의 결론에 따라 문장을 다시 확인한다).
