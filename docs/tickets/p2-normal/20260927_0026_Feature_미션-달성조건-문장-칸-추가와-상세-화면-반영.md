# [Feature] 미션 달성 조건 문장 칸을 추가하고 상세 화면에 반영한다

> 선행: 티켓 `20260927_0025`(문안 40종)는 표 승인과 윈터 검수를 마쳤다. 이 티켓의 입력은 그 티켓의 「컨텐츠 관점」 최종 표(40행)다. 표의 문안을 한 글자도 바꾸지 않고 시드 스크립트와 백필 SQL에 옮긴다.

## 핵심 요약

- 요구사항: 미션 상세 화면의 달성 조건 카드가 복합 조건 미션에서도 실제 조건 문장을 보여 주게 한다. 미션 테이블에 조건 문장 칸을 추가하고, 화면·어드민·시드·문서를 맞추고, 운영 DB의 53행에 확정된 설명과 조건 문장을 반영한다. 회색 보조 문구는 "참가한 뒤 조건을 달성하면 미션이 자동으로 끝나요"로 바꾼다.
- 구현 계획: 아래 「구현 계획」에 파일 단위로 적는다. 파일이 5개를 넘으므로 첫 호출부터 `planOnlyWaiver`를 넣는다. 구현 착수 전에 카리나가 파일 지도(함수명·줄 위치)를 `git grep`으로 채운다.
- 관련 파일: 「구현 계획」 참조.

## 배경 / 문제 정의

티켓 `20260927_0025`의 배경과 같다. 문안을 아무리 고쳐도 복합 조건 미션에는 조건 문장을 담을 칸이 없어, 화면이 "미션 완료 1 달성"만 보여 준다.

기존 조건 문구 생성기(`jam-web/src/lib/badge-engine/conditionRegistry.ts`의 `formatConditionDetail`)로 자동 생성하는 안을 시험했고 채택하지 않았다(2026-09-27 임시 시험, 시험 파일은 삭제함).

- 시간대(`time_band_counts`)와 달력(`distinct_months_*`) 조건은 빈 문장이 나온다.
- "4주 연속, 한 주에 4번"이 "4주(월~일) 연속 이상"으로 줄어 횟수가 사라진다.
- "기준 조건 3회 충족"처럼 UX 라이팅 가이드가 금지한 "충족"을 쓴다.
- 조각 문구를 나열하는 방식이라 완성된 문장이 되지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `missions`에 nullable 텍스트 칸 `condition_text`를 추가한다. 값이 있으면 화면이 그 문장을 쓰고, 없으면 기존 동작(목표 유형별 문구)을 그대로 쓴다. 기존 미션 유형 화면이 바뀌지 않아야 한다.
- 운영 DB는 스테이징과 공용 단일 DB다. 컬럼 추가는 **확장 단계**(되돌림 SQL 포함)이고, 데이터 반영은 화면 코드가 머지된 뒤에 한다.

### UI/UX 관점

- 달성 조건 카드: 첫 줄은 `condition_text`(있을 때), 둘째 줄은 기존 "○○ 활동", 셋째 줄은 회색 보조 문구.
- 보조 문구는 `conditionAutoCompleteHint`를 **"참가한 뒤 조건을 달성하면 미션이 자동으로 끝나요"**로 바꾼다. UX 라이팅 가이드 102행이 「조건 달성」을 금지 표기로 올려 두었지만, 사용자가 이 문구를 확인한 뒤 「조건을 달성하면」을 선택했다(2026-09-27, 채원 사전 판정의 승인 항목). 가이드 예외로 기록한다.
- 새 문장을 넣어도 화면이 깨지지 않는지(긴 문장 줄바꿈, 모바일 폭)를 실렌더로 확인한다.

### 컨텐츠 관점

- 설명 40건과 조건 문장 40건은 `20260927_0025`의 최종 표를 그대로 쓴다. 표 밖의 문구를 새로 지어내지 않는다.
- 한 문장 본문이므로 설명과 조건 문장 모두 끝에 마침표를 찍지 않는다(UX 라이팅 가이드 §3). 「쉬기」·「회복」은 금지어라 새 문구에 쓰지 않는다. 표에는 이미 반영돼 있다.
- 미션명은 바꾸지 않는다. 「회복의 증명」 이름은 사용자가 유지하기로 결정했다(티켓 `20260927_0025`). 이 티켓의 범위 밖이다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- `condition_text`가 있는 미션은 달성 조건 카드 첫 줄에 그 문장이 나오고, 없는 미션은 기존 표시와 같다(값 있음·없음 두 경우 테스트).
- 회색 보조 문구가 "참가한 뒤 조건을 달성하면 미션이 자동으로 끝나요"로 바뀌었다. 가이드 금지 표기와 겹치는 것은 사용자가 승인한 예외이므로, `docs/specs/UX_WRITING_GUIDELINE.md`에 이 예외를 한 줄 적고(어느 화면·어느 문구·결정일), `scripts/check-slop.mjs`가 이 문구를 막으면 예외로 통과시킨다.
- 마이그레이션 두 개가 `jam-web/supabase/migrations/`에 있고, 첫째 파일에 되돌림 SQL이 있다. 둘째 파일은 제목·옛 설명이 일치하는 행만 갱신한다.
- 시드 스크립트가 새 구조로 재생성되고, 표의 40종이 빠짐없이 들어 있다(스크립트 안의 검증 단언으로 확인).
- 어드민 폼에서 조건 문장을 입력·저장할 수 있다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 채팅 승인 후 DB 실행(컬럼 추가 → 데이터 반영), 실행 결과를 조회로 검증하고 티켓에 기록한다.
- 스테이징 화면에서 "페이스의 증명" 상세를 실렌더로 확인한다(설명 산문, 조건 문장, 활동 종류, 회색 보조 문구).

### 주요 의사결정 / 핵심 메모

- 194 파일에 `COMMIT`이 들어 있어 건수가 달라도 확정될 수 있다는 민지의 지적에 따라, 실행할 때는 갱신 건수가 53이 아니면 예외로 취소되도록 감싸서 돌린다.
