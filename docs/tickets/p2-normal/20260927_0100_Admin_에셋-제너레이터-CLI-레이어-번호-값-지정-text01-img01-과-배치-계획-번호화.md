## 배경 / 문제 정의

프리셋을 많이 쓰게 되면서 텍스트·이미지 레이어의 정의가 불분명해 활용이 어렵다는 요청이 있었다. 티켓 20260927_0013에서 어드민 화면이 레이어를 `text01`, `img01`처럼 번호로 보여 주게 됐다. 그런데 CLI는 여전히 텍스트만 배열 순서(1번째=`--text`, 2번째=`--subtext`, 3번째 이후는 저장된 글자)로 채우고 이미지 레이어는 값을 지정할 수 없다. 화면의 번호와 CLI의 값 지정이 같은 이름을 써야 사용자가 배치 요청에서 「프리셋의 번호마다 어떤 값을 넣을지」를 지정할 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- **번호 규칙**: `layerKeys.ts`(티켓 20260927_0013)를 그대로 쓴다. 번호는 목록 순서(위에서 아래) 종류별 01부터다. CLI가 받는 번호는 정규 형태만 허용한다: `text01`, `text12`, `img01`. `text1`·`text001`·`Text01`·`img00`은 「번호 형식이 올바르지 않아요(예: text01)」 오류다(`parseLayerKey`와 `formatLayerKey`의 왕복이 같은 값일 때만 통과).
- **값 지정**: `--text01 "글자"`(리터럴 `\n`은 개행으로 바꾼다), `--img01 <절대 경로 또는 http(s) URL>`. 같은 번호를 두 번 주면 오류다.
- **지정하지 않은 번호**: 프리셋에 저장된 글자·이미지를 그대로 쓴다(사용자 선택, 2026-09-27). 실행 결과에 `layers.saved`(저장된 값을 쓴 번호 목록)와 `layers.applied`(값을 지정한 번호 목록)를 출력해 빠뜨린 값이 눈에 띄게 한다.
- **없는 번호**: 프리셋에 없는 번호를 지정하면 오류로 멈춘다. 오류 메시지에 그 프리셋의 번호 목록을 보여 준다(예: 「이 프리셋에 없는 번호예요: text05. 있는 번호: img01, text01, text02, text03」).
- **이미지 원본 교체**: 이미지 레이어의 위치(`xPct`·`yPct`)·크기(`widthPct`)·회전·불투명도·컬러 오버레이는 프리셋 값을 그대로 두고 원본만 바꾼다. 세로 크기는 새 원본의 비율로 계산된다(기존 규칙, PRD §4.2). 원본 형식은 PNG·SVG, 크기는 5MB 이하다.
- **`--text`·`--subtext` 제거**(사용자 선택, 2026-09-27): 지정하면 오류로 멈추고 새 인자 이름을 안내한다. 별칭으로 남기지 않는다.
- **필수 인자**: `--preset`, `--bg`, `--end`, `--out`(홈피드 원샷은 `--card`·`--out-dir` 등 기존 필수 인자 유지). 텍스트 값은 더 이상 필수가 아니다(전부 저장된 값이어도 렌더된다).
- **일괄 적용 도구 계획 파일**: 위 「관련 파일」의 형식으로 바꾼다. 같은 제목의 미션이 여러 건이면 `match.title`이 여러 미션에 적용되는 기존 동작과 `expectCount` 검사는 그대로다.
- 렌더 엔진(`renderCardPng`의 그리기 부분)·WebP 변환기·업로드 흐름은 수정하지 않는다.

### 문서 관점
- PRD §8을 새 규칙으로 다시 쓴다(이전 서술은 남기지 않는다). 프리셋 레이어 번호를 확인하는 방법(어드민 레이어 목록의 번호 칩, 실행 결과의 `layers`)을 적는다.

### 구현 내용 요약
CLI가 프리셋 레이어를 어드민 화면과 같은 번호(`--text01`, `--img01`)로 지정한다. 새 모듈 `applyLayerValues.mjs`가 텍스트는 `content`, 이미지는 원본만 교체하고 위치·크기·회전은 프리셋 값을 유지한다(반환 `{ layers, applied, saved }`). `loadLayerImage.mjs`가 이미지 원본(절대 경로 또는 URL, PNG·SVG, 5MB 이하)을 읽는다. 없는 번호(프리셋 번호 목록 포함)·형식 오류(`text1`·`text001`·`Text01`·`img00`)·중복 지정은 한국어 오류로 멈추고, `--text`·`--subtext`는 별칭 없이 안내 오류다. `render.mjs`와 홈피드 원샷은 결과에 `layers: { applied, saved }`를 출력한다. 미션 일괄 적용 도구의 계획 파일은 `{ match: { title }, values, bg, end, expectCount }` 형식이 되었고 실제 계획 파일(42종·55건)을 변환했다. `fillTextLayers.mjs`는 삭제했다. PRD §8·홈피드 묶음 문서·윤진 정의·예약 루틴 문서의 인자 서술을 고쳤다. 묶음 기록 필드 `image.text`·`image.subtext`는 이름을 유지하고 `text01`·`text02` 값을 넣는다.
