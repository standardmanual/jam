# [UI] 복합 조건 미션의 「나의 진행 상황」을 한 문장으로 바꾼다

## 핵심 요약

- 요구사항: 미션 상세 화면의 「나의 진행 상황」 카드가 복합 조건(`engine_condition`) 미션에서 「미션 완료」 라벨과 「미달성」 칩만 보여 준다. 조건은 위의 「달성 조건」 카드가 이미 보여 주므로 여기서 다시 보여 주면 중복이라, 상태를 한 문장으로만 알린다. 미완료는 「아직 미션을 달성하지 못했어요」, 완료는 「미션을 달성했어요」다.
- 구현 계획: 아래 파일 지도대로, 복합 조건일 때만 라벨·칩 대신 한 문장을 그린다. 체크인·아이템 픽업 미션은 기존 표시를 그대로 둔다.
- 관련 파일:
  - `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.tsx` 274~285줄(진행상황 카드, `isAchievementType` 분기). 167줄 `isAchievementType`, 169줄 `achieved`
  - `jam-web/src/lib/i18n/ko.ts` 724~725줄(`achieved`·`notAchieved` 옆에 새 문구 두 개 추가). 709줄 `goalEngineCondition`은 「달성 조건」 카드의 조건 문장이 없는 미션 대체 문구로 계속 쓰이므로 지우지 않는다
  - `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.test.tsx`(케이스 추가)

## 배경 / 문제 정의

사용자가 「페이스의 증명」 상세에서 「미션 완료 / 미달성」이 보이는 이유를 물었다. 계정(sihyunrr@gmail.com)을 조회한 결과 표시는 정상이었다(참가 뒤 10km 이상 달리기 없음, 진행값 0, 완료 0건). 다만 「미션 완료」라는 라벨은 티켓 20260927_0026에서 「달성 조건」 카드에서 없앤 「미션 완료 1 달성」과 같은 종류의 정보 없는 문구이고, 조건은 위 카드가 이미 보여 주므로 진행 카드에서 조건을 다시 보여 주면 중복이다(사용자 판단, 2026-09-27).

## 상세 요구사항

### UI/UX 관점

- 대상: `mission.mission_type === 'engine_condition'`이고 참가 중이거나 완료한 경우(카드를 그리는 기존 조건 그대로).
- 미완료(`achieved`가 거짓): 「아직 미션을 달성하지 못했어요」 한 줄, `text-text-secondary`, 기존 본문 크기(`text-[14px] leading-[1.43]`). 라벨과 칩은 그리지 않는다.
- 완료: 「미션을 달성했어요」 한 줄, `text-text`. **카리나의 가정**: 사용자는 미완료 문구만 정했고 완료 문구는 정하지 않았다. 같은 문형으로 정했다.
- 문체는 해요체다. 사용자가 예로 든 「못했습니다」는 서비스 화면의 해요체 규칙(UX 라이팅 가이드 §문장 규칙)에 맞춰 「못했어요」로 적었다.
- 체크인·아이템 픽업 미션은 기존 「라벨 + 달성/미달성 칩」을 그대로 둔다. 새 색·크기·컴포넌트를 만들지 않는다.
- 「미션 상황」 화면(`/missions/[id]/status`)의 사용자별 달성/미달성 칩은 「미션 완료」 라벨이 없어 바꾸지 않는다.

### 컨텐츠 관점

- 문구 2개를 `ko.ts`의 `d.missions` 아래에 추가한다(예: `engineConditionNotAchieved`, `engineConditionAchieved`). 문장 끝에 마침표를 찍지 않는다(한 문장 본문 규칙).

## 구현 계획

1. `ko.ts` 724~725줄 옆에 문구 2개 추가.
2. `MissionDetailClient.tsx` 274~285줄: `isAchievementType` 분기 안에서 `mission.mission_type === 'engine_condition'`이면 `achieved`에 따라 한 문장만 그리고, 아니면 기존 라벨 + 칩을 그린다.
3. 테스트 3~4건: 복합 조건 + 미완료 → 새 문장이 있고 「미션 완료」·「미달성」이 없다 / 복합 조건 + 완료 → 완료 문장 / 체크인 미션 → 기존 라벨과 칩 유지 / 참가 전에는 카드를 그리지 않는다(기존 동작 유지).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 복합 조건 미션(참가 중·미완료)의 「나의 진행 상황」 카드에 「아직 미션을 달성하지 못했어요」만 나오고 「미션 완료」 라벨과 「미달성」 칩이 없다.
- 복합 조건 미션(완료)은 「미션을 달성했어요」가 나온다.
- 체크인·아이템 픽업 미션의 진행 카드는 이전과 같다(테스트로 고정).
- `scripts/check-slop.mjs`와 `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging에서 「페이스의 증명」 상세를 테스트 계정 또는 참가 상태 계정으로 열어 카드가 한 문장으로 보이는지 확인한다.
- 프로덕션 반영은 `/jam-ship`으로 별도 진행하며 사용자 승인을 받는다.
