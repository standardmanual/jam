# [Admin] 렌더 CLI 인자 파서가 값 자리의 다른 인자를 삼키는 문제

> **연결 메모 (2026-09-30 티켓 20260930_1451 사용자 결정):** 20260930_1501(운영툴 미리보기·이미지) 착수 때 함께 판단한다. 07 블루프린트 4.5가 승인 때 에셋 제너레이터의
> 서버 렌더를 재사용하므로 에셋 제너레이터의 역할이 커진다.

## 핵심 요약

- 요구사항: `render.mjs`의 인자 파서(`renderArgs.mjs` `parseFlags`, 약 24~35줄)가 값 자리에 다른 `--` 인자가 오면 그것을 값으로 삼킨다. 예: `--text01 --text02 설명`이면 `text01`이 글자 `--text02`가 되고 `설명`은 조용히 버려져 잘못된 글자가 이미지에 그려진다. 값이 비었거나 다음 토큰이 `--`로 시작하면 「값이 필요해요」 오류로 멈추게 한다.
- 발견 경위: 티켓 20260927_0100 배포 전 테스트 공백 점검(민지 모드 ③, 주의/보통). 홈피드 원샷 파서(`makeHomeFeedCardArgs.mjs`)는 남은 토큰 검사로 우연히 걸러지지만 렌더 파서는 그렇지 않다.
- 관련 파일: `jam-web/scripts/asset-generator/renderArgs.mjs`(`parseFlags`), `jam-web/scripts/asset-generator/__tests__/renderArgs.test.ts`(값 자리에 다른 `--` 인자가 오는 경계 케이스와 `--image01`·`--txt01` 같은 오타 인자 케이스 추가)
- 함께 정할 것: 알 수 없는 인자(오타)를 무시할지 오류로 멈출지(권장: 오류), `--text01 ""`처럼 빈 문자열 값의 의미(글자를 지우는 것을 허용할지, 계획 파일의 `validatePlan`은 빈 값을 거절하므로 두 경로를 맞출지).

## 완료 조건

- `--text01 --text02 설명`은 「--text01 값이 필요해요」 오류로 멈춘다. 알 수 없는 인자는 오류다. 빈 문자열 값의 처리가 테스트로 고정된다.
- `scripts/verify.sh`가 통과한다.
