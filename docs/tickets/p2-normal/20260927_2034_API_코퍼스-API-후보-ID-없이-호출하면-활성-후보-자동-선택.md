# [API] 코퍼스 API — 후보 ID 없이 호출하면 활성 후보를 자동 선택한다

## 핵심 요약

- 요구사항: `GET /api/admin/content-corpus?type=<유형 ID>&limit=<n>`을 후보 ID(`tribeIds`·`itemBookIds`·`badgeIds`) 없이 부르면 지금은 항상 빈 결과다. ID가 없는 종류는 API가 **활성 후보 중에서 `limit`건을 ISO 주차 순환으로 자동 선택**해 돌려준다. ID를 준 종류는 지금과 똑같이 동작한다.
- 구현 계획: `select.ts`의 `selectCorpusForType`에서 종류별 ID 목록이 비었을 때만 자동 선택 분기를 탄다. 후보 ID 조회 함수(활성만)를 `active.ts`에 추가하고, 순환 선택은 DB 없는 순수 함수로 분리해 테스트한다. 응답에 종류별 선택 방식(`auto`·`explicit`)을 싣는다.
- 관련 파일:
  - `jam-web/src/lib/content-corpus/select.ts` — `selectCorpusForType`(약 43~95행): `ctx.badgeIds`·`ctx.tribeIds`·`ctx.itemBookIds`가 비면 자동 선택. `now` 인자(기본 `new Date()`)를 추가해 테스트에서 주차를 고정한다
  - `jam-web/src/lib/content-corpus/active.ts` — `fetchActiveTribes`(약 66행)·`fetchActiveItemBooks`(약 78행)·`fetchActiveBadges`(약 95행)와 같은 활성 판정으로 **ID만** 모두 돌려주는 조회 함수 3개 추가(배지는 1,000행 상한을 넘을 수 있으니 `.range()` 페이지 반복, `lib/today/events.ts`의 `aggregateTodayCardEvents`와 같은 방식)
  - `jam-web/src/lib/content-corpus/types.ts` — `CorpusSelection` 타입에 선택 방식 필드 추가
  - `jam-web/src/app/api/admin/content-corpus/route.ts` — 머리말 주석(8~24행)에 자동 선택 동작을 적는다. 쿼리 파라미터 처리는 그대로
  - 테스트: `jam-web/src/lib/content-corpus/__tests__/content-corpus.test.ts`, `jam-web/src/app/api/admin/content-corpus/__tests__/`

## 배경 / 문제 정의

주간 루틴 저장 프롬프트는 `content-corpus?type=<유형 ID>&limit=3`만 보낸다. `selectCorpusForType`은 호출부가 넘긴 ID 목록에서만 조회하므로 결과가 항상 비고, 루틴은 `TRIBES.md` 절을 대신 인용한다. 그 결과 PRD `content-automation/PRD.md` §4의 「대상 선택은 활성 목록에서만」 판정이 실제 편성에서 작동하지 않는다. 상위 티켓 [20260927_2033](20260927_2033_Infra_홈피드-문서-코드-정합성-정비와-기능-정의-문서-신설-상위.md) 문제 2. 방식은 사용자가 2026-09-27에 「API가 자동 선택」으로 정했다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **자동 선택 조건**: 유형 매핑(`CONTENT_CORPUS_MAPPING`)이 쓰는 종류 중 요청에 그 종류의 ID가 **없거나 빈 목록**인 종류만 자동 선택한다. 종류별로 따로 판정한다(예: T01에 `tribeIds`만 주면 트라이브는 `explicit`, 컬렉션은 `auto`).
- **자동 선택 후보는 활성만**이다. 역할(`recommend`·`narrative`)과 무관하다. 활성 판정은 지금 함수와 같다: 트라이브 `is_active`, 컬렉션 `is_active`이고 소속 트라이브도 활성, 배지 `deleted_at IS NULL`·유효 기간 안·소속 컬렉션·트라이브 활성. (ID를 명시한 `narrative` 인용이 비활성 글을 포함할 수 있는 지금 규칙(PRD §4 규칙 2)은 바꾸지 않는다.)
- **순환 선택**: 후보 ID를 오름차순 정렬하고, KST 기준 ISO 주차로 시작 위치를 정해 `limit`건을 연속으로(끝에 닿으면 처음으로 돌아) 고른다. 같은 주에는 몇 번 불러도 같은 결과, 주가 바뀌면 다른 결과가 나와야 한다. 후보가 `limit`보다 적으면 전부 돌려준다. 순수 함수로 분리한다(입력: 정렬된 ID 배열·`limit`·주차 키).
- 자동 선택한 ID로 기존 조회(`fetchActiveBadges`·`fetchTribesRaw`·`fetchItemBooksRaw`)를 그대로 태워 `targets`·`quotes`를 채운다. `story_text`가 비면 `description`으로 폴백하는 지금 동작도 유지한다.
- **응답**: 기존 `typeId`·`targets`·`quotes`는 그대로 두고, 이번 호출에서 조회한 종류마다 선택 방식을 담는 필드를 추가한다(예: `selection: { tribe: 'auto', item_book: 'explicit' }`). 매핑에 없는 유형은 지금처럼 빈 결과이고 선택 방식 필드도 비어 있다.
- 개인 정보는 다루지 않는다(원천 테이블에 유저 컬럼이 없다). 쓰기 없음.

## 구현 계획

1. `active.ts`에 `listActiveTribeIds()`·`listActiveItemBookIds()`·`listActiveBadgeIds(now)` 추가(이름은 구현 판단). 배지는 페이지 반복.
2. `select.ts`에 순수 함수 `pickRotating(sortedIds, limit, weekKey)`(이름은 구현 판단)와 KST ISO 주차 키 함수를 둔다. 주차 계산이 이미 저장소에 있으면(예: 리포트 주차 계산) 재사용 여부를 먼저 확인한다.
3. `selectCorpusForType`의 각 종류 분기에서 ID가 비면 1·2로 ID를 만든 뒤 기존 조회로 넘긴다.
4. 테스트: 순환 함수(같은 주 같은 결과·다음 주 다른 결과·후보 부족·wrap-around), 자동/명시 혼합 선택, 선택 방식 필드.
5. **문서는 고치지 않는다.** PRD·윤진 정의·예약 작업 문서의 갱신은 형제 티켓 20260927_2037에서 카리나가 한다(같은 문서를 병렬로 고쳐 충돌하는 것을 막는다). 이 티켓에서는 `route.ts` 머리말 주석만 고친다.

## 구현 계획 (아현 1차 반환, 2026-09-27 — 사용자 승인으로 계획 반환 면제)

1차 실행에서 구현·검증을 마친 뒤 diff 297줄(기준 100줄 초과)로 원복하고 반환한 계획이다. 관련 테스트 45건 통과를 확인했다.
1. `types.ts`(+5): `CorpusSelectionMode`(`auto`·`explicit`), `CorpusSelection.selection` 필드.
2. `active.ts`(+66): `listActiveTribeIds()`·`listActiveItemBookIds()`·`listActiveBadgeIds(now)`. 기존 `fetchActiveIds`·`fetchActiveParentIds` 재사용, 배지는 `.range()` 1,000행 페이지 반복.
3. `select.ts`(+77/-12): `isoWeekOrdinal(now)`(KST ISO 8601 주차 → 「연도×53+주차」 정수, `kstDateString` 재사용), 순수 함수 `pickRotating(sortedIds, limit, weekOrdinal)`(wrap-around). `selectCorpusForType`에 `now` 인자, `resolveIds()`로 종류별 auto/explicit 판정, 응답에 `selection`.
4. `route.ts`(+8/-5): 머리말 주석만.
5. `__tests__/content-corpus.test.ts`(+110/-14): 목 경로 추가, 「`badgeIds` 빈 배열 → 미조회」 테스트를 「자동 선택·`selection: auto`」로 교체(새 스펙과 충돌), 순환 5건·ISO 주차 3건·혼합 선택 4건 신규.

## 완료 조건

- `?type=T01&limit=3`을 ID 없이 부르면 활성 트라이브·활성 컬렉션에서 각각 3건 이내가 `quotes`에 실리고 `selection`이 둘 다 `auto`다(단위 테스트로 확인, DB는 목으로 대체).
- `?type=T02&limit=3`을 ID 없이 부르면 활성 배지 3건 이내가 `targets`와 `quotes`에 실린다(단위 테스트).
- 같은 주차 키로 두 번 선택하면 결과가 같고, 다음 주차 키로 선택하면 후보가 `limit`보다 많을 때 결과가 달라진다(단위 테스트).
- 기존 테스트(ID를 명시한 호출)가 수정 없이 통과한다.
- `scripts/verify.sh`가 통과한다.

### 구현 내용 요약
`selectCorpusForType`이 종류(tribe·item_book·badge)별로 후보 ID가 없거나 빈 배열이면 활성 후보를 KST ISO 주차 순환으로 `limit`건 자동 선택(`auto`)하고, ID를 준 종류는 그대로 조회(`explicit`)한다. 응답에 종류별 `selection`을 싣는다. 순수 함수 `isoWeekOrdinal(now)`·`pickRotating(sortedIds, limit, weekOrdinal)`, 조회 함수 `listActiveTribeIds`·`listActiveItemBookIds`·`listActiveBadgeIds(now)`(배지는 `.range()` 페이지 반복). 라우트는 머리말 주석만 바뀌었다.
