# [Admin] 미션 소개 카드 레이아웃 추천값과 홈피드 등록 묶음의 레이아웃·글자 수 검사

## 핵심 요약

- 요구사항: 2026-09-26 사용자 결정(「`mission_spotlight` 카드는 항상 `large_thumbnail`」, PRD `content-automation/PRD.md` §8)과 홈피드 프리셋 글자 수 가이드(제목 11자·요약 22자, `asset-generator/PRD.md` §8)를 코드가 강제하게 한다. ① 어드민 폼이 `mission_spotlight`를 고를 때 추천 레이아웃을 `shortcut`에서 `large_thumbnail`로 바꾼다. ② 홈피드 등록 묶음 검증(`validateHomeFeedBundle`)이 `mission_spotlight`인데 최종 레이아웃이 `large_thumbnail`이 아닌 카드와, 글자 수 가이드를 넘는 `image.text`·`image.subtext`를 거절한다.
- 구현 계획: 상수 1줄 변경 + 묶음 검증 함수에 사유 2종 추가 + 테스트 + 묶음 형식 문서 갱신.
- 관련 파일:
  - `jam-web/src/lib/admin/today-sections.ts` — `SUGGESTED_LAYOUT_FOR.mission_spotlight`(약 88행) `'shortcut'` → `'large_thumbnail'`
  - `jam-web/scripts/asset-generator/registerHomeFeedBundle.mjs` — `validateCard`(약 186행~): 최종 레이아웃(`card.layout_type ?? SUGGESTED_LAYOUT_FOR[card.template_type]`, 같은 식이 `buildTodayCardInsertPayload` 약 435행에 있다)이 `mission_spotlight`에서 `large_thumbnail`이 아니면 사유 추가. `validateImage`(약 317행~, `image.text`·`image.subtext` 타입 검사 약 356~361행 뒤): 글자 수 검사 추가
  - 테스트: `jam-web/scripts/asset-generator/__tests__/registerHomeFeedBundle.test.ts`(`SUGGESTED_LAYOUT_FOR` import 12행, 약 422행 사용처), 어드민 폼 관련 테스트가 추천값을 고정하고 있으면 함께 갱신(`grep -rn SUGGESTED_LAYOUT_FOR jam-web/src`로 확인 — 사용처는 `TodayCardForm.tsx` 123·184행)
  - 문서: `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md` §3.3 `layout_type` 행·템플릿 규칙 아래, §3.4 `image` 절, §4 「검증이 내는 사유 예」

## 배경 / 문제 정의

9/26 규칙은 문서와 루틴 프롬프트에만 있고 코드가 검사하지 않는다. 어드민 폼은 오히려 `mission_spotlight`에 `shortcut`(이미지 없는 짧은 CTA)을 기본 선택하고, 등록 스크립트는 레이아웃과 이미지 글자 수를 보지 않는다. 글자 수를 넘기면 이미지 글자가 좌우로 잘리는데(`asset-generator/PRD.md` §8 실측), 지금은 `--dry-run`이 통과한다. 상위 티켓 [20260927_2033](20260927_2033_Infra_홈피드-문서-코드-정합성-정비와-기능-정의-문서-신설-상위.md) 문제 3. 범위는 사용자가 2026-09-27에 「폼 기본값 + 등록 검사」로 정했다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **추천값**: `SUGGESTED_LAYOUT_FOR.mission_spotlight = 'large_thumbnail'`. 추천값일 뿐이라 어드민은 폼에서 다른 레이아웃을 고를 수 있다(폼 검사는 추가하지 않는다). 이미 등록된 카드의 `layout_type`은 바꾸지 않는다(데이터 변경 없음).
- **묶음 레이아웃 검사**: `template_type`이 `mission_spotlight`이고 최종 레이아웃이 `large_thumbnail`이 아니면 거절한다. 사유 문구는 기존 사유와 같은 해요체 형식으로, 근거(PRD §8 미션 카드 규칙)를 알 수 있게 쓴다.
- **글자 수 검사**(`asset-generator/PRD.md` §8 「글자 수 가이드」 표가 근거, 공백 포함 글자 수):
  - `image.text`(제목, `text01`): 줄바꿈이 있으면 거절(제목은 항상 1줄). 11자를 넘으면 거절.
  - `image.subtext`(요약, `text02`): 1줄이면 22자 이하. 줄바꿈으로 2줄이면 줄마다 15자 이하. 3줄 이상이면 거절.
  - 글자 수는 문자열 `length`가 아니라 **사용자에게 보이는 글자(코드 포인트) 수**로 센다(`[...s].length`). 리터럴 `\n` 두 글자를 개행으로 바꾸는 규칙이 렌더 인자에 있으므로(`renderArgs.mjs` 43행 주석) 묶음 값이 실제 개행인지 리터럴인지 확인하고 둘 다 줄 구분으로 본다.
  - 두 필드가 없으면(선택 필드) 검사하지 않는다.
- `make-home-feed-card.mjs`는 같은 검증을 `--dry-run` 단계에서 거치므로 따로 고치지 않는다. 렌더 전에 막을 필요가 있다고 판단되면 이유를 적고 제안만 한다.

### UI/UX 관점

- 어드민 투데이 카드 폼에서 템플릿을 「미션 소개」로 고르면 레이아웃이 「큰 썸네일형」으로 미리 선택된다. 화면 구조·문구 변경은 없다.

## 구현 계획

1. `today-sections.ts` 상수 변경.
2. `registerHomeFeedBundle.mjs`에 두 검사 추가(사유는 모두 모아 한 번에 알리는 기존 방식 유지).
3. 테스트 추가: `mission_spotlight` + `shortcut` 거절, `mission_spotlight` + 레이아웃 생략 통과(추천값이 `large_thumbnail`이므로), 제목 11자 통과·12자 거절·개행 거절, 요약 22자 통과·23자 거절·2줄 15자씩 통과·2줄 중 16자 거절·3줄 거절.
4. `HOME_FEED_REGISTRATION_BUNDLE.md`의 해당 절을 갱신한다. **다른 문서(PRD·윤진 정의 등)는 형제 티켓 20260927_2037에서 카리나가 고친다.**
