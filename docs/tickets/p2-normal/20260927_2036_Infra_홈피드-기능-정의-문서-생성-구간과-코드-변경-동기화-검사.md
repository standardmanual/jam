# [Infra] 홈피드 기능 정의 문서의 생성 구간과 코드 변경 동기화 검사

## 핵심 요약

- 요구사항: 홈피드 서비스 기능 정의를 담을 새 문서 `docs/specs/prd/home-feed/PRD.md`가 **항상 코드와 같은 상태**이도록 두 장치를 만든다. ① 코드 상수·순수 함수에서 표를 생성하는 스크립트(`--check`로 낡음 검사, `verify.sh`·pre-commit 연결). ② 홈피드 코드가 스테이지됐는데 이 문서가 스테이지되지 않은 커밋을 막는 pre-commit 검사(`JAM_SKIP_DOCLINT=1`로 우회). 문서 본문(서술)은 형제 티켓 20260927_2037에서 카리나가 쓰므로, 이 티켓은 **frontmatter·절 제목·생성 구간만 있는 뼈대**를 만든다.
- 구현 계획: `scripts/gen-home-feed-doc.mjs`(+ `.test.mjs`) 신설. 기존 생성기 `scripts/gen-team-doc.mjs`의 생성 구간 표식(`<!-- BEGIN generated: 이름 -->`·`<!-- END generated: 이름 -->`, 133~148행)과 `--check` 방식을 그대로 따른다. 동기화 검사는 같은 스크립트의 `--staged` 모드 또는 별도 스크립트로 둔다(구현 판단).
- 관련 파일:
  - 신규 `scripts/gen-home-feed-doc.mjs`, `scripts/gen-home-feed-doc.test.mjs`
  - 신규 `docs/specs/prd/home-feed/PRD.md`(뼈대, `status: draft`)
  - `.githooks/pre-commit` — 문서 lint 블록 안 생성기 검사 줄들(약 240~258행, `gen-scheduled-jobs.mjs --check` 다음)에 생성 검사와 동기화 검사를 추가. `doclint=1` 경로를 쓰면 기존 `JAM_SKIP_DOCLINT=1` 우회가 그대로 적용된다
  - `scripts/verify.sh` — `gen-scheduled-jobs` 검사(약 95~99행) 다음에 생성 검사 추가(동기화 검사는 스테이지 기준이라 verify에는 넣지 않는다)
  - `docs/agents/contract.json` — `paths_exist.paths`에 새 문서·스크립트 경로 추가
  - `docs/specs/INDEX.md` — `node scripts/gen-doc-index.mjs`로 재생성(손으로 고치지 않는다)
  - 생성 원천(읽기만): `jam-web/src/lib/admin/today-sections.ts`(`TODAY_TEMPLATE_OPTIONS`·`TODAY_LAYOUT_OPTIONS`·`SUGGESTED_LAYOUT_FOR`·`TODAY_FIELDS_FOR`·`TODAY_EXPOSURE_TAG_OPTIONS`·`TODAY_CONTENT_TYPE_OPTIONS`), `jam-web/src/lib/today/targetHref.ts`(`resolveTargetHref`·`resolveArticleCtaTarget`)

## 배경 / 문제 정의

홈피드 기능 정의가 `01_PRD.md` §4, `02_DATA_MODEL.md`, `content-automation/PRD.md`, `HOME_FEED_REGISTRATION_BUNDLE.md`에 흩어져 있고, 코드를 바꿔도 문서를 고치게 하는 장치가 없어 여러 건이 낡았다(홈 화면 구성, 템플릿 수 등). 사용자는 2026-09-27에 「홈피드 기능 정의 문서를 별도로 항상 최신화」하라고 요청했고, 장치는 「생성 구간 + 커밋 차단」으로 정했다. 상위 티켓 [20260927_2033](20260927_2033_Infra_홈피드-문서-코드-정합성-정비와-기능-정의-문서-신설-상위.md).

## 상세 요구사항

### 서비스/코드베이스 관점

**① 생성기 `gen-home-feed-doc.mjs`**
- 루트 `scripts/`의 plain node 스크립트다. `today-sections.ts`·`targetHref.ts`는 Node 내장 타입 제거(Node 22.18 이상 기본 활성, CI는 Node 24 — `.github/workflows/verify.yml` 72행)로 직접 import한다. 두 파일은 `import type`만 쓰므로 가능하다(확인 2026-09-27: `today-sections.ts` 12행이 유일한 import). Node가 타입 제거를 지원하지 않으면 한국어 오류와 필요한 버전을 출력하고 종료 코드 2로 끝낸다. `jam-web/node_modules`에 의존하지 않는다(pre-commit에서 돈다). 이 방식이 막히면 대안(예: 정규식 파싱)과 이유를 완료 기록에 남긴다.
- 생성 구간(이름은 구현 판단, 아래는 예):
  - `templates` — 템플릿 값 · 라벨 · 추천 레이아웃(`SUGGESTED_LAYOUT_FOR`) · 쓰는 참조 필드(`TODAY_FIELDS_FOR`)
  - `layouts` — 레이아웃 값 · 라벨
  - `exposure-tags` — 노출 태그 값 · 라벨
  - `content-types` — 유형 ID · 라벨(`TODAY_CONTENT_TYPE_OPTIONS`)
  - `destinations` — 템플릿별로 대표 입력(대상 필드가 비었을 때·1개·여러 개·`target_href` 명시)을 `resolveTargetHref`에 넣어 나온 경로를 표로. `ranking_board`는 미션 참가자 대상 맥락 유무 두 경우. 기사 본문 CTA는 `resolveArticleCtaTarget`로 우선순위 표. 입력 카드 객체는 스크립트 안에 고정한다(id는 `{id}`처럼 자리표시로 치환해 표에 쓴다)
- 기본 실행은 문서의 생성 구간을 다시 쓴다. `--check`는 쓰지 않고 비교만 해서 다르면 종료 코드 1과 「`node scripts/gen-home-feed-doc.mjs`를 실행해 다시 생성하라」는 한국어 안내를 낸다. 표식이 없으면 `gen-team-doc.mjs`처럼 어떤 표식을 넣어야 하는지 알린다.
- 생성 구간 밖 본문은 절대 건드리지 않는다.

**② 코드 변경 동기화 검사**
- 기준 경로 목록의 단일 원천은 새 문서 frontmatter의 `code:` 목록이다(스크립트에 경로를 따로 적지 않는다).
- 스테이지된 파일(`git diff --cached --name-only`) 중 `code:` 경로 아래에 있는 파일이 있고, 새 문서가 스테이지되지 않았으면 차단한다. 테스트 파일(`__tests__/` 아래, `*.test.*`)만 바뀐 경우는 제외한다.
- 차단 메시지(한국어): 어떤 파일이 홈피드 코드인지, 고칠 문서 경로, 생성 구간이면 생성기 실행, 동작이 바뀌지 않은 변경(리팩터링 등)이면 `JAM_SKIP_DOCLINT=1`로 우회하고 커밋 메시지에 사유를 남기라는 안내.
- 무인 예약 루틴 커밋은 `jam-doc/operations/reports/`만 바꾸므로 영향이 없다. 머지 커밋은 pre-commit을 거치지 않는다(이 저장소에 `pre-merge-commit` 훅 없음, 2026-09-27 `.githooks/` 확인) — 그 사실을 스크립트 머리말에 적는다.

**③ 뼈대 문서 `docs/specs/prd/home-feed/PRD.md`**
- frontmatter: `type: prd`, `status: draft`(본문이 채워지면 2037에서 `active`로 바꾼다), `description`(한 문장), `tags`(`DOCUMENT_SCHEMA.md`의 태그 어휘에서), `related: ["20260927_2033"]`, `code:` 목록은 아래.
  ```
  code:
    - "jam-web/src/app/(main)/page.tsx"
    - "jam-web/src/app/(main)/TodayCardStack.tsx"
    - "jam-web/src/app/(main)/TodayCardTracker.tsx"
    - "jam-web/src/app/(main)/TodayStatusStrip.tsx"
    - "jam-web/src/app/(main)/today"
    - "jam-web/src/lib/today"
    - "jam-web/src/lib/admin/today-sections.ts"
    - "jam-web/src/app/api/today"
    - "jam-web/src/lib/inputs"
    - "jam-web/src/app/api/cron/external-inputs"
  ```
- 절 제목만 둔다(본문은 비우고 각 절에 `> 2037에서 작성` 한 줄): 1. 한 줄 정의 · 2. 홈 화면 구성 · 3. 카드 노출 규칙 · 4. 노출 태그 · 5. 템플릿 · 6. 레이아웃과 커버 이미지 · 7. 이동 목적지 · 8. 기사 상세 · 9. 계측 · 10. 데이터 · 11. 운영 규칙 위치 · 12. 이 문서를 최신으로 유지하는 방법. 생성 구간은 4·5·6·7절 안에 넣고 생성기를 한 번 실행해 채운다.
- 문서 lint(`doc-check`)와 `gen-doc-index --check`가 통과해야 한다.

## 완료 조건

- `node scripts/gen-home-feed-doc.mjs --check`가 뼈대 문서에서 종료 코드 0이다. `today-sections.ts`의 라벨 하나를 임시로 바꾸면 1이 된다(테스트로 확인, 실제 파일은 되돌린다).
- 동기화 검사: `jam-web/src/lib/today/cards.ts`만 스테이지하면 차단되고, 새 문서도 함께 스테이지하면 통과하고, `jam-web/src/lib/today/__tests__/` 아래 파일만 스테이지하면 통과한다(테스트로 확인 — 임시 git 저장소나 순수 함수 단위로).
- pre-commit·`verify.sh`에 연결돼 있고, `JAM_SKIP_DOCLINT=1`로 우회된다.
- `contract.json`에 새 경로가 있고 `node scripts/check-contract.mjs`가 통과한다.
- `docs/specs/INDEX.md`가 재생성돼 있다.
- `scripts/verify.sh`가 통과한다.
- **문서 본문(서술)·다른 문서는 고치지 않는다**(형제 티켓 2037).
