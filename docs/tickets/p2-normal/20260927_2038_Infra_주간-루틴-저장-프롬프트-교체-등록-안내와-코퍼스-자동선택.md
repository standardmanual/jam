## 1. 브리핑 (카즈하)
먼저 **네가 직접** `node scripts/weekly-collect.mjs --since <지난 주간 리포트의 KST 날짜, YYYY-MM-DD>`를 1회 실행해 출력을 받는다. GA4·운영 집계(KPI)·어드민 현황·티켓 현황판·워크플로 수치·main 커밋·선별 동의율이 `### 출처: …` 절로 나오고, 실패한 출처는 그 절에 사유가 적힌다. KPI는 기본 7일 집계라 `--since`와 기간이 다를 수 있으니 리포트에 KPI 기간을 그대로 적는다.

## 2. 홈피드 편성 후보안 (윤진)
브리핑을 쓴 뒤 Task 도구로 `jam-marketer`(윤진)를 model sonnet으로 불러 같은 파일의 '홈피드 초안' 절에 **다음 주(월~일) 편성 후보안**을 PRD §8 형식으로 쓰게 한다. 규칙은 scheduled-jobs.md 주간 절의 윤진 지시문과 PRD §8·§8-2를 따른다. 특히:
- 요일마다 후보 A·B(·C), 윤진 1픽, 「전원 카드」 칸을 쓴다. **요일마다 전원(`all`) 카드가 1장 이상** 있어야 한다.
- 후보마다 등록에 필요한 내용을 모두 쓴다(제목·부제·템플릿·레이아웃·노출 태그·노출일·목적지). 에디토리얼 기사 후보는 본문 전문과 CTA 목적지를 「후보 본문」 절에 쓴다. 기사 본문은 마크다운으로 렌더되지 않으므로 빈 줄로 문단만 나누고 `**`·`#`·`-` 같은 문법을 쓰지 않는다(PRD §8). 이미지가 준비되지 않은 기사(「이미지 없음」·「이미지 준비 대기」)는 레이아웃을 `other`로 한다. 이미지를 만들 후보는 아래 2-1단계에서 정한다.
- 코퍼스는 `curl -s -H "x-admin-read-token: $ADMIN_API_READ_TOKEN" "https://j-a-m.app/api/admin/content-corpus?type=<유형 ID>&limit=3"`로만 받는다. 후보 ID(`tribeIds`·`itemBookIds`·`badgeIds`, 콤마로 구분)를 주지 않은 종류는 API가 활성 후보에서 주차마다 바뀌는 3건을 고른다(응답 `selection`이 `auto`, 티켓 20260927_2034 — 프로덕션 배포 뒤부터). 특정 트라이브·컬렉션·배지를 쓰려면 그 ID를 넘긴다.
- **요일별 큰 카드 규칙(사용자 결정 2026-09-26)**: 요일마다 「전원 카드」 칸의 카드는 `large_thumbnail`(커버 이미지 필수)이어야 한다. 정본은 PRD §8이다.
- **미션 카드 규칙(사용자 결정·확인 2026-09-26)**: 미션을 대표 이미지와 함께 소개하는 카드(`mission_spotlight`, T04·T15)는 항상 `large_thumbnail`이고, 커버는 그 미션의 대표 이미지(`missions.image_url`)를 그대로 쓰며 새로 만들지 않는다. 1. 판별: 이미지가 필요한 카드(`HOME_FEED_REGISTRATION_BUNDLE.md` §1.1 표: `large_thumbnail`·`banner`·에디토리얼 기사)를 고른다. 우선순위는 ① 요일마다 「전원 카드」(`large_thumbnail`, 요일당 1장) ② 남는 자리에 이미지가 필요한 윤진 1픽 카드다. **새로 만드는 이미지는 주 7장 이내**이고, 미션 대표 이미지(`missions.image_url`)를 재사용하는 카드는 이미지를 만들지 않으며 장수에도 세지 않는다(그 URL을 후보 칸에 `![](URL)`로 적는다). 카드마다 제목(공백 포함 11자 이하, 1줄)과 짧은 요약(공백 포함 22자 이하)을 정한다. 이미지가 필요 없는 카드는 표에 「이미지 없음(사유)」로 적는다.
2. 준비: `cd jam-web && npm ci`를 네가 직접 실행한다(약 30초). 환경변수 `ADMIN_API_BASE_URL`·`ADMIN_API_READ_TOKEN`이 설정돼 있는지 확인한다(값은 출력하지 않는다). 설치가 실패하거나 변수가 없으면 이미지가 필요한 모든 카드를 「이미지 준비 대기(사유)」로 표시하고 3~5를 건너뛴다.
3. 컬러 방향: 네가 Task 도구로 `jam-designer`(채원)를 model sonnet으로 **모든 카드를 한 번에** 넘겨 부르고(카드별 배경색·끝색 후보 1~3쌍과 대비 확인), 세계관과 닿는 카드는 `jam-tribe`(윈터)를 model sonnet으로 한 번에 불러 세계관 적합 검수 결과를 받는다. 두 호출은 동시에 한다. 부를 때 카드 제목·요약·트라이브·무드·이슈를 넘긴다. **채원에게 알린다**: 색 토큰은 `jam-web/design-system/tokens/colors.css`만 읽고 `_ds_manifest.json`은 읽지 않는다. 프리셋 글자색은 흰색(`#ffffff`)이다. 대비는 `cd jam-web && node scripts/asset-generator/contrast.mjs --bg "#rrggbb" --end "#rrggbb"`로 계산하고 계산 코드를 직접 쓰지 않는다. **윈터에게 알린다**: 트라이브 원문은 `docs/service/content/TRIBES.md`에서 해당 트라이브 절(`node scripts/doc-section.mjs docs/service/content/TRIBES.md "### 3. 숲속의 갱단"` 형태)만 읽고 파일 전체는 읽지 않는다. **윤진은 색을 정하지 않는다.** 결과를 받지 못한 카드는 「이미지 준비 대기(채원·윈터 결과 없음)」로 표시한다.
4. 렌더: Task 도구로 `jam-marketer`(윤진)를 model sonnet으로 불러, 받은 색과 검수 결과로 카드마다 다음을 하게 한다. 명령 사용법과 묶음 필드는 `node scripts/doc-section.mjs docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md "### 카드 한 장 원샷"`와 `"## 3."`만 읽는다(문서 전체는 읽지 않는다). 카드마다 **`make-home-feed-card.mjs` 명령 하나**로 「렌더 → `bundle.json` 작성 → `--dry-run` 형식 검증」을 끝낸다(`홈피드` 프리셋 id `51aa4673-f723-4929-ac20-a302202b7aa7`, `--text01` 제목, `--text02` 요약, `--meta`의 `world_review.winter_reviewed`는 실제로 부른 윈터의 결과). `--dry-run`은 `mission_spotlight`인데 레이아웃이 `large_thumbnail`이 아닌 카드, 제목이 11자를 넘거나 줄바꿈이 있는 경우, 요약이 22자(2줄이면 줄당 15자)를 넘거나 3줄 이상인 경우를 거절한다(티켓 20260927_2035). 출력 한 줄 JSON의 `ok`가 `false`이면 사유를 고쳐 다시 실행하고, 두 번 실패하면 그 카드는 「이미지 준비 대기(사유)」로 둔다. 묶음 폴더는 반드시 `docs/operations/reports/weekly/<YYYY-Www>-images/<묶음 ID>/`다(그 밖에 쓰면 커밋이 차단된다). 이 환경의 `--dry-run`은 DB 읽기 검사(참조 ID 존재·중복)를 「건너뜀」으로 표시하며, 그 사실을 리포트에 그대로 적는다(그 검사는 승인 뒤 메인 세션이 다시 한다). 등록 스크립트를 `--dry-run` 없이 실행하거나 `--undo`를 쓰는 것, 프리셋 생성·수정, DB·스토리지 쓰기는 하지 않는다.
5. 리포트 반영: 표 후보 칸에 `![](./<YYYY-Www>-images/<묶음 ID>/image.png)`와 배경색·끝색·선택 근거를 적는다. 이미지가 장당 2MB를 넘으면 그 파일은 지우고 「이미지 없음(용량 초과)」로 표시한다. 임의 색이나 자리표시 이미지로 채우지 않는다. 실제로 만든 이미지 장수를 센다(6단계 슬랙 안내에 쓴다).

## 3. 전략 변경안·유형 리뷰 (윤진, 모드 ④)
- `curl -s -H "x-admin-read-token: $ADMIN_API_READ_TOKEN" "https://j-a-m.app/api/admin/today/metrics?from=YYYY-MM-DD&to=YYYY-MM-DD"`로 최근 3주를 주 단위로 나눠 조회하고, 유형 ID별 노출·열람으로 「전략 변경안」 절을 쓴다(PRD §10 양식). 3주 연속 신호가 없으면 "관찰 중" 한 줄만 쓴다.
- ISO 주차가 짝수인 주에는 「유형 리뷰 (격주)」 절도 쓴다(PRD §11 양식, 자동 등급 T02·T03·T07·T08·T10·T14). 리뷰 기간에 편성 이력이 없는 유형은 "미편성"으로 적고 판정 대상에서 뺀다. 판정 확정은 세션에서 한다.

## 4. 티켓 초안
명확한 문제는 티켓 파일을 만들지 말고 리포트 '결정 필요' 절에 `[분류 대기 초안]`으로 적는다(우선순위 비움, 기존 티켓과 중복 확인).

## 5. 비용
임시 상한은 15만 토큰이다. 강제로 끊을 수 없으므로, 상한에 가까우면 수집을 멈추고 있는 자료로 마무리한다. '비용' 절에 서브에이전트 결과에 표시된 토큰 사용량을 적고, 알 수 없는 값은 '측정 불가'로 적는다. 2-1 이미지 단계(채원·윈터·윤진 호출)가 더해져 첫 실행은 이 상한을 넘을 수 있다. 넘어도 이미지 단계를 생략하지 말고 실제 사용량을 카즈하·윤진·채원·윈터별로 적는다(4회 실행 뒤 상한을 다시 정한다). 직전 시험 실행(2026-09-26)의 하위 에이전트 합계는 399,572(카즈하 66,889·윤진 171,024+66,010·채원 67,313·윈터 28,336)였다. 이번 실행의 합계를 그 값과 나란히 적는다.

  - 전략 변경안이 생긴 주(「관찰 중」만 있으면 생략)와 유형 리뷰 주에는 각각 안내 글을 따로 올린다.
