# [Admin] 곡선 테스트 1건이 vitest 기본 타임아웃(5초)을 넘겨 verify가 실패한다

## 핵심 요약

- 요구사항: `jam-web/src/lib/asset-generator/__tests__/curve.test.ts`의 「고리가 있든 없든 모든 시드의 완성 경로가 회전 반경 5%·중앙 통과 10% 이상이다」(약 103행)가 클라우드 세션 컨테이너에서 5,284ms로 기본 타임아웃 5,000ms를 넘겨 실패한다. 판정 로직은 통과 쪽이며 느린 것이 원인이다. 테스트를 건너뛰거나 지우지 않고, 원인(시드×불규칙도 전수 반복의 계산량)을 줄이거나 근거를 적어 이 테스트의 타임아웃을 명시한다.
- 구현 계획: 반복 범위·계산 비용을 먼저 재고, 커버리지를 유지하는 선에서 계산을 줄인다. 줄일 수 없으면 `it(..., timeout)`으로 근거와 함께 상한을 준다.
- 관련 파일: `jam-web/src/lib/asset-generator/__tests__/curve.test.ts` 약 103행 테스트, 대상 함수 `jam-web/src/lib/asset-generator/curve.ts`

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 원인: `curve.test.ts` 「큰 고리 구간」 describe의 두 테스트가 같은 시드 50개에 대해 가장 비싼 연산 `pickCandidate`를 각각 다시 계산했다(직접 50회 + `buildPath` 경유 50회). `buildPath`의 내부 캐시는 키(`seed|W|H`)가 시드마다 달라 이 반복에서 재사용되지 않는다. 클라우드 세션 실측 5,060ms·6,236ms.
- 변경: describe 본문(수집 단계, `it()` 타임아웃 대상 아님)에서 `pickCandidate`를 시드당 한 번만 계산해 두 테스트가 공유한다. 둘째 테스트는 `buildPath` 대신 이미 구한 후보로 `sampleFitted`를 직접 부른다. `buildPath`는 `sampleFitted` 출력을 그대로 복사하므로(`xs[i]=fit.xs[i%N]`) 검사하는 값은 이전과 같다.
- 타임아웃 상향·테스트 건너뛰기·커버리지 축소는 하지 않았다(시드 50개 × 불규칙성 2종 = 100건, 판정 기준 그대로).
- `curve.ts`는 `PATH_SAMPLE_POINTS` 상수에 `export`만 더했다(계산·출력 불변, 프리셋·시드 호환). 그에 맞춰 프로토타입 번들을 `build-prototype.mjs`로 다시 생성했다.
