# [Feature] 신규 가입자가 5분 안에 서비스를 직접 눌러 보며 파악하는 온보딩 퀘스트를 도입한다 (상위 티켓)

## 핵심 요약
- 요구사항: 신규 가입자에게 홈 상단 퀘스트 카드로 연출용 데이터 기반의 단계형 체험(동기화→배지→픽업→믹스 실패·성공→드랍→둘러보기)을 제공하고, 실제 첫 Strava 활동 1건 이상이 들어온 시점을 완료로 판정해 온보딩 완료 액티비티 배지(100P)를 지급한다.
- 구현 계획: 하위 티켓을 「작업 분해」 표의 선행 순서(N1 → N2 → N3 → T2c → N4 → T3 → T4 → T5 → T5b → T6 → T7a → T7b → T8 → N5a → N5b → T9)대로 `/jam-work`로 처리한다.
- 관련 파일: `jam-web/src/app/(main)/page.tsx`(L36-38 `strava_disconnected` 타일), `jam-web/src/lib/strava/sync.ts`(L1247 `isFirstSync`, L1264 첫 싱크 최신 1건 제한), `jam-web/src/lib/badge-engine/index.ts`(L1024, L1584 `initial_sync_done` 갱신), `docs/service/prd/01_PRD.md` §2·§3, `docs/service/prd/02_DATA_MODEL.md` §1·§2

## 배경 / 문제 정의
가입 직후 흐름은 아이디·이름 → 트라이브 선택 → Strava 동기화 → 첫 배지 알림에서 끝나고 그다음 안내가 없다(`docs/service/prd/01_PRD.md` §2 시나리오 1). 신규 유저는 배지·포인트·드랍·픽업·믹스가 무엇인지, 무엇이 재미있는지 모른 채 막연한 상태가 된다. 게임 튜토리얼처럼 간단한 행동을 하나씩 직접 해 보게 하는 장치가 필요하다.

## 확정한 결정 (2026-09-27 사용자 문답, 혜린 기획)
1. **방식**: 코치마크(말풍선)·설명 팝업이 아니라 퀘스트 방식으로 하나씩 해 보게 한다.
2. **데이터**: 퀘스트 1~7단계는 전부 연출용 데이터로 진행한다(동기화 포함). 서버에는 단계 진행·완료만 기록한다. 실제 데이터를 만들면 비공개 레시피 폐지(2026-07-27)·드랍 무기한 유지(2026-08-29) 정책과 충돌하고, 배지 컬렉션 수·배지 트리·포인트 유통량 대사 집계가 오염되기 때문이다.
3. **목적**: 현실 행동 유도가 아니라 가입 후 5분 안에 이것저것 눌러 보며 서비스를 파악하게 하는 것. 집/밖 구분은 두지 않는다(POI는 어디서든 반경 500m 안에서 확인 가능).
4. **흐름**
   1. 연출용 Strava 동기화 → 연출용 첫 배지
   2. 가방을 열어 배지 확인
   3. 지도에서 가까운 POI의 연출용 드랍 픽업
   4. 아무 재료로 믹스 → **실패**, 투입한 아이템배지가 소각되는 장면(실제 규칙과 동일: `docs/service/content/COMBINE_RECIPES.md` L28·L84, 성공·실패와 무관하게 재료 소각)
   5. 레시피 확인 → 정확한 재료로 믹스 **성공**. 레시피는 슬롯 2개인 「살롱의 장물 시세」로 고정한다
   6. 믹스 결과물을 POI에 드랍
   7. 미션 목록 또는 트라이브 화면 한 번 열기
   8. 기존 홈의 Strava 미연동 타일(첫 동기화 카드)로 이어져 **실제** 연동
5. **완료 판정**: 실제 첫 동기화로 활동이 **1건 이상 실제로 들어온 시점**. Strava 계정이 없거나 활동이 0건이면 미완료 상태로 남고 카드도 계속 노출된다. `users.initial_sync_done`은 활동 0건이어도 true가 되므로 판정 근거로 쓰지 않는다.
6. **보상**: 온보딩 완료 전용 액티비티 배지 1종(실제 데이터) + 100P. 완료 판정 시점에 지급한다. 100P는 시뮬레이터 미검증이다(계정당 1회).
7. **노출**: 완료할 때까지 홈 상단 카드로 계속 노출한다. 투데이 CMS(`today_cards`) 항목이 아니라 앱에서 유저별로 그리는 컴포넌트다.
8. **건너뛰기**: 허용한다. "이 순간을 넘기면 받을 수 없는 것이 있다"는 뉘앙스로 [계속하기]/[건너뛰기]를 선택하게 한다. 건너뛰면 곧바로 실제 동기화 카드로 넘어가고 완료 배지는 **영구히** 받을 수 없다(재도전 경로 없음).
9. **대상**: 배포 이후 가입한 신규 유저만. 기존 유저에게는 노출하지 않고 소급 지급도 하지 않는다.
10. **문구·세계관**: 중립 톤. 트라이브 목소리는 다음 버전으로 미룬다. 윈터 검수는 신규 완료 배지 이름·설명에만 필요하다.
11. **실제 동기화 지연 안내**: 연출 동기화(즉시)와 실제 동기화(최대 60초)의 차이는 따로 안내하지 않는다.

## 추가 결정 (2026-09-27 구현 착수 후)
12. **진행 방식 A**: 단계는 퀘스트 전용 화면 `/onboarding-quest`에서 진행하고, 실제 서비스의 화면 부품을 연출용 데이터로 재사용한다. 실제 동기화 버튼·인벤토리·지도·믹서 페이지에는 퀘스트 분기를 넣지 않는다. 미채택 B(실제 화면에 연출 분기)는 핵심 화면 네 곳에 분기가 생겨 연출 데이터가 실제 화면에 새어 나갈 위험과 티켓 수 증가 때문에 기각.
13. **홈부터 연출 화면**: 퀘스트 진행 중인 신규 유저의 홈은 연출용 홈이다(실제 홈과 같은 구성에 연출 데이터, 투데이 카드는 실제 컨텐츠). 7단계를 마치거나 건너뛰면 실제 홈으로 바뀐다(T2c). 미채택 (b) 퀘스트 카드만 있는 단순 홈.

## 결정 번복 (2026-09-28 사용자)
결정 12(진행 방식 A)와 13(연출용 홈)을 폐기한다. 사유: 퀘스트 전용 화면은 서비스에 없는 페이지라서, 그 화면을 눌러 봐도 실제 서비스를 익히는 온보딩이 되지 않는다.

14. **실제 메뉴 화면에서 진행**: 각 단계는 해당 기능의 실제 메뉴 화면으로 보내 그 화면의 UI 그대로 진행한다. 예: 인벤토리에 추가하는 단계는 실제 인벤토리 메뉴 UI, 드랍 단계는 가상의 지도 이미지 위에 드랍할 POI를 표시한다.
15. **데이터는 연출용 유지**: 결정 2는 그대로다. 실제 화면에 연출용 데이터를 채우고 DB에는 단계 진행만 기록한다.
16. **별도 화면 제거**: `/onboarding-quest`와 관리자 미리보기 `/onboarding-quest/preview`(T2a·T2b·P에서 staging 머지)는 제거한다. 1~2단계 연출 부품(배지 획득 연출·연출 도토리)은 실제 화면으로 옮긴다.
17. **홈**: 새 홈을 만들지 않는다. 퀘스트 중에는 실제 홈의 동기화 버튼이 1단계 연출 동기화로 동작한다(T2c를 이 작업으로 바꾼다, 사용자 선택 없음 → 카리나 추천안).

## 추가 결정 (2026-09-28 사용자, 결정 14~17 실행 반영)
18. **단계와 실제 화면의 대응**: `sync`=홈(`jam-web/src/app/(main)/page.tsx`의 동기화 버튼, 홈에서만 연출), `bag`=`/inventory`, `pickup`·`drop`=`/drops`(가상 지도 이미지), `mix_fail`·`mix_success`=`/combine`, `browse`=`/missions`만 인정(저장소에 전용 트라이브 화면이 없다).
19. **문지기 함수 하나**: 퀘스트 판정은 문지기 함수 하나(`jam-web/src/lib/onboarding-quest/screen-gate.ts`, 신규)로만 한다. 단계→화면 지도와 "지금 이 화면이 차례인가" 판정을 담는다. 차례가 아니면 null을 돌려주고 화면은 평소 실제 화면 그대로다. 연출 데이터는 클라이언트 전용 상수(`demo-data.ts`)이고, 연출 아이템을 눌러도 실제 API(동기화·픽업·믹스)를 부르지 않고 단계 기록 API `POST /api/onboarding-quest/step`만 부른다.
20. **자동 이동 없음**: 단계를 마치면 홈으로 돌아가고, 홈 퀘스트 카드의 [이어 하기]로 다음 실제 화면에 들어간다.

## 검토한 대안과 미채택 이유
- **코치마크·설명 팝업**: 사용자가 명시적으로 배제했다. 읽게 하는 것보다 직접 해 보게 하는 편이 드랍·픽업·믹스를 빨리 이해시킨다.
- **실제 서비스 위에 나에게만 보이는 드랍·레시피를 얹는 혼합안**: 비공개 레시피 폐지·드랍 회수 없음 정책을 되돌리고, 퀘스트 아이템이 여러 집계에 섞여 제외 처리가 필요해 기각.
- **화면 전체를 복제한 완전 샌드박스**: 화면 이중 관리와 드리프트 때문에 기각. 실제 화면에 연출용 데이터를 채우는 방식으로 대체.
- **미션 테이블 재사용**: 미션은 배지엔진이 활동 데이터 조건만 판정하고 참가 필수·취소 불가라, "기능을 한 번 써 봤는지"를 기록하고 건너뛸 수 있어야 하는 온보딩과 맞지 않아 기각.
- **집/밖 두 챕터 구성**: POI 확인은 어디서든 가능하고 목적이 현실 행동 유도가 아니라서 기각.
- **기존 유저 소급 적용**: 이미 실제 배지·아이템이 있는 유저를 연출용 세계로 되돌리는 흐름이 어색하고 소급 보상 문제가 생겨 기각.
- **건너뛴 유저의 재도전 경로**: "다시 받을 수 없다"는 안내를 거짓으로 만들어 기각.
- **트라이브 목소리 문구·온보딩 전용 신규 아이템**: 세계관 검수 사이클이 늘고, 기존 아이템을 빌려 써야 실제 서비스로 체험이 이어져 기각(다음 버전 후보).
