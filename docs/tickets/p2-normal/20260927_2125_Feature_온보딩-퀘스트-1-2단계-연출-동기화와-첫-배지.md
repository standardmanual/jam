# [Feature] 온보딩 퀘스트 1~2단계: 연출용 동기화로 첫 배지를 받고 가방에서 확인한다 (T2)

## 핵심 요약
- 요구사항: 실제 Strava API를 부르지 않고 동기화 장면과 첫 배지 획득 장면을 재생하고, 가방에서 그 배지를 확인하게 한다.
- 구현 계획: 기존 동기화·배지 획득·가방 화면 컴포넌트에 연출용 데이터를 주입하는 방식. 화면 복제는 하지 않는다.
- 관련 파일: 홈 상단 동기화 버튼(`jam-web/src/app/(main)/layout.tsx` L21 TopNav), 가방 화면(`/inventory`), T1 진행 테이블

## 배경 / 문제 정의
퀘스트의 첫 경험은 JAM!의 핵심 흐름인 동기화 → 배지 획득이다. 실제 연동 전에 이 흐름을 연출로 먼저 보여 준다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 공통 원칙: 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 T1의 진행 테이블에 단계 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 1단계: 퀘스트 카드에서 시작하면 동기화 장면이 재생되고 연출용 첫 배지를 획득한다. 배지는 실제 카탈로그의 기존 액티비티 배지를 빌려 쓴다.
- 2단계: 가방을 열어 그 배지를 확인하면 단계가 완료된다. 연출용 항목에는 퀘스트용임을 알 수 있는 표시를 둔다(형태는 채원 판정).
- 각 단계 완료 시 T1 진행 테이블에 기록한다.

## 구현 계획
채원 사전 판정(연출 주입 방식, 퀘스트 표시 형태) → 연출용 데이터 정의 → 기존 화면 컴포넌트에 주입.

## 완료 조건
- 테스트 계정에서 1단계를 진행해도 Strava API 호출과 `user_activity_badges` 행 생성이 없다.
- 1·2단계를 마치면 진행 테이블에 두 단계의 완료 시각이 기록되고 카드 진행도가 2로 바뀐다.
- 퀘스트를 완료했거나 건너뛴 유저, 기존 유저의 가방에는 연출용 배지가 보이지 않는다.
