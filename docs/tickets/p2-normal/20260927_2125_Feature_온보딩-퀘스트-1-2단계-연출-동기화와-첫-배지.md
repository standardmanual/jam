# [Feature] 온보딩 퀘스트 1~2단계: 연출용 동기화로 첫 배지를 받고 가방에서 확인한다 (T2b)

## 핵심 요약
- 요구사항: 퀘스트 화면(T2a)의 1단계(첫 동기화)와 2단계(인벤토리)에 연출 부품을 꽂는다. 1단계는 동기화 장면 뒤 `BadgeRevealOverlay`로 연출용 배지 획득, 2단계는 `InventoryGrid`로 그 배지를 확인한다. 끝나면 T2a의 단계 기록 API를 부른다.
- 구현 계획: 연출용 데이터 정의(실제 카탈로그의 기존 액티비티 배지 한 종의 이름·이미지를 빌림) → 1단계 부품 → 2단계 부품 → 단계 키 매핑 연결.
- 관련 파일: `jam-web/src/lib/onboarding-quest/demo-data.ts`(신규), `jam-web/src/app/(main)/onboarding-quest/steps/SyncStep.tsx`(신규), `.../steps/InventoryStep.tsx`(신규), `jam-web/src/app/(main)/onboarding-quest/page.tsx`(T2a, 매핑 연결), `jam-web/src/components/BadgeRevealOverlay.tsx`(읽기, props `open`·`loading`·`items`·`moreCount`·`profileHref`·`onClose` L54~65), `jam-web/src/components/inventory/InventoryGrid.tsx`(읽기, `items: InventoryGridItem[]` L11~38)

## 배경 / 문제 정의
퀘스트의 첫 경험은 JAM!의 핵심 흐름인 동기화 → 배지 획득이다. 실제 연동 전에 이 흐름을 연출로 먼저 보여 준다. 원래 T2를 규모 기준 때문에 T2a(`20260927_2330`)와 T2b(이 티켓)로 나눴다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 공통 원칙: 퀘스트 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 단계 완료만 기록한다.
- 진행 방식(2026-09-27 사용자 결정 A): 단계는 퀘스트 전용 화면 `/onboarding-quest`에서 진행하고, 실제 서비스의 화면 부품(배지 획득 연출 `BadgeRevealOverlay`, 인벤토리 그리드 `InventoryGrid`, 지도·믹서 부품)을 연출용 데이터로 재사용한다. 실제 동기화 버튼(`SyncButton.tsx`)·인벤토리 페이지·지도·믹서 페이지 코드는 퀘스트 분기를 넣지 않는다.
- 1단계: 「동기화」를 누르면 짧은 동기화 진행 장면 뒤 `BadgeRevealOverlay`가 연출용 배지 1개로 열린다. 실제 API(`/api/strava/sync`)를 부르지 않는다. 오버레이를 닫으면 `step: 'sync'`를 기록하고 다음 단계로 넘어간다.
- 2단계: `InventoryGrid`에 연출용 배지 1개를 보여 준다. 배지를 한 번 누르면 `step: 'bag'`을 기록한다. 연출용임을 알 수 있는 표시 형태는 채원이 판정한다.
- **확정 문구(2026-09-28 사용자 확정)**
  - 2단계 위치 안내(단계 설명 아래 한 줄, `text-caption`·`text-secondary`): **인벤토리는 아래 탭에 있어요**
  - 2단계 연출 표시(그리드 아래 한 줄, `text-caption`·`text-secondary`): **이 배지는 실제 인벤토리에는 남지 않아요.**
  - 기능 위치만 안내하고, 연출 배지를 나중에 다시 볼 수 있다고 읽히는 문장은 쓰지 않는다. 「연습」이라는 말은 쓰지 않는다(사용자 결정).
- **연출 배지(2026-09-28 사용자 확정)**: 실제 카탈로그의 아이템배지 **「황금빛 도토리」**(id `dde83b16-b888-4bae-878c-fee01813679b`, Common, 숲속의 갱단). 인벤토리에는 아이템배지만 들어가므로 액티비티 배지가 아니라 아이템배지를 쓴다. 이름·이미지는 DB 값을 그대로 복사한다: image_url `https://ceehnkzdbecxwzxrhhns.supabase.co/storage/v1/object/public/images/badges/factions/03-09/03-09-1.png?v=1789303162331`. 이 아이템은 4~5단계 믹스 레시피 「살롱의 장물 시세」의 재료라, 이후 단계(3단계 픽업 「잃어버린 결혼반지」 → 5단계 믹스 「최고급 캣닢 뭉치」)와 이어진다.
- 연출용 배지가 실제 인벤토리 페이지·배지 컬렉션에는 나타나지 않는다(클라이언트 연출 데이터이므로 서버에 없다).

## 구현 계획
채원 사전 판정(연출 표시·위치 안내 문구) → `demo-data.ts` → `SyncStep`·`InventoryStep` → 페이지 매핑 연결 → 테스트.

## 완료 조건

### 주요 의사결정 / 핵심 메모
