# [Feature] 온보딩 퀘스트 3단계: 지도에서 가까운 POI의 연출용 드랍을 픽업한다 (T3)

## 핵심 요약
- 요구사항: 지도의 가까운 실제 POI 위치에 연출용 드랍을 표시하고, 탭하면 픽업 장면과 함께 가방에 연출용 아이템이 들어온다.
- 구현 계획: 지도 화면에 연출용 마커를 주입한다. 실제 `poi_drops`·`pickup_drop()`은 쓰지 않는다.
- 관련 파일: 지도·드랍 화면(`/map`), `pickup_drop()` RPC(참고만, 호출 금지), T1 진행 테이블

## 배경 / 문제 정의
드랍·픽업은 JAM!의 핵심 재미지만 설명만으로는 감이 오지 않는다. 한 번 직접 주워 보게 한다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 공통 원칙: 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 T1의 진행 테이블에 단계 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 가까운 실제 POI 위치에 연출용 드랍 마커를 표시한다. 픽업 대상 아이템은 T4 믹스 실패·성공에 쓸 재료다(「살롱의 장물 시세」 슬롯 재료를 포함).
- 위치 권한을 거부했거나 위치를 얻지 못하면 기본 위치 주변 POI로 대체해 흐름이 막히지 않게 한다.
- 연출용 마커는 다른 유저에게 보이지 않는다(클라이언트 연출이므로 서버에 존재하지 않는다).

## 구현 계획
채원 사전 판정(연출 마커와 실제 드랍 마커의 구분) → 마커 주입 → 픽업 장면 → 진행 기록.

## 완료 조건
- 3단계에서 픽업하면 가방에 연출용 재료가 보이고 진행도가 3으로 바뀐다.
- 픽업 전후로 `poi_drops`·`inventory_items`·`custody_events`에 해당 유저의 행이 생기지 않는다.
- 위치 권한을 거부한 상태에서도 3단계를 끝낼 수 있다.
