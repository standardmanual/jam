# [Feature] 온보딩 퀘스트 3단계: `/drops`의 가상 지도에서 연출용 드랍을 픽업한다 (T3)

## 핵심 요약
- 요구사항: 실제 `/drops` 화면 안에 정적 가상 지도 이미지와 누를 수 있는 POI 하나를 보여 주고, 탭하면 픽업 장면과 함께 가방에 연출용 아이템이 들어온다(결정 21 — 실제 인터랙티브 지도에 마커를 얹지 않는다).
- 구현 계획: `drops/page.tsx`가 N1 문지기 함수로 `pickup` 차례인지 확인 → 맞으면 실제 `MapView`/`DropsClient` 대신(또는 그 위에) 정적 가상 지도 이미지 + 클릭 가능한 POI 1개로 구성된 연출 화면을 보여줌 → 탭하면 픽업 장면 후 단계 기록.
- 관련 파일: `jam-web/src/app/(main)/drops/page.tsx`(L19 `DropsPage`), `jam-web/src/app/(main)/drops/DropsClient.tsx`(L44 `DropsClient`, L14 `MapView`는 `next/dynamic` 지연 로드 — 연출 화면은 이 실제 지도를 그대로 쓰지 않는다), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 읽기), `jam-web/src/lib/onboarding-quest/demo-data.ts`(픽업 연출 아이템 추가 대상 — T4 재료와 공유)

## 배경 / 문제 정의
드랍·픽업은 JAM!의 핵심 재미지만 설명만으로는 감이 오지 않는다. 한 번 직접 주워 보게 한다. 결정 번복(2026-09-28)으로 퀘스트 전용 화면이 없어지고 실제 `/drops` 화면에서 진행하며(결정 14), 지도는 실제 인터랙티브 지도가 아니라 정적 가상 지도 이미지 + POI 1개로 보여 준다(결정 21). 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 공통 원칙: 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 `pickup` 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- `pickup` 차례인 유저가 `/drops`에 들어가면 정적 가상 지도 이미지(실제 `MapView`가 아니다) 위에 클릭 가능한 POI 마커 1개를 보여 준다. 실제 위치 권한·GPS 조회는 필요 없다(가상 지도이므로 위치 획득 실패로 흐름이 막히는 문제 자체가 없다).
- POI를 탭하면 픽업 장면과 함께 연출용 아이템이 가방에 들어온다. 픽업 대상 아이템은 T4 믹스 실패·성공에 쓸 재료다(「살롱의 장물 시세」 슬롯 재료를 포함).
- 탭하면 `POST /api/onboarding-quest/step`({ step: 'pickup' })을 호출한다.
- `pickup`이 차례가 아닌 유저(퀘스트 미대상·다른 단계·완료·건너뜀)는 연출 없이 기존 `/drops` 화면(실제 지도·실제 드랍) 그대로다(결정 22).

## 사용자 결정 (2026-09-28, 채원 1차 사전 판정 후)
1. **픽업 흐름은 실제 서비스 그대로**: 마커 → 실제 `PoiCarouselModal`(POI 캐러셀 모달) → 드랍 아이템 → 픽업. 채원 1차 안(마커를 누르면 `BadgeDetailSheet`로 바로 이동)은 캐러셀 단계를 건너뛰어 채택하지 않았다. 실제 모달에 연출 데이터를 넣는 방식은 채원이 다시 판정한다.
2. **가상 지도 이미지는 사용자가 직접 제작**한다. 이미지가 오기 전까지는 임시 배경(`bg-surface-elevated` 등)으로 구현하고, 이미지 경로를 한 곳의 상수로 두어 파일만 넣으면 교체되게 한다. T5(드랍)와 공용이다.
3. **연출 픽업 아이템은 「잃어버린 결혼반지」**(「살롱의 장물 시세」 슬롯 2 재료)다. 실제 카탈로그 값(이름·이미지·badge id)을 `demo-data.ts`에 글자 단위로 복사한다(황금빛 도토리 관례).
4. **POI 마커**: 이미지 좌하단 1/3 지점, 이름 「근처 드랍 지점」(신규 문구, 게이트에서 한국어 검수). **펄스 모션은 넣지 않는다**(실제 지도 마커와 같이 정지).

## 구현 계획
채원 사전 판정(가상 지도 이미지·POI 배치, 실제 지도 화면과의 전환 방식) → 연출 화면 구현 → 픽업 장면 → 단계 기록.

## 완료 조건
- `pickup` 차례인 테스트 계정이 `/drops`에서 가상 지도의 POI를 탭하면 가방에 연출용 재료가 보이고 진행도가 `pickup`까지 바뀐다.
- 픽업 전후로 `poi_drops`·`inventory_items`·`custody_events`에 해당 유저의 행이 생기지 않는다.
- 위치 권한을 거부하거나 위치를 얻지 못해도 3단계를 끝낼 수 있다(가상 지도는 실제 위치에 의존하지 않는다).
- `pickup`이 차례가 아닌 계정은 실제 지도 화면 그대로다.
