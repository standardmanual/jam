# [Feature] 온보딩 퀘스트 4~5단계: 실제 `/combine` 화면에서 믹스 실패를 겪고 레시피로 성공한다 (T4)

## 핵심 요약
- 요구사항: 4단계는 실제 `/combine` 화면에서 아무 재료로 믹스해 실패하고 투입한 아이템배지가 소각되는 장면을 보여 준다. 5단계는 레시피 「살롱의 장물 시세」를 확인하고 정확한 재료로 성공한다.
- 구현 계획: `combine/page.tsx`/`CombineClient.tsx`가 N1 문지기 함수로 `mix_fail`/`mix_success` 차례인지 확인 → 맞으면 연출용 재료·레시피로 믹스 화면을 채우고, 실제 믹스 API 대신 클라이언트 안 결과 계산으로 성공·실패를 연출한다.
- 관련 파일: `jam-web/src/app/(main)/combine/page.tsx`(L12 `CombinePage`, 실제 재료·레시피 서버 조회), `jam-web/src/app/(main)/combine/CombineClient.tsx`(L75 `CombineClient`, `'use client'`), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 읽기), `jam-doc/planning/content/COMBINE_RECIPES.md` L28·L84·L91, T3의 픽업 연출 재료(공유)

## 배경 / 문제 정의
실제 믹스는 성공·실패와 무관하게 투입한 아이템배지를 소각한다(`COMBINE_RECIPES.md` L84). 사용자는 실패하면 아이템배지를 잃을 수 있다는 점을 튜토리얼에서 강조하기를 원했다. 연출용이라 잃어도 손해가 없으므로 실패를 직접 겪게 한다. 결정 번복(2026-09-28)으로 퀘스트 전용 화면이 없어지고 실제 `/combine` 화면에서 진행한다(결정 14). 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 공통 원칙: 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 `mix_fail`·`mix_success` 완료를 각각 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 4단계(`mix_fail` 차례): 실제 `/combine` 화면에서 레시피와 맞지 않는 연출용 재료로 믹스하면 실패하고, 투입한 연출용 아이템이 사라지는 장면과 함께 "실패하면 넣은 아이템배지를 잃는다"는 사실을 강조한다(문구는 채원 확정). 실패해도 실제 `combination_recipes`·`user_combine_fail_logs`에 쓰지 않는다. 성공하면 `POST /api/onboarding-quest/step`({ step: 'mix_fail' })을 호출한다.
- 5단계(`mix_success` 차례): 레시피 탐색에서 「살롱의 장물 시세」를 확인한 뒤, 정확한 연출용 재료로 믹스하면 성공하고 결과물 아이템을 받는다. 성공하면 `POST /api/onboarding-quest/step`({ step: 'mix_success' })을 호출한다.
- 4단계에서 재료를 잃어도 5단계를 할 수 있도록, 픽업(T3)에서 충분한 연출용 재료를 준다.
- `mix_fail`·`mix_success`가 차례가 아닌 유저(퀘스트 미대상·다른 단계·완료·건너뜀)는 연출 없이 기존 `/combine` 화면(실제 재료·실제 레시피) 그대로다(결정 22).

## 구현 계획
채원 사전 판정(실패·성공 연출, 실제 `CombineClient` 재사용 범위) → 연출 재료·결과 정의 → `combine/page.tsx`/`CombineClient.tsx` 분기 → 진행 기록.

## 완료 조건
- `mix_fail` 차례인 테스트 계정이 `/combine`에서 투입한 연출용 아이템이 가방에서 사라지고, 실패로 아이템을 잃는다는 안내가 화면에 보인 뒤 진행도가 `mix_fail`까지 바뀐다.
- `mix_success` 차례에서 「살롱의 장물 시세」 결과물을 받고 진행도가 `mix_success`까지 바뀐다.
- 4·5단계 동안 `combine` 관련 테이블(`user_combine_fail_logs` 포함)과 `point_transactions`에 해당 유저의 행이 생기지 않는다.
- `mix_fail`·`mix_success`가 차례가 아닌 계정은 실제 `/combine` 화면 그대로다.
