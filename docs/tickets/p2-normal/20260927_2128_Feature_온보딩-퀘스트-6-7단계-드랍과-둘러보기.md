# [Feature] 온보딩 퀘스트 6단계: 실제 `/drops` 가상 지도에 믹스 결과물을 드랍한다 (T5)

## 핵심 요약
- 요구사항: 6단계는 믹스 결과물을 `/drops`의 가상 지도 POI에 드랍하는 장면을 보여 준다. 7단계(미션 둘러보기)는 이 티켓에서 분리해 `T5b`(`20260928_0139`)로 옮겼다 — 저장소에 전용 트라이브 화면이 없어 `/missions`만 인정하기로 했기 때문이다(결정 18).
- 구현 계획: T3(픽업)와 같은 `/drops` 가상 지도·POI 부품을 재사용해, `drop` 차례일 때 믹스 결과물을 그 POI에 놓는 연출로 전환한다(결정 21 — 실제 인터랙티브 지도에는 마커를 얹지 않는다).
- 관련 파일: `jam-web/src/app/(main)/drops/page.tsx`(L19 `DropsPage`), `jam-web/src/app/(main)/drops/DropsClient.tsx`(L44 `DropsClient`), T3의 가상 지도·POI 연출 부품(재사용), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 읽기)

## 배경 / 문제 정의
내가 만든 아이템을 세상에 내려놓는 드랍으로 연출 구간의 마지막 "행동" 단계를 마무리한다. 결정 번복(2026-09-28)으로 퀘스트 전용 화면이 없어지고 실제 `/drops` 화면에서 진행하며(결정 14), 7단계는 실제 화면이 없는 트라이브 대신 `/missions`만 인정하기로 하면서 별도 티켓(T5b)으로 분리했다(결정 18). 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 공통 원칙: 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 `drop` 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- `drop` 차례인 유저가 `/drops`에 들어가면 T3와 같은 정적 가상 지도 이미지 + POI 1개를 보여 준다(같은 화면·부품을 재사용하되 이번엔 "드랍" 동작으로 구분).
- POI에 드랍하면 믹스 결과물(연출용 아이템)이 가방에서 빠지고 지도에 놓인 장면을 보여 준다. 실제 `poi_drops`는 만들지 않는다.
- 드랍하면 `POST /api/onboarding-quest/step`({ step: 'drop' })을 호출한다.
- `drop`이 차례가 아닌 유저(퀘스트 미대상·다른 단계·완료·건너뜀)는 연출 없이 기존 `/drops` 화면 그대로다(결정 22).

## 구현 계획
T3의 가상 지도·POI 부품을 재사용해 드랍 연출로 확장 → 화면 진입 판정(N1) → 연출 데이터 정리 → 진행 기록.

## 완료 조건
- `drop` 차례인 테스트 계정이 `/drops`의 가상 지도 POI에 드랍하면 가방에서 연출용 결과물이 빠지고 진행도가 `drop`까지 바뀐다.
- 드랍 동안 `poi_drops`·`inventory_items`에 해당 유저의 행이 생기지 않는다.
- `drop`이 차례가 아닌 계정은 실제 `/drops` 화면(실제 지도·실제 드랍) 그대로다.
