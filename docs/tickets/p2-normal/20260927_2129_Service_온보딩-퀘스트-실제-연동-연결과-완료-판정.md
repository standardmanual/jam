# [Service] 온보딩 퀘스트를 실제 Strava 연동으로 잇고, 활동이 1건 이상 들어온 시점을 완료로 판정한다 (T6)

## 핵심 요약
- 요구사항: 연출 구간 종료(또는 건너뛰기) 뒤 기존 Strava 미연동 타일로 이어지고, 실제 동기화에서 활동이 1건 이상 처리된 시점에 퀘스트를 완료로 기록한다.
- 구현 계획: 완료 판정 함수 하나(`recordOnboardingQuestCompletion`)를 두고 두 곳에서 부른다. ① 동기화에서 새 활동이 1건 이상 처리됐을 때(`syncStravaActivities`, 연동 직후·수동 공통) ② 7단계(`browse`)를 기록한 직후. 조건은 "완료 미기록 + (7단계 완료 또는 건너뜀) + 처리된 실제 활동 1건 이상"이다(사용자 결정 1·2, 2026-09-28). `initial_sync_done`은 쓰지 않는다.
- 관련 파일: `jam-web/src/lib/strava/sync.ts`(L1190 `syncStravaActivities`, L1276 `processFetchedActivities` 호출 직후·L1292 `synced: rawActivities.length` 반환 직전), `jam-web/src/app/api/onboarding-quest/step/route.ts`(L64-77 단계 기록 직후), `jam-web/src/lib/onboarding-quest/completion.ts`(신규), `jam-web/src/lib/onboarding-quest/status.ts`(L29 `completed_at`이면 카드 숨김, 읽기), `jam-web/src/lib/onboarding-quest/config.ts`(`ONBOARDING_QUEST_ENABLED`·`ONBOARDING_QUEST_STEPS`, 읽기)

## 배경 / 문제 정의
퀘스트는 실제 첫 활동을 가져오는 순간 끝나야 한다. `users.initial_sync_done`은 새 활동이 0건이어도 첫 동기화를 실행하기만 하면 true가 되므로(`badge-engine/index.ts` L1024·L1584) 완료 판정에 쓸 수 없다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 공통 원칙: 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 T1의 진행 테이블에 단계 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 7단계를 마쳤거나 건너뛴 유저의 홈 카드는 기존 Strava 미연동 타일로 이어진다. 새 진입점을 만들지 않는다.
- 완료 판정: 실제 동기화에서 처리된 활동 수가 1 이상일 때만 완료로 기록한다. Strava 계정이 없어 연동하지 못했거나 활동이 0건이면 미완료로 남고 카드도 유지된다.
- 이후 첫 활동이 들어오는 동기화(수동·자동 Cron 모두)에서 완료로 기록된다.
- 완료 기록은 한 번만 남는다(중복 동기화에도 멱등).
- 건너뛴 유저도 완료 시각은 기록하되, 보상 대상 여부는 T7이 건너뛰기 기록으로 판정한다.

## 사용자 결정 (2026-09-28, 카리나 코드 확인 후)
1. **건너뛴 유저도 완료 시각을 기록한다.** 티켓 핵심 요약의 "건너뛰지 않았으면 기록"과 상세 요구사항의 "건너뛴 유저도 기록"이 충돌했다. 컬럼 정의(`completed_at` = 실제 첫 활동 유입 시각, 마이그레이션 195)와 상위 티켓 참고 지표(완료 유저와 건너뛴 유저의 1주 행동 비교)에 맞춰 기록 쪽으로 확정했다. 보상 제외는 T7이 `skipped_at`으로 판정한다.
2. **연출 도중 연동으로 들어온 활동은 7단계를 마친 순간 완료로 친다.** 상단 메뉴(`TopNav.tsx` L151)·`StravaStatusCard.tsx`에서 퀘스트 도중에도 연동할 수 있다. 도중에 완료를 기록하면 `status.ts` L29가 홈 퀘스트 카드를 숨겨 남은 단계를 진행할 수 없으므로, 도중에는 기록하지 않는다. 대신 7단계(`browse`) 기록 직후에 이미 처리된 실제 활동이 있으면 그 자리에서 완료를 기록한다(다음 새 활동까지 기다리지 않음). 건너뛰기 시점의 같은 처리는 T8(`20260927_2131`)에서 같은 함수를 호출해 넣는다.
   - 미채택: 다음 새 활동 때 완료(며칠 대기 발생), 도중에도 즉시 완료(남은 단계 진행 불가).

### 카리나 코드 확인 결과 (2026-09-28)
- **자동 동기화 Cron은 없다.** `vercel.json` crons는 poi-cleanup·notifications·ambient-drop·external-inputs뿐이고 Strava 웹훅 라우트도 없다. 활동 유입 경로는 `/api/strava/callback`(연동 직후 첫 동기화, L90)과 `/api/strava/sync`(수동, L26) 두 개이며, 둘 다 `syncStravaActivities`를 부른다. 완료 조건의 "Cron 경로"는 "연동 직후 첫 동기화 경로"로 바꿨다.
- **"실제 연동으로 잇기"는 이미 구현돼 있다.** 7단계를 마쳤거나 건너뛴 유저의 홈 퀘스트 카드는 `awaiting_sync` 상태로 `/api/strava/auth` 링크를 보여 준다(`status.ts` L41, `OnboardingQuestCard.tsx` L92). 이 티켓의 실제 작업은 완료 기록이다.

## 구현 계획
완료 판정 지점 선정(수동·연동 직후 공통 경로) → 멱등 기록 → 단위 테스트(0건·1건·중복 동기화·도중 연동).

### 파일 단위 계획 (예상 5개 파일·약 150줄 — 테스트 포함)
1. `jam-web/src/lib/onboarding-quest/completion.ts`(신규)
   - 순수 함수 `shouldRecordQuestCompletion(row, hasProcessedActivity)`: 행 없음 → false, `completed_at` 있음 → false(멱등), 7단계 미완료이고 `skipped_at`도 없음 → false(결정 2), 처리된 활동 0건 → false, 그 외 true. 7단계 완료 판정은 `nextStepOf(step_progress) === null`(`progress.ts`)을 재사용한다.
   - `recordOnboardingQuestCompletion(supabase, userId)`: `ONBOARDING_QUEST_ENABLED`가 꺼져 있으면 즉시 반환. `user_onboarding_quests`에서 `step_progress, skipped_at, completed_at` 조회 → 활동 조건 외 조건이 안 맞으면 반환(활동 조회 생략) → `strava_activities`에서 해당 유저 행 존재 여부를 1건 조회(`select('id').eq('user_id').limit(1)`) → 순수 함수가 true면 `update({ completed_at: now }).eq('user_id', userId).is('completed_at', null)`(동시 실행에도 한 번만 기록). **절대 throw하지 않는다** — 오류는 `console.error`만 남긴다(동기화·단계 기록 흐름을 막지 않음).
2. `jam-web/src/lib/strava/sync.ts` `syncStravaActivities`: L1276 `processFetchedActivities` 호출 뒤, `rawActivities.length >= 1`이면 `await recordOnboardingQuestCompletion(supabase, userId)`. 0건이면 호출하지 않는다. `processFetchedActivities` 내부(백필 경로도 쓰는 함수)는 건드리지 않는다.
3. `jam-web/src/app/api/onboarding-quest/step/route.ts`: L69 이후 `step_progress` 갱신에 성공했고 `step`이 마지막 단계(`ONBOARDING_QUEST_STEPS`의 마지막, 현재 `browse`)면 `await recordOnboardingQuestCompletion(serviceClient, user.id)`. 응답 형식은 바꾸지 않는다.
4. 테스트 `jam-web/src/lib/onboarding-quest/__tests__/completion.test.ts`(신규): 순수 함수 — 활동 0건 false, 7단계 완료+활동 1건 true, 이미 완료 false(재실행 멱등), 도중(4단계)+활동 1건 false, 건너뜀+활동 1건 true, 행 없음 false.
5. T8 티켓 `docs/tickets/p2-normal/20260927_2131_UI_온보딩-퀘스트-건너뛰기-선택-화면.md`에 "건너뛰기 기록 직후 `recordOnboardingQuestCompletion` 호출" 요구사항 한 줄 추가(결정 2).
- 문서: 온보딩 퀘스트 관련 PRD가 있으면 완료 판정 규칙을 반영한다(아현 판단, 없으면 갱신안 없음).

## 완료 조건
- 활동이 0건인 테스트 계정은 동기화 후에도 완료로 기록되지 않는다.
- 활동이 있는 계정은 첫 동기화 직후 완료 시각이 기록되고, 같은 동기화를 다시 실행해도 기록이 바뀌지 않는다.
- 연동 직후 첫 동기화(`/api/strava/callback`) 경로에서 첫 활동이 들어와도 완료로 기록된다.
- 7단계를 마치기 전에 활동이 들어온 계정은 그 시점엔 완료로 기록되지 않고, 7단계(`browse`) 기록 직후 완료로 기록된다.
- 0건·1건·재실행·도중 연동·건너뜀 경우를 다루는 테스트가 통과한다.
