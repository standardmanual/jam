# [Service] 온보딩 퀘스트 완료 시 온보딩 완료 액티비티 배지와 100P를 지급한다 (T7)

## 핵심 요약
- 요구사항: T6 완료 판정 시점에, 건너뛰지 않은 유저에게 신규 온보딩 완료 액티비티 배지 1개(point_reward 100)를 실제로 지급한다.
- 구현 계획: 배지 행 등록(DB 변경, 승인 후 메인 세션 실행) → `condition_json`에 보상 전용 플래그를 두고 배지엔진 자동 발급 후보에서 제외 → 완료 기록 시 한 번만 지급.
- 관련 파일: `docs/specs/badge-engine/CONDITION_JSON_SPEC.md` L352(`mission_reward` 선례), `jam-doc/planning/content/ACTIVITY_BADGES.md`, `award_points()` RPC, T6 완료 판정 지점

## 배경 / 문제 정의
완료 보상은 크지 않아도 된다는 결정에 따라 100P가 담긴 서비스 전용 액티비티 배지 1종을 지급한다. 보상으로만 받는 배지는 `mission_reward: true` 선례가 있다(`CONDITION_JSON_SPEC.md` L352). 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 공통 원칙: 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 T1의 진행 테이블에 단계 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 신규 액티비티 배지 1종: 이름·설명은 윈터 검수를 거친다. `point_reward`는 100이다(시뮬레이터 미검증, 계정당 1회).
- 보상 전용 플래그(예: `onboarding_reward: true`)를 `condition_json`에 두고, 배지엔진은 `mission_reward`와 같이 항상 fail + 발급 후보 조회에서 제외한다. `CONDITION_JSON_SPEC.md`와 `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md`를 함께 갱신한다.
- 지급 조건: T6 완료 기록 + 건너뛰기 기록 없음. 한 유저에게 한 번만 지급한다(진행 테이블의 보상 지급 시각으로 멱등 보장).
- 지급된 배지는 실제 동기화로 받은 배지와 함께 첫 배지 획득 알림에 포함한다(표시 방식은 채원 판정).
- 어드민 배지 목록에서 온보딩 전용임을 구분할지 이 티켓에서 정한다.

## 구현 계획
윈터 검수(이름·설명) → 배지 행 등록 SQL 작성 → 사용자 승인 후 메인 세션 실행 → 엔진 제외 처리 → 지급 로직 → 컨텐츠·배지엔진 문서 갱신.

## 완료 조건
- 건너뛰지 않은 테스트 계정이 첫 활동을 동기화하면 완료 배지 1개와 `point_transactions`의 100P 1건이 생긴다.
- 같은 계정에서 동기화를 다시 실행해도 배지·포인트가 추가로 생기지 않는다.
- 건너뛴 계정은 첫 활동을 동기화해도 완료 배지를 받지 않는다.
- 활동 조건만으로는 이 배지가 발급되지 않는다(엔진 후보 제외 테스트).
- `ACTIVITY_BADGES.md`·`CONDITION_JSON_SPEC.md`·`BADGE_ENGINE_UNIFIED.md`에 새 배지와 플래그가 반영돼 있다.
