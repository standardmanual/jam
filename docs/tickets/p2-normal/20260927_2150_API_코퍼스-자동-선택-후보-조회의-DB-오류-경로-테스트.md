# [API] 코퍼스 자동 선택 후보 조회의 DB 오류 경로 테스트를 더한다

## 핵심 요약

- 요구사항: `listActiveTribeIds`·`listActiveItemBookIds`·`listActiveBadgeIds`가 DB 오류를 던질 때의 경로가 검증되지 않는다. 기존 목의 `forceErrorTable`은 `.select().in()` 체인만 흉내 내고, 자동 선택 경로가 쓰는 `.select().eq()`·`.select().is().or().or()` 체인은 오류를 재현하지 못한다.
- 구현 계획: 테스트만 추가한다. 테스트가 결함을 드러내면 같은 티켓에서 고친다.
- 관련 파일: `jam-web/src/lib/content-corpus/active.ts` 약 129~172행, 목 `jam-web/src/lib/content-corpus/__tests__/content-corpus.test.ts` 약 28~110행

## 배경 / 문제 정의

2026-09-27 `/jam-ship` 5단계 병렬 점검(민지 모드 ③, 범위 `origin/main..origin/staging` = 2c7e909..b491fbe)의 테스트 공백 발견물이다. 승격을 막지 않는 항목이라 범위 밖 발견물 규칙(`jam-work` SKILL 3.2절)으로 티켓화했다. 원 티켓: 20260927_2034·2035·2036.

## 완료 조건

- 세 함수 각각 DB 오류 시 예외가 `selectCorpusForType`까지 올라가고 라우트가 일반 500 응답을 낸다(단위 테스트).
- `scripts/verify.sh`가 통과한다.

- `jam-web/src/lib/content-corpus/__tests__/content-corpus.test.ts`의 `forceErrorTable` 목을 `.select().in()`만 흉내 내던 형태에서, 어떤 메서드를 불러도 자기 자신을 돌려주는 체인(`errorChain`: in·eq·is·or·order·range)으로 넓혔다.
