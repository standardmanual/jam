# [Feature] 퀘스트 sync 차례일 때 홈 동기화 버튼이 연출 동기화로 동작한다 (T2c)

## 핵심 요약
- 요구사항: 퀘스트 진행 중이고 `sync`가 다음 차례인 유저가 홈에서 동기화 버튼을 누르면, 실제 `/api/strava/sync`를 부르지 않고 연출 동기화(스피너 → `BadgeRevealOverlay` + `DEMO_SYNC_REVEAL_BADGE`)로 동작한다. 오버레이를 닫으면 `sync` 단계를 기록한다. **홈에서만 연출하고**, 다른 화면의 동기화 버튼은 항상 실제 동작이다(결정 18).
- 구현 계획: 홈(`page.tsx`)이 N1 문지기 함수로 `sync` 차례인지 확인 → 맞으면 TopNav 중앙 슬롯의 실제 `SyncButton` 대신 연출 동기화 부품을 렌더 → 오버레이 닫힘 시 단계 기록 API 호출.
- 관련 파일: `jam-web/src/app/(main)/page.tsx`(L63 `<TopNav logo />`), `jam-web/src/components/ui/TopNav.tsx`(L86 `TopNav` 정의, L148-166 `centerSlot`이 `stravaConnected` 여부로 `SyncButton` 또는 연동 유도 버튼을 렌더), `jam-web/src/components/SyncButton.tsx`(L34-120, 연출이 흉내 낼 실제 버튼·오버레이 패턴), 옛 `onboarding-quest/steps/SyncStep.tsx`(N2에서 삭제 대상, L26-76 이식할 스피너·오버레이 로직), `jam-web/src/lib/onboarding-quest/demo-data.ts`(L20-26 `DEMO_SYNC_REVEAL_BADGE`, 읽기), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 읽기)

## 배경 / 문제 정의
결정 번복(2026-09-28)으로 "연출용 홈" 전체를 새로 그리는 접근(결정 13, 폐기)을 버리고, 실제 홈 화면은 그대로 둔 채 동기화 버튼 하나만 퀘스트 차례일 때 연출로 바꾼다(결정 17). 옛 T2c는 「오늘의 현황」·최근 배지 영역까지 연출 값으로 채우는 접근이었으나, 전용 화면과 함께 폐기된 "연출용 홈" 개념의 일부였다. 새 결정은 실제 홈의 실제 데이터(오늘의 현황·투데이 카드)는 손대지 않고, 동기화 버튼의 동작만 바꾼다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `jam-web/src/lib/onboarding-quest/step-error.ts` L4 주석이 삭제된 `StepRunner.tsx`를 예시로 든다. 이 티켓에서 `StepSaveFailedError`를 재사용할 때 주석을 실제 호출부 기준으로 고친다(N2 `20260928_0135` 범위 밖 발견물).
- 공통 원칙: 연출용 데이터다. `user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 `sync` 완료만 기록한다.
- 홈(`page.tsx`)이 N1 문지기 함수로 `sync` 차례인지 확인한다. 맞으면 TopNav 중앙 슬롯에 연출 동기화 부품을 렌더한다 — 실제 `SyncButton`과 같은 모양(버튼 스피너 → `BadgeRevealOverlay`)이지만 `/api/strava/sync`를 부르지 않고, 연출 배지는 `DEMO_SYNC_REVEAL_BADGE` 하나로 고정한다(옛 `SyncStep.tsx` L26-76의 스피너 타이밍·오버레이 호출 로직을 그대로 이식).
- 오버레이를 닫으면 `POST /api/onboarding-quest/step`({ step: 'sync' })을 호출한다. 실패 시 토스트는 옛 `SyncStep.tsx`의 `StepSaveFailedError`/공통 네트워크 오류 문구 패턴을 재사용한다.
- 홈에서만 연출한다: `TopNav`는 여러 화면에서 공통으로 렌더되므로(L86 `TopNav` 정의), 연출 부품 교체는 `page.tsx`가 TopNav에 넘기는 값(예: 새 slot override prop, 또는 홈만 자체 헤더 구성)으로 한정하고, `TopNav.tsx`가 다른 화면에서도 항상 동기화 차례를 검사하게 만들지 않는다.
- `sync`가 차례가 아닌 유저(퀘스트 미대상·다른 단계·완료·건너뜀)의 홈은 기존과 동일하게 실제 동기화 버튼이다(결정 22).

### UI/UX 관점 (해당 시)
- TopNav 연결 방식(새 prop 추가 vs 홈 전용 헤더 구성)과 연출 버튼의 정확한 표시는 채원 사전 판정을 따른다.

## 구현 계획
채원 사전 판정(2026-09-28, 승인 항목 1건 사용자 승인: sync 차례에는 Strava 연동 여부와 무관하게 상단 바 중앙에 연출 동기화 버튼만 보이고 연동 유도 버튼은 가린다)에 따른 파일 단위 계획. 예상 규모는 파일 6개, 테스트 포함 약 170줄이다.

4. `jam-web/src/lib/onboarding-quest/step-error.ts`(L4 주석 2줄): 삭제된 `StepRunner.tsx` 대신 `OnboardingSyncButton.tsx`를 예시로 든다.
5. `jam-web/src/app/(main)/OnboardingSyncButton.test.tsx`(신규, 약 50줄), 필요 시 `TopNav` override 분기 테스트: 버튼 라벨·override 적용 시 연동 유도 버튼 미렌더.

## 완료 조건
- `sync` 차례인 테스트 계정이 홈에서 동기화 버튼을 누르면 연출 배지 1장이 뜨고, 닫으면 진행도가 `sync`까지 기록된다.
- 이 동안 `/api/strava/sync` 요청이 발생하지 않고 `user_activity_badges`·`point_transactions`에 해당 유저의 행이 생기지 않는다.
- `sync`가 차례가 아닌 계정, 그리고 인벤토리·드랍·믹서·미션 등 다른 화면의 동기화 버튼은 항상 실제 동작이다.
- 테스트와 `scripts/verify.sh`가 통과한다.
