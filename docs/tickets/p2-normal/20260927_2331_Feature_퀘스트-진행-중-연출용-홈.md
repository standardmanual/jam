# [Feature] 퀘스트 진행 중인 신규 유저의 홈을 연출용 홈으로 보여 준다 (T2c)

## 핵심 요약
- 요구사항: 퀘스트 진행 중(행 있음·건너뛰지 않음·7단계 미완료·스위치 켜짐)이면 홈의 「오늘의 현황」과 최근 배지 영역을 연출용 데이터로 채운다. 퀘스트에서 획득한 연출 배지가 최근 배지에 나타난다. 투데이 카드(에디토리얼)는 실제 컨텐츠 그대로다. 7단계를 마치거나 건너뛰면 실제 홈으로 바뀐다.
- 구현 계획: 연출용 홈 데이터 함수(진행 단계 → 오늘의 현황·최근 배지 값) → `page.tsx`에서 퀘스트 진행 중이면 이 값을 기존 부품에 넘김 → 테스트.
- 관련 파일: `jam-web/src/app/(main)/page.tsx`(L29~48 병렬 조회·`leftStatus`/`rightStatus`), `jam-web/src/app/(main)/TodayStatusStrip.tsx`(L130 `Props { left, right }`, 읽기), `jam-web/src/lib/onboarding-quest/demoHome.ts`(신규), `jam-web/src/lib/onboarding-quest/demo-data.ts`(T2b, 읽기), `jam-web/src/lib/onboarding-quest/status.ts`(읽기)

## 배경 / 문제 정의
사용자 결정(2026-09-27): 「퀘스트 카드가 노출되는 홈부터 연출 화면」이다. 퀘스트를 하는 동안 실제 홈의 생김새를 미리 익히고, 퀘스트에서 한 행동이 홈에 바로 반영되게 한다(선택지 (a)). 기획 전문은 상위 티켓 `20260927_2123`.

## 상세 요구사항
- 공통 원칙: 퀘스트 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 단계 완료만 기록한다.
- 진행 방식(2026-09-27 사용자 결정 A): 단계는 퀘스트 전용 화면 `/onboarding-quest`에서 진행하고, 실제 서비스의 화면 부품(배지 획득 연출 `BadgeRevealOverlay`, 인벤토리 그리드 `InventoryGrid`, 지도·믹서 부품)을 연출용 데이터로 재사용한다. 실제 동기화 버튼(`SyncButton.tsx`)·인벤토리 페이지·지도·믹서 페이지 코드는 퀘스트 분기를 넣지 않는다.
- 연출용 홈은 실제 홈과 같은 구성이다. 부품을 새로 만들지 않고 기존 `TodayStatusStrip` 등에 연출용 값을 넘긴다.
- 최근 배지: `sync` 단계를 마친 뒤부터 연출용 배지(T2b `demo-data.ts`)가 보인다.
- 오늘의 현황: 퀘스트 진행 단계에 맞춘 연출 값(구체 값은 채원 판정).
- 투데이 카드: 실제 CMS 컨텐츠 그대로 둔다.
- 7단계 완료 또는 건너뛰기 뒤에는 실제 홈(실제 데이터 + Strava 동기화 카드)으로 바뀐다. 기존 유저·행 없는 유저는 영향이 없다.

## 구현 계획
채원 사전 판정(연출 값) → `demoHome.ts` → `page.tsx` 분기 → 테스트. 파일 단위 계획(2026-09-28 카리나, 테스트 포함 약 120줄·파일 3개):

1. `jam-web/src/lib/onboarding-quest/demoHome.ts`(신규, 약 50줄): 순수 함수 `buildDemoHomeStatus(progress)` → `{ left: TodayLeftStatus; right: TodayRightStatus }`. `progress`는 `progress.ts`의 `OnboardingQuestProgress`. `sync` 단계 완료 여부로 좌측 셀 값을 가르고, 연출 배지 이름은 `demo-data.ts`의 `DEMO_SYNC_REVEAL_BADGE.name`을 쓴다. 값·링크는 채원 판정을 따른다(링크는 실제 화면이 아니라 `/onboarding-quest`로 보낸다).
2. `jam-web/src/app/(main)/page.tsx`(L29~48, 약 15줄): 기존 `getOnboardingQuestCard` 결과가 `kind: 'in_progress'`일 때만 `TodayStatusStrip`에 `buildDemoHomeStatus` 값을 넘긴다. 진행 상태를 얻기 위해 DB 조회를 추가하지 않는다 — 필요하면 `status.ts`의 `in_progress` 상태에 `progress`(또는 `doneSteps`)를 실어 보낸다(`status.ts` L12·L33 수정, 기존 `status.test.ts` 기대값 갱신). 투데이 카드(`getTodayCards`)는 그대로 둔다.
3. `jam-web/src/lib/onboarding-quest/__tests__/demoHome.test.ts`(신규, 약 50줄): `sync` 전·후 값, 7단계 전 단계별 값.

가정(2026-09-28, 사용자에게 공유): 현재 홈에는 「최근 배지」 영역이 없다. 새 영역을 만들지 않고, 연출 배지는 「오늘의 현황」 좌측 셀로 반영한다(결정 13 「실제 홈과 같은 구성」). 채원 판정에서 달리 정하면 그 판정을 따른다.

## 완료 조건
- 퀘스트 진행 중 테스트 계정의 홈에서 오늘의 현황·최근 배지가 연출 값으로 보이고, 투데이 카드는 실제 컨텐츠다.
- `sync` 단계 전에는 최근 배지에 연출 배지가 없고, 끝낸 뒤에는 보인다.
- 7단계 완료·건너뛰기·행 없음·스위치 꺼짐 계정은 실제 홈이 보인다.
- 연출 값 계산 테스트와 `scripts/verify.sh`가 통과한다.
