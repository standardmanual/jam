# [Feature] 온보딩 퀘스트를 언제든 처음부터 테스트해 볼 수 있는 미리보기 URL을 만든다

## 핵심 요약
- 요구사항: 관리자 계정이 `/onboarding-quest/preview`에 들어가면 기능 스위치·퀘스트 대상 여부·저장된 진행과 관계없이 1단계부터 퀘스트를 실행해 볼 수 있다. 진행은 서버에 저장하지 않고, 「처음부터 다시」로 언제든 초기화한다(2026-09-28 사용자 요청).
- 구현 계획: 단계 부품(`SyncStep`·`InventoryStep`)이 단계 완료 처리를 직접 하지 않고 `onComplete` 콜백을 받도록 바꾼다. 실제 화면은 기존처럼 API 기록 + `router.refresh()`를 넘기고, 미리보기 화면은 화면 안 상태만 다음 단계로 넘기는 콜백을 넘긴다.
- 관련 파일: `jam-web/src/app/(main)/onboarding-quest/preview/page.tsx`(신규, 관리자 판정 후 클라이언트 부품 렌더), `jam-web/src/app/(main)/onboarding-quest/preview/QuestPreviewClient.tsx`(신규, 단계 상태·처음부터 다시), `jam-web/src/app/(main)/onboarding-quest/steps/SyncStep.tsx`(L23 `SyncStep`, L41~50 fetch·refresh → `onComplete`), `.../steps/InventoryStep.tsx`(L18, L27~36 같은 방식), `jam-web/src/app/(main)/onboarding-quest/page.tsx`(L16 `STEP_COMPONENTS`, API 기록 콜백 전달), `jam-web/src/lib/admin/auth.ts`(L32 `hasAdminAccess`·L43 `getAdminUser`, 읽기)

## 배경 / 문제 정의
퀘스트는 기능 스위치가 꺼져 있고 신규 가입자에게만 한 번 열리며, 단계 기록은 되돌릴 수 없다. 그래서 개발 중에도, 스위치를 켠 뒤에도 같은 계정으로 퀘스트를 반복해서 확인할 방법이 없다. T2b의 클릭 흐름(스피너 → 배지 획득 연출 → 단계 전환)도 자동 테스트로 확인하지 못했다.

## 상세 요구사항
- 경로: `/onboarding-quest/preview`. 이후 단계(T3~T5)가 부품을 추가하면 미리보기에도 자동으로 나타나야 한다(단계 키 → 부품 매핑을 한곳에서 공유).
- 접근: 관리자 계정만(`jam-web/src/lib/admin/auth.ts` 기존 판정 재사용). 관리자가 아니면 홈으로 보낸다. 기능 스위치(`ONBOARDING_QUEST_ENABLED`)와 `user_onboarding_quests` 행 유무는 보지 않는다.
- 저장: 미리보기는 `POST /api/onboarding-quest/step`을 부르지 않고 DB에 아무것도 쓰지 않는다. 진행 상태는 화면 안 상태로만 둔다(새로고침하면 1단계부터).
- 화면: 실제 퀘스트 화면과 같은 구성(표시 전용 상단 바, n/7·타이틀·설명 헤더, 단계 부품). 화면 위쪽에 미리보기임을 알리는 작은 표시와 「처음부터 다시」 버튼을 둔다. 모든 단계를 마치면 마지막 상태(부품이 없는 단계 포함)를 보여 주고 「처음부터 다시」로 돌아갈 수 있다. 문구는 채원 사전 판정에서 정한다(관리자 전용 화면이라 사용자 확정은 필요 없다).
- 부품이 아직 없는 단계(3~7단계)는 빈 자리와 함께 「다음 단계」 버튼으로 넘길 수 있게 한다(미리보기 전용).
- 실제 퀘스트 화면(`/onboarding-quest`)의 동작은 바뀌지 않는다.

## 구현 계획
1. `SyncStep`·`InventoryStep`: `onComplete: () => Promise<void>` prop을 받아, 기존 fetch·refresh 대신 호출한다. 오류 토스트 처리는 부품에 그대로 둔다(콜백이 실패를 throw하면 토스트).
2. `page.tsx`: API 기록 + `router.refresh()`를 수행하는 콜백을 넘긴다(클라이언트 래퍼가 필요하면 작은 래퍼 하나).
3. `preview/page.tsx`: 관리자 판정 → `QuestPreviewClient` 렌더.
4. `QuestPreviewClient.tsx`: 현재 단계 인덱스 상태, 헤더, 단계 부품(없으면 「다음 단계」), 「처음부터 다시」.
5. 테스트: 미리보기 상태 전이(다음 단계, 끝, 처음부터 다시) 순수 로직 단위 테스트.

## 완료 조건
- 관리자 계정으로 `/onboarding-quest/preview`에 들어가면, 기능 스위치가 꺼져 있고 퀘스트 행이 없어도 1단계부터 시작한다.
- 1단계 「동기화」 → 배지 획득 연출 → 닫기 → 2단계, 2단계 도토리 탭 → 3단계로 넘어간다. 이 동안 네트워크에 `/api/onboarding-quest/step`·`/api/strava/sync` 요청이 없다.
- 「처음부터 다시」를 누르면 1단계로 돌아간다. 새로고침해도 1단계부터 시작한다.
- 관리자가 아닌 계정은 홈으로 이동한다.
- 실제 `/onboarding-quest`는 기존처럼 단계 기록 API를 부르고 다음 단계로 넘어간다(기존 테스트 유지).
- `scripts/verify.sh`가 통과한다.

### 구현 내용 요약
- 관리자 전용 미리보기 `/onboarding-quest/preview`: `getAdminUser()`가 없으면 `/`로 보낸다. 기능 스위치·퀘스트 행을 보지 않고 항상 1단계부터 시작하며, 진행은 화면 안 상태로만 둔다(DB 기록 없음).

- 미리보기 상태 전이는 `lib/onboarding-quest/preview.ts` 순수 함수로 분리했다.
