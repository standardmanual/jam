# [Feature] 홈 퀘스트 카드가 실제 화면으로 이어 하기 하도록 경로를 바꾼다 (N3, T1b 후속)

## 핵심 요약
- 요구사항: `OnboardingQuestCard`의 [이어 하기]/[시작하기] 링크가 삭제된 `/onboarding-quest`(N2) 대신, N1 문지기 함수의 단계→화면 지도를 따라 다음 단계에 해당하는 실제 화면으로 이동한다.
- 구현 계획: `status.ts`의 `in_progress` 상태(`nextStep`)를 N1의 단계→화면 지도로 변환해 `OnboardingQuestCard.tsx`가 그 경로로 링크한다.
- 관련 파일: `jam-web/src/app/(main)/OnboardingQuestCard.tsx`(L18 `ONBOARDING_QUEST_PATH`, L39-59 `in_progress` 분기의 `<Link href={ONBOARDING_QUEST_PATH}>`), `jam-web/src/lib/onboarding-quest/status.ts`(L12-14 `OnboardingQuestCardState`의 `nextStep: OnboardingQuestStepKey`, 읽기), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 단계→화면 지도 재사용)

## 배경 / 문제 정의
결정 14·17에 따라 별도 퀘스트 화면이 없어지므로(N2), 홈 카드가 사용자를 보내던 목적지도 바뀌어야 한다. `nextStep`은 이미 `status.ts`가 계산해 두므로, 이 값을 화면 경로로만 바꾸면 된다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `state.nextStep`(`OnboardingQuestStepKey`)을 N1의 단계→화면 지도로 실제 경로(`/`, `/inventory`, `/drops`, `/combine`, `/missions`)로 변환해 `Link href`에 쓴다. 지도를 두 곳에 중복 정의하지 않도록 N1이 export하는 지도(또는 경로 변환 헬퍼)를 그대로 가져다 쓴다.
- `awaiting_sync`(L62-102) 분기는 이미 실제 경로(`/api/strava/auth`)를 쓰고 있어 변경 대상이 아니다.
- 결정 20(자동 이동 없음): 카드는 [이어 하기]를 눌러야만 다음 화면으로 이동한다. 화면 진입 자체를 자동으로 유도하지 않는다.

### UI/UX 관점 (해당 시)
- 1단계(`sync`)는 실제 홈(`/`) 안에서 동기화 버튼을 눌러 진행하므로(결정 20), 카드가 이미 홈에 떠 있는 상태에서 "홈으로 이동"은 아무 효과가 없다. `sync` 차례일 때 카드 버튼을 어떻게 보여줄지(예: 링크 대신 버튼으로 바꿔 안내만 하거나, `#`앵커로 동기화 버튼 위치로 스크롤하거나)는 채원 사전 판정에 맡긴다.

## 구현 계획
채원 사전 판정(1단계 카드 버튼 형태) → 경로 변환 로직 → `OnboardingQuestCard.tsx` 수정 → 기존 테스트가 있다면 갱신.

## 완료 조건
- `bag` 차례인 계정이 카드를 누르면 `/inventory`로 이동한다. `pickup`/`drop` 차례면 `/drops`, `mix_fail`/`mix_success` 차례면 `/combine`, `browse` 차례면 `/missions`로 이동한다.
- `sync` 차례일 때 카드가 채원 판정대로 동작한다(더 이상 존재하지 않는 `/onboarding-quest`로 링크하지 않는다).
- `scripts/verify.sh`가 통과한다.
