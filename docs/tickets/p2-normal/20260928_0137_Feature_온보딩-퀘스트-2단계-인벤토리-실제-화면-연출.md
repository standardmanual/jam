# [Feature] 온보딩 퀘스트 2단계: 실제 인벤토리 화면에서 연출 도토리를 보여 준다 (N4)

## 핵심 요약
- 요구사항: `/inventory` 실제 화면에서 `bag` 차례인 유저에게 연출 도토리(`DEMO_INVENTORY_ITEM`)를 보여 주고, 누르면 단계를 기록한 뒤 홈으로 돌아간다.
- 구현 계획: `inventory/page.tsx`가 N1 문지기 함수로 `bag` 차례인지 확인 → 맞으면 연출 도토리 1개를 보여 주는 작은 클라이언트 부품을 렌더 → 클릭 시 `POST /api/onboarding-quest/step` 호출 후 홈으로 이동.
- 관련 파일: `jam-web/src/app/(main)/inventory/page.tsx`(L20 `InventoryPage`, L56-119 렌더, L104-109 `EmptyState`, L111-116 `InventoryGrid` 실제 아이템 렌더), `jam-web/src/lib/onboarding-quest/demo-data.ts`(L29-34 `DEMO_INVENTORY_ITEM`, 읽기), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 읽기), `jam-web/src/components/inventory/InventoryGrid.tsx`(`mode="select"` 재사용, 옛 `InventoryStep.tsx` L47과 동일 패턴), `jam-web/src/app/(main)/HomeViewTracker.tsx`(참고 패턴 — 서버 컴포넌트 화면에서 클라이언트 훅이 필요할 때 작은 클라이언트 래퍼로 분리하는 기존 사례)

## 배경 / 문제 정의
결정 14·16에 따라 2단계 연출(옛 `InventoryStep.tsx`, N2에서 삭제)을 실제 `/inventory` 화면으로 옮긴다. 실제 화면은 서버 컴포넌트라 클릭 핸들러를 직접 둘 수 없으므로, `HomeViewTracker` 같은 작은 클라이언트 래퍼가 필요하다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 공통 원칙: 연출용 데이터다. `inventory_items`·`user_activity_badges`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 `bag` 완료만 기록한다.
- `inventory/page.tsx`가 N1로 `bag` 차례인지 확인한다(userId는 이미 L20-26에서 조회).
- 연출 도토리를 누르면 `POST /api/onboarding-quest/step`({ step: 'bag' })을 부르고 성공하면 홈(`/`)으로 이동한다(결정 20: 단계를 마치면 홈으로 돌아가고 카드의 [이어 하기]로 다음 화면에 들어간다).
- 실패 시 토스트 처리는 기존 `StepSaveFailedError`/공통 네트워크 오류 문구 패턴(옛 `InventoryStep.tsx` L30-38)을 재사용한다.
- `bag` 차례가 아닌 유저(퀘스트 미대상·다른 단계·완료·건너뜀)는 연출 없이 기존 `/inventory` 화면 그대로다(결정 22).

### UI/UX 관점 (해당 시)
- 실제 아이템이 0개인 유저는 `EmptyState`(L104-109) 대신 연출 슬롯이 보여야 하고, 실제 아이템이 있는 유저는 실제 그리드에 연출 도토리가 섞이지 않도록 구분한다(연출 아이템은 실제 `inventory_items`에 없으므로 실제 그리드와 같은 자리에 섞으면 "진짜처럼" 보여 혼동을 줄 수 있다). 배치·구분 방식은 채원 사전 판정.

## 구현 계획
채원 사전 판정(연출 도토리 배치·실제 아이템과의 구분) → 파일 단위 계획(2026-09-28 카리나, 테스트 포함 약 90줄·파일 3개):

1. `jam-web/src/app/(main)/inventory/page.tsx`(L20-119 일부 수정, 약 15줄): N1 문지기 함수 호출 추가, 결과를 클라이언트 부품에 prop으로 전달.
2. `jam-web/src/app/(main)/inventory/QuestBagDemo.tsx`(신규, 약 45줄): `'use client'`, `DEMO_INVENTORY_ITEM`을 `InventoryGrid mode="select"`로 렌더, 클릭 시 단계 기록 API 호출 + 홈 이동 + 실패 토스트(옛 `InventoryStep.tsx` 로직 이식).
3. `jam-web/src/app/(main)/inventory/__tests__/QuestBagDemo.test.tsx`(신규, 약 30줄): 클릭 → API 호출 → 이동, 실패 시 토스트.

## 완료 조건
- `bag` 차례인 테스트 계정이 `/inventory`에 들어가면 연출 도토리가 보이고, 누르면 진행도가 `bag`까지 기록된 뒤 홈으로 이동한다.
- 연출 도토리를 누르는 동안 `inventory_items`·`user_activity_badges`에 해당 유저의 행이 생기지 않는다.
- `bag` 차례가 아닌 계정은 연출 도토리 없이 기존 화면 그대로다.
- 테스트와 `scripts/verify.sh`가 통과한다.
