# [Admin] 관리자가 DB에 쓰지 않고 실제 화면에서 임의 단계를 확인할 방법을 만든다 (N5)

## 핵심 요약
- 요구사항: 관리자가 DB에 쓰지 않고 임의 단계를 실제 화면에서 확인할 수 있게 한다(옛 `/onboarding-quest/preview`, N2에서 삭제 대체). `20260928_0119`의 proxy 1차 방어 + 페이지 2차 방어 요구사항을 흡수한다.
- 구현 계획: 방식은 착수 전 확정 필요 — 예시안은 N1 문지기 함수가 관리자 전용 쿠키·쿼리 파라미터로 "현재 단계"를 덮어쓰게 하는 것. 어느 쪽이든 관리자가 아닌 요청은 값을 무시하거나 거부해야 한다(1차: 설정 경로를 `proxy.ts`의 어드민 판정 아래 두거나 그 자체를 관리자 API로 제한. 2차: 문지기 함수/화면이 다시 한번 관리자 여부를 확인한다).
- 관련 파일: `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 오버라이드 파라미터 확장 대상), `jam-web/src/lib/admin/auth.ts`(L32 `hasAdminAccess`, L43 `getAdminUser`, 읽기), `jam-web/src/proxy.ts`(L83-84 `pathname.startsWith('/admin')` 어드민 경로 판정, 참고), `docs/tickets/p3-low/20260928_0119_Service_퀘스트-미리보기-어드민-이중-방어.md`(요구사항 흡수 대상, 이 작업 완료 후 폐기)

## 배경 / 문제 정의
옛 관리자 미리보기(`/onboarding-quest/preview`, 티켓 `20260928_0058`)는 전용 화면을 전제로 만들어졌고, 결정 16으로 그 화면이 삭제된다(N2). 관리자가 스위치·진행 행과 무관하게 퀘스트를 확인해 볼 방법은 여전히 필요하다 — 이제는 "실제 화면에서" 확인해야 하므로 접근 방식을 다시 설계한다. 게이트 리뷰(민지)가 지적한 이중 방어 비대칭(`20260928_0119`)도 새 설계에서 처음부터 반영한다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 관리자 계정만 임의 단계를 지정해 실제 화면(홈·인벤토리·드랍·믹서·미션)에서 그 단계의 연출을 확인할 수 있다. 일반 유저의 퀘스트 진행에는 영향을 주지 않는다(DB에 쓰지 않는다).
- 1차 방어: 단계를 지정하는 진입점(쿠키 설정 API든 쿼리 파라미터든)은 관리자가 아닌 요청에서 걸러진다 — `proxy.ts`의 기존 어드민 경로 판정을 재사용하거나, 설정 자체를 `/admin/` 아래 관리자 API로만 노출한다.
- 2차 방어: N1 문지기 함수(또는 그 호출부)가 오버라이드 값을 실제로 적용하기 전에 `getAdminUser()`로 다시 한번 관리자 여부를 확인한다. 두 방어 중 하나가 뚫려도 나머지가 막는다(`20260928_0119`가 지적한 비대칭을 재발시키지 않는다).
- 실제 서비스 화면(홈·인벤토리·드랍·믹서·미션)의 일반 동작은 관리자가 아닌 요청·오버라이드가 없는 요청에서 전혀 바뀌지 않는다.
- 「처음부터 다시」에 준하는 초기화 경로(옛 미리보기 요구사항, 티켓 `20260928_0058`)를 유지한다 — 오버라이드를 지우면 관리자 계정도 평소 판정(N1)으로 돌아간다.

## 구현 계획
- 확인 절차: 채원 사전 판정을 거친다(2026-09-28 사용자 지정). 관리자 전용이지만 미리보기로 들어가는 방법과 화면 표시는 디자인 확인 대상이다.
선행 화면들(T2c·N4·T3·T4·T5·T5b)이 모두 있어야 각 단계를 실제로 확인할 수 있다. 방식 결정(proxy 경로 추가 vs 관리자 전용 API로 쿠키 발급) → N1 문지기 함수에 오버라이드 인자 추가 → 관리자 화면·경로 연결 → 테스트.

## 완료 조건
- 관리자 계정이 오버라이드로 임의 단계를 지정하면, 그 단계에 해당하는 실제 화면에서 연출이 보인다. `user_onboarding_quests`·`inventory_items`·`poi_drops` 등에 행이 생기지 않는다.
- 관리자가 아닌 계정은 오버라이드 진입점에 접근하거나 값을 주입해도 무시되거나 거부된다(1차 proxy 또는 2차 문지기 함수 확인 중 하나에서 막힌다).
- 초기화하면 관리자 계정도 평소 판정으로 돌아간다.
- `scripts/verify.sh`가 통과한다.
