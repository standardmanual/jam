# [Admin] 어드민에서 퀘스트 미리보기 단계를 고르고, 실제 화면에 미리보기 중임을 표시한다 (N5b)

## 핵심 요약
- 요구사항: 관리자가 어드민 화면에서 퀘스트 단계(1~7단계·마지막 연동 카드)를 골라 미리보기를 시작하고 끝낼 수 있게 한다. 미리보기 중인 관리자에게는 실제 서비스 화면에 "미리보기 중"임을 알리는 표시를 보여 준다. 장치(쿠키·이중 방어·DB 무기록)는 N5a(`20260928_1335`)가 만든다.
- 구현 계획: 채원 사전 판정(어드민 화면 구성, 실제 화면의 미리보기 표시 여부·형태) → 어드민 페이지 → 어드민 메뉴 연결 → (판정대로) 서비스 화면 표시.
- 관련 파일: `jam-web/src/app/admin/`(신규 페이지 위치, 기존 예: `jam-web/src/app/admin/gate-missions/`), `jam-web/src/components/admin/adminNavItems.ts`(어드민 메뉴 항목), N5a의 `POST /api/admin/onboarding-quest/preview`(`{ step }` 설정·`{ reset: true }` 삭제)와 `jam-web/src/lib/onboarding-quest/preview.ts`(`getAdminQuestPreview`), `jam-web/src/app/(main)/layout.tsx`(서비스 화면 공통 표시 후보 위치)

## 배경 / 문제 정의
N5를 착수 전 코드 확인 결과로 N5a(장치)와 N5b(이 티켓, 화면)로 나눴다(2026-09-28 사용자 결정, 상위 결정 27). 채원 사전 판정은 2026-09-28 사용자가 지정했다 — 관리자 전용이지만 미리보기로 들어가는 방법과 화면 표시는 디자인 확인 대상이다. 기획 전문은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 어드민 페이지(경로는 `/admin/` 아래 — `proxy.ts`가 관리자만 통과시키는 1차 방어): 현재 미리보기 상태, 단계 8개(7단계 + `done`) 중 하나로 시작하는 버튼, [미리보기 끝내기] 버튼(`{ reset: true }`). 시작하면 홈(`/`)으로 보내 홈 카드부터 확인하게 한다.
- 실제 서비스 화면의 미리보기 표시는 채원이 필요 여부와 형태를 판정한다(예: 미리보기 중일 때만 보이는 작은 띠와 [끝내기]). 표시가 있으면 관리자가 아닌 유저에게는 절대 렌더되지 않아야 한다(`getAdminQuestPreview()`가 null이면 렌더하지 않는다).
- 어드민 화면 문구에는 내부 용어("온보딩")를 써도 되지만, 서비스 화면에 보이는 표시는 유저 노출 규칙(「퀘스트」)을 따른다.
- 이 티켓이 끝나면 `docs/tickets/p3-low/20260928_0119_Service_퀘스트-미리보기-어드민-이중-방어.md`를 흡수 완료로 닫는다(N5a가 이중 방어를 구현).
- 문서: 관리자 미리보기 사용법(어드민 페이지 경로, 쿠키 동작, DB 무기록, 자동 진행, 끝내는 방법)을 `docs/specs/SERVICE_OPERATIONS.md`에 짧은 절로 남긴다. N5a가 홈피드 PRD를 갱신하지 않고 이 티켓으로 미뤘다.

### 카리나가 확인한 코드 지도 (2026-09-28, N5a 머지 후)
- N5a 산출물: `jam-web/src/lib/onboarding-quest/preview.ts`(`getAdminQuestPreview()` — 관리자이고 쿠키가 있을 때만 값, `QuestPreviewValue`는 단계 키 7종 또는 `done`), `POST /api/admin/onboarding-quest/preview`(`{ step }`·`{ reset: true }`, `requireAdmin()`), 단계→화면 지도 `STEP_SCREEN_MAP`(`jam-web/src/lib/onboarding-quest/config.ts`).
- 어드민 메뉴: `jam-web/src/components/admin/adminNavItems.ts` L37~(그룹별 `{ href, label, icon }` 배열). 새 페이지는 `jam-web/src/app/admin/<경로>/page.tsx`.
- 서비스 공통 레이아웃: `jam-web/src/app/(main)/layout.tsx` L44~81(`ToastProvider` → `TopNavDataProvider` → 본문·`TabBar`·`StravaConnectReveal`). 미리보기 표시를 공통으로 붙인다면 이 파일이 후보다(채원 판정).
- `admin` 유형 규칙: 실렌더 검증은 카리나가 머지 뒤 push 전에 로컬 `ADMIN_EMAILS`로 한다(`docs/specs/DEV_PROCESS_GUARDRAILS.md` 패턴 13). 이때 N5a 완료 조건(관리자 계정으로 `bag` 설정 → `/inventory` 연출 → 홈 카드 `pickup` 전이, DB 무기록)도 함께 확인한다.

## 구현 계획
### 채원 사전 판정 (2026-09-28, 승인 항목 4건 사용자 승인)
- 어드민 페이지는 정책상 채원 판정 대상이 아니다(어드민 예외) — 기존 어드민 화면의 단순 Tailwind 패턴.
- 서비스 화면 표시는 서비스 전용 신규 컴포넌트 `QuestPreviewBanner`(MODULAR 확장 기각, `RecentSyncBanner` 재사용 금지 — 게임 이벤트 전용 색 채널).
- 승인 항목: ① `(main)/layout.tsx`의 문서 흐름에 넣어 TopNav를 아래로 미는 배치(fixed 오버레이 아님) ② `--color-warning` 앰버 솔리드 + `--color-text-inverse` 검정 텍스트, radius 0 엣지투엣지 ③ 문구 「퀘스트 미리보기 중 · N/7단계」, `done`이면 「퀘스트 미리보기 중 · 연동 단계」, 버튼 「끝내기」 ④ [끝내기] 실패는 토스트 「미리보기를 끝내지 못했어요. 다시 눌러 주세요.」(띠 유지).
- 노치 기기 안전영역 이중 여백(TopNav가 자체 `env(safe-area-inset-top)`을 가짐)은 카리나 실렌더 때 실측으로 확정한다.

### 파일 단위 계획 (아현 1차 호출 plan_only 반환, 7개 파일·약 250~320줄 — 사용자 승인으로 분할 없이 진행)

## 완료 조건
- 관리자가 어드민 페이지에서 단계를 고르면 홈으로 이동하고, 홈 카드와 해당 실제 화면이 그 단계 연출을 보인다. [미리보기 끝내기]를 누르면 평소 판정으로 돌아간다.
- 관리자가 아닌 계정은 어드민 페이지에 들어갈 수 없고(`/forbidden`), 서비스 화면의 미리보기 표시도 보이지 않는다.
- 미리보기 전 과정에서 DB에 행이 생기거나 바뀌지 않는다(N5a 장치 사용).
