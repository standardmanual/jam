# [Feature] 온보딩 퀘스트 7단계: 실제 미션 화면을 연 것만으로 완료한다 (T5b)

## 핵심 요약
- 요구사항: `/missions` 화면을 연 것만으로 `browse` 단계를 기록한다. 연출 데이터가 없다 — 실제 화면 자체가 컨텐츠라 연출이 필요 없다(상위 티켓 옛 T5의 7단계 요구사항 계승).
- 구현 계획: `missions/page.tsx`가 N1 문지기 함수로 `browse` 차례인지 확인 → 맞으면 `HomeViewTracker` 패턴의 작은 클라이언트 컴포넌트를 마운트해 `POST /api/onboarding-quest/step`을 1회 호출.
- 관련 파일: `jam-web/src/app/(main)/missions/page.tsx`(L10 `MissionsPage`, L104-110 렌더), `jam-web/src/app/(main)/HomeViewTracker.tsx`(전체, 재사용 패턴), `jam-web/src/lib/onboarding-quest/screen-gate.ts`(N1, 읽기)

## 배경 / 문제 정의
상위 티켓 결정 14·18에 따라 원래 T5(옛 `20260927_2128`)의 7단계(둘러보기)를 트라이브 화면과 묶어 처리하던 계획을 분리한다 — 저장소에 전용 트라이브 화면이 없어 `/missions`만 인정한다(결정 18). 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 공통 원칙: 연출용 데이터는 없다. 서버에는 `user_onboarding_quests.step_progress`에 `browse` 완료만 기록한다.
- `browse` 차례인 유저가 `/missions`에 들어가면, 화면이 로드되는 즉시(클릭 없이) 진행도가 `browse`까지 기록된다 — `HomeViewTracker`처럼 마운트 시 1회만 호출하는 클라이언트 컴포넌트로 구현한다.
- 중복 호출 방지: `POST /api/onboarding-quest/step`은 이미 멱등이므로(`route.ts` L64-67 `alreadyDone`) 새로고침을 반복해도 안전하다.
- `browse` 차례가 아닌 유저는 기존 `/missions` 화면 그대로다(결정 22, 안내·차단 없음).

## 완료 조건
- `browse` 차례인 테스트 계정이 `/missions`에 들어가면 진행도가 7(모든 단계 완료)로 바뀐다.
- 같은 화면에 다시 들어가거나 새로고침해도 기록이 중복되지 않는다.
- `browse` 차례가 아닌 계정은 화면 진입만으로 아무 기록도 생기지 않는다.
- `scripts/verify.sh`가 통과한다.
