# [Content] 온보딩 퀘스트 완료 배지 1종을 `mission_reward` 표시로 등록한다 (T7a)

## 핵심 요약
- 요구사항: 온보딩 퀘스트 완료 보상으로 줄 액티비티 배지 1종(`point_reward` 100)을 DB에 등록한다. 동기화 때 저절로 발급되지 않도록 새 플래그 대신 기존 `condition_json.mission_reward: true`를 재사용한다(사용자 결정 1).
- 구현 계획: 고정 UUID로 배지 행을 넣는 SQL 마이그레이션 작성(실행은 사용자 승인 후 메인 세션) → 지급 코드(T7b)가 쓸 배지 id 상수 추가 → 컨텐츠·배지엔진 문서에 반영. 대표 이미지는 행 등록 후 사용자가 어드민 액티비티 배지 이미지 생성기로 직접 만든다(사용자 결정 3).
- 관련 파일: `jam-web/supabase/migrations/196_onboarding_completion_badge.sql`(신규), `jam-web/src/lib/onboarding-quest/config.ts`(배지 id 상수 추가), `docs/specs/badge-engine/CONDITION_JSON_SPEC.md` L352(§3 `mission_reward` 표), `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md`, `jam-doc/planning/content/ACTIVITY_BADGES.md`(생성 문서 — 생성 스크립트 `v5_doc_build.mjs` 확인 후 반영)

## 배경 / 문제 정의
T7(`20260927_2130`)을 착수 전 코드 확인 결과로 둘로 나눴다(2026-09-28 사용자 결정 2). 이 티켓은 배지 행 등록과 문서, T7b(`20260927_2130`)는 지급 로직이다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 사용자 결정 (2026-09-28, 카리나 코드 확인 후)
1. **표시 방식: 기존 `mission_reward` 재사용.** 새 플래그(`onboarding_reward`)를 만들면 DB 허용 키 제약·조건 등록표·어드민 폼·배지 상세 문구·배지 트리까지 약 13개 파일이 바뀐다. 재사용하면 엔진 코드는 바뀌지 않는다. 대가로 다음을 받아들인다.
   - 유저 배지 상세의 획득 조건 문장이 「'<배지 이름>' 미션을 완료하면 받을 수 있는 배지예요.」로 고정된다(`jam-web/src/lib/badgeConditionText.ts` L307). 그래서 배지 이름은 이 문장에 넣어도 자연스러워야 한다(윈터 검수 조건).
   - 어드민 배지 목록·상세에 「미션 보상」 칩과 「미션 완료로만 지급」이 보인다. 온보딩 전용 구분은 `admin_category = 'jam'`(JAM! 카테고리)과 배지 이름으로 한다. 티켓 요구사항 "어드민에서 구분할지"는 이것으로 결정한다.
2. **티켓 분할**: T7a(이 티켓, 배지 행·문서) → T7b(`20260927_2130`, 지급 로직). 새 플래그를 쓰지 않으므로 엔진 티켓은 없다.
3. **대표 이미지**: 행 등록 후 사용자가 어드민 액티비티 배지 이미지 생성기(`/admin/activity-badge-image`)로 만든다. 이 티켓의 SQL은 `image_url`을 NULL로 둔다.

### 확인한 DB 사실 (2026-09-28 카리나 조회)
- `badges_condition_json_known_keys` CHECK에 `mission_reward`가 이미 있다. `{"mission_reward": true}` 단독 조건을 넣을 수 있다(마이그레이션 084 선례).
- `badges_rarity_level_exclusive`: `rarity`와 `level` 중 하나만 채운다. `activity_types`는 NOT NULL(기본값 `'{}'`)이다.
- 트리거 `badges_family_consistency`는 `mission_reward`가 true면 검사 없이 통과한다.
- `badges_admin_category_known_values`: `admin_category`는 NULL 또는 `'jam'`이다. 배지엔진 후보 조회는 `mission_reward`와 `admin_category = 'jam'`을 둘 다 제외한다(`jam-web/src/lib/badge-engine/index.ts` L1026). 사용량 배지 평가(`usageBadges.ts` L91)는 숫자 지표 키가 있는 배지만 고르므로 이 배지를 고르지 않는다.
- 현재 `activity_types = '{}'`인 액티비티 배지는 0건이다. 배지함(`jam-web/src/app/(main)/badges/BadgesClient.tsx` L37·L180)은 JAM! 배지가 `[]`인 것을 전제로 `admin_category`로 JAM! 탭을 판정한다.
- `user_activity_badges`에 `UNIQUE (user_id, badge_id)`가 있다(T7b 멱등의 2차 방어).

## 상세 요구사항
- 배지 행 값: `id` 고정 UUID(SQL과 `config.ts` 상수가 같은 값), `type` `'activity'`, `rarity` `'common'`, `level` NULL, `activity_types` `'{}'`, `family_key` `'onboarding:complete'`, `admin_category` `'jam'`, `point_reward` 100, `condition_json` `{"mission_reward": true}`, `image_url` NULL, 이름·설명은 아래 「윈터 검수 결과」 값을 글자 단위로 복사한다.
- SQL은 재실행 가능하게 쓴다(`ON CONFLICT (id) DO NOTHING`). 되돌림 SQL(보유자가 0명일 때만 삭제)을 파일 하단 주석에 남긴다. 규칙은 `.claude/skills/jam-work/references/db-migration-rules.md`를 따른다.
- `config.ts`에 `ONBOARDING_COMPLETION_BADGE_ID` 상수를 추가한다. 아직 이 상수를 읽는 코드는 없다(T7b가 쓴다).
- 배지 id를 쓰는 화면이 `activity_types = []`인 액티비티 배지에서 깨지지 않는지 확인한다: `jam-web/src/lib/strava/sync.ts` L526, `jam-web/src/lib/badgeTree.ts` L312, `jam-web/src/lib/admin/badge-list-view.ts` L93, `jam-web/src/lib/admin/badge-families.ts` L184. 네 곳 모두 빈 배열을 건너뛰거나 맨 뒤로 보내는 것으로 보이지만(카리나 확인), 코드 수정이 필요하면 멈추고 보고한다.
- 문서: `CONDITION_JSON_SPEC.md` §3 `mission_reward` 행에 "온보딩 퀘스트 완료 배지도 이 플래그를 쓴다(지급 경로는 온보딩 완료 판정, T7b)"를 반영한다. `BADGE_ENGINE_UNIFIED.md`에서 `mission_reward` 지급 경로를 서술한 곳이 있으면 같은 내용을 반영한다. `ACTIVITY_BADGES.md`는 생성 문서이므로 생성 원천에 반영할지, 생성 범위 밖 절에 적을지 `/jam-docs` 규칙으로 판단한다.

## 윈터 검수 결과 (2026-09-28, 사용자 확정)
- **이름: `퀘스트 클리어`**
- **설명: `퀘스트를 모두 마친 증표입니다.`**
- 배지 상세 획득 조건 문장: 「'퀘스트 클리어' 미션을 완료하면 받을 수 있는 배지예요.」
- 근거: `docs/specs/UX_WRITING_GUIDELINE.md` L116이 이 단계형 과제의 유저 노출 용어를 「퀘스트」로 고정하고 「온보딩」을 금지한다. 「첫 퀘스트 완료」는 고정 문장에서 「완료」가 겹치고, 「퀘스트 완주」는 「완주」가 러닝 계열 배지 어휘라 제외했다. 설명은 윈터 안(「…받는 열쇠입니다.」)에서 「열쇠」를 뺐다 — 미션 보상 배지의 열쇠 모티프는 다음 문을 연다는 뜻인데 이 배지는 여는 것이 없다(사용자 선택).
- 세계관 충돌 없음, 금칙어 매칭 없음, 기존 배지 이름과 중복 없음(윈터 확인).

## 구현 계획
### 파일 단위 계획 (예상 4~5개 파일·약 90줄)
1. `jam-web/supabase/migrations/196_onboarding_completion_badge.sql`(신규): INSERT 1건 + 검증 쿼리·되돌림 SQL 주석. **작성만 하고 실행하지 않는다.**
2. `jam-web/src/lib/onboarding-quest/config.ts`: `ONBOARDING_COMPLETION_BADGE_ID` 상수 추가(주석에 마이그레이션 196과 같은 값이라고 명시).
3. `docs/specs/badge-engine/CONDITION_JSON_SPEC.md` L352 표 행과 L490 표 행.
4. `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md`(해당 서술이 있을 때).
5. `jam-doc/planning/content/ACTIVITY_BADGES.md` 또는 그 생성 원천.
