# [UI] 홈 퀘스트 카드에서 보상 안내 문구를 없애고, 진행도(n/7)를 우측 상단으로 옮기고, 모든 카드에 왼쪽 하단 CTA 버튼을 둔다

## 핵심 요약
- 요구사항: 홈 온보딩 퀘스트 카드의 네 상태 전부에서 (1) 보상 안내 문구 「끝까지 가면 퀘스트 클리어 배지와 100포인트」를 제거하고 (2) 진행도 분수(n/7)를 카드 우측 상단(칩과 같은 줄)으로 옮기고 (3) 카드마다 왼쪽 하단에 CTA 버튼을 둔다.
- 구현 계획: 아래 「구현 계획」의 파일 단위 목록대로 한다. 1단계 카드 CTA는 `OnboardingSyncButton`을, 첫 활동 대기 카드 CTA는 실제 `SyncButton`을 카드용 표시 방식으로 재사용한다.
- 관련 파일:

  - `jam-web/src/app/(main)/OnboardingSyncButton.tsx` — `OnboardingSyncButton`(L28-86) 반환부 `Button`(L64-74)

  - `jam-web/src/app/(main)/page.tsx` — L100 `<OnboardingQuestCard state=… />`(첫 활동 대기 카드의 `SyncButton`에 `username` 전달), `userProfile`(L61)

## 배경 / 문제 정의
상위 티켓 20260927_2123의 홈 퀘스트 카드를 staging에서 확인한 사용자가 수정을 요청했다(2026-09-28). 지금 카드는 진행 중 상태마다 보상 안내 문구가 붙고, 진행도 분수가 진행 바 위에 있으며, CTA가 텍스트 링크(「이어 하기 >」)이거나 아예 없다(1단계 카드·첫 활동 대기 카드).

## 확정한 결정 (2026-09-28 사용자 문답)
1. 보상 안내 문구 `rewardHint`는 모든 카드에서 제거한다. 건너뛰기 확인 시트(`skip.confirmBody`)와 첫 활동 대기 설명(`awaitingActivity.description`)의 보상 언급은 이 요청 범위가 아니다. 그대로 둔다.
2. 진행도 n/7은 카드 우측 상단으로 옮긴다. 진행 바 자체는 유지하고 바의 분수 라벨만 뺀다.
3. CTA 버튼은 카드 왼쪽 하단에 둔다. 상태별 동작:
   - ① 진행 중 · sync 차례: **카드에서 바로 동기화.** 상단 바의 연출 동기화 버튼과 똑같이 동작한다(스피너 → 연출 배지 1장 → `sync` 단계 기록). 위치 안내 문구(`steps.sync.locationHint`)는 뺀다. 상단 바 버튼은 그대로 둔다.
   - ② 진행 중 · 그 외 차례(2~7단계): 기존 「시작하기/이어 하기」 이동을 버튼 모양으로 바꾼다. 이동 대상은 그대로(`STEP_SCREEN_MAP`).
   - ③ 7단계 완료·건너뜀 + Strava 미연동: 기존 「Strava 동기화하기」 → `/api/strava/auth` 이동을 버튼 모양으로 바꾼다.
   - ④ 첫 활동 대기(Strava 연동됨, 활동 0건): **실제 Strava 동기화 버튼**을 추가한다(`SyncButton`과 같은 `POST /api/strava/sync` + 획득 배지 연출). 누를 수 없던 카드에 버튼만 생긴다.

## 상세 요구사항

### UI/UX 관점
- 카드 첫 줄: 왼쪽 칩(「첫 퀘스트」), 오른쪽 n/7. 진행 바가 없는 ④ 카드에는 n/7도 없다.
- CTA 버튼은 카드 안 마지막 줄, 왼쪽 정렬. 버튼 컴포넌트·크기·톤(inverse 카드 위)은 채원 사전 판정을 따른다.
- ②·③은 지금 카드 전체가 링크다. 카드 전체 탭을 유지할지, 버튼만 누를 수 있게 할지는 채원 사전 판정을 따른다(링크 안에 `<button>`을 중첩하지 않는다).
- 건너뛰기 진입점(카드 아래 텍스트)은 그대로 둔다.

### 컨텐츠 관점
- 삭제: `onboardingQuest.rewardHint`, `onboardingQuest.steps.sync.locationHint`(다른 사용처가 없으면).
- ①·④ 버튼 라벨은 기존 `d.today.syncButton`(「동기화」) 재사용을 우선한다. 새 문구를 만들면 승인 필요 항목으로 올린다.

## 구현 계획
1. `ko.ts`: `rewardHint` 삭제, `steps.sync.locationHint` 삭제(사용처 grep으로 확인).
2. `OnboardingSyncButton.tsx`: 표시 방식 prop(예: `appearance: 'nav' | 'card'`, 기본 `nav`)을 추가해 카드용 버튼 모양을 낸다. 동작(연출·단계 기록·토스트·GA4)은 바꾸지 않는다.
3. `SyncButton.tsx`: 같은 방식의 표시 prop 추가(기본값은 지금 모양, TopNav 영향 없음). 동작은 바꾸지 않는다.
4. `OnboardingQuestCard.tsx`
   - 칩 줄을 `flex justify-between`으로 바꾸고 오른쪽에 `{done}/{total}`(③은 7/7) 표시, `ProgressBar`는 `labelType="none"`.
   - `body`에서 `rewardHint` 줄 제거.
   - ①: `locationHint` 줄 대신 `<OnboardingSyncButton appearance="card" />`.
   - ②·③: `CTA_CLASS` 텍스트 링크를 왼쪽 하단 버튼 모양으로 교체.
   - ④: 설명 아래 `<SyncButton username={…} appearance="card" />`. `username`은 `Props`에 선택 필드로 추가하고 `page.tsx`가 `userProfile?.username ?? null`을 넘긴다.
5. `page.tsx`: L100에 `username` 전달.
6. 테스트: `OnboardingQuestCard.test.tsx`에 보상 문구 부재, 네 상태별 CTA 존재, n/7 표시 위치(칩과 같은 줄) 단언 추가·수정. `OnboardingSyncButton.test.tsx`에 `appearance="card"`에서도 같은 동작.
7. 문서: `docs/specs/prd/home-feed/PRD.md` 「온보딩 퀘스트 카드」 표의 네 행 표시·이동 칸 갱신(보상 안내 삭제, n/7 위치, CTA 버튼, ④ 동기화 버튼).

규모: 바뀌는 파일 약 8개(코드 5·테스트 2·문서 1)로 `plan_only` 임계값(5개 초과)을 넘는다. 파일 단위 계획을 위에 적었으므로 첫 호출부터 계획 반환 면제를 넘긴다.

## 완료 조건
- 퀘스트 카드 어느 상태에서도 「끝까지 가면 퀘스트 클리어 배지와 100포인트」가 보이지 않는다(`ko.ts`에서도 키가 사라짐).
- ①②③ 카드에서 n/7이 칩과 같은 줄 오른쪽 끝에 보이고, 진행 바 위의 분수 라벨은 없다.
- ① 카드 왼쪽 하단 버튼을 누르면 상단 바 버튼과 같은 연출(스피너 → 연출 배지) 뒤 `sync` 단계가 기록되어 카드가 2단계로 넘어간다. 위치 안내 문구는 없다.
- ② 카드 왼쪽 하단 버튼(「시작하기/이어 하기」)을 누르면 그 단계의 실제 화면으로 이동한다.
- ③ 카드 왼쪽 하단 버튼(「Strava 동기화하기」)을 누르면 `/api/strava/auth`로 이동한다.
- ④ 카드 왼쪽 하단 동기화 버튼을 누르면 `POST /api/strava/sync`가 호출되고, 결과가 TopNav 동기화 버튼과 같은 방식(배지 연출 또는 토스트)으로 표시된다.
- TopNav의 두 동기화 버튼(연출·실제)은 모양·동작이 바뀌지 않는다.
- `scripts/verify.sh` 통과, `home-feed/PRD.md` 상태 표가 코드와 일치한다.
