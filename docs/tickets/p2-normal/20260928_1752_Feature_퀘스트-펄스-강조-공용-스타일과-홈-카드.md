# [Feature] 퀘스트 「지금 눌러야 할 곳」 펄스 강조의 공용 스타일을 만들고 홈 퀘스트 카드 버튼에 먼저 적용한다 (Q1)

## 핵심 요약
- 요구사항: 온보딩 퀘스트 진행 중 눌러야 할 요소에 브랜드 빨강 box-shadow가 번지는 펄스(B안)를 준다. 이 티켓은 공용 스타일(토큰·키프레임·클래스)을 만들고, 홈 퀘스트 카드의 `in_progress` CTA(① 동기화 ② 다음 단계)에 적용한다.
- 구현 계획: 아래 「구현 계획」 4항목. 대상 컴포넌트(`Button`·`OnboardingSyncButton`)는 고치지 않고, 카드의 CTA 줄에서 버튼을 감싸는 pill 모양 래퍼에 클래스를 붙인다.
- 관련 파일:
  - `jam-web/design-system/tokens/motion.css` — 토큰 2개 추가 위치(기존 `--duration-*` 목록 뒤)
  - `jam-web/src/components/transitions.css` — 키프레임·클래스 추가(`t-skel-pulse` L361 부근과 같은 방식, 파일 끝의 `prefers-reduced-motion` 가드 패턴)
  - `jam-web/src/app/(main)/OnboardingQuestCard.tsx` — `CTA_ROW_CLASS`(L45 부근), ① `OnboardingSyncButton appearance="card"`(L107-109 부근), ② `Button`(L122-131 부근). ③(L157-167)·④(L186-188)는 손대지 않는다
  - 테스트: `jam-web/src/app/(main)/OnboardingQuestCard.test.tsx`
  - 문서: `docs/specs/prd/home-feed/PRD.md` 「온보딩 퀘스트 카드」 절(L47-66)

## 배경 / 문제 정의
사용자가 퀘스트 진행 중 "눌러야 할 곳"을 시각적으로 강조해 달라고 요청했다(2026-09-28). 샘플 캔버스(https://claude.ai/artifact/DhBUDH3DqUhkgBjjNHegD3)에서 스포트라이트 디밍(A안)과 펄스만(B안)을 비교했고, 사용자가 **B안**을 골랐다. 혜린이 단계별 대상 지도와 분해안을 만들었다(Q1~Q4).

## 확정한 결정 (2026-09-28 사용자 문답)
1. **펄스만**(B안): 화면은 그대로 두고 대상에서만 `rgba(232,70,31,.55)`(= `--color-primary`) box-shadow가 0 → 10px로 번지며 사라지는 반복 애니메이션. 주기 1.6초, easing `cubic-bezier(.2,0,0,1)`. 말풍선·설명 문구 없음(상위 결정 1 "코치마크가 아니라 퀘스트 방식" 유지).
2. `prefers-reduced-motion: reduce`면 애니메이션을 끈다.
3. 누르면 펄스가 멈춘다. 홈 카드 버튼은 누르면 화면을 떠나거나(②) 연출 오버레이가 열리므로(①) 별도 정지 상태를 두지 않아도 된다. 오버레이를 닫은 뒤 카드가 다음 단계로 바뀌면 새 대상의 펄스가 다시 시작되는 것이 맞다.
4. **1단계는 카드 버튼만** 펄스한다. 상단 바(`TopNav`) 연출 동기화 버튼에는 주지 않는다.
5. **퀘스트 이후 카드(③ Strava 동기화하기, ④ 첫 활동 대기)는 제외**한다.
6. 하단 탭 아이콘은 이번 범위에서 제외한다.
7. 한 단계에 대상이 여럿이면 지금 눌러야 할 하나에만 펄스를 주고 다음 대상으로 옮긴다(Q2~Q4에 해당, 이 티켓은 대상이 하나씩이다).

## 구현 계획
1. `motion.css`: `--duration-quest-pulse: 1.6s;`, `--ease-quest-pulse: cubic-bezier(.2, 0, 0, 1);` 추가(온보딩 퀘스트 전용임을 이름에 드러낸다).
2. `transitions.css`: `@keyframes jam-quest-pulse`(0% `box-shadow: 0 0 0 0 rgba(232,70,31,.55)` → 100% `0 0 0 10px rgba(232,70,31,0)`), `.jam-quest-pulse { animation: jam-quest-pulse var(--duration-quest-pulse) var(--ease-quest-pulse) infinite; }`, `@media (prefers-reduced-motion: reduce) { .jam-quest-pulse { animation: none; } }`. 색은 가능하면 `--color-primary` 기반(`color-mix` 등)으로, 불가하면 주석으로 토큰 값 근거를 남긴다 — 채원 판정을 따른다.
3. `OnboardingQuestCard.tsx`: ①·②의 버튼을 pill 모양(`rounded-[var(--radius-pill)]`) 래퍼로 감싸 `jam-quest-pulse` 클래스를 붙인다. `Button`·`OnboardingSyncButton` 자체는 수정하지 않는다. ③·④는 그대로.
4. 테스트·문서: ①② CTA에 펄스 클래스가 있고 ③④에는 없다는 단언. `home-feed/PRD.md`의 진행 중 두 행에 "CTA에 펄스 강조(퀘스트 진행 중에만)" 서술, 절 머리에 펄스 규격 한 줄(단일 원천: `transitions.css` `.jam-quest-pulse`).

규모: 바뀌는 파일 5개(토큰 1·CSS 1·컴포넌트 1·테스트 1·문서 1), 예상 60줄 이내.

## 완료 조건
- `.jam-quest-pulse`가 결정 1의 규격대로 반복 애니메이션을 내고, reduced-motion 환경에서는 멈춰 있다.
- 홈 퀘스트 카드 ① 1단계 「동기화」와 ② 「다음 단계」 버튼 둘레에 펄스가 보인다. ③·④ 카드와 상단 바 동기화 버튼에는 펄스가 없다.
- 버튼 크기(`xs`)·위치(왼쪽 하단)·동작은 바뀌지 않는다.
- `scripts/verify.sh` 통과, `home-feed/PRD.md`가 코드와 일치한다.
