# [Feature] 퀘스트 4·5단계(믹서)에서 지금 눌러야 할 요소로 펄스 강조를 옮겨 간다 (Q4)

## 핵심 요약
- 요구사항: `mix_fail`·`mix_success` 차례의 `/combine`에서 지금 눌러야 할 요소 하나에만 공용 펄스(`.jam-quest-pulse`, 티켓 20260928_1752)를 주고 누르면 다음 요소로 옮긴다.
  - `mix_fail`: ① 레시피 「살롱의 장물 시세」 행 → ② 빈 슬롯(가방을 처음 여는 순간 단계 완료)
  - `mix_success`: ③ 가방 시트의 후보 행(슬롯마다) → ④ 다음 빈 슬롯 → ⑤ 「조합하기」 버튼(`canSubmit === true`일 때)
- 구현 계획: 새 순서 상태 없이 `CombineClient`가 이미 계산한 값(선택된 레시피, 빈 슬롯, 열린 가방 시트, `canSubmit`)으로 지금 대상을 정한다. 디자인 시스템 컴포넌트 `MixerSlot`은 수정하지 않고 `CombineClient`의 슬롯 래퍼에 클래스를 붙인다(Storybook 갱신 회피, `QuestPickupScene`이 `MapView`를 건드리지 않은 선례). 래퍼 방식이 슬롯 모양과 맞는지는 채원 판정을 따른다.
- 관련 파일:
  - `jam-web/src/app/(main)/combine/CombineClient.tsx` — `renderRecipeRow` L377-388, `MixerSlot` 그리드 L463-473, `openBagFor` L247-268, 가방 시트 행 L508-548(`fillSlot`), 조합 버튼 L479-486, `canSubmit` L163
  - `jam-web/src/app/(main)/combine/RecipeRewardRow.tsx` — 레시피 행 래퍼(필요할 때만)
  - 테스트: `CombineClient` 기존 테스트(정적 렌더 단언)
  - 문서: `docs/specs/prd/01_PRD.md` 온보딩 퀘스트 서술에 4·5단계 강조 대상 한 줄

## 배경 / 문제 정의
상위 20260927_2123의 펄스 강조 분해안 Q4. 결정·규격은 티켓 20260928_1752 「확정한 결정」을 따른다. 4단계 구조는 상위 결정 23(실패 체험 폐기, 레시피 확인 단계)을 따른다.

## 확정한 결정 (2026-09-28 사용자 승인, 채원 사전 판정 승인 항목)
1. `mix_success` 차례에 레시피를 아직 고르지 않은 상태(재방문 시 `selectedRecipeId=null`로 다시 시작)에도 `mix_fail`과 같이 **레시피 행에 펄스**를 준다. 아무것도 반짝이지 않는 공백 구간을 두지 않는다.
2. 슬롯·레시피 행은 래퍼로 감싸지 않고 `MixerSlot`·`RecipeRewardRow`의 **기존 `className` 패스스루**로 펄스 클래스를 넘긴다(화면 결과 동일, design-system 파일은 여전히 무변경).

## 완료 조건
- `mix_fail` 차례: 레시피를 고르기 전에는 레시피 행에만, 고른 뒤에는 빈 슬롯에만 펄스가 있다.
- `mix_success` 차례: 레시피를 고르기 전이면 레시피 행에, 가방 시트가 열려 있으면 후보 행에, 닫혀 있고 빈 슬롯이 있으면 그 슬롯에, 두 슬롯이 다 차면 「조합하기」에만 펄스가 있다.
- 퀘스트 차례가 아닌 평소 `/combine`에는 펄스가 없다. `MixerSlot`(design-system) 파일은 바뀌지 않는다.
- 기존 믹스 연출과 단계 기록 동작이 그대로다.
- `scripts/verify.sh` 통과, `01_PRD.md` 서술이 코드와 일치한다.
