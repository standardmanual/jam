# [UI] 처음 들어온 믹서 퀘스트 흐름에서 가방 후보 행과 「조합하기」 버튼에 펄스가 켜지지 않는다

## 핵심 요약
- 요구사항: `mix_fail` 차례로 `/combine`에 들어와 가방을 처음 연 뒤에는, 같은 화면에서 5단계 규칙(후보 행 → 다음 빈 슬롯 → 「조합하기」)으로 펄스가 옮겨 가게 한다.
- 구현 계획: 경미 수정(0.1절). 판정 단계를 정하는 순수 함수 `resolveQuestPulseStep(questStep, mixFailRecorded)`를 두고 `computeQuestPulseTarget()` 호출에 넘긴다.
- 관련 파일: `jam-web/src/app/(main)/combine/CombineClient.tsx`(신규 `resolveQuestPulseStep` L114 부근, `pulseTarget` 계산 L468 부근), 테스트 `CombineClient.test.tsx` 끝

## 배경 / 문제 정의
티켓 20260928_1755(Q4) 머지 뒤 카리나가 staging 관리자 미리보기(4단계)에서 확인했다. `questStep`은 서버에서 받은 prop이라, 가방을 처음 열어 `mix_fail`을 기록해도 화면이 새로고침되지 않아 계속 `'mix_fail'`이다(상위 결정 23: 4·5단계는 같은 화면에서 이어 간다). `computeQuestPulseTarget()`의 `mix_fail` 규칙에는 후보 행·「조합하기」 대상이 없어서, 처음 들어온 사용자의 주 경로에서 가방 후보에 펄스가 없고 두 슬롯을 채우면 펄스가 사라졌다. Q4의 아현 가정("두 슬롯이 다 찬 `mix_fail` 상태는 거의 생기지 않는다")과 카리나의 보고가 틀렸다 — 이것이 주 경로다. 게이트는 순수 함수 단위로만 검증해 화면 흐름의 prop 고정을 잡지 못했다.

## 완료 조건
- `resolveQuestPulseStep('mix_fail', true)`가 `'mix_success'`를 돌려주고, 나머지 조합은 입력 그대로다(단위 테스트).
- staging 4단계 흐름: 레시피 행 → 슬롯 → (가방) 후보 행 → 다음 빈 슬롯 → 「조합하기」 순으로 펄스가 옮겨 간다.
