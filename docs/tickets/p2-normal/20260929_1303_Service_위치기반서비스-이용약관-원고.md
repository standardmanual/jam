# [Service] 위치기반서비스 이용약관 원고를 작성하고 게시 전제 조건을 정리한다

## 핵심 요약
- 요구사항: 당근·한국관광공사 약관과 로폼 작성 가이드의 구성을 참고해 JAM!의 위치기반서비스 이용약관 원고를 만든다.
- 구현 계획: docs 유형. 코드·DB 스키마에서 위치정보 수집·이용·보관·공개 흐름을 조사하고, 그 사실에 맞춰 `docs/specs/LOCATION_TERMS.md`(draft)를 작성한다. 페이지 게시는 이 티켓 범위가 아니다.
- 관련 파일: `docs/specs/LOCATION_TERMS.md`, 조사 근거 `jam-web/src/app/(main)/drops/DropsClient.tsx`, `jam-web/src/app/api/drops/route.ts`, `jam-web/src/lib/abusing/gps-detector.ts`, `jam-web/src/lib/strava/sync.ts`, `jam-web/src/lib/poi/reverse-geocode.ts`

## 배경 / 문제 정의
JAM!은 기기 위치(드랍 지도·드랍·픽업 판정)와 스트라바 GPS 경로(체크인 배지 판정)를 쓰지만 위치기반서비스 이용약관이 없다. 위치정보법 제18조는 약관 명시와 동의를 요구한다. 네이버 약관 페이지는 접근이 막혀 참고하지 못했다.

## 완료 조건
- 원고가 위치정보법 제18조 필수 기재사항(사업자 정보, 권리·행사방법, 서비스 내용, 확인자료 보유근거·기간)을 모두 조항으로 갖춘다.
- 서비스별 보유기간이 코드 조사 결과와 일치한다.
- 게시 전 해결할 일(사업자 정보, 신고, 동의 UI, 확인자료 기록, 자동 파기, 방문 기록 공개 쟁점)이 원고 하단 내부 메모에 정리된다.

## 대기 사유
원고 작성은 끝났다. 게시하려면 사용자가 사업자 정보·보유기간·위탁 표기 범위·시행일을 확정해야 하고, 동의 UI와 확인자료 기록 등 구현 티켓을 따로 만들어야 한다(원고 하단 A~D 항목).
