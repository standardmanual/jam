# [Service] 개인정보 처리방침을 사업자 정보·실제 위치정보 보관·GA4 사용 사실에 맞게 고친다

## 핵심 요약
- 요구사항: 게시 중인 개인정보 처리방침(v1.0)에 확정된 사업자 정보를 넣고, 실제 코드와 어긋나는 서술 3건(위치정보 미보관, 구글 애널리틱스 미사용, 활동 지역 수집)을 고친다. 위치기반서비스 이용약관 초안(`docs/specs/LOCATION_TERMS.md`) 제5조 보유기간·제6조 위탁 목록과 표현을 맞추고 개정 이력에 v1.1을 추가한다.
- 구현 계획: docs 유형 + 게시 페이지 문구 수정. 카리나가 원고와 페이지를 함께 고친다(레이아웃·컴포넌트 변경 없음, 기존 `DefCard`·`P`·`Section` 헬퍼만 사용).
- 관련 파일:
  - `docs/specs/PRIVACY_POLICY.md` — 머리말(8~12행), 2항 (2)·(3)·(6)(71~105행), 3항 보유기간 표(116~122행), 5항 위탁 표(148~152행), 6항 국외 이전 표(163~172행), 8항 쿠키(185~196행), 9항 프로필 수정 항목(206행), 10항 보호책임자(227행), 12항 개정 이력(250~252행), 하단 「남은 확인 필요 사항」
  - `jam-web/src/app/(main)/privacy/page.tsx` — 상단 주석(17~21행), `EFFECTIVE_DATE`(29행), 각 섹션의 `DefCard` 값(170·180~185·229~234·244~248·290~307·323~369·393~415·428·452·481행)
  - 근거 코드: `jam-web/supabase/migrations/010_abusing_policy.sql`(53~55행 `last_location_*`), `jam-web/src/app/api/drops/[dropId]/pickup/route.ts`(92~99행 `logAbusingEvent` 좌표), `jam-web/src/lib/strava/sync.ts`(`recordProcessedActivities`, `normalized` 저장), `jam-web/src/app/layout.tsx`(`GoogleAnalytics`), `jam-web/src/lib/analytics/gtag.ts`(`trackEvent`), `jam-web/src/components/PoiCarouselModal.tsx`(483·555행 `item_drop`·`item_pickup`의 `poi_id`), `jam-web/supabase/migrations/150_drop_users_region_activity_types.sql`

## 배경 / 문제 정의
v1.0(2026-09-01 게시)은 사업자 정보가 없어 해당 항목을 생략했다. 2026-09-29 사용자가 상호 standardmanual, 대표자 황시현, 주소 서울특별시 성동구 상원길 63을 확정했다. 같은 날 위치기반서비스 이용약관 초안을 쓰면서 조사한 결과 처리방침의 서술 3건이 실제 동작과 다르다.

1. 위치정보를 "판정 즉시 미보관"이라고 적었지만 `users.last_location_lat/lng/at`(직전 픽업 좌표, 픽업마다 덮어씀), `abusing_logs.detail`의 좌표(GPS 조작 탐지 시), `strava_activities.normalized`의 시작·종료 좌표가 저장된다.
2. 구글 애널리틱스를 쓰지 않는다고 적었지만 GA4가 설치돼 있고, `item_drop`·`item_pickup` 이벤트에 `poi_id`가 들어간다.
3. 수집 항목에 "활동 지역"(과 "선호 활동 유형")이 있지만 입력 UI가 없고 마이그레이션 150에서 삭제하기로 한 컬럼이다.

## 완료 조건
- 원고와 페이지 양쪽에 사업자 정보(상호·대표자·주소·연락처) 항목이 있고, 개인정보 보호책임자 성명이 황시현으로 적혀 있다.
- 위치정보 보유기간이 `LOCATION_TERMS.md` 제5조와 같은 값이다(현재 좌표 즉시 파기, 직전 픽업 좌표는 다음 픽업 때 갱신, 부정 이용 탐지 기록 3개월, 스트라바 시작·종료 좌표와 방문·드랍·픽업 기록은 탈퇴 시까지).
- 위탁 항목에 네이버클라우드 주식회사(역지오코딩 포함)·Vercel Inc.·Supabase Inc.가 제6조와 같은 이름으로 있다.
- 구글 애널리틱스 미사용 서술이 사라지고, GA4 사용 사실·전송 항목·거부 방법이 8항과 6항에 있다.
- 수집 항목과 9항 프로필 수정 목록에 "활동 지역"·"선호 활동 유형"이 없다.
- 개정 이력에 v1.1이 있고 페이지 `EFFECTIVE_DATE`와 원고 12항 적용일이 같다.
- `npx eslint "jam-web/src/app/(main)/privacy/page.tsx"`와 `npm run typecheck`가 통과한다.

## 완료 기록

### 구현 내용 요약
- 머리말에 개인정보처리자 정보(상호·대표자·주소·연락처)를 추가하고, 10항 보호책임자에 성명(황시현)·직책(대표자)을 넣었다. 사업자등록번호는 확정값이 없어 적지 않았다.
- 2항 (3) 위치정보를 기기 현재 좌표와 스트라바 좌표·경로로 나눠 적고, 「보관하는 위치 관련 정보」(직전 픽업 좌표·시각과 당일 누적 이동거리, 부정 이용 탐지 기록, 스트라바 시작·종료 좌표, 방문·드랍·픽업 기록)와 「보관하지 않는 위치정보」를 분리했다. 3항 보유기간 표는 `LOCATION_TERMS.md` 제5조 값과 같다.
- 2항에 (7) 구글 애널리틱스를 추가하고, 6항 국외 이전에 Google LLC(GA) 행, 8항에 분석 쿠키와 거부 방법(GA 차단 부가기능)을 넣었다. 구글 애널리틱스 미사용 서술 2곳을 지웠다.
- 2항 (2)와 9항에서 활동 지역·선호 활동 유형을 빼고 소속 트라이브를 넣었다(`users.tribe_id`, 온보딩 선택).
- 5항 위탁 표를 제6조 표기(Supabase Inc.·Vercel Inc.·네이버클라우드 주식회사)로 맞추고, 역지오코딩과 위치 판정 요청 처리를 위탁 업무에 넣었다. Vercel·Supabase가 미국 법인이라 "국내 수탁업체" 표현을 지웠다.
- 12항 적용일을 2026-10-01(약관 시행일과 동일)로, 개정 이력에 v1.1을 추가했다.
- `LOCATION_TERMS.md` 하단 D항을 해결로 표시했다.

### 확인한 사실(2026-09-29)
- Vercel 서버 함수 리전은 `jam-web/vercel.json`의 `regions: ["icn1"]`이다.
- GA 이벤트는 `trackEvent()` 호출 15곳이며 `user_id`·이메일·좌표 파라미터는 없다. `item_drop`·`item_pickup`에 `poi_id`가 있다.
- `users.region`·`users.activity_types` 컬럼은 DB에 남아 있고(마이그레이션 150 미실행), 4명에게 값이 있다. 이를 읽거나 쓰는 코드는 없다.
