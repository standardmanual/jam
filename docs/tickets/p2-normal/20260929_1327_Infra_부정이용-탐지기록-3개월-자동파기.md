# [Infra] 부정 이용 탐지 기록(abusing_logs)을 3개월이 지나면 자동으로 파기한다

## 핵심 요약
- 요구사항: 개인정보 처리방침 v1.1(적용일 2026-10-01) 3항과 위치기반서비스 이용약관 제5조는 부정 이용 탐지 기록의 보유기간을 "탐지일로부터 3개월"로 적었다. 현재 `abusing_logs`는 기간 제한 없이 쌓이므로, `created_at`이 3개월 지난 행을 매일 자동 삭제한다.
- 구현 계획: `jam-web/src/lib/abusing/`에 삭제 함수(예: `purgeExpiredAbusingLogs(now)`, 기준 시각을 인자로 받아 테스트 가능하게)를 두고, 기존 일일 크론 `/api/cron/poi-cleanup`(매일 00:00 UTC)이 드랍 소각 뒤에 호출한다. 새 크론 경로는 만들지 않는다. 삭제 건수를 응답 JSON과 `console.info`에 남긴다. 삭제 실패는 드랍 소각 결과를 무효로 만들지 않는다(에러를 로그로 남기고 응답에 표시).
- 관련 파일:
  - `jam-web/src/app/api/cron/poi-cleanup/route.ts` — `GET`(15~39행). 39행 응답에 삭제 건수 추가
  - `jam-web/src/lib/abusing/` — 새 파일 또는 `shadow-ban.ts`(161·210행 부근 `abusing_logs` insert)와 같은 서비스 클라이언트 패턴으로 삭제 함수 추가
  - `jam-web/src/lib/abusing/__tests__/` — 삭제 함수 테스트
  - `jam-web/supabase/migrations/010_abusing_policy.sql`(58~64행, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`) — 참고만, 스키마 변경 없음
  - 문서: `docs/specs/PRIVACY_POLICY.md` 하단 「남은 확인 필요 사항」 7번, `docs/specs/LOCATION_TERMS.md` 하단 「남은 확인 필요 사항」 B-3을 해결로 표시

## 주요 의사결정
- 파기 범위는 `event_type`과 관계없이 **전체 행**이다(2026-09-29 사용자 결정). `abusing_logs`에는 GPS 조작 탐지 기록 외에 관리자 제재 해제 기록(`releaseBans`·`releasePoiBlocks`가 남기는 행)도 있지만, 방침이 공개한 보관 항목과 정확히 맞추기 위해 함께 지운다.
- 3개월은 달력 기준(`now - interval '3 months'`와 같은 의미)으로 계산한다.

## 배경 / 문제 정의
티켓 20260929_1326에서 처리방침 보유기간을 약관 초안(2026-09-29 사용자 확정값 3개월)과 맞췄다. 문서는 3개월을 약속하지만 파기 장치가 없어, 적용일(2026-10-01) 이후 3개월이 지나는 2027-01-01 전에는 구현돼야 서술이 사실이 된다. `LOCATION_TERMS.md` 하단 B-3, `PRIVACY_POLICY.md` 하단 7번과 같은 과제다.

## 완료 조건
- 탐지일로부터 3개월이 지난 `abusing_logs` 행이 `event_type`과 관계없이 매일 한 번 자동 삭제된다. 확인 방법: 테스트에서 삭제 함수가 `created_at < (기준 시각 - 3개월)` 조건으로만 삭제를 요청하는지 확인한다(3개월 1일 전 행은 대상, 2개월 전 행은 비대상).
- 크론 인증(`CRON_SECRET`)과 기존 드랍 소각 동작·응답 필드는 그대로다.
- 삭제 건수가 크론 응답 또는 서버 로그에 남는다.
- `PRIVACY_POLICY.md` 하단 7번과 `LOCATION_TERMS.md` B-3을 해결로 표시한다.
