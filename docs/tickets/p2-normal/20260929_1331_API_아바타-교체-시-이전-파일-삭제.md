# [API] 아바타를 바꾸면 이전 파일을 Storage에서 지운다

## 핵심 요약

- 요구사항: `POST /api/profile/avatar`는 매번 새 경로에 올리고 `users.avatar_url`만 바꾼다. 이전 파일은
  공개 버킷에 그대로 남아, 이용자가 바꿔 치운 사진도 이전 URL을 아는 사람은 계속 볼 수 있다.
  DB 갱신이 성공한 뒤 이전 객체를 삭제한다.
- 구현 계획: 업로드 전에 `users.avatar_url`을 읽어 두고, 갱신 성공 후 그 URL이 `avatars` 버킷의
  `{user.id}/` 아래 경로일 때만 `remove()`한다(구글 기본 이미지 등 외부 URL은 건드리지 않는다).
  삭제 실패는 로그만 남기고 응답은 성공으로 둔다.
- 관련 파일: `jam-web/src/app/api/profile/avatar/route.ts` `POST` 61~74행(공개 URL 계산·DB 갱신 뒤).
  티켓 20260929_1317 머지 후 줄 위치가 달라지므로 그 기준으로 다시 확인한다.

## 배경 / 문제 정의

2026-09-29 실측에서 `avatars` 버킷 객체 6개 중 3개가 어떤 `users.avatar_url`도 가리키지 않는 이전
파일이었다(티켓 20260929_1330 표). 이미 쌓인 파일 정리는 20260929_1330에서 한다.

## 완료 조건

- 아바타가 있는 이용자가 새로 올리면 이전 객체에 대해 `remove()`가 한 번 호출된다(라우트 테스트).
- 이전 `avatar_url`이 외부 URL이거나 다른 이용자 경로면 `remove()`를 부르지 않는다.
- `remove()`가 실패해도 응답은 200이고 새 `avatar_url`을 돌려준다.
