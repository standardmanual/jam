# [Service] 개인정보 처리방침·위치기반서비스 이용약관 페이지를 로그인 없이 볼 수 있게 한다

## 핵심 요약
- 요구사항: `/privacy`와 `/location-terms`를 로그인하지 않은 방문자도 열 수 있게 한다. URL은 바꾸지 않는다. 로그인한 사용자가 여는 경우의 화면(상단 바·하단 탭 바 유무)과 비로그인 방문자에게 보이는 화면은 채원① 판정을 따른다(2026-09-29 사용자 결정).
- 구현 계획: 두 페이지는 `(main)` 라우트 그룹 안에 있어 `(main)/layout.tsx`가 비로그인 사용자를 `/login`으로 보내고, `TopNav` 래퍼는 `(main)` 레이아웃이 내려주는 로그인 사용자 컨텍스트(`useTopNavData`)를 쓴다. 따라서 (1) 두 페이지를 `(main)` 밖의 새 라우트 그룹(예: `src/app/(legal)/`)으로 옮기고 그 그룹에 로그인 없이 렌더되는 레이아웃을 두며, (2) `proxy.ts`의 `publicPaths`에 두 경로를 추가한다. 페이지 본문(원고 문구)은 바꾸지 않는다.
- 관련 파일:
  - `jam-web/src/proxy.ts` — 56~57행 `publicPaths`·`isPublicPath`, 67~74행 비로그인 리다이렉트(STAGING_MODE면 `/api/dev-login`)
  - `jam-web/src/app/(main)/layout.tsx` — 13~20행 `getUser()` 후 `redirect('/login')`, 50행~ 렌더 구조(`TopNavDataProvider`, `main` 배경 그라데이션, Footer·TabBar)
  - `jam-web/src/app/(main)/privacy/page.tsx`, `jam-web/src/app/(main)/location-terms/page.tsx` — 옮길 대상. 둘 다 `TopNav`(`@/components/ui/TopNav`)를 쓴다
  - `jam-web/src/components/ui/TopNav.tsx` — 87행 `useTopNavData()`
  - `jam-web/src/components/ui/Footer.tsx` — 24행 `FOOTER_EXCLUDED_PATHS`(두 경로가 `(main)` 밖으로 나가면 제외 목록에서 빼도 되는지 확인)
  - `jam-web/src/app/(main)/philosophy/page.tsx` 178행 — `/privacy` 링크(URL 불변이라 수정 불필요)

## 주요 의사결정
- 로그인 화면 안내 문구(`ko.ts` 854행 `login.terms`)에서 두 문서로 링크를 거는 일은 이 티켓 범위가 아니다. 공개 접근이 먼저다.
- 페이지 파일을 옮기면 diff가 커질 수 있어(이름 변경이 아닌 삭제·추가로 잡히는 경우) 파일 단위 계획을 위에 적고 첫 호출부터 계획 반환을 면제한다.

## 배경 / 문제 정의
2026-09-29 조사에서 `publicPaths`에 `/privacy`가 없는 것을 확인했다. 로그인하지 않은 방문자는 방침을 열면 `/login`으로 보내진다. 로그인 화면은 "계속하면 JAM!의 이용약관 및 개인정보처리방침에 동의하는 것으로 간주돼요"라고 안내하는데, 동의하기 전에는 그 방침을 읽을 수 없다. 「개인정보 보호법」 제30조제2항은 처리방침을 정보주체가 쉽게 확인할 수 있게 공개하도록 정한다.

## 완료 조건
- 로그아웃 상태(브라우저 쿠키 없음, STAGING_MODE 아님)에서 `/privacy`와 `/location-terms`를 열면 리다이렉트 없이 본문이 보인다.
- 로그인 상태에서 두 페이지를 열어도 본문이 보인다.
- 다른 보호 경로(예: `/`, `/profile`)는 로그아웃 상태에서 종전대로 `/login`으로 간다.
- 두 페이지의 본문 문구는 옮기기 전과 같다.
- 홈 Footer의 두 링크가 종전과 같은 URL로 이동한다.
- `scripts/verify.sh`가 통과한다.
