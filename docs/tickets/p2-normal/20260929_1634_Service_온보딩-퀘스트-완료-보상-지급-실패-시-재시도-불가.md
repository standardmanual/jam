# [Service] 온보딩 퀘스트 완료 보상 지급이 한 번 실패하면 다시 시도되지 않아 배지·100P가 영구 유실된다

## 핵심 요약
- 요구사항: 완료 보상(퀘스트 클리어 배지 + 100P) 지급이 일시 오류로 실패해도 다음 완료 판정 호출(동기화·단계 기록)에서 다시 지급되게 한다. 멱등성(1회 지급)은 유지한다.
- 관련 파일: `jam-web/src/lib/onboarding-quest/completion.ts` L70-99(`grantOnboardingQuestReward` 선점·롤백), L172(`completed_at` 있으면 즉시 null), L188-200(`completed_at` 갱신 뒤 지급), `jam-web/src/lib/points/index.ts` L47-70(`awardPoints`는 실패해도 throw하지 않음), 테스트 `completion-reward.test.ts` L201-214

## 배경 / 문제 정의
2026-09-29 `/jam-ship` 병렬 점검에서 민지 모드 ②(주의)·③(주의)이 같은 결함을 짚었고 카리나가 코드로 확인했다. 사용자가 결함을 알고 배포하기로 결정했다(2026-09-29, 배포 직후 후속 수정). `completed_at`을 먼저 기록한 뒤 보상을 지급한다. 배지 insert가 23505 외 오류로 실패하면 `reward_granted_at`을 NULL로 되돌리며 주석은 "다음 호출에서 재시도"라고 하지만, 다음 호출은 L172에서 `completed_at`이 있어 바로 끝난다. 또 배지 insert가 성공한 뒤 `awardPoints`가 실패하면 배지만 있고 100P는 없는 상태가 남는다(한 트랜잭션이 아님).

## 완료 조건
- `completed_at`이 있고 `skipped_at`이 없고 `reward_granted_at`이 NULL이면 다음 호출에서 지급을 다시 시도한다(단위 테스트: 23503 실패 → 롤백 → 두 번째 호출에서 지급).
- 연속 2회 호출에도 배지·포인트는 1회만 나간다(단위 테스트).
- 배지는 발급됐는데 포인트가 실패한 경우의 처리 방침을 정해 구현하거나 기록한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 순수 함수 `shouldRetryQuestReward(completedAt, skippedAt, rewardGrantedAt)`를 추가하고, 진행 행 조회에 `reward_granted_at`을 넣었다. `completed_at` 있음 + `skipped_at` 없음 + `reward_granted_at` NULL이면 활동 조회 없이 `grantOnboardingQuestReward`를 다시 부른다.
- 1회 지급 보장은 기존 `reward_granted_at` 조건부 선점(`.is(null)`)과 배지 23505 처리가 그대로 맡는다.
- 배지는 발급됐고 포인트만 실패한 경우: **재시도 없이 수동 재지급**(A안). `awardPoints`가 `engine_decision_log`에 `point_award_failed`(sourceBadgeId 포함)를 남기므로 운영에서 재지급한다. 배지 삭제 후 전체 롤백(B)은 부작용 되돌리기 위험으로, 자동 재시도(C)는 RPC 커밋 뒤 응답 유실 시 100P 이중 지급 위험으로 기각. 방침은 `grantOnboardingQuestReward` 주석에 기록했다.
