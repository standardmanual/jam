# [Feature] 라이브 운영 체계 구현 (07 블루프린트) 상위

> 2026-09-30 사용자가 `jam-doc/planning/business-plan/07 JAM! 라이브 운영 블루프린트.md`를 승인하고, 10절의 추천 순서대로 단계마다 새 세션에서 진행하기로 했다. 과정 기록과 근거는
> `jam-doc/planning/business-plan/06 JAM! 라이브 운영 플랜.md`, 이전 인수인계는 티켓 20260929_2226에 있다.

## 핵심 요약

- 요구사항: 에이전트가 정기 루틴으로 운영 기획안을 제출하고, 사용자가 AI를 쓰지 않는 어드민 운영툴에서 보고 승인하거나 직접 고치면,
  툴이 예약 공개하고 모든 결정을 기록한다(07 1~5절).
- 구현 계획: 07 6절 인벤토리를 아래 하위 티켓으로 나눴고, 07 10절 순서로 진행한다. 하위 티켓마다 새 세션에서 시작하고 아래 진행 규칙을 따른다.
- 관련 문서: 07 블루프린트(설계 정본), 06 플랜(과정 기록과 근거), 티켓 20260929_2226(이전 인수인계).

## 진행 규칙 (모든 하위 티켓에 적용, 사용자 지시 2026-09-30)

1. **한국어로 소통한다.** 대화, 질문, 보고, 커밋 메시지, 문서, 코드 주석을 모두 한국어로 쓴다(CLAUDE.md 절대 규칙 1).
2. **하위 티켓 하나를 새 세션 하나에서 진행한다.** 새 세션에서 「라이브 운영 다음 단계 시작」이라고 하면, 카리나가 아래 표에서 선행 조건이
   충족된 OPEN 티켓 가운데 가장 앞선 것을 골라 사용자에게 확인한다. 특정 티켓을 지정하려면 「티켓 <ID> 시작」이라고 한다. 컨텍스트
   사용량이 40%를 넘으면 인수인계를 남기고 새 세션으로 넘긴다.
3. **시작할 때 혜린이 먼저 검토하고 사용자에게 질문한다.** 카리나는 하위 티켓의 핵심 요약과 07의 관련 절을 혜린(`jam-pm`)에게 넘긴다.
   혜린은 가정 목록을 먼저 보이고, 질문을 한 번에 하나씩 추천·이유와 함께 사용자에게 묻는다. 사용자의 답을 하위 티켓의 「주요 의사결정」에
   적고 구현 계획을 확정한 뒤에만 작업을 시작한다.
4. **이미 개발한 것에 영향이 있으면 별도 티켓으로 바로 실행한다.** 진행 중 변경이 이미 개발된 기능·문서·예약 루틴에 영향을 주면, 그 자리에서
   새 티켓을 만든다(`parent: "20260930_1450"`). 핵심 요약·관련 파일·완료 조건을 채워 곧바로 `/jam-work`로 실행할 수 있게 하고, 지금
   단계의 티켓에 섞지 않는다. 만든 티켓은 아래 「영향 티켓」 표에 한 줄로 추가한다.
5. **07 블루프린트가 설계 정본이다.** 07과 다르게 가야 하면 사용자 승인을 받고 07을 먼저 고친다.
6. **DB 변경은 마이그레이션 파일로 남기고, 사용자 승인 뒤 메인 세션만 실행한다**(CLAUDE.md 절대 규칙 6).
7. **전환 전까지 지금 운영을 멈추지 않는다.** 화요일 주간 루틴과 지금의 홈피드 등록 절차는 1504가 새 체계로 바꿀 때까지 그대로 돈다.
