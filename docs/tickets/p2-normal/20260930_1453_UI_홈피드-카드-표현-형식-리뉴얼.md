# [UI] 홈피드 카드 표현 형식 리뉴얼

> 상위: 20260930_1450 · 순서 1 병행(설계) · 3 병행(구현) · 07 인벤토리 F

## 핵심 요약

- 요구사항: 홈피드 카드의 표현 형식을 지금의 개발 버전(템플릿·레이아웃, 유형 카탈로그 T01~T17)에 매이지 않고, 새 운영 컨텐츠(미션·드랍·
  레시피·JAM! 배지·연재)에 맞춰 새로 만든다(07 5.3, 06 6.4·12.4의 1).
- 구현 계획: 두 단계다. 설계는 채원이 순서 1과 함께 하고 사용자 승인을 받는다. 구현은 아현이 순서 3과 함께 한다.
- 관련 파일: `docs/specs/prd/home-feed/PRD.md`(표는 생성 구간, `node scripts/gen-home-feed-doc.mjs`), `jam-web/src/app/(main)/TodayCardStack.tsx`,
  기사 화면 `jam-web/src/app/(main)/today/[cardId]/`, 어드민 미리보기 `jam-web/src/app/admin/today/TodayPreviewModal.tsx`, 티켓 20260929_1335(설명문 칸).
- 관련 티켓: 20260927_2235(칩 라벨 공용화)·20260927_2236(눌림 애니메이션 동작 줄이기)·20260928_1647(카드 레이아웃 회귀 검증)은 이 티켓
  구현 뒤로 미룬다(2026-09-30 티켓 20260930_1451 사용자 결정).

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**

- 06 3.1의 「큰 새 기능 금지」는 새 메뉴를 만들지 말라는 원칙이다. 이 작업은 기존 홈피드 메뉴의 리뉴얼이다.

## 완료 조건

### 설계 (순서 1과 함께)
- 채원의 사전 판정과 새 카드 형식 목록(자원별 표현, 레이아웃, 이미지 규칙)을 사용자가 승인했다.
- 기존 카드 노출·열람 계측(`content_type_id`, 어드민 `today/metrics`)을 패턴별 결과와 어떻게 잇는지 정해 이 티켓에 적었다
  (2026-09-30 티켓 20260930_1451 사용자 결정으로 추가).
- 「요일마다 전원 카드는 큰 카드(`large_thumbnail`)」 요건을 새 형식에서 어떻게 할지 정해 운영툴 PRD §5.1에 적었다.
  새 목표는 「매일 새 컨텐츠, 단조롭지 않은 홈」이다(2026-09-30 티켓 20260930_1452 사용자 결정으로 추가). 요건의 출처는 0809가 아니라
  티켓 20260926_1542와 content-automation PRD §8이다(2026-09-30 혜린 검토 D1로 정정).

### 구현 (순서 3과 함께)
- 새 형식의 카드가 홈에 게재되고, 어드민 미리보기가 같은 형식을 보여 준다.
- 새 형식의 카드는 DB에 저장된 카드 행 없이 표시용 데이터만으로 그릴 수 있다(1501이 승인 전 초안을 미리보기로 그린다, 2026-09-30 혜린 검토 A10).
- 홈피드 PRD의 생성 구간이 새 형식으로 갱신됐다.
- 노출 시간대 태그 `time_dawn`의 범위(00~06시, `jam-web/src/lib/today/exposure.ts` 35줄, 홈피드 PRD 138줄)가 심야를 포함한다. 운영 패턴 사전은 심야를 22:00~05:00, 새벽·이른 아침을 05:00~08:00(KST)로 정의하고 `time_dawn`을 새벽 조건의 근거로 쓰지 않는다. 구현 때 태그 범위나 이름을 이 정의에 맞출지 정한다(2026-09-30 티켓 20260930_1454 윈터 검수로 추가).

### 1. 모양 5개 (결정 1·11)

| 식별자 | 이름 | 이미지 | 대표 카드 후보 | 모습 |
|---|---|---|---|---|
| `hero` | 큰 이미지 | 16:9, 새로 제작(1280×720) | 예 | 이미지가 위, 흰 본문이 아래. 기사 카드도 이 모양이다(끝 줄 「기사 읽기 →」, 칩 줄 끝에 게재일) |
| `poster` | 포스터 | 4:5, 새로 제작(1024×1280). 아래 40%에는 이미지 속 글자를 두지 않는다 | 예 | 이미지가 카드 전체이고, 아래쪽 어두운 막 위에 흰 글자. 막은 글자 블록 첫 줄에서도 진하기 60% 이상 |

| `brief` | 짧은 소식 | 64px 정사각 썸네일 또는 자원 아이콘(커버가 아니다) | 아니오 | 한눈에 읽는 작은 카드, 최소 높이 88px |
| `list` | 목록 | 64px 타일(커버가 아니다) | 아니오 | 배지·재료 가로 타일형, 또는 랭킹 행형(행마다 프로필 링크, 카드 전체 링크 없음). 타일이 0개면 `brief`로 그린다 |

- 이미지가 있는 모양은 `hero`·`poster`·`square`, 이미지가 없는 모양은 `brief`·`list`다(07 4.2 신호의 「이미지가 있는 모양」).
- 모양은 자원마다 고정하지 않고, 컨텐츠의 특성(이미지 비율, 정보량)에 따라 카드마다 고른다(결정 13). 아래 2의 자원별 모양은 기본 추천이다.
  예외: 기사는 기사 화면과 커버 한 장을 같이 쓰므로 `hero`로 고정한다.

### 3. 글자 배치 (360 기기 카드 폭 328px 기준)

| 요약 | 16px `/60`, 30자, 2줄 | 없음 | 선택 | 없음 | 16px `/60`, 30자, 2줄 |

- 이미지가 제목을 말하는 카드(「이미지에 제목 있음」 표시)는 화면 글자에서 제목·요약을 빼고 필수 정보를 놓는다. 제목은 스크린리더용으로 남기고,
  이미지 로드에 실패하면 제목을 보인다(결정 6). 옛 미션 소개 카드는 커버 주소가 연결 미션의 `image_url`과 같으면 저장 없이 「제목 있음」으로 본다(결정 12).
- 옅은 글자는 `/60` 이상으로 한다. 지금 「자세히 보기 →」의 `/40`은 흰 카드에서 약 2.85:1이라 AA에 못 미친다.
- 희귀도는 배지 목록과 같은 색 칩(`RarityBadge size="md"`)이고, Common은 칩이 없으며 등급이 없는 무한레벨형은 이름만 보인다(결정 8).
  미보유 배지는 흑백, 유저 정보가 없는 미리보기는 컬러로 그린다.
- 이미지 alt는 제목이 화면 글자로 보이면 빈 값, 이미지에만 있으면 제목이다.
- 큰 카드 사이에 작은 카드를 최소 1장 끼우는 것을 편성 원칙으로 권한다(신호는 07 4.2 「겹침」).

### 5. 이미지 규칙

- 에셋 생성기 비율에 16:9(1280×720)를 더한다(결정 0). `resolveStageSize`에 명시 분기를 두고, 프리셋 저장 API의 허용 값과 DB CHECK(185)를 함께 바꾼다.
  홈피드용 16:9·4:5 프리셋은 새로 배치한다(1:1 프리셋을 변환할 수 없다). 지금 글자수 가이드(제목 11자·설명 22자)는 1:1 실측값이라 새 비율에서 다시 잰다.
- 미션 이미지(1:1)는 `hero`·`poster`에 넣지 않는다. 16:9로 자르면 위아래의 미션 이름·로고가, 4:5로 자르면 좌우 첫 글자가 잘린다. `square`나 `brief`로 쓴다.
- 옛 1:1 홈피드 커버는 옛 카드에서만 16:9·4:5로 잘려 보이는 것을 허용하고, 같은 방식으로 새로 만들지 않는다.

### 7. 기사 화면 (결정 2·10·14)

- TopNav: 제목 「투데이」(`d.today.cardStackTitle`), 뒤로 `/`, `headerStyle` 없음. 동기화 버튼·알림 종·아바타가 다른 상세 화면처럼 붙는다.
- 머리 이미지는 TopNav 바로 아래에 16:9(`aspect-video`, `priority`)로 붙는다. 이미지 아래 「← 오늘로」 링크를 빼고 본문 위 간격을 `pt-24` 하나로 통일한다.
  링크가 빠지면 `d.todayCard.backToToday`는 사용처가 없어진다.
- 본문을 표시 데이터만 받는 `ArticleView`로 빼서 운영툴 미리보기(1501)도 쓰게 한다. 미리보기에는 실제 TopNav를 넣지 않고 바 모양만 정적으로 그린다.

### 8. 구조·디자인 시스템 판정 (채원 사전 판정, 결정 15)

- 카드 그리기를 jam-web/src/components/today/ 폴더(서비스 공용, 아직 없음)로 옮기고, 표시 데이터 변환은 순수 함수(`toCardView`·`resolveShape`·`buildFacts`)로
  `jam-web/src/lib/today/`에 둔다. 서버 조회와 운영툴 초안 미리보기가 같은 함수를 쓴다. 5개 모양은 서비스 전용이다(MODULAR 승격은 운영 2~4주 뒤 재판정).

  선택 값은 `subtitle`·`description`·`facts`(최대 2)·`href`·`publishedAt`·`titleInImage`·`now`다. 카드 ID·활성 여부·노출 기간·정렬 순서·유저별 보유 여부
  없이도 그려져야 한다. 미리보기 폭은 360과 430을 전환한다.
