# [UI] 홈피드 카드 표현 형식 리뉴얼

> 상위: 20260930_1450 · 순서 1 병행(설계) · 3 병행(구현) · 07 인벤토리 F

## 핵심 요약

- 요구사항: 홈피드 카드의 표현 형식을 지금의 개발 버전(템플릿·레이아웃, 유형 카탈로그 T01~T17)에 매이지 않고, 새 운영 컨텐츠(미션·드랍·
  레시피·JAM! 배지·연재)에 맞춰 새로 만든다(07 5.3, 06 6.4·12.4의 1).
- 구현 계획: 두 단계다. 설계는 채원이 순서 1과 함께 하고 사용자 승인을 받는다. 구현은 아현이 순서 3과 함께 한다.
- 관련 파일: `docs/specs/prd/home-feed/PRD.md`(표는 생성 구간, `node scripts/gen-home-feed-doc.mjs`), `jam-web/src/app/(main)/TodayCardStack.tsx`,
  기사 화면 `jam-web/src/app/(main)/today/[cardId]/`, 어드민 미리보기 `jam-web/src/app/admin/today/TodayPreviewModal.tsx`, 티켓 20260929_1335(설명문 칸).
- 관련 티켓: 20260927_2235(칩 라벨 공용화)·20260927_2236(눌림 애니메이션 동작 줄이기)·20260928_1647(카드 레이아웃 회귀 검증)은 이 티켓
  구현 뒤로 미룬다(2026-09-30 티켓 20260930_1451 사용자 결정).

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

## 고려할 것

- 06 3.1의 「큰 새 기능 금지」는 새 메뉴를 만들지 말라는 원칙이다. 이 작업은 기존 홈피드 메뉴의 리뉴얼이다.
- 운영툴의 미리보기(1501)가 같은 형식을 보여 줘야 한다.
- 지금의 주간 루틴 홈피드 초안(윤진 ⑧, 홈피드 프리셋)과 카드 등록 절차가 영향을 받는다. 진행 규칙 4에 따라 별도 티켓으로 다룬다.

## 완료 조건

### 설계 (순서 1과 함께)
- 채원의 사전 판정과 새 카드 형식 목록(자원별 표현, 레이아웃, 이미지 규칙)을 사용자가 승인했다.
- 기존 카드 노출·열람 계측(`content_type_id`, 어드민 `today/metrics`)을 패턴별 결과와 어떻게 잇는지 정해 이 티켓에 적었다
  (2026-09-30 티켓 20260930_1451 사용자 결정으로 추가).
- 「요일마다 전원 카드는 큰 카드(`large_thumbnail`)」 요건을 새 형식에서 어떻게 할지 정해 운영툴 PRD §5.1에 적었다.
  새 목표는 「매일 새 컨텐츠, 단조롭지 않은 홈」이다(2026-09-30 티켓 20260930_1452 사용자 결정으로 추가). 요건의 출처는 0809가 아니라
  티켓 20260926_1542와 content-automation PRD §8이다(2026-09-30 혜린 검토 D1로 정정).

### 구현 (순서 3과 함께)
- 새 형식의 카드가 홈에 게재되고, 어드민 미리보기가 같은 형식을 보여 준다.
- 새 형식의 카드는 DB에 저장된 카드 행 없이 표시용 데이터만으로 그릴 수 있다(1501이 승인 전 초안을 미리보기로 그린다, 2026-09-30 혜린 검토 A10).
- 홈피드 PRD의 생성 구간이 새 형식으로 갱신됐다.

**사용자 결정 0 (2026-09-30, 세션 시작 때).** 사용자가 「기존 이미지 크기에 16:9 비율을 추가한다」고 지시했고, 지금 코드를 바꾸지 않고
이 티켓의 설계 조건으로만 반영하기로 했다(구현은 순서 3). 시작 시점에 확인한 사실은 다음과 같다.

- 어드민 에셋 생성기가 만드는 비율은 1:1·4:5·9:16 세 가지다(`jam-web/src/lib/asset-generator/types.ts` 24줄,
  크기 계산은 `jam-web/src/app/admin/asset-generator/assetGeneratorHelpers.ts`의 `resolveStageSize`).
- DB 프리셋 표 `asset_presets.stage_ratio`는 CHECK 제약으로 세 값만 허용한다(`jam-web/supabase/migrations/185_asset_presets.sql` 52~53줄).
- 홈 화면의 표시 비율은 큰 썸네일 카드 16:9(`jam-web/src/app/(main)/TodayCardStack.tsx` 97줄), 배너 카드 4:5(201줄),
  기사 화면 머리 이미지 16:10(`jam-web/src/app/(main)/today/[cardId]/page.tsx` 41줄)이다.
- 이 결정은 티켓 20260926_1548의 「1:1 유지, 잘림 허용, 16:9 프리셋은 만들지 않는다」를 대체한다(1548은 CLOSED라 고치지 않는다).

**혜린 시작 검토 (2026-09-30).** 파일에서 확인한 사실과 어긋난 점은 다음과 같다.

- 16:9 추가가 걸리는 곳: 에셋 생성기 비율 타입과 `resolveStageSize`(명시 분기가 없으면 9:16으로 처리한다), 프리셋 저장 API의 허용 값 목록
  (`jam-web/src/app/api/admin/asset-generator/presets/route.ts` 35·92줄), DB CHECK(185), 비율별로 따로인 프리셋(1:1 프리셋을 변환할 수 없다).
  홈피드 프리셋 id와 글자수는 윤진 정의에 고정돼 있으나, 1519가 10/6 전에 루틴의 이미지 단계를 끄므로 지금 루틴과 충돌하지 않는다.
- 카드 커버와 기사 머리는 같은 `cover_image_url` 한 장을 쓴다. 미션 소개 카드는 항상 큰 카드이고 커버는 `missions.image_url`(정사각형)을 재사용하며,
  코드가 이를 강제한다(content-automation PRD 208~213줄).
- 어드민 미리보기는 홈과 같은 `TodayCardStack`을 쓰지만 저장된 카드만 날짜로 조회해 그린다. 승인 전 초안을 그리는 경로는 없다.
- `template_type`·`layout_type`·`content_type_id`에 DB CHECK가 있어 새 값은 마이그레이션이 필요하다. 옛 코드가 목록 밖 템플릿 값을 만났을 때의 동작은
  확인하지 않았다.
- 계측 이벤트는 기록 시점의 유형 ID 복사본을 저장한다(183). 집계는 API 하나(`jam-web/src/app/api/admin/today/metrics/route.ts`)뿐이고 어드민 화면은
  없다. 소비자는 카즈하 브리핑과 윤진의 전략 변경안·유형 리뷰다.
- 어긋난 점:
  - D1. 「전원 카드는 큰 카드」 요건의 출처는 0809가 아니라 티켓 20260926_1542와 content-automation PRD §8이다. 1542에서 사용자 요청
    「요일마다 `large_thumbnail` 카드 최소 1개」를 전원 카드에 건다고 해석했고, 사용자 답 없이 진행했다. 운영툴 PRD §5.1과 이 티켓의 표기를 정정한다.
  - D2. 계측 이음 조건이 이 티켓과 1503에 같은 문장으로 있다. 이 티켓이 정하고 1503은 참조한다.
  - D4. 1501의 선행 조건이 「홈피드 카드는 1453」인데 상위 표 순서 3 행에는 1453이 없다. 순서 3 안에서 「1453 구현 → 1501 카드 미리보기」로 메모한다.
  - D7. 미션 소개 카드 규칙(항상 큰 카드 + 미션 이미지)도 큰 카드 요건과 같은 뿌리라 질문 3에서 함께 정한다.
  - D8. 관련 파일의 1335(설명문 칸)는 1451에서 완료로 닫혔다. 새 형식이 이어받는 기존 기능이다.

**확인하지 않은 가정.** A1 이번 세션은 문서와 결정만 기록한다. A2 16:9는 에셋 생성기에 1280×720으로 더하고 기존 세 비율과 이미 만든 이미지는 그대로 둔다.
A3 홈 카드에서 16:9는 큰 이미지 카드와 기사 머리, 4:5는 포스터 카드에 쓰고 1:1·9:16은 쓰지 않는다. A4 옛 1:1 이미지는 다시 만들지 않는다.
A5 범위는 투데이 카드 전체와 기사 머리이고, 온보딩 퀘스트 카드와 오늘의 현황 줄은 제외한다. A6 랭킹보드·컬렉션 소식·자동 카드도 형식 목록에 넣는다.
A7 연재는 별도 자원이 아니라 기존 자원의 이어짐이고, 카드에 「몇 막·남은 시간」으로 나타낸다. A8 이동 목적지·새 메뉴 없음·흑백 원칙을 지키고 모양만 바꾼다.
A9 계측에 유저 식별자를 저장하지 않고 옛 T01~T17 기록은 지우지 않는다. A10 새 카드는 저장된 카드 행 없이 표시용 데이터만으로 그릴 수 있어야 한다(1501 미리보기).
A11 이미지는 승인 때 만들므로 승인 전까지 모양을 바꿀 수 있다. A12 설계 승인 대상은 형식 목록·자원별 대응표·이미지 규칙·옛→새 대응표·글자 배치도이고
시안 이미지는 만들지 않는다. A13 경제 수치 변경이 없어 시뮬레이터 검증은 하지 않고, 카드 문구에 세계관 문장이 들어갈 때만 윈터가 확인한다.
A14 07 4.2의 신호 초기값은 바꾸지 않는다. 사용자는 가정 A1~A14에 이의를 달지 않았다.

**07 수정 (2026-09-30, 사용자 승인, 진행 규칙 5).** 결정 3을 신호에 반영하려고 07 4.2 문단에 대표 카드 규칙 한 문장을 더하고, 기존 신호 두 개의
조건을 넓혔다(새 신호는 추가하지 않았다). 「비어 있는 컨텐츠」(주의)에 「이미지가 없는 모양으로 편성된 대표 카드」를, 「단조로운 흐름」(참고)에
