# [Content] 운영 패턴 사전 초안과 초기 데이터

> 상위: 20260930_1450 · 순서 1 병행(원고) · 4(툴 입력) · 07 인벤토리 J

## 핵심 요약

- 요구사항: 06 5절의 채택 아이디어 63개에서 작동 원리를 뽑아 운영 패턴 15~20개로 묶는다. 에이전트가 이 패턴을 익혀 매주 새로운 운영을
  기획하는 재료다(07 3.4, 06 10.2).
- 구현 계획: 두 단계다. 원고는 윤진·윈터가 순서 1과 함께 쓰고 사용자 승인을 받는다. 툴 입력은 1503(패턴 사전 기능) 뒤에 한다.
- 관련 파일: 06 플랜 5절(통합표와 폐기 목록)·4.3(유저 루프 층)·6.2(옵션), 07 3.4·3.6.

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

## 패턴마다 적을 것

작동 원리, 쓰는 메뉴와 옵션(O#), 조절 손잡이(조건·장소·시간·보상·트라이브), 샘플(06 5절 번호), 주의점(윤리 원칙, 파밍), 「유저가 겪는 것」
쉬운 한 문장, 취향 신호(06 폐기 목록에서 옮긴 "다시 제안하지 않을 방향").

원고를 둘 위치는 1452의 「패턴 사전 문서 표기」 결정을 따른다.

## 완료 조건

- 패턴 15~20개 원고를 사용자가 승인했고, 채택 아이디어 63개가 모두 어느 패턴의 샘플로 들어가 있다(대조표).
  원고는 `jam-doc/planning/content/`에 새 문서로 두고, 패턴 한 건의 항목은 운영툴 PRD §10 「패턴 사전」 행을 따른다.
  CLAUDE.md 문서 체계 표의 ③ 컨텐츠 행과 `/jam-docs` ③에 이 문서를 더하는 설정 변경은 카리나가 제안해 승인받는다(2026-09-30 티켓 20260930_1452 사용자 결정으로 추가).
- 툴 입력 뒤 원고 문서의 머리말을 `source_of_truth: db`와 입력일 `snapshot`으로 바꿨다(운영툴 PRD §10.1)(2026-09-30 티켓 20260930_1452 사용자 결정으로 추가).
- 1503 완료 뒤 패턴이 툴에 입력되어, 조합 뽑기 API가 패턴을 돌려준다.
- 패턴의 「쓰는 카드 모양」은 티켓 1453 「확정 설계」의 모양 식별자 5개(`hero`·`poster`·`square`·`brief`·`list`)로 적는다(2026-09-30 티켓 20260930_1453 설계 결정으로 추가).

**혜린 시작 검토 (2026-09-30).** 파일에서 확인한 사실과 문서끼리 어긋난 점은 다음과 같다.

- 06 5절 통합표(161~223줄)의 채택 아이디어는 63개(유지 45, 수정 유지 18)로 티켓과 같다. 제외 번호는 20개(4·5·10·23·26·27·35·36·37·51·52·58·66~70·81~83)이고,
  63+20으로 1~83번이 빠짐없이 나뉜다. 06 4.3의 다섯 층(6+11+18+20+8)도 63개이고 번호가 표와 일치한다.
- 폐기 목록은 두 덩어리, 합쳐서 43개다. 「2·3차 판정」 23개는 이름만 있고 번호·설명·판정 이유가 없다(가운뎃점 묶음을 나누면 최대 25개).
  「통합표 판정」 20개는 위 제외 행이다.
- 구현 열은 혜린 집계로 「지금 가능」 31개, 「옵션 필요」 32개이고, 옵션이 필요한 것 가운데 O5가 12개다.
- 어긋난 곳 3가지(원고 승인 뒤 카리나가 처리를 정한다):
  - 06 10.2의 1번은 패턴 형식을 「콘텐츠_기획_레퍼런스.md(15줄 상한)」로 적었다. 1452 결정(운영툴 PRD §10.1)이 나중이므로 PRD §10 행을 따른다.
  - 06 10.2의 4번 예시(앙코르 따라잡기·택1 의뢰서·슬롯 가림)는 5절 폐기 이름과 표기가 다르다. 취향 신호는 5절 이름으로 적는다.
  - 이 티켓의 「패턴마다 적을 것」은 PRD §10 「패턴 사전」 행보다 넓다(쓰는 메뉴·옵션, 「유저가 겪는 것」, 쓰는 카드 모양). PRD §10과 1503에 넣을지는
    원고 승인 뒤 정한다. 1503은 개발 전이라 영향 티켓은 만들지 않는다.

**가정 (사용자가 수정 없이 받아들임, 2026-09-30).**

1. 원고 파일은 `jam-doc/planning/content/OPS_PATTERNS.md`다. 머리말은 `type: catalog`, `source_of_truth: doc`이고 태그는 기존 어휘만 쓴다.
   툴 입력 뒤 `db`와 `snapshot`으로 바꾼다. 문서 체계 표 ③ 행과 `/jam-docs` ③에 더하는 설정 변경은 카리나가 따로 제안한다.
2. 묶는 기준은 작동 원리(유저의 어떤 행동을 어떻게 움직이는가)다. 06 4.3의 층과 메뉴는 패턴마다 붙는 표시다. 패턴은 18개 안팎이고
   샘플이 2개 미만인 패턴은 만들지 않는다. 샘플은 주 패턴 한 곳에만 세고, 걸치면 「보조」로 적는다(07 3.5: 항목 하나에 패턴 번호 하나).
3. 패턴 한 건의 항목: 이름(쉬운 말), 작동 원리, 「유저가 겪는 것」 한 문장, 쓰는 메뉴·옵션(샘플마다 「지금 가능/옵션 필요」), 손잡이 5종
   (조건·장소·시간·보상·트라이브), 샘플 번호, 주의점(윤리·파밍), 쓰는 카드 모양(1453의 식별자 5개 또는 없음), 취향 신호, 상태(승인 대기).
4. 장소 손잡이는 06 6.1의 지점 카테고리 이름을 쓴다. 트라이브 손잡이는 활성 트라이브가 아니라 캐논 전체를 기준으로 한다.
5. 윤진이 분류와 초안을 쓰고(카드 모양은 1453 「자원별 기본 추천」을 옮긴다), 윈터가 세계관·금기를 검수하며 트라이브 손잡이 예시를 쓴 뒤, 윤진이 반영한다.
6. 확률과 등급 비율을 바꾸는 손잡이는 열지 않는다. 32 트라이브 바람과 43 등급 물결 주간은 「어느 컬렉션·트라이브 것을 뿌릴지」 손잡이만 적는다(07 3.6).
7. 폐기 43개는 가장 가까운 패턴의 취향 신호로 붙이고, 맞는 곳이 없으면 문서 끝 「공통 취향 신호」에 모은다. 수정 유지 18개에 담긴 사용자 의견은 해당 패턴의 주의점으로 옮긴다.
8. 대조표는 문서 끝 부록 표 1개(번호 | 이름 | 주 패턴 | 보조 | 구현 상태, 63행)다. 샘플 번호의 원천은 패턴 본문이고 대조표는 그 역표임을 문서에 밝힌다.
   63개가 한 번씩 들어갔는지는 카리나가 기계로 대조해 완료 기록에 남긴다.

**사용자 결정 (2026-09-30).**

- Q1 상시 장치 6개(25 드랍 주워짐 알림, 40 돌아온 날 알림, 42 최초 발급자 칩, 45 발자국 온도, 46 획득 배지 끝 카드, 48 컬렉션 등급 칩):
  **이웃 패턴의 「보조 장치」 샘플로 붙인다.** 63개가 모두 들어가고, 사전에 있는데 못 쓰는 패턴이 생기지 않으며, 툴에 새 항목이 필요 없다.
- Q2 승인 방식: **두 번에 나눈다.** 먼저 「패턴 이름 + 한 줄 원리 + 63개 번호의 배치」 뼈대 표를 승인받고, 그 뒤 본문을 쓴다.
- Q3 폐기 이유: **윤진이 이름에서 문제였던 방향을 한 줄로 추정하고 「추정」 표시를 단다.** 본문 승인 때 틀린 것만 고친다.
