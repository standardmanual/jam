# [Admin] 운영툴 골격

> 상위: 20260930_1450 · 순서 2 · 07 인벤토리 A

## 핵심 요약

- 요구사항: 운영툴의 바탕을 만든다. 운영 묶음·항목·결정 기록 데이터, 기획안 제출 API, 받은 기획함(S2), 기획 상세(S3)의 단계 표시줄과
  상태 흐름, 한 주 묶음 일괄 승인, 직접 수정과 결정 기록, 슬랙 이력 알림, 오른쪽 서랍의 틀(07 4.1·4.3·4.4·4.6·4.7·4.8·4.9).
- 구현 계획: 1452의 운영툴 PRD를 따른다. 자원을 실제로 만드는 일은 1500, 미리보기는 1501, 운영 홈·일정표·신호는 1502에서 한다.
- 관련 파일: `jam-web/src/lib/admin/auth.ts`(`requireAdminRead`, 지금 GET 전용이다. 받은 기획함 제출 경로 하나에만 쓰기 예외를 둔다),
  `jam-web/src/app/admin/`, `jam-web/src/app/api/admin/`, `scripts/slack-post.mjs`(게시 방식 참고), 등록 묶음 형식 `docs/specs/prd/asset-generator/`.

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

## 주의

- staging과 프로덕션이 DB 하나를 쓴다. 새 테이블은 마이그레이션 파일로 남기고 사용자 승인 뒤 메인 세션이 실행한다.
- 자동화 토큰의 쓰기 예외는 민지의 보안 점검을 받는다. 토큰으로는 받은 기획함에만 쓸 수 있어야 한다(07 4.9).
- 화면은 채원의 사전 판정을 받는다. 쉬운 문장, 단계 표시, 오른쪽 서랍 원칙을 따른다(07 4.1).

## 완료 조건

- 손으로 만든 샘플 운영 묶음을 제출 API로 넣으면 받은 기획함에 뜨고, 슬랙 `#jam-report`에 도착 이력이 온다.
- 기획 상세에서 단계 표시줄을 보며 승인·반려·직접 수정을 할 수 있고, 각 행동이 결정 기록(누가·언제·무엇을·수정 전후 차이·사유)에 남는다.
- 자동화 토큰으로 받은 기획함 밖에 쓰려는 요청은 거부된다(테스트).
