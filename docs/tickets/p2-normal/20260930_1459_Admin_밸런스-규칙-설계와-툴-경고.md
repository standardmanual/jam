# [Admin] 밸런스 규칙 설계와 툴 경고

> 상위: 20260930_1450 · 순서 2 병행(설계) · 3(툴 경고) · 07 인벤토리 H

## 핵심 요약

- 요구사항: 혜린이 밸런스 규칙(동시 개방 컬렉션 수, 개방 속도, 포인트 크기, 파밍 방지)과 초기값을 설계하고, 툴이 AI 없이 그 규칙으로
  경고를 띄운다(07 3.6·4.2·S7, 06 12.4의 2·5).
- 구현 계획: 두 단계다. 규칙 설계는 2026-10-01 사용자가 승인했다(아래 「규칙표」). 1단계는 07과 운영툴 PRD에 규칙을 적는 일이고,
  2단계는 툴 경고(조각 A), S7 밸런스 구역(조각 B), 1502 신호 기준값의 S7 이전(조각 C)을 `/jam-work`로 만드는 일이다(아래 「구현 계획」). 혜린의 「주간 밸런스 점검」
  모드 정의는 1504에서 한다.
- 관련 파일: 06 플랜 3.1(포인트 원칙)·6.2(O5 계산 방식), 07 4.2(신호 「밸런스 경고」)·4.7·4.8, `docs/service/prd/ops-tool/PRD.md`
  §5·§6·§10·§11·§13, `jam-web/src/components/admin/ops/OpsItemDetail.tsx` 166~178행(「밸런스 판정」 표시 자리),
  `jam-web/src/lib/admin/opsInbox/query.ts`, `jam-web/src/app/api/admin/simulate/route.ts`(드랍 상수가 v1이라 근거로 쓰지 않는다,
  20261001_1219).

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

## 주의

- 경제 수치에 닿는 규칙은 시뮬레이터 실측값을 근거로 쓴다(혜린 원칙). 시뮬레이션이 없으면 없다고 적는다.
- 드랍 확률과 포인트 보상 체계 자체는 바꾸지 않는다(07 3.6).

## 규칙표 (사용자 승인 2026-10-01)

경고 수준은 모두 「주의」이고 승인을 막지 않는다. 수치를 읽을 수 없는 항목은 「점검 못 함」(참고)으로 보인다. 「임시값」은 화면에
「임시값·실측 전」 표시가 붙고, 실측 티켓 20261001_1220이 끝나면 다시 정한다. 1단계가 끝나면 이 표의 원천은 운영툴 PRD §5.2다.

### 조각 A 파일 단위 계획 (2026-10-01 확정, 마이그레이션 번호 207 예약)

1. **마이그레이션** `jam-web/supabase/migrations/207_ops_rules.sql`(새 파일). 착수할 때 최신 staging에 207이 이미 있으면 다음 빈 번호를 쓰고
   이 줄을 고친다. 실행은 민지 판정 뒤 사용자 승인을 받아 카리나가 한다.
   - 테이블 `ops_rules`: `rule_key text PRIMARY KEY`, `rule_group text NOT NULL CHECK (rule_group IN ('balance','signal'))`,
     `value jsonb NOT NULL`, `level text NOT NULL CHECK (level IN ('info','warn'))`(참고·주의), `enabled boolean NOT NULL DEFAULT true`,
     `updated_at timestamptz NOT NULL DEFAULT now()`, `updated_by text`(시드는 비움), `previous_value jsonb`. RLS를 켜고 정책은 만들지
     않는다(서비스 롤 전용, 마이그레이션 198과 같은 방식). 신호 기준값(조각 C)은 `rule_group = 'signal'`로 같은 테이블에 들어온다.
   - `value` 형식: R1~R3 `{"max": n, "provisional": true}`, R4 `{"min_days": 28, "provisional": false}`, R5
     `{"kinds": {"count_badge": {"max": 10, "provisional": true}, "achievement_badge": {"max": 100, "provisional": false},
     "mission": {"max": 50, "provisional": true}, "collection_completion": {"max": 20, "provisional": false},
     "recipe": {"max": 30, "provisional": false}}}`, R6·R7 `{}`(R5를 따른다), R8 `{"keys": [...]}`(PRD §5.2의 23개 컬럼 이름).
   - 시드: 「규칙표」의 R1~R8 8행, 모두 `rule_group = 'balance'`, `level = 'warn'`, `enabled = true`. 규칙 키는 PRD §5.2를 따른다.
   - 되돌림 SQL은 파일 끝 주석 블록에 `DROP TABLE IF EXISTS public.ops_rules;`.
2. **규칙·평가** `jam-web/src/lib/admin/opsInbox/balance/`(새 폴더)
   - `rules.ts`: 규칙 키·그룹·값 타입과 `value` 해석(형식이 틀리면 그 규칙만 「점검 못 함」), 규칙 이름·설명 문구.
   - `evaluate.ts`: 순수 함수 `evaluateBundleBalance(items, rules, state, nowIso)` → `{ warnings, unreadable, checkedRuleCountByItem }`.
     결과 한 건은 PRD §5.2의 형식(규칙 키, 수준, 항목 키 또는 비움, 문장, 잰 값, 기준값, 임시값 여부). R2·R3·R7은 항목 키를 비운다(묶음 알림).
   - `state.ts`: 서비스 상태 조회. R1은 `jam-web/src/lib/itembook/visibility.ts`의 `isItemBookDroppable`을 공개 시각 기준으로 쓴다. 다른 묶음의
     `collection_launch` 항목(시험이 아닌 묶음, 반려 제외, 만들어진 자원 ID 없음), 같은 `family_key`의 기존 배지 `point_reward`, 보상 배지의
     `point_reward`를 읽는다. 읽기 실패는 해당 규칙만 「점검 못 함」으로 넘긴다.
   - `messages.ts`: 「확정 설계」의 문구.
   - 테스트 `balance/__tests__/`: 규칙별 경계값(값과 같으면 통과, 넘으면 경고), 점검 못 함 3종, 수정본 우선, 반려 제외, 꺼진 규칙, 시험 묶음끼리 세지
     않음, R5 종류 판정(횟수형·달성형), R1 공개 시각 기준 노출 판정.
3. **조회** `jam-web/src/lib/admin/opsInbox/query.ts`: 기획 상세 데이터에 규칙 읽기와 평가 결과(항목별 경고, 묶음 경고, 확인한 규칙 수, 평가
   실패 여부)를 더한다. 평가 실패는 예외로 화면을 죽이지 않고 실패 표시로 넘긴다.

### 조각 B 파일 단위 계획 (2026-10-01 확정, DB 변경 없음)

1. **규칙 저장·검증** `jam-web/src/lib/admin/opsInbox/balance/`
   - `rules.ts`: 저장 입력 검증 함수를 더한다. R1~R3 `max`는 1 이상 정수, R4 `min_days`는 1 이상 정수, R5 `kinds`의 다섯 `max`는 0 이상 정수이고
     `provisional`은 불리언. R6·R7·R8은 값을 바꾸지 않는다(켜기·경고 수준만 바꾼다). 오류는 칸별 `fieldErrors`로 돌려준다(문구는 「확정 설계」).
   - `save.ts`(새 파일): `saveOpsRule({ ruleKey, value, level, enabled, expectedUpdatedAt, actor })`. `.eq('updated_at', expectedUpdatedAt)`로 갱신하고
     0행이면 409. 값이 바뀌면 `previous_value`에 이전 값을 넣고 `updated_by`(관리자 ID)·`updated_at`을 채운다. 「직전 값으로 되돌리기」는 화면이
     직전 값을 새 값으로 보내는 같은 저장이다.
   - `state.ts`: 조각 A 게이트 발견물 ①·②를 고친다. R1은 DB 컬렉션과 자원이 아직 없는 개방 항목을, R2·R3은 만들어진 자원 ID와 상관없이 모든
     `collection_launch` 항목을 센다(94행 근처). 평가할 `collection_launch` 항목이 없는 묶음은 컬렉션·다른 묶음 조회를 건너뛴다(193행 근처).
     열린 컬렉션 총수를 S7이 쓸 수 있게 내보낸다.
2. **API** `jam-web/src/app/api/admin/ops-rules/`
   - `route.ts` `GET`: `requireAdminRead(req)`(읽기 토큰 또는 관리자 세션). 쿼리 `group`(기본 `balance`)으로 규칙 행을 돌려준다. 혜린 주간 점검(1504)이 이
     경로로 읽는다. 쓰기 메서드는 두지 않는다.
   - `[ruleKey]/route.ts` `PATCH`: 관리자 세션(`getAdminUser()`) 전용. 본문 `{ value?, level?, enabled?, expectedUpdatedAt }`. 400(`fieldErrors`),
     404(없는 규칙), 409(충돌)를 돌려준다. 토큰 쓰기 예외를 만들지 않는다 — `src/app/api/admin/__tests__/token-write-contract.test.ts`가 그대로 통과해야
     한다. 새 인증 래퍼를 만들면 `docs/agents/contract.json`의 `deploy_gate.auth_wrappers` 규칙을 따른다.

- [기본값으로 되돌리기]는 그 칸의 행만 지우고 같은 카드 다른 칸의 입력 중 값은 남는다. 「바꾼 값 N」과 마지막 줄이 맞게 바뀐다.

- 읽기 전용 시각의 세 상태가 맞고 입력·되돌리기·저장·「바꾼 값 N」·「마지막으로 바꾼 사람」 대상이 아니다.

- `monotonyWindowDays`·`actionSpikeBaselineWeeks`를 바꾸면 신호가 읽는 데이터 범위도 바뀐다.
- 두 탭 409, 네트워크 끊김, 신호 구역 조회 실패 시 밸런스 구역 정상을 확인한다.
- 읽기 토큰으로 `GET ?group=signal`은 되고 쓰기는 막히며, 응답에 관리자 UUID가 없다.
- 기본값은 코드와 PRD 표 한 곳에만 있어 `thresholds.test.ts`가 그대로 통과하고 DB에 기본값 행이 없다.
