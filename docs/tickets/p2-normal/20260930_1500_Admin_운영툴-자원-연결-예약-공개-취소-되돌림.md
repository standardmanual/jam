# [Admin] 운영툴 자원 연결 (예약 공개·취소·되돌림)

> 상위: 20260930_1450 · 순서 3 · 07 인벤토리 C
> 선행: 20260930_1516(컬렉션 노출 판정 통일)을 먼저 끝낸다. 이 티켓이 그 판정에 기대기 때문이다(티켓 20260930_1451 결정).

## 핵심 요약

- 요구사항: 승인하면 자원을 만들고 예약 공개·취소·되돌림을 한다. 대상은 홈피드 카드, 미션, JAM! 배지, 드랍 일정, 레시피, 컬렉션 런칭이다
  (07 4.5·4.9, 06 11.7의 5).
- 구현 계획: 연결된 항목(카드와 그 카드가 여는 미션)은 함께 공개하고 함께 되돌린다. 공개 뒤에는 종료로 내린다. 같은 묶음을 두 번 실행하지
  않는다(07 9절 5·6, 4.9). 등록 전 검증은 지금 등록 스크립트의 `--dry-run` 검사를 재사용한다.
- 관련 파일: `jam-web/scripts/asset-generator/register-*.mjs`·`registerFlow.mjs`, 어드민 API `today`·`missions`·`recipes`·`ambient-drop`·`badges`·`itembooks`.

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」을 따른다. 새 세션에서 시작하고, **혜린의 검토와 사용자 질문을 거쳐 답을 이 티켓에 적은 뒤에만**
작업을 시작한다. 진행 중에 이미 개발된 것에 영향이 생기면 별도 티켓으로 떼어 바로 실행한다.

## 선행 조건

1455(골격), 1456(O5), 1457(O6), 1458(O16).

## 주의

- 지금의 등록 절차(컨텐츠 자동화 PRD §8-2의 시드 SQL, 목요일 배포 때 카리나 등록)가 이 기능으로 바뀐다. 진행 규칙 4와 7에 따라 전환은
  1504에서 하고, 그 전까지 지금 절차를 유지한다.

## 완료 조건

- 자원 종류마다 샘플 항목을 승인하면 예약 공개 상태로 만들어지고, 공개 시각에 유저에게 보인다(테스트).
- 공개 전 취소가 되고, 묶음 실행 중 일부가 실패하면 연결된 항목이 함께 되돌려진다(테스트).
- 같은 묶음을 두 번 실행하면 두 번째는 거부된다.
- 형식 오류가 남은 채 승인된 항목(1455 사용자 결정 Q3: 형식 오류는 경고만 하고 승인을 막지 않는다)이 등록 전 검증에서 걸렸을 때, 그 항목만 실패로 둘지
  연결 항목까지 되돌릴지 정하고 실패 사유를 결정 기록과 화면에 보여 준다. 1455-③(티켓 20260930_1818)이 띄운 「공개는 아직 연결 전이에요」 안내를 걷어 낸다
  (2026-09-30 티켓 20260930_1455 결정으로 추가).

### 주요 의사결정 / 핵심 메모
> 시작할 때 혜린 검토에서 사용자가 답한 내용을 먼저 적는다(상위 티켓 20260930_1450 진행 규칙 3).

- 2026-10-01 1458(레시피 공개 시각) 시작 검토에서 넘긴 메모. 1500 시작 검토 때 혜린에게 함께 넘긴다.
  - 레시피는 HTTP가 아니라 서버 함수로 부른다: `createRecipeWithSlots`·`cancelScheduledRecipe`·`recipeReleaseState`(1158이 만든다). ops 항목의 `starts_at`을 `valid_from`에 넣는다.
  - 레시피에는 종료 시각이 없다. 레시피 항목에 `ends_at`이 오면 형식 오류로 처리한다. 내릴 때는 삭제다(07 5.1, 사용자 승인 2026-10-01).
  - 레시피는 시각이 지나면 저절로 보이는 상태 예약이라 실행 주체가 없다. 07 4.2의 「예약 누락」 신호(공개 시각이 지났는데 공개되지 않음)는 레시피에서 구조적으로 생기지 않는다.
  - 「이 레시피를 가장 먼저 성공」(`recipe_first_success`) 배지는 레시피와 같은 `valid_from`으로 만든다. 다르면 배지가 레시피보다 먼저 목록에 보인다.
  - 레시피 보상·슬롯 배지가 아직 열리지 않은 컬렉션 소속이면, 레시피만 열려도 그 배지를 얻을 수 있다. 「연결 항목 함께 공개」와 1516의 컬렉션 공개 판정으로 맞춘다.
  - 1457(앰비언트 드랍 예약)도 같은 다섯 동작(만들기·공개 전 취소·공개 전 시각 수정·상태 읽기·공개 후 취소 거절)을 주는지 확인한다. 시각 칸 이름은 달라도 된다.
  - 운영자 계정은 공개 전 레시피를 믹스 화면에서 보고 시험 믹스할 수 있다(1159). 화면 미리보기(1501)와 역할이 겹치는지 1501 검토 때 본다.
