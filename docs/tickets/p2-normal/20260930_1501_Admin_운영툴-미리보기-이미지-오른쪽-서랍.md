## 핵심 요약

- 요구사항: 자원별 미리보기(저장하지 않는 렌더), 오른쪽 서랍의 에셋 제너레이터와 컨텐츠 연결, 승인 때 에셋 제너레이터로 실제 이미지 생성
  (07 4.1·4.3·4.5, 06 12.4의 3).

- 관련 파일: `jam-web/src/app/admin/asset-generator/`, `jam-web/scripts/asset-generator/render.mjs`, `jam-web/src/app/admin/today/TodayPreviewModal.tsx`.

  (착수 때 함께 판단한다, 2026-09-30 티켓 20260930_1451 사용자 결정).

### 주요 의사결정 / 핵심 메모
> 시작할 때 혜린 검토에서 사용자가 답한 내용을 먼저 적는다(상위 티켓 20260930_1450 진행 규칙 3).
- 2026-10-02 1500 ①(20261001_2205) 메모(시작 검토 입력): 예약 등록은 이미지를 만들지 않고, 이미지 주소가 없으면 비운 채 예약한다(1500 G1, 운영툴 PRD §8.8). 이미지는 이 티켓의
  서랍에서 만들어 `created_resource`가 가리키는 자원에 쓰고(카드 `cover_image_url`, 미션·배지·컬렉션 `image_url`), 예약한 뒤에도 쓸 수 있어야 한다. 예약 전이면 항목의
  `resource`에 쓴다. 신호의 「이미지가 빈 항목」은 운영 항목의 `resource.cover_image_url`을 읽으므로(`opsSignals/composition.ts`의 `hasItemImage`), 예약 뒤 자원에만 쓰면
  1153·1156의 합치기 전까지 신호가 남는다. 둘 중 어느 쪽을 맞출지 시작 검토에서 정한다. 예약 등록이 실패해 되돌리거나 공개 전에 취소할 때 저장소의 이미지 파일을 정리하는
  책임은 이 티켓에 있다. 레시피 미리보기는 1159(운영자 시험 믹스)와 역할이 겹치는지 본다(1458 메모).

- 2026-10-06 시작 검토(혜린 검토, 사용자 질문 Q1~Q7 모두 추천안으로 확정):
  - **Q1 이미지 쓰는 자리: 옵션 B.** 이미지는 항상 항목의 `resource`에 먼저 붙이고, 예약된 뒤에는 `created_resource`가 가리키는 자원에도 함께 붙인다.
    신호 `hasItemImage`와 1502의 합치기 로직은 건드리지 않는다. 예약 등록이 항목의 이미지를 자원으로 옮기므로(1500 G1) 예약 전 이미지는 따라간다.
  - **Q2 만드는 시점: 옵션 A.** 승인 직후 자동으로 만든다. 실패해도 승인은 유지하고 「이미지 제작 필요」로 남기며 서랍에서 다시 만든다. 서버 렌더가 웹 서버에서
    돌지 않으면 서랍에서 누를 때만 만드는 방식으로 물러난다. 이에 맞춰 완료 조건 3번 문장을 고쳤다(07 4.5·1500 Q1과의 어긋남 해소).
  - **Q3 파일 정리: 옵션 A.** 새 자원 전용 경로에 올리고 취소·되돌림·예약 실패 때 그 파일만 지운다. 기존 자원에 붙이는 적용 탭은 그대로 둔다(20260926_1456).
  - **Q4 색 대기: 옵션 A.** 트라이브별 승인 색 쌍 목록에서 고르거나 직접 입력한다. 채우면 `color_pending`을 해제하고 결정 기록에 남긴다. 팔레트 데이터 유무는 ④ 착수 때 확인.
  - **Q5 레시피: 옵션 A.** 정적 미리보기만 만들고 시험 믹스는 1159에 맡긴다. 서랍에는 링크와 안내 문구만 둔다.
  - **Q6 후속 티켓: 옵션 A.** 6건(1341·1824·0129·0130·1830·1827)을 ⑥으로 묶고, 조건부 2건(1825·0124)은 같은 파일이 겹칠 때만 끌어온다. 나머지 8건은 그대로 둔다.
  - **Q7 분해: ①~⑥ 하위 티켓으로 확정.** 「하위 티켓」 절 참고.

  - **Q8 렌더 위치: 옵션 A(2026-10-06, 1801 착수 때 추가).** 지금 서버 렌더는 PC·예약 루틴에서 도는 명령줄 도구(`@napi-rs/canvas`, 구글 글꼴 내려받기)이고, 웹 서버(Vercel)에서 같은 라이브러리가 도는 선례가 없다(`badge-image/generate`는 `next/og`). 그래서 이미지는 승인을 누른 운영자 브라우저에서 에셋 제너레이터와 같은 코드(`src/lib/asset-generator/render.ts`)로 만들고, 완성 파일을 저장 API에 올린다. Q2의 「승인 직후 자동, 실패하면 이미지 제작 필요」는 그대로 지킨다. 한계: 이미지를 만드는 동안 탭이 열려 있어야 한다(닫으면 서랍에서 다시 만든다).
