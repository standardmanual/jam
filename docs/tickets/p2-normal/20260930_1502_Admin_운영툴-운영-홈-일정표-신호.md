**사용자 결정**

- **Q1 신호 범위: A.** 11종은 규칙까지 완성한다. 실행 실패·예약 누락은 상태·시각 규칙으로 만들고 시험 데이터로 테스트한다. 뺀 항목·루틴 실패는 입력
  형식을 정해 같은 방식으로 만든다. 밸런스 경고·획득 경로가 막힌 컬렉션 2종은 자리와 표시만 두고 계산은 1459·1503이 채운다. 재료가 없는 신호는
  「아직 확인하지 않아요」로 따로 보여, 신호가 안 뜬 것을 안전하다고 오해하지 않게 한다. 완료 조건을 「11종 + 2종 자리」로 고쳤다.
- **Q2 시험 묶음: B.** 기본은 제외하고, 운영 홈·일정표 위에 「시험 묶음 포함해서 보기」 스위치(기본 꺼짐)를 둔다. 켜면 신호와 숫자에 들어가고
  「시험」 표시가 붙는다. 시험 묶음은 어떤 경우에도 슬랙으로 알리지 않는다. 1459의 「샘플 제출 시 운영 홈 경고」는 스위치를 켠 상태로 확인한다.
- **Q3 중단 알림: A.** 매시 점검 크론을 새로 둔다. 시각 창으로 판정해 새로 걸린 것만 한 번 알리고 DB는 쓰지 않는다. 실행 실패는 1500의 사건
  알림이 맡으므로 이 점검은 알리지 않는다. 크론이 한 번 건너뛰면 그 알림도 한 번 놓치는 것을 감수한다.
- **Q4 서랍: B(추천 A와 다름).** 서랍에서 항목 요약을 보이고, S3의 항목 단위 승인·반려·편집 부품(`OpsItemDetail`·`OpsItemActions`·
  `OpsItemEditForm`, `decisionClient`)을 재사용한다. 같은 API와 결정 기록을 쓰므로 승인 창구가 둘로 갈리지 않고, 묶음 단위 승인이 기본이라는
  07 9절 4도 그대로다. 미리보기·색 채우기·에셋 제너레이터는 1501이 같은 서랍에 더한다. 07 4.3 S4 행에 이 범위를 한 줄 보탰다(진행 규칙 5).
