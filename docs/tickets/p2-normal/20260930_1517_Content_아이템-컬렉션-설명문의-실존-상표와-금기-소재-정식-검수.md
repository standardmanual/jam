# [Content] 아이템·컬렉션 설명문의 실존 상표·금기 소재를 정식 검수한다 (윈터)

> 상위: 20260930_1450 · 진행 규칙 4로 생성(티켓 20260930_1451 결정)

## 핵심 요약

- 요구사항: 아이템배지 이름·설명과 컬렉션 설명·서사에 섞여 있는 실존 상표와 금기 소재를 전수 검수하고, 사용자가 승인한 대체 문안으로
  바꾼다. 첫 실제 컨텐츠 요청(첫 시즌·컬렉션 런칭)보다 먼저 끝낸다.
- 구현 계획: 원문을 DB에서 뽑아(읽기 전용) 윈터(`jam-tribe`) 모드 ② 검수로 판정표를 만들고, 문제 항목마다 모드 ③으로 대체 문안을 받는다.
  사용자 승인 뒤 메인 세션이 SQL 파일로 DB를 고치고 `ITEMBOOKS.xlsx`를 맞춘다.
- 관련 파일:
  - 원천: DB `badges`(`type = 'item'`의 `name`·`description`), `item_books`(`name`·`description`·`story_text`), 목록 문서 `jam-doc/planning/content/ITEMBOOKS.xlsx`
  - 규칙: `.claude/agents/jam-tribe.md` 「② 검수 점검표」(실존 상표·인물 사용 여부, 금기어), `jam-doc/planning/content/TRIBES.md` 「어떤 트라이브에도 붙이지 않는 소재」(200줄 부근, 실존 대회명·상표명 포함),
    06 플랜 661줄(실존 상표는 현재 캐논이 금지하는 소재, 협업마다 사용자 승인으로 예외)
  - DB 변경 기록: `jam-web/supabase/migrations/`(파일로 남기고 실행은 사용자 승인 뒤 메인 세션)

## 배경 / 문제 정의

- 티켓 20260929_2226 「발견물」(389~391줄): 아이템 설명문·이름에 실존 상표(고어텍스·코닥·고프로·소니 워크맨·당근 마켓·새우깡·츄르·
  춘천 마라톤·"G사")와 금기 소재(맥주 병뚜껑, 07-06 「숙취와 포션」, 07-04 「불법(?) 부스터 배합」)가 섞여 있다는 기록만 있다.
  어느 배지·컬렉션인지, 전체에 몇 건인지는 검수하지 않았다.
- 06 플랜(661줄)은 실존 상표를 현재 캐논이 금지하는 소재로 적었다. 윤진 정의(`jam-marketer.md` 「Forbidden」)도 실존 브랜드명 사용을 금지한다.
- 새 운영 체계에서는 에이전트가 코퍼스(아이템·컬렉션 설명)를 재료로 인용한다. 원문에 상표·금기 소재가 남아 있으면 기획안과 홈피드에
  그대로 옮겨질 수 있다.

## 상세 요구사항

### 컨텐츠 관점
- 검수 범위: 아이템배지(`badges.type = 'item'`) 이름·설명, 컬렉션 이름·설명·서사. 삭제 표시(`deleted_at`) 배지와 비활성 트라이브 소속
  컬렉션을 포함할지는 착수 때 사용자에게 확인한다(추천: 포함. 06 플랜은 지금 활성 컨텐츠를 테스트 상태로 보고, 앞으로 여는 트라이브의
  컬렉션이 그 원문을 쓴다).
- 판정 유형은 두 가지다: 실존 상표·인물·실존 대회명, 금기 소재(`TRIBES.md` 「어떤 트라이브에도 붙이지 않는 소재」와 윈터 금기 목록 기준.
  발견물의 음주·불법 암시 소재가 여기에 해당하는지 윈터가 판정한다).
- 항목마다 「현재 문안 → 문제 유형 → 대체 문안 → 판정(주의/중단)」을 한 줄로 적는다. 대체 문안은 트라이브 목소리를 유지한다.
- 협업으로 상표를 쓰기로 한 예외는 06 플랜 661줄대로 사용자 승인으로만 둔다. 이번 검수에서는 예외를 만들지 않는다.
- 지점 카테고리 라벨 「미슐랭」(`jam-web/supabase/migrations/162_poi_category_michelin.sql`)과 미슐랭 체크인 배지 42종은 지금 검수 범위 밖이다. 두 표기(미쉐린·미슐랭)는 같은 실존 브랜드다. 착수 때 이 둘을 범위에 넣을지와 앱 라벨을 바꿀지를 사용자에게 함께 묻는다(2026-09-30 티켓 20260930_1454 윈터 검수로 추가). 운영 패턴 사전은 라벨을 장소 손잡이의 카테고리 이름으로만 쓰고, 유저에게 나가는 문안에는 브랜드 글자와 별·스타·등급 어휘를 쓰지 않는다.

### 서비스/코드베이스 관점
- DB 원문 추출은 읽기 전용 조회로 한다. 개인정보는 없다(컨텐츠 테이블만 읽는다).
- 고칠 때는 `jam-web/supabase/migrations/`에 UPDATE SQL과 되돌림 SQL(주석)을 남기고, 사용자 승인 뒤 메인 세션만 실행한다(CLAUDE.md 절대 규칙 6).

## 구현 계획

1. 메인 세션이 DB에서 검수 대상 원문을 뽑는다(읽기 전용).
2. 윈터 모드 ②로 판정표를 만든다. 문제 항목만 모드 ③으로 대체 문안을 받는다.
3. 사용자 승인을 받는다(항목별 승인·반려).
4. 승인분을 SQL 파일로 만들고 실행한다. `ITEMBOOKS.xlsx`를 같은 값으로 맞춘다.

## 진행 기록

- 2026-10-01 사용자 결정(범위): 비활성 컬렉션 70개와 그 아이템배지 630종(삭제 표시)까지 **전부 포함**한다(컬렉션 100개·아이템 900종).
  지점 카테고리 라벨 「미슐랭」은 **유지**하고, 그 체크인 배지 42종은 설명문만 검수한다(식당 이름은 실제 장소라 그대로 둔다).
- 2026-10-01 원문 추출(읽기 전용, 스크립트로 파일에 직접 저장)과 기계 필터(상표·대회명·금기 키워드와 영문 표기, 221줄 후보)를 돌렸다.
  기존 발견물 12건이 모두 후보에 잡혔다. 윈터 모드 ②는 정식 전수 검수라 기본 모델(Haiku) 대신 Sonnet으로 3묶음을 동시에 돌렸다.

> 2026-10-01 작성. 판정은 윈터 모드 ②(Sonnet, 3묶음 동시), 대체 문안은 윈터 모드 ③(Sonnet, 트라이브별 6묶음 + 추가 1회). 카리나가 ID·인용 구간을
> 추출 원문과 기계 대조했고(86/86 일치), 새 문안에 금지 키워드가 다시 들어가지 않았는지 검사했다(오탐 1건: 「연금술」의 「술」).

### 판정 기준 (사용자 결정, 2026-10-01)

- 범위: 컬렉션 100개·아이템배지 900종 전부(비활성·삭제 표시 포함). 「미슐랭」 지점 카테고리 라벨은 유지하고 그 체크인 배지 42종은 설명문만 봤다(42종 모두 문제 없음).
- 실존 상표: 일반명사처럼 굳은 상표(워크맨·포스트잇·포크레인·대일밴드·블루투스 등)와 우회 표기(「G사」)까지 교체한다. 「좋아요」·「편의점」·「콜라」·「호빵」·「쭈쭈바」·「구미베어」·「하프 마라톤」은 일반어로 보고 남겼다.
- 실존 인물: 생존 인물(엄홍길)과 고인(달리·뉴턴·베토벤·파블로프)을 모두 교체한다. 식당 이름에 든 셰프 이름은 실제 장소 이름이라 남겼다.
- 음주(금기 10): 권유 문장뿐 아니라 술을 즐거움으로 그리거나 숙취 상태로 운동하는 묘사까지 교체한다. 예외는 낭만 미식가 정본의 「10km를 달린 후 마시는 맥주 한 캔」 범위(「구겨진 캔맥주」)뿐이다.
