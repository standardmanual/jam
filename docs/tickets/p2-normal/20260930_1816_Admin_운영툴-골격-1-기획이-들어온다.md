# [Admin] 운영툴 골격 ① 기획이 들어온다

> 상위: 20260930_1455 · 하위 순서 ① · 07 인벤토리 A

## 핵심 요약

- 요구사항: 운영 묶음·묶음 항목·결정 기록 테이블을 만들고(마이그레이션), 에이전트가 읽기 토큰으로 `POST /api/admin/ops-inbox`에 운영 묶음을 제출하면
  공통 필드를 검증해 저장하고 슬랙 `#jam-report`에 도착 이력을 알린다. 토큰의 쓰기는 이 경로 하나에만 열린다.
- 구현 계획: 아래 「구현 계획」 절. 1455 가정 4·5·6·8~12·15·16과 사용자 결정 Q1을 따른다.
- 관련 파일: `jam-web/src/lib/admin/auth.ts`(80-84 `isValidAdminReadToken`, 96-101 `requireAdminRead`),
  `jam-web/src/proxy.ts`(74-86 토큰 GET 통과 분기), `jam-web/src/lib/admin/__tests__/admin-read-token.test.ts`(103-111 쓰기 403 고정),
  기존 `route-contract.test.ts`(라우트 전수 계약 검사 방식), `jam-web/supabase/migrations/`(RLS 선례 `185_asset_presets.sql:55-59`),
  `scripts/slack-post.mjs`(게시 방식 참고, 23-26의 `process.exit` 때문에 재사용하지 않는다), `jam-web/scripts/asset-generator/registerHomeFeedBundle.mjs:443`
  (`validateHomeFeedBundle`, 검증 오류를 「경로: 사유」로 모으는 방식 참고), `docs/specs/prd/asset-generator/`의 등록 묶음 형식,
  `docs/specs/prd/04_PROJECT_SPEC.md`(91·214 「GET 전용」 문장, 205-226 환경변수 표), `docs/agents/contract.json`.

## 시작 절차

상위 티켓 20260930_1455의 「주요 의사결정」(가정 1~17, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게 확인한다.

## 주의

- 토큰 쓰기 예외는 proxy와 라우트를 함께 연다. 경로를 접두사로 열지 않는다. 경로·메서드를 상수 하나로 두고 proxy와 라우트가 함께 쓴다.
- `requireAdminRead`와 그 테스트(103-111)는 그대로 둔다. 제출용 검사 함수를 따로 만든다.
- `proxy.ts`는 모든 요청이 지난다. 기존 GET 토큰 통과와 쿠키 없는 다른 POST의 로그인 리다이렉트를 회귀 테스트로 고정한다.
- 마이그레이션은 파일 작성까지만 한다. 실행은 머지 뒤 사용자 승인을 받아 메인 세션이 한다(공용 단일 DB).
- 서버에서 슬랙에 게시하려면 Vercel 환경변수(`SLACK_BOT_TOKEN`, 채널 ID 2개)가 필요하다. 코드는 값이 없으면 게시를 건너뛰고 기록만 남긴다.
  등록은 사용자가 한다.
- 화요일 루틴과 지금의 홈피드 등록 절차, 기존 라우트는 바꾸지 않는다(1450 진행 규칙 7).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 마이그레이션 파일 하나가 테이블 3개(운영 묶음, 묶음 항목, 결정 기록)를 만들고 RLS를 켠다. 되돌림 SQL이 함께 있다. 기존 테이블은 바꾸지 않는다.
- 읽기 토큰으로 `POST /api/admin/ops-inbox`에 샘플 묶음을 내면 묶음과 항목이 저장되고, 결정 기록에 「제출」 1행이 남는다(테스트).
- 토큰으로 이 경로 밖의 어드민 경로에 POST·PUT·PATCH·DELETE를 보내면 모두 거부된다. 토큰 쓰기 검사를 부르는 라우트가 제출 라우트 하나뿐인지
  계약 테스트가 확인한다. 기존 GET 토큰 통과와 쿠키 없는 다른 POST의 리다이렉트는 그대로다(회귀 테스트).
- 같은 `bundle_id`를 다시 내면 내용이 같을 때 200이고 슬랙에 다시 알리지 않는다. 내용이 다르면 409이고 덮어쓰지 않는다(테스트).
- JSON이 아니거나 `bundle_id`·`author`가 없으면 400이다. 그 밖의 공통 필드 오류는 저장하고 응답에 「경로: 사유」 목록을 돌려준다(테스트).
- 본문 1MB, 항목 60개를 넘으면 400이다. 시간당 제출 20회를 넘으면 429다(테스트).
- 저장 뒤 슬랙 `#jam-report`에 도착 글(에이전트, 항목 수, 형식 오류 수, 시험이면 「[시험]」)을 게시한다. 게시가 실패하거나 환경변수가 없어도 제출은
  성공하고, 결정 기록에 알림 결과가 남는다(테스트). 제출 문자열은 슬랙 특수문자를 이스케이프한다.
- 문서: 운영툴 PRD §3(제출 형식)·§9(1455가 보내는 이벤트)·§10(테이블)·§11(제출 경로와 요청·응답)을 사실로 바꾸고 §13 표를 갱신한다.
  `02_DATA_MODEL.md`에 테이블 3개, `04_PROJECT_SPEC.md`에 토큰의 제출 경로 예외와 새 환경변수를 적고, 환경 주장에는 `contract.json` 검사 줄을 더한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 사용자 승인을 받아 마이그레이션을 실행하고 생성 타입을 확인한다.
- 사용자가 Vercel 두 프로젝트에 슬랙 환경변수를 등록하면, 손으로 만든 샘플 묶음(`is_sample: true`)을 staging에 제출해 저장과 `#jam-report`의
  「[시험]」 도착 글을 확인한다.
