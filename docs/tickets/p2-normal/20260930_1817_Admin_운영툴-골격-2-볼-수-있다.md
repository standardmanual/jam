# [Admin] 운영툴 골격 ② 볼 수 있다

> 상위: 20260930_1455 · 하위 순서 ② · 07 인벤토리 A

## 핵심 요약

- 요구사항: 묶음 상태를 항목 상태에서 계산하는 함수, 받은 기획함(S2), 기획 상세(S3)의 읽기 화면을 만든다. S3에는 단계 표시줄, 항목 목록,
  아이콘과 글을 함께 쓰는 상태 표시, 형식 오류 표시, 미리보기 자리와 오른쪽 서랍의 빈 틀을 둔다. 기획 상세를 처음 열면 「도착」이 「검토중」으로 바뀐다.
- 구현 계획: 착수 전에 채원이 S2·S3 화면을 설계한다(1455 가정 17: 화면 설계는 채원, MODULAR 재사용 판정은 면제). 1455 가정 2·3·7을 따른다.
- 관련 파일: `jam-web/src/app/admin/`(어드민 화면 폴더, `layout.tsx`의 메뉴), `jam-web/src/app/api/admin/ops-inbox/`(1816에서 만든 제출 라우트 옆에
  읽기 라우트를 둔다), 운영툴 PRD §4·§6·§7.

## 시작 절차

상위 티켓 20260930_1455의 「주요 의사결정」(가정 1~17, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게 확인한다.

## 완료 조건

- 묶음 상태 계산 함수가 1455 가정 7의 규칙대로 동작한다(항목 상태 조합별 테스트). 규칙이 운영툴 PRD §7에 적혀 있다.
- 1816으로 넣은 샘플 묶음이 S2에 뜨고, 목록에 에이전트·주차·항목 수·묶음 상태·형식 오류 수·「[시험]」 표시가 보인다.
- S3에서 단계 표시줄 6단계(도착 → 검토 → 준비 → 예약 → 게재 → 종료)가 상태에 맞게 강조되고, 반려·취소·실패는 표시줄 밖에 아이콘과 글로 표시된다
  (PRD §7.1). 상태는 색만으로 나누지 않는다.
- 기획 상세를 처음 열면 「도착」 항목이 「검토중」으로 바뀐다. 읽기 요청만으로는 상태가 바뀌지 않는다(테스트).
- 미리보기 자리와 오른쪽 서랍은 빈 틀로 있고, 서랍이 열려도 원래 화면이 보인다.
- 제출 문자열은 HTML로 그리지 않는다.
- 문서: 운영툴 PRD §6에 S2·S3 세부(구성 요소, 빈 상태, 오류 문구)를 채운다.
