# [Admin] 운영툴 골격 ② 볼 수 있다

> 상위: 20260930_1455 · 하위 순서 ② · 07 인벤토리 A

## 핵심 요약

- 요구사항: 묶음 상태를 항목 상태에서 계산하는 함수, 받은 기획함(S2), 기획 상세(S3)의 읽기 화면을 만든다. S3에는 단계 표시줄, 항목 목록,
  아이콘과 글을 함께 쓰는 상태 표시, 형식 오류 표시, 미리보기 자리와 오른쪽 서랍의 빈 틀을 둔다. 기획 상세를 처음 열면 「도착」이 「검토중」으로 바뀐다.
- 구현 계획: 착수 전에 채원이 S2·S3 화면을 설계한다(1455 가정 17: 화면 설계는 채원, MODULAR 재사용 판정은 면제). 1455 가정 2·3·7을 따른다.
- 관련 파일: `jam-web/src/app/admin/`(어드민 화면 폴더, `layout.tsx`의 메뉴), `jam-web/src/app/api/admin/ops-inbox/`(1816에서 만든 제출 라우트 옆에
  읽기 라우트를 둔다), 운영툴 PRD §4·§6·§7.

## 시작 절차

상위 티켓 20260930_1455의 「주요 의사결정」(가정 1~17, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게 확인한다.

### S2 받은 기획함 (1817)
메뉴: 사이드바 맨 위에 새 그룹 「라이브 운영」 › 「받은 기획함」(IconInbox).
```
받은 기획함   부제 「에이전트가 보낸 한 주 기획을 확인하고 승인해요」
[전체 4] [결정할 것 2] [진행 중 1] [끝남·멈춤 1]           <- Tabs, 숫자 포함
주차·가설 | 에이전트 | 상태 | 항목 | 형식 오류 | 받은 시각
[시험] 41주차 (10/5~10/11)  | 주간 루틴 | (새로 도착) | 35개 | (!) 3건 | 10/1(수) 09:12
 가설 한 줄(muted, 1줄 말줄임)
```
- 주차·가설: 「시험」 칩(IconFlask2, 테두리형)을 맨 앞에. 「41주차 (10/5~10/11)」 굵게(`week`에서 월~일 범위 계산, 형식이 틀리면 「주차 없음」). 아랫줄에 가설.
- 에이전트: `author`를 글자로만. 상태: 묶음 단계 `OpsStatusBadge`(도착이면 「새로 도착」과 그 행 글자 굵게), 검토 단계는 아랫줄 「결정 3/12」, 실패 항목이 있으면 「일부 실패」 칩.
- 항목 「35개」. 형식 오류: 묶음 오류 목록 길이 「(!) 3건」, 0이면 muted 「없음」. 받은 시각 「10/1(수) 09:12」(KST).
- 정렬: 기본 받은 시각 최신순(`sort=-received_at`). 머리 칸 클릭 정렬은 주차·항목·받은 시각. 묶음 상태는 항목에서 계산하므로 서버에서 계산한 뒤 거르고 정렬하고 50건씩 자른다.
- 필터: 상태 탭 4개만(결정할 것=도착·검토, 진행 중=준비·예약·게재, 끝남·멈춤=종료·반려·취소). 검색·전체 선택·일괄 처리·내보내기·「시험 숨기기」는 없다.
- 행 어디를 눌러도 같은 탭에서 상세로 간다.
- 빈 상태(0건): IconInbox와 「아직 받은 기획이 없어요」/「에이전트가 기획을 보내면 여기에 나타나요.」 필터 결과 0건: 「이 조건에 맞는 기획이 없어요」와 [전체 보기].

### S3 기획 상세
```
[<- 받은 기획함]  41주차 (10/5~10/11) [시험]  에이전트 {author}     [... 시험 묶음 지우기] (시험일 때만, 1818)
가설 {hypothesis}(muted, 2줄)
+ 단계 표시줄 카드 ---------------------------------------------------------------+
| (v)도착 --- (2)검토 --- (3)준비 --- (4)예약 ... (5)게재 ... (6)종료  [11개 승인하기] <- 슬롯 barAction |
|   -         12개        -          -           -         -                             |
| 표시줄 밖: 검토에서 반려 2개 · 예약 단계에서 취소 1개 · 준비에서 실패 1개 (0인 것은 숨김)      |
+---------------------------------------------------------------------------------+
알림 슬롯(위에서 아래): 형식 오류 요약(warning) / 「공개는 아직 연결 전이에요」(1818) / 상태 전환 실패
[미리보기 280] [가운데 1fr: 탭 + 목록 | 상세] [서랍 320(열릴 때만)]
```
- 표시줄: 지난 단계는 채운 원과 체크, 지금 단계는 굵은 테두리 원과 굵은 글자(`aria-current="step"`, 숨은 글 「지금 단계」), 아직은 점선 원. 지난 구간 연결선만 실선.
  단계 아래에 그 단계 항목 수(0이면 「-」). 단계 매핑은 PRD §7.1. 1455에서 예약·게재·종료는 늘 「아직」 모양이다.
- 표시줄 밖(§7.1): 표시줄 아래 한 줄에 「{마지막 단계}에서 {상태} N개」 칩(아이콘과 글). 반려는 「검토에서」, 취소는 「예약 단계에서」, 실패는 결정 기록에 단계가 있으면 붙이고
  없으면 「실패 N개」. 묶음이 전부 반려·취소이면 모든 단계를 점선으로 그리고 표시줄 자리에 배너 「이 기획은 모두 반려됐어요」/「모두 취소됐어요」.
- 가운데 열: 탭 [전체 35 · 결정할 것 12 · 형식 오류 3 · 멈춘 것 2]. 열 폭이 40rem 이상이면 안쪽 2단(목록 2fr | 상세 3fr, 각자 스크롤, 상세는 sticky), 좁으면 목록
  (최대 50vh 스크롤) 위·상세 아래. 처음 선택은 결정 전 첫 항목(없으면 첫 행).
- 미리보기(빈 틀): 카드 「미리보기」와 폰 비율 점선 틀, 「미리보기는 곧 열려요」. `sticky top-[4.5rem]`(EditorShell 레일과 같은 값).
- 서랍(빈 틀) `OpsDrawerFrame`: 인라인 `aside`. 열림은 URL `?drawer=…`(1455는 `empty` 하나, 여는 버튼은 1501). 컨테이너 68rem 이상이면 3열(미리보기 240 | 가운데 1fr(480 이상)
  | 서랍 320)로 밀어내고, 좁으면 가운데 열 맨 아래에 카드로 쌓인다. 딤·포커스 가둠 없이 Esc와 닫기 버튼(「서랍 닫기」)으로 닫는다.

### 항목 목록의 한 행
```
[x] 홈피드 카드 · 10/6(월) 09:00 시작              [검토중] [형식 오류 2]
    비 오는 월요일 아침, 홈에서 「우산 챙겨 달리기」 카드를 만나요.        (유저가 겪는 것, 2줄까지)
```
- 날짜별 묶음: 공개 시각(KST) 날짜마다 머리줄 「10/6(월) · 3개」(sticky), 같은 날은 공개 시각 순. 공개 시각이 없는 항목은 맨 끝 「공개 시각이 없어요」.
- 종류(아이콘 `aria-hidden`과 글): 홈피드 카드 IconNews · 미션 IconTarget · 드랍 일정 IconDice · 믹스 레시피 IconFlask · JAM! 배지 IconAward · 컬렉션 런칭 IconBook ·
  패턴 제안 IconBulb. 허용값 밖은 「종류 확인 필요」.
- 「유저가 겪는 것」이 비면 muted 「유저가 겪는 것이 비어 있어요」. 형식 오류 칩은 항목 `format_errors` 개수. 행을 누르면 선택(`?item={항목 id}`, `item_key`는 중복될 수 있어
  쓰지 않는다). 선택 행은 왼쪽 굵은 선, 배경, 오른쪽 chevron, `aria-current`.
- 체크박스(1818)는 검토중 항목에만 보이고 나머지는 자리만 비운다.
- 상세 카드(1817, 위에서 아래): ① 종류·상태 칩·패턴 번호·손잡이 값(작은 「이름: 값」) ② 형식 오류(warning. 「경로: 사유」를 첫 「: 」에서 잘라 경로는 쉬운 이름표로 바꿔 작게,
  사유를 본문으로. 끝에 「형식 오류가 있어도 승인할 수 있어요. 공개 준비에서 걸릴 수 있으니 고칠 수 있는 것은 먼저 고쳐 주세요.」) ③ 유저가 겪는 것 ④ 내용(문안·색 견본과 글자·
  공개/종료 시각·대상·연결은 눌러서 그 항목 선택) ⑤ 검수·판정(「세계관과 닿는 카드예요/아니에요」·「윈터 검수 끝났어요/아직이에요」·이유. 밸런스 판정은 1459 전까지 「이름: 값」 글)
  ⑥ 제출 원본(Accordion 접힘) ⑦ 결정 기록(최신순, 「누가·언제·무엇」과 사유·차이 줄, 「슬랙 알림 실패」 표시, 토큰 제출은 「에이전트(이름)가 제출했어요」).

### 행동 영역 (1818)
```
detailFooter(상세 카드 아래 고정 줄):  [반려하기] (테두리형, 붉은 글)            [수정하기] [승인하기] (primary)
```
- 세 버튼은 검토중 항목에만 보인다. 그 밖의 상태는 버튼 자리에 「승인한 항목은 여기서 고칠 수 없어요」처럼 안내 글만 둔다.
- 항목 승인 확인창(`OpsConfirmDialog`): 「이 항목을 승인할까요?」/ 항목 한 줄 요약 / 「승인하면 「승인됨」으로 바뀌고 기록이 남아요. 승인은 되돌릴 수 없어요.」 / 「공개는 아직
  연결 전이에요. 공개는 지금 쓰는 방법으로 해 주세요.」 / 형식 오류가 있으면 warning 상자에 오류 목록과 「그래도 승인할 수 있어요」(Q3) / [취소][승인하기].
- 반려 확인창: 「이 항목을 반려할까요?」와 「반려 이유」 textarea(필수, 공백만이면 [반려하기] 비활성, 500자, 도움말 「에이전트가 다음 기획에 참고해요. 구체적으로 적어 주세요」),
  「반려는 되돌릴 수 없어요」 / [취소][반려하기] (destructive). 붉은 면은 이 버튼 하나뿐이다.
- 결정 뒤: 창이 닫히고 토스트 「승인했어요」/「반려했어요」, 행 칩이 바뀌고 상세가 다음 결정 전 항목으로 넘어간다. 실패는 창 안 인라인(「승인하지 못했어요. 잠시 뒤 다시 눌러 주세요.」/
  「이미 다른 곳에서 처리한 항목이에요. 화면을 새로 불러왔어요.」)이고 창은 유지한다.
- 일괄 승인: 목록 머리줄 「전체 선택」과 「결정할 것 12개 중 11개 선택」. 기본 체크는 검토중이면서 형식 오류가 없는 항목이고, 형식 오류 항목은 기본 해제(제외)다. 표시줄의
  [11개 승인하기] (0개면 비활성, 「승인할 항목을 골라 주세요」)를 누르면 요약 창이 뜨고, 요약이 곧 확인이다.
```
 11개 승인, 1개 제외
 승인할 것  홈피드 카드 7 · 미션 2 · 드랍 일정 2
 제외할 것  비 오는 월요일 아침… — 형식 오류가 있어요 / 체크를 풀었어요
 (!) 형식 오류가 있는 항목 N개가 들어 있어요   <- 포함될 때만
 승인은 되돌릴 수 없어요. 공개는 아직 연결 전이에요.        [취소] [11개 승인하기]
```
  결과 토스트 「11개를 승인했어요」. 그 사이 처리된 항목이 있으면 「10개 승인, 1개는 이미 처리돼 건너뛰었어요」.
- 수정 양식: [수정하기]를 누르면 상세 카드가 그 자리에서 편집 모드가 된다(모달·서랍 아님). 칸은 5개뿐: ① 문안(제출된 문안 항목마다 한 칸) ② 색(`BackgroundColorField` 배경색·끝색)
  ③ 시각(공개·종료 `datetime-local`, KST) ④ 대상 ⑤ 유저가 겪는 것(textarea). 종류·패턴·손잡이·연결·검수·판정은 읽기 전용이고 「고칠 수 없어요」 툴팁을 단다. 고친 칸에는 「수정됨」 칩.
- 차이 표시 `OpsDiffLines`: 칸 아래 「바뀌는 내용」에 바뀐 칸만 「문안: 전 → 후」 한 줄씩(전은 취소선과 muted, 후는 굵게, 「→」 글자로 색에 기대지 않음). 바뀐 게 없으면 [저장하기] 비활성.
  그 밑에 「수정한 이유(선택)」 한 줄 입력. 저장은 확인창 없이 바로(Q4)이고, 공통 검증 실패는 칸 아래 인라인(「끝나는 시각이 시작보다 빨라요. 시작 뒤로 바꿔 주세요.」)이다.
- 수정 되돌리기: 같은 동작이 두 곳. ① 저장 토스트의 [되돌리기] (10초) ② 상세 「수정 내역」 머리의 「마지막 수정 되돌리기」(수정 내역이 있는 검토중 항목만). 확인창 없음, 한 번에 한 단계,
  다시 하기 없음. 되돌리면 결정 기록에 「되돌림」 태그의 새 수정 줄이 생기고 그 줄에는 버튼이 없다.

- 묶음 상태 계산 함수가 1455 가정 7의 규칙대로 동작한다(항목 상태 조합별 테스트). 규칙이 운영툴 PRD §7에 적혀 있다.

- 문서: 운영툴 PRD §6에 S2·S3 세부(구성 요소, 빈 상태, 오류 문구)를 채운다.
