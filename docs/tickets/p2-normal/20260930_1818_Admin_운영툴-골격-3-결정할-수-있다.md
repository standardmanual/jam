# [Admin] 운영툴 골격 ③ 결정할 수 있다

> 상위: 20260930_1455 · 하위 순서 ③ · 07 인벤토리 A

## 핵심 요약

- 요구사항: 기획 상세(S3)에서 항목 승인, 반려, 한 주 묶음 일괄 승인, 직접 수정, 수정 되돌리기를 할 수 있게 하고, 모든 행동을 결정 기록에 남기며
  슬랙 `#jam-report`에 알린다. 승인은 `승인됨`에서 멈추고 「공개는 아직 연결 전이에요」를 안내한다.
- 구현 계획: 1455 가정 1·6·13~16과 사용자 결정 Q3(형식 오류는 경고만 하고 승인 허용), Q4(누르기 전 확인, 되돌리기는 직접 수정만), Q5(반려는
  자유 입력 사유 필수, 수정 사유는 선택, 승인은 사유 없음)를 따른다. 채원이 설계한 S3에 행동을 붙인다. 설계는 1817 티켓의 「채원 화면 설계」 절(「행동 영역」과 「1817 / 1818 경계」)이 정본이다.
- 관련 파일: 1817에서 만든 S3 화면과 읽기 라우트, 1816의 결정 기록 테이블과 슬랙 게시 함수, 운영툴 PRD §7·§9.

## 시작 절차

상위 티켓 20260930_1455의 「주요 의사결정」(가정 1~17, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게 확인한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 승인·반려·일괄 승인·직접 수정·수정 되돌리기가 결정 기록에 누가·언제·무엇을·수정 전후 차이·사유로 남는다(테스트). 결정 기록은 추가만 된다.
- 반려는 사유 없이 저장되지 않는다. 승인·반려 전에 확인 창이 뜨고, 일괄 승인은 「11개 승인, 1개 제외」 같은 요약을 먼저 보여 준다.
- 형식 오류가 있는 항목도 경고를 보여 준 뒤 승인할 수 있다.
- 직접 수정은 검토중 항목의 문안·색·공개·종료 시각·대상·「유저가 겪는 것」만 바꾸고, 제출 원본은 바꾸지 않는다. 수정 전후 차이가 「문안: 전 → 후」로 보인다.
- 같은 항목을 동시에 두 번 승인해도 한 번만 반영된다(조건부 갱신, 테스트).
- 승인·반려·일괄 승인·직접 수정이 슬랙 `#jam-report`에 알려지고, 슬랙이 실패해도 결정은 유지된다(테스트).
- 시험 묶음은 어드민이 결정 기록까지 지울 수 있고, 시험이 아닌 묶음은 지울 수 없다(테스트).
- 문서: 운영툴 PRD §7(행동별 상태 전이)·§9·§11(사용자 → 툴 경로)·§13을 사실로 바꾼다.

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- 2026-09-30 착수 가정(사용자 승인): ① 수정 되돌리기는 되돌리지 않은 가장 최근 수정을 한 단계씩 되돌리고(「구현 계획」 1번 `findRevertTarget`), 되돌림도 슬랙에 수정 글로
  「되돌림」을 붙여 알린다. ② 수정 저장 때 형식 오류를 다시 검사한다. 고친 칸의 새 오류는 저장을 막고, 이미 있던 오류를 고치면 형식 오류 표시가 사라진다(일괄 승인 기본 체크에도 들어간다).
  ③ 「공개는 아직 연결 전이에요」는 1500 전까지 모든 기획 상세에 늘 둔다. ④ 반려 슬랙 글에 사유를 100자까지 붙인다. ⑤ 결정 기록 `actor`는 관리자 ID, 화면은 「관리자가 …」.
  ⑥ 1817 셸에 슬롯 `listHeader`·`detailHistoryAction`을 더한다(채원 설계에 있으나 1817 슬롯 목록에 빠졌다). ⑦ 머지 뒤 로컬 실렌더에서 1816 시험 묶음에 실제로 결정하고
  `#jam-report`에 「[시험]」 글이 올라간다. 시험 묶음 지우기는 두 번째 시험 묶음으로 확인하고 1816 시험 묶음은 남긴다.
- 규모 사전 판정: 새 파일 약 20개와 1817 파일 보강으로 `plan_only` 기준을 넘는다. 1455가 나눈 마지막 조각이라 더 쪼개지 않고 파일 단위 「구현 계획」으로 첫 호출부터 면제한다.
