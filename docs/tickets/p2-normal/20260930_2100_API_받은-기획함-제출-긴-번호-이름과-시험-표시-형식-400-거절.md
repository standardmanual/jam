# [API] 받은 기획함 제출에서 긴 묶음 번호·이름과 불리언이 아닌 시험 표시를 400으로 거절한다

> 상위: 20260930_1455 · 1816 게이트 범위 밖 발견물(민지) · 경미 수정(`/jam-work` 0.1절, 카리나 직접)

## 핵심 요약

- 요구사항: ① `bundle_id`(200자 초과)·`author`(100자 초과)가 길면 400으로 거절한다. 지금은 유일 인덱스의 행 크기 제한(약 2.7KB)에 걸려 500이 나고
  다시 보내도 계속 실패한다. ② `is_sample`이 있는데 불리언이 아니면 400으로 거절한다. 지금은 형식 오류로만 적고 운영 묶음(`false`)으로 저장해,
  시험 묶음이 학습 재료와 신호에 섞일 수 있다.
- 구현 계획: `validateOpsBundle`의 fatal 검사에 세 조건을 더하고, 저장되는 형식 오류 쪽의 `is_sample` 분기를 정리한다. 테스트를 fatal 기대로 바꾼다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/validate.ts`(257 `validateOpsBundle` fatal 구간, 314 `is_sample` 분기),
  `jam-web/src/lib/admin/opsInbox/__tests__/validate.test.ts`(95 fatal describe, 260 `is_sample` 케이스), `docs/specs/prd/ops-tool/PRD.md` §3.1·§11.1.

## 배경

2026-09-30 1816 게이트에서 민지가 찾았다(sideFindings 1·4). 사용자가 「머지 후 이어서 보강」을 골랐다. 1455 가정 12(「`bundle_id`·`author`가 없으면 400」)에
거절 조건 세 가지가 더해진다. 신원(`bundle_id`·`author`)과 시험 여부는 저장 뒤에 바로잡을 수 없는 값이기 때문이다.

## 완료 조건

- `bundle_id`가 200자를 넘거나 `author`가 100자를 넘으면 fatal(400)이다(테스트).
- `is_sample`이 있는데 불리언이 아니면 fatal(400)이다. 없으면 `false`, `true`면 시험 묶음이다(테스트).
- 운영툴 PRD §3.1과 §11.1의 400 조건에 세 가지가 적혀 있다.
- `npx vitest run src/lib/admin/opsInbox src/app/api/admin/ops-inbox`와 변경 파일 eslint가 통과한다.
