# [Service] 믹스 「레시피 없음」 실패 기록이 DB 규칙에 막혀 저장되지 않는 문제를 고친다

> 1456 시작 검토에서 발견, 라이브 DB 확인(카리나, 2026-10-01)

## 핵심 요약

- 요구사항: 믹스 코드는 실패 사유 `recipe_not_found`를 `user_combine_fail_logs`에 기록하지만(`jam-web/src/lib/combine/index.ts:105`), 테이블의 CHECK 제약에 이 값이 없어(`jam-web/supabase/migrations/153_combine_v3.sql:117-119`) 저장이 조용히 실패한다. 라이브 DB에서도 CHECK에 `recipe_not_found`가 없다(2026-10-01 조회).
- 구현 계획: CHECK에 `recipe_not_found`를 더하는 추가형 마이그레이션(되돌림 SQL 포함). 1456 하위 ①(20261001_0631)이 믹스 관련 마이그레이션을 만들 때 함께 넣을 수 있으면 그 티켓에서 처리하고 이 티켓을 닫는다.
- 관련 파일: `jam-web/src/lib/combine/index.ts:105`, `jam-web/supabase/migrations/153_combine_v3.sql:108-119`

## 완료 조건

- 레시피가 없는 재료 조합으로 믹스하면 실패 기록이 `recipe_not_found`로 저장된다(테스트 또는 DO 블록 롤백 실측).
- 라이브 CHECK 정의에 `recipe_not_found`가 있다(`pg_get_constraintdef`).
