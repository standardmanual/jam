# [BadgeEngine] 한 배지에 사용량 지표를 둘 이상 넣으면 AND가 아니라 먼저 채운 쪽으로 발급되는 문제를 막는다

> 민지 게이트 리뷰의 범위 밖 발견물(티켓 20261001_0631, 2026-10-01)이다.

## 핵심 요약

- 요구사항: 사용량 지표(JAM! 카테고리 10종)는 지표마다 따로 판정한다. 한 배지 조건에 둘 이상을 넣어도 저장 가드가 막지 않아, 운영자가 AND를 기대하고 「믹스 시도 10회 + 믹스 성공 5회」를 넣으면 먼저 채운 지표로 발급된다. 새 믹스 수치 3개는 함께 쓰기 쉬운 조합이라 위험이 커졌다. 저장 가드에서 사용량 지표를 둘 이상 함께 쓰지 못하게 막는다(또는 AND 판정을 구현한다, 착수 때 정한다).
- 구현 계획: AND 판정을 구현하지 않고 **저장 때 막는다**(사용자가 카리나 제안대로 진행하기로 함, 2026-10-01). 아래 「구현 계획」을 따른다.
- 관련 파일: `jam-web/src/lib/admin/badge-condition-guards.ts:101-142`(사용량 지표 가드), `jam-web/src/lib/badge-engine/jamActionBadges.ts:113-125`, `jam-web/src/lib/badge-engine/usageBadges.ts`

## 구현 계획

1. `jam-web/src/lib/admin/badge-condition-guards.ts`: `findUsageMetricOtherMeasurableConflictError`(127줄 근처) 다음에 `export function findMultipleUsageMetricsError(condition: BadgeCondition | null): string | null`를 더한다.
   `USAGE_METRIC_CONDITION_KEYS`(레지스트리 파생, 이 파일 32줄 import) 가운데 조건에 있는 키가 2개 이상이면 오류 문장을 돌려준다.
   문장 형식은 옆 가드와 같게: 「저장할 수 없습니다. 서비스 사용량 지표는 한 배지에 하나만 쓸 수 있습니다 — {라벨(키)들}. 지표마다 따로 판정돼 「모두 채워야」가 아니라 먼저 채운 지표로 발급되기 때문입니다. 지표를 하나만 남겨주세요.」
   JSDoc에 이유(지표별 독립 판정 `usageBadges.ts`·`jamActionBadges.ts`, `CONDITION_JSON_SPEC.md` §4의 「모든 필드는 AND」 원칙)와 티켓 번호를 적는다.
2. 같은 파일 `findConditionShapeSaveError`(182줄 근처)의 순서에 `findUsageMetricRepeatConflictError` 다음, `findUsageMetricOtherMeasurableConflictError` 앞에 넣는다. 머리 주석의 「4종」 개수 표현을 고친다.
   어드민 저장 API(`badge-validation.ts`)와 배지 폼(`BadgeForm.tsx`)은 이 함수를 이미 부르므로 따로 고치지 않는다.
3. 테스트 `jam-web/src/lib/admin/__tests__/badge-condition-guards.test.ts`: 두 개(예: `combine_attempt_count` + `combine_success_count`) → 오류, 세 개 → 오류, 하나 → `null`, 사용량 지표 없음 → `null`,
   기존 6지표 둘(예: `follower_count` + `daily_sync_count`) → 오류, `findConditionShapeSaveError`가 이 오류를 돌려준다(`repeat_count`가 함께 있으면 기존 repeat 오류가 먼저).
4. 문서 `docs/specs/badge-engine/CONDITION_JSON_SPEC.md` §4의 사용량 지표 문장(「사용량 지표 10종」 근처)에 「한 배지에 하나만 쓸 수 있다(저장 가드 `findMultipleUsageMetricsError`)」를 더한다.
- 에셋 제너레이터 등록 경로(`jam-web/scripts/asset-generator/registerFlow.mjs`)의 조건 검증은 이 티켓에서 다루지 않는다(티켓 20261001_0714).
- 2026-10-01 라이브 DB에 사용량 지표를 가진 배지는 0개라 기존 배지 저장에 영향이 없다(카리나 조회).

## 완료 조건

- 사용량 지표 두 개를 한 배지 조건에 넣으면 저장이 거절되고 이유가 보인다(테스트). 하나만 넣으면 지금처럼 저장된다(테스트).
