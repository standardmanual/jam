# [Admin] 운영 묶음 제출 형식에 카드 모양·트라이브·대상·「색 대기」·뺀 항목 칸을 정한다

> 상위: 20260930_1450 · 영향 티켓(진행 규칙 4) · 1502 시작 검토에서 발견, 1502 하위 ①보다 먼저 한다

## 핵심 요약

- 요구사항: 운영 묶음 항목에 카드 모양(`shape`)·트라이브(`tribe`)·대상(전원/신규 등)·「색 대기」 표시를, 묶음에 뺀 항목과 사유(`excluded_items`)를
  정해진 칸으로 두고 제출 검증에서 검사한다. 지금은 이 값이 자유 JSON(`original`·`raw`)에 들어갈 수만 있고 정해진 키가 없으며, `segment`는 문자열일
  수도 객체일 수도 있다. 이 칸이 없으면 1502의 겹침·단조로운 흐름·트라이브 거르기·「이미지 제작 필요」·「색 대기」·「에이전트가 뺀 항목」을 계산할 수 없다.
- 구현 계획: DB 변경 없이 기존 JSON 안의 정해진 키로 둔다. `validate.ts`에 형식 검사를 더하고, 칸을 읽는 함수를 한 곳에 두어 1502 ①이 쓰게 한다.
  운영툴 PRD §3.1 표와 제출 API 테스트를 고친다. 07 9절 1(중단 항목은 빼고 사유를 남긴다)·2(「색 대기」로 제출)를 형식으로 옮기는 일이다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/validate.ts`, `jam-web/src/app/api/admin/ops-inbox/route.ts`와 `__tests__`,
  `jam-web/supabase/migrations/198_ops_inbox.sql`(구조 참고만, 바꾸지 않는다), `docs/specs/prd/ops-tool/PRD.md` §3.1.

## 시작 절차

상위 티켓 20260930_1450의 「진행 규칙」과 20260930_1502의 「주요 의사결정」을 따른다. 칸을 필수로 할지 선택으로 할지, 칸이 없는 기존 형식 묶음
(이미 들어온 시험 묶음 포함)을 어떻게 받을지는 착수 때 정해 사용자에게 확인한다.

## 주의

- 화요일 루틴과 지금의 홈피드 등록 절차는 바꾸지 않는다(1450 진행 규칙 7). 이 형식을 실제로 채우는 것은 1504(윤진 루틴 전환)다.
- 마이그레이션을 만들지 않는다. 열이 꼭 필요하다는 결론이 나면 멈추고 보고한다.

## 완료 조건

- 운영툴 PRD §3.1 표에 새 칸(이름·형식·허용값·필수 여부)이 있다.
- 칸 값이 형식에 어긋나면 제출이 「경로: 사유」 오류로 거절된다(테스트). 뺀 항목은 사유가 없으면 거절된다(테스트).
- 칸이 없는 기존 형식 묶음을 받는 방식이 테스트로 고정된다.
- 항목에서 모양·트라이브·대상·「색 대기」를, 묶음에서 뺀 항목을 읽는 함수가 한 곳에 있고 단위 테스트가 있다.
