- 관련 파일: `jam-web/src/app/admin/WeeklyCalendar.tsx`, `jam-web/src/components/admin/ops/OpsDrawerFrame.tsx`, `OpsItemDetail.tsx`,

> 2026-10-06 보강(채원 S1·S4 사전 판정 승인): 디자인 정본은 상위 티켓 20260930_1502 「주요 의사결정」의 「채원 S1·S4 사전 판정 (2026-10-06 승인)」이다. 아래 항목을 함께 충족한다.

- 주간·월간·타임라인 보기가 `?view=`·`?date=`로 새로고침해도 유지되고, 보기를 바꿔도 기준일이 유지된다. 시험 스위치는 S1과 같은 컴포넌트·같은 `?sample=1`이다.
- 칸에는 상태 칩(아이콘 + 글자 또는 `sr-only` 글자)과 그날 신호의 가장 높은 수준 칩이 보이고, 같은 카드가 실제 카드·운영 항목으로 두 번 나오지 않는다(S1과 같은 합치기 함수).
- 종류·트라이브·패턴으로 거르면 해당 항목만 남는다. 트라이브·패턴을 켜면 옛 카드·미션이 빠지고 안내 문장이 뜨며, 신호 칩은 거르기와 무관하게 그날 전체 기준이다.
- 타임라인은 미션·드랍 일정·컬렉션 런칭 세 줄이고 컬렉션은 준비 구간(R4 값, 규칙 꺼짐·읽기 실패 시 28일)과 노출 구간이 다르게 그려진다. 오늘 선에 「오늘」 글자가 있고, 막대마다 `aria-label`에 종류·기간·상태가 있다.
- 서랍은 `?drawer=item&item=` 또는 `?drawer=day&date=`로 열려 새로고침해도 유지되고, Esc·「서랍 닫기」로 닫으면 URL에서 키가 지워지고 포커스가 누른 칸으로 돌아간다. 서랍은 달력의 형제 요소이며 딤·`fixed`가 없고, 열려도 달력 칸이 DOM에 그대로 있다(테스트).
- 서랍에서 한 승인·반려·편집이 S3와 같은 `decisionClient`·같은 API·같은 결정 기록 줄(`approve`·`reject`·`edit`)을 남긴다(테스트). 승인됨 항목은 「예약 등록은 기획 상세에서 해요」와 [기획 상세로 가기 →]를 보이고, 결정 직후 칸의 상태 칩이 바뀌며 1.2초 잔상이 남는다.
- 로딩(보기별 스켈레톤)·빈(기간 0건/거르기 0건)·오류(카드·미션·운영 항목·신호 재료별 격리, 서랍 안 격리) 상태가 각각 있다. 카드를 못 읽었을 때 「미편성」으로 단정하지 않는다.
- 서랍이 열려 달력 열이 56rem 미만이면 주간이 날짜별 가로 줄로 바뀌고, 320px에서 페이지 가로 스크롤이 없다(타임라인은 상자 안에서만 스크롤).
- 1151 흡수: 비활성 장기 카드가 있는 날에 「장기 카드 N장 · 비활성 M장」이고 단기 + 활성 장기 + 비활성 장기 합이 `/admin/today?date=` 목록 수와 같다(단위 테스트). 비활성이 없는 날의 표시는 지금과 같다.
- 기존 주간 캘린더의 미션 막대·상시 미션 N개·카드 노출·열람 줄·자동 실행(승인 #14)이 빠짐없이 일정표로 옮겨졌다.
- 운영 홈(`/admin`)의 주간 캘린더를 빼고(승인 #13, ②는 캘린더를 그대로 둔다) 그 자리에 「일정표 보기」 링크를 둔다. S1의 날짜 링크를 `/admin/ops-schedule?view=week&date=…&drawer=day`(날짜)·`/admin/ops-schedule`로 바꾼다. 사이드바 「받은 기획함」 아래에 「일정표」를 더한다. ADMIN_PRD §5-7 일정표 몫과 운영툴 PRD §6 S4 구성표를 고친다.

- (2026-10-06 ②-c 게이트 메모) ADMIN_PRD 299행 근처 「미편성은 서비스 점검의 빨간 카드와 같은 빨간 계열(text-red-600)」 서술은 서비스 점검이 `text-red-700`이 된 뒤 맞지 않는다. 「미편성」을 신호로 대체할 때 함께 정리한다.
- (②-c 게이트 메모) 주간 캘린더의 주 이동(`WeeklyCalendar.tsx` 71행)이 `?sample=1`을 잃는다(가정 9). 일정표로 옮길 때 `withSampleParam`을 쓴다.
