# [Admin] 운영 홈·일정표·신호 ④ 중단 신호 매시 점검과 `#jam-alert` 알림

> 상위: 20260930_1502 · 하위 순서 ④ · 선행: 20261001_1155(②와 병행 가능)

## 핵심 요약

- 요구사항: 매시 도는 점검 크론이 ①의 규칙으로 예약 누락·루틴 실패를 판정해, 직전 한 시간 창에 새로 걸린 것만 `#jam-alert`에 한 번 알린다
  (1502 Q3). DB는 쓰지 않는다. 시험 묶음은 어떤 경우에도 알리지 않는다(Q2). 실행 실패는 1500의 사건 알림이 맡으므로 알리지 않는다.
- 구현 계획: 아래 「구현 계획」 절(2026-10-04 파일 단위).
- 관련 파일: `jam-web/vercel.json`, `jam-web/src/app/api/cron/`(기존 `ambient-drop`이 매시 정각), `jam-web/src/lib/admin/opsInbox/slack.ts`,
  `docs/specs/prd/ops-tool/PRD.md` §9, `docs/specs/prd/04_PROJECT_SPEC.md`(크론 개수 문장), 채널 ID 원천 `scheduled-jobs.md` 「Slack 알림」.

## 시작 절차

상위 티켓 20260930_1502의 「주요 의사결정」(가정 1~20, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게

## 구현 계획

> 2026-10-04 카리나 규모 사전 판정: 15파일·약 665줄(테스트 약 400줄). 파일 단위 계획이 있고 사용자가 진행을 지시해 계획 반환을 면제한다. 20261001_2204와 `statusRules.ts`·`rules.test.ts`를 함께 건드리므로(함수는 다름) 나중에 머지되는 쪽이 `origin/staging` 위로 다시 분기한다.

**시작 시각(`onsetAt`)**: 신호 결과에 칸을 두고 규칙이 채운다. 예약 누락 = 공개 시각 + `missedScheduleMinutes`분, 루틴 실패 = 마감 시각(`weekDeadlineMs`·`monthDeadlineMs`), 실행 실패 = `updatedAt`(알림 대상에서는 뺀다). 기준값은 `loadOpsSignals`의 `resolveThresholdValues(overrides)`라 S7 값이 반영된다.
**한 시간 창**: 끝 = 예약 슬롯 시각(정시 + 5분, 지금이 그보다 이르면 한 시간 앞 슬롯), 창 = (끝 − 60분, 끝]. 호출이 몇 분 늦어도 창이 겹치거나 비지 않는다.
**고르기**: 수준 「중단」 가운데 `execution_failed` 제외, 상태 `raised`, 시작 시각이 창 안, 시험 묶음 아님. 걸린 것이 있으면 회차당 한 건만 `postOpsSlack('alert')`. `not_configured`면 오류 없이 건너뛰고 로그.
**중복 경계**: 실행 실패·멈춘 준비중·밖에서 지워짐은 상태 맞추기(⑦)가 알린다. 이 크론은 맞추기를 먼저 돌리고(`after`에서 `notifyReconcile`) 신호를 계산한다.

## 완료 조건

- 창 경계 테스트가 있다. 창 안에서 새로 걸린 것은 1번 알리고, 창 밖이거나 이미 지난 창에서 걸린 것은 알리지 않으며, 시험 묶음은 알리지 않는다.
- 슬랙 토큰이나 채널 값이 없으면 오류 없이 건너뛰고 기록을 남긴다(테스트).
- 크론이 `vercel.json`에 등록되어 있고, 크론 목록을 적은 문서(`04_PROJECT_SPEC.md` 크론 개수 문장 포함)가 새 크론을 반영한다.
- 운영툴 PRD §9에 이 알림 행이 있다.

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.
- 2026-10-04 착수 결정(사용자 지시 「개발 우선, 병렬 실행」에 따라 계획 검토의 추천안 채택): Q1 시작 시각은 결과 칸 `onsetAt`으로 둔다(규칙과 한 곳). Q2 상태 맞추기가 실패하면 예약 누락 알림만 건너뛰고 루틴 실패는 알리며 500을 돌려준다. Q3 묶음 원천을 못 읽으면(`load_failed`) 슬랙에 올리지 않고 로그만 남기고 500. 실행 시각은 정시 + 5분(다른 크론과 겹치지 않게). PRD 절 번호는 이 티켓이 §11.9, 1503 ⑤ 결정 기록 API가 §11.10, 1503 ⑦b 획득 경로 API가 §11.11을 쓴다.
- 2026-10-02 1500 ①(20261001_2205) 메모: 매시 점검은 신호를 계산하기 전에 1500 ⑦의 상태 맞추기 함수를 먼저 부른다(운영툴 PRD §8.6·§11.8). 그러지 않으면
  정상 공개된 항목이 「예약됨」에 남아 「예약 누락」(공개 시각 + 30분)으로 잘못 뜬다. 상태 맞추기는 10분마다 따로도 돈다. 실행 실패는 1500의 예약 등록·상태 맞추기가
  `#jam-alert`로 알리므로 이 점검은 알리지 않는다(핵심 요약과 같다). 1154가 ⑦보다 먼저 끝나면 이 호출 자리만 비워 두고 ⑦이 잇는다.
- 2026-10-02 1500 ⑦-b(20261002_1814) 메모: 매시 점검이 `reconcileOpsItems`를 부르면 **DB를 쓴다**(항목 상태와 결정 기록). 핵심 요약의 「DB는 쓰지 않는다」는
  신호 계산에 대한 말로 고쳐 읽는다. 맞추기는 크론(`/api/cron/ops-reconcile`, 10분마다)이 따로도 돌고 항목 상태를 조건부로 바꿔 겹쳐 돌아도 한 번만 바뀐다.
  이 점검이 맞추기를 부르는 방식은 1154 착수 때 정한다.
