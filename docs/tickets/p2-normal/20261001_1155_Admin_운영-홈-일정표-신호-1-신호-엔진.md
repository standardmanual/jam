# [Admin] 운영 홈·일정표·신호 ① 신호 엔진

> 상위: 20260930_1502 · 하위 순서 ① · 선행: 20261001_1159

## 핵심 요약

- 요구사항: 날짜별 구성 읽기(실제 카드·미션 + 운영 묶음 항목)와 신호 계산을 화면 없이 만든다. 신호 11종은 규칙까지, 밸런스 경고·획득 경로가 막힌
  컬렉션 2종은 「아직 확인하지 않아요」 상태의 자리만 둔다(1502 Q1). 시험 묶음 포함 여부를 인자로 받고 기본은 제외한다(Q2). 기준값은 코드 한 곳에
  모으고 운영툴 PRD §5.1에 값 표를 적는다(Q5). 「이미지 제작 필요」 판정과 옛→새 카드 모양 대응 순수 함수를 둔다.
- 구현 계획: 순수 함수 묶음 + 조회 함수 하나. 판정은 1502 가정 1~19를 따른다. 옛→새 모양 대응은 `jam-web/src/lib/today/`에 두어 1453-b가
  `resolveShape`로 재사용하게 한다(1453 확정 설계 6).
- 관련 파일: `jam-web/src/lib/admin/opsInbox/bundleStatus.ts`(`computeBundleStatus`), `jam-web/src/lib/today/exposure.ts`(`isNewUser`),
  `jam-web/src/lib/admin/contentGaps.ts`(기존 컨텐츠 공백 판정), `jam-web/src/app/admin/DashboardSignals.tsx`(기존 이상 신호),
  1159가 만든 칸 읽기 함수, `docs/specs/prd/ops-tool/PRD.md` §5·§5.1, 07 4.2.

## 시작 절차

상위 티켓 20260930_1502의 「주요 의사결정」(가정 1~20, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게
확인한다. 착수할 때 `/jam-work`로 파일 단위 구현 계획을 확정한다.

## 완료 조건

- 「13종 조건 표」 단위 테스트가 있다. 11종은 각자의 조건을 만들면 뜨고 조건 직전 값에서는 뜨지 않는다. 2종은 「아직 확인하지 않아요」 상태로 나온다.
- 실행 실패·예약 누락은 시험 데이터의 상태·시각으로 검증한다. 예약 누락은 `scheduled`·`preparing`만 본다(가정 19).
- 시험 묶음은 기본으로 빠지고, 포함 인자를 주면 들어가며 「시험」 표식이 붙는다(테스트).
- 기준값이 한 파일에 모여 있고, 운영툴 PRD §5.1의 값 표와 같다. 혜린 추정 초기값 4개(승인 마감 임박·예약 누락·루틴 실패·행동 횟수 급증)는
  「실측 아님」으로 표시한다. 행동 횟수 급증의 최소 건수는 카즈하가 실제 주간 값을 읽고 정한다.
- 「이미지 제작 필요」와 옛→새 모양 대응 함수에 단위 테스트가 있다.
