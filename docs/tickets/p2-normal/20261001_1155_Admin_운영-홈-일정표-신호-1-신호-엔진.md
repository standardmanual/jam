## 완료 조건

- 「13종 조건 표」 단위 테스트가 있다. 11종은 각자의 조건을 만들면 뜨고 조건 직전 값에서는 뜨지 않는다. 2종은 「아직 확인하지 않아요」 상태로 나온다.
- 실행 실패·예약 누락은 시험 데이터의 상태·시각으로 검증한다. 예약 누락은 `scheduled`·`preparing`만 본다(가정 19).
- 시험 묶음은 기본으로 빠지고, 포함 인자를 주면 들어가며 「시험」 표식이 붙는다(테스트).
- 기준값이 한 파일에 모여 있고, 운영툴 PRD §5.1의 값 표와 같다. 혜린 추정 초기값 4개(승인 마감 임박·예약 누락·루틴 실패·행동 횟수 급증)는
  「실측 아님」으로 표시한다. 행동 횟수 급증의 최소 건수는 카즈하가 실제 주간 값을 읽고 정한다.
- 「이미지 제작 필요」 판정에 단위 테스트가 있다. 옛 카드의 모양은 1453-b1의 `resolveShape`로 읽는다.

- 「착수 가정」 A1~A12를 사용자가 그대로 승인했다. 확인한 핵심은 루틴 실패를 1504 전까지 「아직 확인하지 않아요」로 두는 것(A1), 겹침의
  패턴·트라이브를 그날 시작하는 항목끼리 비교하는 것(A6), 승인 전 이미지 없음은 「이미지 제작 필요」 표시만 하는 것(A8)이다.
- 진행 방식: 한 번에 구현. 「구현 계획 (파일 단위)」를 사용자가 승인해 계획 반환 면제를 준다(규모 사전 판정: 파일 11개 안팎·1,500줄 안팎으로
  `plan_only` 임계값을 넘는다). 선택하지 않은 대안은 순수 함수와 조회 함수를 두 티켓으로 나누는 것이다. b1을 기다리는 시간은 줄지만 두 부분이
  같은 입력 형식을 공유하고 티켓·리뷰가 하나씩 늘어 고르지 않았다.
- 행동 횟수 급증 최소 건수(A10): 카리나가 프로덕션 DB를 읽기 전용으로 조회한 최근 9주 주간 합계(8월 5주는 모두 0, 9월 드랍 3~10·픽업 10~20·
  미션 완료 0~1·컬렉션 완성 0~2, 믹스 0)를 카즈하가 읽고 정했다. 믹스 성공은 믹스 시도와 겹쳐 따로 두지 않았다.
- 옛→새 모양 대응: 1453 세션 요청으로 1453-b1의 `resolveShape`를 import만 한다. 구현 호출은 b1 머지 뒤에 한다(A12). 1155가 쓰는 파일은
  b1의 파일(`shape.ts`·`cardView.ts`·`cards.ts`·`database.ts`)과 겹치지 않는다고 1453 세션에 알렸다.
