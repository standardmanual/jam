# [Admin] 운영 홈·일정표·신호 ② 운영 홈(S1)

> 상위: 20260930_1502 · 하위 순서 ② · 선행: 20261001_1155, 채원의 S1·S4 사전 판정과 사용자 승인

## 핵심 요약

- 요구사항: `/admin` 운영 홈에 이번 주 상태(승인 대기·예약됨·게재 중·실패 수) 단계 표시, 신호 영역, 최근 이력(`ops_decisions`)을 둔다.
  신호 영역은 기존 이상 신호·컨텐츠 공백을 흡수하고, 재료가 없는 신호는 「아직 확인하지 않아요」 구역에 따로 보인다. 위쪽에 「시험 묶음 포함해서
  보기」 스위치(기본 꺼짐)를 둔다(1502 Q2). 경제 추이·통계·빠른 실행은 그대로 둔다(가정 20).
- 구현 계획: 신호는 ①의 함수를 쓴다. 상태 칩은 `OpsStatusBadge`, 단계 계산은 `computeBundleStatus`를 S2·S3과 함께 쓴다. ADMIN_PRD §5-7의
  홈 몫을 새 동작에 맞게 고친다. 「미션 공백」 카드는 `contentGaps.ts` 판정을 바꾸지 않고 옮기기만 한다(1529 분리 유지).
- 관련 파일: `jam-web/src/app/admin/page.tsx`, `jam-web/src/app/admin/DashboardSignals.tsx`, `jam-web/src/app/admin/ContentGapCards.tsx`,
  `jam-web/src/components/admin/ops/OpsStatusBadge.tsx`, `docs/specs/prd/admin-ui/ADMIN_PRD.md` §5-7.

## 시작 절차

상위 티켓 20260930_1502의 「주요 의사결정」(가정 1~20, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게
확인한다. 착수할 때 `/jam-work`로 파일 단위 구현 계획을 확정한다.

## 완료 조건

- 샘플 묶음이 있을 때 스위치를 켜면 이번 주 상태 숫자와 신호가 「시험」 표시와 함께 보이고, 끄면 빠진다.
- 기존 요소(Strava·제재·POI 신호, KPI, 경제 추이, 통계, 빠른 실행)가 그대로 보인다.
- 조회가 실패하면 그 영역만 오류 카드로 바뀌고 나머지는 보인다.
- 「아직 확인하지 않아요」 구역에 밸런스 경고·획득 경로가 막힌 컬렉션이 보인다.
- ADMIN_PRD §5-7의 홈 몫이 새 동작과 같다. 「월~목에 다음 주가 비어 있는 것은 정상」 문장은 1502 가정 15에 맞춰 다시 쓴다.

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.
- 2026-10-01 ①(20261001_1155) 머지 메모. 신호는 `loadOpsSignals({ includeSample })`(`jam-web/src/lib/admin/opsSignals/load.ts`)로 읽는다. 신호마다
  상태가 뜸(`raised`)·안 뜸(`clear`)·확인 안 함(`unchecked`, 사유 `not_built`·`not_started`·`load_failed`)으로 나오고, 날짜별 구성(`compositions`)도
  함께 나온다. 서비스 클라이언트로 읽는 함수라 부르는 화면이 ADMIN 검사를 해야 한다(1155 게이트 보안 메모).
- 「밸런스 경고」는 1155에서 자리(`not_built`)만 두었다. 1459 조각 A가 1502용으로 만든 `evaluateBundleBalance`·`BalanceWarning`과 `OpsBalanceLine`
  (`showSampleChip`)을 이 티켓에서 연결할지 시작 검토 때 정한다(운영툴 PRD §5.2 「1502와 나누는 자리」).
