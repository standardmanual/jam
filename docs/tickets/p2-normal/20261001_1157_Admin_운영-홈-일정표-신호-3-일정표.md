# [Admin] 운영 홈·일정표·신호 ③ 일정표(S4)

> 상위: 20260930_1502 · 하위 순서 ③(마지막) · 선행: 20261001_1155, 20261001_1156

## 핵심 요약

- 요구사항: 새 경로의 일정표에 캘린더(월·주)와 타임라인 두 보기를 만든다. 기존 주간 캘린더를 옮겨 넓히고, 종류·트라이브·패턴으로 거르며, 칸마다
  상태와 신호를 표시한다. 타임라인은 미션 기간·드랍 일정·컬렉션 런칭 준비(`collection_launch` 공개 28일 전부터)를 막대로 보인다. 칸을 누르면
  오른쪽 서랍이 열리고, 항목 요약과 S3와 같은 항목 단위 승인·반려·편집을 할 수 있다(1502 Q4). 시험 묶음 스위치를 둔다(Q2).
- 구현 계획: 서랍은 `OpsDrawerFrame`에 S3의 `OpsItemDetail`·`OpsItemActions`·`OpsItemEditForm`과 `decisionClient`를 재사용해 같은 API와 결정
  기록을 쓴다. 미리보기·색 채우기·에셋 제너레이터는 1501이 같은 서랍에 더한다. 20260924_1151(캘린더 장기 카드 「활성 N · 비활성 M」)을 흡수한다.
  ADMIN_PRD §5-7의 일정표 몫과 운영툴 PRD §6의 S1·S4 절을 고친다.
- 관련 파일: `jam-web/src/app/admin/WeeklyCalendar.tsx`, `jam-web/src/components/admin/ops/OpsDrawerFrame.tsx`, `OpsItemDetail.tsx`,
  `OpsItemActions.tsx`, `OpsItemEditForm.tsx`, `decisionClient.ts`(같은 폴더), 티켓 `docs/tickets/p3-low/20260924_1151_Admin_캘린더-장기-카드-수에-비활성-카드-반영.md`.

## 시작 절차

상위 티켓 20260930_1502의 「주요 의사결정」(가정 1~20, 사용자 결정 Q1~Q5)이 이 티켓의 전제다. 그 결정과 다르게 가야 하면 멈추고 사용자에게
확인한다. 착수할 때 `/jam-work`로 파일 단위 구현 계획을 확정한다.

## 완료 조건

- 1502의 완료 조건을 모두 확인하고 1502를 닫는다(이 티켓이 마지막 하위다).
- 서랍에서 승인·반려·편집한 결과가 S3에서 한 것과 같은 결정 기록에 남는다(테스트).
- 서랍은 원래 화면을 가리지 않고, URL `?drawer=`로 열리며 Esc·「서랍 닫기」로 닫힌다.
- 1151의 완료 조건을 이 티켓에서 확인하고 1151을 닫는다.
