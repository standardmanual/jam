# [Service] 레시피 공개 시각 ① 공개 전 레시피 숨김과 믹스 차단

> 상위: 20260930_1458 · 하위 순서 ① · 선행 없음 · 유형 `db`(마이그레이션 204)

## 핵심 요약

- 요구사항: 레시피에 공개 시각(`valid_from`)을 둔다. 공개 시각이 미래인 레시피는 일반 유저의 믹스 화면(목록·검색·슬롯·보상 미리보기)에 나오지 않고, 믹스 시도는
  재료를 태우기 전에 `recipe_not_found`로 거절된다. 비어 있으면 지금처럼 바로 공개다. 이 조각에서는 **운영자도 예외 없이** 막는다(운영자 예외는 ③ 20261001_1159).
- 구현 계획: 아래 「구현 계획」(파일 단위, 혜린 초안·카리나 확정)을 따른다.
- 관련 파일: 「구현 계획」에 파일·함수·줄 위치가 있다.

## 시작 절차

상위 티켓 20260930_1458의 「주요 의사결정」(혜린 시작 검토, 사용자 결정 Q1~Q3, 가정 A1~A13)이 이 티켓의 전제다. 혜린 검토는 1458에서 끝났으므로 다시 하지 않는다.
그 결정과 다르게 가야 하면 멈추고 사용자에게 확인한다. 마이그레이션은 작성까지만 하고, 실행은 머지 뒤 사용자 승인을 받아 메인 세션(카리나)이 한다.

## 구현 계획

파일 단위 계획이다(혜린 초안, 카리나 확정 2026-10-01). 기준을 넘는 크기(약 16개 파일·300줄)라 이 계획으로 계획 반환을 면제한다. 줄 번호는 2026-10-01 staging(96f285b63)
기준이라 착수 때 함수·상수 이름으로 다시 찾는다.

1. **마이그레이션 204** `jam-web/supabase/migrations/204_combination_recipes_valid_from.sql`(새 파일).
   - `.claude/skills/jam-work/references/db-migration-rules.md`를 먼저 읽는다. 확장 단계 하나: `ALTER TABLE public.combination_recipes ADD COLUMN IF NOT EXISTS valid_from TIMESTAMPTZ;`
     + `COMMENT ON COLUMN`(null = 처음부터 공개, 값이 있으면 그 시각부터 공개, 티켓 번호). 백필 없음, 기존 3개 행은 null로 남아 즉시 공개가 유지된다.
   - 칸 이름은 `badges`·`item_books`의 `valid_from`과 같게 둔다(`171_item_books_validity_period.sql:10-12` 선례).
   - 파일 끝에 `-- 되돌림 SQL` 블록: `ALTER TABLE public.combination_recipes DROP COLUMN IF EXISTS valid_from;`. 칸을 지우면 예약 중인 레시피가 즉시 공개로 바뀌므로, 되돌리기 전에
     `SELECT count(*) FROM public.combination_recipes WHERE valid_from > now();`가 0인지 확인하고, 0이 아니면 그 레시피를 먼저 삭제하거나 시각을 지운다고 주석에 적는다.
   - **번호는 착수 때 원격 staging 기준으로 다시 확인한다**(2026-10-01 기준 최신 203). 밀리면 파일 이름만 바꾼다.
2. **타입** `jam-web/src/types/database.ts:550-559` `CombinationRecipeRow`에 `valid_from: string | null` 추가. 593줄 근처 주석 「존재하지 않거나 비활성화된 경우」를
   「존재하지 않거나 공개 전인 경우」로 정정. `jam-web/src/types/database.generated.ts`의 `combination_recipes` Row/Insert/Update(477줄~)에 `valid_from`을 손으로 맞춰 두고,
   마이그레이션 적용 뒤 카리나가 `generate_typescript_types`로 대조한다.
3. **판정 함수** `jam-web/src/lib/combine/visibility.ts`(새 파일, `lib/missions/visibility.ts:339-353`의 `isMissionExposed` 선례).

   - `recipeReleaseState(recipe, now)` → `'released' | 'scheduled'`(②·1500이 쓴다).
   - `filterReleasedRecipes<T>(recipes: T[], now)`.
4. **믹스 시도 차단** `jam-web/src/lib/combine/index.ts:98-110` `combineRecipeAttempt` 0단계. 조회 직후 `if (!recipe || !isRecipeReleased(recipe))`이면

## 완료 조건

- 공개 시각이 미래인 레시피는 일반 유저의 `/combine` 화면 데이터에서 빠지고, 시각이 지나면 들어온다(판정 함수 테스트 + page가 그 함수를 부르는 것은 리뷰로 확인).
- 공개 시각이 미래인 레시피로 믹스를 시도하면 재료 소각 없이 `recipe_not_found`가 나온다(테스트).
- `valid_from`이 비어 있는 기존 레시피는 지금과 똑같이 동작한다(기존 테스트 통과).
- 마이그레이션 204에 되돌림 SQL과 사전 확인 쿼리가 있다.
- 위 9번 문서가 갱신됐다.
