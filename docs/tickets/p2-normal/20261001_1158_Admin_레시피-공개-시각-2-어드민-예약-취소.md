# [Admin] 레시피 공개 시각 ② 어드민 예약·시각 수정·공개 전 취소

> 상위: 20260930_1458 · 하위 순서 ② · 선행: ① 20261001_1157, 영향 티켓 20261001_1200 · 유형 `admin`

## 핵심 요약

- 요구사항: 운영자가 어드민 레시피 폼에서 「바로 공개」 또는 「시각을 정해 예약」을 고른다. 예약된 레시피는 공개 전까지 시각을 바꾸거나 바로 공개로 돌리거나 취소(= 삭제)할
  수 있고, 공개 시각이 지난 레시피는 시각 변경과 취소가 409로 거절된다. 운영툴 자원 연결(1500)이 부를 서버 함수 세 개를 함께 만든다.
- 구현 계획: 아래 「구현 계획」(파일 단위, 혜린 초안·카리나 확정)을 따른다.
- 관련 파일: 「구현 계획」에 파일·함수·줄 위치가 있다.

## 시작 절차

상위 티켓 20260930_1458의 「주요 의사결정」(가정 A3~A6·A10, Q3)이 이 티켓의 전제다. ①이 머지되고 마이그레이션 204가 적용된 뒤, 그리고 영향 티켓 20261001_1200(레시피 삭제
가드)이 끝난 뒤 시작한다. 어드민 화면이라 채원 판정과 MODULAR 적용은 제외다(`jam-web/CLAUDE.md`). 실렌더 검증은 카리나가 머지 뒤 push 전에 한다(`/jam-work` 0.2 `admin`).

## 구현 계획

파일 단위 계획이다(혜린 초안, 카리나 확정 2026-10-01). 기준을 넘는 크기(약 19개 파일·550줄)라 이 계획으로 계획 반환을 면제한다. 줄 번호는 2026-10-01 staging(96f285b63)
기준이라 착수 때 함수 이름으로 다시 찾는다.

1. **입력 검증** `jam-web/src/lib/combine/recipe-payload.ts:36-50,57-97`. `valid_from`을 받는다: 빈 값·null은 바로 공개, 값이 있으면 시간대가 포함된 ISO이고 해석 가능하며
   미래여야 한다(과거는 오류, 가정 A6). 오류 문구는 현상 → 원인 → 해결책.
2. **쓰기 함수** `jam-web/src/lib/admin/recipe-write.ts:23-27,35-103,106-134`.
   - `RecipeRow`에 `valid_from?`(제출하지 않으면 행에 넣지 않는다).
   - 새 `createRecipeWithSlots`(지금 `app/api/admin/recipes/route.ts` POST 63-77줄의 생성 로직을 옮긴다). 1500이 부른다.
   - 새 `cancelScheduledRecipe(id, now)`: `collectRecipeReferences` 가드(영향 티켓 1200이 `recipe_first_success` 참조를 세게 만든다)를 먼저 부르고, 원자적으로
     `delete().eq('id', id).gt('valid_from', now)`. 지운 행이 없으면 「이미 공개됨」(409) 또는 「없음」(404)을 구분해 돌려준다. 1500이 부른다.
   - 새 `assertValidFromChange(existing, nextValidFrom, now)`: 기존 행이 이미 공개면(`isRecipeReleased`) 시각 변경 거절. 예약 상태면 다른 미래 시각 또는 null(바로 공개)로 바꿀 수 있다.
   - `recipeReleaseState`(①의 `lib/combine/visibility.ts`)를 1500용으로 다시 내보내거나 그대로 쓰게 한다.
3. **생성 API** `jam-web/src/app/api/admin/recipes/route.ts:50-80` POST가 `createRecipeWithSlots`를 쓴다.
4. **수정 API** `jam-web/src/app/api/admin/recipes/[id]/route.ts:53-82` PATCH가 기존 행을 읽고 `assertValidFromChange`, 거절이면 409.
5. **취소 API** `jam-web/src/app/api/admin/recipes/[id]/cancel-release/route.ts`(새 파일). `requireAdmin()`, 404 / 409(이미 공개) / 200.
6. **목록** `jam-web/src/lib/admin/recipe-list.ts:11-16` 조회 칸에 `valid_from`. 「레시피에는 활성 여부 칸이 없다」 주석(5줄) 정정.
7. **목록 화면** `jam-web/src/app/admin/recipes/RecipeTable.tsx:63-131`에 「공개」 열(공개됨 / 공개 예정 `formatKstYmdHm`, `lib/admin/kst-format.ts:38-49`). 47-49줄 주석 정정.
   공개 상태 필터는 만들지 않는다(이름 검색만 유지).

## 완료 조건

- 폼에서 미래 시각으로 저장한 레시피는 목록에 「공개 예정」으로 보이고, ①의 판정대로 일반 유저에게 숨겨진다.
- 예약 상태 레시피는 시각 변경·바로 공개 전환·취소가 되고, 공개된 레시피는 시각 변경과 취소가 409로 거절된다(테스트).
- 과거 시각 입력은 저장되지 않는다(테스트).
- 취소는 레시피 삭제 가드를 거친다(테스트).
- 1500이 부를 `createRecipeWithSlots`·`cancelScheduledRecipe`·`recipeReleaseState`가 서버 함수로 있다.
- 위 12번 문서가 갱신됐다.
