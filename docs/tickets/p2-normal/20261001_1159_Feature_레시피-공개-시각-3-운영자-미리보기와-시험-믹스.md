# [Feature] 레시피 공개 시각 ③ 운영자 미리보기와 시험 믹스

> 상위: 20260930_1458 · 하위 순서 ③ · 선행: ① 20261001_1157 · 유형 `ui`(채원 판정)

## 핵심 요약

- 요구사항: 운영자 계정(`hasAdminAccess`: 허용 이메일 목록 또는 `users.is_admin`)은 믹스 화면에서 공개 전 레시피를 「공개 예정」 표시와 함께 보고 믹스할 수 있다.
  운영자가 공개 전 레시피로 믹스하면 **시험 믹스**다: 재료 소모와 보상 지급(배지·포인트, 실패 시 위로 포인트)은 실제와 같고, 성공·실패 기록(`user_combine_success_logs`·
  `user_combine_fail_logs`)과 JAM! 믹스 지표 판정(최초 성공, 시도·성공·실패 횟수)에는 넣지 않는다. 일반 유저는 ①대로 계속 막힌다.
- 구현 계획: 아래 「구현 계획」을 따른다. 「공개 예정」 표시와 시험 믹스 결과 안내의 모양은 채원①이 판정한다.
- 관련 파일: 「구현 계획」에 파일·함수·줄 위치가 있다.

## 시작 절차

상위 티켓 20260930_1458의 「주요 의사결정」(사용자 결정 Q1·Q1-1, 가정 A13)이 이 티켓의 전제다. ①이 머지된 뒤 시작한다. 채원①이 새 UI·새 토큰이 필요하다고 판정하면
아현 호출 전에 멈추고 사용자 승인을 받는다.

## 완료 조건

- 운영자 계정은 공개 전 레시피를 「공개 예정」 표시와 함께 보고, 일반 유저는 보지 못한다.
- 운영자의 공개 전 믹스는 재료 소모와 보상 지급이 실제와 같고, 성공·실패 기록과 믹스 지표 판정에 들어가지 않는다(테스트).
- 공개 시각이 지난 레시피는 운영자가 믹스해도 일반 믹스와 똑같이 기록된다(테스트).
- 위 6번 문서가 갱신됐다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- 엔진 `combineRecipeAttempt`(`lib/combine/index.ts`): 네 번째 인자 `options.allowUnreleased`. 공개 전 레시피이고 `allowUnreleased`면 시험 믹스(`testMix`)로 계속한다. 재료 소각·칸 반환·Consume·
  보상 배지·포인트·위로 포인트는 그대로 하고, `recordCombineSuccess`와 0단계(레시피 조회) 이후의 실패 이력은 건너뛴다. 결과에 `testMix: true`, `jamTriggersForCombineResult`는 빈 배열.
  맨 앞 `invalid_count`는 시험 여부를 알기 전이라 기존대로 이력을 남긴다. 일반 유저는 ①대로 `recipe_not_found`, 공개 후 레시피는 운영자도 일반 믹스다.
- 라우트 `api/combine/route.ts`: `hasAdminAccess`를 `allowUnreleased`로 넘긴다(예외면 false). 응답 키는 그대로이고 시험 믹스에만 `testMix`가 붙는다. 클라이언트가 이 값을 정할 수 없다.
- 화면: `page.tsx`는 운영자 판정을 기존 `Promise.all`에 넣고(실패하면 false) 운영자면 공개 필터를 건너뛴다. `releaseAt`은 `isRecipeReleased`가 거짓인 행에만 `valid_from`.
  `RecipeRewardRow`의 선택 prop `releaseAt` → 「공개 예정 · 10월 6일 오후 3시 30분」 한 줄(`--color-warning`, 두 조각 `whitespace-nowrap` + `flex-wrap`). 목록 행과 믹서 요약 바가 같이 바뀐다.
  `CombineClient`는 CTA 아래 조건형 캡션(`testMixPreNotice`)과, 결과 창을 닫을 때 응답의 `testMix`만 근거로 띄우는 info 토스트(`testMixNotice`). 문구 3개는 `ko.ts` combine 블록.
- 채원① 판정: 서비스 전용(기존 어댑터 확장), MODULAR 변경·새 토큰·새 컴포넌트 없음(`needsApproval: false`). 노란색은 운영자 전용 표시 선례(`QuestPreviewBanner`)를 따랐다.
  칩·배너·아이콘·흐림 처리·CTA 라벨 변경은 하지 않는다. 날짜는 티켓 계획의 「M/D(요일) HH:MM」이 UX Writing 가이드 §3 위반이라 「10월 6일 오후 3시 30분」(행에서는 요일 없음)으로 바로잡았다.
  연결 범위: `ui` 유형이라 해당 없음.
- 문서: `COMBINE_RECIPES.md` 「공개 시각」 절에 「운영자 시험 믹스」, `BADGE_ENGINE_UNIFIED.md` 믹스 지표·믹스 판정 절에 시험 믹스 제외, `01_PRD.md` 믹스 행에 운영자 미리보기.
