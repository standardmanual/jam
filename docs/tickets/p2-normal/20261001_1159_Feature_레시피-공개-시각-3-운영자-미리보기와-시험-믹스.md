# [Feature] 레시피 공개 시각 ③ 운영자 미리보기와 시험 믹스

> 상위: 20260930_1458 · 하위 순서 ③ · 선행: ① 20261001_1157 · 유형 `ui`(채원 판정)

## 핵심 요약

- 요구사항: 운영자 계정(`hasAdminAccess`: 허용 이메일 목록 또는 `users.is_admin`)은 믹스 화면에서 공개 전 레시피를 「공개 예정」 표시와 함께 보고 믹스할 수 있다.
  운영자가 공개 전 레시피로 믹스하면 **시험 믹스**다: 재료 소모와 보상 지급(배지·포인트, 실패 시 위로 포인트)은 실제와 같고, 성공·실패 기록(`user_combine_success_logs`·
  `user_combine_fail_logs`)과 JAM! 믹스 지표 판정(최초 성공, 시도·성공·실패 횟수)에는 넣지 않는다. 일반 유저는 ①대로 계속 막힌다.
- 구현 계획: 아래 「구현 계획」을 따른다. 「공개 예정」 표시와 시험 믹스 결과 안내의 모양은 채원①이 판정한다.
- 관련 파일: 「구현 계획」에 파일·함수·줄 위치가 있다.

## 시작 절차

상위 티켓 20260930_1458의 「주요 의사결정」(사용자 결정 Q1·Q1-1, 가정 A13)이 이 티켓의 전제다. ①이 머지된 뒤 시작한다. 채원①이 새 UI·새 토큰이 필요하다고 판정하면
아현 호출 전에 멈추고 사용자 승인을 받는다.

## 구현 계획

파일 단위 계획이다(카리나 작성 2026-10-01, ①의 구조를 전제로 한다). 기준을 넘는 크기(약 10개 파일·250줄 추정)라 이 계획으로 계획 반환을 면제한다. 줄 번호는 2026-10-01
staging(96f285b63) 기준이라 착수 때 함수 이름으로 다시 찾는다.

1. **믹스 화면 데이터** `jam-web/src/app/(main)/combine/page.tsx`. 로그인 유저로 `hasAdminAccess(user.id, user.email)`(`lib/admin/auth.ts:33`)를 한 번 부른다. 운영자면
   ①의 `filterReleasedRecipes`를 건너뛰고, 공개 전 레시피마다 `releaseAt`(= `valid_from`)을 클라이언트에 넘긴다. 운영자가 아니면 ①과 같다.
2. **믹스 화면 표시** `jam-web/src/app/(main)/combine/CombineClient.tsx`(레시피 카드·목록 511-517줄 근처). `releaseAt`이 있는 레시피에 「공개 예정 · M/D(요일) HH:MM」 표시.
   시험 믹스 결과(응답의 `testMix: true`)에 「공개 전 시험 믹스라 기록에 남지 않아요」 같은 안내. 모양·문구 위치는 채원① 판정을 따른다. 문구는 `ko.ts`에 둔다.
3. **믹스 라우트** `jam-web/src/app/api/combine/route.ts:29-61`. `hasAdminAccess(user.id, user.email)`로 운영자 여부를 구해 `combineRecipeAttempt(user.id, recipeId, itemIds,
   { allowUnreleased: isAdmin })`로 넘긴다. 응답 JSON 키는 기존 그대로 두고 `testMix`만 더한다.
4. **믹스 판정** `jam-web/src/lib/combine/index.ts` `combineRecipeAttempt`.
   - 네 번째 인자 `options?: { allowUnreleased?: boolean }`. ①이 넣은 공개 판정에서 공개 전이고 `allowUnreleased`가 아니면 그대로 `recipe_not_found`. 운영자면 `testMix = true`로 계속.
   - `testMix`면 `recordCombineSuccess`(435줄~)와 모든 `logFailure` 호출을 건너뛴다. 재료 소각, `release_inventory_slots`, Consume 이벤트, 보상 배지 지급(`grantBadge`),
     포인트 지급(`combine_recipe_reward`·`combine_fail_reward`)은 그대로 한다.
   - 결과 객체(`CombineResult`)에 `testMix?: true`를 더한다.
   - `jamTriggersForCombineResult`(463줄~)는 `result.testMix`면 빈 배열을 돌려준다.
5. **테스트**
   - `jam-web/src/lib/combine/__tests__/combine-engine.test.ts`: 공개 전 + 운영자 성공(보상 지급됨, `record_combine_success` 호출 0회, `testMix: true`), 공개 전 + 운영자 미매칭
     (소각·위로 포인트 있음, 실패 로그 0건), 공개 전 + 일반 유저(①과 같이 `recipe_not_found`), 공개 후 + 운영자(시험 믹스 아님, 기록 남음).
   - `jamTriggersForCombineResult`가 `testMix`면 빈 배열(같은 파일 또는 지표 테스트).
   - 믹스 라우트 테스트가 있으면 `allowUnreleased` 전달을 확인한다.
6. **문서**
   - `jam-doc/planning/content/COMBINE_RECIPES.md` 「공개 시각」 절에 「운영자 시험 믹스」(보이는 범위, 실제로 처리되는 것과 기록에서 빠지는 것, 이유: 실제 첫 성공 유저의 최초 성공 몫).
   - `docs/specs/badge-engine/BADGE_ENGINE_UNIFIED.md` JAM! 행동 지표 절의 믹스 지표 계산에 「운영자의 공개 전 시험 믹스는 기록·판정하지 않는다」.
   - `docs/specs/prd/01_PRD.md` 믹스 절에 운영자 미리보기 한 줄.

## 완료 조건

- 운영자 계정은 공개 전 레시피를 「공개 예정」 표시와 함께 보고, 일반 유저는 보지 못한다.
- 운영자의 공개 전 믹스는 재료 소모와 보상 지급이 실제와 같고, 성공·실패 기록과 믹스 지표 판정에 들어가지 않는다(테스트).
- 공개 시각이 지난 레시피는 운영자가 믹스해도 일반 믹스와 똑같이 기록된다(테스트).
- 위 6번 문서가 갱신됐다.
