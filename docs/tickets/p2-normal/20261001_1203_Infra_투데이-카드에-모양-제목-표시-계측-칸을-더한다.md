# [Infra] 투데이 카드에 모양·제목 표시·계측 칸을 더한다 (1453-c1)

> 상위: 20260930_1453 「확정 설계」 9절·11절 조각 c1 · 결정 4·6·16·18

## 핵심 요약

- 요구사항: 새 카드 형식에 필요한 칸 3개를 확장 단계로 더한다. 모두 NULL 허용이고 기존 행은 NULL로 남는다(백필 없음).
  - `today_cards.shape` TEXT NULL, CHECK `shape IS NULL OR shape IN ('hero','poster','square','brief','list')`
  - `today_cards.title_in_image` BOOLEAN NULL. NULL이면 옛 카드라 규칙으로 판정한다(1453 결정 12). 새 카드부터 값을 저장한다(결정 6·18)
  - `today_card_events.card_shape` TEXT NULL. 기록 시점에 「그려진 모양」을 복사한다(결정 4). 설계 9절대로 CHECK는 두지 않는다
- 구현 계획: 마이그레이션 206 한 파일. 이 티켓은 SQL 파일 작성까지이고, 실행과 타입 재생성은 승인 뒤 카리나가 한다.
  이 칸을 읽고 쓰는 코드는 b1·c2에서 만들며, **DB 실행이 그 코드보다 먼저다**(1453 결정 16).
- 관련 파일:
  - `jam-web/supabase/migrations/206_today_cards_shape_and_events_card_shape.sql`(신규. 번호는 착수 직전에 최신+1인지 다시 확인한다.
    조각 a의 205와 같은 날 실행한다)
  - 선례: `jam-web/supabase/migrations/183_today_card_type_and_events.sql` 36~45줄(`content_type_id` 추가와 CHECK 형식)
  - `docs/specs/prd/02_DATA_MODEL.md`의 `today_cards`·`today_card_events` 절(칸 설명 추가)
  - `docs/specs/prd/home-feed/PRD.md` 데이터 절(칸 설명. 그리는 규칙은 b1~b7에서 적는다)

## 배경 / 문제 정의

- 1453 확정 설계 9절은 `shape`와 `card_shape` 두 칸만 적었다. 사용자가 2026-10-01에 「이미지에 제목 있음」 칸을 함께 더하기로 정했다(결정 18).
  이 칸이 없으면 이미지 안에 제목이 있는 새 카드에서 제목이 이미지 안과 카드 아래에 두 번 나온다.
- 드랍 시각·연재 「몇 막」·레시피 연결처럼 직접 입력하는 칸은 그 자원을 만드는 1457·1458·1500에서 만든다(결정 18).
- 공용 DB라 실행 즉시 운영에 반영된다. 옛 코드는 `select('*')`로 카드를 읽고 새 칸을 무시하므로, 칸 추가만으로는 동작이 바뀌지 않는다.

## 구현 계획

1. 183의 형식을 따라 `ADD COLUMN IF NOT EXISTS`와 `DROP CONSTRAINT IF EXISTS` → `ADD CONSTRAINT`로 쓴다(다시 실행해도 안전하게).
2. 칸마다 `COMMENT ON COLUMN`으로 뜻을 적는다(NULL의 의미 포함).
3. 되돌림 SQL(제약 삭제 → 칸 삭제)과 실행 뒤 확인 쿼리(칸 존재, 기존 행 전부 NULL, 제약 정의)를 주석으로 남긴다.
4. 새 인덱스는 더하지 않는다. 모양별 집계 방식은 c2에서 정하고 필요하면 그때 더한다.
5. 데이터 모델 문서와 홈피드 PRD 데이터 절에 칸 설명을 더한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 마이그레이션 206이 위 칸 3개와 `today_cards.shape`의 CHECK를 더하고, 다시 실행해도 오류가 나지 않는다.
- 되돌림 SQL과 실행 뒤 확인 쿼리가 파일에 있다.
- 데이터 모델 문서와 홈피드 PRD에 칸 3개의 뜻과 NULL의 의미가 적혀 있다.
- `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤 push 전)
- 사용자 승인 뒤 마이그레이션 206를 실행하고, 확인 쿼리 결과(기존 71행 이상 전부 NULL)를 이 티켓에 적는다.
- `jam-web/src/types/database.generated.ts`를 다시 만들어 같은 커밋 묶음에 넣는다.
- 실행 뒤 홈 조회와 카드 노출 기록이 계속 동작하는지 확인한다(이벤트 행이 계속 쌓이는지 조회).
