# [Infra] 메인 폴더를 함께 쓰는 병렬 세션의 커밋이 섞이고, 같은 분에 만든 티켓 ID가 겹친다

## 핵심 요약

- 요구사항: 여러 카리나 세션이 메인 폴더에서 동시에 커밋해도 서로의 변경이 한 커밋에 섞이지 않게 하고, 병렬 세션이 같은 분에 만든 티켓 ID가
  겹치면 커밋 전에 잡아낸다.
- 구현 계획: (가정 1) 처리 규칙표에 「메인 폴더 커밋은 `git commit --only -- <경로>`로 한다」를 넣는다. (가정 2) 커밋 때 같은 `id`를 가진 티켓
  파일이 둘 이상이면 차단하는 검사를 `.githooks/pre-commit`에 더하고, push 전에 `origin/staging`과도 대조한다. (가정 3) 티켓을 만들 때 쓰는 ID가
  로컬과 `origin/staging` 어디에도 없는지 확인하는 한 줄 명령을 `/jam-docs` 티켓 절차에 넣는다.
- 관련 파일: `.claude/skills/jam-work/references/handling-rules.md`, `.githooks/pre-commit`, `.githooks/pre-push`, `scripts/doc-check.mjs`,
  `.claude/skills/jam-docs/SKILL.md` 「② 티켓」 파일명 절.

## 배경 / 문제 정의

### 확인한 사실 (2026-10-01 KST)
- 12:04 세션 283edd(1502)가 제 파일 15개만 스테이징한 것을 확인한 뒤 `git commit`을 실행했는데, 커밋 `a3142505f`에는 27개 파일이 들어갔다.
  나머지 12개는 같은 메인 폴더에서 일하던 세션 634b5e(1516·1519·1645 머지)가 그사이에 스테이징한 파일이었다. 634b5e는 빈 기록 정정 커밋
  `bd9ebf79d`로 이 사실을 남겼다.
- 같은 시각 세 세션이 티켓을 연달아 만들면서 ID가 겹쳤다. 1502 세션의 20261001_1157~1159와 1458 세션의 1157~1159, 1516 세션의
  1201~1204와 1453·1458 세션의 1201~1204, 634b5e의 1204와 1453 세션의 1204가 겹쳤다. 겹친 쪽은 1152~1154, 1205, 1208로 옮겼다
  (커밋 `39b1b712d`, `bd9ebf79d`).
- 겹친 상태의 커밋(`a3142505f` 위의 병합 `9f780aa25`)은 pre-commit·pre-push를 통과해 `origin/staging`에 올라갔다. 지금 검사는 같은 `id`를
  가진 티켓 파일이 둘 있어도 막지 않는다.

### 판단
- 메인 폴더의 스테이징 영역은 그 폴더를 쓰는 모든 세션이 공유한다. 스테이징을 확인한 뒤 커밋하기 전까지의 짧은 틈에 다른 세션이 끼어들 수 있으므로,
  확인 절차로는 막을 수 없고 커밋 방식 자체를 바꿔야 한다. `git commit --only -- <경로>`는 지정한 경로만 커밋하고 다른 스테이징을 건드리지 않는다.
- HHMM 규칙(2026-08-27 전환)은 NNN 번호 충돌을 줄였지만, 하위 티켓을 한 번에 여러 개 만들며 분을 하나씩 올리는 관행 때문에 병렬 세션끼리 같은
  분을 다시 쓰게 된다. 생성 시점의 확인과 커밋 시점의 차단이 둘 다 필요하다.
- 세션이 워크트리 대신 메인 폴더에 몰리는 이유 가운데 하나는 워크트리가 자동 정리로 사라지는 문제(티켓 20261001_1143)다. 그 티켓이 해결되면 메인
  폴더 공유 자체가 줄어든다.

## 완료 조건

- 처리 규칙표에 메인 폴더 커밋 방식 규칙이 근거 티켓과 함께 있다.
- 같은 `id`를 가진 티켓 파일 두 개를 만든 임시 저장소에서 커밋하면 pre-commit이 두 경로를 보여 주며 차단한다(테스트). 서로 다른 `id`면 통과한다.
- push 전에 `origin/staging`에 같은 `id`의 다른 파일이 있으면 pre-push가 차단한다(테스트).
- `/jam-docs` 티켓 절차에 ID 사용 여부 확인 명령이 있다.
