# [Admin] 경제 시뮬레이터의 드랍 확률이 옛 버전(v1)이다

> 상위: 20260930_1450 · 영향 티켓(진행 규칙 4) · 20260930_1459 시작 검토에서 혜린이 발견

## 핵심 요약

- 요구사항: `/admin/simulator`의 아이템 드랍 결과가 지금 드랍 엔진과 같은 확률 체계로 나오게 한다. 지금은 v1 상수로 드랍을 굴려서,
  이 결과로 경제를 판단하면 어긋난다.
- 구현 계획: ① 결과 패널에 「드랍은 옛 기준이라 참고용」 고지를 달고 잘못된 주석을 바로잡는다(바로 할 수 있다). ② 드랍 롤을
  `drop-engine`의 순수 함수로 바꾸고 `drop_policy` 값을 읽게 한다. ②는 실측 티켓 20261001_1220와 함께 해도 된다.
- 관련 파일: `jam-web/src/app/api/admin/simulate/route.ts` 20~34행(`RARITY_THRESHOLDS` 40/25/10/5와 주석 「drop-engine과 동일」,
  `rollRarity`), `jam-web/src/lib/drop-engine/policy.ts` 12~15행(엔진 기본값 0.6/0.28/0.09/0.03), `jam-web/src/lib/drop-engine/layers.ts`,
  `jam-web/src/app/admin/simulator/page.tsx`(결과 패널).

## 배경 / 문제 정의

- 시뮬레이터는 등급별 누적 문턱 0.40/0.65/0.75/0.80으로 드랍을 굴린다. 엔진 기본값은 등급 비율 0.6/0.28/0.09/0.03이다
  (2026-10-01 코드 확인).
- 주석이 「drop-engine과 동일」이라 적혀 있어 결과를 그대로 믿기 쉽다. 20260930_1459의 밸런스 규칙은 시뮬레이터 실측값을 근거로
  쓰는 것이 원칙인데, 지금 시뮬레이터로는 그 근거를 만들 수 없다.

## 완료 조건

- 시뮬레이터 화면의 드랍 결과가 현재 `drop_policy` 값과 같은 확률 체계로 나온다(같은 난수 입력으로 엔진 함수와 대조하는 테스트).
- 잘못된 주석과 v1 상수가 남아 있지 않다.
