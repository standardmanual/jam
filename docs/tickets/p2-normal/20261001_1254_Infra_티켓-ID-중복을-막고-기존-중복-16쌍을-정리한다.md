# [Infra] 병렬 세션의 티켓 ID 중복을 막고, 기존 중복 16쌍을 정리한다

> 2026-10-01 병렬 세션(1022·1502·1458·1453 세션)이 같은 분 단위 ID로 티켓을 만들어 중복이 4쌍 생겼다(1157·1158·1159·1204, 당일 정리). 확인 중 옛 중복 16쌍도 발견했다.

## 핵심 요약

- 요구사항: 티켓 ID(`YYYYMMDD_HHMM`)는 만드는 시각이라 「병렬 세션과 경합하지 않는다」는 전제(`/jam-work` 1단계 2번)가 깨졌다. 같은 분에 여러 세션이 만들거나,
  한 세션이 여러 개를 만들며 분을 하나씩 올리면 다른 세션과 겹친다. 중복을 커밋 때 막는 장치와 ID를 정하는 규칙을 둔다. 기존 중복 16쌍을 정리한다.
- 구현 계획: 착수 때 정한다. 후보: (가) pre-commit 문서 검사에 「같은 id가 둘 이상」 차단 추가, (나) ID 규칙에 「같은 분에 여러 개면 초를 붙인다」 같은 꼬리 규칙,
  (다) 기존 16쌍은 나중에 만든 쪽 ID를 바꾸고 참조(상위 티켓 표·본문 언급)를 함께 고친다.
- 관련 파일: `.githooks/pre-commit`, `scripts/doc-check.mjs`(또는 문서 검사 설정), `.claude/skills/jam-work/SKILL.md` 1단계 2번, `.claude/skills/jam-docs/SKILL.md`(파일명 규칙),
  기존 중복 ID(2026-10-01 origin/staging 기준): 20260906_1420·1421·1422·1424, 20260907_2138, 20260908_0010·0040, 20260910_1719·1804·2258, 20260911_1019·2137·2235, 20260912_2116, 20260914_1045, 20260917_2042

## 완료 조건

- 같은 id를 가진 티켓 파일 두 개를 커밋하려 하면 pre-commit이 막는다(시험 커밋으로 확인).
- 기존 중복 16쌍이 0쌍이 되고, 바뀐 ID를 가리키던 참조가 남아 있지 않다.
- ID 규칙 문서가 병렬 세션 상황을 설명한다.
