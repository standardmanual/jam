# [API] 투데이 카드 모양 판정과 표시 데이터 변환 (1453-b1)

> 상위: 20260930_1453 「확정 설계」 1·2·3·6·8절, 11절 조각 b1 · 결정 6·12·13·17·18 · 화면 변화 없음

## 핵심 요약

- 요구사항: 새 카드 그리기(b2~b5)와 운영툴 미리보기(1501)가 함께 쓸 **순수 함수**를 만든다. 카드 행에서 「그릴 모양」을 정하는 함수와, 카드 행을
  「표시 데이터」(카드 행·DB 없이도 만들 수 있는 화면용 값 묶음)로 바꾸는 함수다. 이 조각에서는 홈 화면이 바뀌지 않는다.
- 구현 계획:
  1. `jam-web/src/lib/today/shape.ts`(티켓 20261001_1152가 만든 상수·술어 파일)에 `resolveShape`(카드 행 → 모양, 1453 확정 설계 6절 대응표),
     전환 상수 `LEGACY_SHAPE_CUTOVER = false`, 그려질 모양 판정 함수(예: `drawnShape`)를 더한다. 기존 상수·술어는 그대로 쓴다.
  2. `jam-web/src/lib/today/cardView.ts`(신규)에 표시 데이터 타입과 `toCardView`·`buildFacts`를 둔다.
  3. `getTodayCards`가 표시 데이터에 필요한 자원 값(미션 기간·보상, 컬렉션 이름·아이템 수)을 함께 실어 보낸다.
- 관련 파일:
  - `jam-web/src/lib/today/shape.ts`(1~30줄, 머리 주석이 이 조각을 가리킨다) · `jam-web/src/lib/today/__tests__/shape.test.ts`
  - `jam-web/src/lib/today/cardView.ts`(신규) · `jam-web/src/lib/today/__tests__/cardView.test.ts`(신규)
  - `jam-web/src/lib/today/cards.ts`: 47~57줄 `TodayCardWithHref`, 65~110줄 `getTodayCards`, 156~198줄 `filterMissionSpotlightCards`(이미 `missions` 행을 읽는다, 168줄)
  - `jam-web/src/types/database.ts` 1039~1080줄(`TodayCardTemplateType`·`TodayCardLayoutType`·`TodayCardRow`. 마이그레이션 206의 `shape`·`title_in_image`를 `TodayCardRow`에 더한다)

  - 문서: `docs/specs/prd/home-feed/PRD.md`(머리말 `code:`에 `shape.ts`가 이미 걸려 있다. 아래 「문서」 참조)

## 배경 / 문제 정의

- 1453 결정 17: 옛 카드는 마지막 조각 b7에서 한 번에 새 모양으로 바꾼다. 그 전에는 `shape`가 저장된 카드와 미리보기만 새 모양으로 그린다.
  그래서 「대응표상의 모양」과 「지금 그려질 모양」을 나눈다.
- 1453 확정 설계 8절: 표시 데이터만으로 그릴 수 있어야 한다(운영툴이 승인 전 초안을 그린다). 카드 ID·활성 여부·노출 기간·정렬 순서·유저별 보유
  여부 없이도 만들어져야 한다.
- 티켓 20261001_1152가 `shape.ts`를 만들며 홈피드 PRD 동기화 검사를 「b1에서 고친다」 사유로 건너뛰었다. 이 조각이 PRD를 맞춘다.
- 티켓 20261001_1155(1502 신호 엔진)도 옛→새 모양 대응이 필요하다. 이 조각의 `resolveShape`를 1155가 가져다 쓴다(2026-10-01 1502 세션에 알림).

## 상세 요구사항

### 1. 모양 판정 (`shape.ts`)

- `resolveShape(card)`: `card.shape`가 모양 값이면 그대로, 아니면 옛 `layout_type`으로 정한다(1453 확정 설계 6절).
  - `large_thumbnail` → `hero`. 예외 두 가지는 `square`: 미션 소개 카드(`template_type = 'mission_spotlight'`), 그리고 `cover_image_url`이 없어
    첫 배지 그림으로 승격되던 카드(`TodayCardStack.tsx` 54~64줄의 지금 규칙)
  - `banner` → `poster`. `cover_image_url`이 없으면 `brief`
  - `badge_gallery` → `list`(타일형). `shortcut`·`other` → `brief`. `ranking_list` → `list`(행형)
  - `template_type = 'editorial_article'`은 레이아웃과 관계없이 `hero`(기사는 `hero` 고정, 1453 확정 설계 1절)
  - `list`의 타일형·행형 구분은 표시 데이터가 정한다(랭킹 카드면 행형, 아니면 타일형). 타일이 0개인 타일형은 `brief`로 그린다(확정 설계 1절)
- `LEGACY_SHAPE_CUTOVER = false`(b7에서 `true`로 바꾼다)와 그려질 모양 판정: `card.shape`가 있으면 그 값, 없으면 전환 상수가 켜졌을 때만 `resolveShape`,
  꺼져 있으면 `null`(옛 렌더러로 그린다는 뜻).
- 이미지에 제목 있음 판정(결정 6·12): `title_in_image`가 `true`/`false`면 그 값. `NULL`(옛 카드)이면 미션 소개 카드이고 `cover_image_url`이 연결 미션의
  `image_url`과 같을 때만 `true`, 그 밖은 `false`.

### 2. 표시 데이터 (`cardView.ts`)

- 타입(1453 확정 설계 8절): 필수 `shape`·`resource`·`title`. `hero`·`poster`·`square`는 `imageUrl`, `list` 타일형은 `tiles`가 더 필요하다.
  선택 `subtitle`·`description`·`facts`(최대 2)·`href`·`publishedAt`·`titleInImage`·`now`. 2·3절을 그리는 데 필요한 값(예: 희귀도, 타일별 보유
  여부, 랭킹 행)은 선택 필드로 더해도 되지만, 카드 ID·활성 여부·노출 기간·정렬 순서 없이 만들어져야 한다.
- 계측 정보(카드 ID·`content_type_id`·그려진 모양)는 선택 필드 하나로 묶는다. 이 값이 없으면 b2의 그리기가 트래커와 링크를 그리지 않는다(확정 설계 8절, 티켓 20260930_1645와 이어짐).
- `resource` 값: `mission`·`drop`·`recipe`·`badge`·`article`·`ranking`·`collection`·`auto`. 템플릿 대응은 `mission_spotlight`→`mission`,
  `drop_alert`→`drop`, `badge_spotlight`→`badge`, `editorial_article`→`article`, `ranking_board`→`ranking`, `itembook_milestone`→`collection`,
  `progress_nudge`·`location_trend`→`auto`다. `recipe`는 템플릿이 아직 없다(`recipe_reveal`은 1500·1458 소관)
- `toCardView(card, options)`: 서버 조회 결과(`TodayCardWithHref`)를 표시 데이터로 바꾼다. 모양은 `resolveShape`로 정한다(미리보기는 늘 새 모양으로 그리므로).
- `buildFacts(resource, values, now)`: 자원별 필수 정보(확정 설계 2절)를 글자 줄 최대 2개로 만든다. 값이 없는 줄은 생략한다.
  - 미션: 「기간 10월 12일~11월 8일」(종료가 없으면 「기간 상시」), 「보상 300 포인트 · 배지 1개」(포인트·배지 중 있는 것만)
  - 드랍: 장소(`region_label`). 시각은 값이 없어 생략한다(O6 1457)
  - 컬렉션: 이름, 「아이템 N개」
  - 기사: 게재일(`starts_at`)은 `publishedAt`으로 따로 둔다(칩 줄 끝에 그린다)
  - JAM! 배지: 이름(희귀도는 색 칩이라 글자 줄에 넣지 않는다, 확정 설계 3절)
  - 자동 카드: 미션을 가리키면 그 미션의 기간
  - 랭킹: 없음
  - 남은 시간: 자원의 종료 시각이 7일 이내면 「N일 남음」, 24시간 이내면 「N시간 남음」을 기간 줄 대신 쓴다(카드 `ends_at`은 쓰지 않는다,
    초·분 단위와 카운트다운은 쓰지 않는다). 날짜·시간은 KST 기준이다
- 문구는 `ko.ts`의 `todayCard` 네임스페이스에 둔다. UX Writing 가이드(`docs/specs/UX_WRITING_GUIDELINE.md`)의 고정 용어(포인트·배지·드랍)와 해요체 규칙을 따른다.

### 3. 조회 (`cards.ts`)

- `getTodayCards`가 표시 데이터에 필요한 값을 함께 싣는다: 미션 카드(`mission_id`)의 기간(`starts_at`·`ends_at`)·보상(`reward_points`·`reward_badge_ids`)·`image_url`,
  컬렉션 카드(`item_book_id`)의 이름과 아이템 수. 같은 자원을 여러 번 조회하지 않게 한 번에 모아 읽는다(`filterMissionSpotlightCards`가 이미 미션 행을 읽는 경로를 재사용할 수 있다).
- 이 조각은 화면을 바꾸지 않으므로, 실린 값은 아직 아무도 그리지 않는다. 기존 반환 필드는 바꾸지 않는다.

### 4. 문서

- 홈피드 PRD에 「카드 모양 판정」 짧은 절을 더한다: 모양 상수(`shape.ts`), `resolveShape`의 판정 순서, 전환 상수, 표시 데이터의 뜻. 대응표 전체는 1453 확정
  설계 6절이 b7까지 정본이므로 PRD에는 표를 옮기지 않고 그 위치만 가리킨다(같은 사실을 두 곳에 두지 않는다). b7에서 표를 PRD 생성 구간으로 옮긴다.

## 완료 조건

- `resolveShape`가 옛 값 6종과 예외(미션 소개 → `square`, 커버 없는 큰 썸네일 → `square`, 커버 없는 배너 → `brief`, 기사 → `hero`)를 대응표대로
  돌려준다. `shape`가 저장된 카드는 그 값을 쓴다(단위 테스트).
- `LEGACY_SHAPE_CUTOVER = false`에서 `shape`가 없는 옛 카드의 그려질 모양은 `null`이고, `shape`가 있는 카드는 그 값이다(단위 테스트).
- 이미지에 제목 있음 판정이 결정 6·12대로 동작한다(저장값 우선, 옛 미션 소개 카드는 커버 = 미션 이미지일 때만 `true`, 단위 테스트).
- `toCardView`가 카드 ID·활성 여부·노출 기간·정렬 순서 없이 표시 데이터를 만들 수 있고, 계측 정보가 선택 필드다(타입·테스트).
- `buildFacts`가 자원별 필수 정보를 최대 2줄로 만들고, 값이 없는 줄은 생략하며, 남은 시간 규칙(7일·24시간 경계)을 지킨다(경계 테스트, KST).
- `getTodayCards`의 기존 반환 필드와 홈 화면이 바뀌지 않는다(기존 테스트 통과). 자원 값 조회가 카드 수만큼 반복되지 않는다.
- 홈피드 PRD에 모양 판정 절이 있고 `node scripts/gen-home-feed-doc.mjs --check`와 PRD 동기화 검사가 통과한다.
- `scripts/verify.sh`가 통과한다.

- 아현 가정(확신도 보통, 사용자에게 보이고 머지 승인): (1) 남은 시간은 24시간 이내 올림(최소 1시간), 7일 이내 내림(최소 1일). (2) 드랍 줄은 「장소 {region_label}」. (3) 컬렉션 아이템 수는 컬렉션 화면과 같은 기준(`computeBookCompletion` 분모), 0개면 생략. (4) 저장된 shape가 기사 hero 고정보다 먼저. (5) 커버도 배지 그림도 없는 large_thumbnail은 hero, `resolved_badges`가 없는 행은 `badge_ids`가 있으면 승격으로 본다. (6) 표시 데이터에 `label`·`regionLabel`·`rarity`·`imageDimmed`·`ranking`·타일 `rarity`/`earned` 선택 필드 추가. (7) 계측 정보는 기본 꺼짐.
