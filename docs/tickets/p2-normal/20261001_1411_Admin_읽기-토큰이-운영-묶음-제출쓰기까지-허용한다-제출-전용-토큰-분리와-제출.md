# [Admin] 읽기 토큰이 운영 묶음 제출(쓰기)까지 허용한다: 제출 전용 토큰 분리와 제출자 고정

> `/jam-ship` 2026-10-01 병렬 점검(민지 모드 ②) 범위 밖 발견물. 점검 범위 `efd7be8d..946ebad7`(origin/main → origin/staging).

## 핵심 요약

- 요구사항: 읽기 토큰 `ADMIN_API_READ_TOKEN`이 `POST /api/admin/ops-inbox`(운영 묶음 제출·`#jam-report` 게시) 쓰기까지 허용한다. 토큰 이름은 여전히 READ이고, 결정 기록의 `actor`(`token:<author>`)는 제출자가 보낸 값이라 에이전트 이름을 사칭할 수 있다. 메서드·경로 정확 일치, 라우트 재검사, 소스 계약 테스트, 사람 승인 단계는 이미 있다. [보안/주의]
- 구현 계획: 제출 전용 토큰을 따로 두거나(읽기 토큰은 GET 전용으로 되돌림) 토큰별로 허용 제출자를 고정하는 안을 비교해 정한다. 환경변수를 바꾸면 루틴 저장 프롬프트·`contract.json`도 함께 고친다.
- 관련 파일: `jam-web/src/lib/admin/auth.ts:114`(토큰 쓰기 예외), `jam-web/src/app/api/admin/ops-inbox/route.ts:112`(actor 기록), `docs/service/prd/ops-tool/PRD.md`

## 완료 조건

- 읽기 토큰으로 제출 POST가 거절된다(테스트), 또는 결정한 대안의 권한 경계가 테스트로 고정된다.
- 결정 기록의 제출자를 요청 본문이 아니라 서버가 정한다.

## 완료 기록

### 구현 내용 요약
운영 묶음 제출(POST /api/admin/ops-inbox)을 토큰으로 할 때 결정 기록의 행위자(actor)를 요청 본문의 author로 만든 `token:<author>`가 아니라 서버 고정 값 `OPS_TOKEN_ACTOR = "token:"`으로 바꿨다. 에이전트 이름을 사칭할 수 없다. 관리자 로그인 제출은 관리자 ID 그대로다. 화면의 `classifyActor`는 이름이 빈 `token:`을 «에이전트가 …»로 그리므로 화면 코드 변경은 없고 이전 기록(`token:<이름>`)도 그대로 읽힌다. 사용자가 2026-11-09 질문 팝업에서 새 환경변수(제출 전용 토큰) 대신 «제출자를 서버가 고정»하는 안을 골랐다.
