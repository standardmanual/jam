# [Service] 서버 페이지의 공개 판정 배선(컬렉션 상세·믹스 목록·배지 화면)을 테스트로 지킨다

> `/jam-ship` 2026-10-01 병렬 점검(민지 모드 ③) 범위 밖 발견물. 점검 범위 `efd7be8d..946ebad7`(origin/main → origin/staging).

## 핵심 요약

- 요구사항: `/collections/[id]`의 공개 전 컬렉션 `notFound()`, `/combine`의 `filterReleasedRecipes`, `/badges`·`/badges/[id]`의 공개 전 컬렉션 제외는 서버 컴포넌트라 테스트가 없다. 순수 판정 함수만 테스트가 있어 배선 줄이 지워져도 CI가 통과한다. 믹스는 `combineRecipeAttempt`가 한 번 더 막지만 컬렉션 상세는 지키는 장치가 없다. [정확성/주의]
- 구현 계획: 서버 컴포넌트의 데이터 조회 부분을 테스트 가능한 함수로 빼거나 소스 계약 테스트로 배선을 고정하는 방식 중 하나를 고른다.
- 관련 파일: `jam-web/src/app/(main)/collections/[id]/page.tsx:98`, `jam-web/src/app/(main)/combine/page.tsx:48`, `jam-web/src/app/(main)/badges/page.tsx:121`, `jam-web/src/app/(main)/badges/[id]/page.tsx:242`, `jam-web/src/lib/itembook/visibility.ts`
- 추가 범위(티켓 20261001_1159 게이트 범위 밖 발견물, 2026-10-01): `/combine` 서버 페이지에 운영자 분기가 생겼다. `isAdmin ? recipes : filterReleasedRecipes(recipes)`(48줄)와
  `releaseAt` 산출(`isRecipeReleased(r)`가 거짓인 행에만 `valid_from`, 128줄 근처 `publicRecipes` 변환)도 같은 방식으로 지킨다. [정확성/참고]
  같은 파일의 `publicRecipeRows`·`publicRecipeIds`(48~49줄)는 운영자에게 공개 전 레시피까지 담아 이름과 내용이 어긋난다(주석으로만 설명). 조회 부분을 함수로 뺄 때
  `visibleRecipeRows`처럼 이름을 바로잡는다. [정확성/참고]

## 완료 조건

- 네 곳의 공개 판정 호출이 지워지면 실패하는 테스트가 있다.
- `/combine`의 운영자 분기(운영자면 공개 전 레시피 포함, 일반 유저는 제외)와 `releaseAt`(공개 전 행에만)이 바뀌면 실패하는 테스트가 있다.
- `/combine` 서버 페이지의 레시피 목록 변수 이름이 운영자 분기를 포함한 내용과 맞는다.
