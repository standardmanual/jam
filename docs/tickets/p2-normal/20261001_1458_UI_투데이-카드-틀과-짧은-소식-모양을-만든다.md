# [UI] 투데이 카드 틀과 짧은 소식(`brief`) 모양을 만든다 (1453-b2)

> 상위: 20260930_1453 「확정 설계」 1·3·4·8절, 11절 조각 b2 · 결정 13·15·17·21 · 운영 홈 화면은 바뀌지 않는다(아래 「배경」)

## 핵심 요약

- 요구사항: 새 카드 모양을 그릴 공용 틀(`TodayCard`·`CardFrame`)과 첫 모양 `brief`(짧은 소식)를 `jam-web/src/components/today/`(신규)에 만든다.
  `TodayCardStack`은 한 곳에서 분기해 **모양이 `brief`로 저장된 카드만** 새 틀로 그리고, 옛 카드(`shape` NULL)와 아직 그리지 않는 모양
  (`hero`·`poster`·`square`·`list`)은 지금 렌더러가 그대로 그린다(1453 결정 17). 앞 조각들이 b2에 넘긴 메모(눌림 클래스, 칩, 컬렉션 공개 필터,
  GA `shape`)도 함께 처리한다.
- 구현 계획: 아래 「구현 계획」의 파일 단위 표다. 크기 기준 면제는 1453 결정 20(사용자 승인, 2026-10-01)에 따른다.
- 관련 파일:
  - 신규 `jam-web/src/components/today/`(`TodayCard.tsx`·`CardFrame.tsx`·`BriefCard.tsx`·Story·테스트)
  - `jam-web/src/app/(main)/TodayCardStack.tsx`: 45~51줄 `TemplateChip`, 눌림 문자열 6곳(89·125·170·201·227·297줄), 368~385줄 카드 목록 분기
  - `jam-web/src/app/(main)/TodayCardTracker.tsx`: 21~38줄 props, 68줄 GA `today_card_click`
  - `jam-web/src/app/(main)/TodayStatusStrip.tsx`: 18~19줄 `CELL_CLASS`
  - `jam-web/src/lib/today/cardView.ts`: 180~184줄 `CardViewTracking`, 217~219줄 `BriefCardView`, 300~302줄 `tracking` 채우기
  - `jam-web/src/lib/today/shape.ts`: 94~97줄 `drawnShape`(읽기만 한다. 시그니처·판정 순서를 바꾸지 않는다, 1155가 쓴다)
  - `jam-web/src/lib/today/cards.ts`: 267줄~ `fetchCollectionsById`(272줄 `item_books` 조회), 필터는 `jam-web/src/lib/itembook/visibility.ts` 55줄 `applyLaunchedItemBookFilter`
  - MODULAR(읽기만): `design-system/components/cards/LabelChip`, `design-system/components/cards/RarityBadge`, `src/components/transitions.css` 604~621줄 `.jam-press`
  - 테스트: `jam-web/src/app/(main)/TodayCardStack.test.tsx`·`TodayCardStack.preview.test.tsx`·`TodayStatusStrip.test.tsx`, `jam-web/src/lib/today/__tests__/cardView.test.ts`·`cards-resources.test.ts`
  - 문서: `docs/specs/prd/home-feed/PRD.md` 머리말 `code:`, §6 「카드 모양 판정」(235줄~), §9 계측(304줄~)

## 배경 / 문제 정의

- 2026-10-01 카리나 조회(읽기 전용): `today_cards` 71장 모두 `shape`가 NULL이다(노출 중 2장, 게재 예정을 합쳐 13장). 모양을 저장하는 경로(운영툴 b6,
  카드 생성 1500)도 아직 없다. 그래서 이 조각이 운영에 나가도 홈 화면은 그대로이고, 새 `brief`는 Storybook에서 처음 본다(1453 결정 21,
  사용자 확인 시점 「b2 뒤 Storybook `brief`」).
- 1357(b1)이 표시 데이터(`toCardView`)와 필수 정보·남은 시간 문구를, 1431(c2)이 기록 모양(`card_shape`)을 만들었다. 이 조각이 표시 데이터를
  처음 화면에 그린다. 그래서 1357의 문구가 처음 사용자에게 보이고, 한국어 자연스러움 판정을 이 조각에서 받는다.
- 1645가 `TodayCardStack`에 `preview`(계측·이동 끄기)를 더했다. 새 틀은 「표시 데이터에 계측 정보(`tracking`)가 없으면 트래커와 링크를 그리지
  않는다」(확정 설계 8절)로 같은 일을 한다. `preview` prop 삭제는 b7이다.

## 채원 사전 판정 범위 (짧은 판정, 1453 확정 설계 11절)

- 확정 설계 1~4·8절은 사용자 승인을 마쳤다(결정 15). 모양 5개, 글자 배치, 상태 표, 눌림 토큰·`LabelChip`, focus-visible 윤곽선, 「5개 모양은
  서비스 전용」 판정은 다시 `needs_approval`로 올리지 않는다.
- 이번 판정은 승인 범위 안에서 아직 정하지 않은 b2 세부만 다룬다.
  1. `brief`의 64px 칸: 썸네일을 쓰는 경우(예: JAM! 배지 1개 카드의 배지 그림)와 자원 아이콘을 쓰는 경우의 규칙. 썸네일을 쓰면 `BriefCardView`에
     선택 필드(예: `thumbnailUrl`)를 더할지와, 미보유 배지 흑백·「유저 정보가 없는 미리보기는 컬러」 규칙(확정 설계 3절)을 썸네일에 어떻게 적용할지.
  2. 자원 → 아이콘 대응. `recipe`는 지금 아이콘 목록(`jam-web/src/components/ui/icons.tsx`)에서 고른다. 아이콘 모양으로만 구분하는 흑백 원칙을 지킨다.
  3. `brief`의 칩 줄 구성: 라벨 칩, 지역 핀, JAM! 배지 희귀도 칩(`RarityBadge size="md"`, Common은 칩 없음).
  4. `CardFrame`과 모양 컴포넌트의 경계: 카드 배경(`Card tone="inverse"`), 안쪽 여백, 최소 높이, 링크·트래커·눌림·포커스 윤곽선을 어느 쪽이 맡는지.
  5. Story 상태 행렬(아래 상세 요구사항 5의 최소 목록에 더할 것).
- 판정에서 새 토큰이나 새 MODULAR 컴포넌트가 필요해지면 그 항목만 `needs_approval`로 올린다.

## 상세 요구사항

### 1. 카드 틀 (`jam-web/src/components/today/`, 신규)

- `TodayCard`: 표시 데이터(`CardView`)를 받아 `shape`로 모양 컴포넌트를 고른다. 이 조각에서 그리는 모양은 `brief` 하나다. 새 틀이 그리는 모양 목록은
  상수 하나(예: `RENDERED_SHAPES`)로 두고, b3~b5가 이 목록에 모양을 더한다. 목록에 없는 모양을 받으면 아무것도 그리지 않는다(지금은 Story와
  1501에서만 생길 수 있다).
- `CardFrame`:
  - `view.tracking`이 있으면 `TodayCardTracker`로 감싸 노출·클릭을 기록한다. `view.tracking`과 `view.href`가 모두 있으면 `Link`로 감싼다.
  - 링크는 `display:block`이고 `.jam-press`(눌림)와 focus-visible 윤곽선(카드 바깥 2px, 오프셋 2px, 확정 설계 4절)을 가진다.
  - `tracking`이 없으면(미리보기) 트래커·링크·눌림이 모두 없다. 링크가 없는 카드에는 `.jam-press`를 붙이지 않는다.
- GA `today_card_click`의 `template_type`을 새 틀에서도 보내야 하므로, `CardViewTracking`에 템플릿 값을 더하고 `toCardView`가 채운다.

### 2. `brief` 모양 (확정 설계 1·3·4절 `brief` 열)

- 칩 줄이 첫 줄이다(라벨 6자·지역 핀 10자 이하). 제목 16px, 2줄에서 말줄임. 요약·설명문은 없다.
- 필수 정보는 14px, 아이콘 없이 글자로, 한 줄에 하나씩 최대 2줄이다. 자르지 않고 줄바꿈하며 2줄 한도를 넘지 않는다. 값이 없으면 그 줄만 생략한다.
- 끝 줄은 `›`(장식, `aria-hidden`). 64px 칸은 썸네일 또는 자원 아이콘이다(커버가 아니다). 카드 최소 높이는 88px다.
- 옅은 글자는 `/60` 이상이다(지금 옛 렌더러의 `/30`·`/40`을 쓰지 않는다).
- 표시 데이터 값만 읽는다. 카드 행·카드 ID·활성 여부·노출 기간 없이 그려져야 한다(1501이 승인 전 초안을 그린다).

### 3. `TodayCardStack` 분기 (한 곳)

- 카드마다 그려질 모양(`drawnShape`)이 새 틀이 그리는 모양이면 `toCardView(card, { tracking: !preview })`로 만든 표시 데이터를 `TodayCard`로 그리고,
  아니면 지금 렌더러 그대로 그린다. 화면이 그리는 모양은 기록 모양(1431 `events.ts`)과 같아야 한다.
- 허용하는 차이: b3~b5가 들어오기 전에 모양이 `hero`·`poster`·`square`·`list`로 저장된 카드가 생기면, 기록 모양은 저장된 모양이고 화면은 옛
  렌더러다. 지금 그런 카드는 0장이고 모양을 저장하는 경로가 없어 허용한다. 완료 기록에 남긴다.
- 옛 카드의 출력은 아래 4의 눌림 클래스·칩 교체를 빼고 지금과 같다.

### 4. 앞 조각 메모 처리

- 눌림: `TodayCardStack.tsx` 6곳과 `TodayStatusStrip.tsx` `CELL_CLASS`의 `active:scale-[0.98] transition-transform duration-100`을 `jam-press`로 바꾼다.
  지금 클래스가 붙은 자리에 그대로 바꾸고 적용 범위는 넓히지 않는다(시간 100→80ms, 동작 줄이기 설정에서 눌림 없음은 1453 혜린 검토 가정 A10으로 허용).
  옛 렌더러의 미리보기 경로에 남는 눌림은 옛 렌더러를 지우는 b7에서 함께 사라진다.
- 칩: `TemplateChip`(45~51줄)을 MODULAR `LabelChip`으로 바꾼다. 옛 카드의 칩 출력은 픽셀이 같다(b0 1204 근거).
- 컬렉션 공개 필터(1357 민지 발견): `fetchCollectionsById`의 `item_books` 조회에 `applyLaunchedItemBookFilter`를 적용해, 공개 전·비활성 컬렉션은
  `resolved_collection`이 null이 되게 한다(이름·아이템 수가 표시 데이터에 실리지 않는다). 기준 시각은 `getTodayCards`의 지금 시각을 쓴다.
- GA: `TodayCardTracker`에 `shape`를 받아 `today_card_click`에 `shape` 파라미터를 더한다. 새 틀은 `tracking`의 그려진 모양, 옛 렌더러는 `drawnShape`
  (지금은 null)를 넘긴다.
- 건드리지 않는 것: 라벨 매핑 중복(`cardView.ts` `LABEL_BY_TEMPLATE`과 `TodayCardStack.tsx` `templateLabel`)은 b7에서 정리한다. `shape.ts`는 고치지 않는다.

### 5. Story

- `jam-web/src/components/today/` 안에 서비스 Story(`.stories.tsx`)를 둔다. `jam-web/.storybook/main.ts`가 `../src/**/*.stories.*`를 이미 읽는다.
  서비스 Story는 이번이 처음이다.
- `brief` 최소 상태: 자원별(미션 필수 정보 2줄, 드랍 장소, 컬렉션 이름·아이템 수, JAM! 배지 희귀도 칩, 자동 카드), 필수 정보 0줄, 긴 제목(28자 초과),
  긴 필수 정보(15자 초과 줄바꿈), 계측 있음(링크·눌림·포커스)과 없음(미리보기), 360·430 폭.

### 6. 문서

- 홈피드 PRD: 머리말 `code:`에 `jam-web/src/components/today`를 더한다. §6 「카드 모양 판정」의 제목·본문을 「모양이 `brief`로 저장된 카드는 새 틀로
  그린다」에 맞추고, 새 틀의 계측 규칙(표시 데이터에 계측 정보가 없으면 트래커·링크를 그리지 않는다)과 컬렉션 공개 필터를 적는다. §9의 GA 파라미터에
  `shape`를 더한다. 생성 구간(`<!-- BEGIN generated: ... -->`)은 고치지 않는다(b7).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `shape = 'brief'`인 카드는 새 틀로 그려지고, `shape`가 NULL인 카드와 `brief` 외 모양이 저장된 카드는 옛 렌더러로 그려진다(`TodayCardStack` 렌더 테스트 3가지).
- 새 틀에서 `tracking`이 없는 표시 데이터는 출력에 링크(`<a`)·트래커·`jam-press`가 없다. `tracking`과 `href`가 있으면 링크가 블록 요소이고
  `jam-press`와 focus-visible 윤곽선 클래스를 가진다(테스트).
- `brief`가 위 상세 요구사항 2의 글자 크기·줄 수·옅은 글자 `/60` 이상·최소 높이 88px·끝 줄 `›`를 지키고, 필수 정보는 말줄임 없이 2줄 한도로 줄바꿈한다.
- `TodayCardStack`에 `preview`를 넘기면 `brief` 카드도 계측·이동이 없다(1645 회귀 테스트 통과, `brief` 경우 추가).
- GA `today_card_click`에 `shape`가 실린다(새 틀은 그려진 모양, 옛 카드는 null). 기존 `card_id`·`content_type_id`·`template_type`은 그대로다.
- `TodayCardStack.tsx`·`TodayStatusStrip.tsx`에 `active:scale-[0.98] transition-transform duration-100`이 남지 않는다. `TemplateChip`이 `LabelChip`으로 바뀌었다.
- `getTodayCards`가 공개 전·비활성 컬렉션의 `resolved_collection`을 null로 돌려준다(테스트).
- `components/today/`의 Story에 위 5의 상태가 있고 `scripts/verify.sh`(ds 검사 포함)가 통과한다.
- 홈피드 PRD가 갱신됐고 PRD 동기화 검사와 `node scripts/gen-home-feed-doc.mjs --check`가 통과한다.
- 사용자에게 보이는 문구(1357의 필수 정보·남은 시간 문구 포함)가 한국어 자연스러움 판정을 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤 push 전)
- 로컬 Storybook에서 `brief` Story를 360·430 폭으로 열어 스크린숏을 사용자에게 보이고 확인받는다(1453 사용자 확인 시점 「b2 뒤」).
