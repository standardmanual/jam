## 배경 / 문제 정의

- 2026-10-01 기준 `today_cards`의 `shape`는 71장 모두 NULL이다(1458 완료 기록). 그래서 `RENDERED_SHAPES`에 `hero`를 더해도 홈 화면은 그대로이고,
  새 `hero`는 Storybook에서 처음 본다. 사용자 확인 시점은 b4 뒤(이미지 모양 묶음)다(1453 11절).
- **기사 화면은 이 조각이 운영에 나가는 순간 바뀐다**(TopNav, 16:9, 링크 제거). 결정 2·10·14로 사용자가 승인한 변경이고, 조각 단독 배포 안전(결정 17)에
  어긋나지 않는다. 기사 화면은 `editorial_article` 카드만 연다.
- b2(1458)가 만든 칩 줄과 자원 아이콘 매핑은 `BriefCard.tsx` 안에 있다. `hero`가 두 번째 소비자라 이 조각에서 공용으로 뺀다(1453 11절 b3~b5 메모, 1458 민지 발견).
- 1248: 기사 화면 칩(`bg-surface-inverse text-text-inverse`, `leading-none` 없음)은 `LabelChip`의 네 번째 복제다. b3에서 기사 화면을 다시 그리므로 함께 판정한다.

## 채원 사전 판정 범위 (짧은 판정)

- 확정 설계 1~5·7·8절은 사용자 승인을 마쳤다(결정 2·6·10·13·14·15). 모양 5개, `hero` 글자 배치(3절 표의 `hero` 열), 상태 표, 이미지 규칙,
  기사 화면 TopNav 세부, `ArticleView` 분리, 「5개 모양은 서비스 전용」 판정은 다시 `needs_approval`로 올리지 않는다.
- 이번 판정은 승인 범위 안에서 아직 정하지 않은 b3 세부만 다룬다.
  1. **1248**: 기사 화면 칩을 `LabelChip`에 `tone="inverse"` 변형을 더해 합칠지, 지금 마크업을 유지할지. 변형을 더하면 MODULAR 변경이라 `needs_approval`로 올린다.
     유지로 판정하면 이유를 적는다(1248은 판정과 사용자 승인만 남기고 닫는다).
  2. `hero`의 이미지 칸이 비었을 때(주소 없음·로드 실패)의 자리 표시: 확정 설계 4절 「어두운 판 + 자원 아이콘 + 제목」의 토큰·배치. `SafeImage`가
     실패 때 칸(`containerClassName`) 없이 `fallback`만 그리므로, 자리 표시 자체가 16:9 칸을 가져야 한다. 로딩 중 판은 `--color-surface`다(4절).
  3. `hero` 칩 줄: 라벨 → 지역 핀 → 희귀도 칩 → (기사) 게재일. 게재일의 날짜 형식과 위치(줄 끝 정렬 여부), 328px에서 칩 줄이 넘칠 때 줄어드는 순서.
     공용 칩 줄 컴포넌트의 경계(어느 값을 받는지, 드랍의 핀 생략 규칙을 어디에 두는지).
  4. `hero` 본문: 안쪽 여백(옛 렌더러는 24px), 필수 정보 「14px 굵게」의 색, 끝 줄(「자세히 보기 →」·「기사 읽기 →」)을 `href`가 없을 때 그릴지,
     「이미지에 제목 있음」(`titleInImage`) 카드에서 제목을 스크린리더용으로 남기는 방법과 이미지 실패 때 제목을 보이는 위치.
  5. 기사 화면: 커버가 없을 때 16:9 칸을 유지할지(지금 PRD §8은 「커버 영역 없이 본문부터」), `ArticleView` 표시 데이터의 모양(제목·부제·커버·게재일·문단·CTA),
     운영툴 미리보기(1501)에서 CTA를 링크 없이 그리는 방법. 미리보기용 정적 바는 1501·b6 범위라 이번에는 만들지 않는다.
  6. Story 상태 행렬(아래 상세 요구사항 5의 최소 목록에 더할 것).
- 판정에서 새 토큰이나 새 MODULAR 컴포넌트·변형이 필요해지면 그 항목만 `needs_approval`로 올린다.

## 상세 요구사항

### 1. 공용으로 빼기 (`jam-web/src/components/today/`)

- 자원 → 아이콘 매핑(`BriefCard.tsx` 35~44줄)을 `resourceIcon.ts`(가칭)로 옮기고 `BriefCard`와 `HeroCard`가 함께 쓴다. `auto`의 지역 핀 임시 판별(57줄)은
  `BriefCard`에만 있는 규칙이면 그대로 두고, 공용으로 옮기면 주석의 b7 메모를 유지한다.
- 칩 줄(`BriefCard.tsx` 91~105줄)을 공용 컴포넌트(가칭 `CardChipRow`)로 빼고 `BriefCard`가 그것을 쓴다. **`brief`의 출력은 바뀌지 않는다**(기존 `BriefCard` 테스트·Story가 그대로 통과).

### 2. `hero` 모양 (확정 설계 1·3·4절 `hero` 열)

- 이미지가 위(16:9, `ImageCardView.imageUrl`), 흰 본문이 아래다. `imageDimmed`면 흑백이다.
- 본문: 칩 줄(첫 줄) → 제목 24px 2줄 말줄임 → 요약(`subtitle`) 16px `/60` 2줄 → 필수 정보 14px 굵게, 줄마다 하나, 최대 2줄, 자르지 않고 줄바꿈 →
  설명문(`description`) 14px `/60` 2줄 → 끝 줄 「자세히 보기 →」(기사는 「기사 읽기 →」) 12px `/60`. 기사면 칩 줄 끝에 게재일(`publishedAt`).
- 옅은 글자는 `/60` 이상이다(옛 렌더러 끝 줄의 `/40`을 쓰지 않는다).
- `titleInImage`면 화면 글자에서 제목·요약을 빼고 필수 정보를 놓는다. 제목은 스크린리더가 읽을 수 있게 남긴다. 이미지 alt는 제목이 화면 글자로 보이면 빈 값,
  이미지에만 있으면 제목이다(3절). 이미지 로드에 실패하면 제목을 보인다.
- 이미지 칸 상태: 로딩 중에는 `--color-surface` 단색 판으로 높이가 고정되고(스켈레톤·모션 없음), 주소가 없거나 실패하면 같은 16:9 칸에 어두운 판 + 자원 아이콘 + 제목이다(4절).
- 표시 데이터 값만 읽는다. 카드 행·카드 ID·활성 여부·노출 기간 없이 그려져야 한다(1501). 링크·트래커·눌림·포커스 윤곽선은 `CardFrame`이 맡는다.
- `TodayCard`의 `RENDERED_SHAPES`에 `hero`를 더하고 `switch`에 분기를 더한다. `TodayCardStack`은 고치지 않는다(분기는 이미 `RENDERED_SHAPES`를 본다).

### 3. 기사 화면 (`/today/[cardId]`, 확정 설계 7절)

- TopNav: 제목 「투데이」(`d.today.cardStackTitle`), 뒤로 `/`(`backHref="/"`), `headerStyle` 없음. 다른 상세 화면처럼 동기화 버튼·알림 종·아바타가 붙는다.
- 머리 이미지는 TopNav 바로 아래 16:9(`aspect-video`), `priority`. 「← 오늘로」 링크를 빼고 본문 위 간격을 `pt-24`(`--spacing-24`) 하나로 통일한다.
- `d.todayCard.backToToday`는 사용처가 없어지므로 `ko.ts`에서 지운다.
- 본문(머리 이미지·칩·제목·부제·게재일·문단·CTA)을 표시 데이터만 받는 `ArticleView`로 뺀다. TopNav는 `ArticleView` 밖(페이지)에 둔다.
  표시 데이터 변환은 순수 함수로 `jam-web/src/lib/today/`에 둔다(서버 조회와 1501 미리보기가 같은 함수를 쓴다, 확정 설계 8절의 원칙).
- 기사 화면 칩은 채원 판정(1248)에 따른다. 계측은 지금처럼 없다(PRD §8).
- 404 조건(`getPublishedArticleCard`가 null)과 본문 문단 규칙(빈 줄로 나누고 마크다운을 렌더하지 않음), CTA 우선순위·라벨은 바꾸지 않는다.

### 4. 1248 처리

- 채원이 변형 추가로 판정하고 사용자가 승인하면: `LabelChip`에 `tone="inverse"`를 더하고(`.d.ts`·Story 포함, 기존 출력은 픽셀 동일), 기사 화면 칩이 그것을 쓴다.
  `npm run ds:check`가 통과해야 한다.
- 현행 유지로 판정하면 MODULAR를 고치지 않는다. 판정과 이유는 카리나가 1248에 적고 닫는다.

### 5. Story와 테스트

- Story(같은 폴더 `.stories.tsx`): `hero` 최소 상태 — 자원별(기사 게재일·「기사 읽기 →」, 미션, 컬렉션, 배지 그림 승격·흑백), 필수 정보 0·2줄, 요약·설명문 있음/없음,
  `titleInImage`, 이미지 없음, 이미지 로드 실패, 긴 제목(22자 초과), 긴 필수 정보(22자 초과 줄바꿈), 계측 있음/없음(미리보기), 360·430 폭.
  `ArticleView`: 커버·CTA 있음/없음, 본문 없음, 긴 제목, 360·430 폭.
- 테스트: `RENDERED_SHAPES`가 `['brief', 'hero']`, `hero`가 새 틀로 그려지는 `TodayCardStack` 분기(옛 카드·`poster`·`square`·`list`는 옛 렌더러), `HeroCard` 렌더
  (글자 배치·`titleInImage`·이미지 없음 자리 표시·alt 규칙), `ArticleView`(문단 나누기·CTA 없음·커버 없음), 표시 데이터 변환 함수.
- `cardView.test.ts`를 고치게 되면 492줄 테스트 이름 「드랍 카드: 지역 줄과 지역 핀」을 「드랍 카드: 필수 정보 지역 줄과 칩 줄 지역 핀」처럼 다듬는다(1716 민지 발견).

### 6. 문서

- 홈피드 PRD §6 「카드 모양 판정」: 제목·본문을 「모양이 `brief`·`hero`로 저장된 카드는 새 틀로 그린다」에 맞추고, 허용하는 차이를 `poster`·`square`·`list`로 줄인다.
  `hero`의 이미지 칸 상태(로딩 판·자리 표시)를 적는다.

- 생성 구간(`<!-- BEGIN generated: ... -->`)은 고치지 않는다(b7).

## 완료 조건
