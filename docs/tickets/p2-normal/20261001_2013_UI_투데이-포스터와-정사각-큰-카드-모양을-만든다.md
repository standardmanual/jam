## 배경 / 문제 정의

- `today_cards`의 `shape`는 아직 모두 NULL이라(1458·1737 완료 기록) 이 조각이 운영에 나가도 홈 화면은 그대로다. 새 모양은 Storybook에서 처음 본다.
- **사용자 확인 시점이 이 조각 뒤다**(1453 11절 「b4 뒤(이미지 모양)」). `hero`·`poster`·`square` 세 모양을 Storybook으로 함께 보인다. b3에서 넘어온 확인 항목: 1:1 배지 그림이 `hero`에서 위아래가 크게 잘리는 것(`HeroCard.stories.tsx` 「배지 그림 승격」).
- `square`는 미션 소개 카드와 커버 없는 JAM! 배지 카드가 쓴다(결정 7·15, 확정 설계 6절의 옛 → 새 대응). 옛 미션 소개 카드는 커버가 연결 미션 이미지와 같으면 「이미지에 제목 있음」으로 본다(결정 12, `resolveTitleInImage`).
- 1737 채원 판정: `CardChipRow`는 흰 면 전용이라 `poster`의 어두운 막 위 칩 줄은 그대로 쓰지 말고 tone을 따로 판정한다(`LabelChip tone="inverse"`를 쓸 수 있다).

## 채원 사전 판정 범위 (짧은 판정)

- 확정 설계 1~5절은 사용자 승인을 마쳤다(결정 6·7·8·13·15). 모양 5개, `poster`·`square` 글자 배치(3절 표의 두 열), 상태 표, 이미지 규칙, 「5개 모양은 서비스 전용」,
  빈 이미지 자리 표시(아이콘만, `titleInImage` 카드만 제목, 2026-10-01 1737 사용자 결정)는 다시 `needs_approval`로 올리지 않는다.
- 이번 판정은 승인 범위 안에서 아직 정하지 않은 b4 세부만 다룬다.
  1. `poster`의 어두운 막: 확정 설계 1절 「글자 블록 첫 줄에서도 진하기 60% 이상」을 지키는 막의 구성(단색·그라디언트, 높이, 시작 위치)과 쓰는 토큰.
     옛 `BannerCard`의 `from-black/70 via-black/30`은 첫 줄 자리에서 60%에 못 미칠 수 있다. 새 토큰이 필요하면 그 항목만 `needs_approval`로 올린다.
  2. `poster` 칩 줄: 어두운 막 위에서 라벨 칩·지역 핀·희귀도 칩·옅은 글자의 색조. `CardChipRow`에 tone을 더할지, 막 전용 칩 줄을 둘지.
  3. `poster` 상태: 이미지가 없거나 로드 실패할 때(카드 전체가 이미지라 자리 표시가 곧 카드 바탕이다), `titleInImage`일 때(제목 대신 필수 정보), `imageDimmed`일 때 막과 글자 처리.
     옛 `BannerCard`는 커버가 없으면 다른 모양으로 그렸지만 새 규칙은 모양을 바꾸지 않는다(결정 13).
  4. `square`: 이미지 칸(1:1, 자르지 않음, 이미지 위에 아무것도 얹지 않음)과 본문(칩 줄 → 제목 → 요약(선택) → 필수 정보, 설명문·끝 줄 없음)의 간격·여백,
     `hero`의 이미지 칸·자리 표시를 비율만 바꿔 공용으로 쓸지.
  5. 두 모양의 `alt` 규칙(확정 설계 3절)과 `sizes`, Story 상태 행렬(아래 상세 요구사항 4의 최소 목록에 더할 것).
- 판정에서 새 토큰이나 새 MODULAR 컴포넌트·변형이 필요해지면 그 항목만 `needs_approval`로 올린다.

## 상세 요구사항

### 1. `poster` (확정 설계 1·3·4절 `poster` 열)

- 4:5 이미지가 카드 전체이고 아래쪽 어두운 막 위에 흰 글자다. 막은 글자 블록 첫 줄에서도 진하기 60% 이상이다.
- 막 위: 칩 줄(맨 위) → 제목 24px 흰색 2줄 말줄임 → 필수 정보 14px 흰색, 줄마다 하나, 최대 2줄, 자르지 않고 줄바꿈. 요약·설명문·끝 줄은 없다.
- `titleInImage`면 제목을 빼고 필수 정보를 놓는다. 제목은 스크린리더가 읽을 수 있게 남긴다(b3와 같은 방식). 이미지 alt 규칙은 3절이다.
- 이미지가 없거나 로드에 실패해도 카드 높이(4:5)가 그대로이고 모양을 바꾸지 않는다. `imageDimmed`면 이미지만 흑백이다.

### 2. `square` (확정 설계 1·3·4절 `square` 열)

- 1:1 이미지를 자르지 않고 카드 폭 가득 보인다. 이미지 위에는 아무것도 얹지 않는다.
- 이미지 아래 흰 본문: 칩 줄(배지는 희귀도 색 칩 포함) → 제목 24px 2줄 말줄임 → 요약(선택) → 필수 정보 14px 굵게, 줄당 22자, 2줄. 설명문·끝 줄은 없다(결정 15).
- `titleInImage`(옛 미션 소개 카드 포함, 결정 12)면 제목·요약을 빼고 필수 정보를 놓는다. 이미지 상태(로딩 판·자리 표시·흑백)는 `hero`와 같다.

### 3. 새 틀 연결

- `TodayCard`의 `RENDERED_SHAPES`에 `poster`·`square`를 더하고 `switch`에 분기를 더한다. `TodayCardStack`은 고치지 않는다.
- 공용으로 빼는 것(채원 판정에 따라): 이미지 칸·자리 표시, 막 위 칩 줄. `hero`와 `brief`의 출력은 바뀌지 않는다(기존 테스트·Story 통과).

### 4. Story와 테스트

- Story(같은 폴더 `.stories.tsx`): 두 모양 각각 — 자원별(미션 `square`·커버 없는 배지 `square` 컬러·흑백, 컬렉션 `poster`, 레시피 공개 예고 `poster`), 필수 정보 0·1·2줄,
  `titleInImage`(이미지 있음·없음), 이미지 없음, 이미지 로드 실패, 긴 제목(`poster` 18자 초과·`square` 22자 초과), 긴 필수 정보, 계측 있음/없음(미리보기), 360·430 폭, 320 최악 조합.
  `poster`는 밝은 이미지 위에서 막 첫 줄의 대비를 볼 수 있는 Story를 하나 둔다.
- 사용자 확인용으로 세 이미지 모양(`hero`·`poster`·`square`)을 한 화면에 나란히 보이는 Story를 하나 둔다(같은 컨텐츠를 세 모양으로).
- 테스트: `RENDERED_SHAPES`가 `['brief', 'hero', 'poster', 'square']`, `TodayCardStack` 분기(`poster`·`square`는 새 틀, 옛 카드·`list`는 옛 렌더러, 163·186줄 기대값 갱신),
  `PosterCard`·`SquareCard` 렌더(글자 배치·`titleInImage`·자리 표시·alt), 공용으로 뺀 부분.

### 5. 문서

- 홈피드 PRD §6 「카드 모양 판정」: 제목·본문을 「`brief`·`hero`·`poster`·`square`로 저장된 카드는 새 틀로 그린다」에 맞추고, 허용하는 차이를 `list`로 줄인다.
  `poster`의 막 규칙과 이미지 칸 상태를 적는다. 생성 구간(`<!-- BEGIN generated: ... -->`)은 고치지 않는다(b7).

### 구현 범위 (게이트 판정 대상)
- `shape`가 `poster`·`square`인 카드는 새 틀로 그려지고, `shape`가 NULL인 카드와 `list`로 저장된 카드는 옛 렌더러로 그려진다(`TodayCardStack` 렌더 테스트).

새 틀에 이미지 모양 나머지 둘을 더했다(`RENDERED_SHAPES = ['brief', 'hero', 'poster', 'square']`). 세 이미지 모양이 공용 이미지 칸 `CardImageSlot`(ratio `video`·`poster`·`square`,

홈 화면 변화 없음(`shape` 저장 카드 0장).

채원 사전 판정(b4 세부, 승인 필요 없음): 서비스 전용 `CardImageSlot`·`PosterCard`·`SquareCard`, MODULAR 변경·새 토큰 없음(막은 기존 `--color-overlay`, 알파 0.6 이상을
