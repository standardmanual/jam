# [Admin] 시뮬레이터의 맥락 오버라이드가 KST가 아니라 UTC 시각으로 판정된다

> 출처: 20261001_1219 게이트(민지) 범위 밖 발견물 [정확성/주의], 아현 alert. 시뮬레이터가 경제 판단 근거가 되므로 어긋남을 없앤다.

## 핵심 요약

- 요구사항: 가상 활동 변환이 실제 Strava 활동과 같은 로컬 시각 필드를 채워, 시뮬레이터의 맥락 판정이 엔진과 같은 시각 기준으로 나오게 한다.
- 구현 계획: 착수할 때 관련 파일을 읽고 파일 단위로 적는다.
- 관련 파일: `jam-web/src/lib/admin/virtualActivity.ts` 59~68행(`buildVirtualActivities`), `jam-web/src/lib/drop-engine/context.ts` 57행(`matchContextTribes`의 시각 읽기), `jam-web/src/lib/drop-engine/preview.ts`

## 배경 / 문제 정의

시뮬레이터 가상 활동에 `startDateLocal`이 없어 `matchContextTribes`가 새벽(5~7시)·심야(23~4시) 맥락을 UTC 시각으로 판정한다. 실제 엔진은 로컬(KST) 시각을 쓰므로 시뮬레이터의 맥락 오버라이드가 입력 시각과 최대 9시간 어긋난다.

## 완료 조건

- 같은 입력 시각(KST 새벽 6시)으로 시뮬레이터와 엔진의 맥락 판정이 같다(테스트).
- 가상 활동의 로컬 시각 필드가 실제 활동과 같은 규칙(Z를 붙인 로컬 벽시계)으로 채워진다.

## 종료 기록 (전제 소멸)

2026-11-09 종료 점검에서 코드 변경 없이 닫았다. 이 티켓이 고치려던 «시뮬레이터의 맥락 오버라이드가 옛 맥락 엔진과 어긋남»은 전제가 사라졌다.
- 옛 드랍 엔진(`lib/drop-engine/context.ts`, `preview.ts`)은 티켓 20261022_0938(커밋 `1959cb8f2`)에서 삭제됐다.
- 새벽·밤 같은 시간대 판정은 `lib/badge-engine/timeBands.ts`가 활동 시작 시각(UTC `startDate`)을 KST로 바꿔 읽는다(사용자 결정 1). 시뮬레이터의 가상 활동(`lib/admin/virtualActivity.ts`의 `buildVirtualActivities`)도 같은 `startDate`를 채우므로 UTC로 어긋나는 경로가 없다.
- 티켓의 완료 조건 2(`startDateLocal`을 로컬 벽시계로 채움)는 `startDateLocal`을 시각 판정에 쓰지 않는다는 결정과 반대 방향이라 구현하지 않는다.
- 후속 후보: 시뮬레이터 가상 활동의 `startDate`가 `timeBandOfHour`의 KST 변환을 거쳐 기대한 구간에 드는지 확인하는 시험은 필요하면 새 티켓으로 만든다.
