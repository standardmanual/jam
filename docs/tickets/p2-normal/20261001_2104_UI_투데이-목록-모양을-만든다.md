# [UI] 투데이 카드의 목록(`list`) 모양을 만든다 (1453-b5)

> 상위: 20260930_1453 「확정 설계」 1·3·4절, 11절 조각 b5 · 결정 8·13·15·17 · 앞 조각: b4(20261001_2013)

## 핵심 요약

- 요구사항: 새 틀(`jam-web/src/components/today/`)에 마지막 모양 `list`를 더한다. 타일형(배지·재료 64px 가로 타일)과 랭킹 행형(행마다 프로필 링크, 카드 전체 링크 없음)
  두 갈래다. 이 조각이 끝나면 다섯 모양이 모두 새 틀에 있고, 운영툴 카드 미리보기(1501)를 시작할 수 있다.
- 구현 계획: 아래 「구현 계획」의 파일 단위 표다. 크기 기준 면제는 1453 결정 20(사용자 승인, 2026-10-01)에 따른다.

## 배경 / 문제 정의

- `today_cards`의 `shape`는 아직 모두 NULL이라 이 조각이 운영에 나가도 홈 화면은 그대로다. 새 모양은 Storybook에서 처음 본다. 1453 11절의 사용자 확인 시점은 b2·b4·b6·b7 뒤이고 b5 뒤는 없다.
- `list`를 쓰는 카드: JAM! 배지 여러 개(타일형), 레시피(재료 타일형, 재료 타일 값은 1500·1458에서 생긴다 — 이번에는 배지 타일만 실제 값이 있다), 랭킹보드(행형). 옛 `badge_gallery`는 타일형,
  `ranking_list`는 행형으로 간다(확정 설계 6절, 전환은 b7).
- 랭킹 행형은 다른 모양과 링크 구조가 다르다. 행이 각자 프로필 링크를 가지므로 카드 전체를 링크로 감싸면 앵커 안에 앵커가 생긴다. 지금 `CardFrame`은 모양을 모르고 `tracking`·`href`만 보고 카드 전체 링크를 건다.
- 내 순위 강조(`isMe`)는 유저 ID가 필요한데 `TodayCard`는 표시 데이터(`view`)만 받는다. 표시 데이터는 유저 정보 없이 그려져야 한다(확정 설계 8절, 미리보기).

## 채원 사전 판정 범위 (짧은 판정)

- 확정 설계 1~4절은 사용자 승인을 마쳤다(결정 8·13·15). 모양 5개, `list` 글자 배치(3절 표의 `list` 열: 칩 줄 → 제목 24px 22자 2줄 → 요약 16px `/60` 2줄 → 필수 정보 14px 줄당 22자 2줄 →
  설명문 14px `/60` 2줄 → 끝 줄 「전체 보기 →」), 「타일이 0개면 `brief`」, 「5개 모양은 서비스 전용」은 다시 `needs_approval`로 올리지 않는다.
- 이번 판정은 승인 범위 안에서 아직 정하지 않은 b5 세부만 다룬다.
  1. **본문 공용화**: `hero`·`square`·`list`의 칩 줄·제목 그룹·필수 정보를 공용 컴포넌트로 뺄지(b4 판정 「셋째 소비자가 생기면 판단」). 3절 표에서 필수 정보 굵기가 `hero`·`square`는
     굵게, `list`는 굵기 표기가 없다 — 같게 할지 판정한다. 공용으로 빼면 `hero`·`square` 출력은 바뀌지 않아야 한다.
  2. **타일형**: 64px 타일의 배치(가로 스크롤 또는 줄바꿈, 타일 수가 많을 때), 타일 아래 이름(줄 수·말줄임), 타일마다 희귀도를 보일지(`CardViewTile.rarity`, 옛 갤러리는 안 보였다),
     미보유 흑백·미리보기 컬러(결정 8), 그림이 없거나 로드 실패할 때의 대체 그림(자원 아이콘 `resourceIconOf` 또는 옛 `MedalIcon`), 타일 바탕(옛 `bg-black/[0.04]`).
  3. **랭킹 행형의 틀**: 카드 전체 링크를 걸지 않는 방법(`CardFrame`에 링크 범위를 더할지, 랭킹 행형만 틀을 따로 둘지), 제목 영역 링크(옛 규칙: 미션 대상 랭킹만 `href`, 눌림 `.jam-press`),
     카드 단위 클릭 미집계(`trackClick={false}`, 노출은 집계), `tracking`이 없으면(미리보기) 제목 링크·행 링크·트래커가 모두 없을 것.
  4. **내 순위 강조 값의 전달**: `TodayCard`에 선택 prop(`currentUserId`)을 더할지, 표시 데이터에 넣을지. 표시 데이터는 유저 정보 없이 그려져야 한다는 원칙(8절)과 맞는 쪽을 고른다.
  5. **끝 줄과 빈 상태**: 「전체 보기 →」를 타일형·행형 각각 언제 보일지(`href` 유무, 행형은 제목 링크와 겹치는지), 순위가 비었을 때(`ranking`이 null이거나 행 0개) 「아직 랭킹이 없어요」의 자리.
  6. Story 상태 행렬(아래 상세 요구사항 4의 최소 목록에 더할 것).
- 판정에서 새 토큰이나 새 MODULAR 컴포넌트·변형이 필요해지면 그 항목만 `needs_approval`로 올린다.

## 상세 요구사항

### 1. 타일형 (`resource`가 `ranking`이 아닌 `list`)

- 흰 카드에 왼쪽 정렬 본문: 칩 줄 → 제목 24px 2줄 말줄임 → 요약 16px `/60` 2줄 말줄임 → 필수 정보 14px(줄마다 하나, 최대 2줄, 자르지 않고 줄바꿈) → 설명문 14px `/60` 2줄 말줄임 →
  타일 줄 → 끝 줄 「전체 보기 →」. 값이 없는 그룹은 그 그룹만 사라진다. 옅은 글자는 `/60` 이상이다(`/40` 금지, 확정 설계 3절).
- 타일은 64px 칸에 그림, 아래에 이름이다. 미보유(`earned: false`)는 흑백, `earned`가 없으면(유저 정보가 없는 미리보기) 컬러다. 그림이 없거나 로드에 실패해도 칸 크기가 그대로다.
- 링크·계측·눌림·포커스 윤곽선은 카드 틀이 맡는다(`brief`·`hero`와 같다). `tracking`이 없으면 출력에 링크·트래커·`jam-press`가 없다.

### 2. 랭킹 행형 (`resource`가 `ranking`인 `list`)

- 칩 줄 → 제목 → 요약 → 설명문(타일형과 같은 본문) 아래에 순위 행(`RankingListRow` 재사용, 1·2·3위 포디엄 없음). 값 포맷은 `formatRankingMetricValue`다.
- 카드 전체 링크가 없다. 순위 행은 각자 프로필 링크다. 제목 영역은 미션 대상 랭킹(`ranking.metricType === 'mission_progress'`)이고 `href`와 `tracking`이 있을 때만 링크다.
- 노출은 기록하고 카드 단위 클릭은 기록하지 않는다(옛 `trackClick={false}`와 같다).
- `tracking`이 없으면(미리보기) 트래커·제목 링크·행 링크가 모두 없다(옛 `preview`처럼 `username`을 비워 행 링크를 없앤다).
- 홈에서 내 순위 행을 강조한다(`isMe`). 미리보기는 강조가 없다.
- 순위가 비면(`ranking`이 null이거나 행이 0개) 「아직 랭킹이 없어요」(`d.todayCard.rankingEmpty`)를 보인다. 행형은 타일 0개 규칙(`brief`로 바꿈)을 받지 않는다.

### 3. 새 틀 연결

- `TodayCard`의 `RENDERED_SHAPES`에 `list`를 더하고 `switch`에 분기를 더한다. 내 순위 강조 값이 필요하면 `TodayCardStack`이 375줄 새 틀 분기에서 넘긴다(채원 판정 4).
- `TodayCardStack`의 옛 렌더러는 고치지 않는다(b7). `shape`가 NULL인 옛 `badge_gallery`·`ranking_list` 카드는 지금처럼 옛 렌더러가 그린다.
- 공용으로 빼는 것(채원 판정 1·3에 따라): 본문 마크업, 카드 틀의 링크 범위. `brief`·`hero`·`poster`·`square`의 출력은 바뀌지 않는다(기존 테스트·Story 통과).

### 4. Story와 테스트

- Story(같은 폴더 `ListCard.stories.tsx`): 타일형 — 배지 타일 2·3·8개(넘칠 때), 보유·미보유 섞임, 미리보기(컬러), 그림 없음·로드 실패, 긴 이름, 필수 정보 0·1·2줄, 요약·설명문 있음/없음,
  계측 있음/없음. 행형 — 미션 대상(제목 링크)·유저 직접 지정(제목 링크 없음), 내 순위 강조, 순위 없음(null·0행), 미리보기. 공통 — 긴 제목(22자 초과), 360·430 폭, 320 최악 조합.
- 테스트: `RENDERED_SHAPES`가 `['brief', 'hero', 'poster', 'square', 'list']`(순서는 구현이 정하되 테스트와 주석을 맞춘다), `TodayCard.test.tsx` 119~123줄(이제 `list`를 그린다)을
  「모르는 모양은 그리지 않는다」로 바꾼다, `TodayCardStack` 분기(`list`로 저장된 카드는 새 틀, 타일 0개는 `brief`, 옛 카드는 옛 렌더러), `ListCard` 렌더(두 갈래 글자 배치·흑백·
  앵커 중첩 없음·제목 링크 조건·미리보기에서 링크 0개·순위 없음), 공용으로 뺀 부분, 카드 틀의 링크 범위.
- b4 채원 제안: 정사각 카드에 게재일이 보이지 않는다는 단언이 `SquareCard.test.tsx`(178줄 부근)에 있는지 확인하고, 없으면 더한다.
- `lib/today/__tests__/cardView.test.ts`를 고치게 되면 492줄 테스트 이름 「드랍 카드: 지역 줄과 지역 핀」을 「드랍 카드: 필수 정보 지역 줄과 칩 줄 지역 핀」처럼 다듬는다(1716 민지 발견). 고치지 않으면 손대지 않는다.

### 5. 문서

- 홈피드 PRD §6 「카드 모양 판정」: 소절 제목과 본문을 「다섯 모양 모두 새 틀로 그린다」에 맞추고, 「`list`로 저장된 카드는 옛 렌더러」 허용 차이를 지운다. `list` 모양(타일형·행형, 링크 구조,
  내 순위 강조, 빈 상태)을 `hero`·`square` 항목과 같은 형식으로 적는다. 공용화를 했으면 「b5 `list`가 셋째 소비자가 되면 정리한다」 문장을 결과에 맞게 고친다.
  생성 구간(`<!-- BEGIN generated: ... -->`)은 고치지 않는다(b7).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `shape`가 `list`인 카드는 새 틀로 그려지고(타일 0개 타일형은 `brief`), `shape`가 NULL인 옛 카드는 옛 렌더러로 그려진다(`TodayCardStack` 렌더 테스트).
- 타일형이 위 상세 요구사항 1을 지킨다: 미보유 타일은 흑백, `earned`가 없으면 컬러, 그림이 없거나 실패해도 칸 크기 유지(테스트).
- 랭킹 행형이 위 상세 요구사항 2를 지킨다: 출력에 앵커 안 앵커가 없고, 제목 링크는 미션 대상 랭킹에만 있으며, 카드 단위 클릭을 기록하지 않고, 순위가 비면 빈 문구가 보인다(테스트).
- 새 틀에서 `tracking`이 없는 표시 데이터는 두 갈래 모두 출력에 링크·트래커·`jam-press`가 없다(1458과 같은 규칙, 테스트).
