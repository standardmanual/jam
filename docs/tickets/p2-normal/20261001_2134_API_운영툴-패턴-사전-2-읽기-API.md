# [API] 운영툴 패턴 사전 ② 읽기 API

> 상위: 20260930_1503 ②(하위 표의 범위·완료 조건 그대로). 선행 ① 20261001_2056(마이그레이션 210·211 적용 완료).

## 핵심 요약

- 요구사항: 에이전트가 기존 자동화 읽기 토큰으로 패턴 사전을 읽는다. `GET /api/admin/ops-patterns`(목록)와 `GET /api/admin/ops-patterns/[patternNo]`(상세)를
  만든다. GET만 두고, 응답에 관리자 ID(`updated_by`·`confirmed_by`)를 싣지 않으며, 보관한 패턴은 목록에서 기본으로 뺀다(PRD §10.1).
- 구현 계획: 읽기 함수는 `lib/admin/opsPatterns/read.ts` 한 곳에 두고(1153의 패턴 거르기가 재사용한다) 라우트 두 개는 그 함수만 부른다. 인증은
  `ops-rules` 읽기 라우트와 같은 `requireAdminRead`다. 경로와 응답 형식은 PRD §11에 새 절로 적는다.
- 관련 파일: 아래 「구현 계획」 표(파일 단위). 선례는 `jam-web/src/app/api/admin/ops-rules/route.ts`(GET 전체, 39행)와 그 테스트
  `ops-rules/__tests__/route.test.ts`(인증·관리자 ID 비노출 검사), 상수는 `jam-web/src/lib/admin/opsPatterns/constants.ts`(상태 3값·번호 정규식),
  테이블은 `jam-web/supabase/migrations/210_ops_patterns.sql`(31~100행).

## 배경 / 문제 정의

①에서 패턴 사전 테이블 3개(`ops_patterns`·`ops_pattern_taste_signals`·`ops_pattern_common_rules`)를 만들었지만 읽는 경로가 없다. 에이전트(1504의 주간 루틴)는
DB에 직접 닿지 않고 `/api/admin/*` HTTP로만 읽으므로, 시드(③)·조합 뽑기(④)·제출 확인(E1)보다 먼저 읽기 API가 있어야 한다.

## 상세 요구사항

1. **목록 `GET /api/admin/ops-patterns`**
   - 쿼리 `includeArchived=true`일 때만 보관(`archived`) 패턴을 싣는다. 기본은 사용 중·쉬는 중만이다.
   - 응답: `{ patterns, commonRules, tasteSignals }`.
     - `patterns`: 패턴 번호의 숫자 순서(P09 < P10 < P100). 각 항목은 상세와 같은 모든 칸을 싣는다(에이전트가 한 번에 읽도록).
     - `commonRules`: 공통 규칙 전부, `ruleNo` 순서.
     - `tasteSignals`: 취향 신호 **전부**(공통 = `patternNo: null` 포함). 보관한 패턴의 취향 신호도 싣는다(PRD §10.1 「보관한 패턴의 취향 신호는 에이전트가 계속
       읽는다」). 순서는 공통 먼저, 그다음 패턴 번호 숫자 순서, 같은 패턴 안에서는 `sort_order`.
   - 테이블이 비어 있으면(③ 시드 전) 빈 목록을 돌려준다(오류 아님).
2. **상세 `GET /api/admin/ops-patterns/[patternNo]`**
   - `patternNo`가 `OPS_PATTERN_NO_PATTERN`에 맞지 않으면 400, 없으면 404. 보관한 패턴도 번호로 직접 읽으면 돌려준다(번호와 기록은 남는다).
   - 응답: `{ pattern, tasteSignals }`(그 패턴의 취향 신호만, `sort_order` 순서).
3. **응답 칸** (DB 스네이크 → 카멜. 아래에 없는 칸은 싣지 않는다)
   - 패턴: `patternNo`·`name`·`principle`·`userExperience`·`menus`·`samples`·`cardShapes`·`knobs`·`pitfalls`·`status`·`statusLabel`(상수의 한국어 이름표)·
     `pauseReason`·`origin`·`originItemId`·`createdAt`·`updatedAt`. JSONB(`samples`·`cardShapes`·`knobs`)는 그대로 넘긴다.
   - 취향 신호: `id`·`patternNo`·`name`·`reason`·`basis`(`estimate`·`confirmed`)·`evidenceDecisionId`·`confirmedAt`·`sortOrder`.
   - 공통 규칙: `ruleNo`·`title`·`body`·`updatedAt`.
   - **`updated_by`·`confirmed_by`는 select 목록에서부터 빼고 응답에도 없다**(ops-rules 조각 B 게이트 발견물과 같은 원칙: 읽지도 돌려주지도 않는다).
4. **인증**: 관리자 세션 또는 읽기 토큰(`requireAdminRead`, GET 전용). 쓰기 메서드는 두지 않는다. `proxy.ts`·`auth.ts`는 바꾸지 않는다(`GET /api/admin/*` 접두
   규칙으로 이미 열린다). `token-write-contract.test.ts`의 규칙(라우트가 토큰 헤더를 직접 다루지 않음)을 지킨다.
5. **오류**: DB 조회 실패는 500과 한국어 문구 하나(`read.ts`의 상수). 로그 머리표는 `[admin/ops-patterns]`.

## 범위 밖 (하지 않는다)

- `scripts/admin-api-read.mjs`의 경로 목록에 새 경로를 넣는 일: 1504(에이전트·루틴 재설정)가 읽기 API 경로를 넘겨받아 한다(1503 메모).
- `docs/specs/prd/04_PROJECT_SPEC.md` 91행의 읽기 라우트 나열: 이미 `ops-rules`가 빠져 있는 옛 나열이다. 이 티켓에서 항목을 덧붙이지 않는다(같은 사실을 두 곳에 적지 않는다).
- 쓰기(S5 만들기·고치기)는 ⑩a, 조합 뽑기는 ④, 시드는 ③.

## 완료 조건

- [ ] 읽기 토큰으로 목록·상세 GET이 200을 돌려주고, 토큰이 없거나 틀리면 거절된다(라우트 테스트).
- [ ] 목록 기본 응답에 보관 패턴이 없고 `includeArchived=true`면 있다. 취향 신호는 보관 패턴 것까지 실린다.
- [ ] 응답 어디에도 관리자 ID 칸이 없다(테스트가 본문 문자열로 확인).
- [ ] 형식이 틀린 번호는 400, 없는 번호는 404다.
- [ ] PRD §11.6이 실제 경로·응답 칸과 일치한다.
- [ ] `scripts/verify.sh` 통과.
