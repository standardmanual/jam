# [UI] 투데이 옛 카드를 새 모양으로 전환하고 옛 렌더러를 지운다 (1453-b7)

> 상위: 20260930_1453 「확정 설계」 6·10절, 11절 조각 b7 · 결정 5·16·17 · 앞 조각: b6(20261001_2208) · 흡수: 20260927_2235·20260927_2236

## 핵심 요약

  1453 메모의 b7 정리 항목(트래커 위치, 기록 모양 = 화면 모양, 계측 모듈의 화면 모듈 의존, 홈 밖 눌림 통일, 자동 카드 아이콘, 랭킹 판단 한 곳)을 모두 같이 한다(2026-10-01 사용자 결정).

## 배경 / 문제 정의

- b1~b6으로 다섯 모양·카드 틀·어드민 미리보기가 모두 새 틀에 있다. 지금 홈은 `shape`가 저장된 카드만 새 틀로 그리는데 그런 카드는 0장이라, 홈은 여전히 옛 렌더러다(결정 17: 전환은 b7의 상수 하나로).
- 지금 노출 중·게재 예정 카드 16장(`large_thumbnail`·`shortcut`)에는 이미지가 필요한 모양인데 이미지가 없는 카드와 `list` 후보가 없다(2026-10-01 조회). 전환해도 홈에 빈 판 카드는 생기지 않는다.
- 1431 민지 발견(1453 b7 메모): 전환을 켜면 옛 카드의 기록 모양을 `events.ts`가 배지 그림을 모른 채 `badge_ids`로 판정한다. 커버 없는 `large_thumbnail`에 배지는 있으나 그림이 없으면 화면은 `hero`, 기록은 `square`로 갈린다.
- 1458 민지 발견: `CardFrame`이 `@/app/(main)/TodayCardTracker`를 가져와 components → app 방향 의존이 생겼다. 옛 렌더러를 지우면 트래커의 사용처는 `CardFrame` 하나다.
- 2235(칩 공용화)는 b0 뒤 세 파일(`TodayStatusStrip`·`TodayCardStack`·`OnboardingQuestCard`)이 모두 `LabelChip`을 써서 옛 렌더러를 지우면 완료 조건을 채운다. 2236(눌림 동작 줄이기)은 홈 카드의 눌림이 `.jam-press`로 모였는지 확인하고 닫는다.

## 상세 요구사항

### 1. 전환

- `LEGACY_SHAPE_CUTOVER`를 `true`로 바꾼다. 상수와 `drawnShape`의 전환 분기는 남긴다(되돌릴 때 상수 하나로 끈다). 관련 테스트의 기대값(shape.test 164줄, events.test 146·310줄)을 전환 뒤로 바꾼다.
- `TodayCardStack`은 모든 카드를 `toCardView(card, { tracking: true })` → `TodayCard`(`currentUserId` 전달)로 그린다. `drawnShape`가 `null`을 줄 수 없게 되므로 옛 렌더러 분기를 지운다.
  섹션 머리(「투데이」·부제)와 카드 0장일 때 아무것도 그리지 않는 동작은 그대로다.

### 2. 옛 렌더러와 `preview` 삭제

- `TodayCardStack.tsx`의 옛 카드 6종·`CardBody`·`templateLabel`·`TemplateIcon`·`resolveCover`·설명문 헬퍼를 지운다. 카드 종류 라벨은 `cardView.ts`의 `LABEL_BY_TEMPLATE` 한 곳만 남는다.
- `preview` prop과 `TodayCardStack.preview.test.tsx`를 지운다(어드민은 b6부터 `TodayCardPreview`를 쓴다). 그 테스트의 의도(미리보기는 계측과 이동을 끈다)가 `TodayCardPreview.test.tsx`에 있는지 확인한다.
- 지운 뒤 사용처가 없어지는 import·사전 키(`d.todayCard.backToToday` 등)는 `grep`으로 확인해 함께 정리한다. 다른 화면이 쓰는 키는 남긴다.

### 3. 트래커 이동

- `TodayCardTracker.tsx`를 `jam-web/src/components/today/`로 옮기고 `CardFrame`·이벤트 API·`cardEventClient`의 참조를 고친다. GA `today_card_click` 연결 줄을 테스트로 고정한다.

### 4. 기록 모양 = 화면 모양

- 같은 카드 행이면 이벤트에 기록하는 모양(`events.ts` `resolveDrawnShape`)과 홈이 그리는 모양(`toCardView`)이 같아야 한다. 이벤트 경로에 DB 조회를 더하지 않는다.
- 권하는 방법: 두 쪽이 같은 입력으로 판정하게 한다(예: 배지 승격 판정을 `badge_ids` 유무로 통일해, 배지는 있으나 그림이 없으면 화면도 `square`로 가고 이미지 칸에 자리 표시를 그린다 — 결정 13).
  다른 방법을 고르면 이유를 적는다. 피할 수 없는 차이(예: `badge_ids`가 전부 삭제된 배지인 타일형)는 홈피드 PRD §9에 허용 차이로 적는다.
- 판정 규칙을 바꾸면 `resolveShape`를 쓰는 1502 신호 엔진(`jam-web/src/lib/admin/opsSignals/load.ts`)의 기대도 함께 확인한다(테스트가 있으면 통과, 결과가 바뀌면 완료 기록에 적는다).
- 같은 카드 입력 묶음(옛 레이아웃 6종 × 커버 있음/없음 × 배지 0/그림 있는 배지/그림 없는 배지)에 대해 두 경로의 모양이 같음을 단언하는 테스트를 둔다.

### 5. 계측 모듈의 화면 모듈 의존 정리

- `events.ts`가 `cardView.ts`를 값으로 가져오지 않게, 순수 판정 함수 `resourceOfTemplate`·`fallbackEmptyTileShape`를 `shape.ts`(또는 사전을 가져오지 않는 순수 모듈)로 옮긴다. `cardView.ts`는 그것을 가져다 쓴다(다시 내보내도 된다).
  이벤트 API 번들에 `@/lib/i18n` 사전이 실리지 않음을 확인할 수 있으면 확인한다(import 그래프 테스트 또는 기록).

### 6. 테스트

- `TodayCardStack.test.tsx`를 새 전제로 다시 쓴다: 옛 `layout_type` 카드(`shape` NULL)가 대응표대로 새 모양이 된다, 모든 카드가 트래커로 감싸진다, 랭킹 행형만 카드 전체 링크가 없다, `currentUserId`가 랭킹 강조로 간다,
  카드 0장이면 아무것도 그리지 않는다, 옛 렌더러의 클래스·마크업이 남지 않는다.

### 7. 문서

- 홈피드 PRD §6: 옛 레이아웃 표와 「커버 결정」·「눌림과 칩」 문단을 새 체계에 맞게 고친다(레이아웃은 `shape`가 없는 카드의 모양을 정하는 입력값일 뿐이다). 「카드 모양 판정」 소절의 「전환 상수가 꺼져 있다」 서술을 고친다.
- 생성 구간: `gen-home-feed-doc.mjs`에 새 생성 구간 두 개를 더한다 — 모양 목록(`CARD_SHAPES`, 이미지가 있는 모양 표시)과 옛 값 → 새 모양 대응표(`resolveShape`를 `fakeCard`로 돌려 만든 표, 예외 행 포함).
  기존 `layouts` 생성 구간(값·라벨)은 운영 입력값 목록으로 남긴다.
- 1453 「확정 설계」의 내용 중 PRD에 아직 없는 것을 §6에 옮긴다: 2절 자원별 기본 추천 모양·필수 정보 표, 3절 글자 배치 상한(b2~b5 실측값이 PRD에 있으면 그 값), 5절 이미지 규칙(16:9 1280×720·4:5 아래 45%·1:1 미션 이미지는 `hero`·`poster`에 넣지 않음).
  옮긴 뒤 1453 「확정 설계」 절을 줄이는 일은 카리나가 머지 뒤에 한다(아래 후속 범위).
- §9·§10: 전환 뒤 옛 카드의 `card_shape`가 NULL이 아니게 된다는 사실, 위 4의 허용 차이.

### 8. 홈 밖에 남은 눌림 문자열 통일 (사용자 결정으로 포함)

- `active:scale-[0.98]`(+ `transition-transform duration-100` 류)를 `.jam-press`(`--scale-press-card` 0.98, `--duration-micro` 80ms, 동작 줄이기 설정에서 없음)로 바꾼다. 대상(2026-10-01 `grep`):
  `jam-web/src/components/ui/ListRowCard.tsx`(미션 랭킹 화면과 투데이 순위 행 공용), `jam-web/src/components/ui/CollectionGridCard.tsx`, `jam-web/src/components/PoiCarouselModal.tsx`,
  `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.tsx`, `jam-web/src/app/(main)/[username]/collections/page.tsx`. 착수 때 다시 `grep`해 빠진 곳이 없게 한다(테스트 파일·`transitions.css` 정의는 제외).
- `.jam-press`가 붙는 요소는 `display:block`(또는 inline 아닌 상자)이어야 하고, 비활성(disabled) 요소에는 붙이지 않는다(b2 메모). 눌림이 100ms에서 80ms로 바뀌는 것은 허용한다(1453 가정 A10).
- 저장소에 `active:scale-[0.98]`이 정의(`transitions.css`)와 회귀 단언 테스트 밖에 남지 않음을 테스트나 검사로 확인한다.

### 9. 자동 카드 아이콘 (사용자 결정으로 포함)

- 지금 `resourceIconOf`(`components/today/resourceIcon.ts`)는 자원 `auto`(진행 알림 `progress_nudge`·지역 트렌드 `location_trend`)를 지역 값 유무로 가른다(지역 값이 있으면 핀). 진행 알림에 지역 값이 있으면 핀으로 그려진다.
- 표시 데이터에 템플릿 구분 값을 더하고(이름은 구현이 정한다, 계측 정보 `tracking`과 별개로 늘 실린다) 아이콘은 그 값으로 고른다: 지역 트렌드는 핀, 진행 알림은 모래시계(지역 값과 무관). 다른 자원의 아이콘은 그대로다.
- 미리보기(`TodayCardPreview`)와 홈이 같은 아이콘을 그린다. 자원 대응(`resourceOfTemplate`)·`CARD_RESOURCES`는 바꾸지 않는다(1502 신호가 쓴다).

### 10. 「랭킹이면 행형」 판단을 한 곳으로 (사용자 결정으로 포함)

- `TodayCard.tsx` 61줄 `link={view.resource !== 'ranking'}`(카드 전체 링크 끄기)와 `ListCard.tsx`의 갈래 선택이 같은 판정 함수 하나를 쓰게 한다. 한쪽만 바뀌어 앵커 중첩이나 이중 링크가 생기지 않음을 테스트로 고정한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `shape`가 NULL인 옛 카드가 홈에서 대응표대로 새 모양으로 그려지고, 옛 렌더러 코드와 `preview` prop이 저장소에 없다(테스트, `grep`).
- 모든 홈 카드가 트래커로 감싸지고, 랭킹 행형만 카드 전체 링크가 없다(테스트).
- 같은 카드 입력이면 기록 모양과 화면 모양이 같다(위 4의 입력 묶음 테스트). 허용 차이가 있으면 PRD §9에 적혀 있다.
- `TodayCardTracker`가 `components/today/`에 있고 GA 연결 줄이 테스트로 고정돼 있다. `events.ts`가 `cardView.ts`를 값으로 가져오지 않는다.
- 홈피드 PRD가 갱신됐고 새 생성 구간 두 개가 있으며 PRD 동기화 검사와 `node scripts/gen-home-feed-doc.mjs --check`가 통과한다.
- 홈 밖 눌림 문자열이 `.jam-press`로 바뀌었고 남은 곳이 없다(위 8). 자동 카드 아이콘이 템플릿 구분 값으로 정해진다(위 9, 테스트). 랭킹 행형 판정이 한 함수다(위 10, 테스트).
- `scripts/verify.sh`가 통과한다. 사용자에게 보이는 새 문구는 없다(있으면 한국어 자연스러움 판정을 받는다).

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- push 전: 로컬 `next dev`에서 홈을 실렌더로 확인한다(서버 렌더 오류 없음, 오늘 카드가 새 모양).
- push 뒤: staging 홈(`stage.j-a-m.app`)을 사용자에게 보여 확인받는다(1453 사용자 확인 시점 「b7 뒤」). 확인이 끝날 때까지 다른 티켓의 프로덕션 배포(`/jam-ship`)를 미룬다(결정 17).
