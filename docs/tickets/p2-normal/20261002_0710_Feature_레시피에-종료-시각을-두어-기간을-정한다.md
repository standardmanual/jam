# [Feature] 레시피에 종료 시각을 두어 기간을 정한다

> 영향 티켓(상위 1450 진행 규칙 4). 2026-10-02 사용자 결정 「레시피에도 기간 설정 필요」(1500 ① 20261001_2205 보고에 대한 답).
> 2026-10-01에 정한 「레시피에는 종료 시각이 없고 내릴 때는 삭제한다」(07 5.1, 티켓 20261001_1157·1158)를 뒤집는다.
> 1500 ⑧(레시피 핸들러)보다 먼저 한다.

## 핵심 요약

- 요구사항: 레시피에 공개 시각(`valid_from`)에 더해 종료 시각(`valid_until`, 선택)을 둔다. 종료 시각이 지난 레시피는 유저의 믹스 화면과 믹스 시도에서 빠진다(보이는 방식은
  아래 「확인할 것」). 비어 있으면 지금처럼 상시다. 어드민 레시피 폼에서 정하고, 운영툴의 레시피 항목은 `ends_at`을 받아 다른 자원처럼 종료된다.
- 구현 계획: 마이그레이션으로 칼럼을 더한 뒤(확장, 사용자 승인 뒤 메인 세션 실행) 공개 판정 한 곳(`visibility.ts`)에 종료 판정을 넣고, 입력 정규화·어드민 폼·목록·내보내기를 잇는다.
  착수 때 파일 단위 계획을 쓴다. 예상 약 16파일·600줄(테스트 포함)이다.
- 관련 파일:
  - 새 마이그레이션 `jam-web/supabase/migrations/2xx_combination_recipes_valid_until.sql`: `valid_until TIMESTAMPTZ NULL`, CHECK(둘 다 있으면 `valid_from < valid_until`), 되돌림 SQL.
    번호는 착수 때 원격 staging 기준으로 잡는다(212는 1503 ③ 시드가 쓸 예정).
  - `jam-web/src/lib/combine/visibility.ts` 전체(60줄): `RecipeReleaseInput`에 `valid_until`, `isRecipeReleased`에 종료 판정, `recipeReleaseState`에 `ended`, `filterReleasedRecipes`.

## 배경 / 문제 정의

1500 ①(20261001_2205)을 정리하며 레시피 운영 항목이 공개 뒤 「게재중」에서 끝나지 않는 문제가 나왔다. 레시피에 종료 시각이 없어 툴이 내릴 수 없고, 레시피를 담은 묶음이
「게재」 단계에 영원히 남는다. 사용자가 「레시피에도 기간 설정 필요」로 정했다. 기간 한정 레시피(시즌 레시피 등)를 운영할 수 있게 되고, 운영툴의 레시피 항목도 다른 자원처럼
종료 시각에 「종료」로 닫히고 「지금 종료」를 쓸 수 있다.

## 가정 (카리나 초안, 확인 전)

- G1 종료 시각은 선택이다. 비어 있으면 상시이고, 기존 레시피는 모두 비어 있어 동작이 바뀌지 않는다(백필 없음).
- G2 경계: 공개 시각 ≤ 지금 < 종료 시각일 때 공개다(종료 시각 그 순간부터 끝). 해석할 수 없는 값은 숨김(지금 공개 판정과 같은 fail-closed).
- G3 종료된 레시피로 이미 받은 아이템·포인트·배지는 그대로다. 「가장 먼저 성공」 배지 등 그 레시피를 가리키는 배지는 건드리지 않는다.
- G4 삭제는 그대로 남는다(삭제 가드 포함). 종료는 삭제와 별개다.
- G5 운영툴: 레시피 항목의 `ends_at`을 `valid_until`로 받는다(지금 PRD §8.4는 형식 오류로 둔다). 공개 뒤 「지금 종료」 대상에 레시피를 더한다(07 4.9의 「레시피는 버튼 없음」을 바꾼다).
  이 부분의 구현은 1500 ⑧·⑪이 하고, 이 티켓은 서비스·어드민·문서만 한다.
- G6 경제 수치(보상 포인트·확률)는 바꾸지 않는다. 밸런스 규칙에 레시피 기간 규칙은 더하지 않는다.

## 확인할 것 (사용자 결정 대기)

- Q1 종료된 레시피는 유저에게 어떻게 보이나?
- Q2 어드민에서 공개 뒤에 종료 시각을 바꿀 수 있나(앞당기기·늦추기·지우기)?

## 완료 조건

- (Q1·Q2 확정 뒤 채운다) 종료 시각이 지난 레시피는 일반 유저의 믹스 화면·레시피 탐색·믹스 시도에서 Q1대로 처리된다(테스트: 경계 시각 포함).
- 종료 시각이 비어 있는 레시피의 동작은 바뀌지 않는다(기존 테스트 무수정 통과).
- 어드민 레시피 폼에서 종료 시각을 정할 수 있고, 공개 시각보다 앞선 값은 저장되지 않는다(서버·화면 같은 검증 함수).
- 마이그레이션 파일에 되돌림 SQL이 있고, 사용자 승인 뒤 메인 세션이 적용한다. 생성 타입이 일치한다.
- 위 「관련 파일」의 문서에서 「레시피에는 종료 시각이 없다」 서술이 사라지고 새 규칙으로 바뀌었다.
