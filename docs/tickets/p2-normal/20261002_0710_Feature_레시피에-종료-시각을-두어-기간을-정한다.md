# [Feature] 레시피에 종료 시각을 두어 기간을 정한다

> 영향 티켓(상위 1450 진행 규칙 4). 2026-10-02 사용자 결정 「레시피에도 기간 설정 필요」(1500 ① 20261001_2205 보고에 대한 답).
> 2026-10-01에 정한 「레시피에는 종료 시각이 없고 내릴 때는 삭제한다」(07 5.1, 티켓 20261001_1157·1158)를 뒤집는다.

  지금처럼 상시다. 어드민 레시피 폼에서 정하고 공개 뒤에도 바꿀 수 있다(Q2). 운영툴의 레시피 항목은 `ends_at`을 받아 다른 자원처럼 종료된다(1500 ⑧·⑪이 잇는다).

## 배경 / 문제 정의

1500 ①(20261001_2205)을 정리하며 레시피 운영 항목이 공개 뒤 「게재중」에서 끝나지 않는 문제가 나왔다. 레시피에 종료 시각이 없어 툴이 내릴 수 없고, 레시피를 담은 묶음이
「게재」 단계에 영원히 남는다. 사용자가 「레시피에도 기간 설정 필요」로 정했다. 기간 한정 레시피(시즌 레시피 등)를 운영할 수 있게 되고, 운영툴의 레시피 항목도 다른 자원처럼
종료 시각에 「종료」로 닫히고 「지금 종료」를 쓸 수 있다.

## 가정 (카리나 초안, 2026-10-02 사용자에게 보임)

- G1 종료 시각은 선택이다. 비어 있으면 상시이고, 기존 레시피는 모두 비어 있어 동작이 바뀌지 않는다(백필 없음).
- G2 경계: 공개 시각 ≤ 지금 < 종료 시각일 때 공개다(종료 시각 그 순간부터 끝). 해석할 수 없는 값은 숨김(지금 공개 판정과 같은 fail-closed).
- G3 종료된 레시피로 이미 받은 아이템·포인트·배지는 그대로다. 「가장 먼저 성공」 배지 등 그 레시피를 가리키는 배지는 건드리지 않는다.
- G4 삭제는 그대로 남는다(삭제 가드 포함). 종료는 삭제와 별개다.
- G5 운영툴: 레시피 항목의 `ends_at`을 `valid_until`로 받는다(지금 PRD §8.4는 형식 오류로 둔다). 공개 뒤 「지금 종료」 대상에 레시피를 더한다(07 4.9의 「레시피는 버튼 없음」을 바꾼다).
  이 부분의 구현은 1500 ⑧·⑪이 하고, 이 티켓은 서비스·어드민·문서만 한다.
- G6 경제 수치(보상 포인트·확률)는 바꾸지 않는다. 밸런스 규칙에 레시피 기간 규칙은 더하지 않는다.

- G7(카리나 판단) 운영자의 공개 전 미리보기·시험 믹스(티켓 20261001_1159)는 「공개 전」 레시피만 대상이다. 종료된 레시피는 운영자에게도 믹스 화면에서 빠지고 시험 믹스도
  `recipe_not_found`다. 지난 레시피에 「공개 예정」 표시가 붙는 오류를 막고, 시험 믹스의 목적(공개 전 확인)과도 맞다.

## 사용자 결정 (2026-10-02, 둘 다 추천안)

- Q1 종료된 레시피는 **사라진다**. 공개 전처럼 없는 레시피가 된다: 믹스 화면·레시피 탐색·슬롯·보상 미리보기에서 빠지고 믹스 시도는 재료 소각 전에 거절된다. 이미 받은 보상은 그대로다.
  「끝난 레시피」로 남기는 안은 믹스 화면에 새 표시와 디자인 판정이 필요해 택하지 않았다.
- Q2 종료 시각은 **공개 뒤에도 바꿀 수 있다**(앞당기기·늦추기·지우기). 지난 시각으로 바꾸면 곧바로 내려간다. 운영툴의 「지금 종료」도 같은 칸을 지금으로 바꾸는 방식이라 규칙이 하나다.
  공개 전에만 바꾸는 안은 택하지 않았다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 종료 시각이 지난 레시피는 일반 유저의 믹스 화면(목록·검색·슬롯·보상 미리보기)에서 빠지고, 믹스 시도는 재료 소각 전에 `recipe_not_found`로 거절된다. 종료 시각 그 순간부터
  끝이다(테스트, 경계 포함).
- 운영자도 종료된 레시피는 믹스 화면에서 보지 않고 시험 믹스도 거절된다. 공개 전 레시피의 운영자 미리보기·시험 믹스는 그대로다(테스트, G7).
- 종료 시각이 비어 있는 레시피와 칸이 없는 응답(`undefined`)의 동작은 바뀌지 않는다(기존 테스트 무수정 통과).
- 어드민 폼에서 종료 시각을 정하고 지울 수 있고, 공개 뒤에도 바꿀 수 있다. 공개 시각보다 앞서거나 같은 종료 시각은 서버와 화면이 같은 함수로 거절한다(400). 지난 시각으로
  저장하면 확인창을 거쳐 바로 종료된다.
- 어드민 목록의 상태 열이 「공개 예정」·「공개 중」·「종료됨」을 구분하고, 내보내기에 「종료 시각」 열이 있다.
- 마이그레이션 파일은 칼럼 추가와 CHECK뿐이고(백필 없음) 되돌림 SQL이 있다.
- 구현 계획 5의 문서 네 곳에서 「종료 시각이 없다」 서술이 새 규칙으로 바뀌었다.

### 후속 범위 (담당: 카리나, 시점: 게이트 뒤 사용자 머지 승인 때)
- 사용자 승인 뒤 Supabase MCP로 마이그레이션을 적용하고 생성 타입을 대조한 다음 코드를 머지한다. 코드가 `valid_until`을 select하므로 칼럼이 먼저 있어야 한다(확장 먼저).
- 머지 뒤 push 전에 어드민 레시피 폼을 로컬에서 실렌더한다. 실DB 쓰기 시험은 처리 규칙표의 「숨김·예약 기능을 실DB 쓰기로 시험」 행을 따른다.

### 구현 내용 요약

- DB: `combination_recipes.valid_until`(TIMESTAMPTZ NULL)과 CHECK `combination_recipes_valid_period_check`(공개 < 종료). 마이그레이션 213, 2026-10-02 적용.
- 판정: `recipeReleaseState`가 `scheduled`·`released`·`ended` 세 값을 돌려주고 `isRecipeReleased`는 `released`일 때만 참이다. 종료된 레시피는 믹스 화면에서 빠지고 믹스 시도는 재료 소각 전에
  `recipe_not_found`다. 운영자의 미리보기·시험 믹스는 `scheduled`만 대상이다(G7).
