# [Infra] 클라우드 대화형 세션의 git 작성자가 예약 루틴과 같아 커밋이 막힌다

> 범위 밖 발견물(2026-10-02 카리나, 티켓 20261001_2205·20261002_0710 진행 중).

## 핵심 요약

- 요구사항: 사용자가 claude.ai 클라우드에서 직접 연 대화형 세션은 컨테이너 기본 git 작성자가 `Claude <noreply@anthropic.com>`(`/root/.gitconfig`)이다. 이 이메일은
  `.githooks/pre-commit`이 무인 예약 루틴으로 판정하는 작성자와 같아서, 대화형 세션의 카리나와 아현도 `docs/operations/reports/` 밖 파일을 커밋하지 못한다. 대화형 세션은
  정상 커밋하고 예약 루틴은 지금처럼 막히도록 둘을 가른다.
- 구현 계획: 사용자가 방법 B를 골랐다(2026-10-23). 아래 「구현」에 있다. 무인 루틴 세션의 실제 환경 값 확인이 후속 범위로 남아 있다.
- 관련 파일: `.githooks/pre-commit` 31~60행(`ROUTINE_AUTHOR_EMAIL` 판정), `docs/agents/contract.json` 285행 부근(`author_email` 계약), `scripts/pre-commit-routine-author.test.mjs`,
  `.claude/skills/jam-work/references/scheduled-jobs.md` 216행(무인 쓰기 범위), `.githooks/pre-push` 43~54행(끝 커밋 작성자 검사), `scripts/ensure-hooks-path.sh`(세션 시작 훅),
  `.claude/workflows/jam-work.js`(아현 프롬프트), `docs/agents/orchestrator.md` §5

## 배경 / 문제 정의

- 2026-10-02 이 세션(클라우드, 사용자 대화형)에서 카리나의 문서 커밋이 막혔다. 카리나는 커밋마다 `git -c user.name=standardmanual -c user.email=sihyunrr@gmail.com`으로
  작성자를 사용자 계정으로 지정해 넘겼고(18738b8·5104d03·778a86a), 사용자에게 보고했다.
- 같은 날 티켓 20261002_0710의 아현이 구현·검증을 마친 뒤 같은 이유로 커밋하지 못하고 `halted`로 돌아왔다(약 24만 토큰 실행). 아현은 훅의 「우회 변수는 없습니다」를 보고 작성자를
  바꾸지 않았다. 카리나가 같은 방식으로 다섯 커밋을 대신 만들고 게이트만 다시 돌렸다.
- 로컬 PC 세션은 사용자 git 설정(`standardmanual`)으로 커밋하므로 걸리지 않는다. 클라우드 대화형 세션만의 문제다.
- 지금의 우회(커밋마다 `-c`로 사용자 계정 지정)는 훅이 막으려는 것(무인 루틴의 쓰기)과 겉으로 구분되지 않는다. 규칙으로 정해 두지 않으면 세션마다 판단이 갈린다.

## 가를 방법 후보 (착수 때 사용자 확인)

- A. 예약 루틴의 작성자를 전용 값(예: `JAM Routine <routine@jam.internal>`)으로 바꾸고 훅은 그 값을 막는다. 루틴 프롬프트가 작성자를 정해야 해서 루틴 재설정(1504)과 함께 하면 좋다.
- B. 세션 시작 훅이 대화형 세션에서만 저장소 로컬 `user.email`을 사용자 계정으로 맞춘다. 대화형과 예약 세션을 가르는 신호가 필요하다(확인 전).
- C. 지금처럼 커밋마다 `-c`로 사용자 계정을 지정하는 것을 규칙으로 적는다(카리나·아현 정의와 `handling-rules.md`). 가장 작지만 훅의 방어 의미가 약해진다.

## 사용자 결정 (2026-10-23)

## 신호 조사 (2026-10-23)

방법 B의 전제인 «대화형과 예약 세션을 가르는 신호»를 확인했다.

- 사실(이 세션, 사용자가 iOS 앱에서 연 클라우드 세션의 환경 변수): `CLAUDE_CODE_REMOTE=true`, `CLAUDE_CODE_SESSION_ATTENDED=1`, `CLAUDE_CODE_ENTRYPOINT=remote_mobile`, `CLAUDE_CODE_TRIGGER_ID` 없음, `CLAUDE_CODE_USER_EMAIL`이 사용자 계정 이메일과 같다.
- 사실(실행 파일 `/opt/claude-code/bin/claude`에서 읽은 판정식): `CLAUDE_CODE_SESSION_ATTENDED`는 Claude Code가 셸에 `1` 또는 `0`으로 넣는다. 세션 종류가 `bg`·`daemon`이거나 팀원 에이전트이면 `0`이고, 상호작용 세션이거나 허용된 진입점에서 시작한 하위 세션이 아닌 세션이면 `1`이다. 허용된 진입점 목록의 값은 읽지 못했다. `CLAUDE_CODE_TRIGGER_ID`는 실행 파일이 읽어 세션 시작 이벤트에 `trigger_id`로 기록한다.
- 사실(서버 기록): 데일리 미팅 루틴의 마지막 세션(2026-10-23)은 `origin: scheduled_trigger`이고, 이 세션은 `origin: ios`다.
- 확인하지 못한 것: 무인 루틴 세션 컨테이너 안의 `CLAUDE_CODE_SESSION_ATTENDED`·`CLAUDE_CODE_TRIGGER_ID`·`CLAUDE_CODE_ENTRYPOINT` 실제 값. 서버 기록에는 컨테이너 환경 변수가 없다. 그래서 `SESSION_ATTENDED` 하나로 가르지 않고, 조건을 여럿 겹치고 허용 진입점을 사람이 연 세션에서 확인한 `remote_mobile` 하나로 좁혔다.
- 해석: 예약 세션이 `SESSION_ATTENDED=1`이어도 `TRIGGER_ID`가 있거나 진입점이 `remote_mobile`이 아니면 걸러진다. 다만 이 두 가지가 예약 세션에서 실제로 그렇다는 것은 후속 범위에서 확인한다.

## 구현 (2026-10-23)

- `scripts/ensure-session-author.sh`(SessionStart 훅): 다음 여섯 조건을 모두 만족할 때만 이 클론의 `user.name`·`user.email`을 `interactive_session_author` 값으로 바꾼다. 클라우드 컨테이너, 지금 작성자가 루틴 작성자와 같음, `SESSION_ATTENDED=1`, `TRIGGER_ID` 없음, 세션 소유자 이메일이 선언한 이메일과 같음, 진입점이 허용 목록에 있음. 하나라도 어긋나면 아무것도 바꾸지 않고 이유를 한 줄 남긴다(사람이 붙은 세션이면 화면에, 아니면 훅 로그 stderr에).
- `.githooks/pre-commit`은 바꾸지 않았다(우회 변수 없음 유지). 예약 루틴 세션은 위 조건에서 걸러져 작성자가 그대로이므로 지금처럼 막히도록 설계했다. 걸러지는지는 실제 값으로 아직 확인하지 못했고 후속 범위에서 확인한다.
- `docs/agents/contract.json`: `interactive_session_author`(이름·이메일·허용 진입점) 선언, SessionStart 훅 목록, 필수 경로를 더했다. `scripts/check-contract.mjs` 검사 ⑮가 선언이 깨졌거나 이메일이 루틴 작성자와 같으면 막는다.
- 시험 `scripts/ensure-session-author.test.mjs`: 환경 변수 조합 11묶음. 조건 네 개(ATTENDED, TRIGGER_ID, 소유자, 진입점)를 하나씩 뺀 변형 스크립트 4개를 만들어 시험이 모두 실패시키는 것을 확인했다.
- 문서: `orchestrator.md` §5, `scheduled-jobs.md` 무인 쓰기 범위, `team-operations.md` 생성 구간과 `team-map.html`을 생성기로 갱신했다.
- 게이트(민지, 2026-10-23) WARN, 지적 두 건을 고쳤다. ① 허용 진입점을 쉼표로 이어 붙여 비교해서 목록이 둘 이상이면 «remote_mobile,remote_web» 같은 값이 통과하던 잠복 결함이다. 시험을 먼저 추가해 현재 스크립트에서 실패하는 것을 재현한 뒤 항목별 정확 비교로 고쳤다(허용 목록이 하나인 지금 계약에서는 닿지 않았다). ② 무인 세션의 실제 값을 확인하지 못했는데 «적용하지 않는다»로 확정해 적은 서술 네 곳(스크립트 메시지, `scheduled-jobs.md`, 생성기 설명문, 이 티켓)을 확인된 범위로 낮췄다.
- 한계: 이 훅은 조건에 맞는 세션의 작성자 지정이다. pre-commit이 `git var GIT_AUTHOR_IDENT`를 보기 때문에 어느 세션이든 `git -c user.email=…`로 작성자를 바꿔 넘기면 통과한다는 점은 이전과 같다.
- 공개 저장소: `interactive_session_author`의 이름·이메일은 공개 저장소에 올라간다. 이 이메일은 이미 공개된 커밋 작성자 이메일과 같다.

## 재발 기록

- 후보 C(우회를 규칙으로 적기)를 고른다면 «건별 사용자 승인 + 적용 범위 기록»을 규칙에 넣을지 함께 정한다.
