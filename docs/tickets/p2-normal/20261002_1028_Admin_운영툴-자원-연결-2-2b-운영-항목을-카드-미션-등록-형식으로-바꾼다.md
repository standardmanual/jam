# [Admin] 운영툴 자원 연결 ②-2b 운영 항목을 카드·미션 등록 형식으로 바꾼다

> 상위: 20260930_1500 ②-2의 뒤 절반. 유형 `api`. 선행: ②-2a(20261002_1027). JAM! 배지 변환은 ⑨로 미뤘다(2026-10-02 사용자 결정).

## 핵심 요약

- 요구사항: 승인된 운영 항목(`ops_bundle_items`, 수정본 우선)의 `home_feed_card`·`mission`을 운영툴 PRD §8.4 규칙대로 `today_cards`·`missions` insert 값으로 바꾸는 서버 함수를 만든다.
  결과는 `{ payload, errors, warnings, linkFields }`이고, 검사는 ②-2a가 옮긴 `validateCard`·`validateMission`을 쓴다. DB에 쓰지 않는다(쓰기는 ③·④·⑥).
- 구현 계획: 착수 때 ②-2a 머지 결과를 보고 파일 단위로 적는다. 2026-10-02 Explore 지도의 추정은 새 파일 `jam-web/src/lib/admin/opsInbox/registerInput.ts`(약 300줄),
  `jam-web/src/lib/today/shape.ts`에 카드 제목 글자 수 상한 상수, 테스트 약 450줄이다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/itemView.ts`(`itemField` 22–26·`asRecord` 17–19·`linksOf` 40–43), `opsInbox/balance/evaluate.ts`(`readTimeValue` 117–126·`readResource` 137–142),
  `jam-web/src/lib/admin/today-calendar.ts`(`kstDayBoundsIso` 45–50), `opsInbox/labels.ts`(`kstDateKey` 218–221), `jam-web/src/lib/admin/opsPatterns/constants.ts`(`OPS_PATTERN_NO_PATTERN` 22),
  `jam-web/src/lib/today/shape.ts`(`CARD_SHAPES`), ②-2a의 `registerChecks/homeFeedFields.ts`·`missionFields.ts`.

## 착수 전에 정한 것 (2026-10-02 카리나 가정, 사용자에게 보임)

1. 운영툴이 만드는 행의 `image_source`는 null이다(어드민 today·missions 라우트 선례). 이미지 제작 경로 표시는 1501이 정한다.
2. 카드의 `created_by`는 예약 등록을 실행한 관리자 ID다(변환 함수의 인자).
3. 미션 `description`은 등록 스크립트처럼 필수다. 배지 `description`도 DB NOT NULL이라 필수다(⑨). 운영툴 PRD §8.4 표에 「필수」 표기를 더한다.
4. JAM! 배지는 종목(`activity_types`)과 함께 쓰지 않는다(어드민 폼 규칙). §8.4 표의 `jam_badge` 행에서 `activity_types`를 뺀다(⑨에서 확정).
5. 카드의 `pattern_no`는 ②-2a의 페이로드 코어가 아니라 이 변환이 덧붙인다(G11). 기존 scripts 테스트(`registerHomeFeedBundle.test.ts` 548–558의 키 대조)를 고치지 않기 위해서다.
   1500 G11의 「556행 제외 목록에서 pattern_no를 뺀다」는 메모는 이 결정으로 바꾼다.
6. 카드 종료 시각이 없으면 공개한 날의 끝 `kstDayBoundsIso(kstDateKey(starts_at)).endIso`(23:59:59.999 KST)로 채운다. 신호 계산(`opsSignals/composition.ts`의 `bundleItemPeriod`)과 같은 값이다.
7. 검사 오류 문장(`card.title: …`)은 그대로 두고, 운영 항목 경로(`copy.title`·`resource.template_type` 등)를 함께 돌려준다. 화면 표기는 ⑤에서 정한다.
8. 연결로 채울 칸(`mission_id`·`badge_ids`·`item_book_id`·`reward_badge_ids`, §8.3)은 결과의 `linkFields`로 알리고, 등록 전 DB 검사에서 그 ID의 존재 확인은 건너뛴다(같은 실행에서
   만들어질 ID다. 생성 순서가 존재를 보장한다). 검증용으로는 미리 정한 UUID를 넣어 템플릿별 필수 참조 검사를 통과시킨다(G3).

## 완료 조건 (착수 때 다듬는다)

- `home_feed_card`·`mission` 항목을 §8.4 규칙(공통 칸 우선, 글자 칸은 `copy` 먼저, 표에 없는 키·툴이 정하는 칸은 경고, G10·G11·G15)대로 insert 값으로 바꾸고, 지금 등록 스크립트와 같은
  검사로 오류를 낸다(테스트).
- DB에 쓰지 않는다. 연결로 채울 칸 목록을 돌려준다.
- 위 1~8이 테스트와 운영툴 PRD §8.4에 반영돼 있다.
