# [Admin] 운영툴 자원 연결 ②-2b 운영 항목을 카드·미션 등록 형식으로 바꾼다

> 상위: 20260930_1500 ②-2의 뒤 절반. 유형 `api`. 선행: ②-2a(20261002_1027). JAM! 배지 변환은 ⑨로 미뤘다(2026-10-02 사용자 결정).

## 핵심 요약

- 요구사항: 승인된 운영 항목(`ops_bundle_items`, 수정본 우선)의 `home_feed_card`·`mission`을 운영툴 PRD §8.4 규칙대로 `today_cards`·`missions` insert 값으로 바꾸는 서버 함수를 만든다.
  결과는 `{ payload, errors, warnings, linkFields }`이고, 검사는 ②-2a가 옮긴 `validateCard`·`validateMission`을 쓴다. DB에 쓰지 않는다(쓰기는 ③·④·⑥).
- 구현 계획: 아래 「구현 계획 (파일 단위)」. 약 7파일·850줄(테스트 약 450줄 포함)이라 첫 호출부터 계획 반환 면제를 넘긴다. ②-2a는 머지됐다(a1c422d).
- 관련 파일: `jam-web/src/lib/admin/opsInbox/itemView.ts`(`itemField` 22–26·`asRecord` 17–19·`linksOf` 40–43), `opsInbox/balance/evaluate.ts`(`readTimeValue` 117–126·`readResource` 137–142),
  `jam-web/src/lib/admin/today-calendar.ts`(`kstDayBoundsIso` 45–50), `opsInbox/labels.ts`(`kstDateKey` 218–221), `jam-web/src/lib/admin/opsPatterns/constants.ts`(`OPS_PATTERN_NO_PATTERN` 22),
  `jam-web/src/lib/today/shape.ts`(`CARD_SHAPES`), ②-2a의 `registerChecks/homeFeedFields.ts`·`missionFields.ts`.

## 착수 전에 정한 것 (2026-10-02 카리나 가정, 사용자에게 보임)

1. 운영툴이 만드는 행의 `image_source`는 null이다(어드민 today·missions 라우트 선례). 이미지 제작 경로 표시는 1501이 정한다.
2. 카드의 `created_by`는 예약 등록을 실행한 관리자 ID다(변환 함수의 인자).
3. 미션 `description`은 등록 스크립트처럼 필수다. 배지 `description`도 DB NOT NULL이라 필수다(⑨). 운영툴 PRD §8.4 표에 「필수」 표기를 더한다.
4. JAM! 배지는 종목(`activity_types`)과 함께 쓰지 않는다(어드민 폼 규칙). §8.4 표의 `jam_badge` 행에서 `activity_types`를 뺀다(⑨에서 확정).
5. 카드의 `pattern_no`는 ②-2a의 페이로드 코어가 아니라 이 변환이 덧붙인다(G11). 기존 scripts 테스트(`registerHomeFeedBundle.test.ts` 548–558의 키 대조)를 고치지 않기 위해서다.
   1500 G11의 「556행 제외 목록에서 pattern_no를 뺀다」는 메모는 이 결정으로 바꾼다.
6. 카드 종료 시각이 없으면 공개한 날의 끝 `kstDayBoundsIso(kstDateKey(starts_at)).endIso`(23:59:59.999 KST)로 채운다. 신호 계산(`opsSignals/composition.ts`의 `bundleItemPeriod`)과 같은 값이다.
7. 검사 오류 문장(`card.title: …`)은 그대로 두고, 운영 항목 경로(`copy.title`·`resource.template_type` 등)를 함께 돌려준다. 화면 표기는 ⑤에서 정한다.
8. 연결로 채울 칸(`mission_id`·`badge_ids`·`item_book_id`·`reward_badge_ids`, §8.3)은 결과의 `linkFields`로 알리고, 등록 전 DB 검사에서 그 ID의 존재 확인은 건너뛴다(같은 실행에서
   만들어질 ID다. 생성 순서가 존재를 보장한다). 검증용으로는 미리 정한 UUID를 넣어 템플릿별 필수 참조 검사를 통과시킨다(G3).

## 구현 계획 (파일 단위)

1. **새 `jam-web/src/lib/admin/opsInbox/registerInput.ts`** (서버·화면 공용 순수 모듈, DB 접근 없음).
   - 입력 타입 `OpsRegisterItem`: `ViewableItem`(`opsInbox/itemView.ts` 12–15행) + 행 칸 `kind`·`starts_at`·`ends_at`·`pattern_no`. 시각은 `itemField` 값을 먼저, 없으면 행 칸(선례
     `opsInbox/balance/evaluate.ts`의 `readTimeValue` 117–126행).
   - 결과 타입 `RegisterInputResult<P>`: `{ payload: P | null, errors: RegisterInputIssue[], warnings: RegisterInputIssue[], linkFields: string[] }`, `RegisterInputIssue = { path, message }`.
     `path`는 운영 항목 경로(`copy.title`·`resource.template_type`·`starts_at`·`shape` 등), `message`는 검사 문장 그대로(결정 7). 오류가 하나라도 있으면 `payload`는 null.
   - `toTodayCardRegisterInput(item, { id, actorId, linkedIds })`: 운영툴 PRD §8.4 카드 행대로 읽는다. 공통 칸(`starts_at` 필수, `ends_at`은 없으면 결정 6, `shape` 필수·`isCardShape`,
     `exposure_tags`, `pattern_no`는 `OPS_PATTERN_NO_PATTERN`(`opsPatterns/constants.ts` 22행)에 맞으면 쓰고 아니면 null + 경고, 결정 5), 글자 칸 `title`·`subtitle`·`description`·`body_markdown`·
     `region_label`은 `copy` 먼저 그다음 `resource`, 나머지 `resource` 칸(`template_type`·`layout_type`·`title_in_image`·`cover_image_url`·`badge_ids`·`mission_id`·`item_book_id`·`ranking_mode_id`·
     `content_type_id`·`target_href`·`sort_order`). 표에 없는 `copy`·`resource` 키, 툴이 정하는 키(`id`·`created_at`·`created_by`·`image_source`·`is_active`), 공통 칸과 겹치는 `resource` 키는 무시하고 경고.
     `linkedIds`(`mission_id`·`badge_ids`·`item_book_id`, ③이 §8.3으로 정해 넘김)로 연결 칸을 채운다(`badge_ids`는 뒤에 더함, 단일 칸에 `resource` 값도 있으면 오류). 채운 칸은 `linkFields`.
     CLI 모양 card 객체를 만들어 `validateCard`(`registerChecks/homeFeedFields.ts` 129행)로 검사하고, `card.<칸>:` 문장을 운영 항목 경로로 옮긴다. 제목 글자 수가 모양별 상한을 넘으면 경고(G15).
     페이로드는 `buildTodayCardInsertPayload(card, { id, coverImageUrl: resource.cover_image_url ?? null, imageSource: null, shape, titleInImage })`에 `pattern_no`와 `created_by: actorId`를 덧붙인다(결정 1·2·5).
   - `toMissionRegisterInput(item, { id, linkedIds })`: §8.4 미션 행대로 읽는다. `starts_at` 필수, `ends_at`은 없으면 상시, 글자 칸 `title`·`description`(필수, 결정 3)·`condition_text`, `resource` 칸
     (`mission_type`·`condition_json`·`reward_points`·`reward_badge_ids`·`status_display_type`·`visible_rank_count`·`max_completions`·`gate_axis`·`gate_stage`·`visibility_rule_json`·`image_url`).
     툴이 정하는 값 `exposure_mode = 'start_date'`, `exposure_at` null. `linkedIds.reward_badge_ids`는 뒤에 더한다. `condition_text`·`image_url`은 CLI 검사 칸이 아니므로 빼고 `validateMission`
     (`registerChecks/missionFields.ts` 68행)으로 검사, `mission.<칸>:` 문장을 경로로 옮긴다. 경고는 `warnings`로. 페이로드는 `buildMissionInsertPayload(mission, { id, imageUrl: resource.image_url ?? null,
     imageSource: null, conditionText })`.
   - `withoutLinkedFields(payload, linkFields)`: 등록 전 DB 검사(`runHomeFeedDbChecks`·`runMissionDbChecks`)에 넘길 사본에서 연결로 채운 ID를 빼 준다(결정 8. 같은 실행에서 만들어질 ID라
     존재 확인을 건너뛴다). 배열 칸은 연결 몫만 빼고 `resource` 몫은 남긴다.
2. **`jam-web/src/lib/admin/registerChecks/homeFeedFields.ts` 286–297행, `missionFields.ts` 203–212행.** `coverImageUrl`·`imageUrl` 타입을 `string | null`로 넓힌다(G1: 이미지 없이 예약). 스크립트 래퍼는
   계속 문자열을 넘기므로 동작이 같다.
3. **`jam-web/src/lib/today/shape.ts`.** 모양별 카드 제목 글자 수 상한 상수(`hero` 22·`poster` 18·`square` 22·`brief` 28·`list` 22, 홈피드 PRD §6 「글자 배치 상한」 표)를 `CARD_SHAPES` 옆에 둔다.
   import를 더하지 않는다(`__tests__/eventsImports.test.ts`가 import 그래프를 본다).
4. **새 테스트 `jam-web/src/lib/admin/opsInbox/__tests__/registerInput.test.ts`.** 수정본 우선, 공통 칸 우선과 겹침 경고, `copy` 먼저·`resource` 다음, 표에 없는 키·툴이 정하는 키 경고, 결정 6의 종료 시각
   (KST 자정 넘김 포함), 결정 5의 `pattern_no`(맞음·틀림·없음), G15 경고(모양별 경계), 연결 칸 채우기와 단일 칸 충돌 오류, `validateCard`·`validateMission` 문장의 경로 매핑, 미션 `description` 필수,
   `condition_text`가 `copy`에서 오는지, 페이로드 키 집합(카드는 스크립트 키 + `pattern_no`·`created_by`, 미션은 스크립트와 같음), `image_source` null, `withoutLinkedFields`.
5. **문서.** `docs/specs/prd/ops-tool/PRD.md` §8.4 머리에 「구현됨(카드·미션, 티켓 20261002_1028)」과 변환 함수 위치, 미션 `description`(필수), 결정 1·2·5·6·7·8. `jam_badge` 행의 `activity_types`는
   ⑨ 확정까지 그대로 두고 「⑨에서 정한다」를 적는다. 상위 1500의 G11 메모를 결정 5로 바꾼다(카리나가 머지 뒤).

## 완료 조건

- `home_feed_card`·`mission` 항목을 §8.4 규칙과 결정 1~8대로 insert 값으로 바꾸고, 지금 등록 스크립트와 같은 검사로 오류를 낸다(테스트).
- DB에 접근하지 않는다(모듈에 Supabase import 없음). 연결로 채운 칸 목록을 돌려주고, DB 검사용 사본에서 그 칸을 뺄 수 있다.
- 페이로드 함수의 이미지 주소가 null을 받고, 기존 scripts 테스트(`jam-web/scripts/asset-generator/__tests__/`)는 무수정 통과한다. `scripts/verify.sh` 전 항목 통과.
- 운영툴 PRD §8.4가 구현과 결정을 반영한다.
