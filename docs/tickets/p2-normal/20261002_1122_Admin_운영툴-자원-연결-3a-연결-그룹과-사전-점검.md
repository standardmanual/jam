## 착수 전 확인한 사실 (2026-10-02 Explore 지도, HEAD e483e86)

- 연결 그룹을 만드는 기존 함수, 생성 순서 상수, 종류 쌍 상수는 없다. 선례는 `balance/evaluate.ts`의 `readRewardRefs`(223–245행, 첫 일치만 씀)뿐이다.
- `item_key`는 유일 제약이 없어 겹칠 수 있고(형식 오류로만 저장, `validate.ts` 280–291행), `links`가 자기 자신이나 없는 키를 가리켜도 형식 오류로만 남는다(344–357행).
- `jam-web/src/lib/admin/registerChecks/` 폴더에는 새 파일을 두지 않는다(`__tests__/registerChecks.test.ts` 322–324행이 파일 8개를 단언한다).
- `jam-web/src/app/api/admin/__tests__/token-write-contract.test.ts` 112–125행은 `__tests__` 밖의 모든 `.ts` 원문(주석 포함)에 제출 토큰 래퍼 두 이름이 없어야 한다고 본다. 새 파일의 주석에도 그 이름을 쓰지 않는다.
- `registerInput.ts`의 `fillLinkedId`(207–226행)는 연결 ID와 `resource`의 같은 단일 칸이 함께 있으면 오류를 낸다. PRD §8.3은 이 경우를 사전 점검의 「못 하는 항목」(승인됨 유지)으로 정하므로 사전 점검이 먼저 걸러야 한다.
- 결정 전 상태 판정은 `isUndecidedStatus`(도착·검토중), 멈춘 상태는 `balance/rules.ts` 85행 `BALANCE_SKIPPED_STATUSES`(반려·취소·실패)가 있다.

## 착수 전에 정한 것 (2026-10-02 카리나 가정, 사용자 확인 2026-10-02 「이대로 진행」)

1. 형식 오류가 남은 승인 항목은 `format_errors` 열만으로 막지 않는다. §8.4 변환·검사(②-2b)가 걸러 낸다(③-b). 사전 점검은 공개 시각·연결·종류만 본다.
2. `pattern_proposal` 승인 항목은 네 분류 밖이다(`excluded`로 따로 돌려주고 N에 세지 않는다). 최종 상태는 1503 ⑪이 정한다.
3. `item_key`가 겹치거나 `links`가 없는 키·자기 자신을 가리키는 항목은 「못 하는 항목」이고, 그 그룹 전체가 함께 막힌다(사유 「연결을 읽을 수 없어요」).
4. 「실패로 닫을 항목」은 반려·취소·실패한 항목을 직접 또는 다른 항목을 거쳐 가리키는 승인 항목이다. 멈춘 항목이 가리키기만 하는(참조당하는) 항목은 실패가 아니다(예: 반려된 카드가 여는 미션은 그대로 예약할 수 있다).
   연결 그룹은 멈춘 항목을 빼고 만든다.
5. G6 경계: 공개 시각 − 지금 ≤ 10분이면 막는다(정확히 10분 남아도 막는다).
6. 사전 점검은 그룹 안 공개 시각이 서로 달라도 막지 않고 경고만 한다(G4). 같은 그룹에 이미 예약·게재 중인 항목이 있으면 그 항목은 실행 대상이 아니고 연결 대상(만든 ID를 `created_resource`에서 읽음)으로만 쓴다.
