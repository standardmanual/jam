# [Admin] 운영툴 자원 연결 ④-b 공개 전 취소 API

> 상위: 20260930_1500 ④의 뒤 절반. 유형 `api`. 선행: ④-a(20261002_1255). ⑤(화면의 취소 확인창)보다 먼저 한다. 파일 단위 계획은 착수 때 쓴다.

## 핵심 요약

- 요구사항: `POST /api/admin/ops-inbox/[bundleId]/items/[itemId]/cancel`(운영툴 PRD §11.7, 동작 §8.7 796–803행)을 만든다. 예약됨 항목의 자원을 공개 전에 지우고 항목을 「취소」로 둔다.
  - 그 항목을 가리키는 항목도 함께 취소한다. 그중 게재 중인 항목이 있으면 409다.
  - 운영툴 밖의 참조가 있으면 409다. 카드는 `findHomeFeedUndoReferences`로 확인한다.
  - 공개 시각이 지났으면 서버가 자원을 다시 읽어 확인하고 409다. `RegisterQuery`에는 `gt`가 없어 행을 읽은 뒤 비교한다.
  - 사유는 500자까지 받는다. 결정 기록은 `cancel`(함께 취소한 항목은 같은 `batch_id`), 슬랙은 `#jam-report`다.
- 착수 때 정할 것:
  - 핸들러 인터페이스에 취소용 메서드를 더할지, `undo`에 공개 전 확인을 얹을지 정한다. 지금 `undo`는 실행 중 되돌림 전용이다.
  - `OPS_DECISION_ACTION_CANCEL` 상수와 슬랙 문장을 정한다.
  - 관리자 로그인만 받는다(`token-write-contract.test.ts` 무수정).
- ④-a에서 넘김(2026-10-02, 민지 범위 밖 발견물): 카드 insert가 실패한 항목에도 만들어지지 않은 카드 ID가 `created_resource.today_card_id`에 남는다(`idFirst`, `run.ts` 326행). 취소 대상은 「예약됨」뿐이라
  보통 닿지 않지만, 자원을 다시 읽을 때 행이 없으면 오류가 아니라 「밖에서 지워짐」으로 다룬다(PRD §8.6과 같은 뜻).
- 관련 파일(2026-10-02 Explore): `jam-web/src/lib/admin/opsInbox/constants.ts` 68–74행(결정 기록 값, `cancel` 없음), `execute/run.ts`(선점·결정 기록·슬랙 선례), `ops-inbox/[bundleId]/execute/route.ts`
  (라우트 선례), `registerChecks/references.ts` 165–175행, 운영툴 PRD §8.7·§10(891행 `cancel`)·§11.7. 예상 규모는 라우트 약 80줄, 취소 로직 150–200줄, 테스트 약 250줄, 상수·슬랙 20–30줄이다.

## 완료 조건

- 예약됨 카드 항목을 취소하면 `today_cards` 행이 지워지고 항목이 「취소」가 되며 `cancel` 기록이 남는다(테스트).
- 공개 시각이 지난 카드, 노출 기록이 붙은 카드, 게재 중인 항목이 가리키는 항목은 409이고 아무것도 지우지 않는다(테스트).
- 응답·결정 기록·슬랙에 DB 오류 원문이 없다(테스트). `scripts/verify.sh` 전 항목 통과.
