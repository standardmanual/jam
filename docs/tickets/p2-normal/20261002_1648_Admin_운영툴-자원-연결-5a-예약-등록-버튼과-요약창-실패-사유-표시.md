## 착수 전에 정한 것 (2026-10-02 카리나)

1. **N은 서버 로더가 센다.** `getOpsBundleDetail`이 항목을 읽을 때 `created_resource`도 읽고, 원본 행으로 `ExecuteItem` 목록을 만들어 `precheckBundle(items, { now })`를 부른다(기본 레지스트리).
   결과에서 `execution: { approvedCount, readyCount, unconnectedKinds }`만 상세에 싣는다. `unconnectedKinds`는 멈추지 않은 항목(반려·취소·실패·종료 밖) 가운데 레지스트리에 핸들러가 없는 종류의
   목록(묶음 안 첫 등장 순)이다. 레지스트리·카드 핸들러를 클라이언트 번들로 끌어오지 않으려고 화면에서는 계산하지 않는다.
2. **버튼.** `barAction`에 둔다. 일괄 승인 버튼이 함께 있으면 그 오른쪽에 둔다. 승인됨 항목이 하나라도 있으면 보인다. 문구는 `readyCount > 0`이면 「N개 예약 등록하기」,
   0이면 「예약 등록하기」다(눌러서 왜 못 하는지 볼 수 있게 끄지 않는다).
3. **요약창.** 열 때 사전 점검 요청(`{ dryRun: true }`)을 새로 보내 지금 결과로 그린다(로더 값은 버튼 문구에만 쓴다). 창은 `OpsDialogShell`·`OpsConfirmPanel` 선례를 쓰고, 목록이 길면 창 안에서 스크롤한다
   (`AlertDialogContent`에 높이 제한이 없다). 내용 순서와 문구:
   - 제목 「예약 등록 전에 확인해 주세요」.
   - 「예약할 항목 N개」: 공개 시각 순, 연결 묶음(`groups`)은 한 덩어리로 묶어 보인다. 항목 이름은 목록 행과 같은 표시(종류·공개 시각 KST·제목)를 쓴다.
   - 「기다리는 항목 N개」: 「연결된 항목이 아직 승인 전이에요」(사전 점검 문장). (2026-10-02 바로잡음: 실제 사전 점검 문장 「연결된 항목이 아직 결정 전이에요」가 기준이다. 완료 기록 참고.)
   - 「예약할 수 없는 항목 N개」: 항목마다 사전 점검 이유.
   - 「실패로 닫을 항목 N개」: 항목마다 이유와 「예약 등록하면 실패로 닫혀요」.
   - 경고(`warnings`)가 있으면 경고 줄.
   - 시험 묶음이면 「시험 묶음이라 자원은 만들지 않아요」.
   - 버튼: 보조 「닫기」, 주 「N개 예약 등록하기」(진행형 「예약 등록하는 중」). 예약할 항목이 0개이고 실패로 닫을 항목도 0개면 주 버튼을 끄고 「지금 예약할 수 있는 항목이 없어요」를 보인다.
     예약할 항목이 0개여도 실패로 닫을 항목이 있으면 주 버튼은 「실패로 닫기」다(실행 API는 이 경우 200으로 닫는다, ④-a 가정 6).
4. **실행과 결과.** 주 버튼은 `{ itemIds }`(요약창이 보인 예약할 항목, 없으면 실패로 닫을 항목)로 실행 요청을 보낸다. 결과:
   - 성공: 창을 닫고 토스트. 「N개를 예약 등록했어요」, 실패가 있으면 「N개를 예약 등록했고 M개는 실패했어요」, 예약 없이 닫기만 했으면 「M개를 실패로 닫았어요」. 건너뛴 항목이 있으면 「K개는 그사이 바뀌어
     건너뛰었어요」를 덧붙인다. `decisionLogFailed`면 경고 토스트 「결정 기록을 남기지 못했어요. 예약은 그대로예요.」. 끝나면 `router.refresh()`.
   - 409: 창 안에 서버 문장을 보이고 화면을 새로 부른다(`postDecision`의 409 처리와 같다). 그 밖의 실패: 창 안에 서버 문장, 네트워크 오류는 `NETWORK_ERROR_MESSAGE`.
   - 호출은 던지지 않는 결과 형태(`postDecision`과 같은 `{ ok, status, error, data }`)로 새 `executeClient.ts`에 둔다(⑤-b가 취소 요청을 더한다).
5. **실패 사유.** 셸이 결정 기록에서 항목별 가장 최근 `fail` 사유 맵을 만들어 목록에 넘긴다(밸런스 `balanceLinesByItem` 방식). 상태가 「실패」인 행에만 칩 아래 한 줄로 사유를 보인다(줄임 한 줄).
6. **결정 기록 이름표.** `DECISION_ACTION_LABELS`에 `execute` 「관리자가 예약 등록했어요」, `fail` 「예약 등록에 실패했어요」, `cancel` 「관리자가 공개 전에 취소했어요」를 더하고,
   `DECISION_REASON_LABELS`에 `fail` 「실패 사유」, `cancel` 「취소 사유」를 더한다. 「일괄 승인」 칩 규칙은 바꾸지 않는다.
7. **안내 문장.**
   - 늘 떠 있던 `OPS_PUBLISH_NOT_CONNECTED_NOTICE`를 없애고, `unconnectedKinds`가 있을 때만 「{종류 이름을 ·로 이은 것} 항목은 아직 예약 등록을 연결하지 않았어요. 승인해도 예약되지 않아요.」를 보인다
     (종류 이름은 `kindLabel`). 없으면 알림 줄을 그리지 않는다.
   - 승인 확인창(`OpsItemActions.tsx` 206행)과 일괄 승인 요약(`OpsBulkApprove.tsx` 112행)의 「공개는 아직 연결 전이에요…」를 「예약은 승인한 뒤 [예약 등록하기]에서 해요.」로 바꾼다
     (일괄 승인은 「승인은 되돌릴 수 없어요. 예약은 승인한 뒤 [예약 등록하기]에서 해요.」).
8. 실렌더 확인은 머지 뒤 카리나가 한다(`admin` 유형, `DEV_PROCESS_GUARDRAILS.md` 패턴 13). 클라우드 세션에는 관리자 환경 파일이 없어 PC 세션에서 한다(0710과 같다).
