## 착수 전에 정한 것 (2026-10-02 카리나)

1. 경로는 `/api/cron/ops-reconcile`, 일정은 `*/10 * * * *`다. `/api/cron/reconcile`은 예전 Strava 크론 이름이라 쓰지 않는다(04 112행).
2. 라우트는 GET이다. `CRON_SECRET`이 비었거나 헤더가 `Bearer <값>`과 다르면 401이다(빈 값을 먼저 막는다, P3 20260929_1636의 약점을 새 라우트에 들이지 않는다). `maxDuration = 60`.
   `createServiceClient()`로 `reconcileOpsItems`를 부른다. `RunFailure`면 그 상태 코드와 `{ ok: false, error }`. 성공이면 응답 본문은 개수만 싣는다
   (`{ ok, published, ended, cancelled, failed, externalChanged, errors }`, 항목 ID·사유는 싣지 않는다). `errors > 0`이면 500(Vercel이 실패로 센다, `cron/notifications` 선례), 아니면 200.
   성공(`ReconcileSuccess`)이면 오류가 있어도 `after(() => notifyReconcile(service, result))`로 응답 뒤에 슬랙을 보낸다.
3. 어드민 크론 달력(`cronSchedule.ts`): 분 칸의 `*/N`을 읽어 「N분마다」로 보이고, `CRON_LABELS`에 `/api/cron/ops-reconcile` → 「운영 상태 맞추기」를 더한다. 하루 144번을 달력 칸에 하나씩 찍지 않고
   매시 크론처럼 한 줄로 보인다(지금의 「매시간」 표시 방식을 따른다). 테스트의 경로 수·발생 수 단언을 고친다.
4. 결정 기록 화면(`OpsItemDetail.tsx`):
   - 행위자가 `system:`으로 시작하면 「시스템이 …」로 쓴다(지금은 `token:`이 아니면 모두 「관리자가」).
   - `end` 이름표 「종료했어요」, 사유 이름 「종료 사유」. `external_change` 이름표 「밖에서 바뀐 것을 찾았어요」.
   - `external_change`의 `diff`(⑦-a `ExternalDiff`: `starts_at`·`ends_at`은 `{ item, resource }`, `is_active`는 `{ item: true, resource: false }`)를 줄마다 보인다:
     「공개 시각: <항목> → <자원>」, 「종료 시각: <항목> → <자원>」(KST, `formatKstDayTime`), 「자원이 비활성이에요」.
   - `fail`은 행위자가 시스템이면 「시스템이 실패로 닫았어요」, 그 밖은 지금처럼 「예약 등록에 실패했어요」(앞에 행위자 없음). 사유 줄은 그대로 「실패 사유」.
5. 문서와 메모: 04 스펙의 크론 절(28행 건수, 103–108행 표, 120행, 216행 `CRON_SECRET` 라우트 수), `SERVICE_OPERATIONS.md` 1089–1095행 Cron 표(빠진 external-inputs도 함께),
   운영툴 PRD §11.8(경로·일정·인증·응답, 「구현됨」)과 §13 C행, 티켓 20261001_1154 「주요 의사결정」에 메모 한 줄(매시 점검이 `reconcileOpsItems`를 부르면 DB를 쓴다. 핵심 요약의 「DB는 쓰지 않는다」는 신호 계산에 대한 말로 고쳐 읽는다. 1154 착수 때 정한다).
