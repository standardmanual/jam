# [Admin] 미션 등록 스크립트의 제목 중복 규칙을 운영툴과 같게 기간 겹침으로 바꾼다

> 영향 티켓(상위 20260930_1450 진행 규칙 4). 티켓 20261002_1944(1500 ⑥) 게이트의 범위 밖 발견물 두 건을 합쳤다. 사용자 결정 2026-10-02 「스크립트도 맞추기」.

## 핵심 요약

- 요구사항: ⑥이 운영툴의 미션 「제목 중복」 검사를 「같은 제목의 기존 미션과 기간이 겹칠 때만 막기」로 바꿨다(사용자 결정). 미션 등록 스크립트는 같은 DB 검사 함수를 쓰지만 모드를 고르지 않아
  지금도 같은 제목이 하나라도 있으면 거절한다. 두 경로의 규칙을 하나로 맞춘다(사용자 결정 2026-10-02 「스크립트도 맞추기」).
  함께 고칠 것(민지 [참고]): 모드 값 `titleDuplicate`가 미션 입력 객체 안에 있어, 스크립트가 묶음 JSON의 `mission` 객체를 그대로 넘기면 JSON에 같은 키가 들어갈 때 모드가 바뀔 수 있다.
  모드를 미션 객체 밖의 별도 인자로 옮기거나, 규칙이 하나로 통일되면 모드 자체를 없앤다.
- 관련 파일:
  - `jam-web/src/lib/admin/registerChecks/mission.ts`: 머리 주석 4행, 입력 칸 15–25행(`starts_at`·`ends_at`·`titleDuplicate?: 'any' | 'overlap'`), 분기 65행, `missionPeriodsOverlap`.
  - `jam-web/scripts/asset-generator/registerMissionFlow.mjs`: 래퍼 `runMissionDbChecks` 68–69행, 호출 260행(`mission: bundle.mission`).
  - 운영툴 쪽 호출: `jam-web/src/lib/admin/opsInbox/execute/mission.ts`(⑥, `titleDuplicate: 'overlap'`).
  - 테스트: `jam-web/src/lib/admin/registerChecks/__tests__/registerChecks.test.ts`(모드별 경계), 스크립트 테스트(있으면).
  - 문서: `docs/service/prd/asset-generator/MISSION_REGISTRATION_BUNDLE.md` 154행(제목 중복 문장 「기존 미션 갱신은 이 스크립트 범위 밖이라 중복으로 거절해요」)과 모드 설명 문장, 운영툴 PRD §8.1·§8.2의 「스크립트는 기존 동작」 문장.

## 착수 전에 정한 것 (2026-10-02 카리나)

1. **모드를 없앤다.** 규칙이 하나(기간 [공개, 종료)이 겹칠 때만 제목 중복)로 통일되므로 `MissionDbCheckInput.titleDuplicate`와 `'any'` 분기를 지운다. `runMissionDbChecks`의 「제목 중복」은 늘 같은 제목의 기존 미션을
   모두 읽어(`id, starts_at, ends_at`) `missionPeriodsOverlap`으로 견준다. 모드 값이 미션 객체 안에 있던 문제(민지 [참고])는 칸이 사라져 함께 풀린다. 묶음 JSON의 `mission`에 `titleDuplicate` 같은 키가 있어도
   함수가 읽지 않는다(테스트로 고정).
2. 스크립트(`registerMissionFlow.mjs`)는 바꾸지 않는다. 이미 `bundle.mission`(필수 칸 `starts_at`, 선택 칸 `ends_at`)을 그대로 넘긴다. 문장은 운영툴과 같은 「같은 제목의 미션이 이미 있고 기간이 겹쳐요(id: …)」가 된다.
   운영툴 핸들러(`execute/mission.ts` 107행)는 `titleDuplicate: 'overlap'` 인자만 뺀다(사유 고정 문장은 그대로).
3. 시각을 읽을 수 없으면 겹친 것으로 보는 기존 안전 규칙(`missionPeriodsOverlap`)은 그대로다. 공개 시각이 없는 입력도 같은 제목이 있으면 막힌다.

## 구현 계획 (파일 단위)

1. `jam-web/src/lib/admin/registerChecks/mission.ts`: 머리 주석 4행, `MissionDbCheckInput`의 `starts_at`·`ends_at` 주석(15–18행)과 `titleDuplicate` 칸(19–25행) 삭제, 「제목 중복」 분기(65–83행)를 겹침 판정 하나로.

3. 테스트: `jam-web/src/lib/admin/registerChecks/__tests__/registerChecks.test.ts`(175행의 옛 문장 기대값, 202–281행 「기간이 겹칠 때만」 묶음에서 모드 인자 삭제, 278–281행 「고르지 않으면 지금까지처럼」을
