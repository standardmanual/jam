# [API] 운영툴 패턴 사전 ⑤ 결정 기록 읽기 API와 패턴별 결정 집계

> 상위: 20260930_1503 · 하위 순서 ⑤ · 선행: ② 20261001_2134(CLOSED). ⑫ S6 화면과 1504 월간 루틴(학습 재료)이 쓴다.

## 핵심 요약

- 요구사항: 에이전트와 ⑫ 화면이 결정 기록을 읽는 `GET /api/admin/ops-decisions`를 만든다. 기본 기간 최근 4주, 쪽당 200건, 수정 전후 차이(`diff`)를 싣고
  제출 원본(`raw`)·슬랙 결과는 싣지 않는다. 같은 기간의 패턴별 결정 집계 `byPattern`을 함께 돌려준다. 시험 묶음은 항상 빼고, `actor` 원문(관리자 ID)은 select
  목록에서부터 빼 행위자 종류만 싣는다.
- 구현 계획: 아래 「구현 계획」 절. DB 변경 없음(`ops_decisions`, 마이그레이션 198).
- 관련 파일: `jam-web/src/lib/admin/opsPatterns/read.ts`·`jam-web/src/app/api/admin/ops-patterns/route.ts`(그대로 따를 구조, 인증 `requireAdminRead`),
  `jam-web/supabase/migrations/198_ops_inbox.sql`(칸), `jam-web/src/lib/db/fetchAllRows.ts`, `docs/specs/prd/ops-tool/PRD.md` §11·§13.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- `jam-web/src/lib/admin/opsDecisions/read.ts`: 쿼리 읽기(기간 기본 4주·92일 상한·패턴 번호·행동·커서), 결정 기록 조회(항목·묶음 inner join, 시험 묶음 제외, 최신순 커서 쪽 나누기), 패턴별 집계(쪽이 아니라 기간 전체).
  `actor` 원문은 `actorType`·`agentName`으로만 바꿔 싣고 `raw`·`slack_result`는 읽는 칸에 넣지 않는다. 커서는 정규식·UUID 검사로 `or` 필터 주입을 막는다.
- `GET /api/admin/ops-decisions`: `requireAdminRead`(읽기 토큰은 GET 전용, 아니면 관리자 세션), 쿼리 오류 400, 실패 500 고정 문장, 시험 묶음 스위치는 받지 않는다.
