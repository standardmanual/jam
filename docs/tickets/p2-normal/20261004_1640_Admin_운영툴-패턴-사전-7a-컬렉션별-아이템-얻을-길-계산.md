# [Admin] 운영툴 패턴 사전 ⑦a 컬렉션별 아이템 얻을 길 계산(순수 함수)

> 상위: 20260930_1503 · 하위 순서 ⑦을 ⑦a(이 티켓, 계산)와 ⑦b 20261004_1641(읽기 API·문서)로 나눴다(2026-10-04 규모 판정, 합치면 8파일·약 960줄).
> ⑧(「획득 경로가 막힌 컬렉션」 신호)이 이 함수를 DB 없이 그대로 쓴다.

## 핵심 요약

- 요구사항: 이미 읽어 온 컬렉션·아이템·레시피·미션 행과 기준 시각을 받아, 아이템마다 드랍·믹스·미션 세 길이 열려 있는지 계산하는 순수 함수를 만든다(1503 Q5).
  판정은 기존 함수만 다시 쓴다: 컬렉션 노출 `isItemBookDroppable`, 레시피 공개 `isRecipeReleased`, 미션 `isMissionActive`·`isMissionExposed`. 아이템 상태는
  「열림 / 막힘 / 드랍 제외」 셋 중 하나다.
- 구현 계획: 아래 「구현 계획」 절. DB 변경 없음, DB 읽기 없음.
- 관련 파일: `jam-web/src/lib/itembook/visibility.ts`, `jam-web/src/lib/drop-engine/index.ts`(`fetchDropStructure` 조건), `jam-web/src/lib/combine/visibility.ts`,
  `jam-web/src/lib/missions/visibility.ts`, `jam-web/src/lib/ambient-drop/index.ts` 200~225행(앰비언트 드랍 조건 대조).

> 2026-10-04 카리나 규모 사전 판정: 3파일·약 510줄(테스트 260줄). 파일 단위 계획이 있고 사용자가 진행을 지시해 계획 반환을 면제한다.

판정 규칙:
- 드랍 길: `fetchDropStructure`와 같은 조건(컬렉션 노출 중·`drop_excluded` 아님, 아이템 삭제 안 됨·`drop_excluded` 아님·유효기간 안). 활동 드랍 또는 앰비언트 드랍으로 보고
  누적 조건은 보지 않는다.
- 믹스 길: 공개된 레시피의 `reward_badge_ids`에 그 아이템이 있다. 미션 길: 진행 중이고 노출된 미션의 `reward_badge_ids`에 있다. 어드민 직접 지급·컬렉션 완성 보상은 세지 않는다.
- 세 길이 모두 닫히면 「막힘」. 컬렉션 또는 아이템이 `drop_excluded`이고 다른 길이 없으면 「드랍 제외」로 따로 둔다.
- 경계: 레시피 종료 시각은 빼고(`<`), 컬렉션 종료는 포함한다(`<=`) — 기존 함수를 그대로 써서 맞춘다.

테스트: 노출 중이 아닌 컬렉션(비활성·공개 전·기간 끝) → 드랍 닫힘 / `drop_excluded` → 「드랍 제외」 / 아이템 유효기간 밖 → 드랍 닫힘 / 레시피 공개 예정·종료 → 믹스 닫힘 /
레시피 종료 시각 정각 → 닫힘 / 미션 `hidden`·종료·시작 전 → 닫힘 / 상시 미션(`ends_at` null) → 열림 / 세 길 모두 닫힘 → 「막힘」 / 여러 레시피·미션 ID 중복 없음.
