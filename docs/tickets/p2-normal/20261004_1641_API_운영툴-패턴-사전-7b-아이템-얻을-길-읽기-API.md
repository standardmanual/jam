# [API] 운영툴 패턴 사전 ⑦b 아이템 얻을 길 읽기 API(`GET /api/admin/item-paths`)

> 상위: 20260930_1503 · 하위 순서 ⑦b · 선행: ⑦a 20261004_1640(계산 함수). ⑬ S6 화면과 에이전트가 쓴다.

## 핵심 요약

- 요구사항: `requireAdminRead`(관리자 세션 또는 토큰 GET, 쓰기 메서드 없음)로 인증하는 `GET /api/admin/item-paths`를 만든다. 요청 때 ⑦a `computeItemPaths`로
  계산하고 저장하지 않으며, 결과를 컬렉션 단위로 쪽을 나눠 돌려준다(`limit`/`offset`, `onlyBlocked`). 원천 하나라도 읽기에 실패하면 500(조용히 「막힘」으로 바뀌지 않게).
- 구현 계획: 아래 「구현 계획」 절. DB 변경 없음.
- 관련 파일: `jam-web/src/app/api/admin/ops-patterns/route.ts`(구조), `jam-web/src/lib/db/fetchAllRows.ts`(1,000행 넘는 쪽 읽기 — 활동 아이템 3,600개 이상),
  `docs/service/prd/ops-tool/PRD.md` §11, `docs/service/badge-engine/BADGE_ENGINE_UNIFIED.md` §3.12.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- `GET /api/admin/item-paths`(`requireAdminRead`, 세션 또는 읽기 토큰 GET, 라우트는 GET만 내보낸다). 요청 때 `loadItemPathInputs`로 읽어 ⑦a `computeItemPaths`로 계산하고 저장하지 않는다.
  `compute.ts`는 이 서버 라우트에서만 부른다.
- 읽기(`lib/admin/itemPaths/load.ts`): 공개된 컬렉션 전부(`applyLaunchedItemBookFilter`, 기간 끝 포함, 비활성·공개 전 제외), 그 소속 삭제 안 된 아이템 배지(`fetchAllRowsIn`), 레시피·미션 전부를
  `fetchAllRows`로 끝까지 읽는다. 표 하나라도 실패하면 부분 결과 없이 던지고 라우트가 고정 문장 500으로 받는다.
- 쿼리: `limit`(1~50, 기본 10, 컬렉션 수 기준)·`offset`·`onlyBlocked=true`(막힘 아이템이 있는 컬렉션만, 그 안에서도 막힘 아이템만, 개수 칸은 컬렉션 전체 기준). 형식·범위 오류는 읽기 전 400.
  응답 `{ now, total, limit, offset, nextOffset, collections }`, 관리자 ID 없음.
- 문서: 운영툴 PRD §11 도입 문장과 새 §11.11(경로·인증·읽는 범위·쿼리·응답·사유 값·「드랍 제외」와 막힘의 구분·오류), 엔진 문서 §3.12 한 줄.
