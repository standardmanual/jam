# [API] 공개 전 컬렉션이 로그인 유저의 직접 조회에 보인다

> 발견: 1500 ⑩ 시작 검토(2026-10-04 카리나, Explore 코드 지도와 라이브 DB 읽기 전용 조회). 1500의 영향 티켓 E4다(상위 1450 진행 규칙 4).
> 사용자 결정(2026-10-04 「둘 다 영향 티켓」): 첫 실제 컬렉션 예약(1500 ⑩ 사용자 확인 지점) 전에 고친다. 마이그레이션 실행은 파일명·영향 범위·되돌림 SQL 위치를 보인 뒤 다시 승인받는다.
> 선례: 20261002_1257(공개 전 홈피드 카드, 마이그레이션 214 `ALTER POLICY`).

## 핵심 요약

- 현상(확인한 사실):
  - `item_books`의 SELECT 정책은 「item_books: 전체 읽기 허용」(`FOR SELECT TO authenticated USING (TRUE)`) 하나다. 근거는 `jam-web/supabase/migrations/001_initial_schema.sql` 188–193행이고, 2026-10-04 `pg_policies` 조회 결과도 `qual = true`로 같다.
    그 뒤로 이 정책을 고친 마이그레이션은 없다. `anon`은 정책이 없어 읽지 못하고, 쓰기 정책은 없다.
  - 로그인 유저는 공개 키와 자기 세션으로 PostgREST를 직접 불러 공개 전(`valid_from`이 미래)·비활성 컬렉션의 이름·설명·`story_text`·이미지 주소·보상 포인트·보상 배지 ID를 읽을 수 있다.
  - 앱 화면과 API는 막혀 있다. 사용자 세션 클라이언트로 `item_books`를 읽는 곳은 모두 앱에서 공개 판정(`jam-web/src/lib/itembook/visibility.ts` `isItemBookLaunched`·`pickLaunchedItemBook`·`applyLaunchedItemBookFilter`)을 다시 한다:
    `app/(main)/collections/[id]/page.tsx` 56·87–98행, `app/api/itembooks/route.ts` 18·62–65행, `app/(main)/badges/page.tsx` 29·123–126행, `app/(main)/badges/[id]/page.tsx` 51·234–242행(2026-10-04 Explore).
- 영향: 운영툴 자원 연결(1500 ⑩-a, 티켓 20261004_2039)이 공개 전 컬렉션을 예약으로 만든다. 컬렉션 런칭의 이름·이야기·보상이 공개 전에 새어 나갈 수 있다. 지금 기존 어드민으로 만드는 비활성·미래 컬렉션도 같은 상태다.
- 구현 계획(안): 정책 조건을 앱의 공개 판정과 같게 바꾼다: `is_active = TRUE AND (valid_from IS NULL OR valid_from <= now())`. 종료(`valid_until`)는 넣지 않는다(종료된 컬렉션은 보유자에게 계속 보인다. `isItemBookLaunched`도 종료를 보지 않는다).
  컬럼·함수 변경이 없는 정책 교체라 확장→전환→축소로 나누지 않는다(214와 같다). 적용은 `ALTER POLICY ... USING (...)` 형태다(214 적용 때 도구 시간 초과로 바꾼 형태).
- 관련 파일: 새 `jam-web/supabase/migrations/215_item_books_select_launched.sql`(번호는 착수 때 확인. 212는 1503 ③ 시드가 예약했다), `docs/specs/prd/02_DATA_MODEL.md`의 `item_books` 절, 선례 `jam-web/supabase/migrations/214_today_cards_select_period.sql`.

## 착수 때 확인할 것

1. 사용자 세션 클라이언트의 **임베드 조회**(`badges` 등을 읽으며 `item_books(...)`를 함께 가져오는 select)가 있는지 `jam-web/src`를 grep한다. 있으면 정책 뒤 그 칸이 NULL이 되는 화면이 공개 판정과 같은 결과인지(지금도 공개 전·비활성은 숨기는지) 확인한다.
2. `item_books`를 읽는 뷰·구체화 뷰·함수, Realtime 발행(`pg_publication_tables`)이 있는지 라이브 DB에서 읽기 전용으로 확인한다(1257과 같은 절차). `SECURITY DEFINER` RPC(`slot_item_into_book` 등)는 정책을 거치지 않으므로 영향이 없다.
3. 테이블 권한(`anon`·`authenticated`)이 Supabase 기본값인지 확인한다.

## 착수 때 확인한 결과 (2026-10-05 카리나, Explore 코드 지도 + 라이브 DB 읽기 전용 조회, 기준 커밋 145060a)

1. **임베드 조회는 `jam-web/src`에 없다.** `item_books(`·`item_book:`·`item_books!`와 `item_books`를 가리키는 외래 키를 가진 6개 테이블의 select 문자열을 찾았다. `lib/notifications/batch/following.ts` 373행은 임베드가 아니라 로그 라벨이다(실제 조회는 376행 service).
   사용자 세션 클라이언트로 `item_books`를 읽는 곳은 핵심 요약의 4곳뿐이고 모두 지금도 앱 공개 판정으로 거른다:
   `app/(main)/collections/[id]/page.tsx` 87–98(98행 `isItemBookLaunched`가 거짓이면 `notFound()`), `app/(main)/badges/[id]/page.tsx` 234–242(`pickLaunchedItemBook`), `app/(main)/badges/page.tsx` 123–126·`app/api/itembooks/route.ts` 62–65(`applyLaunchedItemBookFilter`).
   관리자 화면(`app/admin/**`)·관리자 API(`app/api/admin/**`)·유저 프로필(`app/(main)/[username]/**`)·슬롯 API(`app/api/itembooks/[id]/slot`)·`lib/` 아래 조회는 모두 service 클라이언트다
   (`app/admin/layout.tsx` 21·`lib/admin/auth.ts` 45의 사용자 세션은 로그인 확인에만 쓴다). 브라우저 클라이언트와 미들웨어는 `item_books`를 읽지 않는다. 그래서 정책 뒤 화면·응답 결과는 바뀌지 않는다.
   부수 효과 하나: 비활성·공개 전 컬렉션 주소로 `/collections/[id]`에 들어오면 91행 `.single()`이 0행 오류(PGRST116)를 내 93행 `console.error`가 찍힌 뒤 같은 404가 된다. 이 티켓에서 `.maybeSingle()`로 바꿔 로그 잡음을 막는다(카리나 결정, 아래 구현 계획 3).
2. **라이브 DB(2026-10-05):** `item_books`를 읽는 뷰·구체화 뷰 없음, Realtime 발행 없음, 읽는 함수는 `slot_item_into_book`(`SECURITY DEFINER`) 하나. 정책은 「item_books: 전체 읽기 허용」(`authenticated`, `qual = true`) 하나이고 RLS가 켜져 있다.
   관리자 예외용 SQL 함수(`is_admin()` 등)는 없다(214도 관리자 예외를 두지 않았다).
3. **테이블 권한:** `anon`·`authenticated` 모두 SELECT·INSERT·UPDATE·DELETE·TRUNCATE·REFERENCES·TRIGGER(Supabase 기본값). 실제 제한은 RLS다(`anon` SELECT 정책 없음, 쓰기 정책 없음).
- 숨겨질 행(2026-10-05): 컬렉션 100개 중 70개(모두 비활성, 공개 전 0개). 이 70개에는 유저 슬롯·완성 기록·삭제되지 않은 아이템 배지가 하나도 없다.

## 구현 계획 (파일 단위)

1. **새 마이그레이션 파일 `jam-web/supabase/migrations/215_item_books_select_launched.sql`**(번호 215는 2026-10-05 비어 있음을 확인). 214의 형식을 따른다: 머리 주석(티켓·「작성만 하고 실행하지 않았다」 경고·이유·변경·001 주석과의 관계·영향:
   위 「착수 때 확인한 결과」 1~3과 숨겨질 행 수, 재실행 가능), `BEGIN; ALTER POLICY "item_books: 전체 읽기 허용" ON public.item_books USING (is_active = TRUE AND (valid_from IS NULL OR valid_from <= now())); COMMIT;`,
   파일 끝 `-- 되돌림 SQL` 주석 블록(원래 `USING (TRUE)`, `db-migration-rules.md` §4 형식). 정책 이름은 그대로 둔다(이름의 「전체」가 낡게 되는 사실은 머리 주석에 적는다. 이름을 바꾸면 `ALTER POLICY ... RENAME`이 한 문장 더 들어간다).
2. **`docs/specs/prd/02_DATA_MODEL.md` `item_books` 절(236행 부근).** RLS 서술을 더한다: 인증 유저 SELECT는 활성이고 공개 시각이 지났거나 비어 있는 행만(마이그레이션 215, 앱 공개 판정 `isItemBookLaunched`와 같은 조건, 종료 시각은 보지 않음), `anon` 읽기·쓰기 정책 없음, 앱의 관리자·서버 조회는 service 클라이언트.
3. **`jam-web/src/app/(main)/collections/[id]/page.tsx` 91행 `.single()` → `.maybeSingle()`.** 0행일 때 오류 로그 없이 94행 `!bookRaw` 분기로 같은 404가 된다(존재하지 않는 ID도 같다). 다른 코드는 바꾸지 않는다.
4. 규칙 5(환경 서술)에 따라 새 사실 서술에 대응하는 검사 줄이 필요하면 `docs/agents/contract.json`에 더한다.
