## 착수 전에 정한 것 (2026-10-04. 1은 사용자 결정, 나머지는 카리나 가정으로 사용자에게 보였고 이의 없음)

1. **건너뛰는 범위는 연결로 채운 컬렉션 모두다(사용자 결정 「연결 컬렉션 모두」).** 같은 실행에서 만들 컬렉션과 이전 실행이 만든 컬렉션(`created_resource`에서 읽은 ID)을 가리지 않는다.
   이전 실행이 만든 컬렉션도 아이템을 공개 전에 채우므로(1500 Q4) 비어 있을 수 있다. 그래서 드랍 핸들러는 `prepared.linkedIds.collection_ids`를 그대로 미룰 ID로 쓴다. `run.ts`·`handlers.ts`는 고치지 않는다.
   PRD §8.4의 「같은 실행에서 만들」 문구는 카리나가 이 결정으로 고쳤다.
2. **건너뛰는 것은 연결로 채운 컬렉션의 판정뿐이다.** `resource`에 직접 적은 컬렉션, 지점 쪽 판정(지점 없음·운영 종료, `no_eligible_poi`), 형식 검사(파서), 지점 종류 확인은 지금처럼 한다.
3. **대상이 미룬 컬렉션뿐이어도 막지 않는다.** 미룬 컬렉션이 하나라도 있으면 「노출 중인 컬렉션이 없어요」(`no_eligible_collection`)와 「놓을 수 있는 아이템이 없어요」(`no_candidate_badges`)를 내지 않는다
   (후보 풀이 예정 시각에 미룬 컬렉션에서 생길 수 있다). 직접 적은 컬렉션이 노출 중이 아니면 지금처럼 「놓을 수 없는 대상이 있어요」로 막는다. 미룬 ID를 빼서 남은 목록이 비면 아이템 쪽 조회를 하지 않는다
   (빈 목록을 넘기면 「전체」로 해석되는 함정). ID는 소문자로 견준다(파서가 소문자화한다).
4. **구현 자리는 선택 인자다.** `loadScheduleTargets(supabase, spec, atIso, options = {})`의 `options.deferredCollectionIds`(이름은 아현이 정해도 된다)와
   `createAmbientDropSchedule`의 다섯 번째 인자 `options`에 같은 칸을 더한다. 넘기지 않으면 지금과 똑같다. 어드민 만들기·시각 수정(`rescheduleAmbientDrop`)·미리보기와 드랍 실행기는 넘기지 않으므로 바뀌지 않는다.
   그래서 운영툴이 만든, 빈 컬렉션을 가리키는 드랍은 아이템을 채우기 전까지 어드민 시각 수정이 거절된다(바꾸지 않고 PRD에 적는다). 저장되는 `collection_ids`는 미룬 ID를 포함한 전체다.
   `run.test.ts`는 `loadScheduleTargets` 하나만 mock하므로 새 export 함수를 만들어 거치지 않는다(가짜 DB가 받지 않는 질의로 깨진다).
5. **사전 점검에 드랍 → 컬렉션 공개 순서 규칙을 더한다.** `DROP_COLLECTION_FIELDS = ['collection_ids']`로 `opensBeforeLinked`를 부른다. 비교 조건은 기존 규칙과 같다(같은 시각 통과, 예약된 대상은 그 공개 시각과 견줌,
   게재 중·종료된 대상과 읽을 수 없는 시각·`resource`에 직접 적은 ID는 견주지 않음. 연결 대상이 여럿이면 하나라도 늦게 열리면 막는다). 사유는 같은 문장 「연결된 컬렉션보다 먼저 공개돼요」를 다시 쓰고,
   키 `cardBeforeCollection`은 `beforeLinkedCollection`으로 이름을 바꾼다(참조처는 `precheck.ts`와 테스트뿐, 2026-10-04 grep).
6. **「아이템이 없는 컬렉션」 신호.** 대상은 `kind = 'collection_launch'`이고 상태가 `scheduled`·`live`이며 `created_resource.item_book_id`가 문자열인 항목이다(준비중·승인 전·시험 묶음은 자원이 없거나 곧 바뀌어 뺀다).
   그 컬렉션의 아이템 배지(`badges.item_book_id`, `type = 'item'`, `deleted_at is null`, 드랍 대상과 같은 기준)가 0개이면 「비어 있는 컨텐츠」 결과에 한 건을 더한다. **검사 날짜와 무관하게 본다**(날짜 구성은 종료 시각이 없는
   컬렉션을 공개한 날 하루에만 걸쳐 먼 미래·이미 공개된 컬렉션을 놓친다). 결과의 날짜는 항목 공개 시각의 KST 날짜, 수준은 「비어 있는 컨텐츠」 그대로 주의다.
   문장(안): 예약됨 「{공개 시각}에 공개할 {항목 이름}에 아이템이 없어요. 공개 전에 기존 어드민에서 아이템 배지를 채워 주세요.」, 게재중 「게재 중인 {항목 이름}에 아이템이 없어요.」(`itemName`·`formatKstDayTime` 보조 함수의 형태에 맞춰 다듬는다. 자원 ID는 문장에 넣지 않는다).
7. **신호 데이터.** `load.ts`가 항목의 `created_resource`를 읽고(`ITEM_COLUMNS`), 대상 컬렉션 ID가 있을 때만 `badges`에서 `item_book_id`를 페이징으로 읽어 컬렉션별 수를 센다(ID가 없으면 조회하지 않는다). 새 원천 이름을 `OpsSignalSource`에 더한다.
   이 원천을 읽지 못하면 「비어 있는 컨텐츠」 전체를 「확인하지 못했어요」(`load_failed`)로 둔다(그 데이터에 기대는 신호만 확인하지 못함, PRD §5). 계산 입력 칸은 선택(`?`)으로 두어 기존 계산 테스트 입력이 그대로 통과하게 하고,
   칸이 없으면(넘기지 않음) 컬렉션 검사를 하지 않는다. `loadOpsSignals`는 늘 채운다.
8. **바꾸지 않는 것.** 실행(`run.ts`)·핸들러 계약·드랍 실행기·상태 맞추기·어드민 드랍 화면과 API, 날짜 구성(`buildDayCompositions`)과 기존 「비어 있는 컨텐츠」 판정. DB 변경 없음.
