# [API] 공개 전 배지가 로그인 유저의 직접 조회에 보인다

> 발견: 티켓 20261004_2041(E4, 공개 전 컬렉션 직접 조회) 게이트의 민지 범위 밖 발견물([보안/참고]). 카리나가 라이브 DB로 확인하고 P2로 올렸다(E4·20261002_1257과 같은 종류의 누출이고,
> 운영툴이 공개 전 배지를 만들기 시작하면 실제로 새기 때문이다). 1500의 영향 티켓 E6이다(상위 1450 진행 규칙 4). 첫 실제 JAM! 배지·컬렉션 예약 전에 고친다.

## 핵심 요약

- 현상(확인한 사실, 2026-10-05):
  - `badges`의 SELECT 정책은 「badges: 전체 읽기 허용」(`FOR SELECT TO authenticated USING (TRUE)`) 하나다. 근거는 `jam-web/supabase/migrations/001_initial_schema.sql` 99–103행이고, 2026-10-05 `pg_policies` 조회 결과도 `qual = true`로 같다.
  - 그래서 로그인 유저는 공개 키와 자기 세션으로 PostgREST를 직접 불러 공개 전(`valid_from`이 미래) 배지와, 비활성·공개 전 컬렉션 소속 아이템 배지의 이름·설명·이미지 주소·조건을 읽을 수 있다.
  - 2026-10-05 라이브 DB에는 공개 전 배지가 0개, 비활성 컬렉션 소속 아이템 배지가 0개라 지금 새는 행은 없다.
- 영향: 운영툴 자원 연결이 공개 전 JAM! 배지(1500 ⑨-a, 티켓 20261004_1756)와 공개 전 컬렉션(⑩-a)을 예약으로 만들고, 컬렉션의 아이템 배지는 공개 전에 기존 어드민에서 채운다(1500 Q4).
  E4(마이그레이션 215)로 컬렉션 행은 숨겨지지만 그 아이템 배지와 공개 전 JAM! 배지는 이 정책 때문에 여전히 보인다.
- 구현 계획(안, 착수 때 확정): E4·1257과 같은 `ALTER POLICY`로 공개 조건을 더한다. 조건 후보는 「삭제되지 않음·공개 시각이 지났거나 비어 있음·소속 컬렉션이 있으면 그 컬렉션이 공개됨」이다.
  배지는 사용자 세션으로 읽는 곳이 컬렉션보다 많을 수 있으므로(배지 목록·상세·프로필·획득 기록 임베드 등) 착수 때 E4와 같은 절차로 조회 지도를 먼저 만든다.
  종료(`valid_until`)는 넣지 않는다(이미 받은 배지는 계속 보여야 한다).
- 관련 파일: `jam-web/supabase/migrations/001_initial_schema.sql` 99–103, 선례 `215_item_books_select_launched.sql`(E4)·`214_today_cards_select_period.sql`(1257), 앱 공개 판정(배지의 `valid_from` 판정 위치는 착수 때 찾는다), `docs/specs/prd/02_DATA_MODEL.md`의 `badges` 절.

## 착수 때 확인할 것

1. 사용자 세션 클라이언트로 `badges`를 읽는 곳과 `badges(...)` 임베드 조회(획득 기록·슬롯·레시피·카드 등)를 모두 찾고, 정책 뒤 화면 결과가 바뀌는지 본다(E4 「착수 때 확인한 결과」와 같은 표).
2. `badges`를 읽는 뷰·구체화 뷰·함수, Realtime 발행, 다른 테이블 정책의 서브쿼리를 라이브 DB에서 읽기 전용으로 확인한다.
3. 소프트 삭제(`deleted_at`) 배지를 유저가 이미 가진 경우의 화면 기대 동작(지금 앱이 어떻게 보이는지)을 확인하고 정책 조건에 넣을지 정한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 마이그레이션 파일이 정책 교체와 되돌림 SQL 주석 블록을 담고, `scripts/deploy-gate.mjs check`를 통과한다. `scripts/verify.sh` 전 항목 통과.
- 착수 때 확인한 것 1~3의 결과가 티켓에 적혀 있고, 사용자 세션 조회의 화면 결과가 바뀌지 않는다는 근거(파일·줄)가 있다. 바뀌는 곳이 있으면 같은 티켓에서 고친다.
- `02_DATA_MODEL.md`가 새 정책을 서술한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤 사용자 재승인)
- `apply_migration`으로 적용하고, `pg_policies`의 `qual`과 로그인 유저 역할 조회에서 공개 전 배지·공개 전 컬렉션 소속 배지가 0행인지 확인한다.
