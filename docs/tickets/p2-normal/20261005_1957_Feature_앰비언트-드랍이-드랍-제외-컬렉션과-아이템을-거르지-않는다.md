# [Feature] 앰비언트 드랍이 드랍 제외(`drop_excluded`) 컬렉션과 아이템을 거르지 않는다

> 티켓 20261004_1640(1503 ⑦a) 게이트 범위 밖 발견물 [정확성/주의](민지, 2026-10-05, 확신도 높음). ⑦a 티켓 잔여 이슈에서 예고한 차이를 grep으로 확인했다.

## 핵심 요약

- 요구사항: 활동 드랍(`fetchDropStructure`, `jam-web/src/lib/drop-engine/index.ts` 184~261행)은 `drop_excluded`인 컬렉션·아이템을 후보에서 빼는데, 앰비언트 드랍은 컬렉션에
  `applyDroppableItemBookFilter`만, 아이템 배지에 `type`·`deleted_at`·`item_book_id`·유효기간만 건다(`jam-web/src/lib/ambient-drop/index.ts` 103~105행, 193~207행). 그래서 드랍 제외로 표시한
  컬렉션·아이템도 앰비언트로는 놓일 수 있다. ⑦a(`lib/admin/itemPaths/compute.ts`)는 `fetchDropStructure`를 따라 이 아이템의 드랍 길을 「드랍 제외」 또는 「막힘」으로 내므로, 운영툴이 보여 주는 얻을 길과
  실제가 어긋난다. 먼저 「드랍 제외」가 앰비언트 드랍에도 적용돼야 하는지(의도) 정하고, 앰비언트 쪽을 맞추거나 ⑦a의 드랍 길 정의를 고친다.
- 구현 계획: 아래 「구현 계획」(2026-10-06 사용자 결정 A 반영). 이전 메모: 착수 때 정한다. 사용자 확인 질문 하나(드랍 제외가 앰비언트에도 적용되는가)가 먼저다. 적용된다면 앰비언트 조회 두 곳에 `drop_excluded` 조건을 더하고 테스트를 붙인다.
  적용되지 않는다면 ⑦a의 드랍 길을 「활동 드랍」과 「앰비언트 드랍」으로 나눠 판정한다(⑦b·⑬ 화면 문구에 영향).
- 관련 파일: `jam-web/src/lib/ambient-drop/index.ts`(103~105행 컬렉션 조회, 193~207행 아이템 배지 조회), `jam-web/src/lib/drop-engine/index.ts`(`fetchDropStructure` 184~261행),
  `jam-web/src/lib/admin/itemPaths/compute.ts`(드랍 길 판정), `docs/service/badge-engine/BADGE_ENGINE_UNIFIED.md`(드랍 제외 서술), `docs/service/prd/ops-tool/PRD.md` §11.11(⑦b가 쓴다)

## 결정 (2026-10-06, 사용자)

- **드랍 제외를 앰비언트 드랍에도 적용한다(A, 추천안).** 근거: 드랍 제외를 만든 의도가 「드랍 후보에서만 뺀다」였고(티켓 20260911_2220), 완성 분모에서 드랍 제외 배지를 빼는 결정(마이그레이션 178,
  2026-09-21)과도 맞는다. ⑦a(`lib/admin/itemPaths/compute.ts`)는 이미 이 기준이라 고치지 않고, ⑦b(20261004_1641)는 계획대로 진행한다.
- 적용 범위: 무작위 앰비언트(컬렉션 조회 `ambient-drop/index.ts` 103–105행, 아이템 배지 조회 193–207행)와 운영자가 지정한 예약·지금 배포(`ambient-drop/scheduleTargets.ts` 대상 판정)
  모두. 지정한 아이템·컬렉션이 드랍 제외면 등록 판정이 「드랍 제외 아이템이에요」 같은 이유로 막는다. 특별히 드랍하려면 운영자가 드랍 제외 표시를 먼저 끈다.
- 거절한 안: B(무작위에만 적용, 지정 예약은 허용 — 얻을 길이 세 갈래가 되어 ⑦a 수정 필요), C(앰비언트에는 적용 안 함 — ⑦a 길 분리와 완성 분모 이유 재정의 필요).

## 완료 조건

- 드랍 제외 컬렉션과 드랍 제외 아이템이 앰비언트 무작위 배포의 후보에서 빠진다(테스트).
- 예약 드랍·지금 배포에서 드랍 제외 아이템이나 컬렉션을 지정하면 등록 판정이 「드랍 제외 아이템」·「드랍 제외 컬렉션」 사유로 제외하고, 컬렉션 지정 모드의 후보 풀에서도 드랍 제외 아이템이 빠진다(테스트).
- 엔진 문서에 「드랍 제외는 활동 드랍과 앰비언트 드랍 모두에 적용」이 적혀 있고, ⑦a(`lib/admin/itemPaths/compute.ts`)의 드랍 길 판정과 같은 기준이다(⑦a 변경 없음).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- 원인: 앰비언트 드랍이 컬렉션에는 노출 판정(`applyDroppableItemBookFilter`)만, 아이템 배지에는 type·deleted_at·item_book_id·유효기간만 걸어 `drop_excluded`를 보지 않았다.
- 정기·즉시 배포(`runAmbientDropBatch`): 컬렉션 조회와 아이템 배지 조회에 `drop_excluded = false`(활동 드랍과 같은 조건). 공용 노출 필터는 완성 판정(`checker.ts`·`completable.ts`)도 쓰므로 건드리지 않았다.
- 지정 배포·예약(`loadScheduleTargets`): 사유 `badge_drop_excluded`(「드랍 제외 아이템」)·`collection_drop_excluded`(「드랍 제외 컬렉션」) 추가. 아이템 지정은 아이템 또는 소속 컬렉션이 제외면 걸리고,
  컬렉션 지정은 제외 컬렉션을 거르고 후보 풀에서 제외 아이템을 뺀다(남는 후보가 없으면 `no_candidate_badges`). 등록·시각 수정·미리보기·지금 배포·예약 실행이 모두 이 함수를 쓴다. ⑦a 변경 없음.
- 문서: `BADGE_ENGINE_UNIFIED.md` §3.12(예약 노출 판정·축 3 문단과 표·새 단락 「드랍 제외는 활동 드랍과 앰비언트 드랍 모두에 적용」·배치 로직 3단계·스킵 사유), §3.16 한 줄.
