# [Admin] 배지 수정 폼이 연결 지점을 못 불러온 채 저장하면 지점 연결이 지워진다

## 핵심 요약

- 요구사항: 체크인 배지 수정 폼이 연결 지점 목록을 불러오기 전(또는 불러오지 못한 상태)에 저장해도 기존 지점 연결이 지워지지 않게 한다.
- 구현 계획: 불러오기가 끝났는지를 상태로 들고, 끝나기 전에는 저장 버튼을 막거나 `poi-links` PUT을 보내지 않는다. 최초 1회 가드(`poiLinksLoadedRef`)가 개발 모드의
  이중 실행(React StrictMode)에서 두 번째 실행을 막아 결과가 버려지는 문제도 함께 고친다.
- 관련 파일: `jam-web/src/app/admin/badges/BadgeForm.tsx`(연결 지점 상태 237–243, 최초 불러오기 `useEffect` 245–263, 저장 뒤 `poi-links` PUT 505–516),
  `jam-web/src/app/api/admin/badges/[id]/poi-links/route.ts`(GET·PUT)

## 배경 / 문제 정의

2026-10-06 PC 세션에서 티켓 20261004_2043(어드민 기간 입력)을 로컬 어드민으로 실렌더하다 발견했다(상위 20260930_1450 진행 중 범위 밖 발견물).

- 확인한 사실: 로컬 개발 서버(`jam-web-admin`, `npm run dev`)에서 체크인 배지 「라연」(`fc3125e5-c359-4ab2-b1f1-7ba6a9b7e310`)의 수정 화면을 열면 「연결된 지점 0곳」으로 보인다.
  같은 화면에서 `GET /api/admin/badges/fc3125e5-…/poi-links`는 200으로 지점 1곳을 돌려주고, 상세 화면과 DB(`poi.linked_badge_id`)도 1곳이다.
- 확인한 사실: 저장 핸들러는 배지 저장 뒤 `linkedPois` 전체로 `poi-links`를 PUT한다(505–516행). 화면이 0곳이면 빈 목록을 보낸다.
- 판단(코드 읽기, 재현 확인 전): 최초 불러오기 `useEffect`가 `poiLinksLoadedRef.current = true`를 먼저 적고, 정리 함수가 `cancelled = true`로 첫 응답을 버린다.
  개발 모드는 효과를 두 번 실행하므로 두 번째 실행이 가드에 걸려 다시 부르지 않고, 결과적으로 목록이 비어 있는 채 남는다. 프로덕션 빌드는 한 번만 실행하므로 이 경로는
  개발 모드에서만 나지만, 불러오기가 끝나기 전에 저장을 누르면 프로덕션에서도 같은 결과(빈 목록 PUT)가 된다.
- 위험: 로컬 서버도 프로덕션과 같은 DB를 쓴다. 처리 규칙표의 「어드민 화면 로컬 실렌더」로 체크인 배지를 열어 저장하면 프로덕션 배지의 지점 연결이 지워진다.
  기간이 설정된 배지 984개는 모두 체크인 배지라 기간 입력 확인이 정확히 이 화면을 쓴다. 이번 세션은 저장 요청을 브라우저에서 막고 확인해 실제 쓰기는 없었다(DB에서 1곳 유지 확인).

## 완료 조건

- 로컬 개발 모드에서 체크인 배지 수정 화면을 열면 연결된 지점 수가 상세 화면·DB와 같다.
- 연결 지점 불러오기가 끝나기 전이거나 실패한 상태에서는 저장해도 `poi-links` PUT이 나가지 않는다(또는 저장 버튼이 막힌다). 테스트로 확인한다.
- 지점을 실제로 더하거나 뺀 저장은 지금처럼 반영된다.
