# [UI] 운영툴 자원 연결 ⑫-a 홈 레시피 공개 카드 그리기 (코드만)

## 핵심 요약

- 요구사항: 홈에 레시피 공개 카드(`recipe_reveal`)를 그린다. 공개 전에는 「재료 수 · 공개일」만 보이는 공개 예고, 공개 뒤에는 재료 타일이다. 재료 수(슬롯 수)와
  공개일(`valid_from`)은 카드에 직접 쓰지 않고 레시피에서 읽는다. 누르면 공개 전·후 모두 `/combine`(운영자 지정 이동 주소가 있으면 그쪽). 처음 보는 템플릿 값이 와도 홈 전체가
  오류 화면이 되지 않게 막는다. **DB 변경은 없다**: 카드의 레시피 칸 `today_cards.recipe_id`와 CHECK 값은 ⑫-b(20261006_1218)가 만든다.
- 구현 계획: 아래 「구현 계획」(파일 단위). 유형 `ui`, 채원① 판정 필요(아래 「채원① 판정 항목」).
- 관련 파일: `jam-web/src/lib/today/cards.ts`(`getTodayCards` 107–112 서비스 클라이언트·`select('*')`), `jam-web/src/lib/today/cardView.ts`(`recipe` 자원 124–125, `buildFacts` `recipe` case 151–154,
  list 타일 262–267은 `resolved_badges`에서만), `jam-web/src/lib/today/shape.ts`(`resourceOfTemplate` 139), `jam-web/src/components/today/resourceIcon.ts`(44–48 `createElement(undefined)`),
  `jam-web/src/components/today/TodayCard.tsx`(모양별 렌더 32–69), `jam-web/src/lib/today/targetHref.ts`(운영자 주소 우선 41–42, 드랍 고정 63), `jam-web/src/lib/admin/today-sections.ts`(`TODAY_TEMPLATE_OPTIONS` 67,
  `todayTemplateFields` 205–210), `jam-web/src/types/database.ts`(`TodayCardTemplateType` 1097–1105, 수기 유니온), `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts`(`REQUIRED_REFERENCE_FIELDS` 91–100, Record라

## 배경 / 문제 정의

1500 ⑫ 시작 검토(2026-10-06, 1500 「주요 의사결정」 ⑫ 항목 둘)의 사용자 결정 Q1~Q5와 혜린 가정 1~11이 이 티켓의 전제다. 07은 §4.4·§4.5·§5.1에 먼저 반영했다.
홈피드 PRD 237행은 `recipe_reveal`을 「기본 `list`(재료 타일), 공개 예고 `poster`, 필수 정보 재료 수·공개일」로 정했지만 템플릿·칸·그리는 코드가 없다.
라이브 DB `today_cards_template_type_check` 허용 값 8개에 `recipe_reveal`이 없고(2026-10-06 확인), 1453 결정 5·16에 따라 그리는 코드를 DB보다 먼저 낸다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 템플릿 값 `recipe_reveal`을 정본 목록·수기 유니온·필수 참조 표에 더한다. 필수 참조는 없다(`recipe_id`는 비어 있어도 카드가 그려진다).
- 카드 읽기(`cards.ts`): `recipe_reveal` 카드의 `recipe_id`(⑫-b 전에는 칼럼이 없어 `undefined`)로 `combination_recipes`와 슬롯을 한 번에 읽는다(서비스 클라이언트, 이 테이블은 RLS 정책 0개).
  **공개 전**(`valid_from > now`)에는 재료 수와 공개일 두 값만 카드 뷰에 넘기고 이름·슬롯 후보·보상은 넘기지 않는다(사용자 결정 Q3). **공개 뒤**에는 재료 타일을 슬롯 후보 배지로 만든다.
  레시피가 끝났거나(`valid_until <= now`) 없거나 `recipe_id`가 비면 레시피 줄 없이 그린다(가정 7).
- 그리기: 공개 전에는 타일이 0개라 기존 규칙대로 `list` → `brief`로 그려진다. 공개 예고 `poster`도 같은 두 값을 정보 줄로 보인다.
- 이동: 기본 목적지 `/combine`(공개 전·후 같다). 운영자 지정 주소가 우선한다(기존 41–42행 규칙).
- 안전망(가정 8): `resourceOfTemplate`가 모르는 템플릿에 `undefined`를 주면 아이콘 없이 그린다. 어드민 상세·폼의 `todayTemplateFields(x)`도 모르는 값에서 던지지 않는다.
- 운영툴 사전 점검: 카드 → 레시피 쌍은 ⑫-b가 더한다. ⑫-a는 `REQUIRED_REFERENCE_FIELDS.recipe_reveal = []`까지만.

### UI/UX 관점
- 채원① 판정 항목: (1) 후보가 여럿인 슬롯의 타일 표현 (2) 타일 최대 개수 (3) 공개 뒤 필수 정보 줄 문구 (4) 공개 전 `list` → `brief` 전환과 `poster`의 정보 줄 모습. 새 모양·새 컴포넌트는 만들지 않는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `recipe_reveal` 카드가 공개 전 레시피를 가리키면 정보 줄에 재료 수와 공개일만 보이고, 응답(카드 뷰)에 레시피 이름·슬롯 후보·보상이 없다(테스트).
- 공개 뒤에는 재료 타일이 슬롯 후보 배지로 그려진다(채원① 판정대로, 테스트).
- `recipe_id`가 없거나 비었거나 레시피가 끝났거나 없으면 레시피 줄 없이 카드가 그려진다(테스트).
- 누르면 기본 `/combine`, 운영자 지정 주소가 있으면 그쪽이다(테스트).
- 처음 보는 템플릿 값의 카드가 있어도 홈 목록 렌더와 어드민 상세·폼이 던지지 않는다(테스트).
- 위 깨질 테스트 다섯 곳이 갱신되고, 홈피드 PRD 237행·`COMBINE_RECIPES.md`가 현재 상태로 바뀌었다.

### 후속 범위 (담당: 카리나, 시점: ⑫-b 머지와 `/jam-ship` 뒤 PC 세션)
- 첫 실제 레시피 공개 카드를 예약해 공개 전 예고 → 공개 뒤 타일을 확인한다(사용자 승인 뒤).
