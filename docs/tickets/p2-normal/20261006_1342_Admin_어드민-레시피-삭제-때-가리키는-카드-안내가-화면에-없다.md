# [Admin] 어드민에서 레시피를 지울 때 그 레시피를 가리키는 카드 안내가 화면에 없다

## 핵심 요약

- 요구사항: 어드민 레시피 삭제(일괄 삭제 포함) 확인 단계에서 그 레시피를 가리키는 홈 카드(`today_cards.recipe_id`) 수를 운영자가 볼 수 있게 한다. 삭제는 막지 않는다(⑫-b 가정 B).
- 구현 계획: 아래 「구현 계획」(파일 단위). 유형 `admin`(MODULAR 적용 제외, 실렌더는 카리나가 머지 뒤 push 전에 한다).
- 관련 파일: `jam-web/src/app/api/admin/recipes/[id]/route.ts`(52–57행 단건 DELETE의 notice), `jam-web/src/app/api/admin/recipes/bulk/route.ts`(36행 부근), `jam-web/src/lib/admin/recipe-references.ts`(`collectRecipeReferences`의 `noticeTotal`), 어드민 레시피 목록 화면의 일괄 삭제 확인창

## 배경 / 문제 정의

⑫-b(20261006_1218) 착수 때 사용자가 확인한 가정 B는 「어드민에서 레시피를 지울 때는 막지 않고 안내만 한다, 카드는 레시피 줄 없이 남는다」다.
⑫-b 게이트(민지, WARN 사유 2·범위 밖 발견물)에 따르면 안내는 단건 DELETE 응답의 `notice` 하나뿐이고, 이 응답을 읽는 화면이 없다. 어드민 레시피 화면은 일괄 엔드포인트만 부르며, 일괄 삭제에는 안내가 없다.
그래서 운영자는 레시피를 지운 뒤 레시피 공개 카드가 레시피 줄 없이 그려진다는 것을 알 수 없다. 레시피 공개 카드는 `/jam-ship` 전에는 만들지 않으므로(⑫-b 「금지」) 지금 당장 영향받는 카드는 없다.

## 구현 계획

> 2026-10-06 카리나 규모 사전 판정: 테스트·문서 포함 약 7파일·150줄. 아래 표에 파일 경로와 함수·줄 위치가 있어 첫 호출부터 계획 반환 면제로 진행한다.
> 어드민에서 레시피가 지워지는 화면 경로는 둘이다: 목록의 일괄 삭제(`RecipeTable.tsx` → `/api/admin/recipes/bulk`)와 편집 화면의 「예약 취소」(`RecipeForm.tsx` → `/api/admin/recipes/[id]/cancel-release`,
> 공개 전 레시피를 지운다). 단건 `DELETE /api/admin/recipes/[id]`를 부르는 화면은 없다(⑫-b 게이트 확인).

| 경로 | 위치 | 변경 |
|---|---|---|
| `jam-web/src/app/api/admin/recipes/bulk/route.ts` | `POST`의 `dryRun` 분기 49–68 | 삭제 대상(`deletable`)을 가리키는 카드 수를 `collectRecipeReferences(supabase, deletable).noticeTotal`로 세어 `impact.cardCount`로 돌려준다. 조회 실패는 슬롯 수와 같이 500(fail-closed) |
| `jam-web/src/app/admin/recipes/RecipeTable.tsx` | 미리보기 상태 타입 41–42, `openDelete` 176–182, 확인창 `impact` 266–288 | `cardCount`를 받아 0보다 크면 확인창에 안내 한 줄을 더한다 |
| `jam-web/src/app/admin/recipes/[id]/page.tsx` | 로더 8–51 | 이 레시피를 가리키는 카드 수(`collectRecipeReferences(supabase, [id]).noticeTotal`)를 읽어 `RecipeForm`에 넘긴다. 조회 실패면 안내를 빼고 화면은 그대로 연다(삭제 판정은 서버가 따로 한다) |
| `jam-web/src/app/admin/recipes/RecipeForm.tsx` | props, `handleCancelRelease` 228–231 | 카드 수가 0보다 크면 예약 취소 확인 문구에 안내 한 줄을 덧붙인다 |
| 안내 문구 | 두 화면 공용 순수 함수(예: `recipe-references.ts` 옆) | 「홈 카드 N장이 이 레시피를 가리켜요. 지우면 그 카드는 레시피 정보 없이 남아요.」(해요체, 0장이면 문구 없음) |
| 테스트 | 새 `jam-web/src/app/api/admin/recipes/bulk/__tests__/route.test.ts` 또는 기존 레시피 라우트 테스트(`recipes/[id]/__tests__/route.test.ts`)를 본뜸, 문구 함수 테스트 | `dryRun` 응답의 `impact.cardCount`(0·N·조회 실패 500), 문구 함수(0장·N장) |
| 문서 | `docs/specs/prd/ops-tool/PRD.md` 1182행(어드민 예약 취소·삭제는 막지 않는다), 어드민 레시피 화면을 설명하는 문서가 있으면 그 절 | 「막지 않고 확인창에서 카드 수를 안내한다」로 현재 상태를 적는다 |

- 지금 라이브 DB에는 레시피를 가리키는 카드가 0장이다(⑫-b 217 적용 뒤 확인). 그래서 실렌더로는 안내가 없는 상태만 볼 수 있고, 안내가 보이는 경우는 테스트로 고정한다.
  ⑫-b 「금지」대로 이 확인을 위해 `recipe_reveal` 카드를 만들지 않는다.

## 완료 조건

- 어드민 일괄 삭제 확인창과 편집 화면의 예약 취소 확인 문구에, 카드가 가리키는 레시피면 「홈 카드 N장이 이 레시피를 가리켜요. 지우면 그 카드는 레시피 정보 없이 남아요.」가 보이고,
  삭제는 그대로 진행된다(테스트). 카드가 0장이면 문구가 없다.
- 운영툴 PRD 1182행이 현재 상태다.
