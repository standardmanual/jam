# [Service] 공개 전 배지·컬렉션 정책(215·216)에 기대는 화면 경로에 테스트가 없다

## 핵심 요약

- 요구사항: 마이그레이션 215·216으로 정책이 0행을 돌려줄 수 있게 되면서 바꾼 `.single()` → `.maybeSingle()` 3곳과 임베드 null 방어(`item.badge && …`)가 모두 테스트 0%다. 공개 전 배지·컬렉션이 정책에 걸릴 때의 404·null 경로를 테스트로 고정한다.
- 구현 계획: 각 경로에 정책이 0행·null 임베드를 돌려주는 모의 케이스를 더한다.
- 관련 파일: `jam-web/src/app/api/badges/[id]/share-data/route.ts` 102, `jam-web/src/app/(main)/badges/[id]/page.tsx` 88, `jam-web/src/app/(main)/collections/[id]/page.tsx` 91, `jam-web/src/app/(main)/inventory/page.tsx` 51, `jam-web/src/app/(main)/badges/page.tsx` 82

## 배경 / 문제 정의

2026-10-06 `/jam-ship`(origin/main daf6db727 → 565c3067b) 5단계 병렬 점검(민지 모드 ③ 3번 [정확성/주의]). null 방어는 지금 마이그레이션 주석의 코드 읽기에만 기대고 있다.

## 완료 조건

- 위 다섯 경로가 정책 0행·null 임베드에서 404 또는 빈 상태로 그려지는 것이 테스트로 고정된다.
