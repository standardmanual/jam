## 카리나 가정 (2026-10-06, 사용자 이의 없음)

1. 서랍 데이터는 새 GET API로 그 항목만 읽고 URL은 `history.replaceState`로 바꾼다(S3와 같은 방식). 날짜 서랍은 이미 읽은 페이지 데이터로 그린다.
2. 도착 항목의 S4 안내는 「기획 상세를 열면 검토중으로 바뀌어요」 + 링크(`OpsItemActions.tsx` 33행의 「화면을 새로 고치면…」 대신, S4에서는 `/open`을 부르지 않음).
3. 여러 날에 걸친 항목: 카드는 걸치는 날마다, 그 밖의 운영 항목은 시작일 칸에만. 미션은 막대 줄에도 상태 아이콘과 함께 두고 `weeklyMissions` 막대에서는 합친 미션을 뺀다.
4. 실패 항목은 타임라인에는 「실패」 색으로 남기고 달력 칸에는 넣지 않는다.
5. 신호는 검사 범위(오늘~일요일 또는 다음 주)에만 있다. 범위 밖 칸에는 칩을 두지 않고, 날짜 서랍에 「이 날짜는 신호를 확인하는 기간이 아니에요」(「이상 없음」 금지).
6. 거르기가 하나라도 켜지면 자동 실행 줄을 숨기고, 장기 카드 줄은 종류 거르기에 「홈피드 카드」가 있을 때만 남긴다(트라이브·패턴 거르기면 숨김).
7. 「일정표 보기」는 운영 홈 `OpsWeekStatus` 머리 오른쪽(채원 판정 도식).
8. 사이드바 「일정표」는 ③-d에서 더한다. ③-a~c 동안은 주소로만 들어간다.
9. 타임라인 창은 월요일 기준 4주 격자에 맞춰 고정한다(날짜를 눌러도 창이 흔들리지 않음).
10. jsdom이 없어 클릭·포커스 실행 테스트는 하지 않는다. 순수 함수 + 정적 렌더 테스트 + 기존 결정 API 테스트로 고정하고, 카리나가 머지 전에 리뷰 브랜치를 실렌더한다.
11. 주간 보기는 비활성 카드까지 읽으려고 `today_cards`를 따로 읽는다(`loadDayCompositions`는 활성 카드만). `created_resource`로 비활성 카드까지 중복을 제거한다.
12. 새 GET API는 `requireAdmin`(세션 전용)이다. 옛 카드·미션 서랍 키는 `item=card:<uuid>`·`mission:<uuid>`.
13. `WeeklyCalendar`는 ③-a~c에서 제자리에서 확장하고(옛 모드 출력은 그대로, `home-sections.test.tsx` 578–583행이 고정), 파일 이동과 옛 모드 제거는 ③-d에서 한다.

## 완료 조건

- 주간·월간·타임라인이 `?view=`로 유지되고, 보기를 바꿔도 기준일(`date`)이 유지된다.
- 타임라인은 미션·드랍 일정·컬렉션 런칭 세 줄과 맨 위 신호 줄이고, 컬렉션 준비 구간(R4, 규칙이 꺼졌거나 못 읽으면 28일) 점선과 노출 구간 실선이 다르다. 실패 항목은 「실패」 색이다.
- 오늘 세로선에 「오늘」 글자가 있고 막대마다 `aria-label`에 종류·기간·상태가 있다.
- 보기별 스켈레톤, 월간은 칸 폭 40rem 미만에서 개수 표시, 타임라인은 상자 안에서만 가로 스크롤(320px에서 페이지 가로 스크롤 없음).
- 월간·타임라인에서 아이콘만 보이는 상태는 범례 [상태 아이콘 보기]로 뜻을 볼 수 있다.
