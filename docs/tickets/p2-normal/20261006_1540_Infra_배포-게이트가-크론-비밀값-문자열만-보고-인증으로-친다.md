# [Infra] 배포 게이트가 크론 비밀값 문자열만 보고 인증으로 친다

## 핵심 요약

- 요구사항: `scripts/deploy-gate.mjs`의 새 API 라우트 인증 검사(`ROUTE_AUTH`, 230행 부근)는 라우트 소스에 `CRON_SECRET` 문자열이 있으면 인증이 있는 것으로 본다. 그래서 새 크론 라우트가
  `!secret` 선검사 없이 `Bearer ${process.env.CRON_SECRET}` 비교만 해도 게이트를 통과한다(값이 없는 환경에서 `Bearer undefined`가 통과하는 P1 20260929_1636의 약점). 이 모양을 게이트가 막게 한다.
- 구현 계획: 착수 때 정한다. 후보: `CRON_SECRET`을 쓰는 라우트는 빈 값 선검사 모양(`!secret ||` 또는 공용 함수 호출)이 있어야 통과, 아니면 차단. `scripts/deploy-gate.test.mjs` 104행의 통과 사례를 차단 사례로 바꾼다.
- 관련 파일: `scripts/deploy-gate.mjs` 230행 부근(`ROUTE_AUTH`), `scripts/deploy-gate.test.mjs` 104행, 본보기 `jam-web/src/app/api/cron/ops-reconcile/route.ts` 21–22

## 배경 / 문제 정의

P1 20260929_1636 게이트(민지)의 범위 밖 발견물 [참고/보안]이다. 1636이 크론 4종의 구멍을 막았지만, 같은 약점을 가진 새 크론이 들어와도 기계 검사가 잡지 못한다. 1636과 같은 계열이라 P2로 올렸다.

## 완료 조건

- 빈 값 선검사 없이 `CRON_SECRET`을 비교하는 새 라우트가 `node scripts/deploy-gate.mjs check`에서 차단되고, 지금 크론 6종은 통과한다(테스트).
