# [Infra] staging 자동 로그인 세션으로 누구나 공용 DB의 일반 API를 쓸 수 있다

## 핵심 요약

- 요구사항: jam-stage에는 Vercel 접근 보호가 없어 쿠키 없는 요청 누구나 `/api/dev-login`으로 dev-tester의 Supabase 세션을 받는다(`src/proxy.ts` 88–95). P1 20261006_1527로 이 계정의
  어드민 판정은 막았지만, 이 세션으로 닿는 일반 유저 API(체크인·드랍 픽업·믹스·팔로우 등)와 공개 anon 키로 부르는 PostgREST는 staging·프로덕션 공용 DB에 쓴다. 막을 방법을 정한다.
- 구현 계획: 사용자 결정 사항이다. 후보: (A) Vercel jam-stage 배포 보호(비밀번호 또는 Vercel 로그인)를 켠다 — 사용자가 Vercel 설정에서 직접, 목요일 무인 배포의 staging 응답 확인과 카리나의
  staging 확인 절차를 함께 고친다 (B) staging 자동 로그인을 끄고 staging 확인은 로컬 실렌더로만 한다 (C) 받아들인다(테스트 계정 활동이 프로덕션 지표에서 이미 제외되는지 확인).
- 관련 파일: `jam-web/src/proxy.ts` 88–95, `jam-web/src/app/api/dev-login/route.ts`, `jam-web/src/lib/env/test-accounts.ts`, `.claude/skills/jam-work/references/scheduled-jobs.md`(주간 배포의 staging 확인)

## 배경 / 문제 정의

2026-10-06 P1 20261006_1527 게이트(민지)의 범위 밖 발견물 [보안/참고]이다. 같은 날 `/jam-ship` 보안 점검에서 쿠키 없는 요청이 `/` → `/api/dev-login`(307)으로 가 dev-tester 세션 쿠키를 받는 것을 확인했다.

## 완료 조건

- (A)·(B)·(C) 가운데 사용자가 고른 방식이 적용되고, 그 이유가 기록된다.
