# [Admin] 운영툴 미리보기·이미지·서랍 ② 서랍 틀과 카드 미리보기

> 상위: 20260930_1501 ② · 20260930_1450 순서 3 · 07 인벤토리 D

## 핵심 요약

- 요구사항: 1502 ③-b가 만든 서랍(`OpsDrawerFrame`·`OpsScheduleDrawer`)에 미리보기와 폭 360·430 전환을 넣는다. 공용 `TodayCardPreview`를 재사용한다. 색·문안을 바꾸면 미리보기가 바로 바뀌고 서랍이 열려도 원래 화면은 그대로 보인다. 저장 없이 표시 데이터로 그리고 계측과 링크를 남기지 않는다.
- 구현 계획(파일 단위, 2026-10-06 조사 결과와 사용자 결정 Q9·Q10을 따름. 경로는 `jam-web/src/` 기준):
  1. 신규 `lib/admin/opsInbox/cardPreview.ts`(코드 90줄 안팎): `itemToPreviewCard(item, draftValues?, { now })` → `TodayCardWithHref | null`, `previewViewOf(...)` → `CardView | null`. `applyDraftToItem`으로 저장 전 입력값을 덮어쓴 항목에서 `copy`(`CARD_COPY_KEYS`)·`resource`(`registerInput.ts` 145~158줄 키)·`starts_at`·`ends_at`·`shape`를 관대하게 읽는다(없는 칸은 비운다, 제목이 비면 「(제목 미입력)」, 연결된 미션·배지는 읽지 않는다). `shape`는 `readOpsItemShape`, 「모름」이면 `resolveShape`에 맡긴다. `toCardView`에 `tracking`을 주지 않는다. 카드(홈피드 카드)가 아니면 null. 선례는 `app/admin/today/TodayCardForm.tsx` 331~377줄.
  2. `lib/admin/opsInbox/editDraft.ts`: 순수 함수 `applyDraftToItem(item, values)` 추가(25줄 안팎). `computeDraftDiff`와 같은 방식으로 `copy.<키>`·`colors.<키>`·`starts_at`·`ends_at`을 항목에 덮어쓴 `ViewableItem`을 돌려준다.
  3. 신규 `components/admin/ops/OpsCardPreview.tsx`(50줄 안팎): 항목과 `draft.values`를 받아 `TodayCardPreview`에 `views=[view]`를 넘긴다. 색은 `colors.*` 값을 색 견본 칩으로 한 줄 보여 준다(Q9 A+B, 카드 틀은 색을 그리지 않는다). 카드가 아닌 종류는 「이 종류의 미리보기는 곧 열려요」 한 줄(⑤가 채운다). 이미지형 카드(`hero`·`poster`·`square`)에 `cover_image_url`이 없으면 「이미지는 승인 뒤 만들어요」 문구. 기기 폭 선택은 같은 화면에서 항목을 옮겨도 유지되도록 컴포넌트에 항목 ID로 `key`를 걸지 않는다.
  4. `components/admin/ops/OpsScheduleDrawer.tsx` `ReadyItemBody`(약 160~215줄): `OpsItemDetail` 위에 `<OpsCardPreview item draft={draft?.itemId === item.id ? draft.values : undefined} />` 한 블록(15줄). `draft`는 이미 이 컴포넌트가 든다. 서랍 폭(28rem)은 그대로 두고 판의 가로 스크롤을 허용한다.
  5. `components/admin/ops/OpsBundleWorkspace.tsx` 237~246줄: 「미리보기는 곧 열려요」 빈 틀(`aside aria-label="미리보기"`)을 `OpsCardPreview`(`ctx.selectedItem`, `ctx.draft`)로 교체(25줄 안팎).
  6. `app/admin/today/TodayCardPreview.tsx`: 원칙적으로 고치지 않는다. 서랍 안에서 판 안쪽 여백이 문제가 되면 `compact` 선택 props만 더한다(0~15줄).
  7. 테스트: 신규 `lib/admin/opsInbox/__tests__/cardPreview.test.ts`(130줄 안팎, 순수 함수), 신규 `components/admin/ops/__tests__/cardPreview.test.tsx`(서버 렌더 40줄 안팎: 계측·링크 없음, 색 칩, 카드 아님, 이미지 없음 문구), 기존 `scheduleDrawer.test.tsx`·`render.test.tsx`에 케이스 한 건씩. vitest `environment: 'node'`라 `renderToStaticMarkup`과 순수 함수로 쓴다.
  8. 문서: 운영툴 PRD §6.1 S3의 「미리보기는 곧 열려요」 서술을 교체하고 서랍 절에 미리보기 자리를 적는다(20줄 안팎). 1802 완료 기록, 1501 「주요 의사결정」.
  - 수정하지 않는 것: `OpsDrawerFrame`, 서랍 API, 카드 틀(`TodayCard`·`CardFrame`·`CardImageSlot`), `toCardView`, `registerInput.ts`.
- 관련 파일: `jam-web/src/app/admin/today/TodayCardPreview.tsx`, `TodayPreviewModal.tsx`, 1502 ③-b의 `OpsDrawerFrame`·`OpsScheduleDrawer`, 티켓 1453 「확정 설계」 7·8
