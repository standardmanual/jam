# [Admin] 기획 상세 왼쪽 미리보기 칸이 좁아 카드가 잘린다

> 상위: 20260930_1501 ② 실렌더 확인(2026-10-07)에서 발견. ③ 20261006_1803 앞에 처리하면 좋다.

## 핵심 요약

- 요구사항: 기획 상세(S3) 왼쪽 미리보기 칸에서 카드가 잘리지 않고 보이게 한다.
- 문제: 1440 폭에서 왼쪽 칸은 280px이고 안쪽 판은 246px인데, 기기 폭 360을 고르면 카드 판이 360px라 가로로 스크롤해야 한다. 430은 더 넘친다. 운영자는 카드를 한눈에 못 본다.
- 구현 계획: (a) 왼쪽 열을 360·430 판이 들어가는 폭으로 넓히거나, (b) 미리보기 판을 칸 폭에 맞춰 축소(`transform: scale`)하거나, (c) 좁은 칸에서는 기기 폭 전환을 숨기고 축소만 한다. 폭이 한정된 3열 배치(`@[68rem]`)와 서랍 열(320px) 배분을 함께 본다. 방식은 채원 사전 판정과 사용자 선택이 필요하다.
- 결정(2026-10-07, 사용자 승인): (b) 칸 폭에 맞춰 축소(`transform: scale`)로 간다. 열 배분(`280px`·`@[68rem]` 3열·서랍 `320px`)은 건드리지 않는다. 채원 판정은 admin 유형이라 생략(경로 ②에 준해 아현 → 민지).
- 구현 지도: `TodayCardPreview.tsx`의 판(`overflow-x-auto` div, `data-preview-board`)을 바깥 측정 칸 + 안쪽 축소 칸으로 나눈다. 측정 칸 폭(ResizeObserver)에서 판 안쪽 여백(`p-4` 좌우 32px)을 뺀 값을 `previewCardWidth(deviceWidth)`로 나눠 `scale = min(1, 가용폭/카드폭)`을 구하고, `transform-origin: top left`로 축소한다. `transform`은 레이아웃 높이를 줄이지 않으므로 바깥 칸 높이를 안쪽 실측 높이 × scale로 맞춘다. 칸이 충분히 넓으면 scale 1이라 기존 모습 그대로다. 공용 부품이므로 날짜 미리보기 모달·카드 폼의 「홈 화면 미리보기」에서 회귀가 없어야 한다(`overflow-x-auto`를 쓰는 기존 테스트가 있으면 함께 조정).
- 관련 파일: `jam-web/src/components/admin/ops/OpsBundleWorkspace.tsx`(왼쪽 `aside aria-label="미리보기"`와 `@[68rem]` 그리드), `jam-web/src/components/admin/ops/OpsCardPreview.tsx`, `jam-web/src/app/admin/today/TodayCardPreview.tsx`(`previewCardWidth`, 판 `overflow-x-auto`)

## 완료 조건

- [x] 폭 360·430 전환이 동작한다.
- [x] 서랍 안 미리보기도 같은 기준으로 확인한다. (현재 서랍에는 미리보기 칸이 없어 해당 칸 없음. 같은 부품이 폭만 보고 축소하므로 ③ 20261006_1803에서 서랍에 붙일 때 같은 기준이 적용된다)

## 완료 기록

### 구현 내용 요약
- 원인: 미리보기 판이 카드 폭(360 기기 328px, 430 기기 398px)을 고정하고 `overflow-x-auto`로 가로 스크롤시켜, 1440 폭의 280px 왼쪽 칸에서 카드가 잘렸다.
- 결정(사용자 승인): (b) 칸 폭에 맞춰 `transform: scale` 축소. 열 배분(280px·`@[68rem]` 3열·서랍 320px)은 그대로다. admin 유형이라 채원 판정은 생략하고 아현 → 민지로 진행했다.
- 변경: `TodayCardPreview.tsx`의 판을 바깥 칸(`data-preview-frame`, ResizeObserver로 가용폭 실측)과 안쪽 판(`data-preview-board`)으로 나눴다. `previewScale(가용폭, 카드폭)`이 min(1, 가용폭/카드폭)을 구하고, 1 미만이면 `top left` 기준으로 축소하며 바깥 칸 높이를 안쪽 높이 × scale로 맞춘다. 칸이 넓거나 측정 전(서버 렌더)이면 scale 1이다.

### 주요 의사결정
- 1차 호출은 아현이 `needs_design`으로 반환했다. 원인은 격리 워크트리가 `origin/staging` 기준인데 승인된 결정을 적은 티켓 수정이 로컬에만 있었기 때문이다. 티켓을 커밋·push한 뒤 재호출했다. 교훈: 승인 결정을 티켓에 적는 경우 워크플로 호출 전에 push해야 한다.
- 민지 게이트는 WARN이었다. 사유는 완료 조건이 실제 렌더에서만 확인된다는 점으로, 위 실렌더로 해소했다.
- 머지 전 오염 검사가 실패한 것처럼 보였으나(종료 코드 1), 브랜치에만 있는 커밋은 구현 커밋 1개이고 staging가 분기 뒤 전진한 경우였다. staging를 먼저 받은 뒤 머지했다.
