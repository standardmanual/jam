# [Admin] 운영툴 서랍에서 이미지 만들기 ③-b 서랍·승인 흐름과 「이미지 제작 필요」 표시

## 핵심 요약

- 요구사항: ③-a의 엔진으로 승인 직후 이미지를 자동으로 만들어 항목에 붙이고(예약 뒤에는 자원에도), 실패해도 승인을 유지하며 「이미지 제작 필요」로 남긴다. 서랍에서 [이미지 만들기]·다시 만들기를 누를 수 있다. 시험 묶음은 저장하지 않는다. 기획안의 이미지 지시 칸(`image_spec`)을 정하고 문서·검사에 반영한다(2026-10-07 사용자 결정).
- 선행: ③-a 20261007_0945.
- 착수 때 할 일: 칸 이름 확정(`image_spec.preset_id`·`bg`·`end`·`values` 등)과 일괄 승인·시드·「다시 만들기」 정책을 확정한다(아래 미결정). 그 뒤 티켓의 파일 단위 계획을 갱신하고 `/jam-work`로 진행한다. 이 티켓도 규모가 커서(파일 12개 안팎) 필요하면 「승인 직후 자동」과 「서랍 버튼·표시」로 다시 나눈다.

## 미결정(착수 때 사용자에게 묻는다)

- `image_spec` 칸 이름과 필수 여부(현재 DB의 실제 기획안 8건은 이 칸이 비어 있다).
- 일괄 승인(`OpsBulkApprove`)도 자동 제작 대상인가(여러 장을 순차로 그리며 탭을 오래 열어야 한다). 추천: 이번에는 제외하고 서랍·기획 상세 버튼으로만 만든다.
- 「다시 만들기」는 새 시드를 쓰는가, 같은 시드를 쓰는가.
- 시험 묶음 미리보기 렌더(저장 없이 그리기)를 이번에 할지 ⑤로 미룰지.

## 코드 지도 (2026-10-07 Explore 조사, 줄 번호는 조사 시점)

- 저장 API: `app/api/admin/ops-inbox/[bundleId]/items/[itemId]/image/route.ts`(POST, multipart `image` PNG ≤5MB, 시험 묶음·이미지 칸 없는 종류·반려/취소/실패/종료는 409). 항목 `edited.resource`에 먼저 쓰고 예약 뒤에는 자원 행에도 쓴다(`opsInbox/image.ts` `applyItemImage`). `image.ts`는 서버 전용이라 클라이언트가 import하지 않는다(`imageKeyOfKind`는 순수 함수로 뽑는다).
- 승인 경로: `OpsItemActions.tsx` 164~233줄 → `postDecision`(`decisionClient.ts`) → 성공 뒤 `onDecided` → `useOpsItemResultHandlers.handleDecided`(`OpsItemFooter.tsx` 62~66줄). 승인 뒤 `OpsItemActions`는 상태가 사라지므로(`status !== 'reviewing'` 분기 174~176줄) 제작 상태는 계속 마운트되는 부모(훅 또는 `OpsScheduleDrawer`의 `ReadyItemBody`·`OpsBundleWorkspace`)에 둔다.
- 서랍: `OpsScheduleDrawer.tsx` `ReadyItemBody`(190~239줄)의 `statusNotice`(207~211줄)가 승인됨 항목에서 푸터를 대체하므로 [이미지 만들기]는 푸터 밖에 둔다. 기획 상세 `OpsDecisionWorkspace.tsx` 183~203줄은 같은 `OpsItemFooter`·훅을 쓴다.
- 표시: `opsSignals/composition.ts` 139~142줄 `needsImageProduction`은 승인 전 4상태에서만 참이고 화면 사용처가 없다. `OpsCardPreview.tsx` 33~38줄의 「이미지는 승인 뒤 만들어요」는 따로 계산한다. 신호 `imageMissing`(340줄)·`dayRules.ts` 77줄은 ①이 건드리지 않기로 한 영역이다.
- 시험 묶음: 서버가 409로 막는다(마지막 안전망). 클라이언트는 `isSample`이면 렌더·업로드를 건너뛰고 버튼·표시를 감춘다(`OpsItemActions`에 `isSample` prop 추가).
- 영향 테스트: `composition.test.ts`(213~250줄), `cardPreview.test.tsx`(54줄), `scheduleDrawer.test.tsx`, `itemFooter.test.tsx`, `execute.test.tsx`, `no-html.test.ts`.
- 문서: 운영툴 PRD §3.1 표(78·80줄), §5 「이미지 제작 필요」(186~192줄), §6.1 미리보기 표(374줄), §8.8(1336~1349줄), §13 D행.

## 완료 조건

- [ ] 승인하면 이미지가 만들어져 항목에 붙고, 예약된 뒤에는 자원에도 붙는다.
- [ ] 이미지 제작이 실패해도 승인은 유지되고 「이미지 제작 필요」가 표시되며 서랍에서 다시 만들 수 있다.
- [ ] 예약 등록은 이미지 때문에 막히지 않는다.
- [ ] 시험 묶음은 렌더·저장하지 않고 버튼·표시를 감춘다.
- [ ] `image_spec` 칸 규칙이 PRD §3.1과 제출 검사(경고만)에 반영된다.
