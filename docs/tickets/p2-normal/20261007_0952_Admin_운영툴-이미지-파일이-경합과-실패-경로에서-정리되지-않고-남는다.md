# [Admin] 운영툴 이미지 파일이 경합과 실패 경로에서 정리되지 않고 남는다

## 핵심 요약

- 요구사항: (1) 이미지 업로드 중 같은 항목이 취소·반려·실패로 바뀌면 라우트가 두 파일을 올린 뒤 `applyItemImage`에서 409를 내고 올린 파일을 지우지 않는다(`image/route.ts` 113행, 같은 경로 동시 업로드 `upsert:true`도 테스트 없음). (2) `failGroup`은 이번 실행에서 만든 자원이 있는 항목의 파일만 지워, 준비·사전검사 단계 실패(`run.ts` 366·368행 `failGroup(ctx, items, [], …)`), 자원 생성 실패 항목, 함께 실패한 미생성 항목, 반려 항목은 승인 상태에서 올린 파일이 남는다(`run.ts` 327–337행). 의도인지 정하고 테스트로 고정해야 한다.
- 구현 계획: 남겨도 되는 경우와 지워야 하는 경우를 먼저 정하고(공개 버킷 용량·노출), 지워야 하면 409 경합과 `failGroup` 경로에서 `removeOpsImageFiles`를 부른다. 경합·정리 테스트를 추가한다.
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/[bundleId]/items/[itemId]/image/route.ts`(113행), 운영툴 실행 `run.ts`(327–337·366·368행, `failGroup`), `removeOpsImageFiles`, `run.test.ts`

## 배경 / 문제 정의

2026-10-07 `/jam-ship` 5단계 병렬 점검(민지 모드 ③ 테스트 공백, 범위 565c3067b..9142afab7)의 범위 밖 발견물 [동시성/주의] 3번·[정합성/주의] 4번이다. 승격을 막지 않는 항목이라 배포와 별도로 처리한다.

## 완료 조건

- 경합·실패 경로의 파일 처리 방침이 정해지고, 그 방침이 테스트로 고정된다.
