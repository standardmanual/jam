# [Admin] 일정표 서랍의 결정 흐름이 소스 문자열 검사로만 고정돼 있다

## 핵심 요약

- 요구사항: 일정표 항목 서랍의 승인·반려·수정·되돌리기·취소·종료가 `detail.bundleId`를 쓰는지를 소스 정규식으로만 확인한다(`scheduleDrawer.test.tsx` 242–262행). `useOpsItemResultHandlers`의 실제 동작(되돌리기 409 시 새로 읽기, 토스트 → `afterToast` → 새로 읽기 순서, `logWarning` 토스트, `OpsItemFooter.tsx` 46–100행)과 서랍이 항목을 빠르게 옮길 때 오래된 응답을 버리는 effect(`OpsScheduleDrawer.tsx` 279행)는 검증이 없다. `OpsDecisionWorkspace`에서 푸터를 떼어낸 리팩터라 S3 결정 흐름 회귀 위험이 있다.
- 구현 계획: jsdom(또는 happy-dom) 도입 여부를 정하고, 도입하면 훅과 서랍 effect를 동작 테스트로 바꾼다. 도입하지 않으면 훅의 순수 로직을 함수로 떼어 단위 테스트한다.
- 관련 파일: `jam-web/src/components/admin/ops/OpsItemFooter.tsx`(46–100행), `OpsScheduleDrawer.tsx`(279행), `__tests__/scheduleDrawer.test.tsx`(242–262행), `jam-web/vitest.config.ts`

## 배경 / 문제 정의

2026-10-07 `/jam-ship` 5단계 병렬 점검(민지 모드 ③ 테스트 공백, 범위 565c3067b..9142afab7)의 범위 밖 발견물 [테스트/주의] 5번이다. 승격을 막지 않는 항목이라 배포와 별도로 처리한다.

## 완료 조건

- 결정 결과 처리와 서랍 응답 순서가 동작 테스트(또는 순수 함수 테스트)로 고정된다.

### 구현 내용 요약
일정표 서랍의 결정 결과 처리 순서를 새 itemResultFlow.ts의 순수 함수(되돌리기 결과, 결정 완료 단계, 취소·종료 토스트 목록, 오래된 응답 버리기 판정)로 떼고, OpsItemFooter 훅과 OpsScheduleDrawer effect는 그 결과를 실행만 하게 했다. jsdom은 도입하지 않았고 vitest 설정은 바꾸지 않았다. 화면 동작과 토스트 문장은 그대로다.
