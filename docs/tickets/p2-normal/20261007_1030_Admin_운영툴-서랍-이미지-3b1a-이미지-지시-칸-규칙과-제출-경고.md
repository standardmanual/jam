## 핵심 요약

- 요구사항: 기획안 항목에 이미지 지시 칸 `image_spec`(`preset_id`·`bg`·`end`·`values`, 모두 선택)을 정의하고, 제출 검사가 모양을 확인하며 비어 있으면 경고만 한다(오류로 만들지 않는다). 렌더·화면은 건드리지 않는다.
- 선행: 없음(③-a 20261007_0945 CLOSED).
- 구현 계획(파일 단위):
  1. 신규 `jam-web/src/lib/admin/opsInbox/imageSpec.ts`(서버·클라이언트 공용 순수 모듈, `server-only` 금지): `readImageSpec(item)`(`itemField(item,'image_spec')` 사용), `imageSpecToRenderArgs(spec, seed)`(`preset_id` 없으면 null, 타입은 `imageRender.client.ts`의 `RenderPresetToPngArgs`를 type-only import), `imageSpecWarnings(spec, path)`, `imageKeyOfKind(kind)`·`isImageKind(kind)`를 `image.ts` 22~42줄에서 이쪽으로 옮긴다(카드 `cover_image_url`, 미션·배지·컬렉션 `image_url`).
  2. `jam-web/src/lib/admin/opsInbox/image.ts`: 옮긴 순수 함수를 새 파일에서 다시 import(`image.test.ts`는 그대로 통과해야 한다). `table`·`prefix`·`storagePathOf`는 서버에 남긴다.
  3. `jam-web/src/lib/admin/opsInbox/validate.ts`: `OpsBundleValidation`·`ValidatedOpsItem`(55~76줄)에 `warnings: string[]` 추가, `validateItem`(255줄~) 끝 `validateOpsCardFields` 호출(~362줄) 근처에서 `image_spec`이 있으면 모양 확인(객체, `preset_id`·`bg`·`end` 문자열, `values` 문자열 맵), 비어 있으면 경고. `errors`로 만들지 않는다.
  4. `jam-web/src/app/api/admin/ops-inbox/route.ts`(`summary` ~114줄, 응답부): 응답에 `warnings`를 싣는다. DB 저장 없음.

## 결정 (2026-10-07 사용자 승인) 과 가정

- 승인: `image_spec`은 선택 칸이고 비어 있으면 제출 검사에서 경고만 한다. 일괄 승인(`OpsBulkApprove`)은 자동 제작에서 제외한다. 「다시 만들기」는 새 시드를 쓴다. ③-b를 나눈다.
- 가정(카리나, 사용자가 코드 지도 조사 뒤 따로 답하지 않은 항목): (1) 경고는 제출 응답에만 싣고 DB에는 저장하지 않는다(`ops_bundles.format_errors`는 오류 전용). (2) `image_spec`이 비어 있으면 `colors`로 대신 그리지 않고 제작을 건너뛴 채 「이미지 제작 필요」로 둔다. (3) 「이미지 제작 필요」 판정 대상은 PRD §5 현행대로 카드 모양(hero·poster·square)만이다. (4) 게재중·예약됨 항목에는 표시하지 않는다.
- 시험 묶음 미리보기 렌더(저장 없이 그리기)는 ⑤로 미룬다.
