- 선행: ③-b1-a 20261007_1030.

## 결정 (2026-10-07 사용자 승인) 과 가정

- 승인: `image_spec`은 선택 칸이고 비어 있으면 제출 검사에서 경고만 한다. 일괄 승인(`OpsBulkApprove`)은 자동 제작에서 제외한다. 「다시 만들기」는 새 시드를 쓴다. ③-b를 나눈다.
- 가정(카리나, 사용자가 코드 지도 조사 뒤 따로 답하지 않은 항목): (1) 경고는 제출 응답에만 싣고 DB에는 저장하지 않는다(`ops_bundles.format_errors`는 오류 전용). (2) `image_spec`이 비어 있으면 `colors`로 대신 그리지 않고 제작을 건너뛴 채 「이미지 제작 필요」로 둔다. (3) 「이미지 제작 필요」 판정 대상은 PRD §5 현행대로 카드 모양(hero·poster·square)만이다. (4) 게재중·예약됨 항목에는 표시하지 않는다.
- 시험 묶음 미리보기 렌더(저장 없이 그리기)는 ⑤로 미룬다.

## 완료 기록

### 구현 내용 요약
- 신규 `useItemImageProduction.ts`: 순수 함수 `produceItemImage`가 `readImageSpec` → `imageSpecToRenderArgs` → `renderPresetToPngBlob` → `postItemImage` 순서로 부른다. 시험 묶음·이미지 칸 없는 종류·`preset_id` 없음은 건너뛰고, 실패는 던지지 않고 `failed`로 돌려 경고 토스트만 띄운다. 시드는 호출마다 새로 뽑는다. 훅은 「만드는 중」 집합과 중복 시작 방지만 맡는다.
- `OpsItemFooter`가 단건 승인 성공 때 `start`를 부르고, `OpsDecisionWorkspace`·`OpsScheduleDrawer`가 훅을 만들어 내려준다. 일괄 승인은 이 경로를 타지 않아 제외된다(소스 검사 테스트로 고정).
- `composition.ts`: `OPS_IMAGE_PRODUCTION_STATUSES`(승인됨·준비중)로 `needsImageProduction`을 좁혔다. 「이미지 제작 필요」는 데이터로 계산하므로 새로 고쳐도 남는다. `OpsCardPreview`는 도착·검토중은 「이미지는 승인 뒤 만들어요」, 승인됨·준비중은 「이미지 제작 필요」다.
- PRD §5·§6.1·§8.8 갱신.
