## 결정 (2026-10-07 사용자 승인, 코드 지도 조사 뒤)

- ⑥을 A(서버 렌더 테스트·명령줄 인자) · B(URL 원본 내려받기 보호) · C(프리셋 저장 검증·호환 테스트) 세 조각으로 나눈다. 서로 독립이라 순서는 상관없다. 조건부 2건 중 0124(렌더 캐시 키)는 A에서 같은 파일을 열 때 함께 처리하고, 1825(어드민 화면 로더)는 제외한다.
- 조사 사실: 6건은 모두 지금도 유효하거나 부분 유효하다(닫을 건 없음). 서버 렌더 스크립트(`jam-web/scripts/asset-generator/*`)는 윤진 예약 루틴(`.claude/agents/jam-marketer.md` 140~183줄)이 계속 쓴다. 새 브라우저 렌더 `renderPreset.ts`는 서버 `renderCardPng`를 대체하지 않는 세 번째 복사본이다. 티켓의 줄 번호(`render.mjs:79-110`)는 어긋나 있고 대상은 `renderCard.mjs` 1~55줄의 `renderCardPng`다. 실제 캔버스 테스트(`@napi-rs/canvas`)는 현재 환경에서 돌며 `verify.sh`(`npm test`)에 포함된다. DB 변경은 없다.
- 보호 정책(티켓 권장대로): 이미지 주소는 https만 허용하고 내려받기에 시간·크기(5MB) 상한을 헤더와 스트리밍 양쪽에서 걸며 오류 문구에서 주소 쿼리를 뺀다. 명령줄은 알 수 없는 인자가 오면 오류로 멈추고 빈 문자열 값은 거절한다(계획 검사 `validatePlan`이 빈 값을 거절하는 것과 같은 규칙). 윤진 루틴이 지금 쓰는 인자는 그대로 동작해야 한다(테스트로 확인).
- 프리셋 저장 검증(C): 오버레이 색은 `#rrggbb` 6자리만, 이미지 주소는 이 프로젝트 저장소 호스트만 허용하고 호스트는 환경변수(`NEXT_PUBLIC_SUPABASE_URL`)에서 읽는다. `overlayEnabled: true`인데 색이 없는 저장은 거절하고 렌더는 지금처럼 관대하게 둔다. 운영 DB의 기존 프리셋 2개(홈피드·미션)는 모두 색 `#ffffff`·호스트 `ceehnkzdbecxwzxrhhns.supabase.co`라 영향이 없다.
- 옛 시드는 PRD §11에 「더 이상 같은 그림이 나오지 않는다」를 문서화하고 경계 테스트만 보강한다. 렌더 조립 코드 세 벌(서버·브라우저 엔진·어드민 화면)의 통합은 이번 범위가 아니고 후속 티켓으로 올린다.
