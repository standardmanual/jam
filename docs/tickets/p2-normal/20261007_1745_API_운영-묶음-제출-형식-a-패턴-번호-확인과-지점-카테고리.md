# [API] 운영 묶음 제출 형식 a: 패턴 번호 사전 확인과 지점 카테고리

> 상위: 20261001_2057(E1) 하위 a. 2026-10-07 사용자 결정으로 둘로 나눴다(a 패턴 번호·지점 카테고리 → 1503 ④ 조합 뽑기가 쓴다, b 20261007_1746 패턴 제안 내용 칸 → 1503 ⑪이 쓴다).
> 선행: 1503 ③ 20261007_1633(패턴 사전 초기 데이터, 2026-10-07 CLOSED·DB 입력 완료).

## 배경 / 문제 정의

- 지금은 `pattern_no`를 문자열·숫자로만 보고(`7`·`P-07`도 통과), `knobs`는 검사 없이 저장한다. 패턴 사전 번호는 `^P[0-9]{2,}$`(마이그레이션 210 CHECK)다.
- 1503 ④(조합 뽑기)는 `knobs.place_category`로 지점 카테고리 순위를 매기고, 1500 카드 생성·결정 기록 패턴별 집계·일정표는 항목의 `pattern_no` 열을 읽는다(`registerInput.ts:405-417`,
  `opsDecisions/read.ts:280-300`, `opsSchedule/filters.ts:52-67`). 틀린 번호가 열에 들어가면 집계에 엉뚱한 줄이 생긴다.

## 결정 (사용자, 2026-10-07, 모두 추천안)

1. 지점 카테고리는 형식(문자열 배열)뿐 아니라 **실제 `poi_categories.slug`에 있는지까지** 본다. 조회 실패는 500.
2. **보관(`archived`) 패턴의 번호도 사전에 있는 번호**로 본다(번호는 지우지 않고 보관만 하므로). 사전 조회는 상태와 무관하게 번호 전체를 읽는다.
3. 형식이 틀린 `pattern_no`(예: `P-07`, `7`)는 **항목의 `pattern_no` 열을 비워(NULL) 저장**하고 형식 오류만 남긴다. 제출 원본(`original`)에는 그대로 남는다.
   형식은 맞지만 사전에 없는 번호(예: `P99`)는 열에 그대로 저장하고 형식 오류를 남긴다.

## 상세 요구사항

- `pattern_no`가 있으면(현행 `isPresent`): 문자열이고 trim 뒤 `OPS_PATTERN_NO_PATTERN`에 맞아야 한다. 숫자는 더 이상 받지 않는다(형식 오류, 열은 NULL).
  `ctx.patternNos`가 있으면 그 안에 있어야 한다(없으면 형식 오류, 열은 값 그대로). `pattern_no`가 없으면 지금처럼 오류 없음(필수 아님).
- `knobs`가 객체이고 `place_category` 키가 있으면: 문자열 배열이어야 하고(빈 배열은 허용), 각 값은 `ctx.poiCategorySlugs`가 있으면 그 안에 있어야 한다.
  어긋난 값마다 또는 한 줄로 「`items[n].knobs.place_category: …`」 형식 오류. `knobs`가 없거나 객체가 아니거나 `place_category`가 없으면 검사하지 않는다(나머지 `knobs`는 지금처럼 검사 없음).
- 조회: 제출(`POST /api/admin/ops-inbox`)과 직접 수정 3경로(editItem·fillColor·revertLastEdit)가 같은 함수로 트라이브·패턴 번호·카테고리 목록을 한 번에 읽는다. 하나라도 실패하면
  저장하지 않고 지금과 같은 500 문장이다.
- 직접 수정의 다시 검사는 지금 규칙(고친 칸의 오류만 400) 그대로라 `pattern_no`·`knobs`의 새 오류는 저장을 막지 않는다. 직접 수정은 `pattern_no` 열을 갱신하지 않는다(현행 유지).
- 기존 묶음(시험 묶음 1개, `pattern_no` `P-07`)은 다시 검사하지 않는다. 읽기 함수가 형식이 틀린 값을 「모름」(`OPS_FIELD_UNKNOWN`)으로 돌려준다(1152 선례). 데이터는 고치지 않는다.
- 형식 오류 경로 이름표: `place_category`에 「지점 카테고리」를 더한다(`pattern_no`의 「패턴 번호」는 이미 있다).

## 완료 조건

- 사전에 없는 번호(`P99`)·형식이 틀린 번호(`P-07`·`7`)·없는 카테고리 slug가 항목 `format_errors`에 「경로: 사유」로 들어가고, 저장과 승인은 막히지 않는다(테스트).
- 형식이 틀린 번호의 항목은 `ops_bundle_items.pattern_no`가 NULL로, 사전에 없는 번호는 값 그대로 저장된다(라우트 테스트).
- 보관 패턴 번호는 형식 오류가 아니다(`loadOpsPatternNos`가 보관 포함, 테스트).
- 패턴 번호·카테고리 목록 조회가 실패하면 제출과 직접 수정 3경로 모두 저장하지 않고 500이다(테스트).
- 기존 묶음은 다시 검사하지 않고, 읽기 함수가 `P-07`을 모름으로 돌려준다(테스트).
- PRD §3.1이 갱신됐다. `scripts/verify.sh`가 통과한다.
