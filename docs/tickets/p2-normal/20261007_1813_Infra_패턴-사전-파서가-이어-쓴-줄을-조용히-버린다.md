# [Infra] 패턴 사전 파서가 필드 값의 이어 쓴 줄을 조용히 버린다

> 출처: 2026-10-07 `/jam-ship` 5단계 민지 모드 ③(배포 전 테스트 공백 점검)의 [정확성/주의]. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: `scripts/ops-patterns-seed.mjs`의 `readFields`(83~93행)는 「- **라벨:** 값」 줄과 그 아래 두 칸 들여쓴 「  - 항목」 줄만 모은다. 값이 다음 줄로 이어지면(들여쓴 일반 문장 등)
  이어진 줄은 어느 필드에도 들어가지 않고 버려진다. 그런데 `validateOpsPatterns`는 아무 문제도 내지 않아 검사가 거짓으로 통과한다. 민지가 「작동 원리」 아래 이어 쓴 줄을 넣는 탐침으로 확인했다.
  분류되지 않는 줄이 블록 안에 있으면 멈춤(문제 한 줄)으로 내보내게 고친다.
- 구현 계획: 착수 때 정한다. 지금 원고에서 분류되지 않는 줄은 첫 블록 앞 머리말 3줄뿐이므로, 블록 안의 분류되지 않는 비어 있지 않은 줄을 문제로 내도 현재 원고는 통과해야 한다.
- 관련 파일: `scripts/ops-patterns-seed.mjs` `readFields`(83~93행)·`validateOpsPatterns`, `scripts/ops-patterns-seed.test.mjs`(탐침과 같은 입력의 테스트 추가),
  `docs/service/content/OPS_PATTERNS.md`(원고).

## 배경 / 문제 정의

- 현재 시드 212는 원고와 같고(`--check` 통과) 버려진 줄도 없어 DB 데이터에는 영향이 없다. 원고를 다시 써서 시드를 다시 만들 때 문장이 일부 빠진 채 DB에 들어갈 수 있는 잠복 위험이다.
- 오류가 삼켜져 거짓 통과가 나는 경우라 주의(P2)로 둔다.

## 완료 조건

- 블록 안에서 어느 필드에도 속하지 않는 줄이 있으면 `validateOpsPatterns`가 문제 한 줄을 낸다(줄 번호나 패턴 번호 포함).
- 이 경우를 재현하는 테스트가 있고, 실제 원고로 `node scripts/ops-patterns-seed.mjs --check`가 계속 통과한다. `scripts/verify.sh`가 통과한다.
