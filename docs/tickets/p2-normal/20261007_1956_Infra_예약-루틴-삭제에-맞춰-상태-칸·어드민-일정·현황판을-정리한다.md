# [Infra] 예약 루틴 삭제에 맞춰 상태 칸·어드민 운영 일정·현황판을 정리한다

> 출처: 2026-10-07 사용자가 예약 루틴을 모두 삭제했다. 같은 날 카리나가 문서 머리말 표시만 넣었다(사용자 선택 「지금은 표시만」). 이 티켓은 그 뒤에 남은 정리다.
> ~~WAITING 사유: 루틴을 영구 중단할지, 다시 만들지 사용자가 정한 뒤에 착수한다.~~
> **사용자 결정(2026-10-15)**: JAM 2.0 완료 전까지 점검은 필요할 때 수동으로 요청한다(데일리 미팅 2026-10-14 결정 요청 3의 답). 아래 구현 계획 (가)로 진행하되 두 가지를 지킨다.
> ① 2026-10-14에 등록한 데일리 미팅 루틴(`trig_01MVcETJSaatpjrj3MgBHxi7`, 월·수·금)은 켜져 있다. 이 루틴이 쓰는 `routine_commit_restriction`과 훅의 루틴 작성자 규칙은 걷어내지 않는다.
> ② 영구 중단이 아니라 「JAM 2.0 완료 전까지」 중단이다. 루틴을 다시 만들지는 2.0 완료 뒤에 정하므로, 상태 칸에는 그 조건을 적는다.
> jam-web(생성 파일·테스트·어드민 운영 일정)을 고치므로 `/jam-work`로 처리한다.

## 핵심 요약

- 요구사항: 2026-10-07 `RemoteTrigger list`로 cron 루틴이 0개임을 확인했다(남은 것은 꺼진 일회성 알림 7개). 그런데 아래는 아직 루틴이 돈다고 가정한다.
  - `.claude/skills/jam-work/references/scheduled-jobs.md` 각 절의 `| 상태 |` 칸이 `켜짐`이다(199·222·386·408행 부근). 이 칸을 세 곳이 읽는다.
    - `scripts/ticket-dashboard.mjs`: 세션 시작 현황판의 리포트 누락 감지. 루틴이 없으니 화요일 주간 리포트 등이 없다는 경고가 잘못 나올 수 있다.
    - `scripts/gen-scheduled-jobs.mjs` → `jam-web/src/lib/admin/scheduledJobs.generated.ts`(`enabled: true` 4건) → `jam-web/src/lib/admin/scheduledRoutines.ts` → 어드민 운영 일정 주간 보기(`jam-web/src/lib/admin/opsSchedule/weekView.ts`). 돌지 않는 루틴이 일정에 나온다.
    - `jam-web/src/lib/admin/__tests__/scheduled-routines.test.ts` 91~119행이 실제 생성 파일에서 루틴이 `enabled: true`라고 단정한다. 상태 칸을 바꾸면 이 테스트를 함께 고쳐야 한다.
  - 그 밖에 루틴을 전제로 한 곳: `scripts/check-routine-reports.mjs`, `.githooks/pre-commit`·`pre-push`의 루틴 작성자 규칙, `docs/agents/contract.json` `routine_commit_restriction`, `.claude/agents/jam-ops.md`·`jam-marketer.md`의 예약 실행 절, `docs/service/prd/content-automation/PRD.md` 등(2026-10-07 검색 기준 약 30개 파일).
- 구현 계획: 사용자 결정에 따라 갈린다. (가) 영구 중단: 상태 칸을 `꺼짐(2026-10-07 삭제)`으로 바꾸고 생성 파일·테스트를 맞춘 뒤, 루틴 전용 검사·훅·문서 절을 걷어낸다. (나) 다시 만듦: 루틴을 다시 등록하고 상태 칸은 그대로 둔다. 주간 배포 실행 루틴은 확인 메시지에 적은 커밋까지만 병합하게 만든다(티켓 20261007_1812 잔여 이슈).
- 관련 파일: 위 목록. 2026-10-07 표시를 넣은 곳은 `scheduled-jobs.md` 머리말, `docs/agents/team-operations.md` §6, `.claude/skills/jam-ship/SKILL.md` 9단계·「주간 무인 배포와의 관계」.
