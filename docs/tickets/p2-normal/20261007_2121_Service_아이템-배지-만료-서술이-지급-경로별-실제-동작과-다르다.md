# [Service] 아이템 배지 만료 서술이 지급 경로별 실제 동작과 다르다

> 범위 밖 발견물 — 티켓 20261007_2119(유저 드랍 만료 서술 정정)를 조사하다 발견했다.

## 핵심 요약
- 요구사항: `inventory_items.expires_at`(아이템 배지 개체의 만료)을 지급 경로별로 실제 코드와 대조해 `docs/service/SERVICE_OPERATIONS.md`를 현재 동작에 맞춘다.
- 구현 계획: 지급 경로(동기화 드랍·믹스 보상·미션 보상·드랍 이벤트)마다 `grant_inventory_item`에 넘기는 `p_expires_at`을 확인하고 문서 줄을 고친다. 문서만 바꾼다.
- 관련 파일: `docs/service/SERVICE_OPERATIONS.md` 446행(동기화 드랍 6단계 `expires_at: now + 30일`)·519행(드랍 이벤트 `만료 30일`)·538행(7-1 인벤토리 구조 `expires_at: 획득일 + 30일`), 코드 근거 `jam-web/src/lib/drop-engine/index.ts` 509~516행(`picked.valid_until ?? null`), `jam-web/src/lib/combine/index.ts` 426~430행(+30일), `jam-web/src/lib/missions/rewards.ts` 124~128행(`p_expires_at` 없음)

## 배경 / 문제 정의

`SERVICE_OPERATIONS.md`는 아이템 배지가 획득일부터 30일 뒤 만료된다고 적지만, 코드는 지급 경로마다
다르게 동작한다. 2026-10-07 확인한 사실:

- 동기화 드랍: `drop-engine/index.ts`가 `p_expires_at`에 배지의 `valid_until`(없으면 NULL)을 넘긴다. 30일 계산이 없다.
- 믹스 보상: `combine/index.ts`가 지급 시점 + 30일을 넘긴다. 문서(628행 6-a)와 일치한다.
- 미션 보상: `missions/rewards.ts`가 `p_expires_at`을 넘기지 않는다. `grant_inventory_item`의 기본값은 NULL이다.
- 드랍 이벤트(519행): 아직 확인하지 않았다.
- 운영 DB(읽기 전용 조회): 2026-09-01 이후 생긴 `inventory_items` 중 `obtained_by`가 `drop`(91건)·`ambient_drop`(936건)·`seed`·`system_event`인 행은 모두 `expires_at`이 NULL이다.

재설계 진행 노트(`docs/plan/jam2/09 JAM! 서비스 재설계 진행 노트.md` 282행, 6-8)가
이 문서를 근거로 "동기화, 미션 보상, 믹스로 받은 아이템 배지는 받은 날부터 30일 뒤 만료된다"고
인용했다. 코드 기준으로 30일 만료는 믹스 보상뿐이므로, 그 노트의 전제 설명(7-5 추천안과의 관계 포함)을
사용자가 다시 확인할 필요가 있다. 노트는 사용자 답 기록이라 이 티켓에서 고치지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 지급 경로 4개(동기화 드랍·믹스 보상·미션 보상·드랍 이벤트)의 만료값을 코드로 확인한다.
- `SERVICE_OPERATIONS.md` 446·519·538행을 확인한 동작으로 덮어쓴다. 같은 사실을 여러 줄에 반복하지 않고 7-1 인벤토리 구조를 단일 원천으로 둔다.

## 구현 계획
- `docs` 유형(카리나 직접 처리). 코드·DB는 바꾸지 않는다.

## 완료 조건
- `SERVICE_OPERATIONS.md`의 아이템 배지 만료 서술이 지급 경로 4개의 코드와 일치한다. 재현: 각 경로의 `grant_inventory_item` 호출부 `p_expires_at` 인자와 문서 줄을 나란히 대조한다.
- 재설계 노트 6-8의 전제가 어긋난다는 사실을 사용자에게 보고했다.

### 주요 의사결정 / 핵심 메모
- 이번 작업은 사용자가 티켓 20261007_2119와의 범위 겹침을 확인해 달라고 요청하며 시작됐다. 2119는 `poi_drops.expires_at`(POI에 놓인 드랍)을 다뤄 범위가 겹치지 않았고, 범위가 같은 이 티켓에서 처리하기로 사용자가 정했다(새 티켓 없음).
- 지급 경로를 티켓에 적힌 4개에서 6개로 넓혔다. 시스템 드랍과 POI 픽업도 개체를 인벤토리에 넣는 경로이고, 어드민 시뮬레이션은 실제 드랍과 같은 `obtained_by: 'drop'`을 쓰면서 만료값이 달라 표에 없으면 표가 틀린 사실을 말하게 된다.
- 운영 DB의 수치(공개 종료일 있는 배지 0개 등)는 시점에 따라 바뀌므로 스펙 문서에 적지 않고 이 티켓에만 남겼다.
- 코드는 고치지 않았다. 어드민 시뮬레이션이 실제 드랍과 다르게 지급하는 문제는 범위 밖 발견물 20261008_1106으로 분리했다.
- `docs/agents/contract.json`에 검사 줄은 추가하지 않았다. 2119와 같은 판단으로, 이 계약은 에이전트 환경에 대한 주장을 다루고 이번 사실은 서비스 데이터의 동작이다.
- 재설계 진행 노트(`09 JAM! 서비스 재설계 진행 노트.md` 288행, 6-8)는 "동기화, 미션 보상, 믹스로 받은 아이템 배지는 받은 날부터 30일 뒤 만료된다"고 옛 서술을 인용한다. 코드 기준으로 30일 만료는 믹스 보상과 어드민 시뮬레이션뿐이다. 노트는 구상 단계 문서이고 사용자 답 기록이라 고치지 않았고, 완료 보고에서 사용자에게 알렸다.
