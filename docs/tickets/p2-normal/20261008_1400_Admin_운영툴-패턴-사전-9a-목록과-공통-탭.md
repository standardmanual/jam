## 설계 결정 (2026-10-08, 채원 판정 승인 + 카리나 가정)

- **D1 범위 경계(카리나 가정)**: ⑨a는 목록·공통 탭·제안 줄·사이드바·칩 2종(`pattern-status`·`taste-basis`)만 만든다. 목록 행은 **링크를 걸지 않는다**(상세 경로는 ⑨b가 만든다. 링크가 404로 남지 않게 ⑨b가 행 링크를 단다).
  [+ 새 패턴 만들기] 버튼은 ⑩a, 공통 탭의 [고치기]·[이유 고치고 확정하기]는 ⑩b가 단다.
- **D2 세기 함수(채원 위험 4)**: `draw.ts`에 순수 함수 `countOpsPatternUsage(rows, patternNos, now)`를 두고 `Map<patternNo, { uses, lastUsedAt }>`를 돌려준다. 규칙은 지금 `rankOpsDraw`와 같다(시험 제외, 승인 이후 상태,
  `pattern_proposal` 제외, `usageTimeOf`, 최근 28일, 마지막 사용은 기간과 무관). `rankOpsDraw`는 사용 중 패턴 번호로 이 함수를 부른다(응답 불변, 기존 테스트 그대로 통과). S5는 모든 상태의 번호로 부른다.
- **D3 승인 대기 제안 건수**: `ops_bundle_items`에서 `kind = 'pattern_proposal'`이고 상태가 결정 전(`arrived`·`reviewing`)이며 시험이 아닌 묶음(`ops_bundles!inner(is_sample)` + `.eq('ops_bundles.is_sample', false)`)의 개수.
  읽기 함수는 `opsPatterns/read.ts`에 `countPendingPatternProposals(service)`. 링크는 `/admin/ops-inbox?tab=decide`(기존 링크 함수가 있으면 그것). 0건이면 muted 「승인 대기 제안이 없어요」, 링크 없음.
