## 설계 결정 (2026-10-08, 채원 판정 승인 + 카리나 가정)

- **D1 경로·없는 번호(승인 5)**: `/admin/ops-patterns/[patternNo]`. 번호 형식이 `OPS_PATTERN_NO_PATTERN`과 다르거나 행이 없으면 `notFound()`. 보관 패턴도 번호로 열린다. 패턴 읽기가 **실패**하면 404가 아니라 `OpsSectionNotice` 「패턴을 불러오지 못했어요」.
- **D2 머리**: 「← 패턴 사전」(`IconArrowLeft` 링크, `patternListHref()`) → `P03  이름 [상태 칩] [출처 칩 아님: muted 글자 「출처: 원고 입력|직접 만듦|제안 승인」]`. 쉬는 중이면 아래 muted 「쉬는 이유: …」(비었으면 ⑨a와 같은 「쉬는 이유: 적지 않았어요」).
  [수정하기]·[상태 바꾸기 ▾]는 ⑩a가 단다(자리 비움). **카리나 가정**: 출처는 칩이 아니라 muted 글자로 둔다(새 칩 종류를 늘리지 않음, 판정 원문 `[출처: …]`의 괄호는 묶음 표기로 읽음). 모르는 출처 값은 「출처 확인 필요」.
- **D3 본문 구역(`SectionCard`, 순서 = 목차)**: 요약 · 손잡이 · 샘플 · 주의점 · 취향 신호 · 사용 이력 · 결과.
  - 요약: 작동 원리 · 유저가 겪는 것 · 쓰는 메뉴(쉼표 목록) · 카드 모양(모양 이름 + 메모). `ReadOnlyGrid`/`ReadOnlyItem`.
  - 손잡이: 조건·장소·시간·보상은 「열 수 있는 값 | 닫은 값」 두 칸, 트라이브는 「규칙 | 예시」.
  - 샘플: 번호 · 이름 · 역할(`main` 주 · `aux` 보조 · `related` 관련, 한국어 이름은 기존 상수가 있으면 그것) · 구현. 번호 순.
  - 주의점: `whitespace-pre-wrap`.
  - 취향 신호: 이 패턴 것만, `[추정]`/`[확정 · YYYY-MM-DD(KST)]` 칩 + 이름 + 이유. 근거 결정 ID가 있으면 「근거 반려 기록 있음」 muted 글자(링크는 ⑩b). 0건이면 「이 패턴에 정리된 취향 신호가 없어요」.
  - 사용 이력: D5. 결과: 「결과와 기록에서 봐요」 한 줄(링크는 ⑫a가 S6 경로를 만든 뒤 단다. 지금은 글자만 — **카리나 가정**, 404 링크를 남기지 않는다).
- **D4 JSONB 해석(깨져도 화면 유지)**: `detailView.ts`의 순수 함수가 `samples`·`cardShapes`·`knobs`를 칸 단위로 읽는다. 빈 칸·형식 틀린 칸은 「적지 않았어요」, 모르는 역할은 「역할 모름」, `CARD_SHAPES` 밖 모양은 「목록에 없는 모양」,
  배열이 아닌 `samples`·`cardShapes`는 그 구역 전체를 「적지 않았어요」. 0이나 빈 목록으로 바꿔 숨기지 않는다.
- **D5 사용 이력(승인 9)**: 요약 줄 「최근 4주 N회 · 마지막 사용 YYYY-MM-DD HH:mm」(안 썼으면 「쓴 적 없어요」)은 `countOpsPatternUsage(rows, [patternNo], now)`.
  이력 줄은 같은 행에서 `countableUsedAt`이 시각을 돌려주고 패턴 번호가 이 패턴인 항목만(= 시험·승인 전·반려·취소·실패·`pattern_proposal`·시각 없음 제외), **기간 제한 없이** 사용 시각 최신순, 10건/쪽 `?usagePage=`(1부터, 틀린 값·범위 밖은 1쪽).
  줄 = 사용 시각(KST) · 종류(`kindLabel`) · 이름(`describeBundleItem`) · 항목 상태 칩(`item`) · 행 전체가 `opsTargetHref({ bundleId, itemId })` 링크. 0건이면 「아직 이 패턴을 쓴 기록이 없어요」. 읽기 실패는 구역 `OpsSectionNotice` 「사용 기록을 읽지 못했어요」(요약 숫자도 「–」).
  사용 기록 읽기는 `draw.ts`에 `loadPatternUsageRows(service)`(= `loadDrawUsageRows`와 같은 조건 + `bundle_id`·`item_key` 칸)를 두고, `countableUsedAt`을 export한다(조합 뽑기 동작 불변).
- **D6 레일(`RailCard`)**: 목차(`SectionNav`) · 마지막 수정 시각(KST, 수정한 사람은 안 보임 — 승인 15) · 만든 날. 56rem 미만 한 단(`EditorShell` 기본).
- **D7 구역 격리·상태**: 패턴(머리·요약·손잡이·샘플·주의점) / 취향 신호 / 사용 이력을 따로 읽는다. 구역별 스켈레톤, 실패는 그 구역만 `OpsSectionNotice`. 실패를 0이나 빈 상태로 보이지 않는다.
- **D8 목록 행 링크(⑨a D1 이월)**: `OpsPatternList`의 표 행과 카드 줄에 `patternDetailHref(patternNo)` 링크를 단다(이름 칸 `Link` + `after:absolute after:inset-0`, 행 `relative`). ⑨a 테스트의 「행에 링크 없음」 단정을 「행마다 상세 링크 1개」로 바꾼다.
- **D9 하지 않는 것**: DB·API 변경 없음(조합 뽑기·`ops-patterns` 읽기 API 응답 불변), 쓰기 버튼(⑩a)·취향 신호 확정(⑩b)·S6 링크(⑫a), 시험 스위치(S5에는 없음, 승인 4), 새 토큰, 새 칩 종류.
