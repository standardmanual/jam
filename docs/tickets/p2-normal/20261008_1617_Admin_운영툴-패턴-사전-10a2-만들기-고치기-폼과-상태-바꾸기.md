## 설계 결정 (2026-10-08, 채원 판정 승인 + 카리나 가정)

- **D1 경로**: `/admin/ops-patterns/new`, `/admin/ops-patterns/[patternNo]/edit`(서버 컴포넌트가 `getOpsPattern`으로 읽어 폼에 넘김, 없는 번호·틀린 형식 `notFound()`, 읽기 실패는 `OpsSectionNotice`). 보관 패턴도 고칠 수 있다(카리나 가정 — API가 막지 않음).
  `new`는 정적 세그먼트라 `[patternNo]`보다 먼저 잡힌다(테스트나 실렌더로 확인).
- **D2 폼 5구역(`SectionCard` + 레일 목차)**: 기본(이름*·작동 원리*·유저가 겪는 것*) / 쓰는 메뉴(칩 입력: 입력 후 Enter 또는 [더하기], 칩마다 지우기 버튼, 10개 상한)·카드 모양(모양 `Select` + 메모 줄, 줄 더하기·지우기) /
  손잡이 5종(조건·장소·시간·보상은 「열 수 있는 값」「닫은 값」, 트라이브는 「규칙」「예시」 `Textarea` 2개씩) / 샘플(번호·이름·역할 `Select`·구현 줄, 줄 더하기·지우기, 20개 상한) / 주의점(`Textarea`).
  칸 아래 글자 수(상한 근처에서만 보이는 정도는 아현 재량), 서버 `fieldErrors`는 같은 칸 아래 붉은 글(키 `samples.2.role`처럼 경로 → 그 칸).
- **D3 레일(`RailCard`, `RAIL_ACTIONS_CLASS`)**: [저장](고친 칸이 있을 때만 켜짐, 옆에 `UnsavedChip`), 「바뀐 칸 N개」 + 칸 이름 목록(고치기만), 안내 「이전 내용은 남지 않아요. 저장하면 에이전트가 바로 새 내용을 읽어요」, [취소](상세 또는 목록으로). **확인창 없음**(승인 13).
- **D4 만들기**: 저장 → `POST` → 201이면 `router.push(patternDetailHref(새 번호))` + 토스트 「P19를 만들었어요」(번호는 응답 값). 번호 충돌 409는 `SaveFailureAlerts` 경고에 ⑩a-1 문장(`PATTERN_CREATE_CONFLICT_MESSAGE`)을 그대로, [최신 값 불러오기] 대신 다시 저장하면 된다(카리나 가정 — 만들기에는 불러올 최신 값이 없다).
- **D5 고치기**: `PATCH`에 내용 칸 전체 + `expectedUpdatedAt`. **`expectedUpdatedAt`은 서버에서 받은 `updatedAt` 문자열을 가공하지 않고 그대로 보낸다**(⑩a-1 민지 [참고] — 시각을 `Date`로 바꿨다 되돌리면 자릿수가 달라져 매번 409). 200이면 상세로 + 토스트 「저장했어요」, `changed: false`면 「바뀐 내용이 없어요」.
  409(승인 14)는 입력 유지 + 경고 + [최신 내용 불러오기] → `OpsConfirmDialog` 「입력한 내용이 사라져요」 확인 → `router.refresh()`로 다시 읽어 폼을 새 값으로 바꾼다. 번호·출처·상태는 폼에 없다(머리에 글자로만).
- **D6 입력 검사**: 저장 전에 클라이언트에서 같은 `validateOpsPatternInput`(D 관련 파일의 `input.ts`)으로 막고, 서버 `fieldErrors`도 같은 자리에 보인다. 첫 오류 칸으로 포커스.
- **D7 이탈 경고**: 고친 칸이 있으면 `beforeunload` 경고(작은 훅 `usePatternLeaveGuard`, 저장 성공·취소 확인 뒤 해제). 앱 안 링크 이동은 막지 않는다(카리나 가정 — Next 라우터 가로채기는 범위 밖, [취소]는 고친 칸이 있으면 `OpsConfirmDialog` 「입력한 내용이 사라져요」).
- **D8 상태 바꾸기(승인 12)**: 상세 머리 `[상태 바꾸기 ▾]`(`DropdownMenu`) → 지금 상태에 따라 항목: 사용 중이면 「쉬게 하기」·「보관하기」, 쉬는 중이면 「다시 사용하기」·「쉬는 이유 고치기」·「보관하기」, 보관이면 「다시 사용하기」.
  각 항목은 `OpsConfirmDialog`: 쉬게 하기·쉬는 이유 고치기(이유 `Textarea` 필수 200자, 설명 「조합 뽑기에서만 빠져요. 이미 예약된 항목에는 영향이 없어요」), 다시 사용하기(「조합 뽑기에 다시 나와요」 — 카리나 가정 문구), 보관하기(「목록에서 숨고 조합 뽑기에서 빠져요. 번호와 취향 신호는 남아요」).
  성공하면 토스트 + `router.refresh()`. 409는 창 안 `error` 「그사이 상태가 바뀌었어요」 + [새로 읽기](`router.refresh()` 후 창 닫음). 「쉬는 이유 고치기」는 같은 상태 요청(⑩a-1 D5가 허용).
- **D9 버튼 자리**: 상세 머리에 [수정하기](링크 버튼, `edit` 경로) [상태 바꾸기 ▾]. 목록 머리 오른쪽 [+ 새 패턴 만들기](링크 버튼). 버튼은 어드민 `Button` 기존 변형만, 새 토큰 없음.
- **D10 하지 않는 것**: DB·API 변경(⑩a-1에서 끝남), 취향 신호·공통 규칙 고치기(⑩b), 제안 승인 연결(⑪), 앱 안 링크 이동 가로채기, 삭제.

## 완료 조건

- 목록 머리 [+ 새 패턴 만들기] → `/admin/ops-patterns/new` 폼, 상세 머리 [수정하기] → `edit` 폼, [상태 바꾸기 ▾] → 상태별 항목과 확인창.
- 저장하면 ⑩a-1 API로 가고, 만들기는 새 번호 상세로 이동, 고치기는 상세로 돌아간다. 고친 칸이 없으면 저장이 꺼져 있고 「바뀐 칸 N개」가 칸 이름과 함께 보인다. 확인창 없이 저장한다.
- 409면 입력이 남고 경고와 [최신 내용 불러오기]가 보이며, 불러오기 전에 「입력한 내용이 사라져요」 확인을 받는다. `expectedUpdatedAt`은 받은 문자열 그대로다(테스트).
- 쉬게 하기는 이유가 필수다. 상태 409는 창 안 오류로 보인다. 입력 검사 오류는 칸 아래에 보인다. 고친 칸이 있으면 창 닫기·새로 고침에 경고가 뜬다.
- 320px에서 가로 스크롤 없음. 새 토큰 0. `scripts/verify.sh` 통과. DB·API 동작 변경 없음(검사 함수 이동만).
