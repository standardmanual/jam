## 설계 결정 (2026-10-08, 채원 판정 승인 + 카리나 가정)

- **D1 취향 신호 줄 안 펼침(승인 16·17, 패턴 상세)**: 줄의 버튼 글자는 추정이면 「이유 고치고 확정하기」, 확정이면 「이유·근거 고치기」. 펼치면 첫 입력(이유 `Textarea`, 현재 이유 원문 채움, 500자)으로 포커스, 닫으면 누른 버튼으로 포커스 복귀, `motion-safe` 200ms 페이드.
  버튼: 추정이면 [확정하기], 확정이면 [저장하기], 그리고 [취소]. 한 번에 한 줄만 펼친다(다른 줄을 열면 앞 줄은 닫힘 — 카리나 가정, 고친 내용이 있으면 닫기 전에 그대로 버린다, 확인창 없음).
- **D2 근거 선택(`OpsEvidencePicker`)**: 펼칠 때 `GET …/rejections`(offset 0)를 부른다. 머리글 `fieldset`/`legend` 「같은 패턴 항목의 반려 기록 N건 — 근거로 붙일 수 있어요(선택)」(N = `total`), 네이티브 라디오(새 ui 부품 없음).
  첫 선택지 「근거 없이 확정」(기본). 확정 신호에 근거가 있으면 그 결정이 기본 선택이고, 불러온 목록에 없으면 맨 위에 「지금 붙은 근거 유지」 선택지를 둔다(카리나 가정 — 목록 밖 근거를 잃지 않게).
  반려 줄: 날짜(KST) · `decisionLineText` · 항목 이름 · 반려 이유(없으면 생략) · [기획 보기](S3 링크 `opsTargetHref({ bundleId, itemId })`, 라디오 `label` 밖에 둬 클릭이 겹치지 않게). [더 보기]는 `hasMore`일 때, 10건씩 이어 붙이고 같은 `id`는 한 번만.
  0건이면 「붙일 반려 기록이 없어요. 근거 없이 확정할 수 있어요」. 읽기 실패는 줄 안 muted 「반려 기록을 불러오지 못했어요」 + [다시 시도], 근거 없이 확정은 계속 가능.
- **D3 저장(취향 신호)**: 클라이언트 검사(`validateTasteSignalInput`) → `PATCH`(`expectedUpdatedAt`은 받은 `updatedAt` 문자열 그대로) → 200이면 토스트(처음 확정 「확정했어요」, 그 밖 「저장했어요」, `changed: false`면 「바뀐 내용이 없어요」), 펼침 닫기, `router.refresh()`, 줄 1.2초 `bg-muted` 잔상.
  400 `fieldErrors`는 칸 아래(`evidenceDecisionId`는 근거 묶음 아래). 409는 줄 안 경고(서버 문장) + [최신 값 불러오기] → `router.refresh()` 후 펼침을 닫는다(카리나 가정 — 줄 안 편집은 입력이 짧아 확인창 없이). 추정으로 되돌리는 버튼은 없다.
- **D4 공통 취향 신호(공통 탭)**: 같은 편집 부품을 근거 없이(`evidenceDecisionId: null` 고정, 근거 묶음 자리 없음) 쓴다. 버튼 글자 규칙은 D1과 같다.
- **D5 공통 규칙 고치기(승인 19, 공통 탭)**: 규칙마다 [고치기] → 줄 안 펼침(제목 `Input` 60자 + 본문 `Textarea` 2,000자, 현재 값 채움) + [저장하기]·[취소]. [저장하기]는 고친 칸이 있을 때만 켜지고(`UnsavedChip`), 누르면 `OpsConfirmDialog`
  「모든 패턴에 적용되는 규칙이에요. 저장하면 에이전트가 바로 새 내용을 읽고, 이전 내용은 남지 않아요」 → `PATCH` → 토스트 「저장했어요」 + `router.refresh()` + 잔상. 409·400은 D3과 같다. 추가·삭제 버튼은 없다. 기존 [전체 보기]/[접기]는 읽기 상태에서 그대로.
- **D6 읽기 모양 확장**: `TasteSignalLine`에 `updatedAt`·`evidenceDecisionId`·`reasonRaw`(원문)를 더한다(표시용 `reason`은 그대로). 공통 탭은 `OpsTasteSignalRecord`·`OpsCommonRuleRecord`를 그대로 넘긴다(둘 다 `updatedAt` 있음).
- **D7 하지 않는 것**: DB·API 변경, 취향 신호 추가·삭제(승인 18), 공통 규칙 추가·삭제, 추정으로 되돌리기, 이탈 경고(줄 안 편집 — 카리나 가정), 반려 창 변경.

- 상세 취향 신호 줄에서 이유를 고치고 근거(선택)를 골라 확정하면 ⑩b-1 API로 가고, 새로 읽은 줄이 「확정 · 날짜」 칩으로 바뀐다. 확정 뒤에도 이유·근거를 고칠 수 있고 추정으로 되돌리는 버튼은 없다.
