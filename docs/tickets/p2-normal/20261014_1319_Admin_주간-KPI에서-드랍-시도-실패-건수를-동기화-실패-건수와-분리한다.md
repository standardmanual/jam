# [Admin] 주간 KPI에서 드랍 시도 실패 건수를 동기화 실패 건수와 분리한다

## 핵심 요약

- 요구사항: 주간 KPI의 `stravaSyncFailures`가 `failure_type = 'drop_attempt_failed'` 행을 세지 않게 하고, 그 행의 건수를 새 필드 `dropAttemptFailures`로 따로 반환한다.
- 구현 계획: `computeKpiWeeklyMetrics`가 `strava_sync_failures`를 한 번 세던 조회를 둘로 나눈다. 기존 조회에는 `.neq('failure_type', 'drop_attempt_failed')`를 붙이고, 새 조회는 같은 기간을 `.eq`로 센다. 응답 타입·정의 문구·테스트를 함께 고친다. 후속 티켓 20261014_1320의 선행 작업이고, DB 변경은 없다.
- 관련 파일:
  - `jam-web/src/lib/admin/kpiWeekly.ts`: 응답 타입 `stravaSyncFailures`(83줄), 정의 문구 `DEFINITIONS`(104줄), 조회 `computeKpiWeeklyMetrics`(169~194줄, `Promise.all` 안의 `strava_sync_failures` 조회는 184~187줄), 반환(210~213줄)
  - `jam-web/src/lib/admin/__tests__/kpi-weekly.test.ts`: 모의 테이블 분기(48줄), 단언(151~152줄)
  - 소비처 확인만: `jam-web/src/app/admin/DashboardSignals.tsx`, `jam-web/src/app/admin/_home/sections.tsx`, `jam-web/src/app/admin/__tests__/home-sections.test.tsx` (기존 필드는 이름과 의미를 유지하므로 수정이 필요 없는지만 본다)
  - 문서: KPI 주간 응답 필드를 서술한 `docs/service/prd/admin-ui/ADMIN_PRD.md`, `docs/service/prd/04_PROJECT_SPEC.md`에서 해당 서술이 있을 때만 갱신한다. `docs/service/prd/02_DATA_MODEL.md`는 티켓 20261014_1320이 고치므로 이 티켓에서는 건드리지 않는다(두 티켓의 병합 충돌 방지).

## 배경 / 문제 정의

2026-10-14 위험 진단 검토의견을 코드와 대조하다가, 동기화의 드랍 시도 오류가 콘솔 로그만 남기고 해당 활동이 처리 완료로 표시되어 복구 경로가 없다는 점을 확인했다(`jam-web/src/lib/strava/sync.ts` 1011줄 catch). 후속 티켓 20261014_1320이 이 오류를 `strava_sync_failures`에 기록한다.

그 행이 기존 「동기화 실패 건수」에 섞이면 동기화는 성공했는데 실패 건수가 늘어 보인다. 그래서 집계를 먼저 분리한다. 이 티켓은 새 유형의 행이 아직 없어도 안전하게 배포되며, 그 경우 `dropAttemptFailures`는 0이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 기존 필드 `stravaSyncFailures`의 이름과 응답 모양은 바꾸지 않는다. 정의 문구에는 「드랍 시도 실패는 제외」를 명시한다.
- 새 필드 `dropAttemptFailures`는 `stravaSyncFailures`와 같은 `{ value, definition }` 모양이다.
- 두 조회 모두 `occurred_at` 기간 조건은 기존과 같다. user_id는 응답에 포함하지 않는다(상위 티켓 20260918_1307 §4-6).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 기간 안에 `failure_type = 'drop_attempt_failed'` 행이 섞여 있어도 `stravaSyncFailures.value`는 그 행을 제외한 건수다. 테스트로 고정한다.
- 응답에 `dropAttemptFailures: { value, definition }`이 있고, 같은 기간의 해당 유형 건수를 반환한다. 테스트로 고정한다.
- 기존 테스트와 타입 검사가 그대로 통과한다.
- KPI 응답 필드를 서술한 PRD가 있으면 새 필드가 반영된다.
