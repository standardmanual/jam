# [API] 유저 검색이 이메일 부분일치를 써서 다른 유저의 이메일 일치 여부가 드러난다

## 핵심 요약

- 요구사항: 유저 검색이 `email`로 일치시키지 않게 하거나, 일치시키더라도 본인 이메일만 대상으로 한다.
- 구현 계획: `username`과 `display_name`으로만 검색한다. 이메일로 찾는 기능이 의도된 것이라면 정확히 일치할 때만 허용하고 호출 빈도를 제한한다.
- 관련 파일: `jam-web/src/app/api/users/search/route.ts`(`.or(...email.ilike...)`, 45~52줄 부근), `jam-web/src/app/(main)/search/page.tsx`(53줄 부근, 같은 조건)

## 배경 / 문제 정의

### 확인한 사실 (2026-10-14, 코드를 직접 읽어 확인)

- 라우트가 서비스 롤로 `users`를 `username.ilike.%q%,email.ilike.%q%`로 조회한다. 주석에 「email로도 검색해야 하므로 RLS 우회」라고 적혀 있다.
- 응답에는 `id`, `username`, `display_name`, `avatar_url`만 담겨 이메일 자체는 나가지 않는다.
- 그러나 로그인한 유저는 검색어를 바꿔 가며 어떤 이메일 조각이 존재하는지 알아낼 수 있다(일치 여부 오라클). 예를 들어 `gmail`로 검색하면 gmail 이메일을 가진 유저가 모두 나온다.

### 판단

- 이번 배포가 만든 문제가 아니다. 민지 모드 ② 보안 점검이 짚었고 위 사실은 직접 확인했다. 배포 차단 사유는 아니다. 위험도: 주의, 확신도 높음.
- 같은 배포에 들어 있는 프로필 노출 수정(티켓 20261008_1354)과 같은 자산(이메일)을 다룬다.

## 완료 조건

- 검색 조건에 `email`이 없다(또는 본인 이메일 정확 일치로만 한정된다).
- 검색 결과가 이메일에 의해 달라지지 않음을 테스트로 고정한다.
