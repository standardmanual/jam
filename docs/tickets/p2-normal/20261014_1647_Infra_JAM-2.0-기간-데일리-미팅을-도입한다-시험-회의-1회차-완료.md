# [Infra] JAM 2.0 기간 데일리 미팅을 도입한다 (시험 회의 1회차 완료)

## 핵심 요약

- 요구사항: 에이전트들이 매일 저녁 8시에 JAM! 서비스에 대한 데일리 미팅을 하고 대화를 리포트로 남긴다. 사용자가 리포트를 읽고 피드백을 주어 발전시킨다(2026-10-14 사용자 요청).
- 구현 계획: 진행 규칙을 `docs/operations/daily-meeting.md`에 두고, 사회자가 에이전트 6명을 **한 라운드**로 병렬 호출한 결과를 `docs/operations/reports/daily/YYYY-MM-DD.md`로 남긴다(2라운드는 의미가 적다는 사용자 판단, 2026-10-14). **월·수·금** 20:00 KST 클라우드 루틴 `trig_01MVcETJSaatpjrj3MgBHxi7`로 자동 실행한다(사용자 요청. 처음에는 매일이었으나 같은 날 사용자가 주 3회로 줄였다).
- 관련 파일: `docs/operations/daily-meeting.md`(신규), `docs/operations/reports/daily/2026-10-14.md`(신규), `docs/operations/reports/README.md`(구조·읽기 상한 한 줄씩)

## 배경 / 문제 정의

- 2026-10-07에 사용자가 예약 루틴을 모두 삭제했다. JAM 2.0 리뉴얼로 옛 루틴이 의미 없어졌기 때문이다(2026-10-14 사용자 설명). 그 뒤 지표 점검과 리포트를 도는 곳이 없다.
- 사용자가 에이전트 간 데일리 미팅을 요청했고, 안건은 사회자가 스스로 정해 진행하라고 했다. 이 티켓은 그 도입을 추적한다.

## 확인한 사실 (2026-10-14)

- 시험 회의 1회차를 수동으로 열었다. 참석 6명(혜린·카즈하·채원·윈터·윤진·하니), 2라운드, 12건 발언.
- 사용량: 1라운드 217,794토큰, 2라운드 136,300토큰, 합계 354,094토큰(사회자 제외). 같은 시점 계정 한도는 5시간 19%, 주간 85%였다.
- 합의 3건, 이견 2건, 사용자 결정 요청 4건이 나왔다(리포트 참고).
- 서브에이전트는 서로 직접 말을 걸지 못해, 사회자가 앞선 발언을 다음 라운드의 입력으로 넘기는 방식으로 대화를 만들었다.
- 사용자가 「1·2라운드를 나누는 것이 크게 의미 없다」고 판단해 한 라운드로 줄이고, 자동 실행 등록과 리포트 저장 위치 결정을 맡겼다(2026-10-14). 저장 위치는 `docs/operations/reports/daily/`로 정했다. 리포트 폴더의 규칙(덮어쓰지 않음, 읽기 상한)과 루틴 커밋 제한(`docs/operations/reports/` 안만)에 맞는다.
- 클라우드 루틴 `trig_01MVcETJSaatpjrj3MgBHxi7`을 만들었다(처음 cron `0 11 * * *`였다가 사용자 요청으로 `0 11 * * 1,3,5`로 바꿨다. 환경 `jam-ops`, 모델 `claude-sonnet-5-5`). **생성 응답에 계정의 커넥터 11개가 지정하지 않았는데도 붙어 있어 모두 제거했다**(`clear_mcp_connections`, 조회로 `mcp_connections: []` 확인).

- 클라우드 시험 실행에 성공했다(2026-10-14, 세션 실행 약 2분). 리포트 `daily/2026-10-14-2.md` 한 파일만 커밋해 staging에 push했고 작성자는 `noreply@anthropic.com`이며 훅과 커밋 제한을 통과했다. 서브에이전트 여섯 명 합계 104,608토큰, 합의 3건, 결정 요청 2건이다. 사용한 커넥터는 없었다(실행 기록에 외부 도구 호출이 없다).
- 시험 실행에서 찾은 개선 두 가지를 루틴 프롬프트에 반영했다. 「오늘 날짜 리포트가 있으면 열지 않는다」는 중복 방지 규칙과, 이틀에서 사흘 간격에 맞춘 「지난 회의 이후」 변경 이력 읽기다.
- 중복 방지 규칙을 수동 실행으로 확인했다(9초, 서브에이전트 호출·파일·커밋 없음). 확인 뒤 2026-10-14 18:41 KST에 루틴을 켰다. 오늘 20:02 KST의 첫 발동은 같은 규칙으로 회의 없이 끝나고, 회의가 열리는 첫 정기 실행은 금요일 20:00 KST다.
- 한계: 서브에이전트 다수가 읽기 도구를 1~3회만 써서 발언이 얕다. **정정(2026-10-15)**: 도구 1회는 결과를 돌려주는 보고 동작이었고, 하니를 뺀 다섯 명은 읽기를 하지 않았다(티켓 20261015_1103의 측정).
- 사용자 결정(2026-10-15, 리포트 피드백 칸): ① 어드민 조치 공통 변경 기록 반영 → 「JAM 2.0 서비스 운영 로직」 1.4절에 넣었다. ② 테스트 유저 8명에게 알리지 않는다. ③ JAM 2.0 완료 전까지 점검은 필요할 때 수동으로 요청한다 → 티켓 20261007_1956을 OPEN으로 바꿨다. ④ 자동 실행은 지금 등록한다(월·수·금으로 등록 완료). 자동 실행 1회차의 결정 요청 2(로고·파비콘)는 「2.0에서 진행함」 → 티켓 20260925_1125에 기록했다.
- 피드백 처리에서 찾은 문제: 자동 실행 1회차의 결정 요청 2는 「아직 적용 전」이라는 전제로 물었으나 로고는 이미 프로덕션에 있었다. 사회자가 티켓을 읽지 않고 발언을 결정 요청으로 올렸다. 회의 규칙에 「결정 요청으로 올리는 티켓은 사회자가 상태와 완료 기록을 읽고 올린다」를 더했다. 실행 기록의 완료 시각이 실제 저장보다 약 1분 빨랐다(사회자가 응답을 한 번 끝냈다가 서브에이전트 발언이 도착해 이어졌다).

## 비용 재계산과 조정안 (2026-10-15, 4단계, 결정 대기)

기준은 회당 50,000토큰 이하(서브에이전트 합계, 사회자 제외, 사용자 요청 2026-10-15)다. 아래 「재계산」과 「예상」은 추정이고, 2026-10-16 첫 정기 실행의 실측으로 갱신한다.

| 발언자 | 시험 실행 실측(2026-10-14) | 정의 정리로 줄어든 양(측정, 「확인」만 답한 호출) | 재계산 |
|---|---|---|---|
| 혜린 | 11,413 | 없음 | 11,413 |
| 채원 | 15,062 | 2,267 | 12,795 |
| 윈터 | 12,857 | 없음 | 12,857 |

| 윤진 | 22,929 | 8,477 | 14,452 |
| 하니 | 23,242 | 없음 | 23,242 |
| 합계 | 104,608 | 13,024 | 약 91,600 |

- `CLAUDE.md` 정리(티켓 20261015_1225)는 호출당 약 250토큰이라 여섯 명에 약 1,500토큰이다. 합쳐 약 90,000토큰이고 기준까지 약 40,000토큰이 남는다.
- 읽기를 하지 않은 발언의 값이 바닥이다(혜린 11,413). 가장 싼 네 명(혜린·채원·윈터·윤진)의 합이 약 51,500, 세 명의 합이 약 37,000이다. 여섯 명을 모두 부르면 정의 문서를 더 줄여도 50,000에 닿지 않는다.
- 하니(23,242)와 카즈하(19,105)가 비싼 까닭은 읽기 도구를 쓴 데 있다. 프롬프트는 읽기를 8회까지 허용하므로 읽기를 늘리면 한 명의 값이 더 커진다.

| 안 | 내용 | 회당 예상(추정) | 장단 |
|---|---|---|---|
| A | 회의마다 세 명: 혜린 고정, 나머지 둘은 사회자가 그날 사실에 맞춰 고르고 이유를 리포트에 적는다. 여섯 명 전원은 주 1회 | 약 37,000~45,000 | 기준을 채운다. 한 회의의 시선은 셋이다 |
| B | 여섯 명 유지, 읽기 0회, 발언 450자 | 약 75,000 | 기준 미달이고 발언이 더 얕아진다 |
| C | 기준을 회당이 아니라 주간 합계로 바꾼다 | 주 3회 합계 약 270,000 | 기준 변경이 필요하다 |

- 사회자 추천: A에 읽기 상한 8회를 3회로 낮추고, 사회자가 각자에게 읽을 파일 한두 개를 지정해 준다. 탐색 비용을 줄이면서 확인 범위를 사회자가 정할 수 있다.
- 적용하려면 `docs/operations/daily-meeting.md`의 「참석」·「진행」·「비용」 절과 클라우드 루틴 프롬프트의 2단계를 고친다. 루틴 프롬프트는 저장소 밖(claude.ai/code/routines)에 있어 `RemoteTrigger`로 고치며, 문서와 프롬프트가 다르면 문서를 따른다.
- **사용자 결정(2026-10-15)**: 2026-10-16 금요일 첫 정기 실행의 실측을 보고 정한다. 그때까지 루틴 프롬프트와 `daily-meeting.md`는 고치지 않는다.
- 금요일 뒤 확인할 것: `docs/operations/reports/daily/2026-10-16.md`의 「사용 비용」 절에서 발언자별 토큰을 위 「재계산」 열과 견준다. 합계가 50,000 이하면 조정이 필요 없고, 90,000 안팎이면 위 A·B·C 중에서 고른다. 정의를 바꾼 뒤 처음 나가는 실행이라 `CLAUDE.md` 정리(티켓 20261015_1225)의 효과도 이 값에 들어 있다.

## 완료 조건

- 사용자가 리포트 형식과 안건에 대한 피드백을 주고, 그 반영이 `docs/operations/daily-meeting.md`에 남는다.
- 루틴의 시험 실행이 리포트를 `docs/operations/reports/daily/`에 커밋하는 데 성공하고, 그 결과를 확인한 뒤 루틴을 켠다(시험 실행은 성공했다). 첫 정기 실행(2026-10-16 금요일 20:00 KST)이 리포트를 저장했는지 파일로 확인하고, 사용자가 그 결과를 읽고 피드백을 준다.
- 회의가 올린 결정 요청 1~3에 대한 사용자의 답이 기록된다.
