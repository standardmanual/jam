# [UI] JAM 2.0 디자인 시스템(Modulor V2)을 서비스에 적용한다 (상위)

## 핵심 요약

- 요구사항: [JAM 2.0 디자인 시스템](<../../plan/jam2/11 JAM 2.0 디자인 시스템.md>)을 유저 화면 전체에 적용한다. 다크 테마를 라이트 테마로 바꾸고, 토큰 이름을 새 시스템 이름으로 모두 바꾼다.
- 구현 계획: 하위 티켓 5개를 아래 순서로 하나씩 진행한다. 하위 티켓마다 시작 전에 사용자에게 주요 결정을 질문창으로 묻는다.
- 관련 파일: `jam-web/design-system/tokens/`, `jam-web/src/app/globals.css`, `jam-web/src/components/ui/`, `jam-web/design-system/components/`

## 배경 / 문제 정의

JAM 2.0 디자인 단계에서 사용자가 새 디자인 시스템(피그마 `JAM-Modulor-V2`)을 정의했다(2026-10-15). 지금 서비스는 다크 전용 MODULAR 토큰을 쓴다.
비교 분석과 적용 기준은 [JAM 2.0 디자인 시스템](<../../plan/jam2/11 JAM 2.0 디자인 시스템.md>)에 있다. JAM 2.0 5단계(티켓) 가운데 디자인 시스템 적용만 사용자 요청으로 먼저 시작한다.

## 사용자 결정 (2026-10-15)

1. **작업 위치는 staging이다.** 별도 브랜치나 테마 스위치를 두지 않는다. 그래서 staging은 이 묶음이 끝날 때까지 일부 화면만 바뀐 라이트 테마가 된다.
   **JAM 2.0 출시 전까지 `/jam-ship`(staging → main)을 하지 않는다.** 프로덕션 긴급 수정은 main에서 따로 처리한다(방법은 그때 사용자와 정한다).
2. **토큰 이름은 새 시스템 이름으로 일괄 교체한다.** 기존 `--color-*` 등 옛 이름은 남기지 않는다. 새 시스템에 없는 값(확장 토큰)도 새 시스템의 이름 규칙을 따라 이름을 바꾼다.
3. **하위 티켓 5개, 순서는 ①토큰 → ②서체 → ④공통 컴포넌트 → ③직접 적은 색 → ⑤스토리북·DESIGN.md다.** 아래 표의 ID 순서가 진행 순서다.
4. **하위 티켓마다 시작 전에 주요 결정을 질문창으로 묻는다.** 질문 후보는 각 하위 티켓의 「시작 전에 사용자에게 물을 결정」에 있다. 추천안을 함께 보인다.
5. **실제 개발은 새 세션에서 시작한다.**
6. **디자인 시스템 문서 6절의 열린 항목은 우선 새 디자인 시스템 값 그대로 적용하고 나중에 바꾼다.** 진행 상태 선은 `warning`·`success`, 「방금 들어옴」 점은 `accent-blue`, 태그는 `accent-content` 6색 순환, 탭바 활성 아이콘은 `accent`, 모달 배경 blur는 0, mystic 칩은 흰 글자다.
7. 기존 피그마 파일(서비스 화면 파일, 리뉴얼 파일)은 참고하지 않는다.

## 완료 조건

- 하위 티켓 5개가 모두 CLOSED다.
- 유저 화면(어드민 제외)에서 옛 토큰 이름(`--color-*`, `--status-*` 등)을 참조하는 곳이 0건이다. 확인 명령은 하위 티켓 1의 완료 조건에 있다.
- staging(stage.j-a-m.app)에서 홈, 배지, 인벤토리, 지도, 프로필 화면이 라이트 테마로 보이고 다크 배경이 남은 영역이 없다.
