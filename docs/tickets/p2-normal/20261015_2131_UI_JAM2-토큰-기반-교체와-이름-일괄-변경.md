# [UI] JAM 2.0 토큰 기반 교체와 토큰 이름 일괄 변경

> 개발 세션의 카리나는 이 티켓을 시작하기 전에 아래 「시작 전에 사용자에게 물을 결정」을 질문창(AskUserQuestion)으로 묻고, 답을 「주요 의사결정」에 적은 뒤 아현을 부른다(상위 티켓 결정 4).

## 핵심 요약

- 요구사항: 서비스 토큰을 Modulor V2 값과 이름으로 바꾸고, 유저 화면 코드의 옛 토큰 이름 참조를 모두 새 이름으로 치환한다. 다크 전용 설정을 라이트로 바꾼다.
- 구현 계획: ① 새 토큰 파일 작성(값은 디자인 시스템 문서 2·3·4절) ② 옛 이름 → 새 이름 대응표를 데이터로 두고 치환 스크립트로 일괄 변경 ③ 옛 토큰 정의 삭제 ④ 옛 이름 0건 확인.
- 관련 파일:
  - `jam-web/design-system/tokens/colors.css`(151줄, 전체 재작성), `colors.light.css`(36줄, 삭제 후보), `typography.css`, `radius.css`, `spacing.css`, `motion.css`, `materials.css`
  - `jam-web/src/app/globals.css`: 1행 Pretendard import(하위 티켓 2에서 처리), 45~58행 `@theme`의 `--color-jam-*`·`--color-main/sub`(사용 0건, 삭제), 67~126행 `@theme inline` 매핑, 142~167행 서비스 전용 `:root`, 187~258행 `[data-admin-theme]` shadcn 실값, 499행 이후 `html`·`body`
  - 치환 대상: 어드민을 뺀 `jam-web/src`와 `jam-web/design-system` 229개 파일, 참조 3,989회(2026-10-15 측정, 스토리 49·테스트 22 포함). 어드민 코드에서 서비스 토큰을 쓰는 곳은 3개 파일(`--color-surface` 2회, `--spacing-16` 2회)이다

## 배경 / 문제 정의

상위 티켓 결정 2에 따라 옛 이름을 별칭으로 남기지 않고 새 이름으로 일괄 교체한다. 새 시스템 이름(`background`, `foreground`, `accent`, `border`, `muted` 등)은 어드민이 쓰는 shadcn 표준 이름과 겹친다.
shadcn 실값은 `[data-admin-theme]` 안에서만 정의되고, `@theme inline`이 `--color-accent: var(--accent)`처럼 전역에서 Tailwind 유틸리티로 이어 준다(globals.css 170~185행 주석).
겹치는 이름을 어떻게 나눌지가 이 티켓의 첫 결정이다.

## 시작 전에 사용자에게 물을 결정

1. **어드민 shadcn 이름과 겹치는 문제**
   - (추천) 서비스가 새 이름을 `:root`에 정의하고, 어드민은 지금처럼 `[data-admin-theme]` 안에서 같은 이름을 다시 정의해 덮는다. 다이얼로그처럼 어드민 범위 밖(`body` 바로 아래)에 그려지는 요소가 서비스 색을 받지 않는지 실렌더로 확인한다.
   - 서비스 토큰에 접두어를 붙인다. 충돌은 없지만 피그마 이름과 달라진다.
   - 어드민 shadcn 이름을 바꾼다. 어드민 109개 파일을 고쳐야 한다.
2. **글자 크기·간격·반경을 어떻게 쓸지**
   - (추천) 피그마의 `dimensions/*` 값이 Tailwind 기본 단계와 같으므로 Tailwind 기본 유틸리티(`text-xs`, `p-4`, `rounded-2xl`)를 쓴다. 단, 지금 `@theme inline`의 `--radius-md~4xl`이 shadcn 기준(`calc(var(--radius) * …)`)으로 덮여 있어 서비스 기준으로 되돌리는 방법을 함께 정한다.
   - 토큰 변수(`var(--text-sm)` 등)를 직접 쓴다.
3. **확장 토큰 이름 표 확인** (새 시스템 규칙 `그룹/그룹-변형` → CSS `--그룹-변형`을 따른 제안)
   - 희귀도 칩 글자색: `--rarity-common-foreground` 등 4개
   - 진행 상태: `--progress-short`, `--progress-done`, `--progress-latest`, `--progress-latest-soft`, `--progress-track`, `--progress-sweep`
   - 탭바: `--tabbar-background`, `--tabbar-blur`, `--tabbar-selection`, `--tabbar-icon`, `--tabbar-icon-active`
   - 레이아웃·모션·터치: `--layout-card-padding`, `--duration-*`, `--ease-*`, `--touch-target-min`은 이미 규칙에 맞아 그대로 둔다
4. **다크 테마 코드 처리**
   - (추천) 다크를 지운다. `colors.light.css`를 없애고 `color-scheme`을 light로 바꾼다. 스토리북의 라이트/다크 전환도 없앤다.
   - 다크 값을 다크 모드로 남겨 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 색 값은 디자인 시스템 문서 2절(사용자 결정)과 피그마 `JAM-Modulor-V2` Theme 컬렉션을 따른다. 결정 4·5에 따라 `separator`는 하나만, 검정 계열 역할 토큰은 `neutral-900`(#171717) 하나만 둔다.
- 옛 → 새 대응은 디자인 시스템 문서 3절 표를 따른다. `--color-primary`는 쓰임에 따라 채우기(`accent`)와 강조 글자(`link`)로 갈리므로 기계 치환하지 않고 파일마다 판단한다(문서 5.3절).
- 치환 스크립트는 대응표를 데이터로 두고 실행 결과(파일별 치환 수)를 남긴다. 스크립트는 `jam-web/scripts/`에 두고 실행 뒤 지울지 남길지는 구현 때 정한다.
- 화면별 다크 전제 하드코딩 색은 이 티켓 범위가 아니다(하위 티켓 4).

## 완료 조건

- `jam-web/src`(어드민 제외)와 `jam-web/design-system`에서 아래 옛 이름 참조가 0건이다: `--color-`(Tailwind 기본 팔레트 변수 제외), `--status-`, `--text-heading`, `--text-body`, `--text-caption`, `--text-small`, `--text-micro`, `--radius-card`, `--radius-pill`, `--blur-chrome`, `--blur-scrim`. 확인 명령과 결과를 완료 기록에 남긴다.
- `scripts/verify.sh`가 통과한다.
- 로컬 `next dev`(메인 트리)에서 홈 화면 바탕이 #fafaf0, 본문 글자가 #171717로 계산된다(`getComputedStyle`로 확인).
- 어드민 화면 하나(대시보드)와 어드민 다이얼로그 하나의 색이 바뀌기 전과 같다.
