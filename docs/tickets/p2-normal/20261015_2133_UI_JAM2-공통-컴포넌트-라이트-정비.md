# [UI] JAM 2.0 공통 컴포넌트를 라이트 테마로 정비한다

> 개발 세션의 카리나는 이 티켓을 시작하기 전에 아래 「시작 전에 사용자에게 물을 결정」을 질문창(AskUserQuestion)으로 묻고, 답을 「주요 의사결정」에 적은 뒤 아현을 부른다(상위 티켓 결정 4).

## 핵심 요약

- 요구사항: 새 시스템에 없는 공통 컴포넌트(TopNav, 카드류, BottomSheet)와 새 시스템에 대응 부품이 있는 컴포넌트(버튼, 입력창)를 새 토큰과 화면 규칙으로 정비한다. 탭바는 지금 디자인을 그대로 옮긴다.
- 구현 계획: 컴포넌트별로 새 토큰 적용 → 스토리 갱신 → 사용하는 화면 실렌더 확인.
- 관련 파일(사용 파일 수, 2026-10-15): `jam-web/src/components/ui/TopNav.tsx`(24), `ListRowCard.tsx`(16), `jam-web/design-system/components/cards/Card.jsx`(14), `BottomSheet.tsx`(9), `BadgeGridCard.tsx`(5), `CollectionGridCard.tsx`(2), `Button.tsx`(20), `TabBar.tsx`(1, 294줄, 248행 nav·264행 선택 필·286행 아이콘 색), `jam-web/design-system/components/forms/Input.jsx`

## 배경 / 문제 정의

디자인 시스템 문서 5.1절: 페이지 바탕은 `background`, 카드는 `surface` + 1px `border`, 그림자 없음. 흰 카드와 크림 바탕의 대비가 1.05:1이라 테두리가 없으면 카드가 보이지 않는다.
탭바는 사용자 결정 9(문서 4.3절)대로 지금 모양(흰 72% + blur 20px, 바 49×최대 388px)을 유지하고 전용 토큰만 쓴다.

## 시작 전에 사용자에게 물을 결정

1. **카드 톤 변형**: 지금 Card는 기본·틴트·반전 톤이 있다. (추천) 기본 → `surface` + `border`, 틴트 → `background-secondary`(테두리 없음), 반전 → `background-inverse`로 대응한다 / 반전 톤을 없앤다
2. **버튼 변형 대응**: (추천) 주 버튼 → `accent`, 보조 버튼 → `default`, 위험 동작 → `danger`, 외곽선 버튼 → `field/border` 테두리 / 다른 대응
3. **입력창 모양**: (추천) 새 시스템대로 캡슐형(`field/radius` 100)과 `field/*` 색을 쓴다 / 지금 반경 8px 유지
4. **TopNav 배경**: (추천) 페이지 바탕과 같은 `background`(불투명) / `surface`(흰색) + 아래 구분선
5. **탭바 위치의 바탕**: 크림 바탕 위의 흰 72% 탭바는 경계가 약하다. (추천) 지금 모양 그대로 두고 staging에서 눈으로 본 뒤 정한다 / `border` 1px 외곽선을 더한다

## 완료 조건

- 면(배경·카드 면)과 그 위의 글자·아이콘 색 짝을 전수 점검해 4.5:1(글자)·3:1(아이콘·UI 경계) 미만을 0건으로 만든다. 2131이 기계 치환으로 남긴 짝 어긋남이 재작업 3회에 걸쳐 나왔으므로 인계 절의 모든 항목을 이 점검으로 확인한다.

- 위 컴포넌트에 다크 전용 값(검정·흰색 반투명 직접 지정)이 남지 않는다.
- 각 컴포넌트의 스토리가 새 토큰으로 렌더된다(스토리북 실행 확인).
- 컴포넌트를 쓰는 화면 가운데 홈, 배지 목록, 미션, 알림, 프로필의 393px 폭 스크린샷에서 카드 경계가 보이고 그림자가 없다.
- 탭바의 크기·위치·선택 필 여백이 바뀌기 전과 같다(`getBoundingClientRect` 비교).

#### 알려진 임시 결함

- **카드 속 카드(이중 테두리)**: 지금 `RankingListRow`(= ListRowCard 흰 면 + 테두리)가 `ListCard`(흰 면 + 테두리) 안에 들어가고, 배지 상세의 획득 이력·미션 현황도 같은 구조다. 대응 없이 두면 테두리 박스가 박스 안에 들어가 무겁다. 승인 항목 3의 `tone="tint"`로 푼다.
- **가짜 테두리 혼용 금지**: `shadow-[inset_0_0_0_1px_var(--border)]`로 테두리를 흉내 낸 곳(`InventoryGrid.tsx:130`)과 실제 `border`를 섞지 않는다. 이번 회에서는 `border border-border` 하나로 통일한다. 선택·강조 링(2px `--link`)만 inset shadow로 둔다.
- **그라디언트·inset 하이라이트는 흰 면 위에서 효과가 없는 습관적 장식**이다. 걷고 새 장식(그림자·유리질·글로우)을 대신 얹지 않는다. 걷은 자리에 테두리를 빠뜨리지 않는다(티켓 인계 항목은 걷기만 적혀 있어 면 경계가 사라질 위험이 있다).
- **불투명도로 만든 글자색 금지**: `text-snow/60`을 `text-foreground/60`으로 옮기지 않는다. `text-muted` 토큰 하나로 통일한다.
- **장식 아이콘의 `opacity-50`**: TodayStatusStrip의 빈 셀 아이콘은 `text-muted opacity-50`이면 약 2.1:1이라 3:1에 못 미친다. 문구가 뜻을 전하는 장식 아이콘이고 EmptyState가 같은 값이라 예외로 두되, 점검표에 「장식 예외」로 적는다. 이 관례를 바꾸려면 EmptyState를 같이 바꿔야 한다.
- **tint는 크림 위 단독 카드로 쓰지 않는다**: `--background-secondary`(#f2f2f2)와 크림은 1.07:1이고 테두리가 없다. 서비스 호출 0건이므로 `Card.prompt.md`에 흰 카드 안 구획용이라고 한 줄 적는다.
- **LabelChip 윤곽**: 기본 칩 면 `--background`(크림)가 흰 카드 위 1.05:1이라 알약 모양이 거의 안 보이고 글자만 떠 보인다(옛 「짙은 회색 라벨 필」 의도 소실). 승인 항목 6.
- **사진 가장자리**: PosterCard·HeroCard·SquareCard는 이미지가 카드 가장자리까지 닿는데 1px 베이지 테두리가 사진 외곽에 선으로 남는다. 렌더로 보고 거슬리면 이미지 카드만 `style={{ borderColor: 'transparent' }}`가 아니라 테두리를 유지하는 쪽을 추천한다(이미지 실패·로딩 판이 `--background` 크림이라 테두리 없이는 흰 카드가 사라진다). 호출부별 예외를 만들지 않는다.
- **일괄 치환 금지**: `text-snow` → `text-foreground`를 기계적으로 하지 않는다. 면이 어두운 곳(`ArticleView` CTA·Toast·로그인 버튼·막 위 `text-white`)은 그대로 둔다. 면을 바꿀 때만 같은 변경에서 글자를 맞춘다.
- **작업 순서 권장(재작업 방지)**: ① Card + 문서·스토리 ② 서비스 inverse 호출부 한 묶음과 테스트 ③ 면 쌍(ListRowCard·BadgeGridCard·CollectionGridCard + InventoryGrid·BadgeTrophyGridCard) ④ 그라디언트 6곳·SlidingTabs·ProfileClient. 단계마다 vitest 후 다음으로. 2131의 9,000줄 일괄에서 재작업 3회가 나온 전례를 따른다.
- **범위 밖 발견물(민지 기록용)**: 온보딩 트라이브 카드가 `Card onClick`(`role="button"`)인데 선택 상태가 색으로만 전달된다(`aria-pressed` 없음). `MissionsListClient.tsx:52-66`은 `#FFFFFF`·`#B2B2B2` 제목·메타 글자와 `#1A1A1A` 썸네일 면이 남아 있다(2134). `MissionCard.jsx` 상태 칩 10px·기간 11px는 `--text-xs` 12px 아래다. `globals.css`에 `--tt-bg:#1a1a1a`·`--tabs-pill-bg:#ffffff` 같은 다크 기본값이 남아 있다.
