# [UI] JAM 2.0 디자인 시스템에 맞춰 스토리북과 DESIGN.md를 동기화한다

> 개발 세션의 카리나는 이 티켓을 시작하기 전에 아래 「시작 전에 사용자에게 물을 결정」을 질문창(AskUserQuestion)으로 묻고, 답을 「주요 의사결정」에 적은 뒤 아현을 부른다(상위 티켓 결정 4).

## 핵심 요약

- 요구사항: 스토리북의 파운데이션 페이지와 컴포넌트 스토리, `jam-web/DESIGN.md`, MODULAR 안내 문서를 새 디자인 시스템 기준으로 맞춘다.
- 구현 계획: `/jam-ds` 절차로 네 층(서비스 UI, MODULAR, 스토리북, claude.ai/design)의 어긋남을 진단한 뒤 맞춘다.
- 관련 파일: `jam-web/design-system/foundations/*.stories.tsx`(Colors·Fonts·Motion·Radius·Spacing·Typography), `jam-web/design-system/guidelines/*.html`(12개), `jam-web/design-system/readme.md`, `jam-web/design-system/SKILL.md`, `jam-web/DESIGN.md`, `jam-web/design-system/styles.css`

## 배경 / 문제 정의

`jam-web/DESIGN.md`는 다크 캔버스와 레드오렌지 기준이고, 희귀도 이름도 옛 이름(legend·mythic)이다. 상위 티켓 결정 1로 staging이 라이트가 되므로 문서와 스토리북도 지금 서비스에 맞춰야 한다.
[JAM 2.0 디자인 시스템](<../../plan/jam2/11 JAM 2.0 디자인 시스템.md>) 0절은 "JAM 2.0을 배포할 때 DESIGN.md를 덮어쓴다"고 적었는데, staging에 바로 적용하기로 해서 시점이 앞당겨진다.

## 시작 전에 사용자에게 물을 결정

1. **DESIGN.md 갱신 시점**: (추천) 지금 덮어쓴다. 에이전트가 옛 다크 기준을 근거로 쓰지 않게 한다 / JAM 2.0 출시 때 덮어쓴다
2. **guidelines HTML 12개**: (추천) 색·글자·반경·간격 페이지만 새 값으로 고치고, 옛 다크 기준 페이지(dos-donts 등)는 새 규칙으로 다시 쓴다 / 모두 지우고 스토리북 파운데이션 페이지로 대체한다
3. **claude.ai/design 업로드본**: (추천) 이 티켓에서 함께 갱신한다 / 별도 티켓으로 뺀다

## 완료 조건

- `/jam-ds` 진단 결과 네 층 사이 어긋남이 0건이거나, 남은 항목마다 사유가 완료 기록에 있다.
- `jam-web/DESIGN.md`의 색·서체·반경 값이 새 토큰 파일 값과 같다.
- 스토리북 파운데이션 페이지 6개가 새 토큰으로 렌더된다.
- [JAM 2.0 디자인 시스템](<../../plan/jam2/11 JAM 2.0 디자인 시스템.md>) 0절의 DESIGN.md 덮어쓰기 문장을 실제 시점에 맞게 고친다.
