# [Infra] claude.ai/design 업로드본(MODULAR)을 JAM 2.0 기준으로 갱신한다

## 핵심 요약

- 요구사항: claude.ai/design 프로젝트 `MODULAR`(projectId `fd735d58-25c2-4347-95ed-d15ee2b36124`)의 원격 사본이 2026-08-20 업로드 그대로라 옛 다크 기준이다. `npm run ds:check`가 `UPLOAD_STALE`로 계속 알린다. JAM 2.0 라이트 기준으로 갱신한다.
- 막힌 이유: `DesignSync`가 디자인 시스템 인증을 요구했다. 도구 안내문은 `/design-login`을 실행하라고 했지만 Claude Code 2.1.149에서 이 명령은 `Unknown command`다(2026-10-16 터미널에서 확인, 데스크톱 앱은 「isn't available in this environment」). 앱 세션은 비대화형이라 권한 요청을 띄울 수 없다. **대안: 터미널의 Claude Code 세션(claude.ai 로그인)에서 이 티켓을 진행하면 첫 `DesignSync` 호출 때 디자인 시스템 접근 권한 요청이 뜰 수 있다(도구 설명). 그 요청을 승인한다.** 그래도 같은 인증 오류가 나면 claude.ai 디자인 화면의 「Send to Claude Code Web」나 프로젝트 파일을 직접 받는 방식으로 바꾼다.
- 구현 계획: 인증 뒤 `/jam-ds` 5절 절차를 따른다. ① `list_files`로 구조 차이를 만든다. ② `finalize_plan`에서 쓰기·삭제 경로를 사용자가 직접 본다(외부 서비스에 올리는 일이라 이 단계가 승인이다). ③ `write_files`는 `localPath`로 넘긴다. ④ 성공하면 `.design-sync/state.json`의 `lastUploadCommit`·`lastUploadAt`을 갱신한다.
- 삭제 경로 후보(원격에 남은 것): `guidelines/*.html` 12개, `_vendor/`(React·Babel 번들), `dashboard.html`(업로드 제외 대상이었으므로 원격에 없을 수 있음). 쓰기 후보: 2131~2135에서 바뀐 `design-system/tokens/*`, `components/**`(스토리 제외), `foundations`는 스토리라 제외, `readme.md`·`SKILL.md`·`_ds_manifest.json`·`styles.css`.
- 사용자 판단 거리: `design-system/.thumbnail`(640×427 WebP)과 `thumbnail.html`의 SVG는 옛 보라(#5433eb) 바탕에 흰 「Jam」 로고라 새 시스템과 맞지 않는다. 새로 만들지, 그대로 둘지 정한다.
- 근거: 티켓 20261015_2135 결정 3(업로드본을 이 티켓에서 갱신, 실행 직전 승인).
