# [Infra] JAM 2.0 묶음 0: 끝난 운영 자동화 티켓을 마감하고 돌지 않는 루틴의 표시를 맞춘다

## 핵심 요약

- 요구사항: [현재 서비스 비교](<../../plan/jam2/service-redesign/현재 서비스 비교.md>) 6절에서 사용자가 정한(2026-10-10) 운영 자동화 정리 가운데 "지금 할 일"을 처리한다.
- 구현 계획: 이 티켓은 새 하위 티켓을 만들지 않고, 이미 있는 티켓 네 개를 각자의 티켓으로 처리하는 추적용이다. 처리할 때마다 아래 표의 상태 칸을 갱신한다.
- 관련 파일: `docs/tickets/` 아래 티켓 20260930_1500, 20260930_1454, 20261007_1956, 20260930_1505, 20260930_1450(표 갱신). 1956의 작은 범위는 예약 루틴 상태 칸(`.claude/skills/jam-work/references/scheduled-jobs.md`, 생성 파일 `jam-web/src/lib/admin/scheduledJobs.generated.ts`(생성 스크립트 `scripts/gen-scheduled-jobs.mjs`))과 그 상태를 읽는 생성 파일·테스트·어드민 일정표·세션 시작 현황판이다(정확한 파일은 1956 티켓의 「관련 파일」을 따른다).

## 배경 / 문제 정의

운영툴은 JAM 2.0에서도 쓰므로 버리지 않는다. 다만 지금 두 가지가 어긋나 있다.

1. 코드까지 끝난 티켓이 열려 있다. 1500(자원 연결)은 하위 티켓과 영향 항목이 모두 CLOSED인데 마감만 남았고, 1454(패턴 사전 원고)는 기다리던 조건이 2026-10-07에 CLOSED되었는데 WAITING 그대로다.
2. 예약 루틴은 2026-10-07에 모두 삭제되었는데(1956), 어드민 일정표는 돌지 않는 루틴을 보여 주고 세션 시작 점검은 리포트 누락을 경고한다.
   2026-10-16 세션 시작에도 주간 리포트(`2026-W42.md`)가 없다는 경고가 떴다.

에이전트와 루틴을 JAM 2.0 기준으로 다시 만드는 일(1504)과 1450의 완료 조건은 JAM 2.0 기능이 끝난 뒤 정식 오픈 전에 한다. 지금 훅, 검사, 문서 절을 걷어내면 그때 다시 써야 하므로 걷어내지 않는다.

- 1450의 후속 P3 중 "JAM 2.0이 바꾸는 기존 화면과 겹치는 것" 9건은 해당 묶음 티켓을 쓸 때 다시 본다. 이 티켓에서 닫지 않는다.

## 완료 조건

- 위 표의 1~5가 각자의 티켓 또는 기록으로 처리되어 있고, 이 티켓의 표에 처리 결과와 커밋 해시가 적혀 있다.
- 1500, 1454의 상태가 CLOSED이고 완료 기록에 위 방침이 적혀 있다(사용자 승인 뒤).
- 1956의 작은 범위를 처리한 뒤, 세션 시작 점검이 꺼진 루틴에 대해 리포트 누락을 경고하지 않는다. 확인 방법은 새 세션 시작 출력 또는 해당 점검 스크립트 실행 결과다.
- 1956에서 걷어내지 않은 훅, 검사, 문서 절의 목록이 1504 티켓(또는 1956 완료 기록)에 남아 있다.
