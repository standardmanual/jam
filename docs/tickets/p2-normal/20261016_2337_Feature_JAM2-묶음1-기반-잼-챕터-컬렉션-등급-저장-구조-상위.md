# [Feature] JAM 2.0 묶음 1: 잼 원장, 챕터 저장, 컬렉션 4등급 구조를 DB에 추가한다

## 핵심 요약

- 요구사항: 뒤 묶음(동기화 보상, 캡슐, 챕터 연결, 미션)이 올라설 저장 구조 세 가지를 DB에 **추가만** 한다. 화면, 동기화 연결, 어드민 화면은 이 묶음에 없다.
- 구현 계획: 하위 티켓 3개를 아래 순서로 하나씩 진행한다. 하위 티켓마다 SQL 파일 작성(아현) → 게이트 → 사용자 승인 → 카리나가 실행 → 롤백 실측 순서다.
- 관련 파일: `jam-web/supabase/migrations/`(최신 번호 219, 새 번호는 push 직전 원격 staging 기준으로 다시 확인), `docs/service/prd/02_DATA_MODEL.md`, 운영 로직 문서 4장·8장·12장

## 배경 / 문제 정의

운영 로직 문서의 '추가' 12가지 가운데 잼 원장, 챕터와 점수의 저장, 컬렉션 등급 구조는 뒤 묶음이 모두 기대는 기반이다.
저장 구조가 없으면 묶음 2의 동기화가 잼을 줄 곳이 없고, 묶음 3의 캡슐이 채울 잼을 셀 수 없으며, 묶음 5의 챕터가 점수를 쌓을 곳이 없다.
기반을 먼저 만들어 두면 뒤 묶음은 화면과 규칙에 집중할 수 있다.

Supabase는 staging과 프로덕션이 공용이고 프로덕션 코드는 옛 서비스다. 그래서 이 묶음은 **새 테이블과 새 함수를 덧붙이기만** 하고, 옛 함수(`slot_item_into_book`, `award_points` 등)와 옛 컬럼은 건드리지 않는다.

## 하위 티켓

| 순서 | ID | 제목 | 유형 | 이유 |
|---|---|---|---|---|
| 1 | "20261016_2338" (CLOSED 2026-10-17, 마이그레이션 220 적용) | 잼 원장과 지갑 | db | 가장 작고, 포인트 원장 구조를 본뜬다. 안전하게 시작할 수 있다 |
| 2 | "20261016_2339" (CLOSED 2026-10-17, 마이그레이션 221 적용) | 챕터 저장과 점수 기록 | db | 설정 저장 위치 결정이 묶음 7과 이어진다. 잼 원장과 독립이다 |
| 3 | "20261016_2340" | 컬렉션 4등급 구조와 단일 완성 판정 | db + 로직 | 가장 크다. 앞의 둘에서 얻은 DB 작업 방식을 쓴다. 회차를 나눠 돌린다 |

- 세 티켓이 서로의 테이블을 참조하지 않으므로 순서는 위험도 순이다. 병렬로 돌리지 않는다(마이그레이션 번호와 DB 실행이 한 줄로 이어져야 한다).
- 실행 지표와 재작업 횟수는 하위 티켓마다 적는다.

## 완료 조건

- 하위 티켓 3개가 모두 CLOSED다.
- 새 마이그레이션이 옛 테이블, 옛 함수, 옛 컬럼을 바꾸거나 지우지 않는다. 확인 방법은 하위 티켓별 SQL 파일에서 `ALTER ... DROP`, `DROP TABLE`, 기존 함수 `CREATE OR REPLACE` 가 없음을 검색한 결과다.
- 프로덕션(main) 코드가 새 구조 때문에 깨지지 않는다. 확인 방법은 새 테이블과 함수 추가 뒤에 staging과 프로덕션의 홈, 인벤토리, 컬렉션 화면이 이전과 같이 열리는 것이다.
- `docs/service/prd/02_DATA_MODEL.md`에 세 구조가 반영되어 있다.
