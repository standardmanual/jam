# [Service] JAM 2.0 잼 원장과 지갑을 DB에 추가한다

## 핵심 요약

- 요구사항: 운영 로직 4.2절의 "원장과 기록"을 DB로 만든다. 잼이 늘고 주는 모든 일을 원장에 한 줄씩 남기고, 잔액은 원장을 거쳐서만 바뀌며, 0 아래로 내려가지 않는다.
- 구현 계획: 포인트 원장 구조를 본떠 지갑, 원장, 지급·차감 함수를 새 마이그레이션 한 파일(되돌림 SQL 포함)로 추가한다. 동기화, 캡슐, 화면 연결은 하지 않는다.
- 관련 파일: `jam-web/supabase/migrations/080_point_system_renumbered_from_045_duplicate.sql`(본뜰 구조: `point_wallets` 43행, `point_transactions` 60행, `award_points` 111행), 새 파일 `jam-web/supabase/migrations/2XX_jam_ledger.sql`(번호는 push 직전 원격 staging 기준으로 확인), `docs/service/prd/02_DATA_MODEL.md`

## 배경 / 문제 정의

잼은 활동을 동기화하면 쌓이고 캡슐과 잠긴 아이템 배지를 채울 때 쓰는 자원이다(운영 로직 4장). 지금 서비스에는 잼이 없다.
잼은 돈과 달리 사라지지 않고 한도가 없지만, 쌓고 쓰는 내역이 정확해야 어드민이 오류를 바로잡을 수 있다.
그래서 포인트와 같이 "잔액은 원장을 거쳐서만 바뀐다"는 구조를 쓴다. 포인트 쪽에는 잔액이 0 아래로 내려가는 것을 막는 제약이 없어(비교표 4.1절) 이번에는 처음부터 넣는다.

## 시작 전에 사용자에게 물을 결정

1. 기간별 모은 양(예: 이번 주)과 지금까지 모은 총량을 어떻게 저장할지. 추천은 원장에서 합산해 읽는 방식이다. 값이 하나뿐이라 어긋날 일이 없고, 조회가 느려지면 집계 칸을 그때 더한다.
2. 한 활동에 잼을 한 번만 주는 규칙을 DB에서 막을지. 추천은 활동 식별자에 유일 제약을 거는 것이다. 동기화가 두 번 돌아도 한 번만 정산된다.
3. 원장의 사유 값 목록. 추천은 활동 정산, 캡슐 채움, 잠긴 아이템 배지 채움, 운영자 지급, 운영자 회수다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 지갑: 유저마다 지금 가진 양 하나. 본인만 읽을 수 있고, 쓰기는 함수로만 한다(`SECURITY DEFINER`).
- 원장: 추가만 되고 고치거나 지울 수 없다. 늘어난 양은 양수, 쓴 양은 음수이며 0은 허용하지 않는다. 사유, 시각, 운영자 지급·회수일 때 운영자와 사유 문구를 담는다.
- 활동 정산은 활동 식별자를 함께 기록한다(결정 2).
- 함수는 지급(활동 정산, 운영자 지급)과 차감(캡슐 채움, 잠긴 아이템 배지 채움, 운영자 회수)을 다룬다. 차감이 가진 양보다 크면 거절한다.
- 지급·차감 사유가 서로 다른 함수 인자로 새지 않도록 사유별 허용 부호를 검사한다(활동 정산은 양수만, 채움은 음수만).
- 이용 정지 중 동작 차단은 이 티켓의 범위가 아니다(묶음 2의 어뷰징·제재).

### UI/UX 관점 (해당 시)

- 해당 없음. 화면은 묶음 2(동기화 결과), 묶음 3(캡슐), 묶음 5 이후 프로필에서 만든다.

## 구현 계획

1. 위 결정 3개를 질문창으로 받는다.
2. 아현이 마이그레이션 한 파일을 쓴다. `db-migration-rules.md`를 먼저 읽고, 추가만 하며, 파일 안에 되돌림 SQL을 주석 블록으로 싣는다.
3. 민지가 게이트를 판정한다(추가만 있는지, 되돌림 SQL이 있는지, 권한과 RLS 정책, 음수 방지).
4. 카리나가 사용자 승인을 받아 Supabase MCP로 실행한다. 실행 전에 파일명, 영향 범위(새 테이블 둘과 새 함수 둘 이상), 되돌림 SQL 위치를 말한다.
5. 카리나가 `DO` 블록에서 `RAISE EXCEPTION`으로 되돌리는 방식으로 실측한다: 지급 후 잔액, 가진 양보다 큰 차감 거절, 같은 활동을 두 번 정산했을 때 한 번만 들어감, 일반 유저 권한으로 원장을 고칠 수 없음.
6. `generate_typescript_types`로 타입을 대조하고 `02_DATA_MODEL.md`를 갱신한다. `npm run db:types`는 쓰지 않는다(CLI가 없고 파일을 비운다).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 마이그레이션 파일이 새 테이블과 새 함수만 추가하고 기존 객체를 바꾸거나 지우지 않는다.
- 파일 안에 되돌림 SQL이 있다.
- 지갑과 원장에 RLS가 켜져 있고, 일반 유저는 자기 지갑과 원장을 읽기만 할 수 있으며 쓰기 정책이 없다.
- 지급·차감 함수는 가진 양보다 큰 차감을 거절하고, 사유별 허용 부호를 어기면 거절한다.
- 같은 활동 식별자로 활동 정산을 두 번 호출해도 원장에 한 줄만 남는다.
- `docs/service/prd/02_DATA_MODEL.md`에 잼 지갑과 원장이 반영되어 있다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 마이그레이션을 Supabase MCP로 실행했고, 롤백 실측 4가지(위 구현 계획 5번)의 결과가 완료 기록에 있다.
- 타입을 `generate_typescript_types`로 대조한 결과가 완료 기록에 있다.
