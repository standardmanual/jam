# [Service] JAM 2.0 챕터와 점수의 저장 구조를 DB에 추가한다

## 핵심 요약

- 요구사항: 운영 로직 12장의 챕터를 저장할 구조를 만든다. 챕터 정의(필요 누적 점수), 트라이브별 챕터 이름 표, 활동별 점수 설정, 유저의 챕터와 누적 점수, 점수 기록, 오른 기록이다.
- 구현 계획: 새 마이그레이션 한 파일(되돌림 SQL 포함)로 테이블과 점수 가산·챕터 오르기 함수를 추가하고, 챕터 10개와 점수표를 초기값으로 넣는다. 점수를 주는 연결, 연출, 소식, 챕터 배지, 프로필 표시는 묶음 5에서 한다.
- 관련 파일: 새 파일 `jam-web/supabase/migrations/2XX_chapters.sql`(번호는 push 직전 원격 staging 기준으로 확인), `docs/service/prd/02_DATA_MODEL.md`. 점수 세기가 나중에 기댈 JAM 조건 판정 코드는 `jam-web/src/lib/badge-engine/`에 있다(이 티켓에서는 읽지 않아도 된다).

## 배경 / 문제 정의

챕터는 유저마다 하나이고 서비스 활동량으로 오르며 내려가지 않는다(12.2절). 지금 서비스에는 유저의 단계가 없다.
점수를 주는 활동이 여러 묶음(캡슐은 3, 배지는 4, 미션은 5)에 걸쳐 있어서, 저장 구조와 "점수를 더하면 챕터가 오른다"는 규칙을 먼저 한 곳에 두고 각 묶음이 그 함수를 호출하게 한다.

## 시작 전에 사용자에게 물을 결정

1. 점수 수치(챕터별 누적 점수, 활동별 점수, 잼의 주간 상한)를 둘 저장 위치. 묶음 7의 "모은 설정 화면"이 지금 설정 테이블을 다시 쓰기로 되어 있어, 두 가지가 있다.
   (가) 이 티켓에서 전용 테이블을 만들고 묶음 7에서 설정 화면이 그 테이블을 읽게 한다. (나) 지금 설정 테이블에 칸을 더한다.
   추천은 (가)다. 챕터 수와 점수는 행이 많고 챕터를 뒤에 더하는 구조라 설정 한 행에 넣기 어렵다.
2. 같은 활동에서 점수가 두 번 쌓이지 않게 막을 키. 추천은 활동 종류와 원천 식별자를 합친 유일 제약이다.
3. 챕터 1의 시작. 추천은 퀘스트를 마칠 때 챕터 1로 올리는 호출을 따로 두는 것이다(점수 0에서 시작하고 퀘스트 완료가 챕터 1이다).

## 상세 요구사항

### 서비스/코드베이스 관점

- 챕터 정의: 챕터 번호와 오르는 데 필요한 누적 점수. 초기값은 챕터 2부터 1,000, 2,300, 3,800, 5,700, 8,500, 11,500, 15,000, 19,000, 23,000이고 챕터 1은 퀘스트 완료다(12.4절). 챕터는 뒤에 더할 수 있어야 한다.
- 트라이브별 챕터 이름 표: 트라이브 다섯 개 × 챕터 10개 = 50칸. 이름은 별도 주제로 나중에 지으므로 칸은 비워 두고 입력 구조만 만든다(2026-10-08 사용자 결정).
- 활동별 점수 설정: 잼은 1당 1점이고 한 주(월~일)에 300점까지 그대로, 넘는 것은 절반. 캡슐 열기 20, 잠긴 아이템 배지 열기 10, 배지 받기 10, 컬렉션 완성 Common 100·Rare 200·Epic 400·Mystic 800, 믹스 성공 20, 미션 완료 50, 드랍과 픽업 각 5(12.2절 표).
- 유저의 챕터: 지금 챕터 번호와 누적 점수. 본인만 읽는다.
- 점수 기록: 활동 종류, 점수, 원천 식별자, 시각. 활동별로 쌓인 점수를 남긴다(12.2절 "기록").
- 오른 기록: 오른 시각과 그때의 챕터. 한 번에 여러 챕터를 넘으면 넘은 챕터마다 한 줄이다.
- 함수: 점수를 더하고 챕터가 오르는지 판정하며, 오른 챕터 목록을 돌려준다. 챕터는 내려가지 않는다.
- 포인트, 팔로우, 챕터를 조건으로 하는 배지는 점수를 주지 않는다는 규칙은 점수를 부르는 쪽(묶음 4)에서 지킨다. 이 함수는 호출된 점수를 그대로 쌓는다.
- 이용 정지 중 점수 차단은 점수를 부르는 쪽의 동작 차단(묶음 2)이 막는다.

## 구현 계획

1. 위 결정 3개를 질문창으로 받는다.
2. 아현이 마이그레이션 한 파일을 쓴다. 추가만 하고, 초기값 입력은 같은 파일의 삽입 구문으로 하되 다시 실행해도 중복이 생기지 않게 쓴다. 되돌림 SQL을 싣는다.
3. 민지가 게이트를 판정한다.
4. 카리나가 사용자 승인을 받아 MCP로 실행한다.
5. 롤백 실측: 점수를 더해 챕터가 오름, 한 번에 둘 이상 오름, 같은 원천을 두 번 더해도 한 번만 반영됨, 챕터가 내려가지 않음, 일반 유저 권한으로 점수를 고칠 수 없음.
6. 타입 대조와 `02_DATA_MODEL.md` 갱신.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 마이그레이션이 새 객체만 추가하고 되돌림 SQL을 싣는다.
- 챕터 정의 10개의 필요 누적 점수와 활동별 점수 설정의 초기값이 12.4절·12.2절과 같다.
- 트라이브별 챕터 이름 표가 있고 이름 칸은 비어 있다.
- 점수 가산 함수가 같은 활동 종류와 원천 식별자를 두 번 받아도 한 번만 반영한다.
- 점수 가산 함수가 필요 점수를 넘은 만큼 챕터를 올리고, 오른 챕터마다 오른 기록을 남기며, 챕터를 내리지 않는다.
- 일반 유저는 자기 챕터만 읽을 수 있고 쓰기 경로가 없다.
- `02_DATA_MODEL.md`에 챕터 구조가 반영되어 있다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- MCP로 실행했고 롤백 실측 5가지의 결과가 완료 기록에 있다.
- 타입 대조 결과가 완료 기록에 있다.
