# [Service] JAM 2.0 잠긴 아이템 배지의 저장과 규칙: 개체의 잠김·필요한 양·채운 양, 배지 양식의 잠금 칸, 동기화·보류의 잠김 배정

## 핵심 요약

- 요구사항: 운영 로직 7.2·7.4·7.5절의 잠긴 아이템 배지를 «저장과 규칙»까지 만든다. 개체(`inventory_items`)가 잠겼는지, 여는 데 필요한 양, 채운 양, 잠긴 까닭을 갖게 하고, 배지 양식에 «잠김으로 만듦»과 «여는 데 필요한 양» 칸을 더하고, 동기화(2-4)와 보류 고르기(2-5)에서 잠김을 배정하게 한다. 잠긴 개체는 컬렉션 장착, 믹스 재료, 드랍(묶음 4 전까지)에 쓸 수 없다. 채우기와 열기는 3-3이다.
- 구현 계획: 시작 때 사용자 결정 4건을 질문하고, 이 절에 파일 단위 계획을 옮겨 쓴다. SQL(새 칸, 새 설정 칸, 새 기록 테이블)은 사용자 승인과 롤백 실측 뒤 카리나가 실행한다.
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 다시 확인한다):
  - 개체: `jam-web/src/types/database.generated.ts`의 `inventory_items`(칸: `badge_id`, `inventory_id`, `obtained_by`, `serial_number`, `slotted_in`, `dropped_at`, `destroyed_at`, `expires_at`; 잠김 칸 없음), 지급 RPC `grant_inventory_item(p_inventory_id, p_badge_id, p_obtained_by, p_expires_at)`.
  - 동기화 발급: `jam-web/src/lib/drop-engine/syncIssueRun.ts`, `syncIssue.ts`(후보·등급 추첨, 발급 기록 `item_issue_log.locked`는 지금 항상 false), 보류 `sync_pending_items.locked`, 고르기 RPC `resolve_sync_pending_items`(229), 고르기 화면 `PendingItemsPickOverlay.tsx`(잠긴 카드는 이름·그림 없이 보여야 함).
  - 장착: 마이그레이션 222의 `slot_item_into_book_tiered`, `swap_item_in_book_tiered`, `jam-web/src/app/api/itembooks/`. 믹스: `jam-web/src/lib/combine/index.ts`(`combineRecipeAttempt`), `app/api/combine/route.ts`. 드랍: `app/api/drops/`.
  - 배지 양식: 어드민 배지 화면(`jam-web/src/app/admin/badges/`), `badges` 테이블. 값은 `jam_policy`(226·227) 같은 설정 행.
  - 스펙: 운영 로직 7장, 비교표 3.6절.

## 배경 / 문제 정의

지금 서비스에는 잠금 개념이 없다. 2-4는 발급 기록에 `locked` 칸을 두고 항상 false로 남겼고, 2-5는 보류에 `locked` 칸을 만들었다. 캡슐 열기의 마지막 단계(잠김 배정)와 동기화의 잠김 배정이 모두 «개체가 잠겼는가»를 저장할 곳을 필요로 한다.
운영 로직 7.2절: 잠긴 아이템 배지는 따로 된 기능이 아니라 아이템 배지의 상태다. 어떤 아이템 배지인지는 얻을 때 이미 정해지고, 열기는 드러내는 일이다. 잠기는 경우는 세 가지(잠김으로 만든 아이템 배지, 잠긴 채 배정된 아이템 배지, 운영자가 지정한 보상)다. 무작위로 잠김을 정하는 것은 동기화와 캡슐뿐이다.
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **개체의 잠김 저장**: `inventory_items`에 새 칸(잠김 여부, 여는 데 필요한 양, 채운 양, 잠긴 까닭, 연 시각)을 더하는 방식(추천: 옛 코드는 새 칸을 읽지 않고 기본값이 «열림»이라 영향이 없다)과 별도 «개체 잠김» 테이블을 두는 방식.
2. **배지 양식의 잠금 칸**: `badges`에 «잠김으로 만듦», «여는 데 필요한 양»(정하지 않으면 등급 최소값) 새 칸을 더한다(추천). 어드민 배지 양식에 입력을 더하고 등급 최소값보다 적은 값은 저장하지 않는다.
3. **동기화·보류의 잠김 배정**: 3-1에서 «나온 아이템 배지의 25%를 잠긴 채 배정»하는 공통 함수를 만들고 동기화 발급(2-4)과 보류 고르기(2-5)에 연결한다(추천). 캡슐은 3-2가 같은 함수를 쓴다. 대안은 동기화 연결을 3-2로 미루는 것이다.
4. **묶음 4 전까지 잠긴 개체의 드랍**: 막는다(추천). 잠긴 채 드랍과 가린 모습은 묶음 4가 만든다. 그 전에 드랍을 열어 두면 지금 드랍 목록이 이름과 그림을 그대로 보여 준다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **개체의 잠김 상태**: 잠김 여부, 여는 데 필요한 양(배정 때 고정, 이후 어드민이 바꿔도 불변), 채운 양, 잠긴 까닭(`badge_locked`=잠김으로 만듦, `rolled`=잠긴 채 배정됨, `designated`=운영자가 지정함), 연 시각. 기본값은 «열림»이다. 이미 있는 개체와 옛 지급 경로(믹스, 보상, 픽업, 퀘스트)는 모두 열린 채로 남는다.
- **잠김 배정 함수**: 입력은 (이미 정해진 아이템 배지, 등급, 경로)이고 출력은 (잠김 여부, 까닭, 필요한 양)이다. 잠김으로 만든 아이템 배지는 늘 잠김이다. 열린 것으로 만든 아이템 배지는 설정 행의 잠길 확률(기본 25%)로 잠김을 정한다. 운영자가 지정하는 경로(미션 보상, 프로모션)는 무작위로 잠기지 않는다. 필요한 양은 배지 양식의 값, 없으면 그 등급의 최소값(Common 30, Rare 60, Epic 120, Mystic 240)이다. 퀘스트 전 첫 캡슐의 예외(5)는 3-2가 정한다.
- **동기화 연결(2-4, 2-5)**: 발급 계획이 각 개체의 잠김을 정하고, 지급과 보류가 같은 값을 저장한다(`item_issue_log.locked`, `sync_pending_items.locked`와 새 개체 칸). 보류 고르기 화면의 잠긴 카드는 이름과 그림을 가리고 등급과 필요한 양만 보인다(7.3절). 고르기 RPC가 지급할 때 잠김을 개체에 옮긴다.
- **잠긴 동안의 제한**: 컬렉션 장착·교체(`slot_item_into_book_tiered`, `swap_item_in_book_tiered`)와 믹스 재료에서 잠긴 개체를 거부한다. 묶음 4 전까지 드랍도 거부한다. 거부는 서버가 하고 화면의 안내는 3-6이다.
- **포인트**: 아이템 배지에 붙은 포인트는 «열린 상태가 될 때» 한 번 준다(7.2절). 지금 포인트를 주는 경로가 있으면 잠긴 채 받은 개체는 주지 않도록 막는다. 연 때 주는 것은 3-3이다.
- **설정 행**: 새 칸(`jam_policy` 확장 또는 새 설정 행)에 등급별 최소값과 잠길 확률을 둔다. 기본값은 코드 기본값과 같게 유지한다.
- **배지 양식(어드민)**: «잠김으로 만듦», «여는 데 필요한 양» 입력. 등급 최소값보다 적으면 저장 거부. shadcn/ui 표준, 네이티브 `select` 금지. 아이템 배지 현황에서 개체의 잠김 상태를 보여 주는 것은 이 티켓에서 읽기 표시만 더한다.
- 새 칸과 새 함수는 덧붙이기만 한다. 생성 타입을 같은 커밋에 맞춘다.

### UI/UX 관점 (해당 시)

- 보류 고르기 화면의 잠긴 카드 가림만 이 티켓이다(2-5의 `PendingItemsPickOverlay`가 이름·그림을 이미 보여 주는 값에서 잠김일 때 가림). 인벤토리의 잠김 표시 카드와 채우기 화면은 3-4다. 가림 문구와 모양은 채원 판정에 맡긴다.

## 구현 계획 (회차)

규모가 커서 처음부터 2회로 나눠 돌리고 회마다 게이트를 돌린다. 시작 때 파일 단위 계획을 이 절에 옮겨 쓰고 `planOnlyWaiver`를 넘긴다. 요약은 2,500자 이내.

### 1회: 저장(SQL), 잠김 배정 함수, 동기화·보류 연결, 장착·믹스·드랍 거부
### 2회: 어드민 배지 양식, 보류 고르기의 가림, 아이템 배지 현황 표시

## 완료 조건

### 구현 범위 (게이트 판정 대상, 회차마다 해당 항목)

- (1회) 개체의 잠김 상태를 저장하는 새 칸과 설정 행이 있고, 마이그레이션이 옛 칸·옛 함수를 바꾸거나 지우지 않으며 되돌림 SQL을 싣는다. 옛 지급 경로로 받은 개체는 열린 채다.
- (1회) 잠김 배정 함수가 잠김으로 만든 것은 항상 잠그고, 열린 것은 설정 확률로 잠그며, 운영자 지정 경로는 잠그지 않는다. 확률 경계(0%, 100%)와 등급별 필요한 양 시험이 있다.
- (1회) 동기화로 받은 아이템 배지와 보류 고르기로 받은 아이템 배지가 같은 규칙으로 잠긴 채 저장되고, 필요한 양이 배정 때 고정된다.
- (1회) 잠긴 개체는 컬렉션 장착, 믹스, 드랍이 서버에서 거부된다.
- (2회) 어드민 배지 양식에서 잠금과 필요한 양을 정하고, 등급 최소값보다 적은 값은 저장되지 않는다.
- (2회) 보류 고르기 화면에서 잠긴 카드는 이름과 그림이 보이지 않는다.
- (전체) `docs/service/prd/`(데이터 모델, 인벤토리)와 `docs/service/badge-engine/`의 해당 문서가 반영되어 있다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 사용자 확인 1~4번의 결정을 이 티켓 「사용자 결정」 절에 기록한다. SQL 실행은 승인과 롤백 실측 뒤에 한다.
- 어드민 화면 실렌더 확인은 카리나가 머지 뒤 push 전에 로컬에서 한다.
