# [UI] JAM 2.0 캡슐 화면과 잠긴 아이템 배지 카드·채우기·열기 화면

## 핵심 요약

- 요구사항: 3-2·3-3의 API를 쓰는 유저 화면을 만든다. 캡슐 화면(게이지, 채우기, 열기, 열기 결과, 빈칸이 모자랄 때 안내), 인벤토리의 잠김 표시 카드, 잠긴 아이템 배지의 상세(등급, 필요한 양과 채운 양의 게이지, 채우기, 열기), 열 때의 연출. 이용 정지 중의 막힘 안내. 화면 문구는 운영 로직 5.2·7.3절의 말투를 따른다.
- 구현 계획: 시작 때 채원 사전 판정을 받는다. 캡슐 화면의 완성된 디자인은 문서에서 확인되지 않으므로 판정이 제안한 모양을 사용자가 승인한다. 파일이 많으면 2회로 나눈다(1회 캡슐 화면, 2회 잠긴 개체 카드·상세).
- 관련 파일(시작 때 아현이 줄 위치를 확인한다): 인벤토리 `jam-web/src/app/(main)/inventory/`(`page.tsx`, `QuestBagGrid.tsx`, `[itemId]`), 결과 연출 `jam-web/src/components/`의 `BadgeRevealOverlay`와 MODULAR `design-system/components/patterns/BadgeRevealCarousel`(2-5가 선택 모드를 더함), 이용 정지 막힘 안내 선례 `jam-web/src/lib/strava/sync-flow.ts`와 `SyncButton.tsx`, 문구 `jam-web/src/lib/i18n/ko.ts`, 스펙 운영 로직 5.1·5.3·7.1·7.3절, 디자인 시스템 `docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`.

## 배경 / 문제 정의

서버(3-1~3-3)가 모두 선 뒤에 화면을 한 번에 만든다. 운영 로직의 표시 규칙: 캡슐에 채운 양은 게이지로만 보이고 진행 수치는 쓰지 않는다. 캡슐은 아이템 배지 카드와 다른 모양의 물건 하나로 따로 둔다. 잠긴 아이템 배지는 인벤토리의 다른 카드와 같은 모양에 잠김 표시만 더하고, 열기 전에는 등급·필요한 양·채운 양·얻은 날과 경로만 보여 주며 이름·그림·설명·컬렉션·트라이브·일련번호는 가린다. 둘의 채운 양 게이지는 같은 모양이다. 다시 열기를 부추기는 말, 낮은 등급을 꽝으로 표현하는 말을 쓰지 않는다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

시작 때 채원 사전 판정의 승인 항목(새 컴포넌트, 화면 위치, 문구)을 질문한다. 미리 정해 둘 것은 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 서버가 정한 값(필요량, 채운 양, 열 수 있는지, 못 여는 까닭)을 그대로 그린다. 화면이 규칙을 다시 계산하지 않는다.
- 이용 정지 중 채우기·열기가 403 `user_suspended`를 받으면 일반 실패가 아니라 안내(info 토스트)를 낸다(2-6의 `sync-flow` 선례).
- 클라이언트·서버 경계: 클라이언트가 가져오는 모듈은 서버 전용 모듈(`@/lib/supabase/server`, `next/headers`)을 정적·동적 어느 쪽으로도 가져오지 않는다. 순수 계약 파일과 서버 파일을 나눈다.

### UI/UX 관점

- 채원 판정을 따른다. 오버레이를 만들거나 고치면 `docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`의 z-index 레이어 체계를 먼저 읽고, 기하값은 `offsetHeight`로 실측한다.
- 사용자 노출 문구는 UX 라이팅 가이드와 `fluent-korean` 지침을 따른다(예: «캡슐에 잼을 채워 열었어요», «캡슐을 열었어요. 아이템 배지 2개를 얻었어요», «아이템 배지를 열었어요»).

## 구현 계획 (회차)

채원 판정 뒤 파일 단위 계획을 이 절에 옮겨 쓴다. 30개를 넘으면 2회로 나눈다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 캡슐 화면에서 채우기(기본 남은 양, 줄이기), 열기, 열기 결과, 빈칸 모자람 안내(지금 빈칸 수와 필요한 빈칸 수)가 동작한다.
- 인벤토리의 잠긴 아이템 배지는 잠김 표시 카드로 보이고 이름·그림·설명·컬렉션·트라이브·일련번호가 보이지 않는다. 상세에서 채우기와 열기가 동작하고 열면 이름과 그림이 드러난다.
- 캡슐과 잠긴 아이템 배지의 채운 양 게이지가 같은 모양이다. 진행 수치 숫자를 쓰지 않는다.
- 이용 정지 중 채우기·열기가 막히면 일반 실패가 아닌 안내가 나온다.
- 채원 사후 리뷰에 중대 문제가 없다. 새 토큰이나 MODULAR 변경이 있으면 Story와 문서가 함께 반영되어 있다.
- 실렌더 확인(세로 568·667·844px, 너비 320~430px 겹침과 터치 영역)은 카리나가 머지 뒤 push 전에 로컬에서 한다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 채원 사전 판정의 승인 항목을 사용자에게 보고하고 결과를 이 티켓 「사용자 결정」 절에 기록한다.
