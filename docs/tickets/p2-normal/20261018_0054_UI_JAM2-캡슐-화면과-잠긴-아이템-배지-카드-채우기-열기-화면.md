# [UI] JAM 2.0 캡슐 화면과 잠긴 아이템 배지 카드·채우기·열기 화면

## 핵심 요약

- 요구사항: 3-2·3-3의 API를 쓰는 유저 화면을 만든다. 캡슐 화면(게이지, 채우기, 열기, 열기 결과, 빈칸이 모자랄 때 안내), 인벤토리의 잠김 표시 카드, 잠긴 아이템 배지의 상세(등급, 필요한 양과 채운 양의 게이지, 채우기, 열기), 열 때의 연출. 이용 정지 중의 막힘 안내. 화면 문구는 운영 로직 5.2·7.3절의 말투를 따른다.
- 구현 계획: 시작 때 채원 사전 판정을 받는다. 캡슐 화면의 완성된 디자인은 문서에서 확인되지 않으므로 판정이 제안한 모양을 사용자가 승인한다. 파일이 많으면 2회로 나눈다(1회 캡슐 화면, 2회 잠긴 개체 카드·상세).
- 관련 파일(시작 때 아현이 줄 위치를 확인한다): 인벤토리 `jam-web/src/app/(main)/inventory/`(`page.tsx`, `QuestBagGrid.tsx`, `[itemId]`), 결과 연출 `jam-web/src/components/`의 `BadgeRevealOverlay`와 MODULAR `design-system/components/patterns/BadgeRevealCarousel`(2-5가 선택 모드를 더함), 이용 정지 막힘 안내 선례 `jam-web/src/lib/strava/sync-flow.ts`와 `SyncButton.tsx`, 문구 `jam-web/src/lib/i18n/ko.ts`, 스펙 운영 로직 5.1·5.3·7.1·7.3절, 디자인 시스템 `docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`.

## 배경 / 문제 정의

서버(3-1~3-3)가 모두 선 뒤에 화면을 한 번에 만든다. 운영 로직의 표시 규칙: 캡슐에 채운 양은 게이지로만 보이고 진행 수치는 쓰지 않는다. 캡슐은 아이템 배지 카드와 다른 모양의 물건 하나로 따로 둔다. 잠긴 아이템 배지는 인벤토리의 다른 카드와 같은 모양에 잠김 표시만 더하고, 열기 전에는 등급·필요한 양·채운 양·얻은 날과 경로만 보여 주며 이름·그림·설명·컬렉션·트라이브·일련번호는 가린다. 둘의 채운 양 게이지는 같은 모양이다. 다시 열기를 부추기는 말, 낮은 등급을 꽝으로 표현하는 말을 쓰지 않는다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

시작 때 채원 사전 판정의 승인 항목(새 컴포넌트, 화면 위치, 문구)을 질문한다. 미리 정해 둘 것은 없다.

## 사용자 결정 (2026-10-18, 채원 1차 판정에 대한 답)

1. **캡슐을 두는 곳: 투데이와 프로필.** 채원 권장(인벤토리 진입 행 한 곳, 별도 경로 `/capsule`)을 따르지 않는다. 팔로워가 내 프로필을 볼 때는 캡슐이 보이지 않아야 한다(내 프로필에서만 보인다).
2. **캡슐 모양: 가로 알약형.** 임시 디자인이다(나중에 바뀔 수 있으므로 모양을 한 컴포넌트에 가둔다). 채원 권장(세로 알약)을 따르지 않는다.
3. **잠긴 개체를 열 때의 연출: 상세 안 제자리 전환**(권장대로).
4. **나머지(게이지 모양, 높은 등급 축하 연출 없음, «가진 잼» 상시 표시 위치는 별도 결정으로 미룸, 채우기 시트의 숫자 입력창, MODULAR 변경 3건, 문구 초안): 모두 채원 권장안.**

## 상세 요구사항

### 서비스/코드베이스 관점

- 서버가 정한 값(필요량, 채운 양, 열 수 있는지, 못 여는 까닭)을 그대로 그린다. 화면이 규칙을 다시 계산하지 않는다.
- 3-1(2026-10-18)이 가리지 못한 곳을 이 티켓이 가린다: 인벤토리 상세(`app/(main)/inventory/[itemId]/page.tsx`), 이력 API(`app/api/inventory/items/[itemId]/history/route.ts`), 타인 프로필·컬렉션 조회 경로. 가림 카드의 설명 문구는 3-1의 `d.lockedItem.card.description`(«여는 데 잼 {n}만큼 채워야 해요»)과 가림 카드 모양(MODULAR `BadgeRevealCarousel`의 `locked`)을 재사용한다.
- 이용 정지 중 채우기·열기가 403 `user_suspended`를 받으면 일반 실패가 아니라 안내(info 토스트)를 낸다(2-6의 `sync-flow` 선례).
- 클라이언트·서버 경계: 클라이언트가 가져오는 모듈은 서버 전용 모듈(`@/lib/supabase/server`, `next/headers`)을 정적·동적 어느 쪽으로도 가져오지 않는다. 순수 계약 파일과 서버 파일을 나눈다.

### UI/UX 관점

- 채원 판정을 따른다. 오버레이를 만들거나 고치면 `docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`의 z-index 레이어 체계를 먼저 읽고, 기하값은 `offsetHeight`로 실측한다.
- 사용자 노출 문구는 UX 라이팅 가이드와 `fluent-korean` 지침을 따른다(예: «캡슐에 잼을 채워 열었어요», «캡슐을 열었어요. 아이템 배지 2개를 얻었어요», «아이템 배지를 열었어요»).

## MODULAR 변경 (승인 완료, 모양만 정한다)
**1) ProgressBar `outlined` (`design-system/components/feedback/ProgressBar.jsx`)**
- `outlined`는 새 boolean prop이고 기본값은 false라서 기존 8곳과 `DualAxisGauge`는 그대로다.
- true이면 트랙에 `border: 1px solid var(--border)`와 `box-sizing: border-box`를 준다. 채움은 테두리 안쪽에 그려서 외곽선이 가려지지 않게 한다.
- 호출부는 `fillMode="track-gradient"`, `trackColor="var(--background)"`, `height={10}`(안쪽 8px), `labelType="none"`을 쓴다.
- 기본 trackColor가 `--border`와 같은 색이라 외곽선이 안 보인다. 그래서 위 호출부에서 트랙 면을 따로 지정한다.
- 연결 상태는 «연결된 컴포넌트»라서 서비스에 즉시 반영된다. 기존 호출부가 안 바뀌는지 Story로 확인한다.

**2) BadgeGridCard `locked` (병존 구현이라 양쪽을 함께 고친다)**
- 고칠 파일은 `design-system/components/patterns/BadgeGridCard.jsx`와 `jam-web/src/components/ui/BadgeGridCard.tsx`다.
- props는 `locked`, `fillPercent`다. 이름과 그림은 받지 않고, `rarity`는 받는다.
- 모양은 일반 카드와 같은 면(`--surface`, 1px `--border`, `--radius-2xl`)이다.
- 썸네일 자리에 `LockedTile`을 넣고, 이름 줄은 `d.lockedItem.card.name`을 쓴다.
- 등급 칩 아래에 `ProgressBar outlined`를 한 줄 둔다. 높이는 6이다.
- `locked`일 때는 `imageUrl`과 `name` prop이 들어와도 그리지 않는다. 가림이 호출부 실수로 뚫리지 않게 컴포넌트가 막는다.

**3) LockedTile 신규 (`design-system/components/cards/LockedTile.jsx`, 같은 폴더에 `.d.ts`, `.stories.tsx`, `.prompt.md`)**
- props는 `size`뿐이다.
- 모양은 `BadgeRevealCarousel`의 인라인 잠금 타일과 같다. 한 변은 size, `--radius-2xl`, 면 `--background`, 1px `--border`, 안에 `LockIcon`(색 `--muted`)이 들어간다.
- 같은 모양이 BadgeRevealCarousel과 BadgeGridCard, 잠긴 상세, 이렇게 세 곳에서 나오므로 신규로 만든다.
- `BadgeRevealCarousel`의 인라인 타일은 LockedTile로 교체한다. 화면은 달라지지 않아야 하므로 Story로 대조한다.
- 등급 색, 그라데이션, 글로우는 더하지 않는다.
- 등록은 `_ds_manifest.json`, `design-system/readme.md` 색인, 그리고 `jam-ds` 절차가 요구하는 `@ds` 연결 순서로 한다.

- `CapsuleSheet.tsx`: 시트 한 개 안에서 본문 단계와 채우기 단계를 전환한다.
- `jam-web/src/components/jam/JamFillPanel.tsx`: 공용 채우기 입력이다. 캡슐과 잠긴 개체가 같이 쓴다.
  - props는 `remaining`, `balance`, `onConfirm(amount)`, `pending`이다. 어느 API를 부를지는 호출부가 넘긴다.
  - 같은 동작이 두 곳에서 다르면 안 된다는 운영 로직 7.2절을 지키기 위해 한 컴포넌트로 만든다.
- `jam-web/src/lib/capsule/capsule-client.ts`: 클라이언트용 fetch 래퍼다. `capsule-contract.ts`와 `lockedItemFill-contract.ts` 타입만 가져온다. `@/lib/supabase/server`와 `next/headers`는 정적이든 동적이든 가져오지 않는다.
- `jam-web/src/app/(main)/inventory/[itemId]/LockedItemDetail.tsx`: 잠긴 상세와 제자리 전환을 맡는다.

### 토큰

새 토큰은 없다. 전부 기존 토큰이다.

- 면과 테두리: `--surface`, `--background`, `--border`.
- 글자: `--foreground`, `--muted`, `--link`.
  - `--muted`는 흰 면(`--surface`) 위에서만 쓴다. 5.74:1이다.
  - 크림 `--background` 위나 `--border` 면 위에서는 쓰지 않는다. `--border` 면 위는 3.46:1이다.
- 가진 잼 숫자: 포인트 숫자와 같은 문법이다. `text-2xl` bold, `--link`, `tabular-nums`.
- 게이지 채움: `--progress-sweep`. `ProgressBar fillMode="track-gradient"`가 이미 쓴다.
- 모서리: `--radius-full`(알약), `--radius-2xl`(카드와 타일).
- 간격: `--spacing-4`, `--spacing-8`, `--spacing-12`, `--spacing-16`. 알약의 가로 안쪽 여백만 24px로 둔다. `--spacing-24`가 있으면 그것을 쓴다.
- 모션: `--duration-micro`(눌림), `--duration-fast`(문구 교체), `--duration-medium`(제자리 전환), `--duration-slow`(게이지 채움, ProgressBar 기본값), `--ease-smooth-out`.
- 눌림 피드백: 기존 `jam-press` 클래스.
- 쓰지 않는 것: `--accent-soft`는 선택 상태용이라 안 쓴다. `.jam-quest-pulse`는 퀘스트 전용이라 안 쓴다.

## CapsuleSheet (`BottomSheet`, 시트 한 개 안에서 단계 전환)
- **본문 단계** (제목 «캡슐»)
  - 상단에 같은 `ProgressBar outlined`를 둔다.
  - 그 아래에 «가진 잼 {balance}»를 숫자로 보여 준다. (표시 위치 세 곳 중 1번)
  - 푸터 버튼은 상태별로 다르다.
    - filling: 주 버튼 «채우기».
    - ready: 주 버튼 «열기».
    - noSlots: 푸터에 버튼 대신 안내 블록을 둔다. «인벤토리 빈칸이 모자라요», «지금 빈칸 {free}개, 열려면 {needed}개가 필요해요», «채운 잼은 그대로 남아 있어요». 아래에 보조 링크 «인벤토리 보기»(`/inventory`)를 둔다.
- **채우기 단계** (제목 «잼 채우기», 보조 «취소»)
  - 가진 잼 {balance}를 다시 보여 준다. (표시 위치 세 곳 중 3번, 캡슐과 잠긴 개체의 공용 `JamFillPanel`)
  - `Input` 숫자 입력창: `inputMode="numeric"`, 글자 크기 16px 이상, 높이 48px 이상.
  - 기본값은 `min(remaining, balance)`다. 줄일 수 있고, remaining 초과는 입력 단계에서 remaining으로 맞춘다.
  - 입력창 아래 한 줄: «잼 {n}만큼 채워요. 채운 잼은 다시 꺼낼 수 없어요.»(입력값 따라 바로 바뀐다. 조사가 숫자에 따라 갈리지 않는 «만큼» 구조다)
  - 푸터 주 버튼 «채우기».
- **열기 결과**
  - 시트를 닫고 `BadgeRevealOverlay`를 연다. 오버레이 안내 문구는 `d.capsule.openResult`(«캡슐을 열었어요. 아이템 배지 {n}개를 얻었어요.»)다.
  - 잠긴 채 나온 개체는 `locked` 카드로 보인다.
  - 오버레이를 닫으면 위젯이 다음 캡슐 값으로 갱신된다.

## 인벤토리 `jam-web/src/app/(main)/inventory/page.tsx`
- 그리드는 `InventoryGrid`(`jam-web/src/components/inventory/InventoryGrid.tsx`)를 그대로 쓴다.
- `InventoryGridItem`에 `locked`, `fillPercent`를 더한다. 잠긴 항목은 `BadgeGridCard locked`로 렌더한다.
- 서버 페이지가 `inventory_items.locked`, `unlock_required`, `unlock_filled`를 읽는다.
- **잠긴 개체의 이름과 그림은 클라이언트로 내리는 props에 넣지 않는다.** 서버에서 비운다.
- 퍼센트는 `unlock_filled / unlock_required`로 계산한 값이다. 서버 값을 그대로 그리는 것이고, 화면이 새 규칙을 만드는 게 아니다.
- 잠긴 카드 안에는 «잠김» 표시, 등급 칩, 게이지가 들어간다. 만료 칩은 일반 카드와 같은 자리에 둔다.

## 잠긴 상세 `jam-web/src/app/(main)/inventory/[itemId]/page.tsx`
- 서버 페이지에서 `locked`이면 `/badges/...`로 리다이렉트하지 않고 `LockedItemDetail`을 그린다.
- `locked`가 아니면 지금처럼 리다이렉트한다.
```
TopNav showBack (backHref=/inventory)
LockedTile (큰 정사각)
[등급 칩] [잠김 LabelChip]
잠긴 아이템 배지                      (d.lockedItem.card.name, text-2xl)
```

## 열기 뒤 제자리 전환 (잠긴 개체)
- 열기가 성공하면 같은 화면에서 `LockedTile`이 그림으로 바뀌고, 제목이 이름으로, 설명이 설명 문구로 바뀐다.
- 게이지와 «가진 잼» 줄은 접힌다.
- 등급 칩은 유지한다.
- «잠김» 칩은 사라진다.
- `serialNumber`는 `ItemSerialCode`로, `collection`과 `tribe`가 있으면 한 줄씩 보여 준다.
- 하단에 «배지 상세 보기» 링크(`/badges/{badgeId}?item={itemId}&from=inventory`)를 둔다. 배지 상세를 이 화면에 다시 만들지 않는다.
- `pointsAwarded > 0`이면 한 줄을 더한다.
- 응답의 `item`이 null이면(열기는 확정, 정보 조회만 실패) 전환 없이 `router.refresh()`로 서버 페이지의 리다이렉트에 맡긴다.

### 상태 목록

## 캡슐 위젯과 시트
- **로딩**
  - 위젯은 같은 높이의 `Skeleton` 알약이다. 높이가 변하지 않게 한다.
  - 서버 초기값이 있으면 로딩 없이 바로 그린다.
- **빈**
  - 해당 없음. 캡슐은 언제나 있고 `filled = 0`인 빈 게이지가 기본 상태다.
  - 가진 잼 0은 별도 상태다(아래).
- **오류**
  - 알약 안에서 «캡슐을 불러오지 못했어요» + «다시 시도» 한 줄로 바뀐다. 크기는 같다. 탭하면 재조회한다. 문구는 `d.capsule.loadFailed`다.
  - 채우기와 열기 실패는 시트 안 토스트(error)로 낸다. 문구는 `d.capsule.*`의 거절 문구를 응답 `code`로 고른다.
- **기본(filling)**: 게이지가 일부 차 있고 우측 문구는 «채우기 ›».
- **가진 잼 0**: 시트의 «채우기»를 비활성(`aria-disabled`)으로 두고, 그 아래에 «가진 잼이 없어요. 동기화로 잼을 받으면 채울 수 있어요.» 한 줄을 둔다.
- **채우기 입력 상태**
  - 기본값: remaining.
  - 가진 잼이 remaining보다 적으면 기본값은 balance다.
  - 입력이 0, 빈 값, 비숫자이면 «채우기»를 비활성으로 한다.
  - 제출 중에는 버튼이 «채우는 중»으로 바뀌고(`SwapText`) 중복 제출을 막는다.
- **ready**: 게이지가 가득 차고 우측 문구는 «열 수 있어요 ›». 시트에는 «열기» 버튼.
- **noSlots**: 가득 찬 게이지, 우측 문구 «빈칸이 모자라요 ›». 시트에는 안내 블록과 «인벤토리 보기». 열기 버튼은 없다.
- **열기 진행 중**: 버튼이 «여는 중»으로 바뀌고 비활성이 된다.
- **열기 결과**: 오버레이. 잠긴 채 나온 항목은 `locked` 카드로 보인다.
- **이용 정지(403 `user_suspended`)**
  - 일반 실패가 아니라 info 토스트로 낸다. 채우기는 `d.suspension.capsuleBlocked`, 열기는 `d.suspension.capsuleOpenBlocked`, 잠긴 개체는 `d.suspension.lockedItemFillBlocked`와 `lockedItemOpenBlocked`를 쓴다.
  - 버튼은 미리 비활성으로 만들지 않는다. 서버 응답으로 판단하는 `sync-flow` 선례를 따른다.
- **누름**: 알약에 `jam-press`. 키보드 포커스 링도 둔다.

## 잠긴 카드와 상세
- **기본**: 게이지가 일부 찬 잠김 카드.
- **다 찬(openable)**: 카드의 게이지는 가득 찬다. 상세에서 주 버튼이 «열기»로 바뀐다.
- **로딩**: 상세는 서버 페이지가 값을 가지고 렌더하므로 해당 없음. 채우기와 열기 처리 중 상태만 둔다.
- **빈**: 해당 없음. 잠긴 개체가 없으면 일반 카드만 나온다.
- **오류**: 채우기·열기 실패 토스트. 알려진 코드는 `d.lockedItem.fill.*`, `d.lockedItem.open.*`로 매핑하고, 알 수 없는 코드는 `d.lockedItem.fill.failed`와 `d.lockedItem.open.failed`를 쓴다.
  - `not_locked`: «이미 열린 아이템 배지예요» 토스트 뒤 `router.refresh()`.
  - `item_not_found`: 토스트 뒤 `/inventory`로 이동.
- **열기 직후**: 열린 모습(제자리 전환 뒤).
- **이용 정지**: 위와 같은 info 토스트.

### 모션

- **게이지 채움**: `ProgressBar track-gradient`의 clip-path 전환이 이미 있다(`--duration-slow`, `--ease-smooth-out`). 새 모션을 더하지 않는다.
- **채우기 성공**: 시트의 게이지가 새 값으로 차오른다. 이어서 시트는 본문 단계로 돌아간다(`--duration-fast`). 위젯의 게이지도 같은 방식으로 갱신된다.
- **시트 단계 전환(본문 ↔ 채우기)**: 내용만 짧게 교체한다. 시트 높이는 `BottomSheet` detent 안에서 유지한다.
- **버튼 문구 교체**: `SwapText`(채우는 중, 여는 중).
- **열기 결과**: 시트를 닫고, 닫힘이 끝난 뒤 `BadgeRevealOverlay`를 연다. 오버레이의 기존 진입 모션 `ds-badge-reveal-in`(220ms)을 그대로 쓴다. **높은 등급 축하 연출은 없다**(승인 사항).
- **오버레이를 닫은 뒤**: 위젯 게이지가 다음 캡슐의 값으로 `--duration-slow`로 전환된다.
- **잠긴 개체 제자리 전환**: 타일 → 그림 크로스페이드(`--duration-medium`, `--ease-smooth-out`, 그림이 scale 0.96에서 1로). 제목과 설명은 `SwapText`. 게이지 줄은 높이와 투명도를 `--duration-fast`로 접는다. 등급 칩은 움직이지 않는다.
- **prefers-reduced-motion**: 위 모든 전환을 즉시 교체로 바꾼다. 프로젝트의 기존 reduced-motion 처리(`transitions.css`)와 같은 방식으로 따른다.
- **쓰지 않는 것**: 열기 직전 흔들림이나 두근거림, 위젯 펄스, 숫자 카운트업. 열기를 부추기는 효과가 되기 때문이다(운영 로직 5.2절 연출 규칙).

### 기기·접근성

- **터치 영역**
  - 알약은 약 74px 높이 전체가 버튼이다(최소 44px 충족).
  - 시트의 «채우기»와 «열기», 입력창은 모두 44px 이상이고 입력창은 48px 이상이다.
- **가로 320px**
  - 알약 안쪽 여백 24px을 빼면 본문이 약 270px이다.
  - 1행의 우측 문구(최장 «빈칸이 모자라요 ›»)는 `shrink-0`, 제목은 `min-w-0`으로 둔다. 겹치면 우측 문구가 한 줄 유지가 우선이다.
  - 알약은 `--radius-full`이라 위아래 모서리 곡률이 크다. 1행 높이가 곡률에 닿지 않도록 위 여백 16px을 지킨다.
- **세로 568·667·844px**
  - 시트 본문과 푸터는 568px에서도 스크롤 없이 보이는 구조다.
  - 채우기 단계는 숫자 키패드가 올라오면 화면의 절반 가까이를 가린다. 입력창과 «채우기» 푸터가 키패드 위에 남는지 568px에서 카리나가 머지 뒤 실렌더로 확인한다.
- **입력창**: `inputMode="numeric"`, `enterKeyHint="done"`, 글자 크기 16px 이상(iOS 줌 방지). 숫자는 `tabular-nums`.
- **안전영역**
  - 상단은 TopNav가 처리한다.
  - 시트 푸터는 `BottomSheet`의 `footerBottomInset`을 따른다. 탭바가 보이는 화면에서는 기본값을 쓴다.
- **레이어**
  - 시트(z-50)와 `BadgeRevealOverlay`(zIndex 60)와 토스트(z-[60])가 있다.
  - 구현 전에 `docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`의 z-index 레이어 체계를 먼저 읽는다. 스태킹 컨텍스트 규칙도 같이 읽는다(`relative z-10` 조상 안의 시트가 탭바에 가려진 2026-08-25 사고).
  - 열기 성공 시 시트를 먼저 닫는 순서로 겹침 자체를 피한다.
  - 위젯을 감싸는 컨테이너에 `z-index`를 주지 않는다.
- **토스트와 오버레이 동률(60)**: 오버레이가 열린 동안은 캡슐 쪽 토스트를 띄우지 않는다.
- **접근성**
  - 알약의 `aria-label`은 «캡슐, {상태}»다.
  - 게이지는 색과 외곽선으로만 읽히는 것이 아니라, 상태 문구가 같은 정보를 글자로 준다.
  - 진행 숫자와 퍼센트는 화면에도 스크린리더에도 읽히지 않게 한다. 운영 로직 4.3절이 숫자 진행 표시를 막는다.
  - 열기 결과와 오류 문구는 라이브 리전으로 알린다.

### 마감 메모

- **알약을 꾸미지 않는다.** 그라데이션 배경, 유리질, 그림자, 반투명 면을 더하지 않는다. 색은 게이지 하나(`--progress-sweep`)만 갖고, 알약 면은 `--surface`와 1px `--border`뿐이다. 모양이 임시이므로 장식은 나중에 바꿀 때 걸림돌이 된다.
- **캡슐 아이콘이나 글리프를 새로 그리지 않는다.** 새 아이콘은 승인 범위 밖이다. 알약 모양과 게이지가 그 역할을 한다.
- **«열 수 있어요»를 점, 배지, 펄스, 색 강조로 부추기지 않는다.** 텍스트와 가득 찬 게이지로만 알린다. `.jam-quest-pulse`는 퀘스트 전용이다.
- **게이지 위나 옆에 숫자, 퍼센트, «120 / 300»을 쓰지 않는다.** `labelType="none"`으로 고정한다.
- **잠김 표시에 자물쇠에 더한 등급 색, 글로우, 그라데이션을 쓰지 않는다.** 등급은 `RarityBadge` 칩 하나로만 전달한다(`BadgeRevealCarousel`의 선례).
- **위젯을 `Card` 안에 다시 넣지 않는다.** 시트 안에도 카드를 중첩하지 않는다. 알약이 그 자체로 면이다.
- **습관적 가운데 정렬 금지.** 알약 1행은 좌/우 분할, 시트 본문은 왼쪽 정렬이다. 잠긴 상세의 타일만 상단에 가운데 둔다. 히어로 하나뿐이다.
- **두 위치에서 같은 컴포넌트를 쓰되 크기나 여백을 위치별로 갈라 쓰지 않는다.** 위치별 차이는 부모의 여백(`gap-6`)만이다.
- **잠긴 카드의 게이지 줄이 일반 카드의 만료 칩 자리와 어긋나지 않게 한다.** 그리드 3열에서 행 높이가 일반 카드와 같아야 한다. 일반 카드와 잠긴 카드를 한 그리드에 섞은 Story로 확인한다.
- **카피 규칙**
  - 용어는 «잠김»(잠금 아님), «채우기», «열기», «잼은/잼을»(받침 있는 말)이다.
  - 다시 열기를 부추기는 말(한 번만 더, 곧 좋은 게 나와요)과 낮은 등급을 깎아내리는 말(꽝)은 쓰지 않는다.
  - 새 문구는 `ko.ts`의 `d.capsule`과 `d.lockedItem` 묶음에 더한다. UX 라이팅 가이드와 `fluent-korean` 지침을 따른다.
- **가림 규칙 점검 (구현 중 발견할 때 아현에게 알린다)**
  - `/badges/[id]?item=` 경로는 잠긴 개체 id가 와도 이름과 그림을 그리는 경로가 남아 있을 수 있다. 3-1이 인벤토리 상세, 이력 API, 타인 프로필, 컬렉션 조회를 가리지 못했다고 티켓에 적혀 있으므로 이 경로도 같이 확인한다.
  - 인벤토리 서버 페이지에서 잠긴 개체의 이름과 그림이 클라이언트 props로 내려가지 않는지도 확인한다.

### 범위

`ui` 유형이지만 `design-system/`을 건드리므로 연결 범위를 표기한다.

- **ProgressBar(`outlined`)**: «연결된 컴포넌트»에 해당한다. 서비스에 즉시 반영된다. 새 prop만 더하고 기본 동작은 바꾸지 않는다. 기존 8곳과 `DualAxisGauge`가 그대로인지 Story로 확인한다.
- **BadgeGridCard(`locked`)**: «병존 구현»에 해당한다. DS만 고치면 서비스가 따라오지 않으므로 `design-system/components/patterns/BadgeGridCard.jsx`와 `jam-web/src/components/ui/BadgeGridCard.tsx`를 함께 고친다. `npm run ds:check`의 페어 검사로 값 일치를 확인한다.
- **LockedTile(신규)**: 신규 MODULAR 컴포넌트다. 서비스는 `@ds/components/cards/LockedTile`로 바로 import한다(연결된 부류). Story, `.d.ts`, `.prompt.md`, `_ds_manifest.json`, `design-system/readme.md` 색인을 함께 만든다.
- **BadgeRevealCarousel**: 인라인 잠금 타일을 LockedTile로 교체한다. 화면은 달라지지 않는다. 연결된 컴포넌트라 즉시 반영되므로 Story의 `locked` 케이스를 변경 전후로 대조한다.
- **토큰**: 변경 없음.
- **서비스 전용**: `CapsulePill`, `CapsuleWidget`, `CapsuleSheet`, `JamFillPanel`, `LockedItemDetail`은 `design-system/`에 넣지 않는다.

- 투데이의 `TodayStatusStrip` 아래에 알약이 보이고, 내 프로필에서는 헤더와 통계 탭 사이에 같은 알약이 보인다.

  - 잠긴 채 나온 개체는 잠금 타일 카드로 나온다.
  - 높은 등급 축하 연출은 없다.
- 인벤토리 빈칸이 모자라면 «열기»가 없고 안내, 지금 빈칸 수와 필요한 빈칸 수, 인벤토리 링크가 보인다.
- 가진 잼이 0이면 «채우기»가 비활성이고 이유 문구가 보인다.

## 잠긴 개체 (2회)
- 인벤토리 그리드에서 잠긴 개체는 잠김 카드로 보인다. 일반 카드와 같은 면과 같은 행 높이이며 «잠김» 표시, 등급 칩, 게이지가 있다. 이름, 그림, 설명, 컬렉션, 트라이브, 일련번호가 DOM에도 없다.

## 판정 근거
- 사용자 결정 (1)의 «투데이와 내 프로필, 타인에게 안 보임»은 `isOwnProfile`일 때만 서버에서 조회하고 prop을 내리는 방식으로 닫을 수 있다. 클라이언트에서 숨기면 팔로워에게 데이터가 실리므로 쓰지 않는다.
- 채우기, 열기, 결과를 «두 곳의 위젯이 같은 시트를 여는 안»으로 정했다. 스택 화면 안은 새 라우트와 뒤로가기 분기(투데이/프로필)가 필요해 변경이 더 크다. 시트 안은 새 라우트가 없고, 같은 컴포넌트를 두 번 마운트하며, 열기 결과는 기존 `BadgeRevealOverlay`를 재사용한다.
- 결정 (2)의 «모양을 한 컴포넌트에 가둔다»는 `CapsulePill.tsx`가 모양을 아는 유일한 파일이 되는 구조로 반영했다. 위젯, 시트, 클라이언트 API 코드는 모양을 모른다.
- 결정 (3)의 제자리 전환은 `inventory/[itemId]/page.tsx`가 `locked`일 때 리다이렉트하지 않고 `LockedItemDetail`을 그리는 구조로 한다. 현재 이 페이지는 무조건 `/badges/{badge_id}?item=...`으로 리다이렉트하므로, 이를 그대로 두면 잠긴 개체의 이름과 그림이 노출된다.
- 가진 잼 표시 위치는 미정이다. 이 티켓은 캡슐 시트, 잠긴 상세, 공용 채우기 입력 단계, 이렇게 세 곳에만 표시하도록 다시 정했다. 위젯에는 표시하지 않는다.
