# [Feature] JAM 2.0 인벤토리·컬렉션 마무리: 잠김 제외, 가득 참 표시와 알림, 장착 풀기 제한

## 핵심 요약

- 요구사항: 운영 로직 8.2·8.3·6.4절 가운데 묶음 3에 남은 것을 닫는다. (1) 컬렉션 화면이 잠긴 개체를 기준에서 빼고 가린다(잠긴 아이템 배지는 컬렉션 칸에 꽂을 수 없고 완성으로 치지 않는다). (2) 인벤토리 화면에 가득 참 표시와 남은 칸 3칸·1칸일 때의 알림(2-5가 묶음 3으로 넘긴 것). (3) 인벤토리가 가득 차 있으면 장착을 풀 수 없다. (4) 장착·드랍·믹스에서 막힌 까닭을 화면이 알려 준다(3-1이 서버에서 거부한 것).
- 구현 계획: 시작 때 사용자 결정 3건을 질문하고 채원 사전 판정을 받는다. 파일 단위 계획을 옮겨 쓴다. 규모에 따라 1~2회.
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 컬렉션 `jam-web/src/app/(main)/collections/`, 컬렉션 API `app/api/itembooks/`, 장착 RPC(마이그레이션 222 `slot_item_into_book_tiered`, `swap_item_in_book_tiered`), 완성 판정 `jam-web/src/lib/itembook/completion-basis.ts`, 인벤토리 `app/(main)/inventory/`(`QuestBagGrid.tsx`), 칸 수 설정 `inventory_policy`와 어드민 인벤토리 정책 화면, 알림 `app/api/notifications/`와 `app/(main)/notifications/`, 가득 참 표시 선례 `PendingItemsPickOverlay.tsx`(빈칸 0 문구, `d.syncPending.*`), 스펙 운영 로직 6.4·8.2·8.3절.

## 배경 / 문제 정의

2-5는 가득 참 표시와 알림(6.4절)을 묶음 3의 인벤토리 화면으로 넘겼다. 3-1은 잠긴 개체의 장착을 서버에서 거부하게 했고, 3-3·3-4는 잠긴 카드를 인벤토리에 보여 준다. 컬렉션 화면은 «인벤토리에 가진 열린 아이템 배지가 속한 컬렉션만 보여 준다. 잠긴 아이템 배지는 열기 전에 컬렉션을 가리므로 기준에서 뺀다»(8.3절)를 지켜야 한다. 장착한 아이템 배지를 풀면 인벤토리 칸이 차지되므로, 가득 차 있으면 장착을 풀 수 없다(8.3절).
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **가득 참 알림의 기준과 저장**: 남은 칸 3칸과 1칸일 때 알림을 한 번씩 보낸다(6.4절). 알림은 기존 알림 테이블에 새 종류로 더하고(추천), 한 단계에 한 번만 보내려고 «마지막으로 보낸 단계» 칸을 새로 더한다. 대안은 화면에서만 표시하고 알림은 묶음 6(홈·소셜·알림)으로 미루는 것이다.
2. **가득 참 표시의 모양**: 인벤토리 화면의 칸 수 막대 옆 문구와 색 없는 표시(추천, 새 색을 만들지 않음)와 상단 안내 카드. 시작 때 채원 판정으로 정한다.
3. **장착 풀기 제한의 위치**: DB 함수에서 가득 참을 확인해 막고(추천, 경쟁 상태를 잠금 안에서 막는다) 화면은 막힌 까닭만 알린다. 장착 RPC(222)는 옛 프로덕션 코드가 쓰므로 바꾸지 않고 새 함수 또는 새 경로로 더한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **컬렉션 화면의 잠김 제외**: 보여 줄 컬렉션의 기준(가진 열린 아이템 배지가 속한 컬렉션)에서 잠긴 개체를 빼고, 장착 후보 목록에서 잠긴 개체를 뺀다. 완성 판정(`completion-basis.ts`)은 잠긴 개체를 세지 않는다. 장착 API가 잠긴 개체를 거부하는 응답을 화면이 이해한다.
- **가득 참 표시**: 빈칸이 0이면 «인벤토리가 가득 찼어요»와 해결 경로(장착, 드랍, 믹스)를, 남은 칸이 적으면 남은 칸 수를 인벤토리 화면에 보인다. 칸 수 값은 인벤토리 정책(어드민)이다.
- **남은 칸 알림**: 남은 칸이 3칸, 1칸이 되는 순간 알림을 한 번씩 보낸다. 빈칸이 늘면 단계를 풀어 다시 보낼 수 있게 한다.
- **장착 풀기 제한**: 인벤토리가 가득 차 있으면 장착 풀기를 거부한다(409, 까닭 코드). 교체(swap)는 칸 수가 변하지 않으므로 허용한다.
- **막힌 까닭 안내**: 잠긴 개체의 장착·믹스·드랍, 가득 참일 때의 장착 풀기가 서버에서 거부되면 일반 실패가 아니라 까닭이 보이는 안내를 낸다.
- 새 칸과 새 함수는 덧붙이기만 한다. 생성 타입을 같은 커밋에 맞춘다.

### UI/UX 관점

- 채원 사전 판정을 따른다. 사용자 노출 문구는 UX 라이팅 가이드와 `fluent-korean` 지침을 따른다(가득 참 문구는 2-5의 «단호하고 사실적으로» 방향과 맞춘다).

## 구현 계획 (회차)

시작 때 파일 단위 계획을 이 절에 옮겨 쓰고 `planOnlyWaiver`를 넘긴다. 규모가 크면 1회(서버, 알림, 장착 풀기 제한), 2회(화면)로 나눈다.

## 완료 조건

### 구현 범위 (게이트 판정 대상, 회차마다 해당 항목)

- 컬렉션 화면이 잠긴 개체를 기준과 장착 후보와 완성 판정에서 뺀다. 시험이 고정한다.
- 인벤토리가 가득 차 있으면 장착 풀기가 서버에서 거부되고, 교체는 허용된다. 동시 요청에서도 칸 수를 넘기지 않는다.
- 인벤토리 화면이 가득 참과 남은 칸을 알리고, 남은 칸 3칸·1칸 알림이 한 단계에 한 번만 간다.
- 잠김·가득 참으로 막힌 장착·믹스·드랍이 까닭이 보이는 안내를 낸다.
- 채원 사후 리뷰에 중대 문제가 없고, 마이그레이션이 옛 객체를 바꾸지 않으며 되돌림 SQL을 싣는다. `docs/service/prd/`에 반영되어 있다.
- 실렌더 확인(세로 568·667·844px, 너비 320~430px 겹침과 터치 영역)은 카리나가 머지 뒤 push 전에 로컬에서 한다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 사용자 확인 1~3번의 결정을 이 티켓 「사용자 결정」 절에 기록한다. SQL 실행은 승인과 롤백 실측 뒤에 한다.
