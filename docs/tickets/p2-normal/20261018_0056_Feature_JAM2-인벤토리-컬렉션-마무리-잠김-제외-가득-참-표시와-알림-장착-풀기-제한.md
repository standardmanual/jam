# [Feature] JAM 2.0 인벤토리·컬렉션 마무리: 잠김 제외, 가득 참 표시와 알림, 장착 풀기 제한

## 핵심 요약

- 요구사항: 운영 로직 8.2·8.3·6.4절 가운데 묶음 3에 남은 것을 닫는다. (1) 컬렉션 화면이 잠긴 개체를 기준에서 빼고 가린다(잠긴 아이템 배지는 컬렉션 칸에 꽂을 수 없고 완성으로 치지 않는다). (2) 인벤토리 화면에 가득 참 표시와 남은 칸 3칸·1칸일 때의 알림(2-5가 묶음 3으로 넘긴 것). (3) 인벤토리가 가득 차 있으면 장착을 풀 수 없다. (4) 장착·드랍·믹스에서 막힌 까닭을 화면이 알려 준다(3-1이 서버에서 거부한 것).
- 구현 계획: 시작 때 사용자 결정 3건을 질문하고 채원 사전 판정을 받는다. 파일 단위 계획을 옮겨 쓴다. 규모에 따라 1~2회.
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 컬렉션 `jam-web/src/app/(main)/collections/`, 컬렉션 API `app/api/itembooks/`, 장착 RPC(마이그레이션 222 `slot_item_into_book_tiered`, `swap_item_in_book_tiered`), 완성 판정 `jam-web/src/lib/itembook/completion-basis.ts`, 인벤토리 `app/(main)/inventory/`(`QuestBagGrid.tsx`), 칸 수 설정 `inventory_policy`와 어드민 인벤토리 정책 화면, 알림 `app/api/notifications/`와 `app/(main)/notifications/`, 가득 참 표시 선례 `PendingItemsPickOverlay.tsx`(빈칸 0 문구, `d.syncPending.*`), 스펙 운영 로직 6.4·8.2·8.3절.

## 배경 / 문제 정의

2-5는 가득 참 표시와 알림(6.4절)을 묶음 3의 인벤토리 화면으로 넘겼다. 3-1은 잠긴 개체의 장착을 서버에서 거부하게 했고, 3-3·3-4는 잠긴 카드를 인벤토리에 보여 준다. 컬렉션 화면은 «인벤토리에 가진 열린 아이템 배지가 속한 컬렉션만 보여 준다. 잠긴 아이템 배지는 열기 전에 컬렉션을 가리므로 기준에서 뺀다»(8.3절)를 지켜야 한다. 장착한 아이템 배지를 풀면 인벤토리 칸이 차지되므로, 가득 차 있으면 장착을 풀 수 없다(8.3절).
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **가득 참 알림의 기준과 저장**: 남은 칸 3칸과 1칸일 때 알림을 한 번씩 보낸다(6.4절). 알림은 기존 알림 테이블에 새 종류로 더하고(추천), 한 단계에 한 번만 보내려고 «마지막으로 보낸 단계» 칸을 새로 더한다. 대안은 화면에서만 표시하고 알림은 묶음 6(홈·소셜·알림)으로 미루는 것이다.
2. **가득 참 표시의 모양**: 인벤토리 화면의 칸 수 막대 옆 문구와 색 없는 표시(추천, 새 색을 만들지 않음)와 상단 안내 카드. 시작 때 채원 판정으로 정한다.
3. **장착 풀기 제한의 위치**: DB 함수에서 가득 참을 확인해 막고(추천, 경쟁 상태를 잠금 안에서 막는다) 화면은 막힌 까닭만 알린다. 장착 RPC(222)는 옛 프로덕션 코드가 쓰므로 바꾸지 않고 새 함수 또는 새 경로로 더한다.

## 사용자 결정과 조사 결과 (2026-10-18)

- 결정 1(알림): **새 코드 경로에서 지급 직후 보낸다.** 동기화·캡슐·믹스·받기 등 새 코드가 아이템 배지를 준 직후 한 곳의 함수가 남은 칸을 보고, 3칸·1칸 단계에 들어서는 순간 알림을 한 번씩 보낸다. DB 트리거는 쓰지 않는다(옛 프로덕션 코드의 지급에서도 알림이 생겨 옛 알림 화면에 «알 수 없는 소식»이 보일 수 있다). 알림 종류(DB enum `notification_type`)에 새 값 `inventory_slots_low`를 더하고, 인벤토리 행에 «마지막으로 보낸 단계» 칸을 새로 더한다. 옛 프로덕션 알림 화면은 모르는 종류를 `d.notifications.unknown` 문구로 처리하므로 깨지지 않는다(조사 결과, `message.ts`의 default 분기).
- 결정 3(장착 풀기 제한): **이미 DB 함수에 있다.** `unslot_item_from_book`(마이그레이션 111)이 인벤토리 행 잠금 안에서 `used_slots >= max_slots`이면 `inventory_full`로 거절한다. 새 SQL이 필요 없고 이 티켓은 화면이 그 거절 까닭을 안내하는지(`inventory_full`을 일반 실패로 처리하지 않는지)와 시험을 확인한다. 교체(swap)는 칸 수가 변하지 않아 허용 그대로다.
- 컬렉션 화면의 잠김 제외: 3-4 2회가 이미 처리했다(`/{username}/collections`, 컬렉션 상세 장착 후보, `/api/itembooks` 두 곳, 프로필 컬렉션 수에 `locked=false`). 이 티켓은 완성 판정(`lib/itembook/completion-basis.ts`)이 잠긴 개체를 세지 않는지 확인하고 시험으로 고정한다.
- 결정 2(가득 참 표시의 모양)는 채원 사전 판정에서 정한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **컬렉션 화면의 잠김 제외**: 보여 줄 컬렉션의 기준(가진 열린 아이템 배지가 속한 컬렉션)에서 잠긴 개체를 빼고, 장착 후보 목록에서 잠긴 개체를 뺀다. 완성 판정(`completion-basis.ts`)은 잠긴 개체를 세지 않는다. 장착 API가 잠긴 개체를 거부하는 응답을 화면이 이해한다.
- **가득 참 표시**: 빈칸이 0이면 «인벤토리가 가득 찼어요»와 해결 경로(장착, 드랍, 믹스)를, 남은 칸이 적으면 남은 칸 수를 인벤토리 화면에 보인다. 칸 수 값은 인벤토리 정책(어드민)이다.
- **남은 칸 알림**: 남은 칸이 3칸, 1칸이 되는 순간 알림을 한 번씩 보낸다. 빈칸이 늘면 단계를 풀어 다시 보낼 수 있게 한다.
- **장착 풀기 제한**: 인벤토리가 가득 차 있으면 장착 풀기를 거부한다(409, 까닭 코드). 교체(swap)는 칸 수가 변하지 않으므로 허용한다.
- **막힌 까닭 안내**: 잠긴 개체의 장착·믹스·드랍, 가득 참일 때의 장착 풀기가 서버에서 거부되면 일반 실패가 아니라 까닭이 보이는 안내를 낸다.
- 새 칸과 새 함수는 덧붙이기만 한다. 생성 타입을 같은 커밋에 맞춘다.

### UI/UX 관점

- 채원 사전 판정을 따른다. 사용자 노출 문구는 UX 라이팅 가이드와 `fluent-korean` 지침을 따른다(가득 참 문구는 2-5의 «단호하고 사실적으로» 방향과 맞춘다).

## 구현 계획 (회차)

시작 때 파일 단위 계획을 이 절에 옮겨 쓰고 `planOnlyWaiver`를 넘긴다. 규모가 크면 1회(서버, 알림, 장착 풀기 제한), 2회(화면)로 나눈다.

## 사용자 결정 (2026-10-18, 채원 판정에 대한 답)

1. 알림 역할: **새 `inventory_slots_low`는 남은 칸 3개·1개 단계의 선제 알림, 기존 `inventory_full`은 남은 칸 0개일 때만 남긴다**(권장대로). 배치(`lib/notifications/batch/account.ts` 111줄 근처)의 조건이 «남은 칸 3 이하»에서 «0»으로 바뀌어, 지금 3개 이하에서 받던 «꽉 찼어요» 알림은 새 알림으로 대체된다.
2. 인벤토리 화면 표시와 새 문구: **모두 제안대로.** 남은 칸 1~3개는 «N개만 남았어요»로 줄을 진하게 올리고 굵기만 더한다(새 색·카드 없음). 0개일 때만 안내 카드를 쓰고 본문을 고친다. 단위는 «칸»이 아니라 «개»다. 알림 문구, 가득 참 안내 카드 본문, 해제 가득 참 문구(숫자 제거), `msgInventoryFull`의 «픽업이 안 될 수 있어요»를 실제 동작에 맞게 고친다. 최종 문구는 UX 라이팅 가이드와 fluent-korean 검수를 거친다.
3. 막힌 장착·믹스·드랍: **오류가 아니라 안내(info) 톤**(권장대로). 믹스는 결과 오버레이 대신 info 토스트, 드랍은 error 토스트를 info로, 해제 가득 참 문구에서 «50개»를 뺀다. 진짜 실패는 error 그대로.
4. 3열 카드 이름 줄바꿈: **공통 카드(`BadgeGridCard`)에서 공백 기준 줄바꿈으로 고친다**(권장대로). 320px에서 세 줄이 되면 잠긴 카드만 세 줄까지 허용한다(실렌더 뒤 결정).

## 채원 사전 판정 (2026-10-18, 위 사용자 결정으로 승인 항목 처리)

### 판정 요지

재사용 (새 컴포넌트·새 색·새 토큰 없음). MODULAR 확장 없음, 서비스 전용 화면 수정으로 끝난다. ds 유형 아님.

### 컴포넌트

재사용만 한다.
- 인벤토리 화면: jam-web/src/app/(main)/inventory/page.tsx의 기존 `ProgressBar`(@ds/components/feedback/ProgressBar)와 `d.inventory.slotsDetail` 줄, 기존 가득 참 안내 카드(인라인 div, 컴포넌트 아님)를 그대로 쓴다. 새 카드·배너 컴포넌트는 만들지 않는다.
- 알림 화면: app/(main)/notifications/NotificationsClient.tsx의 `TypeIcon`에 `inventory_slots_low`를 `inventory_full`과 같은 `PackageIcon`으로 더한다. 경고 재평가는 기존 `view.warning` 경로(bg-warning 아이콘 칸)를 쓴다.
- 안내 토스트: 기존 `toast(msg, 'info')`(DS Toast)를 쓴다. 새 variant는 만들지 않는다.
- 막힌 장착: SlotGrid의 기존 그리드 배너·시트 배너를 그대로 쓴다.
- 판별 모듈: `lib/suspension/suspended-block.ts`를 본뜬 순수 모듈 하나를 새로 둔다(예: `lib/inventory/locked-item-block.ts`의 `isLockedItemBody(status, body)`). UI 컴포넌트가 아니라 로직이다. `lib/inventory/lockedItem.ts`는 서버 쪽 조회 함수가 섞여 있어 클라이언트에서 가져오면 경계 위반 위험이 있으니 같은 파일을 확장하지 않는다.
- 카드 줄바꿈: components/ui/BadgeGridCard.tsx 이름 `<p>`에 클래스를 더하는 것으로 끝난다.

### 토큰

새 토큰·새 색 없음.
- 텍스트: `--foreground`(강조 줄), `--muted`(기본 남은 칸 줄), `--surface`+`--border`(안내 카드, 기존), `--background`(카드 안 CTA, 기존).
- 알림 경고면: `--warning`과 `--foreground` 아이콘(기존 경고 규칙, 8.64:1).
- 남은 칸이 적을 때(1~3개): ProgressBar 채움색을 바꾸지 않는다. `--progress-short`는 «채우는 중 모자람»이라는 다른 뜻이라 쓰지 않는다. 의미가 다른 곳에 색을 재활용하면 슬롭이다.
- 타이포: 기존 `text-sm`(남은 칸 줄), `text-base`(카드 본문). 글자 크기를 줄이는 임의 값(`text-[13px]` 등)은 쓰지 않는다.

### 배치

(1) 인벤토리 화면 머리, 위에서 아래로
- 제목 «인벤토리» (text-5xl) / 우측 «믹스하기» pill (기존)
- ProgressBar (height 6, 기존)
- 남은 칸 줄 (text-sm). 세 갈래다.
  · 남은 칸 4개 이상: `{used}/{max}개 사용 중 · {remaining}개 남음` (기존 `slotsDetail`, --muted)
  · 남은 칸 1~3개: `{used}/{max}개 사용 중 · {remaining}개만 남았어요` 신규 문구 `slotsDetailLow`. 줄 전체 색을 --foreground로 올리고 font-bold는 «N개만 남았어요» 구간에만 준다. 색 추가 없이 대비와 굵기만으로 구분한다.
  · 남은 칸 0개: 줄은 기존 `slotsDetail`(0개 남음)을 유지하고 바로 아래에 기존 안내 카드를 둔다.
- 안내 카드는 0칸일 때만 나온다. 1~3칸에는 카드를 만들지 않는다. 카드는 «막혔다»는 뜻이다. 아직 막히지 않았는데 카드를 띄우면 매번 경고만 보게 되고, 선제 알림은 알림 화면이 맡는다.
- 안내 카드(기존 모양): 본문 text-base 하나 + «드랍하기» pill 하나(/drops). 믹스는 머리의 «믹스하기»가 이미 있어 CTA를 늘리지 않는다. 본문만 [현상→원인→해결책]에 해결 경로 세 가지를 모두 넣도록 고친다.
  제안 문구(최종은 fluent-korean 검수): «인벤토리가 꽉 찼어요. {max}개까지만 보관할 수 있어서 새 아이템 배지를 받을 수 없어요. 컬렉션에 장착하거나, 믹스하거나, 드랍해서 자리를 비워 주세요.»
  주의: 지금 `fullNoticeBody`가 «지금 활동을 동기화해도 새 아이템 배지를 받을 수 없어요»라고 단정한다. 2-5의 보류·고르기 흐름(`d.syncPending`)에서 실제로 무엇이 일어나는지 아현이 확인하고, 사실과 맞게 쓴다(맞지 않으면 «받을 수 없어요» 대신 «바로 받을 수 없어요»).

(2) 알림 화면: 두 종류의 역할을 나눈다
- `inventory_slots_low` (신규, 사건): 남은 칸이 3개, 1개 단계에 들어선 순간 지급 직후 한 번. payload는 `{ remaining_slots: 3 | 1, max_slots }`다. 행: [PackageIcon, 경고 판정에 따라 bg-warning 칸] + 한 줄 문구 + 시각 + 읽지 않음 dot(기본 bump). 탭하면 /inventory(`href.ts` single).
  제안 문구(과거형이라 시간이 지나도 거짓이 되지 않는다):
  · 3개 단계: «인벤토리 남은 칸이 3개로 줄었어요. 다 차기 전에 장착·믹스·드랍으로 자리를 만들어 보세요»
  · 1개 단계: «인벤토리 남은 칸이 1개로 줄었어요. 다 차면 새 아이템 배지를 받을 수 없어요»
  단위는 인벤토리 화면의 «개»와 맞춘다(`slotCount`). 티켓의 «칸» 표기는 사용자 화면 문구로 쓰지 않는다(slotsDetail 주석의 용어 규칙과 같은 취지).
  경고 판정: 라이브 남은 칸 ≤ 3이면 경고면, 4 이상이면 일반 PackageIcon으로 강등된다(`warning.ts`의 inventory_full과 같은 규칙). `feed.ts`의 `needsInventory`도 이 종류를 포함해야 한다.
- `inventory_full` (기존, 상태): 0칸일 때만 남긴다. 배치 조건(account.ts:111)을 `remaining > THRESHOLD` 건너뛰기에서 «남은 칸이 0이 아니면 건너뛰기»로 좁히고, `msgInventoryFull`의 «픽업이 안 될 수 있어요»를 실제 동작(위 2-5 확인)에 맞게 고친다. 이렇게 해야 3칸 이하 구간에서 한 사건에 알림이 두 개 생기지 않는다.
- 이 배치 조건 변경은 기존 알림의 눈에 보이는 동작 변화다. 3칸 이하 유저가 배치로 받던 «꽉 찼어요»는 사라지고 새 알림으로 대체된다. 승인 항목에 넣었다.

(3) 막힌 까닭 안내
- 컬렉션 장착·교체·해제(SlotGrid): 기존 그리드 상단 배너와 시트 배너를 유지한다. 문구는 서버가 이미 준다. 해제의 `inventory_full` 문구에서 «50개»를 빼고 숫자 없이 고친다. 제안: «인벤토리가 꽉 차서 해제할 수 없어요. 인벤토리에서 드랍하거나 믹스해 자리를 만든 뒤 다시 해제해 주세요.» (숫자가 사라지면 어드민 칸 수 정책이 바뀌어도 어긋나지 않고 서버에서 max를 따로 읽을 필요도 없다.) 두 거절 응답(잠김·해제 가득 참)에 `code`를 실어 화면이 일반 실패와 구분하게 한다.
- 믹스(CombineClient): 409 + `locked_item_not_allowed`를 `pending_results_exist` 분기 옆에서 가로채 `toast(data.message ?? d.lockedItem.combine, 'info')`로 낸다. 결과 오버레이를 열지 않고 슬롯도 그대로 둔다(소각 전 거절이므로).
- 드랍(PoiCarouselModal): 같은 판별이 참이면 `toast(err.error, 'info')`. 그 밖의 실패는 기존 'error' 그대로.
- 예방이 먼저다: 믹스 재료 후보와 드랍 선택 목록이 잠긴 개체를 이미 빼는지 아현이 확인한다(두 파일에 `locked` 처리가 보이지 않는다). 이미 빼고 있으면 위 토스트는 경합 때만 닿는 안전망이고, 빼지 않으면 목록에서 빼는 것이 일반 실패 안내보다 먼저 할 일이다.

(4) BadgeGridCard 이름 줄
- 이름 `<p>`: `line-clamp-2 leading-tight w-full text-center`에 `break-keep wrap-break-word`를 더한다. 공백에서만 줄이 바뀌고, 공백 없는 긴 이름은 `wrap-break-word`가 안전하게 꺾는다.

### 상태 목록

- 로딩: 인벤토리 화면은 서버 렌더라 이 티켓이 새로 만드는 로딩 상태는 없다(기존 유지). 알림 화면도 기존 로딩 유지. 제출 중 상태는 믹스(`loading`)·장착(`pendingBadgeId`)이 이미 있다.
- 빈: 인벤토리가 비면 기존 `EmptyState`. 남은 칸은 max개이므로 가득 참·적음 표시는 나오지 않는다. 알림이 없을 때도 기존 빈 상태.
- 오류: 막힌 까닭(잠김, 가득 참 해제)은 «오류»가 아니라 안내(info)로 낸다. 진짜 실패(네트워크, 타임아웃, 500)는 기존대로 error 톤을 유지한다. 알림 행의 알 수 없는 종류는 기존 `d.notifications.unknown`.
- 인벤토리 남은 칸: 4개 이상(기본), 1~3개(강조 줄만), 0개(안내 카드 추가).
- 알림 `inventory_slots_low`: 3개 단계·1개 단계 문구 2종 × 경고(라이브 남은 칸 ≤ 3) / 일반(강등) × 읽음·안읽음.
- 알림 `inventory_full`: 0칸 경고 / 일반(강등).
- 막힌 장착·믹스·드랍: 잠김 거절, 해제 가득 참 거절, 그 밖의 실패(기존 error). 비활성 상태는 새로 두지 않는다.
- BadgeGridCard 이름: 두 줄 안에 들어가는 이름, 세 줄이 필요한 이름(320px), 공백 없는 긴 이름.

### 모션

새 모션을 더하지 않는다.
- 남은 칸 줄 문구·강조는 값이 바뀔 때 즉시 바뀐다. 숫자 카운트 애니메이션이나 깜빡임은 넣지 않는다.
- 안내 카드는 기존 CTA의 `active:scale-95 transition-transform duration-100`만 유지한다. 등장·퇴장 애니메이션은 넣지 않는다.
- info 토스트는 기존 DS Toast의 등장 동작을 그대로 쓴다. 알림 행도 기존과 같다.
- prefers-reduced-motion에서 추가로 줄일 것이 없다.

### 기기·접근성

- 320~430px에서 안내 카드 본문은 3~4줄까지 늘어난다. 카드는 가로 인셋(px-4)을 유지하고 edge-to-edge로 만들지 않는다. 문장은 `break-keep wrap-break-word`.
- CTA pill은 기존 min-h-11(44px)을 유지한다. 알림 행 터치 영역도 기존 행 높이를 유지한다.
- 세로 568px(소형 기기)에서 머리(제목+바+줄+카드)가 화면의 절반을 넘지 않게 카드 문구를 3줄 이내로 쓴다. 넘으면 문구를 줄이지 카드를 접는 장치를 만들지 않는다.
- 안전영역: 이 화면은 기존 레이아웃이라 새 고정 요소가 없다. 토스트는 기존 위치.
- BadgeGridCard 3열 320px: 카드 안쪽 폭이 약 68px라 «잠긴 아이템 배지»가 한 줄에 못 들어간다. `break-keep`을 적용한 뒤 «잠긴 아이템 / 배지»(2줄)로 들어가는지 320px 실렌더로 확인한다(카리나가 머지 뒤 push 전에 한다). 측정 전이라 단정하지 않는다. 안쪽 폭이 모자라 세 줄이 되면 아래 우선순위를 따른다.
  1) 글자 크기를 줄이지 않는다.
  2) 잠긴 카드에만 `line-clamp-3`을 준다.
  3) 공통 안쪽 여백(p-3)을 줄이는 방안은 모든 카드에 퍼지므로 마지막 수단이다.
  열린 카드의 긴 이름은 `break-keep` + 기존 `line-clamp-2`로 충분하다. 두 줄을 넘는 이름은 말줄임으로 자른다.

### 마감 메모

- 1~3칸 구간에 안내 카드를 띄우는 것은 지양한다. 항상 경고만 보이는 화면이 되고, 0칸일 때 카드의 신호가 죽는다. 알림이 선제 안내를 맡는다.
- 남은 칸이 적다고 ProgressBar를 노랑·빨강으로 바꾸지 않는다. 새 색이 되고, `--progress-short`는 뜻이 다르다.
- 알림 아이콘을 새로 그리지 않는다. 같은 PackageIcon이다.
- 숫자를 드러내려고 «N/N» 큰 숫자 위젯·유리질 카드·그라디언트 강조를 만들지 않는다.
- 막힌 까닭을 error 토스트(빨강)로 내면 사용자가 잘못한 것처럼 보인다. 이용 정지·받지 않은 결과 선례처럼 info로 낸다.
- 문구에 숫자를 박지 않는다(«50개» 사례). 칸 수는 어드민 정책값이다.
- 알림 문구에 라이브 숫자를 단정으로 쓰지 않는다(`줄었어요` 같은 사건 과거형을 쓴다).
- 사용자 문구에 «슬롯»·«개체»를 쓰지 않는다. 쓰는 말은 «칸 → 개»(인벤토리 화면 표기)·«일련번호»다.
- 가운데 정렬을 늘리지 않는다. 카드 본문은 좌측 정렬(기존), 카드 이름만 기존대로 가운데다.

### 범위

ds 유형이 아니라 해당 없음. 연결 범위 분류를 하지 않는다. 서비스 UI 연결만 있다. 새 MODULAR 승격 후보도 없다. 새 컴포넌트와 새 토큰이 없고, 카드 줄바꿈은 서비스의 `components/ui/BadgeGridCard.tsx` 수정이며 design-system/components에는 BadgeGridCard가 없다.

### 완료 조건

1. 인벤토리: 남은 칸 4개 이상이면 지금과 같고, 1~3개면 남은 칸 줄이 «N개만 남았어요»로 --foreground 굵게 바뀌며 카드는 없다. 0개면 기존 카드가 나오고 본문에 장착·믹스·드랍이 모두 들어 있다. 새 색이 쓰이지 않았다.
2. 알림: 3개·1개 단계에서 `inventory_slots_low`가 한 번씩만 오고, 알림 화면에 PackageIcon(경고면)과 위 문구로 나오며 탭하면 /inventory로 간다. `inventory_full`은 0칸에서만 생기고 3칸 이하 구간에서 알림이 중복되지 않는다. 옛 앱 호환은 `d.notifications.unknown`으로 깨지지 않는다.
3. 막힘: 잠긴 개체의 장착·믹스·드랍과 가득 참 해제가 일반 «실패» 톤이 아니라 까닭이 보이는 안내로 나온다. 믹스는 결과 오버레이를 열지 않고 info 토스트다. 드랍은 info 토스트다. 해제의 가득 참 문구에 숫자 50이 없다.
4. 카드: 320px에서 «잠긴 아이템 배지»가 단어 중간에서 끊기지 않는다(실렌더 확인). 열린 카드의 긴 이름도 공백에서만 줄이 바뀌고 두 줄 안에서 말줄임된다.
5. 세로 568·667·844px, 너비 320~430px에서 겹침이 없고 터치 영역은 44px 이상이다. 새 컴포넌트·새 토큰이 없다.
6. 시험이 고정한다: 새 알림 종류 message·href·warning 분기, 막힘 판별 함수, 막힘 분기, BadgeGridCard 이름 클래스. 이미 있는 `BadgeGridCard.locked.test.tsx`·`cardFacePairs.test.tsx`를 깨지 않는다.
회차 분할 제안은 두 회차다.
- 1회(서버·알림): `lib/notifications`의 `types.ts`·`message.ts`·`href.ts`·`warning.ts`·`feed.ts`, `types/database.ts`의 NotificationType, i18n 문구, 지급 직후 한 곳에서 `inventory_slot_alert_step`을 부르는 함수와 호출 지점, account.ts 배치 조건, slot 라우트의 `code`와 해제 문구.
- 2회(화면): `inventory/page.tsx`, `NotificationsClient.tsx`의 TypeIcon, `CombineClient.tsx`, `PoiCarouselModal.tsx`, `SlotGrid.tsx` 확인, 막힘 판별 순수 모듈, `BadgeGridCard.tsx`.

### 판정 근거

조사로 확인한 사실 5가지가 판정의 근거다.
1. 가득 참 안내 카드는 이미 있다. jam-web/src/app/(main)/inventory/page.tsx의 `remainingSlots === 0` 블록(bg-surface + border-border 카드, `d.inventory.fullNoticeBody`, CTA «드랍하기» → /drops, PRD docs/service/prd/inventory)이다. 남은 칸 문구 `d.inventory.slotsDetail`과 ProgressBar도 이미 있다. 새로 만들 표면이 없고 문구와 강조만 손본다.
2. `inventory_full` 알림도 이미 있다. lib/notifications/batch/account.ts:111이 남은 칸 3 이하일 때 하루 한 번 만든다. warning.ts의 `INVENTORY_LOW_SLOTS_THRESHOLD = 3`이 경고면(--warning) 유지·강등을 판정한다. 문구 `msgInventoryFull`은 «꽉 찼어요 … 픽업이 안 될 수 있어요»인데 조건은 3칸 이하다. account.ts 머리 주석도 이 불일치를 인정한다. 새 `inventory_slots_low`를 그대로 더하면 3칸 이하 유저가 같은 사건에 알림 두 개를 받는다. 그래서 역할을 나눠야 한다.
3. 막힌 까닭 문구는 서버가 이미 준다. slot 라우트는 `d.lockedItem.slot`과 `inventoryFullForUnslot`을 내려 주고, SlotGrid는 `data.error`를 배너에 그대로 보인다. 믹스는 `d.lockedItem.combine`, 드랍은 `d.lockedItem.drop`을 준다. 빠진 것은 화면의 톤이다. 믹스는 409(잠김)가 결과 오버레이의 «실패»로 떨어지고, 드랍은 같은 까닭이 `toast(..., 'error')`로 나간다. 이용 정지(`CombineClient`의 `toast(..., 'info')`)와 받지 않은 결과(`pending_results_exist`) 선례는 info다.
4. `inventoryFullForUnslot`에 «50개»가 박혀 있다. 칸 수는 어드민 정책값이라 어긋날 수 있다.
5. BadgeGridCard 이름 줄은 `line-clamp-2 leading-tight`뿐이고 `break-keep`이 없다. 같은 저장소에 `break-keep wrap-break-word` 선례가 있다(JamBalance, CapsulePill, BadgeRevealOverlay). 새 규칙을 만들 필요가 없다.

단 BadgeGridCard 줄바꿈 수정은 공통 카드의 눈에 보이는 변화(이름 줄바꿈이 전 화면에 적용)라 승인 항목으로 올린다. 새 문구(알림 2종, 남은 칸 줄, 안내 카드 개정)도 사용자 노출 문구라 승인을 받는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상, 회차마다 해당 항목)

- 컬렉션 화면이 잠긴 개체를 기준과 장착 후보와 완성 판정에서 뺀다. 시험이 고정한다.
- 인벤토리가 가득 차 있으면 장착 풀기가 서버에서 거부되고, 교체는 허용된다. 동시 요청에서도 칸 수를 넘기지 않는다.
- 인벤토리 화면이 가득 참과 남은 칸을 알리고, 남은 칸 3칸·1칸 알림이 한 단계에 한 번만 간다.
- 잠김·가득 참으로 막힌 장착·믹스·드랍이 까닭이 보이는 안내를 낸다.
- 채원 사후 리뷰에 중대 문제가 없고, 마이그레이션이 옛 객체를 바꾸지 않으며 되돌림 SQL을 싣는다. `docs/service/prd/`에 반영되어 있다.
- 실렌더 확인(세로 568·667·844px, 너비 320~430px 겹침과 터치 영역)은 카리나가 머지 뒤 push 전에 로컬에서 한다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 사용자 확인 1~3번의 결정을 이 티켓 「사용자 결정」 절에 기록한다. SQL 실행은 승인과 롤백 실측 뒤에 한다.
