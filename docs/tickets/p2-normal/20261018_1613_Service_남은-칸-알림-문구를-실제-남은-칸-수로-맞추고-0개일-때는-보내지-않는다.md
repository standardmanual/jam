# [Service] 남은 칸 알림 문구를 실제 남은 칸 수로 맞추고, 남은 칸이 0개일 때는 보내지 않는다

## 핵심 요약

- 요구사항: 티켓 20261018_0056 게이트(민지)가 짚고 사용자가 수정을 승인했다(2026-10-18). 마이그레이션 237의 단계(`inventory_slot_alert_step`)는 남은 칸 2~3개를 단계 3, 0~1개를 단계 1로 정한다. 그런데 알림 payload `remaining_slots`에 단계 값(3 또는 1)을 싣고 문구가 그 값을 말해, 남은 칸이 2개여도 «3개로», 0개여도 «1개로 줄었어요»로 나간다. 또 0개일 때는 기존 `inventory_full` 배치 알림이 따로 생겨 한 사건에 알림이 둘이 된다.
- 수정(마이그레이션 없음): (1) `lib/inventory/slotAlert.ts`가 RPC 응답의 실제 남은 칸(`free`)을 읽어, `free === 0`이면 `inventory_slots_low`를 만들지 않고(0개는 `inventory_full`이 맡는다. 단계는 DB가 이미 1로 갱신했으므로 0개에서 풀렸다가 다시 줄어들 때까지 다시 보내지 않는다), 그 밖에는 payload `remaining_slots`에 실제 남은 칸(1~3)을 싣는다. (2) `lib/notifications/message.ts`의 `inventory_slots_low`는 `remaining_slots`가 1이면 «다 차면 …» 문구, 2 이상이면 «다 차기 전에 …» 문구를 쓰고 `{remaining}`에 그 숫자를 넣는다(잘못된 값이 와도 깨지지 않게 1~3 밖이면 3개 문구로 처리). (3) `docs/service/prd/notification/PRD.md`의 «#42 생성 조건을 0개로 좁혔다» 서술을 사실에 맞게 고친다(조건은 원래 0개였고 이 티켓에서 문구만 고쳤다)와 `inventory_slots_low`의 payload 값 설명을 실제 남은 칸으로 고친다.
- 관련 파일: `jam-web/src/lib/inventory/slotAlert.ts`(`parseSlotAlertStep`, `notifyInventorySlotsLow`), `jam-web/src/lib/notifications/message.ts`(732줄 근처 `inventory_slots_low` case), `jam-web/src/lib/i18n/ko.ts`(1660·1661줄 `msgInventorySlotsLowThree`·`msgInventorySlotsLowOne`), 시험 `jam-web/src/lib/inventory/__tests__/slotAlert.test.ts`와 `jam-web/src/lib/notifications/__tests__/message-href.test.ts`, 문서 `docs/service/prd/notification/PRD.md`, `docs/service/prd/notification/DATA_MODEL.md`.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 남은 칸 3·2·1개에서 알림 문구가 각각 «3개로»·«2개로»·«1개로 줄었어요»로 실제 숫자를 말하고 1개일 때만 «다 차면 …» 문구다. 시험이 고정한다.
- 남은 칸이 0개가 되는 지급에서는 `inventory_slots_low`를 만들지 않는다. 단계 전이(0→3→1→0 등)마다 알림이 나가는지 시험이 고정한다(5개 → 0개로 한 번에 줄어도 `inventory_slots_low`는 나가지 않는다).
- 문서가 사실과 맞다. 새 SQL은 없다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

**1회 완료(2026-10-18, 아현, 브랜치 `claude/jamwork-20261018_1613-slot-alert-remaining`, 게이트 PASS, staging 로컬 머지, `route: light`).** SQL 없음.
- `lib/inventory/slotAlert.ts`: `parseSlotAlertStep`이 `{stage, free}`를 돌려주고(free가 0~3 정수가 아니면 null), `free === 0`이면 `inventory_slots_low`를 만들지 않는다(0개는 `inventory_full`이 맡는다). 그 밖에는 payload `remaining_slots`에 실제 남은 칸(1~3)을 싣는다.
- `lib/notifications/message.ts`: `remaining_slots`가 1이면 «다 차면 …», 2 이상이면 «다 차기 전에 …» 문구를 쓰고 `{remaining}`에 실제 숫자를 넣는다. 1~3 밖의 값은 3개 문구로 처리한다. `types.ts`는 payload 타입을 `1 | 2 | 3`으로, `ko.ts`는 주석만 고쳤다. 새 문구는 만들지 않았다.
- PRD #46·#42 서술과 DATA_MODEL payload 설명을 사실에 맞게 고쳤다.
