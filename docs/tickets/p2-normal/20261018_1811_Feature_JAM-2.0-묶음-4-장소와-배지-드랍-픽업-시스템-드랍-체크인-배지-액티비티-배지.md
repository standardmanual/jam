# [Feature] JAM 2.0 묶음 4: 장소와 배지 (드랍·픽업, 시스템 드랍, 체크인 배지, 액티비티 배지)

## 핵심 요약

- 요구사항: 운영 로직 9장(장소, 드랍과 픽업), 10장(액티비티 배지), 11장(체크인 배지)을 만든다. 지도에서 줍고 드랍하고(잠긴 채 드랍 포함), 시스템 드랍이 스펙대로 놓이고, 체크인 배지를 처음 받을 때 포인트가 나가고, 새 조건의 액티비티 배지가 켜진다. 4.1절의 문제 셋(시스템 드랍 전체 무작위, 꺼진 장소 픽업, 배지 수정 폼의 장소 연결 20261006_1028)을 함께 고친다. 묶음 3(캡슐과 인벤토리)이 끝난 상태에서 시작한다.
- 구현 계획: 하위 티켓 6개를 순서대로 진행한다(아래 표). 서버(4-1~4-5)가 화면(4-6)보다 먼저 간다. 하위 티켓마다 시작 전에 주요 결정을 질문창으로 묻고, 화면이 있는 것은 채원 사전 판정을 받는다.
- 관련 파일: `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 9·10·11장, `docs/plan/jam2/service-redesign/현재 서비스 비교.md`, `docs/plan/jam2/service-redesign/액티비티 배지 재활용 후보.md`, `docs/plan/jam2/tribe-rethink/manuscript/06 액티비티 배지.md`.

## 배경 / 문제 정의

묶음 3까지 잼으로 캡슐과 잠긴 아이템 배지를 채워 열 수 있게 됐다. 이제 아이템 배지가 유저 사이를 오가는 길(드랍과 픽업)이 잠긴 개체와 이용 정지를 이해해야 하고, 체크인 배지와 액티비티 배지가 새 규칙을 따라야 한다.
지금 코드의 상태(2026-10-18 조사): 드랍·픽업 라우트에 이용 정지 검사가 없고, 픽업이 꺼진 장소를 보지 않으며, 드랍 목록 API는 잠긴 개체를 가리지 않고 이름·그림·일련번호를 내려준다. 시스템 드랍의 «전체 무작위»는 카테고리·등급·컬렉션 설정을 모두 무시하고 잠김으로 만든 배지를 잠긴 채 놓는 처리가 없다. 체크인 배지는 처음 받을 때 포인트를 주지 않고 공개 기간으로 발급을 막지 않는다. 액티비티 배지 엔진은 시간대 구간이 스펙과 다르고(새벽 4~8 등, 로컬 시각 판정) 숨김 배지·가지 분류 칸·새 JAM 조건·날 단위 횟수 세기가 없다.

## 사용자 결정 (2026-10-18, 질문창, 추천안)

1. **하위 티켓은 서버 5개 + 화면 1개로 쓰고 서버를 먼저 진행한다.** 서버가 선 뒤 화면(드랍 지도·장소 카드·배지함·트리·상세)을 한 번에 만들어 다시 고칠 일을 줄인다. 묶음 3과 같은 방식이다.

### 순서의 근거

- 잠긴 채 드랍과 가린 모습(4-1)은 묶음 3이 만든 잠긴 개체 저장과 채우기·열기가 선 뒤에야 의미가 있다. 238이 만든 `create_user_drop`의 잠긴 개체 거부를 4-1이 «잠긴 채 드랍»으로 바꾼다.
- 액티비티 배지의 JAM 조건(드랍·픽업·잠긴 개체 픽업·캡슐·믹스 횟수)은 4-1과 묶음 3의 기록(`poi_drops`, `capsule_opens`, `inventory_item_events`, `user_combine_*_logs`)을 읽는다. 챕터 점수 연결(드랍·픽업·체크인·믹스 점수)은 묶음 5에서 한다. 이 묶음은 챕터 점수를 올리지 않고 기록만 남긴다.
- 이용 정지 검사(`assertNotSuspended`, 2-6)는 드랍·픽업(4-1)에 연결하고, 체크인 판정(4-3)은 정지 중 판정하지 않는다.
- 값(시스템 드랍의 양·주기·등급 비율, 체크인 포인트)은 설정 테이블 행으로 두고 코드는 읽기만 한다. 설정 화면은 묶음 7이다.
- 티켓 20261006_1028(배지 수정 폼의 장소 연결)은 4-2에 흡수한다.

## 진행 상황 (2026-10-18)

- 4-1(`1812`), 4-2(`1813`), 4-3(`1814`)을 구현·머지하고 CLOSED했다(마이그레이션 238~241 적용). 남은 하위 티켓은 4-4(`1815`), 4-5(`1816`), 4-6(`1817`)이다.

## 완료 조건

- 하위 티켓 6개가 모두 CLOSED다.
- 잠긴 개체를 잠긴 채로 드랍하고 픽업할 수 있고(채운 양은 사라지고 사라질 양을 미리 알린다), 지도와 목록에는 무엇인지 보이지 않는다. 이용 정지 중과 꺼진 장소에서는 드랍·픽업이 막힌다.
- 시스템 드랍이 설정(카테고리·등급·컬렉션)을 따르고, 잠김으로 만든 배지만 잠긴 채 놓이며, 공개 기간이 끝난 배지는 놓이지 않는다.
- 체크인 배지를 처음 받을 때 등급 포인트가 한 번 나가고 공개 기간 밖에는 새로 주지 않는다.
- 액티비티 배지 조건이 스펙의 시간대와 날 단위 세기를 따르고, 숨김 배지와 가지 분류가 저장된다.
- 새 마이그레이션이 옛 테이블, 옛 함수, 옛 칸을 바꾸거나 지우지 않는다(예외는 각 티켓이 사용자 승인을 받아 기록한다).
- 운영 로직 9·10·11장 가운데 코드로 옮긴 부분이 `docs/service/prd/`, `docs/service/badge-engine/`, `docs/service/content/`에 반영되어 있다.
