# [Feature] JAM2 시스템 드랍과 장소 어드민: 전체 무작위 고침, 잠긴 채 놓기, 지점·POI 표기를 장소로, 장소 연결 폼

## 핵심 요약

- 요구사항: 운영 로직 9.2·9.4·9.7절을 만든다. (1) 시스템 드랍의 «전체 무작위»가 켜져 있으면 카테고리·등급·컬렉션 설정이 모두 무시되는 문제(비교표 4.1절)를 고친다(설정을 따르게). (2) 잠김으로 만든 배지(`badges.always_locked`)만 잠긴 채 놓이게 하고 공개 기간이 끝난 배지·드랍 제외인 배지는 놓지 않는다(이미 거름, 확인). (3) 행사 때 운영자가 장소와 컬렉션(또는 배지)을 지정해서 놓는 경로를 유지한다. (4) 유저 화면과 어드민의 «지점»·«POI» 표기를 «장소»로 바꾼다. (5) 배지 수정 폼에서 장소 연결을 불러오기 전에 저장하면 연결이 지워지는 문제(티켓 20261006_1028)를 고친다. (6) 장소 폼의 배지 검색을 체크인 배지로 제한한다(연결은 체크인 배지로만).
- 구현 계획: 시작 때 사용자 결정 3건을 질문하고 파일 단위 계획을 옮겨 쓴다. SQL이 필요하면(`mint_and_place_ambient_drop`의 잠김 처리) 사용자 승인과 롤백 실측 뒤 카리나가 실행한다. 규모에 따라 1~2회.
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 설정 `jam-web/src/lib/ambient-drop/config.ts`(`ambient_drop_config`, 마이그레이션 104·137), 엔진 `lib/ambient-drop/index.ts`(`runAmbientDropBatch` 57줄, «전체 무작위» 판정 63~65줄), 날짜 예약 `lib/ambient-drop/scheduleRun.ts`(177줄 근처)와 `scheduleTargets.ts`(`ambient_drop_schedules`, 209), 크론 `app/api/cron/ambient-drop/route.ts`, DB 함수 `mint_and_place_ambient_drop`(108, `locked`를 설정하지 않음), 어드민 `app/admin/ambient-drop/`(`AmbientDropForm.tsx` 216줄의 «3축 전부 무작위» 문구 등)과 메뉴 이름 `components/admin/adminNavItems.ts` 80줄, 장소 어드민 `app/admin/poi/`(`PoiForm.tsx` 236줄 `BadgeSearchSelect`에 `typeFilter` 없음, `page.tsx` 77줄 «POI 관리»), API `app/api/admin/poi/*`, 배지 폼 `app/admin/badges/BadgeForm.tsx`(245~263줄 `poiLinksLoadedRef` 가드, 505~525줄 빈 목록 PUT), 문구 `lib/i18n/ko.ts`(«지점» 27곳), `components/admin/PoiSearchSelect.tsx`·`PoiMultiSearchSelect.tsx`, 약관 `app/(legal)/location-terms`·`privacy`(«관심지점(POI)»), 티켓 `20261006_1028`.

## 배경 / 문제 정의

시스템 드랍의 «전체 무작위»는 버그라기보다 의미가 스펙과 다르게 설계되어 있다(`AmbientDropForm`의 문구가 «3축 전부 무작위»이고 지금 DB가 이 상태다). 스펙(9.4절)은 공개 중인 컬렉션 전체에서 고르되 양·주기·장소당 상한·등급 비율은 어드민 설정을 따르게 한다. 지금은 설정이 무시된다.
장소 표기는 유저 화면과 어드민이 «지점»·«POI»·«장소»를 섞어 쓴다. 약관과 개인정보 처리방침은 «관심지점(POI)»을 쓰는데 이는 법적 문서라 이 티켓에서 바꾸지 않고 묶음 6(18장)에 맡긴다.
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **«전체 무작위»의 새 의미**: 설정 칸은 그대로 두고 켜 있으면 «컬렉션만 무시하고 등급 비율·카테고리는 따른다», 또는 «전체 무작위 설정을 없애고 각 축의 설정을 늘 따른다»(추천: 스펙 9.4절에 «전체 무작위»가 없음). 어드민의 옛 설정 행이 어떻게 해석되는지도 정한다.
2. **잠긴 채 놓기의 필요한 양**: 잠김으로 만든 배지는 배지의 `unlock_required`(없으면 등급 최소값)를 놓을 때 고정한다(추천, 3-1·3-5와 같은 규칙).
3. **«지점»·«POI» 표기 범위**: 유저 화면과 어드민 문구, 코드 안의 설명 주석은 제외하고 화면에 보이는 문구만 «장소»로 바꾼다(추천). 약관·개인정보 처리방침의 문구는 법적 문서라 묶음 6으로 넘긴다.

## 사용자 결정과 진행 (2026-10-18)

1. «전체 무작위»: **엔진이 각 축의 설정만 따르게 한다**(권장대로). 엔진(`lib/ambient-drop/index.ts`·`scheduleRun.ts`)이 `all_random`을 더는 보지 않고 카테고리·등급·컬렉션 각 축의 모드(무작위/지정)만 따른다. 어드민 폼의 «전체 무작위» 스위치는 없애고 세 축을 따로 고르게 한다. 옛 DB 값(`all_random = true`)은 그대로 두어 옛 프로덕션 코드는 영향이 없다. 지금 DB 행(등급 Common 100%, 컬렉션 3개 지정, 카테고리 무작위, `auto_enabled = false`)이 그대로 켜지면 그 입력대로 놓인다. 자동 배포가 꺼져 있어 당장 놓이는 것은 없다.
2. 잠긴 채 놓기의 필요한 양: **배지의 값, 없으면 등급 최소값**(권장대로, 3-1·3-5와 같은 규칙, 놓을 때 고정).
3. «지점»·«POI» 표기 범위: **약관과 방침까지 한 번에**(권장과 다름). 유저 화면·어드민 문구뿐 아니라 `app/(legal)/location-terms`·`privacy`의 «관심지점(POI)»도 «장소»로 고친다. 법적 문서이므로 아현은 해당 페이지에 시행일·개정 이력 표시가 있는지 확인해 보고하고(만들어 내지 않는다), 약관 개정 절차(공지·시행일)는 카리나가 사용자에게 확인한다.
- DB 적용 완료(마이그레이션 240): 새 함수 `mint_and_place_ambient_drop_locked(p_poi_id, p_badge_id, p_lock_reason, p_unlock_required)`가 잠긴 개체(`locked`, 까닭, 필요한 양 고정, 채운 양 0, 소유자 없음)를 만들어 시스템 드랍으로 놓고 `Minted` 이력을 남긴다. 옛 `mint_and_place_ambient_drop`(108)은 그대로다. 롤백 실측 통과(성공 시 개체·드랍·이력, 잘못된 까닭·필요한 양·NULL 거절 시 개체를 만들지 않음, 옛 함수는 열린 개체를 그대로 만듦, 권한). 적용 뒤 확인: SECURITY DEFINER, `authenticated` 실행 권한 없음, 옛 함수 1개 그대로.

## 상세 요구사항

### 서비스/코드베이스 관점

- **전체 무작위**: 결정 1에 따라 엔진(`index.ts`·`scheduleRun.ts`)이 설정을 따르게 한다. 컬렉션·카테고리·등급 비율이 시스템 드랍에 반영되는지 시험으로 고정한다.
- **잠긴 채 놓기**: `badges.always_locked`인 배지는 놓을 때 잠긴 개체로 만든다(`lock_reason = 'badge_locked'`, 필요한 양 고정). `mint_and_place_ambient_drop`이 `locked`를 설정하지 않으므로 DB 함수를 덧붙이거나(새 함수 또는 `grant_inventory_item_locked` 재사용) 앱이 놓은 뒤 잠금 칸을 채운다. 동기화·캡슐의 잠김 배정(`lib/drop-engine/lockAssignment.ts`)과 같은 필요한 양 규칙을 쓴다.
- **놓지 않는 것**: 공개 기간이 끝난 배지와 드랍 제외(`drop_excluded`)인 것, 꺼진 컬렉션·꺼진 장소는 이미 거른다(`index.ts`, `scheduleTargets.ts`). 시험으로 고정한다.
- **행사 지정**: 운영자가 장소와 컬렉션(또는 배지)을 지정해서 놓는 날짜 예약 경로가 새 규칙을 따른다.
- **표기**: 화면에 보이는 «지점»·«POI»를 «장소»로 바꾼다(`ko.ts`, 어드민 화면, `PoiSearchSelect`, `adminNavItems`, `admin/poi/page.tsx`). 데이터 구조·코드 식별자는 그대로다.
- **장소 연결 폼(20261006_1028)**: `BadgeForm`이 장소 연결을 불러오기 전이나 불러오기에 실패했을 때는 `poi-links` PUT을 보내지 않는다(개발 모드 이중 실행에서도). 시험으로 고정한다.
- **장소 폼의 배지 검색**: `PoiForm`의 `BadgeSearchSelect`에 체크인 배지만 고르는 `typeFilter`를 걸고, `api/admin/poi` 저장 쪽도 연결 배지 종류가 체크인이 아니면 400으로 거절한다(검증은 서버에서).
- 어드민 UI는 shadcn/ui 표준을 따른다(MODULAR 적용 제외). 새 칸·새 함수는 덧붙이기만 한다. 생성 타입을 같은 커밋에 맞춘다.

### UI/UX 관점 (해당 시)

- 어드민 폼 문구와 안내는 UX 라이팅 가이드를 따른다. 실렌더는 카리나가 머지 뒤 push 전에 로컬에서 한다(`ADMIN_EMAILS` 셸 환경변수 방식).

## 구현 계획 (회차)

2회로 나눈다. DB는 마이그레이션 240이 적용되어 있다(위). 파일 경로는 jam-web/src 기준이고 줄 위치는 아현이 다시 확인한다.

### 1회: 시스템 드랍 엔진

1. `lib/ambient-drop/index.ts`(`runAmbientDropBatch` 63~65줄)와 `scheduleRun.ts`(177줄 근처): `all_random`을 더는 보지 않고 세 축의 모드만 따른다. `config.ts`의 `all_random` 읽기는 두되 엔진이 쓰지 않는다. 지금 DB 행(등급 Common 100%, 컬렉션 3개 지정, 카테고리 무작위)이 그대로 반영되는 시험.
2. 잠긴 채 놓기: 놓기 직전에 후보 배지의 `always_locked`를 읽어, 참이면 `mint_and_place_ambient_drop_locked`(까닭 `badge_locked`, 필요한 양은 배지의 `unlock_required`, 없으면 `lib/jam/policy.ts`의 등급 최소값)로, 아니면 옛 `mint_and_place_ambient_drop`으로 놓는다. 동기화·캡슐의 잠김 배정(`lib/drop-engine/lockAssignment.ts`)과 같은 필요한 양 규칙. 시험이 두 갈래와 필요한 양을 고정한다.
3. 공개 기간이 끝난 배지·드랍 제외·꺼진 컬렉션·꺼진 장소를 거르는 현재 동작(`index.ts`, `scheduleTargets.ts`)을 시험으로 고정한다. 행사 지정(날짜 예약, `scheduleRun.ts`)이 새 규칙을 따르는지 시험.
4. 어드민 폼 `app/admin/ambient-drop/AmbientDropForm.tsx`(216줄의 «3축 전부 무작위» 문구)·`ScheduleForm.tsx`에서 «전체 무작위» 스위치를 없애고 세 축을 따로 고르게 한다(shadcn/ui 표준). 서버 저장 라우트·검증이 `all_random`을 새로 쓰지 않게 한다.
5. 문서: `docs/service/prd/02_DATA_MODEL.md`(240), 시스템 드랍 문서(`docs/service/badge-engine/` 또는 `docs/service/prd/`에서 찾는다).

### 2회: 장소 어드민과 표기

1. «지점»·«POI» → «장소»: `lib/i18n/ko.ts`(«지점» 27곳), `app/admin/poi/page.tsx`(77줄 «POI 관리»)와 `PoiTable` 등, `components/admin/adminNavItems.ts`(메뉴), `components/admin/PoiSearchSelect.tsx`·`PoiMultiSearchSelect.tsx`, `app/admin/badges/BadgeForm.tsx`, `app/admin/ambient-drop/*`, 약관·방침 `app/(legal)/location-terms`·`privacy`(«관심지점(POI)»). 코드 식별자·주석은 그대로. 법적 페이지의 시행일·개정 이력 표시 유무를 보고한다.
2. 배지 수정 폼(20261006_1028): `app/admin/badges/BadgeForm.tsx` 245~263줄 `poiLinksLoadedRef` 가드와 505~525줄: 장소 연결을 불러오기 전이나 불러오기에 실패했을 때는 `poi-links` PUT을 보내지 않는다(개발 모드 이중 실행 포함). 시험.
3. 장소 폼 `app/admin/poi/PoiForm.tsx` 236줄 `BadgeSearchSelect`에 체크인 배지만 고르는 `typeFilter`, `app/api/admin/poi` 저장 쪽도 연결 배지 종류가 체크인이 아니면 400. 시험.
4. 문서: `docs/service/content/POI.md`, `docs/service/prd/`의 장소 문서. 어드민 화면 실렌더는 카리나가 머지 뒤 로컬에서 한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 시스템 드랍이 카테고리·등급·컬렉션 설정을 따른다. 잠김으로 만든 배지만 잠긴 채 놓이고 필요한 양이 고정된다. 공개 기간이 끝난 배지·드랍 제외는 놓이지 않는다.
- 유저 화면과 어드민에 «지점»·«POI» 표기가 남지 않는다(법적 문서 제외).
- 배지 수정 폼이 장소 연결을 불러오기 전에는 빈 목록을 저장하지 않는다. 장소 폼의 연결 배지는 체크인 배지로만 고를 수 있고 서버도 거절한다.
- 마이그레이션이 옛 객체를 바꾸지 않으며 되돌림 SQL을 싣는다(SQL이 있을 때). `docs/service/prd/`·엔진 문서·`docs/service/content/POI.md`에 반영되어 있다.
- 어드민 화면 실렌더 확인은 카리나가 머지 뒤 push 전에 한다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 시작 때 결정 1~3번을 이 티켓 「사용자 결정」 절에 기록한다. SQL 실행이 있으면 승인과 롤백 실측 뒤에 한다. 티켓 20261006_1028을 CLOSED로 닫는다.

### 구현 내용 요약

### 잔여 이슈
- **약관·방침의 개정 절차(사용자 확인 필요).** `location-terms/page.tsx`는 `EFFECTIVE_DATE`가 «2026년 10월 1일»(24행)이고 부칙 제1조(시행일, 487행)에 쓰이며 개정 이력 표시는 없다(개정 절차 조항은 112~120행). `privacy/page.tsx`는 `EFFECTIVE_DATE`가 «2026. 10. 1.»(30행)이고 `PREVIOUS_EFFECTIVE_DATE`가 «2026. 9. 1.»(33행)이며 적용일(599행), v1.1 이력(608행), v1.0 최초 제정(614행)에 쓰인다. 문구만 «장소»로 바꾸고 시행일과 이력은 건드리지 않았으므로, 개정 공지·시행일과 방침 v1.2 이력 추가 여부는 배포 전에 정해야 한다.
- `PUT /api/admin/badges/[id]/poi-links`는 연결 배지 종류를 서버에서 검증하지 않는다(어드민 한정, 이 티켓 범위 밖). 체크인 배지 폼에서만 호출한다.
- 장소 연결 불러오기에 실패하면 새로고침 말고는 재시도 경로가 없고 배지 본문 저장도 막힌다(작성자가 의도한 선택).
- 옛 DB 값 `all_random = true`는 묶음 6의 축소 때 정리한다. 비교표의 «전체 무작위가 켜져 있으면 무시된다» 서술은 고치기 전 상태 기록으로 두었다.
- `lib/ambient-drop/index.ts` 276줄 주석이 옮겨진 함수의 옛 위치(`placement.ts`)를 가리킨다(동작 영향 없음).
