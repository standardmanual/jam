# [BadgeEngine] JAM2 체크인 배지 서버: 처음 받을 때 포인트, 공개 기간, 방문 기록, 옛 장소 연결 발급 경로 삭제

## 핵심 요약

- 요구사항: 운영 로직 11장에 맞춰 체크인 배지 서버를 고친다. (1) 처음 받을 때 그 배지의 등급에 맞는 포인트를 한 번 준다(다시 지나가면 방문 기록만). (2) 공개 기간을 새로 받을 수 있는 기간으로 쓴다(기간 밖이면 새로 주지 않고, 받은 배지에는 기한이 없다). (3) 같은 활동을 다시 동기화해도 방문 기록이 두 번 세지지 않고, 같은 장소에 체크인한 날의 수를 방문 기록으로 센다. (4) 장소에 액티비티 배지를 연결했을 때 옛 경로로 한 번 발급되는 길을 지운다. (5) 이용 정지 중에는 체크인을 판정하지 않는다. 인정되지 않은 활동과 교통수단 구간으로는 체크인되지 않는다(이미 인정 판정 뒤에 돈다, 확인). 챕터 점수 연결은 묶음 5다.
- 구현 계획: 시작 때 사용자 결정 3건을 질문하고 파일 단위 계획을 옮겨 쓴다. SQL이 필요하면(처음 받을 때 포인트 중복 방지 기록, 공개 기간 판정) 사용자 승인과 롤백 실측 뒤 카리나가 실행한다. 1회로 돌린다.
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 판정 `jam-web/src/lib/strava/sync.ts`(`processFetchedActivities` 945~1095줄, 옛 경로 1066~1094줄: `type !== 'checkin'`인 연결 배지에 `user_activity_badges`를 `triggered_by='poi_match'`로 한 번 발급, 첫 획득 여부는 `visitCount === 1`), `lib/poi/matcher.ts`(`matchPoisForActivity` 143줄 근처, `is_active`와 반경으로 거름, 최신 활동 10건만 봄), 방문 기록 `user_checkin_badge_earns`(마이그레이션 053·103, UNIQUE(user, badge, poi, strava_id)), 포인트 `lib/points/index.ts`(`awardPoints`), 이용 정지 `lib/suspension/suspension.ts`, 지도 표시 `app/api/checkin-badges/route.ts`(120줄, 공개 기간을 지도 표시에만 씀), 화면 `app/(main)/badges/[id]/PoiEarnHistory.tsx`·`PoiMapButton.tsx`.

## 배경 / 문제 정의

지금 체크인 배지는 포인트 칸이 있지만 주는 코드가 없고(`sync.ts`에 `awardPoints`가 없음), 공개 기간은 지도 표시에만 쓰며 발급은 기간을 보지 않는다. 장소에 액티비티 배지를 연결하면 옛 경로로 한 번 발급되는 길이 남아 있다(스펙은 장소 연결을 체크인 배지로만 하게 하고 이 길을 지운다). 체크인 판정이 최신 활동 10건만 보는 점은 시작 때 의도인지 확인한다.
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **처음 받을 때 포인트의 중복 방지**: 방문 기록 `user_checkin_badge_earns`의 «첫 방문» 판정(`visitCount === 1`)만으로 지급하고 포인트 원장 `point_transactions`가 같은 배지에 한 번만 있게 DB 제약이나 지급 함수로 지킨다(추천). 대안은 앱 코드의 첫 방문 판정만 믿는 것이다(동시 동기화에서 두 번 줄 수 있다).
2. **옛 장소 연결 발급 경로의 삭제**: 코드 경로(`sync.ts` 1066~1094줄)를 지우고 이미 이 경로로 발급된 `user_activity_badges`(`triggered_by='poi_match'`) 행은 그대로 둔다(추천). 대안은 옛 행도 정리하는 것이다(공용 DB 데이터 변경이라 신중해야 한다).
3. **공개 기간 밖 체크인**: 기간 밖에서는 새로 받지 않지만 방문 기록은 남긴다(추천, 이미 받은 배지에는 기한이 없다). 대안은 방문 기록도 남기지 않는 것이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **처음 받을 때 포인트**: 처음 받는 체크인 배지에 `badge.point_reward`(등급별 Common 10, Rare 20, Epic 50, Mystic 100, 어드민이 배지마다 정함)를 `awardPoints`로 한 번 준다. 다시 지나가면 방문 기록만 남기고 포인트는 주지 않는다. 같은 활동을 다시 동기화해도 두 번 주지 않는다.
- **공개 기간**: 체크인 발급이 배지의 `valid_from`·`valid_until`을 본다. 기간 밖이면 새로 주지 않는다. 이미 받은 배지는 그대로다.
- **방문 기록**: 같은 장소를 지난 활동마다 한 줄(이미 있는 UNIQUE가 같은 활동의 중복을 막는다). 같은 장소에 체크인한 날의 수는 이 기록으로 센다(새 위치 기록을 만들지 않음).
- **옛 경로 삭제**: 장소에 연결된 `type !== 'checkin'` 배지를 `poi_match`로 발급하는 코드를 지운다. 장소 연결이 체크인 배지로만 되는 것은 4-2가 폼과 API로 막는다.
- **이용 정지·인정 판정**: 정지 중에는 판정하지 않는다. 인정되지 않은 활동과 교통수단 구간은 이미 걸러진 뒤에 도는지 확인한다.
- 새 칸과 새 함수는 덧붙이기만 한다. 생성 타입을 같은 커밋에 맞춘다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 체크인 배지를 처음 받을 때 등급 포인트가 한 번 나가고, 같은 활동 재동기화와 동시 동기화에서도 두 번 나가지 않는다.
- 공개 기간 밖에서는 체크인 배지가 새로 발급되지 않는다. 방문 기록이 중복 없이 남는다.
- 장소에 연결한 액티비티 배지가 옛 경로로 발급되지 않는다. 이용 정지 중에는 판정하지 않는다.
- 마이그레이션이 옛 객체를 바꾸지 않으며 되돌림 SQL을 싣는다(SQL이 있을 때). `docs/service/prd/`·엔진 문서에 반영되어 있다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 시작 때 결정 1~3번을 이 티켓 「사용자 결정」 절에 기록한다. SQL 실행이 있으면 승인과 롤백 실측 뒤에 한다.
