# [UI] JAM2 장소·드랍·픽업·배지 화면: 지도 카드, 잠김·숨김 표시, 배지함·트리·상세

## 핵심 요약

- 요구사항: 4-1~4-5의 서버를 쓰는 유저 화면을 만든다. (1) 드랍 지도와 장소 카드: 장소별 드랍 개수, 반경 안 드랍 목록(잠긴 개체는 «잠김»과 등급만), 픽업(가득 참 안내, 이용 정지·꺼진 장소·장소 차단 안내), 드랍(잠긴 개체를 드랍하기 전에 «채운 잼 N은 사라져요» 안내). (2) 배지함·배지 트리·배지 상세: 새 조건 키와 가지 분류, 숨김 배지(받기 전에는 안 보이고 받으면 나타남), 체크인 배지 방문 기록 화면, «다음 목표»의 진행. 문구는 운영 로직 7.3·9.3·10.4절의 말투를 따른다. «지점»·«POI» 표기는 «장소»로 통일한다(4-2).
- 구현 계획: 시작 때 채원 사전 판정을 받는다. 판정이 제안한 모양을 사용자가 승인한다. 파일이 많으면 2회로 나눈다(1회 지도·장소 카드·드랍·픽업, 2회 배지함·트리·상세).
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 확인한다): 지도 `jam-web/src/app/(main)/drops/DropsClient.tsx`(324줄), `components/map/MapView.tsx`(588줄), `drops/BadgeDetailSheet.tsx`(203줄), 장소 카드와 드랍·픽업 목록 `components/PoiCarouselModal.tsx`(1055줄), 배지함 `app/(main)/badges/page.tsx`(277줄)·`BadgesClient.tsx`(347줄), 트리 `badges/tree/page.tsx`(350줄)·`BadgeTreeClient.tsx`(399줄)·`lib/badgeTree.ts`(602줄)·`components/badges/BadgeFamilyRow.tsx`(249줄), 상세 `badges/[id]/page.tsx`(673줄)·`BadgeConditionCard.tsx`(49줄)·`PoiEarnHistory.tsx`·`PoiMapButton.tsx`, 3-4에서 만든 가림 방식 `components/ui/BadgeGridCard.tsx`의 `locked`와 MODULAR `LockedTile`, 이용 정지 막힘 안내 선례 `lib/suspension/suspended-block.ts`와 info 토스트, 문구 `lib/i18n/ko.ts`, 스펙 운영 로직 7.3·9.3·10.4절, 디자인 시스템 `docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`.

## 배경 / 문제 정의

서버(4-1~4-5)가 모두 선 뒤에 화면을 한 번에 만든다. 운영 로직의 표시 규칙: 지도 위에 놓인 잠긴 개체도 «잠김»으로만 보이고 이름·그림은 보이지 않는다(7.3절). 채우다 만 잠긴 개체를 드랍하면 채운 양이 사라지므로 드랍하기 전에 알린다. 액티비티 배지는 서사 설명과 따로 명확한 값으로 적힌 획득 조건을 보여 주고, 숨김 배지는 받기 전까지 트리에도 보이지 않는다(10.3절).
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

시작 때 채원 사전 판정의 승인 항목(새 컴포넌트, 화면 위치, 문구)을 질문한다. 미리 정해 둘 것은 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 서버가 정한 값(잠김, 사라질 양, 막힌 까닭, 숨김, 진행)을 그대로 그린다. 화면이 규칙을 다시 계산하지 않는다.
- 잠긴 개체의 이름·그림은 클라이언트로 내리는 props에 넣지 않는다(서버에서 비운다, 3-4 방식).
- 이용 정지·꺼진 장소·가득 참·장소 차단으로 막힌 드랍·픽업은 일반 실패가 아니라 까닭이 보이는 안내(info 톤)를 낸다(2-6·3-6 선례).
- 클라이언트·서버 경계: 클라이언트가 가져오는 모듈은 서버 전용 모듈(`@/lib/supabase/server`, `next/headers`)을 정적·동적 어느 쪽으로도 가져오지 않는다. 순수 계약 파일과 서버 파일을 나눈다.

### UI/UX 관점

- 채원 판정을 따른다. 오버레이를 만들거나 고치면 `docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`의 z-index 레이어 체계를 먼저 읽고 기하값은 `offsetHeight`로 실측한다.
- 사용자 노출 문구는 UX 라이팅 가이드와 `fluent-korean` 지침을 따른다.

## 구현 계획 (회차)

채원 판정 뒤 파일 단위 계획을 이 절에 옮겨 쓴다. 30개를 넘으면 2회로 나눈다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 장소 카드의 드랍 목록에서 잠긴 개체가 «잠김»과 등급만 보이고 이름·그림·일련번호가 DOM 어디에도 없다. 잠긴 개체를 드랍하기 전에 사라질 양이 보인다.
- 가득 참·이용 정지·꺼진 장소·장소 차단으로 막힌 픽업·드랍이 까닭이 보이는 안내를 낸다.
- 배지함·트리·상세가 가지 분류와 숨김 배지를 서버 값대로 보인다(숨김 배지는 받기 전에 어디에도 안 보임). 체크인 배지 상세가 방문 기록을 보인다.
- 화면의 «지점»·«POI» 표기가 «장소»로 통일되어 있다.
- 채원 사후 리뷰에 중대 문제가 없다. 새 토큰이나 MODULAR 변경이 있으면 Story와 문서가 함께 반영되어 있다.
- 실렌더 확인(세로 568·667·844px, 너비 320~430px 겹침과 터치 영역)은 카리나가 머지 뒤 push 전에 로컬에서 한다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 채원 사전 판정의 승인 항목을 사용자에게 보고하고 결과를 이 티켓 「사용자 결정」 절에 기록한다.
