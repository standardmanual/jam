# [UI] JAM2 장소·드랍·픽업·배지 화면: 지도 카드, 잠김·숨김 표시, 배지함·트리·상세

## 핵심 요약

- 요구사항: 4-1~4-5의 서버를 쓰는 유저 화면을 만든다. (1) 드랍 지도와 장소 카드: 장소별 드랍 개수, 반경 안 드랍 목록(잠긴 개체는 «잠김»과 등급만), 픽업(가득 참 안내, 이용 정지·꺼진 장소·장소 차단 안내), 드랍(잠긴 개체를 드랍하기 전에 «채운 잼 N은 사라져요» 안내). (2) 배지함·배지 트리·배지 상세: 새 조건 키와 가지 분류, 숨김 배지(받기 전에는 안 보이고 받으면 나타남), 체크인 배지 방문 기록 화면, «다음 목표»의 진행. 문구는 운영 로직 7.3·9.3·10.4절의 말투를 따른다. «지점»·«POI» 표기는 «장소»로 통일한다(4-2).
- 구현 계획: 시작 때 채원 사전 판정을 받는다. 판정이 제안한 모양을 사용자가 승인한다. 파일이 많으면 2회로 나눈다(1회 지도·장소 카드·드랍·픽업, 2회 배지함·트리·상세).
- 관련 파일(2026-10-18 조사, 시작 때 아현이 줄 위치를 확인한다): 지도 `jam-web/src/app/(main)/drops/DropsClient.tsx`(324줄), `components/map/MapView.tsx`(588줄), `drops/BadgeDetailSheet.tsx`(203줄), 장소 카드와 드랍·픽업 목록 `components/PoiCarouselModal.tsx`(1055줄), 배지함 `app/(main)/badges/page.tsx`(277줄)·`BadgesClient.tsx`(347줄), 트리 `badges/tree/page.tsx`(350줄)·`BadgeTreeClient.tsx`(399줄)·`lib/badgeTree.ts`(602줄)·`components/badges/BadgeFamilyRow.tsx`(249줄), 상세 `badges/[id]/page.tsx`(673줄)·`BadgeConditionCard.tsx`(49줄)·`PoiEarnHistory.tsx`·`PoiMapButton.tsx`, 3-4에서 만든 가림 방식 `components/ui/BadgeGridCard.tsx`의 `locked`와 MODULAR `LockedTile`, 이용 정지 막힘 안내 선례 `lib/suspension/suspended-block.ts`와 info 토스트, 문구 `lib/i18n/ko.ts`, 스펙 운영 로직 7.3·9.3·10.4절, 디자인 시스템 `docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`.

## 배경 / 문제 정의

서버(4-1~4-5)가 모두 선 뒤에 화면을 한 번에 만든다. 운영 로직의 표시 규칙: 지도 위에 놓인 잠긴 개체도 «잠김»으로만 보이고 이름·그림은 보이지 않는다(7.3절). 채우다 만 잠긴 개체를 드랍하면 채운 양이 사라지므로 드랍하기 전에 알린다. 액티비티 배지는 서사 설명과 따로 명확한 값으로 적힌 획득 조건을 보여 주고, 숨김 배지는 받기 전까지 트리에도 보이지 않는다(10.3절).
공용 DB 주의: 옛 프로덕션 코드가 같은 테이블·함수를 쓴다. 새 칸·새 테이블·새 함수·새 설정 행만 덧붙이고 기존 칸의 뜻은 바꾸지 않는다. 축소는 묶음 6이다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

시작 때 채원 사전 판정의 승인 항목(새 컴포넌트, 화면 위치, 문구)을 질문한다. 미리 정해 둘 것은 없다.

## 사용자 결정 (2026-10-19 질문창 답, 카리나 기록)

채원 사전 판정(1차)의 승인 항목에 대한 답이다. 1차 판정은 «배지 트리 구조»를 전제로 했으므로 트리 관련 항목은 아래 1번 결정으로 다시 판정한다(채원 재판정).

1. **배지 트리 기능 제거(사용자가 «배지트리 기능 제거할 것임»이라고 답했고 4-6에서 제거까지 하기로 확정)**: 배지 트리 화면(`app/(main)/badges/tree/`), 진입 링크, 트리 전용 모듈(`lib/badgeTree.ts`, `components/badges/BadgeFamilyRow.tsx` 등)을 걷어낸다. 운영 로직 10장은 «다음 목표»와 계열 진행을 트리에서 보여 주는 것으로 적혀 있어, **«다음 목표»와 계열 진행을 보이는 자리**(배지함 안 섹션 또는 배지 상세만 등)를 채원이 재판정한다. 가지(`branch_key`) 소제목은 트리와 함께 사라지므로 이번에 노출하지 않는다. 트리가 쓰던 서버 값(계열 진행 스냅샷 `user_family_progress`, `badgeProgress.ts`)과 4-4가 만든 숨김 거름(`hiddenBadges.ts`)은 새 자리에서도 그대로 쓴다. 트리 제거에 따라 운영 로직 10.1·10.4절, PRD, 사용자 문서의 «배지 트리» 서술과 `docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`·MODULAR(`BadgeStatusSection` 등 트리 전용 컴포넌트가 다른 곳에서 쓰이지 않는지)를 함께 정리한다. MODULAR 컴포넌트 삭제나 변경이 있으면 Story와 문서를 같이 고친다(채원 판정 필요).
2. **배지함 종목 필터**: «JAM!» 옵션을 «공통»(`activity_types`가 비어 있는 모든 배지, 합산 8개와 JAM 활동 12개 포함)으로 바꾼다(추천).
3. **숨김 배지 정책**: 숨김 배지를 선행 조건·교차 게이트·미션 보상으로 지정하지 못하게 어드민·서버에서 저장 단계에서 막는다(추천). 화면에는 «비밀 배지 필요» 같은 칩·자리표시 문구를 만들지 않는다. 구현은 티켓 `20261019_0012`에서 한다.
4. **채원 제안 일괄 승인(추천)**: ① 잠긴 채 픽업했을 때 놓은 사람에게 «{누군가}님이 잠긴 아이템 배지를 픽업했어요» 소식(묶음은 기존 «드랍한 아이템 배지 N개가 픽업됐어요», 눌러도 갈 곳 없음, 피드는 계속 올리지 않음). ② 막힘 안내: 가득 참은 시트 안 인라인 안내, 장소 차단은 인라인 안내와 [픽업] 비활성, 이용 정지는 info 토스트만, 꺼진 장소는 info 토스트 후 카드 닫기, «이미 누가 픽업함»도 error에서 info로 낮춤. ③ 새 서비스 전용 컴포넌트 1개(인라인 안내 블록, MODULAR 승격은 이번에 하지 않음). ④ 사라질 양을 읽지 못하면 잠긴 개체 드랍을 막고 [다시 확인]을 보인다.
- 채원 1차 판정의 나머지 항목(장소 카드 잠긴 개체 행, 픽업 시트 잠긴 변형, 드랍 확인 단계의 사라질 양 블록, 체크인 배지 상세 «방문 기록»과 «처음 받은 날», 새 문구 목록, 토큰 사용)은 트리와 무관해 그대로 유효하다. 1차 판정 원문은 이 티켓 「채원 사전 판정(1차)」 절에 있다.

## 채원 사전 판정(2차, 트리 제거 재판정, 2026-10-19)과 사용자 최종 결정

채원은 트리 제거 재판정에서 «배지함 맨 위 다음 목표 3개 한 줄(`BadgeStatusSection`+`BadgeProgressRingCard`)» 안을 추천했으나 **사용자가 «진행 표시를 완전히 뺌»을 선택했다**(채원이 «받지 않은 배지를 볼 곳이 없어져 운영 로직 10.4와 어긋난다»며 비추천한 안). 사용자 최종 결정은 다음과 같고 구현은 이를 따른다.

1. **배지 트리 제거, 진행 표시(«다음 목표»·계열 진행)는 만들지 않는다**: 배지함은 지금처럼 받은 배지만 보여 주고 화면에는 진행이 어디에도 없다. 받지 않은 배지의 상세는 지금처럼 조건 카드·선행 배지·포인트 보상을 보이고(링크로 들어왔을 때만), 진행을 새로 만들지 않는다. 운영 로직 10.1(셋째 줄)·10.2·10.3·10.4·10.6과 사용자 노출 문서의 «배지 트리»·«다음 목표»·«진행» 서술은 «배지함은 받은 배지를 보여 주고 받지 않은 배지는 상세에서 조건을 본다»로 고친다. 진행 표시가 없어지는 것은 사용자 결정이며 운영 로직 10.4의 «받지 않은 배지는 다음 목표에 진행이 가까운 순으로 나온다» 약속을 접는 것이므로 10.4를 고치고 잔여 이슈에 적는다.
2. **서비스에서 제거**(채원 조사): `app/(main)/badges/tree/page.tsx`, `tree/BadgeTreeClient.tsx`, `components/badges/BadgeFamilyRow.tsx`, `BadgeTrophyGridCard.tsx`, `BadgeUnlockSheet.tsx`, `BadgesClient.tsx`의 «배지 트리» 버튼(약 200줄, 문구 `d.badges.treeButton`). 옛 주소 `/badges/tree`는 `next.config`의 redirects로 `/badges`에 307 임시 이동시킨다. 다음 목표가 없으므로 이 화면만 쓰던 `BadgeProgressGridCell.tsx`, `lib/badgeProgressText.ts`(`formatGridCellCaption`), `badgeTreeConditionStatus.ts`, `badgeTreeConditionCheck.server.ts` 중 **다른 곳에서 쓰이지 않는 것은 grep으로 확인해 함께 지운다**(어드민·`badgeProgress.ts`·엔진이 쓰는 것은 남긴다). `lib/badgeTree.ts`는 어드민 4곳(`admin/badge-families/page.tsx`, `admin/gate-missions/GateMissionForm.tsx`, `admin/badges/bulk/BulkToolManager.tsx`, `lib/admin/badge-list-view.ts`·`badge-families.ts`)과 `lib/badge-engine/badgeProgress.ts`(`BadgeTreeLock`)가 쓰므로 파일은 남기고 안 쓰게 된 export만 정리한다(이름 변경은 후속). 계열 진행 스냅샷(`user_family_progress`, `sync.ts` `updateFamilyProgressSnapshots`)은 읽는 곳이 없어지지만 이번에 건드리지 않고 후속 정리 티켓으로 남긴다. `lib/i18n/ko.ts`의 트리 전용 문구를 정리한다.
3. **MODULAR 삭제(사용자 승인)**: 트리에서만 쓰던 6개 `BadgeStageRail`, `BadgeLevelGauge`, `BadgeStampRow`, `DualAxisGauge`, `BadgeTreeSummaryHeader`, `UnlockConditionSheetContent`와, 다음 목표를 만들지 않아 서비스 사용처가 없어지는 `BadgeProgressRingCard`·`BadgeStatusSection`(둘 다 서비스에서 쓰이지 않는지 grep으로 확인한 뒤)을 각각의 `.jsx`·`.d.ts`·`.prompt.md`·`.stories.tsx`·`_ds_manifest.json`·`design-system/readme.md` 색인·`docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`·테스트(`cardFacePairs.test.tsx`, `dsLiteralColors.test.ts`)까지 함께 정리한다. `BadgeFamilyCardHeader`는 `progressRampColor`·`NEAR_THRESHOLD`의 단일 원천(`BadgeProgressRingCard`·`badgeProgressText.ts`·`dsLiteralColors.test.ts`가 가져옴)이므로, `BadgeProgressRingCard`와 `badgeProgressText.ts`가 사라지면 그 상수를 쓰는 곳이 남는지 보고 남지 않으면 같이 지운다(남으면 `.prompt.md`에 «서비스 미사용, 상수가 단일 원천»을 적는다). 삭제는 임시로 숨겨 두거나 `@deprecated`로 남기지 않고 한 번에 끝낸다. 삭제는 claude.ai/design 사본에 바로 반영되지 않으므로(DesignSync 인증이 막힘, 티켓 20260920_2220 WAITING) 잔여 이슈에 «claude.ai/design 사본에 MODULAR 삭제 미반영(모드 ③ 동기화로 처리)»를 적는다. 트리 제거(서비스)와 MODULAR 삭제는 커밋을 나눠 되돌리기 쉽게 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 서버가 정한 값(잠김, 사라질 양, 막힌 까닭, 숨김, 진행)을 그대로 그린다. 화면이 규칙을 다시 계산하지 않는다.
- 잠긴 개체의 이름·그림은 클라이언트로 내리는 props에 넣지 않는다(서버에서 비운다, 3-4 방식).
- 이용 정지·꺼진 장소·가득 참·장소 차단으로 막힌 드랍·픽업은 일반 실패가 아니라 까닭이 보이는 안내(info 톤)를 낸다(2-6·3-6 선례).
- 클라이언트·서버 경계: 클라이언트가 가져오는 모듈은 서버 전용 모듈(`@/lib/supabase/server`, `next/headers`)을 정적·동적 어느 쪽으로도 가져오지 않는다. 순수 계약 파일과 서버 파일을 나눈다.

### UI/UX 관점

- 채원 판정을 따른다. 오버레이를 만들거나 고치면 `docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`의 z-index 레이어 체계를 먼저 읽고 기하값은 `offsetHeight`로 실측한다.
- 사용자 노출 문구는 UX 라이팅 가이드와 `fluent-korean` 지침을 따른다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 장소 카드의 드랍 목록에서 잠긴 개체가 «잠김»과 등급만 보이고 이름·그림·일련번호가 DOM 어디에도 없다. 잠긴 개체를 드랍하기 전에 사라질 양이 보인다.
- 가득 참·이용 정지·꺼진 장소·장소 차단으로 막힌 픽업·드랍이 까닭이 보이는 안내를 낸다.
- 배지함·트리·상세가 가지 분류와 숨김 배지를 서버 값대로 보인다(숨김 배지는 받기 전에 어디에도 안 보임). 체크인 배지 상세가 방문 기록을 보인다.

- 실렌더 확인(세로 568·667·844px, 너비 320~430px 겹침과 터치 영역)은 카리나가 머지 뒤 push 전에 로컬에서 한다.
