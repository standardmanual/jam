# [Service] JAM2 미션 보상과 소식: 새 개체 복사, 잠김, 가득 참 보류와 받기, 숨김 배지 차단, 소식·기록

## 핵심 요약

- 요구사항: 운영 로직 13.2절의 «보상»과 «소식과 기록»을 서버에 맞춘다. (1) 보상은 액티비티 배지(미션으로만 받는 보상 배지 포함), 포인트, 아이템 배지(잠김 여부 지정)다. 잼은 보상으로 주지 않는다. (2) 이미 가진 아이템 배지도 새 개체로 주고, 인벤토리가 모자라면 받지 않은 상태로 두며, 미션 기간이 끝난 뒤에도 기한 없이 미션 상세에서 받을 수 있다(6.4절). (3) 숨김 배지를 미션 보상으로 쓰지 못하게 서버와 어드민 검색에서 막는다(티켓 `20261019_0012`). (4) 소식은 진행 50%와 80%, 완료, 마감 이틀 전, 순위 상승, 종료 결과, 트라이브 변경에 따른 참가 취소다. 지금 있는 것은 두고 없는 것만 더한다. (5) 참가, 진행, 완료, 받은 보상, 받지 않은 보상, 참가 취소를 기록한다.
- 구현 계획: 시작 때 사용자 결정 2건을 질문하고 파일 단위 계획을 옮겨 쓴다. DB는 새 테이블·새 칸·알림 종류 추가만 한다(알림 종류 추가는 새 enum 값을 같은 트랜잭션에서 쓰지 못해 마이그레이션을 따로 나눈다). SQL은 사용자 승인과 롤백 실측 뒤 카리나가 실행한다.
- 관련 파일(2026-10-19 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 보상 지급 `jam-web/src/lib/missions/rewards.ts`(`grantMissionRewards` 31줄, 활동 배지 INSERT 104줄, 아이템 배지 `grant_inventory_item` RPC 127줄, 가진 것·가득 참 건너뛰기 121~122줄, 포인트 163·179줄), 호출 `lib/missions/checker.ts:188`, 어드민 보상 배지 선택 `app/admin/missions/MissionForm.tsx:321`(`BadgeMultiSearchSelect`) → `app/api/admin/badges/search/route.ts`, 저장 `app/api/admin/missions/route.ts`·`[id]/route.ts`(`reward_badge_ids` 미검증), 미션 상세 `app/(main)/missions/[id]/page.tsx:40`, 잠김 지정 지급 `grant_inventory_item_locked`(마이그레이션 231, 84줄), 가득 참 보류 `sync_pending_items`(마이그레이션 229)와 받기 경로, 소식 `lib/notifications/batch/missions.ts`·`lib/notifications/index.ts:124`(`createNotification`), 흡수 티켓 `docs/tickets/p3-low/20261019_0012_*`, 조사 결과 전문은 상위 티켓 `20261019_1310`.

## 배경 / 문제 정의

지금 미션 보상 지급은 이미 가진 아이템 배지와 가득 찬 인벤토리를 그냥 건너뛰고(`rewards.ts:121-122`) 나중에 받는 길이 없다. 잠김 지정도 없다. 묶음 2에서 동기화 보상에는 가득 참 보류와 받기를 만들었으므로(마이그레이션 229), 미션 보상이 같은 구조를 쓰는지가 이 티켓의 핵심이다.
숨김 배지는 어드민 검색에서 걸러지지 않고, 서버도 `reward_badge_ids`의 존재·유형·숨김 여부를 검증하지 않으며, 지급과 미션 상세도 숨김을 거르지 않는다. 그래서 받기 전에 미션 상세에서 숨김 배지의 이름이 보일 수 있다. 티켓 `20261019_0012`는 숨김 배지를 선행 조건과 교차 게이트로 쓰지 못하게 막는 것까지 포함한다. 이 티켓은 미션 보상 경로를 맡고, 선행 조건·교차 게이트 경로는 시작 때 범위를 확인한다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **미션 보상의 가득 참 보류**: 묶음 2의 보류 저장(마이그레이션 229)에 미션 출처를 더해 같은 «받기» 경로와 화면을 쓴다(추천, 받기 코드를 두 벌 만들지 않는다). 대안은 미션 전용 보류 테이블을 새로 두는 것이다(독립적이지만 받기 화면이 둘이 된다).
2. **숨김 배지 차단의 범위**: 미션 보상은 서버 저장 검증과 지급 시 검증, 어드민 검색 제외까지 하고, 선행 조건·교차 게이트 경로는 `20261019_0012`의 원래 범위대로 이 티켓에서 함께 막는다(추천, 사용자가 이미 구현을 결정했다). 대안은 미션 보상만 이 티켓에서 막고 나머지는 별도로 남기는 것이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **새 개체로 주기**: 이미 가진 아이템 배지도 새 개체를 만든다(일련번호는 새로 매긴다). 건너뛰는 코드를 없앤다.
- **잠김 지정**: 미션 보상의 아이템 배지에 «잠긴 채로 준다» 지정을 저장하고, 지급이 `grant_inventory_item_locked`를 쓴다. 지정 칸의 모양은 시작 때 아현이 정한다(보상 배지 목록 JSON에 항목별 값 또는 새 칸).
- **가득 참 보류**: 인벤토리가 모자라면 지급하지 않고 받지 않은 상태로 두며, 미션 기간이 끝난 뒤에도 기한 없이 받을 수 있다. 받기 경로는 결정 1을 따른다.
- **숨김 배지 차단**: 어드민 검색에서 숨김 배지를 빼고, 저장 API가 보상 배지를 검증해(존재, 유형, 숨김 여부) 거절하며, 지급과 미션 상세 조회가 숨김 배지를 거른다. 선행 조건·교차 게이트 경로는 결정 2를 따른다.
- **소식**: 지금 있는 소식(50%·80%·완료·마감 임박·순위 상승·종료 결과)을 확인하고 없는 것만 더한다. 새로 필요한 것은 «트라이브가 바뀌어 「○○」 미션 참가가 취소됐어요» 소식이다(5-1의 취소 함수가 돌려준 목록으로 호출). 알림 종류 추가 순서는 마이그레이션(`ALTER TYPE notification_type ADD VALUE`, 237 참고), `types/database.ts`, `lib/notifications/types.ts`, `message.ts`, `href.ts`다. 문구는 UX Writing 가이드(`docs/service/writing/UX_WRITING_GUIDELINE.md`)를 따른다.
- **기록**: 참가, 진행, 완료, 받은 보상, 받지 않은 보상, 참가 취소를 조회할 수 있어야 한다. 이미 있는 테이블로 충분한지 확인하고 모자란 칸만 덧붙인다.
- 새 칸·새 테이블·새 함수는 덧붙이기만 한다. 생성 타입을 같은 커밋에 맞춘다.

## 구현 계획 (회차)

1~2회로 돌린다(아현 판단, 예상 파일 약 15개). 1회는 보상 지급 경로(새 개체, 잠김, 보류, 숨김 차단), 2회는 소식과 기록이다. 앱 파일 단위 계획은 아현이 시작 때 쓴다.

1. 마이그레이션(번호는 시작 때 확인): 미션 보류 출처(결정 1), 알림 종류 추가(별도 파일). 되돌림 SQL을 싣는다.
2. `lib/missions/rewards.ts`: 새 개체 지급, 잠김 지정, 보류 저장, 숨김 거르기.
3. 어드민 검색·저장 API의 숨김 배지 제외와 검증, 미션 상세 조회의 숨김 가림.
4. 소식 종류 추가와 참가 취소 소식, 기록 조회.
5. 시험: 이미 가진 아이템 배지도 새 개체 지급, 가득 참 보류 뒤 받기, 잠김 지정 지급, 숨김 배지 보상 저장 거절, 숨김 배지가 상세에 노출되지 않음.
6. 문서: 미션 PRD, `docs/service/prd/02_DATA_MODEL.md`, 엔진 문서의 보상 경로 서술.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 미션 보상의 아이템 배지가 이미 가진 것이어도 새 개체로 지급되고, 잠김 지정이 반영된다.
- 인벤토리가 모자라면 받지 않은 상태로 남고, 미션 기간이 끝난 뒤에도 받을 수 있다.
- 숨김 배지를 미션 보상으로 저장할 수 없고(어드민 검색에도 안 나온다), 지급과 미션 상세에서 걸러진다. 티켓 `20261019_0012`의 완료 조건을 만족한다.
- 트라이브 변경에 따른 참가 취소 소식이 만들어진다(함수 호출 시험으로 확인). 기록 조회가 된다.
- 마이그레이션이 옛 객체의 서명·권한을 바꾸지 않고 되돌림 SQL을 싣는다.

### 후속 범위 (담당: 카리나, 시점: 사용자 승인 뒤)

- 시작 때 결정 1·2번을 이 티켓 「사용자 결정」 절에 기록한다. 티켓 `20261019_0012`는 이 티켓 완료 뒤 CLOSED로 바꾼다.
