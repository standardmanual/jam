# [Infra] vitest 제외 패턴이 어드민 미션 보상 배지 라우트 시험을 말없이 제외한다

## 핵심 요약

- 요구사항: `jam-web/vitest.config.ts`의 제외 패턴 `**/admin/missions/__tests__/**`가 `src/app/api/admin/missions/__tests__/reward-badges-routes.test.ts`(vitest 스위트)까지 제외해 CI에서 한 번도 돌지 않는다. 이 시험을 돌게 하고, 같은 폴더의 `tsx`(node:assert) 시험과 구분하는 방법을 정한다.
- 구현 계획: 폴더 단위 제외를 파일 단위 제외(`test:node` 목록의 파일만)로 바꾸고, 되살아난 시험이 통과하는지 확인한다. 제외 패턴이 다른 vitest 스위트를 가리는 곳이 더 있는지 전체를 점검한다.
- 관련 파일: `jam-web/vitest.config.ts` 제외 목록(티켓 20261019_1317 2회가 `**/missions/__tests__/**`를 `**/lib/missions/__tests__/**`와 `**/admin/missions/__tests__/**` 둘로 좁힌 뒤의 모습), `jam-web/src/app/api/admin/missions/__tests__/reward-badges-routes.test.ts`, `jam-web/package.json`의 `test:node` 목록.

## 배경 / 문제 정의

티켓 20261019_1317 2회에서 `(main)/missions/__tests__`의 vitest 시험이 `**/missions/__tests__/**` 한 줄에 걸려 한 번도 돌지 않았다는 것을 아현이 찾았다. 그 줄을 `lib/missions`와 `admin/missions` 두 폴더만 제외하도록 좁혔고, 되살아난 시험은 통과했다. 그런데 `admin/missions/__tests__` 폴더 안의 `reward-badges-routes.test.ts`는 vitest 스위트(`vi` 기반 기록형 가짜 클라이언트로 숨김 거절, 유형, 읽기 실패 500을 고정)라서 같은 이유로 계속 제외된다. 숨김 배지 차단(티켓 20261019_1313 2회)의 어드민 저장 검증을 지키는 시험이라 CI가 이 방어를 보지 못한다.

발견: 2026-10-21 티켓 20261019_1317 2회 게이트(민지)와 아현 보고. 확인한 사실은 파일 존재와 제외 패턴 문자열이다. 이 시험이 실제로 통과하는지는 아직 돌려 보지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 제외 대상은 `test:node`로 도는 `tsx` 시험 파일로만 한정한다(폴더가 아니라 파일 이름으로).
- `reward-badges-routes.test.ts`를 돌려 통과하는지 확인한다. 실패하면 시험이 낡은 것인지 코드 회귀인지 가려서 고친다.
- 제외 패턴이 가리는 다른 vitest 스위트가 있는지 `npx vitest list`와 폴더별 시험 수를 대조해 찾는다.

## 완료 조건

- [ ] 제외 목록에 vitest 스위트를 가리는 폴더 패턴이 없다
- [ ] `reward-badges-routes.test.ts`가 `npx vitest run`에서 돌고 통과한다
- [ ] 같은 방식으로 가려진 다른 시험이 있으면 목록과 처리를 기록한다
