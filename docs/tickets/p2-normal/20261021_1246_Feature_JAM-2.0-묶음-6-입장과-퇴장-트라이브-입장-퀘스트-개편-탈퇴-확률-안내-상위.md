# [Feature] JAM 2.0 묶음 6: 입장과 퇴장 (트라이브 입장, 퀘스트 개편, 탈퇴, 확률 안내, 옛 객체 정리 준비)

## 핵심 요약

- 요구사항: 운영 로직 2장(가입, 트라이브, 온보딩), 15장(홈, 소셜, 알림, 문의), 17장(탈퇴와 데이터), 18장(안전과 확률 안내)을 만든다. 트라이브를 고르기 전에는 앱의 어느 화면과 Strava 연결·동기화도 쓸 수 없게 하고, 퀘스트의 실제 세 단계를 마치면 챕터 1이 되게 하며, 유저가 스스로 탈퇴할 수 있게 하고, 확률 안내 페이지를 만든다. 옛 객체를 정리하는 DB 변경은 SQL 작성과 롤백 실측까지만 하고 실행은 출시 뒤에 한다(사용자 결정, 2026-10-21).
- 구현 계획: 하위 티켓 4개를 순서대로 진행한다(아래 표). 6-1 입장, 6-2 퀘스트 개편, 6-3 퇴장, 6-4 안내·전환이다. 하위 티켓마다 시작 전에 주요 결정을 질문창으로 묻고, 화면이 있는 것은 채원 사전 판정을 받는다. 규모가 30개 파일을 넘을 것 같으면 처음부터 2~3회로 나눈다.
- 관련 파일: `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 2·15·17·18장, `docs/plan/jam2/service-redesign/현재 서비스 비교.md`(5.3절 「13 온보딩과 기존 유저·데이터」「14 안전과 윤리」 행), `docs/plan/jam2/service-redesign/13 온보딩과 기존 유저·데이터.md`.

## 배경 / 문제 정의

상위 티켓 `20261016_2335`의 묶음 표는 묶음 6을 «새 온보딩에서 트라이브를 고르고, 확률 안내 페이지가 생기며, 탈퇴 유저가 하나의 텍스트로 보인다. 기존 유저를 지우는 전환도 여기서 맨 마지막에 한다»로 정했다. 온보딩 퀘스트의 실제 두 단계(캡슐 열기, 잠긴 아이템 배지 열기)는 캡슐이 생긴 뒤에야 완성되므로 묶음 3 뒤에 두었고, 묶음 5에서 챕터 1 시작이 퀘스트 완료 처리에 연결되었다.
지금 서비스는 트라이브를 고르지 않아도 앱을 쓸 수 있고, 유저가 스스로 탈퇴하는 길이 없으며(프로필 편집에 메일 링크뿐), 확률 안내 페이지가 없다. 앞 묶음이 «묶음 6에서 하자»고 넘긴 항목도 여럿 쌓여 있다.
