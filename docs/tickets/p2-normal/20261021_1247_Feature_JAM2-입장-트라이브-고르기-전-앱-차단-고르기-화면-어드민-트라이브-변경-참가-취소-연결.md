# [Feature] JAM2 입장: 트라이브 고르기 전 앱 차단, 고르기 화면, 어드민 트라이브 변경과 참가 취소 연결 (묶음 6, 6-1)

## 핵심 요약

- 요구사항: 운영 로직 2장을 서버와 화면에 맞춘다. (1) 트라이브를 고르기 전에는 앱에 들어오는 모든 경로에서 온보딩으로 보내고, Strava 연결과 동기화도 막는다. (2) 트라이브 고르기 화면에 대주제와 짧은 한 줄, «고른 뒤에는 바꿀 수 없다», «동기화로 받는 아이템 배지가 고른 트라이브의 것이다» 안내를 둔다. (3) 어드민이 유저의 트라이브를 바꿀 수 있게 하고, 바꾸면 참가 중인 트라이브 미션을 취소하며(`mission_cancel_for_tribe_change`) 취소 소식을 보낸다. 캡슐에 채우다 만 잼을 새 트라이브의 캡슐로 옮기는 규칙(온보딩 설계 13-5)도 확인한다.
- 구현 계획: 시작 때 사용자 결정을 질문하고 채원 사전 판정(트라이브 고르기 화면)을 받은 뒤 파일 단위 계획을 옮겨 쓴다. DB 변경이 필요하면 추가만 한다(기존 열·함수를 바꾸지 않는다).
- 관련 파일(2026-10-21 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 게이트 후보 `jam-web/src/proxy.ts`, `app/(main)/layout.tsx`, `app/api/strava/`(연결·동기화 라우트), 이동 지점 `app/auth/callback/route.ts`, `app/(main)/profile/page.tsx`, 고르기 화면 `app/(main)/onboarding/page.tsx`와 `lib/i18n/ko.ts` 1285줄 근처, 참가 취소 `lib/missions/participation-cancel.ts`와 마이그레이션 249, 어드민 유저 화면 `app/admin/users`, 알림 종류 `lib/notifications/types.ts`(참가 취소 종류 있음).

## 배경 / 문제 정의

운영 로직 2장은 «트라이브를 고르기 전에는 앱의 어느 화면도 쓸 수 없다. 로그인 직후만이 아니라 앱에 들어오는 모든 경로에서 트라이브를 확인하고, 없으면 온보딩으로 보낸다. Strava 연결과 동기화도 할 수 없다»고 정했다. 동기화로 받는 아이템 배지가 모두 소속 트라이브의 것이라 트라이브가 없으면 줄 아이템 배지를 정할 수 없기 때문이다.
지금은 트라이브를 고르지 않아도 앱을 쓸 수 있다. 트라이브를 바꾸는 경로도 없어서 5-1이 만든 참가 취소 함수를 부르는 곳이 없다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **게이트 기준**: `users.tribe_id`가 있는가(추천, 운영 로직 2장 문구와 같다). 대안은 `onboarding_completed_at`이다.
2. **트라이브 변경 입력**: 어드민 유저 상세에서 트라이브를 고르고 사유를 남긴다(추천). 변경 이력을 남길 표가 필요한지도 정한다.
3. **고르기 화면 모양**: 채원 사전 판정으로 확정한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 게이트는 한 곳에서 판정한다. 화면 라우트(`(main)`), 동기화·Strava 연결 API가 같은 판정을 쓴다. 트라이브를 읽지 못하면 막지 않고 로그를 남기는지, 막는지 시작 때 정한다.
- 트라이브를 바꾸면 `mission_cancel_for_tribe_change`가 돌려준 (미션 id, 이름) 목록으로 `mission_participation_cancelled` 소식을 한 건 보낸다(`lib/missions/participation-cancel.ts`).
- 이미 받은 보상은 그대로 두고, 챕터 숫자는 그대로이며 이름만 새 트라이브의 것으로 바뀐다(운영 로직 12.2절).
- 사용자 노출 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

### UI/UX 관점

- 고르는 화면: 트라이브마다 대주제와 짧은 한 줄, 고른 뒤에는 바꿀 수 없다는 안내, 동기화로 받는 아이템 배지가 고른 트라이브의 것이라는 안내(운영 로직 2.2절). 화면 구성은 채원 판정이다.

## 구현 계획 (회차)

시작 때 파일 단위로 옮겨 쓴다. 예상 규모가 30개 파일을 넘으면 2회로 나눈다(1회 게이트와 고르기 화면, 2회 어드민 트라이브 변경과 참가 취소 연결).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 트라이브가 없는 유저가 앱의 화면 라우트, Strava 연결, 동기화를 요청하면 온보딩으로 보내지거나 거절된다(시험으로 확인).
- 고르기 화면에 운영 로직 2.2절의 세 안내가 보인다.
- 어드민이 유저의 트라이브를 바꾸면 참가 중이던 트라이브 미션이 취소되고 취소 소식이 한 건 나간다. 이미 받은 보상은 그대로다(시험으로 확인).
- 마이그레이션이 있으면 옛 객체의 서명·권한을 바꾸지 않고 되돌림 SQL을 싣는다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 시작 때 결정을 이 티켓 「사용자 결정」 절에 기록한다. 머지 뒤 push 전에 로컬 화면을 열어 확인한다(공용 DB를 바꾸는 버튼은 누르지 않는다).
