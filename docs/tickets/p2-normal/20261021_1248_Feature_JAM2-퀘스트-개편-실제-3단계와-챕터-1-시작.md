# [Feature] JAM2 퀘스트 개편: 실제 3단계와 챕터 1 시작 (묶음 6, 6-2)

## 핵심 요약

- 요구사항: 운영 로직 2.2절의 퀘스트를 만든다. 연출 7단계는 지금 퀘스트를 그대로 쓰고, 실제 3단계(첫 동기화, 캡슐 열기, 잠긴 아이템 배지 열기)를 마치면 챕터 1을 받는다. 건너뛰기는 연출 단계만 건너뛰며 실제 단계를 마치면 건너뛴 유저도 챕터 1을 받는다. 챕터가 없는 유저의 캡슐은 첫 동기화로 받은 잼으로 열 수 있는 양이고, 첫 캡슐에서는 잠긴 아이템 배지가 반드시 하나 나온다. 가장 짧은 활동(10분 걷기, 잼 10)으로 실제 단계를 모두 마칠 수 있다.
- 구현 계획: 시작 때 사용자 결정을 질문하고 채원 사전 판정(퀘스트 카드)을 받은 뒤 파일 단위 계획을 옮겨 쓴다. 5-6이 만든 챕터 1 시작과 재시도 경로를 유지한다.
- 관련 파일(2026-10-21 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 완료 처리 `jam-web/src/lib/onboarding-quest/completion.ts`(완료 조건 41줄 근처), 챕터 1 시작 `lib/chapter/start.ts`, 퀘스트 화면 `app/(main)/OnboardingQuestCard.tsx`·`lib/onboarding-quest/status.ts`, 퀘스트 전 캡슐 `lib/capsule/open.ts`(179줄 근처)와 마이그레이션 232~234(`capsule_policy.pre_quest_fill_amount`), 문구 `lib/i18n/ko.ts`(222·272·283줄 근처 «퀘스트»).

## 배경 / 문제 정의

운영 로직 2.2절은 퀘스트를 연출 단계와 실제 단계로 나눈다. 지금 완료 조건은 연출 7단계(또는 건너뛰기)와 처리된 활동 1건이라 캡슐 열기와 잠긴 열기를 보지 않는다. 5-6이 챕터 1 시작을 이 완료 처리에 연결해 챕터 1이 첫 동기화 직후에 시작되고, 캡슐 열기와 잠긴 열기 점수는 챕터 1 뒤에 쌓인다. 캡슐 행은 홈 진입 때 처음 만들어지고 그때 챕터가 없으면 퀘스트 전 값 5, 있으면 챕터별 값(챕터 1은 90)을 쓴다. 이 순서가 운영 로직과 어긋나므로 완료 조건을 실제 단계로 바꾼다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창)

1. **퀘스트 카드의 모양과 문구**: 실제 3단계를 어떻게 보이는지 채원 사전 판정으로 확정한다. 유저 화면의 «퀘스트» 표기가 운영 로직과 맞는지도 함께 확인한다.
2. **챕터 1 시작 시점**: 실제 3단계를 모두 마친 순간(추천, 운영 로직 2.2절). 완료 조건 바꾸기 전에 이미 챕터 1을 받은 유저의 처리는 필요 없다(정식 오픈 전에 모든 테스트 유저를 지운다).

## 상세 요구사항

### 서비스/코드베이스 관점

- 완료 판정은 실제 3단계(활동이 처리된 첫 동기화, 캡슐 열기 기록, 잠긴 아이템 배지 열기 기록)를 읽어 정한다. 건너뛴 유저도 실제 단계를 마치면 챕터 1을 받는다.
- 챕터 1 시작과 재시도 경로(`ensureChapterStarted`)는 유지한다. 완료 조건이 바뀌어도 `chapter_start`가 멱등이라 안전하다.
- 첫 캡슐에서 잠긴 아이템 배지가 반드시 하나 나오는지(운영 로직 2.2절)는 시작 때 서버가 보장하는지 확인한다.
- 사용자 노출 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

### UI/UX 관점

- 퀘스트 카드에 실제 3단계의 진행이 보인다. 연출 7단계는 지금 모양을 유지한다. 구성은 채원 판정이다.

## 구현 계획 (회차)

시작 때 파일 단위로 옮겨 쓴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 실제 3단계를 모두 마치면 챕터 1이 시작되고 그 전에는 시작되지 않는다. 건너뛴 유저도 같다(시험으로 확인).
- 챕터가 없는 유저의 캡슐이 퀘스트 전 값으로 열린다. 챕터 1 시작과 재시도 경로가 그대로 동작한다.
- 퀘스트 카드에 실제 3단계가 보인다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 시작 때 결정을 이 티켓 「사용자 결정」 절에 기록한다. 머지 뒤 push 전에 로컬 화면을 연다. 새 퀘스트 흐름은 사용자가 staging에서 새 계정으로 확인한다.
