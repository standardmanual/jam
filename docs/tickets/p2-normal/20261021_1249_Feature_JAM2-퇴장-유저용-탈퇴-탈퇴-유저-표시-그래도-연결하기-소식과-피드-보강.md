# [Feature] JAM2 퇴장: 유저용 탈퇴, 탈퇴 유저 표시, 그래도 연결하기, 소식과 피드 보강 (묶음 6, 6-3)

## 핵심 요약

- 요구사항: 운영 로직 17장과 15장 일부를 만든다. (1) 유저가 «탈퇴하기»로 스스로 탈퇴할 수 있고, 탈퇴와 어드민 삭제와 Strava 다른 계정 연결 때의 기존 계정 지우기가 같은 규칙으로 지운다(아바타 파일과 문의 행도 지운다). (2) 지운 유저가 남긴 이력의 빈 행위자는 하나의 텍스트(운영 로직 17.2절)로 보인다. (3) Strava 다른 계정 연결 시 «그래도 연결하기»와 동의 철회를 연결한다. (4) 소식과 피드를 보강한다: 받지 않은 보상·트라이브 변경 소식, 챕터·등급 완성 피드, 필요하면 이용 정지·풀림 소식.
- 구현 계획: 시작 때 법 보관 기록과 기간을 사용자에게 확인하고(운영 로직 17장이 비워 둠, 티켓 `20260929_1303` 대기 중) 채원 사전 판정(탈퇴 화면)을 받은 뒤 파일 단위 계획을 옮겨 쓴다. 지우는 일이 되돌릴 수 없으므로 실행 전 지울 범위를 보이고 승인을 받는 절차를 구현에 포함한다.
- 관련 파일(2026-10-21 조사, 시작 때 아현이 줄 위치를 다시 확인한다): 탈퇴 진입 `jam-web/src/app/(main)/profile/edit/page.tsx`(375줄 근처 메일 링크), 어드민 삭제 `lib/admin/user-actions.ts`(175줄 근처), 시트 `lib/googleSheets.ts`(39줄 근처 읽기 전용), 이력 이름 스냅샷 마이그레이션 108(193~197줄)과 `app/admin/item-badges/[badgeId]/[itemId]/CustodyTimeline.tsx`(11줄 «익명화 안 함»), 표시 문구 `lib/i18n/ko.ts`(561줄 근처 «알 수 없는 유저»), 그래도 연결하기 `app/api/strava/*`·티켓 `20261017_1422`, 소식 종류 `types/database.ts`(1955줄 근처), 피드 `lib/activity-feed/index.ts`.

## 배경 / 문제 정의

운영 로직 17장은 계정을 지우는 경우를 유저 탈퇴, 같은 Strava 계정을 다른 JAM 계정에 연결하며 기존 계정을 지울 때, 이용 정지 뒤 이야기한 결과 지우게 될 때로 나누고 모두 같은 규칙으로 지운다고 정했다. 지울 때 이력의 행위자 칸은 비워지므로 비어 있는 행위자를 정해진 텍스트로 보이면 된다.
지금은 유저용 탈퇴가 없고(프로필 편집에 메일 링크뿐), 어드민 삭제는 계정 삭제만 하며 아바타 파일과 문의 행을 지우지 않는다. 법이 보관을 요구하는 기록과 기간은 정해지지 않았고, 이력 이름 스냅샷은 운영 로직 17.2절과 충돌한다. «그래도 연결하기»는 앞 티켓이 묶음 6으로 넘겼다.

## 시작 전에 사용자에게 확인할 것 (주요 결정, 질문창. 2026-10-21 결정 완료, 아래 「사용자 결정」 참조)

1. **법이 보관을 요구하는 기록과 기간**: 정해야 시작할 수 있다. 정하지 못하면 이 티켓은 WAITING으로 둔다.
2. **이력 이름 스냅샷 충돌**: 마이그레이션 108의 이름 스냅샷과 어드민 «익명화 안 함»이 운영 로직 17.2절(지울 때 이름을 지움)과 충돌한다. 어느 쪽을 따를지 정한다.
3. **이용 정지·풀림 소식**: 배너 말고 소식도 보낼지 정한다(운영 로직 16장).
4. **탈퇴 화면의 모양**: 채원 사전 판정으로 확정한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 지우는 규칙은 한 함수가 맡고 유저 탈퇴, 어드민 삭제, 그래도 연결하기가 같이 쓴다. 지운 뒤에는 행위자가 비어 있는 이력이 정해진 텍스트로 보인다.
- 지울 범위를 실행 전에 보이고 승인을 받는다(되돌릴 수 없는 작업). 공용 DB를 바꾸는 시험은 하지 않고 시험이 규칙을 증명한다.
- DB 변경이 필요하면 추가만 한다. 이력 열의 제약이나 외래키를 바꾸는 일은 옛 객체를 바꾸는 것이므로 이 티켓에서는 하지 않고 6-4의 정리 목록에 올린다.

### UI/UX 관점

- 프로필 설정에 «탈퇴하기»가 있고 확인 화면에서 지워지는 것을 알린다. 구성은 채원 판정이다.

## 사용자 결정 (2026-10-21)

시작 전 조사(코드와 공용 DB 읽기 전용) 뒤 질문창으로 받았다. 추천과 다르게 정한 항목은 표시했다.

1. **법 보관 기록**: 지금 약관과 방침에 적힌 기간대로 **보관 표를 이 티켓에서 만든다**(추천은 «표 없이 진행»이었으나 사용자가 다르게 정했다). 위치정보 확인자료(체크인 방문 기록) 6개월, 부정 이용 탐지 기록 3개월이다. 기간 근거는 `location-terms/page.tsx` 232~233줄(6개월 이상 보관)과 `privacy/page.tsx` 312줄(부정 이용 탐지 3개월)이다. 법무 확인은 티켓 `20260929_1303`에서 하고, 거기서 기간이 바뀌면 이 티켓의 보관 표 기간 상수를 맞춘다.
2. **문의 기록**: 지우지 않고 방침대로 **처리 완료 후 3년 보관**한다(`privacy/page.tsx` 324줄). 문의는 DB가 아니라 Tally와 연결된 구글 시트(읽기 전용 권한, 유저 id 칸 없음)라 시트 쓰기 권한은 만들지 않는다. 운영 로직 17.2 표의 «아바타 파일과 문의 기록처럼 DB 밖에 남는 것은 함께 지운다»를 «아바타 파일은 함께 지우고 문의 기록은 처리 완료 후 3년 보관한 뒤 파기한다»로 고친다.
3. **이름 스냅샷**: 운영 로직 17.2대로 **지울 때 이력의 이름 칸을 비운다**. 어드민 아이템 배지 이력에는 비어 있는 행위자가 `₩*&%#@`로 보인다. `custody_events`의 외래키와 제약은 바꾸지 않는다.
4. **정지됨·풀림 소식**: **소식 2종을 보낸다**(운영 로직 15.4의 소식 종류에 이미 있다).
5. (조사에서 정리) 탈퇴 화면의 모양은 채원 사전 판정으로 확정한다. «운영자가 트라이브를 바꿨다» 소식은 6-1(`20261021_1247`, 마이그레이션 261 `tribe_changed`)이 만들므로 이 티켓에서 뺀다.

## 가정 (사용자 확인 대상)

시작 전에 이 가정으로 진행해도 되는지 확인받는다. 다르게 정하려는 항목만 알려 주면 된다.

① **회차는 5개**로 나눈다. 1회 지우기 규칙과 보관 표(DB), 2회 탈퇴 유저 표시와 파기 크론과 문서, 3회 유저용 탈퇴 화면, 4회 그래도 연결하기와 동의 철회, 5회 소식과 피드. 1회와 5회는 DB 변경이 있어 아현이 SQL 파일만 쓰고 카리나가 롤백 실측과 승인 뒤 실행한다.
② **보관 표는 하나**(`retained_records`: 종류, 대상 유저 id(외래키 없음), 내용 json, 보관 만료 시각)로 둔다. 탈퇴하는 순간에만 복사한다. 체크인 방문 기록은 최근 6개월 안의 것만, 부정 이용 탐지 기록은 최근 3개월 안의 것만 복사하고 만료 시각은 각 기록 시각 + 기간이다. 이미 기간이 지난 기록은 복사하지 않는다.
③ **보관 표는 서비스 키로만 읽는다**(RLS 정책 없음, 어드민 화면 없음). 수사 등 요청이 오면 SQL로 조회한다. 만료된 행은 하루 한 번 크론이 지운다(`api/cron/poi-cleanup`과 같은 방식).
④ **지우는 순서**는 (가) 준비 함수(보관 복사, 이력 이름 칸 비우기, 아이템 배지 «없어짐» 처리를 한 트랜잭션으로, 다시 불러도 안전) → (나) 아바타 파일 삭제 → (다) 계정 삭제(`auth.admin.deleteUser`)다. 아바타 파일 삭제가 실패해도 계정 삭제는 멈추지 않고 서버 로그에 남긴다(파일이 남는 것보다 탈퇴가 막히는 것이 더 나쁘다).
⑤ **«없어짐» 처리**: 인벤토리의 아이템 배지는 이력에 «없어짐» 기록을 남기고 소유를 비운다. 일련번호는 다시 쓰지 않는다. 지금 트리거가 남기는 `Orphan` 이벤트와 어떻게 구분할지는 1회 시작 때 아현이 마이그레이션 108과 240을 읽고 정리해 보고한다(새 이벤트 종류가 필요하면 추가만 한다). 주인 없는 아이템 배지 화면(운영 로직 17.4, 테스트 유저 정리용)은 그대로 둔다.
⑥ **유저용 탈퇴**: 본인 데이터 요약(배지·아이템·잼·포인트·연결된 Strava)을 보여 주고 확인 문구를 입력하게 한다. 서버도 문구를 다시 검사한다. 어드민 계정은 거절한다. **이용 정지 중인 유저도 탈퇴할 수 있다**(막으면 오히려 문의가 늘어난다).
⑦ **그래도 연결하기**(4회): Strava 인증을 마친 뒤 연결을 저장하기 전의 안내 시트에서 고른다(운영 로직 3.2절). 인증으로 받은 토큰을 짧은 시간 보관해야 하므로, 4회 시작 때 보관 방식(서버 표에 10분 만료로 보관, 또는 서명된 쿠키)을 설계해 다시 확인받는다. 기존 계정이 어드민이면 거절한다.
⑧ **동의 철회**(4회): 연결 끊기를 위치정보 수집 동의 철회로 본다(운영 로직 3.2절). 약관 342~345줄의 «지체 없이 파기»와 법정 보관(확인자료 6개월)이 충돌하므로, 4회 시작 때 약관과 코드를 대조해 파기 범위를 정하고 다시 확인받는다.
⑨ **소식·피드**(5회): 받지 않은 보상 소식, 정지됨·풀림 소식을 새 종류로 더하고, 피드에 챕터 오름과 컬렉션 등급별 완성을 더한다(운영 로직 15.3, 15.4). «운영자가 트라이브를 바꿨다» 소식은 6-1이 한다.

**2회 가정 (시작 전 확인 대상)**

① **구분 규칙**: 표시는 위 규칙대로 «필수 칸의 `*_user_id`가 NULL이면 탈퇴»로 판정하고, `*_user_id`가 NULL인 칸의 이름 문자열은 값이 있어도 무시한다(옛 이름 13건을 화면에서 가린다).
② **옛 이름 13건은 지운다**: 마이그레이션 `264_clear_withdrawn_custody_usernames.sql`로 `*_user_id`가 NULL인 칸의 `*_username`을 NULL로 비운다(데이터 정리 한 번, 13행, 제약·외래키는 건드리지 않는다). 지우는 것이 목적이라 되돌림 SQL은 없다. 아현은 파일만 쓰고 카리나가 롤백 실측과 사용자 승인 뒤 실행한다.
③ **`Pickup.from` 판정**은 어드민 이력 한정이다. 어드민 페이지가 그 개체의 `poi_drops`를 읽어 `picked_up_at`이 이벤트 시각과 같은 행의 `source`로 가른다. `source = 'user'`면 `₩*&%#@`, 시스템이거나 짝이 없으면 지금처럼 아무것도 그리지 않는다.
④ **소식**: 행위자를 쓰는 5종에서 행위자가 없으면 이름 자리에 `₩*&%#@`를 쓴다. 다른 종류와 프로필 제목의 «익명»은 그대로 둔다. 묶음 소식에서 두 번째 행위자가 탈퇴면 지금처럼 «A님 외 1명»이 된다(문장 정확성은 그대로이므로 건드리지 않는다). 행위자 프로필이 없으므로 이름은 링크가 아니다.
⑤ **드랍**: `source = 'user'`인데 드랍한 유저가 없을 때만 `₩*&%#@`를 쓴다. 시스템 드랍과, 프로덕션에서 조회 대상에서 뺀 스테이징 테스트 계정은 «익명» 그대로다. 인벤토리 이력 시트의 시스템 드랍 «알 수 없는 유저 · 장소 드랍» 표시는 이번에 바꾸지 않는다(후속 티켓).
⑥ **이력 시트**: `picked_up`과 `obtained` 이벤트를 빠뜨리지 않고 `withdrawn` 표시를 달아 `₩*&%#@`로 보인다. `dropped`는 `source`로 시스템과 탈퇴를 가른다.
⑦ **문구**: 이름 자리 텍스트는 `₩*&%#@`이고, 안내 문구 «₩*&%#@님은 탈퇴한 사용자입니다»는 이름 요소의 `title`과 `aria-label`에만 쓴다(누를 곳이 없으므로 링크와 팝업은 만들지 않는다). 사전은 `ko.ts` 한 곳에 둔다.
⑧ **크론**: 기존 `poi-cleanup` 크론에 `purge_expired_retained_records()` 호출을 더한다. 앞의 정리가 실패해도 이 호출을 하고, 이 호출이 실패해도 응답은 200이며 실패 문구만 응답에 싣는다(`abusingLogPurgeError`와 같은 방식).
⑨ **채원 사전 판정은 생략한다**: 새 컴포넌트·토큰이 없고 이름 자리의 글자만 바뀐다. 유형은 `api`, 경로는 표준에서 채원을 뺀 형태다(워크플로 인자 `workType: 'api'`).

- **토큰을 잠깐 보관할 수단**: 암호화(`encrypt`/`decrypt`)는 AES-256-CBC로 변조 탐지가 없고, 서명 코드(`createHmac`)와 서명 전용 비밀 환경변수는 저장소에 없다. 쿠키 선례는 `strava_oauth_state`(httpOnly, lax, 600초, path `/api/strava`)가 있다. 토큰 2개를 암호화해도 약 300자라 쿠키 4KB 안이다(추정). Strava 인증을 한 번 더 돌리는 방식은 `approval_prompt` 기본값(auto)에 기대는데 이 저장소에서는 확인하지 못했다.
- **개인위치정보(좌표)가 저장되는 곳**: ① `users.last_location_lat/lng/at`(직전 픽업 좌표, 부정 이용 방지, 마이그레이션 010), ② `abusing_logs.detail`(GPS 조작 탐지 때 좌표, 3개월 뒤 크론이 삭제), ③ `strava_activities.normalized`의 `startLatLng`·`endLatLng`(쓰기만 하고 읽는 앱 코드가 없다). 방문·드랍·픽업·체크인 기록은 장소 id와 시각뿐이라 좌표가 없다.
- **연결 끊기와 위치정보**: `api/strava/disconnect/route.ts`는 위치정보를 지우지 않는다(Strava 앱 해제, 토큰 비우기, `disconnected_at`·`disconnect_reason = 'user_disconnected'` 저장뿐). 약관 제11조 ①은 철회하면 개인위치정보와 확인자료를 지체 없이 파기한다고 적었고, 제5조 ③은 확인자료를 6개월 이상 보관한다고, 제5조 ④는 다른 법령상 보관은 그 기간 보관한다고 적었다(제11조 ①에는 «다른 법령» 단서가 없다). 약관 안에서 서로 맞서는 지점이다.
- **동의 이력**: 로그인 화면의 «계속하면 … 동의하는 것으로 간주돼요» 문구뿐이고 동의 시각을 저장하는 열은 없다. 철회를 남기는 수단은 `disconnected_at`·`disconnect_reason`뿐이고 재연결 때 지워진다.
- **기존 계정의 특성**: `deleteAccount`는 어드민이면 `admin_account`로 거절하고, 이용 정지 중인 계정은 정지를 검사하지 않아 그대로 지운다. 콜백은 기존 계정의 `user_id`만 읽으므로 어드민·정지 여부를 어디서도 확인하지 않는다. 시트를 보여 주기 전에 막아야 한다.

**4회 채원 사전 판정과 사용자 결정 (2026-10-22)**

채원 사전 판정이 승인 항목 세 가지를 올렸고, 사용자가 모두 추천대로 정했다.

- **버튼 이름**: «그래도 연결하기»를 유지한다(진행 중 라벨 «연결하는 중»). UX 라이팅 가이드 1.3절 «Strava 동기화» 행에 «계정끼리 이어지는 중복 안내 시트의 «그래도 연결하기»는 예외» 한 줄을 더해 용어표와 코드가 어긋나지 않게 한다.
- **막힘 시트(`?strava=duplicate_blocked`)**: «닫기»와 «문의하기»(`d.voc.inquireCta`, `/voc`) 두 버튼으로 간다. 가정 ④의 «취소만»에서 바뀐 부분이다. 막힌 까닭(어드민인지 정지인지)은 문구에 쓰지 않는다.
- **«좌표는 지워져요» 문구**: 문구를 유지하고, 연결 끊기 라우트가 `scrub_user_location`을 한 번 재시도한다(두 번 실패해도 끊기는 성공, 서버 로그). 끊긴 연결을 하루 한 번 쓸어 담는 파기는 후속 티켓 `20261022_0500`으로 분리했다(이번 4회에서는 만들지 않는다).
- 채원 사전 판정의 나머지(재사용, 새 MODULAR 컴포넌트·토큰 없음, 레이아웃·상태·문구 제안)는 워크플로 인자 `reuseDecision`으로 아현에게 넘긴다. 문구 3번 줄은 «지금 계정이 초기화되는 뜻»으로 읽히지 않게 쓰고, 1번 줄은 «동기화돼 있어요»가 아니라 «연결돼 있어요»로 쓴다.

**4회 가정 (시작 전 확인 대상, 가정 ⑦·⑧을 구체화)**

① **토큰 보관(가정 ⑦)**: 서버 표 대신 **암호화하고 서명한 쿠키**에 10분간 담는다. 콜백이 중복을 만나면 토큰·athlete id·로그인한 유저 id·만료를 담은 쿠키(`strava_replace_offer`, httpOnly, lax, path `/api/strava`, secure는 운영에서만)를 굽고 시트로 보낸다. 암호화는 기존 `encrypt`를 쓰고, 변조 탐지는 `ENCRYPTION_KEY`에서 파생한 키로 HMAC-SHA256을 더한다(새 환경변수 없음, DB 변경 없음). 서버 표와 «인증 한 번 더 돌리기» 방식은 쓰지 않는다(전자는 DB 변경과 만료 파기가 필요하고, 후자는 Strava의 재승인 동작을 확인하지 못했다).
② **그래도 연결하기**: 시트에 «취소»와 «그래도 연결하기»(같은 무게)를 둔다. 누르면 `POST /api/strava/replace`가 쿠키를 검증하고(서명, 만료, 쿠키의 유저 id = 로그인한 유저) 기존 계정(해당 athlete를 가진 다른 유저)을 `deleteAccount`로 지운 뒤 새 연결을 저장하고 첫 동기화를 시작한다(`first_sync_pending: true`, 운영 로직 3.2의 «처음부터 다시 시작»). 끝나면 `/profile?strava=connected&reveal=1`로 간다. 삭제와 저장 사이에 실패하면 기존 계정은 이미 지워졌으므로 다시 연결하면 되는 상태가 된다(고정 안내 문구).
③ **Strava 앱 해제 건너뛰기**: `deleteAccount`에 옵션 `skipStravaDeauthorize`를 더하고 이 경로에서만 켠다(같은 athlete의 해제가 새 토큰을 죽이지 않게).
④ **막는 경우**: 기존 계정이 어드민이거나 이용 정지 중이면 «그래도 연결하기»를 주지 않는다. 콜백이 시트로 보내기 전에 기존 계정의 `is_admin`·이메일·이용 정지를 확인해 쿠키를 굽지 않고 `?strava=duplicate_blocked`로 보낸다. 그 시트는 «취소»만 두고 «이 Strava 계정은 지금 연결할 수 없어요. 문의에서 알려 주세요.»라고 안내한다(정지 우회를 막는다, 티켓 `20261021_2241`과 같은 맥락). 실행 때 `POST /api/strava/replace`가 같은 확인을 다시 한다.
⑤ **공용 함수**: 콜백의 연결 저장(137~203줄)을 `lib/strava/connection-save.ts`로 뽑아 콜백과 `replace` 라우트가 함께 쓴다. 기존 콜백 시험이 그대로 통과해야 한다.
⑥ **동의 철회(가정 ⑧) — 파기 범위**: 연결 끊기를 동의 철회로 보고, 끊을 때 **개인위치정보(좌표)만** 파기한다. `users.last_location_lat/lng/at`을 NULL로, 활동의 `normalized`에서 `startLatLng`·`endLatLng` 키를 지운다. 확인자료(좌표 없는 방문·드랍·픽업·체크인 기록)와 부정 이용 탐지 기록(`abusing_logs`, 방침 3개월)은 지우지 않는다. 약관 제11조 ①의 «확인자료 지체 없이 파기»와 제5조 ③④의 6개월 보관이 맞서므로 약관 문구는 이 티켓에서 고치지 않고 법무 확인 티켓 `20260929_1303`에 기록한다.
⑦ **파기 구현**: 마이그레이션 `265_scrub_user_location.sql`(함수 `scrub_user_location(p_user_id)`, service_role 전용, 추가만)을 아현이 파일로 쓰고 카리나가 롤백 실측과 사용자 승인 뒤 실행한다. 연결 끊기 라우트가 끊김 저장 뒤에 부르고, 파기가 실패해도 끊기는 성공으로 두되 서버 로그에 남긴다. 연결 끊기 시트에 «마지막 위치와 활동 좌표는 지워져요» 한 줄을 더한다. 번호 265는 6-4 티켓(`20261021_1250`)이 `265_post_release_*`부터 쓰려고 적어 둔 번호와 겹치므로 6-4는 266부터 쓴다(6-4 티켓에 한 줄 적는다).
⑧ **동의 이력**: 동의 시각 열은 만들지 않는다. 철회 기록은 지금처럼 `disconnected_at`·`disconnect_reason`으로 둔다(재연결 때 지워지는 한계는 티켓 `20260929_1303`의 법무 확인 때 필요하면 다룬다).
⑨ **확인 문구는 쓰지 않는다**: 시트의 두 번째 버튼 누름이 확인이다(운영 로직 3.2는 버튼만 말한다). 시트에는 기존 계정의 이름·정보를 보이지 않는다.
⑩ **유형과 경로**: 유형 `ui`(채원 사전 판정과 사후 리뷰 포함), 표준 경로. DB 변경은 마이그레이션 265 하나다. 시험은 쿠키 봉인·검증, 연결 저장, 교체 라우트(어드민·정지·만료·변조·유저 불일치), 시트 보기, 파기 호출이다.
