# [BadgeEngine] 회차 조건에 회차 판정이 다루지 못하는 키가 끼면 발급이 멈추는데, 저장할 때 알리지 않는다

## 핵심 요약

- 요구사항: 회차 조건(`repeat_count` 등)에 회차 술어가 소비하지 않는 키가 끼면 엔진이 회차를 0으로 처리해서 배지가 발급되지 않는다. 이 사실은 서버 로그(`console.warn`)에만 남고 어드민 화면과 저장 응답에는 없다. 티켓 20261019_1318 2회가 «진행 미지원» 경고를 지우면서 이 사유를 알리던 자리가 사라졌다. 저장할 때 같은 판정으로 알린다.
- 구현 계획: ① `unconsumedRepeatConditionKeys`가 어떤 키를 가려내는지 먼저 정리한다. ② 저장 가드(`badge-condition-guards.ts`)에서 같은 함수로 판정한다(새 규칙을 따로 만들지 않는다). ③ 저장을 막을지 경고만 돌려줄지 정한다. 추천은 경고만이다(미션 조건에서 «판정 못 하는 조건은 저장 허용 후 경고만»으로 정한 선례를 따른다). ④ 경고는 응답 `warning`으로 보내 양식에 보인다.
- 관련 파일: `jam-web/src/lib/badge-engine/repeatOccurrences.ts` 636줄 근처(`unconsumedRepeatConditionKeys`와 `console.warn`, 카리나가 5-8 2회 브랜치에서 확인), `jam-web/src/lib/admin/badge-condition-guards.ts`(저장 가드, 위치는 착수 때 확인), `jam-web/src/app/admin/badges/BadgeConditionSection.tsx`(지운 경고 자리), 시험은 가드와 같은 폴더의 `__tests__`.

## 배경 / 문제 정의

티켓 20261019_1318 2회 구현 과정에서 아현이 알림([주의])으로 보고했고, 게이트(민지)가 범위 밖 발견물로 다시 지적했다.

- 지운 경고에는 «발급이 안 되는» 사유가 하나 들어 있었다. 회차 조건에 회차 술어가 다루지 못하는 키가 끼면 회차가 0이 된다.
- 휴식 2개 이상과 회차를 함께 쓰는 경우는 저장 가드가 이미 막는다(아현 보고).
- 위 키 조합은 저장 가드가 막지 않아서, 어드민은 발급이 되지 않는 이유를 알 방법이 없다(민지 보고, 가드 코드를 카리나가 직접 확인하지는 않았다).

이번 티켓은 경고를 되살리는 것이 아니라, 엔진이 실제로 막는 조합만 엔진과 같은 판정으로 알리는 것이다.

발견: 2026-10-21 티켓 20261019_1318 2회 게이트.

## 상세 요구사항

### 서비스/코드베이스 관점

- 엔진이 막는 조합만 알린다. 엔진과 같은 함수를 쓰고, 어드민 쪽에 규칙을 따로 만들지 않는다.
- 경고 문구는 현상, 원인, 해결책 3단계를 따른다.
- 기존 배지의 조건 JSON을 일괄 점검할 필요가 있는지는 착수 때 판단한다(이미 저장된 조건 중 이 조합이 있는지 읽기 전용으로 센다).

## 완료 기록

### 구현 내용 요약

- 원인: 회차 조건에 회차 판정이 다루지 못하는 키가 끼면 엔진이 회차를 0으로 처리해 배지가 발급되지 않는데, 이 사실이 서버 로그에만 남고 어드민 화면과 저장 응답에는 없었다.
- 저장 가드(`badge-condition-guards.ts`)에 `findConditionShapeSaveWarning`을 더했다. 판정은 엔진의 `unconsumedRepeatConditionKeys`를 그대로 써서 어드민에 키 목록을 따로 두지 않는다. 엔진이 먼저 끝내는 조합(기간 단위 회차, 휴식 키 회차)과 엔진이 평가하지 않는 배지(아이템 배지, JAM! 카테고리)에는 경고를 붙이지 않는다. 휴식 키가 2개 이상인 조합은 기존 가드가 저장을 막는다.
- 저장은 허용하고 경고만 돌려준다. 배지 저장 라우트 POST·PUT의 응답에 `warning`이 담긴다. 경고 문구는 현상, 원인, 해결책 3단계다.
- 양식(`BadgeForm.tsx`, `BadgeConditionSection.tsx`)은 저장 전에 같은 함수와 문구로 조건 영역에 경고를 미리 보인다. 저장 후 목록으로 이동하는 양식이라 응답 `warning`을 화면에 따로 띄우지 않는다(구현 계획 ④의 «응답 warning을 양식에 보인다»와 방식이 다르나 정보는 같다).
- `CONDITION_JSON_SPEC.md` §2.11에 경고 동작과 제외 조합을 더하고 `collectRepeatOccurrences`의 위치를 `repeatOccurrences.ts`로 바로잡았다. fail-closed 절에도 한 줄을 더했다.
- `image-source-reset.test.ts`의 `badge-validation` 모킹이 새 내보내기를 몰라 깨지던 시험 5건을 보강했다.
