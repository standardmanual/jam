# [Feature] JAM2 챕터를 트라이브와 상관없이 «챕터 숫자»로만 표기한다: 챕터 이름 표와 이름 읽기를 걷어낸다

## 핵심 요약

- 요구사항: 사용자가 정책을 바꿨다(2026-10-21). 결정 원문은 «모든 유저의 챕터는 트라이브와 상관없이 '챕터' + 숫자로 표기함»이다. 트라이브별 챕터 이름(50개)을 두지 않는다. 묶음 5의 5-7과 5-8 2회가 만든 이름 읽기, 이름 표시, 이름 표 어드민을 걷어내고 문서를 맞춘다.
- 구현 계획: 2회로 나눈다. 1회는 코드와 문서(서버 읽기, 유저 화면, 어드민, PRD와 계획 문서)이고, 2회는 DB의 `chapter_names` 표 삭제(`db` 유형, 사용자 승인 뒤 카리나가 실행)다. 1회 코드가 배포되어 표를 더 읽지 않는 것을 확인한 뒤에 2회를 한다. 파일 단위 계획은 아래 「구현 계획」에 있다.
- 관련 파일: 아래 「구현 계획」의 파일 목록(서버 `lib/chapter/`, 유저 화면 `components/chapter/`, 어드민 `app/admin/chapter-names/`와 `lib/admin/user-chapter-view.ts`, 문서 `docs/service/prd/chapter/PRD.md` 외).

## 배경 / 문제 정의

2026-10-08의 결정 17-4(트라이브마다 챕터 이름을 붙여 «챕터 3 · 단골»로 보여 준다, 이름 50개)를 사용자가 2026-10-21에 대체했다. 이유는 따로 적지 않았다. 이미 만든 것은 다음과 같다.

- 5-7: 프로필 챕터 줄의 이름 조각(내 프로필 «챕터 3 · 단골», 다른 유저 «트라이브 · 챕터 3 · 단골»), 오름 축하 카드의 이름 줄과 이름을 읽는 `GET /api/chapter/me`.
- 5-8 2회: 어드민 챕터 이름 표(`/admin/chapter-names`, API, 메뉴, 삭제 가드), 유저 상세 챕터 구역의 이름.
- 5-1~5-6: 서버의 `lib/chapter/name.ts`와 `read.ts`의 이름 읽기, DB 표 `chapter_names`(마이그레이션 221).

공용 DB의 `chapter_names`는 0행이다(2026-10-21 읽기 전용 조회). 지울 데이터가 없다. 이름 표를 채운 적이 없으므로 화면에는 지금도 «챕터 3»처럼 숫자만 보이고, 바뀌는 것은 «이름이 생길 자리»를 걷어내는 일이다.

정책 문서는 2026-10-21에 카리나가 먼저 고쳤다: `service-redesign/17 챕터.md`(4·5·6·8절), `10 JAM 2.0 서비스 운영 로직.md`(12장 외 12곳), `service-redesign/04 트라이브, 출신, 레벨.md`(7곳), `09 JAM! 서비스 재설계 진행 노트.md`(17-3~17-5, 5단계 진행). PRD와 데이터 모델은 구현된 사실을 적는 문서라 이 티켓의 코드와 함께 고친다.

## 시작 전에 사용자에게 확인할 것 (가정)

사용자 확인 전에는 아래 가정으로 계획을 썼다. 틀리면 바로잡는다.

- ① 표기는 «챕터 3»(띄어쓰기, 지금 `ko.ts`의 `d.chapter.line.chapter`와 같다). 다른 유저의 프로필 줄은 «트라이브 · 챕터 3»이다.
- ② 오름 축하 카드는 이름 줄만 뺀다(«축하해요! 챕터 3에 올랐어요»는 그대로). 이름만 읽던 `GET /api/chapter/me`는 소비처가 없어져 라우트째 삭제하고, 카드는 호출 없이 바로 열린다.
- ③ 어드민 챕터 이름 표(화면, API, 메뉴)와 시험은 삭제한다. 5-8 2회가 오늘 머지한 것이고 사용자 확인 전이라 되돌릴 데이터가 없다.
- ④ DB 표 `chapter_names`는 1회 코드가 배포되어 읽는 곳이 없음을 확인한 뒤 2회에서 삭제한다(0행, 되돌림 SQL은 표 재생성). 그 사이에는 비어 있는 표가 남는다.
- ⑤ 원고(`tribe-rethink/manuscript/01~06`)의 챕터 이름 후보는 지우지 않고 «쓰지 않음(2026-10-21 결정)»만 덧붙인다.
- ⑥ 유형은 1회 `ui`(채원 사전 판정, 눈에 보이는 변화는 이름 줄 삭제뿐), 2회 `db`다. 어드민 화면은 채원 판정 대상이 아니다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 챕터 숫자의 계산과 오름 처리, 챕터 배지, 캡슐에 채우는 양은 바꾸지 않는다. 바뀌는 것은 이름의 읽기와 표시뿐이다.
- 이름을 읽던 호출이 사라지므로 `getMyChapter`와 `getPublicChapter`의 응답에서 `name`을 뺀다. 공개 프로필 줄에 필요한 트라이브 이름은 남긴다.
- 트라이브 삭제 가드(`TRIBE_REFERENCE_SOURCES`)에서 `chapter_names` 항목을 뺀다. 2회가 끝나 표가 없어지기 전에는 CASCADE로 지워지는 비어 있는 표라 안내가 필요 없다.
- 새 문구는 만들지 않는다. 지우는 변경이다.

### UI/UX 관점

- 내 프로필 챕터 줄은 «챕터 3»과 «다음 챕터까지» 게이지만 보인다.
- 다른 유저 프로필 줄은 «트라이브 · 챕터 3»이다.
- 오름 축하 카드는 이름 줄 없이 제목(«챕터 3에 올랐어요»)만 보인다.
