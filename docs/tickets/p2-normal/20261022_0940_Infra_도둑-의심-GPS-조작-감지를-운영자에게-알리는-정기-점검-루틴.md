# [Infra] GPS 조작 감지(도둑 의심)를 운영자에게 알리는 정기 점검 루틴을 만든다

## 핵심 요약

- 요구사항: 정책 20번 4절과 운영 로직 16.5절은 GPS 조작이 감지되면 «그 픽업을 거부하고, 그 장소를 72시간 차단하고, 기록을 남기고, **운영자에게 알린다**. 운영자가 기록을 보고 정지를 건다»고 정했다. 6-4 2회가 옛 72시간 섀도우밴을 지우면서 앞의 셋(거부, 장소 차단, 기록)은 유지했지만 **«운영자에게 알린다»는 지금 어디에도 없다**(앱 코드에 Slack 알림이 없다). 정기 점검 루틴이 기록을 읽어 `#jam-alert`에 띄우게 한다.
- 구현 계획: ① 읽을 기록: `abusing_logs`(event_type `gps_spoof_detected`, 좌표가 든 `detail`은 알림에 싣지 않는다)와 `poi_blocks`의 새 행(마지막 점검 이후). ② 루틴을 어디서 돌릴지 정한다. **2026-10-07에 예약 루틴이 모두 삭제되어 지금 도는 정기 점검이 없다**(`.claude/skills/jam-work/references/scheduled-jobs.md` 머리말). 루틴을 다시 만들 때 이 알림을 넣을지, 라이브 운영 체계(티켓 `20260930_1450`)의 중단 신호에 합칠지 정한다. ③ 알림 문구는 «누가, 어느 장소에서, 언제, 무엇 때문에»를 운영자가 판단할 만큼만 적고, 좌표와 이메일은 싣지 않는다(위치정보이므로 방침과 맞춘다). ④ 같은 채널로 가는 대량 수령 경보(운영 로직 16.3), 여러 계정 신호(16.6)와 형식을 맞춘다. 운영자가 이 알림을 보고 어드민 «이용 정지»에서 정지를 건다.
- 관련 파일: `jam-web/src/app/api/drops/[dropId]/pickup/route.ts`(감지와 기록 위치, 알림은 앱에 넣지 않는다), `jam-web/src/lib/abusing/abusing-log.ts`, `.claude/skills/jam-work/references/scheduled-jobs.md`(「Slack 알림」 절), `docs/plan/jam2/service-redesign/20 어뷰징과 밴.md` 4절, 운영 로직 16.3·16.5·16.6.

## 배경 / 문제 정의

사용자 결정 4(6-4, 2026-10-21): 옛 도둑 의심 제재의 밴을 지우고 픽업 거부, 장소 차단, 기록은 유지한다. «운영자에게 알린다»는 앱에 Slack을 넣지 않고 정기 점검 루틴이 기록을 읽어 `#jam-alert`에 띄우는 방식으로 별도 티켓에 남기기로 했다. 지금은 GPS 조작이 감지돼도 운영자가 알 수 있는 곳이 없어(공용 DB `abusing_logs` 0건이라 아직 한 번도 없었다), 정지 판단이 기록을 직접 찾아보는 일에 기댄다.

발견: 2026-10-21 티켓 `20261021_1250` 6-4 조사와 결정 4.

## 상세 요구사항

### 서비스/코드베이스 관점

- GPS 조작 감지 기록이 생기면 점검 주기 안에 `#jam-alert`에 알림이 뜬다. 같은 기록은 두 번 알리지 않는다.
- 알림에 좌표, 이메일, 토큰을 싣지 않는다.
- 자동으로 정지를 걸지 않는다(정책 20번 4절).

## 완료 조건

- [ ] 루틴을 돌릴 곳과 주기가 정해져 있고 `scheduled-jobs.md`에 적혀 있다
- [ ] 시험 기록 한 건으로 알림이 한 번만 뜨는 것을 확인했다(공용 DB 쓰기 없이 가짜 데이터로)
- [ ] 알림 문구 예시가 이 티켓에 있다
