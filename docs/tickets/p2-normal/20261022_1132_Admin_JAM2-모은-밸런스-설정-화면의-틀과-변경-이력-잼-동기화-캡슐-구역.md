# [Admin] JAM2 모은 밸런스 설정 화면의 틀과 변경 이력: 잼·동기화·캡슐 구역 (묶음 7, 7-1)

## 핵심 요약

- 요구사항: 운영 로직 19.1의 모은 설정 화면의 틀을 만든다. 컨텐츠별 구역(잼, 동기화, 캡슐, 잠긴 아이템 배지, 인벤토리, 컬렉션과 믹스, 시스템 드랍, 챕터, 배지와 포인트, 어뷰징) 가운데 이 티켓에서는 틀과 **잼·동기화·캡슐 구역**을 만든다. 서버 검증, 확률 값을 바꿀 때의 확인창, 변경 이력(누가 언제 무엇을 어떤 값에서 어떤 값으로 바꿨는지)을 포함한다.
- 구현 계획: 1회 화면 틀, 서버 검증, 변경 이력 표(마이그레이션 271, 추가만)와 저장 API 공용 경로. 2회 잼·동기화·캡슐 구역(`jam_policy`, `capsule_policy`, `capsule_chapter_costs`)과 확률 변경 확인창. 변경 이력은 옛 표에 트리거를 달지 않고 저장 API가 새 이력 표에 쓴다.
- 관련 파일(시작 때 아현이 줄 위치를 확인한다): `jam-web/src/app/admin/`의 `adminNavItems.ts`(메뉴, 0938과 충돌), 새 설정 표 `jam_policy`·`capsule_policy`·`capsule_chapter_costs`(마이그레이션 220~234), 운영 로직 19.1과 18장(확률 변경 때 확률 안내 페이지 반영과 공지)(혜린 조사(2026-10-22), 카리나가 직접 확인하지는 않았다).

## 배경 / 문제 정의

밸런스 수치를 어드민 설정으로 두고 코드 수정 없이 바꾸는 것이 19.1의 요구다. 새 설정 표는 편집 화면이 없다. 화면은 shadcn/ui 표준을 따르고, 구성과 나누는 단위는 이 티켓의 화면 설계에서 정한다. 어드민 화면은 MODULAR 적용 대상이 아니고 채원의 판정 대상도 아니다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 확률이 들어간 값을 바꾸면 확률 안내 페이지에 함께 반영되는지 확인하고, 바꾸기 전 확인창으로 경고한다. 공지하는 수단은 6-4도 확인하지 못했으므로 확인창까지만 한다.
- 동기화 구역은 0개로 둘 수 있는 값을 허용한다(운영 로직 19.1 표).
- 믹스 칸 수(5)와 등급 올리기 재료 수(5)는 코드에 두고 화면에 올리지 않는다.

## 선행과 시작 전 확인

- 선행: 티켓 `20261022_0938` 1회 머지(메뉴 파일 충돌과 옛 드랍 정책 화면 삭제).
- 시작 때 사용자에게 물을 것: 화면 구성(한 화면에 구역을 모두 둘지, 구역별 탭으로 나눌지)을 정한다. 추천안은 시작 때 붙인다.

## 완료 조건

- 설정 화면에서 잼·동기화·캡슐 값을 바꾸면 저장되고 변경 이력에 남는다(시험으로 고정).
- 확률 값을 바꿀 때 확인창이 뜬다.
- 새 표의 값은 마이그레이션 없이 바뀐다.
