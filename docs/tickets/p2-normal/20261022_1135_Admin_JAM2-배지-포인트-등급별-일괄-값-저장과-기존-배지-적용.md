# [Admin] JAM2 배지 포인트 등급별 일괄 값 저장과 기존 배지 적용 (묶음 7, 7-4)

## 핵심 요약

- 요구사항: 운영 로직 19.1의 «배지와 포인트» 구역을 만든다. 배지 포인트의 등급별 일괄 값을 저장하고, 배지 양식(`badges/BadgeForm`)과 아이템북 양식(`itembooks/ItemBookForm`)의 포인트 칸에 이 값이 기본값으로 들어가게 하고, 이미 있는 배지에 적용하는 SQL을 쓴다. 등급별 값을 저장할 자리와 화면이 지금은 없다(혜린 조사(2026-10-22), 카리나가 직접 확인하지는 않았다).
- 구현 계획: 1회. 마이그레이션 272(등급별 값을 저장할 자리 추가, 추가만)와 설정 구역, 양식의 기본값 연결, 기존 배지 적용 SQL(드라이런, 사후 검증, 되돌림). SQL 실행은 사용자 승인 뒤 카리나가 한다.
- 관련 파일(시작 때 아현이 확인한다): `jam-web/src/app/admin/badges/BadgeForm.tsx`, `itembooks/ItemBookForm.tsx`, 운영 로직 10장·11장·14장의 포인트 값. 규모 약 12파일 900줄.

## 배경 / 문제 정의

포인트 칸이 배지·컬렉션·레시피 양식에 흩어져 있어 등급별 일괄 조정이 어렵다. 지금 기존 배지의 포인트를 바꾸면 프로덕션 유저가 받는 포인트가 바로 달라진다(공용 DB).

## 상세 요구사항

### 서비스/코드베이스 관점

- 새 배지는 양식에서 등급별 기본값이 채워진다. 기존 배지에 일괄 값을 적용하는 일은 SQL로 하고 적용 시점은 사용자가 정한다.
- 7-6에서 입력하는 새 배지의 포인트 값과 이 일괄 값이 맞는지 대조한다.

## 선행과 시작 전 확인

- 선행: 7-1.
- **시작 때 사용자에게 물을 것**: 일괄 값을 기존 배지에 적용할 시점. 혜린 추천은 새 배지는 기본값을 바로 쓰고, 기존 배지는 오픈 직전 SQL(마이그레이션 244와 같은 때)에 적용하는 것이다. 지금 적용하면 프로덕션 유저가 받는 포인트가 오늘부터 달라지기 때문이다.

## 완료 조건

- 등급별 값을 저장하면 배지·아이템북 양식의 포인트 기본값이 바뀐다(시험으로 고정).
- 기존 배지 적용 SQL이 드라이런 결과(바뀔 건수)와 사후 검증 쿼리, 되돌림 SQL을 갖추고 있다.
