# [Content] JAM2 트라이브 컨텐츠 입력 1: 컬렉션 50개와 아이템 배지 1,800개 (묶음 7, 7-6)

## 핵심 요약

- 요구사항: 트라이브 재구상 원고(`docs/plan/jam2/tribe-rethink/manuscript/`)의 컬렉션 50개와 아이템 배지 450종 × 4등급(1,800개)을 DB에 넣는다. 같은 이름의 아이템 배지는 4등급 모두 이름이 같고 설명은 등급마다 따로 둔다. 이미지는 빈 이미지로 시작한다. 운동 속성 구간 이름도 원고에 있으면 함께 넣는다(원고 위치는 시작 때 확인한다).
- 구현 계획: 2회. 1회 원고 파서와 대응표(원고 컬렉션 ↔ 기존 컬렉션), 드라이런. 2회 트라이브별 SQL 파일(마이그레이션 273~277)과 적용·사후 검증. 한 번 실행 한도를 넘을 수 있어 트라이브별 파일로 나눈다. 번호는 시작 때 `origin/staging` 기준으로 다시 확인한다. SQL은 아현이 파일로 쓰고, 실행은 사용자 승인과 롤백 실측 뒤 카리나가 한다.
- 관련 파일(시작 때 아현이 확인한다): 원고 `docs/plan/jam2/tribe-rethink/manuscript/`, 컨텐츠 문서 `docs/service/content/`, 운영 로직 19.3·19.4, 정책 `docs/plan/jam2/service-redesign/15 트라이브 컨텐츠 제작.md`(혜린 조사(2026-10-22), 카리나가 직접 확인하지는 않았다). 규모 약 12파일 1,200줄(SQL 제외).

## 배경 / 문제 정의

공용 DB의 컬렉션 100개는 모두 4등급 방식이 꺼져 있다. 새 컨텐츠를 옛 컬렉션에 덮어쓰고 4등급을 켠 채 넣고 넣자마자 켜기로 사용자가 정했으므로(상위 티켓 「사용자 결정」), 입력 즉시 프로덕션 화면에 새 이름과 설명이 보이고 트라이브·컬렉션이 온보딩에도 나타난다.

## 상세 요구사항

### 컨텐츠 관점

- 같은 이름의 아이템 배지는 4등급 이름이 같고 설명만 등급마다 다르다. 아이템 배지 상세는 설명, 일련번호, 획득 이력만 보이고 조건은 적지 않는다.
- 기존 컬렉션 가운데 자리가 확정된 것은 이름을 되도록 살리고 설명은 새로 쓴다. 원고에 자리가 없는 컬렉션은 비활성화한다(비활성화의 적용 시점은 7-7이다).
- 컬렉션은 트라이브마다 3개로 시작해 석 달마다 1개씩 연다. 순서는 사용자가 어드민에서 고르며 운영툴의 예약 공개를 쓸 수 있다(19.4). 이 티켓이 «넣자마자 켠다»를 트라이브마다 3개로 시작하는 규칙과 어떻게 맞출지 시작 때 정한다.

### 서비스/코드베이스 관점

- 이미 장착된 개체가 있는 컬렉션에 4등급을 켜면 꽂힌 등급 정리가 필요하다. **이 티켓의 DB 적용은 7-8(켜기 전 꽂힌 등급 조회) 뒤에 한다.**

## 선행과 시작 전 확인

- 선행: 트라이브 5개 등록과 옛 트라이브 끄기(트라이브 화면의 운영 입력, 사용자). 7-8은 DB 적용 전까지.
- 시작 전 조사: 원고 컬렉션 50개와 기존 컬렉션 100개의 대응표(덮어쓸 것, 끌 것), 덮어쓸 컬렉션의 장착 기록, 1,800행 SQL이 한 번 실행 한도를 넘는지.
- 시작 때 사용자에게 물을 것: 대응표의 확정(어느 옛 컬렉션을 살리고 어느 것을 끌지)과 «트라이브마다 3개로 시작» 규칙과의 관계. 추천안은 시작 때 붙인다.

## 시작 전 조사 결과 (2026-10-22, 카리나, 공용 DB와 원고를 읽기 전용으로 확인)

**요약**
- 원고 컬렉션 50개 가운데 **44개는 기존 컬렉션을 이어받고 6개는 새로 만든다**(비사이드 레코즈 7~10번, 혼자들 9·10번). 44개의 옛 이름은 공용 DB의 컬렉션 이름과 모두 한 건씩 맞는다(원고의 «무명(無名)을 쫓는 야식가들»만 DB에는 한자에 괄호가 없는 «무명無名을 쫓는 야식가들»로 있어 이름이 글자 하나 다르다).
- 이어받는 44개 가운데 **11개는 지금 활성**이고 유저의 장착이 있다(63칸, 유저 3명 안에서). **33개는 이미 비활성**이고 소속 배지 9개가 모두 소프트 삭제 상태이며 장착이 없다. 이어받지 않는 나머지 **56개는 활성 19개**(장착 45칸, 13개 컬렉션)와 비활성 37개다.
- 이어받는 컬렉션의 옛 아이템 배지가 유저 보유로 남은 것은 모두 1,030개다(소프트 삭제 상태인 배지를 가리키는 보유 포함).

**덮어쓸 컬렉션의 장착 기록**(활성 11개, 합계 63칸): 시장 골목의 전설 12칸(유저 2명, 옛 완성 기록 1건), 무명無名을 쫓는 야식가들 11칸(유저 2명, 옛 완성 기록 1건), 생존 배낭의 밑바닥 10칸(유저 3명), 까치의 반짝이는 보물 8칸(유저 1명), 편의점 심야 만찬 4칸(유저 2명), 비 오는 날의 기름 냄새 4칸(유저 1명), 새벽 라이딩 끝의 국밥 4칸(유저 2명), 환상의 꼬치구이 트럭 3칸(유저 1명), 겨울밤의 소박한 온기 3칸(유저 2명), 겨울잠의 안식처 3칸(유저 2명), 위로의 탄수화물 1칸(유저 1명). 옛 완성 기록은 이 둘뿐 아니라 공용 DB 전체에 3건이다. 모두 common 배지만 꽂혀 있어 등급이 여러 개 섞인 유저는 없다.

**장착 63칸을 원고의 옛 배지 처리와 대조한 결과**(원고 6절의 «옛 이름과 처리» 열을 파싱해 옛 배지 이름으로 맞췄다): 옛 배지를 이어 쓰는 것(살림 17칸, 다듬음 4칸) **21칸**, 같은 자리에 내용을 바꿔 쓰는 것(새로 씀 23칸, 사물로 바꿈 6칸) **29칸**, 원고에 옛 배지 이름이 없는 것(옛 배지를 쓰지 않음) **13칸**이다. 13칸은 «생존 배낭의 밑바닥» 8칸을 비롯한 칸으로, 이 컬렉션은 «열쇠고리를 단 가방»으로 바뀌며 살릴 수 있는 옛 아이템 배지가 0~1개뿐이다.

**아이템 배지 단위(원고 6절의 처리 열)**: 이어받는 컬렉션의 450개 가운데 396개(44개 컬렉션 × 9)는 옛 배지 칸이 있다. 이 중 **이어 쓰는 것(살림 66, 다듬음 23) 89개**, 사물로 바꿔 내용이 달라지는 것 166개, 새로 쓰는 것 141개다. 새로 만드는 컬렉션 6개의 54개는 전부 새 행이다. 아이템 배지 행으로 세면 새 행은 이어 쓰는 89개를 뺀 361개의 Common과 450개 × 3등급(Rare, Epic, Mystic) 1,350개를 더해 1,711개가 되고, 이어 쓰는 옛 행 89개는 이름과 설명을 고친다(원고 숫자 기준 계산, 시작 때 DB로 다시 센다).

**이어받지 않는 컬렉션 56개**: 활성 19개 가운데 장착이 있는 13개는 공원 벤치의 포식자(2칸/1명), 다람쥐의 월동 준비(5칸/1명), 은밀한 밤의 무도회(1칸/1명), 골목길 마피아의 회합(3칸/2명), 아스팔트 열기(9칸/3명), 태풍의 눈(1칸/1명), 업힐 끝의 단맛(5칸/2명), 그루터기 살롱의 VIP(2칸/1명), 영하 15도의 호흡(1칸/1명), 도심 숲의 불청객(4칸/2명), 열대야의 극야 갈증(4칸/1명), 그루터기 살롱의 장물들(2칸/1명), 블랙 트랙의 생존자(6칸/2명)로 합계 45칸이다. 이 컬렉션들은 7-7이 «쓰지 않는 컬렉션 끄기»로 비활성화한다(적용은 오픈 직전).

**시작할 때 사용자에게 물을 결정**

1. **옛 배지 행을 어떻게 이어받을지**(컬렉션 덮어쓰기에 이어 배지 단위를 정한다). 추천: **원고가 «살림·다듬음»이라 한 89개만 옛 배지 행을 Common으로 이어 쓰고**(이름·설명을 고치고 보유와 장착이 이어진다), «사물로 바꿈·새로 씀»은 새 행으로 넣고 옛 행은 소프트 삭제 상태로 둔다. 이유: 원고가 «이어 쓴다»고 한 것만 이어지고, 유저가 가진 아이템이 모르는 사이에 다른 아이템으로 바뀌지 않는다. 대안은 옛 행을 모두 덮어쓰기(보유 1,030개와 장착 29칸의 내용이 바뀐다)다.
2. **장착이 있는 이어받지 않는 컬렉션 13개(45칸)**를 비활성화하면 그 유저 화면에서 해당 칸 진행이 보이지 않는다(기록은 남는다). 이 비활성화는 7-7에서 오픈 직전에 한다. 추천: 그때까지 그대로 둔다.
3. **새 트라이브 5개 등록 시점**(선행): 사용자가 트라이브 화면에서 한다. 등록하면 «넣자마자 켜기» 결정에 따라 프로덕션 온보딩에 바로 보일 수 있다.
4. **이어받는 컬렉션의 `tribe_id`를 새 트라이브로 바꾸는 시점**: 옛 트라이브 3개의 활성 컬렉션이 이 순간 새 트라이브로 옮겨진다.

## 사용자 결정 (2026-10-22)

- **옛 아이템 배지 행은 모두 덮어쓴다**(카리나 추천은 «원고가 살림·다듬음이라 한 89개만 이어 쓰고 나머지는 새 행으로 넣고 옛 행은 소프트 삭제»였으나 사용자가 모두 덮어쓰기를 골랐다). 이어받는 44개 컬렉션의 옛 아이템 배지 행 396개를 컬렉션마다 새 아이템 9개와 1:1로 짝지어 Common 행으로 덮어쓰고(이름, 설명, 이미지 칸을 새 값으로), 각 아이템의 Rare·Epic·Mystic 3등급은 새 행으로 넣는다. 새로 만드는 컬렉션 6개의 54개 아이템은 4등급 모두 새 행이다. 새 행은 396 × 3 + 54 × 4 = **1,404개**이고 덮어쓰는 옛 행 396개를 더하면 1,800개다.
- 사용자가 알고 결정한 영향: 이어받는 컬렉션의 옛 배지를 유저가 가진 **보유 1,030개와 장착의 내용이 바뀐다**. 카리나가 결정 뒤에 다시 센 장착 영향은 **63칸 가운데 원고가 이어 쓴다고 한 21칸(살림 17, 다듬음 4)만 같은 아이템이고 나머지 42칸은 다른 아이템 내용으로 바뀐다**(질문 때 말한 29칸에 원고에 옛 배지 이름이 없어 짝을 정해야 하는 13칸을 더한 값이다). 보유 1,030개도 옛 행을 이어 쓰는 89개의 보유분을 뺀 나머지의 내용이 바뀐다(정확한 수는 시작 때 DB로 센다).
- 덮어쓰기라 옛 행은 소프트 삭제하지 않는다. 33개 비활성 컬렉션의 옛 행 297개는 지금 소프트 삭제 상태이므로 덮어쓰면서 소프트 삭제를 풀고(`deleted_at` 비움) 컬렉션을 활성으로 바꾼다.
- 이 결정 때문에 시작할 때 **짝짓기 표**(옛 배지 행 396개 ↔ 새 아이템 396개)를 먼저 만들어 확인받는다. 원고의 «옛 이름과 처리» 열의 옛 이름과 공용 DB 배지 이름이 정확히 맞는 것은 그대로 짝짓고, 맞지 않는 것(장착 63칸 가운데 13칸이 이런 배지다)은 같은 컬렉션 안의 남는 옛 행과 남는 새 아이템을 사용자가 확인한 순서로 짝짓는다.
- 아직 정하지 않은 것은 아래 「시작할 때 사용자에게 물을 결정」의 2~4번이다(이어받지 않는 컬렉션의 비활성화 시점, 새 트라이브 5개 등록 시점, 컬렉션을 새 트라이브로 옮기는 시점).
