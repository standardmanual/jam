# [Content] JAM2 트라이브 컨텐츠 입력 2: 단서 레시피, 등급 올리기 레시피, 쓰지 않는 컬렉션 끄기 (묶음 7, 7-7)

## 핵심 요약

- 요구사항: 단서 레시피 20개와 등급 올리기 레시피 1,350개를 넣고, 원고에 자리가 없는 옛 컬렉션을 끈다. 단서 레시피는 재료와 결과의 컬렉션이 모두 열렸을 때 열고, 운영자가 컬렉션을 열 때 함께 연다(19.4).
- 구현 계획: 1회. 마이그레이션 278~280(번호는 시작 때 다시 확인). 등급 올리기 레시피는 칸 5개와 후보 90종이라 id가 약 60만 개이므로 값을 직접 쓴 SQL이 아니라 DB 안에서 `INSERT … SELECT`로 만든다. 쓰지 않는 컬렉션 끄기는 SQL을 만들되 **적용은 오픈 직전**이다.
- 관련 파일(시작 때 아현이 확인한다): 원고 `docs/plan/jam2/tribe-rethink/manuscript/`, 레시피 표(믹스 정책, `docs/service/content/`), 운영 로직 19.3·19.4(혜린 조사(2026-10-22), 카리나가 직접 확인하지는 않았다). 규모 약 8파일 700줄.

## 배경 / 문제 정의

믹스 화면과 어드민 목록이 약 60만 행에서 느려지는지는 확인하지 못했다. 시작 때 행 수와 조회 계획을 먼저 확인한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 등급 올리기 레시피는 DB 안에서 만들고 드라이런(만들 행 수)과 사후 검증(행 수, 칸 수, 중복 없음)을 갖춘다.
- 쓰지 않는 컬렉션 끄기는 기존 코드가 «새로 발급하지 않음»으로 다루는 방식을 쓴다(소프트 삭제). 이미 받은 기록은 그대로 남긴다.

## 선행과 시작 전 확인

- 선행: 7-6의 DB 적용.
- 시작 때 사용자에게 물을 것: 믹스 화면의 레시피 후보가 약 60만 행이 될 때의 성능을 어디까지 확인할지. 추천안은 시작 때 붙인다.

## 완료 조건

- 단서 레시피 20개와 등급 올리기 레시피 1,350개가 입력됐다(사후 검증 쿼리 결과가 드라이런과 같다).
- 쓰지 않는 컬렉션 끄기 SQL이 롤백 실측을 통과했고 적용 시점이 7-9의 목록에 있다.
