# [Admin] JAM2 컬렉션 4등급 켜기 화면과 켜기 전 꽂힌 등급 정리 (묶음 7, 7-8)

## 핵심 요약

- 요구사항: 컬렉션의 4등급 방식을 켜는 칸과 화면을 만든다. 등급별 보상을 입력하고, 켜기 전에 이미 꽂힌 등급(옛 방식으로 장착된 개체)을 조회해 정리할 수 있게 한다. 티켓 `20261016_2340`이 넘긴 정리 6건도 여기서 처리한다. 지금은 이 칸과 화면이 없다(혜린 조사(2026-10-22), 카리나가 직접 확인하지는 않았다).
- 구현 계획: 1회. 켜기 칸(컬렉션 설정의 4등급 방식 여부), 등급별 보상 입력(`item_book_tier_default_rewards`와 컬렉션별 값), 켜기 전 꽂힌 등급 조회와 정리 동작, 2340이 넘긴 정리 6건.
- 관련 파일(시작 때 아현이 확인한다): 티켓 `20261016_2340`(컬렉션 4등급 구조)의 넘긴 항목, 티켓 `20261022_0939`(옛 컬렉션 구조 축소), `jam-web/src/app/admin/itembooks/`. 규모 약 14파일 1,000줄. DB 변경은 없다.

## 배경 / 문제 정의

공용 DB의 컬렉션 100개는 모두 4등급 방식이 꺼져 있다. 사용자가 7-6에서 새 컨텐츠를 옛 컬렉션에 덮어쓰고 4등급을 켠 채 넣기로 했으므로(상위 티켓 「사용자 결정」), 켜기 전에 이미 장착된 개체를 확인하고 정리하는 동작이 7-6의 DB 적용보다 먼저 있어야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 켜기 전 조회가 컬렉션별로 «꽂힌 개체 수»와 정리가 필요한 건수를 보인다. 정리하지 않고는 켜지 못한다.
- 이미 받은 기록과 장착은 지우지 않는다(정리는 등급 정보를 맞추는 동작이다).

## 선행과 시작 전 확인

- 선행 없음. **7-6의 DB 적용보다 먼저 끝낸다.**
- 시작 때 사용자에게 물을 것: 정리 6건의 내용과 처리 방식(2340의 완료 기록을 먼저 읽고 정한다). 추천안은 시작 때 붙인다.

## 완료 조건

- 컬렉션 4등급 켜기 칸이 화면에서 바뀌고 변경 이력에 남는다.
- 켜기 전 꽂힌 등급 조회가 정확한 건수를 보인다(시험으로 고정).
- 2340이 넘긴 정리 6건이 처리됐거나 처리하지 않는 이유가 기록돼 있다.
