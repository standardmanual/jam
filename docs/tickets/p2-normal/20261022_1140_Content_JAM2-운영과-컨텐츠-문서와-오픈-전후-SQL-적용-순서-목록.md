# [Content] JAM2 운영과 컨텐츠 문서와 오픈 전후 SQL 적용 순서 목록 (묶음 7, 7-9)

## 핵심 요약

- 요구사항: 묶음 7이 끝난 뒤 PRD, 컨텐츠 문서, 데이터 모델을 맞추고, 오픈 직전과 오픈 뒤에 실행할 SQL의 순서를 한 목록으로 만든다. 5-6 계열(액티비티 배지)의 이름과 설명 원고를 누가 언제 쓸지 정리한다.
- 구현 계획: 문서만(카리나 직접). 오픈 전후 SQL 목록에 들어갈 것(오픈 직전): **트라이브마다 컬렉션 10개 가운데 3개만 활성으로 남기고 나머지 7개를 예약 공개로 바꾸는 일**(7-6이 10개를 모두 활성으로 넣는다, 2026-10-22 사용자 결정, 처음 열 3개는 사용자가 고른다), 마이그레이션 244·245·248(액티비티 배지 비활성화와 새 계열 입력, 이 순서), 7-4의 기존 배지 포인트 적용, 7-7의 쓰지 않는 컬렉션 끄기, 출시 뒤 정리 SQL 266~269와 티켓 `20261022_0938`·`0939`의 정리.
- 관련 파일: `docs/service/prd/`의 어드민·컨텐츠 관련 PRD, `docs/service/content/`, `docs/service/prd/02_DATA_MODEL.md`, 운영 로직 19장, 티켓 `20261018_1816`·`20261019_0542`(혜린 조사(2026-10-22), 카리나가 직접 확인하지는 않았다).

## 배경 / 문제 정의

5-6 계열은 판정 키는 있으나 원고에 이름과 설명이 없어 이 계열이 빈 채 출시될 수 있다. 혜린 추천은 오픈 전에 윈터가 쓰고 입력하는 것이다. 적용 순서가 흩어져 있으면 오픈 직전에 순서를 잘못 실행할 수 있다.
