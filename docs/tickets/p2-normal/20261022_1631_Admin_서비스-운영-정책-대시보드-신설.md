# [Admin] JAM! 서비스 운영 정책 대시보드 신설 (/admin/policy-dashboard)

## 핵심 요약

- 요구사항: JAM 2.0 서비스 운영 로직(19장 전체)과 개발 티켓 세부 결정을 망라하는 «서비스 운영 정책 대시보드»를 어드민 «정책 및 밸런스» 최상단에 신설한다.
- 구현 계획: 19장 도메인별 정책 카탈로그(`policiesData.ts`), 실시간 DB 값 조회 및 인라인 수정 API(`PUT /api/admin/policy-dashboard/field`), 검색·필터·점프 네비게이션이 포함된 대시보드 클라이언트 컴포넌트, 어드민 메뉴 등록 및 단위 시험 작성.
- 관련 파일: `jam-web/src/app/admin/policy-dashboard/page.tsx`, `jam-web/src/lib/admin/policyDashboard/`, `jam-web/src/components/admin/policyDashboard/`, `jam-web/src/components/admin/adminNavItems.ts`, `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md`.

## 배경 / 문제 정의

JAM 2.0 기획과 묶음 0~7 개발을 거치며 수많은 서비스 정책, 비즈니스 판정 조건, 속도 및 어뷰징 기준값, 데이터 보관 규칙이 결정됐다. 그러나 현재 어드민에서는 수치 설정이 개별 화면(`balance`, `abusing`, `combine-policy`, `inventory-policy` 등)에 흩어져 있고, 코드에 고정된 중요한 비즈니스 규칙(예: 러닝 20km/h 초과 배제, 10분 최소 활동 시간, 야간 22~05시 제한, 탈퇴 시 6개월 위치정보 보관 등)은 운영자가 한눈에 조망하기 어려웠다. 운영자가 서비스의 모든 도메인 정책을 주제별로 조회·검색하고, DB 기반 설정은 대시보드에서 즉시 수정할 수 있는 단일 관제 화면이 필요하다.

## 사용자 결정 (2026-10-22)

1. **메뉴 및 경로**: «정책 및 밸런스» 메뉴 최상단에 `/admin/policy-dashboard` («서비스 정책 대시보드»)로 신설한다.
2. **범위**: JAM 2.0 서비스 운영 로직(19장 전체)과 개발 티켓의 세부 결정을 기준으로 삼고, 어드민 즉시 수정 가능 / 코드 고정 규칙 / 티켓 세부 결정 / 오픈 전 적용 대기를 구분해 전수 표시한다.
3. **인라인 수정**: 이미 DB 테이블(`abusing_policy`, `jam_policy`, `combine_policy`, `inventory_policy`, `ambient_drop_config` 등)에 있는 수치는 대시보드 카드에서 즉시 수정·저장할 수 있게 연결한다.
4. **UI 기능**: 상단 지표 카드 요약, 성격별 필터 탭(전체/DB 수정 가능/코드 고정/티켓 결정/오픈 전 대기), 19장 빠른 목차 점프, 실시간 키워드 검색, 유저가 겪는 결과 설명, 근거 문서 및 티켓 번호를 표시한다.
