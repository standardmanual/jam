# [Admin] 밸런스 및 시스템 설정 어드민 UI 텍스트 간결화 (UX Writing 가이드 1단계)

## 핵심 요약
- 요구사항: JAM! UX 라이팅 가이드와 슬롭 사전 원칙에 따라, 어드민 내 가장 설명형 문장이 길고 개발자 메모가 노출되어 있던 `abusing`(어뷰징 정책), `balance`(밸런스 설정), `ops-settings`(운영 설정)의 UI 텍스트를 간결화하고 라벨과 힌트로 분리한다.
- 구현 계획: 
  - `AbusingClient.tsx`의 10개 정책 라벨에서 개발 티켓/페이즈 번호 제거 및 간결한 라벨 + 힌트 2단 구조로 리팩터링, 관련 테스트(`AbusingClient.test.tsx`) 동기화.
  - `balance/sections.tsx`의 5개 밸런스 구역 설명문 압축 및 간결화.
  - `opsInbox/balance/settings.ts` 및 `thresholdSettings.ts`의 메타 문장 압축 및 간결화, 관련 테스트 동기화.
- 관련 파일:
  - `jam-web/src/app/admin/abusing/AbusingClient.tsx`
  - `jam-web/src/app/admin/abusing/AbusingClient.test.tsx`
  - `jam-web/src/lib/admin/balance/sections.tsx`
  - `jam-web/src/lib/admin/opsInbox/balance/settings.ts`
  - `jam-web/src/lib/admin/opsSignals/thresholdSettings.ts`

## 배경 / 문제 정의
어드민 설정 화면들에서 `(20260909_1012)`, `(Phase 18)` 등 내부 개발 메모가 노출되고, 라벨 하나에 판정 조건과 시스템 로직이 뭉쳐 있어 관리자가 파라미터의 의미를 직관적으로 파악하기 어려웠다. 이를 해결하기 위해 간결한 명사형 라벨과 단일 힌트 문장으로 정돈한다.

## 상세 요구사항
1. **어뷰징 관리 (`AbusingClient.tsx`)**:
   - `이동 속도 임계값 (km/h) — 이 속도를 초과하면 GPS 조작으로 판단` → 라벨 `이동 속도 임계값 (km/h)`, 힌트 `초과 시 비정상 이동(GPS 조작)으로 판정해요`
   - `하루 누적 이동거리 상한 (km) — 순간 속도는 정상이지만 하루 총 이동거리가 이 값을 넘으면 GPS 조작(느린 텔레포트)으로 판단` → 라벨 `하루 이동거리 상한 (km)`, 힌트 `하루 총 이동거리가 이 값을 넘으면 비정상 이동으로 판정해요`
   - `차량 속도 필터 (km/h) — 이 속도를 초과하는 활동은 배지·아이템 드랍·미션 평가에서 모두 제외 (Phase 18)` → 라벨 `차량 속도 필터 (km/h)`, 힌트 `초과하는 활동은 배지·아이템 드랍·미션 평가에서 제외해요`
   - `교통수단 구간 감지 — 걷기/러닝/자전거 최고속도 임계값 (km/h)` → 간결한 라벨 및 30초 초과 시 대중교통 제외 힌트
   - `종목 불일치` 최소 평균속도 라벨 및 힌트 정돈
2. **밸런스 설정 (`balance/sections.tsx`)**:
   - 잼, 동기화, 캡슐, 잠긴 아이템 배지, 컬렉션과 믹스 5개 구역의 장황한 구어체 설명문을 핵심 수식과 결과 중심의 팩트 문장으로 압축
3. **운영 설정 (`ops-settings`)**:
   - 밸런스 규칙 및 신호 기준값의 불필요한 메타 서술 제거 및 간결화
