# [Admin] 운영설정 신호 기준값 구역 설명 시험이 문구 간결화 뒤 실패한다

## 핵심 요약

- 요구사항: `jam-web/src/app/admin/ops-settings/__tests__/section.test.tsx`의 «신호 기준값 구역 설명은 승인을 막지 않고 바꾼 값만 저장한다는 것과 밸런스 구역 안내를 담는다» 시험이 지금 staging에서 실패한다(`OPS_SETTINGS_SECTIONS[1].description`이 기대한 세 문장과 다르다). 시험을 새 문구에 맞출지, 문구가 잃은 안내를 되살릴지 정한 뒤 시험을 통과시킨다.
- 구현 계획: 문구 변경 의도부터 확인한다. 티켓 `20261022_2055`(어드민 밸런스·어뷰징·운영설정 UI 텍스트 간결화 1단계)가 신호 기준값 구역 설명을 세 문장에서 두 문장으로 줄였고, 시험은 같은 커밋에서 고쳐지지 않았다. 줄이면서 «밸런스 경고의 기준은 「밸런스 규칙」 구역에서 바꿔요.» 안내가 빠졌다.
- 관련 파일: `jam-web/src/lib/admin/opsSignals/thresholdSettings.ts`(신호 기준값 구역 `description`), `jam-web/src/app/admin/ops-settings/__tests__/section.test.tsx`(137줄 부근, 기대 문장 세 개), 원인 커밋 `e146fda47`

## 배경 / 문제 정의

티켓 `20261022_1133`(7-2) 2회 머지 뒤 전체 시험을 돌렸을 때 16,918건 가운데 이 한 건이 실패했다. 7-2 변경은 `ops-settings`와 `opsSignals`를 건드리지 않았고, 같은 파일들이 `e146fda47`과 같은 상태에서 시험이 실패한다. staging push에는 전체 시험 CI가 걸려 있지 않아(티켓 `20260922_0205`) 지금까지 눈에 띄지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 시험이 지키려던 계약은 «설명에 승인을 막지 않는다는 것, 바꾼 값만 저장한다는 것, 밸런스 구역 안내가 있다»는 세 가지다. 간결화로 셋째 안내가 사라졌다면 그 안내가 필요 없다는 결정을 티켓에 남기고 시험을 맞춘다. 필요하면 두 문장 안에 안내를 담는다.
- 같은 유형의 시험(설명 문구를 문자열로 고정한 시험)이 간결화 1단계·2단계의 다른 화면에도 있는지 한 번 훑는다.

## 구현 계획

문구를 정하는 쪽(티켓 `20261022_2055`를 맡은 쪽)과 맞춘 뒤 `thresholdSettings.ts`와 시험 중 한 곳, 또는 둘을 고친다.

## 완료 조건

- `npx vitest run src/app/admin/ops-settings` 전체가 통과한다.
- 밸런스 구역 안내 문장을 두는지 빼는지 결정이 티켓 「주요 의사결정」에 적혀 있다.
