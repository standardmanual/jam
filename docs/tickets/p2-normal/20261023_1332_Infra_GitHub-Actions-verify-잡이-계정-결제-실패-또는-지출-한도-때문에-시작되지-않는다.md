# [Infra] GitHub Actions verify 잡이 계정 결제 실패 또는 지출 한도 때문에 시작되지 않는다

## 핵심 요약

- 요구사항: 2026-10-23 13:22(KST)부터 GitHub Actions의 `verify` 잡이 코드와 상관없이 시작되지 않는다. 잡이 2초 만에 단계 0개로 끝나고, 주석이 «최근 계정 결제가 실패했거나 지출 한도를 올려야 한다»는 뜻이다. **계정 결제 설정을 사람이 풀어야 하는 문제**라 사용자가 GitHub의 «Billing & plans»를 확인해야 한다.
- 구현 계획: 코드 변경은 없다. 사용자가 결제 수단 또는 지출 한도를 풀면 `verify` 런이 다시 도는지 확인하고 이 티켓을 닫는다.
- 관련 파일: `.github/workflows/verify.yml`, 런 `39899967801`(2026-10-23 13:22 KST, 실패), 직전 성공 런 `39898231052`(13:03 KST, 같은 저장소의 다른 브랜치).

## 배경 / 문제 정의

티켓 `20261021_1018`의 게이트(민지)가 발견했다. 카리나가 `gh api`로 같은 사실을 확인했다. 최근 런의 잡 `verify`는 `failure`이고 단계가 0개이며 주석은 다음과 같다: «The job was not started because recent account payments have failed or your spending limit needs to be increased.» 13:03(KST)의 런은 성공했으므로 그 뒤 20분 안에 한도에 닿았거나 결제가 실패한 것으로 보이나, 원인은 계정 설정을 봐야 안다.

그 이전(12:43 KST 안팎) 여러 브랜치의 `verify` 실패는 이 문제가 아니라 최신 staging에서 실패하던 프로필 캡슐 시험 1건 때문이었다(티켓 `20261023_1248`, 이미 고침).

## 영향

- `scripts/verify.sh`를 CI에서 돌리는 `verify`가 게이트 구실을 못 한다. 지금은 게이트(민지)가 `scripts/verify.sh`를 격리 워크트리에서 직접 실행해 대신 판정한다.
- 이 상태가 길어지면 staging과 리뷰 브랜치의 검증이 전부 사람 손과 에이전트의 직접 실행에 기댄다.

## 완료 조건

- [ ] 사용자가 GitHub 결제 설정을 풀었다
- [ ] 새 푸시에서 `verify` 잡이 단계 1개 이상을 실행하고 성공한다

- 2026-10-23 13:44(KST) 런 `39901913163`이 성공했다. 그 전 13:36 런은 `test` 단계까지 실행됐으므로, 결제로 잡이 시작되지 않던 상태는 풀린 것으로 보인다. 사용자가 설정을 바꾼 것인지 한도가 초기화된 것인지는 확인하지 못했다. 사용자 확인을 기다리며 티켓은 열어 둔다.
