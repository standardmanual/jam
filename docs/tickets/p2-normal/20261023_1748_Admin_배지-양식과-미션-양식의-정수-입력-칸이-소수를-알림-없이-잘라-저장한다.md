# [Admin] 배지 양식과 미션 양식의 정수 입력 칸이 소수를 알림 없이 잘라 저장한다

## 핵심 요약

- 요구사항: 정수 입력 칸에 «2.5»를 쓰면 2로, «7.9»를 쓰면 7로, «1e3»을 쓰면 1로 읽혀 저장 전 범위 검사를 통과하고 알림 없이 저장된다. 운영자가 쓴 값과 다른 값이 조용히 저장되지 않도록, 정수가 아닌 입력은 저장 전에 막고 알린다.
- 구현 계획: 정수 읽기 함수가 입력 문자열 전체가 정수인지 먼저 확인하고, 아니면 저장 전 검사에서 칸 이름과 함께 «정수로 입력해 주세요»를 보인다. 착수 때 두 가지를 사용자와 정한다. (1) 막고 알리기와 올림·내림해서 보여 주기 가운데 어느 쪽인지(추천: 막고 알리기). (2) 고치는 범위를 미션 양식에만 둘지 배지 양식까지 넓힐지(읽기 함수가 레지스트리에 있어 배지 양식에도 같은 동작이 있을 가능성이 높고, 배지 쪽은 아직 직접 실측하지 않았다). 정수 칸에 걸린 `inputMode="decimal"`도 숫자 키패드(`numeric`)로 바꾼다.
- 관련 파일: `jam-web/src/lib/badge-engine/conditionRegistry.ts` 469줄 근처(`int`, `parseInt(raw, 10)`), `jam-web/src/app/admin/missions/missionConditionFields.ts` 347줄 근처(`int`)와 범위 검사의 `integerOnly` 분기(폼 경로에서는 도달하지 않는다), `jam-web/src/app/admin/missions/MissionConditionSection.tsx` 565줄 근처(`inputMode`).

## 배경 / 문제 정의

티켓 `20261021_1114` 2회 게이트(민지)가 [정확성/주의]로 남겼다. 게이트가 «2.5»→2, «7.9»→7, «1e3»→1을 직접 실측했다. 원래 있던 동작이고 1회 위임 키 칸에도 같은 읽기 함수가 쓰였다. 저장되는 값은 서버의 «1 이상의 정수» 규칙을 지키므로 잘못된 값이 저장되지는 않는다. 다만 기간 동안 모은 잼 같은 순위 기준 칸에서 운영자가 의도한 값과 다른 값이 조용히 저장될 수 있다. 구현 요약의 «소수도 막는다»는 조립된 `condition_json`을 직접 넘길 때만 성립하고, 입력 칸 경로의 `integerOnly` 분기는 시험도 덮지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 막는 동작은 배지 양식과 미션 양식에서 같아야 한다. 다르게 두면 그 이유를 티켓에 적는다.
- 시험은 입력 칸 경로(문자열 → 읽기 → 범위 검사)를 지나게 쓴다. 조립된 JSON을 직접 넘기는 시험으로는 이 문제를 잡지 못한다.

## 완료 조건

- [ ] 정수 칸에 «2.5»와 «1e3»을 쓰고 저장하면 저장 전에 칸 이름이 든 안내로 막힌다
- [ ] 막는 동작이 배지 양식과 미션 양식에서 같거나, 다른 이유가 기록돼 있다
- [ ] 정수 칸에 숫자 키패드(`inputMode="numeric"`)가 걸린다
- [ ] 입력 칸 경로를 지나는 시험으로 고정돼 있다
