# [Admin] 배지 양식의 조건 칸이 아닌 정수 칸과 미션 양식의 공개 인원·최대 완료 횟수·보상 포인트가 소수나 지수 표기를 알림 없이 다룬다

## 핵심 요약

- 요구사항: 티켓 `20261023_1748`이 조건 칸의 정수 입력을 저장 전에 막도록 고쳤지만, 조건 칸이 아닌 정수 칸이 남아 있다. (1) 배지 양식의 포인트 보상, 패치 가격, 레벨은 `parseInt`로 읽혀 «1e3»이 1로 잘린다(입력 칸이 `type="number"`라 «2.5»는 브라우저 자체 검사가 막을 수 있지만 «1e3»은 올바른 숫자로 보여 통과한다). (2) 미션 양식의 공개 인원, 최대 완료 횟수, 보상 포인트는 `Number(...)`로 읽혀 소수가 그대로 서버로 간다. 서버가 거절하는지는 확인하지 못했다.
- 구현 계획: 먼저 서버가 (2)의 소수를 거절하는지 읽기 전용으로 확인한다. 거절하지 않으면 공용 DB에 소수가 저장될 수 있으므로 우선순위를 올린다. 그다음 1748과 같은 판정 함수와 같은 문구로 이 칸들도 저장 전에 막는다. 칸마다 허용 범위(0 허용 여부 포함)가 달라 착수 때 사용자와 정한다.
- 관련 파일: `jam-web/src/app/admin/badges/BadgeForm.tsx` 481·535·539·559줄 근처(`parseInt`), `jam-web/src/app/admin/missions/MissionForm.tsx` 199·252·257줄 근처(`Number`), 1748에서 만든 `findNonIntegerFormInputs`·`describeNonIntegerInputs`(`jam-web/src/lib/badge-engine/conditionRegistry.ts`).

## 배경 / 문제 정의

1748 게이트(민지)가 [정확성/주의]와 [정확성/참고]로 남겼다. 1748의 범위는 «조건 칸»이라 이 칸들은 건드리지 않았다. 포인트 보상과 패치 가격은 유저 지급·가격에 닿는 값이라 조용히 다른 값이 저장되는 것을 우선 막는다.

## 사용자 결정 (2026-10-24)

- 허용 범위는 추천대로 정했다. 모두 소수와 지수 표기(`1e3` 등)는 저장 전에 막고 조건 칸과 같은 문구로 안내한다.
  - 배지 양식: 포인트 보상 0 이상 정수(빈칸은 0), 패치 가격 0 이상 정수(빈칸은 값 없음), 레벨 1 이상 정수(레벨형 배지에서만).
  - 미션 양식: 공개 인원 1 이상 정수(빈칸은 제한 없음), 최대 완료 횟수 1 이상 정수(빈칸은 제한 없음), 보상 포인트 0 이상 정수(빈칸은 0).

## 구현 계획 (파일 단위, 카리나 작성)

1. 서버 확인(읽기만): `jam-web/src/app/api/admin/missions/route.ts`·`[id]/route.ts`와 배지 저장 API가 위 여섯 칸의 소수를 거절하는지, DB 열 형식(`supabase/migrations`)과 함께 코드로 확인해 완료 기록에 남긴다. 거절하지 않으면 잔여 이슈에 «서버 측 검사 없음»으로 적고 서버 보강은 이 티켓에 넣지 않는다(사용자 결정 필요).
2. 범위 판정 함수: 조건 칸의 `isIntegerFormText`와 `describeNonIntegerInputs`를 그대로 쓰는 작은 함수 하나를 `jam-web/src/lib/admin/` 아래에 더한다(`conditionRegistry.ts`는 이미 2,800줄이라 늘리지 않는다). 칸 이름, 입력 글자, 최소값을 받아 «정수가 아님»과 «최소값 미만»을 구분해 한 문장으로 돌려준다.
3. `jam-web/src/app/admin/badges/BadgeForm.tsx`: 저장 전 검사(481줄 근처 `findHiddenBadgeError` 앞)에 포인트 보상·패치 가격·레벨을 더한다.
4. `jam-web/src/app/admin/missions/MissionForm.tsx`: 저장 전 검사에 공개 인원·최대 완료 횟수·보상 포인트를 더한다(`Number(...)` 읽기 앞에서 글자를 검사한다).
5. 시험: 범위 판정 함수 단위 시험과, 1748의 시험(`conditionFormFields.test.ts`, `missionConditionFields.test.ts`, `condition-registry-integer-fields.test.ts`)이 쓴 입력 칸 경로(글자, 읽기, 저장 전 검사) 방식으로 여섯 칸의 거절과 정상 값을 고정한다.
