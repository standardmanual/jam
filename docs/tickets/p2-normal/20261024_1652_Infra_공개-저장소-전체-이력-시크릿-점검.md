# [Infra] 공개로 전환한 저장소의 전체 이력에 시크릿이 남아 있는지 점검한다

## 핵심 요약

- 요구사항: 저장소가 공개로 바뀌었으므로(티켓 20261023_1332) 현재 파일뿐 아니라 모든 브랜치의 전체 커밋 이력에 시크릿이 남아 있는지 확인한다. 앞서 한 점검은 현재 파일과 얕은 복제(커밋 100개)에 그쳤다.
- 구현 계획: 전체 이력을 내려받아 gitleaks로 점검하고, 탐지 항목은 값을 가린 채 하나씩 분류한다. 프로젝트에서 쓰는 서비스 토큰 형태는 별도 패턴으로 이력을 한 번 더 찾는다.
- 관련 파일: 없음(점검만 했고 저장소 파일은 바꾸지 않았다). 점검 도구는 저장소 밖 작업 폴더에 내려받아 썼다.

## 배경 / 문제 정의

2026-10-23에 사용자가 저장소를 공개로 바꿨다. 공개 저장소는 현재 파일뿐 아니라 이력에 남은 모든 값을 누구나 읽을 수 있다. 이미 이력에 들어간 시크릿은 파일에서 지워도 공개 상태에서는 그대로 읽히므로, 있다면 키를 폐기하고 교체해야 한다. 그래서 공개 직후에 전체 이력을 점검한다.

## 구현 계획

1. `git fetch --unshallow origin`으로 전체 이력을 받는다.
2. gitleaks 8.18.4(공식 릴리스, 체크섬 `sha256sum -c` 일치)를 `--log-opts="--all" --redact`로 실행한다. 값은 보고서에 남기지 않는다.
3. 탐지 항목마다 `git show <커밋>:<파일>`로 줄을 열어 값은 앞 4자와 길이만 남기고 가린 채 성격을 분류한다.
4. 기본 규칙이 놓칠 수 있는 형태를 이력 전체에서 따로 찾는다: 커밋된 `.env` 파일, 인증서·서비스 계정 파일명, JWT 문자열, Supabase 개인 토큰(`sbp_`), GitHub·Slack·Stripe·Vercel·AWS 토큰 형태.

## 완료 조건

- 전체 이력 점검의 탐지 항목이 모두 «실제 시크릿 / 시험·문서 예시 / 판단 불가»로 분류돼 이 티켓에 남아 있다.
- 실제 시크릿이 있으면 폐기·교체가 필요한 항목을 사용자에게 알린다. 없으면 «없음»과 함께 점검하지 못한 범위를 적는다.

### 구현 내용 요약

실제 시크릿은 찾지 못했다. gitleaks는 21건을 탐지했고(`generic-api-key` 19건, `private-key` 2건) 모두 시험 값, 자리표시자, 문서 속 식별자, 개발 도구 세션 기록으로 분류했다. 별도 패턴으로 이력 전체를 찾은 결과도 아래와 같다.

추가 패턴 점검 결과:

- 커밋된 `.env`류 파일은 없었다(`.example`·`.sample`·`.template` 제외).
- `.mcp.json`이 이력에 있었다. 최초 버전(`3eef35cf8`, 2026-07-28)의 토큰 칸은 30자 자리표시자 `SUPABASE_PERSONAL_ACCESS_TOKEN`이었고, 이후 `${SUPABASE_PERSONAL_ACCESS_TOKEN}` 환경변수 치환으로 바뀌었다. 현재는 `.gitignore`에도 들어 있다.
- JWT 형태 문자열(`eyJ...eyJ...`)을 추가한 커밋은 없었다. `sbp_` 토큰 형태도 없었다.
- GitHub·Slack·Stripe·Vercel·AWS 토큰 형태로 걸린 커밋은 2건이었고 모두 Slack 봇 게시 시험의 가짜 값 `xoxb-` + 10자였다(`c4d1963bb`, `39172a872`).

### 주요 의사결정 / 검토한 대안과 미채택 이유
- 도구 선택: gitleaks를 받아 쓰고 저장소에 도입하지 않았다. 정기 점검(CI나 커밋 훅) 도입은 오탐 관리와 비용이 따르는 결정이라 이번 범위에서 뺐다.
- 값 가림: `--redact`로 실행하고 확인할 때도 앞 4자와 길이만 보았다. 시크릿이 있었다면 대화 기록에 남지 않게 하려는 조치다.
- 이력 다시 쓰기·키 교체: 실제 시크릿이 없어 하지 않았다.

### 잔여 이슈
- 점검하지 못한 범위:
  - 병합 제외 커밋 7,947개 가운데 gitleaks가 점검한 것은 7,887개다. 차이 60개 중 43개는 텍스트 변경이 없는 커밋이다(빈 커밋 19, 이진 파일만 바뀐 것 9, 이름·모드만 바뀐 것 15). 나머지 17개는 이유를 확인하지 못했다. 위 «추가 패턴 점검»은 이 17개를 포함한 이력 전체에서 돌렸고 실제 값은 없었다.
  - 이 복제본이 가진 참조(`--all`)만 점검했다. GitHub에만 있는 풀 리퀘스트 참조나 삭제된 브랜치의 객체는 가져오지 못했다.
  - 기본 규칙과 위 패턴 밖의 형태(서비스 고유 키, 개인정보가 담긴 데이터 파일, 운영 전략 문서의 민감한 내용)는 찾지 못할 수 있다. 공개 전환으로 문서가 외부에 보이는 것은 사용자가 정한 사항이다.
- 정기 점검 도입 여부(CI에 gitleaks를 더할지)는 사용자 결정 사항으로 남긴다.
