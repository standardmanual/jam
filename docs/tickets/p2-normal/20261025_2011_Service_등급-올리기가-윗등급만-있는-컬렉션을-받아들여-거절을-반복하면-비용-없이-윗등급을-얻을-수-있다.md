# [Service] 등급 올리기가 윗등급만 있는 컬렉션을 받아들여 거절을 반복하면 비용 없이 윗등급을 얻을 수 있다

## 핵심 요약

- 요구사항: 서버가 «고른 컬렉션에 재료 등급 아이템 배지와 바로 윗등급 아이템 배지가 모두 있는가»를 소각 전에 검사해, 한쪽이 없는 컬렉션은 `invalid_collection`으로 거절한다. 지금은 컬렉션에 재료 등급 아이템은 없고 윗등급만 있으면 같은 등급이 굴려질 때(30%) `no_candidate`로 재료를 소각하지 않고 거절하므로, 거절될 때마다 다시 시도해 비용 없이 윗등급 100%를 얻을 수 있다.
- 구현 계획: `tierUp`의 컬렉션 검사(⑥과 ⑦ 사이)에서 «재료 등급» 후보와 «바로 윗등급» 후보가 모두 있는지 본다. 믹스 화면 목록의 조건(`tierUpCollectionChoices`)과 같은 판정을 서버에서도 강제하고, 둘이 같은 함수를 쓰게 한다. 시험은 한쪽만 있는 컬렉션이 `invalid_collection`으로 거절되고 재료가 소각되지 않는 것을 고정한다.
- 관련 파일: `jam-web/src/lib/combine/tierUp.ts`(198~206행 부근 컬렉션 검사와 `no_candidate`), `jam-web/src/lib/combine/tierUpCollections.ts`, `jam-web/src/app/(main)/combine/tierUpClient.ts`(`tierUpCollectionChoices`), `jam-web/src/lib/drop-engine/syncIssue.ts`(`isIssuableBook`), 시험 `jam-web/src/lib/combine/__tests__/tierUp.test.ts`

## 배경 / 문제 정의

티켓 `20261023_1648`(7-7b) 2회 게이트(민지)의 범위 밖 발견물이다(정확성/주의). 그 티켓의 가정 (다)가 «결과 등급의 후보가 고른 컬렉션에 없으면 소각 전에 거절하고 아래 등급으로 내려가지 않는다»로 정했고, 믹스 화면 목록은 3회 판정(2026-10-23, 사용자 승인)대로 두 등급이 모두 있는 컬렉션만 보인다. 서버는 이 조건을 강제하지 않아 API를 직접 부르면 열려 있다.

2026-10-23 읽기로는 새 트라이브 컬렉션 50개가 4등급 아이템 배지를 모두 갖추고 옛 컬렉션 19개는 Common뿐이어서, 지금 데이터에는 «윗등급만 있는» 컬렉션이 없다. 어드민에서 컬렉션을 새로 입력하거나 아이템 배지를 끄는 과정에서 생길 수 있어 오픈 전에 서버 쪽 조건으로 막는다.

## 완료 조건

- 재료 등급 또는 바로 윗등급 아이템 배지가 없는 컬렉션을 고르면 서버가 소각 전에 `invalid_collection`으로 거절한다.
- 서버 검사와 믹스 화면 목록이 같은 판정 함수를 쓴다.
- 한쪽만 있는 컬렉션으로 반복 요청해도 재료가 소각되지 않고, 윗등급이 나오는 경우가 없다는 시험이 있다.

## 완료 기록

### 구현 내용 요약

등급 올리기 서버가 소각 전에 «고른 컬렉션에 재료 등급과 바로 윗등급 아이템 배지가 모두 있는가»를 검사해, 한쪽이 없으면 `invalid_collection`으로 거절하게 했다. 이전에는 믹스 화면 목록(`tierUpCollectionChoices`)만 두 등급을 요구했고 서버는 열린 컬렉션인지만 봤다. API를 직접 부르면 윗등급만 있는 컬렉션을 고를 수 있었고, 같은 등급이 굴려질 때마다 소각 없이 `no_candidate`로 거절되는 것을 반복해 비용 없이 윗등급을 얻을 수 있었다.

- 서버(`lib/combine/tierUp.ts` ⑥-2)와 화면 목록(`app/(main)/combine/tierUpClient.ts`의 `tierUpCollectionChoices`)이 순수 파일 `lib/combine/tierUpOdds.ts`의 `collectionSupportsTierUp`·`tierUpUpperRarity` 하나를 쓴다. 중복 상수 `NEXT_RARITY`는 지웠다.
- 컬렉션별 등급 계산을 `tierUpCollections.ts`의 `issuableRaritiesByBook`으로 뽑아 목록 만들기(`buildTierUpCollectionOptions`)와 서버가 같이 쓴다. 목록 결과는 바뀌지 않았다.
- `no_candidate` 거절은 방어용으로 남겼고 정상 흐름에서는 도달하지 않는다(정리 여부는 `20261025_2144`).
- 문서: 운영 로직 8.4절, `docs/service/content/COMBINE_RECIPES.md`, `docs/service/prd/probability/PRD.md`, 정책 대시보드 카드 `ch8-tier-up-recipes`의 현재 규칙.
