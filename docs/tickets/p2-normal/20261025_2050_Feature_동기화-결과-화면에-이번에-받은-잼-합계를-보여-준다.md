# [Feature] 동기화 결과 화면에 이번 동기화로 받은 잼의 합계를 보여 준다

## 핵심 요약

- 요구사항: 운영 로직 2장 3번(253줄)과 4장(422줄)은 «동기화 결과 화면에서 이번 동기화로 받은 잼의 합계와 받은 배지, 아이템 배지를 본다. 활동마다 받은 잼은 보여 주지 않는다»고 정한다. 서버는 이미 합계를 돌려주지만(`jamEarned`) 이를 읽어 보여 주는 화면이 없다. 유저는 동기화해도 잼을 얼마 받았는지 알 수 없다.
- 구현 계획: 동기화 응답의 `jamEarned`를 읽는 클라이언트(`app/(main)/profile/ProfileClient.tsx` 321줄 근처에서 `data.earnedBadges`를 처리하는 곳, 응답 타입 37~38줄)와 결과 화면(`components/StravaConnectReveal.tsx` 및 받은 배지 연출)에 «이번에 받은 잼» 한 줄을 더한다. 활동마다의 양은 보여 주지 않는다. 표시 자리와 문구는 시작 때 채원 사전 판정과 사용자 결정으로 정한다.
- 관련 파일: 서버 `jam-web/src/lib/strava/sync.ts`(435줄 응답 타입 `jamEarned: number`, 481줄 초기값), `jam-web/src/lib/jam/settlement.ts`(정산), 응답 시험 `jam-web/src/app/api/strava/sync/__tests__/route.test.ts`(131줄), 문서 `docs/service/prd/01_PRD.md`(«표시 UI는 후속»으로 남은 줄).

## 배경 / 문제 정의

티켓 `20261017_1423`(묶음 2의 2-3)은 응답에 잼 합계 필드만 더하고 «화면 표시는 2-5(결과 캐러셀)와 묶음 3(가진 잼을 보여 주는 자리)에서 한다»고 넘겼다. 그 뒤 묶음 3의 하위 티켓에는 이 표시가 들어가지 않았고, 이를 추적하는 티켓도 없었다. 2026-10-25 적체 티켓을 닫으면서 묶음 2 상위 티켓(`20261017_1420`)을 검토하다 발견했다. 서버 응답 필드는 있으나 읽는 화면 코드는 없다(`grep jamEarned`로 확인, 서버와 시험에만 있음).

관련해 묶음 3의 «가진 잼»을 늘 보이는 자리, 잠긴 개체를 열 때의 포인트 알림과 피드, `capsule_changed` 안내 문구는 사용자 결정이 아직 없다(`20261018_0050` 잔여 이슈). 같은 화면 작업이므로 시작 때 함께 묻는다.

## 상세 요구사항

### UI/UX 관점
- 동기화가 끝난 결과 화면에서 이번 동기화로 받은 잼의 합계를 한 줄로 보여 준다. 합계가 0이면 보이지 않거나 «받은 잼이 없어요» 중 하나로 정한다(시작 때 결정).
- 활동마다 받은 잼은 보여 주지 않는다(운영 로직 4장).
- 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`의 고정 용어를 따른다.

### 서비스/코드베이스 관점
- 서버는 바꾸지 않는다. 응답의 `jamEarned`를 읽어 표시만 더한다.
- 동기화 응답이 `jamEarned`를 빼고 오는 옛 응답에도 화면이 깨지지 않는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 활동이 있는 동기화 뒤 결과 화면에 이번 동기화로 받은 잼의 합계가 보인다. 활동마다의 양은 보이지 않는다.
- `jamEarned`가 없거나 0인 응답에서도 화면이 깨지지 않고, 0일 때의 표시가 결정대로 나온다(시험).
- 너비 320~430px에서 겹침이 없다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- `docs/service/prd/01_PRD.md`의 «표시 UI는 후속» 줄을 구현 결과에 맞게 고친다.

## 완료 기록
### 구현 내용 요약

동기화가 끝난 결과 화면에 «이번에 잼 {n}만큼 받았어요» 한 줄을 더했다. 서버는 바꾸지 않고 응답의 `jamEarned`를 읽어 보여 줄 뿐이다. 티켓 본문은 `ProfileClient`·`StravaConnectReveal`을 말했지만 실제 동기화 결과를 다루는 곳은 `SyncButton`과 배지 연출 오버레이(`BadgeRevealOverlay`)여서 그 둘을 고쳤다.

- 신규 순수 모듈 `lib/strava/sync-result.ts`: `foldJamEarned`가 응답 값을 읽는다(양의 유한 수만 내림, 없거나 0·NaN·음수·문자열은 0). `resolveSyncResult`가 결과 갈래를 정한다.
  - 배지가 1개 이상: 배지 연출 헤더에 잼 줄을 얹는다(`summaryMessage`).
  - 배지 0개, 잼 있음: «동기화 완료» 대신 잼 문구 토스트 한 줄.
  - 배지 0개, 잼 0: 예전 그대로(완료 토스트, 또는 보류 고르기를 먼저 보여 줬으면 화면만 새로 읽기).
- 잼 합계가 0이면 줄 자체를 그리지 않는다. 활동마다 받은 잼은 어느 갈래에서도 보여 주지 않는다(운영 로직 4장).
- `BadgeRevealOverlay`에 선택 prop `summaryMessage`를 더했다. 있을 때만 헤더에 한 줄이 생기고 라이브 리전 문구는 `openedWithSummary`(«배지 {count}개를 획득했어요. {summary}»)로 읽는다.
- 문구 `today.syncJamEarned: '이번에 잼 {n}만큼 받았어요'`. 용어표(UX Writing 1.3)에 «잼 = 받다 / {n}만큼»을 등재했다(획득은 배지·아이템 배지용).
- PRD `01_PRD.md`의 «표시 UI는 후속» 줄과 `02_DATA_MODEL.md`를 구현 결과에 맞게 고쳤다.
