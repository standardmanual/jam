# [Infra] 메인 세션의 DB 쓰기 SQL 실행에서 사용자 승인 단계를 없앤다

## 핵심 요약

- 요구사항: 사용자가 «SQL 승인 없이 클로드가 바로 실행하도록 하고 싶다»고 정했다(2026-10-25). 지금까지는 채팅에서 사용자 승인을 받는 것이 프로덕션 DB 쓰기의 유일한 관문이었다(CLAUDE.md 절대 규칙 6, 티켓 20260924_0625).
- 구현 계획: 승인 단계를 없애고 실행 전 점검(되돌림 SQL 확인, 드라이런, 백업, 롤백 실측)과 실행 직후 확인·보고를 관문으로 삼도록 규칙 문서를 고친다. 클라우드 세션의 Supabase 도구 이름(대문자 S)도 자동 허용 목록에 더한다.
- 관련 파일: `CLAUDE.md` 절대 규칙 6, `docs/agents/orchestrator.md` 4절, `docs/agents/team-operations.md` 권한 표, `.claude/skills/jam-work/SKILL.md` 3단계 4번, `.claude/skills/jam-work/references/handling-rules.md`, `.claude/skills/jam-ship/SKILL.md`, `docs/agents/contract.json` `settings_permissions`, `.claude/settings.json` `permissions.allow`.

## 배경 / 문제 정의

7-4 2회(티켓 `20261022_1135`)에서 아이템 배지 1,701개의 포인트를 바꾸는 SQL 289를 사용자 승인을 받아 실행하려 했다. 승인 뒤 롤백 실측을 한 번에 실행하자 Supabase 서버가 «사용자에게 확인 질문»을 보냈고 60초 안에 답이 없어 호출이 시간 초과로 끝났다. 사용자는 승인 절차 없이 바로 실행하기를 원한다고 정했다.

## 완료 조건

- 규칙 문서(CLAUDE.md 6, orchestrator.md 4절, team-operations.md, handling-rules.md, jam-work/jam-ship SKILL.md, contract.json)가 «승인 없이 바로 실행, 대신 실행 전 점검»으로 서로 맞는다. `bash scripts/verify.sh`가 통과한다.
- `.claude/settings.json`의 `permissions.allow`에 클라우드 연결 이름(`mcp__Supabase__execute_sql`, `mcp__Supabase__apply_migration`)이 있고 계약 검사가 이를 확인한다.

## 완료 기록

### 구현 내용 요약

- 승인 단계 폐지: 메인 세션은 SQL을 사용자 승인 없이 바로 실행한다. 서브에이전트는 이전처럼 파일 작성까지만 한다.
- 승인 대신 지키는 점검(orchestrator.md 4절 «승인 대신 점검으로 실행한다»): 되돌림 SQL 확인, 데이터를 바꾸는 SQL의 드라이런, 바뀌는 행의 백업, 일부러 오류를 내는 문장을 붙인 롤백 실측, 실행 직후 읽기 전용 확인과 영향 범위·건수 보고, 기대 건수와 다르면 멈추고 보고.
- 대량 삭제와 프로덕션 데이터 대량 변경에 있던 «반드시 사용자 확인» 조항은 위 점검을 건너뛰지 않는다는 문장으로 바꿨다. 이 변경이 대량 삭제까지 승인 없이 실행하게 한다는 점을 사용자에게 알렸다.
- 클라우드 세션은 claude.ai 연결 도구(`mcp__Supabase__…`, 대문자 S)를 쓰므로 소문자 이름만 있던 허용 목록에 대문자 두 개를 더하고 계약 검사 `allow_contains`에도 넣었다.
- Supabase 서버가 데이터를 바꾸는 여러 문장에 확인을 되묻는 동작은 서버가 보내는 것이라 저장소 설정으로 끌 수 있는지 확인하지 못했다. orchestrator.md 4절에 현상과 대처(같은 호출을 되풀이하지 않고 사유 보고, 사용자가 claude.ai 연결 설정의 도구 권한을 바꿈)를 적었다.

### 주요 의사결정 / 핵심 메모
- 사용자 결정(2026-10-25): SQL 승인 없이 바로 실행. 범위는 사용자 문장 그대로 «메인 세션의 모든 SQL»로 읽었고, 승인을 다시 받는 예외는 두지 않았다.
- 검토한 대안: (가) 데이터를 바꾸거나 지우는 SQL만 승인 유지, (나) 도구 확인창만 끄고 채팅 승인 유지. 사용자의 문장이 승인 폐지였고 두 안은 그 문장보다 좁아 채택하지 않았다.

### 잔여 이슈
- Supabase 연결이 데이터 변경 SQL 앞에서 보내는 확인 질문은 이 변경으로 없어지지 않을 수 있다. 같은 호출이 막히면 사용자가 claude.ai 연결 설정의 도구 권한을 허용으로 바꾸거나 화면의 확인에 답해야 한다.
- 승인 없는 실행의 위험은 사용자가 받아들였다. 되돌릴 수 없는 삭제는 백업 표 없이는 복구할 수 없으므로 점검 절차의 백업 단계가 유일한 안전망이다.
