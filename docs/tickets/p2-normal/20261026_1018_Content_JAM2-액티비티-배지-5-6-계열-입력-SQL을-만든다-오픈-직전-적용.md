# [Content] JAM2 액티비티 배지 5-6 계열(혼자들 «채워 둔 세제 칸») 입력 SQL을 만든다 (오픈 직전 적용)

## 핵심 요약

- 요구사항: 사용자가 확정한 5-6 계열 «같은 장소에 여러 날 체크인함»(혼자들 «채워 둔 세제 칸», 등급형 3단 Common·Rare·Epic, 같은 장소 체크인 누적 5·20·50일)을 액티비티 배지로 넣는 마이그레이션 SQL 파일을 만든다. 245·248과 같은 방식이다. **파일만 만들고 실행하지 않는다.** 실행은 오픈 직전에 244 → 245 → 248 뒤 사용자 승인으로 한다(오픈 전후 순서 문서 4절 2번).
- 구현 계획: 생성기 `jam-web/scripts/gen-new-activity-badge-families.mjs`를 확장해(예: `--set late`) 원고 `06 액티비티 배지.md`의 2절 5-6 행과 11.5절 5-6 표를 읽어 새 마이그레이션(번호는 시작 때 `origin/staging` 기준으로 정한다. 지금 가장 높은 번호는 290)을 만든다. 245·248의 출력은 한 글자도 바뀌지 않아야 한다(시험이 디스크 파일과 대조한다). 가드(건수, 중복 이름), 되돌림 SQL, 드라이런을 245와 같은 틀로 쓴다. 번호 대조(verifyNumbering)와 재활용 후보 문서(`액티비티 배지 재활용 후보.md`) 2절의 분류가 5-6에 맞는지 확인하고, 없으면 그 문서에 5-6을 «새로 만듦»으로 더한다.
- 관련 파일: `jam-web/scripts/gen-new-activity-badge-families.mjs`와 그 시험, `jam-web/supabase/migrations/245_seed_new_activity_badge_families.sql`·`248_seed_held_activity_badge_families.sql`(선례), 원고 `docs/plan/jam2/tribe-rethink/manuscript/06 액티비티 배지.md`(2절 111줄 근처, 11.5절 5-6), `docs/plan/jam2/service-redesign/액티비티 배지 재활용 후보.md`, 조건 키는 `jam-web/src/lib/badge-engine/`의 «같은 장소 체크인 일수» 판정과 마이그레이션 246·247의 키 목록.

## 배경 / 문제 정의

5-6의 이름과 설명은 2026-10-25에 사용자가 확정해 원고에 넣었지만(계열 55개, 이름 88개, 설명 228개) 입력 SQL이 없다. 5-6이 빠지면 이 계열은 빈 채 출시된다. 포인트는 245·248과 같이 규칙 값(등급형 10·20·50)으로 넣고, 기존 액티비티 배지의 일괄 값 적용(290)과 겹치지 않게 순서를 지킨다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 파일 이름은 `<번호>_seed_activity_badge_family_5_6.sql`처럼 245·248과 같은 이름 규칙을 따른다.
- 활성(삭제되지 않은) 액티비티 배지 수 가드는 5-6 3개를 반영한다. 290의 «390개일 때만 진행» 가드와 어긋나지 않는지 확인한다(290이 5-6 뒤에 적용되면 393개). 어긋나면 290의 기대 수를 어떻게 바꿀지 보고한다(이 티켓에서 290을 고치지 않는다).
- 새 배지가 민지 게이트의 숨김·가지 제약(badges_hidden_*)과 포인트 제약을 어기지 않는다.

### 컨텐츠 관점
- 이름과 설명은 원고 11.5절의 문장을 한 글자도 바꾸지 않고 쓴다. 트라이브는 혼자들이다.
