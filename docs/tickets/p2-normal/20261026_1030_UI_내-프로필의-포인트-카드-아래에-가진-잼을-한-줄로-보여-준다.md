# [UI] 내 프로필의 포인트 카드 아래에 «가진 잼 {n}» 한 줄을 보여 준다

## 핵심 요약

- 요구사항: 묶음 3(`20261018_0050`)에서 사용자 결정이 남았던 «가진 잼을 늘 보이는 자리»를 정한 결과를 구현한다. 사용자가 채원 추천을 승인했다(2026-10-26): **내 프로필의 포인트 카드 바로 아래에 «가진 잼 {n}» 한 줄**을 둔다. 투데이에는 이미 캡슐 위젯이 있어 두지 않는다.
- 구현 계획: 기존 `jam-web/src/components/jam/JamBalance.tsx`를 재사용한다. 내 프로필의 포인트 카드 위치는 시작 때 아현이 확인한다(`jam-web/src/app/(main)/profile/ProfileClient.tsx` 근처). 잔액 데이터는 지갑/원장 읽기를 이미 하는 곳이 있으면 그것을 쓴다. 다른 유저의 프로필에는 보이지 않는다. 화면 작업이라 채원 사전 판정을 받는다.
- 관련 파일: `jam-web/src/components/jam/JamBalance.tsx`, `jam-web/src/app/(main)/profile/ProfileClient.tsx`, 문구 `jam-web/src/lib/i18n/ko.ts`, 잼 원장 읽기 `jam-web/src/lib/jam/`.

## 배경 / 문제 정의

잼 잔액을 늘 보이는 자리가 없어 유저가 지금 가진 잼을 캡슐 시트를 열어야 알 수 있다. 동기화 결과 화면의 «이번에 받은 잼»(`20261025_2050`)은 잔액이 아니라 받은 합계라 `JamBalance`와 섞이지 않게 한다.

## 완료 조건

- 내 프로필에서 포인트 카드 바로 아래에 «가진 잼 {n}»이 보이고 다른 유저의 프로필에는 보이지 않는다.
- 잔액이 0이어도 깨지지 않고, 320~430px에서 겹침과 가로 넘침이 없다.
- 기존 프로필 시험이 통과한다.

## 완료 기록

### 구현 내용 요약

내 프로필의 포인트 행(포인트 숫자와 편집 버튼) 바로 아래에 «가진 잼 {n}» 한 줄을 더했다. 채원 사전 판정은 «재사용, 승인 필요 없음»이다. 기존 `JamBalance`를 props 그대로 쓰고 새 컴포넌트·토큰·문구는 만들지 않았다.

- `ProfileClient.tsx`: `isOwnProfile && capsuleInitial != null && <JamBalance balance={capsuleInitial.balance} />`를 포인트 행의 다음 형제로 두었다. 값은 내 프로필에서만 내려오는 캡슐 상태의 잔액이라 새 읽기가 없다. 잔액 0은 «가진 잼 0»으로 보이고(날숫자 «0» 누수 없음), 읽지 못한 경우(null·undefined)는 줄과 빈 자리가 없다. 읽지 못한 값을 0으로 대신 보이지 않는다.
- 타인 프로필: 서버가 값을 내려주지 않고(`[username]/page.tsx` 무수정) 화면도 `isOwnProfile`로 한 번 더 막는다.
- 갱신: 캡슐을 채우거나 연 뒤 `router.refresh()`로 서버 값이 와서 숫자가 따라 바뀐다. 클라이언트 상태는 없다.
- `JamBalance.tsx` 머리 주석을 «세 곳»에서 «네 곳»으로 고쳤다(코드 무변경). 인벤토리 PRD와 홈피드 PRD의 해당 문장을 갱신했다.

### 주요 의사결정 / 핵심 메모
- 사용자 결정(2026-10-26): 채원 추천안 그대로 내 프로필의 포인트 카드 바로 아래에 한 줄을 둔다. 투데이에는 두지 않는다(이미 캡슐 위젯이 있다).
- 이름, 포인트, 가진 잼 숫자가 모두 24px이고 포인트와 잼이 같은 굵은 링크 색으로 쌓인다. 사용자가 «같은 숫자 문법»으로 정했기 때문에 바꾸지 않았고, 실렌더 캡처에서도 라벨(16px 일반 글자)과 chevron 유무로 구분돼 위계 문제는 보이지 않았다.
- 헤더가 약 20px 늘어 첫 화면에서 통계 탭이 그만큼 내려간다(채원이 허용).
- 누를 수 없는 텍스트로 두었다. 캡슐 시트를 여는 동작을 연결하지 않았다(범위 밖).

### 잔여 이슈
- 서버 조회가 실패해 캡슐 상태가 null이면 캡슐 알약은 클라이언트에서 다시 가져오지만 가진 잼 줄은 다음 서버 갱신(`router.refresh`)까지 나오지 않는다(채원 판정이 허용한 동작).
- `JamBalance`의 숫자 칸이 `break-keep`이라 8자리 이상 잔액은 320px에서 열을 넘칠 수 있다. 7자리까지는 한 줄에 들어오고, 현실 범위(캡슐 필요량이 수백 단위)를 벗어난다.
