# [Infra] 기획 묶음에 기획 제목·기획 이유·에이전트 단계 기록·읽은 트렌드 필드를 더한다

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 제출 묶음에 `title`, 항목별 `rationale`·`highlight`, `routine_run.stages`, `trends[]`를 선택 필드로 받고, 루틴 「시작」 기록 1번을 받는 쓰기 경로를 만든다(PRD §5).
- 구현 계획: 제출 검증(`lib/admin/opsInbox/validate.ts`)에 새 필드 형식 검사를 더하고, 저장 위치를 정해 마이그레이션을 쓴다. 시작 기록은 같은 읽기 토큰으로 받는다. 화면은 만들지 않는다.
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/route.ts`, `jam-web/src/lib/admin/opsInbox/validate.ts`·`constants.ts`, `jam-web/supabase/migrations/198_ops_inbox.sql`(기존 구조), 스펙 `docs/service/prd/admin-boards/PRD.md` §5

## 상세 요구사항

- 모든 새 필드는 선택이다. 없는 묶음(옛 묶음·시험 묶음)도 지금처럼 들어온다.
- 길이 제한: `title` 30자, `rationale.label` 12자, `rationale.note` 120자, 항목당 `rationale` 3개, `highlight` 묶음당 5개.
- `rationale.kind`는 `trend`·`season`·`weather`·`signal`·`pattern` 다섯 값만 받는다. `stages[].stage`는 `plan`·`world_review`·`balance_check`다.
- `trends[].outcome`은 `used`·`held`·`excluded`다. `excluded`면 `outcome_reason`(자동 제외 범주)이 있어야 한다.
- 형식 오류는 지금처럼 묶음을 막지 않고 형식 오류 목록에 쌓는다(기존 동작과 같게).
- 루틴 시작 기록: 주차·시작 시각·에이전트 목록. 같은 주차에 제출이 들어오면 짝지어진다. 3시간 안에 제출이 없으면 「멈춤」으로 판정할 수 있게 저장한다(판정 화면은 2023).

## 완료 조건

- 새 필드를 모두 채운 시험 묶음과 하나도 없는 시험 묶음이 둘 다 제출되고, 저장된 값을 읽기 API로 되읽으면 보낸 값과 같다.
- 길이·값 범위를 넘는 묶음은 형식 오류 목록에 해당 항목이 남는다(단위 테스트).
- 시작 기록을 보낸 뒤 같은 주차 묶음을 제출하면 둘이 이어져 읽힌다(단위 테스트).
- 마이그레이션 파일과 되돌림 SQL이 `jam-web/supabase/migrations/`에 있고 생성 타입이 갱신돼 있다.
