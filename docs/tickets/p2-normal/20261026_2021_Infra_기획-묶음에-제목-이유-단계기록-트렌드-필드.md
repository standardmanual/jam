# [Infra] 기획 묶음에 기획 제목·기획 이유·에이전트 단계 기록·읽은 트렌드 필드를 더한다

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 제출 묶음에 `title`, 항목별 `rationale`·`highlight`, `routine_run.stages`, `trends[]`를 선택 필드로 받고 저장해 되읽게 한다(PRD §5.1·5.2·5.3 앞부분·5.4). 루틴 「시작」 기록은 티켓 20261026_2032가 맡는다(2026-10-26 분할).
- 구현 계획: 아래 「구현 계획」의 파일 단위 표를 따른다. 마이그레이션 1개(`ops_bundles`에 `title`·`trends` 두 칸만 더함), 검증·저장·조회 코드, 테스트, 문서 2곳. 화면은 만들지 않는다.
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/route.ts`, `jam-web/src/lib/admin/opsInbox/validate.ts`·`constants.ts`, `jam-web/supabase/migrations/198_ops_inbox.sql`(기존 구조), 스펙 `docs/service/prd/admin-boards/PRD.md` §5

## 상세 요구사항

- 모든 새 필드는 선택이다. 없는 묶음(옛 묶음·시험 묶음)도 지금처럼 들어온다.
- 길이 제한: `title` 30자, `rationale.label` 12자, `rationale.note` 120자, 항목당 `rationale` 3개, `highlight` 묶음당 5개.
- `rationale.kind`는 `trend`·`season`·`weather`·`signal`·`pattern` 다섯 값만 받는다. `stages[].stage`는 `plan`·`world_review`·`balance_check`다.
- `trends[].outcome`은 `used`·`held`·`excluded`다. `excluded`면 `outcome_reason`(자동 제외 범주)이 있어야 한다.
- 형식 오류는 지금처럼 묶음을 막지 않고 형식 오류 목록에 쌓는다(기존 동작과 같게).

## 구현 계획 (파일 단위, 2026-10-26 카리나 사전 확인)

저장 위치 결정(PRD §5의 「저장 위치는 2021에서 정한다」에 대한 답): 새 테이블을 만들지 않는다. 이미 있는 칸을 최대한 쓴다.

| 필드 | 저장 |
|---|---|
| 묶음 `title` | `ops_bundles.title TEXT NULL` 새 칸 |
| 묶음 `trends[]` | `ops_bundles.trends JSONB NULL` 새 칸 |
| `routine_run.stages[]` | 기존 `ops_bundles.routine_run`(JSONB, 지금은 저장만 하고 그리지 않음) 안에 둔다. 새 칸 없음 |
| 항목 `rationale`·`highlight` | 기존 `ops_bundle_items.original` 안에 둔다(제출 항목 원본). 새 칸 없음 |

| 파일 | 할 일 |
|---|---|
| `jam-web/supabase/migrations/294_ops_bundle_title_trends.sql` (새 파일) | `ALTER TABLE public.ops_bundles ADD COLUMN IF NOT EXISTS title TEXT NULL, ADD COLUMN IF NOT EXISTS trends JSONB NULL`. 되돌림 SQL을 주석으로 싣는다(`db-migration-rules.md` §4). 번호 292·293은 티켓 20261026_2026(Content)이 이미 잡았다. push 직전에 `origin/staging` 기준으로 다시 확인한다 |
| `jam-web/src/types/database.generated.ts` | 아현은 `ops_bundles`의 Row/Insert/Update에 두 칸을 손으로 더한다. 적용 뒤 카리나가 MCP 생성 타입과 대조한다 |
| `jam-web/src/lib/admin/opsInbox/constants.ts` | `OPS_RATIONALE_KINDS`(trend·season·weather·signal·pattern), `OPS_ROUTINE_STAGES`(plan·world_review·balance_check; 기존 `excluded_items[].stage` 값 상수를 재사용), `OPS_TREND_OUTCOMES`(used·held·excluded), 길이 상수(title 30, label 12, note 120, 항목당 이유 3개, highlight 5개) |
| `jam-web/src/lib/admin/opsInbox/validate.ts` | `validateOpsBundle`(603줄 부근)에 `title`·`trends`·`routine_run.stages` 검사, `validateItem`(429줄 부근)에 `rationale`·`highlight` 검사를 더한다. 오류는 지금처럼 필수(fatal)가 아니라 형식 오류 목록(`errors`)에 쌓는다. `highlight`가 묶음에서 5개를 넘으면 경고. `ValidatedOpsBundle`(65줄)에 `title`·`trends` 필드를 더한다 |

| `jam-web/src/lib/admin/opsInbox/query.ts` | 묶음·항목 읽기 타입과 select 목록에 `title`·`trends`를 더하고, 항목의 `rationale`·`highlight`를 `original`에서 꺼내는 읽기 함수를 둔다(화면은 2023·2024) |

| `jam-web/src/app/api/admin/ops-inbox/__tests__/route.test.ts` | 새 필드를 채운 묶음 제출 → insert에 `title`·`trends`가 실린다 |
| `jam-web/src/lib/admin/opsInbox/__tests__/query.test.ts` | 되읽기 사례 |
| `docs/service/prd/ops-tool/PRD.md` §3.1 | 제출 형식 표에 새 필드를 더한다 |
| `docs/service/prd/admin-boards/PRD.md` §5 | 저장 위치 결정을 적고 §5.1·5.2·5.4에 「구현됨」 표지를 붙인다 |

## 주요 의사결정

- 새 테이블 대신 기존 `routine_run`·`original` 칸을 쓴다. 이유: 마이그레이션이 작아지고(칸 두 개 추가, 백필 없음) 확장 마이그레이션이라 옛 코드와 함께 돌아도 안전하다. 미채택: 항목 `rationale` 전용 칼럼. 필터·정렬에 쓸 일이 생기면 그때 더한다.
- 루틴 「시작」 기록(별도 쓰기 경로, 별도 테이블)은 파일 수가 임계값을 넘겨 20261026_2032로 뗐다.

## 완료 조건

- 새 필드를 모두 채운 시험 묶음과 하나도 없는 시험 묶음이 둘 다 제출되고, 저장된 값을 읽기 API로 되읽으면 보낸 값과 같다.
- 길이·값 범위를 넘는 묶음은 형식 오류 목록에 해당 항목이 남는다(단위 테스트).
- 마이그레이션 파일(되돌림 SQL 포함)이 `jam-web/supabase/migrations/`에 있고, 적용 뒤 `ops_bundles`에 `title`·`trends` 칸이 있다(카리나가 읽기 전용 쿼리로 확인). 생성 타입이 갱신돼 있다.
