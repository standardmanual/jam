# [Infra] 기획 묶음에 기획 제목·기획 이유·에이전트 단계 기록·읽은 트렌드 필드를 더한다

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 제출 묶음에 `title`, 항목별 `rationale`·`highlight`, `routine_run.stages`, `trends[]`를 선택 필드로 받고 저장해 되읽게 한다(PRD §5.1·5.2·5.3 앞부분·5.4). 루틴 「시작」 기록은 티켓 20261026_2032가 맡는다(2026-10-26 분할).
- 구현 계획: 아래 「구현 계획」의 파일 단위 표를 따른다. 마이그레이션 1개(`ops_bundles`에 `title`·`trends` 두 칸만 더함), 검증·저장·조회 코드, 테스트, 문서 2곳. 화면은 만들지 않는다.
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/route.ts`, `jam-web/src/lib/admin/opsInbox/validate.ts`·`constants.ts`, `jam-web/supabase/migrations/198_ops_inbox.sql`(기존 구조), 스펙 `docs/service/prd/admin-boards/PRD.md` §5

## 상세 요구사항

- 모든 새 필드는 선택이다. 없는 묶음(옛 묶음·시험 묶음)도 지금처럼 들어온다.
- 길이 제한: `title` 30자, `rationale.label` 12자, `rationale.note` 120자, 항목당 `rationale` 3개, `highlight` 묶음당 5개.
- `rationale.kind`는 `trend`·`season`·`weather`·`signal`·`pattern` 다섯 값만 받는다. `stages[].stage`는 `plan`·`world_review`·`balance_check`다.
- `trends[].outcome`은 `used`·`held`·`excluded`다. `excluded`면 `outcome_reason`(자동 제외 범주)이 있어야 한다.
- 형식 오류는 지금처럼 묶음을 막지 않고 형식 오류 목록에 쌓는다(기존 동작과 같게).

## 구현 계획 (파일 단위, 2026-10-26 카리나 사전 확인)

저장 위치 결정(PRD §5의 「저장 위치는 2021에서 정한다」에 대한 답): 새 테이블을 만들지 않는다. 이미 있는 칸을 최대한 쓴다.

## 주요 의사결정

- 새 테이블 대신 기존 `routine_run`·`original` 칸을 쓴다. 이유: 마이그레이션이 작아지고(칸 두 개 추가, 백필 없음) 확장 마이그레이션이라 옛 코드와 함께 돌아도 안전하다. 미채택: 항목 `rationale` 전용 칼럼. 필터·정렬에 쓸 일이 생기면 그때 더한다.
- 루틴 「시작」 기록(별도 쓰기 경로, 별도 테이블)은 파일 수가 임계값을 넘겨 20261026_2032로 뗐다.

## 완료 조건

- 새 필드를 모두 채운 시험 묶음과 하나도 없는 시험 묶음이 둘 다 제출되고, 저장된 값을 읽기 API로 되읽으면 보낸 값과 같다.
- 길이·값 범위를 넘는 묶음은 형식 오류 목록에 해당 항목이 남는다(단위 테스트).
- 마이그레이션 파일(되돌림 SQL 포함)이 `jam-web/supabase/migrations/`에 있고, 적용 뒤 `ops_bundles`에 `title`·`trends` 칸이 있다(카리나가 읽기 전용 쿼리로 확인). 생성 타입이 갱신돼 있다.
