# [Admin] 운영 상황판 2: 결정 패널·서랍·기획 이유 칩

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 결정 패널(기획 제목, 이유 칩, 이번 기획의 핵심, 종류별로 고르기, 「N건 승인하고 예약」)과 항목 서랍(이유 칩, 미리보기, 「왜 이 기획?」, 검수 결과, 핵심 값, [빼기] [고치기] [이대로 두기])을 만든다(PRD §6.3).
- 구현 계획: 지금 기획 상세(`OpsBundleWorkspace`·`OpsItemDetail` 7블록)를 결정 패널 + 서랍 구조로 바꾼다. 이유 칩 컴포넌트를 하나 만들어 운영 상황판 전체에서 쓴다.
- 관련 파일: `jam-web/src/app/admin/ops-inbox/[bundleId]/page.tsx`, `jam-web/src/components/admin/ops/OpsBundleWorkspace.tsx`·`OpsDecisionWorkspace.tsx`·`OpsItemDetail.tsx`·`OpsItemActions.tsx`, `jam-web/src/lib/admin/opsInbox/itemView.ts`

## 상세 요구사항

- 이유 칩 다섯 종류는 기호와 테두리로 상태 색과 구분한다(PRD §3 원칙 4).
- 핵심 항목(`highlight`)이 없는 묶음은 「확인 필요」 항목을 대신 위에 둔다.
- 「종류별로 고르기」의 체크를 바꾸면 주 버튼의 건수가 바로 바뀐다. 0건이면 버튼이 꺼진다.
- 지금 상세에 있던 제출 원본·결정 기록은 서랍 안 접힘으로 옮긴다.
- 이 티켓은 2022·2031(승인과 예약 합치기의 서버·화면)이 끝난 뒤 시작한다.

## 완료 조건

- 새 필드를 채운 시험 묶음을 열면 제목·이유 칩·핵심 항목이 보이고, 항목을 누르면 서랍에 「왜 이 기획?」이 보인다(로컬 실화면 스크린샷).
- 새 필드가 없는 옛 묶음도 깨지지 않고 열린다.
- 「N건 승인하고 예약」이 2031의 흐름을 그대로 부른다.
- 화면에 두 줄을 넘는 설명 문단이 없다(채원 사후 리뷰 체크).
