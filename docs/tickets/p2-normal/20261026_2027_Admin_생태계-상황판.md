# [Admin] 생태계 상황판: 목표 대비·순환 지도·정책 패널

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 성장 순환과 필드 순환을 마디로 그리고, 마디마다 지표·상태를 보이며, 누르면 해당 정책 목록과 [값 바꾸기]·[개발 요청]을 보인다. 밸런스 목표 대비 주의 이상을 위에 띄운다(PRD §7).
- 구현 계획: 정책 대시보드(`policiesData.ts`)의 항목에 순환 마디 연결을 더하고, 마디별 지표 계산 함수를 만든다. 값 변경은 지금 설정 화면으로 보낸다. [개발 요청]은 2028의 요청 저장을 쓴다.
- 관련 파일: `jam-web/src/app/admin/policy-dashboard/page.tsx`, `jam-web/src/lib/admin/policyDashboard/policiesData.ts`·`types.ts`, `jam-web/src/components/admin/policyDashboard/`, `jam-web/src/app/admin/balance/`, `jam-web/src/app/admin/ops-settings/`

## 구현 계획 (3회차로 나눈다)

큰 티켓이라 회차로 나눈다. 순서: 1회차 = 개발 요청 저장(DB·API), 2회차 = 순환 마디·지표 계산(화면 없음), 3회차 = 화면(생태계 상황판 페이지·운영 홈 구역 이동). 요약은 2,500자 이내다. 어드민 shadcn 부품만 쓴다.

**조사로 알게 된 것 (2026-10-27)**
- 「밸런스 목표」 정책 5개(`policiesData.ts` 1288줄 부근, `ch19-kpi-*`)의 지표 계산·목표·상태는 이미 밸런스 서브 대시보드(`jam-web/src/lib/admin/balanceDashboard/`의 `compute.ts`·`load.ts`·`targets.ts`)에 있다. 목표 대비 칸은 새로 계산하지 않고 그 읽기를 재사용한다.
- 정책 대시보드 항목(`PolicyItem`)에는 마디 연결 칸이 없다. 2회차가 더한다.
- [개발 요청]의 저장소(DB)는 티켓 2028도 쓴다(PRD §8). 생태계 상황판이 먼저 시작되므로 **저장소와 API를 이 티켓 1회차에서 만들고** 2028은 그것을 읽어 보드에 보이는 일만 한다(2028 티켓에 한 줄 적는다).

- 정책 값은 지금처럼 설정값을 읽는다: 이 회차는 `liveValues`를 만들지 않고 3회차 화면이 정책 대시보드 `page.tsx`의 읽기를 재사용한다.

### 3회차: 생태계 상황판 화면과 운영 홈 구역 이동 (3-1 화면, 3-2 구역 이동으로 나눠 두 번 돌린다)

**정한 것 (2026-10-27, 카리나 제안)**

- 주소는 `/admin/ecosystem`이고 사이드바 「밸런스」 그룹 맨 위에 「생태계 상황판」으로 둔다. 어드민 UI는 채원 판정 대상이 아니라 shadcn 부품(`components/admin/ui/`)으로 바로 만든다. 상태는 색만 쓰지 않고 기호와 글자를 함께 쓰고(PRD §3 원칙 2), 인라인 `style`은 쓰지 않는다.
- 화면 위에서 아래로: 머리(제목·한 줄 설명·요약 줄 「주의 이상 N · 읽지 못함 M」) → **목표 대비** → **순환 지도** → **정책 패널**(지도에서 마디를 누르면 그 아래에 열린다) → (3-2에서) 주간 핵심 지표·배지 경제 흐름·통계.
- **마디 선택은 주소 쿼리 `?node=`(마디 ID)로 한다.** 마디는 링크라서 서버에서 그리고, 공유하고 새로 고쳐도 같은 마디가 열린다. 허용 밖 값은 선택 없음으로 본다.
- 지도는 두 줄이다. 성장 순환 6마디가 화살표로 이어지고, 필드 순환은 시스템 드랍·유저 드랍(위아래로 겹침) → 지점 → 픽업 → 인벤토리다. 필드 쪽 인벤토리는 같은 마디의 바로가기이며 누르면 성장 쪽 인벤토리가 선택된다. 선과 SVG 화살표는 그리지 않고 글자 화살표(→)만 쓴다. 좁은 화면에서는 줄바꿈된다.
- 마디 카드: 이름, 상태(기호+글자), 대표 지표 값(단위 붙인 글자), 보조 값, 기간 글자(`NODE_PERIOD_TEXT`). 밸런스 마디는 부족이면 「표본 N/M명」처럼 부족 사유를 한 줄 더 쓴다.
- 목표 대비 줄: 5개 정책마다 제목, 칸별 현재 값·목표 글자·상태, 목표 표시선(SVG 막대에 `markerOf` 비율로 목표 범위 띠와 현재 값 표시, 값이 없으면 막대 없이 「부족」). **주의·중단 줄이 맨 위**로 올라온다(정렬 규칙은 순수 함수).
- 정책 패널: 선택한 마디의 정책을 `policiesOfNode` 순서(설정값 → 코드 고정 → 그 밖)로 보인다. 설정값 정책은 현재 값(`liveValues`, 정책 대시보드와 같은 읽기)과 [값 바꾸기](`adminLink.href`로 이동)를, 코드 고정 정책은 [개발 요청]을 둔다. 이미 열린 요청이 있는 정책은 버튼 대신 「요청 N번 접수됨」과 [접기]를 보인다. 마디가 없는 정책은 맨 아래 「순환 밖 정책 N개」 접힘 목록(`policiesOutsideLoop`)에 둔다.
- [개발 요청]은 대화상자(제목은 정책 제목으로 채움, 내용 선택 입력)에서 `POST /api/admin/dev-requests`(`origin: 'eco'`, `policyId`)를 부른다. 409면 「같은 정책의 요청 N번이 이미 열려 있어요」를 보이고, 400·네트워크 오류는 [현상]→[원인]→[해결] 한 줄로 보인다. 성공하면 토스트와 함께 그 줄이 「요청 N번 접수됨」으로 바뀐다.
- API 변경: 세션용 `GET /api/admin/dev-requests` 응답에 `id`를 더한다(1회차 게이트 참고). 읽기 토큰 응답에는 `id`를 싣지 않는 규칙을 지킨다(토큰 요청 판별은 `isAdminReadTokenRequest`).
- **「상단 바 숫자」는 만들지 않는다.** PRD §7의 「상단 바 숫자에 더한다」를 조사했더니 지금 어드민에는 상단 바 숫자가 없고(`AdminHeader`는 제목과 이메일뿐), 숫자를 달면 모든 어드민 화면이 매번 지표를 읽게 된다. 대신 이 화면의 요약 줄에 개수를 쓴다. PRD §7 문장을 이에 맞게 고친다.
- 이동할 구역 3개는 같은 모양으로 옮긴다: `?trend=`는 `/admin/ecosystem?trend=`가 읽고, 운영 홈에서는 빼며, 서비스 점검·신호·최근 이력은 남는다(PRD Q3).
