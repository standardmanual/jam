# [Admin] 트렌드에서 새 체크인 지점을 만드는 7번째 예약 대상

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 에이전트가 트렌드에서 찾은, 아직 없는 장소를 「새 지점」으로 기획하면, 승인할 때 지점을 만들고 홈피드 카드와 함께 공개한다(PRD Q1).
- 구현 계획: 결정이 나면 예약 대상 레지스트리에 지점 핸들러를 더한다(지점을 꺼진 상태로 만들고 공개 시각에 켠다). 카드가 새 지점을 가리키는 연결 그룹을 쓴다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/execute/registry.ts`·`constants.ts`, 지점(POI) 생성 서버 함수, 스펙 `docs/service/prd/ops-tool/PRD.md` §8, `docs/service/content/POI.md`

## 결정 대기 (사용자)

- 추천: 더한다. 지점은 꺼진 상태로 만들고 공개 시각에 켠다. 위치·반경은 에이전트 제안을 운영자가 서랍에서 확인한다.
- 대안: 더하지 않는다. 새 지점은 운영자가 지점 화면에서 직접 만들고, 에이전트는 이미 있는 지점만 소개한다.
- 고려할 점: 체크인 성립 판정과 지점 데이터 품질(좌표 오차, 사유지)은 사람이 확인해야 한다.

## 완료 조건

- 결정과 근거가 이 티켓과 PRD §11에 적혀 있다.
- (더하기로 하면) 「새 지점」 항목과 그 지점을 가리키는 카드를 함께 승인하면 지점이 공개 시각에 켜지고, 카드 생성이 실패하면 지점도 되돌려진다(단위 테스트 + 로컬 실화면).
