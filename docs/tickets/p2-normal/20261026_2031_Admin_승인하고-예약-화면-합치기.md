# [Admin] 「승인하고 예약」 한 번으로 끝나는 화면 (2022의 화면 쪽)

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 승인과 예약 등록의 화면을 「N건 승인하고 예약」 버튼 하나로 합친다(D1). 서버 쪽은 20261026_2022가 먼저 끝나 있어야 한다.
- 구현 계획: 요약창(사전 점검 + JAM! 배지 소급 수)을 확인 단계로 살리고, 창을 열 때 `dryRun + approve`로 검토중 항목까지 점검한 뒤 확인하면 `itemIds + approve`로 실행한다. 지금의 「승인하기」 「N개 승인하기」 「예약 등록하기」 버튼과 확인창을 걷어낸다. 반려와 수정은 그대로다.
- 관련 파일: `jam-web/src/components/admin/ops/OpsExecuteBundle.tsx`(286줄), `OpsBulkApprove.tsx`(182줄), `OpsItemActions.tsx`(233줄), `executeClient.ts`, `OpsBundleWorkspace.tsx`·`OpsDecisionWorkspace.tsx`, `jam-web/src/lib/admin/opsInbox/executeView.ts`(`executeButtonLabel` 등 라벨), 스펙 `docs/service/prd/admin-boards/PRD.md` §6.3, `docs/service/prd/ops-tool/PRD.md` §7.3·§8

## 선행 조건

20261026_2022(서버: `execute` 경로의 `approve`·`includeReviewing`)가 끝나고 staging에 올라가 있다.

## 상세 요구사항

- 버튼 이름은 「N건 승인하고 예약」이다. N은 승인 대상(검토중 + 이미 승인된 예약 가능 항목) 수다. 0이면 꺼진다.
- 요약창은 지금 구역 구성(예약할 항목, 연결 기다리는 항목, 예약할 수 없는 항목, 실패로 닫을 항목, 경고, 배지 소급 수)을 유지하되 문장은 한 줄 이내로 줄인다(PRD §3 원칙 5).
- 패턴 제안 항목은 지금처럼 승인 즉시 종료이고 요약창에 들어가지 않는다.
- 항목 서랍(OpsItemActions)의 개별 「승인하기」는 없애고 [빼기]·[고치기]는 남긴다. 결정 패널 전체 개편은 20261026_2024가 한다. 이 티켓은 버튼과 확인 흐름만 바꾼다.
- 검토중 항목이 요약창 안에서 「승인할 항목」으로 구분되어 보인다.

## 구현 계획 (파일 단위, 2026-10-26 카리나 사전 확인)

현재 구조(읽어서 확인): `OpsDecisionWorkspace.tsx`의 `barAction`이 `OpsBulkApprove`(「N개 승인하기」, 체크한 항목)와 `OpsExecuteBundle`(「N개 예약 등록하기」, 승인된 예약 가능 항목) 두 버튼을 나란히 그린다. 체크박스(`rowLead`·`listHeader`)로 승인 대상을 고른다. 서버는 2022에서 `approve: true`를 받도록 끝났다(`dryRun`은 검토중 항목 전부를 점검하고, 실행은 `itemIds`로 받은 항목만 처리한다).

결정한 화면 동작:
- 버튼은 하나다: 「N건 승인하고 예약」. N = 체크한 검토중 항목(패턴 제안 제외) + 이미 승인돼 예약을 기다리는 항목(`execution.readyCount`). 이미 승인돼 남은 항목도 함께 세므로 2022의 동시 처리로 남은 「승인됨」 항목이 다음 번에 이어서 예약된다. 0이면 꺼진다.
- 누르면 요약창이 열린다. 열 때 `{ dryRun: true, approve: true }`를 보내 그 결과로 그린다. 요약이 곧 확인이다(확인창을 한 번 더 두지 않는다). 요약창의 주 버튼은 「N건 승인하고 예약」이고, 누르면 `{ itemIds, approve: true }`를 보낸다. `itemIds` = 요약의 「예약할 항목」 중 (이미 승인된 항목 + 체크한 검토중 항목). 체크하지 않은 검토중 항목은 `itemIds`에 넣지 않는다(서버가 연결 그룹이 모자라면 「연결 기다리는 항목」으로 둔다).
- 요약창에 「승인할 항목」 표시(2022의 `approving`)를 더한다. 실패로 닫을 검토중 항목은 요청 `itemIds`에 없어도 승인된다(2022 규칙)는 점이 눈에 보이게 「실패로 닫을 항목」 구역에서 같이 보여 준다.
- 패턴 제안 항목은 예약 대상이 아니다. 항목 서랍의 승인 버튼은 **패턴 제안에만** 남기고 이름을 「패턴 사전에 넣기」로 바꾼다. 그 밖의 종류에는 개별 승인 버튼이 없다. [반려]·[수정하기]는 그대로다.
- 일괄 승인 컴포넌트(`OpsBulkApprove`)는 화면에서 쓰지 않는다. 쓰이지 않는 코드와 테스트를 지운다(`decisions` 라우트의 `approve`·`bulk_approve`는 서버에 남긴다).

## 주요 의사결정

- 체크박스 선택은 그대로 둔다. 승인 대상을 고르는 방법을 바꾸지 않고 두 버튼만 하나로 합친다. 결정 패널 전체 개편은 20261026_2024가 한다.
- 개별 항목의 단독 승인(패턴 제안 제외)은 없앤다. 한 건만 승인하려면 나머지 체크를 풀고 같은 버튼을 쓴다.
- 요약창이 확인 단계라는 구조는 그대로다(JAM! 배지 소급 지급 수를 보여 주는 안전장치를 유지).

## 완료 조건

- 화면에 「예약 등록하기」·「승인하기」·「N개 승인하기」 문구가 남아 있지 않다(문구 검색 + 컴포넌트 테스트).
- 로컬 `next dev`에서 시험 묶음이 아닌 묶음으로 「N건 승인하고 예약」 → 요약창 → 확인을 눌러 항목이 「예약됨」이 되고 자원이 공개 전 상태로 생긴 것을 확인한다(카리나, 메인 트리 실렌더 + DB 대조).
- 사전 점검 실패 항목은 확인 전에 요약창에서 이유와 함께 보이고, 확인해도 실패 항목은 만들어지지 않는다(컴포넌트 테스트).

- 「N개 승인하기」와 「N개 예약 등록하기」를 「N건 승인하고 예약」 버튼 하나로 합쳤다. 요약창(사전 점검·「승인할 항목」·JAM! 배지 소급 지급 수)이 확인 단계이고 확인하면 `{ itemIds, approve: true }`로 승인과 예약이 한 번에 일어난다. 체크하지 않은 검토중 항목은 `itemIds`에서 뺀다.

### 주요 의사결정 / 핵심 메모
- 체크박스 선택은 그대로 두고 버튼만 합쳤다. 개별 항목 단독 승인(패턴 제안 제외)은 없앴다.

### 잔여 이슈
- 승인과 예약이 한 번에 일어나면서 「이미지 만들 시간」이 사라졌다 → **20261026_2034**(첫 실제 묶음 전에 끝낸다).
