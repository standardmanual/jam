# [API] 루틴 「시작」 기록 경로와 멈춤 판정 (토큰 쓰기 2번 중 첫 번째)

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 주간 루틴이 시작할 때 보내는 「시작」 기록 1번을 받아 저장하고, 같은 주차 묶음이 제출되면 이어 읽히게 한다. 3시간 안에 제출이 없으면 「멈춤」으로 판정할 수 있게 한다(PRD §5.3, D2). 20261026_2021에서 떼어 냈다.
- 구현 계획: 새 테이블 `ops_routine_starts`와 토큰 쓰기 경로, 제출 때 짝짓기, 멈춤 판정 순수 함수. 화면은 만들지 않는다(그리는 곳은 20261026_2023).
- 관련 파일: `jam-web/src/lib/admin/opsInbox/auth.ts`(`requireOpsInboxSubmit`, 토큰 쓰기 예외), `jam-web/src/app/api/admin/ops-inbox/route.ts`, 새 `jam-web/src/app/api/admin/ops-inbox/routine-start/route.ts`, 새 `jam-web/src/lib/admin/opsInbox/routineStart.ts`, `.claude/skills/jam-work/references/scheduled-jobs.md`(「예약 실행은 DB 쓰기를 하지 않는다」 예외 문장)

## 선행 조건

20261026_2021(`routine_run.stages` 검증과 저장)이 끝나 있다.

## 상세 요구사항

- 저장: `ops_routine_starts(id, run_key unique, week, author, agents jsonb, started_at, bundle_id → ops_bundles ON DELETE SET NULL)`. 마이그레이션 번호는 만들 때 `origin/staging` 기준으로 다시 확인한다(292·293은 티켓 20261026_2026 Content가 잡았고 294는 20261026_2021이 잡았다).
- 제출 때 묶음의 `routine_run.run_key`가 시작 기록과 같으면 `bundle_id`를 채운다. 시작 기록이 없는 제출은 그대로 받는다.
- 멈춤 판정: `started_at`에서 3시간이 지나도 `bundle_id`가 비어 있으면 멈춤. 기준 시간은 운영 설정 값으로 읽을 수 있게 상수 한 곳에 둔다.
- 토큰 쓰기 예외는 이 경로 하나만 더한다. 관리자 로그인 세션도 통과한다.
- `scheduled-jobs.md`의 「예약 실행은 DB 쓰기를 하지 않는다」 문장에 받은 기획함 제출 예외로 「시작 기록」을 함께 적는다(스펙 문서 수정은 카리나).

## 완료 조건

- 시작 기록을 보낸 뒤 같은 `run_key`의 묶음을 제출하면 둘이 이어져 읽힌다(단위 테스트).
- 시작 후 3시간이 지난 미연결 기록은 멈춤으로, 3시간 안은 진행 중으로 판정된다(순수 함수 단위 테스트).
- 시작 기록 없이 제출한 묶음도 지금처럼 저장된다.
- 마이그레이션(되돌림 SQL 포함)이 있고 적용 뒤 테이블이 존재한다(카리나 확인).
