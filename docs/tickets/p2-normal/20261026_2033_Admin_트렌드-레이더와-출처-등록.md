# [Admin] 트렌드 레이더와 트렌드 출처 등록

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 운영자가 트렌드 출처(해시태그·채널·검색어 추이·직접 올린 자료)를 어드민에 등록하고, 루틴이 읽은 트렌드와 결과(반영·보류·자동 제외)를 운영 상황판에서 본다(D5, PRD §6.4).
- 구현 계획: 출처 저장소를 정하고(PRD Q2, 추천은 DB), 출처 추가·끄기 화면과 루틴용 읽기 API(읽기 토큰)를 만든다. 읽은 트렌드는 2021의 `trends[]`를 모아 그린다.
- 관련 파일: `jam-web/src/app/api/admin/`(새 경로), `jam-web/src/app/admin/`(운영 상황판), `docs/operations/inbox/trends/README.md`, 스펙 `docs/service/prd/content-automation/PRD.md` §10

## 구현 계획 (2회차로 나눈다)

DB가 들어가는 티켓이라 회차를 나눈다(1회차 = DB·API, 2회차 = 화면). **PRD Q2 결정(2026-10-27, 카리나가 추천안 채택): 트렌드 출처 목록은 DB에 둔다.** 어드민에서 바로 고치고 루틴이 읽기 토큰으로 읽는다. 근거는 저장소 문서(커밋·push가 있어야 반영)보다 DB가 「켜기·끄기」를 즉시 반영하고 루틴이 매번 최신 목록을 읽기 때문이다. 요약은 2,500자 이내다.

### 1회차: DB·API (화면 없음)

1. `jam-web/supabase/migrations/296_ops_trend_sources.sql` (새, 이 파일은 아현이 **작성만** 하고 실행은 카리나가 한다. 머리 주석은 `295_ops_routine_starts.sql`과 같은 형식): `public.ops_trend_sources` 신규.
   - 칸: `id UUID PK DEFAULT gen_random_uuid()`, `no INTEGER GENERATED ALWAYS AS IDENTITY UNIQUE`(루틴과 화면이 쓰는 출처 번호, 서랍의 「출처 N」), `name TEXT NOT NULL CHECK (char_length(btrim(name)) BETWEEN 1 AND 60)`, `kind TEXT NOT NULL CHECK (kind IN ('hashtag','channel','search_trend','manual_upload'))`, `location TEXT NOT NULL DEFAULT '' CHECK (char_length(location) <= 300)`(주소·해시태그·검색어, 직접 올린 자료는 비워도 된다), `enabled BOOLEAN NOT NULL DEFAULT true`, `created_at`·`updated_at TIMESTAMPTZ NOT NULL DEFAULT now()`, `created_by UUID NULL`.
   - 색인: `UNIQUE (lower(btrim(name)))`(같은 이름 두 번 등록 방지), `(enabled)`.
   - RLS를 켜고 정책은 만들지 않는다(service_role만 접근, 295와 같은 패턴). `COMMENT ON TABLE`·`COMMENT ON COLUMN`을 쓴다. 끝에 검증 쿼리 주석과 되돌림 SQL(`DROP TABLE IF EXISTS public.ops_trend_sources;`)을 단다. 「마지막으로 읽은 시각」은 칸을 두지 않고 읽을 때 계산한다(5번).
2. `jam-web/src/types/database.generated.ts`: 위 테이블의 `Row`·`Insert`·`Update`·`Relationships`(없음)를 SQL과 같게 손으로 더한다(알파벳 순서 자리). 카리나가 적용 뒤 MCP 생성 타입과 대조한다.
3. `jam-web/src/lib/admin/opsTrends/constants.ts` (새): `OPS_TREND_SOURCE_KINDS = ['hashtag','channel','search_trend','manual_upload']`와 화면 글자(해시태그·채널·검색어 추이·직접 올린 자료), `OPS_TREND_SOURCE_MAX_NAME = 60`, `OPS_TREND_SOURCE_MAX_LOCATION = 300`, `OPS_TREND_SOURCE_MAX_BODY_BYTES = 8192`.
4. `jam-web/src/lib/admin/opsTrends/sources.ts` (새, 순수 함수): `validateTrendSourceCreate(raw)`(`name`·`kind`·`location`, 앞뒤 공백 제거, 종류·길이 검사, 직접 올린 자료가 아닌 종류는 `location`이 비면 오류), `validateTrendSourcePatch(raw)`(`enabled`·`name`·`location` 중 하나 이상, 같은 검사), 둘 다 `{ ok: true, value } | { ok: false, errors: string[] }`.
5. `jam-web/src/lib/admin/opsTrends/sourceStore.ts` (새, 서버): `listTrendSources(service, { includeDisabled })`는 행을 `no` 순으로 읽고 `lastReadAt`을 계산해 붙인다(`ops_bundles`에서 최근 60일 `received_at, trends`를 읽어 `trends[].source_ids`에 그 출처 `no`가 든 묶음 중 가장 늦은 `received_at`, 없으면 null. 시험 묶음 제외). `createTrendSource(service, input, adminId)`, `updateTrendSource(service, id, patch)`는 고유 위반(`23505`)을 `{ ok: false, code: 'duplicate' }`로, 없는 행을 `'not_found'`로 돌려준다(던지지 않는다). 읽기·쓰기 실패는 호출부가 500으로 바꾸게 던진다.
6. `jam-web/src/app/api/admin/ops-trend-sources/route.ts` (새): `GET` — 관리자 세션 또는 읽기 토큰(`requireAdminRead`, `jam-web/src/lib/admin/auth.ts`). **토큰 요청은 켜진 출처만** `{ sources: [{ no, name, kind, location }] }`로 돌려주고(`includeDisabled`는 무시), 관리자 세션은 기본이 켜진 출처이고 `?includeDisabled=true`이면 전부 `{ sources: [{ id, no, name, kind, location, enabled, lastReadAt, createdAt }] }`로 돌려준다. 읽기 토큰으로 온 요청인지는 `isValidAdminReadToken(req.headers.get('x-admin-read-token'))`로 가른다. `POST` — **관리자 세션만**(`getAdminUser()`가 없으면 403, 읽기 토큰은 보지 않는다), 본문 8KB 상한, 검증 실패 400, 이름 중복 409, 성공 201 `{ source }`.
   `jam-web/src/app/api/admin/ops-trend-sources/[id]/route.ts` (새): `PATCH` — 관리자 세션만, `id`가 UUID가 아니면 404, 검증 실패 400, 이름 중복 409, 없는 행 404, 성공 200 `{ source }`. (삭제 경로는 없다. 끄기로 대신한다. 옛 묶음의 `source_ids`가 번호로 남아 있기 때문이다.)
   응답에 `created_by`를 싣지 않는다. 오류 본문에 내부 메시지를 싣지 않는다. `export const dynamic`을 두거나 `Cache-Control: no-store`로 캐시하지 않는다.
7. 시험(모두 `.ts`): `lib/admin/opsTrends/__tests__/sources.test.ts`(검증), `sourceStore.test.ts`(가짜 서비스 클라이언트: 목록 정렬·`lastReadAt` 계산·시험 묶음 제외, 중복·없는 행, 읽기 실패는 던짐), `app/api/admin/ops-trend-sources/__tests__/route.test.ts`(토큰 GET은 켜진 출처만·`id`와 `enabled`를 싣지 않음, 토큰으로 POST·PATCH 거부, 세션 CRUD, 409·404·400, 읽기 실패 500), 필요하면 기존 `lib/admin/__tests__/auth.test.ts` 대조.
8. 문서: `docs/service/prd/admin-boards/PRD.md` §6.4에 「구현됨(DB·API): 티켓 20261026_2033 1회차」와 테이블·API 규칙, §5.4에 `source_ids`가 출처 번호(`no`)라는 규칙, §11 Q2를 「결정: DB(2026-10-27)」와 근거로 바꾼다. `docs/service/prd/content-automation/PRD.md` §10.1 소재 출처에 「등록된 출처 목록은 `GET /api/admin/ops-trend-sources`(읽기 토큰)」 한 줄. 어드민 API를 모아 적은 문서가 있으면(grep) 한 줄 더한다.

### 1회차 결과 (머지·적용 완료, 2026-10-27)

마이그레이션 296을 롤백 실측(번호 증가, 이름 중복·허용 밖 종류·빈 이름·301자 위치·번호 직접 입력 거절, RLS 켜짐·정책 0) 뒤 적용했고, 적용 뒤 RLS 켜짐·정책 0개·색인 4개·칸 9개와 MCP 생성 타입 대조(35줄 일치)를 확인했다. API 실확인(메인 트리, 시험 출처 2개): 세션으로 추가 201, 같은 이름(공백·대소문자 달라도) 409, 허용 밖 종류·위치 없음 400, 끄기 200, 비UUID·없는 행 404·빈 패치 400, 세션 목록 기본은 켜진 것만이고 `includeDisabled=true`는 전부(`lastReadAt` 포함), 읽기 토큰 GET은 켜진 출처의 `no`·`name`·`kind`·`location`만이고 `includeDisabled`를 무시, 토큰 POST·PATCH는 통과하지 못해 행이 만들어지지 않았다(토큰만 있는 요청은 어드민 경로라 프록시가 로그인으로 돌려보낸다, 307). 출처 번호를 가리키는 묶음을 제출하면 그 출처의 `lastReadAt`이 묶음 받은 시각으로 채워졌다. 시험 행은 지우고 번호 시작을 1로 되돌렸다.

### 2회차: 화면 (1회차는 머지·적용됐다. 출처 DB·API는 `lib/admin/opsTrends/`, `/api/admin/ops-trend-sources`에 있다)

어드민 shadcn 부품(`components/admin/ui/`)과 Tailwind 토큰만 쓴다. 요약은 2,500자 이내다. 새 페이지 `/admin/ops-trends`(「트렌드 레이더」)를 만든다. 위쪽은 「내가 등록한 출처」, 아래쪽은 「읽은 트렌드」다.

1. `jam-web/src/lib/admin/opsTrends/radar.ts` (새, 순수 함수, 서버 전용 모듈을 가져오지 않는다):
   - `readBundleTrends(trends: Json | null)`: 묶음의 `trends`(PRD §5.4: `{ label, source_ids, summary, series?, outcome, outcome_reason? }`)를 읽어 `{ index, label, sourceNos, summary, series: number[] | null, outcome, outcomeReason }[]`로 돌려준다. 모양이 틀린 원소는 뺀다. `source_ids`는 정수 또는 정수 문자열을 번호로 본다(`sourceStore.ts`의 규칙과 같게).
   - `trendLinkedItemIds(trend, items)`: 그 묶음 항목 중 `rationale`(`readOpsItemRationales`, `jam-web/src/lib/admin/opsInbox/rationaleRead.ts`)에 `kind === 'trend'`이면서 `sourceId`가 `trend.sourceNos`에 드는 항목의 ID 배열(반려·취소 항목은 뺀다).
   - `collectRadar({ bundles, now, windowDays: 14, includeSample })`: 최근 14일 안에 받은 묶음의 트렌드를 `{ bundleId, bundleTitle, week, receivedAt, trend, linkedItemCount }[]`(받은 시각 내림차순)와 요약 `{ used, held, excluded }` 건수로 모은다. 시험 묶음은 `includeSample`일 때만 센다.
2. `jam-web/src/lib/admin/opsTrends/radarLoad.ts` (새, 서버): `loadTrendRadarInput({ now, includeSample })` — 최근 14일 `ops_bundles`(`id, week, title, received_at, trends, is_sample`)와 그 묶음들의 `ops_bundle_items`(`id, bundle_id, status, original, edited`)를 읽는다. 시험 포함이 꺼져 있으면 시험 묶음은 읽지 않는다. 읽기 실패는 던진다. 출처 목록은 `listTrendSources`(`sourceStore.ts`, `includeDisabled: true`)로 읽는다.
3. `jam-web/src/app/admin/ops-trends/page.tsx` (새, 서버 페이지, `jam-web/src/app/admin/ops-patterns/page.tsx`의 머리·오류 처리 패턴을 따른다): 쿼리 `sample=1`(시험 포함, 운영 홈과 같은 스위치 `OpsSampleSwitch`)을 읽고, 위 두 읽기를 `Promise.all`로 부른다. 한쪽을 못 읽으면 그 구역만 `OpsSectionNotice` 안내 카드다(다른 구역은 그대로).
4. `jam-web/src/components/admin/ops/trends/OpsTrendSources.tsx` (새, 클라이언트): 출처 표(이름·종류 글자·위치·마지막으로 읽은 시각(KST, 없으면 「아직 읽지 않았어요」)·켜짐 스위치(`components/admin/ui/switch.tsx`)). 스위치를 누르면 `PATCH /api/admin/ops-trend-sources/[id]`로 즉시 켜고 끄고(요청 중에는 그 줄만 잠금, 실패하면 되돌리고 한 줄 오류), 「출처 추가」(이름·종류(shadcn `Select`)·위치 입력, 직접 올린 자료는 위치를 비워도 된다)는 `POST`로 보낸다. 서버 응답 오류 문장(400 `details`, 409)을 그대로 한 줄로 보인다. 직접 올린 자료 종류에는 「파일 목록은 루틴이 제출에 싣는 값으로 보여요」 한 줄. 출처가 하나도 없으면 한 줄 안내와 추가 버튼. 목록을 바꾼 뒤 `router.refresh()`.
5. `jam-web/src/components/admin/ops/trends/OpsTrendRadar.tsx` (새, 서버 컴포넌트)와 `OpsTrendSparkline.tsx`: 요약 줄(「반영 N · 보류 N · 자동 제외 N」, 점+글자), 트렌드 카드 목록. 카드: 이름, 요약(한 줄 말줄임), 출처 칩(「출처 N · 이름」, 이름은 출처 목록에서 찾고 없으면 「출처 N」), 추이(`series`가 있으면 14칸 막대, SVG 속성으로 그린다. `style` 속성을 쓰지 않는다), 결과 칩(반영·보류·자동 제외, 자동 제외는 범주 `outcomeReason` 한 줄), 받은 묶음 제목과 시각, 반영(`used`)이면 「연결 항목 N건」 링크(`/admin/ops-inbox/{묶음 행 ID}?trend={index}`, 시험 포함 중이면 `sample=1`). 14일 안에 트렌드가 없으면 「최근 14일에 읽은 트렌드가 없어요」 한 줄.

7. 메뉴: `jam-web/src/components/admin/adminNavItems.ts`의 「라이브」 묶음에 「트렌드 레이더」(`/admin/ops-trends`, `IconTrendingUp`)를 「패턴 사전」 앞에 더하고 `components/admin/__tests__/adminNavItems.test.ts` 등 메뉴 시험을 맞춘다.

## 상세 요구사항

- 출처 필드: 이름, 종류, 위치(주소나 검색어), 켜짐 여부, 마지막으로 읽은 시각.
- 직접 올린 자료(`docs/operations/inbox/trends/`)는 출처 종류 하나로 보이고, 파일 목록은 루틴 제출에 실린 값으로 보인다(어드민이 저장소 파일을 직접 읽지 않는다).
- 자동 제외된 트렌드도 범주와 함께 보인다.
- 반영 결과를 누르면 그 트렌드에서 나온 항목만 걸러 결정 패널을 연다.

## 완료 조건

- 어드민에서 출처를 추가·끄기 하면 루틴용 읽기 API가 켜진 출처만 돌려준다(API 테스트).
- `trends[]`를 채운 시험 묶음을 넣으면 레이더에 트렌드·결과·연결 항목 수가 보인다(로컬 실화면).
- PRD Q2의 결정과 근거가 PRD §11과 이 티켓에 적혀 있다.
