# [Admin] 「승인하고 예약」 뒤에 이미지를 자동으로 만든다 (2031 후속, 첫 실제 묶음 전에 끝낸다)

> 상위: 20261026_2020

## 핵심 요약

- 요구사항: 「N건 승인하고 예약」을 누르면, 이미지 지시(`image_spec`)가 있고 이미지가 비어 있는 항목은 이미지를 자동으로 만들어 올린다. 승인과 예약이 한 번에 일어나면서 사라진 「이미지 만들 시간」을 되살린다.
- 구현 계획: 2031의 실행 완료 처리(`OpsDecisionWorkspace`의 `handleExecuted`)에서 `produceItemImage`(`useItemImageProduction.ts`)를 승인된 항목마다 부른다. 이미지 업로드 API는 예약된 뒤에도 자원에 이미지를 붙인다(`useItemImageProduction.ts` 머리 주석). 수동 [이미지 만들기] 버튼은 지금 승인됨·준비중에만 나오는데 예약됨·게재 전 항목도 허용할지 정한다.
- 관련 파일: `jam-web/src/components/admin/ops/OpsDecisionWorkspace.tsx`, `useItemImageProduction.ts`, `OpsImageProduction.tsx`, `OpsItemFooter.tsx`(154줄: 개별 승인 때만 자동 제작), `jam-web/src/lib/admin/opsSignals/composition.ts`(`OPS_IMAGE_PRODUCTION_STATUSES`), 스펙 `docs/plan/vision/07 JAM! 라이브 운영 블루프린트.md` 4.5, `docs/service/prd/ops-tool/PRD.md`

## 배경 / 문제 정의

2031 게이트(민지)가 찾았다. 예전에는 일괄 승인 뒤 항목이 「승인됨」에 머물러, 운영자가 [이미지 만들기]를 눌러 이미지를 채운 다음 「예약 등록」을 했다. 새 흐름은 항목이 곧바로 「예약됨」이 되고, 수동 버튼은 승인됨·준비중에만 나오므로 이미지 없이 예약될 수 있다. 사전 점검은 이미지 유무를 막지 않는다. 07 4.5는 「승인할 때 운영툴이 이미지를 만든다」다.

## 완료 조건

- `image_spec`이 있는 카드·미션 항목을 「승인하고 예약」하면, 결과 화면에서 이미지가 만들어져 자원에 붙는다(로컬 실화면 + DB 대조는 카리나).
- 이미지 제작이 실패해도 예약은 유지되고 「이미지 제작 필요」로 남는다. 운영자는 예약됨 항목에서도 이미지를 다시 만들 수 있다.
- 시험 묶음은 이미지를 만들지 않는다(지금과 같음).
