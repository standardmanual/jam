# [Admin] 주간 KPI의 레시피 수가 공개 전(예약) 레시피까지 센다 (1504 시작 검토 발견)

> 상위: 20260930_1450 · 진행 규칙 4(이미 개발된 기능에 영향) · 1504보다 먼저, 첫 예약 레시피가 생기기 전에 끝낸다

## 핵심 요약

- 문제: 주간 KPI(`jam-web/src/lib/admin/kpiWeekly.ts`의 `totalRecipes`, 154~175줄 부근)는 `combination_recipes`를 `valid_from`으로 거르지 않아 공개 전(예약) 레시피도 센다. 카즈하 주간 브리핑이 이 수를 「공개된 레시피 수」로 읽으면 틀린 숫자가 된다. 카즈하는 읽기 전용이고 응답에 예약 구분 필드가 없어 프롬프트 규율만으로는 구분할 수 없다(티켓 20260930_1504 「주요 의사결정」의 1458 종료 메모).
- 구현 계획: `totalRecipes`를 공개된 것(`valid_from`이 없거나 지금 이전)만 세게 하고, 공개 전 레시피 수를 별도 필드(`scheduledRecipes`)로 돌려준다. 주간 브리핑 형식(`.claude/skills/jam-work/references/forms/weekly-briefing-format.md`)에 「공개된 레시피 수」와 「예약 레시피 수」를 구분해 적게 한다.
- 관련 파일: `jam-web/src/lib/admin/kpiWeekly.ts`, `jam-web/src/lib/admin/__tests__/`의 주간 KPI 시험, `jam-web/src/app/api/admin/kpi/weekly/route.ts`(응답 모양을 문서화한 곳), `.claude/skills/jam-work/references/forms/weekly-briefing-format.md`

## 완료 조건

- 공개 전 레시피가 `totalRecipes`에 들지 않고 `scheduledRecipes`로 따로 나온다(시험).
- 주간 KPI를 쓰는 화면·스크립트·브리핑 형식이 새 필드와 어긋나지 않는다.

## 완료 기록

### 구현 내용 요약
주간 KPI의 `countRecipesWithInvalidRewardBadges`(`kpiWeekly.ts`)가 `combination_recipes`를 `valid_from`으로 거르지 않아 공개 전(예약) 레시피까지 `totalRecipes`에 들었다. 같은 쿼리에서 `valid_from`도 읽고, 집계 시각(`range.endIso`)보다 뒤인 레시피를 `scheduledRecipes`로 따로 세게 했다. `totalRecipes`와 `invalidRecipes`는 공개된 레시피만 센다. 응답 타입과 `definition` 문구를 맞췄고, 주간 브리핑 형식의 지표 출처 표에 공개된/예약/삭제된 배지 레시피 수 3종과 «공개된 레시피 수와 예약 레시피 수를 합쳐 전체 레시피로 쓰지 말라» 규칙을 더했다.
