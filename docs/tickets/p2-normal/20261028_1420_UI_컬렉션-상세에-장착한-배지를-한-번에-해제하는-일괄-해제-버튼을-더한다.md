# [UI] 컬렉션 상세에 장착한 배지를 한 번에 해제하는 일괄 해제 버튼을 더한다

## 핵심 요약

- 요구사항: 본인의 컬렉션 상세 화면에 그 컬렉션에 장착한 배지를 한 번에 모두 해제하는 버튼을 더한다. 4등급 컬렉션은 등급이 정해진 뒤 다른 등급으로 다시 채우려면 장착한 배지를 전부 해제해야 하므로(티켓 20261028_1408 정책), 배지를 하나씩 해제하는 번거로움을 줄이는 부가 기능이다.
- 선행 조건: 티켓 20261028_1408(컬렉션 화면이 처음 장착한 등급의 9칸만 보여 준다)이 staging에 머지된 뒤 시작한다. 두 티켓이 같은 파일(`SlotGrid.tsx`, `page.tsx`, `ko.ts`)을 고치므로 동시에 구현하면 충돌한다.
- 구현 계획: 서버에 일괄 해제 경로를 더하고(기존 `unslot_item_from_book`을 장착마다 호출, SQL 변경 없음 권장), 화면에 버튼과 확인 단계를 더한다. 아래 「구현 계획」에 적었다.
- 관련 파일(줄 위치는 2026-10-28 `origin/staging` 기준이며 시작 때 다시 확인한다):
  - `jam-web/src/app/api/itembooks/[id]/slot/route.ts`: 해제 `DELETE` 191~232줄(슬롯 한 개씩 `unslot_item_from_book` 호출), 오류 표 `UNSLOT_ERROR_STATUS_MAP` 48~50줄(`inventory_full`은 409와 `code: INVENTORY_FULL_CODE`로 응답).
  - `jam-web/src/app/(main)/collections/[id]/SlotGrid.tsx`: 한 칸 해제 `handleUnslot` 263줄, 칸별 «해제» 버튼 406줄 부근, 오류 배너 `error`.
  - `jam-web/src/app/(main)/collections/[id]/page.tsx`: 본인 화면 여부 `isOwnBook`, 장착 목록 `slots`.
  - `jam-web/src/lib/i18n/ko.ts` `d.itembooks`: 기존 해제 문구 `unslotButton`(1613줄), `inventoryFullForUnslot`(1673줄). 새 문구는 여기에 둔다.
  - `jam-web/src/lib/inventory/locked-item-block.ts`: `INVENTORY_FULL_CODE`.
  - 문서: `docs/service/prd/02_DATA_MODEL.md` 4-2절 「장착 API 분기」(해제 설명 508줄 부근).

## 배경 / 문제 정의

지금은 장착한 배지를 한 칸씩 «해제» 버튼으로만 뺄 수 있다. 9칸을 모두 비우려면 9번 누르고 9번 기다려야 한다. 4등급 컬렉션은 처음 장착한 등급이 컬렉션 등급으로 고정되고, 다른 등급으로 다시 채우려면 장착한 배지를 모두 빼야 한다. 그래서 모두 빼는 동작이 정책을 따르는 정상 경로가 되었고, 이 동작을 한 번에 하게 해 달라는 요청이다(사용자 요청, 2026-10-28).

해제의 현재 제약은 다음과 같다.

- 해제한 배지는 인벤토리로 돌아오므로 칸이 필요하다. `unslot_item_from_book`은 인벤토리 행을 잠근 안에서 `used_slots >= max_slots`이면 `inventory_full`로 거절한다.
- 일괄 해제는 장착한 배지 수만큼 여유 칸이 있어야 끝까지 갈 수 있다. 여유가 모자라면 앞부분만 해제되고 멈추는 일이 생길 수 있다.
- 장착을 풀어도 등급별 완성 기록은 남고 다시 채워도 같은 등급의 보상은 나가지 않는다(운영 로직 문서의 컬렉션 완성 규칙). 일괄 해제도 같다.

## 사용자 결정 (2026-10-28)

- **여유 칸이 모자랄 때**: 인벤토리 칸이 모자라다는 안내와 인벤토리로 가는 버튼을 보여 준다. 이때 아무것도 해제하지 않는다.
- 참고할 기존 선례: `InlineNotice`(`jam-web/src/components/ui/InlineNotice.tsx`)의 `action`에 인벤토리 이동 링크를 두는 방식을 이미 세 곳이 쓴다(`app/(main)/combine/PendingResultsSheet.tsx` 119줄, `app/(main)/missions/[id]/MissionDetailClient.tsx` 424줄, 문구 `inventoryLink` 세 곳). 링크 이름은 선례가 «인벤토리 보기»이고 사용자 표현은 «인벤토리 가기»다. 최종 이름은 채원 판정이 UX Writing 가이드와 선례를 맞춰 정한다.
- 안내 문구는 현상, 원인, 해결책 순서로 쓰고 칸 수는 쓰지 않는다(기존 `inventoryFullForUnslot` 주석 규칙).

## 상세 요구사항

### 서비스/코드베이스 관점

- 대상은 본인이 그 컬렉션에 장착한 배지 전부다. 다른 컬렉션과 다른 유저의 장착은 건드리지 않는다.
- 해제 한 건의 처리는 기존 DB 함수 `unslot_item_from_book`을 그대로 쓴다. 새 SQL 함수를 만들어야 한다고 판단되면(전부 아니면 전무가 필요한 경우 등) 이 티켓에서 멈추고 보고한다. `db` 유형은 자동 진행하지 않는다(정지 조건 3번).
- 여유 칸이 모자랄 때의 동작은 아래 「사용자 결정」을 따른다. 여유 칸이 장착한 배지 수보다 적으면 아무것도 해제하지 않는다. 경합으로 중간에 가득 차서 일부만 해제된 경우에는 해제한 수와 남은 수를 응답에 담고, 화면이 사실대로 알리면서 같은 인벤토리 이동 버튼을 보여 준다(이 경합 처리는 사용자 결정의 연장으로 둔 가정이며 채원 판정에서 확인한다).
- 응답과 오류는 기존 해제와 같은 모양을 따른다(`inventory_full`은 409와 `code`).
- 소프트 삭제된 배지에 꽂힌 장착도 해제 대상에 포함한다. 이런 장착은 컬렉션 화면에 칸이 없어 칸별 «해제» 버튼으로 풀 수 없는데, 서버는 그 장착의 등급을 컬렉션 등급으로 본다(티켓 20261028_1408 게이트 발견). 그대로 두면 «모두 해제하면 다른 등급으로 다시 정할 수 있어요» 안내를 따를 수 없는 막다른 길이 되므로, 일괄 해제가 이 경우의 유일한 해소 경로다.
- 4등급 여부와 관계없이 모든 컬렉션에서 동작한다. 서버 규칙(`tier_mismatch`)과 완성 판정은 바꾸지 않는다.

### UI/UX 관점

- 노출 조건: 본인 화면(`readOnly`가 아님)이고 장착이 한 개 이상일 때만 보인다. 화면에 칸이 없는 삭제 배지 장착만 남은 경우도 «장착이 있음»으로 센다. 타인 열람과 장착이 없는 상태에는 보이지 않는다.
- 한 번 누르면 최대 9개가 풀리고 4등급 컬렉션은 컬렉션 등급도 풀리므로 확인 단계를 둔다.
- **채원 사전 판정이 필요한 결정**: (가) 버튼의 위치와 모양(격자 위, 진행도 근처, 하단 고정 등), (나) 확인 단계의 형태(기존 시트·다이얼로그 재사용 여부)와 문구, (다) 진행 중 표시, (라) 여유 칸이 모자랄 때 보여 줄 안내 블록의 모양(아래 「사용자 결정」의 내용을 어떤 컴포넌트로 그릴지), (마) 해제 뒤 화면 전환(4등급 컬렉션은 등급 없는 9칸으로 돌아온다).
- 사용자 노출 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다. 화면 문구에 «슬롯»을 쓰지 않고 «장착»·«해제»를 쓴다. 오류 문구는 현상, 원인, 해결책 순서다.

## 구현 계획

1. 서버: 컬렉션의 본인 장착 전체를 해제하는 경로를 더한다. 기존 `DELETE`(슬롯 한 개)와 구분되게 별도 경로(예: `jam-web/src/app/api/itembooks/[id]/slots/route.ts`의 `DELETE`)를 권장한다. 인증과 오류 응답은 기존 해제를 따른다. 처리 순서는 (a) 본인 장착 목록 조회 (b) 인벤토리 여유 칸 확인 (c) 장착마다 `unslot_item_from_book` 순서 호출이다. 중간 실패 때는 멈추고 해제한 수를 돌려준다.
2. 화면: `SlotGrid.tsx`에 일괄 해제 처리 함수와 버튼, 확인 단계를 더한다. 버튼을 그리는 위치는 채원 판정을 따른다. 처리 중에는 다른 장착·해제·교체 버튼을 막는다. 끝나면 `router.refresh()`로 갱신한다.
3. 문구: `ko.ts` `d.itembooks`에 버튼, 확인, 결과, 오류 문구를 더한다.
4. 시험: 경로 시험(전부 해제, 장착 없음, 여유 칸 부족, 중간 실패, 인증 없음, 다른 유저 슬롯 접근 불가)과 화면 시험(노출 조건, 확인 취소, 진행 중 비활성).
5. 문서: `02_DATA_MODEL.md` 4-2절 「장착 API 분기」에 일괄 해제 경로를 한 줄 더한다. 정책 대시보드(`policiesData.ts`)에 인벤토리 가득 참 해제 제한 항목이 있으면 일괄 해제 동작을 맞춘다.

규모는 시험과 문서까지 세면 파일 7개 안팎이라 `plan_only` 기준(파일 5개 초과)을 넘길 것으로 본다. 시작 때 파일 단위 계획을 확정하고 `planOnlyWaiver`를 넘긴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 장착한 배지가 있는 본인 컬렉션 상세에 일괄 해제 버튼이 보이고, 장착이 없거나 타인 열람이면 보이지 않는다. 시험으로 고정한다.
- 버튼을 누르면 확인 단계가 나오고, 취소하면 아무것도 해제되지 않는다. 시험으로 고정한다.
- 소프트 삭제된 배지에 꽂힌 장착만 남은 컬렉션에서도 일괄 해제가 그 장착을 풀고, 4등급 컬렉션의 등급이 풀린다. 시험으로 고정한다.
- 확인하면 그 컬렉션에 장착한 배지가 모두 해제되어 인벤토리로 돌아오고 칸이 비어 있는 상태로 갱신된다. 다른 컬렉션의 장착은 그대로다. 시험으로 고정한다.
- 인벤토리 여유 칸이 장착한 배지 수보다 적으면 아무것도 해제되지 않고, 인벤토리 칸이 모자라다는 안내와 인벤토리로 가는 버튼이 나온다. 버튼을 누르면 인벤토리 화면(`/inventory`)으로 이동한다. 시험으로 고정한다.
- 해제 도중 가득 차서 일부만 해제된 경우 응답이 해제한 수를 담고, 화면이 사실대로 안내하면서 같은 인벤토리 이동 버튼을 보여 준다. 시험으로 고정한다.
- 4등급 컬렉션에서 모두 해제하면 컬렉션 등급이 풀려 등급 없는 칸으로 돌아온다(티켓 20261028_1408과 연결).
- 등급별 완성 기록은 지워지지 않고 다시 채워도 같은 등급 보상이 나가지 않는다(기존 규칙 회귀).
- 새 문구는 UX Writing 가이드의 용어(장착·해제)와 해요체를 따른다.
- `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging 화면에서 4등급 컬렉션과 옛 컬렉션의 상세를 열어 버튼 노출 여부를 읽기 화면으로 확인한 기록을 완료 기록에 남긴다. 실제 해제는 공용 DB를 바꾸므로 누르지 않고 시험으로 갈음한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

컬렉션 상세에 장착한 배지를 한 번에 해제하는 «모두 해제하기» 버튼과 서버 경로를 더했다. 새 SQL은 없고 기존 `unslot_item_from_book`을 장착마다 순서대로 부른다.

- 서버: 새 경로 `DELETE /api/itembooks/[id]/slots`. 요청 유저와 이 컬렉션의 `user_item_book_slots` 전부를 삭제 배지 필터 없이 조회한다. 인벤토리 빈칸이 장착 수보다 적으면 아무것도 해제하지 않고 409와 `code: inventory_full`로 답한다. 경합으로 중간에 가득 차면 멈추고 같은 409에 `released`·`remaining`을 싣는다. 그 밖의 실패는 500에 같은 두 수를 싣는다.
- 화면: 격자 아래 `Button outline fullWidth`(흰 면)로 «모두 해제하기». 노출은 `!readOnly && slotCount > 0`이고 `slotCount`는 삭제 배지 장착을 포함한 `slots.length`다. 확인 시트 `UnslotAllSheet`(보기와 컨테이너 분리): 제목, 본문(등급이 정해졌으면 등급 풀림, 완성했으면 완성 기록 유지 문장 추가), 취소·확정 한 쌍, 제출 중 닫기 차단과 중복 탭 방지. 안내는 푸터 맨 위 `InlineNotice`이고 «인벤토리 보기» 링크는 빈칸 부족·일부 해제에만 붙는다. 성공·실패·시간 초과 모두 새로고침하고, 진행 중에는 칸 버튼과 트리거를 막는다.
- 문구: `d.itembooks.unslotAll` 묶음(버튼, 시트 제목·본문, 취소·확정·진행 중, 성공 토스트, 빈칸 부족 안내, 일부 해제 안내, 일반 실패, 링크 이름).
- 문서: `02_DATA_MODEL.md` 4-2절 장착 API 분기, 운영 로직 8.3절 한 줄, 정책 대시보드 `ch8-collection-4tiers`, `inventory/PRD.md`(민지 WARN 지적을 병합 때 보완).
