# [API] 트렌드 출처 저장소 폴더 종류의 허용 폴더 검사를 더한다 (api, 조각 B)

## 핵심 요약

- 요구사항: 출처 종류 `repo_folder`(화면 이름 「저장소 폴더」)를 받고, 위치는 코드에 고정한 허용 폴더 목록과 글자 단위로 같을 때만 저장한다. 등록(`POST`)과 수정(`PATCH`) 둘 다 검사한다.
- 구현 계획: 상수 → 검증 → 저장소 → 라우트 → 테스트 순. **선행: 조각 A(마이그레이션 298)가 DB에 적용된 뒤** 시작한다(통합 테스트가 아니라 단위 테스트이므로 코드는 먼저 쓸 수 있지만, 머지·배포는 A 적용 뒤다).
- 관련 파일: 아래 「구현 계획」의 파일 단위 지도.

## 배경 / 문제 정의

- 상위 티켓 20261028_1422의 조각 B다. 위치는 지금 300자 이내 아무 문자열이다. 폴더 종류는 서버가 저장소 파일을 열 수 없으므로(배포본) 문자열 허용 목록으로만 지킨다.
- 허용 폴더 목록에 없는 경로(`docs/tickets/`, `../x/`, `/etc/`, 역슬래시 경로)가 저장되면 루틴이 엉뚱한 폴더를 읽게 될 수 있다. 그래서 등록과 수정에서 모두 막는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 허용 폴더 목록: `OPS_TREND_SOURCE_FOLDERS = ['docs/operations/trendresearch/'] as const`. 목록에 폴더를 더하는 일은 코드 변경이라 리뷰를 거친다.
- `POST`: `kind`가 `repo_folder`이면 `location`이 비어 있으면 400(기존 「주소·해시태그·검색어를 적어야 해요」 문장을 이 종류에 맞게 풀거나 같은 문장 유지), 목록에 없으면 400이다. 오류 문장은 해요체로 「정해 둔 폴더 중에서 골라 주세요」를 알린다.
- `PATCH`: 본문에 종류가 없으므로 저장소(`updateTrendSource`)가 현재 행의 종류를 읽어 `repo_folder`일 때 새 위치를 허용 목록과 견준다. 목록에 없으면 새 결과 코드 `folder_not_allowed`를 돌려주고, 라우트가 400으로 바꾼다.
- 다른 종류의 위치 검사는 바꾸지 않는다.
- 화면 컴포넌트가 종류별 안내 문구를 `Record<OpsTrendSourceKind, string>`으로 가진다. 종류를 더하면 타입 오류가 나므로, 이 조각에서 `OpsTrendSources.tsx`의 `KIND_PLACEHOLDERS`에 `repo_folder: '목록에서 골라요'` 한 줄만 더해 타입 검사를 통과시킨다(입력 칸을 목록 선택으로 바꾸는 일은 조각 C).

### UI/UX 관점 (해당 시)

- 오류 문장만 해당한다. 해요체의 쉬운 문장으로 쓴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- `POST`에 `{ name, kind: 'repo_folder', location: 'docs/operations/trendresearch/' }`를 보내면 201이다.
- `POST`의 위치가 비었거나 `docs/tickets/`, `../x/`, `/etc/`, `docs\operations\trendresearch\`이면 400이고 `details`에 위치 오류 문장이 있다.
- `PATCH`로 폴더 출처의 위치를 목록 밖 값으로 바꾸면 400이고, 목록 안 값으로는 200이다. 종류가 다른 출처의 위치 수정은 이전과 같다.
- 같은 이름 중복은 409, 없는 `id`는 404로 이전과 같다.
- 위 케이스가 단위 테스트에 있고 `scripts/verify.sh`(lint·타입·테스트)가 통과한다.

### 후속 범위 (담당: 카리나, 시점: A 적용 뒤 머지)

- 머지 전에 A(마이그레이션 298)가 DB에 적용됐는지 읽기 SQL로 확인한다.
- 머지·push 뒤 staging 배포가 완료됐는지 확인하고, 읽기 토큰 `GET`이 켜진 폴더 출처 행을 돌려주는지는 조각 C 배포 뒤 화면 등록으로 함께 확인한다.

## 완료 기록

### 구현 내용 요약

- 출처 종류 `repo_folder`(화면 이름 「저장소 폴더」)와 허용 폴더 목록 `OPS_TREND_SOURCE_FOLDERS = ['docs/operations/trendresearch/']`을 `constants.ts`에 더했다.
- 등록(`POST`): `validateTrendSourceCreate`가 폴더 종류의 위치(앞뒤 공백을 뗀 값)를 목록과 글자 그대로 견준다. 비었거나 목록 밖이면 `location: 정해 둔 폴더 중에서 골라 주세요.` 하나로 거절한다(길이·제어 문자 오류가 이미 있으면 겹쳐 내지 않는다). `isTrendSourceFolder`와 `TREND_SOURCE_FOLDER_ERROR`를 내보내 등록·수정·테스트가 같은 값을 쓴다.
- 수정(`PATCH`): `updateTrendSource`가 위치를 바꾸는 수정이면 현재 종류를 읽는다. 비움은 기존 `location_required`가 먼저이고, 폴더 종류인데 새 위치가 목록 밖이면 새 결과 코드 `folder_not_allowed`를 돌려준다. `[id]/route.ts`가 이를 400과 위치 오류 문장으로 바꾼다.
- 화면 컴포넌트는 `KIND_PLACEHOLDERS`에 `repo_folder: '목록에서 골라요'` 한 줄만 더했다(타입 검사용). 목록 선택 UI는 조각 C다.
- 다른 종류의 위치 검사는 바뀌지 않았다. `POST` 라우트는 이미 검증 결과를 400으로 바꾸므로 변경이 없다.

### 주요 의사결정 / 핵심 메모

- 계획 반환 면제로 진행했다. 실제는 8개 파일·233줄(추가 219, 삭제 14)이라 티켓 예상(약 9개·120~160줄)보다 줄 수가 많았다(테스트 포함).

- 빈 위치의 `POST` 오류는 티켓이 허용한 두 안 중 「이 종류에 맞게 풀기」를 택해 폴더 문장 하나로 알린다.

### 잔여 이슈
- `PATCH`로 폴더 위치를 비울 때의 문장(「직접 올린 자료가 아닌 종류는 주소·해시태그·검색어를 적어야 해요」)이 폴더 종류에는 어색하다. 조각 C 티켓에 정할 일로 적었다.
- PRD §6.4가 코드와 어긋난 상태다. 조각 D에서 고친다.
- 단위 테스트가 가짜 DB 클라이언트라 DB 제약과의 맞물림은 조각 C 배포 뒤 화면 등록으로 확인한다.
