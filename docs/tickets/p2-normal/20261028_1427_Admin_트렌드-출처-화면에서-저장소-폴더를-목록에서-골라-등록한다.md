# [Admin] 트렌드 출처 화면에서 저장소 폴더를 목록에서 골라 등록한다 (admin, 조각 C)

## 핵심 요약

- 요구사항: `/admin/ops-trends`의 [출처 추가]에서 종류 「저장소 폴더」를 고르면 위치 입력이 글자 입력이 아니라 **허용 폴더 목록 선택**으로 바뀐다. 표에는 폴더 경로가 보이고 스위치로 켜고 끈다.
- 구현 계획: 컴포넌트 한 개와 그 테스트 한 개를 고친다. **선행: 조각 B(상수·검증·API)가 머지된 뒤** 시작한다.
- 관련 파일: `jam-web/src/components/admin/ops/trends/OpsTrendSources.tsx`(46행 `KIND_PLACEHOLDERS`, 53행 `locationRequired`, 58~66행 `SourceAddForm` 상태·`missing`, 113~120행 위치 입력, 214~220행 표 위치 칸), 테스트 `.../__tests__/OpsTrendSources.test.tsx`.

## 배경 / 문제 정의

- 상위 티켓 20261028_1422의 조각 C다. 경로를 손으로 치면 오타·경로 탈출 위험이 있어 목록 선택으로 받는다. 조각 B가 서버에서도 같은 목록으로 막으므로 화면은 편의를 맡는다.
- 조각 B가 `KIND_PLACEHOLDERS`에 `repo_folder` 한 줄을 이미 더해 둔다(타입 검사 때문). 이 조각이 그 칸의 의미를 완성한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 종류 선택(`OPS_TREND_SOURCE_KINDS`를 도는 `Select`)에는 「저장소 폴더」가 이미 나온다(상수에서 온다).
- 종류가 `repo_folder`이면 위치 칸을 `Input`이 아니라 `OPS_TREND_SOURCE_FOLDERS` 선택(`Select`)으로 그린다. 종류를 바꾸면 이전 위치 값을 비운다(다른 종류의 글자 값이 폴더 칸에 남지 않게).
- 위치 선택 전에는 [추가]가 눌리지 않는다(`missing`에 이미 `locationRequired(kind)`가 있어 값이 비면 막힌다).
- 서버 오류 문장(400 `details`·409)을 그대로 한 줄로 보이는 기존 동작은 그대로 둔다.

### UI/UX 관점 (해당 시)

- 안내 문구(해요체): 폴더 종류를 골랐을 때 위치 아래에 「정해 둔 폴더 중에서 골라요. 루틴이 이 폴더의 안내 문서에 적힌 대로 읽어요」 수준의 한 줄을 보인다. 기존 직접 올린 자료의 안내(`TREND_SOURCE_MANUAL_HINT`)와 같은 자리·같은 모양(`text-sm text-muted-foreground`)이다.
- 표 위치 칸은 폴더 경로를 그대로 보인다. 폴더 출처의 이름 예시는 placeholder에 「예: 트렌드 리서치」를 쓴다.
- `admin` 화면이라 MODULAR 적용 제외이고 새 토큰·새 컴포넌트는 만들지 않는다. 기존 `Select`·`Input`만 쓴다.

## 구현 계획

1. `jam-web/src/components/admin/ops/trends/OpsTrendSources.tsx`
   - import에 `OPS_TREND_SOURCE_FOLDERS`를 더한다.
   - `SourceAddForm`(약 58행~): `kind` 변경 핸들러(`onValueChange`, 약 100행)에서 `setLocation('')`을 함께 부른다.
   - 위치 칸(113~120행): `kind === 'repo_folder'`이면 `Select`(값 `location`, 항목 `OPS_TREND_SOURCE_FOLDERS`, `aria-labelledby` 연결), 아니면 기존 `Input`.
   - 직접 올린 자료 안내(123행 `kind === 'manual_upload' &&`) 옆에 폴더 종류 안내 한 줄을 더한다. 문구는 모듈 최상단 상수로 둔다(`TREND_SOURCE_FOLDER_HINT`, 다른 안내 상수와 같은 자리).
   - 표(214~220행)는 `source.location`을 그대로 보이므로 변경 없음.
2. `jam-web/src/components/admin/ops/trends/__tests__/OpsTrendSources.test.tsx`: 종류 「저장소 폴더」를 고르면 폴더 선택이 나오고 `Input`이 사라지는지, 위치를 고르면 [추가]가 켜지고 `createTrendSourceRequest`에 `{ kind: 'repo_folder', location: 'docs/operations/trendresearch/' }`가 가는지, 종류를 바꾸면 위치가 비는지 확인하는 케이스를 더한다.

규모: 파일 2개, 약 60~80줄. `plan_only` 임계값 안이다.

실렌더 검증(유형 `admin`): 카리나가 머지 뒤 push 전에 로컬 `ADMIN_EMAILS` 환경에서 `/admin/ops-trends`를 열어 종류 선택 → 폴더 선택 → 추가 → 스위치를 확인한다(`DEV_PROCESS_GUARDRAILS.md` 패턴 13). 아현·민지는 격리 워크트리에서 실렌더를 시도하지 않는다. 이 실렌더에서 출처 행이 실제 DB에 생기므로, 확인에 쓴 행은 끄기로 정리하고 사용자에게 알린다(삭제 경로가 없다). 사용자가 직접 등록할 「트렌드 리서치」 행을 이 검증으로 대신해도 된다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 종류를 「저장소 폴더」로 고르면 위치 입력이 폴더 목록 선택으로 바뀌고, 다른 종류로 되돌리면 글자 입력으로 돌아온다.
- 폴더를 고르기 전에는 [추가]가 비활성이고, 고른 뒤 누르면 `kind: 'repo_folder'`, 위치가 고른 경로인 요청이 간다.
- 종류를 바꾸면 위치 값이 비워진다.
- 표에는 폴더 출처의 경로가 보이고 스위치로 켜고 끈다(기존 동작).
- 컴포넌트 테스트와 `scripts/verify.sh`가 통과한다. 새 토큰·새 공용 컴포넌트가 없다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤 push 전)

- 로컬 실렌더 확인(위 「구현 계획」 끝). 확인 결과를 티켓에 적는다.
