# [Content] JAM2 게이트 미션 삭제 SQL(299) 롤백 실측과 오픈 직전 실행 (묶음 7, 7-9)

## 핵심 요약

- 요구사항: 티켓 `20261028_1530`이 작성한 마이그레이션 299(JAM 2.0 이전 게이트 미션 53건과 그 알림·소식을 백업한 뒤 삭제)를 오픈 직전에 롤백 실측하고 실행한다. 실행한 뒤 현재 서비스를 서술하는 문서를 고친다.
- 구현 계획: 코드 변경은 없다. 카리나가 244를 적용한 바로 다음, 245를 적용하기 앞에서 실행한다(순서 244 → 299 → 245).
- 관련 파일: `jam-web/supabase/migrations/299_delete_pre_jam2_gate_missions.sql`(머리의 드라이런, 본문, 사후 확인 쿼리, 되돌림 SQL), `docs/plan/jam2/12 JAM 2.0 오픈 전후 적용 순서.md`(4절 12번, 4.1절 2번).

## 배경 / 문제 정의

2026-10-28에 사용자가 JAM 2.0 이전의 게이트 미션을 폐기가 아니라 삭제하기로 정했고, 같은 날 그 미션을 가리키는 알림·소식도 함께 지우기로 했다. 결정의 기록과 SQL 작성, 읽기 전용 검증은 티켓 `20261028_1530`에서 끝났다.

SQL의 가드는 대상 미션의 보상 배지가 꺼져 있어야(244 적용 뒤) 통과한다. 그래서 롤백 실측도 실행도 244를 적용하기 전에는 할 수 없고, 오픈 일정이 정해지지 않아 이 티켓은 WAITING으로 둔다.

## 완료 조건

### 후속 범위 (담당: 카리나, 시점: 오픈 직전 244 적용 뒤)

- **롤백 실측**: 299 본문을 한 트랜잭션으로 실행하고 마지막에 일부러 오류를 내 DB가 그대로인지 확인한다. 결과를 이 티켓에 남긴다.
- **실행 직전 읽기 확인**: 299 파일 머리의 드라이런을 돌려 기대값과 같은지 본다(대상 미션 53, 대상 밖 미션 2, 보상 배지 연결 중 켜진 것 0, 막는 참조 0, 비워지는 참조 0, 알림·소식은 키로 센 값과 문자열로 센 값이 같음). 참가 6, 완료 1, 알림 1, 소식 7은 같거나 줄어야 한다. 어긋나거나 가드가 멈추면 실행하지 않고 사유를 보고한다.
- **실행**: 한 번의 호출로 299를 실행한다. 직후 파일의 «사후 확인» 쿼리를 읽고 영향 범위와 건수를 사용자에게 바로 보고한다.
- **실행 뒤 문서 정리**: 현재 서비스를 서술하는 문서(`docs/service/SERVICE_OPERATIONS.md`, `docs/service/prd/01_PRD.md`·`02_DATA_MODEL.md`·`admin-ui/ADMIN_PRD.md`, `docs/service/content/ACTIVITY_BADGES.md`, `docs/service/badge-engine/BADGE_ENGINE_UNIFIED.md`)에서 «게이트 미션 53건» 서술을 확인해 고친다. 기능 지도(`current-service-map`)는 2026-10-09 스냅샷이므로 고치지 않고 삭제 시점을 한 줄 덧붙인다. 244 적용 뒤 `ACTIVITY_BADGES.md`에 634에서 270으로의 변화를 반영하는 기존 후속(티켓 `20261018_1816`)과 한 번에 정리한다.
- **12 오픈 전후 적용 순서 갱신**: 4절 12번의 상태를 «적용 완료»로 고친다.
- **백업 표 정리**: 오픈 뒤 문제가 없다고 확인한 다음 `gate_mission_backup_20261028`을 지운다(파일 끝의 DROP).
