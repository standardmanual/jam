# [Infra] DB 확장: 챕터 횟수·서비스 활동 잼표·보류·소멸·포인트 차감의 새 구조만 덧붙인다

> 상위 티켓 `20261028_1730`의 하위 티켓 U2다. 연결된 결정: D4, D5, D6, D9, D12. 처리 유형(`/jam-work`): db(단독 호출, SQL 파일까지).

## 핵심 요약

- 요구사항: 새 구조만 덧붙이는 확장 SQL을 만든다. 유저 눈에는 변화가 없고, 옛 함수와 화면은 그대로 동작한다.
- 구현 계획: 챕터별 횟수 칸, 서비스 활동 잼표(종류별 잼·하루·주간 상한), 잠긴 아이템 배지 포인트 비용, 보류 보상 표(최대 2), «아직 보지 않은 캡슐 결과» 표시, 잼 원장 사유 추가(서비스 활동 잼·소멸), 포인트 원장 사유 추가(잠긴 열기 차감)와 잔액 0 미만 방지 제약을 한 묶음의 확장으로 쓴다. 생성 타입을 재생성한다.
- 관련 파일: `jam-web/supabase/migrations/234_capsule_concurrency_fix.sql`(옛 `capsule_fill`·`capsule_open`, 건드리지 않는다), `220_jam_ledger.sql`(`jam_transactions.reason` CHECK), `221_chapters.sql`(챕터 표), 포인트 원장 마이그레이션(아현이 첫 호출에서 위치 확인), `jam-web/src/types/database.generated.ts`. 줄 위치는 아현이 첫 호출에서 확인한다.

## 배경 / 문제 정의

- DB는 staging과 프로덕션이 공용이라 SQL 실행이 즉시 프로덕션에 반영된다. 프로덕션 main이 옛 함수를 아직 쓰는 동안 옛 함수를 지우면 깨진다.
- 챕터·잼 거래·캡슐 열기가 모두 0건이라 백필이 필요 없다(2026-10-28 실측). 오픈 직전에 다시 확인한다(U12).

## 상세 요구사항

### 서비스/코드베이스 관점

- 확장은 옛 함수의 시그니처를 그대로 둔다. 되돌림 SQL을 같은 묶음에 둔다.
- 포인트 잔액이 0 아래로 내려가지 않게 막는 제약을 이 묶음에 넣는다(운영 로직 14.5절의 알려진 문제).
- SQL 파일은 `jam-web/supabase/migrations/`에 남기고, 실행은 메인 세션이 읽기 전용 확인과 사용자 보고까지 한다(CLAUDE.md 규칙 6, `db-migration-rules.md`).

## 구현 계획

챕터별 횟수 칸, 서비스 활동 잼표(종류별 잼·하루·주간 상한), 잠긴 아이템 배지 포인트 비용, 보류 보상 표(최대 2), «아직 보지 않은 캡슐 결과» 표시, 잼 원장 사유 추가(서비스 활동 잼·소멸), 포인트 원장 사유 추가(잠긴 열기 차감)와 잔액 0 미만 방지 제약을 한 묶음의 확장으로 쓴다. 생성 타입을 재생성한다.

## 완료 조건

- SQL 파일과 되돌림 SQL이 migrations에 있고, 드라이런 결과와 롤백 실측이 티켓에 기록되어 있다.
- 실행 뒤 옛 채우기·열기 함수와 화면이 그대로 동작함을 읽기 전용 질의로 확인했다.
- 포인트 잔액을 0 아래로 만드는 회수와 차감이 거절된다는 시험이 있다.
- 생성 타입을 재생성해 같은 커밋에 넣었다.
