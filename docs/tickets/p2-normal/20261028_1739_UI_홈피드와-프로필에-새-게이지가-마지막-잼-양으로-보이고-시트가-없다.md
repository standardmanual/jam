# [UI] 홈피드와 프로필에 새 게이지가 마지막 잼 양으로 보이고 시트가 없다

> 상위 티켓 `20261028_1730`의 하위 티켓 U8다. 연결된 결정: D2, D9, D10, B2, B3. 처리 유형(`/jam-work`): ui(채원 사전 판정 필요).

## 핵심 요약

- 요구사항: 홈피드와 프로필에 어두운 트랙과 오렌지 채움 게이지를 프로토타입 기준으로 반영한다. 접속하면 가장 마지막 잼 양까지 진입 모션으로 차오르고, 바텀시트와 «채우기»·«열기»·«가진 잼» 줄은 없어진다.
- 구현 계획: `CapsulePill`·`RadialCapsule`을 새 게이지로 바꾸고 `CapsuleWidget`의 시트·채우기·열기 흐름을 걷어낸다. 보류·차단 안내 메시지 영역과 확률 안내 링크의 새 자리를 만든다.
- 관련 파일: `jam-web/src/components/capsule/CapsulePill.tsx`·`CapsuleWidget.tsx`·`CapsuleSheet.tsx`·`RadialCapsule.tsx`, `jam-web/src/components/jam/JamBalance.tsx`·`JamFillPanel.tsx`, 프로토타입 `jam-web/src/app/spike/capsule-fill/`(`JamGauge.tsx`), `jam-web/src/app/(main)/page.tsx`·`profile/`. 줄 위치는 아현이 첫 호출에서 확인한다.

## 배경 / 문제 정의

- 확률 안내 링크는 지금 캡슐 시트 안에 있어서 시트를 없애면 접근 경로가 사라진다. 확률 공개는 지키기로 한 약속이라 새 위치가 필요하다(운영 로직 18장).

## 상세 요구사항

### 서비스/코드베이스 관점

- 프로필의 «다음 챕터까지» 게이지와 캡슐 게이지가 둘이 되는 문제는 채원이 판정한다(B3). 홈피드에는 «챕터 N» 글자만 작게 두는 쪽을 추천한다.
- 진행 수치(숫자·퍼센트)는 화면에 내보내지 않는다(운영 로직 5.3절).

### UI/UX 관점

- 확률 안내 링크는 캡슐 게이지 아래 고정 한 줄(홈피드·프로필 공통)을 추천한다(B2).
- 게이지를 눌러도 시트가 열리지 않는다. 눌렀을 때의 동작이 필요하면 채원이 판정한다.
- 채원 사전 판정 없이 구현을 시작하지 않는다(`needs_design`).

## 구현 계획

`CapsulePill`·`RadialCapsule`을 새 게이지로 바꾸고 `CapsuleWidget`의 시트·채우기·열기 흐름을 걷어낸다. 보류·차단 안내 메시지 영역과 확률 안내 링크의 새 자리를 만든다.

### 규모 사전 판정 (2026-10-30)

바뀌는 곳은 캡슐 위젯 묶음(`CapsuleWidget` 234줄, `CapsulePill`, `RadialCapsule` 231줄, `CapsuleSheet` 123줄)과 그 시험(합쳐 700줄 안팎), 새 게이지(프로토타입 `JamGauge` 166줄 기반), 캡슐 상태 계약·조회(`capsule-contract.ts`, `capsule.ts`, `GET /api/capsule`), 보류 받기 호출(`capsule-flow.ts`, `capsule-client.ts`), 걷어낼 것(`CapsuleSheet`, `JamFillPanel`, `JamBalance`, `capsule-sheet-signal.ts`, 채우기·열기 호출), 홈 `(main)/page.tsx`, 프로필 `ProfileClient.tsx`, 문구(`ko.ts`), 문서다. 파일 30개 안팎이고 1,500줄 안팎이라 `plan_only` 기준(5개 초과, 100줄 이상)을 크게 넘는다. 티켓의 처음 추정(«홈과 프로필 분할»)을 따라 **4회차로 나눈다**: 1회(api) 캡슐 상태에 보류·차단을 싣는다, 2회(ui) 홈의 새 게이지와 위젯, 3회(ui) 프로필, 4회(content) 문서와 정책 카드. 두 화면 회차는 `ui`라 채원 사전 판정을 거치고, 전체 방향은 **구현 전에 채원이 한 번에 판정한 뒤 사용자 승인**(프로토타입 승인, B2·B3)을 받는다.

### 현재 사실 (2026-10-30, 코드 읽기 전용 확인)

- 홈(`(main)/page.tsx` 153줄)과 프로필(`ProfileClient.tsx` 693줄)이 같은 `CapsuleWidget`을 쓴다. 이 위젯은 알약(`CapsulePill` → `RadialCapsule`)을 누르면 `CapsuleSheet`를 띄우고, 시트 안에서 «채우기»(`JamFillPanel`)와 «열기»를 하며, 열기 성공 뒤 `BadgeRevealOverlay`를 연다.
- 캡슐 상태 계약 `CapsuleStatus`는 필요량·채운 양·남은 양·가진 잼·열 수 있는지·못 여는 까닭·빈칸 수만 싣는다. 보류한 보상(`capsule_pending_rewards`, U3)의 개수, 잼을 받을 수 없는 상태, 보지 않은 결과(`capsule_unseen_results`)는 싣지 않는다.
- 보류 받기는 서버에 이미 있다(`POST /api/capsule/claim`, `lib/capsule/claim.ts`). 알림 두 종류(`capsule_nearly_full`, `capsule_jam_blocked`)는 U4 3회가 만들었고 알림 링크는 «홈으로 보내고 화면 반영은 U8»이라고 적혀 있다(`lib/notifications/href.ts`).
- 프로토타입(`app/spike/capsule-fill/`)은 어두운 트랙 + 오렌지 채움 게이지(`JamGauge`), 진입 모션, 챕터 오름 오버레이(`LevelUpOverlay`)를 보인다. 프로토타입 티켓 `20261028_1516`은 사용자가 모션을 확인한 뒤 닫도록 열려 있다. 수치(숫자·퍼센트)는 화면에 그리지 않는다.
- 홈의 «JAM! 시작하기» 카드는 U7에서 캡슐 열기 단계를 없앴고 캡슐 위젯과 신호(`capsule-sheet-signal`)로 이어지지 않는다. 신호는 이제 위젯만 구독한다.
- 확률 안내 링크는 지금 캡슐 시트 안에 있다(운영 로직 18장).

### 동작 설계 초안 (채원 판정과 사용자 승인으로 확정)

1. **새 게이지**: 어두운 트랙에 오렌지 채움(프로토타입 기준). 접속하면 가장 마지막 잼 양(서버가 준 `filled / required`)까지 진입 모션으로 차오른다. 숫자·퍼센트는 그리지 않고 상태는 `aria-label`로만 알린다.
2. **시트 없음**: 게이지를 눌러도 시트가 열리지 않는다. «가진 잼» 줄, 채우기 버튼, 열기 버튼, `CapsuleSheet`, `JamFillPanel`, `JamBalance`, 채우기·열기 호출, 위젯의 열기 신호 구독을 화면에서 없앤다(채우기·열기 API와 DB 함수는 U11까지 둔다).
3. **게이지 아래 안내 영역**: 보류가 있으면 «받기» 한 번(D9, `POST /api/capsule/claim`), 잼을 받을 수 없는 상태와 70·80·90% 안내(D10)를 메시지로 보인다. 소식(알림)과 같은 단계 규칙을 쓴다. 문구는 채원과 윈터의 톤 확인.
4. **확률 안내 링크**(B2): 게이지 아래 고정 한 줄(홈피드·프로필 공통)을 추천한다.
5. **프로필**(B3): «다음 챕터까지» 게이지와 캡슐 게이지가 둘이 되는 구분은 채원이 판정한다. 홈피드에는 «챕터 N» 글자만 작게 두는 쪽을 추천한다.
6. **캡슐 열기 결과**: 100%에 닿으면 서버가 자동으로 열고 결과를 `capsule_unseen_results`에 남긴다. 결과를 보여 주는 연출과 챕터 오름은 U9 몫이고, U8은 게이지와 안내까지다. 보지 않은 결과가 있을 때 U8이 무엇을 보이는지는 채원이 판정한다.
7. 이 티켓이 하지 않는 것: 적립 한 번이 합쳐진 연출(U9), 잠긴 상세와 다른 표면(U10에서 끝), 옛 채우기·열기 DB 함수와 API 삭제(U11), 알림 문구 변경(U4에서 끝).

### 위험과 대응

| 위험 | 대응 |
|---|---|
| 시트가 없어지면 확률 안내와 «받기»·차단 안내 경로가 사라짐 | 새 자리를 먼저 만들고(2회) 시트를 걷어낸다. 같은 회차 안에서 끊김이 없게 한다 |
| 캡슐 상태 계약에 보류·차단이 없어 화면이 판단하지 못함 | 1회(api)에서 서버가 보류 개수와 받을 수 없는 상태를 싣는다. 화면은 다시 계산하지 않는다 |
| 알림이 홈으로 보내는데 홈에 안내가 아직 없음 | 알림 링크는 이미 홈이다. 안내는 2회에서 올리고 push는 4회차 뒤 한 번만 한다 |
| 진입 모션이 홈 응답을 늦추거나 접근성 설정을 무시 | 모션은 `prefers-reduced-motion`이면 즉시 마지막 값으로 그리고, 값은 서버가 준 `initial`로 시작한다 |
| 프로토타입 승인 없이 서비스에 반영 | 구현 전에 사용자에게 프로토타입 승인과 B2·B3를 묻는다. 승인 전에는 아현을 부르지 않는다 |

### 채원 사전 판정과 사용자 확정 (2026-10-30)

채원 모드 ①이 전체 방향을 한 번에 판정했고, 사용자가 승인 항목에 아래처럼 답했다. **이 절이 U8 모든 회차의 기준이다.** 위 「동작 설계 초안」과 다르면 이 절이 우선한다.

**사용자 확정**

| 항목 | 결정 |
|---|---|
| 프로토타입(어두운 트랙, 오렌지 채움, 높이 72, 점 4개, 번개) | 승인. 옛 `RadialCapsule`(96px, 퍼센트·«CAPSULE» 글자)은 없어진다 |
| 새 색 토큰 | 신설: `--capsule-fill`(#F94C31), `--capsule-track`(#19201C), `--capsule-ring`(#0B0F0D). U9 오버레이가 같은 오렌지를 다시 쓴다 |
| 진입 모션 | 화면에 들어올 때마다 한 번(라우트 이동, 새로고침, 탭 이동으로 다시 마운트될 때). 같은 화면에서 값이 바뀌면 처음부터 다시 돌지 않고 지금 값에서 새 값으로 옮겨 간다. `prefers-reduced-motion`이면 쉼도 시간도 0 |
| 확률 안내 링크(B2) | **게이지 주변에 두지 않는다.** 이미 있는 푸터의 «확률 안내» 페이지 링크로 통합한다. 채원의 «캡슐 묶음 맨 아래 한 줄» 추천은 채택하지 않는다 |
| 안내 문구 | «최대한 간결하게»(사용자). 아래 간결 문구를 쓰고 퍼센트는 쓰지 않는다. 채원 초안의 «이 동안 들어오는 잼은 사라져요» 설명 문장은 뺀다 |
| 프로필 게이지 구분(B3) | 사용자가 따로 답하지 않았다. **가정**: 채원 추천대로 «다음 챕터까지» 8px 막대와 캡슐 게이지를 둘 다 두고 간격만 16으로 넓히며, 홈은 게이지 위에 «챕터 N»(text-sm muted)을 둔다. 아니면 3회차 전에 바로잡는다 |

**간결 문구**(해요체, 숫자는 못 받은 보상 개수와 빈칸 수뿐, 윈터 톤 확인은 구현 뒤 별도)

| 상태 | 문구 |
|---|---|
| 보류 1개, 단계 없음 | 못 받은 보상이 1개 있어요 |
| 보류 1개, 단계 70·80·90 | 캡슐이 거의 찼어요 |
| 잼을 받을 수 없음(보류 2개) | 지금은 잼을 받을 수 없어요 |
| 빈칸 부족 덧줄 | 빈칸 {free}개, 필요 {needed}개 |
| 가득 찬 채 남음(트라이브 없음 등) | 캡슐이 가득 찼어요 |
| 버튼 | 받기 / 받는 중 / 빈칸 부족이면 인벤토리 보기 |
| 받은 뒤 | 기존 `BadgeRevealOverlay` 결과 문구 «아이템 배지 {n}개를 받았어요» |
| 받기 거절·받을 것 없음 | 기존 `d.capsule.claimInsufficientSlots`·`claimNoPending` 알림 + 다시 조회 |

**판정 요지**
- 새 게이지는 서비스 전용 `components/capsule/CapsuleGauge.tsx`(프로토타입 `JamGauge` 이식)다. 눌러도 동작이 없고(`button`·`jam-press`·커서 없음) 접근성 역할은 `role="img"` + 상태 문장 `aria-label`(숫자 없음)이다. 수치 변환(`jamPercentToGraphPercent`, `graphPercentToFillRatio`)은 `lib/capsule/capsule-gauge.ts`로 옮기고 `planFill`·`LevelUpOverlay`는 U9 몫이라 스파이크에 남긴다. `JamBolt`는 U9이 쓰도록 내보낸다.
- 진입 모션: 시작 그래프 2%(잼 0%), 끝 `filled / required`, 시작 전 260ms 쉼, 1,500ms, `--ease-smooth-out`. 값이 0이면 모션 없음. 번개 튐(`pulseKey`)은 U9에 남긴다.
- 로딩은 MODULAR `Skeleton`(높이 72), 오류는 지금 오류 분기의 짜임(상자 자체가 «다시 시도» 버튼), 안내는 서비스 `InlineNotice`, 버튼은 MODULAR `Button`(«받기» primary, «인벤토리 보기» outline)이다. 받기 결과는 `BadgeRevealOverlay`와 `toRevealBadges`를 쓴다.
- 홈 배치: 오늘의 현황 스트립 아래 `[챕터 N][게이지][안내 영역(조건부)]`. 프로필 배치: «가진 잼» 줄(`ProfileClient.tsx` 665줄)을 지우고 `ChapterLine`(8px 막대) 아래에 같은 캡슐 묶음을 둔다.
- 처리 파일: `RadialCapsule`·`CapsulePill`·`CapsuleSheet`와 시험, `JamBalance`, `capsule-sheet-signal.ts`는 삭제하고, `CapsuleWidget`은 다시 쓴다(상태 조회, 진입 모션 지휘, 안내 영역, 받기 흐름). `JamFillPanel.tsx`는 파일을 지우지 않고 화면 사용처만 없앤다(옛 `spike/capsule-fill`이 쓴다, U9 또는 U11에서 삭제). 옛 `app/spike/capsule/`(방사형 프로토타입)은 `RadialCapsule`과 함께 2회차에 삭제한다. `app/spike/capsule-fill/`은 U9 끝까지 둔다.
- 게이지가 100%에 머무는 순간은 «가득 찬 채 남음» 한 가지뿐이다(서버가 동기화 안에서 열거나 보류로 넘기고 새 빈 캡슐을 만든다). 보지 않은 결과(`capsule_unseen_results`)는 U8이 읽지 않고 따로 보이지도 않는다(U9 몫).
- 상태 표: 로딩(Skeleton), 오류(상자), 채움 중, 보류 1(받기), 보류 1과 단계 70·80·90(받기), 보류 있음과 빈칸 부족(인벤토리 보기, 받기는 숨김), 잼을 받을 수 없음(받기 또는 인벤토리 보기), 받는 중(비활성), 이용 정지(안내 없음, 홈은 `SuspensionBanner`), 가득 찬 채 남음(문구만).

**1회차(api)가 `CapsuleStatus`(`GET /api/capsule`, `getCapsuleStatus`)에 더할 필드**

| 필드 | 형 | 뜻 |
|---|---|---|
| `pendingCount` | `0 \| 1 \| 2` | 못 받은 보상 수 |
| `jamBlocked` | boolean | 보류 2개라 잼이 사라지는 상태(화면이 개수로 따지지 않게 서버가 정함) |
| `alertStage` | `0 \| 70 \| 80 \| 90` | `user_capsules.alert_stage`. 보류가 1개가 아니면 0. 소식과 같은 단계 규칙 |
| `claim` | `{ available: boolean; blockedReason: 'no_slots' \| 'suspended' \| 'no_tribe' \| null; freeSlots: number; neededSlots: number }` | 받기 버튼과 빈칸 줄. `neededSlots`는 가장 오래된 보류에서 나올 수 있는 최대 개수 |
| `notice` | `'none' \| 'pending' \| 'pending_nearly_full' \| 'jam_blocked' \| 'full_waiting'` | 안내 영역이 고를 문구를 서버가 하나로 정해 준다 |

`required`·`filled`는 게이지 값으로 그대로 쓴다. `balance`·`openable`·`notOpenableReason`은 옛 채우기·열기 API가 U11까지 있어 계약에 남기되 화면은 읽지 않는다. 홈의 «챕터 N»은 캡슐 계약에 넣지 않고 `page.tsx`가 `getMyChapter`(`lib/chapter/read.ts`)를 함께 읽는다. 받기 뒤에는 응답으로 상태를 계산하지 않고 `GET /api/capsule`을 다시 부른다.

**채원이 확인하지 못한 것과 가정**: `getMyChapter`가 U3 뒤 «다음 챕터까지» 비율을 캡슐 횟수로 계산하는지, `capsule-sheet-signal`을 보내는 쪽이 정말 없는지(전수 확인 안 함), 홈 본문 좌우 여백 16(너비 343) 가정, «가득 찬 채 남음»에서 트라이브가 없는 유저는 다음 동기화에도 열리지 않아 «다음 동기화 때 열려요»가 틀릴 수 있다(그래서 문구를 «캡슐이 가득 찼어요»로만 줄였다), 대비는 계산값(오렌지와 트랙 약 4.8:1, 흰 번개와 오렌지 약 3.4:1)이고 실측이 아니다.

**회차 조정**: 2회차에 옛 `spike/capsule/` 삭제를 넣고, 3회차는 묶음 간격·«가진 잼» 줄 삭제·프로필 시험이 남는 작은 회차가 된다. 확률 링크는 게이지 주변에 두지 않으므로 어떤 회차에도 새 링크가 없다. 푸터에 «확률 안내»가 홈과 프로필에 보이는지는 2·3회차에서 확인한다.
