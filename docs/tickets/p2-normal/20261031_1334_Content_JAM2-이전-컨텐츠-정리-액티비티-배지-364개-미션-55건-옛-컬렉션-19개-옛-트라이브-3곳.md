# [Content] JAM2 이전 컨텐츠 정리: 액티비티 배지 364개, 미션 55건, 옛 컬렉션 19개와 옛 레시피 3건, 옛 트라이브 3곳

## 핵심 요약

- 요구사항: JAM 2.0 이전에 만든 컨텐츠 가운데 더 필요하지 않은 것을 확인하고(조사), 사용자 지시(2026-10-31 «미션 두건은 삭제», «순서대로 실행해»)에 따라 정리한다.
- 구현 계획: 코드 변경은 없다. 공용 DB에 SQL 5건을 순서대로 실행했다(244 → 299 → 307 → 282 → 308). 새 계열을 넣는 245·248·290·291과 292·293은 정리가 아니라서 이번 범위에서 뺐다.
- 관련 파일: `jam-web/supabase/migrations/244_deactivate_activity_badges_outside_recycle.sql`, `299_delete_pre_jam2_gate_missions.sql`, `307_delete_remaining_two_missions.sql`, `282_retire_unused_collections_and_old_recipes.sql`, `308_retire_old_tribes.sql`, `docs/plan/jam2/12 JAM 2.0 오픈 전후 적용 순서.md`(4절 3·4·7·12번).

## 배경 / 문제 정의

12번 문서의 오픈 직전 SQL 가운데 정리에 해당하는 것들이 모두 미적용이었다. 사용자가 이 가운데 정리 대상을 확인하고 한꺼번에 실행하라고 지시했다. 공용 DB라서 실행 즉시 프로덕션에 반영된다.

### 주요 의사결정 / 핵심 메모

- **실행 방식**: 244·299·282는 파일의 본문과 같은 문장을 쓰되, 반복되는 배열과 주석을 줄이고 244는 DO 블록 하나로 묶어 실행했다. 판정 규칙(가드, 끝 검사)은 파일과 같다. 244는 파일이 «사전 백업 SELECT 결과를 티켓에 붙인다»고 한 부분을 백업 표 `gate_key_backup_20261031`로 대신했다(되돌림 ②는 이 표의 `gate_mission_badge`, `cross_between_axis`를 `condition_json`에 다시 넣는다).
- **미션 2건 삭제(사용자 결정)**: 299가 의도적으로 남긴 «그루터기 살롱의 겨울 채비»(2026-10-31 23:59 종료)와 «겹쳐진 도시의 새 얼굴»을 사용자가 삭제하기로 했다. 두 미션의 `today_cards` 4장은 외래 키가 `SET NULL`이라 카드가 남는다(모두 기간이 지났다). 보상 배지 2개(아이템 배지)는 그대로 남는다.
- **옛 트라이브**: SQL이 없어 새로 썼다(308). 소속 유저가 `dev-tester@jam.local`(스테이징 자동 로그인 계정)과 사용자 계정이라 영향을 먼저 읽었다. `tribes.is_active`는 관리자 화면과 콘텐츠 후보 필터에서만 쓰이고 소속 유저의 앱 사용을 막는 코드는 없다.
- **마이그레이션 번호**: 처음 300·301로 썼으나 원격 staging에 캡슐 마이그레이션이 이미 쓰고 있어 307·308로 바꿨다.
- **범위에서 뺀 것**: 새 계열 입력(245·248·291)과 포인트 일괄 적용(290)은 정리가 아니다. 이번에 만든 백업 표 5개와 기존 백업 표 4개(`bak20260907_missions_pre_v5_cleanup`, `poi_backup_144`, `content_overwrite_backup_20261022`, `badge_point_backup_289`)는 되돌림 근거라서 지우지 않았다.

### 잔여 이슈

- 244로 꺼진 배지 364개 가운데 42개는 유저 4명이 받은 기록(81건)이 있다. 기록은 남아 있지만 배지함에서는 보이지 않는다.
- 생성 타입(`database.generated.ts`)에는 새 백업 표 5개가 아직 없다. 12번 문서 6절 10번(출시 직후 재생성)에서 함께 반영한다.
- 오픈 전에는 245·248·290·291이 남아 있어 활성 액티비티 배지가 270개인 상태다(오픈 직전 목표 393개). 그 전에 main에 올리면 5-6 계열 등이 비어 나간다.
