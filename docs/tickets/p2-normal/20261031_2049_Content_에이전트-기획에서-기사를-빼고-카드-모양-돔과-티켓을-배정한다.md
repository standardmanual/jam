# [Content] 에이전트 기획에서 기사를 빼고 카드 모양 돔과 티켓을 배정한다

## 핵심 요약

- 요구사항(사용자, 2026-10-31): 에이전트의 기획에서 기사 방식을 제거하고, 카드 모양에 돔(`dome`)과 티켓(`ticket`)을 추가해 사용할 컨텐츠를 배정한다. 배정안은 사용자가 승인했다(«이대로 진행»).
- 구현: 코드 변경 없음. 에이전트가 읽는 패턴 사전(DB `ops_patterns`) 5행을 고치고, 문서 사본과 PRD, 윤진 정의를 맞췄다. 서비스의 기사 카드(`editorial_article`)와 `/today/[id]`는 그대로다.
- 관련 파일: `jam-web/supabase/seed_20261031_ops_patterns_no_article_dome_ticket.sql`, `docs/service/content/OPS_PATTERNS.md`(사본), `docs/service/prd/home-feed/PRD.md` §6, `docs/service/prd/ops-tool/PRD.md`(112·143·242·950줄 부근), `docs/service/prd/content-automation/PRD.md`(94줄 부근), `.claude/agents/jam-marketer.md`(모드 ⑨ 행).

## 배경 / 문제 정의

에이전트는 패턴 사전의 «쓰는 카드 모양»을 보고 홈피드 카드 모양을 고른다. 기사(`hero`)가 P04·P07·P10 세 패턴에 들어 있었고, 2026-10-22에 추가된 돔·티켓은 어느 패턴에도 배정되지 않아 에이전트가 쓸 수 없었다. 제출 형식 검증은 두 모양을 이미 허용한다(`CARD_SHAPES` 7종).

## 배정

| 모양 | 어울리는 내용 | 배정한 패턴 |
|---|---|---|
| `ticket` | 기간·시간이 정해진 것: 한정 미션, 날짜 예고, 회차 카드 | P02(하루 중 짧은 시간에만 열린다), P03(달력의 그날에만 열린다), P10(회차 카드, 막마다 한 장) |
| `dome` | 장소·집처럼 문이나 창을 여는 이미지 | P03(절기 컬렉션 소식), P04(궂은 날엔 집에서), P07(놓인 곳을 알려 준다: 지점 힌트) |

기사를 뺀 자리:

- P04: 기사(`hero`)를 `dome`으로 바꿨다. 원리·보상·조건의 «서사 읽기»를 «컬렉션 구경»으로 고쳤다(기사 없이는 서사를 읽는 행동이 없다).
- P07: 기사(`hero`)를 `dome`으로 바꿨다. 원리·손잡이·주의점의 «기사»를 «카드»로 고쳤다.
- P10: 기사(`hero`)를 `ticket`(회차 카드)과 `poster`(에필로그 카드)로 바꿨다. «홈피드 기사»·«에필로그 기사»를 «카드»로 고쳤다.

### 주요 의사결정 / 핵심 메모

- **경로**: 코드 변경이 없는 컨텐츠·문서 작업이라 Workflow 없이 카리나가 직접 처리했다. DB는 메인 세션이 백업과 롤백 실측 뒤 실행했다.
- **에이전트는 데이터로 배운다.** 루틴이 읽는 것은 DB의 패턴 사전이라 문서만 고치면 반영되지 않는다. `OPS_PATTERNS.md`는 사본이다(원천은 운영툴).
- **막지 않고 안내만 한다.** 제출 검증에 «기사 템플릿 거절» 경고는 넣지 않았다. 에이전트가 기사를 제안하지 않게 하는 장치는 패턴 사전의 문구와 윤진 정의의 한 줄이다. 어긋남이 보이면 `validate.ts`에 `resource.template_type`이 `editorial_article`일 때 경고를 더하는 작은 티켓을 만든다.
- 취향 신호 P16 «열독가(82)»의 «기사를 읽은 수»는 폐기한 방향의 기록이라 그대로 뒀다.
