# [Content] 에이전트 기획에서 기사를 빼고 카드 모양 돔과 티켓을 배정한다

## 핵심 요약

- 요구사항(사용자, 2026-10-31): 에이전트의 기획에서 기사 방식을 제거하고, 카드 모양에 돔(`dome`)과 티켓(`ticket`)을 추가해 사용할 컨텐츠를 배정한다. 배정안은 사용자가 승인했다(«이대로 진행»).
- 구현: 에이전트가 읽는 패턴 사전(DB `ops_patterns`) 5행을 고치고, 문서 사본과 PRD, 윤진 정의를 맞췄다. 2차(같은 날 사용자 지시 «기존 프리셋을 활용해서 프리셋을 만들어», «기사형 카드·컨텐츠를 생성하지 않도록 에이전트 설정을 변경해»): 이미지 프리셋 `홈피드 16:9`·`홈피드 4:5`를 만들고, 에이전트 정의·루틴 스펙에 기사 제외와 모양별 프리셋을 적고, 제출 검증이 기사형 카드(`resource.template_type = editorial_article`)를 형식 오류로 거른다. 서비스의 기사 카드와 `/today/[id]`는 그대로다.
- 관련 파일: `jam-web/supabase/seed_20261031_asset_presets_home_feed_ratios.sql`, `jam-web/src/lib/admin/opsInbox/validate.ts`(`validateOpsCardFields`), `.claude/skills/jam-work/references/scheduled-jobs.md`(새 체계 주간·월간 «기사 제외» 행), `jam-web/supabase/seed_20261031_ops_patterns_no_article_dome_ticket.sql`, `docs/service/content/OPS_PATTERNS.md`(사본), `docs/service/prd/home-feed/PRD.md` §6, `docs/service/prd/ops-tool/PRD.md`(112·143·242·950줄 부근), `docs/service/prd/content-automation/PRD.md`(94줄 부근), `.claude/agents/jam-marketer.md`(모드 ⑨ 행).

## 배경 / 문제 정의

에이전트는 패턴 사전의 «쓰는 카드 모양»을 보고 홈피드 카드 모양을 고른다. 기사(`hero`)가 P04·P07·P10 세 패턴에 들어 있었고, 2026-10-22에 추가된 돔·티켓은 어느 패턴에도 배정되지 않아 에이전트가 쓸 수 없었다. 제출 형식 검증은 두 모양을 이미 허용한다(`CARD_SHAPES` 7종).

## 배정

| 모양 | 어울리는 내용 | 배정한 패턴 |
|---|---|---|
| `ticket` | 기간·시간이 정해진 것: 한정 미션, 날짜 예고, 회차 카드 | P02(하루 중 짧은 시간에만 열린다), P03(달력의 그날에만 열린다), P10(회차 카드, 막마다 한 장) |
| `dome` | 장소·집처럼 문이나 창을 여는 이미지 | P03(절기 컬렉션 소식), P04(궂은 날엔 집에서), P07(놓인 곳을 알려 준다: 지점 힌트) |

기사를 뺀 자리:

- P04: 기사(`hero`)를 `dome`으로 바꿨다. 원리·보상·조건의 «서사 읽기»를 «컬렉션 구경»으로 고쳤다(기사 없이는 서사를 읽는 행동이 없다).
- P07: 기사(`hero`)를 `dome`으로 바꿨다. 원리·손잡이·주의점의 «기사»를 «카드»로 고쳤다.
- P10: 기사(`hero`)를 `ticket`(회차 카드)과 `poster`(에필로그 카드)로 바꿨다. «홈피드 기사»·«에필로그 기사»를 «카드»로 고쳤다.

### 주요 의사결정 / 핵심 메모

- **경로**: 코드 변경이 없는 컨텐츠·문서 작업이라 Workflow 없이 카리나가 직접 처리했다. DB는 메인 세션이 백업과 롤백 실측 뒤 실행했다.
- **에이전트는 데이터로 배운다.** 루틴이 읽는 것은 DB의 패턴 사전이라 문서만 고치면 반영되지 않는다. `OPS_PATTERNS.md`는 사본이다(원천은 운영툴).
- **차단 장치 셋**: 패턴 사전의 문구(에이전트가 읽는 재료), 윤진 정의와 주간·월간 루틴 스펙의 «기사 제외», 제출 검증의 형식 오류. 형식 오류는 저장은 하되 어드민에 형식 오류 신호를 띄운다(승인을 막지는 않는다). 기사형 카드를 사람이 운영툴에서 직접 고쳐 만들려 해도 같은 오류가 붙으므로, 운영자가 기사를 쓰려면 기존 투데이 카드 화면을 쓴다.
- **경로**: 검증 규칙은 ~8줄과 시험 3건이라 경미 수정 경로(카리나 직접)로 처리했고 게이트(민지)는 거치지 않았다. 패턴과 프리셋 데이터는 메인 세션이 실행했다.
- **프리셋의 로고 SVG는 기존 «홈피드» 프리셋의 저장 경로를 가리킨다.** 기존 프리셋의 레이어 파일을 지우면 새 프리셋의 로고도 사라진다.
- 취향 신호 P16 «열독가(82)»의 «기사를 읽은 수»는 폐기한 방향의 기록이라 그대로 뒀다.
