# [Feature] 연결 없이 쓰는 컨텐츠 소개 카드 유형을 추가한다

## 핵심 요약

- 요구사항: 미션·배지·컬렉션에 연결하지 않고 서비스 컨텐츠를 소개하는 홈피드 카드 유형 `content_intro`를 더한다. 카드에서 이동할 주소(`target_href`)는 필수다. 사용자 승인 2026-11-01.
- 구현 계획: DB CHECK 확장(마이그레이션 310), 타입·라벨·자원·어드민 폼·등록 검사·미리보기에 값을 더하고 시험과 문서를 맞춘다.
- 관련 파일: `jam-web/supabase/migrations/310_today_cards_content_intro.sql`(새 파일, 217의 ② 구간 형식), `jam-web/src/types/database.ts:1230`, `jam-web/src/lib/today/shape.ts:132-142`(`RESOURCE_BY_TEMPLATE`), `jam-web/src/lib/today/cardView.ts:37-47`(`LABEL_BY_TEMPLATE`), `jam-web/src/lib/i18n/ko.ts:491`, `jam-web/src/lib/today/targetHref.ts:51-82`, `jam-web/src/lib/admin/today-sections.ts:72-81,97-106,136-145`, `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts:94-105`, `jam-web/src/lib/admin/opsInbox/cardPreview.ts:22-30`, `docs/service/prd/home-feed/PRD.md`, `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md:138,170,184`, `docs/service/prd/02_DATA_MODEL.md:1496`

## 배경 / 문제 정의

날마다 전원 카드 5장 이상을 기획하려면 이야기·안내·기능 소개 카드가 많이 필요하다. 지금 등록 검사는 진행 알림(`progress_nudge`)에 배지나 미션을 요구해서, 시험 묶음 W45-c의 진행 알림 26장이 막혔다. 이 카드들은 「진행 알림」 칩도 내용과 맞지 않았다. 2026-11-03 정기 주간 루틴도 같은 문제를 만날 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 값은 `content_intro`, 어드민 라벨은 「컨텐츠 소개 (content_intro)」다. 필수 참조는 `target_href` 하나이고, 입력 칸은 설명문과 이동 주소만 연다(배지·미션·컬렉션 칸 없음).
- 자원은 `auto`로 묶지 않고 판단이 필요하면 채원 판정을 따른다. 자원 줄(필수 정보)은 없다.
- 추천 레이아웃은 `shortcut`이다. 모양은 `shape`로 정하고 `hero`·`poster`·`square`·`brief`·`dome`·`ticket`을 쓸 수 있다.
- 이동 주소 기본값은 두지 않는다(등록 검사가 필수로 막고, `targetHref.ts`의 `default`는 그대로 안전망이다).
- 옛 코드(main)는 모르는 템플릿을 오류 없이 그린다(`resourceOfTemplate` 안전망 주석). DB CHECK만 먼저 넓히는 확장 단계라 main에 영향이 없음을 마이그레이션 머리에 적는다.

### UI/UX 관점

- 칩 문구는 채원이 판정한다. 카리나 제안은 「소개」다. 칩 줄 라벨 6자 이내, 용어 규칙을 따른다.
- 새 카드 컴포넌트와 새 토큰을 만들지 않는다. 기존 7개 모양이 표시 데이터 그대로 그린다.

## 구현 계획

파일 수가 5개를 넘어 첫 호출부터 계획 반환 면제를 넘긴다.

1. 마이그레이션 310: `today_cards_template_type_check`를 10개 값으로 교체한다. 되돌림 SQL과 확인 SQL을 적는다. 실행은 카리나가 한다.
2. 타입 유니온, `RESOURCE_BY_TEMPLATE`, `LABEL_BY_TEMPLATE`, `ko.ts`, `TODAY_TEMPLATE_OPTIONS`, `SUGGESTED_LAYOUT_FOR`, 템플릿별 입력 칸, `REQUIRED_REFERENCE_FIELDS`, `cardPreview.ts`의 템플릿 목록에 더한다.
3. 시험: `shapeParity`·`cardView`·`today-sections`·`registerInput`·`homeFeedCard`·`registerHomeFeedBundle`에 사례를 더한다. `target_href` 없으면 오류, 있으면 통과를 고정한다.
4. Story: `BriefCard.stories.tsx`에 사례 하나를 더한다.
5. 문서: `node scripts/gen-home-feed-doc.mjs`로 생성 구간을 갱신하고 위 문서의 템플릿 수와 표를 고친다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- `content_intro` 카드는 `target_href`가 있으면 등록 검사를 통과하고 없으면 오류가 난다. 시험으로 고정한다.
- `brief`·`hero`·`ticket`·`poster`·`square`·`dome` 표시 데이터가 정해진 칩 문구로 만들어지고 자원 줄이 없다. 시험으로 고정한다.
- 어드민 폼에서 이 유형을 고르면 설명문과 이동 주소 칸이 열리고 배지·미션·컬렉션 칸은 없다.
- 마이그레이션 파일에 되돌림 SQL과 확인 SQL이 있다.
- `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 전)

- 마이그레이션 310을 실행하고 제약을 읽기로 확인한다.
- 메인 트리 어드민에서 W45-c의 이야기 카드를 이 유형으로 등록해(게재일 2027-12-31) 카드 생성과 미리보기를 확인한다.
- 윤진 정의 모드 ⑨에 이 유형과 등록 조건(템플릿별 필수 참조, 미션 소개와 돔 포스터형 충돌, 레시피 재료 칸, 랭킹 기준)을 적는다.
