# [Admin] 에셋 프리셋의 JAM 로고를 최신 로고로 바꾼다

## 핵심 요약

- 요구사항: 자동 제작 이미지에 들어가는 JAM 로고가 옛 로고였다. 최신 로고로 바꾼다(사용자 요청 2026-11-01).
- 구현 계획: 최신 로고를 저장소에 새 이름으로 올리고 프리셋 4개의 로고 레이어 `assetUrl`을 바꾼다.
- 관련 파일: `jam-web/supabase/seed_20261101_asset_presets_latest_logo.sql`, `docs/assets/brand/jam_logo.svg`, `docs/service/prd/asset-generator/PRD.md`

## 배경 / 문제 정의

3차 로고 교체(티켓 20261028_0944)는 코드의 글자 경로와 PNG만 바꿨다. 프리셋의 로고는 DB `asset_presets.layers`의 이미지 레이어가 저장소 파일을 가리키는 구조라 옛 로고(578×205)가 그대로 남았다. 최신 로고는 2610×865다.

## 완료 조건

- 프리셋 4개의 로고 레이어가 최신 로고 파일을 가리키고, 새로 만든 이미지에 최신 로고가 보인다.

## 완료 기록

### 구현 내용 요약

`docs/assets/brand/jam_logo.svg`를 저장소 `images/asset-generator/presets/{프리셋}/{레이어}-logo-20261028.svg` 2곳에 올렸고(받은 파일이 원본과 같음을 확인), 드라이런 뒤 프리셋 4개(홈피드·미션·홈피드 16:9·홈피드 4:5)의 `assetUrl`을 바꿨다. 옛 파일은 지우지 않았다. 되돌림 SQL은 SQL 파일 끝에 있다. 코드는 바꾸지 않았다.

### 테스트 결과
- [x] DB 확인: 4개 모두 새 경로를 가리키고 레이어 수는 그대로다(3·4·3·3개).
- [x] 다시 만든 16:9 `hero`와 4:5 `dome` 이미지를 받아 최신 로고 원본과 눈으로 대조했다(J의 긴 홈, A의 물방울 구멍).
- [ ] 미션 프리셋으로 새 이미지를 만들어 보지는 않았다.

### 주요 의사결정 / 핵심 메모
- 같은 경로에 덮어쓰지 않았다. 저장소 응답이 `max-age=3600`이라 옛 로고가 한동안 보일 수 있고, 옛 파일이 있어야 되돌리기 쉽기 때문이다.
- 로고 비율이 넓어져 같은 `widthPct`에서 로고 높이가 약 6.5% 줄었다. 크기 값은 바꾸지 않았다.
- 기간이 지나지 않은 실제 카드 가운데 이미지가 있는 카드와 이미지가 있는 진행 중 미션은 0건이다(2027년 시험 카드 제외, DB 조회). 옛 로고로 게재 중인 이미지는 없다.

### 잔여 이슈
- 시험 이미지는 모두 새 로고로 다시 만들었다(브라우저 창을 띄운 상태에서 실행, 2026-11-01).
- 시험 중 어드민 묶음 화면이 홈(`/`)으로 세 번 옮겨 갔다. 서버 오류는 없었고 미리보기 코드에 홈으로 보내는 호출도 없었다. 원인은 찾지 못했다(같은 창을 사용자도 볼 수 있어 사용자 조작일 수도 있다).

- 2026-11-09 종료 점검: 프리셋 4개(홈피드, 미션, 홈피드 16:9, 홈피드 4:5)의 로고 레이어 `assetUrl`이 공용 DB에서 모두 새 경로(`…-logo-20261028.svg`)인 것을 읽기로 확인하고 닫았다. 새 로고가 그려진 이미지의 육안 대조는 완료 기록을 따랐고 이번에 다시 그리지 않았다.
