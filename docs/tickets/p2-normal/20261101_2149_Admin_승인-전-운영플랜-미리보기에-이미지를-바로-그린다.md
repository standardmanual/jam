# [Admin] 승인 전 운영플랜 미리보기에 이미지를 바로 그린다

## 핵심 요약

- 요구사항: 운영플랜에서 승인 전 홈피드 카드도 실제 이미지가 보이게 한다. 이미지 지시(`image_spec`)가 있는 카드를 브라우저에서 바로 그리고 저장은 하지 않는다. 승인 후 만들어지는 이미지는 승인 전에 본 이미지와 같아야 한다. 사용자 승인 2026-11-01.
- 구현 계획: 항목 ID에서 고정 시드를 만들고, 그 시드로 렌더한 blob URL을 표시 데이터의 `imageUrl`에 넣는 클라이언트 훅을 더한다. 첫 제작은 같은 고정 시드를 쓴다.
- 관련 파일: `jam-web/src/components/admin/ops/OpsCardPreview.tsx:39-66`(항목 미리보기·안내 문구), `jam-web/src/components/admin/ops/preview/HomePreviewPanel.tsx`·`OpsHomeFeedPreviewRow.tsx`, `jam-web/src/lib/admin/opsInbox/homeFeedPreview.ts`(「홈피드로 보기」), `jam-web/src/components/admin/ops/useItemImageProduction.ts:39-64,84-104,107-`(`newSeed`·`produceItemImage`·`produceItemImages`·`start`), `jam-web/src/lib/admin/opsInbox/imageRender.client.ts:161`(`renderPresetToPngBlob`), `jam-web/src/lib/admin/opsInbox/imageSpec.ts:43`(`imageSpecToRenderArgs`), `jam-web/src/components/today/CardImageSlot.tsx`, `jam-web/src/components/SafeImage.tsx`(blob 주소는 일반 img로 그린다), `docs/service/prd/ops-tool/PRD.md`(§412 카드 미리보기, 1405 이미지 만들기)

## 배경 / 문제 정의

지금은 사용자가 승인과 예약을 누른 뒤에야 이미지가 처음 만들어져서, 승인 전 미리보기는 이미지 자리가 비어 있다. 사용자는 승인하기 전에 이미지를 보고 판단해야 한다. 렌더 엔진은 이미 브라우저에서 돌아가므로 저장 없이 그릴 수 있다. 시드가 제작 때마다 무작위라서 무늬를 맞추려면 시드를 고정해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 대상: 기획 상세 왼쪽 미리보기, 일정표 서랍, 「홈피드로 보기」의 `home_feed_card` 항목 가운데 저장된 이미지가 없고 `image_spec.preset_id`가 있는 카드. 시험 묶음도 포함한다. 미션·배지·컬렉션은 이번 범위가 아니다.
- 저장소와 DB에 쓰지 않는다. 카드 데이터(`cover_image_url`)도 바꾸지 않는다.
- 저장된 이미지가 있으면 그대로 그것을 보인다.
- 고정 시드: 항목 ID를 해시한 값(`imageSpec.ts`에 순수 함수로 둔다). `produceItemImage`의 기본 시드와 「이미지 만들기」(이미지가 없을 때)는 이 값을 쓰고, 「이미지 다시 만들기」는 지금처럼 새 무작위 시드를 쓴다.
- 색이 없는 카드(`bg`·`end` 없음, 「색 대기」)도 미리보기에서는 임시 중립색으로 그린다. 실제 제작 규칙은 바꾸지 않는다.
- 렌더는 한 번에 한 장씩 하고 입력(프리셋·색·문구·시드)을 키로 캐시한다. 수정 초안의 문구가 바뀌면 400ms 뒤 다시 그린다. 쓰지 않는 blob URL은 해제한다.
- 렌더가 실패하면 지금처럼 자리 표시로 두고 화면을 깨뜨리지 않는다. 승인을 막지 않는다.

### UI/UX 관점

- 어드민 화면이라 MODULAR 판정 대상이 아니고 shadcn 기준을 따른다.
- 안내 문구: 그리는 동안 「이미지를 그리는 중이에요」. 다 그린 승인 전 이미지는 「승인하면 이 이미지로 만들어요」. 임시 색이면 「색이 정해지지 않아 임시 색으로 보여요」. 지시가 없으면 지금 문구를 유지한다.

## 구현 계획

파일 수가 5개를 넘어 첫 호출부터 계획 반환 면제를 넘긴다.

1. `imageSpec.ts`: `stableImageSeed(itemId)`와 `previewRenderArgs(spec, itemId)`(임시 색 여부를 함께 돌려준다)를 더한다.
2. 새 훅 `components/admin/ops/useDraftImagePreview.ts`: 입력 키 캐시, 순차 렌더, blob URL 관리, 400ms 지연.
3. `OpsCardPreview.tsx`: 훅 결과를 `preview.view.imageUrl`에 넣고 안내 문구를 바꾼다.
4. `homeFeedPreview`·`OpsHomeFeedPreviewRow.tsx`: 승인 전 카드에 같은 훅을 적용한다.
5. `useItemImageProduction.ts`: 첫 제작은 고정 시드, 다시 만들기는 새 시드.
6. 시험과 PRD를 고친다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 같은 항목 ID는 같은 시드를 만들고, 첫 제작이 그 시드를 쓰며 다시 만들기는 다른 시드를 쓴다. 시험으로 고정한다.
- 저장된 이미지가 있거나 `preset_id`가 없으면 렌더를 호출하지 않는다. 시험으로 고정한다.
- 미리보기는 저장 API를 부르지 않는다. 시험으로 고정한다.
- 색이 없을 때 임시 색과 안내 문구가 나오고, 렌더가 실패하면 자리 표시로 돌아간다. 시험으로 고정한다.
- PRD가 새 동작과 일치한다. `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤 push 전)

- 메인 트리 어드민에서 W45-c의 기획 상세와 「홈피드로 보기」에 이미지가 보이는지 확인한다.
- 승인 전 미리보기와 승인 후 제작 이미지가 같은지 시험 카드로 대조한다(게재일 2027-12-31).
