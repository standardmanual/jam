# [Infra] 트렌드 자료 폴더를 하나로 합치고 주제별로 나눈다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-02): 자료 폴더를 하나로 통합하고 주제로 나눈다. 에이전트가 트렌드 리서치를 할 때 주제별로 자료를 수집하도록 구조를 만든다(인기 있는 체크인 스팟, 리테일의 유행 먹거리, 밈과 은어, 그 밖의 발견). 주제는 등록된 체크인 장소 카테고리를 활용한다.
- 구현 계획:
    1. `docs/operations/trendresearch/` 하나로 합치고 `places`·`sports`·`service`·`culture` 그룹 아래 주제 폴더(`latest.md`, `archive/`, `notes/`)를 둔다. 주제 표와 규칙은 그 폴더의 `README.md`가 단일 원천이다.
    2. 옛 사용자 제출함 `docs/operations/inbox/trends/`는 없앤다(자료 파일은 없었고 README만 있었다).
    3. 기존 메일 기반 회차 한 건(2026-10-27)은 `culture/` 아래 네 주제의 `archive/`로 나눠 옮긴다.
    4. 훅 ⑩, 슬롭 검사 제외 경로, 계약 파일, 문서 지도, 에이전트 정의, 루틴 규칙의 경로와 읽기 규칙을 바꾼다.
- 관련 파일: `docs/operations/trendresearch/README.md`, `.githooks/pre-commit`(⑩ 규칙), `scripts/check-slop.mjs`, `scripts/check-slop.test.mjs`, `docs/agents/contract.json`, `CLAUDE.md`, `docs/README.md`, `.claude/skills/jam-work/references/scheduled-jobs.md`(저장 위치와 읽기 상한, 월간 절), `.claude/skills/jam-story/references/marketer-trends.md`, `.claude/agents/jam-marketer.md`·`jam-tribe.md`
- 이 티켓이 함께 해결하는 것: 티켓 `20261028_1428`(저장소 폴더 출처를 월간 루틴이 읽는 규칙), `20260930_1518`(사용자 제출 폴더와 루틴 연결)의 읽는 규칙 부분.
- 이 티켓이 하지 않는 것: 월간 루틴 저장 프롬프트 교체(공용 자원이라 사용자 허용이 필요하다), 패턴 사전에 주제 칸을 더하는 일, 장소·집계 읽기 도구 추가.

### 주요 의사결정

- 폴더는 `trendresearch/` 하나로 정했다. 트렌드 레이더 출처 «저장소 폴더»의 허용 폴더(`OPS_TREND_SOURCE_FOLDERS`)가 이 경로 하나라서 코드를 바꾸지 않아도 된다.
- 장소 그룹의 폴더 이름은 DB의 `poi_categories.slug`를 그대로 쓴다. 목록의 원천을 DB 하나로 두고, README에는 수집 우선 카테고리만 적었다.
- 주기는 일 단위로 정했다(7일 7개, 14일 6개, 28일 15개 주제). 주간 수집 루틴이 매주 월요일에 가장 오래된 주제부터 15개까지 수집한다. 처음에는 월간 수집으로 정했고, 사용자가 «세상이 빨리 변한다»며 더 빠른 주기를 요구해 매일로 올렸다가 «1주일에 한번이면 될듯해»라고 해서 주 1회로 정했다. 값은 임시이고 실측 뒤 다시 정한다.
- 주간 편성은 그날 고른 주제의 폴더만 읽는다.

### 잔여 이슈

- 월간 저장 프롬프트는 바꾸지 않는다. 주제별 수집은 새 주간 트렌드 수집 루틴(티켓 20261102_1410)이 맡는다. 예약 루틴의 커밋은 `.githooks/pre-commit`이 `docs/operations/reports/` 안으로 제한하므로, 그 루틴이 쓰려면 훅 예외도 필요하다(1410에서 다룬다).
- 메일에서 회차 파일을 만드는 주체는 저장소에서 확인하지 못했다(1회 기록뿐). 다음 회차는 `culture/` 주제별로 쓰도록 안내해야 한다.
- 패턴 사전에 «주제» 칸을 더하는 일(DB 열, 화면 이름 «패턴»), 장소·집계 읽기 도구, 카드 설명 규칙(조건표 방식)은 별도 티켓이다.
- 티켓 `20261028_1428`, `20260930_1518`의 읽는 규칙 부분은 이 티켓이 대신한다. 닫기는 사용자 승인 뒤에 한다.
