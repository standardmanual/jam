# [Infra] 트렌드 수집은 Muse로, 작성은 주간 루틴으로 나눈다

> 상위: 20261102_1355 · 관련: 20261102_1410

## 핵심 요약

- 요구사항(사용자 지시 2026-11-02): 트렌드 리서치(수집)와 저장(작성)을 다른 AI로 나눈다. 시험 비교 없이 바로 나누고, 수집 AI는 Muse로 한다.
- 구현 계획: 수집은 Muse가 한다. 이번 주 요청문은 `node scripts/trend-requests.mjs`가 README 주제 표와 `latest.md`의 `확인일`로 만든다. 결과는 카리나가 주제 폴더의 `notes/`에 올리고, 주 1회 루틴(월요일 05:00)이 `notes/`만 읽어 `latest.md`를 쓴다. 루틴은 웹 검색을 하지 않는다.
- 분리 이유: 루틴의 웹 검색 도구는 미국 한정이라 한국어 자료가 얇았고, WebFetch는 허용 도메인 밖에서 막혔다. 정식 1회 실행은 15개 중 7개만 기록했다.
- 관련 파일: `docs/operations/trendresearch/README.md`(1·3·4·5절), `.claude/skills/jam-work/references/scheduled-jobs.md`(「트렌드 수집」 절), `scripts/trend-requests.mjs`·`scripts/trend-requests.test.mjs`, `.claude/skills/jam-story/references/marketer-trends.md`

## 완료 조건

- `node scripts/trend-requests.test.mjs`가 통과하고, 실제 저장소에서 기한이 지난 주제와 요청문이 나온다.
- README와 루틴 규칙 절이 같은 역할 분담(Muse 수집, 루틴 작성)을 말한다.
- 사용자가 허용하면 루틴 저장 프롬프트를 작성 전용으로 바꾸고 웹 도구를 뗀다.

### 주요 의사결정

- 시험 비교는 하지 않았다(사용자 지시). 수집 AI의 품질은 첫 결과를 보고 판단한다.
- Muse를 외부 AI(이 저장소의 에이전트가 아님)로 다룬다. 접근 방식은 앱에서 직접 쓴다(사용자 확인 2026-11-02). 그래서 API 자동화(GitHub Actions)는 하지 않는다.
- 요청문은 코드(스크립트)가 만들고, 올리기는 카리나가 한다. Muse 앱은 한 번에 긴 요청이 부담이라 주제 5개씩 묶어 붙여 넣는다.

### 잔여 이슈

- 루틴 저장 프롬프트는 아직 검색 방식 그대로다. 규칙 절이 우선한다고 적혀 있어 동작은 절을 따르지만, 프롬프트와 허용 도구(WebSearch·WebFetch) 교체는 사용자 허용이 필요하다.
- Muse의 한국어 검색·출처 제공 능력은 첫 결과를 보고 판단한다.
