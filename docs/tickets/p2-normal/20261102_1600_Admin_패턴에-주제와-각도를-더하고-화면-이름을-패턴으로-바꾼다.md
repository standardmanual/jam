# [Admin] 패턴에 주제와 각도를 더하고 화면 이름을 «패턴»으로 바꾼다

> 상위: 20260930_1503 (운영툴 패턴 사전과 학습 기능)

## 핵심 요약

- 요구사항(사용자 지시 2026-11-02): 홈피드 기획을 «주제를 정해 두고 그날의 상황에 맞춰 세부 컨텐츠를 정한다»는 방식으로 바꾼다. 별도 메뉴를 만들지 않고 패턴 사전(이름은 «패턴»)에 통합한다. 주제 패턴은 `topic`과 샘플 각도 `angles`(JSON 배열, 각 항목 `{ type, title, note, needs[] }`)를 가진다. 기존 원리형 패턴 P01~P18은 `topic`이 NULL이고 `angles`가 빈 배열이다.
- DB는 끝났다: 마이그레이션 311(칸 추가)과 312(주제 패턴 P19~P39 21행)가 적용됐고 `src/types/database.generated.ts`에도 반영됐다. 이 티켓은 **코드와 화면만** 맡는다.
- 구현 계획(파일 단위):
  1. 읽기: `lib/admin/opsPatterns/read.ts`의 `OPS_PATTERN_COLUMNS`(29행)·`OpsPatternRecord`(36행)·`OpsPatternRow`(78행)·`toPatternRecord`(116행)에 `topic: string | null`, `angles: Json`을 더한다.
  2. 입력 검사: `input.ts`에 `topic`(선택, 빈 문자열은 NULL, 영문 소문자·숫자·`/`·`-`만, 60자 이내)과 `angles`(선택 배열, 항목마다 `type`은 `소개|유도|미션|큐레이션|현황|회고|이야기`, `title`·`note`는 필수 텍스트, `needs`는 `places|place-stats|badges|item-paths|trends|kpi` 부분집합)를 `pitfalls`·`cardShapes`와 같은 방식(`readOptionalText`, 줄 번호 오류 키 `angles.N.title`)으로 더한다. 허용 목록 상수는 `constants.ts`에 둔다.
  3. 쓰기: `write.ts`의 `samePatternContent`(97~100행 부근)와 insert(166행)·update(233행)에 두 칸을 더한다. 새로 만드는 패턴 번호는 지금처럼 가장 큰 번호 다음이다.
  4. API: `app/api/admin/ops-patterns/route.ts`와 `[patternNo]/route.ts`의 `CONTENT_KEYS`(30행)에 `topic`·`angles`를 더한다. `GET /api/admin/ops-patterns`는 쿼리 `topic`(정확히 일치) 또는 `topic=none`(원리형만)으로 거를 수 있어야 한다. 읽기 토큰으로도 쓸 수 있다(기존 `requireAdminRead`).
  5. 목록: `listView.ts`의 `PatternListRow`·`buildPatternRows`에 `topic`과 `angleCount`를 더하고, `OpsPatternList.tsx`가 주제 이름표와 각도 개수를 보인다. 목록 위에 «전체·원리형·주제형» 거름을 둔다(`listView.ts`의 파라미터와 `parsePatternListParams`에 `kind` 추가).
  6. 상세: `detailView.ts`에 `readAngleLines(angles)`를 `readCardShapeLines`와 같은 방식(배열이 아니면 null, 깨진 항목은 숨기지 않음)으로 만들고, `OpsPatternDetail.tsx`에 «샘플 각도» 구역을 더한다. 각도는 종류별로 묶어 보여 주고 `needs`는 작은 이름표로 보인다.
  7. 폼: `formDraft.ts`(`PatternDraft`·`draftFromRecord`·`draftToInput`·`FIELD_LABEL`·`PatternFormSectionId`)와 `OpsPatternForm.tsx`·`OpsPatternFormParts.tsx`에 «주제»(기본 구역의 텍스트 칸)와 «샘플 각도»(행 추가·삭제, 종류는 shadcn Select, 제목·설명은 Input/Textarea, 재료 필요는 체크 모음) 구역을 더한다. 어드민 UI는 shadcn/ui 표준이다(네이티브 select 금지).
  8. 이름 변경: 화면과 API 응답에 노출되는 «패턴 사전»을 «패턴»으로 바꾼다(`components/admin/adminNavItems.ts`, `app/admin/ops-patterns/page.tsx`, `OpsPatternList.tsx`, `OpsPatternDetail.tsx`, `OpsPatternProposalsStrip.tsx`, `OpsCommonRulesView.tsx`, `OpsDecisionWorkspace.tsx`, `OpsItemActions.tsx`, `read.ts`의 메시지 상수, 두 API route.ts의 머리 주석, 그리고 이 문구를 단언하는 `__tests__` 파일). 라우트 경로 `/admin/ops-patterns`와 API 경로는 바꾸지 않는다.
  9. 문서: `docs/service/content/OPS_PATTERNS.md`·`docs/service/prd/ops-tool/PRD.md`·`docs/service/prd/content-automation/PRD.md`에 주제 패턴과 각도 설명을 한 절씩 더하고 «패턴 사전»을 «패턴»으로 바꾼다. 역사 문서(`docs/archive/`, 지난 티켓, 보고서)는 고치지 않는다.
  10. 시험: 위 입력 검사, 쓰기 변경 감지, 목록 거름, `readAngleLines`, 이름 변경으로 깨지는 기존 단언을 고친다.
- 관련 파일: 위 경로. 시드 원천은 `scripts/data/ops-pattern-topics.json`과 `scripts/ops-pattern-topics-seed.mjs`(읽기만, 바꾸지 않는다).

## 배경 / 문제 정의

운영 기획은 지금 «패턴(원리) → 묶음» 순서라 어떤 주제를 어떤 날에 낼지 정하는 틀이 없다. 사용자가 주제를 먼저 정하고 그날의 상황(트렌드, 재료, 계절)에 맞춰 세부 컨텐츠를 고르는 방식을 원했다. 주제와 샘플 각도를 패턴에 담아 에이전트(윤진)가 읽고 새 각도를 만들도록 한다. 각도는 예시일 뿐 닫힌 목록이 아니다.

## 완료 조건

- `GET /api/admin/ops-patterns`가 모든 패턴에 `topic`·`angles`를 싣고, `?topic=sports/run`은 그 주제만, `?topic=none`은 원리형 18개만 돌려준다.
- 패턴을 만들거나 고칠 때 `topic`·`angles`를 보낼 수 있고, 잘못된 각도 종류·필요 재료·빈 제목은 400과 줄 번호가 있는 오류 메시지로 거절된다. 값이 같으면 변경 없음으로 처리한다.
- `/admin/ops-patterns` 목록에서 주제 이름표와 각도 개수가 보이고 «전체·원리형·주제형» 거름이 동작한다. 상세에 «샘플 각도» 구역이 종류별로 보이고, 폼에서 주제·각도를 추가·삭제·저장할 수 있다.
- 화면과 메시지 어디에도 «패턴 사전»이 남지 않는다(역사 문서 제외). 라우트·API 경로는 그대로다.
- `npm run typecheck`, 관련 vitest, `scripts/verify.sh`가 통과한다. 로컬 `next dev`에서 목록·상세·폼을 열어 렌더를 확인한다(카리나가 머지 뒤 push 전에 한다).
