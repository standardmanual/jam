# [API] 윤진이 장소와 배지 재료를 읽는 읽기 API 두 개를 만든다

> 상위: 20260930_1503 (운영툴 패턴 사전과 학습 기능). 같은 날 티켓 20261102_1600(패턴 화면)과 파일이 겹치지 않는다.

## 핵심 요약

- 요구사항(사용자 지시 2026-11-02): 주제 패턴(`ops_patterns.angles[].needs`)이 가리키는 재료 중 `places`·`place-stats`·`badges`를 에이전트가 읽을 수 있게 한다. `item-paths`(컬렉션별 얻을 길)와 `trends`·`kpi`는 이미 있다. 읽기 전용이고 읽기 토큰(`requireAdminRead`)으로 쓴다. 쓰기 메서드는 두지 않는다.
- 구현 계획:
  1. `GET /api/admin/ops-places` (새 `app/api/admin/ops-places/route.ts`, 계산은 `lib/admin/opsPlaces/`에 둔다).
     - 쿼리 없이 부르면 **카테고리 요약**: `[{ slug, label, placeCount, checkinBadgeCount, dropCount, pickupCount }]`. `poi_categories`와 `poi`, 체크인 배지가 연결된 장소 수(`badges`의 장소 연결 칸, 실제 칸 이름은 스키마에서 확인), `poi_drops`의 드랍 수와 픽업 수(상태 칸으로 구분)를 합친다.
     - `category=<slug>`를 주면 **그 카테고리 장소 목록**: `[{ id, name, category, hasCheckinBadge, dropCount, pickupCount, region? }]`. `q`(이름 포함), `limit`(1~100, 기본 30), `offset`, `sort=drops|name`(기본 drops)을 받는다. 잘못된 값은 400이고 읽지 않는다.
     - 장소 좌표·주소 등 위치 전체를 싣지 않는다(지역 구분에 필요한 시·구 수준까지만). 읽지 못한 원천이 하나라도 있으면 500이다(비어 있는 값으로 바꿔 숨기지 않는다).
  2. `GET /api/admin/ops-badges` (새 `app/api/admin/ops-badges/route.ts`, `lib/admin/opsBadges/`).
     - 액티비티 배지 계열 목록: `[{ family, name, tiers: [{ tier, conditionSummary, earnedCount }], hidden }]`. **숨김 배지는 응답에서 제외한다.** 획득 수는 `user_activity_badges`를 계열·단계별로 센 집계이며 **유저 ID를 싣지 않는다**. 조건 요약은 기존 `badge_metric_labels`·배지 조건 읽기 도구(`lib/admin/badge*`)가 있으면 그것을 쓰고, 없으면 조건 JSON을 사람이 읽는 한 줄로 바꾸는 함수를 `lib/admin/opsBadges/`에 만든다.
     - 쿼리 `family`(이름 포함), `limit`(1~100, 기본 30), `offset`.
  3. `scripts/ops-read.mjs`의 `READ_TARGETS`에 `places: '/api/admin/ops-places'`, `badges: '/api/admin/ops-badges'`를 더하고 `scripts/ops-read.test.mjs`를 맞춘다. `.claude/skills/jam-work/references/ops-weekly.md`·`scheduled-jobs.md`의 읽기 도구 목록(있다면)에 두 이름을 더한다.
  4. 시험: 각 route의 `__tests__/route.test.ts`(인증 거절·쿼리 검사·집계 모양·유저 ID 미노출·숨김 배지 제외)와 순수 함수 시험.
- 관련 파일: `app/api/admin/item-paths/route.ts`(인증·쿼리 읽기·500 처리 모범), `app/api/admin/poi-categories/route.ts`, `lib/admin/auth`(`requireAdminRead`), `src/types/database.generated.ts`의 `poi`·`poi_categories`·`poi_drops`·`badges`·`user_activity_badges`·`user_checkin_badge_earns`, `scripts/ops-read.mjs`(READ_TARGETS)·`ops-read.test.mjs`, `docs/service/prd/ops-tool/PRD.md`(읽기 API 목록 절).

## 배경 / 문제 정의

윤진이 장소 주제(체크인과 장소, 드랍과 픽업)와 액티비티 배지 주제로 카드를 기획하려면 «어떤 카테고리에 장소가 몇 곳 있고 어디에 드랍이 놓였는지», «어떤 배지 계열이 몇 명에게 받아졌는지»를 읽어야 한다. 지금은 읽기 도구가 없어 추측으로 쓰거나 DB를 직접 봐야 한다. 현황 기준으로 장소는 2,081곳(체크인 배지 연결 1,836곳: 지하철역 946, 산 847, 미슐랭 42, 동호회 1)이고 드랍 1,180건, 픽업 125건이다.

## 완료 조건

- `GET /api/admin/ops-places`(쿼리 없음)가 카테고리 요약을 돌려주고, 장소 수 합계가 DB의 `poi` 행 수와 같다(시험 또는 SQL 대조).
- `GET /api/admin/ops-places?category=mountain&limit=5`가 산 장소 5곳과 드랍·픽업 수를 돌려준다. 잘못된 `limit`·`sort`는 400이다.
- `GET /api/admin/ops-badges`가 숨김 배지를 제외한 계열 목록과 단계별 획득 수를 돌려주고, 응답 어디에도 유저 ID가 없다.
- 두 API 모두 읽기 토큰과 관리자 세션으로만 열리고 인증 없는 요청은 거절된다. POST 등 쓰기 메서드는 없다.
- `node scripts/ops-read.mjs places`·`badges`가 허용 목록 이름으로 동작하고 시험이 통과한다.
- `npm run typecheck`와 관련 vitest, `scripts/verify.sh`가 통과한다.
