# [UI] 아직 얻지 못한 아이템 배지를 회색 실루엣과 실제 이름으로 보여준다

## 핵심 요약

- 요구사항: 아이템북·컬렉션 화면에서 아직 얻지 못한 아이템 배지(`undiscovered`)는 지금 «흐린 흑백 원본 그림 + 이름 `???`»으로 나온다. 이를 **등록된 이미지의 가장 바깥 윤곽만 따서 회색 한 가지 색으로 채운 실루엣 + 배지의 원래 이름**으로 바꾼다. 디자인시스템(MODULAR) 원본과 서비스 컴포넌트를 함께 바꾼다.

## 배경 / 문제 정의

- 현재: `undiscovered` 카드는 원본 그림을 `grayscale + opacity-40`으로 흐리게 보이고(서비스는 카드 전체에 `opacity-30`도 더한다) 이름 자리에 `???`를 찍는다.
- 기대: 어떤 이름의 배지가 있는지는 알려 주고(수집 목표가 보이도록), 그림은 윤곽만 보여 «아직 못 얻은 칸»임을 한눈에 구분한다.
- 이전 결정과의 관계: 2026-09-06에 사용자가 «미획득 배지는 원본 그레이»로 되돌린 적이 있다(커밋 `2a6bad2c3`, 당시 폐기된 것은 모든 배지가 같은 모양인 공통 SVG 실루엣 `BadgeSilhouette`). 이번 요청은 **배지마다 자기 이미지의 윤곽을 딴다**는 점이 다르고, 사용자가 직접 지시한 새 결정이다. 적용 범위는 `undiscovered`(아이템북 미발견 칸)만이고, `earned={false}`(액티비티 배지의 미획득)는 기존 «원본 + grayscale» 그대로 둔다.
- 알아 둘 사실(2026-11-02 실측): DB의 아이템 배지 1,971개 중 이미지가 등록된 것은 171개뿐이고, **활성 컬렉션(15개, 540개 배지)은 이미지가 0개**다. 등록된 171개 중 배경이 투명한 것은 `factions/03-xx` 계열(72개)뿐이고, `factions/02-xx`·`tribes/01-xx` 계열은 배경이 불투명이다(알파 0%). 불투명 이미지에 실루엣을 걸면 네모가 되므로 임시 등록은 투명 배경 이미지로만 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 실루엣은 **원본 `<img>` 하나를 그대로 쓰고 CSS로 만든다**(새 에셋·캔버스·서버 처리 없음). 기본 방법은 `filter: brightness(0)`으로 불투명 픽셀을 모두 검정으로 만든 뒤 `invert()`로 원하는 회색을 맞추는 것이다. 알파 채널이 그대로 남으므로 이미지의 가장 바깥 윤곽이 실루엣이 된다. 안쪽 투명 구멍은 그대로 비는 것을 허용한다(바깥 윤곽 우선).
- 마스크(`mask-image`) 방식은 이미지 호스트의 CORS 설정에 의존하므로 쓰지 않는다. 불가피하게 다른 방법이 필요하면 채원①이 사유와 함께 판정한다.
- 회색 값은 하드코딩 색 리터럴이 아니라 디자인 토큰과 맞는 값으로 정한다(`src/components/__tests__/commonLiteralColors.test.ts`가 지켜진다). 필터로는 토큰을 직접 못 쓰므로, 채원①이 토큰과 같은 밝기의 `invert` 값 또는 토큰 사용 방식을 정해 준다.
- 이름 줄은 `undiscovered`여도 `name`을 그린다. `<img>`의 `alt`도 `name`이다(`'???'` 제거). 단 `locked`(잠긴 아이템 배지)는 지금처럼 이름·그림을 절대 그리지 않는다 — 건드리지 않는다.
- `undiscovered`일 때 등급 칩은 지금처럼 그리지 않는다(이번 범위에서 바꾸지 않는다).
- 이미지가 없는 배지(`imageUrl` 비어 있음)는 지금처럼 `MedalIcon` 대체 그림이 나온다. 이 경우 아이콘도 회색 계열이므로 별도 처리하지 않는다.
- `SlotGrid.tsx`의 `className={isUndiscovered ? 'opacity-30' : ''}`는 걷어낸다. 카드 전체를 30%로 흐리게 하면 이제 읽혀야 하는 이름이 거의 안 보인다. 미발견 칸의 구분은 실루엣의 회색이 맡는다.
- 디자인시스템 사본과 서비스 컴포넌트는 별도 구현(병존)이다. 두 곳의 동작·문구를 같은 커밋에서 맞춘다.

### UI/UX 관점

- 미발견 칸: 회색 한 가지 색의 윤곽 + 배지 이름(획득한 칸과 같은 글자 굵기·색). 흐림(opacity)·흑백 원본·`???`는 쓰지 않는다.
- 같은 화면에서 획득한 칸(원본 컬러), 후보가 있는 칸(추가 버튼), 미발견 칸(실루엣)이 서로 구분되어야 한다.
- 텍스트는 새로 늘지 않는다(기존 이름을 그대로 노출). 새 문구가 생기면 UX Writing 가이드를 따른다.

### 컨텐츠 관점

- 활성 컬렉션 배지에 이미지가 없어 화면에서 결과를 볼 수 없으므로, 후속 범위로 임시 이미지를 등록한다(아래).
