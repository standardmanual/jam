# [API] 윤진이 읽는 장소 재료에 지역과 활성 구분을 더하고 배지 재료에 배지 ID를 싣는다

> 상위: 20260930_1503 (운영툴 패턴과 학습 기능). 티켓 20261102_1602가 만든 읽기 API 두 개의 한계를 푼다.

## 핵심 요약

- 요구사항(사용자 지시 2026-11-02 «재료의 한계를 해결할 수 있는 방법을 기획하고 개발해»): 윤진이 읽는 재료의 한계 세 가지를 푼다.
  1. 장소에 지역(시·도, 시·군·구) 칸이 없어 «이 동네의 산», «이 구의 역» 같은 지역 카드를 기획할 수 없다.
  2. 배지 읽기 응답에 배지 ID가 없어 `badge_spotlight` 카드(`card.badge_ids` 필수)를 기획할 수 없다.
  3. 장소 수에 비활성(`is_active=false`)과 검수 대기(`pending_review=true`) 장소가 섞여 있다(현황: 병원 303, 음식점 169 등이 비활성).
- 결정(카리나 설계, 2026-11-02):
  1. **DB(확장 단계만)**: `poi`에 `sido text NULL`, `gu text NULL`을 더한다(마이그레이션 313, 되돌림 SQL 동반). 기존 행과 코드는 영향이 없다.
  2. **채움 스크립트**: `scripts/backfill-poi-region.mjs`. 좌표를 `src/lib/poi/reverse-geocode.ts`의 NCP 역지오코딩(`{ sido, gu, dong }`)으로 바꿔 `sido`·`gu`를 채운다. 기본은 드라이런이고 `--apply`가 있을 때만 쓴다. 이미 채워진 행은 건너뛴다. 초당 5건 이하로 호출한다. 실패한 행은 NULL로 두고 개수와 id 목록(최대 20개)만 출력한다. **이 스크립트는 아현이 파일과 시험까지만 만들고 실행하지 않는다**(NCP 호출과 DB 쓰기는 메인 세션이 한다).
  3. **ops-places API**: `placeCount` 등 모든 수치를 기본으로 `is_active=true AND pending_review=false`만 센다. 요약 행에 `inactiveCount`·`pendingReviewCount`를 따로 싣는다. 쿼리 `status=active|inactive|pending|all`(기본 `active`), `sido`·`gu`(정확히 일치) 거름을 더한다. 장소 목록 행에 `sido`·`gu`를 싣는다(없으면 null). `groupBy=region`이면 `[{ sido, gu, placeCount, checkinBadgeCount, dropCount, pickupCount }]`를 돌려준다(`category`를 함께 주면 그 카테고리만). 좌표·주소·`dong`은 싣지 않는다. 잘못된 값은 400이다.
  4. **ops-badges API**: 단계 항목에 `badgeId`(해당 단계 배지 행의 UUID)를 더한다. 숨김 배지 제외와 «유저 ID 미노출»은 그대로다. 윤진은 이 값을 `card.badge_ids`에 넣는다.
  5. **문서와 에이전트 정의**: 윤진 ⑨ 정의의 `places`·`badges` 설명(지역·상태 거름, `badgeId`로 `badge_spotlight` 가능), ops-tool PRD §11.15·§11.16, `ops-weekly.md`·`scheduled-jobs.md`의 읽기 도구 설명, `docs/service/prd/ops-tool/PRD.md`를 맞춘다.
- 관련 파일(지도):
  - 신규 `jam-web/supabase/migrations/313_poi_region_columns.sql`과 되돌림 SQL(같은 폴더의 기존 되돌림 파일 이름 규칙을 따른다). `jam-web/src/types/database.generated.ts`의 `poi` Row·Insert·Update에 `sido`·`gu`를 더한다(`npm run db:types`는 실행 불가, 손으로 맞춘다).
  - 신규 `scripts/backfill-poi-region.mjs`와 시험(`scripts/*.test.mjs` 규칙). 역지오코딩 함수는 `jam-web/src/lib/poi/reverse-geocode.ts`(NCP 키 `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`·`NCP_MAP_CLIENT_SECRET`, 값은 출력하지 않는다).
  - `jam-web/src/lib/admin/opsPlaces/{types,query,load,compute}.ts`, `jam-web/src/app/api/admin/ops-places/route.ts`와 각 `__tests__`.
  - `jam-web/src/lib/admin/opsBadges/{query,load,compute}.ts`, `jam-web/src/app/api/admin/ops-badges/route.ts`와 각 `__tests__`.
  - `.claude/agents/jam-marketer.md`(⑨ 읽기 도구 설명), `.claude/skills/jam-work/references/ops-weekly.md`, `.claude/skills/jam-work/references/scheduled-jobs.md`(읽기 도구 표), `docs/service/prd/ops-tool/PRD.md` §11.15·§11.16.

## 배경 / 문제 정의

2026-11-02 샘플 기획(45주차)에서 윤진이 지역 단위 카드를 못 만들었고, 배지 소개를 `content_intro`로 돌려 써야 했다. 장소 수 집계에는 비활성·검수 대기 장소가 섞여 있어 «산 847곳, 역 949곳» 같은 숫자가 실제 체크인 가능한 장소 수와 어긋날 수 있다.

## 완료 조건

- `GET /api/admin/ops-places`(쿼리 없음)의 `placeCount`가 활성·검수 통과 장소 수와 같고 `inactiveCount`·`pendingReviewCount`가 따로 있다. `status=all`의 합계가 `poi` 전체 행 수와 같다.
- `GET /api/admin/ops-places?groupBy=region`이 시·도, 시·군·구별 장소 수를 돌려주고, `sido=서울특별시`처럼 거른 목록에서 지역 칸이 보인다. 응답에 좌표·주소·동이 없다.
- `GET /api/admin/ops-badges`의 단계 항목마다 `badgeId`가 있고, 숨김 배지는 여전히 없으며 유저 ID가 없다.
- `node scripts/backfill-poi-region.mjs`(드라이런)가 쓰기 없이 채울 행 수·실패 예상 수를 출력하고, `--apply`는 시험에서 가짜 클라이언트로만 확인한다(실제 실행은 하지 않는다).
- 마이그레이션 313과 되돌림 SQL이 있고, 되돌림이 `sido`·`gu` 칸을 지운다.
- 윤진 ⑨ 정의, ops-tool PRD, 읽기 도구 설명 문서가 새 거름과 `badgeId`를 설명한다.
- `npm run typecheck`, 관련 vitest, `scripts/verify.sh`가 통과한다.

## 실행 순서(메인 세션, 구현 머지 뒤)

1. 마이그레이션 313 적용(확장만, 즉시 되돌림 가능). 2. 채움 스크립트 드라이런 → 소규모(20행) 실측 → 전체 `--apply`. 3. 읽기 API로 지역 분포와 빈 칸 수를 확인한다.
