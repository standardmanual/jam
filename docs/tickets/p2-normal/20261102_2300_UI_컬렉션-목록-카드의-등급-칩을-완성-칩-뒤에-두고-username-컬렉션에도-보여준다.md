# [UI] 컬렉션 목록 카드의 등급 칩을 완성 칩 뒤에 두고 `[username]/collections`에도 보여준다

## 핵심 요약

- 요구사항: 컬렉션 목록의 각 카드 썸네일 **왼쪽 위(안쪽 여백 있음)** 에 컬렉션 등급 칩을 보여주고, 순서는 **완성 칩이 먼저, 등급 칩이 그 뒤**다(사용자 지시 «완성칩 뒤에 두면 되»). **등급 칩은 항상 하나다** — 컬렉션은 처음 추가한 아이템 배지와 같은 등급의 배지만 담을 수 있다(사용자 지시 2026-11-03).
- 현재(변경 전): `CollectionGridCard`(`/badges` 컬렉션 탭·프로필)에 등급 칩이 하나 있고 순서가 «등급 → 완성»이다. `[username]/collections`의 인라인 카드에는 등급 칩이 없고 완성 칩이 오른쪽 위에 있다.
- 구현 계획: ① `CollectionGridCard`와 디자인시스템 사본의 태그 행 순서를 «완성 → 등급»으로 바꾸고 좁은 폭에서 줄바꿈하게 한다. ② `[username]/collections` 카드에 같은 태그 행(완성 → 등급, 줄바꿈)을 둔다. 등급은 다른 두 목록과 같은 규칙(최초 등록 아이템 배지의 등급)으로 읽는다. ③ 순서 시험을 더한다.
- 관련 파일:
  - `jam-web/src/components/ui/CollectionGridCard.tsx` (태그 행 `{(rarity || completed) && ...}` 구간)
  - `jam-web/design-system/components/patterns/CollectionGridCard.{jsx,d.ts}` (태그 행 99~106행 부근, `rarity` 주석)
  - `jam-web/src/app/(main)/[username]/collections/page.tsx` (배지 조회 `select`·`order`, `rarityByBook`, `cards` 조립, 카드 마크업의 태그 행)
  - 신규 시험: `jam-web/src/components/ui/__tests__/CollectionGridCard.tagOrder.test.tsx`

## 배경 / 문제 정의

- 컬렉션 안의 아이템 배지는 모두 같은 등급이므로 등급 칩은 하나다. 그 등급은 `badges/page.tsx`·`api/users/[username]/itembooks`가 이미 «최초 등록 배지의 등급(`created_at` 오름차순 첫 번째)»으로 계산한다.
- **처음 구현은 «등록된 등급을 모두 칩으로» 보였다(티켓 초안 해석 오류).** 사용자가 컬렉션이 같은 등급만 담는다고 바로잡아 머지를 되돌리고(`f7de46869`) 위 계획으로 다시 구현했다. 새로 만들었던 `buildBookRarities`·`rarities` prop은 버렸다.
- `RarityBadge`는 Common 등급 칩을 그리지 않는다(JAM 2.0 결정). 2026-11-03 로컬 DB의 컬렉션은 모두 최초 등록 배지가 Common이라 칩이 보이지 않는다.

## 완료 조건

### 구현 범위
- `CollectionGridCard`와 디자인시스템 사본의 태그 행이 «완성(있을 때) → 등급» 순서이고, 완성하지 않은 컬렉션은 등급 칩만, Common이고 완성하지 않았으면 행 자체가 없다(시험).
- `[username]/collections` 카드 왼쪽 위에 같은 태그 행(완성 → 등급)이 나오고 오른쪽 위에는 아무것도 없다.
- 320px 2열에서 칩이 잘리거나 겹치지 않고 가로 스크롤이 없다(실측).

### 후속 범위 (담당: 카리나, 시점: push 뒤)
- staging에서 같은 화면을 확인한다.

### 구현 내용 요약

- 처음에는 등록된 등급을 모두 칩으로 보이는 방식(`buildBookRarities`, `rarities` prop)으로 구현해 민지 게이트(WARN)와 채원 리뷰를 거쳤으나, 사용자가 «컬렉션은 처음 추가한 아이템 배지와 같은 등급만 담으므로 칩은 하나»라고 바로잡았다. 머지(`6aae99b09`)는 push 전이라 되돌리고(`f7de46869`) 단일 등급 칩으로 다시 구현했다.
- `CollectionGridCard`와 디자인시스템 사본의 태그 행을 «완성 → 등급»으로 바꾸고 `right-2 flex-wrap`으로 좁은 폭에서 줄바꿈하게 했다.
- `[username]/collections` 인라인 카드에 같은 태그 행을 두고(오른쪽 위 완성 칩은 없앴다), 등급은 `rarityByBook`(최초 등록 배지의 등급, 배지 조회에 `created_at` 정렬 추가)으로 읽는다.
- `RarityBadge`는 Common을 그리지 않으므로 Common이면 칩이 없다.

### 주요 의사결정 / 핵심 메모

- 사용자 지시 해석이 한 번 틀렸다: 「컬렉션에 등록된 아이템 배지의 등급을 chip으로」를 «등록된 등급 전부»로 읽었지만 실제 규칙은 «컬렉션은 처음 추가한 배지와 같은 등급만 담는다 → 칩은 하나»였다. 코드에 이미 있던 `rarityByBook`(최초 등록 배지 등급) 주석이 같은 규칙을 말하고 있었다. 모호한 요구는 구현 전에 현재 화면·코드의 기존 규칙부터 확인한다.
- 머지 전 오염 검사는 병렬 세션이 티켓 20261102_2254를 먼저 머지해 실패했으나(staging이 앞서감) 브랜치 위 커밋이 이 티켓의 2건뿐임을 확인해 머지했다.
- 병렬 세션이 같은 시각 번호(`20261102_2254`)로 티켓을 만들어 이 티켓의 번호를 `20261102_2300`으로 바꿨다.
- 다중 등급 구현에서 `[username]/collections`의 `calc(100%-3.5rem)`이 86px 썸네일에서 깨진 것을 실렌더로 발견했다. 단일 등급으로 바뀌며 이 문제는 사라졌고, 대신 완성 칩과 등급 칩을 같은 줄바꿈 행에 둔다.

### 잔여 이슈
- 모든 컬렉션이 Common이라 지금은 등급 칩이 하나도 보이지 않는다. Common 칩을 그리려면 `RarityBadge`(또는 컬렉션 전용 칩)를 바꿔야 하는 디자인 결정이 필요하다.
- 이 URL 해시(`#collection`) 진입 시 탭 hydration 경고는 기존 동작으로 보이며 이 변경과 무관하다.
