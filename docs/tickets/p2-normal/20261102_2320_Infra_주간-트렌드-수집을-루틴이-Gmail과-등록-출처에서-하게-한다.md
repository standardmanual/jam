# [Infra] 주간 트렌드 수집을 루틴이 Gmail과 등록 출처에서 하게 한다

> 상위: 20260930_1503. 앞선 결정을 이어받는다: 티켓 20261102_1600(Muse 폐기, 수집을 대화 세션으로), 20261028_1422(트렌드 출처에 저장소 폴더 종류).

## 핵심 요약

- 요구사항(사용자 지시 2026-11-02): «에이전트가 주간 트렌드를 지메일과 어드민에서 등록한 출처에서 수집하는 것으로 알고 있어 그렇게 되도록 해». 수집을 대화 세션이 아니라 월요일 05:00 루틴이 하게 한다.
- 구현 계획:
  1. 규칙 문서: `scheduled-jobs.md` 「트렌드 수집」 절을 «만료 정리만»에서 «Gmail 라벨 JAM 메일 + 켜진 등록 출처를 읽어 `latest.md` 작성»으로 고친다(완료). README의 수집 주체 서술, `trend-requests.mjs` 머리 주석, 월간 절의 서술도 맞춘다(완료).
  2. 루틴 설정(사용자 허용 필요): 저장 프롬프트를 절의 «프롬프트 초안»으로 교체하고, Gmail 커넥터(`list_labels`·`search_threads`·`get_thread` 읽기 도구 셋만)를 연결하며, `WebSearch`·`WebFetch`를 `allowed_tools`에서 뺀다.
  3. 시험: 시험 모드(수동 실행, 저장소에 쓰지 않음)로 3개 주제를 돌려 Gmail이 클라우드 환경에서 읽히는지, 훅이 허용하는 경로만 쓰는지 본다. 읽히지 않으면 실패 처리 절대로 «Gmail 읽기 실패»를 기록하는 쪽으로 동작해야 한다.
  4. 등록 출처 중 `hashtag`·`channel`·`search_trend`는 읽는 도구가 없어 «읽을 도구 없음»으로 기록한다. 현재 켜진 출처는 `repo_folder` 1건(`docs/operations/trendresearch/`)뿐이다.
- 관련 파일: `.claude/skills/jam-work/references/scheduled-jobs.md`(「트렌드 수집」 절, 월간 절 461·489행), `docs/operations/trendresearch/README.md`, `scripts/trend-requests.mjs`, `.githooks/pre-commit`(46행 `ROUTINE_ALLOWED_FILE_REGEX`, 변경 없음), 루틴 `trig_014GYPdF5BoqSUcuZ8mCLz48`.

## 배경 / 문제 정의

Muse가 되지 않아 수집을 대화 세션으로 옮겼지만, 세션이 요청받지 않으면 폴더가 낡는다. 메일 커넥터와 어드민 등록 출처가 이미 있으므로 루틴이 직접 읽게 한다. 웹 검색과 WebFetch는 한국어 자료가 얇고 도메인이 막혀 계속 쓰지 않는다.

## 완료 조건

- 「트렌드 수집」 절과 README가 루틴 수집 방식으로 서술되고 문서 간 모순이 없다.
- 루틴 저장 프롬프트가 절의 초안과 같고, Gmail 읽기 도구 셋만 연결되며, 웹 도구가 없다.
- 시험 모드 실행에서 Gmail 읽기 결과(스레드 수)와 등록 출처 읽기 결과가 실행 기록 전문에 보인다.
- `scripts/verify.sh`가 통과한다.
