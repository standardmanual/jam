# [Admin] 카드와 미션 등록 검사에 카피 규칙을 기계로 거르는 검사를 더한다

> 상위: 20261103_1152 (카피 화자와 권유 어미 규칙). 그 티켓이 후속으로 남긴 «기계 검사»다. 유형은 `admin`(MODULAR·채원 판정 대상 아님).

## 핵심 요약

- 요구사항(사용자 지시 2026-11-03 «기계 검사 만들기»): UX 라이팅 가이드라인 §2.6과 사용자 결정으로 정한 카피 규칙 가운데, 문자열만 보고 판정할 수 있는 것을 **카드와 미션의 등록 검사**에서 거절한다. 윤진이 쓴 묶음과 어드민 상황판에서 예약 등록하는 묶음이 둘 다 같은 함수를 지나므로 한 곳에 걸면 두 경로가 막힌다.
- 왜 `scripts/check-slop.mjs`가 아닌가: 그 검사는 저장소 파일의 diff 줄만 본다. 홈피드 카드와 미션 문구는 DB 행이고, 묶음 JSON은 저장소에 커밋되지 않는다. 문구가 DB로 들어가는 길목(등록 검사)이 맞는 자리다.
- 거르는 규칙(오류로 거절, 메시지는 해요체로 대체 문구를 안내한다):
  1. 제목·부제·설명 모두: 권유 자리의 「~하세요」(`세요` 앞이 `주`인 「해 주세요」는 제외). 「~해 봐요」로 쓴다.
  2. 설명만: 느낌표(`!`, `！`). 권유·안내 문장에는 쓰지 않는다.
  3. 설명만: 문장이 「획득」 또는 「보상」(뒤에 공백·`!`·`.`만 붙은 것 포함)으로 끝남. 「10포인트를 획득해요」처럼 문장으로 맺는다.
  4. 제목·부제·설명 모두, 쓰지 않는 말: 「도장」(사용자 결정, 체크인·획득으로 쓴다), 숫자 500 뒤 `m` 또는 `미터`(500m 반경은 화면에 노출하지 않는다), 「장소 배지」·「POI 배지」·「지점 배지」·「방문 배지」(§1.3 고정 용어 X 목록), 「발견」·「찾아서」(획득 맥락의 용어 정리), 「이웃」(화자가 친구라서 이웃 호칭을 쓰지 않는다).
  5. **(추가 2026-11-03, 사용자 지시 «카피는 규칙으로 만들어서 이렇게 나오지 않도록 해»)** 제목(`card.title`, `mission.title`)이 조건을 요약한 말이면 거절한다. 조건 요약 제목은 AI 느낌이 크고 어색해서 쓰지 않는다. 걸리는 모양은 세 가지다: (가) 행동 이름 + 수량으로 끝남, 즉 `(체크인|걷기|달리기|라이딩|등산|활동|동기화|드랍|픽업|획득)` 뒤에 `(숫자|한|두|세|네|다섯)`과 `(곳|번|개|회|일|km|m|분|시간)`이 와서 끝남(「새 역 체크인 2곳」, 「겨울 앞두고 걷기 3번」, 「산 체크인 한 곳」); (나) `걸어서|달려서|올라서|타고` + 수 + 단위만으로 된 제목(「걸어서 10km」); (다) 행동 이름(`체크인|획득|드랍|픽업|동기화`)으로 끝남(「입동 주간, 새 장소 체크인」). 걸리지 않아야 하는 제목: 「지하철 역에서 만나는 행운」, 「쌀쌀한 날의 짧은 산책」, 「걷다 보면 어느새 10km」, 「처음 오른 산에서의 한 걸음」, 「주말엔 한 번, 10km」, 「활동 두 번이면 충분해요」. 메시지는 «제목이 조건을 요약한 말처럼 읽혀요. 「지하철 역에서 만나는 행운」처럼 장면이나 기대가 보이게 써 주세요(UX 라이팅 가이드라인 §2.6)»로 안내한다. 제목이 장면과 기대를 말하고 조건(숫자와 행동)은 설명문이 말한다는 역할 분담이 근거다. 가이드라인 §2.6에도 이 규칙을 Good/Bad 한 줄로 더한다.
- 거르지 않는 것(문맥 판단이라 민지·윈터 몫): 기한 암시(「~하기 전에」), 절기 표현, 문장 모양 반복, 끝맺음 쏠림, 같은 과제 중복.
- 관련 파일(지도):
  - 신규 `jam-web/src/lib/admin/registerChecks/copyRules.ts`: 순수 함수 `collectCopyErrors(prefix, field, value)`가 오류 문자열 배열을 돌려준다. 이 폴더 규칙대로 `node:`·`scripts/` 가져오기 금지(서버 번들 가능). 규칙 목록 상수를 이 파일 한 곳에 둔다.
  - 신규 `jam-web/src/lib/admin/registerChecks/__tests__/copyRules.test.ts`: 규칙마다 걸리는 문장과 안 걸리는 문장(「해 주세요」, 「10km」, 「500원」처럼 비슷한 문장).
  - `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts` `validateCard`: 약 178~189행 `checkOneLine(...)` 호출 바로 뒤에서 `card.title`·`card.subtitle`·`card.description`에 `collectCopyErrors`를 호출해 `errors`에 더한다. 줄바꿈·제어 문자 오류가 이미 난 값은 건너뛴다.
  - `jam-web/src/lib/admin/registerChecks/missionFields.ts` `validateMission`: 약 92~100행에서 `mission.title`·`mission.description`에 같은 호출을 더한다.
  - 기존 시험 자료: `scripts/asset-generator/__tests__/registerHomeFeedRecord.test.ts` 41행의 「도전해 보세요」, `registerMissionRecord.test.ts` 40행의 「달려 보세요」. 그 시험이 검사 함수를 지나면 새 규칙에 걸리므로 «해 봐요»로 고친다. 지나지 않으면 그대로 둔다. 실행해서 걸리는 시험만 고친다.
  - 문서: `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md`(필드 표 `title`·`subtitle`·`description` 행과 오류 표에 카피 규칙 행), `docs/service/prd/asset-generator/MISSION_REGISTRATION_BUNDLE.md`(`mission.title`·`mission.description`), `docs/service/writing/UX_WRITING_GUIDELINE.md` §2.6(맨 끝에 «기계가 거르는 규칙은 `copyRules.ts`가 단일 원천»이라는 한 줄과, 「발견」·「찾아서」·「이웃」 금지를 규칙 목록에 더함), `.claude/skills/jam-story/references/marketer-home-feed.md`(윤진이 묶음을 쓰기 전에 걸리는 규칙을 알게 하는 한 줄).

## 배경 / 문제 정의

20261103_1152에서 정한 카피 규칙을 사람이 지키게만 두면 다음 주 편성부터 다시 샌다. 이번에 고친 카드·미션 19건이 모두 같은 문구 틀로 샜던 것처럼, 윤진과 어드민 상황판 입력이 둘 다 같은 등록 검사를 지나므로 거기서 거르면 수정 비용이 가장 낮다. 문맥 판단이 필요한 규칙은 기계에 넣으면 오탐이 늘어 바로 우회되므로 넣지 않는다.

## 완료 조건

- 위 규칙 1~5에 걸리는 카드·미션 문구가 `validateCard`·`validateMission`에서 오류로 나오고, 오류 메시지가 어느 칸(`card.description` 등)과 무엇을 어떻게 고칠지 해요체로 알려 준다.
- 「해 주세요」, 「10km」, 「500원」, 「획득해요」, 「획득한 배지」(중간의 「획득」)는 걸리지 않는다.
- `copyRules.test.ts`가 규칙마다 걸리는 경우와 안 걸리는 경우를 확인한다. 새 규칙 때문에 깨진 기존 시험은 문구를 «해 봐요»로 고쳐 통과시킨다(규칙을 풀지 않는다).
- 현재 DB에서 노출 기간이 남은 카드·미션 문구(`today_cards`, `missions`)가 새 규칙을 모두 통과한다(읽기 전용 확인).
- `registerChecks`가 서버 번들에 들어갈 수 있다는 기존 시험(원문 가져오기 검사)이 통과한다.
- `npm run typecheck`, 관련 vitest, `scripts/verify.sh`가 통과한다.

## 구현 계획

위 «관련 파일»이 파일 단위 계획이다. 파일 수가 임계값(5개 초과)을 넘으므로 `planOnlyWaiver`를 넘기고, 사유는 «파일 단위 계획이 이 절에 있고 사전 확인(기존 시험 자료 위치, 검사 함수 호출 위치)을 마쳤다»이다.

## 후속(구현 뒤, 카리나)

- 어드민 상황판의 대기 중인 묶음(`ops_inbox`)에 새 규칙에 걸리는 문구가 있는지 읽기 전용으로 확인한다. 있으면 등록 때 막히므로 윤진에게 고쳐 쓰게 한다.
