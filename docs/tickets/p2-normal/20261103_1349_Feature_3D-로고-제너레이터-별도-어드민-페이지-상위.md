# [Feature] 3D 로고 제너레이터 — Google Fonts·SVG를 3D 로고 이미지로 (별도 어드민 페이지, 상위 티켓)

> 2026-11-03 사용자와 대화로 요구사항을 정하고, 「3개 티켓으로 나눠 진행」을 승인받아 만든 상위 티켓이다.
> 구현은 하위 티켓 3개를 순서대로 진행한다. 이 티켓은 요구사항 정본·결정 기록·하위 티켓 표를 담는다.

## 핵심 요약

- 요구사항: 어드민에 별도 페이지(`/admin/logo-3d`)를 만들어 Google Fonts 글자 또는 SVG 로고를 3D로 압출하고, 원본보다
  앞뒤로 튀어나오는 외곽선(스틸 틀)을 자동으로 만들어, 두께·색·회전·줌·등각 시점·배경(Gradient/Solid/Transparent)을 조절한 뒤
  PNG로 저장한다. 기본값은 얇은 매트 스틸 외곽선 + 큰 도자기 타일 면 + 모든 모서리가 둥근 베벨.
- 구현 계획: 하위 티켓 3개 — ① 형상 엔진(순수 함수 라이브러리) → ② 입력(폰트·SVG를 윤곽으로) → ③ 화면(페이지·패널·뷰포트·메뉴·문서).
- 관련 파일: `jam-web/src/lib/logo-3d/`(신설), `jam-web/src/app/admin/logo-3d/`(신설),
  `jam-web/src/app/api/admin/logo-3d/font/route.ts`(신설), `jam-web/src/components/admin/adminNavItems.ts`(108줄 근처 "에셋" 항목 아래),
  `jam-web/src/lib/admin/googleFonts.ts`(재사용), `jam-web/src/app/admin/assets/shapeStudioConfig.ts`(`BackgroundMode`·`bgA`·`bgB`·`bgAngle`,
  `CanvasRatio` 59~82줄)

## 배경 / 문제 정의

배지·컬렉션·홈피드용 브랜드 이미지에 3D 질감의 로고가 필요한데, 지금은 Blender로 사람이 하나씩 만든다. 2026-11-03에 JAM! 로고를
Blender로 만들어 보며 방법을 확정했다(얇은 매트 스틸 틀, 유약 광택의 도자기 타일 면, 모든 모서리를 둥근 베벨로, 외곽선이 앞뒤로
튀어나오는 구조). 이 과정을 웹에서 반복할 수 있게 하면 폰트·색·두께만 바꿔 즉시 같은 품질의 3D 이미지를 뽑을 수 있다.

## 요구사항 정본 (사용자, 2026-11-03)

1. Google Fonts 글자 또는 SVG 소스를 3D로 변형한다
2. 외곽선(틀) 두께를 자동으로 만든다 — 소스(타일 면)보다 앞뒤로 더 튀어나오게
3. 컬러 팔레트로 색을 바꾼다
4. x·y·z 축으로 회전한다
5. 줌 인·아웃
6. PNG로 저장한다(어드민 에셋과 같은 1:1·4:5·9:16·16:9 비율)
7. 등각(isometric) 시점
8. 스테이지(배경)는 어드민 에셋의 3개 모드와 같다 — Gradient·Solid·Transparent (`bgA`·`bgB`·`bgAngle`)
9. **두께 조절**: 로고 깊이, 외곽선 폭, 모서리 둥글림 반지름을 슬라이더로 조절한다
10. 폰트는 Google Fonts를 쓴다

## 결정 기록 (사용자 확인, 2026-11-03)

- 어드민 에셋 안의 탭이 아니라 **별도 페이지**로 만든다.
- 티켓은 **3개로 나눠** 순서대로 진행한다.
- 가정(카리나가 제시하고 승인됨):
  1. `three`는 이미 설치돼 있다(`jam-web/package.json` 50줄, `^0.183.2`) — 새로 설치하지 않는다.
  2. 폰트 목록은 기존 정적 카탈로그(`googleFontsCatalog.json`, 1,946종, API 키 불필요)를 재사용한다.
  3. 공개 스타일시트(`fonts.googleapis.com/css2`)는 브라우저에 woff2만 줘서 글자 윤곽을 읽을 수 없다 → 서버 API가 구형 사용자
     에이전트로 TTF를 받아 오게 한다(어드민 로그인 확인 필수).
  4. 새 라이브러리 두 개 — 폰트 윤곽을 읽는 `opentype.js`, 윤곽을 늘리고 줄이는 2D 연산 라이브러리(Clipper2 계열).
  5. 메뉴는 어드민 "에셋" 그룹의 "에셋" 바로 아래, 이름은 "3D 로고".
  6. 서버 저장(프리셋·콘텐츠 적용)은 이번 범위 밖 — PNG 저장까지만.
  7. 한글 폰트는 첫 버전에서 파일 전체를 받는다(용량 줄이는 처리는 다음 단계).

## Blender 작업에서 확정한 형상 규칙 (하위 티켓 공통 참고)

오늘 Blender에서 시행착오로 얻은 값과 함정이다. 하위 티켓은 이 값을 기본값·검증 기준으로 쓴다(로고 높이를 1로 정규화한 값).

| 항목 | 기본값 | 비고 |
|---|---|---|
| 압출 두께(깊이) | 0.30 | 두께 슬라이더 |
| 외곽선(틀) 폭 | 0.030 | 파란 면이 크게 보이도록 얇게. 폭이 두꺼우면 비율이 틀어진다(0.09는 과함) |
| 틀 윗면 높이 | 0 (타일보다 0.016 앞으로 튀어나옴) | 타일 윗면 = -0.016 |
| 틀 뒤쪽 돌출 | 타일·바닥판보다 뒤로 더 내려감 | 바닥판 윗면 ≈ -0.052 ~ 뒤쪽 -0.30 |
| 틀 베벨 반지름 | 0.0145 | 틀 폭(0.03)의 절반 이하 |
| 타일 베벨 반지름 | 0.016 | 타일 두께 0.036 |
| 글자 윤곽 모서리(평면) 반지름 | 바깥 0.05, 안쪽 0.04 | 베벨 반지름보다 커야 한다 |

**함정 (모두 실제로 겪음)**
1. 베벨 반지름이 윤곽의 곡률 반지름보다 크면 모서리가 겹치고 엉킨다 → 평면 모서리를 먼저 베벨보다 큰 반지름으로 둥글린다.
2. 윤곽을 안쪽으로 줄이면 볼록 모서리가 다시 뾰족해진다 → 오프셋 결과마다 따로 둥글린다.
3. 아주 짧은 선분이나 일직선상의 불필요한 점이 있으면 넓이가 거의 0인 납작한 삼각형이 생겨 렌더에 가는 이음선이 보인다 →
   삼각분할 전에 공선(共線) 점을 제거하고 점 간격을 균일하게 유지한다.
4. 폭이 좁은 틈(M의 두 틈, 폭 약 0.064)은 "안쪽 모서리 메우기" 반지름이 틈 폭의 절반보다 작아야 막히지 않는다.
5. 외곽선의 앞뒤 돌출은 틀이 타일보다 두껍다는 뜻이다 — 틀과 타일을 별개 개체로 만들고 타일·바닥판을 틀 안쪽에 앉힌다.

## 리스크

- 실시간 렌더(WebGL)라 크롬·유약 반사의 품질이 Blender 경로 추적 렌더보다 낮다 → 환경 맵으로 최대한 맞추고, 차이는 문서에 적는다.
- 한글 폰트 파일이 수 MB → 첫 버전은 허용, 용량 줄이기는 후속.
- 장식이 많거나 획이 매우 가는 폰트는 외곽선·둥글림이 깨질 수 있다 → 3번 티켓에서 반지름을 윤곽 최소 두께에 맞춰 자동 제한.

### 주요 의사결정 / 핵심 메모
- 3개 티켓으로 나눠 순서대로 실행했다(묶음 실행 안 함): 2·3번이 1번 코드에 의존해 머지 사이에 `origin/staging`이 바뀌기 때문이다.
- **규모 면제(`planOnlyWaiver`)를 세 티켓 모두 사용**: 파일 5개 초과·100줄 이상이 처음부터 예상됐고, 파일 단위 계획이 티켓에 있었다.
- **실렌더 확인이 단위 테스트가 못 잡은 결함을 잡았다**: 여러 글자를 만들 때 옆면이 사라지던 결함은 단위 테스트·게이트·CI를 모두 통과했다. 어드민 화면은 격리 워크트리에서 실렌더가 불가능해 머지 뒤 로컬 확인이 유일한 관문이었다 — 이번에 그 단계가 효과를 보였다. 1번 티켓 테스트는 글자를 하나씩만 시험했고, 윤곽이 둘 이상인 입력을 시험하지 않았다.
- 실행 지표 합계(3개 티켓): 1번 193,101 / 2번 179,991 / 3번 392,837 토큰.
- 사용자와의 대화 중 진단·설명이 바뀐 곳: ① 폰트 목록은 API 키 대신 기존 정적 카탈로그 재사용 ② 3번 FAIL 원인 진단 정정(earcut 복귀 → 삼각분할이 공선점을 지움) ③ 옆면 결함의 첫 진단 정정.
