## 핵심 요약

- 요구사항: 높이 1로 정규화한 2D 윤곽(`LogoOutline`)을 받아 ① 윤곽 오프셋·모서리 둥글림 ② 외곽선(스틸 틀)·타일·바닥판 3개 형상을
  만들어 `three`의 `BufferGeometry`로 돌려준다. 틀은 타일보다 앞뒤로 튀어나오고, 모든 모서리는 둥근 베벨이다. 두께·틀 폭·베벨
  반지름은 매개변수다.
- 구현 계획: `jam-web/src/lib/logo-3d/`에 타입·2D 연산·형상 생성 세 파일과 테스트 두 파일을 만든다. 2D 연산은 Clipper2 계열 순수 JS
  라이브러리를 새로 추가해 쓴다(WASM 아님). 형상은 `three`의 `Shape`·`ExtrudeGeometry`로 만든다.
- 관련 파일(모두 신설, 줄 위치는 신설이라 해당 없음)
  - `jam-web/src/lib/logo-3d/types.ts`
  - `jam-web/src/lib/logo-3d/polygonOps.ts`

  - `jam-web/src/lib/logo-3d/__tests__/polygonOps.test.ts`

## 배경 / 문제 정의

Blender 경로에서는 윤곽을 shapely로 오프셋하고 삼각분할을 제약 들로네로 바꾸고서야 이음선·엉킨 베벨 문제를 풀었다. 같은 품질을
웹에서 내려면 윤곽 처리와 형상 생성을 검증 가능한 순수 함수로 먼저 만들어야 한다. 화면(3번)과 입력(2번)은 이 엔진의 입출력 형식에
의존하므로 형식을 여기서 확정한다.

## 상세 요구사항

### 서비스/코드베이스 관점

**타입 (`types.ts`)**
- `Point = readonly [number, number]`, `Ring = Point[]`(닫힌 고리, 마지막 점을 처음 점과 중복하지 않는다)
- `OutlinePolygon = { outer: Ring; holes: Ring[] }`, `LogoOutline = OutlinePolygon[]`(글자마다 하나, 높이 1·중앙 정렬)
- `Logo3DParams` — 최소 아래 필드, 모두 로고 높이 1 기준 비율:
  `depth`(압출 두께, 기본 0.30), `frameWidth`(틀 폭, 기본 0.030), `frameFrontProtrusion`(틀이 타일보다 앞으로 튀어나온 양, 기본 0.016),
  `frameBevelRadius`(기본 0.0145), `tileBevelRadius`(기본 0.016), `tileThickness`(기본 0.036), `cornerRadiusOuter`(기본 0.05),
  `cornerRadiusInner`(기본 0.04), `gap`(타일과 틀 안쪽 벽 사이 틈, 기본 0.0012)
- `DEFAULT_LOGO3D_PARAMS`, `LOGO3D_PARAM_RANGES`(슬라이더 최소·최대·단계 — 3번 화면이 그대로 쓴다)

**2D 연산 (`polygonOps.ts`)** — 입출력은 모두 `LogoOutline`
- `normalizeOutline(raw)`: 높이를 1로 맞추고 가로·세로를 중앙 정렬한다.
- `offsetOutline(outline, delta)`: delta<0이면 안쪽, >0이면 바깥쪽. 모서리는 둥근 연결(round join)이다.
- `roundCorners(outline, { convex, concave })`: 볼록 모서리는 안쪽으로 줄였다가 되돌려(opening), 오목 모서리는 늘렸다가 되돌려(closing)
  둥글린다. 폭이 좁은 틈이 막히지 않도록 `concave` 반지름이 틈 폭의 절반 이상이면 그 모서리는 건너뛰고 경고를 돌려준다.
- `cleanRing(ring, { minSegment, collinearTolerance })`: 일직선상 점과 너무 짧은 선분을 제거해 점 간격을 균일하게 한다.
- `ringArea`, `outlineArea`, `minThickness(outline)`(윤곽이 가장 가는 곳의 두께 — 둥글림 반지름 상한 계산용)

**형상 생성 (`buildGeometry.ts`)**
- `buildLogoGeometry(outline, params): { frame, tile, backPlate, bounds, warnings }`
  - `frame`(스틸 틀): 바깥 윤곽에서 `frameWidth`만큼 안쪽으로 줄인 윤곽을 뺀 고리 모양. 윗면 z=0, 아랫면 z=-depth. 모서리는 `frameBevelRadius`로
    둥글다.
  - `tile`(도자기 면): 틀 안쪽 윤곽에서 `gap`만큼 더 줄인 형상. 윗면 z=-frameFrontProtrusion, 두께 `tileThickness`. 모서리는 `tileBevelRadius`로
    둥글다.
  - `backPlate`(바닥판): 틀 안쪽을 막는 판. 윗면이 타일 아랫면에 닿는다. 틀은 바닥판·타일보다 뒤로 더 내려간다(앞뒤 돌출).
  - 베벨 반지름이 윤곽의 곡률 반지름을 넘으면 자동으로 줄이고 `warnings`에 사유를 적는다(겹침 방지).
  - 삼각분할 품질: 넓이/최장변² 가 2×10⁻⁴ 미만인 윗면 삼각형이 없어야 한다(납작한 삼각형 금지).
- `three`는 서버·테스트 환경에서도 쓸 수 있도록 WebGL 없이 `BufferGeometry`만 다룬다(렌더러·재질은 이 티켓 범위 밖).

## 구현 계획

1. `package.json`에 Clipper2 계열 순수 JS 포트를 추가한다. 후보는 구현 시 아현이 `npm view`로 유지 상태·번들 크기를 확인해 하나를
   고르고 사유를 「주요 의사결정」에 남긴다.
2. `types.ts` → `polygonOps.ts` → `buildGeometry.ts` 순서로 쓴다. 테스트를 함께 쓴다.
3. 형상 생성은 `three`의 `Shape`와 `ExtrudeGeometry({ depth, bevelEnabled, bevelThickness, bevelSize, bevelSegments, curveSegments })`를 쓴다.
   `ExtrudeGeometry`의 베벨은 윤곽을 바깥으로 `bevelSize`만큼 키우므로, 최종 윤곽이 맞도록 입력 윤곽을 그만큼 줄여서 넘긴다.
4. 점 간격: 곡선 구간은 점 수를 늘리되 `cleanRing`으로 최소 선분 길이를 보장한다. 직선 구간은 끝점만 남긴다.
5. 테스트용 윤곽은 파일 안에 직접 만든다 — (가) 구멍이 있는 글자(A 모양), (나) 폭 0.064의 좁은 틈이 있는 글자(M 모양),
   (다) 직각 모서리 글자(J 모양).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `offsetOutline(-d)`의 넓이가 d가 커질수록 줄고, 구멍은 커진다. 같은 윤곽에 `offsetOutline(+d)` 뒤 `offsetOutline(-d)`를 하면 넓이가
  원래의 ±1% 안이다(단위 테스트).
- (나) M 모양에서 `roundCorners` 뒤에도 좁은 틈 두 개가 구멍·오목부로 그대로 남는다(틈이 막히면 실패).
- `buildLogoGeometry`가 돌려준 `frame`의 z 범위가 `tile`의 z 범위를 앞(위)으로 `frameFrontProtrusion`만큼, 뒤(아래)로 0보다 크게 넘는다.
- `tile`·`frame`의 윗면 삼각형 중 넓이/최장변² < 2×10⁻⁴ 인 것이 0개다(세 테스트 윤곽 모두).
- 베벨 반지름을 윤곽 최소 두께보다 크게 주면 예외 없이 줄어든 값으로 만들고 `warnings`에 사유가 들어 있다.
- 모든 정점·인덱스에 NaN이 없다.
- `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).

### 주요 의사결정 / 핵심 메모
- **윗면·아랫면 삼각분할을 `ExtrudeGeometry`의 earcut에서 Clipper2 제약 들로네(`triangulateD`)로 교체**: earcut이 A 윤곽에서 넓이/최장변² 약 1×10⁻⁵ 의
  납작한 삼각형을 만들었다(Blender 경로에서 렌더 이음선의 원인이던 것과 같은 현상). 옆면·베벨은 `ExtrudeGeometry`를 그대로 쓰고, 삼각분할이 실패하면 earcut 결과로 되돌린다.
- **의존성**: `clipper2-ts@2.0.1-18`(순수 TS, 2026-07 갱신, BSL-1.0). 기각한 후보는 `clipper2-js`(2024-01 이후 갱신 없음), `js-angusj-clipper`(WASM).
- **티켓에 없던 추가**: `@types/three@^0.183.1`(개발 의존성) — `three`에 타입이 없고 코드에서 쓰는 곳도 없었다. lock에 하위 의존성 8개 포함(추가 76줄, 삭제 0줄). 사용자에게 보고함.
- **바닥판 아랫면**: 틀의 뒤쪽 돌출량 매개변수가 티켓에 없어 `-depth + max(frameFrontProtrusion, frameBevelRadius)`로 정했다(앞 돌출과 같은 값).
- **두께·틈 측정**: 변 위 표본에서 광선을 쏘는 방식. 마주보는 벽은 법선 내적 0.95(약 18도 이내)만 평행으로 본다. 0.7로 두면 A의 삼각 구멍 꼭짓점을 틈(0.0078)으로 잘못 재서
  오목 반지름이 0.0035로 줄었다.
- 아현은 이 워크트리의 `jam-web/node_modules`를 링크에서 실제 설치(`npm ci`)로 바꿨다(의존성 추가에 필요).

### 잔여 이슈
- 기본값에서 틀 윗면의 평평한 부분 폭이 `frameWidth - 2*frameBevelRadius ≈ 0.001`이라 삼각형 품질 여유가 약 2배뿐이다(최솟값 4.5×10⁻⁴, 기준 2×10⁻⁴) → 3번 티켓 완료 조건에 경계 조합 검증을 추가함.
- `frameBevelRadius` 최댓값(0.04)이 `frameWidth` 최솟값(0.01)보다 커서 조합에 따라 베벨이 자동으로 줄어든다 → 3번 티켓에서 `warnings`를 패널에 보여주도록 추가함.
- `minWallDistance`가 O(n²) → 별도 P3 티켓(`20261103_1418`)로 분리.
- (3번 티켓 로컬 실렌더에서 발견, 2026-11-03) 이 티켓의 테스트는 글자(윤곽)를 하나씩만 시험해, 윤곽이 둘 이상일 때 둘째 글자부터 옆면이 사라지던 결함(`withDelaunayLids`가 첫 옆면 그룹만 사용)을 못 잡았다. 3번 티켓에서 고치고 회귀 시험을 더했다(커밋 8090ecb78).
