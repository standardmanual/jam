# [Admin] 3D 로고 제너레이터 2 — 입력: Google Fonts 글자·SVG 업로드를 윤곽으로 변환 (서버 폰트 API 포함)

> 상위 티켓 [20261103_1349](20261103_1349_Feature_3D-로고-제너레이터-별도-어드민-페이지-상위.md)의 2번. 1번(형상 엔진)의 `LogoOutline`
> 형식을 입력으로 만든다. 화면은 3번 티켓이므로 여기서는 함수와 서버 API까지만 만든다.

## 핵심 요약

- 요구사항: ① Google Fonts 폰트 이름과 글자열을 받아 글자 윤곽(`LogoOutline`)을 돌려준다 ② SVG 문자열(업로드 파일 내용)을 받아
  `LogoOutline`으로 바꾼다. 폰트 파일은 서버 API가 TTF로 받아 오게 한다(공개 스타일시트가 브라우저에 woff2만 줘서 글자 윤곽을 읽을 수 없음).
- 구현 계획: 서버에 `GET /api/admin/logo-3d/font?family=…&weight=…` 라우트를 만들고(어드민 로그인 확인), 클라이언트에 `opentype.js`로 글자 윤곽을
  뽑는 함수와 `three`의 `SVGLoader`로 SVG 경로를 윤곽으로 바꾸는 함수를 만든다. 둘 다 1번의 `normalizeOutline`으로 마무리한다.
- 관련 파일
  - `jam-web/src/app/api/admin/logo-3d/font/route.ts`(신설, 서버 폰트 중계)
  - `jam-web/src/lib/logo-3d/fontOutline.ts`(신설, `opentype.js` → `LogoOutline`)
  - `jam-web/src/lib/logo-3d/svgOutline.ts`(신설, SVG → `LogoOutline`)
  - `jam-web/src/lib/logo-3d/__tests__/fontOutline.test.ts`, `__tests__/svgOutline.test.ts`(신설)
  - `jam-web/src/lib/admin/googleFonts.ts`(재사용: `GOOGLE_FONT_CATALOG`, `searchGoogleFonts` — 수정하지 않는다)
  - `jam-web/package.json`(`opentype.js`와 타입 추가), 1번 티켓의 `jam-web/src/lib/logo-3d/types.ts`·`polygonOps.ts`(의존)
  - 기존 어드민 API 라우트의 로그인 확인 패턴: `jam-web/src/app/api/admin/asset-generator/presets/route.ts` 참고

## 배경 / 문제 정의

Google Fonts 공개 스타일시트(`fonts.googleapis.com/css2`)는 브라우저 요청에 woff2 파일을 돌려주는데, `opentype.js`는 woff2를 읽지 못한다.
TTF를 받으려면 구형 사용자 에이전트로 요청해야 하고, 브라우저는 이 헤더를 바꿀 수 없으므로 서버가 중계해야 한다. SVG는 JAM! 로고처럼
이미 윤곽이 있는 입력이라 업로드 즉시 윤곽으로 바꾸면 된다.

## 상세 요구사항

### 서비스/코드베이스 관점

**서버 폰트 API (`route.ts`)**
- 어드민 권한이 없으면 401/403(기존 어드민 API 패턴을 그대로 따른다).
- `family`는 `GOOGLE_FONT_CATALOG`에 있는 이름만 허용한다(임의 URL 요청 방지, SSRF 차단). `weight`는 100~900의 100 단위만 허용한다.
- `fonts.googleapis.com/css2`에 구형 사용자 에이전트로 요청해 TTF URL을 얻고, `fonts.gstatic.com` 도메인인 경우에만 받아 온다.
- 응답은 바이너리(TTF)로 돌려주고 캐시 헤더를 붙인다. 실패하면 `[현상] → [원인] → [해결책]` 형식의 한국어 오류 메시지.
- 한글 폰트처럼 큰 파일은 그대로 중계한다(용량 줄이기는 범위 밖).

**폰트 → 윤곽 (`fontOutline.ts`)**
- `fontToOutline(fontBuffer, text, options): LogoOutline` — `opentype.js`로 글자 경로를 얻어 곡선을 선분으로 펴고(곡선당 분할 수를 옵션으로),
  윤곽 방향(바깥 반시계, 구멍 시계)을 맞춰 글자별 `OutlinePolygon`으로 묶은 뒤 `normalizeOutline`을 적용한다.
- 글자 사이 간격(어드밴스 너비)과 커닝을 반영한다. 공백은 윤곽 없이 간격만 만든다.
- 굵기별 파일이 따로 있는 폰트는 `weight`로 고른다. 가변 폰트는 이번 범위 밖(처음 버전은 고정 굵기만).

**SVG → 윤곽 (`svgOutline.ts`)**
- `svgToOutline(svgText, options): LogoOutline` — `three`의 `SVGLoader`로 `path` 요소를 읽어 채움이 있는 도형만 윤곽으로 바꾼다.
  구멍은 채움 규칙(even-odd/non-zero)에 맞게 처리한다. `fill="none"` 도형과 선(stroke)만 있는 도형은 건너뛰고 경고를 돌려준다.
- 변환(transform)·`viewBox`를 반영한다. SVG Y축은 아래로 향하므로 위쪽이 +Y가 되도록 뒤집는다.
- 외부 리소스(`<image>`, 외부 링크)와 스크립트는 읽지 않는다(어드민 업로드라도 입력은 신뢰하지 않는다).

## 구현 계획

1. `package.json`에 `opentype.js`(와 `@types/opentype.js`)를 추가한다.
2. `route.ts` → `fontOutline.ts` → `svgOutline.ts` 순서로 쓴다. 곡선을 펴는 함수는 `polygonOps.ts`의 `cleanRing`(1번 티켓)을 써서 점 간격을 균일하게 한다.
3. 테스트용 폰트 파일은 저장소에 넣지 않는다. 서버 라우트는 네트워크를 목(mock) 처리해 테스트하고, `fontOutline`은 `opentype.js`의 `Font` 객체를
   테스트 안에서 직접 만든 간단한 글자(사각형·구멍 있는 글자)로 시험한다.
4. SVG 테스트에는 `docs/assets/brand/jam_logo.svg`(J·A·M 세 경로, A에 구멍, even-odd 채움)를 그대로 쓴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `/api/admin/logo-3d/font`: 로그인하지 않은 요청은 401·403, 카탈로그에 없는 `family`는 400, 허용되지 않은 `weight`는 400. 정상 요청은
  TTF 바이트와 캐시 헤더를 돌려준다(네트워크 목 테스트).
- `svgToOutline(jam_logo.svg)`이 세 글자 영역을 돌려주고, A 영역에 구멍이 정확히 1개 있다. 높이가 1로 정규화되고 중앙에 있다.
- `fill="none"`만 있는 SVG는 빈 윤곽과 경고를 돌려주고 예외를 던지지 않는다. `<script>`·`<image>`가 들어 있어도 읽지 않는다.
- `fontToOutline`이 구멍 있는 글자에서 구멍 고리를 만들고(방향이 바깥과 반대), 글자열이 길수록 가로 폭이 늘어나며, 높이는 1로 정규화된다.
- 폰트 파일 읽기에 실패하면 예외 대신 `[현상] → [원인] → [해결책]` 형식의 한국어 오류를 돌려준다.
- `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).
