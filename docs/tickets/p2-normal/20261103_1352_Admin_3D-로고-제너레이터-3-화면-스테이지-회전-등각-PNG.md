## 상세 요구사항

### 서비스/코드베이스 관점

**상태·기본값 (`logo3dConfig.ts`)**
- `Logo3DState`: 입력(`source: 'font' | 'svg'`, 폰트 이름·굵기·글자열, SVG 문자열), 1번의 `Logo3DParams`, 색(`frameColor`·`tileColor`와 팔레트),
  회전(`rotX`·`rotY`·`rotZ`, 도), 줌, 시점(`view: 'perspective' | 'isometric'`), 스테이지(`bgMode: BackgroundMode`, `bgA`, `bgB`, `bgAngle`, 도 단위),
  `ratio: CanvasRatio`.
- 기본값: 외곽선 폭 0.030, 두께 0.30, 틀·타일·둥글림은 1번 티켓 기본값, 틀 색 은회색 계열(매트 스틸), 타일 색 하늘색 계열(도자기), 회전
  (x 14°, y 22°, z 3°), 시점은 원근, 스테이지는 Gradient(`bgA` 하늘색 → `bgB` 진한 하늘색, 각도는 에셋 기본값과 같게).
- 순수 함수: `isometricCameraPose()`(방위각 45°, 고도 약 35.264° — 정확한 등각 투영), `stageSizeFor(ratio)`(PNG 크기, `resolveStageSize` 재사용),
  `composeBackground(...)`(Gradient·Solid·Transparent별 배경 칠하기 계획), `PALETTES`(프리셋 팔레트 여러 개: 틀·타일 색 쌍).

**뷰포트 (`Logo3DViewport.tsx`)**
- `three`의 `WebGLRenderer`(`alpha: true`), 원근/직교 카메라 전환, 마우스 드래그 회전(`OrbitControls`)과 휠 줌, 슬라이더로 정한 회전·줌과 서로 동기화.
- 재질: 틀은 금속성 높게·거칠기 중간(매트 스틸, 기본 거칠기 0.36), 타일은 `MeshPhysicalMaterial`(광택층 있는 도자기, 거칠기 0.3, 광택층 거칠기 0.07).
  반사용 환경 맵은 `PMREMGenerator`로 만든 스튜디오 환경(대비가 있는 밝은·어두운 띠)을 쓴다. 환경은 배경과 별개다(배경이 투명이어도 반사는 그대로).
- 입력이 바뀌면 `buildLogoGeometry`(1번)로 형상을 다시 만들고, 이전 형상의 `geometry`·`material`을 `dispose()`한다(메모리 누수 방지).
- PNG 저장: 선택한 비율의 크기로 다시 그려서 저장한다. Transparent는 투명 PNG, Solid·Gradient는 2D 캔버스에 배경을 먼저 칠하고 3D 이미지를 위에 얹는다
  (가장자리 흰 테두리가 생기지 않도록 알파 처리를 맞춘다). 파일명은 `logo-3d-{글자열 앞부분}-{ratio}.png`.

**설정 패널 (`Logo3DPanel.tsx`)** — 어드민 UI 규칙대로 shadcn/ui 컴포넌트만 쓴다(`@/components/admin/ui/*`, 네이티브 select 금지)
- 입력: 폰트 검색 드롭다운(`searchGoogleFonts`), 굵기 선택, 글자열 입력, SVG 파일 업로드 버튼(둘 중 하나가 활성).
  입력 변환은 2번 티켓의 `fontToOutline`·`svgToOutline`이며 둘 다 `{ outline, warnings, error }`(`OutlineResult`)를 돌려준다 — `error`가 있으면 오류 영역에 보이고
  이전 형상을 유지하며, `warnings`는 패널에 한 줄로 알린다. 폰트 파일은 `GET /api/admin/logo-3d/font?family&weight`(TTF)로 받는다.
- **두께**: 로고 깊이, 외곽선 폭, 틀 앞쪽 돌출, 모서리 둥글림 반지름(틀·타일 각각)을 슬라이더로(`LOGO3D_PARAM_RANGES`). 윤곽 최소 두께를 넘는 값은 상한으로
  자동 제한하고 이유를 한 줄로 알린다(1번의 `warnings` 사용).
- 색: 프리셋 팔레트 선택 + 틀 색·타일 색 직접 선택.
- 회전: x·y·z 슬라이더, 시점 전환(원근/등각), 줌 슬라이더·초기화 버튼.
- 스테이지: "배경 방식" 드롭다운(Gradient·Solid·Transparent), 배경 A·B 색, 배경 각도 슬라이더 — 어드민 에셋 배경 섹션과 같은 문구·배치. 모드에 맞지 않는 값은 비활성.
- 저장: 비율 선택(1:1·4:5·9:16·16:9)과 PNG 저장 버튼. 저장 중에는 버튼을 막고 완료 토스트(`sonner`)를 띄운다.

**메뉴**
- `adminNavItems.ts`의 "에셋" 항목 바로 아래에 `{ href: '/admin/logo-3d', label: '3D 로고', icon: IconCube }`를 추가한다. 아이콘 import도 추가한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `/admin/logo-3d`에서 폰트를 고르고 글자열을 입력하면 3D 로고가 나오고, SVG를 업로드하면 그 SVG가 3D로 나온다.
- 두께·외곽선 폭·둥글림 슬라이더가 형상에 반영되고, 윤곽 최소 두께를 넘는 값은 상한으로 줄며 안내 문구가 보인다.
- 틀 색·타일 색이 팔레트와 직접 선택으로 바뀐다.
- (2번 티켓 게이트 참고) 실제 브라우저에서 SVG 파일(`docs/assets/brand/jam_logo.svg`)을 업로드하면 브라우저 `DOMParser` 경로로 읽혀 3D 로고가 나온다 — 2번 티켓은 테스트에서 `@xmldom/xmldom`으로 대체해 검증했다.
- 회전 x·y·z 슬라이더와 마우스 드래그가 서로 동기화되고, 줌 인·아웃이 된다. "등각" 시점에서 카메라가 방위각 45°·고도 약 35.26° 직교 투영이다(`isometricCameraPose` 단위 테스트).
- 스테이지가 Gradient·Solid·Transparent 3모드로 바뀌고, 각 모드에서 쓰지 않는 입력은 비활성이다. Transparent로 저장한 PNG의 배경 픽셀 알파가 0이다.
- PNG 저장이 선택한 비율의 크기(`stageSizeFor`)로 나온다(단위 테스트: 4개 비율 모두).
- 형상을 바꿀 때 이전 `geometry`·`material`이 `dispose()`된다(코드 확인 또는 테스트).
- 어드민 사이드바 "에셋" 아래에 "3D 로고"가 나오고 클릭하면 `/admin/logo-3d`로 간다. 어드민이 아닌 계정은 기존 레이아웃 규칙대로 접근할 수 없다.
- 새 화면은 shadcn/ui 컴포넌트만 쓴다(네이티브 `<select>` 없음).
- (1번 티켓 게이트 alert) 틀 폭·틀 베벨 슬라이더를 최솟값·최댓값 어느 조합으로 움직여도 `buildLogoGeometry`가 돌려주는 윗면 삼각형의 넓이/최장변²가
  2×10⁻⁴ 이상이다 — 경계 조합(틀 폭 최소 × 베벨 최대 등)을 포함한 테스트로 확인한다. 기본값의 품질 여유가 약 2배뿐이다.
- (1번 티켓 게이트 alert) 베벨이 틀 폭에 맞춰 자동으로 줄어든 경우 `warnings` 문구를 패널에 한 줄로 보여준다(`LOGO3D_PARAM_RANGES`의 `frameBevelRadius` 최댓값 0.04가
  `frameWidth` 최솟값 0.01보다 크다).
- `docs/service/prd/logo-3d/PRD.md`가 있고 색인에 걸려 있다.
- `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).

### 주요 의사결정 / 핵심 메모
- **재작업 사유(게이트 FAIL)**: 틀 폭 최소(0.01) × 틀 베벨 최대(0.04) 조합에서 윗면 삼각형 205개가 품질 기준(2×10⁻⁴) 미만이었고, 그 조합을 `it.fails`로 가려 CI가 초록으로 나왔다. 사용자가 「엔진을 고쳐서 재작업」을 선택했다. 베벨 상한에 윗면 띠 폭 하한(`MIN_LID_BAND=0.0003`)을 두어 경계 조합 12개를 모두 통과시켰다.
  **진단 정정**: 처음 진단(삼각분할 실패 → earcut 복귀)은 틀렸다. 실제 원인은 Clipper2 삼각분할이 일직선 위 중간 점을 지워 긴 직선 띠가 양 끝점만 남는 것이었다.
- **하한 값 선택**: 제안했던 0.0015~0.002는 기본 베벨 0.0145를 0.0141로 깎아 1번 티켓의 기존 시험 2건을 깨서 쓰지 않았다. 하한 0.0003~0.0006은 통과, 0.0004·0.0007은 경계 1건 실패, 0.0008은 기본 시험을 깬다(값이 단조롭지 않다).
- **로컬 실렌더에서 발견한 결함과 카리나 직접 수정**: 단위 테스트·게이트·CI가 모두 통과했는데 실제 화면에서 "JAM" 중 J만 3D로 나오고 A·M은 두께 없는 얇은 면이었다. 원인은 `withDelaunayLids`가 `geometry.groups.find`로 **첫 옆면 그룹 하나만** 가져온 것
  (`ExtrudeGeometry`는 글자마다 옆면 그룹을 만든다). 윤곽이 둘 이상인 모든 입력(여러 글자, 안쪽 섬이 있는 A 단독)이 영향을 받았다. 1번 티켓 테스트는 글자 하나씩만 시험했다. 모든 옆면 그룹을 쓰도록 고치고(약 12줄), 표면 전체 넓이를 글자별 합과 견주는 회귀 시험 3개를 더했다(수정 전 코드에서 3개 모두 실패, 수정 후 통과).
  실제 폰트로 재측정한 "JAM" 틀 부피 0.0291 → 0.1329. 규모가 작고 원인이 분명해 파이프라인 없이 카리나가 직접 고쳤다. **중간에 진단이 한 번 틀렸다**: 여러 윤곽을 한 번에 삼각분할하는 문제로 보고 고쳤으나 결과가 같아 되돌렸고, 단계별 추적으로 옆면 그룹 선택임을 찾았다. 첫 회귀 시험도 윗면 넓이만 재서 결함을 못 잡았다(수정 전 코드에서도 통과) — 표면 전체 넓이로 바꿨다.
- **구현 선택(아현)**: 마우스 드래그는 `OrbitControls`(카메라를 돌림) 대신 로고 그룹 회전으로 구현해 회전 슬라이더 값과 합친다. 파일명의 비율 `:`는 `x`로(`logo-3d-JAM-16x9.png`). 굵기 100~900을 모두 노출하고 폰트에 없는 굵기는 API 오류를 패널에 보인다. 기본 폰트 Poppins 700, 기본 글자열 `JAM`.
  타일 두께·틈·바깥/안쪽 윤곽 둥글림은 기본값으로 고정하고 슬라이더 5종만 노출.
- **팔레트 6종과 배경 A·B 기본색은 아현이 임의로 정했다.** 채원 확인이 필요하다(잔여 이슈).
- **머지 절차**: 브랜치가 최신 staging 위에 있지 않아 임시 워크트리에서 `origin/staging` 위로 리베이스(충돌 없음, 상황판 파일 보존 확인)했다. 기존 review 브랜치를 덮어쓰는 강제 push는 권한 설정이 막아, 같은 내용을 새 브랜치(`-r2`)로 일반 push해 CI를 돌리고 그 커밋들을 staging에 fast-forward로 머지했다.
- 아현은 격리 워크트리의 `node_modules` 링크를 `npm ci` 실설치로 바꿨다(새 의존성 때문). 메인 폴더에는 `npm install`로 빠진 의존성만 추가했다(lock 변경 없음).
