# [Admin] 예약된 기획안의 카피를 공개 전까지 직접 고친다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-03 «에이전트가 제시한 홈피드, 미션 생성의 기획안에서 카피를 내가 수정할 수 있도록 해», 범위는 «예약됨까지 열기»로 사용자가 골랐다): 어드민 상황판에서 홈피드 카드와 미션의 문안(제목·부제·설명·달성 조건 문장)을 지금은 「검토중」에서만 고칠 수 있다. 승인하면 곧바로 예약되므로 승인 뒤에는 어떤 카피도 고칠 수 없다. 「예약됨」 항목도 공개 시각 전까지는 문안을 고칠 수 있게 한다.
- 구현 계획: 문안(`copy.<키>`)만 고치는 예약됨 전용 수정 경로를 만든다. 수정본(`edited`)을 쓰고, 이미 만들어진 자원 행(`today_cards`·`missions`)의 같은 열도 한 번에 고친다. 저장할 때 카피 규칙 검사(`copyRules.ts`)를 그대로 통과해야 한다.
- 관련 파일(지도):
  - 서버 진입: `jam-web/src/app/api/admin/ops-inbox/[bundleId]/decisions/route.ts`(`edit` 분기 `switch (action)` 70줄 근처), `jam-web/src/lib/admin/opsInbox/decide.ts`(`editItem` 623줄 근처. 지금 `item.status !== 'reviewing'`이면 409, `saveEditedItem`·`revalidateOpsItem`·`blockingFieldErrors` 재사용).
  - 순수 계산: `jam-web/src/lib/admin/opsInbox/edit.ts`(`computeEditDiff`·`applyDiff`·`readEditableValues`. 예약됨 경로는 `copy.<키>` 밖의 경로를 400으로 거절).
  - 자원 쓰기: `jam-web/src/lib/admin/opsInbox/execute/handlers.ts`(`ExecuteHandler`에 선택 메서드 `updateCopy` 추가), `execute/homeFeedCard.ts`(`HOME_FEED_CARD_HANDLER`, `cancel`의 «공개 시각 조건부 쓰기» 패턴을 따른다), `execute/mission.ts`(미션 핸들러), `execute/registry.ts`.
  - 문안과 열의 대응: 카드는 `registerChecks/homeFeedFields.ts`의 `buildTodayCardInsertPayload`(title·subtitle·description), 미션은 `registerChecks/missionFields.ts`의 `buildMissionInsertPayload`(title·description·condition_text). `opsInbox/registerInput.ts`의 `toTodayCardRegisterInput`·`toMissionRegisterInput`이 `copy` → 페이로드로 옮긴다.
  - 화면: `jam-web/src/components/admin/ops/OpsItemFooter.tsx`와 `OpsCancelItem.tsx`(예약됨에서 [공개 전 취소하기]가 나오는 자리), `OpsItemActions.tsx`(`startEdit`·`decisionGuidance`), `OpsItemEditForm.tsx`(문안 칸만 보이는 모드), `OpsDecisionWorkspace.tsx`(초안 `draft` 상태).
  - 문서: `docs/service/prd/ops-tool/PRD.md` §7.3(직접 수정), §8.7(공개 전 취소)과 «화면에서 막는 안내 글»(`decisionGuidance`).

## 배경 / 문제 정의

윤진이 만든 묶음은 상황판 «기획 상세»에서 사람이 검토한다. 문안 수정 양식(`copy.title`·`copy.description` 등)은 이미 있지만 「검토중」 항목에서만 열린다. 승인과 예약 등록은 한 번에 일어나므로(티켓 20261026_2022·2031) 승인하는 순간 문안이 굳고, 승인한 항목은 「승인한 항목은 여기서 고칠 수 없어요」로 막힌다. 지금 DB에는 검토중 항목이 없고 홈피드 카드 24건·미션 6건이 모두 예약됨 또는 게재 중이다. 그래서 오늘 시점에는 카피를 고칠 방법이 사실상 없다(고치려면 마이그레이션 SQL로 `today_cards`·`missions`를 직접 바꿔야 한다. 2026-11-03에 40건을 그렇게 바꿨다).

## 상세 요구사항

### 서비스/코드베이스 관점

- **대상**: 상태가 「예약됨」이고 종류가 홈피드 카드(`home_feed_card`) 또는 미션(`mission`)인 항목. 게재 중·종료·취소·실패는 그대로 막는다.
- **고칠 수 있는 칸**: 문안 `copy.<키>`(제출된 키마다 한 칸, 문자열 값만)뿐이다. 색·시각·대상·「유저가 겪는 것」·`image_spec`은 이 경로에서 고치지 않는다(시각을 바꾸면 자원 행의 노출 기간도 달라지기 때문이다).
- **쓰는 곳 두 군데를 함께 맞춘다**:
  1. 항목의 수정본 `edited.copy`(제출 원본 `original`은 바꾸지 않는다. 기존 `applyDiff`의 최상위 키 덮어쓰기 규칙을 따른다).
  2. 이미 만들어진 자원 행의 같은 열(카드: `today_cards.title`·`subtitle`·`description`, 미션: `missions.title`·`description`·`condition_text`). 대상 행은 `created_resource`의 ID로 찾는다.
- **공개 전만 쓴다**: 자원 행 쓰기는 `starts_at > 지금` 조건부 update다. 공개 시각이 이미 지났으면 아무것도 바꾸지 않고 409 «이미 공개된 항목이라 고칠 수 없어요»로 알린다. 읽고 쓰는 사이에 공개 시각이 지나는 경우를 `cancel`과 같은 방식으로 다시 읽어 가른다.
- **두 쓰기가 어긋나지 않게 한다**: 자원 행을 먼저 고치고 항목 수정본을 저장한다. 수정본 저장이 실패(낙관적 잠금 409 포함)하면 자원 행을 원래 값으로 되돌리고 오류를 돌려준다. 되돌리기마저 실패하면 `#jam-alert` 글을 남기고 «화면을 새로 고쳐 확인해 주세요»를 돌려준다.
- **카피 규칙 검사를 그대로 건다**(구현 중 확인: `revalidateOpsItem`은 `collectCopyErrors`를 부르지 않고 카피 규칙은 예약 등록 변환 `toTodayCardRegisterInput`·`toMissionRegisterInput`에서만 돈다. 그래서 같은 변환을 고친 항목에 다시 돌려 고친 칸의 오류만 막는 `scheduledCopyRuleErrors`를 더했다): 저장 전에 규칙 검사가 돌아야 하고, 고친 칸에 걸린 오류는 저장을 막고 칸별 문장(`fieldErrors`)으로 돌려준다. 이미 검토중 경로가 쓰는 `blockingFieldErrors(validated, touchedKeys(diff))`를 재사용한다.
- **결정 기록과 되돌리기**: 결정 기록 `action = 'edit'`로 남기고 `diff`에 바뀐 칸 전후를 넣는다. 수정 되돌리기(`revert`)도 예약됨 항목의 문안 수정에 한해 열고, 되돌릴 때도 자원 행을 함께 되돌린다(`findRevertTarget`·`computeRevertDiff` 재사용). 슬랙 `#jam-report`에는 기존 수정 글과 같은 모양으로 올린다(항목 이름에 「예약됨」을 구분해 적을 필요는 없다).
- **막는 경우**: 핸들러가 `updateCopy`를 구현하지 않은 종류는 409 «아직 연결하지 않은 종류예요», 자원 ID가 `created_resource`에 없는 항목(시험 묶음의 `{ sample: true }` 포함)은 자원 쓰기를 건너뛰고 수정본만 고친다(시험 묶음은 자원이 없다, PRD §8.8).
- 카드와 미션은 서로 다른 항목이라 한쪽 제목을 고쳐도 다른 쪽이 따라 바뀌지 않는다(같은 카피를 두 곳에서 따로 고친다).

### UI/UX 관점

- 예약됨 항목의 하단 줄에 외곽선 [문안 고치기]를 [공개 전 취소하기] 옆에 둔다. 누르면 검토중과 같은 «상세 카드가 그 자리에서 편집 모드가 된다» 방식으로 열리되, 문안 칸(`copy.<키>`)만 보이고 나머지는 읽기 전용이다.
- 저장하기 전에 카피 규칙 위반을 칸마다 보여 준다(서버가 돌려주는 `fieldErrors`를 칸 아래에 그린다. 검토중 양식이 이미 하는 방식).
- 저장 뒤 10초 동안 토스트의 [되돌리기]가 나온다(검토중과 같다).
- 커버 이미지에 구워 넣은 글자(`image_spec.values`)는 이 양식에서 고칠 수 없다는 한 줄 안내를 둔다: 「카드 이미지 속 글자는 여기서 바뀌지 않아요」. (이미지 다시 만들기는 이 티켓 범위 밖이다.)
- 어드민 화면이라 채원 사전 판정 대상이 아니다. shadcn/ui 컴포넌트(`components/ui`)를 쓴다.

### 컨텐츠 관점

- 새 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md` 해요체와 용어(획득·드랍·픽업·체크인)를 따른다. 오류 문구는 [현상] → [원인] → [해결책].

## 구현 계획

규모가 크다(코드 8개 안팎, 테스트·문서 포함 12개 이상). 첫 호출부터 `planOnlyWaiver`를 넣고 아래 순서로 진행한다.

1. `execute/handlers.ts`: `ExecuteHandler`에 선택 메서드 `updateCopy(service, resourceId, fields, { now })`를 추가한다. 반환은 `{ ok: true, previous: Record<string, string | null> } | { ok: false, code: 'published' | 'error', failure }`처럼 «이전 값»을 돌려주는 모양으로 한다(롤백 근거).
2. `execute/homeFeedCard.ts`·`execute/mission.ts`: `updateCopy`를 구현한다. 카드는 `title`·`subtitle`·`description`, 미션은 `title`·`description`·`condition_text`만 받는다. 읽기 → `starts_at` 확인 → `.gt('starts_at', now)` 조건부 update → 0행이면 재조회로 «공개됨/없어짐» 가름(`cancel`의 패턴). 카드의 `subtitle`이 비어 있는 값은 null로 저장한다(`buildTodayCardInsertPayload`와 같다).
3. `decide.ts`: `editItem`의 상태 검사를 `reviewing`이면 기존 경로, `scheduled`이고 종류가 카드·미션이면 새 경로로 나눈다. 새 경로는 `copy.<키>` 이외 경로를 400으로 거절하고, `revalidateOpsItem` 뒤 핸들러 `updateCopy` → `saveEditedItem` 순으로 실행하며 실패하면 되돌린다. `revertEdit`도 같은 방식으로 `scheduled`를 허용한다.
4. `edit.ts`: 예약됨 전용 허용 경로 판정 함수(`isCopyOnlyPath` 등)를 순수 함수로 더한다.
5. 화면: `OpsItemFooter.tsx`·`OpsCancelItem.tsx` 쪽에 [문안 고치기]를 더하고 `OpsItemEditForm.tsx`에 «문안만» 모드를 더한다. `decisionGuidance`의 «이 항목은 이미 다음 단계에 있어서…» 안내를 예약됨 항목에는 쓰지 않는다.
6. 문서: PRD §7.3 «직접 수정» 표 행과 본문, §8.7, 안내 글 목록을 갱신한다. 예약됨 수정이 `scheduled` 상태를 유지한다는 점, 자원 행을 함께 고친다는 점, 공개 시각이 지나면 막힌다는 점을 적는다.
7. 시험(vitest): `edit` 예약됨 허용·거절 경로, `updateCopy` 조건부 쓰기(공개됨·없어짐·읽기 실패), 롤백(수정본 저장 실패 시 자원 행 복구), 카피 규칙 위반이 400 `fieldErrors`로 돌아오는 것, 게재 중·취소 항목은 409, 시험 묶음(`sample`)은 수정본만 바뀌는 것.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 예약됨 홈피드 카드와 미션에서 [문안 고치기]로 제목·설명(카드는 부제 포함, 미션은 달성 조건 문장 포함)을 저장하면 항목의 `edited.copy`와 자원 행(`today_cards`/`missions`)의 같은 열이 함께 바뀐다. 제출 원본(`original`)은 그대로다.
- 공개 시각이 지난 항목, 게재 중·종료·취소·실패 항목은 서버가 409로 거절하고 자원 행이 바뀌지 않는다(시험으로 확인).
- 카피 규칙 위반(예: `~하세요`, 설명의 `!`, 조건 요약 제목)은 400 `fieldErrors`로 칸별 문장이 돌아오고 저장되지 않는다(시험으로 확인).
- 수정본 저장이 실패하면 자원 행이 원래 값으로 돌아온다(시험으로 확인).
- 결정 기록에 `edit`가 남고 [되돌리기]로 자원 행까지 원래 값이 된다(시험으로 확인).
- 문안 이외 경로(`starts_at` 등)를 예약됨 항목에 보내면 400으로 거절된다.
- `npx vitest`로 이 변경의 시험이 통과하고 `scripts/verify.sh`가 통과한다.
- PRD §7.3·§8.7이 새 동작과 일치한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 로컬 `next dev`(`ADMIN_EMAILS` 환경변수)에서 예약됨 항목에 [문안 고치기]가 보이고 저장되는 것을 실렌더로 확인한다(`DEV_PROCESS_GUARDRAILS.md` 패턴 13).
- 프로덕션 DB 변경이 없으므로 SQL 실행은 없다.

## 가정과 범위 밖

- 시각·색·대상·`image_spec` 수정은 예약됨에서 열지 않는다. 커버 이미지 글자를 새 카피에 맞게 다시 굽는 일은 별도 티켓이다.
- 게재 중인 항목의 문안 수정(공개 뒤 수정)은 열지 않는다. 필요하면 공개 시각 조건 없이 고치는 별도 경로가 필요하고, 이미 노출 중인 문구가 바뀌므로 따로 결정한다.
- 이미 예약된 24건 중 상황판의 `original`은 옛 제출 문구를 보인다. 이 티켓은 그 표시를 맞추지 않는다(수정본이 있으면 수정본을 먼저 읽는 기존 규칙만 따른다).

## 완료 기록

### 구현 내용 요약
예약됨 홈피드 카드·미션의 문안을 공개 시각 전까지 고칠 수 있게 했다. 서버는 핸들러 선택 메서드 `updateCopy`(카드·미션, 공용 `execute/copyColumns.ts`)로 자원 행의 문안 열을 `starts_at > 지금` 조건부로 고치고, 이어서 항목 수정본(`edited.copy`)을 저장한다. 수정본 저장이 실패하면 자원 행을 이전 값으로 되돌리고, 되돌림도 실패하면 `#jam-alert` 글과 새로 고침 안내(500)를 낸다. 결정 기록은 `edit`, 수정 되돌리기도 예약됨 문안 수정에 한해 열었다(예약 전 수정이 대상이면 409이고 화면이 [되돌리기]를 숨긴다). 화면은 예약됨 줄에 [문안 고치기]를 두고 문안 칸만 보이는 편집 모드를 연다(기획 상세와 일정표 서랍 공통). PRD §6.1·§7.3·§8.7 갱신.
