# [Admin] 3D 로고 제너레이터 — 「SVG 파일」 모드를 고르면 기본으로 JAM! 로고 SVG를 3D로 보여 준다

> 2026-11-03 사용자 요청: 「svg 선택 시 기본으로 로고 svg를 사용하도록 해」. 상위 티켓 [20261103_1349](20261103_1349_Feature_3D-로고-제너레이터-별도-어드민-페이지-상위.md)의 후속 개선이다.

## 핵심 요약

- 요구사항: `/admin/logo-3d`에서 입력 방식을 「SVG 파일」로 바꿨을 때, 올린 파일이 없으면 지금처럼 빈 상태가 아니라 JAM! 로고(`docs/assets/brand/jam_logo.svg`와 같은 J·A·M 세 글자 SVG)가 바로 3D로 나온다. SVG를 올리면 올린 파일로 바뀐다.
- 구현 계획: 로고 SVG 문자열을 상수로 두고(`logo3dDefaultSvg.ts` 신설), 페이지에서 `source === 'svg'`이고 올린 SVG가 없을 때 그 상수를 `svgToOutline`에 넣어 `svgResult`를 채운다. 디자인시스템의 로고 파일과 상수 내용이 다르면 실패하는 동기화 시험을 둔다(로고 교체 티켓 20260925_1125가 나중에 로고를 바꿔도 이 화면이 낡은 로고를 쓰지 않게).
- 관련 파일(줄 위치는 신설 시점 기준)
  - `jam-web/src/app/admin/logo-3d/logo3dDefaultSvg.ts`(신설) — `DEFAULT_LOGO_SVG`(문자열), `DEFAULT_LOGO_SVG_LABEL`(= `'jam-logo'`, PNG 파일명용)
  - `jam-web/src/app/admin/logo-3d/page.tsx` — `svgResult` 상태(58줄), 폰트 입력 효과(`useEffect`, 68줄 이후)와 같은 방식의 SVG 기본 효과 추가, `handleSvgFile`(154~166줄), PNG 파일명 label(176줄 근처)
  - `jam-web/src/app/admin/logo-3d/Logo3DPanel.tsx` — SVG 안내 문구(296줄 근처 「올린 파일: …」 삼항식)
  - `jam-web/src/app/admin/logo-3d/logo3dConfig.ts` — `svgText`·`svgName`(23~24줄 타입, 65~66줄 기본값) — 변경 없음, `svgText === ''`가 「기본 로고」를 뜻한다
  - `jam-web/src/app/admin/logo-3d/__tests__/logo3dDefaultSvg.test.ts`(신설)
  - 로고 원본: `jam-web/design-system/assets/logo/jam-logo.svg`(1,413바이트, fill=white, 세 `<path>`). `docs/assets/brand/jam_logo.svg`와 도형이 같고 fill만 black이다.
  - `docs/service/prd/logo-3d/PRD.md`(입력 방식 설명에 한 줄)

## 배경 / 문제 정의

지금은 「SVG 파일」을 고르면 파일을 올리기 전까지 미리보기가 비어 있다(안내 문구만 있음). 이 도구를 쓰는 가장 흔한 입력이 JAM! 로고인데 매번 파일을 찾아 올려야 한다. 기본으로 로고가 보이면 모드 전환만으로 바로 결과를 볼 수 있고, SVG 입력 경로(브라우저 `DOMParser`)도 즉시 확인된다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 「SVG 파일」 모드로 바뀌고 올린 SVG가 없으면(`state.svgText === ''`) `DEFAULT_LOGO_SVG`를 `svgToOutline`에 넣어 `svgResult`에 적용한다. 이미 올린 SVG가 있으면 그것을 그대로 쓴다(기본 로고로 덮어쓰지 않는다).
- 올린 SVG를 읽는 데 실패해도(`handleSvgFile`의 오류 경로) 직전 형상이 유지되는 기존 동작은 그대로다. 오류 뒤에 기본 로고로 되돌아가지 않는다.
- 로고 SVG는 **파일을 새로 서버에 두거나 네트워크로 받아 오지 않는다.** 문자열 상수로 번들에 포함한다(1.4KB).
- 로고 상수는 디자인시스템 로고 파일과 같아야 한다 — 같은지 확인하는 시험이 실패하면 상수를 새 로고로 갱신하라는 신호다.
- 서버 렌더링(SSR) 중에는 `DOMParser`가 없으므로 이 변환은 클라이언트에서만 돌린다(`useEffect` 안). 초기 상태가 서버와 클라이언트에서 달라져 하이드레이션 경고가 나면 안 된다.

### UI/UX 관점
- 「SVG 파일」 모드 + 올린 파일 없음일 때 안내 문구(`Logo3DPanel.tsx` 296줄 근처)를 「기본 로고(JAM!)를 보여 주고 있어요. SVG 파일을 올리면 바꿀 수 있어요.」 식으로 바꾼다(해요체, 사용자가 올린 것으로 오해하지 않게 「올린 파일」이라는 표현을 쓰지 않는다). 정확한 문구는 구현자가 정하되 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.
- 올린 파일이 있으면 지금처럼 「올린 파일: {파일명}」을 보인다.
- 기본 로고일 때 PNG 파일명은 `logo-3d-jam-logo-{비율}.png`가 되도록 `label`에 `DEFAULT_LOGO_SVG_LABEL`을 쓴다.

### 컨텐츠 관점
- 해당 없음.

## 구현 계획

1. `logo3dDefaultSvg.ts`를 신설한다. `DEFAULT_LOGO_SVG`는 `design-system/assets/logo/jam-logo.svg`의 내용을 그대로 옮긴 문자열이다.
2. `page.tsx`에 효과를 추가한다: `source === 'svg'`이고 `state.svgText === ''`일 때 `svgToOutline(DEFAULT_LOGO_SVG)`를 `setSvgResult((prev) => applyResult(prev, result))`로 적용한다. 의존성은 `[source, state.svgText]`. `handleSvgFile`은 건드리지 않는다.
3. 패널 문구와 PNG label을 위 UX 항목대로 바꾼다.
4. 시험 `logo3dDefaultSvg.test.ts`:
   - `DEFAULT_LOGO_SVG`가 `design-system/assets/logo/jam-logo.svg` 파일 내용과 공백 차이를 빼고 같다(`node:fs`로 읽어 비교).
   - `svgToOutline(DEFAULT_LOGO_SVG)`가 J·A·M 세 영역을 돌려주고 A에 구멍이 1개다(`svgOutline.test.ts`와 같은 `@xmldom/xmldom` 준비를 쓴다).
5. PRD 입력 방식 설명에 한 줄을 더한다.

- 「SVG 파일」 모드로 바꾸고 올린 파일이 없으면 JAM! 로고가 3D로 나온다(J·A·M 세 글자 모두 두께와 틀이 있다). 시험으로 `svgToOutline(DEFAULT_LOGO_SVG)`의 결과(세 영역, A의 구멍 1개)를 확인한다.

### 주요 의사결정 / 핵심 메모
- 티켓은 `useEffect` 안에서 `setSvgResult`로 채우라고 했으나 lint 규칙 `react-hooks/set-state-in-effect`가 오류를 내서, 렌더 중 `useMemo` 파생값(`defaultSvgResult`)으로 바꿨다. `source === 'svg' && svgText === ''`일 때만 변환하고 `typeof DOMParser !== 'undefined'` 가드를 둬 서버 렌더링에서 변환이 돌지 않는다(하이드레이션 불일치 없음). 게이트가 사유를 받아들였다.
- 로고 SVG는 서버 파일이 아니라 문자열 상수(1.4KB)로 번들에 넣고, 디자인시스템 로고와 다르면 실패하는 동기화 시험을 둬 로고 교체(티켓 20260925_1125) 때 낡은 로고를 쓰지 않게 했다.
- 이 화면은 곧 에셋 3D 모드로 옮겨진다(상위 티켓 20261103_1733). 이 로직은 그때 함께 옮긴다.

### 잔여 이슈
- 기본 로고 상태에서 SVG를 올리다 읽기 실패하면 오류가 기본 로고 위에 표시된다(게이트 참고 사항, 의도된 동작).
