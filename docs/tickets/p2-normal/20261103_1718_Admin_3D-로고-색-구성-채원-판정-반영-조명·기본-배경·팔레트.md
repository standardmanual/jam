# [Admin] 3D 로고 제너레이터 — 채원의 색 구성 판정과 사용자 레퍼런스를 반영해 색감·질감을 살린다 (조명·재질·기본 배경·팔레트·팔레트별 배경 세트)

> 2026-11-03 채원(`jam-designer`)의 사후 색 구성 판정(확신도 보통)에서 나온 중대 문제 2건과 제안을 사용자가 「전부 반영」으로 확정했다.
> 같은 날 사용자가 「렌더링되는 색감이 너무 탁하고 질감 표현이 부족하다」며 레퍼런스 이미지(# 모양: 선명한 파랑 배경, 유약 광택이 강한 하늘색 타일, 베벨에 밝은 하이라이트 선이 있는 건메탈 틀)를 주어 질감 요구를 더했다.
> 3번 티켓(20261103_1352) 완료 기록의 잔여 이슈 「팔레트 6종·배경 기본색 채원 확인」을 닫는 후속이다.
> **착수 조건(변경)**: 3D가 에셋의 「3D」 모드로 통합된다(상위 티켓 20261103_1733). 이 티켓은 하위 티켓 1734~1738이 머지된 뒤 시작하며, 그때 파일 위치(패널·뷰포트가 에셋 쪽으로 옮겨짐)와 배경 처리(3D 자체 배경 대신 에셋 Background 공유 — D의 `bgTouched`는 에셋 공유 배경을 대상으로 한다)를 통합 구조에 맞춰 카리나가 고친 뒤 실행한다. 아래 줄 위치는 통합 전 기준이다.

> **진행 메모 (2026-11-03, 카리나)**: 사용자가 「조명을 받은 콘트라스트가 더 강했으면, 타일이 너무 플랫한데 반사광이 더 표현되었으면」을 요청해 **E(질감)와 A(조명·톤매핑)를 먼저 처리했다.** 로컬 실렌더를 보며 값을 정해 `jam-web/src/app/admin/assets/logo3d/Logo3DViewport.tsx`의 `LOGO3D_LOOK` 상수 한 곳에 모았다:
> - 톤매핑 `ACESFilmicToneMapping` → `NeutralToneMapping`(노출 1.0), 환경 바탕 0.05(어둡게), 작고 아주 밝은 소프트박스(세기 8~30)와 검은 면으로 대비 — 넓은 밝은 면은 확산광이 많아 타일 색을 허옇게 띄워서 쓰지 않았다.
> - 타일이 평평한 거울이라 어떤 조명에서도 면 전체가 같은 밝기로 비쳐 질감이 없었다 → 형상은 그대로 두고 **유약 결 법선 맵**(`createGlazeNormalMap`, 완만한 굴곡 + 미세한 결)을 바탕층·광택층에 넣고, 기본 각도에서 타일이 비추는 방향 둘레에 대각선 반사광 띠 세 줄을 두었다.
> - 틀 거칠기 0.36 → 0.3(새틴 스틸), 타일 거칠기 0.1·광택층 거칠기 0.03, 키 라이트 1.0.
> 남은 범위는 **B(기본 배경)·C(팔레트 7종)·D(팔레트가 배경도 바꿈)**이다. 통합 뒤 파일이 `assets/logo3d/`로 옮겨졌으므로 아래 줄 위치는 옛 위치 기준이다 — 실행 전에 고쳐 쓴다. 3D 배경은 이제 에셋 Background(Shape와 공유)이므로 B·D는 그 공유 배경을 대상으로 한다.

|---|---|---|
| 배경 | 좌상 `#6ed3fe` → 우하 `#29a3f3` (채도 높은 하늘색) | 좌 `#d4eff8` → 우 `#75b3e6` (흰빛에서 번지는 연한 그라데이션) |

## 상세 요구사항

### 서비스/코드베이스 관점

**A. 미리보기 조명·톤매핑 (`Logo3DViewport.tsx`) — 중대 1** *(구현 구조는 아현, 최종 수치는 카리나가 머지 뒤 로컬 실렌더로 조정 — 아래 E 참고)*
- 환경 바탕 상자 색을 `Color(0.16, 0.18, 0.21)`에서 `Color(0.34, 0.37, 0.42)` 안팎으로 올린다.
- 어두운 띠 3장(156~158줄)의 `0.01`을 `0.04` 정도로 올린다.
- 톤매핑을 `NeutralToneMapping`(색상·채도 보존)으로 시험해 채도가 살아나는지 렌더로 확인한다. 안 되면 `ACESFilmicToneMapping`을 유지하고 다른 조정(틀 `metalness`를 `0.95`에서 `0.85`로 낮추기)을 쓴다. 값은 **렌더 결과의 「확인 기준」을 맞추도록 실측으로 정하고** 사유를 완료 기록에 남긴다.
- 틀 재질의 거칠기(0.36, 매트 스틸)·타일 재질은 바꾸지 않는다.

**B. 기본 배경 (`logo3dConfig.ts`) — 중대 2**
- `DEFAULT_LOGO3D_STATE`의 `bgA`를 `#6ed3fe`, `bgB`를 `#29a3f3`, 배경 각도를 `-45`로 바꾼다(`composeBackground` 기준으로 양수는 위쪽 회전이라 좌상→우하는 음수). `DEFAULT_BG_ANGLE`이 어드민 에셋과 같은 값이라는 주석이 있으므로, 이 화면의 기본 각도를 따로 두고 주석을 고친다(어드민 에셋 쪽 값은 바꾸지 않는다).

**C. 팔레트 값 조정과 추가 (`PALETTES`)**
- 타입을 `Logo3DPalette = { id; name; frame; tile; bgA; bgB; bgAngle }`로 넓힌다(`bgAngle`은 도).
- 아래 값으로 7종을 만든다(채원 제안 + 사용자 「전부 반영」). 「스틸 · 민트」는 유지하고 「스틸 · 그린」을 7번째로 추가한다.

| id | 이름 | 틀 | 타일 | `bgA` → `bgB` | 각도 |
|---|---|---|---|---|---|
| steel-sky | 스틸 · 하늘 | `#9ba3ab`(유지) | `#a9e0ff`(전 `#7cc4f0`) | `#6ed3fe` → `#29a3f3` | -45 |
| steel-mint | 스틸 · 민트 | `#9ba3ab`(유지) | `#9ff0d6`(전 `#7fdcc0`) | `#8fe9d3` → `#2fb8a0` (제안값, 렌더로 확인) | -45 |
| steel-green | 스틸 · 그린 (신규) | `#9ba3ab` | `#7be39b` | `#7ee6a0` → `#1fae6a` | -45 |
| steel-rose | 스틸 · 로즈 | `#a3a0a6`(유지) | `#ffc0d0`(전 `#f4a3b8`) | `#ffb3c8` → `#ee6f95` | -45 |
| gold-cream | 골드 · 크림 | `#c9a24a`(유지) | `#f6ecd6`(유지) | `#35457a` → `#141a3d` | -45 |
| graphite-lime | 그래파이트 · 라임 | `#5d636b`(전 `#4b5057`) | `#c4e56a`(유지) | `#f1f0eb` → `#cfc9b4` | -45 |
| copper-navy | 코퍼 · 네이비 | `#b8764f`(유지) | `#5c7fd1`(전 `#3d5a9e`) | `#f6e7d6` → `#e0b48f` | -45 |

- 첫 항목(스틸 · 하늘)이 기본값이다. `DEFAULT_LOGO3D_STATE`의 `frameColor`·`tileColor`·`bgA`·`bgB`·`bgAngle`은 첫 팔레트에서 파생해 **값이 두 곳에서 어긋나지 않게** 한다(B의 기본 배경과 스틸 · 하늘 팔레트의 배경이 같은 값).
- 「스틸 · 민트」의 배경값은 채원 표에 없어 같은 규칙(밝은 계열 → 진한 계열, -45°)으로 정한 제안값이다. 렌더로 확인해 어색하면 조정하고 완료 기록에 최종값을 남긴다.

**D. 팔레트가 배경도 바꾼다 (`Logo3DPanel.tsx`, `Logo3DState`) — 패널 UX 제안**
- 상태에 `bgTouched: boolean`(기본 `false`)을 추가한다. 배경 방식 선택·배경 A·B 색·배경 각도를 사용자가 직접 바꾸면 `true`가 된다.
- 팔레트를 누르면 틀·타일은 항상 바꾸고, **`bgTouched`가 `false`일 때만** `bgA`·`bgB`·`bgAngle`도 그 팔레트의 값으로 바꾼다(배경 방식은 바꾸지 않는다). 사용자가 직접 지정한 배경은 유지된다.
- 틀 색·타일 색을 직접 바꿀 때의 기존 동작(`paletteId: ''`)은 그대로다.
- 이 변환은 순수 함수(예: `applyPalette(state, palette)`)로 `logo3dConfig.ts`에 두고 시험한다.

**E. 질감 — 사용자 레퍼런스 기준 (`Logo3DViewport.tsx`)**

레퍼런스와 지금 웹 렌더의 차이: ① 배경이 채도 높은 선명한 파랑인데 웹은 흰빛이 섞여 탁하다 ② 타일은 유약 광택이 강해 대각선으로 넓고 밝은 반사 줄기와 하이라이트가 보이는데 웹은 반사가 거의 없어 평평한 청회색이다 ③ 틀은 어두운 건메탈 위에 베벨을 따라 밝은 하이라이트 선이 또렷한데 웹은 대비 없이 어둡게 뭉개진다.
- **환경 맵을 「스튜디오 조명」 구조로 만든다**: 어두운 바탕에 **아주 밝은 소프트박스 면**(발광 세기를 지금보다 크게, 예: 4~10 범위)을 2~3장 두어, 광택 있는 타일에는 넓은 대각선 반사 줄기가, 금속 틀 베벨에는 가는 하이라이트 선이 맺히게 한다. 밝은 면과 어두운 면의 대비가 질감의 핵심이다(Blender 작업에서도 밝은 띠·어두운 띠가 번갈아 있어야 크롬으로 읽혔다).
- **타일 재질**: `MeshPhysicalMaterial`의 광택층(`clearcoat` 1, `clearcoatRoughness` 0.03~0.08)으로 유약 반사를 또렷하게 하고, 기본 거칠기는 0.15~0.3 범위에서 조정한다. 아주 미세한 표면 굴곡(노이즈 법선 맵, 세기 매우 약하게)은 넣을 수 있으면 넣는다(도자기 느낌, 반사 줄기가 살짝 일렁임).
- **틀 재질**: 사용자가 앞서 「외곽선은 스틸 매트한 질감」을 요청했으므로 거울 같은 크롬으로 만들지 않는다. 금속성 1에 거칠기 0.22~0.32 범위의 **새틴(반무광) 스틸**로, 레퍼런스처럼 베벨 하이라이트 선과 어두운 면의 대비가 보이게 한다.
- **색 관리**: 톤매핑은 채도를 덜 빼는 `NeutralToneMapping`을 기본으로 시험하고 노출(`toneMappingExposure`)을 함께 조정한다. 재질 색과 배경 색이 sRGB로 올바르게 해석되는지(`ColorManagement`, `outputColorSpace`) 확인한다.
- **구현 담당 분리**: 격리 워크트리에서는 렌더를 볼 수 없어 수치를 맞출 수 없다(지난 실행에서 탁한 결과가 나온 원인). 아현은 **조정 가능한 구조**(소프트박스 개수·위치·세기, 재질 값, 톤매핑·노출을 상수로 모아 한 곳에서 바꿀 수 있게)와 노이즈 법선 맵 생성까지 만들고, 최종 수치는 카리나가 머지 뒤 로컬 실렌더로 레퍼런스와 대조하며 정한다(후속 범위).

### UI/UX 관점
- 팔레트 버튼 목록에 「스틸 · 그린」이 추가되어 7개가 한 줄에 어색하게 넘치지 않게 배치한다(기존 줄바꿈 방식 유지).
- 사용자 노출 문구는 새로 늘리지 않는다(팔레트 이름 「스틸 · 그린」만 추가, 해요체·용어 규칙은 `docs/service/writing/UX_WRITING_GUIDELINE.md`).

### 컨텐츠 관점
- 해당 없음. (트라이브 10종은 트라이브별 대표색이 없어 팔레트와 겹치지 않는다는 채원 확인.)

## 구현 계획

1. `logo3dConfig.ts`: 타입 확장 → `PALETTES` 7종 → `DEFAULT_LOGO3D_STATE` 파생 → `bgTouched` → `applyPalette` 순수 함수. 시험을 같이 쓴다.
2. `Logo3DPanel.tsx`: 팔레트 `onClick`을 `applyPalette`로 바꾸고, 배경 입력(방식·A·B·각도) 변경 때 `bgTouched: true`를 함께 넘긴다.
3. `Logo3DViewport.tsx`: 환경 바탕 상자·어두운 띠·톤매핑을 A대로 조정한다. 격리 워크트리에서는 렌더가 안 되므로 값은 코드·시험 기준으로 두고, 실제 수치 대조는 카리나가 머지 뒤 로컬에서 한다.
4. PRD(`docs/service/prd/logo-3d/PRD.md`)의 팔레트·기본값 설명이 있으면 새 값과 「팔레트가 배경도 바꾼다」를 한 줄 반영한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `DEFAULT_LOGO3D_STATE`의 `bgA`=`#6ed3fe`, `bgB`=`#29a3f3`, 배경 각도=`-45`, 기본 타일=`#a9e0ff`(단위 테스트).
- `PALETTES`가 위 표의 7종 값과 일치하고, `DEFAULT_LOGO3D_STATE`의 틀·타일·배경이 첫 팔레트와 어긋나지 않는다(단위 테스트: 기본 상태 = 첫 팔레트 적용 결과).
- `applyPalette`: `bgTouched=false`에서 팔레트를 고르면 틀·타일·`bgA`·`bgB`·`bgAngle`이 모두 그 팔레트 값으로 바뀌고, `bgTouched=true`에서는 틀·타일만 바뀌고 배경은 그대로다(단위 테스트 두 경우).
- 배경 방식·배경 A·B 색·배경 각도를 직접 바꾸면 `bgTouched`가 `true`가 된다(코드 확인 또는 시험).
- `Logo3DViewport.tsx`의 조명·재질 값(환경 바탕 색, 소프트박스 개수·위치·발광 세기, 틀·타일 재질 값, 톤매핑 종류·노출)이 **이름 붙은 상수 한 곳**에 모여 있어 카리나가 값만 바꿔 조정할 수 있다. 초기값은 A·E의 제안 범위 안이다(코드 확인).
- 타일 재질에 광택층(`clearcoat`)이 있고, 미세 표면 굴곡용 노이즈 법선 맵을 만들었다면 생성 함수가 시험된다(크기·값 범위).
- 기존 시험이 모두 통과하고, `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).

### 후속 범위 (담당: 카리나, 시점: 머지 뒤, push 전)
- **조명·재질 최종 수치 조정**: 로컬 실렌더를 보며 E의 상수를 레퍼런스(사용자 첨부 # 이미지: 선명한 파랑 배경, 넓은 대각선 반사 줄기가 있는 유약 타일, 베벨 하이라이트 선이 있는 새틴 스틸 틀)에 맞춘다. 바꾼 값과 사유를 완료 기록에 남기고, 조정 커밋도 `verify.sh`를 통과시킨다.
- 메인 트리 `ADMIN_EMAILS` 개발 서버로 `/admin/logo-3d`를 열어 **세 지점의 수치로 다시 대조**한다. 확인 기준(스크린샷 픽셀, 대략값):
  - 배경: 좌상 ≈ `#6ed3fe`, 우하 ≈ `#29a3f3`
  - 타일: `#ade3ff` 안팎이고 배경보다 밝다(타일이 배경에 묻히지 않는다)
  - 틀: 옆면이 `#585e69`보다 어둡지 않다. 특히 「그래파이트 · 라임」의 틀이 검정으로 죽지 않는다
- 7개 팔레트를 하나씩 눌러 틀·타일·배경이 어울리는지, 팔레트를 누른 뒤 배경 색을 직접 바꾸고 다른 팔레트를 눌러도 배경이 유지되는지 눈으로 확인한다.
- 어긋나면 값을 조정하고 완료 기록에 최종값을 남긴다. 필요하면 채원에게 재확인을 요청한다.
