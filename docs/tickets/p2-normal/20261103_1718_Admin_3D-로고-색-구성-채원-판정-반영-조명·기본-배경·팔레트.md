# [Admin] 3D 로고 제너레이터 — 채원의 색 구성 판정과 사용자 레퍼런스를 반영해 색감·질감을 살린다 (조명·재질·기본 배경·팔레트·팔레트별 배경 세트)

> 2026-11-03 채원(`jam-designer`)의 사후 색 구성 판정(확신도 보통)에서 나온 중대 문제 2건과 제안을 사용자가 「전부 반영」으로 확정했다.
> 같은 날 사용자가 「렌더링되는 색감이 너무 탁하고 질감 표현이 부족하다」며 레퍼런스 이미지(# 모양: 선명한 파랑 배경, 유약 광택이 강한 하늘색 타일, 베벨에 밝은 하이라이트 선이 있는 건메탈 틀)를 주어 질감 요구를 더했다.
> 3번 티켓(20261103_1352) 완료 기록의 잔여 이슈 「팔레트 6종·배경 기본색 채원 확인」을 닫는 후속이다.
> **착수 조건(변경)**: 3D가 에셋의 「3D」 모드로 통합된다(상위 티켓 20261103_1733). 이 티켓은 하위 티켓 1734~1738이 머지된 뒤 시작하며, 그때 파일 위치(패널·뷰포트가 에셋 쪽으로 옮겨짐)와 배경 처리(3D 자체 배경 대신 에셋 Background 공유 — D의 `bgTouched`는 에셋 공유 배경을 대상으로 한다)를 통합 구조에 맞춰 카리나가 고친 뒤 실행한다. 아래 줄 위치는 통합 전 기준이다.

> **진행 메모 (2026-11-03, 카리나)**: 사용자가 「조명을 받은 콘트라스트가 더 강했으면, 타일이 너무 플랫한데 반사광이 더 표현되었으면」을 요청해 **E(질감)와 A(조명·톤매핑)를 먼저 처리했다.** 로컬 실렌더를 보며 값을 정해 `jam-web/src/app/admin/assets/logo3d/Logo3DViewport.tsx`의 `LOGO3D_LOOK` 상수 한 곳에 모았다:
> - 톤매핑 `ACESFilmicToneMapping` → `NeutralToneMapping`(노출 1.0), 환경 바탕 0.05(어둡게), 작고 아주 밝은 소프트박스(세기 8~30)와 검은 면으로 대비 — 넓은 밝은 면은 확산광이 많아 타일 색을 허옇게 띄워서 쓰지 않았다.
> - 타일이 평평한 거울이라 어떤 조명에서도 면 전체가 같은 밝기로 비쳐 질감이 없었다 → 형상은 그대로 두고 **유약 결 법선 맵**(`createGlazeNormalMap`, 완만한 굴곡 + 미세한 결)을 바탕층·광택층에 넣고, 기본 각도에서 타일이 비추는 방향 둘레에 대각선 반사광 띠 세 줄을 두었다.
> - 틀 거칠기 0.36 → 0.3(새틴 스틸), 타일 거칠기 0.1·광택층 거칠기 0.03, 키 라이트 1.0.
> 남은 범위는 **B(기본 배경)·C(팔레트 7종)·D(팔레트가 배경도 바꿈)**이다. 통합 뒤 파일이 `assets/logo3d/`로 옮겨졌으므로 아래 줄 위치는 옛 위치 기준이다 — 실행 전에 고쳐 쓴다. 3D 배경은 이제 에셋 Background(Shape와 공유)이므로 B·D는 그 공유 배경을 대상으로 한다.

## 핵심 요약

> **통합 구조에 맞춰 고친 범위 (2026-11-03, 카리나)**: A(조명·톤매핑)와 E(질감)는 진행 메모대로 끝났다. 이번 실행 범위는 **B·C·D**이고, 3D 배경이 에셋 Background(Shape와 공유하는 `ShapeStudioState`의 `bgMode`·`bgA`·`bgB`·`bgAngle`)로 바뀐 데 맞춰 사용자가 두 가지를 새로 정했다.
> - **팔레트는 공유 배경을 항상 바꾼다**: Shape 모드의 그라데이션 프리셋(`handleSelectGradientPreset`)과 같은 동작이다. 원래 D의 `bgTouched`(직접 고친 배경 유지)는 **넣지 않는다**.
> - **3D 기본 배경은 3D로 처음 열 때만 적용한다**: `?mode=3d`로 에셋 화면을 바로 열면 공유 배경이 「스틸 · 하늘」 배경으로 시작한다. Shape·Ribbon에서 3D로 전환할 때는 배경을 바꾸지 않는다.

- 요구사항: 3D 팔레트 값을 채원 판정대로 조정하고 「스틸 · 그린」을 더해 7종으로 만든다. 팔레트마다 어울리는 배경(`bgA`·`bgB`·`bgAngle`)을 두고, 팔레트를 누르면 틀·타일과 함께 공유 배경도 그 값으로 바뀐다. 3D로 처음 열 때의 배경은 첫 팔레트(스틸 · 하늘)의 배경이다.
- 구현 계획: `logo3dConfig.ts`에 팔레트 타입·값·순수 함수를 두고, `page.tsx`가 팔레트 선택 처리기와 초기 상태를 맡고, `Logo3DSections.tsx`의 팔레트 버튼이 그 처리기를 부른다.
- 관련 파일

로컬 실렌더에서 웹 기본값이 Blender 확정본과 눈에 띄게 어긋난다. 채원이 두 결과를 픽셀로 비교한 결과(웹 스크린샷이 370px 축소본이라 수치는 대략값):

| 위치 | Blender 확정본 | 웹 기본값 렌더 |
|---|---|---|
| 배경 | 좌상 `#6ed3fe` → 우하 `#29a3f3` (채도 높은 하늘색) | 좌 `#d4eff8` → 우 `#75b3e6` (흰빛에서 번지는 연한 그라데이션) |
| 타일 | `#ade3ff` 안팎, 하이라이트 `#e2ffff`, 배경보다 밝다 | `#7e9eb5`~`#81a9c3`, 배경보다 어둡고 탁한 청회색 |

원인은 팔레트 색 값보다 **미리보기 조명과 배경 기본값**이다.

## 상세 요구사항

### 서비스/코드베이스 관점

**A. 조명·톤매핑, E. 질감 — 완료** (진행 메모 참고, `Logo3DViewport.tsx`의 `LOGO3D_LOOK`). 이번 실행에서는 건드리지 않는다.

**C. 팔레트 값 조정과 추가 (`logo3dConfig.ts`)**
- 타입을 `Logo3DPalette = { id; name; frame; tile; bgA; bgB; bgAngle }`로 넓힌다(`bgAngle`은 도, `composeBackground` 규칙상 0°는 왼쪽→오른쪽이고 양수는 위쪽 회전이라 좌상→우하는 `-45`).
- 아래 값으로 7종을 만든다(채원 제안 + 사용자 「전부 반영」). 「스틸 · 그린」은 「스틸 · 민트」 다음, 3번째에 둔다.

| id | 이름 | 틀 | 타일 | `bgA` → `bgB` | 각도 |
|---|---|---|---|---|---|
| steel-sky | 스틸 · 하늘 | `#9ba3ab`(유지) | `#a9e0ff`(전 `#7cc4f0`) | `#6ed3fe` → `#29a3f3` | -45 |
| steel-mint | 스틸 · 민트 | `#9ba3ab`(유지) | `#9ff0d6`(전 `#7fdcc0`) | `#8fe9d3` → `#2fb8a0` (제안값) | -45 |
| steel-green | 스틸 · 그린 (신규) | `#9ba3ab` | `#7be39b` | `#7ee6a0` → `#1fae6a` | -45 |
| steel-rose | 스틸 · 로즈 | `#a3a0a6`(유지) | `#ffc0d0`(전 `#f4a3b8`) | `#ffb3c8` → `#ee6f95` | -45 |
| gold-cream | 골드 · 크림 | `#c9a24a`(유지) | `#f6ecd6`(유지) | `#35457a` → `#141a3d` | -45 |
| graphite-lime | 그래파이트 · 라임 | `#5d636b`(전 `#4b5057`) | `#c4e56a`(유지) | `#f1f0eb` → `#cfc9b4` | -45 |
| copper-navy | 코퍼 · 네이비 | `#b8764f`(유지) | `#5c7fd1`(전 `#3d5a9e`) | `#f6e7d6` → `#e0b48f` | -45 |

- 순수 함수 두 개를 둔다: `paletteScenePatch(p)` → `{ paletteId, frameColor, tileColor }`, `paletteStagePatch(p)` → `{ bgA, bgB, bgAngle }`. 화면과 시험이 같은 함수를 쓴다.

**B. 기본 배경 (`logo3dConfig.ts`, `page.tsx`)**
- `DEFAULT_LOGO3D_SCENE`의 색과 `DEFAULT_LOGO3D_STATE`의 `bgA`·`bgB`·`bgAngle`은 첫 팔레트에서 파생해 값이 두 곳에서 어긋나지 않게 한다(`bgMode`는 `'gradient'` 그대로). `DEFAULT_BG_ANGLE`이 「어드민 에셋과 같은 값」이라는 주석은 사실과 달라지므로, 3D 기본 각도는 첫 팔레트의 값을 쓰고 상수 이름·주석을 고친다. Shape 쪽 `INITIAL_STATE`는 바꾸지 않는다.
- `page.tsx` 초기 상태: `initialEngineMode === '3d'`이면 `cloneState(INITIAL_STATE)`에 `paletteStagePatch(PALETTES[0])`를 덧씌워 시작한다(그 밖의 모드는 지금과 같다). 덧씌우는 계산은 순수 함수(예: `initialStudioStateFor(mode, base)`)로 두고 시험한다.
- 「되돌리기」 옆 초기화(`handleReset`)도 같은 규칙을 따른다: 3D 모드에서 누르면 공유 배경이 스틸 · 하늘 배경으로, 그 밖의 모드에서는 지금처럼 `INITIAL_STATE`로 돌아간다.
- 모드 전환(`onChangeEngineMode`)은 배경을 바꾸지 않는다(사용자 결정).

**D. 팔레트가 공유 배경도 바꾼다 (`page.tsx`, `Logo3DSections.tsx`)**
- `page.tsx`에 팔레트 선택 처리기(예: `handleSelectLogo3dPalette(p)`)를 둔다. `remember(stateRef.current)`로 되돌리기 기록을 남긴 뒤 `setLogo3d`에 `paletteScenePatch(p)`, `setState`에 `paletteStagePatch(p)`를 적용한다(배경 방식 `bgMode`는 바꾸지 않는다). Shape의 `handleSelectGradientPreset`과 같은 모양이다.
- 패널에 넘기는 `logo3d` 묶음에 `onSelectPalette`를 더하고, `Logo3DColorSection`의 팔레트 버튼이 그것을 부른다.
- 직접 지정한 배경을 유지하는 표시(`bgTouched`)는 두지 않는다(사용자 결정, Shape 프리셋과 같은 동작). 틀·타일 색을 직접 바꿀 때의 `paletteId: ''` 동작은 그대로다.
- 프리셋 저장·불러오기(`logo3dEngineState.ts`)는 바꾸지 않는다. 배경은 이미 공유 상태로 저장된다.

### UI/UX 관점

- 사용자 노출 문구는 팔레트 이름 「스틸 · 그린」만 늘린다(`docs/service/writing/UX_WRITING_GUIDELINE.md`).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `PALETTES`가 위 표의 7종 값·순서와 일치한다(단위 테스트).
- `DEFAULT_LOGO3D_STATE`의 `bgA`=`#6ed3fe`, `bgB`=`#29a3f3`, `bgAngle`=`-45`, 타일=`#a9e0ff`이고, 틀·타일·배경이 첫 팔레트와 어긋나지 않는다(단위 테스트).
- `composeBackground('gradient', A, B, -45, w, h)`의 시작점이 좌상, 끝점이 우하 쪽이다(단위 테스트).
- `initialStudioStateFor('3d', INITIAL_STATE)`는 배경 세 값만 스틸 · 하늘 값으로 바꾸고 나머지는 그대로이며, `'shape'`·`'ribbon'`은 입력과 같다(단위 테스트).
- 3D 팔레트 버튼을 누르면 틀·타일과 공유 배경 `bgA`·`bgB`·`bgAngle`이 그 팔레트 값으로 바뀌고 `bgMode`는 그대로이며, 되돌리기로 이전 배경이 돌아온다(시험 또는 코드 확인).
- 모드 전환이 배경을 바꾸지 않는다(코드 확인).
- PRD §16이 갱신됐다.
- 기존 시험이 모두 통과하고 `scripts/verify.sh`(lint·typecheck·test)가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤, push 전)
- 메인 트리 `ADMIN_EMAILS` 개발 서버로 `/admin/assets?mode=3d`를 열어 확인한다. 확인 기준(스크린샷 픽셀, 대략값):
  - 배경: 좌상 ≈ `#6ed3fe`, 우하 ≈ `#29a3f3`
  - 타일이 배경보다 밝아 배경에 묻히지 않는다
  - 「그래파이트 · 라임」의 틀이 검정으로 죽지 않는다
- 7개 팔레트를 하나씩 눌러 틀·타일·배경이 어울리는지 보고, 「스틸 · 민트」 제안 배경이 어색하면 조정해 완료 기록에 최종값을 남긴다.
- `/admin/assets`(Shape)로 열면 배경이 Morning 그대로이고, 거기서 3D로 전환해도 배경이 바뀌지 않는지 확인한다.
