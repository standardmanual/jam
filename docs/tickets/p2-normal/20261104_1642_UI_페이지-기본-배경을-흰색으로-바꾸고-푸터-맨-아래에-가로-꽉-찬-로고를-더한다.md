# [UI] 서비스 페이지 기본 배경을 흰색(#FFF)으로 바꾸고, 푸터 맨 아래에 가로 100% 로고를 더한다

## 핵심 요약

- 요구사항(사용자 2026-11-04):
  1. 서비스의 가장 기본 배경색(`body`의 `--background`, 크림 `#f1f0eb`)은 **지금 그대로 둔다.**
  2. 서비스 화면에서 상단 내비(TopNav)부터 푸터까지의 **페이지 기본 배경을 `#FFF`로** 바꾼다.
  3. 푸터 맨 아래에 **로고 이미지를 가로 100%로 채워** 넣는다. 위치는 「© 2026 Standard Manual」 **아래**이고 둘 사이에 간격을 둔다. 로고는 **항상 페이지의 제일 아래**에 맞춰 놓인다(콘텐츠가 짧아도 화면 중간에 뜨지 않는다).
- 구현 계획: `lib/pageBackground.ts`에 `(main)` 화면용 흰 배경 값을 만들어 `(main)/layout.tsx`의 `main`에 쓰고, TopNav가 같은 흰 면으로 보이게 맞춘다. `Footer.tsx`의 저작권 줄 아래에 기존 로고 마크(`.jam-logo-mark`, 글자색 토큰으로 칠하는 마스크)를 가로 100%로 넣는다. 새 이미지 파일은 만들지 않는다.
- 관련 파일(경로 + 줄 위치는 2026-11-04 `staging` 기준):
  - `jam-web/src/lib/pageBackground.ts` — `PAGE_GRADIENT_BACKGROUND`(`background: 'var(--background)'`, `backgroundAttachment: 'fixed'`). `(main)`·`(legal)`·`(onboarding)` 레이아웃 셋이 함께 쓴다
  - `jam-web/src/app/(main)/layout.tsx` — 129줄 `<main style={PAGE_GRADIENT_BACKGROUND}>`(`pb-[calc(5rem+env(safe-area-inset-bottom))]`는 하단 탭 바 여백), 138~139줄 `{children}` 래퍼(`min-h-dvh`)와 `<Footer />`
  - `jam-web/src/components/ui/Footer.tsx` — `<footer className="relative z-10 flex flex-col items-start justify-center gap-6 py-6 px-4 bg-transparent">`, 저작권 줄은 맨 끝 `<span>`(`d.common.footerCopyright`)
  - `jam-web/src/components/ui/TopNav.tsx` — 26~32줄 주석: 헤더 배경은 DS TopNav가 불투명 `--background`로 칠하고, 바꿔야 하는 화면은 `headerStyle`을 넘긴다. 132줄 `.jam-logo-mark` 사용례
  - `jam-web/src/app/globals.css` — 481~495줄 `.jam-logo-mark`(`aspect-ratio: 2610 / 865`, `--foreground`색 마스크, `public/jam-logo-white.png`)
  - 시험: `jam-web/src/components/ui/__tests__/Footer.test.tsx`, `jam-web/src/components/ui/__tests__/TopNav.test.tsx`, `jam-web/src/app/(legal)/legal.test.tsx`(47~48줄이 `PAGE_GRADIENT_BACKGROUND` 값을 못 박고 있다), `jam-web/src/app/(main)/__tests__/layout.*.test.tsx`
  - 문서: `docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`(배경·푸터 설명이 있으면 갱신)

## 배경 / 문제 정의

현재는 모든 화면이 크림 `--background` 위에 있어 TopNav·본문·푸터가 한 면이다. 사용자는 페이지가 보이는 영역(상단 내비~푸터)만 흰색으로 하고, 서비스 바탕색(`body`, 하단 탭 바 뒤·화면 밖)은 크림으로 남기려 한다. 푸터는 2026-09-09(티켓 20260909_2319)에 로고 이미지를 걷고 저작권 텍스트만 남겼는데, 이번에 저작권 아래로 로고가 다시 들어온다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **배경**
  - `body { background: var(--background) }`와 `--background` 토큰 값은 바꾸지 않는다(어드민 `[data-admin-theme]`도 그대로).
  - `(main)` 레이아웃의 페이지 면(`main`)을 `#FFF`로 한다. 값은 색을 새로 만들지 않고 흰색 토큰이 있으면 그것을 쓰고, 없으면 `lib/pageBackground.ts`에 이름 붙은 상수 한 곳에만 둔다.
  - **TopNav가 본문과 같은 흰 면으로 보여야 한다.** DS TopNav는 `--background`로 칠하므로, `headerStyle` 같은 기존 확장점으로 흰색을 넘기는 방식을 먼저 검토한다. DS 컴포넌트 자체를 고쳐야 하면 채원 판정에서 승인 항목(`needsApproval`)으로 올린다.
  - **적용 범위 기본값(가정)**: TopNav와 푸터가 있는 `(main)` 화면만 바꾼다. `(legal)`(개인정보·약관·확률)과 `(onboarding)`은 TopNav·푸터가 없는 별도 화면이라 이번에 바꾸지 않는다. 그래서 공용 상수 `PAGE_GRADIENT_BACKGROUND`는 두 레이아웃을 위해 그대로 두고, `(main)`용 값을 따로 둔다. 채원이 다른 범위가 맞다고 판정하면 따른다.
  - 화면이 스스로 칠하는 풀블리드 배경(원색·이미지·배지 상세의 고정 배경 레이어)은 건드리지 않는다. `/drops` 같은 풀스크린 지도 화면도 영향이 없어야 한다.
  - 회색 면(`#e9e7e0`, `bg-surface` 등)이 흰 바탕 위에서 구분되는지 눈으로 확인한다.
- **푸터 로고**
  - 로고는 기존 `.jam-logo-mark`(글자색 토큰 `--foreground`로 칠하는 마스크)를 쓴다. 새 이미지 파일·새 색을 만들지 않는다. 장식이므로 접근성 이름은 `role="img"`와 `aria-label="JAM!"` 또는 `aria-hidden`으로 정한다(TopNav 쓰임새와 같게).
  - 가로 100%: 푸터 좌우 여백(`px-4`)을 뚫고 페이지 폭(최대 430px) 끝까지 채운다. 높이는 `aspect-ratio`(2610:865)로 정해진다.
  - 위치: 저작권 줄 **아래**, 푸터의 가장 마지막 요소. 저작권과 로고 사이는 푸터의 기존 줄 간격(`gap-6`)과 같은 간격을 기본으로 한다.
  - **항상 페이지 맨 아래**: 푸터가 문서 흐름의 마지막이고 `main`이 하단 탭 바용 여백(`pb-[calc(5rem+env(safe-area-inset-bottom))]`)을 둔다. 로고가 탭 바에 가리지 않으면서 콘텐츠가 짧아도 스크롤 끝(화면 맨 아래)에 붙도록, 여백을 푸터 아래가 아니라 **로고가 탭 바 위에 놓이도록** 정리하는 방법을 채원이 정한다. 로고 아래에 흰 여백이 길게 남지 않아야 한다.
  - 푸터가 숨겨지는 경로(`/drops`, `/philosophy`)는 그대로 숨긴다.
- 주석 정리: `Footer.tsx`의 「로고 이미지 제거, 저작권 텍스트만」 주석과 `bg-transparent` 설명, `pageBackground.ts` 상단 설명을 새 동작에 맞게 고친다. 낡은 설명을 남기지 않는다.

### UI/UX 관점

- 새 문구는 없다(저작권 문구 그대로). 새 컴포넌트·토큰이 필요하면 채원 판정에서 `needs_approval`로 올린다.
- 확인 화면: 홈, 배지 상세(고정 배경 레이어가 있다), 컬렉션, 프로필, 짧은 화면(콘텐츠가 적은 화면)과 긴 화면 모두에서 푸터 로고가 맨 아래에 있는지.

### 컨텐츠 관점

- 해당 없음.

## 구현 계획 (파일 단위, 채원 사전 판정 반영 — 2026-11-04)

> 첫 실행에서 아현이 「바뀌는 파일 7개(임계값 5개 초과)」로 `plan_only`를 반환했다. 규모 사전 판정이 파일 수를 놓친 것이다(「관련 파일」에 시험 3개를 세지 않았다). 변경은 한 가지 동작에 속하고 합쳐서 약 70~90줄이라 쪼개지 않고, 사용자가 「한 번에 진행」으로 승인했다.

1. `jam-web/src/lib/pageBackground.ts`: `MAIN_PAGE_BACKGROUND = { background: 'var(--surface)' }`를 추가한다(`--surface`는 `design-system/tokens/colors.css`의 `#ffffff`, 새 토큰 없음). 상단 설명을 새 동작에 맞게 고친다. `PAGE_GRADIENT_BACKGROUND`는 `(legal)`·`(onboarding)`용으로 그대로 둔다.
2. `jam-web/src/app/(main)/layout.tsx`(16줄 import, 128~129줄 `main`): `main`의 style을 `MAIN_PAGE_BACKGROUND`로 바꾼다. `pb-[calc(5rem+env(safe-area-inset-bottom))]`를 `main`에서 빼서 바깥 래퍼(`div.min-h-dvh`)로 옮긴다. 그러면 흰 면(`main`)은 로고에서 끝나고, 그 아래 탭 바 여백은 `body` 크림이 비친다. 문서 스크롤 길이가 어색하면 `main` 뒤에 같은 높이(`calc(5rem+env(safe-area-inset-bottom))`)의 빈 `div`를 두는 방식으로 바꾼다.
3. `jam-web/src/components/ui/Footer.tsx`(94줄 근처 맨 끝): 저작권 줄 다음에 `<div className="jam-logo-mark -mx-4 w-[calc(100%+2rem)]" role="img" aria-label="JAM!" />`를 더한다(푸터 `px-4`를 뚫어 열 끝까지, 간격은 기존 `gap-6`). 「로고 이미지 제거」·`bg-transparent` 주석을 새 동작에 맞게 고친다. `items-center`는 건드리지 않는다.

5. `jam-web/src/components/ui/__tests__/Footer.test.tsx`: 「저작권 줄 다음에 로고가 푸터의 마지막 요소」 시험을 더한다. `/drops`·`/philosophy` 숨김 시험은 유지한다.
6. `jam-web/src/components/ui/__tests__/TopNav.test.tsx`: 「기본 헤더 배경 `var(--surface)`, `headerStyle`의 `background`가 우선」 시험을 더한다.
7. `jam-web/src/app/(main)/__tests__/layout.chapter.test.tsx` 또는 `layout.tribe-gate.test.tsx` 중 한 곳: `main`의 배경값이 `MAIN_PAGE_BACKGROUND`인지 확인한다.

- 로고의 `-mx-4` 때문에 가로 스크롤이 생기지 않는지 확인한다(`main`이 `overflow-y-auto`).
- `(legal)`의 `legal.test.tsx` 47~48줄은 그대로 통과해야 한다.

- 적용 범위는 `(main)` 화면만이다(가정, 사용자에게 알림). `(onboarding)` 레이아웃도 `Footer`를 쓰므로 푸터 로고가 크림 바탕 위에 나타난다.
- 사용자 지적(2026-11-04): 「서비스 영역은 화이트」. 처음 구현은 탭 바 구간(래퍼 하단 여백)에 body 크림이 비치게 했는데, 사용자 의도는 서비스 열 전체가 흰색이므로 바깥 래퍼에도 같은 배경을 걸었다. 로고가 흰 면 맨 아래에 붙도록 푸터 아래쪽 패딩도 0으로 줄였다.
- 머지 전 오염 검사에서 다른 세션의 홈 캡슐 커밋 두 개 때문에 브랜치가 최신 staging을 포함하지 않았다. 변경 파일이 겹치지 않아 임시 워크트리에서 리베이스하고 `-r2` 브랜치로 CI를 돌려 머지했다.
