# [UI] 아이템 배지 일련번호(ItemSerialCode)의 배경을 메탈 플레이트 질감으로 바꾸고 글자를 검정으로 바꾼다

## 핵심 요약

- 요구사항: 아이템 배지 상세화면의 일련번호(`ItemSerialCode`) 배경을 어두운 인장 면에서 **첨부 이미지의 브러시드 메탈 플레이트 질감**으로 바꾼다. 숫자 릴(회전) 모션은 그대로 두고, 알파벳·숫자 글자색은 검정으로 바꾼다.
- 구현 계획: 플레이트 질감 이미지 한 장(`jam-web/public/images/item-serial-plate.jpg`)을 쓰고, 타일 5장(알파벳 4 + 숫자 1)이 **하나의 연속된 플레이트를 나눠 비추도록** 타일마다 `background-position`을 어긋나게 준다. 타일의 티켓 모양(`clipPath`)과 릴 구조는 건드리지 않는다.
- 관련 파일:
  - `jam-web/design-system/components/patterns/ItemSerialCode.jsx` — `TileShell`(230행 부근, 배경 `background`), `Tile`(253행, 글자색 `var(--snow)`), `ReelColumn`(87행, 숫자 글자색 `var(--snow)`), `ItemSerialCode`(286행, 전체 폭 계산)
  - `jam-web/design-system/components/patterns/ItemSerialCode.prompt.md`, `ItemSerialCode.stories.tsx`, `ItemSerialCode.d.ts`(필요 시)
  - `jam-web/src/components/__tests__/dsLiteralColors.test.ts` — `ALLOWED_LITERAL`의 ItemSerialCode 항목 2개(56~67행)가 옛 인장 면 전용이라 새 구성에 맞게 갱신
  - `jam-web/public/images/item-serial-plate.jpg` — 신규 자산(아래 「자산」 참고)
  - 사용처(모두 같은 컴포넌트를 쓰므로 함께 바뀐다): `src/app/(main)/badges/[id]/page.tsx`(height 50), `drops/BadgeDetailSheet.tsx`(height 40), `inventory/[itemId]/LockedItemDetail.tsx`, `components/inventory/ItemCandidateRow.tsx`, `badges/[id]/ItemEarnHistory.tsx`, `dev-sample/item-badge-serial/page.tsx`

## 배경 / 문제 정의

현재 일련번호는 어두운 회색 그라디언트 위에 흰 글자를 올린 "각인된 태그" 모양이다(`TileShell`: `--base-neutral-600→800` + 흰 하이라이트 19%). 사용자가 이를 금속 명판(메탈 플레이트)처럼 보이게 하고 글자는 검정으로 바꾸기를 요청했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 새 질감은 이미지 한 장으로 처리한다. 자산은 이 티켓을 만든 세션이 첨부 이미지(828×274)에서 나사·테두리·배경 육각 패턴을 뺀 **플레이트 중앙부 610×170을 잘라** `item-serial-plate.jpg`(약 7.7KB)로 만들어 두었다. 파일 원본 위치: `/private/tmp/claude-502/-Volumes---------JAM-/66d23038-0f10-49f8-85e5-ff31b2ce118d/scratchpad/item-serial-plate.jpg`. 아현은 이 파일을 `jam-web/public/images/item-serial-plate.jpg`로 복사해 커밋한다(메인 트리에는 미커밋 상태가 없다).
- 이미지는 `url('/images/item-serial-plate.jpg')`로 참조한다(서비스·Storybook `staticDirs: '../public'` 모두 같은 경로로 열린다).
- 연속 플레이트: `ItemSerialCode`가 전체 폭(`totalWidth` = 알파벳 4장 폭 + 간격 + 숫자 박스 폭)을 계산해 각 `TileShell`에 `plate={{ totalWidth, offsetX }}`를 넘기고, `TileShell`은 `backgroundImage: url(...)`, `backgroundSize: ${totalWidth}px ${height}px`, `backgroundPosition: ${-offsetX}px 0`으로 그린다. `offsetX`는 왼쪽부터 각 타일의 시작 x(알파벳 i번째 = i×(tileWidth+gap), 숫자 박스 = 4×(tileWidth+gap))다.
- 글자색: `Tile`·`ReelColumn`의 `var(--snow)`를 **검정 토큰**으로 바꾼다. 리터럴 `#000`은 쓰지 않는다. 플레이트는 테마에 따라 바뀌지 않는 재질이므로 테마 반전 토큰 대신 팔레트 검정(`--base-neutral-900` 등, `design-system/tokens/colors.css` 확인)을 쓰고, `dsLiteralColors.test.ts`의 허용 목록에 이유와 함께 등록한다.
- 이미지 위에 글자가 놓이므로 이미지 밝기 범위(실측 휘도 120~208, 평균 168)에서 검정 글자의 대비가 4.5:1 이상인지 확인한다.
- 옛 `radial-gradient`·`--base-neutral-600/800` 그라디언트는 제거하고, `dsLiteralColors.test.ts`의 옛 허용 항목 2개도 지운다(남기면 죽은 예외가 된다).

### UI/UX 관점
- **회전(릴) 모션은 그대로 유지한다.** `DigitReelGroup`·`ReelColumn`·`t-reel*` CSS·SVG 블러 필터·`animate`·모션 축소 분기·`aria-hidden`/`sr-only` 구조는 글자색 한 줄 외에 건드리지 않는다.
- 티켓 모양(둥근 모서리 + 양옆 반원 노치) `tilePath`는 그대로 둔다. 타일 사이 간격(`GAP_RATIO`)도 그대로 둔다.
- 크기는 `height` 하나로 비례한다는 규칙을 지킨다(플레이트 배치도 `height`·`totalWidth`에서 계산한다).
- 모든 사용처(상세 height 50, 드랍 시트 height 40, 잠긴 상세, 후보 행, 획득 이력, dev-sample)가 같은 컴포넌트를 쓰므로 함께 바뀐다. 상세화면에서만 바꾸는 변형(prop)은 만들지 않는다 — `prompt.md`가 "낱장으로 분리해 재조합하지 않는다"고 못박은 한 덩어리 패턴이고, 한 화면에서만 질감이 다르면 일관성이 깨진다.

### 컨텐츠 관점
- 해당 없음.

## 구현 계획

1. 자산 복사: 위 원본을 `jam-web/public/images/item-serial-plate.jpg`로 복사.
2. `ItemSerialCode.jsx`: 상수 추가(`PLATE_SRC = '/images/item-serial-plate.jpg'`), `TileShell`에 `plate` prop, `Tile`·`DigitTile`이 `plate`를 전달, `ItemSerialCode`에서 `totalWidth`·`offsetX` 계산. 글자색 두 곳 교체. 파일 머리 주석(「각인된 태그」·인장 면 설명)을 새 질감에 맞게 정리.
3. `dsLiteralColors.test.ts`: 옛 허용 항목 삭제, 검정 토큰 직접 참조 허용 항목 추가(해당 시). 기존 테스트 `expect(serial).toMatch(/--base-neutral-600/)`(137~139행)가 옛 토큰을 단정하므로 새 구성에 맞게 고친다.
4. `ItemSerialCode.prompt.md`·`.stories.tsx`: 설명과 Story를 새 모습에 맞게 갱신(Story는 MODULAR을 고쳤을 때 필수).
5. `scripts/verify.sh`(lint·typecheck·test·ds:check·slop) 통과 확인. `jam-ds` 동기화 점검 항목이 있으면 `_ds_manifest.json`·`readme.md` 문구도 확인한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `ItemSerialCode`의 알파벳 타일 4장과 숫자 타일 배경이 어두운 그라디언트가 아니라 `/images/item-serial-plate.jpg` 이미지이고, 5장이 이어 붙인 하나의 플레이트처럼 질감 결이 연속된다(`backgroundSize`가 전체 폭, `backgroundPosition`이 타일 시작 x의 음수).
- 알파벳·숫자 글자색이 검정 토큰이고, 코드에 리터럴 흰색·검정 값이 새로 생기지 않는다(`dsLiteralColors.test.ts` 통과).
- 숫자 릴 모션이 그대로다: `ReelColumn`·`DigitReelGroup`·`t-reel*`·SVG 블러 필터 코드에 글자색 외 변경이 없고, `animate={false}`·모션 축소에서는 최종 값만 즉시 그려진다.
- 접근성 구조가 그대로다: 릴은 `aria-hidden="true"`, 숫자 타일 안에 실제 숫자가 담긴 `sr-only` 텍스트가 있다.
- `height` 40·50에서 글자가 잘리거나 타일 밖으로 나가지 않는다(Story 또는 dev-sample 실렌더 확인).
- Story와 `prompt.md`가 새 모습에 맞게 갱신되고, `scripts/verify.sh`가 통과한다.
- 신규 자산 `jam-web/public/images/item-serial-plate.jpg`가 커밋에 포함된다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬에서 `/dev-sample/item-badge-serial`과 배지 상세(`/badges/[id]`)를 열어 질감·대비·릴 모션을 실렌더로 확인하고 결과를 사용자에게 보여 준다.

### 주요 의사결정 / 핵심 메모
- 경로: 가벼운 UI(`route: 'light'`). 고칠 내용이 이 티켓에 확정돼 있고 로직 변경이 없다.
- 질감은 첨부 이미지의 플레이트 중앙부(나사·테두리 제외)만 썼다. 나사와 육각 배경은 쓰지 않았다.
- 글자 검정은 티켓의 「--base-neutral-900 등」 중 950을 골랐다. 900은 플레이트 최악 픽셀 대비가 4.06:1, 950은 4.48:1이다.
- 머지 시점에 `origin/staging`이 앞서 있었으나(푸터 로고 커밋 1개, 겹치는 파일 없음) review 브랜치 고유 커밋은 1개뿐이라 오염이 아님을 확인하고 cherry-pick으로 이어 붙였다.

### 잔여 이슈
- 대비 4.48:1 한 줄기는 이미지 자체의 가장 어두운 결이다. 더 어두운 글자 토큰은 없으므로(950이 최댓값) 그대로 둔다.
