# [Feature] 미션 카피의 역할을 나누고 달성 조건을 지표 라벨 불릿으로 바꾼다 (상위)

## 핵심 요약

- 요구사항: 미션의 대표 이미지·홈피드 카드·미션명·설명·달성 조건 섹션이 같은 조건을 저마다 다른 양식으로 반복한다. 역할을 나누고, 달성 조건은 `admin/badge-metric-labels`의 라벨·단위로 만든 짧은 불릿으로 통일한다.
- 구현 계획: 회차 3개로 나눈다(아래 「구현 계획」). 1회차는 화면과 문구 규칙, 2회차는 «동기화 횟수» 판정 키, 3회차는 기존 미션 6개와 홈피드 카드 문구 교체다.
- 관련 파일: 회차별 티켓에 지도를 적는다.

## 배경 / 문제 정의

미션 「드랍하고, 픽업하고, 이어가기」(`e66f802f-…`)로 본 현재 상태:

| 자리 | 지금 문구 | 문제 |
|---|---|---|
| 대표 이미지 | 놓고, 줍고, 나누기 / 드랍 1·픽업 1 | 조건 수량을 이미지에 다시 적는다 |
| 홈피드 | 놓고 줍고. 드랍 한번, 픽업 한번 | 표기가 이미지·상세와 또 다르다 |
| 미션명 | 드랍하고, 픽업하고, 이어가기 | (유지) |
| 설명 | 아이템 배지를 한 번 드랍하고 한 번 픽업한 뒤 동기화하면 10포인트를 획득해요. | 조건과 보상을 한 문장에 풀어 쓴다. 재미가 안 보인다 |
| 달성 조건 | 긴 문장 한 줄(DB `condition_text`) + 「참가한 뒤 조건을 달성하면 미션이 자동으로 끝나요」 | 설명과 같은 내용 반복. 끝 문구는 당연한 말 |

미션 6개 모두 `condition_text`를 손으로 쓴 상태라 쓴 사람마다 표현이 달라진다. `badge_metric_labels`는 53개 지표가 있지만 이 미션이 쓰는 `drop_item_count`·`pickup_item_count`는 없다.

## 상세 요구사항

### 역할 분담 (사용자 결정 2026-11-04)

| 자리 | 역할 | 규칙 |
|---|---|---|
| 미션명 | 마케팅 감각으로 미션의 느낌을 살린다 | 지금처럼 유지. 조건 요약 금지(기존 규칙) |
| 설명 | 이 미션이 주는 재미를, 유저 입장의 상황으로 쓴다 | **보상은 쓰지 않는다.** 조건 수량·단위도 반복하지 않는다 |
| 달성 조건 | 조건만 간결하게 | 지표 라벨·단위로 만든 불릿. 긴 문장 금지. «달성하면 미션이 끝난다» 같은 당연한 문구 삭제 |
| 대표 이미지·홈피드 | 조건 수량을 다시 적지 않는다 | 3회차에서 문구 규칙 정리 |

### 달성 조건 표기 (사용자 결정 2026-11-04)

- **불릿은 조건 데이터와 지표 라벨로 화면이 자동 생성한다.** 문장을 손으로 쓰지 않는다. `condition_text`는 예외 때문에 덮어쓸 때만 쓴다.
- 예시(이 미션):
  - 아이템 배지 드랍 1회
  - 아이템 배지 픽업 1회
  - 동기화 1회
- 라벨이 없는 지표는 `admin/badge-metric-labels`에 추가한다(1회차 SQL 시드).
- **«동기화 1회»를 조건 데이터에 추가한다**(사용자 선택). 판정 로직 변경이라 2회차로 분리한다.

## 구현 계획

| 회차 | 유형 | 범위 | 선행 |
|---|---|---|---|
| 1 (완료, 20261104_2148) | ui + copy + content | 상세 달성 조건 카드가 조건 데이터 + 지표 라벨로 불릿 생성, 「자동으로 끝나요」 문구 삭제, 라벨 시드 SQL(`drop_item_count`·`pickup_item_count` 등 현재 미션 키), 설명·조건 역할 규칙을 UX 라이팅 가이드·등록 검사(`registerChecks/copyRules.ts`)·윤진 지침에 반영 | 없음 |
| 2 (완료, 20261104_2234) | engine | 미션 전용 키 «참가한 뒤 동기화 횟수» 추가: 읽기 함수·`dbMetrics.ts` 읽기 표·판정·시험·어드민 폼·라벨. 동기화 기록의 원천 테이블을 먼저 확인한다(`daily_sync_count`는 배지 전용·외부 평가라 그대로 쓸 수 없다) | 1회차 |
| 3 (3-A·3-C 완료, 이미지 교체만 남음, 20261104_2314) | content | 기존 미션 6개의 설명·`condition_json` 갱신(DB), 홈피드 카드·대표 이미지 문구 규칙(HOME_FEED 묶음 문서) | 2회차 |

## 완료 조건

1~3회차 티켓이 모두 CLOSED이고, 「드랍하고, 픽업하고, 이어가기」 상세 화면의 달성 조건이 라벨 불릿 세 줄이며 홈피드·이미지·설명에 같은 수량 문구가 반복되지 않는다.

## 주요 의사결정

- 2026-11-04 사용자: 불릿은 지표 라벨로 자동 생성한다(문장 직접 작성 안 함).
- 2026-11-04 사용자: «동기화 1회»를 조건 데이터에 추가한다(표시만 하는 안과 불릿 두 줄로 끝내는 안은 채택하지 않음).
- 조사 사실(2026-11-04 확인): 운영 DB 미션 6개 전부 `condition_text` 보유. `badge_metric_labels` 53행에 드랍·픽업·동기화 키 없음. `engine_condition` 미션은 4개.
- 2026-11-04 1회차 완료(티켓 `20261104_2148`): 드랍·픽업 미션의 달성 조건이 라벨 불릿 두 줄로 바뀌었고, 미션 설명의 보상 표현은 등록 검사가 거절한다. 시드 316(드랍·픽업 라벨)을 운영 DB에 적용했다. 후속 정리는 `20261104_2227`(P3). 남은 일: 2회차(동기화 1회 키), 3회차(기존 미션 6개와 홈피드 카드).
- 2026-11-04 2회차 완료(티켓 `20261104_2234`): 동기화 기록 표 `user_sync_events`와 미션 전용 키 `sync_count`를 더했고(317 운영 DB 적용), 불릿 생성기가 미션 전용 키를 뒤에 붙인다. 남은 일: 3회차에서 「드랍하고, 픽업하고, 이어가기」의 `condition_json`에 `sync_count: 1`을 넣어 `동기화 1회` 불릿을 보이게 하고, 나머지 미션 5개·홈피드 카드·어드민 «달성 조건 문장» 도움말을 정리한다.
- 2026-11-04 3회차 거의 완료(티켓 `20261104_2314`, 3-A `20261104_2321`): 나머지 미션 5개의 불릿 확장, 문구 확정·적용, 규칙 문서 반영을 마쳤다. 남은 일은 대표 이미지 문구 교체(사용자 승인 대기)뿐이다.
