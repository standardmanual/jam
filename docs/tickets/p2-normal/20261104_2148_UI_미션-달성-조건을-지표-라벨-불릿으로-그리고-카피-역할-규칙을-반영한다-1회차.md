# [UI] 미션 달성 조건을 지표 라벨 불릿으로 그리고 카피 역할 규칙을 반영한다 (1회차)

## 핵심 요약

- 요구사항: 미션 상세의 달성 조건 카드가 조건 데이터와 `badge_metric_labels`로 불릿을 자동 생성하고, 「참가한 뒤 조건을 달성하면 미션이 자동으로 끝나요」 줄을 없앤다. 미션 설명에서 보상을 빼는 규칙을 문서·등록 검사·윤진 지침에 반영한다. 상위 티켓 `20261104_2146`의 1회차다.
- 구현 계획: 아래 「구현 계획」 표. 파일이 5개를 넘으므로 첫 호출부터 `planOnlyWaiver`를 넣는다(구현 착수 전에 파일 지도가 파일·함수 단위로 적혀 있다).
- 관련 파일: 「구현 계획」 참조.

## 배경 / 문제 정의

상위 티켓 `20261104_2146`의 배경과 같다. 요약: 달성 조건이 설명과 같은 내용을 긴 문장으로 되풀이하고, 당연한 안내 문구가 붙어 있으며, 쓴 사람마다 표현이 다르다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. **불릿 생성 함수**(순수 함수)를 새로 만든다. 입력은 `mission_type`·`condition_json`·지표 라벨 맵(`getMetricLabels`가 돌려주는 `Map<metric_key, {label, unit}>`)이고, 출력은 불릿 문자열 배열이다. 생성하지 못하면 `null`을 돌려준다.
   - 형식: `{라벨} {값}{단위}`(예: `아이템 배지 드랍 1회`). 값이 정수면 소수점 없이, 소수면 그대로(`0.5km`).
   - **범위는 `engine_condition` 미션의 숫자 조건 키다.** `distance`·`activity_count` 등 옛 유형과, 값이 숫자가 아닌 키(`checkin_category_count` 같은 객체, `activity_type`)는 이번 회차에서 생성하지 않는다. 한 키라도 생성하지 못하면(라벨 없음·값 모양 다름) **불릿 전체를 `null`로 돌려 기존 표시로 되돌린다**(일부만 그리면 조건이 빠져 보인다).
   - 키 순서는 조건 레지스트리 선언 순서(`formatConditionDetailEntries`가 쓰는 `CONDITION_FIELDS` 순서)를 따른다.
   - 라벨 문구 우선순위: `badge_metric_labels`의 `label_ko`·`unit_ko`. 단위가 없으면 값만 붙인다.
2. **상세 페이지 서버**가 `getMetricLabels`로 라벨을 읽어 불릿을 만들고 클라이언트에 `conditionBullets: string[] | null`로 넘긴다. 클라이언트에서 DB를 읽지 않는다. 라벨 조회에 실패하면(빈 맵) `null`이 되어 기존 표시로 간다.
3. **우선순위**: 불릿(`conditionBullets`)이 있으면 그것만 보인다. 없으면 `condition_text`, 그것도 없으면 지금의 `{goal.label} {n}{unit} 달성` 줄이다. (기존 미션 6개의 `condition_text`는 3회차에서 정리하므로 이번 회차에서 지우지 않는다. 불릿이 우선이라 드랍·픽업 미션은 바로 바뀐다.)
4. **라벨 시드 SQL**(되돌림 SQL 포함, 번호는 `origin/staging`의 마이그레이션 최대 번호 다음 — 지금 315, push 직전 재확인)로 `badge_metric_labels`에 현재 미션이 쓰는 키를 추가한다: `drop_item_count`=`아이템 배지 드랍`/`회`, `pickup_item_count`=`아이템 배지 픽업`/`회`. 이미 있는 키의 라벨은 바꾸지 않는다(배지 진행 화면도 같은 표를 읽는다). 실행은 4단계에서 카리나가 한다.
5. **등록 검사**(`jam-web/src/lib/admin/registerChecks/copyRules.ts`): 미션 설명에서 보상을 말하면 거절하는 규칙을 더한다. 카드(`card.`)와 미션(`mission.`)은 같은 `COPY_RULES`를 쓰므로 규칙에 적용 대상(미션만)을 가릴 수 있는 칸을 더한다. 카드 설명은 3회차 전까지 지금 규칙 그대로다.
   - 걸리는 모양: `숫자 + 포인트·잼`(`10포인트`, `100잼`), 「보상」.
   - 안내: `미션 설명에는 보상을 쓰지 않아요. 보상은 화면에 따로 보여 줘요. 미션이 주는 재미를 유저 입장의 장면으로 써 주세요.`
   - 같은 파일 `noun-ending` 규칙의 안내 예시 「10포인트를 획득해요」는 새 규칙과 어긋나므로 「아이템 배지를 획득해요」로 바꾼다.
6. 기존 시험·고정 값 중 위 규칙에 걸리는 미션 설명(예: 「10포인트를 획득해요」를 쓰는 등록 검사 시험)은 규칙 취지에 맞게 고친다. 규칙 때문에 시험을 약하게 만들지 않는다.

### UI/UX 관점

- 달성 조건 카드(`MissionDetailClient.tsx` 525~543줄 부근): 불릿 행은 기존 `ConditionRow tone="primary"`를 그대로 쓴다. 불릿마다 한 줄(짧은 문구)이다. `조건 활동 종류`(`condition.activity_type`) 줄과 회색 보조 문구 줄은 불릿이 있을 때 **보조 문구 줄을 삭제**한다. 보조 문구 줄은 불릿이 없는 폴백 경로에서도 삭제한다(당연한 문구이므로 어느 경로에서도 보이지 않는다).
- 문구 상수 `d.missions.conditionAutoCompleteHint`(`jam-web/src/lib/i18n/ko.ts` 906줄 부근)를 삭제한다. 시험 `MissionDetailClient.test.tsx`(29·69줄 부근)의 해당 기대도 삭제하고, 불릿 표시·폴백 표시를 검증하는 시험을 더한다.
- 새 컴포넌트·토큰은 만들지 않는다(기존 `ConditionRow` 재사용).
- 병렬 세션(티켓 20261104_2210)이 `MissionDetailClient.tsx`·`ko.ts`를 같은 시기에 고치고 있다. **이 회차는 `origin/staging`에서 분기한 격리 워크트리에서만 작업**하고, 머지 때 충돌 여부를 확인한다.

### 컨텐츠 관점

- 문구 상수는 이 회차에서 삭제만 한다. 새 문구는 라벨 시드 두 개뿐이다(위 4).
- UX 라이팅 가이드 §2.6 근처에 미션 문구 역할 분담을 적는다: 제목=느낌(조건 요약 금지), 설명=유저 입장의 재미(보상·조건 수량 금지), 달성 조건=지표 라벨 불릿. 106행의 「미션 상세 달성 조건 카드의 안내 문구 … 「달성」 예외」 문장은 문구를 없애므로 삭제하고 사유(2026-11-04, 이 티켓)를 한 줄 남긴다. 344행의 기계 규칙 목록에 새 규칙을 더한다.
- `.claude/agents/jam-marketer.md`: 미션 설명은 보상·조건 수량을 쓰지 않고 유저 입장의 재미를 쓴다는 규칙을 더하고, 「Examples now live」의 「아이템 배지를 한 번 드랍하고 한 번 픽업한 뒤 동기화하면 10포인트를 획득해요.」를 미션 설명 예시에서 뺀다(홈피드 카드 설명 규칙은 3회차에서 정리하므로 카드 쪽 문장은 건드리지 않는다).
- `docs/service/prd/asset-generator/MISSION_REGISTRATION_BUNDLE.md` 108행(`description` 필드 규칙)에 새 거절 규칙을 더하고 129행(`condition_text`는 비워 둔다)에 「달성 조건은 화면이 지표 라벨로 만들고 `condition_text`는 예외 덮어쓰기용」임을 적는다.

## 완료 조건

- 「드랍하고, 픽업하고, 이어가기」 상세의 달성 조건 카드에 `아이템 배지 드랍 1회`·`아이템 배지 픽업 1회` 두 줄이 보이고 「참가한 뒤 조건을 달성하면 미션이 자동으로 끝나요」는 없다(시험 + 로컬 실렌더 확인).
- 라벨이 없는 키가 섞인 `engine_condition` 미션과 옛 유형 미션은 기존 표시(`condition_text` 또는 `{goal.label} … 달성`)로 그려진다(시험).
- 어느 경로에서도 보조 문구 줄이 없고 `conditionAutoCompleteHint` 상수가 코드에 남아 있지 않다.
- 미션 설명에 `10포인트`·`보상`이 들어가면 등록 검사가 거절하고, 카드 설명은 영향받지 않는다(시험).
- 마이그레이션 두 파일이 있고 되돌림 SQL이 맞으며, 실행 뒤 `badge_metric_labels`에 두 행이 있다.
- 문서 3개가 갱신됐고 `scripts/verify.sh`가 통과한다.

## 주요 의사결정

- 2026-11-04: 불릿은 `engine_condition`의 숫자 키만 만들고 모자라면 통째로 기존 표시로 돌린다. 이유: 일부만 그리면 조건이 빠져 보이고, 나머지 미션 5개는 3회차에서 라벨·조건을 함께 정리한다.
- 2026-11-04: 이미 있는 라벨(`repeat_count`=「충족 횟수」 등)은 이 회차에서 고치지 않는다. 배지 진행 화면이 같은 표를 읽고, 「충족」은 가이드 금지어이므로 3회차에서 별도로 정한다.
- 이번 회차에서 불릿에 「동기화 1회」는 나오지 않는다(2회차에서 조건 키를 더한 뒤 나온다).
