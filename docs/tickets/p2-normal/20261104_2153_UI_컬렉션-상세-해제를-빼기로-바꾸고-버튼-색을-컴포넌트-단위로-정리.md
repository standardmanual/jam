# [UI] 컬렉션 상세의 «해제»를 «빼기»로 바꾸고, 빼기 버튼 색을 컴포넌트 단위로 정리한다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-04, «컴포넌트 근원적 접근 필요함»):
  1. 칸별 «해제» 버튼: 색을 **그레이**로, 라벨을 **«빼기»**로.
  2. 격자 아래 «모두 해제하기» 버튼: 색을 **블랙**(지금 칸별 해제 버튼이 쓰는 검정)으로, 라벨을 **«모두 빼기»**로.
  3. «해제 → 빼기»를 UX Writing 가이드 용어 규칙에 반영한다. **적용 범위는 «컬렉션 문구 전체 통일»로 사용자가 정했다(2026-11-04)**: 시트 제목·본문·토스트·오류·안내 문구와 서버가 내려보내는 문장까지 장착의 반대 뜻 «해제»를 모두 «빼기»로 바꾼다. 이용 정지 해제·Strava 권한 해제 같은 다른 뜻의 «해제»는 그대로 둔다.
  4. 컬렉션 등급 안내(`tierFixedHint`)에서 «Rare 등급으로 모으고 있어요.» 다음에 줄바꿈을 넣는다.
- 구현 계획: 아래 「구현 계획」(파일 단위).
- 관련 파일: 아래 「구현 계획」 파일 표.

## 배경 / 문제 정의

- 칸별 장착 취소 버튼은 `SlotGrid.tsx` 안에서 `bg-[var(--background-inverse)] text-[var(--snow)]`를 손으로 적은 알약이다. 같은 격자의 «교체»·«추가»도 같은 모양의 알약을 색 클래스만 바꿔 세 번 반복한다(`SlotGrid.tsx` 약 499~535줄). 색이 컴포넌트가 아니라 호출부 클래스에 흩어져 있어, 이번처럼 색을 바꿀 때 세 곳을 따로 고쳐야 한다.
- «모두 해제하기»는 `Button variant="outline"`에 `bg-surface!`를 덮어 쓴 절충이다(`SlotGrid.tsx` 약 546줄). 블랙은 `Button`의 `primary`(`surface="main"`)가 이미 가진 면이라 덮어쓰기 없이 변형 선택만으로 얻을 수 있다.
- 칸별 «해제» 라벨은 UX Writing 가이드 §1.3에서 «해제(UNEQUIP), X: 빼기»로 고정돼 있어, 용어 규칙부터 바꿔야 한다.

## 상세 요구사항

### UI/UX 관점 (채원 사전 판정 대상)
- **칸별 빼기 버튼**: 그레이 면. 후보 토큰은 `--default` 면 + `--foreground` 글자(`Button`의 `secondary`와 같은 쌍). 판정은 채원이 한다. 칸의 «교체»·«추가»(accent)와 «빼기»(그레이)가 **같은 알약 컴포넌트의 색 의도(tone)만 다르게** 쓰이도록 한다 — 세 곳의 손으로 쓴 클래스를 하나로 모은다(새 컴포넌트를 둘지 `Button`에 작은 크기를 더할지는 채원이 정한다. 크기는 지금 알약(px-3 py-1 text-xs)과 같게 유지해 격자 칸 높이가 변하지 않아야 한다).
- **모두 빼기 버튼**: `Button`의 `primary`(검정 알약)를 쓴다. `variant="outline"` + `bg-surface!` 덮어쓰기는 걷어낸다. 폭·`whitespace-nowrap`·비활성(`disabled`) 동작은 그대로다.
- 확인 시트(`UnslotAllSheet`)의 확정 버튼은 이미 `primary` 검정이므로 색은 바꾸지 않고 문구만 바뀐다.
- **등급 안내 줄바꿈**: `tierFixedHint`는 «{tier} 등급으로 모으고 있어요.» 뒤에서 줄이 바뀐다. 문자열에 `\n`을 넣고 `page.tsx`의 `<p>`에 `whitespace-pre-line`을 준다(둘째 문장 앞의 공백은 줄바꿈으로 대체).

### 서비스/코드베이스 관점
- 문구는 모두 `d.itembooks`(`src/lib/i18n/ko.ts`) 사전이 단일 원천이다. 서버 `api/itembooks/[id]/slots`, `slot` 라우트가 내려보내는 문장도 이 사전을 쓰므로 사전만 고치면 서버 응답도 따라온다.
- 고칠 문구(약 20곳, `ko.ts` 기준 줄 번호는 작업 시점에 다시 찾는다): `dropItemSlotted`(743), `unslotFailed`(1574), `unslotButton`(1580), `swapSheetUnslotButton`(1599), `tierFixedHint`(1605), `unslotAll.*`(1619~1639: button·title·confirm·confirming·successToast·full 두 문장·partial·failed), `alreadySlotted`(1658), `slotNotFound`(1670), `inventoryFullForUnslot`(1680).
- 어미 변환 기준: «해제하기→빼기», «모두 해제하기→모두 빼기», «해제할까요→뺄까요», «해제하는 중→빼는 중», «해제했어요→뺐어요», «해제하지 못했어요→빼지 못했어요», «해제하면→빼면», «해제된→빼진», «해제해 주세요→빼 주세요», «장착 해제에 실패했어요→빼기에 실패했어요». 문장이 어색해지는 곳은 아현이 UX Writing 가이드(해요체·한 문장 한 뜻)에 맞게 다듬는다.
- 소스 주석·식별자(`unslot…`, `UNSLOT_ERROR_STATUS_MAP` 등)는 바꾸지 않는다. 다만 사용자에게 보이는 라벨을 가리키는 주석(예: «모두 해제하기» 버튼)은 새 라벨로 고친다.

### 컨텐츠/문서 관점
- `docs/service/writing/UX_WRITING_GUIDELINE.md` §1.3 «해제 (UNEQUIP)» 행을 **«빼기 (UNEQUIP)»**로 바꾼다. 같은 문서의 «이용 정지»·«언팔로우»·«잠김» 행이 «해제»를 다른 뜻으로 쓰므로, 그 행들의 설명 문장(장착의 반대인 «해제(UNEQUIP)»를 가리키는 곳)을 새 용어에 맞춘다. 장착 행의 «추가» 예외 문장(장착 버튼 라벨만 «추가»)은 그대로 둔다. 가이드 안의 «X: 빼기» 금지어 표기는 «X: 해제, 제거, 취소, 언이큅»으로 뒤집는다.
- `docs/service/prd/inventory/PRD.md` 139줄의 «모두 해제하기» 서술을 «모두 빼기»로 맞춘다.
- `jam-web/src/lib/admin/policyDashboard/policiesData.ts` 798·800줄의 «장착한 배지를 모두 해제하면»을 «모두 빼면»으로 맞춘다(CLAUDE.md §2 정책 대시보드 동기화). 대응 시험 `policiesData.test.ts`가 문구를 고정하면 함께 고친다.

## 완료 조건

- 칸의 «빼기» 버튼이 그레이 면이고, «교체»·«추가»는 accent 면 그대로이며, 세 버튼이 한 알약 컴포넌트에서 tone으로 갈린다. 칸 높이·폭이 이전과 같다(로컬 실측).
- «모두 빼기» 버튼이 `Button primary`의 검정 면이고 `outline`·`bg-surface!` 덮어쓰기가 없다.
- 컬렉션 상세에서 사용자에게 보이는 장착의 반대 뜻 «해제»가 한 곳도 남지 않는다(시트 제목·본문·토스트·오류·서버 응답 문구 포함). 이용 정지·Strava 권한 같은 다른 뜻의 «해제»는 그대로다.
- 등급 안내가 «Rare 등급으로 모으고 있어요.» 다음 줄에 «장착한 배지를 모두 빼면 다른 등급으로 다시 정할 수 있어요.»로 두 줄 표시된다(로컬 실렌더).
- UX Writing 가이드 §1.3에 «빼기 (UNEQUIP)»가 반영되고 «해제»를 금지어로 적는다. PRD·정책 대시보드 문구도 맞는다.
- `scripts/verify.sh`(lint·typecheck·test·slop)가 통과한다.

## 완료 기록

### 채원 사전 판정
- 서비스 전용 + 재사용. 칸의 «교체»·«빼기»·«추가» 알약은 `SlotActionPill` 하나로 모으고 tone(accent·neutral)으로 색을 가른다. «모두 빼기»는 `Button variant="primary"`를 그대로 쓴다. MODULAR `Button`은 확장하지 않았다.
- 근거: `Button size="xs"`는 높이가 약 31px이라 칸 알약(약 24px)을 대체하면 칸 높이가 변한다. 알약은 한 파일에서만 쓰여 MODULAR 승격 기준에 못 미친다. 새 토큰은 없다(빼기=`--default` 면 + `--foreground` 글자, `Button secondary`와 같은 쌍).

### 구현 내용 요약
- `SlotActionPill.tsx`(신규)로 칸 알약 3개의 모양을 한 곳에 두고 tone으로 색만 가른다. «빼기»는 그레이, «교체»·«추가»는 accent다. `preventDefault`·`stopPropagation`과 «…» 표기는 호출부에 그대로 있다.
- «모두 빼기»는 `outline` + `bg-surface!` 덮어쓰기를 걷어내고 `Button primary`(검정)로 바꿨다.
- `ko.ts`의 장착 반대 뜻 «해제»를 «빼기»로 통일했다(약 20곳, 서버 응답 문구 포함). 이용 정지·Strava 권한의 «해제»는 그대로다.
- `tierFixedHint`에 `\n`을 넣고 `page.tsx`의 `<p>`에 `whitespace-pre-line`을 줬다.
- UX Writing 가이드 §1.3을 «빼기 (UNEQUIP)»로 바꾸고 «해제»를 금지어로 적었다. PRD 두 곳, 정책 대시보드, JAM2 운영 로직 문서의 문구를 맞췄다.
