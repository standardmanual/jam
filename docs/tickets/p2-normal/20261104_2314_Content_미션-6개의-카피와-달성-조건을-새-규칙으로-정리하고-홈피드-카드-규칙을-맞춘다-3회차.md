# [Content] 미션 6개의 카피와 달성 조건을 새 규칙으로 정리하고 홈피드 카드 규칙을 맞춘다 (3회차)

## 핵심 요약

- 요구사항: 운영 DB의 미션 6개와 연결된 홈피드 카드 6건을 새 역할 분담(제목=느낌, 설명=재미, 달성 조건=지표 라벨 불릿)에 맞게 고친다. 홈피드 카드 설명에도 같은 규칙을 적용한다. 사용자가 범위를 «6개 전부 + 홈피드 규칙 한 번에»로 정했다(2026-11-04). 상위 `20261104_2146`의 3회차다.
- 구현 계획: 조각 3개로 나눠 순서대로 한다. **3-A** 불릿 생성기를 나머지 미션 모양으로 넓힌다(코드, jam-work 파이프라인). **3-B** 새 문구를 확정한다(윤진 초안 → 사용자 확인). **3-C** 확정된 문구·조건을 운영 DB와 규칙 문서에 적용한다(카리나, 드라이런·백업·롤백 실측).
- 관련 파일: 조각별로 아래에 적는다.

## 배경 / 문제 정의

1·2회차가 틀(불릿 생성, `sync_count`, 등록 검사의 미션 설명 보상 금지)을 만들었다. 지금 운영 DB는 틀과 맞지 않는다.

- 미션 6개의 `condition_text`가 모두 긴 문장이고, 설명 6개와 카드 설명 6건이 모두 「N포인트를 획득해요」로 끝나며 조건 수량을 되풀이한다.
- 불릿은 `engine_condition`의 숫자 키만 만들 수 있어, 「드랍하고, 픽업하고, 이어가기」를 뺀 5개 미션은 아직 긴 문장 폴백으로 그려진다.
- 「드랍하고, 픽업하고, 이어가기」는 `condition_json`에 `sync_count`가 없어 `동기화 1회` 불릿이 안 나온다.
- 대표 이미지 보조 문구(예: 「드랍 1·픽업 1」)가 조건 수량을 되풀이한다.
- 어드민 «달성 조건 문장 (선택)» 도움말이 1회차 이후 사실과 어긋난다.
- `badge_metric_labels`의 `repeat_count`가 「충족 횟수」다. 「충족」은 UX 라이팅 가이드 금지어다.

운영 DB 사실(2026-11-04 확인):

| 미션 | 유형 | condition_json | 참가자 |
|---|---|---|---|
| 지하철 역에서 만나는 행운 | engine_condition | `checkin_category_count {count:2, category:train_subway}` | 2 |
| 처음 오른 산에서의 한 걸음 | engine_condition | `checkin_category_count {count:1, category:mountain}` | 0 |
| 쌀쌀한 날의 짧은 산책 | engine_condition | `repeat_count 3`, `activity_type walking`, `single_distance_km 0.5` | 2 |
| 드랍하고, 픽업하고, 이어가기 | engine_condition | `drop_item_count 1`, `pickup_item_count 1` | 2 |
| 활동 두 번이면 충분해요 | activity_count | `count 2` | 0 |
| 걷다 보면 어느새 10km | distance | `distance_km 10`, `activity_type walking` | 0 |

완료 기록은 0건이다. 카테고리 이름은 `poi_categories`(`mountain`=산, `train_subway`=기차/지하철)에 있다. 홈피드 카드 6건은 모두 `mission_spotlight`(제목 3건은 미션명과 다르다).

## 상세 요구사항

### 3-A. 불릿 생성기 확장 (코드, 파이프라인)

제안(윤진 초안과 함께 사용자 확인 뒤 확정):

- **객체 조건 `checkin_category_count`**: `{카테고리 이름} 체크인 배지 {count}개`. 카테고리 이름은 서버가 `poi_categories`에서 읽어 넘긴다(`/` 이름은 「·」로 바꿔 «기차·지하철»). 라벨 행 `checkin_category_count`=`체크인 배지`/`개`를 더한다.
- **옛 유형**: `distance`는 `{누적 거리 라벨} {n}km`, `activity_count`는 `활동 횟수 {n}회` 불릿으로 그린다. 값 모양이 맞지 않으면 기존 표시로 되돌린다.
- **`activity_type`**: 활동 종류 줄은 기존대로 별도 줄(`걷기 활동`)이다. 불릿 목록 맨 앞에 두는 것이 읽기 쉬운지 채원 판정에 따른다.
- **라벨 값 변경**: `repeat_count` 「충족 횟수」→「활동 횟수」(금지어 제거). 이 표를 읽는 곳은 미션 상세뿐임을 확인했다(배지 진행 화면은 아직 읽지 않는다).
- 어드민 «달성 조건 문장 (선택)» 도움말을 「불릿이 만들어지지 않을 때만 그 자리에 보여요」로 고친다.
- 파이프라인 경로 ③(표준), 유형 `ui`. 파일 지도는 시작 시점에 `git grep`으로 채운다.

### 3-B. 새 문구 확정 (윤진 초안 → 사용자 확인)

- 6건 각각: 미션 설명, 카드 설명(60자 이하), 이미지 text01·text02 제안. 미션명은 바꾸지 않는다.
- 문구는 서비스 노출 카피라 **사용자가 확인한 뒤에만 DB에 적용한다.** 윤진 초안은 규칙 자체 검사(조건 수량·보상 단어 없음, `copyRules.ts`)를 통과해야 한다.

### 3-C. 적용 (카리나)

- 마이그레이션(번호는 318 이후 재확인)으로 `missions.description`·`condition_json`(드랍·픽업 미션에 `sync_count: 1`)·`condition_text`(null)와 `today_cards.description`을 갱신한다. 제목·설명이 모두 옛 값과 일치하는 행만 갱신하고, 갱신 건수를 검증한다. 되돌림 SQL과 백업 표(옛 값)를 둔다.
- 이미 참가한 미션 3개(참가자 각 2명)는 `sync_count` 추가로 완료가 막히지 않는지 확인한다(동기화 기록은 317 적용 시점부터 쌓인다. 미션 판정이 도는 동기화는 기록이 먼저 남으므로 막히지 않는다).
- 대표 이미지 보조 문구는 이미지를 다시 구워야 한다. `scripts/asset-generator/make-home-feed-card.mjs`로 다시 만들어 올리는 일이라 이미지 파일 교체 승인을 따로 받는다(이번 조각에서 문구만 확정하고, 이미지 교체는 승인 뒤에 한다).
- 규칙 문서·검사: `UX_WRITING_GUIDELINE.md` §2.6에 카드 설명 규칙을, `HOME_FEED_REGISTRATION_BUNDLE.md`와 `jam-marketer.md`의 카드 설명 문장(현재 「…N포인트를 획득해요」 예시와 «what the user receives» 문구)을 새 규칙으로 맞춘다. 카드 설명에 보상·조건 수량 금지 규칙을 `copyRules.ts`에 더할지(미션 카드만 가려낼 수 없다는 한계)는 3-B 결과를 보고 정한다.

## 완료 조건

- 미션 6개의 설명·카드 설명에 보상 표현과 조건 수량이 없고, 달성 조건이 라벨 불릿으로 그려진다(「드랍하고, 픽업하고, 이어가기」는 드랍·픽업·동기화 세 줄).
- 어느 미션의 상세에도 긴 `condition_text` 문장이 남아 있지 않다.
- `repeat_count` 라벨에 금지어가 없다.
- 카드 설명 규칙이 가이드·묶음 문서·윤진 지침에 같은 문장으로 적혀 있다.
- 홈피드 카드 6건이 새 설명으로 보인다. 대표 이미지 교체는 승인된 건만 한다.

## 주요 의사결정

- 2026-11-04 사용자: 범위는 미션 6개와 홈피드 카드 규칙까지 한 번에 한다(좁게 시작하는 안은 채택하지 않음).
- 문구 적용 전 사용자 확인을 받는다(서비스 노출 카피, 운영 DB는 프로덕션과 공용).
