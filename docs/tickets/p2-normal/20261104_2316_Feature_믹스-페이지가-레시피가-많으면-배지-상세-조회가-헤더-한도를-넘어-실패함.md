# [Feature] 믹스 페이지가 레시피가 많으면 보상 배지 상세 조회가 HTTP 헤더 한도를 넘어 실패한다

## 핵심 요약

- 현상: 로컬 /combine에서 서버 로그 `[combine/page] 슬롯 후보·보상 배지 상세 조회 실패`가 반복된다. 원인은 `fetch failed … HTTP headers exceeded server limits (typically 16K)`로, 배지 ID를 `.in(...)`에 한꺼번에 넣어 요청 주소가 너무 길어진 것이다(힌트: RPC 함수로 바꾸라는 안내가 같이 나온다).
- 영향: 이 조회가 실패하면 레시피 행의 보상 배지 이미지·이름이 비어 보인다(로컬에서 코인 아이콘만 보였다). 운영 DB 레시피 수가 늘면 같은 문제가 생길 수 있다.
- 관련 파일: `jam-web/src/app/(main)/combine/page.tsx`(보상 배지·슬롯 후보 상세 조회 `.in()` 부분 — 줄 위치는 작업 시점에 찾는다)
- 구현 계획(제안): ID 목록을 일정 크기(예: 100개)로 나눠 여러 번 조회하거나 RPC로 바꾼다. 조회 실패 시 행이 어떻게 보이는지도 함께 정한다.

## 완료 조건

- 레시피·후보가 많아도 조회가 실패하지 않고 보상 배지가 행에 보인다. 청크 경계를 시험으로 고정한다.
