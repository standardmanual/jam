# [UI] 서비스의 모든 포인트 표기를 오렌지로 통일한다 (값과 «포인트» 글자 모두, 한 컴포넌트에서)

## 핵심 요약

- 요구사항(사용자 지시 2026-11-04): «모든 포인트는 오렌지 컬러로 표기하는 걸 규칙으로 한다.» 포인트 값(숫자)과 «포인트» 글자 모두 오렌지다. 규칙은 UX Writing 가이드 «포인트(POINT)» 행에 이미 적었다(티켓 20261104_2315). 이 티켓은 서비스 전 화면에 그 규칙을 적용한다.
- 지금 규칙을 따르는 곳: 믹스 레시피 행(`RecipeRewardRow.tsx`)뿐이다.
- 구현 계획(제안, 채원 사전 판정 필요):
  1. 값+단위를 그리는 공용 컴포넌트(예: `PointText`)를 한 곳에 둔다. 색은 `text-warning`(`--warning` #f5a300) 하나만 받는다.
  2. 문구 사전(`ko.ts`)의 «{n} 포인트»가 문장 속에 섞인 문자열(약 87곳 중 사용자 노출분)은 문장 전체가 아니라 «{n} 포인트» 조각만 칠해야 한다. `t()`가 ReactNode 조각을 받을 수 있게 하거나, 조각만 감싸는 도우미를 둔다.
  3. 화면별로 값·단위가 보이는 곳을 전수 조사해 적용한다: 홈 피드·온보딩 퀘스트 카드·프로필·포인트 내역(`points/page.tsx`)·미션 목록/상세 보상·믹스·배지 상세·잠긴 아이템 상세·인벤토리 상세·드랍 시트·알림·배지 공개 오버레이·픽업 선택 오버레이·지도·회원 탈퇴 시트 등(`grep 포인트`로 약 30개 파일).
  4. MODULAR(`design-system/`)에 같은 규칙이 들어가야 하는지는 채원이 판정한다.
- 관련 파일: 위 화면 목록, `jam-web/src/lib/i18n/ko.ts`·`t()` 구현, `jam-web/src/components/ui/`(공용 컴포넌트 위치), `docs/service/writing/UX_WRITING_GUIDELINE.md`(§1.3 포인트 행)

## 먼저 정해야 할 것 (채원 판정에서 다룬다)

- **글자 대비**: `--warning`(#f5a300)은 흰 면 위에서 대비가 약 2:1이라 12~16px 글자로는 WCAG 기준(4.5:1)에 못 미친다. 서비스 전체 규칙으로 쓰면 읽기 어려운 곳이 생긴다. 더 짙은 오렌지 글자용 토큰을 새로 정할지, 굵은 큰 글자에만 쓸지, 지금 색을 그대로 쓸지는 사용자 승인이 필요한 새 토큰 판단이다.
- 크림·색 배경(캡슐, 배지 상세 테마 배경) 위의 포인트는 같은 색이 읽히는지 확인한다.
- 다크 테마에서도 같은 토큰인지 확인한다.

## 완료 조건

- 사용자에게 보이는 포인트 값과 «포인트» 글자가 모든 화면에서 같은 오렌지로 보인다(어드민 제외). 문장 속 «{n} 포인트» 조각도 같다.
- 색은 한 컴포넌트·한 토큰에서만 정의하고 화면별로 색 클래스를 따로 적지 않는다.
- 글자 대비 판정 결과(새 토큰 또는 현행 유지)가 티켓에 기록된다.
- `scripts/verify.sh` 통과.
