# [UI] 달성 조건 불릿 생성기를 나머지 미션 모양으로 넓힌다 (3회차 3-A)

## 핵심 요약

- 요구사항: 달성 조건 불릿이 `engine_condition`의 숫자 키만 그려지는 것을, 나머지 미션 5개 모양(체크인 카테고리 객체, 옛 유형 `distance`·`activity_count`, 걷기 미션)까지 그리게 넓힌다. 어드민 «달성 조건 문장» 도움말을 사실에 맞게 고친다. 후속 정리 티켓 `20261104_2227`(죽은 `muted` 분기, 불릿 `key`)을 같은 회차에서 함께 닫는다. 상위 `20261104_2314`의 3-A다.
- 구현 계획: 아래 「구현 계획」 표. 파일이 5개를 넘으므로 첫 호출부터 `planOnlyWaiver`를 넣는다.
- 관련 파일: 「구현 계획」 참조.

## 배경 / 문제 정의

운영 DB 미션 6개 중 불릿이 그려지는 것은 드랍·픽업 미션뿐이다(1회차). 나머지는 긴 `condition_text` 문장으로 되돌아간다. 3-C에서 `condition_text`를 비우므로, 그 전에 모든 미션이 불릿(또는 짧은 기본 문구)으로 그려져야 한다.

| 미션 | 유형 | `condition_json` | 원하는 불릿 |
|---|---|---|---|
| 지하철 역에서 만나는 행운 | engine_condition | `checkin_category_count {count:2, category:'train_subway'}` | `기차·지하철 체크인 배지 2개` |
| 처음 오른 산에서의 한 걸음 | engine_condition | `checkin_category_count {count:1, category:'mountain'}` | `산 체크인 배지 1개` |
| 쌀쌀한 날의 짧은 산책 | engine_condition | `repeat_count 3`, `activity_type walking`, `single_distance_km 0.5` | `한 번의 거리 0.5km`, `활동 횟수 3회` (+ 기존 `걷기 활동` 줄) |
| 드랍하고, 픽업하고, 이어가기 | engine_condition | `drop_item_count 1`, `pickup_item_count 1`(3-C에서 `sync_count 1` 추가) | 1~2회차 그대로 |
| 활동 두 번이면 충분해요 | activity_count | `count 2` | `활동 횟수 2회` |
| 걷다 보면 어느새 10km | distance | `distance_km 10`, `activity_type walking` | `누적 거리 10km` (+ 기존 `걷기 활동` 줄) |

## 상세 요구사항

### 서비스/코드베이스 관점

1. **`jam-web/src/lib/missions/conditionBullets.ts`** 에 다음을 더한다(순수 함수 유지).
   - 입력에 장소 카테고리 이름 맵(`Map<slug, label>`)을 더한다. `buildConditionBullets`·`conditionBulletKeys`의 시그니처가 바뀌면 호출부(`page.tsx`)와 시험을 함께 고친다.
   - **객체 키 `checkin_category_count`**: 값이 `{count: number, category: string}`이면 `{카테고리 이름} {라벨} {count}{단위}`. 카테고리 이름의 `/`는 `·`로 바꾼다(`기차/지하철` → `기차·지하철`). 카테고리가 맵에 없으면 `null`이다.
   - **옛 유형** `distance`(키 `distance_km`)·`activity_count`(키 `count`): 해당 유형일 때 그 키 하나를 `{라벨} {값}{단위}`로 만든다. `activity_type`은 지금처럼 별도 줄에 맡긴다. 값이 숫자가 아니거나 라벨이 없으면 `null`이다. 그 밖의 유형(`checkin`·`item_collect`·`streak_days` 등)은 이번에도 `null`이다.
   - 한 키라도 만들지 못하면 불릿 전체 `null`이라는 1회차 규칙은 그대로다.
2. **`jam-web/src/app/(main)/missions/[id]/page.tsx`** (`MissionDetailPage`, 불릿 구간 110~114줄 부근): 조건에 `checkin_category_count`가 있을 때만 `poi_categories`(`slug`, `label`)를 service 클라이언트로 읽어 맵으로 넘긴다. 읽지 못하면 맵을 비워 `null` 경로로 간다(오류 문구 없음).
3. **지표 라벨 마이그레이션 `318_...`**(파일 작성만, 실행은 카리나): `badge_metric_labels`에 `count`=`활동 횟수`/`회`, `checkin_category_count`=`체크인 배지`/`개`를 `ON CONFLICT DO NOTHING`으로 더하고, `repeat_count`의 라벨을 `충족 횟수`에서 `활동 횟수`로 바꾼다(`WHERE metric_key='repeat_count' AND label_ko='충족 횟수'`일 때만). 「충족」은 UX 라이팅 가이드 금지어다. 이 표를 읽는 곳이 미션 상세뿐임은 확인했다(`git grep getMetricLabels`). 되돌림 SQL 파일(`_down.sql`)을 같이 둔다.
4. **`jam-web/src/app/(main)/missions/[id]/MissionDetailClient.tsx`**: `ConditionRow`의 `tone="muted"` 분기(사용처 0)와 관련 클래스를 정리하고, 불릿 `key`를 `` `${index}-${bullet}` ``처럼 위치를 포함해 바꾼다(티켓 `20261104_2227`). 불릿이 있을 때 `activity_type` 줄을 그 뒤에 두는 기존 순서는 유지한다. 채원 판정이 앞에 두라고 하면 따른다.
5. **어드민 도움말**(`jam-web/src/app/admin/missions/MissionForm.tsx` 332줄 부근, `jam-web/src/app/admin/gate-missions/GateMissionForm.tsx` 459줄 부근): 「미션 상세의 달성 조건 카드 첫 줄에 보여요. 비우면 목표 유형에 맞는 기본 문구가 나와요.」를 「달성 조건은 지표 라벨로 만든 불릿이 먼저 보여요. 불릿을 만들 수 없을 때만 이 문장이 보여요.」(해요체, 문구는 가이드에 맞춰 다듬어도 된다)로 바꾼다. 같은 문구를 단언하는 시험이 있으면 함께 고친다.

### UI/UX 관점

- 새 컴포넌트·토큰 없음. 기존 `ConditionRow tone="primary"`를 불릿 개수만큼 반복한다(1회차 채원 판정과 같다).
- 걷기 미션은 불릿 두 줄 뒤에 `걷기 활동` 줄이 붙는다. 읽기 순서가 어색하면 채원 판정으로 정한다.

### 컨텐츠 관점

- 라벨 문구 3개(`활동 횟수`, `체크인 배지`, `repeat_count` 변경)만 새로 쓴다. 사용자 확인: 「모두 제안대로」(2026-11-04).

## 완료 조건

- `{checkin_category_count:{count:2,category:'train_subway'}}`는 `기차·지하철 체크인 배지 2개`, `{count:1,category:'mountain'}`는 `산 체크인 배지 1개`다(시험, 카테고리 맵·라벨 맵은 시험에서 준다). 카테고리가 맵에 없으면 `null`이다.
- `distance` 유형(`distance_km:10`)은 `누적 거리 10km`, `activity_count` 유형(`count:2`)은 `활동 횟수 2회`다. `activity_type`은 불릿에 들어가지 않는다(시험).
- 걷기 미션(`repeat_count:3`, `single_distance_km:0.5`, `activity_type:walking`)은 `한 번의 거리 0.5km`, `활동 횟수 3회` 두 줄이다(시험, 순서는 레지스트리 순서를 따른다).
- 불릿이 없을 때의 기존 폴백(`condition_text` → `{goal.label} … 달성`)은 그대로다(시험).
- `ConditionRow`에 `muted` 분기가 없고, 같은 문구의 불릿 두 줄이 `key` 경고 없이 그려진다(시험).
- 어드민 도움말이 새 문구고, 같은 문구를 단언하던 시험이 통과한다.
- 마이그레이션 두 파일이 있고 되돌림 SQL이 맞다. `scripts/verify.sh` 통과.

## 완료 기록

### 구현 내용 요약

- 불릿 생성기가 체크인 카테고리 객체(`기차·지하철 체크인 배지 2개`, `산 체크인 배지 1개`)와 옛 유형(`distance`→`누적 거리 10km`, `activity_count`→`활동 횟수 2회`), 걷기 미션(`한 번의 거리 0.5km`, `활동 횟수 3회`)까지 만든다. 서버가 체크인 카테고리 객체가 있을 때만 `poi_categories`를 읽고, 읽지 못하면 폴백으로 간다.
- 채원 판정: 활동 종류 줄(`걷기 활동`)은 불릿이 있을 때 맨 위로, 폴백일 때는 기존처럼 뒤에 둔다(범위 → 수량 순).
