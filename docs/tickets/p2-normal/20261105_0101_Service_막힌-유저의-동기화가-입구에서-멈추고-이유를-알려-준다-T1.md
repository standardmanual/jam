# [Service] 막힌 유저의 동기화가 입구에서 멈추고 이유를 알려 준다 (T1)

## 핵심 요약

- 요구사항: 캡슐이 가득 차고 인벤토리 빈칸이 필요 칸수보다 적은 유저가 동기화를 누르면, Strava를 부르지 않고 409 `capsule_inventory_blocked`로 멈추며 안내 토스트(info)가 나온다.
- 구현 계획: 막힘 판정 DB 함수 `capsule_receive_blocked(uuid)`(읽기 전용)를 만들고, 동기화 입구(`assertNotSuspended` 바로 뒤, 보류 고르기 검사 앞)에서 부른다.
- 관련 파일: `jam-web/supabase/migrations/320_capsule_receive_blocked.sql`과 `_down.sql`(신규, 번호는 push 직전 재확인), `jam-web/src/lib/capsule/receive-block.ts`(신규), `jam-web/src/lib/strava/sync.ts`(1144~1148행 `SyncPendingItemsError` 선례 옆), `jam-web/src/app/api/strava/sync/route.ts`(59~64행 409 매핑), `jam-web/src/lib/strava/sync-flow.ts`, 동기화 버튼 컴포넌트(`SyncButton.tsx`), `jam-web/src/lib/i18n/ko.ts`, `jam-web/src/lib/admin/policyDashboard/policiesData.ts`

## 배경 / 문제 정의

상위 티켓 20261105_0100의 첫 조각이다. 동기화 조회 커서는 `strava_activities`의 최신 `start_date`이고 `last_synced_at` 선점 잠금은 입구 뒤라, 입구에서 막으면 활동 기록이 사라지지 않고 풀린 뒤 이어서 정상 반영된다(코드 읽기로 확인). 같은 선례로 `SyncPendingItemsError`가 가져오기 전에 던져 409로 알린다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 판정은 DB 함수 하나가 단일 원천이다. TS에 같은 판정을 따로 구현하지 않는다.
- 함수는 `blocked`, `free`, `needed`를 돌려준다. 필요 칸수는 `capsule_policy`의 `guaranteed_count + bonus_count`다(`neededSlotsOf`와 같은 값).
- 이용 정지가 먼저 적용되고, 트라이브 없음은 기존 `tribe_required` 그대로다.
- 보류 고르기 대기(409 `sync_pending_items`)와 겹치면 이번 막힘 안내를 먼저 낸다(Q8 추천).
- 콜백 직후 동기화(`connection-save.ts`)와 백필(`backfill.ts`)이 막혀 던져도 Strava 연결 저장은 성공해야 한다.

### UI/UX 관점
- 안내 토스트(info)는 동기화 버튼을 눌렀을 때 낸다. 문구는 UX 라이팅 가이드의 해요체·[현상]→[원인]→[해결책] 구조를 따른다(윈터 톤 확인).

## 구현 계획

1. 마이그레이션 `_down.sql` 짝 파일을 함께 쓴다(확장 단계, `db-migration-rules.md` 규칙). 롤백 실측 드라이런(`DO` 블록 + `RAISE EXCEPTION`)을 하고, 시험 계정으로 막힘/해제를 읽는다.
2. `receive-block.ts`에 RPC 호출 래퍼와 `CapsuleInventoryBlockedError`를 둔다.
3. `sync.ts` 입구에서 막혔으면 가져오기 전에 던지고, `route.ts`가 409 `capsule_inventory_blocked`로 매핑한다.
4. 화면은 409 응답을 받으면 토스트를 낸다. `ko.ts`에 문구를 더한다.
5. 큰 백로그(수십 건) 시험: 막힌 채로 쌓인 활동이 풀린 뒤 60초 안에 끝나는지 확인한다.
6. 같은 커밋에서 `policiesData.ts`에 «인벤토리 가득 참 잼 차단» 항목을 신설한다.

크기: 상한(파일 5개·100줄)을 넘는다. 카리나가 파일 단위 계획과 함께 «계획 반환 면제»를 부여하거나, T1을 «DB 함수·입구·409»와 «토스트»로 나눈다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 막힌 시험 계정이 동기화를 누르면 Strava 호출 없이 409 `capsule_inventory_blocked`와 안내 토스트(info)가 나온다.
- 그때 `strava_activities` 행과 `last_synced_at`이 변하지 않는다.
- 막히지 않은 계정의 동기화 동작은 이전과 같다(단위 시험과 시험 계정 실측).
- 콜백 직후 동기화·백필이 막혀 던져도 연결 저장은 성공한다.
- 빈칸을 필요 칸수 이상으로 만든 뒤 다음 동기화가 정상이다.
- `capsule_receive_blocked`가 읽기 전용이고 `_down.sql`로 되돌려진다(롤백 실측 기록).
- `policiesData.ts`에 «인벤토리 가득 참 잼 차단» 항목이 있다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 큰 백로그(수십 건) 풀림 시험은 가능한 범위에서 기록하고, 60초를 넘는 위험이 확인되면 별도 티켓을 만든다.

체크포인트: db 유형이므로 DB 단독 호출 전 사용자 확인. 롤백 실측 후 실행한다.
