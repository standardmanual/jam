# [Infra] 캡슐 보관 구조를 DB에서 걷어 낸다 (T6, 축소)

## 핵심 요약

- 요구사항: `capsule_hold_reward`·`capsule_claim_pending` 함수, `capsule_pending_rewards` 표, `user_capsules.alert_stage` 열을 삭제한다(축소 단계).
- 구현 계획: 시작 시 `capsule_pending_rewards`가 0행이 아니면 예외로 중단한다. DB 안 호출 전수 검색(`pg_proc.prosrc`·뷰 정의)에서 호출 0건을 확인한 뒤 지운다. `_down.sql`로 표·함수·열을 복원한다. 생성 타입을 재생성한다.
- 관련 파일: `jam-web/supabase/migrations/323_drop_capsule_pending.sql`과 `_down.sql`(번호는 push 직전 재확인), `jam-web/src/types/database.generated.ts`, `docs/service/prd/02_DATA_MODEL.md`

## 배경 / 문제 정의

T5까지 끝나 코드가 보관 구조를 더 쓰지 않으면, DB에 남은 표·함수·열은 정리 대상이다. 응답 키(`pendingCount`·`forfeited`·`alertStage`) 제거도 이 티켓에서 한다. 되돌릴 수 없는 작업이므로 실행 전 점검 절차(되돌림 SQL 확인, 롤백 실측, 실행 직후 읽기 전용 확인과 보고)를 지킨다. `jam_forfeit_weekly` 뷰는 유지를 추천한다(Q9, 새 소멸 0건 확인용, 오픈 4주 뒤 정리).

## 구현 계획

1. T5가 프로덕션에 배포된 뒤에 시작한다(옛 코드가 함수를 부르는 동안은 지우지 않는다).
2. 호출 전수 검색 후 표 행 수 0 확인, `DO` 블록 롤백 실측, 실행.
3. 새 함수를 실제로 한 번씩 불러 «함수 없음» 오류가 없음을 시험한다.
4. MCP `generate_typescript_types`로 생성 타입을 받아 대조·반영한다(CLI 없음).

크기: 마이그레이션 2개와 생성 타입(대형). 면제 필요.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `capsule_hold_reward`·`capsule_claim_pending`가 없고 `capsule_pending_rewards` 표와 `user_capsules.alert_stage` 열이 없다.
- 시작 시 `capsule_pending_rewards`가 0행이 아니면 중단하는 확인이 있다.
- DB 안 호출 전수 검색에서 삭제 대상 호출이 0건이다.
- 새 함수를 실제로 호출해 «함수 없음» 오류가 없다.
- `_down.sql`이 표·함수·열을 복원한다(롤백 실측 기록).
- 생성 타입이 같은 커밋에 반영되어 있다.

선행: T5 배포 뒤. 체크포인트: db 유형 단독 호출과 되돌릴 수 없는 작업이므로 실행 전 점검 절차를 지킨다.
