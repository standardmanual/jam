# [UI] 막힘 안내가 «배지 n개를 얻었고 k칸을 비우라»는 맥락으로 바뀐다 (R3)

## 핵심 요약

- 요구사항: 홈 막힘 배너와 캡슐 위젯 안내를 새 맥락으로 바꾼다. 「배지 n개를 얻었다 → 그런데 인벤토리가 가득 차서 못 넣었다 → k칸을 비워라 → 그 전까지 잼을 얻을 수 없다」. n은 대기 보상 개수, k는 부족한 칸 수(`shortfall`)다.
- 구현 계획: 배너 본문과 위젯 문구를 새 값(`pending`, `shortfall`)으로 그린다. 서버가 내려 주는 `HomeCapsuleBlockedBannerView`에 `pending`을 더한다. 레이아웃(반전 카드, 작은 버튼, 게이지 안 문구)은 T4 후속 수정에서 확정된 그대로 둔다.
- 관련 파일: `jam-web/src/app/(main)/CapsuleBlockedBanner.tsx`, `jam-web/src/lib/capsule/receive-block-contract.ts`, `home-blocked-banner.ts`, `jam-web/src/lib/i18n/ko.ts`(`d.capsule.blockedBanner`, `d.capsule.widget.notice`, 약 1093~1110줄), `jam-web/src/components/capsule/CapsuleWidget.tsx`, 시험 파일들, `docs/service/writing/UX_WRITING_GUIDELINE.md`, `docs/service/prd/home-feed/PRD.md`, `policiesData.ts`

## 배경 / 문제 정의

T4 문구(«인벤토리가 가득 찼어요 / 캡슐을 열 빈칸이 모자라서…»)는 보상이 아직 정해지지 않은 구조를 전제로 했다. R1 이후에는 보상이 이미 정해져 있어 «얻은 배지가 있는데 못 넣고 있다»가 사실이다.

## 상세 요구사항

### UI/UX 관점
- 제목 시안: «배지 {n}개를 얻었어요». 본문 시안: «인벤토리가 가득 차서 넣지 못했어요. {k}칸을 비우면 바로 들어와요. 그 전까지는 잼을 얻을 수 없어요.» 해요체, 마침표 규칙은 가이드를 따른다. 윈터 톤 확인과 민지 한국어 점검(12번)을 받는다.
- 게이지 안 문구(위젯)는 «배지를 얻었어요» 계열로 줄이거나 현재 «캡슐이 가득 찼어요»를 유지할지 정한다(미결, 추천: 새 맥락에 맞춰 짧게 «배지가 기다려요»).
- k가 0이 되는 순간(칸이 충분해진 순간)은 R2가 자동 지급하므로 배너는 곧 사라진다. 지급 전 한 순간 k=0이 보이면 «1칸»으로 올려 보이지 않는다(기존 `Math.max(1, shortfall)` 유지 여부 확인).
- **게이지 문구 자리**: 보류가 생기면 캡슐은 새 캡슐(채움 0)이 되어 게이지가 비어 있다. 지금의 «채움 안쪽 왼쪽에 문구» 방식은 채움이 0이면 자리가 없다. 비어 있는 게이지에서 문구를 어디에 둘지(트랙 안쪽 왼쪽 등)는 채원 판정이 필요하다.
- 새 컴포넌트·토큰 없음. 위 게이지 자리 문제 때문에 경로 ③(표준, 채원 사전 판정 포함)으로 간다.

## 구현 계획

1. 계약 타입과 서버 로더에 `pending`을 더한다.
2. 문구 사전과 배너·위젯을 고친다.
3. 시험 개정, UX Writing 가이드·PRD·`policiesData.ts` 갱신.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 대기 보상 2개, 빈칸 1개인 유저의 홈에 «배지 2개»와 «1칸»이 정확히 나온다. 대기 1개, 빈칸 0개면 «배지 1개»와 «1칸»이다.
- 줄바꿈이 일찍 꺾이지 않고(`text-balance` 없음), 반전 카드·작은 버튼 모양은 그대로다.
- 사용자 노출 문구가 UX Writing 가이드(해요체, 고정 용어)를 지키고 `check-slop` 검사를 통과한다.
- 대기 보상이 없으면 배너가 DOM에 없다.

## 완료 기록

### 구현 내용 요약
- 배너 문구: 제목 «아이템 배지 {n}개를 얻었어요»(n = 대기 개수), 본문 «인벤토리가 가득 차서 넣지 못했어요. {k}칸을 비우면 바로 들어와요. 그 전까지는 잼을 얻을 수 없어요.»(k = max(1, 부족분)). 구조(반전 카드, 붉은 아이콘 하나, 작은 버튼, `text-balance` 없음)는 그대로다.
- `HomeCapsuleBlockedBannerView`에 `pending`을 더하고 `home-blocked-banner.ts`와 `page.tsx`가 값을 내려 준다.
- 게이지: 문구가 있어도 자리를 `capsuleNumberPlacement`로 정한다(채움 0이면 트랙 오른쪽 끝 오렌지 글자). 문구 가시성을 보임 관찰자에 묶지 않아 새로고침 직후에도 사라지지 않는다. 페이드 240ms는 클래스(`motion-reduce:transition-none`)로 건다. 스크린리더 라벨은 «캡슐, 얻은 아이템 배지를 넣지 못해 잼을 얻을 수 없어요».
- 게이지 안 문구는 사용자 결정으로 «캡슐이 가득 찼어요» 그대로다.
- UX Writing 가이드에 «잼을 얻을 수 없어요»를 사용자 결정(2026-11-05) 예외로 명시했다. PRD(home-feed)와 `policiesData.ts`도 같은 문구로 맞췄다.
