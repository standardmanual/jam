# [UI] 인벤토리 가득 참 안내와 알림을 어두운 반전 면으로 표시한다

## 핵심 요약

- 요구사항: 홈 막힘 카드(티켓 20261105_1912)처럼 «인벤토리가 가득 찼다»는 안내를 어두운 반전 면(네거티브, 사용자 결정 2026-11-05)으로 보인다. 두 곳이다. (1) 인벤토리 화면의 가득 참 상시 안내 카드, (2) 알림 화면의 `inventory_full` 알림 행. 문구·링크·동작은 바꾸지 않고 면과 글자·버튼 색만 바꾼다.
- 범위 밖(사용자 결정): 남은 칸이 적다는 알림(`inventory_slots_low`)과 캡슐 관련 옛 알림 행은 그대로 둔다.
- 관련 파일(지도):
  - `jam-web/src/app/(main)/inventory/page.tsx` 약 113~128행: `remainingSlots === 0` 안내 `div`(지금 `bg-surface border border-border`)와 안의 `Link`(드랍하기, `bg-background`).
  - `jam-web/src/components/ui/ListRowCard.tsx`: `ListRowCardTone`, `TONE_CLASS`. `inverse` 톤을 더한다.
  - `jam-web/src/app/(main)/notifications/NotificationsClient.tsx`: `NotificationRow`(약 173행), `NotificationBody`(약 148행), `RowIcon`(약 105행), 시각 `trailing`. `view.type === 'inventory_full'`일 때만 반전 톤으로 그린다.
  - 시험: `NotificationsClient.test.tsx`, ListRowCard 시험(있으면), 인벤토리 안내 마크업 시험(있으면).
  - 문서: `docs/service/prd/inventory/PRD.md`(가득 참 안내 면 서술), `docs/service/prd/notification/PRD.md`(행 면 서술), `docs/service/writing/UX_WRITING_GUIDELINE.md`는 문구가 안 바뀌므로 해당 없음.

## 배경 / 문제 정의

홈 막힘 카드를 어두운 반전 면으로 바꾼 뒤, 같은 «가득 참» 안내가 인벤토리와 알림에서는 흰 면이라 서로 다른 말처럼 보인다. 사용자가 같은 반전 면으로 통일하라고 했다(질문 답: «홈 카드처럼 어두운 반전 면», 알림은 «인벤토리 가득 참 알림만»).

## 상세 요구사항

### UI/UX 관점
- 인벤토리 안내 카드: `Card tone="inverse"`(또는 같은 토큰 `--background-inverse`) 면, 글자 `--snow`. «드랍하기» 링크는 홈 막힘 카드의 «인벤토리 가기»와 같은 밝은 알약(secondary 면 `--default`, 글자 `--foreground`)이고 최소 높이 44px와 눌림 모양은 그대로다. 카드 인셋(좌우 여백)과 위 간격(`mt-3`)은 그대로다.
- 알림 행: `inventory_full` 행만 `ListRowCard`의 새 `inverse` 톤(`--background-inverse` 면과 같은 색 1px 테두리, 크기는 default와 같다). 문구는 `--snow`, 굵은 슬롯은 그대로 굵게, 시각 글자는 반전 면 위에서 읽히는 밝기(snow 70% 안팎)로 한다. 아이콘 칸은 밝은 면 위 어두운 아이콘 그대로 두거나 반전 면에 맞는 기존 토큰으로 정한다(채원 판정). 새 토큰·새 색은 만들지 않는다.
- 안 읽은 알림 구분 등 알림 행의 다른 동작과 링크 대상은 바꾸지 않는다. 다른 종류의 알림 행은 그대로 흰 면이다.
- 붉은 면·경고 아이콘은 쓰지 않는다(홈 카드와 같다).
- 대비: 반전 면 위 모든 글자는 4.5:1 이상(시각 글자는 채원 판정 후 확인).

## 구현 계획

1. `ListRowCard.tsx`: `ListRowCardTone`에 `'inverse'`를 더하고 `TONE_CLASS.inverse = 'bg-background-inverse border border-background-inverse text-snow'`. 주석에 용도(경고성 안내 행)를 적는다. MODULAR 쪽 `ListRowCard`는 건드리지 않는다(서비스 전용 확장).
2. `NotificationsClient.tsx`: `NotificationRow`가 `view.type === 'inventory_full'`이면 `tone="inverse"`를 넘기고, `NotificationBody`와 시각 `trailing`, `RowIcon`이 반전 면 위 글자 색을 받게 한다(`inverse` 인자로 클래스만 바꾼다).
3. `inventory/page.tsx`: 안내 `div`를 반전 면으로, `Link` 색을 밝은 알약으로 바꾼다.
4. 시험: 알림 행 마크업(inventory_full만 반전, 다른 종류는 그대로), 인벤토리 안내 마크업(가득일 때만 있고 반전 클래스), ListRowCard `inverse` 톤.
5. 문서: 인벤토리 PRD·알림 PRD의 면 서술을 고친다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 인벤토리가 가득 찬 유저의 인벤토리 화면에 어두운 반전 면 안내 카드가 보이고, 문구와 «드랍하기» 링크(`/drops`)는 그대로다. 가득 차지 않았으면 안내가 DOM에 없다.
- 알림 화면에서 `inventory_full` 알림 행만 어두운 반전 면이고, 같은 화면의 다른 종류 행(남은 칸 적음 포함)은 흰 면 그대로다. 링크 대상·읽음 처리는 그대로다.
- 반전 면 위 글자(본문·시각)와 버튼이 대비 4.5:1 이상으로 읽힌다. 새 색·토큰이 없다.
- `scripts/verify.sh` 통과, 문구 변경이 없어 UX Writing 점검은 «문구 불변» 확인으로 갈음한다.

### 후속 범위 (담당·시점)
- 모바일 390px·320px 실렌더(인벤토리 화면과 알림 화면)는 머지 뒤 staging에서 카리나가 232 계정으로 확인한다(232는 인벤토리가 가득 찬 상태). 알림 행은 232 계정에 `inventory_full` 알림이 없으면 시험 행이 필요하다.
