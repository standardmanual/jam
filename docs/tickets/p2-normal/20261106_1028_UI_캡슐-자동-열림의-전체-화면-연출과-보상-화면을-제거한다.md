# [UI] 캡슐 자동 열림의 전체 화면 연출과 보상 화면을 제거한다

## 핵심 요약

- 요구사항(사용자 2026-11-06 «전체 화면으로 커지는 모션과 알림 화면은 제거해», 범위 질문 답 «보상 화면까지 모두 제거»): 캡슐이 자동으로 열렸을 때 레이아웃에서 한 번 뜨는 **합친 연출**을 없앤다. 오렌지 채움이 화면 전체로 퍼지는 모션, 그 뒤의 문구·버튼 화면(챕터·«획득한 배지 보기»/«닫기»), 이어서 뜨는 배지 보상 화면(`BadgeRevealOverlay`)이 모두 대상이다. 열린 결과는 인벤토리의 아이템 배지로만 확인한다.

## 배경 / 문제 정의

캡슐이 동기화나 서비스 활동 잼으로 자동으로 열리면 다음 화면을 열 때 오렌지가 전체 화면으로 퍼지고 문구 화면과 배지 보상 화면이 차례로 떴다. 사용자가 이 전체 화면 연출과 알림 화면을 없애라고 했고, 범위를 묻자 보상 화면까지 모두 제거하기로 정했다(인벤토리 가득 참 구조에서 «전달은 인벤토리 아이템으로만 보인다»는 앞 결정과 같다).

## 상세 요구사항

### UI/UX 관점
- 캡슐이 열린 뒤 어떤 화면을 열어도 전체 화면 연출·문구 화면·배지 보상 화면이 뜨지 않는다. 열린 배지는 인벤토리에서 보인다.
- 게이지는 지금 값까지 일반 채움 모션으로 차오르며, 연출을 기다리느라 2% 원에 붙들리는 일이 없다.
- 챕터가 오르면 기존 챕터 오름 카드(`ChapterRiseOverlay`)가 그대로 한 번 뜬다. 합친 연출이 대신 보여 주던 챕터 번호 연출이 없어지는 대신 이 카드가 뜨는 것은 의도된 결과가 아니라 부수 효과이므로 완료 기록에 사용자 확인 사항으로 남긴다.
- 같은 결과를 더 보여 줄 화면이 없으므로 레이아웃은 보지 않은 결과를 읽지 않는다.

### 데이터
- `capsule_unseen_results`는 이번에 새 행을 쓰지 않는다(표·읽기 라우트·«봤어요» 라우트와 옛 행은 그대로 둔다). 표와 라우트 정리는 후속 티켓이다. DB 변경 없음.

## 구현 계획

1. 위 「관련 파일」 순서대로 삭제와 걷어내기를 한다. 먼저 `CapsuleGauge`·`ChapterRiseWatcher`·`layout.tsx`가 문맥을 읽지 않도록 고치고, 그 뒤 프로바이더·오버레이·문맥·흐름·모델·`capsuleReveal`과 시험을 지운다.
2. `sync-auto-fill.ts`에서 쓰기를 걷고 시험을 맞춘다.
3. `ko.ts`의 합친 연출 전용 문구를 지우고 참조가 남지 않았는지 `git grep`으로 확인한다.
4. 문서와 `policiesData.ts`를 고친다(보지 않은 결과 정책은 «새 행을 쓰지 않음»으로).
5. `scripts/verify.sh`가 통과하는지 본다.
