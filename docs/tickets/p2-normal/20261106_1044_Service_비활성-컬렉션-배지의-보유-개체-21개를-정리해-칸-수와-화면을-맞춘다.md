# [Service] 비활성 컬렉션 배지의 보유 개체 21개를 정리해 칸 수와 화면을 맞춘다

## 핵심 요약

- 요구사항(사용자 2026-11-06): staging의 `sihyunrr@gmail.com` 인벤토리에 8개만 보이는데 «10/10 가득 찼어요» 안내가 나온다. 비활성 컬렉션의 배지는 안 보이는 게 맞으니 컬렉션을 켜지 말고 개체를 정리한다. 범위는 «5명 전체 정리».
- 결과: 5개 계정의 개체 21개를 소프트 파괴하고 칸 수를 맞췄다. 이 계정은 10/10에서 8/10이 되어 화면의 8개와 같다. DB만 바꿨고 코드 변경은 없다.
- 관련 파일: `jam-web/supabase/migrations/325_cleanup_inactive_collection_held_items.sql`, 되돌림 `325_cleanup_inactive_collection_held_items_down.sql`.

## 배경 / 문제 정의

- 화면(`jam-web/src/app/(main)/inventory/page.tsx` 47~54행)은 칸 수를 `inventory.used_slots`로 세고, 그리드는 `item.badge`가 읽히는 개체만 그린다.
- `badges`의 읽기 정책(`badges: 전체 읽기 허용`)은 아이템 배지를 «`item_book_id`가 NULL이거나 컬렉션이 `is_active`이고 `valid_from`이 지났을 때만» 읽게 한다. 어드민에서 끈 컬렉션(`item_books.is_active = false`)의 배지는 사용자 화면에서 숨겨진다.
- 이미 받은 개체는 칸을 그대로 차지한다. 이 계정은 장착되지 않은 개체 10개 중 `매운 컵라면`(편의점 심야 만찬)·`파우치`(열쇠고리를 단 가방) 2개가 비활성 컬렉션 소속이라 화면에서 사라지고 칸만 찼다. 5개 계정에 같은 개체가 21개 있었다.
- 이 개체들은 대부분 오늘(2026-11-06 오전 10시대 KST) 월드 드랍에서 주운 것이다(`poi_drops.picked_up_at`). 컬렉션이 꺼진 뒤에도 드랍이 남아 있다는 뜻이며 후속 티켓 20261106_1052가 다룬다.

## 결정 / 검토한 대안

- **배지 일괄 비활성화(`deleted_at`)는 하지 않았다.** 사용자가 처음 지시했으나 실행 전에 멈추고 근거를 보였다. 대상이 54개 컬렉션의 배지 1,431개(보유 개체 924개)이고, 이 컬렉션들은 오픈 계획의 예약 컬렉션이라 오픈 때 `is_active` 하나로 켜게 돼 있다(292). 배지를 폐기하면 컬렉션을 켜도 배지가 살아나지 않는다. 또 `deleted_at`은 개체와 칸 수를 건드리지 않아 이 증상을 풀지 못한다.
- **읽기 정책에 «가진 개체는 보이게» 예외를 두는 안**: 제안했으나 사용자가 «비활성 컬렉션이면 배지도 안 보이는 게 맞다»고 정해 채택하지 않았다.
- **채택: 개체 소프트 파괴.** 조합 소모·만료·어드민 폐기와 같은 방식(`destroyed_at`, `inventory_id = NULL`)이고 행과 보관 이력은 남는다. 일련번호는 풀로 돌아간다.
