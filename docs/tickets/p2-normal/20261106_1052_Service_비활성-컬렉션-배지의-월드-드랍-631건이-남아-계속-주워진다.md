# [Service] 비활성 컬렉션 배지의 월드 드랍 631건이 남아 계속 주워진다

## 핵심 요약

- 현상: 어드민에서 끈 컬렉션(`item_books.is_active = false`)의 아이템 배지가 월드에 아직 떨어져 있고(`poi_drops.is_available = true`), 사용자가 주우면 화면에 보이지 않는 개체가 칸만 차지한다.
- 규모(2026-11-06 측정): 시스템 드랍 611건(컬렉션 7개, 2026-09-03~10-02 생성), 사용자 드랍 20건(컬렉션 4개, 2026-09-08~11-05 생성). 이 계정은 오늘 오전 10시대에 비활성 컬렉션 개체 2개를 주워 10/10이 됐다.
- 필요한 결정: 이 드랍을 만료시킬지, 주울 때 막을지, 컬렉션이 켜질 때까지 두되 칸에서 세지 않을지(사용자 판단 필요). 예약 컬렉션은 오픈 때 켜는 계획이라(292) 배지는 폐기하지 않는다.

## 배경 / 문제 정의

- 부모 티켓 20261106_1044에서 비활성 컬렉션 배지의 보유 개체 21개를 정리했다. 정리해도 월드 드랍이 남아 있으면 같은 일이 되풀이된다.
- 읽기 정책이 비활성 컬렉션 배지를 숨기므로 사용자는 주운 개체를 볼 수 없다. 픽업 RPC(`pickup_drop`)와 드랍 생성이 컬렉션 활성 여부를 보지 않는 것이 원인으로 보이나 아직 코드를 읽어 확인하지 않았다.

## 검토 거리

- 만료: `poi_drops`를 `is_available = false` 처리하거나 개체를 파괴한다(되돌릴 수 없는 쪽에 가까우므로 백업 필요).
- 픽업 차단: 비활성 컬렉션 배지의 드랍은 줍지 못하게 한다. 컬렉션을 켜면 바로 다시 주울 수 있어 오픈 계획과 맞는다.
- 드랍 생성 단계에서 비활성 컬렉션 배지를 거르는지 확인한다(어드민 `itemPaths`의 `collectionInactive` 판정은 있으나 시스템 드랍 생성 경로는 미확인).
- 정책 문서와 어드민 정책 대시보드(`policiesData.ts`)의 해당 항목을 함께 갱신한다.

## 잔여 이슈

- 아직 어떤 방안도 정하지 않았다. 사용자 결정을 기다린다.
- 관련: 20261005_1151(공개 전 배지가 로그인 유저의 직접 조회에 보인다), 292(예약 컬렉션 끄기).
