# [UI] 챕터 오름 전체 화면 카드를 제거한다

## 핵심 요약

- 요구사항(사용자 2026-11-06, 티켓 20261106_1028의 확인 질문에 «함께 제거»): 챕터가 오를 때 화면을 열면 한 번 뜨는 전체 화면 축하 카드(`ChapterRiseOverlay`)와 그것을 띄우는 감시자(`ChapterRiseWatcher`)를 없앤다. 합친 연출이 사라지면서 이 카드가 그 자리를 이어받아 뜨게 되는 것을 막는 것이 목적이다.
- 지키는 것: 챕터가 오르는 서버 처리(`lib/chapter/rise.ts`의 `processChapterRise`, 오름 배지·알림 `chapter_up` 생성), 알림 목록의 «챕터 오름» 행, 프로필의 챕터 표기(`ChapterLine`, `d.chapter.line`), `user_chapters` 표.
- 관련 파일(지도):
  - 삭제: `jam-web/src/components/chapter/ChapterRiseOverlay.tsx`, `ChapterRiseWatcher.tsx`, `components/chapter/__tests__/ChapterRiseOverlay.test.tsx`, `ChapterRiseWatcher.test.tsx`.
  - `jam-web/src/app/(main)/layout.tsx`: `ChapterRiseWatcher` 가져오기(17행)와 그리는 줄(153행), 그것만을 위한 챕터 읽기와 `parseChapterNo`(18·97행 근처의 `user_chapters` 조회)를 걷는다. 챕터 번호를 다른 곳이 쓰는지 아현이 확인하고, 쓰지 않으면 조회도 지운다. 시험 `app/(main)/__tests__/layout.chapter.test.tsx`(«챕터 행이 있으면 ChapterRiseWatcher…» 계열)·`layout.tribe-gate.test.tsx`(108행 모의)를 맞춘다.
  - `jam-web/src/lib/chapter/celebrate.ts`(`claimChapterRise`·`parseChapterNo`·`StorageLike`)와 `lib/chapter/__tests__/celebrate.test.ts`: 호출부가 없어지면 지운다. 다른 곳이 쓰면 그 부분만 남긴다.
  - `jam-web/src/lib/i18n/ko.ts` 약 469행 `d.chapter.rise` 블록(카드 전용 4개 키)을 지운다. `d.chapter.line`과 `d.notifications`의 chapter_up은 남긴다.
  - `jam-web/src/components/StravaConnectReveal.test.tsx` 5행과 `app/(main)/missions/[id]/MissionDetailClient.claim.test.tsx`의 `ChapterRise*` 언급은 낡은 주석 여부를 확인하고 필요하면 고친다.
  - 문서: `docs/service/prd/chapter/PRD.md`(frontmatter `code:` 21·22행과 «누가 정하나»·«모양(`ChapterRiseOverlay`)» 절 약 162~175행), `docs/service/writing/UX_WRITING_GUIDELINE.md`의 챕터 오름 카드 문구 절, `docs/service/prd/home-feed/PRD.md`·`02_DATA_MODEL.md`·`notification/DATA_MODEL.md`의 카드 서술, `jam-web/src/lib/admin/policyDashboard/policiesData.ts`의 챕터 오름 연출 항목.

## 배경 / 문제 정의

티켓 20261106_1028에서 캡슐 자동 열림의 합친 연출(오렌지 전체 화면 퍼짐·문구 화면·배지 보상 화면)을 걷었다. 합친 연출은 챕터 번호도 보여 주면서 챕터 오름 카드가 같은 오름을 중복으로 띄우지 않게 막고 있었다. 연출이 없어지면 챕터가 오를 때 이 카드가 전체 화면으로 뜬다. 사용자가 이 카드도 함께 없애라고 했다.

## 상세 요구사항

### UI/UX 관점
- 챕터가 올라도 어떤 화면에서도 전체 화면 축하 카드가 뜨지 않는다. 오름 사실은 알림 목록의 «챕터 오름» 행과 프로필의 챕터 표기로만 보인다.
- 오름 배지 지급과 `chapter_up` 알림 생성은 그대로다.

### 데이터
- DB 변경 없음. `user_chapters`는 그대로 쓰이며 읽기만 줄어들 수 있다.

## 구현 계획

1. `layout.tsx`에서 감시자 그리기와 가져오기, 그것만을 위한 챕터 조회를 걷고 레이아웃 시험을 맞춘다.
2. `ChapterRiseOverlay`·`ChapterRiseWatcher`와 시험을 지운다.
3. `celebrate.ts`와 시험을 지우거나(호출부 없음), 남는 호출부가 있으면 해당 부분만 남긴다.
4. `ko.ts`의 `d.chapter.rise`를 지우고 `git grep`으로 참조 0건을 확인한다.
5. 문서와 `policiesData.ts`를 맞춘다(챕터 PRD의 카드 절은 «카드 없음, 오름은 알림 행과 프로필 표기로만»으로).
6. `scripts/verify.sh` 통과를 확인한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `ChapterRiseOverlay`·`ChapterRiseWatcher`·`d.chapter.rise`를 가져오거나 쓰는 코드가 `git grep`으로 0건이다(문서 이력 제외). 레이아웃은 감시자를 그리지 않고, 감시자만 쓰던 챕터 조회가 남지 않는다.
- `processChapterRise`·오름 배지·`chapter_up` 알림·프로필 챕터 표기(`ChapterLine`)·`d.chapter.line`은 바뀌지 않는다.
- `scripts/verify.sh` 통과. 문구 추가가 없어 UX Writing 점검은 «문구 불변·삭제» 확인으로 갈음한다.

### 후속 범위 (담당·시점)
- staging 실렌더(카리나, 머지 뒤): 232 계정 홈·프로필에서 챕터 오름 전체 화면 카드가 뜨지 않고 프로필 챕터 표기가 그대로인지 확인한다.
