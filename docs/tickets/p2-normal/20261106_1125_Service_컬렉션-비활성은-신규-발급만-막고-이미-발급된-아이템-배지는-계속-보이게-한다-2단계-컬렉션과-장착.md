# [Service] 컬렉션 비활성은 신규 발급만 막고 이미 발급된 아이템 배지는 계속 보이게 한다 (2단계: 컬렉션과 장착, 상위)

## 핵심 요약

- **한 줄 정의**: 컬렉션 비활성은 «새 아이템 배지 발급 중단 + 둘러보기에서 내림»이다. 이미 발급된 상태(보유·장착·완성·월드 드랍)는 켜진 컬렉션과 똑같이 보이고 똑같이 쓸 수 있다. 오픈 전 비밀 유지는 고려하지 않는다(사용자 2026-11-06).
- 기획서는 2026-11-06 혜린(`jam-pm`) 문답 5개와 사용자 승인으로 확정했다. **판단: 만들자.** 크기는 하위 티켓 6개이고, 이 중 T1만 DB 유형이라 사용자 확인 뒤 실행한다.
- 1단계(`20261106_1124`, 마이그레이션 327)는 완료했다(`badges` 읽기 정책 예외, 발급 기록 표 `issued_item_badges`).

## 하위 티켓 (순서대로)

| 순서 | 티켓 | 유형 | 선행 | 보이는 동작 |
|---|---|---|---|---|
| T1 | `20261106_1227` 컬렉션 단위 발급 기록 표와 읽기 정책 | **db** | 없음 | 개체를 가진 사람이 꺼진 컬렉션과 그 칸 전체를 읽는다 |
| T2 | `20261106_1228` 비활성 컬렉션 상세에서 모든 칸이 보이게 한다 | ui | T1 | 꺼진 컬렉션을 열면 칸 전체가 보인다 |
| T3 | `20261106_1229` 가진 개체를 비활성 컬렉션에 장착하고 완성 보상을 받게 한다 | api | T2 | 마지막 칸을 채우면 완성 기록과 보상이 나간다 |
| T4 | `20261106_1230` 내 컬렉션 목록과 배지 상세 카드에 비활성 컬렉션이 나오게 한다 | ui | T1, T2 | 내 화면 세 곳에 꺼진 컬렉션이 나온다 |
| T5 | `20261106_1231` 다른 사람 프로필에서도 비활성 컬렉션이 보이게 한다 | ui | T2 | 팔로워가 보는 프로필에 꺼진 컬렉션이 나온다 |
| T6 | `20261106_1232` 컬렉션 비활성과 드랍 제외 어드민 문구와 정책 대시보드를 바꾼다 | admin | T3, T4, T5 | 운영자가 «끄면 신규만 멈춘다»고 읽는다 |

- **실행 방법**: T1이 `db`라 묶음 실행은 T1 앞에서 멈춘다. T1은 단독 호출로 사용자 확인과 적용을 받고, 그 뒤 T2부터 묶음(`batch`)으로 순차 실행한다. 이유: T2 이후가 모두 T1의 읽기 정책에 기대고, 1단계에서 게이트가 성능을 보지 못해 재작업한 선례가 있다. T4·T5는 T3와 독립이지만 같은 `visibility.ts`를 만지므로 순차로 둔다.
- 배포는 staging만 나가고 main 배포는 출시 전까지 멈춰 있다(2026-10-15 결정). 중간 단계가 사용자에게 보이지 않아도 순서는 «읽기 정책 → 판정 → 장착 → 목록 → 프로필 → 문구»로 두어 문구가 실제 동작을 앞서지 않게 한다.

## 기획서

### 문제와 대상
- 지금은 꺼진 컬렉션의 개체를 가진 사람이 그 컬렉션 화면·프로필 탭·배지 상세 카드를 못 보고 장착도 못 한다(이미 받은 것을 잃은 것처럼 보인다). 어드민 문구도 «화면 노출 자체를 끄는 강한 토글»이라 실제 뜻과 다르다.
- 대상: 꺼진 컬렉션에 개체를 꽂은 사용자 3명(사용자·컬렉션 짝 36개, 2026-11-06 실측), 앞으로 컬렉션이 꺼질 때의 보유자, 그 사람의 프로필을 보는 다른 사용자, 어드민 운영자.

### 동작 정의
- **노출 판정은 셋이다**(`jam-web/src/lib/itembook/visibility.ts`). 공개됨(켜짐 + 시작됨): 둘러보기·홈 카드·신규 노출용. 노출 중(공개됨 + 기간 안): 드랍·완성 판정·소식·배치용(지금 그대로). **열람 가능(신규) = 공개됨 OR 그 컬렉션에 발급 기록이 있음**: 컬렉션 상세, 장착, 가진 사람의 화면용.
- 가진 사람 기준 목록(내 컬렉션, 프로필 탭, 배지 상세 카드, 다른 사람 프로필)은 «개체를 가졌다 = 발급 기록이 있다»라서 공개됨 필터를 뺀다. 내 컬렉션 목록은 «공개됨 컬렉션 ∪ 내가 개체를 가진 컬렉션»이다.
- 컬렉션 상세는 열람 가능 컬렉션의 **모든 칸**을 읽는다. 그래서 컬렉션 단위 발급 기록이 필요하다(T1).
- 장착은 `POST`의 공개됨 검사를 열람 가능으로 바꾼다. 해제(`DELETE`)·교체(`PATCH`)·일괄 해제는 이미 노출 검사가 없어 그대로 둔다. 완성 기록·등급별 포인트·챕터 점수·보상 배지는 장착 RPC와 `slotReward.ts`가 노출을 보지 않아 자동으로 따라온다.
- 꺼진 컬렉션 표시·별도 문구·안내는 두지 않는다(화면 문구는 켜진 컬렉션과 같다).
- 어드민 문구: 비활성 =「새 아이템 배지의 발급을 멈추고 둘러보기 목록에서 내려요. 이미 받은 사람에게는 계속 보여요.」 드랍 제외 =「새 개체가 드랍되는 것만 멈춰요. 목록과 화면은 그대로예요.」

### 범위 밖(하지 않는 일)
꺼진 컬렉션 표시·라벨 / `drop_excluded` 로직 변경 / 완성 가능 소식·티어 승급 후보·배치 알림·홈 카드·오늘의 현황의 대상 확대 / 보상 수치 변경 / 시뮬레이터 신규 작성 / 드랍·민트·조합 쪽 로직 변경 / 직접 주소 차단 장치.

### 사용자 결정 기록 (2026-11-06)
- 비활성 = 신규 발급 막음. 이미 발급된 상태는 모두 보이고 쓸 수 있다. 오픈 전 비밀 유지는 고려하지 않는다.
- 가정 7개 확정: 내 화면 3곳 노출, 가진 것 없는 사람에게 목록 비노출, 직접 주소 차단 없음, 장착 가능, 완성 기록, 소식·승급 후보·배치 알림 제외, `drop_excluded` 무변경, **팔로워 프로필에서도 그 사람이 가진 꺼진 컬렉션 노출**.
- 질문 1 = A: 꺼진 컬렉션 완성 보상을 기간이 끝난 컬렉션과 똑같이 그대로 지급. 질문 2 = D: 모든 칸 표시(못 얻은 칸은 티켓 20261102_1834의 회색 실루엣 + 이름). 질문 3 = A: 꺼진 표시 없음. 질문 4: 화면 문구는 켜진 컬렉션과 같게. 질문 5 = A: 어드민 문구 두 개(위).
- **정정(사용자)**: «회색 윤곽»은 그림 안의 투명한 부분을 뺀 불투명 부분의 윤곽이다(기존 구현과 같은 뜻이며 새 규칙이 아니다).
- 열린 질문(착수 전) 3개를 **추천대로** 확정: ① `checker.ts`(보상 배지 발급 실패 따라잡기)는 건드리지 않고 꺼진 컬렉션의 사각을 받아들인다(완료 기록에 명시, 필요하면 수동 보정). ② 다른 사람 프로필에서 기간이 끝난 컬렉션도 함께 보이게 맞춘다. ③ 홈 카드와 오늘의 현황은 꺼진 컬렉션을 계속 제외한다(가진 사람의 홈 현황에서 꺼진 컬렉션 진행도가 빠지는 것은 의도된 결과).

### 검토한 대안 (컬렉션 읽기 방식)
- (가) `item_books` 정책이 `badges`와 조인해 «발급된 배지가 있는가»를 보게 하는 안: 두 정책이 서로를 참조해 무한 재귀 위험과 조인 비용이 있어 폐기.
- (나) 정책 안에서 행마다 함수 호출: 1단계 측정(컬렉션 33개 조회 2.0→9.7ms)으로 폐기.
- (다) DB 변경 없이 컬렉션 상세만 서비스 키로 읽는 안: 배지 상세 카드·`/api/itembooks`·`/badges` 탭이 로그인 권한으로 컬렉션을 읽어 정책이 어차피 필요하고, 경로마다 권한 판단이 갈려 어긋날 위험이 커서 폐기.
- **(라) 채택**: 보조 표 `issued_item_books(item_book_id PK)`를 `inventory_items` INSERT 트리거로 채우고(배지→`item_book_id`), 배지의 `item_book_id`가 바뀔 때도 트리거로 기록한다(어드민 `assign` 경로, `api/admin/badges/[id]/assign/route.ts` 16행). `item_books`·`badges` 읽기 정책이 이 표를 `EXISTS`(PK 조회)로 본다. 1단계와 같은 방식이다. 트리거가 `SECURITY DEFINER`라 재귀가 없다.

### 리스크
- **경제 균형**: 실측(2026-11-06 DB)은 꺼진 컬렉션 91개 중 완성 보상이 걸린 것이 10개(등급형 보상 0개), 꺼진 컬렉션에 개체를 꽂은 사용자가 3명(짝 36개), 이미 기록된 완성이 2건(재지급 없음)이다. 신규 완성이 나올 수 있는 범위는 이 3명이 마저 채우는 경우로 좁다(신규 개체가 안 나오기 때문, T1의 «개체 생성 경로» 확인으로 확정). 챕터 점수 «컬렉션 완성»도 컬렉션당 1회다. **총 지급 상한과 시뮬레이터 검증은 미검증**이다. 완성 보상이 걸린 10개 컬렉션의 포인트·보상 배지 × 보유 사용자 수를 카즈하가 계산해 T3 착수 전에 사용자에게 보인다.
- **이미지 현실(2026-11-06 실측, 질문 2·S2와 연결)**: 꺼진 컬렉션의 아이템 배지 1,431개 중 이미지가 등록된 것은 171개, 한 번도 발급된 적 없는 칸 1,256개 중 이미지가 없는 것이 1,167개, 있는 것이 89개다. 그래서 새로 보이는 칸 대부분은 «메달 아이콘 + 이름»이고, 이미지가 있는 칸 중 배경이 불투명한 것은 윤곽 대신 회색 사각형으로 보인다(티켓 20261102_1834·20261102_2246의 기존 한계, 이번 범위에서 바꾸지 않는다).
- **유저가 이미 학습한 규칙의 변경**: 꺼진 컬렉션이 «사라짐»에서 «그대로 있음»으로 바뀐다. 이미 받은 사람에게는 복구에 가깝다.
- **운영 부담**: 어드민이 «끄면 다 숨겨진다»고 오해하지 않도록 T6에서 문구를 바꾼다. 꺼 둔 컬렉션이 91개라 첫 적용 직후 변화가 크지만 새로 보이는 곳은 위 3명 범위다.
- **DB 성능**: 1단계에서 정책 안 함수 호출이 조회를 크게 늦췄다. 이번에도 «작은 표 + EXISTS(PK)»만 쓰고, 게이트가 성능을 보지 못하므로 카리나가 `authenticated` 권한으로 전후를 측정한다(S7).
- **비용·개인정보**: 표 1개와 트리거 2개(개체 INSERT마다 PK 조회 한 번). 개인정보 영향 없음. 잠긴 개체 규칙(운영 로직 7.3절)은 사용자별로 컬렉션을 드러내지 않게 하는 것이며 컬렉션 단위 발급 기록은 전역 정보라 영향이 없다(T2에서 잠긴 개체만 가진 사용자의 화면이 그대로인지 시험에 넣는다).

### 가정
- 확인됨: 위 결정 전부, 1단계 읽기 정책 구조, 컬렉션 읽기 정책(마이그레이션 215)의 현재 본문, 컬렉션 상세가 배지를 로그인 권한으로 읽는 것(`collections/[id]/page.tsx` 110행), 장착 `DELETE`·`PATCH` 무검사, 다른 사람 프로필 두 곳이 서비스 키로 읽고 `is_active`·`valid_until`을 거르는 것, 어드민이 배지의 `item_book_id`를 옮기는 경로(`assign`), 완성 기록은 한 번만 만들어져 재지급되지 않는 것.

### 남은 열린 질문 (나중에 정해도 됨)
- 직접 주소의 노출 범위: 발급 기록이 있는 꺼진 컬렉션은 가진 것 없는 사람에게도 칸 전체가 보인다(결정). 막으려면 읽기 정책이 아니라 화면에서 «가진 것이 없으면 404»를 더하는 별도 티켓이다.
