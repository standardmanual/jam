# [Service] 컬렉션 단위 발급 기록 표와 읽기 정책을 만든다 (2단계 T1, db)

## 핵심 요약

- 요구사항: 개체가 한 번이라도 만들어진 컬렉션은 비활성이어도 개체를 가진 사람(과 누구나)이 컬렉션과 **그 컬렉션의 모든 칸(배지)** 을 읽을 수 있게 한다. 상위 티켓 20261106_1125의 «열람 가능 = 공개됨 OR 발급 기록 있음»의 DB 쪽이다.
- 구현 계획(요지): 보조 표 `issued_item_books`를 만들고, `inventory_items` INSERT 트리거와 배지의 `item_book_id` 변경 트리거로 채우며, 기존 개체로 백필하고, `item_books`·`badges` 읽기 정책이 이 표를 `EXISTS`(PK 조회)로 보게 한다.
- 선행: 없음. **체크포인트: 유형이 `db`라 `/jam-work`가 자동 진행하지 않는다.** 단독 호출로 사용자 확인을 받고, DB 실행은 카리나(메인 세션)가 드라이런·성능 측정과 함께 한다. 아현은 SQL 파일 작성까지만 한다.
- 크기 상한: 파일 약 4~5개(마이그레이션·되돌림·생성 타입·`02_DATA_MODEL.md` 등). `plan_only` 임계값(파일 5개 초과 또는 100줄 이상) 근처라 카리나가 파일 단위 계획과 함께 `planOnlyWaiver`를 넣을지 판단한다.

## 배경 / 문제 정의

- 현재 `item_books` 읽기 정책은 `is_active = true AND (valid_from IS NULL OR valid_from <= now())`(마이그레이션 215)이고 `badges`는 1단계(327)로 `item_book_id IS NULL OR 컬렉션 노출 OR EXISTS(issued_item_badges)`이다. 그래서 꺼진 컬렉션은 가진 사람에게도 읽히지 않고, 개체가 만들어진 배지만 읽혀 **컬렉션 안의 나머지 칸은 숨는다**.
- 컬렉션 상세(`jam-web/src/app/(main)/collections/[id]/page.tsx` 110행)는 `badges`를 로그인 권한으로 읽어, 그대로 두면 읽히는 칸만 남아 칸 수와 분모가 줄고 **«2칸 중 2칸 완성»** 같은 가짜 완성이 보일 수 있다. 서버 완성 판정은 전체 칸을 센다.
- 정책을 설계할 때는 1단계 교훈을 따른다(메모리 `feedback_rls_policy_cost_measure_as_authenticated`): 정책 안에서 행마다 함수를 부르면 컬렉션 33개 조회가 2.0→9.7ms로 느렸다. **작은 보조 표를 `EXISTS`(PK)로 보는 방식만 쓴다.**

## 상세 요구사항

### 데이터/DB 관점
- 새 표 `public.issued_item_books (item_book_id uuid PRIMARY KEY REFERENCES public.item_books(id) ON DELETE CASCADE, first_issued_at timestamptz NOT NULL DEFAULT now())`. RLS를 켜고 읽기 정책 하나만 둔다(`FOR SELECT TO authenticated USING (true)`). 쓰기 정책은 두지 않는다.
- 백필: `INSERT INTO public.issued_item_books (item_book_id) SELECT DISTINCT b.item_book_id FROM public.inventory_items ii JOIN public.badges b ON b.id = ii.badge_id WHERE b.item_book_id IS NOT NULL ON CONFLICT DO NOTHING`. 적용 시점의 행 수를 기록한다.
- 트리거 ①: `inventory_items` `AFTER INSERT FOR EACH ROW`가 `NEW.badge_id`의 `item_book_id`(NULL이면 건너뜀)를 `ON CONFLICT DO NOTHING`으로 기록한다. 함수는 `SECURITY DEFINER`, `SET search_path TO 'public'`, `REVOKE ALL … FROM PUBLIC, anon, authenticated`(1단계 교훈: 기본 부여된 `anon`·`authenticated` 권한까지 회수).
- 트리거 ②: `badges` `AFTER UPDATE OF item_book_id`가 새 `item_book_id`가 NULL이 아니고 그 배지가 `issued_item_badges`(1단계 표)에 있을 때 새 컬렉션을 기록한다. 어드민이 발급된 배지를 다른 컬렉션으로 옮기는 경로(`jam-web/src/app/api/admin/badges/[id]/assign/route.ts` 16행)를 위한 것이다.
- 읽기 정책 교체(`DROP POLICY` 후 `CREATE POLICY`, 한 트랜잭션): ① `item_books`: 기존 조건 `(is_active = true AND (valid_from IS NULL OR valid_from <= now()))`을 글자 그대로 첫 조건으로 두고 `OR EXISTS (SELECT 1 FROM public.issued_item_books s WHERE s.item_book_id = item_books.id)`를 더한다. ② `badges`: 1단계 조건의 세 번째 항(`EXISTS issued_item_badges`)을 `EXISTS (SELECT 1 FROM public.issued_item_books s WHERE s.item_book_id = badges.item_book_id)`로 바꾼다(컬렉션 단위 조건이 배지 단위 조건의 상위 집합이다). 두 정책 모두 현재 본문과 대상 역할을 `pg_policies`로 읽어 첫 조건을 글자 그대로 둔다. `issued_item_books`만 참조하므로 정책끼리 서로를 부르는 재귀는 없다.
- 1단계의 `issued_item_badges` 표와 트리거는 **지우지 않는다**(재시험 부담을 줄이고, 정리는 성능 측정 뒤 후속으로).
- 되돌림 SQL: 정책 두 개를 옛 본문으로 복원한 뒤 트리거 둘·트리거 함수·표를 지운다(정책을 먼저 복원). 번호는 328(원격 최신 327)이며 push 직전에 `origin/staging` 기준으로 다시 확인한다.

### 서비스/코드베이스 관점
- 서비스 코드 변경 없음(읽기 정책만). 아현은 개체가 새로 생기는 모든 경로(드랍·민트·조합·캡슐·어드민 재배정)가 `inventory_items` INSERT로 모이는지 코드로 확인해 요약에 적는다(INSERT 외의 경로가 있으면 트리거를 맞춘다).
- 생성 타입: 카리나가 MCP로 받아 새 표 `issued_item_books` 한 블록만 `jam-web/src/types/database.generated.ts`에 더한다(전체 덮어쓰기 금지, 현재 파일은 이번 변경과 무관하게 최신 DB와 어긋나 있다).
- 문서: `docs/service/prd/02_DATA_MODEL.md`에 `issued_item_books` 표·두 트리거·`item_books`/`badges` 읽기 정책을 적는다(정본). 운영 로직 문서에는 한 줄 참조만.

## 구현 계획

1. `jam-web/supabase/migrations/328_issued_item_books.sql`(신규): 표·RLS·백필·트리거 2개·정책 2개 교체. 헤더 주석에 왜·하는 일·하지 않는 일(1단계 표 유지, 신규 발급 로직 불변, 직접 주소 차단 없음)을 적고 `BEGIN`/`COMMIT`으로 감싼다. 파일 끝에 검증 쿼리 주석.
2. `jam-web/supabase/migrations/328_issued_item_books_down.sql`(신규): 위 되돌림.
3. `docs/service/prd/02_DATA_MODEL.md` 갱신.
- 카리나(4단계): 드라이런(적용→측정→되돌림→원상 대조→예외로 전부 취소, `authenticated`·`god` 계정), 실행, 적용 후 성능 재측정, 읽기 전용 사후 확인, 생성 타입 반영, staging 확인.

## 완료 조건

- 마이그레이션·되돌림 짝 파일이 있고 `deploy-gate`가 이 파일에 대해 통과한다. 두 정책의 첫 조건은 현재 본문과 글자 그대로 같다.
- 드라이런에서 적용 전후와 되돌림 후 정책 본문 원상이 확인된다.
- `authenticated`로 읽을 때: 개체가 있는 꺼진 컬렉션은 `item_books`에서 읽히고 그 컬렉션의 모든 배지(삭제 제외)가 읽힌다. **개체가 한 번도 없는 꺼진 컬렉션과 그 배지는 읽히지 않는다**(노출 0건). 백필 행 수를 기록한다.
- 트리거 시험(취소되는 트랜잭션): ① 발급 기록 없는 꺼진 컬렉션의 배지로 개체를 만들면 그 컬렉션이 기록되고 읽힌다. ② 발급된 배지를 다른 컬렉션으로 옮기면 새 컬렉션이 기록된다. 권한 회수 뒤에도 트리거가 돈다.
- 성능(S7): `authenticated` 권한으로 컬렉션 33개의 아이템 배지 조회가 적용 후 **3.0ms 이하**(적용 전 2.3ms)이고, 배지 전체 읽기·컬렉션 목록 읽기·개체 INSERT 오버헤드의 전후 값이 완료 기록에 있다.
- 새 트리거 함수의 `proacl`에 `anon`·`authenticated`가 없다. 생성 타입 반영 뒤 `npm run typecheck`가 통과한다.
