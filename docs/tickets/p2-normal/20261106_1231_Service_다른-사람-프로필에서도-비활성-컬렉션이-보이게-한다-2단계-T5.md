# [Service] 다른 사람 프로필에서도 비활성 컬렉션이 보이게 한다 (2단계 T5)

## 핵심 요약

- 요구사항(사용자 가정 7): 팔로워(다른 사용자)가 보는 프로필의 컬렉션 탭에서도 **그 사람이 가진 컬렉션**이 꺼진 것이어도 보인다.
- **열린 질문 결정(사용자 추천대로)**: 프로필에서 **기간이 끝난 컬렉션도 함께 보이게 맞춘다.** 지금은 내 화면에서는 끝난 컬렉션이 계속 보이는데(결정 E1) 다른 사람 프로필 두 곳만 `valid_until` 조건으로 숨긴다. 이 불일치를 같은 수정에서 맞춘다.
- 구현 계획(요지): 프로필 두 곳의 컬렉션 조회에서 `is_active`·`valid_from`·`valid_until` 조건을 뺀다(그 사람이 슬롯을 가진 컬렉션은 모두 보인다). 프로필의 컬렉션 개수 통계가 같은 기준인지 대조한다.
- 선행: T2. 서비스 키 경로라 T1과는 독립이지만 순서상 뒤에 둔다. 크기 상한: 파일 약 4개.

## 배경 / 문제 정의

- `jam-web/src/app/api/users/[username]/itembooks/route.ts` 78~84행과 `jam-web/src/app/(main)/[username]/collections/page.tsx` 105~110행이 서비스 키로 `item_books`를 읽으며 `.eq('is_active', true)`, `valid_from`, `valid_until` 조건을 건다. 그래서 다른 사람 프로필에서는 꺼진 컬렉션과 기간이 끝난 컬렉션이 모두 숨는다.
- 프로필 컬렉션 개수 통계(`jam-web/src/app/(main)/[username]/page.tsx` 약 181~188행 `itemBookCount`)가 같은 거름 기준인지 확인이 필요하다(목록과 개수가 어긋나면 안 된다).

## 상세 요구사항

### 서비스/코드베이스 관점
- 프로필 두 곳의 `item_books` 조회에서 `is_active`·`valid_from`·`valid_until` 조건을 뺀다. 거름 기준은 «그 사람이 슬롯을 가진 컬렉션(`user_item_book_slots`)»이다. 이미 읽은 `bookIds`가 그 기준이다(코드 구조를 확인해 같은 기준임을 요약에 적는다).
- `itemBookCount`(`[username]/page.tsx`)도 같은 기준으로 맞춘다.
- 다른 사람 컬렉션 상세를 볼 때의 규칙(`collections/[id]/page.tsx` 203행 «그 사람의 슬롯이 없으면 404»)은 그대로다.
- 서비스 키 읽기라 **개체가 없는 꺼진 컬렉션은 프로필에 애초에 나오지 않는다**(슬롯이 없으므로). 잠긴 개체 규칙(운영 로직 7.3절)과 충돌하지 않는지 시험으로 확인한다.

## 구현 계획

1. `jam-web/src/app/api/users/[username]/itembooks/route.ts`(약 70~90행): 조회 조건 제거, 주석(`컬렉션 노출 판정 = is_active && 노출 기간 내`)을 새 기준으로 고친다.
2. `jam-web/src/app/(main)/[username]/collections/page.tsx`(약 95~112행): 같은 수정.
3. `jam-web/src/app/(main)/[username]/page.tsx`(약 181~188행): 개수 통계 기준 대조·수정.
4. 시험: 각 파일의 기존 시험에 «꺼진·기간이 끝난 컬렉션도 그 사람이 슬롯을 가졌으면 프로필에 나옴», «슬롯이 없으면 나오지 않음», «목록 항목 수 = 통계 개수»를 더한다.
5. 문서: `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md`에 «프로필의 컬렉션은 그 사람이 가진 것이면 꺼졌거나 기간이 끝났어도 보인다» 한 줄.

## 완료 기록 (2026-11-06 KST)

### 구현 내용 요약
- 다른 사람 프로필의 컬렉션 탭(`[username]/collections/page.tsx`), `/api/users/[username]/itembooks`, 프로필 컬렉션 개수 통계(`[username]/page.tsx`의 `itemBookCount`) 세 곳에서 `item_books` 조회의 `is_active`·`valid_from`·`valid_until` 조건을 모두 뺐다. 쓰지 않게 된 `now` 변수와 옛 주석도 새 기준으로 고쳤다.
- 거름 기준은 세 곳 모두 «그 사람이 잠기지 않은 상태로 가진 아이템 배지(`inventory_items`: `dropped_at` null, `locked=false`, 삭제 안 된 `type='item'` 배지)가 속한 컬렉션»(`bookIds`/`bookIdsForCount`)에서 시작한다. 타인 열람은 목록이 `slottedCount > 0`, 통계가 슬롯 행 유무로 한 번 더 거르고, 내 열람은 거르지 않는다. 그래서 목록과 통계의 기준이 같다. 잠긴 개체만 가진 컬렉션은 `locked=false` 조건 때문에 애초에 빠져 운영 로직 7.3절과 충돌하지 않는다.
- **열린 질문 2의 결정(사용자 추천대로, 2026-11-06)**: 프로필에서 기간이 끝난 컬렉션과 시작 전 컬렉션도 꺼진 컬렉션과 함께 보이게 맞췄다. 내 화면에서는 끝난 컬렉션이 이미 계속 보였던(결정 E1) 불일치를 해소한다.
