# [Admin] 컬렉션 비활성과 드랍 제외 어드민 문구와 정책 대시보드를 바꾼다 (2단계 T6)

## 핵심 요약

- 요구사항(사용자 질문 5 = A, 문구 그대로): 어드민에서 컬렉션의 활성 스위치와 드랍 제외 스위치를 읽는 운영자가 새 뜻을 읽게 한다.
  - 비활성 =「새 아이템 배지의 발급을 멈추고 둘러보기 목록에서 내려요. 이미 받은 사람에게는 계속 보여요.」
  - 드랍 제외 =「새 개체가 드랍되는 것만 멈춰요. 목록과 화면은 그대로예요.」
- 구현 계획(요지): 옛 정의(«화면 노출 자체를 끄는 강한 토글», 「더 이상 보이지 않아요」 계열)가 적힌 어드민 문구·주석을 전부 찾아 위 문장으로 교체하고, 정책 대시보드(`policiesData.ts`)의 해당 항목을 같은 문구로 맞춘다. **문구 이외 어드민 UI 변경은 없다**(어드민은 채원 판정 대상 아님).
- 선행: T3, T4, T5(문구가 실제 동작을 앞서지 않게 마지막에 둔다). 크기 상한: 파일 약 4~5개.

## 배경 / 문제 정의

- 어드민은 비활성을 «화면 노출 자체를 끈다»고 안내한다(예: `jam-web/src/app/admin/itembooks/ItemBookForm.tsx` 393·566행 부근의 안내와 확인 문구, `jam-web/src/app/api/admin/itembooks/[id]/drop-exclude/route.ts` 머리 주석 «화면 노출 자체를 끄고 소속 배지를 연쇄 소프트삭제하는 강한 토글»). 이는 이번 결정(비활성 = 신규 발급 중단)과 반대다.
- 두 스위치는 지금도 의미가 겹친다(둘 다 «새로 못 얻는다»). 이번 결정으로 차이가 분명해진다: **비활성은 신규 발급을 멈추고 둘러보기 목록에서도 내리는 것**, **드랍 제외는 드랍만 멈추고 목록은 그대로 두는 것**.

## 상세 요구사항

### 서비스/코드베이스 관점 (어드민)
- 문구 두 개를 **위 글자 그대로** 쓴다(해요체, UX Writing 가이드 `docs/service/writing/UX_WRITING_GUIDELINE.md` 용어 준수).
- 교체 대상(아현이 검색으로 전수 확인): `ItemBookForm.tsx`의 활성 스위치 안내·확인 다이얼로그, `drop-exclude/route.ts` 머리 주석, 컬렉션 목록·일괄 토글의 라벨·확인 문구, `jam-web/src/lib/itembook/visibility.ts` 머리 주석의 옛 서술(T2가 이미 손댔으면 중복 수정하지 않는다), 어드민 컬렉션 상세의 안내.
- 정책 대시보드 `jam-web/src/lib/admin/policyDashboard/policiesData.ts`: 1단계 항목 `ch9-collection-inactive-keeps-issued-visible`의 문구를 «컬렉션 단위 발급 기록» 기준으로 갱신하고, 컬렉션 비활성·드랍 제외 항목이 있으면 같은 문구로 맞춘다(없으면 비활성 의미 항목을 하나 더한다). 정책 대시보드 시험(고유 ID·필수 칸)이 통과해야 한다.
- 문서: `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md`의 컬렉션 절에서 `is_active`와 `drop_excluded`의 차이를 한 줄로 정리한다(정본 서술은 T1의 `02_DATA_MODEL.md`).

## 구현 계획

1. 위 교체 대상 파일들의 문구·주석 수정(문구 이외 로직·스타일 변경 없음).
2. `jam-web/src/lib/admin/policyDashboard/policiesData.ts`: 항목 문구 갱신/추가.
3. `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md`: 한 줄.
4. 검색 확인: 옛 문구(«화면 노출 자체를 끄는 강한 토글», 「더 이상 보이지 않아요」 등 옛 정의를 담은 표현)가 `jam-web/src`와 `docs/service`에 남은 곳이 0건임을 `grep` 결과로 요약에 적는다(과거 완료 기록 티켓은 제외).

## 완료 조건

- 어드민의 비활성 스위치 문구와 드랍 제외 스위치 문구가 확정 문구와 **글자까지 같다**(S8, 글자 대조). 옛 정의를 담은 문구가 서비스 코드·서비스 문서에 0건 남는다.
- 정책 대시보드 항목이 같은 문구로 갱신돼 있고 관련 시험이 통과한다. 문구 외 어드민 UI·로직 변경이 없다. `scripts/verify.sh`가 통과한다.
