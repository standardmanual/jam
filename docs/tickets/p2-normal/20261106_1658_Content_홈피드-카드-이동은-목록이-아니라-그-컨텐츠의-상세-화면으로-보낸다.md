# [Content] 홈피드 카드 이동은 목록이 아니라 그 컨텐츠의 상세 화면으로 보낸다

## 핵심 요약

- 요구사항: (1) 지금 노출 중인 카드 3장의 이동 주소를 고친다. (2) 앞으로 에이전트가 카드를 기획할 때도 «카드가 소개한 그 컨텐츠의 상세 화면으로» 보내도록 지침과 등록 검사를 고친다.
- 구현 계획: 카드 3장은 `today_cards.target_href`만 바꾼다(DB). 지침은 윤진 정의·루틴 절·PRD에 같은 규칙을 한 줄씩 더한다. 등록 검사는 목록 화면(`/badges`·`/missions`·`/collections`)으로 해석되는 카드를 오류로 거절한다.
- 관련 파일: `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts`(`REQUIRED_REFERENCE_FIELDS` 95줄 부근, `target_href` 검사 235줄 부근), `jam-web/src/lib/today/targetHref.ts`(`resolveTargetHref`, 읽기만), `.claude/agents/jam-marketer.md`(모드 ⑨, 37줄), `.claude/skills/jam-work/references/scheduled-jobs.md`(「카드 기획 기준」 행), `.claude/skills/jam-story/references/marketer-home-feed.md`, `docs/service/prd/content-automation/PRD.md`(§6 편성 규칙), `docs/service/prd/home-feed/PRD.md`(§7)

## 배경 / 문제 정의

사용자가 홈피드 카드 3장의 랜딩이 잘못됐다고 알려 왔다(2026-11-06).

| 카드 | 지금 | 가야 할 곳 |
|---|---|---|
| 이번 주 산행, 아이템 배지가 숨은 두 곳 (`location_trend`) | 값이 비어 `/badges`(배지 목록)로 해석됨 | `/drops`(드랍 메뉴) |
| 산에서 보내는 하루 (`content_intro`) | `/badges`(목록) | 「산에서의 하루」 배지 상세 |
| 주말엔 한 번, 10km (`content_intro`) | `/badges`(목록) | 「주말 장거리」 배지 상세 |

원인은 «목록 화면으로 보내면 안 된다»는 규칙이 지침과 등록 검사에 없는 것이다. 윤진 정의 모드 ⑨의 `content_intro` 설명이 이동 주소 예시로 `/badges`·`/collections`·`/missions`를 그대로 나열해 목록 화면이 정답처럼 읽힌다. 같은 이름의 배지가 등급별로 4개씩 있어(`family_key` 동일) 어느 등급 상세로 보낼지도 정해져 있지 않았다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 카드가 소개한 컨텐츠가 하나로 정해지면 그 컨텐츠의 상세 화면(`/badges/{id}`·`/missions/{id}`·`/collections/{id}`)으로 보낸다. 목록 화면은 소개한 컨텐츠가 여럿이거나 상세가 없는 화면일 때만 쓴다.
- 등급형 배지는 카드 문구가 말한 조건과 맞는 등급의 배지로 보낸다(예: «3시간» → 180분 등급, «한 번에 10km» → 1회 등급).
- 숨은 아이템 배지·드랍을 알리는 카드는 드랍 메뉴(`/drops`)로 보낸다.
- 등록 검사: 목록 루트로 해석되는 카드를 오류로 거절한다. `ranking_board`(수동 지정 유저 대상 폴백)·`drop_alert`·`recipe_reveal`·`editorial_article`은 예외다.

### 컨텐츠 관점
- 지금 노출 중이거나 예정인 다른 카드 4장도 같은 문제가 있다(입동 주간 처음 가는 곳으로, 오늘은 입동이에요, 입동에 만나는 활동 배지 「겨울잠」, 송파구 역마다 체크인 배지가 있어요). 사용자가 범위로 말한 3장이 아니므로 이 티켓에서 고치지 않고 사용자에게 보고한다.

## 구현 계획

1. 카드 3장 `target_href` 수정 SQL을 `jam-web/supabase/migrations/`에 기록 파일로 남기고 실행한다(되돌림 SQL 포함). 번호가 붙는 스키마 마이그레이션이 아니다.
2. 지침 4곳에 같은 규칙을 더한다: 윤진 정의 ⑨·⑥, 루틴 절 「카드 기획 기준」, content-automation PRD 편성 규칙, home-feed PRD §7.
3. `homeFeedFields.ts`에 목록 루트 거절 검사를 더하고 시험을 쓴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `homeFeedFields.ts` 검사: `content_intro`가 `target_href: "/badges"`(또는 `/missions`·`/collections`)를 가지면 오류가 나고, `/badges/{uuid}`이면 통과한다.
- 같은 검사: `location_trend`가 `badge_ids`와 `target_href` 둘 다 비면 오류, `target_href: "/drops"`이면 통과한다. `badge_spotlight`가 배지 1개이면 통과, 배지 여러 개이고 `target_href`가 없으면 오류다.
- `ranking_board`·`drop_alert`·`recipe_reveal`·`editorial_article`은 이 검사로 새 오류가 나지 않는다.
- `npx vitest run` 중 `registerFields.test.ts`·`registerInput.test.ts`·`registerHomeFeedBundle.test.ts`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 전 직접)
- DB 카드 3장: `select id, target_href from today_cards where id in (…)` 결과가 위 표의 «가야 할 곳»과 같다(드랍 `/drops`, 배지 상세 `/badges/669b6886-b5d4-4cce-a6f6-da5bc54e8f8e`와 `/badges/b6a3bfc0-9597-4347-a518-18e523ebf47c`).
- 지침 4곳에 규칙이 들어갔고 `node scripts/check-contract.mjs`가 통과한다.

### 주요 의사결정 / 핵심 메모
- 카드 3장은 `content_intro`를 `badge_spotlight`로 바꾸지 않고 `target_href`만 채웠다. 사용자 요청이 «링크 수정»이고 템플릿을 바꾸면 카드 모양이 달라지기 때문이다.
- 아현·민지에게 넘기기 전에 티켓과 지침 문서를 먼저 staging에 push했다(워크트리가 `origin/staging`에서 시작해 티켓이 원격에 있어야 읽는다). `jam-web/` 밖 변경만이라 빌드는 생기지 않았다.
- 민지 참고: `progress_nudge`는 배지가 여러 개이거나 참조가 없으면 `/badges`로 해석돼 새 검사로 오류가 난다. 규칙 취지와 같아 그대로 두고 등록 묶음 문서에 적었다.

### 잔여 이슈
- 같은 문제를 가진 노출 중·예정 카드 4장(입동 주간 처음 가는 곳으로, 오늘은 입동이에요, 입동에 만나는 활동 배지 「겨울잠」, 송파구 역마다 체크인 배지가 있어요)은 범위 밖이라 값을 바꾸지 않았다. 사용자 결정 대기.
