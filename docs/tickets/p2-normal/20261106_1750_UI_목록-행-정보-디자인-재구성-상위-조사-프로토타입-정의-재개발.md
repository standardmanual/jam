# [UI] 목록 행 정보 디자인 재구성 (상위): 조사, 프로토타입, 디자인 시스템 정의, 재개발

## 핵심 요약

- 요구사항: 프로필 피드·알림·미션·믹스 레시피 등 목록 행이 화면마다 글자 크기·강조·간격이 달라 보기 어렵다(사용자 요청 2026-11-06). 목록 행 컴포넌트를 정보 역할 기준으로 재구성해 디자인 시스템에 새로 정의하고, 적용할 화면을 다시 개발한다.
- 진행 순서(사용자 결정 2026-11-06): ① 목록 행이 쓰이는 곳 전수 조사 → ② 조사 결과로 컴포넌트를 재구성하고 프로토타입 제작 → ③ 프로토타입 검토 후 디자인 시스템 정의 → ④ 새 컴포넌트로 적용처 재개발.
- 현재: 1단계(조사)·2단계(프로토타입, 20261106_1759)·3단계(디자인 시스템 정의, 20261106_2003) 완료. 4단계(서비스 재개발)는 1배치(프로필 피드, 20261106_2252)가 끝났고 2배치(알림·레시피) 계획 단계다.
- 관련 파일: `jam-web/src/components/ui/ListRowCard.tsx`(서비스 사본), `jam-web/design-system/components/patterns/ListRowCard.jsx`(원본), `jam-web/design-system/tokens/typography.css`

## 배경 / 문제 정의

프로필 피드 한 행의 «행위 라벨 / 대상 / 장소» 세 줄이 모두 16px이고 색만 다르며, 시간도 16px로 제목과 경쟁한다. 알림·미션·믹스 레시피의 행은 각자 다른 크기와 강조를 쓴다. 공용 `ListRowCard`가 아이콘·제목·부제·오른쪽 칸만 정하고, 실제 화면 대부분은 `children`으로 안쪽을 직접 그리기 때문이다.

## 1단계 조사 결과

조사 방법: 영역 4개로 나눠 코드를 읽었다(프로필·소셜·알림, 미션·랭킹·배지, 믹스·인벤토리·드랍·기타, 디자인 시스템과 공용 부품). 코드에서 확인한 값만 적었고 실렌더 측정은 하지 않았다. 어드민 화면과 테스트는 제외했다. 글자 크기는 Tailwind 클래스를 px로 환산했다(text-xs 12, sm 14, base 16, lg 18, xl 20, 2xl 24).

### 5. 최악 사례 (2단계 Storybook 입력)

프로토타입 검토는 아래 사례가 깨지지 않는지 보는 방식으로 한다.

- 피드 A1: 마지막 파편 아이템 드랍 + 트라이브 파편 meta + 반복 획득(2줄 eyebrow) + 등급 칩 + 「마지막 파편!」 칩 + ×N 필 + 30일 넘은 날짜 시간.
- 피드 A2: 활동 이름 + «배지 N개와 N 포인트를 획득했어요» + 썸네일 4개 + 「+N」 + 시간 + 쉐브론.
- 알림 A4: 줄 제한 없는 장문(「캡슐이 가득 찼고 못 받은 보상이 2개라 지금 들어오는 잼은 사라져요. …」), 아바타 2단 링크, inverse 톤.
- 포인트 내역 A5: 긴 이름 + 관리자 자유 입력 사유 + 긴 절대 날짜 + 「+1,000 포인트」.
- 미션 목록 B2: NEW 칩 + 상태 칩 + 설명 2줄 + 잠김 조건 줄(등급 칩 + 배지명) + 보상 줄(배지 여러 개 + 잠긴 아이템 배지 + 포인트 « + » 연결, 줄바꿈).
- 레시피 B1: 보상 배지 여러 개 + 「잠김」 칩 + 포인트 + 「공개 예정 · 10월 6일 오후 3시 30분」.
- 개체 후보 B7: 만료 임박 + 등급 + 일련번호(폭 212) + 선택됨 + 「처리 중」, 잠김 변형 «N 포인트 필요».
- 순위 C4: 내 행(숫자·값 24px 확대) + 긴 이름 truncate. 달성 C5: 내 행 + 「(나)」 + 칩.
- 팔로우 C1·C2: 긴 이름 + 오른쪽 버튼(이름이 먼저 잘려야 함).
- 공통: 320px 폭, 글자 크게 보기 설정, 한 줄 말줄임과 줄바꿈 혼용(`break-keep`).

### 6. 행과 카드의 경계 제안

- **행**: A군 전체, B1·B5·B6·B7·B8·B10·B11, C군 전체, D군(값 행은 변형으로 둘지 별도 부품으로 둘지 2단계에서 정한다).
- **미디어 행(변형)**: lead 64px 이상이거나 본문이 3줄 이상인 것. B2(미션 목록, lead 90 + 최대 5줄), B3·B4(보상 행 lead 64). lead는 크기를 한 가지로 고정한다(2단계 결정 4). 미션 목록은 면이 없고 보상 행은 tint라 면 표현도 정리 대상이다.
- **카드**: lead가 위에 놓이는 세로 배치, 열 격자. 행 규칙 밖.
- **가설: 행 계열 5종 + 미디어 변형 1종**. 활동·이벤트 행(A), 대상 행(B), 사람 행(C), 값 행(D), 체크 목록 행(E) 모두 «lead + 본문 + trail» 골격은 같고 역할 구성만 다르다. 2단계는 하나의 골격 컴포넌트와 역할 슬롯으로 다섯 계열을 모두 표현할 수 있는지부터 증명한다.
