# [UI] 목록 행 2단계: 행 컴포넌트 재구성과 프로토타입 (MODULAR + Storybook)

## 핵심 요약

- 요구사항: 상위 티켓 20261106_1750의 «1단계 조사 결과»를 근거로, 정보 역할 기준 목록 행 컴포넌트를 MODULAR(디자인 시스템 원본)에 프로토타입으로 만들고 Storybook에서 검토할 수 있게 한다. 서비스 화면은 바꾸지 않는다.
- 구현 계획: 새 컴포넌트를 `jam-web/design-system/components/patterns/`에 더한다(기존 `ListRowCard`는 이 단계에서 고치지 않는다). 스토리에 조사한 최악 사례와 전/후 비교를 모두 넣는다.
- 관련 파일: `jam-web/design-system/components/patterns/ListRowCard.{jsx,d.ts,prompt.md,stories.tsx}`(참조), 새 파일 `ListRow.{jsx,d.ts,prompt.md,stories.tsx}`(이름은 채원이 판정), `jam-web/design-system/tokens/typography.css`·`spacing.css`·`radius.css`(참조)

## 배경 / 문제 정의

상위 티켓의 «1단계 조사 결과»에 있다. 같은 정보 역할(title·meta·chip·time·value)이 화면마다 다른 모양이고, 공용 `ListRowCard`는 껍데기만 정해 안쪽은 호출부가 직접 그린다. 디자인 시스템 원본은 쓰이지 않고 서비스 사본이 따로 진화했다.

## 사용자 결정 (2026-11-06)

1. **적용 범위**: 4단계에서 프로필 피드 한 곳을 먼저 적용해 검증한다. 이 단계에서는 서비스 화면을 바꾸지 않고, 프로필 피드 행을 첫 번째 스토리 대상으로 삼는다.
2. **시간 위치**: eyebrow(행위·종류 라벨) 줄의 오른쪽. 값(포인트·숫자)이 있는 행의 오른쪽 칸과 충돌하지 않게 한다.
3. **미션 목록 포함**: 미디어 행 변형으로 같은 컴포넌트에 포함한다.
4. **썸네일(lead) 영역은 모든 행에서 같은 크기로 고정한다.** 현재 24·36·40·44·48·64·90px가 섞여 있다. 크기는 하나의 토큰으로 정한다.
   - 추천 크기는 **48px**이다. 근거: 지금 가장 많은 40px에서는 배지·아이템 이미지 안의 그림이 잘 읽히지 않고, 새 행은 eyebrow가 12px로 줄어 행 높이가 낮아지므로 48px이 높이에 맞는다. 프로토타입 스토리에 40px과 48px을 나란히 보여 사용자가 최종 선택한다.
   - 모양은 크기와 별개다. 기본안은 대상(배지·아이템·컬렉션)은 `rounded-2xl`, 사람·코인은 원형이다. 채원이 모양 규칙을 판정한다.
   - **영향**: 미션 목록 썸네일이 90px에서 줄어든다. 이 때문에 «미디어 행» 변형은 lead 크기가 아니라 본문 줄 수(3줄 이상)로 구분한다. 스토리에 미션 목록의 전/후를 넣어 줄어든 모습을 검토할 수 있게 한다.

## 설계 출발점 (채원이 판정으로 확정하거나 고친다)

정보 역할을 슬롯 이름으로 고정한다. 글자 모양은 기존 크기 토큰(`--text-xs` 12, `--text-sm` 14, `--text-base` 16)만 쓰고 새 크기 토큰은 만들지 않는다.

| 역할 | 내용 | 시작 모양 |
|---|---|---|
| lead | 왼쪽 이미지·아이콘 | 위 결정 4의 고정 크기 |
| eyebrow | 행위·종류(「배지 획득」「아이템 픽업」) | 12 / 보통 / muted |
| title | 대상 이름 | 16 / 굵게 / foreground, 한 줄 말줄임 |
| meta | 장소·부가 정보 | 12~14 / muted, 한 줄 |
| chips | 등급·Lv·상태 | 칩 크기 하나로 통일 |
| time | 상대 시간·날짜 | 12 / muted, eyebrow 줄 오른쪽 |
| value | 포인트·숫자(오른쪽 칸) | 기존 `PointText` 규칙 |

- 강조는 굵기(title), 포인트 색(value), 칩 세 가지로 제한한다. 한 행에서 색으로 강조하는 곳은 한 곳 이하다.
- 문장형 행(알림)은 title 자리에 «문장» 변형을 둔다. 핵심어 굵기는 유지하고 크기와 시간 규칙은 같게 한다.
- 행 계열 5종(활동·이벤트 A, 대상 B, 사람 C, 값 D, 체크 목록 E)이 하나의 골격과 역할 슬롯으로 모두 표현되는지가 이 단계의 핵심 증명 과제다. 값 행(D)과 체크 목록 행(E)을 같은 컴포넌트의 변형으로 둘지 별도 부품으로 둘지도 채원이 판정한다.
- 선택됨·비활성·눌림·반전 면(inverse)·tint 상태를 컴포넌트가 가진다. 조사에서 4종으로 갈린 선택 표현을 하나로 정한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 변경 범위는 `jam-web/design-system/` 안으로 한정한다. 서비스 화면(`jam-web/src/app/`, `jam-web/src/components/`)과 서비스 사본 `ListRowCard.tsx`는 바꾸지 않는다.
- 기존 `ListRowCard`(원본)는 고치지 않는다. 새 컴포넌트가 확정되기 전까지 두 컴포넌트가 공존한다.
- 새 토큰이 필요하면(lead 크기, 행 안 간격, 칩 크기 등) 채원이 승인 필요 항목으로 올린다. 토큰 확정은 3단계다. 프로토타입에서는 컴포넌트 안의 CSS 변수로 임시 정의하고 이름에 프로토타입 표시를 한다.
- 컴포넌트는 MODULAR 관례(인라인 style + 토큰 변수, `.d.ts`, `.prompt.md`, `.stories.tsx`)를 따른다.

### UI/UX 관점
- 스토리는 아래를 모두 포함한다.
  1. 계열별 기본 스토리 5종(A~E)과 미디어 행 변형.
  2. **프로필 피드 행 전/후 비교**: 지금 모양(조사 A1)과 새 모양을 나란히.
  3. **미션 목록 행 전/후 비교**: 90px 썸네일 모양(조사 B2)과 새 모양을 나란히.
  4. **lead 40px 대 48px 비교** 스토리.
  5. **최악 사례**(상위 티켓 «1단계 조사 결과» 5번 목록 전부): 피드 A1·A2, 알림 장문 A4, 포인트 내역 A5, 미션 목록 B2, 레시피 B1, 개체 후보 B7, 순위 C4와 달성 C5, 팔로우 C1·C2.
  6. 폭 320px과 360px 프레임, 글자 크게 보기(글자 크기 확대) 상태, 한 줄 말줄임과 줄바꿈 혼용.
  7. 상태: 기본·tint·inverse·선택됨·비활성·눌림.
- 한국어 문구는 `UX_WRITING_GUIDELINE.md` 용어를 쓴다(획득·드랍·픽업·체크인).
