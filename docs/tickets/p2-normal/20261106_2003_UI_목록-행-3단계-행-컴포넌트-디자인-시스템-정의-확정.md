# [UI] 목록 행 3단계: 행 컴포넌트를 디자인 시스템 정의로 확정한다 (토큰·문서·아이콘·정리)

## 핵심 요약

- 요구사항: 2단계에서 검토를 통과한 `ListRow` 프로토타입을 디자인 시스템의 정식 정의로 확정한다(사용자 지시 2026-11-06 «수정 후 3단계»). 임시 값(`-proto`)을 정식 토큰으로 올리고, 문서와 색인과 기존 `ListRowCard`와의 관계를 정리한다. 서비스 화면은 4단계에서 옮기므로 이 단계에서는 바꾸지 않는다.
- 구현 계획: 회차 3-1 채원 사전 판정(토큰 이름·위치·값, 승인 항목 확정) → 사용자 승인 → 회차 3-2 구현.
- 관련 파일: `jam-web/design-system/components/patterns/ListRow.{jsx,d.ts,prompt.md,stories.tsx}`, `jam-web/design-system/tokens/*.css`(`spacing.css`·`colors.css`·`radius.css`), `jam-web/design-system/components/patterns/ListRowCard.prompt.md`, `jam-web/design-system/readme.md`, `jam-web/design-system/_ds_manifest.json`, `jam-web/src/app/globals.css`(토큰 import, 읽기만)

## 배경 / 문제 정의

2단계 결과(상위 티켓 20261106_1750, 하위 20261106_1759)로 `ListRow`가 MODULAR에 프로토타입으로 있다. 아직 임시인 것들이 남아 있다.
- 컴포넌트 안 임시 CSS 변수 9종(`--list-row-*-proto`)과 컴포넌트 안에 직접 든 값(`leadBadge`의 -6px 위치·20px 크기·`0 6px` 여백, 반전 면 위 글자 `color-mix`).
- 채원 사후 리뷰와 실렌더에서 3단계로 넘긴 항목(아래 «범위»).
- 기존 `ListRowCard`와 공존 중이라 어느 쪽을 써야 하는지 문서가 알려 주지 않는다.

## 사용자 결정 (2026-11-06, «네, 수정 후 3단계»로 추천안 채택)

- lead(썸네일)는 모든 행에서 **48px** 하나로 확정한다.
- 활동 묶음 행(A2)은 쉐브론 없음을 유지한다(사용자 코멘트 «제거»). 쉐브론을 더한 대안은 스토리에 참고로 남긴다.
- `flat` 톤 + 선택됨은 «대안»(좌우 여백 + 모서리)을 채택해 호출부가 덮어쓰지 않고 컴포넌트가 자동으로 준다(3단계에서 구현).

## 범위 (3단계에서 하는 일)

1. **임시 변수의 정식 토큰화**: `--list-row-lead-size-proto`(48px)·`indicator`(24px)·`gap`(12px)·`pad-x`(16px)·`pad-y`(12px)·`line-gap`(2px)·`chip-pad`(2px 8px)·`selected-ring`(2px)·`disabled-opacity`(0.4)를 정식 이름과 위치(`tokens/*.css`)로 올린다. 이름과 위치는 채원이 판정한다.
2. **신규 색 토큰 후보 `--muted-on-inverse`**(snow 70%): 반전 면 위 보조 글자용. 현재 `color-mix`로 처리 중.
3. **`leadBadge` 값 토큰화**: 위치(-6px)·크기(20px)·여백(`0 6px`)·`lineHeight: 1`.
4. **`flat` + 선택됨**: 컴포넌트가 좌우 여백(`--spacing-16`)과 모서리(`--radius-2xl`)를 자동으로 준다.
5. **아이콘**: 컴포넌트 안에서 직접 그리는 아래 방향 쉐브론을 `IconCatalog`의 `ChevronDownIcon`으로 올려 쓴다.
6. **스타일 중복 렌더 제거**: 행마다 같은 `<style>` 블록이 렌더되는 것을 한 번만 주입하도록 정리한다(서비스 이식 전 필수).
7. **등급 칩 크기 통일 검토**: `RarityBadge` md가 11px라 «칩 12px 한 크기» 기준과 어긋난다. 다른 컴포넌트(서비스 전반에 쓰임)에 영향이 있어 채원이 파급 범위를 판정하고 승인 항목으로 올린다.
8. **문서**: `ListRow.prompt.md` 최종본, `ListRowCard.prompt.md`에 «새 화면은 `ListRow`를 쓴다» 안내와 폐기 예정 표시, `readme.md` 색인과 `_ds_manifest.json` 갱신(`npm run ds:manifest`).
9. 스토리 정리: `-proto` 표기와 «프로토타입» 표현 제거, 스토리 안 임의 값(raw px)을 토큰으로.

범위 밖: 서비스 화면 이식과 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`(4단계), claude.ai/design 업로드본 갱신(티켓 20261016_2220).

## 구현 계획

회차로 나눈다. 회차마다 채원 사전 판정, 아현 구현, 민지 게이트를 거친다.
1. **회차 3-1 (설계 판정)**: 채원이 위 범위의 토큰 이름·위치·값과 파급 범위를 확정하고 승인 필요 항목으로 올린다. 사용자 승인을 받는다.
2. **회차 3-2 (토큰·컴포넌트)**: 토큰 파일 추가, `ListRow.jsx` 정리(임시 변수 교체, `flat` 선택, 쉐브론 아이콘, 스타일 1회 주입), 스토리·문서 갱신. 파일 단위 계획은 3-1 판정 뒤 이 티켓에 적는다.
3. **회차 3-3 (색인·문서)**: `ListRowCard.prompt.md`, `readme.md`, `_ds_manifest.json`.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `ListRow.jsx`에 `-proto` 이름이 남아 있지 않고, 값이 토큰에서 나온다.
- 신규 토큰이 `tokens/*.css`에 정의되고 `npm run ds:manifest`로 `_ds_manifest.json`에 등록돼 `npm run ds:check`가 오류 0으로 통과한다.
- `flat` + 선택됨이 호출부 덮어쓰기 없이 여백과 모서리를 갖는다.
- 아래 방향 쉐브론이 `IconCatalog`의 아이콘을 쓴다.
- 여러 행을 렌더해도 같은 `<style>`이 한 번만 문서에 들어간다.
- `ListRowCard.prompt.md`와 `readme.md`가 `ListRow`를 안내한다.
- `jam-web/src` 서비스 화면 코드는 바뀌지 않는다(`globals.css` 토큰 import 확인 외). `scripts/verify.sh`가 통과한다.
