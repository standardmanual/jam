# [UI] 목록 행 4단계 1배치: 프로필 피드(활동 행·활동 묶음 행)를 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 4단계(서비스 재개발)의 첫 배치다(사용자 결정 2026-11-06 «추천대로»). 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`를 만들고, 프로필 피드의 활동 행(`FeedCard`)과 활동 묶음 행(`ActivityGroupCard`)을 이 컴포넌트로 옮긴다. 같은 `FeedSection`을 쓰는 친구 활동 화면(`/feed`)과 타인 프로필도 함께 바뀐다. 상세 시트(`DetailSheet`)는 바꾸지 않는다.
- 구현 계획: 채원 사전 판정(매핑표·승인 항목) → 아현 구현(사본 + 아이콘 + 피드 전환 + 시험) → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 아래 «구현 계획»에 있다(계획 반환 면제 사유).
- 관련 파일: 아래 «관련 파일 지도».

## 배경 / 문제 정의

상위 티켓 20261106_1750의 1~3단계로 `ListRow`가 디자인 시스템의 정식 정의가 됐다(`design-system/components/patterns/ListRow.{jsx,d.ts,prompt.md,stories.tsx}`). 서비스는 아직 옛 `ListRowCard`를 쓴다. 프로필 피드는 처음 문제를 발견한 화면이고(스크린샷 첨부 2026-11-06), 2단계 프로토타입의 `BeforeAfterProfileFeed` 스토리가 실제 6행으로 옮긴 결과를 이미 보여 준다.

## 사용자 결정 (2단계·3단계에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 eyebrow 줄 오른쪽 끝(`time` 슬롯).
- lead(썸네일)는 모든 행에서 48px. 이전 40px에서 커진다.
- 활동 묶음 행(A2)은 쉐브론 없음. `aria-expanded`만 남긴다(펼침 단서가 보이지 않는 위험은 3단계 잔여 이슈로 기록돼 있다. 이 배치의 판정에서 다시 확인한다).
- `flat`+`selected` 규칙은 이 배치에서 쓰지 않는다.

## 범위

1. **서비스 사본 `ListRow.tsx`**: DS 원본 `ListRow.jsx`를 TypeScript로 옮긴다. `ListRow`·`ListRowEm`·`ListRowChip`을 내보낸다.
   - 인라인 스타일 값은 원본과 같게 둔다. `scripts/ds-sync-check.mjs`가 매니페스트의 `ListRow` 쌍(원본 `.jsx` ↔ 서비스 `ListRow.tsx`)의 기하를 대조한다.
   - 링크 모드는 `<a>` 대신 `next/link`의 `Link`를 쓴다(`ListRowCard`와 같다). `leadHref` 링크도 같다.
   - 아이콘은 서비스 `icons.tsx`의 `CheckIcon`·`ChevronRightIcon`·새 `ChevronDownIcon`을 쓴다. 서비스 아이콘은 `className`으로 크기를 정하므로 `width`·`height` 속성 대신 `w-5 h-5`로 20px을 맞춘다.
   - `<style href="ds-list-row" precedence="medium">`는 그대로 쓴다(React 19, 행이 몇 개든 문서에 1개).
   - `ListRowSkeleton`은 서비스에 스켈레톤 부품이 없고 이 배치에서 쓰이지 않으므로 사본에 넣지 않는다. `ds:check`가 이 때문에 오류를 내면 넣지 말고 보고한다.
2. **`icons.tsx`에 `ChevronDownIcon` 추가**: 기존 `ChevronRightIcon`(165줄)과 같은 양식. DS 쪽 `IconCatalog.jsx`의 같은 이름 아이콘과 같은 경로 값이어야 한다.
3. **`FeedSection.tsx` 전환**:
   - `FeedCard`(483줄 근처)를 `ListRow`로 바꾼다. 아래 «매핑표»를 따른다.
   - `ActivityGroupCard`(696줄 근처)를 `ListRow variant="media"`로 바꾼다.
   - 카드용 일반 문자열 라벨 함수를 새로 둔다(`eventLabelText`). 기존 `eventLabel`(236줄)은 상세 시트가 `<strong>`을 쓰는 ReactNode 형태로 계속 쓰므로 그대로 둔다(아래 «판정이 필요한 점» 1번).
   - 더 이상 쓰이지 않는 `ListRowCard` import와 `EarnCountBadge`를 정리한다(`ListRowCard`는 다른 화면이 쓰므로 컴포넌트 자체는 지우지 않는다).
4. **시험**: `FeedSection.test.tsx`는 서버 렌더 마크업 문자열을 고정하므로 새 마크업에 맞게 고친다. 새 `src/components/ui/ListRow.test.tsx`로 사본의 핵심 동작(슬롯 배치, 1회 스타일 주입, 한 줄 말줄임 스타일, `aria-expanded`, `leadHref`+`leadLabel`)을 고정한다.
5. **문서**: 이 화면의 PRD(`docs/service/prd/chapter/PRD.md`의 프로필 피드 절)에 행 모양 변경을 한 줄로 반영하고, 상위 티켓 4단계 표를 갱신한다.

범위 밖: 알림·레시피·후보 행·미션 목록 등 다른 화면(2~4배치), `ListRowCard` 삭제(마지막 배치 뒤), `RarityBadge` sm 8px→12px 승격(별도 티켓), `DetailSheet`.

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| `FeedCard` 아이콘 40×40 `SafeImage`(alt=제목) + 폴백 이벤트 아이콘 | `lead`(이미지는 `alt=""` 장식, `fill`로 48 박스를 채움) + 폴백 이벤트 아이콘 |
| `EarnCountBadge` ×N 필 | `leadBadge`(`×N`) |
| 라벨 줄(`eventLabel`, muted, 최대 2줄) | `eyebrow`(문자열) |
| 오른쪽 상대 시각 | `time` |
| 제목(`feedTitle`) | `title`(strong, 1줄 말줄임). 제목이 비면 `title`을 주지 않는다 |
| 부제(`sub`: 트라이브 파편·장소·보상 포인트) | `meta` |
| 등급 칩(`BadgeChip`)·«마지막 파편!» 칩 | `chips` |
| `ActivityGroupCard` 아이콘 + 활동 이름 + 헤드라인 + 썸네일 줄 | `variant="media"`, `lead`(ActivityIcon), `eyebrow`(활동 이름), `time`, `title`(헤드라인), `footer`(썸네일 24px 묶음 + «+N»), `onClick`, `aria-expanded`, `aria-controls` |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **`eyebrow`가 문자열이면 한 덩어리 문장, ReactNode면 칩 줄**로 그려진다(`ListRow.jsx`의 `typeof eyebrow === 'string'` 분기). 지금 `eventLabel`은 반복 획득일 때 «N번째»의 숫자만 `<strong>`으로 감싼 조각 모음을 돌려주므로 그대로 넣으면 문장이 칩처럼 쪼개져 4px 간격이 끼어든다. 2단계 프로토타입(`FamilyA`의 A1)은 숫자 강조 없이 평문 한 줄이다. 카드는 평문 문자열을 쓰고 숫자 강조는 상세 시트(`DetailSheet`)에만 남기는 안을 기본으로 판정한다.
2. **칩 높이 불일치**: `RarityBadge` md(11px)·`BadgeLevelChip`은 `ListRowChip`(12px)과 높이가 다르다(3단계 잔여 이슈). 이 배치에서 실제 렌더로 측정하고, 어긋남이 눈에 띄면 서비스 호출부 한정 보정을 할지 별도 티켓으로 둘지 정한다.
3. **활동 묶음 행의 펼침 단서**: 쉐브론이 없어 눌러 보지 않으면 펼쳐진다는 것을 알 수 없다. 사용자 결정은 «제거»이므로 유지하되, 썸네일 줄(+N)과 헤드라인이 단서가 되는지 실렌더로 확인해 결과만 보고한다(바꾸려면 사용자에게 묻는다).
4. **펼친 패널 안의 행**(`pl-4`로 들여쓴 `FeedCard` 목록)은 지금 `default` 톤이다. 그대로 두는지 판정한다.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 5개 파일을 넘고 시험·문서까지 100줄 이상이지만 전부 위 지도에 확정돼 있고 탐색이 필요 없다).

1. `jam-web/src/components/ui/icons.tsx` — `ChevronRightIcon`(165줄) 아래에 `ChevronDownIcon` 추가(약 8줄).
2. `jam-web/src/components/ui/ListRow.tsx` — 신규(약 330줄). `design-system/components/patterns/ListRow.jsx`의 `ListRow`·`ListRowEm`·`ListRowChip`과 내부 `Lead`·`Indicator`·`clamp`·`TONES`·`ROW_WEIGHT`·`STATIC_CSS`를 옮긴다. `'use client'`는 불필요하다(훅·이벤트 핸들러 정의 없음, `onClick`은 prop 전달). `Link`는 `next/link`.
3. `jam-web/src/app/(main)/FeedSection.tsx` — import 교체(15줄), `EarnCountBadge`(120줄) 삭제, `eventLabelText` 신설(236줄 근처), `FeedCard`(483~544줄) 재작성, `ActivityGroupCard`(696~779줄) 재작성. 썸네일 줄은 `footer`로 옮기고 `aria-hidden`을 유지한다. 변경은 약 90줄.
4. `jam-web/src/app/(main)/FeedSection.test.tsx` — 카드 마크업 고정 문자열 갱신(40×40 타일 → 48 lead, 라벨·제목 클래스 → `ListRow` 슬롯 마크업). 활동 묶음 행·«N번째» 평문 라벨·시각이 eyebrow 줄에 있다는 것을 고정하는 시험 추가.
5. `jam-web/src/components/ui/ListRow.test.tsx` — 신규. 사본 시험.
6. `docs/service/prd/chapter/PRD.md`, 상위 티켓 `20261106_1750` — 문서 갱신.
7. `jam-web/design-system/_ds_manifest.json`은 이미 `ListRow`가 올라 있어 변경 없음(`npm run ds:check`로 쌍 대조만 한다).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- `ListRow.tsx`가 존재하고 `npm run ds:check`가 오류 0이다(원본과 기하가 같다).
- 프로필·타인 프로필·친구 활동 화면의 피드 활동 행이 `ListRow`다: lead 48, 시간이 eyebrow 줄 오른쪽 끝, 제목 굵게 한 줄 말줄임, 부제 14px, 칩 줄, ×N은 lead 우하단.
- 활동 묶음 행은 `variant="media"`이고 쉐브론이 없으며 `aria-expanded`·`aria-controls`가 유지돼 눌러서 열고 닫을 수 있다. 접힌 패널은 `inert`가 유지된다.
- 한 줄 말줄임이 실제 DOM에서 동작한다(`white-space: nowrap`, 긴 제목이 잘린다). 코드만 읽고 통과시키지 않는다.
- 상세 시트(`DetailSheet`)와 다른 화면의 `ListRowCard` 사용처는 바뀌지 않는다.
- `FeedSection.test.tsx`·새 `ListRow.test.tsx`와 `scripts/verify.sh`가 통과한다. `serviceLiteralColors` 시험이 통과한다(색 직접값 없음).
- 로컬 실렌더 또는 Storybook으로 320px·360px 폭의 최악 사례(반복 획득 2줄 eyebrow, 30일 넘은 날짜, 긴 제목, 칩 2개)를 확인한 결과가 기록돼 있다. 메인 트리에서만 가능하면 후속 범위로 둔다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging(stage.j-a-m.app)에서 프로필 화면 확인과 Vercel 배포 상태 확인.
- 판정 1~4의 결과를 상위 티켓 «4단계 진행» 절에 기록하고 2배치(알림·레시피) 계획을 세운다.
