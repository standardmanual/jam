# [UI] 행 안 등급 칩 글자를 12px로 맞춘다 (RarityBadge·BadgeLevelChip sm 승격)

## 핵심 요약

- 요구사항: 프로필 피드 행에서 한 줄에 놓이는 등급 칩(글자 8px, 높이 16px)과 «마지막 파편!» 칩(글자 12px, 높이 20px)의 크기를 맞춘다. 서비스 약 18곳이 쓰는 sm 크기가 바뀌므로 파급 범위를 채원이 판정한다.
- 구현 계획: 채원 사전 판정(2026-11-08, 사용자 승인 완료) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/components/ui/BadgeGridCard.tsx` 근처의 `RarityBadge`·`BadgeLevelChip`(정의 위치는 착수 때 확인), `jam-web/design-system/components/cards/RarityBadge.*`, `BadgeLevelChip.*`

## 배경 / 문제 정의

티켓 20261106_2252 실측: 등급 칩 Epic·Lv.7은 높이 16px·글자 8px, 마지막 파편 칩은 높이 20px·글자 12px로 4px 차이가 났다(3단계 때 티켓에 적은 11px가 아니라 실제로는 8px). 상위 티켓 3단계 잔여 이슈 «칩 12px 한 크기»의 후속이다. 사용자 결정이 필요한 변경이라 별도 티켓으로 둔다.

## 상위 티켓에서 이관됨

상위 티켓 `20261106_1750`(목록 행 정보 디자인 재구성)이 2026-11-08 사용자 승인으로 닫히면서, 상위 완료 조건 3(같은 역할의 글자 모양이 같다) 중 **chip 역할의 통일**을 이 티켓이 이어받는다. 값 행(value)은 5-4·5-5에서 16px/700으로 통일했고 이 티켓과 무관하다. 이 티켓이 끝나면 상위 조건 3이 완전히 닫힌다.

## 사용자 결정 (2026-11-08, 채원 사전 판정 승인 항목 4건을 권고대로 승인)

1. **MODULAR 확장**: `RarityBadge`·`BadgeLevelChip`에 행 전용 새 크기 `row`를 더한다(글자 12px `--text-xs`, 줄높이 `--text-xs--line-height` 16px, 패딩은 `--list-row-chip-padding` 토큰이라 높이 20px). 기존 `sm`(16px)·`md`(22px) 값은 바꾸지 않는다. 제목의 «`sm` 승격»(`sm` 15곳 파급, 칩 65% 축소 결정을 뒤집음)과 «호출부만 `md`»(높이 22px 대 20px로 완료 조건 미달)는 채택하지 않는다.
2. 이름은 `row`로 한다.
3. 글자 굵기는 700을 유지한다(등급 색 칩은 그 자체가 정보). 상위 조건 3의 chip은 «크기와 높이»로 읽어 닫는다. `ListRowChip`은 보통(400)이라 굵기는 다르다.
4. 미션 목록 조건·보상 줄 안 인라인 칩(`MissionsListClient.tsx` 79·90·170줄)은 이번 범위에서 제외하고 `sm` 8px로 둔다. 문장 12px 옆에서 칩이 작아 보이는 문제는 별도 P3 티켓(20261108_1832)으로 뺐다.
5. **범위 보정(카리나, 승인에 포함)**: 채원은 행 안 호출부를 3곳으로 셌으나 `ListRow` `eyebrow`에 `RarityBadge`를 넣은 곳이 두 군데 더 있어 **5곳**으로 한다: `FeedSection.tsx`(260·268줄), `RecipeRewardRow.tsx`(105줄), `ItemCandidateRow.tsx`(109줄), `PoiCarouselModal.tsx`의 `ItemRow`(1112줄, 5-3에서 옮긴 행), `MissionDetailClient.tsx`의 `rarityEyebrow`(212줄, 보상 행 세 곳 223·245·536줄에서 씀, 4-1에서 옮긴 행). `PoiCarouselModal.tsx` 928줄(드랍 확인 화면의 가운데 정렬 칩)과 미션 목록 인라인 칩은 `ListRow` eyebrow가 아니라 제외다.

## 범위

1. `RarityBadge.jsx`·`BadgeLevelChip.jsx`의 `SIZES`에 `row`를 더한다. `RarityBadge`는 `lineHeight: 1`이 고정이라 `SIZES` 항목에 `lineHeight` 필드를 두고 `row`만 16px 토큰으로 한다(`sm`·`md`는 그대로 1).
2. 같은 변경에 따라 오는 파일: `.d.ts` 2개의 `size` 유니온, `.prompt.md` 2개의 크기표, `.stories.tsx` 2개의 `row` 사례, `_ds_manifest.json`(갱신이 필요하면).
3. 호출부 5곳이 `size="row"`를 넘긴다. `RecipeRewardRow.tsx` 101줄의 «8px 등급 칩이 12px 잠김 칩 높이로 늘어난다» 주석과 `MissionDetailClient.tsx`의 «2322 머지 뒤 칩이 커진다»류 주석은 사실이 바뀌므로 정리한다.
4. 시험: 깨지는 단정이 있으면 의도를 지켜 고치고, `row`가 `sm`·`md`의 렌더를 바꾸지 않는다는 단정을 더한다.

범위 밖: `ListRow` 본체, 인라인 칩, 나머지 `sm` 호출부(약 9곳)와 `md` 호출부 4곳.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경이 같은 모양의 작은 수정의 반복이고 파일 목록과 줄 위치가 채원 판정과 이 티켓에 확정돼 있다. 파일 수는 디자인 시스템 9개 안팎과 호출부 5개로 5개를 넘지만 탐색이 필요 없다).

1. `jam-web/design-system/components/cards/RarityBadge.jsx`(`SIZES` 69~70줄), `BadgeLevelChip.jsx`(`SIZES` 23~26줄)
2. `RarityBadge.d.ts`, `BadgeLevelChip.d.ts`, `RarityBadge.prompt.md`, `BadgeLevelChip.prompt.md`, 두 `*.stories.tsx`, `_ds_manifest.json`
3. `jam-web/src/app/(main)/FeedSection.tsx` 260·268줄, `combine/RecipeRewardRow.tsx` 105줄, `components/inventory/ItemCandidateRow.tsx` 109줄, `components/PoiCarouselModal.tsx` 1112줄, `missions/[id]/MissionDetailClient.tsx` 212줄
4. 깨지는 시험과 주석 정리

## 완료 조건

- 행 안(`ListRow` eyebrow·chips)에서 모든 칩의 글자가 12px이고 높이가 같다(20px). `sm`·`md`의 렌더(16px·22px)는 바뀌지 않는다.
- 서비스에서 sm 칩이 쓰이는 곳의 줄바꿈·넘침이 깨지지 않는다(채원 파급 판정과 사용자 승인 후).
