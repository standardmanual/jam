# [UI] 목록 행 4단계 2-1배치: 알림 행을 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 알림 화면(`NotificationRow`)의 행을 `ListRow`로 옮긴다. 문장형 제목(`titleVariant="sentence"`)이 서비스에서 처음 쓰이는 사례다. 상위 티켓 4단계 2배치의 앞 절반이고, 뒤 절반(레시피·등급 올리기)은 티켓 20261107_0011이다.
- 구현 계획: 채원 사전 판정(매핑표·판정 4건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/notifications/NotificationsClient.tsx`(import 8줄, `RowIcon` 105~142줄, `NotificationBody` 148~171줄, `NotificationRow` 173~221줄), `NotificationsClient.test.tsx`(40×40 타일·`bg-background-inverse` 문자열을 고정하는 시험 다수), `jam-web/src/components/ui/ListRow.tsx`(읽기만).

## 배경 / 문제 정의

1배치(20261106_2252)로 서비스에 `ListRow` 사본이 생겼고 프로필 피드가 옮겨졌다. 알림 행은 `ListRowCard`의 `children` 경로로 문장을 직접 그려서 글자 모양이 다른 행과 따로 논다. 알림 29종이 같은 행을 쓰고, 경고(`warning`)·반전(`inventory_full`)·아바타 2단 링크 같은 변형이 있다. 상위 티켓 1단계 조사의 A4 행이다.

## 사용자 결정 (1~3단계에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 12px muted. `eyebrow`가 있으면 그 줄 오른쪽 끝, 없으면 제목 줄 오른쪽 끝(`time` 슬롯).
- lead(썸네일)는 모든 행에서 48px 한 가지. `ListRow` 본체에 크기 prop은 없다.
- 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`(1배치 20261106_2252에서 추가)를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1배치에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`로 넘긴다(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322).

## 범위

1. `NotificationRow`를 `ListRow`로 바꾼다.
   - lead: 아바타는 `leadShape="round"`, 종류별 아이콘·경고는 `tile`. 아바타 이미지는 장식(`alt=""`)이 되고 접근 가능한 이름은 `leadLabel`이 맡는다.
   - 제목: `titleVariant="sentence"`, 줄 제한 없음. `NotificationBody`가 돌려주던 `<p>`를 없애고 토큰을 `ListRowEm`(굵게)과 일반 텍스트로 그린다. `pointify`는 그대로 쓴다.
   - 시간: `time={formatRelativeTime(view.updatedAt)}`. 제목 줄 오른쪽 끝에 붙는다.
   - 링크: 본문 링크(`href`)와 아바타 링크(`avatarHref`)가 둘 다 있으면 `href` + `leadHref` + `leadLabel`로 2단 링크를 만든다. `ListRow`가 lead를 클릭 영역 밖 형제로 빼므로 `<a>` 안의 `<a>`가 생기지 않는다. 아바타 링크만 있고 본문 링크가 없으면 `href` 없이 `leadHref`만 준다.
   - 반전: `tone="inverse"`는 `inventory_full`에만 쓴다(기존과 같다). 글자·시간 색은 톤이 정한다.
2. 아이콘 컴포넌트(`TypeIcon`·`RowIcon`)는 크기만 48 박스에 맞게 고친다. 경고는 `--warning` 면을 lead 박스 전체에 채우고 `role="img"`·`aria-label`을 유지한다(경고 아이콘 색은 `--foreground`).
3. `NotificationsClient.test.tsx`의 마크업 고정 문자열을 새 마크업에 맞게 고친다. 29종의 문구·링크 목적지·경고·반전 판정을 확인하는 기존 시험의 의미는 유지한다(마크업 문자열만 바꾼다).
4. 문서: 알림 PRD의 화면 설명에 행 모양 변경을 한 줄 반영하고, 상위 티켓 4단계 표를 갱신한다.

범위 밖: 레시피·등급 올리기(20261107_0011), `ListRowCard` 삭제, 알림 문구·토큰 규칙, 섹션 머리·새 소식 구분선(`SectionHeader`·`NewDivider`).

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| `RowIcon` 40×40 종류별 아이콘 타일 | `lead`(아이콘만, 타일 박스는 `ListRow`가 준다) |
| 아바타 `Image` 40 `rounded-full` | `lead` + `leadShape="round"`, `alt=""` |
| 경고 타일(`bg-warning`, `role="img"`) | `lead` 안에서 박스를 `--warning`으로 채운다 |
| 아바타 `Link`(`aria-label`) + 본문 `Link` | `leadHref` + `leadLabel` + `href` |
| `NotificationBody`(`<p>`, 굵은 토큰) | `title` + `titleVariant="sentence"`, 굵은 토큰은 `ListRowEm` |
| 오른쪽 `trailing` 시간(12px) | `time` |
| `tone` default·inverse | `tone` default·inverse |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **경고 lead**: `ListRow`의 lead 박스는 자체 면색(`leadBg`)을 가진다. 경고 타일을 `--warning`으로 채우려면 lead 안에서 `w-full h-full` 요소로 덮어야 하는데, 박스의 `overflow: hidden`과 모서리가 그대로 적용되는지 확인한다. 이 방식이 막히면 사본·원본에 손대지 말고 승인 항목으로 올린다.
2. **본문 눌림 피드백**: 지금은 본문 링크에 `active:opacity-70`, 아바타 링크에 `active:scale-95`가 따로 있다. `ListRow`는 행 전체 눌림(0.98)만 준다. 둘을 `ListRow`의 눌림으로 통일하고 개별 효과는 버리는 안을 기본으로 판정한다.
3. **2단 링크의 클릭 영역**: `leadHref`가 있으면 lead는 행 클릭 영역 밖이라 행 전체 눌림이 본문 쪽에만 걸린다. 아바타만 눌렀을 때 시각 반응이 어떻게 되는지 확인하고 받아들일 수 있는지 판정한다.
4. **반전 행의 시간 색**: `inventory_full`의 시간은 지금 `text-snow/70`이다. `ListRow` inverse 톤의 `--muted-on-inverse`와 같은 값인지 확인한다.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경 파일은 3개지만 시험 마크업 고정 문자열이 많아 100줄 이상이 될 수 있고, 위치가 전부 확정돼 있어 탐색이 필요 없다).

1. `NotificationsClient.tsx` — import에서 `ListRowCard`를 `ListRow`·`ListRowEm`으로 교체(8줄). `RowIcon`(105~142줄)은 박스 크기 클래스(`w-10 h-10`)를 걷고 아이콘만 남긴다(경고는 채움 요소). `NotificationBody`(148~171줄)는 `<p>` 대신 조각 모음을 돌려주고 굵은 토큰을 `ListRowEm`으로 그린다. `NotificationRow`(173~221줄)는 두 갈래(2단 링크·단일)를 `ListRow` 한 호출로 합친다.
2. `NotificationsClient.test.tsx` — 40×40 타일 문자열(274·316·362·399줄 근처)과 `bg-background-inverse`·`border-background-inverse`(478~512줄 근처) 고정 문자열을 새 마크업 기준으로 바꾼다. 2단 링크 마크업(`<a>` 안에 `<a>` 없음)과 제목이 줄 제한 없이 그려진다는 시험을 추가한다.
3. `docs/service/prd/notification/PRD.md` 화면 설명 한 줄, 상위 티켓 4단계 표.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 알림 행이 `ListRow`다. lead 48, 시간이 제목 줄 오른쪽 끝, 제목은 줄 제한 없이 전체가 보이고 «핵심어만 굵게»다.
- 아바타 행은 `leadHref`+`leadLabel`로 2단 링크이고 `<a>` 안에 `<a>`가 없다. 접근 가능한 이름은 기존 `d.notifications.avatarLinkLabel`과 같다.
- 경고 행은 `--warning` 면 + `role="img"` + `aria-label`이 유지된다. `inventory_full`만 반전 톤이다.
- 알림 29종의 문구·링크 목적지는 바뀌지 않는다(기존 시험의 의미가 유지된다).
- 긴 문장(줄 제한 없음)과 긴 닉네임(공백 없음)이 320px에서 가로로 넘치지 않는다. 실렌더로 확인한 값이 기록돼 있다.
- `NotificationsClient.test.tsx`와 `scripts/verify.sh`가 통과하고 `serviceLiteralColors` 시험이 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging(stage.j-a-m.app)에서 알림 화면 확인과 Vercel 배포 상태 확인.
- 판정 1~4 결과를 상위 티켓 «4단계 진행» 절에 기록한다.
