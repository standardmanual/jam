# [UI] 목록 행 4단계 2-2배치: 레시피 행·등급 올리기 입구 행을 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 믹스(combine) 화면의 행 세 곳을 `ListRow`로 옮긴다. ① 레시피 보상 행 `RecipeRewardRow`(탐색 목록과 믹서 상단 요약바가 같은 컴포넌트를 공유) ② 등급 올리기 입구 행(`CombineClient.tsx`) ③ 등급 올리기 컬렉션 고르기 행(`TierUpCollectionPicker.tsx`). 상위 티켓 4단계 2배치의 뒤 절반이다(앞 절반은 20261107_0010).
- 구현 계획: 채원 사전 판정(매핑표·판정 4건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획». 20261107_0010이 머지된 뒤 시작한다(공유 파일은 없지만 상위 티켓과 `FeedSection` 이후 같은 사본을 쓴다).
- 관련 파일: `jam-web/src/app/(main)/combine/RecipeRewardRow.tsx`(전체 139줄), `CombineClient.tsx`(등급 올리기 입구 1033~1036줄, 레시피 행 호출 940줄·1075줄은 prop만 넘기므로 바뀌지 않는다), `TierUpCollectionPicker.tsx`(행 컴포넌트 `TierUpCollectionRow`, 91~99줄), 시험 `CombineClient.test.tsx`(`RecipeRewardRow` 공개 예정 줄·제목 굵기 시험, 305~330줄·1023줄 근처)·`CombineClient.tierUp.test.tsx`(`ListRowCard` 타입으로 입구 행을 찾는 곳 179줄)·`TierUpCollectionPicker.test.tsx`(행 마크업 고정, 45~150줄).

## 배경 / 문제 정의

레시피 행은 «제목 + 슬롯 개수 원 + 등급 칩 + 배지명 + 공개 예정 + 포인트 값»이 한 행에 들어가 정보가 가장 많다(1단계 조사의 B1, 최악 사례 «레시피 B1»). 지금은 `ListRowCard`의 `children`으로 마크업을 직접 짜서 제목 굵기를 `ListRowCardTitle`로 맞추는 임시 방편이 붙어 있다. 등급 올리기 행은 두 줄 라벨·값 구성이다.

## 사용자 결정 (1~3단계에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 12px muted. `eyebrow`가 있으면 그 줄 오른쪽 끝, 없으면 제목 줄 오른쪽 끝(`time` 슬롯).
- lead(썸네일)는 모든 행에서 48px 한 가지. `ListRow` 본체에 크기 prop은 없다.
- 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`(1배치 20261106_2252에서 추가)를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1배치에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`로 넘긴다(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322).

## 범위

1. `RecipeRewardRow`를 `ListRow` 기반으로 다시 쓴다. 바깥 prop(`title`·`slotCount`·`badges`·`points`·`onClick`·`className`·`releaseAt`·`noReward`·`rewardLocked`)은 바꾸지 않아 호출부 두 곳(`CombineClient.tsx` 940줄·1075줄)은 그대로다.
2. 등급 올리기 입구 행(`CombineClient.tsx` 1033~1036줄)을 `ListRow`로 바꾼다(제목 + 보조 줄 + 오른쪽 쉐브론).
3. `TierUpCollectionRow`를 `ListRow`로 바꾼다(lead = 컬렉션 타일, 라벨·값 두 줄, 선택 가능하면 쉐브론, 제출 중 `disabled`).
4. 시험 세 파일의 마크업 고정 부분을 새 마크업에 맞게 고친다.
5. 문서: 믹스 PRD(`docs/service/prd/01_PRD.md` 믹스(레시피) 화면을 다루는 절(전용 PRD가 없다. 절을 찾지 못하면 갱신 대상 없음으로 보고))에 행 모양 변경 한 줄, 상위 티켓 4단계 표.

범위 밖: 알림(20261107_0010), `ListRowCard` 삭제, 레시피 이름·보상 계산 로직, 믹서 본체, `RarityBadge` 크기 승격(티켓 20261106_2322).

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| 배지 이미지 40 `rounded-full` 원 / 코인·상자 아이콘 원 | `lead`(타일 48). 배지 이미지는 `alt=""`, 폴백은 아이콘 |
| `ListRowCardTitle`(제목 굵게 한 줄) | `title`(strong, 1줄 말줄임) |
| 슬롯 개수 20px 회색 원 | `titleSuffix`(줄어들지 않는 인라인 노드) |
| 부제: 등급 칩 + «잠김» 칩 + 배지명(+N) | `chips`(등급 칩·«잠김» 칩) + `meta`(배지명 +N) 또는 한 줄 조합. 채원이 판정 |
| «보상 없음» 부제 | `meta` |
| «공개 예정 · 날짜»(두 조각, 날짜가 통째로 내려감) | 판정 필요(아래 1번) |
| 오른쪽 `PointText`(쌓은 배치) | `value` |
| 등급 올리기 입구: 제목 + 보조 + `ChevronRightIcon` | `title` + `meta`(`metaLines` 2) + `chevron` |
| 등급 올리기 컬렉션 행: `CollectionTile` 40 + 라벨(14px) + 값(16px) | `lead` + `eyebrow`/`meta` 또는 `titleVariant="label"` 조합. 채원이 판정 |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **공개 예정 줄의 자리**: `footer`는 `variant="media"` 전용이다. 레시피 행을 default로 둘지 media로 둘지, 아니면 `meta`에 두 조각을 `whitespace-nowrap`으로 넣을지 정한다. 날짜가 말줄임되면 안 된다(정보라서). `metaLines`는 말줄임이라 날짜가 잘릴 수 있으니 주의한다.
2. **`PointText` 값이 `value` 슬롯에 맞는지**: `value`는 16px 굵게·줄지 않음·세로 중앙이다. `PointText layout="stacked"`(숫자 + 작은 «포인트»)가 그 안에서 높이·정렬이 맞는지 확인한다. 안 맞으면 `trail` 슬롯 쓰임 여부를 판정한다(`trail`은 클릭 영역 밖이라 행 전체 눌림이 아니다).
3. **믹서 상단 요약바**: 같은 `RecipeRewardRow`를 `onClick` 없이(표시 전용) 쓴다. 표시 전용 행도 눌림 피드백이 없어야 한다(`ListRow`는 `onClick`·`href`가 없으면 눌림이 없다). 면 모양(`default` 톤)이 그대로 맞는지 확인한다.
4. **레시피 칩 높이와 한 행의 색 강조 한 곳 규칙**: 등급 칩(8px 글자)과 «잠김» 칩(`LabelChip`)이 같은 줄에 놓인다. `LabelChip`을 `ListRowChip`으로 바꿔야 하는지(12px 한 크기), 등급 칩의 8px는 티켓 20261106_2322 범위라 보정하지 않는지 판정한다.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경 파일이 6개이고 시험 마크업 고정이 많아 100줄 이상이 될 수 있지만, 위치와 prop이 확정돼 있어 탐색이 필요 없다).

1. `RecipeRewardRow.tsx` — 전체를 `ListRow` 호출 한 번으로 다시 쓴다. 바깥 prop과 export는 유지한다. `ListRowCard`·`ListRowCardTitle` import를 걷는다. 파일 머리 주석의 «병존 구현» 설명은 새 사실에 맞게 고친다.
2. `CombineClient.tsx` — import에서 `ListRowCard`를 `ListRow`로 바꾸고 등급 올리기 입구(1033~1036줄)를 옮긴다. 레시피 행 호출은 바꾸지 않는다.
3. `TierUpCollectionPicker.tsx` — `TierUpCollectionRow`(91~99줄)를 옮긴다. 시트 안 줄(`TribeStep` 단일 선택 관용구)은 이번 범위가 아니다.
4. 시험: `CombineClient.test.tsx`(제목 굵기 시험 1023줄과 공개 예정 줄 시험 305~330줄을 새 마크업 기준으로), `CombineClient.tierUp.test.tsx`(입구 행을 `ListRowCard` 타입으로 찾는 179줄을 `ListRow`로), `TierUpCollectionPicker.test.tsx`(행 마크업 고정 45~150줄). 새 마크업에서도 의미(공개 예정 날짜 비말줄임, 보상 없음, 잠김 칩, 제출 중 잠김)는 그대로 고정한다.
5. 문서 두 곳.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 레시피 행이 `ListRow`다. 제목 굵게 한 줄, 슬롯 개수 원이 제목 끝에 붙고 제목이 길면 제목만 잘린다.
- 공개 예정 날짜가 어떤 폭에서도 말줄임되지 않는다(실렌더 확인 값 기록).
- 보상 있음(배지+포인트, 배지만, 포인트만)·보상 없음·잠김·공개 예정 변형이 모두 기존과 같은 정보를 그린다.
- 믹서 상단 요약바(표시 전용)는 눌림 피드백이 없고, 탐색 목록 행(`onClick`)은 눌림이 있다.
- 등급 올리기 입구 행과 컬렉션 고르기 행이 `ListRow`이고 제출 중 `disabled`가 유지되며, 정적 행(재료 없음·후보 없음)은 눌러도 아무 일이 없다.
- 한국어 문장은 `break-keep`을 유지한다(`ListRow`의 `word-break: keep-all`로 대체되는 곳은 그 사실이 시험에 남아 있다).
- 세 시험 파일과 `scripts/verify.sh`가 통과하고 `serviceLiteralColors` 시험이 통과한다.
- 320px·360px에서 최악 사례(레시피 B1: 보상 배지 여러 개 + 「잠김」 칩 + 포인트 + 「공개 예정 · 10월 6일 오후 3시 30분」)의 실렌더 값이 기록돼 있다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging에서 믹스 화면 확인과 Vercel 배포 상태 확인.
- 판정 1~4 결과를 상위 티켓에 기록하고 3배치(나머지 `ListRowCard` 사용처) 계획을 세운다.
