# [UI] 목록 행 4단계 3-1배치: 사람 행(팔로워·팔로잉 탭, 팔로우 목록, 검색 결과)을 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 사람을 보여 주는 행 세 곳을 `ListRow`로 옮긴다. ① 프로필의 팔로워·팔로잉 탭(1단계 C1) ② 팔로워·팔로잉 페이지 `FollowUserList`(C2) ③ 검색 결과(C3). 상위 티켓 4단계 3배치의 첫 회차다.
- 구현 계획: 채원 사전 판정(매핑표·판정 3건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/profile/ProfileClient.tsx`(import 17줄, 팔로워·팔로잉 탭의 `ListRowCard` 502~534줄), `jam-web/src/app/(main)/[username]/FollowUserList.tsx`(import 7줄, 행 59~81줄), `jam-web/src/app/(main)/search/page.tsx`(import 7줄, 행 122~137줄), 시험 `ProfileClient.capsule.test.tsx`·`ProfileClient.chapter.test.tsx`(팔로워·팔로잉 탭 마크업을 읽는 곳이 있는지 확인), `jam-web/src/components/ui/ListRow.tsx`(읽기만).

## 배경 / 문제 정의

세 곳 모두 «원형 아바타 + 이름 한 줄 + 오른쪽 한 가지(팔로우 버튼 또는 쉐브론)» 구성이라 `ListRow`의 기본형으로 옮기기 쉽다. 지금은 아바타 크기가 40이고 폴백 아이콘 크기가 곳마다 다르다(탭·검색은 20, `FollowUserList`는 16). `FollowUserList`는 행 전체가 아니라 안쪽 `Link`가 이름과 아바타만 감싸고, 팔로우 버튼은 `trailing`에 있다. 상위 티켓 1단계 조사의 C1~C3 행이다.

## 사용자 결정 (1~3단계에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 12px muted. `eyebrow`가 있으면 그 줄 오른쪽 끝, 없으면 제목 줄 오른쪽 끝(`time` 슬롯).
- lead(썸네일)는 모든 행에서 48px 한 가지. `ListRow` 본체에 크기 prop은 없다.
- 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1·2배치(20261106_2252, 20261107_0010, 20261107_0011)에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`로 넘긴다(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322).
- `ListRow`는 `<style>`을 행마다 함께 내보내므로 정적 마크업(`renderToStaticMarkup`)의 `href=`·텍스트 검사는 style을 먼저 걷어야 한다(2-2에서 `kindPreview.test`·`TierUpPanel.test`가 이렇게 고쳐졌다. 티켓 20261107_1815).
- 실렌더는 메인 트리 개발 서버(`preview_start jam-web`)에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. 세 곳의 `ListRowCard`를 `ListRow`로 바꾼다.
   - lead: 아바타 이미지는 `leadShape="round"`, `alt=""`(이름은 제목이 이미 읽어 준다). 이미지가 없을 때는 `UserIcon`(`w-5 h-5 text-muted`)이고 48 박스는 `ListRow`가 준다. 폴백 아이콘 크기를 20 한 가지로 맞춘다.
   - 제목: `title={getDisplayName(u)}`, `titleVariant="strong"`이 아니라 기본(판정 1).
   - 링크: `href={`/${u.username}`}`. `FollowUserList`는 안쪽 `Link`를 걷고 행 전체를 `href`로 만든다. 팔로우 버튼은 `trail`에 둔다(클릭 영역 밖이라 `stopPropagation`·`preventDefault`가 필요 없다).
   - 프로필 탭의 `onNavigate`(해시 제거, 티켓 20260902_0915)는 `ListRow`의 `onClick`(링크 클릭 시 호출됨)으로 옮긴다. 이동 직전에 `window.location.hash`를 지우는 동작이 유지돼야 한다.
   - 검색 결과의 오른쪽 `ChevronRightIcon`은 `chevron` prop으로 바꾼다.
2. 팔로우 버튼(`Button`·`FollowButton`)은 모양을 바꾸지 않는다. `trail` 안에서 높이·정렬이 맞는지만 확인한다(`.ds-list-row-trail`이 터치 영역 44px를 자동으로 준다).
3. 시험: 팔로워·팔로잉 탭 마크업을 읽는 시험이 있으면 새 마크업에 맞게 고치고, 없으면 `ListRow` 조합 시험을 추가한다(탭 행의 해시 제거·본인 행에 버튼 없음·`href` 행에 `<a>` 안 `<a>` 없음).
4. 문서: 프로필 팔로워·팔로잉 화면을 다루는 PRD 절(`docs/service/prd/01_PRD.md`에서 탐색, 없으면 갱신 대상 없음으로 보고)에 행 모양 변경 한 줄, 상위 티켓 4단계 표.

범위 밖: 팔로우 버튼 모양, 팔로우 로직과 배지 획득 오버레이(`BadgeRevealOverlay`), `ListRowCard` 삭제.

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| 40 원형 아바타(`Image`·`alt`=이름) / 폴백 원 + 아이콘 16·20 | `lead` + `leadShape="round"`, 이미지 `alt=""`, 폴백 `UserIcon w-5 h-5 text-muted` |
| `title`(이름 16) | `title`(기본 변형) |
| `trailing` 팔로우 버튼 | `trail` |
| `trailing` 쉐브론(검색) | `chevron` |
| 탭의 `onNavigate`(해시 제거) | `onClick`(`Link`에 전달됨) |
| `FollowUserList`의 안쪽 `Link`(이름·아바타만) | 행 전체 `href` |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **제목 굵기**: 지금 이름은 16px 일반 굵기(`FollowUserList`는 `text-base`, 나머지는 기본)다. `titleVariant`의 `strong`(굵게 1줄)으로 올릴지 기본으로 둘지 정한다. 사람 행에서 이름만 있는 한 줄이라 기본 유지를 기본 안으로 한다.
2. **`FollowUserList` 클릭 영역 변경**: 지금은 아바타·이름만 눌리고 행의 빈 곳은 눌리지 않는다. 행 전체가 눌리도록 바뀌는 것을 받아들일 수 있는지 확인한다(탭·검색은 이미 행 전체다).
3. **`trail` 버튼 줄 맞춤**: 팔로우 버튼이 `trail` 슬롯에서 세로 중앙에 놓이고 행 높이를 키우지 않는지 확인한다. 이름이 긴 행(공백 없는 닉네임)에서 버튼이 밀려 나가지 않는지도 본다.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경 파일이 3개 + 시험이고 위치가 전부 확정돼 있어 탐색이 필요 없다. 시험 추가분 때문에 줄 수가 100줄 안팎이 될 수 있다).

1. `ProfileClient.tsx` — import 17줄 `ListRowCard` → `ListRow`. 502~534줄 행을 옮긴다(`onNavigate` → `onClick`, `icon` → `lead`, `trailing` → `trail`). 289줄 주석의 «ListRowCard의 onNavigate와 동일한 패턴» 설명은 새 사실에 맞게 고친다.
2. `FollowUserList.tsx` — import 7줄, 행 59~81줄. 안쪽 `Link`를 걷고 `href`로 올린다. `Image` 크기 속성(`width={40}`)은 `ListRow`가 48 박스를 주므로 맞춰 바꾼다(`next/image`의 `width`·`height`는 원본 크기 힌트).
3. `search/page.tsx` — import 7줄, 행 122~137줄.
4. 시험: 팔로워·팔로잉 탭 마크업을 읽는 `ProfileClient.*.test.tsx` 단언 확인·수정, 필요하면 새 시험 파일.
5. 문서 두 곳.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 세 곳이 `ListRow`다. lead 48 원형, 폴백 아이콘 20 한 가지다.
- 프로필 탭에서 다른 사람 프로필로 이동하면 `/{username}#followers`의 해시가 지워진 채 이동한다(기존 동작 유지).
- `FollowUserList`·프로필 탭의 본인 행에는 팔로우 버튼이 없고, 다른 행의 버튼은 눌러도 행 이동이 일어나지 않는다.
- 긴 닉네임(공백 없음)이 320px에서 가로로 넘치지 않고 버튼이 밀려 나가지 않는다. 실렌더 값이 기록돼 있다.
- 변경한 시험 파일과 `scripts/verify.sh`가 통과하고 `serviceLiteralColors` 시험이 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging에서 프로필 팔로워·팔로잉 탭, 팔로우 목록, 검색 결과 확인과 Vercel 배포 상태 확인.
- 판정 1~3 결과를 상위 티켓 «3배치 진행» 절에 기록하고 3-2를 시작한다.
