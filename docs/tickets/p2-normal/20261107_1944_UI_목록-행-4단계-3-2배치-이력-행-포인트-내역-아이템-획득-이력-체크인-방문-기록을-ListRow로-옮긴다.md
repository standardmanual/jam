# [UI] 목록 행 4단계 3-2배치: 이력 행(포인트 내역, 아이템 획득 이력, 체크인 방문 기록)을 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 날짜·값 중심의 이력 행 세 곳을 `ListRow`로 옮긴다. ① 포인트 내역(`points/page.tsx`, 1단계 A5) ② 배지 상세의 아이템 획득 이력(`ItemEarnHistory`, A6) ③ 배지 상세의 체크인 방문 기록(`PoiEarnHistory`, A7). 상위 티켓 4단계 3배치의 두 번째 회차다. 3-1이 머지된 뒤 시작한다.
- 구현 계획: 채원 사전 판정(매핑표·판정 4건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/points/page.tsx`(import 8줄, 행 126~145줄), `jam-web/src/app/(main)/badges/[id]/ItemEarnHistory.tsx`(import 5줄, 행 78~86줄), `jam-web/src/app/(main)/badges/[id]/PoiEarnHistory.tsx`(import 5줄, 행 87~98줄), 시험 `points/page.test.tsx`·`badges/[id]/PoiEarnHistory.test.tsx`(`ItemEarnHistory` 전용 시험은 없다), `jam-web/src/components/ui/ListRow.tsx`(읽기만).

## 배경 / 문제 정의

포인트 내역은 «코인 원 + 제목 + 사유·날짜 두 줄 + 오른쪽 값»이고, 두 이력 행은 lead 없이 날짜(그리고 «처음 받은 날» 칩)만 있는 행이다. 이력 행의 오른쪽은 쉐브론이며 누르면 바텀시트로 상세를 연다. 날짜는 `LocalDate`(클라이언트에서 지역 시간으로 그리는 컴포넌트)로 그려진다. 1단계 조사의 A5·A6·A7 행이다.

## 사용자 결정 (1~3단계에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 12px muted. `eyebrow`가 있으면 그 줄 오른쪽 끝, 없으면 제목 줄 오른쪽 끝(`time` 슬롯).
- lead(썸네일)는 모든 행에서 48px 한 가지. `ListRow` 본체에 크기 prop은 없다.
- 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1·2배치(20261106_2252, 20261107_0010, 20261107_0011)에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`로 넘긴다(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322).
- `ListRow`는 `<style>`을 행마다 함께 내보내므로 정적 마크업(`renderToStaticMarkup`)의 `href=`·텍스트 검사는 style을 먼저 걷어야 한다(2-2에서 `kindPreview.test`·`TierUpPanel.test`가 이렇게 고쳐졌다. 티켓 20261107_1815).
- 실렌더는 메인 트리 개발 서버(`preview_start jam-web`)에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. 포인트 내역 행: lead = 코인 원(`CoinIcon`, `leadShape="round"`), 제목 = `it.title`, 값 = `formatAmount(it.amount)`(`value` 슬롯, 굵게). 사유(`it.note`)와 날짜는 `meta`로 둔다. 날짜(`formatKoreanDateTime`)는 연도·시각이 들어간 긴 절대 날짜라 `time` 슬롯이 아니라 `meta`(판정 1). `href`가 있는 행만 `href`를 준다.
2. 아이템 획득 이력 행(2번째부터): lead 없음, `title` = `<LocalDate … />`(날짜가 제목), `onClick`으로 시트를 열고 `chevron`을 둔다.
3. 체크인 방문 기록 행(2번째부터): lead 없음, `title` = `<LocalDate … />`, «처음 받은 날» 칩(`LabelChip`)은 `eyebrow`(판정 2), `onClick` + `chevron`.
4. 시험: `points/page.test.tsx`·`PoiEarnHistory.test.tsx`의 마크업 고정 단언을 새 마크업 기준으로 고친다(날짜 문자열·칩 표시·`href` 유무·시트 열기 동작의 의미는 유지). `ItemEarnHistory`는 시험이 없으므로 `ListRow` 조합을 확인하는 시험을 하나 추가한다.
5. 문서: 포인트 내역 화면 PRD(`docs/service/prd/point-system/INTERACTION_FLOW.md`에서 행 모양을 다루는 절을 찾는다), 배지 상세 이력 PRD 절(`docs/service/prd/01_PRD.md`에서 탐색, 없으면 갱신 대상 없음으로 보고), 상위 티켓 4단계 표.

범위 밖: 이력 상세 바텀시트 내용, 첫 항목 카드(`Card` + `ItemCardContent`·`EarnCardContent`), 포인트 적립·차감 로직, 더 보기 버튼.

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| 포인트 내역 40 코인 원(`bg-background-secondary`) | `lead`(`CoinIcon`) + `leadShape="round"` |
| `title` + `subtitle`(사유 12/muted + 날짜 12/muted, 세로 두 줄) | `title` + `meta`(사유, 날짜) |
| `trailing` 포인트 값(16 굵게) | `value` |
| 획득 이력 `children` 날짜 16 + 쉐브론 | `title`(날짜) + `chevron` + `onClick` |
| 방문 기록 `children`(«처음 받은 날» 칩 + 날짜) + 쉐브론 | `eyebrow`(칩) + `title`(날짜) + `chevron` + `onClick` |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **포인트 내역의 날짜 자리**: `time` 슬롯은 12px muted로 제목 줄 오른쪽 끝에 붙는다. 이 행의 날짜는 «2026년 11월 7일 오후 3시 30분»처럼 길어 `ListRow.prompt.md`의 time 규정(긴 절대 날짜는 `meta`로 내린다)대로 `meta`에 두는 안을 기본으로 판정한다. 사유(`note`)가 없을 때와 있을 때의 줄 수와, 오른쪽 `value`와의 정렬을 확인한다.
2. **«처음 받은 날» 칩**: 칩이 `eyebrow`에 놓이면 날짜 위에 놓인다(지금과 같은 순서). `LabelChip`(12px 굵게 대문자)을 `ListRowChip`(12px 일반)으로 바꿀지 판정한다(2-2의 «잠김» 칩 선례는 `ListRowChip`).
3. **`LocalDate` 컴포넌트와 phrasing**: `LocalDate`가 `<span>`·`<time>` 같은 phrasing 요소만 그리는지 확인한다(`<div>`면 클릭 영역 안에 둘 수 없다). `title`에 ReactNode를 줄 수 있는지, 말줄임·줄 제한 설정과 충돌하지 않는지도 확인한다.
4. **lead 없는 행의 정렬**: 날짜만 있는 행의 높이가 최소 터치 영역(44px) 근처인지, 같은 목록 안의 첫 카드(`Card`)와 위아래 간격이 어색하지 않은지 본다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 세 곳이 `ListRow`다. 포인트 내역은 코인 lead + 제목 + 사유·날짜 + 오른쪽 값이고, 두 이력 행은 lead 없는 날짜 행이다.
- 날짜가 어떤 폭에서도 말줄임되지 않고 값(`value`)과 겹치지 않는다. 실렌더 값이 기록돼 있다.
- `href`가 없는 포인트 내역 행은 눌려도 아무 일이 없다. 이력 행을 누르면 기존처럼 바텀시트가 열린다.
- «처음 받은 날» 칩은 해당 행에만 보인다.
- 변경한 시험 파일과 `scripts/verify.sh`가 통과하고 `serviceLiteralColors` 시험이 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging에서 포인트 화면, 배지 상세의 획득 이력·방문 기록 확인과 Vercel 배포 상태 확인.
- 판정 1~4 결과를 상위 티켓 «3배치 진행» 절에 기록하고 3-3을 시작한다.
