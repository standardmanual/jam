# [UI] 목록 행 4단계 3-3배치: 대상 행(미션 포인트 보상, 배지 상세 컬렉션 링크)을 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 큰 화면 안에 한 줄씩 놓인 행 두 곳을 `ListRow`로 옮긴다. ① 미션 상세의 포인트 보상 행(`MissionDetailClient`, 1단계 B5) ② 배지 상세의 «속한 컬렉션» 링크 행(`badges/[id]/page.tsx`, B6). 상위 티켓 4단계 3배치의 세 번째 회차다. 3-2가 머지된 뒤 시작한다.
- 구현 계획: 채원 사전 판정(매핑표·판정 3건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.tsx`(import 14줄, 포인트 보상 행 552~562줄), `jam-web/src/app/(main)/badges/[id]/page.tsx`(import 8줄, 컬렉션 링크 445~471줄), 시험 `MissionDetailClient.test.tsx`·`MissionDetailClient.claim.test.tsx`·`MissionDetailClient.notice.test.tsx`·`badges/[id]/__tests__/page.test.tsx`·`page.locked.test.tsx`·`page.item-book.test.tsx`(마크업을 읽는 곳만 고친다), `jam-web/src/components/ui/ListRow.tsx`(읽기만).

## 배경 / 문제 정의

두 행 모두 이미지 한 칸과 제목 한 줄이 전부다. 미션 보상 행은 `tone="tint"`로 같은 영역의 배지 보상 행(`Card tone="tint"`, 이번 배치 밖)과 면을 맞춘다. 컬렉션 링크는 lead가 44px `rounded-2xl`이라 48로 바뀌고, 이미지는 `SafeImage`(미등록 호스트로 화면 전체가 500이 나는 것을 막는 래퍼, 티켓 20260824_005)로 그려진다. 1단계 조사의 B5·B6 행이다.

## 사용자 결정 (1~3단계에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 12px muted. `eyebrow`가 있으면 그 줄 오른쪽 끝, 없으면 제목 줄 오른쪽 끝(`time` 슬롯).
- lead(썸네일)는 모든 행에서 48px 한 가지. `ListRow` 본체에 크기 prop은 없다.
- 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1·2배치(20261106_2252, 20261107_0010, 20261107_0011)에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`로 넘긴다(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322).
- `ListRow`는 `<style>`을 행마다 함께 내보내므로 정적 마크업(`renderToStaticMarkup`)의 `href=`·텍스트 검사는 style을 먼저 걷어야 한다(2-2에서 `kindPreview.test`·`TierUpPanel.test`가 이렇게 고쳐졌다. 티켓 20261107_1815).
- 실렌더는 메인 트리 개발 서버(`preview_start jam-web`)에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. 미션 포인트 보상 행: lead = `CoinIcon`(`leadShape="round"`, 지금의 `--accent` 면 + `--accent-foreground` 아이콘 색은 판정 1), 제목 = `tPoint(rewardPointsLine, …)`, `tone="tint"`. `onClick`·`href`가 없는 표시 전용 행이다(눌림 없음).
2. 컬렉션 링크 행: lead = `SafeImage`(`alt=""`, `leadShape="tile"`, 폴백 `BookIcon`), `title` = `itemBook.name`, `href`와 `chevron`. `?u=` 쿼리가 붙는 href 로직은 그대로 둔다.
3. 시험: 위 시험 중 두 행의 마크업을 읽는 단언(`ListRowCard` 클래스·40×40 박스·44 이미지 등)만 새 마크업에 맞게 고친다. 의미(보상 점수 문구, 컬렉션 링크 목적지·`?u=` 유지, 폴백 표시)는 유지한다.
4. 문서: 미션 상세·배지 상세 PRD 절(`docs/service/prd/01_PRD.md`에서 탐색, 없으면 갱신 대상 없음으로 보고), 상위 티켓 4단계 표.

범위 밖: 미션 상세의 배지 보상 행·잠긴 보상 행(직접 마크업, 1단계 B3·B4, 4배치 미디어 행 변형에서 다룬다), 미션 목록, 컬렉션 화면.

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| 40 서클 `CoinIcon`(`--accent` 면) | `lead` + `leadShape="round"` |
| `title`(보상 문구) | `title` |
| `tone="tint"` | `tone="tint"` |
| 44 `rounded-2xl` `SafeImage` + 폴백 `BookIcon` | `lead` + `leadShape="tile"`, 이미지 `alt=""` |
| `trailing` 쉐브론 | `chevron` |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **코인 lead의 면 색**: `ListRow`의 lead 박스는 자체 면색을 가진다. 지금의 강조색 면(`--accent`)을 `ListRow` 위에서 어떻게 나타낼지 판정한다(lead 안을 `w-full h-full` 요소로 채우는 2-1 경고 타일 선례, 또는 기본 면 + 아이콘만). 이 방식이 막히면 사본·원본에 손대지 말고 승인 항목으로 올린다.
2. **`SafeImage`의 이미지 맞춤**: 컬렉션 이미지는 지금 `object-contain p-1`(여백을 두고 전체가 보이게)로 그려진다. `ListRow` lead는 `object-fit: cover`라 정사각이 아닌 이미지가 잘릴 수 있다(2-2 게이트의 같은 발견). 어드민이 올리는 컬렉션 이미지의 실제 비율을 확인하고, 잘림이 허용되는지 판정한다. 안 되면 원본 변경이 필요한 승인 항목이다.
3. **표시 전용 tint 행의 눌림**: `onClick`·`href`가 없으면 `ListRow`는 눌림 피드백이 없다. 지금 `ListRowCard`가 같은 동작인지 확인하고, tint 면이 배지 보상 행(`Card tone="tint"`)과 나란히 놓였을 때 어긋나지 않는지 본다.

## 완료 기록

### 구현 내용 요약

- 미션 상세의 포인트 보상 행(`MissionDetailClient.tsx`)을 `ListRow`로 옮겼다. `tone="tint"`, `leadShape="round"`, lead는 `var(--accent)` 면을 채운 `<span>` 안의 `CoinIcon`(`--accent-foreground`)이다. `href`·`onClick`이 없는 표시 전용 행이고 눌림이 없다. 조건부 렌더와 `tPoint` 호출은 그대로다.
- 배지 상세의 «속한 컬렉션» 링크 행(`badges/[id]/page.tsx`)을 `ListRow`로 옮겼다. 기본 톤, `leadShape="tile"`, lead는 `SafeImage` 48×48(`alt=""`)이고 폴백은 `BookIcon`(`w-5 h-5 text-muted`)만 넘긴다. 쉐브론은 `chevron` prop이다. `href`(`?u=` 포함)는 한 글자도 바꾸지 않았다. `object-contain`·`p-1`·`containerClassName`·44px 폴백 박스를 걷었다.
- 시험: `page.item-book.test.tsx`의 컴포넌트 이름 탐색만 `ListRow`로 바꿨다. 문구·`href`·`title`을 읽는 시험의 의미는 그대로다. 문서는 상위 티켓 4단계 표(3-3)만 갱신했고, `01_PRD.md`에는 행 모양을 서술한 절이 없어 갱신 대상 없음이다.

### 채원 사전 판정 (needsApproval: false)

1. 코인 lead의 강조색 면은 lead 안을 `w-full h-full` 요소로 채우는 2-1 경고 타일 방식으로 해결된다(사본·원본 변경 없음). 면 색은 `MissionDetailClient.test.tsx`가 `background:var(--accent)` 개수를 세므로 인라인 스타일로 준다.
2. 컬렉션 이미지는 `ListRow` lead의 `object-fit: cover`로 바뀐다(호출부 클래스로는 덮을 수 없다). 정사각은 가장자리 여백(4px)만 사라지고, 정사각이 아니면 중앙 기준으로 잘린다. 허용 여부는 실제 비율 확인 뒤로 두었다.
3. 표시 전용 tint 행은 지금도 눌림이 없고 높이(72px)·모서리·면이 같다.

### 컬렉션 이미지 비율 확인 (머지 전, 읽기 전용 쿼리와 PNG 헤더)

- `item_books` 106개 중 이미지가 있는 것은 56개이고, **56개 모두 비활성 컬렉션**이다. 활성 컬렉션 15개는 이미지가 없어 현재는 `BookIcon` 폴백이 보이고 잘림이 생기지 않는다.
- 이미지 56개 중 원격 저장소(`itembooks/`·`badges/factions|tribes/`) 28개는 27개가 정사각이고 1개가 1080×1073(차이 0.6%)이다. 사실상 잘림이 없다.
- 나머지 28개는 `/badges/sample/…` 샘플 이미지이고 이 가운데 26개가 정사각이 아니다(예: 355×192, 843×336, 389×132). 비활성이라 지금은 보이지 않지만, 개체가 한 번이라도 만들어지면 상세 화면에 링크로 보이며 그때 중앙 기준으로 잘린다. 활성 컬렉션이 새 이미지를 받게 될 때도 같은 확인이 필요하다.

### 실렌더 측정 (메인 트리 개발 서버, 폭 320px, 테스트 계정)

- 미션 포인트 보상 행(미션 `e66f802f…`): `<div>`·`data-interactive="false"`(눌림 없음), 높이 74(안쪽 72 + 테두리 2), lead 48 원형(`border-radius` 9999px), lead 안 면 `rgb(25, 181, 81)`, 행 면 `rgb(233, 231, 224)`(tint), 가로 넘침 없음. «10 포인트»가 한 줄로 보인다.
- 컬렉션 링크 행(배지 `27c18a29…`, 활성 컬렉션이라 이미지 없음): `<a>` + `/collections/{id}`(내 배지라 `?u=` 없음), 높이 74, lead 48 타일(모서리 16px, 면 `rgb(233, 231, 224)`), 폴백 `BookIcon` 20·쉐브론 20, 행 안 `<div>`·`<p>`·`a a` 0개, 가로 넘침 없음. 제목 굵기 700.
- 컬렉션 이름 «비 오는 날의 기름 냄새»(13자)는 320px에서 한 줄 말줄임(«비 오는 날의 기름 …»)이다. 이전에도 `truncate`였고, 굵기가 보통에서 700으로 바뀌어 더 일찍 잘린다. 행 전체가 링크라 눌러서 컬렉션에서 전체 이름을 볼 수 있다.
- 비정사각 이미지의 실제 잘림은 활성 컬렉션에 이미지가 없어 화면에서 보지 못했다. 남의 배지(`?u=`) 경로, 360·390px도 측정하지 못했다.
