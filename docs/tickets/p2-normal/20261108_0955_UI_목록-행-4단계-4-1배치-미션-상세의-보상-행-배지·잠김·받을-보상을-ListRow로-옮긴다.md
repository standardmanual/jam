# [UI] 목록 행 4단계 4-1배치: 미션 상세의 보상 행(배지·잠김·받을 보상)을 서비스용 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 미션 상세의 보상 행 세 곳을 `ListRow`(lead 48)로 옮기고, 같은 보상 박스 안 포인트 행(3-3에서 이미 `ListRow tone="tint"`)과 높이를 맞춘다. ① 배지 보상 행(1단계 B3) ② 잠긴 보상 행 `LockedRewardRow`(B4) ③ 받을 보상 행 `PendingRewardRow`(B8, 1단계 표에 없던 줄). 상위 티켓 4단계 4배치의 첫 회차이고, 4-2(미션 목록)는 이 회차가 머지된 뒤 시작한다.
- 구현 계획: 채원 사전 판정(매핑표·판정 4건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.tsx`(704줄. `LockedRewardRow` 212줄, `PendingRewardRow` 226줄, 받을 보상 카드 452줄 부근, 보상 박스 515~560줄), 시험 `MissionDetailClient.test.tsx`·`MissionDetailClient.claim.test.tsx`·`MissionDetailClient.notice.test.tsx`(같은 폴더, 마크업을 읽는 단언만 고친다), `jam-web/src/components/ui/ListRow.tsx`(읽기만), `jam-web/design-system/components/cards/LockedTile.jsx`(크기 값 확인만).

## 배경 / 문제 정의

세 행은 모두 lead 64 이미지 + 등급 칩(`RarityBadge`) + 이름(16px 굵게) + 선택 캡션(13px)을 직접 마크업으로 그린다. 같은 보상 박스 안의 포인트 행은 3-3에서 lead 48인 `ListRow`가 되어, 코드상으로는 배지 보상 행과 높이가 다르다. 결정 4(lead 48 고정)에 따라 이 행들도 lead 48로 맞춘다. 실제 데이터에는 열린 배지 보상이 없어 배지 보상 행은 실렌더로 볼 수 없고 시험 값으로만 증명된다.

## 사용자 결정 (1~4배치 조사에서 확정된 것, 이 배치에 그대로 적용)

- 시간은 12px muted. lead(썸네일)는 모든 행에서 48px 한 가지이고 `ListRow` 본체에 크기 prop은 없다.
- 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1~3배치에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`로 넘긴다(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322).
- `ListRow`는 `<style>`을 행마다 함께 내보내므로 정적 마크업(`renderToStaticMarkup`)의 `href=`·텍스트 검사는 style을 먼저 걷어야 한다.
- 컬러 개편(20261107_2201)이 닫혔으므로 색은 그 정의를 따른다.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. **배지 보상 행(B3)**: `Link`(`/badges/{id}`)로 감싼 `Card tone="tint"` 안의 직접 마크업을 `ListRow tone="tint" href=…`로 옮긴다. lead = `SafeImage`(`alt=""`, 폴백 🏅), eyebrow = `RarityBadge`, title = 배지 이름, meta = `rewardBadgeCaption`.
2. **잠긴 보상 행(B4)**: `LockedRewardRow`를 `ListRow tone="tint"`로 옮긴다. lead = `LockedTile`(크기 48), eyebrow = `RarityBadge`, title = «잠긴 아이템 배지», meta = 캡션(없으면 `undefined`). 이름·그림·링크·id는 DOM에 없어야 한다(운영 로직 7.3절).
3. **받을 보상 행(B8)**: `PendingRewardRow`를 같은 방식으로 옮긴다. 열린 보상은 `SafeImage` lead + 등급 칩 + 이름이고, 잠긴 보상은 B4 컴포넌트를 그대로 쓴다. 이 행은 `InfoCard`(흰 면) 안에 있어 면 톤은 채원이 판정한다.
4. 시험: 위 세 시험 중 세 행의 마크업을 읽는 단언만 새 마크업에 맞게 고친다. 의미(잠긴 보상에 이름·그림·id 없음, 링크 없음, 등급 칩, 캡션 문구, 보상 순서)는 유지한다.
5. 문서: 미션 상세 PRD 절(`docs/service/prd/01_PRD.md`에서 탐색, 없으면 갱신 대상 없음으로 보고), 상위 티켓 4단계 표.

범위 밖: 미션 목록(4-2), 포인트 보상 행(3-3에서 완료), 미션 달성 행.

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| lead 64 이미지 상자(`rounded-2xl bg-border`) | `lead`(48) + `leadShape="tile"` |
| `LockedTile size={64}` | `lead`(`LockedTile` 48) |
| `RarityBadge`(맨 윗줄) | `eyebrow` |
| 이름 16px 굵게 | `title`(strong) |
| 캡션 13px muted | `meta` |
| `Card tone="tint"` 면 | `tone="tint"` |
| `Link` 래퍼 | `href` |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **eyebrow에 `RarityBadge`를 넣는 방식**: `RarityBadge`는 MODULAR 칩이고 행 안 12px 통일 티켓(20261106_2322)과 겹친다. `ListRowChip`이 아니라 `RarityBadge`를 eyebrow에 그대로 두어도 되는지, 높이가 다른지 판정한다.
2. **`LockedTile` 크기 48**: 원본이 `size`를 받으므로 호출부 값만 바꾸면 되는지, 내부 자물쇠 아이콘 비례가 48에서 어색한지 확인한다. 원본 변경이 필요하면 승인 항목이다.
3. **받을 보상 행의 면 톤**: 흰 `InfoCard` 안이라 `flat`이 맞는지, 박스 안 구분이 필요한지 판정한다.
4. **눌림**: 배지 보상 행만 링크이고 나머지는 표시 전용이다. 한 박스 안에서 행마다 눌림 유무가 달라도 어긋나지 않는지 본다.

4. 배지 행만 링크이고 나머지는 표시 전용이다. 같은 박스 안 포인트 행이 이미 표시 전용이라 새 불일치는 아니다.
