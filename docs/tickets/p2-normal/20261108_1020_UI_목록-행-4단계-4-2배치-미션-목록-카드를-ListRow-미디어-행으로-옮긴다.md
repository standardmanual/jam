# [UI] 목록 행 4단계 4-2배치: 미션 목록 카드(B2)를 서비스용 ListRow 미디어 행으로 옮긴다

## 핵심 요약

- 요구사항: 미션 목록의 카드(`MissionsListClient.tsx`, 1단계 B2)를 `ListRow variant="media" tone="flat"`으로 옮긴다. 썸네일은 사용자 결정(2026-11-08)에 따라 **lead 48 고정**이다. 그림 속 조건 요약 문구가 목록에서 읽히지 않게 되는 것은 받아들이기로 했다(조건은 상세 화면에서 읽는다). 상위 티켓 4단계 4배치의 두 번째 회차이고 4-1(20261108_0955)은 머지됐다.
- 구현 계획: 채원 사전 판정(매핑표·판정 5건 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/missions/MissionsListClient.tsx`(525줄. 색 상수 58~78줄, 보상 노드 95~135줄, `NewBadge` 144줄·`StatusBadge` 164줄·`JoinedBadge` 189줄, `topStatusLabel` 229줄, 카드 렌더 365~515줄), 시험 `MissionsListClient.new-chip.test.tsx`·`MissionsListClient.locked-reward.test.tsx`·`__tests__/page.hidden-reward.test.tsx`(마크업을 읽는 단언만 고친다), `jam-web/src/components/ui/ListRow.tsx`(읽기만. `ListRowChip`도 같은 파일에 있다).

## 배경 / 문제 정의

현재 카드는 직접 마크업이다. 썸네일 90px(`object-contain`, 12px 모서리), 칩 줄(NEW·참가중·상태, 10px 칩을 파일 안에서 그림), 제목 16px 굵게, 설명 12px 2줄 말줄임, 잠긴 미션의 «조건» 줄, 보상 줄(`--link` 굵은 12px, 등급·레벨 칩과 « + » 연결)로 이뤄진다. 320px에서 카드 높이는 제목 1줄이면 134px, 2줄이면 154px다. 잠긴 미션은 `<button aria-disabled>` + 토스트이고, 썸네일만 흑백·딤·자물쇠로 보이고 글자 대비는 유지한다. 열린 미션은 `Link`다.

## 사용자 결정 (1~4배치 조사에서 확정된 것, 이 배치에 그대로 적용)

- **썸네일(lead)은 모든 행에서 48px 한 가지다(예외 없음).** 미션 목록도 90px에서 48px로 줄어든다. 그림 속 조건 요약 문구가 읽히지 않는 것은 받아들인다. 목록에서 조건 정보를 보강하지 않는다(2026-11-08).
- 시간은 12px muted. 새 토큰·MODULAR 변경은 하지 않는다. 서비스 사본 `jam-web/src/components/ui/ListRow.tsx`를 그대로 쓴다. 값이 모자라면 사본을 고치지 말고 보고한다(`ds:check` 쌍 대조).
- 1~4-1배치에서 확정된 규칙을 따른다: 빈 슬롯은 `undefined`(`false`·빈 fragment 금지), lead 안 이미지는 `alt=""`(장식), 클릭 영역 안은 phrasing 요소만 쓴다(`<div>`·`<p>` 금지), 칩 높이는 측정만 하고 호출부에서 덮지 않는다(티켓 20261106_2322), `import { ListRow, ListRowChip } from '@/components/ui/ListRow'`는 named import다.
- `ListRow`는 `<style>`을 행마다 함께 내보내므로 정적 마크업의 `href=`·텍스트 검사는 style을 먼저 걷어야 한다.
- 색은 컬러 개편(20261107_2201) 정의를 따른다. `ListRowChip` 톤은 neutral·accent·warning·done·surface·surface-muted다.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. 카드(365~515줄)를 `ListRow variant="media" tone="flat"`으로 옮긴다.
   - lead = 썸네일 이미지(48, `alt=""`). 이미지가 없으면 지금의 회색 칸 폴백을 쓴다. 잠긴 미션은 흑백(`grayscale`)·딤(0.4)·자물쇠 오버레이를 lead 안 내용으로 옮기고, 시작 전 딤(0.6)도 lead 안에서만 건다(글자 대비 유지).
   - eyebrow = NEW·상태 칩 줄(`ListRowChip`: NEW는 `warning`, 참가중은 `accent`, 완료·기간·시작 전은 `neutral`, 잠김은 `neutral` + 자물쇠 글리프).
   - title = 미션 제목(strong), meta = 설명(`metaLines=2`), footer = 잠긴 미션의 «조건» 줄과 보상 줄(media 전용 슬롯).
   - 열린 미션은 `href={`/missions/${m.id}`}`, 잠긴 미션은 `disabled` 없이 `onClick`으로 토스트를 띄운다(`disabled`는 행 전체 불투명도 0.4와 키보드 차단을 함께 걸어 «썸네일만 흐림, 글자 대비 유지» 규칙과 토스트 동작을 깨기 때문이다).
2. 파일 안 `NewBadge`·`StatusBadge`·`JoinedBadge`와 칩 색 상수(`C_*_BADGE_*`)를 걷는다. 보상 줄 노드 함수(`rewardNodes`·`rewardBadgeNode`·`lockedRewardNode`)는 그대로 쓰되 `footer` 안에 넣는다.
3. 시험: 위 세 시험 중 마크업을 읽는 단언만 새 마크업에 맞게 고친다. 의미(NEW 칩 노출 기준 2일, 잠긴 보상에 이름·그림·id 없음, 숨김 보상, 잠긴 미션의 토스트·링크 없음)는 유지한다.
4. 문서: 미션 목록 PRD 절(`docs/service/prd/01_PRD.md`에서 탐색, 없으면 갱신 대상 없음으로 보고), 상위 티켓 4배치 표.

범위 밖: 미션 상세(4-1에서 완료), 미션 달성 행, 컨텐츠(미션 카피 3회차 20261104_2314).

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | `ListRow` |
|---|---|
| 썸네일 90px(`object-contain`, 12px 모서리) | `lead`(48) |
| NEW·참가중·상태 칩 줄 | `eyebrow`(`ListRowChip`) |
| 제목 16px 굵게 | `title`(strong) |
| 설명 12px 2줄 말줄임 | `meta` + `metaLines=2` |
| «조건» 줄(잠긴 미션만) | `footer` |
| 보상 줄(`--link` 굵게, 칩 + « + ») | `footer` |
| 열린 미션 `Link` | `href` |
| 잠긴 미션 `<button aria-disabled>` + 토스트 | `onClick`(`disabled` 쓰지 않음) |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **잠긴 미션의 표현과 접근성**: `disabled` 없이 `onClick`만 쓸 때 `aria-disabled`를 어떻게 전달하는지(`ListRow`가 `aria-*`를 클릭 영역으로 넘기는지), 눌림 피드백이 열린 행과 같은 정도여도 되는지 판정한다.
2. **보상 줄 색**: 지금은 `--link` 굵은 글자인데 `footer`에는 색 슬롯이 없다. 호출부가 색을 정해도 되는지, 컬러 개편 뒤에도 `--link` 글자색이 남는지 확인한다. 안 되면 승인 항목이다.
3. **칩 크기 변화**: 파일 안 칩은 10px, `ListRowChip`은 12px라 칩이 커진다. 보상 줄 안의 `RarityBadge`·`BadgeLevelChip`은 MODULAR 칩이라 행 안 12px 통일 티켓(20261106_2322)과 겹친다. 이 배치에서 어디까지 맞출지 판정한다.
4. **lead 48 안 상태 표현**: 흑백·딤·자물쇠 오버레이(자물쇠 24px)가 48 안에서 읽히는지, 자물쇠 크기를 줄여야 하는지 판정한다. 그림 속 문구는 어차피 읽히지 않으므로 «알아보는 용도»로 충분한지도 본다.
5. **«조건» 줄과 보상 줄의 `footer` 배치**: 잠긴 미션에서 두 줄이 한 `footer` 안에 같이 들어갈 때 간격과 줄바꿈, 높이를 판정한다.

## 채원 사전 판정에서 올라온 결정 (사용자 결정 2026-11-08, 추천대로)

1. **NEW 칩은 `done` 톤(검정 면 + 흰 글자)이다.** `ListRowChip`의 `warning` 톤은 면 `#525252` 위에 글자 `#171717`이라 대비가 약 2.3:1로 읽기 어렵다(옛 NEW 칩은 같은 면에 흰 글자였다). `warning`은 이 배치에서 쓰지 않고, 톤 정의 수정은 별도 ds 티켓(20261108_1110)으로 올렸다.
2. **참가중 칩도 `done` 톤이다.** `accent` 톤은 면이 `#f5f5f5`라 흰 바탕에서 보이지 않아 강조가 사라진다. NEW와 참가중은 글자로 구분한다. 완료·기간·시작 전·잠김은 `neutral` 그대로다.
3. **행 구분은 `gap-2`를 걷고 각 행에 `separator`(1px)를 준다.** 마지막 행에도 선이 생기는 것은 받아들인다.

채원이 판정한 나머지: 잠긴 미션은 `disabled` 없이 `onClick` + `aria-disabled="true"`(`ListRow`가 `aria-*`를 클릭 영역으로 넘긴다), 보상 줄은 색 지정 없이 `footer`가 `--foreground`를 상속(`--link`와 값이 같다), 자물쇠는 lead 안에서 20px, 미션 그림은 `object-fit: contain` 유지, 조건 줄과 보상 줄은 한 `footer`에 둔다.
