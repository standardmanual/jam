# [UI] 목록 행 4단계 5-1: 문의 카드(VocCard)를 Card로, 개발용 샘플의 컬렉션 링크 행을 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 서비스 코드에서 `ListRowCard`를 아직 쓰는 마지막 2곳을 없앤다. ① 문의 화면의 `VocCard`(1단계 A9)는 **카드로 남기고** `ListRowCard` 대신 `Card`(default 면)로 바꾼다(사용자 결정 2026-11-08, 문의 행은 카드로 남긴다). ② 개발용 샘플 `dev-sample/item-badge-serial`의 컬렉션 링크 행은 `ListRow`로 바꾼다. 이 티켓이 끝나면 `ListRowCard` 사용처가 0이 되고, 5-2(삭제)가 열린다.
- 구현 계획: 채원 사전 판정(문의 카드 구성·`#번호` 자리·샘플 행 매핑 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/voc/page.tsx`(import 6줄, `VocCard` 58~105줄, 사용 199줄), `jam-web/src/app/dev-sample/item-badge-serial/page.tsx`(import 2줄, 컬렉션 링크 행 79~90줄), `jam-web/src/components/ui/ListRow.tsx`(읽기만), `jam-web/design-system/components/cards/Card.jsx`(읽기만).

## 배경 / 문제 정의

`VocCard`는 `ListRowCard`의 `icon`에 `#번호`를 두고 `children`에 칩 줄(상태·심각도·날짜), 유형 칩 줄, 장문 본문, 답변 박스를 직접 넣는다. 한 행이 아니라 카드라서 `ListRow`의 슬롯으로 표현되지 않는다. `ListRowCard`는 흰 면 + 1px 테두리(default)이고 `Card` default도 같아 외형은 거의 그대로다. 개발용 샘플은 실제 배지 상세가 3-3에서 `ListRow`가 된 뒤 낡은 모양(lead 44)이다. 상위 티켓 «ListRowCard 정리 조사 결과» 절의 5-1이다.

## 사용자 결정

- 문의 행은 **카드로 남긴다**(2026-11-08). `ListRow`로 옮기지 않는다.
- 새 토큰·MODULAR 변경은 하지 않는다. `Card`·`ListRow`는 서비스에서 쓰는 그대로 쓴다. 값이 모자라면 사본·원본을 고치지 말고 보고한다.
- 칩(상태·심각도·날짜·유형)은 이 티켓에서 모양을 바꾸지 않는다. 문의 화면의 칩 색은 컬러 개편 3회차(20261107_2246)가 정한 그대로다.
- `ListRow`를 쓰는 곳은 1~4배치 규칙을 따른다: named import, 빈 슬롯은 `undefined`, lead 안 이미지는 `alt=""`, 클릭 영역 안은 phrasing 요소만.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. `voc/page.tsx`의 `VocCard`를 `Card`(default) 기반으로 바꾼다. `ListRowCard` import를 걷는다. 지금 `icon` 자리의 `#번호`는 카드 맨 윗줄의 칩 줄 안으로 옮기는 안을 채원이 판정한다(`#번호`가 칩 줄과 같은 줄에 놓여도 320px에서 줄바꿈이 어색하지 않은지). 칩 줄·유형 줄·본문·답변 박스의 마크업과 문구는 그대로 둔다.
2. `dev-sample/item-badge-serial/page.tsx`의 컬렉션 링크 행을 `ListRow`(lead 48 `BookIcon` 타일, `title`, `href="#"`, `chevron`)로 바꾼다. 이 페이지는 어두운 배경이라 면 톤은 채원이 판정한다. 개발용이라 시험은 없다.
3. 시험: 문의 화면과 샘플은 시험이 없다. `ListRowCard`가 사라져도 통과해야 하는 기존 시험(`cardFacePairs`·`pressClass`·`ListRowCard.test`)은 5-2에서 다루므로 이 티켓에서 건드리지 않는다.
4. 문서: 문의 화면 PRD 절(`docs/service/prd/`에서 탐색, 없으면 갱신 대상 없음으로 보고), 상위 티켓 5배치 표.

범위 밖: `ListRowCard` 삭제와 문서·주석의 참조 정리(5-2).

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | 대응 |
|---|---|
| `VocCard`의 `ListRowCard`(흰 면 + 1px 테두리, 안쪽 여백) | `Card`(default) |
| `icon`에 `#번호` | 카드 맨 윗줄(칩 줄 앞)로 옮김(판정) |
| 칩 줄·유형 줄·본문·답변 박스 | 그대로 |
| 샘플 컬렉션 링크 `ListRowCard`(lead 44 타일 + 쉐브론) | `ListRow`(lead 48 타일, `chevron`, `href`) |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **`#번호` 자리**: `Card`에는 `icon` 슬롯이 없다. 칩 줄 안(앞)에 넣을지, 칩 줄 위에 별도 줄로 둘지, 320px에서 줄바꿈과 정렬을 판정한다.
2. **`Card`의 안쪽 여백**: `Card`는 `--layout-card-padding`이고 `ListRowCard`는 자체 값이다. 두 값의 차이로 문의 카드의 모양이 달라지는지, 목록의 카드 간격(`gap`)을 맞춰야 하는지 판정한다.
3. **샘플 행의 면 톤**: 어두운 배경 위라 `ListRow`의 어떤 톤이 맞는지 판정한다. 개발용 샘플이라 눈에 띄는 변화는 허용한다.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경 파일이 2개이고 위치가 확정돼 있어 탐색이 필요 없다).

1. `voc/page.tsx` — import 6줄의 `ListRowCard`를 `Card`로 바꾸고, `VocCard`(58~105줄)의 바깥 요소를 `Card`로 바꾼다.
2. `dev-sample/item-badge-serial/page.tsx` — import 2줄을 `{ ListRow }`로 바꾸고 79~90줄을 `ListRow`로 바꾼다. 안 쓰게 되는 import(`ChevronRightIcon` 등)는 lint로 확인한다.
3. 문서 두 곳.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 서비스 코드 어디에도 `ListRowCard` import가 없다(`grep`으로 확인, 5-2에서 지울 파일 자신과 시험·문서·주석은 제외).
- 문의 카드가 `Card` 기반이고 칩 줄·유형 줄·본문·답변 박스·`#번호`가 모두 그대로 나온다. 답변이 없는 문의와 있는 문의 모두 마크업이 깨지지 않는다.
- 개발용 샘플의 컬렉션 링크 행이 `ListRow`다.
- 변경한 파일이 `scripts/verify.sh`와 `serviceLiteralColors` 시험을 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 메인 트리 개발 서버에서 문의 화면을 320px로 열어 전후를 비교한다(카드 높이, 칩 줄 줄바꿈, 답변 박스).
- 판정 1~3 결과를 상위 티켓에 기록하고 5-2(삭제)를 시작할지 묻는다.
