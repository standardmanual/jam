# [UI] 목록 행 4단계 5-1: 문의 카드(VocCard)를 Card로, 개발용 샘플의 컬렉션 링크 행을 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 서비스 코드에서 `ListRowCard`를 아직 쓰는 마지막 2곳을 없앤다. ① 문의 화면의 `VocCard`(1단계 A9)는 **카드로 남기고** `ListRowCard` 대신 `Card`(default 면)로 바꾼다(사용자 결정 2026-11-08, 문의 행은 카드로 남긴다). ② 개발용 샘플 `dev-sample/item-badge-serial`의 컬렉션 링크 행은 `ListRow`로 바꾼다. 이 티켓이 끝나면 `ListRowCard` 사용처가 0이 되고, 5-2(삭제)가 열린다.
- 구현 계획: 채원 사전 판정(문의 카드 구성·`#번호` 자리·샘플 행 매핑 확정) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: `jam-web/src/app/(main)/voc/page.tsx`(import 6줄, `VocCard` 58~105줄, 사용 199줄), `jam-web/src/app/dev-sample/item-badge-serial/page.tsx`(import 2줄, 컬렉션 링크 행 79~90줄), `jam-web/src/components/ui/ListRow.tsx`(읽기만), `jam-web/design-system/components/cards/Card.jsx`(읽기만).

## 배경 / 문제 정의

`VocCard`는 `ListRowCard`의 `icon`에 `#번호`를 두고 `children`에 칩 줄(상태·심각도·날짜), 유형 칩 줄, 장문 본문, 답변 박스를 직접 넣는다. 한 행이 아니라 카드라서 `ListRow`의 슬롯으로 표현되지 않는다. `ListRowCard` default는 `#f7f7f7` 면·외곽선 없음·안쪽 여백 16px이고 `Card` default도 같은 `--card-bg` 면이라 면 색은 같지만 안쪽 여백은 24px로 달라진다(티켓을 쓸 때 «흰 면 + 1px 테두리»로 잘못 적은 것을 채원 판정이 바로잡았다). 개발용 샘플은 실제 배지 상세가 3-3에서 `ListRow`가 된 뒤 낡은 모양(lead 44)이다. 상위 티켓 «ListRowCard 정리 조사 결과» 절의 5-1이다.

## 사용자 결정

- 문의 행은 **카드로 남긴다**(2026-11-08). `ListRow`로 옮기지 않는다.
- 새 토큰·MODULAR 변경은 하지 않는다. `Card`·`ListRow`는 서비스에서 쓰는 그대로 쓴다. 값이 모자라면 사본·원본을 고치지 말고 보고한다.
- 칩(상태·심각도·날짜·유형)은 이 티켓에서 모양을 바꾸지 않는다. 문의 화면의 칩 색은 컬러 개편 3회차(20261107_2246)가 정한 그대로다.
- `ListRow`를 쓰는 곳은 1~4배치 규칙을 따른다: named import, 빈 슬롯은 `undefined`, lead 안 이미지는 `alt=""`, 클릭 영역 안은 phrasing 요소만.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.

## 범위

1. `voc/page.tsx`의 `VocCard`를 `Card`(default) 기반으로 바꾼다. `ListRowCard` import를 걷는다. 지금 `icon` 자리의 `#번호`는 카드 맨 윗줄의 칩 줄 안으로 옮기는 안을 채원이 판정한다(`#번호`가 칩 줄과 같은 줄에 놓여도 320px에서 줄바꿈이 어색하지 않은지). 칩 줄·유형 줄·본문·답변 박스의 마크업과 문구는 그대로 둔다.
2. `dev-sample/item-badge-serial/page.tsx`의 컬렉션 링크 행을 `ListRow`(lead 48 `BookIcon` 타일, `title`, `href="#"`, `chevron`)로 바꾼다. 이 페이지의 바깥 배경은 흰색(`#fff`)이다(어두운 배경이라는 처음 서술은 틀렸다). 면 톤은 채원이 판정했다. 개발용이라 시험은 없다.
3. 시험: 문의 화면과 샘플은 시험이 없다. `ListRowCard`가 사라져도 통과해야 하는 기존 시험(`cardFacePairs`·`pressClass`·`ListRowCard.test`)은 5-2에서 다루므로 이 티켓에서 건드리지 않는다.
4. 문서: 문의 화면 PRD 절(`docs/service/prd/`에서 탐색, 없으면 갱신 대상 없음으로 보고), 상위 티켓 5배치 표.

범위 밖: `ListRowCard` 삭제와 문서·주석의 참조 정리(5-2).

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | 대응 |
|---|---|
| `VocCard`의 `ListRowCard`(`#f7f7f7` 면, 외곽선 없음, 안쪽 여백 16px) | `Card`(default, 같은 면, 안쪽 여백 24px) |
| `icon`에 `#번호` | 카드 맨 윗줄(칩 줄 앞)로 옮김(판정) |
| 칩 줄·유형 줄·본문·답변 박스 | 그대로 |
| 샘플 컬렉션 링크 `ListRowCard`(lead 44 타일 + 쉐브론) | `ListRow`(lead 48 타일, `chevron`, `href`) |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **`#번호` 자리**: `Card`에는 `icon` 슬롯이 없다. 칩 줄 안(앞)에 넣을지, 칩 줄 위에 별도 줄로 둘지, 320px에서 줄바꿈과 정렬을 판정한다.
2. **`Card`의 안쪽 여백**: `Card`는 `--layout-card-padding`이고 `ListRowCard`는 자체 값이다. 두 값의 차이로 문의 카드의 모양이 달라지는지, 목록의 카드 간격(`gap`)을 맞춰야 하는지 판정한다.
3. **샘플 행의 면 톤**: 흰 배경 위에서 `ListRow`의 어떤 톤이 맞는지 판정한다. 개발용 샘플이라 눈에 띄는 변화는 허용한다.

## 완료 기록

### 구현 내용 요약

- 문의 카드(`voc/page.tsx`의 `VocCard`)를 `ListRowCard`에서 `Card`(default, 비대화형)로 바꿨다. `icon` prop은 없애고 `#번호`는 칩 줄 맨 앞 첫 항목으로 옮겼다(`text-xs leading-none text-muted whitespace-nowrap`, 칩 면 없음, 크기는 `text-base`에서 `text-xs`로 내렸다). 칩 줄·유형 줄·본문·답변 박스의 마크업과 문구는 그대로다.
- 개발용 샘플(`dev-sample/item-badge-serial/page.tsx`)의 컬렉션 링크 행을 `ListRow`(기본 톤, `href="#"`, lead 48 `BookIcon` 20px, `chevron`)로 바꿨다. 48px 타일 래퍼 `div`와 `ChevronRightIcon` import는 걷었다.
- 서비스 코드에서 `ListRowCard`를 import하는 곳이 0이 됐다. 남은 참조는 `ListRowCard.tsx` 자신, 시험 3개(`ListRowCard.test`·`cardFacePairs`·`pressClass`), 문서·주석뿐이고 5-2 범위다.
- 문서: 문의 화면 PRD 절은 `docs/service/prd/`에서 `voc|문의`로 탐색해 `/voc` 링크 언급만 있어 갱신 대상이 없다. 상위 티켓에 «5-1 판정 결과» 절과 5배치 표를 갱신했다. 정책·수치 변경이 없어 `policiesData.ts`는 해당 없음이다.

### 채원 사전 판정 (needsApproval: false) — 티켓 전제 두 가지를 바로잡았다

- `ListRowCard` default는 «흰 면 + 1px 테두리»가 아니라 `#f7f7f7`(`bg-card-bg`) 면·외곽선 없음·안쪽 여백 16px이다(컬러 개편 20261107_2203·2246). `Card` default도 같은 `--card-bg` 면이라 면 색은 그대로이고, 칩·유형 칩·답변 박스의 대비도 그대로다. 안쪽 여백만 16에서 24px로 달라진다.
- 개발용 샘플의 바깥 배경은 어두운 색이 아니라 흰색(`#fff`)이다.
- 판정 1(`#번호` 자리): 칩 줄 맨 앞 첫 항목. 별도 줄로 빼면 카드마다 한 줄이 늘어난다.
- 판정 2(안쪽 여백): `Card`의 `--layout-card-padding`(24px)을 덮어쓰지 않고 그대로 쓴다. 본문 폭이 약 200에서 약 238px로 넓어져 높이 증가가 일부 상쇄된다. 목록 `gap-2`는 유지한다.
- 판정 3(샘플 면 톤): `ListRow` default 톤. 실제 배지 상세와 같은 구성이다.

### 실렌더 측정 (메인 트리 개발 서버, 폭 320px, 테스트 계정)

- 문의 카드 4건(#4~#1, 전부 답변 있는 문의): 카드 폭 288, 면 `rgb(247, 247, 247)`, 안쪽 여백 24px, 모서리 16px, 테두리 `1px solid rgba(0,0,0,0)`, 본문 폭 238(예측값과 같음), 높이 342·558·390·318px, 카드 넘침 없음, 페이지 가로 넘침 없음. 답변 박스와 JAM 로고 마스크가 4건 모두 나온다.
- `#번호`는 12px 한 줄(높이 12)이고, 칩 줄 안 같은 줄에서 «답변완료» 칩, «심각도 1/5» 칩 순으로 놓인다. 날짜(`2026년 9월 8일 …`)는 아래 줄로 내려간다(예상한 모양). 화면으로 보면 번호가 칩과 어색하게 끊기지 않는다.
- 샘플 행: `<div data-interactive>` 안 링크, lead 48×48, lead 안은 `BookIcon`(20px) 하나뿐이라 타일 박스가 이중이 아니다, 행 높이 74.
- 확인하지 못한 것: 답변이 없는 문의는 시트 데이터 4건이 전부 답변완료라 화면으로 보지 못했다(마크업은 `item.answer &&` 분기가 그대로다). 긴 URL·영문이 박스를 넘는 경우도 보지 못했다. 변경 전 화면은 측정하지 못해, «전후 높이 비교»는 하지 못했다(채원 계산: 본문 폭이 넓어져 줄 수가 줄어 상쇄됨). 첫 접속에서는 개발 서버 컴파일 때문에 «불러오는 중»에 오래 머물렀고 새로고침 뒤 정상이었다.
