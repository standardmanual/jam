# [UI] 목록 행 4단계 5-2: 쓰는 곳이 없어진 ListRowCard를 삭제하고 문서·주석의 참조를 정리한다

## 핵심 요약

- 요구사항: 5-1이 끝나 서비스 코드에서 `ListRowCard`를 import하는 곳이 0이다. 디자인 시스템 원본(`design-system/components/patterns/ListRowCard.*` 4파일), 서비스 사본(`src/components/ui/ListRowCard.tsx`와 시험), `_ds_manifest.json` 항목, 시험 2개의 해당 구간을 지우고, 문서·주석에 남은 참조를 정리한다. 상위 티켓 4단계의 마지막 배치다. **디자인 시스템 컴포넌트를 지우는 일은 MODULAR 원본 변경이라 승인 항목이다**(채원 사전 판정에서 `needsApproval`로 멈추고, 사용자 승인 뒤 구현한다).
- 구현 계획: 채원 사전 판정(`ds` 유형, 연결 범위·삭제 안전성 확인) → 사용자 승인 → 아현 구현 → 민지 게이트 → 채원 사후 리뷰. 파일 단위 계획은 «구현 계획».
- 관련 파일: 아래 «범위»의 삭제·수정 표.

## 배경 / 문제 정의

`ListRowCard`는 `ListRow`가 서비스 화면에 정착하기 전의 목록 행 컴포넌트다. 1~4배치와 5-1로 `ListRow`와 `Card`가 그 자리를 모두 대신했다. 지금 남은 `ListRowCard` 참조는 자기 자신, 시험 3개(`ListRowCard.test`·`cardFacePairs`·`pressClass`), 디자인 시스템 안 `ListRow` 설명문, 문서와 주석이다. 쓰는 곳이 없는 컴포넌트가 남아 있으면 «새 목록 행은 어느 것을 쓰나»가 헷갈리고, `ds:check`가 쓰이지 않는 쌍을 계속 검사한다.

**확인한 사실(2026-11-08, 작업 트리 기준, 명령으로 확인)**
- `grep -rn "ListRowCard" jam-web/src jam-web/design-system`로 코드 참조를 찾았을 때 `.ts`·`.tsx`·`.jsx` 중 서비스 화면의 import는 0이다. 남은 곳은 아래 범위 표와 같다.
- `ListRowCardTitle`(`ListRowCard.tsx`가 내보내는 보조 컴포넌트)을 자기 파일 밖에서 쓰는 곳은 없다.
- `ds:check`의 쌍은 `_ds_manifest.json`에서 만들어진다(`ds-sync-check.mjs`의 `buildPairs`). 이름이 스크립트에 박혀 있지 않아 manifest 항목을 지우면 쌍도 함께 사라진다(`npm run ds:manifest`로 manifest를 다시 만들 수 있다).
- 5-1에서 «`ListRowCard`는 흰 면 + 1px 테두리»라고 코드를 읽지 않고 적은 것이 틀렸다(실제는 `#f7f7f7` 면·외곽선 없음). 이 티켓의 사실은 모두 명령으로 확인한 것이고, **아현은 서술을 믿지 말고 각 파일을 직접 열어 확인한다.**

## 사용자 결정

- `ListRowCard`는 삭제한다(2026-11-06 상위 티켓 계획 «마지막 정리»). 삭제 승인은 채원 판정이 올린 승인 항목에서 다시 받는다.
- 새 토큰·새 컴포넌트는 만들지 않는다. 날짜가 박힌 과거 기록(`docs/plan/**`, `jam-web/docs/storybook/*`, `jam2-token-migrate.report.json`)은 고치지 않는다.
- 원본과 서비스 사본은 같은 값으로 함께 다룬다(`ds:check`). 삭제도 한 번에 한다.
