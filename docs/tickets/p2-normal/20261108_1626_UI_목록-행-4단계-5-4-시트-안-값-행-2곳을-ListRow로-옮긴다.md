# [UI] 목록 행 4단계 5-4: 시트 안 값 행 2곳(피드 상세·탈퇴)을 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 라벨(왼쪽 muted)과 값(오른쪽)으로 이뤄진 값 행(1단계 D1·D2) 중 바텀시트 안에 있는 2곳을 `ListRow`의 값 행 구성(`title` `label` + `value`, `flat` 톤)으로 옮긴다. 두 곳 모두 16px이라 글자 모양 통일 문제는 5-5(카드 값 행)에서 푼다. `ListRow.prompt.md`에 `titleLines={0}` 안내 한 줄을 더한다.
- 구현 계획: 채원 사전 판정(2026-11-08 완료, 승인 항목 4건 사용자 승인) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰.
- 관련 파일: `jam-web/src/app/(main)/FeedSection.tsx`(`Row` 298~305줄, `<Row` 6번 호출), `jam-web/src/components/account/WithdrawSheet.tsx`(`SummaryRows` 70~90줄, 스켈레톤 108~118줄, `SKELETON_MIN_HEIGHT`), `jam-web/src/app/(main)/FeedSection.test.tsx`(시험), `jam-web/design-system/components/patterns/ListRow.prompt.md`(한 줄), `jam-web/src/components/ui/ListRow.tsx`(읽기만).
- 담당 에이전트: 채원(사후 리뷰), 아현(구현), 민지(게이트).

## 배경 / 문제 정의

두 곳 모두 라벨 16/muted + 값 16/foreground로 모양은 같지만 줄 간격이 다르다(`FeedSection` `py-2`, `WithdrawSheet` `py-1`). `WithdrawSheet`의 주석이 «`FeedSection`의 Row와 같은 영수증 행»이라고 적을 만큼 같은 역할을 각자 복제해 왔다. `ListRow`는 값 행을 이미 정의한다(`ListRow.prompt.md` 17줄). 조사 결과는 상위 티켓 «5-3배치 조사 결과».

**처음에는 값 행 3곳이었다.** 인벤토리 획득 방법 행(`InventoryItemHistorySheet.tsx`)을 세 번째로 넣었는데 5-4 채원 사전 판정에서 이 컴포넌트가 어느 화면에서도 import되지 않는 죽은 코드임이 드러나 범위에서 뺐다(삭제는 별도 P3 티켓).

## 사용자 결정

- `ListRow`를 쓰는 곳은 1~5배치 규칙을 따른다: named import(`{ ListRow, ListRowChip, ListRowEm }`), 빈 슬롯은 `undefined`, lead 안 이미지는 `alt=""`(이름은 `title`이 담는다), 클릭 영역 안은 phrasing 요소만.
- 새 토큰·MODULAR 변경은 하지 않는다. `ListRow` 사본·원본이 모자라면 고치지 말고 보고한다(원본 변경은 승인 항목). 예외는 아래 «사용자 결정» 3번의 문서 한 줄이다.
- 사용자 노출 문구는 바꾸지 않는다. 기존 `d.*` 사전 키를 그대로 쓴다.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.
- **(2026-11-08, 채원 사전 판정 승인 항목 4건을 권고대로 승인)**
  1. 값 글자가 보통(400)에서 굵게(700)로 바뀌는 것을 받아들인다. `ListRow` 값 슬롯의 정해진 규칙이며 5-5의 카드 값 행도 같다.
  2. 값이 최대 폭 60%에서 줄바꿈되는 것을 허용한다(피드 상세 «일시» 행이 두 줄이 될 수 있다). 실렌더에서 어색하면 그 장면과 함께 다시 올린다.
  3. `ListRow.prompt.md`에 값 행 라벨은 `titleLines={0}`(줄 제한 없음)을 쓰라는 문구 한 줄을 더하는 MODULAR 원본 문서 변경을 승인한다.
  4. `InventoryItemHistorySheet`는 옮기지 않고 5-4 범위에서 뺀다. 삭제는 별도 P3 티켓이다.
- 줄 간격은 `ListRow`의 값 행 기본값으로 맞춘다(행 높이 48px). 두 곳이 서로 다른 값을 쓰던 차이는 없어진다.

## 범위

1. `FeedSection.tsx`의 `Row`를 `ListRow tone="flat" titleVariant="label" titleLines={0}`를 쓰는 얇은 래퍼로 바꾼다. 6번 호출부는 그대로 둔다. 바깥 카드의 `py-2`는 `py-1`로 줄인다(행이 자기 위아래 12px를 가진다).
2. `WithdrawSheet.tsx`의 `SummaryRows` 5줄을 `ListRow`로 바꾸고 `dl`/`dt`/`dd`를 걷는다. 스켈레톤 줄도 같은 `ListRow`로 만들고 `SKELETON_MIN_HEIGHT`를 `160px`에서 `240px`(5×48)로 고친다. 이 값과 주석의 높이 계산을 함께 갱신한다.
3. `ListRow.prompt.md`에 `titleLines={0}` 한 줄을 더한다(`design-system/` 원본 문서만, 서비스 사본 코드는 바뀌지 않는다).
4. 시험: `FeedSection.test.tsx`가 통과해야 한다(`>일시<` 일치 467줄, 텍스트 일치 552줄). `WithdrawSheet`는 시험이 없어 최소 `renderToStaticMarkup` 시험(탈퇴 5줄 라벨·값 문구)을 추가한다.
5. 문서: 피드 상세·탈퇴 PRD 절에서 행 모양 서술이 있으면 갱신, 상위 티켓 5배치 표.

범위 밖: 카드 안 값 행(5-5), `LockedItemDetail`의 포인트 블록(5-5), `InventoryItemHistorySheet`(삭제 티켓).

## 매핑표 (채원 사전 판정 확정)

| 현재 | 대응 |
|---|---|
| `FeedSection` `Row`: `flex justify-between gap-4 py-2`, 라벨 16 muted, 값 16 foreground, `whitespace-nowrap` | `ListRow tone="flat" titleVariant="label" titleLines={0} title={label} value={value}`. 값 700, 최대 폭 60%에서 줄바꿈, 행 높이 40에서 48 |
| `WithdrawSheet` `SummaryRows`: `dl`/`dt`/`dd`, `py-1`(행 32px) | 같은 구성 `ListRow` 5개를 `div`로 감싼다. 행 48px, 묶음 160에서 240px |
| 탈퇴 시트 스켈레톤: `div` 5줄(`h-6`) | `ListRow` 안에 `h-6` 막대(제목·값 자리). 후퇴안은 `py-3` + `h-6` |

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경 파일이 코드 2·시험 1~2·문서 1~2이고 위치가 확정돼 있다).

1. `FeedSection.tsx` — `Row`(298~305줄) 교체와 바깥 카드 `py-1`.
2. `WithdrawSheet.tsx` — `SummaryRows`(70~90줄), 스켈레톤(108~118줄), `SKELETON_MIN_HEIGHT`와 주석.
3. `ListRow.prompt.md` — 한 줄.
4. 시험과 문서.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 두 곳의 값 행이 `ListRow`이고 라벨·값 문구가 그대로 나온다.
- 탈퇴 시트가 로드 전후에 높이가 튀지 않는다(스켈레톤 행 높이 = 실제 행 높이, `SKELETON_MIN_HEIGHT` 240px).
- `ListRow.prompt.md`에 `titleLines={0}` 안내가 있고 `ds:check`가 통과한다.
- 변경한 파일이 `scripts/verify.sh`와 `serviceLiteralColors` 시험을 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 개발 서버에서 피드 상세 시트를 320px로 열어 행 높이(48)와 «일시» 줄바꿈을 확인한다(읽기만). 탈퇴 시트는 열기까지만 하고 실행하지 않는다.
- 사전 판정 결과를 상위 티켓에 기록한다.
