# [UI] 목록 행 4단계 5-4: 시트 안 값 행 3곳(피드 상세·탈퇴·인벤토리 획득 방법)을 ListRow로 옮긴다

## 핵심 요약

- 요구사항: 라벨(왼쪽 muted)과 값(오른쪽)으로 이뤄진 값 행(1단계 D1·D2·D3) 중 바텀시트 안에 있는 3곳을 `ListRow`의 값 행 구성(`title` `label` + `value`, `flat` 톤)으로 옮긴다. 세 곳은 모두 16px이라 글자 모양 통일 문제는 5-5(카드 값 행)에서 푼다.
- 구현 계획: 채원 사전 판정(톤·줄 간격·획득 방법 행의 `value`+`chevron` 구성·탈퇴 시트 스켈레톤 높이) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰.
- 관련 파일: `jam-web/src/app/(main)/FeedSection.tsx`(`Row` 298~305줄, `<Row` 6번 호출), `jam-web/src/components/account/WithdrawSheet.tsx`(`SummaryRows` 70~90줄, 스켈레톤 108~118줄), `jam-web/src/app/(main)/inventory/[itemId]/InventoryItemHistorySheet.tsx`(획득 방법 버튼 62~74줄), `jam-web/src/app/(main)/FeedSection.test.tsx`(시험), `jam-web/src/components/ui/ListRow.tsx`(읽기만).
- 담당 에이전트: 채원(사전 판정·사후 리뷰), 아현(구현), 민지(게이트).

## 배경 / 문제 정의

세 곳 모두 라벨 16/muted + 값 16/foreground로 모양은 같지만 줄 간격이 다르다(`FeedSection` `py-2`, `WithdrawSheet` `py-1`, 획득 방법 버튼 `px-4 py-4`). `WithdrawSheet`의 주석이 «`FeedSection`의 Row와 같은 영수증 행»이라고 적을 만큼 같은 역할을 각자 복제해 왔다. `ListRow`는 값 행을 이미 정의한다(`ListRow.prompt.md` 17줄). 조사 결과는 상위 티켓 «5-3배치 조사 결과».

## 사용자 결정

- `ListRow`를 쓰는 곳은 1~5배치 규칙을 따른다: named import(`{ ListRow, ListRowChip, ListRowEm }`), 빈 슬롯은 `undefined`, lead 안 이미지는 `alt=""`(이름은 `title`이 담는다), 클릭 영역 안은 phrasing 요소만.
- 새 토큰·MODULAR 변경은 하지 않는다. `ListRow` 사본·원본이 모자라면 고치지 말고 보고한다(원본 변경은 승인 항목).
- 사용자 노출 문구는 바꾸지 않는다. 기존 `d.*` 사전 키를 그대로 쓴다.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.
- 줄 간격은 `ListRow`의 값 행 기본값으로 맞춘다. 세 곳이 서로 다른 값을 쓰던 차이는 없어진다.

## 범위

1. `FeedSection.tsx`의 `Row`를 `ListRow`로 바꾸고 6번 호출이 그대로 동작하게 한다(`Row` 컴포넌트 자체를 얇은 래퍼로 두거나 호출부를 바꾸는 쪽은 채원이 판정).
2. `WithdrawSheet.tsx`의 `SummaryRows` 5줄을 `ListRow`로 바꾼다. 스켈레톤 줄(`SKELETON_ROWS`)과 `SKELETON_MIN_HEIGHT`가 새 행 높이와 맞아야 한다(맞지 않으면 시트가 로드 때 튄다).
3. `InventoryItemHistorySheet.tsx`의 획득 방법 행을 `ListRow`(`title` `label` + `value` + `chevron`, `onClick`)로 바꾼다.
4. 시험: `FeedSection.test.tsx`가 통과해야 한다. `WithdrawSheet`·`InventoryItemHistorySheet`는 시험이 없다. 값 행 문구가 그대로 나오는지 보는 최소 렌더 시험을 추가할지는 채원·민지가 판정한다.
5. 문서: 피드 상세·탈퇴·인벤토리 PRD 절에서 행 모양 서술이 있으면 갱신, 상위 티켓 5배치 표.

범위 밖: 카드 안 값 행(5-5), `LockedItemDetail`의 포인트 블록(5-5).

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | 대응(안) |
|---|---|
| `FeedSection` `Row`: `flex justify-between gap-4 py-2`, 라벨 16 muted, 값 16 foreground 오른쪽 정렬 | `ListRow tone="flat" titleVariant="label" title={label} value={value}` |
| `WithdrawSheet` `SummaryRows`: `dl`/`dt`/`dd`, `py-1` | 같은 구성. `dl` 의미가 사라지는 대신 행 목록 의미를 어떻게 줄지 판정 |
| 획득 방법: `button`(`px-4 py-4`), 라벨 + 값 + 쉐브론 16 | `ListRow` + `value` + `chevron` + `onClick` |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **값이 줄바꿈될 때**: 지금 `FeedSection` `Row`의 값은 `whitespace-nowrap`이다. `ListRow` 값 행은 «value가 줄바꿈되고 오른쪽 정렬»이라 긴 값에서 동작이 달라진다. 320px에서 가장 긴 값(활동 이름 등)을 판정한다.
2. **시트 면 위의 톤**: 시트 배경 위에서 `flat`이 맞는지, 구분선(`separator`)을 쓸지 판정한다. 지금 세 곳 모두 구분선이 없다.
3. **탈퇴 시트 스켈레톤**: `SKELETON_ROWS`의 `h-6` 줄과 `SKELETON_MIN_HEIGHT`가 새 행 높이와 같아야 한다. 같게 맞추는 방법을 판정한다.
4. **획득 방법 행**: 값 + 쉐브론 + 눌림의 슬롯 순서와 눌림 표시를 판정한다. 지금은 `active:opacity-70`이다.
5. **`dl` 의미**: 탈퇴 시트의 `dl`을 걷어도 접근성이 후퇴하지 않는지 판정한다.

## 구현 계획

파일 단위 계획(계획 반환 면제 사유: 변경 파일이 3개, 위치가 확정돼 있고 시험·문서까지 5개 이내다).

1. `FeedSection.tsx` — `Row`(298~305줄) 교체.
2. `WithdrawSheet.tsx` — `SummaryRows`(70~90줄) 교체와 스켈레톤 높이 맞춤.
3. `InventoryItemHistorySheet.tsx` — 획득 방법 버튼(62~74줄) 교체.
4. 시험과 문서.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 세 곳의 값 행이 `ListRow`이고 라벨·값 문구가 그대로 나온다.
- 탈퇴 시트가 로드 전후에 높이가 튀지 않는다(스켈레톤 높이 = 행 높이).
- 획득 방법 행을 눌러 시트가 열린다.
- 변경한 파일이 `scripts/verify.sh`와 `serviceLiteralColors` 시험을 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 개발 서버에서 피드 상세 시트·탈퇴 시트·인벤토리 상세를 320px로 열어 전후 높이를 비교한다(읽기만, 탈퇴는 열기까지만 하고 실행하지 않는다).
- 판정 1~5 결과를 상위 티켓에 기록한다.
