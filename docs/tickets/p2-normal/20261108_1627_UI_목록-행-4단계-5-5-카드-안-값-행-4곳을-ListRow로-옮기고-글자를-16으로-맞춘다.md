# [UI] 목록 행 4단계 5-5: 카드 안 값 행 4곳을 ListRow로 옮기고 값 행 글자를 16으로 맞춘다

## 핵심 요약

- 요구사항: 카드 안의 값 행(1단계 D4·D7과 배지 상세 획득 정보 카드) 4곳을 `ListRow` 값 행 구성으로 옮기고, 같은 역할인데 14px인 라벨·값을 5-4의 16px과 맞춘다. 상위 완료 조건 3(같은 역할의 글자 모양이 화면마다 같다)을 직접 닫는 티켓이다.
- 구현 계획: 채원 사전 판정(통일 크기 14 vs 16·`LockedItemDetail`의 24px 강조 포함 여부·긴 값 처리) → 아현 구현 → 민지 게이트 → 채원 사후 리뷰.
- 관련 파일: `jam-web/src/app/(main)/badges/[id]/page.tsx`(획득 정보 카드 634~668줄), `jam-web/src/app/(main)/badges/[id]/PoiEarnHistory.tsx`(`EarnCardContent` 21~55줄), `jam-web/src/app/(main)/badges/[id]/ItemEarnHistory.tsx`(`ItemCardContent` 17~34줄), `jam-web/src/app/(main)/inventory/[itemId]/LockedItemDetail.tsx`(포인트 블록 70~80줄 근처), 시험은 `badges/[id]/__tests__/`(`page`·`page.locked`·`page.item-book`·`PoiEarnHistory.test`), `ListRow.tsx`(읽기만).
- 담당 에이전트: 채원(사전 판정·사후 리뷰), 아현(구현), 민지(게이트).

## 배경 / 문제 정의

값 행 7곳 중 시트 3곳(5-4)은 16px인데 카드 3곳(배지 상세 획득 정보 `text-sm`, 체크인 획득 `text-[14px]`, 아이템 획득 `text-[14px]`)은 14px이다. `LockedItemDetail`은 16px이고 필요 포인트 줄만 24px 굵게다. 전부 라벨 muted + 값 오른쪽 정렬이라 같은 역할인데 크기가 갈린다. 조사 결과는 상위 티켓 «5-3배치 조사 결과».

## 사용자 결정

- **(5-4 사전 판정에서 승인, 2026-11-08)** 값 글자가 보통(400)에서 굵게(700)로 바뀌는 것과, 값이 최대 폭 60%에서 줄바꿈되는 것을 받아들인다. `ListRow` 값 슬롯의 정해진 규칙이라 이 티켓의 카드 값 행도 같다. 긴 활동 이름의 말줄임은 이 규칙 때문에 줄바꿈으로 바뀐다.
- **정정**: 5-3 조사에서 값 행 7곳으로 센 것 중 `InventoryItemHistorySheet`(인벤토리 획득 방법)는 어느 화면에서도 쓰이지 않는 죽은 코드다. 이 티켓의 대상(카드 4곳)에는 원래 없었고, 값 행은 실제로 6곳이다.

- `ListRow`를 쓰는 곳은 1~5배치 규칙을 따른다: named import(`{ ListRow, ListRowChip, ListRowEm }`), 빈 슬롯은 `undefined`, lead 안 이미지는 `alt=""`(이름은 `title`이 담는다), 클릭 영역 안은 phrasing 요소만.
- 새 토큰·MODULAR 변경은 하지 않는다. `ListRow` 사본·원본이 모자라면 고치지 말고 보고한다(원본 변경은 승인 항목).
- 사용자 노출 문구는 바꾸지 않는다. 기존 `d.*` 사전 키를 그대로 쓴다.
- 실렌더는 메인 트리 개발 서버에서 320px로 확인한다. 격리 워크트리에서는 `next dev`가 뜨지 않는다.
- 값 행의 글자 크기는 한 가지로 맞춘다(상위 조건 3). 14와 16 중 어느 쪽인지는 채원이 판정하고, 5-4에서 이미 16인 세 곳과 어긋나지 않게 한다. 카리나의 추천은 본문 크기인 16이다.

## 범위

1. 배지 상세 획득 정보 카드, `PoiEarnHistory`의 `EarnCardContent`, `ItemEarnHistory`의 `ItemCardContent`의 값 행을 `ListRow`(`label` + `value`, `flat`)로 바꾼다. `PoiEarnHistory`의 «처음 받은 날» 칩과 Strava 링크(행 밖 줄)는 그대로 둔다.
2. `LockedItemDetail`의 «필요 포인트 / 가진 포인트» 두 줄은 채원 판정 뒤 정한다: (가) `ListRow`로 옮기되 필요 포인트 값 24px 굵게는 `value`에 `ListRowEm`/호출부 스타일로 두는 안, (나) 이 두 줄은 행에서 제외하는 안. 슬롯을 늘려야 하면 MODULAR 원본 변경이라 승인 항목이다.
3. 시험: 위 시험이 통과해야 한다. 값 행 문구·순서가 그대로 나오는지 보는 단정이 없으면 추가를 판정한다.
4. 문서: 배지 상세·인벤토리 PRD 절에서 값 행 글자 서술이 있으면 갱신, 상위 티켓 5배치 표.

범위 밖: 시트 값 행(5-4), 온보딩 체크 목록, 약관 정의 카드·확률 표.

## 매핑표 (채원이 사전 판정에서 확정·교정한다)

| 현재 | 대응(안) |
|---|---|
| 획득 정보 카드: `flex justify-between items-center` 행 최대 4줄, 14, 카드 `gap-3` | `ListRow tone="flat" titleVariant="label"` + `value`. 카드의 줄 간격은 판정 |
| 활동 이름 값: `truncate max-w-[180px] text-right` | `value`(줄바꿈 허용이면 말줄임이 사라진다. 판정) |
| 체크인·아이템 획득 카드 14 | 같은 구성 |
| `LockedItemDetail` 필요 포인트 16/**24 굵게** `tabular-nums` | 판정 |

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **통일 크기**: 14를 16으로 키우면 카드 3곳의 높이가 늘고, 14로 내리면 5-4의 세 곳이 바뀐다. `ListRow` `label` 변형의 기본 크기를 기준으로 판정한다.
2. **긴 값**: 활동 이름이 지금은 180px에서 말줄임이다. 줄바꿈으로 바뀌어도 되는지, 말줄임을 지킬지 판정한다.
3. **카드 안 줄 간격**: 카드 `gap-3`(12px)과 `ListRow`의 행 안쪽 여백이 겹쳐 간격이 커질 수 있다. 카드 안에서 `separator` 없이 쓰는 구성을 판정한다.
4. **`LockedItemDetail` 24px 강조**: 위 범위 2의 (가)/(나).
5. **시험 부재**: `LockedItemDetail`은 시험이 없다. 최소 렌더 시험을 추가할지 판정한다.

## 구현 계획

파일 단위 계획. 코드 4개에 시험·문서가 더해지면 `plan_only` 임계값(파일 5개 초과)을 넘을 수 있다. 아현이 크기를 재서 넘으면 계획만 반환하고 카리나가 면제를 판단한다.

1. `badges/[id]/page.tsx` — 획득 정보 카드(634~668줄)의 값 행 교체.
2. `PoiEarnHistory.tsx` — `EarnCardContent`의 값 행 교체.
3. `ItemEarnHistory.tsx` — `ItemCardContent`의 값 행 교체.
4. `LockedItemDetail.tsx` — 판정에 따라 포인트 블록.
5. 시험과 문서.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 카드 안 값 행 3곳(+판정에 따라 `LockedItemDetail`)이 `ListRow`이고 라벨·값 문구와 순서가 그대로 나온다.
- 값 행의 글자 크기가 5-4의 세 곳과 같다(`grep`으로 `text-[14px]`·`text-sm` 값 행이 남지 않았는지 확인).
- «처음 받은 날» 칩, Strava 링크, 만료 «없음» 문구가 그대로다.
- 변경한 파일이 `scripts/verify.sh`와 `serviceLiteralColors` 시험을 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 개발 서버에서 획득 기록이 있는 배지 상세를 320px로 열어 전후 카드 높이와 긴 활동 이름을 비교한다. 데이터가 없으면 확인하지 못했다고 기록한다.
- 판정 1~5 결과를 상위 티켓에 기록하고, 상위 완료 조건 3을 다시 대조해 상위 티켓을 닫을지 묻는다.
