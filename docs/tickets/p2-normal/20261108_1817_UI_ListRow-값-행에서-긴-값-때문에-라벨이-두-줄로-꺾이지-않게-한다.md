# [UI] ListRow 값 행에서 긴 값 때문에 라벨이 두 줄로 꺾이지 않게 한다

## 핵심 요약

- 요구사항: `ListRow`의 값 행(`titleVariant="label"` + `value`)에서 값이 길면 라벨이 남는 폭에서 줄바꿈되어 «트리거 활동»이 «트리거 / 활동»으로 꺾인다. 값이 줄바꿈되는 것은 허용하되(5-4 사용자 승인) 라벨은 꺾이지 않게 하는 규칙을 `ListRow`에 정의한다. MODULAR 원본 변경이라 `ds` 유형이고 사용자 승인이 필요하다(2026-11-08 사용자가 티켓 개설을 승인했다. 규칙 자체의 승인은 채원 판정 뒤에 받는다).
- 구현 계획: 채원 사전 판정(규칙 안 확정과 **연결 범위** 판정, `.claude/skills/jam-work/references/ds-connection-scope.md` 기준) → 사용자 승인 → 아현 구현(원본 `.jsx`·`.d.ts`, 서비스 사본 `.tsx`, `prompt.md`, Story, 시험) → 민지 게이트 → 채원 사후 리뷰.
- 관련 파일: `jam-web/design-system/components/patterns/ListRow.jsx`(`isLabel` 226줄, 라벨 색 272줄, 값 칸 스타일 348~349줄), `jam-web/src/components/ui/ListRow.tsx`(`isLabel` 267줄, 라벨 색 313줄, 값 칸 스타일 389~390줄, `clamp` 80줄), `jam-web/design-system/components/patterns/ListRow.prompt.md`(7·9·18·19줄), `jam-web/design-system/components/patterns/ListRow.stories.tsx`(값 행 사례 232~238줄), `jam-web/src/components/ui/ListRow.test.tsx`, `jam-web/scripts/ds-sync-check.mjs`(원본·사본 쌍 검사).
- 담당 에이전트: 채원(사전 판정·사후 리뷰), 아현(구현), 민지(게이트).

## 배경 / 문제 정의

목록 행 4단계 5-5(`20261108_1627`)를 머지한 뒤 320px 실렌더(활동 배지 «획득 정보» 카드, `/badges/…?u=` 대상 유저의 읽기 전용 확인)에서 나온 장면이다.

- `ListRow` 값 칸은 `maxWidth: 60%`·`whiteSpace: normal`·오른쪽 정렬·`flexShrink: 1`이다(사본 389~390줄, 원본 348~349줄). 라벨은 `titleLines={0}`(줄 제한 없음)이라 남는 폭에서 줄바꿈된다.
- 카드 안쪽 폭 약 224px에서 값 «2026 JTBC 서울 마라톤 Full»이 60% 폭을 차지하고, 라벨 «트리거 활동»(약 82px)은 남은 약 90px에서 간격까지 합쳐 들어가지 못해 «트리거 / 활동»으로 두 줄이 된다. 이 줄에서 값도 두 줄이다(행 74px).
- 5-4 사용자 승인 2번(값 줄바꿈 허용)의 부수 효과다. 승인 당시 채원이 «실렌더에서 어색하면 그 장면과 함께 다시 올린다»고 했다.

## 사용자 결정

- 값 줄바꿈 허용과 값 굵게(700)는 5-4에서 승인했다. 이 티켓은 그 규칙을 뒤집지 않고 **라벨 쪽**만 다룬다.
- 새 토큰을 만들지 않는다. 값 행 라벨의 길이는 «획득 일시»·«활동 거리»·«트리거 활동»처럼 짧다는 전제(5-5·5-4 사용처 6곳 확인)로 판정하되, 긴 라벨이 들어와도 화면이 깨지지 않게 한다.
- 원본(`.jsx`)을 바꾸면 서비스 사본(`.tsx`)을 같이 바꾼다. `npm run ds:check`(쌍 검사)가 통과해야 한다. Storybook 사례(`D 값`)와 `prompt.md`를 함께 고친다.

## 사용자 결정 (2026-11-08, 채원 사전 판정 승인 항목 4건을 권고대로 승인)

1. **규칙 안**: 값 행(`titleVariant="label"`이고 `value`가 있고 `titleLines={0}`)의 라벨 칸을 `width: max-content`, `maxWidth: 50%`, `flex: 0 0 auto`로 둔다. 라벨이 값 때문에 꺾이지 않고, 50% 상한을 넘는 긴 라벨만 줄바꿈된다. `display: block`·`overflowWrap: break-word`는 유지한다. 티켓 안 (가) `nowrap` 단독, (나) `nowrap` + 값 칸 최소 폭, (다) NBSP는 채택하지 않는다.
2. 라벨 최대 폭은 **50%**다(새 시각 값 1개, 토큰이 아니라 레이아웃 비율이며 값 칸 최대 폭 60%와 짝이다). 40%는 320px에서 값 쪽 여유가 너무 적어 쓰지 않는다. 원본과 사본에 같은 리터럴로 두고 값 칸 60% 옆에 «라벨 50%와 값 60%의 합이 100%를 넘어도 값이 먼저 줄어든다»는 한 줄 주석을 남긴다.
3. 새 규칙은 `titleLines`를 1이나 2로 직접 정한 행에는 적용하지 않는다(호출부가 말줄임이나 줄 수 제한을 의도한 것). 값이 없는 `label` 행(체크 목록 E)에도 적용하지 않는다. 기본값(`label` + `value`의 `titleLines` 기본 1)은 바꾸지 않는다.
4. 서비스 호출부 코드는 바꾸지 않는다(`label` 사용처 12곳 중 `titleLines={0}` 11곳에 자동 적용, 탈퇴 시트 스켈레톤 1곳은 영향 없음).

## 범위

1. `ListRow`의 값 행에서 라벨이 값 때문에 꺾이지 않게 하는 규칙을 원본·사본에 정의한다(안은 아래 «판정이 필요한 점»).
2. `prompt.md` 9줄(값 행 라벨은 `titleLines={0}`을 쓴다)을 새 규칙에 맞게 고친다.
3. Story `D 값`에 «긴 값 + 짧은 라벨» 사례(예: 라벨 «트리거 활동» + 값 «2026 JTBC 서울 마라톤 Full»)를 더한다.
4. 시험: `ListRow.test.tsx`에 값 행 라벨이 줄바꿈 금지 스타일을 갖는지, 체크 목록(E)의 `label`은 그대로 줄바꿈되는지 단정을 더한다.
5. 서비스 사용처 확인: 값 행을 쓰는 곳(`WithdrawSheet`, 배지 상세 «획득 정보» 카드, `PoiEarnHistory`, `ItemEarnHistory`)이 깨지지 않는지, 체크 목록 사용처가 있으면 그것도 본다.
6. 문서: 값 행 글자 서술이 있는 곳, 상위 티켓 5배치 표.

범위 밖: 값 칸 최대 폭 60% 규칙 자체, 값 굵기, 5-5 이전 값 행 전환.

## 판정이 필요한 점 (채원 사전 판정 입력)

1. **규칙 안**:
   - (가) 값 행(`label` + `value`)일 때만 라벨 `white-space: nowrap`. 값이 남는 폭에서 줄바꿈된다. 긴 라벨이 오면 값 칸이 거의 0이 되어 화면이 깨질 수 있다.
   - (나) 라벨은 `nowrap`이되 값 칸에 `min-width`를 보장한다. 라벨이 너무 길면 라벨이 줄바꿈되는 상한을 정한다.
   - (다) 호출부가 라벨 문자열에 줄바꿈 없는 공백(NBSP)을 쓴다. MODULAR 변경은 없지만 사전 `d.*` 문구를 바꾸는 일이라 각 라벨마다 해야 하고 재발한다.
2. **체크 목록(E) 보호**: `label` 변형은 `prompt.md` 19줄의 체크 목록(아직 안 한 단계)에도 쓰인다. 그 라벨은 문장이라 줄바꿈이 필요하다. 규칙이 `value`가 있을 때만 켜지는지(값 행만 해당) 확인한다.
3. **`titleLines`와의 관계**: `titleLines={0}`(줄 제한 없음)과 새 규칙이 부딪치는지, 새 규칙이 있으면 호출부가 `titleLines={0}`을 줄 필요가 있는지 판정한다.
4. **연결 범위**(`ds` 유형): 원본·사본·Story·`prompt.md`·시험의 어디까지를 한 티켓에 묶는지(`ds-connection-scope.md`).
5. **실렌더 확인 항목**: 값이 매우 긴 경우(라벨이 한 줄 고정이라 값이 얼마나 좁아지는지), 320px에서 «획득 정보» 카드와 탈퇴 시트를 다시 잰다.

4. 사용처 확인(코드 변경은 판정에 따라).
