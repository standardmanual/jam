# [UI] 서비스 화면의 여백·카드 패딩·카드 간격 점검 (조사, 코드 무변경)

## 핵심 요약

- 요구사항: 서비스 화면의 페이지 여백, 카드 안 패딩, 카드 사이 간격이 규칙 없이 섞여 있다는 사용자 판단을 확인한다. 큰 값 금지, 컨텐츠 그룹에 맞는 간격, 카드 사이 넓은 간격 금지, 카드·버튼·폼의 균형을 기준으로 문제와 개선 방향을 프로토타입(아티팩트)으로 제시한다. 개발은 하지 않는다.
- 구현 계획: 없음(조사 티켓). 사용자가 아래 「먼저 정해야 할 것」 3건을 정하면 적용 티켓을 5단계 회차로 나눠 만든다.
- 관련 파일: 화면 루트 틀은 `jam-web/src/app/(main)/` 아래 각 화면(`page.tsx`, `profile/ProfileClient.tsx`, `profile/edit/page.tsx`, `missions/MissionsListClient.tsx`, `missions/[id]/MissionDetailClient.tsx`, `missions/[id]/status/MissionStatusClient.tsx`, `badges/BadgesClient.tsx`, `badges/[id]/page.tsx`, `collections/[id]/page.tsx`, `inventory/page.tsx`, `combine/CombineClient.tsx`, `points/page.tsx`, `notifications/NotificationsClient.tsx`, `voc/page.tsx`, `philosophy/page.tsx`). 눈금 토큰은 `jam-web/design-system/tokens/spacing.css`, 카드 기본 패딩은 `jam-web/design-system/components/cards/Card.jsx` 55줄.

## 배경 / 문제 정의

사용자가 서비스 페이지의 패딩, 카드 안 패딩, 카드 사이 간격이 특별한 규칙 없이 섞여 있다고 판단했다(2026-11-08). 화면을 하나씩 고치기 전에 현황을 숫자로 확인하고 기준 눈금을 먼저 정하기 위한 조사다.

## 조사 결과 (2026-11-08)

방법: 서비스 화면 16개의 최상위 틀 소스 대조 + stage(375px, 테스트 계정) 실측(홈·미션 목록·미션 상세·배지 목록·포인트)과 화면 캡처(프로필 편집·미션 상세 안쪽).

| 항목 | 현재 | 비고 |
|---|---|---|
| 가로 여백 | 16 (14개 화면), 24 (미션 상세·배지 상세) | 실측: 미션 목록 콘텐츠 왼쪽 16·폭 343, 같은 미션 상세는 왼쪽 24·폭 327 |
| 첫 요소 위 | 0·8·12·16·24·32·50·64 (8종) | 포인트·미션 상세·컬렉션 상세는 0, 문의 50(임의 값), 소개 64 |
| 맨 아래 | 12·16·24·32·40·64 | 임의 값 `pb-[32px]`·`pb-[40px]` 포함 |
| 구획 사이 | 8·12·16·24·32·64 (6종) | 알림 8, 컬렉션 상세 12, 소개 64 |
| 카드 안 패딩 | 12·16·24 | 홈 히어로·진행도·포인트 잔액 24, 홈 피드 12/16, 타일 12 |
| 카드 사이 | 8·12·16·24 | 실측: 포인트 내역 8, 홈 피드 16, 홈 위쪽 카드 24 |
| 폼 | 입력칸 → 다음 라벨 약 64 | 안내 문구 자리 24가 항상 비어 있고 필드 간격 32가 더해진다(프로필 편집, 캡처에서 읽은 값) |
| 눈금 토큰 사용 | 16개 화면 중 14개가 미사용 | 임의 px 값 16곳(14px 4, 32px 7, 40px 3, 50px 1, 13px 1) |

추가로 확인한 문제: 포인트 잔액 카드는 위아래 32를 클래스로 지정했지만 실측은 24다. 카드 기본값의 인라인 패딩(`var(--layout-card-padding)` = 24)이 먼저 적용되어 호출하는 쪽의 패딩 지정이 무시된다.

## 개선 방향 (제안)

1. 상한: 레이아웃 간격 32 이하, 카드 안 패딩 20 이하, 카드 사이 12 이하. 40 이상 눈금(40·48·64·96)은 화면이 직접 쓰지 못하게 뺀다.
2. 가까울수록 좁게: 라벨↔값 4, 제목↔본문 8, 묶음 안 12, 구획 사이 24, 큰 구획 전환 32.
3. 같은 종류는 같은 값: 카드 패딩 12(행·타일)·16(일반)·20(요약·히어로), 같은 목록의 카드 사이 8(이미지가 큰 카드만 12).
4. 화면 틀 한 번에 정하기: 가로 16 · 위 16 · 아래 32. 아래쪽의 하단 탭 가림 여유는 적용 때 실기기로 확인한다(이번에는 확인하지 않았다).
5. 폼: 라벨↔입력 8, 입력칸 → 다음 라벨 약 28(안내 자리 16 + 4 띄움 + 필드 간격 8), 버튼끼리 8, 입력↔버튼 영역 24.

전후 비교 프로토타입(홈·미션 상세·포인트·프로필 편집·소개 5화면, 간격 표시 포함): https://claude.ai/artifact/Po4G2tVK4P82b1G3MkH5uf

## 먼저 정해야 할 것 (추천 포함)

1. 미션 상세·배지 상세 가로 여백을 16으로 맞출까? 추천: 16 통일(목록↔상세 폭 일치).
2. 카드 기본 패딩을 24에서 16으로 낮추고 요약 카드만 20을 쓸까? 추천: 그렇게 한다. MODULAR 카드 기본값이 바뀌어 카드를 쓰는 모든 화면에 영향이 간다.
3. 소개 화면 구획 사이를 64에서 32로 줄일까? 추천: 32(위아래 여백도 16과 32로).

## 적용 시 회차 제안 (사용자 결정 뒤 별도 티켓)

1. 눈금과 이름 정의(40 이상 눈금을 화면 직접 사용에서 제외) 2. 화면 틀 통일(16개 화면 루트) 3. 카드 패딩 3종 확정과 Card 기본값 변경(ds, MODULAR 동기화) 4. 화면별 간격 정리(홈·미션 상세·포인트·프로필 편집·소개 순) 5. 규칙 검사 추가(눈금 밖 px·상한 초과를 검사 스크립트가 막음).

## 한계 (확인하지 않은 것)

데스크톱 폭의 간격, 어드민 화면, 드랍 지도 화면과 시트·모달류 안쪽 간격, 하단 탭 가림 여유. 프로필 편집과 미션 상세 안쪽 값은 캡처에서 읽은 값이라 약 ±2px 오차가 있다.
