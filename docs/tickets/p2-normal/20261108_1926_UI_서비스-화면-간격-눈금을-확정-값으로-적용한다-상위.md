# [UI] 서비스 화면 간격 눈금을 확정 값으로 적용한다 (상위, 5회차)

## 핵심 요약

- 요구사항: 조사 티켓 20261108_1846에서 사용자가 확정한 간격 눈금을 서비스 16개 화면에 적용한다. 코드 변경은 아직 시작하지 않았다.
- 구현 계획: 아래 5회차로 나눠 회차마다 하위 티켓을 만든다. 3회차(카드 패딩)는 MODULAR 카드 기본값이 바뀌어 영향이 가장 크다.
- 관련 파일: `jam-web/design-system/tokens/spacing.css`(눈금), `jam-web/design-system/components/cards/Card.jsx` 55줄(카드 기본 패딩 24), `jam-web/src/app/(main)/` 각 화면 루트(15개 파일은 20261108_1846 「관련 파일」 참조). 근거 아티팩트: https://claude.ai/artifact/Po4G2tVK4P82b1G3MkH5uf

## 확정 값

| 항목 | 확정 | 현재 |
|---|---|---|
| 화면 틀 | 가로 16 · 위 16 · 아래 24 | 가로 16/24, 위 0~64, 아래 12~64 |
| 구획·카드 블록 사이 | 20 (큰 구획 전환 24) | 8~64 |
| 묶음 안 | 블록 12 · 제목+본문 8 · 라벨+값 4 | 혼재 |
| 카드 사이 | 같은 목록 8 · 상세 화면의 이어진 카드 12 | 8·12·16·24 |
| 카드 안 패딩 | 16 (목록 행만 12/16) | 12·16·24 |
| 폼 | 라벨↔입력 4 · 입력칸 → 다음 라벨 16 · 버튼끼리 8 · 입력↔버튼 영역 20 · 안내 문구 자리는 오류 때만 | 입력칸 사이 약 64 |
| 상한 | 레이아웃 24 이하 · 카드 패딩 16 이하 · 목록 카드 사이 8 이하. 32 이상 눈금은 화면이 직접 쓰지 못하게 뺀다 | 40 이상 눈금 4개, 임의 px 16곳 |

## 회차

1. 눈금과 이름 정의(32 이상 눈금을 화면 직접 사용에서 제외) → 하위 티켓 20261108_1928 (완료). 클래스는 기존 규칙대로 Tailwind 기본 유틸리티를 쓰고, 이름은 CSS 변수와 대응표로 남긴다(별칭 없음)
2. 화면 틀 통일(16개 화면 루트, 미션·배지 상세 가로 16 포함) → 하위 티켓 20261108_2005 (완료). 아래 24가 하단 탭에 가리지 않는지 실기기 확인 포함
3. 카드 패딩 16 통일과 Card 기본값 변경(ds, MODULAR·Storybook·업로드본 동기화 포함). 카드 인라인 패딩이 호출부 지정을 덮는 문제도 함께 정리
4. 화면별 간격 정리(홈·미션 상세·포인트·프로필 편집·소개 순, 화면마다 실렌더 확인) → 하위 티켓 4a 20261108_2048(완료) · 4b 20261108_2049(완료) · 4c 20261108_2050(완료)(파일이 겹치지 않아 병렬)
5. 규칙 검사 추가(눈금 밖 px·상한 초과를 검사 스크립트가 막음) → 하위 티켓 20261108_2140

## 완료 조건

- 5회차 하위 티켓이 모두 닫히고, 16개 화면의 틀·카드 패딩·카드 사이가 위 확정 값과 같다(stage 375px 실측으로 확인).
- 규칙 검사가 눈금 밖 값을 막는다.

데스크톱 폭, 어드민, 드랍 지도 화면과 시트·모달류 안쪽 간격, 하단 탭 가림 여유(2회차에서 확인).
