# [Infra] 간격 눈금 밖 값을 검사가 막는다 (5회차)

## 핵심 요약

- 요구사항: 서비스 화면 소스에 눈금 밖 간격(임의 px 값, 32 이상)이 새로 들어오면 `scripts/verify.sh`가 실패하게 한다. 지금 남아 있는 위반은 기준선 파일에 파일별 개수로 고정하고, 개수가 늘거나 새 파일에 생기면 막는다(줄어드는 것은 허용, 기준선도 줄이도록 안내).
- 구현 계획: `scripts/check-spacing.mjs`(신규)가 서비스 소스를 읽어 위반을 세고 `scripts/spacing-baseline.json`(신규)과 견준다. `scripts/check-spacing.test.mjs`(신규)가 규칙·기준선 비교를 검증한다. `scripts/verify.sh`에 단계를 더하고 `docs/agents/contract.json`에 검사 줄을 더한다. DS readme 간격 절에 한 줄 안내(검사 이름과 기준선 줄이는 법)를 더한다.
- 관련 파일: `scripts/verify.sh`(`check-slop` 43줄·`check-contract` 72줄 단계와 같은 모양, 완료 문구 135줄), `scripts/check-slop.mjs`·`check-skills.mjs`와 각 `.test.mjs`(형식 참고), `docs/agents/contract.json`, `jam-web/design-system/readme.md`.
- 근거: 상위 티켓 20261108_1926, 아티팩트 https://claude.ai/artifact/Po4G2tVK4P82b1G3MkH5uf

## 검사 규칙

대상: `jam-web/src/app/(main)`, `(auth)`, `(onboarding)`, `(legal)`, `jam-web/src/components` 중 `admin/` 하위를 뺀 곳의 `.tsx`·`.ts`·`.css`. `*.test.*`·`*.stories.*`·`__tests__`·`dev-sample`·`spike`는 뺀다. 문자열 속 클래스를 정규식으로 센다(주석 줄도 센다, 단순하게).

1. 임의 px 간격: `(p|px|py|pt|pb|pl|pr|m|mx|my|mt|mb|ml|mr|gap|gap-x|gap-y|space-x|space-y)-[<숫자>px]` (예: `pt-[32px]`).
2. 32 이상 눈금: 위 접두의 Tailwind 단계 `8·9·10·11·12·14·16·20·24·28·32·36·40…`(= 32px 이상, 예: `gap-8`·`pb-10`·`pt-16`). 단 `w-`·`h-`·`size-`·`inset-`·`top-` 등 크기·위치 접두는 대상이 아니다. `-m*` 음수 마진은 대상에서 뺀다.
3. 인라인 `style`의 `padding`·`margin`·`gap` 값이 `var(--spacing-32|40|48|64|96)`을 참조하는 경우.

면제: 같은 줄에 `spacing-allow: <사유>` 주석이 있으면 센다 안 한다(사유 필수, 한 줄에 한 사유).

기준선: 위 규칙으로 센 파일별 위반 개수를 `scripts/spacing-baseline.json`에 `{ "경로": 개수 }`로 저장한다(현재 staging에서 한 번 생성). 검사는 (가) 기준선에 없는 파일의 위반, (나) 기준선보다 늘어난 파일을 실패로 낸다. 줄었는데 기준선이 그대로면 「기준선을 줄이세요」 안내만 낸다(실패 아님). `node scripts/check-spacing.mjs --write-baseline`으로 갱신한다.

## 완료 조건

- 규칙 1~3과 면제 주석, 기준선 비교가 `check-spacing.test.mjs`로 검증된다(임의 px·`gap-8`·`pt-16` 적발, `w-8`·`top-10`·음수 마진 무시, 면제 주석, 기준선 증가·신규 파일 실패, 감소 허용).
- 현재 staging 소스에서 `node scripts/check-spacing.mjs`가 통과하고(기준선 생성 직후), 위반 하나를 더하면 실패한다.
- `scripts/verify.sh`에 `spacing` 단계가 있고 완료 문구에도 포함된다. `docs/agents/contract.json`에 이 검사의 존재(경로)를 확인하는 줄이 있어 `check-contract.mjs`가 통과한다.
- DS readme 간격 절에 안내 한 줄이 있다. 화면의 동작·모양은 바뀌지 않는다.
