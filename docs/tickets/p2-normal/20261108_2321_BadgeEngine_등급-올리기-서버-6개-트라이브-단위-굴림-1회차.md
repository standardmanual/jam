# [BadgeEngine] 등급 올리기 서버: 6개, 트라이브 단위 굴림, Mystic 허용 (1회차)

## 핵심 요약

- 요구사항: 서버 규칙을 상위 티켓 20261108_2320의 결정대로 바꾼다. 재료 6개, 컬렉션 입력 없음, 트라이브의 활성 컬렉션 전체에서 아이템 배지 균등 굴림, Mystic 재료 허용(결과 Mystic 100%).
- 구현 계획: 아래 「파일별 계획」. 화면(`app/(main)/combine/**`)과 i18n 문구, 확률 안내·정책 대시보드·문서는 2·3회차 범위라 건드리지 않는다(화면이 아직 `collectionId`를 보내도 서버가 무시하고, 5개를 보내면 `invalid_count`로 거절한다).
- 근거: 상위 티켓 20261108_2320.

## 결정 (상위 티켓과 같음)

| 항목 | 결정(2026-11-08, 사용자) |
|---|---|
| 재료 | 같은 등급의 아이템 배지 6개(지금 5개). 중복 없음 |
| 결과 등급 | 지금 확률 유지: 윗등급 `combine_policy.tier_up_probability`(기본 0.7), 재료 등급 그대로 나머지(어드민에서 조정). Mystic 재료는 윗등급이 없어 Mystic 100% |
| 컬렉션 | 유저가 고르지 않는다. 소속 트라이브의 활성 컬렉션(공개 기간 안) 전체에서 아이템 배지마다 같은 확률로 뽑는다 |
| Mystic | Mystic 6개도 재료로 허용한다(Mystic이 나온다) |
| 같은 등급만 | 이미 구현되어 있다(첫 재료를 담으면 그 등급만 활성, 나머지 비활성). 6칸에서도 유지한다 |
| 후보 부족 | 굴린 등급의 후보가 트라이브에 없으면 소각 전에 거절한다. 지금처럼 재료 등급과 윗등급 후보가 모두 있어야 시작할 수 있다(윗등급 100%를 노린 재시도 방지) |

## 파일별 계획 (`jam-web/src/` 기준, 2026-11-08 staging)

| 파일 | 변경 |
|---|---|
| `lib/combine/tierUpOdds.ts` | `TIER_UP_MATERIAL_COUNT` 5→6, `TIER_UP_MATERIAL_RARITIES`에 `mystic` 추가. `tierUpProbabilities('mystic', p)`는 `[['mystic', 1]]`(확률 설정과 무관). `tierUpUpperRarity`의 Mystic 처리(윗등급 없음)와 `collectionSupportsTierUp` 대신 트라이브 단위 판정 `tribeSupportsTierUp(rarities, materialRarity)`(재료 등급과 윗등급 후보가 모두 있어야 시작, Mystic은 Mystic만) 추가. 기존 `collectionSupportsTierUp`·`issuableRaritiesByBook`는 2·3회차가 쓰는 동안 남기지 않고 이 회차에서 호출부(itemPaths 포함)를 모두 바꾼 뒤 삭제 여부를 정한다(화면 쪽 `tierUpClient.ts`가 가져오고 있으면 그 import만 2회차까지 남긴다) |
| `lib/combine/tierUp.ts` | 입력에서 `collectionId`를 빼고 `rollTierUp`이 트라이브의 후보 전체(`listIssueCandidates`, 소속 트라이브·활성·공개 기간)에서 굴린 등급의 아이템을 균등으로 뽑는다(`pickItemBadge`). 실행 순서의 «⑥-2 고른 컬렉션 검사»를 «트라이브에 후보가 있는지 검사(`tribeSupportsTierUp`)»로 바꾼다(소각 전 거절 유지). `invalid_collection` 거절 이유를 없앤다. 머리 주석을 새 규칙으로 고친다 |
| `app/api/combine/tier-up/route.ts` | 본문 `{ itemIds }` 6개. `collectionId`는 받아도 무시한다(검사하지 않는다). `invalid_collection` 문구 매핑 삭제, 머리 주석 갱신. `invalid_count`는 6개가 아닐 때 |
| `lib/admin/itemPaths/compute.ts`, `types.ts` | 등급 올리기 길을 «컬렉션이 재료 등급과 윗등급을 모두 가짐»에서 «그 컬렉션이 속한 트라이브의 활성 컬렉션 전체가 재료 등급과 윗등급 후보를 가짐»으로 바꾼다. 결과 등급 집합은 재료 M마다 {M, 윗등급}(Mystic은 {Mystic}) |
| 시험 | `lib/combine/__tests__/tierUp.test.ts`, `tierUpCollections.test.ts`, `app/api/combine/tier-up/__tests__/route.test.ts`, itemPaths 시험을 새 규칙으로 갱신(6개, 컬렉션 입력 없음, 트라이브 균등, Mystic 100%, 후보 부족 거절). 확률 안내가 쓰는 `tierUpProbabilities` 시험도 Mystic 줄을 더한다 |

## 완료 조건

- `tierUp`이 6개 재료와 `userId`만으로 동작하고, 굴림이 트라이브 전체 후보에서 균등이며, 재료·윗등급 후보가 없으면 소각 전에 거절한다.
- Mystic 재료 6개로 Mystic 결과가 나온다(확률 설정 무관). 5개나 7개는 `invalid_count`다.
- `collectionId`를 보내도 응답이 같고, 서버에 컬렉션 검사(`invalid_collection`)가 남지 않는다.
- 어드민 아이템 길의 등급 올리기 판정이 새 규칙과 일치한다.
- `scripts/verify.sh` 통과. 화면·문구·문서는 바뀌지 않는다.
