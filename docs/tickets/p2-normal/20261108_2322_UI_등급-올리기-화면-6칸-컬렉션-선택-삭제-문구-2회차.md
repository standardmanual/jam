# [UI] 등급 올리기 화면: 6칸, 컬렉션 선택 삭제, Mystic 재료, 문구 (2회차)

## 핵심 요약

- 요구사항: 믹스의 등급 올리기 화면을 새 규칙에 맞춘다. 재료 슬롯 6칸(3+3), «받을 컬렉션» 행과 시트 삭제, Mystic도 재료 등급으로 허용, 안내·오류 문구를 6개와 트라이브 무작위에 맞춘다. 같은 등급만 활성(첫 재료를 담으면 그 등급만 담을 수 있음)은 이미 있어 6칸에서도 유지하고 시험으로 지킨다.
- 구현 계획: 아래 「파일별 계획」. 서버·API는 1회차가 반영된 뒤 시작한다(요청 본문은 `{ itemIds }` 6개).
- 근거: 상위 티켓 20261108_2320, 1회차 20261108_2321.

## 결정 (상위 티켓과 같음)

| 항목 | 결정(2026-11-08, 사용자) |
|---|---|
| 재료 | 같은 등급의 아이템 배지 6개(지금 5개). 중복 없음 |
| 결과 등급 | 지금 확률 유지: 윗등급 `combine_policy.tier_up_probability`(기본 0.7), 재료 등급 그대로 나머지(어드민에서 조정). Mystic 재료는 윗등급이 없어 Mystic 100% |
| 컬렉션 | 유저가 고르지 않는다. 소속 트라이브의 활성 컬렉션(공개 기간 안) 전체에서 아이템 배지마다 같은 확률로 뽑는다 |
| Mystic | Mystic 6개도 재료로 허용한다(Mystic이 나온다) |
| 같은 등급만 | 이미 구현되어 있다(첫 재료를 담으면 그 등급만 활성, 나머지 비활성). 6칸에서도 유지한다 |
| 후보 부족 | 굴린 등급의 후보가 트라이브에 없으면 소각 전에 거절한다. 지금처럼 재료 등급과 윗등급 후보가 모두 있어야 시작할 수 있다(윗등급 100%를 노린 재시도 방지) |

## 완료 조건

- 등급 올리기 화면에 슬롯 6칸이 있고 컬렉션을 고르는 행·시트가 없다.
- 첫 재료를 담으면 그 등급만 담을 수 있고 나머지 등급은 비활성이다(Mystic 포함). 6개가 모이면 제출할 수 있다.
- 요청이 `{ itemIds }` 6개이고 응답 처리·결과 오버레이·거절 문구가 새 규칙과 맞다.
- 사용자 노출 문구에 5개·컬렉션 선택 표현이 남지 않는다. `scripts/verify.sh` 통과. 실렌더(375px)는 배포 뒤 카리나가 확인한다.
