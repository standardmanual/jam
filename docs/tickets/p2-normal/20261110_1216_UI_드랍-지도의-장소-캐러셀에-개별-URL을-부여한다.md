# [UI] 드랍 지도의 장소 캐러셀에 개별 URL을 부여한다

## 핵심 요약

- 요구사항: `/drops`에서 장소를 누르면 전체 화면 장소 캐러셀 모달(`PoiCarouselModal`)이 `carouselPoiId` 상태로만 열린다. 이를 쿼리 URL `/drops?poi=<장소ID>`에 싣는다. 열 때 history 항목을 쌓고, 뒤로가기(브라우저·기기)가 모달을 닫아 지도 화면으로 돌아가게 한다. 새로고침·링크로 열면 같은 장소의 캐러셀이 열린다.
- 구현 계획: 아래 「구현 계획」 참조.
- 관련 파일: `jam-web/src/app/(main)/drops/DropsClient.tsx`(`carouselPoiId` L73, 열기 L207, 모달 렌더 L321~327, 닫기 `onClose`), `jam-web/src/components/PoiCarouselModal.tsx`(`initialPoiId`·`selectedPoiId` props), 시험 `jam-web/src/app/(main)/drops/` 아래 기존 시험, 스펙은 `docs/service/prd/`에서 드랍·픽업 화면 설명을 찾는다

## 배경 / 문제 정의

디자이너가 «믹스하기의 개별 레시피 상세 화면처럼 개별 URL이 없는 화면들은 뒤로 가기(history back)가 안 돼서 불편하다. 같은 방식으로 표시되는 화면들에 개별 URL을 부여하라»고 했다(2026-11-10). 지금은 화면 안의 상태(`useState`)로만 화면이 바뀌어서, 브라우저·기기의 뒤로가기를 누르면 그 화면이 아니라 앞서 있던 다른 라우트로 나가 버린다. 전수 조사로 URL이 없는 곳을 찾았고, 디자이너가 아래 범위를 정했다: ① 믹스하기 레시피 상세·등급 올리기, ② 드랍 지도의 장소 캐러셀, ③ 탭·필터 전환. URL 모양은 쿼리 방식이고, 잘못된 값은 목록(기본 화면)으로 조용히 돌려보낸다. 온보딩 2단계와 시트·확인 오버레이는 이번 범위에 넣지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 모달 열림 상태를 URL(`useSearchParams`의 `poi`)에서 파생한다. 열 때 `router.push('/drops?poi=ID')`, 닫을 때는 push로 열린 경우 `router.back()`, 링크·새로고침으로 바로 열린 경우 `router.replace('/drops')`.
- 캐러셀 안에서 다른 장소로 넘기는 동작(있다면)은 history를 쌓지 않고 `replace`한다.
- 근처 장소 목록(`pois`)에 없는 장소 ID로 열면 모달을 열지 않고 `/drops`로 정리한다. 장소 목록이 아직 로딩 중일 때는 판정을 미룬다(로딩이 끝난 뒤 판정).
- 온보딩 퀘스트용 `QuestPickupScene`의 `carouselOpen`은 이번 범위가 아니다.

### UI/UX 관점
- 모달 모양은 그대로이고 뒤로가기 동작만 바뀐다.

### 컨텐츠 관점
- 새 문구 없음.

## 구현 계획

1. `jam-web/src/app/(main)/drops/DropsClient.tsx`: `useRouter`·`useSearchParams`로 `poi`를 읽어 `carouselPoiId`를 파생한다. 열기 함수(L207 안팎, `setCarouselPoiId(poiId)` 호출부)를 `router.push`로, `onClose`(L327)를 «닫기» 규칙으로 바꾼다. 장소 목록 로딩 후 존재하지 않는 ID는 `replace('/drops')`.
2. `jam-web/src/components/PoiCarouselModal.tsx`: 모달 안에서 장소가 바뀌는 곳이 있으면 URL을 `replace`로 맞춘다(`selectedPoiId`·`initialPoiId` 사용부 확인).
3. 시험: `DropsClient` 관련 시험에 열기=push, 닫기=back/replace, 잘못된 ID=정리를 더한다(없으면 순수 판정 함수를 떼어 시험).
4. 문서: 드랍 화면을 설명하는 PRD가 있으면 URL 규칙을 한 줄 적는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `/drops`에서 장소를 열면 주소가 `/drops?poi=<ID>`가 되고 history 항목이 쌓인다. 뒤로가기(브라우저·기기)를 누르면 모달이 닫히고 지도 화면이 남는다.
- `/drops?poi=<ID>`를 새로고침하거나 링크로 열면 같은 장소의 캐러셀이 열리고, 닫으면 `/drops`가 된다.
- 근처 장소에 없는 ID는 모달 없이 `/drops`로 정리된다.
- 시험이 통과하고 `scripts/verify.sh`가 통과한다(어드민 `Invalid hook call` 실패는 티켓 20261110_1157의 기존 문제).

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`에서 `/drops`의 열기·뒤로가기·새로고침을 눌러 확인한다(위치 권한이 필요하면 확인 불가 항목으로 보고한다).
