# [UI] 믹스하기 레시피 카드의 제목을 보상 배지명으로 바꾸고 아래 배지명 줄을 없앤다

## 핵심 요약

- 요구사항: 디자이너가 «레시피명은 해당 레시피로 만들어지는 배지명으로 하고, 레시피 제목 카드에 있는 레시피명 아래 배지명은 제거하라»고 했다(2026-11-10). 지금 믹스하기의 레시피 카드(목록 행과 상세 상단 요약 행)는 제목에 레시피 이름(`combination_recipes.name`), 그 아래 작은 글씨로 보상 배지명을 보여 준다. 제목 자리에 보상 배지명을 쓰고 아래 배지명 줄은 없앤다.
- 구현 계획: `RecipeRewardRow`가 보상 배지가 있으면 제목을 «대표 배지명(+N)»으로 그리고 meta의 배지명 줄을 그리지 않는다. 보상 배지가 없는 레시피(포인트만·보상 없음)는 레시피 이름을 제목으로 그대로 쓴다. 상세 요약 행의 배지 상세 링크는 제목으로 옮겨 밑줄 링크를 유지한다.
- 관련 파일: `jam-web/src/app/(main)/combine/RecipeRewardRow.tsx`(`badgeLine`·`meta`·`title` 전달부, 파일 후반), `jam-web/src/app/(main)/combine/CombineClient.tsx`(`recipeDisplayName` L272 안팎, 호출부 L968·L1093 안팎: 호출부는 바꾸지 않아도 된다), `jam-web/src/components/admin/ops/OpsKindPreview.tsx`(같은 컴포넌트를 쓰는 어드민 미리보기, 자동으로 따라온다), 시험 `jam-web/src/app/(main)/combine/CombineClient.test.tsx`의 `RecipeRewardRow` 구역, `jam-web/src/components/__tests__/safeImageCallSites.test.tsx`, 스펙 `docs/service/prd/01_PRD.md`(믹서 설명)

## 배경 / 문제 정의

레시피 이름(예: «노트 위의 별»)은 운영자가 붙인 이름이고, 사용자가 실제로 받는 것은 보상 배지(예: «접이식 테이블»)다. 카드 제목이 받는 배지의 이름이면 무엇을 얻는 레시피인지 바로 읽히고, 같은 정보를 두 줄에 나눠 적을 필요가 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 제목 규칙은 `RecipeRewardRow` 안에서 정한다(목록 행·상세 요약 행·어드민 미리보기가 같은 컴포넌트라 한 곳에서 맞춘다). `title` prop은 «보상 배지가 없을 때 쓰는 제목»(레시피 이름)으로 의미가 좁아진다.
- 보상 배지가 있으면 제목은 대표(첫 번째) 배지명이고, 2개 이상이면 지금 배지명 줄과 같이 ` +N`을 붙인다. 제목은 한 줄 말줄임(`titleLines={1}`)을 유지한다.
- 보상 배지가 없으면(포인트만, 보상 없음) 제목은 레시피 이름이다. «보상 없음» 부제(`d.combine.noRewardLabel`)와 «공개 예정» 줄은 그대로 둔다.
- 상세 요약 행(`linkBadge`)에서는 제목이 배지 상세(`/badges/{id}`)로 가는 밑줄 링크가 된다(지금 배지명 줄이 하던 일). 이미지 링크(`leadHref`)는 그대로다. 눌림 행(`onClick`, 목록)에서는 링크를 두지 않는 규칙도 그대로다.
- 등급 칩(eyebrow), «잠김» 칩, 포인트 값은 그대로다.
- 레시피 검색(`recipeMatchesSearch`)은 레시피 이름·후보 배지명·보상 배지명을 모두 찾는 지금 동작을 유지한다(제목에서 사라진 레시피 이름으로도 계속 찾을 수 있다).
- 서버·API·DB는 바꾸지 않는다.

### UI/UX 관점
- 카드의 높이가 한 줄 줄어든다(제목 + 배지명 두 줄 → 제목 한 줄, 공개 예정 줄이 있으면 그 줄은 남는다).
- 새 토큰·새 색을 만들지 않는다.

### 컨텐츠 관점
- 새 문구 없음.

## 구현 계획

1. `jam-web/src/app/(main)/combine/RecipeRewardRow.tsx`: `showBadge`일 때 제목 노드를 `primary.name` + `extraCount > 0 ? ' +N'`으로 만든다(`badgeHref`가 있으면 `Link`에 `underline underline-offset-2`). `badgeLine`의 배지명 노드를 없애고 `meta`는 «보상 없음» 부제와 «공개 예정» 줄만 남긴다. 머리 주석의 3케이스 설명(`eyebrow=등급 칩, meta=배지명`)과 `title` prop 주석을 새 규칙으로 고친다.
2. `jam-web/src/app/(main)/combine/CombineClient.test.tsx`: `RecipeRewardRow` 구역(공개 예정 줄·보상 없음·잠김 칩·ListRow 구조·획득 포인트 표기)에서 배지명이 meta에 있다고 단정하던 곳을 «제목이 배지명, meta에 배지명 없음»으로 고친다. 보상 배지 없음 레시피는 제목이 레시피 이름인 시험을 더한다. `jam-web/src/components/__tests__/safeImageCallSites.test.tsx`의 `RecipeRewardRow` 케이스가 깨지면 맞춘다.
3. `docs/service/prd/01_PRD.md`: 믹스 설명에 레시피 카드 제목 규칙(제목=보상 배지명, 배지가 없으면 레시피 이름)을 한 줄 적는다. `docs/service/content/COMBINE_RECIPES.md`에 카드 표기를 설명한 곳이 있으면 같이 고친다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 레시피 목록 행과 상세 상단 요약 행의 제목이 대표 보상 배지명이고, 배지가 2개 이상이면 ` +N`이 붙는다. 제목 아래의 배지명 줄은 없다.
- 보상 배지가 없는 레시피는 제목이 레시피 이름이고, 보상 없음 부제·공개 예정 줄·등급 칩·잠김 칩·포인트 값은 지금과 같다.
- 상세 요약 행의 제목은 배지 상세로 가는 밑줄 링크이고, 목록 행(누르는 행)에는 링크가 없다.
- 레시피 검색이 레시피 이름으로도 계속 찾아진다.
- 시험이 통과하고 `scripts/verify.sh`가 통과한다(메인 폴더의 어드민 `Invalid hook call` 실패는 티켓 20261110_1157의 기존 문제).
- PRD가 새 규칙과 맞다.
