# [Feature] 등급 올리기 확률 안내·정책 대시보드·운영 문서를 서비스 전체 풀로 갱신한다 (2회차)

## 핵심 요약

- 요구사항: 1회차(20261111_0846)가 반영된 뒤, «내 트라이브의 …»로 적힌 등급 올리기 설명을 «서비스에서 받을 수 있는 …»로 맞춘다. 정책 대시보드(`policiesData.ts`)는 CLAUDE.md 절대 규칙 2에 따라 같은 변경에서 갱신한다.
- 관련 파일(2026-11-11 staging 기준):
  - `jam-web/src/app/(legal)/probability/page.tsx` 72 (등급 올리기 소개 문단: 「내 트라이브의 새 아이템 배지를 받아요」), 75 (`TIER_UP_PICK_NOTE`: 「내 트라이브의 컬렉션 전체에서 …」), 23 (머리 주석). 읽기가 실패해도 그대로 두는 고정 문구다
  - `jam-web/src/lib/probability/disclosure.ts`: 트라이브 말은 없다(표는 확률만). 시험 `page.test.tsx`·`page.tierUp.test.tsx`가 문구를 대조하면 함께 고친다
  - `jam-web/src/lib/admin/policyDashboard/policiesData.ts` 870~880 («등급 올리기 규칙 (레시피 없음)»: `currentSpec`, `userExperience`, `ticketId`를 이 티켓으로), 필요하면 등급 올리기를 언급하는 다른 항목도 대조
  - `jam-web/src/lib/admin/balanceDashboard/targets.ts` 169 근처: 트라이브 말이 있는지 확인만
  - 문서: `docs/service/prd/probability/PRD.md` 61·91·148, `docs/service/SERVICE_OPERATIONS.md` 8-3절(672~680), `docs/service/content/COMBINE_RECIPES.md` 134·160, `docs/service/prd/01_PRD.md` 113, `docs/service/writing/UX_WRITING_GUIDELINE.md` 67, `docs/service/prd/admin-ui/ADMIN_PRD.md`·`02_DATA_MODEL.md`·`ops-tool/PRD.md`에서 등급 올리기+트라이브 문장, 운영 로직 정본 `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 8.4절(·18.3·19.3절에 트라이브 말이 있으면)
- 확률 안내 페이지는 법적 성격의 공개 문구라, 바뀐 문장은 **초안을 사용자에게 보여 확인받은 뒤** 확정한다(앞 회차 20261108_2323도 사용자 승인을 받았다).

## 상세 요구사항

- 유저에게 보이는 문구는 확률 숫자·「후보」 같은 내부 말을 쓰지 않는다(UX 라이팅 §3.3). 「내 트라이브」는 빼고, 받는 아이템 배지가 소속과 상관없다는 점이 읽히게 쓴다.
- 문서는 같은 사실을 여러 곳에 옮겨 적지 않는다: 정본(운영 로직 8.4절)을 고치고 나머지는 한 줄 규칙만 맞춘다(CLAUDE.md 절대 규칙 5).
- 1회차의 시작 검사 단위(서비스 풀에 재료 등급과 윗등급이 모두 필요)와 소속 트라이브가 없는 유저도 가능하다는 점을 문서에 반영한다.

## 완료 조건

- 위 파일에서 등급 올리기의 결과 후보를 «소속 트라이브»로 적은 문장이 없다(`grep` 확인, 재료는 트라이브 무관이라는 문장은 유지).
- 정책 대시보드의 «등급 올리기 규칙» 항목이 서버 규칙과 일치하고 `ticketId`가 이 티켓 계열이다.
- 확률 안내 페이지 시험과 `scripts/verify.sh` 통과.
- 바뀐 확률 안내 문구를 사용자가 확인했다.
