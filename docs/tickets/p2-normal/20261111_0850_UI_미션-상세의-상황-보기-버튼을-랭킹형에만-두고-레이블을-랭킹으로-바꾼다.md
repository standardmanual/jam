# [UI] 미션 상세의 «미션 상황 보기» 버튼을 랭킹형에만 두고 레이블을 «랭킹»으로 바꾼다

## 핵심 요약

- 요구사항: 달성형·개인형 미션은 미션 상세에서 상황 화면으로 가는 버튼을 주지 않는다. 랭킹형은 버튼 레이블을 «미션 상황 보기»에서 «랭킹»으로 바꾼다(사용자 지시, 2026-11-11).
- 구현 계획: 버튼을 그리는 조건에 `mission.status_display_type === 'ranking'`을 더하고, 문구 `d.missions.statusViewButton`의 값을 «랭킹»으로 바꾼다.
- 관련 파일:
  - `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.tsx` — «미션 상황 보기 — 참가자만» 블록(635행 부근). 미션 행은 `select('*')`로 읽혀 `status_display_type`이 이미 들어 있다.
  - `jam-web/src/lib/i18n/ko.ts` — `missions.statusViewButton`
  - `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.test.tsx` — 분기 시험 추가

## 배경 / 문제 정의

미션 상황 화면(`/missions/[id]/status`)은 표시 방식에 따라 랭킹형(포디엄·순위 목록), 달성형(달성 칩 목록), 개인형(내 현황 카드) 세 가지로 갈린다. 사용자는 이 중 랭킹형만 상세에서 진입시키기로 했고, 랭킹만 보이는 화면이 되므로 버튼 이름도 «랭킹»으로 줄였다.

## 상세 요구사항

### UI/UX 관점
- 랭킹형: 참가 중이거나 완료한 미션에 버튼을 그대로 두고 글자만 «랭킹»으로 바꾼다. 참가 전에는 지금처럼 없다.
- 달성형·개인형: 참가 중이든 완료했든 버튼을 그리지 않는다.
- `/missions/[id]/status` 화면과 API는 이번에 건드리지 않는다. 주소를 직접 열면 달성형·개인형 화면은 그대로 열린다(아래 잔여 이슈).

## 완료 조건

- 랭킹형 + 참가 중/완료: 링크 `/missions/{id}/status`가 «랭킹» 글자로 보인다.
- 달성형·개인형: 참가 중/완료 모두 링크가 없다.
- 이 문구를 단정하는 다른 시험·문서가 없다(grep 확인).

### 잔여 이슈
- 달성형·개인형 상황 화면(`MissionStatusClient`의 achievement·individual 분기와 API 분기)은 상세에서 닿는 길이 없어졌지만 코드는 남아 있다. 지울지는 사용자 결정을 기다린다.
- 같은 화면으로 가는 다른 길이 있다: 알림(`lib/notifications/href.ts` 145·197행)과 홈 카드(`lib/today/targetHref.ts` 78행의 랭킹 모드 대상). 이 두 곳이 달성형·개인형 미션 ID를 넘기는지는 확인하지 않았다.
