# [UI] 미션 상황 화면에서 달성형·개인형 코드를 지운다

## 핵심 요약

- 요구사항: 티켓 20261111_0850으로 미션 상황 화면(`/missions/[id]/status`)이 랭킹형만 열게 됐다. 이제 어떤 길로도 열리지 않는 달성형·개인형 화면 코드와 API 분기, 그 시험·문구를 지운다(사용자 지시, 2026-11-11).
- 구현 계획: 클라이언트에서 달성형·개인형 분기와 `AchievementRow`를 지우고, API는 랭킹형이 아니면 404를 돌려주며 달성형·개인형 분기를 지운다. 시험과 안 쓰는 문구 키도 함께 정리한다.
- 관련 파일:
  - `jam-web/src/app/(main)/missions/[id]/status/MissionStatusClient.tsx` — `AchievementEntry`·`IndividualStatus` 타입(30~45행), `StatusResponse`의 achievement·individual 변형(47~50행), `AchievementRow`(309행)·`SimpleAvatar`(328행), 렌더의 달성형(471~503행)·개인형(505~526행) 블록. `ListRow`·`ListRowChip` import는 이 둘만 쓴다(지울 것). `UserIcon`·`UsersIcon`·`EmptyState`·`ProgressBar`·`Card`는 랭킹형이 계속 쓴다. `isMeInEntries`의 `data?.type !== 'individual'` 조건은 단순화한다.
  - `jam-web/src/app/(main)/missions/[id]/status/AchievementRow.test.tsx` — 파일째 삭제
  - `jam-web/src/app/api/missions/[id]/status/route.ts` — `AchievementEntry`·`IndividualStatus` 타입(40행 부근), 개인형 분기(93~105행), 달성형 분기(157~176행). 미션 조회(55~58행) 직후 `status_display_type !== 'ranking'`이면 `d.missions.missionNotFound`로 404를 돌려준다(트라이브 제한과 같은 «없는 미션» 취급).
  - `jam-web/src/app/api/missions/[id]/status/__tests__/route.test.ts` — 달성형 정지 시험(「달성형: 정지 중인 달성자는 목록에서 빠진다」)과 개인형 시험(「개인형은 …정지 조회를 하지 않는다」)을 지우고, 「랭킹형이 아니면 404이고 정지 조회를 하지 않는다」를 더한다. 파일 머리말 주석의 «달성자 목록»·«개인형» 줄도 맞춘다.
  - `jam-web/src/lib/i18n/ko.ts` — `statusAchievementLabel`(881행)·`statusIndividualLabel`(882행)·`statusMeAchievement`(886행)을 지운다. `achieved`·`notAchieved`·`myProgressTitle`은 미션 상세와 랭킹 카드가 쓰므로 남긴다.
  - `jam-web/src/app/(main)/missions/[id]/status/page.tsx` — 이미 랭킹형이 아니면 상세로 돌려보낸다(0850). `displayType` prop은 건드리지 않는다.

## 배경 / 문제 정의

0850에서 상세의 «랭킹» 버튼을 랭킹형에만 두고, 상황 화면 서버 페이지가 랭킹형이 아니면 상세로 돌려보내게 했다. 그 결과 `MissionStatusClient`의 달성형·개인형 화면과 `/api/missions/[id]/status`의 같은 분기는 호출될 길이 없다.

## 상세 요구사항

### 지우지 않는 것 (범위 밖)
- DB 컬럼 `missions.status_display_type`과 `MissionStatusDisplayType` 타입(`types/database.ts`). 랭킹형 판정(알림 순위 상승, 랭킹모드 정합성 검사)이 계속 쓴다.
- 어드민의 «미션 상황 표시 방식» 선택(`admin/missions/MissionForm.tsx`, `admin/gate-missions/GateMissionForm.tsx`, `missionFormRules.ts`). 달성형·개인형 선택지를 없앨지는 사용자 결정이 따로 필요하다.
- `d.missions.achieved`·`notAchieved`·`myProgressTitle`, 미션 상세 화면.

### 동작
- 랭킹형 미션의 상황 화면과 API 응답(`type: 'ranking'`)은 지금과 같다.
- API는 랭킹형이 아닌 미션에 404(`missionNotFound`)를 돌려준다. 이때 정지 조회·참가자 조회를 하지 않는다.

## 완료 조건

- `AchievementRow.test.tsx`가 없다.
- API route에 개인형·달성형 분기와 타입이 없고, 랭킹형이 아니면 404다.
- `ko.ts`에서 지운 키 3개를 쓰는 곳이 없다(grep).
- `npm run verify` 계열(lint·typecheck·test)이 통과한다. 랭킹형 시험은 그대로 통과한다.
