# [UI] 캔버스에서 확정된 화면 수정을 서비스에 반영한다 (상위)

## 핵심 요약

- 요구사항: 사용자가 Claude 디자인 캔버스(https://claude.ai/artifact/UMeqT42Sg3Cyk38duATBS3)에서 직접 지시해 확정한 화면 수정 약 25건을 서비스 코드에 반영한다(2026-11-12 사용자 지시). 반영은 **디자인시스템 컴포넌트를 근원적으로 고치는 방식**이다. 화면마다 소스를 흩뿌려 고치지 않고, 한 곳을 고치면 모든 사용처가 따라오게 한다.
- 구현 계획: 회차 4개로 나눈다. 1회차 공통 버튼·더보기(20261112_1626), 2회차 컬렉션·믹스(20261112_1627), 3회차 포인트·아이콘·알림·홈·피드·검색(20261112_1628), 4회차 미션·체크인·캐러셀(20261112_1629). 회차는 같은 파일을 겹쳐 만지므로 순서대로 머지한다.
- 관련 파일: 각 회차 티켓의 «핵심 요약»에 파일 단위 지도가 있다.

## 배경 / 문제 정의

캔버스는 배포된 staging 화면을 그대로 옮긴 편집 가능한 사본이고, 사용자가 댓글로 화면별 수정을 확정했다. 코드에는 아직 반영되지 않았다. 캔버스의 최종 마크업 파일은 `/private/tmp/claude-502/-Volumes---------JAM-/eea63599-4894-44d0-9d68-758d14ecd3a9/scratchpad/canvas_new/project/*.dc.html`에 있다(보드 15개, 참고용. 값이 필요하면 이 파일의 인라인 스타일을 읽는다).

## 상세 요구사항

### 공통 원칙 (모든 회차)
- 캔버스는 **배포된 staging 기준**이라 최근 로컬 커밋(`ListRowChip` 규격 통일 등)이 이미 반영한 항목이 있을 수 있다. 코드를 먼저 읽고 **이미 충족한 항목은 고치지 않는다**.
- 서비스에는 디자인시스템 사본이 따로 있다(`jam-web/src/components/ui/{Button,ListRow,BadgeGridCard,BottomSheet,SlidingTabs}.tsx`). **사본을 고치면 DS 원본(`jam-web/design-system/components/**`)도 같이 고친다**(쌍 대조: `jam-web/scripts/ds-sync-check.mjs`, `src/components/ui/__tests__/buttonVariantPairs.test.tsx`).
- 색은 토큰만 쓴다: 회색 알약 `--btn-secondary`(#e5e5e5), 검정 `--foreground`·`--background-inverse`(#171717), 레드 `--jam-red`(#FF1D1D), 포인트 주황 `--point-text`(#ff4400), 바탕 `--background`(#f0f0f0), 카드 `--card-bg`(#fff), 보조 글자 `--muted`(#666). 새 하드코딩 색을 쓰지 않는다.
- 각 변경은 해당 컴포넌트의 Storybook 스토리와 `.prompt.md`·문서(`/jam-docs`)를 같이 갱신한다. 정책·수치가 아닌 화면 변경이라 `policiesData.ts`는 건드리지 않는다.
- 사용자 노출 문구는 `src/lib/i18n/ko.ts`의 키를 고친다(화면 안에 글자를 직접 쓰지 않는다).
- 사용자가 요청하기 전에는 push하지 않는다. 로컬 커밋까지만 한다.

### 확정된 해석 (캔버스 작업에서 사용자와 합의한 값)
- 포인트 아이콘의 바깥 검정 원(배지·미션 상세 보상 행의 `leadShape="round"`)은 남기고, **아이콘 자체의 서클만** 지운다.
- 믹스 '믹스하기' 버튼의 아이콘은 레시피 상세에서만 지운다(인벤토리 링크는 그대로).
- 교체 시트의 «빼기» 버튼은 크기만 시트 큰 버튼 규격으로 바꾸고 색(검정)은 유지한다.
- 미션 상세에서 포인트 보상 행·진행 상황 카드만 바꾸고, 배지 보상 행(`REWARD_ROW_STYLE` 공유)과 잠긴 보상 행은 그대로 둔다.

## 구현 계획

회차 티켓 4개를 순서대로 `/jam-work`로 처리한다. 각 회차는 아현 구현 후 민지 검토를 거치고 카리나가 staging에 머지한다. 전부 끝나면 상위 티켓을 닫는다.

## 완료 조건

- 하위 티켓 4개가 모두 CLOSED다.
- 캔버스의 각 수정 항목이 서비스 화면에서 같은 모양으로 보인다(staging 화면 확인은 사용자가 요청할 때 `[배포]` 빈 커밋으로 한다).
- 같은 변경이 컴포넌트 한 곳에서 이뤄졌고 개별 화면에 중복 소스가 늘지 않았다.
