## 배경 / 문제 정의

캔버스에서 사용자가 포인트 화면을 «프로필 전체 피드와 같은 행위·대상 이름·날짜시각» 구조로 바꾸고, 포인트 숫자는 믹스 레시피 목록처럼 «숫자와 포인트 두 줄, + 없음»으로 확정했다. P 아이콘은 «서클을 제거하고 P를 더 크게 볼드로, 색은 유지»(사용된 모든 곳)로 확정했고, P를 한 번 더 키우도록(130%) 두 번 지시했다(최종 배율 2.08).

## 상세 요구사항

### UI/UX 관점
- 위 지도의 값이 전부다. 새 색·새 크기를 만들지 않는다.
- 포인트 내역의 행위 라벨은 서비스에 이미 있는 사유 이름(`배지 보상`·`미션 보상`·`믹스 보상`·`믹스 실패 보상`·`컬렉션 완성 보상`·`포인트 조정`)을 쓴다. 새 문구는 만들지 않는다.
- 날짜는 한 줄에 들어가야 한다(`YYYY-MM-DD AM hh:mm`).

## 구현 계획

위 지도의 순서. API 응답 모양이 바뀌므로 소비처(`PointHistoryList`, 시험, 프로필 `#points`)를 같은 티켓에서 맞춘다.

## 완료 조건

- 포인트 아이콘에 원 외곽선이 없고 P가 크고 굵다. 6개 사용처가 한 번의 수정으로 모두 반영된다(소스에 사용처별 개별 스타일이 늘지 않는다). DS 사본과 서비스 사본이 같다.
- 포인트 화면 «현재 잔액»이 블랙 칩이다. 내역 행이 «행위·대상 이름·날짜시각» 3줄이고 서클이 없으며, 오른쪽이 숫자/«포인트» 두 줄(주황, + 없음, − 유지)이다.
- 검색 화면에 «2자 이상 입력해 주세요»가 없다. 홈 체크리스트에 체크 서클이 없다. 친구 활동 제목 옆에 «N개»가 없다.
- `/api/points` 시험, `PointHistoryList`·포인트 화면·`FeedSection`·`OnboardingQuestCard` 시험이 통과하고 `scripts/verify.sh`가 통과한다.
