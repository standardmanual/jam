# [UI] 등급 올리기 결과 연출을 블랙 전환·로고 흡수·배지 팝업으로 바꾼다

## 핵심 요약

- 요구사항: 등급 올리기 성공 뒤 지금은 일반 배지 획득 캐러셀(`BadgeRevealOverlay`)이 뜬다. 사용자가 캔버스 댓글로 확정한 7단계 연출(프로토타입 https://claude.ai/artifact/Gjtnm1EgMTM1i3gurETB2u, 현재 버전 7)로 바꾼다. 확인을 누르면 등급 올리기 화면이 슬롯이 빈 초기 상태로 돌아온다.
- 구현 계획: 새 전용 오버레이 컴포넌트를 만들고 `CombineClient.handleTierUp`의 «잠기지 않은 성공 결과»에서만 쓴다. 잠긴 결과와 받지 않은 결과(`pending`)는 지금 오버레이를 그대로 쓴다. 서버 응답에 결과 배지의 설명문(`description`)을 더한다.
- 관련 파일(지도, 경로 기준 `jam-web/`):
  - `src/app/(main)/combine/CombineClient.tsx`: `handleTierUp`(893행 부근, `setResult({... kind: 'tierUp'})` 두 갈래), `closeResult`(956행 부근, `closing?.kind === 'tierUp'`이면 `setTierUpSlots(emptyTierUpSlots())`), 결과 오버레이 렌더(1242행 부근 `<BadgeRevealOverlay>`), `toTierUpRevealBadges`(156행).
  - `src/app/(main)/combine/tierUpClient.ts`: `TierUpResultBadge`에 `description` 추가.
  - `src/lib/combine/tierUp.ts`: 결과 배지 `resultBadge`(234행 부근)에 `description` 추가, `rolled.badge`가 읽는 select(배지 조회부)에 `description` 컬럼 추가. 잠긴 결과는 이름·그림처럼 설명문도 싣지 않는다. `src/app/api/combine/tier-up/route.ts` 머리 주석의 응답 모양도 고친다.
  - 재료 그림 주소: `CombineClient`의 `tierUpFilled`(500행 부근, 슬롯별 인벤토리 개체)의 `badge.image_url`. 슬롯 화면 위치는 `TierUpPanel.tsx`의 슬롯(`SlotCircleButton`·배지 이미지)을 DOM에서 재서 오버레이가 시작 위치로 쓴다.
  - 로고: `public/jam-logo-white.png`(2610×865 흰색 로고).
  - 참고: `src/components/BadgeRevealOverlay.tsx`(오버레이 포털·z-index 방식), `../docs/service/prd/2026-08-15 DESIGN_RENEWAL_SPEC.md`의 «z-index 레이어 체계» 절.
  - 문서: `docs/service/prd/`의 믹스·등급 올리기 PRD 중 결과 연출을 적은 곳.

## 배경 / 문제 정의

사용자가 캔버스에서 «등급 올리기 버튼을 누르면 블랙 → 배지가 JAM 로고 뒤로 모임 → 로고가 화면을 채우며 사라짐 → 새 배지 팝업 → 이름·설명이 한 줄씩 → 확인» 흐름을 요청했고, 프로토타입을 보며 다음 사항을 확정했다(2026-11-12).

## 상세 요구사항

### UI/UX 관점 (프로토타입 v7이 기준이다 — 값은 프로토타입 코드를 그대로 옮긴다)

1. 배경: 전체 화면을 덮는 검은 층. **단색 블랙이 아니라 중심이 조금 밝은 원형 그라데이션** `radial-gradient(circle farthest-corner at 50% 42%, #343434 0%, #1a1a1a 38%, #000 100%)`. 0.5초 페이드인. 결과 배지 뒤의 glow(금색 후광)는 **두지 않는다**.
2. 재료 배지 6개는 지금 슬롯에 보이는 위치·크기(72px 안팎)·**원본 그림 그대로** 검은 층 위에 남는다(원래 슬롯의 배지는 가린다). 화면 하단에 JAM 로고(흰색)가 **좌우 여백 16px을 뺀 가로 폭 전체(361px 기준, 비율 유지)** 로 아래에서 살짝 올라오며 나타난다. 재료 배지는 하나씩(80ms 간격) 로고 뒤로 작아지며 모인다(로고가 배지보다 앞). 마지막 배지가 들어가면 로고가 한 번 살짝 커졌다 돌아온다.
3. 로고가 화면 위쪽으로 커지며 화면을 넘치게 채운 뒤 사라진다. **0.52초**(프로토타입 `d:520`, 곡선 `cubic-bezier(.6,0,.8,.3)`, 70% 지점에서 불투명도 1 유지 후 사라짐). 이후 0.1초 안에 4단계로 넘어간다.
4. 새 배지 이미지가 화면 위쪽 가운데(지름 200px)에서 팝업(0.2배 → 1.1배 → 1배, 0.65초)으로 나타난다.
5. 그 아래에 등급 칩 → 배지 이름 → 배지 설명문의 문장들이 **위에서 아래로, 한 줄씩 0.65초 간격으로 천천히**(각 0.7초, 위 14px에서 내려오며 나타남) 나타난다. **설명문은 새로 만들어진 아이템 배지의 설명문**이고 문장 단위로 나눠 한 줄씩 보인다(`splitDescriptionSentences`를 쓴다 — `BadgeHeroSection` 어댑터와 같은 규칙).
6. 하단에 흰 알약 «확인» 버튼(52px, 좌우 16px)이 아래에서 올라오며 나타난다.
7. 확인을 누르면 연출 요소가 모두 사라지고(0.4초) 검은 층이 사라진 뒤(0.45초) **등급 올리기 화면이 초기화된 상태(슬롯 6칸 모두 비움)** 로 돌아온다(지금 `closeResult`의 `setTierUpSlots(emptyTierUpSlots())` 동작과 같다).
- 잠긴 결과(`locked`)와 받지 않은 결과(`resultStatus: 'pending'`)는 이 연출을 쓰지 않고 지금 오버레이(`BadgeRevealOverlay`)를 그대로 쓴다. 연출은 «잠기지 않은 성공»에만 붙는다.
- 요청이 끝나기 전에는 연출을 시작하지 않는다(제출 중 로딩 상태 그대로). 결과 응답이 오면 시작한다.
- 모션 줄이기 설정(`prefers-reduced-motion`)에서는 전환을 짧은 페이드로 대신한다(크기 변화 없음).
- 접근성: 오버레이는 `role="dialog"`·`aria-modal`로 열고, «확인» 버튼에 포커스를 둔다. 결과 문구(이름·설명)는 `aria-live`로 읽힌다.

### 서비스/코드베이스 관점

- 새 오버레이는 service 전용 컴포넌트(`src/components/`)로 만든다. MODULAR 승격 여부와 토큰·레이어 결정은 채원① 판정을 따른다(오버레이 z-index 층 서열은 DESIGN_RENEWAL_SPEC을 따른다).
- 모든 색은 토큰이거나 이 연출 전용의 검정·흰색 리터럴이어도 된다(캐러셀 오버레이가 이미 어두운 면을 쓰는 방식을 따른다 — `serviceLiteralColors.test.ts` 규칙을 확인한다).
- 서버 응답에 `description`(string | null)을 더한다. 잠긴 결과에는 싣지 않는다. 기존 응답 소비처(`toTierUpRevealBadges`)는 `description: ''` 대신 이 값을 쓴다.

## 구현 계획

1. 서버: `lib/combine/tierUp.ts`가 읽는 결과 배지 조회에 `description`을 추가하고 `TierUpResultBadge`·응답·라우트 주석·시험에 반영한다.
2. 클라이언트 타입·도우미: `TierUpResultBadge.description`, 설명문을 문장 줄로 나누는 순수 함수 사용.
3. 새 오버레이 컴포넌트(예: `TierUpRevealOverlay`): props — `open`, `materials`(그림 주소와 화면 시작 위치 배열), `result`(이름·등급·그림·설명 줄), `onConfirm`. 시퀀스는 Web Animations API로 프로토타입 값을 옮긴다. 시작 위치는 `TierUpPanel` 슬롯 DOM의 `getBoundingClientRect`를 오버레이가 열릴 때 한 번 잰다.
4. `CombineClient`: `result.kind === 'tierUp'`이고 잠기지 않은 성공이면 새 오버레이를, 아니면 기존 `BadgeRevealOverlay`를 연다. 확인 시 `closeResult`를 호출한다.
5. 시험·PRD 갱신.

## 완료 조건

- 잠기지 않은 등급 올리기 성공 결과에서 새 오버레이가 열리고, 7단계가 프로토타입 v7과 같은 순서·시간으로 재생된다. 확인을 누르면 오버레이가 닫히고 슬롯 6칸이 모두 비어 있다(시험으로 확인).
- 설명문이 서버 응답의 새 배지 `description`에서 오고 문장 단위 줄로 나뉜다. 응답의 잠긴 결과에는 `description`이 없다(서버 시험).
- 잠긴 결과·받지 않은 결과는 기존 오버레이가 뜬다(기존 시험 통과).
- 배경이 중심이 밝은 원형 그라데이션이고 글로우가 없다(시험에서 스타일 문자열 확인).
- 모션 줄이기 설정에서 크기 변화 없이 페이드만 쓴다.
- `scripts/verify.sh` 통과, `ds:check` 오류 0.
- 확인하지 못하는 항목(실제 재생 부드러움, 슬롯 실좌표)은 완료 기록에 적고 메인 트리 `next dev`에서 실렌더로 확인한다.
