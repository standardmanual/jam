# [Infra] 아이템 배지 이미지 생성기의 프리셋·묘사 문장·생성 이력 표를 만든다

> 묶음: 20261113_1130(DB) → 20261113_1131(서버) → 20261113_1132(어드민 화면). 이 티켓이 첫 번째다.

## 핵심 요약

- 요구사항: 어드민 「디자인 > 이미지 생성」(Recraft로 아이템 배지 이미지를 만드는 생성기)이 쓸 표 3개를 새로 만든다. ① 프리셋(스타일 ID + 고정 요청 틀) ② 아이템별 묘사 문장(Claude가 쓴 문장을 저장해 재사용) ③ 생성 이력(보낸 요청 전체·후보 이미지·적용 여부·이전 이미지 주소). 기존 표는 바꾸지 않는다.
- 구현 계획: 확장 단계 마이그레이션 하나(`jam-web/supabase/migrations/3XX_badge_image_generator_tables.sql`)와 되돌림 SQL(`_down.sql`)을 쓴다. 번호는 작성 시점의 `origin/staging` 최대 번호 + 1(2026-11-13 기준 336이 최대). **SQL 실행은 하지 않는다**(카리나가 머지 뒤 실행).
- 관련 파일: `jam-web/supabase/migrations/`(새 파일 2개), `jam-web/src/types/database.ts`(새 표 행 타입 3개 추가, `BadgeRow` 근처), 규칙 `.claude/skills/jam-work/references/db-migration-rules.md`

> 2026-11-13 갱신: 티켓 20261113_1145로 `badges.form_description`(한국어 형태 묘사)이 생겨, 영어 묘사 문장은 이 칸을 옮긴 결과가 되고 원문 지문 칸 `source_hash`를 더했다. 고정 문장에 의인화 금지와 「한 덩어리」 허용을 반영했다.

## 배경 / 문제 정의

아이템 배지 450종(`badges.gaze_motion` 값이 있는 4등급 아이템, 아이템당 4행이 같은 `image_url`을 공유)에 이미지가 거의 없다(이미지 있는 아이템 4종). 기존 `/jam-img` 스킬·`scripts/recraft`·캔버스 생성기는 쓰지 않고(사용자 지시), 어드민에서 Recraft 스타일 ID로 일관된 이미지를 만드는 새 생성기를 만든다. 같은 요청 형식을 계속 보내야 결과가 흔들리지 않으므로 요청 틀을 프리셋으로 저장하고, 토큰을 아끼려고 Claude가 쓴 묘사 문장을 DB에 저장해 재사용한다.

## 상세 요구사항

### 서비스/코드베이스 관점

**표 ① `badge_image_presets`**
- `id` uuid PK, `name` text not null unique, `style_id` text not null (Recraft 스타일 ID)
- `model` text not null default `'recraftv3'`
- `composition_text` text not null (구도·형태 고정 문장), `forbid_text` text not null (금지 고정 문장)
- `negative_prompt` text not null default ''
- `background_color` text not null default `'#F2F2F2'` (hex)
- `version` int not null default 1 (고정 문장·설정을 고칠 때마다 1 증가 — 서버가 올린다)
- `is_active` boolean not null default true, `created_at`/`updated_at` timestamptz default now()
- 시드 1행: 이름 `기본`, `style_id`는 빈 문자열이 아닌 자리표시자 `'SET_ME'`, 고정 문장 2개와 네거티브는 아래 「시드 값」 그대로

**표 ② `badge_image_item_prompts`** — 아이템(=같은 컬렉션 안 같은 이름의 등급 행 묶음)당 1행
- `id` uuid PK, `item_book_id` uuid not null references `item_books(id)` on delete cascade, `item_name` text not null
- `description_en` text not null (형태 묘사를 Claude가 옮긴 영어 문장, 또는 운영자가 고친 문장)
- `source_hash` text not null (영어 문장을 만들 때 쓴 `badges.form_description`의 sha256 16진수 — 원문이 바뀌면 화면이 「원문이 바뀌었어요」를 띄운다)
- `source` text not null check in (`'claude'`, `'manual'`)
- `updated_at` timestamptz default now()
- unique (`item_book_id`, `item_name`)

**표 ③ `badge_image_generations`** — 생성 1회(후보 2장)당 1행
- `id` uuid PK, `item_book_id` uuid not null references `item_books(id)` on delete cascade, `item_name` text not null
- `preset_id` uuid references `badge_image_presets(id)` on delete set null, `preset_version` int not null
- `prompt` text not null (Recraft에 보낸 최종 프롬프트 전체), `request_json` jsonb not null (모델·크기·n·style_id·controls·negative_prompt 전체)
- `candidate_urls` text[] not null default '{}' (Recraft 원본 후보를 저장소에 옮긴 주소)
- `status` text not null default `'generated'` check in (`'generated'`, `'applied'`, `'reverted'`, `'failed'`)
- `applied_index` int (적용한 후보 번호, 0 또는 1), `applied_url` text (적용한 최종 WebP 주소), `previous_image_url` text (적용 직전 4등급 공통 `image_url`, 되돌리기용)
- `feedback` text (이 생성 직전 운영자가 입력한 불만족 사항, 없으면 null)
- `error` text, `created_by` text (어드민 이메일), `created_at` timestamptz default now(), `applied_at` timestamptz
- 인덱스: (`item_book_id`, `item_name`, `created_at desc`)

**공통**
- 세 표 모두 RLS를 켜고 정책은 만들지 않는다(서비스 롤만 접근 — 어드민 API가 `createServiceClient`로 읽고 쓴다). `anon`·`authenticated`에 대해 `revoke all`을 명시한다.
- 되돌림 SQL은 세 표를 `drop table if exists`로 지운다(새 표뿐이라 데이터 손실은 이 기능의 데이터뿐).

**시드 값**
- `composition_text`: `A single object (or one compact group of the same object) for a collectible badge, centered, the whole object fully visible with generous empty space around it, seen from a slight three-quarter angle. Clear, simple silhouette that reads at small sizes. Restrained detail, soft even light, plain solid background.`
- `forbid_text`: `No text of any kind: no letters, numbers, symbols, labels, signs, signatures, logos or letter-like marks. No faces, no eyes, no people, no hands, no extra objects, no glow, no sparkles, no dramatic lighting, no border, no scenery.`
- `negative_prompt`: `text, letters, numbers, digits, symbols, writing, label, signature, logo, watermark, face, eyes, cartoon character, people, hands, multiple objects, cropped, glossy, plastic, sparkles, glow, lens flare, bokeh, dramatic lighting, hyperrealistic, oversaturated, cluttered, ornate, scenery`

## 구현 계획

1. 마이그레이션 SQL 1개 + `_down.sql` 1개 작성(확장 단계만, 기존 표 무변경).
2. `jam-web/src/types/database.ts`에 `BadgeImagePresetRow`, `BadgeImageItemPromptRow`, `BadgeImageGenerationRow` 타입 추가.
3. SQL은 실행하지 않는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 새 마이그레이션 파일이 표 3개·제약·인덱스·RLS·revoke·시드 1행을 위 명세대로 만든다(SQL 본문으로 대조).
- `_down.sql`이 세 표를 지우고 기존 표를 건드리지 않는다.
- 행 타입 3개가 SQL 칸과 이름·nullable 여부가 일치한다.
- `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 번호 충돌을 `origin/staging` 기준으로 재확인하고, 드라이런(DO 블록 롤백) 뒤 실행, 실행 직후 표 3개와 시드 1행을 읽기 전용으로 확인한다.
