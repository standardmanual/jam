# [Admin] 어드민 디자인 섹션에 아이템 배지 이미지 생성 화면을 만든다

> 묶음: 20261113_1130(DB) → 20261113_1131(서버) → **20261113_1132(어드민 화면)**. 1131이 staging에 머지된 뒤 시작한다.

## 핵심 요약

- 요구사항: 어드민 「디자인」 섹션에 「이미지 생성」 메뉴(`/admin/image-generator`)를 더하고, 1131의 API로 아이템 배지 이미지를 만드는 화면을 만든다. 컬렉션 검색 → 아이템 선택 → 프리셋 선택 → 후보 2장 생성 → (다시 뽑기 / 묘사 직접 수정 / 불만족 입력 재생성) → 적용 → 필요하면 되돌리기. 프리셋 관리도 이 화면에서 한다.
- 구현 계획: 페이지 1개 + 클라이언트 컴포넌트 4개 + 메뉴 항목 1줄(+메뉴 시험 갱신). UI는 `jam-web/src/components/ui`의 shadcn 컴포넌트만 쓴다(네이티브 select 금지).
- 관련 파일: `jam-web/src/components/admin/adminNavItems.ts`(`id: 'design'` 묶음, 103~110줄 — `에셋` 아래에 `{ href: '/admin/image-generator', label: '이미지 생성', icon: IconSparkles }` 추가), `jam-web/src/components/admin/__tests__/adminNavItems.test.ts`(89~91줄 근처 경로 목록), 새 폴더 `jam-web/src/app/admin/image-generator/`. API 계약은 `docs/tickets/p2-normal/20261113_1131_API_아이템-배지-이미지-생성기의-Recraft·Claude-서버-기능을-만든다.md` 「서비스/코드베이스 관점」 1~6.

## 배경 / 문제 정의

1130·1131 티켓 참고. 운영자(디자이너)가 아이템 450종의 이미지를 일관된 톤으로 만들고 바로 배지에 반영하는 화면이 필요하다. 적용은 공용 DB라 프로덕션에 즉시 반영되므로, 되돌리기와 이력을 화면에서 바로 쓸 수 있어야 한다.

## 상세 요구사항

### UI/UX 관점

화면은 좌우 두 칸(좁은 화면에서는 위아래).

**왼쪽: 컬렉션과 아이템**
- 컬렉션 검색 입력(`GET items?q=`) → 결과 목록에서 하나 선택.
- 선택한 컬렉션의 아이템 목록(`GET items?bookId=`): 썸네일(현재 이미지, 없으면 빈 칸), 아이템 이름, 상태 표시(`이미지 없음` / `후보 있음` / `적용됨`).

**오른쪽: 선택한 아이템**
1. 아이템 이름과 「시선과 동작」(읽기 전용).
2. 프리셋 선택(shadcn Select). 기본값은 이 컬렉션에서 마지막으로 쓴 프리셋, 없으면 `기본`. 프리셋 `style_id`가 `SET_ME`면 생성 버튼을 막고 「프리셋에 스타일 ID를 먼저 넣어 주세요.」 안내.
3. 묘사 문장(영어) 텍스트 영역. 저장본을 보여 주고 고칠 수 있다. 고친 뒤 「문장 저장」 → `describe`에 `manualText`.
4. 버튼: 「생성」(저장본이 없으면 서버가 문장부터 만든다), 「다시 뽑기」(같은 문장으로 생성 — Claude 호출 없음, 생성 기록이 하나라도 있을 때만 보임).
5. 불만족 사항 입력칸 + 「반영해서 다시 생성」 → `generate`에 `feedback`. 입력이 비어 있으면 버튼 비활성.
6. 후보 2장 미리보기(체크무늬 배경 위, 정사각). `touchesEdge`가 true인 후보에는 「그림이 잘렸을 수 있어요」 경고 표시. 각 후보 아래 「이 이미지 적용」.
7. 적용 확인 대화상자: 「이 이미지를 4개 등급 배지에 바로 적용합니다. 서비스에 즉시 보여요.」 확인 시 `apply`. 409 `text_detected`면 「이미지 안에 글자로 보이는 부분이 있어 적용하지 않았어요. 다시 뽑거나 문장을 고쳐 주세요.」
8. 생성 이력(최근 10개): 시각(KST), 프리셋 이름·버전, 상태, 후보 썸네일. `applied` 기록에 「되돌리기」(확인 대화상자 뒤 `revert`).
9. 생성·적용 중에는 버튼을 막고 진행 표시를 한다(Recraft는 수십 초 걸릴 수 있다).

**프리셋 관리**(화면 상단 「프리셋 관리」 버튼 → 시트 또는 대화상자)
- 목록: 이름, 스타일 ID, 모델, 버전, 적용된 아이템 수.
- 추가·수정 폼: 이름, 스타일 ID, 모델(`recraftv3` / `recraftv4_1` 등 텍스트 입력 대신 Select로 `recraftv3`, `recraftv4`, `recraftv4_1`), 구도 고정 문장, 금지 고정 문장, 네거티브 프롬프트(「recraftv3에서만 적용돼요」 보조 문구), 배경색(hex 입력).
- 이미 적용한 아이템이 있는 프리셋을 고칠 때 「이 프리셋으로 적용한 아이템 N개와 분위기가 달라질 수 있어요.」 경고.

### 서비스/코드베이스 관점
- 페이지는 서버 컴포넌트(`page.tsx`)에서 관리자 확인 후 클라이언트 컴포넌트를 렌더한다(기존 어드민 페이지 패턴을 따른다).
- 문구는 해요체. 시각은 KST로 표시.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 어드민 사이드바 「디자인」 묶음에 「이미지 생성」이 「에셋」 아래에 보이고 `/admin/image-generator`로 간다(메뉴 시험 통과).
- shadcn 컴포넌트만 쓰고 네이티브 `<select>`가 없다.
- 「다시 뽑기」는 `describe`를 부르지 않고 `generate`만 부른다(코드로 확인).
- 적용·되돌리기는 확인 대화상자를 거친 뒤에만 API를 부른다.
- `scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤 push 전)
- 로컬 `next dev`(`ADMIN_EMAILS` 셸 변수)로 화면을 열어 컬렉션 검색·아이템 선택·프리셋 관리 화면이 렌더되는지 확인한다. 실제 생성·적용은 사용자가 스타일 ID를 넣은 뒤 함께 시험한다.
