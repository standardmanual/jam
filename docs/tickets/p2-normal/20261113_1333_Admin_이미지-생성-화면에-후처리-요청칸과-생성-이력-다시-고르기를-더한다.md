# [Admin] 이미지 생성 화면에 후처리 요청칸과 생성 이력 다시 고르기를 더한다

> 묶음: 20261113_1332(DB·서버) → **20261113_1333(화면)**. 1332가 머지된 뒤 시작한다.

## 핵심 요약

- 요구사항(사용자 2026-11-13): ① 후보 이미지를 하나 골라 「후처리 요청」 칸에 지시를 적고 「처리」를 누르면 Claude가 Recraft로 다시 처리한 결과를 새 후보로 보여 준다 ② 생성 이력(최근 10개)의 이미지도 다시 골라 후처리·적용에 쓸 수 있다.
- 구현 계획: `ItemWorkbench.tsx`에 「작업 이미지」 선택 상태를 두고, 후보 카드와 이력 썸네일 모두 클릭으로 작업 이미지를 고른다. 작업 이미지 아래에 후처리 요청 칸·「처리」 버튼·「이 이미지 적용」을 둔다. API 호출은 `imageGeneratorApi.ts`에 `editImage()`를 더한다.
- 관련 파일: `jam-web/src/app/admin/image-generator/ItemWorkbench.tsx`(후보 영역 약 62줄 근처·이력 영역), `jam-web/src/app/admin/image-generator/imageGeneratorApi.ts`, API 계약은 1332 티켓 「edit 라우트」·「적용 조건 완화」 절과 머지된 `jam-web/src/app/api/admin/badge-image-generator/edit/route.ts`(코드가 우선).

## 상세 요구사항

### UI/UX 관점

1. **작업 이미지 고르기**: 후보 카드(현재 생성분)와 생성 이력의 썸네일 모두 누르면 「작업 이미지」로 선택된다. 선택된 이미지는 테두리로 표시한다. 기본값은 가장 최근 후보의 첫 장.
2. **작업 이미지 영역**(후보 아래): 큰 미리보기(체크무늬 배경), 출처 표시(「후보 1」, 「이력 11월 13일 13:05 · 후처리」 등), `touchesEdge`면 「그림이 잘렸을 수 있어요.」.
3. **후처리 요청**: 여러 줄 입력칸(placeholder 「예: 오른쪽 종이를 지워 줘, 잘린 윗부분을 살려 줘」, 300자 제한) + 「처리」 버튼. 입력이 비면 버튼 비활성. 처리 중에는 「처리하는 중이에요 (최대 1분)」와 함께 버튼을 막는다.
4. 처리 결과는 새 후보로 보여 주고 자동으로 작업 이미지로 고른다. Claude가 고른 방법을 한 줄로 보인다: 「지우기 · <reason_ko>」, 「다시 그리기 · …」, 「바깥 넓히기 · …」, 「다시 칠하기 · …」.
5. 오류: `plan_invalid`면 「요청을 처리 방법으로 바꾸지 못했어요. 지울 부분이나 바꿀 내용을 더 구체적으로 적어 주세요.」, 그 밖에는 서버 오류 문구.
6. 「이 이미지 적용」은 작업 이미지 기준으로 기존 확인 대화상자를 거쳐 `apply(generationId, index)`를 부른다. 이미 적용 중인 기록(`applied`)이면 버튼을 막고 「지금 적용된 이미지예요.」.
7. 생성 이력 행에 편집 기록은 「후처리」 표시와 요청 원문(한 줄 말줄임)을 보인다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 후보 카드와 이력 썸네일 클릭이 같은 작업 이미지 상태를 바꾼다(코드로 확인).
- 「처리」는 입력이 있을 때만 `edit`를 부르고, 결과를 새 후보·작업 이미지로 반영한다.
