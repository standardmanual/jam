# [UI] 위치를 쓰기 전 안내와 허용 방법 화면을 캔버스대로 만든다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-14, 클로드 캔버스 보드 «JAM · 위치 허용 전» 댓글): 위치 사용을 안내하는 «위치정보 사용 동의» 화면을 캔버스대로 만들어 서비스(`/drops`)에 적용한다. 카드 배경은 약한 투명(흰 면 72%)을 쓴다.
- 시안 구성: 화면 제목 «JAM», 카드 한 장(원형 핀 아이콘, «근처 장소를 보려면 위치가 필요해요», 설명 두 문장, «허용하는 방법» 3단계 구획, «허용했어요, 다시 시도» 버튼). 카드 뒤에는 지도 윤곽이 희미하게 비친다(약한 투명이 보이게 하는 장치로, 실제 지도 레이어를 쓸지 단색 바탕으로 둘지는 채원이 판정한다).
- 구현 계획: `DropsClient.tsx`의 `locError` 분기(약 275~288행, 지금은 한 줄 문구와 «다시 시도» 버튼만 있는 전체 화면)를 이 화면으로 바꾼다. TopNav·화면 제목·탭바가 함께 보이게 한다.
- 관련 파일(jam-web/src 기준, 지도):
  - `app/(main)/drops/DropsClient.tsx` — 위치 조회 effect(약 126~166행, `locError` 설정), `locError` 렌더 분기(약 275행~), `userLat === null` 로딩 분기(약 289행~)
  - `lib/i18n/ko.ts` 641~660행 `drops.locationUnsupported`·`locationDenied`·`retry`·`locating` — 문구 키 추가·수정(UX Writing 가이드 확인)
  - 새 부품이 필요하면 채원 판정에 따른다(`@ds`의 Card·Button·EmptyState 재사용 검토). 시험 `app/(main)/drops/` 아래 새 시험

## 배경 / 문제 정의
스테이징 화면 리뷰의 JAM 탭 빈 상태: 위치 권한이 없으면 가운데 한 줄 문구와 «다시 시도»만 나와 왜 필요한지, 어떻게 허용하는지 알 수 없다. 사용자가 캔버스 시안을 확정했다.

## 상세 요구사항

### UI/UX 관점
- 카드 면은 `rgb(255 255 255 / 0.72)` 정도의 약한 투명이다. DS는 «블러는 탭바만»이므로 블러는 쓰지 않는다. 투명도 값은 새 토큰이 필요하면 채원 판정에 올려 승인을 받는다.
- 웹에서는 기기 설정 화면을 열 수 없으므로 시안의 «설정 열기» 버튼은 없다(캔버스에서도 뺐다). «허용하는 방법»은 브라우저·기기 설정에서 이 사이트의 위치를 허용하는 순서를 안내하고, 버튼은 허용 뒤 다시 시도(위치 다시 요청)다. 문구는 웹에서 지킬 수 있는 약속만 쓴다.
- `locationUnsupported`(브라우저 미지원) 상태도 같은 카드 모양에서 허용 방법 구획과 다시 시도 버튼 없이 안내만 보인다.
- 처음 방문(권한 프롬프트 전)에도 같은 카드를 먼저 보일지, 아니면 거부 상태에서만 보일지는 채원이 판정해 승인을 받는다. 지금 코드는 화면에 들어오면 곧바로 브라우저 권한을 요청한다. 먼저 보이려면 «허용하기» 버튼이 요청을 시작하는 흐름 변경이 필요하다.
- 탭바(활성 «체크인» 이름표), TopNav(아이콘 서클 동기화)는 이미 머지된 변경을 따른다.

### 서비스/코드베이스 관점
- 위치 조회·거부 처리 로직(`watchPosition`, 오류 코드)은 바꾸지 않는다. 처음 방문 흐름을 바꾸는 경우만 판정 승인 뒤에 바꾼다.
- 한국어 문구는 `UX_WRITING_GUIDELINE.md`의 고정 용어와 해요체를 따른다.

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- 위치 권한이 거부된 상태에서 `/drops`가 TopNav·«JAM» 제목·반투명 흰 카드(핀 아이콘, 제목, 설명, 허용하는 방법 3단계, 다시 시도 버튼)·탭바로 보인다. 카드는 전체 화면 덮개가 아니라 화면 안의 카드다.
- «다시 시도» 버튼이 위치를 다시 요청한다(기존 `reload` 동작 이상).
- 브라우저 미지원 상태는 같은 카드에서 안내만 보인다.
- 새 색은 없고, 새 토큰(투명도 등)이 필요하면 판정 승인을 받은 것만 추가된다. 시험과 `scripts/verify.sh`(`ds:check` 포함)에서 이번 변경 시험이 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`에서 위치 권한을 거부한 상태로 `/drops`를 열어 눈으로 확인한다.
