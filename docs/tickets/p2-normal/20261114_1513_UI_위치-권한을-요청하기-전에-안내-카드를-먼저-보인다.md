# [UI] 위치 권한을 요청하기 전에 안내 카드를 먼저 보인다

## 핵심 요약
- 요구사항: `/drops`에 처음 들어온 사용자(권한 상태가 «묻기 전»)에게 브라우저 권한 팝업보다 먼저 위치 안내 카드를 보이고, «위치 허용하기» 버튼이 권한 요청을 시작하게 한다. 이미 허용한 사용자는 카드 없이 바로 지도로 간다.
- 구현 계획: `navigator.permissions.query({ name: 'geolocation' })`로 상태(granted·prompt·denied)를 먼저 읽고, `prompt`일 때만 카드를 보인다. 버튼이 `watchPosition`을 시작한다. 위치 조회 effect(`DropsClient.tsx` 약 126~166행)의 흐름 변경이라 채원 판정과 민지 게이트를 거친다. Permissions API가 없는 브라우저(일부 iOS Safari)는 지금처럼 바로 요청한다.
- 관련 파일(jam-web/src): `app/(main)/drops/DropsClient.tsx`, `app/(main)/drops/LocationPermissionCard.tsx`(티켓 20261114_1507에서 만든 카드를 재사용), `lib/i18n/ko.ts` drops 문구

## 배경 / 문제 정의
지금은 화면에 들어서자마자 브라우저 권한 팝업이 떠서, 사용자가 이유를 모른 채 «차단»을 누르기 쉽다. 차단하면 설정에서 직접 풀어야 한다. 카드 → 버튼 → 팝업 순서로 바꾸면 첫 허용률과 거부 뒤 복구가 함께 좋아진다(채원 판정 추천, 티켓 20261114_1507).

## 완료 조건
- 권한 상태가 `prompt`인 사용자가 `/drops`에 들어오면 브라우저 팝업이 뜨지 않고 안내 카드가 먼저 보인다. 버튼을 누르면 팝업이 뜬다.
- `granted`인 사용자는 카드 없이 바로 지도가 열린다. `denied`는 티켓 20261114_1507의 거부 카드다.
- Permissions API가 없는 브라우저에서는 지금과 같이 바로 요청한다.
- 위치 조회 흐름 변경에 대한 시험이 있고 `scripts/verify.sh`에서 이번 변경 시험이 통과한다.
