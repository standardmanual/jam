# [UI] 미션 목록을 큰 이미지 카드로 바꾸고 서비스 공통 리스트 카드를 DS에 더한다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-14, 클로드 캔버스 보드 «미션 목록» 댓글):
  1. 미션 목록(`/missions`)을 캔버스 모양으로 바꾼다: 행마다 흰 카드 안에 큰 이미지(높이 약 140px, 둥근 모서리), 이미지 위 왼쪽 아래에 **미션 이름**(코드로 얹는다), 이미지 아래에 칩 줄과 포인트 줄, 설명 두 줄.
  2. 이 카드를 MODULAR에 «서비스 전체에서 공통으로 쓰는 리스트 카드형 컴포넌트»로 추가한다. 미션 목록이 첫 사용처다.
  3. 캔버스에서 이미지 위에 있던 «MISSION» 글자는 반영하지 않는다.
  4. 이미지 위의 미션명은 코드에서 얹는다(지금 미션 그림은 조건 문구가 든 합성 이미지라 이름 글자가 이미지 안에 있을 수 있다. 이중으로 보이지 않게 이미지 쪽은 채원이 확인한다).
  5. 칩은 «상태 칩 + 남은 기간 칩»을 캔버스처럼 함께 보인다: 상태는 진행중·참가중·종료, 남은 기간은 «n일 남음». 참가중 칩은 지금 코드의 강조색 빨강 면(`tone="red"`), 진행중·종료는 기본 칩이다.
- 구현 계획: DS에 새 패턴 컴포넌트(이름·분류·슬롯은 채원 판정)를 더하고 서비스 래퍼와 쌍으로 만든 뒤 `MissionsListClient.tsx`의 `ListRow` 자리에 쓴다. 잠금 카드(locked)·신규 칩·보상 줄·«조건» 줄 같은 지금 행이 가진 정보는 새 카드에서도 잃지 않게 판정이 배치를 정한다.
- 관련 파일(jam-web 기준, 지도):
  - `src/app/(main)/missions/MissionsListClient.tsx` — 카드 렌더(약 310~416행: `list.map`, `lead`·`eyebrow`·`footer`·`<ListRow>`), `topStatusLabel`(약 168행, 상태 칩), `periodText`(약 147행, 남은 기간), `rewardNodes`, 잠금 처리 `lockedToastText`
  - `src/app/(main)/missions/missionStatusKind.ts` — 상태 판정 우선순위(진행중·참가중·종료·잠김 등 칩 종류)
  - `src/components/ui/ListRow.tsx`(서비스 ListRow, 칩 `ListRowChip`) — 참고·재사용 판단
  - `design-system/components/cards/MissionCard.{jsx,d.ts,stories.tsx}`, `design-system/components/patterns/` — 기존 MissionCard·패턴과의 관계(재사용·확장·신규 판정)
  - 시험: `src/app/(main)/missions/MissionsListClient.list-row.test.tsx`, `MissionsListClient.locked-reward.test.tsx`, `MissionsListClient.new-chip.test.tsx`, `MissionsListClient.url-query.test.tsx` — 새 카드 구조에 맞게 고친다

## 배경 / 문제 정의
스테이징 화면 리뷰의 공통 개선(공통 5): 미션 아트가 52px 썸네일로 줄어 있다. 사용자가 캔버스 시안(큰 아트 카드)을 확정했고 같은 카드를 서비스 전체의 리스트 카드형으로 쓰기로 했다.

## 상세 요구사항

### UI/UX 관점
- 시안 구성(카드 하나): 바깥은 흰 면 `rounded-2xl`. 안에 이미지 칸(높이 140, 반경 12, 이미지가 없으면 자리표시), 이미지 위 왼쪽 아래에 미션명(`--snow` 글자, 22px 굵게, 두 줄까지), 이미지 아래에 칩 줄 [상태 칩][n일 남음 칩] + 오른쪽 «20 포인트»(`--point-text`), 그 아래 설명 두 줄(말줄임).
- 이미지 위 글자는 어두운 막이 필요할 수 있다(DS 규칙: 이미지 위 글자만 `--snow`, 막은 `--base-black` 혼합 허용). 가독성은 채원이 판정한다.
- «MISSION» 글자는 넣지 않는다.
- 칩: 참가중은 강조색 빨강 면(기존), 진행중·종료·n일 남음은 기본 칩 규격(`ListRowChip`)이다. 남은 기간 칩은 기존 `periodText`를 쓰며 상시·종료·완료 문구는 지금 규칙을 따른다. 종료 미션은 상태 칩 «종료»만 보이고 남은 기간 칩은 없다.
- 잠금(locked) 카드와 신규(new) 칩, 보상 줄, «조건» 줄은 정보를 잃지 않는다. 배치는 채원 판정이 정하고 사용자 승인이 필요한 변경이면 승인 항목으로 올린다.

### 서비스/코드베이스 관점
- 새 카드는 MODULAR에 추가하고 서비스 래퍼 또는 직접 import로 쓴다. DS `.jsx`·`.d.ts`·`.stories.tsx`·`.prompt.md`를 함께 낸다(Story는 의무).
- 미션 외 화면도 쓸 수 있게 도메인 데이터(미션 상태 등)에 묶이지 않는 범용 props(이미지, 제목, 칩 슬롯, 값, 설명)로 만든다.
- 클릭 영역·잠금 토스트·`aria-disabled` 동작은 지금과 같다.

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- `/missions`의 각 미션이 큰 이미지 카드로 보이고, 이미지 위에 미션명이 코드 글자로 얹힌다. «MISSION» 글자는 없다.
- 칩 줄에 상태 칩(진행중·참가중·종료)과 «n일 남음» 칩이 함께 보인다(종료는 상태 칩만). 참가중 칩은 빨강 면이다.
- 잠금·신규·보상·조건 정보가 새 카드에서도 보인다.
- DS에 새 리스트 카드 컴포넌트가 추가되고 서비스가 그것을 쓴다. 기존 미션 목록 시험이 새 구조에 맞게 고쳐져 통과하고 `scripts/verify.sh`(`ds:check` 포함)에서 이번 변경 시험이 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`에서 진행중·참가중·종료 탭, 잠금 카드, 신규 칩, 360px 폭을 눈으로 확인한다.

- 판정에 없던 추가: 이미지가 없거나 딤이 걸린 카드의 제목은 `--foreground`다(옅은 면 위 흰 글자가 안 읽혀서). 사용자 확인이 필요하다.
