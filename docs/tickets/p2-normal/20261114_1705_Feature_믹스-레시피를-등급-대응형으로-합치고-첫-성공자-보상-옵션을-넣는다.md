# [Feature] 믹스 레시피를 등급 대응형으로 합치고, 첫 성공자 보상 옵션을 넣는다

## 핵심 요약

- 요구사항: 같은 이름의 아이템 배지를 등급만 달리해 4개씩 만든 레시피 목록(80개)을 레시피 1개(20개)로 합친다. 새 레시피 유형 «등급 대응형»을 만들어, 재료를 모두 같은 등급으로 넣으면 같은 등급의 결과 아이템 배지가 100% 나오게 한다. 「가장 먼저 성공」 배지 조건은 없애고, 레시피를 만들 때 «첫 성공자에게 줄 아이템 배지»를 지정하는 옵션으로 바꾼다.
- 구현 계획: 4회차로 나눈다. 1회 DB와 믹스 판정, 2회 어드민 레시피 양식, 3회 `/combine` 화면, 4회 「가장 먼저 성공」 조건 제거와 문서 정리. 자세한 순서는 아래 「구현 계획」.
- 관련 파일: 아래 「구현 계획」 각 회차에 파일 지도를 적었다. 단일 원천 문서는 `docs/service/content/COMBINE_RECIPES.md`이고, 믹스 엔진은 `jam-web/src/lib/combine/index.ts`(583줄)다.

## 배경 / 문제 정의

- 레시피 83개 중 80개가 «같은 이름 × 4등급»(20묶음)이다. 묶음 안에서 재료와 결과는 모두 같은 등급이고, 보상 포인트·공개 기간·잠금 설정도 같다(DB 조회로 확인, 2026-11-14). 나머지 3개는 종료된 옛 레시피다.
- 레시피 목록에 같은 레시피가 등급 수만큼 반복해 보인다. 레시피의 목적은 «원하는 아이템 배지를 얻는 것»이므로, 등급은 재료 등급을 따라가면 충분하다.
- 「가장 먼저 성공」 배지 조건(`recipe_first_success`)은 배지가 레시피 하나를 가리키는 구조라 레시피를 합치면 «등급별 1명»이 «전체 1명»으로 의미가 바뀐다. 이 조건을 쓰는 배지와 미션은 0개다(삭제된 것 포함). 믹스 성공 기록 중 «첫 성공» 표시가 켜진 것은 3건이다.

### 확인한 현황 (2026-11-14, 프로덕션 DB)

| 항목 | 값 |
|---|---|
| 레시피 / 슬롯 | 83개 / 352개 (활성 80개, 종료 3개) |
| 현재 쓰는 레시피의 아이템 배지 묶음 | 106종, 전부 4등급이 모두 있음 |
| 믹스 성공 기록 | 3건(레시피 3개에 1건씩, 전부 «첫 성공» 표시) |
| 받지 않은 결과 / 홈피드 카드의 레시피 참조 / 실패 기록 | 0 / 0 / 0 |
| 「가장 먼저 성공」 조건을 쓰는 배지·미션 | 0 / 0 |

## 상세 요구사항

### 서비스/코드베이스 관점

1. **레시피 유형 두 가지**
   - `등급 대응형`(새로 추가, 앞으로의 기본): 재료 슬롯과 결과가 «아이템 배지 묶음»(같은 컬렉션·같은 이름)을 가리킨다. 모든 재료를 같은 등급으로 넣으면 결과도 그 등급이다. 확률은 없고 100%다.
   - `등급 고정형`(지금 방식 그대로): 특정 등급의 배지만 재료로 받고 특정 등급의 배지가 나온다. 옛 종료 레시피 3개와 «이 등급만 허용» 같은 특별한 레시피에 쓴다.
2. **같은 등급 규칙**: 등급 대응형에서 재료 등급이 섞이면 재료를 소각하기 전에 거절한다(새 오류 코드, 포인트 지급 없음). 이 거절은 실패 보상 경로를 타지 않는 점을 정한다(아래 「정할 것」).
3. **첫 성공자 보상 옵션**: 레시피에 «첫 성공자에게 줄 아이템 배지»를 하나 지정할 수 있다(선택). 믹스가 성공했을 때 DB가 «이번이 이 레시피의 첫 성공인가»를 가린다(`record_combine_success_with_id`가 반환하는 `is_recipe_first`, 레시피당 1건만 들어가는 부분 유일 인덱스로 원자적). 첫 성공이면 지정한 배지를 일반 결과와 함께 지급한다.
   - 인벤토리 빈칸이 모자라면 일반 결과와 같이 «받지 않은 결과»에 담는다(기한 없음).
   - 지정한 배지는 아이템 배지만 가능하고, 다른 경로(드랍·캡슐 등)에서 나오지 않도록 막는다.
   - 이미 성공한 사람이 있는 레시피에는 켤 수 없다(저장 때 거절).
   - 재료 등급과 관계없이 지정한 배지(한 등급)를 준다.
4. **「가장 먼저 성공」 조건 제거**: `recipe_first_success` 조건 종류를 배지·미션 양식, 판정 엔진, 레시피 삭제 가드, 운영 인박스에서 걷어낸다. 믹스 성공 기록의 `is_recipe_first` 칸은 새 옵션이 쓰므로 남긴다.
5. **레시피 합치기(데이터)**: 같은 묶음 4개를 등급 대응형 1개로 합친다. 합친 뒤 믹스 성공 기록 3건의 레시피 참조를 옮기고, «첫 성공» 표시는 합친 레시피 기준으로 가장 이른 1건만 남도록 다시 계산한다.

### UI/UX 관점

- `/combine` 레시피 목록에 같은 레시피가 한 번만 보인다.
- 등급 대응형 레시피에서 첫 재료를 고르면 등급이 정해지고, 나머지 칸에는 그 등급의 재료만 보인다. 결과 미리보기도 그 등급으로 바뀐다.
- 카드에 «내가 지금 만들 수 있는 등급»을 보이는 안은 선택 사항이다(디자인 판정에서 결정).
- 어드민 레시피 양식: 레시피 유형 선택(등급 대응형 / 등급 고정형), 첫 성공자 보상 배지 선택, 등급 대응형일 때 «4등급이 모두 있는 아이템 배지만» 고르게 하는 검사. 아이템 배지 전체 621종 중 171종은 4등급이 다 있지 않다.

### 컨텐츠 관점

- 합친 뒤 레시피 20개의 재료·결과·포인트·공개 기간·잠금 설정이 합치기 전 4개 묶음과 같아야 한다.

## 정할 것 (구현 전에 사용자 확인)

1. 재료 등급이 섞였을 때의 거절을 «실패 보상 포인트를 주는 실패»로 볼지, 재료를 건드리지 않고 알림만 하는 거절로 볼지. 권장은 후자다(믹스 화면이 같은 등급만 고르게 막으므로 실제로는 직접 요청할 때만 생긴다).
2. 첫 성공자 보상 배지를 만들 때 «다른 경로에서 나오지 않게 막는» 방법(기존 `drop_excluded` 활용 여부).

## 구현 계획

작업이 크므로 아래 4회차로 나누고, 회차마다 요약은 2,500자 이내로 쓴다. 규모 사전 판정에서 크기 기준을 넘기므로 첫 호출부터 `planOnlyWaiver`에 이 계획의 파일 지도를 근거로 넣는다.

### 1회: DB와 믹스 판정 (db, engine)

- 마이그레이션 340번대(번호는 push 직전에 `origin/staging`에서 다시 확인): `combination_recipes`에 레시피 유형 칸(`grade_mode`: `follow_materials` / `fixed`, 기본 `fixed`)과 첫 성공자 보상 배지 칸(`first_success_badge_id`, 선택)을 더한다. 되돌림 SQL(`_down.sql`)을 함께 쓴다.
- 합치기 SQL: 20묶음을 대표 레시피 1개로 합치고 슬롯·보상을 «아이템 배지 묶음 기준»으로 바꾼다. 믹스 성공 기록 3건의 `recipe_id`를 옮기고 `is_recipe_first`를 다시 계산한다. 실행 전에 백업 표, 롤백 실측(DO 블록과 `RAISE EXCEPTION`), 드라이런을 한다. 프로덕션 DB가 staging과 공용이므로 코드가 새 칸을 읽도록 배포되기 전에 옛 코드가 깨지지 않는지 확장→전환→축소 순서를 `references/db-migration-rules.md`로 확인한다.
- `jam-web/src/lib/combine/index.ts`: 슬롯 판정(약 343~363줄의 `allowed_badge_ids` 비교)을 등급 대응형에서 «아이템 배지 묶음 + 같은 등급» 판정으로 확장한다. 결과 지급(약 180~190줄의 `reward_badge_ids` 조회)은 재료 등급에 맞는 배지를 고른다. 성공 기록 호출(약 527~583줄)이 돌려주는 `is_recipe_first`로 첫 성공자 보상을 함께 지급한다.
- `jam-web/src/lib/combine/recipe-payload.ts`, `visibility.ts`, `pending.ts`: 레시피 유형·첫 성공자 보상 칸을 읽도록 맞춘다.

### 2회: 어드민 레시피 양식 (admin)

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 레시피 목록에 같은 이름의 레시피가 등급별로 반복해 나오지 않는다. 재현 경로: 합친 뒤 `/combine`과 `/admin/recipes`에서 '칸 번호 팻말' 레시피가 1개만 보인다.
- 등급 대응형 레시피에서 재료를 모두 Rare로 넣으면 결과 아이템 배지가 Rare로 나온다. Common·Epic·Mystic도 같다.
- 재료 등급이 섞이면 재료가 소각되기 전에 거절되고, 인벤토리와 포인트가 그대로다.
- 등급 고정형 레시피(옛 종료 레시피 포함)는 지금과 똑같이 동작한다.
- 첫 성공자 보상 배지를 지정한 레시피에서, 처음 성공한 유저는 레시피 결과와 함께 그 배지를 받고, 이후 성공한 유저는 받지 않는다. 인벤토리가 가득 차 있으면 «받지 않은 결과»에 담긴다. 동시에 두 명이 성공해도 배지는 1개만 지급된다.
- 이미 성공 기록이 있는 레시피에는 첫 성공자 보상을 켤 수 없다(저장 거절).
- 어드민 레시피 양식에서 4등급이 모두 없는 아이템 배지는 등급 대응형으로 고를 수 없다.
- `recipe_first_success` 조건을 가리키는 코드·양식·문구·시험이 남아 있지 않다(`grep` 0건, 기록 보존용 마이그레이션 제외).
- 합치기 전후로 활성 레시피 20개의 재료·결과·보상 포인트·공개 기간·잠금 설정이 같다(전후 대조 표를 완료 기록에 남긴다). 믹스 성공 기록 3건이 합친 레시피로 옮겨졌다.
- 합치기 SQL에 되돌림 SQL이 있고, DO 블록 롤백으로 실측한 기록이 있다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 프로덕션 DB 실행(드라이런 → 백업 → 실행 → 읽기 전용 확인 → 사용자 보고).
- `docs/service/` 문서와 정책 대시보드 갱신 확인, 닫히는 열린 티켓 2건의 상태 정리.
