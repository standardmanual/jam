# [Feature] 합친 믹스 레시피의 홈 카드와 운영 서랍이 보상 배지 수를 4개로 세는 것을 맞춘다

## 핵심 요약

- 요구사항: 등급 대응형 레시피는 `reward_badge_ids`에 같은 이름의 4등급 배지를 모두 담는다. 이 칸의 길이를 «보상 배지 N개»로 세는 곳이 있어, 합친 레시피가 «배지 4개»로 보인다. 실제 보상은 재료 등급에 맞는 배지 1개다. 등급 대응형은 같은 이름 묶음 수로 세도록 맞춘다.
- 구현 계획: 아래 두 곳의 개수 계산을 «등급 대응형이면 아이템 배지 이름 묶음(같은 컬렉션·같은 이름) 수»로 바꾼다. 묶음을 세는 함수는 `lib/combine/gradeMode.ts`·`lib/admin/recipe-grade-bundles.ts`에 이미 있는 규칙을 재사용한다.
- 관련 파일: `jam-web/src/lib/today/cards.ts`(552줄 `reward_badge_count: recipe.reward_badge_ids?.length`와 `fetchRecipesById`의 레시피 조회에 `grade_mode`가 없다, 슬롯 대표 후보를 고르는 `toResolvedRecipe`도 4등급 후보 중 첫 번째를 쓴다), `jam-web/src/lib/admin/opsBoard/drawerView.ts`(59행 `badgeCountOf`가 `resource.reward_badge_ids.length`).

## 배경 / 문제 정의

- 티켓 20261114_1705에서 레시피 80개를 등급 대응형 20개로 합쳤다(2026-11-14 프로덕션 DB 적용). 합친 레시피의 보상 배지 칸과 슬롯 후보에는 4개 등급 배지가 모두 들어 있다.
- 홈 카드(`today_cards`)가 레시피를 가리키는 행은 지금 0건이라 당장 화면에 나오지 않는다. 오픈 때 «레시피 공개 카드»를 올리면 «배지 4개» 같은 숫자와 4등급 후보 중 첫 번째 배지(등급 낮은 순이 아니라 id 순)를 대표로 고르는 타일이 보일 수 있다.
- 믹스 화면(`/combine`)은 3회차에서 등급 대응형에 맞췄다. 같은 규칙을 홈 카드와 어드민 운영 서랍에도 적용한다.

## 상세 요구사항

- 홈 레시피 카드: 등급 대응형이면 보상 배지 수를 이름 묶음 수(보통 1)로 센다. 슬롯 타일의 대표 후보는 가장 낮은 등급의 배지로 고정해 등급 칩이 없는 대표 그림을 보인다(믹스 목록의 대표 배지 규칙과 같게).
- 어드민 운영 서랍(`opsBoard/drawerView.ts`): 레시피 항목이면 같은 규칙으로 센다.
- 고정형 레시피와 미션·카드의 보상 배지 수는 지금과 같다.
- UI 변경이 있으므로 `ui` 유형(채원 판정)으로 진행한다.

## 구현 계획

1. `fetchRecipesById`의 select에 `grade_mode`를 더하고 `FetchedRecipe`에 등급 대응형 여부를 싣는다.
2. 개수 계산과 대표 후보 선택을 등급 대응형 분기로 고친다(순수 함수로 빼서 시험).
3. `drawerView.ts`의 `badgeCountOf`가 레시피 항목일 때 이름 묶음 수로 센다.

## 완료 조건

- 등급 대응형 레시피(4등급 보상 배지 4개)를 가리키는 홈 카드의 보상 줄이 «배지 1개»로 나온다. 재현: 가짜 레시피 데이터로 `fetchRecipesById`·`toResolvedRecipe` 시험.
- 고정형 레시피와 미션 카드의 보상 배지 수는 그대로다.
- 운영 서랍의 레시피 보상 배지 수가 이름 묶음 수로 나온다.
- 홈 카드 슬롯 타일의 대표 후보가 가장 낮은 등급의 배지다.
