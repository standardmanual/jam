## 상세 요구사항

### 서비스/코드베이스 관점

- **사양 읽는 법**: spec.json의 `icons[]` 항목마다 `name`(새 이름), `oldName`(지금 이름, 없으면 신규), `lineOnly`, `svgInner48`(48 격자 SVG 조각)이 있다. 조각의 요소 클래스는 «역할»이다(`roles`·`roleCss` 참고): `b` 바탕 면, `g` 틈 있는 면, `c` 비운 면, `kb`·`kc` 점, `ta`·`tb`·`tc` 굵은 선(선 굵기×1.5), `nb`·`nc` 가는 선, `ro`+`rc` 띠, `h` 2배 확대 그룹. 같은 조각을 `.ln`(라인)과 `.fl`(채움) 규칙으로 그리면 두 벌이 나온다. 캔버스에서 쓴 CSS가 `roleCss`에 그대로 있다.
- **배경색에 기대지 않는다**: 캔버스는 비운 면·틈을 `--bg`(배경색) 칠로 흉내 냈다. 서비스에서는 아이콘이 흰 카드, 회색 칸(#F3F3F3), 검정 토스트, 반투명 탭바, 초록 지도 마커 위에 올라가므로 배경색 칠로 구현하지 않는다. 비운 면·틈·라인 판의 가림은 SVG `mask`(아이디는 `useId`)처럼 실제로 투명하게 뚫는 방식으로 구현한다. 방식은 아현이 정하되 위 다섯 배경에서 모두 같은 모양이어야 한다.
- **색**: `currentColor`만 쓴다. 지금 세트 규칙 «제3의 컬러 도입 금지»는 그대로다.
- **크기·굵기**: `viewBox="0 0 48 48"`, 선 굵기 3(24px 렌더에서 1.5px). 기본 `className="w-6 h-6"`은 그대로 둔다.
- **이름**: 그림이 바뀐 10종 — `TargetIcon→TicketIcon`, `PackageIcon→ArrowDownIcon`, `GiftIcon→ArrowUpIcon`, `BookIcon→MagicBookIcon`, `HourglassIcon→SparkleCircleIcon`, `GachaMachineIcon→MixingBowlIcon`, `ActivityIcon→SyncCircleIcon`, `CheckCircleIcon→CheckBoldIcon`, `XCircleIcon→XBoldIcon`, `RankingIcon→PodiumIcon`. 옛 이름은 `/** @deprecated 20261114_2346에서 제거 */ export const BookIcon = MagicBookIcon` 꼴의 별칭으로 남긴다.
- **신규 7종**: `HomeIcon`, `CheckinIcon`, `CrateIcon`(탭바용), `TreasureBoxIcon`(지도 마커 원 안 그림, spec에서 바깥 원은 이미 뺐다), `LocateIcon`, `AlertCircleIcon`, `BanIcon`. 이 회차에서는 정의·카탈로그만 하고 사용처 연결은 3회차다.
- **`CoinIcon`**: 새 그림(P와 작은 반짝이)은 채움 판이 지금의 굵은 P에 가깝다. `CoinIcon`만 기본 `variant`를 `'fill'`로 둔다(포인트 숫자 옆 표시가 지금처럼 꽉 찬 P로 보이게).
- 파일 머리 주석을 새 세트 설명(라인·채움, 48 격자, currentColor, 사양 경로)으로 바꾼다.

### UI/UX 관점

- 그림은 `board.png`와 같아야 한다. 아이콘 조각의 좌표는 spec.json에서 그대로 옮긴다(손으로 다시 그리지 않는다).

## 구현 계획

1. `icons.tsx`: 역할 조각을 받아 라인·채움으로 그리는 내부 렌더러 하나를 만들고(예: `RoleIcon`), 아이콘 39개는 spec.json의 조각을 상수로 옮겨 그 렌더러를 부르는 얇은 함수로 둔다. `IconProps`에 `variant`를 더한다. 옛 이름 별칭 10개를 파일 끝에 둔다.
2. `IconCatalog.jsx`·`.d.ts`: 서비스 `icons.tsx`와 같은 이름·같은 조각·같은 `variant` 속성으로 맞춘다. `ICON_ENTRIES`에 새 이름과 쓰임(사양의 `role`)을 넣고 옛 이름 항목은 뺀다. 카탈로그 화면은 아이콘마다 라인·채움을 나란히 보인다.
3. `IconCatalog.stories.tsx`: 라인·채움 두 벌과 다섯 배경(흰색, #F3F3F3, #171717, 반투명, 초록)에서 보이는 스토리를 둔다.
4. `__tests__/icons.test.tsx`: 39종이 두 `variant`로 모두 렌더되고, 별칭 10개가 새 컴포넌트와 같은 함수인지, `fill`/`stroke`에 `currentColor`·`none`·`url(#…)` 말고 다른 색이 없는지 확인한다.
5. `scripts/verify.sh`(ds:check 포함)를 통과시킨다.

## 완료 조건

- `icons.tsx`가 spec.json의 39종을 새 이름으로 내보내고, 각 아이콘이 `variant="line"`·`"fill"`로 렌더된다(동작 글리프 7종은 `lineOnly`라 두 값 모두 라인).
- 옛 이름 10개가 `@deprecated` 별칭으로 남아 있어, 사용처를 고치지 않은 상태에서 `npm run typecheck`와 기존 시험이 통과한다(시험이 옛 SVG 경로 문자열을 단언하는 곳이 있으면 새 그림에 맞게 고친다).
- SVG 안에 `currentColor` 밖의 색 값이 없다. 배경색으로 구멍을 칠하지 않는다(DS 스토리에서 흰색·#F3F3F3·#171717·반투명·초록 배경 위 모양이 같다).
- 24px 렌더에서 선 굵기가 1.5px이다.
- DS `IconCatalog`가 서비스 `icons.tsx`와 같은 이름·그림·`variant`를 가진다(`ds:check` 통과).
- `CoinIcon` 기본 `variant`가 `'fill'`이다.
