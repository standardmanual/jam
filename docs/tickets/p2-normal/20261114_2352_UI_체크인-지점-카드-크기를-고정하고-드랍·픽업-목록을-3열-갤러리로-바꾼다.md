# [UI] 체크인 지점 카드 크기를 고정하고 드랍·픽업 목록을 3열 갤러리로 바꾼다

## 핵심 요약

- 요구사항: 드랍 메뉴에서 체크인 지점을 누르면 열리는 지점 카드 캐러셀(`PoiCarouselModal`)의 카드가, 안의 내용이
  불러와지면서 크기가 바뀐다. 카드가 **처음 열릴 때부터 정해진 크기**로 열리고 어떤 상태에서도 그 크기를 유지하게 한다.
  이를 위해 픽업 목록(이 지점에 드랍된 아이템 배지)과 드랍 선택 목록(내 인벤토리에서 고르기)을 행 목록이 아니라
  컬렉션 상세와 같은 **3열 갤러리**로 바꾼다. 기본 영역은 **3열 × 2행(6칸)** 이고, 묶음이 6개를 넘으면 그 영역
  안에서만 세로로 스크롤된다.
- 구현 계획: `PoiCard`의 본문을 «높이가 고정된 본문 영역 + 그 아래 고정 버튼 줄»로 바꾸고, `ItemRow` 행 목록 두 곳을
  3열 갤러리(같은 파일 안의 로컬 컴포넌트 하나)로 교체한다. 데이터·묶음·클릭 동작·API는 바꾸지 않는다.
  칸 규격(썸네일 크기, 이름 줄 수, 칩 배치, 2행 높이 값)은 채원 사전 판정을 따른다.
- 관련 파일:
  - `jam-web/src/components/PoiCarouselModal.tsx`
    - `PoiCard`(852~1042행): 본문 분기 904~1039행. 로딩(905~907), 드랍 확인(910~958), 인벤토리 로딩(959~962),
      드랍 선택 빈 상태(963~968), 드랍 선택 목록(974~989, `max-h-[50vh]`), 픽업 목록(1001~1016, `max-h-[50vh]`),
      픽업 빈 상태(1018~1023), 「여기에 드랍」 버튼(1025~1037)
    - `ItemRow`(1044~1146행): 두 목록이 함께 쓰는 행. 갤러리 칸으로 대체한다
    - 패널 위치 주석(713~721행)과 본문 주석(897~903행): «내용만큼 자란다»는 서술을 고정 높이 기준으로 고친다
  - `jam-web/src/components/PoiCarouselModal.test.tsx`: 펄스(57~66행), 잠긴 개체 행(117~189행),

## 배경 / 문제 정의

드랍 메뉴(`/drops`) 지도에서 체크인 지점 마커를 누르면 지점 카드 캐러셀이 열린다. 지금 카드의 본문은 내용만큼
자라는 구조다.

- 열리는 순간에는 로딩 표시만 있어 카드가 낮다. 드랍 목록이 도착하면 행 수만큼 카드가 위로 자란다
- 「여기에 드랍」을 누르면 인벤토리 로딩 → 드랍 선택 목록 → 드랍 확인 단계로 넘어가면서 그때마다 높이가 바뀐다
- 옆 카드(peek)는 머리(지점 이름·거리)만 있어, 옆으로 넘길 때도 카드 크기가 바뀐다

행 목록은 묶음 하나가 한 줄을 차지해, 고정 높이 안에 넣으면 몇 개 보이지 않는다. 3열 갤러리로 바꾸면 같은 높이에
6개를 보일 수 있어 고정 크기를 정할 수 있다(2026-11-14 사용자 지시).

이전 결정과의 관계: 티켓 20260908_0217이 드랍 선택을 그리드에서 행으로 바꿔 픽업 목록과 통일했다. 이번에는
**두 목록을 함께** 갤러리로 옮기므로 «두 목록이 같은 문법을 쓴다»는 그 결정의 취지는 유지된다.
티켓 20260917_2042가 넣은 `max-h-[50vh]`(카드가 화면 위로 넘치지 않게)는 고정 높이가 대신한다.

## 상세 요구사항

### UI/UX 관점

1. **카드 크기 고정**
   - 활성 카드는 열리는 순간부터 닫힐 때까지 높이가 같다. 다음 상태가 모두 같은 높이의 본문 영역 안에서 그려진다:
     드랍 목록 로딩, 픽업 갤러리, 픽업 빈 상태, 인벤토리 로딩, 드랍 선택 갤러리, 드랍 선택 빈 상태, 드랍 확인 단계
   - 옆 카드(peek)도 같은 높이다. 본문은 비워 둔다(옆 카드는 지금처럼 데이터를 불러오지 않는다, 티켓 20260820_025)
   - 「여기에 드랍」 버튼은 본문 영역 아래 같은 자리에 둔다. 버튼이 없는 상태(온보딩 pickup 연출, 드랍 선택·확인 단계)에서도
     카드 높이가 달라지지 않게 한다. 버튼 자리 처리 방식은 채원 판정을 따른다
2. **3열 갤러리**
   - 픽업 목록과 드랍 선택 목록을 `grid grid-cols-3 gap-2` 갤러리로 그린다(컬렉션 상세와 같은 열 수·간격)
   - 기본 영역은 3열 × 2행이다. 묶음이 6개 이하면 스크롤이 없고, 7개 이상이면 갤러리 영역 안에서만 세로 스크롤된다
   - 묶음이 1~5개여도 영역 높이는 2행 그대로다(빈 칸 자리 표시를 둘지는 채원 판정)
   - 칸 높이는 내용(이름 줄 수, 등급 칩·만료 칩 유무)과 상관없이 같아야 한다. 그래야 «2행»이 고정 높이가 된다
3. **유지해야 하는 것**
   - 같은 배지 묶음(badge_id), 2개 이상일 때의 ×N 개수 표시와 보조기술 문구(`dropOwnedCountAria`·`pickupAvailableCountAria`)
   - 잠긴 개체: 잠금 타일 + «잠긴 아이템 배지» + 등급만 보이고 이름·그림·일련번호가 DOM 어디에도 없다. 만료 표시도 없다.
     잠긴 묶음은 열린 묶음 뒤에 둔다
   - 누르면 지금과 같다: 개체 1개는 바로 다음 단계, 2개 이상은 개체 선택 시트
   - 온보딩 퀘스트 펄스(`questPulseStep`): pickup이면 픽업 칸, drop이면 「여기에 드랍」 → 드랍 선택 칸 → 확인 버튼
   - 빈 상태 문구와 버튼 문구는 그대로 쓴다. 새 문구를 만들지 않는다

4. **확정 사항** (2026-11-15 사용자 확정. 채원 사전 판정과 다르면 이 절이 우선한다)
   - 칸 규격: 썸네일 56 고정, 이름 12px 굵게 2줄(1줄 이름도 2줄 높이를 차지한다), 칩 줄 하나. 칸 높이 약 138, 2행 갤러리 높이 약 284.
     값은 구현 때 한 곳에서 고정하고 카리나가 실측으로 확인한다
   - **갤러리 칸에는 만료 임박을 표시하지 않는다.** 칩 줄에는 등급 칩만 둔다(Common은 비우고 줄 높이는 유지한다).
     만료일은 칸을 누른 뒤의 픽업 상세 시트·개체 선택 시트에서 지금처럼 보인다
   - 칸의 면은 지금 행 목록과 같은 회색 면(`--background-secondary`)이다. 지점 카드의 면이 `--card-bg`(흰색)라
     컬렉션 상세의 칸 면(`--card-bg`)을 그대로 쓰면 칸의 경계가 보이지 않는다. 썸네일 상자의 면은 지금 행의 그림 상자와 같은 `--surface`(흰색)다
   - 드랍 선택 단계에서는 버튼 자리를 비워 둔 채 카드 높이를 유지한다. 갤러리를 버튼 자리까지 늘리지 않는다
   - 드랍 확인 단계의 [취소]·[드랍] 버튼 줄은 「여기에 드랍」 버튼과 같은 자리에 둔다
   - 묶음이 6개 미만이어도 갤러리 영역 높이는 그대로이고 빈 칸 자리 표시는 그리지 않는다. 로딩은 같은 높이의 영역 가운데에 기존 로딩 표시만 둔다
   - 기준 최소 폭은 375다. 그보다 좁은 기기에서 칸 높이가 달라지는 것은 받아들인다
   - 칸 컴포넌트는 `BadgeGridCard`에 변형을 더해 쓴다(기본값에서는 다른 화면의 마크업이 그대로여야 한다). 디자인 시스템 사본은 건드리지 않는다

### 서비스/코드베이스 관점

- 바꾸는 것은 `PoiCard`의 렌더링뿐이다. `dropGridItems`·`groupPickupDrops`·`handleSelect*`·API·캐시·데모 모드 로직은 건드리지 않는다
- 카드 폭 사실(계산값, 구현 때 실측으로 확인): 슬라이드 폭은 컨테이너의 72%이고 컨테이너 최대 폭은 430이다.
  카드 폭은 375 화면에서 약 270px, 430 화면에서 약 310px이고, 카드 안쪽 여백(`--card-padding` 16)을 빼면 안쪽 폭은
  약 238~278px다. 3열(간격 8)이면 칸 폭이 약 74~87px다. `BadgeGridCard` 기본 규격(안쪽 여백 12, 썸네일 최대 90,
  이름 2줄, 등급 칩, 만료 칩)을 그대로 쓰면 썸네일이 50~63px로 줄고 칸 높이가 내용에 따라 달라진다
- 높이 값은 `min-h-*`·여백 역산이 아니라 실측(`offsetHeight`)으로 확인한다(`jam-web/CLAUDE.md` 오버레이 규칙).
  격리 워크트리에서는 `next dev`가 뜨지 않으므로 실측은 카리나가 메인 트리에서 한다(아래 후속 범위)
- 높이 667px 화면(작은 기기)에서 카드 윗변이 화면 밖으로 나가지 않아야 한다. 패널은 아래에서 `safe-area + 92px` 띄워져 있다

- `ItemRow`, 만료 임박 계산(`earliestExpiry`·`isRowExpiringSoon`)과 쓰지 않게 된 import를 걷었다. 데이터·핸들러·API·개체 선택 시트는 그대로다
- 채원 사전 판정: 서비스 전용 변형(재사용 + 변형 추가), MODULAR 승격 없음. `ui` 유형이라 연결 범위 분류는 해당 없음

### 주요 의사결정 / 핵심 메모

  카드 폭(약 270~310px)에서 칸이 커져 세로 공간을 줄이지 못한다
- 채원 사전 판정(2026-11-15): 서비스 전용 변형. `BadgeGridCard`에 `compact` 변형을 더하고 `PoiCarouselModal.tsx` 안의 로컬 갤러리 하나로 두 목록을 그린다. MODULAR 승격은 하지 않는다(사용처가 한 곳이고 디자인 시스템 사본이 이미 서비스 쪽과 어긋나 있다). 승인 항목 다섯 가지를 사용자에게 올렸다
- 사용자 확정(2026-11-15): 만료 임박은 갤러리 칸에 표시하지 않는다(채원 추천은 «만료 임박 칩이 등급 칩을 대신한다»였다). 나머지는 추천안대로다. 칸의 면 색은 채원안(`--card-bg`) 대신 카리나가 올린 `--background-secondary`로 확정했다(지점 카드 면과 같은 흰색이라 칸이 보이지 않는다는 점을 토큰 값으로 확인했다)
