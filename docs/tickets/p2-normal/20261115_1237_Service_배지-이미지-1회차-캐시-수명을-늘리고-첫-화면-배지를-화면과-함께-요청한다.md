## 배경 / 문제 정의

실측 수치와 원인 판단은 상위 티켓 20261115_1232에 있다. 이 티켓에 필요한 사실만 옮긴다.

- 배지함(`/badges`)에서 이미지 요청 시작 시점(506ms)이 화면 첫 표시 시점(516ms)과 같다. 배지 이미지는 모두 지연 로딩 기본값을 쓴다
- 저장소 이미지를 변환한 응답의 헤더는 `public, max-age=14400, must-revalidate`다. `images.minimumCacheTTL` 지정이 없어 Next 16 기본값이 적용된다
- 정적 파일(`/badges/…`)을 변환한 응답의 헤더는 `public, max-age=0, must-revalidate`다(`stage.j-a-m.app` 실측).
  `images.minimumCacheTTL`이 14400인 지금도 0이므로, 이 값을 늘려도 정적 파일 쪽 헤더가 바뀐다는 근거가 없다
- 정적 파일 배지는 2,083건이고, 그중 `/badges/poi/…` 1,830건은 256px PNG에 평균 15KB다
- 저장소 주소 2,807건 가운데 2,726건에는 `?v=` 값이 붙어 있다. 나머지 81건은 업로드 시각이 파일 이름에 들어 있다

## 상세 요구사항

### 기능 요구사항

1. **변환 캐시 수명 31일.** `images.minimumCacheTTL`을 2678400으로 지정한다(Next 문서의 예시값)
2. **정적 파일 배지는 직접 받는다.** `/badges/`로 시작하는 내부 경로는 변환 주소를 거치지 않고 원래 주소로 요청한다.
   `/badges/:path*` 응답에 `Cache-Control: public, max-age=86400, stale-while-revalidate=2592000`을 붙인다.
   같은 이름으로 그림이 교체돼도 하루 뒤에는 새 그림을 확인하게 하려는 값이다
3. **첫 화면 분량은 지연 로딩에서 뺀다.** 그리드의 앞 12칸(3열 × 4행), 지점 카드 갤러리의 앞 6칸(3열 × 2행), 대표 그림
   (배지 상세·드랍 시트의 히어로, 컬렉션 히어로), 지점 카드 확인 단계의 80px 그림이 대상이다. 그 뒤 칸은 지금처럼 지연 로딩한다
4. **원본을 받는 세 곳을 통일한다.** 컬렉션 상세의 체크인 배지, 컬렉션 히어로는 `SafeImage`로 바꾼다. 지도 마커는 HTML 문자열이라
   변환 주소를 직접 조립한다
5. **외곽선 추적 주소를 카드 주소와 맞춘다.** `slotOutlineTraceSrc`가 돌려주는 주소는 카드가 실제로 받는 주소와 같아야 한다
   (정적 파일 배지는 직접 주소). 다르면 같은 그림을 두 번 받는다

### UI/UX 관점

- 새 UI가 없고 눈에 보이는 변화가 없다. 채원 사전 판정 대상이 아니다
- `<img>`를 `SafeImage`로 바꾸는 두 곳은 크기·정렬·흑백 처리(`grayscale opacity-40`)가 그대로여야 한다

### 범위 밖

- 저장소 업로드의 `cacheControl` 지정: 3회차로 옮긴다. 이 회차 뒤에는 서비스 화면이 저장소 원본을 직접 받지 않으므로
  원본의 캐시 설정이 화면 속도에 영향을 주지 않는다
- 드랍 지도의 미리 받기(2회차), 표시 크기 파생본의 사전 생성(3회차), 어드민 화면
