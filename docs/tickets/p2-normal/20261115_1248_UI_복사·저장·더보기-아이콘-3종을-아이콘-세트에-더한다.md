# [UI] 복사·저장·더보기 아이콘 3종을 아이콘 세트에 더한다 (1회차)

## 핵심 요약

- 요구사항: 배지 공유 시트의 세 버튼에 쓸 아이콘 `CopyIcon`(복사하기)·`DownloadIcon`(저장하기)·`MoreIcon`(더보기)을 아이콘 세트 v2에 더한다. 사양 `spec.json`, 서비스 `icons.tsx`, DS `IconCatalog` 세 곳에 같은 조각으로 넣는다. 사용처 연결은 2회차(20261115_1249)다.
- 구현 계획: 아래 「구현 계획」. 조각(48 격자 SVG)은 이 티켓에 확정돼 있으니 그대로 옮긴다(모양을 새로 정하지 않는다).
- 관련 파일:
  - `docs/assets/prototypes/icon-set-v2/spec.json` `icons[]` 끝(BanIcon 다음)
  - `jam-web/src/components/ui/icons.tsx`: 머리 주석(2~13줄, «39종»·동작 글리프 문장), 노드 상수 구역(`BAN_NODES` 339줄 다음), 내보내기 함수(`BanIcon` 536~538줄 다음)
  - `jam-web/src/components/ui/__tests__/icons.test.tsx`: 머리 주석 2줄, `'사양은 39종이다'` 36~38줄
  - `jam-web/design-system/components/icons/IconCatalog.jsx`: 아이콘 함수(`BanIcon` 531줄 다음), `ICON_ENTRIES`(536줄~, `BanIcon` 항목 575줄 다음), 머리 주석의 종 수
  - `jam-web/design-system/components/icons/IconCatalog.d.ts`(`BanIcon` 45줄 다음)
  - 상위 티켓 `20261115_1247`

## 배경 / 문제 정의

상위 티켓 참고. 지금 세트 39종에는 복사·저장(내려받기)·더보기에 맞는 그림이 없다. `ArrowDownIcon`은 «아이템 드랍» 뜻으로 쓰이므로 저장 아이콘으로 겸하지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

아이콘 조각(48 격자, 역할 클래스는 spec.json `roles` 규칙 그대로):

| 이름 | role | lineOnly | svgInner48 |
|---|---|---|---|
| `CopyIcon` | 복사하기 | false | `<rect class="b" x="17.5" y="6.5" width="24" height="24" rx="5.5"></rect><rect class="g" x="6.5" y="17.5" width="24" height="24" rx="5.5"></rect>` |
| `DownloadIcon` | 저장하기 | false | `<path class="b" d="M20 8.5 Q20 6 22.5 6 H25.5 Q28 6 28 8.5 V17.5 H32.5 Q35.8 17.5 33.8 20.1 L26 30.3 Q24 32.9 22 30.3 L14.2 20.1 Q12.2 17.5 15.5 17.5 H20 Z"></path><path class="ta" d="M8.5 31 V35.5 Q8.5 40.5 13.5 40.5 H34.5 Q39.5 40.5 39.5 35.5 V31"></path>` |
| `MoreIcon` | 더보기 | true | `<circle class="kc" cx="11" cy="24" r="3.8"></circle><circle class="kc" cx="24" cy="24" r="3.8"></circle><circle class="kc" cx="37" cy="24" r="3.8"></circle>` |

- spec.json 항목: `name`, `oldName: null`, `role`(위 표), `section: "공유 시트"`, `lineOnly`, `svgInner48`(위 표 그대로), `usedFor: ["공유 시트 · <role>"]`.
- `icons.tsx` 노드 상수의 선 굵기는 기존 규칙대로 `b`·`g` 3, `ta` 4.5, `kc` 0이다(같은 역할을 쓰는 기존 상수와 대조한다).
- `MoreIcon`은 `lineOnly`라 `variant="fill"`을 받아도 라인과 같다. 머리 주석의 «동작 글리프 7종 … 라인이다» 문장에 `MoreIcon`도 라인만이라는 점을 더한다.
- 종 수 표기(«39종»)를 42종으로 고친다(서비스·DS 머리 주석, 시험 이름·단언).
- DS `ICON_ENTRIES`에 `section: '공유 시트'`로 세 항목을 더한다. 카탈로그 화면은 구획을 자동으로 그리므로 별도 수정이 필요한지 확인만 한다.
- `board.png`는 캔버스 산출물이라 다시 굽지 않는다.

### UI/UX 관점

- 2026-11-15 카리나가 위 조각을 기존 세트 옆에 라인·채움 24px·96px로 렌더해 결이 맞는지 확인했다(투명 판은 비운 면이 실제로 뚫려야 한다: `CopyIcon` 채움 판의 앞 상자와 뒤 상자 사이 틈).

## 구현 계획

1. `spec.json`: `BanIcon` 다음에 세 항목을 더한다.
2. `icons.tsx`: `COPY_NODES`·`DOWNLOAD_NODES`·`MORE_NODES` 상수를 `BAN_NODES` 다음에 두고, `/** 공유 시트 · 복사하기 */ export function CopyIcon` 꼴의 함수 세 개를 `BanIcon` 다음에 둔다(`MoreIcon`은 `lineOnly`). 머리 주석을 고친다.
3. `IconCatalog.jsx`·`.d.ts`: 같은 조각·같은 이름으로 더하고 `ICON_ENTRIES`에 항목을 더한다.
4. `icons.test.tsx`: 종 수를 42로 고친다(사양을 읽어 도는 기존 묘사 시험이 새 3종도 자동으로 검사한다).
5. `scripts/verify.sh`(ds:check 포함)를 돌린다.

## 완료 조건

- spec.json이 42종이고, 서비스 `icons.tsx`와 DS `IconCatalog`가 세 아이콘을 같은 마크업으로 내보낸다(`icons.test.tsx`의 기존 동일성·색 검사 통과).
- `MoreIcon`은 `variant="fill"`이어도 라인과 같다.
- SVG 안에 `currentColor` 밖의 색이 없고 배경색 칠이 없다.
- typecheck·lint·ds:check·`icons.test.tsx`가 통과한다.
