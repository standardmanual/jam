# [Infra] 메인 작업 폴더에서 전체 시험이 554건 실패하는 원인을 찾는다

## 핵심 요약

- 요구사항: 메인 작업 폴더에서 전체 시험을 돌리면 554건이 실패한다. 깨끗하게 설치한 워크트리에서는 7건만 실패한다.
- 구현 계획: 메인 폴더의 `node_modules`가 `package-lock.json`과 맞는지부터 대조한다.
- 관련 파일: `jam-web/package-lock.json`, `jam-web/node_modules`, `.githooks/pre-push`(리뷰 브랜치 push의 verify 게이트)

## 배경 / 문제 정의

### 실측한 사실 (2026-11-15)

- 메인 작업 폴더에서 pre-push가 돌린 전체 시험: 54개 파일 실패, 554건 실패 / 21,244건
- 실패 문구는 519건이 `Invalid hook call`이다. 실패 파일은 `src/components/admin` 444건, `src/app/admin` 167건에 몰려 있다
- 같은 날 `npm ci`로 설치한 임시 워크트리에서는 같은 커밋 계열이 7건만 실패했다(티켓 20261115_1237의 검증 기록)
- 메인 폴더의 `jam-web/node_modules` 수정 시각은 11월 8일, `node_modules/.package-lock.json`은 11월 3일이다
- 메인 폴더에서 배지 카드 시험과 `imageSrc` 시험은 통과한다

### 판단

메인 폴더의 설치본이 낡았을 가능성이 있다. 확인하지는 않았다. 메인 폴더에 다시 설치하면 이 폴더의 `node_modules`를
링크로 쓰는 워크트리와 병렬 세션에 영향을 주므로, 설치 시점을 정해서 진행한다.

### 영향

메인 세션이 리뷰 브랜치(`claude/jamwork-*`)에 push하면 pre-push의 verify가 실패해 막힌다. 기준선 7건(티켓 20261114_1411)만으로도
막히므로, 좁은 재작업을 카리나가 직접 올려 게이트만 다시 받는 절차(`gateOnly`)를 지금은 쓸 수 없다.

## 완료 조건

- 554건의 원인이 기록돼 있다
- 메인 폴더의 전체 시험 실패가 깨끗한 설치의 실패 목록과 같아진다
