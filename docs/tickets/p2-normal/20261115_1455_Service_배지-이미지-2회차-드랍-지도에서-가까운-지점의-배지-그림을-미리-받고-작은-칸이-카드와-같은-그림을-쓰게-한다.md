# [Service] 배지 이미지 2회차: 드랍 지도에서 가까운 지점의 배지 그림을 미리 받고, 작은 칸이 카드와 같은 그림을 쓰게 한다

## 핵심 요약

- 요구사항: 드랍 지도에서 지점 카드를 열 때 갤러리의 배지 그림이 목록과 함께 보이게 한다. 상위 티켓 20261115_1232의 2회차 가운데
  드랍 지도 부분이다(사용자 승인 2026-11-15). **화면의 모양은 바꾸지 않는다.**
- 구현 계획: 두 가지를 한다. (가) 56px 칸(지점 카드 갤러리, 드랍 선택)이 90px 카드와 같은 변환본을 요청하게 해서, 한 번 받은 그림을
  두 곳이 함께 쓴다. (나) 지도에서 지점 목록이 도착하면 드랍할 수 있는 거리 안의 가까운 지점 3곳의 드랍 배지 그림을 미리 받는다.
- 관련 파일(지도):
  - `jam-web/src/components/SafeImage.tsx`(`next/image` 분기 두 줄)
  - `jam-web/src/components/ui/BadgeGridCard.tsx` 205행(56px `SafeImage`, `compact` 분기), 262행(90px)
  - `jam-web/src/lib/imageSrc.ts`의 `nextImageWidthFor`, `BADGE_CARD_DISPLAY_WIDTH`, `optimizedImageUrl`
  - `jam-web/src/components/BadgeImageWarmup.tsx`의 `loadOne`과 6장씩 받는 반복(공용 함수로 뺄 부분)
  - `jam-web/src/app/(main)/drops/DropsClient.tsx` 184행 `setPois(json.pois ?? [])`, 232~238행(`in_drop_range`인 지점만 카드가 열린다)
  - `jam-web/src/types/drops.ts` 9~10행 `available_drops_count`, `in_drop_range`
  - `jam-web/src/components/PoiCarouselModal.tsx` 358~381행 `fetchPoiDrops`, 355행 `dropsCache`
  - `jam-web/src/app/api/drops/poi/[poiId]/route.ts`(응답 `drops[].badge_image_url`, 잠긴 개체는 그림이 없다)

## 배경 / 문제 정의

### 확인한 사실 (2026-11-15)

- 56px 이미지에 `next/image`가 만드는 변환 폭은 1배 화면 64, 2배 이상 화면 128이다. 90px 카드는 96과 256이다.
  같은 배지라도 두 곳이 서로 다른 주소를 요청한다(`nextImageWidthFor`의 시험 값)
- 티켓 20261115_1344의 미리 받기는 90px 카드의 주소(96·256)로 인벤토리 전체를 받는다. 드랍 선택 갤러리는 같은 인벤토리를
  56px 칸으로 그리므로 지금은 미리 받은 그림을 쓰지 못한다
- `/api/drops` 응답(`NearbyPoi`)에는 그림 주소가 없다. 지점 카드는 중앙에 온 지점만 `/api/drops/poi/:id`로 조회하고,
  한 번 조회한 지점은 `dropsCache`에 두어 다시 조회하지 않는다
- 지점 카드는 `in_drop_range`인 지점에서만 열린다

### 판단

- 미리 조회한 드랍 목록을 카드의 `dropsCache`에 넣지 않는다. 그사이에 다른 사람이 주워 갔을 수 있어서, 목록은 카드가 열릴 때의
  조회 결과를 쓴다. 미리 조회한 응답은 그림 주소를 얻는 데에만 쓴다
- 3배 화면에서 56px 칸은 168px이 필요한데 지금은 128px 변환본을 늘려 그린다. 256px 변환본으로 바꾸면 조금 더 선명해진다

## 상세 요구사항

### 기능 요구사항

1. **작은 칸의 변환 폭 통일**
   - `SafeImage`에 `variantWidth?: number` prop을 더한다. 값이 있으면 `next/image`의 `loader`로 srcset의 폭을
     `nextImageWidthFor(variantWidth, 1)`(1배)와 `nextImageWidthFor(variantWidth, 2)`(2배 이상)로 고정한다
   - `BadgeGridCard`의 `compact` 분기(56px)가 `variantWidth={BADGE_CARD_DISPLAY_WIDTH}`를 넘긴다. 표시 크기와 마크업은 그대로다
   - 정적 파일 배지(`unoptimized`)에는 영향이 없어야 한다
2. **그림 받기 공용 함수**
   - `BadgeImageWarmup.tsx`의 «주소 목록을 6장씩 낮은 우선순위로 받는다» 부분을 `jam-web/src/lib/` 아래의 함수로 옮겨 두 곳이 함께 쓴다
3. **드랍 지도 미리 받기**
   - `DropsClient.tsx`에서 지점 목록이 도착한 뒤(184행), `in_drop_range`이고 `available_drops_count`가 1 이상인 지점을
     거리가 가까운 순으로 최대 3곳 고른다
   - 한가한 시점에 지점마다 `/api/drops/poi/:id`를 불러 `badge_image_url`을 모으고, 2번 함수로 받는다. 주소는 카드가 요청하는
     주소(`optimizedImageUrl(src, nextImageWidthFor(BADGE_CARD_DISPLAY_WIDTH, dpr))`)와 같아야 한다
   - 지도 화면이 떠 있는 동안 이미 받은 지점은 다시 부르지 않고, 합쳐서 9곳을 넘기지 않는다
   - `navigator.connection.saveData`가 켜져 있으면 실행하지 않는다. 실패해도 화면에 영향이 없어야 한다
   - 응답을 `PoiCarouselModal`의 `dropsCache`에 넣지 않는다

### UI/UX 관점

- 새 UI가 없다. 3배 화면에서 56px 칸의 그림이 조금 더 선명해지는 것 말고는 눈에 보이는 변화가 없다. 채원 사전 판정 대상이 아니다

### 범위 밖

- 지도 마커(체크인 배지) 그림, 배지 상세 시트의 대표 그림(200px, 다른 변환본)
- 홈 피드의 48px·24px 썸네일
- 미리 조회한 드랍 목록으로 지점 카드를 먼저 그리는 방식(목록의 신선도 문제가 있어 따로 판단한다)
