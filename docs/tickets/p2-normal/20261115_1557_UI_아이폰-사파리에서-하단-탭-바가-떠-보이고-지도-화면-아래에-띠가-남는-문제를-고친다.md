# [UI] 아이폰 사파리에서 하단 탭 바가 떠 보이고 지도 화면 아래에 띠가 남는 문제를 고친다

## 핵심 요약

- 요구사항: 아이폰 12 mini 사파리(staging)에서 (1) 주소창 근처에 남는 여백이 화면마다 다르다. 체크인 지도 화면은 지도 아래에
  빈 띠가 보이고, 미션 화면은 본문이 주소창까지 이어진다. (2) 하단 탭 바를 더 아래로 붙이고 싶다(사용자 요청 2026-11-15, 캡처 2장).
- 구현 계획: 먼저 그 기기의 사파리가 화면 아래쪽을 어떻게 계산하는지 측정 화면으로 확인한다. 그 값으로 탭 바의 위치 식과
  지도 화면의 아랫변을 고친다. **측정 화면의 배포와 사용자 기기에서의 확인이 먼저 필요하다(승인 대기).**
- 관련 파일(지도):
  - `jam-web/src/components/ui/TabBar.tsx` 408행 `bottom: max(10px, calc(env(safe-area-inset-bottom) + 16px - 32px))`
  - `jam-web/design-system/components/navigation/TabBar.jsx`(같은 식을 쓰는 병존 구현)
  - `jam-web/src/app/(main)/drops/DropsClient.tsx` 336행(지도 화면 컨테이너 `fixed inset-0`), 302행(탭 바 높이를 전제한 아래 여백)
  - `jam-web/src/app/(main)/layout.tsx` 95~98행(본문 래퍼 `min-h-dvh`, 회색 바탕)
  - `docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`(탭 바 위치 식의 서술)

## 범위 변경 (2026-11-15)

- **하단 탭 바를 더 아래로 내리는 요청은 사용자가 취소했다.** 탭 바의 위치 식과 최소 여백 10px은 그대로 둔다
- 지도 화면 아래에 남는 띠는 진행 여부가 정해지지 않았다. 원인이 탭 바와 같고(이 사파리의 `fixed` 기준선), 고치려면 아래의
  측정 화면 배포와 사용자 기기에서의 확인이 필요하다. 사용자 확인 전에는 아무것도 배포하지 않는다

## 배경 / 문제 정의

### 확인한 사실 (2026-11-15)

**캡처에서 잰 위치** (아이폰 12 mini, 화면 높이 780pt로 환산한 값이며 오차는 2pt 안팎이다)

| 위치 | 체크인 지도 화면 | 미션 화면 |
|---|---|---|
| 탭 바 아랫변 | 약 623pt | 약 623pt |
| 화면 내용의 아랫변 | 약 632pt(지도가 여기서 끝난다) | 약 648pt(본문이 사파리 도구 막대까지 이어진다) |
| 사파리 도구 막대 윗변 | 약 648pt | 약 648pt |

- 지도 화면에는 지도 아랫변과 사파리 도구 막대 사이에 약 16pt의 띠가 있고, 본문 래퍼의 회색 바탕이 보인다
- 탭 바 아랫변은 지도 아랫변에서 약 10pt 위, 사파리 도구 막대에서는 약 26pt 위에 있다

**코드**

- 탭 바는 `position: fixed`이고 아래 여백의 하한이 10px이다. 지도 화면 컨테이너도 `fixed inset-0`이다. 미션 화면의 본문은 문서 흐름이다
- 하한 10px은 사용자 결정이다. 티켓 20260824_013에서 하한을 0px로 두었다가, 탭 바가 화면 맨 아래에 붙어 버린다는 사용자 요청으로
  티켓 20260824_014에서 10px로 되돌렸다

**외부 보고** (직접 재현하지 못했다. 이 컴퓨터에는 iOS 시뮬레이터 런타임이 없다)

- iOS 26 사파리에서 `position: fixed` 내용이 브라우저 도구 막대 아래쪽 영역에 그려지지 않는다는 보고가 Apple 개발자 포럼에 있다
  (https://developer.apple.com/forums/thread/800798, https://developer.apple.com/forums/thread/800125)
- 같은 검색 결과에 «Safari 26.1 베타 릴리스 노트가 뷰포트 크기의 fixed 컨테이너 아래에 틈이 생기는 문제의 수정을 싣고 있다»는
  언급이 있다. 사용자 기기의 iOS 버전은 확인하지 못했다

### 판단

- 두 현상은 원인이 같다. 이 사파리에서는 `fixed` 요소의 아래 기준선이 도구 막대보다 약 16pt 위에 있고, 문서 흐름의 본문은
  도구 막대까지 그려진다. 그래서 `fixed`인 지도는 띠를 남기고, `fixed`인 탭 바는 의도한 10pt가 아니라 26pt 떠 보인다
- 하한 10px을 그냥 낮추면 이 사파리에서는 내려가지만, 다른 기기(안드로이드, 구형 아이폰)에서는 탭 바가 다시 맨 아래에 붙는다.
  2026-08-24에 되돌린 상태다. 그래서 «이 사파리의 16pt»만 보정해야 한다
- 보정 방법을 정하려면 그 기기에서 CSS·JS가 이 차이를 볼 수 있는지 알아야 한다. 후보는 `sticky` 배치, `dvh`·`svh`·`lvh` 단위,
  `visualViewport`와 `fixed` 요소 위치의 비교다. 어느 것이 통하는지는 실제 기기에서만 알 수 있다

## 상세 요구사항

### 진행 순서 (승인 대기)

1. **측정 화면**: `/spike/viewport-probe`(로그인 없이 열리는 경로)에 측정 화면을 둔다. `fixed`·`sticky` 표지선, `dvh`·`svh`·`lvh` 표지선,
   `innerHeight`·`visualViewport`·`safe-area-inset-bottom` 값, 브라우저 버전을 한 화면에 보인다. staging에 배포한다
2. **기기 확인**: 사용자가 아이폰 사파리로 그 화면을 열어 캡처를 보낸다
3. **수정**: 측정 결과로 탭 바의 위치 식(서비스와 디자인 시스템 두 곳)과 지도 화면의 아랫변을 고친다. 다른 기기에서의 여백 10px은 유지한다

### UI/UX 관점

- 눈에 보이는 변화가 있다(탭 바의 위치, 지도 화면의 아랫변). 3번은 채원 사전 판정을 거친다
- 목표: 이 사파리에서도 탭 바가 도구 막대 위 약 10pt에 놓이고, 지도가 도구 막대까지 이어진다

## 구현 계획

측정 결과가 나온 뒤에 파일 단위로 적는다.

## 완료 조건

- 사용자 기기(아이폰 12 mini 사파리)에서 탭 바와 사파리 도구 막대 사이의 간격이 목표값이고, 지도 화면 아래에 띠가 없다
- 안드로이드 크롬과 데스크톱 브라우저에서 탭 바의 아래 여백이 10px 그대로다
