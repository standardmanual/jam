# [UI] 첫 가입 퀘스트 카드와 관련 화면에서 누르기를 유도하는 곳에 퍼플 강조색을 적용한다

## 핵심 요약

- 요구사항: 첫 가입 뒤 홈에 노출되는 «JAM! 시작하기» 퀘스트 카드와, 퀘스트가 보내는 관련 화면(드랍·픽업 장면, 장소 캐러셀, 믹스, 인벤토리)에서 «지금 눌러야 할 곳»에 퍼플 강조색(`--jam-purple`, #BA8AF7)을 적용한다. 사용자 요청: «첫가입후 노출되는 퀘스트 카드와 관련 화면에서 유저에게 누르기를 유도하는 곳에 퍼플 강조색을 적용해»(2026-11-15 KST)
- 구현 계획: 두 가지를 한 규칙으로 묶는다. ① «지금 눌러야 할 곳» 펄스 링(`.jam-quest-pulse`)의 색을 `--link` 기반에서 `--jam-purple` 기반으로 바꾼다(펄스를 쓰는 모든 자리에 한 번에 반영된다). ② 그 자리에 놓인 버튼의 면을 퍼플로 칠한다(글자는 `--foreground`). 두 효과는 퀘스트 중에만 나타나며 퀘스트 밖 화면은 그대로다.
- 관련 파일(경로 + 고칠 구간):
  - `jam-web/src/components/transitions.css` 약 667~694줄: `@keyframes jam-quest-pulse`의 `color-mix(in srgb, var(--link) …)` 두 곳, 주석(「브랜드 강조색」)
  - `jam-web/src/app/(main)/OnboardingQuestCard.tsx`: `CTA_ROW_PULSE_CLASS`(약 62줄), `ConnectButton`·`RealCta`·`DemoCta`의 `Button variant="primary" surface="sub" size="sm"`(연출 CTA·연결·인벤토리 가기), `SyncOrConnect`의 `SyncButton`
  - `jam-web/src/app/(main)/OnboardingSyncButton.tsx`(연출 동기화 버튼, 약 78~86줄), `jam-web/src/components/SyncButton.tsx`(실제 동기화 버튼)
  - `jam-web/src/app/(main)/combine/CombineClient.tsx` 약 1246~1252줄(믹스하기 버튼, `pulseTarget.type === 'submit'`일 때 `jam-quest-pulse`), 약 1064줄(레시피), `combine/RecipeSlotCard.tsx` 약 68줄·`combine/BagItemCell.tsx` 약 39줄(칸·셀 펄스)
  - `jam-web/src/components/PoiCarouselModal.tsx` 약 905~915줄(드랍 확인 버튼), 약 980~990줄(«여기에 드랍» 버튼), 약 1052~1080줄(펄스 셀)
  - `jam-web/src/app/(main)/drops/QuestPickupScene.tsx` 약 139줄(픽업 마커 원 펄스)
  - 토큰 주석: `jam-web/design-system/tokens/colors.css` 약 59~67줄(강조색 5가지의 사용처 문구), `jam-web/design-system/foundations/Colors.stories.tsx` 약 144줄(`--jam-purple`의 «사용처 미지정»), `jam-web/design-system/_ds_manifest.json`·`_adherence.oxlintrc.json`(퍼플 토큰 항목이 있는지 확인)
  - 관련 시험: `OnboardingQuestCard.test.tsx`, `QuestPickupScene.test.tsx`, 조합·캐러셀 펄스 시험

## 배경 / 문제 정의

- 퀘스트는 연출 7단계와 실제 2단계로 유저를 여러 화면에 보낸다. 지금은 «지금 눌러야 할 곳»을 `--link` 색 펄스 링으로만 알리고, 버튼 면은 검정(accent)이라 다른 버튼과 구분되지 않는다.
- `--jam-purple`은 강조색 5가지 중 하나지만 사용처가 아직 없다(`colors.css` 주석 «사용처는 사용자가 따로 지정한다», 스토리 «사용처 미지정»). 이번 요청이 첫 사용처 지정이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 퍼플은 «퀘스트가 지금 누르라고 안내하는 자리»에만 쓴다. 퀘스트 밖 화면의 같은 버튼·셀은 지금 모양 그대로다.
- 펄스 링 색은 `color-mix(in srgb, var(--jam-purple) …)`로 바꾼다(리터럴 hex 금지). 바꾸면 펄스를 쓰는 모든 자리에 한 번에 반영된다.
- 버튼 면 퍼플은 한 곳에서 정의한다(예: 퀘스트 전용 클래스 한 개 또는 같은 효과의 방법). 호출부마다 색을 따로 적지 않는다. `Button`(`ui/Button.tsx`)과 DS `Button.jsx`의 변형 쌍 시험(`buttonVariantPairs.test.tsx`)은 깨지 않는다.
- 퍼플 면 위 글자는 `--foreground`(검정)다. `--snow`(흰색)는 퍼플 위 대비가 약 1.4:1이라 쓰지 않는다(`--foreground`는 약 8:1).
- 토큰 사용처 문구를 실제와 맞춘다: `colors.css`의 강조색 주석에 «`--jam-purple`은 온보딩 퀘스트의 «지금 눌러야 할 곳»(펄스 링·CTA 면)에 쓴다(2026-11-15)»를 더하고, `Colors.stories.tsx`의 «사용처 미지정»을 고친다.

### UI/UX 관점

- 퍼플을 칠하는 자리(채원 사전 판정에서 확정): 퀘스트 카드의 현재 단계 CTA(연출 «계속» 류 버튼, 연출 동기화, 실제 연결·동기화, «인벤토리 가기»), 조합 화면 «믹스하기»(펄스 중일 때), 장소 캐러셀의 드랍 확인·«여기에 드랍»(펄스 중일 때). 칸·셀·마커처럼 면을 칠하기 어려운 자리(레시피 칸 `+` 버튼, 가방 셀, 픽업 마커 원)는 펄스 링 색만 퍼플로 바꾼다. 카드 안 «건너뛰기»(검정 소형)와 취소·보조 버튼은 칠하지 않는다.
- 한 화면의 퍼플 면 버튼은 하나다(지금 누를 곳 하나, 결정 7).
- 동작 줄이기 설정에서는 펄스가 없으므로 퍼플 면과 링 색 말고 달라지는 것이 없다.

## 구현 계획

1. `transitions.css`의 펄스 키프레임 색을 `--jam-purple` 기준으로 바꾸고, 같은 파일에 퀘스트 CTA 면 클래스(퍼플 면 + `--foreground` 글자)를 더한다. 클래스는 Tailwind 유틸리티보다 확실히 이기도록 둔다(unlayered 규칙이거나 같은 효과의 방법).
2. 위 «관련 파일»의 CTA 버튼들에 그 클래스를 붙인다. 펄스가 걸리는 조건과 같은 조건에서만 붙게 한다(퀘스트 중 아니면 붙지 않는다).
3. `colors.css` 주석·`Colors.stories.tsx` 문구·필요하면 DS 매니페스트의 퍼플 항목을 사용처와 맞춘다. 시험을 갱신하고 `scripts/verify.sh`를 통과시킨다.

## 완료 조건

- 퀘스트 카드(연출·실제 두 구역)의 현재 단계 CTA가 퍼플 면 + 검정 글자이고, 펄스 링이 퍼플이다. 건너뛰기 버튼은 그대로 검정이다.
- 드랍·픽업 장면, 장소 캐러셀, 믹스 화면에서 퀘스트가 가리키는 자리의 펄스 링이 퍼플이고, 버튼인 자리(믹스하기, 드랍 확인, «여기에 드랍»)는 면도 퍼플이다. 퀘스트가 아닐 때 같은 화면의 버튼은 지금 모양 그대로다(퍼플 클래스 미부착).
- `transitions.css`·퀘스트 관련 파일에 리터럴 `#BA8AF7`이 없고 `--jam-purple`만 쓴다.
- 퍼플 면 위 글자 대비가 4.5:1 이상이다(`--foreground` 사용).
- 토큰 주석·스토리의 `--jam-purple` 사용처 문구가 실제와 맞다. `ds:check`·typecheck·lint·관련 시험이 통과한다.
- 로컬 실렌더(헤드리스 크롬 375×812, 테스트 계정)로 퀘스트 카드와 믹스·캐러셀 화면에서 퍼플 면과 링을 눈으로 확인한 기록이 있다.
