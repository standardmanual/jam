# [Feature] «JAM! 시작하기» 온보딩 퀘스트 기능과 어드민 화면을 제거한다 (상위)

## 핵심 요약
- 요구사항: 홈의 첫 시작 카드와 5개 화면(홈·인벤토리·드랍·믹스·미션)의 연출, 퀘스트 API·로직·어드민 미리보기·정책 대시보드 항목·문서를 걷는다. 사용자 지시(2026-11-15 «퀘스트 기능을 제거해. 어드민도 제거해»).
- 구현 계획: 하위 티켓 4개 + 문서를 순서대로 처리한다. A(챕터 1 시작·완료 배지를 트라이브 선택 시점으로 이동) → B(화면 연출·홈 카드 제거) → C(로직·API·타입·다국어·어드민·정책 제거) → D(DB 테이블 삭제, 메인 세션 실행) → 문서.
- 관련 파일: 하위 티켓 참조. 진행 중이던 `20261115_1932`(카드 퍼플 면)·`20261115_2043`(연출 구역 레이아웃)은 이 제거로 무의미해져 닫는다.

## 사용자 결정 (2026-11-15)
1. DB: 테이블까지 삭제한다(백업 표와 되돌림 SQL을 갖춘 별도 단계 D).
2. 챕터 1 시작: 트라이브 선택(가입 완료) 즉시 시작한다. 지금은 퀘스트 완료 처리(첫 동기화 + 잠긴 개체 열기)에서만 시작하므로, 걷으면 신규 가입자가 챕터 1을 영영 못 받는다.
3. 완료 보상 배지 「JAM!」(포인트 포함): 계속 지급한다. 시점은 챕터 1 시작과 같은 순간으로 둔다(2에 맞춰 카리나 가정, 보고 때 확인받는다). 이미 받은 2명은 그대로다.

## 조사 결과 (2026-11-15, 공용 DB 실측)
- `user_onboarding_quests` 2행, 둘 다 완료·보상 지급됨, 진행 중 0행. 퀘스트 보상 배지 행(`triggered_by='onboarding_quest'`) 2개.
- `ensureChapterStarted`(`lib/chapter/start.ts`)의 호출부는 퀘스트 완료(`lib/onboarding-quest/completion.ts`)뿐이다.
- 화면 게이트(`screen-gate.ts`)는 연출 단계 표시만 정한다. 실제 기능을 막지 않으므로 걷어도 열리는 실제 기능은 없다. 챕터가 NULL이면 캡슐이 «퀘스트 전» 캡슐로 처리되는 부분(`lib/capsule/claim.ts` preQuest)은 챕터 1 시작 시점을 앞당기면 자연히 줄어든다.

## 완료 조건
- 하위 A~D와 문서가 모두 CLOSED다.
- 홈·인벤토리·드랍·믹스·미션 화면이 퀘스트 없이 정상 동작하고(로컬 확인), `npx tsc --noEmit`·`npx eslint`·`npx vitest run`(어드민 ops 기존 실패 28개 파일 제외)이 통과한다.
- 신규 가입자가 트라이브를 고르면 챕터 1이 시작되고 「JAM!」 배지가 1회 지급된다.
