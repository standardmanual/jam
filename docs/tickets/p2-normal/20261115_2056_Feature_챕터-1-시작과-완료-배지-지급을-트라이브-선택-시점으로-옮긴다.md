# [Feature] 챕터 1 시작과 «JAM!» 완료 배지 지급을 트라이브 선택(가입 완료) 시점으로 옮긴다

## 핵심 요약
- 요구사항: 트라이브 선택으로 가입이 끝나는 순간 챕터 1을 시작하고, 완료 배지 「JAM!」(고정 id `cd20f271-9445-42cc-ac51-d8a96b25e1c3`)과 그 `point_reward`를 1회만 지급한다. 퀘스트 모듈(`lib/onboarding-quest`)에 의존하지 않게 한다. 이 티켓 뒤에는 퀘스트를 지워도 챕터 1·배지가 끊기지 않는다.
- 구현 계획: ① 신규 `src/lib/chapter/signup-reward.ts`에 `grantSignupBadge`를 둔다. `onboarding-quest/completion.ts`의 `grantOnboardingQuestReward`(L99~176)에서 `reward_granted_at` 선점·롤백을 빼고 배지 insert(23505면 이미 지급, 포인트·피드 생략) → 배지 정보 조회 → `awardBadgeReceiveScore` → `awardPoints` → `recordFeedEvent` 순서를 그대로 옮긴다. `triggered_by` 값은 기존 `'onboarding_quest'`를 유지한다(기존 행·집계와 같게, 값 이름 정리는 하지 않는다). ② 배지 id 상수도 이 파일로 옮겨(`config.ts`의 `ONBOARDING_COMPLETION_BADGE_ID`) `badgeConditionText.ts`가 새 위치를 임포트하게 한다(config.ts의 상수는 C에서 지워진다). ③ `src/app/api/onboarding/complete/route.ts`의 2단계 성공 직후(L123 `onboarding_completed_at` 저장 성공 뒤, 퀘스트 행 upsert 앞)에 `ensureChapterStarted(serviceClient, user.id)`와 `grantSignupBadge`를 부른다. 둘 다 던지지 않고, 실패해도 가입 응답을 막지 않는다. ④ `badgeConditionText.ts`의 `ONBOARDING_COMPLETION_CONDITION_TEXT`(L47) 문구를 «JAM!의 첫 단계를 모두 마치면 …»에서 가입 시점에 맞게 고친다(UX Writing 가이드·해요체). ⑤ `api/dev-login/route.ts` 5번 블록(L81~)은 퀘스트 행 upsert 대신 `ensureChapterStarted` 호출로 바꾼다(테스트 계정이 챕터 1을 갖게). ⑥ 위 호출부와 새 함수의 시험을 더한다(가입 2단계 호출 시 챕터 시작·배지 1회 지급, 재호출 시 중복 없음, 실패해도 응답 성공).
- 관련 파일: `src/lib/onboarding-quest/completion.ts`(원본, 이 티켓에서는 건드리지 않고 복사해 옮긴다), `src/lib/chapter/start.ts`(`ensureChapterStarted` L97), `src/app/api/onboarding/complete/route.ts`, `src/app/api/onboarding/complete/__tests__/route.test.ts`, `src/app/api/dev-login/route.ts`(+`__tests__/route.test.ts`), `src/lib/badgeConditionText.ts`(L29·47·376), `src/lib/__tests__/badgeConditionText.test.ts`, `src/lib/onboarding-quest/config.ts`(상수 출처), `src/lib/chapter/badgeReceive.ts`, `src/lib/points`, `src/lib/activity-feed`.

## 배경 / 문제 정의
챕터 1 시작과 완료 배지는 퀘스트 완료 처리(실제 2단계: 첫 동기화 + 잠긴 개체 열기)에서만 일어난다. 퀘스트를 걷으면 이 둘이 끊기므로, 사용자 결정(상위 20261115_2055)에 따라 가입 완료 시점으로 옮긴다.

## 완료 조건
- 트라이브를 고르는 2단계 호출(성공)에서 `user_chapters.chapter_no`가 1로 시작하고 배지가 1회 지급된다. 같은 유저가 다시 호출해도(409 경로 포함) 중복 지급이 없다. 재현: `route.test.ts`.
- 챕터 시작·배지 지급이 던져도 `POST /api/onboarding/complete`는 `{ success: true }`를 돌려준다.
- 이 티켓의 코드는 `lib/onboarding-quest/*`를 임포트하지 않는다(상수 포함). `npx tsc --noEmit`·`npx eslint`·관련 `vitest`가 통과한다.
- 기존 `lib/onboarding-quest/completion.ts`는 이 티켓에서 변경하지 않는다(C에서 삭제).
