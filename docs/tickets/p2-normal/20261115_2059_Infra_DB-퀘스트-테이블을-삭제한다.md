# [Infra] DB의 `user_onboarding_quests` 테이블을 백업한 뒤 삭제한다

## 핵심 요약
- 요구사항: 코드가 퀘스트 테이블을 더 읽지 않게 된(A·B·C 머지, 배포 반영) 뒤에 테이블을 지운다. 사용자 결정으로 테이블까지 삭제한다.
- 구현 계획: ① `supabase/migrations/3NN_drop_user_onboarding_quests.sql`(번호는 실행 직전 원격 staging 기준 확인)을 쓴다. 순서: 백업 표 `user_onboarding_quests_backup_20261115`에 2행 복사 → `DROP TABLE public.user_onboarding_quests`(RLS 정책·코멘트 함께 사라짐). ② 되돌림 SQL은 파일 하단 주석에 195번 정의와 백업 복원 `INSERT ... SELECT`로 둔다. ③ 메인 세션이 DO 블록 롤백 실측(`RAISE EXCEPTION`)으로 드라이런한 뒤 실행하고 읽기 전용으로 확인한다(CLAUDE.md 6). ④ `src/types/database.generated.ts`를 MCP `generate_typescript_types`와 대조해 퀘스트 항목이 없는지 확인한다. ⑤ 이전 마이그레이션 195·216·256·290은 이력이므로 고치지 않는다.
- 관련 파일: `supabase/migrations/195_user_onboarding_quests.sql`(원본 정의), `src/types/database.generated.ts`.
- 실행 선행 조건: C까지 반영된 코드가 프로덕션이 아닌 현재 공용 DB를 보는 staging에서 정상이며, 프로덕션(main)이 아직 옛 코드를 쓰고 있다면 테이블 삭제 시 옛 main 코드가 퀘스트 테이블 조회 실패를 겪는다. **main 승격 시점과 순서를 사용자와 정한 뒤 실행한다.** 옛 코드는 조회 실패를 null로 처리하고 화면을 막지 않는다(`screen-gate.ts` L67~).

## 완료 조건
- 테이블이 사라졌고 백업 표에 2행이 있으며, 되돌림 SQL이 파일에 있다. 삭제 후 홈·가입 화면이 오류 없이 열린다.
