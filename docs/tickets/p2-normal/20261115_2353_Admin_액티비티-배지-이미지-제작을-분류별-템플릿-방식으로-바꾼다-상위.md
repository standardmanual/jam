# [Admin] 액티비티 배지 이미지 제작을 분류별 템플릿 방식으로 바꾼다 (상위)

## 핵심 요약
- 요구사항: 어드민의 «액티비티 배지 이미지 생성기»(`/admin/activity-badge-image`)를 템플릿 방식으로 대체한다. 배지를 검색해 선택하면 그 배지가 속한 분류의 템플릿이 자동으로 적용되고, 이름과 값(달성한 조건)이 템플릿의 지정된 자리에 표시된다. 템플릿 색의 HUE·명도·채도·색 계열과 글자의 색·글꼴을 조정해 긴 변 1280px 이미지로 등록한다. 템플릿 디자인(SVG)은 사용자가 따로 만들어 제공하므로 이 티켓의 범위가 아니다.
- 구현 계획: 일곱 회차의 하위 티켓으로 나눈다(아래 「구현 계획」의 표). 1·2회차는 동시에, 나머지는 순서대로 진행한다. 기존 에셋 제너레이터의 글자 레이어·구글 폰트·배지 적용 기능을 재사용한다.
- 관련 파일: 아래 「재사용 지도」 절. 사용자 결정의 원문은 이 티켓의 「결정 사항」 절이 단일 기록이다.

## 배경 / 문제 정의
지금의 생성기는 피그마 시안을 코드 상수로 옮긴 고정 구도(블롭 배경, 글래스 판, 등급 칩, 이름, 설명)를 그린다. 디자이너가 만든 템플릿을 받을 수 없고, 이름과 설명을 운영자가 직접 입력한다. JAM 2.0의 액티비티 배지는 55개 계열 228개 단계여서, 단계마다 손으로 만들기 어렵다.

사용자(디자이너)는 분류마다 템플릿을 하나씩 디자인하고, 어드민이 배지의 이름과 값을 자동으로 채워 넣기를 원한다(2026-11-15 대화).

## 결정 사항 (사용자, 2026-11-15)
- **용어:** 템플릿을 나누는 묶음은 «분류»라고 부른다. 분류 4개가 곧 템플릿 4개다. «계열»은 같은 조건을 단계로 나눈 배지 묶음(DB의 `family_key`)에만 쓴다.
- **이미지에 넣는 글자:** 이름, 값, JAM 로고뿐이다. 로고는 템플릿에 포함된다. 등급·레벨·반복 횟수는 화면의 칩이 보여 주고 이미지에는 넣지 않는다.
- **값:** 그 단계에서 달성한 조건이다. 획득 조건(`condition_json`)에서 자동으로 가져온다. 운영자가 손으로 입력하지 않는다.
- **분류(값의 단위 기준):** 운동 수치(거리·높이·시간) / 쌓은 날(누적한 일·주·해) / 이어 온 날(연속과 복귀) / 횟수와 양(회·개·명·잼·챕터). 카리나가 낸 안으로 캔버스 샘플을 만들었고, 사용자는 이 네 분류를 템플릿 4개로 받아들였다.
- **흐름:** 배지 검색 → 선택 → 분류의 템플릿 자동 적용 → 이름과 값이 지정 자리에 표시.
- **템플릿 형식:** SVG 한 장. 사용자가 제공한다.
- **글자 기능:** 미리 정하지 않는다. 사용자가 템플릿을 줄 때마다 그 템플릿에 필요한 글자 기능을 판단해서 만든다. 이번에는 직선 글자만 만든다.
- **색 프로퍼티:** 템플릿 색의 HUE·명도·채도 조정과 색 계열 변경은 반드시 넣는다. 입력된 값 글자의 색과 글꼴도 바꿀 수 있어야 한다.
- **등록 규격:** 긴 변 1280px로 통일한다.
- **구간 계열:** 등급마다 이름이 다른 계열(운동 속성 11개)은 그림을 같게 두고 이름 글자만 바꿔 자동으로 만든다.
- **재사용:** 기존에 개발된 기능은 재사용한다.
- **대체:** 기존 액티비티 배지 메뉴 페이지를 이 기능으로 바꾼다.
- **범위 밖:** 배지함에서 등급형을 계열당 한 장으로 접는 일은 하지 않는다.
- **글자 색(사용자, 2026-11-16):** 이름·값 글자 색은 템플릿 색 조정과 따로 둔다. 템플릿을 다른 색 계열로 돌려도 글자 색은 그대로이고, 글자 색은 글자 조정에서 따로 고른다.
- **안쪽 상자(사용자, 2026-11-16 오후):** 제공한 SVG는 배지 이미지를 꽉 채우지 않고 안쪽 가운데에 이미지 생성 메뉴의 기준과 같은 크기로 들어간다. 사용자의 말은 «배지 이미지 크기 1024에서 내부 중심 87% 정도, 이전 이미지 생성 메뉴 개발 시 설정한 기준»이다. 그 기준은 코드(`badgeImageGenerator/normalize.ts`)에 1024 캔버스·긴 변 870(약 85%)·정중앙으로 들어 있어서, 카리나가 870÷1024로 읽고 사용자에게 알렸다. 등록 크기는 처음에 «1280 유지»로 답했다가(2026-11-16 오후) 곧 바꿨다. 아래 «이미지 기준 크기»를 본다.
- **이미지 기준 크기(사용자, 2026-11-16 오후):** 배지·미션·컬렉션 이미지의 기준을 긴 변 1280에서 «긴 변 1024 또는 1024×1024»로 바꾼다. 사용자가 «이걸 원칙으로 정할게»라고 했다. 단서는 «최근에 브라우저 저장용으로 설정한 사이즈는 유지해»이고, 카리나는 변환본 폭(96·256·384·640)으로 읽었다. 액티비티 배지 템플릿의 등록도 1024×1024가 된다(안쪽 상자 870, 여백 77). 티켓 20261116_1522가 8-2회차 뒤에 이 일을 한다.
- **템플릿을 넣는 방식(사용자, 2026-11-16 오후):** 어드민에 SVG를 올리는 방식을 그만두고, 템플릿마다 그때그때 개발해서 넣는다. 사용자가 SVG와 글꼴 이름을 주면 카리나가 그 템플릿에 맞춰 글자 놓는 방식을 만든다. 사용자가 든 까닭은 디자인마다 글자가 놓이는 형태가 원일 수도, 타원일 수도, 다른 형태일 수도 있다는 것이다. 어드민의 «템플릿» 탭(올리기·검사)과 템플릿 저장 API는 지운다. 위의 «템플릿 형식»(SVG 한 장, 사용자가 제공)과 «글자 기능»(템플릿을 받을 때마다 판단해서 만든다)은 그대로다.

## 가정 (사용자 승인, 2026-11-15)
- 분류는 획득 조건의 종류를 보고 자동으로 정한다. 숫자가 없는 배지 넷은 «밤», «첫 체크인», «최장 거리», «최고 페이스»로 고정한다.
- 템플릿은 분류마다 한 개다. 이름 자리와 값 자리는 SVG 안의 레이어 이름 `name`, `value`로 찾는다. 템플릿이 없는 분류의 배지를 고르면 «템플릿 없음» 안내를 보인다.
- DB에 표가 하나 늘어난다. 공용 DB라 프로덕션에도 바로 생기지만 읽는 곳은 어드민뿐이다.
- 지금 배지에 걸려 있는 이미지는 그대로 둔다. 새 기능으로 다시 등록한 배지만 바뀐다.
- 옛 생성기가 그리던 설명 글, 등급 칩, 블롭 배경은 없어진다.
- 새 계열 가운데 DB에 아직 없는 것은 입력되는 대로 같은 규칙이 적용된다(입력은 티켓 20261018_1816).
- 로컬 커밋까지만 하고 push는 사용자가 요청할 때 한다. 화면 확인은 카리나가 로컬 어드민에서 한다.
- 개발하는 동안에는 시험용 임시 SVG를 쓴다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 값의 꼴은 캔버스 «액티비티 배지 · 이름과 값 목록» 보드(`project/BadgeNameValue.dc.html`)가 기준이다. 그 목록은 원고 `docs/plan/jam2/tribe-rethink/manuscript/06 액티비티 배지.md` 11절의 조건 표기에서 뽑았다. 꼴의 규칙은 하위 티켓 20261115_2354에 표로 옮겼다.
- 색 조정은 SVG에 쓰인 색을 자동으로 찾아 색 칸으로 보여 주는 방식이다. HUE·명도·채도는 색 전체에 한꺼번에 적용하고, 색 계열 변경은 색 조합을 통째로 바꾸거나 칸 하나씩 바꾼다. 그라데이션이나 반투명이 든 템플릿의 처리는 그런 템플릿을 받았을 때 판단한다.
- 조정한 값은 배지의 `image_gen_params`에 저장해 다시 열어 고칠 수 있게 하고, `image_source`에 제작 경로를 남긴다.

### UI/UX 관점 (해당 시)
- 어드민 화면은 shadcn/ui 표준을 쓴다(MODULAR 적용 대상이 아니다).

## 첫 템플릿 분석 (2026-11-16, 사용자가 `Frame 13.svg`를 제공)

### 확인한 사실 (파일을 그려 보고, `validateTemplateSvg`와 좌표 계산으로 확인)
- 크기는 876×876이다. 요소는 바깥 원(`Ellipse 5`), 별 모양(`Union`), `name`, `value`, `JOIN AND MOVE`, JAM 로고(`Vector`)다. `<text>`와 `<textPath>`는 없다.
- `name`과 `value`는 글자를 모양으로 바꾼 `<path>` 하나씩이다. 지금 검사기는 «이름 자리가 글자가 아니에요. 피그마 내보내기 설정의 Outline text를 끄고 다시 내보내 주세요.»로 거절한다.

- `value`(샘플 «135939km»): 같은 중심의 아래쪽 원호에 놓여 있다. 중심에서의 거리는 297.2~384.5이고, 6시 방향을 0°로 볼 때 −44.9°~+45.3°를 차지한다(좌우 대칭, 약 90°). 글자의 윗부분이 중심을 향한다.
- 색은 #000000, #DD2C0F, #FC8471, #FFFFFF 네 가지이고, `extractSvgColors`가 그라데이션의 색까지 모두 읽는다.
- 바깥 원은 반지름 449.5에 선 두께 23이라서 프레임 밖으로 나가고, 선이 위·아래·양옆에서 잘려 보인다.

- 실행 지표의 합(하위 티켓 열한 개, 2026-11-16): 에이전트 호출 26회, 전체 토큰 1,595,204, 출력 토큰 아현 353,387 / 게이트 129,474, 소요 3시간 45분 37초, 도구 호출 565회. 주간 집계와 겹치지 않게 위 표에는 적지 않는다.
- 회차를 일곱 개에서 열한 개로 늘린 까닭: 화면이 있는 회차(3, 4, 5, 6)를 «계산·API»와 «화면»으로 나눴다. 계산을 시험으로 먼저 고정해 두면 화면 확인에서 어긋났을 때 원인을 가리기 쉽고, 한 티켓의 크기도 줄어든다.
- 티켓 분해는 혜린을 거치지 않고 카리나가 직접 했다. 정의가 사용자와의 대화에서 이미 끝났기 때문이며, 사용자가 이 진행 방식을 골랐다(2026-11-15).
- 분류를 가지(`branch_key`) 기준이 아니라 값의 단위 기준으로 잡은 까닭: 사용자가 «값은 달성한 조건을 표시하는 것이 옳다»고 정한 뒤 그 값의 모양에서 거꾸로 분류를 정했다. 가지로는 이 분류를 가릴 수 없다(예: 리듬 가지의 계열은 «쌓은 날»과 «이어 온 날»로 갈린다).
