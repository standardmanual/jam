# [API] 배지 템플릿 SVG를 정화하고 자리를 읽어 저장하는 어드민 API를 만든다

## 핵심 요약
- 요구사항: 분류별 배지 템플릿(SVG)을 받아 위험한 요소를 걷어 내고, 이름 자리(`name`)와 값 자리(`value`)를 읽어 `activity_badge_templates` 표에 저장하는 어드민 API와 그 바탕 모듈을 만든다. 화면은 만들지 않는다(상위 티켓 20261115_2353의 3회차 가운데 첫 부분. 화면은 다음 티켓).
- 구현 계획: SVG 처리(정화, 자리 읽기)를 순수 모듈로 만들고 시험으로 고정한 뒤, 목록·저장·삭제 라우트 세 개를 그 위에 얹는다.
- 관련 파일:
  - 새 파일 `jam-web/src/lib/admin/activityBadgeTemplate/templateSvg.ts` (`sanitizeTemplateSvg`, `readTemplateSlots`, 타입과 상수)
  - 새 파일 `jam-web/src/lib/admin/activityBadgeTemplate/__tests__/templateSvg.test.ts`
  - 새 파일 `jam-web/src/app/api/admin/activity-badge-templates/route.ts` (GET), `jam-web/src/app/api/admin/activity-badge-templates/[classKey]/route.ts` (PUT, DELETE), 각 `__tests__/route.test.ts`
  - `jam-web/package.json` 71줄: `@xmldom/xmldom`이 devDependencies에 있다. 서버 코드에서 쓰므로 dependencies로 옮기고 `package-lock.json`을 맞춘다
  - `docs/service/prd/asset-generator/PRD.md`: 맨 뒤에 «액티비티 배지 템플릿» 절을 더한다(표, API, SVG 약속)
  - 읽기만: `jam-web/src/lib/admin/activityBadgeTemplate/resolveTemplateText.ts`(7줄 `BadgeTemplateClassKey`, 9줄 `BADGE_TEMPLATE_CLASS_LABEL`), `jam-web/src/types/database.ts`(`ActivityBadgeTemplateRow`), `jam-web/src/lib/admin/auth.ts`(`getAdminUser`. 없으면 403), `jam-web/src/lib/supabase/server.ts`(40줄 `createServiceClient`), `jam-web/src/app/api/admin/asset-generator/apply/route.ts`(112~113줄 권한 확인 방식), `jam-web/src/app/api/admin/suspensions/__tests__/route.test.ts`(28~29줄, `vi.mock`으로 권한과 DB를 흉내 내는 예), `jam-web/src/lib/logo-3d/svgOutline.ts`(31줄, DOMParser로 SVG를 읽는 예)

## 배경 / 문제 정의
템플릿을 저장할 표는 2회차(20261115_2355)에서 만들었다. 이 표에 템플릿을 넣고 꺼내는 길이 아직 없다. 템플릿은 디자이너가 피그마에서 내보낸 SVG라서, 저장하기 전에 두 가지를 해야 한다. 첫째, 스크립트나 바깥 주소를 부르는 요소를 걷어 낸다(저장소에 SVG 정화 코드가 없다). 둘째, 어드민이 이름과 값을 넣을 자리를 SVG에서 찾아 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### SVG 처리 모듈 (`templateSvg.ts`)
- `@xmldom/xmldom`의 `DOMParser`와 `XMLSerializer`로 읽고 쓴다. 서버, 브라우저, 시험(vitest의 node 환경) 어디서나 같은 코드가 돌아야 한다.
- `sanitizeTemplateSvg(svgText)`는 `{ svg, removed }`를 돌려준다. `removed`는 걷어 낸 것의 목록(사람이 읽을 수 있는 짧은 문자열)이다.
  - 걷어 내는 요소: `script`, `foreignObject`, `iframe`, `object`, `embed`, `link`, `meta`. `style` 요소는 내용에 `@import`나 `url(`이 있으면 걷어 낸다.
  - 걷어 내는 속성: 이름이 `on`으로 시작하는 모든 속성. `href`와 `xlink:href`는 값이 `#`으로 시작하거나 `data:image/`로 시작할 때만 남긴다.
  - 뿌리 요소가 `svg`가 아니거나 XML로 읽지 못하면 오류를 던진다(오류 종류를 구분할 수 있게 코드나 이름을 붙인다).
- `readTemplateSlots(svgText)`는 `TemplateSlots`를 돌려준다.
  - `id`가 `name`인 요소와 `value`인 요소를 찾는다. 그 요소가 `text`면 그대로 쓰고, `g`면 그 안의 첫 `text`를 쓴다.
  - 자리마다 읽는 값: 찾았는지(`found`), 글자 요소인지(`isText`), `x`와 `y`(요소에 없으면 첫 `tspan`에서), `fontFamily`, `fontSize`(숫자), `fontWeight`, `fill`, `letterSpacing`, `textAnchor`, `transform`, 자리 표시용 글자(`placeholder`). 값이 없으면 `null`이다. 속성이 `style` 안에 있으면 거기서도 읽는다.
  - 뿌리의 `viewBox`에서 너비와 높이를 읽는다. 없으면 `width`·`height` 속성에서 읽고, 둘 다 없으면 `null`이다.
  - 요소는 있는데 글자가 아니면(예: 윤곽선으로 바뀐 `path`) `found: true, isText: false`다.
- 상수: 자리 이름(`name`, `value`), SVG 최대 크기 1,000,000바이트.
- 피그마가 내보내는 글자의 모양은 다음과 같다. 시험의 임시 SVG도 이 모양을 따른다: `<text id="name" fill="#123B2E" xml:space="preserve" style="white-space: pre" font-family="Pretendard" font-size="48" font-weight="bold" letter-spacing="0em"><tspan x="120" y="96">배지 이름</tspan></text>`

#### API
- 세 라우트 모두 `getAdminUser()`가 `null`이면 403을 돌려준다. DB는 `createServiceClient()`로 읽고 쓴다.
- `GET /api/admin/activity-badge-templates` → `{ templates: [...] }`. 분류 4개를 `metric`, `days`, `streak`, `count` 순서로 항상 돌려준다. 항목은 `{ classKey, label, svg, slots, updatedAt, updatedBy }`이고, 등록되지 않은 분류는 `svg`·`slots`·`updatedAt`·`updatedBy`가 `null`이다. `label`은 `BADGE_TEMPLATE_CLASS_LABEL`에서 가져온다.
- `PUT /api/admin/activity-badge-templates/[classKey]`, 본문 `{ svg: string }`
  - 400: `classKey`가 네 분류가 아님 / `svg`가 문자열이 아니거나 비어 있음 / 1,000,000바이트 초과 / SVG로 읽지 못함 / 이름 자리나 값 자리를 찾지 못함 / 자리가 글자 요소가 아님
  - 성공: 정화한 SVG와 읽어 낸 자리를 저장한다(`class_key` 기준 upsert, `updated_by`는 관리자 이메일, `updated_at`은 지금). 응답은 저장된 항목(GET의 항목 모양)과 `removed`다.
- `DELETE /api/admin/activity-badge-templates/[classKey]` → 그 분류의 템플릿을 지운다. 없어도 200이다. `classKey`가 잘못되면 400이다.
- 오류 응답의 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다(해요체, 현상 → 원인 → 해결책). 예: «이름 자리를 찾지 못했어요. 피그마에서 이름 글자의 레이어 이름을 name으로 바꾸고, 글자를 윤곽선으로 바꾸지 않은 채 다시 내보내 주세요.» DB 오류의 원문은 응답에 싣지 않는다.

### UI/UX 관점 (해당 시)
- 화면은 다음 티켓에서 만든다. 화면이 템플릿을 그릴 때는 SVG를 문서에 직접 끼워 넣지 않고 이미지(`img`나 캔버스)로만 그린다는 약속을 PRD 절에 적어 둔다.

## 구현 계획
1. `templateSvg.ts`와 시험을 먼저 만든다. 시험의 임시 SVG는 시험 파일 안에 문자열로 둔다.
2. `@xmldom/xmldom`을 dependencies로 옮긴다.
3. 라우트 세 개와 시험을 만든다. 시험은 `vi.mock('@/lib/admin/auth')`와 `vi.mock('@/lib/supabase/server')`로 권한과 DB를 흉내 낸다.
4. PRD에 절을 더한다: 표의 칸, API 세 개, SVG 약속(자리 이름 `name`·`value`, 글자를 윤곽선으로 바꾸지 않기, 정화 규칙, 이미지로만 그리기).

## 완료 조건
- 정화: `script` 요소, `onload` 같은 `on*` 속성, `foreignObject`, 바깥 주소를 가리키는 `href`가 든 SVG를 넣으면 결과 SVG에 그것들이 없고 `removed`에 기록된다. `#`으로 시작하는 `href`와 도형·글자·색은 그대로 남는다. 재현 경로: `cd jam-web && npx vitest run src/lib/admin/activityBadgeTemplate`.
- 자리 읽기: 피그마 모양의 임시 SVG에서 `name`과 `value` 자리의 `x`, `y`, `fontFamily`, `fontSize`, `fill`, `placeholder`가 읽힌다. `g`로 감싼 글자도 읽힌다. 자리가 없으면 `found: false`, 윤곽선이면 `isText: false`다.
- API: 권한이 없으면 세 라우트 모두 403이다. GET은 아무것도 등록되지 않았을 때도 네 항목을 돌려준다. PUT은 위 400의 경우마다 400을 돌려주고 DB에 쓰지 않는다. 정상 SVG는 정화된 본문과 자리, 관리자 이메일이 upsert된다. DELETE는 없는 분류에도 200이다. 재현 경로: `npx vitest run src/app/api/admin/activity-badge-templates`.
- `@xmldom/xmldom`이 dependencies에 있다.
- PRD에 «액티비티 배지 템플릿» 절이 있다.
- 리뷰 브랜치의 CI verify가 success다.
