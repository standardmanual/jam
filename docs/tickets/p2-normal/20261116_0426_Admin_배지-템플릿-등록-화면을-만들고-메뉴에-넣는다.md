## 배경 / 문제 정의
템플릿을 저장하는 표와 API는 있지만 운영자가 쓸 화면이 없다. 템플릿은 디자이너가 피그마에서 내보낸 SVG다. 피그마는 기본 설정으로 내보내면 글자를 윤곽선으로 바꾸고 레이어 이름을 싣지 않으므로, 자리 인식이 실패하기 쉽다. 그래서 화면은 올바른 내보내기 방법을 알려 주고, 저장하기 전에 인식 결과를 보여 줘야 한다.

피그마 도움말(«Export formats and settings», 2026-11-16 확인)에서 확인한 사실은 다음과 같다. SVG 내보내기 설정에 «Include "id" attribute»와 «Outline text»가 있다. id는 레이어 패널의 이름을 따라 만들어진다. «Outline text»는 글자 레이어를 고르면 기본으로 켜져 있고, 켜져 있으면 글자가 윤곽선으로 바뀐다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 정화 보강 (`templateSvg.ts`)
- 도우미 `hasExternalUrl(value)`를 더한다. 값 안의 모든 `url(...)`을 찾아, 따옴표와 공백을 벗긴 대상이 `#`으로도 `data:image/`로도 시작하지 않는 것이 하나라도 있으면 참이다.
- `style` 속성: `;`로 나눈 선언 가운데 `hasExternalUrl`이 참이거나 `@import`, `expression(`, `javascript:`가 든 선언만 빼고 나머지는 남긴다. 남은 선언이 없으면 속성을 지운다. `removed`에는 `속성 style의 {선언 이름}(바깥 주소)`를 적는다.
- 그 밖의 속성: 값에 `hasExternalUrl`이 참이면 속성을 지우고 `removed`에 `속성 {이름}(바깥 주소)`를 적는다.
- 안쪽 참조는 남아야 한다. `fill="url(#paint0_linear)"`, `style="fill:url('#a')"`, `filter="url(#f)"`가 그대로 남는지 시험으로 고정한다(피그마의 그라데이션, 마스크, 필터가 이 꼴이다).
- `style` 요소 규칙(117줄)과 `on*`·`href` 규칙은 바꾸지 않는다.

#### 검증 함수 (`validateTemplate.ts`, 새 파일)
- `validateTemplateSvg(svgText: unknown)`는 `{ ok: true, svg, removed, slots } | { ok: false, error }`를 돌려준다. 예외를 던지지 않는다.
- 순서와 문구:
  1. 문자열이 아니거나 비어 있음 → «SVG 내용이 비어 있어요. 피그마에서 내보낸 SVG를 올려 주세요.»
  2. `TEMPLATE_SVG_MAX_BYTES` 초과 → «SVG가 너무 커요. 1MB 이하로 줄여서 다시 올려 주세요.» 바이트 수는 `new TextEncoder().encode(svgText).length`로 센다(브라우저에서도 돌아야 하므로 `Buffer`를 쓰지 않는다).
  3. `TemplateSvgError` → «SVG를 읽지 못했어요. 피그마에서 SVG로 다시 내보내 주세요.»
  4. 자리 없음(`found: false`) → «{이름|값} 자리를 찾지 못했어요. 피그마에서 {이름|값} 글자의 레이어 이름을 {name|value}로 바꾸고, 내보내기 설정의 Include "id" attribute를 켠 뒤 다시 내보내 주세요.»
  5. 글자가 아님(`isText: false`) → «{이름|값} 자리가 글자가 아니에요. 피그마 내보내기 설정의 Outline text를 끄고 다시 내보내 주세요.»
- 이 모듈과 `templateSvg.ts`, `templateItem.ts`는 화면(클라이언트)에서도 불러 쓴다. 서버 전용 모듈(`@/lib/supabase/server`, `next/headers` 등)을 들여오지 않는다.
- `[classKey]/route.ts`의 PUT은 34~67줄을 이 함수 호출로 바꾼다. `ok: false`면 그 `error`로 400을 돌려준다. 본문을 JSON으로 읽지 못했을 때의 400과 분류가 틀렸을 때의 400은 그대로 둔다.
- 4·5번 문구가 3-1과 달라진다. `route.test.ts`의 단언이 옛 문구에 묶여 있으면 새 문구에 맞게 고친다.
- `TemplateItem.slots`의 타입을 `TemplateSlots | null`로 좁힌다(`templateSvg.ts`의 `TemplateSlots`). `toTemplateItem`의 변환도 맞춘다.

#### 화면
- `page.tsx`는 서버 컴포넌트다. `createServiceClient()`로 `activity_badge_templates`를 읽고(`class_key, svg, slots, updated_at, updated_by`), `TEMPLATE_CLASS_KEYS` 순서로 `toTemplateItem`을 거쳐 `<TemplateManager initial={…} />`에 넘긴다. 조회 오류는 `ranking-modes/page.tsx`처럼 `throwOnQueryError`로 넘긴다. 권한은 `src/app/admin/layout.tsx`가 공용으로 확인하므로 페이지에서 다시 확인하지 않는다.
- `TemplateManager.tsx`는 클라이언트 컴포넌트다. 분류별 항목과 «저장 전 확인» 상태, 진행 중 여부를 들고 있고, 카드 4개를 그린다.
  - 파일을 고르면 `file.text()`로 읽어 `validateTemplateSvg`에 넣는다. 통과하면 그 분류를 «저장 전 확인» 상태(`ready`)로, 실패하면 오류 상태(`invalid`)로 둔다. 아직 서버에 보내지 않는다.
  - «저장»을 누르면 원본 SVG 글자를 `PUT /api/admin/activity-badge-templates/{classKey}`에 `{ svg }`로 보낸다. 성공하면 응답의 `template`으로 그 분류의 항목을 바꾸고 확인 상태를 비운다. 실패하면 응답의 `error`를 `toast.error`로 보인다.
  - «지우기»는 확인 대화상자를 거쳐 `DELETE`를 보낸다. 성공하면 그 분류를 빈 항목으로 바꾼다.
- `TemplateCard.tsx`는 표시만 한다. 상태와 동작은 모두 props로 받는다(`item`, `pending`, `busy`, `onPickFile`, `onSave`, `onCancel`, `onDelete`). 같은 파일에서 순수 함수 `svgToDataUrl(svg)`(`data:image/svg+xml;charset=utf-8,` + `encodeURIComponent`)과 `describeSlot(slot)`(아래 «자리 줄»의 글자를 만든다)을 내보낸다.
- 템플릿은 `<img src={svgToDataUrl(svg)}>`로만 그린다. SVG를 문서에 직접 끼워 넣지 않는다(`dangerouslySetInnerHTML` 금지. PRD 17.3의 약속이다).

### UI/UX 관점 (해당 시)
어드민 화면이라 shadcn/ui(`@/components/admin/ui`)를 쓴다. 네이티브 `select`나 `confirm()`을 쓰지 않는다. 문구는 아래를 그대로 쓴다.

**페이지 머리** (`badge-metric-labels/page.tsx`와 같은 틀)
- 제목: 액티비티 배지 템플릿
- 설명: 분류마다 템플릿 SVG를 한 장씩 올려요. 배지를 만들 때 그 배지가 속한 분류의 템플릿이 자동으로 쓰여요

**안내 상자** (`alert`, 카드 위)
- 제목: 피그마에서 내보내는 방법
- 1. 이름 글자의 레이어 이름은 name, 값 글자의 레이어 이름은 value로 지어 주세요.
- 2. 내보내기 설정에서 Include "id" attribute를 켜고 Outline text를 꺼 주세요.
- 3. 형식을 SVG로 골라 내보낸 뒤 여기에 올려 주세요. 1MB까지 올릴 수 있어요.

**카드** (`card`, 분류 순서대로 4개. 넓은 화면에서는 2열)
- 머리: 분류 이름(`item.label`)과 상태 배지 «등록됨» 또는 «없음»
- 값의 예 한 줄: 운동 수치 «값의 예: 21.1km, 1,947m, 1시간 30분» / 쌓은 날 «값의 예: 100일, 5주, 3년» / 이어 온 날 «값의 예: 14일 연속, 4주 연속, 7일 만에» / 횟수와 양 «값의 예: 5회, 50개, 잼 1,250, 챕터 10»
- 미리보기: 정사각 영역(`bg-muted`)에 이미지. `alt`는 «{분류} 템플릿 미리보기». 템플릿이 없으면 «아직 템플릿이 없어요». 이미지 아래에 작은 글씨로 «미리보기의 글자는 이 컴퓨터에 설치된 글꼴로 보여요.»
- 자리 줄(등록됨일 때): «이름 자리», «값 자리», «크기» 세 줄. 자리 줄의 값은 `describeSlot`이 만든다: `“{placeholder}” · {fontFamily} · {fontSize}px · {fill}`에서 값이 없는 조각은 뺀다. 크기는 `{viewBoxWidth} × {viewBoxHeight}`, 없으면 줄을 뺀다.
- 수정 정보(등록됨일 때): `{formatKstYmdHm(updatedAt)} · {updatedBy}`
- 버튼: 템플릿이 없으면 «SVG 올리기», 있으면 «바꾸기»와 «지우기». 파일 선택은 숨긴 `<input type="file" accept=".svg,image/svg+xml">`을 버튼으로 연다.

**저장 전 확인 상태** (`pending.kind === 'ready'`. 카드의 미리보기와 자리 줄이 새 파일의 것으로 바뀐다)
- 머리말: 저장하기 전에 확인해 주세요 (그 아래 파일 이름)
- 걷어 낸 것이 있으면: «안전을 위해 {n}가지를 걷어 냈어요»와 그 목록
- 버튼: «저장», «취소»

**오류 상태** (`pending.kind === 'invalid'`)
- `alert`(destructive)에 검증 문구를 보인다. 버튼은 «다른 파일 고르기», «취소». 기존에 등록된 템플릿의 미리보기와 자리 줄은 그대로 둔다.

**지우기 확인** (`alert-dialog`)
- 제목: {분류} 템플릿을 지울까요?
- 설명: 이미 등록한 배지 이미지는 그대로 남아요. 이 분류의 배지는 템플릿을 다시 올릴 때까지 새로 만들 수 없어요.
- 버튼: «지우기», «취소»

**알림** (`toast`)
- «{분류} 템플릿을 저장했어요.» / «{분류} 템플릿을 지웠어요.»
- 실패: 서버 응답의 `error`. 없으면 «템플릿을 저장하지 못했어요. 잠시 후 다시 시도해 주세요.» / «템플릿을 지우지 못했어요. 잠시 후 다시 시도해 주세요.»
- 진행 중(`busy`)에는 그 카드의 버튼을 모두 비활성으로 둔다.

**메뉴**
- `adminNavItems.ts`의 «디자인» 묶음, «액티비티 배지» 바로 아래에 `{ href: '/admin/activity-badge-template', label: '배지 템플릿', icon: IconTemplate }`을 더한다. 기존 «액티비티 배지» 항목은 그대로 둔다(7회차에서 정리한다).

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- 정화: `style="fill:url(https://a.example/x.png);stroke:#000"`은 `stroke:#000`만 남고 `removed`에 기록된다. `fill="url(https://a.example/x)"`는 속성이 없어진다. `fill="url(#paint0_linear)"`, `style="fill:url('#a')"`, `filter="url(#f)"`는 그대로 남는다. 재현 경로: `cd jam-web && npx vitest run src/lib/admin/activityBadgeTemplate`.
- 검증 함수: 위 다섯 경우마다 적힌 문구가 나오고, 정상 SVG는 `ok: true`와 `svg`·`removed`·`slots`가 나온다. 예외를 던지지 않는다.
- API: PUT이 `validateTemplateSvg`를 쓰고, `npx vitest run src/app/api/admin/activity-badge-templates`가 통과한다.
- 카드: 등록됨, 없음, 저장 전 확인, 오류의 네 상태에서 위 문구와 버튼이 나온다. 이미지의 `src`가 `data:image/svg+xml`로 시작하고, 템플릿 SVG의 본문이 마크업에 날것으로 들어가지 않는다(시험용 SVG에 표식 글자를 넣어 확인한다). 재현 경로: `npx vitest run src/app/admin/activity-badge-template`.
- 메뉴: «디자인» 묶음의 순서가 체크인 배지, 액티비티 배지, 배지 템플릿, 에셋, 이미지 생성이다.
- `validateTemplate.ts`, `templateSvg.ts`, `templateItem.ts`, `TemplateCard.tsx`, `TemplateManager.tsx`가 서버 전용 모듈을 들여오지 않는다.
- PRD 17절이 갱신돼 있다.
- 리뷰 브랜치의 CI verify가 success다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤, push 전)
- 로컬 어드민(`ADMIN_EMAILS` 셸 변수)에서 `/admin/activity-badge-template`을 열어 실제로 그려지는지 확인한다. 시험용 SVG를 올려 저장 전 확인, 저장, 바꾸기, 지우기를 눌러 본다. 시험으로 넣은 템플릿은 확인 뒤 지운다(공용 DB라 프로덕션의 표에 그대로 들어간다).
- 아현과 민지는 격리 워크트리에서 화면 실렌더를 시도하지 않는다.

### 주요 의사결정 / 핵심 메모
- 새 화면의 경로를 `/admin/activity-badge-template`으로 따로 둔 까닭: 4~6회차의 제작 화면도 이 경로에 얹어 만들고, 기존 `/admin/activity-badge-image`는 7회차에서 한꺼번에 바꾼다. 그동안 기존 화면은 그대로 쓸 수 있다.
- 올리자마자 저장하지 않고 «저장 전 확인»을 둔 까닭: 이미 등록된 템플릿을 잘못 고른 파일로 덮어쓰는 일을 막고, 자리 인식 결과를 저장 전에 보여 주기 위해서다. 검증을 브라우저에서 먼저 하려고 검증 함수를 서버와 화면이 함께 쓰는 순수 모듈로 뺐다.
- 규모: 파일 14개, 600줄 안팎으로 `plan_only` 기준을 넘는다. 둘로 더 쪼개면 화면 없는 조각이 다시 생겨 화면 확인이 한 회차 더 늦어지므로, 파일 단위 계획을 적고 면제를 넘긴다.
- 미리보기는 SVG를 이미지로 그리므로 SVG 안의 글자가 웹 글꼴을 불러오지 못한다. 이 컴퓨터에 설치된 글꼴로만 보인다. 실제 배지의 글자는 제작 화면(4회차)이 캔버스에 따로 그린다.
