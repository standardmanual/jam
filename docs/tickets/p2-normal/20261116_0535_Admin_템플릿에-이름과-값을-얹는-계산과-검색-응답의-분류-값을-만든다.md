# [Admin] 템플릿에 이름과 값을 얹는 계산과 검색 응답의 분류·값을 만든다

## 핵심 요약
- 요구사항: 제작 화면(다음 티켓)이 쓸 바탕을 만든다. ① 템플릿 SVG에서 이름 자리와 값 자리의 예시 글자를 걷어 내는 함수 ② 자리 정보를 캔버스 글자 설정으로 바꾸는 계산(글꼴 대응, 가운데 맞춤, 넘치면 줄이기) ③ 배지 검색 응답에 분류와 값 싣기. 화면은 만들지 않는다(상위 티켓 20261115_2353의 4회차 가운데 첫 부분).
- 구현 계획: 모두 순수 함수로 만들고 시험으로 고정한다. 캔버스에 실제로 그리는 일과 화면은 다음 티켓에서 한다.
- 관련 파일:
  - 새 파일 `jam-web/src/lib/admin/activityBadgeTemplate/composeTemplate.ts`, `__tests__/composeTemplate.test.ts`
  - 새 파일 `jam-web/src/lib/admin/activityBadgeTemplate/studioBadge.ts`, `__tests__/studioBadge.test.ts`
  - `jam-web/src/app/api/admin/activity-badge-image/search/route.ts`: `BadgeRow`(35~44줄), select 문자열(58줄), 응답 매핑(86~97줄)
  - 읽기만: `jam-web/src/lib/admin/activityBadgeTemplate/templateSvg.ts`(`TemplateSlot`, `TemplateSlots`, `TemplateSvgError`, `parseSvg`와 `findById`·`findFirst`는 내보내지 않은 내부 함수다), `resolveTemplateText.ts`(168줄 `resolveBadgeTemplateText`, 9줄 `BADGE_TEMPLATE_CLASS_LABEL`), `jam-web/src/lib/asset-generator/render.ts`(271줄 `TextLayerRenderInput`, 303줄 `drawTextLayer`), `jam-web/src/lib/asset-generator/types.ts`(`TextLayerFont`), `jam-web/src/lib/admin/googleFonts.ts`(19줄 `GOOGLE_FONT_CATALOG`), `jam-web/src/app/admin/asset-generator/assetGeneratorHelpers.ts`(211줄 `SYSTEM_DEFAULT_FONT`)

## 배경 / 문제 정의
제작 화면은 배지를 고르면 그 분류의 템플릿 위에 이름과 값을 그린다. 그리려면 세 가지가 먼저 있어야 한다.

- 템플릿에는 디자이너가 넣어 둔 예시 글자(«배지 이름», «21.1km»)가 있다. 실제 이름과 값을 그리기 전에 이 글자를 걷어 내야 한다.
- 피그마는 글자의 왼쪽 시작점만 SVG에 남기고 가운데 정렬 정보는 남기지 않는다(티켓 20261116_0234의 메모). 예시 글자의 폭으로 가운데를 되찾아야 한다.
- 검색 응답에는 배지의 획득 조건이 없어서 화면이 분류와 값을 알 수 없다.

글자는 기존 에셋 제너레이터의 `drawTextLayer`로 그린다(상위 티켓의 결정: 기존 기능 재사용). 이 함수는 위치와 크기를 스테이지 대비 비율로 받고, 세로 위치를 글자 높이의 가운데(`textBaseline: 'middle'`)로 받는다. SVG는 글자의 기준선 위치를 주므로 변환이 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### `composeTemplate.ts` (순수 모듈. 서버·브라우저·시험에서 함께 돈다)
- `stripSlotText(svgText)`: 이름 자리와 값 자리의 `text` 요소를 통째로 지운 SVG 글자를 돌려준다. `id`가 `g`에 있으면 그 안의 첫 `text`를 지운다. 자리가 없으면 다른 것은 건드리지 않는다. 읽지 못하면 `TemplateSvgError`를 던진다. `@xmldom/xmldom`으로 읽고 쓴다. `templateSvg.ts`의 내부 함수가 필요하면 그 파일에서 내보내 쓴다(같은 로직을 다시 만들지 않는다).
- `parseFontWeight(v)`: `'bold'` → 700, `'normal'` → 400, 숫자 글자 → 100~900 범위에서 100 단위로 맞춘 값, 그 밖과 `null` → 400.
- `parseLetterSpacingEm(v, fontSize)`: `'0em'` → 0, `'-0.02em'` → -0.02, `'2px'`나 `'2'`는 `fontSize`로 나눈 값(`fontSize`가 없거나 0이면 0), `null` → 0.
- `resolveTemplateFont(slot)`: `{ font: TextLayerFont, requestedFamily: string | null, fallback: boolean }`을 돌려준다. `fontFamily`의 첫 항목(쉼표 앞, 따옴표 제거)을 `GOOGLE_FONT_CATALOG`에서 대소문자를 가리지 않고 찾는다. 있으면 카탈로그의 표기를 쓰고 `fallback: false`다. 없거나 `fontFamily`가 `null`이면 `SYSTEM_DEFAULT_FONT.family`를 쓰고 `fallback: true`다. 굵기는 `parseFontWeight(slot.fontWeight)`다.
- `layoutSlotText({ slot, viewWidth, placeholderWidth, contentWidth })`: `{ anchorX, fontSizePx, shrunk } | null`을 돌려준다. 단위는 SVG의 viewBox 단위다. 폭 두 개는 자리의 원래 글자 크기로 잰 값이고, 재는 일은 호출하는 쪽(다음 티켓의 캔버스 코드)이 한다.
  - `slot.x`나 `slot.fontSize`가 없으면 `null`이다.
  - 가운데 기준 `anchorX`: `textAnchor`가 `'middle'`이면 `x`, `'end'`면 `x - placeholderWidth / 2`, 그 밖(피그마의 기본)이면 `x + placeholderWidth / 2`다.
  - 넘치면 줄이기: `maxWidth = 2 × min(anchorX, viewWidth - anchorX) × 0.92`다. `maxWidth`가 0보다 크고 `contentWidth`가 그보다 크면 `fontSizePx = slot.fontSize × maxWidth / contentWidth`, `shrunk: true`다. 아니면 원래 크기 그대로다.
- `toTextLayerInput({ content, font, color, letterSpacingEm, layout, baselineY, middleOffsetEm, viewWidth, viewHeight, stageWidth, stageHeight })`: `TextLayerRenderInput`을 돌려준다.
  - `sizePct = layout.fontSizePx / min(viewWidth, viewHeight) × 100`
  - `xPct = layout.anchorX / viewWidth × 100`
  - `yPct = (baselineY - middleOffsetEm × layout.fontSizePx) / viewHeight × 100` (`middleOffsetEm`은 기준선에서 글자 상자 가운데까지의 거리를 글자 크기로 나눈 값이다. 호출하는 쪽이 캔버스에서 잰다)
  - `align: 'center'`, `lineHeight: 1`, `rotationDeg: 0`, `opacityPct: 100`, `letterSpacing: letterSpacingEm`, `color`가 `null`이면 `'#000000'`

#### `studioBadge.ts`와 검색 응답
- `toStudioBadgeFields(row)`: 입력은 배지 행의 `condition_json`, `is_hidden`, `family_key`다. `resolveBadgeTemplateText`로 판정해 `{ templateClass, templateClassLabel, templateValue, familyKey }`를 돌려준다. 판정하지 못하면 앞의 셋이 `null`이다.
- `search/route.ts`: select에 `condition_json, is_hidden, family_key`를 더하고, 응답의 각 항목에 `toStudioBadgeFields(row)`의 네 칸을 더한다. 기존 칸과 기존 화면(`/admin/activity-badge-image`)의 동작은 바꾸지 않는다.

## 구현 계획
1. `composeTemplate.ts`와 시험을 만든다. 시험의 SVG는 `templateSvg.test.ts`와 같은 피그마 모양을 쓴다.
2. `studioBadge.ts`와 시험을 만든다.
3. `search/route.ts`에 칸을 더한다.
4. PRD는 이 티켓에서 고치지 않는다(화면이 생기는 다음 티켓에서 17절에 더한다).

## 완료 조건
- `stripSlotText`: 피그마 모양 SVG를 넣으면 결과에 예시 글자(«배지 이름», «21.1km»)와 `id="name"`·`id="value"`의 `text`가 없고, `rect`와 `defs`는 남는다. `g`로 감싼 글자도 지워진다. 자리가 없는 SVG는 도형이 그대로다. 재현 경로: `cd jam-web && npx vitest run src/lib/admin/activityBadgeTemplate`.
- `resolveTemplateFont`: `IBM Plex Sans KR`는 `fallback: false`, `Pretendard`는 `fallback: true`와 `SYSTEM_DEFAULT_FONT.family`, `'Inter', sans-serif`는 `Inter`가 나온다. `font-weight="bold"`는 700이다.
- `layoutSlotText`: `x: 352, fontSize: 64`, `placeholderWidth: 320`, `viewWidth: 1024`면 `anchorX`가 512다. `contentWidth: 1200`이면 `fontSizePx`가 `64 × 942.08 / 1200`이고 `shrunk: true`다. `contentWidth: 600`이면 64 그대로다. `textAnchor: 'middle'`이면 `anchorX`가 `x`다.
- `toTextLayerInput`: 위 계산식대로 `sizePct`, `xPct`, `yPct`가 나온다(숫자 예를 시험에 적는다).
- `toStudioBadgeFields`: `{ single_distance_km: 21.1 }`은 `metric`, «운동 수치», «21.1km»다. 규칙에 없는 조건은 세 칸이 `null`이다.
- 검색 응답의 항목에 네 칸이 들어 있고 기존 칸이 그대로다.
- 새 모듈이 서버 전용 모듈을 들여오지 않는다.
- 리뷰 브랜치의 CI verify가 success다.

- 4회차를 둘로 나눈 까닭: 계산과 화면을 한 티켓에 넣으면 파일이 13개를 넘고, 글자 위치 계산은 시험으로 먼저 고정해 두는 편이 화면 확인 때 원인을 가리기 쉽다.
