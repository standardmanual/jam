## 배경 / 문제 정의
템플릿을 올리는 화면(3-2)과 이름·값을 얹는 계산(4-1)이 있다. 이제 운영자가 배지를 골라 결과를 눈으로 보는 화면이 필요하다. 이 화면이 사용자가 정한 흐름의 중심이다: 배지 검색 → 선택 → 분류의 템플릿 자동 적용 → 이름과 값이 지정 자리에 표시.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 그리기 (`renderTemplateBadge.ts`, 브라우저 전용)
- `renderTemplateBadge(canvas, { svg, slots, name, value, longSidePx })`는 `Promise<{ fontFallbacks, shrunk, skipped }>`를 돌려준다. 세 칸은 각각 자리 이름(`'name' | 'value'`)의 목록이다(`fontFallbacks`는 `{ slot, requestedFamily }`의 목록).
- 순서:
  1. `stripSlotText(svg)`로 예시 글자를 걷어 낸 SVG를 `svgToDataUrl`로 이미지에 실어 불러온다.
  2. 캔버스 크기를 정한다. 비율은 `slots.viewBoxWidth`·`viewBoxHeight`를 따르고(없으면 불러온 이미지의 크기), 긴 변이 `longSidePx`다.
  3. 캔버스를 비우고 이미지를 캔버스 전체에 그린다.
  4. 이름 자리와 값 자리를 차례로 그린다. 자리마다:
     - `resolveTemplateFont(slot)`으로 글꼴을 정하고 `loadFontInBrowser`로 불러온다. 불러오기가 실패하면 `SYSTEM_DEFAULT_FONT.family`로 바꾸고 `fontFallbacks`에 적는다. `resolveTemplateFont`가 `fallback: true`를 준 경우도 적는다.
     - 자리의 원래 글자 크기(viewBox 단위 그대로)로 `ctx.font`를 잡고 폭을 잰다. 폭은 `drawTextLayer`와 같은 방식으로 글자 하나씩 재서 더하고, 글자 사이마다 `자간(em) × 글자 크기`를 더한다. 예시 글자(`slot.placeholder`, 없으면 빈 글자)와 넣을 글자를 각각 잰다.
     - `layoutSlotText`가 `null`을 주면 그 자리는 그리지 않고 `skipped`에 적는다. `shrunk`가 참이면 `shrunk`에 적는다.
     - 기준선에서 글자 상자 가운데까지의 거리(`middleOffsetEm`)를 잰다. `textBaseline`을 `'alphabetic'`으로 두고 `measureText('가')`의 `emHeightAscent`·`emHeightDescent`가 있으면 `(ascent - descent) / 2 / 글자 크기`, 없고 `fontBoundingBoxAscent`·`fontBoundingBoxDescent`가 있으면 같은 식, 둘 다 없으면 0.35를 쓴다.
     - `toTextLayerInput(...)`의 결과로 `drawTextLayer`를 부른다. `stageWidth`·`stageHeight`는 캔버스의 크기다.
- 같은 캔버스에 그리기가 겹치지 않게 한다. 배지를 빠르게 바꿔 고르면 마지막 요청의 결과만 남아야 한다(요청 번호를 두고, 기다린 뒤 번호가 바뀌었으면 그리지 않는다).

#### 화면 구성
- `page.tsx`: 지금처럼 서버에서 템플릿 네 개를 읽어 `<TemplateWorkspace initial={items} />`에 넘긴다. 설명 문구를 아래 것으로 바꾼다.
- `TemplateWorkspace.tsx`(클라이언트): 템플릿 항목(`items`)을 상태로 들고, 탭 두 개를 그린다. «배지 만들기»에는 `<BadgeStudio templates={items} onGoToTemplates={…} />`, «템플릿»에는 `<TemplateManager items={items} onItemsChange={setItems} />`를 둔다. 템플릿 탭에서 올리거나 지운 결과가 새로 고침 없이 «배지 만들기»에 반영돼야 한다.
- `TemplateManager.tsx`: 자기 상태로 들던 `items`를 props(`items`, `onItemsChange`)로 받게 바꾼다. 동작과 문구는 그대로다.
- `BadgeStudio.tsx`(클라이언트): 검색 조건, 결과, 고른 배지를 들고 `BadgePicker`와 `BadgePreview`를 그린다. 검색은 기존 `POST /api/admin/activity-badge-image/search`를 쓴다(요청 본문과 페이지 넘김은 옛 화면의 `runSearch`와 같다). 응답 항목에서 `id`, `name`, `rarity`, `level`, `leveled`, `activityTypes`, `hasImage`와 4-1이 더한 `templateClass`, `templateClassLabel`, `templateValue`, `familyKey`를 쓴다.
- `BadgePicker.tsx`(표시 전용): 검색 카드와 결과 표. 옛 화면의 검색 카드(이름 입력, 종류·등급·활동 종목 고르기, 검색 버튼)와 결과 표(페이지 넘김 포함)를 본보기로 옮긴다. 옛 화면의 파일은 고치지 않는다(7회차에서 지운다). 선택지 상수는 새 파일에 다시 둔다.
- `BadgePreview.tsx`(클라이언트): 고른 배지와 템플릿으로 아래 상태 가운데 하나를 그린다. 정상 상태에서는 `<canvas>`를 두고 `useEffect`에서 `renderTemplateBadge`를 `longSidePx: 1024`로 부른다.

#### 3-2의 범위 밖 발견물
- `validateTemplateSvg`: 지금은 자리마다 «없음 → 글자 아님»을 이어서 검사해, 이름 자리가 글자가 아닐 때 값 자리가 없다는 사실보다 먼저 알린다. 두 자리의 «없음»을 먼저 검사하고 그다음에 «글자 아님»을 검사하게 바꾼다. 시험에 이 순서를 고정한다(이름은 윤곽선이고 값 자리는 없는 SVG → «값 자리를 찾지 못했어요…»).
- 지우기 확인 창: 닫히는 0.2초 동안 제목의 분류 이름이 먼저 비워진다. 창의 열림 여부와 지울 대상을 따로 들어, 닫히는 동안에도 이름이 남게 한다.

### UI/UX 관점 (해당 시)
어드민 화면이라 shadcn/ui(`@/components/admin/ui`)를 쓴다. 문구는 아래를 그대로 쓴다.

**페이지 머리**
- 제목: 액티비티 배지 템플릿 (그대로)
- 설명: 배지를 고르면 그 배지가 속한 분류의 템플릿에 이름과 값이 자동으로 들어가요

**탭**: «배지 만들기»(기본), «템플릿»

**검색 카드** (옛 화면과 같은 구성)
- 제목: 배지 검색
- 설명: 액티비티 배지만 검색해요. 이름이 같은 배지는 등급·레벨과 값을 확인하고 골라 주세요
- 입력 자리 표시: 배지 이름 검색 (예: 저녁)
- 고르기: «전체 종류», «전체 등급»(종류가 레벨형이면 감춘다), «전체 활동 종목»
- 버튼: «검색», 검색하는 동안 «검색 중…»
- 검색 실패: 서버 응답의 `error`. 없으면 «배지를 검색하지 못했어요. 잠시 후 다시 시도해 주세요.»

**결과 표**
- 제목: 검색 결과 {n}건
- 열: 배지 이름 / 등급 · 레벨(`slotLabelOf`) / 분류(`templateClassLabel`, 없으면 «없음») / 값(`templateValue`, 없으면 «-») / 이미지(«있음» 또는 «없음») / 선택(버튼 «선택»)
- 결과 없음: 검색 결과가 없어요
- 페이지 넘김: «이전», «{현재} / {전체}», «다음»

**미리보기 카드**
- 제목: 미리보기
- 배지를 고르기 전: 배지를 검색해서 골라 주세요
- 고른 배지 머리: 배지 이름, 등급·레벨 칩, 분류 칩
- 분류를 정하지 못한 배지(`templateClass`가 없음): «이 배지는 분류를 정하지 못했어요. 획득 조건이 템플릿 규칙에 없는 종류예요. 규칙을 더해야 하니 개발 요청을 남겨 주세요.»
- 그 분류의 템플릿이 없음: «{분류} 템플릿이 아직 없어요. 템플릿 탭에서 SVG를 올려 주세요.»와 버튼 «템플릿 탭으로 가기»(누르면 «템플릿» 탭으로 바뀐다)
- 정상: 캔버스(화면에서는 최대 폭 480px)와 그 아래 세 줄 «이름», «값», «분류»
- 정상 상태의 안내(해당할 때만, 작은 글씨):
  - 글꼴을 찾지 못함: «{이름|값} 자리의 글꼴 {글꼴 이름}를 구글 폰트에서 찾지 못해 기본 글꼴로 보여요.» (글꼴 이름이 없으면 «{이름|값} 자리에 글꼴 정보가 없어 기본 글꼴로 보여요.»)
  - 줄임: «{이름|값}이 길어서 글자 크기를 줄였어요.»
  - 그리지 못한 자리: «{이름|값} 자리의 위치를 읽지 못해 글자를 그리지 못했어요. 템플릿을 다시 올려 주세요.»
- 그리기 실패(예외): «미리보기를 그리지 못했어요. 템플릿을 다시 올린 뒤 시도해 주세요.»

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- 검사 순서: 이름은 윤곽선이고 값 자리는 없는 SVG를 넣으면 «값 자리를 찾지 못했어요…»가 나온다. 재현 경로: `cd jam-web && npx vitest run src/lib/admin/activityBadgeTemplate`.
- 표시 시험: `BadgePreview`가 배지 선택 전, 분류 없음, 템플릿 없음, 정상의 네 상태에서 위 문구를 낸다. `BadgePicker`가 결과 표의 열과 «없음»·«-» 표기를 낸다. 재현 경로: `npx vitest run src/app/admin/activity-badge-template`.
- `TemplateManager`가 `items`와 `onItemsChange`로 동작하고, 기존 `TemplateCard` 시험이 통과한다.
- `renderTemplateBadge.ts`가 4-1의 함수와 `drawTextLayer`, `loadFontInBrowser`를 쓰고, 글자 위치 계산을 다시 만들지 않는다.
- 옛 화면(`src/app/admin/activity-badge-image/`)의 파일은 바뀌지 않는다.
- PRD 17.5가 있다.
- 리뷰 브랜치의 CI verify가 success다.

### 후속 범위 (담당: 카리나, 시점: 게이트 통과 뒤 머지 전후)
- 로컬 어드민 실렌더: 시험용 SVG를 운동 수치에 올리고 «트럭 꽁무니를 따라 뛴 저녁»을 골라 값 자리에 «21.1km»가 보이는지 확인한다(상위 티켓의 완료 조건).

- 아현과 민지는 격리 워크트리에서 화면 실렌더를 시도하지 않는다.

### 주요 의사결정 / 핵심 메모
- 검색은 옛 화면의 검색 API를 그대로 쓴다. 옛 화면을 지우는 7회차에서 이 API의 경로를 정리한다.
- 검색 카드와 결과 표를 옛 화면에서 공용 컴포넌트로 빼내지 않고 새 파일로 옮겨 적은 까닭: 옛 화면은 7회차에서 통째로 지우므로, 지금 옛 파일을 고치면 지울 코드를 손보는 셈이 된다.
- 규모: 파일 11개, 700줄 안팎으로 `plan_only` 기준을 넘는다. 계산은 4-1로 이미 떼어 냈고, 남은 것은 서로 물려 있는 화면 조각이라 파일 단위 계획을 적고 면제를 넘긴다.
