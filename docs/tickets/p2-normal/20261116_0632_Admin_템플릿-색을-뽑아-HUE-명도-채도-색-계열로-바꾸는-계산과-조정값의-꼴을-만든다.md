# [Admin] 템플릿 색을 뽑아 HUE·명도·채도·색 계열로 바꾸는 계산과 조정값의 꼴을 만든다

## 핵심 요약
- 요구사항: 제작 화면의 조정 패널(다음 티켓)이 쓸 바탕을 만든다. ① 템플릿 SVG에 쓰인 색을 뽑는 함수 ② HUE·채도·명도 조정과 색 계열 변경, 색 칸 하나씩 바꾸기를 SVG에 적용하는 함수 ③ 색과 글자의 조정값을 담는 꼴과 그 검증. 화면은 만들지 않는다(상위 티켓 20261115_2353의 5회차 가운데 첫 부분).
- 구현 계획: 모두 순수 함수로 만들고 시험으로 고정한다.
- 관련 파일:
  - 새 파일 `jam-web/src/lib/admin/activityBadgeTemplate/templateColors.ts`, `__tests__/templateColors.test.ts`
  - 새 파일 `jam-web/src/lib/admin/activityBadgeTemplate/templateParams.ts`, `__tests__/templateParams.test.ts`
  - 읽기만: `jam-web/src/lib/admin/activityBadgeTemplate/templateSvg.ts`(내보낸 `parseSvg`, `TemplateSlot`, `TemplateSlotName`, `TEMPLATE_SLOT_NAMES`, `TemplateSvgError`), `composeTemplate.ts`(`stripSlotText`가 SVG를 읽고 다시 쓰는 방식, `parseFontWeight`)

## 배경 / 문제 정의
사용자가 반드시 넣으라고 정한 기능이다(상위 티켓 「결정 사항」): 템플릿 색의 HUE·명도·채도 조정과 색 계열 변경, 값 글자의 색과 글꼴 변경. 저장소에는 SVG의 색을 뽑거나 바꾸는 코드가 없다(상위 티켓 「재사용 지도」의 조사 결과). 조정값은 6회차에서 배지의 `image_gen_params`에 저장해 다시 열 수 있어야 하므로, 꼴과 검증을 여기서 먼저 정한다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### `templateColors.ts` (순수 모듈. 서버·브라우저·시험에서 함께 돈다)
- 색을 읽는 속성: `fill`, `stroke`, `stop-color`, `flood-color`, `lighting-color`, `color`. 요소의 속성과 `style` 속성 안의 같은 이름 선언을 모두 본다.
- `parseSvgColor(value)`: 대문자 `#RRGGBB`를 돌려준다. `#RGB`, `#RRGGBB`, `#RRGGBBAA`(뒤의 투명도 두 자리는 떼고 읽는다), `rgb(r, g, b)`와 `rgb(r g b)`, 이름 `white`·`black`을 읽는다. `none`, `currentColor`, `transparent`, `inherit`, `url(...)`, 그 밖의 이름과 읽지 못하는 값은 `null`이다.
- `extractSvgColors(svgText)`: `{ color, count }[]`를 처음 나온 순서로 돌려준다. `count`는 그 색이 쓰인 횟수다. 읽지 못하는 SVG는 `TemplateSvgError`를 던진다.
- `hexToHsl(hex)`는 `{ h, s, l }`(h는 0 이상 360 미만, s와 l은 0~1), `hslToHex({ h, s, l })`는 대문자 `#RRGGBB`를 돌려준다.
- `adjustColor(hex, { hueShift, saturation, lightness })`:
  - 색상: `h' = (h + hueShift)`를 0 이상 360 미만으로 접는다.
  - 채도: `saturation`이 0 이상이면 `s' = s + (1 - s) × saturation / 100`, 음수면 `s' = s × (1 + saturation / 100)`.
  - 명도: `lightness`가 0 이상이면 `l' = l + (1 - l) × lightness / 100`, 음수면 `l' = l × (1 + lightness / 100)`.
  - 무채색(`s < 0.02`)은 채도를 올리지 않는다(흰색·검정·회색에 색이 끼지 않게 한다). 명도 조정은 받는다.
- `buildColorMap(colors, { hueShift, saturation, lightness, overrides })`: 원래 색마다 `adjustColor(overrides[색] ?? 색, …)`를 값으로 하는 대응표를 돌려준다. 칸 하나씩 바꾼 색 위에도 전체 조정이 얹힌다.
- `applyColorMap(svgText, map)`: 위 속성과 `style` 선언의 값 가운데, 읽은 색이 대응표에 있는 것만 새 색으로 바꾼 SVG 글자를 돌려준다. `#RRGGBBAA`는 뒤의 두 자리를 그대로 붙인다. 색이 아닌 값(`none`, `url(#…)`)과 다른 속성은 건드리지 않는다.
- 색 계열:
  - `COLOR_FAMILIES`: `{ key, label, hue }` 여덟 개. 빨강 0, 주황 28, 노랑 50, 초록 135, 청록 178, 파랑 215, 보라 270, 분홍 330.
  - `dominantHue(colors)`: `s >= 0.1`이고 `0.05 < l < 0.95`인 색 가운데 `count × s`가 가장 큰 색의 색상을 돌려준다. 같으면 먼저 나온 색, 없으면 `null`이다.
  - `hueShiftForFamily(colors, familyHue)`: 대표 색상을 그 계열의 색상으로 옮기는 `hueShift`를 -180 초과 180 이하로 돌려준다. 대표 색상이 없으면 `null`이다.

#### `templateParams.ts` (순수 모듈)
- 꼴:
  ```ts
  interface TemplateColorParams { hueShift: number; saturation: number; lightness: number; overrides: Record<string, string> }
  interface SlotTextParams { color: string | null; fontFamily: string | null; fontWeight: number | null; sizeScalePct: number }
  interface TemplateBadgeParams { kind: 'activity-template'; v: 1; color: TemplateColorParams; text: Record<TemplateSlotName, SlotTextParams> }
  ```
  글자 칸의 `null`은 «템플릿을 따른다»는 뜻이다.
- `TEMPLATE_PARAM_RANGES`: `hueShift` -180~180, `saturation` -100~100, `lightness` -100~100, `sizeScalePct` 50~200. 모두 1 단위다.
- `DEFAULT_TEMPLATE_BADGE_PARAMS`: 세 색 조정 0, `overrides` 빈 객체, 글자 칸은 모두 `null`과 `sizeScalePct: 100`.
- `parseTemplateBadgeParams(raw)`: `kind`가 `'activity-template'`이고 `v`가 1인 객체만 받아 정리한 값을 돌려주고, 아니면 `null`이다(옛 생성기가 `image_gen_params`에 남긴 값과 가리기 위해서다). 정리: 숫자는 범위로 자르고 정수로 맞춘다. `overrides`는 키와 값이 모두 `parseSvgColor`로 읽히는 것만 대문자로 남긴다. 글자 색은 `parseSvgColor`로 읽히면 그 값, 아니면 `null`. `fontFamily`는 앞뒤 공백을 뗀 비어 있지 않은 글자, 아니면 `null`. `fontWeight`는 100~900의 100 단위 수, 아니면 `null`. 빠진 칸은 기본값으로 채운다.
- `isDefaultTemplateBadgeParams(p)`: 기본값과 같으면 참.
- `styleSlot(slot, p)`: 자리 정보에 글자 조정을 얹은 사본을 돌려준다. `fill`은 `p.color ?? slot.fill`, `fontFamily`는 `p.fontFamily ?? slot.fontFamily`, `fontWeight`는 `p.fontWeight`가 있으면 그 수의 글자, `fontSize`는 `slot.fontSize × p.sizeScalePct / 100`(없으면 `null`). 나머지 칸은 그대로다.

## 완료 조건
- `parseSvgColor`: `#abc` → `#AABBCC`, `#123b2e80` → `#123B2E`, `rgb(18, 59, 46)` → `#123B2E`, `white` → `#FFFFFF`, `none`·`url(#a)`·`currentColor` → `null`. 재현 경로: `cd jam-web && npx vitest run src/lib/admin/activityBadgeTemplate`.
- `extractSvgColors`: `fill`, `stroke`, `stop-color`, `style` 안의 `fill`에 쓰인 색을 처음 나온 순서와 횟수로 돌려준다. `url(#paint0)`과 `none`은 들어가지 않는다.
- `adjustColor`: `#FF0000`에 `hueShift: 120` → `#00FF00`. `saturation: -100` → `#808080`. `lightness: 100` → `#FFFFFF`, `-100` → `#000000`. `#FFFFFF`에 `saturation: 50` → `#FFFFFF`. `hueShift: -30`과 `330`의 결과가 같다.
- `applyColorMap`: 대응표에 있는 색만 바뀌고, `fill="url(#paint0)"`과 `stroke="none"`은 그대로다. `style="fill:#123B2E;stroke:#000"`의 두 색이 각각 바뀐다. `#123B2E80`은 새 색 뒤에 `80`이 붙는다.
- `hueShiftForFamily`: 대표 색상이 150인 색 목록에서 파랑(215)은 65, 빨강(0)은 -150이다. 무채색뿐이면 `null`이다.
- `parseTemplateBadgeParams`: `kind`가 다르거나 `v`가 다르면 `null`. 범위를 넘는 수는 잘리고, 읽지 못하는 색의 `overrides` 항목은 빠진다. 기본값을 넣으면 같은 값이 나오고 `isDefaultTemplateBadgeParams`가 참이다.
- `styleSlot`: `sizeScalePct: 150`이면 `fontSize`가 1.5배, 색과 글꼴이 `null`이면 템플릿의 값 그대로다.
- 새 모듈이 서버 전용 모듈을 들여오지 않는다.
- 리뷰 브랜치의 CI verify가 success다.

### 주요 의사결정 / 핵심 메모
- «색 계열 변경»의 뜻은 카리나의 가정이다. 상위 티켓은 «색 조합을 통째로 바꾸거나 칸 하나씩 바꾼다»고만 적었다. 통째로 바꾸기는 템플릿의 대표 색을 고른 계열의 색상으로 돌리는 것(나머지 색도 같은 각도로 따라 돈다)으로, 칸 하나씩 바꾸기는 `overrides`로 풀었다. 사용자에게 화면으로 보여 주고 확인받는다.
- 채도와 명도를 덧셈이 아니라 «남은 폭의 비율»로 올리고 내리는 까닭: +100에서 완전히 흰색(또는 원색), -100에서 완전히 검정(또는 회색)에 닿고, 중간값에서 색이 한꺼번에 잘리지 않는다.
- 반투명(`fill-opacity`, `opacity`)과 그라데이션의 정지점 위치는 건드리지 않는다. 그라데이션의 색(`stop-color`)은 다른 색과 똑같이 조정된다.
