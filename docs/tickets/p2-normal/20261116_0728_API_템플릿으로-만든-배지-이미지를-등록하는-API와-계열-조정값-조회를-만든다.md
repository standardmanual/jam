# [API] 템플릿으로 만든 배지 이미지를 등록하는 API와 계열·조정값 조회를 만든다

## 핵심 요약
- 요구사항: 제작 화면의 «등록»(다음 티켓)이 쓸 서버 쪽을 만든다. ① 브라우저가 구운 PNG를 받아 긴 변 1280px WebP로 바꿔 저장하고 배지에 반영하는 등록 API ② 검색 API에 계열(`family_key`)로 좁히는 조건과, 배지에 저장된 조정값을 응답에 싣는 일. 화면은 만들지 않는다(상위 티켓 20261115_2353의 6회차 가운데 첫 부분).
- 구현 계획: 에셋 제너레이터 적용 API의 저장 방식(원본 PNG와 WebP를 함께 올리고 `image_url`을 WebP로 바꾼다)을 그대로 따른다.
- 관련 파일:

  - `jam-web/src/app/api/admin/activity-badge-image/search/route.ts`: select 문자열(62줄), 조건(72~78줄), 응답 매핑(90줄부터)
  - `jam-web/src/lib/admin/activityBadgeTemplate/studioBadge.ts`(`StudioBadgeFields`, `toStudioBadgeFields`), `__tests__/studioBadge.test.ts`
  - `docs/service/prd/asset-generator/PRD.md` 17절(17.2의 API 목록에 더한다)
  - 읽기만: `jam-web/src/app/api/admin/asset-generator/apply/route.ts`(206~256줄, PNG를 WebP로 바꿔 두 파일을 올리고 표를 고치는 구간), `jam-web/src/app/api/admin/asset-generator/apply/__tests__/route.test.ts`(sharp는 실제로 돌리고 Supabase와 권한만 흉내 내는 시험의 본보기), `jam-web/src/app/api/admin/activity-badge-image/generate/route.ts`(배지 확인, `after`와 `warmImageVariants`), `jam-web/src/lib/admin/badgeImageWebp.ts`(`convertBadgeImageToWebp`, `BADGE_IMAGE_WEBP_MAX_LONG_SIDE_PX`), `jam-web/src/lib/admin/applyGeneratedImageConstants.ts`(`APPLY_GENERATED_IMAGE_BUCKET`, `MAX_APPLY_IMAGE_BYTES`), `jam-web/src/lib/admin/activityBadgeTemplate/templateParams.ts`(`parseTemplateBadgeParams`), `jam-web/src/lib/admin/contentImageSource.ts`(제작 경로 값 3종)

## 배경 / 문제 정의
제작 화면은 미리보기까지만 된다. 만든 이미지를 배지에 걸려면 저장하는 길이 있어야 한다. 사용자가 정한 것(상위 티켓 「결정 사항」): 등록 규격은 긴 변 1280px, 조정값은 배지의 `image_gen_params`에 저장해 다시 열 수 있게 하고 `image_source`에 제작 경로를 남긴다. 등급마다 값이나 이름만 다른 같은 계열의 단계는 한꺼번에 등록할 수 있어야 하므로, 계열의 단계를 불러오는 길도 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 등록 API `POST /api/admin/activity-badge-templates/register`
- 본문은 `multipart/form-data`다: `badgeId`(글자), `params`(JSON 글자), `image`(PNG 파일).
- 순서와 응답:
  1. `getAdminUser()`가 없으면 403.
  2. 본문을 읽지 못하면 400 «요청 내용을 읽지 못했어요. 다시 시도해 주세요.»
  3. `badgeId`가 없으면 400 «배지를 골라 주세요.»
  4. `params`가 JSON이 아니거나 `parseTemplateBadgeParams`가 `null`을 주면 400 «조정값을 읽지 못했어요. 화면을 새로 고친 뒤 다시 시도해 주세요.»
  5. `image`가 없거나 비었거나 `image/png`가 아니면 400 «PNG 이미지가 없어요. 다시 시도해 주세요.»
  6. `MAX_APPLY_IMAGE_BYTES`를 넘으면 400 «이미지가 너무 커요. 5MB 이하만 등록할 수 있어요.»
  7. sharp로 크기를 읽어 긴 변이 `BADGE_IMAGE_WEBP_MAX_LONG_SIDE_PX`(1280)가 아니면 400 «이미지 크기가 맞지 않아요. 긴 변이 1280px인 이미지만 등록할 수 있어요.» 읽지 못하는 파일도 같은 400이다.
  8. 배지를 찾는다(`type = 'activity'`, `deleted_at IS NULL`). 없으면 404 «액티비티 배지를 찾지 못했어요.»
  9. `convertBadgeImageToWebp`로 바꾸고, `APPLY_GENERATED_IMAGE_BUCKET`의 `badges/activity-template/{id}.png`와 `.webp`에 `upsert: true`로 올린다.
  10. `badges`를 고친다: `image_url`은 WebP의 공개 주소에 `?v={지금 시각}`을 붙인 값, `image_gen_params`는 정리된 조정값, `image_source`는 `'admin-generator'`.
  11. 응답 뒤에 `after(() => warmImageVariants(imageUrl, origin))`으로 변환본을 미리 만든다.
  12. 200 `{ badgeId, badgeName, imageUrl, originalUrl, webpBytes }`.
- 올리기나 표 고치기가 실패하면 500이고 DB 오류 원문은 응답에 싣지 않는다: «이미지를 저장하지 못했어요. 잠시 후 다시 시도해 주세요.», «이미지는 올렸지만 배지에 반영하지 못했어요. 잠시 후 다시 시도해 주세요.»
- 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다(해요체).

#### 검색 API
- `parseActivityBadgeImageSearchParams`가 `familyKey`(비어 있지 않은 글자, 아니면 `null`)를 읽는다. 라우트는 `familyKey`가 있으면 `.eq('family_key', familyKey)`를 더한다. 다른 조건과 함께 걸 수 있다.
- `toStudioBadgeFields`의 입력에 `image_gen_params`를 더하고, 결과에 `templateParams`(`parseTemplateBadgeParams(image_gen_params)`의 값, 없으면 `null`)를 더한다. 라우트의 응답 항목에 이 칸이 실린다.
- 기존 칸과 옛 화면(`/admin/activity-badge-image`)의 동작은 바꾸지 않는다.

## 구현 계획
1. `studioBadge.ts`에 `templateParams`를 더하고 시험을 고친다.
2. `activityBadgeImageSearch.ts`와 `search/route.ts`에 `familyKey`를 더하고 시험을 고친다.
3. `register/route.ts`와 시험을 만든다. 시험은 `asset-generator/apply`의 시험처럼 sharp를 실제로 돌리고(1280×1280 PNG를 sharp로 만들어 넘긴다) Supabase와 권한만 흉내 낸다.
4. PRD 17.2에 등록 API와 검색 응답의 새 칸을 적는다.

## 완료 조건
- 등록 API: 권한이 없으면 403이고 저장소와 DB에 닿지 않는다. 위 3~7번과 8번의 경우마다 적힌 상태 코드와 문구가 나오고 올리지 않는다. 1280×1280 PNG와 기본 조정값을 보내면 PNG와 WebP가 `badges/activity-template/{id}.png|webp`에 올라가고, `badges`가 `image_url`(`.webp?v=`), `image_gen_params`(`kind: 'activity-template'`), `image_source: 'admin-generator'`로 고쳐진다. 1024×1024 PNG는 400이다. 재현 경로: `cd jam-web && npx vitest run src/app/api/admin/activity-badge-templates`.
- 검색: `familyKey`가 있으면 그 계열만 조회하는 조건이 걸린다. `image_gen_params`가 템플릿 조정값이면 응답 항목의 `templateParams`에 정리된 값이, 옛 생성기의 값이거나 없으면 `null`이 실린다. 재현 경로: `npx vitest run src/lib/admin`.
- 옛 화면이 쓰는 기존 칸이 그대로다.
- PRD 17.2가 갱신돼 있다.
- 리뷰 브랜치의 CI verify가 success다.

### 주요 의사결정 / 핵심 메모
- 제작 경로를 새 값으로 만들지 않고 `'admin-generator'`(수동 제작)를 쓰는 까닭: `badges.image_source`에는 값 3종만 허용하는 CHECK 제약이 있다(마이그레이션 186). 새 값을 더하려면 프로덕션 공용 DB의 제약을 바꿔야 한다. 템플릿 제작도 운영자가 어드민에서 손으로 만드는 경로이고, 어떤 도구로 만들었는지는 `image_gen_params`의 `kind`로 가릴 수 있다. DB 변경 없이 간다(카리나의 가정).
- 저장 경로를 옛 생성기(`badges/activity/{id}.png`)나 에셋 제너레이터(`badges/asset-generator/{id}`)와 따로 둔 까닭: 같은 배지를 다른 도구로 만든 원본이 서로 덮어쓰지 않게 한다. 서비스가 읽는 것은 `image_url` 하나다.
- `activity_badge_templates.default_params`(분류의 기본 조정값)는 이 회차에서 쓰지 않는다. 템플릿은 디자이너가 뜻한 색 그대로 올라오므로 기본 조정이 없고, 배지마다의 조정은 `image_gen_params`에 남는다. 필요해지면 그때 만든다.

- 아현의 가정: 배지 조회가 DB 오류로 실패하면 500 «배지를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.», WebP 변환 실패는 «이미지를 저장하지 못했어요…»(500)로 묶었다.
