# [Admin] 제작 화면에서 배지 이미지를 등록하고 같은 계열을 한꺼번에 등록한다

## 핵심 요약
- 요구사항: «배지 만들기» 탭의 미리보기 아래에 «등록»과 «같은 계열 모두 등록» 버튼을 둔다. 등록하면 긴 변 1280px로 다시 그린 이미지와 지금의 조정값이 배지에 저장된다. 조정값이 저장된 배지를 고르면 그 조정값을 불러온다(상위 티켓 20261115_2353의 6회차 가운데 둘째 부분). 5-2(20261116_0653)의 범위 밖 발견물 2건도 함께 고친다.
- 구현 계획: 6-1(20261116_0728)의 등록 API와 검색 응답(`familyKey` 조건, `templateParams`)을 쓴다. 아래 「구현 계획」에 파일 단위로 적었다.

## 배경 / 문제 정의
5회차까지로 미리보기와 조정이 된다. 이제 만든 이미지를 배지에 건다. 사용자가 정한 것(상위 티켓 「결정 사항」): 등록 규격은 긴 변 1280px, 등급마다 값이나 이름만 다른 같은 계열의 단계는 그림을 같게 두고 글자만 바꿔 한꺼번에 만든다, 조정값은 저장해서 다시 열 수 있게 한다.

등록은 프로덕션에 보이는 배지 이미지를 바로 바꾼다. 그래서 두 버튼 모두 확인 대화상자를 거친다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 등록 도우미 (`registerTemplateBadge.ts`, 브라우저 전용)
- `registerTemplateBadge({ badge, template, params })`는 `Promise<{ ok: true, imageUrl } | { ok: false, error }>`를 돌려준다.
  1. 화면에 붙이지 않은 캔버스(`document.createElement('canvas')`)에 `renderTemplateBadge`를 `longSidePx: 1280`으로 그린다.
  2. 그리지 못한 자리(`skipped`)가 있으면 등록하지 않고 `ok: false`와 «{이름|값} 자리를 그리지 못해 등록할 수 없어요. 템플릿을 다시 올려 주세요.»를 돌려준다. 글꼴이 바뀌어 그려진 것(`fontFallbacks`)과 줄어든 것(`shrunk`)은 막지 않는다.
  3. `canvasToBlob`으로 PNG를 만들어 `FormData`(`badgeId`, `params`는 JSON 글자, `image`)로 `POST /api/admin/activity-badge-templates/register`에 보낸다.
  4. 실패하면 응답의 `error`, 없으면 «이미지를 등록하지 못했어요. 잠시 후 다시 시도해 주세요.»를 돌려준다. 예외를 던지지 않는다.
- `summarizeBatch(results)`(순수 함수): 일괄 등록의 결과 목록을 받아 `{ total, okCount, failed: { name, error }[] }`를 돌려준다.

#### 화면
- 단건 등록: «등록»을 누르면 확인 대화상자를 연다. 확인하면 `registerTemplateBadge`를 부르고, 성공하면 알림을 띄우고 검색 결과의 그 배지를 `hasImage: true`, `templateParams: 지금 조정값`으로 고친다.
- 일괄 등록: «같은 계열 모두 등록»은 고른 배지에 `familyKey`가 있을 때만 보인다. 누르면 검색 API를 `{ familyKey, page: 1 }`로 불러 그 계열의 단계를 받는다. 받은 단계 가운데 `templateClass`가 고른 배지와 같은 것만 대상으로 삼고, 확인 대화상자에 목록을 보인다. 확인하면 하나씩 차례로 등록한다(동시에 보내지 않는다). 실패한 단계가 있어도 끝까지 간다. 진행 중에는 «{i} / {n} 등록하는 중이에요»를 보이고 두 버튼과 조정 패널을 비활성으로 둔다.
- 조정값 불러오기: 배지를 고를 때 그 배지의 `templateParams`가 있으면 조정값을 그것으로 바꾸고 미리보기 머리 아래에 «이 배지에 저장된 조정값을 불러왔어요»를 보인다. 없으면 지금 조정값을 그대로 둔다(5-2의 동작).
- 등록하는 동안과 일괄 등록하는 동안에는 다른 배지를 고르지 못하게 한다(«선택» 버튼 비활성).

#### 5-2의 범위 밖 발견물
- `renderTemplateBadge.ts`에 직접 적힌 «색 조정이 기본값인가» 조건을 `templateParams.ts`의 새 함수 `isDefaultTemplateColorParams(color)`로 옮긴다. `isDefaultTemplateBadgeParams`도 이 함수를 쓴다(판정이 한곳에 있게 한다).
- `BadgePreview.tsx` `ReadyPreview`의 들여쓰기를 바로잡는다.

### UI/UX 관점 (해당 시)
어드민 화면이라 shadcn/ui(`@/components/admin/ui`)를 쓴다. 문구는 아래를 그대로 쓴다.

**버튼** (미리보기의 이름·값·분류 세 줄 아래): «등록», «같은 계열 모두 등록»

**단건 확인** (`alert-dialog`)
- 제목: 이미지가 있는 배지는 «{이름} 배지 이미지를 바꿀까요?», 없는 배지는 «{이름} 배지 이미지를 등록할까요?»
- 설명: 등록하면 서비스에 보이는 이 배지의 이미지가 바로 바뀌어요.
- 버튼: «등록», «취소»

**일괄 확인** (`alert-dialog`)
- 제목: 같은 계열 배지 {n}개에 이미지를 등록할까요?
- 설명: 지금 조정값 그대로 단계마다 이름과 값만 바꿔서 등록해요. 서비스에 보이는 이미지가 바로 바뀌어요.
- 목록: 단계마다 한 줄 «{이름} · {등급·레벨(`slotLabelOf`)} · {값}»
- 버튼: «{n}개 등록», «취소»
- 대상이 0개면 대화상자를 열지 않고 알림 «같은 계열에 등록할 배지가 없어요.»

**알림** (`toast`)
- 단건 성공: «{이름} 배지 이미지를 등록했어요.»
- 일괄 끝: «{n}개 가운데 {ok}개를 등록했어요.»
- 실패: `registerTemplateBadge`가 돌려준 문구
- 계열 조회 실패: «같은 계열의 배지를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.»

**일괄 실패 목록** (실패가 있을 때만, 미리보기 아래 `alert` destructive)
- 제목: 등록하지 못한 배지
- 줄: «{이름}: {사유}»

1. `templateParams.ts`에 `isDefaultTemplateColorParams`를 더하고 `renderTemplateBadge.ts`가 쓰게 한다. 시험을 더한다.
2. `registerTemplateBadge.ts`를 만든다(`summarizeBatch`의 시험 포함).
3. `RegisterDialogs.tsx`(대화상자 두 개, 표시 전용)와 시험(`renderToStaticMarkup`. Radix 포털이 서버 렌더에서 비면 `BadgeStudioParts.test.tsx`가 Select를 다룬 방식처럼 시험에서만 단순 태그로 바꾼다)을 만든다.
4. `BadgePicker.tsx`의 타입, `BadgePreview.tsx`의 버튼·진행·실패 목록, `BadgeStudio.tsx`의 상태와 흐름을 붙인다.
5. PRD 17.7 «등록»을 더한다: 등록 규격(긴 변 1280px, 원본 PNG와 WebP), 저장되는 값(`image_url`, `image_gen_params`, `image_source`), 일괄 등록의 대상과 순서, 조정값 불러오기, 확인 대화상자를 두는 까닭.

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- `isDefaultTemplateColorParams`: 세 값이 0이고 `overrides`가 비었을 때만 참이다. `renderTemplateBadge.ts`에 같은 조건이 따로 남아 있지 않다. 재현 경로: `cd jam-web && npx vitest run src/lib/admin/activityBadgeTemplate`.
- `summarizeBatch`: 성공 2건과 실패 1건을 넣으면 `total: 3`, `okCount: 2`, `failed`에 이름과 사유 한 건이 나온다.
- 대화상자 시험: 이미지가 있는 배지와 없는 배지의 제목이 다르게 나온다. 일괄 대화상자에 단계 목록과 «{n}개 등록» 버튼이 나온다. 재현 경로: `npx vitest run src/app/admin/activity-badge-template`.
- `registerTemplateBadge.ts`가 `renderTemplateBadge`를 `longSidePx: 1280`으로 부르고, 그리지 못한 자리가 있으면 서버에 보내지 않는다.
- 일괄 등록이 요청을 하나씩 차례로 보낸다(`Promise.all`로 한꺼번에 보내지 않는다).
- PRD 17.7이 있다.
- 리뷰 브랜치의 CI verify가 success다.

### 후속 범위 (담당: 카리나, 시점: 게이트 통과 뒤 머지 전)
- 로컬 어드민 실렌더로 버튼, 대화상자, 조정값 불러오기 안내까지 확인한다.
- **실제 등록은 프로덕션의 배지 이미지를 바꾸므로 사용자에게 먼저 묻는다.** 어느 배지로 시험할지, 시험 뒤 원래 이미지로 되돌릴지를 정한 다음에 한다. 허락 전에는 등록 요청이 나가는 확인 버튼을 누르지 않는다.
- 아현과 민지는 격리 워크트리에서 화면 실렌더를 시도하지 않는다.

### 주요 의사결정 / 핵심 메모
- 확인 대화상자를 두는 것은 카리나의 가정이다. 등록은 프로덕션에 보이는 배지 이미지를 바로 바꾸고, 일괄 등록은 한 번에 여러 개를 바꾼다.
- 일괄 등록을 서버 한 번이 아니라 브라우저가 단계마다 그려서 하나씩 보내는 까닭: 이미지를 그리는 곳이 브라우저 캔버스다(글꼴과 `drawTextLayer`). 서버에는 그리는 코드를 두지 않는다.
- 규모: 파일 10개, 600줄 안팎으로 `plan_only` 기준을 넘는다. 서버 쪽은 6-1로 떼어 냈고 남은 것은 서로 물려 있는 화면 조각이라 파일 단위 계획을 적고 면제를 넘긴다.
