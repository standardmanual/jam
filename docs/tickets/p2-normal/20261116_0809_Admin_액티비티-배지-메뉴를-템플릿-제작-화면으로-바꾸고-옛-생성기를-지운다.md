## 배경 / 문제 정의
사용자가 정한 것(상위 티켓 「결정 사항」의 «대체»): 기존 액티비티 배지 메뉴 페이지를 새 기능으로 바꾼다. 새 화면은 6회차까지로 템플릿 올리기, 배지 검색과 미리보기, 색과 글자 조정, 등록과 일괄 등록이 된다. 옛 생성기(블롭 배경에 설명 글과 등급 칩을 얹던 화면)는 더 쓰지 않는다(상위 티켓 「가정」: 옛 생성기가 그리던 설명 글, 등급 칩, 블롭 배경은 없어진다).

옛 생성기로 이미 등록한 배지 이미지는 저장소(`badges/activity/{id}.png`)와 배지의 `image_url`에 그대로 남는다. 이 티켓은 그 이미지를 건드리지 않는다. 배지의 `image_gen_params`에 남은 옛 조정값도 그대로 두며, 새 화면은 `kind`가 다른 값을 조정값으로 읽지 않는다(`parseTemplateBadgeParams`).

## 상세 요구사항

### 서비스/코드베이스 관점
- 지우기 전에 「관련 파일」의 «지운다» 목록마다 저장소를 다시 검색해, 목록 밖에서 가져오는 곳이 남아 있지 않은지 확인한다(`jam-web/src`, `jam-web/scripts`, 루트 `scripts`). 남아 있으면 지우지 말고 `alerts`에 `[주의]`로 알린다.
- 옛 주소 `/admin/activity-badge-image`는 새 화면으로 보낸다. 권한은 `src/app/admin/layout.tsx`가 공용으로 확인한다.
- 옛 등록 API `POST /api/admin/activity-badge-image/generate`는 없앤다(404가 된다). 새 등록은 `POST /api/admin/activity-badge-templates/register`다.
- 검색 API의 주소는 바꾸지 않는다(`/api/admin/activity-badge-image/search`). 응답에서 `imageGenParams` 칸만 빠진다.
- DB는 바꾸지 않는다. `badges.image_gen_params`의 칸 설명(마이그레이션 126의 COMMENT)이 옛 생성기를 가리키지만, 고치려면 프로덕션 공용 DB에 새 마이그레이션이 필요하므로 이 티켓에서 하지 않는다.

### UI/UX 관점 (해당 시)
- 메뉴 «디자인» 묶음의 순서: 체크인 배지, 액티비티 배지(새 화면), 에셋, 이미지 생성.
- 새 화면의 제목과 설명은 그대로 둔다.

## 구현 계획
1. `search/route.ts`에서 옛 모듈과의 연결을 끊고 오류 문구를 고친다. 섞인 시험에서 ③ 구역을 지운다.
2. 메뉴와 메뉴 시험을 고친다.
3. 옛 화면을 새 화면으로 보내는 페이지로 바꾸고, «지운다» 목록의 파일을 지운다.
4. 낡은 주석을 고친다.
5. 문서를 고친다: PRD 17절에 «메뉴 «액티비티 배지»가 이 화면을 연다, 옛 화면과 옛 등록 API는 2026-11-16에 없앴다, 옛 생성기로 등록한 이미지는 그대로 남는다»를 적고, 334행과 나머지 세 문서의 옛 화면 언급을 지금 상태에 맞게 고친다.
