# [Content] 읽히지 않는 배지 이름과 설명을 변경안으로 고친다

## 핵심 요약

- 요구사항: 한국어로 적혀 있지만 어디서 끊어 읽어야 할지 알 수 없거나 뜻이 잡히지 않는 배지 이름과 설명을, 사용자가 승인한 변경안으로 바꾼다. 대상은 액티비티 배지와 아이템 배지이고 체크인 배지는 제외한다.
- 구현 계획: 대응표(`jam-web/scripts/jam2-content/badge-copy-fix-20261116.json`)의 기존 문구를 변경안으로 그대로 옮긴다. (1) DB를 고치는 1회성 SQL과 되돌림 SQL을 쓴다(실행하지 않는다). (2) 원고 문서를 고치고, 원고에서 만들어지는 시드 SQL 파일을 생성기로 다시 만든다. (3) 지금 서비스의 컨텐츠 문서와 시드 원천을 맞춘다.
- 관련 파일:
  - 대응표: `jam-web/scripts/jam2-content/badge-copy-fix-20261116.json` (`names` 24종, `descriptions` 140건, `manuscriptOnlyNames` 21종)
  - 새로 쓰는 SQL: `jam-web/supabase/migrations/seed_badge_copy_readability_20261116.sql`, 같은 이름의 `_down.sql`
  - 원고: `docs/plan/jam2/tribe-rethink/manuscript/01 미식.md`·`02 사진.md`·`03 음악.md`·`04 물건 덕후.md`·`05 내향인.md`(아이템 배지 4등급 설명 표와 이름), `06 액티비티 배지.md`(11절의 이름과 설명 표)
  - 원고에서 다시 만드는 SQL: `jam-web/scripts/gen-new-activity-badge-families.mjs` → `245_`·`248_`·`291_` 파일, `jam-web/scripts/jam2-content/gen-content-sql.mjs` → `276_`~`280_` 파일
  - 지금 서비스 문서와 시드 원천: `docs/service/content/ACTIVITY_BADGES.md`, `docs/service/content/v5_badge_name_split.md`, `docs/service/content/ITEMBOOK_REPLACEMENT_MAP.md`와 `jam-web/scripts/jam2-content/pairing.json`, `docs/assets/content-seed/`의 v5 카탈로그 JSON과 `jam-web/supabase/migrations/seed_v5_activity_badges.sql`, `docs/plan/jam2/12 JAM 2.0 오픈 전후 적용 순서.md`

## 배경 / 문제 정의

사용자가 액티비티 배지 이름 «빨래방 한 저녁을 걸은 날»을 예로 들어, 낱말을 어떻게 묶거나 끊어 읽어야 하는지 알 수 없는 이름과 설명을 모두 찾아 달라고 요청했다(2026-11-16). 삭제되지 않은 액티비티 배지 390개와 아이템 배지 1,971개의 이름·설명을 모두 읽어 해당 문구를 찾았고, 변경안을 만들어 사용자에게 기존과 변경안을 나란히 보여 주었다. 사용자는 이름을 더 짧게 줄여 달라고 한 번 고친 뒤 «이름 설명 모두 제시안으로 반영해»라고 지시했다.

대응표의 건수는 다음과 같다. DB 건수는 2026-11-16에 `badges` 표와 대조해 확인했다.

| 구분 | 종수 | DB 행 수 |
|---|---|---|
| 액티비티 배지 이름 | 14종 | 53행 |
| 아이템 배지 이름 | 10종 | 28행 |
| 액티비티 배지 설명 | 14건 | 22행 |
| 아이템 배지 설명 | 126건 | 126행 |
| 아직 DB에 없는 액티비티 배지 원고의 이름 | 21종 | 없음(원고만 고친다) |

## 상세 요구사항

### 서비스/코드베이스 관점

- 대응표의 `old`를 `new`로 바꾼다. 문구는 한 글자도 다듬지 않고 대응표 그대로 옮긴다.
- DB는 공용 단일 DB라서 SQL을 실행하면 프로덕션에도 바로 반영된다. 아현은 SQL 파일만 쓰고 실행하지 않는다.
- 원고 문서와 시드 SQL 파일은 시험으로 묶여 있다. `gen-content-sql.test.mjs`는 생성기 출력이 `276_`~`280_` 파일과 한 글자도 다르지 않은지 검사하고, `new-activity-families-seed.test.ts`·`held-activity-families-seed.test.ts`·`late-activity-family-5-6-seed.test.ts`는 `245_`·`248_`·`291_` 파일을 같은 방식으로 검사한다. 원고를 고친 뒤에는 생성기로 이 파일들을 다시 만들어야 시험이 통과한다(선례: 커밋 `592732acb`, 티켓 20261028_1736 2회).
- `pairing.test.mjs`는 `pairing.json`이 `ITEMBOOK_REPLACEMENT_MAP.md`와 원고에서 다시 만든 값과 같은지 검사한다. 아이템 배지 이름을 바꾸면 문서와 `pairing.json`을 함께 맞춘다.

### 컨텐츠 관점

- 액티비티 배지 이름은 계열 안에서 이어지게 지었다. 예: 걷기 한 번에 오래 계열은 «건조기 도는 동안 걸은 날» → «세탁 2번 동안 걸은 날» → «세탁 3번 동안 걸은 날» → «저녁 내내 걸은 날»이다.
- 고유명사는 설명에서 처음 나오는 자리에 정체를 붙였다(엔드롤 주인 한소리, 현상소 반셔터, 푸드트럭 무명, 영업사원 곱빼기, 잡화점 주인 함수정, 디저트 가게 얼리버드).
- 원래 뜻을 끝까지 확인하지 못해 추정으로 고친 설명이 11건, 원고의 이름이 6종 있다. 사용자는 이 항목을 포함해 모두 반영하라고 지시했다.

## 구현 계획

1. **DB용 SQL** `seed_badge_copy_readability_20261116.sql`을 쓴다(선례: `seed_copy_friend_voice_20261103.sql`과 `_down.sql`).
   - 대응표의 `names[].ids`와 `descriptions[].ids`로 `public.badges`의 `name`·`description`을 고친다. 행은 id로 지정한다.
   - 각 UPDATE는 지금 값이 대응표의 `old`와 같을 때만 바뀌게 한다(`AND name = old`, `AND description = old`).
   - 전체를 한 번에 실행되는 블록으로 묶고, 바뀐 행 수가 이름 81행·설명 148행과 다르면 예외를 내어 전부 되돌린다.
   - 이름 «'수리 중' 펜»처럼 작은따옴표가 든 문구는 SQL 문자열 규칙에 맞게 적는다.
   - `_down.sql`은 같은 id의 값을 `old`로 되돌린다.
   - 대응표에서 SQL을 만드는 작은 생성 스크립트를 `jam-web/scripts/jam2-content/`에 두어도 된다.
2. **원고** `01`~`05`의 아이템 배지 이름과 4등급 설명, `06`의 11절 이름·설명을 대응표대로 고친다. `manuscriptOnlyNames` 21종은 `06`에만 있다. 원고 안에서 옛 이름을 가리키는 다른 대목(2절 계열 목록, 선별표, 점검 기록 등)도 함께 맞춘다.
3. **생성기 재실행**: `gen-new-activity-badge-families.mjs`로 `245_`·`248_`·`291_`을, `gen-content-sql.mjs`로 `276_`~`280_`을 다시 만든다. 이 파일들은 이미 DB에 적용된 기록이므로 다시 실행하지 않는다. DB는 1번의 SQL로만 고친다.
4. **지금 서비스 문서와 시드 원천**: `ACTIVITY_BADGES.md`·`v5_badge_name_split.md`(이름 «일곱 바퀴의 궤도» → «일주일의 바퀴», 설명 5건), `docs/assets/content-seed/`의 v5 카탈로그 JSON 4개와 `seed_v5_activity_badges.sql`, `ITEMBOOK_REPLACEMENT_MAP.md`와 `pairing.json`(아이템 배지 이름 6종), `12 JAM 2.0 오픈 전후 적용 순서.md`(이름 1종)를 맞춘다.
5. **시험 파일**: `held-activity-families-seed.test.ts` 478행처럼 다시 만든 시드의 이름을 기대값으로 둔 곳은 새 이름으로 맞춘다. `jam-action-badges.test.ts` 275·283행과 `badge-engine-v5.test.ts` 1210행은 이름을 임의 값으로 쓰는 곳이라 고치지 않아도 된다.
6. **고치지 않는 곳**: `docs/tickets/`의 다른 티켓, `docs/assets/image-production/`의 제작 기록, 생성기와 묶여 있지 않은 옛 SQL(`019_`·`138_`·`139_`·`330_`·`338_`, `seed_배지이미지라운드처리_20260916.sql`), `ops_bundles` 표의 묶음 기록.

**막히면 멈추는 지점**: 원고를 고친 뒤 문장 길이나 쉼표 수 같은 보이스 규칙을 검사하는 시험이 실패하면, 문구를 임의로 줄이지 말고 실패한 항목을 보고하고 멈춘다.

## 주요 의사결정

- **계획 반환 면제**: 바뀌는 파일이 5개를 넘고 줄 수도 100줄을 넘는다. 사용자가 기존과 변경안 목록 전체를 검토한 뒤 모두 반영하라고 승인했고(2026-11-16), 변경이 대응표를 그대로 옮기는 치환이라서 첫 호출부터 면제를 준다.
- **이미지 속 글자와 달라지는 8행도 지금 반영한다**(사용자 결정, 2026-11-16): 기존 액티비티 배지 이미지에는 이름과 설명이 글자로 그려져 있다. «일곱 바퀴의 궤도» 3행과 설명 5행(높은 곳 Mystic, 달려온 거리 Lv.3, 이번 주의 바퀴 Epic, 주말 라이더 Epic, 안장에 오른 횟수 Lv.2)은 이미지를 다시 만들 때까지 이미지 속 글자가 옛 문구로 남는다. 새로 넣은 계열(빨래방·좌판 등)은 지금도 다른 배지의 이미지를 임시로 쓰고 있어서 달라지는 점이 없다.
- **세계관 검수는 거치지 않았다**: 변경안은 트라이브 보이스 2절·3절과 트라이브 초안을 기준으로 썼고, 윈터의 검수는 받지 않았다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- 대응표의 기존 문구를 변경안으로 그대로 옮겼다. DB(`public.badges`)의 이름 24종 81행과 설명 140건 148행, 원고 `01`~`06`, 지금 서비스의 컨텐츠 문서와 시드 원천을 함께 고쳤다. 아직 DB에 없는 원고의 이름 21종은 `06 액티비티 배지.md`에서만 고쳤다.
- 원고에서 만들어지는 시드 SQL `245_`·`248_`·`276_`~`280_`을 생성기로 다시 만들었다. `291_`은 달라지는 내용이 없었다. 이 파일들은 다시 실행하지 않았다.
- DB는 2026-11-16(KST)에 카리나가 Supabase MCP로 반영했다. 공용 DB라서 프로덕션에도 바로 반영됐다. 실행 방식과 순서는 `seed_badge_copy_readability_20261116_apply.sql`에 적었다.
  - 백업: `public.badge_copy_backup_20261116`에 229행(이름 81, 설명 148)의 이전 값과 새 값을 담았다. RLS를 켜고 anon·authenticated 권한을 거뒀다.
  - 드라이런: 반영 직전에 DB의 현재 값이 대응표의 기존 값과 모두 같았다(이름 81행, 설명 148행).
  - 롤백 실측: 반영 블록 끝에 일부러 예외를 붙여 실행했다. 예외 문구에 81행·148행이 찍혔고, 실행 뒤 배지 표는 그대로였다.

### 주요 의사결정 / 핵심 메모
> 개발 과정에서 검토·결정된 사항, 선택하지 않은 대안과 그 이유.

- **1회 실행이 멈춘 이유**: 아현의 리뷰 브랜치 push가 자동 권한 검사에 거부됐고, `verify.sh`의 문구 검사가 `ITEMBOOK_REPLACEMENT_MAP.md` 한 줄에서 실패했다. 사용자가 작업 브랜치 push와 검사 제외를 승인했고, 카리나가 작업 폴더에서 제외 목록을 고쳐 커밋·push한 뒤 게이트만 다시 돌렸다.
- **게이트 WARN의 사유**: `jam-web/design-system/components/patterns/ListRow.stories.tsx` 490~492행에 옛 이름 «건너온 물건 칸»이 남아 있다. 이 견본은 사용자가 보낸 프로필 피드 화면(2026-11-06)을 그대로 옮긴 것이고 서비스 동작에 영향이 없어서 고치지 않았다.
- **DB 실행 방식**: 새 SQL 파일이 약 120KB라서 MCP 호출에 그대로 넣지 않았다. 대응표 값을 백업 표에 담고 그 표를 읽는 블록 하나로 같은 행을 같은 조건으로 고쳤다. 결과는 대응표의 새 값과 전부 대조했다.
- **`badges_family_consistency` 트리거**: 액티비티 배지의 이름을 고치면 계열의 측정 조건 일치를 검사한다. 이번 변경은 조건을 건드리지 않아 롤백 실측에서 걸리지 않았다.
- **고치지 않은 곳**: 홈피드 묶음 `weekly-2026-W46-0901`의 내부 메모(`ops_bundles.raw`)와 컬렉션의 시선·동작 문장(`item_books.gaze_motion`)에 옛 이름이 문장의 일부로 남아 있다. 사용자에게 보이지 않는 기록이라 그대로 두었다.
