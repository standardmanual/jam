## 배경 / 문제 정의
사용자가 정한 것(상위 티켓 「결정 사항」의 «템플릿을 넣는 방식»): 어드민에 SVG를 올리지 않고 템플릿마다 개발해서 넣는다. 8-1회차에서 템플릿을 코드로 정의하는 틀(`templateDef.ts`, `templates/`), 원을 따라 글자를 놓는 계산(`layoutArcText`), 운동 수치 템플릿 정의를 만들었다. 제작 화면은 아직 DB의 `activity_badge_templates` 표(지금 0줄)에서 템플릿을 읽고, `<text>` 자리의 x·y에 직선으로만 그린다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 템플릿 항목 (`templateItem.ts`)
```ts
export interface TemplateItem {
  classKey: BadgeTemplateClassKey
  label: string
  svg: string | null
  slots: TemplateDefSlots | null
}
/** 네 분류를 정해진 순서로 돌려준다. 코드에 정의가 없는 분류는 svg와 slots가 null이다. */
export function listTemplateItems(): TemplateItem[]
```
- `TEMPLATE_CLASS_KEYS`와 `isTemplateClassKey`는 그대로 둔다.

#### 2. 페이지와 화면
- `page.tsx`는 DB를 읽지 않는다. 제목과 설명은 그대로 두고 `<BadgeStudio templates={listTemplateItems()} />`를 그린다.
- 탭이 없어진다. `BadgeStudio`와 `BadgePreview`에서 `onGoToTemplates`를 지운다.

#### 3. 원호 자리 그리기 (`renderTemplateBadge.ts`)
- `RenderTemplateBadgeInput.slots`는 `TemplateDefSlots`다. 자리마다 `isArcSlot`으로 갈라, 직선 자리는 지금 코드 그대로 그리고 원호 자리는 아래대로 그린다.
- 글꼴 준비(캔버스를 건드리기 전): `styled = styleArcSlot(slot, params.text[slotName])`, `resolveTemplateFont(styled)`로 글꼴을 정하고 `loadFontInBrowser`와 `loadFontForText(font, text)`로 불러온다. 실패하면 직선 자리와 같은 방식으로 기본 글꼴로 바꾸고 `fontFallbacks`에 적는다.
- 그리기(좌표는 viewBox 단위로 계산하고, 그릴 때 `s = width ÷ viewBoxWidth`를 곱한다):
  1. `ctx.font`를 `${font.weight} ${styled.fontSize}px "${font.family}"`로 두고 글자마다 `ctx.measureText(ch).width`를 잰다(`Array.from(text)`로 글자를 나눈다).
  2. `layoutArcText({ advances, fontSize: styled.fontSize, letterSpacingEm: slot.letterSpacingEm, cx, cy, baselineRadius, centerDeg, facing, maxSpanDeg })`. `null`이면 `skipped`에 적고 넘어간다. `shrunk`이면 `result.shrunk`에 적는다.
  3. `ctx.fillStyle = styled.fill`, `ctx.font`를 `${font.weight} ${layout.fontSize × s}px "${font.family}"`로, `textAlign`을 `center`, `textBaseline`을 `alphabetic`으로 둔다.
  4. 글자마다 `ctx.save()` → `ctx.translate(glyph.x × s, glyph.y × s)` → `ctx.rotate(glyph.rotationDeg × π ÷ 180)` → `ctx.fillText(글자, 0, 0)` → `ctx.restore()`.
  5. 끝나면 캔버스의 상태(`font`·`fillStyle`·`textAlign`·`textBaseline`)가 다음 자리에 새지 않게 전체를 `save`·`restore`로 감싼다.
- 글자가 비어 있으면 아무것도 그리지 않는다(`skipped`가 아니다).
- 샘플 글자를 걷어 내는 일은 `stripSlotText`가 이미 한다(8-1회차).

#### 4. 그림을 안쪽 상자에 맞추기 (`composeTemplate.ts`, `renderTemplateBadge.ts`)
사용자 지시(2026-11-16): 제공한 SVG가 배지 이미지 안쪽 가운데에 이미지 생성 메뉴의 기준과 같은 크기로 들어가게 한다. 그 기준은 `normalize.ts`의 1024 캔버스에 긴 변 870(약 85%), 정중앙이다.
```ts
/** 이미지 생성 메뉴의 규격(normalize.ts의 BOX_PX ÷ CANVAS_PX)과 같은 값이다 */
export const TEMPLATE_CONTENT_BOX_RATIO = 870 / 1024
export interface TemplateContentLayout {
  canvasWidth: number
  canvasHeight: number
  /** viewBox 좌표에 곱하는 배율 */
  scale: number
  offsetX: number
  offsetY: number
  drawWidth: number
  drawHeight: number
}
export function layoutTemplateContent(input: { viewWidth: number; viewHeight: number; longSidePx: number }): TemplateContentLayout
```
- 캔버스는 `longSidePx × longSidePx` 정사각형이다. 안쪽 상자의 한 변은 `longSidePx × TEMPLATE_CONTENT_BOX_RATIO`이고, `scale = 상자의 한 변 ÷ max(viewWidth, viewHeight)`, `drawWidth = viewWidth × scale`, `drawHeight = viewHeight × scale`, `offsetX = (canvasWidth − drawWidth) ÷ 2`, `offsetY = (canvasHeight − drawHeight) ÷ 2`다. 값을 반올림하지 않는다.
- `renderTemplateBadge`는 캔버스를 `canvasWidth × canvasHeight`로 만들고 그림을 `ctx.drawImage(img, offsetX, offsetY, drawWidth, drawHeight)`로 그린다. 바깥 여백은 투명하다.
- 원호 자리: 3번의 `s` 대신 `scale`을 쓰고, 글자의 위치는 `(offsetX + glyph.x × scale, offsetY + glyph.y × scale)`다.
- 직선 자리: `ctx.save()` → `ctx.translate(offsetX, offsetY)` → `drawTextLayer`에 `stageWidth: drawWidth`, `stageHeight: drawHeight`를 넘김 → `ctx.restore()`.
- 미리보기(`BadgePreview.tsx`의 `longSidePx: 1024`)와 등록(`registerTemplateBadge.ts`의 `REGISTER_LONG_SIDE_PX = 1280`)의 긴 변은 이 티켓에서 바꾸지 않는다. 등록 크기를 1024로 바꿀지는 사용자에게 물어 둔 상태다.
- 시험에서 `TEMPLATE_CONTENT_BOX_RATIO`가 `normalize.ts`의 `BOX_PX ÷ CANVAS_PX`와 같은지 대조한다(두 기준이 어긋나면 시험이 잡는다).

#### 5. 지우기
- 「관련 파일」의 «지운다» 목록을 지운다. 지우기 전에 목록마다 저장소를 다시 검색해(`jam-web/src`, `jam-web/scripts`, 루트 `scripts`) 목록 밖에서 가져오는 곳이 없는지 확인한다. 남아 있으면 지우지 말고 `alerts`에 `[주의]`로 알린다.
- 없어지는 API: `GET /api/admin/activity-badge-templates`, `PUT`·`DELETE /api/admin/activity-badge-templates/[classKey]`. 남는 API: `POST /api/admin/activity-badge-templates/register`.
- DB는 바꾸지 않는다. `activity_badge_templates` 표(0줄)는 쓰는 코드가 없어지지만, 표를 지우는 일은 이 티켓에서 하지 않는다(프로덕션 공용 DB의 축소 단계라 별도 티켓으로 한다).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `listTemplateItems()`가 네 분류를 정해진 순서로 돌려주고 운동 수치만 코드의 템플릿(8-1회차)을 가진다. 페이지는 DB를 읽지 않는다.
- `layoutTemplateContent`로 그림을 1024 캔버스의 안쪽 상자(긴 변 870, 여백 77)에 맞춘다. 이미지 생성 메뉴의 기준(`normalize.ts`)과 같은지 대조하는 시험이 있다.
- `renderTemplateBadge`가 원호 자리를 글자마다 회전해 그린다. 직선 자리는 위치만 안쪽 상자로 옮긴다.
- «템플릿» 탭, 목록·저장·삭제 API, SVG 검사·정화 코드를 지웠다. 남은 API는 등록(`register`) 하나다.
- 템플릿이 없는 분류, 미리보기 실패, 자리 그리기 실패의 문구를 바꿨다. PRD 17절을 고쳤다.

### 주요 의사결정 / 핵심 메모
- 템플릿 항목을 페이지가 prop으로 넘기는 꼴을 그대로 둔 까닭: 화면 시험이 템플릿을 바꿔 끼울 수 있고, `BadgeStudio`·`BadgePreview`·`registerTemplateBadge`의 고칠 곳이 줄어든다.
- 원호 글자를 그리는 코드에 단위 시험을 두지 않는 까닭: 캔버스에 직접 그리는 브라우저 전용 코드다. 계산은 8-1회차의 `layoutArcText` 시험이 고정하고, 그린 결과는 카리나가 로컬 어드민에서 원본과 겹쳐 잰다.
- 표 `activity_badge_templates`를 이 티켓에서 지우지 않는 까닭: 프로덕션 공용 DB의 변경은 메인 세션이 실행한다. 쓰는 코드를 먼저 없앤 뒤(이 티켓) 표를 지우는 순서로 간다.
- 안쪽 상자의 비율을 87%가 아니라 870÷1024(약 85%)로 둔 까닭: 사용자가 «87% 정도, 이미지 생성 메뉴 개발 때 정한 기준»이라고 했고, 그 기준이 코드에 870px로 들어 있다. 같은 기준을 쓰는 것이 지시의 뜻이라고 카리나가 읽었고 사용자에게 알렸다.
- 지우는 양이 많아 `plan_only`의 줄 수 기준을 넘는다. 지울 파일과 고칠 곳을 조사해 이 티켓에 적었으므로 면제를 넘긴다.
