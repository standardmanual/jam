# [Admin] «이어 온 날» 분류의 템플릿을 코드로 정의해 넣는다

## 핵심 요약
- 요구사항: 사용자가 준 `Group 14.svg`를 분류 «이어 온 날»(`streak`)의 템플릿으로 코드에 정의한다(사용자 지시, 2026-11-16: «분류 이어온날의 템플릿 svg야 추가해»). 상위 티켓 20261115_2353의 11회차이고, 첫 템플릿(운동 수치, 티켓 20261116_1435)과 같은 방식이다. 이 템플릿은 글자가 원호가 아니라 직선이라서 새 글자 배치 기능은 필요 없다.

## 배경 / 문제 정의
사용자가 정한 것(상위 티켓 「결정 사항」의 «템플릿을 넣는 방식»): 템플릿마다 그때그때 개발해서 넣는다. 사용자가 두 번째 템플릿으로 `Group 14.svg`를 주었고 분류는 «이어 온 날»이다.

카리나가 파일을 분석한 결과(2026-11-16):
- 크기는 1021×834다. 글자는 모양이 아니라 실제 `<text>` 두 개다(첫 템플릿과 다르다).
- 이름 자리: 글꼴 Noto Sans KR, 굵기 900, 크기 90, 자간 -0.08em, 시작 x 40.4758, 기준선 y 345.745, 색 black, 샘플 «동해물과 백두산이 백두산이»(공백 포함 14자).
- 값 자리: 같은 글꼴·굵기·자간, 크기 129, 시작 x 197.157, 기준선 y 574.845, 색 black, 샘플 «연속 3000일».
- `<text>`의 `id`는 `name`·`value`가 아니라 샘플 글자 그대로다. 그릴 때 샘플을 걷어 내는 코드(`stripSlotText`)가 `id="name"`·`id="value"`를 찾으므로, 정의 파일이 두 `<text>`의 `id`를 `name`·`value`로 바꾼 사본을 SVG로 쓴다. 원본 파일(`streakSvg.ts`)은 그대로 둔다.
- 샘플 글자는 모두 가운데 정렬로 놓은 것이다(샘플 폭의 가운데가 이름 515.7, 값 514.3이고 그림 가운데 510.5에 가깝다). 지금의 직선 글자 배치(`layoutSlotText`)는 «샘플 글자 폭의 가운데에 새 글자의 가운데를 맞춘다»라서 그대로 맞는다. 샘플 글자를 같은 방식으로 다시 그린 것과 원본의 색이 다른 픽셀은 0개였다(헤드리스 크롬, Noto Sans KR 900).
- 이 분류의 실제 배지 63개의 값은 «N일 연속»·«N주 연속»·«N일 만에» 세 꼴이고 가장 긴 것이 «14일 만에», 이름은 가장 긴 것이 9자(작심삼일의 파괴자)·평균 6.5자라서 샘플 글자보다 모두 짧다. 글자 크기를 줄이는 규칙은 거의 발동하지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 정의 파일 (`templates/streak.ts`)
```ts
import type { BadgeTemplateDef } from '../templateDef'
import type { TemplateSlot } from '../templateSvg'
import { STREAK_ORIGINAL_SVG } from './streakSvg'

/** 두 <text>의 id를 앞에서부터 name·value로 바꾼 사본. <text>가 둘이 아니면 원본을 그대로 돌려준다(시험이 둘인지 확인한다) */
export function nameSampleTextLayers(svg: string): string
export const STREAK_TEMPLATE: BadgeTemplateDef
```
- `nameSampleTextLayers`는 문서 순서대로 첫 `<text id="…">`를 `id="name"`, 둘째를 `id="value"`로 바꾼다. 다른 글자는 바꾸지 않는다. 정규식이면 충분하다(`<text id="` 뒤 따옴표까지).
- `STREAK_TEMPLATE`: `classKey: 'streak'`, `svg: nameSampleTextLayers(STREAK_ORIGINAL_SVG)`, `slots.viewBoxWidth: 1021`, `viewBoxHeight: 834`. 두 자리는 `TemplateSlot` 꼴이다(원호가 아니라 직선):

| 자리 | found | isText | x | y | fontFamily | fontSize | fontWeight | fill | letterSpacing | textAnchor | transform | placeholder |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| name | true | true | 40.4758 | 345.745 | 'Noto Sans KR' | 90 | '900' | '#000000' | '-0.08em' | null | null | '동해물과 백두산이 백두산이' |
| value | true | true | 197.157 | 574.845 | 'Noto Sans KR' | 129 | '900' | '#000000' | '-0.08em' | null | null | '연속 3000일' |

- 수치에는 «사용자가 준 `Group 14.svg`의 글자 속성 그대로이고 원본과 같은 위치에 놓이는 것을 카리나가 확인했다»는 주석을 단다.
- `templates/index.ts`: `BADGE_TEMPLATE_DEFS`에 `streak: STREAK_TEMPLATE`를 더한다.

#### 2. 시험 (`__tests__/templateDefs.test.ts`)
- `getBadgeTemplateDef('streak')`가 위 표의 값을 가진다. `'days'`·`'count'`는 `null`이다. `'metric'`은 그대로다.
- 모든 정의 공통: SVG의 `viewBox`가 정의와 같다. `stripSlotText(def.svg)`의 결과에 `id="name"`·`id="value"`가 없다. 두 자리의 글꼴이 `resolveTemplateFont`에서 `fallback: false`, 굵기 900이다.
- `metric` 전용: 지금의 `Union`·`Vector` 남김, 색 네 가지, 원호 자리 확인(옮겨 둔다).
- `streak` 전용:
  - `STREAK_ORIGINAL_SVG`에 `<text`가 정확히 둘이고, `nameSampleTextLayers`의 결과에는 `id="name"`·`id="value"`가 한 번씩 있고 그 밖의 줄은 원본과 같다(두 `id` 값만 다르다).
  - `stripSlotText(STREAK_TEMPLATE.svg)`의 결과에 `<text`가 없고 `id="Line 1"`·`id="Group"`·`id="Vector"`가 남아 있다.
  - `extractSvgColors(STREAK_TEMPLATE.svg)`가 `#000000`·`#5BF700`·`#FFFFFF`를 돌려준다(`black`은 `#000000`으로 읽힌다).
  - 직선 글자 배치: `layoutSlotText({ slot: name 자리, viewWidth: 1021, placeholderWidth: 950.4, contentWidth: 630 })`의 `anchorX`가 ≈ 515.68이고 `shrunk`는 false다. 값 자리는 `placeholderWidth: 634.2`, `contentWidth: 497.7`에서 `anchorX ≈ 514.26`, `shrunk` false다.

### 주요 의사결정 / 핵심 메모
- 샘플 글자의 `id`를 정의 파일에서 바꾼 사본을 쓰는 까닭: 사용자가 준 파일을 고치지 않고 그대로 두면 그림을 바꿀 때 파일만 통째로 바꾸면 된다. 공유 코드(`stripSlotText`)를 이 템플릿 하나를 위해 고치지 않는다. 사용자가 다음부터 레이어 이름을 `name`·`value`로 지어 주면 바꿀 필요가 없다.
- 직선 자리를 그대로 쓰는 까닭: 샘플 글자의 가운데가 그림 가운데 부근이고, 지금의 배치가 «샘플 글자 폭의 가운데에 맞춘다»라서 원본과 같은 위치에 놓인다(카리나가 확인).
- 글자 크기를 줄이는 규칙의 한계: 값 자리는 이 템플릿에서 초록 띠(가로 114~906)보다 글자가 넓어지면 띠를 넘는다. 실제 값은 가장 긴 것이 «14일 만에»(샘플 «연속 3000일»보다 짧다)라서 넘지 않는다. 더 긴 값이 생기면 그때 자리별 최대 폭을 정의에 더한다.
- 바뀌는 파일이 다섯 개 안팎이고 줄 수도 적어 `plan_only` 기준에 걸리지 않을 수 있으나, 파일 단위 계획을 이 티켓에 적었으므로 면제를 넘긴다.
