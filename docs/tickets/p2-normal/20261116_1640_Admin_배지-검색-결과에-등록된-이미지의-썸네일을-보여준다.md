# [Admin] 배지 검색 결과에 등록된 이미지의 썸네일을 보여준다

## 핵심 요약
- 요구사항: 어드민 «액티비티 배지» 화면의 배지 검색 결과 표에서 «이미지» 칸이 지금은 «있음»·«없음» 글자만 보여 준다. 등록된 배지 이미지의 썸네일을 보여 준다(사용자 지시, 2026-11-16: «배지 검색결과에 등록된 배지 이미지 썸네일을 보여줘»).
- 구현 계획: 검색 API가 배지의 이미지 주소(`imageUrl`)를 응답에 싣고, 표의 «이미지» 칸이 그 주소로 작은 그림을 그린다. 이미지가 없는 배지는 지금처럼 «없음»을 보인다.
- 관련 파일:
  - `jam-web/src/app/api/admin/activity-badge-image/search/route.ts`: 응답 항목을 만드는 구간(98행의 `hasImage: Boolean(row.image_url)` 부근). `imageUrl`을 더한다
  - `jam-web/src/app/admin/activity-badge-template/BadgePicker.tsx`: `StudioSearchBadge`(42행 부근)에 `imageUrl`을 더하고, «이미지» 칸(190행 `TableHead`와 200행 부근 `TableCell`)을 고친다
  - `jam-web/src/app/admin/activity-badge-template/BadgeStudio.tsx`: 검색 결과를 `StudioSearchBadge`로 쓰는 곳(응답을 그대로 담는다면 고칠 것이 없는지 확인한다)
  - 시험: `jam-web/src/app/api/admin/activity-badge-image/search/__tests__/route.test.ts`, `jam-web/src/app/admin/activity-badge-template/__tests__/BadgeStudioParts.test.tsx`(`describe('BadgePicker')`)
  - 문서: `docs/service/prd/asset-generator/PRD.md` 17.5(제작 화면)
  - 읽기만: `jam-web/src/lib/imageSrc.ts`의 `optimizedImageUrl`(127행), `jam-web/src/app/admin/badge-image/page.tsx`(276행의 `<img>` 사용 본보기)

## 배경 / 문제 정의
검색 결과에서 어느 배지에 이미 이미지가 올라가 있는지는 «있음»으로만 알 수 있고, 어떤 이미지인지는 배지를 골라 미리보기를 열어야 보인다. 같은 이름의 배지가 여러 등급으로 나오는 계열(예: 걸은 날들 Lv.1~Lv.8)은 이미지가 등급마다 다르게 올라가 있는지 훑어보기 어렵다. 썸네일이 있으면 표에서 바로 보인다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 검색 API 응답의 각 배지에 `imageUrl: string | null`을 더한다. 값은 `badges.image_url` 그대로다(비어 있으면 `null`). `hasImage`는 그대로 둔다(기존 시험과 화면이 쓴다).
- `StudioSearchBadge`에 `imageUrl: string | null`을 더한다. 시험의 가짜 배지 객체(`BadgeStudioParts.test.tsx` 등)도 새 칸을 채운다.
- 썸네일 주소: `optimizedImageUrl(badge.imageUrl, 96)`이 돌려주는 값을 `<img src>`로 쓴다(다음 이미지 변환 주소 `/_next/image?url=…&w=96&q=75`). 96은 표시 크기 48px의 2배다. 변환할 수 없는 주소는 이 함수가 원래 주소를 그대로 돌려주므로 따로 처리하지 않는다. `?v=` 꼬리표는 주소에 그대로 들어가 있어서 다시 등록하면 새 그림이 보인다.
- `<img>`를 쓴다(어드민의 다른 화면과 같다, `badge-image/page.tsx` 275행의 `eslint-disable-next-line @next/next/no-img-element` 주석을 같은 방식으로 단다). `loading="lazy"`, `decoding="async"`, `alt`는 `«{배지 이름} 이미지»`로 둔다.
- 그림이 불러와지지 않으면(`onError`) 그 칸은 «불러오지 못함» 글자 배지로 바꾼다. 화면 상태 하나(`useState`)면 충분하고, 그림 주소가 바뀌면 다시 시도한다(`key`에 주소를 넣는다).

### UI/UX 관점 (해당 시)
- «이미지» 칸: 이미지가 있으면 가로세로 48px 칸에 `object-contain`으로 그림을 보여 준다. 칸 모양은 `rounded-md border bg-muted`로 하고 배지가 투명 PNG라서 배경이 비치지 않게 한다. 이미지가 없으면 지금처럼 «없음» 배지를 보인다. «있음» 배지는 썸네일로 대체되어 사라진다.
- 표 머리글 «이미지»는 그대로 둔다. 한 줄의 높이가 썸네일 때문에 늘어나도 괜찮다(48px).
- 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

## 구현 계획
1. 검색 API 응답에 `imageUrl`을 더하고 라우트 시험에서 값이 실리는지 확인한다.
2. `StudioSearchBadge`와 `BadgePicker`의 «이미지» 칸을 고친다.
3. `BadgeStudioParts.test.tsx`를 고친다(썸네일 주소, 없음, 불러오기 실패).
4. PRD 17.5에 «검색 결과 표에 썸네일을 보인다»를 적는다.

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- 검색 API 응답의 배지마다 `imageUrl`이 있다. `image_url`이 있는 배지는 그 값, 없는 배지는 `null`이다. 기존 칸(`hasImage` 포함)은 그대로다.
- `BadgePicker`가 이미지가 있는 배지에 `<img>`를 그리고 `src`가 `optimizedImageUrl(imageUrl, 96)`의 값이며 `loading="lazy"`·`alt`가 위와 같다. 이미지가 없는 배지는 «없음»만 보이고 `<img>`가 없다.
- 그림 불러오기에 실패하면 «불러오지 못함»이 보인다(시험은 `onError` 처리 함수를 직접 부르거나 렌더 결과에서 확인한다. 불가능하면 이 항목은 `assumptions`에 이유를 적는다).
- 검색 조건(분류 필터 포함), 쪽 넘김, 선택 버튼의 동작이 그대로다.
- PRD 17.5가 갱신돼 있다.
- 재현 경로: `cd jam-web && npx vitest run src/lib/admin src/app/admin/activity-badge-template src/app/api/admin/activity-badge-image`.
- 리뷰 브랜치의 CI verify가 success다.

### 주요 의사결정 / 핵심 메모
- 썸네일 주소를 `optimizedImageUrl(…, 96)`으로 만든 까닭: 등록된 이미지는 1024px(약 50~90KB)라서, 한 쪽(50줄)에 원본을 그대로 쓰면 수 MB를 받는다. 서비스 화면이 쓰는 다음 이미지 변환(96px, 31일 캐시)을 같이 쓰면 줄마다 수 KB다.
- 이 티켓은 «이어 온 날» 템플릿 티켓(20261116_1634)과 고치는 파일이 겹치지 않아 함께 진행한다. PRD는 다른 절(17.3과 17.5)을 고친다.
- 파일 수는 여섯 개이고 100줄이 안 되는 크기지만, 함수 꼴과 시험 기대값을 이 티켓에 적었으므로 면제를 넘긴다.
