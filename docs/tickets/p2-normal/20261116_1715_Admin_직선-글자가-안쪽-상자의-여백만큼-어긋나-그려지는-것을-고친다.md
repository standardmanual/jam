# [Admin] 직선 글자가 안쪽 상자의 여백만큼 어긋나 그려지는 것을 고친다

## 핵심 요약
- 요구사항: «이어 온 날» 템플릿(직선 글자)을 로컬 어드민에서 열었더니 이름이 위쪽 «JOIN AND MOVE» 띠에 겹치고 값이 이름 자리에 그려졌다. 직선 글자가 안쪽 상자의 여백(오른쪽 77, 아래 156 캔버스 픽셀)만큼 위·왼쪽으로 어긋나 있었다. 이를 고친다.
- 구현 계획: 글자 위치를 안쪽 상자 기준 퍼센트에서 캔버스 전체 기준 퍼센트로 바꾸는 순수 함수를 더하고, 직선 자리를 그리는 곳에서 쓴다(경미 수정, 카리나가 직접 처리).
- 관련 파일: `jam-web/src/lib/admin/activityBadgeTemplate/composeTemplate.ts`(`offsetTextLayerInput` 추가), `jam-web/src/app/admin/activity-badge-template/renderTemplateBadge.ts`(직선 자리 그리는 구간), 시험 `__tests__/composeTemplate.test.ts`

## 배경 / 문제 정의
8-2회차(티켓 20261116_1513)가 직선 자리를 `ctx.translate(offsetX, offsetY)`로 안쪽 상자 여백만큼 옮긴 뒤 `drawTextLayer`를 불렀다. 그런데 `drawTextLayer`는 위치를 `ctx.setTransform(...)`으로 절대 좌표로 정하고 끝에 단위 행렬로 되돌리므로 앞의 `translate`가 사라진다. 첫 템플릿(운동 수치)은 원호 글자라 이 경로를 쓰지 않아서 시험에 걸리지 않았고, 두 번째 템플릿(이어 온 날)이 처음으로 직선 자리를 썼다. 게이트와 CI도 브라우저 전용 그리기 코드라 잡지 못했다. 로컬 어드민 실렌더에서 발견했다.

## 상세 요구사항
- `offsetTextLayerInput(input, box)`: 안쪽 상자(drawWidth×drawHeight, 여백 offsetX·offsetY) 기준의 글자 입력을 캔버스 전체 기준으로 바꾼다(stage를 캔버스 크기로, 위치와 크기의 퍼센트를 다시 계산). 직선 자리는 `translate` 대신 이 함수를 거쳐 그린다.

## 완료 조건
- 시험: 안쪽 상자의 퍼센트가 캔버스 전체의 퍼센트로 바뀐다(캔버스 1000×1000, 상자 500×250, 여백 250·375에서 xPct 50→50, yPct 40→47.5, sizePct 20→5). 여백이 없으면 값이 그대로다. `npx vitest run src/lib/admin/activityBadgeTemplate` 통과.
- 로컬 어드민 실렌더: «작심삼일의 파괴자»(3일 연속)를 골라 이름이 위쪽 초록 띠 안에, 값이 선 아래 띠 안에 그려지고 JOIN AND MOVE·Jam이 가려지지 않는다. 그림은 1024 캔버스에서 870×712, 위치 (77, 156)이다.
