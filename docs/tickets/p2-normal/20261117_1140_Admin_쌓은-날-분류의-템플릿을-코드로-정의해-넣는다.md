# [Admin] «쌓은 날» 분류의 템플릿을 코드로 정의해 넣는다

## 핵심 요약
- 요구사항: 사용자가 준 `Group 15.svg`를 분류 «쌓은 날»(`days`)의 템플릿으로 코드에 정의한다(사용자 지시, 2026-11-17: «쌓은 날 템플릿으로 등록해, 위의 원호는 배지명, 아래 날은 값»). 상위 티켓 20261115_2353의 13회차다. 이름은 원호 글자(운동 수치 템플릿과 같은 방식), 값은 직선 글자(이어 온 날 템플릿과 같은 방식)라서 새 글자 배치 기능은 필요 없다.
- 구현 계획: 원본 SVG는 카리나가 `templates/daysSvg.ts`에 그대로 옮겨 커밋해 두었다. 아현은 정의 파일 `templates/days.ts`를 만들고 `templates/index.ts`에 등록하며 시험을 정리한다. 화면과 API는 바꾸지 않는다. «등록»은 이 템플릿을 코드에 넣는다는 뜻이고 배지 이미지를 올리지 않는다.
- 관련 파일:
  - **이미 있다(카리나가 사용자의 파일을 그대로 옮겨 커밋했다. 고치지 않는다)**

  - **새 파일**

## 배경 / 문제 정의
사용자가 정한 것(상위 티켓 「결정 사항」의 «템플릿을 넣는 방식»): 템플릿마다 그때그때 개발해서 넣는다. 세 번째 템플릿으로 `Group 15.svg`를 주었다.

카리나가 파일을 분석하고 글꼴을 맞춘 결과(2026-11-17):
- 크기는 702×1098이다. 위는 반원, 아래도 반원인 세로로 긴 알약 모양이고, 가운데에 Jam 글자 세 줄, 양옆에 세로 글자 «JOIN AND MOVE», 값 위에 가로선이 있다.
- 이름과 값 모두 글자 모양(`<path>`)이다. 샘플 글자는 레이어 이름에 들어 있다: 이름 «매일 닦은 유리 칸»(공백 포함 9자), 값 «1000일». 사용자가 글꼴을 Noto Sans KR이라고 알려 주었고 굵기는 말하지 않았다. 굵기 700·800·900을 원본 모양에 겹쳐 본 결과 900이 가장 잘 맞았다(값 겹침 비율 0.965·0.943·0.905, 이름 0.852·0.852·0.797).
- 이름은 위쪽 원호에 글자 윗부분이 바깥을 향해 놓인다. 원의 중심 x는 그림 가운데 351이고 중심 y는 300.49다. 샘플이 차지한 각도는 177.2°다.
- 값은 가로 한 줄이고 가운데 x 350.51, 기준선 y 949.75다.
- 두 `<path>`의 `id`는 `name`·`value`가 아니라 샘플 글자 그대로다. 그릴 때 샘플을 걷어 내는 코드(`stripSlotText`)가 `id="name"`·`id="value"`를 찾으므로, 정의 파일이 두 `<path>`의 `id`를 바꾼 사본을 SVG로 쓴다. 원본 파일(`daysSvg.ts`)은 그대로 둔다. 이어 온 날 템플릿의 `nameSampleTextLayers`와 같은 방식이다.
- 이 분류 배지 82개의 값은 «N일»·«N주»·«N년» 세 꼴이고 가장 긴 것이 «300일»(샘플 «1000일»보다 짧다). 이름은 17종이고 가장 긴 것이 10자(하늘빛이 다른 자리, 두 종)다. 샘플보다 긴 이름은 글자 크기를 줄이는 규칙으로 호의 각도를 177.2°에 맞춘다(10자는 약 9% 줄어든다).

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 정의 파일 (`templates/days.ts`)
```ts
import type { BadgeTemplateDef, TemplateArcSlot } from '../templateDef'
import type { TemplateSlot } from '../templateSvg'
import { DAYS_ORIGINAL_SVG } from './daysSvg'

/** `id`가 Union·Line으로 시작하지 않는 <path id="…">를 문서 순서대로 앞에서부터 name·value로 바꾼 사본. 그런 <path>가 정확히 둘이 아니면 원본을 그대로 돌려준다 */
export function nameSampleShapes(svg: string): string
export const DAYS_TEMPLATE: BadgeTemplateDef
```
- 원본의 `<path id=…>`는 `Union`, 이름 샘플, 값 샘플(`1000…`), `Line 1` 네 개다. 앞의 둘은 `Union`·`Line 1`이 아니라서 «이름 샘플 → name, 값 샘플 → value»가 된다. `<g id=…>`는 건드리지 않는다.
- `DAYS_TEMPLATE`: `classKey: 'days'`, `svg: nameSampleShapes(DAYS_ORIGINAL_SVG)`, `slots.viewBoxWidth: 702`, `viewBoxHeight: 1098`.
- 이름 자리(원호, `TemplateArcSlot`): `kind: 'arc'`, `cx: 351`, `cy: 300.49`, `baselineRadius: 178.13`, `centerDeg: 0.25`, `facing: 'outward'`, `maxSpanDeg: 177.2`, `fontFamily: 'Noto Sans KR'`, `fontWeight: '900'`, `fontSize: 84`, `letterSpacingEm: -0.0802`, `fill: '#000000'`.
- 값 자리(직선, `TemplateSlot`): `found: true`, `isText: true`, `x: 350.51`, `y: 949.75`, `fontFamily: 'Noto Sans KR'`, `fontSize: 116.44`, `fontWeight: '900'`, `fill: '#000000'`, `letterSpacing: '-0.0756em'`, `textAnchor: 'middle'`, `transform: null`, `placeholder: '1000일'`.
- 수치에는 «사용자가 준 `Group 15.svg`의 샘플 글자 모양에 Noto Sans KR 900을 겹쳐 맞춘 값이다. 그림을 바꾸면 다시 맞춘다. 굵기는 사용자가 말하지 않아 겹침이 가장 큰 900으로 정했다»는 주석을 단다.
- `templates/index.ts`: `BADGE_TEMPLATE_DEFS`에 `days: DAYS_TEMPLATE`를 더한다.

#### 2. 시험
- `templateDefs.test.ts`:
  - `getBadgeTemplateDef('days')`가 위 표의 값을 가진다(원호 자리는 `toMatchObject`, 값 자리도 같게). `'count'`만 `null`이다. `'metric'`·`'streak'`는 그대로다.
  - 공통(모든 정의): `viewBox`가 정의와 같다. `stripSlotText(def.svg)`에 `id="name"`·`id="value"`가 없다. 두 자리의 글꼴이 `fallback: false`, 굵기 900이다. 지금의 공통 확인 가운데 원호 자리를 전제로 한 줄이 있으면 직선 자리도 통과하게 둔다(streak가 이미 통과한다).
  - `days` 전용: `DAYS_ORIGINAL_SVG`에서 `Union`·`Line`으로 시작하지 않는 `<path id=…>`가 정확히 둘이고, `nameSampleShapes`의 결과에는 `id="name"`·`id="value"`가 한 번씩 있으며 원본과 다른 줄은 그 두 곳뿐이다. `<path id=…>`가 둘이 아닌 입력(예: 하나만 남긴 SVG)은 원본 그대로 돌려준다. `stripSlotText(DAYS_TEMPLATE.svg)` 뒤에 `id="Union"`·`id="Line 1"`·`id="Vector_3"`가 남아 있다. `extractSvgColors`가 `#000000`·`#990000`·`#FF0000`을 돌려준다(그라데이션 끝점의 색이 읽히지 않으면 아현이 `alerts`에 알린다).
  - 배치 계산: `layoutArcText`로 이름 자리 입력(글자 폭은 임의의 같은 값 9개, `advances: Array(9).fill(50)` 등)을 넣었을 때 `spanDeg`가 `maxSpanDeg` 이하이고 `shrunk`가 폭에 따라 맞게 나온다. `layoutSlotText`로 값 자리(`placeholderWidth: 355.5`, `contentWidth: 230`)를 넣으면 `anchorX ≈ 350.51`이고 `shrunk`는 false다.
- `templateItem.test.ts`: `listTemplateItems()`의 결과에서 `metric`·`days`·`streak`는 `svg`와 `slots`가 있고 `count`만 `null`이다.

### 주요 의사결정 / 핵심 메모
- 굵기를 900으로 정한 까닭: 사용자가 글꼴 이름(Noto Sans KR)만 알려 주었다. 원본 글자 모양과 겹친 비율이 가장 높은 굵기를 골랐고, 값의 겹침은 0.965로 높다. 틀렸다면 사용자가 알려 주면 이 정의의 `fontWeight`만 고친다.
- 이름 자리 겹침이 0.85에 머무는 까닭: 확인하지 못했다. 원호 위에서 글자를 놓는 규칙(글자마다 폭을 재서 호를 따라 놓음)과 피그마의 글자 놓는 방식이 완전히 같지 않을 수 있다. 오버레이 그림에서 글자 가장자리가 1~2px 어긋나는 정도였다.
- 이름 샘플(9자)보다 긴 10자 이름은 호의 각도를 177.2°에 맞추려고 약 9% 줄어든다. 더 넓은 각도를 쓰면 위쪽 Jam 글자와 가까워진다(각도 100° 부근에서 y≈330, Jam 윗변 y=354). 사용자가 더 큰 글자를 원하면 `maxSpanDeg`를 조정한다.
- 값 자리에는 글자 최대 폭 제한이 없다(알약 아래 반원의 안쪽 폭 약 442). 실제 값은 가장 긴 것이 «300일»이라 넘지 않는다.
- 바뀌는 파일이 다섯 개 안팎이라 `plan_only` 기준에 걸리지 않을 수 있으나, 파일 단위 계획과 수치를 이 티켓에 적었으므로 면제를 넘긴다.

- 아현의 리뷰 브랜치 push가 자동 권한 검사에서 거부됐다. 사용자가 두 번의 확인 끝에 허락(«둘 다 올려») 한 뒤 카리나가 올렸다(코드 수정 없음).
- 굵기 900은 사용자가 말하지 않아 카리나가 겹침이 가장 큰 값으로 정했다. 틀렸다면 정의의 `fontWeight`만 고친다.
- 이름 샘플(9자)보다 긴 10자 이름(하늘빛이 다른 자리)은 호의 각도를 177.2°에 맞추려고 약 9% 줄어든다.
- 실제 배지 이미지 등록은 하지 않았다.
