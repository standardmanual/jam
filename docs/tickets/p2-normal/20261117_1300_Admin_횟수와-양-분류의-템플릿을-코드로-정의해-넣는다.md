# [Admin] «횟수와 양» 분류의 템플릿을 코드로 정의해 넣는다

## 핵심 요약
- 요구사항: 사용자가 준 `Group 18.svg`를 분류 «횟수와 양»(`count`)의 템플릿으로 코드에 정의한다(사용자 지시, 2026-11-17: «횟수와 양 분류 템플릿 파일이야, 폰트는 동일한 Noto Sans», 이어서 «svg 파일 변경, name 이름, value 값»으로 파일을 바꿔 다시 주었다). 상위 티켓 20261115_2353의 14회차다. 이름과 값이 모두 직선 한 줄이라 새 배치 방식은 필요 없고, 글자가 마름모 안쪽을 넘지 않게 자리마다 최대 폭을 정할 수 있게 `maxWidth` 칸 하나를 더한다.
- 구현 계획: 원본 SVG는 카리나가 `templates/countSvg.ts`에 그대로 옮겨 커밋해 두었다. 아현은 `templates/count.ts`를 만들고 `templates/index.ts`에 등록하며, `maxWidth` 칸을 더하고 시험을 정리한다. 화면과 API는 바꾸지 않는다. «등록»은 이 템플릿을 코드에 넣는다는 뜻이고 배지 이미지를 올리지 않는다.
- 관련 파일:

  - **새 파일**

    - `jam-web/src/lib/admin/activityBadgeTemplate/templateSvg.ts`: `TemplateSlot`(29~42행 부근)에 `maxWidth?: number | null`을 더한다. 값은 viewBox 단위의 글자 폭 상한이고, 없으면 지금 규칙을 쓴다
    - `jam-web/src/lib/admin/activityBadgeTemplate/composeTemplate.ts`: `layoutSlotText`(74행 부근)가 `slot.maxWidth`가 양수이면 그 값을 상한으로 쓴다. 없으면 지금의 `2 × min(anchorX, viewWidth − anchorX) × 0.92`를 쓴다
    - `jam-web/src/app/admin/activity-badge-template/renderTemplateBadge.ts`: 직선 자리를 그릴 때 `layoutSlotText`의 `slot`에 `maxWidth: slot.maxWidth ?? null`을 함께 넘긴다(`layoutSlotText({ slot: { x, textAnchor, fontSize }, … })`를 부르는 곳)

## 배경 / 문제 정의
사용자가 정한 것(상위 티켓 「결정 사항」의 «템플릿을 넣는 방식»): 템플릿마다 그때그때 개발해서 넣는다. 네 번째이자 마지막 템플릿으로 «횟수와 양»의 `Group 18.svg`를 주었다. 사용자가 같은 이름의 파일을 한 번 바꿔서 다시 주었고, 이 티켓은 **바뀐 파일**(sha256 앞 12자리 9ebb231ba062)을 기준으로 한다.

카리나가 파일을 분석한 결과(2026-11-17):
- 크기는 1582×958이다. 가로로 긴 주황 마름모(바깥)와 연보라 마름모(안쪽), 양옆의 타원 줄무늬, 둘레의 «JOIN AND MOVE» 글자 모양, 안쪽 마름모 위쪽의 Jam 로고, 가운데의 이름과 값이다.
- 이름과 값은 실제 글자(`<text>`)이고 `id`가 이미 `name`·`value`다. 둘 다 Noto Sans KR, 굵기 900, 자간 −0.08em, 색 black이다. 사용자가 글꼴을 «동일한 Noto Sans»라고 했다.
- 글자 위치는 `transform="translate(…)"`과 `<tspan x y>`를 더해야 나온다:
  - 이름: 시작 x = 464.264 + 0.471375 = 464.7354, 기준선 y = 385.906 + 101.737 = 487.643, 크기 101.844, 샘플 «벼룩시장 건너편»(공백 포함 8자, 폭 627.3)
  - 값: 시작 x = 685.264 + 0.179871 = 685.4439, 기준선 y = 558.906 + 67.4463 = 626.3523, 크기 92.014, 샘플 «5가지»(폭 210.6)
- 두 샘플의 가운데는 이름 778.4, 값 790.75이고 그림의 세로 가운데 축은 x = 791이다. 이름이 12.6 왼쪽인 것은 샘플의 공백 폭이 피그마와 크롬에서 다른 데서 생긴 어긋남으로 카리나가 읽었다(확인하지 못했다). 이 템플릿은 **두 자리를 모두 가운데 축 x = 791에 가운데 맞춤**한다(`textAnchor: 'middle'`).
- 글자는 안쪽 마름모 안에 있어야 한다. 안쪽 마름모의 꼭짓점은 (790.82, 172.91)·(1294.38, 477.91)·(790.82, 782.90)·(287.26, 477.91)이다. 글자 윗부분(기준선 − 0.88×크기)과 아랫부분(기준선 + 0.2×크기)에서 마름모의 폭을 재고 양쪽 여백 40을 빼면 최대 폭은 이름 663.4, 값 376.2다.
- 이 분류 배지 9개의 이름은 3종(붕어빵 틀 대결, 벼룩시장 건너편, 처음 듣는 골목)이고 모두 공백 포함 8자라 이름 폭이 562~627로 상한 안이다. 값은 «N가지»·«첫 체크인»·«N개» 세 꼴이고 가장 긴 «첫 체크인»이 폭 335로 상한 안이다. 그래서 글자 크기를 줄이는 규칙은 지금 값에서는 발동하지 않는다.
- SVG의 색은 `#F95B1D`·`#D3ACFD`·`#222222`·`black`이다. `#222222` 줄무늬 경로에 `style="mix-blend-mode:overlay"`가 있고, Jam 글자 경로에 `fill-opacity="0.97"`이 있다. 이 속성들은 색 조정을 거쳐도 남아야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 정의 파일 (`templates/count.ts`)
```ts
import type { BadgeTemplateDef } from '../templateDef'
import type { TemplateSlot } from '../templateSvg'
import { COUNT_TEMPLATE_SVG } from './countSvg'

export const COUNT_TEMPLATE: BadgeTemplateDef
```
- `classKey: 'count'`, `svg: COUNT_TEMPLATE_SVG`(바꾸지 않는다), `slots.viewBoxWidth: 1582`, `viewBoxHeight: 958`.
- 두 자리는 `TemplateSlot`이다(원호 아님):

| 자리 | found | isText | x | y | fontFamily | fontSize | fontWeight | fill | letterSpacing | textAnchor | transform | placeholder | maxWidth |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| name | true | true | 791 | 487.64 | 'Noto Sans KR' | 101.84 | '900' | '#000000' | '-0.08em' | 'middle' | null | '벼룩시장 건너편' | 663.4 |
| value | true | true | 791 | 626.35 | 'Noto Sans KR' | 92.01 | '900' | '#000000' | '-0.08em' | 'middle' | null | '5가지' | 376.2 |

- `transform`은 null이다(원본의 `translate`는 x·y에 더해 적었다). 수치에는 «사용자가 준 `Group 18.svg`의 글자 속성이고, 가운데 맞춤은 그림의 세로 가운데 축(x = 791)에 둔다. 최대 폭은 안쪽 마름모에서 양쪽 여백 40을 뺀 값이다»라는 주석을 단다.
- `templates/index.ts`: `BADGE_TEMPLATE_DEFS`에 `count: COUNT_TEMPLATE`를 더한다.

#### 2. 최대 폭 (`maxWidth`)
- `TemplateSlot.maxWidth?: number | null`, `layoutSlotText`는 `slot.maxWidth`가 0보다 크면 그것을 상한으로 쓴다. 이 값이 `contentWidth`보다 작으면 `fontSizePx = slot.fontSize × maxWidth ÷ contentWidth`, `shrunk: true`다.
- 기존 템플릿(`streak`)은 `maxWidth`가 없어서 동작이 바뀌지 않는다.

#### 3. 시험
- `templateDefs.test.ts`: `getBadgeTemplateDef('count')`가 위 표의 값을 가진다. `metric`·`days`·`streak`·`count` 네 분류가 모두 정의를 가진다(`days`는 아직 머지되지 않았다면 이 시험에서 `days`는 건드리지 않는다. 이 티켓의 브랜치에 `days`가 없으면 `metric`·`streak`·`count`만 확인한다). 공통 시험(viewBox 일치, `stripSlotText` 뒤 `id="name"`·`id="value"` 없음, 글꼴 `fallback: false`·굵기 900)이 `count`에도 돈다.
- `count` 전용:
  - `stripSlotText(COUNT_TEMPLATE.svg)` 뒤에 `<text`가 없고 `id="Rectangle 10"`·`id="Rectangle 11"`·`id="Vector"`가 남아 있다.
  - `extractSvgColors`가 `#F95B1D`·`#D3ACFD`·`#222222`·`#000000`을 돌려준다.
  - `applyColorMap`으로 색을 바꾼 결과에도 `mix-blend-mode:overlay`와 `fill-opacity="0.97"`이 그대로 남아 있다(색만 바뀐다). 남지 않으면 `templateColors.ts`의 `style`·`fill-opacity` 처리를 고치되 `alerts`에 `[주의]`로 알린다.
  - 직선 배치: `layoutSlotText({ slot: name 자리, viewWidth: 1582, placeholderWidth: 627.3, contentWidth: 562.2 })`의 `anchorX`가 791이고 `shrunk`는 false다. `contentWidth: 700`이면 `shrunk: true`이고 `fontSizePx ≈ 101.84 × 663.4 ÷ 700 = 96.52`다. 값 자리도 `contentWidth: 335`는 `shrunk` false, `contentWidth: 420`은 `fontSizePx ≈ 92.01 × 376.2 ÷ 420 = 82.42`다.
- `composeTemplate.test.ts`: `maxWidth`가 없으면 지금 규칙이고(기존 시험이 통과), 있으면 위 규칙을 따른다.
- `templateItem.test.ts`: `listTemplateItems()`의 네 분류가 모두 `svg`와 `slots`를 가진다(`days`가 이 브랜치에 없으면 있는 분류만 확인한다).

### UI/UX 관점 (해당 시)
- 해당 없음(화면을 바꾸지 않는다). `listTemplateItems()`가 정의를 읽으므로 «횟수와 양» 배지를 고르면 이 템플릿으로 미리보기가 그려진다.

### 주요 의사결정 / 핵심 메모
- 샘플의 가운데가 아니라 그림의 세로 가운데 축(x = 791)에 맞춘 까닭: 이름 샘플의 가운데가 축에서 12.6 어긋나 있는데, 값 샘플은 0.25 이내로 맞는다. 어긋남은 샘플의 공백 폭 차이로 보이고(확인하지 못했다), 디자이너가 가운데로 놓으려 한 뜻을 따랐다. 틀렸다면 사용자가 알려 주면 `x`만 고친다.
- 처음 준 `Group 18.svg`(세로로 긴 물방울 모양, 이름이 두 줄)는 쓰지 않는다. 사용자가 같은 이름의 새 파일로 바꿨다. 두 줄 이름 배치는 만들지 않았다.
- 파일 수가 여덟 개 안팎이라 `plan_only` 기준에 걸릴 수 있어, 파일 단위 계획과 수치를 이 티켓에 적었으므로 면제를 넘긴다.
