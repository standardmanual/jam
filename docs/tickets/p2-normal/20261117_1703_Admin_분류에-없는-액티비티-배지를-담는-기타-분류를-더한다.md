# [Admin] 분류에 없는 액티비티 배지를 담는 «기타» 분류를 더한다

## 핵심 요약
- 요구사항: 액티비티 배지 가운데 네 분류(운동 수치, 쌓은 날, 이어 온 날, 횟수와 양)에 들어가지 않는 배지를 모두 «기타» 분류(`etc`)로 둔다(사용자 지시, 2026-11-17: «액티비티 배지중에 분류에 추가 되지 않은 배지들은 기타 분류를 추가해서 배치해. 템플릿도 기타 분류를 전달할게»). 이번에는 분류와 값 글자를 정하는 규칙, 검색 필터, 분류 목록까지 하고, **기타 템플릿(SVG)은 사용자가 나중에 준다**. 그때까지 «기타» 배지를 고르면 «기타 템플릿이 아직 준비되지 않았어요.»가 보인다. 상위 티켓 20261115_2353의 15회차다.
- 구현 계획: 분류 규칙 함수(`resolveBadgeTemplateText`)가 네 분류에 맞지 않는 배지를 `null`이 아니라 `etc`로 돌려주게 하고, 분류 키·이름·목록·필터·시험·문서에 `etc`를 더한다.
- 관련 파일(모두 `jam-web/src` 아래):
  - `lib/admin/activityBadgeTemplate/resolveTemplateText.ts`: `BadgeTemplateClassKey`(7행), `BADGE_TEMPLATE_CLASS_LABEL`(9행), `RULES`(62행 부근), `PRIORITY`, `resolveBadgeTemplateText`(마지막 함수), `UNSUPPORTED_CONDITION_KEYS`, `TEMPLATE_RULE_KEYS`
  - `lib/admin/activityBadgeTemplate/templateItem.ts`: `TEMPLATE_CLASS_KEYS`(7행), `listTemplateItems`
  - `lib/admin/activityBadgeImageSearch.ts`, `app/admin/activity-badge-template/BadgePicker.tsx`, `lib/admin/activityBadgeTemplate/studioBadge.ts`, `templateDef.ts`, `templates/index.ts`: 분류 키 타입을 쓰는 곳. 타입 오류가 나는 곳을 `etc`에 맞게 고친다(분류 필터의 선택지는 `BADGE_TEMPLATE_CLASS_LABEL`에서 만들어지므로 «기타»가 자동으로 더해지는지 확인한다)
  - 시험: `lib/admin/activityBadgeTemplate/__tests__/resolveTemplateText.test.ts`, `__tests__/templateItem.test.ts`, `__tests__/templateDefs.test.ts`, `lib/admin/__tests__/activity-badge-image-search.test.ts`, `app/api/admin/activity-badge-image/search/__tests__/route.test.ts`, `app/admin/activity-badge-template/__tests__/BadgeStudioParts.test.tsx`
  - 문서: `docs/service/prd/asset-generator/PRD.md` 17절(17.3 정의된 분류 목록, 17.5 분류 필터), `docs/service/content/`에 분류를 적은 문서가 있으면 함께 고친다(`grep -rn "횟수와 양" docs/service`로 찾는다)

## 배경 / 문제 정의
지금 분류 규칙은 획득 조건(`condition_json`)에서 분류를 뽑고, 맞는 것이 없으면 `null`(분류 없음)을 돌려준다. 2026-11-17 조회한 결과 이미지 제작 대상 액티비티 배지 320개 가운데 39개가 분류 없음이다(JAM 분류 70개는 검색에서 빠진다). 분류 없음 배지는 미리보기도 등록도 할 수 없다. 사용자가 이들을 «기타»로 모으고 템플릿을 따로 주겠다고 했다.

분류 없음 39개의 내용(2026-11-17 DB 조회):

| 계열 | 개수 | 예 | 조건 칸 |
|---|---|---|---|
| running:K3, hiking:K3, trail_running:K3, cycling:K3 | 각 6, 합 24 | 달린 횟수, 오른 횟수 | `total_count`, `activity_type` |
| running:C2, cycling:C2, walking:P2 | 각 4, 합 12 | 이번 주의 페이스, 이번 주의 바퀴, 이번 주의 약속 | `weekly_count`, `repeat_count`, `activity_type` |
| walking:A6 | 3 | 초하루의 사람 | `total_count`, `day_of_month`, `activity_type` |

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. 분류 키와 이름
- `BadgeTemplateClassKey`에 `'etc'`를 더한다. `BADGE_TEMPLATE_CLASS_LABEL.etc`는 `'기타'`다.
- `TEMPLATE_CLASS_KEYS`는 `['metric', 'days', 'streak', 'count', 'etc']` 순서다. `listTemplateItems()`는 다섯 항목을 이 순서로 돌려주고, `etc`는 코드에 정의된 템플릿이 없어 `svg`와 `slots`가 `null`이다.

#### 2. 분류 판정 (`resolveBadgeTemplateText`)
- 네 분류의 규칙과 우선순위(`streak`, `days`, `metric`, `count`)는 **바꾸지 않는다**. 어느 분류에도 맞지 않으면 `null` 대신 `{ classKey: 'etc', value }`를 돌려준다.
- `etc`의 값은 아래 순서로 정한다(사용자가 정한 것이 아니라 카리나가 정한 임시 규칙이다. 기타 템플릿을 받으면 다시 정한다):
  1. `total_count`가 숫자면 `«N회»`(예: 30 → «30회»)
  2. `weekly_count`가 숫자면 `«주 N회»`(예: 3 → «주 3회»)
  3. 위가 모두 아니면 빈 글자 `''`
- `RULES`는 지금처럼 네 분류만 가진다(`Record<Exclude<BadgeTemplateClassKey, 'etc'>, Rule[]>`). `etc`는 위 두 줄을 별도 함수로 처리한다.
- `UNSUPPORTED_CONDITION_KEYS`에서 `weekly_count`를 빼고, 위 규칙이 쓰는 칸임이 드러나게 `TEMPLATE_RULE_KEYS`(규칙표 칸 전체, 「새 칸 감시」 시험이 쓰는 목록)에 `'weekly_count'`를 더한다. `day_of_month`는 지금처럼 미지원 목록에 둔다. 「새 칸 감시」 시험이 통과해야 한다.
- 반환 타입은 `BadgeTemplateText | null`을 그대로 둔다(호출부의 `null` 처리를 건드리지 않는다). 실제로는 `null`이 나오지 않는다는 주석을 단다.

#### 3. 검색과 화면
- 검색 요청의 `templateClass`에 `'etc'`가 들어오면 기타 분류 배지만 돌려준다(`parseActivityBadgeImageSearchParams`가 `BADGE_TEMPLATE_CLASS_LABEL`의 키를 받으므로 자동으로 받는지 확인한다. 아니면 고친다).
- 분류 선택 상자의 선택지는 «전체 분류», «운동 수치», «쌓은 날», «이어 온 날», «횟수와 양», «기타»다.
- 결과 표의 «분류» 칸에는 «기타»가 보인다. «없음»은 이제 나오지 않는다.
- 미리보기: 기타 배지를 고르면 «기타 템플릿이 아직 준비되지 않았어요.»가 보인다(지금의 «{분류 이름} 템플릿이 아직 준비되지 않았어요.» 문구가 그대로 쓰인다). 등록 버튼은 보이지 않는다.

#### 4. 시험
- `resolveTemplateText.test.ts`:
  - `{ total_count: 30, activity_type: 'running' }` → `{ classKey: 'etc', value: '30회' }`
  - `{ weekly_count: 3, repeat_count: 4, activity_type: 'cycling' }` → `{ classKey: 'etc', value: '주 3회' }`
  - `{ day_of_month: 1, total_count: 12, activity_type: 'walking' }` → `{ classKey: 'etc', value: '12회' }`
  - `{ activity_type: 'running' }`과 `{}`와 `null` → `{ classKey: 'etc', value: '' }`
  - 기존 네 분류의 규칙표 시험이 그대로 통과한다. 지금 «판정 불가는 null»을 확인하는 시험(64행 부근)은 «판정 불가는 기타»로 고친다
  - 「새 칸 감시」가 통과한다
- `templateItem.test.ts`: `listTemplateItems()`가 다섯 항목을 `metric`, `days`, `streak`, `count`, `etc` 순서로 돌려주고 앞의 넷은 `svg`와 `slots`가 있고 `etc`만 `null`이다.
- `templateDefs.test.ts`: `getBadgeTemplateDef('etc')`가 `null`이고 네 분류는 정의가 있다. 지금 «네 분류가 모두 정의를 가진다» 시험은 그대로 둔다.
- 검색 시험(`activity-badge-image-search.test.ts`, 라우트 시험): `templateClass: 'etc'`를 받는다. 라우트 시험은 `etc`로 부르면 응답이 모두 `templateClass: 'etc'`인 것을 확인한다.
- `BadgeStudioParts.test.tsx`: 분류 선택 상자의 선택지가 여섯 개(전체 분류 + 다섯 분류)다.

### UI/UX 관점 (해당 시)
- 분류 선택 상자 폭(`sm:w-36`)과 순서는 그대로이고 «기타»가 맨 끝에 더해진다. 문구는 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

## 구현 계획
1. `resolveTemplateText.ts`에 `etc`와 값 규칙을 더하고 시험을 고친다.
2. `templateItem.ts`와 타입 오류가 나는 곳을 고친다.
3. 검색·화면 시험을 고친다.
4. PRD 17절과 분류를 적은 문서를 고친다.

### 주요 의사결정 / 핵심 메모
- 기타의 값 규칙(«N회», «주 N회», 없으면 빈 글자)은 사용자가 정한 것이 아니다. 분류 없음 배지 39개 가운데 24개는 `total_count`(활동 횟수), 12개는 `weekly_count`(주당 횟수)를 쓰고 3개는 `total_count`와 `day_of_month`를 함께 쓴다. 이 칸들을 «횟수와 양» 분류로 옮길 수도 있었지만 사용자가 «분류에 추가되지 않은 배지는 기타»라고 했으므로 네 분류의 규칙은 바꾸지 않았다. 템플릿을 받으면 값 규칙을 다시 정한다.
- 기타는 `null`(분류 없음)을 대신한다. 그래서 «분류를 정하지 못했어요» 안내(`BadgePreview.tsx`)는 더 나오지 않는다. 그 안내 코드는 지우지 않는다(호출부 타입이 `null`을 받는다).
- 바뀌는 파일이 열 개 안팎이라 `plan_only` 기준에 걸릴 수 있어, 파일 단위 계획과 시험 기대값을 이 티켓에 적었으므로 면제를 넘긴다.
