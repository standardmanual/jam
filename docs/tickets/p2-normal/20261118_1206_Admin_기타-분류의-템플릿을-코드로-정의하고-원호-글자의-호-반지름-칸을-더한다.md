# [Admin] «기타» 분류의 템플릿을 코드로 정의하고 원호 글자의 «호 반지름» 칸을 더한다

## 핵심 요약
- 요구사항: 사용자가 준 `Group 28.svg`를 분류 «기타»(`etc`, 티켓 20261117_1703)의 템플릿으로 코드에 정의한다(사용자 지시, 2026-11-18: «기타 분류 템플릿으로 만들어»). 이름은 위쪽 원호, 값은 아래쪽 원호이고 글자는 사용자가 알려 준 설정(Noto Sans KR Black, 크기 111, 자간 −8%)이다. 상위 티켓 20261115_2353의 16회차다.
- 구현 계획: 원본 SVG는 카리나가 `templates/etcSvg.ts`에 그대로 옮겨 두었다. 아현은 `templates/etc.ts`를 만들고 `index.ts`에 등록한다. 원호 자리에 선택 칸 `pathRadius`(글자 사이 간격을 재는 호의 반지름)를 더하고, 시험을 정리한다. «등록»은 이 템플릿을 코드에 넣는다는 뜻이고 배지 이미지를 올리지 않는다.
- 관련 파일(모두 `jam-web/src/lib/admin/activityBadgeTemplate/` 아래, 화면 파일은 `jam-web/src/app/admin/activity-badge-template/`):
  - **이미 있다(카리나가 사용자의 파일을 그대로 옮겨 두었다. 고치지 않는다)**: `templates/etcSvg.ts`(`ETC_TEMPLATE_SVG`, 975×1153)
  - **새 파일**: `templates/etc.ts`

## 배경 / 문제 정의
사용자가 정한 것(상위 티켓 「결정 사항」의 «템플릿을 넣는 방식»): 템플릿마다 그때그때 개발해서 넣는다. «기타» 분류는 네 분류에 들어가지 않는 배지 39개를 담고(티켓 20261117_1703), 템플릿은 사용자가 따로 주기로 했다.

카리나가 파일을 분석하고 글자를 맞춘 결과(2026-11-18):
- 크기는 975×1153이다. 구슬 모양의 초록 고리(위아래 두 원이 옆에서 맞물린 모양), 가운데 주황 타원, Jam 로고, 안쪽의 «JOIN»·«MOVE» 글자 모양이다.
- 이름(`<path id="name">`)은 위쪽 원호다. 샘플은 «동해물과 백두산이 백두산이»(공백 포함 14자)이고 각도 약 182°를 차지한다.
- 값(`<path id="value">`)은 아래쪽 원호이고 글자 윗부분이 중심을 향한다. **샘플 글자가 «JOIN AND MOVE»**이다. 사용자가 이 자리를 값으로 정했고, 이름과 값의 글자 설정을 같게(Noto Sans KR Black 크기 111 자간 −8%) 알려 주었다. 그래서 값으로 처리한다(이 슬로건은 그릴 때 걷어 내져 사라지고 그 자리에 값 글자가 놓인다).
- 글자 설정을 그대로 놓았을 때 원본과 맞으려면 **글자 사이 간격을 재는 호의 반지름**이 글자를 놓는 기준선의 반지름과 달라야 한다. 이름은 기준선 319.6에 간격은 369.3(+49.7), 값은 기준선 400.8에 간격은 372.5(−28.3)에서 가장 잘 맞는다(원본과 겹치는 비율 이름 0.70, 값 0.83). 같은 크기·자간으로 기준선 반지름 하나만 쓰면 이름이 원본보다 약 10% 넓게 퍼지고 겹치는 비율이 0.35, 값 0.48로 떨어진다. 피그마가 글자를 호 위에 놓을 때 글자 가운데쯤의 호를 따라 간격을 재기 때문으로 카리나가 읽었다(확인하지 못했다).
- 이름은 가운데와 오른쪽이 원본과 잘 맞고, 샘플이 14자일 때 왼쪽 끝 글자 몇 개가 원본보다 조금 어긋난다. 기타 배지의 이름은 가장 긴 것이 «이번 주의 페이스»(8자, 각도 약 110°)라서 가운데 쪽에 놓여 영향이 작다. 값은 가장 긴 것이 «320회» 꼴이고 각도 약 43°다.
- SVG의 색은 `#FF3A00`·`#00892B`·`black`·`white`다.

## 상세 요구사항

### 서비스/코드베이스 관점

#### 1. `pathRadius` (`arcText.ts`, `templateDef.ts`)
- `ArcTextInput.pathRadius?: number`, `TemplateArcSlot.pathRadius?: number`. 값이 없으면 `baselineRadius`와 같다(기존 템플릿 `metric`·`days`의 계산이 달라지지 않는다).
- 글자의 위치 `(x, y)`는 지금처럼 `baselineRadius`(R)로 정한다. **바뀌는 것은 각도뿐이다:** 글자 사이 각도 `a = ((cursor + w/2) / P) × DEG`와 `spanDeg = (length / P) × DEG`, 줄이는 규칙의 `span0 = (length0 / P) × DEG`에서 `R` 대신 `P = pathRadius ?? baselineRadius`를 쓴다.
- `pathRadius`가 0 이하이거나 유한한 수가 아니면 `null`을 돌려준다(`baselineRadius`와 같은 검사).

#### 2. 정의 파일 (`templates/etc.ts`)
```ts
import type { BadgeTemplateDef } from '../templateDef'
import { ETC_TEMPLATE_SVG } from './etcSvg'
export const ETC_TEMPLATE: BadgeTemplateDef
```
- `classKey: 'etc'`, `svg: ETC_TEMPLATE_SVG`(바꾸지 않는다, 레이어 이름이 이미 `name`·`value`다), `slots.viewBoxWidth: 975`, `viewBoxHeight: 1153`.
- 두 자리는 원호(`TemplateArcSlot`)다. 공통 값: `kind: 'arc'`, `fontFamily: 'Noto Sans KR'`, `fontWeight: '900'`, `fontSize: 111`, `letterSpacingEm: -0.08`, `fill: '#000000'`.

| 자리 | cx | cy | baselineRadius | pathRadius | centerDeg | facing | maxSpanDeg |
|---|---|---|---|---|---|---|---|
| name | 489 | 471.8 | 319.63 | 369.34 | 0 | outward | 181.8 |
| value | 487.56 | 682 | 400.75 | 372.5 | 180 | inward | 122.5 |

- 수치에는 «사용자가 준 `Group 28.svg`의 샘플 글자 모양에 사용자가 알려 준 글자 설정(크기 111, 자간 −8%)을 겹쳐 맞춘 값이다. 이름의 왼쪽 끝은 샘플이 길 때 조금 어긋난다»라는 주석을 단다.
- `templates/index.ts`: `BADGE_TEMPLATE_DEFS`에 `etc: ETC_TEMPLATE`를 더한다. 이제 다섯 분류가 모두 정의를 가진다.

#### 3. 시험
- `arcText.test.ts`: 입력 `advances: [50, 50]`, `fontSize: 100`, `letterSpacingEm: 0`, `cx: 0`, `cy: 0`, `baselineRadius: 100`, `pathRadius: 200`, `centerDeg: 0`, `facing: 'outward'`, `maxSpanDeg: 180`이면 `spanDeg ≈ 28.648`, 첫 글자 `rotationDeg ≈ −7.162`, `x ≈ −12.467`, `y ≈ −99.220`, 둘째 글자는 부호만 반대(`x ≈ 12.467`, 같은 `y`)다. `pathRadius`가 없으면 기존 결과와 같다(기존 시험이 통과한다). `inward`·`centerDeg: 180`이면 첫 글자가 `x ≈ −12.467`, `y ≈ 99.220`, `rotationDeg ≈ 7.162`다. `maxSpanDeg: 14.324`이면 `shrunk` true, `scale ≈ 0.5`, `fontSize ≈ 50`이다. `pathRadius: 0`은 `null`이다.
- `templateDefs.test.ts`: `getBadgeTemplateDef('etc')`가 위 표의 값을 가지고 다섯 분류가 모두 정의를 가진다(이전 «etc는 null» 시험을 이에 맞게 고친다). 공통 시험(viewBox 일치, `stripSlotText` 뒤 `id="name"`·`id="value"` 없음, 글꼴 `fallback: false`·굵기 900)이 `etc`에도 돈다. `etc` 전용: `stripSlotText(ETC_TEMPLATE.svg)` 뒤에 `id="Union"`·`id="Union (Stroke)"`·`id="Vector_2"`가 남아 있다. `extractSvgColors`가 `#FF3A00`·`#00892B`·`#000000`·`#FFFFFF`를 돌려준다. `layoutArcText`로 이름 자리(글자 8개, 폭 각 80)를 놓으면 `spanDeg`가 `maxSpanDeg` 이하다.
- `templateItem.test.ts`: `listTemplateItems()`의 다섯 분류가 모두 `svg`와 `slots`를 가진다.

### 주요 의사결정 / 핵심 메모
- 값 자리의 샘플이 «JOIN AND MOVE»인데 값으로 처리한 까닭: 사용자가 레이어 이름을 `value`로 지었고, 이름과 같은 글자 설정을 값 자리에도 알려 주었다. 슬로건을 그대로 두려는 뜻이라면 사용자가 레이어 이름을 바꿔 주면 이 정의의 값 자리를 지운다.
- `pathRadius`를 따로 둔 까닭: 사용자가 알려 준 글자 설정(크기 111, 자간 −8%)을 기준선 반지름 하나로 놓으면 원본과 어긋난다(겹침 0.35·0.48). 호 반지름을 둘로 나누면 0.70·0.83으로 오른다. 원인은 피그마가 글자 가운데쯤의 호를 따라 간격을 재기 때문이라고 읽었으나 확인하지 못했다.
- 이름 자리의 겹침이 0.70에 머무는 까닭은 확인하지 못했다. 원호 규칙이 피그마와 완전히 같지 않을 수 있다. 이름 샘플이 14자라 왼쪽 끝이 조금 어긋나고, 실제 이름(최대 8자)은 가운데에 놓여 영향이 작다.
- 이름의 원 중심 `cy`가 471.8로 고리의 위쪽 원 중심(487.5)과 다른 것도 맞춤의 결과이고 이유를 확인하지 못했다.
- 바뀌는 파일이 여덟 개 안팎이라 `plan_only` 기준에 걸릴 수 있어, 파일 단위 계획과 수치를 이 티켓에 적었으므로 면제를 넘긴다.

### 잔여 이슈
- 이름 자리 왼쪽 끝 어긋남과 `cy` 471.8의 근거는 확인하지 못했다(실제 이름 길이에서는 눈에 띄지 않았다).
- 값 규칙(`N회`·`주 N회`·빈 값)은 카리나가 임시로 정했고 사용자와 확인이 남았다.
