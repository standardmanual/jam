# [Admin] «횟수와 양» 분류의 템플릿을 새 그림(Group 30)으로 바꾸고 두 자리를 원호로 옮긴다

## 핵심 요약
- 요구사항: «횟수와 양»(`count`) 분류의 템플릿을 사용자가 준 `Group 30.svg`로 바꾼다(사용자 지시, 2026-11-18: «횟수와 양 템플릿 변경»). 옛 그림(`Group 18.svg`, 마름모 안의 직선 글자 두 줄)은 새 그림으로 완전히 대체한다. 상위 티켓 20261115_2353의 17회차다.
- 새 그림: 616×409. 위쪽 빨간 띠에 이름(`<path id="name">`), 아래쪽 주황 띠에 값(`<path id="value">`)이 모두 **원호 글자**이고 가운데에 Jam 로고가 있다. 두 샘플 글자가 모두 «입양 칸에서 온 물건»이다. 이름 자리는 가운데가 위로 솟은 호(바깥쪽 글자), 값 자리는 가운데가 아래로 처진 호(글자 윗부분이 중심을 향함)다. 그림 아래쪽 바깥의 «JOIN AND MOVE» 장식(`<g id="Vector">`)은 그림의 일부로 그대로 남긴다.
- 구현 계획: 원본 SVG는 카리나가 `templates/countSvg.ts`에 이미 그대로 옮겨 두었다(고치지 않는다). 아현은 `templates/count.ts`를 직선 두 자리에서 **원호 두 자리**로 다시 쓴다. 원호 자리와 `pathRadius`는 기타(티켓 20261118_1206)에서 이미 만들었으므로 새 코드는 필요 없다.
- 관련 파일(모두 `jam-web/src/lib/admin/activityBadgeTemplate/` 아래):
  - **이미 바뀌었다(고치지 않는다)**: `templates/countSvg.ts`(`COUNT_TEMPLATE_SVG`, 616×409)
  - **다시 쓴다**: `templates/count.ts`(`COUNT_TEMPLATE`을 원호 자리로. 직선 자리의 `common`·`name`·`value`와 `TemplateSlot` import를 지운다)
  - **고친다(시험)**: `__tests__/templateDefs.test.ts`(`count는 표의 수치를 가진다`(62행 부근)와 `count 전용`(291행 부근)을 새 구성으로)
  - **읽기만**: `templates/etc.ts`(원호 두 자리의 본보기), `arcText.ts`의 `layoutArcText`, `composeTemplate.ts`의 `stripSlotText`(글자가 아닌 모양도 `id`가 `name`·`value`이면 통째로 지운다)
  - **문서**: `docs/service/prd/asset-generator/PRD.md`(642행 부근 «지금 정의가 있는 분류»의 `count` 설명을 «직선 글자·가운데 축 x = 791·마름모 최대 폭»에서 새 설명으로)

## 배경 / 문제 정의
사용자 결정(상위 티켓 「결정 사항」): 템플릿마다 그때그때 개발해서 넣는다. 이번에는 «횟수와 양»의 그림이 통째로 바뀌었고 글자 자리가 직선에서 원호로 바뀐다.

카리나가 파일을 분석하고 글자를 맞춘 결과(2026-11-18, 헤드리스 크롬에서 Noto Sans KR 900으로 샘플 모양에 글자를 겹쳐 맞춤):
- 이름·값 모두 글꼴은 Noto Sans KR Black(900)에 **크기 54, 자간 −6.5%**(−0.065em)로 두면 두 자리 모두 원본과 잘 맞는다(원본과 겹치는 비율 이름 0.80, 값 0.795). 크기·자간은 사용자가 따로 알려 주지 않았고, 이름과 값을 같게 두고 맞춘 값이다. 자리마다 따로 맞추면 겹침이 0.78 안팎이라 같은 값을 쓰는 편이 낫다.
- 기타 템플릿과 같이 글자 사이 간격을 재는 호의 반지름(`pathRadius`)이 글자를 놓는 기준선의 반지름과 조금 다르다(이름 650 대 666.25, 값 656 대 633).
- 이름은 윗호의 가운데가 x ≈ 308.6, 값은 아랫호의 가운데가 x ≈ 308.4다(그림 가운데 308보다 조금 치우친다. 맞춘 값을 그대로 쓴다).
- 샘플 이름의 각도는 약 35°, 값은 약 37°다. 띠 안에서 양옆에 남는 여유를 보고 최대 각도는 두 자리 모두 40°로 둔다(넘으면 글자가 작아진다).
- SVG의 색은 `#FFA100`(주황)·`#FF0000`(빨강)·`black`·`white`다. 옛 그림에 있던 `mix-blend-mode`·`fill-opacity`는 없다.

### 서비스/코드베이스 관점

#### 1. 정의 파일 (`templates/count.ts`)
```ts
import type { BadgeTemplateDef } from '../templateDef'
import { COUNT_TEMPLATE_SVG } from './countSvg'
export const COUNT_TEMPLATE: BadgeTemplateDef
```

- `classKey: 'count'`, `svg: COUNT_TEMPLATE_SVG`(바꾸지 않는다), `slots.viewBoxWidth: 616`, `viewBoxHeight: 409`.
- 두 자리는 원호(`TemplateArcSlot`)다. 공통 값: `kind: 'arc'`, `fontFamily: 'Noto Sans KR'`, `fontWeight: '900'`, `fontSize: 54`, `letterSpacingEm: -0.065`, `fill: '#000000'`, `maxSpanDeg: 40`.

| 자리 | cx | cy | baselineRadius | pathRadius | centerDeg | facing |
|---|---|---|---|---|---|---|
| name | 308.625 | 735.25 | 650 | 666.25 | 0 | outward |
| value | 308.375 | -352.125 | 656 | 633 | 180 | inward |

- 수치에는 «사용자가 준 `Group 30.svg`의 샘플 글자 모양에 Noto Sans KR 900(크기 54, 자간 −6.5%)을 겹쳐 맞춘 값이다. 크기·자간은 사용자가 지정한 값이 아니라 두 자리를 같게 두고 맞춘 값이다»라는 주석을 단다. 옛 직선 자리 설명(마름모·가운데 축 x = 791)은 지운다.
- `templates/index.ts`는 이미 `count: COUNT_TEMPLATE`를 등록하고 있으므로 바꾸지 않는다.

#### 2. 시험 (`__tests__/templateDefs.test.ts`)
- `count는 표의 수치를 가진다`: `getBadgeTemplateDef('count')`가 위 표의 값(`viewBoxWidth` 616, `viewBoxHeight` 409, 두 원호 자리가 표와 같음)을 가진다. 기타 시험(`etc는 표의 수치를 가진다`)과 같은 모양으로 쓴다.
- `count 전용`(291행 부근)을 새 그림에 맞게 바꾼다: ① `stripSlotText(COUNT_TEMPLATE.svg)`를 거치면 `id="name"`·`id="value"`가 사라지고 `id="Subtract"`·`id="Subtract_2"`·`id="Vector_2"`·`id="Vector"`는 남는다. ② `extractSvgColors`가 `#FFA100`·`#FF0000`·`#000000`·`#FFFFFF`를 돌려준다(대소문자는 올려서 비교). ③ 색 바꿈 시험은 옛 그림의 `mix-blend-mode`·`fill-opacity`를 확인하던 부분을 지우고, `applyColorMap`으로 모든 색을 `#123456`으로 바꾸면 결과에 `#123456`이 있고 `#FFA100`이 없는지만 본다. ④ 두 자리가 원호 자리(`isArcSlot`이 `true`)다. ⑤ 직선 배치 시험(`layoutSlotText`)은 지운다. 대신 `layoutArcText`로 이름 자리에 글자 9개(각 폭 40)를 놓았을 때 `spanDeg`가 `maxSpanDeg` 이하이고, 글자 20개(각 폭 40)를 놓으면 `shrunk`가 `true`이며 `spanDeg`가 `maxSpanDeg` 이하인지 본다.
- 이 파일의 다른 시험(공통 시험: viewBox 일치, `stripSlotText` 뒤 name·value 없음, 글꼴 `fallback: false`·굵기 900)은 `BADGE_TEMPLATE_DEFS`를 돌기 때문에 `count`에도 그대로 적용된다. 통과하는지 확인한다.
- 다른 시험 파일이 `count`의 직선 값(`1582`, `791` 등)을 쓰고 있으면 함께 고친다(`grep`으로 찾는다. 지금 확인한 곳은 `templateDefs.test.ts`뿐이다).

#### 3. PRD (`docs/service/prd/asset-generator/PRD.md` 642행 부근)
- «`count`(횟수와 양, 직선 글자, `templates/count.ts`·티켓 20261117_1300)»를 «`count`(횟수와 양, 이름 위쪽 원호·값 아래쪽 원호 둘 다 원호 자리, `templates/count.ts`·티켓 20261118_1506, 사용자가 준 `Group 30.svg`를 그대로 옮긴 `countSvg.ts`)»로 고친다.
- «`count`의 두 자리는 가운데 축(x = 791)에 가운데 맞춤이고 `maxWidth`로 안쪽 마름모 안의 최대 폭을 정한다.» 문장을 지운다. 그림 아래 바깥의 «JOIN AND MOVE»는 그림의 일부이고 글자 자리가 아니라는 한 문장을 더한다.
