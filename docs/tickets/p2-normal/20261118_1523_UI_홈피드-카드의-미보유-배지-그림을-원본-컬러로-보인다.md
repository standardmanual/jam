# [UI] 홈피드 카드의 미보유 배지 그림을 원본 컬러로 보인다

## 핵심 요약

- 요구사항: 홈피드 카드에 보이는 배지 그림은 유저가 그 배지를 갖지 않았어도 원본 컬러로 그린다. 카드를 눌러 이동한 상세 화면(`/badges/[id]` 등)은 지금처럼 미보유를 회색으로 보인다(이번 티켓에서 건드리지 않는다).
- 구현 계획: 홈피드 카드 전용 흑백 장치를 통째로 걷는다. 표시 데이터(`toCardView`)의 흑백 값 3개(`imageDimmed`·`thumbnailDimmed`·타일 `earned`)와 그 값을 읽는 컴포넌트 분기(`CardImageSlot`·`CardThumb`·`BriefCard`·`ListCard`)를 지우고, 시험·Story·견본 화면·PRD를 새 규칙에 맞춘다. 아래 「구현 계획」에 파일 단위로 적었다.
- 관련 파일: 아래 「구현 계획」의 표가 지도다(경로 + 줄 위치).

## 배경 / 문제 정의

홈피드 카드는 미보유 배지의 그림을 흑백(`grayscale`)으로 그린다(티켓 20260905_0038 B, 2026-09-06 확정 규칙). 2026-11-18 사용자 결정으로 이 규칙을 홈피드에서 뺀다. 홈피드는 배지를 소개하는 화면이라 보유 여부와 무관하게 원본 그림이 보여야 한다. 보유 여부는 카드를 눌러 들어간 상세 화면이 지금처럼 회색으로 알려 준다.

흑백이 걸리는 곳은 세 군데다.

1. 커버가 없어 첫 배지 그림이 이미지 칸으로 올라간 카드(`hero`·`poster`·`square`·`dome`·`ticket`): `ImageCardView.imageDimmed` → `CardImageSlot`
2. `brief` 모양의 64px 썸네일: `BriefCardView.thumbnailDimmed` → `CardThumb`
3. `list` 타일형의 타일(배지 타일, 레시피 공개 카드의 재료 타일): `CardViewTile.earned === false` → `CardThumb`

## 상세 요구사항

### 서비스/코드베이스 관점
- 홈(`/`)의 카드(`TodayCardStack` → `TodayCard`)가 그리는 배지 그림에는 어떤 경우에도 `grayscale`이 붙지 않는다. 레시피 공개 카드의 재료 타일도 같다(가진 재료와 없는 재료를 색으로 구분하지 않는다).
- 어드민 미리보기(`TodayCardForm`·`HomePreviewPanel`·`opsInbox/cardPreview`)는 같은 `toCardView`를 쓰므로 함께 컬러가 된다. 이미 «미리보기는 컬러»였으므로 화면 차이는 `earned: false`를 실은 경우뿐이다.
- `ResolvedBadge.earned`(서버 조회 값, `lib/today/cards.ts`)는 **지우지 않는다.** 레시피 공개 카드가 슬롯의 대표 후보를 고를 때 이 값을 쓴다(`cards.ts` 605~626줄). 조회 로직(`getTodayCards`의 보유 조회 3건)도 바꾸지 않는다. 주석만 새 규칙으로 고친다.
- 상세 화면의 회색 처리(`components/BadgeHeroSection.tsx`, `components/ui/BadgeGridCard.tsx`, `components/ui/ListCard.tsx`, `app/(main)/collections/[id]/page.tsx`, `app/(main)/missions/**`, `app/(main)/combine/RecipeSlotCard.tsx`, `components/map/MapView.tsx`)는 이번 diff에 들어오면 안 된다.

### UI/UX 관점 (해당 시)
- 흑백만 걷는다. 카드의 크기·여백·칩·글자·자리 표시(아이콘)·이미지 맞춤 방식은 그대로다.
- 새 토큰·새 컴포넌트·새 문구는 없다.

### 주요 의사결정 / 핵심 메모

- **흑백 장치를 값만 끄지 않고 통째로 걷는다.** `toCardView`가 값을 싣지 않게만 하면 3줄로 끝나지만, 컴포넌트의 `dimmed` 분기와 «미보유 흑백» Story가 쓰이지 않는 채로 남아 화면 규칙과 어긋난 설명이 된다. `components/today/`는 홈피드 전용이라 다른 화면이 이 분기를 쓰지 않는다.
- **레시피 공개 카드의 재료 타일도 컬러로 간다.** 사용자 지시가 «홈피드에 노출되는 배지 이미지»라 타일을 예외로 두지 않았다(카리나 해석). 머지 승인 때 사용자에게 가정으로 알린다.
- **계획 반환 면제를 첫 호출부터 넘긴다.** 바뀌는 파일이 25개 안팎이라 `plan_only` 기준(5개 초과)을 넘지만, 대부분이 흑백 시험·Story 삭제이고 파일 단위 계획을 위 표에 적었다(면제 조건 (a)(b)).
- 경로는 ② 가벼운 UI다(로직 변경 없는 스타일 변경, 고칠 내용 확정). 채원①·②를 생략한다.
- 재료 타일 가정은 머지 승인 요청 때 사용자에게 알렸고, 사용자가 그대로 머지를 승인했다(2026-11-18).
- 아현이 첫 검사에서 `templateDefs.test.ts` 실패를 만났다. 로컬 리뷰 브랜치가 옛 staging 위에 있어 티켓 20261118_1506의 변경이 반쯤만 들어 있었기 때문이고 이 티켓과 무관하다. 그 사이 병렬 세션이 staging을 push해서 `origin/staging`(9d44038ec)으로 리베이스하자 통과했다.
- 계획 표에 없던 `RecipeRevealCard.test.tsx`·`cards-recipes.test.ts`도 같은 이유(타일 `earned`와 흑백 서술)로 고쳤다. 사전 검색을 `earned: false`·`grayscale` 문자열로만 해서 놓친 파일이다.
