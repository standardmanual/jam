# [Infra] 운영툴 주간 기획이 카드와 미션의 이미지 지시를 빠짐없이 내게 한다

## 핵심 요약

- 요구사항: 어드민에서 승인한 뒤 이미지가 없는 카드와 미션은 이미지가 자동으로 만들어져야 한다. 지금은 주간 기획 에이전트(윤진)가 이미지 지시(`image_spec`)를 내지 않아 승인해도 아무것도 만들어지지 않는다. 에이전트 정의를 고쳐 **미션 전부와 이미지가 보이는 모든 카드 모양**이 `image_spec`을 내게 한다.
- 구현 계획: 코드는 바꾸지 않는다. 에이전트 정의(`.claude/agents/jam-marketer.md` 모드 ⑨)의 이미지 지시 문장을 새 규칙으로 바꾸고, 운영툴 PRD와 예약 작업 문서의 같은 서술을 맞춘다. 주간 루틴 저장 프롬프트 갱신은 이 티켓 밖의 후속이다(아래).
- 관련 파일: 「구현 계획」 참조.

## 배경 / 문제 정의

승인 뒤 이미지는 브라우저가 항목의 `image_spec`(프리셋 ID·색·글자)으로 PNG를 그려 올린다(`jam-web/src/components/admin/ops/useItemImageProduction.ts`의 `produceItemImage`). `image_spec.preset_id`가 없으면 `imageSpecToRenderArgs`가 null을 돌려 조용히 `skipped`가 된다.

2026-11-18 실제 묶음 데이터(Supabase `ops_bundle_items`, 시험 묶음 제외):

| 주차 | 카드 | 카드 중 `image_spec` 있음 | 미션 | 미션 중 `image_spec` 있음 |
|---|---|---|---|---|
| W48 | 11 | 0 | 2 | 0 |
| W47 | 12 | 1 | 2 | 0 |
| W46 | 9 | 0 | 2 | 0 |

원인은 에이전트 정의 두 곳이다.

1. `jam-marketer.md` 모드 ⑨가 `hero`·`ticket`(16:9)과 `poster`·`dome`(4:5)에만 `preset_id`를 쓰게 하고 `square`·`brief`·`list`는 «새 이미지가 필요 없다»며 비우게 한다.
2. 미션에 대한 이미지 규칙이 정의에 없다. 프리셋 «미션»(`98562783-36c9-44aa-8fba-3c4793608f28`, 1:1)이 이미 있고 제작 코드도 미션 이미지 칸(`image_url`)을 지원하는데 에이전트가 이 ID를 모른다. 주간 리포트(W45·W47)는 빈 지시를 «이미지가 필요 없는 카드와 미션이라 의도한 상태»로 적었다.

사용자 결정(2026-11-18): 이미지 없는 카드와 미션은 승인 뒤 이미지를 만들게 한다. 모양은 전부(`square` 포함)를 원했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 에이전트 정의의 프리셋 대응은 아래와 같다(프리셋 ID는 `asset_presets`에서 확인한 값이다).

| 항목 | 프리셋 | ID |
|---|---|---|
| 카드 `hero`·`ticket` | 홈피드 16:9 | `c5491ad2-12d4-4ab0-a59d-6897067a8a9a` |
| 카드 `poster`·`dome` | 홈피드 4:5 | `a4d7f928-2531-4cc4-a611-3399db244bfe` |
| 카드 `square` (신규) | 홈피드(1:1) | `51aa4673-f723-4929-ac20-a302202b7aa7` |
| 미션 (신규) | 미션(1:1) | `98562783-36c9-44aa-8fba-3c4793608f28` |

- 미션은 `image_spec.values`에 `text01`(조건 문구)·`text02`(미션 이름)를 낸다. 규약과 글자 수 한도의 근거는 `docs/service/prd/asset-generator/PRD.md` 「기존 미션 이미지 일괄 적용」 절과 `docs/assets/mission-images/20260926_mission-image-plan.json`이다. 미션 프리셋에는 텍스트 레이어가 3개 있으므로 세 번째 레이어의 쓰임을 프리셋(`asset_presets.layers`)에서 확인해 정의에 적는다.
- `bg`·`end`(`#rrggbb`)를 반드시 함께 낸다. 없으면 제작이 실패한다(PRD §3.1).
- `brief`·`list` 모양은 이번에 포함하지 않는다. 홈 화면이 이 두 모양에서 커버 이미지(`cover_image_url`)를 그리지 않아(`toCardView`의 `brief`는 배지 썸네일, `list`는 타일만 그린다) 만들어도 보이지 않는다. **사용자 확인 완료(2026-11-18): `brief`·`list`는 제외한다.** 처음의 «전 모양에 생성» 답은 이 사실을 알리기 전의 것이었고, 사실을 알린 뒤 «네, 제외»로 확정했다.
- `jam_badge`·`collection_launch` 항목은 이번 범위 밖이다.

### UI/UX 관점 (해당 시)
- 없음. 어드민 화면과 홈 화면은 바뀌지 않는다.

### 주요 의사결정 / 핵심 메모

- 사용자가 «전 모양에 생성»을 정했지만 `brief`·`list`는 홈 화면이 커버를 그리지 않아 보이지 않는다. 사실을 알리고 확인을 요청했고, 사용자가 «네, 제외»로 확정했다(2026-11-18). 게이트(민지)가 1회차에서 «전 모양» 답만 보고 FAIL을 냈으나 최신 결정은 제외다.
- 경로는 표준(채원 생략: 화면 변경 없음, 유형 `infra`)이다.
- 1회차 게이트 FAIL은 구현 결함이 아니라 판정 전제의 오류였다. 리뷰어에게 넘어간 요청문에는 «전 모양에 생성» 답만 있었고 이후의 «제외» 확정이 없었다. 재판정(`gateOnly`) 요청문에 확정 경위와 카리나의 DB 대조 결과를 함께 넘겼다. 같은 일을 줄이려면 사용자가 앞선 답을 바꿀 때 티켓의 해당 문장을 바꾼 뒤 구현을 요청한다.
- 아현의 리뷰 브랜치 push가 자동 권한 검사에 거부돼 사용자 허락(2026-11-18)을 받고 카리나가 wf 워크트리에서 push했다. 훅이 CI에 맡겨 통과했다.
- 로컬 staging에 병렬 세션의 미push 커밋이 있어 빨리감기가 되지 않았고, 머지 커밋을 만들지 않으려고 `cherry-pick`으로 옮겼다. `docs/tickets/_index.json`은 생성 파일이라 충돌을 현재 쪽으로 풀었고 pre-commit이 다시 만든다.
