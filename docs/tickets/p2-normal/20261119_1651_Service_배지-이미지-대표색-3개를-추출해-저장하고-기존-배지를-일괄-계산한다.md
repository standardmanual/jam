# [Service] 배지 이미지 대표색 3개를 추출해 저장하고 기존 배지를 일괄 계산한다

## 핵심 요약
- 요구사항: `badges`에 대표색 칸을 만들고, 이미지에서 대표색 최대 3개를 뽑는 서버 함수와 기존 배지 일괄 계산 스크립트를 만든다. 이미지가 바뀌었는데 색이 안 바뀐 채 남지 않도록 DB 트리거로 막는다.
- 구현 계획: ① 마이그레이션 347(칸 추가 + 무효화 트리거, 확장 단계라 되돌림 SQL 동반) ② `src/lib/badgeColorExtract.ts`(서버 전용, `sharp`) ③ `scripts/backfill-badge-bg-colors.mjs`(드라이런 → 실행 → 사후 검증) ④ 타입 갱신.
- 관련 파일: 아래 「구현 계획」.

## 배경 / 문제 정의
상위 티켓 20261119_1650 참고. 목록 한 화면에 배지가 수십 장 나오므로 색을 화면에서 뽑지 않고 **미리 뽑아 저장**한다(사용자 결정). 색을 저장하면 이미지가 뜨기 전부터 배경이 있고 계산 비용이 없다. 대신 배지 이미지가 바뀔 때 색이 낡지 않게 하는 장치가 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `badges.bg_colors jsonb NULL`: 이미지에서 뽑은 **원색(보정 전)** 최대 3개를 **밝기 높은 순**으로 담은 hex 문자열 배열(예: 노란 배지는 `["#eaf36d","#c9b48a","#9bbd6a"]`처럼 이미지에서 뽑은 색 그대로). 색을 보정하는 규칙(연하게 값)은 화면이 쓰는 표(`badgeAura.ts`, 1653)에 두어 **색을 다시 뽑지 않고 톤만 조정**할 수 있게 한다.
- 추출 규칙(샘플의 `extract`와 같게): 64×64로 줄여 알파 200 미만·채도 .18 미만·명도 .14 미만 또는 .92 초과 픽셀을 뺀다. 남은 픽셀을 색상 24구간으로 나눠 구간 점수(이웃 합산, 중앙 가중치 2) 순으로 색상 간격 40° 이상인 구간을 최대 3개 고르고, 구간 안의 원형 평균 색상과 가중 평균 채도·명도를 낸다. 색이 3개 미만이면 **있는 색만 저장한다**(채우기는 화면 쪽 `fill3`가 한다). 색이 하나도 없으면(흑백 위주) 빈 배열 `[]`로 저장한다(NULL과 구분: NULL=아직 안 뽑음, `[]`=뽑았는데 색 없음).
- 트리거 `badges_bg_colors_stale_guard`: `BEFORE UPDATE OF image_url ON badges`에서 `NEW.image_url IS DISTINCT FROM OLD.image_url`이고 `NEW.bg_colors IS NOT DISTINCT FROM OLD.bg_colors`(작성자가 새 색을 함께 안 줌)면 `NEW.bg_colors := NULL`로 비운다. 작성자가 같은 UPDATE에서 새 색을 주면 그대로 둔다. 어떤 경로가 이미지를 바꿔도 **낡은 색이 남지 않는다**는 안전망이다.
- 서버 함수 `extractBadgeColors(imageUrl: string): Promise<string[] | null>`: 절대 주소는 `fetch`로, `/`로 시작하는 정적 주소는 `public/`에서 읽어 `sharp`로 디코드한다. 실패하면 `null`을 돌려주고 예외로 저장 흐름을 막지 않는다(색은 장식이다).
- 일괄 계산 스크립트: `bg_colors IS NULL`이고 `image_url IS NOT NULL`인 배지(약 4,890개 중 이미지 있는 것)를 읽어 계산해 저장한다. `--dry-run`(저장 없이 분포·실패 수 출력)과 `--limit`, 재실행 안전(이미 값이 있으면 건너뜀), 동시 요청 수 제한, 진행·실패 출력(비밀값 출력 금지)을 갖춘다. 이 스크립트는 **메인 세션이 실행**한다(아현은 작성까지).

## 구현 계획
- 마이그레이션 `jam-web/supabase/migrations/347_badge_bg_colors.sql` + `347_badge_bg_colors_down.sql`. 번호는 push 직전 원격 staging 기준으로 다시 확인한다(병렬 세션 선점 사례). 칸은 NULL 허용이라 기존 코드는 영향이 없다(확장 단계). 공용 DB라 실행 즉시 프로덕션에 반영된다. 실행 전 되돌림 SQL을 확인하고, 실행 직후 읽기 전용으로 칸·트리거 존재를 확인한다.
- 신규 `jam-web/src/lib/badgeColorExtract.ts`: `extractBadgeColors`와 순수 함수 `pickBadgeColors(rgba: Uint8Array)`를 나눠 순수 쪽을 단위 시험한다. 서버 전용이므로 파일 첫 줄에 `import 'server-only'`를 둔다(클라이언트에서 가져오면 번들링 단계에서 막힌다 — 경계 위반은 빌드해 봐야 드러난다).
- 신규 `jam-web/scripts/backfill-badge-bg-colors.mjs`: 위 함수와 같은 알고리즘이 필요하므로 TS 함수를 `.mjs`가 직접 못 쓰면 알고리즘을 한 파일(`src/lib/badgeColorExtract.core.mjs`)에 두고 `.ts`가 재수출하는 방식을 택해 **복사본이 두 벌 생기지 않게** 한다.
- 타입: `src/types/database.ts`의 `badges` Row·Insert·Update에 `bg_colors: string[] | null`을 추가한다. `npm run db:types`는 실행 불가(파일을 비운다)이므로 MCP `generate_typescript_types` 결과와 대조해 손으로 반영한다.
- 시험: `pickBadgeColors` — 검은 외곽선 많은 이미지에서 외곽선 색이 안 뽑힌다, 색이 하나뿐이면 1개를 돌려준다, 흑백이면 `[]`, 색상 간격 40° 미만 색은 한 구간으로 합쳐진다, 같은 입력에 같은 결과(결정성).

## 완료 조건
### 구현 범위 (게이트 판정 대상)
- `badges.bg_colors jsonb NULL` 칸과 `badges_bg_colors_stale_guard` 트리거를 만드는 마이그레이션과 되돌림 SQL 파일이 있다.
- `pickBadgeColors`가 위 시험 5건을 통과한다. 검은 외곽선 비중이 큰 이미지에서 결과 색에 검정·회색이 없다.
- `extractBadgeColors`는 어떤 실패에도 예외를 던지지 않고 `null`을 돌려준다.
- 일괄 계산 스크립트가 `--dry-run`으로 실행되고 분포(색 3개·2개·1개·`[]`·실패 수)를 출력한다. 두 번 실행해도 두 번째는 0건 처리한다.
- 타입 파일이 MCP 생성 타입과 일치한다. `verify.sh`가 통과한다.
### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 마이그레이션 347을 실행하고(되돌림 SQL 확인·실행 직후 읽기 전용 확인), 일괄 계산 스크립트를 드라이런 → 실행 → 사후 검증한다. 사후 검증 기준: 이미지가 있는 배지의 `bg_colors IS NULL` 건수와 실패 목록을 사용자에게 보고한다.
- 트리거 동작을 DO 블록 롤백으로 실측한다(이미지만 바꾸면 색이 비워지고, 이미지와 색을 함께 바꾸면 색이 유지된다).
