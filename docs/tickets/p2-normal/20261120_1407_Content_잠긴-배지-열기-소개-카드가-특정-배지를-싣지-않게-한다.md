# [Content] 잠긴 배지 열기 소개 카드가 특정 배지를 싣지 않게 한다

## 핵심 요약

- 요구사항: «잠긴 채 온 배지, 열어 볼까요» 카드는 잠긴 배지를 포인트로 열어 보라는 소개인데, 기획이 배지 한 개(「빌린 유리 칸」)를 골라 그 그림과 `/badges/<id>` 링크를 실었다. 이미 연 유저에게는 맞지 않는다. 이런 소개 카드는 특정 배지를 싣지 않고 인벤토리로 연결한다.
- 구현 계획: 패턴 P26의 열기 소개 각도 2개와 카드 모양 설명, 주의 문장을 고치고(DB, 마이그레이션 348), 윤진 정의에 일반 규칙 한 문장을 더한다. 코드는 바꾸지 않는다.
- 관련 파일: `jam-web/supabase/migrations/348_pattern_p26_no_specific_badge.sql`(+`_down`), `.claude/agents/jam-marketer.md` 모드 ⑨의 착륙 규칙 문장.

## 배경 / 문제 정의

2026-11-18 주간 묶음(W48)의 카드 `c-lock-open`(패턴 P26, 카드 `4ec62e7d-365e-4bb3-aa21-dcb1968c6a65`)이 `badge_spotlight`로 만들어져 `badge_ids`에 배지 한 개를 싣고 `target_href`가 비어 `/badges/<id>`로 갔다. P26의 첫 각도 «잠긴 아이템 배지 한 개의 여는 값»이 `needs: ["badges"]`와 «한 개»라는 표현으로 에이전트가 배지를 고르게 했다. 잠금은 유저마다 상태가 달라(2026-10-08 정책: 한 번 연 배지는 다시 잠기지 않는다) 어떤 배지를 골라도 이미 연 유저가 있다.

사용자 결정(2026-11-20): 이 카드는 잠긴 배지를 열어 보라는 소개 정도만 하고, 링크는 인벤토리가 맞다. 이런 기획이 없게 조정한다.

## 상세 요구사항

### 컨텐츠 관점
- P26의 «소개» 각도(등급별 여는 값)와 «유도» 각도(포인트가 모였다면 열어 보기)는 `needs`를 비우고 설명에 «배지 없이 `content_intro`, `target_href` `/inventory`»를 적는다. 각도 제목은 «잠긴 아이템 배지 열어 보기»로 바꾼다.
- P26의 카드 모양 «배지 1개»의 설명에 «열기 소개 각도는 배지 없이 `content_intro`»를 덧붙인다.
- P26의 주의 문장 끝에 같은 규칙과 이유(열었는지는 유저마다 다르다)를 적는다.
- 윤진 정의 모드 ⑨의 착륙 규칙에 일반 규칙을 더한다: 무엇을 하라고 알리는 카드(예: 포인트로 잠긴 배지 열기)는 `content_intro`로 `/inventory`에 연결하고 `badge_ids`를 싣지 않으며 한 배지를 그림이나 링크로 삼지 않는다.

## 완료 조건
- `ops_patterns`의 P26 각도 0·1번 제목이 새 값이고 `needs`가 비어 있다. 각도 10개와 다른 칸은 그대로다.
- 윤진 정의에 일반 규칙이 있다.
- 후속(카리나, 다음 주간 실행 뒤 2026-11-24): 제출된 묶음에서 P26 카드가 `content_intro`·`/inventory`·`badge_ids` 없음으로 나왔는지 DB로 확인한다.

## 완료 기록 *(작업 완료 후 작성)*

- 경로: 경미 수정(DB 한 행의 설명 칸과 정의 한 문장, 원인과 수정이 명백)으로 jam-work 파이프라인 없이 카리나가 처리했다.
- DB(마이그레이션 348, 실행 완료): 스모크(DO 블록에서 같은 UPDATE 후 롤백)로 1행만 바뀌고 각도 10개가 보존됨을 확인한 뒤 실제로 실행했고, 읽기 전용 SELECT로 새 값을 확인했다. 되돌림은 `348_pattern_p26_no_specific_badge_down.sql`이다.
- 변경 파일: `jam-web/supabase/migrations/348_pattern_p26_no_specific_badge.sql`, `348_..._down.sql`, `.claude/agents/jam-marketer.md`.
- 노출 중이던 카드(`today_cards.id` `4ec62e7d-365e-4bb3-aa21-dcb1968c6a65`, 11-18~11-21)는 사용자 승인(2026-11-20)으로 같은 날 고쳤다. `template_type` `badge_spotlight` → `content_intro`, `badge_ids` `{b3c94db8-bd4d-4098-9f49-3aebdc7aa30b}` → `{}`, `target_href` NULL → `/inventory`. 현재 값이 옛 값일 때만 바뀌도록 조건을 걸어 1행만 바꿨다. 되돌림: `UPDATE today_cards SET template_type='badge_spotlight', badge_ids=ARRAY['b3c94db8-bd4d-4098-9f49-3aebdc7aa30b']::uuid[], target_href=NULL WHERE id='4ec62e7d-365e-4bb3-aa21-dcb1968c6a65'`. 이 변경은 마이그레이션 파일이 없는 운영 데이터 수정이다.
- 확인(staging 사이트, 같은 DB): 카드가 «소개» 칩과 자원 아이콘으로 보이고 링크가 `/inventory`다. 배지 그림은 없다.
- 배포: 하지 않음(요청 때 push). 루틴은 push된 staging의 정의를 읽는다.

### 잔여 이슈
- 패턴 사전은 DB가 정본이라 저장소 문서에는 P26 서술이 없다. 어드민 패턴 사전 화면에서도 새 값이 보이는지는 확인하지 않았다.
