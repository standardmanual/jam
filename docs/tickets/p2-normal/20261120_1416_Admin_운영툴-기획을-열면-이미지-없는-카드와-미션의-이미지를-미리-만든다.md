# [Admin] 운영툴 기획을 열면 이미지 없는 카드와 미션의 이미지를 미리 만든다

## 핵심 요약

- 요구사항: 이미지는 승인 뒤가 아니라 기획 단계(도착·검토중)에서 만들어져 있어야 한다. 관리자가 기획 상세를 열면, 이미지가 없고 이미지 지시(`image_spec`)가 완성된 카드·미션 항목의 이미지를 화면이 자동으로 만들어 저장한다. 승인할 때는 이미 이미지가 있다(사용자 결정 2026-11-20, 방식 A).
- 구현 계획: 기존 제작 코드(`useItemImageProduction`·`produceItemImage`·이미지 저장 API)를 그대로 쓰고, 기획 상세가 열릴 때 대상 항목을 골라 `startMany`를 부르는 한 곳과 순수 선별 함수를 더한다. 승인 전 안내 문구를 바꾼다. 서버 API·DB는 바꾸지 않는다.
- 관련 파일: 「구현 계획」 표.

## 배경 / 문제 정의

지금 이미지는 승인 직후(`OpsDecisionWorkspace.handleExecuted` → `imageProduction.startMany`)에만 만들어지고, 도착·검토중 항목에는 «이미지는 승인 뒤 만들어요»가 보인다. 에이전트가 `image_spec`을 내지 않아 승인 뒤에도 만들어지지 않던 문제는 티켓 20261118_1715로 고쳤다(다음 주간 실행부터). 이 티켓은 한 걸음 더 나아가 승인 전에 이미지가 이미 있게 한다. 에이전트가 직접 그리는 방식은 읽기 토큰의 쓰기 권한을 넓혀야 해 채택하지 않았다.

서버의 이미지 저장 API(`POST /api/admin/ops-inbox/[bundleId]/items/[itemId]/image`)는 반려·취소·실패·종료 외 모든 상태를 받으므로 서버 변경은 필요 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 자동 제작 대상: 시험 묶음이 아니고, 상태가 `arrived`·`reviewing`이며, 이미지 칸이 있는 종류(`imageKeyOfKind`)이고, 자원에 이미지가 아직 없고(`hasResourceImage` 아님), `image_spec`에서 제작 인자가 나오고(`preset_id`) `bg`·`end`가 모두 비어 있지 않고, `color_pending`이 아닌 항목. 색이 없는 항목은 만들지 않는다(승인 전 미리보기가 임시 색으로 그리는 기존 동작은 그대로다).
- 시드는 항목 ID의 고정 시드(`stableImageSeed`)라 승인 전 미리보기와 같은 무늬다.
- 같은 화면 세션에서 한 항목은 한 번만 시도한다(실패해도 새로 고침 전까지 다시 시도하지 않는다). 이미 만드는 중인 항목은 `startMany`가 건너뛴다.
- 색이 나중에 채워지면(`fill_color` 뒤 새로 읽기) 그때 대상이 된다.
- 이미 저장된 이미지는 다시 만들지 않는다. 승인 뒤의 «이미지 다시 만들기»와 승인·예약 때의 자동 제작(이미 있으면 건너뜀)은 그대로다.
- 서버 응답이 막힌 상태(409)이거나 렌더가 실패하면 조용히 넘기되 한 번 알린다.

### UI/UX 관점 (해당 시)
- 승인 전 미리보기 안내 문구를 새 동작에 맞춘다. `PREVIEW_IMAGE_PENDING_TEXT` «이미지는 승인 뒤 만들어요»는 «이미지는 색이 정해지면 만들어요»(색이 없어 건너뛴 경우)와 «이미지를 만드는 중이에요»(만드는 중, 기존 `PREVIEW_IMAGE_MAKING_TEXT`)로 나눈다. 저장된 이미지가 있으면 문구가 없다. 문구는 UX Writing 가이드(해요체)를 따른다.
- 실패 알림은 승인 전용 문구(«승인은 유지했어요…»)가 맞지 않으므로 «이미지를 만들지 못했어요. 승인한 뒤 [이미지 만들기]로 다시 만들 수 있어요.» 형태의 새 문장을 쓴다.

## 구현 계획

| 파일 | 할 일 |
|---|---|
| `jam-web/src/lib/admin/opsInbox/autoImage.ts` (신규) | 순수 함수 `pickAutoImageItemIds(items, { isSample, attempted })`: 위 대상 조건을 계산해 항목 ID 배열을 돌려준다. `OPS_IMAGE_PRODUCTION_STATUSES`(승인 이후)와 겹치지 않는 `arrived`·`reviewing`만 본다. `imageSpecToRenderArgs`·`hasResourceImage`(훅 파일의 것을 공용으로 빼거나 같은 로직)·`imageKeyOfKind`를 재사용한다 |
| `jam-web/src/components/admin/ops/OpsDecisionWorkspace.tsx` 129~140줄 근처 | `useEffect`로 `items`가 바뀔 때마다 `pickAutoImageItemIds`를 부르고 나온 ID를 `attempted` ref에 더한 뒤 `imageProduction.startMany(ids, items)`를 부른다. 결과로 새로 읽기(`onDone`)는 훅이 이미 한다 |
| `jam-web/src/components/admin/ops/useItemImageProduction.ts` | `startMany`가 실패 알림 문구를 고를 수 있게 한다(승인 전 호출은 새 문구). 기본 동작(승인 뒤)은 그대로 |
| `jam-web/src/components/admin/ops/OpsCardPreview.tsx` 29~35줄·93~104줄 | 안내 문구 상수와 분기를 위 UI 규칙대로 바꾼다 |
| 시험 | `autoImage` 순수 함수 시험(대상·제외 조건 전부), `OpsCardPreview` 문구 시험 갱신, `useItemImageProduction`의 새 알림 시험, 가능하면 `OpsDecisionWorkspace`가 대상 항목에만 `startMany`를 부르는 시험 |
| `docs/service/prd/ops-tool/PRD.md` 1408~1419줄 근처 | «승인 직후 자동 제작»과 «승인 전 이미지 바로 그리기» 서술에 «기획을 열면 자동 제작(저장)»을 더하고, «도착·검토중은 아직 만들 때가 아니다»(222줄 부근)를 고친다 |

화면 변경이지만 어드민 화면은 MODULAR 판정 대상이 아니다. 새 컴포넌트는 없다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `pickAutoImageItemIds`가 위 조건대로 대상을 고르고, 색이 없는 항목·시험 묶음·이미 이미지가 있는 항목·승인 이후 상태·이미지 칸이 없는 종류·이미 시도한 항목을 제외한다(시험으로 확인).
- 기획 상세가 열려 대상이 있으면 `startMany`가 한 번 불린다. 같은 항목은 새로 읽은 뒤에도 다시 불리지 않는다(시험으로 확인).
- 승인 전 미리보기 문구가 새 규칙대로 나온다(시험).
- 서버 API·DB·`produceItemImage` 본문은 diff에 없다.
- PRD가 새 동작을 적고 있다. `scripts/verify.sh`와 CI가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 어드민(`ADMIN_EMAILS` 셸 변수, 테스트 로그인)에서 시험 묶음이 아닌 실제 묶음으로 확인하기는 어렵다(시험 묶음은 이미지를 저장하지 않는다). 다음 주간 묶음(2026-11-24 화) 도착 뒤 기획 상세를 열어 이미지가 만들어지는지 확인한다.
