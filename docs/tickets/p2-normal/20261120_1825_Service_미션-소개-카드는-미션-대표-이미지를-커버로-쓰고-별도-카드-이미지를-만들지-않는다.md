# [Service] 미션 소개 카드는 미션 대표 이미지를 커버로 쓰고 별도 카드 이미지를 만들지 않는다

## 핵심 요약

- 요구사항: 사용자 결정(2026-11-20) — 에이전트가 미션으로 카드(`mission_spotlight`)를 기획하면 그 카드는 자동으로 미션 대표 이미지(`missions.image_url`)를 쓴다. 카드용 이미지를 따로 만들지 않는다. 지금 게시 중인 카드에도 같은 규칙이 적용된다.
- 구현 계획: ① 홈 화면 변환(`toCardView`)이 `mission_spotlight` 카드의 커버가 비어 있으면 연결된 미션의 대표 이미지를 쓰고, 그 경우 «이미지가 제목을 말하는 카드»로 본다. ② 운영툴의 이미지 제작(기획을 열 때 자동 제작, 승인 뒤 자동 제작, [이미지 만들기])은 미션 소개 카드를 대상에서 뺀다. ③ 운영툴 기획 미리보기는 연결된 미션 항목의 이미지를 카드 커버로 보이고, 이미지가 아직 없으면 «미션 대표 이미지를 써요»를 안내한다. ④ 에이전트 정의와 문서가 «미션 소개 카드는 이미지 지시를 내지 않는다»로 맞춘다.
- 관련 파일: 아래 「구현 계획」 표.

## 배경 / 문제 정의

문서에는 이미 «미션 소개 카드는 미션 대표 이미지를 그대로 쓴다»가 있다(`content-automation/PRD.md` 편성 규칙 4, `home-feed/PRD.md` 「커버 결정」, `scheduled-jobs.md` 71줄). 그런데 코드가 이 규칙을 지키지 않는다.

- `toCardView`(`jam-web/src/lib/today/cardView.ts`)의 이미지 모양 분기는 «커버가 있으면 커버, 없으면 첫 배지 그림»뿐이다. 미션 소개 카드는 배지가 없으므로 커버가 비면 아이콘만 있는 어두운 판이 된다. 등록 단계도 미션 이미지를 카드 커버로 옮겨 주지 않는다.
- 2026-11-20 확인 결과 노출 중인 `mission_spotlight` 카드 4장은 모두 `cover_image_url`이 비어 있다(미션 대표 이미지가 있는 카드 2장, 없는 카드 2장).
- 티켓 20261118_1715가 에이전트 정의에 «이미지가 보이는 모양(`hero`·`ticket`·`poster`·`dome`·`square`)의 카드는 모두 `image_spec`을 낸다»고 넣었다. 미션 소개 카드는 항상 `square`라서 여기에 걸려 미션 이미지와 별개인 카드 이미지를 또 만들게 된다. 티켓 20261120_1416의 «기획을 열면 자동 제작»도 같은 카드를 대상으로 삼는다. 둘 다 이번 결정과 어긋난다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **홈 화면(커버 대체)**: 이미지 모양(`hero`·`poster`·`square`·`dome`·`ticket`)의 `mission_spotlight` 카드에 `cover_image_url`이 없고 연결된 미션의 `image_url`이 있으면 그 주소를 `imageUrl`로 쓴다. 우선순위는 카드 커버 → 미션 대표 이미지 → 첫 배지 그림이다. 이때 `titleInImage`는 `true`다(미션 이미지는 조건·이름이 글자로 들어 있다). 저장된 `title_in_image`가 `false`여도 미션 이미지를 쓰는 경우는 `true`다. 카드 커버가 있으면 지금과 같다. 미션 이미지도 없으면 지금처럼 아이콘 판이다.
- **게시 중인 카드**: 데이터는 바꾸지 않는다. 위 대체 규칙이 같은 코드로 노출 중인 카드 4장에도 적용된다(미션 이미지가 있는 2장은 이미지가 생기고, 없는 2장은 그대로다). 카드 행에 미션 이미지 주소를 복사해 넣지 않는다(미션 이미지가 바뀌면 어긋난다).
- **이미지 제작 대상에서 제외**: 종류가 `home_feed_card`이고 `resource.template_type`이 `mission_spotlight`인 항목은 «별도 이미지를 만들지 않는 항목»이다. 이 판정을 `imageSpec.ts`에 순수 함수 하나로 두고, 기획을 열 때 자동 제작(`pickAutoImageItemIds`), 승인 직후·예약 뒤 자동 제작과 [이미지 만들기](`useItemImageProduction`의 `skipped` 판정)가 같은 함수를 쓴다. 에이전트가 옛 정의로 `image_spec`을 내도 카드 이미지가 만들어지지 않아야 한다(만들어지면 커버가 생겨 미션 이미지를 가린다).
- **운영툴 기획 미리보기**: `mission_spotlight` 카드 항목은 같은 묶음에서 `links`로 연결한 미션 항목의 `resource.image_url`이 있으면 그것을 카드 커버로 보인다(미리보기는 홈 화면과 같은 `toCardView`를 쓰므로 `itemToPreviewCard`가 이 주소를 미션 이미지로 넘기면 된다). 연결한 미션 항목이 없거나 이미지가 아직 없으면 안내 문구 «미션 대표 이미지를 써요»를 보이고, «이미지 제작 필요»·«이미지는 색이 정해지면 만들어요»는 이 카드에 보이지 않는다.
- **에이전트 정의·문서**: `.claude/agents/jam-marketer.md` 모드 ⑨ 행(37줄)의 이미지 지시 문장에서 `mission_spotlight` 카드를 뺀다. 문장 뜻은 «미션 항목과 이미지가 보이는 모양의 카드는 `image_spec`을 낸다, 단 `mission_spotlight` 카드는 내지 않는다. 앱이 연결된 미션의 대표 이미지를 커버로 그리므로 이미지는 미션 항목에서 한 번만 만든다»이다. `docs/service/prd/home-feed/PRD.md` 「커버 결정」(333줄 근처)의 «운영 규칙은 …커버로 넣는다»를 «커버가 없으면 미션 대표 이미지를 대신 그린다»로 고친다. `content-automation/PRD.md` 편성 규칙 4(126줄)와 `ops-tool/PRD.md`의 이미지 제작 절(§8.8, 84·222줄 근처)에 같은 규칙을 한 줄씩 적는다. `scheduled-jobs.md` 71줄·220줄 근처도 확인해 어긋난 문장이 있으면 맞춘다.

### UI/UX 관점

- 새 디자인은 없다. 기존 이미지 칸에 다른 이미지가 들어갈 뿐이다. 미리보기 안내 문구 하나만 늘어난다(`PREVIEW_IMAGE_MISSION_TEXT`). 사용자 노출 문구가 아니라 어드민 화면 문구이며 해요체로 쓴다.
