# [Feature] 홈피드 카드를 새 유형·칩·컬러 조합으로 개편한다 (상위)

## 핵심 요약

- 요구사항: 샘플 아티팩트로 확정해 온 홈피드 카드 디자인(카드 유형, 기울인 칩, 제목 속 칩, 박스 모양, 도장, 컬러 조합, 컬렉션 배지 모션)을 서비스에 넣는다. 에이전트(윤진)는 기획에 맞춰 유형·칩·색을 자동으로 정하고, 사용자는 어드민에서 같은 것을 손으로 지정할 수 있어야 한다.

## 배경 / 문제 정의

2026-11-20에 사용자가 참조 이미지(채도 높은 단색 면, 기울인 칩, 도장, 틀 안의 이미지)를 주고 홈피드 카드 유형을 조정하려 한다고 했다. 카리나가 JAM의 실제 카드 문구·배지·미션·컬렉션 이미지로 샘플 피드를 캔버스 아티팩트로 만들었고, 사용자가 아티팩트 댓글로 디자인을 다듬었다. 사용자는 이 결과를 서비스에 적용하겠다고 결정했다.

샘플 아티팩트(비공개, 소유자만 열람): https://claude.ai/artifact/96PUfXQX41hqcSj8LTeXuL
작업 사본은 세션 임시 폴더에 있어 사라질 수 있으므로, 규격의 원천은 아티팩트와 이 티켓이다.

현재 서비스와의 차이(2026-11-20 코드 조사 결과):

- 카드는 모양 7가지(`hero`·`poster`·`square`·`brief`·`list`·`dome`·`ticket`) 중 하나로 그려진다. 에이전트는 묶음 항목에 `shape`를 반드시 적어 내고, 어드민 카드 작성 화면에는 모양·`title_in_image`·색을 고르는 칸이 없다.
- `today_cards`에는 색이나 배경을 저장하는 칸이 없다. 카드 면 색은 컴포넌트에 고정돼 있다.
- 칩은 유형 라벨·지역 핀·희귀도·게재일뿐이다. «4일 남음», «20 포인트»는 칩이 아니라 「필수 정보 줄」(`facts`, 최대 2줄)이다.
- 기울인 칩, 제목 속 칩, 도장, 물결·티켓·우표 박스, 컬렉션 배지 모션은 서비스에 없다.
- 디자인 시스템의 강조색 5가지(`--jam-red`·`--jam-yellow`·`--jam-green`·`--jam-purple`·`--jam-blue`)는 지정된 사용처 밖으로 퍼뜨리지 않는 규칙이 있다(`jam-web/design-system/tokens/colors.css`). 홈피드 카드 면에 쓰려면 이 규칙을 바꿔야 한다.

## 상세 요구사항

### 사용자가 확정한 것 (2026-11-20)

**운영 방식**

- 에이전트는 유형·칩·색을 스스로 자동으로 정한다. 사용자는 어드민에서 같은 것을 손으로 지정할 수 있다.
- 어드민에서 사용자가 직접 만들 때는 카드 유형에 따라 색을 지정할 수 있다.

**칩**

- 칩을 자동으로, 무작위 기울기와 위치로 넣는다.
- 컨텐츠의 주요 DB 값을 칩으로 표현한다(샘플의 예: 달성 기준 «10회»·«700m»·«14일 만에», 남은 기간 «2일 남음», «배지 3종류», 장소 이름).
- 제목 글줄 안의 키워드를 칩으로 표현한다(샘플의 예: «문경과 가평의 산으로 한 걸음»에서 «문경», «가평»). 이것은 선택 사항이다. 제목 속 칩을 만들지 말지는 카드마다 에이전트 또는 사용자가 판단해서 정한다.
- 칩과 꾸밈 요소에는 검정 2px 외곽선을 둔다.

**색**

- 색 조합을 자동으로 정한다. 조합을 정해진 개수로 고정하지 않는다.
- 다만 시각적으로나 감각적으로 가장 나쁜 조합(워스트 조합)은 제외한다.
- 이전의 밝은 조합(JAM 액센트의 연한 색 배경 + 같은 계열 원색 칩)과 참조 그림의 조합을 함께 쓴다.
- 키즈 감성이 느껴지는 조합은 제외한다(2026-11-20 샘플 묶음 2의 댓글). 카리나의 규칙 초안: 레드·옐로·그린·블루 원색끼리의 조합과, 밝은 색(밝기 0.7 초과)끼리 색상 차이가 40도를 넘는 조합을 제외한다. 이 규칙으로 44가지가 더 빠져 210가지 중 120가지가 남는다. 한 카드에 쓰는 색도 세 가지(배경, 칩, 박스)로 줄였다. 기준은 사용자가 검수표에서 확인해 다듬는다.
- 칩과 칩이 아닌 것(카드 배경, 박스)의 명도가 비슷하지 않게 한다. 칩이 밝으면 바탕은 칩보다 어둡고, 그 반대도 같다. 또는 두 색이 보색이면 된다(2026-11-20 샘플 묶음 2의 댓글). 카리나의 규칙 초안: 눈에 보이는 밝기(L*) 차이가 15 이상이거나 색상 차이가 150도 이상. 이 규칙을 더한 뒤 자동 규칙 결과는 대비 제외 50, 키즈 제외 36, 명도 제외 50, 남은 조합 74가지다. 이미지 위에 놓이는 칩에는 아직 적용하지 못했다(이미지의 밝기가 필요하다).
- 흰색 배경(칩, 박스)은 쓸 수는 있지만 최대한 지양한다(2026-11-20 샘플 묶음 2의 댓글). 자동 배정은 흰색을 쓰지 않고 조합 색에서 고르며, 흰색은 직접 지정할 때만 쓴다. 샘플 묶음 2에서는 흰색 칩을 카드마다 고른 세 번째 색으로, 흰색 박스를 그 카드의 박스 색으로 바꿨다.
- 샘플에 쓴 색 값: 액센트 원색 `#FF1D1D`·`#FEC100`·`#34EF5A`·`#BA8AF7`·`#0695EC`, 그 연한 색 초안 `#FF9A9A`·`#FFDD73`·`#9AF7AD`·`#D6B9FA`·`#8FCFF6`(카리나가 계산한 초안), 참조 그림에서 뽑은 색 `#F5442C`·`#95C1F7`·`#C0DC66`·`#E57FBB`·`#F2EC6A`(2026-11-20 정정: 처음에는 그림의 Display P3 색 프로파일을 무시하고 `#E2533A`·`#9EBFF0`·`#C5DB76`·`#D784B8`·`#F1EC7E`로 잘못 뽑았다. 사용자가 참조 레드를 그림의 색으로 바꾸라고 지시해 화면에 보이는 sRGB 값으로 다시 뽑았다. 정정 뒤 자동 규칙 결과는 대비 제외 50, 키즈 제외 36, 남은 조합 124가지다).

**이미지**

- 배지 이미지를 제외하고, 카드에 쓰는 이미지(썸네일, 카드 커버, 미션 대표 이미지 등)에는 앞으로 텍스트도 로고도 넣지 않는다. 배지 이미지는 지금처럼 이름·값·로고가 들어간다.
- 게시 중인 카드는 고려하지 않는다. 새 디자인의 카드는 새로 만든다. 기존 카드의 이미지를 다시 만들거나 기존 카드를 새 유형에 맞추는 작업은 하지 않는다.
- 카드 안 이미지 박스에는 외곽선을 두지 않는다.
- 박스 모양은 고르는 옵션이다. 티켓 모양을 포함한 박스 모양은 텍스트를 담는 박스로도, 이미지를 잘라 보이는 마스크로도 쓸 수 있어야 한다.
- 반원(아치)이 있는 박스는 쓰지 않는다. 예외는 드랍·픽업 카드의 아이템 배지 박스로, 몸통 위아래 가운데에 반원이 하나씩 튀어나온 모양을 쓴다.

**카드 유형과 박스 모양 (샘플 14장)**

- 히어로: 위에 이미지 박스, 아래에 제목과 설명. 이미지 박스 모양은 라운드, 가로로 긴 티켓 모양, 가로로 긴 우표 모양.
- 전체 배경 이미지: 이미지가 카드 전체를 채우고 그 위에 칩과 도장을 얹는다.
- 배지 소개: 히어로 구성에서 이미지 자리에 배지를 박스 없이 가운데에 둔다.
- 컬렉션 소개: 컬렉션 대표 그림을 박스 없이 가운데에 두고, 컬렉션에 속한 아이템 배지를 원 없이 둘레에 둔다. 카드가 스크롤되어 화면에 들어오면 배지가 가운데에서 방사형으로 불규칙하게 퍼진다.
- 배지만: 꾸밈 요소 없이 위에 제목, 아래에 배지 이미지. 작은 설명은 없다.
- 텍스트: 글자만 있는 유형. 안쪽 박스는 세로로 길고, 모양은 물결(꾸불꾸불한 윤곽, 검정 외곽선), 티켓(양쪽 변에 반원 홈 2개씩, 검정 외곽선), 우표(위아래 변에 작은 반원 홈이 줄지음). 박스 색은 배경과 다른 계열의 색. 꾸미는 칩을 박스 모서리에 걸쳐 둔다.
- 드랍·픽업: 아이템 배지 3개를 각각 박스에 넣어 한 줄로 둔다.

**도장 꾸밈**

- 문구는 `JOIN AND MOVE`만 쓴다. 색 면 위의 반전 글자(네거티브)이고 배경은 액센트 색이다.
- 가운데 작은 원은 투명한 구멍이어서 뒤의 이미지가 보인다. 글자는 안쪽 원과 바깥 원 사이 한가운데에 둔다.
- 크기는 샘플 기준 60px로, 처음 시안(78~84px)보다 작게 쓴다.

### 아직 정하지 않은 것 (카리나의 추천안 포함)

1. **워스트 조합을 가려내는 방법 (2026-11-20 확정, 추천안대로).** 자동 규칙으로 먼저 거르고(배경과 짝 색의 밝기 차이가 너무 작은 조합, 색상이 너무 가까운 조합, 채도 높은 보색끼리 맞붙는 조합, 검정 글자 대비가 모자란 배경), 남은 조합을 한 화면에 모아 사용자가 제외할 조합을 직접 고른다. 제외 목록은 저장해 두고 자동 배정이 피한다.
2. **색의 범위 (2026-11-20 확정, 추천안대로).** 조합을 고정하지 않으려면 조합의 재료가 되는 색 목록은 있어야 한다. 위의 15색을 홈피드 전용 색으로 디자인 시스템에 추가하고, 색을 더하거나 빼는 것은 사용자가 정한다.
3. **전체 배경 이미지 유형의 제목.** 이미지에 글자를 넣지 않기로 했으므로, 이 유형은 제목을 이미지 위에 얹어야 한다. 샘플의 두 장은 이미지 속 글자에 기대고 있어 이 모습이 아직 없다. 샘플을 고쳐 확인받아야 한다.
4. **기존 모양 값의 처리.** 게시 중인 카드를 고려하지 않기로 했으므로 기존 카드를 새 디자인으로 바꿔 보이게 하는 대응 작업은 하지 않는다. 남은 질문은 기존 모양 7가지의 코드를 언제 걷어 내느냐이다. 추천: 새 유형은 새 칸으로 더하고, 기존 모양의 카드는 기간이 끝날 때까지 지금 모습으로 그린 뒤, 남은 카드가 없어지면 별도 티켓으로 걷어 낸다. `list`(랭킹·배지 목록)를 새 디자인에 포함할지는 따로 정한다.
5. **제목 속 칩의 저장 방식.** 추천: 제목 문자열은 그대로 두고, 칩으로 만들 낱말 목록을 따로 저장한다(제목에 기호를 넣으면 알림·상세 화면 등 제목을 그대로 쓰는 곳이 깨진다). 목록이 비어 있으면 제목 속 칩을 만들지 않는다. 낱말은 제목에 그대로 들어 있어야 하고 최대 2개.
6. **박스 모양 옵션의 목록.** 샘플에 있는 모양은 라운드, 물결, 티켓, 우표, 반원 돌출(드랍·픽업 카드의 아이템 박스)이다. 2026-11-20 확정: 다섯 모양 모두 양쪽에서 고를 수 있게 하되, 세로로 긴 텍스트 박스와 가로로 긴 이미지 박스의 두 방향을 모양마다 준비한다.
7. **DB 값 칩의 규칙표 (2026-11-20: 필요하다고 확정, 1회차에서 작성한다).** 자원별로 어떤 값을 칩으로 낼지(미션: 남은 기간·보상·조건 값, 배지: 달성 기준·레벨, 컬렉션: 아이템 수, 장소: 지역 이름)와 카드당 개수 상한. 지금의 「필수 정보 줄」과 겹치는 값의 처리.

16. **컬러셋 교체 어드민 (2026-11-20 사용자 의견, 개발이 끝난 뒤의 기능).** 개발을 마친 뒤 컬러셋이 마음에 들지 않으면 컬러셋별로 교체할 수 있는 어드민 기능이 있었으면 한다. 카리나의 해석과 설계 전제: 컬러셋은 색 15개의 묶음(액센트 원색 5, 연한 색 5, 참조 색 5)이고, 교체는 색 키(`red-soft` 등)는 그대로 두고 키가 가리키는 hex 값을 바꾸는 것이다. 이를 위해 지금부터 지킬 것: (가) 카드에는 hex가 아니라 색 키를 저장한다(2회차에서 반영됨). (나) 화면은 색을 `var(--…)` 변수로만 참조하고 기본값은 `colors.css`에 둔다. 값을 덮어쓰는 층(어드민이 저장한 값을 홈 화면의 CSS 변수로 내려 주는 부분)이 나중에 끼어들 수 있게 한다. (다) 자동 제외 규칙의 계산은 hex를 입력으로 받는 함수로 만들어, 색을 바꾸면 규칙 결과가 다시 계산된다. 나중에 정할 것(**해결, 2026-11-21 사용자 «설계대로 진행», 후속 티켓 20261121_2145·2146**: 저장 표는 `feed_color_overrides`(마이그레이션 352, 행이 없으면 기본값·복원은 행 삭제, 「사용 여부」 칸은 두지 않는다), 적용은 미리보기와 규칙 재계산을 거쳐 «적용»을 눌러야 반영, 제외 규칙 경고는 덮어쓴 hex로 다시 계산, 되돌리기는 기본값 복원, 덮어쓰는 범위는 홈피드 카드 전용 변수 `--feed-color-<키>`): 컬러셋 값을 저장할 표(키, hex, 사용 여부), 바꾼 값의 적용 시점(저장 즉시인지 확인 뒤인지), 바꾼 뒤 제외 규칙에 걸리는 조합의 경고, 되돌리기. 새 색 키를 더하거나 빼려면 허용 값 제약(2회차의 `CHECK`)을 바꾸는 마이그레이션이 필요하다. 이 기능은 6회차(어드민 수동 작성)에 넣는다.

### 서비스/코드베이스 관점

- 색과 칩의 무작위 배정은 화면을 열 때마다 바뀌면 안 된다. 카드마다 정해진 값이 유지돼야 하고, 서버와 브라우저가 같은 결과를 그려야 한다.
- 이웃한 카드가 같은 색 조합이 되지 않게 하는 규칙은 피드 순서를 알아야 하므로 카드 한 장의 값만으로는 정할 수 없다.
- 그림 색과 배경색이 겹치지 않게 하려면(예: 파란 아이템 그림과 파란 배경) 이미지의 대표 색을 알아야 한다.
- 새 칸을 비워 두면 자동으로 정해지게 해서, 기존 카드와 기존 묶음이 그대로 동작해야 한다.
- 어드민 미리보기와 운영툴 기획 미리보기가 실제 화면과 같은 모습을 보여야 한다.
- DB는 staging·프로덕션 공용이다. 칸 추가는 확장 단계만 먼저 하고, 프로덕션 코드가 모르는 값이 화면을 깨지 않는지 확인한다.

### UI/UX 관점

- `ui`·`ds` 유형이므로 채원의 사전 판정을 받는다. 강조색 사용 규칙 변경, 새 색, 새 컴포넌트는 `needs_approval` 대상이다.

- 하위 티켓이 모두 CLOSED이고, 각 하위 티켓의 완료 조건이 충족됐다.

- 사용자가 제외한 색 조합이 자동 배정에 나오지 않는다. 확인 경로: 개발용 미리보기에서 카드 100장 이상을 그려 제외 목록과 대조하는 시험.

- 유형·칩·색을 적지 않은 기존 형식의 묶음과, 새 칸을 채운 묶음이 모두 검증을 통과하고 승인 뒤 카드로 만들어진다.

- 제목 속 칩 낱말을 지정한 카드는 제목 안에 칩이 보이고, 지정하지 않은 카드는 제목이 글자로만 보인다.
- 어드민에서 박스 모양을 골라 텍스트 박스와 이미지 마스크에 각각 적용할 수 있다.
