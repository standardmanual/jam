# [UI] 홈피드 개편 1회차: 카드 유형·박스·색·칩의 규격을 확정한다

## 핵심 요약

- 요구사항: 상위 티켓 20261120_2026의 1회차. 샘플 아티팩트로 확정한 카드 유형 8가지, 박스 모양 5가지, 색 15개와 제외 규칙, 칩 규칙, 도장, 목록형, 컬렉션 모션을 문서 규칙으로 옮기고, 채원의 디자인 사전 판정을 받는다.
- 구현 계획: `docs/service/prd/home-feed/PRD.md` §6 끝에 「개편 규격: 새 카드 유형·박스·색·칩 (구현 전)」 절을 더한다(코드 변경 없음). 채원이 이 절을 읽고 재사용·확장·신규 판정, 승인이 필요한 항목, 디자인 시스템에 없는 값을 낸다.
- 관련 파일: `docs/service/prd/home-feed/PRD.md`(§6 「개편 규격」 절, `## 7. 이동 목적지` 바로 위), 상위 티켓 `docs/tickets/p2-normal/20261120_2026_Feature_홈피드-카드를-새-유형-칩-컬러-조합으로-개편한다-상위.md`. 치수 근거는 `jam-web/design-system/tokens/`의 `radius.css`·`spacing.css`·`typography.css`·`colors.css`.

## 배경 / 문제 정의

사용자가 2026-11-20에 샘플 아티팩트(비공개)를 보고 «이대로 개발을 진행한다»고 정했다. 구현 전에 규격을 문서로 고정해야 2회차(DB)부터 같은 기준으로 만든다. 규격의 원천은 이 문서와 상위 티켓이고, 아티팩트는 시각 확인용이다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 코드는 바꾸지 않는다. 문서만 쓴다.

### UI/UX 관점
- 모서리·여백·간격·글자 크기는 기존 디자인 시스템 값을 쓰고 색만 새 값을 쓴다(사용자 지시). 디자인 시스템에 값이 없는 것(기울기, 박스 홈 크기, 도장 크기, 물결 높낮이, 칩 자리 오프셋)을 채원이 판정한다.
- 강조색 5가지는 지정된 사용처 밖에 쓰지 않는 규칙이 지금 있다(`design-system/tokens/colors.css`). 홈피드 카드 면에 쓰려면 이 규칙을 바꿔야 하므로 채원의 `needs_approval` 항목이다.

### 컨텐츠 관점
- 설명 문장 노출은 샘플대로 확정했다(히어로·배지 소개·컬렉션 소개·드랍·픽업·목록형은 보임, 전체 배경 이미지·배지만·텍스트는 숨김).

## 구현 계획

1. PRD 규격 절 작성(완료).
2. 채원 사전 판정: 재사용할 기존 컴포넌트, 새로 만들 것, 승인 필요 항목.
3. 판정 결과를 상위 티켓에 옮긴다. 승인 필요 항목은 사용자에게 묻는다.

## 완료 조건

- PRD §6에 「개편 규격」 절이 있고, 유형·박스·색(15색과 규칙 4가지)·칩·도장·목록형·컬렉션 모션·이미지 규칙·치수 원칙이 모두 적혀 있다.
- 채원의 사전 판정이 이 티켓에 기록돼 있고, 승인이 필요한 항목은 사용자에게 보고됐다.
- 「아직 정하지 않은 것」 5가지가 PRD와 상위 티켓에 같은 내용으로 남아 있다.

### 채원 사전 판정 (2026-11-20)

**판정**: 서비스 전용(홈피드 한정), 사용자 승인 필요(`needsApproval`), 확신도 높음. 다른 화면이 쓰게 되면 디자인 시스템 승격을 다시 판정한다.

- 재사용: `today/CardFrame.tsx`, `CardBody.tsx`의 제목·필수 정보·설명 조각, `CardThumb.tsx`, `SafeImage`, `TodayCard.tsx`의 모양 분기. 확장: `CardFrame`은 링크를 끄면 클릭 계측도 꺼지므로 둘을 분리한다. 항목 링크는 `CardLink`를 재사용한다.
- 새로 만들 것: 칩(`LabelChip`은 확장 불가), 박스 모양 5종, 도장, 갤러리 4칸, 컬렉션 모션, 색 배정 함수, 유형 8종. `CardChipRow`·`CardImageSlot`은 옛 7모양 전용으로 둔다.
- 디자인 시스템 눈금으로 표현되는 값: 모서리 12px, 칩 여백 12·16, 글자 14·18, 홈 지름 20·24·40. 없는 값(홈 지름 28·52·56, 도장 60px, 칩 높이 32·40, 외곽선 2px, 기울기 여섯 값, 물결 높낮이, 칩 자리 오프셋, 모션 곡선·길이)은 토큰이 아니라 `lib/today`의 서비스 전용 상수 한 파일에 둔다.
- 색: 원색 5개는 기존 `--jam-*`와 같은 값이어서 재사용한다. 신규 10개는 `--jam-*-soft`(연한 색)와 `--feed-ref-*`(참조 색)로 `colors.css`에 둔다. 카드에는 색 키를 저장한다. 강조색 규칙 개정안: «강조색 5개의 지정 사용처에 홈피드 새 카드의 배경·칩·박스·도장을 추가한다. 신규 10색은 홈피드 카드 전용이며 Card·Button·상태색에는 쓰지 않는다.»
- **사용자 승인이 필요한 항목**: ① 신규 색 10개와 값 확정, ② 강조색 사용처 규칙 개정, ③ 새 칩(`--chip-padding` «모든 칩» 원칙의 예외), ④ 새 컴포넌트 묶음, ⑤ 서비스 전용 상수 등록, ⑥ 홈피드 외형 전면 변경과 옛 7모양 공존, ⑦ 수동 지정 경고만 할지·문구 칩 12자, ⑧ 모션 반복 재생.
- 규격에 반영한 수정: 칩 글자는 `--foreground` 고정(`--snow`는 15색 위에서 대비 최고 3.76:1로 AA 미달), 도장 글자는 검정, 자리가 하나뿐인 유형은 칩 1개, 칩은 마스크 밖 형제 층, 목록형 접근성 이름·빈 상태, 모션의 기본 HTML은 퍼진 모습, 관찰자 분리, 무작위 값은 카드 id 시드로 저장, 새 유형 키 분리(옛 `ticket`과 이름 충돌).

### 주요 의사결정 / 핵심 메모

- 2026-11-20: 개편 규격은 구현 전 규격이라 PRD의 기존 절(지금 코드의 사실)을 고치지 않고 §6 끝에 새 절로 더했다. 구현이 끝나면 기존 절을 새 내용으로 바꾼다.
