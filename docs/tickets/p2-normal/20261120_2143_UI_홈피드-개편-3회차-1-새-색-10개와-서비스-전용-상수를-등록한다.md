# [UI] 홈피드 개편 3회차-1: 새 색 10개와 서비스 전용 상수를 등록한다

## 핵심 요약

- 요구사항: 상위 티켓 20261120_2026의 3회차(화면 부품)를 둘로 나눈 앞쪽이다. 새 색 10개를 디자인 시스템 색 파일에 등록하고, 강조색 사용처 규칙을 개정하고, 디자인 시스템에 없는 치수·모션 값을 `lib/today`의 한 파일에 근거와 함께 둔다. 뒤쪽 3회차-2(티켓 20261120_2144)가 이 값을 쓴다.
- 구현 계획: 아래 「구현 계획」의 파일 단위 표를 따른다. 유형은 `ds`. 채원 사전 판정은 1회차 티켓 20261120_2129에 있고 사용자 승인(추천안대로, 2026-11-20)을 받았다.
- 관련 파일: 아래 「구현 계획」 표. 규격 정본은 `docs/service/prd/home-feed/PRD.md` §6 끝의 「개편 규격: 새 카드 유형·박스·색·칩 (구현 전)」 절이다.

## 배경 / 문제 정의

사용자가 2026-11-20에 샘플 아티팩트로 홈피드 카드 디자인을 확정했다. 새 카드는 15색(원색 5개는 기존 `--jam-*` 그대로, 연한 색 5개와 참조 색 5개는 새 값)으로 배경·칩·박스를 짝 짓는다. 지금 `colors.css`는 강조색 5가지를 «Card·Button·상태색에는 매핑하지 않는다»고 막아 두었고 지정된 사용처 밖으로 퍼뜨리지 않는 규칙이 있어, 홈피드 카드 면에 쓰려면 규칙을 먼저 고쳐야 한다. 칩 높이 32·40, 외곽선 2px, 기울기, 박스 홈 지름, 도장 60px, 물결 높낮이, 모션 값은 디자인 시스템에 없어 서비스 전용 상수로 둔다(채원 판정).

## 상세 요구사항

### 서비스/코드베이스 관점

- 이 티켓은 DB·마이그레이션·`src/types/`·`src/lib/admin/`를 건드리지 않는다. `lib/today/`에는 새 파일만 더한다(2회차 DB 세션이 `cards.ts` 등을 병렬로 고치고 있다).
- 새 색 10개의 이름과 값(채원 판정, 사용자 승인):
  - 연한 색: `--jam-red-soft` `#FF9A9A`, `--jam-yellow-soft` `#FFDD73`, `--jam-green-soft` `#9AF7AD`, `--jam-purple-soft` `#D6B9FA`, `--jam-blue-soft` `#8FCFF6`
  - 참조 색: `--feed-ref-red` `#F5442C`, `--feed-ref-blue` `#95C1F7`, `--feed-ref-lime` `#C0DC66`, `--feed-ref-pink` `#E57FBB`, `--feed-ref-yellow` `#F2EC6A`
  - 원색 5개는 기존 `--jam-red`·`--jam-yellow`·`--jam-green`·`--jam-purple`·`--jam-blue`를 그대로 쓴다.
- 강조색 사용처 규칙 개정안(사용자 승인): «강조색 5개의 지정 사용처에 홈피드 새 카드의 배경·칩·박스·도장을 추가한다. 신규 10색은 홈피드 카드 전용이며 Card·Button·상태색에는 쓰지 않는다.» 이 문장을 다섯 곳에 같은 뜻으로 적는다.
- 서비스 전용 상수(한 파일, 값마다 근거 주석): 칩 높이 32·40px, 칩 글자 14·18px·가로 여백 12·16px은 디자인 시스템 눈금이라 값을 새로 만들지 않고 «눈금 어느 값에 해당하는지»를 주석으로 가리킨다. 새 값은 외곽선 2px, 기울기 −8°·−6°·−4°·4°·6°·8°, 박스 홈 지름 28·52·56px(텍스트 박스)·20·40px(이미지 마스크), 도장 60px, 물결 높낮이 12~22px, 모션 길이 0.72초·지연 70~210ms·곡선 `cubic-bezier(0.2, 1.5, 0.4, 1)`이다.
- 15색의 hex는 코드(상수 파일)에도 둔다. 계산(자동 규칙)이 hex를 읽기 때문이다. `colors.css`와 같은지 대조하는 시험을 둔다.
- 카드에는 hex가 아니라 색 키를 저장한다(2회차). 상수 파일은 색 키 15개(`red`·`yellow`·`green`·`purple`·`blue`, `red-soft`·`yellow-soft`·`green-soft`·`purple-soft`·`blue-soft`, `ref-red`·`ref-blue`·`ref-lime`·`ref-pink`·`ref-yellow`)와 각 CSS 변수 이름·hex를 한 표로 가진다. 키 이름은 2회차 DB가 정할 값과 다를 수 있으므로 상수 파일 머리말에 «2회차가 키 이름을 바꾸면 이 표를 맞춘다»고 적는다.

### UI/UX 관점

- 모서리·여백·간격·글자 크기는 기존 디자인 시스템 값(`radius.css`·`spacing.css`·`typography.css`)을 쓰고 색만 새 값이다(사용자 지시).
- 사용자 노출 문구는 없다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- `colors.css`에 신규 10색이 위 이름·값으로 있다. 원색 5개는 새로 만들지 않았다.
- 강조색 사용처 규칙의 개정 문장이 `colors.css` 주석, 디자인 시스템 문서 11 §5.3, `_adherence.oxlintrc.json`(두 곳에 신규 10개 등록), `_ds_manifest.json`에 같은 뜻으로 반영돼 있다.
- `lib/today/feedConstants.ts`에 서비스 전용 상수(칩 높이 32·40, 외곽선 2px, 기울기 여섯 값, 박스 홈 지름 28·52·56·20·40, 도장 60, 물결 12~22, 모션 0.72초·70~210ms·곡선)와 15색 표가 근거 주석과 함께 있고, `lib/today/`에는 새 파일만 더했다.
- 대조 시험이 있고 통과한다: 15색의 hex가 `colors.css`와 같다.
- `Colors.stories.tsx`에서 신규 10색이 보인다.
- `scripts/verify.sh`(lint·typecheck·test·ds:check)가 통과하고 통과 기록이 티켓에 남는다.
- DB·마이그레이션·`src/types/`·`src/lib/admin/`가 바뀌지 않았다.
