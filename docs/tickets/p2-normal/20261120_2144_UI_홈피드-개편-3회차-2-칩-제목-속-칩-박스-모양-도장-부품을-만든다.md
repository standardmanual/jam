## 배경 / 문제 정의

새 카드 디자인(2026-11-20 사용자 확정)은 기울인 알약 칩, 제목 속 칩, 다섯 박스 모양, 도장으로 꾸민다. 화면 연결(4회차)보다 먼저 값을 받아 그리기만 하는 부품을 만들어 Story에서 모든 상태를 확인할 수 있게 한다. 기존 `CardChipRow`·`CardImageSlot`·`LabelChip`은 옛 7모양 전용이라 고치지 않는다(`LabelChip`은 12px 대문자에 외곽선이 없어 확장하지 않는다).

## 상세 요구사항

### 서비스/코드베이스 관점

- 부품은 값만 받는다. DB·`cards.ts`·`getXxx` 조회·`'use client'` 훅 기반 데이터 연결을 쓰지 않는다. 가능하면 서버 컴포넌트로 그릴 수 있게(훅·`window` 없이) 만든다.
- 건드리지 않는다: DB·마이그레이션, `jam-web/src/types/`, `jam-web/src/lib/admin/`, `lib/today/` 안의 기존 파일. `lib/today/`에는 새 파일만 더한다.
- 색은 3회차-1이 등록한 색 키 15개(`FeedColorKey` 등, `lib/today/feedConstants.ts`)와 CSS 변수를 쓴다. hex를 컴포넌트에 직접 적지 않는다(도장·칩의 검정 `--foreground`, 흰색 `--snow`/`--background` 같은 기존 토큰 제외).
- **색 키 교체 전제(2026-11-20, 사용자 의견 추가)**: 개발 뒤 컬러셋이 마음에 들지 않으면 어드민(6회차)에서 색 키가 가리키는 hex 값만 바꿔 교체할 예정이다. 그래서 ① 부품은 색을 hex가 아니라 색 키(`red`·`yellow`·`green`·`purple`·`blue`, `red-soft`·`yellow-soft`·`green-soft`·`purple-soft`·`blue-soft`, `ref-red`·`ref-blue`·`ref-lime`·`ref-pink`·`ref-yellow` 15개, 2회차 DB의 `today_cards.bg_color_key` 등 허용 값과 같다)로만 받는다. ② 부품 안에는 hex를 직접 쓰지 않고 `var(--…)`로만 참조한다. 키에서 CSS 변수 이름을 얻는 함수 `feedColorVar(key)`를 `lib/today/feedConstants.ts`에 둔다(3회차-1이 이미 만들었으면 그것을 쓰고, 없으면 이 티켓이 같은 파일에 더한다). 부품은 이 함수만 거쳐 색을 칠해, 나중에 어드민이 저장한 값을 홈 화면의 CSS 변수로 덮어쓰는 층이 끼어들 수 있게 한다. ③ 자동 제외 규칙(대비·키즈·명도)의 계산 함수는 5회차가 쓴다. 이 티켓에서 구현하지 않지만, 상수 파일의 15색 표가 «키 → CSS 변수 이름 + 기본 hex»의 순수 데이터라 hex를 입력으로 받는 순수 함수가 그 위에 붙을 수 있는 모양인지만 확인한다. 3회차-1에 위 ①②가 어긋나게 들어갔으면 이 티켓에서 바로잡고 「주요 의사결정」에 적는다.
- 무작위 값은 시드를 받아 정한다. `Math.random`을 쓰지 않는다. 같은 시드는 같은 결과를 그리고, 서버와 브라우저가 같은 결과를 그린다(하이드레이션 불일치 없음).
- 사용자에게 보이는 고정 문구는 도장의 `JOIN AND MOVE` 하나뿐이다(영문 고정, 장식이라 `aria-hidden`). 그 밖의 문구는 호출부가 넘기는 값이다. 사용자 노출 문구를 새로 쓰면 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

### UI/UX 관점 (규격 정본은 PRD §6 개편 규격 절)

**칩**
- 검정 2px 외곽선, 알약 모양(`rounded-full`), 글자는 굵게·한 줄.
- 큰 칩: 높이 40px·글자 18px(`text-lg`)·가로 여백 16px. 작은 칩: 높이 32px·글자 14px(`text-sm`)·여백 12px.
- 글자 색은 `--foreground` 고정. 칩 면이 검정일 때만 `--snow` 글자(구분 칩).
- 기울기를 값으로 받는다(−8°, −6°, −4°, 4°, 6°, 8° 여섯 값의 타입. 이 밖의 값은 타입 오류).
- 자리(위치)는 부모가 정한다. 칩 자체는 위치 클래스를 받아 쓸 뿐 자리를 계산하지 않는다. 칩은 박스를 자르는 마스크 밖의 형제 층에 놓는 용도이므로, 컴포넌트가 마스크를 가진 요소의 안에 칩을 넣지 않는다(Story의 합성 예시에서 형제 층 구조를 보인다).
- 면 색은 색 키 15개 + 검정 + 흰색(직접 지정용) 중 하나다.

**제목 속 칩**
- 제목 문자열과 낱말 목록(최대 2개)을 받아 낱말을 칩으로 감싼다. 제목 문자열은 그대로 두고(기호 삽입 없음) 낱말 목록은 따로 받는다.
- 낱말이 제목에 없으면 그 낱말은 무시한다. 목록이 비었거나 모두 무시되면 제목만 그린다(칩 없는 글자로만).
- 3개 이상 들어오면 앞의 2개만 쓴다. 같은 낱말이 제목에 여러 번 나오면 처음 나온 곳만 칩으로 만든다. 낱말끼리 겹치면(예: «문경»과 «문경새재») 먼저 나온 쪽을 쓰고 겹치는 쪽은 무시한다. 빈 문자열 낱말은 무시한다.
- 제목 줄 높이는 칩만큼 커진다(칩 높이가 줄 높이를 밀어 올린다). 읽는 순서와 글자는 제목 문자열과 같아야 한다(보조 기술이 제목을 한 문장으로 읽는다).
- 칩 색은 낱말마다 받는다(없으면 기본 색을 쓴다). 칩은 큰 칩·작은 칩 크기를 고른다.
- 낱말 쪼개기는 순수 함수로 분리해 단독 시험한다.

**박스 모양 5종**
- 모양: 라운드, 티켓, 우표, 물결, 반원 돌출. 같은 모양을 텍스트 박스(세로로 긴 쪽)와 이미지 마스크(가로로 긴 쪽) 두 방향에 모두 쓴다. 아이템 배지 박스(작은 칸)에도 쓸 수 있다. 박스에는 외곽선이 없다.
- 치수(샘플 기준, PRD 표): 라운드 모서리 12px(`rounded-xl`). 티켓: 텍스트 박스는 양쪽 변에 반원 홈 2개씩(지름 56px), 이미지 마스크는 위·아래 변에 홈 2개씩(지름 40px). 우표: 텍스트 박스는 위·아래 변에 지름 24px 홈이 줄지음, 이미지 마스크는 양쪽 변에 지름 20px 홈 5개. 물결: 둘레 전체가 불규칙한 물결, 22개, 높낮이 12~22px, 마디마다 깊이·간격을 조금씩 다르게 한다. 반원 돌출: 아이템 배지 박스는 위·아래로 반지름 28px, 이미지 마스크는 양쪽으로 반지름 52px.
- 구현 방식: 티켓·우표·반원 돌출은 CSS mask(radial-gradient), 물결은 시드로 만든 SVG 경로. 픽셀 고정 치수와 비율 변환이 충돌하는 곳(카드 폭 288~398px에서 박스 크기가 바뀐다)은 구현할 때 맞추고, 어떻게 맞췄는지 코드 주석과 완료 기록에 적는다.
- 반원 돌출은 박스 밖으로 튀어나오므로 마스크가 튀어나온 부분을 자르지 않게 한다(돌출 크기만큼 바깥 여백을 확보하고, 부모에게 필요한 여백 값을 내보낸다).
- 같은 시드는 같은 물결을 그린다. 시드가 없으면 물결을 그리지 않고 라운드로 대신한다(또는 오류) 중 하나를 정해 주석에 적는다.
- 방향 값은 `text`(텍스트 박스)·`image`(이미지 마스크)·`item`(아이템 배지 박스, 작은 칸)이다. `item`에서 PRD가 치수를 정한 것은 반원 돌출(위·아래 반지름 28px)뿐이므로 다른 모양의 `item` 홈 크기는 칸 크기에 맞춰 줄여 쓰되 그 값을 `lib/today/`의 새 파일(박스 모양 전용)에 근거 주석과 함께 두고 완료 기록의 「잔여 이슈」에 «채원 확인 필요»로 올린다(3회차-1의 상수 파일은 고치지 않는다).
- 면 색은 색 키 15개 + 흰색 중 하나이고, 이미지 마스크로 쓸 때는 안쪽 이미지를 모양대로 자르는 용도로 `children`을 받는다.

**도장**
- 문구는 `JOIN AND MOVE`만 쓴다. 안쪽 원과 바깥 원 사이 띠를 도는 도넛 모양, 크기 60px, 가운데 작은 원은 투명한 구멍(뒤의 이미지가 보인다), 검정 외곽선 2px, 글자는 검정, 띠 안쪽 면은 카드의 색 중 하나(색 키로 받는다).
- 글자는 안쪽 원과 바깥 원 사이 띠의 한가운데 경로를 따라 돈다. `aria-hidden`, 포인터 이벤트 없음(`pointer-events: none`).
- 한 카드에 하나만 두므로 위치는 부모가 정한다(자리를 계산하지 않는다).
