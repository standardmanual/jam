# [UI] 홈피드 개편 4회차-2: 새 카드 데이터 연결과 박스형 카드 5유형을 만든다

## 핵심 요약

- 요구사항: 상위 티켓 20261120_2026의 4회차(카드 유형)를 넷으로 나눈 둘째다. ① `today_cards`의 새 칸(`feed_type` 등)을 읽어 새 카드의 표시 데이터(`FeedCardView`)로 바꾸는 연결을 만들고, ② 히어로(`hero_box`)·텍스트(`text_box`)·배지 소개(`badge_intro`)·배지만(`badge_only`)·전체 배경 이미지(`full_image`, 꺼 둠) 다섯 유형을 3회차 부품(칩·제목 속 칩·박스·도장)으로 그린다. 컬렉션 소개·드랍·픽업·목록형은 4-3, 개발용 미리보기 페이지와 staging 확인은 4-4다.
- 구현 계획: 아래 「구현 계획」의 파일 단위 표를 따른다. 유형은 `ui`.
- 관련 파일: 아래 표. 규격 정본은 `docs/service/prd/home-feed/PRD.md` §6 끝 「개편 규격」 절. 4-1(20261121_0012)이 만든 계산 함수와 3회차(20261120_2143, 20261120_2144)가 만든 부품을 쓴다. 샘플 보드 사본: `/private/tmp/claude-502/-Volumes---------JAM---claude-worktrees-feed-redesign-ui-b07f8e/ffe0ef70-d8d6-4567-a5c5-6e883466d7b8/scratchpad/artifact-files/4189ae18-0a3f-46cb-8d5f-753f1ec8981b/project/Feed2.dc.html`(없으면 아래 「샘플 치수」 표만 따른다).

## 배경 / 문제 정의

사용자가 2026-11-20에 샘플로 확정한 새 카드 디자인을 실제 홈 화면 코드로 옮기는 단계다. 부품(3회차)과 값을 정하는 계산(4-1), DB 칸(2회차)은 있지만 «DB 행 → 새 카드 표시 데이터 → 화면»을 잇는 층이 없다. `feed_type`이 NULL인 기존 카드는 지금 모습 그대로여야 하고(게시 중인 카드는 고려하지 않는다는 결정이지만 옛 7모양은 공존한다), 새 유형이 아직 그릴 수 없는 `feed_type`도 옛 모양으로 되돌아가 화면이 비지 않아야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·`src/lib/admin/`를 건드리지 않는다(읽기만). `CardShape`·`RENDERED_SHAPES`·`shape` 열 의미는 바꾸지 않는다(옛 이름 `ticket`·`hero`·`list`와 새 유형의 이름이 섞이지 않게 새 유형은 `feed_type` 키로만 구분한다, 규격 «새 유형 키»).
- **표시 데이터**: `CardView`에 새 갈래 `FeedCardView`를 더한다. 새 갈래는 `shape` 대신 `feedType`(`FeedType`, 4-1 `feedChipSlots.ts`)을 판별 값으로 갖고, 값만 담는다(훅·조회 없음). 계측 정보(`tracking`)는 옛 모양과 같은 구조를 쓰되 `shape`에는 행의 옛 `shape` 값을 그대로 넣어 기존 집계가 섞이지 않게 하고 `feedType`을 선택 필드로 더한다. **GA 이벤트 파라미터는 바꾸지 않는다**(집계 스키마 변경은 사용자 결정 사항이라 잔여 이슈로 적는다).
- **`toCardView`**: `feed_type`이 있고 4-2가 그릴 수 있는 다섯 유형 중 하나면 `FeedCardView`를 낸다. 그 밖(NULL, 4-3 유형, 모르는 값)은 지금 경로 그대로다. 기존 카드의 출력이 한 글자도 바뀌면 안 된다(기존 시험이 그대로 통과해야 한다).
- **값 해석 함수 `resolveFeedLook`(신규 `lib/today/feedLook.ts`)**: 행의 새 칸(`bg_color_key`·`chip_color_key`·`box_color_key`·`chips`·`title_chip_words`·`show_description`·`stamp_enabled`·`stamp_slot`·`box_shape`·`box_kind`·`feed_seed`)과 4-1 함수를 합쳐 «그릴 값»을 낸다. 칸이 NULL이면 4-1의 `assignFeedColors`·`assignChipPlacement`가 정한다. 시드는 `feed_seed`가 있으면 그것, 없으면 카드 id의 해시다(서버와 브라우저가 같은 값을 내야 하고 `Math.random`·`Date.now`는 쓰지 않는다). 이웃 카드는 보지 않는다(등록 때 값을 저장해 고정하는 일은 5~6회차이고, 그 전까지 화면이 같은 입력에서 같은 값을 계산하는 것으로 충분하다). `box_shape`가 NULL이면 시드로 5종 중 하나를 정한다(박스를 끄는 선택지는 없다). 칩 색 키는 15색 키 또는 `black`(구분 칩)이다. 도장은 `stamp_enabled`가 참일 때만 그리고 한 카드에 하나다.
- **칩 구성**: 저장된 `chips`(문구 칩·구분 칩·값 칩 정의)가 있으면 그것, NULL이면 자원에 따른 구분 칩(«미션»·«체크인» 등)과 값 칩을 4-1 `buildValueChips`로 만든다. 카드당 최대 2개, 제목 속 칩은 따로 최대 2개이고 `title_chip_words`에서 온다. 값 칩의 입력은 **지금 `CardView`·`TodayCardWithHref`가 이미 싣고 있는 값만** 쓴다(기간·보상 포인트·컬렉션 아이템 수·체크인 필요 배지 수·장소 이름). 미션 조건 값·배지 달성 기준·레벨은 `cards.ts` 조회 확장이 필요해 4-4로 미룬다(그 칩은 만들지 않는다, 칩이 없는 카드는 정상이다).
- **카드 컴포넌트**: 새 파일 `components/today/feed/` 아래에 유형별 컴포넌트와 조립 컴포넌트(`FeedCard`)를 둔다. 3회차 부품(`FeedChip`·`ChipTitle`·`FeedBox`·`FeedStamp`)과 기존 `CardFrame`(접근·계측 겹)·`SafeImage`·`CardThumb`를 그대로 쓴다. 기존 `CardChipRow`·`CardImageSlot`·`LabelChip`·옛 7모양 컴포넌트는 고치지 않는다. 카드 전체 링크는 `CardFrame`이 건다(CTA 버튼은 모든 카드에서 뺀다).
- **`TodayCard` 분기**: `view`가 새 갈래면 `FeedCard`로 가고, 아니면 지금 `switch` 그대로다. 새 갈래의 `FeedCard`는 모르는 `feedType`이면 `null`이 아니라 호출부가 옛 경로를 쓰도록 `toCardView` 단계에서 이미 걸러져 있어야 한다(둘이 어긋나면 카드가 사라지므로, 지원 유형 목록 한 곳을 둘이 함께 쓴다).
- **전체 배경 이미지(`full_image`)는 꺼 둔다**: 이미지 위 제목의 대비 기준이 없어(규격 «이미지 위 제목», 이미지 규칙 8회차 전) 켜지 않는다. 컴포넌트와 Story는 만들되 `FEED_FULL_IMAGE_ENABLED = false` 상수(`feedConstants.ts`에 추가만 한다)가 거짓이면 `toCardView`가 이 유형을 옛 경로로 보낸다. 제목 뒤에는 어두운 막이 필요하다는 점을 코드 주석에 적고, 막의 농도는 채원이 정할 값으로 남긴다(Story에서 보이게 하되 상수로 분리).
- 서버 컴포넌트로 그려진다(`'use client'` 금지, 상호작용 없음). 모션·관찰자는 4-3(컬렉션)에서만 쓴다.

### UI/UX 관점

- **샘플 치수**(2026-11-20 사용자 확정, 폭 390 화면의 카드 폭 358, 기준은 샘플 보드): 모든 카드는 안쪽 여백 16px(`p-4`), 모서리 `rounded-2xl`(16px), 제목 30px/줄 36px 굵기 900(자간 −0.02em), 설명 14px/20px 굵기 500, 제목과 설명 사이 간격 8px, 글자색 `--foreground`. 치수는 디자인 시스템 눈금 값을 쓰고 맞는 값이 없을 때만 `feedConstants.ts`에 근거와 함께 추가한다. 샘플의 높이는 `min-height`로 두고 내용이 길면 늘어난다(제목 줄 수가 달라도 글자가 잘리지 않게).

- 사용자 노출 문구는 카드 제목·설명·칩 글자(데이터에서 온다)뿐이다. 코드에 새로 적는 문구는 접근성 이름(이미지 `alt`)뿐이고 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.
- 접근성: 장식(도장·박스 모양)은 `aria-hidden`, 칩의 글자는 읽힌다(기울임은 시각 효과). 터치 영역은 카드 전체 링크다.

## 채원 사전 판정 (1회차 판정 20261120_2129를 이 회차에 적용, 카리나가 옮겨 적음)

채원①은 새 티켓을 읽지 못하므로(main 기준 워크트리) 판정의 핵심을 여기에 적고 `reuseDecision`으로도 넘긴다. 결론: **서비스 전용 구현(승인 완료)**. 디자인 시스템에 새로 올릴 부품은 없고 3회차 서비스 전용 부품을 재사용한다.

- 재사용: `FeedChip`·`ChipTitle`·`FeedBox`·`FeedStamp`(3회차), `CardFrame`·`SafeImage`·`CardThumb`(기존). 새로 만들지 않는다: 칩·박스·도장.
- 색: 부품에는 색 키만 넘기고 `feedColorVar(key)`를 거쳐 `var(--…)`로 칠한다(hex 금지). 글자색 `--foreground` 고정, 검정 칩만 `--snow`.
- 치수: 모서리·여백·간격·글자 크기는 디자인 시스템 눈금, 색만 새 값. 새 치수는 `feedConstants.ts`에 근거와 함께.
- 외곽선: 칩과 도장에만. 박스·이미지·카드 면에는 없다.
- 상태: 칩 0·1·2개, 제목 속 칩 0·1·2개, 도장 유무, 박스 5모양, 이미지 없음(색 면), 설명 숨김·보임을 Story에서 모두 보인다.
- 모션 없음(컬렉션은 4-3). 기울기는 정지 상태 값이다.
- 채원 확인 대기 값(3회차 보고): 칩이 모서리에 걸치는 정도 가로 12·세로 16, 아이템 박스 줄인 홈, 텍스트 박스 우표 홈 8개, 텍스트 박스 돌출 반지름 28. 이 회차에서 화면에 처음 올라가므로 사후 리뷰에서 눈으로 확인한다.
- 지킬 점: 물결 박스의 안쪽 여백, 텍스트 박스 티켓 `min-height` 190 이상, `full_image`는 꺼 둠.
