# [UI] 홈피드 개편 4회차-3: 컬렉션 소개·드랍·픽업·목록형 카드 3유형을 만든다

## 핵심 요약

- 요구사항: 4회차(카드 유형)의 셋째다. 4-2가 만든 새 카드 연결(`FeedCardView`·`resolveFeedLook`·`FeedCard`) 위에 남은 세 유형을 더한다. ① 컬렉션 소개(`collection_intro`): 대표 그림 뒤에서 아이템 배지 4개가 스크롤 진입 때 방사형으로 퍼지는 모션. ② 드랍·픽업(`drop_pickup`): 아이템 배지 3개를 박스에 담아 한 줄로 둔다. ③ 목록형(`gallery_list`): 제목·설명 아래 4칸 갤러리(항목 3개와 화살표 칸)이고 항목마다 따로 링크를 건다. 필요한 값을 카드 조회가 싣도록 `cards.ts`를 넓힌다. 개발용 미리보기 페이지와 staging 확인은 4-4다.
- 구현 계획: 아래 「구현 계획」의 파일 단위 표를 따른다. 유형은 `ui`.
- 관련 파일: 아래 표. 규격 정본은 `docs/service/prd/home-feed/PRD.md` §6 끝 「개편 규격」 절의 «카드 유형 8가지»·«목록형»·«컬렉션 모션». 4-2(20261121_0041)가 만든 `components/today/feed/`, `lib/today/feedLook.ts`, `lib/today/feedChipLayout.ts`와 4-1의 `feedChipSlots.ts`를 쓴다. 샘플 보드 사본: `/private/tmp/claude-502/-Volumes---------JAM---claude-worktrees-feed-redesign-ui-b07f8e/ffe0ef70-d8d6-4567-a5c5-6e883466d7b8/scratchpad/artifact-files/4189ae18-0a3f-46cb-8d5f-753f1ec8981b/project/Feed2.dc.html`(없으면 아래 표만 따른다).

## 배경 / 문제 정의

4-2가 박스형 다섯 유형과 «DB 행 → 새 카드 → 화면» 연결을 만들었다. 지원하지 않는 `feed_type`은 옛 경로로 되돌아간다. 이 티켓은 그 목록에 `collection_intro`·`drop_pickup`·`gallery_list`를 더한다. 세 유형은 새 값이 필요하다: 컬렉션의 대표 그림과 아이템 배지 그림, 드랍·픽업 박스에 담을 아이템 배지 3개, 목록형 항목(저장된 `list_items`·`list_more_href`). 컬렉션 모션만 브라우저 스크립트(`'use client'`)이고 나머지는 서버 컴포넌트다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·`src/lib/admin/`·GA 이벤트 파라미터를 건드리지 않는다. 옛 7모양 컴포넌트와 4-2의 박스형 카드 컴포넌트는 고치지 않는다(조립 `FeedCard`·`toCardView`·`feedLook.ts`의 지원 목록에 더하는 것만 한다).
- **지원 목록 확장**: `FEED_RENDERED_TYPES`에 세 유형을 더한다. 필요한 값이 없는 행(컬렉션 그림이 없거나 목록 항목이 0개 등)의 처리는 아래 각 유형에 적었다. 처리하지 못하는 행은 `toCardView`가 **옛 경로로 되돌린다**(화면이 비지 않는다). 기존 카드의 출력은 한 글자도 바뀌면 안 된다(기존 시험 무수정 통과).
- **조회 확장(`cards.ts`)**: 컬렉션 소개 카드에 쓸 값(컬렉션 대표 그림은 카드의 `cover_image_url`이고, 속한 아이템 배지 그림 최대 4개와 이름)과 드랍·픽업 카드에 쓸 아이템 배지(카드가 가리키는 `resolved_badges`에서 앞 3개) 중 지금 `getTodayCards`가 싣지 않는 값만 더한다. **`select('*')`로 읽는 기존 경로를 좁히지 말고, 새 값은 기존 결과에 선택 필드로만 더한다.** 이 조회는 홈 서버 경로라 호출 수가 늘지 않게 기존 조회와 묶거나 한 번의 `in(...)` 조회로 한다(카드 수가 많아도 N+1이 없게). 새 조회가 실패해도 카드는 그려진다(그 값이 없는 모습으로). 값을 읽을 코드가 어디 있는지(예: 아이템 배지 그림의 출처 `badges`·`items`·`inventory` 중 무엇인지)는 코드를 읽어 정한다.
- **컬렉션 소개 `collection_intro`**:
  - 구성(샘플): 높이 416, 안쪽 여백 16. 위 영역 높이 240 가운데에 대표 그림 168×168(`object-contain`), 그 뒤 가운데에 아이템 배지 4개(크기 68~84, 샘플 80·64·72·84). 아래에 제목(컬렉션 이름 30/36)과 설명. 칩은 작은 칩 1개가 그림 모서리(칩 자리 목록은 4-1 `feedChipSlots.ts`).
  - 모션: 카드가 화면에 **55% 넘게** 들어오면 퍼지고, 화면 밖으로 **완전히** 나가면 다시 모이고, 다시 들어오면 재생된다. 관찰자 임계값 0.55와 «나감» 판정(`isIntersecting === false`)을 쓴다. 모션 관찰자는 노출 계측의 관찰자(50%, `TodayCardTracker`)와 **분리한다**(같은 관찰자를 공유하지 않는다).
  - 값(샘플의 계산): 모이는 상태는 `translate(0,0) rotate(0) scale(0.3)`·불투명도 0, 퍼진 상태는 배지마다 도착 위치·기울기(예: 위 영역 326×240 기준 (−112,−30)·8°, (−84,78)·−14°, (104,−76)·−9°, (112,48)·12°)와 불투명도 1이다. 시작 시각은 배지마다 70~210ms 다르게(샘플 0·140·70·210ms), 0.72초 동안 `cubic-bezier(0.2, 1.5, 0.4, 1)`(`FEED_MOTION`)이다.
  - 저장 값: `collection_burst`(2회차 DB)는 배지마다 `{x,y,tilt,size,delay_ms}`다. `x`·`y`는 가운데에서 영역 가장자리까지를 1로 본 -1~1이다(샘플 위치 ≈ x ±0.69, y ±0.65). 값이 NULL이면 **카드 id 시드로 4개를 불규칙하게 정한다**(`resolveFeedLook` 확장, `createRng`·`hashSeed` 재사용, `Math.random` 금지, 서버와 브라우저가 같은 값). 배지끼리·대표 그림과 지나치게 겹치지 않게 최소 거리를 두는 규칙을 코드와 시험에 둔다.
  - **기본 HTML은 퍼진 모습**이고 스크립트가 도착하면 «모인 상태»를 건다(스크립트가 늦거나 꺼져도 배지가 사라지지 않는다). 기기에서 «동작 줄이기»(`prefers-reduced-motion: reduce`)가 켜져 있으면 모션 없이 퍼진 모습만 보인다(전환 없음). 모션은 `transform`·`opacity`만 쓴다.
  - 아이템 배지 그림이 0개면 모션 없이 대표 그림만, 대표 그림이 없으면 그 행은 옛 경로로 보낸다. 배지 4개 미만이면 있는 만큼만 퍼진다.
  - 접근성: 모션 배지는 장식이라 `alt=""`·`aria-hidden`(카드 제목이 이름을 말한다). 대표 그림의 `alt`는 컬렉션 이름이다.
- **드랍·픽업 `drop_pickup`**:
  - 구성(샘플): 높이 360. 위에 아이템 배지 3개를 박스에 담아 한 줄(영역 높이 184, 3칸 간격 8, 칸마다 배지 80×80을 가운데에, 박스 모양은 선택한 5종 중 하나를 **아이템 방향**(`item`)으로 그림). 칩은 박스 줄 위에 «드랍»·«픽업» 문구 칩 2개(큰 칩 40, 검정 하나와 색 하나, 서로 대각선). 아래에 제목과 설명.
  - 배지가 3개 미만이면 있는 만큼, 0개면 옛 경로로 보낸다. 이미지가 없는 배지는 이름 글자로 대신한다.
- **목록형 `gallery_list`**:
  - 구성(샘플): 높이 260 이상(내용이 늘면 늘어난다). 위에 제목·설명, 아래에 4칸 한 줄 갤러리(`grid-cols-4`, 칸 간격 8). 앞 세 칸은 항목: 정사각(`aspect-square`), 모서리 12(`rounded-xl`), 면 색은 박스 색 키, 안에 그림(있으면) 또는 항목 이름 글자(그림이 없으면, 12px 굵게 가운데), 아래에 이름 12px 굵게 두 줄까지(`line-clamp-2`). 마지막 칸은 검정 바탕 정사각 안에 «→» 화살표이고 `list_more_href`로 간다.
  - 링크: 항목마다 `list_items[i].href`로 따로 링크를 건다. **카드 전체에는 링크를 걸지 않는다**(`CardFrame link={false}`). 단, 카드 전체 링크를 끄면 클릭 계측도 꺼지므로 **링크와 계측을 분리한다**: 항목·화살표 클릭도 카드 클릭으로 기록되게 한다(`TodayCardTracker`·`createClickReporter`가 클릭을 어떻게 읽는지 코드를 보고 앵커가 겹치지 않는 방식으로 맞춘다. 트래커의 동작을 바꿔야 하면 기존 카드의 동작이 그대로임을 시험으로 고정한다). 화살표 칸의 접근성 이름은 «{제목} 전체 보기»다.
  - 항목이 3개보다 적으면 빈 칸 없이 화살표 칸을 앞으로 당긴다. `list_more_href`가 없으면 화살표 칸을 그리지 않는다. 항목이 0개면 카드를 그리지 않는다(`toCardView`가 옛 경로로 보낸다).
  - 터치 영역: 칸 하나의 폭은 약 85px라 터치 영역 44px을 채운다.
- 칩 자리·기울기·색 배정은 4-2의 `resolveFeedLook`을 그대로 쓴다. 새 유형의 설명 노출은 PRD 표대로 `collection_intro`·`drop_pickup`·`gallery_list` 모두 «보임»이고 `show_description === false`면 숨긴다.
- 서버 컴포넌트가 기본이다. `'use client'`는 컬렉션 모션 부분(작은 래퍼 하나)에만 쓴다.

### UI/UX 관점

- 모서리·여백·간격·글자 크기는 디자인 시스템 눈금, 색만 새 값(색 키 + `feedColorVar`)이다. 글자색은 `--foreground` 고정, 검정 칩만 `--snow`. 박스에는 외곽선이 없다(칩·도장에만).
- 모션 값(0.72초·70~210ms·탄성 곡선)은 `FEED_MOTION`에 이미 있다. 새 값이 필요하면 근거와 함께 추가만 한다.
- 사용자 노출 문구는 데이터에서 오는 제목·설명·칩·항목 이름과 접근성 이름(«{제목} 전체 보기», 이미지 `alt`)뿐이다. `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다.

## 채원 사전 판정 (1회차 판정 20261120_2129를 이 회차에 적용, 카리나가 옮겨 적음)

채원①은 새 티켓을 읽지 못하므로 판정의 핵심을 여기에 적고 `reuseDecision`으로도 넘긴다. 결론: **서비스 전용 구현(승인 완료)**. 새 디자인 시스템 부품은 없다.

- 재사용: `FeedChip`·`FeedBox`(item 방향)·`ChipTitle`(3회차), `FeedCard`·`FeedCardParts`·`resolveFeedLook`(4-2), `CardFrame`·`SafeImage`(기존). 새로 만들지 않는다: 칩·박스·도장.
- 색은 색 키 + `feedColorVar`만(hex 금지). 새 치수·모션 값은 `feedConstants.ts`에 근거와 함께 추가만.
- 모션 규칙은 PRD «컬렉션 모션»대로(55%·재생 반복·동작 줄이기·기본 HTML 퍼짐·관찰자 분리). 동작 줄이기에서 전환이 없어야 한다.
- 상태: 컬렉션(모인·퍼진·동작 줄이기, 배지 0~4개), 드랍·픽업(배지 1~3개, 이미지 없음), 목록형(항목 1~3개, 화살표 유무, 그림 없는 항목)을 Story로 보인다. 모션 Story는 모인 상태와 퍼진 상태를 따로 고정해 볼 수 있어야 한다.
- 지킬 점: 물결 박스 안쪽 여백, 아이템 박스 홈 치수(3회차 «줄인 값»은 채원이 이 화면에서 눈으로 확인), 폭 320에서 칩이 좌우 16px 바깥으로 나가지 않는다.

### 구현 내용 요약

컬렉션 소개·드랍·픽업·목록형 세 유형을 4-2의 새 카드 연결 위에 더했다. `FEED_RENDERED_TYPES`가 8유형이 됐고, 그릴 값이 없는 행(컬렉션 커버 없음, 배지 0개, 목록 항목 0개)은 `toCardView`가 옛 경로로 보낸다.

- 조회(`cards.ts`): 이미 읽던 컬렉션 아이템 배지 조회에 `image_url`만 더해 선택 필드 `item_badges`(item 타입만, 이름 중복 제거, 최대 4개)로 싣는다. 조회 수는 그대로이고 실패해도 카드는 그려진다. 드랍·픽업은 `resolved_badges` 앞 3개를 쓴다.
- 컬렉션: `FeedCollectionBurst`(`'use client'`)가 카드 루트 요소를 관찰한다(임계값 0.55, 나가면 모임, 다시 들어오면 재생). 기본 HTML은 퍼진 모습이고, 동작 줄이기에서는 관찰자를 만들지 않아 전환이 없다. 배지 위치는 `collection_burst`가 NULL이면 카드 시드로 사분면마다 하나씩 정하고 최소 거리 규칙이 있다.
- 드랍·픽업: 박스 줄의 네 모서리 자리에 대각선 칩 «드랍»(색)·«픽업»(검정) 두 개. 칩이 저장되지 않은 행의 자동 칩이다.
- 목록형: 카드 전체 링크 없이 항목·화살표 링크만 있고(`CardFrame link={false}` + `trackLinkClicks`, 트래커 `clickOnLinksOnly`) 클릭은 카드 클릭으로 계측된다. 항목·더 보기 주소는 내부 경로 또는 `https://`만 링크가 된다(`isSafeListHref`).
