# [UI] 홈피드 개편 4회차-4: 개발용 미리보기 페이지와 값 칩 조회를 만든다

## 핵심 요약

- 요구사항: 4회차(카드 유형)의 마지막이다. ① 새 카드 8유형을 한 화면에서 보는 개발용 미리보기 페이지 `/dev-sample/home-feed-cards/new`(가짜 데이터, 서비스 데이터 조회 없음. 같은 주소의 `/dev-sample/home-feed-cards`에는 옛 7모양 샘플 페이지가 이미 있어 그대로 두고 새 페이지는 `/new` 아래에 둔다)를 만든다. ② 자동 규칙으로 카드 120장을 배정해 그려 보고, 배정 결과가 규칙을 모두 통과하는지와 제외 조합과 겹치지 않는지를 화면에서도 시험에서도 확인한다. ③ 값 칩에 필요한 미션 조건 값·배지 달성 기준·레벨을 카드 조회가 싣게 하고 값 칩 입력에 연결한다(4-1이 만든 규칙표의 «지금 카드에 없는 칸»).
- 구현 계획: 아래 「구현 계획」의 파일 단위 표를 따른다. 유형은 `ui`.
- 관련 파일: 아래 표. 규격 정본은 `docs/service/prd/home-feed/PRD.md` §6 끝 「개편 규격」 절의 «DB 값 칩의 규칙표»·«자동 배정». 4-1(20261121_0012)·4-2(20261121_0041)·4-3(20261121_0115)이 만든 코드를 쓴다.

## 배경 / 문제 정의

세 회차에서 계산 함수(4-1)와 카드 컴포넌트(4-2, 4-3)가 만들어졌지만 서비스 화면에서 새 카드를 쓰려면 `today_cards` 행이 필요해 아직 눈으로 모아 볼 곳이 없다. 이 티켓은 (가) 사용자와 채원이 모든 유형·상태를 한 화면에서 확인하게 하고(상위 티켓 완료 조건의 확인 경로 «`/dev-sample/home-feed-cards`»는 옛 7모양 샘플이 쓰고 있어 새 카드는 `/dev-sample/home-feed-cards/new`로 바꾼다), (나) 값 칩이 쓰는 값 중 조회가 빠진 것을 채운다. 스테이징 배포는 사용자가 push를 요청할 때 이뤄지므로 이 티켓의 범위에 넣지 않는다.

## 결정 기록

- 2026-11-21: 아현이 구현 전에 멈췄다. `(main)/dev-sample/home-feed-cards/page.tsx`(옛 7모양 샘플, 667줄)가 이미 `/dev-sample/home-feed-cards`를 서비스하고, 같은 주소의 새 페이지는 빌드가 막힌다. 선택지 A(`/new` 하위에 새 페이지, 옛 페이지 무변경)를 카리나가 골랐다. 옛 페이지 교체(B)는 사용자 승인이 필요하고, 옛 페이지에 덧붙이기(C)는 667줄 위에 600줄이 쌓이고 홈 틀 폭 기준과 맞지 않는다. 상위 티켓의 확인 경로 문구는 `/dev-sample/home-feed-cards/new`로 읽는다. 옛 7모양이 모두 끝나 걷어낼 때(PRD §6) 두 페이지를 합칠지 정한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·`src/lib/admin/`·GA 이벤트 파라미터를 건드리지 않는다. 옛 7모양 컴포넌트와 4-2·4-3 카드 컴포넌트의 동작은 바꾸지 않는다(필요하면 Story·시험만 더한다).
- **미리보기 페이지** `jam-web/src/app/(main)/dev-sample/home-feed-cards/new/page.tsx`(옛 샘플 `(main)/dev-sample/home-feed-cards/page.tsx`와 같은 `(main)` 그룹이라 같은 틀 안에서 열린다. **옛 샘플 페이지 파일은 한 글자도 바꾸지 않는다.** 같은 주소에 새 `page.tsx`를 만들면 Next 빌드가 막힌다): 가짜 데이터만 쓰는 서버 컴포넌트다(DB·세션·`getTodayCards` 호출 없음, 계측 `tracking` 없음). 기존 `app/dev-sample/item-badge-serial`과 같은 «샘플 전용» 안내 문구를 머리말 주석에 적는다. 폭 390 화면(카드 폭 358) 기준 한 열로 보이고, 데스크톱에서도 한 열 최대 폭 안에 둔다.
- **구성**: ① 유형별 구역 8개(히어로·전체 배경 이미지·배지 소개·배지만·컬렉션 소개·드랍·픽업·텍스트·목록형). 전체 배경 이미지는 서비스에서는 꺼져 있으므로 이 페이지에서만 컴포넌트를 직접 렌더해 «꺼짐 상태, 켤 때 채원이 정함»이라고 표시한다. ② 박스 모양 5종 × 박스가 있는 유형(히어로·텍스트·드랍·픽업). ③ 칩 0·1·2개·제목 속 칩·도장 켬/끔·설명 숨김 상태. ④ **자동 배정 구역**: 서로 다른 시드 120장을 `resolveFeedLook`(칩·색 NULL)으로 배정해 그리고, 위쪽에 요약(카드 수, 규칙 위반 수, 제외 조합과 겹친 수, 되돌림 기본 조합이 쓰인 수)을 적는다. 사용자가 검수표에서 제외한 조합 예시를 미리보기용 입력으로 넣어 요약에 반영되게 한다. ⑤ 모션 구역: 컬렉션 카드의 모인·퍼진 상태를 고정해 나란히 보이고, 실제 스크롤 재생을 보는 카드 하나를 둔다.
- 가짜 이미지는 저장소에 이미 있는 정적 자산(예: `/badges/sample/…`)이나 색 면으로 대신한다(새 이미지 파일을 더하지 않는다. 더해야 하면 작은 SVG 하나로 한정). 외부 주소·내려받기 금지.
- 이 페이지의 가짜 데이터 만들기와 요약 계산은 **페이지 파일이 아니라 순수 함수 파일**(`jam-web/src/lib/today/feedPreviewData.ts`, 신규)에 둔다. 같은 입력이면 같은 결과이고 `Math.random`·`Date.now`를 쓰지 않는다. 120장 배정의 «규칙 위반 수»는 4-1의 `feedColorRules` 함수로 센다. 이 함수를 시험(아래)이 검사한다.
- **값 칩 조회 확장(`cards.ts`)**: 4-1 `feedValueChips.ts` 상단 표가 «지금 `ResolvedMission`·`ResolvedBadge`에 실려 있지 않다»고 적은 칸 — 미션 조건 값(`condition_json`)과 배지 달성 기준(`condition_json`)·레벨 — 을 **기존 결과에 선택 필드로** 더한다. 이미 `select('*')`로 읽는 미션 행에서 꺼내는 값은 조회를 늘리지 않고, 배지 조회(`'id, name, image_url, rarity'`)에는 필요한 컬럼만 더한다. 새 조회를 만들지 않는다(N+1 금지). 실패하거나 값이 없으면 그 칩을 만들지 않는다(칩이 없는 카드는 정상). 값 칩 변환은 4-1 `feedValueChips.ts`가 이미 한다. `resolveFeedLook`이 그 입력에 연결한다(자동 칩 구성: 값 칩 → 구분 칩 순서는 4-2에서 정함, 그대로).
- 값 칩에 쓰는 미션·배지 값이 «필수 정보 줄»(기간·보상)과 겹치면 칩이 가져가고 정보 줄에서 뺀다는 규격(PRD «DB 값 칩의 규칙표»)은 **새 카드 갈래에만** 적용한다(새 카드는 정보 줄을 그리지 않는다). 옛 카드의 정보 줄은 바꾸지 않는다.
- **정책 대시보드**: 색 거르는 규칙의 임계값은 화면 표시 규칙이지 운영 정책·밸런스 수치가 아니어서 `policiesData.ts`를 갱신하지 않는다(판단을 「주요 의사결정」에 적는다).

### UI/UX 관점

- 모서리·여백·간격·글자 크기는 디자인 시스템 눈금이다. 페이지의 안내 글(구역 제목·상태 설명)은 한국어 해요체 문장이고 `docs/service/writing/UX_WRITING_GUIDELINE.md`를 따른다. 개발용 페이지라 길게 쓰지 않는다.
- 구역 제목은 눈에 띄지만 카드보다 앞서지 않게 한다. 요약 숫자는 한눈에 읽히는 표로 보인다.
- 이 페이지는 `noindex`다(`robots` 메타 또는 `metadata`로 검색 색인에서 뺀다).

## 채원 사전 판정 (1회차 판정 20261120_2129를 이 회차에 적용, 카리나가 옮겨 적음)

결론: **서비스 전용 구현(승인 완료)**. 새 디자인 시스템 부품은 없다. 이 티켓은 화면 부품을 만들지 않고 기존 카드 컴포넌트를 모아 보이는 개발용 페이지와 조회 확장이다.

- 재사용: `TodayCard`·`FeedCard`와 유형별 카드, `resolveFeedLook`, `feedColorRules`·`feedAssign`(4-1). 새로 만들지 않는다: 카드·칩·박스.
- 이 페이지에서 채원이 눈으로 확인할 값(사후 리뷰): 칩이 모서리에 걸치는 정도(가로 12·세로 16), 아이템 박스 줄인 홈, 텍스트 박스 우표 홈 8개, 돌출 반지름 28, 목록형 칩과 긴 제목의 겹침, 드랍·픽업 아래쪽 칩 16px 걸침, 컬렉션 배지 배치.
- 상태가 한 화면에서 모두 보여야 한다(유형 8 × 박스 5 × 칩 0·1·2 × 도장 × 설명 숨김 × 컬렉션 모인·퍼진).

## 완료 조건

- `/dev-sample/home-feed-cards/new`가 로컬에서 열리고 유형 8개·박스 5종·칩·도장·설명 숨김·컬렉션 모인/퍼진 상태가 보인다.
- 120장 자동 배정의 규칙 위반이 0이고 제외 조합과 겹침이 0이다(화면 요약과 시험 모두).
- 값 칩 입력(미션 조건 값, 배지 달성 기준·레벨)이 새 카드 갈래에서 칩 문구로 나온다. 기존 카드 출력은 그대로다.
- `scripts/verify.sh`가 통과한다.
