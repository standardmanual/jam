# [Feature] 홈피드 개편 5회차-1: 어드민 저장 경로와 값 검증, 저장 때 자동 값 고정을 만든다

## 핵심 요약

- 요구사항: 5회차(어드민 수동 작성)의 첫 조각이다. 화면 없이 **저장 경로**만 만든다. ① 어드민 폼 값과 저장 페이로드에 개편 칸(마이그레이션 349의 15개)을 더하는 순수 함수, ② 그 값을 검증하는 순수 함수(허용 값·구조·제목 속 칩 낱말·칩 자리·목록 항목 주소), ③ `POST·PATCH /api/admin/today`가 새 칸을 검증해 저장하고, **새 카드를 만들 때** 비워 둔 값을 자동 규칙으로 정해 고정(feed_seed, 색 키)하게 한다.
- 구현 계획: 아래 표. 화면(폼 칸·미리보기)은 5-2~5-4가 한다. 유형은 `feature`.
- 관련 파일: 규격 정본은 `docs/service/prd/home-feed/PRD.md` §6 끝 「개편 규격」(칸 표, «값을 정하는 시점»). 4회차가 만든 `lib/today/feedAssign.ts`·`feedChipSlots.ts`·`feedValueChips.ts`·`feedLook.ts`를 쓴다.

## 배경 / 문제 정의

DB에는 새 칸이 있고(349) 홈 화면은 새 칸을 읽어 그린다(4회차). 그런데 어드민 저장 API는 요청 본문을 그대로 `insert`·`update`에 넘길 뿐이라 새 칸을 검증하지 않는다. 잘못된 값(허용하지 않는 칩 자리, 제목에 없는 제목 칩 낱말, `javascript:` 주소의 목록 항목)이 DB의 `CHECK`에 걸리지 않는 구멍으로 들어가면 홈이 이상하게 그리거나 사용자가 읽기 어려운 DB 오류를 본다. 또 PRD는 «어드민에서 만드는 카드는 저장할 때 값을 정하고 이후 바꾸지 않는다»고 정했으므로, 저장하는 쪽이 비워 둔 값을 자동 규칙으로 채워야 같은 카드를 언제 열어도 같은 모습이 된다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트(`components/today/`)는 건드리지 않는다. 새 칸의 타입(`TodayFeedType`·`TodayChipSpec` 등)은 `src/types/database.ts`에 이미 있다. 타입이 모자라면 고치지 말고 멈추고 보고한다.
- **값 의미(폼 → 저장)**: 빈 문자열·선택 안 함은 `NULL`(자동 규칙이 정한다). 칩은 «자동»(`NULL`)·«칩 없음»(`[]`)·«직접»(1~2개)을 구분한다. 도장은 «자동»(`NULL`)·«사용 안 함»(`false`)·«사용»(`true`+자리). 설명 노출은 «자동»(`NULL`)·«보임»(`true`)·«숨김»(`false`). **유형이 비어 있으면 옛 7모양 카드다**(4-2의 `feed_type` NULL 경로). 이때 다른 새 칸 값이 있어도 홈은 옛 경로로 그리므로, 검증은 «유형 없이 새 칸이 채워져 있으면 경고»만 돌려주고 막지 않는다.
- **새 순수 함수 파일** `jam-web/src/lib/admin/feedCardFields.ts`(신규, `import type`만 쓰는 순수 함수, React·서버 의존 없음):
  - `FeedCardFormValues`(폼 상태 모양: 위 값 의미를 담는 문자열·열거 값)와 빈 값 `EMPTY_FEED_CARD_FORM_VALUES`, 저장 행에서 폼 값을 되살리는 `feedCardFormValuesFromRow(row)`, 폼 값에서 저장 칸 묶음을 만드는 `buildFeedCardColumns(values)`.
  - `validateFeedCardColumns(columns, { title })` → `{ errors: string[]; warnings: string[] }`. **errors(저장을 막는다)**: `feed_type`·`box_shape`·`box_kind`·색 키 3개가 허용 값 밖, 칩이 3개 이상·칩 `kind`가 값/문구/구분 밖·`kind=value`인데 `source` 없음·`kind=phrase`인데 `text` 없음, 칩 자리가 그 유형의 허용 자리(`isAllowedSlot`) 밖, 칩 2개가 대각선 짝이 아님(`diagonalOf`), 기울기가 `−8,−6,−4,4,6,8` 밖, 제목 속 칩 낱말이 3개 이상이거나 제목에 그대로 들어 있지 않음, 도장 사용인데 자리가 허용 밖, 목록 항목이 4개 이상·이름 없음·주소가 `isSafeListHref` 밖(내부 경로 또는 `https://`), 대표 페이지 주소가 같은 규칙 밖, 컬렉션 모션 배지가 5개 이상 또는 값 범위(x·y −1~1, 크기 68~84, 지연 70~210ms, 기울기 −45~45) 밖. **warnings(막지 않는다)**: 문구 칩이 12자 초과(`checkChipTextLength`), 고른 색 조합이 색 거르는 규칙(`feedColorRules.ts`)에 걸림, 목록형인데 항목이 0개(홈이 옛 모양으로 그린다), 컬렉션 소개인데 컬렉션이 없음, 유형 없이 새 칸이 채워져 있음. 에러·경고 문구는 `UX_WRITING_GUIDELINE.md`의 «현상 → 원인 → 해결책» 순서, 해요체다.
  - 목록 항목 주소 검사는 `components/today/feed/FeedGalleryListCard.tsx`의 `isSafeListHref`를 **그대로 가져다 쓴다**(복사하지 않는다. 가져올 때 서버·클라이언트 경계가 문제되면 순수 함수만 있는 파일로 옮기는 안을 보고하고 멈춘다).
- **`today-sections.ts`**: `TodayCardFormValues`·`TodayCardSavePayload`에 위 칸 묶음을 더하고 `buildTodaySavePayload`(저장 페이로드를 만드는 기존 함수)가 `buildFeedCardColumns` 결과를 합치게 한다. 기존 필드의 동작·순서·시험은 바뀌지 않는다(새 칸은 선택 필드).
- **API 검증**: `POST /api/admin/today`·`PATCH /api/admin/today/[id]`가 본문의 새 칸을 `validateFeedCardColumns`로 검사해 errors가 있으면 `400`과 문구를 돌려준다. 새 칸이 본문에 없으면(옛 호출) 검증하지 않는다(그대로 저장). 일괄 수정·내보내기 등 다른 `today` 라우트는 건드리지 않는다. 본문의 새 칸 외 키 처리(옛 동작)는 그대로 둔다.
- **저장 때 자동 값 고정(새 카드 `POST`에서만, PATCH는 아래 예외 한 가지만)**: 유형(`feed_type`)이 지정된 카드를 만들 때 ① `feed_seed`가 비어 있으면 서버에서 0 이상 2³² 미만 정수 하나를 정해 저장한다(`crypto.getRandomValues` 등 서버 난수. 서비스 화면 코드가 아니므로 `Math.random` 금지 규칙의 대상은 아니나 시험 가능하게 난수 공급 함수를 인자로 받는다) ② 배경·칩·박스 색 키 중 비어 있는 것을 `assignFeedColors`로 정해 저장한다. 입력: 시드, 사용자가 고른 값(지정값 보존), **같은 시기에 노출되는 카드의 배경색 사용 빈도**(`starts_at`~`ends_at`이 겹치고 `bg_color_key`가 있는 카드의 색 키별 장수를 서비스 클라이언트로 조회), 제외 조합(지금 운영 코드에 연결된 목록이 없으므로 빈 목록. 연결된 목록이 있으면 같은 것을 쓴다). 칩 자리·기울기와 컬렉션 모션 위치는 시드로 홈이 같은 값을 그리므로 저장하지 않는다(`NULL`로 둔다).
  - `PATCH`는 이미 저장된 값을 다시 정하지 않는다. 예외: 기존 카드에 처음 `feed_type`을 지정하며 `feed_seed`가 `NULL`이면 위 ①②를 한 번 수행한다. 사용자가 색을 «자동»(`NULL`)으로 되돌려 보내면 같은 시드로 다시 정한다.
  - 사용자가 지정한 값은 자동 배정이 덮어쓰지 않는다. 자동 배정 함수가 통과 조합을 못 찾아 기본 조합으로 되돌리면(`usedFallback`) 저장은 하되 응답 본문에 `warnings`로 알린다.
  - 이 로직은 라우트 파일이 아니라 순수 함수 `decideFeedCardValues({ columns, seed, overlappingBgUsage, excludedPairs })`(위 `feedCardFields.ts` 또는 같은 폴더의 새 파일)에 두고 라우트는 조회·호출·저장만 한다.
- **정책 대시보드**: 규칙·밸런스 수치를 바꾸지 않으므로 `policiesData.ts`를 갱신하지 않는다(판단을 「주요 의사결정」에 적는다).
