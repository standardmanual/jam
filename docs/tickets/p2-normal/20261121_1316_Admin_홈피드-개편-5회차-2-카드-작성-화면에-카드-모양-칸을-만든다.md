# [Admin] 홈피드 개편 5회차-2: 카드 작성 화면에 «카드 모양» 칸을 만든다

## 핵심 요약

- 요구사항: 어드민 카드 작성·수정 화면(`/admin/today/new`, `/admin/today/[id]/edit`)에 새 섹션 **「카드 모양」**을 더한다. 유형(8개), 박스 모양(5개)과 박스 용도, 배경·칩·박스 색(15색), 설명 문장 노출, 도장 사용과 자리, 제목 속 칩 낱말을 값으로 지정한다. 비워 두면 자동 규칙이 정한다. 칩 문구·목록 항목·컬렉션 모션은 5-3, 미리보기 연결은 5-4가 한다.
- 구현 계획: 아래 표. 유형은 `admin`(MODULAR 적용 제외, shadcn/ui 표준 부품 사용).
- 관련 파일: 5-1(20261121_1315)이 만든 `lib/admin/feedCardFields.ts`(폼 값 모양·검증)를 쓴다. 규격 정본은 `docs/service/prd/home-feed/PRD.md` §6 끝 「개편 규격」(유형별 구성 표, 박스, 색, 도장, 제목 속 칩).

## 배경 / 문제 정의

지금 카드 작성 화면은 템플릿·레이아웃(옛 7모양의 입력)만 고르게 한다. 새 카드는 유형·박스·색·도장이 구성 요소이고, 사용자가 확정한 요구(상위 티켓 14번)는 «구성하는 모든 것을 어드민에서 값으로 설정할 수 있고, 비워 두면 자동이 정한다»이다. 이 티켓이 그 중 카드의 «겉모습» 칸을 만든다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트는 건드리지 않는다. 저장 API·검증은 5-1이 끝냈다(이 티켓은 폼 상태와 입력 칸만).
- **섹션 구성**: `today-sections.ts`의 `TodaySectionId`에 `'feed'`(제목 «카드 모양»)를 더하고 `TODAY_SECTION_ORDER`에서 `basic` 다음에 둔다(`visibleTodaySections`·섹션 목차·상태 계산에 반영). 섹션 설명 한 줄: «홈에서 카드가 어떤 모습으로 보일지 정해요. 비워 두면 자동으로 정해져요.» 기존 섹션의 순서·상태 계산 결과는 바뀌지 않는다(옛 카드는 `feed` 섹션이 «선택» 상태).
- **폼 상태**: `TodayCardForm.tsx`가 5-1의 `FeedCardFormValues`를 한 덩어리 상태로 들고(수정 화면은 `feedCardFormValuesFromRow(card)`로 채운다) 저장 때 `buildTodaySavePayload`에 넘긴다. 이 섹션 UI는 새 파일 `jam-web/src/app/admin/today/FeedCardSection.tsx`(클라이언트 컴포넌트)에 두어 `TodayCardForm.tsx`의 길이를 늘리지 않는다. 값과 변경 함수만 props로 받는다.
- **칸(값 의미는 5-1 «값 의미»)**:
  - 유형: 선택 «옛 모양 그대로(유형 지정 안 함)»(기본)와 8개 유형(이름은 PRD 유형 표의 한국어 이름). 유형을 고르면 그 유형이 쓰는 칸만 보인다(예: 목록형·컬렉션 소개는 박스 칸이 없다. 어떤 유형이 어떤 칸을 쓰는지는 PRD 유형별 구성 표와 `feedLook.ts`·`feedChipSlots.ts`가 정한 값을 따르고, 코드에 새 표를 만들지 않고 기존 상수를 읽는다). 유형을 «옛 모양 그대로»로 되돌리면 새 칸 값은 폼 안에 남아 있어 다시 유형을 고르면 살아나지만, **저장할 때는 보내지 않는다**(새 칸을 `NULL`로 저장한다. 홈이 옛 모양으로 그리므로 값이 남아 있어도 영향이 없고 5-1의 «유형 없이 새 칸이 채워져 있음» 경고도 뜨지 않는다).
  - 박스 모양(5개: 둥근 모서리·티켓·우표·물결·돌출)과 박스 용도(글자 박스·이미지 마스크): 둘 다 «자동» 선택이 있다. 박스가 있는 유형에서만 보인다.
  - 색 3칸(배경·칩·박스): 각각 «자동» + 15색. 색 선택지에는 색 견본(`feedColorVar`)과 한국어 이름을 함께 보인다(색만으로 구분하게 하지 않는다). 고른 조합이 색 규칙에 걸리거나 사용자가 제외한 조합이면 **경고만** 보이고 저장을 막지 않는다(PRD 「수동 지정」). 판정은 `feedColorRules.ts`의 함수를 쓴다.
  - 설명 문장 노출: 자동·보임·숨김. 설명 칸이 없는 유형은 «이 유형은 설명을 보이지 않아요»로 비활성.
  - 도장: 자동·사용 안 함·사용 + 자리(그 유형이 허용하는 자리만, 이미지 모서리·박스 모서리). 허용 자리와 이름은 `feedChipLayout.ts`(도장 자리 함수)와 `feedChipSlots.ts`를 따른다.
  - 제목 속 칩 낱말: 0~2개 입력. 제목에 그대로 들어 있지 않으면 입력 아래에 오류 문구(저장 막힘, 5-1 검증과 같은 규칙), 낱말을 지우면 제목이 글자로만 보인다.
- **어드민 UI 규칙**: shadcn/ui 표준(`components/admin/ui/`의 `select`·`switch`·`input` 등). 네이티브 `<select>` 금지. 새 하드코딩 색·간격 금지(`check-spacing`, 토큰 사용). 칸 이름·설명은 해요체, 제목에 마침표 없음.

### UI/UX 관점

- 칸마다 «자동»이 기본이고, 자동일 때 보조 문구 «저장할 때 자동으로 정해져요»를 보인다. 사용자가 고른 값은 일반 상태, 자동은 흐린 상태로 구분한다.
- 키보드로 모든 칸을 조작할 수 있고, 색 선택지는 견본과 이름이 함께 읽힌다(스크린리더 이름 = 색 이름).
- 폭이 좁은 레일에서도 가로 스크롤이 생기지 않는다.
