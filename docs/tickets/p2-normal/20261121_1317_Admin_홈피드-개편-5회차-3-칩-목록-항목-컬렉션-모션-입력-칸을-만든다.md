# [Admin] 홈피드 개편 5회차-3: 칩, 목록 항목, 컬렉션 모션 입력 칸을 만든다

## 핵심 요약

- 요구사항: 카드 작성 화면의 「카드 모양」 섹션(5-2) 아래에 **칩**(문구·DB 값·구분, 자리, 기울기), **목록형의 항목과 항목별 링크**, **컬렉션 모션**(배지 도착 위치) 입력 칸을 더한다. 모두 «자동»이 기본이고 비워 두면 홈이 시드로 정한다.
- 구현 계획: 아래 표. 유형은 `admin`.
- 관련 파일: 5-1(20261121_1315)의 `feedCardFields.ts`(값 모양·검증), 5-2(20261121_1316)의 `FeedCardSection.tsx`를 쓴다. 규격은 PRD §6 「개편 규격」 중 칩(DB 값 칩의 규칙표)·목록형·컬렉션 모션 절.

## 배경 / 문제 정의

칩·목록 항목·컬렉션 모션은 값이 구조를 가진다(칩 2개의 대각선 짝, 항목 3개와 링크, 배지 4개의 좌표). 한 칸 입력으로 풀리지 않아 따로 한 티켓으로 둔다. 상위 티켓 14번이 «칩(문구, DB 값 사용 여부, 자리, 기울기)·목록형의 항목과 항목별 링크·컬렉션 모션»을 어드민에서 지정할 수 있어야 한다고 정했다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트·저장 API는 건드리지 않는다. 값의 모양과 검증은 5-1이 끝냈고 이 티켓은 입력 칸과 폼 상태만 만든다. 5-1 검증이 막는 값은 화면에서도 같은 문구로 먼저 보여 준다(`validateFeedCardColumns`를 입력 중에 호출).
- **새 파일** `jam-web/src/app/admin/today/FeedChipsEditor.tsx`, `FeedListItemsEditor.tsx`, `FeedBurstEditor.tsx`(모두 클라이언트 컴포넌트, 값과 변경 함수를 props로 받는다)를 만들어 `FeedCardSection.tsx`가 유형에 맞는 것만 렌더한다.
- **칩 칸** — 모드 선택 3개: «자동»(홈이 정한다)·«칩 없음»·«직접». 직접이면 칩 1~2개(그 유형의 `chipLimitOf` 한도 안):
  - 종류: «문구»(직접 입력)·«값»(DB 값 사용)·«구분»(자원 이름 칩). 문구는 12자를 넘으면 경고만(`checkChipTextLength`, 막지 않음). 값 칩은 출처 선택(`FEED_VALUE_CHIP_RULES`의 자원별 선택지. 폼이 아는 자원(미션·배지·컬렉션·체크인·드랍픽업) 중 카드 템플릿과 맞는 출처만 보여 준다).
  - 자리: 그 유형의 허용 자리 선택(`FEED_CHIP_SLOT_SPECS[유형]`, 한국어 자리 이름), 칩 2개면 두 번째는 첫 칩의 **대각선 짝**(`diagonalOf`)으로 고정되어 선택지가 하나다. 기울기: «자동»·−8·−6·−4·4·6·8도.
  - 색은 5-2의 칩 색 칸이 정한다(이 칸에는 색 선택을 두지 않는다).
- **목록 항목 칸**(`gallery_list`에서만): 항목 1~3개, 항목마다 이름(글자 수 상한은 홈 카드 칸 폭에서 두 줄이 넘치지 않는 값으로 PRD 목록형 절이 정한 값이 있으면 따르고, 없으면 «20자» 경고만), 링크(내부 경로 또는 `https://`, 5-1 검증과 같은 오류 문구), 이미지(선택, 기존 이미지 입력 부품이 있으면 그것을 쓰고 없으면 주소 입력). 대표 페이지 주소 한 칸(«→» 칸). 항목 추가·삭제·위아래 이동 버튼은 키보드로 조작할 수 있고 버튼 이름이 읽힌다.
- **컬렉션 모션 칸**(`collection_intro`에서만): «자동»(카드 시드로 홈이 정한다)·«직접» 선택. 직접이면 배지 4개마다 도착 위치 x·y(−1~1, 가운데에서 카드 가장자리까지를 1로 본 값), 크기(68~84px), 기울기(−45~45), 시작 지연(70~210ms)을 숫자 칸으로 입력한다. 범위 밖이면 즉시 오류. «자동 값 불러오기» 버튼(현재 시드로 `generateCollectionBurst`가 만든 값을 칸에 채운다. 채운 뒤 사용자가 고친다)을 둔다.
- **어드민 UI 규칙**: shadcn/ui 표준 부품, 네이티브 `<select>` 금지, 하드코딩 색·간격 금지. 폼 상태는 5-2와 같은 `FeedCardFormValues`에 담는다(없는 칸은 5-1 값 모양에 맞춰 이 티켓이 더하되 5-1 파일의 기존 공개 모양을 깨지 않고 필요한 추가는 선택 필드로 한다).

### UI/UX 관점

- «자동»이 기본이고 자동일 때 «저장할 때 자동으로 정해져요»(칩)·«홈이 카드마다 정해 줘요»(모션) 보조 문구를 보인다.
- 칩 두 번째 자리가 첫 칩에 따라 바뀐다는 것을 문구(«대각선 자리에 놓여요»)로 알린다.
- 폭이 좁은 레일에서 가로 스크롤이 없다.

## 완료 조건

- 칩·목록 항목·컬렉션 모션을 입력해 저장하면 5-1 검증을 통과해 저장되고, 수정 화면에서 같은 값으로 다시 열린다.
- 칩 2개는 대각선 짝으로만 고를 수 있고, `javascript:` 주소·범위 밖 모션 값은 화면에서도 오류로 막힌다.
- 모두 «자동»(기본)으로 두면 저장 본문에 새 값이 실리지 않는다(`NULL`).
- `scripts/verify.sh`가 통과한다. 화면 실렌더는 5-4에서 확인한다.
