# [Admin] 홈피드 개편 5회차-4: 미리보기 연결과 수정 화면, 카드 표, 문서를 마무리한다

## 핵심 요약

- 요구사항: 5회차(어드민 수동 작성)의 마지막이다. ① 카드 작성 화면의 「홈 화면 미리보기」가 5-2·5-3에서 입력한 새 칸(유형·박스·색·칩·도장·제목 칩·목록 항목·모션)을 **입력하는 즉시** 홈과 같은 모습으로 보이게 한다. ② 수정 화면이 저장된 새 칸을 그대로 불러온다. ③ 카드 목록 표에서 새 유형 카드를 알아볼 수 있게 한다. ④ 어드민 PRD·홈피드 PRD를 이 회차 결과와 일치시킨다.
- 구현 계획: 아래 표. 유형은 `admin`.
- 관련 파일: 5-1(20261121_1315)·5-2(20261121_1316)·5-3(20261121_1317)이 만든 `feedCardFields.ts`·`FeedCardSection.tsx`·편집기를 쓴다. 미리보기 변환은 `lib/today/cardView.ts`의 `toCardView`, 그림은 `components/today/TodayCard.tsx`다(4회차 결과, 수정하지 않는다).

## 배경 / 문제 정의

폼의 미리보기는 지금 `previewCardBase`에 옛 칸만 채워 `toCardView`로 바꾼다. 새 칸을 채우지 않으면 새 유형을 골라도 미리보기가 옛 모양으로 보여, 사용자가 «이 값으로 저장하면 홈에서 어떻게 보이나»를 확인할 수 없다. 상위 티켓의 완료 조건 «어드민에서 지정해 저장하면 홈에 그대로 보이고, 비워 두면 자동으로 정해진다»를 사용자가 저장 전에 눈으로 확인하려면 미리보기가 정확해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트(`components/today/` 전체)·저장 API는 건드리지 않는다. `toCardView`·`TodayCard`는 **읽기만**(import) 한다.
- **미리보기 연결(`TodayCardForm.tsx`)**: `previewCardBase`에 폼의 새 칸을 채운다. 값 의미는 5-1: «자동»은 `NULL`, 유형이 비어 있으면 새 칸을 싣지 않는다(옛 7모양 미리보기 그대로). 저장된 카드를 수정할 때는 `feed_seed`를 그대로 쓰고, 새 카드는 미리보기 전용 고정 시드(코드 상수, `Math.random`·`Date.now` 금지)를 쓴다.
  - **미리보기가 보이는 한계를 화면에 적는다**: ① 자동 배경색은 저장할 때 «같은 시기 노출 카드의 사용 빈도»를 보고 정해져 미리보기와 다를 수 있다. ② 미션·배지 값 칩의 DB 값(조건·보상·기간)은 폼이 미션·배지 전체 행을 읽지 않아 폼이 가진 값(배지 이름·지역)까지만 보인다. ③ 컬렉션 소개의 배지 그림은 폼이 컬렉션의 배지를 읽지 않으면 자리 표시로 보인다(컬렉션 배지 조회가 폼에 이미 있거나 쉬우면 그것을 쓰고, 없으면 자리 표시와 «저장하면 홈에서 컬렉션 배지가 보여요» 문구). 세 한계를 미리보기 아래 «미리보기와 홈이 다를 수 있는 것» 접이식(shadcn `accordion`)에 한 줄씩 적는다.
  - 자동 값 입력(색 규칙에 쓰는 제외 조합 등)은 5-1이 쓴 것과 같은 것을 쓴다.
- **수정 화면**: `/admin/today/[id]/edit`이 `card`의 새 칸을 5-2의 `feedCardFormValuesFromRow`로 폼에 채운다. 저장된 자동 값(5-1이 새 카드 저장 때 고정한 색·시드)은 지정값처럼 보이므로 섹션 상단에 «저장할 때 자동으로 정해진 값은 그대로 보여요. 바꾸려면 값을 고르거나 「자동」을 고르세요» 한 줄을 둔다. 새 칸 SELECT는 기존 조회(`select('*')`)가 이미 싣는지 확인하고, 싣지 않으면 조회 칸을 더한다(싣지 않는 조회가 있는지 읽어서 정한다).
- **날짜 미리보기 모달(`TodayPreviewModal`)·목록 미리보기**: 새 칸을 읽는 조회를 쓰는지 확인하고, 안 쓰면 새 칸이 모달 미리보기에도 반영되게 한다(모달은 `toCardView`로 그리므로 행에 칸만 실리면 된다).
- **카드 표(`TodayCardTable.tsx`)**: 「유형」 열을 더한다. 새 유형이면 한국어 유형 이름(PRD 유형 표의 이름), 아니면 «옛 모양 (레이아웃 이름)»을 보인다. 정렬·필터·기존 열은 바뀌지 않는다. 표 조회가 칸을 고르는 `select`면 `feed_type`을 더한다.
- **문서**: `docs/service/prd/admin-ui/ADMIN_PRD.md`의 투데이 카드 폼 절(있으면)에 «카드 모양» 섹션과 세 편집기, 저장 때 자동 값 고정, 미리보기 한계를 적는다(없으면 투데이 절 끝에 새 항목). `docs/service/prd/home-feed/PRD.md` §6의 「(구현 전)」 중 이 회차가 끝낸 어드민 항목을 구현 위치와 함께 정리하고, 아직 남은 것(에이전트 묶음·이미지·컬러셋 교체)은 «6~7회차·후속»으로 남긴다.
- **정책 대시보드**: 정책·밸런스 수치를 바꾸지 않으므로 `policiesData.ts`는 갱신하지 않는다.

### UI/UX 관점

- 미리보기는 입력 즉시 갱신된다(저장 없이). 새 유형을 고르면 홈 폭(360·430, 기존 기기 폭 전환)에서 그 유형 모습이 보인다.
- 미리보기 한계 접이식은 기본 접힘이고 키보드로 열린다.
- 모든 문구는 해요체, 제목에 마침표 없음.

## 완료 조건

- 폼에서 유형·박스·색·칩·도장·제목 칩·목록 항목·모션을 바꾸면 미리보기가 즉시 그에 맞는 홈 모습으로 바뀐다. 유형을 «옛 모양 그대로»로 두면 지금과 똑같다.
- 수정 화면이 저장된 새 칸을 그대로 불러오고, 다시 저장해도 값이 바뀌지 않는다.
- 카드 표에 「유형」 열이 보이고 기존 열·정렬·필터는 바뀌지 않는다.
- `scripts/verify.sh`가 통과한다. 어드민 두 PRD가 이 회차의 동작과 일치한다.
- **화면 실렌더(카리나가 머지 뒤 push 전에 한다)**: 폼은 서비스 키가 필요한 서버 조회를 거치므로, 가짜 `card` props로 폼을 그리는 임시 경로(저장소에 남기지 않는다)를 만들어 폭 360·430과 새 유형 8개에서 미리보기를 직접 열어 확인한다. 서비스 키·서버 비밀은 쓰지 않는다.

### 구현 범위 (게이트 판정 대상)
