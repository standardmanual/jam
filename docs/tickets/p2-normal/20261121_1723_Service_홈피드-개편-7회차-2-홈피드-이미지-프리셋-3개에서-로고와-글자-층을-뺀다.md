# [Service] 홈피드 개편 7회차-2: 홈피드·미션 이미지 프리셋 4개에서 로고와 글자 층을 뺀다

## 핵심 요약

- 요구사항: DB `asset_presets`의 프리셋 4개의 `layers`를 빈 배열로 바꾼다: 홈피드 3개(`홈피드` 1:1 `51aa4673-f723-4929-ac20-a302202b7aa7`, `홈피드 16:9` `c5491ad2-12d4-4ab0-a59d-6897067a8a9a`, `홈피드 4:5` `a4d7f928-2531-4cc4-a611-3399db244bfe`, 각각 로고 이미지 층 1개 + 제목·설명 글자 층 2개)와 **미션 1개**(`미션` `98562783-36c9-44aa-8fba-3c4793608f28`, 로고 이미지 층 1개 + 글자 층 3개: 조건 문구·미션 이름·고정 라벨 «MISSION», 사용자 결정 2026-11-21 «미션 이미지 글자 제거», 2026-11-21 읽기 전용 조회로 구성 확인). 리본(색 그라데이션과 «J» 모양 스탬프)은 엔진이 그리므로 그대로 남는다(사용자 결정 2026-11-21).
- 구현 계획: 마이그레이션 SQL 파일 두 개(적용·되돌림)와 층 백업 표를 만들고, 드라이런으로 실측한 뒤 메인 세션(카리나)이 실행한다. 실제로 구워 본 이미지를 눈으로 대조하고 사용자에게 보여 준다. 유형은 `db`.
- **선행 조건**: 7-1(20261121_1722, 홈피드 카드 이미지 경로)과 7-5(20261121_1726, 미션 이미지 경로와 옛 모양 제목 판정)가 모두 병합돼야 한다. 먼저 바꾸면 `image_spec.values`의 `text01` 등이 있는 운영 항목과 미션 이미지 CLI가 실패하고, 옛 모양 미션 소개 카드의 제목이 사라질 수 있다.
- **하지 않는 것**: 배지·컬렉션 프리셋은 바꾸지 않는다(배지 이미지는 이름·값·로고를 유지). 컬렉션 프리셋은 대상이 아니다.
- **미션 이미지 글자 제거의 영향(2026-11-21 조사)**: 미션 목록·상세 화면은 이미지 옆에 미션 제목을 글자로 따로 그려서(`MissionsListClient`의 `ListCard title`, `MissionDetailClient`의 `<h1>`) 이미지 속 글자에 기대지 않는다. 기대는 곳은 옛 모양 `mission_spotlight` 카드의 «제목이 이미지에 있다» 판정(`shape.ts`의 `resolveTitleInImage`, `cardView.ts`의 강제 `titleInImage = true`)이며 7-5가 고친다. 이미 구워진 미션 이미지(글자 있음)는 그대로 남는다.

## 배경 / 문제 정의

프리셋은 에셋 제너레이터와 운영툴 자동 제작이 읽는 «틀»이다. 지금 홈피드 프리셋으로 구운 카드 이미지에는 JAM 로고와 제목·설명 글자가 들어가는데, 새 규격(홈피드 PRD §6 이미지 규칙)은 카드 이미지에 글자와 로고를 넣지 않는다. 게시 중인 카드의 이미지는 이미 구워져 있어 프리셋을 바꿔도 영향이 없다(상위 티켓: 게시 중인 카드는 고려하지 않는다).

## 상세 요구사항

### 서비스/코드베이스 관점

- Supabase는 staging·프로덕션 공용 단일 DB다. 바로 프로덕션에 반영된다. CLAUDE.md 규칙 6에 따라 SQL 파일은 `jam-web/supabase/migrations/`에 남기고 메인 세션이 실행한다(서브에이전트는 파일 작성까지).
- **파일**: `jam-web/supabase/migrations/350_asset_presets_home_feed_text_logo_free.sql`(적용)·`350_asset_presets_home_feed_text_logo_free_down.sql`(되돌림). 마지막 번호는 349다(병렬 세션이 선점하지 않았는지 실행 직전 원격 staging 기준으로 다시 확인한다).
- **적용 SQL의 안전장치**: ① 백업 표 `asset_presets_layers_backup_20261121`(id, name, target_type, layers, backed_up_at)을 만들고 대상 4행의 `layers`를 그대로 담는다. ② 변경 대상은 id 4개(홈피드 3개는 `target_type = 'home_feed'`, 미션은 `target_type = 'mission'`)로 좁힌다. ③ 각 행의 `layers`가 이 티켓이 읽은 구성(홈피드: 이미지 층 1개 + 글자 층 2개, 미션: 이미지 층 1개 + 글자 층 3개)과 같을 때만 바꾼다(다르면 건너뛰고 건너뛴 행 수를 알린다). 다르다는 것은 누군가 어드민에서 프리셋을 고쳤다는 뜻이라 덮어쓰지 않고 확인한다. ④ `updated_at`을 갱신한다.
- **되돌림 SQL**: 백업 표의 `layers`로 3행을 되돌리고(백업 행이 있는 id만, 4행), 백업 표는 지우지 않는다(되돌림 뒤 사용자 확인이 끝나면 별도로 정리).
- **실행 전 점검(관문)**: 되돌림 SQL 확인, 프로덕션 DDL·데이터 변경의 DO 블록 롤백 실측(`RAISE EXCEPTION`으로 되돌리며 갱신 행 수 4·건너뜀 0 확인), 실행 직후 읽기 전용 확인(4행 `layers = []`, 백업 표 4행, 다른 프리셋·행 불변)과 사용자 보고.
- **실렌더 대조**: 프리셋을 바꾼 뒤 에셋 엔진으로 홈피드 프리셋 하나(1:1)와 미션 프리셋을 실제로 구워(에셋 렌더 함수를 esbuild+Playwright로 브라우저에서 호출하는 방식, 배포 없이) 로고·글자 없이 리본만 있는지 눈으로 확인하고 이미지를 사용자에게 보낸다.
- 사용자 노출 문구·정책 수치는 없다(`policiesData.ts` 갱신 없음, 판단을 「주요 의사결정」에 적는다).

### UI/UX 관점

- 어드민 에셋 제너레이터 화면에서 이 프리셋을 불러오면 오버레이 층이 비어 있는 상태로 열린다(에러 없이 열리는지 확인).
