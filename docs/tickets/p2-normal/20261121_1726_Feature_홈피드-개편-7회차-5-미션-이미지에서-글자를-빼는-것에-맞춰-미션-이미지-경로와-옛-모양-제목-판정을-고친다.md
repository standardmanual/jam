# [Feature] 홈피드 개편 7회차-5: 미션 이미지에서 글자를 빼는 것에 맞춰 미션 이미지 경로와 옛 모양 제목 판정을 고친다

## 핵심 요약

- 요구사항: 사용자가 «미션 이미지 글자 제거»를 결정했다(2026-11-21). 미션 프리셋(`98562783-36c9-44aa-8fba-3c4793608f28`, 로고 + 조건 문구·미션 이름·«MISSION» 글자 3개)의 층을 비우는 데이터 변경은 7-2가 한다. 이 티켓은 그 전에 **코드가 글자 없는 미션 이미지를 받아들이고, 옛 모양 미션 소개 카드가 제목을 숨기지 않게** 고친다. 7-1(20261121_1722)이 홈피드 카드 경로를 맡았으므로, 이 티켓은 같은 방식을 **미션 경로와 제목 판정**에 적용한다.
- 구현 계획: 아래 표. 유형은 `feature`(화면 변경은 옛 모양 카드의 제목 표시뿐).
- 선행: 7-1 병합(층 번호 무시 모드 `applyLayerValues`의 선택 인자가 생긴 뒤 이 티켓이 미션 경로에 쓴다).

## 배경 / 문제 정의

조사 결과(2026-11-21): 미션 목록·상세 화면은 이미지 옆에 미션 제목을 글자로 따로 그려 이미지 속 글자에 기대지 않는다. 기대는 곳은 두 군데다. ① 옛 모양 `mission_spotlight` 카드가 커버로 미션 대표 이미지를 쓸 때 «제목이 이미지 안에 있다»고 보고 카드 제목을 숨긴다(`shape.ts`의 `resolveTitleInImage`의 NULL 분기, `cardView.ts`의 `titleInImage = true` 강제). 글자 없는 새 미션 이미지가 이 경로에 쓰이면 제목이 화면에서 사라진다. ② 미션 이미지를 만드는 도구(운영툴 `mission` 항목의 `image_spec.values`, 에셋 CLI `apply-mission-images.mjs`·`register-mission.mjs`)가 `text01`·`text02`·`text03`·`img01` 값을 프리셋에 적용하는데, 층이 없으면 던진다(`applyLayerValues`의 기본 동작).

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·어드민 저장 API는 건드리지 않는다. 프리셋 행 데이터는 7-2가 바꾼다. 배지·컬렉션 이미지 경로는 바꾸지 않는다(엄격한 동작 유지).
- **옛 모양 제목 판정**: `resolveTitleInImage`의 NULL 분기를 «**항상 false**(제목을 글자로 그린다)»로 바꾼다. 저장된 `title_in_image`가 불리언이면 그 값을 그대로 따른다(기존 동작). `cardView.ts`의 미션 이미지를 커버로 쓸 때 `titleInImage = true`로 강제하는 줄도 같은 이유로 없앤다(저장된 불리언이 있으면 그 값). 이미 구워진 미션 이미지(글자 있음)를 커버로 쓰는 옛 카드는 제목이 이미지 글자와 함께 한 번 더 보이는데, 상위 티켓의 결정(게시 중인 카드는 고려하지 않는다)에 따라 허용한다. `shapeParity.test.ts`·`shape.test.ts`·`cardView.test.ts`의 기대값 중 이 판정을 가정한 것은 새 규칙으로 고치고, 고친 시험과 이유를 「주요 의사결정」에 적는다. 새 유형 8종은 `titleInImage`를 읽지 않으므로 영향이 없다.
- **미션 이미지 제작 경로의 값 무시**: 7-1이 만든 «없는 층 번호 무시» 선택 인자(`ignoreMissingKeys`)를 미션 경로에도 쓴다. 7-1은 이 모드를 **프리셋 `targetType === 'home_feed'`일 때만** 켜므로(`imageRender.client.ts`·`renderCard.mjs`), 이 티켓이 `targetType === 'mission'`도 켜게 넓힌다(`jam_badge`·컬렉션·배지 프리셋은 계속 엄격). 대상: 운영툴 `kind = mission` 항목의 제작(7-1이 홈피드 카드 항목에만 적용한 `values` 처리를 `mission`까지 넓힌다. 다른 종류 `jam_badge`·`collection_launch`는 그대로 엄격), `imageSpecWarnings`의 «카드 이미지에는 글자와 로고를 넣지 않아서 values는 쓰지 않아요» 경고를 미션 항목에도 낸다, 에셋 CLI의 미션 경로(`apply-mission-images.mjs`·`applyMissionImagesFlow.mjs`·`register-mission.mjs`·`registerMissionBundle.mjs`)는 프리셋에 글자 층이 없으면 글자 값을 무시하고 경고한다. 글자 넘침 검사(`textOverflow.mjs`)는 글자 층이 없으면 건너뛴다. 글자 층이 있는 프리셋(데이터 변경 전)이면 지금과 똑같이 동작한다.
- **「이미지 제작 필요」·미리보기**: `mission` 항목은 지금도 이미지 칸(`image_url`)이 있는 종류다. 새 판정이 필요한 것은 없다(7-1의 카드 판정과 겹치지 않게 변경이 없으면 변경 없음으로 적는다).
- **문서**: `docs/service/prd/asset-generator/MISSION_REGISTRATION_BUNDLE.md`의 `image.text` 서술(`text`는 글자 층이 없으면 무시)·`docs/service/prd/asset-generator/PRD.md` §8 미션 프리셋 `text01`~`text03` 서술(글자 층 없음, 7-2 이후), `docs/service/prd/home-feed/PRD.md` §6의 «카드 모양 판정»(`resolveTitleInImage`)과 구현 위치(7회차-5), `docs/service/prd/ops-tool/PRD.md` §3.1의 `image_spec`(카드·미션 항목의 `values`는 쓰지 않음). 윤진 정의는 7-4가 고친다.
- **정책 대시보드**: 규칙·밸런스 수치를 바꾸지 않으므로 `policiesData.ts`를 갱신하지 않는다.

### UI/UX 관점

- 옛 모양 미션 소개 카드는 제목이 항상 글자로 보인다(이미지에 글자가 있어도). 새 유형 카드는 그대로다.

### 구현 내용 요약

미션 이미지에서 글자를 빼는 것(사용자 결정 2026-11-21)에 맞춰 코드가 글자 없는 미션 이미지를 받아들이고, 옛 모양 미션 소개 카드가 제목을 숨기지 않게 했다. 7-2 이전(미션 프리셋에 글자 층이 있는 지금)에는 동작이 이전과 같다.

- 옛 모양 제목 판정: `shape.ts`의 `resolveTitleInImage`는 저장된 `title_in_image` 불리언이 있으면 그 값이고 `NULL`이면 항상 `false`다. `cardView.ts`의 미션 이미지를 커버로 쓸 때 `titleInImage = true`로 강제하던 줄을 없앴다.
- 운영툴: `imageRender.client.ts`가 프리셋 `targetType`이 `home_feed` 또는 `mission`이면 `ignoreMissingKeys`를 켠다(배지·컬렉션은 엄격). `imageSpecWarnings`가 `kind === 'mission'`에도 values 경고를 낸다.
- 에셋 CLI: `renderCard.mjs`가 미션 프리셋의 없는 번호를 무시한다. `apply-mission-images`는 글자 층이 하나도 없으면 번호·대비 검사를 건너뛰고 알려 준다. `textOverflow.mjs`는 글자 층이 없으면 `false`다. `register-mission`은 글자 층 없는 프리셋의 `image.text`에 알림만 남긴다.
