# [Feature] 체크인 지점 이미지를 구글 맵 장소 사진으로 보인다 (기획, 결정 대기)

## 핵심 요약

- 배경: 상위 티켓 15번 «체크인 지점을 보이는 자리에는 아이콘 대신 해당 지점의 이미지를 쓴다». 사용자가 이미지 출처를 **구글 맵**으로 정했다(2026-11-21).
- 이 티켓은 **구현 전 기획과 결정 정리**다. 구글 맵 장소 사진은 약관이 저장을 막고 API 키·요금이 필요하므로, 아래 결정이 끝나기 전에는 코드를 만들지 않는다. 상태는 WAITING이다.

## 확인한 사실 (2026-11-21)

- 앱 코드에 구글 지도·장소 API 사용이 **없다**(저장소 검색 결과 0건). 지점 표 `poi`에는 `osm_id`·`naver_id`가 있고 **구글 장소 ID 칸이 없다**(칸: id·name·latitude·longitude·radius_meters·category·linked_badge_id·osm_id·poi_tier·naver_id·is_active·naver_category·naver_keyword·pending_review·sido·gu).
- 지점 이미지 칸도 없다(상위 티켓 15번 조사와 같다).

## 구글 맵 이용 조건 (공개 약관 요지, 구현 전에 공식 문서로 다시 확인할 것)

- 구글 지도 플랫폼의 장소 사진·지도 이미지는 **내려받아 우리 저장소에 올려 두고 재사용하는 것이 허용되지 않는다**(캐시·저장 제한. 허용 예외는 장소 ID 정도). 보일 때마다 구글 API로 불러와야 한다.
- 사진에는 **작성자 표시(attribution)**를 함께 보여야 하고, API 키(결제 계정)와 요청 건수에 따른 **요금**이 든다. 키는 비밀 값이라 사용자가 직접 발급·등록해야 한다(저는 키를 받지도 쓰지도 않는다).
- 따라서 «에이전트가 이미지를 찾아 저장소에 넣는다»(상위 티켓 15번의 원래 구상)는 구글 사진으로는 할 수 없고, «지점마다 구글 장소 ID를 저장해 두고 화면에서 그때그때 불러 보인다»가 맞는 형태다.

## 제안(추천안, 사용자 결정 대기)

1. **저장하는 것**: `poi`에 `google_place_id`(문자열, NULL 허용)만 저장한다. 사진 파일·사진 주소는 저장하지 않는다. 지점 이름과 좌표로 구글 «장소 검색»을 불러 가장 가까운 후보의 ID를 채우고, 좌표 거리가 멀면(예: 150m 초과) 채우지 않고 사람이 확인하는 목록에 올린다. 한 번 채우는 일괄 작업 + 새 지점 등록 때 채우기.
2. **보이는 방법**: 카드를 그릴 때 서버가 구글 «장소 사진» 요청 주소로 이미지를 불러 보인다(브라우저에 키가 드러나지 않게 서버 경유를 권한다). 작성자 표시를 이미지 아래 작은 글자로 붙인다. 사진을 못 불러오면 지금의 아이콘으로 되돌린다(화면이 비지 않게).
3. **어디에 쓰나**: 체크인 지점이 카드에서 보이는 자리(장소 목록 카드, 지점을 소개하는 카드)만. 새 유형 «목록형»의 항목 이미지(`list_items[].image_url`)와 드랍·픽업 소개의 지점 칩 옆에 쓰는 안을 먼저 본다.
4. **비용 상한**: 월 호출 건수 상한과 알림을 두고, 사진은 서버가 짧게(요청 단위, 구글이 허용하는 범위) 다루며 저장소에 두지 않는다.
5. **대안(저장 가능한 이미지가 필요할 때)**: 공공누리 제1유형·위키미디어 공용처럼 이용 조건이 명확한 사진만 저장하고 출처를 함께 적는 안, 또는 자동 제작 이미지(리본)로 대신하는 안. 구글 사진과 섞어 쓰는 것도 가능하다.

## 정해야 할 것 (사용자 결정)

- (가) 구글 «장소 사진»(실제 사진, 구글에 올라온 사용자 사진 포함)을 쓸지, 아니면 «지도 이미지/스트리트 뷰»를 쓸지. 추천: 장소 사진.
- (나) API 키와 결제를 사용자가 발급·등록하는 것에 동의하는지, 월 비용 상한을 얼마로 둘지.
- (다) 사진이 없거나 못 불러올 때 아이콘으로 되돌려도 되는지(추천: 예).
- (라) 사진에 간판 글자가 찍혀도 «텍스트·로고 없는 이미지» 규칙의 예외로 보는지(상위 티켓 15번 (다)). 외부 사진이라 우리가 글자를 지울 수 없으므로 예외로 볼 수밖에 없다.

## 결정이 나면 나눌 일(안)

1. DB: `poi.google_place_id` 칸 추가(확장 단계), 지점 매칭 일괄 작업과 확인 목록.
2. 서버: 사진 불러오기 경로와 작성자 표시, 실패 시 아이콘 되돌림, 호출 상한.
3. 화면: 목록형 항목·지점 소개 카드에 연결.
4. 문서: 홈피드 PRD §6 이미지 규칙의 체크인 지점 항목, 운영 설정 문서의 키 등록 절차.
