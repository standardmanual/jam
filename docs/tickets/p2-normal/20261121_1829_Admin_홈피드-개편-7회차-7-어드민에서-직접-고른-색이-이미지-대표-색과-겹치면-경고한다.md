# [Admin] 홈피드 개편 7회차-7: 어드민에서 직접 고른 색이 이미지 대표 색과 겹치면 경고한다

## 핵심 요약

- 7-6(20261121_1828)이 정한 규칙 ⑤(그림과 배경)·⑥(그림과 칩)을 어드민 카드 작성 화면의 **수동 색 지정**에도 경고로 보인다. 경고만 하고 저장은 막지 않는다(사용자 결정 2026-11-21, 기존 색 규칙 경고와 같다).
- 구현 계획: 아래 표. 유형은 `admin`(MODULAR 적용 제외, shadcn/ui 표준).
- **선행**: 7-3(대표 색 저장)과 7-6(`violatesImageColorRule`·`imageColorsForCard`) 병합.
- 관련 파일: 5-2가 만든 `jam-web/src/app/admin/today/FeedCardSection.tsx`의 `feedColorWarnings`(기존 색 규칙 경고)와 색 칸, `TodayCardForm.tsx`(폼 상태·`card`), 배지 검색 결과 타입과 라우트.

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트·저장 API는 건드리지 않는다.
- **이미지 대표 색을 아는 경우에만** 경고한다. 알 수 없으면 경고하지 않는다(조용히 건너뛴다).
  - 커버 색: 수정 화면에서 `card.cover_colors`가 있으면 쓴다. 새 카드는 저장 전이라 대표 색이 없어 경고가 없고, 보조 문구로 «커버 이미지를 저장하면 색이 겹치는지 알려 드려요»를 한 줄 보인다.
  - 배지 색: 폼이 가진 연결 배지 정보에 `bg_colors`가 없으면 배지 검색 결과와 이름표 조회에 `bg_colors` 칸을 더한다(어드민 배지 검색 라우트의 `select`에 한 칸을 더하는 작은 변경. 이 라우트의 다른 동작은 바뀌지 않는다). 필요하면 폼이 선택한 배지의 `bg_colors`만 따로 들고 있게 한다.
- `FeedCardSection`의 색 경고(`feedColorWarnings`)에 이미지 규칙을 더한다. `imageColorsForCard({ feedType, boxKind, coverColors, badgeColors })`로 `imageHexes`·`chipOnImage`를 구하고, 사용자가 고른 배경색(규칙 ⑤)·칩 색(규칙 ⑥, `chipOnImage`일 때만)의 hex를 `violatesImageColorRule`로 검사한다. 걸리면 «배경색이 이미지의 색과 비슷해서 그림이 묻혀 보일 수 있어요», «칩 색이 이미지의 색과 비슷해서 칩이 묻혀 보일 수 있어요»처럼 해요체 경고를 보인다(기존 경고 줄과 같은 모양, `break-keep wrap-break-word`). **자동**으로 둔 칸은 검사하지 않는다(자동은 7-6이 이미지 규칙을 이미 지킨다).
- **정책 대시보드**: 규칙·수치를 바꾸지 않아 `policiesData.ts`를 갱신하지 않는다.

### UI/UX 관점

- 경고만이고 저장은 막지 않는다. 새 하드코딩 색·간격이 없다. 색 이름·견본 표시는 기존 그대로다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

어드민 카드 작성 화면에서 직접 고른 배경색(규칙 ⑤)·칩 색(규칙 ⑥, `chipOnImage`일 때만)이 이미지 대표 색과 겹치면 경고를 보인다. 경고만 하고 저장은 막지 않는다. 이미지 대표 색을 아는 경우에만 검사하고, 자동으로 둔 칸·대표 색을 모르는 경우·해당 없는 유형은 경고가 없다. 판정은 7-6의 `violatesImageColorRule`·`imageColorsForCard`, 이유 문구는 `COLOR_RULE_REASON.image`를 재사용했다.

- `FeedCardSection.tsx`: `feedColorWarnings`에 선택 인자 `imageColors`, `imageColorWarnings` 함수, 선택 props `coverColors`·`badgeColors`·`coverColorsPending`. 새 카드(또는 폼에서 커버를 바꾼 뒤)는 커버 색 규칙을 쓰는 유형에서만 «커버 이미지를 저장하면 색이 겹치는지 알려 드려요.» 한 줄을 보인다.
- `TodayCardForm.tsx`: 수정 화면에서 저장된 `card.cover_colors`와 연결 배지의 `bg_colors`(`badge_ids` 순서)를 넘긴다. 커버를 폼에서 바꾼 뒤에는 저장된 색이 낡은 값이라 모르는 것으로 보고 안내 한 줄만 보인다(티켓의 «새 카드»를 커버 변경까지 넓혔다).
- 배지 검색 라우트 `select`와 수정 화면 배지 조회에 `bg_colors` 한 칸을 더했고, `BadgeSearchResult`에 선택 필드 `bg_colors`를 더했다(다른 동작 불변).

### 잔여 이슈

- 수정 화면의 배지 조회는 삭제된 배지를 거르지 않아, 첫 배지가 삭제된 카드는 홈이 보는 «첫 배지»와 다른 배지 색으로 경고할 수 있다(경고만이라 저장에는 영향 없음, PRD에 한계로 적었다).
- 수정 화면은 저장 때 자동으로 정해진 색 키도 지정값처럼 보여 검사 대상이 된다. 자동 배정에서 이미지 규칙 안전장치(`imageRuleSkipped`)가 작동한 카드는 자동 색인데도 경고가 뜰 수 있다(경고만이라 무해).
