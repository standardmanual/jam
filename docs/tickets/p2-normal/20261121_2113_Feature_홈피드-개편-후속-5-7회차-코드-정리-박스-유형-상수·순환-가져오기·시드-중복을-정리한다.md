# [Feature] 홈피드 개편 후속: 5~7회차 코드 정리 (박스 유형 상수, 순환 가져오기, 시드 중복, 등록 때 시드 연결)

## 핵심 요약

- 상위 티켓 20261120_2026을 종료하면서 잔여 이슈로 남긴 **코드 정리** 네 건을 한 티켓으로 묶는다. 동작을 바꾸지 않는 정리가 세 건이고, 한 건만 동작이 아주 조금 바뀐다(아래 4번). 모든 기존 시험은 가져오기 경로 외에는 바뀌지 않는다.
- 구현 계획: 아래 표. 유형은 `feature`.

## 정리할 것

1. **박스 유형 목록 한 곳으로**: `FeedCardSection.tsx`의 `BOX_FEED_TYPES`(`hero_box`·`text_box`·`drop_pickup`)·`BOX_KIND_FEED_TYPES`(`text_box`)는 5-2에서 읽을 상수가 없어 어드민 파일에 새로 적었다(게이트 WARN). 이 목록을 `lib/today/feedConstants.ts`(또는 `feedChipSlots.ts` 옆)의 공용 상수로 옮기고 `FeedCardSection`이 그것을 읽게 한다. 홈 컴포넌트가 «박스를 그리는 유형»을 이미 어디선가 정하고 있으면(`feedLook.ts`의 `boxKind` 기본값, `FeedCard.tsx`의 유형별 컴포넌트) 같은 상수를 읽게 하고, 읽게 하기 어려우면 **상수와 컴포넌트의 일치를 지키는 시험**을 더한다(유형 8개를 각각 렌더해 박스가 그려지는 유형이 상수와 같은지). 서비스 홈 컴포넌트의 그리는 결과는 바뀌지 않는다.
2. **순환 가져오기 제거**: `FeedChipsEditor.tsx`가 `FeedCardSection.tsx`의 `ChoiceField`·`ChoiceOption`·`stampSlotLabel`을 가져오고 `FeedCardSection.tsx`가 `FeedChipsEditor`를 가져오는 순환이 있다(5-3 게이트 참고). 공용 조각을 새 파일 `app/admin/today/FeedFieldParts.tsx`(또는 이름이 맞는 곳)로 옮기고 두 파일이 그것을 가져오게 한다. `FeedCardSection.tsx`는 기존 이름들을 **다시 내보내** 외부 가져오기(`TodayCardForm.tsx`·`TodayCardTable.tsx`·시험)가 깨지지 않게 한다.
3. **미리보기 시드 중복**: `PREVIEW_FEED_SEED`(`lib/admin/opsInbox/cardPreview.ts`)와 `FEED_PREVIEW_SEED`(`app/admin/today/TodayCardForm.tsx`)가 같은 값 1121을 두 번 적고 시험이 일치를 지키고 있다. 순수 파일(예: `lib/today/feedPreviewSeed.ts`)에 상수 하나로 두고 둘이 가져온다. 기존 일치 시험은 가져오는 상수가 같음을 확인하는 시험으로 바꾼다.
4. **등록 때 `feed_seed`를 색 계산에 연결(동작 변경, 작음)**: `completeFeedCardValues`는 `columns.feed_seed`가 있어도 색 계산에 새로 뽑은 난수 시드를 쓴다(6-2 게이트 참고). 에이전트·어드민이 `feed_seed`를 직접 낸 카드는 **그 값을 색 계산 시드로 쓴다**(없으면 지금처럼 새로 뽑는다). 지금 묶음 경로는 `feed_seed`를 싣지 않아 결과가 바뀌지 않는다. 시험: `feed_seed`가 있으면 같은 입력이 같은 색·같은 저장 시드가 되는지, 없으면 지금과 같은지.
5. `jam-web/src/types/database.ts`의 `title_in_image` 칸 주석(1351행 부근)이 «NULL이면 옛 카드라 `resolveTitleInImage` 규칙으로 판정한다»로 남아 옛 규칙을 연상시킨다. **주석 한 줄만** 새 규칙(`NULL`이면 항상 `false`)에 맞게 고친다(타입·필드는 바꾸지 않는다).

## 하지 않는 것

DB·마이그레이션, 서비스 홈 컴포넌트의 그리는 결과, 어드민 화면의 동작·모양, 저장 API의 동작(4번 외), 351 트리거(경계 동작은 별도 결정), 컬러셋 교체 어드민, 체크인 지점 후속.
