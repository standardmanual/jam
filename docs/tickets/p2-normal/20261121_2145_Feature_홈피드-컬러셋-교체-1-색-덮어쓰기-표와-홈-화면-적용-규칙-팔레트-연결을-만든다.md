# [Feature] 홈피드 컬러셋 교체 1: 색 덮어쓰기 표와 홈 화면 적용, 규칙 팔레트 연결을 만든다

## 핵심 요약

- 사용자 결정(2026-11-21, «설계대로 진행»): 컬러셋이 마음에 들지 않으면 어드민에서 바꿀 수 있게 한다. **색 키(15개)는 그대로 두고 키가 가리키는 hex만 덮어쓴다.** 바꾸기 전에 미리보기와 규칙 재계산을 거쳐 «적용»을 눌러야 반영하고, 기본값 복원이 있다. 이미 저장된 카드의 색 키는 바뀌지 않고 보이는 색만 바뀐다. 이 티켓은 **저장 표·홈 화면 적용·규칙 팔레트 연결**(서비스 쪽)이고, 어드민 화면은 2번(20261121_2146)이다.
- 구현 계획: 마이그레이션 352(표, 메인 세션이 실행)와 코드(워크플로). 유형은 `feature`.
- **선행**: 코드 정리 티켓 20261121_2113이 병합돼야 한다(같은 파일 `feedCardServer.ts`·`FeedCardSection.tsx`를 고친다).
- 관련 파일: `jam-web/src/lib/today/feedConstants.ts`(`FEED_COLORS`·`feedColorVar`: 이 함수가 «덮어쓰기 층이 끼어들 자리»로 설계돼 있다), `design-system/tokens/colors.css`(기본값), `lib/today/feedAssign.ts`(`DEFAULT_FEED_PALETTE`, `assignFeedColors`의 `palette` 옵션), `feedColorRules.ts`(hex 입력 규칙), `lib/admin/feedCardServer.ts`(`completeFeedCardValues`), `lib/today/feedLook.ts`(`resolveFeedLook`), `app/(main)/layout.tsx`·홈 카드 쌓기(`TodayCardStack`), `app/admin/today/FeedCardSection.tsx`의 `feedColorWarnings`.

## 설계 (사용자 승인)

- **덮어쓰는 범위는 홈피드 카드만이다.** 원색 5개(`--jam-red` 등)는 디자인 시스템 전체가 쓰는 토큰이라 건드리지 않는다. 카드 전용 변수 `--feed-color-<키>`를 앞에 두고 기본값으로 기존 변수를 가리키게 한다: `feedColorVar(key)` → `var(--feed-color-<키>, var(<기존 cssVar>))`. 덮어쓴 키만 `:root{--feed-color-<키>: #rrggbb}`로 내려준다. 덮어쓰지 않은 키와 디자인 시스템의 다른 곳은 그대로다.
- **저장**: `feed_color_overrides(color_key, hex, updated_at, updated_by)`(마이그레이션 352). 행이 없으면 기본값이고, 기본값 복원은 행 삭제다. 읽기는 누구나(홈 화면), 쓰기는 `service_role`만이다.
- **계산도 같은 팔레트**: 자동 색 배정·색 규칙·어드민 경고는 hex를 입력으로 받는다(2·4회차 설계). 덮어쓴 값으로 합친 팔레트(`FeedPalette`)를 만들어 넘긴다. 규칙 결과는 hex가 바뀌면 다시 계산된다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 마이그레이션 `352_feed_color_overrides.sql`·`_down.sql`은 이미 작성됐다(메인 세션이 승인 뒤 실행). 이 티켓의 코드는 표가 있다고 가정하되 **표가 없거나 읽기가 실패해도 기본값으로 그린다**(홈 화면이 깨지지 않는다). 생성 타입은 표가 생긴 뒤 메인 세션이 `database.generated.ts`에 반영한다(코드는 수기 `database.ts`에 행 타입을 선택으로 둔다).
- **순수 파일** `jam-web/src/lib/today/feedColorOverrides.ts`(신규): `FeedColorOverrides`(키 → hex), `isOverrideHex`(`#rrggbb`), `normalizeOverrides`(모르는 키·잘못된 hex는 버린다, 대소문자 정규화), `buildFeedPalette(overrides)`(15색 기본 hex에 덮어쓴 값을 합친 `FeedPalette`), `feedColorOverrideCss(overrides)`(`:root{…}` 문자열, 덮어쓴 키만, 값은 정규화된 `#rrggbb`만 허용해 CSS 주입이 불가능하게 한다).
- **`feedColorVar`**: 위 설계대로 폴백 변수를 둔다. 덮어쓰기가 없으면 렌더 결과가 의미상 같다(기존 시험은 변수 문자열 기대값이 바뀌는 부분만 고친다. 고친 시험과 이유를 「주요 의사결정」에 적는다).
- **서버 읽기**(`lib/today/feedColorOverridesServer.ts` 신규, 서버 전용): `feed_color_overrides`를 읽어 캐시한다(`unstable_cache`나 이 프로젝트가 쓰는 캐시 방식, 태그 `feed-colors`, 짧은 재검증 시간). 어드민이 적용하면 태그를 무효화한다(무효화 함수 시그니처는 `node_modules/next/dist/docs/`의 안내를 읽고 맞춘다). 읽기가 실패하면 빈 덮어쓰기(기본값)를 돌려주고 서버 로그에 남긴다.
- **홈 화면 적용**: `FeedColorStyle`(서버 컴포넌트 또는 같은 역할의 함수)이 `<style>`로 덮어쓴 변수를 내린다. 홈 카드가 그려지는 곳(`(main)` 홈, 개발용 미리보기 `/dev-sample/home-feed-cards/new`)과 어드민 미리보기(어드민 레이아웃)에서 쓴다. 덮어쓴 키가 없으면 아무것도 그리지 않는다.
- **팔레트 연결**: ① `completeFeedCardValues`(등록·저장 때 색 고정)가 덮어쓴 팔레트를 `assignFeedColors`의 `palette` 옵션과 규칙 판정에 넘긴다. ② `resolveFeedLook`(홈이 색이 비어 있는 카드를 그릴 때)이 선택 입력 `palette`를 받아 쓴다(안 주면 기본 팔레트, 기존 결과 불변). ③ 어드민 카드 폼의 색 경고(`feedColorWarnings`)와 7-7의 이미지 색 경고가 팔레트를 선택 props로 받는다(안 주면 기본). 색 견본(`FeedCardSection`의 색 선택지)은 `feedColorVar`를 쓰므로 변수로 자동 반영된다.
- `lib/admin/feedCardServer.ts`가 읽는 덮어쓰기는 서비스 클라이언트로 한 번 읽는다(`completeFeedCardValues`의 기존 조회와 묶거나 같은 캐시를 쓴다). 읽기 실패는 기본 팔레트로 진행한다. `homeFeedCard.ts`의 번들 경계(`client-server-imports`)를 지킨다.
- **정책 대시보드**: 색 값은 표시 설정이지 운영 정책·밸런스 수치가 아니어서 `policiesData.ts`를 갱신하지 않는다(판단을 「주요 의사결정」에 적는다).

### UI/UX 관점

- 덮어쓰기가 없는 지금 상태에서 홈의 모습이 바뀌지 않아야 한다(실렌더로 확인). 어드민 화면은 2번 티켓이다.

### 구현 내용 요약

색 키는 그대로 두고 hex만 덮어쓰는 서비스 쪽을 구현했다(마이그레이션 352는 위 「진행 기록」). 덮어쓰기 행이 없으면 의미상 이전과 같다.

- `feedColorVar(key)`가 `var(--feed-color-<키>, var(<기존 변수>)))`로 바뀌었다. 덮어쓴 키만 `:root{--feed-color-<키>: #rrggbb}`로 내려가고 디자인 시스템 토큰(`--jam-*`)은 건드리지 않는다.
