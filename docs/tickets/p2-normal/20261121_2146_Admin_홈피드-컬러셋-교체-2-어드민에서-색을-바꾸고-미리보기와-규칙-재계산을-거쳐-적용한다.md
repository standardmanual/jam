# [Admin] 홈피드 컬러셋 교체 2: 어드민에서 색을 바꾸고 미리보기와 규칙 재계산을 거쳐 적용한다

## 핵심 요약

- 어드민에 **「홈피드 컬러셋」 화면**(`/admin/feed-colors`, 이름은 기존 어드민 메뉴 이름 규칙을 따른다)을 만든다. 15색 각각의 현재 값·기본값을 보고 hex를 바꾸고, **적용 전에** 카드 미리보기와 규칙 재계산(통과하는 조합 수, 새로 걸리는 조합, 영향받는 카드 목록)을 본 뒤 «적용»으로 저장한다. 기본값 복원(색별·전체)이 있다. 사용자 승인 설계(2026-11-21).
- 구현 계획: 아래 표. 유형은 `admin`(MODULAR 적용 제외, shadcn/ui 표준).
- **선행**: 1번(20261121_2145, 표·팔레트 연결·홈 적용)이 병합되고 마이그레이션 352가 실행돼야 한다.
- 관련 파일: 1번이 만든 `lib/today/feedColorOverrides.ts`·`feedColorOverridesServer.ts`, `feedColorRules.ts`(`summarizeColorPairs`·`firstViolatedRule`·`passesColorRules`, hex 입력 순수 함수), `feedConstants.ts`(`FEED_COLORS`), 카드 미리보기 부품(`components/today/feed/FeedCard.tsx`, `lib/today/feedPreviewData.ts`의 가짜 카드), 어드민 메뉴(`components/admin/AdminSidebar.tsx`), 어드민 인증(`requireAdmin`).

## 상세 요구사항

### 서비스/코드베이스 관점

- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트의 그리는 결과는 건드리지 않는다(표 읽기·쓰기만).
- **화면 구성**(서버 컴포넌트 `page.tsx`가 덮어쓰기·영향 조회를 읽어 클라이언트 편집기에 넘긴다):
  1. **색 표**: 15행 — 이름(한국어, `FEED_COLOR_LABELS`처럼 기존 이름 표를 읽는다), 색 견본, 기본 hex, 현재 저장된 hex, 편집 중인 hex(색 선택기 `input type=color`와 hex 글자 칸 둘 다, 잘못된 hex는 칸 아래 오류), «기본값으로» 버튼. 바뀐 행은 표시한다.
  2. **미리보기**: 편집 중인 팔레트로 홈피드 샘플 카드(유형 8개 중 대표 몇 장, `feedPreviewData.ts`의 가짜 카드)를 그린다. 변수 덮어쓰기는 미리보기 컨테이너에만 걸어(`style`로 `--feed-color-<키>`) 저장 전 값이 다른 곳에 새지 않는다. 기기 폭 360·430 전환은 기존 미리보기 부품을 쓴다.
  3. **규칙 재계산**: 편집 중인 팔레트의 hex로 `summarizeColorPairs`를 돌려 «통과하는 조합 N개(지금 M개)»와 단계별로 제외되는 개수를 보인다. 지금보다 줄면 경고 문구를 보인다(막지 않는다, 기존 색 규칙 경고와 같은 정신).
  4. **영향받는 카드**: 노출 기간이 아직 끝나지 않은 `today_cards`(`ends_at >= now`)의 색 키 조합(배경·칩·박스, 자동 배정으로 저장된 것 포함)을 서버가 읽어 넘기고, 편집 중인 팔레트에서 **지금은 규칙을 통과하는데 새로 걸리는** 카드를 목록으로 보인다(카드 제목·걸린 규칙 이름·바뀐 색). 카드의 색 키는 바뀌지 않고 보이는 색만 바뀐다는 안내를 함께 둔다. 카드가 많으면 위에서 20장까지 보이고 «외 N장»을 적는다.
  5. **적용·복원**: «적용»은 확인 대화상자(shadcn `alert-dialog`)에서 «바뀌는 색 N개, 새로 걸리는 카드 M장»을 다시 알린 뒤 `PUT /api/admin/feed-colors`로 저장한다. «전체 기본값으로 되돌리기»는 같은 확인을 거쳐 모든 행을 지운다. 저장 뒤 화면을 다시 읽어 «저장돼 있는 값»을 갱신한다.
- **API** `app/api/admin/feed-colors/route.ts`: `GET`(덮어쓰기와 기본값), `PUT`(본문 `{ overrides: { <키>: '#rrggbb' | null } }`: 값이 hex면 upsert, `null`이면 행 삭제. 모르는 키·잘못된 hex는 `400`과 해요체 문구(`normalizeOverrides` 재사용, «현상 → 원인 → 해결책»). `requireAdmin` 필수, `updated_by`에 관리자 id, 저장 뒤 캐시 태그 `feed-colors` 무효화). 본문 크기·키 개수를 15개로 제한한다.
- **메뉴**: 어드민 사이드바의 홈피드 관련 그룹에 항목을 더한다(기존 항목 순서·동작 불변).
- **어드민 UI 규칙**: shadcn/ui 표준 부품, 네이티브 `<select>` 금지, 새 하드코딩 색·간격 금지(견본 색은 `feedColorVar`·편집 중 hex를 `style`로 칠하는 것만 허용하고 `check-spacing`·`slop` 검사를 통과한다). 색 이름만이 아니라 견본과 이름이 함께 읽힌다. 키보드로 조작할 수 있다.
- **문서**: `docs/service/prd/admin-ui/ADMIN_PRD.md`에 「홈피드 컬러셋」 절(화면 구성·적용 흐름·API), `docs/service/prd/home-feed/PRD.md` §6 구현 위치(후속 2). **정책 대시보드**: 색 설정은 운영 정책·밸런스 수치가 아니어서 `policiesData.ts`를 갱신하지 않는다.

### UI/UX 관점

- 적용 전에는 아무것도 저장되지 않는다(미리보기는 화면 안에서만). 바뀐 행·새로 걸리는 카드 수가 한눈에 보이고, 되돌리기 버튼이 항상 보인다. 폭이 좁은 화면에서 가로 스크롤이 없다.

어드민 «홈피드 컬러셋»(`/admin/feed-colors`)을 만들었다. 서버 `page.tsx`가 덮어쓰기(캐시 없이 표에서 직접)와 `ends_at`이 지금 이후인 `today_cards`의 색 키를 읽어 넘기고, 클라이언트 `FeedColorsEditor`가 다음을 맡는다.
