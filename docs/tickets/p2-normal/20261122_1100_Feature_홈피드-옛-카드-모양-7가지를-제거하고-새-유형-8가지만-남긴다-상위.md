# [Feature] 홈피드 옛 카드 모양 7가지를 전부 제거하고 새 유형 8가지만 남긴다 (상위)

## 핵심 요약

- 요구사항: 사용자 지시(2026-11-22 «기존 카드 타입은 제거해», 범위는 «목록형까지 전부»). 옛 모양 7가지(`brief`·`square`·`hero`·`ticket`·`dome`·`poster`·`list`)의 화면 코드와 그것을 고르는 어드민·운영툴·계측 경로를 걷어 낸다. 새 유형 8가지(`hero_box`·`full_image`(꺼짐)·`badge_intro`·`badge_only`·`collection_intro`·`drop_pickup`·`text_box`·`gallery_list`)만 남긴다. `feed_type`이 비었거나 모르는 값인 카드는 텍스트 박스로 그린다. 랭킹 보드·레시피 공개·배지 타일 카드는 홈에서 더 내지 않는다.
- 구현 계획: 8회차로 4조각(아래 표). DB 칸(`shape`·`layout_type`·`card_shape` 등)과 마이그레이션은 건드리지 않는다 — 칸 삭제는 별도 «축소» 티켓이다(확장→전환→축소 규칙).
- 관련 파일: 조각별 티켓에 있다. 규격 정본 `docs/service/prd/home-feed/PRD.md` §6 (1~7회차 구현 완료 기록 아래에 8회차를 더한다).

## 배경 / 문제 정의

홈피드 개편(상위 20261120_2026)은 옛 모양 7가지와 새 유형 8가지를 공존시키며 «옛 카드가 모두 끝나면 걷어 낸다»고 정했다. 2026-11-22에 DB의 홈 카드 121장을 전부 새 유형으로 바꿨다(마이그레이션 353, 위 상위 티켓 완료 기록). 이제 옛 모양을 그리는 코드는 쓰이지 않는다. 남겨 두면 어드민에서 옛 모양을 새로 고를 수 있고, 계측·신호 엔진·운영 패턴이 옛 모양 이름을 기준으로 돌아가 개편과 어긋난다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **지우는 것**: 옛 7모양 카드 컴포넌트와 그 부품(`BriefCard`·`SquareCard`·`HeroCard`·`TicketCard`·`DomeCard`·`PosterCard`·`ListCard`, 그 아래에만 쓰이는 `CardBody`·`CardThumb`·`CardImageSlot`·`CardChipRow`), 옛 값→모양 판정(`resolveShape`·`drawnShape`·`LEGACY_SHAPE_CUTOVER`), 어드민 폼·표·내보내기의 옛 모양·레이아웃 선택, 운영 묶음의 `shape` 필수 조건, 운영 패턴·신호 엔진의 모양 키, 옛 모양 Story·시험·시험용 페이지.
- **남기는 것**: 기사 상세 화면(`ArticleView`, `/today/[cardId]`)은 카드 모양이 아니라 화면이라 남는다. `RankingListRow`는 미션 상태 화면이 쓰므로 남는다. DB 칸과 마이그레이션 파일은 그대로다. `CardFrame`(링크·계측 틀)은 새 유형이 쓰므로 남는다.
- **카드 기록(`today_card_events.card_shape`)**: 칸은 그대로 두고 값을 새 유형 이름(`hero_box` 등)으로 기록한다(칸에 CHECK가 없다, 마이그레이션 206). 이전 기록의 옛 모양 이름은 그대로 남는다.
- **정책 대시보드**: 규칙·밸런스 수치가 아니므로 `policiesData.ts`는 갱신하지 않는다(조각별 티켓에서 확인).

### UI/UX 관점

- 홈 카드의 겉모습은 이미 새 유형이다. 이 작업은 화면 코드 제거라 눈에 보이는 변경은 어드민의 선택지가 줄어드는 것뿐이다(8-2).

## 완료 조건

- 8-1~8-4가 모두 CLOSED이고, `grep`으로 옛 모양 컴포넌트·`resolveShape`·`CARD_SHAPES` 참조가 코드에 없다(DB 타입 파일의 칸 이름 제외).
- 홈(`/`)과 `/dev-sample/home-feed-cards/new`에서 카드가 새 유형으로만 그려지고 오류가 없다.
- 어드민 카드 작성 화면에서 옛 모양을 고를 수 없다.
