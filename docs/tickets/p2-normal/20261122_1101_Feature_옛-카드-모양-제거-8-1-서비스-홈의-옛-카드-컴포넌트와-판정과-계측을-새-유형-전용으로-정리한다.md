# [Feature] 옛 카드 모양 제거 8-1: 서비스 홈의 옛 카드 컴포넌트·판정·계측을 새 유형 전용으로 정리한다

## 핵심 요약

- 요구사항: 홈이 새 유형 8가지만 그리게 한다. 옛 7모양 카드 컴포넌트와 그 부품, 옛 값→모양 판정의 화면 쪽 사용, 홈 조회의 랭킹·레시피 해석을 지운다. `feed_type`이 비었거나 모르는 값이면 텍스트 박스로 그린다. 계측이 `card_shape`에 새 유형 이름을 기록한다. 어드민·운영툴·운영 패턴·`shape.ts`의 상수는 8-2~8-4가 정리하므로 이 조각은 컴파일이 깨지지 않게 남겨 둔다.
- 구현 계획: 아래 표. 유형은 `feature`(채원 판정 생략: 새 화면·새 토큰이 없고 코드 제거와 분기 단순화뿐).
- 관련 파일: `jam-web/src/components/today/TodayCard.tsx`(`RENDERED_SHAPES`·`isRenderedShape`·switch), `components/today/{BriefCard,SquareCard,HeroCard,TicketCard,DomeCard,PosterCard,ListCard,CardBody,CardThumb,CardImageSlot,CardChipRow}.tsx`와 같은 이름의 `__tests__/`·`.stories.tsx`, `components/today/ImageShapes.stories.tsx`, `components/today/resourceIcon.ts`(옛 부품에서만 쓰이면), `jam-web/src/lib/today/cardView.ts`(옛 갈래 뷰 조립, `toCardView`), `lib/today/cards.ts`(`resolved_ranking`·`resolved_recipe`, ~138~231줄), `lib/today/events.ts`(`card_shape` 기록), `jam-web/src/app/(main)/TodayCardStack.tsx`, `app/(main)/dev-sample/home-feed-cards/page.tsx`, `app/spike/card-shapes/page.tsx`. 스펙 `docs/service/prd/home-feed/PRD.md` §6.

## 배경 / 문제 정의

상위 티켓 20261122_1100 참조. 카드 121장이 모두 새 유형이라 옛 컴포넌트는 그려지지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `TodayCard.tsx`는 `FeedCard`만 부른다. `view`에 `feedType`이 없거나 모르는 값이면 텍스트 박스 규격으로 그린다(`toCardView`가 이 기본값을 정해 늘 새 유형 뷰를 돌려준다). `RENDERED_SHAPES`·`isRenderedShape`와 옛 분기는 지운다.
- 옛 7모양 컴포넌트, 그 Story·시험을 지운다. `CardBody`·`CardThumb`·`CardImageSlot`·`CardChipRow`·`resourceIcon`은 **다른 곳에서 가져오지 않는 것만** 지운다(가져오는 곳이 남으면 그대로 둔다). `ArticleView`·`RankingListRow`·`CardFrame`은 지우지 않는다.
- `cardView.ts`: 옛 갈래 뷰(모양별 필드·랭킹 행·타일·레시피 타일 조립)를 지우고 새 유형 뷰만 만든다. 새 유형이 읽는 값(제목·설명·배지·커버·목록 등)은 그대로다. 다른 코드가 가져오는 이름은 `shape.ts`에 남겨 둔 상수를 쓴다(8-4에서 정리).
- `lib/today/cards.ts`: 홈이 더는 그리지 않는 랭킹·레시피 해석(`resolved_ranking`·`resolved_recipe`)의 조회를 지운다. 새 유형이 읽는 필드(`resolved_badges` 등)는 그대로다. 다른 호출부(어드민 미리보기 등)가 쓰면 그 호출부와 함께 정리하거나 남기고 이유를 적는다.
- `events.ts`: 기록하는 `card_shape` 값을 새 유형 이름으로 바꾼다. 기록 모양 = 화면 모양이라는 일치 시험(`shapeParity.test.ts`)을 새 기준으로 고친다.
- DB·`src/types/`·마이그레이션·어드민·운영툴은 건드리지 않는다.

### UI/UX 관점

- 홈의 겉모습은 바뀌지 않는다. 확인: `/`와 `/dev-sample/home-feed-cards/new`가 오류 없이 그려진다.

### 구현 범위 (게이트 판정 대상)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- `TodayCard`는 `FeedCard`만 그린다(`RENDERED_SHAPES`·`isRenderedShape`·옛 분기·`currentUserId` 인자 삭제). 옛 7모양 컴포넌트 7개와 부품 5개(`CardBody`·`CardThumb`·`CardImageSlot`·`CardChipRow`·`resourceIcon`), 옛 모양 Story·시험, 옛 샘플 페이지 `(main)/dev-sample/home-feed-cards/page.tsx`를 지웠다.
- 유형 판정은 새 순수 파일 `lib/today/feedType.ts`의 `resolveFeedType` 하나다. `feed_type`이 비었거나 모르는 값(꺼진 `full_image` 포함)이면 텍스트 박스, 컬렉션 소개(커버 없음)·드랍·픽업(배지 0개)·목록형(그릴 항목 0개)도 텍스트 박스다. `toCardView`와 `events.ts`가 같은 함수를 쓴다.
- `toCardView`는 옛 갈래(모양별 필드·타일·랭킹 행·레시피 타일·`resolveShape`)를 지우고 `FeedCardView` 하나만 만든다. `tracking`에는 `feedType`이 늘 실리고(`shape` 없음), `CardFrame`이 이 값을 GA `today_card_click`의 `shape` 파라미터로 보낸다(이름은 그대로, 값이 새 유형 이름).
- `getTodayCards`는 랭킹 순위·레시피를 해석하지 않는다(`resolved_ranking` null, `resolved_recipe` 없음, 랭킹 모드 읽기는 트라이브 거름만 남음).
- `events.ts`의 `card_shape`는 새 유형 이름이다. 카드 조회 칸이 `feed_type`·`cover_image_url`·`badge_ids`·`list_items`·`pattern_no`로 바뀌고 레시피 읽기가 없어졌다. `shapeParity.test.ts`는 `feed_type` 8가지+비었거나 모르는 값 × 커버 × 배지 × 목록 264건으로 기록 유형 = 화면 유형을 맞춘다.
- 홈피드 PRD §6(구현 위치 8회차-1, 옛 7모양 설명은 «이력» 표기)·§9(계측)를 고쳤다.
