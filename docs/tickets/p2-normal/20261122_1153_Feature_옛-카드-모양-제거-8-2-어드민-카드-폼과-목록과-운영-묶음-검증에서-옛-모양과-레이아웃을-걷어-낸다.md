# [Feature] 옛 카드 모양 제거 8-2: 어드민 카드 폼·목록·상세·내보내기와 운영 묶음 검증에서 옛 모양·레이아웃을 걷어 낸다

## 핵심 요약

- 요구사항: 어드민에서 옛 모양(`shape`)·노출 형태(`layout_type`)를 더는 고르거나 보이지 않게 한다. 새 카드는 늘 새 유형을 갖는다(`feed_type` 필수). 운영 묶음의 `home_feed_card` 항목은 `shape` 대신 `resource.feed_type`이 필수다. 8-1이 서비스 홈을 이미 정리했다. DB 칸·마이그레이션·`src/types/`는 건드리지 않는다.
- 구현 계획: 아래 표. 유형은 `admin`(MODULAR 적용 제외, shadcn 표준).
- 관련 파일: `jam-web/src/app/admin/today/TodayCardForm.tsx`(~169·261·431·504줄 `layoutType`·`SUGGESTED_LAYOUT_FOR`·`TODAY_LAYOUT_OPTIONS`), `app/admin/today/FeedCardSection.tsx`(유형 선택 «옛 모양 그대로» 빈 값), `app/admin/today/TodayCardTable.tsx`(~30·80·88·160줄 노출형태 열, `feedTypeCellText`), `components/admin/today/TodayCardDetail.tsx`(~35·83·166줄), `app/api/admin/today/export/route.ts`(~49줄 `노출형태` 열), `app/api/admin/today/route.ts`·`[id]/route.ts`(`layout_type` 검증), `lib/admin/today-sections.ts`(~53·106·118·382줄 `TODAY_LAYOUT_OPTIONS`·`SUGGESTED_LAYOUT_FOR`·`shape`), `lib/admin/today-list-query.ts`(~19·26줄), `lib/admin/feedCardFields.ts`(`feed_type` 빈 값 처리), `lib/admin/opsInbox/{validate,registerInput}.ts`(`shape` 필수·`CARD_SHAPES`·제목 글자 수 경고), `lib/admin/registerChecks/homeFeedFields.ts`(~55·73·197~220·333줄 `layout_type`·`LAYOUT_TYPES`). 스펙 `docs/service/prd/admin-ui/ADMIN_PRD.md` §5-11, `docs/service/prd/ops-tool/PRD.md` §8.4, `.claude/agents/jam-marketer.md`.

## 배경 / 문제 정의

상위 티켓 20261122_1100 참조. 8-1에서 홈이 새 유형 8가지만 그린다. 어드민이 아직 노출 형태(옛 레이아웃)와 «옛 모양 그대로» 선택지를 주면, 고른 값이 화면에 반영되지 않는데 선택지가 남아 운영자를 헷갈리게 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **카드 작성·수정 폼**: 「노출 형태」 선택과 `SUGGESTED_LAYOUT_FOR` 기본값 연동을 지운다. 저장할 때 `layout_type`은 DB 기본값(`large_thumbnail`, NOT NULL)으로 보내거나 보내지 않는다(API가 필수로 검증하면 고정값). `shape`는 보내지 않는다(NULL). 카드 유형(`feed_type`) 선택에서 «옛 모양 그대로»(빈 값) 선택지를 없애고 새 유형 중 하나를 필수로 하며 새 카드의 기본값은 `text_box`다. 이미 저장된 카드가 `feed_type`이 NULL이면 수정 화면은 `text_box`로 보여 주고 저장하면 채워진다.
- **목록 표**: 「노출형태」 열을 지운다. 「유형」 열은 `feed_type`만 보이고, NULL(옛 데이터)은 «텍스트 박스(기본)»로 보인다(`feedTypeCellText`의 «옛 모양 (…)» 갈래 삭제). **상세 화면**의 「노출 형태」 항목은 카드 유형으로 바꾼다. **내보내기(CSV)**의 `노출형태` 열은 `카드유형`(`feed_type`)으로 바꾼다.
- **조회 칸**: `lib/admin/today-list-query.ts`의 `layout_type` 조회·타입을 지운다(상세·미리보기 등 다른 호출부가 `layout_type`을 읽으면 그 호출부는 남긴다 — 완료 기록에 이유를 적는다).
- **운영 묶음 검증(`validateOpsCardFields`)·등록 변환(`toTodayCardRegisterInput`)**: `home_feed_card` 항목은 `shape` 필수 조건을 `resource.feed_type` 필수로 바꾼다(없으면 형식 오류, 문구는 «현상 → 원인 → 해결책»). 항목에 `shape`가 있으면 오류로 막지 않고 «이제 쓰지 않아요, 무시해요» 경고를 붙이고 저장하지 않는다. `layout_type`도 같다(읽는 칸 목록에서 빼고 경고). 제목 글자 수 경고(`CARD_TITLE_MAX_LENGTH[shape]`)는 모양 기준이라 지운다(새 유형별 상한이 PRD에 없으면 만들지 않는다). 패턴 입력의 `card_shapes`는 8-3 범위라 건드리지 않는다.
- **`registerChecks/homeFeedFields.ts`**: `buildTodayCardInsertPayload`가 `layout_type`·`shape`를 페이로드에 싣지 않는다(DB 기본값). `LAYOUT_TYPES`·`mission_spotlight`는 `large_thumbnail` 검증을 지운다.
- **문서·에이전트 정의**: `docs/service/prd/admin-ui/ADMIN_PRD.md`(§5-11 폼·표 설명), `docs/service/prd/ops-tool/PRD.md` §8.4(`shape` → `resource.feed_type` 필수), `docs/service/prd/content-automation/PRD.md`·`.claude/agents/jam-marketer.md`에서 윤진이 항목에 `shape`를 적게 하는 문장을 `resource.feed_type` 기준으로 바꾼다(에이전트 정의 수정은 이 문장만).
- DB·마이그레이션·`src/types/`·서비스 홈 컴포넌트는 건드리지 않는다. `policiesData.ts`는 갱신하지 않는다(규칙·수치 변경 아님).

### UI/UX 관점

- 어드민 화면은 MODULAR 대상이 아니다(shadcn 표준). 사용자(운영자)에게 보이는 변화: 폼에서 «노출 형태»가 사라지고 유형이 필수가 된다. 문구는 해요체.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 어드민 카드 작성·수정 폼에 「노출 형태」 선택이 없고, 카드 유형 선택에 «옛 모양 그대로»가 없으며 새 카드의 기본 유형은 `text_box`다(시험으로 고정).
- 저장 본문이 `shape`를 싣지 않고 `layout_type`은 DB 기본값 또는 고정값이다. `PATCH`·`POST` 시험이 통과한다.
- 목록 표에 「노출형태」 열이 없고 「유형」 열이 새 유형 이름(NULL은 «텍스트 박스(기본)»)을 보인다. 상세 화면과 내보내기도 카드 유형으로 바뀐다.
- 운영 묶음의 `home_feed_card` 항목은 `resource.feed_type`이 없으면 형식 오류이고, `shape`가 있으면 오류가 아니라 «쓰지 않아요» 경고가 붙으며 등록 페이로드에는 `shape`가 없다.
- `scripts/verify.sh`가 통과한다. 삭제한 상수·함수를 가리키는 import가 없다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 로컬 어드민(`ADMIN_EMAILS`)에서 카드 작성 화면이 열리고 폼에 노출 형태가 없는지 실렌더로 확인한다(서비스 키가 없으면 임시 페이지로 폼 부품만 확인한다).

## 완료 기록 *(작업 완료 후 작성)*
### 구현 내용 요약

- **카드 작성·수정 폼**(`TodayCardForm.tsx`): 「노출 형태」 선택과 템플릿별 추천 연동을 지웠다. 저장 본문에 `layout_type`·`shape`가 없다(새 카드는 DB 기본값, 수정은 저장값 유지). 카드 유형 선택(`FeedCardSection`)에서 «옛 모양 그대로»를 없애 필수로 하고(`ChoiceField`에 `required`), 새 카드 기본은 `text_box`(`feedCardFields.ts`의 `DEFAULT_FEED_TYPE`·`withDefaultFeedType`)다. 유형이 비어 있던 카드는 수정 화면에서 `text_box`로 보이고 저장하면 채워진다. «옛 모양으로 보여요» 안내 문구는 «텍스트 박스로»로 고쳤다.
- **목록·상세·내보내기**: 목록 표의 노출형태 열과 조회 칸을 지웠고 유형 열은 NULL이면 «텍스트 박스(기본)»이다. 상세는 「카드 유형」, CSV는 `카드유형`(`feed_type` 원값, NULL은 빈 칸)이다.
- **운영 묶음**(`validate.ts`·`registerInput.ts`·`homeFeedFields.ts`): `home_feed_card`는 `resource.feed_type`이 필수다(없으면 형식 오류, 현상→원인→해결책 문구). `shape`·`resource.shape`·`resource.layout_type`이 있으면 «이제 쓰지 않아요» 경고만 붙이고 등록 값에 싣지 않는다. 모양별 제목 글자 수 경고와 미션 카드의 `large_thumbnail` 검사를 지웠다. `buildTodayCardInsertPayload`는 `layout_type`·`shape`를 싣지 않는다.
- **문서·정의**: ADMIN_PRD §5-11, ops-tool PRD §3.1·§8.4, content-automation PRD, home-feed PRD(8회차-2), `HOME_FEED_REGISTRATION_BUNDLE.md`, `jam-marketer.md`(`shape` 적게 하는 문장 1곳)를 고쳤다.
