## 상세 요구사항

### 서비스/코드베이스 관점
- 랜덤 색은 **서버 컴포넌트에서 요청마다** 고른다(`Math.random`을 기본값으로 받되 시험을 위해 주입 가능하게). 후보는 원색 5개(`--jam-red`·`--jam-yellow`·`--jam-green`·`--jam-purple`·`--jam-blue`, hex는 `FEED_COLORS`의 같은 키). 홈피드 덮어쓰기 변수(`--feed-color-*`)는 쓰지 않는다.
- 이미지 색 회피: `violatesImageColorRule(후보 hex, badge.bg_colors ?? [])`가 참인 후보를 뺀다. 다 빠지면 5개 전체에서 고른다.
- 끝색: 노랑 계열(HSL 색상 40~70°)이면 `oklch(from var(--ticket) calc(l - 0.03) calc(c * 1.15) calc(h - 20))`, 아니면 `oklch(from var(--ticket) calc(l - 0.08) calc(c * 1.2) h)`. 판정은 hex로 서버에서 한다.
- **깜빡임 금지**: 티켓색·끝색은 서버 HTML의 인라인 CSS 변수(`--ticket`·`--ticket-end`)로, 모양·그라데이션·토큰 덮어쓰기는 CSS 모듈로 내려 첫 화면부터 그린다. 클라이언트 컴포넌트·`useEffect`·`useState`로 색이나 모양을 정하지 않는다. 로고 마스크 이미지(`/jam-logo-white.png`)는 `ReactDOM.preload`(as: 'image')로 미리 받게 한다. 그레인은 data URI라 추가 요청이 없다.
- 전체 화면 배경 테마 레이어를 그리지 않는다. `BadgeHeroSection`에는 `themedBackground={false}`를 넘겨 오라 배경이 나오게 한다(배경색 지정 아이템 배지 10개는 상위 티켓 후속으로 DB 값을 지운다).
- 날짜(티켓 머리): 아이템=대표 개체(`activeItem`) `obtained_at`, 체크인=`checkinEarns[0].earned_at`(최신), 액티비티=`earned.earned_at`. 한국 시각 `YYYY.MM.DD`. 값이 없으면(미획득) 날짜 줄을 그리지 않는다.

### UI/UX 관점
- 상위 티켓 「확정 규격」의 페이지·티켓 머리·절취선·아래 블록(그라데이션·그레인)·토큰 덮어쓰기를 그대로 따른다. 이번 회차의 아래 블록 구성: 사진 자리(히어로 카드 통째, 래퍼 좌우 16px 안쪽) → (아이템만) 일련번호 → 절취선 2 → 카드 구간(기존 info·desc·action 섹션 그대로, 공유 버튼과 체크인 안내 문단 제외).
- 종류 글자 `ITEM` / `CHECK IN` / `ACTIVITY`는 i18n 사전(`d.badges`)에 둔다.

## 구현 계획

1. `lib/badgeTicket/ticketColor.ts`: `TICKET_COLOR_KEYS = ['red','yellow','green','purple','blue']`, `pickTicketColor(imageHexes, rand = Math.random)` → `{ key, cssVar, hex, endColor }`, `isYellowHue(hex)`, `ticketEndColor(hex)`. 시험: 회피 규칙·전부 빠졌을 때·노랑 판정(#FEC100은 노랑, #FF1D1D·#34EF5A·#BA8AF7·#0695EC는 아님)·rand 주입으로 결정적 선택.
2. `badges/[id]/BadgeTicket.tsx` + `.module.css`: props `{ color, kindLabel, dateText, photo, afterPhoto?, body }`. 루트에 `style={{ '--ticket': var(cssVar), '--ticket-end': endColor }}`. 머리(로고 `.jam-logo-mark` + 종류·날짜), 아래 블록(절취선 1 점선, 사진, afterPhoto, 절취선 2 점선+삼각 홈 두 개(페이지 배경색 삼각형), body). 머리 아래 모서리 홈은 CSS 마스크(`linear-gradient` 45° 4층 교차, `-webkit-mask-composite: source-in` 병기), 아래 블록 윗모서리 홈도 같은 방식. 토큰 덮어쓰기는 티켓 루트 클래스에서.
3. `page.tsx` 세 변형: 루트 `div`에 `--background: #F1E9D6`과 배경을 주고 TopNav는 그대로, `badgeBackgroundLayer`·`themedTextStyle`·`topNavStyle` 제거, 기존 섹션들을 `BadgeTicket`의 `photo`·`afterPhoto`·`body`에 옮겨 담고, 공유 버튼은 티켓 밖 `padding: 24px 16px 32px` 래퍼로.
4. 시험·문서 갱신.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 세 변형의 서버 렌더 HTML에 `--ticket:` 인라인 변수가 원색 5개 중 하나로 들어 있고, 티켓 머리에 종류 글자와(획득 시) `YYYY.MM.DD` 날짜가 있다.
- `pickTicketColor` 시험: bg_colors가 빨강 계열이면 `red`가 후보에서 빠진다. 5개가 모두 빠지는 입력에서도 5개 중 하나를 돌려준다. `--jam-yellow`만 노랑 끝색 문자열을 받는다.
- `BadgeTicket.tsx`와 그 CSS 모듈에 `'use client'`·`useEffect`·`useState`가 없다.
- 체크인 상세 HTML에 `checkinSafetyNotice` 문장이 없고, 액티비티 획득 정보 카드에 «획득 정보» 제목이 없다. 공유 버튼은 티켓 루트 요소 밖에 있다.
- 전체 화면 배경 테마 레이어(`position: fixed` 배경 div)가 세 변형 모두에서 렌더되지 않는다.
- `scripts/verify.sh` 통과.
- `docs/service/prd/badge-detail/PRD.md`가 생기고 확정 규격과 구현 위치가 적혀 있다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`로 세 변형을 실렌더해 스크린샷을 캔버스와 대조한다.
