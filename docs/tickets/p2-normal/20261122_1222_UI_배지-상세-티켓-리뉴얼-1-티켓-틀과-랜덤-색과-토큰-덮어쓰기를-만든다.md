## 상세 요구사항

### 서비스/코드베이스 관점
- 랜덤 색은 **서버 컴포넌트에서 요청마다** 고른다(`Math.random`을 기본값으로 받되 시험을 위해 주입 가능하게). 후보는 원색 5개(`--jam-red`·`--jam-yellow`·`--jam-green`·`--jam-purple`·`--jam-blue`, hex는 `FEED_COLORS`의 같은 키). 홈피드 덮어쓰기 변수(`--feed-color-*`)는 쓰지 않는다.
- 이미지 색 회피: `violatesImageColorRule(후보 hex, badge.bg_colors ?? [])`가 참인 후보를 뺀다. 다 빠지면 5개 전체에서 고른다.
- 끝색: 노랑 계열(HSL 색상 40~70°)이면 `oklch(from var(--ticket) calc(l - 0.03) calc(c * 1.15) calc(h - 20))`, 아니면 `oklch(from var(--ticket) calc(l - 0.08) calc(c * 1.2) h)`. 판정은 hex로 서버에서 한다.
- **깜빡임 금지**: 티켓색·끝색은 서버 HTML의 인라인 CSS 변수(`--ticket`·`--ticket-end`)로, 모양·그라데이션·토큰 덮어쓰기는 CSS 모듈로 내려 첫 화면부터 그린다. 클라이언트 컴포넌트·`useEffect`·`useState`로 색이나 모양을 정하지 않는다. 로고 마스크 이미지(`/jam-logo-white.png`)는 `ReactDOM.preload`(as: 'image')로 미리 받게 한다. 그레인은 data URI라 추가 요청이 없다.
- 전체 화면 배경 테마 레이어를 그리지 않는다. `BadgeHeroSection`에는 `themedBackground={false}`를 넘겨 오라 배경이 나오게 한다(배경색 지정 아이템 배지 10개는 상위 티켓 후속으로 DB 값을 지운다).
- 날짜(티켓 머리): 아이템=대표 개체(`activeItem`) `obtained_at`, 체크인=`checkinEarns[0].earned_at`(최신), 액티비티=`earned.earned_at`. 한국 시각 `YYYY.MM.DD`. 값이 없으면(미획득) 날짜 줄을 그리지 않는다.

### UI/UX 관점
- 상위 티켓 「확정 규격」의 페이지·티켓 머리·절취선·아래 블록(그라데이션·그레인)·토큰 덮어쓰기를 그대로 따른다. 이번 회차의 아래 블록 구성: 사진 자리(히어로 카드 통째, 래퍼 좌우 16px 안쪽) → (아이템만) 일련번호 → 절취선 2 → 카드 구간(기존 info·desc·action 섹션 그대로, 공유 버튼과 체크인 안내 문단 제외).
- 종류 글자 `ITEM` / `CHECK IN` / `ACTIVITY`는 i18n 사전(`d.badges`)에 둔다.
