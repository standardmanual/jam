# [Feature] 옛 카드 모양 제거 8-4: shape.ts 잔여 상수·집계·문서 생성 구간·옛 시안 페이지를 정리하고 남은 참조를 전수 점검한다

## 핵심 요약

- 요구사항: 8-1~8-3이 화면·어드민·운영툴을 새 유형 기준으로 바꿨다. 8-4는 남은 옛 모양 잔재를 걷는 마무리다. ① `lib/today/shape.ts`에서 옛 모양 상수·판정(`CARD_SHAPES`·`CardShape`·`CARD_TITLE_MAX_LENGTH`·`IMAGE_CARD_SHAPES`·`isCardShape`·`isImageShape`·`ShapeCardInput`·`resolveShape`·`drawnShape`·`LEGACY_SHAPE_CUTOVER`·`fallbackEmptyTileShape`·`isRankingRows`)를 지우고 아직 쓰이는 것(`CARD_RESOURCES`·`resourceOfTemplate`·`DESCRIPTION_TEMPLATES`·`showsDescription`·`resolveTitleInImage`)만 남긴다. ② `TODAY_LAYOUT_OPTIONS`·`SUGGESTED_LAYOUT_FOR`를 지우고 홈피드 PRD 생성 구간 스크립트(`scripts/gen-home-feed-doc.mjs`와 시험)가 새 기준을 읽게 한다. ③ 집계 API(`metrics/route.ts`)의 옛 이름·새 이름 혼재를 표시로 구분한다. ④ 옛 시안 페이지 `app/spike/card-shapes`를 지운다. ⑤ PRD·스킬 문서의 옛 7모양 문구를 정리한다. ⑥ 남은 참조를 전수 점검한다.
- 구현 계획: 아래 표. 유형은 `feature`(채원 생략, 화면 변경 없음). **DB·마이그레이션은 건드리지 않는다**(`src/types/database.ts`는 옛 함수 이름을 가리키는 주석 두 곳만 고친다).
- 관련 파일: `jam-web/src/lib/today/shape.ts`와 `__tests__/shape.test.ts`(78줄 참조), `lib/today/cardView.ts`(~21·377줄이 `CARD_RESOURCES`·`resolveTitleInImage`·`resourceOfTemplate`를 가져온다 — 남는 것), `lib/admin/today-sections.ts`(~12·103~117줄)와 `__tests__/today-sections.test.ts`, `lib/admin/registerChecks/homeFeedFields.ts`(~22·276줄 `DESCRIPTION_TEMPLATES` — 남는 것), `scripts/gen-home-feed-doc.mjs`·`scripts/gen-home-feed-doc.test.mjs`(`TODAY_LAYOUT_OPTIONS`를 읽는다), `jam-web/src/app/api/admin/today/metrics/route.ts`(~62·82줄 `byShape`), `jam-web/src/app/spike/card-shapes/page.tsx`, `jam-web/src/types/database.ts`(~1348·1351줄 주석), 문서 `docs/service/prd/{02_DATA_MODEL,home-feed/PRD,ops-tool/PRD,admin-ui/ADMIN_PRD}.md`, `.claude/skills/jam-story/references/marketer-assets.md`(24줄 근처), `.claude/skills/jam-work/references/scheduled-jobs.md`(459줄 근처, 생성 파일 `scheduledJobs.generated.ts`가 이 문서에서 나오니 생성 스크립트를 함께 돌린다), `.claude/agents/jam-marketer.md`.

## 배경 / 문제 정의

상위 티켓 20261122_1100 참조. 8-1~8-3이 끝난 뒤에도 옛 상수·판정 함수와 문서의 옛 모양 설명이 남아 있으면 «옛 모양이 아직 있다»고 읽혀 다음 작업을 헷갈리게 한다. 8-2·8-3에서 일부러 남긴 것(생성 구간이 읽는 상수, 집계 혼재, 스킬 문서)을 여기서 닫는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- **`shape.ts` 정리**: 위 «지우는 것»을 지우고 «남기는 것»만 둔다. 파일 이름·위치는 그대로 둔다(옮기면 가져오는 곳이 크게 흔들린다. 머리 주석을 «카드 자원(`resource`) 대응과 설명·제목 판정»으로 고친다). 지운 뒤에도 클라이언트·서버 번들 경계(`events.ts`가 사전을 값으로 가져오지 않는다는 `eventsImports.test.ts`)가 유지된다. `shape.test.ts`는 남은 함수만 시험하도록 줄인다.
- **레이아웃 상수**: `TODAY_LAYOUT_OPTIONS`·`SUGGESTED_LAYOUT_FOR`와 `today-sections.test.ts`의 해당 시험을 지운다. 이 상수를 읽던 홈피드 PRD 생성 구간(`scripts/gen-home-feed-doc.mjs`)은 «노출 형태» 표를 더는 만들지 않게 하거나 카드 유형 표(`FEED_TYPES`와 이름 표 `lib/admin/feedTypeLabels.ts`)로 바꾼다. 생성 스크립트와 시험(`.test.mjs`)을 함께 고치고 `node scripts/gen-home-feed-doc.mjs`로 PRD 생성 구간을 갱신한다(`scripts/verify.sh`의 home-feed-doc 검사가 통과해야 한다). 생성 구간은 손으로 고치지 않는다.
- **집계 API**: `byShape`는 응답 키 이름을 그대로 두고(소비 코드 호환) 각 행에 `kind`(`feed_type` | `legacy` | `unknown`)를 더한다. 새 유형 8가지 이름이면 `feed_type`, `unknown`이면 `unknown`, 그 밖(옛 7모양 이름)이면 `legacy`다. 정렬·값 계산은 그대로다. 응답 형식은 `docs/service/prd/home-feed/PRD.md` §9 집계 절에 적는다.
- **옛 시안 페이지**: `app/spike/card-shapes`와 그 시험·링크가 있으면 지운다(옛 7모양만 다루는 시안).
- **`src/types/database.ts`**: 옛 `resolveShape`를 가리키는 주석 두 곳만 현재 동작(홈은 `feed_type`으로 그리고 값이 없으면 텍스트 박스)에 맞게 고친다. 타입·칸 이름은 건드리지 않는다.
- **전수 점검**: 마지막에 `jam-web/src`·`jam-web/scripts`·`scripts/`에서 `resolveShape`·`drawnShape`·`CARD_SHAPES`·`isCardShape`·`isImageShape`·`IMAGE_CARD_SHAPES`·`CARD_TITLE_MAX_LENGTH`·`LEGACY_SHAPE_CUTOVER`·`TODAY_LAYOUT_OPTIONS`·`SUGGESTED_LAYOUT_FOR`·`fallbackEmptyTileShape`를 grep해 0건임을 확인하고(옛 이름을 «옛 모양 이름»으로 보여 주는 운영 패턴 코드와 `card_shapes` 칸 이름 식별자는 예외), 결과를 완료 기록에 적는다.
- **문서·스킬**: `02_DATA_MODEL.md`(`today_cards.shape`·`layout_type`·`card_shape` 설명은 «옛 칸, 쓰지 않음(2026-11-22), 값은 보관»으로), 홈피드 PRD(옛 7모양 설명 절 — 모양 판정 표·글자 배치 상한·옛 렌더 설명 — 은 «삭제됨(티켓 20261122_1100), git 이력 참고» 한 줄 안내로 줄이되 DB 칸·계측 사실은 남긴다), ops-tool PRD·ADMIN_PRD의 남은 옛 모양 문구, `marketer-assets.md`·`scheduled-jobs.md`·`jam-marketer.md`의 옛 7모양 문구를 새 유형 기준으로 고친다. `scheduled-jobs.md`를 고치면 `scheduledJobs.generated.ts` 생성 스크립트를 돌려 같은 커밋에 넣는다. 규칙·수치가 바뀌지 않으므로 `policiesData.ts`는 갱신하지 않는다.
- DB·마이그레이션·서비스 홈 컴포넌트·운영 패턴의 `card_shapes` 값은 건드리지 않는다.

### UI/UX 관점

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- `shape.ts`에 옛 모양 상수·판정이 없고 남긴 함수만 시험이 통과한다. 전수 점검 grep이 0건이다(예외는 위에 적은 것만).
- `TODAY_LAYOUT_OPTIONS`·`SUGGESTED_LAYOUT_FOR`가 없고 `scripts/verify.sh`의 home-feed-doc 검사가 통과한다(PRD 생성 구간이 생성 스크립트로 갱신됨).
- 집계 API `byShape` 행에 `kind`가 있고 시험이 새 유형·옛 이름·`unknown` 세 경우를 고정한다.

- 문서·스킬에 옛 7모양을 «지금 있는 것»처럼 쓴 문장이 없다(이력 표기만 허용).
