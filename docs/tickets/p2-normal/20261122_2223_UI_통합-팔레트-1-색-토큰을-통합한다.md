# [UI] 통합 팔레트 1: 색 토큰을 통합한다 (노랑·초록 값 교체, 분홍·하늘·짙은 초록·값 칩 흰색 추가)

## 핵심 요약

- 요구사항: 상위 티켓 [20261122_2217](20261122_2217_Feature_홈피드와-배지-상세를-통합-팔레트와-새-칩-규칙으로-리뉴얼한다-상위.md) 「확정 결정 §1 통합 팔레트」를 디자인 시스템 토큰에 반영한다. `--jam-yellow`를 #FEC100에서 #F9FD69로, `--jam-green`을 #34ef5a에서 #59C02B로 바꾸고, 새 토큰 넷(분홍 #F372C1, 하늘 #51CDF5, 짙은 초록 #3D851E, 값 칩 흰색 #FFFFFF)을 더한다. 빨강·보라·파랑(`--jam-red`·`--jam-purple`·`--jam-blue`)은 값을 바꾸지 않는다. 홈피드 15색 키 구조·자동 배정·색 규칙의 교체는 하위 2번 티켓이 한다(이 티켓은 값과 새 토큰만).
- 구현 계획: 아래 「구현 계획」의 파일 단위 표. 새 토큰 이름은 채원① 판정을 따른다(제안: `--jam-pink`·`--jam-sky`·`--jam-green-deep`·`--jam-chip-white`).
- 관련 파일: `jam-web/design-system/tokens/colors.css`(강조색 주석 61~64줄, `--jam-*` 65~69줄, 홈피드 10색 주석 72줄), `jam-web/src/lib/today/feedConstants.ts`(`FEED_COLORS`의 `yellow`·`green` hex 60~61줄), `jam-web/src/lib/today/__tests__/feedColorRules.test.ts`(요약 개수 기대값 136~175줄), `jam-web/design-system/foundations/Colors.stories.tsx`(강조색 절 140~151줄), `jam-web/design-system/_ds_manifest.json`(1036·1042줄 근처).

## 배경 / 문제 정의

- 강조색 5개(`--jam-*`)는 배지 상세 티켓색과 홈피드 원색 5개가 함께 읽는 토큰이다. 사용자가 통합 팔레트를 확정하면서 노랑·초록 값을 바꾸고 새 색 넷을 더하기로 했다(2026-11-22).
- `--jam-green`은 컬렉션 목록 카드·컬렉션 상세·인벤토리의 진행도 바와 완성한 컬렉션 카드 면에도 쓰여, 그 화면들의 초록도 함께 바뀐다(사용자 승인 «제안대로 값을 통합»).

## 상세 요구사항

### 서비스/코드베이스 관점
- `colors.css`: 두 값 교체, 새 토큰 넷 추가. 강조색 주석에 «통합 팔레트(티켓 20261122_2217)» 출처와 새 토큰의 지정 사용처(홈피드 카드·칩·분류 스티커·배지 상세 티켓, 흰색은 값 칩 전용)를 적는다. 72줄 «글자는 --foreground 고정(--snow는 15색 위에서 AA 미달)» 주석에 예외를 적는다: 짙은 초록 바탕 카드의 바탕 위 글자는 흰색(`--snow`, 대비 4.5).
- `feedConstants.ts`의 `FEED_COLORS.yellow`·`green` hex를 새 값으로 맞춘다(`feedConstants.test.ts`가 colors.css와 대조한다).
- 색 값이 바뀌어 달라지는 시험 기대값(`feedColorRules.test.ts`의 15색 요약 개수 등)을 새 값으로 고친다. 고친 기대값과 이유를 「주요 의사결정」에 적는다. 계산 규칙 자체는 바꾸지 않는다(2번 티켓 범위).
- Storybook `Colors.stories.tsx`: 강조색 절의 노랑·초록 설명을 갱신하고 새 토큰 넷을 견본에 더한다. `_ds_manifest.json`의 값도 맞춘다.
- 현행 문서에서 옛 값(#FEC100·#34ef5a)을 쓰는 곳을 찾아 고친다(`docs/tickets/`·`docs/archive/`는 고치지 않는다).

### UI/UX 관점
- 컬렉션 진행도 바·완성 컬렉션 카드의 초록이 풀색으로 바뀐다. 흰 글자나 다른 색과 겹쳐 읽기 어려워지는 곳이 있으면 `[주의]`로 보고한다(이 티켓에서 고치지 않는다).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `--jam-yellow`를 #FEC100에서 #F9FD69로, `--jam-green`을 #34ef5a에서 #59C02B로 바꿨다. `--jam-red`·`--jam-purple`·`--jam-blue`는 그대로다.
- 보조 토큰 4개를 정의했다: `--jam-pink` #F372C1, `--jam-sky` #51CDF5, `--jam-green-deep` #3D851E, `--jam-chip-white` #FFFFFF. 이름은 채원①이 정했다. 값만 정의했고 쓰는 코드는 하위 2번 이후 티켓에서 붙인다.
- 홈피드 카드 색 주석에 «짙은 초록 바탕 위 글자는 --snow 흰색(대비 약 4.59:1, 계산값)» 예외를 적었다.
- `FEED_COLORS.yellow`·`green` hex를 맞추고, 새 값 때문에 달라진 시험 기대값을 고쳤다(계산 로직과 15색 키 구조는 그대로). Storybook 색 견본, `_ds_manifest.json`, 홈피드 PRD의 옛 hex도 바꿨다.
- 머지할 때 카리나가 지도 드랍 마커 주석의 대비 수치를 «약 11:1»에서 «약 7.7:1»로 고쳤다(채원② 제안). 채원②가 적은 9.0:1은 순수 검정 기준이고, 실제 글자 색 `--foreground`(#171717) 기준으로는 7.68:1이다.

### 채원① 판정과 연결 범위
- 판정: 재사용(기존 토큰 값 교체와 토큰 4개 추가). 컴포넌트 변경 없음. 상위 티켓에서 사용자가 승인한 값이라 승인 필요 항목 없음.
- 연결 범위: 토큰, 서비스에 즉시 반영(`ds-connection-scope.md` 첫째 부류). 영향받는 곳은 컬렉션 진행도 바(목록·상세·인벤토리), 완성 컬렉션 카드 면과 상세 완성 영역, 지도 드랍 마커, 홈피드 카드(`feedConstants.ts` 경유), 배지 상세 티켓이다.
