# [Feature] 통합 팔레트 2: 홈피드 색 체계를 통합 팔레트로 바꾸고 기존 카드를 다시 배정한다

## 핵심 요약

- 요구사항: 상위 티켓 [20261122_2217](20261122_2217_Feature_홈피드와-배지-상세를-통합-팔레트와-새-칩-규칙으로-리뉴얼한다-상위.md) 「확정 결정 §1·§2·§5」를 홈피드 계산에 반영한다. 홈피드 15색 키(`FEED_COLORS`)를 통합 팔레트 키(노랑·초록·짙은 초록·분홍·하늘·빨강·보라·파랑·흰색)로 바꾸고, 쓰임 표(바탕·박스·값 칩·스티커), 카드 바탕+박스 조합 9개와 가중치, 짙은 초록 바탕 카드 리듬(다섯~여섯 장에 한 장, 바탕 위 글자 흰색), 배제 조합 표(대비·키즈·명도 계산 규칙 대체, 배지 그림 색 겹침 규칙은 유지)를 만든다. 저장된 카드 121장은 모두 새 규칙으로 다시 배정한다(결정 9, SQL은 파일만 쓰고 실행은 카리나).
- 하위 1번에서 넘어온 점(2026-11-23): 연한 노랑 `--jam-yellow-soft`(#FFDD73)·참조 노랑 `--feed-ref-yellow`(#F2EC6A)가 새 노랑 #F9FD69와 같은 계열이라 한 카드 안에서 구분되지 않는다. 15색 키를 통합 팔레트 키로 바꿀 때 연한 색 5개(`--jam-*-soft`)·참조 색 5개(`--feed-ref-*`) 토큰과 `globals.css`의 `--color-jam-*-soft` 매핑도 쓰는 곳이 없으면 함께 걷는다. 1번 머지 뒤 옛 색 규칙을 통과하는 조합이 74쌍에서 86쌍으로 늘었지만, 이 계산 규칙은 이 티켓에서 배제 표로 바뀌므로 따로 맞추지 않는다.
- 구현 계획: 하위 1번(색 토큰) 뒤에 한다. 규모가 커서 착수 전에 파일 단위 계획을 이 티켓에 적고 회차로 나눌지 판정한다.
- 관련 파일: `jam-web/src/lib/today/feedConstants.ts`(`FEED_COLOR_KEYS`·`FEED_COLORS`·`feedColorVar`), `jam-web/src/lib/today/feedColorRules.ts`(`COLOR_RULE_THRESHOLDS`·`firstViolatedRule`·`passesColorRules`·`summarizeColorPairs`), `jam-web/src/lib/today/feedAssign.ts`(`assignFeedColors`·`DEFAULT_FEED_PALETTE`·`FEED_FALLBACK_COLORS`), `jam-web/src/lib/today/feedLook.ts`(`resolveFeedLook`), `jam-web/src/lib/admin/feedCardServer.ts`(`completeFeedCardValues`), `jam-web/supabase/migrations/`(색 키 제약·재배정), `jam-web/src/types/database.generated.ts`.

## 완료 조건

- 홈피드가 통합 팔레트 키만 쓰고, 자동 배정이 쓰임 표·조합 9개·가중치·배제 표·짙은 초록 바탕 카드 리듬을 따른다(단위 시험).
- 짙은 초록 바탕 카드의 바탕 위 제목·설명은 흰색, 박스 위 글자는 검정이다.
- 배지 그림 색 겹침 규칙은 그대로 동작한다(컬렉션 소개는 대표 그림과 아이템 배지 4개의 색을 모두 본다).
- 재배정 SQL과 되돌림 SQL이 `jam-web/supabase/migrations/`에 있고, 드라이런 결과(바뀌는 카드 수 121)를 티켓에 적는다. 실행은 카리나가 머지 뒤에 한다.
