조사 사실:
- 저장(`today_cards`): `chips` JSONB(최대 2개, 원소 kind·text|source·slot·tilt, NULL=자동, []=칩 없음), 색 3키(`bg/box/chip_color_key`), `feed_seed`, `stamp_*`. 변환된 기존 카드는 `chips`가 모두 NULL이라 칩 글자·자리·기울기는 전부 그릴 때 계산한다. 358 재배정으로 `chip_color_key`는 모두 새 규칙(값 칩 7색, 배제 표)으로 정해져 저장돼 있어 «칩 색 무작위»는 이미 충족한다.
- 계산 흐름: `toCardView`(`cardView.ts:328`) → `resolveFeedLook`(`feedLook.ts:383`) → `draftChips`(`feedLook.ts:228`, 글자) → `assignChipPlacement`(`feedAssign.ts`, 자리·기울기 ±4/6/8) → 그리기 `FeedChipLayer`(`FeedCardParts.tsx:110`)·`chipPositionOf`(`feedChipLayout.ts:52`). 앵커는 카드가 아니라 유형별 이미지 박스·배지 칸·박스 줄이고 유형 컴포넌트가 각자 넣는다. 목록형은 흐름 줄 `ChipRow`, 컬렉션은 `positionOf` size sm 고정.
- `FeedTilt`(여섯 값)는 `FeedChip`·`ChipTitle`·`feedLook`·`feedAssign`·`FeedChipsEditor`와 DB CHECK에 걸려 있다. 3~12° 자유 각도는 저장 칸이 아니라 계산값으로만 두면 마이그레이션이 필요 없다(어드민이 저장한 6값은 3~12 안).
- 홈 카드 순서: `getTodayCards`(`cards.ts`)가 «유저 id + KST 날짜» 시드로 셔플한다. 같은 카드도 유저·날마다 이웃이 달라서 «앞 카드 배치 금지»는 배열 전체를 한 번 훑어야 지킬 수 있다. PRD §6 «무작위 값 저장·이웃 미고려»와 어긋나므로 PRD를 고친다.
- 서버는 DOM 실측을 못 한다: 카드 폭은 고정이 아니다(390 화면에서 358, 티켓의 343은 캔버스 값). 안쪽 6%·5%는 CSS `%`로 쓰고, 글자 영역은 «글자 수×글자 크기÷가로 폭»으로 추정한다. 안전 구역은 이미지 픽셀을 읽지 않고 그림 상자 가운데 비율만 피한다. 1:1은 `aspect-square`로 하고 343을 하드코딩하지 않는다.
- 칩 크기를 `FEED_CHIP`에서 바로 바꾸면 제목 속 칩(`ChipTitle`)이 같이 커져 30px 제목 줄을 깬다. 코너 칩 전용 상수를 따로 둔다.

### 결정 (2026-11-23 사용자 «추천대로»)

1. 제목 속 칩(`ChipTitle`)은 현행 크기를 유지하고 카드 모서리 칩만 새 크기(40/18·52/24, 굵기 900)로 바꾼다. 코너 칩 전용 상수를 둔다.
2. 칩 색은 저장값(`chip_color_key`, 358에서 값 칩 7색으로 이미 무작위 배정)을 그대로 쓴다. 그릴 때 다시 고르지 않는다.
3. 어드민이 직접 정한 칩 자리·기울기는 존중한다. 겹치면 자리 이동을 뺀 나머지 물러서기 단계만 적용한다.
4. 칩 없는 카드(`[]`, 배지만 등)는 건너뛰고 «앞 카드와 같은 배치»는 직전의 칩 있는 카드와 비교한다.
5. 드랍·픽업은 두 칩이 모두 분류 칩이다. 스티커는 한 카드에 한 개만, 둘째는 검정 알약으로 둔다.
6. 목록형 카드는 제목 위 흐름 줄(`ChipRow`)을 유지하고 새 크기·영어 문구만 적용한다(스티커·모서리 배치 제외).

- 홈피드 칩을 새 규칙으로 바꿨다. 카드 모서리 칩은 전용 크기(큰 칩 52/글자 24, 작은 칩 40/18, 굵기 900)와 3~12° 자유 각도·두 칩 반대 방향을 쓰고, 분류 칩은 영어 대문자(ACTIVITY·ITEM·MISSION·CHECK IN·COLLECTION·DROP·PICKUP, «배지» 제거), 값 칩은 한국어 그대로다. 제목 속 칩은 불변이다.
- 칩 배치는 저장하지 않고 그릴 때 계산한다: 유형 7개별 모서리 후보와 겹침 계산(`feedChipGeometry.ts`), 한 카드의 칩·스티커 배치와 물러서기 5단계(`feedChipPlan.ts`: 기울기 3° → 스티커 80% → 검정 알약 → 값 칩 작게 → 분류 칩 빼기), 피드 순서 규칙(`feedChipChain.ts`: 같은 값 연속 2장 한도·앞 카드와 같은 배치 금지·같은 꼴 3연속 금지·스티커 글자·색 짝), 진입점 `toCardViews`. 분류 칩의 절반 정도가 분류 스티커(조약돌·물결)로 그려진다.
- 카드 셸의 `FeedChipPlanLayer`가 계획대로 알약(`FeedChip corner`)과 스티커(`CategorySticker`)를 그린다(`pointer-events-none`). 텍스트형은 1:1, 사진 텍스트형은 흰 글자+막 32%이고 큰 제목은 카드 폭 비율(`cqw`)로 줄어든다. 목록형은 흐름 줄 `ChipRow`를 유지했다.
- 개발용 미리보기와 어드민 «홈 미리보기»가 홈과 같은 `toCardViews`를 쓰고, 개발용 미리보기 상단에 칩 배치 요약(스티커·알약 장수, 물러서기 단계별 장수, 규칙 위반 수)이 한 줄 더해졌다. 어드민 칩 편집기의 값 출처 라벨은 «분류 문구 · 값 이름»으로, 자리·기울기 도움말은 새 규칙으로 바꿨다.

### 주요 의사결정
- 사용자 결정(2026-11-23 «추천대로»): 제목 속 칩은 현행 크기 유지, 칩 색은 저장값 그대로, 어드민이 직접 정한 자리·기울기는 존중, 칩 없는 카드는 건너뜀, 드랍·픽업은 스티커 한 개+검정 알약, 목록형은 흐름 줄 유지.
- 카리나 결정: 계획 폭을 [288, 358]에서 [343]으로 줄였다(아이폰 최소 화면 375의 카드 폭. 구형 320 화면은 칩이 줄지 않는다). 폭 288까지 맞추면 드랍·픽업 2칩 카드의 약 2/3가 둘째 칩을 잃었다.
- 텍스트형 큰 제목 글자 크기를 px 대신 카드 폭 비율(`cqw`, 카드가 `@container`)로 정했다(폭 288에서 5자×4줄 제목이 박스 밖으로 잘렸다).
- R7 판정 FAIL(개발용 미리보기 자동 배정 120장 구간의 규칙 위반 29건)은 요청문의 «위반 0» 조건이 과했기 때문이다. 이 구간은 유형 8개를 고정 순환으로 돌려 컬렉션 소개·드랍픽업이 번갈아 나오고, 두 유형이 둘째 분류 칩을 잃어 알약 하나만 남는 것이 위반의 원인이다. 티켓 완료 조건(연속 2장 한도·앞 카드 배치 금지의 단위 시험 고정)은 R5 시험이 충족한다. 위반 수는 요약 줄에 그대로 보이게 두고 7번 티켓에서 다시 본다.
- 어드민 카드 미리보기 시험이 스티커 SVG의 `<textPath href="#…">`를 링크로, 칩의 `rotate() scale()`을 미리보기 축소로 오인해 실패해 단언을 좁혔다(전체 검사에서 발견).

### 잔여 이슈
- 드랍·픽업: 배지 세 칸이 위쪽 모서리를 채워 둘째 분류 칩이 항상 빠진다. 7번 티켓(«흩뿌린 배지»)에서 배지 배치를 바꾼 뒤 다시 본다. 컬렉션 소개도 분류 칩(COLLECTION)이 빠지는 카드가 많다.
- 히어로의 스티커가 사진 박스 가장자리에 걸칠 수 있다(사진 가운데를 피하지 않는다).
- 폭 320 이하에서 칩 고정 크기가 글자와 닿을 수 있고, 카드에 `overflow-hidden`이 없어 칩이 바깥 6px까지 나가므로 카드 간격이 6px보다 좁으면 이웃과 닿는다.
- 같은 분류 문구 3연속은 후보로 고칠 수 없어 위반으로 남는다. 실제 홈 피드 데이터로 빈도를 본다.
- staging push 뒤 실기기에서 칩·스티커 배치를 확인하고 사용자 확인을 받아 닫는다.
