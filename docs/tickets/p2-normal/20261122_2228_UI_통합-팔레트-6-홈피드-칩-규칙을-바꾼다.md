# [UI] 통합 팔레트 6: 홈피드 칩 규칙(크기·문구·자리·각도·무작위·가리지 않기)과 텍스트형 1:1을 바꾼다

## 핵심 요약

- 요구사항: 상위 티켓 [20261122_2217](20261122_2217_Feature_홈피드와-배지-상세를-통합-팔레트와-새-칩-규칙으로-리뉴얼한다-상위.md) 「확정 결정 §3·§4 적용·§6·§7」. 칩 크기(40/18·52/24, 굵기 900, 테두리 2px), 문구(분류 영어 대문자·«배지» 제거, 값 한국어), 모서리 자리(안쪽 가로 6%·세로 5%, 바깥 최대 6px), 두 칩 같은 줄 금지, 각도 3~12°·반대 방향, 각자 무작위+같은 값 연속 2장 한도, 앞 카드와 같은 배치 금지, 분류 칩 절반 정도를 스티커로(5번 부품), 값 칩 알약만, 분류 알약 검정, 가리지 않기(안전 구역 방식)와 물러서기 순서(기울기 3°→스티커 80%→검정 알약 분류 칩→값 칩 작게→분류 빼기), 텍스트형 1:1, 사진 텍스트형 흰 글자+어둠 막 32%, 컬렉션 소개는 퍼진 배지 자리를 피할 영역에 넣는다.
- 구현 계획: 5번과 2번 뒤에 한다. 피드 순서(앞 카드)를 알아야 하므로 배치는 그리는 시점에 정한다. 규모가 커서 회차로 나눈다.
- 관련 파일: `jam-web/src/lib/today/feedChipLayout.ts`(`chipPositionOf` 52줄), `jam-web/src/lib/today/feedChipSlots.ts`, `jam-web/src/lib/today/feedConstants.ts`(`FEED_CHIP`·`FEED_TILTS`), `jam-web/src/lib/today/cardView.ts`(분류 문구 275줄 근처), `jam-web/src/components/today/feed/FeedCardParts.tsx`, 유형별 부품, 개발용 미리보기 `jam-web/src/app/(main)/dev-sample/home-feed-cards/new/page.tsx`.

## 회차 분할안 (초안, 2026-11-23 계획 에이전트 조사 + 카리나 정리, 사용자 결정 대기)

조사 사실:
- 저장(`today_cards`): `chips` JSONB(최대 2개, 원소 kind·text|source·slot·tilt, NULL=자동, []=칩 없음), 색 3키(`bg/box/chip_color_key`), `feed_seed`, `stamp_*`. 변환된 기존 카드는 `chips`가 모두 NULL이라 칩 글자·자리·기울기는 전부 그릴 때 계산한다. 358 재배정으로 `chip_color_key`는 모두 새 규칙(값 칩 7색, 배제 표)으로 정해져 저장돼 있어 «칩 색 무작위»는 이미 충족한다.
- 계산 흐름: `toCardView`(`cardView.ts:328`) → `resolveFeedLook`(`feedLook.ts:383`) → `draftChips`(`feedLook.ts:228`, 글자) → `assignChipPlacement`(`feedAssign.ts`, 자리·기울기 ±4/6/8) → 그리기 `FeedChipLayer`(`FeedCardParts.tsx:110`)·`chipPositionOf`(`feedChipLayout.ts:52`). 앵커는 카드가 아니라 유형별 이미지 박스·배지 칸·박스 줄이고 유형 컴포넌트가 각자 넣는다. 목록형은 흐름 줄 `ChipRow`, 컬렉션은 `positionOf` size sm 고정.
- `FeedTilt`(여섯 값)는 `FeedChip`·`ChipTitle`·`feedLook`·`feedAssign`·`FeedChipsEditor`와 DB CHECK에 걸려 있다. 3~12° 자유 각도는 저장 칸이 아니라 계산값으로만 두면 마이그레이션이 필요 없다(어드민이 저장한 6값은 3~12 안).
- 홈 카드 순서: `getTodayCards`(`cards.ts`)가 «유저 id + KST 날짜» 시드로 셔플한다. 같은 카드도 유저·날마다 이웃이 달라서 «앞 카드 배치 금지»는 배열 전체를 한 번 훑어야 지킬 수 있다. PRD §6 «무작위 값 저장·이웃 미고려»와 어긋나므로 PRD를 고친다.
- 서버는 DOM 실측을 못 한다: 카드 폭은 고정이 아니다(390 화면에서 358, 티켓의 343은 캔버스 값). 안쪽 6%·5%는 CSS `%`로 쓰고, 글자 영역은 «글자 수×글자 크기÷가로 폭»으로 추정한다. 안전 구역은 이미지 픽셀을 읽지 않고 그림 상자 가운데 비율만 피한다. 1:1은 `aspect-square`로 하고 343을 하드코딩하지 않는다.
- 칩 크기를 `FEED_CHIP`에서 바로 바꾸면 제목 속 칩(`ChipTitle`)이 같이 커져 30px 제목 줄을 깬다. 코너 칩 전용 상수를 따로 둔다.

### 결정 (2026-11-23 사용자 «추천대로»)

1. 제목 속 칩(`ChipTitle`)은 현행 크기를 유지하고 카드 모서리 칩만 새 크기(40/18·52/24, 굵기 900)로 바꾼다. 코너 칩 전용 상수를 둔다.
2. 칩 색은 저장값(`chip_color_key`, 358에서 값 칩 7색으로 이미 무작위 배정)을 그대로 쓴다. 그릴 때 다시 고르지 않는다.
3. 어드민이 직접 정한 칩 자리·기울기는 존중한다. 겹치면 자리 이동을 뺀 나머지 물러서기 단계만 적용한다.
4. 칩 없는 카드(`[]`, 배지만 등)는 건너뛰고 «앞 카드와 같은 배치»는 직전의 칩 있는 카드와 비교한다.
5. 드랍·픽업은 두 칩이 모두 분류 칩이다. 스티커는 한 카드에 한 개만, 둘째는 검정 알약으로 둔다.
6. 목록형 카드는 제목 위 흐름 줄(`ChipRow`)을 유지하고 새 크기·영어 문구만 적용한다(스티커·모서리 배치 제외).
