# [UI] 통합 팔레트 7: 드랍·픽업 카드를 «흩뿌린 배지» 디자인으로 바꾼다

- 요구사항: 상위 티켓 [20261122_2217](20261122_2217_Feature_홈피드와-배지-상세를-통합-팔레트와-새-칩-규칙으로-리뉴얼한다-상위.md) 「확정 결정 §7」. 드랍·픽업 카드에서 박스 3칸을 없애고, 아이템 배지를 크게 겹치고 기울여 흩뿌린다. 배지 수(1~5개)마다 배치 틀을 미리 정하고(캔버스 Drop-A5), 지금의 «앞 3개» 대신 5개까지 그린다. DROP·PICKUP 칩은 둘 다 분류 칩으로 6번 티켓 규칙을 따른다.

## 구현 계획

1. **카드 모양**: 박스(`FeedBox`) 3칸을 걷는다. 카드 바탕색 위에 아이템 배지 그림을 직접 놓는다. 위쪽 «배지 영역» 안에서 배지를 크게 겹치고 기울여 흩뿌리고, 그 아래에 제목·설명을 지금처럼 둔다. 배지 영역 높이는 배지 수에 따라 시안대로 다르게 잡는다(1개는 한 장이 크게, 5개는 작게 흩어지는 식).
2. **배지 수별 배치 틀(1~5개)**: 배치 틀은 코드에 고정 표로 둔다(`FEED_DROP_PICKUP_FRAMES` 같은 이름은 채원①이 정한다). 배지마다 중심 위치(영역 폭·높이 대비 %), 한 변 크기(px), 기울기(도), 앞뒤 순서(z)를 정한다. 값은 `board-a5.jpg`를 기준으로 채원①이 판정에 적는다. 무작위가 아니라 **배지 수가 틀을 정한다**(같은 카드는 늘 같은 모양). 틀 안의 배지 순서는 카드에 걸린 배지 순서를 따른다.
3. **6개 이상**: 앞 5개만 그린다. `FEED_ITEM_BADGE_LIMIT`을 3에서 5로 바꾸고, `cardView.ts`의 `itemBadges`·`feedImageColors.ts`의 색 추출도 5개까지 읽는다.
4. **이미지 없는 배지**: 지금처럼 이름 글자로 대신하되, 배지 그림 크기와 기울기를 같은 틀에 맞춘다.
5. **칩**: DROP·PICKUP은 둘 다 분류 칩이고 6번 규칙(자리·기울기·스티커·알약·물러서기 순서)을 그대로 쓴다. 칩 계획의 «피할 영역»은 틀의 배지 그림 상자(가운데 안전 구역)와 제목·설명 글자로 바꾼다. 시안처럼 배지를 비워 둔 모서리와 제목 옆에 칩이 놓이고, 둘째 칩이 6번 뒤에도 항상 빠지던 문제(배지 3칸이 위 모서리를 채움)가 풀려야 한다.
6. **색**: 박스가 없으므로 카드의 박스 색 칸은 이 유형에서 쓰지 않는다. 바탕색은 통합 팔레트 바탕 규칙(`FEED_COLOR_USAGE`·바탕+박스 조합·짙은 초록 리듬)을 그대로 따른다. 박스를 요구하는 조합 규칙이 이 유형에서 걸림돌이 되면 채원①이 판정에 적는다(바탕만 보는 쪽으로 푼다).
7. **어드민·미리보기**: 어드민 «홈 미리보기»와 개발용 미리보기(`dev-sample/home-feed-cards/new`)는 같은 카드 컴포넌트와 같은 칩 계산을 쓰므로 따로 고치지 않는다. 드랍·픽업 견본이 배지 1~5개로 나오도록 견본 데이터만 맞춘다.
8. **문서**: PRD `home-feed/PRD.md`의 드랍·픽업 설명(앞 3개·박스 3칸)을 새 규칙으로 고친다. 정책 수치는 아니므로 `policiesData.ts`는 해당 항목이 있을 때만 맞춘다. `node scripts/gen-home-feed-doc.mjs`로 생성 표를 다시 만든다.

### 구현 내용 요약
- 드랍·픽업 카드에서 박스 3칸을 걷고, 아이템 배지 1~5개를 배지 수별 고정 틀(`FEED_DROP_PICKUP_FRAMES`)로 겹치고 기울여 바탕색 위에 직접 놓는다. 같은 배지 수는 늘 같은 모양이고, 6개 이상이면 앞 5개만 그린다(한도 원천은 `FEED_DROP_PICKUP.max`).
- 배지 영역은 기준 폭 326×248을 폭에 비례해 줄이고(`dropPickupAreaHeightOf`), 카드 최소 높이는 시안의 다섯 장이 모두 같은 높이라 360에서 400으로 올렸다. 그림 없는 배지는 같은 상자에서 이름 글자(`feedTextOnBg`)로 대신한다. 박스가 사라져 `BOX_FEED_TYPES`에서 이 유형을 뺐다(어드민 박스 칸이 숨는다).
- 칩: DROP·PICKUP은 분류 칩이고 6번 규칙을 따른다. 피할 영역은 배지마다 기울인 상자의 가운데 50%와 제목·설명 글자(따로)다. 드랍·픽업에만 «제목 옆 가장자리» 후보(`TITLE_EDGE`: 칩 가운데가 카드 높이의 62~78%, 오른쪽 가장자리, 바깥 6px 이하)를 더해 두 칩이 시안처럼 함께 놓이게 했다.
- 보정(카리나, 실화면 확인 뒤): 글자 길이 추정이 공백도 한 글자로 세어 제목 줄 폭이 25~35% 넓게 나와(폭 343에서 «내겐 남는 것이» 추정 235px, 실측 175px) 후보가 닫혔다. 드랍·픽업 제목 줄 폭에만 `TITLE_WIDTH_CORRECTION` 0.8을 곱한다.

### 주요 의사결정
- 영역 높이는 배지 수와 상관없이 하나로 두고, 1개는 크게 5개는 작게 하는 차이를 배지 크기로 풀었다(시안의 다섯 장이 같은 높이). 카드 최소 높이 400은 시안을 읽은 값이다.
- 둘째 칩 자리: 틀의 배지 위치를 옮기지 않고 칩 후보를 더하는 쪽으로 풀었다(배지 위치는 사용자가 확정한 시안이라 마지막 수단으로 남겼다).
- 제목 폭 보정은 다른 유형의 칩 계획이 바뀌지 않게 드랍·픽업에만 적용했다(시험이 변경 전 서명 4,320개 입력과 대조).
- 채원① 사전 판정 1회, 재작업은 가벼운 경로(아현·민지만)로 돌렸다. 채원 사후 리뷰는 첫 실행에서 중대 문제 없음.

### 잔여 이슈
- 제목 줄이 길면(추정 약 9자 이상) 배지 3개 이상 카드에서 둘째 칩이 빠질 수 있다(PRD 「알려진 한계」).
- 보정 계수 0.8은 공백이 줄마다 1~2개인 제목 기준의 평균값이다. 공백 없는 긴 낱말 제목은 칩이 제목에 닿을 수 있어 실제 글꼴로 확인이 필요하다.
- 개발 미리보기의 «박스 5종» 줄에 드랍·픽업 행이 남아 있다(박스 모양은 보이지 않는다, 시험이 고정). `box-row-*` 자리 이름 정리도 이번에는 하지 않았다.
- 견본 배지 그림(s001 등)이 가로로 길어 시안의 그림보다 작아 보인다. 실제 아이템 배지 그림의 비율은 확인하지 못했다.
- 아현·민지 push는 분류기가 거부해 review 브랜치는 로컬에만 있다(2026-11-10 지시와 일치). CI 기록은 없고 로컬 전체 검사로 대신했다.
