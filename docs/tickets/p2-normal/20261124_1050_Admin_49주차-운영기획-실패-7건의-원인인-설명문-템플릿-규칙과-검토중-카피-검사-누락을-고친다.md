# [Admin] 49주차 운영기획 실패 7건의 원인인 설명문 템플릿 규칙과 검토중 카피 검사 누락을 고친다

## 핵심 요약

- 요구사항: 49주차(11/30~12/6) 운영 묶음 `weekly-2026-W48-0901`을 2026-11-24 10:40(KST)에 승인하고 예약했더니 12개 중 7개가 「실패」로 닫혔다. 원인 두 가지를 코드에서 고치고, 실패한 7개를 같은 주차의 새 묶음으로 다시 올린다.
- 구현 계획: ① 운영 묶음 예약 등록 변환이 설명문을 템플릿 목록(`badge_spotlight`·`content_intro`)으로 거절하지 않게 한다. 홈은 설명 문단을 카드 유형(`feed_type`)·`show_description`으로 그린다. ② 검토중 항목을 직접 고칠 때도 고친 문안 칸에 카피 규칙 검사를 건다(지금은 예약됨 문안 수정에만 건다).
- 관련 파일: `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts`(`validateCard`, 옵션 `feedTypeDecidesDescription`, 템플릿 규칙 반복문 ~283줄), `jam-web/src/lib/admin/opsInbox/registerInput.ts`(`toTodayCardRegisterInput`의 `validateCard` 호출 ~434줄), `jam-web/src/lib/admin/opsInbox/decide.ts`(`copyRuleErrors` ~669줄, `editItem`의 호출 ~841줄), 시험 `__tests__/registerInput.test.ts`·`__tests__/decide.test.ts`.

## 배경 / 문제 정의

결정 기록(`ops_decisions`의 `fail` 행)에 남은 실패 사유는 세 갈래다.

| 항목 | 실패 사유 |
|---|---|
| `c-mission-walk`·`c-mission-act`·`c-mission-hike`(미션 소개 카드 3장) | `card.description: mission_spotlight 템플릿은 이 필드를 쓰지 않아요(홈은 badge_spotlight·content_intro에서만 설명 문단을 그려요)` |
| `m-walk-45`·`m-act-3`·`m-hike-300`(미션 3개) | 연결된 카드가 실패해 함께 실패(「연결된 항목을 만들지 못해 함께 실패했어요」) |
| `c-lock-open` | 검토중에 고친 제목 「잠긴 배지를 열어보세요」가 권유 자리의 「~하세요」 금지 규칙에 걸림 |

- **설명문 규칙이 낡았다.** 티켓 20261122_1101이 서비스 홈의 옛 7모양 카드를 지우면서 `toCardView`의 설명 판정이 `showsDescription(template)`에서 카드 유형 기준(`feedLook.ts`의 `DESCRIPTION_DEFAULT`, 히어로는 보임)으로 바뀌었다. 등록 검사(`validateCard`)는 옛 템플릿 목록으로 설명문을 계속 거절했다. 그래서 홈이 실제로 그리는 히어로 유형 미션 소개 카드의 설명문이 예약 등록 때 거절됐다. 홈피드 PRD 「카드 유형 8가지」 표(2026-11-20 사용자 확정)도 히어로의 설명 문장을 «보임»으로 정한다.
- **검토중 수정에 카피 규칙 검사가 없었다.** `editItem`은 예약됨 문안 수정(티켓 20261103_1446)에만 예약 등록 변환을 다시 돌려 카피 규칙을 걸었다. 검토중 수정은 제출 형식 검사(`revalidateOpsItem`)만 돌아서 「~하세요」 제목이 저장됐고, 실행 때 처음 걸렸다.
- 실패는 끝 상태라 같은 항목을 다시 예약할 길이 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 운영 묶음 경로(`toTodayCardRegisterInput`)는 `validateCard`에 `feedTypeDecidesDescription: true`를 넘기고, 이때 템플릿 규칙 반복문은 `description`을 건너뛴다. 다른 칸의 템플릿 규칙(`recipe_id` 등)은 그대로다.
- 카드 유형이 없는 CLI 등록 묶음(`jam-web/scripts/asset-generator/registerHomeFeedBundle.mjs`)은 옵션을 넘기지 않아 옛 규칙 그대로다.
- `editItem`은 종류가 홈피드 카드·미션이면 상태와 관계없이 `copyRuleErrors`를 돌린다. 오류는 고친 `copy.<키>` 칸만 본다(예약됨 수정은 원래 문안 칸만 고칠 수 있어 동작이 같다).

### 컨텐츠 관점
- 실패한 7개는 새 묶음 `weekly-2026-W49-retry-01`(제목 「12월 첫 주 걷기: 실패 7개 다시 올림」, 작성자 카리나)로 다시 제출한다. 사용자가 검토중에 고친 제목 7개는 그대로 싣고, `c-lock-open` 제목만 규칙에 맞게 「잠긴 배지를 열어 봐요」로 바꾼다. 원래 묶음의 실패 기록은 그대로 둔다.
