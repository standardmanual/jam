# [Admin] 어드민 홈피드 카드 폼의 설명문 칸을 템플릿 대신 카드 유형 기준으로 연다

## 핵심 요약

- 요구사항: 어드민 홈피드 카드 작성·수정 폼과 조회 화면은 설명문 칸을 템플릿(`badge_spotlight`·`content_intro`)일 때만 연다. 홈은 티켓 20261122_1101부터 설명 문단을 카드 유형(`feed_type`)과 `show_description`으로 그린다. 폼·조회 화면이 홈과 같은 판정으로 칸을 열고, 도움말 문구가 홈의 실제 동작과 같게 한다.
- 구현 계획: 홈의 기준 표(`feedLook.ts`의 `DESCRIPTION_DEFAULT`) 옆에 판정 함수 `feedTypeShowsDescription`을 하나 두고, 폼의 설명문 칸·「카드 모양」 섹션의 설명 노출 칸·조회 화면의 설명문 행이 모두 그 함수를 쓴다. 템플릿 표(`TODAY_FIELDS_FOR`)에서 `description` 플래그를 지우고, 카드 유형이 없는 CLI 등록 묶음의 옛 거절 규칙은 `showsDescription`을 직접 불러 동작을 그대로 둔다. 자세한 지도는 아래 「구현 계획」.
- 관련 파일: `jam-web/src/lib/today/feedLook.ts`(`DESCRIPTION_DEFAULT` ~94줄), `jam-web/src/app/admin/today/FeedCardSection.tsx`(`feedFieldVisibility` ~96줄), `jam-web/src/app/admin/today/TodayCardForm.tsx`(설명문 칸 541~558줄), `jam-web/src/components/admin/today/TodayCardDetail.tsx`(설명문 행 178~183줄), `jam-web/src/lib/admin/today-sections.ts`(`TodayCardFormValues.description` 주석 ~22줄, `TODAY_DESCRIPTION_MAX_LENGTH` 주석 ~103줄, `TodayTemplateFields`·`TODAY_FIELDS_FOR` 110~147줄), `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts`(`TEMPLATE_FIELD_KEY` ~80줄, `validateCard`의 설명문 주석 ~221줄과 템플릿 규칙 반복문 ~280줄), `jam-web/src/lib/today/shape.ts`(`DESCRIPTION_TEMPLATES`·`showsDescription` 머리 주석 11~14줄), `scripts/gen-home-feed-doc.mjs`(`FIELD_LABELS` ~92줄), 시험 `jam-web/src/lib/admin/__tests__/today-sections.test.ts`(~139줄)·`jam-web/src/app/admin/today/__tests__/TodayCardForm.description.test.tsx`(전체)·`jam-web/src/lib/today/__tests__/feedLook.test.ts`. 문서 `docs/service/prd/home-feed/PRD.md`(~279줄과 생성 구간), `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md`(~147줄).

## 배경 / 문제 정의

- 2026-11-24 49주차 운영 묶음에서 히어로 유형 미션 소개 카드 3장이 예약 등록 때 «mission_spotlight 템플릿은 설명문을 쓰지 않아요»로 실패했다. 원인은 티켓 20261122_1101이 홈의 설명 판정을 템플릿에서 카드 유형으로 옮기면서 등록 검사를 그대로 둔 것이다. 티켓 20261124_1050이 운영 묶음 등록 검사만 고쳤고(`validateCard`의 `feedTypeDecidesDescription`), 어드민 폼은 범위 밖이라 남았다.
- 지금 홈의 판정(`cardView.ts` `toCardView` → `feedLook.ts` 466줄): 그려지는 유형이 설명을 보이는 유형(`DESCRIPTION_DEFAULT`가 참)이고 `show_description`이 거짓이 아닐 때만 설명 문단을 그린다. 유형이 비었거나 모르는 값이거나 그릴 값이 없으면 `resolveFeedType`이 텍스트 박스로 보내고, 텍스트 박스는 설명을 숨긴다.
- 지금 폼의 판정: `TodayCardForm.tsx`가 `todayTemplateFields(templateType).description`으로 칸을 열어 배지 소개·컨텐츠 소개 템플릿에서만 칸이 보인다. 그래서 히어로 유형 미션 소개 카드는 홈에 설명이 보이는데도 폼에서 설명을 적을 칸이 없고, 텍스트 유형 배지 소개 카드는 홈에 설명이 안 보이는데도 칸이 열린다. 도움말 「배지 소개·컨텐츠 소개 카드에서만 홈에 보여요」도 사실과 다르다.
- 기준 표는 홈피드 PRD «카드 유형 8가지»(2026-11-20 사용자 확정)다: 히어로·배지 소개·컬렉션 소개·드랍·픽업·목록형은 보임, 전체 배경 이미지·배지만·텍스트는 숨김.

## 상세 요구사항

### 서비스/코드베이스 관점
- 판정은 한 함수다. 폼 설명문 칸, 「카드 모양」의 「설명 문장 노출」 칸, 조회 화면 설명문 행이 같은 함수를 쓴다.
- 칸이 닫혀도 적어 둔 설명문은 저장할 때 지우지 않는다(티켓 20261109_1519 규칙 유지). `buildTodayCardSavePayload`는 지금처럼 설명문을 그대로 싣는다.
- 홈의 그리기 동작은 바꾸지 않는다(`feedLook.ts` 466줄, `cardView.ts`는 수정 대상이 아니다).
- `today-sections.ts`는 `scripts/gen-home-feed-doc.mjs`가 Node로 직접 읽어 `import type`만 쓸 수 있다. 이 파일에는 값 가져오기를 더하지 않는다(주석만 고친다).
- 운영 묶음 등록 변환(`feedTypeDecidesDescription: true`)과 CLI 등록 묶음(옵션 없음)의 검사 결과는 지금과 같다. CLI 거절 문장도 글자 그대로 둔다(`registerHomeFeedBundle.test.ts`·`registerHomeFeedFlow.test.ts`가 그대로 통과해야 한다).

### UI/UX 관점
- 설명문 칸은 지금 자리(「기본 정보」 섹션의 부제 아래)에 그대로 두고, 「카드 모양」의 유형을 바꾸면 즉시 열리거나 닫힌다.
- 도움말 두 번째 줄은 아래 문장으로 바꾼다. 숨김 유형 이름은 코드에서 `DESCRIPTION_DEFAULT`가 거짓인 유형을 `FEED_TYPES` 순서대로 골라 `FEED_TYPE_LABELS`로 이어 만든다(손으로 적지 않는다. 지금 값이면 «전체 배경 이미지·배지만·텍스트»).
  - 「홈에 보일지는 카드 모양이 정해요. 전체 배경 이미지·배지만·텍스트 유형으로 바꾸면 이 칸이 숨겨지고 적은 문구는 지우지 않아요. 「설명 문장 노출」이 「숨김」이거나 카드가 텍스트 박스로 보이면 홈에 나오지 않아요.」
- 글자 수 표시 줄(`n/60`)은 그대로다.

## 구현 계획

1. `jam-web/src/lib/today/feedLook.ts` — `DESCRIPTION_DEFAULT` 바로 아래에 순수 함수를 더한다.
   ```ts
   /** 이 유형의 카드가 설명 문단을 그릴 수 있는지(`DESCRIPTION_DEFAULT`). 유형이 비었거나 모르는 값이면 홈은 텍스트 박스로 그려 설명을 숨기므로 거짓이다. 어드민 폼·조회 화면이 설명문 칸을 여는 판정이다(티켓 20261124_1119). */
   export function feedTypeShowsDescription(feedType: unknown): boolean
   ```
   본문은 `isFeedType(feedType) && DESCRIPTION_DEFAULT[feedType]`이다(`isFeedType`은 이미 가져와 있다). `DESCRIPTION_DEFAULT` 머리 주석의 «어드민 「카드 모양」 칸이 읽는다»는 «어드민은 `feedTypeShowsDescription`으로 읽는다»로 고친다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 어드민 카드 폼에서 「카드 모양」의 유형이 히어로·배지 소개·컬렉션 소개·드랍·픽업·목록형이면 설명문 칸이 열리고, 텍스트·배지만·전체 배경 이미지면 닫힌다. 템플릿은 판정에 쓰이지 않는다(`TodayCardForm.description.test.tsx`).
- 칸이 닫혀도 저장 페이로드의 `description`은 입력값 그대로다(`today-sections.test.ts`의 기존 페이로드 시험이 그대로 통과).
- 「카드 모양」의 「설명 문장 노출」 칸이 비활성인 유형과 설명문 칸이 닫히는 유형이 같다(둘 다 `feedTypeShowsDescription`을 부른다).
