# [Admin] 운영 묶음 이미지 색이 공개 순서로 이웃한 항목끼리 겹치지 않게 한다

## 핵심 요약

- 요구사항: 시스템이 배정한 이미지 색(티켓 20261124_1052)이 한 묶음 전체의 계열 분포는 맞췄지만, 공개 순서로 이웃한 두 항목이 같은 색 계열을 쓰는 경우를 막지 않는다. 49주차 재배정 결과에서 산 300m 미션과 세 번 활동 미션이 둘 다 분홍을 끝색으로 써서 연달아 나온다. 사용자 요청(2026-11-24): «동일한 컬러가 연속으로 나오지 않도록 변경해야 해».
- 구현 계획: `assignImageColors`가 항목 ID 순이 아니라 **공개 순서**(`starts_at` 오름차순, 같으면 `position`)로 하나씩 정하고, 바로 앞 항목과 계열이 하나도 겹치지 않는 쌍만 후보로 삼는다. 그 안에서 기존 순서(쌍 한 바퀴 → 계열 최댓값 → 제곱합 → 시드)로 고른다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/imageColorAssign.ts`(`assignImageColors`·`applyImageColors`), `jam-web/src/lib/admin/opsInbox/__tests__/imageColorAssign.test.ts`, `docs/service/prd/ops-tool/PRD.md` §8.9.

## 배경 / 문제 정의

- 49주차 6건을 한 묶음처럼 재배정한 결과를 공개 순서(`starts_at`, `position`)로 늘어놓으면 다음과 같다.

| 순서 | 항목 | 시작색 → 끝색 |
|---|---|---|
| 1 | c-drops-near (11/30) | 초록 → 노랑 |
| 2 | m-walk-45 (11/30) | 하늘 → 보라 |
| 3 | m-act-3 (11/30) | 빨강 → 분홍 |
| 4 | m-hike-300 (11/30) | 노랑 → 분홍 |
| 5 | c-pickup-walk (12/2) | 짙은 초록 → 하늘 |
| 6 | c-lock-open (12/3) | 빨강 → 보라 |

- 3번과 4번이 분홍을 끝색으로 같이 쓴다. 현재 배정은 항목 ID 순으로 정하고 이웃을 보지 않아서, 계열 분포(2칸씩)는 맞아도 이웃 겹침은 막지 못한다.
- 원인은 `assignImageColors`가 입력 순서를 버리고 ID로 다시 정렬하는 설계이고(순서를 바꿔도 같은 결과를 내려는 의도였다), 호출부 `applyImageColors`가 `starts_at`을 넘기지 않는 데 있다.

## 상세 요구사항

1. **이웃 규칙.** 대상 항목을 공개 순서(`starts_at` 오름차순, `null`은 맨 뒤, 같으면 `position`, 그래도 같으면 항목 ID)로 늘어놓았을 때, 이웃한 두 항목은 **색 계열을 하나도 공유하지 않는다**(시작색·끝색 네 칸 모두 서로 다른 계열). 계열은 기존 `COLOR_FAMILY_OF` 기준(초록·짙은 초록은 초록, 하늘·파랑은 파랑)이다. 같은 색뿐 아니라 같은 계열도 막는다.
2. **우선순위.** 이웃 규칙은 필수 조건이고, 후보에서 먼저 거른다. 그 안에서 기존 순서를 그대로 쓴다: 가장 적게 쓴 쌍 → 계열 칸 수 최댓값이 낮은 쌍 → 제곱합이 낮은 쌍 → 항목 ID 시드. 단 «가장 적게 쓴 쌍»은 이웃 규칙을 통과한 후보 안에서만 센다.
3. **쏠림 한도는 유지한다.** 대상이 4개 이상인 묶음에서 한 계열은 색 칸의 25%(올림)를 넘지 않는다. 기존 시험(4~24개)이 이웃 규칙을 더한 뒤에도 통과해야 한다. 통과하지 못하면 우선순위를 조정하되(예: 쏠림 한도를 쌍 한 바퀴보다 앞에 둠) 이웃 규칙은 포기하지 않는다.
4. **막다른 길이 없다.** 쌍 표 11개 모두에 대해, 그 쌍과 계열이 겹치지 않는 쌍이 하나 이상 있다(시험으로 확인). 그래서 앞에서부터 하나씩 정하는 방식이 중간에 막히지 않는다. 그래도 후보가 비는 입력이 생기면 겹침이 가장 적은 쌍을 고른다(던지지 않는다).
5. **결정성.** 같은 묶음(같은 항목, 같은 공개 순서)은 언제나 같은 결과다. 난수·현재 시각은 쓰지 않는다. 항목 순서를 바꿔도 같은 결과여야 한다는 옛 조건은 **폐기한다**(공개 순서가 결과를 정하는 것이 이 티켓의 뜻이다).
6. **함수 모양.** `assignImageColors(sequence)`는 이미 공개 순서로 늘어놓은 항목 ID 배열을 받아 같은 순서의 결과 배열을 돌려준다(내부 재정렬을 하지 않는다). 공개 순서로 정렬하는 일은 `applyImageColors`가 한다. `ColorAssignableItem`에 `starts_at: string | null`을 더한다(`route.ts`가 이미 `item.starts_at`을 쓰므로 넘기는 값이 있다). `starts_at`이 날짜로 읽히지 않으면 `null`로 본다.
7. **범위 밖.** 이미 저장된 다른 묶음과의 이웃(예: 월요일 묶음의 마지막 항목과 다음 묶음의 첫 항목)은 보지 않는다. 한 묶음 안에서만 지킨다. 이미 만든 49주차 이미지는 이 티켓이 아니라 카리나가 머지 뒤에 새 규칙으로 다시 배정한다(후속 범위).

## 구현 계획

1. `jam-web/src/lib/admin/opsInbox/imageColorAssign.ts`
   - `assignImageColors(ids)`: 첫 줄의 정렬(`order`)을 없애고 입력 순서대로 돈다. 직전 항목의 계열 집합을 들고 다니며, `IMAGE_COLOR_PAIRS` 중 `COLOR_FAMILY_OF[pair.bg]`·`COLOR_FAMILY_OF[pair.end]`가 직전 계열 집합과 겹치지 않는 쌍만 `allowed`로 둔다. `minUse`는 `allowed` 안에서 구하고, 이후 점수·시드 비교는 그대로다. `allowed`가 비면 직전과 겹치는 계열 수가 가장 적은 쌍들을 `allowed`로 삼는다.
   - `applyImageColors(items)`: `targets`를 `starts_at`(없으면 맨 뒤)·`position`·`idOf` 순으로 정렬한 배열을 만들어 `assignImageColors`에 넘기고, 결과를 같은 순서로 항목에 되돌려 쓴다. `ColorAssignableItem`에 `starts_at`을 더한다.
   - 머리 주석과 함수 주석에서 «항목 ID 순», «순서를 바꿔도 같은 쌍» 서술을 새 규칙으로 고친다.
2. `jam-web/src/lib/admin/opsInbox/__tests__/imageColorAssign.test.ts`
   - 49주차 6건(위 표의 순서와 `starts_at`)을 `applyImageColors`에 넣어 이웃 항목이 계열을 공유하지 않고 한 계열이 3칸을 넘지 않음을 확인한다.
   - 4~24개 묶음에서 이웃이 계열을 공유하지 않음과 쏠림 한도를 함께 확인한다(기존 시험에 이웃 조건 추가).
   - 쌍 표 11개 모두에 겹치지 않는 쌍이 있음(막다른 길 없음)을 확인한다.
   - `starts_at`이 같은 항목은 `position` 순, `starts_at`이 없는 항목은 맨 뒤, 같은 입력은 같은 결과임을 확인한다. «순서를 섞어도 같은 쌍» 시험은 «공개 순서가 같으면 같은 결과»로 고친다.
   - 기존 `applyImageColors` 시험의 항목 객체에 `starts_at`을 채운다.
3. `docs/service/prd/ops-tool/PRD.md` §8.9의 「균형 배정」 항목: ID 순 서술을 공개 순서와 이웃 규칙으로 고치고, «항목 순서를 바꿔도 같은 쌍» 문장을 지운다. 「쏠림 한도」 항목 뒤에 이웃 규칙 항목을 더한다.
4. `route.ts`는 고치지 않는다(`applyImageColors(items)`에 이미 `starts_at`이 든 항목을 넘긴다. 시험으로 확인).

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 공개 순서로 이웃한 대상 항목 두 개가 색 계열을 공유하지 않는다. 시험이 49주차 6건과 4~24개 여러 묶음으로 확인한다.
- 대상 4개 이상인 묶음에서 한 계열이 색 칸의 25%(올림)를 넘지 않는다(기존 시험 유지). 49주차 6건은 한 계열 3칸 이하다.
- 쌍 표 11개 모두에 계열이 겹치지 않는 쌍이 있음을 시험이 확인한다.
- `assignImageColors`는 입력 순서를 바꾸지 않고(내부 재정렬 없음), `applyImageColors`가 `starts_at`·`position`·항목 ID 순으로 정렬해 넘긴다. 같은 입력은 같은 결과다.
- `starts_at`이 같은 항목은 `position` 순이고, `starts_at`이 없는 항목은 맨 뒤다.
- PRD §8.9가 코드와 같은 규칙을 적는다. `bash scripts/verify.sh`가 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- 이미 예약된 49주차 이미지 6건을 새 규칙으로 다시 배정하고 이미지를 다시 만든다(방식은 티켓 20261124_1052의 후속 처리와 같다: 공유 DB의 `original.image_spec` 6행 갱신 → 로컬 어드민에서 «이미지 다시 만들기» → DB·이미지 확인).
- 50주차(12/7~) 묶음이 들어오면 이웃 겹침과 계열 분포를 DB에서 읽어 확인한다.
- push는 사용자 요청 때만 한다. 윤진 정의 변경은 이 티켓에 없다.
