# [Infra] 컬렉션·트라이브 영문 이름 칸과 표지 생성 설정 칸을 추가한다 (생성기 1회차)

## 핵심 요약

- 요구사항: `item_books.name_en text`, `item_books.cover_params jsonb`, `tribes.name_en text`를 추가하고 정해진 영문 이름 10개를 채운다.
- 구현 계획: 마이그레이션 363(push 직전 원격 번호 재확인)과 되돌림 SQL을 쓰고, 메인 세션이 실행한 뒤 생성 타입을 MCP로 받아 반영한다.
- 관련 파일: `jam-web/supabase/migrations/363_item_books_tribes_name_en_cover_params.sql`(+`_down.sql`), `jam-web/src/types/database.generated.ts`(item_books·tribes Row/Insert/Update), `jam-web/src/types/database.ts`(ItemBookRow·TribeRow 도메인 타입), `docs/plan/jam2/service-redesign/트라이브 보이스.md` 7절, `jam-web/src/lib/admin/policyDashboard/policiesData.ts` `ch19-english-names`

## 상세 요구사항

- 칸은 모두 NULL 허용, 기본값 없음. 확장 단계만 한다(기존 칸 변경·삭제 없음).
- 채울 값: 트라이브 한입만 연구회 ONE BITE CLUB, 찰칵단 CLICK CREW, 비사이드 레코즈 B-SIDE RECORDS, 소나무 잡화점 PINE TREE GENERAL STORE,
  혼자들 THE LONERS. 컬렉션 골목길 필름 스냅 ALLEY FILM SNAPS, 무명을 쫓는 야식가들 MIDNIGHT SNACK CHASERS, 아날로그 믹스테이프 ANALOG MIXTAPE,
  짝 잃은 양말 LONELY SOCKS, 창고의 문구 상자 THE STATIONERY BOX. 이름으로 찾되 활성 행 한 건씩만 맞는지 끝 검사로 확인한다.
- `cover_params` 모양(생성기 3회차가 쓴다): `{ version: 1, seed: string, rerolls: number, bgHex: string, bgSource: 'auto'|'manual',
  textColors: { title: string, tribe: string, join: string }, badgeId: string, appliedAt: string }`. DB는 모양을 강제하지 않는다.
- 문서: `트라이브 보이스.md` 7절과 정책 항목 `ch19-english-names`의 «DB에는 영문 이름 칸이 없음»을 고친다. 영문 이름의 기준을 DB 칸으로
  옮기고, 7절 표는 처음 정한 값의 기록으로 남긴다(같은 값을 두 곳에서 고치지 않게 문서에 명시).

## 구현 계획 (파일 단위, 2026-11-24 카리나 사전 확인)

번호 363은 로컬 staging(최신 362)·`origin/staging`(최신 359)·원격 `claude/*` 브랜치 어디에도 없음을 확인했다. DB에는 세 칸이 아직 없고,
위 10개 이름은 각각 정확히 한 행이며 모두 `is_active = true`다(트라이브 15행 중 활성 5행, 컬렉션 51행).

1. `jam-web/supabase/migrations/363_item_books_tribes_name_en_cover_params.sql`(새 파일): `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 3개 →
   `UPDATE tribes/item_books SET name_en = ... WHERE name = ... AND is_active` 10건 → 끝에 DO 블록으로 트라이브 5행·컬렉션 5행이
   채워졌는지 세어 다르면 `RAISE EXCEPTION`. 칸마다 `COMMENT ON COLUMN`.
2. `..._down.sql`(새 파일): 세 칸 `DROP COLUMN IF EXISTS`.
3. `jam-web/src/types/database.generated.ts`: `item_books`(1834줄 근처) Row·Insert·Update에 `name_en`·`cover_params`(Json), `tribes`(4160줄 근처)
   Row·Insert·Update에 `name_en`. 알파벳 순서 자리에 넣는다(카리나가 실행 뒤 MCP 생성 결과와 대조한다).
4. `jam-web/src/types/database.ts`: `ItemBookRow`(527줄)에 `name_en: string | null`, `cover_params: Json | null`(이 파일이 쓰는 Json 타입을 따른다),
   `TribeRow`(1109줄)에 `name_en: string | null`. 이 타입을 쓰는 객체 리터럴·시험 픽스처가 typecheck에서 깨지면 그 자리도 고친다.
5. `docs/plan/jam2/service-redesign/트라이브 보이스.md` 7절(341~347줄 본문): «DB에는 영문 이름 칸이 없고» 문장을 고쳐 기준을 DB 칸
   (`tribes.name_en`, `item_books.name_en`)으로 옮기고, 7.1·7.2 표는 «처음 정한 값의 기록(2026-11-24)»이며 이후 변경은 DB(어드민 생성기)에서만
   한다고 적는다.
6. `jam-web/src/lib/admin/policyDashboard/policiesData.ts` `ch19-english-names`(1690줄): `currentSpec`의 «DB에는 영문 이름 칸이 없음»을 DB 칸 기준으로
   고치고 `ticketId`를 이 티켓으로, `basisDoc`은 그대로 둔다. 생성기 내용은 3회차(20261124_1744)가 더한다.

### 주요 의사결정 / 핵심 메모
- 로컬 staging이 `origin/staging`보다 앞서 있고 push는 사용자 요청 때만 하므로, 티켓 커밋 위에 로컬 리뷰 브랜치를 만들어 `retryBranch`로 넘겼다. 아현의 push가 거부되자 push 없이 `gateOnly`로 민지만 돌렸다(같은 저장소라 로컬 커밋이 보인다). 판정 범위를 티켓 계획 커밋부터로 좁혀 다른 티켓의 미푸시 커밋이 섞이지 않게 했다.
- 민지 WARN 사유는 «CI 없음»과 «실행 뒤 확인은 카리나 몫» 두 가지였고, 뒤의 것은 위 테스트 결과로 채웠다.
- 민지 범위 밖 발견물(참고): 끝 검사가 개수만 세고 어떤 행인지는 보지 않는다. 실행 뒤 확인에서 행 이름과 값을 직접 대조했으므로 별도 티켓은 만들지 않았다.
