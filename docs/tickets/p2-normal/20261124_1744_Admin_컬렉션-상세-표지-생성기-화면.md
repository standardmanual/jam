# [Admin] 컬렉션 상세 페이지에 표지 생성기 구역(미리보기·수동 변경·적용)을 붙인다 (생성기 3회차)

## 핵심 요약

- 요구사항: `/admin/itembooks/[id]`에 «대표 이미지 생성기» 구역을 더한다. 미리보기 캔버스, 컬렉션 영문 이름 입력, 대표 배지 선택,
  배경색 다시 뽑기·직접 지정, 글자색 3개(제목·트라이브·JOIN AND MOVE), 기본값으로 되돌리기, 적용 버튼을 둔다.
- 구현 계획: 2회차 모듈(`src/lib/collection-cover/`)을 브라우저 캔버스로 호출해 미리보기를 그린다. 적용은 1024 PNG를
  `/api/admin/asset-generator/apply`(`targetType: 'collection'`)로 올리고, 같은 흐름에서 `name_en`·`cover_params`를 저장한다.
- 관련 파일: `jam-web/src/app/admin/itembooks/[id]/page.tsx`(서버 조회에 name_en·cover_params·tribes.name_en·소속 배지 sort_order 추가,
  다른 컬렉션 cover_params 배경색 목록, 새 구역 배치), 새 `jam-web/src/components/admin/itembooks/CollectionCoverGenerator.tsx`(클라이언트),
  `jam-web/src/app/api/admin/itembooks/[id]/route.ts`(name_en·cover_params 저장 허용), `jam-web/src/app/api/admin/asset-generator/apply/route.ts`(필요 시만),
  `jam-web/src/lib/admin/policyDashboard/policiesData.ts` `ch19-english-names`

## 상세 요구사항

- 어드민 UI는 shadcn/ui(`components/admin/ui`)를 쓴다. 네이티브 select·color input을 그대로 노출하지 않는다(색 칸은 shadcn 입력 + 색 견본).
- 기본값: `cover_params`가 있으면 그 상태로 연다. 없으면 시드 = 컬렉션 id, 다시 뽑기 0회, 배지 = 소속 아이템 배지 중 이미지가 있는 첫 배지(sort_order),
  글자색은 모듈 기본 규칙. 컬렉션 영문 이름이 비어 있으면 입력을 요구하고 적용 버튼을 막는다. 트라이브 영문 이름은 DB 값을 읽기만 한다
  (비어 있으면 경고).
- 다시 뽑기: 횟수를 1 올려 새 시드로 배경색을 만든다. 직접 지정: 색을 고르면 `bgSource: 'manual'`. 다른 컬렉션 배경 색상 목록을
  모듈에 넘겨 30° 이내 색을 피한다.
- 글자색 3개는 각각 «자동»과 직접 지정을 오갈 수 있다. 자동이면 배경이 바뀔 때 기본 규칙으로 다시 정한다.
- 대표 배지: 소속 아이템 배지를 썸네일 목록으로 보여 주고 고른다(같은 이름의 등급 중복은 묶지 않아도 된다).
- 미리보기는 설정이 바뀔 때마다 다시 그린다(글꼴·배지 이미지 로드 완료 뒤). Sour Gummy 800은 브라우저에서도 굵기 800 파일을 쓴다
  (기존 `loadFontInBrowser`는 굵기 400만 받으므로 FontFace로 직접 로드).
- 적용: 확인창 → 업로드·교체 → 성공 시 `name_en`·`cover_params`(appliedAt 포함) 저장 → 화면 새로고침. 실패 시 [현상]→[원인]→[해결책] 문구.
- 정책 대시보드 `ch19-english-names`에 생성기(위치, 기본 규칙 요약, 수동 변경 항목, 적용 동작)를 반영한다.

## 구현 계획 (파일 단위, 2026-11-24 카리나 사전 확인)

확인한 사실: 1회차로 DB 칸 세 개가 생겼고 5개 샘플 컬렉션과 활성 트라이브 5개에 영문 이름이 있다. 2회차 모듈의 공개 API는
`renderCollectionCover(canvas, input, { createCanvas })`, `hueOfHex`, `defaultTextColors`, `hexToRgb`, `coverSeed`이고 입력은
`{ titleEn, tribeEn, badgeImage, seed: 컬렉션 id, rerolls, usedHues, bgOverride?, textColorOverrides? }`, 반환 `bgSource`는 `'generated' | 'override'`다
(`cover_params.bgSource`에는 `'auto' | 'manual'`로 옮겨 저장). 5개 샘플을 서버 캔버스로 구운 PNG는 1.42~1.48MB라 적용 API 상한(5MB) 안이다.
소속 아이템 배지의 `sort_order`가 모두 0이라 기본 배지는 sort_order → 이름 → id 순으로 정한다(같은 이름의 등급은 같은 그림이다).

1. `jam-web/src/app/admin/itembooks/[id]/page.tsx`(10~37줄 조회, 64줄 뒤 배치): tribes 조회에 `name_en`, badges 조회에 `sort_order`를 더한다. 다른 컬렉션의
   `cover_params`를 `select('cover_params').neq('id', id).not('cover_params', 'is', null)`로 읽어 `bgHex` 목록을 만든다. `ItemBookDetail` 다음에
   `<div className="border-t pt-8"><CollectionCoverGenerator … /></div>`를 둔다(`book.name_en`·`book.cover_params`는 `select('*')`에 이미 있다).
2. 새 `jam-web/src/components/admin/itembooks/collectionCoverState.ts`(순수 함수): `parseCoverParams(raw)`(모양이 맞지 않으면 null), `pickDefaultBadge(badges)`
   (`deleted_at` 없음·`image_url` 있음, 위 정렬), `initialCoverState(...)`(cover_params가 있으면 그 시드·횟수·배지·배경 출처를 쓰고, 저장된 글자색이
   그 배경의 `defaultTextColors`와 같으면 «자동», 다르면 직접 지정으로 연다), `buildCoverParams(state, result, appliedAt)`, `normalizeHex`.
3. 새 `jam-web/src/components/admin/itembooks/CollectionCoverGenerator.tsx`(클라이언트): Sour Gummy 800은
   `new FontFace('Sour Gummy', 'url(/fonts/sour-gummy/SourGummy-ExtraBold.ttf)', { weight: '800' })` → `load()` → `document.fonts.add`(한 번만).
   배지 이미지는 `crossOrigin = 'anonymous'`로 불러온다(선례 `src/lib/admin/opsInbox/imageRender.client.ts` 21~30줄, 없으면 캔버스가 오염돼 PNG를 못 만든다).
   1024 캔버스에 그리고 화면에서는 CSS로 줄여 보인다. shadcn 컴포넌트(`components/admin/ui`의 Input·Button·Switch·Alert·AlertDialog·Skeleton·Card)만 쓴다.
   색 칸은 Input(#rrggbb) + 색 견본 상자다. 상태: 글꼴·배지 로드 중(Skeleton), 영문 이름 없음(입력 요구 문구 + 적용 비활성), 트라이브 영문 이름 없음·이미지 있는
   배지 없음(경고, 미리보기·적용 비활성), 적용 중(버튼 비활성·문구), 실패([현상]→[원인]→[해결책]).
   적용: AlertDialog 확인 → `canvas.toBlob('image/png')` → FormData(`targetType: 'collection'`, `targetId`, `image`)로 `/api/admin/asset-generator/apply` POST
   (호출 예시 `src/app/admin/asset-generator/ApplyTab.tsx`) → 성공하면 `PATCH /api/admin/itembooks/[id]`에 `{ name_en, cover_params }` → `router.refresh()`.
   이미지는 바뀌었는데 설정 저장만 실패하면 그 사실을 따로 알린다.
4. `jam-web/src/app/api/admin/itembooks/[id]/route.ts` PATCH(87~119줄): `is_active`·`name_en`·`cover_params` 중 하나 이상을 받는다. `is_active`는 boolean,
   `name_en`은 문자열(앞뒤 공백 제거·대문자, 빈 값은 null, 60자 이하) 또는 null, `cover_params`는 null 또는 위 모양(version 1, bgHex·textColors는 #rrggbb,
   bgSource는 auto|manual, rerolls는 0 이상 정수). 기존 `is_active`만 보내는 호출과 응답은 그대로다.
5. `jam-web/src/lib/admin/policyDashboard/policiesData.ts` `ch19-english-names`: 생성기 위치(컬렉션 상세), 기본 규칙 요약, 수동 변경 항목, 적용 동작을 반영하고
   `ticketId`를 이 티켓으로 바꾼다.
6. 시험: `src/components/admin/itembooks/__tests__/collectionCoverState.test.ts`(순수 함수), `__tests__/CollectionCoverGenerator.test.tsx`(모듈·FontFace·이미지 로드를
   목으로 바꿔 상태별 표시와 적용 때 두 요청의 본문을 확인), `src/app/api/admin/itembooks/[id]/__tests__/route.test.ts`에 PATCH 새 칸 사례.
