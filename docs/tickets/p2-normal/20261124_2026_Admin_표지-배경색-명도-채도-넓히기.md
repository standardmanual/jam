# [Admin] 표지 배경색 다시 뽑기에 명도·채도 변화와 어두운 색을 넣고, 다시 열 때 적용한 색을 그대로 보인다

## 핵심 요약

- 요구사항: 사용자 지적(2026-11-24) «다시 뽑기를 누르면 명도·채도의 변화가 없어 보여» → 비교 시안을 본 뒤 «어두운 색도 넣어»로 결정. 배경 명도를 0.30~0.90으로, 채도를 최대의 60~96%로 넓히고, 어두운 배경이면 제목을 자동으로 흰색으로 바꾼다. 함께, 표지를 적용한 컬렉션을 다시 열면 저장된 배경색을 그대로 보인다(지금은 시드로 다시 계산해 적용한 표지와 다를 수 있다).
- 구현 계획: 아래 «구현 계획» 6개 항목.
- 관련 파일: `jam-web/src/lib/collection-cover/color.ts`(`generateBackground` 143~167줄, `defaultTextColors` 177~180줄), `jam-web/src/lib/collection-cover/__tests__/color.test.ts`, `jam-web/src/components/admin/itembooks/collectionCoverState.ts`(`CoverState`, `initialCoverState`, `buildCoverParams` 99~115줄), `jam-web/src/components/admin/itembooks/CollectionCoverGenerator.tsx`(배경색 라벨 217줄, 그리기 373줄, 다시 뽑기·직접 지정 442~443줄), `jam-web/src/components/admin/itembooks/__tests__/collectionCoverState.test.ts`, `jam-web/src/lib/admin/policyDashboard/policiesData.ts` `ch19-english-names`

## 새 규칙 (상위 티켓 «표지 규칙»의 배경색 생성·제목 색을 대체한다)

- 난수 순서: 색상 h(0~360 균등) → 밝기 L(0.30~0.90 균등) → 채도 비율 k(0.60~0.96 균등). C = 그 L·h의 sRGB 최대 채도 × k.
- 버림 조건: C < 0.15(칙칙한 색), 배지 주된 색상과 70° 미만, 다른 컬렉션 표지 배경과 30° 미만(완화 단계 50°/20°, 30°/0°는 그대로), 그리고 제목 대비:
  선화 배지면 검정 제목 대비 4.5 이상만 쓴다(선화는 검정 선이라 어두운 배경을 쓰지 않는다). 선화가 아니면 검정 제목 대비 4 이상이거나, 흰 제목 대비 4 이상이어야 한다.
- 제목 기본 색(`defaultTextColors`의 title): 검정(#161412) 대비 4 이상이면 검정, 아니면 흰색과 검정 중 대비가 큰 쪽. 직접 지정한 배경에도 같은 규칙. 트라이브·JOIN AND MOVE 기본 색 규칙(흰색 대비 3 이상이면 흰색)은 그대로.
- 2026-11-24 시뮬레이션: 컬렉션 2개 × 다시 뽑기 24번 중 20번이 흰 제목(남색·와인·벽돌·짙은 보라), 가장 어두운 L 0.41(채도 하한 때문에 0.30 근처는 드물다).

## 구현 계획 (파일 단위, 카리나 사전 확인)

1. `color.ts` `generateBackground`: 위 규칙으로 바꾼다(75%/25% 두 구간 분기를 없앤다). `defaultTextColors`: 제목 색 규칙을 더한다. 두 함수의 주석을 새 규칙으로 고친다.
2. `__tests__/color.test.ts`: 완료 조건 2의 «검정 제목 대비 ≥ 4»를 «자동 제목 색(`defaultTextColors(rgb).title`) 대비 ≥ 4»로 바꾸고, C ≥ 0.15·배지 70°(relaxStep 0) 검사는 유지한다. 새 사례: 표본 200개에서 흰 제목이 나오는 배경이 있고(L < 0.5), 밝기는 0.5 미만과 0.8 초과가 모두 나오며, k < 0.9인 배경이 있다. 선화 배지면 모든 표본이 검정 제목·대비 4.5 이상이다. `defaultTextColors`의 제목 규칙 사례(어두운 남색 → 흰색, 밝은 노랑 → 검정).
3. `collectionCoverState.ts`: `CoverState`에 `bgSaved: string | null`을 더한다. `initialCoverState`는 `cover_params`가 있으면 `bgSaved = params.bgHex`(출처가 manual이면 지금처럼 `bgManual`), 없으면 null. `buildCoverParams`의 `bgSource`는 `bgManual`이면 'manual', `bgSaved`로 그렸으면 원래 저장된 출처를 유지, 그 밖에는 'auto'(필요하면 함수에 저장된 출처를 넘긴다).
4. `CollectionCoverGenerator.tsx`: 그리기 입력 `bgOverride = state.bgManual ?? state.bgSaved ?? undefined`. 배경색 라벨: 직접 지정이면 «배경색(직접 지정)», `bgSaved`로 그리면 «배경색(적용한 색)», 그 밖에는 «배경색(자동)». 다시 뽑기·직접 지정·기본값으로 되돌리기는 `bgSaved`를 지운다.
5. `__tests__/collectionCoverState.test.ts`: `bgSaved` 초기값·`buildCoverParams` 출처 사례를 더한다.
6. `policiesData.ts` `ch19-english-names`: «제목은 잉크색»을 새 제목 색 규칙으로, 배경색 생성 요약에 명도·채도 범위와 어두운 배경을, «다시 열면 적용한 색으로 연다»를 반영한다. ticketId를 이 티켓으로.
