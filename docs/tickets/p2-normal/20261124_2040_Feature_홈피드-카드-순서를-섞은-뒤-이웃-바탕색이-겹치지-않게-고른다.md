# [Feature] 홈피드 카드 순서를 섞은 뒤 이웃 바탕색이 겹치지 않게 고른다

## 핵심 요약

- 요구사항: 홈피드에서 바탕색이 같은 카드가 연달아 나오지 않게 한다. 사용자가 staging 화면에서 노랑 바탕 카드 두 장이 이어진 것을 확인했다(2026-11-24).
- 구현 계획: 홈 정렬(`sortHomeCards`)이 끝난 뒤에 «앞 카드와 바탕색이 같으면 뒤에서 다른 바탕의 가장 가까운 카드를 당겨 오는» 순서 보정 순수 함수를 더한다. 홈 조회와 어드민 홈 미리보기가 같은 함수를 쓴다.
- 관련 파일:
  - `jam-web/src/lib/today/cardSelection.ts`: `sortHomeCards`(73행 근처) 아래에 보정 함수(예: `spreadAdjacentBg`)를 새로 둔다.
  - `jam-web/src/lib/today/cards.ts`: `getTodayCards`의 `sortHomeCards` 호출(204행) 바로 뒤에서 보정 함수를 부른다.
  - `jam-web/src/lib/admin/homePreview/load.ts`: `sortHomeCards` 호출 두 곳(288행 `live`, 292행 `pendingToday`) 뒤에서 같은 함수를 부른다.
  - `jam-web/src/lib/today/__tests__/cardSelection.test.ts`: 보정 함수 시험을 더한다.
  - `docs/service/prd/home-feed/PRD.md` 124행(정렬 3번)과 459행(무작위 값): 순서 보정 규칙을 적는다.

## 배경 / 문제 정의

- staging 홈피드에서 「한 해의 마지막 계절 앞에서」(노랑 바탕)와 「낯선 골목에서 시작하는 하루」(노랑 바탕)가 연달아 나온다.
- DB 확인 결과 두 카드의 `bg_color_key`는 둘 다 `yellow`로 저장돼 있다. 저장값이 잘못된 것이 아니다.
- 원인: 바탕색은 카드를 등록할 때 `assignFeedColors`가 «등록 순서에서 바로 앞 카드와 다르게» 정해 저장한다. 그런데 홈 순서는 `sortHomeCards`가 «유저 id + KST 날짜» 시드로 섞기 때문에 화면에서의 이웃은 유저와 날짜마다 다르다. 등록 순서의 이웃과 화면의 이웃이 달라서, 저장된 색만으로는 이웃 겹침을 막을 수 없다.
- 같은 문제를 운영 묶음 이미지 색에서는 «공개 순서»를 기준으로 풀었다(티켓 20261124_1517). 홈 카드 바탕색은 순서가 사람마다 달라서 같은 방식을 쓸 수 없고, 순서를 섞은 뒤에 보정해야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 보정 함수는 `sortHomeCards`가 돌려준 배열을 입력으로 받는 순수 함수다. 입력을 바꾸지 않고, 같은 입력은 같은 결과를 낸다(`Math.random` 금지).
- 규칙: 앞에서부터 한 장씩 자리를 채운다. 지금 자리에 올 카드는 «아직 놓지 않은 카드 중 정렬 순서가 가장 앞이면서 바로 앞에 놓인 카드와 바탕색이 다른 카드»다. 그런 카드가 없으면(남은 카드가 모두 같은 바탕) 정렬 순서가 가장 앞인 카드를 그대로 둔다.
- 바탕색을 알 수 없는 카드(`bg_color_key`가 NULL이거나 통합 팔레트 9키에 없는 값)는 어느 색과도 겹치지 않는 것으로 본다. 먼저 어느 유형이 바탕을 실제로 보이는지(`feedLook.ts`, 유형별 카드 컴포넌트)를 확인하고, 바탕이 보이지 않는 유형은 같은 방식으로 겹침 판정에서 뺀다.
- 새 카드(노출 시작 24시간 이내) 묶음이 맨 앞에 온다는 규칙은 유지한다. 보정은 가능한 한 적게 순서를 바꾸는 방향이라, 새 카드가 뒤로 밀리는 경우는 «앞 카드와 바탕이 같을 때»로 한정된다.
- 같은 유저가 하루 안에 새로고침해도 순서가 같아야 한다(결정적).
- `getTodayCards`와 어드민 홈 미리보기(`load.ts` 두 곳)가 같은 함수를 쓴다. 미리보기 전용 판정을 따로 두지 않는다.

### UI/UX 관점 (해당 시)

- 카드 모양과 색은 바뀌지 않는다. 순서만 바뀐다.

### 컨텐츠 관점 (해당 시)

- 해당 없음.

## 구현 계획

1. `cardSelection.ts`에 `spreadAdjacentBg<T>(cards: readonly T[], bgKeyOf: (card: T) => string | null): T[]`를 더한다. 위 규칙대로 한 장씩 자리를 채운다.
2. `cards.ts`의 `getTodayCards`에서 `sortHomeCards` 결과에 이 함수를 적용한다. `bgKeyOf`는 카드의 `bg_color_key`를 읽는다.
3. `homePreview/load.ts`의 `live`와 `pendingToday` 두 곳에도 같은 함수를 적용한다(`pendingToday`는 묶음 항목이라 바탕 키를 읽는 경로가 다르면 `entry`에서 읽는다).
4. `cardSelection.test.ts`에 시험을 더한다: ① 노랑·노랑·파랑 순서가 노랑·파랑·노랑으로 보정된다 ② 바탕이 모두 같으면 순서가 그대로다 ③ 바탕을 모르는 카드(NULL)는 겹침으로 보지 않는다 ④ 같은 입력은 같은 결과다 ⑤ 입력 배열을 바꾸지 않는다 ⑥ 새 카드 묶음이 앞에 오는 정렬 시험이 그대로 통과한다.
5. PRD 정렬 3번과 «무작위 값» 항목에 «섞은 뒤 이웃 바탕색이 겹치지 않게 순서를 보정한다»를 적는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- 바탕색이 서로 다른 카드가 둘 이상 있는 경우, 보정 함수의 출력에서 이웃한 두 카드의 바탕색이 같은 쌍이 생기지 않는다. 단, 남은 카드가 모두 같은 바탕이면 예외다(시험으로 확인한다).
- 같은 입력으로 두 번 부르면 같은 순서가 나오고, 입력 배열은 바뀌지 않는다(시험으로 확인한다).
- `getTodayCards`와 어드민 홈 미리보기 두 경로가 같은 보정 함수를 부른다(코드로 확인한다).
- `npx vitest run src/lib/today/__tests__/cardSelection.test.ts`와 `scripts/verify.sh`가 통과한다.
- PRD 정렬 서술이 새 규칙과 맞다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)

- staging 홈피드에서 실제로 이웃 바탕색이 겹치지 않는지 화면 또는 어드민 미리보기로 확인한다(push 요청이 있을 때 `[배포]` 커밋으로 올린 뒤).

### 주요 의사결정 / 핵심 메모

- 대안 1, 등록할 때 이웃을 맞추기: 홈 순서가 유저와 날짜마다 달라서 불가능하다.
- 대안 2, 보여 줄 때 바탕색을 다시 배정하기: 저장된 색, 어드민에서 사람이 고른 색, 그림 색 규칙(⑤·⑥)과 충돌하므로 채택하지 않았다.
- 채택: 순서를 섞은 뒤 겹치는 이웃만 최소로 옮긴다. 색은 건드리지 않는다.

### 잔여 이슈
- 카드 수가 적고 바탕이 한쪽으로 몰려 있으면 보정해도 겹침이 남을 수 있다(예: 노랑 3장과 파랑 1장).
