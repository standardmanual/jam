# [Admin] 컬렉션 표지 생성기 색 조정 시 마우스·화면 지연 성능을 개선한다

## 핵심 요약

- 요구사항: 어드민 컬렉션 상세(`/admin/itembooks/[id]`) 대표 이미지 생성기에서 배경색·글자색 컬러 피커를 드래그할 때 마우스와 화면 반응이 느려지는 병목을 제거한다. 표지 규칙(배경색 시드 결정론, 대비, 레이아웃, 배지 외곽 마스크, 최종 1024 PNG 그레인)은 그대로 유지한다.
- 구현 계획: 배지 분석·외곽 마스크를 배지 이미지 단위로 분리 캐시하고, 자동 배경색·글자색 계산을 `useMemo`로 분리하며, `color.ts`·`badge.ts`·`layout.ts` 연산을 최적화한다. 생성기 컴포넌트는 rAF로 프레임당 1회만 경량 합성(그레인 생략)하고, 입력 종료 디바운스·적용(`submit`) 시점에 오프스크린 `willReadFrequently` 버퍼로 정밀 그레인을 적용한다.
- 관련 파일: `jam-web/src/lib/collection-cover/color.ts`(`maxChroma`·`peakChroma`·`generateBackground` 84~184줄), `jam-web/src/lib/collection-cover/badge.ts`(`outlineInteriorMask` 57~77줄), `jam-web/src/lib/collection-cover/layout.ts`(`layoutTitle` 43~54줄), `jam-web/src/lib/collection-cover/render.ts`(`renderCollectionCover` 124~284줄 및 준비·세션 렌더러 추가), `jam-web/src/components/admin/itembooks/CollectionCoverGenerator.tsx`(`ColorField` 87~134줄, 렌더 effect·`submit` 314~460줄), 각 `__tests__`

## 배경 / 문제 정의

티켓 20261124_1956에서 색 견본을 `<Input type="color">`로 바꾼 뒤 컬러 피커를 드래그하면 초당 60~120회 `onChange`가 발생한다. 현재는 매 틱마다 `renderCollectionCover`가 동기 실행되며 아래 비용을 전부 반복해 메인 스레드와 GPU 파이프라인이 막힌다.

1. 배지 외곽 마스크(`outlineInteriorMask` + `dilateMask` 25탭 2패스 약 1,160만 루프)를 색이 바뀔 때마다 재계산
2. 1024×1024 메인 캔버스에 매 틱 `getImageData`(GPU→CPU readback) + `Math.random()` 315만 회 + `putImageData` 수행
3. 원본 배지 `alphaBounds` + 128px `analyzeBadgePixels` + 임시 캔버스 6개를 매 틱 재생성(`willReadFrequently` 미지정)
4. 미적용 컬렉션 또는 다시 뽑기 뒤 글자색 조정·영문 이름 입력 시 `generateBackground`와 `peakChroma(h)`(호출당 `oklchToLinear` 1,584회)가 매 틱 재실행
5. `useEffect` 안 `setResult(r)`로 매 색 변경마다 2중 리렌더 발생 및 컬러 피커/입력칸 반응 지연

## 상세 요구사항

### 서비스/코드베이스 관점
- **배지 단위 캐싱**: `prepareCoverBadge(badgeImage, createCanvas)`를 추가해 배지 픽셀 분석(`analysis`), 투명 여백(`bounds`), 리사이즈 배지 캔버스(`bc`), 팽창 외곽 마스크 캔버스(`haloMaskCanvas`)를 배지 이미지당 1회만 계산한다.
- **세션형 렌더러(`createCoverRenderer`)**: 종이 얼룩 텍스처(`mottleCanvas`), 바탕 사본(`bgSnap`), 마스크 합성 스크래치(`haloScratch`), 그레인 작업 버퍼(`grainWorkCanvas`, `{ willReadFrequently: true }`), 그레인 델타 배열(`Int8Array`), 레이아웃 캐시를 재사용한다.
  - 배경색이 바뀌지 않았으면(글자색만 변경) 바탕 그라데이션·종이 얼룩을 다시 그리지 않고 `bgSnap`을 재사용한다.
  - `grain: 'skip' | 'exact'` 옵션을 지원해 라이브 드래그 중에는 GPU 합성만 수행하고, 정착(디바운스) 및 최종 적용 시에는 오프스크린 `grainWorkCanvas`에서 정밀 그레인을 적용한 뒤 메인 캔버스로 1회 `drawImage`한다.
- **기존 API 호환**: `renderCollectionCover(canvas, input, deps)` 시그니처와 동작은 그대로 유지하고 내부 로직을 공유해 중복을 없앤다.
- **색상/알고리즘 최적화(출력 동등성 유지)**:
  - `color.ts`: `maxChroma`·`peakChroma`·`generateBackground`에서 `cos(h)`/`sin(h)` 사전 계산 및 스칼라 영역 검사로 배열 할당·삼각함수 중복 호출을 제거하고, `usedLabs` 선택 전달을 지원한다. 동일 시드·입력에서 기존과 동일한 결과(`hex`, `relaxStep`)를 보장한다.
  - `badge.ts`: `outlineInteriorMask`에서 `Int32Array` 스택과 push 시점 방문 마킹으로 중복 push를 제거한다.
  - `layout.ts`: `layoutTitle` 재귀에서 3줄 상한 조기 가지치기로 $O(2^n)$ 분기를 $O(n^2)$로 줄인다.
- **UI 입력·상태 최적화**:
  - `CollectionCoverGenerator.tsx`: `resolvedBg`와 `textColors`를 `useMemo`로 즉시 파생해 `useEffect` 안 `setResult` 2중 리렌더를 제거한다. 글자색 변경·영문 이름 수정 시 `generateBackground`가 재실행되지 않는다.
  - 캔버스 그리기를 `requestAnimationFrame`으로 프레임당 최대 1회로 병합하고, 드래그 중에는 `grain: 'skip'`으로 즉시 그린 뒤 120ms 디바운스 후 `grain: 'exact'`로 마무리한다.
  - `submit`(적용) 시점에 그레인이 아직 반영되지 않았으면 동기적으로 `grain: 'exact'` 최종 렌더를 실행한 뒤 `canvas.toBlob`을 호출한다.

### UI/UX 관점 (해당 시)
- 표시 문구, 레이아웃, 색 규칙(자동/적용한 색/직접 지정, 어두운 배경 흰 제목)은 기존과 동일하다.
- 배경색 드래그 시 자동 전환되는 글자색 견본도 지연 없이 즉시 따라온다.

## 구현 계획

1. `jam-web/src/lib/collection-cover/color.ts`: `cos(h)`/`sin(h)` 사전 계산 헬퍼(`inGamutOk`, `maxChromaCS`, `peakChromaCS`), `usedLabs` 옵션 지원, `resolveCoverBackground` 순수 함수 정리.
2. `jam-web/src/lib/collection-cover/badge.ts`: `outlineInteriorMask` `Int32Array` 스택 + push 시점 마킹.
3. `jam-web/src/lib/collection-cover/layout.ts`: `layoutTitle` 3줄 조기 가지치기, `BADGE_MAX` 기반 크기 계산 공유.
4. `jam-web/src/lib/collection-cover/render.ts`: `CoverCanvasLike.getContext` 옵션 허용, `prepareCoverBadge`, `createCoverRenderer` 구현, `renderCollectionCover`가 같은 경로를 쓰도록 통합.
5. `jam-web/src/components/admin/itembooks/CollectionCoverGenerator.tsx`: `preparedBadge`·`usedLabs`·`resolvedBg`·`textColors`를 `useMemo`로 분리, `createCoverRenderer` ref 재사용, rAF 병합 + 120ms 그레인 디바운스 + `submit` 시 최종 그레인 보장, 동일 hex 중복 `setState` 가드.
6. 단위 테스트 보강: `color.test.ts`(시드 결정론/성능 최적화 결과 일치), `badge.test.ts`(`outlineInteriorMask` 정합성), `layout.test.ts`(긴 제목 가지치기 정합성), `render.test.ts`(`prepareCoverBadge` + `createCoverRenderer` 캐시 재사용·`grain: 'skip' | 'exact'`·기존 `renderCollectionCover` 일치성).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 색 변경 시 `prepareCoverBadge`(배지 분석·`alphaBounds`·`outlineInteriorMask`·`dilateMask`)가 재호출되지 않고 `createCoverRenderer`가 캐시된 배지·마스크·바탕 버퍼를 재사용함이 단위 테스트로 검증된다.
- 글자색 변경·영문 이름 변경 시 `generateBackground`가 재실행되지 않고, 배경색·글자색 파생값이 캔버스 렌더를 기다리지 않고 동기 계산된다.
- `color.ts`·`badge.ts`·`layout.ts` 최적화 이후에도 기존 표지 규칙(시드별 동일 배경색, 14색 회피, 선화 대비, 고리 마스크, 줄 나눔)이 모든 단위 테스트에서 그대로 통과한다.
- `submit` 호출 시 그레인이 미적용 상태여도 최종 `grain: 'exact'` 렌더 뒤 PNG를 추출한다.
- `scripts/verify.sh` 전체 항목이 통과한다.

### 후속 범위 (담당: 카리나/사용자, 시점: 머지 뒤)
- 로컬 `ADMIN_EMAILS` 환경의 어드민 `/admin/itembooks/[id]`에서 배경색·글자색 컬러 피커 드래그 시 마우스/미리보기 지연이 해소됐는지 실렌더로 확인하고 티켓을 CLOSED 처리한다.
