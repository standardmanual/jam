## 상세 요구사항

### 서비스/코드베이스 관점
- 표지색 파생: `deriveCoverTicketColor(bgHex: string | null | undefined, delta = 0.10)` 같은 순수 함수를 `ticketColor.ts`에 둔다. hex를 OKLCH로 바꾸고 명도를 `max(0.2, L − 0.10)`로 낮춘 뒤 hex로 되돌린다(색역을 벗어나면 채도만 줄여 맞춘다). 입력이 없거나 `#rrggbb`가 아니면 `pickTicketColor(null)`처럼 통합 팔레트 일곱 색 중 하나로 대신한다.
- 파생 결과 타입은 팔레트 키가 없는 색도 담아야 하므로 `TicketColor`의 `key`·`cssVar` 의존을 풀거나 별도 타입(예: 임의 hex를 담는 `ticket`·`ticketEnd`·`text` 값)을 둔다. 배지 상세 호출부의 동작과 시험은 바뀌지 않는다.
- 끝색은 기존 `ticketEndColor(hex)` 문자열을 그대로 쓴다. 글자색은 티켓색 hex와 끝색 hex(OKLCH 상대색 문자열이 아니라 같은 공식으로 계산한 hex)에서 `#171717`의 대비가 둘 다 4.5 이상이면 `#171717`, 아니면 흰색이다(둘 다 안 되면 티켓색 기준으로 더 큰 쪽). 시안의 계산식(아티팩트 소스의 `ticketColors`)이 기준이다.
- 색은 서버에서 정한다. 클라이언트 훅·`useEffect`로 칠하지 않는다.
- 데이터 읽기는 바꾸지 않는다. `cover_params`는 `jsonb`라 `book.cover_params as { bgHex?: unknown } | null`로 좁혀 읽는다(`database.generated.ts`에 타입이 없으면 지역 타입으로).
- 진행 수 칩: 모으는 중 `{slottedCount}/{totalBadgeCount} 모음`, 완성(`isCompleted`) `완성 {totalBadgeCount}/{totalBadgeCount}`. 문구는 `d.itembooks`에 키를 둔다(`d.itembooks.completed` 기존 문구 재사용 가능). 사용자 노출 문구라 `docs/service/writing/UX_WRITING_GUIDELINE.md` 용어를 지킨다. 완성 알림의 제목·본문(`completedTitle`·`completedBody`)은 화면에서 빠지므로 쓰지 않게 되면 번역 사전의 해당 키는 남기거나 지워도 되지만 lint·slop 검사를 통과해야 한다.

### UI/UX 관점
- 짙은 티켓에서 `--muted`·`--border`·글자 상자 테두리·로고가 흰색 계열로 따라간다. 슬롯 칸의 점선(미획득)이 짙은 티켓과 연한 티켓 모두에서 보이는지 확인한다. 점선 표현 자체는 바꾸지 않는다.
- 슬롯 선택 시트·«모두 빼기» 시트 등 오버레이는 티켓 밖이라 모양을 바꾸지 않는다.
- 표지가 없으면(`image_url` null) 메달류 아이콘(기존 `MagicBookIcon`)을 `--card-bg` 사진 자리에 둔다.

## 구현 계획

1. `ticketColor.ts`: OKLCH 변환·색역 맞춤·대비 계산 순수 함수와 `deriveCoverTicketColor`를 더한다. 단위 시험으로 고정한다: 명도가 0.10 낮아졌는가, 채도·색상이 같은가(색역 안일 때), 활성 컬렉션 15개 bgHex 전부에서 글자 대비 4.5 이상, 입력 없음·잘못된 입력은 팔레트로 대신.
2. `BadgeTicket.tsx`·`BadgeTicket.module.css`: 색 입력을 일반화하고 `--ticket-text`를 받는다. `kindLabel`·`dateText`는 이미 있다(`dateText=null`이면 날짜 줄 없음). 배지 상세 세 변형의 결과 HTML이 같아야 한다(기존 `badgeTicket.test.tsx`가 통과해야 한다).
3. `TicketTitleBoxes.tsx` 일반화 또는 컬렉션용 상자, 새 사진 자리 부품.
4. `collections/[id]/page.tsx`: 위 구조로 교체. 장착 모드(`slotMode`)·타인 보기(`!isOwnBook`)·404 분기는 그대로.
5. 시험 갱신, PRD 갱신.
6. `scripts/verify.sh`(CI와 같은 검사)를 통과시킨다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 컬렉션 상세(본인·타인·장착 모드)가 티켓 틀 안에 표지 사진 자리, 진행 수 칩·이름·설명 글자 상자, 이야기 글·슬롯 칸·체크인 배지 카드 구간 순서로 그려진다. 완성 알림 초록 카드와 카드 밖 진행 바는 없다.
- 티켓색은 `cover_params.bgHex`의 OKLCH 명도를 0.10 낮춘 색이다(단위 시험으로 고정). 글자색은 대비 4.5 이상이다(활성 컬렉션 15개 bgHex 전부 시험).
- 전체 화면 배경 테마 레이어와 대표 카드 안 블롭 애니메이션은 그려지지 않는다.
- 배지 상세 세 변형의 렌더 결과는 바뀌지 않는다(기존 시험 통과).
- 머리에 날짜 줄이 없고 종류 글자는 `COLLECTION`이다.
- `scripts/verify.sh` 통과.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`로 `/collections/<id>`를 짙은 표지(시장 골목의 전설)와 연한 표지(유리 칸 닦는 아침)에서 390px로 확인한다.
