# [UI] 컬렉션 상세 티켓 2: 트라이브 배경 테마 카드와 어드민 미리보기 프레임을 걷는다

## 핵심 요약

- 요구사항: 어드민 트라이브 폼(`TribeForm`)의 «배경 테마» 카드와 그 카드가 쓰는 컬렉션 상세 미리보기 프레임(`ItemBookDetailPreviewFrame`)을 걷고, 쓰는 곳이 없어지는 `ItemBookHeroSection`과 그 시험 둘을 지운다. 서비스 화면은 1회차(20261124_2253)에서 티켓으로 바뀌어 배경 레이어를 그리지 않으므로, 이 미리보기는 실제와 다른 화면을 보여 주는 상태다.
- 방향 변경: 처음 계획은 프레임을 티켓 모양으로 맞추는 것이었다. 병렬 티켓 20261124_2326(검토 대기, 아직 staging에 없음)이 어드민 컬렉션 편집 폼의 미리보기를 이미 없애서 프레임을 쓰는 곳이 트라이브 폼 하나만 남았고, 그 카드는 «트라이브 자체에는 배경이 적용되지 않아요»라고 안내하는 화면이다. 사용자가 «카드와 프레임을 함께 걷는다»로 정했다(2026-11-24).
- 관련 파일(지도):
  - `jam-web/src/app/admin/tribes/TribeForm.tsx` — import(7·8~10줄: `HEX_COLOR_PATTERN`, `BackgroundGeneratorPreview`, `BackgroundGeneratorLivePreviewState`, `ItemBookDetailPreviewFrame`, `BlobAnimationParams`·`parseBlobAnimation` 등), state(36·38~39줄), 검증(49~50줄), 저장 본문(57~75줄의 `background_color`·`background_animation`), 카드 JSX(약 213~247줄). 배경 관련 import·state·검증·전송 필드·카드를 모두 걷는다.
  - 삭제: `jam-web/src/app/admin/itembooks/ItemBookDetailPreviewFrame.tsx`, `jam-web/src/app/(main)/collections/[id]/ItemBookHeroSection.tsx`, `jam-web/src/app/(main)/collections/[id]/__tests__/heroChildren.test.tsx`, `heroTextColor.test.tsx`.
  - 주석 정리: `jam-web/src/app/admin/badges/BackgroundGeneratorPreview.tsx` 13줄, `jam-web/src/lib/backgroundGenerator/types.ts` 5줄이 삭제되는 프레임을 가리키는 설명이다. 사실에 맞게 고친다(상수 `SERVICE_WIDTH`는 다른 곳이 쓰면 남긴다. `grep`으로 확인).
  - 시험: 트라이브 폼을 다루는 시험이 있으면(`grep -rl TribeForm jam-web/src`) 배경 필드 기대를 걷는다. 병렬 브랜치가 추가한 `background-theme-removed.test.ts`(2326)가 있으면 이 브랜치에는 없으므로 건드리지 않는다.
  - 문서: 트라이브 관리 화면을 설명하는 PRD가 «배경 테마»를 말하면(`grep -rn "배경 테마" docs/service/prd`) 고친다. `docs/service/prd/badge-detail/PRD.md`의 «컬렉션 상세» 절에 이 정리를 한 줄 더한다.

## 상세 요구사항

- 트라이브 저장(PUT/POST)은 `background_color`·`background_animation`을 더 보내지 않는다. PUT API는 `undefined` 필드를 기존 값으로 두고 POST는 `null`로 저장한다(2326과 같은 방식이다. 먼저 API 코드를 열어 확인하고, 다르면 멈추고 보고한다 `halted`).
- DB 칸(`tribes.background_color`·`background_animation`), API 라우트, `BackgroundGeneratorPreview`·`BackgroundColorField`·`BlobAnimationFields` 공용 부품은 지우지 않는다. 다른 곳이 쓰는지는 이번에 판단하지 않는다.
- `ItemBookHeroSection`·프레임을 import하는 곳이 남아 있으면 삭제하지 말고 멈추고 보고한다.
- 2326 브랜치와 겹치는 파일은 없어야 한다(2326은 `BadgeDetail`·`BadgeForm`·`badge-sections`·`ItemBookForm`을 고친다).

## 구현 계획

1. `TribeForm.tsx`에서 배경 카드·state·검증·전송 필드·불필요 import를 걷는다.
2. 프레임·`ItemBookHeroSection`·그 시험 둘을 지운다.
3. 남은 참조(주석·문서)를 고친다.
4. `scripts/verify.sh` 통과.

## 완료 조건

- `ItemBookDetailPreviewFrame`·`ItemBookHeroSection`과 그 시험 둘이 없고, 저장소 어디서도 그 이름을 import하지 않는다(주석 포함 남은 언급이 사실과 맞다).
