# [UI] 서비스·어드민 뒤로가기 시 탭·필터 상태 유지

## 핵심 요약

- 요구사항: 서비스(`(main)`)와 어드민(`admin`) 전반에서 목록의 탭·필터·검색·정렬·페이지를 선택한 뒤 상세/편집 화면에 들어갔다가 상단 뒤로가기(`TopNav <`, 어드민 `← 목록`/`취소`) 또는 브라우저 뒤로가기를 누르면 직전 목록의 탭·필터·페이지 상태로 정확히 돌아가게 한다. 직접 링크/새 탭 진입 시에는 기존 목록 경로로 안전하게 폴백한다.
- 구현 계획:
  1. 공용 앱 내 히스토리 깊이 추적기(`appHistory.ts`, `AppHistoryTracker.tsx`)와 Next.js 16 안전 URL 쿼리 갱신 헬퍼(`urlQueryState.ts`의 `replaceUrlQuery`·`pushUrlQuery`)를 도입하고 `app/layout.tsx`에 마운트한다.
  2. 서비스 `TopNav`의 `backHref`를 «앱 내 히스토리 없음 시 폴백»으로 전환(앱 내 이동 시 `router.back()`, 명시적 `onBack` 우선)하고, 배지 목록(`BadgesClient`)·프로필(`ProfileClient`)의 해시 탭을 `?tab=` 쿼리로 승격하며(기존 `#collection`·`#poi`·`#followers` 등 구 주소 호환 유지), 배지·미션·피드의 탭·필터를 `searchParams`와 동기화한다.
  3. 어드민 공용 뒤로가기 링크(`AdminBackLink.tsx`)와 `goBackOrPush`를 도입해 상세/편집/신규 화면의 `← 목록`·`취소`가 직전 목록의 쿼리(탭·필터·검색·정렬·쪽)를 유지한 채 돌아가게 하고, `PolicyDashboardClient`·`OpsBundleWorkspace`·`OpsScheduleBoard`의 탭·필터·`replaceState` 처리를 공용 규칙으로 맞춘다.
- 관련 파일:
  - 공용: `jam-web/src/lib/appHistory.ts`, `jam-web/src/components/AppHistoryTracker.tsx`, `jam-web/src/lib/urlQueryState.ts`, `jam-web/src/app/layout.tsx`
  - 서비스: `jam-web/src/components/ui/TopNav.tsx`, `jam-web/src/app/(main)/badges/BadgesClient.tsx`, `jam-web/src/app/(main)/badges/page.tsx`, `jam-web/src/app/(main)/collections/page.tsx`, `jam-web/src/app/(main)/collections/[id]/page.tsx`, `jam-web/src/app/(main)/badges/[id]/page.tsx`, `jam-web/src/app/(main)/missions/MissionsListClient.tsx`, `jam-web/src/app/(main)/FeedSection.tsx`, `jam-web/src/app/(main)/profile/ProfileClient.tsx`
  - 어드민: `jam-web/src/components/admin/AdminBackLink.tsx`, 어드민 상세/편집/신규 페이지 `← 목록` 링크 및 폼 `취소` 버튼, `jam-web/src/components/admin/policyDashboard/PolicyDashboardClient.tsx`, `jam-web/src/app/admin/policy-dashboard/page.tsx`, `jam-web/src/components/admin/ops/OpsBundleWorkspace.tsx`, `jam-web/src/app/admin/ops-schedule/OpsScheduleBoard.tsx`
  - 문서: `docs/service/prd/01_PRD.md`

## 배경 / 문제 정의

유저가 «배지 > 컬렉션 탭 > 컬렉션 상세» 순서로 들어간 뒤 `TopNav`의 `<` 또는 브라우저 뒤로가기를 누르면 컬렉션 탭이 아니라 기본 탭(액티비티 배지)으로 돌아가는 문제가 서비스 전반과 어드민 서비스에서 동일하게 발생하고 있다.

원인 분석 결과, 서비스와 어드민 모두 세 가지 구조적 원인이 겹쳐 있었다.
1. **하드코딩된 뒤로가기 경로가 히스토리를 덮어씀**:
   - 서비스 `TopNav.tsx`는 `backHref`가 있으면 무조건 `router.push(backHref)`를 호출해 직전 화면의 쿼리·스크롤을 버리고 히스토리 핑퐁을 만든다(`collections/[id]`의 `backHref="/badges#collection"`, `MissionDetailClient`의 `backHref="/missions"`, `today/[cardId]`의 `backHref="/"` 등).
   - 어드민 상세/편집/신규 화면의 `← 컬렉션`, `← 배지`, `← 운영플랜`, `← 유저 목록`, `← 미션`, `← 체크인`, `← 패턴` 등과 폼의 `취소` 버튼이 쿼리 없는 고정 경로(`<Link href="/admin/...">`, `router.push('/admin/...')`)로 이동해, 목록에서 `useListParams`로 쌓아 둔 탭·검색·필터·정렬·페이지가 전부 초기화된다. 반대로 `BadgeDetail`의 `← 뒤로`는 폴백 없는 `router.back()`이라 새 탭 직접 진입 시 동작하지 않는다.
2. **해시 기반 탭과 `clearHashOnNavigate`·`clearProfileHash`로 인한 상태 소실**:
   - `BadgesClient.tsx`는 탭을 `#collection` 해시에 저장하고, 배지 상세 이동 직전에 `clearHashOnNavigate()`로 해시를 지워 뒤로가기 시 무조건 `activity` 탭으로 초기화된다. 또한 서버 컴포넌트(`badges/page.tsx`)는 해시를 읽지 못한다.
   - `ProfileClient.tsx` 역시 팔로워/팔로잉 행 클릭 시 `clearProfileHash()`로 `#followers` 해시를 지워 타인 프로필에서 돌아올 때 목록 탭이 풀린다.
3. **일회성 `useState` 초기화 및 미저장 클라이언트 상태**:
   - `MissionsListClient`·`FeedSection`은 `useState(() => readEnumParam(...))`로 최초 1회만 쿼리를 읽어 클라이언트 복원·URL 변경 시 탭이 어긋날 수 있고, 배지/미션의 드롭다운 필터는 URL에 실리지 않아 상세에서 돌아오면 초기화된다.
   - 어드민 `PolicyDashboardClient`의 탭·검색어와 `OpsBundleWorkspace`의 항목 필터 탭이 `useState`에만 있어 다른 화면(밸런스 설정 등)으로 이동했다가 돌아오면 초기화된다. `OpsBundleWorkspace`·`OpsScheduleBoard`는 `window.history.replaceState(null, ...)`를 직접 호출한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- **앱 내 히스토리 추적(`appHistory.ts` + `AppHistoryTracker.tsx`)**:
  - `window.history.pushState`·`replaceState`·`popstate`를 통해 현재 탭 세션에서 앱 내부 이동으로 쌓인 깊이(`__jamNavIdx`)를 추적한다.
  - 새 탭/직접 URL 진입/외부 유입(`document.referrer`가 타 오리진이거나 `window.history.length <= 1`)은 깊이 `0`(`canGoBackInApp() === false`)으로 판정해 앱 바깥으로 이탈하거나 무반응이 되지 않게 한다.
  - 새로고침(F5) 뒤에도 브라우저가 보존한 `history.state.__jamNavIdx`를 읽어 직전 앱 내 화면으로 정상 복귀할 수 있게 한다.
  - `replaceState` 호출은 깊이를 증가시키지 않고 현재 `__jamNavIdx`를 유지한다.
- **URL 쿼리 갱신(`urlQueryState.ts`)**:
  - `replaceUrlQuery(nextHref)`·`pushUrlQuery(nextHref)`를 제공한다. Next.js 16 App Router의 `history.replaceState`/`pushState` 패치가 `copyNextJsInternalHistoryState`와 `useSearchParams()` 동기화를 정상 수행하도록 `__NA`/`_N`/`__PRIVATE_NEXTJS_INTERNALS_TREE`를 제외한 커스텀 상태(`__jamNavIdx` 등)만 유지해 호출한다.
- **서비스(`(main)`)**:
  - `TopNav`: `onBack` > 앱 내 히스토리 존재 시 `router.back()` > 폴백 `backHref ?? '/'` 순으로 동작한다. 알림함에서 진입한 타인 프로필(`?from=notifications`)은 기존대로 `onBack`으로 `/notifications` 직접 복귀를 유지한다.
  - `BadgesClient` + `badges/page.tsx` + `collections/page.tsx` + `collections/[id]/page.tsx`: 탭 정본 URL을 `/badges?tab=checkin|collection`(기본 `activity`는 쿼리 없음)으로 통일하고, 구 주소(`#collection`, `#checkin`, `#activity`, `#poi`, `?tab=poi`) 진입 시 정상 탭으로 복원·정규화한다. `clearHashOnNavigate()`를 제거한다. 액티비티/체크인 드롭다운 필터(`activity`, `rarity`, `category`, `sort`)도 `replaceUrlQuery`로 URL 쿼리에 동기화한다(기본값 생략, 다른 탭 전환 시 이전 탭 전용 필터는 정리).
  - `MissionsListClient`: `tab`·`sort`·`activity`를 `searchParams`와 동기화하고 `replaceUrlQuery`로 갱신한다(불필요한 서버 재요청 제거).
  - `FeedSection`: `activeFilter`를 `searchParams`와 동기화하고 `replaceUrlQuery`로 갱신한다(프로필 `?u=`·`?from=` 등 다른 쿼리 보존).
  - `ProfileClient`: `#followers`·`#following`·`#points` 해시 탭을 `?tab=followers|following|points` 쿼리(`pushUrlQuery`)로 전환하고, 구 해시 링크 호환을 유지한다. 팔로워/팔로잉 행 클릭 시 해시 제거 꼼수를 없애 타인 프로필에서 돌아와도 목록 탭이 유지되게 한다.
- **어드민(`admin`)**:
  - `AdminBackLink`: `<Link href={fallbackHref}>`를 렌더해 새 탭 열기/우클릭/SSR 링크 시맨틱을 유지하면서, 일반 클릭 시 `canGoBackInApp()`가 참이면 `router.back()`으로 직전 목록의 탭·필터·검색·정렬·쪽을 그대로 복원한다.
  - 상세/편집/신규 화면의 모든 `← 목록` 링크와 `BadgeDetail`의 `← 뒤로`, 폼 `취소` 버튼에 `AdminBackLink` / `goBackOrPush`를 적용한다(저장·삭제 후 리다이렉트는 기존 동작 유지).
  - `PolicyDashboardClient`의 탭(`?tab=`)과 검색어(`?q=`), `OpsBundleWorkspace`의 항목 필터(`?filter=`)를 URL 쿼리에 동기화하고 `OpsBundleWorkspace`·`OpsScheduleBoard`의 `replaceState`를 `replaceUrlQuery`로 통일한다.

### UI/UX 관점
- 기존 화면 디자인·레이아웃·문구 변경 없음.
- 탭/필터 전환 시 서버 재요청으로 인한 깜빡임이나 스크롤 튐이 없어야 한다.

### 컨텐츠 관점
- 새 사용자 노출 문구 없음. `docs/service/prd/01_PRD.md`의 배지·프로필 URL 규칙 설명을 최신 동작에 맞게 갱신한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `배지 > 컬렉션 탭 > 컬렉션 상세`에서 `TopNav <` 및 브라우저 뒤로가기 모두 `컬렉션` 탭(`/badges?tab=collection`)으로 돌아간다. 체크인 탭·액티비티 필터·미션 탭/필터·피드 필터·프로필 팔로워/팔로잉 탭에서도 동일하게 상태가 유지된다.
- 기존 구 주소(`/badges#collection`, `/badges#poi`, `/badges?tab=poi`, `/collections`, `/[username]#followers`)가 깨지지 않고 해당 탭으로 열린다.
- 직접 링크/새 탭으로 상세 화면에 진입했을 때 `TopNav <` 및 어드민 `← 목록`·`취소`가 폴백 경로로 안전하게 이동한다.
- 어드민에서 필터·탭·검색·페이지가 적용된 목록(`/admin/itembooks?status=...&page=2`, `/admin/ops-inbox?tab=reviewing`, `/admin/badges?type=item`, `/admin/policy-dashboard?tab=admin_link` 등)에서 상세/편집 화면으로 들어갔다가 `← 목록`·`취소` 또는 브라우저 뒤로가기를 누르면 직전 탭·필터·페이지가 유지된다.
- 신규 단위 테스트(히스토리 추적기, `urlQueryState`, `TopNav`, `BadgesClient`, `MissionsListClient`, `FeedSection`, `ProfileClient`, `AdminBackLink`, `PolicyDashboardClient`) 및 기존 영향 테스트, `npm run test:node`, `lint:ci`, `typecheck`, `ds:check`, 계약/슬롭 검사가 모두 통과한다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`에서 서비스(배지→컬렉션 상세→뒤로, 미션→상세→뒤로, 프로필 팔로워→타인→뒤로, 직접 진입 폴백)와 어드민(컬렉션/배지/운영플랜/정책 대시보드 필터→상세→뒤로, 새 탭 직접 진입 폴백)의 실화면 동작을 확인한다.
