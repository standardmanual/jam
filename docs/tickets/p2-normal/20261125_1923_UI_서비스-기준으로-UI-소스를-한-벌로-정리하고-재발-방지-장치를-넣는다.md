## 핵심 요약

- 요구사항 (사용자, 2026-11-25): 현재 staging 서비스를 기준으로 컴포넌트 정본을 완성하고, 이 기준에서 쓰이지 않는
  토큰·값(지워도 영향이 없는 것)을 모두 지워 소스 탐색 부담을 없앤다. 이어서 ① jam-work 개선 ② 서비스 소스 체계
  최적화 ③ 스토리북 기존 데이터를 지우고 서비스 기준으로 다시 정리 ④ 재발 방지 규칙 최적화 ⑤ 쌓인 규칙·원칙 문서
  정리가 가능한지 묻는다.

   컴포넌트·토큰으로 바꾼다. 실제 서비스 화면은 바뀌지 않아야 한다(전후 화면 캡처 비교). 기준선은 0이 되면 지우고
   규칙을 예외 없는 규칙으로 바꾼다.
3. **관문은 토큰만이 아니라 UI 개발 전 과정에 건다.** 클로드 코드(메인 세션·서브에이전트)가 DS·스토리북을 거치지 않고
   독단으로 UI를 새로 코딩하지 못하게 한다. 구체 장치:
   - 화면 코드(`src/app/**`의 서비스 경로, 도메인 컴포넌트)는 정본 컴포넌트를 조합하고 배치만 한다. 색·글자·모서리·

     실측한다.
   - 채원①은 컴포넌트 목록(스토리북 기준) 밖의 것을 쓰려면 승인 필요로 올리고, 민지는 목록 밖 사용을 FAIL로 본다.
   - 어드민 화면은 기존 정책대로 범위 밖이다(shadcn 표준).
4. **사용자 메모리는 로컬이 아니라 프로젝트(저장소)에 정의한다** (사용자, 2026-11-25). 지금은 카리나가 저장소 밖
