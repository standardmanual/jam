# [UI] 서비스 기준으로 UI 소스를 한 벌로 정리하고 재발 방지 장치를 넣는다 (상위)

## 핵심 요약

- 요구사항 (사용자, 2026-11-25): 현재 staging 서비스를 기준으로 컴포넌트 정본을 완성하고, 이 기준에서 쓰이지 않는
  토큰·값(지워도 영향이 없는 것)을 모두 지워 소스 탐색 부담을 없앤다. 이어서 ① jam-work 개선 ② 서비스 소스 체계
  최적화 ③ 스토리북 기존 데이터를 지우고 서비스 기준으로 다시 정리 ④ 재발 방지 규칙 최적화 ⑤ 쌓인 규칙·원칙 문서
  정리가 가능한지 묻는다.
- 판단: 다섯 가지 모두 가능하다. 다만 순서가 중요하다 — 측정 도구 → 새 이탈 차단 → 삭제 → 단일화 → 스토리북 →
  나머지 장치 → 문서 정리 순으로 간다. 문서 정리를 마지막에 두는 이유는, 앞 단계에서 장치로 옮겨 간 규칙 문장이
  확정돼야 지울 문장이 정해지기 때문이다.
- 근거 조사: 티켓 20261125_1848 (방법론 조사와 방향 제안). 사용자가 그 티켓의 결정 1을 «서비스 기준 정본»으로 답했다.
