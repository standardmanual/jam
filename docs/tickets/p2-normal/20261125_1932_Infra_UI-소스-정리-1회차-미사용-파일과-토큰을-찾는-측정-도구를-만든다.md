# [Infra] UI 소스 정리 1회차: 미사용 파일과 토큰을 찾는 측정 도구를 만든다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923의 3·4회차(삭제)에서 «무엇을 지워도 되는가»의 근거가 될 측정 도구 두 개를 만든다.
  ① 미사용 파일·export·의존성 검사(knip) ② CSS 변수(토큰) 사용 스캐너. **이번 회차는 도구만 만들고 아무것도 지우지
  않는다.** `verify.sh`에도 넣지 않는다(관문 연결은 2·8회차).
- 구현 계획: 아래 「구현 계획」의 파일 5개.
- 관련 파일: `jam-web/package.json`(scripts·devDependencies), `jam-web/package-lock.json`(기계 생성),
  `jam-web/knip.json`(신규), `jam-web/scripts/token-usage.mjs`(신규), `jam-web/scripts/__tests__/tokenUsage.test.ts`(신규)

## 배경 / 문제 정의

상위 티켓 측정에서 MODULAR 컴포넌트 13개가 스토리·시험에서만 쓰이고, CSS 변수 462개 중 178개가 실행 코드에서 쓰이지
않는 후보로 나왔다. 그 측정은 카리나가 일회성 파이썬으로 한 것이라 다시 돌릴 수 없고, 동적 클래스 조합을 못 잡는다.
삭제 회차가 같은 기준으로 반복 측정할 수 있도록 저장소 안의 도구로 만든다.

## 구현 계획

1. **knip 도입** — `jam-web`에 `knip`을 devDependency로 추가하고 `jam-web/knip.json`을 만든다.
   - Next.js(app router)·Storybook·Vitest 플러그인을 켜서 라우트 파일·스토리·시험을 진입점으로 인식시킨다.
   - `design-system/**`의 `.jsx`+`.d.ts` 컴포넌트와 경로 별칭(`@ds/`, `@/`)을 해석하게 한다.
   - `package.json`에 `"audit:unused": "knip"`과 기계 판독용 `"audit:unused:json": "knip --reporter json"`을 더한다.
   - 결과에서 미사용 파일·미사용 export·미사용 의존성이 나오면 된다. 오탐이 나오는 진입점(예: `scripts/`의 일회성 스크립트,
     `public/`)은 `ignore`로 빼고, 무엇을 왜 뺐는지는 티켓 완료 기록에 적는다.
2. **토큰 사용 스캐너** — `jam-web/scripts/token-usage.mjs` (Node 표준 라이브러리만).
   - 정의 수집: `design-system/tokens/*.css`, `design-system/styles.css`, `src/**/*.css`의 `--이름: 값;`. `@theme` 블록
     안 정의인지 표시한다.
   - 사용 수집: `src/`·`design-system/`·`.storybook/`의 코드·CSS에서 정의 자리를 뺀 `--이름` 등장. 파일 종류를
     실행 코드 / 시험·스토리로 나눈다.
   - `@theme` 변수는 Tailwind 유틸리티 사용(`--color-surface` → `bg-surface`·`text-surface` 등, 네임스페이스 color·text·
     font·font-weight·leading·tracking·radius·shadow·spacing·ease·animate·blur)도 사용으로 센다.
   - 다른 변수의 값에서 참조되는 변수는 참조하는 쪽이 살아 있을 때만 산 것으로 본다(고정점 반복).
   - 템플릿 문자열로 클래스를 조합하는 곳(`` `bg-${…}` ``, `` `text-jam-${…}` `` 처럼 접두만 보이는 경우)이 있으면 그 접두에
     걸리는 변수는 «확인 필요»로 따로 분류한다(삭제 후보에 넣지 않는다).
   - 분류: `used`(실행 코드) / `test-only`(시험·스토리만) / `unused` / `needs-review`(동적 조합 의심). 정의 파일별 집계와
     이름 목록을 사람이 읽는 표로 출력하고, `--json`이면 JSON으로 출력한다.
   - `package.json`에 `"audit:tokens": "node scripts/token-usage.mjs"`를 더한다.
3. **시험** — `jam-web/scripts/__tests__/tokenUsage.test.ts`: 임시 폴더에 작은 CSS·TSX 픽스처를 만들어 네 분류
   (`used`·`test-only`·`unused`·`needs-review`)와 `@theme` 유틸리티 인식, 값 참조 고정점을 각각 확인한다. 스캐너는 검사
   루트를 인자(`--root`)로 받게 해서 시험이 실제 저장소를 읽지 않게 한다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `npm run audit:unused`가 오류 없이 끝나고 미사용 파일·export·의존성 목록을 출력한다.
- `npm run audit:tokens`가 정의 파일별 «정의 수 / used / test-only / unused / needs-review» 표를 출력하고, `--json`이 같은
  내용을 JSON으로 낸다.
- 두 도구가 어떤 파일도 수정·삭제하지 않는다(읽기 전용).
- `tokenUsage.test.ts`가 네 분류·`@theme` 유틸리티·값 참조 고정점을 확인하고 통과한다.
- `scripts/verify.sh` 전체 통과. 서비스 화면 코드(`src/app/**`, `src/components/**`)와 토큰 파일은 바뀌지 않는다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 두 도구를 staging에서 돌린 결과 요약(분류별 개수, 상위 티켓 측정값과의 차이)을 상위 티켓 20261125_1923에 남긴다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `knip`을 devDependency로 추가하고 `jam-web/knip.json`을 만들었다. `npm run audit:unused`(사람용)·
  `audit:unused:json`(기계용)은 `--no-exit-code`로 발견 항목이 있어도 종료 코드 0이다(측정 도구라서).
- `jam-web/scripts/token-usage.mjs`(Node 표준 라이브러리만, 읽기 전용, `--root`·`--json`)와 `npm run audit:tokens`를 더했다.
  분류는 used / test-only / unused / needs-review(템플릿 접두로 동적 조합되는 변수)다.
- knip `ignore`에서 뺀 경로와 이유: `public/**`, `scripts/asset-generator/**`, `scripts/badge-image-gen/**`,
  `scripts/recraft/**`, `scripts/jam2-content/**` — 사람이 손으로 실행하는 일회성 스크립트라 진입점이 없어 전부
  미사용으로 잡히기 때문이다.
- 아무것도 지우지 않았고 `verify.sh`에도 연결하지 않았다.

### 주요 의사결정 / 핵심 메모
- 계획 반환 면제를 첫 호출부터 넣었다. 파일 5개가 계획에 확정돼 있었고 줄 수 대부분이 `package-lock.json` 기계 생성분이었다.
- 티켓이 로컬 staging에만 있어 로컬 리뷰 브랜치를 `retryBranch`로 넘겼다. 아현이 그 브랜치를 원격에 처음 올렸다.
- 아현은 작업 폴더의 `node_modules` 링크를 지우고 `npm ci`로 실제 설치한 뒤 knip을 추가했다. 메인 폴더의
  `node_modules`에는 knip이 없으므로, 메인 폴더에서 `audit:unused`를 돌리려면 먼저 `npm install`이 필요하다.
- 민지 범위 밖 발견물 2건(참고)은 별도 티켓 대신 상위 티켓의 해당 회차에 넣었다: 스캐너가 문자열 연결
  (`'--x-' + y`)로 만든 이름을 못 잡는 사각지대(4회차 삭제 전 확인), `knip.json` 24행 ignore 줄 정렬(2회차).
