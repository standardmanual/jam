# [Infra] UI 소스 정리 2-1회차: DS 밖 값을 잡는 규칙 엔진과 기준선을 만든다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 2회차(관문 1차)의 첫 조각. 서비스 화면 소스에서 DS 밖 값을 찾는 **규칙 엔진 하나**를
  만들고, 지금 있는 위반은 파일별 기준선으로 동결한 뒤 `verify.sh`에 연결한다. 이 엔진은 다음 조각(2-2: 파일을 쓰는 순간
  거절하는 클로드 코드 훅, pre-commit)이 그대로 불러 쓴다 — 규칙을 여러 곳에 따로 적지 않기 위해서다.
- 사용자 결정(2026-11-25): 기존 위반은 동결에서 멈추지 않고 7회차에서 0까지 고친다. 기준선은 그때까지의 임시 장치다.
- 서비스 화면은 바뀌지 않는다. 이번 조각은 검사 도구·기준선·설정만 바꾼다.
- 관련 파일: `scripts/check-ui-rules.mjs`(신규), `scripts/check-ui-rules.test.mjs`(신규), `scripts/ui-rules-baseline.json`(신규,
  생성물), `scripts/verify.sh`(136행 근처 spacing 단계 뒤에 한 단계 추가), `jam-web/knip.json`(ignore 정렬·의존성 오탐 제외)

## 배경 / 문제 정의

ESLint에 서비스 화면용 DS 규칙이 없고, 차단형 검사는 간격(`scripts/check-spacing.mjs`) 하나뿐이다. 1회차 측정에서 서비스
화면 163개 파일에 임의값 Tailwind 173건, 인라인 style 212건, hex 리터럴 27건, 원시 `<button>` 29건이 나왔다.

## 구현 계획

`scripts/check-spacing.mjs`의 구조(대상 폴더·건너뛸 폴더·파일별 기준선·`--write-baseline`·주석 예외)를 그대로 따른다.

1. **`scripts/check-ui-rules.mjs`** (Node 표준 라이브러리만)
   - 대상: `jam-web/src/app/(main)`, `(auth)`, `(onboarding)`, `(legal)`, `jam-web/src/components`의 `.tsx`·`.ts`·`.css`.
     건너뜀: `admin/`, `__tests__/`, `*.test.*`, `*.stories.*`, `spike/`, `dev-sample/`, `node_modules`. 토큰 정의 파일
     (`jam-web/design-system/tokens/*.css`, `jam-web/src/app/globals.css`)과 `jam-web/design-system/components/**`는 대상이 아니다.
   - 규칙 네 가지 (규칙 키는 기준선·출력에 그대로 쓴다):
     - `arbitrary` — Tailwind 임의값 클래스 `접두-[값]`. 값이 `var(--…)` 하나뿐이면 위반이 아니다. `data-[…]:`·`aria-[…]:`·
       `[&…]:` 같은 임의 **변형**(뒤에 `:`가 붙음)은 위반이 아니다. `check-spacing.mjs`가 이미 세는 간격 접두(`PREFIX`)의
       `[Npx]`는 중복을 피하려고 세지 않는다.
     - `color-literal` — 문자열·CSS 값 안의 `#rgb`~`#rrggbbaa`, `rgb(`·`rgba(`·`hsl(`·`hsla(`·`oklch(`. `//`·`*`로 시작하는
       주석 줄은 세지 않는다.
     - `inline-visual` — `style={{ … }}` 안에서 시각 속성(color, background, backgroundColor, borderColor, border, fontSize,
       fontWeight, lineHeight, letterSpacing, borderRadius, boxShadow, fontFamily)에 **리터럴 값**(숫자 또는 `var(`가 없는
       문자열)을 준 것. 변수·식(`tone.fg`)은 세지 않는다.
     - `raw-element` — JSX `<button`·`<input`·`<select`·`<textarea`. 정본 컴포넌트 폴더 `jam-web/src/components/ui/`
       안에서는 세지 않는다.
   - 예외: 같은 줄에 `ui-allow: <사유>` 주석이 있으면 세지 않는다(사유가 비면 예외가 아니다).
   - 기준선: `scripts/ui-rules-baseline.json`에 `{ "경로": { "규칙 키": 개수 } }`. 기준선보다 늘어난 파일·기준선에 없는 파일의
     위반은 실패(종료 코드 1), 줄어든 파일은 «기준선을 줄이세요» 안내만 낸다.
   - 실패 메시지에는 파일·줄·규칙 키와 **고치는 방법**을 적는다. 예: `arbitrary` → «토큰 클래스나 정본 컴포넌트의 variant를
     쓰세요. 맞는 토큰이 없으면 새로 만들지 말고 카리나에게 토큰 추가 승인을 요청하세요»; `raw-element` → «`@/components/ui`의
     정본 컴포넌트(Button 등)를 쓰세요».
   - 실행 방식:
     - 인자 없음 — 대상 전체 검사.
     - `--files <경로…>` — 주어진 파일만 검사(2-2의 pre-commit용).
     - `--stdin-file <경로>` — 표준 입력의 내용을 그 경로의 새 내용으로 보고 검사(2-2의 클로드 코드 훅용, 디스크를 읽지 않음).
     - `--write-baseline` — 현재 개수로 기준선을 다시 쓴다.
     - `--json` — 결과를 JSON으로 낸다.
     - `--root <dir> --baseline <file>` — 시험용.
   - 경로는 저장소 루트 기준으로 정규화한다. 한글 경로는 NFC로 맞춘다(설정값 NFC·git 경로 NFD 차이).
2. **`scripts/check-ui-rules.test.mjs`** — `check-spacing.test.mjs`와 같은 방식(임시 폴더 픽스처). 규칙 네 가지 각각의 위반·
   비위반 사례, `var(--…)` 허용, 임의 변형 비위반, 간격 접두 중복 제외, `ui-allow` 예외(사유 없으면 무효), 기준선 초과·감소,
   `--files`·`--stdin-file` 모드를 확인한다.
3. **`scripts/ui-rules-baseline.json`** — `--write-baseline`으로 생성한다.
4. **`scripts/verify.sh`** — spacing 단계(136행 근처) 바로 뒤에 같은 형식으로 `check-ui-rules` 단계를 넣고, 마지막 «verify 통과»
   줄의 목록에 `ui-rules`를 더한다.
5. **`jam-web/knip.json`** — 24행 근처 `ignore` 배열을 한 항목씩 줄을 나눠 정렬한다(1회차 민지 참고 발견물). `tailwindcss`·
   `tw-animate-css`가 CSS `@import`로 쓰이는데 미사용 의존성으로 잡히는 오탐을 `ignoreDependencies`로 뺀다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `node scripts/check-ui-rules.mjs`가 현재 staging에서 종료 코드 0으로 끝난다(기준선과 같음).
- 대상 파일에 `text-[13px]`, `'#ff0000'`, `style={{ color: '#000' }}`, `<button` 중 하나를 새로 넣으면 종료 코드 1과 함께
  파일·줄·규칙 키·고치는 방법이 출력된다(시험으로 확인).
- `--stdin-file`이 디스크를 읽지 않고 표준 입력 내용으로 판정한다(시험으로 확인).
- `ui-allow:` 뒤 사유가 있을 때만 예외가 된다(시험으로 확인).
- `scripts/verify.sh`가 이 검사를 돌리고 전체 통과한다.
- `npm run audit:unused`에서 `tailwindcss`·`tw-animate-css`가 더 이상 미사용 의존성으로 나오지 않는다.
- 서비스 화면 코드(`jam-web/src/app/**`, `jam-web/src/components/**`)와 토큰 파일은 바뀌지 않는다.
