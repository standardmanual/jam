# [Infra] UI 소스 정리 2-2회차: DS 밖 UI를 쓰는 순간 거절하는 훅을 건다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 2회차(관문 1차)의 둘째 조각. 클로드 코드(메인 세션·서브에이전트)가 서비스 화면 파일을
  `Write`·`Edit`·`MultiEdit`로 쓰려는 **순간에** 2-1의 규칙 엔진(`scripts/check-ui-rules.mjs --stdin-file`)으로 새 내용을 판정해,
  DS 밖 값이 늘면 쓰기 자체를 거절한다(`PreToolUse` 훅, 종료 코드 2). 셸(Bash)로 쓴 변경은 이 훅에 걸리지 않으므로
  `.githooks/pre-commit`에도 같은 엔진을 연결해 커밋 단계에서 막는다.
- 사용자 결정(2026-11-25): 클로드 코드가 UI 개발 전 과정에서 DS·스토리북을 거치지 않고 독단으로 UI를 새로 코딩하지 못하게 한다.
- 서비스 화면은 바뀌지 않는다.
- 관련 파일: `.claude/hooks/ui-guard.mjs`(신규), `scripts/ui-guard.test.mjs`(신규 — `verify.sh` 59행의 `scripts/*.test.mjs`
  순회에 잡히는 위치), `.claude/settings.json`(`hooks`에 `PreToolUse` 항목 추가, 기존 `SessionStart`는 그대로),
  `.githooks/pre-commit`(494행 `exit 0` 바로 앞에 한 단계 추가)

## 배경 / 문제 정의

2-1로 DS 밖 값이 늘면 `verify.sh`가 실패하게 됐지만, 그 검사는 작업이 끝난 뒤 돈다. 그 사이 에이전트는 이미 DS 밖 코드를 써
놓고 나중에 고치거나 기준선을 올리려 한다. 쓰는 순간 거절하면 에이전트는 그 자리에서 정본 컴포넌트·토큰으로 다시 쓴다.

## 구현 계획

1. **`.claude/hooks/ui-guard.mjs`** (Node 표준 라이브러리만)
   - 표준 입력의 훅 JSON(`tool_name`, `tool_input`)을 읽는다. `tool_name`이 `Write`·`Edit`·`MultiEdit`가 아니면 종료 코드 0.
   - `tool_input.file_path`(절대 경로)에서 위로 올라가며 `scripts/check-ui-rules.mjs`가 있는 폴더를 저장소 루트로 삼는다.
     **`$CLAUDE_PROJECT_DIR`이 아니라 편집 대상 파일 기준**으로 찾는다 — 서브에이전트는 별도 작업 폴더(워크트리)에서 파일을 쓰고,
     그 폴더의 규칙·기준선으로 판정해야 하기 때문이다. 못 찾으면 종료 코드 0.
   - 새 내용 계산: `Write`는 `content`. `Edit`는 현재 파일을 읽어 `old_string`을 `new_string`으로 바꾼다(`replace_all`이면 전부,
     아니면 첫 번째). `MultiEdit`는 `edits`를 순서대로 적용한다. 파일이 없거나 `old_string`이 없으면 종료 코드 0(도구가 알아서 실패한다).
   - `node <루트>/scripts/check-ui-rules.mjs --stdin-file <루트 기준 상대 경로>`에 새 내용을 표준 입력으로 넘긴다(작업 폴더 = 루트).
     - 종료 코드 0 → 0(허용).
     - 종료 코드 1 → 엔진 출력에 «이 편집은 거절됐습니다. 정본 컴포넌트(`jam-web/src/components/ui/`)와 DS 토큰으로 다시 쓰세요.
       기준선을 올리거나 `ui-allow`를 붙여 피하지 말고, 맞는 컴포넌트·토큰이 없으면 멈추고 카리나에게 승인을 요청하세요»를 붙여
       표준 오류로 내고 **종료 코드 2**(거절).
     - 엔진 실행 자체가 실패(예외·다른 종료 코드) → 표준 오류에 원인 한 줄, 종료 코드 1(차단하지 않는 경고). 검사기 고장으로 모든
       편집이 막히는 것을 피한다. 이때도 `verify.sh`·pre-commit이 뒤에서 막는다.
2. **`.claude/settings.json`** — `hooks.PreToolUse`에 `matcher: "Write|Edit|MultiEdit"`, 명령
   `node "$CLAUDE_PROJECT_DIR/.claude/hooks/ui-guard.mjs"` 항목을 더한다. 기존 `SessionStart` 항목과 다른 설정은 바꾸지 않는다.
3. **`.githooks/pre-commit`** — `exit 0` 바로 앞에 단계 하나: 스테이징된 파일(추가·수정) 목록을 `scripts/check-ui-rules.mjs --files`에
   넘겨 종료 코드 1이면 «차단(pre-commit): …» 메시지와 함께 커밋을 막는다. 대상 밖 파일은 엔진이 알아서 통과시킨다. 파일명 공백은
   기존 단계처럼 NUL 구분으로 다룬다. 우회 환경변수는 두지 않는다.
4. **`scripts/ui-guard.test.mjs`** — 임시 폴더에 작은 저장소 구조(`scripts/check-ui-rules.mjs`는 실제 파일을 복사, 기준선은 빈
   객체)를 만들고 훅 JSON을 표준 입력으로 넣어 확인한다: 대상 파일 `Write`에 `text-[13px]` → 종료 코드 2·표준 오류에 규칙 키,
   깨끗한 `Write` → 0, `Edit`로 위반을 더함 → 2, `Edit`로 위반을 뺌 → 0, `MultiEdit` 순차 적용, 어드민 경로 → 0, `Read` 등 다른 도구
   → 0, 저장소 루트를 못 찾음 → 0, 엔진 고장(일부러 깨진 엔진) → 1.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `scripts/ui-guard.test.mjs`의 9가지 경우가 통과하고 `verify.sh`의 scripts-test 단계에 잡힌다.
- `.claude/settings.json`이 유효한 JSON이고 `PreToolUse` 항목이 위 명령을 가리킨다. 기존 `SessionStart` 항목은 바뀌지 않는다.
- `.githooks/pre-commit`이 스테이징된 서비스 화면 파일에 DS 밖 값이 늘면 커밋을 막고, 그 밖의 커밋에는 영향이 없다(시험 또는 실행 기록으로 보인다).
- `scripts/verify.sh` 전체 통과. 서비스 화면 코드와 토큰 파일은 바뀌지 않는다.

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 훅 설정은 세션을 시작할 때 읽히므로 이 세션에서는 실측할 수 없다. 머지 뒤 이 설정이 들어간 폴더에서 새 세션을 열어, 메인 세션과
  서브에이전트가 각각 위반 코드를 쓰려 할 때 거절되는지 실측하고 결과를 상위 티켓에 남긴다.
- 세션이 여는 메인 폴더가 이 커밋을 포함한 브랜치여야 훅이 켜진다. 지금 메인 폴더는 이미 머지된 리뷰 브랜치(1650)에 있으므로,
  메인 폴더를 staging으로 되돌리는 방법을 사용자에게 확인한다.

### 주요 의사결정 / 핵심 메모
