## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 3회차(미사용 제거)의 마지막 조각. knip이 찾은 미사용 export·type 가운데 **경로에 `/admin/`이 든 파일**
  (`src/app/admin/**`, `src/components/admin/**`, `src/lib/admin/**` 등)의 것을 3-3a와 같은 방법으로 정리한다. 약 export 368·type 171건.
- 사용자 결정(2026-11-25): 지워도 영향이 없는 값은 모두 지운다. 3-3a(어드민 밖) 다음 조각으로 어드민을 한다(«3-3b 시작»).
- **화면·동작 변화가 없어야 한다.** `export`를 떼고, 그 결과 파일 안에서도 안 쓰이게 된 선언만 지운다.
- **제외: `src/components/admin/ui/**`(shadcn에서 가져온 부품 묶음, `components.json`의 `ui` 별칭).** 부품 라이브러리라 당장 안 쓰는 하위 부품도
  나중에 그대로 꺼내 쓰는 것이 정상 사용법이다. 내보내기를 떼지 않는다.
- 3-3a에서 일부러 남긴 어드민 밖 항목(`MISSION_DB_*`, `Assert*` 타입, DS 컴포넌트·`icons.tsx`, `combine/tierUp.ts`, `database.generated.ts`)은 다시 건드리지 않는다.
- 관련 파일: knip이 고르는 어드민 경로 파일(위 제외 폴더 빼고). 상위 폴더별 건수는 `src/components/admin/ops` 101, `src/lib/admin/opsInbox` 64,
  `src/lib/admin/opsPatterns` 39, `src/lib/admin/balance` 23, `src/app/admin/assets` 17, `src/lib/admin/opsSignals` 17 등(staging `88d43e846` 실측).

## 구현 계획

1. 브랜치에서 `cd jam-web && npx knip --fix --fix-type exports,types --no-exit-code`를 돌린다(파일 삭제 옵션은 쓰지 않는다).
2. **어드민 밖과 제외 폴더 되돌리기**: `git diff --name-only`에서 경로에 `/admin/`이 없는 파일, `src/components/admin/ui/` 아래 파일, 생성 파일
   (`database.generated.ts` 등)은 `git checkout -- <경로>`로 되돌린다.
3. **Next.js·Storybook 약속 이름 보호**: 3-3a와 같다 — `default`, `metadata`, `generateMetadata`, `generateStaticParams`, `viewport`, `generateViewport`,
   `dynamic`, `dynamicParams`, `revalidate`, `fetchCache`, `runtime`, `preferredRegion`, `maxDuration`, `GET`·`POST`·`PUT`·`PATCH`·`DELETE`·`HEAD`·`OPTIONS`,
   `config`, `middleware`, 스토리 파일의 모든 export. diff에서 떼어졌으면 되돌린다. `'use server'` 파일의 export(서버 액션)도 떼어졌으면 되돌린다.
4. 이중 export 중 어드민 파일 1건(`src/app/admin/assets/shapeStudioConfig.ts`의 `INITIAL_STATE`·`DEFAULT_STATE`)은 쓰이는 이름 하나만 남긴다.
5. `npm run lint`에서 새로 생긴 `no-unused-vars`(내보내기를 뗀 뒤 파일 안에서도 안 쓰이는 선언)를 지운다. 애매하면 남기고 보고한다.
6. `npm run typecheck`, `npm run lint:ci`(경고 기준선 26 이하), `npx knip --no-exit-code`로 어드민 경로(제외 폴더 빼고) 미사용 export·type이 0인지 확인.
   **워크트리 `node_modules`가 링크면 어드민 렌더 시험이 `Invalid hook call`로 실패하므로, 시작할 때 `npm ci --ignore-scripts`로 실제 설치한 뒤** `scripts/verify.sh`
   전체 통과를 확인한다.
7. **커밋 직후 `git status`로 스테이징 안 된 변경이 없는지 확인한다.** pre-commit의 문서 검사(예: 홈피드 PRD 동반 규칙)에 막히면 `JAM_SKIP_DOCLINT`로 우회하지 말고,
   변경을 스테이징한 채 `halted`로 돌아와 막힌 메시지를 그대로 보고한다(우회 여부는 사용자가 정한다).
