# [UI] UI 소스 정리 5-1회차: MODULAR 카드류 컴포넌트 8개를 서비스 정본 폴더로 옮긴다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 5회차(정본 단일화)의 첫 조각. `jam-web/design-system/components/cards/`의 컴포넌트 8개를 서비스 정본 폴더
  `jam-web/src/components/ui/`로 옮기고(.jsx + .d.ts → .tsx 하나), 이것들을 가져다 쓰는 곳(서비스·어드민·시험·스토리·다른 MODULAR 컴포넌트)의
  import를 모두 새 경로로 바꾼다.
- 사용자 결정(2026-11-25): 현재 staging 서비스 기준으로 컴포넌트 정본을 완성한다. 정본은 `src/components/ui/` 한 곳이다. **화면 변화는 없어야 한다.**
- 사용자 승인: 2026-11-25 상위 티켓의 승인 줄(«1~8·10회차에서 토큰·정본 컴포넌트를 지우고 옮기고 고치는 변경을 포함, 화면 변화 없음 전제»)에 해당한다.
- 대상 8개(줄 수는 .jsx 기준): `BadgeHeroSection`(115), `BadgeLevelChip`(53), `Card`(62), `CategorySticker`(421), `LabelChip`(54), `LockedTile`(43),
  `RarityBadge`(109), `SlotOutline`(351). 모두 `.d.ts`와 `.stories.tsx`가 있다. 서비스 `src/components/ui/`에 같은 이름의 파일은 없다.
- 이번 조각에서 옮기지 않는 것: 나머지 MODULAR 컴포넌트(5-2·5-3회차), 토큰(`design-system/tokens/`), 로고(`design-system/assets/`), 토큰 스토리(`design-system/foundations/`).

## 구현 계획

1. 시작할 때 `cd jam-web && npm ci --ignore-scripts`(링크 상태면 어드민 시험이 실패한다).
2. 컴포넌트마다:
   - `git mv design-system/components/cards/<이름>.jsx src/components/ui/<이름>.tsx`로 옮기고(이력 보존), 같은 이름의 `.d.ts`에 있던 props 타입을 `.tsx` 안으로
     옮긴 뒤 `.d.ts`를 지운다. **구현(마크업·스타일 객체·값·클래스)은 한 글자도 바꾸지 않는다.** `strict` 타입 오류가 나면 타입 표기만 더해서 맞춘다
     (`as` 남용 금지, 동작 변경 금지).
   - `<이름>.stories.tsx`를 `git mv`로 `src/components/ui/<이름>.stories.tsx`로 옮기고 import 경로만 고친다. 스토리 제목(`title`)은 바꾸지 않는다(6회차에서 정리).
3. 서로 참조:
   - `BadgeHeroSection` → `RarityBadge`·`BadgeLevelChip`: 같은 조각이라 새 경로(`./RarityBadge` 등)로 바꾼다.
   - `LockedTile` → `design-system/components/icons/IconCatalog.jsx`의 `LockIcon`: IconCatalog는 5-3회차에 옮긴다. 이번에는 `@ds/components/icons/IconCatalog`로
     가리키게 둔다(서비스 `icons.tsx`의 아이콘과 같은지 확인하지 않은 채 바꾸지 않는다).
   - 아직 옮기지 않은 MODULAR 컴포넌트(`BadgeRevealCarousel` 등)가 이번 8개를 상대 경로로 가져다 쓰면 `@/components/ui/<이름>`으로 바꾼다.
4. 가져다 쓰는 곳 전부(`src/**`, `design-system/**`, `.storybook/**`, 시험·스토리 포함)의 `@ds/components/cards/<이름>` 등 옛 경로를 `@/components/ui/<이름>`으로 바꾼다.
   `git grep -n "components/cards/"`가 0건이어야 한다(이 조각의 8개 기준).
5. **기준선**: 옮긴 파일은 이제 `check-ui-rules`·`check-spacing` 검사 대상 폴더에 들어온다. MODULAR에 있던 기존 위반을 옮겨 온 것이므로 **옮긴 8개 파일에 한해**
   `node scripts/check-ui-rules.mjs --write-baseline`·`node scripts/check-spacing.mjs --write-baseline`으로 기준선을 더하는 것을 허용한다(7회차에서 0으로 만든다).
   다른 파일의 기준선이 늘면 안 된다. 더한 파일·규칙별 건수를 `summary`에 적는다.
6. 두 벌 대조 시험(옛 MODULAR 사본과 서비스 사본을 `import * as`로 대조하던 것 등)이 대조 대상을 잃으면, 정본 하나를 검사하도록 바꾸거나 그 사례만 뺀다.
   `src/components/__tests__/dsLiteralColors.test.ts`가 `design-system/components`의 파일 개수 하한을 단언하면 하한을 실제 남은 개수에 맞춘다.
7. 검증: `npm run typecheck`, `npm run lint:ci`(경고 기준선 26 이하), `scripts/verify.sh` 전체 통과, `npm run build-storybook`(너무 오래 걸리면 스토리 시험으로 대신하고 적는다).
8. 커밋 직후 `git status`로 빠진 변경이 없는지 확인한다. 문서 검사에 막히면 우회하지 말고 스테이징한 채 `halted`로 돌아온다. push하지 않는다(사용자 push 금지 지시).
