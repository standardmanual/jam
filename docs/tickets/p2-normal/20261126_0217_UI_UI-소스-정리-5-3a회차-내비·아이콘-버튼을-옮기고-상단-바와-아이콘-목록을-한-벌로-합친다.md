# [UI] UI 소스 정리 5-3a회차: 내비·아이콘 버튼을 옮기고 상단 바와 아이콘 목록을 한 벌로 합친다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 5회차(정본 단일화)의 셋째 조각 앞부분. 남은 MODULAR 컴포넌트 중 **화면 변화 위험이 없는 것**을 정리한다.
  1. `IconButton`(buttons/), `Accordion`·`Carousel`(navigation/)을 5-1·5-2와 같은 방법으로 `src/components/ui/`로 옮긴다.
  2. 두 벌인 상단 바: 서비스 `src/components/ui/TopNav.tsx`가 MODULAR `TopNav`를 감싸 쓰고, `src/app/(legal)/LegalTopNav.tsx`는 MODULAR `TopNav`를 직접 쓴다.
     MODULAR `TopNav.jsx`의 구현을 그대로 `src/components/ui/TopNavBar.tsx`(이름 `TopNavBar`)로 옮기고 두 곳이 그것을 가리키게 한다.
  3. 두 벌인 아이콘: MODULAR `IconCatalog.jsx`의 아이콘은 서비스 `src/components/ui/icons.tsx`와 같은 이름으로 모두 있고(MODULAR에만 있는 export는 카탈로그
     표시용 `ICON`·`IconCatalog`뿐), `icons.test.tsx`·`coinIconPair.test.tsx`가 두 사본의 마크업이 같다고 대조한다. 사용처(`LockedTile`의 `LockIcon`,
     BadgeHeroSection 스토리의 `MedalIcon`, TopNav 스토리의 `BellIcon`)를 서비스 `icons`로 바꾸고 `IconCatalog.jsx`·`.d.ts`를 지운다.
  4. 5-1·5-2에서 옮긴 컴포넌트에 남은 옛 전제 주석(«원본은 design-system/components/…», «design-system은 서비스 lib를 import할 수 없어서…» 등)을 고친다.
- **이번 조각에서 하지 않는 것: `Button`(MODULAR) 정리.** `EmptyState`·`BadgeRevealCarousel`·spike 화면·어드민 일부가 MODULAR Button을 쓰며, 서비스 Button으로 바꾸면
  화면이 달라질 수 있어 5-3b회차에서 따로 확인한다. `ds:check` 정리도 5-3b.
- 사용자 승인: 상위 티켓의 승인 줄(2026-11-25)에 해당한다. 화면 변화는 없어야 한다.

## 구현 계획

5-1회차 티켓(20261126_0002)의 방법(실제 설치, `git mv`, `.d.ts` 합침, 구현 무변경, 스토리 함께 이동·제목 유지, 옮긴 파일만 기준선 추가 허용, `dsLiteralColors.test.ts`
목록 갱신, verify·스토리북 빌드, 커밋 직후 `git status`, 문서 검사 우회 금지, push 금지)을 따른다. 특유한 것:

1. **IconButton·Accordion·Carousel 이동**: `BadgeRevealCarousel.tsx`의 `@ds/components/buttons/IconButton` import는 `./IconButton`으로 바꾼다.
2. **상단 바**: `git mv design-system/components/navigation/TopNav.jsx src/components/ui/TopNavBar.tsx`, export 이름만 `TopNav` → `TopNavBar`로 바꾸고 구현은 그대로 둔다.
   `TopNav.stories.tsx`는 `TopNavBar.stories.tsx`로 옮긴다. 서비스 `TopNav.tsx`·`LegalTopNav.tsx`의 `import { TopNav as DsTopNav } from '@ds/components/navigation/TopNav'`를
   `import { TopNavBar as DsTopNav } from '@/components/ui/TopNavBar'`(별칭 이름은 그대로 두어 본문을 바꾸지 않는다)로 바꾼다. 서비스 `TopNav.tsx`의 다른 줄은 바꾸지 않는다.
3. **아이콘**: 먼저 `icons.test.tsx`·`coinIconPair.test.tsx`를 돌려 두 사본이 같음을 확인한 뒤, 사용처를 `@/components/ui/icons`로 바꾸고 `IconCatalog.jsx`·`.d.ts`를 지운다.
   두 시험은 서비스 `icons.tsx`가 사양(`docs/assets/prototypes/icon-set-v2/spec.json`)과 맞는지 계속 검사하도록 MODULAR 쪽 대조만 뺀다.
   아이콘 카탈로그 스토리(`IconCatalog.stories.tsx`)는 서비스 아이콘을 보여 주는 `src/components/ui/icons.stories.tsx`로 옮긴다. 카탈로그 그리드 컴포넌트는 스토리 파일 안에만
   둔다(정본 컴포넌트로 만들지 않는다). 품이 크면 스토리를 지우고 6회차(스토리북 재구성)로 넘긴 뒤 `summary`에 적는다.
4. **주석**: 위 4번 주석만 고친다(코드 줄은 바꾸지 않는다). 예: `BadgeGridCard.tsx:84`, `ListCard.tsx:10`, `ListRow.tsx:8`, `ListRow.test.tsx:4`, `LoadMoreButton.tsx:7`,
   `transitions.css:586`, `ItemSerialCode.tsx`·`BadgeRevealCarousel.tsx`의 «design-system은 서비스 lib를 import할 수 없어서» 주석(전제만 고치고 중복 훅 합치기는 7회차).
5. 옮긴 뒤 `design-system/components/`에는 `buttons/Button.*`만 남는다. `git grep -nE "components/(navigation|icons)/|buttons/IconButton"`이 코드·시험·스토리·`.storybook`에서 0건.
