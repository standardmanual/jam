# [Infra] UI 소스 정리 6-1b회차: 홈피드 PRD 동반 검사가 스토리와 동작 무변경 수정에는 걸리지 않게 한다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 6회차의 첫 조각 중 하나(6-1a 20261126_0947과 동시에 돈다, 겹치는 파일 없음). 사용자 승인(2026-11-26, «시작»):
  5회차 뒤 제안한 홈피드 PRD 동반 검사 개선 두 가지를 넣는다.
- 지금 동작: pre-commit이 `node scripts/gen-home-feed-doc.mjs --staged`를 돌린다. `docs/service/prd/home-feed/PRD.md` frontmatter `code:` 경로 아래 파일이
  하나라도 스테이지되고 그 문서가 함께 스테이지되지 않으면 막는다. 예외는 시험 파일(`__tests__/`·`*.test.*`)뿐이다.
- 문제: export 정리·파일 이동·주석 수정처럼 동작이 바뀌지 않은 커밋에서 세 번 막혀 `JAM_SKIP_DOCLINT=1` 우회를 사용자 허용으로 받았다(3-3a, 3-3b, 5-2).
  스토리 파일(`*.stories.*`)도 예외가 아니라 6·7회차에서 `src/components/today` 스토리·코드를 고치면 또 막힌다. 우회는 다른 문서 검사까지 함께 끈다.
- 바꿀 것:
  1. **스토리 파일 예외**: `*.stories.*`를 시험 파일처럼 감시에서 뺀다.
  2. **동작 무변경 예외**: 스테이지 전후 내용을 비교해 바뀐 것이 주석·import 선언·re-export 줄·선언 앞 `export` 표기·공백뿐이면 감시에서 빼고 안내만 낸다.
     새 파일·지운 파일은 비교할 짝이 없으니 예외가 아니다(지금처럼 막는다). 이름만 바뀐 파일(rename)은 옛 경로 내용과 새 경로 내용을 비교한다.
- 바뀌는 것은 검사 도구와 그 설명뿐이다. 서비스 코드·화면 변화 없음.
- 같은 문서의 476행 옛 스토리 제목(`MODULAR/Cards/CategorySticker`)도 이 조각에서 고친다(6-1a가 그 제목을 `UI/Cards/CategorySticker`로 바꾼다).

## 구현 계획

공통 규칙(5-1회차 티켓 20261126_0002: 실제 설치 `npm ci --ignore-scripts`, 커밋 직후 `git status`, 문서 검사 우회 금지, push 금지)을 따른다.
바뀌는 파일은 3개(`scripts/gen-home-feed-doc.mjs`, `scripts/gen-home-feed-doc.test.mjs`, `docs/service/prd/home-feed/PRD.md`)이고 줄 수는 약 150줄이다.

1. **`scripts/gen-home-feed-doc.mjs`**
   - `isTestFile`(226행) 옆에 `export function isStoryFile(filePath)`(`/\.stories\.[^/.]+$/`)를 더한다.
   - `export function stripNeutral(src)`: 비교용 정규화. 순서대로 ① 블록 주석 `/* … */`(JSX `{/* … */}` 포함) ② 줄 주석 — 줄 처음이나 공백 뒤의 `//`부터 줄 끝까지만
     (`'https://…'`처럼 `:` 뒤에 붙은 `//`는 건드리지 않는다) ③ import 선언(여러 줄 `import { … } from '…'`, `import type`, 부수효과 `import '…'`)
     ④ re-export 줄(`export * from '…'`, `export { … } from '…'`) ⑤ 선언 앞 `export `·`export default `(뒤에 `async function`·`function`·`const`·`let`·`class`·
     `type`·`interface`·`enum`이 올 때만) ⑥ 모든 공백을 걷는다.
   - `export function isBehaviorNeutral(before, after)`: 둘 다 문자열이고 `stripNeutral` 결과가 같으면 `true`. 하나라도 `null`이면 `false`.
   - `runStagedCheck`(249~273행):
     - 스테이지 목록을 `git diff --cached --name-status -M`으로 받아 (상태, 옛 경로, 새 경로)로 나눈다. 옛 경로나 새 경로가 `code:` 아래이고 시험·스토리 파일이 아니면 후보다.
     - 후보마다 비교 짝을 정한다: `M`은 `HEAD:<경로>`와 `:<경로>`, `R`은 `HEAD:<옛 경로>`와 `:<새 경로>`. `A`·`D`·그 밖의 상태는 짝이 없으므로 `null`.
       내용은 `git show`로 읽고 실패하면 `null`로 둔다.
     - `isBehaviorNeutral`이 `true`인 후보는 «안내(pre-commit): 주석·import·export 표기만 바뀌어 홈피드 문서 동반을 요구하지 않습니다» 아래에 경로를 출력하고(표준 오류, 종료 코드에 영향 없음) 차단 목록에서 뺀다.
     - 남은 후보가 있으면 지금과 같은 차단 메시지로 종료 코드 1. 메시지의 «동작이 바뀌지 않은 변경(리팩터링 등)이면 JAM_SKIP_DOCLINT=1로 우회» 줄은
       «주석·import·export 표기만 바뀐 파일은 자동으로 제외된다. 그 밖의 동작 무변경 리팩터링이면 JAM_SKIP_DOCLINT=1로 우회»로 고친다.
     - `staged.includes(DOC_PATH)`면 바로 통과하는 지금 규칙과 문서가 없을 때 통과하는 규칙은 그대로 둔다.
   - 머리 주석 11·23행의 ② 설명에 두 예외를 한 줄로 더한다.
2. **`scripts/gen-home-feed-doc.test.mjs`**(기존 `assert` 형식, 기존 ②절 임시 저장소 시험 옆):
   - 단위: `isStoryFile`(스토리 참/일반 파일 거짓), `isBehaviorNeutral` — 주석만 바뀜 참, 여러 줄 import 경로 바뀜 참, 선언 앞 `export` 제거 참,
     식 하나 바뀜 거짓, `null` 짝 거짓, URL 문자열 `'https://a.com/x'` → `'https://a.com/y'` 거짓.
   - 임시 저장소: `code:` 경로 아래 파일을 커밋한 뒤 ① 주석만 바꿔 스테이지 → `--staged` 종료 코드 0 ② 식을 바꿔 스테이지 → 1 ③ 같은 경로에 `.stories.tsx` 새 파일 → 0
     ④ 같은 경로에 일반 새 파일 → 1 ⑤ `git mv`로 이름만 바꾸고 import 경로만 고침 → 0.
3. **`docs/service/prd/home-feed/PRD.md`**:
   - 622행 «동기화 검사» 설명: 예외를 «테스트 파일(`__tests__/`·`*.test.*`)·스토리 파일(`*.stories.*`), 그리고 주석·import·export 표기만 바뀐 파일»로 고치고,
     우회 문장을 «그 밖의 동작 무변경 리팩터링은 `JAM_SKIP_DOCLINT=1`로 우회하고 사유를 커밋 메시지에 남긴다»로 고친다. 626행 근거에 이 티켓 번호를 더한다.
   - 476행 `(Story \`MODULAR/Cards/CategorySticker\`, 규칙 \`CategorySticker.prompt.md\`)` → `(Story \`UI/Cards/CategorySticker\`)`(규칙 파일은 3-1회차에 지워져 없다).
   - 생성 구간(§4~§7 표)은 손대지 않는다. 커밋 전에 `node scripts/gen-home-feed-doc.mjs --check` 통과를 확인한다.
4. **확인**: 실제 설치본에서 `scripts/verify.sh` 전체 통과. 이 커밋 자체는 문서를 함께 스테이지하므로 검사를 우회할 일이 없다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 스토리 파일과 주석·import·export 표기만 바뀐 파일은 `--staged`가 막지 않고, 식이 바뀐 파일·새 일반 파일은 지금처럼 막는 것을 임시 저장소 시험이 보인다.
- URL 문자열 안의 `//` 뒤 변경을 동작 무변경으로 잘못 보지 않는 것을 시험이 보인다.
- 홈피드 PRD 622·626행 설명이 새 동작과 맞고, 476행 옛 제목이 고쳐졌다. 생성 구간 `--check` 통과.
- 바뀐 파일은 위 3개뿐이다. 실제 설치본에서 `scripts/verify.sh` 전체 통과.
