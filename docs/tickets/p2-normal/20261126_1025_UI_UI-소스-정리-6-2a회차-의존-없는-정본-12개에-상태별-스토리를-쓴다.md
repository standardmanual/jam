## 6-2 공통 규칙 (6-2b·6-2c도 이 절을 따른다)

1. **파일과 제목**: `jam-web/src/components/ui/<이름>.stories.tsx`. meta는 기존 스토리(`EmptyState.stories.tsx`)와 같은 형식(`Meta`·`StoryObj` from `@storybook/nextjs-vite`, `title`, `component`, `parameters.layout`)이고
   `title`은 위 표 값이다. `tags`는 넣지 않는다(매니페스트 기본 포함).
2. **상태 고르는 법**: 그 컴포넌트를 import하는 서비스 호출부(`jam-web/src/app/**`(어드민 제외)·`jam-web/src/components/**`, 스토리·시험 제외)를 `git grep`으로 모두 찾는다.
   실제로 쓰이는 props 조합(variant·size·surface·disabled·loading·아이콘 유무 등)마다 스토리 하나를 만든다. 서비스에서 쓰지 않는 조합은 만들지 않는다.
   열림·로딩·빈 값처럼 화면에 나타나는 상태도 서비스에서 나타나는 것만 만든다. 조합이 많으면(예: Button) 같은 모양으로 그려지는 호출을 묶어 한 스토리로 한다.
3. **한 스토리 한 상태**: 여러 상태를 한 스토리에 나열하지 않는다. 스토리 `name`은 상태를 한국어로 짧게 쓴다(예: «보조 버튼 · 작게»).
   export 바로 위에 JSDoc 한 줄로 이 상태가 서비스 어디에서 나오는지 적는다(예: `/** 배지 상세 하단의 «믹스하기» 버튼 */`).
4. **문구·데이터**: 서비스 호출부의 실제 문구나 `@/lib/i18n`의 `d` 사전 값을 쓴다. 지어낸 문구·영문 자리표시자를 쓰지 않는다. 이미지가 필요하면 `jam-web/public`의 실제 자산 경로를 쓴다.
5. **스토리 안의 시각 값**: 기존 스토리처럼 배치용 감싸개(`style={{ width: 320 }}` 같은 폭·여백)만 쓴다. 색은 `var(--토큰)`으로만 쓰고 hex·rgb를 쓰지 않는다.
   컴포넌트의 생김새를 스토리에서 덮어쓰지 않는다(`className`으로 색·글자·모서리를 바꾸지 않는다).
6. **의존**: `next/link`·`next/navigation`·`next/image`는 `@storybook/nextjs-vite`가 처리한다. 경로가 필요하면 `parameters: { nextjs: { appDirectory: true, navigation: { pathname: '…' } } }`를 쓴다.
   공급자(Context)가 필요하면 스토리 `decorators`로 감싼다. 마운트 때 네트워크를 부르는 컴포넌트가 나오면 흉내 내지 말고 `halted`로 멈춰 보고한다.
7. **기준선·목록**: 스토리를 만든 컴포넌트를 `scripts/stories-baseline.json`에서 지우고 `node scripts/gen-component-list.mjs`로 `docs/service/prd/ui-components/README.md`를 다시 만든다.
   동시에 도는 다른 조각과 이 두 파일이 충돌하는 것은 괜찮다(카리나가 머지 때 다시 만든다). 다른 조각의 컴포넌트 스토리는 쓰지 않는다.
8. **확인**: 실제 설치본(`npm ci --ignore-scripts`)에서 `scripts/verify.sh` 전체 통과, `npm run build-storybook` 성공. 이어서 렌더 확인을 한다:
   빌드 산출물(`jam-web/storybook-static`)을 로컬 정적 서버로 띄우고 Playwright(`chromium.launch({ channel: 'chrome' })`, 번들 크로미움 없음)로 **이번에 만든 스토리마다**
   `iframe.html?id=<스토리 id>&viewMode=story`를 연다. 스토리북 오류 화면(`.sb-show-errordisplay`)이 없고 `#storybook-root`가 비어 있지 않으며 콘솔 오류가 없는지 본다.
   스토리 id는 `storybook-static/index.json`에서 읽는다. 결과(스토리 수, 오류 수)를 `summary`에 적는다. 이 확인용 스크립트는 저장소 밖 임시 폴더에 두고 커밋하지 않는다.
9. **공통 금지**: 정본 컴포넌트 파일·다른 스토리 파일·토큰을 고치지 않는다. 문서 검사 우회 금지, push 금지(사용자 지시), 커밋 직후 `git status` 확인.
