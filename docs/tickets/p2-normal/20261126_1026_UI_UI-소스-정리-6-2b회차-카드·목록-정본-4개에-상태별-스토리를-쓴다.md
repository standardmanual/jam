## 구현 계획

바뀌는 파일은 6개(새 스토리 4, 기준선 1, 목록 문서 1)이고 줄 수는 약 700줄이다.

1. 4개마다 공통 규칙 2번대로 호출부를 찾아 상태 목록을 정하고 스토리 파일을 쓴다. 특유한 것:
   - **BadgeGridCard**: 배지 이미지·등급 칩·레벨·방문 수·잠김처럼 인벤토리·컬렉션·검색 화면에서 실제로 나오는 상태. 빈 슬롯(`BadgeGridCardPlaceholder`)은 같은 파일의 별도 스토리로 둔다.
     카드 면·칩 색은 지금 컴포넌트가 그리는 그대로 둔다(티켓 20261125_1649·1650에서 정리됨). 스토리에서 덮어쓰지 않는다.
     이미지는 `jam-web/public`의 실제 배지 자산 경로를 쓴다(원격 Supabase 주소 금지). `SafeImage`가 이미지 실패 때 그리는 대체 상태가 서비스에 나오면 그것도 한 스토리로 둔다.
   - **CollectionGridCard·ListCard**: 호출부가 적어 상태가 적다. 호출부에 있는 상태만 쓴다.
   - **ListRow**: 호출부가 22곳이라 조합이 많다. 같은 모양으로 그려지는 호출을 묶는다(앞 아이콘·썸네일 유무, 오른쪽 칩·값·화살표, 줄 수 제한, 링크 여부 등 생김새를 가르는 props 기준).
     스토리 수는 많아도 15개 안쪽으로 한다. 부품 `ListRowEm`·`ListRowChip`은 ListRow 스토리 안에서 쓰이는 모습으로 보인다(따로 스토리를 만들지 않는다).
