# [UI] UI 소스 정리 6-2c회차: 겹침·내비게이션 정본 6개에 스토리를 쓰고 스토리 기준선을 없앤다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 6회차의 6-2 마지막 조각. 사용자 승인(2026-11-26, «6-2c 시작»).
  6-2a·6-2b(머지 `b53d50555`·`f18c6f044`)로 정본 46개 중 40개에 스토리가 생겼다. 남은 6개는 겹침(포털)·화면 경로·데이터 공급자가 있어야 그려지는 것이다.

| 컴포넌트 | 제목 | 호출 파일 | 그리려면 필요한 것 |
|---|---|---|---|
| BottomSheet | `UI/Feedback/BottomSheet` | 24 | `open`·`onClose`, `createPortal`(문서 body), `@/lib/uiOverlay` |
| Toast | `UI/Feedback/Toast` | 42 (`useToast` 사용) | `ToastProvider` 감싸개, 마운트 뒤 `useToast()`로 띄우는 감싸개 |
| TabBar | `UI/Navigation/TabBar` | 3 | `usePathname`·`useSearchParams`(경로별 선택 탭), `username` prop, `useTabBarHidden` |
| TopNav | `UI/Navigation/TopNav` | 33 | `TopNavDataProvider`(`@/lib/topNavData`), `useRouter`, 연동 상태가 `connected`면 `SyncButton`이 `ToastProvider`·`PendingItemsPickerProvider`를 요구 |
| Footer | `UI/Navigation/Footer` | 5 | `usePathname` |
| NotificationBell | `UI/Navigation/NotificationBell` | 1 | `TopNavDataProvider`(`hasUnreadNotifications`) |

- 6개를 다 쓰면 스토리 기준선이 0이 된다. 사용자 결정 2(2026-11-25: 기준선은 0이 되면 지우고 규칙을 예외 없는 규칙으로 바꾼다)에 따라
  `scripts/stories-baseline.json`과 생성기의 기준선 개념을 없애고 **«정본 컴포넌트는 모두 같은 이름의 스토리 파일이 있어야 한다»** 를 예외 없는 검사로 바꾼다.
- 화면 변화 없음: 새 스토리 파일, 검사 도구, 목록 문서만 바뀐다. 정본 컴포넌트 파일(`*.tsx`)과 공급자 파일(`@/lib/topNavData` 등)은 주석까지 고치지 않는다.
- 사용자 승인: 상위 티켓의 승인 줄(2026-11-25)과 6-2c 진행 승인(2026-11-26)에 해당한다.
- **스토리 규칙은 6-2a 티켓(20261126_1025)의 «6-2 공통 규칙» 절(1~9번)을 그대로 따른다.** 이 티켓에는 다른 점만 적는다.

## 구현 계획

바뀌는 파일은 약 10개(새 스토리 6, 기준선 삭제 1, 생성기·시험 2, verify 주석 1, 목록 문서 1)이고 줄 수는 약 900줄이다.

1. **스토리 6개**(공통 규칙 2번대로 호출부에서 상태를 고른다). 특유한 것:
   - **공급자**: 스토리 `decorators`로 실제 공급자를 감싼다(가짜 Context를 새로 만들지 않는다). `TopNavDataProvider`의 `value`는 호출부·레이아웃이 넘기는 모양 그대로
     (`username`, `avatarUrl`은 `jam-web/public` 자산 경로 또는 `null`, `stravaState`, `hasUnreadNotifications`). `PendingItemsPickerProvider`는 `initialPendingCount={0}`.
   - **경로**: `parameters: { nextjs: { appDirectory: true, navigation: { pathname: '…', query: {…} } } }`로 화면 경로를 준다. TabBar는 서비스 탭마다 «그 탭이 선택된 경로»가 한 상태다.
   - **BottomSheet**: `open: true`로 열린 모습을 보인다. 호출부 24곳을 `title`·`footer` 유무, 본문 길이(짧음·스크롤)처럼 생김새를 가르는 props로 묶는다. 스토리 `parameters.layout`은 `fullscreen`.
   - **Toast**: `ToastProvider`로 감싸고, 마운트 직후 `useToast()`로 토스트를 띄우는 작은 감싸개 컴포넌트를 스토리 파일 안에 둔다. 서비스가 쓰는 토스트 종류(성공·오류 등 API가 가르는 것)마다 한 스토리.
     `ToastRow`·`ToastScrim`을 따로 그리지 않는다(실제 경로로 보인다).
   - **TopNav**: 호출부의 조합(제목+뒤로, 로고, 오른쪽 슬롯, `syncStyle`)과 `stravaState` 세 갈래(`connected`·`disconnected_error`·그 밖)를 고른다. 스토리에서 버튼을 누르지 않는다.
   - **Footer·NotificationBell**: Footer는 경로에 따라 달라지는 것만, NotificationBell은 안 읽은 소식 있음·없음.
   - **네트워크 금지**: 마운트만으로 `/api/` 요청이나 외부 주소 요청이 생기면 흉내 내지 말고 `halted`로 멈춰 보고한다.
2. **스토리 기준선 없애기**:
   - `scripts/stories-baseline.json`을 `git rm`한다.
   - `scripts/gen-component-list.mjs`: `judgeStories(entries, baseline)`를 `judgeStories(entries)`(스토리 없는 파일 목록만 돌려줌)로 줄이고, `--baseline` 인자·`DEFAULT_BASELINE`·축소 안내·머리 주석 10행의 기준선 설명을 지운다.
     실패 문구는 «스토리 파일이 없는 정본 컴포넌트가 있습니다: … 같은 이름의 <이름>.stories.tsx를 만드세요»로 한다.
   - `scripts/gen-component-list.test.mjs`: 기준선 사례(34~36행)를 «스토리 없는 파일은 실패, 다 있으면 빈 목록»으로 바꾸고, 임시 폴더 시험(44·47행)의 `--baseline` 인자를 뺀다.
     스토리 없는 새 파일을 넣으면 `--check`가 종료 코드 1을 내는 사례는 남긴다.
   - `scripts/verify.sh` 157행 주석의 «기준선(scripts/stories-baseline.json) 밖으로» 표현을 «스토리 없는 정본 파일이 없는지»로 고친다.
   - `docs/service/prd/ui-components/README.md` 16행(손으로 쓴 안내)을 «스토리가 없는 정본 파일은 허용하지 않는다(`verify`의 `component-list` 단계와 pre-commit이 검사).
     새 정본 컴포넌트는 같은 이름의 스토리 파일과 함께 들어와야 한다»로 고치고, 생성 구간은 `node scripts/gen-component-list.mjs`로 다시 만든다.
3. **확인**: 6-2a 공통 규칙 8번(실제 설치본 verify 전체, `build-storybook`, 새 스토리 렌더 확인). 렌더 확인 때 HTTP 400 이상 응답과 `/api/`·외부 주소 요청을 함께 기록한다.
   첫 페이지의 `favicon.ico` 404(크롬 자동 요청, 빌드에는 `favicon.svg`만 있음)는 알려진 것이라 따로 적고 오류로 세지 않는다. 그 밖의 콘솔 오류는 거르지 않는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 표의 6개에 스토리 파일이 있고 제목이 표와 같다. 각 스토리가 서비스 호출부에서 실제로 쓰이는 상태이며, 스토리마다 출처를 적은 JSDoc 한 줄이 있다. 공급자는 실제 공급자를 쓴다.
- 정본 컴포넌트 파일·공급자 파일·다른 스토리는 바뀌지 않았다.

- 목록 문서가 «정본 46개 · 스토리 있음 46개 · 없음 0개»이고 `--check`가 통과한다.
- 실제 설치본에서 `scripts/verify.sh` 전체 통과, `build-storybook` 성공, 새 스토리 렌더 확인 오류 0건(파비콘 제외), 마운트 때 `/api/`·외부 요청 0건.
