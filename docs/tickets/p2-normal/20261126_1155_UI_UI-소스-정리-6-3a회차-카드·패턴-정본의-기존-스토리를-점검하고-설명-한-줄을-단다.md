## 6-3 공통 규칙 (6-3b도 이 절을 따른다)

1. **`@summary` 쓰는 법**:
   - 위치: 그 파일의 주된 export(컴포넌트) 바로 위 JSDoc. JSDoc이 있으면 그 안에 `@summary …` 줄을 더하고, 없으면 `/** @summary … */`를 새로 둔다. 여러 컴포넌트를 export하는 파일(예: `icons.tsx`)은 파일 맨 위 JSDoc 하나에 단다.
   - 내용: 이 컴포넌트가 **무엇이고 서비스 어디에서 쓰는지**를 한두 문장, 60자 안팎의 평서문(«…다.»)으로. 예: `@summary 배지 한 장을 정사각 썸네일로 보여 주는 격자 카드다. 인벤토리·컬렉션·검색 격자에서 쓴다.`
   - 넣지 않는 것: 티켓 번호, 작업 이력, «MODULAR», 영어 문장, props 나열. 서비스 어디에서 쓰는지는 실제 호출부를 보고 적는다(지어내지 않는다).
   - 기존 주석 문장은 고치거나 지우지 않는다(이번 범위 밖). **코드 줄은 한 줄도 바꾸지 않는다** — 정본 파일의 diff는 추가된 주석 줄뿐이어야 한다.
   - `.claude/output-styles/fluent-korean.md` 지침(문장 성분 생략 금지, 조사·어미 유지)을 따른다.
2. **기존 스토리 점검 기준** (6-2 공통 규칙 2~5번과 같다): 스토리 하나하나를 보고
   - (가) 서비스 호출부에서 실제로 쓰이는 상태인가 → 아니면 **지운다**. 같은 모양으로 그려지는 스토리가 여럿이면 하나만 남긴다.
   - (나) 한 스토리에 한 상태인가 → 여러 상태를 한 화면에 나열한 스토리(갤러리·매트릭스)는 서비스가 쓰는 상태별 스토리로 나누거나, 이미 따로 있는 스토리와 겹치면 지운다.
   - (다) 문구가 서비스 문구(`@/lib/i18n`의 `d`·호출부 문구)인가 → 지어낸 문구·영문 자리표시자는 서비스 문구로 바꾼다.
   - (라) 스토리가 hex·rgb 색이나 컴포넌트 생김새를 덮어쓰는 `className`을 쓰는가 → 쓰지 않게 고친다(배치용 폭·여백 감싸개는 괜찮다).
   - (마) export 바로 위에 서비스 출처 JSDoc 한 줄(«이 상태가 서비스 어디에서 나오는지»)이 있는가 → 없으면 단다. 스토리 `name`은 상태를 한국어로 짧게.
   - 남는 스토리가 하나도 없게 되면 안 된다(정본마다 스토리가 있어야 `component-list` 검사가 통과한다). **서비스 호출부가 하나도 없는 정본 컴포넌트**를 만나면 스토리를 지우지 말고 대표 스토리 하나를 남긴 뒤 `summary`에 보고한다(컴포넌트를 지울지는 별도로 정한다).
   - 메타(`title`·`component`)는 바꾸지 않는다. 스토리 id가 바뀌어도 괜찮다(참조하는 곳이 없다).
3. **확인**: 실제 설치본(`npm ci --ignore-scripts`)에서 `scripts/verify.sh` 전체 통과(다른 무거운 작업과 동시에 돌리지 않는다 — `CategorySticker.test.tsx`가 부하에서 시간 초과로 실패한 일이 있다, 티켓 20261126_1154),
   `npm run build-storybook` 성공, `node scripts/gen-component-list.mjs`로 목록 문서를 다시 만든 뒤 설명 칸에 `—`나 주석 조각이 없는지 본다.
   렌더 확인: 이번에 고친 스토리 파일의 **모든 스토리**를 6-2a 공통 규칙 8번 방법(정적 빌드 + Playwright `channel: 'chrome'`)으로 열어 오류 화면·빈 루트·콘솔 오류가 없는지 본다.
   첫 페이지의 `favicon.ico` 404는 알려진 것이라 오류로 세지 않고, 그 밖의 콘솔 오류는 거르지 않는다. 결과(스토리 수, 오류 수, 지운 스토리 수·남긴 스토리 수)를 `summary`에 적는다.
4. **공통 금지**: 정본 컴포넌트의 코드 줄·토큰·다른 조각 대상 파일을 고치지 않는다. 문서 검사 우회 금지, push 금지(사용자 지시), 커밋 직후 `git status` 확인.
   목록 문서(`docs/service/prd/ui-components/README.md`)는 동시에 도는 6-3b와 충돌해도 괜찮다(카리나가 머지 때 다시 만든다).
