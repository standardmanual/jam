## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 6회차의 마지막 조각(6-3) 중 하나. 사용자 승인(2026-11-26, «이 세션에서 시작»).
  6-3a(20261126_1155, 카드·패턴)와 동시에 돈다. 겹치는 파일은 생성 문서뿐이다.
- **규칙은 6-3a 티켓의 «6-3 공통 규칙» 절(1~4번)을 그대로 따른다.** 이 티켓에는 대상과 다른 점만 적는다.

| 할 일 | 대상 (기존 스토리 수) |
|---|---|
| 기존 스토리 점검 + `@summary` (12개) | Accordion(4), Carousel(3), Checkbox(9), EmptyState(6), IconButton(11), Input(11), ProgressBar(11), Select(7), Skeleton(6), TopNavBar(13), WanderingEyesLoader(5), icons(5) |
| `@summary`만 (14개, 6-2에서 쓴 스토리는 이미 기준에 맞음) | Button, LoadMoreButton, SlotCircleButton, SyncIconButton, InlineNotice, ProgressCountBar, SlidingTabs, FooterLogo, BottomSheet, Toast, TabBar, TopNav, Footer, NotificationBell |
| 토큰 소개 스토리 점검 (6개 파일, 각 1개) | `jam-web/design-system/foundations/{Colors,Fonts,Motion,Radius,Spacing,Typography}.stories.tsx` |

- 화면 변화 없음: 정본 컴포넌트 파일은 주석 줄 추가만 한다(코드 줄 무변경). 나머지는 스토리 파일과 생성 문서다.
- 사용자 승인: 2026-11-26 — 6-3 진행(«이 세션에서 시작»): 정본 컴포넌트 파일에 JSDoc `@summary` 주석 한 줄씩 추가(코드 무변경), 기존 스토리 중 기준에 맞지 않는 것 수정·삭제
  (상위 티켓 승인 줄 2026-11-25의 범위 안).

## 구현 계획

바뀌는 파일은 약 45개(정본 26개 주석 추가, 스토리 12개, 토큰 소개 스토리 최대 6개, 목록 문서 1)다. 줄 수는 `@summary` 약 55줄 + 스토리 점검(삭제 위주) 수백 줄이다.

1. 위 표의 정본 스토리 12개 파일을 6-3a 공통 규칙 2번대로 점검한다. 특유한 것:
   - **Checkbox·Input·Select**: 폼 상태(기본·채움·오류·비활성 등) 중 서비스 호출부에서 나오는 것만 남긴다.
   - **TopNavBar**(13개): 서비스 `TopNav`·`LegalTopNav`가 넘기는 조합만 남긴다. 6-2c에서 `TopNav` 스토리가 생겼으므로 같은 화면을 그리는 TopNavBar 스토리는 겹치면 줄인다.
   - **icons**: 아이콘 목록(카탈로그)은 «여러 상태 나열»이 아니라 목록 자체가 쓰임새이므로 (나) 기준의 예외로 남긴다. 서비스가 쓰지 않는 아이콘이 목록에 있으면 `summary`에 개수만 보고한다(아이콘 삭제는 이번 범위 밖).
2. **토큰 소개 스토리 6개**: 상태 스토리가 아니라 토큰 목록이므로 (가)(나) 기준은 적용하지 않는다. 대신 화면에 보이는 토큰 이름·값이 지금 토큰 파일(`jam-web/design-system/tokens/*.css`)·`globals.css`에 정의된 것과 맞는지,
   4회차에서 지운 토큰이 목록에 남아 있지 않은지, 설명 문장에 «MODULAR»·claude.ai/design 같은 옛 전제가 남아 있지 않은지만 본다. 고칠 것이 없으면 파일을 바꾸지 않는다.
3. 표의 26개 정본 파일에 6-3a 공통 규칙 1번대로 `@summary`를 단다. `icons.tsx`는 파일 맨 위 JSDoc에 단다.
4. 목록 문서를 다시 만들고 6-3a 공통 규칙 3번 확인(토큰 소개 스토리도 렌더 확인에 넣는다).

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 표의 정본 26개 파일에 `@summary`가 하나씩 있고, 그 파일들의 diff는 추가된 주석 줄뿐이다(코드 줄 무변경).
- 표의 기존 스토리 12개 파일의 남은 스토리가 모두 6-3a 공통 규칙 2번 (가)~(마)를 만족한다(icons 목록은 위 예외). 지운 스토리 수와 사유 분류를 `summary`에 적는다.
- 토큰 소개 스토리에 정의 없는 토큰·옛 전제 문장이 없다.
- 목록 문서에서 이 티켓 대상 26개의 설명 칸이 `@summary` 값이다. `node scripts/gen-component-list.mjs --check` 통과.
- 실제 설치본에서 `scripts/verify.sh` 전체 통과, `build-storybook` 성공, 고친 스토리 파일의 모든 스토리 렌더 확인 오류 0건(파비콘 제외).
