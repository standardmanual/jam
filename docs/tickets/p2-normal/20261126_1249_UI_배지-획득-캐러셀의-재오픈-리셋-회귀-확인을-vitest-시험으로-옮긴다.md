# [UI] 배지 획득 캐러셀의 재오픈 리셋 회귀 확인을 vitest 시험으로 옮긴다

## 핵심 요약

- 배경: 6-3a회차(20261126_1155)에서 `BadgeRevealCarousel.stories.tsx`의 `ReopenResetRegression` 스토리를 지웠다(서비스 상태가 아닌 시험 하네스). 이 스토리의 play가
  20260824_001 게이트에서 나온 회귀(스핀 제거 뒤 같은 카드 수로 닫았다 다시 열면 직전에 넘긴 카드가 그대로 남음)를 재현·검증하던 유일한 장치였다.
  다만 스토리 play는 20260906_1348에 vitest에서 빠져 자동으로 돌지 않았다. 사용자 결정(2026-11-26, «머지하고 후속 티켓»)으로 같은 검증을 실제로 도는 vitest 시험으로 옮긴다.
- 화면 변화 없음(시험 파일만 더한다). 정본 컴포넌트 코드는 바꾸지 않는다.

## 구현 계획

- 지운 스토리의 원문은 `git show db964a7d2:jam-web/src/components/ui/BadgeRevealCarousel.stories.tsx`의 `ReopenResetHarness`(약 200~232행)와 `ReopenResetRegression`(242~290행)이다.
- 새 시험 `jam-web/src/components/ui/__tests__/BadgeRevealCarouselReopen.test.tsx`(또는 기존 `jam-web/src/components/BadgeRevealCarouselSelect.test.tsx` 옆 형식): 하네스를 시험 안에 두고 play 단계를 그대로 옮긴다.
  ① 3개로 열면 첫 카드가 중앙 ② ArrowRight로 2번 ③ Escape로 닫기 ④ 같은 3개로 다시 열면 첫 카드 ⑤ 열린 채 20개로 바꿔도 첫 카드 ⑥ 20개 → 닫기 → 1개 재오픈도 첫 카드.
- 중앙 카드 판정은 지운 스토리의 `centerBadgeName` 도우미와 같은 기준을 쓴다. jsdom에서 3D 변환·애니메이션 때문에 판정이 안 되면 `prefers-reduced-motion`·타이머 흉내로 해결하고, 그래도 안 되면 `halted`로 보고한다.
- 회귀가 다시 나면 실패하는지: 정본의 리셋 조건(`navToken` 계산)을 임시로 되돌려 시험이 실패하는 것을 한 번 확인하고 되돌린다(커밋하지 않는다).

## 완료 조건

- 새 시험이 `npm test`에서 돌고 통과한다. 리셋 조건을 되돌리면 실패하는 것을 확인했다(`summary`에 기록).
- 정본 컴포넌트·스토리 파일은 바뀌지 않았다.
