# [Infra] UI 소스 정리 7-1회차: 값 규칙 검사기의 주석 오탐을 없애고 새 치수 토큰 18개를 정의한다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 7회차(기존 위반 정리)의 첫 조각. 사용자 승인(2026-11-26, «이대로 시작»)과 새 토큰 18개 승인은 상위 티켓 «회차 진행 기록»의
  «7회차 사용자 결정»·승인 줄에 있다. 7-2~7-4가 이 조각의 검사 결과를 기준으로 화면 코드를 고친다.
- 하는 일 세 가지:
  1. `scripts/check-ui-rules.mjs`·`scripts/check-spacing.mjs`가 **주석 안의 글자를 세지 않게** 한다. 지금은 JSDoc 본문·여러 줄 블록 주석·JSX `{/* */}` 주석·줄 끝 `//` 주석 안의
     `max-w-[430px]`·`#171717`·`<button>`·`py-[13px]` 같은 설명 글자를 위반으로 센다(측정 2026-11-26: ui-rules 약 13건, spacing 8건).
  2. `check-ui-rules`의 임의값 규칙이 **토큰만으로 이뤄진 값**을 위반으로 보지 않게 한다: 형식 힌트가 붙은 토큰 하나(`text-[color:var(--link)]`)와
     토큰·`100%`·화면 단위·숫자·연산자로만 이뤄진 계산식(`top-[calc(var(--spacing-safe-top)+var(--topnav-height))]`). 스토리 전용 견본 파일은 검사에서 뺀다.
  3. 사용자가 승인한 **새 치수 토큰 18개를 토큰 파일에 정의**하고 토큰 소개 스토리에 보인다. 이 조각에서는 아무 곳도 새 토큰을 참조하지 않는다(7-2~7-4가 바꾼다).
- **화면 변화 없음**: 검사기·시험·기준선·토큰 정의·토큰 소개 스토리만 바뀐다. `src/app/**`·`src/components/**`의 화면 파일은 고치지 않는다.
- 관련 파일:
  - `scripts/strip-code-comments.mjs`(신규)·`scripts/strip-code-comments.test.mjs`(신규)
  - `scripts/check-ui-rules.mjs`: 머리 주석 3~16행, `isCommentLine`(64~67행), `findHits`(70~126행), `VAR_ONLY`(54행), `SKIP_FILE`(32행)
  - `scripts/check-ui-rules.test.mjs`, `scripts/check-spacing.mjs`(머리 주석 4~8행, `countLine`·`countViolations` 45~63행), `scripts/check-spacing.test.mjs`
  - `scripts/ui-rules-baseline.json`, `scripts/spacing-baseline.json` (줄어든 개수로 다시 쓴다)
  - `jam-web/design-system/tokens/spacing.css`(«컴포넌트 치수» 48행 부근·«하단 고정 UI의 기준선» 64행 부근), `jam-web/design-system/tokens/motion.css`(10~19행)
  - `jam-web/design-system/foundations/Spacing.stories.tsx`(138행 `--spacing-safe-bottom` 줄 부근), `jam-web/design-system/foundations/Motion.stories.tsx`(186행 부근)

## 구현 계획

바뀌는 파일은 약 12개이고 줄 수는 약 400줄이다(시험 포함).

1. **주석 지우개 `scripts/strip-code-comments.mjs`** (`export function stripComments(text, ext)`):
   - 주석 안의 글자를 공백으로 바꾼 같은 길이의 문자열을 돌려준다. 줄바꿈은 그대로 둔다(줄 번호·열이 바뀌지 않는다).
   - `.ts`·`.tsx`: `//`부터 줄 끝, `/* … */`(여러 줄 포함, JSX `{/* */}`도 이것으로 처리된다). 문자열 `'…'`·`"…"`·템플릿 문자열(백틱, `${…}` 안은 코드로 본다) 안의
     `//`·`/*`는 주석이 아니다(예: `'https://…'`). 역슬래시 이스케이프를 처리한다. 정규식 리터럴은 다루지 않는다(머리 주석에 한계로 적는다).
   - `.css`: `/* … */`만 주석이다. 문자열 안은 그대로 둔다.
   - 시험: 줄 주석·블록 주석·여러 줄 JSDoc·JSX 주석·문자열 안의 `//`·템플릿 안의 `${}`·CSS 주석, 그리고 돌려준 문자열의 길이와 줄 수가 입력과 같은지.
2. **`check-ui-rules.mjs`**:
   - 네 규칙(arbitrary·color-literal·raw-element·inline-visual)을 모두 **주석을 지운 본문**에서 센다. `isCommentLine`은 지운다.
     `ui-allow: <사유>` 예외는 지금처럼 **원래 줄**에서 읽는다(예외 주석 자체가 주석이므로).
   - 임의값 값이 다음 중 하나면 위반이 아니다(지금의 `VAR_ONLY`를 넓힌다):
     (가) `var(--이름)` 하나 (지금과 같음), (나) `<영문 형식>:var(--이름)` (예: `color:var(--link)`, `length:var(--x)`),
     (다) `calc(`·`min(`·`max(`·`clamp(`로 감싼 식에서 `var(--이름)`, `100%`, `100dvh`·`100svh`·`100lvh`·`100vh`·`100vw`, 단위 없는 숫자, `+ - * /`, 괄호, `,`, `_`(공백)를
     빼면 아무것도 남지 않는 것. `var(--x,1rem)`처럼 대체값에 리터럴이 있는 것, `calc(100%+8px)`처럼 리터럴 길이가 섞인 것은 지금처럼 위반이다.
   - `SKIP_FILE`에 스토리 전용 견본 파일(파일 이름이 `StoryFixtures.ts`·`StoryFixtures.tsx`로 끝나는 것)을 더한다. 지금은 `jam-web/src/components/today/feed/feedStoryFixtures.tsx`
     하나이고, 이 파일은 `*.stories.tsx` 8개만 import한다(서비스 코드는 import하지 않는다 — 구현 전에 `grep -rln feedStoryFixtures jam-web/src`로 다시 확인한다).
   - 머리 주석(3~16행)의 규칙 설명을 위 내용으로 고친다. 출력 문구(`FIXES`)는 그대로 둔다.
   - 시험(`check-ui-rules.test.mjs`)에 더한다: JSDoc·블록·JSX·줄 끝 주석 안의 임의값·색·`<button>`은 세지 않음, 문자열 안 `'https://x'` 옆의 `bg-[#fff]`는 셈,
     `text-[color:var(--link)]`·`top-[calc(var(--a)+var(--b))]`·`min-h-[calc(100dvh-var(--a))]`는 통과, `w-[calc(100%+0.75rem)]`·`pb-[var(--x,1rem)]`은 위반,
     `style={{ /* color: '#fff' */ }}`의 주석 속 값은 세지 않음, `ui-allow` 주석이 있는 줄은 지금처럼 빠짐, `…StoryFixtures.tsx`는 검사 대상이 아님.
3. **`check-spacing.mjs`**: 같은 주석 지우개를 거친 본문의 줄에서 센다(`spacing-allow`는 원래 줄에서 읽는다). 머리 주석 4행의 «주석 줄도 센다(단순하게)»를 «주석 안은 세지 않는다»로 고친다.
   시험에 주석 줄·블록 주석 안의 `py-[13px]`·`gap-8`은 세지 않는 사례를 더한다.
4. **기준선 다시 쓰기**: 1~3을 마친 뒤 `node scripts/check-ui-rules.mjs --write-baseline`과 `node scripts/check-spacing.mjs --write-baseline`을 실행한다.
   **늘어난 파일이 하나도 없어야 한다**(규칙을 좁히기만 했으므로). 늘어난 파일이 있으면 기준선을 쓰지 말고 `halted`로 멈춰 그 줄을 보고한다.
   전후 규칙별 합계(ui-rules 4규칙, spacing 합계)와 파일 수를 `summary`에 적는다.
5. **새 토큰 18개** (값은 지금 코드에 있는 값 그대로, 각 줄에 «어디에 쓰는 값인지» 한국어 주석 한 줄):

## 완료 조건

- 주석 안의 글자를 두 검사기가 세지 않고, 문자열 안의 `//`는 주석으로 보지 않는다(시험).
- 토큰만으로 이뤄진 임의값은 통과하고, 리터럴이 섞인 값은 지금처럼 위반이다(시험).
- 기준선 두 파일이 줄어든 개수로 다시 쓰였고 늘어난 파일이 없다. 전후 합계가 `summary`에 있다.
- 새 토큰 18개가 값 그대로 정의되고 토큰 소개 스토리에 보인다. 컴파일 CSS 차이가 새 선언뿐이다.
- 화면 파일(`jam-web/src/app/**`, `jam-web/src/components/**`)이 바뀌지 않았다.
