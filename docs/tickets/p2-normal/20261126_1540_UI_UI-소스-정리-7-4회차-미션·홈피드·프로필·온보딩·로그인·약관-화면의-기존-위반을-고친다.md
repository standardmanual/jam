## 채원① 사전 판정 (사용자 결정 반영, 2026-11-26)

**사용자 결정 2026-11-26 — 이 판정보다 앞선다.** ① 프로필 숫자 칸 3개(팔로워·팔로잉·포인트, `ProfileClient.tsx` 512행) → «숫자 + 이름» 누르는 칸 정본을 새로 만든다(지금 모양 그대로, 스토리·`@summary` 포함). ② 사진 고르기(`profile/edit/page.tsx` 261행, `onboarding/page.tsx` 356행 부근) → 아바타를 감싼 얇은 정본(누름 효과 + 올리는 중 덮개)을 새로 만들고 두 화면이 함께 쓴다(지금 모양 그대로). ③ 굵기는 `var(--font-weight-bold)`가 아니라 `font-bold` 클래스로 쓴다(`--font-weight-*`는 DS 토큰이 아니다, 7-2·7-3과 같음). ④ 지도 «내 위치»는 `IconButton`의 기본 모양을 받아들인다(새 선택 prop을 만들지 않는다). 아이콘 색·테두리가 바뀌면 «화면이 바뀌는 곳 목록»에 적는다. ⑤ 이 판정의 «승인 대기» 항목은 위 ①②로 모두 풀렸다. 승인 필요 항목은 더 없다.

- 약관 3화면: 위 16 · 좌우 16 · 아래 24, 구획 사이 20(예전 위아래 64·구획 48·32).
- 로그인: 중앙 정렬 단일 열(검정 바탕). 로고 → 24px → 안내 배너(있을 때) → 구글 Button(secondary, max-w-64) → 개발 환경에서만 dev 로그인 Button(secondary dark). 중앙 정렬은 로그인 한 화면의 의도된 구성이라 유지.

- 프로필 편집: 상단 가운데 96px 둥근 사각 아바타(승인 대기 항목) → 안내 문구 → 입력 묶음 → 맨 아래 «탈퇴» ghost xs 버튼.

### 상태

- 로딩·빈·오류: 이 조각은 화면 구조를 바꾸지 않고 값만 옮기는 정리라 새 상태를 만들지 않는다. 기존 상태를 그대로 유지하고 구현자는 아래만 확인한다.
- IconLabelButton: 기본·primary·busy(aria-busy, 누름 중복 차단은 호출부 책임)·키보드 포커스 링(focus-visible)·누름(active:scale-95)·reduced-motion. 로딩·빈·오류는 해당 없음(단일 행동 버튼).
- IconButton locate: 기본·locating 중 soft disabled(aria-disabled + 흐림, 클릭은 호출부가 막는다. 지금은 native disabled라 동작이 달라질 수 있으니 handleLocateClick에서 locating이면 return하는지 확인).
- VOC 페이지네이션: 현재 쪽(aria-current)·일반 쪽·이전/다음 비활성(첫·마지막 쪽)·생략 부호. 총 1쪽이면 렌더 없음(기존).
- 로그인: 기본·오류 배너(auth_failed·기타)·탈퇴 완료 안내(InlineNotice)·dev 로그인(development에서만).
- 프로필 편집: 탈퇴 버튼 기본·누름·포커스. 사진 고르기는 승인 대기 중이라 원본 그대로 유지(기본·업로드 중·업로드 오류).
- 약관·미션 상세·홈피드 큰 제목: 정적 화면이라 새 상태 없음.

### 모션

- IconLabelButton·Button·IconButton은 공통 누름 피드백(active:scale-95, 100ms)과 motion-reduce:transition-none을 유지한다. 새 모션은 만들지 않는다.
- 모션 시간은 숫자 대신 --duration-* 토큰(240ms는 --duration-fast 250ms)으로 옮긴다. 이번 파일에서 걸리면 transition 값을 눈으로 대조한다.
- FeedStamp SVG의 fontFamily 'inherit'은 지워도 글꼴이 같은지 렌더로 확인하고, 다르면 규칙 6대로 text-inherit에 해당하는 방법을 쓴다.

### 기기 주의

- 터치 영역: xs 버튼으로 바뀌는 곳(VOC 페이지 번호·이전·다음, 탈퇴)은 xs가 31px라 min-h-11 + style minHeight var(--touch-target-min)으로 44px를 반드시 유지한다. 지도 내 위치 버튼도 44px 그대로.
- 안전영역: layout·login의 env(safe-area-inset-*)는 --spacing-safe-top·--spacing-safe-bottom으로 옮기되 노치·홈 인디케이터 기기에서 값이 같은지 확인한다. 약관 3화면 아래 24px는 안전영역 위쪽이라 홈 바와 겹치지 않는지 확인한다.
- 작은 화면 360px: 로그인 구글 버튼 max-w-64, 약관 본문, 미션 상세 text-4xl+leading-11이 넘치지 않는지, VOC 페이지네이션이 쪽 번호 7개 이상일 때 한 줄에 들어가는지(gap-2, Button xs 가로 패딩 24px 때문에 넘칠 수 있으니 ghost xs 패딩을 줄이거나 쪽 목록 폭을 실측)를 확인한다.
- 공유 시트는 safe-bottom 위에서 버튼 3개가 한 줄에 들어가야 한다.
- 화면 캡처 확인은 카리나 몫: 약관 3화면·로그인·온보딩·미션 상세·홈피드 큰 제목·VOC 하단·프로필 편집·공유 시트·지도 내 위치.

### 만듦새
