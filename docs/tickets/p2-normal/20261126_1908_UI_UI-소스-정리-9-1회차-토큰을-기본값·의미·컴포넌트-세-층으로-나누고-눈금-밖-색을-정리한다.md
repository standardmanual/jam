# [UI] UI 소스 정리 9-1회차: 토큰을 기본값·의미·컴포넌트 세 층으로 나누고 눈금 밖 색을 정리한다

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 9회차의 첫 조각. 측정과 분할안은 상위 티켓 «9회차 준비» 항목에 있다.
  토큰 정의를 세 층 파일로 나누고, 의미·컴포넌트 토큰이 직접 들고 있는 색 값을 기본값 참조로 바꾼다. globals.css에 있는 서비스용 모션 레시피 변수도 토큰 폴더로 옮긴다.
- 사용자 결정(2026-11-26): ① 토큰 이름은 지금 이름을 유지하고 층은 파일로 나눈다 ② 회색 눈금 밖 4개 값은 거리상 가장 가까운 회색 눈금으로 맞춘다
  ③ 위험 글자·포인트 글자는 값을 보존하고 기본값 층에 새 이름을 만든다 ④ 등급색 3개·캡슐 채움색은 값을 보존하고 새 이름을 만든다. 캡슐 트랙·테두리는 거의 같은 회색 눈금으로 맞춘다.
- 사용자 승인: 2026-11-26 — 9-1 토큰 층 재배치와 아래 «값 대응표»(회색 눈금 맞춤 5건·캡슐 트랙/테두리 2건의 화면 변화 포함), 기본값 층 새 이름 6개(`--base-danger-red`·`--base-point-orange`·`--base-rarity-green`·`--base-rarity-amber`·`--base-rarity-pink`·`--base-capsule-orange`)
- **화면이 바뀐다**: 앱 배경이 조금 밝아지고, 보조 글자(154곳)·Common 칩·입력 테두리가 조금 옅어진다. 나머지는 값이 같아야 한다.
- 대비 참고(사용자가 알고 고른 값): 보조 글자 #737373은 새 배경 #f5f5f5 위에서 대비 4.35(본문 글자 기준 4.5 미달), 입력 테두리 #a3a3a3은 흰 바탕 위 2.52(테두리 기준 3 미달)다.
- 바꾸는 방법은 7-2 티켓(20261126_1407) «7회차 공통 규칙»을 따른다(시험은 새 값으로, verify 전체는 카리나, push하지 않음).

## 층 규칙

| 층 | 무엇 | 값 규칙 | 예 |
|---|---|---|---|
| 기본값 | 원재료 눈금 | 직접 값(색 hex·px·ms·곡선)은 이 층에만 둔다 | `--base-neutral-*`, `--base-white`, `--jam-*` 브랜드색, `--spacing-4`~`--spacing-96`, `--radius-xs`~`--radius-full`, `--duration-*`, `--ease-*`, `--text-*` 글자 크기, `--leading-*`, `--scale-*`, 새 이름 6개 |
| 의미 | 쓰임새 이름 | **색은 반드시 기본값 참조**(투명도는 `color-mix(in srgb, var(--기본값) N%, transparent)`). 눈금에 없는 치수(44px 같은)는 직접 값을 허용한다 | `--background`, `--muted`, `--border`, `--danger-text`, `--page-x`, `--gap-*`, `--touch-target-min`, `--z-*` |
| 컴포넌트 | 한 컴포넌트 전용 | 색은 기본값·의미 참조. 그 컴포넌트에만 있는 치수·모션 레시피 값은 직접 값을 허용하되, 기본값에 같은 값이 있으면 참조한다 | `--tabbar-*`, `--list-row-*`, `--capsule-*`, `--progress-*`, `--rarity-*`, `--status-card-*`, `--toast-*`, 모션 레시피 |

- 파일: `jam-web/design-system/tokens/`에 `primitive.css`·`semantic.css`·`component.css` 세 파일을 두고, 지금의 `colors.css`·`typography.css`·`spacing.css`·`radius.css`·`motion.css`·`materials.css` 정의를 층에 맞게 옮긴 뒤 옛 파일은 지운다. `fonts.css`는 그대로 둔다.
  `[data-service-theme]`처럼 지금 붙어 있는 선택자 범위는 그대로 유지한다(같은 이름의 덮어쓰기 블록도 옮긴다).
- 어드민 shadcn 토큰(`[data-admin-theme]`·`.dark`)과 `@theme inline` 매핑은 이번 범위 밖이다(9-2에서 기본 테마를 닫을 때 다룬다).
- 7회차에 만든 치수 토큰 18개(`--app-max-width`·`--z-toast` 등)도 이 규칙대로 층에 넣는다.

| `--capsule-fill` | #f94c31 | `var(--base-capsule-orange)` (새 기본값 #f94c31) | 없음 |

- 이미 기본값과 같은 값을 직접 적은 의미 토큰 11개(`--background-secondary`·`--card-bg`·`--btn-secondary`·`--surface`·`--accent-soft`·`--accent-soft-hover`·`--border`·`--separator`·`--warning`·`--default`·`--default-soft`)는 같은 값의 기본값 참조로 바꾼다(화면 변화 없음).
- `rgba(...)`·`color-mix(...)` 값은 같은 색이 되도록 기본값 참조로 바꾼다(`rgba(0,0,0,0.5)` → `color-mix(in srgb, var(--base-black) 50%, transparent)`). `rgba(82, 82, 82, 0.18)`은 `--base-neutral-600`과 RGB가 같으므로 같은 방식으로 바꾼다. 기본값에 같은 RGB가 없으면 바꾸지 말고 `summary`에 적는다.

## 구현 계획

1. 층 규칙대로 세 파일을 만들고 옛 토큰 파일 정의를 옮긴다. `jam-web/src/app/globals.css`의 `@import`를 새 파일로 바꾼다. 옛 파일 경로를 읽는 곳(시험 `transitions.test.ts`·`Toast.position.test.ts`·`scrimBlur.test.ts`·`feedConstants.test.ts`, `src/lib/today/feedConstants.ts`, `Button.tsx` 주석,
   `scripts/check-token-refs.mjs`·`scripts/check-ui-approval.mjs`와 시험, 스토리북 토큰 스토리, `.claude/agents/jam-designer.md`·`.claude/skills/jam-ds/SKILL.md`·`.claude/skills/jam-design/references/ui-review-checklist.md`·`.claude/skills/jam-work/references/ds-connection-scope.md`)을 `git grep "design-system/tokens"`로 모두 찾아 새 경로로 고친다.
2. 값 대응표와 «이미 같은 값» 11개, `rgba`·`color-mix` 정리를 반영한다. 새 기본값 6개를 `primitive.css`에 더한다.
3. `globals.css`의 서비스용 `:root` 모션 레시피 변수(약 83개, `--duration-stagger`부터 `--reel-ease`까지)를 `component.css`로 옮긴다. 값이 기본값과 같으면(`250ms` = `--duration-fast`, `cubic-bezier(0.22, 1, 0.36, 1)` = `--ease-smooth-out` 등) 기본값을 참조한다. 같은 이름을 두 번 정의하지 않는다.
   `--tabs-text-muted` 같은 색 참조는 그대로 의미 토큰을 참조한다.
4. 확인용 계산 스크립트(커밋하지 않아도 된다): 바꾸기 전후 `:root`에서 모든 토큰의 최종 값(참조를 끝까지 따라간 값)을 계산해 비교한다. **값 대응표의 7건(배경·페이지 배경·보조 글자·Common·입력 테두리·캡슐 트랙·캡슐 테두리) 말고는 최종 값이 모두 같아야 한다.** 비교 결과(달라진 토큰 목록)를 `summary`에 적는다.
5. 스토리북 토큰 스토리(색·간격·모션 등)가 새 파일에서 읽도록 고치고, 층이 보이게 제목이나 묶음을 맞춘다(새 스토리 파일은 만들지 않는다).
6. 확인: 바꾼 파일 시험·`npm run typecheck`·`npm run lint`·`check-ui-rules`·`check-spacing`·`check-token-refs`·`gen-component-list --check`. `summary`에 «화면이 바뀌는 곳 목록». 로컬 커밋만 하고 push하지 않는다.

## 완료 조건

- 토큰 정의가 `primitive.css`·`semantic.css`·`component.css`에 층 규칙대로 있고, 옛 토큰 파일 6개와 globals.css의 서비스용 모션 레시피 정의가 없다.
- 의미·컴포넌트 층에 색 직접 값(hex·`rgba`)이 없다(보고한 예외 제외).
- 계산 비교에서 최종 값이 달라진 토큰이 값 대응표의 7건뿐이다.
- 카리나: 실제 설치본 verify 통과, 스토리북 전후 캡처(바뀌는 곳이 배경·보조 글자·Common 칩·입력 테두리 쪽뿐인지) 확인 뒤 사용자 머지 승인.
