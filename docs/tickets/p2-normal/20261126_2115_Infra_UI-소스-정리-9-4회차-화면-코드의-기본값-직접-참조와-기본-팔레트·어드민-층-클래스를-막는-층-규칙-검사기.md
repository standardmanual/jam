# [Infra] UI 소스 정리 9-4회차: 화면 코드의 기본값 직접 참조와 기본 팔레트·어드민 층 클래스를 막는 층 규칙 검사기

## 핵심 요약

- 요구사항: 상위 티켓 20261125_1923 9회차 네 번째 조각. 9-3a·9-3b(20261126_2024·2025)가 화면 코드의 기본값 직접 참조를 0으로 만들었다. 다시 생기지 않게 검사기로 막는다. **기준선 없이 위반 1건에도 실패하는 예외 없는 규칙이다(8회차 방식).**
- 사용자 승인: 2026-11-26 — 9회차 분할안(9-4 층 규칙 검사기). 새 토큰·새 컴포넌트는 만들지 않는다.
- 관련 파일: `scripts/check-ui-rules.mjs`(+시험), `scripts/check-token-refs.mjs`(+시험), 새 `scripts/check-admin-palette.mjs`(+시험), `scripts/verify.sh`(143~154줄 근처), `.githooks/pre-commit`(458줄 근처 ui-rules 단계), `jam-web/src/app/globals.css`(`@theme inline`의 어드민 shadcn 매핑, 필요할 때만).
- 화면 변화: 없음(검사기만 바뀐다). 단, 끊어진 매핑 줄을 지우면 그 줄이 만들던 빈 유틸리티 규칙이 사라진다(아래 3번).

## 경계 (9-3a 티켓 «기본값을 쓸 수 있는 곳과 없는 곳»과 같다)

- 기본값을 쓸 수 있다: 토큰 파일, `jam-theme.css`·`admin-theme.css`·`globals.css`, 정본 폴더 `jam-web/src/components/ui/`, `jam-web/src/components/transitions.css`, 스토리북 토큰 소개.
- 쓸 수 없다: `check-ui-rules`의 대상(서비스 화면·도메인 코드) 중 위 허용 구역을 뺀 곳.

## 구현 계획

1. **`check-ui-rules.mjs`에 규칙 두 개를 더한다**(규칙 키는 출력에 그대로 쓴다).
   - `primitive-ref`: 정본 폴더와 `transitions.css`를 뺀 대상 파일에서 `var(--이름)`의 이름이 기본값이면 위반이다. 기본값 이름은 **실행할 때 파일에서 읽는다**(하드코딩하지 않는다): `jam-web/design-system/tokens/primitive.css`와 `jam-web/src/app/jam-theme.css`의 `@theme`에 정의된 이름. `--root`를 주면 그 아래에서 읽는다(시험용).
     `var(--x, 대체값)`도 위반이다. 주석 안 글자는 세지 않는다(지금처럼 `stripComments`).
   - `palette-class`: 같은 대상에서 기본 팔레트·어드민 층·강조색 클래스를 쓰면 위반이다. 이름은 실행할 때 읽는다:
     `admin-theme.css`의 `--color-*`(팔레트 98색·white·black)와 `--shadow-*`, `globals.css` `@theme inline` 안 «shadcn 이름 — 어드민 전용» 묶음(`primary`·`secondary`·`muted-foreground`·`destructive`·`input`·`ring`·`popover*`·`card`·`card-foreground`·`sidebar*`·`chart-*`), 강조색 매핑 `--color-jam-*`.
     클래스는 색 접두(`bg`·`text`·`border`(+방향)·`fill`·`stroke`·`from`·`via`·`to`·`ring`·`ring-offset`·`outline`·`decoration`·`accent`·`caret`·`divide`·`placeholder`)와 변형 접두(`hover:` 등)·불투명도 접미(`/50`)를 포함해 찾는다. `shadow-sm` 같은 그림자 클래스도 센다.
   - 두 새 규칙은 **`ui-allow` 줄 예외를 받지 않는다**(예외 없는 규칙). 기존 네 규칙의 `ui-allow` 처리는 그대로 둔다. 머리 주석·`FIXES` 안내문을 새 규칙에 맞게 쓴다(«의미·컴포넌트 토큰이나 서비스 눈금 클래스를 쓰세요. 맞는 토큰이 없으면 카리나에게 토큰 추가 승인을 요청하세요»).
   - 지금 저장소에서 두 규칙 위반이 0이어야 한다(9-3 머지 뒤). 0이 아니면 고치지 말고 목록을 `summary`에 적고 멈춘다(`halted`).
   - `--files`·`--stdin-file` 경로(클로드 코드 편집 훅·pre-commit)도 새 규칙을 그대로 쓴다. 편집 훅 `.claude/hooks/ui-guard.mjs`가 출력 문구를 따로 만들면 새 규칙 키를 알아보게 맞춘다.
2. **`check-admin-palette.mjs`(새 파일)**: `jam-web/src/**`의 `.ts`·`.tsx`에서 기본 팔레트 모양의 클래스(`bg-lime-500`, `text-gray-700/80`, `shadow-xl` 등: 색 이름 22개 × 단계 50~950, 그림자 크기)를 찾아, `admin-theme.css`에 정의가 없으면 위반이다(Tailwind 기본 테마가 닫혀 있어 그 클래스는 규칙이 만들어지지 않고 조용히 무시된다). 주석은 세지 않는다. 지금 저장소에서 위반이 있으면 고치지 말고 목록을 `summary`에 적는다(어드민 화면 변경은 이 티켓 범위 밖, 후속 티켓으로 카리나가 정한다). 위반 0이면 verify에 연결한다.
3. **`check-token-refs.mjs` 범위 확대**(7회차 넘김 ④, 5-3c 넘김):
   - 대상: `jam-web/src/**`와 `jam-web/design-system/**`의 `.ts`·`.tsx`·`.css`(시험·스토리 포함, `node_modules` 제외). CLI 인자로 폴더를 받으면 그 폴더만 본다(시험용).
   - 정의로 인정하는 이름: 토큰 파일 + `jam-theme.css`·`admin-theme.css`·`globals.css` + **대상 파일 어디서든 선언한 이름**(CSS `--x:`·style 객체 `'--x':`·`setProperty('--x'`) — 서버가 인라인으로 넣는 `--ticket` 같은 실행 값 때문이다. Tailwind 내부 변수 `--tw-*`는 넘어간다.
   - 확대 뒤 걸리는 참조가 있으면: `globals.css` `@theme inline`의 어드민 매핑 중 원래 변수가 어디에도 없는 줄(4회차 기록: `--color-chart-*`·`--color-card-foreground`·`--color-sidebar-primary*` 등)은 그 클래스를 쓰는 곳이 `jam-web/src` 전체에 없을 때만 지운다. 쓰는 곳이 있거나 다른 종류의 미정의 참조는 고치지 말고 `summary`에 목록을 적고 멈춘다.
   - 시험: 미정의 참조가 있는 임시 폴더로 종료 코드 1, 없는 폴더로 0을 확인한다.
4. **연결**: `scripts/verify.sh`에 `admin-palette` 단계를 `token-refs` 단계 바로 뒤에 더하고 마지막 «verify 통과» 목록에 이름을 더한다. `.githooks/pre-commit`의 ui-rules 단계(458줄 근처)는 그대로 새 규칙을 탄다. 9-5가 동시에 `verify.sh`의 `component-list` 단계 뒤와 pre-commit의 생성 문서 단계에 줄을 더하므로 그 자리는 건드리지 않는다.
5. 확인(아현): 바꾼 스크립트 시험(`node --test scripts/check-ui-rules.test.mjs` 등), 세 검사기 전체 실행 결과(위반 0 또는 멈춘 목록), `bash .githooks/pre-commit`이 아닌 `node scripts/check-ui-rules.mjs --stdin-file <경로>`로 위반 예시를 넣었을 때 거절되는지. `verify.sh` 전체는 카리나가 실제 설치본에서 돈다. **push하지 않는다.**

## 완료 조건
