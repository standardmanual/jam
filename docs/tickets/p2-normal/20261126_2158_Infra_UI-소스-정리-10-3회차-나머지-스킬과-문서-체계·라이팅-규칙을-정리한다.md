## 구현 계획

1. push 정합: 스킬의 push 문장을 CLAUDE.md 규칙 3(사용자 요청 전에는 push하지 않음, main 머지는 명시 승인)에 맞춘다. jam-sync는 «올려줘·푸시해»가 있을 때만 push하고 «동기화해줘»만 들어오면 상태 진단과 pull만 한다. `git add -A`는 파일을 명시하는 방식으로 바꾸고, 작업 폴더 경로는 «현재 저장소가 열린 경로»로 쓴다.
2. 꺼진 기능 규칙 삭제: jam-sync «분리 구조 정리», jam-ship «주간 무인 배포와의 관계»(대응표는 `scheduled-jobs.md` «무인 경로에 적용하는 점검» 한 곳에만), UX 가이드의 배지 트리 용어.
3. 단일 원천 배분: 폴더별 쓰기 방식·버전 규칙·경로 표기는 `docs/README.md`, frontmatter·태그·검사 등급은 `docs/DOCUMENT_SCHEMA.md`(열거값은 `scripts/doc-check.config.json`을 가리킴), 카테고리별 작성 절차는 jam-docs. 나머지 자리의 같은 문장은 참조로 바꾼다. CLAUDE.md는 10-2에서 고친다.
4. 라이팅 경계: 일반 금칙은 `SLOP_DICTIONARY.md`(기계 검사의 원천), JAM 특화 문체는 UX 가이드, 채팅 출력은 `.claude/output-styles/fluent-korean.md`. UX 가이드에서 SLOP·fluent-korean과 겹치는 행과 기계 검사 목록은 참조로 바꾼다. `SERVER_ERROR_MESSAGE_RULE.md`는 코드 27개 파일이 «ADR 0001»로 가리키므로 남긴다.
5. 낡은 사실: docs/README «백틱 경로는 경고만»(실제는 오류), DOCUMENT_SCHEMA의 «태그 위반 경고»·없는 agent 필드 검증·basis 경고, jam-docs 정책 수 96→실제 값, marketer-trends의 수집 주체, jam-ship·UX 가이드의 MODULAR·`RarityBadge.prompt.md` 전제를 고친다. 경위는 판단 근거가 되는 실측·사고만 `rationale.md`의 스킬별 절로 옮기고(머리말의 범위를 넓힌다) 단순 이력·인라인 티켓 번호는 지운다.
