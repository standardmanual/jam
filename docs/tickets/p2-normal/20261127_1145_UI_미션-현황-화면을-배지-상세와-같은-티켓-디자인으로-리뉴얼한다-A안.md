# [UI] 미션 현황 화면을 배지 상세와 같은 티켓 디자인으로 리뉴얼한다 (A안: 검정 바탕 + 코랄 레드 티켓)

## 핵심 요약

- 요구사항: 미션 현황 화면(`/missions/[id]/status`)을 배지 상세·컬렉션 상세의 티켓 틀(`BadgeTicket`)로 감싸 리뉴얼한다(사용자 지시, 2026-11-27). 바탕은 검정(A안), 티켓색은 첨부 이미지의 코랄 레드 느낌이다. 랭킹형·달성형(달성·미달성) 모두 적용한다.
- 사용자 확정 사항: ① **A안 = 검정 바탕 + 코랄 레드 티켓 + 검정 카드**(프로토타입 `mission-status-proto-static.html`의 A안 열). ② **기존 DS 컴포넌트로 개발한다.** ③ **신규 토큰·신규 컴포넌트가 필요하면 구현 전에 사용자 확인을 받는다**(채원① `needsApproval`로 멈춘다).
- 구현 계획: 티켓 틀 안에 «내 요약 글자 상자 → 절취선 → 검정 카드(전체 순위/달성 현황)»를 둔다. 행은 기존 `RankingListRow`·`ListRow`·`ListRowChip`·`ProgressBar`를 그대로 쓴다. 정확한 재사용 판정과 필요한 토큰은 채원① 판정이 정한다.
- 관련 파일(지도):
  - `jam-web/src/app/(main)/missions/[id]/status/MissionStatusClient.tsx` — 화면 본체. 루트 `background: var(--mission-accent)`(약 197행), `MyHero`(94행), `CardHeader`(130행), 랭킹형 블록(216행~), 달성형 블록(279행~)을 티켓 구조로 바꾼다.
  - `jam-web/src/app/(main)/missions/[id]/status/page.tsx` — 서버 페이지. 미션·참가 기록을 읽어 `MissionStatusClient`를 그린다. 티켓 틀(서버 컴포넌트 `BadgeTicket`)을 어디에 두는지에 따라 손댄다.
  - `jam-web/src/app/(main)/badges/[id]/BadgeTicket.tsx`·`BadgeTicket.module.css` — 재사용 대상. 머리 종류 글자(`kindLabel`)·날짜·티켓색 입력(`TicketPaint`)을 그대로 받는다. 절취선 홈은 `var(--background)`라 페이지 바탕과 같은 색이 된다.
  - `jam-web/src/app/(main)/badges/[id]/TicketTitleBoxes.tsx` — 2px 두 칸 글자 상자(`TicketTitleBoxesView`). «내 요약» 상자에 쓸 수 있는지 채원이 판정한다.
  - `jam-web/src/lib/badgeTicket/ticketColor.ts` — 티켓색(통합 팔레트 일곱 색, 표지색 파생). `--jam-red`는 `#FF1D1D`라 첨부 이미지 코랄(`#D3474D`)과 다르다.
  - `jam-web/design-system/tokens/component.css` — `--status-card-bg`(38행), `--mission-accent`(40행), `--ticket-ink`·`--ticket-paper`(42~43행).
  - 시험: `status/MissionStatusClient.test.tsx`, `status/AchievementRow.test.tsx`, `status/page.test.tsx`.
  - 문서: `docs/service/prd/` 미션 현황 정의(`grep -rl "미션 상황\|미션 현황" docs/service/prd`), `docs/service/writing/UX_WRITING_GUIDELINE.md` 98행(용어).

## 배경 / 문제 정의

지금 미션 현황은 `--mission-accent` 단색 바탕 위 검정 카드다(티켓 20261111_2049). 배지 상세·컬렉션 상세(티켓 20261124_2252)가 티켓 디자인으로 바뀌어 미션 현황만 결이 다르다. 사용자가 두 화면의 티켓 스타일을 미션 현황에 쓰되 첨부 이미지(코랄 레드 티켓 + 검정)의 색감으로 바꾸라고 지시했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 데이터 로딩(`/api/missions/[id]/status`)·정렬·«나» 표식·빈 상태·오류 상태의 동작은 바꾸지 않는다.
- 색은 서버가 정한 값으로 첫 HTML에 담는다(`BadgeTicket`의 원칙). 클라이언트 훅으로 색을 칠하지 않는다.
- 신규 토큰·신규 정본 컴포넌트가 필요하면 만들지 않고 채원① 판정(`needsApproval`)으로 멈춰 사용자 승인을 받는다.

### UI/UX 관점
프로토타입 A안 기준.
- 머리: `JAM!` 로고, 종류 글자(랭킹형 `RANKING`, 달성형 `MISSION`), 날짜. 티켓 면 위 글자는 검정 계열.
- 절취선 1 → 글자 상자(2px 두 칸). 위 칸: 내 아바타 96, 이름, 랭킹형은 «내 기록»(48px 굵게 + 단위), 달성형은 «내 현황» 알약(달성/미달성). 아래 칸 두 개: 랭킹형 «내 순위»·«1위와 차이», 달성형 «달성한 참가자»·«전체 참가자».
- 절취선 2 → 검정 카드. 랭킹형은 «전체 순위»(+참가자 수) 목록(순위·아바타·이름·캡슐 진행 막대·값, 내 행은 «나» 원), 달성형은 «달성 현황»(+다른 참가자 수) 목록(아바타·이름·달성/미달성 칩).
- 페이지 바탕은 검정이다. 절취선 홈·점선이 바탕과 같은 검정으로 비친다.
- 로딩(눈 모양 로더)·오류·«다른 참가자 없음» 빈 상태는 지금과 같은 컴포넌트를 쓰되 검정 바탕에서 읽히게 한다.

### 컨텐츠 관점
- 새 문구(`1위와 차이`, `내 기록`, `내 현황`, `달성한 참가자`, `전체 참가자`)는 `UX_WRITING_GUIDELINE.md`의 고정 용어와 해요체 기준으로 `lib/i18n/ko.ts`에 둔다.

## 구현 계획

채원① 사전 판정(2026-11-27)을 따른다. 파일 단위:

1. **정본 변형 A** — `jam-web/src/app/(main)/badges/[id]/BadgeTicket.tsx`·`BadgeTicket.module.css`: 페이지 바탕 변형 `surface="inverse"`(래퍼가 `--background`를 `--background-inverse`로, `--foreground`를 `--snow`로 덮고 `min-h-dvh` 바탕을 칠한다). 절취선 홈·점선은 `var(--background)`를 읽어 그대로 검정으로 비친다.
2. **정본 변형 B** — `jam-web/src/app/(main)/badges/[id]/TicketTitleBoxes.tsx`: `TicketTitleBoxesView`에 «위 칸 슬롯 + 아래 2칸 통계»를 받는 변형(같은 모듈 클래스, 2px·직각·투명 면 규격 유지).
3. **신규 토큰 C** — `jam-web/design-system/tokens/primitive.css`(`--jam-coral: #D3474D`), `component.css`(`--mission-ticket: var(--jam-coral)`). 티켓색 입력은 통합 팔레트에 섞지 않고 미션 전용 값으로 넘긴다(`jam-web/src/lib/badgeTicket/ticketColor.ts`에 미션용 입력 추가 여부는 아현이 최소로 정한다). 토큰 카탈로그 자동 생성 구간 재생성.
4. **정본 변형 D·E** — `jam-web/src/components/ui/ListRow.tsx`(+ 스타일·스토리): 검정 카드 위 `onInverse` 행 톤(면 `--surface-on-inverse`, 글자 `--snow`), `ListRowChip`에 큰 크기(lg)와 외곽선 톤. 새 변형마다 스토리.
5. **화면 구조** — `status/page.tsx`(서버)가 `BadgeTicket`을 그리고 photo·body 슬롯에 클라이언트 조각을 넣는다. `status/MissionStatusClient.tsx`는 «fetch + 컨텍스트 + TopNav»만 맡는 래퍼로 줄이고, 요약 상자·목록 카드는 status 폴더 안 조각 컴포넌트로 나눈다. 인라인 `style`(MyHero 원·알약)은 정본·CSS 모듈로 옮긴다.
6. **문구** — `jam-web/src/lib/i18n/ko.ts` `d.missions`에 `1위와 차이`·`내 기록`·`내 현황`·`달성한 참가자`·`전체 참가자`.
7. **시험** — `MissionStatusClient.test.tsx`, `AchievementRow.test.tsx`, `page.test.tsx`, 정본 변형 시험·스토리. 옛 구조(`--mission-accent` 루트 배경 등)를 고정한 항목만 새 구조로 고친다.
8. **문서** — `docs/service/prd/`의 미션 현황 정의, `docs/service/writing/UX_WRITING_GUIDELINE.md` 98행, `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 해당 절(있으면).
