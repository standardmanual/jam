# [UI] C4 DS 승인 항목을 처리한다: 챕터 게이지 카드 토큰과 정본

## 핵심 요약

- 요구사항: 시안의 새 값 4개(챕터 번호 36px, 안쪽 여백 12px·2px, JAM 워드마크 칩, 영문 «CHAPTER» 라벨)에 대한 채원 사전 판정과 사용자 승인을 받고, 필요한 토큰·정본 변형을 추가한다. 다른 티켓과 병행할 수 있다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/design-system/tokens/primitive.css`, `jam-web/design-system/tokens/component.css` / `jam-web/src/components/ui/`(승인되면 새 변형)와 스토리
- 선행 티켓: 없음
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 채원 모드 ① 사전 판정을 받는다: 재사용·정본 변형·새 정본 중 무엇인지, 쓸 토큰, 텍스트 배치도, 상태 목록(시작 0, 20%, 65%, 가득, 긴 트라이브 이름, 챕터 10).
2. 승인 필요 항목을 사용자에게 보고하고 `- 사용자 승인: YYYY-MM-DD — <항목>` 줄을 티켓에 적는다(없으면 `.githooks/commit-msg`가 막는다).
3. 승인된 값만 `jam-web/design-system/tokens/primitive.css`, `component.css`에 더하고, 필요한 정본 변형을 `jam-web/src/components/ui/`에 더한다. 스토리를 함께 만든다.
4. 윈터 검수: 영문 «CHAPTER» 라벨과 JAM 워드마크 칩의 톤.

## 완료 조건

- 채원 사전 판정이 티켓에 기록돼 있고, 승인 항목마다 `사용자 승인` 줄이 있다.
- 승인된 토큰·정본만 추가됐고, 승인 항목 외 새 토큰과 리터럴 색·px가 0이다.
- 스토리와 `gen-token-catalog` 검사, `commonLiteralColors.test.ts`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 3~5개, 약 120줄(추정, 미검증)
- 체크포인트: 채원 `needsApproval` 정지가 걸린다. 사용자 승인 뒤에 구현한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
