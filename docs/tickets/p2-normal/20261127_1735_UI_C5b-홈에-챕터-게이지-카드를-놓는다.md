# [UI] C5b 홈에 챕터 게이지 카드를 놓는다

## 핵심 요약

- 요구사항: 홈 인사말 줄 아래의 캡슐 위젯(`CapsuleWidget`)을 걷고, C4가 만든 정본 `ui/ChapterGaugeCard`로 교체한다. 홈 «오늘의 현황» 2열 카드(`TodayStatusStrip`)는 건드리지 않는다(2026-11-28 사용자 정정, 티켓 20261128_0747). 동기화 뒤 `router.refresh()`로 값이 내려오면 게이지가 현재 값에서 새 값까지 차오른다.
- 구현 계획: 아래 «구현 계획»을 파일 단위로 따른다. 새 정본·새 토큰은 만들지 않는다(조합과 배치만).
- 관련 파일: `jam-web/src/app/(main)/page.tsx`, `jam-web/src/components/chapter/ChapterGaugeSection.tsx`(신규, 클라이언트)와 시험, `jam-web/src/components/chapter/ChapterRewardBlockedCard.tsx`(신규)와 시험, `jam-web/src/lib/i18n/ko.ts`(`d.chapterGauge` 신설), `jam-web/src/app/(main)/capsuleMount.test.ts`(교체), `docs/service/prd/home-feed/PRD.md`(4행, `code:` 경로 변경 커밋은 이 문서도 같이 고쳐야 훅을 통과한다), 읽기: `jam-web/src/lib/chapter/read.ts`(`getMyChapter`), `jam-web/src/lib/capsule/receive-block.ts`(`readCapsuleReceiveBlocked`), `jam-web/src/components/ui/ChapterGaugeCard.tsx`(C4 정본, 수정 금지)
- 선행 티켓: 20261127_1733(C4, CLOSED), 20261127_1734(C5a, CLOSED), 20261127_1730(C2b, CLOSED)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 사용자 결정 (2026-11-28, 카리나 문의에 대한 답)

- 막힘 안내: **카드 아래에 이어 붙인다.** 챕터 게이지 카드는 그대로 두고, 그 아래에 지금과 같은 구성의 안내 카드(두 줄 문구 + «인벤토리 가기» 버튼)를 새 카드의 폭·모서리에 맞춰 붙인다. 문구는 지금 `d.capsule.blockedBanner`를 그대로 쓴다(화면에 «캡슐» 글자가 없다). 키 이름 정리는 C7.
- 챕터가 아직 없는 유저(`chapterNo`가 null, 퀘스트 전·트라이브 선택 전): **카드를 그리지 않는다.** 이 유저에게는 온보딩 퀘스트 카드가 먼저 보인다.
- 사용자 승인: 2026-11-28 — 홈 캡슐 게이지를 챕터 게이지 카드(C4 정본)로 교체, 막힘 안내 카드는 새 카드 아래에 이어 붙이는 재배치(눈에 보이는 변경). 새 정본·새 토큰·새 변형은 없다.

## 구현 계획

C4가 정본 `ui/ChapterGaugeCard`(+ 스켈레톤, 오류 블록)와 진입·이동 모션 상수(`chapterGaugeCardMath.ts`)를 이미 만들었다. 이 티켓은 데이터를 연결하고 홈 자리를 바꾸는 일이다. 모션 상수를 옮기는 일은 C4에서 끝났다(예전 계획의 2단계 삭제).

1. **서버 조회(`page.tsx`)**: `getCapsuleStatus`·`capsulePromise`·`CapsuleWidget` import와 호출을 걷는다. 대신 `settlePromise`(`settleAfterSlotsFreed`) 뒤에 `getMyChapter(createServiceClient(), userId)`와 `readCapsuleReceiveBlocked(createServiceClient(), userId)`를 이어서 읽는다(대기 보상을 먼저 정리해 막힘이 바로 풀리도록, 지금과 같은 순서). 막힘 안내는 이용 정지 중이면 없다(지금 `getCapsuleStatus`의 `toNotice(suspended, blocked)`와 같은 판정: 홈이 이미 읽는 정지 배너 값 `suspensionPromise`를 재사용하고 정지 조회를 새로 더하지 않는다). 두 조회가 실패하면 던지지 않고 `console.error` 뒤 null로 접어 카드가 오류 블록을 그린다. `capsule_get_or_create`(캡슐 행 생성)는 더 이상 홈이 부르지 않는다.
2. **`components/chapter/ChapterGaugeSection.tsx`(신규, `'use client'`)**: props `chapter: MyChapterResult | null`(서버에서 직렬화한 값), `blocked: { pendingItemCount: number } | null`. `chapter`가 null이거나 `ok: false`이면 `ChapterGaugeCardError`(카드와 같은 높이, 버튼 «다시 시도»가 `router.refresh()`), `ok`이고 `chapterNo === null`이면 아무것도 그리지 않는다, 그 외에는 `ChapterGaugeCard`에 `tribeName`·`chapterNo`·`filled=chapterJam`·`required=requiredJam`(마지막 챕터는 null)과 `d.chapterGauge`의 문구를 넘긴다. `blocked`가 있으면 카드 아래에 `ChapterRewardBlockedCard`를 놓는다. 클라이언트 재조회 API는 만들지 않는다(서버가 `router.refresh()`로 새 값을 내려 주면 정본이 현재 값에서 새 값으로 이동한다).
3. **`components/chapter/ChapterRewardBlockedCard.tsx`(신규, `'use client'`)**: 지금 `components/capsule/CapsuleBlockedCard.tsx`의 구성(`Card inverse`, 두 줄 문구, 소형 `Button secondary`로 `/inventory`)을 가져오되, 윗모서리를 각지게 하고 새 카드 아래 모서리(`rounded-2xl`)에 맞춰 이어 붙인다(겹침은 카드 모서리 반지름만큼, 눈금 안의 값만 쓴다). 문구는 `d.capsule.blockedBanner`를 그대로 쓴다. 옛 `CapsuleBlockedCard`는 지우지 않는다(내 프로필 C6가 바뀔 때까지 쓰이고, 제거는 D단계).
4. **문구(`lib/i18n/ko.ts`)**: `d.chapterGauge`를 새로 둔다: 영문 라벨 `CHAPTER`(영문 유지는 Q-k 확정, 스크린리더에는 장식), 카드 접근성 라벨 `챕터 {chapterNo}, {tribeName}`(트라이브가 없으면 `챕터 {chapterNo}`), 트랙 접근성 라벨 `다음 챕터까지 잼 {filled} / {required}`(마지막 챕터는 `잼 {filled}`), 오류 문구와 «다시 시도». `d.capsule.*`는 지우지 않는다(프로필 C6·D단계). 문구는 `UX_WRITING_GUIDELINE.md`를 따르고 민지가 12번으로 검수한다.
5. **시험**: `ChapterGaugeSection.test.tsx`(정적 렌더: 값이 서버 렌더 결과에 들어 있음, 마지막 챕터에서 필요 잼 줄이 비어 있음, `chapterNo` null이면 빈 출력, `ok: false`이면 오류 블록과 «다시 시도», `blocked`이면 카드 아래에 막힘 카드), `ChapterRewardBlockedCard.test.tsx`(문구와 버튼, 윗모서리 각짐, `pendingItemCount` 0 이하 문장). `capsuleMount.test.ts`를 새 구조 시험으로 교체한다: 홈이 `CapsuleWidget`·`getCapsuleStatus`를 쓰지 않고 `getMyChapter`를 읽으며, 카드가 인사말 아래·`TodayStatusStrip` 위에 한 번만 있고, 감싸는 곳에 z-index가 없고, `TodayStatusStrip`의 면이 바뀌지 않았다.
6. **문서**: `docs/service/prd/home-feed/PRD.md` 4행(캡슐 → 챕터 게이지 카드, 막힘 안내와 «카드 없음» 상태)과 서술. `node scripts/gen-home-feed-doc.mjs`로 생성 구간을 다시 만든다. 정책 대시보드(`policiesData.ts`)는 값이 바뀌지 않아 이 티켓에서 건드리지 않는다.
7. **하지 않는 것**: `ui/ChapterGaugeCard`·토큰·`TodayStatusStrip` 수정, 내 프로필(C6), 옛 `capsule/*` 파일 삭제(D단계), `d.capsule.*` 문구 삭제·문구 개정(C7), `/api/capsule` 변경.

## 완료 조건

- 홈에 챕터 게이지 카드가 보이고 시안과 같은 구성이다(트라이브 이름, CHAPTER 번호, JAM 칩이 붙은 게이지, 필요량 숫자). 서버 렌더 결과에 값이 들어 있다. 확인: `ChapterGaugeSection.test.tsx`와 로컬 화면(390px, 카리나).
- 챕터가 없는 유저는 카드가 없고, 오류이면 «다시 시도» 블록이 카드와 같은 높이로 보이고, 챕터 10이면 필요 잼 줄이 비어 있다.
- 대기 보상으로 막힌 유저(`readCapsuleReceiveBlocked`의 `blocked`)는 카드 아래에 막힘 안내 카드가 이어 붙고, 이용 정지 중이면 안내가 없다.
- 진입 모션은 정본의 값을 그대로 쓰고(0.26초 쉼, 1.5초 채움, 숫자 팝인, 한 방문에 한 번), 모션 줄이기에서는 바로 마지막 값이다. 동기화 뒤 값이 바뀌면 현재 값에서 이동한다.
- 홈에서 `CapsuleWidget`과 `getCapsuleStatus`가 사라졌고 `TodayStatusStrip`은 바뀌지 않았다. 채원 사후 리뷰와 `commonLiteralColors.test.ts`가 통과한다.
