# [UI] C5b 홈에 챕터 게이지 카드를 놓는다

## 핵심 요약

- 요구사항: 홈 인사말 줄 아래에 확정 시안의 챕터 게이지 카드를 놓는다. 동기화 뒤 게이지가 차오르고 진입 모션이 현행과 같다. 캡슐 위젯은 홈에서 뺀다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(5단계).
- 관련 파일: `jam-web/src/components/chapter/ChapterGaugeCard.tsx`(신규)와 시험 / `jam-web/src/app/(main)/page.tsx`(11·13·14·53~59·126~129행) / `jam-web/src/app/(main)/capsuleMount.test.ts`(교체), `jam-web/src/lib/capsule/capsule-gauge.ts`(모션 함수 이동 원본)
- 선행 티켓: 20261127_1733(C4), 20261127_1734(C5a), 20261127_1730(C2b)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 새 `jam-web/src/components/chapter/ChapterGaugeCard.tsx`와 시험: 확정 시안(캔버스 최신 값)을 C4 토큰으로 구현한다.
2. 모션: 기존 `lib/capsule/capsule-gauge.ts`의 진입·이동 함수(`GAUGE_ENTRY_DELAY_MS`, `GAUGE_ENTRY_MS` 등)를 새 위치로 옮겨 재사용한다. 값은 같다.
3. `jam-web/src/app/(main)/page.tsx`: 11·13·14행 import, 53~59행 캡슐 조회, 126~129행 `CapsuleWidget` 호출을 새 카드와 `getMyChapter`로 바꾼다.
4. `jam-web/src/app/(main)/capsuleMount.test.ts`를 새 카드 시험으로 교체한다.
5. 챕터 10(마지막)의 표시는 Q-e 결정대로 한다.

## 완료 조건

- 홈에 카드가 보이고 시안과 같은 구성이다(트라이브 이름, CHAPTER 번호, JAM 칩이 붙은 게이지, 필요량 숫자). 서버 렌더 결과에 값이 들어 있다.
- 진입 모션이 현행 상수와 같고(0.26초 쉼, 1.5초 채움, 숫자 팝인, 한 방문에 한 번), 모션 줄이기에서는 바로 마지막 값이다.
- 홈에서 캡슐 위젯과 캡슐 조회가 사라졌다. 채원 사후 리뷰와 `commonLiteralColors.test.ts`가 통과한다.
