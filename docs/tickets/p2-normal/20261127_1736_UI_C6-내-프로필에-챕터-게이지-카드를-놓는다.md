# [UI] C6 내 프로필에 챕터 게이지 카드를 놓는다

## 핵심 요약

- 요구사항: 내 프로필에 같은 카드를 놓고, 타인 프로필의 DOM과 RSC 페이로드에는 진행값이 실리지 않게 한다. 프로필 헤더의 «챕터 N» 줄은 정해진 대로 처리한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/src/app/(main)/profile/ProfileClient.tsx`(30~32·99~128·567·615~620행) / `jam-web/src/app/(main)/[username]/page.tsx`(10·71행) / `jam-web/src/components/chapter/ChapterLine.tsx`와 시험 3개
- 선행 티켓: 20261127_1735(C5b)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 사용자 결정 (2026-11-28, 카리나 문의에 대한 답)

- 내 프로필 헤더의 «트라이브 · 챕터 N» 작은 글씨 줄은 **내 프로필에서만 제거**한다(카드와 중복). 다른 유저 프로필의 같은 줄(`public` 모양)은 그대로 둔다. 헤더 같은 행 오른쪽의 «편집» 버튼은 남긴다.
- 막힘 안내 카드는 프로필에서도 **홈과 같이 게이지 카드 아래에 이어 붙인다**(기존 캡슐 위젯이 프로필에서도 막힘 카드를 보였다).

## 구현 계획

홈(C5b)에서 만든 `components/chapter/ChapterGaugeSection.tsx`(client, props `chapter: MyChapterResult | null`, `blocked: { pendingItemCount } | null`)를 그대로 쓴다. 새 컴포넌트·토큰·정본 수정은 없다.

1. `jam-web/src/app/(main)/[username]/page.tsx`: 10·70~76행 `getCapsuleStatus`·`capsulePromise`를 걷고, 내 프로필에서만 `settleAfterSlotsFreed` 뒤에 `getMyChapter`(81행의 `myChapterPromise`가 이미 있다)와 `readCapsuleReceiveBlocked`를 읽는다. 둘 다 실패하면 던지지 않고 `console.error` 뒤 null로 접는다(홈 `page.tsx` 58~69행과 같은 방식). `getMyTribeName` 호출(84행·118~119행)은 `getMyChapter`가 `tribeName`을 돌려주므로 제거한다(함수 삭제는 하지 않는다). 프로필에는 이용 정지 배너가 없으므로 막힘 카드는 정지 여부와 상관없이 `readCapsuleReceiveBlocked` 결과만 따른다(기존 캡슐 위젯과 같은 동작). 91·101행 `capsuleInitial`, 376행 `{ capsuleInitial: ..., chapterInitial }`는 `{ chapter, blocked }`(내 프로필 전용)로 바꾼다. 타인 프로필에는 조회도 prop도 없다.
2. `jam-web/src/app/(main)/profile/ProfileClient.tsx`: 30~31행 `CapsuleWidget`·`CapsuleStatus` import와 99행 `capsuleInitial` prop을 `chapter`·`blocked`(내 프로필 전용, 옵션) prop으로 바꾼다. 102~106행 `chapterInitial` prop과 567행 `ChapterLine variant="mine"`은 제거하고(행의 오른쪽 «편집» 버튼 래퍼는 유지), 615~620행 `CapsuleWidget` 호출을 `isOwnProfile && chapter !== undefined && <ChapterGaugeSection chapter={chapter} blocked={blocked ?? null} />`로 바꾼다. 자리는 지금의 캡슐 위젯 자리(프로필 헤더와 피드·목록 사이, 간격은 바깥 gap 하나)다. 타인 프로필의 `publicChapter`·`ChapterLine variant="public"`(615행 위)은 그대로 둔다.
3. `jam-web/src/components/chapter/ChapterLine.tsx`: `mine` 모양과 `MyChapterLineData` 타입을 걷고 `public` 모양만 남긴다(`ChapterLine` Props에서 `variant` 구분이 필요 없으면 단순화한다). `jam-web/src/components/chapter/__tests__/ChapterLine.test.tsx`도 맞춘다. `d.chapter.line.*` 문구 키 삭제는 하지 않는다(C7).
4. 시험: `profile/ProfileClient.capsule.test.tsx`를 챕터 게이지 카드 기준으로 바꾸고(이름도 `ProfileClient.chapterGauge.test.tsx`로), `profile/ProfileClient.chapter.test.tsx`에서 `mine` 줄 단언을 걷고 `public` 줄은 유지하며, `[username]/__tests__/page.test.tsx`는 내 프로필에서 `chapter`·`blocked`가 내려가고 **타인 프로필의 직렬화한 prop에 진행값(`chapterJam`·`requiredJam`·`chapter`·`blocked`)이 0건**임을 단언한다. `profile/page.test.tsx`에 `capsuleInitial` 참조가 있으면 맞춘다.
5. 문서: `docs/service/prd/chapter/PRD.md`의 code 경로·134~149행(프로필 표와 «내 진행은 타인에게 실리지 않는다» 절)을 새 구조로 고친다. 정책 대시보드는 값이 바뀌지 않아 건드리지 않는다.
6. **하지 않는 것**: `ui/ChapterGaugeCard`·`ChapterGaugeSection`·`ChapterRewardBlockedCard`·토큰 수정, 홈 수정, `components/capsule/*` 삭제(D단계), `d.capsule.*`·`d.chapter.line.*` 삭제와 문구 개정(C7), `getMyTribeName` 함수 삭제, `/api/capsule` 변경, 다른 유저 프로필 줄 변경.
