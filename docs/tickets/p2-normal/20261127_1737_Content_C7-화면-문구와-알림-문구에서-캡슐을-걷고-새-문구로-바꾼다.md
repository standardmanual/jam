# [Content] C7 화면 문구와 알림 문구에서 캡슐을 걷고 새 문구로 바꾼다

## 핵심 요약

- 요구사항: UX 라이팅 가이드와 `ko.ts`의 `d.capsule.*`(26곳)를 새 카드 문구로 바꾸고, 알림 문구를 정리한다. 이미 받은 알림 행은 Q-f 결정대로 처리한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `docs/service/writing/UX_WRITING_GUIDELINE.md`(111·207~230행) / `jam-web/src/lib/i18n/ko.ts`(`d.capsule.*`) / `jam-web/src/lib/notifications/message.ts`, `types.ts`, `href.ts`, `jam-web/src/app/(main)/notifications/NotificationsClient.tsx`
- 선행 티켓: 20261127_1722(A2), 20261127_1735(C5b)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 사용자 결정 (2026-11-28, 카리나 문의에 대한 답)

- Q-f(과거 기록의 «캡슐» 문구): **문구를 «캡슐» 없이 바꿔 보인다.** 이미 받은 소식 행(`capsule_nearly_full`, `capsule_jam_blocked`)은 사실만 남기는 문장으로, 인벤토리 상세의 «캡슐 열기 보상» 출처 표시는 «캡슐» 없는 말로 바꾼다. DB 행·enum 값·키 이름은 지우거나 바꾸지 않는다(데이터 변경 없음).
- 범위 밖으로 둔 것: 어드민 화면·유저 상세의 원장 사유 표시는 C9, 확률 안내 «캡슐» 구역은 C8, 죽은 코드(`components/capsule/*`, `api/capsule/*`)와 그 문구 키는 D단계에서 지운다. Q-j(포인트 동사)는 C14b 전 결정이라 이 티켓에서 건드리지 않는다.

## 구현 계획

살아 있는 화면과 알림에서 기능 용어 «캡슐»이 보이는 자리만 바꾼다. 홈·프로필에서 쓰는 막힘 카드 문구가 `d.capsule.blockedBanner`에 걸려 있어 새 위치로 옮기는 것이 핵심이다.

1. `jam-web/src/lib/i18n/ko.ts`
   - `d.capsule.blockedBanner`(line1·line2·line2NoCount·cta, 약 995행 앞)를 `d.chapterGauge`(C5b가 만든 객체) 아래 `blocked` 키로 옮긴다. 문구 자체에는 «캡슐»이 없어 글자는 그대로다. 호출부 `jam-web/src/components/chapter/ChapterRewardBlockedCard.tsx`(31행 `const copy = d.capsule.blockedBanner`)와 그 시험, `jam-web/src/components/ui/Button.stories.tsx`(115행)·`Card.stories.tsx`(41·63·64행), 옛 `components/capsule/CapsuleBlockedCard.tsx`(31행, 죽은 코드지만 컴파일이 깨지면 안 되므로 같은 새 키를 가리키게 하거나 옛 키를 그대로 둔다. 어느 쪽이든 D1에서 지울 때 걸리는 곳이 없어야 한다)를 맞춘다.
   - `d.inventory.obtainByCapsule`(510행 `'캡슐 열기 보상'`)을 «캡슐» 없는 출처 문구로 바꾼다. 이웃 키 `obtainByChapterReward: '챕터 오름 보상'`과 구분돼야 하고(후보: «잼으로 받은 보상»), 최종 문구는 윈터 검수가 정한다. 키 이름은 바꾸지 않는다(`ObtainRouteKey`의 `capsule` 값, `lib/inventory/__tests__/obtainRoute.test.ts`, `LockedItemDetail.tsx` 62행이 쓴다).
   - 알림 문구 `msgCapsuleNearlyFull`·`msgCapsuleNearlyFullNoStage`·`msgCapsuleJamBlocked`(1714~1718행)를 «캡슐»·«받기 버튼»·«%» 없이 그때 있었던 일을 사실만으로 적은 해요체 문장으로 바꾼다(차분·사실, 서두르게 하는 말 금지). 윗 주석의 설명도 맞춘다.
2. `jam-web/src/lib/notifications/message.ts`(709~720행): `capsule_nearly_full` 분기가 `percent` 변수를 만들어 넘기는데 새 문구에는 없다면 그 변수와 단계 판정을 걷고 두 문구를 하나로 합친다(키 정리). `types.ts`(278·285행)와 `href.ts`(172행)의 enum 값·payload 타입·착지는 바꾸지 않는다. `jam-web/src/app/(main)/notifications/NotificationsClient.tsx`(70행)는 바뀌는 것이 없으면 손대지 않는다.
3. `docs/service/writing/UX_WRITING_GUIDELINE.md`: 111·112·207~230·402·404행 등 «캡슐» 15곳을 개정한다. «캡슐 위젯 안내 문구» 절(207~230행)은 «챕터 게이지 카드 안내 문구»로 다시 쓴다(막힘 카드 두 줄 안내와 «인벤토리 가기», 오류 블록, 접근성 라벨, 동기화 토스트). 용어 표 111행(캡슐이 가득 찼어요)·112행은 인벤토리 기준으로 고치고, 영문 라벨 `CHAPTER`를 고정 용어 예외로 적는다. 죽은 코드의 문구 목록은 «D단계에서 삭제»로 표시한다.
4. 시험: `NotificationsClient.test.tsx`, `lib/notifications/__tests__/message-href.test.ts`·`kst-group-key.test.ts`, `lib/inventory/__tests__/obtainRoute.test.ts`, `ProfileClient.chapterGauge.test.tsx`, `ChapterRewardBlockedCard.test.tsx`에서 바뀐 문구·키를 새 값으로 단언한다. «캡슐» 글자가 사라졌음을 단언하는 시험을 하나 둔다.
5. 윈터 검수(아현이 아닌 카리나가 구현 뒤 `jam-tribe`로 부른다): 바뀐 알림 문구, 인벤토리 출처 문구, 가이드의 용어 개정, 영문 `CHAPTER` 예외.
6. **하지 않는 것**: `components/capsule/*`·`api/capsule/*`·`lib/capsule/*` 삭제와 그 문구 키 삭제(D단계), 확률 안내 페이지(C8), 어드민 화면·정책 대시보드·유저 상세 원장 표시(C9·C10a), DB·enum 값·키 이름 변경, 알림 payload 타입 변경, Q-j.

### 구현 내용 요약

살아 있는 화면과 알림에서 기능 용어 «캡슐»이 보이던 자리를 바꿨다.
- 홈·프로필 막힘 카드 문구 `d.capsule.blockedBanner`를 `d.chapterGauge.blocked`로 옮겼다(글자는 그대로). 호출부 `ChapterRewardBlockedCard`, 옛 `CapsuleBlockedCard`(죽은 코드, 컴파일 유지용), 스토리 2개, 시험을 새 키로 맞췄다.
- 이미 받은 소식 문구(Q-f)를 «캡슐»·«받기 버튼»·«%» 없이 사실만 남기게 바꿨다. 세 키(`msgCapsuleNearlyFull`·`msgCapsuleNearlyFullNoStage`·`msgCapsuleJamBlocked`)를 두 키(`msgPastRewardHeld`·`msgPastJamBlocked`)로 정리했고 `message.ts`에서 단계 판정과 `percent` 변수를 걷었다. DB 행·enum 값·payload 타입·`href.ts`·`NotificationsClient.tsx`는 건드리지 않았다.
- 인벤토리 상세의 출처 문구 `d.inventory.obtainByCapsule`을 «이전 잼 보상»으로 바꿨다(키 이름과 `ObtainRouteKey`는 그대로).
- UX 라이팅 가이드의 용어 표와 «챕터 게이지 카드 안내 문구» 절을 개정하고 영문 `CHAPTER` 예외와 범위를 적었다. 운영 로직 문서 603행의 절 이름 참조도 맞췄다.

### UX Writing 검증 / 윈터 검수 (2026-11-28)
- 이미 받은 소식 두 건: 통과. 두 번째 문장의 «쌓이지 않았어요»는 용어 체계(잼의 양은 «모으다»)에 맞춰 «모이지 않았어요»로 고쳤다.
- 인벤토리 출처 문구: «잼으로 받은 보상»은 «챕터 오름 보상»과 겹쳐 읽히고 지금은 새로 생기지 않는 옛 경로라, 윈터 제안 «이전 잼 보상»으로 바꿨다. 이 라벨이 `LockedItemDetail`과 일반 아이템 배지 상세 두 화면에서 같이 쓰일 때의 폭·줄바꿈은 확인하지 않았다.
