# [Content] C7 화면 문구와 알림 문구에서 캡슐을 걷고 새 문구로 바꾼다

## 핵심 요약

- 요구사항: UX 라이팅 가이드와 `ko.ts`의 `d.capsule.*`(26곳)를 새 카드 문구로 바꾸고, 알림 문구를 정리한다. 이미 받은 알림 행은 Q-f 결정대로 처리한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `docs/service/writing/UX_WRITING_GUIDELINE.md`(111·207~230행) / `jam-web/src/lib/i18n/ko.ts`(`d.capsule.*`) / `jam-web/src/lib/notifications/message.ts`, `types.ts`, `href.ts`, `jam-web/src/app/(main)/notifications/NotificationsClient.tsx`
- 선행 티켓: 20261127_1722(A2), 20261127_1735(C5b)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `docs/service/writing/UX_WRITING_GUIDELINE.md`(15곳, 111·207~230행): 용어와 카드 안내 문구를 개정한다.
2. `jam-web/src/lib/i18n/ko.ts`: `d.capsule.*` 26곳을 새 키로 바꾼다.
3. `jam-web/src/lib/notifications/message.ts`(709~720행), `types.ts`, `href.ts`(172행), `NotificationsClient.tsx`: 알림 enum 값은 지우지 않고(`ch5-capsule-alerts`) 새 소식 문구를 정한다.
4. 윈터 검수를 받는다.

## 완료 조건

- 화면과 알림 문구에 기능 용어 «캡슐»이 없다(유지 목록 제외). 문구가 UX 라이팅 가이드(해요체, 고정 용어)를 따른다.
- 이미 받은 알림 행의 처리가 Q-f 결정대로 동작한다.
- 윈터 검수 결과가 티켓에 남아 있고 `check-slop` 검사와 `scripts/verify.sh`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 6개, 약 150줄(추정, 미검증)
- 체크포인트: 윈터 검수와 Q-f(과거 기록 문구) 결정이 선행이다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
