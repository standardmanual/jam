# [Admin] C9a 어드민 밸런스: 챕터별 필요 잼 편집으로 바꾼다

## 핵심 요약

- 요구사항: 어드민 밸런스의 «챕터» 구역이 점수(`required_score`) 대신 «챕터별 필요 잼»(`required_jam`)을 편집하게 바꾼다. «캡슐» 구역을 걷는 일은 C10b로 옮겼다(아래 결정).
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/src/components/admin/balance/CapsuleSection.tsx`, `ChapterSection.tsx` / `jam-web/src/lib/admin/balance/capsule.ts`, `chapter.ts`, `sections.tsx` / `jam-web/src/app/admin/balance/page.tsx`, `jam-web/src/app/api/admin/balance/route.ts`와 시험
- 선행 티켓: 20261127_1724(B1)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 순서 결정 (2026-11-28, 카리나, 구현 중단 보고에 대한 답)

첫 구현이 «캡슐 구역을 구역 배열에서 빼면 밸런스 대시보드(`balanceDashboard/targets.ts`의 «바로 조정» 링크가 `sectionId: 'capsule'`을 가리킴)와 그 시험 둘, 저장 라우트 시험의 «캡슐 구역» 블록이 깨진다»며 멈췄다. 이 파일들은 C10b(밸런스 대시보드와 생태계 노드의 캡슐 지표) 범위이고 C10b는 C9a 뒤 순서다. 그래서 **«캡슐» 구역을 걷는 일(구역 배열에서 빼기, `CapsuleSection.tsx` 삭제, 대시보드 링크·시험·저장 라우트 시험 정리, 동기화 구역의 «캡슐과 함께 쓰는 값» 문구)은 C10b로 옮기고**, 이 티켓은 챕터 구역을 `required_jam`으로 바꾸는 데 집중한다. C10b 티켓에 이 항목들을 적었다. 사용자 승인 대상이 아닌 순서 조정이라 카리나가 정했다.

## 구현 계획 (2026-11-28, 현재 코드 기준으로 다시 씀)

어드민 밸런스 설정(`/admin/balance`)에서 이미 있는 «챕터» 구역(`id = 'chapter'`)이 점수 대신 **챕터별 필요 잼**(`chapter_definitions.required_jam`, 마이그레이션 364로 DB에 이미 있다: 챕터 1~9가 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960, 챕터 10은 NULL)을 편집하게 한다. 새 구역은 만들지 않는다. 챕터 보상 편집(`chapter_reward_policy`)은 C9b 소관이다. DB·SQL 변경은 없다(열은 이미 있다).

1. `jam-web/src/lib/admin/balance/chapter.ts`(221줄, 구역 id `chapter`): `required_score` 읽기·쓰기를 `required_jam`으로 바꾼다. `CHAPTER_DEFAULT_REQUIRED`(옛 점수 0, 1000, 2300 …)는 마이그레이션 364 시드 값 870 … 3,960(챕터 10 없음)으로 바꾼다. 칸 이름은 `required_jam:N`(옛 `required:N`과 겹치지 않게), 단위는 «잼», 챕터 1~9가 편집 칸이다(챕터 1도 편집한다. 옛 구조의 «챕터 1은 0으로 고정»은 없어진다). 챕터 10은 칸이 없고 «필요한 잼이 없어요(마지막 챕터)»로 읽기만 보인다(NULL을 `0`으로 바꿔 보이지 않는다). 값은 1 이상의 정수이고 `validateRequiredOrder`(앞 챕터보다 커야 한다)는 없앤다(필요량이 챕터마다 꼭 늘 필요는 없다). 읽기는 가공하지 않은 행에서 읽고 `required_jam`이 NULL인 챕터 1~9(정의 위반)가 있으면 던진다. 행 단위 조건부 갱신과 되돌림은 지금 구조(`rowwise.ts`)를 그대로 쓴다. `CHAPTER_DEFINITION_SELECT`는 `chapter_no, required_jam, updated_at`이다. 모든 칸의 `affectsDisclosure`는 `false`다(확률 안내가 읽지 않는다).
2. `jam-web/src/components/admin/balance/ChapterSection.tsx`: 안내 문장(`CHAPTER_RISEN_NOTICE`, 지금은 «챕터는 캡슐이 100%에 닿은 횟수로 오르고 …»)을 새 구조로 다시 쓴다. 담을 내용: 이미 오른 유저의 챕터는 내려가지 않는다, 챕터는 잼을 모아 오르고 넘친 잼은 다음 챕터로 이월된다, 이 값은 홈·프로필 챕터 게이지 카드의 필요 잼으로 보인다, 챕터 번호는 늘리거나 줄이지 않고 값만 바꾼다. 문구는 어드민 해요체이고 «캡슐»·«점수»를 쓰지 않는다.
3. `jam-web/src/lib/admin/balance/sections.tsx`: «챕터» 항목의 `description` 두 줄을 새 구조로 고친다. **«캡슐» 구역(`CAPSULE_BINDING`·`CapsuleSection`)은 이 티켓에서 구역 배열에 그대로 둔다**(아래 결정). 맨 위 설명 주석에서 챕터 구역 서술만 맞춘다. `jam-web/src/app/admin/balance/page.tsx`와 저장 라우트 `jam-web/src/app/api/admin/balance/route.ts`(구역 배열 하나를 읽는 구조)는 바뀌는 것이 없으면 손대지 않는다.
4. 동기화 구역의 «캡슐과 함께 쓰는 값» 안내(`jam-web/src/lib/admin/balance/sync.ts`의 `SHARED_GROUP` 등)와 «캡슐» 구역 설명 문구는 이 티켓에서 건드리지 않는다(구역이 C10b에서 걷힌다).
5. 시험: `jam-web/src/lib/admin/balance/__tests__/chapter.test.ts`와 `jam-web/src/components/admin/balance/__tests__/sections.test.tsx`를 새 구조로 고친다. 챕터 1~9 칸이 870 … 3,960으로 보이고 챕터 10은 칸이 없고 «필요한 잼이 없어요»로 보이며, 저장하면 `required_jam`이 바뀌고 이력이 남고, 충돌(409)·행 단위 되돌림이 그대로 동작하고, «캡슐» 구역은 그대로 남아 있고(`sections.test.tsx`의 캡슐 단언 유지), 챕터 구역 화면에 «캡슐»·«점수» 글자가 없다는 단언을 하나 둔다.
6. 문서: `docs/service/prd/`의 어드민 밸런스 PRD(`admin-ui/` 또는 `balance` 관련 문서에서 «캡슐 구역»·«챕터 구역»을 서술한 곳)를 새 구조로 고친다. 정책 대시보드 `policiesData.ts`의 어드민 구역 서술은 C10a 소관이라 건드리지 않고 발견하면 요약에 남긴다.
7. 어드민은 채원 판정 제외(shadcn 표준). 아현·민지는 격리 워크트리에서 실렌더를 시도하지 않는다. 실렌더 검증은 카리나가 머지 뒤 push 전에 한다(패턴 13).
8. **하지 않는 것**: 챕터 보상 편집 구역(C9b), `chapter_reward_policy`·확률 칸 편집, DB·SQL 변경, `lib/capsule/*` 삭제(D3), `policiesData.ts`(C10a), 유저 상세 화면의 챕터·캡슐 표시(C9 이후 별도), 챕터 번호 더하기·줄이기.
