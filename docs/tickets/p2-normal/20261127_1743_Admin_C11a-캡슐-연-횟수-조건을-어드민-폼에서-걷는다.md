# [Admin] C11a «캡슐 연 횟수» 조건을 어드민 폼에서 걷는다

## 핵심 요약

- 요구사항: 미션·배지 어드민 폼에서 조건 키 `capsule_open_count`를 새로 고를 수 없게 하고, 평가기는 옛 행이 깨지지 않게 «퇴역 키»로 남긴다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/src/lib/missions/condition-keys.ts`, `jam-web/src/app/admin/missions/{missionConditionFields,missionFormRules}.ts`, `MissionForm.tsx` / `jam-web/src/app/admin/badges/conditionFormFields.ts`, `jam-web/src/lib/badge-engine/conditionRegistry.ts`, `jamActionItemMetrics.ts`와 시험
- 선행 티켓: 20261127_1722(A2)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/lib/missions/condition-keys.ts`(171·436행), `jam-web/src/app/admin/missions/missionConditionFields.ts`, `missionFormRules.ts`, `MissionForm.tsx`: 선택지에서 뺀다.
2. `jam-web/src/app/admin/badges/conditionFormFields.ts`: 같은 처리.
3. `jam-web/src/lib/badge-engine/conditionRegistry.ts`, `jamActionItemMetrics.ts`: 평가기는 퇴역 키로 유지해 옛 행이 계속 평가된다.
4. 시험: 폼 필드, 규칙, 평가기 시험.

## 완료 조건

- 미션·배지 폼에서 `capsule_open_count`를 새로 고를 수 없고, 이미 저장된 옛 행은 폼에서 열어도 깨지지 않는다.
- 평가기가 퇴역 키 행을 계속 평가한다(이미 받은 배지 유지).
- 관련 시험과 `scripts/verify.sh`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 8개 이상, 약 250줄(추정, 미검증). 분할된 첫 조각
- 체크포인트: admin 유형: 카즈하가 보유자 수(미션·J8-1 배지)를 확인한 뒤 진행한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
