# [Content] C11b J8-1 계열 배지와 «캡슐 연 횟수» 미션을 비활성화한다

## 핵심 요약

- 요구사항: «캡슐 연 횟수»를 조건으로 하는 J8-1 계열 배지(5, 20, 50, 100, 200회)와 해당 미션을 어드민에서 비활성화한다. 이미 받은 배지는 유지하고 행은 지우지 않는다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/supabase/migrations/36x_deactivate_capsule_open_badges.sql`(+ `_down.sql`) / `docs/service/content/ACTIVITY_BADGES.md`
- 선행 티켓: 20261127_1743(C11a)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. 마이그레이션 `jam-web/supabase/migrations/245_*`에 있는 J8-1 5행을 비활성화하는 새 마이그레이션과 되돌림 SQL을 쓴다(삭제하지 않는다).
2. `capsule_open_count` 조건 미션을 같은 방식으로 비활성화한다. 보유자 수는 카즈하가 확인한다.
3. 컨텐츠 문서(`docs/service/content/ACTIVITY_BADGES.md`)의 해당 계열에 «비활성» 표시를 남긴다.

## 완료 조건

- J8-1 5행과 `capsule_open_count` 조건 미션이 비활성이고, 행 수가 그대로다(삭제 0).
- 이미 받은 유저의 배지가 유지된다(이전·이후 보유 행 수 대조).
- 되돌림 SQL을 확인했고 컨텐츠 문서에 비활성 표시가 있다.

## 규모와 체크포인트

- 규모: 파일 3개, 약 100줄(추정, 미검증). 분할된 둘째 조각
- 체크포인트: db 유형: 데이터를 바꾸므로 SQL 작성까지만 서브에이전트가 하고 실행은 카리나가 한다. 보유자 수를 사용자에게 보고한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
