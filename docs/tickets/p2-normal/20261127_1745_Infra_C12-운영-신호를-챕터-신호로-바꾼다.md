# [Infra] C12 운영 신호를 챕터 신호로 바꾼다

## 핵심 요약

- 요구사항: `#jam-alert` 일일 요약의 캡슐 줄을 챕터 신호(주당 오름 수 등)로 바꾸고, 임계는 오픈 뒤 관찰값으로 정한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(4단계).
- 관련 파일: `jam-web/src/app/api/cron/capsule-signals/route.ts`, `jam-web/src/lib/capsule/dailySignals.ts` / `jam-web/src/lib/admin/cronSchedule.ts`, `jam-web/src/lib/admin/opsSignals/load.ts`, `scripts/data/ops-pattern-topics.json`
- 선행 티켓: 20261127_1730(C2b)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/app/api/cron/capsule-signals/route.ts`와 `jam-web/src/lib/capsule/dailySignals.ts`: 새 신호를 계산하는 챕터 신호 크론으로 바꾼다(이름 변경은 D2에서).
2. `jam-web/src/lib/admin/cronSchedule.ts`, `jam-web/src/lib/admin/opsSignals/load.ts`를 맞춘다.
3. `scripts/data/ops-pattern-topics.json`(19곳)과 마이그레이션 312의 패턴 사전 시드의 캡슐 주제를 챕터 주제로 바꾼다.
4. 카즈하가 새 신호 정의를 확인한다.

## 완료 조건

- `#jam-alert` 일일 요약에 챕터 신호가 나오고 캡슐 줄이 없다(시험 환경의 메시지 본문으로 확인).
- 패턴 사전의 캡슐 주제가 챕터 주제로 바뀌어 있고, 임계 기준이 «오픈 4주 관찰값으로 정한다»로 적혀 있다.
- 카즈하 확인 결과가 티켓에 있고 `scripts/verify.sh`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 6개, 약 200줄(추정, 미검증)
- 체크포인트: 카즈하 확인이 필요하다. 임계값은 추정이 아니라 오픈 뒤 관찰값으로 정한다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
