# [BadgeEngine] C13 오늘 큐레이션 노출 태그 4개를 챕터 기준으로 바꾸거나 없앤다

## 핵심 요약

- 요구사항: 오늘 큐레이션 노출 태그(`capsule_full`, `capsule_nearly_full`, `jam_plenty`, `jam_low`)를 챕터 기준으로 대체하거나 없앤다. 먼저 카드 행이 이 태그를 쓰는지 확인하고, 방향은 사용자와 정한다.
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(3단계).
- 관련 파일: `jam-web/src/lib/today/exposure.ts`(279~297행), `jam-web/src/lib/today/exposureThresholds.ts` / `docs/service/prd/home-feed/PRD.md`(152~160·196~199행)와 시험
- 선행 티켓: 20261127_1734(C5a)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `jam-web/src/lib/today/exposure.ts`(279~297행 `capsuleGaugeTag` 등)와 `exposureThresholds.ts`: 태그 계산을 챕터 진행 비율로 바꾸거나 삭제한다.
2. `docs/service/prd/home-feed/PRD.md` 152~160·196~199행(생성 구간은 `node scripts/gen-home-feed-doc.mjs`로 다시 만든다).
3. 시험 `exposure-tags-jam2.test.ts`.

## 완료 조건

- 노출 태그 4개가 챕터 기준으로 바뀌었거나 삭제됐고, 큐레이션 카드 행이 없어진 태그를 쓰지 않는다(카즈하가 행 확인).
- 홈피드 PRD의 생성 구간이 생성기로 갱신돼 있고 시험이 통과한다.

## 규모와 체크포인트

- 규모: 파일 4개, 약 120줄(추정, 미검증)
- 체크포인트: 대체할지 없앨지 사용자 결정이 필요하다.

## 주요 의사결정 / 핵심 메모

- 상위 티켓의 사용자 확정 결정과 «하지 않을 것»을 따른다. 확인하지 않은 수치는 «미검증»이다.
- 계획 반환 면제 전제: 이 티켓은 파일 5개 초과 또는 100줄 이상이 예상돼 위 «구현 계획»을 파일 단위로 적었다. 사용자가 이 방식을 승인했다(2026-11-27). `/jam-work` 호출 때 카리나가 `planOnlyWaiver`로 넘기고, 면제 사유를 여기에 이어서 남긴다.
