# [Service] C14c 서비스 PRD와 컨텐츠·엔진 문서에 새 구조를 반영한다

## 핵심 요약

- 요구사항: 상위 티켓의 «PRD 반영» 목록대로 `docs/service/` 문서를 고친다(`/jam-docs` ① PRD, ③ 컨텐츠, ④ 배지 엔진 규칙).
- 구현 계획: 아래 «구현 계획»의 단계를 파일 단위로 따른다(5단계).
- 관련 파일: `docs/service/prd/` 12개 안팎(home-feed, chapter, 02_DATA_MODEL, probability, inventory, notification, admin-ui, ops-tool, content-automation, admin-boards, ui-components) / `docs/service/badge-engine/BADGE_ENGINE_UNIFIED.md`, `CONDITION_JSON_SPEC.md`, `docs/service/content/COMBINE_RECIPES.md`
- 선행 티켓: 20261127_1722(A2), 20261127_1730(C2b)
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 기획 경위와 사용자 확정 결정은 상위 티켓에 있다.

## 배경 / 문제 정의

상위 티켓 20261127_1720의 단계 C(전환, 같은 배포 창)에 속하는 조각이다. 잼은 챕터를 올리는 경험치이고 포인트는 별도 재화이며, 캡슐은 폐지한다(2026-11-27 사용자 결정). 챕터 1~9의 필요 잼은 870, 1,120, 1,260, 1,600, 1,980, 2,205, 2,700, 3,300, 3,960이고, 넘친 잼은 이월한다.

## 구현 계획

1. `docs/service/prd/home-feed/PRD.md`(2-1행·4행, 61~63·94~96·105~112행)와 `chapter/PRD.md`: 오름 방식, 표시, 보상.
2. `docs/service/prd/02_DATA_MODEL.md`(52곳): `capsule_*` 표·함수를 «기록 보존, 신규 쓰기 중단»으로 표시하고 새 열을 적는다.
3. `probability/PRD.md`(18), `inventory/PRD.md`(12), `notification/PRD.md`(9)와 `DATA_MODEL.md`(2), `admin-ui/ADMIN_PRD.md`(15), `ops-tool/PRD.md`(6), `content-automation/PRD.md`(6), `admin-boards/PRD.md`(2), `ui-components/README.md`(4).
4. `docs/service/badge-engine/BADGE_ENGINE_UNIFIED.md`(19), `CONDITION_JSON_SPEC.md`(5): `capsule_open_count` 키를 «사용 중지»로 표시한다. `docs/service/content/COMBINE_RECIPES.md`(3)의 «캡슐 설정과는 따로다» 문장을 정리한다.
5. 홈피드 PRD의 생성 구간은 `node scripts/gen-home-feed-doc.mjs`로 다시 만든다.

## 완료 조건

- 대상 PRD와 엔진·컨텐츠 문서에서 기능 용어 «캡슐»이 0건이다(유지 목록 제외). `capsule_*` 표는 «기록 보존»으로 표시돼 있다.
- 홈피드 PRD의 생성 구간이 생성기로 갱신돼 있다.
- 문서 검사와 `check-contract.mjs`가 통과한다.

## 규모와 체크포인트

- 규모: 파일 15개 이상, 약 400줄(추정, 미검증)
- 체크포인트: 없음. 묶음별로 나누어 커밋해도 된다. 약관(`TERMS_OF_SERVICE.md`)은 A1에서 다룬다.
