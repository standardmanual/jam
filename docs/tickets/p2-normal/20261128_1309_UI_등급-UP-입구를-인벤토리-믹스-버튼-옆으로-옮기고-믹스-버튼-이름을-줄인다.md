# [UI] 등급 UP 입구를 인벤토리 믹스 버튼 옆으로 옮기고 믹스 버튼 이름을 줄인다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-28): 믹스 페이지(`/combine`) 맨 위의 «등급 UP» 입구 행을 인벤토리 화면 «믹스하기» 버튼의 **오른쪽**으로 옮긴다. 인벤토리의 «믹스하기» 버튼 글자는 «믹스»로 바꾼다.
- 구현 계획:
  - 인벤토리(`jam-web/src/app/(main)/inventory/page.tsx` 83~92행): 진행도 바 아래 한 줄에 [믹스] [등급 UP] 두 버튼을 나란히 놓는다. 두 버튼은 지금 믹스 버튼과 같은 정본 `Button`(variant `secondary`, `bg-surface!`)이고 같은 폭(반반)이다. 믹스는 지금처럼 `/combine`과 `MixingBowlIcon`을 쓰고, 등급 UP은 `/combine?view=tier-up`으로 간다(아이콘은 채원 판정). 새 정본·변형·토큰은 만들지 않는다.
  - 문구(`jam-web/src/lib/i18n/ko.ts` 492행 `inventory.combineButton`): '믹스하기' → '믹스'. 등급 UP 버튼 글자는 `d.combine.tierUp.title`(«등급 UP»)을 그대로 쓴다. 레시피 상세의 «믹스하기»(`combine.combineButton`)와 믹스 화면 제목(`combine.title`)은 바꾸지 않는다.
  - 믹스 페이지(`jam-web/src/app/(main)/combine/CombineClient.tsx` 966~974행): 검색창 위의 등급 UP 입구 `ListRow`를 지운다. `openTierUp`과 `combine.tierUp.entrySubtitle`이 쓰이지 않게 되면 정리한다.
  - 뒤로가기(`CombineClient.tsx` 449~452행 `closeToList`, 533~537행 `closeTierUp`): 인벤토리에서 등급 UP으로 들어왔으면 TopNav 뒤로가기가 인벤토리로 돌아가야 한다. 앱 안에서 들어왔으면 `router.back()`, 주소로 바로 들어왔으면 `/inventory`로 폴백하는 방식을 검토한다(`lib/appHistory`의 `goBackOrPush` 참고). 믹스 목록 → 레시피 상세의 기존 뒤로가기는 그대로다.
  - 시험: `CombineClient.tierUp.test.tsx`(입구 행 클릭으로 여는 `openTierUp` 도우미와 285행 «입구를 누르면…» 시험), `CombineClient.navigation.test.tsx`, 인벤토리 페이지 시험, `Button.stories.tsx` 121행을 새 동작에 맞춘다.
- 관련 파일: 위 구현 계획의 경로와 줄 위치

## 배경 / 문제 정의
등급 UP 가차머신 리뉴얼(티켓 20261127_2225) 뒤 사용자가 staging을 보고 입구 위치를 옮기기로 했다. 등급 UP은 레시피가 아니라 인벤토리 재료를 쓰는 기능이라, 인벤토리의 믹스 버튼 옆에 두는 편이 맞다는 판단이다.

## 완료 조건
- 인벤토리 진행도 바 아래에 [믹스] [등급 UP] 두 버튼이 한 줄에 같은 폭으로 놓이고, 각각 `/combine`, `/combine?view=tier-up`으로 간다.
- 인벤토리 믹스 버튼 글자가 «믹스»다. 레시피 상세 «믹스하기»는 그대로다.
- 믹스 페이지에 등급 UP 입구 행이 없다.
- 인벤토리에서 등급 UP으로 들어가 뒤로가기를 누르면 인벤토리로 돌아온다. 주소로 바로 들어온 경우의 뒤로가기도 막히지 않는다.
- 새 토큰·새 정본·정본 변형이 없다(새 문구는 UX 라이팅 가이드를 따른다).
- 바뀐 동작을 시험으로 고정하고 `scripts/verify.sh`가 통과한다.

## 주요 의사결정
- 2026-11-28: «믹스» 글자 변경은 인벤토리 버튼에만 적용한다. 사용자가 «인벤토리 믹스하기 버튼»으로 범위를 정했다.
