# [UI] 챕터 게이지 카드의 필요 잼 숫자를 캡슐바 안으로 옮기고 모은 잼 숫자가 채움 끝을 따른다

## 핵심 요약

- 요구사항(사용자 지시 2026-11-28, 시안 스크린샷 첨부): 카드 아래 줄의 «필요 잼»(예: 870)을 캡슐바 안 오른쪽 끝으로 옮긴다. 모은 잼 숫자(예: 40)는 바 오른쪽 끝에 고정하지 않고 **채움 끝을 따라 움직인다**: 채움 안쪽에 숫자를 둘 자리가 없으면 채움 **오른쪽 바깥**에 붙여 보이고, 채움이 길어져 안쪽에 둘 자리가 생기면 **안쪽**에 보인다. 카드 아래의 필요 잼 줄은 없앤다(카드가 그만큼 낮아진다).
- 구현 계획: 아래 «구현 계획»을 파일 단위로 따른다.

- 사용자 승인: 2026-11-28 — 정본 `ChapterGaugeCard`의 필요 잼 숫자를 캡슐바 안 오른쪽 끝으로 옮기고, 모은 잼 숫자가 채움 끝을 따라 이동하며 안쪽에 자리가 없으면 채움 오른쪽 바깥, 자리가 되면 안쪽에 보이게 하는 변경(카드 아래 필요 잼 줄 제거 포함).
- 상위 티켓: 20261127_1720(챕터 게이지 카드로 전환하고 캡슐을 폐지한다). 정본은 C4(20261127_1733)에서 만들었다.

## 배경 / 문제 정의

지금 카드는 모은 잼 숫자가 바 안 **오른쪽 끝**에 고정되고(채움 밖이면 오렌지, 채움 안이면 어두운 글자) 필요 잼이 바 **아래 줄**에 따로 있다. 사용자가 보인 화면에서는 «40»이 채움(칩 옆 짧은 오렌지)과 멀리 떨어진 바 오른쪽 끝에 있어 어느 값의 숫자인지 읽히지 않고, 필요 잼 «870»이 아래로 떨어져 있다. 두 숫자를 바 안으로 모으고 모은 잼 숫자가 채움에 붙어 다니게 한다.

## 상세 요구사항

### UI/UX 관점
- **필요 잼 숫자**: 캡슐바(트랙) 안 오른쪽 끝에 놓는다. 마지막 챕터(`required === null`)는 숫자도 자리도 없다(바 오른쪽은 비어 있다). 글자 크기·색은 채원 사전 판정이 정한다(모은 잼 숫자와 구분되도록 한 단계 작게, 트랙 위에서는 오렌지 `--capsule-fill`을 제안한다). 같은 수치를 트랙 접근성 라벨이 읽어 주므로 숫자는 `aria-hidden`이다. 카드 아래 필요 잼 줄(`data-chapter-required`)과 그 줄이 만들던 높이·음수 여백은 없앤다. 로딩·오류 자리는 같은 틀을 쓰므로 새 높이를 따라간다.
- **모은 잼 숫자(채움 끝을 따른다)**: 
  - 안쪽에 둘 자리가 있으면(지금 규칙의 «필요 길이» 판정과 같은 방식: 칩 폭 + 간격 + 숫자 폭 + 끝 여백) 채움 **안** 오른쪽 끝에 어두운 글자로 보인다.
  - 자리가 없으면 채움 **바로 오른쪽 바깥**(간격 약 8px)에 오렌지 글자로 붙는다. 값이 0이면 칩 바로 오른쪽 바깥이다. 채움이 자라는 동안에는 지금처럼 숨겼다가 도착하면 최종 자리에서 한 번 팝인한다(값이 바뀌면 같은 방식으로 새 자리에서 팝인).
  - **바깥 자리에도 필요 잼 숫자와 겹치지 않아야 한다.** 채움 끝 + 간격 + 모은 잼 숫자가 오른쪽 끝의 필요 잼 숫자 영역(끝 여백 + 필요 잼 숫자 폭 + 간격)에 닿으면 바깥 자리가 아니라 안쪽 자리를 쓴다. 안쪽 자리도 채움이 거의 가득이라 필요 잼 숫자 영역과 겹치면, 안쪽 숫자의 오른쪽 끝을 필요 잼 숫자 영역 왼쪽에서 멈춘다(두 숫자는 어떤 경우에도 겹치지 않는다).
- **필요 잼 숫자가 채움 위에 걸칠 때**: 채움이 필요 잼 숫자 자리까지 차면 그 숫자의 글자색이 채움(오렌지) 위에서 읽히도록 바뀌어야 한다. 부분적으로만 걸치는 경우(채움 끝이 숫자 중간)에도 숫자가 한 글자 단위가 아니라 깔끔하게 읽혀야 한다 — 채움 안쪽에 어두운 복사본을 채움 크기로 잘라 그리는 방식(클리핑)을 제안한다. 방식은 채원 판정이 정한다.
- 숫자 폭은 지금처럼 글자 수×글자 폭(기준 글자 크기 배율 포함)으로 추정하고 실측으로 맞춘다. 6자리 값(예: 123,456 / 900,000)도 겹치지 않아야 하고, 360px 폭과 글자 125·150% 확대에서도 두 숫자가 겹치지 않거나 규칙대로 안쪽으로 들어가야 한다.
- 모션: 진입(0.26초 쉼, 1.5초 채움)·이동·모션 줄이기 규칙은 그대로다. 필요 잼 숫자는 정적이다(팝인 없음).
- 칩·트랙 높이(36px)·칩 폭(44px)·접근성(트랙 `role="img"`, 칩·워드마크 `aria-hidden`)은 바꾸지 않는다.

## 완료 기록

### 구현 내용 요약

정본 `ChapterGaugeCard`의 숫자 배치를 사용자 지시대로 바꿨다.
- 카드 아래 필요 잼 줄(`data-chapter-required` 옛 줄)과 음수 여백, `requiredText` prop을 걷었다. 카드는 윗줄과 트랙 두 줄이 되어 156px에서 128px로 낮아졌다. 로딩·오류 자리는 같은 틀이라 따라온다.
- 필요 잼 숫자는 트랙 안 오른쪽 끝에 오렌지 글자로 있고(`aria-hidden`, 정적), 마지막 챕터에는 없다. 채움에 걸치면 채움 안의 어두운 복사본이 걸친 부분만 하드 컷으로 어둡게 한다(클리핑).
- 모은 잼 숫자는 채움 끝을 따른다. 안쪽에 둘 폭이 되면 채움 안 오른쪽 끝(어두운 글자), 안 되면 채움 바로 오른쪽 바깥(간격 8px, 오렌지)이다. 값이 0이면 칩 바로 오른쪽 바깥이다. 필요 잼 영역에 닿으면 안쪽으로 클램프해 두 숫자가 겹치지 않는다.
- **구현 뒤 사용자 지시로 두 숫자의 크기를 작은 쪽(16px, `text-base`)에 맞췄다.** 모은 잼 숫자가 20px에서 16px로 줄었고 글자 폭 추정은 12.5에서 10으로 바뀌어 경계 값이 달라졌다(안쪽으로 바뀌는 첫 값 184 → 158 / 870, 바깥 자리의 끝 183 → 157).
- 스토리북 실렌더에서 극단 값(글자 150%·360px, 12,345 / 90,000)이 카드 밖으로 나가는 결함을 찾아, 두 숫자가 한 트랙에 안 들어가면 필요 잼 숫자를 그리지 않게 했다(`requiredNumberFits`). 16px 통일 뒤에는 이 극단도 두 숫자가 함께 들어가 보호 장치는 안전망으로만 남는다.
