# [BadgeEngine] `badgeProgress.test.ts` — "이번 주" 경계 테스트 flaky

## 배경 / 문제 정의

티켓 [20260910_2258(Feature)](../P2-일반/20260910_2258_Feature_JAM배지획득-알림메뉴반영.md)
게이트 리뷰 중 전체 vitest 스위트 실행에서 발견된 범위 밖 이슈.

`badgeProgress.test.ts`의 "걷기는 하루 1회 상한이 이번 주 카운트에도 적용된다" 테스트가
1건 실패했다(1332건 중 1건). `new Date()` 기준 상대 날짜로 "이번 주" 경계를 검증하는
테스트로 보이며, 실행 시점(요일)에 따라 결과가 달라지는 flaky 테스트로 추정된다. 이번
티켓(알림 메뉴 반영)의 변경과는 무관하다.

**추가 재현 사례(2026-09-12 23:55 KST, 티켓 `20260912_2157` 게이트 리뷰 중)**: 같은 테스트가
자정 부근 실행 시 다시 실패함을 확인했다(기대 1, 실제 2). 테스트가 "1시간 뒤" 활동을 같은
날로 가정하는데, 자정을 넘기면 그 가정이 깨지는 것으로 보인다 — 단순 "요일" 경계뿐 아니라
"자정 부근 실행 시각" 자체가 재현 조건일 가능성이 높다는 근거가 추가됐다. 이 재현 역시
쉐이더 랩 작업과는 무관한 범위 밖 발견물이다.

## 상세 요구사항

### 서비스/코드베이스 관점

- `badgeProgress.test.ts`에서 해당 테스트가 실제 날짜(`new Date()`)에 의존하는지 확인한다.
- 의존한다면 고정 시각을 주입하는 방식(예: `vi.setSystemTime()` 또는 명시적 기준일 파라미터)으로
  바꿔 실행 시점과 무관하게 결정적으로 동작하도록 수정한다.
- 월/일 경계(예: 일요일→월요일 전환, 월말) 케이스가 함께 있다면 그 경계도 점검한다.

## 구현 계획

원인 파악 후 테스트 코드만 고치면 되는 범위로 예상된다. 실제 배지 진행률 계산 로직
(`badgeProgress.ts` 등)에 결함이 있는지는 원인 파악 단계에서 함께 확인한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`badgeProgress.test.ts`의 모든 테스트가 `new Date()`(실행 시각) 기준 상대 날짜로 "이번 주"·
"이번 달" 경계를 검증하고 있었다. `vi.useFakeTimers()` + `vi.setSystemTime()`으로 파일
전체에 고정 시각(`2026-07-15T12:00:00`, 수요일 정오 — 주/월 중간이라 "+1시간"·"10일 전" 같은
상대 연산으로도 요일·월 경계를 넘지 않음)을 주입해, 실행 시점(요일·자정 부근)과 무관하게
`new Date()`가 항상 같은 값을 반환하도록 했다. `beforeAll`/`afterAll`로 파일 스코프에 적용하고
개별 테스트 코드(날짜 연산 로직 자체)는 건드리지 않았다.

배지 진행률 계산 로직(`badgeProgress.ts`) 자체에는 결함이 없었다 — 순수하게 테스트의 시각
의존성 문제였다.
