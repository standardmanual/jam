# [Admin] 쉐이더 랩 — PNG export 헤드리스(WebGL2 폴백) 환경에서 alpha=0 잠재 이슈

## 배경 / 문제 정의
> 왜 이 작업이 필요한가. 현재 상태와 기대 상태의 차이.

티켓 [20260914_0953](../P2-일반/20260914_0953_Admin_쉐이더랩-리퀴드메탈-미리보기스테이지크기불일치.md)
(리퀴드 메탈 미리보기·스테이지 크기 불일치 수정)의 게이트 리뷰 과정에서 범위 밖 발견물로
보고된 사항이다.

`ShaderLabExportPanel`의 PNG 다운로드(`canvasToBlob` → `canvas.toBlob()`)를 WebGPU 어댑터가
없는 헤드리스 Chromium(WebGL2 폴백 환경)에서 시도하면, 티켓 20260914_0953의 수정 전/후 패치
양쪽 모두에서 완전 투명(alpha=0) PNG가 나온다(바이트까지 동일하게 재현됨) — 즉 이번 수정과는
무관하게 기존부터 존재하던 현상이라 회귀는 아니다.

게이트 리뷰(conservative-reviewer)는 이 현상이 메인 컴포지트 캔버스에 `preserveDrawingBuffer`가
보장되지 않는 상태에서 비동기 `toBlob()` 호출 시점에 드로잉 버퍼가 유실될 가능성을 시사한다고
추정했다. 개발자(jam-developer)는 실제 macOS Chrome(진짜 GPU 환경)에서는 PNG export가 정상
동작함을 확인했다고 보고했으므로, 실사용 환경에서 문제가 될 가능성은 낮아 보이지만 완전히
배제되지는 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `ShaderLabExportPanel`이 사용하는 메인 컴포지트 캔버스 생성 시점에 `preserveDrawingBuffer`
  옵션이 명시적으로 켜져 있는지 확인한다.
- 실제 GPU 환경(WebGPU 지원 브라우저)과 WebGL2 폴백 환경 양쪽에서 `toBlob()` 호출 시점의
  드로잉 버퍼 상태 차이를 조사한다.
- 조사 결과 실제 위험이 없다고 판단되면(예: 프로덕션 사용자 환경은 전부 WebGPU 지원 브라우저),
  티켓에 그 근거를 기록하고 조치 없이 닫아도 된다 — 반드시 코드 수정이 필요한 티켓은 아니다.

## 구현 계획
> 어떻게 구현할지. 접근 방법, 영향 범위, 주요 변경 포인트.

1. `ShaderLabExportPanel.tsx`/`bakePreviewToBlob.ts`에서 캔버스 컨텍스트 생성 옵션을 확인한다.
2. 실제 GPU 환경과 헤드리스(WebGL2 폴백) 환경에서 `toBlob()` 타이밍과 드로잉 버퍼 보존
   여부를 비교 조사한다.
3. 필요 시 `preserveDrawingBuffer: true` 지정 또는 `toBlob()` 호출 전 동기적으로 버퍼를
   보존하는 방식으로 수정한다. 위험이 없다고 판단되면 조사 결과만 기록하고 조치는 생략한다.
