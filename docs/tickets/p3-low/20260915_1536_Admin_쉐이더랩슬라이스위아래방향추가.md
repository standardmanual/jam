# [Admin] 쉐이더 랩 — 슬라이스 이펙트에 "위"·"아래" 방향 추가

## 배경 / 문제 정의

쉐이더 랩의 슬라이스(slice) 이펙트는 지금까지 "오른쪽"·"왼쪽"·"양쪽"(가로 방향, 각 밴드가
가로로 무작위 방향) 세 가지만 있었다. 세로 방향("위"·"아래")도 추가해달라는 요청.

## 사전 조사 결과

`slice-pass.js`는 이미지를 Y좌표 기준 가로 밴드로 나누고(`sliceHeight`), 각 밴드를
X축으로만 미는 글리치 효과다(`offsetUv`가 항상 `(shift, 0)`). "위"·"아래"는 단순히 기존
가로 이동에 새 값을 추가하는 게 아니라, **자르는 축 자체가 가로→세로로 바뀌어야** 시각적으로
의미가 있다(가로 밴드를 세로로만 미는 건 같은 행 안에서 위아래로 겹치는 것뿐이라 거의
안 보임) — 즉 세로 밴드로 나눠 세로로 미는 구조가 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점

- "방향" select에 "아래"(`down`)·"위"(`up`) 옵션을 추가한다.
- 위/아래를 고르면 세로 밴드(X좌표 기준)로 나누고 Y축으로 미는 걸로 동작한다(자르는 축과
  미는 축이 기존 가로 방향과 90도 회전한 관계).
- 기존 오른쪽/왼쪽/양쪽 동작은 그대로 유지한다(회귀 없음).

## 구현 계획

1. `slice-pass.js`: `SLICE_DIRECTION_DOWN`(3)·`SLICE_DIRECTION_UP`(4) 상수 추가,
   `toSliceDirection()`에 `down`/`up` 매핑 추가.
2. `buildEffectNode()`를 축 독립적으로 재작성 — `isVertical = directionUniform > 2.5`
   조건으로 `sliceIndex`(자르는 축 좌표)·`blockIndex`(이웃 축 좌표)를 `select()`로
   스왑하고, 최종 이동량(`offsetUv`)도 `select()`로 가로/세로 vec2 중 하나를 고른다.
   색수차(`chromaOffsetUv`)·잔상(`trailOffsetUv`)·샘플 UV 계산을 모두 `offsetUv` 전체
   벡터에 대한 연산으로 일반화해 축과 무관하게 동일한 식이 재사용되도록 한다.
3. `effectRegistry.ts`의 `sliceFields` `direction` select에 "아래"(`down`)·"위"(`up`)
   옵션 추가.
4. `npx patch-package @basementstudio/shader-lab`로 patch 반영, `npm install` 재적용성
   확인.
5. 로컬 esbuild+실제 WebGPU 브라우저 실렌더로 "오른쪽"·"아래"·"위" 세 방향을 나란히
   렌더해 스크린샷으로 육안 비교 — 특히 "아래"와 "위"가 서로 반대 방향으로 밀리는지 확인.
6. `npx tsc --noEmit`, 변경 파일 `eslint`.

## 완료 기록

### 구현 내용 요약

구현 계획 1~6 그대로 진행했다. 기존 코드가 `offsetUv.x`처럼 X 성분만 다루던 부분을
`offsetUv`(vec2) 전체로 바꾼 덕분에, `select()`로 고른 vec2 하나만 축에 맞게 결정하면
색수차·잔상·샘플 좌표 계산은 손대지 않고 그대로 재사용됐다 — 코드 중복 없이 깔끔하게
확장됐다.

### 주요 의사결정 / 핵심 메모

- **"자르는 축"과 "미는 축"을 함께 90도 회전시켰다**: 처음엔 "밴드는 가로 그대로 두고
  세로로만 민다"는 단순한 해석도 고려했지만, 같은 가로 밴드 안에서는 좌우 어디든 색이
  거의 균일해 세로로만 밀면 시각적으로 거의 표시가 안 난다. 자르는 축 자체를 세로 밴드로
  바꿔야 "슬라이스" 이펙트의 정체성(밴드 단위로 어긋나 보이는 글리치)이 세로 방향에서도
  똑같이 성립한다.
