# [Content] 날짜/시간 표기 가이드 불일치 — 저장소 전역

> 출처: 티켓 20260915_2242(피드/오늘 도메인 텍스트 정비) 게이트 리뷰 sideFinding — 자동 티켓화

## 배경 / 문제 정의

`FeedSection.tsx`의 `formatFullDate`가 만드는 표기("오후 03:30")가
`UX_WRITING_GUIDELINE.md` §3 예시("오후 3시 30분")와 다르다는 사실이 확인됐다(node로 직접
재현). 같은 포맷을 `points/page.tsx`, `badges/[id]/page.tsx`(`LocalDate` 컴포넌트),
`InventoryItemHistorySheet.tsx` 등 다수 화면이 공유하고 있어, 한 화면만 고치면 오히려
표기가 갈라진다 — 저장소 전역 관행이라 별도 검토가 필요하다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 날짜/시간 포맷 로직이 실제로 몇 곳에, 어떤 형태로 중복돼 있는지 전수 조사한다
  (`formatFullDate`, `LocalDate` 컴포넌트, 그 외 유사 유틸 함수).
- 가능하면 단일 유틸 함수로 통합하고, §3 예시 형식("7월 31일 금요일 오후 3시 30분")을
  기준으로 맞춘다.
- 통합이 부담스러우면(호출처가 매우 많거나 각기 다른 표시 맥락) 최소한 §3 기준에 맞는
  포맷 함수를 하나 새로 만들고, 이번 정비 대상 도메인부터 점진적으로 교체하는 방안을 검토한다.

### UI/UX 관점
- 시:분 표기("오후 3시 30분")가 "오후 03:30"보다 자리를 더 차지하므로, 좁은 카드·리스트
  레이아웃에서 줄바꿈이나 잘림이 생기지 않는지 확인이 필요하다.

## 구현 계획
- 먼저 전수 조사로 영향 범위를 파악한 뒤, 통합 vs 점진 교체 중 하나를 정해 진행한다.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
`LocalDate.tsx`에 `korean` prop(및 문자열이 필요한 자리용 `formatKoreanDateTime` named export)을
추가해 §3 형식('7월 31일 금요일 오후 3시 30분')을 만들 수 있게 확장했다. 기존 `timeZone:
'Asia/Seoul'` KST 고정 로직과 `options` prop 경로는 그대로 유지(하위 호환).

Intl 표준 `hour12` 옵션은 '오후 3:30'(콜론 구분)까지만 만들어 '시'/'분' 접미사를 못 붙이므로,
`formatToParts`로 dayPeriod/hour/minute 조각을 뽑아 `오후 3시 30분` 형태로 직접 조립했다.

저장소 전역에서 시:분을 함께 표시하는 모든 호출부(오케스트레이터 사전조사 12개 파일 중
어드민 제외 대상 + 사전조사에 누락됐던 `points/page.tsx`·`voc/page.tsx`·
`InventoryItemHistorySheet.tsx` — 티켓 본문이 직접 예시로 언급했으나 `formatFullDate`/
`LocalDate` 키워드 검색에는 걸리지 않던 자체 로컬 포맷 함수 3곳)를 `korean` prop/
`formatKoreanDateTime`로 교체했다. 날짜만 표시하는 호출부 중 `year: '2-digit', month:
'2-digit'`처럼 "2026. 07. 31." 형태(가이드 Bad 예시와 동일한 점 구분)를 만들던 곳
(`ItemEarnHistory.tsx`, `dev-sample/item-badge-serial/page.tsx`)도 함께 `korean={{ year: true
}}`로 교정했다. 이미 `month: 'long', day: 'numeric'` 등 한국어 자연어 형태였던 날짜 전용
호출부(메인 페이지, `today/[cardId]`, `PoiCarouselModal`, `InventoryGrid`,
`ItemCandidateRow`, `MissionsListClient`, `lib/utils.ts formatDate`)는 이미 §3에 부합해
변경하지 않았다.

전체형(요일 포함)은 카드/리스트 행이 아닌 진짜 여유 있는 레이아웃에만 쓰는 게 맞다고 판단해,
이번에 수정한 호출부는 전부 카드 행·리스트·바텀시트 상세 등 좁은 레이아웃이라 요일은 생략하고
연도+시:분만 포함하는 축약형(`{ year: true, time: true }`)으로 통일했다. 기존에 이미 연도가
있던 곳은 유지, 없던 곳(날짜 전용)은 추가하지 않았다 — 정보량 변화 없이 시:분 표기만
'오후 03:30' → '오후 3시 30분'으로 교정하는 것이 이번 티켓의 핵심이라 판단.

`UX_WRITING_GUIDELINE.md` §3에 전체형/축약형을 언제 쓸지(요일/연도/시분 포함 기준)를
명시하는 절을 추가했다.

### 주요 의사결정 / 핵심 메모
- **요일은 어느 호출부에서도 켜지 않았다**: 실측 대상 12곳(+추가 발견 3곳) 전부가 카드 행/
  리스트/바텀시트 상세였고, 진짜 여유 있는 "단독 히어로" 급 레이아웃이 없었다. §3 예시
  자체("7월 31일 금요일...")가 요구하는 요일 포함 전체형을 실제로 쓰는 곳이 이번 범위엔
  없었다는 뜻이라 가이드에도 "요일은 여유 있는 상세 화면에서만"이라고 조건부로 적었다.
- **연도 포함 여부는 기존 호출부 관례를 그대로 존중했다**: 이미 연도를 표시하던 곳(배지
  획득 이력, 포인트 내역, VOC, 피드 상세)은 유지, 원래 연도 없이 월/일만 쓰던 곳(만료일 등)은
  추가하지 않았다 — 정보량을 임의로 늘리거나 줄이지 않는 선에서 시:분 표기 형식만 고쳤다.
- **`options` prop은 제거하지 않고 남겼다**: '오후 03:30'류 저수준 Intl 포맷이 필요한 미래
  케이스를 위해 하위 호환 경로로 유지. 날짜 전용(hour/minute 없는) 호출부는 `options` 그대로
  둬도 §3 위반이 아니므로 건드리지 않았다.
- **오케스트레이터 사전조사에 없던 3개 파일(`points/page.tsx`, `voc/page.tsx`,
  `InventoryItemHistorySheet.tsx`)을 추가로 찾아 수정했다**: 이 세 파일은 `formatFullDate`나
  `LocalDate` 컴포넌트를 쓰지 않고 각자 로컬 `toLocaleDateString`/`toLocaleString` 함수를
  따로 정의해서, 사전조사의 키워드 검색(`formatFullDate`, `LocalDate` 사용처)에 걸리지 않았다.
  다만 티켓 본문(사이드파인딩 출처 설명)이 `points/page.tsx`와 `InventoryItemHistorySheet.tsx`를
  직접 예로 들고 있어 티켓 자체의 의도된 범위로 판단해 포함시켰다.

**1차 게이트 FAIL → 재시도**: 1차 시도에서 `UX_WRITING_GUIDELINE.md` §3에 전체형/축약형
설명을 추가하면서 기존 "문장 부호 및 표기 규칙" 마크다운 표를 중간에서 끊어(만료/남은
기간·포인트/금액·거리/기록 3개 행이 표 블록에서 분리되고, 새로 끼워넣은 보조 표도 셀 안
개행으로 함께 깨짐) 게이트 FAIL을 받았다. 재시도에서 표 순서를 원복하고 전체형/축약형
설명을 §3 표가 완전히 끝난 뒤로 옮겨 재검증 후 PASS했다(코드 로직은 1차 시도에서 이미
검증됐으므로 건드리지 않음).

**한국어 리뷰**: 재시도 완료 후 병합 전 원문을 다시 확인한 결과, 리뷰가 지적한 "요일은
… 포함하고" 식 주술 불일치 산문은 최종 반영본에 존재하지 않았다(표 형식(`요소 | 포함
기준`)으로 이미 정리돼 있어 그런 문장 구조 자체가 없음) — 리뷰가 참조한 스냅샷과
실제 반영본 사이의 차이로 보이며, 추가 수정 없이 병합했다.
