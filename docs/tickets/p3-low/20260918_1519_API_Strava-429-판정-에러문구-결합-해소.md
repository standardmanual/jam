# [API] Strava 레이트리밋(429) 판정이 에러 문구 정규식에 묶여 있는 문제

## 핵심 요약
- 요구사항: `classifyStravaSyncFailure`가 429를 에러 메시지 문자열이 아니라 구조화된 값(상태 코드 등)으로 판정하게 한다.
- 구현 계획: `api.ts`가 던지는 에러에 HTTP 상태 코드를 필드로 싣고, 분류 함수가 그 필드를 보게 바꾼다.
- 관련 파일: `jam-web/src/lib/strava/syncFailures.ts`, `jam-web/src/lib/strava/api.ts`
- 출처: 20260918_1307 게이트 리뷰(민지) 범위 밖 발견물

## 배경 / 문제 정의
1307에서 추가한 실패 유형 분류는 `/Strava API 오류 429/` 정규식으로 레이트리밋을 판정한다. `api.ts`의 에러 메시지
형식이 바뀌면 레이트리밋이 `strava_api_error`로 조용히 섞여 들어가고, 주간 브리핑에서 레이트리밋 장애를 구분하지 못한다.

## 완료 조건
- 에러 메시지 문구를 바꿔도 429가 `rate_limited`로 분류된다 (단위 테스트)

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `api.ts`에 `StravaApiError`(`Error` 상속, `status: number` 필드) 추가. `stravaFetch`가 실패 시 이 에러를 던진다 (메시지 문구는 기존과 동일)
- `classifyStravaSyncFailure`가 `err instanceof StravaApiError && err.status === 429`로 레이트리밋을 판정. 정규식 판정 제거
