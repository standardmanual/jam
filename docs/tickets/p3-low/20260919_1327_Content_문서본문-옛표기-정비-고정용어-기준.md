# [Content] 문서 본문 옛 표기 정비 (UX 가이드라인 고정 용어 기준)

> 발견 경위: 티켓 20260919_1248(T4) 하니 초안 작성 중 발견. 건수는 하니의 grep 결과이며 줄별 전수 분류는 하지 않았다.

## 핵심 요약

- 요구사항: 스펙·컨텐츠·마케팅 문서 본문에 남은 옛 표기를 `docs/service/writing/UX_WRITING_GUIDELINE.md` §1.3 고정 용어로 정비한다. 코드·DB 식별자, 파일명, 금지 규칙을 인용한 문장은 그대로 둔다.
- 구현 계획: 문서별로 grep → 건별 분류(고칠 것 / 식별자·인용 예외 / 일반 명사) → 고칠 것만 수정 → 예외 목록 기록.
- 관련 파일: 아래 표기 목록의 각 문서

## 상세 요구사항

### 서비스/코드베이스 관점
- 코드는 바꾸지 않는다. 문서 본문만 대상이다.

### UI/UX 관점 (해당 시)
- 해당 없음.

### 컨텐츠 관점 (해당 시)

- **제외**: 코드·DB 식별자와 파일명(`combination_recipes`, `itembooks`, `poi`, `ITEMBOOKS.xlsx`, `COMBINE_RECIPES.md` 등), 금지 규칙을 인용한 문장(`UX_WRITING_GUIDELINE.md`의 X 목록, `DESIGN_RENEWAL_SPEC.md` 482·533행), 일반 명사 용법(속성 조합 등), 티켓 본문(이력)이다.
- **`ACTIVITY_BADGES.md`는 생성물이다.** 직접 고치지 않고 `v5_catalog_writing.json`을 고친 뒤 재생성한다(문서 서두의 규칙).
- `JAM 포인트`·`잼 포인트`는 가이드라인이 유저 노출 문구에만 금지하므로 도메인명으로 쓰인 곳은 예외다. 알림 문서의 「1,200 JAM 포인트」 표기 규칙은 가이드라인 §1.3과 충돌해 RECAP_CASEBOOK의 "남은 확인"이 다루고 있으므로 그 결정을 따른다.
- 세계관에 닿는 문구(트라이브 서사)는 윈터가 검수한다.

## 구현 계획

1. 문서별로 옛 표기를 grep한다.
2. 건별로 고칠 것, 예외, 일반 명사로 분류한다.
3. 고칠 것만 수정하고 문서별로 작은 커밋을 만든다.
4. 예외 목록을 완료 기록에 남긴다.

## 완료 조건

- 위 표의 대상 문서에서 옛 표기를 grep했을 때 결과가 모두 제외 범주(식별자, 파일명, 인용, 일반 명사, 도메인명)이고, 그 목록이 완료 기록에 있다.
- `ACTIVITY_BADGES.md`의 "달리기" 표기는 입력 데이터 수정 후 재생성으로 사라졌다.
- 정비 대상 문서가 `scripts/check-slop.mjs`를 통과한다.
