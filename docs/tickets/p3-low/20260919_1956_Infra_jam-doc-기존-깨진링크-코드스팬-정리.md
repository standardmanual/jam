# [Infra] jam-doc 기존 깨진 링크·코드스팬 정리

> 발견 경위: 티켓 20260919_1246(T2, jam-doc 훅 복사본과 설정) 게이트 리뷰(민지) 범위 밖
> 발견물. `node scripts/doc-check.mjs --all --summary`로 jam-doc 전체 문서를 스캔한 결과.

## 핵심 요약

- 요구사항: jam-doc 문서 코퍼스에 이미 존재하는 깨진 링크·해석 불가 코드스팬을 확인하고 고친다.
- 구현 계획: `node scripts/doc-check.mjs --all --summary`로 전체 목록을 재확인 → 항목별로
  실제 오류인지 판단(오탐이면 사유를 남김) → 대상 경로 링크를 정정하거나, 이동된 문서면 새
  경로로 갱신.
- 관련 파일: 착수 시 `--all --summary` 재실행으로 정확한 목록을 뽑는다. 민지 발견 당시 예시:
  `jam-doc/planning/business-plan/02 JAM! 서비스 플랜.md`, `jam-doc/planning/content/TRIBES.md`,
  `jam-doc/planning/content/POI.md` — jam 저장소의 `BADGE_ENGINE_UNIFIED.md`나 jam-doc 내부
  `04 JAM! 트라이브.md` 등을 상대경로로 잘못 참조.

## 배경 / 문제 정의

T2(20260919_1246) 게이트 리뷰 중 민지가 `--all --summary`로 jam-doc 전체 문서를 재스캔하면서
발견했다: 깨진 링크 7건, 해석 불가 코드스팬 62건 중 실제 오류로 보이는 것 6건. T2의 diff와는
무관한 기존 상태라 그 판정에는 반영하지 않았다.

`pre-commit`은 staged 파일만 검사하므로, 이 기존 위반들은 해당 파일을 다시 커밋하기 전까지는
표면화되지 않는다 — 저장소 분리(티켓 20260918_2105) 당시 경로 치환에서 누락됐거나, 그 이후
문서가 이동하면서 갱신되지 않은 링크로 추정된다(확인 전).

## 상세 요구사항

### 서비스/코드베이스 관점
- 링크 오류(`link: error` 등급)는 실제로 커밋을 차단하는 대상이므로 우선 처리한다.
- 코드스팬(백틱 경로) 62건 중 해석 불가로 남는 것은 경고 등급이 맞는 케이스(예: 예시 코드,
  일반 파일명 언급)와 실제 옛 경로가 섞여 있을 수 있다 — 항목별로 실제 오류인지 판단한다.
