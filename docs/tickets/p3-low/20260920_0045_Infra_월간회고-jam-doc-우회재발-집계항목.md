# [Infra] jam-doc 갱신안 우회 재발 집계를 정기 점검에 넣기

> **2026-09-20 정정.** 최초 작성 시 "`scheduled-jobs.md`의 월간 절에 두 항목을 넣는다"고
> 적었으나, 확인 결과 **월간 워크플로 회고는 예약 작업이 아니다.** 예약 작업은 주간(카즈하
> 브리핑 + 윤진 홈피드) · 월간(윈터·윤진 트렌드 + 하니 문서 점검) · 주간 배포 승인 셋이고,
> 월간 절은 워크플로 수치를 다루지 않는다. 혜린의 월간 워크플로 회고는 `jam-pm.md` ⑧과
> `/jam-plan`에 정의된 별도 절차이며, 그 입력은 카즈하가 **주간** 브리핑의 「워크플로 수치」
> 절에 모은다(`forms/weekly-briefing-format.md:19`). 두 항목의 목적지가 서로 다르다는 사실도
> 이때 드러났다 — 아래 상세 요구사항이 정정된 계획이다.

## 핵심 요약

- 요구사항: `jam-doc` 갱신안 우회(폴백·수동 반영)의 재발 횟수를 정기적으로 집계해, 상위 티켓
  20260920_0042가 정한 재구조화 트리거에 도달했는지 매달 한 번 드러나게 한다. 분리 이후
  `jam-doc`에 실제로 어떤 커밋이 쌓이는지 점검하는 항목도 함께 넣는다.
- 구현 계획: 두 항목의 담당과 주기가 달라 목적지를 나눈다. 집계는 카즈하의 주간 브리핑 양식과
  혜린의 월간 회고 입력 목록에, 커밋 패턴 점검은 하니의 월간 문서 점검에 넣는다.
- 관련 파일:
  - `.claude/skills/jam-work/references/forms/weekly-briefing-format.md` — 「파일 구성」의
    `## 워크플로 수치` 줄(19행 부근)과 그 아래 설명
  - `.claude/agents/jam-pm.md` — 「월간 워크플로 회고」 절(54행 부근), 혜린이 읽는 입력 목록
  - `.claude/skills/jam-plan/SKILL.md` — 「월간 워크플로 회고」 절(70행 부근), 같은 목록
  - `.claude/skills/jam-work/references/scheduled-jobs.md` — 「월간」 절(211행 부근)의
    하니 프롬프트 초안
- 상위 티켓: [20260920_0042 문서 저장소 경계 관찰 체계와 시드 생성기 정리](../p2-normal/20260920_0042_Infra_문서저장소-경계-관찰체계와-시드생성기-정리.md)

## 배경 / 문제 정의

상위 티켓 20260920_0042가 정한 재구조화 트리거는 "폴백 또는 수동 반영 2회 재발"이다. 티켓
20260920_0043이 매 티켓에 결과를 한 줄로 남기는 절차를 넣었으므로 셀 대상은 생겼다. 그러나
누가 언제 세는지가 정해지지 않으면 기록만 쌓이고 트리거는 아무도 확인하지 않는다.

매 세션이 알아서 챙기기를 기대하는 대신, 이미 정기적으로 도는 점검에 항목으로 박아 넣는다.

Q5로 제기됐던 "분리 이후 `jam-doc`에 실제로 어떤 커밋이 쌓이는가"라는 점검도 별도 작업을 새로
만들 만큼 급하지 않으므로 같은 방식으로 기존 정기 점검에 얹는다.

## 상세 요구사항

### 서비스/코드베이스 관점

**① 갱신안 우회 재발 집계 — 카즈하(주간 수집) · 혜린(월간 소비)**

- `weekly-briefing-format.md`의 「워크플로 수치」 항목에 `jam-doc` 갱신안 집계를 더한다.
  집계 방법은 `docs/tickets/`에서 `jam-doc 갱신안:` 문구를 검색해 세 유형(diff 성공 · 폴백 ·
  수동 반영)의 건수를 세는 것이다. 문구 형식은 티켓 20260920_0043이 고정해 두었다.
- 폴백과 수동 반영의 합이 **2건 이상이면** 브리핑에 **트리거 도달**이라고 명시하고, 저장소
  재구조화 재논의가 필요하다는 사실을 함께 적는다. 카운트는 티켓 20260920_0042 이후 생성된
  컨텐츠 티켓만 센다 — 그 이전 3건(20260919_1246·1249·1956)은 diff 개선 이전 사례다.
- `jam-pm.md`와 `jam-plan/SKILL.md`의 「월간 워크플로 회고」 절에서 혜린이 읽는 입력 목록에
  이 집계를 더한다. 두 파일이 같은 목록을 담고 있으므로 한쪽만 고치면 드리프트가 생긴다.

**② `jam-doc` 커밋 패턴 점검 — 하니(월간 문서 점검)**

- `scheduled-jobs.md` 「월간」 절의 하니 프롬프트 초안에 "분리 이후 `jam-doc`에 실제로 어떤
  종류의 문서가 바뀌고 있는지 확인"을 더한다. 분리 기준이 실제 작업과 맞는지 판단할 근거가
  된다.
- 판정이 아니라 관찰이다. 하니는 수치와 관찰만 적고 분리 기준을 바꾸자는 제안은 하지 않는다.

따른다. `jam-pm.md`는 에이전트 정의라 본문이 영어지만 회고 입력 목록은 한국어이므로 그 관례를
유지한다.
