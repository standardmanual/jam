# [Infra] `core.hooksPath`가 `~/`로 시작하면 정상 값인데도 `.githooks`로 덮어쓴다

## 핵심 요약

- 요구사항: git은 `core.hooksPath`를 경로형 설정으로 읽어 `~/...`를 홈 디렉터리로 펼친다. `scripts/ensure-hooks-path.sh`와 `scripts/check-contract.mjs`의 `checkGitConfig`는 이 값을 문자 그대로 존재하지 않는 경로로 보고 비정상으로 판정한다. 이 저장소의 `.githooks`를 가리키는 `~/...` 값도 정상으로 보게 할지 정한다.
- 관련 파일: `scripts/ensure-hooks-path.sh`(`resolves_to_repo_hooks`), `scripts/check-contract.mjs`(`resolvesToRepoDir`), `scripts/ensure-hooks-path.test.mjs`
- 선행 티켓: 20260921_0841(부모)

## 배경 / 문제 정의

티켓 20260921_0841 재작업의 게이트 리뷰(민지)가 남긴 범위 밖 발견물이다. 동작상 해는 없다. 정상 값을 `.githooks`로 덮어쓰는 과교정이고, 그 결과 훅은 여전히 이 저장소의 `.githooks`를 가리키게 된다. 홈 디렉터리 아래에 저장소를 두는 PC에서 누군가 `~/...`로 설정한 경우에만 일어나는 드문 경우다. 처리하지 않고 알려진 한계로 남겨도 되는지도 함께 판단한다.

## 완료 조건

- `~`로 시작하는 값이 이 저장소의 `.githooks`로 해석되면 ensure는 무출력·무변경이고 check-contract는 통과한다. 두 구현이 같은 규칙을 쓰는 것을 `ensure-hooks-path.test.mjs`가 확인한다.
- 또는 처리하지 않기로 했다면 그 사유와 알려진 한계가 완료 기록에 남아 있다.

## 완료 기록

### 구현 내용 요약
`~`와 `~/...`로 시작하는 `core.hooksPath` 값을 `$HOME` 기준으로 펼쳐 정상 판정하도록 두 구현을 같은 규칙으로 고쳤다. 이 저장소의 `.githooks`를 가리키는 `~/...` 값은 ensure가 무출력·무변경이고 check-contract가 통과한다. `~사용자` 형식은 다루지 않는다.

### 변경된 파일
```
scripts/ensure-hooks-path.sh
scripts/check-contract.mjs
scripts/ensure-hooks-path.test.mjs
```

### 테스트 결과
- [x] `node scripts/ensure-hooks-path.test.mjs` 32개 통과 (이번에 5개 추가)
  - ensure: 이 저장소의 `~/` 경로는 무출력·무변경, 다른 곳을 가리키는 `~/` 경로와 사라진 `~/` 경로는 `.githooks`로 교정
  - check-contract: 이 저장소의 `~/` 경로는 통과, 다른 곳을 가리키는 `~/` 경로는 실패
- 임시 홈 디렉터리(`HOME` 환경변수 주입)로 실제 설정을 건드리지 않았다.
