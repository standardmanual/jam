# [BadgeEngine] 컬렉션 완성 표시 4곳에 공용 함수 연동 테스트 추가

## 핵심 요약

- 요구사항: 티켓 20260921_1112가 바꾼 다섯 위치 중 테스트가 있는 곳은 타인 컬렉션 API 한 곳뿐이다. 나머지 네 곳(컬렉션 목록 API, 컬렉션 상세, 프로필 컬렉션 카드, 배지 화면)이 `computeBookCompletion`으로 분모·분자를 계산하는지 확인하는 테스트를 추가한다.
- 관련 파일: `jam-web/src/app/api/itembooks/route.ts`, `jam-web/src/app/(main)/collections/[id]/page.tsx`, `jam-web/src/app/(main)/[username]/collections/page.tsx`, `jam-web/src/app/(main)/badges/page.tsx`
- 출처: 티켓 20260921_1112 게이트 리뷰(민지)의 범위 밖 발견물

## 배경 / 문제 정의

페이지·라우트마다 데이터 조회가 섞여 있어 통째로 테스트하기 어렵다면, 분모·분자 계산을 함수로 뽑아 그 함수를 테스트하는 방법도 함께 검토한다. 이번 통일의 회귀가 조용히 생기는 곳이 이 네 위치다.

## 완료 조건

- 네 곳 각각에서 제외 배지가 있는 컬렉션의 「N/M」과 완성 여부가 새 기준을 따르는 테스트가 있고 `scripts/verify.sh`가 통과한다. 테스트하기 어려운 곳은 그 이유와 대안이 완료 기록에 남아 있다.

### 배포 전 점검에서 재확인 (2026-09-26, 프로덕션 배포 `8265beec`, 민지 모드 ③)
- `findCompletableItemBooks`(`completable.ts:123-177`)의 이번 변경 로직에 직접 테스트가 없다. 저장소에는 `findCompletableItemBooks`와 `checkItemBookCompletion`을 부르는 테스트 파일이 하나도 없다. 안 덮이는 변경은 `checkinBadgesByBook` 조립(체크인·`item_book_id` 있는 배지만 모으는 필터), `computeBookCompletion(..., new Set(), { filledByBook })` 전환, `remaining` 계산이 전역 집합에서 북별 집합으로 바뀐 부분이다. 같은 배지가 다른 북에 장착됐을 때 "완성 가능" 소식이 뜨지 않는 시나리오가 순수 함수 수준에서만 확인된다. [주의]
- 기존 조회 오류 경로(`checker.ts:100-125` 부근 `slotsRaw` 오류 처리 등)에도 테스트가 없다. 함께 다룬다.
