# [Infra] pre-push 기준 방어의 diff 파싱이 `+++ `로 시작하는 추가 줄을 파일 헤더로 오인할 수 있다

## 핵심 요약

- 요구사항: `.githooks/pre-push`의 기준 방어가 억제 주석을 찾을 때 unified diff의 파일 헤더(`+++ b/...`)와, 내용이 `++ `로 시작해 diff에서 `+++ `로 보이는 추가 줄을 구분하지 못할 수 있다. 파일 경계 판별을 헤더 형식(`+++ b/` 또는 `+++ /dev/null`)과 hunk 위치로 좁힌다.
- 구현 계획: awk의 헤더 판별 조건을 좁히고, 해당 줄이 포함된 diff로 임시 저장소 테스트를 하나 추가한다(`scripts/pre-push-guard-bar.test.mjs`).
- 관련 파일: `.githooks/pre-push`(기준 방어 절), `scripts/pre-push-guard-bar.test.mjs`
- 상위 티켓: 20260921_2304. 출처: 민지 게이트 리뷰의 범위 밖 발견물. 경로: ③ 표준(infra)

## 배경 / 문제 정의

민지가 지적한 이론적 경우이며, 실제 코드에서 재현되지는 않았다. 오판이 생기면 파일 경계 인식이 흔들려 억제 주석 검사가 엉뚱한 파일을 대상으로 삼을 수 있다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. 헤더 판별을 `diff --git` 줄 다음의 `--- `·`+++ ` 쌍으로 한정하거나, `git diff --name-only`로 얻은 파일 목록과 대조한다.
2. 테스트: 추가 줄의 내용이 `++ `로 시작하는 파일과 사유 없는 `eslint-disable`이 함께 있는 diff에서 차단이 정확한 파일을 가리키는지 확인한다.

## 사전 확인과 결정 (카리나, 2026-09-22)

- 사용자 지시(2026-09-22): 이 세션의 범위 밖 발견물 티켓을 전부 실행한다. 이 티켓은 ③ 표준 경로(아현 → 민지)로 진행한다.
- **고치기 전에 재현부터 한다.** 민지가 "이론적 경우"라고만 보고했으므로, 임시 저장소 테스트로 오판이 실제로 일어나는지 먼저 실패하는 테스트로 만든다. 재현이 안 되면 억지로 고치지 말고 재현이 안 된 조건과 함께 `halted`가 아닌 `done`으로 보고하되, 방어적 수정이 값싸면 넣는다.
- 이 훅은 `core.hooksPath`(메인 트리 절대경로)로 모든 작업 공간의 push에서 실행된다. 잘못 고치면 모든 push가 막히거나 기준 방어가 뚫리므로, 기존 기준 방어 테스트 10개와 워크트리 차단 테스트 5개가 그대로 통과해야 한다.
- 이 티켓은 파일 2개 안팎의 작은 변경이라 `계획 반환 면제`가 필요 없다.

## 구현 계획

1. 훅 수정과 테스트 추가, `scripts/verify.sh` 통과.

## 완료 조건

- 새 테스트가 통과하고, 기존 기준 방어 테스트 10개가 그대로 통과한다.
