# [Infra] `vercel-ignore.sh`의 얕은 클론 안전 규칙 때문에 문서 전용 push도 가끔 빌드가 생긴다

## 핵심 요약

- 요구사항: 문서 전용 커밋이 여러 개 쌓이면 Vercel의 얕은 복제가 "직전에 빌드한 커밋"을 찾지 못해 안전 규칙("기준을 모르면 빌드한다")이 발동한다. 이 경우를 줄일 수 있는지 검토하고, 줄일 수 없다면 `jam-work` SKILL.md 4.1절의 "문서만 바뀐 push는 빌드를 만들지 않는다" 서술에 조건을 적는다.
- 구현 계획: ① 얕은 복제의 깊이를 실측한다(빌드 로그의 `Cloning` 줄과 `git rev-list --count` 확인). ② 스크립트에서 기준 커밋을 `git fetch --depth=1 origin <sha>`로 가져올 수 있는지 확인한다(빌드 환경의 원격 접근 권한이 있는지). ③ 안 되면 서술을 고친다.
- 관련 파일: `jam-web/scripts/vercel-ignore.sh`, `.claude/skills/jam-work/SKILL.md` 4.1절
- 상위 티켓: 20260922_0002(스테이징 롤백 연습 준비 중 발견). 경로: ③ 표준(infra)

## 배경 / 문제 정의

확인된 사실(2026-09-22): `jam-stage`에 문서·설정 파일만 바뀐 push(커밋 a22ce300)가 실제 빌드를 만들었다. 빌드 로그에 다음 줄이 있었다.

```
[ignore] 직전 빌드 커밋 10ac65ba…가 이 클론에 없음(얕은 클론) — 빌드합니다
```

직전 빌드 커밋 이후 9개 커밋이 쌓여 있었다(에이전트 브랜치 머지 1회로 6개가 한 번에 들어옴). 스크립트는 판단 근거가 없으면 빌드하는 쪽으로 넘어지도록 설계돼 있어 동작 자체는 의도한 안전 규칙이다. 다만 빌드가 한 번 돌면 마커가 새로 써져 다음 push부터는 다시 건너뛴다. 비용은 빌드 1회(약 2분)이며, 커밋이 한꺼번에 쌓이는 날(에이전트 브랜치 머지가 잦은 날)에 되풀이된다. 20일간 Build CPU 66달러가 이 스크립트를 만든 배경이었으므로 빈도를 확인할 가치가 있다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. 최근 2주 `jam-stage`의 빌드 중 "얕은 클론" 사유로 돈 횟수를 센다(`vercel ls`와 빌드 로그).
2. 빈도가 하루 1회 이상이면 스크립트 개선(기준 커밋 fetch)을 시도하고, 아니면 서술에 조건만 적는다.

## 구현 계획

1. 빈도 집계 → 결정 → 구현 또는 서술 수정.

## 완료 조건

- 최근 2주의 "얕은 클론" 빌드 횟수가 기록돼 있다.
- 스크립트를 고쳤거나, SKILL.md 4.1절에 조건이 적혀 있다.
