# [Infra] 아현의 반환 요약이 정해진 형식(30줄·diff 원문 금지)을 반복 위반하고 확인하지 않은 환경 주장을 넣는다

## 핵심 요약

- 요구사항: `.claude/skills/jam-work/references/forms/implementation-summary-format.md`는 반환 요약을 30줄 이내로, diff 원문 없이 쓰라고 정했다(메인 세션 컨텍스트 보호). 그런데 이 세션에서 아현이 돌려준 요약 세 건(20260921_2303·2304, 20260922_0207)은 그 몇 배였고 0207은 diff 코드 블록까지 넣었다. 또 0207 요약은 "이 저장소에는 워크플로를 실행하는 테스트 하니스가 없다"고 적었으나 `.claude/workflows/jam-work.test.mjs`가 이미 있었다(확인하지 않은 환경 주장, `CLAUDE.md` 규칙 5의 취지 위반).
- 구현 계획: ① 워크플로의 `DEV_RESULT` 스키마에서 `summary`에 `maxLength`를 걸 수 있는지 하네스에서 확인하고, 되면 건다. ② 아현 정의에 "어떤 것이 없다고 적기 전에 `ls`·`grep`으로 확인하고 그 명령을 인용한다"를 넣는다. ③ 길이 초과는 카리나 보고 때 표시한다.
- 관련 파일: `.claude/skills/jam-work/references/forms/implementation-summary-format.md`, `.claude/agents/jam-developer.md`, `.claude/workflows/jam-work.js`(`DEV_RESULT` 스키마)
- 상위 티켓: 20260922_0207. 출처: 민지 게이트의 범위 밖 발견물. 경로: ③ 표준(infra)

## 배경 / 문제 정의

아현의 반환값은 Workflow 결과로 메인 세션 컨텍스트에 그대로 들어온다. 요약이 길면 카리나의 컨텍스트가 빨리 찬다. 사용자도 채팅은 결론 위주로, 상세는 티켓에 두기를 원한다. 형식 규칙이 프롬프트에만 있어 반복해서 어겨진다는 점에서 이것도 "프롬프트로 막은 것은 뚫린다"는 사고 이력과 같은 유형이다. 스키마 제약은 기계가 강제한다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. `DEV_RESULT` 스키마의 `summary`에 `maxLength`를 걸 수 있는지 확인한다(하네스가 스키마 검증을 강제하는지 실측). 걸 수 있으면 형식 규칙의 30줄에 해당하는 글자 수 상한을 정한다.
2. 아현 정의에 확인하지 않은 환경 주장 금지를 넣는다(없다고 적을 때는 확인 명령과 결과를 함께 적는다).
3. 이 세션의 세 요약 길이를 재서 근거 수치로 티켓에 남긴다.

## 구현 계획

1. 하네스에서 스키마 상한 실측 → 정의·스키마 수정 → 다음 티켓의 요약 길이로 확인.
