# [Infra] `scripts/batch-tickets.mjs`의 DB 단서 정규식이 API 응답 스키마를 언급한 티켓을 `db`로 오판정한다

## 핵심 요약

- 요구사항: 묶음 실행의 유형 판정에서 Infra 카테고리 티켓을 `db`/`infra`로 가르는 정규식(`DB_CLUE_RE`, 「스키마」 포함)이 "반환 스키마"처럼 API 응답 구조를 말하는 문장에도 걸린다. 드라이런 실측(상위 20260921_2207)에서 하위 티켓 20260921_2307이 `db`로 잘못 판정됐다. 단서를 정교화해 오판정을 줄이되, 확신이 없으면 여전히 `db`(정지) 쪽으로 기운다.
- 구현 계획: 단서를 "마이그레이션·migration·SQL·`supabase/migrations`·ALTER/CREATE TABLE·FK·RLS" 같은 DB 전용 표현으로 좁히고, 「스키마」는 "DB 스키마·테이블 스키마"처럼 DB 한정어와 함께 있을 때만 세도록 한다. 실제 티켓 본문 픽스처(20260921_2307은 `infra`, 20260909_1045·20260914_1751은 `db`)로 회귀 테스트를 보강한다.
- 관련 파일: `scripts/batch-tickets.mjs`, `scripts/batch-tickets.test.mjs`
- 상위 티켓: 20260921_2305(3차 게이트의 범위 밖 발견물). 경로: ① 경미 또는 ③ 표준(infra) — 정규식 한 줄과 테스트 픽스처 추가면 경미

## 배경 / 문제 정의

오판정 방향이 "실행해야 할 티켓을 멈춘다"라서 위험하진 않지만, 묶음 실행이 자주 멈추면 사람이 매번 개입해야 해서 도입 취지가 약해진다. 정규식은 티켓 2305 2차 재작업에서 처음 들어왔고, 3차 재작업에서 스크립트로 옮기며 그대로 유지됐다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. 「스키마」 단독은 단서에서 빼고 DB 한정어와 결합된 경우만 센다.
2. 오판정 사례(20260921_2307)를 `infra` 기대값 픽스처로 추가한다.
3. 기존 `db` 판정 픽스처 2건은 그대로 `db`여야 한다.

## 구현 계획

1. 정규식 수정 → 픽스처 3건 테스트 → `node scripts/batch-tickets.mjs 20260921_2207`로 재확인.

## 완료 조건

- `scripts/batch-tickets.test.mjs` 전부 통과.
