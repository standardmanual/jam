# [Infra] 아현이 낡은 워크트리를 제거하기 전 상태 확인을 사람 지시가 아니라 스크립트로 보장한다

## 핵심 요약

- 요구사항: 아현 정의 5번은 같은 review 브랜치를 점유한 낡은 워크트리를 제거하기 전에 `git status --short <path>`로 미커밋 변경이 없는지 확인하고, 있으면 멈추라고 지시한다. 티켓 20260921_2305 3차 재작업에서 아현은 격리 제약으로 확인하지 못한 채 `git worktree remove --force`를 실행했다(손실은 없었다). 확인·제거를 한 스크립트로 묶어, 미커밋 변경이 있으면 제거를 거부하고 사유를 출력하게 한다.
- 구현 계획: `scripts/cleanup-stale-worktree.sh <branch>`(가칭)를 만들어 (1) 해당 브랜치를 점유한 워크트리 탐색 (2) `git status --short`가 비어 있지 않으면 종료 코드 2로 거부 (3) 비어 있고 HEAD가 origin에 push돼 있으면 제거. 아현 정의 5번의 절차 서술을 이 스크립트 호출로 바꾸고 테스트를 붙인다. 기존 cleanup 관련 티켓(20260921_2309)과 겹치면 그쪽에 합친다.
- 관련 파일: `.claude/agents/jam-developer.md`(Hard rules 5), `scripts/`, `docs/agents/workflow/agents/01_아현_개발.md`(미러)
- 상위 티켓: 20260921_2305(3차 게이트의 범위 밖 발견물). 경로: ③ 표준(infra)

## 배경 / 문제 정의

민지가 "워크트리 강제 제거 전 상태 확인 절차가 실무에서 종종 생략되는 경향"을 지적했다. 재시도가 잦은 티켓일수록 같은 브랜치를 점유한 워크트리가 남고, 정의에 적힌 절차는 에이전트의 준수에 기대는 구조라 기계화가 맞다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. 미커밋 변경이 있으면 절대 제거하지 않는다. 우회 플래그를 두지 않는다.
2. HEAD가 origin의 같은 브랜치에 없으면(미푸시 커밋) 제거하지 않는다.
3. 아현 정의와 미러 문서를 함께 갱신한다(티켓 20260922_1030의 대조 규칙 대상).

## 구현 계획

1. 스크립트·테스트 작성 → 정의 갱신 → 임시 저장소에서 3종(깨끗함/미커밋/미푸시) 확인.

## 완료 조건

- 임시 저장소 테스트 3종이 기대대로 동작한다.
- 아현 정의 5번이 스크립트 호출로 바뀌고 미러 문서도 같이 바뀐다.
