# [Infra] `batch-tickets.mjs` DB 단서에서 뺀 `column`을 한정어와 함께 복원한다 (infra로 새는 오판정 방지)

## 핵심 요약

- 요구사항: 티켓 20260922_1055가 「스키마」 단독 매칭을 없애면서 `column` 단서도 완전히 뺐다. 영어 'column'만 있고 마이그레이션·SQL·FK·RLS·DB 한정 스키마 표현이 없는 Infra 티켓은 `db`가 아니라 `infra`로 판정돼 정지 조건 3번을 지나친다 — 안전하지 않은 방향의 오판정이다(현재 OPEN 티켓에는 해당 사례 없음, 민지 1055 게이트 확인). `column`·「컬럼」을 DB 한정어(추가·삭제·정리·테이블·DB)와 결합된 형태로만 단서에 복원한다.
- 구현 계획: `DB_CLUE_RE`에 `(?:테이블|DB)\s*(?:column|컬럼)|(?:column|컬럼)\s*(?:추가|삭제|정리|변경)` 같은 결합 패턴을 더하고, 픽스처 테스트에 "컬럼 정리" 문장만 있는 가상 티켓(db 기대)과 "column"이 UI 그리드 열을 뜻하는 가상 티켓(infra 기대)을 추가한다.
- 관련 파일: `scripts/batch-tickets.mjs`, `scripts/batch-tickets.test.mjs`
- 상위 티켓: 20260922_1055(민지 게이트의 범위 밖 발견물). 경로: ① 경미(정규식 한 줄·픽스처 2건)

## 배경 / 문제 정의

1055는 "확신이 없으면 db(정지) 쪽으로 기운다"는 원칙 아래 정규식을 좁혔지만, `column` 제거는 반대 방향(정지해야 할 티켓을 실행)으로 새는 구멍을 남겼다. 실제 사례가 없어 판정에는 영향이 없었으나 묶음 실행이 자동화될수록 위험이 커진다.

## 상세 요구사항

### 서비스/코드베이스 관점

1. `column`·「컬럼」은 한정어와 결합된 경우에만 db 단서다.
2. 기존 픽스처 3건(2307→infra, 1045·1751→db)은 그대로 통과한다.

## 구현 계획

1. 정규식 보강 → 픽스처 2건 추가 → 테스트 → `node scripts/batch-tickets.mjs 20260921_2207` 재확인.

## 완료 조건

- 픽스처 5건이 기대대로 판정되고 `scripts/batch-tickets.test.mjs` 전부 통과.
