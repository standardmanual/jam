# [Service] 코퍼스 활성 판정의 소속 조회 블록 통합 + 진단 함수에 삭제 필터 반영

> 티켓 20260924_0015 게이트 리뷰(민지)의 범위 밖 발견물 2건([구조/참고]·[정확성/참고])에서 자동 생성. P3.

## 핵심 요약

- 요구사항: (1) `fetchActiveBadges`와 `fetchBadgeParentStatus`가 소속 컬렉션·트라이브 활성 ID를 조회하는 `Promise.all` 블록을 같은 모양으로 반복한다.
  공통 헬퍼로 묶는다. (2) 진단 전용 `fetchBadgeParentStatus`에 `deleted_at` 필터가 없어, 소프트삭제된 배지와 소속 비활성이 겹치면 반려 사유가
  "소속 트라이브 비활성"으로만 표시돼 실제 삭제 사유를 가린다. 반려 사유에 "배지 삭제됨"을 먼저 표시하도록 고친다.
- 관련 파일: `jam-web/src/lib/content-corpus/active.ts` 100~102행·114~131행, `jam-web/src/lib/content-corpus/verify.ts` 41~62행, 테스트.

## 완료 조건

- 소속 활성 ID 조회가 헬퍼 하나로 모이고 기존 테스트 15건이 그대로 통과한다.
- 삭제된 배지 + 소속 비활성 케이스에서 반려 사유가 삭제를 먼저 말한다(테스트 1건 추가).

크기 상한: 파일 3개, 60줄 이내.
