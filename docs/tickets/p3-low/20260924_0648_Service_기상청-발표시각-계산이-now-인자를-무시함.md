# [Service] `refreshTodayWeather(now)`의 발표시각 계산이 `now` 인자를 무시한다

> 티켓 20260923_2333 게이트(민지)의 범위 밖 발견물이다. 지금은 cron이 항상 현재 시각으로 호출해 영향이 없다.

## 핵심 요약

- 요구사항: `refreshTodayWeather(now)`가 받은 `now`를 발표시각 계산에 그대로 넘긴다. 테스트에서 시각을 고정해 검증할 수 있게 한다.
- 구현 계획: `fetchKmaForecast`가 `now`를 인자로 받아 `latestKmaBaseTime(now)`를 쓰도록 고친다.
- 관련 파일: `jam-web/src/lib/inputs/weather.ts`(`fetchKmaForecast`의 `latestKmaBaseTime(new Date())`, 96행 근방), `jam-web/src/lib/inputs/__tests__/inputs.test.ts`.

## 배경 / 문제 정의

`refreshTodayWeather(now)`의 `now`는 저장 날짜 키 계산에만 쓰이고, 예보 발표시각은 내부에서 다시 `new Date()`를 만든다. 자정 전후에 호출하거나 테스트에서 시각을 고정하면 날짜 키와 발표시각이 서로 다른 날을 가리킬 수 있다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `latestKmaBaseTime`에 호출부의 `now`가 전달된다.
- 시각을 고정한 테스트로 날짜 키와 발표시각이 같은 날을 가리킴을 확인한다.

크기 상한: 2파일/20줄.
