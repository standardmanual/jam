# [Infra] 선별 루틴의 Slack 요약에 GitHub 리포트 링크 추가

## 핵심 요약

- 요구사항: 선별 루틴이 `#jam-report`에 올리는 요약에 GitHub의 선별 리포트 문서 링크를 붙인다. 지금은 "리포트 경로" 텍스트만 올라가 Slack에서 바로 열 수 없다.
- 구현 계획: 클라우드 루틴 지시문 7단계를 고치고, 원본 문서(스펙)를 같은 내용으로 맞춘다.
- 관련 파일: 클라우드 루틴 `trig_01A99A61oLDRQ8tTfZBMvfiE`, `.claude/skills/jam-work/references/scheduled-jobs.md`(선별 절 절차 ④·프롬프트 초안), `.claude/agents/jam-ops.md`(모드 ③ 리포트 항목).

## 배경 / 문제 정의

리포트는 매일 staging에 push되고, 사용자는 리포트의 체크박스로 판정 동의를 표시한다. Slack 요약에서 리포트 문서로 바로 이동할 수 없으면 사용자가 저장소에서 파일을 직접 찾아야 한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 링크 형식은 `https://github.com/standardmanual/jam/blob/staging/docs/operations/reports/triage/YYYY-MM-DD.md`이고, 요약 글의 마지막 줄에 붙인다.
- 링크가 열리려면 리포트가 이미 push돼 있어야 하므로, push 성공 뒤에만 게시한다. push가 끝내 실패하면 게시하지 않고 기존 「실패 처리」(`#jam-alert`)를 따른다.
- 대상이 0건인 날은 종전대로 게시하지 않는다.

## 완료 조건

- 클라우드 루틴 지시문 7단계에 링크 규칙이 반영돼 있다(`RemoteTrigger get`으로 확인).
- 스펙 문서 두 곳이 같은 내용이다.
- 다음 자동 실행(2026-09-25 06:00 KST) 뒤 `#jam-report` 글에 링크가 붙었는지 확인한다.

### 주요 의사결정 / 핵심 메모
- 링크는 서식 없는 URL로 붙인다. 셸 인자 안에서 `<url|텍스트>` 형식을 쓰면 인용 실수 여지가 있고, Haiku 실행이라 단순한 형식을 택했다.
- 브랜치는 `staging`으로 고정했다. 선별 루틴이 staging에 push하기 때문이다.
- 저장소가 비공개라 링크는 GitHub 로그인이 된 사용자만 열 수 있다.
