# [Infra] `check-slop.mjs` 미추적 파일 검사 보완 (바이너리 제외, 테스트 독립성)

> 티켓 20260924_0037 게이트(민지)의 참고 2건이다. 판정에는 영향이 없었고 지금은 문제가 드러나지 않는다.

## 핵심 요약

- 요구사항: (1) 미추적 파일 검사가 검사 범위(`jam-web`·`docs`·`jam-doc`) 안의 모든 미추적 파일을 utf8로 읽어서, 커밋 전 바이너리가 있으면 깨진 문자열로 읽힌다. 텍스트 확장자만 읽거나 바이너리를 건너뛰게 한다. (2) `check-slop.test.mjs`가 `jam-web` 아래에 임시 파일을 만들고 저장소 전체 검사를 돌려서, 워킹트리에 다른 미커밋 금칙어가 있으면 clean 케이스가 실패할 수 있다. 검사 대상을 임시 파일 하나로 좁히거나 결과에서 그 파일만 판정하게 한다.
- 구현 계획: `collectAddedLines`의 미추적 파일 읽기 앞에 확장자 또는 널 바이트 검사를 두고, 테스트는 임시 파일 경로만 검사하는 진입점을 쓰도록 바꾼다.
- 관련 파일: `scripts/check-slop.mjs` 99~106행 근방(`git ls-files --others --exclude-standard` 처리), `scripts/check-slop.test.mjs` 25행 근방.

## 배경 / 문제 정의

0037로 로컬 slop 검사가 커밋 전 수정·미추적 파일까지 보게 됐다. 그 부작용으로 (1) `jam-doc/assets` 등에 커밋 전 이미지가 있으면 바이너리를 문자열로 읽고, (2) 다른 작업의 미커밋 변경이 이 테스트 결과를 흔든다. 오탐이 생기면 로컬 `verify.sh`만 실패해 원인 추적이 어렵다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 미추적 바이너리 파일이 있어도 slop 검사가 오탐 없이 통과한다(테스트로 확인).
- 워킹트리에 다른 미커밋 금칙어가 있어도 `check-slop.test.mjs`의 clean 케이스가 통과한다.

크기 상한: 2파일/40줄.
