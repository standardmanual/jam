# [Admin] 어드민 메인 상단에 컨텐츠 공백 경고(미션 공백·카드 편성 공백)를 표시한다

## 핵심 요약

- 요구사항: 어드민 메인 「이상 신호」 영역 안에 **「미션 공백」**과 **「카드 편성 공백」** 카드 두 개를 항상 표시한다. 정상이면 회색 "공백 없음", 문제가 있으면 빨간 카드에 내용과 바로가기 링크를 넣는다. 조회가 실패하면 그 카드만 오류 카드가 된다.
- 판정 규칙(2026-09-24 사용자 결정 4건, 아래 「상세 요구사항」)은 이 티켓이 원천이다. 미션 규칙은 `docs/specs/SERVICE_OPERATIONS.md` §9-5가 원천이고 여기서 옮겨 적지 않는다.
- 구현 계획: 아래 「구현 계획」 1~5를 따른다.
- 관련 파일:
  - `docs/specs/SERVICE_OPERATIONS.md` §9-5 공개 미션 운영 원칙 (정의·공백 금지·상시 입문 미션·시즌 공개 미션)
  - `jam-web/src/lib/admin/weeklyCards.ts` `weeklyCards` (63줄, 요일별 `unprogrammed` 판정을 재사용), `SHORT_CARD_MAX_DAYS` (19줄)
  - `jam-web/src/lib/missions/gateMissions.ts` `isGateMission` (217줄)
  - `jam-web/src/lib/admin/today-calendar.ts` `todayKstDateString` (14줄), `shiftDateStr` (53줄), `kstDayBoundsIso` (45줄)
  - `jam-web/src/lib/admin/cronSchedule.ts` `mondayOfWeek`
  - `jam-web/src/app/admin/DashboardSignals.tsx` (이상 신호 섹션, `ErrorCard`)
  - `jam-web/src/app/admin/page.tsx` (`DashboardSignals` 배치와 출처별 try/catch)
  - `docs/specs/prd/admin-ui/ADMIN_PRD.md` §5-7

## 배경 / 문제 정의

2026-09-24 사용자가 대시보드 항목 E로 선택했고, 판정 규칙을 문답으로 정한 뒤 진행한다. 티켓 처음에 적은 후보 규칙 중 "드랍 대상 배지가 N개 미만인 트라이브"와 "카드 유형 미편성"은 이번 범위에서 뺐다(사용자가 선택하지 않음).

2026-09-24 확인한 사실(계획의 근거):
- 미션 공백 규칙은 이미 확정돼 있다(`SERVICE_OPERATIONS.md` §9-5). 공개 미션의 정의는 `visibility_rule_json`이 없고 `gate_axis`도 없는 미션이다. 데이터에서 `gate_axis`가 있는 미션 53개는 모두 노출 조건 객체를 갖고, `gate_axis`가 없는 미션 2개는 `visibility_rule_json`이 SQL NULL이라 판정이 모호하지 않다.
- 공개 미션은 2개다: 상시 입문 미션 「겹쳐진 도시의 새 얼굴」(2026-09-24 시작, 종료일 없음)과 기간 미션 「그루터기 살롱의 겨울 채비」(2026-10-01 00:00 ~ 10-31 23:59 KST).
- 시즌 캘린더는 데이터로 존재하지 않는다(저장소에서 시즌 캘린더 문서를 찾지 못했다). 그래서 §9-5의 "시즌 공개 미션" 규칙은 그대로 검사할 수 없고, "종료 전에 이어지는 기간 미션이 있는가"로 근사한다.
- 카드 편성은 화요일 기획안, 수요일 확정, 목요일 배포 주기다(`docs/specs/prd/content-automation/PRD.md` §8-2). 다음 주 카드가 화·수요일에 비어 있는 것은 정상이다. 목요일 배포 실행은 23:59 KST이므로 금요일부터 다음 주를 검사한다.
- 캘린더에는 이미 날짜별 빨간 "미편성"이 있다(티켓 0906). 상단에는 요약만 올린다.
- 오늘(2026-09-24, 목) 데이터 기준 예상 결과: 이번 주(9/21~9/27)는 날마다 장기 카드만 있고 활성 단기 카드가 없어 **9/24·25·26·27 4일이 미편성**이다. 다음 주(9/28~10/4)는 날마다 단기 카드가 있다. 미션은 공백이 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

**사용자 결정 4건(2026-09-24)**
1. **범위**: 미션 공백과 카드 편성 공백만 다룬다.
2. **카드 편성 공백의 검사 시점**: 이번 주는 오늘부터 일요일까지 항상 검사한다. 다음 주(월~일)는 **금요일부터**(금·토·일 중에) 검사한다. 월~목에는 다음 주를 검사하지 않는다.
3. **미션 공백의 규칙**: (a) 상시 입문 미션(종료일이 없고 이미 시작한 공개 미션)이 0건이면 경고, (b) 오늘부터 앞으로 60일 중 공개 미션이 없는 날짜가 있으면 경고, (c) 종료일이 있는 공개 미션이 **14일 안에 끝나는데 이어지는 기간 공개 미션이 없으면** 경고한다.
4. **표시 방식**: 「이상 신호」 영역 안에 두 카드를 항상 표시한다. 정상이면 회색 "공백 없음", 문제가 있으면 빨간 카드에 내용과 바로가기 링크를 넣는다.

**세부 판정(계획 단계의 가정, 티켓 구현 전에 확정된 값)**
- 카드 편성 "미편성"의 정의는 캘린더와 같다: 그 날짜에 걸치는 **활성 단기 카드**(기간 7일 이하)가 하나도 없는 날. 비활성 단기 카드와 장기 카드만 있는 날은 미편성이다(0906 사용자 결정).
- (b)의 60일은 코드 상수(`MISSION_GAP_HORIZON_DAYS`)로 둔다. (c)의 14일은 상수 `MISSION_ENDING_NOTICE_DAYS`로 둔다. 금요일 기준은 상수 `NEXT_WEEK_CHECK_FROM_WEEKDAY = 5`(금)로 둔다.
- 미션의 날짜 비교는 KST 달력 날짜 기준이다. "이미 시작한" 미션은 `starts_at`이 지금보다 이전인 미션이다. 아직 시작하지 않은 상시 미션은 (a)에 세지 않는다.
- (c)의 "이어지는 기간 공개 미션"은 다른 기간 공개 미션으로서 종료가 더 늦고 시작이 그 미션의 종료 다음 날 시작 시각 이전인 것이다(이미 겹쳐 있어도 인정, 비어 있는 날이 없어야 함). **상시 미션은 후속으로 인정하지 않는다**(시즌 규칙이 시즌 미션의 연속을 요구하기 때문).
- (c)의 검사 대상은 종료일이 오늘 이후이고 오늘부터 14일 이내(당일 포함 14일째까지)인 기간 공개 미션이다.
- 게이트 미션(`gate_axis`가 있음)과 노출 조건이 있는 미션은 공개 미션으로 세지 않는다.
- 카드·미션 조회는 캘린더가 보고 있는 주와 무관하게 항상 "지금" 기준이다. 캘린더용 카드 조회와 별개로 이 카드용 조회를 한다.

**표시 문구(어드민, 짧고 명확하게)**
- 정상: `공백 없음`
- 미션 공백: `상시 입문 미션이 없어요` / `M/D 공개 미션이 없어요`(가장 이른 날짜와 총 일수) / `'<제목>'이 M/D에 끝나는데 이어지는 기간 미션이 없어요`
- 카드 편성 공백: `미편성 N일: M/D, M/D`(날짜는 요일과 함께, 7일까지 나열)
- 링크: 미션 → `/admin/missions`, 카드 편성 → `/admin/today?date=<가장 이른 미편성 날짜>`
- 스타일은 「이상 신호」 카드와 같은 계열(문제는 `bg-red-50 border-red-200`, 정상은 `bg-white border-border`)이다. 어드민 유형이라 MODULAR 적용 대상이 아니다.
- 조회가 실패하면 그 카드만 기존 `ErrorCard`로 바뀌고 나머지 영역은 그대로 표시한다. 조회만 하며 DB 변경은 없다.
- 실렌더는 격리 워크트리에서 시도하지 않는다(`DEV_PROCESS_GUARDRAILS.md` 패턴 13). 「카리나 실렌더, 머지 뒤」로 넘긴다.

## 구현 계획

1. `jam-web/src/lib/admin/contentGaps.ts` (신규): (a) 상수 3개. (b) 순수 함수 `isPublicMission(m)`(`gate_axis`와 `visibility_rule_json`이 모두 없음). (c) 순수 함수 `checkMissionGaps(missions, now)` — 상시 입문 미션 유무, 60일 안의 공개 미션 공백 날짜, 14일 안 종료 미션의 후속 유무를 돌려준다. (d) 순수 함수 `checkCardGaps(cards, now)` — 이번 주 오늘~일요일과(금·토·일이면) 다음 주 월~일의 미편성 날짜 목록을 `weeklyCards`로 구한다. (e) 조회 함수 `fetchContentGaps(now)` — `missions`(필요한 컬럼만: id·title·starts_at·ends_at·gate_axis·visibility_rule_json)와 `today_cards`(이번 주 월요일부터 다음 주 일요일까지 겹치는 카드)를 읽고 두 결과를 독립적으로 돌려준다(한쪽 실패가 다른 쪽에 영향을 주지 않음).
2. `jam-web/src/lib/admin/__tests__/contentGaps.test.ts` (신규): 단위 테스트(아래 완료 조건 목록).
3. `jam-web/src/app/admin/ContentGapCards.tsx` (신규, 서버 컴포넌트): 두 카드를 그린다(정상·문제·오류 세 상태).
4. `DashboardSignals.tsx`와 `page.tsx`: `DashboardSignals`에 선택 prop을 추가해 「이상 신호」 섹션의 세 카드 아래에 `ContentGapCards`를 렌더한다. `page.tsx`는 `fetchContentGaps`를 다른 출처와 독립적으로(try/catch) 호출해 넘긴다. 기존 세 카드와 주간 핵심 지표 표시는 바뀌지 않는다.
5. `docs/specs/prd/admin-ui/ADMIN_PRD.md` §5-7: 「현재 동작」에 컨텐츠 공백 경고(검사하는 규칙, 시점, 표시, 실패 시 처리)를 추가하고 「예정」에서 뺀다. 미션 규칙의 원천은 `SERVICE_OPERATIONS.md` §9-5임을 밝히고 규칙 내용을 옮겨 적지 않는다.

## 완료 조건

- 단위 테스트가 있다(`contentGaps.test.ts`):
  - 미션: 상시 입문 미션 0건 경고, 아직 시작하지 않은 상시 미션은 세지 않음, 게이트 미션·노출 조건이 있는 미션은 공개 미션이 아님, 60일 안 날짜 공백 검출, 종료 14일 경계(정확히 14일 남은 미션은 검사, 15일 남은 미션은 제외), 이어지는 기간 미션이 있으면 경고 없음(연속·겹침), 상시 미션은 후속으로 인정하지 않음, KST 자정 경계.
  - 카드: 목요일에는 다음 주를 검사하지 않고 금요일에는 검사함, 이번 주는 오늘부터(오늘 포함) 일요일까지, 비활성 단기 카드만 있는 날과 장기 카드만 있는 날은 미편성, 활성 단기 카드가 있는 날은 편성.
- (카리나 실렌더, 머지 뒤) 2026-09-24 데이터 기준으로 「카드 편성 공백」이 `미편성 4일: 9/24(목), 9/25(금), 9/26(토), 9/27(일)`로, 「미션 공백」이 `공백 없음`으로 표시된다. 값을 `today_cards`·`missions`에서 SQL로 직접 센 결과와 함께 완료 기록에 남긴다. 링크가 `/admin/today?date=2026-09-24`와 `/admin/missions`로 이동한다.
- 한쪽 조회가 실패해도 다른 카드와 나머지 영역은 표시된다.
- 기존 「이상 신호」 세 카드와 주간 핵심 지표, 캘린더, 그래프 표시는 바뀌지 않는다.
