# [Admin] 어드민 메인 캘린더에서 크론의 시 필드가 여러 값일 때 항목 id가 겹치지 않게 한다

## 핵심 요약

- 요구사항: cron 식의 시 필드가 쉼표로 여러 값(예: `0 6,18 * * *`)을 가지면, 같은 날짜 칸에 id가 같은 항목이 두 개 이상 생겨 React key가 충돌한다. 항목 id에 실행 시각을 포함해 겹치지 않게 한다.
- 구현 계획: `AdminDashboardPage`에서 캘린더 항목을 만드는 `map`의 id를 `${o.path}-${date}`에서 시각까지 포함하는 형태(예: `${o.path}-${date}-${hourly ? 'hourly' : hh:mm}`)로 바꾸고, 여러 시 값을 갖는 cron 식에 대한 테스트를 추가한다. 0905(Claude 예약 루틴)가 같은 항목 생성 구간을 고치므로 그 티켓에서 함께 처리해도 된다.
- 관련 파일:
  - `jam-web/src/app/admin/page.tsx` `AdminDashboardPage` 안의 `columns` 생성 `map` (41줄 부근, id 생성)
  - `jam-web/src/lib/admin/cronSchedule.ts` `parseCronField` (50줄, 쉼표 목록 파싱), `cronToWeeklyOccurrences` (60줄)
  - `jam-web/src/lib/admin/__tests__/cron-schedule.test.ts`

## 배경 / 문제 정의

티켓 20260924_0904 게이트 리뷰(민지)의 범위 밖 발견물이다(`[구조/참고]`). `parseCronField`는 쉼표 목록을 지원하므로 시 필드에 값이 여러 개면 같은 요일에 발생 시각이 여러 개 나온다. 그런데 항목 id에는 경로와 날짜만 들어가서 id가 겹친다. 현재 `jam-web/vercel.json`의 크론 4개는 모두 시 값이 하나이거나 `*`라서 지금은 문제가 드러나지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 어드민 유형이므로 MODULAR를 적용하지 않는다. 조회만 하며 DB 변경은 없다.
- 크론 목록의 원천은 `jam-web/vercel.json` 하나이며, 이 티켓에서 크론 정의는 바꾸지 않는다.

## 구현 계획

핵심 요약의 구현 계획과 같다.

## 완료 조건

- `0 6,18 * * *` 같은 cron 식이 주어지면 같은 날짜 칸에 06:00(KST 변환 뒤 시각)과 18:00 항목이 각각 서로 다른 id로 만들어진다는 단위 테스트가 있다.
- 기존 크론 4개의 표시 결과(시각·라벨·순서)는 바뀌지 않는다.
