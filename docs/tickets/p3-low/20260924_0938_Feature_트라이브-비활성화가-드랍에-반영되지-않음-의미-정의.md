# [Feature] 트라이브를 비활성화해도 드랍에는 반영되지 않는다 — 비활성화의 의미를 정한다

## 핵심 요약

- 요구사항: 트라이브 비활성화가 어디까지 영향을 줘야 하는지 정한다. 드랍 엔진에도 반영할지가 핵심이다.
- 구현 계획: 기획 판단(혜린) 후 결정. 반영한다면 드랍 엔진의 트라이브 조회에 활성 조건을 더한다.
- 관련 파일: `jam-web/src/lib/drop-engine/index.ts:185-201`(트라이브 조회가 `id, name`만 읽음),
  `jam-web/src/app/(main)/onboarding/page.tsx:72-74`, `jam-web/src/app/api/onboarding/complete/route.ts:99-104`,
  `jam-web/src/lib/content-corpus/active.ts`

## 배경 / 문제 정의

상위 티켓 20260924_0916의 파일 지도 작성 중에 확인했다(2026-09-24, 코드 확인).

| 영역 | 트라이브 `is_active`를 보는가 |
|---|---|
| 온보딩 트라이브 선택지 | 본다 |
| 콘텐츠 자동 추천 후보 | 본다(티켓 20260924_0015) |
| 드랍 엔진 | **보지 않는다.** 트라이브를 `id, name`만 조회한다 |

그래서 어드민이 트라이브를 비활성화해도, 그 트라이브에 속한 활성 컬렉션의 아이템배지는 계속 드랍된다. 어드민
목록의 확인창(상위 티켓 §3 등급 2)은 우선 실제 영향(온보딩 선택지·추천 후보에서 빠짐)만 안내한다.

## 완료 조건

- 비활성화의 의미가 결정되어 PRD 또는 ④ 배지엔진 문서에 적혀 있다.
- 드랍에도 반영하기로 하면: 비활성 트라이브의 컬렉션 배지가 드랍 후보에서 빠지는 것을 드랍 엔진 단위 테스트로
  확인한다. 어드민 트라이브 목록의 확인창 문구도 함께 고친다.
