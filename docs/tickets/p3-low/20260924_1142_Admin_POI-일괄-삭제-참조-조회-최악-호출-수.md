# [Admin] POI 일괄 삭제의 참조 조회가 최악의 경우 약 399회까지 늘어난다

## 핵심 요약

- 요구사항: POI 일괄 삭제(최대 200건)에서 참조가 있는 항목을 찾는 방식의 최악 비용을 줄인다.
- 구현 계획: 임베디드 건수 조회(`poi_drops(count)` 등)를 로컬 실측으로 검증한 뒤, 검증되면 행별 건수를 한 번에 받는 방식으로 바꾼다.
- 관련 파일: `jam-web/src/lib/admin/poi-references.ts:268-315`(`collectPoiReferencesById`), `jam-web/src/app/api/admin/poi/bulk/route.ts`

## 배경 / 문제 정의

티켓 20260924_0941 게이트(민지)의 범위 밖 발견물이다(2026-09-24). `collectPoiReferencesById`는 묶음 합계를 보고 참조가 있는 묶음만 반씩
나눠 찾는다. 선택한 200건이 모두 참조를 가지면 `collectPoiReferences` 호출이 이론상 최대 약 399회(회당 참조 테이블 6개 순차 조회)로
늘어난다. `maxDuration = 60`으로 대응돼 있고 기존 배지 일괄 삭제와 같은 패턴이라, 새로 생긴 위험은 아니다.

## 완료 조건

- 참조가 있는 POI 200건을 가정한 스텁 테스트에서 조회 횟수가 상수 회(묶음 수 × 참조 테이블 수 이하)다.
- 임베디드 건수 조회 방식을 쓴다면 로컬 실측 결과를 완료 기록에 남긴다.
