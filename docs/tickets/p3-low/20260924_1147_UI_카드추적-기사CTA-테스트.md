# [UI] 투데이 카드 추적 전송과 기사 CTA 대상 판정 테스트를 추가한다

> 티켓 20260924_0855를 착수 시 둘로 나눈 뒤쪽 절반이다(앞쪽은 20260924_1146).

## 핵심 요약

- 요구사항: (1) `TodayCardTracker`의 전송 동작(노출 임계 0.5, `sessionStorage` 중복 억제, `sendBeacon` 실패 시 `fetch` 폴백, `trackClick=false`일 때 클릭 미전송)을 테스트로 고정한다. (2) `resolveArticleCtaTarget`의 공백만 있는 `target_href` 처리와 우선순위(target_href > 컬렉션 > 미션 > null)를 테스트로 고정한다.
- 구현 계획(파일 단위, 1차 시험 구현에서 확인한 계획):
  1. 신규 `jam-web/src/lib/today/cardEventClient.ts`: `sendTodayCardEvent`(기존 로직 그대로 이동), `IMPRESSION_THRESHOLD = 0.5`, `hasSeenImpression(cardId)`, `markImpressionSeen(cardId)`(`sessionStorage` 접근 예외는 삼킨다), `createClickReporter(cardId, trackClick)`(`trackClick=false`면 undefined 반환).
  2. 수정 `jam-web/src/app/(main)/TodayCardTracker.tsx`: 8~24행 함수와 `IMPRESSION_KEY_PREFIX`를 제거하고 위 모듈을 호출한다. 페이로드(`cardId`·`event`)와 임계값 0.5, GA `trackEvent` 호출은 그대로다.
  3. 신규 `jam-web/src/lib/today/__tests__/cardEventClient.test.ts`: `vi.stubGlobal`로 `navigator`·`fetch`·`sessionStorage`를 대체한다. 검증 항목은 sendBeacon 성공 시 fetch 미호출, sendBeacon이 false이거나 없을 때 keepalive fetch 폴백과 거부 무시, 임계값 0.5, 중복 억제, `sessionStorage` 예외 안전, `trackClick=false`일 때 클릭 미전송이다.
  4. 수정 `jam-web/src/lib/admin/__tests__/today-sections.test.ts`(265행 `resolveArticleCtaTarget` 블록): 우선순위(target_href > 컬렉션 > 미션 > null) 테스트는 이미 있다(274~279행). 빠진 공백만 있는 `target_href` 케이스만 5줄 추가한다. targetHref 테스트를 신규 파일로 만들지 않는다.
- 관련 파일: `jam-web/src/app/(main)/TodayCardTracker.tsx`(8~24행), `jam-web/src/lib/today/targetHref.ts`(83~101행), `jam-web/src/lib/admin/__tests__/today-sections.test.ts`(265행 근방), 신규 `jam-web/src/lib/today/cardEventClient.ts`와 그 테스트

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- 두 경로가 테스트로 고정된다.
- 전송 페이로드(`cardId`·`event`)와 노출 임계값(0.5)은 이전과 같다.

크기 상한: 4파일/추가 약 154줄(1차 시험 구현 실측. 삭제 포함 190줄). 초기 90줄 상한은 컴포넌트 분리 비용을 빠뜨린 잘못된 추정이라 정정했다.

## 주요 의사결정

- 1차 호출에서 아현이 `plan_only`(100줄 이상)로 멈췄다. 사용자가 2026-09-24 계획 반환 면제를 승인했다(파일 단위 계획 있음, 시험 구현에서 vitest 62건 통과 확인, 변경이 모듈 이동과 테스트 추가뿐).
- 1차 호출 때 규모 사전 판정이 빗나간 원인: 노드 환경(vitest `node`)에서는 컴포넌트를 렌더할 수 없어 로직 이동이 필수라는 점을 티켓 작성 때 줄 수에 반영하지 않았다.
