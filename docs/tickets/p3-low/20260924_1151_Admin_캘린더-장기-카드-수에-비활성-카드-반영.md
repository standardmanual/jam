# [Admin] 어드민 메인 캘린더의 "장기 카드 N장"이 비활성 장기 카드를 빼고 세어 `/admin/today` 목록 개수와 어긋날 수 있다

> **연결 메모 (2026-09-30 티켓 20260930_1451 사용자 결정):** 20260930_1502(운영툴 운영 홈·일정표·신호)가 같은 화면을 넓히므로 착수 때 함께 판단한다.

## 핵심 요약

- 요구사항: 캘린더 칸의 "단기 카드 + 장기 카드 수"가 같은 날짜의 `/admin/today?date=` 목록 개수와 항상 같도록, 비활성 장기 카드를 어떻게 셀지 정하고 반영한다.
- 구현 계획: 추천은 장기 카드 줄에 비활성 수를 따로 붙이는 방식이다(예: "장기 카드 40장 · 비활성 2장"). 활성 수는 그대로 두므로 기존 의미가 바뀌지 않는다.
- 관련 파일:
  - `jam-web/src/lib/admin/weeklyCards.ts` `longActiveCount` 계산 (69줄 부근)
  - `jam-web/src/lib/admin/__tests__/weeklyCards.test.ts`
  - `jam-web/src/app/admin/WeeklyCalendar.tsx` "장기 카드 N장" 렌더
  - `docs/specs/prd/admin-ui/ADMIN_PRD.md` §5-7 홈피드 카드 편성 항목

## 배경 / 문제 정의

티켓 20260924_0906 게이트 리뷰(민지)의 범위 밖 발견물이다(`[정확성/참고]`). 0906 티켓에는 두 조건이 함께 적혀 있다.
- 장기 카드 수는 활성 카드만 센다.
- 캘린더 칸의 "단기 카드 + 장기 카드 수"가 같은 날짜의 `/admin/today?date=` 목록 개수와 같다.

`/admin/today` 목록은 비활성 카드도 보여 준다(`jam-web/src/app/admin/today/page.tsx` 32~37줄, `is_active` 조건 없음). 그래서 비활성 장기 카드가 생기면 두 조건이 동시에 성립하지 않는다. 2026-09-24 조회 기준으로 9/21~10/4에는 비활성 장기 카드가 없어서 드러나지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 어드민 유형이므로 MODULAR를 적용하지 않는다. 조회만 하며 DB 변경은 없다.
- "미편성" 판정(활성 단기 카드 없음)은 바꾸지 않는다.

## 구현 계획

핵심 요약의 구현 계획과 같다. 다른 방식(비활성 장기 카드도 "장기 카드 N장"에 합산)을 택하면 0906의 "활성만 센다" 서술을 PRD에서 함께 고친다.

## 완료 조건

- 비활성 장기 카드가 있는 날에도 캘린더 칸의 카드 수 합(단기 + 장기 활성 + 장기 비활성)이 같은 날짜의 `/admin/today?date=` 목록 개수와 같다는 단위 테스트가 있다.
- 비활성 장기 카드가 없는 날의 표시는 지금과 같다.
