# [Admin] 배지 목록의 전체 선택·내보내기가 조회 오류를 "0건"으로 보여 준다

## 핵심 요약

- 요구사항: `fetchBadgeListIds`가 DB 오류를 만나면 빈 결과가 아니라 오류를 돌려주고, ids·export 라우트가 500과 한국어 안내를 응답하게 한다.
- 구현 계획: 오류를 throw하거나 `{ error }`를 반환하도록 바꾸고 두 라우트에서 처리한다. `AssignTribeDialog`의 미리보기 effect 의존성(`ids` 배열 참조)도 함께 점검한다.
- 관련 파일: `jam-web/src/lib/admin/badge-list-query.ts:297-300`, `jam-web/src/app/api/admin/badges/ids/route.ts`, `jam-web/src/app/api/admin/badges/export/route.ts`, `jam-web/src/components/admin/badges/AssignTribeDialog.tsx:95-107`

## 배경 / 문제 정의

티켓 20260924_0944 게이트(민지)의 범위 밖 발견물이다(2026-09-24). `fetchBadgeListIds`가 DB 오류 시 로그만 남기고 `{ ids: [], total: 0 }`을 돌려준다. 그래서 전체 선택 배너와 내보내기가 오류를 "0건"으로 오인시킬 수 있다. 목록 화면 전반의 조용한 실패 구조 점검 티켓(20260901_1848)과 같은 유형이다.
`AssignTribeDialogBody`의 미리보기 effect 의존성에 `ids`(선택 ID 배열)가 있어, 부모가 배열 참조를 매 렌더 새로 만들면 다이얼로그가 열린 채 리렌더될 때마다 미리보기(dry-run)가 다시 호출될 수 있다(실렌더 확인 필요).

## 완료 조건

- DB 오류 스텁에서 `ids`·`export`가 500과 한국어 안내를 응답한다(단위 테스트).
- 트라이브 지정 창이 열린 채 부모가 리렌더돼도 미리보기 요청이 한 번만 나간다(실렌더에서 네트워크 요청 수로 확인).

- `AssignTribeDialog.tsx`의 미리보기 effect는 `ids` 배열 참조 대신 `idsKey`(ids.join) 문자열에만 의존한다.
