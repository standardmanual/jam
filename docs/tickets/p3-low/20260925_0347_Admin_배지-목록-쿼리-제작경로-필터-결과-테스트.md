# [Admin] 배지 목록 쿼리의 제작 경로 필터가 실제로 걸러내는지 테스트를 붙인다

> 티켓 20260924_2200 게이트 리뷰에서 민지가 낸 범위 밖 발견물(`[테스트]`)을 3.2절대로 자동 티켓화했다.

## 핵심 요약

- 요구사항: `jam-web/src/lib/admin/badge-list-query.ts`의 제작 경로(`imageSource`) 필터 분기(`applyBadgeListFilters`의 DB 필터, `fetchCheckinCategoryCandidates`의 메모리 필터)는 `parseBadgeListParams` 매핑까지만 테스트되고 실제 필터링 결과는 검증되지 않는다. 기존 필터(tribeId·poiCategory 등)도 같은 수준이라 이 티켓이 만든 공백은 아니지만, 라벨·필터가 운영자의 원인 추적 수단(사용자 결정 7)이므로 결과 검증을 붙인다.
- 구현 계획: supabase 쿼리 빌더 스텁으로 `.eq('image_source', …)`·`.is('image_source', null)` 호출과 메모리 필터 결과(미상 sentinel 포함)를 확인하는 테스트를 `badge-list-query.test.ts`에 추가한다. 기존 필터도 같은 방식으로 함께 덮으면 관행이 하나가 된다(선택).
- 관련 파일: `jam-web/src/lib/admin/badge-list-query.ts`(`applyBadgeListFilters`·`fetchCheckinCategoryCandidates`), `jam-web/src/lib/admin/__tests__/badge-list-query.test.ts`, 라벨·sentinel 단일 출처 `jam-web/src/lib/admin/badgeImageSource.ts`

## 완료 조건
- 제작 경로 필터 4값(수동 제작·윤진 자동·아이콘 파이프라인·미상)에 대해 DB 필터 호출과 메모리 필터 결과를 확인하는 테스트가 추가되어 통과한다.
- `npm run lint`·`npm test` 통과.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- `badge-list-query.test.ts`에 제작 경로 필터 결과 테스트 12건을 추가했다. 체이닝 호출을 기록하는 supabase 스텁(`recordingSupabase`)을 썼다.
  - DB 필터(`applyBadgeListFilters`): 수동 제작·윤진 자동·아이콘 파이프라인은 `.eq('image_source', 값)`, 미상(`__unknown__`)은
    `.is('image_source', null)`, 필터 없음은 조건 없음, 계열순(전량 정렬 경로)에서도 같은 필터.
  - 메모리 필터(`fetchCheckinCategoryCandidates`, 체크인 + 지점 카테고리 경로): 값 3종은 해당 배지만, 미상은 NULL·빈 문자열 배지만,
    필터 없음은 전부 남기고, 이 경로는 DB에 `image_source` 조건을 걸지 않는다.
- 기존 필터(tribeId 등)까지 함께 덮는 것은 티켓에서 선택 사항이라 하지 않았다.
