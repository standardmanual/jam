# [Infra] 등록 기록 SQL 주석의 한 줄 정리를 모든 주석 줄에 적용하고 제어 문자 정규식 복제를 없앤다

> 티켓 20260924_2202 보안 패치 재판정에서 민지가 낸 범위 밖 발견물(`[보안/참고]`·`[구조/참고]`)을 3.2절대로 자동 티켓화했다.

## 핵심 요약

- 요구사항: (1) `buildRegistrationSql`이 SQL `--` 주석 중 머리 3줄에만 `commentSafe`(개행·제어 문자를 공백으로)를 적용한다. 「이미지 파일」 주석 줄과 되돌림 SQL 주석 줄은 거치지 않는다. 지금 그 값은 상수와 `randomUUID()`라 사용자 입력이 닿지 않아 악용 경로는 없지만, 값의 출처가 바뀌면 같은 구멍이 다시 열린다. (2) 개행·제어 문자 범위 정규식이 `registerBundle.mjs`(`CONTROL_OR_LINE_BREAK`)와 `registerRecord.mjs`(`commentSafe`)에 같은 내용으로 두 번 적혀 있어 한쪽만 고치면 어긋난다.
- 구현 계획: SQL 주석에 들어가는 모든 보간 값을 한 함수로 감싼다(주석 줄을 만드는 작은 헬퍼로 모아 누락을 막는다). 정규식은 한 곳(예: `registerBundle.mjs`에서 export)에서 가져다 쓴다. 두 값의 정의가 갈라지지 않도록 기존 테스트에 "모든 주석 줄이 한 줄" 확인을 넣는다.
- 관련 파일: `jam-web/scripts/asset-generator/registerRecord.mjs`(`commentSafe` 79줄 근처, `buildRegistrationSql` 132·145줄의 이미지 파일·되돌림 주석 줄), `jam-web/scripts/asset-generator/registerBundle.mjs`(`CONTROL_OR_LINE_BREAK` 70줄 근처), `jam-web/scripts/asset-generator/__tests__/registerRecord.test.ts`(주석 주입 방어 테스트)

## 완료 조건
- SQL 기록의 모든 주석 줄이 어떤 record 값에서도 한 줄로 유지된다(개행·CRLF·U+2028이 섞인 모든 필드로 확인하는 테스트).
- 제어·개행 문자 정규식의 원본이 한 곳이다. `npm run lint`·`npm test` 통과.
