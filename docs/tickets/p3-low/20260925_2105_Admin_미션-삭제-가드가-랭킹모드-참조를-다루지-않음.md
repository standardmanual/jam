# [Admin] 어드민 미션 삭제 가드가 랭킹 모드 참조를 다루지 않는다

> 티켓 [20260925_1412](../p2-normal/20260925_1412_Infra_미션-등록묶음-포맷과-등록스크립트.md)
> 게이트(민지)의 범위 밖 발견물이다.

## 핵심 요약

- 요구사항: 미션을 삭제할 때 그 미션을 대상으로 삼는 랭킹 모드가 있으면 운영자가 알 수 있게 한다.
- 구현 계획: 먼저 「결정 필요」를 정한 뒤 `MISSION_REFERENCE_SOURCES`에 랭킹 모드 항목을 추가하고 테스트로
  고정한다.
- 관련 파일: `jam-web/src/lib/admin/reference-guards.ts`(`MISSION_REFERENCE_SOURCES` 135행 근방,
  `collectMissionReferences` 168행 근방), 사용처 `jam-web/src/app/api/admin/missions/[id]/route.ts`(DELETE)·
  `jam-web/src/app/api/admin/missions/bulk/route.ts`·`jam-web/src/lib/admin/mission-bulk.ts`,
  `jam-web/scripts/asset-generator/registerMissionFlow.mjs`(되돌림 검사 6곳).

## 배경 / 문제 정의

### 사실 (2026-09-25 코드를 읽어 확인한 결과)

- 어드민 미션 삭제 가드 `MISSION_REFERENCE_SOURCES`는 5곳을 본다: 완료 이력·참여 이력·랭킹 스냅샷·
  포인트 지급 원장(이상 4곳은 삭제를 막는다)과 투데이 카드 연결(막지 않고 안내만 한다).
- `ranking_modes.target_mission_id`는 `missions(id)`를 참조하고 `ON DELETE SET NULL`이다
  (`jam-web/supabase/migrations/158_ranking_modes.sql` 42행). 이 컬럼은 가드 목록에 없다
  (`reference-guards.ts`에서 `ranking_modes`·`target_mission_id`를 검색해 0건).
- 미션 등록 스크립트(티켓 1412)의 되돌림은 미션을 참조하는 6곳을 모두 검사해 하나라도 데이터가
  있으면 중단한다. 6곳은 생성 타입의 `referencedRelation: "missions"` 외래 키와 일치함을 민지가 확인했다.
  따라서 스크립트의 되돌림 검사와 어드민 삭제 가드가 다루는 범위가 다르다.

### 추론 (코드 읽기로 도출했고 재현하지는 않았다)

- 랭킹 모드가 특정 미션의 참여자를 대상으로 삼는데(`target_type='mission_participants'`, 158
  마이그레이션 주석) 그 미션을 어드민에서 삭제하면 `target_mission_id`가 조용히 NULL이 되고, 삭제
  화면은 이를 알려 주지 않는다. 그 뒤 해당 랭킹 모드가 어떻게 동작하는지는 확인하지 않았다.

## 결정 필요

- **A. 가드 목록에 랭킹 모드를 추가하되 안내만 한다**(투데이 카드 연결과 같은 `blocks: false`).
  삭제는 막지 않지만 운영자가 「이 미션을 대상으로 한 랭킹 모드 N건이 대상 없음이 된다」를 본다.
- **B. 삭제를 막는다**(`blocks: true`). 랭킹 모드가 대상 없는 상태가 되는 것을 원천 차단하지만
  운영자가 먼저 랭킹 모드를 정리해야 한다.
- 카리나 추천: **A**. SET NULL이라 데이터 손상은 없고, 삭제 자체를 막는 것은 과하다. 다만 삭제 뒤 랭킹
  모드 동작을 확인한 결과 화면이 깨진다면 B가 맞다(착수 시 확인).

## 완료 조건

- 결정한 방침이 완료 기록에 남아 있다.
- 랭킹 모드가 참조하는 미션을 삭제하려 할 때(단건·일괄 모두) 그 사실이 운영자에게 보인다(방침 B면
  삭제가 막힌다). 테스트로 고정되어 있다.
- 참조하지 않는 미션의 기존 삭제 동작은 그대로다.
- `scripts/verify.sh` 통과.
