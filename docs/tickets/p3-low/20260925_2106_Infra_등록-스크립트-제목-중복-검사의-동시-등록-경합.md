# [Infra] 등록 스크립트의 제목 중복 검사가 동시 등록 경합에 무방비다

> 티켓 [20260925_1412](../p2-normal/20260925_1412_Infra_미션-등록묶음-포맷과-등록스크립트.md)
> 게이트(민지)의 범위 밖 발견물이다. 홈피드 등록 스크립트(티켓
> [20260925_1413](../p2-normal/20260925_1413_Infra_홈피드-등록묶음-포맷과-등록스크립트.md))가 같은 패턴으로
> 만들어질 예정이라 그 티켓도 이 결정을 따른다.

## 핵심 요약

- 요구사항: 등록 스크립트의 「제목 중복」 검사가 읽고 나서 등록하는 두 단계라 사이에 다른 등록이 끼어들면
  중복을 막지 못한다. 이를 어떻게 다룰지 정한다.
- 구현 계획: 「결정 필요」를 정한 뒤 방침에 따라 정본 문서에 전제를 적거나 DB 제약을 추가한다.
- 관련 파일: `jam-web/scripts/asset-generator/registerMissionFlow.mjs`(`runMissionDbChecks` 103행 근방의
  제목 조회, 208행 근방의 insert), `docs/specs/prd/asset-generator/MISSION_REGISTRATION_BUNDLE.md`.

## 배경 / 문제 정의

### 사실 (2026-09-25 확인한 결과)

- 미션 등록 스크립트는 등록 전에 `missions`에서 같은 제목을 조회(`select id ... eq('title', ...)`)하고,
  통과하면 이미지를 올린 뒤 행을 insert한다. 조회와 insert 사이에 잠금이나 제약이 없다.
- 실행 주체는 메인 세션 한 곳이고 사용자가 `--dry-run` 요약을 컨펌한 뒤에만 등록한다(CLAUDE.md 규칙 6).
- `missions.title`에 UNIQUE 제약이 있는지는 확인하지 않았다.
- 홈피드 등록 스크립트(티켓 1413)의 중복 검사는 「제목 + 시작 일시」를 `eq`로 비교한다(`registerHomeFeedFlow.mjs`
  98행 근방). 1413 확인 때 초 단위 시작 일시를 가진 실제 카드는 중복으로 거절되었지만, 시작 일시에
  마이크로초가 붙은 옛 카드(예: `2026-07-26 01:44:56.115217+00`)와 같은 값을 넣어도 통과했다. 원인은
  스크립트가 시각을 밀리초로 다뤄 값이 정확히 같지 않기 때문으로 추정하며 코드로 확정하지는 않았다.
  어드민 폼과 이 스크립트로 등록되는 카드는 분·초 단위 값이라 실제 영향은 옛 시드 카드에 한정된다.

### 왜 문제인가 (판단)

메인 세션 하나가 컨펌 뒤에 순서대로 실행하는 전제에서는 같은 제목이 동시에 두 번 등록될 가능성이 낮다.
그래도 두 세션이 같은 묶음을 실행하는 경우(병렬 세션)에는 중복 미션이 생기고 이미지도 이중으로 올라간다.

## 결정 필요

- **A. 코드는 그대로 두고 정본 문서에 「단일 메인 세션 실행 전제」를 명시한다.** 변경이 문서 한 줄이다.
- **B. DB에 제목 UNIQUE 제약을 추가한다.** 경합을 원천 차단하지만 마이그레이션이 필요하고 공용 DB에 즉시
  반영되며, 기존 데이터에 중복 제목이 있으면 먼저 정리해야 한다(중복 여부 미확인).
- 카리나 추천: **A**. 위험이 낮고 실행 주체가 하나로 정해져 있어 비용 대비 효과가 작다. 병렬 실행이
  실제로 필요해지면 B를 다시 검토한다.

## 완료 조건

- 결정한 방침이 완료 기록에 남아 있다.
- 방침 A면 미션·홈피드 등록 묶음 정본에 전제가 명시되어 있고, 방침 B면 마이그레이션(되돌림 SQL
  포함)과 중복 제목 사전 조사 결과가 있다.
- `scripts/verify.sh` 통과.
