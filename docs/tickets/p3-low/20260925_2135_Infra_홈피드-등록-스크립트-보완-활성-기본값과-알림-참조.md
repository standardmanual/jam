# [Infra] 홈피드 등록 스크립트 보완: 활성 기본값과 알림 페이로드 참조

> 티켓 [20260925_1413](../p2-normal/20260925_1413_Infra_홈피드-등록묶음-포맷과-등록스크립트.md)
> 게이트(민지)의 범위 밖 발견물 두 건을 묶었다. 둘 다 **결정이 필요한** 참고 사항이다.

## 핵심 요약

- 요구사항: (1) 묶음에 `is_active`를 적지 않으면 카드가 켜진 채 등록되어 기간이 되면 바로 노출되는 기본값을
  유지할지 정한다. (2) 되돌림 전 사용자 데이터 검사에 알림 페이로드의 `today_card_id`를 넣을지 정한다.
- 구현 계획: 아래 「결정 필요」를 정한 뒤 결정에 따라 정본 문서를 보강하거나 스크립트를 고친다.
- 관련 파일: `jam-web/scripts/asset-generator/registerHomeFeedBundle.mjs`(`buildTodayCardInsertPayload`,
  449행 근방 `is_active: card.is_active ?? true`), `jam-web/scripts/asset-generator/registerHomeFeedFlow.mjs`
  (되돌림 참조 검사 주석 44~50행 근방), `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md`
  (115행 `is_active` 필드표).

## 배경 / 문제 정의

### 사실 (2026-09-25 코드·문서를 읽고 확인한 결과)

- 스크립트는 묶음에 `is_active`가 없으면 `true`로 넣는다. 정본 필드표에도 「기본 true. 시험 등록은 false」로
  적혀 있고 dry-run 요약에는 「상태: 비활성/활성」 줄이 나온다(1413 시험 등록의 dry-run에서 「비활성(어디에도
  노출하지 않음)」 표시를 확인했다).
- 되돌림은 `today_card_events.card_id` 참조만 검사한다. 이 외래 키는 `ON DELETE SET NULL`이다(마이그레이션
  183). 코드에서 카드 id를 담는 곳이 하나 더 있는데, 알림 announcement 페이로드의 `today_card_id`다(JSON 안의
  값이라 외래 키가 아니고, 스크립트의 검사 대상이 아니다).
- 미션 등록 스크립트의 노출 기본값(`exposure_mode` 생략 시 `start_date`)도 켜짐 쪽이라, 두 스크립트는 같은
  방향이다.

### 아직 확인하지 않은 것

- 알림 announcement 페이로드가 실제로 어떤 흐름에서 `today_card_id`를 담고, 그 알림이 카드 삭제 후에 어떻게
  보이는지는 확인하지 않았다.

## 결정 필요

**(1) 활성 기본값**
- **A. 현재 유지(기본 켜짐)**. 등록은 사용자가 dry-run 요약(상태 줄 포함)을 컨펌한 뒤에만 하고 시험은 `false`를
  명시하는 절차가 이미 있어 기본값이 사고로 이어질 여지가 작다. 카리나 추천이다(판단).
- **B. 기본을 꺼짐으로 바꾸고 어드민에서 켠다**. 실수로 즉시 노출되는 일이 없지만 등록 뒤 한 단계가 늘고
  미션 스크립트(기본 노출)와 기본값이 갈라진다.

**(2) 알림 페이로드 참조**
- **A. 검사 대상에 넣지 않고 정본에 「알림 페이로드는 검사하지 않는다」를 명시한다**. 카리나 추천이다(판단).
  등록 직후 되돌리는 시험·오등록 상황에서는 알림에 실릴 가능성이 낮다.
- **B. 되돌림 전에 알림 페이로드도 조회해 붙어 있으면 중단한다**. 안전하지만 JSON 내부 값 조회가 필요하고
  알림 저장 구조를 먼저 확인해야 한다.

## 완료 조건

- 두 결정이 완료 기록에 남아 있다.
- 결정이 코드 변경이면(`is_active` 기본 false 또는 알림 참조 검사) 동작이 테스트로 고정되어 있고, 문서 변경만이면
  정본에 반영되어 있다.
- `scripts/verify.sh` 통과.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- **사용자 결정(2026-09-25): 두 결정 모두 방침 A(현재 유지)**.
  1. `is_active` 기본값은 **켜짐을 유지**한다. 등록은 사용자가 `--dry-run` 요약의 「상태」 줄까지 컨펌한 뒤에만 하고 시험 등록은 `false`를 명시하는 절차가 이미 있다.
  2. 알림 announcement 페이로드의 `today_card_id`는 되돌림 검사 대상에 **넣지 않는다**.
- `HOME_FEED_REGISTRATION_BUNDLE.md`를 고쳤다: 필드표의 `is_active` 행에 「생략하면 기간이 되는 즉시 노출된다」와 유지 결정의 근거를 적고, §7에 「이 스크립트는 알림 페이로드를 검사하지
  않는다」를 결정으로 명시했다(알림 저장 구조는 확인하지 않았다는 사실도 함께). 코드는 바꾸지 않았다.
