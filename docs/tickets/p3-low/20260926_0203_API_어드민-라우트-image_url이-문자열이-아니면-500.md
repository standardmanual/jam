# [API] 어드민 배지·미션 수정 라우트가 `image_url`이 문자열이 아닐 때 500을 낸다

> 2026-09-26 프로덕션 배포 전 점검(민지 모드 ②·③ 공통)의 발견물이다.

## 핵심 요약

- 요구사항: 본문 `image_url`이 숫자·객체이면 `imageSourceReset`의 `.trim()`이 던져 500이 된다. 400으로 거절하거나 무시한다.
- 관련 파일: `jam-web/src/lib/admin/imageSourceReset.ts:13-17`, `jam-web/src/app/api/admin/badges/[id]/route.ts:79`, `missions/[id]/route.ts:101`, 테스트 `lib/admin/__tests__/imageSourceReset.test.ts`(6건, 비문자열 입력 없음).

## 완료 조건

- 비문자열 `image_url`을 준 수정 요청이 500이 아니라 의도한 응답(400 또는 무시)이다. 관리자 전용이며 내부 정보는 노출되지 않는다. 테스트로 고정. `scripts/verify.sh` 통과.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 묶음 티켓 20260926_1442로 처리했다. 상세와 실행 지표는 그 티켓의 완료 기록에 있다.
- **400으로 거절하는 쪽을 택했다.** 근거: "무시"는 update 페이로드에 비문자열이 그대로 실려 DB 오류 원문 500이나 조용한 문자열 강제 변환이 남을 수 있고, missions는 `...safeBody` 스프레드라 특히 그렇다. `imageUrlTypeError`를 `imageSourceReset.ts`에 추가하고 `badges/[id]`(PUT)·`missions/[id]`(PATCH) 진입부에서 검사한다. `normalize`는 비문자열에도 던지지 않게 방어했다(`itembooks/[id]`·`today/[id]`도 같은 함수를 써 500은 사라짐). 응답 문구에는 내부 정보가 없다.

### 변경된 파일
```
- jam-web/src/lib/admin/imageSourceReset.ts
- jam-web/src/app/api/admin/badges/[id]/route.ts, missions/[id]/route.ts
- jam-web/src/lib/admin/__tests__/imageSourceReset.test.ts
```

### 테스트 결과
- [x] 비문자열 입력에서 `normalize`가 던지지 않음과 400 문구를 단위 테스트가 고정한다. CI 성공

### 잔여 이슈
- `itembooks/[id]`·`today/[id]` 라우트에는 `imageUrlTypeError` 검사를 붙이지 않았다(500만 사라졌고 비문자열이 update 페이로드로 가는 동작은 종전과 같다). 후속 티켓.
