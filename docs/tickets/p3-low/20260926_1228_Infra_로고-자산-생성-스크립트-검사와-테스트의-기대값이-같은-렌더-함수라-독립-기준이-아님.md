# [Infra] 로고 자산 생성 스크립트의 `--check`와 테스트가 같은 렌더 함수로 기대값을 만들어 독립 기준이 되지 못한다

> 2026-09-26 티켓 20260925_1125 게이트(민지)의 범위 밖 발견물이다. 신호: 참고.

## 핵심 요약

- 요구사항: 로고 자산 검사가 생성 코드와 다른 기준을 갖도록 보강할지 정한다.
- 관련 파일: `jam-web/scripts/gen-brand-assets.mjs`(`renderLogo`·`renderIcon`, `--check`), `jam-web/scripts/gen-brand-assets.test.mjs:70` 부근.

## 배경 / 문제 정의

- `--check`와 테스트는 기대값을 생성에 쓰는 같은 렌더 함수(`renderLogo`·`renderIcon`)로 만든다. SVG나 렌더러가 바뀌면 생성물과 기대값이 함께 움직여 검사가 통과한다. 즉 "저장소 파일이 지금 SVG에서 만든 것과 같은가"는 보지만, "올바른 로고인가"는 보지 못한다.
- 옛 J와 달라야 한다는 완료 조건은 개발자가 한 번 측정한 값(13.9%)을 근거로 삼았고 저장소에는 검증이 없다. 테스트는 좌우 반전 J로 검사가 느슨하지 않은지만 본다.
- 영향은 낮다: 로고는 자주 바뀌지 않고, 바뀔 때 스크립트를 다시 돌리는 절차가 이 티켓의 목적이다.

## 완료 조건

- 두 가지 중 하나를 정한다. (a) 지금 구조를 유지하고 티켓을 닫는다. (b) 고정된 기준 이미지(예: 승인된 J 마스크 해시)를 저장소에 두고 테스트가 그것과 대조하게 한다.
