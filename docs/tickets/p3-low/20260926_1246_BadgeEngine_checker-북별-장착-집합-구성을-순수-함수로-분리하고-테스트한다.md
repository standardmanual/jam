# [BadgeEngine] `checkItemBookCompletion`의 북별 장착·획득 집합 구성을 순수 함수로 분리해 테스트한다

> 2026-09-26 티켓 20260924_0937 게이트(민지)의 WARN 사유(테스트 적절성)에서 나온 후속이다.

## 핵심 요약

- 요구사항: `checker.ts`의 슬롯·체크인 획득 이력을 북별 집합으로 나누는 부분(`checker.ts:108-145` 부근)은 Supabase 호출과 한 함수에 섞여 있어 회귀해도 자동 테스트가 잡지 못한다. 순수 함수로 빼서 단위 테스트한다.
- 구현 계획: `buildFilledByBook(slots, poiBadgesByBook, earnedPoiBadgeIds)` 형태의 순수 함수를 만들고 `checker.ts`가 호출하게 한 뒤, A 장착 X가 B 소속으로 바뀐 조합과 체크인 이력이 소속 북에만 들어가는 경우를 테스트한다.
- 관련 파일: `jam-web/src/lib/itembook/checker.ts:108-145`, `jam-web/src/lib/itembook/__tests__/`.

## 완료 조건

- 구성 함수가 순수 함수로 분리돼 있고 위 두 경우를 검증하는 단위 테스트가 있다.
- 기존 `checkItemBookCompletion` 동작(완성 기록·보상 발급)은 그대로다.

### 배포 전 점검에서 재확인 (2026-09-26, 프로덕션 배포 `96ce45c1`)
- 민지 모드 ③(배포 전 테스트 공백 점검)이 이 공백을 [주의/확신도 높음]으로 다시 지적했다. 완성 보상 배지 발급으로 이어지는 위치라 위험 비중이 가장 크다는 평가다. 체크인 배지를 다른 북 집합에 넣거나 `computeBookCompletion`에 빈 Set을 넘겨 옛 경로가 조용히 죽는 배선 실수를 잡을 테스트가 없다. 다음 BadgeEngine 작업 때 우선 처리한다.
