# [Infra] `worktree-wf_*` 보존 가드가 첫 자동 실행에서 「보존(작업 커밋 있음)」 줄을 대량으로 내는지 확인한다

> 2026-09-26 티켓 20260926_1240 게이트(민지)의 범위 밖 발견물이다. 신호: 참고.

## 핵심 요약

- 요구사항: 새 가드(`scripts/workspace-setup.sh`의 `wf_branch_unique_work`)는 재작성 이전 `worktree-wf_*` 중 tip 제목이 `origin/staging` 이력에 없는 브랜치를 보존한다. 저장소에서 실제로 몇 개가 보존될지는 로컬 브랜치를 건드리지 않으려고 실측하지 않았다. 첫 자동 실행(세션 시작 시 `cleanup`)에서 「보존」 줄이 대량으로 나와 출력이 지저분해지는지 확인한다.
- 구현 계획: 세션 시작 로그에서 첫 실행 결과를 확인한다. 보존 수가 많으면 출력을 요약 한 줄로 줄이거나, 재작성 이전 브랜치 정리를 사용자 승인으로 한 번 처리하는 방안을 정한다.
- 관련 파일: `scripts/workspace-setup.sh:181` 부근, `scripts/workspace-setup.test.mjs`.

## 완료 조건

- 첫 자동 실행에서 보존된 브랜치 수와 출력량을 확인하고, 과하면 출력을 줄이거나 정리 방안을 정했다.
