# [Infra] 예약(클라우드) 세션이 사용자 휴대폰에 푸시 알림을 보낸다: 억제 방법을 확인한다

> 발견 경위: 티켓 20260926_1205 시험 실행(범위 밖 발견물).

## 핵심 요약

- 요구사항: 예약 루틴 세션이 프롬프트에 없던 `PushNotification` 도구를 써서 사용자 휴대폰에 알림을 보내는 일을 막을 수 있는지 확인하고, 필요하면 막는다.
- 구현 계획: 시험 루틴 로그(세션 `cse_014aHkALaWgNw4GZD2LJAtzN`)에서 `PushNotification` 호출 경위를 보고, 루틴 설정(`allowed_tools`·`disallowed_tools`)으로 억제되는지 시험한다. 억제되면 정기 루틴(주간·월간·선별·배포)의 설정에도 적용할 방안을 정한다.
- 관련 파일: 루틴 설정(claude.ai/code/routines, RemoteTrigger의 `job_config.ccr.session_context`), `.claude/skills/jam-work/references/scheduled-jobs.md`(4-3 무인 권한)

## 배경 / 문제 정의

시험 세션의 허용 도구는 Bash·Read·Write·Glob·Grep이었고 프롬프트는 푸시를 시키지 않았는데, 세 번째 실행에서 세션이 `PushNotification`으로 「렌더링 결정성 확인 완료…」를 보냈다(결과 「Mobile push requested」). 정기 루틴이 같은 일을 하면 사용자에게 의도하지 않은 알림이 간다. 무인 권한 표(4-3)의 「Slack 두 채널 외 발행 금지」와도 결이 맞지 않는다.

## 상세 요구사항

- `disallowed_tools`에 `PushNotification`을 넣으면 막히는지 시험 루틴으로 확인한다(시험 루틴에서만, 정기 루틴은 확인 뒤 사용자 승인으로 적용).
- 막을 수 없으면 프롬프트 금지 문구로 대신할 수 있는지 확인하고, 4-3 표에 사실대로 적는다.

## 완료 조건

- 시험 루틴에서 푸시 알림이 억제되는지 여부와 방법이 완료 기록에 있다.
- 정기 루틴 적용 여부를 사용자와 정했고 `scheduled-jobs.md`에 반영됐다.
