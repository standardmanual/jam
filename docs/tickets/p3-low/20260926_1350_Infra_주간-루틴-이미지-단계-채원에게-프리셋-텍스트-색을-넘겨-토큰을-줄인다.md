# [Infra] 주간 루틴 이미지 단계: 채원에게 프리셋 텍스트 색을 넘겨 시간·토큰을 줄인다

> 발견 경위: 티켓 20260926_1207 리허설(세션 `cse_01Esd1bayxUJ7VZkD7nk24Uf`)에서 발견한 개선점.

## 핵심 요약

- 요구사항: 루틴 본체가 채원(색 후보·대비)을 부를 때 `홈피드` 프리셋의 텍스트 색(레이어별 `color`)과 스테이지 비율을 함께 넘기게 한다.
- 구현 계획: 프리셋 단건 조회 `GET {ADMIN_API_BASE_URL}/api/admin/asset-generator/presets/<id>`(읽기 토큰)에서 `preset.layers[].color`를 읽어 채원 프롬프트에 넣는 문장을 저장 프롬프트 2-1단계 3번과 `jam-marketer.md` ⑧ 1단계에 추가한다(루틴 저장 프롬프트 교체는 사용자 승인 필요).
- 관련 파일: `.claude/agents/jam-marketer.md`(⑧ 1단계), `.claude/skills/jam-work/references/scheduled-jobs.md`(주간 절 프롬프트 초안), 주간 루틴 저장 프롬프트(`trig_01DrqvaJccpp17ZBKyTgQgeX`), `jam-web/src/app/api/admin/asset-generator/presets/[id]/route.ts`

## 배경 / 문제 정의

리허설에서 채원이 「호출 프롬프트에 프리셋 텍스트 색이 없다, 프리셋 색은 DB 값이라 직접 조회할 수 없고 추측해 확정하지 않는다」며 흰색·검정 두 경우를 모두 계산해 답하고 실제 색 확인을 요청했다. 무인 실행이라 답할 사람이 없어 루틴 본체가 흰색 기준 후보를 그대로 채택했다. 실측(가상 카드 2장): 채원 78,478토큰·162초. 두 경우를 다 계산한 만큼의 낭비다. `홈피드` 프리셋의 텍스트 레이어는 둘 다 흰색(`#ffffff`)이고 1:1(1280×1280)이다(2026-09-26 DB 조회).

## 상세 요구사항

- 색 값은 하드코딩하지 않고 매 실행마다 API로 읽는다(프리셋을 어드민에서 바꾸면 값이 달라진다).
- 채원 정의(`jam-designer.md` 모드 ⑤ 「프리셋 텍스트 색은 호출 프롬프트가 알려준다」)와 맞춘다.
- 같은 김에 이미지 단계 전체 토큰(리허설 실측: 윈터 24,439 · 채원 78,478 · 윤진 67,300, 합 170,217)을 줄일 수 있는 다른 지점(윤진 프롬프트에 명령을 그대로 적어 탐색 줄이기 등)을 다음 정기 실행 실측 뒤 함께 검토한다.

## 완료 조건

- 채원 호출 프롬프트에 프리셋 텍스트 색이 들어가 채원이 단일 기준으로 대비를 계산하고 되묻지 않는다(다음 정기 실행 또는 리허설 로그로 확인).
- 문서와 저장 프롬프트가 일치한다(저장 프롬프트 교체는 사용자 승인 뒤).
