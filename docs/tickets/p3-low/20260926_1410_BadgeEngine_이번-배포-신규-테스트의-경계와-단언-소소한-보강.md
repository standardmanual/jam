# [BadgeEngine] 이번 배포의 신규 테스트(제재 필터 경계·`buildFilledByBook`)의 경계값과 느슨한 단언을 보강한다

> 2026-09-26 프로덕션 배포(`8265beec`) 전 점검(민지 모드 ③) 발견물이다.

## 핵심 요약

- 요구사항: 민지 모드 ③이 남긴 [참고] 세 가지를 한 번에 정리한다. (1) 제재 필터 경계 테스트가 `BAN_FETCH_LIMIT-3`(997건)과 정확히 1,000건만 있고 999건(한도 바로 아래)과 0건이 없다(`user-list.test.ts`). `>=`를 `>`로 바꾸는 회귀는 1,000건 테스트가 잡으므로 위험은 낮다. (2) `buildFilledByBook`의 빈 입력(`slots: []`와 빈 `checkinBadgesByBook` 동시) 결과가 빈 Map인지 확인하는 테스트가 없다(`filled-by-book.test.ts`). (3) 새 테스트의 단언이 일부 느슨하다: `get('B')?.has('X') ?? false`와 `get('C')?.size ?? 0`는 키가 없는 경우와 빈 집합인 경우를 구분하지 않고, `expect(console.error).toHaveBeenCalledWith(expect.any(String), RAW)`는 로그 접두어를 검증하지 않는다.
- 구현 계획: 경계 케이스 두 개와 빈 입력 케이스를 추가하고, 키 없음·빈 집합을 구분하는 단언과 로그 접두어 단언으로 바꾼다. 코드 변경은 없다.
- 관련 파일: `jam-web/src/lib/admin/__tests__/user-list.test.ts`, `jam-web/src/lib/itembook/__tests__/filled-by-book.test.ts`, `jam-web/src/app/api/admin/badges/list-bulk/__tests__/route.test.ts`.

## 완료 조건

- 위 경계·빈 입력 케이스가 추가되고 단언이 계약을 더 좁게 고정한다. `scripts/verify.sh` 통과.
