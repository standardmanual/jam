# [Admin] 어드민 문구·주석·문서의 소소한 정리 묶음: 삭제 미리보기 문구, 합쇼체 혼용, 낡은 주석, 종료 판정 경계, API 표 누락

> 어드민 목록 공통화(20260924_0916)의 범위 밖 발견물 묶음 티켓들에서 결함성 항목만 골라 한 번의 구현·게이트·병합으로 처리하는 묶음 티켓이다(사용자 지시, 2026-09-26). 원본 항목은 각 하위 발견물 티켓의 「배경」에 있다. 처리하지 않는 항목은 그 티켓을 닫을 때 항목별로 사유를 적는다.

## 핵심 요약

- 요구사항: 동작 변경이 거의 없는 소소한 정리 다섯 가지. (1) 레시피 삭제 미리보기 문구가 `삭제할 수 없어 제외됩니다(라벨: 삭제할 수 없습니다. 이 레시피를 가리키는 참조가 N건 있습니다.)`로 나와 "삭제할 수 없"이 두 번 겹치고 괄호 안에 문장이 들어간다(티켓 1633 #1, `RecipeTable.tsx` 삭제 미리보기 impact 블록). 하나의 자연스러운 문장으로 고친다. (2) `mission-bulk.ts:104`의 일부 오류 문구(`일부만 반영됐습니다`)가 같은 파일의 해요체와 합니다체로 섞인다(티켓 1630 #4). `docs/specs/UX_WRITING_GUIDELINE.md`의 어투 기준으로 통일한다. (3) `MissionForm.tsx:103-105` 주석 2곳이 삭제된 `MissionList.tsx`를 가리킨다(티켓 1630 #6). 현재 상태에 맞게 고치거나 이력 서술로 분명히 표시한다. (4) 종료 판정 경계가 서로 다르다: 목록 상태는 `ends_at < now`가 종료(`mission-list-query.ts:57`)인데 기간 종료 일괄은 `ends_at <= now`를 이미 끝난 것으로 건너뛴다(`mission-bulk.ts:126`, 티켓 1630 #3). 같은 판정으로 맞춘다. (5) `docs/specs/SERVICE_OPERATIONS.md:1057-1058` 어드민 API 표에 신설된 `review/ids`, `drop-policy/exclusions/bulk`, `drop-policy/exclusions/ids`가 없다(티켓 1632 #1). 표에 추가한다.
- 관련 파일: `jam-web/src/app/admin/recipes/RecipeTable.tsx`, `jam-web/src/lib/admin/mission-bulk.ts:104,126`, `jam-web/src/lib/admin/mission-list-query.ts:57`, `jam-web/src/app/admin/missions/MissionForm.tsx:103-105`, `docs/specs/SERVICE_OPERATIONS.md:1057-1058`.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- (1) 레시피 삭제 미리보기(`RecipeTable.tsx`)의 괄호 속 문장 구조를 없애고 "선택한 레시피 중 N개는 삭제 대상에서 제외됩니다." 한 문장과 사유 목록 한 줄로 나눴다. 사유 문장(`recipe-bulk.ts:41`)은 그대로라 "삭제할 수 없"이 한 번만 나온다. 이 다이얼로그의 기존 합니다체는 유지했다.
- (2) `mission-bulk.ts`의 오류 문구 3곳(95·100·105행)을 해요체로 통일했다(`반영에 실패했어요.`, `일부만 반영됐어요.`). 같은 파일의 다른 사유 문구가 해요체이고 UX Writing 가이드 §2.1이 해요체를 기본으로 하기 때문이다. 테스트의 문구 단언도 함께 고쳤다.
- (3) `MissionForm.tsx` 주석의 삭제된 `MissionList.tsx` 언급을 "예전 목록 컴포넌트(현재는 삭제됨)"로 정정했다.
- (4) **종료 판정 경계**: 목록 상태는 `ends_at < now`만 종료로 보고 진행 판정은 `isMissionActive`와 같은 `ends_at >= now`다(`mission-list-query.ts:44-47` 주석). 기준은 목록 쪽이 맞다고 보고 `mission-bulk.ts:126`의 `<=`를 `<`로 바꿨다. `mission-list-query.ts`는 바꾸지 않았다. 종료 시각이 정확히 now인 경계를 테스트로 고정했다.
- (5) `SERVICE_OPERATIONS.md` 어드민 API 표에 3행을 추가했다: `GET /api/admin/poi/review/ids`, `POST /api/admin/drop-policy/exclusions/bulk`, `GET /api/admin/drop-policy/exclusions/ids`. 티켓이 가리킨 1057-1058행은 현재 다른 내용이라 관련 행 옆에 넣었다(실제 경로 `/api/admin/poi/review/ids`).

### 주요 의사결정 / 핵심 메모
- **WARN을 재작업 사유로 보지 않았다.** 서버 공용 문구(`bulk/server.ts:182` 등, 합니다체)가 새로 바꾼 미션 문구(해요체)와 한 문장 안에서 섞일 수 있다는 지적인데, 서버 문구는 티켓 범위 밖이고 동작에는 영향이 없다. 어투 기준을 정한 뒤 통일하는 후속 티켓을 만들었다(어드민 문구를 어디까지 해요체로 할지 먼저 정해야 한다).
- **경계 판정은 목록 쪽을 기준으로 삼았다.** 코드의 "종료" 정의(`isMissionActive`와 같은 `ends_at >= now`가 진행)를 근거로 했다. 실제 시각이 정확히 같을 확률은 사실상 없어 동작 차이는 없다.
- **`mission-list-query.ts`는 바꾸지 않았다.** 티켓 표에 "필요하면"으로 적혀 있었고 목록 기준이 옳아 필요가 없었다.
- **면제 없이 진행했다.** 파일 5개·예상 약 20줄로 임계값 이내였고 실제 jam-web diff는 41줄이었다.
