# [API] 에셋 제너레이터 API 보강 묶음: 프리셋 경로 검증·업로드 순서(0201), apply 실패 경로 테스트(0202), `image_url` 비문자열 500(0203)

> 하위 티켓들을 한 번의 구현·게이트·병합으로 처리하기 위한 묶음 티켓이다(사용자 지시, 2026-09-26). 끝나면 하위 티켓도 함께 닫는다. **각 하위 티켓의 「구현 계획」과 「완료 조건」이 세부 기준이다. 아래 표는 파일 단위 실행 범위이고, 세부 요구사항은 하위 티켓 본문(`docs/tickets/`)을 읽는다.**

## 핵심 요약

- 요구사항: (1) 프리셋 저장·삭제가 스토리지 경로에 형식 검증 없는 값을 넣는 것을 막고, 존재하지 않는 `id`로 덮어쓸 때 404가 나도 파일이 남는 순서를 고치고, 빠진 테스트를 채운다(0201). (2) 운영자가 이미지를 반영하는 유일한 서버 경로(`apply`)의 실패 경로를 테스트로 고정한다(0202). (3) 본문 `image_url`이 숫자·객체이면 `imageSourceReset`의 `.trim()`이 던져 500이 되는 것을 400으로 거절하거나 무시한다(0203).
- 관련 파일: `jam-web/src/app/api/admin/asset-generator/presets/route.ts`(:93 폼 `id`, :104 레이어 `id`, :124-128 경로 구성과 업로드, :140 존재 확인), `presets/[id]/route.ts`(:38-45 삭제 경로), `presets/__tests__/route.test.ts`, `apply/route.ts`(:157·167·174·188-193), `apply/__tests__/route.test.ts`, `jam-web/src/lib/admin/imageSourceReset.ts:13-17`, `badges/[id]/route.ts:79`, `missions/[id]/route.ts:101`, `lib/admin/__tests__/imageSourceReset.test.ts`.

## 완료 조건

- 프리셋 경로에 형식이 틀린 값이 들어가면 거절되고, 404일 때 스토리지에 파일이 남지 않는다(단위 테스트). `apply`의 실패 경로가 테스트로 고정된다.
- 비문자열 `image_url`이 500이 아니라 의도한 응답(400 또는 무시)이다(단위 테스트). `scripts/verify.sh` 통과.
