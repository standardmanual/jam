> 묶음 티켓이다(사용자 지시, 2026-09-26). 끝나면 `20260926_1535`·`20260926_1545`를 함께 닫고, `20260925_0238`은 이번 범위를 완료 기록에 옮겨 적은 뒤 **나머지가 남아 있으므로 OPEN으로 둔다**(export·ids 라우트는 묶음 B `20260926_1547`, 그 밖의 라우트는 후속). **각 하위 티켓 본문이 세부 기준이고, 아래 표가 파일 단위 실행 범위다.**

## 핵심 요약

- 요구사항
  1. **`0238` 일부(DB 오류 원문 정리)**: 아래 라우트에서 DB·스토리지 오류의 `error.message`를 응답에 싣지 않고, **고정 한국어 문장 + 서버 `console.error`** 로 바꾼다. 문장 형식은 `badges/list-bulk/route.ts:32-34`의 상수와 같다(「~하지 못했어요. 서버에서 ~ 중 오류가 났어요. 잠시 뒤 다시 시도해 주세요.」). 로그 접두어도 그 파일처럼 `[<라우트 이름> <무엇> 오류]`로 적는다. **앱이 직접 만든 안내 문장(예: 「유저를 찾을 수 없습니다.」)은 바꾸지 않는다.**
  2. **`1545`**: `isUuid` 직접 단위 테스트, `itembooks/[id]` PUT·`today/[id]` PATCH의 이미지 필드 `null`·빈 문자열 통과 테스트, 본문이 `null`인 요청은 500이 아니라 400으로 거절(기존 라우트에 본문 오류 400 관례가 있으면 그 문구를 쓴다).
  3. **`1535`**: 점검 스크립트 결함 3건(`public-mission-check.mjs:69` null 응답, `deploy-gate.mjs:653` 쿠키 `Expires`, `check-contract.mjs:537` 임시 폴더 생성 실패)을 고치고 테스트로 고정한다. `deploy-gate.test.mjs`에 J2가 남긴 「`Expires` 현재 동작」 기대값은 새 동작으로 바꾼다.
- **범위 제외**: export·ids 라우트(묶음 B), 위에 적지 않은 다른 어드민 라우트, `deleteByIds`의 `reasonFor`가 건네는 개별 삭제 실패 사유(어드민에게 「참조 중」 같은 이유를 보여 주는 용도라 별도 판단이 필요하다. 발견하면 `alerts`에 적는다).
