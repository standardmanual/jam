# [Admin] CLI 이미지 레이어 원본 교체 테스트 보강과 번호 판별 일원화

> **연결 메모 (2026-09-30 티켓 20260930_1451 사용자 결정):** 20260930_1501(운영툴 미리보기·이미지) 착수 때 함께 판단한다. 07 블루프린트 4.5가 승인 때 에셋 제너레이터의
> 서버 렌더를 재사용하므로 에셋 제너레이터의 역할이 커진다.

## 핵심 요약

- 요구사항: 티켓 20260927_0100의 게이트 리뷰(민지)가 남긴 범위 밖 발견물(참고)을 처리한다. 동작 결함은 없고 머지 뒤 실제 프리셋 렌더에서 `--img01` 경로가 정상 동작하는 것을 확인했다.
- 구현 계획: (1) `renderCard.mjs`의 `--img01` 경로(값을 지정한 이미지 번호 판별 → `loadLayerImage` → `serverImageLoader` 연결)에 단위 테스트를 추가한다. (2) `imageAssets` 캐시가 `assetUrl`을 키로 써서 `--img01` 원본과 다른 이미지 레이어에 저장된 `assetUrl`이 같은 문자열이면 한쪽 경로로 통일되는 점을 레이어 번호(`img01`)를 키로 바꿔 없앤다. (3) `checkPlanValues`가 이미지 번호를 `key.startsWith('img')`로 판별하는 것을 `parseLayerKey`(`layerKeys.ts`)로 일원화한다.
- 관련 파일: `jam-web/scripts/asset-generator/renderCard.mjs`(113~122줄 이미지 원본 로드), `jam-web/scripts/asset-generator/applyMissionImagesFlow.mjs`(212줄 `checkPlanValues`), `jam-web/scripts/asset-generator/loadLayerImage.mjs`, `jam-web/src/lib/asset-generator/layerKeys.ts`, `jam-web/scripts/asset-generator/__tests__/`(새 렌더 경로 테스트)

## 완료 조건

- `--img01`으로 지정한 원본이 이미지 레이어에 적용되고 나머지 이미지 레이어는 저장된 값을 쓰는 것이 테스트로 확인된다(같은 `assetUrl`을 가진 두 이미지 레이어 케이스 포함).
- 이미지 번호 판별이 `parseLayerKey` 한 곳으로 모인다.
- `scripts/verify.sh`가 통과한다.
