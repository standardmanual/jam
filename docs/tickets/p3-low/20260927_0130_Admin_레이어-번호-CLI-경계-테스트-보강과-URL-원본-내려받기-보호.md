# [Admin] 레이어 번호 CLI 경계 테스트 보강과 URL 원본 내려받기 보호

## 핵심 요약

- 요구사항: 티켓 20260927_0100 배포 전 점검(민지 모드 ②·③)이 남긴 참고·주의 발견물을 처리한다. 동작 결함은 없다. 차단 사유가 아니다.
- 구현 계획(테스트 공백): (1) `applyLayerValues.mjs` 73~79줄 「값은 문자열이어야 해요」 분기와 빈 문자열 값(`--text01 ""`, `--img01 ""`) 테스트, (2) `loadLayerImage.mjs` URL 경로 경계값(본문 5MB 초과, SVG 응답, 디렉터리 경로) 테스트, (3) `runPreview`에 이미지 번호 값이 흐르는 계획 테스트와 `makeHomeFeedCardFlow.mjs` `--img01` 값 전달 테스트(`text01` 없이 `text02`만 준 기록 필드 매핑 포함), (4) `apply-mission-images.mjs` `createTextOverflowDetector`가 받는 `{ presetId, values }` 계약 테스트(진입 파일이라 함수를 분리해 테스트하는 것을 검토).
- 구현 계획(URL 원본 보호, 보안 참고): (1) `loadLayerImage.mjs` 34~46줄 `fetch`에 타임아웃을 두고 `Content-Length` 사전 검사와 스트리밍 크기 상한으로 5MB를 넘기 전에 중단한다, (2) 사설 IP·링크 로컬 주소로 가는 URL을 거부하거나 허용 목록을 두는 것을 결정한다(권장: 예약 루틴 환경에서는 https만 허용), (3) 오류 메시지에 URL 전체(쿼리의 서명·토큰 포함)를 붙이지 않고 호스트와 경로까지만 남긴다, (4) PNG 픽셀 수 상한을 검토한다(낮음).
- 이전 배포부터 있던 낮은 확신의 참고(이번에는 조치 없음): 롤백이 `applied.json`의 `previous.image_url`을 형식 검증 없이 되써 로컬 파일 변조 시 임의 URL이 들어갈 수 있다(`applyMissionImagesFlow.mjs` 578~581줄), `imageAssets` 캐시가 `assetUrl` 문자열을 키로 써서 `--img01` 값과 저장된 URL이 같은 문자열이면 검증을 건너뛴다(`renderCard.mjs` 113~119줄, 티켓 20260927_0124에서 다룬다).
- 관련 파일: 위 본문의 파일들과 `jam-web/scripts/asset-generator/__tests__/`

## 추가 참고 (티켓 20260927_0119 배포 전 점검, 민지 ②·③, 모두 낮은 위험)

- 이미지 값(로컬 경로·URL)이 `resolved.json`의 미션별 `values`에 그대로 기록된다. 로컬 out-dir에만 쓰이고 DB·프리셋 저장 경로는 없다.
- `--img01`에 로컬 경로를 주면 SVG 안의 외부·로컬 `href` 참조를 렌더러(`serverCanvas.ts` `loadImageAsCanvas`)가 따라가는지 확인하지 못했다(추정, 확신도 낮음).
- `loadLayerImage`의 `<svg` 판별이 4096바이트 경계에서 어떻게 동작하는지 테스트가 없다.
- `render.mjs` 표준 출력의 `layers: {applied, saved}` 필드는 진입점이라 직접 시험하지 않는다.

## 완료 조건

- 위 테스트 항목이 각각 테스트로 확인된다. URL 원본이 시간 초과·5MB 초과 시 본문을 다 받기 전에 오류로 멈추고 오류 메시지에 쿼리가 남지 않는다.
- `scripts/verify.sh`가 통과한다.
