# [Feature] 온보딩 퀘스트 단계별 진입·완료·건너뛰기 이벤트를 GA4로 보낸다 (T9)

## 핵심 요약
- 요구사항: 퀘스트 시작, 단계별 완료(1~7), 건너뛰기, 실제 연동 완료(퀘스트 완료), 보상 지급 이벤트를 GA4로 전송한다.
- 구현 계획: 기존 GA4 이벤트 전송 방식(예: `first_badge_earned`, `jam-web/src/lib/strava/sync.ts` L191)을 따른다.
- 관련 파일: GA4 이벤트 유틸, T1~T8 각 단계 완료 지점, `docs/tickets/p3-low/20260924_0913_Admin_대시보드-가입-온보딩-지표-GA4-연동.md`(참고, 범위 다름)

## 배경 / 문제 정의
성공 기준(완료율, 단계별 이탈, 소요 시간)을 재려면 단계별 이벤트가 필요하다. 기존 티켓 `20260924_0913`은 어드민 대시보드 표시용이었고 구현 없이 폐기됐으므로 합치지 않는다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 상세 요구사항
- 공통 원칙: 1~7단계는 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 T1의 진행 테이블에 단계 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 이벤트 이름과 매개변수는 기존 GA4 이벤트 명명 방식을 따른다. 개인정보(이메일·실명)는 넣지 않는다.
- 연출 구간 소요 시간을 계산할 수 있도록 시작·7단계 완료 이벤트에 시각이 남아야 한다.
- 카즈하 확인: 서버 조회 키 보류 이슈(`20260924_0913`의 폐기 사유)가 이 전송에 영향을 주는지 확인한다.

## 구현 계획
기존 이벤트 전송 경로 확인 → 이벤트 정의 → 각 단계 완료 지점에 연결 → GA4 디버그 뷰로 확인.

## 완료 조건
- 테스트 계정으로 전체 흐름을 진행하면 GA4 디버그 뷰에 시작·단계 1~7·퀘스트 완료·보상 이벤트가 순서대로 보인다.
- 건너뛰기 흐름에서 건너뛰기 이벤트가 보인다.
- 이벤트 매개변수에 개인정보가 없다.
