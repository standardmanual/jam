# [Feature] 온보딩 퀘스트 단계별 진입·완료·건너뛰기 이벤트를 GA4로 보낸다 (T9)

## 핵심 요약
- 요구사항: 퀘스트 시작, 단계별 완료(1~7), 건너뛰기 이벤트를 GA4로 전송한다. 실제 연동 완료(퀘스트 완료)와 보상 지급은 서버 사건이라 DB 시각으로 측정한다(사용자 결정 1). 관리자 미리보기 중에는 보내지 않는다.
- 구현 계획: 기존 GA4 이벤트 전송 방식(예: `first_badge_earned`, `jam-web/src/lib/strava/sync.ts` L191)을 따른다.
- 관련 파일: GA4 이벤트 유틸, N1~N5·T2c~T5b·T8 각 단계 완료 지점(홈·인벤토리·드랍·믹서·미션 화면에 흩어져 있다), `docs/tickets/p3-low/20260924_0913_Admin_대시보드-가입-온보딩-지표-GA4-연동.md`(참고, 범위 다름)

## 배경 / 문제 정의
성공 기준(완료율, 단계별 이탈, 소요 시간)을 재려면 단계별 이벤트가 필요하다. 기존 티켓 `20260924_0913`은 어드민 대시보드 표시용이었고 구현 없이 폐기됐으므로 합치지 않는다. 결정 번복(2026-09-28)으로 단계 완료 지점이 퀘스트 전용 화면 한 곳이 아니라 홈(sync)·인벤토리(bag)·드랍(pickup·drop)·믹서(mix_fail·mix_success)·미션(browse) 다섯 개 실제 화면으로 흩어진다(결정 14·18) — 이벤트 삽입 지점도 그만큼 늘어난다. 기획 전문과 결정 이력은 상위 티켓 `20260927_2123`에 있다.

## 사용자 결정 (2026-09-28, 카리나 코드 확인 후)
1. **완료·보상은 DB 시각으로 측정한다.** GA4에는 화면에서 일어나는 시작·1~7단계 완료·건너뛰기만 보낸다. 퀘스트 완료와 보상 지급은 서버에서 일어나므로(연동 직후 첫 동기화·수동 동기화·7단계 기록·건너뛰기 네 경로) GA4로 보내지 않고, 이미 기록되는 `user_onboarding_quests.completed_at`·`reward_granted_at`과 `user_activity_badges.triggered_by = 'onboarding_quest'`로 집계한다. 미채택: 응답에 실어 화면에서 전송(연동 직후 경로가 서버 리다이렉트라 전달이 복잡), GA4 Measurement Protocol(새 API 비밀 값 발급·Vercel 등록 필요).
2. **시작 = 0/7 카드를 처음 본 순간.** 홈에서 진행 중·0단계 완료 상태의 퀘스트 카드가 처음 렌더될 때 한 번 보낸다(브라우저 `localStorage` 표시로 중복 방지). 「카드는 봤지만 1단계도 안 한」 이탈을 잰다.

### 카리나가 확인한 코드 사실 (2026-09-28)
- GA4 전송은 브라우저 전용이다: `jam-web/src/lib/analytics/gtag.ts` L30 `trackEvent(eventName, params)`(`sendGAEvent` 래퍼, 측정 ID 없으면 무시, `environment` 자동 첨부). 서버 전송 경로는 없다.
- 명명·문서 선례: `docs/service/prd/analytics/GA4_EVENTS.md` L32~46 이벤트 표(snake_case, 예 `first_badge_earned`·`item_pickup`).
- 카즈하 확인 항목(`20260924_0913` 보류 사유)은 GA4 **Data API 조회용** 서비스 계정 키를 Vercel에 둘지의 문제라, 브라우저 **이벤트 전송**에는 영향이 없다(카리나 확인).
- 관리자 미리보기(N5a) 중의 단계 기록은 `POST /api/onboarding-quest/step`·`/skip`이 `preview: true`를 돌려준다. 퍼널 오염을 막기 위해 이 응답에서는 이벤트를 보내지 않는다. 홈 카드도 미리보기에서 만든 상태(`resolvePreviewCard`, `jam-web/src/lib/onboarding-quest/preview.ts` L65)면 시작 이벤트를 보내지 않는다.
- 단계 기록 호출부(모두 `if (!res.ok) throw` 뒤가 성공 지점): `jam-web/src/app/(main)/OnboardingSyncButton.tsx` L45~50, `jam-web/src/app/(main)/inventory/QuestBagGrid.tsx` L36~41, `jam-web/src/app/(main)/drops/QuestPickupScene.tsx` L57~62·L82~87, `jam-web/src/app/(main)/combine/CombineClient.tsx` L252~257·L278·L285, `jam-web/src/app/(main)/missions/MissionsBrowseTracker.tsx` L17. 건너뛰기: `jam-web/src/app/(main)/OnboardingQuestSkipSheet.tsx` L30~31.

## 상세 요구사항
- 공통 원칙: 연출용 데이터다. `inventory_items`·`poi_drops`·`badges`·`user_activity_badges`·`point_transactions`에 행을 만들지 않는다. 서버에는 `user_onboarding_quests.step_progress`에 단계 완료만 기록한다.
- 연출용 아이템·레시피는 실제 카탈로그의 기존 아이템·레시피(이름·이미지)를 빌려 쓴다. 안내 문구는 중립 톤이며 코치마크·설명 팝업은 쓰지 않는다.
- 이벤트 이름과 매개변수는 기존 GA4 이벤트 명명 방식을 따른다. 개인정보(이메일·실명)는 넣지 않는다.
- 연출 구간 소요 시간을 계산할 수 있도록 시작·7단계(`browse`) 완료 이벤트에 시각이 남아야 한다.
- 단계 완료 지점이 화면마다 다르므로(N1의 단계→화면 지도), 각 실제 화면의 단계 기록 호출부(`POST /api/onboarding-quest/step` 성공 시점)에 이벤트를 붙인다 — 화면 5곳(홈·인벤토리·드랍·믹서·미션)을 모두 훑어야 누락이 없다.
- 카즈하 확인: 서버 조회 키 보류 이슈(`20260924_0913`의 폐기 사유)가 이 전송에 영향을 주는지 확인한다.

## 구현 계획
### 이벤트 정의
| 이벤트명 | 트리거 | 파라미터 |
|---|---|---|
| `onboarding_quest_start` | 홈 퀘스트 카드가 `in_progress`·`done === 0`으로 처음 렌더(미리보기 아님, `localStorage` 중복 방지) | — |
| `onboarding_quest_step_complete` | 단계 기록 API 성공 응답이 `alreadyDone: false`이고 `preview`가 아님 | `step`(단계 키), `step_index`(1~7) |
| `onboarding_quest_skip` | 건너뛰기 API 성공 응답이 `preview`가 아님 | `step`(건너뛴 시점의 다음 단계 키), `step_index` |

개인정보 없음. 시각은 GA4 이벤트 타임스탬프로 남는다(시작→7단계 소요 시간 계산 가능).

### 파일 단위 계획 (예상 10개 파일·약 200줄 — 테스트 포함)
1. `jam-web/src/lib/onboarding-quest/analytics.ts`(신규): 이벤트 이름 상수, 순수 판정 `shouldTrackStepComplete(response)`(`alreadyDone`·`preview` 제외), `trackQuestStepComplete(step, response)`, `trackQuestSkip(step, response)`, `trackQuestStartOnce()`(`localStorage` try/catch 중복 방지).
2. 단계 기록 호출부 6곳(위 「코드 사실」 목록): 성공 지점에서 응답 JSON을 읽어 `trackQuestStepComplete` 호출. 기존 오류 처리·흐름은 바꾸지 않는다.
3. `jam-web/src/app/(main)/OnboardingQuestSkipSheet.tsx`: 성공 시 `trackQuestSkip`. 건너뛴 시점의 단계 키가 필요하면 `OnboardingQuestCard.tsx`에서 prop으로 넘긴다.
4. `jam-web/src/lib/onboarding-quest/status.ts`·`preview.ts`: `in_progress` 상태에 미리보기 여부(`preview?: true`)를 싣는다(`resolvePreviewCard`만 채운다).
5. `jam-web/src/app/(main)/OnboardingQuestCard.tsx` + 신규 `jam-web/src/app/(main)/QuestStartTracker.tsx`(`'use client'`, `return null`, `HomeViewTracker` 패턴): `done === 0`이고 미리보기가 아니면 마운트.
6. `docs/service/prd/analytics/GA4_EVENTS.md` 이벤트 표에 3종 추가, 완료·보상은 DB로 잰다는 문단 추가.
7. 테스트: `jam-web/src/lib/onboarding-quest/__tests__/analytics.test.ts`(판정 함수·중복 방지), 카드 테스트(미리보기면 트래커 미마운트).
