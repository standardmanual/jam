# [UI] 홈 카드 세 곳에 복제된 칩 라벨 마크업을 공용 컴포넌트로 뽑아낸다

> **연결 메모 (2026-09-30 티켓 20260930_1451 사용자 결정):** 20260930_1453(홈피드 카드 표현 형식 리뉴얼) 구현 뒤로 미룬다. 리뉴얼 전에 고치면 다시 뜯긴다.
>
> **연결 메모 (2026-09-30 티켓 20260930_1453 설계 결정 15):** 1453-b 구현 조각에 흡수한다(MODULAR `LabelChip` 신설, 사용자 승인).

## 핵심 요약
- 요구사항: `TodayStatusStrip.tsx`의 `CellLabel`, `TodayCardStack.tsx`의 `TemplateChip`, `OnboardingQuestCard.tsx`의 칩이 같은 인라인 클래스(`bg-surface text-text` + `text-[length:var(--text-caption)] font-bold uppercase px-2.5 py-1.5 rounded-[var(--radius-tags)]`)를 반복한다. 하나로 모은다.
- 구현 계획: MODULAR 등재 여부(서비스 전용 유틸 vs 디자인 시스템 컴포넌트)를 채원이 먼저 판정한다.
- 관련 파일: `jam-web/src/app/(main)/TodayStatusStrip.tsx`(`CellLabel`), `jam-web/src/app/(main)/TodayCardStack.tsx`(`TemplateChip`), `jam-web/src/app/(main)/OnboardingQuestCard.tsx`

## 배경 / 문제 정의
티켓 20260927_2133(온보딩 퀘스트 홈 카드) 채원 사전 판정과 사후 리뷰가 세 번째 반복을 MODULAR 승격 후보로 지목했다(범위 밖 발견물).

## 상세 요구사항
- 세 곳의 화면 결과는 바뀌지 않는다(픽셀 동일).
- 공용화 위치는 채원 판정을 따른다. MODULAR에 넣으면 Story를 함께 만든다.

## 구현 계획
채원 사전 판정(ds 연결 범위 포함) → 구현 → Story 동반 확인.

## 완료 조건
- 세 파일이 같은 칩 컴포넌트(또는 유틸)를 쓰고, 인라인 클래스 복제가 남지 않는다.
- 홈 화면 세 카드의 칩 모양이 변경 전과 같다(스크린샷 대조).
- `scripts/verify.sh`가 통과한다.
