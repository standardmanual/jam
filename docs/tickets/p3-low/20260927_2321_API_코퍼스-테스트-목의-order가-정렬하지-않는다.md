# [API] 코퍼스 테스트 목의 `.order()`가 정렬하지 않아 정렬 의존 동작을 검증할 수 없다

## 핵심 요약

- 요구사항: `content-corpus.test.ts`의 배지 테이블 목은 `.order()`를 정렬 없이 통과시킨다. `listActiveBadgeIds`는 실제로 `.order('id', { ascending: true })` 뒤 `.range()`로 페이지를 나누므로, 목이 입력 순서를 그대로 자르면 「정렬된 뒤 페이지를 나눈다」는 전제를 검증하지 못한다.
- 구현 계획: 목의 `.order(column, { ascending })`가 인자대로 정렬한 뒤 `.range()`가 자르도록 바꾼다. 픽스처를 섞은 순서로 넣어 반환 순서가 `id` 오름차순인지 확인하는 테스트를 더한다. 테스트가 결함을 드러내면 같은 티켓에서 고친다.
- 관련 파일: `jam-web/src/lib/content-corpus/__tests__/content-corpus.test.ts` 약 62~79행(`activeFilterChain`), `jam-web/src/lib/content-corpus/active.ts` 약 151~179행(`listActiveBadgeIds`)

## 배경 / 문제 정의

티켓 20260927_2151(활성 배지 ID 1,000행 페이지 경계 테스트) 민지 게이트의 범위 밖 발견물 `[정확성/참고]`이다. 2151의 완료 조건(ID를 빠짐없이 한 번씩 돌려준다)은 순서와 무관한 집합 비교로 충족했으나, 이 목으로는 정렬에 기대는 로직(페이지 사이 중복·누락이 정렬 안정성에 달린 경우 등)을 검증할 수 없다.

## 완료 조건

- 목의 `.order()`가 열·방향 인자대로 정렬하고, 섞인 픽스처에서 `listActiveBadgeIds`가 `id` 오름차순으로 돌려주는 테스트가 있다.
- `scripts/verify.sh`가 통과한다.
