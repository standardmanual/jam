# [Service] 퀘스트 미리보기 경로에도 어드민 이중 방어(proxy 1차)를 적용한다

## 핵심 요약
- 요구사항: `/onboarding-quest/preview`가 기존 어드민 화면처럼 `proxy.ts` 1차 방어 + 페이지 `getAdminUser()` 2차 방어를 갖게 한다.
- 구현 계획: `jam-web/src/proxy.ts` L84 부근 어드민 경로 판정에 미리보기 경로를 추가하거나, 미리보기를 `/admin/` 아래로 옮기는 안 중 하나를 고른다.
- 관련 파일: `jam-web/src/proxy.ts`(L84 `pathname.startsWith('/admin')`), `jam-web/src/app/(main)/onboarding-quest/preview/page.tsx`

## 배경 / 문제 정의
티켓 20260928_0058 게이트 리뷰(민지)의 범위 밖 발견물이다. 기존 어드민 페이지는 모두 proxy + 페이지 이중 방어인데, 미리보기는 페이지 한 겹뿐이다. 미리보기는 연출 데이터만 보여 주고 DB에 쓰지 않아 노출 위험은 낮지만, 방어 방식의 비대칭을 없앤다.

## 상세 요구사항
- 관리자가 아닌 요청은 proxy 단계에서 막힌다.
- 관리자 계정의 미리보기 동작은 바뀌지 않는다.

## 구현 계획
두 안 중 채원·민지 의견을 받아 고른다: (a) proxy 판정에 경로 추가 (b) 미리보기 경로를 `/admin/onboarding-quest-preview`로 이동.

## 완료 조건
- 관리자가 아닌 계정으로 미리보기 경로에 접근하면 proxy 단계에서 막힌다(페이지 렌더 전).
- 관리자 계정은 기존처럼 미리보기를 실행한다.
- `scripts/verify.sh`가 통과한다.
