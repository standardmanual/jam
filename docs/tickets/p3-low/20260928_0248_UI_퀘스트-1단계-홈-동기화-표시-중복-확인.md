# [UI] 퀘스트 1단계 중 미연동 유저의 홈에 "동기화"가 두 곳에 보이는 것이 혼란스러운지 실사용으로 확인한다

## 핵심 요약
- 요구사항: 퀘스트 `sync` 차례인 Strava 미연동 유저의 홈에는 상단 바 중앙의 연출 「동기화」 버튼과 「오늘의 현황」 좌측 `strava_disconnected` 타일("Strava 동기화하면 시작해요")이 동시에 보인다. 두 요소가 같은 단어로 서로 다른 동작(연출 동기화 / 실제 Strava 연동)을 가리켜 혼란스러운지 실사용으로 확인하고, 혼란스러우면 처리안을 정한다.
- 구현 계획: 기능 스위치를 켠 staging 테스트 계정으로 1단계 홈을 확인 → 채원 판정 → 필요 시 수정 티켓 분리.
- 관련 파일: `jam-web/src/app/(main)/page.tsx`(`TopNav` 분기·`TodayStatusStrip` 렌더), `jam-web/src/app/(main)/TodayStatusStrip.tsx`(`strava_disconnected` 셀), `jam-web/src/app/(main)/OnboardingSyncButton.tsx`

## 배경 / 문제 정의
티켓 `20260927_2331`(T2c) 채원 사전 판정의 craftNotes와 민지 게이트 리뷰의 범위 밖 발견물이다. 결정 17("실제 홈의 실제 데이터는 손대지 않는다")의 직접적인 결과라 T2c 범위 밖으로 남겼다.

## 상세 요구사항
- 확인 시점: 온보딩 퀘스트 하위 티켓이 staging에 모인 뒤 기능 스위치를 켜고 실사용 확인할 때 함께 본다.
- 처리안 후보(채원 판정): 그대로 둠 / 퀘스트 진행 중에는 `strava_disconnected` 타일 문구를 바꿈 / 퀘스트 진행 중에는 타일을 숨김. 타일을 바꾸면 결정 17(실제 홈 데이터 무변경)과의 관계를 상위 티켓에 기록한다.

## 구현 계획
실사용 확인 → 채원 판정 → 수정이 필요하면 별도 티켓.

## 완료 조건
- 실사용 확인 결과와 처리안(그대로 둠 포함)이 이 티켓에 기록된다.
