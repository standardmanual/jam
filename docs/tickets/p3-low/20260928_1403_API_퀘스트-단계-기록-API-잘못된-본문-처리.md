# [API] 퀘스트 단계 기록 API가 형식이 깨진 요청 본문에 예외를 그대로 던지지 않고 400으로 응답하게 한다

## 핵심 요약
- 요구사항: `POST /api/onboarding-quest/step`의 `await request.json()`에 오류 처리가 없어, 형식이 깨진 JSON 본문이 오면 예외가 그대로 던져져 500이 된다. 같은 계열의 관리자 미리보기 API(`/api/admin/onboarding-quest/preview`)는 `.catch(() => null)`로 처리한다. 같은 방식으로 맞추고 400 `INVALID_STEP`으로 응답한다.
- 구현 계획: `request.json()`에 `.catch(() => null)`을 붙이고 본문이 없으면 400을 돌려준다. 테스트 1건을 추가한다.
- 관련 파일: `jam-web/src/app/api/onboarding-quest/step/route.ts` L31, 참고 `jam-web/src/app/api/admin/onboarding-quest/preview/route.ts`

## 배경 / 문제 정의
티켓 `20260928_1335`(N5a) 게이트 리뷰에서 민지가 올린 범위 밖 발견물이다([참고]). 정상 클라이언트는 항상 올바른 본문을 보내므로 사용자 영향은 없고, 서버 로그에 불필요한 예외가 남는 수준이다.

## 완료 조건
- 형식이 깨진 본문 요청에 400이 돌아오고 예외 로그가 남지 않는다.
