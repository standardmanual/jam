# [Service] 퀘스트 단계 기록 응답의 JSON 해석이 실패해도 오류 토스트를 띄우지 않게 한다

## 핵심 요약
- 요구사항: T9(`20260927_2132`)가 단계 기록 호출부 6곳의 성공 지점에 GA4 계측용 `await res.json()`을 새로 넣었다. 해석이 실패하면 서버에는 단계가 이미 기록됐는데도 catch 블록이 네트워크 오류로 처리해 오류 토스트를 띄우고 연출 흐름이 멈춘다. 서버는 항상 `NextResponse.json`으로 응답하므로 가능성은 매우 낮다. `res.json().catch(() => null)`로 바꾸고, `trackQuestStepComplete`가 null 응답이면 전송하지 않게 한다.
- 구현 계획: 호출부 6곳의 `await res.json()`을 안전 해석으로 바꾼다 → `shouldTrackStepComplete(null)` false 테스트 추가.
- 관련 파일: `jam-web/src/app/(main)/OnboardingSyncButton.tsx`, `jam-web/src/app/(main)/inventory/QuestBagGrid.tsx`, `jam-web/src/app/(main)/drops/QuestPickupScene.tsx`(2곳), `jam-web/src/app/(main)/combine/CombineClient.tsx`(2곳), `jam-web/src/app/(main)/missions/MissionsBrowseTracker.tsx`, `jam-web/src/lib/onboarding-quest/analytics.ts`

## 배경 / 문제 정의
T9 게이트 리뷰(민지)의 WARN 사유 중 하나다. 계획서가 지시한 구현이라 스펙 위반은 아니지만 새로 생긴 실패 지점이다.

## 완료 조건
- 성공 응답(2xx)의 본문 해석이 실패해도 오류 토스트가 뜨지 않고 연출이 이어진다. GA4 이벤트는 보내지 않는다.
