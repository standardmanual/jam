# [Infra] 서비스 전용 카드의 레이아웃 회귀(버튼 늘어남·정렬 어긋남)를 게이트 리뷰 전에 잡을 검증 수단을 정한다

## 핵심 요약
- 요구사항: 티켓 20260928_1537에서 홈 퀘스트 카드 CTA 버튼이 flex-col 카드의 기본 stretch로 카드 폭 전체로 늘어났는데, verify(lint·typecheck·test)는 모두 통과했고 게이트 리뷰(민지)가 수동으로 재현해서야 잡혔다. 테스트가 `renderToStaticMarkup` 정적 렌더만 쓰고, 서비스 전용 컴포넌트(`src/app/(main)/`)는 Storybook 대상도 아니라 CSS 레이아웃을 검증하는 단계가 없다.
- 구현 계획: 대안(브라우저 렌더 스크린샷·요소 폭 단언 E2E, 서비스 카드용 Storybook 스토리 + 시각 회귀, 채원① 판정 시 레이아웃 전제를 실측하는 절차 추가)의 비용을 비교해 결정한다. 상호작용 테스트 환경 티켓 20260928_1436과 도구가 겹치면 함께 결정한다.
- 관련 파일: `jam-web/src/app/(main)/OnboardingQuestCard.tsx`(L43 `CARD_CLASS`, `CTA_ROW_CLASS`), `jam-web/src/app/(main)/OnboardingQuestCard.test.tsx`, 관련 티켓 `docs/tickets/p3-low/20260928_1436_Infra_퀘스트-클라이언트-상호작용-테스트-환경.md`

## 배경 / 문제 정의
민지 게이트 리뷰 범위 밖 발견물(`[테스트체계/참고]`, 티켓 20260928_1537 재판정). 채원 사전 판정도 "Button은 inline-flex라 카드 폭에 맞춰 늘어나지 않는다"는 잘못된 전제를 담았지만 이를 확인할 단계가 없었다.

## 완료 조건
- 검증 방식이 결정돼 티켓에 근거와 함께 기록돼 있고, 도입하면 `OnboardingQuestCard`의 CTA 버튼이 카드 폭보다 좁다는 단언이 자동 검사에 포함돼 있다.
