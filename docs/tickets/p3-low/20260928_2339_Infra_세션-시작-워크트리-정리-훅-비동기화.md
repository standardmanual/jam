# [Infra] 세션 시작의 워크트리 정리 훅이 최악 19초 걸리고 제거 로그가 매 세션 컨텍스트를 차지한다

## 핵심 요약
- 요구사항: 세션 시작 훅 중 워크트리 정리(`scripts/workspace-setup.sh cleanup`)가 세션 시작을 막지 않고, 그 출력이 세션 컨텍스트에 실리지 않게 한다.
- 구현 계획: 경미 수정(0.1절). `.claude/settings.json` 해당 훅에 `"async": true`를 주고 출력은 버린다. `docs/agents/team-operations.md` 「워크트리 수명」 3번에 한 줄 덧붙인다.
- 관련 파일: `.claude/settings.json` L80-84(SessionStart 세 번째 훅), `docs/agents/team-operations.md` L162-164

## 배경 / 문제 정의
2026-09-28 `/doctor` 점검(최근 세션 50개, 7.1일)에서 SessionStart 훅 4개가 모두 동기식이고 최악 18.9초(startup)·18.4초(resume), 보통 0.9초가 걸렸다. 직접 재 보니 현황판 0.40초, 예약 리포트 확인 0.09초로 빨랐다. 남은 워크트리 정리는 `cleanup_worktrees()`의 `git fetch origin staging`(네트워크)과 워크트리 삭제를 하므로 느린 쪽이다(추정). 또 이 훅이 출력하는 "제거(staging에 병합됨)…" 줄이 많을 때 19줄에 이르러, 매 세션 약 0.4k 토큰(추정)을 차지했다.

## 완료 조건
- 다음 세션 시작 때 "제거(…)" 로그가 컨텍스트에 나오지 않는다.
- 세션 시작 훅 최악 소요가 워크트리 정리 때문에 늘지 않는다(다음 `/doctor`의 훅 집계로 확인).
- `node scripts/check-contract.mjs` 통과(`hooks.SessionStart`에 `workspace-setup.sh`가 그대로 있음), `node scripts/gen-team-doc.mjs` 생성 구간 최신.

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약
- 정리 훅 명령을 `bash "$CLAUDE_PROJECT_DIR/scripts/workspace-setup.sh" cleanup >/dev/null 2>&1 || true`로 바꾸고 `"async": true`를 추가했다. 다른 세 훅(현황판·리포트 확인·hooksPath)은 동기식 그대로다.
- `team-operations.md` 「워크트리 수명」 3번에 백그라운드 실행과 이유, 결과 확인 방법을 적었다.
- 설치된 CLI(2.1.283) 바이너리에 비동기 훅 필드(`asyncRewake` 등)가 있음을 확인했다. 필드를 모르는 버전이면 무시되어 종전처럼 동기로 돈다(악화 없음).
