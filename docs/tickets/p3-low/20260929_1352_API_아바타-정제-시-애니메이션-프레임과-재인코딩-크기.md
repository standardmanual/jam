# [API] 아바타 정제에서 애니메이션 WebP 처리와 재인코딩 뒤 크기를 정한다

## 핵심 요약

- 요구사항: 티켓 20260929_1317의 `sanitizeAvatarImage`는 애니메이션 WebP·다중 프레임 PNG를 첫 프레임
  하나로 재인코딩하고, 5MB 제한은 재인코딩 전 `file.size`로만 검사한다(민지 범위 밖 발견물). 두 동작을
  의도로 확정할지, 애니메이션 유지(`animated: true`)나 재인코딩 뒤 크기 검사·리사이즈를 넣을지 정한다.
- 구현 계획: 결정 후 작성한다.
- 관련 파일: `jam-web/src/lib/avatarImage.ts`(`sanitizeAvatarImage`),
  `jam-web/src/app/api/profile/avatar/route.ts`(`MAX_SIZE` 검사 부근)

## 배경 / 문제 정의

- 현재 영향은 작다. 프로필 사진은 원형 썸네일로만 쓰이고, quality 90 재인코딩은 대체로 원본보다 작다.
- 아바타 표시 크기에 맞춘 리사이즈를 넣으면 저장 용량과 전송량도 함께 줄일 수 있다.

## 완료 조건

- 애니메이션 입력의 처리 방식(유지 또는 첫 프레임)과 재인코딩 뒤 크기 상한이 코드 주석과
  `docs/service/SERVICE_OPERATIONS.md` API 표에 적혀 있고, 각각 테스트로 확인된다.
