# [Service] 온보딩 완료 보상이 배지만 지급되고 포인트·피드가 빠지는 경로의 복구 방식과 반복 재시도 로그를 정리한다

## 핵심 요약
- 요구사항: 완료 보상 지급에서 배지는 발급됐지만 포인트·피드가 빠지는 두 경로의 복구 방식을 정하고, 영구적 오류일 때 매 호출마다 선점·롤백과 오류 로그가 반복되는 것을 줄인다.
- 관련 파일: `jam-web/src/lib/onboarding-quest/completion.ts` L76-84(포인트 실패 방침 주석), L139-143(배지 정보 조회 실패 시 조기 반환), L194-197(재시도 분기), `jam-web/src/lib/points/index.ts` L47-70

## 배경 / 문제 정의
티켓 20260929_1634(완료 보상 재시도) 게이트에서 민지가 남긴 범위 밖 발견물 세 건(모두 참고)이다.
1. 배지 발급 성공 뒤 `badges` 조회가 실패하면 포인트·피드 없이 조기 반환하고 `reward_granted_at`은 유지돼 재시도되지 않는다. 1634가 기록한 "포인트 실패는 수동 재지급" 방침 주석은 이 경로를 다루지 않는다.
2. 배지는 있고 포인트만 실패한 경우는 1634에서 수동 재지급(`engine_decision_log`의 `point_award_failed`)으로 정했다. 자동 복구는 원장 멱등 키 없이는 100P 이중 지급 위험이 있어 제외됐다(1634 아현 선택지 C).
3. 배지 행 부재 같은 영구적 FK 오류면 동기화·단계 기록 호출마다 선점과 롤백을 반복하며 `console.error`가 쌓인다.
4. (2026-09-29 후속 `/jam-ship` 민지 모드 ② 참고) 배지 insert가 실제로는 커밋됐는데 응답만 유실돼 롤백되면, 다음 재시도에서 insert가 23505를 받아 포인트·피드를 건너뛰고 끝난다(`completion.ts` L110-121). 누락 방향이라 보안 위험은 아니지만 1번·2번과 같은 "배지만 있음" 상태를 만든다. 재시도 횟수 제한·영구 실패 감지도 같은 발견물의 범위 밖 제안이다.

## 완료 조건
- 1번 경로의 처리 방침(수동 재지급 대상에 포함 또는 재시도)이 정해져 코드나 주석에 반영돼 있다.
- 2번 자동 복구를 할지 결정이 기록돼 있고, 한다면 원장 멱등 키 기반으로 이중 지급이 불가능함을 테스트로 보인다.
- 3번의 반복 로그가 줄거나(예: 영구 오류 코드는 재시도 대상에서 제외) 그대로 두는 사유가 기록돼 있다.
