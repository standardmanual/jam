# [BadgeEngine] 유효기간 판정이 값이 없으면 조용히 통과시키고, 테스트가 select 누락을 잡지 못한다

## 핵심 요약
- 요구사항: POI 매칭 발급 경로의 유효기간 필터가 select에서 `valid_from`·`valid_until`이 빠지는 회귀를 테스트로 잡을 수 있게 한다.
- 구현 계획: 하네스 페이크가 `badges` 조회의 select 컬럼 목록대로만 필드를 돌려주게 하거나, select 문자열에 두 컬럼이 들어 있는지 호출 기록으로 대조하는 테스트를 더한다. `isWithinValidPeriod`의 입력 처리(값 없음·파싱 불가 → 기간 안)는 그대로 둘지 함께 판단한다.
- 관련 파일: `jam-web/src/lib/strava/__tests__/sync-poi-checkin-valid-period.test.ts` L97-135(페이크 supabase), `jam-web/src/lib/badge-engine/validPeriod.ts` L15-19, `jam-web/src/lib/strava/sync.ts` 연결 배지 조회(select에 `valid_from, valid_until`), `jam-web/src/app/api/admin/simulate/route.ts` POI 배지 조회

## 배경 / 문제 정의
티켓 `20260930_0015` 게이트 리뷰(민지)의 범위 밖 발견물 2건을 묶었다([정확성/참고] 둘).

1. 새 하네스의 페이크 supabase는 select 컬럼 목록과 무관하게 `badges` 전체 필드를 돌려준다. 그래서 select에서 두 컬럼이 빠져도 테스트는 통과한다.
2. `isWithinValidPeriod`는 값이 없거나(undefined) 파싱할 수 없으면 기간 안으로 판정한다. 기존 섀도우밴 하네스 호환을 위한 선택이고 DB 컬럼은 `timestamptz`라 파싱 불가는 실제로 생기지 않는다.

두 가지가 겹치면, 누군가 select에서 두 컬럼을 빼는 순간 유효기간 필터가 조용히 꺼지고 테스트도 그대로 통과한다. 현재 select 문자열은 정상이다(2026-09-30 코드 대조).

## 완료 조건
- `sync.ts`의 연결 배지 select에서 `valid_from` 또는 `valid_until`을 빼면 실패하는 테스트가 있다.
- 어드민 시뮬레이터 조회도 같은 보호를 받거나, 받지 않는 이유가 기록된다.
