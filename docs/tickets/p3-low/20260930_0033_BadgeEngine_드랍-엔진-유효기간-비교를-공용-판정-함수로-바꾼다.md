# [BadgeEngine] 드랍 엔진·앰비언트 드랍의 유효기간 문자열 비교를 공용 판정 함수로 바꾼다

## 핵심 요약
- 요구사항: `drop-engine`·`ambient-drop`의 인라인 유효기간 비교(ISO 문자열 대소 비교)를 `badge-engine/validPeriod.ts`의 `isWithinValidPeriod`(시각 값 비교, 경계 포함)로 바꾼다. 동작은 바뀌지 않아야 한다.
- 구현 계획: 두 곳의 `if (b.valid_from && b.valid_from > now)`·`if (b.valid_until && b.valid_until < now)`를 `isWithinValidPeriod(b, now)`로 교체하고, 기존 드랍 테스트가 그대로 통과하는지 확인한다. `now`가 문자열인 곳은 `Date`로 바꿔 넘긴다.
- 관련 파일: `jam-web/src/lib/drop-engine/index.ts` L258-259(`droppable` 필터), `jam-web/src/lib/ambient-drop/index.ts` L200-201(`badgesByRarity` 구성), `jam-web/src/lib/badge-engine/validPeriod.ts`

## 배경 / 문제 정의
티켓 `20260930_0015` 게이트 리뷰(민지)의 범위 밖 발견물이다([구조/참고]). `20260930_0015`에서 POI 매칭 발급 경로용 공용 판정 함수를 만들었지만, 티켓이 범위 밖으로 정해 드랍 두 곳은 그대로 뒀다.

드랍 두 곳은 DB 값(`+00:00` 표기)과 `toISOString()`(`Z` 표기)을 문자열로 비교한다. 날짜·시각 부분이 앞에 오므로 지금 값에서는 대체로 맞게 동작하지만, 표기가 다른 두 문자열의 대소 비교라 오프셋이 섞이거나 초 단위 경계에서 어긋날 수 있다. 같은 조건을 여러 방식으로 판정하면 한쪽만 바뀌는 드리프트도 생긴다.

## 완료 조건
- 두 곳이 `isWithinValidPeriod`를 쓴다.
- 기존 drop-engine·ambient-drop 테스트가 모두 통과한다.
- 오프셋 표기가 다른 값(`+00:00`, `Z`)에서도 같은 판정을 내리는 테스트가 있다(공용 함수 테스트로 충분하면 그 사실을 기록한다).
