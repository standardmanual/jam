# [API] 받은 기획함 제출이 본문을 다 읽기 전에 Content-Length로 크기를 먼저 거절한다

## 핵심 요약

- 요구사항: `POST /api/admin/ops-inbox`가 `req.text()`로 본문을 모두 읽은 뒤에 1MB 상한을 검사한다. `Content-Length` 헤더가 1MB를 넘으면 읽기 전에 400으로 거절한다.
- 구현 계획: 헤더 값이 있으면 먼저 비교하고, 헤더가 없거나 거짓일 수 있으므로 읽은 뒤의 바이트 검사는 그대로 둔다.
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/route.ts`(83 부근 본문 읽기), 같은 폴더 `__tests__/route.test.ts`.

## 배경

2026-09-30 1816 게이트에서 민지가 찾았다(sideFindings 2, 성능/참고). Vercel 플랫폼 본문 상한(4.5MB)이 있어 실제 위험은 작다.

## 완료 조건

- `Content-Length`가 1MB를 넘는 요청은 본문을 읽지 않고 400이다(테스트).
- 헤더가 없는 요청은 지금처럼 읽은 뒤 바이트로 검사한다(테스트).
