# [Admin] 받은 기획함 목록이 요청마다 모든 항목 상태를 읽는 비용을 줄인다

> 민지 게이트 리뷰의 범위 밖 발견물(티켓 20260930_1817, 2026-09-30)이다.

## 핵심 요약

- 요구사항: `listOpsBundles`는 요청마다 모든 묶음의 항목 상태 행을 1000행씩 끝까지 받아 묶음 상태를 계산한다. 지금 규모(주 1~2묶음, 묶음당 최대 60항목)는 문제가 없지만 묶음이 쌓이면 읽는 행이 선형으로 는다. 묶음 수가 기준을 넘기 전에 DB 쪽 집계(뷰나 RPC로 묶음별 상태 개수)나 기간 제한을 검토한다.
- 구현 계획: 착수 때 관련 파일의 해당 함수를 열어 고친다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/query.ts:193`(`listOpsBundles`와 그 위 항목 상태 전량 조회), `jam-web/src/lib/admin/opsInbox/bundleStatus.ts`(`computeBundleStatus`), 운영툴 PRD §7.2

## 완료 조건

- 받은 기획함 목록 한 번에 읽는 항목 행 수가 묶음 수와 무관하게 상한 안에 있다(또는 착수 시 측정으로 필요 없다고 판단한 근거를 적고 닫는다). 탭 개수·정렬·50건 자르기 결과가 지금과 같다(기존 query 테스트 통과).
