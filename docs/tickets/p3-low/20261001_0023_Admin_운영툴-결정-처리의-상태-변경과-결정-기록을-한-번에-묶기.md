# [Admin] 운영툴 결정 처리에서 상태 변경과 결정 기록 저장을 한 번에 묶는다

> 민지 게이트 리뷰의 범위 밖 발견물(티켓 20260930_1818, 2026-10-01)이다.

## 핵심 요약

- 요구사항: 승인·반려·일괄 승인·수정·되돌리기는 항목 상태 조건부 update와 결정 기록 insert를 따로 부른다. 둘 사이에서 함수가 끊기면(시간 초과·프로세스 종료) 결정 기록 없이 상태만 바뀐 항목이 남고, insert가 실패했을 때의 되돌림도 실행되지 않는다. 1816 제출 라우트와 같은 구조다. 두 쓰기를 SQL 함수(RPC) 하나로 묶어 원자적으로 만든다.
- 구현 계획: 착수 때 관련 파일의 해당 구간을 열어 고친다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/decide.ts:180-205`(승인), `:292-320`(반려)와 일괄 승인·수정·되돌리기의 같은 구간, 새 마이그레이션(번호는 착수 때 원격 staging 기준으로 확인), 운영툴 PRD §7.3·§11.3

## 완료 조건

- 상태 변경과 결정 기록이 한 SQL 함수 안에서 함께 반영되거나 함께 취소된다. 결정 기록 insert가 실패하는 경우를 모의한 테스트에서 항목 상태가 바뀌지 않는다. 기존 decide·라우트 테스트가 통과한다. DB 변경은 사용자 승인 뒤 메인 세션이 실행한다.
