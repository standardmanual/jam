# [Infra] 조건 키 CHECK 마이그레이션의 되돌림 SQL을 다른 파일 참조 대신 리터럴로 적는다

> 민지 게이트 리뷰의 범위 밖 발견물(티켓 20261001_0633, 2026-10-01)이다.

## 핵심 요약

- 요구사항: 203의 `-- 되돌림 SQL`이 「201 파일의 블록을 재실행」이라는 참조와 사전 조회 쿼리로만 적혀 있고, 실행할 ALTER 문이 없다. 201도 199를 같은 방식으로 참조한다.
  deploy-gate 표식 검사는 통과하지만, 롤백할 때 다른 파일의 줄 범위를 다시 찾아야 한다. 이후 CHECK 확장 마이그레이션은 되돌림 블록에 직전 키 배열의 ALTER 문을 그대로 적도록 규칙과 복사 원본을 고친다.
- 구현 계획: 착수 때 `db-migration-rules.md`의 되돌림 SQL 규칙에 한 줄을 더하고, 다음 CHECK 확장 마이그레이션부터 적용한다. 실행 이력이 있는 199~202 파일은 고치지 않는다. 203은 0633에서 201과 같은 참조 방식으로 작성했다.
- 관련 파일: `jam-web/supabase/migrations/203_condition_json_progress_keys.sql:170`, `jam-web/supabase/migrations/201_condition_json_drop_pickup_keys.sql`(되돌림 블록), `.claude/skills/jam-work/references/db-migration-rules.md`

## 완료 조건

- `db-migration-rules.md`에 「CHECK 재정의 마이그레이션의 되돌림 블록은 직전 상태로 돌리는 ALTER 문을 리터럴로 적는다」가 있다. 다음 CHECK 확장 마이그레이션이 이 규칙을 따른다.
