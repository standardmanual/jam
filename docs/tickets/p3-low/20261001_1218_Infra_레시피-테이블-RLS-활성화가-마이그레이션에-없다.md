# [Infra] 레시피 테이블의 RLS 활성화 문장이 저장소 마이그레이션에 없다

> 티켓 20261001_1157 게이트 리뷰(민지)의 범위 밖 발견물 `[참고/보안]`

## 핵심 요약

- 요구사항: 라이브 DB의 `public.combination_recipes`는 RLS가 켜져 있고 정책이 0개다(2026-10-01 11:40 KST 카리나 조회: `relrowsecurity = true`, `pg_policies` 0행).
  그런데 저장소 마이그레이션에는 이 테이블에 `ENABLE ROW LEVEL SECURITY`를 거는 문장이 없다. 형제 테이블 `combination_recipe_slots`는
  `180_combination_recipe_slots_rls.sql:20`이 켜고, 그 주석(12줄)이 「`combination_recipes`는 RLS를 켜고 정책을 만들지 않는 패턴」이라고만 적었다.
  저장소만으로 DB를 다시 만들면 RLS가 꺼진 채가 되어, anon·authenticated의 SELECT 권한으로 공개 전 레시피(티켓 20261001_1157)를 직접 읽을 수 있다.
- 구현 계획: `180_combination_recipe_slots_rls.sql`과 같은 모양의 재실행 가능한 마이그레이션 하나(`ALTER TABLE public.combination_recipes ENABLE ROW LEVEL SECURITY;`,
  정책 없음, 되돌림 SQL 주석)를 더한다. 라이브에는 이미 켜져 있어 실행해도 동작이 바뀌지 않는다.
- 관련 파일: `jam-web/supabase/migrations/180_combination_recipe_slots_rls.sql`(본보기), 새 마이그레이션(번호는 착수 때 원격 staging 기준).

## 완료 조건

- 새 마이그레이션이 `combination_recipes`의 RLS를 켜고, 되돌림 SQL이 있다.
- 적용 뒤 라이브 `relrowsecurity`가 그대로 `true`이고 정책 0개다.
