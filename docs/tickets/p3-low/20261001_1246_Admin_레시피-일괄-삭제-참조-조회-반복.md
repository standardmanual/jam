# [Admin] 레시피 일괄 삭제에서 막힌 레시피가 있으면 참조 조회가 레시피마다 다시 돈다

> 티켓 20261001_1200 게이트 리뷰(민지)의 범위 밖 발견물 `[성능/참고]`

## 핵심 요약

- 요구사항: `collectRecipeDeletionCandidates`(`jam-web/src/lib/admin/recipe-references.ts:133` 근처)는 전체를 한 번 세서 0건이 아니면 어느 레시피가 막혔는지 가리려고 한 건씩 다시 센다.
  일괄 삭제 상한이 200개라 최대 200회 추가 조회가 생긴다. 1200 이전에는 참조 조회 자체가 없었다. 지금 레시피는 3개라 실제 비용은 없다.
- 구현 계획: 배지 조회 한 번으로 `condition_json->recipe_first_success->>recipe_id` 값을 함께 받아 레시피별로 묶어 센다(분할 조회 유지).
- 관련 파일: `jam-web/src/lib/admin/recipe-references.ts`, `jam-web/src/lib/admin/__tests__/recipe-references.test.ts`.

## 완료 조건

- 막힌 레시피가 있어도 참조 조회 횟수가 대상 레시피 수와 무관하게 분할 묶음 수만큼만 나간다(테스트).
- 레시피 수가 수십 개를 넘기 전까지는 착수하지 않아도 된다.
