# [Admin] 프리셋 직렬화가 DB 비율 값을 검증하지 않고 캐스팅한다

## 핵심 요약

- 요구사항: `presetSerialize.ts`가 DB의 `stage_ratio`를 검증 없이 `as StageRatio`로 바꾼다. 티켓 20261001_1202에서 `resolveStageSize`가
  목록 밖 값에 오류를 내도록 바뀌어서, CHECK와 어긋난 행이 생기면 어드민 에셋 생성기 화면이 렌더 중 예외로 멈춘다.
- 구현 계획: 직렬화 단계에서 값을 `STAGE_RATIO_OPTIONS`(또는 같은 값 목록)와 대조하고, 목록 밖이면 그 프리셋을 목록에서 빼거나 「알 수 없는 비율」로
  표시해 화면 전체가 멈추지 않게 한다. 평소에는 DB CHECK가 막아 발생하지 않으므로 방어 코드다.
- 관련 파일: `jam-web/src/lib/asset-generator/presetSerialize.ts` 29·44줄(`row.stage_ratio as StageRatio`), 그 테스트,
  `jam-web/src/app/admin/asset-generator/assetGeneratorHelpers.ts` `resolveStageSize`(목록 밖 값 throw)

## 배경 / 문제 정의

- 티켓 20261001_1202 게이트 리뷰(민지) 범위 밖 발견물 [정확성/참고]이다. 마이그레이션 205로 CHECK가 4값이고 API가 같은 목록을 검증해 지금은 도달하지 않는다.

## 완료 조건

- DB에 목록 밖 비율 값을 가진 프리셋 행이 있다고 가정한 단위 테스트에서 직렬화가 예외를 던지지 않고, 그 행이 정한 방식(제외 또는 표시)으로 처리된다.
- 정상 4비율 행의 직렬화 결과는 바뀌지 않는다.
- `scripts/verify.sh`가 통과한다.
