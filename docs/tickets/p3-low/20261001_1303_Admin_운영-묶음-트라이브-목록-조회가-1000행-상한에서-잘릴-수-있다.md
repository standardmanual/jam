# [Admin] 운영 묶음 검증의 트라이브 목록 조회가 1000행 상한에서 잘릴 수 있다

> 출처: 티켓 20261001_1152 게이트 리뷰(민지) 범위 밖 발견물 `[성능/참고]`

## 핵심 요약

- 요구사항: 제출·수정 검증이 쓰는 트라이브 목록이 행 수와 상관없이 전부 읽히게 한다. 지금은 범위 없이 `select('id')`로 읽어, PostgREST 기본
  최대 행 수(1000)를 넘으면 목록이 잘리고 실제로 있는 트라이브를 「없는 트라이브」로 판정할 수 있다. 지금 트라이브 수로는 닿지 않는다.
- 구현 계획: 페이지를 나눠 끝까지 읽거나, 제출에 실린 `tribe_id`만 `in` 조건으로 조회해 있는지 본다. 같은 종류의 상한 문제는
  티켓 20260825_037(PostgREST 1000행 상한 일괄 점검)에서 다룬 방식과 맞춘다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/tribes.ts`(18행 `loadTribeIds`), 호출부 `jam-web/src/app/api/admin/ops-inbox/route.ts`·
  `jam-web/src/lib/admin/opsInbox/decide.ts`.

## 완료 조건

- 트라이브가 1000개를 넘는 상황(모킹)에서도 목록 끝쪽의 트라이브가 「있음」으로 판정된다(테스트).
- 제출과 수정이 여전히 같은 판정을 낸다(기존 테스트 통과).
