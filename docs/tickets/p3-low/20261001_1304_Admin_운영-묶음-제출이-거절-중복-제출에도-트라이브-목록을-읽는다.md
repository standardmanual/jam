# [Admin] 운영 묶음 제출이 거절되거나 중복인 제출에도 트라이브 목록을 매번 읽는다

> 출처: 티켓 20261001_1152 게이트 리뷰(민지) 범위 밖 발견물 `[성능/참고]`

## 핵심 요약

- 요구사항: 필수 형식 위반(400)·시간당 한도(429)·같은 `bundle_id` 확인(200·409)으로 끝나는 제출에서는 트라이브 목록을 읽지 않게 한다. 지금은
  1152 계획대로 조회가 이 판정들보다 앞에 있어, 저장하지 않을 제출에도 매번 `tribes`를 읽는다. 인증 뒤라 영향은 작다.
- 구현 계획: 라우트에서 fatal·한도·중복 판정을 먼저 하고, 저장할 제출에만 `loadTribeIds`를 부른다. 판정 순서가 바뀌어도 응답 코드와 저장
  여부가 지금과 같아야 한다(트라이브 조회 실패 시 500·미저장 포함).
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/route.ts`(102행 근처), `jam-web/src/app/api/admin/ops-inbox/__tests__/route.test.ts`,
  `docs/service/prd/ops-tool/PRD.md` §11.1(판정 순서).

## 완료 조건

- fatal·429·같은 본문(200)·다른 본문(409) 제출에서 트라이브 조회가 일어나지 않는다(테스트로 호출 횟수 확인).
- 저장하는 제출의 판정과 조회 실패 500은 지금과 같다(기존 테스트 통과). PRD §11.1의 순서 설명이 새 순서와 같다.
