# [API] 투데이 카드 자원 값 조회의 필요 이상 전달과 주석 정리

## 핵심 요약

- 요구사항: 티켓 20261001_1357(1453-b1) 게이트 리뷰의 범위 밖 발견물 2건을 정리한다.
  1. `resolved_mission`이 미션을 가리키는 자동 카드(`progress_nudge`·`location_trend`)에도 미션 노출 판정(숨김·잠금) 없이 실린다. `buildFacts('auto')`는
     기간만 쓰는데 `reward_points`·`reward_badge_count`·`image_url`까지 실려 서버에서 화면으로 필요 이상 전달된다. 값 자체는 미션 목록에 공개된
     종류라 민감도는 낮다(민지 [보안/참고]).
  2. `fetchMissionsById`·`fetchCollectionsById`의 주석은 「export하는 이유: 시험이 확인한다」인데 시험은 두 함수를 직접 import하지 않는다. 주석이 사실과
     다르고 export가 불필요하다(민지 [가독성/참고]).
- 구현 계획: 자동 카드에는 기간 칸만 싣거나, 미션 노출 판정을 거친 뒤 싣는다(어느 쪽인지 착수 때 정한다). 두 함수의 export와 주석을 정리한다.
- 관련 파일: `jam-web/src/lib/today/cards.ts` 147줄 부근(`resolved_mission` 싣기), 243·262줄(`fetchMissionsById`·`fetchCollectionsById`),
  `jam-web/src/lib/today/__tests__/cards-resources.test.ts`

## 배경 / 문제 정의

- 1357은 화면을 바꾸지 않는 조각이라 실린 값이 아직 그려지지 않는다. 그리는 조각(1453-b2~b5)이 머지되기 전에 정리하면 가장 싸다.
- 같은 리뷰의 「컬렉션 이름을 공개 전 필터 없이 읽는다」는 1453 확정 설계 11절의 b2~b5 메모로 넘겼다(그리는 쪽에서 판단).

## 완료 조건

- 자동 카드의 `resolved_mission`에 기간 외 값이 실리지 않거나, 미션 노출 판정을 거친 미션만 실린다(테스트).
- 두 함수의 export와 주석이 실제 사용과 맞는다.
- 기존 `cards-resources.test.ts`와 `scripts/verify.sh`가 통과한다.
