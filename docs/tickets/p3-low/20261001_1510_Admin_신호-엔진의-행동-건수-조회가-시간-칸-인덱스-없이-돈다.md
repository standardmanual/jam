# [Admin] 신호 엔진의 행동 건수 조회가 시간 칸 인덱스 없이 돈다

> 출처: 티켓 20261001_1155 게이트 리뷰(민지) 범위 밖 발견물 `[성능/참고]`

## 핵심 요약

- 요구사항: 「행동 횟수 급증」 신호가 쓰는 행동 건수 조회(지표 5종 × 최근 7일·직전 28일, 정확한 개수 세기 12회)가 시간 칸 단독 인덱스가 없는
  테이블에서 돈다(`poi_drops.dropped_at`·`picked_up_at`, `user_combine_success_logs`·`user_combine_fail_logs.attempted_at`,
  `user_mission_completions`·`user_item_book_completions.completed_at`). 테이블이 커지면 시간 초과로 이 신호만 「확인하지 못했어요」가 될 수 있다.
  2026-10-01 실DB 측정에서는 신호 전체 조회가 첫 호출 약 1.0초, 두 번째 0.25초였다(카리나, 티켓 1155 머지 전 확인). 지금은 문제가 없다.
- 구현 계획: 실행 계획(`EXPLAIN`)으로 순차 스캔 여부를 먼저 확인한다. 필요하면 시간 칸 인덱스를 더하거나(DB 변경, `db` 유형 규칙), 집계용 RPC
  하나로 묶는다. 측정 없이 인덱스부터 만들지 않는다.
- 관련 파일: `jam-web/src/lib/admin/opsSignals/load.ts`(250행 부근 행동 건수 조회), `jam-web/src/lib/admin/opsSignals/actionSpike.ts`.

## 완료 조건

- 행동 건수 조회의 실행 계획을 확인한 결과와, 조치했다면 조치 전후 소요 시간을 티켓에 남긴다.
- 조치한다면 「행동 횟수 급증」 판정 시험이 그대로 통과한다.
