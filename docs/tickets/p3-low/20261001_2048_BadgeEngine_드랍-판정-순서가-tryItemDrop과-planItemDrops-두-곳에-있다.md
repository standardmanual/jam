# [BadgeEngine] 드랍 판정 순서가 `tryItemDrop`과 `planItemDrops` 두 곳에 복제돼 있다

> 출처: 20261001_1219 게이트(민지) 범위 밖 발견물 [구조/참고].

## 핵심 요약

- 요구사항: `tryItemDrop`이 판정은 `planItemDrops`에 맡기고 쓰기만 하도록 합치거나, 둘의 판정 순서를 대조하는 테스트를 더한다. 합치는 쪽은 엔진 본체 변경이라 `engine` 유형이다(2026-10-01 사용자는 1219에서 엔진 본체 공용화를 고르지 않았으므로, 착수 전에 방향을 다시 확인한다).
- 구현 계획: 착수할 때 관련 파일을 읽고 파일 단위로 적는다.
- 관련 파일: `jam-web/src/lib/drop-engine/index.ts` 568행~(`tryItemDrop`), `jam-web/src/lib/drop-engine/preview.ts` 7행(머리 주석)·`planItemDrops`

## 배경 / 문제 정의

20261001_1219에서 시뮬레이터용 `planItemDrops`(쓰기 없음)를 `tryItemDrop`의 판정 순서를 따라 따로 만들었다. 대조 테스트는 엔진 구성 함수를 직접 부르는 기준 구현과 비교할 뿐 `tryItemDrop` 자체와는 대조하지 않아, `tryItemDrop`의 순서만 바뀌면 CI가 잡지 못한다(파일 머리 주석과 BADGE_ENGINE §3.7.2에만 의존).

## 완료 조건

- `tryItemDrop`의 판정 순서를 바꾸면 테스트가 실패해 시뮬레이터와 어긋남이 드러난다.
