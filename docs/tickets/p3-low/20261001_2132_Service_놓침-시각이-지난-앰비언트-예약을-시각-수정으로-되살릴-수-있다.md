# [Service] 「놓침」 시각이 지난 앰비언트 예약을 시각 수정으로 되살릴 수 있다

> 출처: 20261001_2051(1457-①) 게이트(민지) 범위 밖 발견물

## 핵심 요약

- 요구사항: 파생 상태가 `missed`(예정 시각 + 3시간 경과)인 예약의 시각 수정을 cron이 DB에 표시하기 전이라도 409로 거절한다(2026-10-01 사용자 결정 「막는다」). 다시 놓으려면 새로 등록한다.
- 구현 계획: 아래 「구현 계획」 표(파일 4개·약 40줄). 취소(`cancelScheduledAmbientDrop`)는 바꾸지 않는다.
- 관련 파일: `jam-web/src/lib/ambient-drop/scheduleStore.ts` 187행(`rescheduleAmbientDrop`), `jam-web/src/lib/ambient-drop/scheduleSpec.ts`(`ambientDropScheduleState`)

## 배경 / 문제 정의

DB 상태가 `scheduled`이면 파생 상태가 `missed`(예정 시각 + 3시간 경과, cron이 아직 표시 전)여도 `rescheduleAmbientDrop`이 통과해 예약이 되살아난다. 의도인지 정해지지 않았다.

cron은 매시 놓친 예약을 DB에 `missed`로 표시하므로, 예정 시각 + 3시간이 지난 뒤 다음 cron까지(보통 1시간 안쪽, cron이 멈추면 더 길게) 같은 「놓침」 예약이
고쳐지기도 하고 거절되기도 한다. 운영자가 볼 수 없는 cron 시각에 따라 결과가 갈리지 않도록 화면에 보이는 상태(파생 상태)를 기준으로 막는다.

## 완료 조건

- 파생 상태가 `missed`인 예약의 시각 수정 동작이 문서와 테스트로 정해져 있다.
- 화면 기준으로 「놓침」인 예약의 시각 수정은 cron 표시 여부와 관계없이 같은 409 문구로 거절된다(테스트).
- 취소 동작은 바뀌지 않는다.
