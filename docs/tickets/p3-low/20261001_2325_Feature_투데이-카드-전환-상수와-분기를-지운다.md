# [Feature] 투데이 카드 전환 상수(`LEGACY_SHAPE_CUTOVER`)와 분기를 지운다

> 출처: 티켓 20261001_2244(1453-b7 전환·정리) 민지 범위 밖 발견물([구조/참고])·아현 [주의]

## 핵심 요약

- 요구사항: b7이 옛 렌더러를 지운 뒤 `LEGACY_SHAPE_CUTOVER`는 화면을 되돌리는 수단이 아니다. 화면은 늘 `resolveShape`로 그리고, 상수는 이벤트의 기록 모양(`drawnShape`)에만 작용한다.
  누군가 상수를 `false`로 끄면 옛 카드의 기록 모양만 NULL이 되어 「기록 모양 = 화면 모양」 보장이 깨진다. 상수와 `drawnShape`의 전환 분기를 지워 기록도 늘 `resolveShape`를 쓰게 한다.
- 구현 계획: `jam-web/src/lib/today/shape.ts` 45줄 부근 상수·`drawnShape` 분기 정리, `jam-web/src/lib/today/events.ts`의 `drawnShape` 사용처, 관련 테스트(`shape.test.ts`·`events.test.ts`·`shapeParity.test.ts`),
  `scripts/gen-home-feed-doc.mjs`와 홈피드 PRD §6 「전환 상수」 항목·§9. 화면을 되돌리는 방법은 머지 되돌리기(`git revert`)뿐이라는 사실을 PRD에 적는다.
- 관련 파일: 위 구현 계획의 파일들. `drawnShape`를 쓰는 다른 곳이 있는지 착수 때 `grep -rn "drawnShape\|LEGACY_SHAPE_CUTOVER" jam-web/src scripts`로 확인한다(1502 신호 엔진은 `resolveShape`를 쓴다).

## 배경 / 문제 정의

- 1453 결정 17은 「옛 카드의 전환은 b7의 코드 상수 하나로 켠다」였다. b7 티켓은 「상수와 분기는 남긴다(되돌릴 때 상수 하나로 끈다)」와 「옛 렌더러 삭제」를 함께 요구했는데, 옛 렌더러가 없으면 상수로 화면을 되돌릴 수 없다.
  아현이 이 모순을 [주의]로 보고했고 `shape.ts` 주석과 PRD §6에 「상수는 기록 모양에만 작용한다」고 적었다.
- 지금 상수는 `true`라 동작 문제는 없다. 남겨 두면 끄는 실수가 생길 수 있는 장치다.

## 완료 조건

- 저장소에 `LEGACY_SHAPE_CUTOVER`가 없고, 이벤트의 기록 모양과 홈의 화면 모양이 같은 함수로 정해진다(`shapeParity.test.ts` 통과).
- 홈피드 PRD §6·§9가 바뀐 사실과 맞고, 화면 되돌림 방법이 적혀 있다. `node scripts/gen-home-feed-doc.mjs --check`와 `scripts/verify.sh`가 통과한다.
