# [Admin] 운영툴: 공개 전 취소가 409를 받아도 확인창이 예전 미리 보기를 보인다

> 범위 밖 발견물(2026-10-02 민지, 티켓 20261002_1649 ⑤-b 게이트 리뷰). 신호 **참고**.

## 핵심 요약

- 요구사항: 공개 전 취소 확인창은 열 때 한 번 받은 미리 보기(`{ dryRun: true }`)로 「함께 취소될 항목」·「취소를 막는 항목」을 그린다. 확인 버튼을 눌렀는데 그사이 다른 항목이
  막는 항목이 되어 서버가 409를 돌려주면, 창은 서버 문장만 덧붙이고 예전 미리 보기를 그대로 보인다. 409를 받으면 미리 보기를 다시 받아 구역을 새로 그린다.
- 관련 파일: `jam-web/src/components/admin/ops/OpsCancelItem.tsx`(미리 보기 요청 `previewRun` 152–168행, 취소 요청 실패 처리 172–189행), `executeClient.ts`(`postCancel`),
  `lib/admin/opsInbox/executeView.ts`(`cancelNeedsRefresh` 등 취소 순수 함수), 테스트 `components/admin/ops/__tests__/cancelItem.test.tsx`.

## 배경 / 문제 정의

- 다시 눌러도 서버가 같은 이유로 막으므로 위험은 없다. 다만 창에 보이는 「취소를 막는 항목」이 실제와 달라 운영자가 무엇을 먼저 처리해야 하는지 알기 어렵다.
- 409에서 화면 전체를 새로 읽지만(`onConflict`), 확인창의 미리 보기 상태(`view`)는 그대로 남는다.

## 완료 조건

- 취소 요청이 409를 받으면 확인창이 미리 보기를 다시 받아 함께 취소될 항목·막는 항목을 새로 보인다(테스트).
- 새 미리 보기에 막는 항목이 있으면 확인 버튼이 꺼진다.
