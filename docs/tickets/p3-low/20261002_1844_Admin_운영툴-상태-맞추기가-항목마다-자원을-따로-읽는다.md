# [Admin] 운영툴: 상태 맞추기가 항목마다 자원을 따로 읽는다

> 범위 밖 발견물(2026-10-02 민지, 티켓 20261002_1813 ⑦-a 게이트 리뷰). 신호 **참고**(성능). 아현도 같은 내용을 [주의]로 남겼다.

## 핵심 요약

- 요구사항: 상태 맞추기 한 회차는 실제 묶음의 예약됨·게재중 항목마다 핸들러 `observe`를 순서대로 한 번씩 부른다. 지금은 카드만 예약할 수 있어 문제없지만, ⑥~⑩이 다른 종류를
  붙이고 상시 게재중 자원(미션·배지·컬렉션)이 쌓이면 10분마다 항목 수만큼 DB 읽기가 늘어난다. 종류별로 ID를 모아 한 번에 읽는 방법(예: `observeMany`)이나 동시 실행 상한을 둔다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/execute/reconcile.ts` 473–499행(`reconcileOpsItems` 안의 항목 반복과 `observeGuarded`), `execute/handlers.ts`(`ExecuteHandler.observe`),
  `execute/homeFeedCard.ts`(카드 `observe`).
- 착수 시점: ⑥~⑩ 가운데 상시 게재중 자원을 만드는 핸들러가 붙은 뒤, 또는 한 회차의 소요가 크론 `maxDuration`(60초)에 가까워지면.

## 완료 조건

- 같은 종류의 자원을 한 회차에서 묶어 읽고, 판정 결과는 지금과 같다(기존 `reconcile.test.ts` 통과).
