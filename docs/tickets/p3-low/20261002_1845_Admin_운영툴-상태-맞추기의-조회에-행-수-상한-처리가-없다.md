# [Admin] 운영툴: 상태 맞추기의 조회에 행 수 상한 처리가 없다

> 범위 밖 발견물(2026-10-02 민지, 티켓 20261002_1813 ⑦-a 게이트 리뷰). 신호 **참고**(정확성).

## 핵심 요약

- 요구사항: 상태 맞추기의 대상 항목 조회와 결정 기록 조회가 페이지를 나누지 않는다. Supabase 기본 응답 행 수 상한(1000)을 넘으면 넘친 항목이나 결정 기록이 오류 없이 빠진다.
  결정 기록이 빠지면 「같은 차이는 한 번」·「이미 `fail`이면 다시 남기지 않음」 판정이 틀어져 기록이 중복될 수 있다. 페이지를 나눠 끝까지 읽거나, 항목마다 가장 최근 결정 기록만 읽도록 바꾼다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/execute/reconcile.ts` `loadTargets` 373행(`ops_bundle_items` 대상 조회)·394행(`ops_decisions` 결정 기록 조회, 항목 ID 묶음마다 최신순 전체).
- 착수 시점: 대상 항목이나 그 결정 기록이 수백 건에 가까워지기 전. 지금은 주당 수십 건이라 닿지 않는다.

## 완료 조건

- 대상 항목·결정 기록이 1000행을 넘어도 빠지는 행이 없다(테스트).
