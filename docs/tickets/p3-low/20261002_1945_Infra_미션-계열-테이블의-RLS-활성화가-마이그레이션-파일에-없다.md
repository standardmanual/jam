# [Infra] 미션 계열 테이블의 RLS 활성화가 마이그레이션 파일에 없다

> 범위 밖 발견물(2026-10-02 카리나, 티켓 20261002_1944 ⑥ 시작 검토의 Explore). 신호 **참고**(재현성).

## 핵심 요약

- 요구사항: 운영 DB에서 `missions`·`user_mission_participations`·`user_mission_completions`·`mission_rank_snapshots`는 RLS가 켜져 있고 정책이 0개다(2026-10-02 시스템 카탈로그 읽기 조회).
  그래서 공개 전 미션이 로그인 유저의 직접 조회로 새지 않는다. 그런데 저장소 마이그레이션에는 이 RLS 활성화가 없다(`jam-web/supabase/migrations/011_*`은 테이블만 만든다). 새 환경을 마이그레이션으로 다시 만들면
  RLS가 꺼진 채 생겨 공개 전 미션이 노출될 수 있다. 지금 상태를 그대로 적는 마이그레이션(`ALTER TABLE … ENABLE ROW LEVEL SECURITY`, 운영 DB에는 효과 없음)을 남긴다.
- 관련 파일: `jam-web/supabase/migrations/011_*`, 같은 종류의 레시피 사례 P3 20261001_1218.
- DB 변경: 운영 DB에는 이미 켜져 있어 실제 변화는 없지만 마이그레이션 파일이므로 절대 규칙 6(사용자 승인 뒤 메인 세션 실행)을 따른다.

## 완료 조건

- 미션 계열 4개 테이블의 RLS 활성화가 마이그레이션 파일에 있고, 운영 DB 상태와 같다(시스템 카탈로그 대조).
