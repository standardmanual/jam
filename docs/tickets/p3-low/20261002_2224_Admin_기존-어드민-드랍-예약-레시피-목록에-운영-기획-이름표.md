# [Admin] 기존 어드민의 드랍 예약 화면과 레시피 목록에 「운영 기획」 이름표를 붙인다

> 1500 ⑧ 시작 검토의 사용자 결정(2026-10-02): 「운영 기획에서 만든 예약」 표시는 이름표만 붙이고, 버튼은 그대로 두며, ⑧이 끝난 뒤 별도 티켓으로 한다.
> 이 결정은 티켓 20261001_2154 잔여 이슈의 「표시를 붙일지는 1500 ⑧ 착수 때 정한다」에 대한 답이다. 선행: ⑧-a(20261002_2221)·⑧-b.

## 핵심 요약

- 요구사항: 운영툴(1500)이 만든 앰비언트 드랍 예약과 레시피는 기존 어드민 화면에도 보인다. 그 화면에서 시각을 바꾸거나 취소하면 운영 항목과 어긋나고, 상태 맞추기가 결정 기록에
  「밖에서 바뀜」·「취소」로 남긴다(운영툴 PRD §8.6). 운영자가 그 사실을 미리 알 수 있게 두 목록의 행에 「운영 기획」 이름표를 붙인다. 시각 수정·취소 버튼은 막지 않는다. DB 변경은 없다.
- 구현 계획(착수 때 확정): 로더가 `ops_bundle_items`에서 `created_resource->>ambient_drop_schedule_id`(드랍)·`created_resource->>recipe_id`(레시피)가 목록의 ID와 같은 항목을 거꾸로 찾는다.
  두 테이블에는 출처 칼럼이 없다(마이그레이션 209 `created_by`는 관리자 이메일, `combination_recipes`에는 없음).
- 관련 파일(2026-10-02 Explore 코드 지도): 드랍은 로더 `jam-web/src/lib/ambient-drop/scheduleList.ts` `listAmbientDropSchedules` 124–157행·`toScheduleListItem` 82–103행, 목록 타입 `scheduleView.ts`
  `AmbientDropScheduleListItem` 32–54행, 행 컴포넌트 `jam-web/src/app/admin/ambient-drop/ScheduleList.tsx` 이름 칸 78행. 레시피는 로더 `jam-web/src/app/admin/recipes/page.tsx` 37–60행(`RECIPE_LIST_COLUMNS`,
  `lib/admin/recipe-list.ts` 15행), 표 `RecipeTable.tsx` 이름 칸 68–77행.

## 완료 조건

- 운영툴이 만든 드랍 예약·레시피 행에 「운영 기획」 이름표가 보이고, 그 밖의 행에는 없다(테스트, 카리나 실렌더).
- 이름표를 찾는 조회가 실패해도 목록은 그대로 열린다(이름표만 빠진다).
- `scripts/verify.sh` 전 항목 통과. DB 변경 없음.
