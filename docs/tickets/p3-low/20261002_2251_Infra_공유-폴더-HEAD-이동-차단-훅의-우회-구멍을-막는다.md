# [Infra] 공유 폴더 HEAD 이동 차단 훅의 우회 구멍을 막는다

> 범위 밖 발견물(2026-10-02 민지 게이트 WARN 사유 2와 sideFindings, 티켓 20261002_1905). 신호 **주의** 1건·**참고** 4건을 한 티켓으로 묶었다.
> 우선순위는 P3로 조정했다(카리나): 훅은 공격자가 아니라 에이전트의 실수를 막는 장치이고, 실제 사고 형태(읽기 명령에 섞은 직접 `git checkout`)는 이미 막는다.

## 핵심 요약

- 요구사항: `scripts/guard-shared-head.mjs`(민지·채원 frontmatter 훅)가 아래 형태를 통과시킨다. 실수로도 나올 수 있는 형태부터 막는다.
  1. `cd .claude/worktrees/<없는-이름>; git checkout x`: `;`로 이으면 cd가 실패해도 뒤 명령이 메인 폴더에서 실행되는데 통과한다. 테스트가 `cd ./.claude/worktrees/gate-x; git reset --hard`를 통과 목록에 두었다(`guard-shared-head.test.mjs` 108행).
  2. `(cd .claude/worktrees/x && git log); git checkout abc`: 서브셸 안의 cd가 밖으로 새어 통과한다(`findViolations`의 cd 추적, 233–246행).
  3. 간접 호출 `timeout 10 git checkout`·`nice git checkout`·`xargs git checkout`·`find -exec git checkout`·`g=git; $g checkout`을 명령으로 인식하지 못한다(`WRAPPERS` 48행).
  4. `git symbolic-ref`·`update-ref`·`branch -f`·`read-tree -u`·`checkout-index -f`는 막는 목록(36–39행)에 없다. 단 `git symbolic-ref HEAD refs/heads/<브랜치>`는 사고 복구 명령이기도 해서 막을지 착수 때 정한다.
  5. 워크플로 프롬프트 `WORKDIR_RULE`(`.claude/workflows/jam-work.js` 194–197행)이 탈출구 경로를 `.claude/worktrees/` 아래로 정해 두지 않아, 다른 경로에 워크트리를 만들면 훅에 한 번 막힌 뒤 다시 시도하게 된다.
- 관련 파일: `scripts/guard-shared-head.mjs`, `scripts/guard-shared-head.test.mjs`, `.claude/workflows/jam-work.js`(194–197행, `workflow_freeze` 계약 확인).

## 완료 조건

- 위 1~3 형태가 막히고, 기존 통과 명령(읽기 명령, `.claude/worktrees/` 아래에서 `&&`로 이은 명령, `git -C <worktrees 아래>`)은 그대로 통과한다(테스트).
- 4는 착수 때 정한 대로 반영되고, 5는 프롬프트가 탈출구 경로를 `.claude/worktrees/` 아래로 안내한다.
- `scripts/verify.sh` 전 항목 통과.
