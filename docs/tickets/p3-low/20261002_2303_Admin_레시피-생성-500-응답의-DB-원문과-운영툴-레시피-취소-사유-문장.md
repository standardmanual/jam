# [Admin] 레시피 생성 500 응답의 DB 원문과 운영툴 레시피 취소 사유 문장을 바로잡는다

> 범위 밖 발견물(2026-10-02 민지 게이트 sideFindings, 티켓 20261002_2221 1500 ⑧-a). 신호 **참고** 2건을 한 티켓으로 묶었다(둘 다 레시피 오류 문장).

## 핵심 요약

- 요구사항:
  1. 어드민 `POST /api/admin/recipes`가 `createRecipeWithSlots`의 500 결과를 그대로 응답해, 행 insert가 실패하면 DB 오류 원문(`error.message`)이 화면에 나간다. 관리자 로그인 뒤라 위험은 낮다.
     운영툴 핸들러는 같은 값을 `detail`(서버 로그)에만 두고 고정 문장을 쓴다. 서버 함수가 쉬운 문장을 돌려주고 원문은 로그에 남기도록 맞춘다(같은 파일의 슬롯 저장 실패는 이미 그렇게 한다).
  2. 운영툴 레시피 취소 사유 `cancelReferenced`(「…가리키고 있거나 확인하지 못해 지우지 않았어요」)의 「확인하지 못해」는 실제로 쓰이지 않는다. 참조 읽기 실패는 서버 함수가 500으로 돌려줘
     「레시피를 지우지 못했어요」로 간다. 문장을 실제 경우(참조가 있음)에 맞춘다.
- 관련 파일: `jam-web/src/lib/admin/recipe-write.ts` 184행 부근(`createRecipeWithSlots`의 insert 오류), `jam-web/src/app/api/admin/recipes/route.ts` 62행 부근, `jam-web/src/lib/admin/opsInbox/execute/recipe.ts` 44행 부근(`cancelReferenced`),
  테스트 `jam-web/src/lib/admin/__tests__/recipe-write.test.ts`·`execute/__tests__/recipe.test.ts`, 문서 `docs/service/prd/ops-tool/PRD.md` §8.1 레시피 사유 표.

## 완료 조건

- 레시피 생성의 insert가 실패하면 어드민 응답에 DB 원문이 없고 쉬운 문장이 나간다. 원문은 서버 로그에 남는다(테스트).
- 운영툴 레시피 취소의 참조 사유 문장이 실제 경우와 맞고, PRD 사유 표가 같은 문장이다.
- `scripts/verify.sh` 전 항목 통과.
