# [Admin] 드랍 핸들러 후속 정리: 대상 판정 이중 읽기와 낡은 주석 두 곳

> 범위 밖 발견물(2026-10-04 민지 게이트 sideFindings 3건과 아현 [주의]·[참고], 티켓 20261002_2306 1500 ⑧-b). 신호는 모두 **참고**다. 기능 오류는 없다.

## 핵심 요약

- 요구사항:
  1. **이중 읽기.** 드랍 한 건당 지점 종류 조회와 예정 시각 기준 대상 판정(`loadScheduleTargets`)이 핸들러 `check`와 `create`(`createAmbientDropSchedule` 안)에서 두 번씩 돈다(`execute/dropSchedule.ts` 98·105행 부근).
     등록 전 검증을 그룹 전체에서 먼저 해야 해서 생긴 의도적 중복이다(아현 [주의]). 묶음이 커지면 예약 등록 요청 시간(`maxDuration` 60초)을 먹으므로, 저장소 함수에 「검증을 건너뛰는 insert」 경로를 둘지 착수 때 정한다.
     변환의 `ends_at` 거절 문장이 파서 문장과 뜻이 겹치는 것도 함께 본다.
  2. **낡은 주석.** `jam-web/src/lib/admin/opsInbox/execute/run.ts` 7행 머리 주석 「(지금은 홈피드 카드)」(지금은 카드·미션·레시피·드랍), `jam-web/src/lib/ambient-drop/__tests__/schedule-test-db.ts` 8–9행
     「모든 쓰는 곳에서 `batch/shared`를 `sharedMock`으로 바꾼다」(이제 `schedule-store.test.ts`는 mock 없이 실제 `fetchAllRows`로 돈다).
  3. **칼럼 주석.** 마이그레이션 209의 `ambient_drop_schedules.created_by` 주석은 「등록한 관리자 이메일」인데 운영툴은 실행한 관리자 ID를 넣는다(티켓 20261002_2306 결정, 화면은 이 칸을 그리지 않는다).
     칼럼 주석을 바꾸려면 DB 변경이라 사용자 승인 뒤 메인 세션이 실행한다. 바꿀지 착수 때 정한다.
- 관련 파일: 위 경로들, `jam-web/src/lib/ambient-drop/scheduleStore.ts` `createAmbientDropSchedule`, `jam-web/supabase/migrations/209_ambient_drop_schedules.sql`.

## 완료 조건

- 1은 착수 때 정한 대로 반영하고(중복을 없애면 기존 드랍 저장소·핸들러 테스트가 그대로 통과), 2의 주석 두 곳이 사실과 같다. 3은 정한 대로 반영하거나 하지 않기로 한 사유를 남긴다.
- `scripts/verify.sh` 전 항목 통과.
