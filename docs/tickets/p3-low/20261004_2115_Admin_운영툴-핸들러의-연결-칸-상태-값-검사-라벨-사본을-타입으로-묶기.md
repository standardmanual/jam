# [Admin] 운영툴 핸들러의 연결 칸·상태 값·검사 라벨 사본을 타입으로 묶기

> 범위 밖 발견물(2026-10-04 민지 게이트 sideFindings 3건, 티켓 20261004_2039 1500 ⑩-a). 신호는 모두 **참고**다.

## 핵심 요약

- 요구사항: 다른 파일의 값을 글자 그대로 다시 적은 사본 세 곳이 타입 검사 밖에 있다. 원본이 바뀌면 컴파일 오류 없이 조용히 어긋난다.
  1. **연결 쌍 칸 이름.** `jam-web/src/lib/admin/opsInbox/execute/jamBadge.ts` 57–58행의 `COLLECTION_LAUNCH_KIND`·`COLLECTION_REWARD_LINK_FIELD` 문자열과 `execute/handlers.ts` 78–81행 `PointedByEntry`의 `kind`·`field`(`string` 타입)가
     `execute/groups.ts` `LINK_PAIRS`의 값을 따로 적은 사본이다. `LINK_PAIRS`의 칸 이름이 바뀌면 컬렉션 보상 배지의 발급 조건 예외가 꺼진다. 티켓 20261004_1913의 3번(연결 쌍을 칸 이름으로만 구분)과 함께 볼 수 있다.
  2. **드랍 예약 상태 값.** `jam-web/src/lib/admin/registerChecks/references.ts` 345행 `AMBIENT_SCHEDULE_UNFINISHED_STATUSES`가 `readonly string[]`이라 `AmbientDropScheduleStatus`(`jam-web/src/types/database.ts`)로 검사받지 않는다.
     상태 값이 늘면 컬렉션 되돌림 참조 판정(끝나지 않은 드랍 예약만 센다)이 어긋날 수 있다.
  3. **검사 라벨.** `execute/collectionLaunch.ts` 49–54행 `REASON_BY_CHECK_LABEL`이 `registerChecks/collection.ts`의 라벨 문자열(「이름 중복」 등)을 다시 적는다. 라벨이 바뀌면 고정 문장이 일반 문장(`checkFailed`)으로 떨어진다.
     `jamBadge.ts`(⑨-a)·`mission.ts`(⑥)도 같은 방식이다(기존 패턴).
- 관련 파일: 위 경로들과 각 테스트(`execute/__tests__/jamBadge.test.ts`·`collectionLaunch.test.ts`·`registerChecks/__tests__/registerChecks.test.ts`).

## 완료 조건

- 세 곳이 원본 타입(`LINK_PAIRS`에서 뽑은 타입, `AmbientDropScheduleStatus`, 검사 라벨 상수 또는 유니온 타입)으로 묶여, 원본이 바뀌면 타입 검사가 실패한다. 동작은 바뀌지 않는다(기존 테스트 통과).
- `scripts/verify.sh` 전 항목 통과.
