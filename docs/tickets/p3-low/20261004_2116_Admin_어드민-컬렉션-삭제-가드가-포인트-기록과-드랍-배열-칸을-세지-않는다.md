# [Admin] 어드민 컬렉션 삭제 가드가 포인트 기록과 드랍 배열 칸을 세지 않는다

> 범위 밖 발견물(2026-10-04 민지 게이트 sideFindings, 티켓 20261004_2039 1500 ⑩-a). 신호는 **참고**다. ⑩-a 시작 검토(Explore 코드 지도)에서 먼저 확인했고, ⑩-a는 이 가드를 고치지 않기로 정했다(⑩-a 가정 7).

## 핵심 요약

- 현상(확인한 사실, 2026-10-04 코드):
  - 기존 어드민 컬렉션 삭제(`jam-web/src/app/api/admin/itembooks/[id]/route.ts` `DELETE` 122–159행)와 일괄 삭제(`bulk/route.ts`)는 `jam-web/src/lib/admin/reference-guards.ts`의 `collectItemBookReferences`(276–322행)로 참조를 본다.
    참조 목록 `ITEM_BOOK_REFERENCE_SOURCES`(243–274행)는 장착·완성·드랍 상태를 막고 배지·카드는 막지 않는다.
  - 이 목록에 `point_transactions.source_item_book_id`(외래 키, ON DELETE 미지정 = NO ACTION, 마이그레이션 157 49행)와 배열 칸 `ambient_drop_schedules.collection_ids`·`ambient_drop_config.collection_ids`(외래 키 아님)가 없다.
  - 운영툴의 되돌림·취소 참조(`registerChecks/references.ts` `findItemBookUndoReferences`, ⑩-a)는 이 셋을 센다.
- 영향(위 사실에서 따라 나오는 결과): 완성 포인트 기록이 있는 컬렉션은 DB가 삭제를 막아 가드 대신 DB 오류(500)로 끝난다. 드랍 예약·상시 드랍 설정이 가리키는 컬렉션은 지워지고, 그 예약은 실행 때 대상을 찾지 못한다.
- 구현 계획(안): 어드민 가드 목록에 세 곳을 더하거나 `findItemBookUndoReferences`와 목록을 하나로 합친다. 드랍 예약은 끝나지 않은 상태만 센다(⑩-a와 같은 기준). 착수 때 어드민 가드의 「막지 않는 참조」 구분(배지·카드)을 그대로 둘지 정한다.
- 관련 파일: 위 경로들, `reference-guards.ts`의 테스트, 어드민 PRD의 컬렉션 삭제 서술(착수 때 위치 확인).

## 완료 조건

- 포인트 기록이나 끝나지 않은 드랍 예약·상시 드랍 설정이 가리키는 컬렉션을 어드민에서 지우면 409와 참조 위치가 나온다(테스트). 기존 가드의 다른 동작은 바뀌지 않는다.
- `scripts/verify.sh` 전 항목 통과.
