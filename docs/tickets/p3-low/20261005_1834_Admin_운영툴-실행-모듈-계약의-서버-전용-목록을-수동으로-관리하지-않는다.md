# [Admin] 운영툴 실행 모듈 계약의 서버 전용 목록을 손으로 관리하지 않는다

> 티켓 20261005_1607(⑨-b) 게이트 범위 밖 발견물 [구조/참고](민지, 2026-10-05).

## 핵심 요약

- 요구사항: `execute/__tests__/precheck.test.ts`의 모듈 계약(「DB와 서버 전용 코드를 값으로 가져오지 않는다」)은 서버 전용 파일을 손으로 적은 목록 `SERVER_ONLY`로 뺀다.
  새 서버 전용 파일을 `execute/`에 더할 때마다 계약 테스트가 한 번 깨진 뒤에야 목록을 고친다(⑨-b에서 `badgePreview.ts`로 실제로 한 번 깨졌다). 같은 폴더의 `pureModules.test.ts`(`PURE_ENTRIES`)도 손으로 적은 목록이다.
  서버 전용 여부를 파일 스스로 밝히게 하거나(예: 머리 주석 표시, `import 'server-only'`), 순수 모듈 목록 한 곳만 두게 해서 두 목록이 따로 어긋나지 않게 한다.
- 구현 계획: 착수 때 정한다. 후보는 ① 서버 전용 파일이 `server-only` 패키지나 정해진 표시를 갖고 계약 테스트가 그 표시로 거르는 방식, ② `PURE_ENTRIES` 하나만 두고 `precheck.test.ts`의 목록 검사를 거기서 파생하는 방식이다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/execute/__tests__/precheck.test.ts` 958–975행(`SERVER_ONLY`, 「순수 모듈 열 개가 있다」), `jam-web/src/lib/admin/opsInbox/execute/__tests__/pureModules.test.ts` 60–74행(`PURE_ENTRIES`),
  서버 전용 파일 `execute/run.ts`·`cancel.ts`·`reconcile.ts`·`badgePreview.ts`

## 완료 조건

- `execute/`에 서버 전용 파일을 새로 더해도 계약 테스트의 목록을 손으로 고칠 필요가 없다. 순수 모듈이 서버 전용 코드를 값으로 가져오면 지금처럼 테스트가 실패한다(테스트).
