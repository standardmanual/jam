# [API] 아이템 얻을 길 API가 요청마다 전체를 읽고 계산한다

## 핵심 요약

- 요구사항: `GET /api/admin/item-paths`는 요청마다 컬렉션·아이템 배지(3,600개 이상)·레시피·미션 전체를 읽고 전체를 계산한 뒤 쪽만 자른다. `limit`을 줄여도 읽기량이 같고,
  `computeItemPaths`의 `summarizeCollection`이 컬렉션마다 전체 결과를 훑는다(컬렉션 × 아이템). 에이전트 루틴이 자주 부르기 시작하면 지연을 재고 필요하면 줄인다.
- 구현 계획: 먼저 실제 응답 시간을 잰다. 줄여야 하면 결과를 컬렉션별로 한 번에 묶어 훑기를 없애고, 쪽에 해당하는 컬렉션의 아이템만 읽는 방법을 검토한다.
- 관련 파일: `jam-web/src/app/api/admin/item-paths/route.ts`(41–55행), `jam-web/src/lib/admin/itemPaths/compute.ts`(`summarizeCollection`), `jam-web/src/lib/admin/itemPaths/load.ts`

## 배경 / 문제 정의

티켓 20261004_1641(1503 ⑦b) 게이트에서 민지가 남긴 범위 밖 발견물 [참고/성능]이다. 지금 규모에서는 문제가 없다.

## 완료 조건

- 실제 응답 시간 실측값이 티켓에 있고, 줄이기로 했으면 같은 결과를 내는 테스트와 함께 읽기량 또는 계산량이 줄어 있다.
