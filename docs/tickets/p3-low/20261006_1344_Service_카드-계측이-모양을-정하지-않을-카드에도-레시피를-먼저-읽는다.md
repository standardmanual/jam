# [Service] 카드 계측이 모양을 정하지 않을 카드에도 레시피 행을 먼저 읽는다

## 핵심 요약

- 요구사항: `jam-web/src/lib/today/events.ts`의 `assertCardExposable`이 `shape`가 없고 전환 상수가 꺼져 모양이 null로 정해질 카드에도 `drawnTileCount`로 레시피 행을 먼저 읽는다. 결과를 쓰지 않는 읽기를 건너뛴다.
- 구현 계획: 아래 「구현 계획」. 유형 `bug`. 1단계 규모 판정: 코드 1·테스트 1, 약 40줄로 `plan_only` 임계값 아래다.
- 관련 파일: `jam-web/src/lib/today/events.ts` 90–97행(`assertCardExposable`, `drawnTileCount`, `resolveDrawnShape`)

## 배경 / 문제 정의

⑫-b(20261006_1218) 게이트의 범위 밖 발견물 [성능/참고]이다. 레시피 공개 카드의 노출 이벤트마다 쓰이지 않는 레시피 읽기가 한 번 더 생길 수 있다. 레시피 공개 카드가 아직 없어(⑫-b 「금지」) 지금 부하는 없다.

## 구현 계획

| 경로 | 위치 | 변경 |
|---|---|---|
| `jam-web/src/lib/today/events.ts` | `assertCardExposable` 90–97, `drawnTileCount` 105–123, `resolveDrawnShape` 134–138 | 먼저 `drawnShape(card)`로 모양을 정하고, null이면 레시피를 읽지 않고 기록 모양 null로 끝낸다. 타일 수가 판정에 쓰이는 경우(`fallbackEmptyTileShape`가 보는 경우)에만 `drawnTileCount`를 부른다. 기록 결과는 지금과 같다 |
| `jam-web/src/lib/today/__tests__/events.test.ts` | ⑫-b가 더한 레시피 공개 카드 계측 케이스 | 모양이 null로 정해지는 레시피 공개 카드에서 `combination_recipes` 조회가 일어나지 않는 케이스를 더하고, 기존 케이스(공개 중 `list`·그 밖 `brief`·읽기 실패)는 그대로 통과 |

## 완료 조건

- 모양이 null로 정해지는 카드의 이벤트 기록에서 레시피 읽기가 일어나지 않는다(테스트).

## 완료 기록 *(작업 완료 후 작성)*

### 구현 내용 요약

- `events.ts`의 `resolveDrawnShape`를 async로 바꿔 모양을 먼저 정한다(`drawnShape`). null이면 레시피를 읽지 않고 null로 끝내고, `fallbackEmptyTileShape(shape, resource, 0) === shape`이면(타일 수가 판정에
  쓰이지 않는 모양: `list`가 아닌 모양·랭킹 행형) `drawnTileCount`를 부르지 않는다. `list` 타일형에서만 레시피를 읽는다. 기록 결과는 그대로다.
- 홈피드 PRD §9 「기록 모양 = 화면 모양」에 레시피 행을 읽는 조건을 적었다.
