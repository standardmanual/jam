# [Admin] 레시피 삭제 카드 안내의 화면 테스트와 일괄 삭제 문구

## 핵심 요약

- 요구사항: (1) 어드민 레시피 일괄 삭제 확인창(`RecipeTable.tsx`)과 편집 화면 예약 취소 확인 문구(`RecipeForm.tsx` `handleCancelRelease`)에 카드 안내가 실제로 그려지는 경우(카드 1장 이상)를
  컴포넌트 테스트로 고정한다. (2) 일괄 삭제에서 여러 레시피를 지울 때 안내 문구 「이 레시피를」과 합계 카드 수가 맞도록 문구를 정한다(예: 「지울 레시피를」).
- 구현 계획: 아래 「구현 계획」(파일 단위). 유형 `admin`. 기존 admin 컴포넌트 테스트는 jsdom 없이 `renderToStaticMarkup`으로 처음 그린 모양만 고정하므로(`ops-inbox/__tests__/table.test.tsx` 머리말),
  누른 뒤 열리는 확인창 안쪽은 지금 구조로 테스트할 수 없다. 그래서 안내 부분을 표시 컴포넌트와 순수 함수로 떼어 그것을 테스트한다.
- 관련 파일: `jam-web/src/app/admin/recipes/RecipeTable.tsx`(230행 부근 확인창), `jam-web/src/app/admin/recipes/RecipeForm.tsx`(`handleCancelRelease`), `jam-web/src/app/admin/recipes/[id]/page.tsx`(카드 수 전달),
  `jam-web/src/lib/admin/recipe-bulk.ts`(`recipeCardNoticeMessage`)

## 배경 / 문제 정의

20261006_1342 게이트(민지) WARN 사유 두 가지와 범위 밖 발견물 [정확성/참고]다. 1342의 테스트는 서버 응답 `impact.cardCount`와 문구 함수까지만 고정한다.
화면이 그 값을 읽어 안내를 그리는 연결은 테스트가 없고, 라이브 DB에 레시피를 가리키는 카드가 0장이라 실렌더로도 안내 없는 상태만 볼 수 있다.
일괄 삭제 문구는 1342 티켓이 정한 「이 레시피를」을 그대로 써서, 여러 개를 지울 때 카드 수(대상 전체의 합)와 문구가 정확히 맞지 않는다.

## 구현 계획

> 2026-10-06 카리나 규모 사전 판정: 테스트 포함 약 6파일·150줄. 아래 표에 파일 경로와 함수·줄 위치가 있어 첫 호출부터 계획 반환 면제로 진행한다.

| 경로 | 위치 | 변경 |
|---|---|---|
| `jam-web/src/lib/admin/recipe-bulk.ts` | `recipeCardNoticeMessage` 29–32 | 대상 표현 인자를 더한다. 편집 화면(레시피 하나): 「홈 카드 N장이 이 레시피를 가리켜요. 지우면 그 카드는 레시피 정보 없이 남아요.」, 일괄 삭제: 「홈 카드 N장이 지울 레시피를 가리켜요. 지우면 그 카드는 레시피 정보 없이 남아요.」(0장·음수·NaN이면 없음은 그대로) |

## 완료 조건

- 카드 수가 1 이상일 때 두 확인 단계에 안내가 보이고, 0일 때 보이지 않는다(컴포넌트 테스트).
- 일괄 삭제에서 레시피를 여러 개 고르면 문구가 여러 레시피를 가리키는 표현이다(테스트).
