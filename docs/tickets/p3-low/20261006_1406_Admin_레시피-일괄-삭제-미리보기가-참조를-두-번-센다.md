# [Admin] 레시피 일괄 삭제 미리보기가 참조를 두 번 센다

## 핵심 요약

- 요구사항: `jam-web/src/app/api/admin/recipes/bulk/route.ts`의 미리보기(`dryRun`)에서 `collectRecipeDeletionCandidates`가 `collectRecipeReferences`를 한 번 부른 뒤, 카드 수를 위해 삭제 대상으로 다시 부른다.
  결과는 정확하고 조회가 한 번 더 돈다. 한 번의 조회로 막는 참조와 카드 수를 함께 얻게 한다.
- 구현 계획: 아래 「구현 계획」. 유형 `admin`. 1단계 규모 판정: 테스트 포함 3파일·약 60줄로 `plan_only` 임계값(5파일 초과 또는 100줄 이상) 아래다.
- 관련 파일: `jam-web/src/app/api/admin/recipes/bulk/route.ts`(61행 부근), `jam-web/src/lib/admin/recipe-references.ts`(`collectRecipeDeletionCandidates` 132–)

## 배경 / 문제 정의

20261006_1342 게이트(민지)의 범위 밖 발견물 [정확성/참고]다. 일괄 삭제는 최대 건수가 정해져 있어 부하는 작다.

## 구현 계획

| 경로 | 위치 | 변경 |
|---|---|---|
| `jam-web/src/lib/admin/recipe-references.ts` | `collectRecipeDeletionCandidates` 132–166, 결과 타입 | 이미 부르는 `collectRecipeReferences`의 `noticeTotal`을 버리지 않고 돌려준다. 막는 참조가 0건이면(전체 한 번 조회) 전체의 `noticeTotal`, 아니면 한 건씩 다시 세는 반복에서 각 레시피의 `noticeTotal`을 후보에 담아 호출부가 삭제 대상만 더할 수 있게 한다 |
| `jam-web/src/app/api/admin/recipes/bulk/route.ts` | `dryRun` 분기의 카드 수 조회(61행 부근) | 추가 `collectRecipeReferences` 호출을 지우고 위 결과로 `impact.cardCount`를 만든다. 건너뛴(막힌) 레시피를 가리키는 카드는 세지 않는다(지금 동작과 같음) |
| 테스트 | `jam-web/src/app/api/admin/recipes/bulk/__tests__/route.test.ts`(1342 신규 6건), `jam-web/src/lib/admin/__tests__/recipe-references.test.ts` | 응답이 그대로인지(카드 0·N장, 건너뜀 제외, 조회 실패 500)와 미리보기 한 번에 카드 수를 위한 추가 조회가 없는지 |

## 완료 조건

- 미리보기 한 번에 레시피 참조 조회가 한 번만 일어나고, 응답(`impact.cardCount`·`skipped`)은 그대로다(테스트).
