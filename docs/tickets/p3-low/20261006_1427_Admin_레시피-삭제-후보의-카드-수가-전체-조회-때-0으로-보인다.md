# [Admin] 레시피 삭제 후보의 카드 수가 전체 한 번 조회 때 0으로 보인다

## 핵심 요약

- 요구사항: `collectRecipeDeletionCandidates`가 돌려주는 후보별 `noticeTotal`(`RecipeDeletionLookupCandidate`)은 막는 참조가 0건이라 전체를 한 번에 센 경우 레시피별로 나눌 수 없어 항상 0이다.
  지금은 라우트가 `allNoticeTotal`이 있으면 후보값을 쓰지 않아 정확하지만, 이후 호출부가 후보 단위 값만 읽으면 카드가 있어도 0장으로 오판한다. 오판할 수 없는 모양으로 바꾼다.
- 구현 계획: 후보별 값을 「모름」(null)으로 두거나, 두 경우를 판별 가능한 유니온 타입으로 돌려주는 방식이 후보다.
- 관련 파일: `jam-web/src/lib/admin/recipe-references.ts`(119행 부근 `RecipeDeletionLookupCandidate`, `collectRecipeDeletionCandidates`), `jam-web/src/app/api/admin/recipes/bulk/route.ts`(dryRun 분기)

## 배경 / 문제 정의

20261006_1406 게이트(민지)의 범위 밖 발견물 [구조/참고]다. 지금 이 값을 읽는 곳은 일괄 삭제 라우트 하나이고 주석이 제약을 적고 있어 당장 틀린 값이 나가지는 않는다.

## 완료 조건

- 후보별 카드 수를 셀 수 없는 경우가 타입이나 값으로 드러나 0장과 구별된다(테스트).
