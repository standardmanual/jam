# [Service] 페이지·라우트 테스트의 모의 Supabase 빌더가 여러 곳에 복제돼 있다

## 핵심 요약

- 요구사항: (1) 20261006_1530이 처음 만든 서버 페이지 테스트들과 share-data 라우트 테스트에 Proxy 기반 모의 Supabase 빌더(`makeBuilder` 약 25줄)가 거의 같은 형태로 3곳 이상 복제돼 있다.
  공용 테스트 헬퍼로 모은다. (2) 컬렉션 상세 테스트의 「404가 나면 소속 배지 조회까지 가지 않는다」는 `.single()` 변이에서도 통과해 회귀를 잡지 못하는 대조 케이스다. 의미 있는 단언으로 바꾸거나 대조라고 명시한다.
  (3) 20261006_1529의 ⑩·⑪ 테스트가 「`badges` 둘째 조회 = 첫 유저의 JAM! 후보 조회」라는 호출 순서에 기대어 오류를 주입한다. 조회 순서가 바뀌면 다른 이유로 통과할 수 있으니 조회 대상으로 주입 지점을 고른다.
- 구현 계획: 착수 때 정한다(테스트 전용 변경).
- 관련 파일: `jam-web/src/app/api/badges/[id]/share-data/__tests__/route.test.ts` 21, `jam-web/src/app/(main)/badges/[id]/__tests__/page.test.tsx`, `jam-web/src/app/(main)/collections/[id]/__tests__/page.test.tsx` 101,
  `jam-web/src/lib/badge-engine/__tests__/reevaluate-catalog-jam.test.ts` 612–634
