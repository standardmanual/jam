# [Admin] 운영툴 이미지 저장이 PNG를 MIME으로만 거르고 픽셀 한도가 없다

## 핵심 요약

- 요구사항: 이미지 저장 라우트가 PNG 여부를 클라이언트가 보낸 `file.type === 'image/png'`로만 거르고 매직 바이트를 보지 않는다. sharp는 JPEG·SVG·GIF 등도 디코딩하므로 다른 형식이 변환을 통과하고 원본 바이트가 `.png`로 공개 버킷 `images`에 올라간다(`contentType`은 `image/png` 고정이라 스크립트 실행은 아님, 관리자 세션 한정). `sharp()`에 `limitInputPixels`가 없어 5MB 이하로 압축한 고해상도 PNG가 디코딩 때 메모리를 크게 쓸 수 있다(관리자 한정 서비스 거부). 이 라우트를 부르는 클라이언트 코드는 아직 없다(보안 [참고] 2번).
- 구현 계획: `sharp(input).metadata()`의 `format === 'png'`로 형식을 확인하고, `limitInputPixels`를 둔다. 비PNG·고해상도 입력 테스트를 추가한다.
- 관련 파일: `jam-web/src/app/api/admin/ops-inbox/[bundleId]/items/[itemId]/image/route.ts`(63–64·88–91행), `jam-web/src/lib/admin/badgeImageWebp.ts`(25–33행)

## 배경 / 문제 정의

2026-10-07 `/jam-ship` 5단계 병렬 점검(민지 모드 ② 보안·모드 ③ 테스트 공백, 범위 565c3067b..9142afab7)의 범위 밖 발견물 [보안/참고] 1·2번과 [테스트/참고] 7번이다. 승격을 막지 않는 항목이라 배포와 별도로 처리한다.

## 완료 조건

- PNG가 아닌 입력과 픽셀 한도 초과 입력이 거절되고 테스트로 고정된다.
