# [Infra] 패턴 사전 파서 테스트가 원고 사본의 본문에 묶여 있다

> 출처: 티켓 20261007_1633(1503 ③) 게이트 리뷰에서 민지가 낸 범위 밖 발견물 [참고]. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: `scripts/ops-patterns-seed.test.mjs`의 「실제 원고」 테스트 3건(170~210행 부근: 「실제 원고: 18·63·43·7이고 검사를 통과한다」, 「실제 원고: P07·P06·P14·걸침 구현」,
  「실제 원고 SQL: …」)이 `jam-doc/planning/content/OPS_PATTERNS.md`의 현재 본문을 읽는다. 이 원고는 2026-10-07부터 DB의 입력일 기준 사본(`source_of_truth: db`)이다.
  누가 사본 본문을 고치면(예: 사본을 DB 현재값으로 다시 맞출 때 패턴이 19개가 되면) `scripts/verify.sh`가 막힌다. 사본 수정이 검사를 막지 않게 고친다.
- 구현 계획: 착수 때 둘 중 하나를 고른다. (가) 세 테스트가 원고 대신 고정 사본(테스트 픽스처)을 읽게 바꾼다. (나) 원고 머리말이 `source_of_truth: db`이면 개수 단정을 건너뛰고
  파싱이 오류 없이 끝나는지만 본다. 개발자는 같은 이유로 `--check`를 실제 원고에 거는 테스트를 이미 뺐다(1633 완료 기록).
- 관련 파일: `scripts/ops-patterns-seed.test.mjs` 170~210행 부근, `scripts/ops-patterns-seed.mjs`(`EXPECTED`·`SOURCE_PATH`), `jam-doc/planning/content/OPS_PATTERNS.md` 머리말.

## 배경 / 문제 정의

- 지금은 원고와 DB가 같아(1633에서 칸 단위 해시 대조 불일치 0) 테스트가 통과한다. 문제는 원고 사본을 고치는 시점에 생긴다. 패턴 수정은 운영툴(S5, 1503 ⑩a)에서 하므로
  사본을 고칠 일은 드물다. 그래서 P3로 둔다.

## 완료 조건

- 원고 사본의 패턴 수를 바꾼 상태에서도 `node --test scripts/ops-patterns-seed.test.mjs`가 통과한다(또는 (가)라면 원고를 읽지 않는다).
- 칸 매핑·멈춤 조건 테스트의 검증 범위는 줄지 않는다. `scripts/verify.sh`가 통과한다.
