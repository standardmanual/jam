# [Admin] 카드 등록 변환의 패턴 번호 읽기를 읽기 함수 하나로 합친다

> 출처: 티켓 20261007_1745(E1-a) 게이트 리뷰에서 민지가 낸 범위 밖 발견물 [참고]. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: `jam-web/src/lib/admin/opsInbox/registerInput.ts` 405-417행(결정 5, G11)은 항목의 `pattern_no`를 직접 읽고, 숫자면 문자열로 바꾼 뒤 `OPS_PATTERN_NO_PATTERN`으로 거른다.
  2026-10-07(1745)부터 제출 검증은 숫자를 받지 않고 형식이 틀리면 열을 비우므로, 숫자 분기는 옛 묶음 데이터에만 닿는다. 같은 판정이 `fields.ts`의 `readOpsItemPatternNo`(1745 신설,
  형식이 틀리면 모름)에도 있어 규칙이 두 곳에 있다. 카드 등록 변환이 `readOpsItemPatternNo`를 쓰게 바꿔 판정을 한 곳으로 모은다.
- 구현 계획: 착수할 때 정한다. 「모름」이면 지금처럼 비우고 경고한다(경고 문장은 유지). 옛 묶음의 숫자 값(예: 7)을 받아들일지는 착수 때 확인한다(지금은 받아들여 `7`로 읽은 뒤 형식에서 걸러 비운다 — 결과는 같다).
- 관련 파일: `jam-web/src/lib/admin/opsInbox/registerInput.ts` 405-417, `jam-web/src/lib/admin/opsInbox/fields.ts`(`readOpsItemPatternNo`), 해당 테스트(`jam-web/src/lib/admin/opsInbox/__tests__/registerInput.test.ts`).

## 완료 조건

- 카드 등록 변환이 `readOpsItemPatternNo`로 패턴 번호를 읽고, 형식이 맞으면 쓰고 아니면 비우고 경고하는 동작이 기존 테스트와 같다.
- `scripts/verify.sh`가 통과한다.
