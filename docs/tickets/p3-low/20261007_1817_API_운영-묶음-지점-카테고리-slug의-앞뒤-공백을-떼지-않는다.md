# [API] 운영 묶음 검증이 지점 카테고리 slug의 앞뒤 공백을 떼지 않는다

> 출처: 2026-10-07 `/jam-ship` 5단계 사후 점검(티켓 20261007_1745 범위) 민지 모드 ③의 [정확성/참고]. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: `jam-web/src/lib/admin/opsInbox/validate.ts` 246~258행은 `knobs.place_category`의 원소가 `isNonEmptyString`을 통과하면 다듬지 않고 그대로 slug 목록과 비교한다.
  그래서 `" cafe "`가 「없는 카테고리」로 판정된다. 패턴 번호는 앞뒤 공백을 떼는데 카테고리는 떼지 않아 규칙이 어긋난다. 공백·중복·대소문자를 어떻게 다룰지 정하고 테스트를 더한다.
- 구현 계획: 착수 때 정한다. 패턴 번호와 같이 앞뒤 공백을 떼고 비교할지, 지금처럼 그대로 두고 오류 문장으로 알릴지를 PRD §3.1(운영툴)에 맞춰 고른다. 저장 값(`fields.ts`의 `readOpsItemPlaceCategories`)도 같은 규칙을 따르게 한다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/validate.ts` 246~258행, `jam-web/src/lib/admin/opsInbox/fields.ts`, `jam-web/src/lib/admin/opsInbox/__tests__/validate.test.ts`,
  `docs/specs/prd/ops-tool/PRD.md` §3.1.

## 완료 조건

- 공백이 섞인 slug·중복 slug·대소문자가 다른 slug의 처리 규칙이 PRD §3.1에 적혀 있고, 그대로 동작하며 테스트가 있다.
- `scripts/verify.sh`가 통과한다.
