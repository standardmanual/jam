# [API] 운영 묶음 검증 컨텍스트와 직접 수정 경로에 테스트 공백이 있다

> 출처: 2026-10-07 `/jam-ship` 5단계 사후 점검(티켓 20261007_1745 범위) 민지 모드 ③의 [구조/참고]·[정확성/참고] 3건. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: 동작은 바꾸지 않고 아래 세 곳에 테스트를 더한다.
  - `jam-web/src/lib/admin/opsInbox/validationContext.ts` 16~27행: 전용 테스트 파일이 없다. `loadPoiCategorySlugs`의 `data ?? []`와 `select('slug')` 열 한정, 조회 두 개 이상이
    동시에 실패하는 경우(`Promise.all`)를 직접 확인하는 테스트가 없다. 같은 일을 하는 `loadOpsPatternNos`는 열 한정·빈 테이블·오류를 단위 테스트한다.
  - `jam-web/src/lib/admin/opsInbox/__tests__/decide.test.ts` 678행 부근: 직접 수정 테스트 「열은 NULL 그대로」는 시드 열이 null이라, 열에 `P-07`이 이미 저장된 옛 묶음 항목을
    재현하지 못한다. 열이 `P-07`인 항목을 수정해도 열이 보존되는지 테스트한다(새 제출은 열을 null로 저장하므로 두 상태가 공존한다).
  - `jam-web/src/lib/admin/opsInbox/decide.ts` 367·626·703행: 색 채우기와 되돌리기는 조회 실패 500만 테스트한다. 기존 패턴·카테고리 오류가 있는 항목에서 고친 칸과 무관한 오류는 막지 않는
    성공 경로를 `editItem`처럼 테스트한다.
- 구현 계획: 착수 때 정한다. 세 곳 모두 테스트만 더한다.
- 관련 파일: 위 파일과 행 번호, `jam-web/src/lib/admin/opsInbox/__tests__/`.
