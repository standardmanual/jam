# [API] 조합 뽑기가 승인 이후 항목 전체를 요청마다 읽는다

> 출처: 티켓 20261007_2221(1503 ④) 게이트 리뷰에서 민지가 낸 범위 밖 발견물 [성능/참고]. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: `jam-web/src/lib/admin/opsPatterns/draw.ts`(297행 부근 `loadDrawUsageRows`)는 「마지막 사용」(`lastUsedAt`, 설계 결정 D2)을 구하려고 기간 조건 없이 승인 이후 상태의
  운영 항목 전체를 요청마다 읽는다. 2026-10-07 기준 해당 항목은 0건이라 부담이 없지만, 항목이 수천 건으로 늘면 응답이 느려진다. 그 시점에 DB 쪽 집계(뷰·RPC 등)로 바꾼다.
- 구현 계획: 착수 때 정한다. 착수 기준은 응답 시간이나 항목 수로 정한다(예: 승인 이후 항목 2,000건 초과). PRD §11.14 「성능」에 이 한계가 적혀 있다.
- 관련 파일: `jam-web/src/lib/admin/opsPatterns/draw.ts`, `docs/specs/prd/ops-tool/PRD.md` §11.14.

## 완료 조건

- 같은 입력에서 응답이 지금과 같고(기존 `draw.test.ts`·`draw-route.test.ts` 통과), 읽는 행 수가 패턴·트라이브·카테고리 수에 비례하도록 줄어든다. `scripts/verify.sh`가 통과한다.
