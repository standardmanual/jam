# [API] 조합 뽑기와 밸런스 점검(R4)의 테스트 공백

> 출처: 2026-10-07 `/jam-ship` 5단계 민지 모드 ③(배포 전 테스트 공백 점검, 범위 53335ddda..836983f78)의 [참고] 4건. 자동 티켓화(`/jam-work` 3.2절).

## 핵심 요약

- 요구사항: 동작은 바꾸지 않고 아래 공백을 메운다.
  1. 공유 상수 `OPS_POST_APPROVAL_ITEM_STATUSES`(`jam-web/src/lib/admin/opsInbox/constants.ts`)의 값을 직접 단언하는 테스트가 없다. 밸런스 R4 테스트
     (`jam-web/src/lib/admin/opsInbox/balance/__tests__/evaluate.test.ts` 393~402행)는 승인 이후 분기를 `approved`·`scheduled`로만 시험하고 `preparing`·`live`·`ended`는 시험하지 않는다.
     상수가 바뀌면 R4 기준 시각이 조용히 달라지고 조합 뽑기 테스트만 깨진다.
  2. `jam-web/src/lib/admin/opsPatterns/__tests__/draw.test.ts` 443~456행이 select 문자열 전체와 `.eq`·`.in` 호출 순서를 그대로 단언한다(구현 세부 결합). 동작은 `draw-route.test.ts`의
     걸러내는 가짜가 따로 지키므로, 칸 집합·조건 집합 단언으로 느슨하게 바꾼다.
  3. `drawOpsCombination`(`jam-web/src/lib/admin/opsPatterns/draw.ts` 318~323행)의 네 읽기를 `Promise.all`로 부르는데, 완료 순서가 뒤바뀌어도 같은 결과인지 시험하지 않는다.
  4. 라우트(`jam-web/src/app/api/admin/ops-patterns/draw/route.ts` 17~24행)의 잔여 오류 경로: `createServiceClient()`가 던지는 경우, 로그인했지만 관리자가 아닌 세션의 403,
     `?limit=3&limit=9`처럼 limit이 겹칠 때 첫 값을 쓰는 동작(`draw.ts` 49행).
- 구현 계획: 착수 때 정한다. 테스트만 더하거나 고친다.
- 관련 파일: 위 경로와 행 번호.

## 완료 조건

- 위 네 가지마다 테스트가 있고 통과한다. 상수 값 단언과 R4의 다섯 상태 분기 테스트가 있다. `scripts/verify.sh`가 통과한다.
