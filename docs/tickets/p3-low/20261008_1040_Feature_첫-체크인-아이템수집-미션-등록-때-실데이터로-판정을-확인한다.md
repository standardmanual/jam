# [Feature] 첫 체크인·아이템 수집 미션을 등록할 때 실제 데이터로 판정을 한 번 확인한다

## 핵심 요약
- 요구사항: 티켓 `20260930_0014`가 미션 판정에 체크인 배지 이력(`user_checkin_badge_earns`)을 더했지만, 검증은 페이크 클라이언트 단위 테스트로만 했다. 운영에서 `checkin` 또는 `item_collect` 미션을 처음 등록할 때, 실제 참가자 한 명으로 진행도와 완료가 맞게 기록되는지 확인한다.
- 구현 계획: 코드 변경 없음. 첫 미션이 등록되면 아래 「완료 조건」의 SELECT로 확인하고 결과를 이 티켓에 적는다.
- 관련 파일:
  - `jam-web/src/lib/missions/checker.ts` L127-145(`checkMissions`의 대상 지점·배지 id 수집), L421-489(`loadOwnership`의 `user_checkin_badge_earns` 조회 두 갈래)
  - 참고: `jam-web/src/lib/missions/checker-ownership.test.ts`(페이크 클라이언트 테스트 8건)

## 배경 / 문제 정의
2026-10-08 게이트 리뷰(민지)의 범위 밖 발견물이다. 2026-10-08 DB 조회 결과 `mission_type`이 `checkin`·`item_collect`인 미션은 0건이다. 그래서 `.in('poi_id', …)`·`.in('badge_id', …)` 조회가 실제 PostgREST 응답으로 돌아간 적이 없다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 확인 시점은 운영툴 미션 폼 또는 운영 묶음으로 `checkin`·`item_collect` 미션이 처음 등록된 뒤, 참가자가 동기화를 한 번 마친 때다.
- DB 변경을 하지 않는다. 확인은 SELECT만 쓴다.

## 구현 계획
1. 첫 미션의 `id`·`condition_json`을 조회한다.
2. 그 미션 참가자 중 대상 지점(`poi_id`) 또는 대상 배지(`badge_id`)의 `user_checkin_badge_earns` 행이 있는 사용자를 찾는다.
3. 그 사용자의 `user_mission_participations.progress_value`와 `user_mission_completions` 행을 확인한다.

## 완료 조건
- 대상 이력이 있는 참가자가 동기화한 뒤 `user_mission_participations.progress_value`가 1이고 `user_mission_completions`에 그 미션 행이 있다.
- 대상 이력이 없는 참가자는 완료 행이 없다.
- 결과(미션 id, 확인한 참가자 수, 일치 여부)를 이 티켓 완료 기록에 적는다. 어긋나면 원인을 적고 버그 티켓을 새로 만든다.
