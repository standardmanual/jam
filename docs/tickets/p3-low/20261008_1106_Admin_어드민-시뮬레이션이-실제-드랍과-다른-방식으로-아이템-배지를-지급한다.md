# [Admin] 어드민 시뮬레이션이 실제 드랍과 다른 방식으로 아이템 배지를 지급한다

> 범위 밖 발견물: 티켓 20261007_2121(아이템 배지 만료 서술 정정)을 조사하다 발견했다.

## 핵심 요약
- 요구사항: 어드민 시뮬레이션(`dryRun`이 아닐 때)이 아이템 배지를 지급하는 방식을 실제 동기화 드랍과 맞춘다. 만료값과 지급 경로(RPC) 두 가지가 다르다.
- 구현 계획: 시뮬레이션의 직접 삽입을 `grant_inventory_item()` RPC 호출로 바꾸고, `p_expires_at`을 동기화 드랍과 같은 규칙으로 넘긴다. 바꾼 뒤 `SERVICE_OPERATIONS.md` 7-1 「만료값」 표의 어드민 시뮬레이션 행을 갱신한다.
- 관련 파일: `jam-web/src/app/api/admin/simulate/route.ts` 151~168행(`inventory_items` 직접 `insert`, `expires_at` 지급 시점 + 30일, 이어서 `inventory.used_slots`를 `update`), 비교 기준 `jam-web/src/lib/drop-engine/index.ts` `insertDrop()` 509~516행(`picked.valid_until ?? null`을 `grant_inventory_item` RPC로 넘김)

## 배경 / 문제 정의

2026-10-08에 코드로 확인한 사실:

- 동기화 드랍(`insertDrop()`)은 `grant_inventory_item()` RPC(마이그레이션 173)로 개체 삽입과 `used_slots` 증가를 한 트랜잭션에서 처리하고, 만료값으로 그 배지의 공개 종료일(`valid_until`, 없으면 NULL)을 넘긴다.
- 어드민 시뮬레이션은 같은 `obtained_by: 'drop'`을 쓰면서 `inventory_items`에 직접 삽입하고, 만료값으로 지급 시점 + 30일을 넣는다. 그 뒤 `inventory.used_slots`를 루프 전에 읽어 둔 값 + 삽입 개수로 덮어쓴다.
- 결과: 시뮬레이션으로 받은 개체만 만료일이 화면에 표시되고, `used_slots` 갱신이 마이그레이션 173이 다른 경로에서 없앤 "읽은 뒤 덮어쓰기" 방식으로 남아 있다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 시뮬레이션 지급을 `grant_inventory_item()` RPC로 바꾼다. 슬롯이 찼을 때(`slot_full`)의 처리는 동기화 드랍과 같게 한다.
- 만료값은 `SERVICE_OPERATIONS.md` 7-1 「만료값」 표의 동기화 드랍 행과 같은 규칙을 쓴다.

## 구현 계획
- `admin` 유형. 코드 변경이 있으므로 `/jam-work` 표준 절차로 처리한다.

## 완료 조건
- 시뮬레이션 지급 경로에 `inventory_items` 직접 `insert`와 `used_slots` 직접 `update`가 없다.
- 시뮬레이션이 넘기는 `p_expires_at`이 동기화 드랍과 같은 규칙이다.
- `SERVICE_OPERATIONS.md` 7-1 「만료값」 표의 어드민 시뮬레이션 행이 바뀐 동작과 일치한다.
