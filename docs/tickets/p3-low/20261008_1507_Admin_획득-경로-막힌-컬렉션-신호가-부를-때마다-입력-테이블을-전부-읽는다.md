# [Admin] 「획득 경로가 막힌 컬렉션」 신호가 부를 때마다 입력 테이블을 전부 읽는다

## 핵심 요약
- 요구사항: 운영 신호 「획득 경로가 막힌 컬렉션」(수준 `info`, 알림에 쓰지 않음) 때문에 매시 중단 점검 크론까지 아이템 배지·조합식·미션 전체를 읽는 부담을 줄인다. 크론 실행 시간과 DB 부하를 재 보고 필요하면 호출처별로 이 원천을 건너뛰거나 결과를 짧게 캐시한다.
- 구현 계획: (미정 — 착수 시 작성) 먼저 매시 크론 실행 시간과 이 원천의 읽기 시간을 잰다. `stopAlert.ts`가 `info` 신호를 쓰지 않는다면 그 호출에서 `item_paths` 원천을 빼는 방향.
- 관련 파일: `jam-web/src/lib/admin/opsSignals/load.ts` L441-478(`settle`·`Promise.all`), L516 부근(`loadItemPathInputs`) / 호출처: `jam-web/src/lib/admin/opsSignals/stopAlert.ts`(매시 크론 `/api/cron/ops-stop-signals`), `jam-web/src/lib/admin/opsSchedule/load.ts`, `jam-web/src/app/admin/_home/sections.tsx` / 신설 티켓: 20261008_1301

## 배경 / 문제 정의

### 확인한 사실 (2026-10-08 15:06 KST, 민지 배포 전 보안 점검 모드 ②)
- 티켓 20261008_1301이 `loadOpsSignals`에 새 원천 `item_paths`를 더했다. 이 원천은 `item_books`, 아이템 배지(3,600개 이상), `combination_recipes`, `missions`를 전체 페이지 읽기로 가져온다.
- `loadOpsSignals`는 운영 홈, 일정표, 매시 중단 점검 셋에서 부른다. 신호 수준은 `info`라 중단 알림 계산에는 쓰이지 않는다.
- 읽기가 실패해도 `settle('item_paths')`가 가둬 중단 알림 계산을 막지 않는다.

### 판단
- 서비스 거부로 이어질 경로는 없고, 크론 실행 시간과 DB 읽기만 늘었다. 실제 증가량은 재 보지 않았다. **위험도: 참고, 확신도 보통.**

## 완료 조건
- (착수 시 구체화) 매시 크론 1회 실행 시간과 읽은 행 수를 변경 전후로 비교해 기록한다.
