# [API] 오늘 카드 노출·열람 지표(byPattern 포함)를 로그인 유저가 부풀릴 수 있다

## 핵심 요약
- 요구사항: `POST /api/today/events`로 쌓는 카드 노출·열람 기록을 한 유저가 반복 전송해 부풀리지 못하게 하거나, 지표를 읽는 쪽에서 부풀린 값을 걸러낼 수 있게 한다. 패턴 사전이 `byPattern`을 패턴 사용 판단의 근거로 쓰기 시작하기 전에 정한다.
- 구현 계획: (미정 — 착수 시 작성) 유저별 중복 제거 키(익명화한 유저 키 + 카드 + 날짜 등)를 둘지, 속도 제한을 인스턴스 메모리 밖(DB·KV)으로 옮길지 비교한다.
- 관련 파일: `jam-web/src/lib/today/events.ts` L178-189(기록 시 `pattern_no` 복사), `jam-web/src/app/api/today/events/route.ts` L27-30(인스턴스 메모리 `Map` 속도 제한), `jam-web/src/app/api/admin/today/metrics/route.ts`(`byPattern` 집계)

## 배경 / 문제 정의

### 확인한 사실 (2026-10-08 15:06 KST, 민지 배포 전 보안 점검 모드 ②)
- 이벤트 라우트는 카드가 활성이고 기간 안인지만 확인하고 유저 ID를 저장하지 않아, 같은 유저의 반복 전송을 구분할 수 없다.
- 속도 제한은 인스턴스 메모리의 `Map`이라 서버리스 환경에서는 인스턴스마다 따로 센다.
- `pattern_no`는 요청 값이 아니라 DB의 카드 값을 복사하므로 임의 패턴 번호 주입은 없다.
- 유형별·모양별 집계에도 원래 있던 성질이고, 티켓 20261008_1059가 패턴별 집계(`byPattern`)를 더했다.

### 판단
- 지표 왜곡일 뿐 데이터 노출·권한 문제는 없다. 다만 패턴 사전의 사용 판단에 쓰면 영향이 커진다. **위험도: 참고, 확신도 높음.**

## 완료 조건
- (착수 시 구체화) 같은 유저가 같은 카드 이벤트를 짧은 시간에 반복 전송해도 집계가 한 번만 늘어난다는 것을 테스트로 고정한다.
