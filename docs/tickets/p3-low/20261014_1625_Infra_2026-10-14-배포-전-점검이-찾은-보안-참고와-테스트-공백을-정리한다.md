# [Infra] 2026-10-14 배포 전 점검이 찾은 보안 참고와 테스트 공백을 정리한다

## 핵심 요약

- 요구사항: `/jam-ship` 5단계 병렬 점검(민지 모드 ②·③, 범위 `836983f78..1e2d55e27`)이 찾은 발견물 중 이번 배포에서 처리하지 않는 것을 한 곳에 모아 둔다. 중단급은 없었다.
- 구현 계획: 항목별로 필요한 것만 골라 티켓을 나눈다. 이 티켓은 목록과 근거를 보관한다.
- 관련 파일: 항목마다 아래에 적었다.

## 배경 / 문제 정의

분리해서 처리한 두 건은 이 티켓에 넣지 않았다: P0 `20261014_1623`(users 본인 행 `is_admin` 쓰기), P2 `20261014_1624`(유저 검색 이메일 부분일치). 아래 내용은 코드와 테스트를 읽어 대조한 결과이고 민지는 테스트를 직접 실행하지 못했다.

## 보안 참고 (모드 ②)

1. **Strava 연동 이력 점검**: OAuth state 수정(1349) 이전에 남의 `user_id`로 다른 athlete가 연결된 적이 있는지는 코드로 확인할 수 없다. `strava_connections`에서 이상 연결이 있는지 DB로 점검한다(확신도 보통).
2. **`strava_connections` 본인 행 INSERT·UPDATE가 열려 있다**(`001_initial_schema_rerun.sql` 167~168행). 타인 행에는 영향이 없다. 토큰 열을 클라이언트가 쓸 수 있는지 검토한다.
3. **프로필의 공개 노출**: `[username]/page.tsx`가 타인의 `feedItems`(150행)와 `activityNames`(Strava 활동 제목)를 내려보낸다. 설계상 공개이나 제목은 유저가 쓴 자유 텍스트라 위치가 섞일 수 있다(347~357행 부근).
4. **쓰기 라우트가 Origin·Content-Type을 보지 않고 SameSite=Lax 쿠키에 기댄다**(기존 어드민과 같은 패턴, 낮음).
5. **OAuth 쿠키에 `__Host-` 접두사가 없다**(낮음). 신뢰하지 않는 형제 서브도메인이 없으면 해당 없다.
6. **Strava 토큰 암호화가 AES-256-CBC 무인증이다**(`lib/utils.ts` 85행 부근). 암호문이 DB 안에만 있어 악용 경로는 없다(낮음).
7. **`seed_cleanup_drops_map_trace_20261010.sql`에 실제 유저 UUID가 있다.** 비공개 저장소라 위험은 낮다.
8. **배포 시각에 OAuth를 시작한 유저**는 쿠키가 없어 `state_mismatch`로 한 번 실패한다. 의도된 동작이고 다시 시도하면 된다.
9. **`users`의 다른 열도 로그인한 유저가 직접 쓸 수 있다**(데일리 미팅 2026-10-14 윈터·카즈하 제안). 마이그레이션 219는 `is_admin`만 막는다. 같은 구조로 `tribe_id`(JAM 2.0에서 「바꿀 수 없는 정체성」으로 공개할 값), `gps_daily_distance_km`·`gps_daily_distance_date`(하루 이동 거리 상한 우회), `initial_sync_done`(첫 동기화 제한 우회), `last_location_*`가 열려 있다. 근거: 2026-10-14 라이브 DB에서 확인한 정책(열 제한 없음)과 권한(`authenticated`의 테이블 UPDATE). 열마다 직접 쓰기를 시도하지는 않았다. 열마다 클라이언트가 쓸 이유가 있는지 확인해 트리거나 권한 회수로 막는다.
10. **어드민 조치 변경 기록(감사 로그)이 없다.** `is_admin` 변경 이력을 남기지 않아 과거 악용 여부를 단정할 수 없다. JAM 2.0 요구로 올릴지는 데일리 미팅 2026-10-14의 결정 요청 1이다. 2026-10-15 사용자가 반영을 결정해 「JAM 2.0 서비스 운영 로직」 1.4절에 공통 변경 기록과 유저 정보 노출·수정 범위 목록을 디자인 명세 필수 요구로 넣었다. 지금 서비스에 기록을 붙일지는 정하지 않았다.

## 테스트 공백 (모드 ③)

주의 4건:

1. **주간 KPI 분리 테스트가 기간 필터를 검증하지 못한다.** 모의의 `gte`·`lt`가 인자를 버리고 모의 행에 `occurred_at`이 없다. `jam-web/src/lib/admin/__tests__/kpi-weekly.test.ts` 54~60행, `jam-web/src/lib/admin/kpiWeekly.ts` 201~211행.
2. **`changeOpsPatternStatus`의 조회·쓰기 오류 500 경로와 「읽은 뒤 행이 사라짐 → 404」(`resolveEmptyUpdate`) 경로에 테스트가 없다.** `jam-web/src/lib/admin/opsPatterns/write.ts` 263~307행.
3. **패턴 사전 쓰기 화면의 클릭 흐름이 고정돼 있지 않다**: 저장 중복 클릭 가드, 409 후 [최신 내용 불러오기], 상태 바꾸기 확인창, 근거 선택·저장. jsdom·testing-library가 없다. `OpsPatternForm.tsx`, `OpsPatternStatusMenu.tsx`, `OpsTasteSignalEditor.tsx`.
4. **서버 페이지 4개에 직접 테스트가 없다**: `app/admin/ops-patterns/page.tsx`, `[patternNo]/page.tsx`, `[patternNo]/edit/page.tsx`, `new/page.tsx`. 같은 영역에 선례가 있다(`app/admin/__tests__/home-page.test.tsx`).

참고 6건:

5. 패턴 제안 승인(`approvePatternProposal`, `lib/admin/opsInbox/decide.ts` 244~330행)은 실DB 실행 기록이 없다. 첫 실행은 11/1 월간 루틴이다.
6. 같은 승인 흐름의 두 분기에 테스트가 없다: 결정 기록 실패 뒤 재승인에서 `findOpsPatternByOriginItem`이 null·오류인 경우, `restoreStatus` 자체가 실패해 항목이 `ended`로 남는 경우.
7. 패턴 손잡이 칸 정의가 세 곳에 있고 같음을 고정하는 테스트가 없다: `opsPatterns/constants.ts`, `opsInbox/validate.ts`, `opsPatterns/input.ts`.
8. 프로필 prop 회귀 테스트의 가짜가 피드·인벤토리를 빈 목록으로 돌려줘 타인 피드 행의 직렬화는 검사에 걸리지 않는다.
9. 드랍 시도 실패 기록: 한 배치에서 연속 실패해 행이 여러 건 쌓이는 경우와 `classifyStravaSyncFailure`가 새 값을 내지 않는 것의 직접 고정이 없다.
10. 자산 등록 스크립트 3종의 링크 검증 정규식이 `(docs|jam-doc)`에서 `docs`로 좁아졌다. `jam-doc/…`가 거절됨을 고정하는 음성 테스트가 없다.
11. 새 PostgREST 질의(`ops_bundles!inner` 임베드, 임베드 칸 `.eq`, `count:'exact'`+`range`)의 실DB 실행 기록이 일부 없다: `listPatternRejections`, `countPendingPatternProposals`, `loadPatternUsageRows`.
12. `createOpsPattern`(수동 만들기)에 멱등 키가 없다. 응답이 끊긴 뒤 다시 저장하면 패턴이 두 번 만들어질 수 있다(설계 판단 사항, 확신도 낮음).
13. `scripts/verify.sh`에 `next build` 단계가 없다. 이번에는 staging의 Vercel 빌드와 사용자의 staging 확인으로 갈음했다.
