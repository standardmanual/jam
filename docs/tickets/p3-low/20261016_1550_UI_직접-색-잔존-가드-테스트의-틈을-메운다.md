# [UI] 직접 색 잔존 가드 테스트의 틈을 메운다

## 핵심 요약

- 요구사항: `jam-web/src/components/__tests__/dsLiteralColors.test.ts`(3회)의 `TEXT_COLOR_WITH_PROGRESS_TOKEN`은 `color: ... var(--progress-*)` 꼴만 잡고 `TEXT_COLOR_VARIABLE`은 변수명이 caption/text/value/label/pct/ramp + Color일 때만 잡는다. `DualAxisGauge.jsx` AxisRow처럼 `const color = met ? ... : ...`를 만든 뒤 `{ color }` 단축 속성으로 쓰는 꼴은 둘 다 못 잡는다(`const color = met ? 'var(--progress-done)' : ...`를 넣어도 매칭 0건). 또 `color: 'white'`·`'black'` 키워드, `rgb()`·`hsl()` 함수, `#fafafa` 같은 다른 hex도 못 잡는다(`jam-web/src/components/__tests__/dsLiteralColors.test.ts:62`). 스토리 `play`는 CI에서 안 돌아 이 vitest가 유일한 자동 가드다.
- 구현 계획: 변수명 패턴에 단독 `color`·`tone`을 넣고 `color,` 단축 속성도 검사한다. 리터럴 키워드·함수·다른 hex도 막는다. 지도 마커의 면–글리프 짝(`MapView.tsx:233-247`, 문자열 HTML을 만드는 비공개 함수 안)은 짝 자체를 고정하는 테스트를 따로 둔다.
- 근거: 티켓 20261015_2134 3회·2회 민지·채원② 발견물.
