# [Admin] 어뷰징 정책 화면의 숫자 입력칸이 값을 지우면 기본값으로 되돌아가는 문제를 고친다

## 핵심 요약

- 요구사항: 어뷰징 정책 화면의 숫자 입력칸이 `parseInt(값) || 기본값` 형태라서 값을 모두 지우는 순간 기본값(예: 6)으로 되돌아간다. 새 값을 처음부터 다시 입력하기 어렵다. 입력 도중의 빈 값을 허용하고 저장할 때 검증하게 고친다.
- 구현 계획: 한 번에 돌린다. 화면의 모든 숫자 입력칸(기존 칸 포함)에 같은 방식을 적용한다.
- 관련 파일(2026-10-17 게이트 판독, 시작 때 아현이 줄 위치를 다시 확인한다): `jam-web/src/app/admin/abusing/AbusingClient.tsx`(정책 탭 입력칸, 366 부근의 `parseInt(...) || 기본값`), `jam-web/src/app/api/admin/abusing/policy/route.ts`(저장 검증). 스펙: 어드민은 shadcn/ui 표준이다.

## 배경 / 문제 정의

티켓 20261017_1421 2회가 정책 입력칸 2개를 더하면서 기존 칸과 같은 패턴을 따랐고, 게이트가 이 패턴의 불편을 짚었다. 값을 지우면 기본값이 들어가 «지우고 다시 쓰기»가 어렵다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 입력 도중에는 빈 문자열을 허용하고, 저장 시점에 서버 검증(1 이상의 정수 등)이 오류를 돌려주게 한다. 저장 검증은 이미 서버에 있다.
- 어드민 화면은 MODULAR 적용 대상이 아니며 shadcn/ui 표준을 따른다. 실렌더 확인은 카리나가 로컬에서 한다.

## 구현 계획

한 번에 돌린다. 요약은 2,500자 이내.

## 완료 조건

- 입력칸의 값을 모두 지워도 기본값으로 되돌아가지 않고, 저장 시 비어 있으면 오류 문구가 보인다. 확인 방법은 단위 시험과 로컬 실렌더다.
- 기존 입력칸의 정상 저장 동작이 바뀌지 않는다.
