# [Admin] 어드민 드랍 시뮬레이터와 미리보기를 JAM 2.0 동기화 발급 규칙에 맞춘다

## 핵심 요약

- 요구사항: 티켓 20261017_1424 2회가 동기화 아이템 배지 발급을 소속 트라이브 기준의 새 규칙(개수, 등급, 후보, 한 등급 내림 폴백)으로 바꿨다. 그러나 어드민 시뮬레이터 라우트가 부르는 `tryItemDrop`과 미리보기(`preview.ts`)는 옛 규칙(트라이브 고르기, 보정 셋)을 따라 실제 발급과 어긋난다. 운영이 시뮬레이터로 확인하는 값과 실제 동작이 같게 맞춘다.
- 구현 계획: 한 번에 돌린다. 어드민이므로 shadcn/ui 표준을 따르고 MODULAR 적용 대상이 아니다. 시작 전에 시뮬레이터의 쓰임(밸런스 확인 용도)을 확인한다.
- 관련 파일(2026-10-17 게이트 판독, 시작 때 아현이 위치를 확인한다): `jam-web/src/lib/drop-engine/preview.ts`, `jam-web/src/lib/drop-engine/index.ts`(`tryItemDrop`), 어드민 시뮬레이터 라우트(`tryItemDrop` 호출처 검색), `jam-web/src/lib/drop-engine/syncIssue.ts`(새 판정). 스펙: 운영 로직 6.2절.

## 배경 / 문제 정의

2-4 2회는 동기화가 `tryItemDrop` 대신 새 모듈(`syncIssueRun.ts`)을 쓰게 했지만, `tryItemDrop`은 어드민 시뮬레이터가 부르므로 지우지 않았다. 지금 미리보기는 옛 트라이브 고르기·등급 보정을 계산하므로 운영이 새 설정(정책 테이블의 확률, 확정 개수)을 바꿔도 시뮬레이터에 반영되지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 시뮬레이터와 미리보기가 새 판정(`syncIssue.ts`)과 정책 테이블(`jam_policy`) 값을 쓰게 한다.
- 시뮬레이터가 실제 유저 데이터를 바꾸지 않게 한다(미리보기 전용).

## 구현 계획

한 번에 돌린다. 요약은 2,500자 이내.

## 완료 조건

- 시뮬레이터의 개수·등급·후보 결과가 실제 동기화 발급과 같은 판정 함수를 쓴다. 확인 방법은 같은 입력에서 두 경로가 같은 결과를 내는 시험이다.
- 옛 규칙을 쓰던 미리보기 코드 가운데 더 이상 호출되지 않는 부분이 정리되어 있다.
