# [Admin] 어드민 홈의 제재 집계가 옛 섀도우밴 테이블을 읽는다

## 핵심 요약

- 요구사항: 티켓 20261017_1426 1회 게이트가 짚었다. 어드민 홈 섹션(`jam-web/src/app/admin/_home/sections.tsx` 154줄 근처)이 `user_shadow_bans`를 직접 읽는데, 비교표 3.20절의 «남은 섀도우밴 경로» 표에 없다. 이용 정지(`user_suspensions`)로 바뀐 뒤에도 홈 숫자가 옛 테이블 기준으로 남는다.
- 구현 계획: 2-6 2회(어드민 제재 탭을 이용 정지 기준으로 다시 쓰는 일)에서 함께 처리하는 것이 자연스럽다. 2회 시작 때 이 항목을 범위에 넣을지 정하고, 넣지 않으면 묶음 7(어드민)에서 처리한다. 비교표 3.20절의 남은 경로 표에 이 경로를 더한다.
- 관련 파일: `jam-web/src/app/admin/_home/sections.tsx`, `jam-web/src/app/admin/__tests__/home-sections.test.tsx`, `docs/plan/jam2/service-redesign/현재 서비스 비교.md` 3.20절.

## 완료 조건

- 어드민 홈의 제재 집계가 이용 정지 기준으로 나오거나, 옛 테이블을 읽는 것이 의도임이 문서에 적혀 있다.
- 비교표 3.20절의 남은 경로 표에 이 경로가 있다.

## 완료 기록

티켓 20261017_1426 2회에서 처리했다(2026-10-17). 어드민 홈 서비스 점검의 제재 집계를 `user_shadow_bans`에서 `user_suspensions` 진행 중 건수로 바꿨다(`jam-web/src/app/admin/_home/sections.tsx`의 `readSuspensions`). 시험(`home-sections.test.tsx`)은 옛 표를 읽지 않음을 고정한다. 비교표 3.20절 남은 경로 표에서 이 경로를 뺐다. 카드 링크는 기존 시험이 요구해 `/admin/abusing`(정책 탭) 그대로다.
