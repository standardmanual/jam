# [Infra] graphify(코드 지식 그래프 도구)를 jam-work에 반영할 수 있는지 검토한다

## 핵심 요약

- 요구사항: GitHub 저장소 `Graphify-Labs/graphify`를 jam-work에 반영하고 싶다는 요청이 있어, 반영 가능성과 충돌 지점을 먼저 검토한다.
- 검토 의견(확신도 보통): 지금 바로 jam-work에 상시 도입하지 않는다. 저장소를 건드리지 않는 읽기 전용 시험으로 효과를 먼저 재고, 그 결과로 도입 여부를 정한다.
- 구현 계획: 코드 변경 없음. 시험을 승인받으면 「시험 설계」 절차로 진행하고 결과를 이 티켓에 기록한다.
- 관련 파일(도입하기로 결정했을 때 손댈 후보): `.claude/agents/jam-developer.md` 198행 `## Token discipline`, `.claude/agents/jam-reviewer.md`, `.claude/workflows/jam-work.js`(아현·민지 프롬프트), `.claude/skills/jam-work/references/handling-rules.md`(카리나 섹션). 건드리지 않을 곳: 루트 `CLAUDE.md`, `.claude/settings.json`의 hooks, `.githooks/`.
- 관련 티켓: [서브에이전트 토큰 누적 절감 (20260918_1553)](../p2-normal/20260918_1553_Infra_서브에이전트-작업중-토큰누적-절감.md), CLAUDE.md 고정 비용 정리(20261015_1225)

## 배경 / 문제 정의

graphify는 코드·SQL·문서를 읽어 "어떤 함수가 어디서 호출되는가" 같은 관계를 그래프로 저장하고, 에이전트가 `graphify query`로 필요한 부분만 조회하게 하는 도구다. jam-work에서는 아현이 탐색에 쓰는 토큰을 줄이거나, 놓치기 쉬운 호출처를 찾는 데 쓸 수 있을지가 쟁점이다.

JAM!에는 이미 비슷한 문제를 다룬 기록이 있다.

- 토큰: 서브에이전트 토큰 누적 절감 티켓이 아현의 통독·재독·초반 탐색을 문제로 짚었고, 티켓 「관련 파일」 지도와 `offset/limit` 읽기 규칙으로 대응해 머지했다. 다만 성공 기준(다음 실제 구현 티켓에서 `npm install`과 300줄 초과 통독이 없는지)은 아직 관찰하지 못해 `WAITING`이다. 그래서 지금은 효과를 비교할 기준선이 없다.
- 놓친 호출처: `handling-rules.md`에 `fn(prop)` 형태의 호출을 찾지 못해 게이트 WARN이 난 사례(티켓 20261008_1354)와, 문서 서술을 뒤집는 티켓에서 전수 검색이 빠진 사례(티켓 20260926_2229)가 남아 있다. 호출 그래프가 이런 누락을 줄일 가능성이 가장 큰 사용처다.

## 확인한 사실 (2026-10-19, 명령으로 확인)

저장소와 배포본

- 저장소는 `Graphify-Labs/graphify`, 기본 브랜치 `v8`, 라이선스 Apache-2.0(`LICENSE-MIT`도 포함), 별 128,449개, 열린 이슈 1,555개다. 보관(archived) 상태가 아니다.
- 최신 릴리스는 0.9.92(KST 2026-10-17 02:57)다. 0.9.91은 KST 10-15 07:17, 0.9.90은 KST 10-14 07:17에 나와서 3일 사이 3회 릴리스됐다. 1.0 이전 버전이다.
- PyPI 패키지명은 `graphifyy`(y가 둘)이고, 메타데이터의 Repository 주소가 위 GitHub 저장소를 가리킨다. `graphify`(y 하나) 이름은 PyPI에서 조회되지 않았다. 따라서 설치할 때 철자를 정확히 지켜야 한다.
- 필수 의존성은 Python 3.10 이상, networkx, numpy, rapidfuzz, tree-sitter와 언어별 문법 약 25개다. SQL 문법(`tree-sitter-sql`)은 선택 항목 `sql`에 있다.

동작과 설치가 바꾸는 것(소스 `install.py`·`hooks.py`·`cli.py`·`SECURITY.md` 확인)

- 코드 추출은 로컬 AST 파싱이다. `graphify update .`는 AST 전용이라 API 비용이 없다고 설치 블록에 적혀 있다. 문서·이미지의 의미 추출은 모델 호출을 쓴다.
- `graphify install`은 프로젝트 루트 `CLAUDE.md`에 `## graphify` 섹션(규칙 5줄)을 쓴다. 그 규칙에는 코드를 탐색하는 모든 서브에이전트 프롬프트에 같은 규칙을 넣으라는 문구가 들어 있다.
- 같은 설치가 `.claude/settings.json`에 PreToolUse 훅 2개(`Bash|Grep`, `Read|Glob`, 제한 시간 10초)를 등록한다. 안내 문구는 에이전트마다 기본 5회까지만 나온다(`GRAPHIFY_HOOK_NUDGE_CAP`). `--strict`를 켜면 세션의 첫 원문 읽기를 차단한다.
- `graphify hook install`은 git의 `post-commit`·`post-checkout`·`post-merge`·`post-rewrite` 훅을 설치하고, `core.hooksPath`가 있으면 그 경로를 따른다.
- 산출물 폴더 `graphify-out/`의 위치는 환경변수 `GRAPHIFY_OUT`으로 바꿀 수 있다. 설치 블록은 `graph.json`을 커밋하는 구성을 전제로 적혀 있다.
- Postgres 연결 옵션(`--postgres`, 추가 의존성 `psycopg`)이 있어 실제 DB의 DDL을 읽을 수 있다.
- 사용 중인 PC의 `python3`는 3.14.6이고 `uv`는 설치돼 있으며 `pipx`는 없다. Python 3.14에서 tree-sitter 휠이 설치되는지는 확인하지 않았다.

JAM! 쪽 규모

- 추적 파일 8,248개: `jam-web` 4,930개, `docs` 3,166개. 확장자별로는 `.ts` 약 1,240개, `.tsx` 약 610개, `.sql` 약 340개, `.md` 약 3,100개다.

README 주장(검증하지 않음)

- 토큰 절감 71.5배는 코퍼스 크기에 따라 달라지며, 파일 6개 규모에서는 약 1배라고 README가 직접 밝힌다. JAM! 규모에서의 효과는 측정 전이다.

## 판단 (위 사실과 분리해서 적는다)

충돌 지점

1. 고정 비용: 루트 `CLAUDE.md` 섹션은 모든 서브에이전트 호출에 자동 포함된다. 진행 중인 CLAUDE.md 고정 비용 정리 티켓(20261015_1225)과 방향이 반대다. 규칙을 넣는다면 `jam-developer.md`·`jam-reviewer.md`와 `jam-work.js` 프롬프트처럼 필요한 에이전트에게만 넣는다.
2. 작업 폴더 규칙: `graphify-out/`가 저장소 안에 생기면 untracked 파일이 남는다. 프로젝트 규칙 4번(untracked 금지, `.gitignore` 신규 항목 금지)과 어긋난다. 저장소 밖으로 `GRAPHIFY_OUT`을 돌리거나, 커밋하는 구성이라면 `graph.json`이 빌드마다 통째로 바뀌는 diff를 감수해야 한다.
3. git 훅: `.githooks/`는 계약 검사 대상이고 아현이 만드는 격리 워크트리마다 커밋이 일어난다. 4종 훅을 붙이면 병렬 작업 때 커밋마다 재빌드가 돌 수 있다. 계약 검사가 이 변경을 막는지는 확인하지 않았다.
4. 그래프 최신성: 아현의 격리 워크트리는 main 기준으로 만들어진 뒤 `origin/staging`을 체크아웃한다. 그래프를 한 곳에서 공유하면 어느 브랜치 기준인지 모르는 오래된 그래프를 읽을 수 있다.
5. 운영 위험: 1.0 이전 버전이 며칠 간격으로 바뀌므로 버전을 고정해야 한다. Python 도구라서 Node 기반 저장소에 새 실행 환경이 생기고, PC마다 따로 설치해야 한다.
6. 공용 DB: Supabase가 staging·프로덕션 공용 단일 DB라 `--postgres` 연결은 쓰지 않는다. 마이그레이션 SQL 파일만 읽게 한다.

기대 효과가 있는 자리

- 카리나가 티켓을 쓸 때 「관련 파일」 지도를 만드는 단계와, 민지가 변경 함수의 호출처를 확인하는 단계다. 아현의 탐색은 지도 규칙이 이미 있으므로 추가 효과가 작을 가능성이 크다.

## 시험 설계 (제안, 사용자 승인 전에는 실행하지 않는다)

1. 격리: 저장소 밖(스크래치패드)에 `uv` 가상환경을 만들고 `graphifyy==0.9.92`로 버전을 고정해 설치한다. 외부 패키지를 내려받는 일이라 사용자 승인 뒤에만 한다.
2. 설치 범위: `graphify install`과 `graphify hook install`은 실행하지 않는다. 출력은 `GRAPHIFY_OUT`으로 저장소 밖에 둔다. 저장소의 `git status`는 시험 전후로 같아야 한다.
3. 입력 범위: `jam-web`의 ts·tsx와 `supabase/migrations`의 sql만 AST 방식으로 읽는다. `docs/`와 이미지는 제외한다(문서 추출은 모델 호출 비용이 든다).
4. 비교 질문 두 가지: (가) 티켓 20261008_1354의 「`fn(profile)` 호출까지 찾기」를 그래프 질의로 재현할 수 있는가. (나) 티켓 20260926_2229처럼 특정 함수·테이블을 쓰는 곳을 전수로 찾을 수 있는가. 같은 질문을 `git grep`으로 풀 때와 도구 호출 수·읽은 양을 비교한다.
5. 기록할 값: 첫 빌드 시간, 증분 빌드 시간, 그래프 크기, 두 질문의 재현 여부, Python 3.14 설치 가능 여부. 시간 기준은 결과를 보고 정한다.

## 완료 조건

- 시험을 승인받아 실행했다면, 위 5개 값과 `git status` 전후 동일 여부가 이 티켓 완료 기록에 적혀 있다.

- 시험 중 저장소에 새 파일·훅·설정 변경이 생기지 않았다.
