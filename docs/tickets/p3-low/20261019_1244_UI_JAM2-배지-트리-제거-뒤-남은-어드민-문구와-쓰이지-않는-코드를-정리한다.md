# [UI] JAM2 배지 트리 제거 뒤 남은 어드민 문구와 쓰이지 않는 코드를 정리한다

## 핵심 요약

- 진행 메모 (2026-10-19 사용자 결정): 묶음 5의 5-8(티켓 `20261019_1318`)에서 함께 처리한다. 그 티켓이 끝나면 이 티켓을 CLOSED로 바꾼다.
- 요구사항: 4-6 2회가 배지 트리 화면과 MODULAR 9종을 지웠다(진행 표시는 사용자 결정으로 두지 않았다). 제거된 화면을 가리키거나 읽는 곳이 없어진 코드가 남아 있어 정리한다.
- 구현 계획: 아래를 하나씩 확인해 지우거나 고친다. 지울 때는 시험·문서·Story를 함께 고친다.
  1. 어드민 문구 `jam-web/src/app/admin/badges/BadgeConditionSection.tsx` 690줄 근처 «이 조건은 배지 트리 화면에 진행률이 표시되지 않아요» 경고와 `progressIssue`: 진행이 어디에도 보이지 않으므로 경고의 뜻이 사라졌다. 경고와 그 계산(`lib/badge-engine/badgeProgress.ts` 730줄 근처 설명 포함)을 지울지 정한다. `BadgeForm.tsx` 72·608줄 주석도 같이 고친다. «지표 이름» 화면 설명(진행 축 라벨)도 같다.
  2. 읽는 곳이 없어진 쓰기 경로: `jam-web/src/lib/strava/sync.ts`의 `updateFamilyProgressSnapshots`와 표 `user_family_progress`(동기화마다 쓰지만 읽는 곳이 없다). 표 정리는 묶음 6의 확장→전환→축소 규칙을 따른다.
  3. 시험에서만 쓰이는 코드: `jam-web/src/lib/badgeTree.ts`의 `buildBadgeActivityTrees`(`badgeTree.test.ts`·`hidden-badges.test.ts`만 호출), 파일 이름 변경(어드민과 `badgeProgress.ts`가 `TREE_ACTIVITY_ORDER`·`sortRank`·`BadgeTreeLock`을 쓴다).
  4. 서비스 소비처가 없는 MODULAR: `BadgeStatusGlyphs`(소비처 전부 삭제), `RecentSyncBanner`(호출부 없음). 삭제하려면 Story와 문서를 함께 고친다. `ProgressBar`·`Accordion`의 주석에 삭제된 이름이 이력으로 남아 있다.
  5. claude.ai/design 사본에 MODULAR 삭제 9종이 반영되지 않았다(DesignSync 인증이 막혀 있음, 티켓 `20260920_2220` WAITING, 모드 ③ 동기화로 처리).
- 관련 파일: 위 본문, `docs/service/prd/`·`docs/plan/jam2/11 JAM 2.0 디자인 시스템.md`.
