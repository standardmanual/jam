# [Service] JAM2 미션 즉시 판정: 믹스·캡슐 열기·드랍·픽업 직후에 미션 완료를 판정한다

## 핵심 요약

- 요구사항: 5-2b(티켓 `20261019_1445`)가 믹스·드랍·픽업·캡슐 열기 같은 DB 기록 키를 미션 조건으로 판정하게 하지만, 미션 판정(`checkMissions`)의 호출처는 `jam-web/src/lib/strava/sync.ts` 1221줄(새 활동이 있는 동기화) 한 곳이다. 믹스·캡슐 열기·드랍·픽업·아이템북 슬롯·잠긴 개체 열기 API(`app/api/combine/route.ts`, `capsule/open`, `drops/route.ts`, `drops/[dropId]/pickup`, `itembooks/[id]/slot`, `inventory/items/[itemId]/open`)는 `runJamActionEvaluation`으로 배지만 판정한다. 그래서 «믹스 3번 성공» 미션은 믹스한 순간이 아니라 다음 활동 동기화 때 완료된다(사용자 결정 2026-10-19, 5-2b 결정 4).
- 구현 계획: 시작 때 두 가지를 정한다. (1) 판정 비용: `checkMissions`가 활동 이력 전체를 매번 읽으므로(`checker.ts` 168~170줄) API마다 부르면 무겁다. DB 키만 가볍게 판정하는 별도 진입점(활동 이력을 읽지 않고 DB 키가 든 미션만 대상)이 필요한지 정한다. (2) 완료 시 보상·소식 흐름(`mission_complete` → `grantMissionRewards`)을 API 응답 시간에 얹어도 되는지, 비동기로 돌릴지 정한다. 5-2b 1회가 끝난 뒤의 로더(`lib/missions/dbMetrics.ts`)를 재사용한다.
- 관련 파일: `jam-web/src/lib/missions/checker.ts`, `jam-web/src/lib/badge-engine/jamActionRoute.ts`(`runJamActionEvaluation`, 라우트 6개의 공통 진입), `jam-web/src/lib/strava/sync.ts`.

## 완료 조건

- 믹스·캡슐 열기·드랍·픽업·잠긴 개체 열기 직후, 그 행동으로 조건이 채워지는 미션이 같은 요청 또는 곧바로 이어지는 처리에서 완료된다(시험으로 확인).
- API 응답 시간이 늘어나는 정도와 이력 읽기 비용이 이 티켓에 기록되어 있다.
