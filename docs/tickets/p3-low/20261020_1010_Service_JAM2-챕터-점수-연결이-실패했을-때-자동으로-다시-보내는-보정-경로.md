# [Service] JAM2 챕터 점수 연결이 실패했을 때 자동으로 다시 보내는 보정 경로

## 핵심 요약

- 요구사항: 5-5(티켓 `20261019_1315`)는 점수 연결이 실패해도 본 동작을 성공시키고 실패를 `engine_decision_log`(`chapter_score_failed`)에 기록만 남긴다. 같은 원천 id로 다시 보내면 DB(`chapter_add_score`)가 멱등이라 안전하지만, 다시 보내는 경로가 없다. 실패한 점수가 영구히 빠지지 않게 보정 경로를 만든다.
- 확인한 사실(2026-10-20, 5-5 시작 전 조사): 지점마다 원천 행과 날짜를 복원할 수 있다. 모은 잼은 `jam_transactions`(`reason='activity_settlement'`, 날짜는 `strava_activities.start_date`), 캡슐 열기는 `capsule_opens`(`opened_at`), 잠긴 열기는 `inventory_item_events`(`unlocked`, `created_at`), 컬렉션은 두 완성 표(`completed_at`), 믹스는 `user_combine_success_logs`(`attempted_at`), 미션은 `user_mission_completions`(`completed_at`), 드랍·픽업은 `poi_drops`(`dropped_at`·`picked_up_by`·`picked_up_at`), 배지 받기는 `user_activity_badges`·`user_checkin_badge_earns`(`earned_at`, 제외 규칙 판정에 `badges` 조인 필요)이다.
- 구현 계획: 시작 때 «적용 시점 이후만» 보는 기준 시각(워터마크)을 정한다. 없으면 오픈 전 기록이 한꺼번에 소급 가산된다. 그다음 동기화 때 자동 보정이나 정리 배치 중 하나를 고르고, 보정이 제외 규칙(숨김·포인트·팔로우·챕터 조건 배지, 자기 픽업, 재평가 배치 배지 등)을 같은 함수로 적용하게 한다. 티켓 `20261019_1650`(미션 보상 지급 복구)과 같은 설계 흐름이라 함께 본다.
- 관련 파일: `jam-web/src/lib/chapter/score.ts`(5-5에서 신설), `jam-web/supabase/migrations/221_chapters.sql`.

## 완료 조건

- 점수 연결이 실패한 활동이 보정 경로로 다시 보내져 한 번만 세어진다(시험으로 확인).
- 보정이 «적용 시점 이후» 기록만 대상으로 하고 제외 규칙을 지킨다.
