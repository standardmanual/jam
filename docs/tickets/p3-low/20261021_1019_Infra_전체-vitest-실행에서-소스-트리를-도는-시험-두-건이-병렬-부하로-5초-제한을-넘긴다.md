# [Infra] 전체 vitest 실행에서 소스 트리를 도는 시험 두 건이 병렬 부하로 5초 제한을 넘긴다

## 핵심 요약

- 요구사항: `npx vitest run` 전체 실행에서 `src/lib/capsule/__tests__/capsule-boundary.test.ts`와 `src/lib/inventory/__tests__/lockedItemFill.test.ts`가 5초 제한을 넘겨 실패한다. 두 파일 단독 실행은 통과한다. 로컬 전체 실행의 거짓 실패를 없앤다.
- 구현 계획: 소스 트리를 순회하는 부분을 한 번만 읽어 공유하거나, 두 시험에만 더 긴 제한을 준다. 먼저 병렬 실행에서 느려지는 원인(파일 읽기량)을 재 본다.
- 관련 파일: `jam-web/src/lib/capsule/__tests__/capsule-boundary.test.ts`, `jam-web/src/lib/inventory/__tests__/lockedItemFill.test.ts`, `jam-web/vitest.config.ts`(제한 시간 설정).

## 배경 / 문제 정의

티켓 20261019_1317의 1회와 2회 모두 아현의 로컬 전체 실행에서 같은 두 시험이 5.3~6.5초로 5초 제한을 넘겼고, 두 번 같은 결과였다. 단독 실행은 77건 모두 통과(2.38초)했고 CI `verify`는 통과했다. 그래서 변경 때마다 아현이 이 두 건을 «변경과 무관»하다고 설명해야 하고, 진짜 실패와 섞일 위험이 있다.

발견: 2026-10-21 티켓 20261019_1317 2회 게이트(민지, 참고).
