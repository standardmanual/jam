# [Service] 투데이 미션 카드의 «배지 N개»가 잠긴 보상도 세어 내린다 (허용 범위 확인)

## 핵심 요약

- 요구사항: 투데이 카드가 미션 보상을 «배지 N개»로 보일 때 `reward_badge_ids` 전체 길이를 쓴다. 보상에 잠긴 아이템 배지가 섞여 있으면 개수가 잠긴 보상을 포함한다. 운영 로직 7.3절이 허용하는 양(등급까지는 가능, 열기 전 이름·그림은 불가)에 개수가 들어가는지 정하고, 안 되면 고친다.
- 구현 계획: 7.3절을 읽고 개수가 허용되는지 판정한다. 허용되지 않으면 `lib/today/cards.ts`가 잠긴 보상 id를 빼고 센다. `lib/missions/locked-rewards.ts`(티켓 20261019_1317 2회에서 만듦)의 판정을 쓰면 상세·목록과 단일 출처가 된다.
- 관련 파일: `jam-web/src/lib/today/cards.ts` 362줄 근처(`reward_badge_count: m.reward_badge_ids?.length ?? 0`)와 같은 파일의 다른 카드 종류, `jam-web/src/lib/today/cardView.ts`, `jam-web/src/lib/missions/locked-rewards.ts`, 정책 `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 7.3절.

## 배경 / 문제 정의

티켓 20261019_1317 2회에서 미션 목록과 상세는 잠긴 보상을 이름·그림·id 없이 등급만 내리도록 고쳤다. 같은 미션을 보여 주는 투데이 카드는 이 변경의 범위 밖이어서 손대지 않았고, 민지가 게이트에서 투데이 카드의 개수 표시를 발견했다. 이름과 그림은 내려가지 않으므로 심각도는 낮다. 허용 범위는 아직 판단하지 않았다.

발견: 2026-10-21 티켓 20261019_1317 2회 게이트(민지, 참고).

## 상세 요구사항

### 서비스/코드베이스 관점

- 허용 여부를 먼저 정한다. 개수가 허용되면 이 티켓은 «확인했고 그대로 둔다»는 기록으로 닫는다.
- 고치는 경우 투데이 카드의 시험을 함께 고친다.

## 완료 조건

- [ ] 7.3절 기준으로 허용 여부를 판정해 티켓에 근거를 적었다
- [ ] 허용되지 않으면 투데이 카드 개수에서 잠긴 보상이 빠진다
