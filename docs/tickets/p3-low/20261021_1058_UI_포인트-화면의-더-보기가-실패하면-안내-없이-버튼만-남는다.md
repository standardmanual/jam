# [UI] 포인트 화면의 «더 보기»가 실패하면 안내 없이 버튼만 남는다

## 핵심 요약

- 요구사항: 포인트 내역에서 «더 보기»(다음 쪽 읽기)가 실패하면 화면에 아무 안내가 없고 «더 보기» 버튼만 그대로 남는다. 실패했다는 사실과 다시 누르면 된다는 안내를 보인다.
- 구현 계획: 추가 쪽 읽기 실패 상태를 따로 두고 버튼 아래에 한 줄 안내(문구는 `UX_WRITING_GUIDELINE.md` 에러 3단계)를 보인다. 처음 읽기 실패(`error`)의 «다시 시도» 카드와는 구분한다. 채원 사전 판정이 필요한 새 UI이므로 `/jam-work`의 표준 경로로 처리한다.
- 관련 파일: `jam-web/src/app/(main)/points/page.tsx` 35~52줄의 `load`(`if (!append) setError(true)`로 추가 읽기 실패를 삼킨다)와 151~159줄의 «더 보기» 버튼, `jam-web/src/app/(main)/points/page.test.tsx`(현재 동작을 «받은 내역 유지, 버튼 남음»으로 고정해 두었다. 고치면 이 시험도 함께 바꾼다), 문구 `jam-web/src/lib/i18n/ko.ts` `d.points`(1314줄~).

## 배경 / 문제 정의

티켓 20261019_1317 3회에서 포인트 화면 시험을 쓰다가 민지와 아현이 발견했다. 스펙 위반은 아니고 이번 티켓의 범위(회수 용어와 받은 내역 확인)도 아니라서 고치지 않고 현재 동작을 시험으로 고정했다. 네트워크가 불안정할 때 유저가 «더 보기»를 눌러도 아무 일도 일어나지 않은 것처럼 보인다.

발견: 2026-10-21 티켓 20261019_1317 3회 게이트(민지, 참고).

## 상세 요구사항

### UI/UX 관점

- 실패한 뒤에도 이미 읽은 내역은 그대로 둔다. 잔액을 바꾸지 않는다.
- 문구는 «회수»·«지급»을 쓰지 않는 해요체 문장으로 정한다.

## 완료 조건

- [ ] 추가 쪽 읽기가 실패하면 안내 한 줄이 보이고, 다시 누르면 같은 쪽을 다시 읽는다
- [ ] 처음 읽기 실패 카드와 겹치지 않는다
- [ ] 320~430px에서 겹침이 없다
