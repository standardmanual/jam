# [Service] 포인트 사유 «기타»의 자유 입력 메모에 «회수»가 적히면 유저 화면에 그대로 보인다

## 핵심 요약

- 요구사항: 어드민이 포인트를 지급·회수하며 사유를 «기타 (자유 입력)»로 고르고 메모를 적으면, 그 메모가 유저의 포인트 화면 내역 행에 그대로 나온다. 메모에 «회수»·«지급» 같은 원장 용어가 있으면 14.2절·UX 라이팅 §1.3(유저 화면에 «회수» 금지)과 어긋난다. 막는 방법을 정한다.
- 구현 계획: 후보는 (a) 어드민 입력 화면에 «이 메모는 유저에게 보여요. 회수·지급 같은 용어는 쓰지 마세요» 경고를 둔다, (b) 서버가 저장할 때 금지 용어가 있으면 거절한다, (c) 유저 화면에서 메모를 아예 보이지 않는다. 사용자가 정한다. 추천은 (a)와 (b)를 함께 하는 것이다(메모를 유저에게 알려 주려는 목적은 살린다).
- 관련 파일: `jam-web/src/app/api/points/route.ts` 90줄(`note: t.admin_reason_label === 'other' ? t.admin_reason_note : null`), `jam-web/src/lib/points/reasons.ts`(55줄 근처 주석이 금지 용어를 설명), 어드민 지급·회수 입력 화면과 `validateAdminGrantInput`, 문구 사전 시험 `jam-web/src/lib/i18n/__tests__/user-facing-terms.test.ts`(사전 값만 보므로 이 경로를 잡지 못한다).

## 배경 / 문제 정의

티켓 20261019_1317 3회에서 포인트 화면의 «회수» 부재를 시험으로 고정하다가 발견했다. 사전(`d`)과 사유 라벨은 유저용 문구로 바뀌지만, 사유가 «기타»일 때 어드민이 직접 적은 글은 걸러지지 않는다. 지금까지 메모에 금지 용어가 적힌 실제 사례는 확인하지 않았다(가능성만 있다).

발견: 2026-10-21 티켓 20261019_1317 3회 게이트(민지, 참고). 3회 계획의 가정 ②에 한계로 기록했다.
