# [Infra] 화면 시험의 보조 함수가 파일마다 따로 있고 일부는 react를 통째로 가짜로 바꾼다

## 핵심 요약

- 요구사항: 클라이언트 화면 시험이 요소 트리를 훑는 보조 함수(`walk`·`textOf`·`visibleText`)를 파일마다 따로 갖고 있다. 포인트 화면 시험은 `useState`·`useEffect`·`useCallback`을 `vi.mock('react')`로 화면 함수 실행 동안만 가짜로 바꾼다. 화면의 훅 개수나 순서가 바뀌면 화면 동작과 무관하게 시험이 깨질 수 있다. 보조 함수를 한 곳으로 모으고, 훅이 든 화면을 제대로 그릴 방법(jsdom 도입 포함)을 검토한다.
- 구현 계획: 먼저 저장소 안 시험에서 같은 이름·같은 일을 하는 보조 함수를 센다. 모은다면 `jam-web/src/test-utils/` 같은 한 곳(위치는 검토)으로 옮기고 시험 파일이 가져오게 한다. jsdom을 들일지는 의존성과 실행 시간을 재 보고 정한다(별도 사용자 승인이 필요한 의존성 추가일 수 있다).
- 관련 파일: `jam-web/src/app/(main)/points/page.test.tsx` 32~51줄(`vi.mock('react')`)과 132~148·169줄, `jam-web/src/app/(main)/__tests__/layout.chapter.test.tsx` 132줄, `jam-web/src/app/(main)/notifications/NotificationsClient.test.tsx` 77줄, `jam-web/src/app/(main)/missions/[id]/MissionDetailClient.claim.test.tsx` 등 기존 화면 시험, `jam-web/vitest.config.ts`(환경 설정).

## 배경 / 문제 정의

티켓 20261019_1317 2회와 3회에서 화면 시험을 쓸 때 저장소에 jsdom이 없어 요소 트리를 직접 훑는 방식을 택했다. 그 결과 같은 보조 함수가 여러 시험 파일에 복사됐고, 포인트 화면 시험은 훅을 가짜로 바꾸는 취약한 방식이 됐다. 지금은 동작에 문제가 없고 각 시험은 제품 코드를 일부러 깨뜨려 실패하는 것을 확인했다. 시험이 늘수록 유지 비용이 커지는 구조 문제다.

발견: 2026-10-21 티켓 20261019_1317 3회 게이트(민지, 참고 두 건: 보조 함수 중복, `vi.mock('react')` 취약성)와 아현 보고.

## 상세 요구사항

### 서비스/코드베이스 관점

- 시험의 변별력은 그대로 지킨다. 보조 함수를 옮긴 뒤 기존 시험이 모두 통과하고, 제품 코드를 깨뜨리면 여전히 실패해야 한다.
- jsdom을 도입하면 기존 `node` 환경 시험과 실행 시간에 미치는 영향을 기록한다.
