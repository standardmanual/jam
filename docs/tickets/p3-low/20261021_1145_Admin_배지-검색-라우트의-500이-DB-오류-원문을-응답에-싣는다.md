# [Admin] 배지 검색 라우트의 500이 DB 오류 원문을 응답에 싣는다

## 핵심 요약

- 요구사항: 어드민 배지 검색 API가 500일 때 `error.message`(DB 오류 원문)를 응답 본문에 싣는다. 같은 패턴을 미션 저장 라우트에서는 고정 문구로 고쳤다(티켓 20261019_1318 1회). 이 라우트도 고정 문구와 `console.error`로 맞춘다.
- 구현 계획: 응답을 고정 문구로 바꾸고 원문은 서버 로그에만 남긴다. 시험에서 원문이 응답에 없음을 확인한다. 같은 패턴이 어드민 라우트에 더 있는지 `error.message`를 응답에 싣는 곳을 찾아 목록을 티켓에 적는다(고치는 범위는 목록을 보고 정한다).
- 관련 파일: `jam-web/src/app/api/admin/badges/search/route.ts` 67줄 근처, 시험 `jam-web/src/app/api/admin/badges/search/__tests__/route.exclude-hidden.test.ts`, 선례 `jam-web/src/lib/admin/mission-save-messages.ts`와 `api/admin/missions/route.ts`.

## 배경 / 문제 정의

티켓 20261019_1318 1회 게이트(민지, 참고)가 이 라우트를 발견했다. 이번 변경이 만든 동작이 아니라 원래 있던 모양이다. 어드민 화면에서만 보이고 외부 노출 위험은 낮지만, 내부 구조(표·열 이름)가 오류 문구에 섞여 나올 수 있다. 같은 이유로 `api/admin/tribes/route.ts` 19줄 근처와 `api/admin/tribes/[id]/route.ts` 113줄 근처에도 비슷한 응답이 있다(조사 에이전트 보고, 직접 확인하지 않았다). 이 중 `tribes/[id]` 라우트의 PUT·DELETE 500은 티켓 20261019_1318 2회가 고정 문구로 바꿨다. 같은 2회 게이트(민지)가 `api/admin/tribes/bulk/route.ts` 63줄 근처의 dryRun 500도 `failed.message`(DB 오류 원문)를 싣는다는 것을 발견했고, 카리나가 2회 브랜치에서 확인했다(2026-10-21). 이 티켓의 «같은 패턴 목록»에 넣는다.

발견: 2026-10-21 티켓 20261019_1318 1회 게이트.

## 상세 요구사항

### 서비스/코드베이스 관점

- 응답 문구는 현상, 원인, 해결책 3단계를 따르는 고정 문구로 한다.
- 어드민 화면이 오류를 보여 주는 방식은 바꾸지 않는다.

## 완료 조건

- [ ] 500 응답에 DB 오류 원문이 없고 서버 로그에는 남는다
- [ ] 시험이 원문 미노출을 고정한다
- [ ] 같은 패턴이 있는 다른 어드민 라우트 목록과 처리를 기록했다
