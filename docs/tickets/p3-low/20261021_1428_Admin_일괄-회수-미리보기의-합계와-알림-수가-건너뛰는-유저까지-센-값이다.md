# [Admin] 일괄 회수 미리보기의 합계와 알림 수가 건너뛰는 유저까지 센 값이다

## 핵심 요약

- 요구사항: 어드민 유저 일괄 회수의 미리보기에서 «회수 합계»와 «알림 수»가 실제로 회수할 유저만이 아니라 건너뛰는 유저까지 센 값이다. 티켓 20261019_1318 2회가 «회수하지 못하고 건너뛰는 유저 N명» 문구를 더했지만 합계와 알림 수는 그대로다. 합계와 알림 수를 실제 처리 대상 기준으로 맞추거나, 문구로 두 값이 어떤 유저를 포함하는지 밝힌다.
- 구현 계획: ① 미리보기 계산(`jam-web/src/lib/admin/user-bulk-impact.ts` 68줄 근처)이 건너뛰는 유저를 합계에 넣는 지점을 확인한다. ② 실제 실행 경로(`jam-web/src/lib/admin/user-bulk.ts`, `api/admin/users/bulk/route.ts`)가 같은 대상을 처리하는지 대조한다. ③ 미리보기 숫자를 실행 결과와 같은 기준으로 맞추고 시험한다.
- 관련 파일: `jam-web/src/lib/admin/user-bulk-impact.ts`, `jam-web/src/lib/admin/user-bulk.ts`, `jam-web/src/app/admin/users/UserBulkImpactSummary.tsx`(40~41줄 문구), `jam-web/src/app/api/admin/users/bulk/route.ts`. 줄 위치는 민지 보고이며 카리나가 직접 확인하지는 않았다. 숫자가 어긋나는 사실은 카리나가 로컬에서 `dry_run` 요청으로 확인했다(2026-10-21): 잔액 0인 테스트 유저 3명에 -100점을 보내면 `revokeSkippedCount: 3`인데 `totalAmount: -300`, `notificationCount: 3`이 함께 온다.

## 배경 / 문제 정의

티켓 20261019_1318 2회 게이트(민지, 참고)가 발견했다. 2회가 `negativeBalanceCount`를 사실에 맞는 이름(`revokeSkippedCount`)으로 바꾸고 문구를 고친 범위 밖이다. 표시되는 합계가 실제 회수 결과와 다를 수 있어 운영자가 숫자를 믿고 실행할 때 어긋남이 생긴다.

발견: 2026-10-21 티켓 20261019_1318 2회 게이트.

## 상세 요구사항

### 서비스/코드베이스 관점

- 미리보기와 실제 실행의 대상 판정은 같은 함수를 쓴다(따로 계산하지 않는다).
- 화면 문구는 현상, 원인, 해결책 3단계를 따른다.

## 완료 조건

- [ ] 미리보기의 합계와 알림 수가 실제 처리 대상 기준이다(또는 포함 범위가 화면에 밝혀져 있다)
- [ ] 시험이 건너뛰는 유저가 섞인 경우를 고정한다
