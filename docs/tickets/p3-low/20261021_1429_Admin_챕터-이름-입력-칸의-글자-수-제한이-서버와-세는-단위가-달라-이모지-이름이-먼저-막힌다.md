# [Admin] 챕터 이름 입력 칸의 글자 수 제한이 서버와 세는 단위가 달라 이모지 이름이 먼저 막힌다

## 핵심 요약

- 요구사항: 어드민 챕터 이름 표의 입력 칸 `maxLength`는 UTF-16 단위로 세고, 서버의 20자 상한은 문자 단위로 센다. 이모지처럼 UTF-16에서 2칸을 차지하는 문자가 낀 이름은 서버 기준으로 20자 이하인데도 입력 칸이 먼저 막는다. 서버를 우회하는 문제는 아니고 화면이 더 엄격할 뿐이다. 두 쪽이 세는 단위를 맞춘다.
- 구현 계획: 입력 칸의 `maxLength` 대신 서버와 같은 함수로 글자 수를 세어 입력을 막거나 안내한다. 어느 쪽이든 서버 검증(`jam-web/src/lib/chapter/names-table.ts`)을 최종 방어선으로 둔다. 영향이 매우 작으므로 챕터 이름에 이모지를 쓰는 운영 계획이 생길 때 함께 처리해도 된다.
- 관련 파일: `jam-web/src/app/admin/chapter-names/ChapterNamesTable.tsx` 107줄 근처(`maxLength`), `jam-web/src/lib/chapter/names-table.ts`(글자 수 판정). 줄 위치는 민지 보고이며 카리나가 직접 확인하지는 않았다.

## 배경 / 문제 정의

티켓 20261019_1318 2회 게이트(민지, 참고)가 발견했다. 2회가 가정 ①(챕터 이름 20자 상한)을 구현하면서 생긴 단위 차이다.

발견: 2026-10-21 티켓 20261019_1318 2회 게이트.
