# [UI] 온보딩 1단계 «다음» 버튼을 공용 Button으로 바꾸고, 로그아웃 실패 안내를 버튼 가까이에 둔다

## 핵심 요약

- 요구사항: (1) 온보딩 1단계(아이디·이름)의 «다음»이 공용 `Button`이 아닌 원시 `<button>`이라 모양과 잠금 규칙이 2단계 버튼과 따로 논다. 공용 `Button`(primary)으로 바꾼다. (2) 1단계에서 로그아웃이 실패하면 «네트워크 오류가 발생했어요.»가 아이디 입력 아래 안내 줄에 뜨는데, 로그아웃 버튼은 화면 맨 아래에 있어 짧은 화면에서는 두 곳이 한 화면에 들어오지 않는다. 실패를 놓치지 않게 안내를 버튼 가까이에 둔다.
- 구현 계획: 두 변경 모두 시각이 바뀌므로 채원 사전 판정을 받고 시작한다. (1)은 «다음»의 폭(지금 `w-[70%]`)과 모양이 달라질 수 있어 사용자 판단이 필요하다. 시작 때 질문한다.
- 관련 파일: `jam-web/src/app/(onboarding)/onboarding/page.tsx` 416줄 근처(로그아웃 실패 안내 위치), 471줄 근처(«다음» 원시 버튼). 줄 위치는 민지 보고이며 카리나가 직접 확인하지는 않았다.

## 배경 / 문제 정의

티켓 20261021_1247 1회의 로그아웃 길 추가에서 민지 게이트(참고)와 채원 사전 판정, 채원 사후 리뷰가 함께 발견했다. 사용자가 로그아웃 링크를 1단계까지 넓혀 머지하기로 해서 이번 범위에서는 고치지 않았다.

발견: 2026-10-21 티켓 20261021_1247 1회 재작업 게이트와 채원 사후 리뷰.

## 상세 요구사항

### UI/UX 관점

- 1단계 «다음»과 2단계 «이 트라이브로 시작하기»가 같은 부품과 같은 잠금 규칙(`disabled`, 진행 중 스피너)을 쓴다.
- 1단계에서 로그아웃이 실패했을 때 실패 문구가 로그아웃 버튼과 한 화면에 보인다. 문구는 기존 `d.onboarding.networkError`를 그대로 쓴다.

## 완료 조건

- [ ] 1단계 «다음»이 공용 `Button`이다(폭과 모양은 사용자가 정한 대로)
- [ ] 로그아웃 실패 문구가 버튼 가까이에 보인다(430px 이하, 짧은 화면 포함)
- [ ] 기존 온보딩 시험이 통과하고 새 위치를 시험이 고정한다
