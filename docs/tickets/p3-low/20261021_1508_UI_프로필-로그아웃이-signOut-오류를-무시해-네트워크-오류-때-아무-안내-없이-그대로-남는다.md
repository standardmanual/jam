# [UI] 프로필 로그아웃이 signOut 오류를 무시해, 네트워크 오류 때 아무 안내 없이 로그아웃이 안 된 채로 끝난다

## 핵심 요약

- 요구사항: 프로필 화면의 `handleLogout`은 `supabase.auth.signOut()`이 돌려주는 오류를 보지 않고 곧장 `/login`으로 보낸다. 네트워크 오류로 세션이 지워지지 않으면 `proxy.ts`가 로그인된 유저를 `/login`에서 `/`로 되돌려서, 유저는 아무 안내 없이 로그아웃이 안 된 채로 홈에 돌아온다. 티켓 20261021_1247 1회에서 온보딩의 로그아웃은 이 경우를 막았다(오류 시 «네트워크 오류가 발생했어요.»를 보이고 다시 누를 수 있게 함). 프로필도 같은 방식으로 맞춘다.
- 구현 계획: `signOut`의 `{ error }`를 받고, 오류가 있거나 throw되면 토스트로 `d.common.networkError`(또는 온보딩과 같은 문구)를 보이고 버튼을 다시 누를 수 있게 한다. 성공하면 `/login`으로 보낸다. 온보딩의 `handleLogout`(`jam-web/src/app/(onboarding)/onboarding/page.tsx`)을 참고한다.
- 관련 파일: `jam-web/src/app/(main)/profile/ProfileClient.tsx` 395~399줄(`handleLogout`), `jam-web/src/proxy.ts` 97~101줄(로그인된 유저의 `/login` 접근 되돌림). 줄 위치는 민지 보고이며 카리나가 직접 확인하지는 않았다.

## 배경 / 문제 정의

티켓 20261021_1247 1회 재작업 게이트(민지, 참고)가 발견했다. 프로필의 로그아웃은 이번 범위 밖이라 고치지 않았다.

발견: 2026-10-21 티켓 20261021_1247 1회 재작업 게이트.

## 상세 요구사항

### 서비스/코드베이스 관점

- 프로필 로그아웃이 실패하면 유저에게 알리고 다시 시도할 수 있다.
- 성공 경로(세션 삭제 후 `/login`)는 바꾸지 않는다.

- [ ] 성공하면 `/login`으로 간다
- [ ] 시험이 오류·throw·성공 분기를 고정한다
