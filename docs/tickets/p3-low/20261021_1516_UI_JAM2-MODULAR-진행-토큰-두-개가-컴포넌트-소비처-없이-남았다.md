# [UI] JAM2 MODULAR 진행 토큰 `--progress-latest`·`--progress-latest-soft`가 컴포넌트 소비처 없이 남았다

## 핵심 요약

- 요구사항: `RecentSyncBanner`를 지우면서(티켓 20261019_1318 3회) 토큰 `--progress-latest`와 `--progress-latest-soft`를 쓰는 컴포넌트가 하나도 없어졌다. 이 토큰을 지울지 남길지 사용자가 정한다.
- 구현 계획: ① 사용자가 지우기로 하면 서비스 `src/`에서 쓰는 곳이 정말 없는지 `grep`으로 다시 확인한다(2026-10-21 머지 전 작업 트리에서는 `src/`에 없었다). ② 아래 남은 참조를 함께 고치고 `node scripts/ds-manifest-sync.mjs --write`로 색인을 다시 만든다. ③ 남기기로 하면 이 티켓을 «남김, 사유»로 닫는다.
- 남은 참조(카리나가 `grep`으로 확인, 2026-10-21): `jam-web/design-system/tokens/colors.css` 92~93줄, `jam-web/design-system/foundations/Colors.stories.tsx` 169~170줄, `jam-web/design-system/_adherence.oxlintrc.json`, `jam-web/design-system/_ds_manifest.json` 686·692줄, `jam-web/DESIGN.md` 51줄, `jam-web/scripts/jam2-token-map.json` 49~50줄(과거 토큰 이전의 매핑 기록이라 고치지 않을 수 있다).

## 배경 / 문제 정의

티켓 20261019_1318 3회 사전 판정(채원)과 게이트(민지)가 참고로 지적했다. 토큰 삭제는 서비스 색에 즉시 반영될 수 있고 취향 판단이 섞여서 3회에서는 지우지 않고 남겼다. `--progress-done`과 `--progress-track`은 `ProgressBar`가 쓰므로 해당하지 않는다.

발견: 2026-10-21 티켓 20261019_1318 3회 게이트.

## 상세 요구사항

### UI/UX 관점

- 토큰을 지워도 서비스 화면의 색이 바뀌지 않아야 한다(소비처가 없음을 지울 때 다시 확인한다).
- `jam2-token-map.json`처럼 과거 실행 기록은 이 티켓에서 고치지 않는다.

## 완료 조건

- [ ] 지우기로 했다면 남은 참조가 정리되고 `ds:check`와 `ds-manifest-sync`가 통과한다
