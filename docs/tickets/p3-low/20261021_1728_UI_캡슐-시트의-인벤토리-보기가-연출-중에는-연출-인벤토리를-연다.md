# [UI] 캡슐 시트의 «인벤토리 보기»가 연출 중에는 연출 인벤토리를 연다

## 핵심 요약

- 요구사항: 캡슐 시트의 «인벤토리 보기» 링크(`d.capsule.sheet.inventoryLink`, 인벤토리 빈칸이 모자랄 때 보임)가 `/inventory`로 가는데, 연출 7단계 중에는 `/inventory`가 연출용 인벤토리로 바뀐다(`inventory/page.tsx`가 `getOnboardingQuestGate`를 쓴다). 새 첫 과제에서 «JAM! 시작하기» 카드가 같은 문구를 재사용해 빈칸 모자람 안내를 보이는데, 연출이 남은 유저가 이 링크를 누르면 실제 인벤토리가 아니라 연출 인벤토리가 열린다. 실제 인벤토리로 가는 길을 만든다.
- 구현 계획: 링크 목적지를 연출 문지기와 무관하게 실제 인벤토리를 보여 주는 경로로 바꾸거나, 연출 문지기가 실제 단계를 이미 시작한 유저에게는 실제 인벤토리를 열게 한다. 어느 쪽이 맞는지는 연출 7단계의 인벤토리 단계(`bag`)와의 관계를 읽고 정한다. 시작 때 사용자에게 방향을 묻는다.
- 관련 파일: `jam-web/src/components/capsule/` 캡슐 시트의 인벤토리 링크, `jam-web/src/app/(main)/inventory/page.tsx`, `jam-web/src/lib/onboarding-quest/screen-gate.ts`. 줄 위치는 채원 사전 판정과 아현 보고이며 카리나가 직접 확인하지는 않았다.

## 배경 / 문제 정의

티켓 20261021_1248 2회 채원 사전 판정이 발견했다(범위 밖 발견물 7번). 카드의 ③ 버튼은 `/inventory/{itemId}` 깊은 링크라 문지기를 지나지 않아 이번 범위에서는 막히지 않았다.

발견: 2026-10-21 티켓 20261021_1248 2회 채원 사전 판정.

## 상세 요구사항

### 서비스/코드베이스 관점

- 연출 중에도 실제 인벤토리를 열어야 하는 길(빈칸 모자람 안내)은 실제 인벤토리로 간다.
- 연출 7단계의 인벤토리 단계 동작은 바꾸지 않는다.

## 완료 조건

- [ ] 연출이 남은 유저가 빈칸 모자람 안내의 «인벤토리 보기»를 누르면 실제 인벤토리가 열린다
- [ ] 연출 인벤토리 단계의 기존 동작이 그대로다
- [ ] 시험이 두 경로를 고정한다
