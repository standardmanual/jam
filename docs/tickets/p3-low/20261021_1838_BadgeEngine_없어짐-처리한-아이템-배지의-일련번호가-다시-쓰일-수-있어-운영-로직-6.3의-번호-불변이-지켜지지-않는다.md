# [BadgeEngine] 없어짐 처리한 아이템 배지의 일련번호가 다시 쓰일 수 있어 운영 로직 6.3의 «번호를 다시 쓰지 않는다»가 지켜지지 않는다

## 핵심 요약

- 요구사항: 운영 로직 6.3절과 17.2절은 탈퇴 등으로 없어진 아이템 배지 개체의 일련번호를 다시 쓰지 않는다고 정했다. 그런데 DB는 `destroyed_at IS NULL`인 개체끼리만 번호가 겹치지 않게 막는다(마이그레이션 108의 `idx_inventory_items_serial_number_active`와 함수 `assign_random_serial()`). 그래서 없어짐 처리된 개체의 번호는 새 개체가 받을 수 있다. 번호 불변을 보장할지, 보장한다면 어떻게 할지 정한다.
- 구현 계획: ① 번호가 다시 쓰이는 정도를 잰다. `assign_random_serial()`은 1~999,999(ambient_drop은 50,001~)에서 무작위로 고르므로 비워진 번호 하나가 새 개체에 붙을 확률은 개체 하나당 약 100만 분의 1이다. 공용 DB에는 지금 `destroyed_at`이 채워진 개체가 429개 있다. ② 보장하기로 하면 옛 인덱스와 함수를 바꾼다(예: 유일 인덱스의 `destroyed_at IS NULL` 조건과 함수의 같은 조건을 뺀다). 이미 겹친 번호가 있는지 먼저 센다. 확장→전환→축소 분할과 되돌림 SQL이 필요하다. ③ 보장하지 않기로 하면 운영 로직 6.3절·17.2절의 문구를 «다시 쓰일 수 있다»로 고치고 이 티켓을 «남김, 사유»로 닫는다.
- 관련 파일: `jam-web/supabase/migrations/108_item_identity_custody_model.sql` 74~83줄과 151~178줄 근처(민지 보고, 카리나가 직접 확인하지는 않았다), `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 6.3절·17.2절.

## 배경 / 문제 정의

티켓 20261021_1249(6-3 퇴장) 1회 게이트(민지)가 발견했다. 1회는 탈퇴 유저의 아이템 배지를 `destroyed_at`으로 «없어짐» 처리하는데, 운영 로직 17.2절의 전제(번호를 다시 쓰지 않는다)가 DB와 어긋났다. 사용자는 2026-10-21 이 어긋남을 알고도 «없어짐 처리 유지 + 틈 기록»을 선택했다(확률이 매우 낮고 어드민 삭제·믹스와 같은 동작이기 때문이다). 번호 불변은 옛 인덱스·함수를 바꾸는 일이라 6-3의 금지 항목이다.

발견: 2026-10-21 티켓 20261021_1249 1회 게이트.

## 상세 요구사항

### 서비스/코드베이스 관점

- 번호 불변을 보장하기로 하면 이미 발급된 개체의 번호는 바꾸지 않는다.
- 공용 DB 변경이므로 사용자 승인 뒤 카리나만 실행한다.

- [ ] 비보장이면 운영 로직 6.3절·17.2절과 PRD가 «다시 쓰일 수 있다»로 맞춰졌다
