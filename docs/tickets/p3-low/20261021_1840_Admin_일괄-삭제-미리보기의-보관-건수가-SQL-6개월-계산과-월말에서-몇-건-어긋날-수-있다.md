# [Admin] 일괄 삭제 미리보기의 보관 건수가 SQL의 6개월 계산과 월말에서 몇 건 어긋날 수 있다

## 핵심 요약

- 요구사항: 일괄 삭제 미리보기의 `retainedRecordCount`는 자바스크립트 `setUTCMonth`로 «6개월 전»을 구하고, 실제 복사하는 SQL(`prepare_account_deletion`)은 `INTERVAL '6 months'`를 쓴다. 기준 시각이 31일처럼 대상 달에 없는 날이면 두 방식의 보정이 달라 미리보기 건수와 실제 복사 건수가 몇 건 어긋날 수 있다. 두 계산을 맞춘다.
- 구현 계획: `lib/abusing/purge-logs.ts`의 `abusingLogCutoff`가 이미 «대상 달에 그 일자가 없으면 말일로 보정»하는 방식을 쓴다. 이 보정을 `lib/account/retention.ts`에 재사용하거나, 미리보기 건수를 SQL 함수로 세게 해 계산을 한 곳으로 모은다. 어느 쪽이든 PostgreSQL의 `INTERVAL` 월 계산(말일 보정)과 같은 결과인지 월말 날짜로 시험한다.
- 관련 파일: `jam-web/src/lib/account/retention.ts` 30~34줄 근처(민지 보고, 카리나가 직접 확인하지는 않았다), `jam-web/supabase/migrations/263_prepare_account_deletion.sql`.

## 배경 / 문제 정의

티켓 20261021_1249 1회 게이트(민지, 참고)가 발견했다. 미리보기는 안내용 숫자이고 실제 복사에는 영향이 없다.

발견: 2026-10-21 티켓 20261021_1249 1회 게이트.
