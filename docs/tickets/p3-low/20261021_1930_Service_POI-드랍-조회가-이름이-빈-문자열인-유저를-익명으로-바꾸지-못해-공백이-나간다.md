# [Service] POI 드랍 조회가 이름이 빈 문자열인 유저를 «익명»으로 바꾸지 못해 공백이 나간다

## 핵심 요약

- 요구사항: `api/drops/poi/[poiId]/route.ts`는 `nameById[id] ?? dict.drops.anonymous`로 드랍한 사람의 이름을 정한다. `getDisplayName`이 빈 문자열을 돌려주면 `??`는 `null`·`undefined`만 걸러서 빈 이름이 그대로 나가고, 화면에는 «이(가) 드랍»처럼 이름이 없는 문장이 보인다. 빈 문자열도 «익명»으로 바꾸게 고친다.
- 구현 계획: `??`를 빈 문자열까지 거르는 방식(`||` 또는 길이 검사)으로 바꾸고, `getDisplayName`이 빈 문자열을 돌려주는 조건(닉네임과 표시 이름이 모두 비어 있는 유저)을 시험으로 고정한다. 같은 패턴(`?? ... anonymous`)이 `api/drops/[dropId]/route.ts` 63줄 근처에도 있는지 확인한다(그쪽은 `(drop.users && getDisplayName(drop.users)) || ...`라 이미 빈 문자열을 거른다).
- 관련 파일: `jam-web/src/app/api/drops/poi/[poiId]/route.ts` 98줄 근처, `jam-web/src/app/api/drops/poi/[poiId]/__tests__/route.test.ts`. 줄 위치는 조사 에이전트 보고이며 카리나가 직접 확인하지는 않았다. 이 파일은 티켓 `20261021_1249` 2회도 고치므로(탈퇴 유저 표시) 2회가 머지된 뒤에 시작한다.

## 배경 / 문제 정의

6-3 2회 시작 전 조사에서 발견했다. 기존 동작이고 6-3 2회가 만드는 문제가 아니다.

발견: 2026-10-21 티켓 20261021_1249 2회 시작 전 조사.

## 상세 요구사항

### 서비스/코드베이스 관점

- 프로덕션에서 조회 대상에서 뺀 스테이징 테스트 계정의 «익명»은 그대로 둔다.
