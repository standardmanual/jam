# [Service] 소식 행위자 조인이 유저 조회 오류를 확인하지 않아 조회가 실패하면 행위자가 탈퇴 유저로 보인다

## 핵심 요약

- 요구사항: 소식 목록을 만들 때 행위자(`actor_user_id`)의 프로필을 `users`에서 조회하는데, 그 조회의 오류(`usersRes.error`)를 확인하지 않는다. 조회가 실패하면 행위자가 있어도 `actor`가 null이 된다. 티켓 `20261021_1249` 2회부터 행위자를 쓰는 소식 5종은 행위자가 없으면 «₩*&%#@님»(탈퇴 유저)으로 보이므로, 조회 실패가 «살아 있는 유저가 탈퇴했다»는 거짓 표시로 이어진다(예전에는 «익명»이었다). 조회 오류를 확인해 실패하면 소식 목록 전체를 오류로 처리하거나 해당 소식을 건너뛰게 한다.
- 구현 계획: `usersRes.error`가 있으면 던지거나 호출자에게 오류를 알리고(다른 조회 오류 처리와 같은 방식), 시험으로 «유저 조회 실패 시 탈퇴 텍스트가 나오지 않는다»를 고정한다.
- 관련 파일: `jam-web/src/lib/notifications/feed.ts` 188줄과 235줄 근처(민지 보고, 카리나가 직접 확인하지는 않았다), 시험 `jam-web/src/lib/notifications/__tests__/`.

## 배경 / 문제 정의

티켓 20261021_1249 2회 게이트(민지, 참고)가 발견했다. 오류 확인이 없는 것은 기존 코드이고, 2회의 표시 변경이 그 영향을 «익명»에서 «탈퇴 유저»로 바꿨다.

발견: 2026-10-21 티켓 20261021_1249 2회 게이트.

## 상세 요구사항

### 서비스/코드베이스 관점

- 행위자가 정말 지워진 경우(`actor_user_id`가 NULL)의 표시는 바꾸지 않는다.
