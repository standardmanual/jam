# [Infra] 마이그레이션 규칙에 «지우는 것이 목적인 데이터 정리는 되돌림 SQL이 없다»는 예외가 없다

## 핵심 요약

- 요구사항: `db-migration-rules.md` §4는 모든 마이그레이션에 되돌림 SQL을 싣도록 한다. 그런데 티켓 `20261021_1249` 2회의 `264_clear_withdrawn_custody_usernames.sql`은 지운 이름을 되살릴 사본이 이 표에 없어서(지우는 것이 목적이다) 실제 되돌림 SQL이 없다. 파일 끝 `-- 되돌림 SQL 없음 — …` 한 줄이 `scripts/deploy-gate.mjs`의 표식 검사(`^\s*--\s*(?:되돌림|ROLLBACK|DOWN)`)를 통과할 뿐이다. 이런 데이터 정리를 규칙이 어떻게 다룰지(예외 서술, 백업 확인 절차, 배포 게이트 표식) 정한다.
- 구현 계획: ① 규칙 문서에 «데이터 삭제가 목적인 마이그레이션은 되돌림 SQL 대신 실행 전 확인 SELECT 결과와 백업 복원 경로를 적는다»를 더할지 정한다. ② `deploy-gate.mjs`가 «되돌림 SQL 없음»을 명시한 줄을 어떻게 볼지(통과시킬지, 사유를 요구할지) 정한다. ③ `/jam-ship`의 롤백 계획 «롤백 경로» 칸에 이런 마이그레이션은 백업 복원으로 적는다는 한 줄을 더한다.
- 관련 파일: `.claude/skills/jam-work/references/db-migration-rules.md` 40줄 근처, `scripts/deploy-gate.mjs` 227줄 근처(민지 보고, 카리나가 직접 확인하지는 않았다), `jam-web/supabase/migrations/264_clear_withdrawn_custody_usernames.sql`.

## 배경 / 문제 정의

티켓 20261021_1249 2회 게이트(민지, 참고)가 발견했다. 264는 사용자가 «지우는 것이 목적이라 되돌림 SQL은 없다»고 승인했다(가정 ②).

발견: 2026-10-21 티켓 20261021_1249 2회 게이트.
