# [Admin] 일괄 삭제에서 유저마다 Strava 앱 해제를 기다려 라우트 최대 실행 시간을 넘길 수 있다

## 핵심 요약

- 요구사항: 티켓 `20261021_1249` 3회부터 `deleteAccount`가 계정 삭제 뒤 Strava 앱 승인을 해제한다(토큰 읽기와 해제 호출, 해제 요청 하나는 최대 8초 타임아웃이고 토큰이 만료 직전이면 갱신이 한 번 더 붙는다). 어드민 일괄 삭제는 최대 50명을 동시 2건으로 처리하므로 해제 호출이 느린 날에는 `maxDuration` 60초 안에 끝나지 않을 수 있다. 실제로 얼마나 걸리는지 재고, 필요하면 해제를 응답 뒤로 미룬다.
- 구현 계획: ① 해제 호출의 실제 소요를 잰다(평소 응답 시간, 최악 8초). ② 최악이 `maxDuration`을 넘으면 Strava 해제를 `after()`(응답 뒤 실행) 같은 방식으로 미루거나, 일괄 삭제에서는 한 번에 처리하는 유저 수를 줄인다. 해제 실패는 지금처럼 로그만 남긴다(계정 삭제 결과에 영향 없음).
- 관련 파일: `jam-web/src/lib/account/delete-account.ts` 116줄 근처(민지 보고, 카리나가 직접 확인하지는 않았다), `jam-web/src/app/api/admin/users/bulk/route.ts`(`maxDuration`).

## 배경 / 문제 정의

티켓 20261021_1249 3회 게이트(민지, 참고)가 발견했다. 실측하지 않았다. 평소 Strava 응답이 빠르면 문제가 없다.

발견: 2026-10-21 티켓 20261021_1249 3회 게이트.
