# [Service] 연결이 끊긴 유저의 좌표가 남아 있는지 하루 한 번 쓸어 담아 파기한다

## 핵심 요약

- 요구사항: 티켓 `20261021_1249` 4회부터 Strava 연결을 끊으면(동의 철회) 연결 끊기 라우트가 `scrub_user_location`으로 좌표(`users.last_location_*`와 활동의 시작·종료 좌표)를 파기한다. 이 파기가 실패해도 끊기는 성공으로 두고 라우트가 한 번 재시도하지만, 두 번 모두 실패하면 «좌표는 지워져요»라고 안내한 시트의 약속이 깨진 채 남는다. 끊긴 연결(`strava_connections.disconnected_at`이 있는 행)의 유저를 하루 한 번 훑어 `scrub_user_location`을 다시 부르는 보정을 만든다.
- 구현 계획: ① 일일 크론 `/api/cron/poi-cleanup`(매일 UTC 00:00)에 «끊긴 연결의 유저에게 좌표가 남았는지 확인하고 파기»를 더하거나 새 크론을 만든다(`purge-retained.ts`와 같은 방식: 실패해도 응답은 200, 응답 필드로만 알림). ② 대상 판정은 `disconnect_reason = 'user_disconnected'`인 행으로 하고(토큰 만료 등 시스템 사유로 끊긴 연결은 동의 철회가 아니므로 제외), `users.last_location_*`가 NULL이 아니거나 `strava_activities.normalized`에 좌표 키가 남은 유저만 고른다. ③ 같은 athlete를 다시 연결한 유저는 `disconnected_at`이 지워지므로 대상에서 빠진다. ④ 시험으로 두 번 불러도 안전함과 실패 격리를 고정한다.
- 관련 파일: `jam-web/src/app/api/strava/disconnect/route.ts`(재시도 구현), `jam-web/src/app/api/cron/poi-cleanup/route.ts`, `jam-web/src/lib/account/purge-retained.ts`(같은 방식의 선례), 마이그레이션 `265_scrub_user_location.sql`(티켓 20261021_1249 4회, 적용 뒤). 줄 위치는 시작 때 아현이 확인한다.

## 배경 / 문제 정의

6-3 4회 채원 사전 판정이 «좌표는 지워져요» 문구가 파기 성공을 약속하는데 실패를 알 방법이 없는 점을 지적했고, 사용자가 2026-10-22 «문구 유지 + 재시도 + 후속 티켓»을 선택했다. 약관 제11조 ①(철회 때 개인위치정보 파기)의 이행 문구라서 문구를 낮추지 않고 파기를 믿을 수 있게 하는 쪽을 택했다.

발견: 2026-10-22 티켓 20261021_1249 4회 채원 사전 판정.

## 상세 요구사항

### 서비스/코드베이스 관점

- 보정은 `scrub_user_location`이 다시 불러도 안전하다는 성질에 기댄다(이미 NULL인 값은 건드리지 않는다).
- 보정 크론의 실패가 다른 크론 작업(드랍 만료, 부정 이용 기록 파기, 보관 행 파기)을 막지 않는다.

## 완료 조건

- [ ] 연결 끊기 때 파기가 실패한 유저의 좌표가 다음 날 크론에서 지워진다(시험으로 고정)
- [ ] 시스템 사유로 끊긴 연결의 유저는 대상이 아니다
