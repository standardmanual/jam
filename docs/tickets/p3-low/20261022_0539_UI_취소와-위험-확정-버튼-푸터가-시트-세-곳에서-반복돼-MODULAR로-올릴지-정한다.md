# [UI] «취소 + 위험 확정» 버튼 푸터가 시트 세 곳에서 반복돼 MODULAR로 올릴지 정한다

## 핵심 요약

- 요구사항: 서비스의 확인 시트 세 곳(`StravaDisconnectSheet`, `WithdrawSheet`, `StravaDuplicateSheet`)이 같은 푸터를 쓴다. 왼쪽 `Button secondary`(취소 또는 닫기)와 오른쪽 `Button danger`(확정)를 `flex gap-4`에 같은 폭(`fullWidth`, `px-3! whitespace-nowrap`)으로 두고, 그 위에 실패 안내(`InlineNotice`)가 붙는 구조다. MODULAR에는 확인 시트나 확인 푸터 부품이 없다. 3곳 기준에 닿았으므로 «확인 시트 푸터» 부품으로 MODULAR에 올릴지, 서비스 전용으로 남길지 정한다.
- 구현 계획: ① 세 시트의 푸터 코드를 비교해 공통 props(취소 라벨, 확정 라벨, 제출 중 여부, 알림 슬롯)를 정리한다. ② 올리기로 하면 `jam-web/design-system/components/`에 컴포넌트와 Story를 더하고 `_ds_manifest.json`을 `ds-manifest-sync`로 맞추며 서비스 쪽을 `@ds` import로 바꾼다(MODULAR 쌍 시험 규칙, 티켓 `20261021_2244`의 `InlineNotice` 승격과 함께 하는 편이 낫다). ③ 남기기로 하면 «서비스 전용, 사유»로 닫는다. 4회가 만든 확인 문구 입력 블록(`ConfirmPhraseField` 후보)은 3회 `WithdrawSheet` 한 곳뿐이라 이번 판단에 넣지 않는다.
- 관련 파일: `jam-web/src/components/strava/StravaDisconnectSheet.tsx`, `jam-web/src/components/account/WithdrawSheet.tsx`, `jam-web/src/components/strava/StravaDuplicateSheet.tsx` 84~118줄(민지 보고, 카리나가 직접 확인하지는 않았다), `jam-web/src/components/ui/Button.tsx`, `jam-web/src/components/ui/InlineNotice.tsx`.

## 배경 / 문제 정의

6-3 4회 채원 사전 판정과 사후 리뷰가 승격 후보로 제안했다. 승격 기준(안정성·범용성)을 3회와 4회 사이에 막 굳은 푸터 모양이라 이 티켓에서 바로 올리지 않고 사용자 판단으로 남겼다.

발견: 2026-10-22 티켓 20261021_1249 4회 채원 사후 리뷰.
