# [Service] «그래도 연결하기» 흐름에서 쿠키를 10분 안에 다시 쓸 수 있고, 두 탭에서 열면 성공한 쪽 뒤에 실패로 읽힌다

## 핵심 요약

- 요구사항: 티켓 `20261021_1249` 4회의 `POST /api/strava/replace`는 성공하면 제안 쿠키(`strava_replace_offer`)를 지우지만 서버에는 사용 기록이 없다. 두 가지 모서리가 남는다. ① 쿠키 값을 따로 보관한 본인이 10분 안에 같은 요청을 다시 보내면 같은 토큰으로 자기 연결을 갱신 저장한다(기존 계정은 이미 없다). 영향은 낮다. ② 같은 시트를 두 탭에서 연 뒤 한쪽이 성공하면 다른 탭은 쿠키가 없어 400 restart(«시간이 지나 연결 요청이 닫혔어요…»)를 받는다. 이미 연결됐는데 실패로 읽힌다. 두 경우를 정리한다.
- 구현 계획: ① 재사용은 쿠키에 한 번만 쓰는 값(무작위 nonce)을 넣고 서버에서 «이미 쓴 nonce»를 걸러 막을 수 있는지 본다(저장소가 필요하므로 비용이 크면 «영향이 낮다»로 남긴다). ② 두 탭 문제는 restart 응답 때 «이미 이 Strava 계정이 연결돼 있는지»를 확인해 연결돼 있으면 성공으로 안내하는 쪽이 간단하다(`strava_connections`에서 로그인한 유저의 `strava_athlete_id`를 읽는다). ③ 하지 않기로 하면 «남김, 사유»로 닫는다.
- 관련 파일: `jam-web/src/app/api/strava/replace/route.ts` 62~125줄, `jam-web/src/lib/i18n/ko.ts` 1394~1399줄 근처(민지 보고, 카리나가 직접 확인하지는 않았다), `jam-web/src/lib/strava/replace-offer.ts`.

## 배경 / 문제 정의

6-3 4회 게이트(민지, 참고)가 발견했다. 둘 다 기능을 해치지 않고 사용자가 드물게 겪는 모서리다.

발견: 2026-10-22 티켓 20261021_1249 4회 게이트.
