# [Admin] 트라이브 «드랍 가중치»와 «인접 트라이브» 설정이 드랍에 쓰이지 않는데 화면은 영향이 있다고 안내한다

> 출처: 티켓 20261022_0938 1회 게이트(민지) 범위 밖 발견물 [정확성/참고].

## 핵심 요약

- 요구사항: 옛 드랍 엔진을 지운 뒤로 트라이브의 `drop_weight`(드랍 가중치)와 인접 트라이브 설정을 읽는 드랍 코드가 없다. 그런데 어드민 화면은 이 값이 드랍에 영향을 주는 것처럼 보인다. 운영자가 값을 바꾸고 효과를 기대하지 않도록 화면을 정리할지 정한다(결정은 사용자, 아래 「결정 필요」).
- 구현 계획: 사용자 결정에 따라 ① 안내문만 고치거나 ② 입력과 열을 화면에서 내린다. 착수할 때 관련 파일을 읽고 파일 단위로 적는다.
- 관련 파일: `jam-web/src/app/admin/tribes/[id]/AdjacencyEditor.tsx`(15줄 주석 «드랍엔진 v2 Layer 2 인접 버킷», 화면의 인접 선택), `jam-web/src/app/admin/tribes/TribeForm.tsx`(27·68·181줄 «드랍 가중치 (0.1 ~ 10.0)»), `jam-web/src/app/admin/tribes/TribesTable.tsx` 185~190줄 «드랍 가중치» 열, 인접을 읽는 곳 `jam-web/src/lib/admin/tribe-list.ts`·`jam-web/src/lib/admin/reference-guards.ts`·`jam-web/src/app/api/admin/tribes/[id]/route.ts`.

## 배경 / 문제 정의

티켓 20261022_0938 1회가 옛 드랍 엔진(트라이브를 고르는 가중치와 인접 버킷 25%를 쓰던 곳)을 지웠다. JAM 2.0의 새 발급 경로(`lib/drop-engine/syncIssue*.ts`)는 유저의 소속 트라이브 컬렉션에서만 후보를 고르므로 이 두 값을 읽지 않는다. 2026-10-22 `grep`으로 확인한 결과, 어드민 화면과 삭제 가드(`reference-guards.ts`)와 목록(`tribe-list.ts`) 밖에서 인접 데이터를 읽는 코드가 없다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 두 값의 DB 열과 인접 표는 그대로 둔다(세계관 인접 그래프 문서 `docs/service/content/TRIBES.md`와 다른 용도가 있는지 먼저 확인한다). 이 티켓은 화면과 안내만 다룬다.

### UI/UX 관점

- 결정 필요 ①: **안내문만 고친다**(추천). «이 값은 지금 드랍에 쓰이지 않아요»를 화면에 적는다. 값은 남겨 두므로 나중에 세계관 운영에 다시 쓸 수 있다.
- 결정 필요 ②: 입력과 열을 화면에서 내린다. 운영자가 헷갈릴 일은 없지만, 값을 다시 쓰고 싶을 때 화면부터 되살려야 한다.

## 완료 조건

- 트라이브 폼·목록·인접 편집 화면의 문구가 이 값들이 드랍에 쓰이는지에 맞게 적혀 있다(또는 해당 입력이 내려가 있다).
- 어드민 UX Writing 규칙(고정 용어, 해요체)을 지킨다.
