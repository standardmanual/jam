# [Service] 4등급 켜기 점검과 `tier_mode` 쓰기 사이에 다른 유저가 장착하면 여러 등급이 장착된 채 켜질 수 있다

## 핵심 요약

- 요구사항: 7-8 1회가 만든 `PUT /api/admin/itembooks/[id]/tier`는 켜기 전에 점검(여러 등급을 장착한 유저가 있는지)을 서버에서 다시 돌리고 통과하면 `tier_mode`를 쓴다. 점검과 쓰기가 한 트랜잭션이 아니어서, 그 사이에 다른 유저가 다른 등급을 장착하면 여러 등급이 장착된 채 켜질 수 있다. 끄기도 완성 기록 확인과 쓰기 사이에 같은 틈이 있다. 이 틈을 막을지 정한다.
- 구현 계획: ① 막을 필요가 있는지 정한다(켜기는 어드민이 드물게 하고, 지금 장착 유저는 3명이며, 7-6의 입력은 SQL로 하면서 사전 점검을 따로 한다). ② 막기로 하면 후보를 정한다: (가) 켠 직후 점검 SQL 2번을 다시 돌려 어드민에게 보이는 재확인 절차, (나) 점검과 쓰기를 한 DB 함수로 묶기(마이그레이션이 필요하고 장착 함수와의 잠금 순서를 정해야 한다), (다) 지금 규모에서는 허용하고 출시 뒤 켜는 일이 생기면 다시 본다.
- 관련 파일: `jam-web/src/app/api/admin/itembooks/[id]/tier/route.ts` 78~108줄(민지 보고), `jam-web/src/lib/admin/itembookTier.ts`, `docs/service/content/ITEMBOOK_TIERS.md` 2절.

## 배경 / 문제 정의

민지 게이트(주의)가 발견했다. DB 변경 없이는 원자적으로 만들 수 없다는 아현의 고지가 맞다고 판정했다. 컬렉션은 출시 전에 켜기 때문에 영향이 작아 우선순위를 P3로 두었고, 출시 뒤에 켜는 일이 생기면 P2로 올린다.

발견: 2026-10-22 티켓 20261022_1139(7-8) 1회 게이트(민지).
