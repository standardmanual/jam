# [API] 어드민 컬렉션 라우트가 UUID가 아닌 id에 404가 아니라 500을 돌려준다

## 핵심 요약

- 요구사항: `GET·PUT /api/admin/itembooks/[id]/tier`에 UUID 형식이 아닌 id를 주면 DB가 형식 오류를 내서 404가 아니라 500(읽기 오류 문구)이 나온다. 기존 `[id]` 라우트들도 같은 수준이다. 어드민 전용이라 영향은 작다. id 형식 검증을 어드민 컬렉션 라우트에 공통으로 둘지 정한다.
- 구현 계획: ① `[id]` 하위 라우트(`route.ts`, `drop-exclude`, `tier`)에 UUID 검사를 한 함수로 더하고 형식이 틀리면 404로 응답한다. ② 같은 문제가 있는 다른 어드민 `[id]` 라우트가 몇 개인지 먼저 센다. 많으면 한 번에 처리하는 편이 낫다.
- 관련 파일: `jam-web/src/app/api/admin/itembooks/[id]/tier/route.ts` 32~39줄(민지 보고), `jam-web/src/app/api/admin/itembooks/[id]/route.ts`.

## 배경 / 문제 정의

민지 게이트(참고)가 발견했다. 새 라우트만의 문제가 아니라 기존 라우트와 같은 동작이어서 이번 티켓에서는 고치지 않았다.

발견: 2026-10-22 티켓 20261022_1139(7-8) 1회 게이트(민지).

## 상세 요구사항

### 서비스/코드베이스 관점

- 정상 id의 응답과 오류 문구는 바꾸지 않는다.
