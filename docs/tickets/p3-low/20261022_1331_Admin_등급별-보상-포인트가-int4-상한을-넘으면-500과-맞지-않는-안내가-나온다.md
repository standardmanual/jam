# [Admin] 등급별 보상 포인트가 int4 상한을 넘으면 500과 맞지 않는 안내가 나온다

## 핵심 요약

- 요구사항: 7-8 2회의 등급별 보상 저장(`itembookTierRewards.ts`)은 포인트를 `Number.isSafeInteger`로만 검사하고 DB 열은 `INTEGER`(int4)라, 2,147,483,647을 넘는 값은 저장 단계에서 DB 오류가 나 500과 «잠시 뒤 같은 값으로 다시 저장해 주세요»가 나간다. 같은 값으로 다시 저장해도 계속 실패하므로 안내가 맞지 않는다. 상한을 검사해 400과 맞는 안내로 바꾼다.
- 구현 계획: 검증 함수에 int4 상한을 더하고 편집기의 포인트 칸 안내에도 상한을 알린다. 시험에 상한과 상한 초과 두 건을 더한다.
- 관련 파일: `jam-web/src/lib/admin/itembookTierRewards.ts` 54줄·107줄 근처, `jam-web/src/components/admin/itembooks/ItemBookTierRewards.tsx`(민지 보고).

## 배경 / 문제 정의

민지 게이트(참고)가 발견했다. 2회 가정 ③이 «포인트 상한은 두지 않는다(기존 컬렉션 양식과 같다)»여서 구현은 가정대로이지만 사용자에게 보이는 안내가 어긋난다.

발견: 2026-10-22 티켓 20261022_1139(7-8) 2회 게이트(민지).

## 상세 요구사항

### 서비스/코드베이스 관점

- 정상 범위의 저장과 «비우면 기본값, 0이면 지급 안 함» 규칙은 바꾸지 않는다.

## 완료 조건

- [ ] int4 상한을 넘는 포인트가 400과 이유가 보이는 안내로 거절된다(시험으로 고정)
