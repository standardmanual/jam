# [Admin] 밸런스 설정의 챕터 더하기와 캡슐 구역의 챕터 행 늘리기

## 핵심 요약

- 요구사항: 운영 로직 12.5·19.1절의 «챕터를 더하는 일도 어드민에서 한다»를 지킨다. 밸런스 설정의 챕터 구역에서 챕터 11 이상을 더하고, 캡슐 구역의 «챕터별 채울 양»이 챕터 수를 따라 함께 늘어나게 한다. 사용자 결정(2026-10-22, 7-2 시작 전 조사): 7-2는 챕터의 값 바꾸기까지만 하고 더하기는 뒤로 미룬다. 챕터를 줄이는 기능은 만들지 않는다.
- 구현 계획: 1회. 더하기 입력(새 챕터의 필요 누적 점수와 캡슐 채울 양)과 두 표에 한 번에 넣는 저장, 캡슐 구역의 챕터 칸을 `capsule_chapter_costs` 행 수에 맞춰 만드는 연결 객체 변경, 챕터 구역의 필요 점수 칸이 `chapter_definitions` 행 수를 따르게 하는 변경, 시험.
- 관련 파일(시작 때 줄 위치를 다시 확인한다): `jam-web/src/lib/admin/balance/capsule.ts`(챕터 1~10 고정, `CAPSULE_CHAPTER_COUNT`와 `readRows`), `jam-web/src/lib/admin/balance/chapter.ts`(7-2 2회가 만드는 챕터 구역), `jam-web/src/lib/admin/balance/types.ts`(`BalanceSectionBinding.fields`가 정적 목록이라 칸이 행 수를 따르려면 계약 확장이 필요하다), `jam-web/src/components/admin/balance/BalanceSectionForm.tsx`.

## 배경 / 문제 정의

7-2 시작 전 조사(2026-10-22)에서 확인한 사실이다.

- 챕터는 10개로 시작하고 운영하며 뒤에 더한다(12.4절). 기준 유저(러닝 보통)가 챕터 10에 닿는 데 12.5달쯤 걸려(같은 절) 챕터 11이 필요해지는 때는 빨라야 오픈 1년 뒤다.
- `capsule_chapter_costs`에는 외래키가 없고, 마지막 행보다 높은 챕터는 마지막 행의 양을 쓴다(마이그레이션 234). 그래서 챕터를 더해도 캡슐은 멈추지 않지만, 새 챕터의 채울 양을 화면에서 바꿀 수는 없다. 7-1 캡슐 구역은 챕터 행을 1~10으로 고정해 읽는다(11 이상은 무시하고 1~10 가운데 빠지면 오류).
- `user_chapters`와 `chapter_ups`의 외래키가 `chapter_definitions`를 가리켜 유저가 있는 챕터는 지울 수 없다. 챕터는 내려가지 않는다. 그래서 줄이기는 만들지 않고 더하기와 값 바꾸기만 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 더하기: 챕터 번호는 마지막 번호 + 1이고(번호를 건너뛰지 않는다), 필요 누적 점수는 마지막 챕터보다 커야 한다. 캡슐 채울 양(1 이상 정수)도 함께 받아 `chapter_definitions`와 `capsule_chapter_costs`에 한 번에 넣는다(한쪽이 실패하면 다른 쪽을 되돌린다). 두 사람이 같은 번호를 동시에 더하면 한쪽은 충돌 오류로 돌려보낸다.
- 챕터 구역의 필요 점수 칸과 캡슐 구역의 챕터 칸은 읽을 때 행 수에 맞춰 만든다. 변경 이력의 칸 이름 규칙(챕터 구역 `required:N`, 캡슐 구역 `chapter:N`)은 그대로다. 더하기 이력은 `add:N`로 한 줄 남긴다.
- 읽는 쪽 점검: 챕터 정의를 읽는 `lib/chapter/progress.ts`·`read.ts`, 프로필 게이지와 오름 연출, 어드민 유저 상세(`lib/admin/user-chapter-view.ts`)가 «마지막 챕터가 10»이라고 가정하는 곳이 없는지 확인한다.
- 챕터 이름 표는 2026-10-21 결정으로 없앴다(마이그레이션 257). 더하기에 이름 칸은 없다.

## 선행과 시작 시점

- 선행: 7-2 2회(챕터 구역) 머지. 시작은 챕터 11이 필요해지기 전이고 사용자 지시를 기다린다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)

- [ ] 챕터 구역에서 챕터를 더하면 `chapter_definitions`와 `capsule_chapter_costs`에 새 행이 함께 생기고 변경 이력에 `add:N`이 남는다(시험으로 고정)
- [ ] 더한 챕터가 캡슐 구역의 «챕터별 채울 양»과 챕터 구역의 필요 점수 칸에 나타나 값을 바꿀 수 있다
- [ ] 필요 점수가 마지막 챕터 이하이거나 번호를 건너뛰면 저장되지 않고 이유가 보인다
- [ ] 한쪽 표를 쓰다 실패하면 다른 쪽이 되돌려진다(시험)
