# [Admin] 밸런스 설정 저장의 이력 실패 되돌림이 행별 수정 시각을 잃는 점을 정리한다

## 핵심 요약

- 요구사항: 공용 저장(`saveBalanceSection`)은 변경 이력을 남기지 못하면 쓴 행을 되돌린다. 이때 쓴 행 모두의 `updated_at`을 «행별 이전 값»이 아니라 «구역의 가장 늦은 수정 시각»으로 되돌린다. 구역 수정 시각(최댓값)은 원래와 같아 지금 동작에는 영향이 없다. 행별 수정 시각을 쓰는 화면이 생기기 전에 둘 중 하나로 정한다. (가) 행별 이전 값으로 되돌린다. (나) 구역 단위 수정 시각만 쓴다는 사실을 코드 주석과 PRD에 못박는다.
- 구현 계획: 먼저 (가)의 비용을 잰다. 읽기 결과가 행별 시각을 이미 갖고 있으면 되돌림 함수에 그 값을 넘기는 정도로 끝난다. 갖고 있지 않으면 (나)로 닫는다.
- 관련 파일: `jam-web/src/lib/admin/balance/save.ts`(150줄 부근, 이력 실패 되돌림), `jam-web/src/lib/admin/balance/rowwise.ts`(`runRowOps`의 되돌림은 행별 이전 값을 쓴다. 이쪽과의 차이를 맞추는 일이다), 시험 `jam-web/src/lib/admin/balance/__tests__/`의 저장 시험

## 배경 / 문제 정의

티켓 `20261022_1133` 2회 게이트의 범위 밖 발견물(참고)이다. `runRowOps`가 중간 실패를 되돌릴 때는 행별 이전 값과 이전 수정 시각을 복원하는데, 이력 실패 되돌림은 구역 단위 값으로 복원해 두 경로의 약속이 다르다. 지금은 어느 화면도 행별 `updated_at`을 읽지 않아 드러나지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 어느 쪽으로 정하든 두 되돌림 경로(`runRowOps`, 이력 실패)가 같은 약속을 지킨다는 문장을 코드 주석에 남긴다.
- 동시 수정 검사(읽은 수정 시각이 같을 때만 갱신)의 동작은 바꾸지 않는다.

## 구현 계획

(가)로 가면 `save.ts`의 되돌림에 행별 이전 값을 넘기고 시험을 더한다. (나)로 가면 주석과 `ADMIN_PRD.md` 5-9절 문장만 고친다. 선택 근거는 티켓 「주요 의사결정」에 적는다.

## 완료 조건

- (가) 이력 기록이 실패한 저장 뒤 쓴 행의 `updated_at`이 저장 전 행별 값과 같다(시험으로 고정). 또는 (나) 구역 단위 수정 시각만 쓴다는 문장이 `save.ts` 주석과 `ADMIN_PRD.md`에 있다.
- 기존 저장·되돌림 시험이 모두 통과한다.
