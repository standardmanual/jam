# [Infra] 투데이 카드 모양 5개를 하드코딩한 시험 5곳이 모양이 또 늘어도 실패하지 않는다

## 핵심 요약

- 요구사항: 투데이 카드 모양 5개(`hero`, `poster`, `square`, `brief`, `list`)를 직접 적어 둔 시험이 5곳 남아 있다. 모두 «5개가 허용값에 든다»는 부분집합 검사라 지금은 통과하지만, 모양이 또 늘어도 실패하지 않아 목록 누락을 잡지 못한다. `CARD_SHAPES`(`jam-web/src/lib/today/shape.ts`)를 직접 가져와 전체 목록과 비교하도록 바꾼다.
- 구현 계획: 한 번에 돌린다. 아래 파일의 하드코딩 목록을 `CARD_SHAPES`로 바꾸고, 부분집합 검사였던 곳은 «전체와 같다»는 검사로 올릴 수 있는지 곳마다 판단한다.
- 관련 파일: `jam-web/src/app/admin/today/__tests__/TodayCardPreview.test.tsx` 127줄, `jam-web/src/lib/admin/opsInbox/__tests__/cardPreview.test.ts` 73줄, `jam-web/src/lib/admin/opsInbox/__tests__/fields.test.ts` 46줄·483줄, `jam-web/src/lib/admin/opsPatterns/__tests__/write.test.ts` 169줄. 기준은 `jam-web/src/lib/today/shape.ts` 18줄.

## 배경 / 문제 정의

티켓 `20261022_2248`의 게이트(민지)와 구현(아현)이 2026-10-23에 범위 밖 발견물로 남겼다. 2248은 같은 원인으로 실패하던 시험 10건만 고쳤다. 이 5곳은 통과하므로 건드리지 않았다.

같은 게이트가 한 가지를 더 짚었다. `validate.test.ts`의 기대 문구(432·453·1069·1072줄)가 `CARD_SHAPES.join(', ')`로 만들어져서, 소스의 안내 문구도 같은 상수를 쓰면 «허용값 목록을 안내한다»는 점은 순환 검증이 된다. 문구의 앞뒤 틀과 목록 포함 여부는 여전히 검증되므로 결함은 아니다. 이 티켓에서 그대로 둘지 정한다.
