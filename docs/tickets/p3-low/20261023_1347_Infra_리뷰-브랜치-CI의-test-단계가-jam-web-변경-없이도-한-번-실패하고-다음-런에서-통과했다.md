# [Infra] 리뷰 브랜치 CI의 test 단계가 jam-web 변경 없이도 한 번 실패하고 다음 런에서 통과했다

## 핵심 요약

- 요구사항: 브랜치 `claude/jamwork-20261017_1638-dynamic-import-boundary-r1`에서 CI `verify`의 `test` 단계가 런 `39901233983`(13:36 KST)에서 실패했고, `jam-web`을 바꾸지 않은 문서 전용 커밋 하나 뒤의 런 `39901913163`(13:44 KST)에서는 같은 `test`가 통과했다. 간헐 실패(시간 초과 등)가 숨어 있을 수 있다. 원인을 찾는다.
- 구현 계획: 먼저 실패 런의 로그를 확인한다. 로그가 이미 사라졌다면 같은 조건에서 `test` 단계를 몇 번 다시 돌려 재현되는지 센다. 느린 시험의 시간 제한 문제와 같은 계열이면 티켓 `20261021_1731`, `20261021_1732`에 합친다.
- 관련 파일: `.github/workflows/verify.yml`, `scripts/verify.sh`의 `test` 단계, 런 `39901233983`, 같은 계열 티켓 `20261021_1731`(5초 제한에 가까운 시험), `20261021_1732`(소스 트리를 훑는 시험의 느린 실행).

## 배경 / 문제 정의

티켓 `20261017_1638`의 게이트(민지)가 2026-10-23에 범위 밖 발견물로 남겼다([참고/신뢰성]). 이 브랜치는 `jam-web`을 건드리지 않아 시험 결과가 달라질 이유가 없다. 카리나가 실패 런의 로그를 `gh run view --log-failed`로 확인하려 했으나 아무 줄도 나오지 않았다.
