# [Infra] verify.sh가 CI에서 실패한 단계의 로그를 출력하지 않아 원인을 못 찾는다

## 핵심 요약

- 요구사항: `scripts/verify.sh`는 단계별 로그를 러너의 임시 폴더(`/tmp/tmp.XXXX/verify.test` 등)에만 쓰고 CI 화면에는 «verify 실패: test»와 로그 경로만 찍는다. 로컬에서 재현되지 않는 실패(느린 러너의 시간 초과 등)는 어느 시험이 실패했는지 알 수 없다. CI에서 실패한 단계의 로그 끝을 출력하게 한다.
- 구현 계획: `verify.sh`의 실패 요약 구간(`verify 실패:` 출력 바로 뒤)에서, 환경변수 `CI`가 있을 때만 실패한 단계마다 로그의 끝 200줄을 출력한다. 로컬 출력(20줄 이내 원칙)은 바꾸지 않는다. 진단용 브랜치 `claude/diag-ci-test-log-20261023`에 같은 변경이 한 번 들어갔고 CI에서 실제로 시험 이름이 보였다.
- 관련 파일: `scripts/verify.sh`(130행 부근 `verify 실패` 분기), `.github/workflows/verify.yml`

## 배경 / 문제 정의

티켓 `20261022_2119`(7-7a) 4회 게이트의 민지가 «CI `test` 실패, 로컬 재현 불가, 실패 시험 이름을 알 수 없다»고 FAIL을 냈고, 원인을 찾으려고 진단용 브랜치를 올려 CI를 따로 돌려야 했다(원인은 티켓 `20261023_1422`). 로그가 출력됐다면 한 번에 알 수 있었다.

## 완료 조건

- CI에서 `verify`가 실패하면 실패한 단계의 로그 끝이 Actions 화면에 보인다.
- 로컬 실행과 push 훅의 출력은 지금과 같다(`CI`가 없으면 로그를 출력하지 않는다).
- `verify.sh`를 다루는 기존 시험이 통과한다.
