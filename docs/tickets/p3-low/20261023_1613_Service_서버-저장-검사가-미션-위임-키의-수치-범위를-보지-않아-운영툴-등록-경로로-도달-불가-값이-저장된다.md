# [Service] 서버 저장 검사가 미션 위임 키의 수치 범위를 보지 않아 운영툴 등록 경로로 도달 불가 값이 저장된다

## 핵심 요약

- 요구사항: 미션 `engine_condition`의 위임 키(서로 다른 시간대 2~6개, 평균 파워 0~2000 등)의 수치 범위를 서버 저장 검사(`checkMissionConditionValue`)가 보지 않는다. 티켓 `20261021_1114` 1회가 어드민 양식에서만 범위를 막았기 때문에, 양식을 거치지 않는 운영툴 등록 경로로는 범위 밖 값(서로 다른 시간대 9개 등)이 그대로 저장되고 그 미션은 절대 완료되지 않는다. 서버 저장 검사가 레지스트리의 범위 정의로 같은 값을 막게 한다.
- 구현 계획: 한 번에 돌린다. 먼저 `checkMissionConditionValue`가 현재 어떤 키의 범위를 보는지 정리하고, 위임 키 12개와 기존 14개 가운데 수치 키의 `min`·`max`를 레지스트리에서 읽어 같은 판정을 서버에 둔다. 규칙을 따로 적지 않고 레지스트리 값을 읽는다. 폼의 `missionConditionRangeError`와 같은 함수를 쓸 수 있으면 합친다.
- 관련 파일: `jam-web/src/lib/missions/condition-keys.ts` 706줄 근처(`checkMissionConditionValue`), `jam-web/src/app/admin/missions/missionFormRules.ts`(`findMissionFormSaveError`)와 `missionConditionFields.ts`(`missionConditionRangeError`), 레지스트리 `jam-web/src/lib/badge-engine/conditionRegistry.ts`.

## 배경 / 문제 정의

티켓 `20261021_1114` 1회의 게이트(민지)가 2026-10-23에 [보안/주의]로 남겼다. 이번 수정으로 새로 생긴 구멍이 아니라 이 키들은 원래 서버가 범위를 보지 않았다. 티켓 1114의 상세 요구사항은 «서버 저장 검사가 최종 방어선이고 양식은 안내와 사전 차단이다»라고 적었는데, 이 키들은 그 전제가 맞지 않는다.

## 완료 조건

- [ ] 운영툴 등록 경로로 범위 밖 값(예: `distinct_time_bands` 9)을 저장하려 하면 서버가 막고 이유를 알린다
- [ ] 범위 안의 경계값은 저장된다
- [ ] 시험이 두 경우를 고정한다
