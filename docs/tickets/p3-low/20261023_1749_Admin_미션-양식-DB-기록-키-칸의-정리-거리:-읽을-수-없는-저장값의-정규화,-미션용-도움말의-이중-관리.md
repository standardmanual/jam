# [Admin] 미션 양식 DB 기록 키 칸의 정리 거리: 읽을 수 없는 저장값의 정규화, 미션용 도움말의 이중 관리

## 핵심 요약

- 요구사항: 티켓 `20261021_1114` 2회 게이트(민지)가 남긴 참고 2건을 정리한다. (1) 저장돼 있는 DB 기록 키 값이 입력 칸이 읽을 수 없는 모양이면(문자열 «3», 카테고리 없는 객체 등) 전에는 원본 그대로 보존했지만 이제는 칸으로 바꾼 뒤 조립해서, 저장할 때 모양이 바뀌거나 빠진다. 칸에 쓰는 단계의 실패는 `catch`로 삼켜진다. (2) 미션용 도움말 6개(`MISSION_DB_HELP_OVERRIDES`)가 배지 조건 레지스트리의 도움말과 이중으로 관리돼, 레지스트리 문구가 바뀌어도 시험이 칸 이름만 대조해서 미션 쪽 문구가 낡는 것을 잡지 못한다.
- 구현 계획: (1)은 읽을 수 없는 값을 열 때 경고를 띄울지, 원본 보존으로 되돌릴지 정한다. 운영툴 등록 경로로 만든 미션에서만 생길 수 있어 지금 영향은 작다. (2)는 도움말 6개가 레지스트리 문구에서 어디가 달라지는지를 시험으로 고정하거나, 레지스트리에 미션용 문구 자리를 만든다.
- 관련 파일: `jam-web/src/app/admin/missions/missionConditionFields.ts` 177줄 근처(도움말 덮어쓰기), 450줄 근처(칸 변환과 조립).
