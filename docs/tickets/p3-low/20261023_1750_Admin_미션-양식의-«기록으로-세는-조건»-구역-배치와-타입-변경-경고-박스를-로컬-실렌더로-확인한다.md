# [Admin] 미션 양식의 «기록으로 세는 조건» 구역 배치와 타입 변경 경고 박스를 로컬 실렌더로 확인한다

## 핵심 요약

- 요구사항: 티켓 `20261021_1114` 2회가 미션 양식에 «기록으로 세는 조건» 구역(DB 기록 키 20개)을 만들었는데, 격리 작업 환경에서는 어드민 화면을 열 수 없어 배치를 눈으로 확인하지 못했다(게이트 WARN, 사용자가 같은 사유는 머지 뒤 별도 확인으로 처리하기로 했다). 로컬 개발 서버에서 어드민 미션 양식을 열어 확인한다.
- 구현 계획: 메인 작업 폴더에서 로컬 `next dev`를 `ADMIN_EMAILS` 셸 환경변수와 함께 띄운다. 티켓 `20261023_1443`(배지 양식 경고 박스), `20261023_1507`(정책 대시보드), `20261023_1614`(1회 위임 키 칸 배치)와 같은 세션에서 묶어 한 번에 한다. 저장 버튼은 누르지 않는다.
- 관련 파일: `jam-web/src/app/admin/missions/MissionConditionSection.tsx`(구역과 소제목 6개, 경고 박스), `jam-web/src/app/admin/missions/missionConditionFields.ts`(칸 정의, 177줄 근처의 미션용 도움말 6개).

## 배경 / 문제 정의

1114 2회 게이트 WARN 사유 2·3이다. 서버 렌더 시험은 값 채움과 마크업 존재를 고정할 뿐 레이아웃은 보지 못한다. 사용자가 따로 보지 않은 문구(미션용 도움말 6칸, 객체형 키 두 개의 안쪽 개수 범위 1~1,000,000)도 화면에서 눈으로 읽어 본다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 문구는 UX Writing 가이드라인에 맞는지 읽어 보고, 고칠 곳이 있으면 사용자에게 먼저 보여 드린다.
