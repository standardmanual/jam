# [Service] 믹스 화면에 들어올 때마다 컬렉션 목록 조회가 돌아 DB 읽기량이 늘어난다

## 핵심 요약

- 요구사항: `/combine` 서버 컴포넌트가 들어올 때마다 `users`, `item_books`, 소속 컬렉션의 아이템 배지(`.in` 청크 페이징)를 읽는다. 등급 올리기 화면에 들어가지 않아도 읽는다. 받지 않은 결과 개수 조회와 `Promise.all`로 함께 읽어 대기 시간은 늘지 않지만 DB 읽기량은 는다. 오픈 뒤 지표(응답 시간·읽기량)를 보고 필요하면 등급 올리기 입구를 열 때 읽거나 짧은 캐시를 두는 쪽으로 줄인다.
- 구현 계획: 오픈 뒤 `/combine`의 응답 시간과 DB 읽기량을 먼저 재고, 부담이 확인되면 목록 조회를 등급 올리기 화면을 열 때 읽는 방식(서버 액션 또는 라우트)으로 옮기거나 짧은 캐시를 둔다. 지금은 아무것도 고치지 않는다.
- 관련 파일: `jam-web/src/app/(main)/combine/page.tsx`(216행 부근, 컬렉션 목록 조회와 `Promise.all`), `jam-web/src/lib/combine/tierUpCollections.ts`

## 배경 / 문제 정의

티켓 `20261023_1648`(7-7b) 3회 게이트(민지)의 범위 밖 발견물이다(성능/참고). 3회는 목록이 화면 첫 렌더에 함께 내려와야 해서(`null`과 빈 배열 구분, 새로고침 없이 시트를 연다) 서버 컴포넌트에서 읽는 방식을 골랐다.

## 완료 조건

- 오픈 뒤 지표로 부담이 확인되지 않으면 고치지 않고 닫는다.
- 부담이 확인되면 읽는 시점이나 캐시 방식을 정하고 `/combine` 시험이 그대로 통과한다.
