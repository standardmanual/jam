# [Service] 컬렉션 목록 읽기 조건이 loadRollData와 따로 적혀 있어 트라이브 규칙을 넓힐 때 같이 고쳐야 한다

## 핵심 요약

- 요구사항: 믹스 화면의 컬렉션 목록은 읽는 양을 줄이려고 `item_books`를 «소속 트라이브·활성·드랍 제외 아님»으로 좁혀 읽는다. 이 조건이 서버 굴림이 쓰는 `loadRollData`와 따로 적혀 있다. 최종 판정은 두 곳 모두 `listIssueCandidates`가 하므로 지금은 어긋나지 않지만, 고를 수 있는 컬렉션을 다른 트라이브로 넓히면 이 읽기 조건도 같이 고쳐야 한다. 같이 고치는 것을 잊지 않게 하나의 상수나 함수로 합치거나 시험으로 묶는다.
- 구현 계획: 읽기 조건을 `lib/combine`의 한 함수로 뽑아 `tierUpCollections.ts`와 서버 굴림이 같이 쓰게 하거나, 두 조건이 같다는 시험을 더한다. 다른 트라이브 컬렉션을 열기로 정하는 시점에 함께 한다.
- 관련 파일: `jam-web/src/lib/combine/tierUpCollections.ts`(76행 부근 읽기 조건), `jam-web/src/lib/combine/tierUp.ts`(`loadRollData`)

## 배경 / 문제 정의

티켓 `20261023_1648`(7-7b) 3회 게이트(민지)의 범위 밖 발견물이다(구조/참고). 3회 가정 (가)는 «소속 트라이브의 열린 컬렉션만»이다.

## 완료 조건

- 서버 굴림과 믹스 화면 목록의 읽기 조건이 한 곳에서 정해지거나 같다는 시험이 있다.
- 다른 트라이브까지 열 때 두 곳이 어긋나지 않는다.
