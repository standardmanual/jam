# [Admin] 정수 칸 안내가 배지 양식과 미션 양식의 오류 줄에 실제로 보이는지 로컬 실렌더로 확인한다

## 핵심 요약

- 요구사항: 티켓 `20261023_1748`이 정수 칸의 소수·지수 표기를 저장 전에 막고 안내하게 했는데, 격리 작업 환경에서는 어드민 화면을 열 수 없어 안내가 화면에 보이는지 확인하지 못했다(게이트 WARN, 사용자가 같은 사유는 머지 뒤 별도 확인으로 처리하기로 했다). 로컬 개발 서버에서 어드민 배지 양식과 미션 양식을 열어 확인한다.
- 구현 계획: 메인 작업 폴더에서 로컬 `next dev`를 `ADMIN_EMAILS` 셸 환경변수와 함께 띄운다. 티켓 `20261023_1443`, `20261023_1507`, `20261023_1614`, `20261023_1750`과 같은 세션에서 묶어 한 번에 한다. **정수가 아닌 값을 넣고 저장을 누르기 전에 브라우저에서 `fetch`를 가로채 저장 요청이 나가지 않게 막아 둔다.** 막는 동작이 어긋나도 공용 DB에 쓰지 않기 위해서다.
- 관련 파일: `jam-web/src/app/admin/badges/BadgeForm.tsx`(하단 오류 줄 1400줄 근처), `jam-web/src/app/admin/missions/MissionForm.tsx`(오류 줄 558줄 근처), `jam-web/src/lib/badge-engine/conditionRegistry.ts`(`describeNonIntegerInputs`).

## 배경 / 문제 정의

1748 게이트 WARN의 유일한 사유다. 단위 시험은 판정 함수와 문구를 고정할 뿐 안내가 오류 줄에 실제로 보이는지, 줄바꿈이 어색하지 않은지는 보지 못한다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 문구가 어색하면 고치기 전에 사용자에게 먼저 보여 드린다.

## 완료 조건

- [ ] 배지 양식의 정수 칸에 «2.5»와 «1e3»을 쓰고 저장을 누르면 칸 이름과 입력한 값이 든 안내가 오류 줄에 보이고 저장 요청이 나가지 않는다
- [ ] 미션 양식도 같은 안내가 보인다
- [ ] 정수가 아닌 칸이 둘 이상이면 첫 칸의 안내 뒤에 «이 밖에 N칸에도 정수가 아닌 값이 있어요.»가 붙는다
- [ ] 정수 칸은 숫자 키패드, 소수 칸은 소수 키패드가 뜬다
- [ ] 320px 폭에서 안내가 잘리거나 가로로 넘치지 않는다
