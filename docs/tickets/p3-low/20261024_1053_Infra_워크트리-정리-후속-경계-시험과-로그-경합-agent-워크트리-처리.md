# [Infra] 워크트리 정리 후속: 허용 목록 경계 시험을 더하고, 로그 경합·`agent-*` 워크트리 처리를 정한다

> 후속 티켓(2026-10-24 카리나, 티켓 20261001_1143 게이트 WARN 사유와 범위 밖 발견물을 묶었다. 사용자가 «머지하고 후속 티켓 1건으로 묶기»를 골랐다).

## 핵심 요약

- 요구사항: 티켓 20261001_1143으로 `scripts/workspace-setup.sh cleanup`이 `.claude/worktrees/` 아래 `wf_*`·`gate-*`만 지우게 됐다. 그 구현을 판정한 민지의 WARN 사유 둘과 발견물 넷을 정리한다. 이 가운데 ①과 ⑥은 바로 할 수 있고 ②~⑤는 사용자 결정이 필요하다.
- 구현 계획: ①은 시험 보강, ⑥은 선택. ②~⑤는 아래 선택지에서 사용자가 고른 뒤 파일 단위로 적는다.
- 관련 파일: `scripts/workspace-setup.sh`(`is_cleanup_target_path` 허용 목록, `trim_cleanup_log` 140~141행 부근, `report_worktree`, `awk '{print $2}'` 38행·208행 부근), `scripts/workspace-setup.test.mjs`(신규 사례 99행 부근), `.claude/agents/jam-reviewer.md` 164행(`gate-*` 워크트리 생성), `docs/agents/team-operations.md` 「워크트리 수명」 3번

## 배경 / 문제 정의

20261001_1143의 게이트(민지, 2026-10-24)는 WARN이었고 통과 항목은 스펙, 회귀, 안전 조건 유지, 문서였다. 아래는 그때 남은 것이다. 근거 줄 번호는 병합 전 리뷰 브랜치(`cb5627587`) 기준이다.

## 결정이 필요한 항목과 선택지

- **② 로그 경합**: (a) 그대로 둔다. 진단용 로그의 손실뿐이고 승인된 «최근 500줄만 유지» 그대로다(추천). (b) 줄이는 대신 `mv log log.1`로 회전해 유실 없이 두 파일(최대 약 1000줄)을 유지한다. 승인된 문구와 달라지므로 사용자 확인이 필요하다.
- **③ 로그 소음**: (a) 그대로 둔다(추천 보류). (b) «정리 대상 경로 아님» 보존 줄은 로그에 쓰지 않고 화면에만 낸다. 허용 목록 안의 판정(제거, 보존, 실패)만 남겨 500줄이 오래 간다. 가정 2의 «보존 포함 판정 기록»과 달라진다.
- **④ `agent-*`**: (a) 허용 목록에 `agent-*`를 더한다. Agent 도구로 아현·민지를 직접 부르는 지금 방식에서 쌓이는 폴더가 자동 정리된다. 앱 세션 이름과 겹치지 않는지 확인이 필요하다. (b) 더하지 않고 호출한 쪽이 끝나면 수동으로 지운다(현재 방식). 추천은 정하기 전에 앱 세션 워크트리가 `agent-` 접두를 쓰는지 사용자 PC에서 확인하는 것이다.
- **⑤ `gate-*` 잠금**: 민지가 `git worktree add` 직후 `git worktree lock`을 걸고 판정이 끝나면 푸는 한 줄을 `jam-reviewer.md` 164행에 더할지 정한다. 추천은 더하는 것이다(잠긴 워크트리는 `git worktree remove`가 거부한다).

## 구현 계획

1. ① `scripts/workspace-setup.test.mjs`에 허용 목록 경계 사례를 더한다. 임시 저장소에서 변경이 없고 `staging`에 병합된 워크트리를 이름만 바꿔 만든 뒤 `cleanup`을 실행해 모두 «보존»이고 지워지지 않는 것을 확인한다: 다른 위치의 `wf_outside`(`.claude/worktrees` 밖), 대소문자 `WF_upper`·`Gate-upper`, 비슷한 이름 `wfx`·`gate_x`, 이름에 공백이 든 `wf_ space`. 하위 폴더 `wf_nest/sub`가 `git worktree add`로 만들어지면 그것도 포함한다. 허용 이름 `wf_ok`·`gate-ok`는 제거되는 것을 같은 시험에서 확인한다.
2. ⑥은 ①의 공백 사례가 «보존»으로 끝나는지만 확인하고, `awk` 줄은 고치지 않는다(지우지 않는 쪽이라 위험이 없다). 로그 경로 표기가 거슬리면 따로 정한다.
3. ②~⑤는 위 선택지에 대한 사용자 답을 이 티켓에 적은 뒤, 고르는 안에 맞춰 파일 단위 계획을 덧붙이고 구현한다.
