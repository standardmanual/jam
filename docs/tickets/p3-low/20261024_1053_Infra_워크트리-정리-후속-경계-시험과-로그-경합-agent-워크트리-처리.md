- 사용자 결정(2026-10-24, «추천대로 진행해»): ②③은 그대로 두고, ⑤는 구현하며, ④는 사용자 PC 확인 뒤로 미룬다(위 「사용자 결정」). ⑤는 지시문 한 줄이라 카리나가 직접 고쳤고 민지 게이트는 부르지 않았다. 민지가 자기 지시문을 판정하는 구조가 되고, 시험으로 고정할 수 있는 동작은 git 쪽(잠긴 워크트리 제거 거부)뿐이기 때문이다. 그 동작은 기존 시험(`wf_locked` 사례)이 이미 고정하고 있고, 이번에 임시 저장소에서 «잠금 상태 제거 거부 → 해제 후 제거 성공»을 명령으로 다시 확인했다.

### 잔여 이슈
- ④ 대기: 사용자 PC에서 앱 세션 워크트리 폴더 이름이 `agent-`로 시작하는지 확인해 알려 주면, 안 쓰면 허용 목록에 `agent-*`를 더하고 쓰면 더하지 않는다. 그때까지 `agent-*`는 호출한 쪽이 끝난 뒤 수동으로 지운다. 그래서 이 티켓은 `IN_PROGRESS`로 열어 둔다.
- ⑤의 한계: 지시문은 민지가 따라야 동작한다. 판정 도중 세션이 끊기면 잠긴 `gate-*`가 남고, 정리는 이를 «제거 실패»로 로그에 남기며 지우지 않는다. 그때는 `git worktree unlock <경로>` 뒤 `git worktree remove <경로>`로 직접 지운다. 또 이 지시는 공유 폴더에서 호출될 때 `gate-*`를 만드는 경우에만 해당하며, 격리 워크트리에서 도는 게이트(Workflow 게이트, `/jam-ship` 모드 ②·③)는 `gate-*`를 만들지 않는다. 지시문이 실제 호출에서 지켜지는지는 시험으로 확인하지 못했다.
- awk를 고쳐 공백 경로를 온전히 읽게 할 때는 `wf_ space`가 `wf_*`에 맞아 지워지게 된다. 그 변경에서 공백이 든 이름을 허용 목록이 어떻게 다룰지(허용 이름 규칙에서 공백 제외 등)를 함께 정하고, 이 시험의 공백 사례 단언 두 개(존재 확인과 출력 줄)도 같이 고쳐야 한다.
- 한국어 로캘(ko_KR)에서의 시험 실행은 확인하지 못했다. 컨테이너에는 `C`, `C.utf8`, `POSIX`만 있고, 잠금 사유 단언은 git 메시지 내용을 보지 않아 영향이 낮다고 민지가 판단했다.
- 이 작업 중 Agent 도구의 격리 워크트리 `agent-*` 2개가 컨테이너에 다시 생겼다. 항목 ④의 결정 전까지는 호출한 쪽이 끝난 뒤 수동으로 지운다.
