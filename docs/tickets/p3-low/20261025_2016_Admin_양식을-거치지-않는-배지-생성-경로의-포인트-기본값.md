# [Admin] 양식을 거치지 않는 배지 생성 경로(운영툴 JAM! 배지 등록, 에셋 등록 스크립트)가 포인트를 비우면 0으로 만든다

## 핵심 요약

- 요구사항: 7-4(`20261022_1135`) 1회가 배지 생성 API(`POST /api/admin/badges`)와 새 배지 양식에는 일괄 포인트 값을 채우게 했지만, 같은 공용 함수 `buildBadgeInsertPayload`(`jam-web/src/lib/admin/badge-insert-payload.ts`)를 쓰는 운영툴 JAM! 배지 등록(`jam-web/src/lib/admin/opsInbox/registerInput.ts` 617~658줄 근처)과 에셋 등록 스크립트(`scripts/asset-generator/registerBundle.mjs`)는 포인트를 비우면 0으로 들어간다. 이 경로도 일괄 값을 쓰게 할지 정한다.
- 구현 계획: 사용자가 정한 뒤 정한다. 후보는 (가) 공용 함수에 일괄 값을 받는 인자를 더해 두 경로가 `getBadgePointPolicy`로 읽은 값을 넘기게 한다, (나) 지금처럼 두고 등록 직후 어드민에서 고친다. 공용 함수의 기본 동작(없으면 0)은 7-4에서 바꾸지 않았다.
- 관련 파일: `jam-web/src/lib/admin/badge-insert-payload.ts` 137줄, `jam-web/src/lib/badge/pointPolicy.ts`, `jam-web/src/lib/admin/badge-point-defaults.ts`, `jam-web/src/lib/admin/opsInbox/registerInput.ts`, `scripts/asset-generator/registerBundle.mjs`.

## 배경 / 문제 정의

7-4 사용자 결정(2026-10-24)에서 «배지 생성 API만 기본값을 채우고, 운영툴 등록과 에셋 스크립트는 P3 후속 티켓으로 남긴다»고 정했다. 두 경로는 서버 밖 스크립트나 운영툴 입력을 거쳐 같은 공용 함수를 부르므로 함수를 바꾸면 영향 범위가 넓다(숨김 배지 0 제약, 등록 스크립트 시험). 지금 이 경로로 만든 배지는 포인트가 0이라 289·290 같은 적용 SQL을 다시 돌려야 일괄 값이 된다.

## 완료 조건

- 사용자가 (가)와 (나) 중 하나를 정해 이 티켓에 적었다.
- (가)라면 두 경로로 포인트를 비운 배지를 만들 때 등급별 일괄 값(레벨형은 레벨형 값, 숨김은 0)이 들어가고 시험이 있다. 값을 준 경우는 그대로다.
- (나)라면 «하지 않는다»와 사유를 완료 기록에 적는다.
