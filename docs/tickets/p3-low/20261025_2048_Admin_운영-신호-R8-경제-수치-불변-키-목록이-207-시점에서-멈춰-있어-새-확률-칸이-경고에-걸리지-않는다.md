# [Admin] 운영 신호 R8 «경제 수치 불변» 키 목록이 207 시점에서 멈춰 있어 새 확률 칸이 경고에 걸리지 않는다

## 핵심 요약

- 요구사항: R8 «경제 수치 불변»이 보는 키 목록(`ops_rules.economy_keys` 행)이 시드 `207_ops_rules.sql`의 23개에서 멈춰 있다. 새로 생긴 확률 칸(`combine_policy.tier_up_probability` 외에도 7-1·7-2·7-3에서 더해진 칸들)을 바꿔도 R8 경고가 뜨지 않는다. 목록은 코드가 아니라 DB 행만 읽고 시드가 `ON CONFLICT DO NOTHING`이라, 넣으려면 데이터 마이그레이션(또는 어드민에서 행 수정)이 필요하다. 빠진 확률 칸을 한 번에 훑어 넣는다.
- 구현 계획: 빠진 경제 수치 칸을 `capsule_policy`, `jam_policy`, `combine_policy`, `ambient_drop_config` 등에서 훑어 목록을 정하고, 마이그레이션(번호는 `origin/staging` 기준 최대+1)으로 `ops_rules.economy_keys`를 갱신한다. DB 변경이라 롤백 실측과 사용자 승인을 거친다.
- 관련 파일: `jam-web/supabase/migrations/207_ops_rules.sql`(89행 부근 시드), `jam-web/src/lib/admin/opsInbox/balance/rules.ts`(27행 부근)

## 배경 / 문제 정의

티켓 `20261023_1648`(7-7b) 4회에서 아현이 `tier_up_probability`를 넣지 않기로 하고 근거를 남겼고, 민지가 같은 점을 지적했다(정확성/주의). 이 칸 하나만 넣으면 목록이 계속 낡으므로 빠진 칸을 함께 정리하는 쪽을 권한다.

## 완료 조건

- R8이 보는 경제 수치 칸 목록에 지금 어드민에서 바꿀 수 있는 확률·비용·임계값 칸이 빠짐없이 들어 있다.
- 변경은 롤백 실측 뒤 사용자 승인으로 적용하고, 어드민 밸런스 변경이 R8 경고로 나오는 것을 시험으로 확인한다.
