# [Admin] 어드민 밸런스 칸의 퍼센트 변환이 NUMERIC(4,3) 눈금을 전제로 해 자릿수 제한이 없는 윗등급 확률과 맞지 않을 수 있다

## 핵심 요약

- 요구사항: `fractionToPercent`는 `NUMERIC(4,3)`(0.001 눈금)을 전제로 반올림하는데 `combine_policy.tier_up_probability`는 자릿수 제한이 없는 `NUMERIC`이다. 어드민으로만 저장하는 동안(소수 첫째 자리 퍼센트)은 어긋나지 않지만, SQL로 0.7123 같은 값을 직접 넣으면 어드민에는 71.2로 보이고 확률 안내는 원래 값을 읽는다. 칸의 눈금을 `NUMERIC(4,3)`로 좁히거나 변환이 칸마다 눈금을 받게 한다.
- 구현 계획: 어드민 밖에서 값을 넣을 일이 없으면 고치지 않는다. 필요하면 칸 정의에 눈금을 두거나(`fields.ts`) DB 칸을 `NUMERIC(4,3)`으로 좁힌다(DB 변경은 승인 필요).
- 관련 파일: `jam-web/src/lib/admin/balance/fields.ts`(43행 부근 `fractionToPercent`), `jam-web/src/lib/admin/balance/collection.ts`, `jam-web/supabase/migrations/287_combine_policy_tier_up_probability.sql`

## 배경 / 문제 정의

티켓 `20261023_1648`(7-7b) 4회 게이트(민지)의 범위 밖 발견물이다(정확성/참고).

## 완료 조건

- 어드민 밖에서 넣은 값이 어드민 표시와 확률 안내에서 같게 보이거나, 그런 값이 들어갈 수 없다.
- 시험이 소수 눈금 밖의 값을 고정한다.
