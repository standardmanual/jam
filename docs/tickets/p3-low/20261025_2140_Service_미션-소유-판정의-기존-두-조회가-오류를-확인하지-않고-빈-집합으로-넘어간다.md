# [Service] 미션 소유 판정의 기존 두 조회가 오류를 확인하지 않고 빈 집합으로 넘어간다

## 핵심 요약

- 요구사항: `jam-web/src/lib/missions/checker.ts`의 `loadOwnership`(558~572줄 근처)에서 `user_activity_badges`와 `inventory` 조회가 `error`를 확인하지 않는다. 조회가 실패하면 조용히 빈 집합이 되어 체크인·아이템 수집 미션이 미달성으로 끝난다. 이번에 더한 체크인 이력 조회(티켓 `20260930_0014`)만 `console.error`로 원인을 남긴다.
- 구현 계획: 두 조회에도 같은 방식으로 오류를 `console.error`로 남기고, 실패하면 미달성으로 두는 지금 동작은 유지한다(예외를 던지지 않는다). 시험은 `checker-ownership.test.ts`에 오류 응답 사례를 더한다.
- 관련 파일: `jam-web/src/lib/missions/checker.ts`(`loadOwnership`), `jam-web/src/lib/missions/checker-ownership.test.ts`.

## 배경 / 문제 정의

티켓 `20260930_0014`의 게이트(민지, 2026-10-25) 범위 밖 발견물이다(정확성/참고). 미달성 쪽으로 끝나 안전하지만 원인이 로그에 남지 않아 일시 오류와 실제 미달성을 구별하기 어렵다.

## 완료 조건

- `user_activity_badges`와 `inventory` 조회가 오류를 내면 `console.error`가 한 번 불리고 `checkMissions`는 예외 없이 끝난다(시험).
- 정상 응답일 때 동작은 그대로다(기존 시험 통과).
