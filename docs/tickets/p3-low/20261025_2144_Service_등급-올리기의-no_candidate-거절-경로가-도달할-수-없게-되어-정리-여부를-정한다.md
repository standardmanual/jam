# [Service] 등급 올리기의 no_candidate 거절 경로가 도달할 수 없게 되어 정리 여부를 정한다

## 핵심 요약

- 요구사항: 티켓 `20261025_2011`이 서버에서 재료 등급과 바로 윗등급이 모두 있는 컬렉션만 받게 하면서, `jam-web/src/lib/combine/tierUp.ts`의 ⑦ 굴림 뒤 `no_candidate` 거절(221줄 근처)과 문구 `d.combine.tierUp.noCandidate`(`jam-web/src/lib/i18n/ko.ts` 2068줄 근처)가 정상 흐름에서는 도달할 수 없게 됐다. 방어용으로 남겨 두었으니 지울지, 방어로 남기고 시험으로 고정할지 정한다.
- 구현 계획: 코드와 문구를 지우면 라우트의 거절 매핑과 시험, 확률 안내·운영 로직의 서술도 함께 정리한다. 남기면 «도달할 수 없다»는 주석과 방어 시험만 두고 닫는다. 사용자 판단 거리라 시작 때 질문한다.
- 관련 파일: `jam-web/src/lib/combine/tierUp.ts`, `jam-web/src/lib/i18n/ko.ts`, `jam-web/src/app/api/combine/tier-up/route.ts`(거절 매핑), `jam-web/src/lib/combine/__tests__/tierUp.test.ts`.

## 배경 / 문제 정의

티켓 `20261025_2011`의 게이트(민지, 2026-10-25) 범위 밖 발견물이다(정확성/참고). 방어용으로 남긴 것은 합당하나 이후 정리 여부는 별도로 판단하도록 남겼다.

## 완료 조건

- `no_candidate` 경로를 지우거나 방어용으로 남긴다는 결정과 사유가 기록돼 있고, 결정대로 코드와 문구, 시험이 일치한다.
