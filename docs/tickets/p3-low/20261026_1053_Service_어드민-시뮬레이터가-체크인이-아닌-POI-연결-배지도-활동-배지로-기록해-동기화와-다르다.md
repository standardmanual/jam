# [Service] 어드민 시뮬레이터가 체크인이 아닌 POI 연결 배지도 활동 배지로 기록해 동기화와 다르다

## 핵심 요약

- 요구사항: `jam-web/src/app/api/admin/simulate/route.ts` 92~95줄 근처의 분기는 `badge.type`이 `checkin`이 아니면 `user_activity_badges`에 기록한다. 그런데 실제 동기화(`jam-web/src/lib/strava/sync.ts` 735줄 `badge.type !== 'checkin'`이면 건너뜀)는 옛 장소 연결 발급 경로를 삭제해 체크인이 아닌 타입의 POI 연결 배지를 발급하지 않는다. 시뮬레이터가 실제와 다른 결과를 낸다.
- 구현 계획: 시뮬레이터의 해당 분기를 지우거나 동기화와 같이 건너뛴다. 시뮬레이터 라우트의 시험(`jam-web/src/app/api/admin/simulate/__tests__/route.test.ts`)에 체크인이 아닌 타입이 기록되지 않는 사례를 더한다.
- 관련 파일: `jam-web/src/app/api/admin/simulate/route.ts`, `jam-web/src/lib/strava/sync.ts` 735줄.

## 배경 / 문제 정의

티켓 `20260930_0015` 2회(v2)의 게이트(민지, 2026-10-26) 범위 밖 발견물이다(정확성/참고). 이번 티켓은 시뮬레이터의 공개 기간만 다뤘다.

## 완료 조건

- 시뮬레이터가 체크인이 아닌 타입의 POI 연결 배지를 기록하지 않아 동기화와 같은 결과를 낸다(시험).

## 완료 기록

### 구현 내용 요약

어드민 시뮬레이터가 체크인이 아닌 타입의 장소 연결 배지를 실제 동기화와 같이 건너뛰게 했다.

- **원인:** 시뮬레이터는 장소에 연결된 배지의 `type`이 `checkin`이 아니면 획득 예정에 넣고 `dryRun=false`일 때 `user_activity_badges`에 기록했다. 실제 동기화(`lib/strava/sync.ts` 735줄 근처 `badge.type !== 'checkin'`이면 `continue`)는 옛 장소 연결 발급 경로를 삭제해 이 타입에 아무것도 하지 않는다.
- **변경:** `app/api/admin/simulate/route.ts`가 `poiBadgesById`를 만들 때 공개 기간 거름 앞에서 체크인 타입만 남긴다(주석으로 `sync.ts`의 같은 판정을 가리킨다). 체크인이 아닌 배지는 획득 예정에도 나오지 않고 어떤 표에도 기록되지 않는다. 장소 매칭(`poisMatched`)은 그대로 보인다. 죽은 코드가 된 `user_activity_badges` 기록 분기를 지웠고 `user_checkin_badge_earns` 기록만 남았다.
- **문서:** `BADGE_ENGINE_UNIFIED.md` 3.18절의 어드민 시뮬레이터 항목에 «체크인이 아닌 타입은 동기화와 같이 건너뛴다» 한 문장을 더했다.

### 주요 의사결정 / 핵심 메모

### 잔여 이슈
- 시뮬레이터가 «이미 받은 배지»를 `user_activity_badges`에서만 읽어 `earnedBadgeIds`를 채운다. 장소 연결 배지에는 이제 체크인 타입만 남아서 이 보유 검사가 장소 배지에는 효과가 없다. 체크인 배지는 `user_checkin_badge_earns`에만 쌓이기 때문이다(게이트 범위 밖 발견물).
- 같은 실행에서 같은 배지에 연결된 장소가 둘 이상이면 시뮬레이터는 한 번만 기록하고 동기화는 장소마다 기록한다. `docs/plan/jam2/service-redesign/current-service-map/02 액티비티 배지와 체크인 배지.md` 127줄이 비슷한 불일치를 이미 적어 두었다.
