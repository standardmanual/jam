# [Admin] 운영툴 PRD의 카드 글자 수 상한 숫자를 상수 참조로 바꾼다

> 출처: 티켓 20260930_1504 3회차 게이트(민지)의 범위 밖 발견물. 같은 사실을 두 곳에 적은 드리프트다.

## 핵심 요약

- 요구사항: 운영툴 PRD가 모양별 글자 수 상한 숫자를 직접 적어 둔 문장을 코드 상수를 가리키는 문장으로 바꾼다.
- 구현 계획: 숫자를 지우고 `CARD_TITLE_MAX_LENGTH`를 가리키게 한다. 같은 PRD의 다른 줄(1025행)이 이미 그렇게 쓴다.
- 관련 파일: `docs/service/prd/ops-tool/PRD.md` 950행(글자 수 상한 문장), 같은 문서 1025행(상수를 가리키는 기존 문장),
  `jam-web/src/lib/today/shape.ts` 26행 `CARD_TITLE_MAX_LENGTH`.

## 배경 / 문제 정의

- PRD 950행은 모양별 상한을 `hero` 22·`poster` 18·`square` 22·`brief` 28·`list` 22자, 5개 모양으로 적는다.
- 코드의 `CARD_SHAPES`는 7개 모양이고(`shape.ts` 18행), 티켓 20261022_2225에서 더한 `dome`·`ticket`의 상한(각 22자)이 PRD 문장에 없다.
- 같은 사실이 PRD와 코드에 두 번 있어서 모양이 늘 때마다 PRD가 낡는다. `CLAUDE.md` 절대 규칙 5(같은 사실을 여러 문서에 적지 않는다)에 어긋난다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 코드 변경은 없다. 문서만 고친다.
- 950행은 숫자 대신 `jam-web/src/lib/today/shape.ts`의 `CARD_TITLE_MAX_LENGTH`를 가리키고, 초과하면 경고만 한다(G15)는 동작 설명은 그대로 둔다.
- 홈피드 PRD §6(`docs/service/prd/home-feed/PRD.md`)이 같은 숫자를 적고 있는지 확인하고, 적고 있으면 같은 방식으로 정리한다.

## 구현 계획

1. `docs/service/prd/ops-tool/PRD.md` 950행의 숫자 나열을 상수 참조 문장으로 바꾼다.
2. 홈피드 PRD §6에 같은 나열이 있는지 확인하고 있으면 함께 바꾼다.
3. `node scripts/doc-check.mjs`와 `node scripts/check-contract.mjs`를 돌린다.

## 완료 조건

- 운영툴 PRD에 모양별 글자 수 숫자가 남아 있지 않고, 상수 이름과 경로로 원천이 가려진다.
- 홈피드 PRD에 같은 숫자 나열이 있었다면 그 문서도 같은 방식으로 바뀐다.
- `node scripts/doc-check.mjs`가 통과한다.
