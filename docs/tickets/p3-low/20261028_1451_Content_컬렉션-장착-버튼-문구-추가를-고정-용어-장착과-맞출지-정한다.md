# [Content] 컬렉션 장착 버튼 문구 «추가»를 고정 용어 «장착»과 맞출지 정한다

## 핵심 요약

- 요구사항: 컬렉션 상세의 장착 버튼 문구 `d.itembooks.slotButton`이 «추가»인데, UX Writing 가이드의 고정 용어는 «장착»(EQUIP)이다. 한 화면에서 버튼은 «추가», 안내 문구와 다른 버튼은 «장착»·«해제»로 갈린다. 맞출지, 맞춘다면 어떤 문구로 할지 정한다.
- 구현 계획: 사용자 결정 뒤에 `ko.ts` 한 곳을 고치고 영향받는 시험의 기대 문구를 맞춘다.
- 관련 파일: `jam-web/src/lib/i18n/ko.ts` `d.itembooks.slotButton`(1614줄 부근), 이 문구를 기대하는 시험(`collections/[id]/__tests__`, `SlotGrid.test.tsx`), `docs/service/writing/UX_WRITING_GUIDELINE.md` §1.3 «장착».

## 배경 / 문제 정의

티켓 20261028_1408의 채원 사전 판정과 민지 게이트가 같은 불일치를 범위 밖 발견물로 올렸다. 원래 있던 불일치이고 화면에 보이는 버튼 이름이라 그 티켓에서는 바꾸지 않았다. 가이드는 장착을 «컬렉션 화면에서 아이템배지 개체를 골라 채우는 행위»로 정의하고 «끼우기, 넣기, 세팅»을 금지 표기로 둔다. «추가»는 금지 표기 목록에 없지만 같은 행위를 가리키는 다른 말이다.

발견: 2026-10-28 티켓 20261028_1408 게이트(민지, 참고).

## 상세 요구사항

### 서비스/코드베이스 관점

- 버튼 문구 하나와 그 문구를 기대하는 시험만 바꾼다. 로직은 건드리지 않는다.

### UI/UX 관점

- «장착» 단어를 쓰면 버튼 폭이 달라지는지 320px 화면에서 확인한다.
- 사용자가 쓰는 말은 «추가»이므로(2026-10-28 대화), 고정 용어를 바꾸는 쪽(가이드에 «추가»를 허용 표기로 더함)도 선택지다. 결정은 사용자 몫이다.

## 구현 계획

1. 사용자가 방향을 정한다(버튼을 «장착»으로 바꿈 / 가이드를 바꿈 / 현행 유지).
2. 선택에 따라 `ko.ts`와 시험 또는 가이드 문서를 고친다.

## 완료 조건

- 컬렉션 화면의 버튼, 안내 문구, 시트 문구가 같은 용어를 쓴다.
- `scripts/verify.sh`가 통과한다.
