# [UI] 등급 없는 선택 시트의 Common 행에 스크린리더용 등급 이름을 더한다

## 핵심 요약

- 요구사항: 컬렉션 등급이 아직 없을 때 «추가»를 누르면 열리는 선택 시트는 한 이름의 여러 등급 배지를 한꺼번에 보여 준다. Common 행은 `RarityBadge` 규약상 등급 칩이 그려지지 않아 눈으로도 스크린리더로도 Common임을 알 단서가 없다. 눈에 보이는 모습은 바꾸지 않고 스크린리더용(`sr-only`) 등급 이름을 더한다.
- 구현 계획: `ItemCandidateRow`에 `sr-only` 텍스트 한 줄을 더하고 시험으로 고정한다. 드랍·픽업 시트의 읽기 결과가 달라지므로 그 영향도 확인한다.
- 관련 파일: `jam-web/src/components/inventory/ItemCandidateRow.tsx`(114줄 부근 등급 칩 그리는 곳), `jam-web/src/components/inventory/__tests__`의 행 시험, 호출부 `PoiCarouselModal.tsx`.

## 배경 / 문제 정의

티켓 20261028_1408에서 채원이 접근성 선택 사항으로 권했지만 눈에 보이는 모습을 바꾸지 않는 선택이라 그 티켓에서는 넣지 않았다. 민지 게이트가 같은 항목을 참고로 올렸다. 등급이 정해진 뒤의 시트는 후보가 한 등급뿐이라 문제가 작지만, 등급이 없는 상태의 시트는 등급이 섞여 있어 단서가 필요하다.

발견: 2026-10-28 티켓 20261028_1408 게이트(민지, 참고).

## 상세 요구사항

### 서비스/코드베이스 관점

- `sr-only` 텍스트는 등급 이름만 읽게 한다(예: «Common»). 문구는 UX Writing 가이드의 등급 표기(영문 고정)를 따른다.
- 드랍·픽업 시트에서는 같은 등급 안에서 읽는 말이 늘어나는 것이므로, 같은 행을 쓰는 곳 전부에서 어색하지 않은지 확인한다.

### UI/UX 관점

- 눈에 보이는 모습은 바뀌지 않는다.

## 구현 계획

1. `ItemCandidateRow`가 등급을 알고 있을 때(`candidate.rarity ?? rarity`) Common이어서 칩이 없는 경우에만 `sr-only` 이름을 그린다. Rare 이상은 칩이 이미 읽히므로 중복해서 읽지 않게 한다.
2. 행 시험에 Common일 때 `sr-only`가 있고 Rare일 때 중복이 없는 사례를 더한다.

## 완료 조건

- Common 행에 스크린리더용 등급 이름이 있고, 화면 모습은 이전과 같다. 시험으로 고정한다.
- Rare 이상 행은 읽는 말이 늘지 않는다. 시험으로 고정한다.
- `scripts/verify.sh`가 통과한다.
