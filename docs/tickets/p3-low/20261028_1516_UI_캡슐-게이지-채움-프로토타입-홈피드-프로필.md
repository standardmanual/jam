# [UI] 홈피드·프로필 캡슐 게이지 채움 모션을 프로토타입(spike)으로 만든다

> 출처: 사용자가 첨부한 화면 기록(`화면 기록 2026-10-28 오후 3.05.04.mov`, 7.5초)과 요구 목록.
> 서비스 반영이 아니라 모션·흐름을 눈으로 확인하는 프로토타입이다. 서비스 컴포넌트는 바꾸지 않는다.

## 핵심 요약

- 요구사항: 어두운 캡슐 안에서 오렌지 캡슐이 오른쪽으로 차오르는 게이지를 `/spike`에 만든다. 진입 모션, 시트에서 채우기, 100% 도달 시 전체 화면 확장과 축하 문구, 닫은 뒤 남은 잼 채우기까지 한 흐름으로 보여 준다.
- 구현 계획: 순수 계산(`capsuleFillMath.ts`) + 표현 컴포넌트(`JamGauge.tsx`) + 전체 화면 오버레이(`LevelUpOverlay.tsx`) + 흐름 조립(`CapsuleFillModule.tsx`) + 시연 화면(`CapsuleFillPrototype.tsx`)으로 나눈다. 시트는 기존 `BottomSheet`·`JamFillPanel`을 재사용한다.
- 관련 파일: `jam-web/src/app/spike/capsule-fill/` (신규 라우트). 참고만 하고 바꾸지 않는 파일: `components/capsule/CapsulePill.tsx`, `RadialCapsule.tsx`, `CapsuleSheet.tsx`, `components/jam/JamFillPanel.tsx`.

## 배경 / 문제 정의

- 현재 서비스의 캡슐 알약은 방사형 그라데이션 디자인(`RadialCapsule`)이다. 새 방향은 어두운 트랙 안에 오렌지 채움이 차오르는 형태다.
- 실제 서비스에 넣기 전에 모션 흐름(진입·채우기·챕터 오름)이 의도대로 읽히는지 프로토타입으로 먼저 확인한다.

## 상세 요구사항

### UI/UX 관점

- 어두운 캡슐 안에 오렌지 캡슐이 오른쪽으로 채워진다. 그래프 2%(원형 최소 채움)가 캡슐 잼 0%에 대응한다.
- 페이지 진입 시 2%에서 보유 잼만큼 채워지는 모션이 실행된다.
- 그래프 전체를 누르면 바텀시트가 열린다. 시트에서 «채우기»를 누르면 시트가 닫히고 지정한 양만큼 채워진다.
- 100%에 닿으면 오렌지가 화면 전체로 확장되고, 축하 문구와 «닫기» 버튼이 나온다. «닫기»를 누르면 디졸브로 닫히고 남은 잼을 채우는 모션이 이어진다.

## 구현 계획

1. 영상 프레임에서 치수·색·점 위치를 읽는다(오렌지 `#F94C31`, 트랙 `#19201C`, 점 4개).
2. 순수 로직(채움 계획: 100% 도달 구간 분할)을 테스트와 함께 만든다.
3. 게이지·오버레이·흐름·시연 화면을 만들고 브라우저에서 실제 동작을 확인한다.

## 완료 조건

- `/spike/capsule-fill`에서 진입 모션, 시트 채우기, 챕터 오름 오버레이, 닫은 뒤 남은 잼 채우기가 요구 순서대로 실행된다.
- 모션 줄이기 설정에서는 확장·채움이 즉시 반영되거나 페이드로 대체된다.
- 서비스 컴포넌트 변경이 없고, `npx vitest run`(해당 테스트)·`npx eslint`·`npm run typecheck`가 통과한다.

## 결정이 필요한 항목 (서비스 반영 전)

- 서버 규칙: 채우기 상한은 지금 `min(남은 양, 가진 잼)`이다(`jam-fill.ts`). 프로토타입은 한 번에 100%를 넘겨 채우는 흐름을 보여 주므로, 서비스에 넣으려면 서버가 초과분을 어떻게 다룰지 정해야 한다.
- 문구: 요청 문구 «축하합니다. 챕터레벨이 상승했습니다.»는 UX Writing 가이드(§챕터: «레벨» 금지, «챕터 N에 올랐어요»)와 어긋난다.
- 서비스 반영 시 채원(`jam-designer`) 사전 판정이 필요하다(새 컴포넌트·새 색).

## 작업 기록

### 경로 판정 (2026-10-28)

- `/spike` 라우트 안에서만 끝나고 서비스 컴포넌트(`CapsulePill`·`RadialCapsule`·`CapsuleSheet`·`JamFillPanel`)는 읽기만 했다. 서비스 화면에 노출되지 않으므로 채원 사전 판정과 게이트 리뷰를 거치지 않고 카리나가 직접 구현했다. 서비스 반영은 별도 티켓이며 그때 채원 판정이 필요하다.

### 구현 (신규 `jam-web/src/app/spike/capsule-fill/`)

| 파일 | 역할 |
|---|---|
| `capsuleFillMath.ts` (+ `.test.ts` 11건) | 그래프 2% ↔ 잼 0% 변환, 100%를 넘는 채우기를 구간으로 나누는 `planFill` |
| `JamGauge.tsx` | 어두운 트랙·오렌지 채움·점 4개(20/40/60/80%)·번개. 값·시간·가속은 호출부가 정한다 |
| `LevelUpOverlay.tsx` | 채움 자리에서 `clip-path`로 화면 전체로 퍼짐 → 문구·«닫기» → 디졸브. z 60, body 포털, 스크롤 잠금, Escape·포커스 복귀 |
| `CapsuleFillModule.tsx` | 진입 모션 · 시트(`BottomSheet`+`JamFillPanel`) · 채우기 · 챕터 오름 · 남은 잼 채우기 흐름 조립 |
| `CapsuleFillPrototype.tsx`, `page.tsx` | 홈피드·프로필 화면 예시, 시나리오 4개, 시연 도구 |

- 영상에서 읽은 값: 오렌지 `#F94C31`, 트랙 `#19201C`, 점 4개(20/40/60/80%), 번개는 채움 오른쪽 끝 원 안.
- «그래프 2% = 잼 0%»는 `jamPercentToGraphPercent`로 구현했다. 화면에서는 2%를 채움 원(지름 = 트랙 안쪽 높이)으로 그리고, 너비는 `원 지름 + (트랙 너비 - 원 지름) × 채움 정도`로 늘린다. 눈금 2%의 실제 너비(트랙의 2%)는 원보다 작아서 그대로 그리면 처음 16% 동안 움직임이 없는 구간이 생기기 때문이다.

### 검증 (브라우저 실측, 375×812)

- 진입: 지연 262ms 뒤 `transition: width 1500ms`가 걸리고, 너비가 60px(원)에서 276.8px(= 240/300 지점)로 늘었다.
- 시트: 게이지 클릭으로 열림, 기본값 120. «채우기» 후 시트가 닫히고 약 0.5초 뒤 채움이 시작된다.
- 챕터 오름: `clip-path`가 `inset(241px 22px 509px 22px round 30px)`에서 `inset(0)`으로 퍼지고 모서리 둥글기가 30px에서 0으로 풀린다. 문구는 퍼짐의 70% 지점부터 나타난다.
- 닫기: 챕터는 «닫기»를 누른 시점에 오른다(3→4). 디졸브 뒤 게이지가 2% 원에서 시작해 남은 잼 60(= 60/300 지점)까지 채운다.
- 연속 오름(700 잼): 오버레이 2회, Escape로 닫기, 챕터 1→2→3, 최종 100/300(너비 150px).
- 채우는 동안 게이지 `aria-disabled="true"`이고 눌러도 시트가 열리지 않는다. 끝나면 풀린다.
- 모션 줄이기(`prefers-reduced-motion` 흉내): 퍼짐 없이 즉시 전체 화면, 흐름은 끝까지 이어진다.
- 프로필 탭 전환 시 진입 모션이 다시 실행된다. 콘솔 오류 없음(404 한 건은 메인 서버를 잘못 연 시도의 잔여 기록).
- `vitest run src/app/spike/capsule-fill` 11건 통과, `npx eslint src/app/spike/capsule-fill` 통과, `npm run typecheck` 통과.

### 알려진 차이·결정 필요 (서비스 반영 전)

- 채우기 상한: 서비스의 `JamFillPanel`은 `min(남은 양, 가진 잼)`까지만 받는다. 프로토타입은 100% 초과 채우기를 보여 주려고 `remaining`에 가진 잼을 넘겨 상한을 풀었다. 서버(`capsule_fill`)가 초과분을 어떻게 다룰지(거절·분할·다음 챕터로 이월) 정해야 한다.
- 문구: «축하합니다. 챕터레벨이 상승했습니다.»는 요청 문구 그대로다. UX Writing 가이드(§챕터)는 «레벨» 금지·«챕터 N에 올랐어요»·첫 줄 «축하해요!»이므로 서비스 반영 전에 고른다.
- 게이지 수치는 화면에 없다(서비스 방침 «진행 숫자와 퍼센트는 어디에도 없다»). 숫자는 시연 도구에만 보인다.
- 시트 버튼은 서비스 DS의 초록(primary)이다. 오버레이 «닫기»는 오렌지 바탕에서 색이 부딪혀 `secondary`를 썼다.
- 환경 메모: 이 저장소 폴더명(`JAM!`) 때문에 워크트리에서 개발 서버를 띄우려면 `node_modules`를 심볼릭 링크 대신 실제 복사본(`cp -cR`)으로 바꿔야 한다. Turbopack은 폴더 밖을 가리키는 심볼릭 링크를, webpack은 경로의 `!`를 거부한다(둘 다 실측).
