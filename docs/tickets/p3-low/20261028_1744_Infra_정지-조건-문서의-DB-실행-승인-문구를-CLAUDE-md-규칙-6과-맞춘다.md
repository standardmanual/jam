# [Infra] 정지 조건 문서의 DB 실행 승인 문구를 CLAUDE.md 규칙 6과 맞춘다

> 출처: 티켓 `20261028_1730`(잼 자동 채움과 포인트 열기 구조 개편) 기획 중 혜린이 발견하고 카리나가 대조한 범위 밖 발견물이다. 같은 일을 두 문서가 다르게 적는 드리프트다(CLAUDE.md 절대 규칙 5).

## 핵심 요약

- 요구사항: DB 변경 실행의 승인 규칙을 한 곳을 원천으로 정하고 다른 문서는 참조만 하게 한다.
- 구현 계획: 두 문서의 문구를 비교해 어느 쪽이 낡았는지 정하고, 낡은 쪽을 원천을 가리키는 문장으로 바꾼다. 필요하면 `docs/agents/contract.json`에 검사 줄을 더한다.
- 관련 파일: `.claude/skills/jam-work/references/stop-conditions.md` 19행(표의 4번 «되돌릴 수 없는 작업»), `CLAUDE.md` 절대 규칙 6, `docs/agents/orchestrator.md` §4.

## 배경 / 문제 정의

- 정지 조건 문서 4번은 «DB 스키마/데이터 변경 실행 … 실행 전 사용자 승인 필수(기존 규칙, orchestrator.md)»라고 적는다.
- CLAUDE.md 규칙 6은 «메인 세션은 사용자 승인을 기다리지 않고 SQL을 바로 실행한다(2026-10-25 사용자 결정, 이전에는 채팅 승인이 유일한 관문이었다). 승인 대신 실행 전 점검이 관문이다»라고 적는다.
- 두 문장이 서로 다른 행동을 지시해서, 읽는 쪽에 따라 DB 실행 전에 멈추거나 멈추지 않는다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 코드 변경은 없고 문서만 고친다.
- `docs/agents/orchestrator.md` §4가 현재 어느 쪽을 말하는지 먼저 확인한다(**미확인**).
- 정한 규칙이 사용자 결정(2026-10-25)과 일치하는지 사용자에게 한 번 확인한다.

## 구현 계획

1. 세 문서의 DB 실행 관련 문구를 나란히 읽는다.
2. 원천 한 곳을 정하고 나머지는 참조 문장으로 바꾼다.
3. `node scripts/check-contract.mjs`와 `node scripts/doc-check.mjs --staged`를 돌린다.

## 완료 조건

- DB 변경 실행의 승인 규칙이 한 문서에만 있고 나머지 두 문서는 그 문서를 가리킨다.
- 세 문서를 읽은 사람이 같은 행동(실행 전에 무엇을 하는지)을 말할 수 있다.
- 계약 검사와 문서 검사가 통과한다.
