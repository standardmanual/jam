# [Admin] 어드민 생태계 상황판이 소멸한 잼을 «쓴 양»에 섞어 센다

## 핵심 요약

- 요구사항: 어드민 생태계 상황판의 잼 집계(`sumJam`)가 원장의 음수 줄을 전부 «쓴 양»으로 세어서, 보류 2개일 때 사라진 잼(`capsule_forfeit`)이 캡슐 채움(`capsule_fill`)과 함께 «쓴 양»에 들어간다. 소멸한 양을 따로 보이게 하거나 «쓴 양»에서 뺀다.
- 구현 계획: `sumJam`이 사유(`reason`)별로 나누도록 고치고, 소멸은 별도 값으로 낸다. 주 단위 소멸 집계는 읽기 전용 뷰 `jam_forfeit_weekly`(`service_role` 전용)가 이미 있어 같은 값을 쓸 수 있다.
- 관련 파일: `jam-web/src/lib/admin/ecosystem/fieldMetrics.ts`(102~111줄 `sumJam`), `jam-web/src/lib/admin/ecosystem/load.ts`(101~104줄 `jam_transactions` 읽기), `jam-web/src/lib/admin/ecosystem/nodes.ts`(68줄 기간 주석), 같은 폴더의 시험.

## 배경 / 문제 정의

티켓 `20261028_1734`(보류·소멸·알림)가 원장 사유 `capsule_forfeit`(음수)를 쓰기 시작했다. 상황판은 원장을 기간으로 읽어 메모리에서 합산하는데 `sumJam`은 사유를 구분하지 않아 소멸이 «쓴 양»에 섞인다. 오픈 뒤 소멸 규모(유저 수·양)는 4주 관찰로 정하기로 했으므로(상위 티켓 `20261028_1730`) 섞이면 관찰값이 흐려진다.

## 상세 요구사항

### 서비스/코드베이스 관점
- «쓴 양»은 `capsule_fill`·`locked_item_badge_fill`·`admin_deduct`(음수 사유)만 세고 `capsule_forfeit`은 따로 낸다.
- 같은 기준이 상황판의 다른 집계(잼 흐름)와 일치하는지 확인하고 시험을 맞춘다.

## 완료 조건

- 상황판의 «쓴 양»에 `capsule_forfeit`이 들어가지 않고, 소멸한 양이 별도 값으로 보인다.
- 관련 시험이 사유별 합산을 기대한다.
