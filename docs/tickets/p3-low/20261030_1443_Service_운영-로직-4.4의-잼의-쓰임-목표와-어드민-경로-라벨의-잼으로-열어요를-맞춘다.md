# [Service] 운영 로직 4.4의 «잼의 쓰임 목표»와 어드민 컬렉션 경로 라벨의 «잼으로 열어요»를 포인트로 여는 방식에 맞춘다

## 핵심 요약

- 요구사항: ① 운영 로직 4.4 값 표의 «잼의 쓰임 목표: 3분의 2는 캡슐, 3분의 1은 잠긴 아이템 배지»(461줄 근처)는 잠긴 아이템 배지가 포인트로 열리는 지금 사실과 어긋난다. 잼의 쓰임 목표를 다시 정해야 하는 밸런스 판단이라 사용자 결정이 필요하다. ② 어드민 컬렉션 경로 화면의 라벨 `LOCKED_ON_RECEIVE_LABEL`(«잠긴 채 받고 잼으로 열어요», `jam-web/src/components/admin/balanceDashboard/PathReasonLabels.ts` 49줄)과 이를 설명한 `docs/service/prd/admin-ui/ADMIN_PRD.md` 519줄이 잼 기준이다. 포인트 기준으로 고친다.
- 구현 계획: ①은 밸런스 시뮬레이터(U1)와 19장 게이미피케이션 밸런스를 보고 «잼은 전부 캡슐로 간다»로 바꾸는지, 목표를 다시 정하는지 사용자에게 묻는다. ②는 라벨과 PRD 문장, 그 라벨을 단언하는 시험을 함께 고친다.
- 관련 파일: `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md` 4.4절, `jam-web/src/components/admin/balanceDashboard/PathReasonLabels.ts`와 시험, `docs/service/prd/admin-ui/ADMIN_PRD.md`.

## 배경 / 문제 정의

티켓 `20261028_1741`(U10) 3회 게이트(민지, 참고)가 발견했다. 밸런스 수치 판단과 어드민 화면 문구 정리는 그 티켓의 범위 밖이었다.

## 상세 요구사항

### 서비스/코드베이스 관점

- ①은 사용자 결정 뒤 문서와 시뮬레이터 변수 목록을 함께 맞춘다. 정책·밸런스 수치가 바뀌면 `policiesData.ts`도 같이 갱신한다(CLAUDE.md 절대 규칙 2).
- ②는 어드민 경로 분류 로직은 바꾸지 않고 문구만 고친다.

## 완료 조건

- 4.4절 «잼의 쓰임 목표»가 사용자 결정에 맞게 고쳐져 있다.
- 어드민 경로 라벨과 PRD 문장이 포인트로 여는 방식과 맞고 시험이 통과한다.

## 처리 기록 (2026-10-31, 카리나)

- ① 사용자 결정(2026-10-31): **잼은 전부 캡슐로 쓴다.** 운영 로직 4.4절 값 표의 «잼의 쓰임 목표»를 «전부 캡슐(잠긴 아이템 배지는 포인트로 연다)»로 고쳤다. 시뮬레이터 변수 목록과 정책 대시보드에는 이 목표 값을 담은 곳이 없다(코드와 문서를 찾아 확인했다).
- ② 어드민 컬렉션 경로 라벨은 티켓 `20261031_0458` 5번에서 이미 «잠긴 채 받고 포인트로 열어요»로 고쳐져 있다(`LOCKED_ON_RECEIVE_LABEL` 문구에 «잼»이 없다).
- 두 항목 모두 끝났다. 종료는 사용자 승인을 기다린다.
