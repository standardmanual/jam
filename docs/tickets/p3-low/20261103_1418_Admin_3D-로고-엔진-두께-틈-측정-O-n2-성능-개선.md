# [Admin] 3D 로고 형상 엔진 — 두께·틈 측정(`minWallDistance`)이 O(n²)라 점이 많은 윤곽에서 느릴 수 있다

> 티켓 20261103_1350(형상 엔진) 게이트 리뷰(민지)의 범위 밖 발견물로 자동 생성한 티켓이다.

## 핵심 요약

- 요구사항: `minThickness`·`minGapWidth`가 쓰는 `minWallDistance`를 점이 많은 실제 글자 윤곽(수천 점)에서도 슬라이더를 움직일 때 끊기지 않을 만큼 빠르게 한다.
- 구현 계획: 먼저 실제 폰트 글자(점 2,000개 이상)로 실측해 문제가 있는지 확인한다. 문제가 있으면 변 쌍 전수 비교 대신 격자·공간 색인으로 후보를 줄이거나, 윤곽이
  바뀔 때만 계산하고 슬라이더 변경에는 결과를 재사용한다(캐시).
- 관련 파일: `jam-web/src/lib/logo-3d/polygonOps.ts`(170줄 근처 `minWallDistance`, 이를 부르는 `minThickness`·`minGapWidth`),
  `jam-web/src/lib/logo-3d/buildGeometry.ts`(베벨·둥글림 반지름 상한 계산에서 호출)

## 배경 / 문제 정의

`minWallDistance`는 변 위 표본에서 광선을 쏘아 마주보는 벽까지의 거리를 재는데, 모든 변 쌍을 돈다. 1번 티켓 테스트 윤곽은 점이 12개 이하라 성능이 확인되지 않았다.
3번 티켓에서 슬라이더를 움직일 때마다 형상을 다시 만들면 점이 많은 실제 폰트 글자에서 느려질 수 있다. 확인되지 않은 위험이므로 우선순위는 낮게 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 측정 결과(두께·틈 폭)는 지금과 같아야 한다(기존 테스트 44개가 그대로 통과).
- 윤곽이 같으면 슬라이더만 바꿀 때 다시 측정하지 않는다.

## 구현 계획

1. 3번 티켓 머지 뒤 실제 폰트(영문·한글 각 1종)로 `buildLogoGeometry` 소요 시간을 잰다. 슬라이더 한 번 조작에 수백 ms를 넘지 않으면 이 티켓은 닫는다.
2. 넘으면 공간 색인 또는 결과 캐시를 넣는다.

## 완료 조건

- 점 2,000개 이상 윤곽에서 `minThickness`·`minGapWidth` 호출 한 번이 100ms 이내다(착수 시 실측한 값으로 이 기준을 확정한다).
- 기존 `polygonOps` 테스트가 그대로 통과한다.
- 윤곽이 바뀌지 않은 상태에서 슬라이더만 바꾸면 측정이 다시 돌지 않는다(호출 횟수 테스트).
