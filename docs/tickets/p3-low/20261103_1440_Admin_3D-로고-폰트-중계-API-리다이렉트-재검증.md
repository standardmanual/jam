# [Admin] 3D 로고 폰트 중계 API — 폰트 파일 요청의 리다이렉트를 따라가지 않거나 최종 주소를 다시 검증한다

> 티켓 20261103_1351(3D 로고 입력 변환) 게이트 리뷰(민지)의 범위 밖 발견물로 자동 생성한 티켓이다.

## 핵심 요약

- 요구사항: 폰트 파일 요청이 `fonts.gstatic.com` 밖으로 리다이렉트되어도 받아 오지 않게 한다.
- 구현 계획: `fetch`에 `redirect: 'manual'`을 주거나, 최종 주소를 다시 `https://fonts.gstatic.com`으로 검증한다.
- 관련 파일: `jam-web/src/app/api/admin/logo-3d/font/route.ts`(98줄 근처 폰트 파일 `fetch`, 103줄 근처 스트림 응답), 같은 폴더 `__tests__/route.test.ts`

## 배경 / 문제 정의

현재는 첫 주소만 gstatic 도메인인지 확인하고 `fetch` 기본 설정대로 리다이렉트를 따라간다. gstatic이 다른 호스트로 보낼 가능성은 낮지만 이 API는 서버가 외부 주소를 대신 받아 오는 구조라, 위험을 한 단계 더 줄여 둔다. 확인된 취약점이 아니라 방어를 더하는 일이라 우선순위를 낮게 둔다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 기존 정상 요청(gstatic 응답)·SSRF 차단 시험 4종은 그대로 통과해야 한다.

## 구현 계획

`fetch`에 `redirect: 'manual'`을 주거나, 최종 주소를 다시 `https://fonts.gstatic.com`으로 검증한다.

## 완료 조건

- gstatic이 아닌 호스트로 리다이렉트하는 응답을 시험에서 만들면 502(또는 오류)로 막힌다.
- 기존 `route.test.ts` 11건이 그대로 통과한다.
- `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).
