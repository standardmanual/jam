# [Admin] 3D 로고 폰트 윤곽 — 한 글자 안에서 서로 겹치는 윤곽을 합친다 (일부 스크립트체 폰트)

> 티켓 20261103_1351(3D 로고 입력 변환) 게이트 리뷰(민지)의 범위 밖 발견물로 자동 생성한 티켓이다.

## 핵심 요약

- 요구사항: 한 글자의 윤곽이 서로 겹치는 폰트(일부 스크립트체·장식체)에서도 구멍이 잘못 생기지 않도록 겹친 윤곽을 합친다.
- 구현 계획: `fontToOutline`이 글자별 고리를 만들 때 합집합 연산(1번 티켓의 Clipper2 의존성)을 적용한 뒤 바깥/구멍을 가른다.
- 관련 파일: `jam-web/src/lib/logo-3d/fontOutline.ts`(117줄 근처 바깥/구멍 분류), `jam-web/src/lib/logo-3d/polygonOps.ts`(`clipper2-ts` 사용부), `__tests__/fontOutline.test.ts`

## 배경 / 문제 정의

일부 스크립트체 폰트는 한 글자를 겹치는 여러 윤곽으로 그려서, 지금처럼 포함 관계만으로 바깥/구멍을 가르면 겹친 부분이 구멍으로 잘못 처리될 수 있다. 첫 버전 범위 밖으로 판단했고, 실제 폰트를 써 보고 필요할 때 처리한다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 겹치지 않는 일반 폰트의 결과는 지금과 같아야 한다.

## 구현 계획

`fontToOutline`이 글자별 고리를 만들 때 합집합 연산(1번 티켓의 Clipper2 의존성)을 적용한 뒤 바깥/구멍을 가른다.

## 완료 조건

- 겹치는 두 윤곽을 가진 테스트 글자에서 합친 결과가 구멍 없이 하나의 바깥 윤곽이 된다.
- 구멍이 있는 일반 글자(A 모양)의 구멍 개수는 그대로 1개다.
- 기존 `fontOutline.test.ts` 11건이 그대로 통과한다.
- `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).
