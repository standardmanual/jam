# [Admin] 3D 로고 제너레이터 — 확인하지 못한 세 가지: PNG 알파 채널, 실제 브라우저 SVG 업로드, 배포 뒤 6MB 한글 폰트 응답

> 티켓 20261103_1352(3D 로고 화면) 게이트 리뷰·로컬 실렌더 확인의 범위 밖 발견물로 자동 생성한 티켓이다.

## 핵심 요약

- 요구사항: 로컬 실렌더 확인에서 빠진 세 가지를 확인한다: ① Transparent로 저장한 PNG 파일의 배경 알파가 0인지 ② 실제 브라우저에서 SVG 파일 업로드(`DOMParser` 경로)로 3D가 나오는지 ③ staging 배포 뒤 6MB급 한글 폰트가 응답 한도(Vercel 4.5MB)에 걸리지 않고 받아지는지.
- 구현 계획: ① PNG를 저장해 배경 픽셀 알파를 읽는다 ② `docs/assets/brand/jam_logo.svg`를 업로드해 본다 ③ staging 배포가 끝난 뒤 어드민이 열리는 환경에서 `/api/admin/logo-3d/font?family=Noto Sans KR&weight=700`을 호출한다(어드민은 배포된 staging에서 열리지 않으므로 프로덕션 반영 뒤 `j-a-m.app/admin`에서 확인).
- 관련 파일: `jam-web/src/app/admin/logo-3d/Logo3DViewport.tsx`(PNG 저장), `jam-web/src/lib/logo-3d/svgOutline.ts`(31줄 근처 `DOMParser`), `jam-web/src/app/api/admin/logo-3d/font/route.ts`(103줄 근처 스트림 응답)

## 배경 / 문제 정의

격리 워크트리에서는 어드민 화면이 렌더되지 않고, 로컬 확인에서는 파일 저장·파일 업로드를 하지 않았으며 로컬에는 Vercel 응답 한도가 없다. 한글 폰트는 로컬에서 6,036,044바이트가 1.3초에 받아지는 것까지만 확인했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 확인이 끝나면 결과를 이 티켓 완료 기록에 남긴다. 문제가 있으면 원인별로 새 티켓을 만든다.

## 구현 계획

① PNG를 저장해 배경 픽셀 알파를 읽는다 ② `docs/assets/brand/jam_logo.svg`를 업로드해 본다 ③ staging 배포가 끝난 뒤 어드민이 열리는 환경에서 `/api/admin/logo-3d/font?family=Noto Sans KR&weight=700`을 호출한다(어드민은 배포된 staging에서 열리지 않으므로 프로덕션 반영 뒤 `j-a-m.app/admin`에서 확인).

## 완료 조건

- Transparent로 저장한 PNG의 배경 픽셀 알파가 0이다.
- `jam_logo.svg` 업로드로 J·A·M 3D 로고가 나온다.
- 프로덕션(어드민이 열리는 환경)에서 Noto Sans KR 700 TTF(약 6.0MB)가 끝까지 받아지고 3D로 나온다.
