# [Admin] 에셋 3D 동영상 — 시간 비례 대신 프레임 단위로 그려, 창 상태와 무관하게 매끄럽고 끝 프레임이 정확히 360°가 되게 한다

> 티켓 20261103_1737(3D 동영상 턴테이블) 게이트 리뷰와 로컬 실녹화의 범위 밖 발견물로 자동 생성한 티켓이다.

## 핵심 요약

- 요구사항: 3D 턴테이블 영상이 브라우저 창이 가려지거나 그레인 계산이 무거워도 일정한 프레임 수(예: 초당 30장 × 15초)로 매끄럽게 돌고, 마지막 프레임이 시작 자세와 정확히 같다.
- 구현 계획: 먼저 Claude 앱 창(또는 일반 브라우저)이 화면에 보이는 상태에서 다시 녹화해 프레임 수를 잰다. 부족하면 경과 시간 비례 회전 대신 프레임 번호로 각도를 정하고(`turntable.ts`), `captureStream(0)` + `track.requestFrame()`처럼 프레임을 직접 밀어 넣는 방식이나 WebCodecs 인코딩을 검토한다.
- 관련 파일: `jam-web/src/app/admin/assets/logo3d/Logo3DViewport.tsx`(`recordVideo`), `logo3d/turntable.ts`, `videoRecording.ts`, `logo3d/stageCompose.ts`(그레인 `getImageData`, 57~75줄)

## 배경 / 문제 정의

2026-11-03 로컬 실녹화 결과 14.6초 영상에 프레임이 17장뿐이었다(초당 약 1.2장). 녹화 중 앱 창이 화면에 보이지 않아 브라우저 패널이 숨김 상태였고 숨겨진 페이지는 `requestAnimationFrame`이 크게 늦춰진다 — 그래서 이 수치가 실제 사용 환경을 대표하지는 않는다. 다만 회전이 경과 시간 비례라 프레임이 빠지면 영상이 끊기고, 끝 프레임도 시작 자세와 정확히 맞지 않았다(PSNR 18.3). 우선순위는 실제 창에서의 실측 결과로 다시 정한다.

## 완료 조건

- 화면에 보이는 창에서 녹화한 15초 영상의 프레임 수가 목표(예: 30fps × 15초 ≈ 450장)의 90% 이상이다(ffprobe 실측). 숨겨진 창에서도 같은 프레임 수가 나오면 더 좋다.
- 첫 프레임과 마지막 프레임이 같은 자세다(시험: 프레임 번호별 각도, 실측: 첫·끝 프레임 PSNR이 충분히 높음).
- 기존 Shape 녹화 동작은 바뀌지 않는다.
- `npm run lint`·`typecheck`·`test`가 통과한다(`scripts/verify.sh`).
