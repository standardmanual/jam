# [UI] 하단 내비 바 활성 아이콘 색을 디자인시스템 블랙으로

## 핵심 요약

- 요구사항: 하단 내비 바(TabBar)의 강조색(활성 탭 아이콘)을 디자인시스템의 블랙으로 지정한다.
- 구현 계획: 토큰 `--tabbar-icon-active`의 값을 `var(--accent)`에서 `var(--foreground)`로 바꾼다. 컴포넌트는 이 토큰을 읽기만 하므로 서비스(`src/components/ui/TabBar.tsx`)와 MODULAR(`design-system/components/navigation/TabBar.jsx`) 두 곳이 함께 바뀐다.
- 관련 파일: `jam-web/design-system/tokens/colors.css`(`--tabbar-icon-active`), `jam-web/design-system/_ds_manifest.json`(토큰 색인), `jam-web/src/components/ui/TabBar.tsx`·`jam-web/design-system/components/navigation/TabBar.jsx`(주석만)

## 배경 / 문제 정의

활성 탭 아이콘은 `--accent`(#19b551)였다. 이 값은 «면 채우기 전용»이라 흰 필 위의 아이콘 대비가 낮다(티켓 20261015_2131의 알려진 임시 결함, 2.67:1). 사용자가 활성 아이콘 색을 디자인시스템의 블랙으로 지정하라고 요청했다.

## 상세 요구사항

### UI/UX 관점
- 디자인시스템에서 블랙은 역할 토큰 `--foreground`(`--base-neutral-900`, #171717)다. `--base-black`(#000)은 이미지·지도 위 막에만 쓰도록 제한돼 있어 쓰지 않는다.
- 비활성 아이콘(`--tabbar-icon`)도 같은 #171717이므로, 활성과 비활성의 구분은 채운 아이콘과 선 아이콘의 차이, 그리고 선택 필(`--tabbar-selection`, 검정 8%)이 맡는다.

## 완료 조건
- 로컬 화면에서 활성 탭 아이콘의 계산된 색이 `rgb(23, 23, 23)`이고 선택 필이 그대로 표시된다.
- `_ds_manifest.json`의 `--tabbar-icon-active` 값이 `colors.css`와 일치한다(`ds-manifest-sync.mjs --check`에서 이 토큰이 차이 목록에 없다).

## 완료 기록

### 구현 내용 요약
`--tabbar-icon-active`를 `var(--foreground)`로 바꿨다. 매니페스트 값과 두 TabBar 파일의 주석을 맞췄다.

### 변경된 파일
```
jam-web/design-system/tokens/colors.css
jam-web/design-system/_ds_manifest.json
jam-web/src/components/ui/TabBar.tsx (주석)
jam-web/design-system/components/navigation/TabBar.jsx (주석)
```

### 테스트 결과
- [x] 로컬 `next dev`에서 활성 아이콘 계산 색 `rgb(23, 23, 23)` 확인, 홈 탭의 채운 아이콘과 선택 필 렌더 확인
- [x] `ds-manifest-sync.mjs` 검사에서 `--tabbar-icon-active` 차이 없음

### 주요 의사결정 / 핵심 메모
- 블랙 후보 중 `--foreground`를 골랐다. `--base-black`은 컴포넌트가 직접 참조하면 안 되는 팔레트 원값이고, 사용 범위가 막 용도로 한정돼 있다.
- 활성·비활성 아이콘이 같은 색이 되므로 구분이 흐려 보이면 선택 필의 농도를 조정하는 후속 판단이 필요하다.

### 잔여 이슈
- `ds-manifest-sync.mjs --check`가 이 작업과 무관한 캡슐 게이지 토큰 4건(`--capsule-*`) 누락을 보고한다. 이번 범위 밖이라 손대지 않았다.
- claude.ai/design 업로드본은 이미 118개 파일 뒤처진 상태(`UPLOAD_STALE`)다. 이 변경도 그 재업로드 대상에 포함된다.
