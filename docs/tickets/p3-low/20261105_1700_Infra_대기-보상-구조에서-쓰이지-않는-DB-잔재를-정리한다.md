# [Infra] 대기 보상 구조에서 쓰이지 않는 DB 잔재(alert_stage 열·jam_forfeit_weekly 뷰·capsule_hold_reward)를 정리한다

## 핵심 요약

- 요구사항: 더는 쓰이지 않는 DB 객체를 걷어 낸다: `user_capsules.alert_stage` 열(323 `capsule_hold_rolled`가 0으로 돌리는 줄 포함), 뷰 `jam_forfeit_weekly`, 옛 함수 `capsule_hold_reward`, `capsule_auto_fill` 응답의 `forfeited`·`alertStage` 고정 키. 원장 사유 `capsule_forfeit` CHECK 값과 과거 줄은 이력이라 남긴다.
- 구현 계획: 확장→전환→축소 분할(`db-migration-rules.md`). 새 코드가 프로덕션에 배포된 뒤 0건 확인을 거쳐 축소 마이그레이션 + 되돌림 SQL을 쓴다. 코드에서 위 이름을 읽는 곳이 0건인지 전수 검색한다.
- 관련 파일: `jam-web/supabase/migrations/302_capsule_pending_forfeit.sql`·`322_*`·`323_*`, `jam-web/src/lib/capsule/auto-fill.ts`(응답 키), `docs/service/prd/02_DATA_MODEL.md`

## 배경 / 문제 정의

상위 티켓 20261105_0100에서 T6(보관 표 삭제)이 취소되면서(보관 표를 다시 쓴다) 이 잔재를 맡을 곳이 없어졌다(민지 게이트 지적). 급하지 않다.

## 완료 조건

- 코드와 문서에서 위 객체를 읽는 곳이 0건이다.
- 축소 마이그레이션과 되돌림 SQL이 롤백 실측을 통과하고 프로덕션에 적용된다.
- `jam_transactions`의 과거 `capsule_forfeit` 줄은 그대로 남는다.
