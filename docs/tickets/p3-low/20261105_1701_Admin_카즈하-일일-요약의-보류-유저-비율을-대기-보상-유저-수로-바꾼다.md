# [Admin] 카즈하 일일 요약의 «보류 유저 비율»을 «대기 보상 유저 수»로 바꾼다

## 핵심 요약

- 요구사항: `#jam-alert` 일일 캡슐 신호 요약의 «보류 유저 비율»을 «대기 보상(`capsule_pending_rewards`)이 있는 유저 수»로 바꾼다. 막히는 순간 소식(`capsule_jam_blocked`)을 새로 보낼지도 이때 사용자에게 묻는다(지금은 보내지 않는다, 홈 배너가 대신한다).
- 구현 계획: `dailySignals`와 `cron/capsule-signals`가 읽는 신호를 바꾸고 시험을 갱신한다. 임계(주의·중단)는 오픈 4주 관찰값으로 정한다(운영 로직 §16).
- 관련 파일: `jam-web/src/lib/capsule/dailySignals.ts`, `jam-web/src/app/api/cron/capsule-signals/route.ts`, `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md`(478줄 부근)

## 배경 / 문제 정의

T5가 일일 요약의 «소멸» 신호를 걷었다(소멸이 없어졌다). 보류 유저 비율은 Q10 개정 뒤에도 의미가 있지만 «대기 보상이 있는 유저 수»가 더 직접적이다. 카즈하와 확인이 필요하다.

## 완료 조건

- 일일 요약에 «대기 보상 유저 수»가 나온다. 시험이 통과한다.
- 운영 로직 문서의 신호 설명이 같은 말로 바뀐다.
