# [Content] 컬렉션 상세의 «모두 빼기» 버튼 문구를 «한번에 빼기»로 바꾼다

## 핵심 요약

- 요구사항: 컬렉션 상세 페이지의 «모두 빼기» 버튼 레이블을 «한번에 빼기»로 바꾼다(사용자 지시, 2026-11-09).
- 구현 계획: 사전 `d.itembooks.unslotAll`의 `button`과 `confirm`을 «한번에 빼기»로 바꾸고, 이 문구를 고정하는 시험과 문서의 버튼 이름을 맞춘다.
- 관련 파일: `jam-web/src/lib/i18n/ko.ts`(`unslotAll.button`, `unslotAll.confirm`), `jam-web/src/app/(main)/collections/[id]/__tests__/SlotGrid.test.tsx`, `UnslotAllSheet.test.tsx`, `docs/service/writing/UX_WRITING_GUIDELINE.md`(빼기 용어 행), `docs/service/prd/inventory/PRD.md`, `docs/service/prd/02_DATA_MODEL.md`, `docs/plan/jam2/10 JAM 2.0 서비스 운영 로직.md`.
- 담당 에이전트: 오케스트레이터(경미 수정, 문구 두 줄).

## 완료 조건

- 컬렉션 상세의 일괄 버튼이 «한번에 빼기»로 보인다.
- 확인 시트의 확정 버튼도 같은 문구다.

---
## 완료 기록

- **결정(2026-11-09, 사용자)**: 버튼 레이블을 «모두 빼기»에서 «한번에 빼기»로 바꾼다. 띄어쓰기는 사용자가 적은 대로 «한번에»를 쓴다.
- **범위 판단**: 사용자는 컬렉션 상세의 버튼을 말했다. 확인 시트의 확정 버튼(`confirm`)도 같은 동작이라 트리거와 문구가 다르면 어긋나므로 함께 바꿨다. 시트 제목(«장착한 배지를 모두 뺄까요?»)과 본문은 문장이라 그대로 뒀다. 확정 버튼만 원래대로 돌리길 원하면 `unslotAll.confirm` 한 줄이다.
- **경로**: 경미 수정이라 오케스트레이터가 직접 처리했다. 로직 변경은 없다.
- **변경**: `ko.ts` 2줄, 시험 2개 파일(기대 문구), 문서 4개(UX Writing 가이드의 빼기 용어 행에 변경 이력, 인벤토리 PRD, 데이터 모델 PRD, 운영 로직 문서의 버튼 이름). 코드 주석에 남은 «모두 빼기»는 기능 이름이라 그대로 뒀다.
- **검증**: eslint 통과, `collections`·`i18n` 시험 9개 파일 138건 통과, 슬롭 검사 통과.
- **확인하지 못한 것**: 실제 화면 렌더. 버튼은 본인 컬렉션에 장착한 배지가 있을 때만 보이는데 로컬 테스트 계정에는 그런 컬렉션이 없다. 문구는 사전 값 하나라 시험의 마크업 검증(`>한번에 빼기<`)으로 갈음했다.
