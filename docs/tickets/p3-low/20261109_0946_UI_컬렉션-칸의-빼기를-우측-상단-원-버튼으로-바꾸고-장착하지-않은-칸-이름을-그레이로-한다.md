# [UI] 컬렉션 칸의 빼기를 우측 상단 원 버튼으로 바꾸고, 장착하지 않은 칸의 이름을 그레이로 한다

## 핵심 요약

- 요구사항 1(사용자 지시, 2026-11-09): 칸의 «빼기» 버튼(칸 아래 회색 알약)을 없애고, 칸 우측 상단에 검은 원 안의 «−» 아이콘 버튼으로 빼도록 한다.
- 요구사항 2(같은 날 사용자 지시): 비어 있는 칸, 또는 추가할 수 있는 아이템 배지가 있는 칸에 보이는 배지 이름을 그레이로 한다.
- 구현 계획: 서비스 전용 `SlotRemoveButton`(원 버튼)과 `MinusIcon`을 더하고 `SlotGrid`가 장착된 본인 칸의 우측 상단에 놓는다. `BadgeGridCard`(서비스 어댑터)에 `nameMuted`를 더해 장착하지 않은 칸에서 켠다.
- 관련 파일: `jam-web/src/app/(main)/collections/[id]/SlotGrid.tsx`, `SlotRemoveButton.tsx`(신규), `SlotActionPill.tsx`(주석), `jam-web/src/components/ui/BadgeGridCard.tsx`, `jam-web/src/components/ui/icons.tsx`, 시험 `__tests__/SlotGrid.test.tsx`.
- 담당 에이전트: 오케스트레이터(사용자가 모양을 직접 정함).

## 완료 조건

- 장착된 본인 칸의 우측 상단에 검은 원 안의 «−» 버튼이 보이고, 누르면 그 칸을 뺀다. 칸 아래의 «빼기» 알약은 없다.
- 장착하지 않은 칸(비어 있는 칸, 추가할 수 있는 칸)의 이름이 그레이이고, 장착된 칸의 이름은 그대로다.

---
## 완료 기록

- **결정(2026-11-09, 사용자)**: 두 지시를 그대로 따랐다. 모양은 사용자가 직접 정했으므로 채원 판정은 거치지 않았다.
- **경로**: 서비스 전용 변경이라 디자인 시스템 원본(`design-system/`)은 건드리지 않았다. 오케스트레이터가 직접 처리했다.
- **빼기 원 버튼**: 24px 검은 원(`bg-background-inverse`) + `--snow` 아이콘(선 두께 3, 14px). 눈에 보이는 원은 24px이고 `before`로 사방 8px를 넓혀 눌리는 영역을 40px로 맞췄다. 글자가 없어 `aria-label="빼기"`로 이름을 알린다. 칸 전체가 링크라 버튼은 링크 안이 아니라 같은 칸 래퍼(`relative flex`)의 형제로 두었다. 요청 중이거나 일괄 해제 중이면 비활성이 되고 반투명해진다.
- **판단한 점**: 교체 후보가 있는 장착 칸에는 이전에 «교체» 알약만 있고 «빼기»는 교체 시트 안에만 있었다. 이제 모든 장착된 본인 칸에 원 버튼이 있으므로 후보가 있는 칸에서도 우측 상단 원 버튼으로 바로 뺄 수 있다. «교체» 알약과 시트 안의 «빼기»는 그대로 뒀다. 이 부분이 의도와 다르면 알려 달라.
- **그레이 이름**: 장착되지 않은 칸 전부(`!isSlotted`)에서 이름이 `text-muted`다. 사용자가 말한 «비어 있는 칸»(미발견)과 «추가할 수 있는 칸»이 모두 포함된다. 등급이 아직 없는 상태의 칸도 장착되지 않았으므로 그레이다.
- **검증**: eslint, `tsc --noEmit` 통과, `src/app/(main)` 시험 54개 파일 1,012건 통과(`SlotGrid.test.tsx`에 원 버튼 4건·그레이 이름 1건을 더하고, 알약 시험은 «교체»·«추가»만 남겼다), 슬롭 검사 통과.
- **확인하지 못한 것**: 실제 화면 렌더. 로컬 테스트 계정에는 장착한 칸이 있는 컬렉션이 없고 타인 열람은 버튼이 없다. 원 버튼이 90px 썸네일 모서리와 겹쳐 보이는 정도와 눌리는 영역은 눈으로 보지 못했다. 배지 데이터가 있는 계정에서 한 번 확인할 것.
