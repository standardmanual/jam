# [UI] 빼기 원 버튼을 24px로 되돌려 안쪽에 두고, 믹서 슬롯의 제거 버튼도 같은 모양으로 바꾼다

## 핵심 요약

- 요구사항(사용자 지시, 2026-11-09, 순서대로): ① 컬렉션 칸의 빼기 원 버튼을 모서리에 겹쳐 놓고 크기를 절반(12px)으로 줄인다. ② 크기를 원래(24px)로 키우고 위치를 슬롯 중심 쪽으로 더 넣는다. ③ 믹스하기 > 등급 올리기에서 슬롯에 넣으면 나오는 X 서클도 이것과 동일하게 바꾼다.
- 결과: 원 버튼은 24px, 가장자리에서 6px 안쪽(①은 시험 단계였고 ②로 대체됨). 믹서 슬롯(`MixerSlot`)의 제거 버튼은 16px «✕»(모서리에 걸침)에서 같은 모양의 24px 검은 원 + 흰 «−»로 바꿨다.
- 관련 파일: `jam-web/src/app/(main)/collections/[id]/SlotRemoveButton.tsx`, 시험 `__tests__/SlotGrid.test.tsx`, `jam-web/design-system/components/patterns/MixerSlot.jsx`, `MixerSlot.stories.tsx`.
- 담당 에이전트: 오케스트레이터(모양을 사용자가 직접 정함).

## 완료 조건

- 컬렉션 칸의 빼기 버튼이 24px 검은 원 + «−»이고 우측·위 가장자리에서 6px 안쪽이다.
- 믹서 슬롯에 담은 배지의 제거 버튼이 같은 모양과 같은 위치다. 눌리는 영역은 40px이다.

## 완료 기록

- **결정(2026-11-09, 사용자)**: 위 세 지시. 위치는 «좀 더 슬롯 중심으로»를 모서리에 걸쳤던 위치에서 안쪽으로 옮기라는 뜻으로 읽어 6px 안쪽으로 정했다(처음 지시의 8px보다 2px 모서리 쪽). 더 안쪽이 필요하면 값만 바꾸면 된다.
- **디자인 시스템 변경**: `MixerSlot`은 MODULAR 정식 컴포넌트이고 서비스 사본이 없다(서비스가 `@ds/...`를 바로 쓴다). 믹서 슬롯의 제거 버튼은 바깥 40px 눌림 박스(`role="button"`, 가장자리에서 -2px) 안에 24px 원을 두는 구조다. 시각 원이 슬롯 가장자리에서 6px 안쪽이 된다. 접근 이름(`removeLabel`, 기본 «슬롯에서 빼기»)과 키보드 동작(Enter·Space)은 그대로다.
- **적용 범위(판단 필요)**: 사용자는 «믹스하기 > 등급 올리기»를 말했지만 `MixerSlot`은 같은 믹스하기 화면의 레시피 믹서(`CombineClient`)도 함께 쓴다. 한 컴포넌트에서 두 화면의 제거 버튼 모양이 갈라지지 않게 컴포넌트를 바꿔 **레시피 믹서의 제거 버튼도 같이 바뀐다.** 등급 올리기에서만 바꾸길 원하면 말해 달라(prop으로 갈라야 한다).
- **검증**: Storybook `MixerSlot 채움` 스토리의 상호작용 검증을 새 모양으로 고쳐(눌림 박스 40, 원 24×24, 면 `rgb(23,23,23)`, 아이콘 `rgb(252,252,252)`, 슬롯 가장자리에서 6px, «−» 아이콘, 글자 없음) 브라우저에서 PASS(10단계)를 확인했고 화면도 봤다. eslint(기존 경고 1건), `tsc --noEmit`, `ds:check`(오류 0) 통과, 믹스하기(`src/app/(main)/combine`) 시험 206건과 컬렉션 시험 68건 통과. 컬렉션 상세 화면은 로컬 실렌더로 24×24px, 안쪽 간격 6px을 쟀다.
- **확인하지 못한 것**: 실제 등급 올리기 화면에서 칸에 배지를 넣은 상태의 실렌더. 로컬 테스트 계정으로는 같은 등급 배지 6개를 담는 흐름을 만들지 못했다. 스토리북의 단일 칸과 시험으로 갈음했다. 등급 올리기 칸이 3열이라 칸 폭이 좁은데(약 105px) 24px 원이 이름·썸네일과 겹쳐 보이는 정도는 눈으로 보지 못했다.
