# [UI] 배지 목록의 레벨형 배지에 Lv.N 칩을, 체크인 배지에 ×방문 횟수 칩을 표시한다

## 핵심 요약

- 요구사항 1(사용자 지시, 2026-11-09): 액티비티 배지 목록에서 레벨형 배지(와 횟수형 배지)를 등급 칩처럼 표시한다.
- 요구사항 2(같은 날 사용자 지시): 체크인 배지 목록에서, 아이템 배지의 등급 칩을 표시하듯이 배지 이름 아래에 «×방문횟수» 형식의 칩을 표시한다.
- 구현 계획: 액티비티 목록 카드에 `level`을 넘긴다(`BadgeGridCard`가 이미 Lv.N 칩을 그린다). `BadgeGridCard`에 `visitCount`를 더해 체크인 목록이 `earnCount`를 넘긴다.
- 관련 파일: `jam-web/src/app/(main)/badges/BadgesClient.tsx`, `jam-web/src/components/ui/BadgeGridCard.tsx`, `jam-web/src/lib/i18n/ko.ts`(`badges.visitCountAria`), 시험 `src/app/(main)/badges/__tests__/BadgesClient.levelChip.test.tsx`·`BadgesClient.visitChip.test.tsx`(신규).
- 담당 에이전트: 오케스트레이터.

## 완료 조건

- 액티비티 목록에서 레벨형 배지에 Lv.N 칩이, Common 배지에 Common 칩이 보인다.
- 체크인 목록에서 2회 이상 방문한 배지에만 이름 아래에 «×N» 칩이 보이고, 1회 방문한 배지에는 없다.

---
## 완료 기록

- **레벨형(요구사항 1)**: 레벨형 배지는 `rarity`가 NULL이라 등급 칩이 없고, 목록 카드가 `level`을 넘기지 않아 칩이 아무것도 없었다. `level={badge.level}`을 넘겨 Lv.N 칩을 그린다. 실렌더에서 레벨형 카드 9장에 Lv.1·Lv.2 칩이 보였다.
- **«횟수형 배지»의 해석(확인 필요)**: 코드와 데이터에서 액티비티 목록에 따로 «횟수형»이라는 종류가 없다. 액티비티 배지는 등급형(Common·Rare·Epic·Mystic)과 레벨형(`level`) 둘뿐이다(DB: 등급형 227개, 레벨형 163개). 그래서 «횟수형»은 이어서 지시한 체크인 목록의 «×방문 횟수» 칩(요구사항 2)을 말한다고 읽었다. 액티비티 목록의 Common 배지(칩이 없는 16장, Common 칩은 그리지 않는 기존 규약)에도 칩을 보여야 하는지는 정해지지 않았다.
- **체크인 방문 횟수 칩(요구사항 2)**: 이름 바로 아래, 등급 칩이 놓이는 자리에 같은 크기(md: 글자 12px, 패딩 5px 10px, 줄 높이 1, 높이 22px)로 그린다. 면은 레벨 칩과 같은 `--default-soft`이고 글자는 `--foreground`다. 체크인 배지는 모두 Common(1,832개)이라 등급 칩이 없어 칩 자리가 겹치지 않는다. 처음에는 1회도 «×1»로 그렸으나 사용자가 1회는 칩을 표시하지 말라고 해 **2회 이상일 때만** 그린다(1회는 읽는 문장도 없다). 보조기술에는 «N번 방문했어요»(`d.badges.visitCountAria`)로 읽힌다. 썸네일 모서리의 «×N» 필(`count`)은 다른 표현이라 건드리지 않았다.
- **검증**: eslint, 시험 1,395건(`src/app/(main)`·`src/components/ui`·`src/lib/i18n`) 통과. 실렌더에서 체크인 목록의 «×2» 칩이 높이 22px, 글자 12px, 면 `rgb(229,229,229)`임을 확인했다. 1회 방문 배지(11개)에는 칩이 없고 «산성산»(2회)만 «×2»가 있음을 스크린샷으로 봤다.
- **참고(이번 변경과 무관)**: `/badges#checkin`처럼 주소의 해시로 탭을 열면 개발 서버에서 하이드레이션 불일치 경고가 뜬다. 서버는 해시를 볼 수 없어 첫 렌더가 액티비티 탭이기 때문이며 기존 동작이다.
- **확인하지 못한 것**: 방문 횟수가 두 자리 이상일 때(×10 이상)의 칩 폭, 320px 폭에서 긴 이름과 칩이 만드는 줄바꿈.
- **후속(2026-11-09, 사용자 지시 «common 칩 표기해»)**: 액티비티 목록의 Common 배지에도 `Common` 칩을 그린다. `RarityBadge`는 Common을 그리지 않는 것이 기존 규약(노이즈 축소, 티켓 20260827_024)이라, 디자인 시스템 컴포넌트에 선택 옵션 `showCommon`(기본 false)을 더했다. 서비스 `BadgeGridCard`에 `showCommonChip`을 더하고 액티비티 목록만 켠다. 다른 화면은 그대로 Common 칩이 없다. `.d.ts`·prompt.md·스토리(`CommonShown`)를 함께 고쳤다. 실렌더에서 액티비티 배지 43장 모두 칩이 있다(Common 16, Rare 10, Epic 7, Mystic 1, Lv 9). 체크인 목록은 사용자 지시가 없어 Common 칩을 켜지 않았다(체크인 배지는 모두 Common이라 켜면 전부 «Common»이 된다).
- **후속(2026-11-09, 사용자 지시 «common 칩의 컬러를 레벨칩과 동일하게해»)**: Common 칩의 면을 레벨 칩과 같은 `--default-soft` 면 + `--foreground` 글자로 바꿨다(이전에는 `--rarity-common` #666 면 + 흰 글자). `RarityBadge`의 Common 설정만 바꿨고 토큰 `--rarity-common`·`--rarity-common-foreground` 값은 그대로다(BadgeFrame·Colors 스토리가 쓴다). Common 칩은 `showCommon`을 켠 화면에만 그려져 다른 등급과 다른 화면은 영향이 없다. 스토리 `CommonShown`의 검증과 서비스 시험에 면 색을 더했다. 실렌더에서 Common 칩과 레벨 칩이 모두 면 `rgb(229,229,229)`, 글자 `rgb(23,23,23)`, 높이 22px다.
- **디자인 시스템 짝 맞춤(같은 날)**: 방문 횟수 칩이 서비스 `BadgeGridCard`에만 있어 `ds:check`가 짝 파일과 배경색이 어긋난다고 오류(1건)를 냈다. 디자인 시스템 `BadgeGridCard`에 같은 칩(`visitCount`)을 더하고 `.d.ts`와 스토리(`VisitCount`)를 함께 고쳐 오류 0이 됐다. 다른 서비스 전용 옵션(`nameMuted`, `chipGray`, `showCommonChip`)은 디자인 시스템 사본에 없다(서비스 사본이 앞선 상태이고 오류는 아니다).
