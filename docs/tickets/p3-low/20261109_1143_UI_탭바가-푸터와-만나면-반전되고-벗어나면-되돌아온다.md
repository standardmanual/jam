# [UI] 탭바가 푸터와 만나면 반전되고 벗어나면 되돌아온다

## 핵심 요약

- 요구사항: 하단 탭바(플로팅 캡슐)의 세로 중간선에 푸터 윗변이 닿는 순간부터 페이지 맨 아래까지는 탭바를 반전(네거티브) 모양으로 보이고, 푸터를 벗어나면 원래 모양으로 되돌린다. 전환은 한 번에 일어나되 dissolve(크로스페이드)처럼 부드럽게 바뀐다. 겹친 부분만 나눠 바꾸는 방식은 쓰지 않는다(사용자 결정 2026-11-09).
- 구현 계획: 푸터 위치를 `IntersectionObserver`로 감지해 TabBar에 반전 상태를 켜고 끈다. 반전 상태의 배경·아이콘·활성 필 색은 토큰으로 정하고, `background-color`·`color`에 `transition`(약 200~300ms)을 준다.
- 관련 파일:
  - `jam-web/src/components/ui/TabBar.tsx`: `TabBar` 컴포넌트의 `<nav>`(className `jam-tabbar-chrome`, `style.bottom`), 활성 필 `<span ref={pillRef}>`(`background: var(--tabbar-selection)`), 아이콘 `<span style={{ color: ... var(--tabbar-icon-active) / var(--tabbar-icon) }}>`. 감지 이펙트는 `ResizeObserver` 이펙트 부근에 둔다.
  - `jam-web/src/components/ui/Footer.tsx`: `<footer className="relative z-10 ... bg-background-inverse">`. 감지 대상. `FOOTER_EXCLUDED_PATHS`(`/drops`, `/philosophy`)에서는 푸터가 없으므로 반전도 없다.
  - `jam-web/src/app/(main)/layout.tsx` 115~131줄: 스크롤 컨테이너는 `window`가 아니라 `<main className="flex-1 overflow-y-auto">`이고, `<Footer />`와 `<TabBar />`는 형제다.
  - `jam-web/src/components/transitions.css` 520~534줄: `.jam-tabbar-chrome`(배경 `--tabbar-background`, blur, `prefers-reduced-transparency` 대체 면 `--surface`), 496~504줄 `.jam-tabbar-pill`(트랜지션 `--tabs-dur`·`--tabs-ease`, `prefers-reduced-motion`에서 끔).
  - `jam-web/design-system/tokens/materials.css`·`colors.css`: `--tabbar-*` 토큰 정의. 디자인 시스템 `TabBar.jsx`와 값을 공유하므로 반전 토큰을 더하면 연결 범위 판정이 필요하다.

## 확정 사항 (사용자 결정 2026-11-09, 채원 사전 판정의 승인 항목에 대한 답)

- 반전 면 색: 푸터(`--background-inverse`)보다 밝고 불투명한 어두운 회색이다. 푸터 위에서 `--surface-on-inverse`(snow 15%)를 합성한 불투명 면에서 시작해, 오버레이를 그보다 강하게(약 20~25%) 올려 더 흐리게 보이게 한다. 값은 기존 토큰의 별칭으로 정하고 새 색 수치를 만들지 않는다. 실렌더로 조정하고 최종 값을 완료 기록에 남긴다.
- 면이 푸터보다 밝으므로 윤곽용 1px 링은 두지 않는다(`--tabbar-ring-inverse` 제외). 신규 토큰은 3종(`--tabbar-background-inverse`, `--tabbar-selection-inverse`, `--tabbar-icon-inverse`)이다.
- 반전 시점은 푸터 윗변이 탭바 세로 중간선에 닿을 때다. 전환은 250ms 크로스페이드(두 레이어 교차)다.
- 이번 티켓은 서비스 전용 확장이다. MODULAR `TabBar.jsx`에 반전 상태를 옮기는 일은 후속 `ds` 티켓으로 낸다.

## 배경 / 문제 정의

- 탭바는 `fixed`로 화면 아래에 떠 있고 밝은 반투명 캡슐이다. 푸터는 2026-11-08부터 반전 면(`bg-background-inverse`)이라, 스크롤이 끝에 가까워지면 밝은 캡슐이 어두운 푸터 위에 얹혀 대비가 어색하다.
- 기대 상태: 푸터와 겹치는 구간에서는 탭바도 어두운 면으로 바뀌어 푸터와 한 덩어리로 읽힌다.

## 상세 요구사항

### 서비스/코드베이스 관점

- 반전 시점은 푸터 윗변이 탭바의 세로 중간선에 닿는 순간이다(사용자 확정). 탭바 윗선 위치(화면 아래에서의 거리)는 `offsetHeight`·`getBoundingClientRect()`로 실측하고 `min-h-*`·`py-*`로 역산하지 않는다(`jam-web/CLAUDE.md` 오버레이 규칙).
- 감지 기준(root)은 `<main>` 스크롤 컨테이너다. 라우트가 바뀌어 푸터가 생기거나 사라져도(`/drops`, `/philosophy`) 감지가 어긋나지 않아야 한다. 푸터가 없으면 반전 상태는 항상 꺼진다.
- 창 크기 변경·iOS 주소창 변화(`dvh` 변동)에도 경계가 맞아야 한다.
- 전체화면 오버레이로 탭바가 `return null`이 되는 동안(`useTabBarHidden`)에는 감지를 하지 않거나, 다시 나타날 때 올바른 상태로 시작한다.

### UI/UX 관점

- 전환은 크로스페이드이고 길이는 250ms(`--duration-fast`), 이징은 `--ease-smooth-out`이다(사용자 확정). 위치·크기·활성 필 이동은 전환 중에도 흔들리지 않는다.
- 반전 상태 색: 탭바 면은 어두운 반투명, 아이콘은 밝은 계열, 활성 필은 밝은 반투명이다. 새 토큰이 필요하면 채원 판정의 승인 항목으로 올린다.
- `prefers-reduced-motion`에서는 전환 없이 즉시 바뀐다. `prefers-reduced-transparency`에서는 불투명 반전 면(`--background-inverse`)을 쓴다.
- 경계 근처에서 스크롤이 떨리면 상태가 깜빡이지 않아야 한다(경계에 히스테리시스를 두거나 임계값 하나로 판정).

## 구현 계획

1. 채원 사전 판정: 반전 색 토큰, 전환 방식, 디자인 시스템 연결 범위를 정한다.
2. `TabBar.tsx`에 푸터 감지 이펙트와 반전 상태를 더하고, 색은 CSS 변수와 `data-` 속성(또는 클래스)으로 바꾼다. 인라인 `style`의 `color`·`background`가 전환되도록 `transition`을 붙인다.
3. 토큰·CSS 변경이 있으면 `transitions.css`와 디자인 시스템 토큰, Storybook Story를 함께 갱신한다.
4. 시험: 감지 경계 계산을 순수 함수로 빼면 단위 시험이 가능하다. 실렌더는 메인 트리에서 스크롤해 확인한다.

## 완료 조건

- 스크롤을 내려 푸터 윗변이 탭바 세로 중간선에 닿으면 탭바가 반전 모양으로 부드럽게 바뀌고, 맨 아래까지 유지된다.
- 다시 올려 푸터가 탭바 아래로 벗어나면 원래 모양으로 부드럽게 돌아온다.
- 푸터가 없는 `/drops`·`/philosophy`에서는 탭바가 반전되지 않는다.
- `prefers-reduced-motion`에서는 전환 효과 없이 즉시 바뀐다.
- 경계에서 스크롤을 천천히 움직여도 상태가 깜빡이지 않는다.
- 모바일 폭(375px)과 데스크톱 폭 모두에서 경계가 맞다.

### 주요 의사결정 / 핵심 메모

- 시점 정정: 처음 티켓에 «푸터 윗선이 탭바 윗선에 닿는 순간»이라고 적었는데 그 시점에는 탭바가 푸터 안에 완전히 들어가 있다. 푸터는 아래에서 올라와 탭바 아랫변→중간선→윗변 순으로 닿는다. 채원 사전 판정이 중간선을 추천했고 사용자가 확정했다.
- 크기 사전 판정 누락: 첫 구현 호출에서 아현이 `plan_only`로 멈췄다(파일 6개·약 200줄). 시작 전 규모 판정이 빗나간 탓이다. 사용자 승인으로 두 회차로 나눴고, 줄 수가 기준 근처이거나 넘어 두 회차 모두 사용자가 검토한 파일 단위 계획을 근거로 `planOnlyWaiver`를 넘겼다.
- 채원 사전 판정이 티켓을 못 읽었다: 채원① 에이전트의 작업 폴더가 main 기준이라 방금 `origin/staging`에 올린 티켓이 보이지 않았다. 판정은 요청 문구와 코드로 했고, 확정 사항은 `reuseDecision`과 티켓 본문으로 다시 전달했다. 새 티켓을 만든 직후 채원① 호출 때는 요청문에 티켓의 핵심 내용을 함께 적는다.
- 22% 확정: 사용자가 처음 «푸터보다 밝게, 불투명도를 더 강하게 해서 더 흐리게»라고 했고, 이를 «푸터색 위 흰색 22% 합성 불투명 면, 링 없음»으로 옮겨 구현했다. 실렌더를 본 뒤 22%로 확정했다.
- 티켓 번호 충돌: 2회차 티켓이 병렬 세션과 같은 시각(`20261109_1154`)으로 겹쳐 `20261109_1240`으로 바꿨다(파일명·id·코드 주석·상위·1회차 티켓 언급 포함).
- 배포 별칭 경쟁: 병렬 세션 커밋 둘이 거의 동시에 배포돼, 더 오래된 커밋(21d1ca9a9)의 빌드가 나중에 끝나 `stage.j-a-m.app`이 옛 코드를 가리켰다. 다음 코드 push 때 자연히 최신으로 넘어간다. 화면 확인은 최신 배포의 Vercel 공유 링크(23시간 유효)로 했다.
