# [UI] 탭바 반전 2회차: 푸터를 감지해 탭바 반전을 켜고 끄고 시험한다

## 핵심 요약

- 요구사항: 1회차(20261109_1153)가 만든 `inverted` 구조에, 푸터 윗변이 탭바의 세로 중간선에 닿는 순간 반전을 켜고 벗어나면 끄는 감지를 연결한다. 확정 사항은 상위 티켓 20261109_1143을 따른다.
- 구현 계획: `TabBar.tsx`가 `IntersectionObserver`로 `[data-jam-footer]`를 관찰해 내부 `inverted`를 정하고, `Footer.tsx`에 감지용 속성을 붙이며, 판정과 경계 조건을 시험한다.
- 관련 파일(3개, 예상 추가+삭제 약 130줄, 시험 줄이 대부분이다. 사용자가 검토한 계획으로 `planOnlyWaiver`를 넘긴다):
  - `jam-web/src/components/ui/TabBar.tsx`: `TabBar` 함수 안, `ResizeObserver` 이펙트 부근에 감지 이펙트를 더한다(+40줄 안팎). root는 뷰포트, 관찰 대상은 `[data-jam-footer]`, `rootMargin` 아래쪽은 «뷰포트 하단에서 탭바 중간선까지 거리»를 음수로 준다. 이 거리는 `nav.getBoundingClientRect()`로 실측하고(상수 금지, safe-area에 따라 달라진다) 기준선은 mount·`ResizeObserver`·`resize` 때만 다시 잰다. 판정은 `isIntersecting` 하나로 하고 스크롤 핸들러는 쓰지 않는다. 되돌림 쪽에 12px 정도 간격을 두고 실렌더로 조정한다. `pathname`이 바뀔 때마다 푸터를 다시 찾고, 푸터가 없으면(`/drops`, `/philosophy`) 항상 `false`다. 첫 판정 전에는 `false`다. `useTabBarHidden`이 `true`였다가 돌아오면 현재 값을 다시 계산한다. 1회차의 `inverted` prop이 있으면 그 값을 우선하고, 없으면 감지 값을 쓴다.
  - `jam-web/src/components/ui/Footer.tsx`: `<footer className="relative z-10 ...">`에 `data-jam-footer`를 붙인다(+1줄).
  - 신규 시험 `jam-web/src/components/ui/TabBar.inverse.test.tsx`(+80~120줄): `IntersectionObserver` 목으로 판정이 `inverted`에 반영되는지, 푸터가 없을 때 안전한지, `pathname`이 바뀌면 관찰자를 새로 만드는지, 숨김 상태에서 복귀할 때 다시 계산하는지, 1회차 구조(`inverted`로 클래스·색이 바뀜)를 시험한다. `layout.shell.test.tsx`와 `layout.tribe-gate.test.tsx`는 `Footer`를 스텁으로 바꿔 쓰므로 계속 통과하는지 확인한다.

## 완료 조건

- 스크롤을 내려 푸터 윗변이 탭바 세로 중간선에 닿으면 탭바가 반전되고 맨 아래까지 유지된다. 위로 올려 벗어나면 되돌아온다. 경계에서 스크롤을 천천히 움직여도 깜빡이지 않는다.
- `/drops`, `/philosophy`에서는 반전되지 않고, 라우트를 옮겨도 이전 페이지의 반전이 남지 않는다.
- 전체화면 오버레이로 탭바가 사라졌다 돌아와도 상태가 맞다.
- 모바일 폭(375px)과 데스크톱 폭 모두에서 경계가 맞다.
- 실렌더 캡처(홈·배지 목록·배지 상세, 밝음/반전 장면)를 사용자에게 보여 주고 최종 색을 확정받는다. 푸터 로고와 겹친 구간도 본다.
- 후속 `ds` 티켓(MODULAR `TabBar.jsx`와 토큰 색인에 `inverse` 반영)을 낸다.
- 시험이 모두 통과한다.
