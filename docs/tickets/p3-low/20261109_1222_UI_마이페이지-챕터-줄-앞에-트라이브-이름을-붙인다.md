# [UI] 마이페이지 챕터 줄 앞에 트라이브 이름을 붙인다

## 핵심 요약

- 요구사항(사용자 지시, 2026-11-09): 마이페이지의 «챕터 n» 앞에 트라이브명을 추가하고, 작은 가운뎃점으로 «챕터 n»과 나눈다.
- 구현 계획: 내 프로필의 챕터 줄(`ChapterLine` mine)이 «트라이브 · 챕터 n»을 그린다. 다른 유저 프로필의 줄(이미 «트라이브 · 챕터 n»)과 같은 구분자와 순서다. 내 트라이브 이름은 서버가 따로 읽어 내려준다.
- 관련 파일: `jam-web/src/components/chapter/ChapterLine.tsx`, `jam-web/src/lib/chapter/read.ts`(`getMyTribeName` 추가), `jam-web/src/app/(main)/[username]/page.tsx`, `jam-web/src/app/(main)/profile/ProfileClient.tsx`(주석), 시험 `ChapterLine.test.tsx`·`read.test.ts`·`[username]/__tests__/page.test.tsx`.
- 담당 에이전트: 오케스트레이터.

## 완료 조건

- 내 프로필의 챕터 줄이 «트라이브명 · 챕터 n»이다(트라이브를 고르지 않았으면 «챕터 n»).

---
## 완료 기록

- **변경**: 구분자는 작은 가운뎃점(U+00B7)이고 앞뒤에 공백이 있다. 다른 유저 프로필 줄이 이미 쓰던 구분자 키(`d.chapter.line.separator`)와 같은 값이라 두 줄이 같은 모양이다. 긴 트라이브 이름은 기존처럼 줄여서(truncate) 오른쪽의 편집 버튼과 겹치지 않는다. 글자 크기·색(`text-xs text-muted`)은 그대로다.
- **데이터**: `getMyChapter`의 응답 키는 점수·진행 계약이라 시험이 고정하고 있어 건드리지 않았다. 대신 내 트라이브 이름만 읽는 `getMyTribeName`을 더했다(`users.tribe_id` → `tribes`, 던지지 않고 읽지 못하면 null). 내 프로필에서만 부른다(타인 프로필은 이미 `getPublicChapter`가 트라이브를 준다). 서버 페이지가 `chapterInitial`에 `tribeName`을 함께 내린다. 내 정보라 타인에게는 조회도 prop도 없다.
- **그대로 둔 것**: 챕터가 없으면(퀘스트 전) 줄 자체를 그리지 않는 기존 규칙은 그대로다(트라이브만 보이는 줄은 만들지 않았다). 점수·진행 값은 어디에도 없다.
- **검증**: eslint, `tsc --noEmit`, `ds:check`(오류 0), 슬롭 검사, 관련 시험 1,366건 통과(챕터 줄 4건, 트라이브 읽기 4건, 프로필 페이지 2건 추가). 실렌더(내 프로필)에서 «낭만 미식가 · 챕터 3»을 확인하고 스크린샷으로 봤다.
- **확인하지 못한 것**: 트라이브를 고르지 않은 계정의 줄, 320px 폭에서 긴 트라이브 이름이 편집 버튼과 이루는 모양.
- **같은 날 제안(코드 변경 없음)**: 마이 페이지 피드에서 대표 이미지를 가져오지 못하는 행(아이템 드랍·픽업, 활동 묶음, 미션 참가)은 이미지 영역을 빼고 글만 보이는 안을 샘플 화면(임시 페이지, 저장소에 넣지 않고 삭제)으로 만들어 스크린샷으로 보였다. 결정 대기 중이다.
