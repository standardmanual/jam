# [UI] 디자인 시스템 TabBar와 토큰 색인에 탭바 반전 상태를 반영한다

## 핵심 요약

- 요구사항: 서비스 `TabBar.tsx`에 들어간 탭바 반전 상태(푸터와 만나면 어두운 면으로 교차 페이드)를 디자인 시스템(MODULAR) 쪽에 옮겨 서비스와 값이 갈리지 않게 한다. 상위 티켓 20261109_1143, 하위 20261109_1153·20261109_1240이 서비스 쪽을 끝냈고 이번 티켓이 디자인 시스템 층을 맞춘다.
- 구현 계획: `design-system/components/navigation/TabBar.jsx`에 `inverted` 상태와 두 레이어 구조를 더하고, Story에 밝음·반전을 보이며, 토큰 색인을 갱신한다. 연결 범위는 `.claude/skills/jam-work/references/ds-connection-scope.md`로 먼저 분류한다.
- 관련 파일:
  - `jam-web/design-system/components/navigation/TabBar.jsx`, `TabBar.d.ts`, `TabBar.stories.tsx`: `inverted` prop, 두 레이어, 아이콘·필 반전 색. 서비스 `jam-web/src/components/ui/TabBar.tsx`와 `components/transitions.css`의 `.jam-tabbar-chrome`·`.jam-tabbar-chrome-inverse`가 기준이다.
  - `jam-web/design-system/_ds_manifest.json`, `_adherence.oxlintrc.json`의 토큰 목록, `Colors.stories.tsx` 색인: 신규 토큰 `--tabbar-background-inverse`, `--tabbar-selection-inverse`, `--tabbar-icon-inverse`(정의는 `design-system/tokens/materials.css`·`colors.css`에 이미 있다).
  - `prefers-contrast: more` 블록(`colors.css`)은 서비스 쪽에서 이미 반전 상태를 포함하도록 고쳤으니 같은 서술이 디자인 시스템 주석에 맞는지 확인한다.

## 배경 / 문제 정의

- 서비스 탭바는 푸터 윗변이 탭바 세로 중간선에 닿으면 푸터보다 밝은 불투명 회색 면(`--snow` 22%)으로 250ms 교차 페이드한다(사용자 확정 2026-11-09). 디자인 시스템의 `TabBar.jsx`에는 이 상태가 없어 두 값이 갈릴 수 있다.
- 푸터 감지(`IntersectionObserver`)는 서비스 화면의 일이고, 디자인 시스템은 `inverted` 값을 받는 부분과 모양만 맡는다.

## 완료 조건

- `TabBar.jsx`에 `inverted`를 주면 서비스와 같은 모양(두 레이어 교차 페이드, 반전 아이콘·필 색)으로 바뀌고, 주지 않으면 지금과 같다. 반전 색은 토큰만 쓰고 새 색 수치가 없다.
- Story에서 밝음과 반전을 확인할 수 있다.
- 토큰 색인(`_ds_manifest.json`, `_adherence.oxlintrc.json`, `Colors.stories.tsx`)에 신규 토큰 3종이 있고 `ds:check`가 통과한다.
- `ds-connection-scope.md` 기준 연결 범위가 티켓에 적혀 있다.
