# [UI] 디자인 시스템 TabBar에 탭바 반전 상태를 반영한다

## 핵심 요약

- 요구사항: 서비스 `TabBar.tsx`에 들어간 탭바 반전 상태(푸터와 만나면 어두운 면으로 250ms 교차 페이드)를 디자인 시스템(MODULAR)의 `TabBar.jsx`에 옮겨 서비스와 값이 갈리지 않게 한다. 상위 티켓 20261109_1143, 하위 20261109_1153·20261109_1240이 서비스 쪽을 끝냈다. 토큰 색인 갱신은 형제 티켓 20261109_1312로 분리했다.
- 구현 계획: `TabBar.jsx`가 `inverted?: boolean`(기본 `false`, controlled)을 받아 두 레이어 구조로 바꾸고, `.d.ts`·Story·`prompt.md`를 맞춘다. 푸터 감지는 서비스 화면의 일이라 디자인 시스템에는 넣지 않는다. 연결 범위는 `.claude/skills/jam-work/references/ds-connection-scope.md`로 채원이 분류한다.
- 관련 파일(4개, 예상 추가+삭제 약 95줄):
  - `jam-web/design-system/components/navigation/TabBar.jsx`(224줄): `STATIC_CSS` 상수(15~16줄 부근)에 반전 레이어 규칙을 더하고, `TabBar` 함수의 `<nav className="ds-tabbar-chrome" style={{...}}>`(135줄 부근)에서 배경을 두 레이어(`ds-tabbar-chrome`, `ds-tabbar-chrome-inverse`) span으로 옮기고 `data-inverted`를 단다. 활성 필(`ds-tabbar-pill`, `background: var(--tabbar-selection)`)과 아이콘 `color: isActive ? ... : ...`(`<span style={{ position: 'relative', color: ...}}>`)에 반전 색을 준다. 서비스 `jam-web/src/components/ui/TabBar.tsx`와 `jam-web/src/components/transitions.css` 534~566줄(`.jam-tabbar-chrome-inverse`, `[data-inverted="true"]`, `.jam-tabbar-icon`, reduced-motion)이 기준이다.
  - `jam-web/design-system/components/navigation/TabBar.d.ts`(11줄): `TabBarProps`에 `inverted?: boolean`.
  - `jam-web/design-system/components/navigation/TabBar.stories.tsx`(102줄): 반전 상태 Story와 밝음↔반전 토글 Story를 더한다(`Interactive` Story 뒤, `Material` Story 형식을 따른다. 어두운 배경 위에서 보인다).
  - `jam-web/design-system/components/navigation/TabBar.prompt.md`(22줄): `inverted` 사용 설명 단락과 예시.
- 시험·토큰 정의는 이 티켓 범위가 아니다. 토큰 3종(`--tabbar-background-inverse`, `--tabbar-selection-inverse`, `--tabbar-icon-inverse`)은 `design-system/tokens/materials.css`·`colors.css`에 이미 있다.

## 배경 / 문제 정의

- 서비스 탭바는 푸터 윗변이 탭바 세로 중간선에 닿으면 푸터보다 밝은 불투명 회색 면(`--snow` 22%)으로 250ms 교차 페이드한다(사용자 확정 2026-11-09). `TabBar.jsx`에는 이 상태가 없어 서비스와 카탈로그가 갈린다. 두 파일은 별도 구현이라 함께 고쳐야 한다(`TabBar.prompt.md`, 20260820_009 결정).

## 상세 요구사항

### UI/UX 관점

- 서비스와 같은 모양이다: 밝은 면과 반전 면 두 레이어의 opacity만 `--duration-fast`(250ms), `--ease-smooth-out`으로 교차한다. `background-color`를 직접 보간하지 않는다. `backdrop-filter` blur는 밝은 레이어에만 두고 보간하지 않는다.
- 반전 상태에서 활성 아이콘은 `--snow`, 비활성은 `--tabbar-icon-inverse`, 활성 필은 `--tabbar-selection-inverse`다. 링·그림자·그라디언트를 더하지 않는다.
- `inverted`를 주지 않으면(기본 `false`) 지금과 모양·동작이 같다. 필 슬라이딩(`transform`)과 반전은 독립이다.
- `prefers-reduced-motion`에서는 전환 없이 즉시 바뀐다. `prefers-reduced-transparency`에서는 밝은 면만 `--surface`가 된다.

## 완료 조건

- `TabBar`에 `inverted`를 `true`로 주면 서비스와 같은 모양(두 레이어 교차 페이드, 반전 아이콘·필 색)으로 바뀌고 `false`면 되돌아온다. 주지 않으면 지금과 같다. 반전 색은 토큰만 쓰고 새 색 수치가 없다.
- Story에서 밝음과 반전을 확인할 수 있고 토글로 교차 페이드를 볼 수 있다.
- `.d.ts`와 `prompt.md`가 `inverted`를 설명한다.
- `ds:check`와 기존 시험이 통과한다.
- `ds-connection-scope.md` 기준 연결 범위가 완료 기록에 적혀 있다.

## 완료 기록

### 구현 내용 요약

- 디자인 시스템 `TabBar`가 `inverted?: boolean`(기본 `false`, controlled)을 받는다. `<nav>`는 `ds-tabbar`와 `data-inverted`만 들고, 안에 밝은 면 `span.ds-tabbar-chrome`과 반전 면 `span.ds-tabbar-chrome-inverse`가 DOM 맨 앞에 있다. 두 레이어의 opacity만 `--duration-fast`·`--ease-smooth-out`으로 교차하고 blur와 `background-color`는 보간하지 않는다. `STATIC_CSS`가 서비스 `transitions.css` 534~566줄과 접두(`jam-` → `ds-`)만 다르게 같은 규칙을 가진다.
- 활성 필은 반전 때 `--tabbar-selection-inverse`, 아이콘은 활성 `--snow`·비활성 `--tabbar-icon-inverse`다. 링·그림자·푸터 감지는 넣지 않았다(푸터 감지는 서비스의 일).
- `TabBar.d.ts`에 `inverted`와 설명, `TabBar.stories.tsx`에 `Inverted`·`InvertedToggle` Story와 `inverted` 컨트롤, `TabBar.prompt.md`에 이 티켓 항목을 더했다.
- 머지 전에 카리나가 한 줄을 더했다: `.ds-tabbar-pill`에 `background-color 250ms` 전환. 서비스 `.jam-tabbar-pill`에는 있는데 디자인 시스템에는 빠져 반전 때 필 색만 즉시 바뀌는 차이를 찾았기 때문이다(채원② 제안과 같은 지점, 서비스 규칙을 그대로 옮긴 것이라 게이트를 다시 돌리지 않았다).
