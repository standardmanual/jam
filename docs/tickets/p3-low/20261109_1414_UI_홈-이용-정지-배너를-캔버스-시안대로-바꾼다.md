# [UI] 홈 이용 정지 배너를 캔버스 시안대로 바꾼다 (제목·배치·사유 라벨·본문·문의 버튼)

## 핵심 요약

- 요구사항: 홈 이용 정지 배너(`SuspensionBanner`)를 디자이너가 캔버스에서 고친 시안(https://claude.ai/artifact/G7eE6dThELeyWBPxuN7Eut 의 `project/Main.dc.html` «이용 정지 배너» 구간, 로컬 사본 `/private/tmp/claude-502/-Volumes---------JAM-/94270d43-5685-4b5c-bbf5-95a68f60f79c/scratchpad/artifact-files/7a667bd6-743f-4e82-8081-1930fd719d4f/project/Main.dc.html`)대로 바꾼다. 시안 문구·배치는 사용자가 직접 정했고 반영을 승인했다(2026-11-09). 변경 6가지:
  1. 제목 «이용이 정지된 계정이에요» → «이용이 정지되었습니다.» (합쇼체와 마침표는 프로젝트 해요체·제목 마침표 금지 규칙과 다르지만 사용자 승인된 값이다. 완료 기록과 판정 보고에 «프로젝트 해요체 규칙과 다름, 사용자 승인됨»으로 남긴다)
  2. 칩 «이용 정지»와 제목을 위아래가 아니라 한 줄(가로, gap 8px)로 놓는다. 칩은 `self-start`다.
  3. 사유·정지일 줄을 «라벨 위 / 값 아래»에서 «라벨 왼쪽 / 값 오른쪽»(가로, 라벨과 값 사이 gap 18px)으로 바꾼다. 두 줄의 값이 같은 x에서 시작하도록 라벨 폭을 맞춘다(시안은 사유 라벨 폭 39px). 라벨 «정지 사유» → «사유». 정지일 라벨은 그대로 «정지일»이다. 사유가 빈 문자열이면 사유 줄만 숨기는 기존 동작은 유지한다.
  4. 본문에서 «지금까지의 기록, 배지, 잼, 포인트는 그대로 남아 있어요. 해제 방법은 문의로 알려 드려요.» 두 문장을 삭제하고, 남는 두 문장 사이(«정지 중에는 동기화와 아이템 배지 획득이 멈추고,» 뒤)에서 줄을 바꾼다. 줄바꿈은 문구 값에 `\n`을 넣고 본문 `<p>`에 `whitespace-pre-line`을 걸어 표현한다(사유 `dd`가 이미 쓰는 방식).
  5. 문의 버튼 문구 «문의하기» → «문의». «문의하기»는 서비스 전체가 쓰는 `d.voc.inquireCta`라서 이 값은 바꾸지 않고, `d.suspension`에 배너 전용 키 `bannerInquireCta: '문의'`를 새로 만들어 쓴다.
  6. 문의 버튼 크기를 온보딩 카드의 «건너뛰기» 버튼과 같은 작은 크기로 한다. «건너뛰기»는 `Button variant="primary" surface="main" size="xs"`(`OnboardingQuestSkipModal.tsx` 55~60줄)다. 문의 버튼도 `size="xs"`로 하고 `fullWidth`는 시안대로 유지한다. `xs`는 44px 터치 타겟 규칙의 명시적 예외(조밀한 컨텍스트 전용)라서, 본문 액션에 쓰는 것은 사용자 결정이라는 점을 판정 보고 `[참고]`에 남긴다.
- 구현 계획: ① `ko.ts`의 `d.suspension` 배너 문구 값 4개(`bannerTitle`·`bannerReasonLabel`·`bannerBody`)를 고치고 `bannerInquireCta`를 더한다. ② `SuspensionBanner.tsx`의 칩·제목 줄, 사유·정지일 줄 배치, 본문 클래스, 버튼 `size`와 문구를 바꾼다. ③ `SuspensionBanner.test.tsx`의 문의 버튼 시험을 `d.suspension.bannerInquireCta`로 고치고, 배치 변경(칩·제목 한 줄, 가로 라벨·값, `whitespace-pre-line`, 버튼 `xs`)을 고정하는 시험을 더한다. ④ `docs/service/prd/home-feed/PRD.md` 58줄 근처의 배너 문구 설명을 맞춘다.

## 배경 / 문제 정의

디자이너가 Design 캔버스에서 홈 이용 정지 배너를 직접 고쳤다(2026-11-09). 시안은 칩과 제목을 한 줄로 묶고, 사유·정지일을 가로로 놓고, 본문을 두 문장으로 줄이고, 버튼을 작게 만든다. 이 시안을 서비스에 반영한다.

반영 전에 사용자에게 알린 확인 사항(사용자가 그대로 진행하기로 했다): 합쇼체 제목은 프로젝트 문체와 다르다. 삭제되는 «기록·배지·잼·포인트가 남아 있다»와 «해제 방법은 문의로 알려 드려요» 두 문장은 정지 중인 유저에게 안심과 다음 행동을 알리는 문장이었다. 같은 «문의로 알려 드려요» 문구가 소식(#50)·동기화 403 등 d.suspension 12곳에 남아 있어 배너와 문구 결이 달라진다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `d.voc.inquireCta` 값과 그 사용처(다른 화면)는 바꾸지 않는다.
- `d.suspension`의 다른 키(`syncBlocked` 등 403 안내 문구 12곳)는 건드리지 않는다. `ko.ts` 1783행 주석의 «해제는 d.suspension 12곳과 맞춘다»는 소식 문구에 관한 것이라 그대로 둔다.
- 정지가 아닐 때 DOM에 아무것도 없는 동작은 `page.tsx`·`home-banner.ts`가 맡으므로 건드리지 않는다.

### UI/UX 관점
- 접근성 구조는 유지한다: `section aria-labelledby`, 제목 id, 사유·정지일은 `dl/dt/dd`, 버튼은 하나.
- 문구에 이모지·새 색을 넣지 않는다. 새 토큰도 만들지 않는다.

### 컨텐츠 관점
- 사용자 노출 문구는 위 6가지뿐이다. 문구 값은 요구사항에 적은 그대로 쓴다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `d.suspension.bannerTitle`이 «이용이 정지되었습니다.», `bannerReasonLabel`이 «사유», `bannerBody`가 «정지 중에는 동기화와 아이템 배지 획득이 멈추고,\n이 기간에 시작한 활동은 해제된 뒤에도 반영되지 않아요.», `bannerInquireCta`가 «문의»다.

- 본문 `<p>`에 `whitespace-pre-line`이 걸려 `\n`이 줄바꿈으로 보이고, 삭제한 두 문장은 코드·문구 사전에 남지 않는다.
