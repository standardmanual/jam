# [UI] 홈피드 카드의 설명 문단·끝 줄·정보 줄 표기를 캔버스 시안대로 바꾼다

## 핵심 요약

- 요구사항: 디자이너가 Design 캔버스(https://claude.ai/artifact/G7eE6dThELeyWBPxuN7Eut)에서 카드 유형 ④ 미션 소개·⑤ 드랍 알림·⑥ 배지 소개를 고쳤고(`project/T01Mission.dc.html`, `T02Drop`, `T03Badge`), 나머지 유형도 같은 규칙으로 맞추도록 정했다. 규칙과 질문 팝업 3건의 결정(2026-11-09)은 아래와 같다. 홈 카드의 모든 모양(hero·poster·square·brief·list·dome·ticket)에 적용한다.
  1. **끝 줄 삭제**: 카드 아래의 «자세히 보기 →»·«전체 보기 →»·«기사 읽기 →»(`CardEndLine`)를 모든 모양에서 그리지 않는다. 카드 전체가 눌리는 동작(링크·계측)은 그대로다.
  2. **설명 문단은 두 유형에서만 보인다(결정)**: `badge_spotlight`(배지 소개)와 `content_intro`(컨텐츠 소개)만 설명 문단을 그리고, 그 밖의 모든 템플릿(미션·드랍·기사·랭킹·컬렉션 소식·진행 알림·지역 트렌드·레시피 공개)은 `description` 값이 있어도 그리지 않는다. 판정은 표시 데이터를 만드는 한 곳(`toCardView`)에서 한다. DB 칸과 운영 입력 칸은 바꾸지 않는다.
  3. **정보 줄 접두어 삭제**: «기간 »·«보상 »·«지역 » 접두어를 뗀다. `d.todayCard.factPeriod: '기간 {range}'` → `'{range}'`, `factReward: '보상 {items}'` → `'{items}'`, `factPlace: '지역 {place}'` → `'{place}'`, `factPeriodOngoing: '기간 상시'` → `'상시'`. 나머지 정보 줄(`factItemCount` «아이템 N개», `factIngredientCount` «재료 N개», `factRevealDate` «공개 M월 D일»)과 남은 시간(«N일 남음»)은 그대로다.
  4. **기간 표기는 공백을 둔다(결정)**: `factPeriodRange: '{start}~{end}'` → `'{start} ~ {end}'` (예: «11월 6일 ~ 11월 29일»). 모든 모양이 같은 값을 쓴다.
  5. **정보 줄 굵게**: `poster`(흰 글자 위)와 `brief`의 정보 줄을 굵게 한다. hero·square·list·dome·ticket은 이미 굵다(`CardFacts`). `brief` 정보 줄은 **굵게 + 본문색(`text-foreground`)** 으로 한다(결정). 포인트 주황색(`pointify`)은 그대로다.
  6. **brief 행 위 정렬**: `BriefCard`의 가로 행(썸네일·본문·›)을 `items-center`에서 `items-start`(위 기준)로 바꾼다. 타일 0개 `list`가 `brief`로 그려지는 경우도 같은 컴포넌트라 함께 바뀐다.

## 배경 / 문제 정의

홈피드 카드가 정보를 겹쳐 보여 준다. 설명 문단과 «자세히 보기 →» 끝 줄은 카드 전체가 눌린다는 것을 알리는 것 외에 새 정보가 없고, «기간»·«보상»·«지역» 접두어는 값만으로 뜻이 분명하다. 디자이너가 캔버스에서 이를 걷어 낸 모양으로 확정했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 카드 모양 판정(`resolveShape`)·계측·링크(`CardFrame`)·랭킹 행형 동작·이미지 칸은 바꾸지 않는다.
- `description` DB 칸, 운영 입력 칸, 등록 검증(`lib/admin/registerChecks/homeFeedFields.ts` 등)은 이 티켓에서 바꾸지 않는다. 설명이 보이지 않는 유형에도 값이 저장될 수 있다는 점은 후속 티켓에서 다룬다.
- 홈과 어드민 미리보기가 같은 `toCardView`를 쓰므로 설명 문단 판정은 한 곳(`toCardView`)에서만 한다.

### UI/UX 관점
- 새 컴포넌트·새 토큰·새 색을 만들지 않는다. `brief` 정보 줄은 기존 토큰(`text-foreground`, `font-bold`)만 쓴다.

### 컨텐츠 관점
- 사용자 노출 문구 변경은 정보 줄 접두어 삭제와 기간 «~» 앞뒤 공백, 끝 줄 문구 삭제다. 문구 값은 요구사항에 적은 그대로 쓴다.
- «상시»는 `factPeriodOngoing`을 접두어 규칙대로 뗀 값이다(사용자가 정하지 않은 값이라 판정 보고에 `[참고]`로 남긴다).
