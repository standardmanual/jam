# [Admin] 홈피드 카드의 설명 입력 칸과 등록 검증을 설명이 보이는 유형에 맞춘다

## 핵심 요약

- 요구사항: 티켓 `20261109_1458`에서 홈피드 카드의 설명 문단이 `badge_spotlight`(배지 소개)와 `content_intro`(컨텐츠 소개)에서만 그려진다. 그 밖의 유형(미션·드랍·기사·랭킹·컬렉션 소식·진행 알림·지역 트렌드·레시피 공개)은 `description`이 저장·검증·입력되어도 화면에 나오지 않는다. 운영자가 쓴 문구가 보이지 않는 칸을 채우게 되므로, 입력 칸과 등록 검증을 보이는 유형에 맞춘다.
- 구현 계획: 먼저 결정이 필요하다(코드 변경 전 사용자 확인). 후보 A: 설명이 보이지 않는 유형에서는 어드민 카드 폼의 설명 칸을 숨기고 등록 검증이 값을 요구하지 않게 한다. 후보 B: 칸은 두되 «이 유형에서는 홈에 보이지 않아요» 안내를 더한다. 후보 C: 지금 상태를 유지한다(저장은 하되 보이지 않는다는 것을 문서에만 적는다). 확정된 안으로 아래 파일을 맞추고 운영 묶음 문서·정책 문서도 고친다.
- 관련 파일:
  - `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts` (설명문 60자·줄바꿈 검증)
  - `jam-web/src/lib/admin/opsInbox/` 카드 필드·등록 입력(`fields.ts`, `registerInput.ts` 등에서 `description` 처리, 파일을 먼저 `grep -rn "description" jam-web/src/lib/admin/opsInbox`로 찾는다)
  - 어드민 카드 편집 화면(`jam-web/src/app/admin/` 아래 today 카드 폼, 파일 위치는 `grep`으로 확인)
  - `jam-web/src/lib/today/shape.ts` (`DESCRIPTION_TEMPLATES`, `showsDescription` — 화면이 보이는 유형의 단일 원천)
  - `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md` (description 행), `docs/service/prd/home-feed/PRD.md` (설명문 문단)

## 배경 / 문제 정의

20261109_1458 게이트에서 민지가 발견했다(참고). 화면 쪽 판정은 `toCardView` 한 곳으로 끝났지만 입력·검증 쪽은 유형과 무관하게 설명을 받는다.

## 완료 조건

- 위 후보 중 하나가 사용자 결정으로 확정되고, 설명이 보이는 유형(`showsDescription`)과 입력 칸·등록 검증이 같은 기준을 쓴다.
- 기존에 저장된 설명 값은 지우지 않는다(보이지 않을 뿐이다).
- 바뀐 동작이 시험과 문서에 반영된다.

## 완료 기록

### 구현 내용 요약
홈피드 카드의 설명 입력 칸과 등록 검증을 설명이 화면에 보이는 유형(`badge_spotlight`, `content_intro`)에 맞췄다(사용자가 2026-11-09 질문 팝업에서 후보 A를 선택). 어드민 카드 폼은 보이는 유형에서만 설명문 칸을 열고, 등록 묶음과 운영툴 예약 등록 검증은 그 밖의 유형에 설명문을 적으면 거절하며 메시지에 보이는 유형 목록을 알려 준다. 저장된 설명 값은 지우지 않는다(폼 저장과 미리보기가 설명문을 비우지 않는다). 폼의 «기사로 바꾸면 삭제돼요» 안내는 사실과 달라 새 안내로 바꿨다. PRD 템플릿 표는 `gen-home-feed-doc.mjs`로 재생성했다. 게이트가 지적한 문서 모순(`mission_spotlight`에 설명문을 쓰라는 옛 작성 지침, 마케터 지침의 «모든 후보에 설명문»)은 카리나가 머지 때 고쳤다.
