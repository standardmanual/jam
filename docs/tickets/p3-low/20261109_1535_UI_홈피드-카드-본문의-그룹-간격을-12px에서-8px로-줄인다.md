# [UI] 홈피드 카드 본문의 그룹 간격을 12px에서 8px로 줄인다

## 핵심 요약

- 요구사항: 디자이너가 Design 캔버스(https://claude.ai/artifact/G7eE6dThELeyWBPxuN7Eut)에서 카드 안 세로 간격 세 가지 안(A 위계형·B 촘촘하게·C 현재 유지)을 나란히 보고 **B 촘촘하게**를 골랐다(2026-11-09, 질문 팝업). 이미지가 있는 모양(hero·square·dome·ticket)과 타일형 list의 본문, poster·dome 포스터형의 막 위 글자 묶음에서 **그룹 사이 간격을 12px에서 8px로** 줄인다. 바뀌는 간격은 칩 줄→제목(12→8)과 제목·요약 묶음→정보 줄(12→8)이다. 제목→요약 4px, 정보 줄 사이 0, 안쪽 여백 16px, 정보 줄→설명 문단(설명이 있는 유형만, 간격이 같은 `gap`이라 12→8로 함께 바뀐다)은 그대로 둔다(설명 간격만 따로 늘리지 않는다). **`brief`는 바꾸지 않는다**(칩→제목 8px, 제목→정보 줄 4px, 안쪽 12px 그대로).
- 구현 계획: ① `CardBody.tsx` 21줄 `flex flex-col gap-3 p-4` → `flex flex-col gap-2 p-4`와 머리 주석(안쪽 여백 16px, 그룹 사이 간격 12px → 8px). ② `PosterCard.tsx` 30줄과 `DomeCard.tsx` 19줄의 막 클래스 `gap-3` → `gap-2`(`pt-8 px-4 pb-4`는 그대로). ③ `ListCard.tsx` 103줄 `flex flex-col gap-3`이 무엇인지 읽고, 타일형 list 본문이면 같은 값으로, 행형(랭킹) 순위 행 간격이면 바꾸지 않는다(판단 근거를 요약에 적는다). ④ 시험의 `gap-3` 단정을 새 값으로 고친다: `components/today/__tests__/CardBody.test.tsx`(17줄), `ListCard.test.tsx`(34줄), `SquareCard.test.tsx`(34줄), `HeroCard.test.tsx`(59·63·76·94줄), `PosterCard.test.tsx`(108줄), 그 밖에 `grep -rn "gap-3" jam-web/src/components/today jam-web/src/app/(main)`로 `BODY_OPEN` 같은 본문 클래스 문자열을 단정하는 시험을 모두 찾는다(`BriefCard.test.tsx` 57줄의 `gap-3`은 brief 행이라 바꾸지 않는다). ⑤ `docs/service/prd/home-feed/PRD.md`에서 카드 본문 안쪽 여백·그룹 간격을 적은 곳(`grep -n "12px\|간격"`으로 찾는다, 예: hero 모양 설명의 «안쪽 여백 16px … 그룹 사이»)을 8px로 맞춘다.
- 관련 파일: `jam-web/src/components/today/CardBody.tsx`, `PosterCard.tsx`, `DomeCard.tsx`, `ListCard.tsx`, 위 시험 파일들, `docs/service/prd/home-feed/PRD.md`. `*.stories.tsx`는 간격 값을 단정하지 않으니 건드리지 않는다.

## 배경 / 문제 정의

설명 문단과 끝 줄이 빠지면서 카드 아래쪽이 짧아져 카드 안 간격이 12px로 넓게 느껴졌다. 디자이너가 세 안을 비교해 칩·제목·요약·정보 줄을 더 촘촘히 묶는 안을 골랐다.

## 상세 요구사항

### 서비스/코드베이스 관점
- `gap` 값만 바꾼다. 마크업 구조·클래스 순서·접근성·링크·계측은 바꾸지 않는다.
- 새 컴포넌트·새 토큰·새 색을 만들지 않는다. `gap-2`는 기존에 쓰는 유틸리티다.

### UI/UX 관점
- 바뀌는 곳: 칩 줄 ↔ 제목 묶음 ↔ 정보 줄 ↔ (있으면) 설명 문단 ↔ (list면) 타일 줄 사이가 모두 8px이다. 같은 `gap`을 쓰므로 한 규칙으로 함께 바뀐다.
- 안 바뀌는 곳: 제목↔요약 4px(`mt-1`), 정보 줄끼리 0, 본문 안쪽 여백 16px, poster·dome 포스터형 막의 위 32px(`pt-8`), brief 전체.

### 컨텐츠 관점
- 사용자 노출 문구 변경은 없다.

## 구현 계획

핵심 요약의 ①~⑤와 같다. 변경 파일은 코드 3~4개, 시험 5~7개, 문서 1개이고 변경 줄은 30줄 안팎이다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `CardBody`의 본문 클래스가 `flex flex-col gap-2 p-4`이고, hero·square·dome·ticket과 타일형 list 본문의 간격이 8px이다.
- poster와 dome 포스터형의 막 글자 묶음이 `gap-2`이고 `pt-8 px-4 pb-4`는 그대로다.
- `BriefCard`는 한 글자도 바뀌지 않는다.
- 시험이 새 클래스 값을 단정하고 통과하며 `scripts/verify.sh`가 통과한다(CI 간격 검사 실패는 별도 티켓 `20261109_1448`의 기존 문제이니 그것만 남아도 된다).
- `home-feed/PRD.md`의 카드 본문 간격 설명이 새 값과 맞다.
- 판정 보고에 «촘촘하게(B안)는 사용자가 캔버스 비교 후 질문 팝업으로 결정»이 `[참고]`로 남는다.
