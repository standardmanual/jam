# [UI] brief 카드의 설명 문단을 글자 열의 왼쪽 시작선에 맞춘다

## 핵심 요약

- 요구사항: 디자이너가 캔버스(https://claude.ai/artifact/G7eE6dThELeyWBPxuN7Eut)의 ⑬ 유형 10 컨텐츠 소개 화면 brief·list 카드에서 «이 설명 문단을 오른쪽으로 옮겨 텍스트들을 왼쪽 맞춤해 달라»는 코멘트를 남겼고, 서비스에도 반영하라고 했다(2026-11-09). 지금 `BriefCard`는 설명 문단을 윗줄(64px 썸네일 · 글자 열 · ›) **아래에 카드 안쪽 폭 전체**로 놓아, 문단의 왼쪽 끝이 썸네일 왼쪽 끝에 붙고 칩·제목 글자의 시작선과 어긋난다. 설명 문단을 **썸네일 칸(64px) + 간격(12px) = 76px만큼 오른쪽으로 들여 쓰기** 해 칩·제목 글자의 시작선과 맞춘다. 문단은 여전히 윗줄 아래(위 간격 8px)에 놓고, 글자 열 안으로 넣지 않는다.
- 구현 계획: ① `jam-web/src/components/today/BriefCard.tsx`: 설명문 칸(`mt-2`, 설명이 있을 때만 그리는 `<div>`)에 왼쪽 안쪽 여백 76px을 더한다(`pl-19`는 4px 눈금의 19배라 눈금 안이다. 이 클래스가 Tailwind 설정에서 동작하지 않으면 `pl-[76px]`와 함께 `spacing-allow` 사유 주석을 단다). 머리 주석의 «설명문이 있으면 윗줄 아래에 카드 안쪽 폭 전체로 놓는다 … 글자 열 안에 넣으면 폭이 약 198px라 …» 부분을 «윗줄 아래에 놓되 글자 열의 왼쪽 시작선(썸네일 64px + 간격 12px = 76px 들여 쓰기)에 맞춘다. 들여 쓴 폭은 약 290px라 60자가 3줄에 든다»로 고친다. ② `jam-web/src/components/today/__tests__/BriefCard.test.tsx`: 설명 칸이 76px 들여 쓰기 클래스를 가진다는 단정과, 설명이 없으면 칸이 없다는 기존 단정을 확인한다. ③ `docs/service/prd/home-feed/PRD.md`: `brief` 모양 설명에서 설명문이 «카드 안쪽 폭 전체»라고 적은 곳(`grep -n "안쪽 폭" -n`으로 찾는다)을 새 규칙으로 고친다.
- 관련 파일: `jam-web/src/components/today/BriefCard.tsx`(설명문 칸 60줄 안팎), `jam-web/src/components/today/__tests__/BriefCard.test.tsx`, `docs/service/prd/home-feed/PRD.md`. 타일 0개 `list`가 `brief`로 그려지는 경우도 같은 컴포넌트라 함께 바뀐다(코드 변경은 이 파일 하나).

## 배경 / 문제 정의

brief의 설명 문단은 썸네일 아래 왼쪽 끝에서 시작해 위쪽의 칩·제목 글자와 시작선이 맞지 않는다. 디자이너가 캔버스에서 문단을 글자 열의 시작선에 맞추도록 요청했다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 설명 문단을 그릴지 말지(`toCardView`의 `showsDescription`)와 문구는 바꾸지 않는다. 마크업 구조는 칸에 클래스 하나를 더하는 것이 전부다.
- 새 토큰·새 색·새 컴포넌트를 만들지 않는다.

### UI/UX 관점
- 들여 쓰기는 썸네일 칸 폭(`CardThumb`의 `w-16` = 64px)과 윗줄 간격(`gap-3` = 12px)의 합 76px이다. 이 두 값이 바뀌면 같이 바꿔야 한다는 것을 주석에 적는다.
- 설명 문단은 3줄 말줄임(`line-clamp-3`)을 그대로 유지한다.

### 컨텐츠 관점
- 사용자 노출 문구 변경은 없다.

## 구현 계획

핵심 요약의 ①~③과 같다. 변경 파일은 3개, 변경 줄은 15줄 안팎이다.

- 시험이 새 클래스를 단정하고 통과하며 `scripts/verify.sh`가 통과한다(CI 간격 검사 실패는 별도 티켓 `20261109_1448`의 기존 문제이니 그것만 남아도 된다).

## 완료 기록

### 구현 내용 요약
brief 카드의 설명 문단 칸에 왼쪽 안쪽 여백 76px(썸네일 64px + 간격 12px)을 더해(`mt-2 pl-19`) 칩·제목 글자의 시작선과 맞췄다. 위 간격 8px, 3줄 말줄임, 설명이 없으면 칸이 없는 동작은 그대로다. `pl-19`는 이 프로젝트의 Tailwind에서 `calc(var(--spacing) * 19)` = 4.75rem(76px)로 컴파일되는 것을 직접 확인했다. 간격 검사 스크립트가 8 이상 단계를 위반으로 세므로 `spacing-allow` 사유 주석을 같은 줄에 달았다(JSX 주석이라 렌더에 공백이 생기지 않는다).

### 주요 의사결정 / 핵심 메모
- 설명 문단은 글자 열 안으로 넣지 않고 윗줄 아래에 둔 채 76px만 들여 썼다. 기존 코드 주석의 «글자 열 안은 폭이 약 198px라 60자가 4줄 이상»이라는 이유를 피하면서(들여 쓴 폭 약 290px) 캔버스 코멘트의 «텍스트 왼쪽 맞춤» 요청을 충족한다.
- 티켓은 `pl-19`가 «눈금 안»이라고 적었으나 검사 스크립트는 8 이상 단계를 위반으로 센다. 그래서 `spacing-allow` 사유 주석을 달았다.
- 머리 주석과 PRD의 «약 290px 폭에서 60자가 3줄에 든다»는 계산값이다. 실렌더 실측으로 확인한다.

### 잔여 이슈
- `pl-19`가 `CardThumb`의 `w-16`과 `BriefCard`의 `gap-3`에 의존한다. 두 값이 바뀌면 함께 바꿔야 한다(머리 주석에 적어 두었다).
