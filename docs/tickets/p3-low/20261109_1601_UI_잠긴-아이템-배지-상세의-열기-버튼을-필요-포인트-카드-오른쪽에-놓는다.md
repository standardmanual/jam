# [UI] 잠긴 아이템 배지 상세의 «열기» 버튼을 필요 포인트 카드 오른쪽에 놓는다

## 핵심 요약

- 요구사항(사용자 지시, 2026-11-09): 잠긴 아이템 배지 상세에서 «열기» 버튼을 «N 포인트 필요» 안내 카드 안 오른쪽에 배치한다.
- 구현 계획: 포인트 카드(`ListRow`)의 `trail` 칸에 작은 «열기» 버튼(`Button size="sm"`)을 넣고, 맨 아래 전체 폭 버튼은 필요 포인트를 읽지 못해 카드가 없을 때만 남긴다.
- 관련 파일: `jam-web/src/app/(main)/inventory/[itemId]/LockedItemDetail.tsx`(`openButton`, 포인트 카드 `ListRow`), 시험 `__tests__/LockedItemDetail.test.tsx`, PRD `docs/service/prd/inventory/PRD.md`.
- 담당 에이전트: 오케스트레이터.

## 완료 조건

- 필요 포인트가 있으면(0 포함) «열기» 버튼이 포인트 카드 안 오른쪽에 있고 맨 아래 버튼은 없다.
- 포인트가 모자라면 같은 버튼이 막히고 안내는 카드 아래에 그대로 있다.

---
## 완료 기록

- **변경**: 버튼을 한 곳(`openButton`)에서 만들어 카드 오른쪽(`trail`)에 놓는다. 크기는 `sm`이라 카드 높이(74px)는 그대로다. 필요 포인트 0(«포인트 없이 열 수 있어요»)인 카드도 같은 자리에 둔다. 필요 포인트를 모르는(null) 경우는 카드가 없으므로 맨 아래 전체 폭 버튼을 그대로 쓴다.
- **열린 뒤**: 포인트 카드가 접힐 때 안의 버튼이 키보드로 눌리지 않도록 접히는 칸에 `inert`를 걸었다(`aria-hidden`과 함께).
- **문서**: 인벤토리 PRD의 잠긴 상세 화면 구성 서술 두 줄을 고쳤다.
- **검증**: eslint, `tsc --noEmit`, `ds:check`, 슬롭 검사, 인벤토리 시험 78건 통과(위치 시험 추가, 열린 뒤 시험 수정). 실렌더(375px, 필요 포인트 50·보유 1,270)에서 카드 안 오른쪽에 활성 «열기»(너비 58px, 높이 37px)가 있고 카드 높이가 74px임을 확인하고 스크린샷으로 봤다. 버튼을 눌러 열지는 않았다(포인트가 실제로 빠진다).
- **확인하지 못한 것**: 포인트가 모자란 상태(막힘)와 필요 포인트가 0인 카드의 실화면, 열린 뒤 접히는 전환 동작(시험은 마크업만 본다).
- **알아 둘 점**: 375px 폭에서는 «획득 일시» 값(`2026-11-06 AM 10:11:39`)이 두 줄로 나뉜다(값 칸 최대 폭 60%). 이번 변경 범위 밖이라 그대로 뒀다.
