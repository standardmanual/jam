# [UI] 잠긴 아이템 배지를 연 뒤 화면에서 트라이브·포인트 문구와 배지 상세 링크를 뺀다

## 핵심 요약

- 요구사항(사용자 지시, 2026-11-09): 잠긴 배지의 «열기»를 누르면 바뀌는 화면 아래의 «트라이브 …», «50 포인트를 냈어요», «배지 보상으로 10 포인트를 받았어요», «배지 상세 보기»가 필요 없다. 아이템 배지 상세 페이지만 보여 준다.
- 구현 계획: 열린 뒤 화면(`LockedItemDetail`)에서 네 줄을 지운다. 일련번호, «획득 정보» 카드, 컬렉션 행은 일반 아이템 배지 상세와 같아 그대로 둔다. 쓰지 않게 된 문구 키(`opened.tribe`·`spent`·`points`·`badgeLink`)를 지운다.
- 관련 파일: `jam-web/src/app/(main)/inventory/[itemId]/LockedItemDetail.tsx`, `jam-web/src/lib/i18n/ko.ts`, 시험 `__tests__/LockedItemDetail.test.tsx`, `docs/service/prd/inventory/PRD.md`, `docs/service/writing/UX_WRITING_GUIDELINE.md`.
- 담당 에이전트: 오케스트레이터.

## 완료 조건

- 열린 뒤 화면에 트라이브 줄, 낸 포인트·받은 포인트 줄, «배지 상세 보기» 링크가 없다.
- 일련번호, «획득 정보» 카드, 컬렉션 행은 그대로 보인다.

## 완료 기록

- **변경**: 열린 뒤 화면에서 네 줄(트라이브, 낸 포인트, 받은 포인트, «배지 상세 보기» 링크)을 지웠다. 맨 아래 전체 폭 «열기» 버튼은 필요 포인트를 읽지 못해 포인트 카드가 없을 때만 그린다(열린 뒤에는 그리지 않는다). 쓰지 않게 된 `Link` 가져오기와 문구 키 네 개를 지웠다(`d.lockedItem.detail.opened`에는 컬렉션 줄 키만 남는다).
- **알아 둘 점**: 열기 응답이 주는 낸 포인트·받은 포인트 값은 화면이 더 이상 읽지 않는다. 열린 직후의 성공 토스트(«열었어요»)는 그대로다. 낸 포인트와 받은 포인트를 따로 알리는 자리는 이제 없다.
- **문서**: 인벤토리 PRD의 열기 뒤 서술과 UX Writing 가이드의 열기 줄(낸·받은 포인트 문장 설명)을 고쳤다.
- **검증**: eslint, `tsc --noEmit`, `ds:check`(오류 0), 슬롭 검사, `src/app/(main)`·`src/components/__tests__`·`src/lib` 시험 14,507건 통과(열린 뒤 문구 없음 시험 추가, 낸·받은 포인트 줄 시험 제거).
- **확인하지 못한 것**: 실렌더. 실제로 열면 테스트 계정의 포인트가 공용 DB에서 빠져 열지 않았다. 열린 뒤 화면은 마크업 시험으로만 확인했다.
