# [Service] 드랍 진입 때 체크인 지점 조회가 한 번 실패하면 다시 조회한다

## 핵심 요약

- 요구사항(사용자 지시, 2026-11-10): 드랍 화면에 처음 들어갔을 때 체크인 지점이 보이지 않다가, 탭을 한 번 더 누르거나 다른 화면에 갔다 오면 체크인 지점이 추가로 나타난다. 이를 고친다.
- 원인(실제 화면에서 재현): 체크인 지점은 지도가 멈출 때 보내는 `/api/checkin-badges` 조회로 불러온다. 이 조회가 한 번 실패하면(서버 오류, 네트워크 끊김 등) 화면이 실패를 조용히 삼키고, 지도는 그 범위를 이미 조회한 것으로 기록한다. 그러면 지도를 크게 움직이거나 90초가 지나기 전까지 다시 조회하지 않아, 드랍·픽업 마커는 뜨는데 체크인 지점만 빠진 채로 남는다. 다른 화면에 갔다 오면 지도가 새로 만들어져 기록이 지워지므로 그제야 나타난다. 실패가 실제로 일어난 이유는 서버 기록이 하루만 보관돼 확인하지 못했다.
- 구현 계획: ① 조회 함수가 성공·실패를 돌려주게 하고, 지도는 실패하면 조회 기록을 지우고 1.5초·3초·4.5초 간격으로 최대 3번 다시 조회한다. ② 먼저 보낸 조회의 응답이 늦게 도착해 최신 범위의 마커를 덮어쓰지 않도록 요청 번호로 걸러 낸다. ③ 지도가 아직 자리를 잡지 못해 폭이나 높이가 0인 범위는 조회하지 않는다.
- 관련 파일: `jam-web/src/components/map/MapView.tsx`(`emitViewport`, `onViewportChange` 타입, `VIEWPORT_RETRY_*` 상수), `jam-web/src/app/(main)/drops/DropsClient.tsx`(`handleViewportChange`, `viewportRequestSeqRef`).
- 담당 에이전트: 오케스트레이터.

## 완료 조건

- 체크인 지점 조회가 실패해도 지도를 움직이거나 화면을 나갔다 오지 않고 자동으로 다시 조회해 지점이 나타난다.
- 성공한 뒤에는 추가 조회가 이어지지 않는다.

## 완료 기록

- **재현**: staging(`stage.j-a-m.app`)의 실제 네이버 지도에서 위치를 서울숲 근처로 고정하고, 첫 체크인 조회만 500으로 바꿔 진입했다. 8초가 지나도 다시 조회하지 않았고, 화면에는 드랍 마커만 있고 체크인 지점(`흐지부지 러닝 클럽`)이 없었다. 같은 탭을 한 번 더 눌러도 조회가 나가지 않았다. 실패 없이 진입하면 한 번의 조회로 정상 표시됐다.
- **검증(로컬 개발 서버)**: 지도 인증이 로컬에서 막혀 가짜 지도를 심고 첫 두 조회를 500으로 바꿨다. 1.5초 뒤, 3초 뒤에 다시 조회했고 세 번째에 성공했으며, 이후 8초 동안 추가 조회가 없었다. eslint와 타입 검사 통과.
- **확인하지 못한 것**: 사용자 기기에서 실패가 난 실제 이유(서버 기록 보관이 하루뿐이라 과거 요청을 볼 수 없었다). 3번 재시도로도 실패가 이어지는 장애에서는 여전히 지점이 빠진다(이 경우 지도를 움직이면 다시 조회한다). 이 화면의 실패를 사용자에게 알리는 문구는 더하지 않았다.
- **알아 둘 점**: 실패 원인이 서버 쪽 느린 응답이나 일시 오류라면 재시도로 풀리지만, 지점이 아예 없는 구역은 원래대로 비어 보인다. 체크인 조회 실패 횟수를 어디에도 기록하지 않으므로, 이후에도 같은 일이 잦다면 서버 쪽 원인을 따로 살펴야 한다.
