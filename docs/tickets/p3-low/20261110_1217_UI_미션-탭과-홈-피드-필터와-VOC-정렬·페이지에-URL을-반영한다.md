# [UI] 미션 탭과 홈 피드 필터와 VOC 정렬·페이지에 URL을 반영한다

## 핵심 요약

- 요구사항: 탭·필터처럼 화면 안에서 상태로만 바뀌는 선택을 쿼리 URL에 싣는다. 미션 목록 탭 `/missions?tab=joined|ended`(기본 `ongoing`은 쿼리 없음), 홈 피드 필터 `?feed=badge|mission|activity_badge`(기본 `all`은 쿼리 없음), VOC `/voc?sort=<정렬>&page=<번호>`(기본값은 쿼리 없음). 탭·필터 전환은 history를 쌓지 않고(`router.replace`) 새로고침·링크 공유·상세에서 돌아오기 때 같은 선택이 유지되게 한다. VOC의 페이지 번호만 `push`로 쌓아 뒤로가기가 이전 페이지로 돌아가게 한다.
- 구현 계획: 아래 「구현 계획」 참조.
- 관련 파일: `jam-web/src/app/(main)/missions/MissionsListClient.tsx`(`tab` L200), `jam-web/src/app/(main)/FeedSection.tsx`(`activeFilter` L900, `handleFilterChange` L910 안팎; `FilterTab`은 L50의 `'all'|'badge'|'mission'|'activity_badge'`), `jam-web/src/app/(main)/voc/page.tsx`(`sort`·`page` L115~116), 각각의 기존 시험

## 배경 / 문제 정의

디자이너가 «믹스하기의 개별 레시피 상세 화면처럼 개별 URL이 없는 화면들은 뒤로 가기(history back)가 안 돼서 불편하다. 같은 방식으로 표시되는 화면들에 개별 URL을 부여하라»고 했다(2026-11-10). 지금은 화면 안의 상태(`useState`)로만 화면이 바뀌어서, 브라우저·기기의 뒤로가기를 누르면 그 화면이 아니라 앞서 있던 다른 라우트로 나가 버린다. 전수 조사로 URL이 없는 곳을 찾았고, 디자이너가 아래 범위를 정했다: ① 믹스하기 레시피 상세·등급 올리기, ② 드랍 지도의 장소 캐러셀, ③ 탭·필터 전환. URL 모양은 쿼리 방식이고, 잘못된 값은 목록(기본 화면)으로 조용히 돌려보낸다. 온보딩 2단계와 시트·확인 오버레이는 이번 범위에 넣지 않는다.

이미 URL이 있는 탭은 이번에 바꾸지 않는다: 배지 목록 탭(`/badges#탭`, 쿼리 `?tab=` 우선, `replaceState`), 프로필 팔로워·팔로잉 탭(`/프로필#followers`, 해시 이동으로 뒤로가기 지원).

## 상세 요구사항

### 서비스/코드베이스 관점
- 각 화면의 상태 초기값을 쿼리에서 읽고, 전환 때 같은 키로 쿼리를 쓴다(`router.replace`, `{ scroll: false }`). 알 수 없는 값은 기본값으로 취급한다.
- 홈 피드 필터(`FeedSection`)는 홈(`/`)과 같은 컴포넌트를 쓰는 다른 화면이 있는지 확인하고, 있으면 그 화면에서도 같은 규칙이 문제없는지 본다. 필터를 바꾸면 «더 보기» 개수(`visibleCount`)는 초기화하는 지금 동작을 유지한다.
- VOC는 정렬 전환 시 1페이지로 돌아가는 지금 동작을 유지하고, 정렬은 `replace`, 페이지 번호는 `push`한다.
- 서버에서 처리하는 값이 아니라면 서버 `page.tsx`는 건드리지 않는다.

### UI/UX 관점
- 화면 모양은 그대로다.

### 컨텐츠 관점
- 새 문구 없음.

## 구현 계획

1. `jam-web/src/app/(main)/missions/MissionsListClient.tsx`: `tab` 초기값을 `?tab=`에서 읽고, 탭 전환 핸들러(`SlidingTabs onChange`, L253 안팎)에서 `router.replace`로 쿼리를 쓴다. 활동종류·정렬 필터는 이번 범위 아님.
2. `jam-web/src/app/(main)/FeedSection.tsx`: `activeFilter` 초기값을 `?feed=`에서 읽고 `handleFilterChange`에서 `router.replace`.
3. `jam-web/src/app/(main)/voc/page.tsx`: `sort`·`page`를 `?sort=&page=`에서 읽고, 정렬 전환은 `replace`(page 1로), 페이지 전환은 `push`.
4. 각 화면의 기존 시험(없으면 순수 쿼리 해석 함수를 떼어 시험)에 «쿼리 → 초기 선택», «전환 → 쿼리», «알 수 없는 값 → 기본값»을 더한다. PRD에 해당 화면 설명이 있으면 URL 규칙을 한 줄 적는다.

## 완료 조건

### 구현 범위 (게이트 판정 대상)
- `/missions?tab=ended`로 열면 종료 탭이 선택되어 있고, 탭을 바꾸면 주소의 쿼리가 따라 바뀌며 history 항목은 늘지 않는다. 기본 탭(`ongoing`)은 쿼리가 없다.
- 홈 피드 필터와 VOC 정렬·페이지도 같은 방식으로 쿼리와 동기화된다. VOC에서 페이지를 넘긴 뒤 뒤로가기를 누르면 이전 페이지가 나온다.
- 알 수 없는 쿼리 값은 기본값 화면으로 열린다.
- 배지 탭·프로필 팔로워 탭의 동작은 바뀌지 않는다.
- 시험이 통과하고 `scripts/verify.sh`가 통과한다(어드민 `Invalid hook call` 실패는 티켓 20261110_1157의 기존 문제).

### 후속 범위 (담당: 카리나, 시점: 머지 뒤)
- 로컬 `next dev`에서 미션·홈·VOC의 전환과 새로고침을 눌러 확인한다.

## 완료 기록

### 구현 내용 요약
미션 목록 탭, 홈 피드 필터, VOC 정렬·페이지를 쿼리 URL에 실었다. 미션 `?tab=joined|ended`, 피드 `?feed=badge|mission|activity_badge`, VOC `?sort=answered&page=N`이고 기본값은 쿼리에서 빠진다. 탭·필터·정렬 전환은 `router.replace`(`scroll:false`)라 history가 쌓이지 않고, VOC 페이지 번호만 `router.push`다. 알 수 없는 값은 기본값으로 처리한다. 공용 순수 함수 `lib/urlQueryState.ts`가 읽기·합치기를 맡고 다른 쿼리와 해시를 보존한다(프로필의 `?u=`·`?from=`·해시 포함). 배지 탭과 프로필 팔로워 탭은 이미 URL이 있어 바꾸지 않았다.

### 주요 의사결정 / 핵심 메모
- 피드 필터 쓰기는 현재 쿼리·해시를 보존하고 `feed` 키만 바꾼다(프로필 화면의 `?u=`와 충돌하지 않는다).
- 페이지 번호는 `^[1-9]\d{0,8}$`만 인정한다(0·음수·소수·`007`은 1쪽).
- VOC는 상태가 아니라 주소에서 직접 읽는다(뒤로가기가 상태를 되돌려야 해서). 이 페이지는 클라이언트 페이지라 `useSearchParams`용 Suspense 경계를 추가했다.

### 잔여 이슈
- 미션 탭 전환의 `router.replace`는 서버 컴포넌트의 쿼리가 바뀌는 이동이라 서버 재요청이 생길 수 있다. 로컬에서는 문제가 없었으나 실서비스 요청 수는 확인하지 못했다.
- VOC 페이지 번호의 `push`와 뒤로가기는 실화면으로 확인하지 못했다.
