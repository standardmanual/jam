# [Admin] 운영 서랍 미리보기의 배지 읽기가 삭제된 배지를 거르지 않아 묶음 수가 홈 카드와 다르다

> 티켓 20261114_2111 게이트 리뷰(민지)의 범위 밖 발견물 `[주의/정합성]`·`[참고/중복]`

## 핵심 요약

- 요구사항: 합친 레시피의 보상 배지를 «이름 묶음 수»로 셀 때, 홈 카드(`lib/today/cards.ts`)는 `deleted_at IS NULL`로 삭제된 배지를 거르지만 운영 서랍 쪽 `previewNames`의 배지 읽기는 거르지 않아 삭제된 배지도 묶음 수에 들어갈 수 있다. 두 곳의 규칙을 같게 맞춘다.
- 구현 계획: `previewNames`가 수집하는 배지 읽기에서 삭제된 배지를 구분해 `rewardBadgeCountOf`에 넘기지 않게 한다(이름 표시용 읽기는 삭제된 배지도 필요할 수 있으므로 «세는 값»에서만 뺀다). 등급 순서가 `lib/combine/gradeMode.ts`의 `GRADE_ORDER`와 `lib/rarity.ts`의 `RARITY_TIER` 두 곳에 있어, 한쪽만 바뀌면 대표 배지 선택이 어긋난다. 두 순서가 같음을 확인하는 시험을 더한다.
- 관련 파일: `jam-web/src/lib/admin/opsInbox/previewNames.ts`(103줄 부근 배지 조회), `jam-web/src/lib/admin/opsBoard/drawerView.ts`(`badgeCountOf`), `jam-web/src/lib/combine/gradeMode.ts`(92줄 부근 `GRADE_ORDER`, `rewardBadgeCountOf`), `jam-web/src/lib/rarity.ts`(`RARITY_TIER`).

## 배경 / 문제 정의

- 현재 합친 레시피의 보상 배지는 삭제된 것이 없어 두 곳의 결과가 같다. 레시피 보상 배지를 나중에 삭제하면 운영 서랍이 «배지 1개» 대신 다른 값을 보일 수 있다.

## 완료 조건

- 합친 레시피의 보상 배지 중 하나를 삭제된 것으로 둔 가짜 데이터에서 운영 서랍과 홈 카드의 보상 배지 수가 같다.
- `GRADE_ORDER`와 `RARITY_TIER`의 등급 순서가 같음을 확인하는 시험이 있다.
