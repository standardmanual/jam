# [Infra] 기준 코드에서 이미 실패하는 시험 5건을 원인별로 고친다

> 티켓 20261114_1705·20261114_2111 구현 중 아현·민지가 «변경 이전 기준 커밋에서도 똑같이 실패»한다고 확인한 시험이다.

## 핵심 요약

- 요구사항: 기준 코드(`origin/staging`)에서 이미 실패하는 시험 5건의 원인을 가려 고친다(코드가 틀렸는지 시험이 낡았는지 건마다 판정).
- 구현 계획: 아래 건을 하나씩 열어 원인별로 고친다. 건마다 «시험이 낡음»이면 기대값을 고치고 «코드가 틀림»이면 코드를 고친다.
- 관련 파일:
  - `jam-web/src/lib/today/__tests__/cardView.test.ts`(375줄 부근 «기본 필드»가 라벨 «배지 소개» 대신 «배지»를 받음)
  - `jam-web/src/lib/events/__tests__/eventsImports.test.ts`(이벤트 API 번들에 한국어 사전이 섞이는지 확인. `lib/events.ts` → `combine/visibility.ts` → `rarity.ts` → `lib/i18n` 경로로 한국어 사전이 딸려 들어옴)
  - `registerChecks.test.ts`(`lib/admin/registerChecks/references.ts`의 item_books 외래 키 대조, 이미지 생성 표 참조 목록)
  - `jam-web/src/app/api/admin/item-paths/route.test.ts`(아이템 길 tierUp)
  - `registerMissionBundle` 시험(`status_display_type` 관련)

## 배경 / 문제 정의

- 푸시 전 검사(`.githooks/pre-push`)와 `scripts/verify.sh`의 test 단계가 이 건들 때문에 실패 상태로 남아, 새 변경이 만든 실패와 구분하기 어렵다.

## 완료 조건

- 위 5건이 모두 통과하거나, 통과시키지 않기로 한 건은 사유와 함께 시험에서 제외된다.
- `scripts/verify.sh`의 test 단계가 변경 없는 기준 코드에서 통과한다(격리 워크트리의 React 연결 오류는 이 티켓 범위가 아니다).
