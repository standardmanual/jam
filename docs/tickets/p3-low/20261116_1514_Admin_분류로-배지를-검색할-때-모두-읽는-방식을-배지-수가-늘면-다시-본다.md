# [Admin] 분류로 배지를 검색할 때 조건에 맞는 배지를 모두 읽는 방식을 배지 수가 늘면 다시 본다

## 핵심 요약
- 요구사항: 액티비티 배지 검색에 분류 조건을 주면 검색 API가 다른 조건에 맞는 배지를 모두 읽어 분류를 계산한 뒤 걸러 낸다. 배지 수가 크게 늘면 이 방식이 느려질 수 있으니 그때 다시 본다(티켓 20261116_1442의 게이트에서 민지가 남긴 범위 밖 발견물, 참고/성능).
- 구현 계획: 지금은 할 일이 없다. 다시 볼 때의 후보는 분류를 DB 칸으로 두거나, 계산 결과를 잠시 보관하는 것이다.
- 관련 파일: `jam-web/src/app/api/admin/activity-badge-image/search/route.ts`(분류 조건이 있을 때 1,000줄씩 끝까지 읽는 구간, 104행 부근), `jam-web/src/lib/admin/activityBadgeTemplate/resolveTemplateText.ts`(분류를 계산하는 규칙)

## 배경 / 문제 정의
분류는 `badges` 표의 칸이 아니라 획득 조건에서 계산하는 값이라서 DB 조건으로 거를 수 없다. 2026-11-16 기준 액티비티 배지는 390개이고, 어드민에서 운영자 한 사람이 쓰는 검색이라 지금은 부담이 작다.

## 상세 요구사항

### 서비스/코드베이스 관점
- 액티비티 배지가 수천 개로 늘거나 분류 검색이 느리다는 말이 나오면 응답 시간을 재고 방식을 정한다.

## 완료 조건
- 응답 시간을 잰 값과 «그대로 둔다» 또는 «바꾼다»는 결정이 이 티켓에 적혀 있다.
