# [Admin] CLI 홈피드 등록 묶음은 카드 유형 칸이 없어 설명문이 홈에 보이지 않는데도 옛 템플릿 규칙으로 설명문을 받는다

## 핵심 요약

- 요구사항: CLI 등록 묶음(`registerHomeFeedBundle.mjs`)으로 만든 카드는 카드 유형(`feed_type`)이 비어 홈이 모두 텍스트 박스로 그리고, 텍스트 박스는 설명 문단을 숨긴다. 그런데 등록 검사는 옛 템플릿 규칙으로 `badge_spotlight`·`content_intro`의 설명문을 받고, 거절 문장은 «홈은 badge_spotlight·content_intro에서만 설명 문단을 그려요»라고 안내한다. 이 경로를 어떻게 정리할지 정한다.
- 구현 계획: 정하지 않았다. 후보는 (가) CLI 묶음에 카드 유형 칸을 더해 운영 묶음과 같은 규칙(`feedTypeDecidesDescription`)으로 검사한다, (나) CLI 경로를 운영 묶음(운영툴)으로 일원화하고 CLI 묶음을 걷어낸다, (다) 거절 문장만 사실대로 고친다.
- 관련 파일: `jam-web/src/lib/admin/registerChecks/homeFeedFields.ts`(`CARD_OPTIONAL_FIELDS` ~53줄, `validateCard`의 설명문 검사, `buildTodayCardInsertPayload`의 `feedColumns` 기본값 `null` ~384줄), `jam-web/scripts/asset-generator/registerHomeFeedBundle.mjs`(`validateCard` 호출 ~275줄, `buildTodayCardInsertPayload` ~297줄), 시험 `jam-web/scripts/asset-generator/__tests__/registerHomeFeedBundle.test.ts`(~670~686줄)·`registerHomeFeedFlow.test.ts`, 문서 `docs/service/prd/asset-generator/HOME_FEED_REGISTRATION_BUNDLE.md`(~147줄).

## 배경 / 문제 정의

- 티켓 20261122_1101부터 홈은 설명 문단을 카드 유형과 `show_description`으로 그린다(`feedLook.ts`의 `DESCRIPTION_DEFAULT`). 유형이 비면 `resolveFeedType`이 텍스트 박스로 보내고, 텍스트 박스는 설명을 숨긴다.
- 운영 묶음 경로는 티켓 20261124_1050이 카드 유형 기준으로 바꿨고, 어드민 폼·조회 화면은 티켓 20261124_1119가 바꾼다.
- CLI 묶음은 `CARD_OPTIONAL_FIELDS`에 `feed_type`이 없어 유형을 실을 수 없고, `buildTodayCardInsertPayload`에 `feedColumns`를 넘기지 않아 새 칸이 모두 NULL로 들어간다(2026-11-24 코드 확인). 그래서 이 경로의 카드에 적은 설명문은 홈에 보이지 않는다.
- 이 경로가 아직 쓰이는지는 확인하지 않았다.

## 완료 조건

- 방향(가·나·다 또는 다른 안)을 사용자와 정하고, 정한 방향대로 바꾼 뒤 CLI 묶음 시험과 `HOME_FEED_REGISTRATION_BUNDLE.md`의 `description` 행이 홈의 실제 동작과 같다.
