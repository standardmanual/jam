# [Admin] 컬렉션 표지 생성 설정(cover_params) 검증을 한 곳으로 모으고 seed·badgeId 타입도 검사한다

## 핵심 요약

- 요구사항: `cover_params` 모양 검사가 저장 API와 화면 상태 함수 두 곳에 따로 있다. 한 함수로 모으고, 저장 API가 빠뜨린 `seed`·`badgeId`(문자열)·`appliedAt` 타입 검사를 더한다.
- 구현 계획: 검사 함수를 `jam-web/src/lib/collection-cover/`(예: `params.ts`)로 옮겨 두 곳이 같이 쓴다. 기존 시험의 사례는 그대로 통과해야 한다.
- 관련 파일: `jam-web/src/app/api/admin/itembooks/[id]/route.ts` 88~102줄(`HEX6`, `isValidCoverParams`), `jam-web/src/components/admin/itembooks/collectionCoverState.ts` 45줄(`parseCoverParams`), 각 `__tests__`

## 배경 / 문제 정의

3회차(티켓 20261124_1744) 게이트에서 민지가 남긴 범위 밖 발견물이다(참고 1건, WARN 사유 1건). 둘 중 하나만 고치면 화면이 저장한 값을 API가 거절하거나, API가 받은 값을 화면이 버리고 기본값으로 여는 어긋남이 생길 수 있다.
저장 API의 `HEX6`는 소문자만 받는다. 화면이 소문자로 맞춰 보내는지도 같이 확인한다.

## 완료 조건

- 검사 함수가 한 곳에만 있고 저장 API·화면이 그것을 쓴다.
- `seed`·`badgeId`·`appliedAt`가 문자열이 아니면 저장 API가 400을 낸다(시험).
- `scripts/verify.sh` 통과.
