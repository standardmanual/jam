# [UI] 홈 «오늘의 현황» 진행·팔로잉 카드를 블랙 면으로 바꾼다

## 핵심 요약

- 요구사항: 홈 캡슐 게이지 아래 «진행»·«팔로잉» 카드의 배경을 블랙으로 바꾼다. 블랙 위에서 반전(네거티브)으로 그려야 하는 요소는 토큰에서 골라 쓰고, 진행 바 색은 그린으로 한다.
- 구현 계획: 두 칸의 `Card`를 `tone="inverse"`로 바꾸고, 라벨 칩은 `--surface-on-inverse` 면 + `--snow` 글자, 진행 바는 정본 `ProgressCountBar`(채움은 기본값 그린)를 쓰고, 블랙 면용 `onInverse` 옵션(트랙 `--surface-on-inverse`, 수치 `--snow`)을 더한다. 새 토큰·새 컴포넌트는 만들지 않는다.
- 관련 파일: `jam-web/src/app/(main)/TodayStatusStrip.tsx`, `TodayStatusStrip.test.tsx`, `jam-web/src/components/ui/ProgressCountBar.tsx`, `jam-web/design-system/tokens/primitive.css`(`--jam-green` 지정 사용처 주석), `docs/service/prd/home-feed/PRD.md`(6번 영역·스트립 서술)

## 배경 / 문제 정의

스트립 두 칸이 흰 카드라 위 캡슐 게이지(검정 트랙)와 면 무게가 다르고, 사용자가 블랙 면을 원했다.

## 상세 요구사항

### UI/UX 관점
- 면: `Card` `inverse` 톤(`--background-inverse`, 글자 `--snow`). 진행·팔로잉의 모든 상태(미연동·진행 중·안내·팔로잉 없음·친구 활동)에 적용한다.
- 라벨 칩(«진행»·«팔로잉»): `LabelChip`의 두 색조가 블랙 면에서 맞지 않아(default는 회색 알약이 튀고 inverse는 면에 묻힌다) `style`로 면·글자를 토큰(`--surface-on-inverse`, `--snow`)으로 덮는다.
- 진행 바: 정본 `ProgressCountBar`(캡슐 16px, 채움은 기본값 그린)를 쓴다. 화면 코드가 기본값 토큰(`--jam-green`)을 직접 쓰면 UI 규칙 검사(primitive-ref)가 거절해서, 그린을 이미 기본으로 가진 정본을 재사용한다.
- 블랙 면에서는 `ProgressCountBar`의 트랙(`--capsule-track`)이 면과 같은 검정이라 사라지고 수치(`--link`)도 보이지 않는다. 그래서 정본에 `onInverse` 옵션을 더해 트랙을 `--surface-on-inverse`, 수치를 `--snow`로 바꾼다.
- `--jam-green`은 지정 사용처에만 쓰는 토큰이라 primitive.css 주석의 지정 사용처에 이 바를 추가한다.

### 같은 티켓에 포함한 인벤토리 변경 (사용자 지시 2026-11-27)
- 인벤토리 상단 진행 바 채움색을 컬렉션 상세의 진행도 바와 같은 `--capsule-fill`로 바꾼다(`inventory/page.tsx`의 `ProgressCountBar`에 `color` 전달).
- 인벤토리 빈 슬롯을 총 6칸까지만 그리던 규칙(`6 - items.length`)을 지우고 남은 슬롯 수(`remainingSlots`)만큼 모두 그린다. «페이지의 길이만큼»을 «남은 슬롯 전부(예: 4/30이면 26칸)»로 풀었다.

## 구현 계획

`TodayStatusStrip.tsx`의 `Card` 5곳 톤 변경, 칩·바 색 상수 추가, 단언 테스트 갱신, PRD·토큰 주석 갱신.

## 완료 조건

- 스트립 두 칸의 배경이 `--background-inverse`이고 `--card-bg`가 없다. 라벨 칩은 `--surface-on-inverse` 면 + `--snow` 글자다. 진행 바는 `ProgressCountBar`로 채움 `--jam-green`, 트랙 `--surface-on-inverse`, 수치 `--snow`다. 확인: `TodayStatusStrip.test.tsx` 단언과 로컬 화면 확인.
- 인벤토리 상단 진행 바 채움이 `--capsule-fill`(주황)이고, 격자 칸 수가 최대 슬롯 수(`max_slots`)와 같다(예: 4/30이면 30칸). 확인: 로컬 화면.
- 타입체크와 `src/app/(main)/TodayStatusStrip`·`inventory` 테스트, UI 규칙 검사가 통과한다.

- 사용자 승인: 2026-11-27 — 홈 «진행»·«팔로잉» 카드 면을 블랙으로 변경, 블랙 위 반전 요소는 기존 토큰 선택, 진행 바는 인벤토리 상단 진행 바와 같은 그린 사용(지정 사용처 추가, 화면 변화). 사용자가 대화에서 직접 지시(인벤토리 바 색 변경과 빈 슬롯 확대도 같은 날 사용자 지시). 블랙 면용 `ProgressCountBar`의 `onInverse` 옵션 추가는 이 지시를 이루는 최소 변경으로 카리나가 포함했고 결과 보고에서 사용자에게 알린다.

### 주요 의사결정 / 핵심 메모
- 진행 바는 새 토큰(`--today-progress-fill` 같은 컴포넌트 토큰)을 만들지 않고 `ProgressCountBar`의 기본 그린을 재사용했다(사용자 답변: 인벤토리 바에 적용된 색). 그 직후 인벤토리 바는 사용자 지시로 `--capsule-fill`로 바뀌었다.
- 칩은 `LabelChip`에 새 색조를 더하지 않고 `style`로 토큰만 덮었다(새 variant는 별도 승인 대상이라 피했다). 같은 칩이 다른 블랙 면에서 또 필요하면 색조 추가를 따로 논의한다.
- 트랙을 `--capsule-track`이 아닌 `--surface-on-inverse`로 한 이유: 카드 면(`--background-inverse`)과 트랙이 같은 검정이라 트랙이 사라진다.

### 잔여 이슈
- 빈 슬롯 «페이지의 길이만큼»을 화면 높이 기준이 아니라 남은 슬롯 전부로 해석했다. 화면 높이만큼만 원했다면 다시 조정한다.
