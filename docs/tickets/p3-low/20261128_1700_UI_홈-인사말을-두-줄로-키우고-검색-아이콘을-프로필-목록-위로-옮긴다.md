# [UI] 홈 인사말을 두 줄로 키우고 검색 아이콘을 프로필 목록 위로 옮긴다

## 핵심 요약

- 요구사항: 홈 인사말을 «{이름}님» / «오늘도 좋은 하루예요» 두 줄로 나누고, 글자 크기를 지금의 2배에 해당하는 눈금으로 키운다. 홈의 검색 버튼은 없애고 내 프로필의 팔로워·팔로잉 목록 첫 줄 위로 옮긴다.
- 구현 계획: `ko.ts`의 `todayStatus.greeting`을 `greetingName`·`greetingBody` 둘로 나누고, 홈 `page.tsx`의 인사말 줄을 `text-3xl` 두 줄로 바꾸며 검색 링크를 지운다. `ProfileClient.tsx`의 팔로워·팔로잉 목록 위에 검색창(`UserSearchBar`)을 내 프로필에서만 그린다.
- 관련 파일: `jam-web/src/lib/i18n/ko.ts`(`todayStatus.greetingName`·`greetingBody`), `jam-web/src/app/(main)/page.tsx`(인사말 줄), `jam-web/src/app/(main)/profile/ProfileClient.tsx`(`renderTabContent`의 `searchLink`), `jam-web/src/app/(main)/homeGreeting.test.ts`(새 테스트), `docs/service/prd/home-feed/PRD.md`(2절 3번 영역)

## 배경 / 문제 정의

홈 인사말이 한 줄 `text-base`라 작고, 검색 아이콘이 인사말 줄 오른쪽에 붙어 있었다. 사용자가 인사말을 크게 두 줄로 보이게 하고, 검색은 팔로우할 사람을 찾는 자리인 프로필 목록으로 옮기기를 원했다.

## 상세 요구사항

### UI/UX 관점
- 인사말: 첫 줄 «{이름}님», 둘째 줄 «오늘도 좋은 하루예요». 이름이 길면 첫 줄만 말줄임(`truncate`)이다.
- 글자 크기: 이전 `text-base`(16px)의 2배(32px)에 해당하는 토큰은 눈금에 없다. 눈금에서 가장 가까운 `text-3xl`(30px, 행간 36px)을 쓴다. 새 토큰은 만들지 않는다.
- 문구: 사용자 요청 예시는 «하루에요.»였으나 기존 문구(«하루예요», UX Writing 가이드의 해요체·문장부호 규칙)를 유지했다.
- 검색창(2026-11-28 사용자 추가 지시로 아이콘 버튼에서 바꿨다): 정본 `UserSearchBar`(compact)를 내 프로필의 팔로워·팔로잉 탭 목록 첫 줄 위에 놓는다. 입력칸 앞에 돋보기, 안쪽 오른쪽에 «검색» 버튼이 있고, 제출하면 `/search?q=`(검색 결과 페이지)로 이동한다. 타인 프로필에는 그리지 않는다. 새 컴포넌트·토큰은 없다.
- 빈 목록(팔로워·팔로잉 없음)에도 검색창을 그린다: 홈에서 검색으로 가는 길이 없어져 팔로우할 사람을 찾는 길이 여기뿐이다.

## 구현 계획

문구 키 분리, 홈 인사말 줄 교체, 프로필 목록 위에 링크 추가, 소스 구조 테스트 추가, PRD 갱신.

## 완료 조건

- 홈에서 인사말이 두 줄이고 글자 크기가 30px(행간 36px)이며 `/search` 링크가 없다. 확인: 로컬 화면의 계산된 스타일과 `a[href="/search"]` 개수 0.
- 내 프로필 팔로잉·팔로워 탭에서 목록 첫 줄 위에 검색창이 있고, 검색어를 넣고 «검색»을 누르면 `/search?q=검색어`로 이동해 결과가 나온다. 확인: 로컬 화면(검색어 minjun → 결과 1명).
- 타입체크와 `(main)` 홈·프로필 테스트가 통과한다.

- 사용자 승인: 2026-11-28 — 홈 인사말 2줄·2배 크기 토큰 적용, 검색 버튼을 내 프로필 팔로워·팔로잉 목록 첫 줄 위로 이동하고 그 앞에 검색창을 표시(화면 변화), 검색 버튼은 검색 결과 페이지로 이동. 사용자가 대화에서 직접 지시했다. 2배(32px)에 정확히 맞는 토큰이 없어 가장 가까운 `text-3xl`을 쓴 것은 카리나의 판단이며 결과 보고에서 알린다.
