# JAM! Service Document

JAM! 서비스를 **기획하고 운영하는** 문서를 모아 둔 폴더입니다. 서비스를 **만드는** 쪽
(Vercel에 배포되는 `jam-web/`, 코드가 따라야 할 스펙 `docs/specs/`, 작업 티켓 `docs/tickets/`)과
짝을 이룹니다.

두 갈래를 나누는 기준은 하나입니다. **배포되는 코드와 같은 맥락에서 함께 바뀌는가.** 그렇다면
`docs/`에, 코드가 바뀌지 않아도 따로 바뀌는 문서라면 이 폴더에 둡니다.

> **이 폴더는 2026-09-18부터 2026-09-20까지 별도 저장소(`standardmanual/jam-doc`)였습니다.**
> 저장소가 둘이라서 동기화·권한·격리 워크트리에서 마찰이 반복돼 다시 합쳤습니다
> (티켓 `docs/tickets/p1-high/20260920_1412_Infra_문서저장소-코드저장소로-재통합.md`).
> 분리 시절의 원격 저장소는 사용자가 직접 삭제합니다. 그 기간(이틀)의 커밋 이력은 남지
> 않으며, 파일 내용은 전부 이 저장소에 그대로 들어와 있습니다.

## 폴더와 쓰기 규칙

| 폴더 | 내용 | 쓰기 방식 |
|---|---|---|
| `planning/content/` | 세계관(TRIBES)·액티비티배지·아이템북·믹스 레시피·POI 컨텐츠 | 덮어쓰기. 지금 사실만 담는다 |
| `planning/content/tribes-history/` | 세계관 설정을 바꾸기 전 스냅샷 | 신규 추가만 |
| `planning/business-plan/` | 서비스플랜·철학 등 비전과 장기 전략 | 덮어쓰기. 버전 사본을 만들지 않는다 |
| `marketing/` | 마케팅 플레이북·브랜드 보이스·트렌드 노트 | 덮어쓰기 |
| `operations/reports/` | 주간·월간·배포 리포트 | 신규 추가만. 기존 파일을 고쳐 쓰지 않는다 |
| `inbox/trends/` | 사용자가 직접 넣는 트렌드 자료(사용법 `jam-doc/inbox/trends/README.md`) | 신규 추가만. 올린 원문은 고치지 않는다. 에이전트는 재료로만 읽는다 |
| `assets/` | 배지 이미지 제작물·UI 프로토타입·브랜드 원본·컨텐츠 시드 생성기(`content-seed/`) | 생성 산출물. 문서 검색 대상이 아니다 |
| `archive/` | 폐기된 기록 | 읽기 전용. 신규 추가·수정 금지. 현재 상태 판단의 근거로 쓰지 않는다 |

- 버전 사본(`v3.1`, `_20260827` 등)을 만들지 않습니다. 이력은 git이 보관합니다.
- 폴더명은 영문 소문자로 씁니다. 파일명과, 콘텐츠 제목이 곧 이름인 폴더(이미지 제작의
  스타일그룹·브리프 폴더)는 한글을 그대로 씁니다.
- 위 규칙 일부는 작업 폴더 루트의 `.githooks/pre-commit`이 기계적으로 막습니다(④⑤⑥ 항목).
  정당한 예외는 `JAM_SKIP_DOCLINT=1`로 우회하고 사유를 커밋 메시지에 남깁니다.
- 같은 훅이 `scripts/doc-check.mjs`로 문서 링크·백틱 경로·frontmatter도 검사합니다
  (스키마: `docs/specs/DOCUMENT_SCHEMA.md`). 새로 깨지는 링크와 frontmatter(`type`·`description`
  누락 등)는 차단하고, 백틱 경로는 경고만 합니다. 무인 예약 루틴이 쓰는 `operations/reports/`는
  검사 범위(`scope.exclude`)에서 빠져 있어 frontmatter가 없어도 항상 통과합니다.

## 경로 표기 규칙

문서에 경로를 적을 때는 **항상 작업 폴더(`JAM!/`)를 기준으로** 적습니다.

- 이 폴더의 파일: `jam-doc/planning/content/TRIBES.md`
- 코드 쪽 파일: `docs/specs/prd/01_PRD.md`, `jam-web/src/...`

`assets/content-seed/`의 생성 스크립트(`v5_*.py`)는 자기 위치에서 세 단계 위를 작업 폴더로
계산해 `jam-web/supabase/migrations/`에 시드를 씁니다. 그래서 이 폴더는 반드시 작업 폴더 바로
아래의 `jam-doc/`에 있어야 하고, 생성기 묶음을 다른 깊이의 폴더로 옮기면 스크립트의 경로 계산도
함께 고쳐야 합니다.

## 동기화

별도 설치 절차가 없습니다. 작업 폴더를 복제하면 이 폴더도 함께 따라옵니다. 이후 동기화는
`/jam-sync`가 처리하고, 커밋과 push도 코드와 같이 한 번에 이뤄집니다.
