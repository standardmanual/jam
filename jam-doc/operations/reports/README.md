# reports — 시점별 기록 (주간·월간·배포 리포트)

> 신설 폴더 (티켓 20260918_1152, 상위 티켓 20260918_1101 안건 3). 이전에는 주간 브리핑
> 양식(`.claude/skills/jam-work/references/forms/weekly-briefing-format.md`)만 있고 저장
> 위치가 없어 보고가 대화와 함께 사라졌다.

## 구조

```
reports/
  weekly/YYYY-Www.md    예: 2026-W38.md (ISO 주차)
  weekly/YYYY-Www-images/<묶음 ID>/  그 주 홈피드 후보 이미지(image.png)와 등록 묶음(bundle.json). 리포트 표가 상대 경로로 참조한다(티켓 20260926_1207)
  monthly/YYYY-MM.md     예: 2026-09.md
  deploy/YYYY-MM-DD.md  예: 2026-09-24.md (주간 배포 승인 루틴, 티켓 20260918_1650)
  triage/YYYY-MM-DD.md  예: 2026-09-22.md (선별 루틴, 티켓 20260921_2306)
  triage/state.json     선별 루틴의 증분 판정 캐시 — 유일한 예외로 매 실행마다 갱신한다(아래 "선별 형식" 참고)
```

- 주간 리포트는 `weekly-briefing-format.md` 형식을 따른다.
- 주간 리포트는 「홈피드 초안」 다음에 「전략 변경안」 절을, ISO 주차가 짝수인 주에는 「유형 리뷰 (격주)」 절을 둔다(티켓 20260923_2300·2301, 양식은 `weekly-briefing-format.md`).
- 월간 리포트는 「배지·미션 제안 재료」 다음에 「유형 카탈로그 리뷰」 절과 「매핑표 갱신 후보」 항목을 둔다(초안·사람 등급 유형 11종, PRD §11).
- 월간 리포트는 "트렌드 노트" 절 다음에 「제외된 소재」 절을 둔다. PRD §7.3 자동 제외 범주로
  걸러진 소재를 사유·건수·범주별 건수와 함께 남긴다(형식·집계 로직은 `scripts/issue-filter-check.mjs`,
  절차는 `scheduled-jobs.md`의 「월간」 표).
- 배포 리포트는 매주 목요일 23:59 KST 실행 결과(배포 여부·승격 커밋 목록·Vercel 검증 결과)를
  남긴다. 절차는 `.claude/skills/jam-work/references/scheduled-jobs.md`의 "주간 배포 승인" 참고.
- 홈피드(투데이 카드) 다음 주 편성 후보안도 카즈하 브리핑 다음, 같은 주간 파일 안 "홈피드 초안" 절에 넣는다. 형식(요일별 후보
  A/B/C·1픽·최종 선택·승인·분포)은 `weekly-briefing-format.md` 「홈피드 초안 형식」, 정본은 PRD §8이다(티켓 20260923_2258).
- 리포트에는 집계 수치만 남긴다. 닉네임·이메일·유저 ID 등 개인 식별 정보는 적지 않는다 —
  개별 사례는 "의심 계정 N건, 어드민 화면에서 확인 필요"로만 쓴다.

## 선별 형식 (티켓 20260921_2306)

카즈하 모드 ③이 매일 남기는 것. 판정 기준·증분 실행 기준은 `.claude/agents/jam-ops.md`
모드 ③ 절이 단일 원천이고, 여기는 형식 예시만 둔다.

`triage/YYYY-MM-DD.md` (티켓당 한 줄, 대상이 없으면 파일을 만들지 않거나 "변경 없음" 한 줄만):

```
# 선별 2026-09-22

- [ ] 20260921_2306 · 적격 · 관련 파일 7개·정의/문서/훅만, verify.sh로 완료 확인 가능
- [ ] 20260920_1907 · 사람 필요 · 에이전트 정의 파일을 건드려 제외 영역에 해당
```

사용자는 동의하는 줄에 체크한다. 이 체크 상태가 주간 브리핑 「선별 동의율」 계산의 입력이다.

`triage/state.json` (증분 캐시 — 시점별 리포트가 아니라 인덱스이므로 "쌓기만 하고 덮어쓰지
않음" 규칙의 유일한 예외다. 매 실행마다 새로 판정한 티켓 항목만 갱신·추가하고 나머지는
그대로 둔다):

```json
{
  "lastRunAt": "2026-09-22T06:00:00+09:00",
  "tickets": {
    "20260921_2306": { "verdict": "적격", "reason": "관련 파일 7개·정의/문서/훅만, verify.sh로 완료 확인 가능", "judgedAt": "2026-09-22T06:00:00+09:00" },
    "20260920_1907": { "verdict": "사람 필요", "reason": "에이전트 정의 파일을 건드려 제외 영역에 해당", "judgedAt": "2026-09-22T06:00:00+09:00" }
  }
}
```

## 수명주기: 시점별 기록 (쌓기만 하고 덮어쓰지 않음)

> 예외 하나: `triage/state.json`은 시점별 리포트가 아니라 선별 루틴의 증분 판정 캐시(인덱스)라 매 실행마다
> 갱신한다. 규칙과 형식은 위 「선별 형식」 절 참고(티켓 20260921_2306).

- 매주·매월 **새 파일을 추가**한다. 기존 파일을 고쳐 쓰지 않는다.
- 분기 요약 후 `archive/`로 옮기지 않는다 — 요약본을 만들지 않는다는 공통 규칙과 충돌한다.
  오래된 리포트도 계속 이 폴더에 남는다.

## 읽기 상한

에이전트가 다음 리포트를 작성하거나 회고할 때 과거 기록을 참고하더라도, 기본으로는
**주간 최근 4주 · 월간 최근 3개월**만 읽는다. 그보다 오래된 기록이 필요하면 그때 찾아 읽는다.

## 현황판과의 관계

`DASHBOARD.md` 같은 저장 파일은 두지 않는다. 티켓 진행 현황판은 세션 시작 hook
(`scripts/ticket-dashboard.mjs`)이 매번 즉석 생성해 보여준다. 자세한 계약은
`.claude/skills/jam-work/references/dashboard-format.md` 참고.
