# 트라이브, 출신, 레벨

> **구상 단계 정책이다.** 사용자가 2026-10-08에 확인했다. 서비스, DB, 티켓에 반영하지 않았고, 에이전트는 이 문서를
> 현재 서비스 사실의 근거로 쓰지 않는다.
> 확인 상태는 [서비스 재설계 정책](README.md) 2절에 있다. 근거는 [서비스 재설계 진행 노트](<../09 JAM! 서비스 재설계 진행 노트.md>)
> 4.1절의 결정, 6절 주제 4의 답, 다른 주제에서 받은 관련 답(5-4, 7-1, 7-2, 10-1, 13-2, 13-5), 그리고 2026-10-08에 이 초안에 받은
> 사용자 확인이다.
> 괄호 안의 번호는 진행 노트 6절의 질문 번호다. 용어는 [공통 용어](<01 공통 용어.md>) 정책을 따른다.
> 주제 이름의 '출신'은 '트라이브'로, '레벨'은 '챕터'로 읽는다(공통 용어 2절).

## 1. 원칙

1. 트라이브는 유저가 JAM에서 쓰는 정체성이다. 한 번 고르면 유저가 바꿀 수 없다(4-1).
2. 트라이브는 유저가 받는 아이템 배지의 출처와 챕터의 이야기를 정한다. 기능의 이름이나 규칙은 트라이브마다 달라지지 않는다
   (진행 노트 3절의 기본 원칙).
3. 트라이브가 바뀌어도 유저가 이미 가진 것과 지나온 기록은 잃지 않는다(4-1).
4. 트라이브의 서사와 인물, 장소는 [트라이브 재구상](<../tribe-rethink/README.md>)이 원본이다. 이 문서는 기능 규칙만 다룬다.

## 2. 트라이브를 고르는 시점과 화면

- 트라이브는 다섯 개다. 각 트라이브의 내용은 트라이브 재구상 문서를 따른다.
- 유저는 가입할 때 온보딩에서 트라이브를 고른다. 정식 오픈 때는 모든 유저가 트라이브를 골라야 한다(7-2).
- 트라이브 고르기는 건너뛸 수 없다(사용자 확인). 트라이브를 고르지 않으면 온보딩이 끝나지 않고, Strava 연결과 동기화도 할 수 없다.
  동기화로 받는 아이템 배지가 모두 소속 트라이브의 것이라, 트라이브가 없으면 줄 아이템 배지를 정할 수 없기 때문이다.
- 고르는 화면에는 아래를 보여 준다(13-2). 화면의 자세한 구성은 실제 기획과 개발 때 정한다.
  - 트라이브마다 대주제와 짧은 한 줄
  - 고른 뒤에는 바꿀 수 없다는 안내
  - 동기화로 받는 아이템 배지가 고른 트라이브의 것이라는 안내

## 3. 트라이브가 유저에게 주는 것

| 무엇 | 규칙 | 근거 |
|---|---|---|
| 동기화로 받는 아이템 배지 | 모두 소속 트라이브 컬렉션의 아이템 배지다 | 7-1 |
| 틴케이스 | 유저마다 하나이고, 다른 트라이브의 틴케이스는 없다. 틴케이스를 열면 소속 트라이브와 다른 트라이브의 아이템 배지가 일정 확률로 나온다 | 4-3, 5-4, 공통 용어 3.1절 |
| 챕터의 이름 | 챕터마다 트라이브 서사를 담은 이름을 붙일 수 있다 | 1-5, 공통 용어 3.3절 |
| 트라이브 미션 | 미션은 누구나 참가할 수 있지만, 운영자가 미션을 만들 때 참가할 수 있는 트라이브를 제한할 수 있다 | 10-1 |
| 프로필 표시 | 내 프로필과 다른 유저가 보는 프로필 모두에 트라이브와 챕터를 함께 보여 준다. 챕터의 이름에 트라이브 서사가 담길 수 있어서 함께 보여야 뜻이 통한다 | 사용자 확인 |

- 액티비티 배지와 체크인 배지는 소속 트라이브와 상관없이 모두가 같은 배지를 받는다. 배지의 이름과 설명에 쓰는 트라이브 서사는
  조건에 어울리는 트라이브에서 가져오고, 유저의 소속과는 관계없다(9-2).
- 다른 트라이브의 아이템 배지는 드랍과 픽업, 미션, 서비스 프로모션, 틴케이스 보상으로 얻는다(진행 노트 4.1절, 5-4).

## 4. 트라이브를 바꾸는 경우

- 유저는 화면에서 트라이브를 바꿀 수 없다(4-1).
- 어드민에서 유저를 조회해 트라이브를 바꿔 주는 기능을 만든다(4-1).
- 화면에는 "바꿀 수 없다"고만 안내하고, 따로 바꾸는 방법을 알리지 않는다. 유저가 문의하면 운영자가 사정을 보고 바꿔 준다(사용자 확인).
  바꾸는 방법을 알리면 "바꿀 수 없다"는 원칙이 흐려지기 때문이다.
- 바꿀 때는 누가, 언제, 어느 트라이브에서 어느 트라이브로, 왜 바꿨는지 기록을 남기고, 유저에게 알림을 보낸다(사용자 확인).
- 바꿀 때 유지하는 것과 달라지는 것은 다음과 같다.

| 유지하는 것 | 달라지는 것 |
|---|---|
| 이미 가진 모든 배지(옛 트라이브의 아이템 배지 포함), 컬렉션 진행, 서비스 이력(4-1) | 그 뒤로 동기화에서 받는 아이템 배지는 새 트라이브의 것이다 |
| 틴케이스에 채우다 만 에너지. 새 트라이브의 틴케이스로 그대로 옮긴다(13-5) | 틴케이스 보상에서 '소속 트라이브'의 기준이 새 트라이브가 된다 |
| 챕터. 챕터는 서비스 활동량으로 오르므로 트라이브와 상관없이 그대로다(4-2) | 챕터에 트라이브 서사를 담은 이름을 붙이면, 새 트라이브의 이름으로 바뀐다(주제 17) |
| 지금 가진 에너지 | 트라이브를 제한한 미션의 참가 자격. 이미 참가한 트라이브 제한 미션은 참가가 취소되고 순위에서도 빠진다(사용자 확인) |

## 5. 챕터(유저의 레벨)의 기본 규칙

- 챕터는 유저마다 하나이고, 서비스 활동량으로 오른다(4-2). 진행 노트 4.1절의 "트라이브마다 5등급"과 호칭 25개는 주제 17에서 다시 확인한다.
- 처음 가입한 유저에게는 챕터가 없다. 퀘스트(첫 챕터를 주는 온보딩 과제)를 마치면 첫 챕터를 받는다(4.1절, 4-6).
- 챕터는 내려가지 않는다(4-4).
- 승급 기준, 챕터 사이의 간격, 챕터의 수, 챕터마다 달라지는 것, 챕터의 이름은 주제 17에서 정한다(4-2, 4-5, 4-7, 1-5).
- 퀘스트의 구성은 주제 13에서 정한다(13-4).

## 6. 지금 서비스와 달라지는 곳

`jam-web/src/app/(main)/onboarding/page.tsx`, `jam-web/src/app/api/onboarding/complete/route.ts`, `jam-web/src/app/(main)/profile/`의
코드를 2026-10-08에 읽어 확인한 결과다. 실행해서 검증하지는 않았다. DB의 숫자는 진행 노트 1절(2026-10-07 DB 기준)을 따른다.

| 항목 | 지금 서비스 | 달라지는 점 |
|---|---|---|
| 트라이브 수 | DB에서 켜진 트라이브는 3개다. UX 라이팅 가이드라인의 고정 용어 설명은 "10개 가운데 하나"다 | 다섯 개로 바꾼다. 가이드라인의 설명은 5단계에서 고친다(공통 용어 4절) |
| 온보딩 | 아이디와 이름을 정하는 단계, 트라이브를 고르는 단계 두 단계다. 서비스에 들어갈 때 아이디만 확인해서, 트라이브를 고르지 않아도 서비스를 쓸 수 있다. 가입 유저 8명 가운데 트라이브를 고른 유저는 0명이다 | 트라이브 고르기를 건너뛸 수 없게 한다 |
| 트라이브 변경 | 한 번 고르면 API가 다시 저장하지 않는다. 어드민에서 바꾸는 기능은 없다 | 어드민에서 바꾸는 기능을 만든다 |
| 트라이브의 쓰임 | 소속 트라이브 값은 운영툴과 온보딩 말고는 쓰이지 않는다(진행 노트 4.1절). 프로필은 트라이브 이름을 받지만 화면에 보여 주지 않는다 | 3절의 쓰임이 생기고, 프로필에 트라이브와 챕터를 보여 준다 |
| 아이템 배지의 트라이브 | 드랍 엔진이 직전 트라이브, 이웃 트라이브, 탐험, 활동 맥락으로 트라이브를 고른다 | 소속 트라이브로 정한다. 처리는 주제 7 |

## 7. 다른 주제로 넘기는 것

- 챕터의 승급 기준, 간격, 수, 이름, 챕터마다 달라지는 것은 주제 17에서 정한다.
- 퀘스트의 구성과 첫 챕터를 주는 방법은 주제 13에서 정한다.
- 동기화로 받는 아이템 배지의 발급 규칙과 지금 드랍 엔진의 트라이브 고르기 규칙을 없애는 처리는 주제 7에서 정한다.
- 틴케이스 보상에서 소속과 비소속 아이템 배지의 비율은 주제 18에서 정한다.
- 트라이브 미션의 참가 제한을 만드는 화면과 조건값은 주제 10에서 정한다.
- 트라이브가 바뀌어 미션 참가가 취소될 때 유저에게 보여 줄 안내는 주제 10에서 정한다.
- 트라이브마다 컬렉션과 아이템 배지의 수량을 맞추는 일은 주제 19(게이미피케이션 밸런스)에서 정하고, 그 수량에 맞춘 컨텐츠는 주제 15에서 만든다.
