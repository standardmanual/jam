# 컬렉션, 믹스, 드랍과 픽업

> **JAM 2.0 기획 문서다.** 사용자가 2026-10-08에 확인했다. 서비스, DB, 티켓에 반영하지 않았고, 에이전트는 이 문서를
> 현재 서비스 사실의 근거로 쓰지 않는다.
> 확인 상태는 [서비스 재설계 정책](README.md) 2절에 있다. 근거는 [서비스 재설계 진행 노트](<../09 JAM! 서비스 재설계 진행 노트.md>)
> 4.1절, 4.2절, 4.3절의 결정, 6절 주제 8의 답, 다른 주제에서 받은 관련 답(6-1, 6-6, 8-6, 9-1), 확인된 정책
> ([잠긴 아이템 배지](<06 잠긴 아이템 배지.md>), [아이템 배지 발급](<07 아이템 배지 발급.md>)), 그리고 2026-10-08에 이 초안에 받은
> 사용자 확인이다. 괄호 안의 번호는 진행 노트 6절의 질문 번호다. 용어는 [공통 용어](<01 공통 용어.md>) 정책을 따른다.

## 1. 원칙

1. 컬렉션, 믹스, 드랍과 픽업은 지금의 개념과 이름을 그대로 쓴다(4.1절, 4.3절).
2. 다섯 트라이브의 컬렉션은 같은 수량으로 다시 만든다. 기존 컨텐츠도 활용한다(4.2절).
3. 다른 트라이브의 아이템 배지를 모을 이유를 만든다. 트라이브를 넘는 믹스 레시피를 두고(8-3), 시스템 드랍에 다른 트라이브의
   아이템 배지를 섞으며(8-4), 다른 트라이브의 컬렉션도 완성할 수 있게 한다(사용자 확인).
4. 잠긴 아이템 배지는 열기 전에는 컬렉션과 믹스에 쓸 수 없고, 드랍과 픽업은 할 수 있다([잠긴 아이템 배지](<06 잠긴 아이템 배지.md>) 3절).

## 2. 컬렉션

### 2.1 수량, 기존 컬렉션, 등급 구성

- 트라이브마다 컬렉션 몇 개, 컬렉션마다 아이템 배지 몇 종을 둘지는 기존 컬렉션을 먼저 배치하면서 정한다(8-1).
- 새 구조에 쓰지 않는 기존 컬렉션을 폐기할지, 다른 트라이브에 배정할지도 배치하면서 정한다(8-2). 없애는 특수 트라이브
  (미스터리 헌터, 작심삼일 클럽)의 컬렉션도 함께 정리한다([아이템 배지 발급](<07 아이템 배지 발급.md>) 3절).
- 컬렉션 안의 등급 구성(Common, Rare, Epic, Mystic을 몇 종씩 둘지)과 트라이브 사이에 등급 구성을 맞출지도 함께 정한다.
- 이 세 가지는 모두 주제 19(게이미피케이션 밸런스)에서 다룬다(사용자 확인). 지금까지의 배치는 자리 확정 40개, 자리 미정 24개,
  그대로는 쓰지 않음 15개, 어디에도 맞지 않음 21개다(진행 노트 4.2절).

### 2.2 보여 주는 컬렉션과 다른 트라이브의 컬렉션

- 지금 서비스처럼, 인벤토리에 가진 아이템 배지가 속한 컬렉션만 보여 준다(사용자 확인). 아이템 배지를 하나도 가지지 않은
  컬렉션은 보이지 않는다.
- 잠긴 아이템 배지는 열기 전에 컬렉션을 가리므로([잠긴 아이템 배지](<06 잠긴 아이템 배지.md>) 4절), 컬렉션을 보여 주는 기준에서 뺀다.
  열린 아이템 배지가 속한 컬렉션만 보여 준다.
- 트라이브로 컬렉션을 나누지 않는다. 다른 트라이브의 아이템 배지를 가지면 그 컬렉션도 보이고, 꽂아서 완성할 수 있다(사용자 확인).

### 2.3 장착과 완성

- 잠긴 아이템 배지는 컬렉션 칸에 꽂을 수 없고, 컬렉션 화면에 보이지 않으며, 완성으로 치지 않는다(6-1).
- 같은 이름의 아이템 배지가 Common, Rare, Epic, Mystic 4개로 있다. 유저가 컬렉션에 처음 꽂은 등급이 그 유저에게 그 컬렉션의 등급이 되고,
  그 뒤로는 같은 등급만 꽂을 수 있다(예: Epic을 처음 꽂으면 그 뒤로 Epic만). 지금 코드에는 이 구조가 없어 새로 만든다(주제 19, 사용자 확인).
- 꽂은 아이템 배지를 모두 빼면 등급이 풀려 다른 등급으로 다시 시작할 수 있다. 완성은 등급마다 따로 기록하고, 완성 보상은 등급마다 한 번씩
  받으며 높은 등급일수록 크다(주제 19, 사용자 확인). 보상의 크기는 주제 19의 포인트 묶음에서 정한다.
- 아래 규칙은 지금 서비스대로 둔다(사용자 확인).
  - 장착하면 인벤토리 칸이 빈다. 인벤토리가 가득 차 있으면 장착을 풀 수 없다.
  - 장착한 아이템 배지는 드랍과 믹스에 쓸 수 없다. 같은 이름의 아이템 배지는 컬렉션마다 하나만 꽂는다.
  - 장착을 풀어도 완성 기록은 남는다.
  - 공개 기간이 끝난 컬렉션에도 가진 아이템 배지를 꽂아 완성할 수 있다. 공개 기간이 끝나도 유저가 가진 것은 그대로 가지기 때문이다
    ([아이템 배지 발급](<07 아이템 배지 발급.md>) 7절).

## 3. 믹스

- 등급을 올리는 레시피를 둔다. 같은 트라이브의 아래 등급 아이템 배지 5개(어느 컬렉션의 것이든)를 넣으면, 유저가 고른 컬렉션과 이름의
  바로 위 등급 아이템 배지 1개가 나온다(주제 19, 사용자 확인). 믹스 칸이 5칸이므로 레시피의 재료는 최대 5개다(사용자 결정, 2026-10-09).
- 믹스 칸은 최대 5칸이다. 레시피에는 이름, 설명, 보상이 있고, 보상은 재료와 같은 등급, 상위 등급, 또는 없음 가운데 레시피마다 정한다(사용자 결정, 2026-10-09).
- 트라이브를 넘는 믹스 레시피를 둔다(8-3). 트라이브 사이에 겹치는 단서(예: 같은 숫자 번호표와 은박지 꼬치)를 재료로 쓰면
  다른 트라이브의 아이템 배지를 모을 이유가 된다.
- 아래 규칙은 지금 서비스대로 둔다(사용자 확인).
  - 정해진 레시피대로 확률 없이 결과가 나온다.
  - 재료가 레시피에 맞지 않으면 재료는 서비스에서 삭제되고 포인트 10을 준다(사용자 확인, 2026-10-09).
  - 믹스 횟수에 상한이 없다. 공개된 레시피는 재료와 결과를 모두 보여 준다.
- 잠긴 아이템 배지는 열기 전에는 믹스 재료로 쓸 수 없다(6-1).
- 운영자가 레시피를 만들 때 결과의 잠김 여부를 함께 정한다. 기본은 열림이다. 잠김으로 만든 아이템 배지는 늘 잠긴 채로 나온다.
  믹스는 무작위로 고르는 경로가 아니므로 무작위로 잠기지 않는다(사용자 확인).
- 믹스 결과가 들어갈 빈칸이 모자라면 결과를 받지 않은 상태로 두고, 받기 전에는 새 믹스를 할 수 없다(아이템 배지 발급 6절).
- 믹스 결과에는 기한을 두지 않는다. 아이템 배지의 기본은 기한 없음이다(6-8).
- 결과 아이템 배지의 공개 기간이 끝난 레시피는 믹스 화면에서 내려 더 쓸 수 없게 한다(사용자 확인). 믹스 결과도 새 발급이라
  공개 기간이 끝나면 나올 수 없는데(아이템 배지 발급 7절), 실패해도 재료가 소모되므로 남겨 두면 유저가 재료만 잃는다.
  재료로 쓰는 아이템 배지는 공개 기간과 상관없이, 가진 것이면 쓸 수 있다.
- 트라이브 안의 일반 레시피는 만들지 않고, 컨텐츠 레시피는 트라이브 재구상 README 3절의 단서 20개에 하나씩 단서 레시피로 만든다
  ([트라이브 컨텐츠 제작](<15 트라이브 컨텐츠 제작.md>) 4절).
- 트라이브를 넘는 믹스 레시피를 성공한 횟수는 액티비티 배지의 조건으로 쓴다(9-1).

## 4. 드랍과 픽업

- 지금의 개념과 이름을 그대로 쓴다(4.1절). 다른 트라이브의 아이템 배지를 주고받는 가장 자연스러운 경로다(4.1절, 8-4).
- 아래 규칙은 지금 서비스대로 둔다(사용자 확인).
  - 지점 500m 안에서 드랍하고 픽업한다. 하루 상한이 없다.
  - 드랍은 사라지지 않는다. 자기가 드랍한 것도 픽업할 수 있다. 다만 자기가 드랍한 것을 주운 것은 챕터 점수와 드랍·픽업 횟수(액티비티 배지의
    JAM 조건)에 세지 않는다(주제 19 점검 G4, 사용자 확인). 드랍과 픽업을 되풀이해 점수와 배지를 쌓는 일을 막는다.
  - 반경 안 지점의 드랍 목록에서 아이템 배지의 이름과 그림을 보고 픽업한다. 잠긴 아이템 배지는 빼고 보여 준다(아래).
  - 트라이브로 드랍과 픽업을 막지 않는다.
- 잠긴 아이템 배지도 잠긴 채로 드랍하고 픽업한다(6-6). 지도와 지점의 드랍 목록에서는 무엇인지 보이지 않고 '잠김'으로 보인다(8-6).
  열기 전에 보여 주는 것과 가리는 것은 [잠긴 아이템 배지](<06 잠긴 아이템 배지.md>) 4절을 따른다.
- 채우다 만 잠긴 아이템 배지를 드랍하면 채운 양은 사라진다(잠긴 아이템 배지 8절).
- 일련번호는 드랍과 픽업을 거쳐도 그대로이고, 트라이브 접두어는 쓰지 않는다(8-5, 아이템 배지 발급 5절).
- 공개 기간이 끝난 아이템 배지도 유저가 가진 것은 드랍할 수 있고, 다른 유저가 픽업할 수 있다(아이템 배지 발급 7절).
- 인벤토리가 가득 차 있으면 픽업하려 할 때 안내를 보여 주고 픽업하지 않는다(아이템 배지 발급 6절).
- 잠긴 아이템 배지를 픽업한 횟수는 액티비티 배지의 조건으로 쓴다(9-1).

### 4.1 시스템 드랍

- 시스템이 지점에 놓는 드랍에 다른 트라이브의 아이템 배지를 섞는다(8-4). 트라이브별 비율을 따로 두지 않고, 지금처럼 공개 중인
  컬렉션 가운데서 고른다(사용자 확인). 지점에 놓인 드랍은 누가 픽업할지 모르므로 유저마다 다르게 맞출 수 없다.
  다섯 트라이브의 컬렉션 수가 같으면 다섯 트라이브가 고르게 섞인다.
- 행사 때는 지금처럼 운영자가 컬렉션을 지정해서 놓는다(사용자 확인).
- 잠김으로 만든 아이템 배지만 잠긴 채로 놓인다(잠긴 아이템 배지 2절).
- 공개 기간이 끝난 아이템 배지는 놓지 않는다(아이템 배지 발급 7절).
- 시스템 드랍의 등급 비율은 주제 19(게이미피케이션 밸런스)에서 정한다.

## 5. 기록

- 컬렉션 장착과 완성, 믹스 시도와 결과, 드랍과 픽업은 지금처럼 기록한다. 아이템 배지 개체가 거쳐 간 이력(장착, 드랍, 픽업, 소모)도
  지금처럼 남긴다.
- 받지 않은 상태로 기다리는 믹스 결과는 생긴 때와 받은 때를 기록한다(아이템 배지 발급 8절).

## 6. 다른 주제로 넘기는 것

- 트라이브별 컬렉션 수와 컬렉션당 아이템 배지 수, 기존 컬렉션의 배치, 쓰지 않는 기존 컬렉션과 특수 트라이브 컬렉션의 정리,
  컬렉션 안의 등급 구성, 시스템 드랍의 등급 비율은 주제 19(게이미피케이션 밸런스)에서 정한다.
- 정해진 수량에 맞춰 컬렉션, 아이템 배지, 믹스 레시피의 내용(이름, 설명, 서사)을 만드는 일은 주제 15(트라이브 컨텐츠 제작)에서 한다.
- 7절의 "완성 판정" 행(장착할 때와 동기화 때 판정이 다르다)은 지금 서비스의 문제라서, 3단계(현재 서비스와 비교)에서 다룬다.

## 7. 지금 서비스와 달라지는 곳

2026-10-08에 코드와 마이그레이션으로 확인했다. 지금 DB에 있는 컬렉션과 레시피의 실제 수는 3단계에서 확인한다.

| 항목 | 지금 서비스 | 달라지는 점 |
|---|---|---|
| 컬렉션 수 | 시드는 트라이브 10개에 10개씩, 모두 100개를 넣고, 컬렉션마다 아이템 배지 9종, 모두 900종이다(`019_seed_worldview.sql`). 컬렉션당 아이템 배지 수는 코드에서 검사하지 않는다 | 다섯 트라이브에 같은 수량으로 다시 만든다(주제 19, 주제 15) |
| 보여 주는 컬렉션 | 인벤토리에 가진 아이템 배지가 속한 컬렉션만 보여 준다(`jam-web/src/app/(main)/badges/page.tsx`) | 잠긴 아이템 배지는 기준에서 뺀다(2.2절) |
| 컬렉션과 트라이브 | 컬렉션에 트라이브 칸이 있다. 장착할 때 트라이브를 보지 않는다 | 바뀌지 않는다(2.2절) |
| 장착 | 장착하면 인벤토리 칸이 빈다. 인벤토리가 가득 차 있으면 장착을 풀 수 없다. 장착한 것은 드랍과 믹스에 쓸 수 없다. 같은 아이템 배지는 컬렉션마다 하나만 꽂는다 | 잠긴 아이템 배지는 꽂을 수 없다(2.3절) |
| 완성 | 처음 완성할 때만 포인트와 보상 배지를 준다. 장착을 풀어도 완성 기록은 남는다. 컬렉션에 등급이 없고, 장착할 때 등급을 보지 않는다(마이그레이션 058에서 컬렉션 등급 칸을 지웠다) | 처음 꽂은 등급이 컬렉션 등급이 되고, 완성과 보상을 등급마다 따로 둔다(2.3절) |
| 아이템 배지의 등급 짝 | Common만 있다. 마이그레이션 055에서 등급 짝을 만들었다가 094에서 Common이 아닌 것을 모두 지웠다 | 같은 이름마다 4등급 짝을 둔다(2.3절) |
| 완성 판정 | 장착할 때의 판정과 동기화 때의 보정 판정이 다르다. 체크인 배지가 섞인 컬렉션은 장착만으로는 완성되지 않고, 공개 기간이 끝난 컬렉션은 장착으로는 완성되지만 보정 판정에서는 빠진다(`179_…sql`, `jam-web/src/lib/itembook/checker.ts`) | 3단계에서 다룬다(6절) |
| 믹스 레시피 | 정해진 재료(슬롯마다 후보 아이템 배지)가 맞으면 확률 없이 결과를 모두 준다. 맞지 않으면 재료를 소모하고 포인트 10을 준다. 재료는 성공과 실패에 상관없이 소모된다. 횟수 상한은 없다(`jam-web/src/lib/combine/`) | 트라이브를 넘는 레시피를 둔다(3절) |
| 트라이브를 넘는 레시피 | 엔진에 트라이브 참조가 없다. 레시피 시드(`seed_combine_recipes_r1_r3.sql`)는 한 트라이브의 재료만 쓰는 레시피 3건이고, 두 트라이브를 섞는 레시피는 보류되어 있다 | 둔다(8-3) |
| 믹스 결과의 잠김 | 잠금 개념이 없다 | 레시피를 만들 때 정한다(3절) |
| 공개 기간이 끝난 결과의 레시피 | 레시피 자체의 공개 기간만 본다 | 결과 아이템 배지의 공개 기간이 끝나면 레시피를 내린다(3절) |
| 믹스 결과의 기한 | 받은 날부터 30일이다 | 기한 없음(3절) |
| 믹스 결과 중 인벤토리 가득 참 | 결과를 조용히 건너뛴다 | 받지 않은 상태로 두고, 받기 전에는 새 믹스를 할 수 없다(3절) |
| 지점의 드랍 목록 | 반경 안 지점의 드랍 목록에서 아이템 배지의 이름, 그림, 일련번호를 픽업 전에 보여 준다(`jam-web/src/components/PoiCarouselModal.tsx`, `jam-web/src/app/api/drops/poi/[poiId]/route.ts`) | 잠긴 아이템 배지는 가린다(4절) |
| 드랍과 픽업의 트라이브 | 드랍, 픽업, 시스템 드랍 어디에도 트라이브를 보는 규칙이 없고, 지점에도 트라이브 칸이 없다 | 바뀌지 않는다 |
| 시스템 드랍 | 컬렉션을 무작위(공개 중이고 드랍 제외가 아닌 것 가운데 하나), 지정, 전체 가운데 하나로 고른다. 등급은 기본 Common 100%다. 지점마다 기본 1개, 한 번에 기본 30개를 놓고, 사라지지 않는다(`jam-web/src/lib/ambient-drop/`) | 섞는 방법은 바뀌지 않는다(4.1절). 등급 비율은 주제 19 |
