# 트라이브 컨텐츠 제작

> **JAM 2.0 기획 문서다.** 사용자가 2026-10-08에 확인했다. 서비스, DB, 티켓에 반영하지 않았고, 에이전트는 이 문서를
> 현재 서비스 사실의 근거로 쓰지 않는다.
> 확인 상태는 [서비스 재설계 정책](README.md) 2절에 있다. 근거는 [서비스 재설계 진행 노트](<../09 JAM! 서비스 재설계 진행 노트.md>)
> 6절 주제 15의 답(15-1~15-6), 다른 주제에서 주제 15로 넘긴 일, 확인된 정책, 그리고 2026-10-08에 이 초안에 받은 사용자 답이다.
> 괄호 안의 번호는 진행 노트 6절의 질문 번호다. 용어는 [공통 용어](<01 공통 용어.md>) 정책을 따른다.

## 1. 원칙

1. 이 주제는 컨텐츠를 **만드는 방법**을 정한다. 수량과 수치는 [게이미피케이션 밸런스](<19 게이미피케이션 밸런스.md>)가 정했고,
   이 주제는 그 수량에 맞춰 이름, 설명, 서사를 채운다.
2. 트라이브 서사의 원본은 [트라이브 재구상](<../tribe-rethink/README.md>) 폴더의 다섯 초안이다. 컨텐츠는 그 초안의 인물, 장소, 사물에서
   가져오고, 초안에 없는 설정을 컨텐츠에서 새로 만들지 않는다. 새 설정이 필요하면 트라이브 초안을 먼저 고친다.
3. 트라이브 재구상 README 4절의 작성 규칙 11가지를 모든 컨텐츠에 적용한다. 금지 소재 6가지는 그 가운데 11번이다(15-6, 14-1).
4. 컬렉션 이름에 들어간 날씨와 시간대(예: 「비 오는 날의 기름 냄새」)는 이야기일 뿐, 아이템 배지를 얻는 조건이 아니다(3-1,
   [배지 획득 조건](<03 배지 획득 조건.md>)).
5. 이 주제는 디자인을 정하지 않는다(사용자 확인). 모든 컨텐츠는 빈 이미지로 만들고, 이미지와 등급의 시각 표현은 이미지를 따로 만들 때 정한다(15-2).

## 2. 만들 것

| 무엇 | 수량 | 근거 |
|---|---|---|
| 컬렉션 | 트라이브마다 10개, 모두 50개 | 19-D1 |
| 아이템 배지 | 컬렉션마다 9종(이름), 모두 450종. 이름마다 Common, Rare, Epic, Mystic 4등급이 있고, 설명은 등급마다 따로 써서 1,800개다(3절) | 19-D1, 19-D2, 사용자 확인 |
| 단서 레시피 | 트라이브 재구상 README 3절의 단서 20개에 하나씩, 20개(4절) | 사용자 확인 |
| 액티비티 배지 | 여덟 가지(리듬, 회복, 시간과 계절, 날씨, 탐험, 운동 속성, 이정표, JAM 활동)에 계열 5~8개씩, 모두 50~60개 계열 | 19-E4 |
| 운동 속성 구간 이름 | 속성마다 구간 이름(예: 가볍게, 넉넉히, 멀리, 아주 멀리). 구간의 수와 경계값은 이미 정했다 | 배지 획득 조건 3절 |

- 체크인 배지는 지점 이름을 그대로 쓰므로 새로 짓지 않는다([액티비티 배지와 체크인 배지](<09 액티비티 배지와 체크인 배지.md>) 4절).
- 미션은 운영자가 수시로 열므로 여기서 미리 만들지 않는다. 미션을 만들 때 같은 방식(7절)으로 이름과 설명을 쓴다([미션](<10 미션.md>) 2절).
- 액티비티 배지의 기준값은 [게이미피케이션 밸런스](<19 게이미피케이션 밸런스.md>) 6절의 규칙으로 배지를 만들 때 정한다(19-E3).
- 등급을 올리는 레시피는 규칙 하나로 모든 컬렉션에 적용되므로 컨텐츠를 따로 쓰지 않는다(19-D5).

## 3. 아이템 배지의 등급 짝

같은 이름의 아이템 배지가 Common, Rare, Epic, Mystic 4개로 있다(19-D2). 등급마다 쓰는 것은 다음과 같다(사용자 확인).

| 항목 | 쓰는 방식 |
|---|---|
| 이름 | 4등급 모두 같다 |
| 설명 | 등급에 맞춰 따로 쓰되, 네 설명이 하나의 짧은 이야기로 이어지고 등급이 오를수록 트라이브 서사 속으로 나아가게 쓴다. Common은 우연히 손에 들어온 물건, Rare는 트라이브 서사의 과거(인물, 장소, 상황)와 겹치는 물건, Epic은 앞으로 나에게 쓰일 물건, Mystic은 트라이브 서사의 중요한 기점이 된 물건이다. 막연한 정황이나 느낌만 쓰지 않는다(사용자 확인). 쓰는 규칙은 [트라이브 보이스](<트라이브 보이스.md>) 3절이다 |
| 조건 표기 | 화면에 표기하지 않는다. 아이템 배지는 값 조건 없이 무작위로 얻기 때문이다. 아이템 배지 상세에는 설명, 일련번호, 획득 이력만 보여 준다(사용자 확인) |

- 디자인(이미지, 등급을 구분하는 시각 표현)은 이 주제에서 정하지 않는다(사용자 확인).

## 4. 믹스 레시피

- 트라이브 안의 일반 레시피는 만들지 않는다(사용자 확인). 등급을 올리는 레시피가 유저에게 이름을 고르게 하고 등급까지 올려 주므로,
  정해 둔 아이템 배지를 주는 일반 레시피는 줄 수 있는 것이 거의 없기 때문이다.
- 컨텐츠 레시피는 트라이브를 넘는 **단서 레시피**로 만든다(사용자 확인). 트라이브 재구상 README 3절의 단서 하나에 레시피 하나다.
  - 재료는 출발 트라이브의 아이템 배지 5개(같은 등급)이고, 결과는 도착 트라이브의 정해 둔 아이템 배지 1개(재료와 같은 등급)다.
  - 재료와 결과의 컬렉션이 모두 열렸을 때 레시피를 연다.
  - 다른 트라이브의 아이템 배지를 얻는 다른 경로(캡슐, 드랍과 픽업, 미션)는 모두 무작위라서, 원하는 것을 골라 얻는 길은 단서 레시피뿐이다.
- 19-D4의 "트라이브를 넘는 레시피는 3분의 1쯤"은 일반 레시피를 전제로 한 비율이라 쓰지 않는다. 시드에 있는 지금 레시피 3건도 쓰지 않는다.
- 레시피의 성공 포인트는 레시피를 만들 때 사용자가 정한다(19-F3).

## 5. 만드는 순서

| 순서 | 할 일 | 근거 |
|---|---|---|
| 1 | 실존 이름과 겹치는 이름 3개(라스트오더, 동백역과 동백시장, 송하윤)를 바꾼다. 트라이브 초안과 README 3절 단서 표를 함께 고친다 | 15-3 |
| 2 | 남은 보강 2건을 마친다. 소나무 잡화점에 교환을 둘러싼 작은 갈등 하나를 더하고, 한입만 연구회의 인물 9명을 정리한다. 동네 약도는 만들지 않고, 장소의 거리감은 각 문서를 손볼 때 맞춘다 | 15-4 |
| 3 | 트라이브 보이스 카드 5장을 쓴다([트라이브 보이스](<트라이브 보이스.md>) 5절). 찰칵단은 윈터가 초안에서 대표 문장 3개를 후보로 뽑고 사용자가 고른 뒤에 쓴다 | 사용자 확인 |
| 4 | 컬렉션 50개의 자리를 모두 정한다(6절). 컬렉션 이름과 한 줄 서사까지 정한다 | 15-1, 19-D3 |
| 5 | 컬렉션 50개의 아이템 배지 이름과 등급별 설명을 쓴다. 같은 때에 챕터 이름 50개와 온보딩 완료 배지 이름을 쓴다 | 사용자 확인, 17-4 |
| 6 | 액티비티 배지 50~60개 계열과 운동 속성 구간 이름을 쓴다 | 19-E4 |
| 7 | 단서 레시피 20개를 쓴다 | 4절 |

- 1과 2는 컨텐츠를 쓰기 전에 마친다(15-3, 15-4). 트라이브 이름의 상표 확인은 외부 홍보 전에 특허청 상표 검색으로 한다(15-3).
- 15-1의 "모자란 트라이브부터 새로 만든다"는 순서 4에 적용한다. 새로 만든 컬렉션은 음악 4개와 내향인 2개다(6절).
- 컬렉션 50개를 모두 먼저 만든다. 정식 오픈 때 트라이브마다 열 3개와 그 뒤 석 달마다 더할 컬렉션의 순서는 사용자가 어드민에서 직접 고른다(사용자 확인, 19-D1).

## 6. 기존 컬렉션의 배치와 손질

- 자리 확정 40개(미식 9, 사진 9, 음악 6, 물건 덕후 9, 내향인 7)를 먼저 쓰고, 트라이브마다 10개가 되게 자리 미정 24개에서 손질해 채운다(19-D3).
  채울 자리는 미식 1, 사진 1, 물건 덕후 1, 내향인 3이고, 자리 미정이 없는 음악은 4개를 새로 만든다.
  내향인은 자리 미정 5개 가운데 맞는 것이 1개뿐이라 2개(진봉수, 변지원)를 새로 만들었다(2026-10-08 사용자 확인). 자리와 이름은 [트라이브 재구상](<../tribe-rethink/README.md>) 7절의 원고에 있다.
- 컬렉션 이름은 트라이브 초안 7절에 적힌 연결에 맞지 않을 때만 고친다. 아이템 배지는 이름을 되도록 살리고, 설명은 새 서사로 다시 쓴다(사용자 확인).
  기존 이름을 살리면 기존 유저가 가진 아이템 배지와 이어진다.
- 쓰지 않는 컬렉션(그대로는 쓰지 않음 15개, 어디에도 맞지 않음 21개, 남는 자리 미정, 특수 트라이브 컬렉션)은 지우지 않고 어드민에서
  비활성화한다([온보딩과 기존 유저·데이터](<13 온보딩과 기존 유저·데이터.md>) 5절). 혼자들의 실내 운동 소재 컬렉션 두 개는 쓰지 않는다(진행 노트 4.2절).

## 7. 쓰는 사람과 검수

- 윈터가 트라이브 서사로 초안을 쓰고, 사용자가 확정한다(15-5). 액티비티 배지, 아이템 배지, 컬렉션, 단서 레시피, 챕터 이름, 미션 모두 같다.
- 서사 문구의 말투와 쓰는 규칙은 [트라이브 보이스](<트라이브 보이스.md>)를 따르고, 화면 문구는 [UX 라이팅 재정비](<UX 라이팅 재정비.md>)를 따른다.
- 윈터는 초안을 쓸 때 금지 소재 6가지와 작성 규칙을 함께 검수하고, 검수 결과를 초안 옆에 적는다(15-5, 14-1).
- 액티비티 배지는 유저의 소속과 상관없이 조건에 어울리는 트라이브의 서사를 쓰고, 같은 계열에는 같은 트라이브의 서사를 쓴다(9-2).
  한 트라이브가 전체 계열의 30%를 넘지 않게 한다(사용자 확인). 날씨, 밤, 기록 같은 조건이 사진이나 혼자들 쪽으로 몰리지 않게 하려는 것이다.
- 배지 획득 조건은 설명과 따로, 명확한 값으로 적는다(예: "멀리(걷기 10km 이상)")(9-2). 표기 규칙은 UX 라이팅 가이드라인 3.1절이다.

## 8. 원고를 두는 자리와 확인 방식

- 이 정책을 확인한 뒤, 5절 순서 1~7을 3단계(현재 서비스와 비교)와 나란히 구상 문서로 쓴다(사용자 확인).
- 원고는 트라이브 재구상 폴더 안의 `manuscript` 폴더에 트라이브마다 원고 파일 하나(예: [미식 원고](<../tribe-rethink/manuscript/01 미식.md>))로 두고,
  액티비티 배지처럼 트라이브를 넘는 것은 공통 원고 파일 하나에 둔다(사용자 확인). 폴더 이름은 저장소 규칙(영문 소문자)을 따른다.
- DB와 ITEMBOOKS.xlsx에 옮기는 일은 5단계(티켓)에서 한다.
- 원고는 트라이브 하나씩 묶어서 사용자에게 보여 주고 확인을 받는다(사용자 확인).

## 9. 다른 주제로 넘기는 것

- 쓰지 않는 기존 컬렉션과, 기존 유저가 가진 기존 아이템 배지를 데이터에서 어떻게 옮길지는 3단계(현재 서비스와 비교)에서 본다.
- 새 트라이브의 금지 소재를 TRIBES.md에 넣는 일은 새 트라이브를 서비스에 반영할 때(5단계) 한다(15-6).
- 에너지의 정식 이름은 트라이브 컨텐츠가 아니라 기능 이름이라서, [공통 용어](<01 공통 용어.md>) 3.4절대로 4단계 전에 정한다.

## 10. 지금 서비스와 달라지는 곳

수치는 [컬렉션, 믹스, 드랍과 픽업](<08 컬렉션, 믹스, 드랍과 픽업.md>)의 「지금 서비스와 달라지는 곳」에서 옮겼다.
