# 트라이브 컨텐츠 제작

> **구상 단계 정책 초안이다.** 사용자 확인 전이다. 서비스, DB, 티켓에 반영하지 않았고, 에이전트는 이 문서를
> 현재 서비스 사실의 근거로 쓰지 않는다.
> 확인 상태는 [서비스 재설계 정책](README.md) 2절에 있다. 근거는 [서비스 재설계 진행 노트](<../09 JAM! 서비스 재설계 진행 노트.md>)
> 6절 주제 15의 답(15-1~15-6), 다른 주제에서 주제 15로 넘긴 일, 그리고 확인된 정책이다.
> 괄호 안의 번호는 진행 노트 6절의 질문 번호다. 용어는 [공통 용어](<01 공통 용어.md>) 정책을 따른다.

## 1. 원칙

1. 이 주제는 컨텐츠를 **만드는 방법**을 정한다. 수량과 수치는 [게이미피케이션 밸런스](<19 게이미피케이션 밸런스.md>)가 정했고,
   이 주제는 그 수량에 맞춰 이름, 설명, 서사를 채운다.
2. 트라이브 서사의 원본은 [트라이브 재구상](<../tribe-rethink/README.md>) 폴더의 다섯 초안이다. 컨텐츠는 그 초안의 인물, 장소, 사물에서
   가져오고, 초안에 없는 설정을 컨텐츠에서 새로 만들지 않는다. 새 설정이 필요하면 트라이브 초안을 먼저 고친다.
3. 트라이브 재구상 README 4절의 작성 규칙 11가지를 모든 컨텐츠에 적용한다. 금지 소재 6가지는 그 가운데 11번이다(15-6, 14-1).
4. 컬렉션 이름에 들어간 날씨와 시간대(예: 「비 오는 날의 기름 냄새」)는 이야기일 뿐, 아이템 배지를 얻는 조건이 아니다(3-1,
   [배지 획득 조건](<03 배지 획득 조건.md>)).
5. 이미지는 지금 만들지 않는다. 모든 컨텐츠는 빈 이미지로 만들고, 그림체와 팔레트와 프레임은 이미지를 따로 만들 때 정한다(15-2).

## 2. 만들 것

| 무엇 | 수량 | 근거 |
|---|---|---|
| 컬렉션 | 트라이브마다 10개, 모두 50개. 정식 오픈 때 트라이브마다 3개를 열고 석 달마다 1개씩 더한다 | 19-D1 |
| 아이템 배지 | 컬렉션마다 9종(이름), 모두 450종. 이름마다 Common, Rare, Epic, Mystic 4등급 짝이 있어 개체 종류는 1,800개다 | 19-D1, 19-D2 |
| 믹스 레시피 | 등급을 올리는 레시피는 규칙 하나로 모든 컬렉션에 적용되므로 컨텐츠를 따로 쓰지 않는다. 그 밖의 레시피 수는 「확인할 것」 3번 | 19-D5, 8절 |
| 액티비티 배지 | 여덟 가지(리듬, 회복, 시간과 계절, 날씨, 탐험, 운동 속성, 이정표, JAM 활동)에 계열 5~8개씩, 모두 50~60개 계열 | 19-E4 |
| 운동 속성 구간 이름 | 속성마다 구간 이름(예: 가볍게, 넉넉히, 멀리, 아주 멀리). 구간의 수와 경계값은 이미 정했다 | 배지 획득 조건 3절 |
| 챕터 이름 | 트라이브마다 10개, 모두 50개 | 17-4 |
| 온보딩 완료 배지 이름 | 1개. 지금 이름 '퀘스트 클리어'를 바꾼다. 트라이브 서사 없이 JAM 공통 문구로 짓는다 | [온보딩과 기존 유저·데이터](<13 온보딩과 기존 유저·데이터.md>) 3절 |

- 체크인 배지는 지점 이름을 그대로 쓰므로 새로 짓지 않는다([액티비티 배지와 체크인 배지](<09 액티비티 배지와 체크인 배지.md>) 4절).
- 미션은 운영자가 수시로 열므로 여기서 미리 만들지 않는다. 미션을 만들 때 같은 방식(6절)으로 이름과 설명을 쓴다([미션](<10 미션.md>) 2절).
- 액티비티 배지의 기준값은 [게이미피케이션 밸런스](<19 게이미피케이션 밸런스.md>) 6절의 규칙으로 배지를 만들 때 정한다(19-E3).

## 3. 만드는 순서

| 순서 | 할 일 | 근거 |
|---|---|---|
| 1 | 실존 이름과 겹치는 이름 3개(라스트오더, 동백역과 동백시장, 송하윤)를 바꾼다. 트라이브 초안과 README 3절 단서 표를 함께 고친다 | 15-3 |
| 2 | 남은 보강 2건을 마친다. 소나무 잡화점에 교환을 둘러싼 작은 갈등 하나를 더하고, 한입만 연구회의 인물 9명을 정리한다. 동네 약도는 만들지 않고, 장소의 거리감은 각 문서를 손볼 때 맞춘다 | 15-4 |
| 3 | 컬렉션 50개의 자리를 모두 정한다(4절). 이 단계에서는 컬렉션 이름과 한 줄 서사까지만 정한다 | 15-1, 19-D3 |
| 4 | 정식 오픈 때 열 컬렉션 15개(트라이브마다 3개)의 아이템 배지 이름과 설명을 쓴다. 같은 때에 챕터 이름 50개, 온보딩 완료 배지 이름을 쓴다 | 19-D1, 17-4 |
| 5 | 액티비티 배지 50~60개 계열과 운동 속성 구간 이름을 쓴다 | 19-E4 |
| 6 | 정식 오픈 때 쓸 믹스 레시피를 쓴다 | 19-D4 |
| 7 | 나머지 컬렉션 35개는 공개하기 전에 차례로 쓴다 | 19-D1 |

- 1과 2는 컨텐츠를 쓰기 전에 마친다(15-3, 15-4). 트라이브 이름의 상표 확인은 외부 홍보 전에 특허청 상표 검색으로 한다(15-3).
- 15-1의 "모자란 트라이브부터 새로 만든다"는 순서 3에 적용한다. 새로 만들어야 하는 컬렉션은 음악 4개다(4절). 다만 음악은 자리를 확정한
  컬렉션이 6개라서 정식 오픈 세트(3개)는 기존 컬렉션으로 채울 수 있고, 새 컬렉션 4개는 일곱 번째 컬렉션을 열기 전까지 만들면 된다.

## 4. 기존 컬렉션의 배치

- 자리 확정 40개(미식 9, 사진 9, 음악 6, 물건 덕후 9, 내향인 7)를 먼저 쓰고, 트라이브마다 10개가 되게 자리 미정 24개에서 손질해 채운다(19-D3).
- 그래서 채울 자리는 미식 1, 사진 1, 물건 덕후 1, 내향인 3이고, 자리 미정이 없는 음악은 4개를 새로 만든다.
- 쓰지 않는 컬렉션(그대로는 쓰지 않음 15개, 어디에도 맞지 않음 21개, 남는 자리 미정, 특수 트라이브 컬렉션)은 지우지 않고 공개 기간을 끝내
  보관한다(19-D3). 혼자들의 실내 운동 소재 컬렉션 두 개는 쓰지 않는다(진행 노트 4.2절).
- 기존 컬렉션을 손질하는 범위는 「확인할 것」 2번이다.

## 5. 아이템 배지의 등급 짝

- 같은 이름의 아이템 배지가 Common, Rare, Epic, Mystic 4개로 있다(19-D2). 이름 짝마다 무엇을 다르게 쓸지는 「확인할 것」 1번이다.

## 6. 쓰는 사람과 검수

- 윈터가 트라이브 서사로 초안을 쓰고, 사용자가 확정한다(15-5). 액티비티 배지, 아이템 배지, 컬렉션, 믹스 레시피, 챕터 이름, 미션 모두 같다.
- 윈터는 초안을 쓸 때 금지 소재 6가지와 작성 규칙을 함께 검수하고, 검수 결과를 초안 옆에 적는다(15-5, 14-1).
- 액티비티 배지는 유저의 소속과 상관없이 조건에 어울리는 트라이브의 서사를 쓰고, 같은 계열에는 같은 트라이브의 서사를 쓴다(9-2).
- 배지 획득 조건은 설명과 따로, 명확한 값으로 적는다(예: "멀리(걷기 10km 이상)")(9-2).

## 7. 이미지

- 모든 컨텐츠는 빈 이미지로 만든다(15-2). 4등급 짝의 구분도 이미지를 만들 때 함께 정한다.
- 이미지를 만들 때는 기존 배지 이미지 제작 절차(`/jam-img`)를 쓰되, 트라이브별 그림체, 팔레트, 프레임을 먼저 정한다.

## 8. 다른 주제로 넘기는 것

- 쓰지 않는 기존 컬렉션과, 기존 유저가 가진 기존 아이템 배지를 데이터에서 어떻게 옮길지는 3단계(현재 서비스와 비교)에서 본다.
- 새 트라이브의 금지 소재를 TRIBES.md에 넣는 일은 새 트라이브를 서비스에 반영할 때(5단계) 한다(15-6).
- 에너지의 정식 이름은 트라이브 컨텐츠가 아니라 기능 이름이라서, [공통 용어](<01 공통 용어.md>) 3.4절대로 4단계 전에 정한다.

## 9. 지금 서비스와 달라지는 곳

수치는 [컬렉션, 믹스, 드랍과 픽업](<08 컬렉션, 믹스, 드랍과 픽업.md>)의 「지금 서비스와 달라지는 곳」에서 옮겼다.

| 항목 | 지금 서비스 | 달라지는 점 |
|---|---|---|
| 트라이브와 컬렉션 | 시드는 트라이브 10개에 컬렉션 10개씩, 모두 100개, 아이템 배지 900종이다 | 트라이브 5개에 컬렉션 10개씩, 아이템 배지 450종 × 4등급 |
| 아이템 배지의 등급 | 모두 Common이다 | 이름마다 4등급 짝 |
| 이미지 | 아이템 배지마다 이미지가 있다 | 새로 쓰는 컨텐츠는 빈 이미지로 시작한다 |
| 이름과 설명의 서사 | 옛 트라이브 10개의 설정을 쓴다 | 새 트라이브 다섯 초안의 서사를 쓴다 |

## 확인할 것

1. **같은 이름의 4등급 짝에서 무엇을 다르게 쓸까?**
   - 추천: 이름과 설명은 4등급 모두 같게 쓰고, 등급은 테두리와 등급 표시로만 구분한다.
   - 이유: 등급을 올리는 믹스가 "같은 이름의 위 등급"을 주므로, 유저에게는 같은 물건이 더 귀해지는 경험이어야 자연스럽다.
     설명을 등급마다 쓰면 쓸 양이 450개에서 1,800개로 늘어난다.
2. **기존 컬렉션을 얼마나 손질할까?**
   - 추천: 컬렉션 이름은 트라이브 초안 7절에 적힌 연결(예: 「비 오는 날의 기름 냄새」 → 비 오는 날 한소리의 식당에서 전 부치는 저녁)에 맞지
     않을 때만 고친다. 아이템 배지 9종은 이름을 되도록 살리고, 설명은 새 서사로 다시 쓴다.
   - 이유: 기존 이름을 살리면 기존 유저가 가진 아이템 배지와 이어지고, 설명만 바꿔도 새 인물과 장소가 드러난다.
3. **믹스 레시피를 무엇으로, 몇 개 만들까?**
   - 등급을 올리는 레시피(같은 트라이브의 아래 등급 5개 → 고른 컬렉션과 이름의 위 등급 1개)가 생기면서, 트라이브 안의 일반 레시피가
     줄 수 있는 것이 거의 없어졌다. 일반 레시피는 정해 둔 아이템 배지를 주는데, 등급을 올리는 레시피는 유저가 이름을 고르고 등급까지 올려 주기 때문이다.
   - 추천: 트라이브 안의 일반 레시피는 만들지 않는다. 컨텐츠 레시피는 트라이브 재구상 README 3절의 단서 20개에 하나씩, 트라이브를 넘는
     **단서 레시피**로 만든다. 재료는 출발 트라이브의 아이템 배지 5개(같은 등급), 결과는 도착 트라이브의 정해 둔 아이템 배지 1개(재료와 같은 등급)다.
     재료와 결과의 컬렉션이 모두 열렸을 때 레시피를 연다.
   - 이유: 다른 트라이브의 아이템 배지를 얻는 다른 경로(틴케이스, 드랍과 픽업, 미션)는 모두 무작위라서, 원하는 것을 골라 얻는 길이 단서 레시피뿐이다.
     단서가 실제 물건의 연결로 보여서 이야기를 읽는 재미도 생긴다.
   - 함께 바뀌는 것: 19-D4의 "트라이브를 넘는 레시피는 3분의 1쯤"은 일반 레시피를 전제로 한 비율이라서, 이 안을 고르면 의미가 없어진다.
     시드에 있는 지금 레시피 3건은 쓰지 않는다.
4. **정식 오픈 때 열 컬렉션 3개는 어떻게 고를까?**
   - 추천: 트라이브마다 중심 장소와 중심 인물이 드러나는 컬렉션 1개와, 다른 트라이브로 이어지는 단서가 담긴 컬렉션 2개를 고른다.
     윈터가 후보를 내고 사용자가 고른다.
   - 이유: 단서가 담긴 컬렉션을 함께 열어야 정식 오픈 때부터 단서 레시피 몇 개를 열 수 있다.
5. **액티비티 배지의 서사를 트라이브 사이에 어떻게 나눌까?**
   - 추천: 조건에 어울리는 트라이브를 고르되(9-2), 한 트라이브가 전체 계열의 30%를 넘지 않게 한다.
   - 이유: 날씨, 밤, 기록 같은 조건은 사진이나 혼자들 쪽으로 몰리기 쉽다. 한쪽에 몰리면 다른 트라이브 유저가 자기 트라이브의 흔적을 덜 본다.
6. **실제 원고는 언제 쓰고 어디에 둘까?**
   - 추천: 이 정책을 확인하면 3절 순서 1~6을 3단계(현재 서비스와 비교)와 나란히 구상 문서로 쓴다. 원고는 트라이브 재구상 폴더 안에
     트라이브마다 원고 파일 하나(예: `tribe-rethink/원고/01 미식.md`)로 두고, 액티비티 배지처럼 트라이브를 넘는 것은 공통 원고 파일 하나에 둔다.
     DB와 ITEMBOOKS.xlsx에 옮기는 일은 5단계(티켓)에서 한다.
   - 이유: 원고는 구상 문서라서 1~4단계에 써도 되고, 4단계 문서(새 Service Operations)를 쓸 때 실제 이름이 있으면 화면 문구를 바로 맞출 수 있다.
   - 확인 방식: 원고는 트라이브 하나씩(컬렉션 3개와 챕터 이름 10개) 묶어서 보여 드린다.
