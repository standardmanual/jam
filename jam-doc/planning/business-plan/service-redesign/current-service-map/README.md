# 현재 서비스 기능 지도

> **JAM 2.0 기획 작업을 위한 2026-10-09(KST) 기준 스냅샷이다.** 3단계(현재 서비스와 비교)의 근거로 쓴다.
> 다른 작업에서 현재 서비스의 근거로 쓸 때는 코드로 다시 확인한다.

## 1. 만든 까닭

3단계를 시작하고 보니, 주제마다 코드를 처음부터 다시 읽어야 지금 서비스의 기능과 정책을 확인할 수 있었다(사용자 지적, 2026-10-09).
현재 서비스를 설명하는 [운영 로직 문서](../../../../../docs/specs/SERVICE_OPERATIONS.md)에는 코드와 다른 곳이 있고, 어드민에서 바꿀 수 있는 것과
DB의 실제 설정값을 담고 있지 않다. 그래서 지금 서비스를 한 번에 정리해 두고, 주제별 비교는 이 지도를 읽고 진행한다.

## 2. 만든 방법

- 서브에이전트 7명이 영역을 나눠 코드를 읽고, DB는 SELECT로만 조회했다. 코드, DB, 저장소는 고치지 않았다.
- 문서는 길잡이로만 쓰고 모든 사실을 코드와 DB로 확인했다. 확인하지 못한 것은 "확인 못 함"으로 적었다.
- 기능마다 같은 틀로 적었다. **유저 화면**, **어드민**(코드 수정 없이 바꿀 수 있는 것), **규칙과 값**(코드 기본값과 DB 실제 값),
  **데이터**, **코드**, **알려진 문제**, **문서 어긋남**이다.
- 카리나는 영역마다 몇 절을 골라 근거(파일 경로, 조회 결과)가 붙어 있는지 확인했다. 모든 문장을 다시 검증하지는 않았다.

## 4. 비교 전에 알아 둘 지금 서비스의 상태

영역 문서에서 옮긴 사실이다. 근거는 각 영역 문서에 있다.

| 사실 | 영역 |
|---|---|
| 켜진 트라이브는 3개다. 살아 있는 아이템 배지는 그 3개 트라이브의 270개이고 모두 Common이다. 켜진 컬렉션은 30개다 | 3 |
| 그래서 드랍 엔진의 등급 비율과 보정 장치는 지금 결과에 영향을 주지 않는다. Rare 이상이 뽑혀도 Common으로 내려간다 | 3 |
| 아이템 배지에 레벨처럼 오르는 장치는 지금 없다. 마이그레이션 055~094 시기에 등급 짝과 상위 등급 레시피가 있었지만 DB에서 사라졌다 | 3 |
| 레벨형은 어드민 화면에서 액티비티 배지로만 만들 수 있다. 저장 API와 DB 제약은 배지 종류를 막지 않는다 | 2 |
| 인벤토리는 DB 설정이 10칸이다(코드 기본값과 여러 문서는 50칸) | 3 |
| 가입 유저 8명 모두 트라이브가 없고, 지금 코드로는 트라이브를 고를 경로가 없다. 유저의 트라이브 값을 쓰는 서비스 로직도 없다 | 6 |
| 미션 55건은 모두 개인형이고 진행 중이다. 미션에 트라이브를 제한하는 칸과 참가 인원 상한 칸이 없다 | 5 |
| 포인트를 쓰는 곳이 없다 | 5 |
| 시스템 드랍은 자동 배치가 꺼져 있고, 모두 무작위 설정이라 저장된 카테고리, 등급, 컬렉션 지정값이 무시된다 | 4 |
| 확률 안내 화면이 없다 | 7 |
| 운영 자동화는 에이전트가 제출한 묶음이 0개이고, 예약 루틴은 2026-10-07에 삭제되었다 | 7 |

## 5. 문서 어긋남

영역 문서의 「문서 어긋남」에 모두 35건을 적었다. 대부분 [운영 로직 문서](../../../../../docs/specs/SERVICE_OPERATIONS.md)가 지금 코드와 다른 곳이다
(예: 미션 참가 취소, 드랍 확률, 인벤토리 칸 수, 컬렉션 완성 판정). 운영 로직 문서는 4단계(새 Service Operations)에서 새로 쓰므로,
이 지도에서는 고치지 않고 기록만 한다.
