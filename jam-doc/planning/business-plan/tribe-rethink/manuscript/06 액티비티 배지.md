# 액티비티 배지 컨텐츠 원고

> **JAM 2.0 기획 문서다.** 순서 6(액티비티 배지 계열과 운동 속성 구간 이름)의 공통 원고다. 사용자 의견, 게이미피케이션 점검, 제외 후보 선택(2026-10-09)을 반영한 계열 목록이다.
> 서비스, DB, 티켓에 반영하지 않았다. 만드는 방법은 [트라이브 컨텐츠 제작](<../../service-redesign/15 트라이브 컨텐츠 제작.md>) 2절, 5절, 7절, 8절,
> 쓰는 규칙은 [트라이브 보이스](<../../service-redesign/트라이브 보이스.md>) 2절과 4절, 갈래와 조건은 [액티비티 배지와 체크인 배지](<../../service-redesign/09 액티비티 배지와 체크인 배지.md>) 2절과
> [배지 획득 조건](<../../service-redesign/03 배지 획득 조건.md>) 2절, 3절, 수량과 기준값은 [게이미피케이션 밸런스](<../../service-redesign/19 게이미피케이션 밸런스.md>) 6절이다.

## 1. 이 원고의 약속 (사용자 결정, 2026-10-09)

- **이름과 등급:** 계열마다 이름은 하나이고, 단계는 등급(레벨형은 Lv.N)으로 표시한다. 운동 속성의 구간 계열(11개)만 구간마다 이름을 둔다([트라이브 컨텐츠 제작](<../../service-redesign/15 트라이브 컨텐츠 제작.md>) 2절).
- **5단 사다리는 레벨형이다.** 등급은 Common, Rare, Epic, Mystic 네 개뿐이라 5단으로 정한 사다리(3-6, 8-4~8-7)는 Lv.1~5로 둔다. 레벨형은 등급이 없고 포인트가 레벨마다 10이다.
- **설명:** 길이는 아이템 배지와 같게 1~2문장이다. 단계마다 따로 쓰고, 레벨형도 레벨마다 따로 쓴다.
- **값은 종목마다 다르다:** 걷기, 러닝, 트레일러닝, 자전거, 등산의 밸런스에 맞춰 횟수 사다리와 구간 경계값을 다르게 한다. 지금 서비스의 값을 참고하고, 값은 임시로 쓴 뒤 나중에 밸런싱한다.
  사용자가 쓴 '하이킹'은 문서의 '등산'과 같은 종목으로 읽었다(지금 서비스의 종목 키는 hiking이다).
- **운동 속성은 종목마다 계열과 이름을 따로 둔다.** 종목마다 쓰지 않는 속성은 골라서 뺀다(2.10절). 다른 갈래의 '종목별' 계열은 계열 하나에 이름 하나를 두고 종목마다 값만 다르게 한다.
- **연속과 누적을 나눈다.** 연속 계열(1-3, 1-4, 2-2, 7-4)은 30일(4주) 안에서 끝나고, 누적 계열은 중간에 비어도 이어진다.
- **횟수는 활동한 날로 센다.** 하루를 인정하는 기준은 동기화된 활동 1건이고, 활동 하나가 인정받는 최소 시간은 [어뷰징과 밴](<../../service-redesign/20 어뷰징과 밴.md>) 정책을 따른다. 내 기록을 넘는 반복형(6-18, 6-19)도 하루에 한 번만 센다(카리나 판단).
- **날씨:** 폭염은 30도 이상, 한파는 영하 5도 이하다([배지 획득 조건](<../../service-redesign/03 배지 획득 조건.md>) 2절, 7절). "비 오는 날 3번 움직였어요"는 이름이 아니라 조건 문구다.
  날씨 갈래는 시간 조건과 섞을 수 있고, 밤과는 섞지 않는다([액티비티 배지와 체크인 배지](<../../service-redesign/09 액티비티 배지와 체크인 배지.md>) 5절).
- **밤과 날씨 배지는 이름과 설명에 트라이브를 담지 않는다.** 해당하는 계열은 7개(3-7, 4-1~4-6)다. 트라이브 서사 없이 조건에 맞게 쓰고, 금지 소재와 보호 장치는 그대로 지킨다.
  문장은 한 문장 45자, 쉼표 한 번까지로 임시로 둔다(카리나 판단).
- **특정 카테고리의 체크인 배지 획득과 관련된 액티비티 배지는 만들지 않는다.**
- **팔로워와 팔로잉은 지금의 수로 센다**(누적 아님). 배지 획득 조건 1절 6번의 "다른 유저와 비교하는 조건은 두지 않는다"와 부딪히는 점을 알고 정했다.
- **운동 배지는 기록과 이야기를 앞세우고 포인트를 내세우지 않는다**([게이미피케이션 밸런스](<../../service-redesign/19 게이미피케이션 밸런스.md>) 9.1절 G1의 (나)). 한 번 동기화에서 받은 배지를 묶어 알리는 기능은 이미 있다(사용자 확인).
- **아직 이름이 없는 말:** 챕터 이름과 에너지 이름은 임시 이름으로 쓰고 정한 뒤에 바꾼다. 캡슐, 믹스, 드랍, 픽업 같은 기능 이름은 JAM 활동 갈래에서 쓴다.
- **같은 문장 모양** 규칙(세 번 넘게 이어지지 않게)은 한 갈래 안과 한 트라이브 안, 두 곳에서 센다(카리나 판단).

## 2. 계열 목록

> 문서가 정한 갈래와 조건 종류에서 골랐다. 지금 서비스의 배지 이름과 계열 구성은 따르지 않았고(백지에서 설계, [액티비티 배지와 체크인 배지](<../../service-redesign/09 액티비티 배지와 체크인 배지.md>) 1절),
> 값(횟수 사다리, 경계값)만 지금 서비스에서 참고했다. 종목 칸의 '합산'은 종목과 상관없이 모든 활동을 세는 것이고, '종목별'은 다섯 종목마다 따로 세고 값이 다른 것이고,
> 종목 이름이 적힌 칸은 그 종목만 쓰는 것이다. 상태 칸의 '승인'은 사용자가 승인한 그대로, '변경'은 사용자 결정으로 바꾼 것,
> '다시 확인'은 종목별로 구조를 바꾼 뒤 따로 의견을 받지 않은 것, '확인 전'은 의견 칸이 없던 표에 있던 것이다.

- 계열의 종류는 등급형 21, 레벨형 19, 구간(운동 속성 등급형) 11, 반복형 5, 숨김 3, 단일 2개다.
- 트라이브를 쓰는 계열은 54개, 트라이브가 없는 계열은 7개다. 61개의 30%는 18.3개라서 한 트라이브는 18개까지다.

### 2.10 운동 속성의 종목별 선별표

운동 속성은 종목마다 계열과 이름을 따로 두므로 종목마다 쓸 속성을 골랐다. 고른 기준은 그 종목을 대표하는 값인가, 오래 움직이거나 빨리 가라고 무리하게 권하지 않는가,
같은 종목의 다른 속성과 겹치지 않는가다. 값은 동호인이 쓰는 숫자(대회 거리, 실제 산 높이, 에베레스트 높이)에 맞춘다.

| 종목 | 한 번의 거리 | 한 번의 시간 | 페이스 | 한 번의 오른 높이 | 한 번의 해발 높이 | 쌓아 온 거리 | 쌓아 온 오른 높이 |
|---|---|---|---|---|---|---|---|
| 걷기 | ○ 6-1 | ○ 6-2 |  |  |  | ○ 6-3 |  |
| 러닝 | ○ 6-4 |  | ○ 6-5 |  |  | ○ 6-6 |  |
| 트레일러닝 | ○ 6-7 |  |  | ○ 6-8 |  |  | ○ 6-9 |
| 자전거 | ○ 6-10 |  |  | ○ 6-11 |  | ○ 6-12 | ○ 6-13 |
| 등산 |  | ○ 6-14 |  | ○ 6-15 | ○ 6-16 |  | ○ 6-17 |

종목에 걸치는 계열은 6-18(내 가장 긴 기록: 걷기, 러닝, 트레일러닝, 자전거의 거리)과 6-19(내 가장 빠른 기록: 러닝 페이스)다.

뺀 것과 이유는 다음과 같다.

- **속도·페이스:** 러닝 페이스만 쓴다. 걷기와 등산은 빨리 가라고 권하게 되고, 트레일러닝은 지형에 따라 속도가 달라 값이 의미가 없다.
  자전거 평균 속도는 도로에서 속도 경쟁을 부추겨 사고 위험이 있어 뺐다. 최고 속도는 정책에 없는 조건이다([액티비티 배지와 체크인 배지](<../../service-redesign/09 액티비티 배지와 체크인 배지.md>) 12절).
- **한 번의 시간:** 걷기와 등산만 쓴다. 걷기는 퍼소나가 시간 기준(60분)이고, 등산은 거리보다 걸린 시간이 대표 값이다. 나머지 종목은 거리와 겹치고 오래 움직이라고 권하게 된다.
- **오른 높이와 해발 높이:** 평지가 중심인 걷기와 러닝은 뺐다. 해발 높이는 등산만 쓴다. 트레일러닝은 오른 높이가 대표 값이고, 해발은 등산과 같은 값이라 뺐다.
- **쌓아 온 거리:** 등산은 오른 높이가 대표 값이라 뺐고, 트레일러닝은 러닝과 같은 값이라 뺐다. **쌓아 온 오른 높이:** 걷기와 러닝은 뺐다.
- 쌓아 온 움직인 시간은 지금까지 모은 에너지(7-1)와 겹쳐 뺐다.

구간 이름은 구간 계열 11개마다 4개씩 모두 44개이고, 종목마다 따로 짓는다. 종목의 움직임이 들어갈 수 있다(예: 걷기는 '걸은 날').
값은 [게이미피케이션 밸런스](<../../service-redesign/19 게이미피케이션 밸런스.md>) 6절의 규칙으로 정한다. Common은 그 종목 보통 퍼소나의 한 번 활동, Rare는 그 1.5배, Epic은 열심 기준선의 한 번 활동, Mystic은 그 위의 의미 있는 숫자다.
걷기와 등산에는 열심 퍼소나가 없어 Epic을 규칙으로 만들 수 없으므로 지금 서비스의 값을 참고해 임시로 채운다(견본 단계에서 표로 보여 준다).

## 5. 쓰는 순서

1. 계열 목록 확정(2026-10-09에 끝남). 사용자가 정한 것은 정책 문서에 옮겼다(6절).
2. 서사 고르기. 액티비티 배지는 트라이브의 것이 아니고, 이름과 설명을 쓸 때 조건과 어울리는 트라이브 서사의 장소나 상황을 살짝 빌려 쓴다(사용자 확인).
   트라이브를 쓰는 54개 계열에 대해 갈래마다 윈터가 빌려 올 트라이브와 장소나 상황을 제안하고, 카리나가 스크립트로 한 트라이브 18개 상한을 점검한다.
   밤과 날씨 7개 계열은 트라이브 없이 쓴다.
3. 견본으로 운동 속성의 걷기와 러닝 묶음(설명 34개)을 먼저 쓴다. 구간 이름과 값 문제가 여기에 모여 있다.
4. 사용자가 확인하면 나머지를 쓴다. 설명 234개를 윈터 한 명에 36개 이하씩 나누면 12명쯤이다. 지시서 파일을 읽히고, 한 번에 띄우는 에이전트는 20개 이하로 한다.
5. 문장 길이, 쉼표, 반복 낱말, 이름 중복을 스크립트로 세어 보여 주고, 사용자가 확인한다.
