# UX 라이팅 재정비

> **JAM 2.0 기획 문서다.** 사용자가 2026-10-08에 확인했다. 지금 화면 문구는 지금 가이드라인
> ([UX 라이팅 가이드라인](../../../../docs/specs/UX_WRITING_GUIDELINE.md))으로 검수하고, 이 문서를 지금 화면의 근거로 쓰지 않는다.
> 근거는 하니(문서 체계), 윤진(말투와 톤), 윈터(서사 문구), 채원(화면 문구와 용어)의 검토와 2026-10-08 사용자 답이다.
> 용어는 [공통 용어](<01 공통 용어.md>) 정책을 따른다.

## 1. 이 문서의 자리와 반영 방법

- 공통 화면 문구의 규칙은 이 문서에, 배지와 아이템 배지 같은 서사 문구의 규칙은 [트라이브 보이스](<트라이브 보이스.md>)에 둔다(사용자 확인).
  두 종류는 검수하는 사람이 다르다. 화면 문구는 리뷰 게이트(민지)가, 서사 문구는 윈터가 검수하고 사용자가 확정한다.
- 5단계 티켓에서 화면 문구 코드와 같은 커밋으로 `docs/specs/UX_WRITING_GUIDELINE.md`를 덮어쓴다(사용자 확인).
  그 전에 덮어쓰면 지금 화면 문구를 아직 적용되지 않은 규칙으로 검사하게 된다.
- 같은 티켓에서 금지 표현 사전(`docs/specs/SLOP_DICTIONARY.md`)과 브랜드 보이스 가이드도 함께 고친다(7절).

## 2. 핵심 철학과 톤

- 핵심 철학(사용자 확인): **움직임이 이야기와 수집으로 쌓이는 곳이다. 문구는 쌓인 것을 알려 주되, 다음 행동을 재촉하지 않는다.**
- 판단 질문 "운동 마치고 돌아온 사람이, 앱을 켜자마자 바로 이해할 수 있는가?"는 그대로 둔다.
- 기본 톤은 **신남**을 유지한다(사용자 결정). 신남은 쌓인 것(획득, 완성, 캡슐 열기, 챕터)을 알릴 때 쓰고, 다음 행동을 부추기는 데 쓰지 않는다.
- [안전과 윤리](<14 안전과 윤리.md>) 5절의 연출 규칙을 문구에도 그대로 적용한다. 낮은 등급이 나와도 같은 신남 톤으로 쓰고 '꽝'이나 실패로 쓰지 않는다.
  높은 등급이 나왔을 때는 축하를 한 줄 더할 수 있다.

### 2.1 상황별 톤 표에서 바뀌는 행

지금 가이드라인 2.3절의 표를 아래처럼 고친다. 적지 않은 행은 그대로 둔다.

| 상황 | 톤 | 예시 | 바뀌는 점 |
|---|---|---|---|
| 배지와 아이템 배지 획득, 컬렉션 완성, 캡슐 열기, 챕터 승급 | 신남 · 축하 | 캡슐을 열었어요! 아이템 배지 3개를 획득했어요 | 캡슐 열기와 챕터 승급을 더한다. 예시를 운동 성과("오늘도 한 걸음 더 갔어요")에서 쌓인 것으로 바꾼다 |
| 잠긴 아이템 배지를 받음 | 담담 · 안내 | 잠긴 아이템 배지를 받았어요. 잼을 채우면 열려요 | 새 행. 무엇인지 모르는 것을 받았으므로 축하하지 않는다 |
| 잼 채우기 확정 | 단호 · 명확 | 잼 120을 채울까요? 채운 잼은 다시 꺼낼 수 없어요 | 새 행. 되돌릴 수 없는 행동이라 단호 톤과 같은 무게의 취소 버튼을 쓴다 |
| 체크인, 드랍, 픽업, 믹스 | 설렘 · 몰입 | 근처에 Mystic 배지가 떨어졌어요! | 지금 표의 '조합'을 '믹스'로 고친다 |

## 3. 말투의 두 층

사용자가 확인했다.

| 층 | 무엇 | 말투 | 규칙 |
|---|---|---|---|
| 공통 화면 문구 | 버튼, 상태, 안내, 확률 안내, 오류, 안전 안내, 캡슐 열기 결과 | 해요체 한 벌 | 이 문서와 지금 가이드라인 |
| 서사 문구 | 배지, 아이템 배지, 컬렉션, 미션, 단서 레시피의 이름과 설명, 챕터 이름 | 설명은 '~습니다' | [트라이브 보이스](<트라이브 보이스.md>) |

- 숫자, 상태, 확률, 되돌릴 수 없는 안내, 안전 안내는 언제나 공통 화면 문구로 쓴다.
- 한 화면에 둘이 함께 있으면 서사 문구는 컨텐츠 카드 안에만 둔다.

## 4. 용어표에서 바뀌는 것

지금 가이드라인 1.3절의 고정 용어 표를 5단계에서 아래처럼 고친다.

| 용어 | 지금 가이드라인 | 반영 후 |
|---|---|---|
| 트라이브 | 10개 가운데 하나를 고르고 바꿀 수 없다 | 5개 가운데 하나. 트라이브 변경은 [트라이브, 출신, 레벨](<04 트라이브, 출신, 레벨.md>)을 따른다. 쓰지 않는 말에 '출신'을 더한다 |
| 퀘스트 | 유저 화면의 고정 용어 | 운영 전용 용어로 옮긴다. 유저 화면에는 이 과제를 가리키는 용어를 쓰지 않는다(공통 용어 3.6절) |
| 아이템 배지, 액티비티 배지, 체크인 배지 | 「아이템배지」처럼 붙여 쓴 곳이 있다 | 띄어 쓴다(공통 용어 3.7절) |
| 획득 | 배지와 아이템을 얻는 모든 맥락 | 한 줄을 더한다: 캡슐을 열어 아이템 배지가 나오는 것은 획득이고, 잠긴 아이템 배지를 여는 것은 획득이 아니다(공통 용어 3.2절) |
| 잠김 | 선행 조건을 채우지 못해 막힌 상태 | 받은 아이템 배지가 잠긴 상태도 더한다. 상태는 '잠김', 안내는 '열려요', 버튼은 '열기'로 짝을 맞춘다 |
| 휴식, 계열, 축, 레벨(Lv.N) | 같은 말이 두 행씩 정의되어 있고 '축'은 뜻이 둘이다 | 한 행씩으로 합친다. '축'은 새 정책에 없으므로, 새 배지 트리 화면에서 쓰지 않으면 지운다 |
| 인벤토리가 가득 참 | 「꽉 찼어요」 | 그대로 쓴다. 정책 문서의 「가득 찼다」, 「빈칸이 모자라요」는 화면에서 이 말로 쓴다 |
| 새 용어 | 없음 | 잼(정식 이름, 2026-10-10 결정. 이전의 임시 이름은 에너지), 캡슐, 채우다(대상을 함께 쓴다. 예: "잼을 채웠어요"), 열기, 챕터, 배지 획득 조건, 확률 안내, 보정 장치, 알림(메뉴)과 소식(알림 안의 항목) |

- 액티비티 배지 가지 이름 '회복'은 기획과 어드민에서만 쓰는 분류라 유저 화면에 나오지 않는다. 지금 가이드라인이 '회복'을 쓰지 않는 말로
  둔 규칙(휴식을 권하지 않기)은 그대로 둔다.

## 5. 새 기능의 화면 문구

### 5.1 진행 수치

- 진행 수치(예: "120 / 300")는 쓰지 않는다(사용자 결정). 캡슐, 잠긴 아이템 배지, 챕터의 진행은 게이지로만 보여 준다.
- 가진 양(가진 잼, 포인트)은 지금처럼 숫자로 보여 준다([활동 평가와 잼](<02 활동 평가와 잼.md>)).
- 잼 채우기 확인 문구의 양("잼 120을 채울까요?")은 진행 수치가 아니라 쓸 양이므로 숫자로 쓴다.

### 5.2 채우기, 열기, 받기

- 버튼은 '채우기', '열기', '받기'로 쓴다. 지금 가이드라인 5.1절의 명사형 버튼 예외(드랍, 픽업)에 더한다.
- 처리 중 라벨은 '채우는 중', '여는 중', '받는 중'이다.
- 스크린리더 라벨에는 대상을 넣는다. 예: "캡슐 열기", "잠긴 아이템 배지 열기".
- 채우기는 되돌릴 수 없으므로 확인 문구에 쓸 양과 되돌릴 수 없다는 것을 함께 적는다(2.1절).

### 5.3 인벤토리가 꽉 찼을 때

[아이템 배지 발급](<07 아이템 배지 발급.md>) 6절의 경로마다 [현상 → 원인 → 해결] 순서로 쓰고, 잃지 않는 것을 먼저 말한다.

| 경로 | 예시 |
|---|---|
| 동기화 | 인벤토리가 꽉 찼어요. 빈칸 3칸만큼 골라 주세요. 고르지 않은 아이템 배지는 다시 받을 수 없어요 |
| 캡슐 | 채운 잼은 그대로 있어요. 인벤토리에 빈칸이 3칸 더 필요해요 |
| 미션 보상, 프로모션, 믹스 결과 | 보상은 그대로 기다리고 있어요. 빈칸을 만든 뒤 받기를 눌러 주세요 |
| 픽업 | 인벤토리가 꽉 찼어요. 빈칸을 만든 뒤 픽업할 수 있어요 |

- 동기화의 고르기는 되돌릴 수 없으므로 단호 톤으로 쓴다.

### 5.4 알림과 소식

- '알림'은 메뉴 이름이고, 알림 안의 항목 하나하나는 '소식'이다.
- 인벤토리는 남은 칸이 3칸, 1칸일 때만 알린다(아이템 배지 발급 6절).
- 챕터 승급 소식은 신남 · 축하, 이용 정지 소식은 차분 · 공감 톤으로 쓴다.

### 5.5 부추기는 말

- 안전과 윤리 5절의 금지 표현을 공통 금지 표현으로 둔다: "한 번만 더", "곧 좋은 게 나와요", '꽝', "확률 UP"처럼 다음 결과를 기대하게 하는 말.
- 기한이 없는데 서두르게 하는 말(예: "지금 아니면")도 쓰지 않는다.
- 확률은 '확률 안내'라는 이름으로 보여 주고, 보장 장치는 '보정 장치'로 부른다.

### 5.6 아이템 배지 상세

- 아이템 배지 상세에는 설명, 일련번호, 획득 이력만 보여 준다. 조건 표기는 하지 않는다(사용자 결정,
  [트라이브 컨텐츠 제작](<15 트라이브 컨텐츠 제작.md>) 3절).

### 5.7 탈퇴한 유저

- 이력과 소식에 남은 탈퇴 유저는 모두 `₩*&%#@`로 보여 주고, 안내 문구는 "₩*&%#@님은 탈퇴한 사용자입니다"로 쓴다(2026-10-10 사용자 결정,
  [온보딩과 기존 유저·데이터](<13 온보딩과 기존 유저·데이터.md>) 4절).

## 6. 액티비티 배지의 조건 표기

지금 가이드라인 3.1절(배지 획득 조건 표기)을 이어받고, 새 액티비티 배지에 맞게 아래를 바꾼다.

- 조건 표기는 한국어 운동 앱에서 흔히 쓰는 말로 짧게 쓴다(사용자 결정, 2026-10-09). 지금 규칙의 「주」 뒤 「(월~일)」과 「보다 빠르게」 페이스 표기는 새 배지에 쓰지 않는다. 「이상·이하」와 「N회」는 그대로 두고, 페이스만 「이내」로 쓴다.
- 판정 기준(시간대의 시각, 계절의 달, 주의 요일, 기온)은 조건 표기에 적지 않는다. 기준은 정책 문서([배지 획득 조건](<03 배지 획득 조건.md>) 2절, 7절)에 두고, 필요하면 화면의 도움말로 보여 준다. 마침표와 괄호, 기호(/km)를 쓰지 않는다.
- 지금 규칙 "종목 동작은 조건문에서 뺀다"는 v5 배지가 종목마다 나뉘어 있어서 생긴 규칙이다. 새 배지는 일곱 가지로 나뉘므로,
  **종목이 조건이면 맨 앞에 종목 이름을 적는다.**
- 한 번 활동의 값에는 '한 번에'를, 쌓은 값에는 '누적'을 붙여 둘을 가른다. 예: 「러닝 한 번에 10km 이상」, 「러닝 누적 600km 이상」
- 쌓는 횟수는 「누적 N일」, 「누적 N주」로 쓰고, 이어져야 하는 것만 「N일 연속」, 「N주 연속」으로 쓴다. 값이 1이면 '누적'을 뺀다.
- 시간은 60분을 넘으면 시간으로 쓴다(「2시간 30분」). 페이스는 「평균 페이스 6분 15초 이내」로 쓴다. 오른 높이는 한 번 활동이면 「상승 고도」, 쌓은 값이면 「누적 고도」로 쓴다.
- 레벨은 화면에서 레벨 칩으로 보여 주므로 조건 표기에 'Lv.N'을 쓰지 않는다(사용자 의견, 2026-10-09).
- '처음 가 본 동네'는 체크인 배지를 처음 받은 것이다(2026-10-10 사용자 결정, [배지 획득 조건](<03 배지 획득 조건.md>) 2절). 계열 이름에는 '동네'를 쓰고,
  조건 표기는 「새 체크인 배지 10개」처럼 받은 체크인 배지의 수로 쓴다.
- 아래 패턴으로 쓴다(사용자 결정, 2026-10-09). 배지마다의 표기는 [액티비티 배지 원고](<../tribe-rethink/manuscript/06 액티비티 배지.md>) 11절에 있다.

| 가지 | 패턴 | 조건 표기 예 |
|---|---|---|
| 리듬 | 한 주 조건을 채운 주를 쌓음 | 주 3일 이상 활동 누적 5주 |
| 리듬 | 연속 | 3일 연속 활동, 주 3일 이상 활동 2주 연속 |
| 리듬 | 활동한 날을 쌓음 | 활동 누적 100일 |
| 회복 | 공백 뒤의 첫 활동 | 14일 이상 휴식 후 첫 활동 |
| 시간과 계절 | 시간대, 주말 | 새벽 활동 누적 20일 |
| 시간과 계절 | 계절 묶음 | 사계절 모두 활동한 해 누적 3년 |
| 탐험 | 처음 | 새 체크인 배지 10개 |
